# 分析：Google Search Console

指导分析 Google Search Console (GSC) 数据：性能指标、索引、站点地图、核心网页质量指标和丰富结果。涵盖月度监控的最佳实践和可操作的见解。

**调用时机**：在**首次使用**时，如果有帮助，用 1-2 句话简要介绍此技能涵盖的内容及其重要性，然后提供主要输出。在**后续使用**时或当用户要求跳过时，直接提供主要输出。

## 范围

- **性能**：点击量、展示量、点击率、平均排名；API 导出
- **洞察**：简化的概览；顶部/趋势内容查询
- **索引**：已索引页面、未索引页面、原因（覆盖率）
- **技术**：站点地图、核心网页质量指标、增强功能
- **API**：searchanalytics.query 用于程序化访问
- **方法**：如何阅读图表、避免常见错误、与发布关联

## 分析最佳实践

### 图表阅读

| 实践 | 原因 |
|------|-----|
| **一次关注一个指标** | 堆叠条形图隐藏波动；关闭其他指标以清晰地查看每个指标 |
| **不要只比较两个点** | 月末与上月比较遗漏月中波动；检查完整趋势 |
| **检查前 10 名之外** | 许多报告默认为前 10 名；滚动或分页以获取更多行 |
| **截图图表** | GSC 保留有限的历史记录；保存图像以供将来参考 |
| **记录在电子表格中** | 月末导出；使用公式跟踪随时间推移的相关性 |
| **跟踪发布日期** | 参与开发会议，阅读发布说明；将 GSC 变化与部署相关联 |

### 调查工作流程

1. **确定日期**：指标何时发生变化？
2. **关联**：是否有发布、CMS 更改、服务器维护、第三方代码？
3. **决定**：调查、修正、忽略或密切监控
4. **反馈**：产品或开发团队以确定根本原因

## 关键报告和指标

### 1. 性能（搜索结果）

**位置**：性能 ? 搜索结果

| 指标 | 用途 |
|--------|-----|
| **点击量** | 来自 Google 搜索的流量 |
| **展示量** | 网站在搜索结果中出现的频率 |
| **点击率** | 用户是否认为页面回答了查询 |
| **平均排名** | 排名趋势 |

**维度**：查询、页面、国家、设备、日期。按搜索类型筛选：网页、图片、视频、新闻。用于查找低点击率高展示量的页面（标题/元标签优化机会）。

**搜索显示**：AMP、蓝色链接、丰富结果（UI 和 API 中可筛选）。

#### 点击率按排名基准

用于比较实际点击率与预期值。基准因搜索结果功能（AI 概述、特色片段）而异。**零点击**：当搜索结果功能满足意图而不需要点击时，有机点击率下降；将其纳入预期值。见 **serp-features**（零点击部分）、**featured-snippet**。干净的搜索结果：

| 排名 | 预期点击率（基准） | 带有 AI 概述（较低） |
|----------|-------------------------|---------------------------|
| 1 | 25-35% | ~19% |
| 2 | 12-18% | ~12% |
| 3 | 8-12% | ~7% |
| 4-5 | 5-7% | ~5% |
| 6-10 | 2-5% | 2-5% |

**解释**：如果实际点击率低于您所在位置的预期值，请优先考虑标题/元标签优化。前页结果中 90% 以上的点击率低于 10%；存在显著提升空间。

#### 低点击率、高展示量：优化工作流程

1. **识别**：按展示量排序；筛选位置 1-10；每月 1,000 次以上展示量
2. **比较**：实际点击率与预期值（见上表）
3. **差距**：例如，位置 4 的点击率为 2%，而预期为 5-7%？~3-5% 的提升潜力
4. **行动**：根据 **title-tag**、**meta-description** 优化标题和元标签；添加模式以获取丰富结果（+10–20% 点击）

#### 丰富结果与点击率

带有评价星级、FAQ 模式或其他丰富片段的页面点击率增加 10-20%。见 **schema-markup**。

### 2. 洞察报告

**位置**：性能 ? 洞察（或概览）

简化的概览；取代独立的 Search Console 洞察。数据仅来自 GSC（GA 数据于 2024 年 12 月删除）。

| 卡片 | 用途 |
|------|-----|
| **点击量和展示量** | 网站可见性和点击效果 |
| **您的内容** | 顶部、上升、下降页面 |
| **导致您网站的查询** | 顶部、上升、下降查询 |
| **主要国家** | 地理受众 |
| **品牌与非品牌** | 品牌认知（AI 标记；可能误标） |
| **其他流量来源** | 图片、视频、新闻搜索、Discover |

**趋势**：基于与上期相比的点击变化。点击项目可跳转到性能报告并筛选到该项目。

**查询组**：相似查询分组；组名 = 最佳性能查询。不适用于子属性或低展示量网站。

### 3. 页面索引（覆盖率）

**位置**：索引 ? 页面索引

**状态分组**（更新）：有效 + 有效带警告？**已索引**。错误 + 排除？**未索引**。

**已索引与未索引是互补的**：并非所有网站内容都应被索引。登录、管理、重复内容、法律声明和低价值页面通常有意使用 noindex。已索引和非索引页面可以相互引用（例如，站点地图包含可索引的 URL；noindex 页面仍然存在并内部链接）。未索引本身并非问题——仅在重要页面被排除时进行调查。见索引（noindex 使用）和 robots-txt（爬虫控制）以了解何时排除。

| 指标 | 行动 |
|--------|--------|
| **已索引页面** | 关闭“未索引页面”以单独查看；注意下降 |
| **未索引页面** | 关闭“已索引页面”以单独查看；注意上升。区分有意（noindex、robots）与意外 |

**筛选**：所有提交页面 / 仅未提交页面（顶部下拉菜单附近）。

**来源列**：指示问题是由网站还是 Google 引起的。

**页面未索引的原因**：深入调查原因和示例 URL。常见原因：

- 重复内容
- noindex 标签
- 重定向错误
- 5xx 错误
- 404 错误
- 被 robots.txt 阻止
- 发现？当前未索引
- 爬取？当前未索引

**快速检查**：如果趋势线稳定，花费约 3 秒；继续前进。如果第四列（趋势）发生变化，则进行调查。

**诊断工作流程**：GSC 覆盖率？点击问题？查看示例 URL？识别模式？修正（见索引以获取修正操作）。

**覆盖率问题类型**：

| 问题 | 含义 | 下一步 |
|-------|---------|-----------|
| 爬取 - 当前未索引 | 爬取但未索引 | 见索引 |
| 被 "noindex" 标签排除 | 有意排除；通常有效（登录、管理、法律等） | 如果预期则忽略；验证重要页面未被意外 noindexed |
| 被 robots.txt 阻止 | 爬取被阻止 | 见 **robots-txt**；可能是有意为之 |
| 重定向 / 404 | 重定向或缺失 | 修正 URL 或重定向 |
| 重复 / 规范 | 重复内容 | 通常可以；保留规范 |

**URL 检查**：结论：“URL 已在 Google 上”、“URL 已在 Google 上，但有问题”、“URL 未在 Google 上”。用于重要页面；验证规范、内部链接、站点地图；如有必要，请求索引。

### 4. 视频索引（如适用）

**位置**：索引 ? 视频索引

- **已索引视频** / **未索引视频**：关闭另一项以清晰查看
- **视频未索引的原因**：缩略图被阻止、无效大小/格式、不在主要内容中，等。

见 **video-optimization**（视频 SEO）；**youtube-seo**（YouTube）。

### 5. XML 站点地图

**位置**：索引 ? 站点地图

| 检查 | 行动 |
|------|--------|
| 状态 | 确认每个站点地图显示“成功” |
| 已索引 URL | 点击站点地图？查看已索引计数；下降表示索引问题 |
| 指示站点地图 | 对于大型网站，监控模板站点地图（按国家、语言、部门） |

企业：错误可能导致新 URL 爬取被阻止、hreflang 混乱、新鲜内容发现延迟。

### 6. 核心网页质量指标

**位置**：体验 ? 核心网页质量指标

**优先级**：移动优先（Google 对移动设备有更高的期望）。

| 指标 | 移动 | 桌面 |
|--------|-------|---------|
| **良好 URL** | 目标 | 次要 |
| **需要改进** | 修正 | 监控 |
| **不良 URL** | 修正 | 监控 |

**URL 没有良好分数的原因**：点击“打开报告”→ 按问题类型分组示例 URL。有关阈值值和修复措施，见 **core-web-vitals**。

**提示**：历史图表较短；导出到电子表格以获取更长的趋势。定期与开发团队分享；将日期与发布相关联。

**布局**（更新）：两个表格——不良或需要改进；良好（点击“查看可用页面的数据”）。

### 7. 增强功能（丰富结果）

**位置**：体验 ? 增强功能（产品片段、购物列表在购物下）

**状态**（更新）：两档？*无效*（严重问题，可能不会显示） vs **有效**（无严重问题；仍可能有警告）。警告不再作为顶级项目显示。

| 类型 | 示例 |
|------|----------|
| 内容 | 面包屑、FAQ、活动、视频（见 **video-optimization**）、职位发布、评价片段、问答、讨论论坛 |
| 购物 | 产品片段、商家列表 |
| 其他 | 配方、数据集、酒店、度假租赁、个人资料页面、练习问题、数学求解器、图像元数据 |

**注意**：报告显示样本项目，而不是完整列表。用于未列出 URL 的 URL 检查。

### 8. AI 概述（GSC 限制）

- **GSC**：AI 概述的点击量/展示量在性能报告中未与有机分开。
- **解决方案**：筛选倾向于触发 AI 概述的查询以估计 AI 驱动的可见性：

```
(?i)^(who|what|where|when|why|how|which|is|are|can|does|should)|\b(vs|versus|compare|difference|pros and cons|guide|tutorial|best|top|list)\b
```

对于 GA4 AI 流量跟踪，见 **ai-traffic-tracking**。

### 9. 链接与排除

**位置**：链接（入站链接）、安全与手动操作

- **链接报告**：查看指向网站和页面的链接；锚文本分布。
- **排除文件**：必要时通过 GSC 提交（手动处罚、有毒链接）。谨慎使用；过度排除可能有害。见 **backlink-analysis** 以了解何时排除。

## Search Console API

**方法**：`searchanalytics.query()` --公开所有性能报告数据。

### 指标

点击量、展示量、点击率、排名。

### 维度

date、query、page、country、device。搜索显示（AMP、蓝色链接、丰富结果）。按搜索类型筛选：网页、图片、视频、新闻。

### 限制

| 限制 | 值 |
|-------|-------|
| 每日每搜索类型每属性的行数 | 50,000 |
| 每次响应的行数 | 25,000（使用分页：startRow、rowLimit） |
| 数据可用性 | 2-3 天后 |

**提示**：每天运行一次查询以获取一天的数据以避免配额。首先验证数据存在（维度：仅 date，无过滤器）。

**优化**：Gzip 压缩；`fields` 参数用于部分响应；分页用于大型数据集。

**参考**：[Search Console API](https://developers.google.com/webmaster-tools/about)，[searchanalytics.query](https://developers.google.com/webmaster-tools/v1/how-tos/search_analytics)

## 月度审计清单

- [ ] 性能：点击量、展示量、点击率、排名趋势
- [ ] 洞察：顶部/趋势内容查询（如果可用）
- [ ] 页面索引：已索引与未索引（隔离视图）
- [ ] 未索引的原因：关键原因的趋势线
- [ ] 站点地图：所有“成功”；已索引 URL 计数稳定
- [ ] 核心网页质量指标：移动良好/需要改进/不良
- [ ] 增强功能：无新的无效项目（严重问题）
- [ ] 链接：无手动操作；仅在必要时排除（见 **backlink-analysis**）
- [ ] 数据导出到电子表格（月末快照）
- [ ] 图表截图以供历史参考
- [ ] 发布说明已审查以供关联

## 输出格式

- **总结**：关键发现、趋势、异常
- **指标**：具体数字和日期范围
- **点击率分析**：实际与预期按排名；低点击率高展示量的页面
- **标题/元标签机会**：点击率差距的页面；具体的优化建议
- **行动项**：优先级修正（索引、CWV、站点地图、增强功能、标题/元标签）
- **关联**：疑似原因（发布、配置更改）
- **下一步**：监控计划、开发交接

## 相关技能

- **title-tag, meta-description, page-metadata**：低点击率页面的标题和元标签优化；hreflang
- **xml-sitemap**：修复站点地图错误
- **indexing**：解决索引问题
- **core-web-vitals**：CWV 优化；修复 LCP、INP、CLS
- **mobile-friendly**：移动可用性报告；移动优先索引
- **schema-markup**：修复结构化数据/丰富结果
- **backlink-analysis**：何时排除；反向链接审计
- **seo-monitoring**：完整 SEO 数据分析、基准
