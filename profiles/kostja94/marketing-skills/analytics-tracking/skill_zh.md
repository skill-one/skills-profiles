# 分析：追踪

指导分析实施：GA4设置、事件追踪、转化和数据处理质量。适用于跨营销渠道的网页和应用追踪。

**调用时机**：在**首次使用**时，如果有帮助，先用1-2句话说明此技能涵盖的内容及其重要性，然后提供主要输出。在**后续使用**或用户要求跳过时，直接进入主要输出。

## 用户ID

- **目的**：跨设备、跨会话的用户识别
- **实施**：在用户识别时（例如登录）设置`user_id`；发送至GA4
- **优势**：跨会话准确归因；更好的受众构建

## CTA归因（文章ROI）

追踪关键文章上的CTA点击以衡量内容ROI：

| 行动 | 目的 |
|------|------|
| **每个CTA的事件** | 例如，`cta_click`带有`content_url`、`content_type` |
| **转化** | 在GA4中标记为转化以进行归因 |
| **使用** | 比较高绩效和低绩效；优化CTA位置和文案 |

参见**seo-monitoring**获取文章数据库和基准背景。

## 基础设施要求

| 组件 | 目的 |
|------|------|
| **数据仓库** | 集中数据；BI报告 |
| **事件追踪** | 用户行为；漏斗映射 |
| **归因** | 广告像素；归因模型；曝光到购买的追踪 |

**优化流程**：清洁UTM + 转化事件 → 归因报告 → 优化渠道组合。

## 范围

- **GA4**：网页数据流、gtag.js、配置
- **用户ID**：跨设备、跨会话识别
- **CTA归因**：每篇文章的转化追踪以衡量内容ROI
- **事件**：推荐和自定义事件
- **转化**：关键事件、参数
- **质量**：命名、测试、验证

## GA4设置

### 前置条件

- Google Analytics属性和网页数据流
- 所有页面上的Google标签（gtag.js）
- 测量ID（例如，`G-XXXXXXXXXX`）

### 增强测量

在管理 > 数据流 > 增强测量中启用，以自动追踪：

- 页面浏览、滚动、外部点击
- 网站搜索、文件下载
- 视频参与（YouTube）

## 事件追踪

### 事件类型

| 类型 | 描述 |
|------|------|
| **自动收集** | page_view、first_visit、session_start |
| **增强测量** | scroll、click、file_download等 |
| **推荐** | purchase、sign_up、search等 |
| **自定义** | 业务特定操作 |

### 命名规范

- **长度**：<=40个字符（GA4硬限制；较长的名称不会被记录）
- **格式**：`snake_case`，小写
- **动词优先**：`download_pdf`、`submit_form`、`video_play`
- **上下文**：`pricing_page_scroll` vs通用`scroll`

### gtag.js语法

```javascript
gtag('event', '<event_name>', {
  <parameter_name>: <value>,
  // 例如，value: 99.99，currency: 'USD'
});
```

放置在Google标签片段下方。事件在页面加载或用户操作（例如按钮点击）时触发。

### 推荐事件

| 事件 | 使用 | 关键参数 |
|------|------|----------|
| `purchase` | 电子商务 | value、currency、items |
| `sign_up` | 注册 | method |
| `login` | 登录 | method |
| `search` | 网站搜索 | search_term |
| `view_item` | 产品查看 | items |
| `add_to_cart` | 加入购物车 | items |

### 自定义事件

- 专注于15-25个与KPIs对齐的具有意义的事件
- 添加参数以提供上下文（例如，`content_type`、`item_id`）
- 避免追踪所有内容；优先考虑质量而非数量

## 转化（关键事件）

- 在GA4管理中标记重要事件为转化
- 用于归因、受众和报告
- 典型：purchase、sign_up、lead、contact

## 归因与转化优化

归因模型决定如何跨触点分配转化信用。使用归因数据优化广告和增长渠道。

| 模型 | 使用 |
|------|------|
| **数据驱动**（GA4默认） | ML根据实际贡献分配信用；最适合多触点旅程 |
| **最后点击** | 100%归因于最终触点；简单但低估了认知/考虑 |

**优化流程**：清洁UTM（来源、媒介、活动）+ 转化事件 → GA4归因报告 → 按归因转化比较渠道 → 将预算重新分配给产生结果的广告/渠道。不一致的UTM会碎片化数据；多触点归因需要可靠的触点数据。

**参考**：[UTM.io – 用于营销归因的UTM](https://web.utm.io/blog/utms-for-marketing-attribution/)，[GA4 – 开始使用归因](https://support.google.com/analytics/answer/10596866)

## 测试与验证

| 工具 | 使用 |
|------|------|
| **Realtime** | 查看事件实时触发 |
| **DebugView** | 详细的事件/参数检查；需要调试模式 |
| **GA4调试模式** | `gtag('config', 'G-XXX', { 'debug_mode': true });`或GTM预览 |

- 发布前测试；验证参数和命名
- 检查重复事件、缺失值
