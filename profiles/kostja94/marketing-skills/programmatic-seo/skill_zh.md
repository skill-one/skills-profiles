# SEO：程序化SEO

本指南介绍了程序化SEO——利用模板和结构化数据自动创建大量SEO优化的页面，而不是手动编写每个页面。**经典的“邮件合并”式SEO**（一个僵化的模板+可替换的变量）往往导致**差异化不足**和感觉单薄的URL。**在相同的数据骨干上负责任地使用AI**，您可以扩展**每个URL的定制化**——与意图一致的文案、部分深度、常见问题解答、语气、本地化——同时仍然遵循**证据块**、**数据层级**和**质量保证**（见下文的**数据强度层级**和**AI辅助生成**）。

**调用时机**：在**首次使用**时，如果有帮助，先用1-2句话说明这项技能涵盖的内容及其重要性，然后提供主要输出。在**后续使用**或用户要求跳过时，直接进入主要输出。

**项目背景**：如果存在`.claude/project-context.md`或`.cursor/project-context.md`，在提出操作手册或页面类型之前，应先阅读产品/ICP部分。

## 定义

**程序化SEO** = 构建一个模板，并用来自数据库、API或电子表格的数据填充它，以生成数百或数千个唯一页面。每个页面都针对长尾关键词（例如，“[城市]最佳SEO工具”、“[应用A] + [应用B]集成”）。

**与传统SEO的关键区别**：技术性（SEO + 工程师）；长尾聚焦；数据驱动（数据质量=成功）；自动化；为规模而构建。

## 经典限制与AI增强差异化

| 时代 | 出现问题 | 有助于解决问题 |
|-----|-------------|------------|
| **僵化的程序化SEO** | 一个模板，最小差异 → 相似的标题/正文，弱的**E-E-A-T**，“明显的邮件合并” | 仍然需要**每个URL的独特证据**和选择性索引 |
| **AI增强程序化SEO** | 相同的**结构化行**（事实、SKU、指标）驱动页面，但模型添加**每个URL的叙事**：引言、FAQ深度、角色角度、本地化、内部链接建议——**规模化差异化** | **事实保留在您的数据层**；AI塑造**措辞和结构**，而不是编造数字——见**AI辅助生成** |

**最佳实践立场**：AI是一个**加速器和定制器**，而不是**数据防御性**（层级1-5）或**技术SEO**（URL、模式、CWV）的替代品。用得好，它符合**质量胜于数量**：更少的薄URL，更多**独特**有用的页面。

## 三部分框架

| 组成部分 | 作用 |
|-----------|------|
| **模板** | 可重用的页面结构：布局、标题、内部链接、内容块；空字段的条件逻辑 |
| **数据** | 结构化信息：位置、产品、价格、功能——必须准确、完整并具有真实价值 |
| **自动化** | 连接数据到模板的系统；动态生成页面或批量发布 |
| **AI层（可选）** | 在**基于事实的输入**（行JSON + 规则）上，生成**多样化的文案**、FAQ扩展和**每个URL的**部分强调——减少“相同模板”疲劳，同时保持可审计性 |

## 模板结构（推荐）

| 部分 | 目的 |
|---------|---------|
| **引言** | 介绍；匹配用户意图 |
| **证据块** | 每个页面独特的、数据驱动的內容（表格、列表、验证统计数据）；区别于薄內容 |
| **决策** | 比较、推荐或下一步行动 |
| **常见问题解答** | 常见问题 |
| **行动号召** | 行动号召 |

**证据块** = 每个页面的真实、结构化数据（商业列表、价格、评论、验证统计数据）。确保每个页面提供真实价值，而不是带有替换变量的循环样板。

## 数据强度层级（防御性）

**最强的程序化页面是由只有您的产品（或您的产品中的客户）才能产生的数据驱动**——尤其是**模板、导出和生成物**。仅依赖第三方或抓取列表是最弱的基石。

| 层级 | 来源 | 示例 | 相对风险 |
|------|--------|----------|----------------|
| **1 — 产品生成** | 您的产品创建或渲染的资产：页面/布局**模板**、电子邮件/Notion/代码模板、导出包、生成预览、品牌片段、“使用[产品]构建”示例 | 模板库行链接到真实的`.json` / CMS字段；导出的截图；独特的预览URL | **最低**当每个URL显示不同的生成输出时 |
| **2 — 产品衍生** | 您拥有的遥测和产品内数据：聚合、群体、基准、功能采用率 | “[行业]中团队中值价值时间”来自您的仓库（聚合） | 如果聚合/匿名化且符合政策，则风险较低 |
| **3 — 用户生成内容/客户** | 评论、提交、展示项、经过审核的社区内容 | 展示网格；验证引言 | 中等——需要审核+同意 |
| **4 — 许可/合作伙伴** | 独家数据源、联合营销数据集 | 合作伙伴价格层级；许可行业统计数据 | 中等——合同和引用纪律 |
| **5 — 公共/抓取** | 互联网、目录、通用丰富 | 名称/地址填充；商品事实 | **最高**——需要编辑层、事实核查和真实的**证据块** |

**为什么Tier 1（模板和生成内容）胜出**：基于**您**的模板系统构建的页面携带专有结构、变量和品牌安全块——更难被竞争对手逐字复制，更容易证明其独特性（嵌入、下载、ID）。与**template-page-generator**一起使用时，用户体验是“浏览画廊 → 使用模板”。

### Tier 2 — 产品衍生（实用）

| 是什么 | 注意事项 |
|------------|----------------|
| 来自**您**的后端、数据仓库或支持/CRM导出的指标：按群体激活率、集成流行度、错误预算、价值时间——不是通用的“行业报告”。 | **隐私&条款**：最小单元格大小；无个人识别；记录聚合了什么以及时间窗口。 |
| 当您可以展示**“只有我们才能知道，因为它运行在我们的产品中”**时，适合 | **过时数据**损害信任：管道作业，“截至[日期]”标签，自动失效。 |

**AI在此处**：使用模型将结构化聚合转换为散文（引言段落，“对[群体]意味着什么”）——**输入必须是来自您的管道的已验证数字/表格**，而不是自由形式的发明。在页面或附录上保留**机器可读的表格或JSON**，以便声明保持可审计。

### Tier 3 — 用户生成内容/客户（实用）

| 是什么 | 注意事项 |
|------------|----------------|
| 引言、评论、展示提交、社区模板——**每个用户的工件**，有同意。 | **审核**：垃圾邮件、PII、竞争对手攻击；**同意**使用名称/徽标；**模式**（评论、CreativeWork）仅当准确时。 |
| 当与**Tier 1**结合时强劲（例如，“客户构建的模板”画廊）。 | **没有质量的量**→薄页面；限制或评分提交。 |

**AI在此处**：将长篇评论总结为要点；**生成草稿替代文本**用于图像；**将提交聚类**到主题页面——始终**人工批准**后再发布。不要编造客户评价。

### Tier 4 — 许可/合作伙伴（实用）

| 是什么 | 注意事项 |
|------------|----------------|
| 合作伙伴价格列表、联合营销报告、API驱动的**允许**字段（徽标、SKU）。 | **合同范围**：哪些字段可以出现在哪些URL上；署名行；**DMCA/商标**在徽标上。 |
| 通常**一个数据源 → 许多URL**；独特性必须来自**您的框架**、比较逻辑或计算器——而不是原始数据源本身。 | **刷新频率**与合作伙伴SLA挂钩。 |

**AI在此处**：从**固定的属性表**（许可+合作伙伴规则）起草**比较文案**和**常见问题解答**；绝不编造SKU或价格——**从数据源获取**，让AI措辞和缩短。

### Tier 5 — 公共/抓取（实用）

| 是什么 | 注意事项 |
|------------|----------------|
| 开放数据、目录、维基百科式事实、**丰富**公共实体。 | **最高**重复/薄风险：每个人都拥有相同的事实；**您必须添加**综合、编辑角度或**独特工具**（计算器、过滤器）在顶部。 |
| **实体SEO**和**引用**很重要：链接到权威来源；日期戳易变事实。 | 计划**修剪**或**noindex**在低流量薄URL上。 |

**AI在此处**：使用模型将混乱的公共文本结构化为表格、**概述**部分、**建议**内部链接——然后**事实核查**名称、数字和日期。**不要**使用AI编造统计数据或引用；将输出视为**草稿**，直到验证。

### AI辅助生成（跨层级）

**为什么AI适合现代程序化SEO**：早期的程序化SEO获得了一个坏名声，因为**模板被冻结**，**文案是可互换的**——每个查询的差异很小。**大型语言模型**，当**基于事实**和您的品牌规则时，使**为每个URL定制**标题、引言、FAQ和“这个页面为何重要”**成为可能**，而无需手写数千个页面。这使执行更接近**最佳实践**（意图匹配、有用内容、独特价值）**规模化**，前提是**您不**让模型编造数据。

| 原则 | 原因 |
|-----------|-----|
| **在结构化输入中基于AI** | 将JSON/CSV行（层级、来源URL、指标）输入提示；**禁止**系统提示中的幻觉数字。 |
| **分离“事实”与“措辞”** | 数据层 = 真实来源；AI = 语气、缩短、本地化、FAQ、**按细分强调**——反之则不可行。 |
| **变化结构，而不仅是形容词** | 请求不同的**部分顺序**、FAQ数量或“初学者与高级用户”角度**按意图标志**在行中——减少模板相同性。 |
| **人工或自动化QA** | 检查高流量URL；如果必需字段为空或引用缺失，则阻止发布。 |
| **在有用时披露** | 例如，“引言由AI生成；数据来自[内部报告，2025年Q3]。” 建立信任并符合政策趋势。 |

**当AI生成是一个强大的杠杆时**：Tiers **2-5**——其中原始材料是表格或重复的，但**需要可读的、差异化的文案**规模化。Tier **1** 仍然受益于AI（从导出JSON生成草稿），但**差异化仍然来自**产品工件本身。

### 运营要求（所有层级）

| 要求 | 实践 |
|-------------|----------|
| **来源** | 记录数据来源；按字段跟踪来源 |
| **新鲜度规则** | 例如，评分每90天，价格每30天，布局更改时模板版本更新 |
| **优先1-2而非5** | 在达到公共抓取之前，用产品生成或产品衍生的数据填充证据 |
| **AI治理** | 仅限结构化输入；无未经验证的数字；对UGC进行审核；可选披露 |
| **清理和合并** | 去重键；删除产生重复意图的行 |

| 要求 | 目的 |

## 技术注意事项

| 主题 | 实践 |
|-----|----------|
| **子文件夹 vs 子域名** | 优先**子文件夹**（`yoursite.com/integration/slack-notion/`）而不是**子域名**（`integrations.yoursite.com/...`）以便权威集中在主域名；见**url-structure**, **domain-architecture**如果重新结构 |
| **选择性索引** | 不要索引所有页面；使用noindex规则对低价值页面 | **网站地图分段** | 按国家、语言、部门管理；管理爬行预算 |
| **URL结构** | 描述性URL；干净的层次结构；见**url-structure** |
| **模式** | JSON-LD：产品、地点、FAQ、ItemList按页面类型 |
| **性能** | 缓存、静态生成；核心网络指标 |

## 严重错误

| 错误 | 后果 |
|---------|-------------|
| **薄内容** | 超过关键词的少量信息；通用文案；占位符部分 → 处罚 |
| **重复页面** | 只有数据交换的相同內容 → 薄内容处罚 |
| **索引膨胀** | 生成不应被索引的页面 → 爬行预算浪费 |
| **大量倾倒** | 一次性发布许多相似页面 → 垃圾信号 |
| **过滤器URL** | 使用过滤器而不是唯一的URL/标题 → 重复内容 |

只有标题、一段话和交换城市名称的页面不会排名，并可能遭受Google处罚。

## 纠正已构建的同类化页面

如果程序化页面已经发布并感觉可以互换——共享结束语、跨URL的相同价值主张、克隆部分结尾——在触发质量信号之前修复內容。

### 诊断方法

运行正则表达式扫描渲染或源文件，以暴露共享的句子尾部和重复的段落结构。查找在超过30%的同类页面中出现的模式。常见的迹象：每个工具页面都以“X是Y的理想选择”结尾，每个分类页面都共享相同的技术摘要，每个位置页面都使用相同的FAQ结尾。

在三个范围内扫描：在单个页面内（它的部分是否重复相同的结束语公式？）、在分类内（所有视频工具页面是否共享模板？）、跨分类（每个页面是否都是全站范围的相同价值声明？）

### 按三个优先级排序修复

| 优先级 | 是什么 | 操作 |
|----------|------------|--------|
| **P0 — 消除** | 纯模板填充，没有信息价值；每个页面都说同样的事情 | 独立重写每个页面，带有页面特定细节 |
| **P1 — 重写** | 核心信息正确但交付公式化（例如，“不同工具使用不同的架构”——真实但通用） | 准备8-15个语义变体，循环使用它们，以便相邻页面不同 |
| **P2 — 降低密度** | 正常词汇出现过于频繁（例如，80%的页面出现“无缝”） | 替换~30-40%的实例，而不是全部——正常词汇在中等频率是正常的 |

### 分阶段执行

首先修复P0模式，一次一个分类。每次轮换后，重新扫描以确认模式已清除，并且没有出现新的模式。一个常见的陷阱：通过应用相同的修复来替换一个模板为另一个模板。按不同的方式分发重写，以便按顺序处理的页面获得不同的处理。

对于单个页面内部重复——其中文件中的所有用例或工具描述都共享相同的结束语——使用功能性的结束语而不是评估性的结束语。功能性结束语描述了实际实践中解决瓶颈的入口；评估性结束语只是声明它是好的选择。

### 管道中的预防

在AI生成提示中添加结构多样性要求（变化部分结尾，禁止重复结束语公式）。将来自不同分类的页面分批生成，而不是一次一个分类的所有页面。在发布前运行N-gram重叠检查，以检查同类页面。

## 分步工作流程

1. **研究** — 领域，意图；包括低流量关键词；SEO工具，问题数据库
2. **收集数据** — 来源日志，新鲜度规则；第一方/许可；定义模板字段
3. **选择堆栈** — Next.js + DB, Webflow CMS, WordPress, headless；API + 模板重用
4. **设计模板** — 引言，证据，决策，FAQ，行动号召；模式；条件逻辑
5. **构建数据库** — 将字段映射到模板插槽；隐藏空值
6. **生成页面** — 描述性URL；优化性能
7. **部署和监控** — 网站地图；索引，排名，CTR，跳出率，转化率
8. **优化** — 删除弱页面；刷新数据；A/B测试布局，行动号召

## 最佳实践

| 实践 | 目的 |
|----------|---------|
| **质量胜于规模** | 每个页面都必须提供真正独特、有价值的內容 |
| **差异化胜于克隆** | 优先**AI增强**的文案差异 + 证据块，而不是一个静态段落与`{城市}`交换 |
| **分批启动** | 小批您可衡量的；避免大量倾倒 |
| **强大的内部链接** | 链接相关的指南/分类 |
| **视觉元素** | 在相关的地方使用表格、地图、比较 |
| **匹配意图** | 避免通用模板文本；精确的用户意图 |
