# 新闻简报生成技能

## 概述

该技能能够生成专业、研究充分的新闻简报，将来自多个来源的精选内容与原创分析和评论相结合。它借鉴了Morning Brew、The Hustle、TLDR和Benedict Evans等现代出版物的新手报最佳实践，以生产信息丰富、引人入胜且具有可操作性的内容。

输出是一个完整的、可直接发布的Markdown格式新闻简报，适用于电子邮件分发平台、网络发布或转换为HTML。

## 核心功能

- 从指定的网络来源研究和精选特定主题的内容
- 生成主题聚焦或多主题新闻简报，保持一致的语气
- 撰写引人入胜的标题、摘要和原创评论
- 结构化内容以优化可读性和扫描效果
- 支持多种新闻简报格式（每日摘要、每周汇总、深度分析、行业简报）
- 包含相关链接、来源和署名
- 根据目标受众（技术型、高管型、普通型）调整语气和风格
- 生成具有一致品牌和结构的定期新闻简报系列

## 何时使用此技能

**始终加载此技能的情况：**

- 用户要求生成新闻简报、电子邮件摘要或内容汇总
- 用户请求关于某个主题的新闻或发展情况的精选摘要
- 用户希望创建定期新闻简报格式
- 用户要求将某个领域近期的发展汇编成简报
- 用户需要一个包含多个精选项目的格式化电子邮件内容
- 用户要求“每周汇总”、“每月摘要”或“晨间简报”

## 新闻简报工作流程

### 第一阶段：规划

#### 第1.1步：理解新闻简报需求

确定关键参数：

| 参数 | 描述 | 默认值 |
|-------|-------|-------|
| **主题** | 主要涵盖的学科领域 | 必填 |
| **格式** | 每日摘要、每周汇总、深度分析或行业简报 | 每周汇总 |
| **目标受众** | 技术型、高管型、普通型或特定社区 | 普通型 |
| **语气** | 专业型、对话型、诙谐型或分析型 | 对话型-专业型 |
| **长度** | 短（5分钟阅读）、中等（10分钟）、长（15分钟+） | 中等 |
| **部分** | 内容部分的数量和类型 | 4-6部分 |
| **频率背景** | 一次性或定期系列的一部分 | 一次性 |

#### 第1.2步：定义新闻简报结构

根据格式，选择适当的结构：

**每日摘要结构**：
```
1. 重要新闻（1项，详细）
2. 快速聚焦（3-5项，简短）
3. 一项数据/每日名言
4. 值得关注的动态
```

**每周汇总结构**：
```
1. 编辑笔记/引言
2. 重要新闻（2-3项，详细）
3. 趋势与分析（1-2项，原创评论）
4. 快速简报（4-6项，简短摘要）
5. 工具与资源（2-3项）
6. 更多内容/结束语
```

**深度分析结构**：
```
1. 引言与背景
2. 背景/为何重要
3. 关键发展（详细分析）
4. 专家观点
5. 未来展望/影响
6. 深入阅读
```

**行业简报结构**：
```
1. 执行摘要
2. 市场发展
3. 公司新闻与动态
4. 产品与技术更新
5. 监管与政策变化
6. 数据与指标
7. 展望
```

### 第二阶段：研究与精选

#### 第2.1步：多源研究

使用网络搜索进行深入研究。**新闻简报的质量直接取决于研究和信息的质量与时效性。**

**搜索策略**：

```
# 当前新闻和发展
"[主题]新闻[当前月份][当前年份]"
"[主题]最新发展"
"[主题]本周公告"

# 趋势与分析
"[主题]趋势[当前年份]"
"[主题]分析专家观点"
"[主题]行业报告"

# 数据和统计
"[主题]统计数据[当前年份]"
"[主题]最新市场数据"
"[主题]增长指标"

# 工具与资源
"[主题]新工具[当前年份]"
"[主题]开源发布"
"最佳[主题]资源[当前年份]"
```

> **重要提示**：始终检查`<当前日期>`以确保搜索查询使用正确的时效性背景。切勿使用硬编码的年份。

#### 第2.2步：来源评估与选择

评估每个来源并精选最佳内容：

| 标准 | 优先级 |
|------|------|
| **时效性** | 优先选择过去7-30天的内容 |
| **权威性** | 优先考虑主要来源、官方公告、知名出版物 |
| **独特性** | 选择提供新视角或未被充分报道的故事 |
| **相关性** | 每个项目都必须明确与新闻简报声明主题相关 |
| **可操作性** | 优先选择读者可采取行动的内容（工具、见解、策略） |
| **多样性** | 混合新闻、分析、数据和实用资源 |

#### 第2.3步：深度内容提取

对于关键新闻，使用`web_fetch`读取全文并提取：

1. **核心事实** — 发生了什么，涉及谁，何时
2. **背景** — 为何重要，背景信息
3. **数据点** — 具体数字、指标或统计数据
4. **引言** — 相关专家引言或官方声明
5. **影响** — 对读者意味着什么

### 第三阶段：撰写

#### 第3.1步：新闻简报头部

每个新闻简报都以一致的头部开始：

```markdown
# [新闻简报名称]

*[标语或描述] — [日期]*

---

[可选：一句话预览内容]
```

#### 第3.2步：部分撰写指南

**重要新闻/精选项目**：
- **标题**：引人入胜、清晰、利益导向（非点击诱饵）
- **钩子**：让读者关心的开篇句子（1-2句）
- **正文**：关键事实和背景（2-4段）
- **为何重要**：与读者世界的联系（1段）
- **来源链接**：始终署名并链接到原始来源

**快速简报/简短项目**：
- **格式**：粗体标题 + 2-3句摘要 + 来源链接
- **重点**：每个项目传达一个关键见解
- **效率**：读者应能不点击即可获取核心见解

**分析/评论部分**：
- **语气**：新闻简报对趋势或发展的独特视角
- **结构**：观察 → 背景 → 影响 → （可选）可操作的见解
- **证据**：每个声明都有数据或来源支持

#### 第3.3步：撰写标准

| 原则 | 实施 |
|------|------|
| **可扫描性** | 使用标题、粗体文本、项目符号和短段落 |
| **吸引力** | 以最有趣的视角开头，而非按时间顺序 |
| **简洁性** | 每个句子都应有所贡献——无情删减填充内容 |
| **准确性** | 每个事实都有来源，每个数字都经过验证 |
| **署名性** | 始终通过内联链接署名原始来源 |
| **人性化** | 像一个知识渊博的朋友一样写作，而非新闻稿 |

**根据受众调整语气**：

| 受众 | 语气 | 示例 |
|------|------|------|
| **技术型** | 精确、无术语解释、假设专业知识 | "新API支持gRPC流式传输，通过流量控制窗口实现背压处理。" |
| **高管型** | 影响导向、底线、战略 | "此次收购使公司X在企业级市场的份额达到40%，直接威胁到Incumbent Y的定价权。" |
| **普通型** | 易于理解、类比、解释概念 | "把它想象成一个数据通用翻译器——它让任何应用都能与任何数据库进行交流，而无需学习新语言。"

### 第四阶段：组装与润色

#### 第4.1步：组装新闻简报

将所有部分按照选定的结构模板组合成最终文档。

#### 第4.2步：尾部

每个新闻简报都以以下内容结束：

```markdown
---

*[新闻简报名称]是[描述其内容]*。
*[如何订阅/分享/提供反馈]*

*来源：所有链接均以内联提供。本新闻简报精选和总结了公开可用的信息，并附有原创评论。*
```

#### 第4.3步：质量检查清单

在最终确定前，验证：

- [ ] **每个事实声明都有来源链接** — 无未署名的断言
- [ ] **所有链接都有效** — 从搜索结果中验证的URL
- [ ] **日期引用使用实际当前日期** — 无硬编码或假设的日期
- [ ] **内容是当前的** — 所有主要项目都在预期时间范围内
- [ ] **无重复新闻** — 每个项目只出现一次
- [ ] **格式一致** — 标题、项目符号、链接使用相同的风格
- [ ] **平衡覆盖** — 不被单一来源或视角主导
- [ ] **适当长度** — 符合指定的长度目标
- [ ] **吸引人的开头** — 前2句让读者想继续阅读
- [ ] **清晰的结尾** — 新闻简报以难忘或可操作的笔记结束
- [ ] **校对** — 无错别字、损坏的格式或不完整的句子

## 适应示例

### 技术新闻简报
- Emoji使用：✅ 适度（部分标题）
- 部分：重要新闻、深度分析、快速简报、开源焦点、开发工具
- 语气：技术型-对话型

### 商业/金融新闻简报
- Emoji使用：❌ 最少或无
- 部分：市场概览、交易流、公司新闻、数据角、展望
- 语气：专业型-分析型

### 行业特定新闻简报
- Emoji使用：适度
- 部分：监管更新、市场数据、创新观察、人事变动、活动
- 语气：专家-权威型

### 创意/营销新闻简报
- Emoji使用：✅ 自由使用
- 部分：活动亮点、趋势观察、本周热门、我们喜爱的工具、灵感
- 语气：热情型-专业型

## 输出处理

生成后：

- 将新闻简报保存到`/mnt/user-data/outputs/newsletter-{主题}-{日期}.md`
- 使用`present_files`工具向用户展示新闻简报
- 提供调整部分、语气、长度或重点区域的选项
- 如果用户需要HTML输出，请备注Markdown可以使用标准工具转换

## 注意事项

- 此技能与`deep-research`技能结合使用效果最佳，用于需要深度分析的新闻简报——需要两者配合使用
- 始终使用`<当前日期>`为搜索和新闻简报中的日期引用提供时效性背景
- 对于定期新闻简报，建议保持一致的结构，以便读者形成预期
- 精选时，质量胜于数量——5个优秀项目胜过15个平庸项目
- 正确署名所有内容——新闻简报通过透明的来源建立信任
- 避免总结无法访问的付费墙内容
- 如果用户提供特定URL或文章要求包含，请将它们与您的精选发现一起使用
- 新闻简报应提供足够的摘要价值，即使读者不点击每个链接也能受益
