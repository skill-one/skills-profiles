# 专业研究报告技能

## 概述

该技能可生成专业级别的咨询级研究报告，以 Markdown 格式呈现，涵盖**市场分析、消费者洞察、品牌战略、财务分析、行业研究、竞争情报、投资研究以及宏观经济分析**等领域。其运作分为两个截然不同的阶段：

1. **阶段 1 — 分析框架生成**：针对研究主题，生成严谨的分析框架，包括章节结构、各章节数据需求、分析逻辑和可视化计划。
2. **阶段 2 — 报告生成**：在数据由其他技能收集后，将所有输入整合为最终精炼的报告。

输出报告遵循麦肯锡/BCG 咨询标准。报告语言遵循 `output_locale` 设置（默认：`zh_CN` 为中文）。

## 数据真实性协议

**严格遵循规则**：报告中呈现的所有数据以及在图表中可视化的数据**必须直接来源于提供的** **数据摘要**或**外部搜索发现**。
- **禁止幻觉**：不得编造、估计或模拟数据。如果数据缺失，应声明“数据不可用”，而不是编造数字。
- **可追溯来源**：每个主要论点和图表都必须可追溯到输入数据包。

## 核心能力

- **从零开始设计分析框架**：仅根据研究主题和范围设计分析框架
- 将原始数据转换为结构化、高深度的研究报告
- 遵循每个子章节的**“可视化锚点 → 数据对比 → 综合分析”**流程
- 生成遵循**“数据 → 用户心理 → 战略启示”**链的洞察
- 嵌入预生成的图表并构建对比表格
- 生成符合**GB/T 7714-2015**标准的行内引用格式
- 以专业咨询口吻，按 `output_locale` 指定的语言输出报告
- 根据领域（营销、财务、行业等）调整分析深度和结构

## 何时使用此技能

**始终加载此技能当**：

- 用户要求市场分析、消费者洞察报告、财务分析、行业研究或任何咨询级分析报告
- 用户提供研究主题，需要在数据收集前获得结构化分析框架
- 用户提供数据摘要、分析框架或图表文件，需要将其整合为报告
- 用户需要专业咨询风格的研究报告
- 任务涉及将研究发现的转化为结构化的战略叙事

# 阶段 1：分析框架生成

## 目的

针对**研究主题**（例如，“Z世代护肤品市场分析”、“NEV行业竞争格局”、“品牌X消费者画像”），生成完整的**分析框架**，作为下游数据收集和最终报告生成的蓝图。

## 阶段 1 输入

| 输入 | 描述 | 是否必需 |
|-------|-------------|----------|
| **研究主题** | 要分析的主题或问题 | 是 |
| **范围 / 限制** | 地理范围、时间范围、行业细分、目标受众等 | 非必需 |
| **具体角度** | 用户希望探索的任何特定角度或假设 | 非必需 |
| **领域** | 分析领域：市场、财务、行业、品牌、消费者、投资等 | 推断 |

## 阶段 1 工作流程

### 步骤 1.1：理解研究主题

- 解析研究主题以识别**核心实体**（市场、品牌、产品、行业、消费者细分、金融工具等）
- 确定分析领域（营销、财务、行业、竞争、消费者、投资、宏观等）
- 根据领域确定**自然分析维度**：

| 领域 | 典型维度 |
|--------|--------------------|
| 市场分析 | 市场规模、增长趋势、市场细分、增长驱动因素、竞争格局、消费者画像 |
| 品牌分析 | 品牌定位、市场份额、消费者认知、营销策略、竞争对手对比 |
| 消费者洞察 | 人口统计画像、购买行为、决策旅程、痛点、情景分析 |
| 财务分析 | 宏观环境、行业趋势、公司基本面、财务指标、估值、风险评估 |
| 行业研究 | 价值链分析、市场规模、竞争格局、政策环境、技术趋势、进入壁垒 |
| 投资尽职调查 | 商业模式、财务健康状况、管理层评估、市场机会、风险因素、退出路径 |
| 竞争情报 | 竞争对手识别、战略对比、SWOT分析、差异化定位、市场动态 |

### 步骤 1.2：选择分析框架和模型

根据已识别的领域和研究主题，选择**一个或多个**专业分析框架来构建每章的推理。所选框架指导章节结构（步骤 1.3）中的**分析逻辑**。

#### 战略与环境分析

| 框架 | 描述 | 适用于 |
|-------|-------------|----------|
| **SWOT分析** | 优势、劣势、机会、威胁 | 品牌评估、竞争定位、战略规划 |
| **PEST / PESTEL分析** | 政治、经济、社会、技术 (+ 环境、法律) | 宏观环境扫描、市场进入评估、政策影响分析 |
| **波特五力模型** | 供应商议价能力、购买者议价能力、新进入者威胁、替代品威胁、行业竞争 | 行业竞争格局、进入壁垒评估、利润率分析 |
| **波特钻石模型** | 要素条件、需求条件、相关产业、企业战略与结构 | 国家/区域竞争优势分析 |
| **VRIO分析** | 价值、稀缺性、可模仿性、组织 | 核心能力评估、资源优势分析 |

#### 市场与增长分析

| 框架 | 描述 | 适用于 |
|-------|-------------|----------|
| **STP分析** | 市场细分、目标市场、定位 | 市场细分、目标市场选择、品牌定位 |
| **BCG矩阵（增长-份额矩阵）** | 明星、金牛、问题、瘦狗 | 产品组合管理、资源配置决策 |
| **安索夫矩阵** | 市场渗透、市场开发、产品开发、多元化 | 增长战略选择 |
| **产品生命周期（PLC）** | 引入期、增长期、成熟期、衰退期 | 产品战略制定、市场时机决策 |
| **TAM-SAM-SOM** | 总计 / 可服务 / 可获得市场 | 市场规模量化、机会量化 |
| **技术采用生命周期** | 创新者 → 早期采用者 → 早期大众 → 晚期大众 → 滞后者 | 新兴技术/类别渗透分析 |

#### 消费者与行为分析

| 框架 | 描述 | 适用于 |
|-------|-------------|----------|
| **消费者决策旅程** | 认知 → 考虑 → 评估 → 购买 → 忠诚 | 消费者行为路径映射、触点优化 |
| **AARRR漏斗（海盗指标）** | 获取、激活、留存、收入、推荐 | 用户增长分析、转化率优化 |
| **RFM模型** | 近期性、频率、金额 | 客户价值细分、精准营销 |
| **马斯洛需求层次理论** | 生理 → 安全 → 社交 → 尊重 → 自我实现 | 消费者心理分析、产品价值主张 |
| **工作要完成（JTBD）** | 用户在特定情境下需要完成的“工作” | 需求洞察、产品创新方向 |

#### 财务与估值分析

| 框架 | 描述 | 适用于 |
|-------|-------------|----------|
| **杜邦分析** | ROE = 净利润率 × 资产周转率 × 权益乘数 | 盈利能力分解、财务健康状况诊断 |
| **DCF（折现现金流）** | 自由现金流折现 | 企业/项目估值 |
| **可比公司分析** | PE、PB、PS、EV/EBITDA倍数比较 | 相对估值、同行基准比较 |
| **EVA（经济增加值）** | 税后营业利润 - 资本成本 | 价值创造能力评估 |

#### 竞争与战略定位

| 框架 | 描述 | 适用于 |
|-------|-------------|----------|
| **标杆管理** | 关键绩效指标逐项比较 | 竞争对手差距分析、最佳实践识别 |
| **战略群组图** | 沿两个关键维度对竞争对手进行聚类 | 竞争格局可视化、空白空间识别 |
| **价值链分析** | 主要活动 + 支持活动价值分解 | 成本优势来源、差异化机会识别 |
| **蓝海战略** | 价值曲线、四个行动框架（消除-减少-提升-创造） | 差异化创新、新市场空间创造 |
| **感知图** | 沿两个消费者感知维度绘制品牌定位 | 品牌定位分析、市场空白发现 |

#### 选择原则

1. **领域优先**：根据步骤 1.1 中识别的领域，从上述工具包中选择**2-4**个最相关的框架
2. **互补性**：选择互补的框架而不是重叠的框架（例如，宏观层面的PESTEL + 微观层面的波特五力模型）
3. **深度优于广度**：深入应用2个框架比肤浅堆叠6个更好
4. **数据可行性**：所选框架必须由下游数据收集技能支持——如果框架所需的数据无法合理获取，则降级或替换
5. **明确映射**：在章节结构中，明确标注每个章节使用的框架及其应用方式

#### 框架选择输出格式

```markdown
## 框架选择

| 章节 | 选择的框架 | 应用 |
|-------|----------------------|-------------|
| 市场规模与增长趋势 | TAM-SAM-SOM + 产品生命周期 | TAM-SAM-SOM用于量化市场空间，PLC用于确定市场阶段 |
| 竞争格局评估 | 波特五力模型 + 战略群组图 | 五力模型用于评估行业竞争强度，群组图用于可视化竞争定位 |
| 消费者画像 | RFM + 消费者决策旅程 | RFM用于细分客户价值，决策旅程用于识别关键转化节点 |
| 品牌战略建议 | SWOT + 蓝海战略 | SWOT用于总结整体格局，蓝海战略用于指导差异化方向 |
```

### 步骤 1.3：设计章节结构

生成分层章节结构。每个章节必须包括：

1. **章节标题** — 专业、简洁、主题化（遵循格式化部分中的标题约束）
2. **分析目标** — 本章旨在揭示什么
3. **分析逻辑** — 章节中的推理链或框架（必须引用步骤 1.2 中选择的框架）
4. **核心假设** — 预先假设，待数据验证或证伪

#### 章节结构输出格式

```markdown
## 分析框架

### 章节 1: [标题]
- **分析目标**: [本章旨在...]
- **分析逻辑**: [使用的框架或推理链]
- **核心假设**: [待验证的假设]
- **数据需求**: (见步骤 1.4)
- **可视化计划**: (见步骤 1.5)

### 章节 2: [标题]
...
```

### 步骤 1.4：定义每章节的数据查询需求

针对每个章节，指定**需要收集的确切数据**。这是连接到下游数据收集技能的桥梁。

每个数据需求条目必须包括：

| 字段 | 描述 |
|-------|-------------|
| **数据指标** | 需要的具体指标或数据点（例如，“2020-2025年中国护肤品市场规模（以十亿人民币计）”） |
| **数据类型** | 定量、定性或混合 |
| **建议来源** | 建议的数据来源类别：行业报告、财务报表、政府统计数据、社交媒体、电商平台、调查数据、新闻 |
| **搜索关键词** | 建议用于数据收集代理的搜索查询 |
| **优先级** | P0（必需） / P1（重要） / P2（补充） |
| **时间范围** | 数据应涵盖的时间段 |

#### 数据需求输出格式（每章节）

```markdown
#### 数据需求

| # | 数据指标 | 数据类型 | 建议来源 | 搜索关键词 | 优先级 | 时间范围 |
|---|-------------|-----------|-------------------|-----------------|----------|------------|
| 1 | 市场规模（十亿人民币） | 定量 | 行业报告，政府统计数据 | "2024年中国护肤品市场规模" | P0 | 2020-2025 |
| 2 | CAGR | 定量 | 行业报告 | "护肤品CAGR增长率" | P0 | 2020-2025 |
| 3 | 子类别份额 | 定量 | 电商平台，行业报告 | "护肤品类别份额乳液精华防晒" | P1 | 最新 |
| 4 | 政策与监管更新 | 定性 | 政府公告，新闻 | "2024年化妆品监管" | P2 | 过去1年 |
```

### 步骤 1.5：定义每章节的可视化与内容结构

针对每个章节，指定最终报告的**计划可视化**和**内容结构**：

| 字段 | 描述 |
|-------|-------------|
| **可视化类型** | 图表类型：折线图、柱状图、饼图、散点图、雷达图、热力图、桑基图、对比表格等 |
| **可视化标题** | 描述性标题 |
| **可视化数据映射** | 哪些数据指标映射到X轴/Y轴或分段 |
| **对比表格设计** | 列标题和对比维度 |
| **论证结构** | 计划的“是什么 → 为什么 → 有什么”叙事大纲 |

#### 可视化计划输出格式（每章节）

```markdown
#### 可视化与内容计划

**图表 1**: [类型] — [标题]
- X轴: [维度], Y轴: [指标]
- 数据来源: 对应数据需求 #1, #2

**对比表格**:
| 维度 | 项目 A | 项目 B | 项目 C |
|-------|--------|--------|--------|

**论证结构**:
1. **观察 (是什么)**: [数据揭示的表面现象]
2. **归因 (为什么)**: [驱动因素或潜在原因]
3. **启示 (有什么)**: [战略启示或建议行动]
```

# 阶段 1→2 过渡：数据收集与图表生成

分析框架生成后，将其转交给**其他数据收集技能**（例如，深度研究、数据分析、网络搜索代理）：

1. 执行每个章节数据需求中的**搜索关键词**
2. 收集定量数据、定性洞察和来源 URL
3. 根据计划可视化生成图表
4. 返回包含以下内容的**数据包**：
   - **数据摘要**：每章节的原始数字、指标和定性发现
   - **图表文件**：生成的图表图像及其本地文件路径
   - **外部搜索发现**：用于行内引用的来源 URL 和摘要

> **此技能不执行数据收集。** 它仅生成框架（阶段 1）和最终报告（阶段 2）。
>
> **图表生成**：如果存在可视化/图表技能（例如，数据分析、图像生成），则可将图表生成推迟到阶段 2 的开始——见步骤 2.3。

# 阶段 2：报告生成

## 目的

接收上游完成的**分析框架**和**数据包**，并将它们整合为最终咨询级报告。

## 阶段 2 输入

| 输入 | 描述 | 是否必需 |
|-------|-------------|----------|
| **分析框架** | 阶段 1 生成的框架文档 | 是 |
| **数据摘要** | 数据收集阶段按章节组织的收集数据 | 是 |
| **图表文件** | 生成的图表图像的本地文件路径。如果未提供，将使用可用的可视化技能在步骤 2.3 中生成 | 非必需 |
| **外部搜索发现** | 用于行内引用的 URL 和摘要 | 非必需 |

## 阶段 2 工作流程

### 步骤 2.1：接收和验证输入

验证所有必需输入是否存在：

1. **分析框架** — 确认其包含章节结构、数据需求和可视化计划
2. **数据摘要** — 确认其包含按章节组织的数据，与 P0 要求进行交叉引用
3. **图表文件** — 确认文件路径是有效的本地路径

如果任何 P0 数据缺失，请在报告中注明，并标记给用户。

### 步骤 2.2：映射报告结构

根据分析框架映射最终报告结构：

1. **摘要** — 执行摘要，包含关键要点
2. **引言** — 背景、目标、方法
3. **主体章节 (2...N)** — 映射自框架的章节结构
4. **结论** — 纯粹客观的综合
5. **参考文献** — GB/T 7714-2015 格式的参考文献

### 步骤 2.3：生成章节图表（报告可视化前）

在开始撰写报告之前，根据分析框架的**可视化与内容计划**生成所有图表。这确保了每个子章节在叙事开始之前都有其“可视化锚点”准备就绪。

#### 执行此步骤的条件

- **图表文件已提供**：跳过此步骤——直接进入步骤 2.4。
- **图表文件未提供但存在可视化技能**：执行此步骤以首先生成所有图表。
- **无图表文件且无可视化技能可用**：跳过此步骤——使用对比表格作为主要可视化锚点，并在步骤 2.4 中注明图表的缺失。

#### 图表生成工作流程

1. **提取图表任务**：从分析框架的 `Visualization & Content Plan` 条目中解析构建图表任务列表：

| # | 章节 | 图表类型 | 图表标题 | 数据映射 | 数据来源 |
|---|---------|------------|-------------|--------------|-------------|
| 1 | 2.1 | 折线图 | 市场规模趋势 2020-2025 | X: 年份, Y: 市场规模 (十亿人民币) | 数据需求 #1, #2 |
| 2 | 3.1 | 饼图 | 消费者年龄分布 | 分段: 年龄组, 值: 百分比 | 数据需求 #5 |
| ... | ... | ... | ... | ... | ... |

2. **准备图表数据**：针对每个图表任务，从**数据摘要**中提取相应的数据点。
   > **关键原则**: 仅使用数据摘要中的数字。不要编造或“平滑”数据以使图表看起来更好。如果数据点缺失，图表必须反映现实（例如，断线或缺失条形），或者必须调整图表类型。

3. **委托给可视化技能**: 使用可用的可视化/图表技能（例如，`data-analysis`）为每个图表任务执行，并提供：
   - 图表类型和标题
   - 结构化数据
   - 轴标签和格式化偏好
   - 输出文件路径约定：`charts/chapter_{N}_{图表索引}.png`

4. **收集图表文件路径**: 记录所有生成的图表文件路径，用于步骤 2.4 中的嵌入：

```markdown
## 生成的图表
| # | 章节 | 图表标题 | 文件路径 |
|---|---------|-------------|-----------|
| 1 | 2.1 | 市场规模趋势 2020-2025 | charts/chapter_2_1.png |
| 2 | 3.1 | 消费者年龄分布 | charts/chapter_3_1.png |
```

5. **验证**: 确认所有 P0 优先级图表已生成。如果任何图表生成失败，请记录并回退到该子章节使用对比表格。

> **原则**: 在开始报告写作之前，完成所有图表生成。这确保了一致的视觉叙事，并避免在写作过程中生成与写作交织。

### 步骤 2.4：撰写报告

针对每个子章节，遵循**“可视化锚点 → 数据对比 → 综合分析”**流程：

1. **可视化证据块**: 使用 `![Image Description](Actual_File_Path)` 嵌入图表——使用步骤 2.3 收集的文件路径
2. **数据对比表格**: 创建 Markdown 对比表格，用于关键指标
   > **来源规则**: 表格中的每个数字都必须来自数据摘要。不要幻觉。
3. **综合叙事分析**: 按照数据 → 用户心理 → 战略启示链撰写分析文本
   > **叙事规则**: 叙事必须解释提供的数据。不要做出未经输入支持的主张。

每个子章节必须以一个**至少 200 字**的分析段落结束，该段落必须：
- 综合冲突或支持的数据点
- 揭示潜在的用户张力或机会
- **可选**: 如果有一个简洁有力的“一句话真理”，请在最后使用**引用块** (`>`) 来锚定该部分。

### 步骤 2.5：最终结构自我检查

在输出之前，确认报告包含**按顺序**的所有部分：

```
摘要 → 1. 引言 → 2...N. 主体章节 → N+1. 结论 → N+2. 参考文献
```

此外验证：
- 所有在步骤 2.3 生成的图表都嵌入在正确的子章节中
- 图表文件路径在 `![](path)` 引用中有效
- 子章节没有图表的对比表格作为可视化锚点

报告**必须**在结论之后输出——**必须**包括参考文献作为最后一部分。

## 格式与语气标准

### 咨询语气
- **语气**: 麦肯锡/BCG — 权威、客观、专业
- **语言**: 所有标题和内容按 `output_locale` 指定的语言
- **数字格式**: 使用英文逗号作为千位分隔符 (`1,000` 不 `1，000`)
- **数据强调**: **加粗**重要的观点和关键数字

### 标题约束
- **编号**: 使用标准编号 (`1.`, `1.1`) 直接后跟标题
- **禁止前缀**: **不得**使用“章节”、“部分”、“部分”作为前缀
- **允许的语气词**: 分析、画像、概述、洞察、评估
- **禁止的词**: “解码”、“DNA”、“秘密”、“心智地图”、“太阳系”、“解锁”

### 子章节结论
- **要求**: 每个子章节必须以一个**至少 200 字**的分析段落结束。
- **叙事流程**: 该段落必须看起来是文本的自然延续。它必须将该部分的发现综合成战略判断。
- **内容逻辑**:
    1. 综合上述冲突或支持的数据点。
    2. 揭示**潜在的**用户张力或机会。
    3. 关键洞察: **可选**: 只有当您有一个简洁有力的“一句话真理”时，才将其放在最后，使用**引用块** (`>`) 来锚定该部分。

### 洞察深度（“有什么”链）

每个洞察都必须连接**数据 → 用户心理 → 战略启示**:

```
❌ 错误的: "女性占 60%。战略：瞄准女性。"

✅ 正确的: "女性占 60%，TGI 为 180。**这表明**购买决策受审美和社会认可驱动，而非纯粹实用。**因此**，媒体支出应转向视觉重平台（例如，RED/Instagram）以最大化点击率，将男性受众视为次要赠品群体。
```

### 参考文献
- **行内**: 使用 Markdown 链接作为来源 (例如 `[Source Title](URL)`) 当使用外部搜索发现时
- **参考文献部分**: 严格遵循 **GB/T 7714-2015**

### Markdown 规则
- **立即开始**: 直接以 `# 报告标题` 开始——没有引言文本
- **无分隔符**: **不得**使用水平规则 (`---`)
