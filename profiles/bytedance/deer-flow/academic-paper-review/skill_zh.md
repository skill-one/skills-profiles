# 学术论文评审技能

## 概述

该技能能够生成结构化、同行评审质量的学术论文和研究出版物分析。它遵循顶级会议（NeurIPS、ICML、ACL、Nature、IEEE）所使用的既定学术评审标准，以提供严谨、建设性和平衡的评估。

评审内容涵盖**摘要、优势、劣势、方法评估、贡献评价、文献定位和可操作的改进建议**——所有内容均基于论文本身的证据。

## 核心功能

- 解析并理解从上传的PDF或获取的URL中提供的学术论文
- 生成遵循顶级会议评审模板的结构化评审
- 评估方法严谨性（实验设计、统计有效性、可复现性）
- 评估贡献的新颖性和重要性
- 通过目标文献检索将工作置于更广泛的研究领域之中
- 识别局限性、差距和潜在改进点
- 生成详细的评审和简洁的执行摘要格式
- 支持任何科学领域的论文（计算机科学、生物学、物理学、社会科学等）

## 何时使用此技能

**始终加载此技能的情况：**

- 用户提供了论文URL（arXiv、DOI、会议论文集、期刊链接）
- 用户上传了研究论文或预印本的PDF
- 用户要求“评审”、“分析”、“批判”、“评估”或“总结”一篇研究论文
- 用户想了解一项研究的优势和劣势
- 用户要求对学术工作进行同行评审式的评估
- 用户请求帮助准备会议或期刊投稿的评审

## 评审方法

### 第一阶段：论文理解

在形成任何判断之前，彻底阅读和理解论文。

#### 第1.1步：识别论文元数据

提取并记录：

| 字段 | 描述 |
|-------|-------------|
| **标题** | 完整论文标题 |
| **作者** | 作者列表和所属机构 |
| **会议/状态** | 出版会议、预印本服务器或投稿状态 |
| **年份** | 出版或投稿年份 |
| **领域** | 研究领域和子领域 |
| **论文类型** | 经验性、理论性、综述、立场论文、系统论文等 |

#### 第1.2步：深度阅读遍历

系统阅读论文：

1. **摘要 & 引言** — 确定所声称的贡献和动机
2. **相关工作** — 注意作者如何将其工作与现有技术进行定位
3. **方法** — 详细理解所提出的方法、模型或框架
4. **实验 / 结果** — 检查数据集、基线、指标和报告的结果
5. **讨论 & 局限性** — 注意作者是否自我识别了任何局限性
6. **结论** — 将结论性声明与实际呈现的证据进行比较

#### 第1.3步：关键声明提取

明确列出论文的主要声明：

```
声明1：[关于贡献或发现的特定声明]
证据：[论文中支持此声明的证据]
强度：[强 / 中等 / 弱]

声明2：[/...]
...
```

### 第二阶段：批判性分析

#### 第2.1步：文献背景搜索

使用网络搜索了解研究格局：

```
搜索查询：
- "[论文主题] 当前年份 研究现状"
- "[关键方法名] 比较基准"
- "[作者] 先前工作 [主题]"
- "[特定技术] 局限性 批评"
- "综述 [研究领域] 近期进展"
```

使用 `web_fetch` 对关键相关论文或综述进行检索，以了解这项工作如何契合其中。

#### 第2.2步：方法评估

使用以下框架评估方法：

| 标准 | 问题 | 评分 |
|-----------|-----------------|--------|
| **可靠性** | 该方法在技术上是否正确？是否存在逻辑错误？ | 1-5 |
| **新颖性** | 真正的新颖性 vs. 逐步改进？ | 1-5 |
| **可复现性** | 详细信息是否足够复现？代码/数据是否可用？ | 1-5 |
| **实验设计** | 基线是否公平？消融是否充分？数据集是否合适？ | 1-5 |
| **统计严谨性** | 结果是否具有统计学意义？是否报告了误差线？是否多次运行？ | 1-5 |
| **可扩展性** | 该方法是否可扩展？是否讨论了计算成本？ | 1-5 |

#### 第2.3步：贡献重要性评估

评估重要性级别：

| 级别 | 描述 | 标准 |
|-------|-------------|----------|
| **里程碑** | 基本改变了该领域 | 新范式，广泛适用的突破 |
| **重要** | 强贡献推动技术前沿 | 清晰的改进，有充分证据 |
| **中等** | 有用的贡献但有某些局限性 | 逐步但有效的改进 |
| **边缘** | 对现有工作只有微小进步 | 小幅增益，适用范围狭窄 |
| **低于标准** | 未达到发表标准 | 基本缺陷，证据不足 |

#### 第2.4步：优势和劣势分析

针对每个优势或劣势，提供：
- **是什么**：具体观察
- **在哪里**：章节/图表/表格引用
- **为什么重要**：对论文声明或实用性的影响

### 第三阶段：评审综合

#### 第3.1步：组装结构化评审

使用以下模板生成最终评审。

## 评审输出模板

```markdown
# 论文评审：[论文标题]

## 论文元数据
- **作者**：[作者列表]
- **会议**：[出版会议或预印本服务器]
- **年份**：[年份]
- **领域**：[研究领域]
- **论文类型**：[经验性 / 理论性 / 综述 / 系统 / 立场]

## 执行摘要

[2-3段摘要，总结论文的核心贡献、方法、主要发现。在开头直接陈述你的整体评估：论文的优势、不足之处，以及其贡献是否足以达到所声称的会议/影响水平。]

## 贡献摘要

1. [第一个声称的贡献——一句话]
2. [第二个声称的贡献——一句话]
3. [其他贡献（如有）]

## 优势

### S1：[简洁的优势标题]
[详细解释，并引用论文中的具体章节、图表或表格。解释为什么这是一个优势及其意义。]

### S2：[简洁的优势标题]
[...]

### S3：[简洁的优势标题]
[...]

## 劣势

### W1：[简洁的劣势标题]
[详细解释，并引用具体内容。解释这种劣势对论文声明的影响。建议如何解决。]

### W2：[简洁的劣势标题]
[...]

### W3：[简洁的劣势标题]
[...]

## 方法评估

| 标准 | 评分 (1-5) | 评估 |
|-----------|:---:|------------|
| 可靠性 | X | [简要说明] |
| 新颖性 | X | [简要说明] |
| 可复现性 | X | [简要说明] |
| 实验设计 | X | [简要说明] |
| 统计严谨性 | X | [简要说明] |
| 可扩展性 | X | [简要说明] |

## 作者问题

1. [具体问题，澄清疑虑或模糊之处]
2. [关于方法选择或替代方法的问题]
3. [关于泛化性或实际适用性的问题]

## 小问题

- [拼写错误、格式问题、不清晰的图表、符号不一致]
- [应引用的缺失参考文献]
- [建议提高清晰度的建议]

## 文献定位

[这项工作如何与当前技术前沿相关？是否引用了关键相关工作？比较是否公平和全面？缺失了哪些重要相关工作？]

## 建议

**整体评估**：[接受 / 弱接受 / 边界 / 弱拒绝 / 拒绝]

**信心**：[高 / 中 / 低] — [信心级别的理由]

**贡献级别**：[里程碑 / 重要 / 中等 / 边缘 / 低于标准]

### 可操作的改进建议
1. [具体的建设性建议]
2. [具体的建设性建议]
3. [具体的建设性建议]
```

## 评审原则

### 建设性批评
- **始终建议如何改进** — 不要只指出问题；提出解决方案
- **给予应有的认可** — 即使在有缺陷的论文中，也要承认真实的贡献
- **具体** — 引用具体的章节、方程、图表和表格
- **区分主次** — 区分致命缺陷和可修复问题

### 客观标准
- ❌ "这篇论文写得不好"（模糊、无帮助）
- ✅ "第3.2节引入了未正式定义的符号X，使得定理1的证明难以理解。考虑在问题陈述后添加符号表。"（具体、可操作）

### 伦理评审实践
- 不要根据作者声誉或所属机构否定工作
- 基于自身 merits 评估工作
- 建设性地指出潜在伦理问题（数据集偏差、双重用途影响）
- 维护未发表论文的保密性

## 不同论文类型的适应性

| 论文类型 | 重点领域 |
|------------|-------------|
| **经验性** | 实验设计、基线、统计显著性、消融、可复现性 |
| **理论性** | 证明正确性、假设合理性、界限的紧密性、与实践的联系 |
| **综述** | 全面性、分类质量、对近期工作的覆盖、综合见解 |
| **系统** | 架构决策、可扩展性证据、实际部署、工程贡献 |
| **立场** | 论证连贯性、声明证据、影响潜力、描述的公平性 |

## 应避免的常见错误

- ❌ 评审你希望写出的论文，而不是提交的论文
- ❌ 要求进行范围不合理的额外实验
- ❌ 因为论文没有解决不同的问题而对其进行惩罚
- ❌ 过度受写作质量而非技术贡献的影响
- ❌ 将与自己的工作缺乏比较视为弱点
- ❌ 只提供摘要而不进行批判性分析

## 质量检查清单

在最终确定评审前，验证：

- [ ] 完整阅读了论文（不只是摘要和引言）
- [ ] 所有主要声明都已被识别，并对照证据进行评估
- [ ] 提供了至少3个优势和3个劣势，并附有具体引用
- [ ] 方法评估表完整，包含评分和理由
- [ ] 作者问题针对真实的模糊之处，而不是修辞批评
- [ ] 进行了文献检索，以定位贡献
- [ ] 建议是可操作的、建设性的
- [ ] 整体评估与识别的优势和劣势一致
- [ ] 评审语气专业且尊重
- [ ] 小问题与主要问题分开

## 输出格式

- 以 **Markdown** 格式输出完整评审
- 在沙盒中工作时，将评审保存到 `/mnt/user-data/outputs/review-{论文主题}.md`
- 使用 `present_files` 工具向用户展示评审

## 注意事项

- 此技能补充 `deep-research` 技能——当用户希望将论文置于更广泛领域的背景下进行评审时，加载两者
- 对于被付费墙挡住的论文，使用可获取的内容（摘要、公开版本、预印本镜像）
- 根据用户需求调整评审深度：快速筛选的简要评估 vs. 提交准备的完整评审
- 在比较多个论文时，在所有评审中保持一致的评判标准
- 始终披露评审的局限性（例如，“我未能详细验证附录B中的证明”）
