# Git 提交

从当前工作区创建精心设计的本地提交。不推送，不创建 PR — 使用 `ce-commit-push-pr` 进行完整的发布流程。

**完成时：** 每个逻辑变更都使用明确的文件列表和说明结果的提交信息进行提交，并且 `git status` 显示这些变更已清理。**停止时：** 树已清理（无内容可提交）。

## 背景

每个命令都作为其 **独立的** shell 工具调用（仅程序+参数）。不要使用 `;`、`&&`、`||`、管道、`$(...)` 或重定向连接它们 — 这种语法在 Windows PowerShell 下会失败。非零退出状态是正常状态，不应将其视为失败来抑制。

| 命令 | 目的 | 非零/空值表示 |
| --- | --- | --- |
| `git status` | 工作区状态 | 不是 git 仓库 — 停止 |
| `git diff HEAD` | 未提交的变更 | 未出生的仓库 / 尚无提交 |
| `git branch --show-current` | 当前分支 | 空值 = 分离的 HEAD |
| `git log --oneline -10` | 最近消息样式 | 未出生的仓库 — 无历史记录 |
| `git rev-parse --abbrev-ref origin/HEAD` | 远程默认分支 | 无 `origin/HEAD` / 空的 `HEAD` — 尝试 `gh repo view --json defaultBranchRef --jq '.defaultBranchRef.name'`，否则 `main` |

将其视为快照。在提交前立即重新读取分支和暂存集，如果可能已发生任何变更。

**默认分支名称：** 从 `origin/HEAD` 中移除前导 `origin/`（所以 `origin/trunk` → `trunk`）。使用该裸名称进行所有“在默认分支上？”的检查 — 永远不要与 `origin/<name>` 进行比较。

## 工作流程

0. **收集** — 运行上述所有背景命令（每个命令作为独立的 shell 调用），然后继续。

1. **无内容可提交** — 如果 `git status` 显示没有暂存、修改或未跟踪的文件，则报告该信息并停止。不要单独使用 `git diff HEAD` 作为清洁度检查（它会遗漏未跟踪的文件）。

2. **先处理分支** — 如果分离的 HEAD，或位于默认分支（`main` / `master` / 上述裸默认名称），则从变更内容创建特性分支（`git checkout -b <name>`），然后重新读取 `git branch --show-current`。不要询问 — 提交操作仍然不能只在工作区或默认分支上。如果派生名称已存在，选择一个不冲突的后缀。

3. **约定** — 匹配项目中已有的提交约定；否则匹配最近的日志模式；否则使用常规提交（`类型(范围): 描述`）。当使用常规提交并且 `fix`/`feat` 都适用时，默认使用 `fix:`（修复损坏或缺失的行为）；保留 `feat:` 用于新功能。用户覆盖优先。

4. **逻辑提交** — 如果变更文件明显分为不同的关注点，则分别提交（仅文件级别，最多 2-3 个，不使用 `git add -p`）。如果模糊不清，则一个提交。

5. **消息** — 主题是祈使句，命名结果（现在可能是什么或已修复什么），而不是文件列表。只有当动机或权衡在主题中不明显时才添加正文。当已经为本次提交持有计划实现单元 ID（对话、调用者或文件属于一个单元）时，将单元的 U-ID 括号附加到末尾 — `(U3)` 表示单元 3。不要寻找计划。当提交跨越单元、单元不明确或没有计划时，省略。

   - 坏：`Update checkout.rb` / `Add tests and fix stuff`
   - 好：`Fix double-submit on checkout`
   - 好：`Add per-subscription mute (U3)`

6. **暂存和提交** — 仅暂存 **命名的文件**（永远不要 `git add -A` 或 `git add .`）。如果调用包含 `exclude:<paths>`，则尊重它：这些文件保持未提交，无论其他什么变更；在报告中说明它们被遗漏了。使用文件写入工具将完整消息（主题行、空行、可选正文）写入仓库外部的文件，然后以每个提交组两个调用暂存和提交：

```bash
git add file1 file2 file3
```

```bash
git commit -F <message-file> -- file1 file2 file3
```

没有 shell 解析 `-F` 中的消息：`$`、引号、反引号或多行正文在任何 shell 下都按字面传递，无需满足引号规则。Git 的正常空白清理仍然适用（尾随空格被修剪，空行运行被折叠），这对提交消息来说很好。

`git commit` 上的尾随路径列表是必需的：裸 `git commit` 会获取整个索引，所以在此运行之前已经暂存的任何内容（调用者的 `exclude:` 路径，或用户暂存但未命名的文件）会一起进入提交。命名路径会精确提交该组并让其他索引条目保持不变。

7. **确认** — `git status`；报告哈希值和主题。
