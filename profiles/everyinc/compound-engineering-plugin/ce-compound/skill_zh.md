# /ce-compound

**结果：** 一个合格的已解决问题被写入 `<root>/solutions/` 下作为持久性学习记录，与当前树关联，可被下一个代理发现。

**完成：** 一个合格的文档被写入或更新，其 frontmatter 和声明被验证，词汇捕获被记录，并发出模式的完成报告；当没有学习符合资格时，不写入任何内容，报告说明原因。

**每次运行一个学习。** 一个会话如果产生了多个结果，将获得多个连续运行，绝不会进行批量运行。阅读 `references/research.md`；它解释了批量处理会破坏什么。

## 前置条件

仅记录一个已解决并经过验证的问题。

<!-- ce-durable-bar:start -->
一个学习只有在它包含不可从最终代码、测试、类型、注释或现有文档中轻易恢复的持久性项目推理时，才能获得其位置，并且失去它可能会合理地导致重复、实质性风险或大量重新发现。应用这个反事实：如果学习文档消失，一个未来的工程师在阅读最终实现时是否仍然可能重复错误或进行大量调查？完成度、努力程度和差异大小并不能确定其资格。
<!-- ce-durable-bar:end -->

如果反事实失败，则不写入任何内容并报告原因。从会话中判断，而不是询问。显式调用请求立即进行判断，但不会降低标准。

一个现有的学习如果变得实质性不准确或不完整，则符合资格，因为保留它可能会误导。更新该学习，而不是创建一个重复的。

`ce-compound` 不会引导 `CONCEPTS.md`。它会作为副作用播种学习自己的区域，绝不会引导整个仓库。向 `ce-compound-refresh` 发送一个独立的请求来创建或引导该文件，然后退出。

## 模式检测

```bash
/ce-compound [简要上下文]
/ce-compound mode:non-interactive depth:lightweight [上下文]
/ce-compound mode:non-interactive depth:full [上下文]
```

在以下**任一**情况下进入非交互模式：你被调用的参数中包含 `mode:non-interactive` 标记或其已弃用的别名 `mode:headless`，**或者**调用使其非交互意图明确，例如调用者或站立指令要求以“headless”、“non-interactively”、“unattended”或“without prompts/questions”的方式运行 `ce-compound`。两个标记一起不是冲突。裸“automatically”或“auto-run”本身**不是**一个非交互信号：它涉及*调用*技能，而不是抑制其提示。一个模糊或缺失的信号默认为交互模式。以 `mode:` 或 `depth:` 开头的标记是标志，不是上下文：在将其余内容视为简要上下文提示之前，请删除它们。一旦检测到，非交互模式将适用于整个运行。

深度仅由显式标记选择，仅在非交互模式下，并且最多接受一个深度标记。`depth:lightweight` 直接路由到轻量级模式。`depth:full` 或没有深度标记进入完整模式，包括其自动会话历史探测。因此，一个不携带深度标记的非交互调用会像它一直以来的行为一样运行。非交互轻量级不提出任何阻塞问题，也不启动任何子代理。如果调用包含未知的 `depth:` 标记、多个 `depth:` 标记或没有非交互意图的 `depth:` 标记，不要猜测：发出非交互失败报告并说明原因，然后以 `Documentation skipped` 结束。

**非交互模式什么也不问。** 它在任何阶段都不提出任何阻塞问题，因为到达此路径的调用者没有人为其回答。每个非交互退出，包括在任何阶段运行之前退出的，都以一个调用者解析的终端信号结束：`Documentation complete`，或者在没有写入文档时以 `Documentation skipped` 和原因结束。交互模式仅在其步骤自己的参考中说明的地方提问，即可发现性检查同意，以及当有多个过时文档时，哪些需要刷新运行。

## 产物根

当你第一次组成 `<root>/solutions/` 路径时解析 `<root>`，并将解析的路径传递给子代理，而不是传递配置。

<!-- ce-docs-root:start -->
**在组成任何产物路径之前解析 CE 产物根 `<root>`。**

- **读取** `docs_root` 从 `<repo-root>/.compound-engineering/config.yaml` 仅 (`<repo-root>` = `git rev-parse --show-toplevel`)。不要从 `config.local.yaml` 读取它。未设置 -> `<root>` 是 `docs`，与之前完全相同。
- **验证** 设置的值：一个相对仓库的目录，其真实路径（解析符号链接后）仍然在仓库内，并且既不是仓库根，也不在 `.git/` 下。否则以错误命名 `docs_root` 和值停止——绝不会回退到 `docs`。
- **使用** `<root>` 作为唯一的产物位置：如果不存在则创建它，将每个路径组成 `<root>/<subdir>`，使用该技能自己的子目录，并且永远不会也读取 `docs`。
<!-- ce-docs-root:end -->

## 写入边界

**只有协调者写入产品文件。** 阶段 1 子代理仅写入每次运行的临时区域，并且永远不会接触 `<root>/`、项目指令文件或任何其他跟踪路径。

协调者写入 `<root>/solutions/` 下唯一的学习，以及它自己的步骤描述的两个维护副作用：在词汇捕获期间写入 `CONCEPTS.md`，以及在交互完整模式**经同意后**——在项目指令文件中写入一个小型可发现性行。在交互完整模式下，当用户在组装目标步骤选择它们时，还存在另外两个写入：一个可写入的声明 Compound Pack 内的规则文件，以及追加到 `.compound-engineering/config.yaml` 的 `packs:` 条目。当 `CONCEPTS.md` 缺失时创建它是预期行为，而不是违规行为。指令文件只被编辑，永远不会被创建。树中的其他任何内容都不会被写入。对*其他*文档的编辑属于 `ce-compound-refresh`，该技能会以狭窄的范围推荐或调用它，但绝不会取代它。

## 选择路径

**在步骤 1 之前阅读 `references/modes.md`。** 一个交互式运行选择自己的深度，而不是询问用户，该参考说明为什么深度选择和会话历史都不是一个问题。默认为**完整**。仅在会话接近其上下文限制时选择**轻量级**。

轻量级模式完全跳过会话历史；非交互完整运行相同的自动探测，它什么也不问，因此保留了非交互合同。

## 完整模式

按顺序运行。每个参考都是其在命名步骤时必须读取的必要内容。

1. **研究** — 读取 `references/research.md`。
2. **会话历史** — 读取 `references/session-history.md`，并在启动并行块*之后*启动它，以便两者重叠而不是序列化。会话历史是最终阶段 1 输入，而不是工作流停止。当它返回时，包括“没有相关的先前会话”，直接进入组装，不要暂停或总结。
3. **组装和写入** — 等待所有阶段 1 输入，然后读取 `references/assembly.md`。
4. **刷新检查和可发现性** — 读取 `references/refresh-and-discoverability.md`。
5. **可选增强** — 读取 `references/enhancement.md`。仅交互式。
6. **报告** — 读取 `references/report.md`，了解你的模式必须发出的报告形状以及该技能如何结束。

**轻量级模式**用单次遍历替换步骤 1-6；读取 `references/lightweight.md`，它定义了两种模式的完成输出。
