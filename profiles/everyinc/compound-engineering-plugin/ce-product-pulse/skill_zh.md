# 产品脉搏

`ce-product-pulse` 查询指定时间窗口内的产品数据源，并生成一份紧凑的单页报告，涵盖使用情况、性能、错误和后续跟进。报告保存在 `<root>/pulse-reports/` 目录下，关键要点会在聊天中展示。

**已完成：** 在 `<root>/pulse-reports/YYYY-MM-DD_HH-MM.md` 存在 30-40 行的报告，其标题和顶级的后续跟进在聊天中显示，并且已达到阶段 3（调度）。

## 边界

- **只读，无处不在。** 该技能不会修改产品、数据库或任何外部系统。其唯一的写操作是追加到 `.compound-engineering/config.local.yaml` 的脉搏设置（面试和选择退出写操作保留在本地覆盖）和报告文件。MCP 和其他数据源工具以只读方式调用；如果某个工具提供写模式，不要使用它们。数据库源必须是只读连接——面试拒绝读写凭证，并且 DB 访问是可选的，因为许多产品仅通过分析和跟踪即可完成脉搏。
- **保存的报告中不包含个人身份信息。** 文件中不包含用户电子邮件、账户 ID 或消息内容。
- **像创始人一样阅读。** 没有硬编码的阈值，没有默认的“好”/“坏”标签，没有告警：展示数字并让读者判断。
- **单页。** 目标是 30-40 行。如果一个部分很薄，就让它保持薄；如果报告变得太长，就删减。
- **不是发布日志或仪表板的替代品。** 已发布的工作存在于问题跟踪器和提交历史中。深入调查仍然使用原生工具；这个工具整合了单页阅读，并且每次运行都会保存，因此过去的脉搏可以按时间线浏览。

## 交互方式

默认使用当前工具列表中已有的主机阻塞式问题工具（按能力匹配，而不是按主机特定名称）。在当前工具列表中的存在证明该工具存在；永远不要调用面向用户的问题工具来发现它是否存在。如果匹配的工具已列出但未加载，使用主机的工具发现原语来加载该能力——不要搜索另一个主机的工具名称。仅在列表中没有该工具或真实的提问调用出错时，才回退到主机用户可见聊天界面的编号选项。永远不要无声地跳过提问。

一次只问一个问题。仅将多选保留在首次运行配置中。

## 回溯窗口

**回溯窗口** 是该技能被调用的指定时间范围（例如 `24h`、`7d`）——显示在当前提示或对话中，无论用户直接提供还是调用技能传递给它。常见的形式包括 trailing hours (`24h`、`48h`、`72h`)、trailing days (`7d`、`30d`)，以及 `1h` 用于发布。

如果参数为空，则默认为配置中的 `pulse_lookback_default`（在阶段 0 中按配置状态解析）；如果这也未设置，则回退到硬编码的默认值 `24h`。如果参数无法解析，请要求用户澄清。

对窗口的上限应用 **15 分钟 trailing buffer**。许多分析和跟踪工具存在摄入延迟；在 `now` 时刻查询会低估最近的事件。对于 `24h` 窗口，查询 `[now - 24h - 15m, now - 15m]`。

## 产物根

该技能在 `<root>/pulse-reports/` 下写入脉搏报告。在您首次组合 `<root>/` 路径时解析 `<root>`（根据下面的块），永远不要在需要它之前解析。写入 `<root>/...` 和读取 `<root>/solutions/` 都算作组合 `<root>/` 路径，因此任何一种都会触发解析；只有完全不触及任何 `<root>/` 路径的运行（仅草稿或无代码库流程）会跳过它。

<!-- ce-docs-root:start -->
**在组合任何产物路径之前解析 CE 产物根 `<root>`。**

- **读取** `docs_root` 从 `<repo-root>/.compound-engineering/config.yaml` 仅 (`<repo-root>` = `git rev-parse --show-toplevel`)。不要从 `config.local.yaml` 读取它。未设置 -> `<root>` 是 `docs`，与之前一样。
- **验证** 设置的值：一个相对仓库的目录，其真实路径（解析符号链接后）仍然在仓库内，既不是仓库根，也不在 `.git/` 下。否则出错，并命名 `docs_root` 和值——永远不要回退到 `docs`。
- **使用** `<root>` 作为唯一的产物位置：如果不存在则创建它，使用该技能自己的子目录组合每个路径为 `<root>/<subdir>`，并且永远不要同时读取 `docs`。

## 阶段 0：按配置状态路由

<!-- ce-config-layers:start -->
**从两个仓库文件解析普通的 CE yaml 键。**

- **读取** `<repo-root>/.compound-engineering/config.local.yaml`，然后 `config.yaml` (`<repo-root>` = `git rev-parse --show-toplevel`)。忽略文件被跳过。Gitignore 不改变解析。
- **胜出** 第一个活动的（非注释）值。对于标量，空值是未设置；无效值继续到下一层，然后是技能默认值。对于列表和映射，存在的键——包括空列表或映射——会替换整个键。
- **不要** 使用此规则来处理 `docs_root`——该键仅在 `config.yaml` 中。
<!-- ce-config-layers:end -->

使用 `git rev-parse --show-toplevel` 解析 `<repo-root>`，然后应用上述普通键规则到 `pulse_*` 键。每当 `pulse_*` 值需要解释时，读取 `references/config.md`——它是键模式，仅此而已：每个键、其允许的值及其默认值，未设置或无效值采用文档中指定的默认值而不是猜测。

**路由：** 每次运行都通过阶段 2（运行脉搏）然后阶段 3（调度）。当 `pulse_product_name` 在级联（上述普通键规则）后未设置时，当仓库根无法解析，或参数为 `setup`、`reconfigure` 或 `edit config` 时，首先运行阶段 1（首次运行面试）；否则从阶段 2（运行脉搏）开始。

## 阶段 1：首次运行面试

首先读取 `references/setup.md`；这是必需的。它定义了策略文档的种子、面试顺序及其推回栏、读写数据库的拒绝、如何将配置写入 `config.local.yaml` 而不干扰其他键，以及一次性调度提议。问题本身来自 `references/interview.md`，该文件将其命名为自己的必需读取。

## 阶段 2：运行脉搏

如果阶段 1（首次运行面试）运行了，使用原生文件读取工具在查询之前重新应用普通键规则（本地然后跟踪）从仓库根，以获取在阶段 1 审查步骤中接受的编辑。否则使用阶段 0（按配置状态路由）中提取的 `pulse_*` 值，对于未设置的任何内容应用 `references/config.md` 中的默认值。

然后在使用任何查询之前读取 `references/run.md`；这是必需的。它定义了并行运行哪些查询和串行运行哪些查询、决定数据库工作是否运行的 `pulse_db_enabled` 检查、可选的质量采样及其评分纪律、四个报告部分以及报告的写入位置。

## 阶段 3：调度

设置提供一次性的重复运行 (`references/setup.md`)。在后续运行中，轻松地再次提及：如果参数是调度关键字 (`daily`、`hourly`、`weekly`)，则说明此次运行是临时的，并指向 harness 的调度原语；如果文件中没有调度，并且这是第三次或后续运行，则提及一次调度是可用的。不要在每次运行时烦扰，并且永远不要自动调度——任何转向调度原语的转交都需要明确的确认。
