# Xcode 模拟器测试

在模拟器上构建和测试 iOS 应用，保留截图、日志、人工验证结果和失败情况作为用户证据。

**已完成：**

- 完成的运行报告总体 `PASS`、`FAIL` 或 `PARTIAL`，包括项目、方案、模拟器、构建结果、每个表面的 `PASS` / `FAIL` / `SKIP`、控制台错误、人工检查和残留失败。
- 每个表面的状态基于证据，而不是用户的路由选择。`PASS` 需要完成的通过证据。`FAIL` 记录观察到的失败证据，直到完成的重新测试替换它。`SKIP` 表示检查没有完成的成果。
- 总体结果是 `FAIL` 时任何失败仍然存在，`PARTIAL` 时没有失败但范围内的检查被跳过，否则为 `PASS`。
- 任何在应用启动并运行日志捕获时出现的失败都会停止后续阶段，并报告一个可操作的设置障碍，附带其证据。

**边界：** 此技能用于测试和报告。诊断和任何用户批准的产品修复属于 `ce-debug`，使用其权限缩小，以便它返回这里而不提交、推送或打开 PR。保持模拟器交互在应用内，并遵循用户放置在范围内的流程。

## 运行

1. **准备和启动。** 阅读 `references/setup-and-build.md`。它定义了 XcodeBuildMCP 可用性检查、项目和方案发现、模拟器选择、构建、安装、启动和日志捕获开始。
2. **执行和报告。** 启动后，阅读 `references/test-and-report.md`。它定义了每个屏幕的证据、仅限人工的流程、SwiftUI 内联链接自动化的限制、检查失败时要做什么、清理以及固定的摘要字段。

不要用记住的工具名称替换任何必需的阅读。XcodeBuildMCP 适配器因主机而异，而它们的可观察成功条件并不相同。
