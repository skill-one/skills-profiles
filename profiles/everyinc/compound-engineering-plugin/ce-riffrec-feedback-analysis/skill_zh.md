# Riffrec 反馈分析

将原始产品反馈转化为下游代理的结构化证据。这项技能是 [Riffrec](https://github.com/kieranklaassen/riffrec) 的消费端，Riffrec 是一款捕获工具，它记录同步的屏幕 + 音频 + 事件会话，并发出一个 `riffrec-*.zip` 压缩包。

**完成情况：**

- 设置完成后会得到当前的捕获/分享路径。
- 快速分析完成后会得到一个有证据支持的错误报告，除非用户要求，否则不会产生持久化工件。
- 深入分析完成后会得到完整的证据集，除非用户只要求提取，否则会进行 `ce-brainstorm` 的交接。
- 输入缺失、分析器失败或路由未解决的情况下，会以可操作的障碍项结束，而不是部分成功的声明。

## 选择路径

根据输入进行路由。仅读取为该路由命名的参考；不要加载其他路径的参考。

- **设置** — 用户还没有录制，并询问如何安装 Riffrec、捕获会话或分享反馈。读取 `references/install-riffrec.md`。
- **快速错误报告** — 输入是一个简短的录制（少于 ~60 秒），用户描述了一个具体的问题，或要求“快速”、“小”或“只需转录”。读取 `references/analyzer.md`，然后 `references/quick-bug-report.md`。
- **深入分析** — 输入更长，包含多个问题、需求或工作流演示，或用户需要需求材料。读取 `references/analyzer.md`，然后 `references/extensive-analysis.md`。继续进入 `ce-brainstorm`，除非用户明确要求只提取或分析工件。

当输入不明确时（例如，没有上下文就收到了一个 zip 文件），在做出选择之前检查录制长度和事件数量。如果仍然不清楚，在运行任何重型操作之前，先询问用户适用哪个路径。

## 常见规则

- 默认情况下，将原始录制、音频片段、zip 内容、会话转储和提取的截图保存在本地。除非用户明确要求且隐私可接受，否则不要提交 `raw/` 或 `frames/` 目录。
- 当文本/元数据工件（需求启动材料、分析摘要、问题分析、源清单）需要用于可追溯性且不包含敏感数据时，可以提交。
- 在提交的文档中使用仓库相对路径的截图，以便后续代理可以在没有绝对本地路径的情况下打开证据。

深入路径使用的复合工程输出格式在 `references/compound-engineering-feedback-format.md` 中有说明。
