# 动画优化

`transitions-dev` 技能的**附加组件**。`transitions-dev` 安装的是完整的动画，而此技能**优化已有的动画**：它会扫描五个动画标记维度——**持续时间、距离、缩放、模糊、缓动**——并为每个值建议对应的标记，以及高级规则，用于确定何时使用这些值（打开/关闭不对称性、悬停进入/退出、错开、延迟）。

可以与 `transitions-dev` 一起安装，也可以单独安装——下面会重述标记值，以便此技能可以独立审计项目。安装后，transitions.dev 的 **优化面板**会自动将这些规则应用到每个 **小型优化** 任务中。

## 核心原则：基于使用场景而非数值匹配

一个值因为偏差 20ms 而不正确是不对的。当它不符合**动画的实际效果**时才是错误的。始终先推断使用场景——模态关闭、下拉菜单打开、工具提示、徽章出现、页面滑动、文本显示、抖动——然后选择文档中与使用场景匹配的标记。`300ms` 的模态关闭映射到 `--duration-quick`（150ms），因为两者都是“模态关闭”，尽管数值不同。如果一个值的使用场景与**没有任何**标记的使用场景匹配，则保持不变。不要因为数值接近就强制替换。

## 五个维度

与 [transitions.dev](https://transitions.dev) 动画标记选项卡相同的比例。将此技能的 [`_root.css`](./_root.css) 复制到项目中一次；导入后，可以引用任何标记为 `var(--…)`。`transitions-dev` 动画使用字面值，因此无需这些标记即可工作——安装此技能可以将其与共享比例进行调优。

### 持续时间

| 标记 | 值 | 使用场景 |
| --- | --- | --- |
| `--duration-stagger` | `40ms` | 每项错开偏移 |
| `--duration-micro` | `80ms` | 工具提示/路径延迟、抖动段、大错开 |
| `--duration-quick` | `150ms` | 模态/下拉菜单关闭、文本交换、工具提示出现 |
| `--duration-fast` | `250ms` | 图标交换、下拉菜单/模态打开、选项卡滑动、页面滑动 |
| `--duration-medium` | `350ms` | 面板关闭、提示关闭 |
| `--duration-slow` | `400ms` | 面板打开、骨架内容显示、输入清除 |
| `--duration-very-slow` | `500ms` | 强调时刻、徽章出现、文本显示、成功检查 |

### 缓动

| 标记 | 值 | 使用场景 |
| --- | --- | --- |
| `--ease-smooth-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 模态/下拉菜单/面板打开+关闭、页面滑动、调整大小、位置变化 |
| `--ease-in-out` | `ease-in-out` | 图标交换、文本交换、文本显示、骨架显示 |
| `--ease-out` | `ease-out` | 工具提示打开/关闭 |
| `--ease-linear` | `linear` | 流光、骨架脉冲、加载器 |
| `--ease-bounce` | `cubic-bezier(0.34, 1.36, 0.64, 1)` | 徽章弹出打开 |
| `--ease-bounce-strong` | `cubic-bezier(0.34, 3.85, 0.64, 1)` | 弹性悬停退出（头像返回） |

`--ease-smooth-out` 是默认值。仅对表面动画（打开/关闭、滑动、调整大小、位置）将通用 `ease`、`ease-in` 或任何手写的 `cubic-bezier(...)` / `linear(...)` 推向它**仅此而已**。保留其他五个标记缓动不变——它们已经对齐且每个都带有自己的意图。

### 距离

| 标记 | 值 | 使用场景 |
| --- | --- | --- |
| `--distance-micro` | `4px` | 文本交换 |
| `--distance-small` | `6px` | 错误抖动（小段） |
| `--distance-base` | `8px` | 徽章对角线显示、页面滑动、错误抖动（大段） |
| `--distance-medium` | `12px` | 文本显示 |
| `--distance-large` | `30px` | 检查徽章出现 |

移动距离随频率降低而减小，随仪式感增强而增大：就地文本交换几乎不动（`4px`），页面滑动以可读的 `8px` 移动，一次性庆祝性徽章可以扫过 `30px`。如果任何翻译距离大于 `~40px`（除完整面板/抽屉外），通常看起来迟缓——将其拉向 `--distance-base`。

### 缩放

| 标记 | 值 | 使用场景 |
| --- | --- | --- |
| `--scale-large` | `0.96` | 模态打开/关闭 |
| `--scale-medium` | `0.97` | 下拉菜单打开 |
| `--scale-small` | `0.98` | 工具提示打开 |
| `--scale-tiny` | `0.99` | 下拉菜单关闭 |

捕获的值是非静止的“预”缩放，表面动画从此开始；它始终稳定到 `1`。更大的表面从更远的地方开始（`0.96` 模态），小提示几乎不缩放（`0.98`–`0.99`）。预缩放低于 `~0.9` 读作“缩放”，很少适用于 UI 修饰——将其固定到使用场景标记。

### 模糊

| 标记 | 值 | 使用场景 |
| --- | --- | --- |
| `--blur-small` | `2px` | 面板显示、图标交换、文本交换、骨架显示、数字弹出 |
| `--blur-medium` | `3px` | 页面滑动、文本显示 |
| `--blur-large` | `8px` | 成功检查打开 |

模糊是非静止的“预”模糊，稳定到 `0`。用于柔化交换或滑动，从不用于普通淡入淡出或颜色/主题更改。模糊也可以**不存在**以及不在标记中：当使用场景明确要求模糊时（无模糊通道的页面滑动）建议添加 `--blur-medium`。

## 优化规则——何时值是正确的

### 打开/关闭不对称性

打开是一种邀请；关闭应该让路。关闭比打开更快、更安静。

- **持续时间**：下拉菜单/模态 **打开 250ms → 关闭 150ms** (`--duration-fast` → `--duration-quick`)；面板 **打开 400ms → 关闭 350ms** (`--duration-slow` → `--duration-medium`)；提示 **关闭 350ms** (`--duration-medium`)。
- **对称例外——双向相同持续时间和缓动，不要拆分**：页面并排（250ms）、选项卡滑动（250ms）、手风琴（250ms）、图标交换（250ms）、文本交换（150ms）。这些读作一个可逆动画，而不是打开/关闭对。
- **距离和模糊**：进入阶段携带距离和模糊；退出可以减少或缩小它们，以便关闭不会将内容甩到屏幕上。
- **缓动**：大多数打开和关闭共享 `--ease-smooth-out`。超调曲线属于*仅进入*（徽章弹出、数字弹出）——不要让关闭弹跳。

### 悬停进入与悬停退出

- **进入**：快速直接——短 `--duration-fast` 或更短的提升，使用 `--ease-smooth-out`。
- **退出**：更柔和、更有弹性——返回可以更长，使用 `--ease-bounce-strong`（头像返回，`cubic-bezier(0.34, 3.85, 0.64, 1)`）以便行稳定而不是突然 snaps。这是唯一*退出*比*进入*更复杂的地方。

### 错开和延迟

- **错开偏移**：`--duration-stagger`（40ms）每项；对于几个大项，提升到 `--duration-micro`（80ms）。保持**总错开**（偏移×项数）在 ~300ms 以下，以免最后一项感觉太晚——对于长列表，限制错开项数或缩小偏移。
- **意图延迟**：工具提示在出现前等待 `--duration-micro`（80ms），以免经过的鼠标触发；成功检查路径绘制使用相同的 80ms 节奏。当您想要*过滤意外触发*或*序列化*两件事时，延迟是正确的——不是填充慢动画。
- **延迟与持续时间**：如果动画感觉太晚，优先缩短**持续时间**而不是添加延迟。保留延迟用于错开、意图门控和有意序列化。
- **永远不要延迟关闭**或悬停退出——撤销必须感觉即时。

## 命令

此技能提供两个命名空间动词。每个命令都以 `transitions` 开头，以便调用不会与同一项目中安装的其他技能的动词冲突。`review` 报告；`polish` 应用。

### transitions review —— 对动画进行标记审计

**触发短语**：`transitions review`、"审查我的动画"、"审计动画"、"扫描临时动画"、"标记我的动画"、"我的持续时间哪里不对"、"与动画标记对齐"、"使时间一致"。

**行为**：

1. **扫描整个项目**——不仅是样式表，还包括内联 `style=` / CSS-in-JS、styled-components、`<style>` 块和 Tailwind 任意值（`duration-[300ms]`、`[transition-timing-function:...]`）——所有五个维度：持续时间（`…ms`/`…s`）、缓动（`cubic-bezier(...)` / 关键字）、平移距离（`translate*(…px)`）、`scale(...)` 和 `blur(...)`。通过驱动它们的 `animation` 读取 `@keyframes`。
2. 对于每个值，从周围的选择器/组件名称推断**动画做什么**（模态关闭、下拉菜单打开、工具提示、徽章出现、页面滑动、文本显示、抖动、悬停提升等）。在上述标记表中查找使用场景，选择文档中与使用场景匹配的标记——**使用场景优先，从不与最近数值匹配**。不要建议整个动画配方交换；那是 `transitions-dev` 的 `transitions apply` 域。
3. 应用**优化规则**：检查打开/关闭不对称性、悬停进入/退出、错开总和和延迟——而不仅仅是单个值是否对齐。
4. 输出一个按文件分组编号的列表，仅显示应更改的值：
   - `path/to/Component.css:L42` — `模态关闭: 300ms → var(--duration-quick) (150ms)` — 关闭应该比 250ms 的打开更快。
   - `path/to/List.css:L20` — `错开: 120ms → var(--duration-stagger) (40ms)` — 8 项 × 120ms = 960ms 总和，最后一项感觉太晚。
   - 跳过使用场景与任何标记不匹配的值——将它们列为 `无匹配标记使用场景` 并保留。
5. **不要编辑任何内容**。以："运行 `transitions polish` 应用这些更改，或确认任何行以单独应用" 结束。

### transitions polish —— 应用动画标记优化

**触发短语**：`transitions polish`、"优化我的动画"、"调整动画"、"调整时间/缓动"、"应用动画标记"、"修复错开"、"标记我的动画"。

**行为**：

1. 如果用户在此会话中未运行 `transitions review`，首先运行 **transitions review** 的相同扫描（步骤 1–4）以构建更改列表。如果用户指定了特定文件、行或值，则将扫描范围限定在该上下文中。
2. 显示一个简短的建议：将更改多少值，按文件分组，并带有一条示例行。在编辑前请求确认。
3. 确认后，**应用标记更改**到源代码：
   - 将硬编码的持续时间/缓动/距离/缩放/模糊替换为 `var(--…)` 引用，其中项目已导入此技能的 [`_root.css`](./_root.css)；否则写入标记的原始值，并注明导入 `_root.css` 可以将来在一个地方进行更改。
   - 保留文件的现有单位/格式（`0.25s` vs `250ms`），除非切换到 `var(--…)`。
   - 仅触摸被优化的动画值——不重新格式化，不进行无关编辑。
   - 处理纯 CSS、CSS Modules、styled-components/emotion、Tailwind 工具/配置、内联 `style` 对象和 Motion/Framer 变体。
4. 如果 `_root.css` 尚未在项目中，则在优化过程中之前或与优化一起提供安装它（一次）的选项。
5. 保持差异小。以被触摸文件的简短摘要结束。

## 与优化面板的关系

当此技能安装在项目中时，transitions.dev 优化面板的 **小型优化** 选项卡会自动将 [`_refine-rules.md`](./_refine-rules.md) 中的紧凑规则内联到其代理提示中，因此每次点击的建议都会遵循这些规则，无需额外的文件读取。`transitions review` 在项目规模上镜像该审计；`transitions polish` 将接受的调整写入源代码。

## 未来扩展

此技能的自然下一步添加：性能卫生（`transition: all`、动画 `width`/`top`/`box-shadow` 而不是 `transform`/`opacity`、`will-change` 的误用）、缺少 `prefers-reduced-motion` 检测、跨项目一致性审计（相同目的的动画使用不同值）、Tailwind/Framer 标记适配器，以及一个“动画优化评分”报告。
