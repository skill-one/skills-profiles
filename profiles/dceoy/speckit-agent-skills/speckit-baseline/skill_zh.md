# Spec Kit 基线技能

## 使用场景

- 你需要对现有或遗留代码编写规范。
- 你希望在重构前记录功能文档。
- 你接手了一个没有书面需求的代码库。

## 输入

- 描述要分析的代码的目标路径、文件列表或通配符模式。
- 包含 `.specify/` 脚本和模板的代码库上下文。

如果目标缺失或模糊，请在继续之前提出一个具体的问题。

## 目标

为现有代码生成与技术无关的规范，然后使用标准的 Spec Kit 模板创建功能分支/规范文件。

## 工作流程

1. **解析目标输入**：识别要分析的文件、目录或模式。
   - 接受文件路径、通配符模式或目录路径。
   - 如果为空：停止并要求提供具体目标。

2. **发现并读取源文件**：
   - 将通配符扩展为文件列表。
   - 读取文件内容以进行分析。
   - 识别主要语言和框架。
   - 映射关键文件关系和依赖项。

3. **分析代码结构**：
   - 识别入口点和公共接口。
   - 提取函数/方法签名和行为。
   - 查找数据模型和实体。
   - 检测 API 端点和路由。
   - 识别面向用户的功能。

4. **从分析代码生成简短名称**（2-4 个词）：
   - 使用动作-名词格式（例如，"用户认证"、"支付处理"）。
   - 基于发现的主要功能。
   - 在有意义的场景下保留技术术语。

5. **创建功能分支和规范文件**：
   - 找到此简短名称的最高现有功能编号（分支/规范）。
   - 使用计算出的编号和简短名称运行 `.specify/scripts/bash/create-new-feature.sh --json`。
   - 从脚本 JSON 输出中读取 `BRANCH_NAME`、`FEATURE_DIR` 和 `SPEC_FILE` 路径。
   - 对于参数中的单引号（如 "I'm Groot"），使用转义语法：例如 'I'\''m Groot'（如果可能，使用双引号："I'm Groot"）。

6. **从 `.specify/templates/spec-template.md` 加载规范模板**。

7. **使用模板结构起草规范**：
   - **用户故事**：从面向用户的代码路径和交互中推断。
   - **验收场景**：从验证逻辑、错误处理和测试中推导。
   - **功能需求**：从业务规则和约束中提取。
   - **关键实体**：从数据模型和模式中识别。
   - **成功标准**：从指标、日志或与性能相关的代码中推断。
   - **假设**：记录分析过程中做出的推断。

8. **抽象实现细节**：
   - 将技术模式转换为面向用户的需求。
   - 移除框架特定术语。
   - 关注代码做什么，而不是它如何做。

9. **在 `FEATURE_DIR/checklists/requirements.md` 创建规范质量检查清单**。

10. **报告完成情况**，包括：
    - 分支名称和规范文件路径。
    - 分析文件的摘要。
    - 发现的关键功能。
    - 需要澄清或审查的领域。

## 输出

- `specs/<feature>/spec.md`
- `specs/<feature>/checklists/requirements.md`

## 关键规则

- 关注从 HOW 中提取 WHAT 和 WHY。
- 在生成的规范中抽象实现细节。
- 记录代码分析过程中做出的假设。
- 标记代码行为不明确的区域。
- 保留发现的业务规则和约束。
- 使用 `[NEEDS CLARIFICATION]` 标记模糊的代码段（最多 3 个）。
- 生成的规范应由了解该功能的人验证。

## 示例

**代码模式 → 规范需求**：

- `if (user.role === 'admin')` → "系统必须限制管理员用户执行操作"
- `password.length >= 8` → "密码必须至少 8 个字符"
- `cache.set(key, value, 3600)` → "系统必须缓存结果以提高性能"
- `try { ... } catch (e) { notify(e) }` → "系统必须在发生错误时通知用户"

**代码模式 → 用户故事**：

- 带有 OAuth 的登录端点 → "作为一个用户，我可以使用我的社交账户登录"
- 购物车逻辑 → "作为一个客户，我可以将商品添加到购物车以供稍后购买"
- 报告生成 → "作为一个分析师，我可以生成系统活动报告"

## 下一步

生成 spec.md 后：

- 使用 `speckit-clarify` 与领域专家**澄清**。
- 使用 `speckit-plan` **规划**现代化/重构。
- 将生成的规范与实际需求**对比**以识别差距。
