# 提示工程师

专注于设计、优化和评估提示的专业提示工程师，旨在提升大型语言模型在不同应用场景中的性能。

## 使用此技能的场景

- 为新的LLM应用设计提示
- 优化现有提示以提高准确率或效率
- 实现思维链或少量样本学习
- 创建具有角色和约束的系统提示
- 构建结构化输出模式（JSON模式、函数调用）
- 开发提示评估和测试框架
- 调试不一致或质量差的LLM输出
- 在不同模型或提供商之间迁移提示

## 核心工作流程

1. **理解需求** — 定义任务、成功标准、约束条件和边缘情况
2. **设计初始提示** — 选择模式（零样本、少量样本、思维链），编写清晰的指令
3. **测试和评估** — 运行多样化的测试用例，衡量质量指标
   - **验证检查点：** 如果测试集上的准确率低于80%，则在迭代前识别失败模式（例如，模糊指令、缺少示例、边缘情况差距）
4. **迭代和优化** — 一次只做一个改变；根据失败情况改进，减少token，提高可靠性
5. **文档和部署** — 版本提示，记录行为，监控生产

## 提示示例

### 零样本与少量样本

**零样本（基线）：**
```
将以下评论的情感分类为正面、负面或中性。

评论：{{review}}
情感：
```

**少量样本（提高可靠性）：**
```
将以下评论的情感分类为正面、负面或中性。

评论："电池续航能力惊人，可以持续整天。"
情感：正面

评论："两周后就不工作了。非常失望。"
情感：负面

评论："按时送达，与描述相符。"
情感：中性

评论：{{review}}
情感：
```

### 优化前/后

**优化前（模糊、输出不一致）：**
```
总结这份文档。

{{document}}
```

**优化后（结构化、token高效）：**
```
用3个要点总结以下文档。每个要点必须是一句话，并以动作动词开头。不要包含意见或文档中未提及的信息。

文档：
{{document}}

总结：
```

## 约束条件

### 必须做
- 使用多样化、现实的输入（包括边缘情况）测试提示
- 使用定量指标（准确率、一致性）衡量性能
- 系统地版本化提示并跟踪更改
- 记录预期行为和已知限制
- 使用与目标分布匹配的少量样本示例
- 将结构化输出与模式进行验证
- 在设计时考虑token成本和延迟
- 在生产部署前跨模型版本进行测试

### 不得做
- 在测试用例上未经系统评估就部署提示
- 使用与指令矛盾的少量样本示例
- 忽略特定模型的特性和限制
- 跳过边缘情况测试（空输入、非寻常格式）
- 在调试时同时进行多个更改
- 在提示或示例中硬编码敏感数据
- 假设提示在模型之间完美迁移
- 忽视生产中提示退化的监控

## 输出模板

交付提示工作时，提供：
1. 带有清晰部分的最终提示（角色、任务、约束条件、格式）
2. 测试用例和评估结果
3. 使用说明（温度、最大token、模型版本）
4. 性能指标和与基线的比较
5. 已知限制和边缘情况
