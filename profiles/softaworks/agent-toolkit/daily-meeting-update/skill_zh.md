# 每日会议更新

通过**交互式访谈**生成每日站会/会议更新。永远不要假设工具已配置——先询问。

---

## 工作流程

```
开始
  │
  ▼
┌─────────────────────────────────────────────────────┐
│ 第一阶段：检测与提供集成                      │
│ • 检查：Claude Code 历史记录？gh CLI？jira CLI？     │
│ • Claude Code → 拉取昨天的会议摘要               │
│   → 用户通过multiSelect选择相关项目             │
│ • GitHub/Jira → 询问用户，经批准后拉取          │
│ • 现在拉取数据（访谈前）                      │
├─────────────────────────────────────────────────────┤
│ 第二阶段：访谈（带洞察）                      │
│ • 显示拉取的数据作为上下文                       │
│ • 昨天：我看到你合并了PR #123，还有其他吗？       │
│ • 今天：你今天会做什么工作？                   │
│ • 阻塞点：有什么阻塞你吗？                    │
│ • 主题：会议结束时有任何需要讨论的吗？          │
├─────────────────────────────────────────────────────┤
│ 第三阶段：生成更新                            │
│ • 结合访谈答案+工具数据                       │
│ • 格式化为干净的Markdown                      │
│ • 展示给用户                                │
└─────────────────────────────────────────────────────┘
```

## 第一阶段：检测与提供集成

### 第一步：静默检测

**静默检测**（抑制错误，不显示给用户）检查可用的集成：

| 集成       | 检测 |
|------------|------|
| **Claude Code 历史记录** | `~/.claude/projects` 目录存在 `.jsonl` 文件 |
| GitHub CLI | `gh auth status` 成功 |
| Jira CLI   | `jira` 命令存在 |
| Atlassian MCP | `mcp__atlassian__*` 工具可用 |
| Git        | 在 git 仓库内 |

### 第二步：提供 GitHub/Jira 集成（如果可用）

> **Claude Code 用户：** 在本阶段使用 `AskUserQuestionTool` 工具回答所有问题。

**GitHub/Git：**

如果 `HAS_GH` 或 `HAS_GIT`：

```
"我检测到你已配置 GitHub/Git。要我拉取你的最近活动（提交、PR、评审）吗？"

选项：
- "是，拉取信息"
- "不是，我会手动提供所有内容"
```

如果同意：

```
"我应该检查哪些仓库/项目？"

选项：
- "仅当前目录"（如果在 git 仓库内）
- "我会列出仓库" → 用户提供列表
```

**Jira：**

如果 `HAS_JIRA_CLI` 或 `HAS_ATLASSIAN_MCP`：

```
"我检测到你已配置 Jira。要我拉取你的工单吗？"

选项：
- "是，拉取我的工单"
- "不是，我会手动提供所有内容"
```

### 第三步：拉取 GitHub/Jira 数据（如果批准）

**GitHub/Git** — 对于每个批准的仓库：
- 用户自昨天以来的提交
- 用户打开/合并的 PR
- 用户完成的评审

**Jira** — 用户分配的工单，过去 24 小时内更新

**关键洞察**：将结果存储起来，用于第二阶段的访谈作为上下文。

### 第四步：提供 Claude Code 历史

此集成捕获你使用 Claude Code 的工作内容——对于召回不在 git 或 Jira 中的工作很有用。

**检测：**
```bash
ls ~/.claude/projects/*/*.jsonl 2>/dev/null | head -1
```

如果存在 Claude Code 历史记录，询问：

```
"我也可以从昨天拉取你的 Claude Code 会话历史。这有助于召回不在 git/Jira 中的工作（研究、调试、规划）。要我检查吗？"

选项：
- "是，拉取我的 Claude Code 会话"
- "不是，我需要所有我需要的信息"
```

如果同意，运行摘要脚本：

```bash
python3 ~/.claude/skills/daily-meeting-update/scripts/claude_digest.py --format json
```

然后使用 multiSelect 展示会话：

使用 `AskUserQuestionTool` 并设置 `multiSelect: true` 让用户选择相关项目：

```
"这是你昨天的 Claude Code 会话。选择与你的站会相关的会话："

选项（multiSelect）：
- "修复认证错误（backend-api）"
- "实现 OAuth 流程（backend-api）"
- "更新主页样式（frontend-app）"
- "研究支付提供者（docs）"
```

**关键洞察**：用户选择哪些会话与工作相关。个人项目或实验可以排除。

**绝对不要运行摘要脚本时：**
- 用户明确拒绝 Claude Code 历史记录
- 用户表示会手动提供所有内容
- `~/.claude/projects` 目录不存在

**如果摘要脚本失败：**
- 回退：静默跳过 Claude Code 集成，继续访谈
- 常见问题：Python 未安装、昨天没有会话、权限错误
- **绝对不要阻塞站会流程**——该脚本只是补充，不是必需的

## 第二阶段：访谈（带洞察）

> **Claude Code 用户：** 使用 `AskUserQuestionTool` 工具进行访谈。这提供了更好的用户体验，具有结构化选项。

**使用拉取的数据作为上下文**使问题更智能。

### 第一个问题：昨天

**如果拉取了数据**，先显示它：

```
"这是我找到的活动：
- 合并了 PR #123：修复登录超时
- backend-api 中的 3 次提交
- 审查了 PR #456（已批准）

你昨天还做了什么我遗漏了吗？"
```

**如果没有拉取数据：**

```
"你昨天/上次站会后做了什么工作？"
```

如果用户回答模糊，问跟进问题：
- "你能详细说明 X 吗？"
- "你完成了什么具体内容？"

### 第二个问题：今天

```
"你今天会做什么工作？"

选项：
- [文本输入 - 用户自由输入]
```

**如果拉取了 Jira 数据**，可以建议：

```
"我看到你分配了这些工单：
- PROJ-123：实现 OAuth 流程（进行中）
- PROJ-456：修复支付错误（待办）

你今天会处理其中的任何一项吗？"
```

### 第三个问题：阻塞点

```
"你有任何阻塞点或障碍吗？"

选项：
- "没有阻塞点"
- "是，我有阻塞点" → 跟进以获取详细信息
```

### 第四个问题：会议结束要讨论的主题

```
"你希望在会议结束时讨论任何主题吗？"

选项：
- "没有，没什么要讨论的"
- "是" → 跟进以获取详细信息

讨论主题示例：
- 需要输入的技术决策
- 与其他团队的协调
- 优先级问题
- 团队公告或信息
```

## 第三阶段：生成更新

将所有信息组合成干净的 Markdown：

```markdown
# 每日更新 - [日期]

## 昨天
- [访谈中的项目]
- [如果拉取了 GitHub/Jira 的项目]

## 今天
- [访谈中的项目]

## 阻塞点
- [阻塞点或“无阻塞点”]

## PRs & Reviews（如果从 GitHub 拉取）
- [打开的 PRs]
- [合并的 PRs]
- [完成的评审]

## Jira（如果从 Jira 拉取）
- [更新的工单]

## 讨论主题
- [主题或“无”]

---
*链接：*
- [PR 链接]
- [工单链接]
```

---

## 核心原则

1. **访谈是主要**——工具补充，它们不取代人类上下文
2. **访问前获得同意**——始终在拉取任何集成之前询问
3. **上下文感知问题**——在访谈期间显示拉取的数据以触发记忆（“我看到你合并了 PR #123...”）

## 快速参考

| 阶段         | 操作         | 工具         |
|-------------|-------------|-------------|
| 1. 检测与提供 | 检查 gh/jira/claude 历史记录，询问用户，拉取数据 | Bash（静默），AskUserQuestionTool* |
| 2. 访谈       | 提问 4 个问题并带洞察 | AskUserQuestionTool* |
| 3. 生成       | 格式化 Markdown | 输出文本     |

*Claude Code 仅：使用 `AskUserQuestionTool` 工具进行结构化问题。

### Claude Code 摘要脚本

```bash
# 获取昨天的会话作为 JSON
python3 ~/.claude/skills/daily-meeting-update/scripts/claude_digest.py --format json

# 获取今天的会话
python3 ~/.claude/skills/daily-meeting-update/scripts/claude_digest.py --date today --format json

# 过滤到特定项目
python3 ~/.claude/skills/daily-meeting-update/scripts/claude_digest.py --project ~/my-app --format json
```

  ☑ 修复认证超时错误（backend-api）

## 反模式

| 避免       | 原因（专家知识）       | 而应       |
|-----------|------------------------|-----------|
| 运行 gh/jira 而不询问 | 用户可能有个人仓库，或处于他们不想暴露的敏感项目上下文中 | 始终先询问，让用户选择仓库 |
| 假设当前目录是唯一项目 | 开发者通常同时处理 2-5 个仓库（前端、后端、基础设施） | 询问“你正在处理哪些项目？” |
| 即使有工具数据跳过访谈 | 工具捕获发生了什么，但错过了为什么和上下文（研究、会议、规划） | 访谈是主要，工具补充 |
| 在完成所有 4 个问题之前生成更新 | 用户可能有关键的阻塞点或讨论主题会改变叙述 | 完成访谈，然后生成 |
| 包含原始提交消息 | 提交消息通常很模糊（“修复”、“进行中”）并且不能说明情况 | 总结为人类可读的结果 |
| 访谈后请求数据 | 在访谈期间显示洞察使问题更智能（“我看到你合并了 PR #123，还有其他吗？”） | 先拉取数据，然后带上下文进行访谈 |

---

## 绝对不要

- **绝对不要假设工具已配置**——许多开发者安装了 gh 但未认证，或 jira CLI 指向错误的实例
- **绝对不要跳过“讨论主题”问题**——这是站会最有价值的部分，工具无法捕获
- **绝对不要生成超过 15 个要点**——站会应该少于 2 分钟阅读；长更新会让观众失去兴趣
- **绝对不要在没有上下文的情况下包含工单/PR 编号**——"PROJ-123" 意义不大；始终包含标题或摘要
- **绝对不要拉取用户未明确批准的仓库数据**——即使你能看到其他仓库，也要尊重界限
