# 你可能不需要副作用

副作用是 React 的一个**逃生通道**，它让你与外部系统同步。如果没有外部系统参与，你就不需要副作用。

## 快速参考

| 情况 | 不要 | 要 |
|------|------|-----|
| 从 props/状态派生状态 | `useState` + `useEffect` | 在渲染期间计算 |
| 执行昂贵的计算 | 使用 `useEffect` 缓存 | 使用 `useMemo` |
| 在 prop 变化时重置状态 | 使用 `useEffect` 调用 `setState` | 使用 `key` 属性 |
| 处理用户事件响应 | 使用 `useEffect` 观察 state | 直接使用事件处理器 |
| 通知父组件发生变化 | 使用 `useEffect` 调用 `onChange` | 在事件处理器中调用 |
| 获取数据 | 无清理的 `useEffect` | 带清理的 `useEffect` 或使用框架 |

## 你需要副作用的情况

- 与**外部系统**同步（非 React 组件、浏览器 API）
- 对外部存储的**订阅**（尽可能使用 `useSyncExternalStore`）
- 组件显示时运行的**分析/日志记录**
- 带有正确清理的**数据获取**（或使用框架的内置机制）

## 你不需要副作用的情况

1. **为渲染转换数据** - 在顶层计算，自动重新运行
2. **处理用户事件** - 使用事件处理器，你知道发生了什么
3. **派生状态** - 直接计算：`const fullName = firstName + ' ' + lastName`
4. **链式状态更新** - 在事件处理器中计算所有下一个状态

## 决策树

```
需要响应某些内容吗？
├── 用户交互（点击、提交、拖动）？
│   └── 使用事件处理器
├── 组件出现在屏幕上？
│   └── 使用副作用（外部同步、分析）
├── Props/状态变化需要派生值？
│   └── 在渲染期间计算
│       └── 昂贵？使用 useMemo
└── prop 变化时需要重置状态？
    └── 在组件上使用 KEY 属性
```
