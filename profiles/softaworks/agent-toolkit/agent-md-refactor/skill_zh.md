# 代理文件重构

重构臃肿的代理指令文件（AGENTS.md、CLAUDE.md、COPILOT.md 等），遵循**渐进式披露原则**——将核心内容保留在根目录，将其他内容组织到相互链接的分类文件中。

---

## 触发条件

在以下情况下使用此技能：
- "重构我的 AGENTS.md"
- "重构我的 CLAUDE.md"
- "拆分我的代理指令"
- "组织我的 CLAUDE.md 文件"
- "我的 AGENTS.md 太长了"
- "对我的指令进行渐进式披露"
- "清理我的代理配置"

---

## 快速参考

| 阶段 | 操作 | 输出 |
|------|------|------|
| 1. 分析 | 发现矛盾 | 待解决的冲突列表 |
| 2. 提取 | 识别核心内容 | 根文件的核心指令 |
| 3. 分类 | 将剩余指令分组 | 逻辑分类 |
| 4. 结构化 | 创建文件层级 | 根目录 + 链接文件 |
| 5. 剪枝 | 标记待删除 | 冗余/模糊的指令 |

---

## 流程

### 阶段 1：发现矛盾

识别任何相互冲突的指令。

**查找：**
- 矛盾的样式指南（例如，"使用分号" vs "不使用分号"）
- 冲突的工作流指令
- 不兼容的工具偏好
- 互斥的模式

**对于每个发现的矛盾：**
```markdown
## 发现矛盾

**指令 A：** [引用]
**指令 B：** [引用]

**问题：** 哪个应优先，或者两个都应条件化？
```

在继续之前，询问用户解决。

---

### 阶段 2：识别核心内容

仅提取属于根代理文件的内容。根目录应保持最小化——适用于**每个任务**的信息。

**核心内容（保留在根目录）：**
| 分类 | 示例 |
|------|------|
| 项目描述 | 一句话："一个用于分析的 React 仪表板" |
| 包管理器 | 如果不是 npm，则仅包含（例如，"使用 pnpm"） |
| 非标准命令 | 自定义构建/测试/类型检查命令 |
| 关键覆盖 | 必须覆盖默认值的内容 |
| 通用规则 | 适用于 100% 的任务 |

**非核心内容（移动到链接文件）：**
- 语言特定约定
- 测试指南
- 代码样式细节
- 框架模式
- 文档标准
- Git 工作流细节

---

### 阶段 3：分组剩余内容

将剩余指令组织到逻辑分类中。

**常见分类：**
| 分类 | 内容 |
|------|------|
| `typescript.md` | TS 约定、类型模式、严格模式规则 |
| `testing.md` | 测试框架、覆盖率、模拟模式 |
| `code-style.md` | 格式化、命名、注释、结构 |
| `git-workflow.md` | 提交、分支、PR、评审 |
| `architecture.md` | 模式、文件夹结构、依赖关系 |
| `api-design.md` | REST/GraphQL 约定、错误处理 |
| `security.md` | 认证模式、输入验证、密钥 |
| `performance.md` | 优化规则、缓存、懒加载 |

**分组规则：**
1. 每个文件应针对其主题自包含
2. 目标是 3-8 个文件（既不太细粒度，也不太宽泛）
3. 清晰命名文件：`{主题}.md`
4. 仅包含可操作的指令

---

### 阶段 4：创建文件结构

**输出结构：**
```
project-root/
├── CLAUDE.md (或 AGENTS.md)     # 最小根目录，带链接
└── .claude/                      # 或 docs/agent-instructions/
    ├── typescript.md
    ├── testing.md
    ├── code-style.md
    ├── git-workflow.md
    └── architecture.md
```

**根文件模板：**
```markdown
# 项目名称

对项目的简短描述。

## 快速参考

- **包管理器：** pnpm
- **构建：** `pnpm build`
- **测试：** `pnpm test`
- **类型检查：** `pnpm typecheck`

## 详细指令

对于具体指南，请参阅：
- [TypeScript 约定](.claude/typescript.md)
- [测试指南](.claude/testing.md)
- [代码样式](.claude/code-style.md)
- [Git 工作流](.claude/git-workflow.md)
- [架构模式](.claude/architecture.md)
```

**每个链接文件模板：**
```markdown
# {主题} 指南

## 概述
简要说明这些指南何时适用。

## 规则

### 规则分类 1
- 具体可操作的指令
- 另一个具体指令

### 规则分类 2
- 具体可操作的指令

## 示例

### 良好
\`\`\`typescript
// 正确模式的示例
\`\`\`

### 避免
\`\`\`typescript
// 不应这样做示例
\`\`\`
```

---

### 阶段 5：标记待删除

识别应完全删除的指令。

**如果：**
| 标准 | 示例 | 删除原因 |
|------|------|--------|
| 冗余 | "使用 TypeScript"（在 .ts 项目中） | 代理已知晓 |
| 太模糊 | "编写干净的代码" | 不可操作 |
| 过于明显 | "不要引入错误" | 浪费上下文 |
| 默认行为 | "使用描述性变量名" | 标准实践 |
| 过时 | 引用已弃用的 API | 不再适用 |

**输出格式：**
```markdown
## 标记待删除

| 指令 | 原因 |
|------|------|
| "编写干净、可维护的代码" | 太模糊，不可操作 |
| "使用 TypeScript" | 冗余 - 项目已经是 TS |
| "不要提交密钥" | 代理已知 |
| "遵循最佳实践" | 没有具体细节则无意义 |
```

## 执行检查清单

```
[ ] 阶段 1：所有矛盾已识别并解决
[ ] 阶段 2：根文件仅包含核心内容
[ ] 阶段 3：所有剩余指令已分类
[ ] 阶段 4：已创建正确的文件结构及链接
[ ] 阶段 5：已删除冗余/模糊的指令
[ ] 验证：每个链接文件是自包含的
[ ] 验证：根文件少于 50 行
[ ] 验证：所有链接均正确
```

---

## 反模式

| 避免 | 原因 | 而应 |
|------|------|------|
| 将所有内容保留在根目录 | 臃肿，难以维护 | 分成链接文件 |
| 分类过多 | 分散 | 合并相关主题 |
| 模糊指令 | 浪费 token，无价值 | 具体或删除 |
| 重复默认值 | 代理已知 | 仅在需要时覆盖 |
| 深层嵌套 | 难以导航 | 平面结构带链接 |

## 示例

### 之前（臃肿的根目录）
```markdown
# CLAUDE.md

这是一个 React 项目。

## 代码样式
- 使用 2 个空格
- 使用分号
- 倾向于 const 而不是 let
- 使用箭头函数
... (200 行更多内容)

## 测试
- 使用 Jest
- 覆盖率 > 80%
... (100 行更多内容)

## TypeScript
- 启用严格模式
... (150 行更多内容)
```

### 之后（渐进式披露）
```markdown
# CLAUDE.md

用于实时分析可视化的 React 仪表板。

## 命令
- `pnpm dev` - 启动开发服务器
- `pnpm test` - 运行带覆盖率的测试
- `pnpm build` - 生产构建

## 指南
- [代码样式](.claude/code-style.md)
- [测试](.claude/testing.md)
- [TypeScript](.claude/typescript.md)
```

---

## 验证

重构后，验证：

1. **根文件最小** - 少于 50 行，仅包含通用信息
2. **链接正常** - 所有引用的文件都存在
3. **无矛盾** - 指令一致
4. **可操作内容** - 每个指令都是具体的
5. **完整覆盖** - 未丢失任何指令（除非标记待删除）
6. **自包含文件** - 每个链接文件独立存在
