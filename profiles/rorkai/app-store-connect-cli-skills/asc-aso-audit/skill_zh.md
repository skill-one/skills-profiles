# asc ASO 审计

执行两阶段 ASO 审计：离线检查本地元数据文件，然后通过 Astro MCP 进行关键词差距分析。
在可用的情况下，将 Apple 生成的应用标签作为可发现性信号包含在内。

## 前置条件

- 通过 `asc metadata pull --app "APP_ID" --version "1.2.3" --dir "./metadata"` 将元数据从本地拉取到规范文件中。
- 如果元数据来自 `asc migrate export` 或 `asc localizations download`，则在运行此技能之前将其规范化为规范 `./metadata` 布局。
- 对于 Astro 差距分析：应用在 Astro MCP 中被跟踪（可选——离线检查无需此功能）。
- 对于 Apple 生成的可发现性标签：`asc app-tags list --app "APP_ID" --output json` 在 API 返回应用的标签时可以工作。

## 开始前

1. 阅读 `references/aso_rules.md` 以了解每个检查强制执行的规定。
2. 确定位于 `metadata/version/` 下面的 **最新版本目录**（最高的语义版本号）。使用此版本进行所有版本级字段。
3. **主要语言环境**是 `en-US`，除非用户指定其他。

## 元数据文件路径

- **应用信息字段** (`subtitle`)：`metadata/app-info/{locale}.json`
- **版本字段** (`keywords`, `description`, `whatsNew`)：`metadata/version/{latest-version}/{locale}.json`
- **应用名称**：可能不在导出的元数据中。如果 `name` 在 app-info JSON 中缺失，则通过 `asc apps info list` 获取或询问用户。不要将其标记为缺失字段错误。

## 第一阶段：离线检查

对本地元数据目录运行这 5 个检查。无需网络调用。

### 1. 关键词浪费

对 `subtitle` 字段（如果可用，则包括 `name`）进行分词。标记任何在 `keywords` 字段中也出现的标记——它已经被索引，浪费了关键词预算。

```
严重性：⚠️ 警告
示例：  "quran" 出现在副标题和关键词中——从关键词中删除以释放 6 个字符
```

如何检查：
1. 读取 `metadata/app-info/{locale}.json` 获取 `subtitle`（如果存在，则读取 `name`）
2. 读取 `metadata/version/{latest-version}/{locale}.json` 获取 `keywords`
3. 分词副标题（+ 名称）：
   - **拉丁/西里尔文字脚本**：按空格分割，去除首尾标点，转换为小写
   - **中文/日文/韩文**：按 `、` `，` `,` 或迭代字符——每个字符或字符组是一个标记。空白分词不适用于 CJK。
   - **阿拉伯文**：按空格分割，然后生成前缀去除变体（去除 `ال` 前缀），因为 Apple 可能会规范化定冠词。例如，"القرآن" 在副标题中应标记 "القرآن" 和 "قرآن" 在关键词中。
4. 按逗号分割关键词，去除空白，转换为小写
5. 报告交集（包括前缀去除产生的模糊匹配）

### 可选：应用标签对齐

应用标签是 Apple 生成的标签，可以出现在搜索结果和产品页面上。它们不是可编辑的 ASO 元数据，但它们是 Apple 分类与预期定位一致的有用证据。

```bash
asc app-tags list --app "APP_ID" --output json
asc app-tags view --app "APP_ID" --id "TAG_ID" --output json
```

仅用作上下文：
- 如果可见标签强化了副标题/关键词策略，则记录对齐情况。
- 如果标签指向了意外的类别或用途，则建议可能改进未来分类的元数据/类别更改。
- 不要承诺更改元数据会立即更改 Apple 生成的标签。

### 可选：官方 Apple 搜索计划

当 App Store Connect 和 Apple Ads 凭据都配置时，使用实验性的只读计划将选定的元数据与官方付费搜索证据关联：

```bash
asc optimize search plan \
  --app "APP_ID" \
  --version "1.2.3" \
  --ad-account "AD_ACCOUNT_ID" \
  --country "US" \
  --genre "PRODUCTIVITY_UTILITIES" \
  --locale "en-US" \
  --out-dir ".asc/optimization/1.2.3" \
  --output markdown
```

- 使用 `asc auth` 分别认证 App Store Connect 和 Apple Ads；两组凭据是独立的。
- 将生成的 CSV 和 JSON 文件视为审查工件。该命令不会应用元数据、确切关键词或否定关键词，并且部分 Apple Ads 源失败会保留在报告中可见。
- 将 Apple 的流行度、应用特定的付费覆盖范围、付费搜索结果和元数据覆盖范围区分开来。不要从该计划推断有机排名或关键词难度。

### 2. 未充分利用的字段

标记使用量低于推荐最小值的字段：

| 字段 | 最小值 | 限制 | 理由 |
|-------|---------|-------|-----------|
| 关键词 | 90 个字符 | 100 | 90%+ 使用最大化索引 |
| 副标题 | 20 个字符 | 30 | 65%+ 使用建议 |

```
严重性：⚠️ 警告
示例：  keywords 是 62/100 个字符（62%）—— 38 个字符的索引机会未使用
```

### 3. 缺失字段

标记空或缺失的必填字段：`subtitle`、`keywords`、`description`、`whatsNew`。

注意：`name` 可能不在导出中——只有在 app-info JSON 明确包含 `name` 键且值为空时才标记它。

```
严重性：❌ 错误
示例：  副标题对于语言环境 en-US 为空
```

### 4. 坏关键词分隔符

检查 `keywords` 字段的格式问题：
- 逗号后的空格 (`quran, recitation`)
- 使用分号代替逗号 (`quran;recitation`)
- 使用管道代替逗号 (`quran|recitation`)

```
严重性：❌ 错误
示例：  keywords 包含逗号后的空格——浪费 3 个字符
```

### 5. 跨语言关键词差距

比较所有可用语言环境的 `keywords` 字段。标记关键词与主要语言环境（默认为 `en-US`）完全相同的语言环境——这通常意味着它们没有被本地化。

```
严重性：⚠️ 警告
示例：  ar 关键词与 en-US 相同——可能未针对阿拉伯市场本地化
```

如何检查：
1. 加载所有语言环境的关键词
2. 比较每个非主要语言环境与主要语言环境
3. 标记精确匹配（不区分大小写）

### 6. 描述关键词覆盖

检查关键词是否自然地出现在 `description` 字段中。虽然 Apple **不**对描述进行索引，但看到其搜索词反映在描述中的用户更有可能下载——这提高了转化率，从而间接提升了排名。

```
严重性：💡 信息
示例：  16 个关键词中的 3 个未在描述中找到：namaz, tarteel, adhan
```

如何检查：
1. 加载每个语言环境的 `keywords` 和 `description`
2. 对于每个关键词，检查它是否作为子字符串出现在描述中（不区分大小写）
3. 考虑屈折形式：阿拉伯语词根匹配、动词变位（例如，"memorizar" ≈ "memorices"）、和格 declines（例如，俄语 "сура" ≈ "суры"）
4. 按语言环境报告缺失的关键词——建议将它们自然地编织到现有句子中
5. **不要**标记：非拉丁脚本关键词在非拉丁描述中（例如，Cyrillic 文本中的 "quran"）——这些针对不同的搜索路径

## 第二阶段：Astro MCP 关键词差距分析

如果 Astro MCP 可用且应用被跟踪，则运行关键词差距分析。**按商店/语言环境运行此操作，而不仅仅是美国商店**——关键词流行度在不同市场差异很大。

### 步骤

1. **获取当前关键词**：使用应用 ID 调用 `get_app_keywords` 以检索被跟踪的关键词及其当前排名。

2. **检查多商店跟踪**：查询每个语言环境的 App Store 地区的现有跟踪。报告未跟踪的商店为不可用并继续审计。仅在用户单独授权跟踪设置时使用 `add_keywords`；未跟踪商店的空排名不能证明表现不佳。

3. **提取竞争对手关键词**：使用 3-5 个顶级竞争对手应用 ID 调用 `extract_competitors_keywords` 以发现关键词差距。这是最高价值的 Astro 工具——它揭示了竞争对手排名而您未排名的关键词。尽可能按商店运行。

4. **获取建议**：使用应用 ID 调用 `get_keyword_suggestions` 以根据类别分析获取额外建议。

5. **检查当前排名**：调用 `search_rankings` 以查看应用在每个商店中针对被跟踪关键词的当前排名。

6. **与元数据对比**：将建议和竞争对手关键词与本地元数据中的 `subtitle`、`name`（如果可用）和 `keywords` 字段的标记进行比较。

7. **暴露差距**：按流行度分数（最高优先级）报告所有差距。包括来源（竞争对手分析 vs. 建议）。

### 跨字段组合策略

在建议关键词添加时，考虑单个词如何跨索引字段组合（标题 + 副标题 + 关键词）。例如：
- 在 "vakti" 已经存在于副标题时将 "namaz" 添加到关键词，可以匹配搜索 "namaz vakti"（66 流行度）
- 在副标题中存在 "Quran" 时将 "holy" 添加到关键词，可以匹配 "holy quran"（58 流行度）

在建议中标记高价值组合。

### 跳过条件

- Astro MCP 未连接 → 跳过并添加注释："连接 Astro MCP 以进行关键词差距分析"
- 应用未在 Astro 中跟踪 → 跳过并添加注释："使用 `mcp__astro__add_app` 将应用添加到 Astro 以进行差距分析"
- 商店未针对语言环境跟踪 → 报告差距并跳过其排名；跟踪设置需要单独授权

## 注意事项

- 离线检查无需任何网络访问——它们仅读取本地文件。
- Astro 差距分析是可加的——即使没有它，审计也很有用。
- 在运行此技能后运行 `asc metadata pull` 以确保规范元数据文件是最新的。
- 对于审计后的关键词仅跟进，优先使用规范关键词工作流：
  - `asc metadata keywords diff --app "APP_ID" --version "1.2.3" --dir "./metadata"`
  - `asc metadata keywords apply --app "APP_ID" --version "1.2.3" --dir "./metadata" --confirm`
  - 当导入外部关键词研究时 `asc metadata keywords sync --app "APP_ID" --version "1.2.3" --dir "./metadata" --input "./keywords.csv"` 时使用
- 更改后，重新运行审计以验证修复。
- 字段利用率表包括促销文本以保持完整性，但不会验证其内容（Apple 不对其进行索引）。
