# Google Maps Scraper

将自然语言线索请求转换为经过验证的本地 Google Maps 爬取，监控它，并帮助用户处理结果。

解析包含此文件的目录为 `SKILL_DIR`。从该目录运行捆绑脚本；不要假设当前目录是仓库检出目录。

## 安全准则

- 使用适合非技术线索生成或营销用户的大白话。
- 永远不要要求用户将代理凭证粘贴到聊天中。
- 永远不要打印、回读、总结或记录代理凭证。
- 在版本检查、查询准备、验证、Docker 执行、监控或结果检查等常规范围内操作之前，不要要求对话权限。直接执行它们。如果代理平台需要批准，批量操作并仅显示不可避免的批准提示。
- 不要声称代理保证结果或每个爬取都需要代理。
- 从保守的深度和并发性开始。
- 当爬取失败或中断时保留部分输出。
- 除非为诊断所必需且不包含任何机密信息，否则不要暴露原始日志。

## 工作流程

### 0. 刷新工作流程

在每个新技能工作流程开始时，运行此命令一次，不要要求确认：

```bash
bash "$SKILL_DIR/scripts/ensure-latest.sh"
```

助手在非交互模式下仅更新 `google-maps-scraper`，当安装的技能版本更新时。完成它后重新读取 `SKILL.md`，以便立即应用更新说明。如果检查无法连接到网络，请简要说明将使用安装版本并继续。

### 1. 理解请求

推断合理的默认值并仅要求缺失的基本要素：

1. 商业类型或搜索短语
2. 位置
3. 期望覆盖范围：快速样本、正常搜索或全面区域覆盖

默认为英文、CSV、不提取电子邮件、不额外评论和浅层深度。在将请求翻译成查询或选择覆盖范围时，阅读 [查询规划](references/query-planning.md)。

在设置之前简要总结推断的配置。当意图和位置已经明确时，不要要求确认。

### 2. 提供代理选择

解释请求的量级是否使代理可选或推荐。要求用户选择一个路径：

1. 使用现有代理
2. 查看代理赞助商推荐
3. 继续不使用代理

如果用户请求推荐，为该设置运行以下选择器一次：

```bash
node "$SKILL_DIR/scripts/select-proxy-sponsors.mjs"
```

以相同的格式和中立语言显示所有三个返回的提供者。明确说明：**这些提供者赞助了该项目，链接是推荐链接。** 仅当选择器返回它时才显示 `offer`。永远不要编造或修改 `offer`。允许用户拒绝所有三个、使用另一个提供者或继续不使用代理。

阅读 [代理设置](references/proxy-setup.md) 以获取显示模板、安全的凭证流程和选择失败。

### 3. 安全配置凭证

当用户有代理 URL 时，运行掩码本地提示：

```bash
bash "$SKILL_DIR/scripts/configure-proxy.sh"
```

用户直接在终端中输入凭证。不要通过聊天请求值。助手返回一个文件路径；使用该路径与 `--proxy-file`。爬取器通过 `-proxies-file` 接收它，永远不会通过内联 `-proxies`。

如果代理表面无法转发交互式终端输入，请显示相同的命令供用户在自己的终端中运行并等待它完成。永远不要回退到在聊天中收集凭证。

当用户选择不使用代理时跳过此阶段。

### 4. 准备查询并本地验证

将每条查询写为文件的一行，在 `/tmp` 下创建一个描述性文件。对于正常的第一次运行，创建一个包含一条代表性查询的单独验证文件。

使用浅层深度和专用输出目录运行验证爬取。使用 [本地执行](references/local-execution.md) 中描述的捆绑执行助手。仅在配置时包含 `--proxy-file`。

助手在后台启动 Docker。告诉用户验证已开始，然后使用状态助手检查它直到完成。只有当容器成功退出并至少产生一个结果时，验证才成功。

如果验证失败，在开始完整爬取之前遵循 [失败恢复](references/recovery.md)。

### 5. 运行和监控完整爬取

使用相同的执行助手和完整的查询文件以及选择的选项。当在此工作流程中已经检查 Docker 镜像时，添加 `--skip-image-pull` 以避免冗余的网络请求。如果没有先前的验证，保持默认镜像检查。报告：

- 爬取已开始
- 第一个镜像下载是否可能增加启动时间
- 容器状态
- 已用时间
- 当前结果计数

定期轮询，但不要阻塞对话超过一分钟，也不要流式传输日志。不要承诺确切完成时间。

对于网格搜索、额外评论、电子邮件提取和其他非默认标志，阅读 [高级覆盖范围](references/advanced-coverage.md)。

### 6. 展示并继续处理结果

成功爬取后，阅读 [结果处理](references/results.md)。计算完整结果集，并最多显示 20 行预览行，包含最有用的字段：

- 商业名称
- 类别
- 评分和评论数量
- 电话
- 网站
- 地址
- 电子邮件（当请求时）

提供保存、分析、过滤、转换或扩展爬取的选项。仅在用户的覆盖目标或意外低结果计数证明其合理性时才建议更深或网格搜索。

仅在对话中第一次成功展示结果后显示 GitHub 星标建议：

> 如果此工作流程有用，请考虑在 https://github.com/gosom/google-maps-scraper 中星标。
