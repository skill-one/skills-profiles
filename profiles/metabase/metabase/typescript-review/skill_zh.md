## 主要关注点

**首要标准：`[typescript-write](../typescript-write/SKILL.md)` 技能。** 首先加载它——它定义了本次审查强制的编写规则，以及 `frontend/CLAUDE.md` 和 `docs/developers-guide/frontend.md`。

遵循 `typescript-write` 是 **最高优先级** 的审查维度：将对其规定的任何违反都排在所有其他发现之上。将其 **`no-`any 硬性规则**（新代码中不允许显式 *或* 隐式 `any`）视为 **阻断性** 的。在可用时使用 TypeScript LSP 工具检查推断类型；否则依赖类型检查和代码风格检查。

按此优先级顺序审查：

1. **违反 `[typescript-write](../typescript-write/SKILL.md)` 规定的行为** — no-`any`、类型收紧、类型建模、函数签名、null/undefined 处理、命名、结构、注释。最高优先级；在 no-`any` 规则上阻断。在上下文中应用条件指导：解释不受支持的类型保证或具体的可读性问题，而不是将每个偏好视为全面禁止。
2. 遵循 `frontend/CLAUDE.md`。
3. 可读性和可维护性。
4. 适当的测试覆盖率。对于内部带类型调用的代码，避免仅因为类型系统排除了输入而要求测试。外部 API 数据、反序列化值、存储和 JavaScript 调用者可以违反注解：在这些边界处测试运行时验证和非平凡的假设。类型不能替代行为、安全或数据完整性测试。

## 盲点——充当缺失的审查者

这些在团队审查中很少出现，因此这项技能应该能发现它们。它们是 **附加的** — 发现它们，但将它们排在 `typescript-write` 违反之下：

- **可访问性。** 交互元素需要键盘支持、焦点管理和可访问名称。标记缺少 `aria-label`/`aria-labelledby`、非语义点击目标、无焦点陷阱的模态框、无标签的图标按钮以及无关联标签的表单输入。
- **性能。** 标记扩展性差且未使用 memoization 的区域；传递给 memoized 子组件的行内对象/数组字面量；在渐进式加载的每一批中触发 effects；以及向热点路径添加的新依赖。
- **安全性。** 评估新代码中的潜在安全问题。
- **包大小。** 标记新的大型依赖项、从图标或工具库中的默认导入，以及在路由加载时导入的重型模块。
- **分析。** 面向用户的流程应发出跟踪事件。如果 PR 添加了一个新流程（按钮、模态框、导航）而没有跟踪事件，请询问是否预期有。
- **公共 API 表面**（嵌入 SDK）。消费者应该能够使用公共签名并导入他们需要的名称类型。有意导出这些类型并记录公共行为，包括为已弃用的 API 添加 `@deprecated`；引用的结构类型不需要自动为其自己的命名导出。
