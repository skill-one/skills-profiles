# Clojure 开发技能

## 工具偏好

当 `clojure-mcp` 工具可用时（例如 `clojure_eval`、`clojure_edit`），**始终使用它们**，而不是使用 shell 命令（如 `./bin/mage -repl`）。MCP 工具提供：
- 无需 shell 逃逸的直接 REPL 集成
- 更好的错误消息和反馈
- 防止语法错误的结构化 Clojure 编辑

只有在 `clojure-mcp` 不可用时才回退到 `./bin/mage` 命令。

## REPL 驱动的开发工作流

- 从小的、基础的功能开始：
- 确定你的任务所需的核心功能或功能。
- 将每个功能分解为可以独立开发和测试的最小、最基本的功能。
- 在 REPL 中编写和测试：
  - 直接在 REPL（读取-求值-打印循环）中编写每个小函数的代码。
  - 使用各种输入（包括典型用例和相关边界情况）彻底测试它，确保其行为符合预期。
- 集成到源代码中：
  - 一旦函数在 REPL 中工作正常，将其从 REPL 环境移动到你的源代码文件（例如，在适当的作用域内）。
- 逐步增加复杂性：
  - 在经过测试的基础功能上构建更复杂的功能或组件。
  - 将较小的函数组合在一起，并在 REPL 中逐步测试每个新的组合，以验证其正确性。
- 确保依赖测试：
  - 确保每个函数在依赖于其他函数之前都在 REPL 中完全测试。
  - 这确保了你的应用程序的每一层在构建之前都是可靠的。
- 充分利用 REPL：
  - 将 REPL 作为你主要的工具，用于尝试不同的方法、快速迭代，并立即获得代码的反馈。
- 遵循函数式编程原则：
  - 保持函数小、专注和可组合。
  - 使用 Clojure 的函数式编程特性（如不可变性、高阶函数和标准库）编写简洁、高效的代码。

## 如何评估代码

### 自下而上的开发循环

1. 将代码写入文件。
2. 评估文件的作用域并确保它正确加载，使用：

```
./bin/mage -repl --namespace metabase.app-db.connection
```

3. 调用作用域中的函数，使用测试输入，并观察输出是否正确
   可以将这些 REPL 会话试验复制到实际测试用例中，使用 `deftest` 和 `is`。
4. 一旦你知道这些函数是好的，返回到 1，并将它们组合成你需要构建的任务。

## 编写文档字符串

文档字符串是调用者的合同，而不是实现者的日记。它说明函数的作用、输入、输出、抛出的异常以及调用者必须遵守的先决条件/不变式。这些保证和要求**属于**那里——它们正是调用者需要在 IDE 中看到的内容。

当你发现文档字符串中包含实现上下文时，默认情况下是**移动而不是删除**——将其移动到函数体中实际相关的内联注释处。这些上下文通常非常有价值；只是放在了错误的位置（调用者不应该阅读它；站在该行的实现者应该阅读）。只有在它是废话时才删除：自我祝贺、重述明显的内容或记录预期默认值的属性。

在最后一种情况下——叙述属性（如“跨所有支持的应用数据库可移植”）不值得一个句子。如果它不可移植，那要么是一个错误，要么意味着调用者必须自行处理每个情况——在这种情况下，必须记录的是**属性的缺失**。记录与预期的偏差，而不是符合预期。

启发式方法——只有当它通过以下两个测试时，句子才配在文档字符串中占有一席之地：

1. 重写测试（必要但不充分）：如果将体重写为具有相同合同的不同实现可以使句子为假，那么它描述的是实现，而不是合同。将其移动到体中实际应用的行号的内联注释处。

2. 所有权测试：如果句子声明了函数不拥有的代码的事实——调用者的行为、库的保证——它在任何重写中都 trivially 存在，这恰恰是单独重写测试不够的原因。如果这个体依赖于该事实，它是实现上下文：将其移动到调用位置。如果这里不依赖于它，它是关于其他人代码的废话：删除它，让调用者自己的文档字符串来回答它。

每个事实只说一次。重复的散文是预先过时的评论：当事实改变时，一个副本被更新，其余副本则默默腐烂。这在属于你自己的代码中也适用——一个命名空间文档字符串重新总结它自己的多方法，三个兄弟函数携带关于重试行为的相同段落。给事实一个家，让其他地方命名它，而不是重述它。

多行文档字符串并不被禁止——代码必须处理的真正不明显约束值得解释。但要谨慎；过多的细节是失败模式。当诱惑写一个多段落的解释性文档字符串时，先与用户确认。并且优先考虑测试而不是散文：如果未来的读者认为“那样做很傻”并改变了它，测试应该失败并告诉他们原因。如果这种情况持续发生，*那*才是评论值得的信号。

## 编辑的关键规则

- 编辑 Clojure 代码时要小心括号的数量
- 每次更改 Clojure 代码后，使用 `-check-readable` 验证可读性
- 所有文件都以换行符结尾
- 在编辑列对齐的表格代码时，尽量保持列对齐
- 一行中如果没有后续内容，不允许有空格
- 更改模块边界后（添加/删除/重命名 `src` 命名空间、跨模块 `require` 或 `:model/X` 引用，或新模块），运行 `./bin/mage fix-modules-config` 以重新生成 `.clj-kondo/config/modules/config.edn` 并保持 `metabase.core.modules-test` 为绿色。当没有漂移时为 No-op；参见项目 `CLAUDE.md` 中的“模块边界”。
