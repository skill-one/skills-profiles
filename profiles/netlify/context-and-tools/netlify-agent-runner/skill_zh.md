# Netlify Agent Runner

在 Netlify 基础设施上远程运行 AI 编码代理（Claude、Codex、Gemini），以自动化您网站上的开发任务。

## 前置条件

- 网站必须**链接到 Netlify 项目**（通过 `netlify link` 或 `netlify init`）。
- **或者完全跳过链接**：直接将 `--project <name>`（项目 ID 或名称）传递给 `netlify agents:create`，以在首次链接之前定位任何 Netlify 网站。
- Netlify CLI 必须已安装并经过身份验证
- Agent 运行**消耗计划积分**。如果账户没有可用的积分——或者代理/AI 使用限制已达到——`netlify agents:create` 将**被阻止**，运行将不会开始。这是一个需要向用户展示的账户/计划状态问题，而不是需要解决的问题。

## 仅使用已文档化的 CLI 界面

仅通过已文档化的 `netlify agents:*` 命令（以及 `netlify --help` 和公共 CLI 参考）与 agent 任务进行交互。**不要**绕过 CLI：

- **不要 curl `https://api.netlify.com/...`** 来获取、创建或停止任务——端点形状不是公共合同的一部分。
- **不要在已文档化的命令失败时运行 `netlify api <method>`** 作为恢复舱门。
- **不要从 `~/Library/Preferences/netlify/config.json`（或磁盘上的任何位置）读取认证令牌**来对侧信道调用进行身份验证。

如果已文档化的命令失败，请向用户报告确切的错误和上下文并停止——不要发明一种未文档化的方式来访问任务。

## Agent 任务如何运行

在创建任务之前阅读此内容——agent 任务的行为与在本地运行 agent 不同，而且这些差异很容易被忽略。

- **远程，不是本地**。任务在 Netlify 基础设施上运行，而不是在您的机器上。它们在网站的**连接存储库**上运行，而不是在您的本地工作区。远程 agent 只能看到已推送到远程的内容——它看不到未提交或未推送的更改。
- **基于分支**。默认情况下，任务针对生产分支（`main` 或 `master`）。要选择代理从哪个*基础*分支开始，请使用 `-b <branch>` 并确保该分支已**首先推送到远程**，否则 agent 将会从远程不存在的代码开始工作。`-b` 设置基础（起始）分支——不是结果写入的位置（见下一个要点）。
- **输出位于新分支上——不是就地**。代理**不会**将其更改提交到您选择的基础分支。它将其工作推送到一个**新分支**，并拥有自己的**部署预览**，因此您的现有分支（或 `main`）永远不会被覆盖。在新的分支/部署预览上查看任务的结果——不要期望基础分支会直接改变。
- **异步**。`netlify agents:create` 在任务入队后立即返回——它**不会**阻塞直到工作完成。当命令返回时，任务仍在远程运行。
- **没有 webhook 或回调**。当任务状态更改或完成时，没有任何内容通知您。要了解正在发生的事情，您必须使用 `netlify agents:show <task-id>` 或 `netlify agents:list` 进行**轮询**。
- **状态要么是终端的，要么不是**。任务会从 `new` → `running` → 之一是 `done`、`error` 或 `cancelled`。在您根据结果采取行动之前，请持续轮询，直到状态是最后三个中的之一。

### 典型工作流程

1. **创建**任务：`netlify agents:create "<prompt>" -a <agent>`。注意它返回的任务 ID（使用 `--json` 可靠地捕获它）。
2. **轮询**状态：`netlify agents:show <task-id>`。定期重复——没有完成通知——直到状态为 `done`、`error` 或 `cancelled`。
3. **查看**任务达到 `done`（或在 `error` 上检查失败）后的结果。

## 创建 Agent 任务

```bash
# 使用默认代理运行提示
netlify agents:create "添加一个联系表单"

# 选择特定代理：claude、codex 或 gemini
netlify agents:create --prompt "添加暗黑模式" --agent claude
netlify agents:create -p "更新 README" -a codex
netlify agents:create -p "编写单元测试" -a gemini

# 针对特定分支
netlify agents:create -p "修复登录错误" -a claude -b feature-branch

# 通过名称指定项目（如果不在链接的目录中）
netlify agents:create "添加测试" --project my-site-name

# 输出结果为 JSON
netlify agents:create "添加页脚" --json
```

### 选项

| 标志 | 描述 |
|------|-------------|
| `-a, --agent <agent>` | 代理类型：`claude`、`codex` 或 `gemini` |
| `-p, --prompt <prompt>` | 代理执行的提示 |
| `-b, --branch <branch>` | 要操作的 Git 分支 |
| `-m, --model <model>` | 代理使用的模型 |
| `--project <project>` | 项目 ID 或名称 |
| `--json` | 输出结果为 JSON |

## 管理Agent任务

所有 `netlify agents:*` 命令都是**项目范围的**——它们针对单个项目（您的目录链接到的项目，或使用 `--project <name>` 指定的项目），而不是您的整个团队。`netlify agents:list` 仅显示该单个项目的任务；没有跨所有您网站的团队范围命令来列出任务。要查看不同站点的任务，请从其链接的目录运行或为它传递 `--project <name>`。

### 列出任务

```bash
# 列出当前站点的所有任务
netlify agents:list

# 按状态过滤
netlify agents:list --status running
netlify agents:list --status done
netlify agents:list --status error

# 输出为 JSON
netlify agents:list --json
```

状态值：`new`、`running`、`done`、`error`、`cancelled`。

### 显示任务详情

```bash
netlify agents:show <task-id>
netlify agents:show <task-id> --json
```

### 停止正在运行的任务

```bash
netlify agents:stop <task-id>
```

## 作为 Agent 使用

如果您是 AI 代理，可以使用 `netlify agents:create` 将工作委托给在 Netlify 上远程运行的代理——例如，以从不同的模型获取第二意见。

**重要——首先请求许可，作为一个明确的确认步骤。** Agent 任务在 Netlify 基础设施上运行并消耗用户的积分，因此一个真实的批准步骤很重要。在运行任何 `netlify agents:create` 命令之前获得明确许可——并将这视为其自己的回合，与用户的原始请求分开。一个指令性的提示（“启动任务…”、“使用 claude 代理并将其固定到 Opus”）本身**不是**批准：它告诉您他们想要什么，但计费命令仍然等待一个“是”。

使许可请求成为一个具体的提议，而不是菜单：

- **确切的命令**，填写完整——例如 `netlify agents:create -p "<真实的提示>" -a codex`——不是 `<占位符>`，也不是一个选择代理的列表。
- **一个代理，已经选择**——承诺一个 `-a` 值，并说明为什么选择它（“codex 用于对认证逻辑的第二意见”），而不是将 claude/codex/gemini 作为可互换的选项提供。
- **原因**，加上**“是”之后会发生什么**：运行是异步的——`agents:create` 在任务入队后立即返回，没有回调，您将轮询 `netlify agents:show <task-id>` 获取结果。
- **即使一个先决条件缺失**（未经过身份验证、未链接到网站、尚未作为 git 仓库），仍然显示您将在解决后运行的**确切的命令和选择的代理**——暴露阻塞**和**具体的提议，而不是只描述阻塞。

未经用户许可，**永远不要**运行这些命令。

在委托之前，了解您正在放手（见上方“Agent 任务如何运行”部分）：

- **它在远程针对已推送的分支——不是您的本地工作**。远程代理只能看到已提交和推送的代码。**不要**委托依赖于您本地进行中的更改的工作；远程代理看不到它们，并将从过时的代码开始工作。如果任务需要您的当前更改，请先提交并推送它们（或者自己完成工作）。
- **它是异步的——委托不会阻塞您**。任务在远程运行，而您继续工作。但由于没有回调，您必须轮询（`netlify agents:show <task-id>`）来了解结果。不要假设任务已完成，仅仅因为您委托了它——在依赖或描述其结果之前，请检查状态。
- **它是一个独立的、自包含的任务——不是您会话的延续**。远程代理从存储库和您给它的提示开始，重新开始。它没有任何对话上下文，因此请编写一个完整、独立的提示。

适用于：

- **交叉验证**——从不同的模型获取对您实现的第二意见
- **边缘情况发现**——另一个模型可能会发现您遗漏的问题
- **替代方法**——看看不同的模型如何解决相同的问题
- **并行工作**——在您继续其他工作时远程启动一个独立任务，然后轮询其结果
