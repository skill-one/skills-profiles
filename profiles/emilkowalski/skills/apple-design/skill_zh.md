# 苹果设计

## 初始响应

当这个技能在没有具体问题时首次被调用时，仅响应：

> 我已准备好帮助您在网页上构建流畅的苹果风格界面，我的知识来源于苹果的 WWDC 设计演讲，专为网页平台（CSS、指针事件、`requestAnimationFrame`、弹簧库如 Motion/Framer Motion）翻译而来。

不要在用户提问之前提供任何其他信息。

苹果如何构建界面，使其感觉不再像计算机，而是您自身的延伸。这些知识来源于苹果的 WWDC 设计演讲——主要是《流畅界面设计》（WWDC 2018）——经过提炼并翻译到网页平台。

主线：**当界面运动从当前屏幕值开始，继承用户的速度，向前投射动量，并且可以在任何时刻被抓取和反转时，它就感觉活了过来。** 弹簧是使这一切自然发生的工具，因为它们本质上是可以中断的，并且感知速度。

## 核心思想

> "当我们使界面与我们的思考和运动方式保持一致时，就会发生奇妙的事情——它不再感觉像计算机，而是开始感觉是我们无缝的延伸。"

当界面表现得像物理世界一样时，它就是流畅的：事物会立即响应，持续移动，携带动量，在边界处产生阻力，并且可以在运动中重新定向。下面的一切都是接近这种效果的方法。

苹果将设计视为满足人类的四个需求：**安全/可预测性、理解、成就感、快乐。** 这里的每条规则都服务于其中之一。

## 1. 响应——消除延迟

一旦出现延迟，直接性的感觉就会“掉下悬崖”。响应是构建其他一切的基础。

- **在指针按下时响应，而不是在释放时。** 按下按钮的瞬间就高亮显示。等待 `click`/touch-up 才显示反馈会感觉死气沉沉。
- **警惕所有延迟。** 审计防抖动、人工计时器、过渡等待和约 300ms 的点击延迟。输入路径上任何非必要的东西都是倒退。
- **反馈必须在交互过程中持续进行，而不仅仅是在结束时。** 对于拖动、滑块或抽屉，在整个过程中都与指针 1:1 更新 UI——永远不要只在手势完成后才动画。

```css
/* 反馈在按下时存在，并且是即时的 */
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## 2. 直接操作——1:1 追踪

> "触摸和内容应该一起移动。"

当用户拖动某物时，它必须粘在手指上——并尊重从他们抓取的位置开始的偏移量。在抓取时对元素中心进行对齐会立即破坏这种错觉。

- 使用 Pointer Events 和 `setPointerCapture`，以便即使指针离开元素的边界时也能继续追踪。
- 追踪一个短的 **速度/位置历史**（最近的几个 `pointermove` 事件），而不仅仅是当前点——你需要在释放时需要速度。

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // 尊重抓取的位置
  // ...追踪位置和时间戳历史记录以获取速度
});
```

## 3. 可中断性——最重要的原则

> "思考和手势是并行发生的。"

每个动画都必须在任何时刻可中断和可重定向。用户必须能够在飞行中的元素中途抓取并反转它，而无需等待动画完成。用户再次抓取正在关闭的模态应该跟随手指——而不是先完成关闭，然后重新打开。

- **在过渡期间永远不要锁定输入。**
- **始终从 *呈现*（当前）值进行动画，而不是目标值。** 在中断时，读取元素当前的屏幕变换并从那里开始新的动画。从逻辑/目标值开始会导致可见的跳跃。
- **避免使用 CSS 过渡和 `@keyframes` 进行任何手势驱动的操作**——它们在飞行中不能被平滑地抓取和反转。弹簧默认从当前值进行动画，这正是中断需要的。
- **当手势反转时，混合速度——不要硬切。** 在反转时用另一个动画替换一个动画会产生速度不连续性，“砖墙”。携带速度通过重新定位的弹簧库可以避免这种情况。（这是 iOS 的 *加性动画* 原生做的事情；在网页上，选择一个从当前速度重新定位的弹簧库。）
- **将 2D 运动分解为独立的 X 和 Y 弹簧。** 单个弹簧在 2D 距离不同步时，当 X 和 Y 具有不同速度时就会失步。

## 4. 行为优于动画——使用弹簧

> "将动画视为您与对象之间的对话，而不是由界面规定的东西。"

预定义的固定时长动画无法响应新输入。弹簧可以——新输入只是改变了目标，而运动保持连续。对于用户可以触摸的任何东西，使用弹簧。

苹果故意用两个设计师友好的参数替换了物理三重组（质量/刚度/阻尼）。用这些参数思考：

- **阻尼比**——控制超调。`1.0` = 临界阻尼，无弹跳，平滑稳定。`< 1.0` = 超调和振荡。越低 = 越弹跳。
- **响应**——值达到目标的速度，以秒为单位。越低 = 越快。**这不是“持续时间”**——弹簧没有固定持续时间；其稳定时间来自参数。

**默认值：**
- 大多数 UI 从 **阻尼 `1.0`**（临界阻尼）开始——优雅且不分散注意力。
- 仅在手势本身携带动量时（快速滑动、抛掷、拖动释放）添加弹跳（阻尼约 `0.8`）。刚淡入的菜单上的超调感觉不对；你快速滑动的卡片上的超调感觉是对的。

**苹果提供的具体值：**

| 交互 | 阻尼 | 响应 |
| --- | --- | --- |
| 移动/重新定位（例如 PiP） | `1.0` | `0.4` |
| 旋转 | `0.8` | `0.4` |
| 抽屉/表格 | `0.8` | `0.3` |

**网页映射（Motion / Framer Motion）：** `bounce` + `duration` 弹簧 API 与苹果的阻尼 + 响应紧密对应。一个安全的做法是默认所有地方使用 `damping: 1.0` 弹簧；将弹跳保留用于动量驱动的、物理交互。

```js
import { animate } from 'motion';

// 临界阻尼默认（无超调）
animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });

// 动量交互——因为有一个快速滑动先于它——所以有一点弹跳
animate(el, { y: target }, { type: 'spring', bounce: 0.2, duration: 0.4 });
```

## 5. 速度传递——拖动和动画之间的衔接

当手势结束时，动画必须 **在手指的确切速度下继续**，以便在拖动和动画之间没有可见的衔接。这是将“流畅”与“精细”区分开来的细节。

将指针的释放速度作为弹簧的初始速度传递。一些弹簧 API 需要相对速度——通过剩余距离到目标来归一化它：

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

示例：元素在 `y=50`，目标 `y=150`（剩余 100px），手指移动 50px/s → 初始弹簧速度 = `50 / 100 = 0.5`。Framer Motion / Motion 直接取绝对 px/s 速度（`velocity` 选项），所以你通常传递原始值。

## 6. 动量投射——动画到手势的 *去向 *

> "从小输入做出大输出。"

不要从 *释放点* 对齐到最近的边界。使用速度来 **投射静止位置**——就像滚动减速一样——然后对齐到最近投射点的目标。这就是使快速滑动感觉像它把元素抛出去的原因。

苹果的确切投射函数（来自 *流畅界面设计* 样式代码）：

```js
// 减速率 ≈ 0.998 对于正常的滚动感觉；0.99 对于更快的
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);   // 从投影中选择目标
animateSpringTo(target, { velocity: releaseVelocity }); // 然后传递速度（§5）
```

注意：教科书中的物理公式 `v²/(2·decel)` *不是* 苹果提供的——使用上面的指数衰减形式。这是良好底部表单和轮播的标准行为（Vaul、Embla）。

## 7. 空间一致性——对称路径、锚定原点

> "如果某物以某种方式消失，我们期望它从它来的地方出现。"

- **沿相同路径进入和退出。** 从右侧滑入的面板必须向右侧消失。从右侧进入/从底部出去感觉不连贯和令人困惑。
- **将交互锚定到它们的源。** 菜单、弹出窗口或表格应从触发它的元素开始——将 `transform-origin` 设置为触发器，以便按钮和内容之间的空间关系是显而易见的。（这是弹出窗口从触发器而不是中心缩放时相同的原点感知点。）
- **镜像可逆过渡的缓动曲线**，以便出站路径与返回路径匹配（使用两个方向的逆三次贝塞尔控制点）。

## 8. 在手势方向的暗示

人类根据轨迹预测最终状态。中间运动应该暗示事情将要发生——Control Center 模块“向上和向外生长到你的手指方向”。使中间帧指向结果，而不仅仅是盲目地插值到它。

## 9. 橡皮筋效果——软边界

在边界处，逐渐阻力而不是硬停止。硬停止读作“冻结”；连续阻力读作“响应，但这里没有更多东西了”。应用随着用户拖动越过了边界而增加的阻尼。

```js
// 越过边界越远，元素跟随得越少——真实的东西在停止前会减速
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

## 10. 手势设计细节（“感觉”清单）

- **点击：** 在触摸*下*高亮显示（立即），在触摸*上*提交。在目标周围添加约 10px 的滞后/点击填充，并允许通过拖动离开并返回来取消。
- **拖动/滑动：** 在提交到某个方向之前，需要一个小移动阈值（滞后，~10px），然后 1:1 追踪。
- **从第一个移动开始并行检测所有可能的手势**，一旦意图明确，就自信地取消失败者。避免只报告*最终*状态的识别器（`swipeleft`-类型事件）——它们会丢弃您需要用于反馈的连续追踪。
- **最小化歧义延迟。** 双击检测不可避免地会延迟单击；仅在双击确实存在的地方支付这种成本。

## 11. 帧级平滑度

平滑度是关于*帧中有什么*，而不仅仅是帧率。

- 保持每帧位置变化低于感知阈值，以避免闪烁。
- 对于非常快的运动，一个微妙的**运动模糊/拉伸**编码速度，比硬锐利条纹读起来更好。
- `requestAnimationFrame` 是网页的显示同步时钟（苹果使用 `CADisplayLink`）。仅动画合成器友好的属性——`transform` 和 `opacity`——并使用 `will-change` 暗示即将发生的运动。

## 12. 材质与深度——透明度传达层次

苹果使用半透明材料作为浮动功能层，它在不分散注意力的同时带来结构。在网页上，使用 `backdrop-filter` 来模拟。

- **将导航/工具栏/表格构建为半透明层**（`backdrop-filter: blur()` + 半透明背景）的内容在下面滚动——而不是不透明的条形，它们会占用固定的条形。
- **材质重量编码层次：** 较暗/较重的材料分离结构区域（侧边栏）；较轻的材料吸引对交互元素（按钮）的注意。**永远不要将轻质半透明表面堆叠在另一个上面**——可读性会崩溃。
- **较大的表面应读作更厚：** 比小芯片更强的模糊 + 更深的阴影。考虑上下文感知阴影——在繁忙/文本内容上较重，在纯背景上较轻。
- **变暗以聚焦，分离以保持流程。** 一个模态任务将表面与变暗的遮罩一起使用，并将背景推回/向下。一个平行的非阻塞面板使用半透明度和偏移量*而不使用遮罩*，这样流程就不会中断。对于堆叠的表格，逐步变暗并推回每个父层。
- **鲜艳度使文本在变化的背景上保持可读性。** 在模糊/半透明表面之上，不要使用平坦的灰色文本——使用更高对比度、略重的粗细和轻微的字母间距增加。将颜色放在一个实层上，而不是半透明的前景。
- **滚动边缘效果，而不是硬分隔符。** 取代粘性标题下方的 1px 边框，在内容与浮动铬重叠的地方渐变一个小模糊/渐变遮罩——仅在浮动 UI 实际重叠内容的地方。
- **材质化，而不仅仅是淡出。** 对于玻璃/模糊表面，在进入/退出时一起动画模糊半径和缩放，这样表面看起来像是一个真正的材料到达，而不是一个普通的透明度淡出。

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* 亮顶边缘 = 光线照射到材质 */
}
```

## 13. 多模态反馈——运动 + 声音 + 触觉

结合感官的三个规则（来自 *设计音频-触觉体验*）：

1. **因果关系** — 必须明显是什么导致了反馈。在真正的因果事件（切换翻转、项目归位）上触发它，并使其特征与动作的物理性相匹配。
2. **和谐** — 视觉、声音和触觉必须在**同一帧**上触发。它们之间的延迟会破坏错觉。不要让 CSS 过渡延迟音频/触觉（振动 API）。
3. **实用性** — 只在它值得的地方添加反馈。将触觉/声音保留用于有意义时刻（成功、错误、提交、归位）。过度反馈训练用户忽略所有反馈。

## 14. 减少运动与无障碍

减少运动并不意味着*没有*反馈——它意味着更温和、非前庭觉的等效物。响应三个独立信号并将它们融入您的组件：

- **`prefers-reduced-motion: reduce`** — 用短的不透明度**交叉淡入或静态过渡**替换滑动/弹簧/视差。放弃弹性/超调。保持不透明度/颜色变化以帮助理解。
- **`prefers-reduced-transparency: reduce`** — 使半透明表面更冷/更实：提高背景不透明度，去掉模糊。
- **`prefers-contrast: more`** — 近似实心背景，具有定义明确的对比边框。

此外：避免全屏移动背景、慢速循环振荡（接近 0.2 Hz / 每 5 秒一个周期）、以及突然的亮度跳跃（平滑黑暗↔亮主题变化）。在移动时使大型移动对象半透明，并在重新定位大时淡出大的表面，并在稳定后淡入。

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
@media (prefers-reduced-transparency: reduce) {
  .toolbar { background: white; backdrop-filter: none; }
}
```

## 15. 字体排印——光学尺寸、字间距、行高

苹果设计字体以随尺寸变化而改变形状；在网页上也应用相同的纪律。（来自 *UI 字体排印的细节*，WWDC 2020。）

- **字间距（字母间距）是尺寸特定的——对所有尺寸使用一个值。** 大型显示文本需要*负*字间距（随着它们变大，字母读起来太远）；小文本需要稍微*正*字间距以提高可读性。固定的 `letter-spacing` 是错误的。收紧标题，正文接近 `0`。
- **行高（行间距）与尺寸反向跟踪。** 大标题上紧，正文上松。对于具有高大升程/降程的脚本，增加行高；对于密集、信息量大的 UI，收紧行高。
- **从权重+尺寸+行高作为一个组合构建层次结构，而不是单独的尺寸。** 用权重强调——它在不占用更多空间的情况下增加了存在感。
- **尊重用户的文本大小设置**（动态类型）。与文本一起缩放布局——使用 `rem`/`em` 中的间距，而不是固定的 px——以便更大的字体不会破坏布局。
- **默认使用平台的系统字体**，然后再使用自定义字体；它已经提供了光学尺寸、跟踪表和可读性调整。只有在有理由的情况下才覆盖。

```css
:root { font: 100%/1.5 system-ui, sans-serif; } /* 正文：系统字体，舒适的行高 */

.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* 大文本的紧行高 */
  letter-spacing: -0.02em;  /* 随着它变大，负字间距 */
  font-optical-sizing: auto;
}
```

## 16. 设计基础——八个原则

上述运动和工艺服务于苹果的八个设计原则（*伟大设计的原则*，WWDC 2026）。将这些用作您推理的名称：

1. **目的。** 带着意图进行创作；决定*不*要构建什么。每个功能都会占用用户的时光、注意力和信任——只在它值得的地方花费这笔预算。
2. **自主权。** 让人们保持控制：提供选择，不要强迫单一路径。用宽恕来支持它——容易撤销错误，仅对真正破坏性、不可逆的操作使用确认对话框（谨慎使用；过度使用会训练人们点击通过）。
3. **责任感。** 以用户的利益行事。隐私：在正确的时机询问，仅需要什么，透明地。安全：预见滥用和伤害——特别是与 AI（一个对过敏的食谱应用必须不会建议有害成分）。添加预览、确认、免责声明；削减风险大于其价值的特性。
4. **熟悉度。** 基于人们已经知道的东西进行设计。使用既不太具体也不太抽象的隐喻（垃圾桶意味着删除），并尊重它们的物理性。保持一致性：看起来相同的元素必须行为相同，并位于相同的地方（在 macOS 上，关闭总是在左上角）以便人们可以预测接下来会发生什么。只有在你能够证明它更好时才打破熟悉的模式——然后测试它，不要假设。
5. **灵活性。** 为不同的上下文、设备和能力的完整范围进行设计。适应平台（iPhone = 快速触摸；桌面 = 精确指针控制的深度工作流）和情况。包容性设计（年龄、语言、专业知识、无障碍）。当没有单一布局适合每个人时，让人们可以个性化——重新排列控件，隐藏他们不使用的部分。
6. **简单性——不是极简主义。** 剥去不必要的，使核心目的发光；将所有东西埋藏在同一个地方看起来极简，但并不简单。要简洁（平实的语言、无术语、更少的步骤）并清晰（使用层次结构——顺序、间距、对比度——使最重要的事情最明显）。每个元素都应有其位置；有时*添加*上下文会简化（一个显示剩余时间的视频卷动器）。
7. **工艺。** 对细节的毫不妥协的注意力建立了信任。美丽的字体排印、适应光线/黑暗的颜色、清晰的图标和立即、自然的反馈的响应式动画。没有什么是随机的——每个间距、时间和对齐值都是一个你可以说服的刻意选择。抖动的滚动、未对齐的图标和旋转时破坏的布局读作粗心大意。工艺需要迭代和持久性——随着功能和硬件的变化，继续发展设计。
8. **愉悦。** 这是得到其他七个正确的结果，而不是在顶部添加彩带。决定您想让人们感受到的情绪（平静、自信、兴奋），并在每个决策中加强它。

服务于这些战术规则的规则：

- **反馈有四种类型：** 状态、完成、警告、错误。确认有意义的操作，显示正在进行的状态，在问题发生前警告，在线内验证（而不是在提交时）。
- **导航。** 每个屏幕都应该回答：我在哪里？我可以去哪里？那里有什么？我如何退出？永远不要困住用户。
- **分组和映射。** 邻近性暗示关系；将控件放置在它影响的附近，并排列控件以映射它们更改的内容。如果你需要一个标签来解释控件，那么映射很弱。
- **直接、具体的标签胜过安全的通用标签。** 为导航项命名其内容（“进度”、“库”），而不是模糊的伞（“主页”）。具体性创造了可预测性。

## 17. 流程

- **交互式原型——交互式演示比“一百万个静态设计”更有价值。** 您通过构建和玩它来发现界面；工作原型还设定了一个具体的标准，可以防止平庸的最终实现。
- **将交互设计和视觉效果一起设计。** “你不应该能够说出它们在哪里结束和哪里开始。” 运动不是在像素之后添加的层。
- **与真实的人在真实的环境中测试**，并使用新鲜的眼睛审查运动——慢速播放/逐帧播放以捕捉在满速时不可见的内容。
