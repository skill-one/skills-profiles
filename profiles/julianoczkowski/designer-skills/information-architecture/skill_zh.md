这项技能定义了产品或网站的结构骨架。它位于设计简报和开发之间。在写完简报后、创建任务前运行此技能。

## 示例提示

- "在开始构建之前，为这个应用程序规划信息架构"
- "规划导航和页面结构"
- "我需要为文档网站组织内容"
- "定义新用户引导体验的用户流程"

## 流程

1. 在 `.design/*/DESIGN_BRIEF.md` 中查找现有的设计简报。如果存在多个子文件夹，使用最新修改的文件夹，或者询问用户他们正在处理哪个功能。如果不存在简报，询问用户他们正在构建什么以及为谁构建。

2. 探索现有的代码库以了解已经存在的结构：
   - **路由**：Next.js `app/` 或 `pages/` 目录、React Router 配置、Vue Router、SvelteKit 路由或静态 HTML 页面文件
   - **导航组件**：页眉、侧边栏、导航栏、面包屑、页脚组件
   - **布局组件**：根布局、嵌套布局、页面包装器、容器组件
   - **页面目录**：文件系统中页面当前的组织方式
   - **URL 模式**：现有的别名、动态片段、查询参数约定
   - **CMS 或数据层**：内容模型、API 路由、数据获取模式、MDX/内容目录
   - 如果存在结构，此技能会扩展和改进它。不要提议一个忽略已构建内容的全新架构。

3. 采访用户关于结构决策。对于每个问题，提供你的推荐答案。

   至少涵盖：
   - 用户需要查找或执行的主要事项是什么？按频率排序。
   - 可接受的导航深度级别有多少？
   - 哪些内容会随时间增长，哪些是固定的？
   - 是否有需要不同入口点的不同用户类型？
   - 用户在哪个页面/视图上花费了 80% 的时间？

4. 一旦达成共识，使用以下模板生成信息架构文档，并将其保存为 `INFORMATION_ARCHITECTURE.md`，保存在与设计简报相同的 `.design/<feature-slug>/` 子文件夹中。

## 信息架构文档模板

```markdown
# 信息架构：[产品/网站名称]

## 网站地图

每个页面或视图的层次结构图。使用缩进来显示嵌套。包含每个 URL 模式。

- 首页 `/`
  - 功能 A `/feature-a`
    - 子页面 `/feature-a/detail`
  - 功能 B `/feature-b`
- 设置 `/settings`
  - 个人资料 `/settings/profile`

## 导航模型

描述导航系统：
- **主要导航**：主导航中显示的内容？最大项数。
- **次要导航**：侧边栏、标签或部分内的上下文链接。
- **工具导航**：账户、设置、帮助以及主内容层次结构之外的内容。
- **移动导航**：导航如何适应。汉堡包、底部标签或其他方式。

## 内容层次结构

对于每个主要页面或视图，定义内容优先级：

### [页面名称]
1. [最高优先级内容] -- 为什么它排在第一位
2. [第二优先级] -- 为什么它排在第二位
3. [第三优先级] -- 理由
4. [折叠内容 / 次要内容]

## 用户流程

产品中的关键路径。每个流程是一系列带有决策点的步骤。

### [流程名称]（例如，“新用户引导”或“创建项目”）
1. 用户访问 [页面]
2. 用户看到 [内容/提示]
3. 用户采取行动：[行动]
   - 如果 [条件 A] -> [结果]
   - 如果 [条件 B] -> [结果]
4. 用户到达 [目的地]

## 命名约定

界面中使用的术语词汇表。一致性很重要。选择一个词并在所有地方使用。

| 概念 | UI 中的标签 | 备注 |
|------|-------------|------|
| [事物] | [我们如何称呼它] | [为什么使用这个词] |

## 组件复用图

哪些结构组件（布局、容器、导航元素）在页面之间共享。

| 组件 | 用于 | 行为差异 |
|------|------|----------|
| [布局/组件] | [页面] | [任何变化] |

## 内容增长计划

网站哪些部分会随时间积累内容，以及信息架构如何适应这种增长（分页、过滤、搜索、存档模式）。

## URL 策略

URL 构建的规则：
- 模式：[例如，`/section/subsection/item-slug`]
- 动态片段：[什么被参数化]
- 查询参数：[过滤、排序、分页]
```
