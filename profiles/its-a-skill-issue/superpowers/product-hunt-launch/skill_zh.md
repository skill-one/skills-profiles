# Product Hunt 发布

通过 [inference.sh](https://inference.sh) CLI，借助研究和视觉效果优化您的 Product Hunt 发布。

## 快速入门

> 需要 inference.sh CLI (`belt`)。[安装说明](https://raw.githubusercontent.com/inference-sh/skills/refs/heads/main/cli-install.md)

```bash
belt login

# 生成画廊封面图
belt app run falai/flux-dev-lora --input '{
  "prompt": "干净的产品展示，现代 SaaS 仪表盘界面在笔记本电脑屏幕上，周围有浮动 UI 元素，从蓝色到紫色的柔和渐变背景，专业的营销封面图，极简干净设计",
  "width": 1248,
  "height": 832
}'

# 研究竞争对手发布
belt app run tavily/search-assistant --input '{
  "query": "Product Hunt 本周顶级 SaaS 工具发布"
}'
```

## 发布规范

| 元素 | 规范 | 备注 |
|------|------|------|
| 产品名称 | — | 保持简短、易记 |
| 标语 | **60 个字符限制** | 结尾不加句号 |
| 描述 | 预览中显示前 **260 个字符** | 完整描述可以更长 |
| 画廊图片 | 最多 **8 张图片** | 推荐 1270 x 760 px |
| 主题 | **最多 3 个** | 选择最具体的 |
| 创作者 | 标记所有团队成员 | 他们可以在评论中参与互动 |
| 链接 | 产品 URL | 投票者将访问的链接 |

## 画廊图片

### 第一张图片至关重要

第一张画廊图片会在信息流、邮件摘要和社交分享中显示。它是您的第一印象。

| 位置 | 内容 | 目标 |
|------|------|------|
| **1 (封面)** | 产品实际使用场景，核心价值可见 | 停止滚动，传达产品功能 |
| **2** | 关键功能演示 | 展示“啊哈时刻” |
| **3** | 前后对比或问题/解决方案 | 展示转变效果 |
| **4** | 社会认可或数据指标 | 建立可信度 |
| **5** | 技术差异化或集成 | 供评估者参考 |

### 尺寸

- 推荐：**1270 x 760 px** (约 16:9 比例)
- 最小：600px 宽
- 支持 GIF 动画演示

## 标语

60 个字符。结尾不加句号。必须传达产品功能，以及为什么人们应该关心。

### 有效公式

| 公式 | 示例 |
|------|------|
| [动作] 为 [受众] | "AI 写作助手为开发者" |
| [结果] 没有 [痛点] | "美观文档无需设计技能" |
| [工具] 为 [利益] | "自动解释数据的分析工具" |
| [形容词] [类别] | "即时客户反馈调查" |
| [类别] 为 [细分领域] | "Figma 的数据可视化替代品" |

### 示例

```
❌ "史上最佳项目管理工具" (最高级，52 字符)
❌ "我们帮助您更好地管理项目" (模糊，有句号，37 字符)
❌ "AI 驱动的机器学习项目管理 SaaS" (术语堆砌)

✅ "分钟级文档发布，而非天级" (31 字符)
✅ "AI 将您的数据转化为故事" (32 字符)
✅ "开源 Calendly 替代品" (37 字符)
```

## 时间安排

### 发布时机

| 因素 | 建议 |
|------|------|
| 星期 | **周二、周三或周四** (流量最高) |
| 时间 | **太平洋时间凌晨 12:01** (PH 日的开始) |
| 避免 | 周末、节假日、苹果/谷歌重大事件 |
| 持续时间 | PH 日 = 太平洋时间午夜至午夜 |

### 选择凌晨 12:01 PT 的原因

- 最大程度获得每日顶级位置的时间
- 全天积累投票
- 美国时间早晨邮件摘要包含您的产品
- 允许跨所有美国时区互动

## 创作者评论

上线后 **5 分钟内** 发布。这是您的推销。

### 结构

```
嘿 Product Hunt！👋

[一句话：产品是什么]

[2-3 句话：为什么开发它/发现的问题]

[1-2 句话：如何工作/关键差异化]

[1 句话：未来计划/您希望看到的]

期待您的反馈——乐意回答任何问题！
```

### 示例

```
嘿 Product Hunt！

DataFlow 将原始 SQL 查询在秒级转换为可视化仪表盘。

作为一名数据工程师，我因花费更多时间格式化报告而非分析数据而感到沮丧。我尝试过的每个 BI 工具都需要博士学位才能配置。所以我开发了 DataFlow——粘贴您的 SQL，获得仪表盘。

它自动检测图表类型，处理大型数据集，并支持一键导出 PDF/PNG。

我们为 PH 用户提供首年 50% 折扣。期待您的反馈——您有哪些报告痛点？
```

## 发布日行动指南

### 发布前 (1-2 周)

- [ ] 画廊图片最终确定（建议 5 张）
- [ ] 标语经 5+ 人测试（他们是否理解产品功能？）
- [ ] 创作者评论草拟并校对
- [ ] 带有 PH 徽标的着陆页准备就绪
- [ ] 早期支持者名单准备（希望体验的人）
- [ ] 社交媒体宣传帖子草拟

### 发布日时间表

| 时间 (PT) | 行动 |
|----------|------|
| 凌晨 12:01 | 产品上线，立即发布创作者评论 |
| 凌晨 12:15 | 在个人社交媒体分享 |
| 上午 6:00 | 首次互动检查——回复所有评论 |
| 上午 9:00 | 在相关社区分享（自然，非垃圾信息） |
| 中午 12:00 | 中午检查——回复所有新评论 |
| 下午 3:00 | 分享早期进展或有趣反馈 |
| 晚上 6:00 | 晚上互动——回复剩余评论 |
| 晚上 11:59 | 日结束——结果最终 |

### 互动规则

- **回复每条评论**——参与互动的创作者获得更多曝光
- **反问问题**——创建对话线程
- **保持真诚**——不要使用模板回复
- **不要要求投票**——违反 PH 服务条款
- **自然分享链接**——"查看 [url]" 而非 "请投票"

## 发布后

| 时间 | 行动 |
|------|------|
| 第 1-3 天 | 回复所有剩余评论，感谢支持者 |
| 第 1 周 | 发布“经验总结”博客文章/推特串 |
| 第 2 周 | 跟进评论中感兴趣的用戶 |
| 第 1 个月 | 检查是否符合“每周/每月产品”资格 |

## 常见错误

| 错误 | 问题 | 解决方法 |
|------|------|------|
| 周五/周末发布 | 流量低，浪费发布 | 仅限周二至周四 |
| 正午发布 | 半天已过 | 凌晨 12:01 PT |
| 无创作者评论 | 看起来被放弃 | 上线后 5 分钟内发布 |
| 要求投票 | 违反 TOS 可能被标记 | 自然分享，让产品说话 |
| 通用画廊图片 | 不展示产品 | 展示真实 UI、真实功能 |
| 不回复评论 | 低互动信号 | 回复每条评论 |
| 主题过多 | 稀释可发现性 | 最多 3 个，选择最具体的 |
| 标语含术语 | 无人知道您做什么 | 清晰、具体、以利益为导向 |
