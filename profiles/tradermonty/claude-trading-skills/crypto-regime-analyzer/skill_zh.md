# 加密货币市场状态分析器技能

## 目的

使用基于数据的6组件评分系统（0-100）量化加密货币市场状态。这是加密货币领域的`市场广度分析器`+`风险敞口教练`的类比：它在进行任何币种级别的分析之前，回答“加密货币市场目前支持何种立场？”

**评分方向：** 100 = 最大风险偏好健康（广泛参与、健康趋势、理性杠杆），0 = 严重风险规避。

**无需API密钥** — 使用CoinGecko的免费公共API和币安的公共期货端点。

## 何时使用此技能

- 用户询问“加密货币现在是风险偏好还是风险规避？”或“加密货币市场有多健康？”
- 用户询问“现在是山寨币季节吗？”或关于BTC主导方向的
- 用户询问资金利率是否过热
- 用户在筛选个别币种之前，想要加密货币套利的风险敞口立场
- 用户希望在股票`市场状态每日`工作流程旁边进行每日加密货币状态检查

## 此技能不做什么

- 没有币种选择，没有买入/卖出信号，没有价格目标
- 没有执行或投资组合变更 — 仅描述状态
- 人类决策关卡仍然是核心，与项目愿景一致

## 前置条件

- **Python 3.9+** 与 `requests`（仅实时模式；离线模式仅使用标准库）
- **互联网访问** 到 `api.coingecko.com` 和 `fapi.binance.com`（实时模式）
- **无需API密钥**

## 组件模型

| # | 组件 | 权重 | 它回答的问题 |
|---|---|---|---|
| 1 | BTC趋势结构 | 25% | 备用资产的 PRIMARY 趋势是否完好？（价格与50/200DMA堆叠，200DMA斜率） |
| 2 | 山寨币广度参与 | 20% | 山寨币参与有多广泛？（前N个中超过200DMA的百分比，50DMA确认） |
| 3 | BTC主导状态 | 15% | 资本正在哪里旋转？（主导方向与BTC趋势联合解释） |
| 4 | 永续资金状态 | 15% | 杠杆有多拥挤？（主要市场的平均资金；在极端情况下反着来） |
| 5 | 回撤与波动率位置 | 15% | 我们在周期中的哪个位置？（从1年高点回撤，已实现波动率百分位数） |
| 6 | 动量冲刺/冲刷 | 10% | 短期确认（30d内宇宙中正面的百分比） |

缺失的组件将按比例重新分配权重（与`市场广度分析器`的约定相同）。完整评分逻辑：`references/crypto_regime_methodology.md`。

### 状态区域

| 分数 | 区域 | 姿态 |
|---|---|---|
| 80-100 | RISK_ON | 观察到广泛的风险偏好条件；在决策前审查风险限额 |
| 40-79 | NEUTRAL | 观察到混合条件；没有强烈的区域结论 |
| 0-39 | RISK_OFF | 观察到防御性市场条件；审查现有的风险控制 |

这些都是启发式描述带，不是经过验证的分配规则。参见
`references/VALIDATION.md` 以获取当前的证据边界以及在进行定量性能声明之前所需的工件。

## 执行工作流程

### 第1阶段：运行分析脚本

**实时模式**（获取CoinGecko + 币安；当天的第一次运行在默认 `--top-n 20` 由于免费套餐速率限制节流大约需要2-4分钟；同日重新运行命中缓存并即时）：

```bash
mkdir -p reports/<例行或日期>
python3 skills/crypto-regime-analyzer/scripts/crypto_regime_analyzer.py \
  --output-dir reports/<例行或日期>
```

**离线模式**（无网络；方法参考中的快照模式）：

```bash
python3 skills/crypto-regime-analyzer/scripts/crypto_regime_analyzer.py \
  --input-json snapshot.json \
  --output-dir reports/<例行或日期>
```

选项：`--top-n <int>` 宇宙大小（默认20），`--cache-dir <路径>` 获取缓存位置（默认 `.crypto_regime_cache`），`--quiet`。

### 第2阶段：解释输出

脚本写入 `crypto_regime.json`（机器可读，用于链接到其他技能）和 `crypto_regime.md`（一页报告），并打印一行摘要：

```
CRYPTO REGIME: NEUTRAL (score 68.4/100) — 观察到混合条件；没有强烈的区域结论
```

在展示结果时，首先引出区域和立场，然后解释导致分数的1-2个组件，使用它们的 `signal` 字符串。标记任何报告 `data_available: false` 的组件以及这对置信度的影响。

### 第3阶段（可选）：向下传递

JSON复合体可以嵌入到 `exposure-coach` 风格的立场摘要中作为
一个描述加密市场输入。它不能独立授权、阻止、调整或执行交易。

## 输出

脚本将两个工件写入 `--output-dir` 并打印用于工作流程链接的一行摘要：

- `crypto_regime.json` — 完整机器可读分析：`metadata`，每个组件的结果（`score`，`signal`，`data_available`，组件特定字段），以及 `composite` 块（`score`，`zone`，`guidance`，`effective_weights`）。
- `crypto_regime.md` — 一页报告：复合分数与区域条形图，立场线，每个组件表（权重 / 分数 / signal），以及置信度注释。
- 控制台：`CRYPTO REGIME: <区域> (score <N>/100) — <立场>` 加上任何跳过组件的警告。

## 资源

- `references/VALIDATION.md` — 验证状态、证据边界和再生产要求。
- `references/crypto_regime_methodology.md` — 完整评分依据，每个阈值表，离线快照JSON模式，以及实时数据源端点列表。
- `scripts/crypto_regime_analyzer.py` — CLI协调器（入口点）。
- `scripts/data_client.py` — CoinGecko/币安获取器，每日缓存，主导历史累积器，离线加载器。
- `scripts/calculators/` — 每个组件一个模块；纯函数，完全单元测试。
- `scripts/scorer.py` — 加权复合体与按比例重新分配权重。
- `scripts/tests/` — 涵盖每个组件、评分器、稀疏数据故障关闭行为和端到端牛/熊/退化快照的测试。

## 已知限制

- **主导历史在本地累积。** CoinGecko的免费套餐仅暴露*当前*主导，因此客户端在缓存目录中存储每天的一个观察值。主导组件报告 `data_available: false`，直到存在31个每日观察值（权重在此期间按比例重新分配）。通过 `--input-json` 更快地启动它。
- **资金是尽力而为的。** 如果币安的端点无法访问（地理限制、中断），组件会优雅地跳过。
- **宇宙按市值顶-N**，排除稳定币和包装/质押资产；它不是一个固定指数，因此组成会随着市场漂移。
- 阈值是启发式的，并在方法参考中记录；它们是保守的默认值，不是回测最优值。
