# FTD检测技能

## 目的

使用威廉·欧奈尔（William O'Neil）经过验证的方法论，检测确认市场底部的Follow-Through Day（FTD）信号。生成质量分数（0-100），并提供回调后重新入场市场的风险敞口指导。

**与市场顶部检测器互补：**
- 市场顶部检测器 = 防御型（检测派发、轮动、恶化）
- FTD检测器 = 进攻型（检测反弹尝试、底部确认）

## 何时使用此技能

**英文：**
- 用户询问“市场是否见底？”或“现在是否安全买入？”
- 用户观察到市场回调（3%+下跌）并希望了解重新入场时机
- 用户询问关于Follow-Through Day或反弹尝试
- 用户希望评估近期反弹是否可持续
- 用户询问回调后如何增加股票敞口
- 市场顶部检测器显示高风险，用户希望确认底部信号

**日文：**
- 「底打ちした？」「買い戻して良い？」
- 調整局面（3%以上の下落）からのエントリータイミング
- フォロースルーデーやラリーアテンプトについて
- 直近の反発が持続可能か評価したい
- 調整後のエクスポージャー拡大の判断
- Market Top Detectorが高リスク表示の後の底打ちシグナル確認

## 与市场顶部检测器的区别

| 方面 | FTD检测器 | 市场顶部检测器 |
|------|----------|---------------|
| 关注点 | 底部确认（进攻型） | 顶部检测（防御型） |
| 触发条件 | 市场回调（3%+下跌） | 市场处于或接近高点 |
| 信号 | 反弹尝试 → FTD → 重新入场 | 派发 → 恶化 → 出场 |
| 分数 | 0-100 FTD质量分数 | 0-100顶部概率 |
| 操作 | 何时增加敞口 | 何时减少敞口 |

## 执行工作流程

### 第一阶段：执行Python脚本

运行FTD检测器脚本：

```bash
python3 skills/ftd-detector/scripts/ftd_detector.py --api-key $FMP_API_KEY
```

脚本将：
1. 从FMP API获取标普500和QQQ的历史数据（60个以上交易日）
2. 获取两个指数的当前报价
3. 运行双指数状态机（回调 → 反弹 → FTD检测）
4. 评估回调后健康状况（派发日、无效化、强力趋势）
5. 计算质量分数（0-100）
6. 生成JSON和Markdown报告

**API预算：** 4次调用（远低于FMP每日250次的免费额度）

### 第二阶段：展示结果

向用户展示生成的Markdown报告，突出显示：
- 当前市场状态（回调、反弹尝试、FTD确认等）
- 质量分数和信号强度
- 推荐的敞口水平
- 关键观察水平（摆动低点、FTD日低点）
- 回调后健康状况（派发日、强力趋势）

### 第三阶段：情境指导

根据市场状态提供额外指导：

**若FTD确认（分数60+）：**
- 建议关注处于合适基础的领先股票
- 参考CANSLIM筛选器寻找候选股票
- 提醒仓位规模和止损设置

**若反弹尝试（第1-3天）：**
- 劝导保持耐心，不要提前买入FTD
- 建议建立观察列表

**若无回调：**
- 上升趋势中FTD分析不适用
- 转向市场顶部检测器获取防御信号

## 状态机

```
NO_SIGNAL → CORRECTION → RALLY_ATTEMPT → FTD_WINDOW → FTD_CONFIRMED
                ↑              ↓               ↓              ↓
                └── RALLY_FAILED ←─────────────┘     FTD_INVALIDATED
```

| 状态 | 定义 |
|------|------|
| NO_SIGNAL | 上升趋势，无合格回调 |
| CORRECTION | 3%+下跌伴随3天以上下跌 |
| RALLY_ATTEMPT | 摆动低点反弹的第1-3天 |
| FTD_WINDOW | 第4-10天，等待合格FTD |
| FTD_CONFIRMED | 检测到有效FTD信号 |
| RALLY_FAILED | 反弹跌破摆动低点 |
| FTD_INVALIDATED | 收盘低于FTD日的低点 |

## 质量分数（0-100）

| 分数 | 信号 | 敞口 |
|------|------|------|
| 80-100 | 强FTD | 75-100% |
| 60-79 | 中等FTD | 50-75% |
| 40-59 | 弱FTD | 25-50% |
| <40 | 无FTD/失败 | 0-25% |

## 前置条件

- **FMP API密钥：** 必须设置。通过环境变量`FMP_API_KEY`或`--api-key`标志传递。
- **Python 3.9+：** 安装`requests`库。
- **API预算：** 每次执行4次调用（远低于FMP每日250次的免费额度）。

## 输出文件

- JSON：`ftd_detector_YYYY-MM-DD_HHMMSS.json`
- Markdown：`ftd_detector_YYYY-MM-DD_HHMMSS.md`
