# 文件名与命名规范审计

## 说明

对代码库中所有文件名和命名规范进行系统性审计，以识别不一致、反模式以及命名标准的违规行为。

### 第一阶段：发现与标准提取

#### 第一步：查找所有文件
使用 Glob 识别代码库中的所有文件：
- 源文件（`.ts`、`.tsx`、`.js`、`.jsx` 等）
- 配置文件
- 文档文件
- 测试文件

创建包含所有待审计文件的全面待办事项列表。

#### 第二步：提取命名标准

读取存储库中的所有 `AGENTS.md` 文件：
- 根目录 `AGENTS.md`（如果存在）
- 特定目录的 `AGENTS.md` 文件

提取命名规范：
- 文件命名模式（kebab-case、PascalCase 等）
- 目录结构规则
- 组件命名规则
- 工具/辅助函数命名规则
- 测试文件命名规则
- 配置文件命名规则
- 常量/枚举文件命名规则

#### 第三步：识别隐式模式

即使没有明确的 `AGENTS.md` 规则，也要识别模式：
- 每个目录中最常见的命名规范
- 分组模式（例如，`*.service.ts`、`*.controller.ts`）
- 组织模式（例如，`components/`、`utils/`、`lib/`）

### 第二阶段：系统性文件审计

对待办事项列表中的每个文件：

#### 第一步：分析文件名
- 当前文件名是什么？
- 它使用哪种命名规范？
- 它是否描述清晰且明确？
- 它是否与其用途/内容匹配？

#### 第二步：对照标准检查

与以下内容进行比较：
- 此目录的显式 `AGENTS.md` 规则
- 同一目录中的隐式模式
- 文件类型的常见命名规范
- 框架/语言的最佳实践

#### 第三步：识别问题

**命名规范违规**：
- 错误的大小写（例如，应使用 kebab-case 时使用 PascalCase）
- 混合规范（例如，`userAuth.service.ts` 混合 camelCase 和点表示法）
- 与目录模式不一致

**清晰度问题**：
- 含糊的名称（例如，`utils.ts`、`helpers.ts`、`stuff.ts`）
- 过于冗长的名称
- 具有误导性的名称（内容与名称不符）
- 缺乏上下文的缩写

**反模式**：
- 临时名称（例如，`temp.ts`、`test.ts`、`new-*.ts`、`*-v2.ts`）
- 泛化名称（例如，`index2.ts`、`common.ts`）
- 过时的名称（例如，`old-*.ts`、`legacy-*.ts`）
- 功能标志名称（例如，`*-new.ts`、`*-enhanced.ts`）

**组织问题**：
- 文件位于错误目录
- 缺少分组后缀（例如，应为 `*.service.ts`）
- 与兄弟文件不一致

#### 第四步：检查文件内容
读取文件以验证：
- 文件名是否准确描述内容？
- 基于文件内容是否存在更好的名称？
- 文件内部是否存在命名规范违规（类名等）？

#### 第五步：记录发现

将以下内容存储在内存中：
```
文件：path/to/filename.ts
使用的规范：camelCase
应改为：kebab-case
模式：违反目录规范
问题：
- [具体问题]
建议名称：[better-name.ts]
严重性：[HIGH|MEDIUM|LOW]
```

#### 第六步：更新待办事项
在待办事项列表中标记文件为已审计。

### 第三阶段：模式分析

审计所有文件后：

#### 第一步：识别系统性问题
- 哪些目录存在最多不一致？
- 哪些命名模式被最频繁违反？
- 是否存在相似违规的集群？

#### 第二步：查找异常情况
- 不匹配任何模式的文件
- 唯一命名方案
- 孤立的文件类型

#### 第三步：检测缺失标准
- 缺乏明确命名规范的目录
- 没有建立模式的文件类型
- 需要创建 `AGENTS.md` 文档的区域

## 关键原则

- **绝不编辑文件** - 这是审计，不是重命名
- **绝不跳过文件** - 审计待办事项列表中的每个文件
- **必须读取 `AGENTS.MD`** - 首先提取显式标准
- **必须识别模式** - 找到隐式规范
- **必须保持一致性** - 对类似文件应用相同标准
- **必须检查内容** - 验证名称与文件内容匹配
- **必须跟踪进度** - 审计时更新待办事项列表
- **必须标记反模式** - 特别是临时/迁移名称

## 成功标准

完整的命名审计包括：
- 审计代码库中所有文件
- 提取并应用所有 `AGENTS.md` 标准
- 为每个目录识别隐式模式
- 按严重性分类违规
- 识别系统性问题
- 记录缺失标准
- 生成结构化报告
- 分析统计数据和趋势

完成审计后，按照手册 `15.04` 为所有发现的问题创建 `tk` ticket。
