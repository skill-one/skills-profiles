# Meshy 3D 生成

使用 Meshy CLI **0.4.0** 将用户的请求转换为交付的资产。完成意味着将请求的文件保存在请求的位置、检查可用的预览，并完成用户请求的任何项目集成。仅登录或任务提交不构成完成。选择最短适用的管道，并重用现有资产进行后续操作。

## 阅读此请求所需内容

| 需求 | 参考 |
|---|---|
| CLI 运行器、凭证或输出位置 | [设置](references/setup.md) |
| 生成、纹理化、绑定、动画或转换 | [管道](references/pipelines.md) |
| 成本、等待、预览、交付或查找先前模型 | [交付](references/delivery.md) |
| 失败或不确定的操作 | [故障排除](references/troubleshooting.md) |

根据需要阅读相关部分；配方是适应请求结果的示例，而不是执行每个阶段的严格要求。未纹理化的模型会跳过纹理生成；现有的 GLB 无需额外的格式转换。当参数不确定时使用命令帮助。

## 首次使用和授权

自动解析运行器：使用兼容的 `meshy`，否则 `npm exec --yes --package=meshy-cli@0.4.0 -- meshy …`。重用已验证的会话。如果需要登录，请按照设置运行 `auth login --device` 在持久工具会话中。显示其验证 URL 和用户代码在 **评论/进度中，而不是最终答案**。在本轮中等待该相同会话，直到它退出，验证 `auth status`，然后继续原始请求。后台进程无法恢复已完成的回合；不要要求“完成”的聊天消息。浏览器批准由用户保留；凭证永远不会属于聊天中。

## 执行边界

- 通过 CLI 运行 API、上传、下载和网格操作。本地输入有 50 MiB 的限制；在适当的地方使用支持 URL 输入路线。
- 使用 `--output-schema v1 --format json --no-update-check` 对于业务命令；认证有自己的 JSON 结构。从用户的输出路径解析 `WORKSPACE` 并将其传递给写入操作。
- 使用 `create --async` 一次性提交，保留拥有的资源和 ID，然后 `wait` 在该任务上。在等待运行命令时保持代理回合活跃。在超时或未知提交时遵循故障排除；这些不会授权另一个付费创建。
- 在用户的批准范围和预算内继续工作。在花费之前提出额外的付费阶段或重跑；交付指定了估算和余额检查。

## 交付

仅下载需要的资产。在可用时检查并显示预览；缺少预览不应阻止交付或被描述为已检查。交付包括早期阶段预览查找、实际费用和现有项目集成。报告结果和任何具体限制；渲染的图像不会建立拓扑质量或提供 3D 查看器。
