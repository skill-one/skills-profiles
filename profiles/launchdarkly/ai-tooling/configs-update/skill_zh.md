# 配置更新与生命周期

您正在使用一个技能，该技能将指导您更新、归档和删除配置及其变体。您的工作是理解配置的当前状态，进行更改，并验证结果。

## 前置条件

此技能要求在您的环境中配置远程托管的 LaunchDarkly MCP 服务器。

**必需的 MCP 工具：**
- `get-ai-config-health` -- 在进行更改前评估配置健康状态（检测缺失的模型、孤立的工具、空配置）
- `get-ai-config` -- 在进行更改前了解当前状态
- `update-ai-config` -- 更新配置元数据（名称、描述、标签、归档）
- `update-ai-config-variation` -- 更新变体模型、提示或参数

**可选的 MCP 工具：**
- `delete-ai-config` -- 永久删除配置（不可逆）
- `delete-ai-config-variation` -- 永久删除变体（不可逆）

## 核心原则

1. **更改前获取**：修改前始终检查当前状态
2. **更改后验证**：再次获取配置以确认更新已应用
3. **删除前归档**：归档是可逆的；删除是不可逆的

## 工作流程

### 第 1 步：评估健康状态并了解当前状态

从 `get-ai-config-health` 开始以获取结构化的健康评估。这可以检测：
- 没有模型的变体（在 UI 中显示为 "NO MODEL"）
- 既没有指令也没有消息的变体
- 孤立的工具引用（附加了不存在于项目中的工具）
- 完全没有变体的配置

健康判断（`healthy`、`warning`、`unhealthy`）有助于您确定要修复的内容的优先级。

然后使用 `get-ai-config` 查看完整详情：
- 当前模式（代理或完成）
- 现有的变体及其模型
- 当前指令或消息
- 附加的工具和参数

### 第 2 步：进行更新

**更新配置元数据** -- 使用 `update-ai-config`：
- 更改名称或描述
- 添加或替换标签
- 使用 `archived: true` 归档（可逆）

**更新变体** -- 使用 `update-ai-config-variation`：
- 切换模型（提供新的 `modelConfigKey` 和 `modelName`）
- 更改指令或消息
- 调整参数（温度、最大令牌等）
- 通过参数对象附加或分离工具

**归档配置** -- 使用 `update-ai-config` 并设置 `archived: true`。归档是**首选**的方法来停用配置：
- 它是可逆的（使用 `archived: false` 解归档）
- 配置会从活动列表中隐藏但被保留
- 调用归档后，将成功的响应视为确认并继续验证
- 当用户说 "删除"、"停用"、"退役"、"不再需要" 时，默认归档，除非他们明确说 "永久删除"

**删除** -- 使用 `delete-ai-config` 或 `delete-ai-config-variation`（不可逆，需要 `confirm: true`）。**始终建议先归档。** 只有在用户明确确认他们希望永久、不可逆删除时才进行删除。

### 第 3 步：验证

使用 `get-ai-config` 确认响应显示您更新的值。

**报告结果：**
- 更新已成功应用
- 配置反映了更改
- 标记任何问题或必要时回滚

## 不要做的事情

- 不要在不先在另一个变体中测试的情况下更新生产配置
- 不要一次性更改多个内容——进行增量更改
- 不要跳过验证
- 不要在未经明确用户确认的情况下删除——始终建议先归档
- 不要因为 API 响应没有回显您发送的确切值而重试更新——改用 `get-ai-config` 进行验证
