# 事实核查器

核查文档中的事实性声明，并基于权威来源提出修正建议。

## 使用场景

在以下用户请求时触发：
- "核查此文档"
- "验证这些 AI 模型规格"
- "检查此信息是否仍然准确"
- "更新此文件中的过时数据"
- "验证此部分中的声明"

## 工作流程

复制此清单以跟踪进度：

```
事实核查进度：
- [ ] 第 1 步：识别事实性声明
- [ ] 第 2 步：搜索权威来源
- [ ] 第 3 步：将声明与来源进行比对
- [ ] 第 4 步：生成修正报告
- [ ] 第 5 步：经用户批准后应用修正
```

### 第 1 步：识别事实性声明

扫描文档以查找可验证的陈述：

**目标声明类型：**
- 技术规格（上下文窗口、定价、功能）
- 版本号和发布日期
- 统计数据和指标
- API 功能和限制
- 基准分数和性能数据

**跳过主观内容：**
- 意见和建议
- 解释性文字
- 教程说明
- 架构讨论

### 第 2 步：搜索权威来源

针对每个声明，搜索官方来源：

**AI 模型：**
- 官方公告页面（anthropic.com/news, openai.com/index, blog.google）
- API 文档（platform.claude.com/docs, platform.openai.com/docs）
- 开发者指南和发布说明

**技术库：**
- 官方文档网站
- GitHub 仓库（releases, README）
- 包注册中心（npm, PyPI, crates.io）

**一般声明：**
- 学术论文和研究
- 政府统计数据
- 行业标准组织

**搜索策略：**
- 使用模型名称 + 规格（例如，"Claude Opus 4.5 上下文窗口"）
- 包含当前年份以获取最新信息
- 尽可能从多个来源验证

### 第 3 步：将声明与来源进行比对

创建比对表格：

| 文档中的声明 | 来源信息 | 状态 | 权威来源 |
|--------------|----------|------|----------|
| Claude 3.5 Sonnet: 200K tokens | Claude Sonnet 4.5: 200K tokens | ❌ 过时模型名称 | platform.claude.com/docs |
| GPT-4o: 128K tokens | GPT-5.2: 400K tokens | ❌ 不正确的版本和规格 | openai.com/index/gpt-5-2 |

**状态代码：**
- ✅ 准确 - 声明与来源一致
- ❌ 不正确 - 声明与来源矛盾
- ⚠️ 过时 - 声明曾经正确但已被取代
- ❓ 无法验证 - 未找到权威来源

### 第 4 步：生成修正报告

以结构化格式呈现结果：

```markdown
## 事实核查报告

### 摘要
- 核查声明总数：X
- 准确：Y
- 发现问题：Z

### 需要修正的问题

#### 问题 1：过时的 AI 模型引用
**位置：** docs/file.md 第 77-80 行
**当前声明：** "Claude 3.5 Sonnet: 200K tokens"
**修正：** "Claude Sonnet 4.5: 200K tokens"
**来源：** https://platform.claude.com/docs/en/build-with-claude/context-windows
**理由：** Claude 3.5 Sonnet 已被 Claude Sonnet 4.5 取代（2025 年 9 月发布）

#### 问题 2：不正确的上下文窗口
**位置：** docs/file.md 第 79 行
**当前声明：** "GPT-4o: 128K tokens"
**修正：** "GPT-5.2: 400K tokens"
**来源：** https://openai.com/index/introducing-gpt-5-2/
**理由：** 128K 是输出限制；上下文窗口为 400K。模型也已更新为 GPT-5.2
```

### 第 5 步：经用户批准后应用修正

**在做出更改前：**

1. 向用户展示修正报告
2. 等待明确批准： "我应该应用这些修正吗？"
3. 只有在确认后才能继续

**应用修正时：**

```python
# 使用编辑工具更新文档
# 示例：
Edit(
    file_path="docs/03-写作规范/AI辅助写书方法论.md",
    old_string="- Claude 3.5 Sonnet: 200K tokens（约 15 万汉字）",
    new_string="- Claude Sonnet 4.5: 200K tokens（约 15 万汉字）"
)
```

**修正后：**

1. 验证所有编辑是否成功应用
2. 记录修正摘要（例如，"更新了 2.1 部分的 4 个声明"）
3. 提醒用户提交更改

## 搜索最佳实践

### 查询构建

**良好查询**（具体、当前）：
- "Claude Opus 4.5 上下文窗口 2026"
- "GPT-5.2 官方发布公告"
- "Gemini 3 Pro token 限制规格"

**不良查询**（模糊、通用）：
- "Claude 上下文"
- "AI 模型"
- "最新版本"

### 来源评估

**优先选择官方来源：**
1. 产品官方页面（最高权威）
2. API 文档
3. 官方博客公告
4. GitHub 发布（针对开源项目）

**谨慎使用：**
- 第三方聚合器（llm-stats.com 等） - 需与官方来源比对
- 博客文章和文章 - 交叉验证声明
- 社交媒体 - 仅用于公告，其他地方需验证

**避免：**
- 过时文档
- 无引用的非官方维基
- 推测和谣言

### 处理歧义

当来源冲突时：

1. 优先选择最新的官方文档
2. 在报告中注明差异
3. 向用户展示两个来源
4. 如有必要，建议联系供应商

当未找到来源时：

1. 标记为 ❓ 无法验证
2. 建议使用替代措辞： "根据 [来源] 截至 [日期]..."
3. 建议添加限定词： "大约"，"据报道"

## 特殊注意事项

### 时间敏感信息

始终包含时间背景：

**良好修正：**
- "截至 2026 年 1 月"（As of January 2026）
- "Claude Sonnet 4.5 (released September 2025)"

**不良修正：**
- "最新版本"（会过时）
- "当前模型"（时间模糊）

### 数值精度

与来源保持一致精度：

**来源说明：** "大约 1 百万 tokens"
**写法：** "1M tokens (大约)"

**来源说明：** "200,000 token 上下文窗口"
**写法：** "200K tokens"（精确）

### 引用格式

在修正中包含引用：

```markdown
> **注**：具体上下文窗口以模型官方文档为准，本书写作时使用 Claude Sonnet 4.5 为主要工具。
```

尽可能链接到来源。

## 示例

### 示例 1：技术规格更新

**用户请求：** "核查 2.1 部分中的 AI 模型上下文窗口"

**流程：**
1. 识别声明：Claude 3.5 Sonnet (200K), GPT-4o (128K), Gemini 1.5 Pro (2M)
2. 搜索官方文档以获取当前模型

5. 经批准后应用修正

**用户请求：** "验证第 5 章中的基准分数"

**流程：**
1. 提取数值声明
2. 搜索官方基准出版物
3. 比对报告值与来源值
4. 标注任何与来源矛盾的数值并附链接

**用户请求：** "检查这些库版本是否仍然当前"

**流程：**
1. 列出所有提到的版本号
2. 检查包注册中心（npm, PyPI 等）
3. 识别过时版本
4. 提供更新建议并附变更日志参考
5. 经用户确认后更新

## 质量清单

完成事实核查前：

- [ ] 所有事实性声明已识别和分类
- [ ] 每个声明已与官方来源验证
- [ ] 来源具有权威性和时效性
- [ ] 修正报告清晰且可操作
- [ ] 包含相关时间背景
- [ ] 获得用户批准后再进行更改
- [ ] 验证所有编辑是否成功
- [ ] 向用户提供摘要

## 限制

**此功能无法：**
- 验证主观意见或判断
- 访问付费或受限来源
- 判断争议性声明中的"真相"
- 预测未来规格或功能

**对于此类情况：**
- 在报告中注明限制
- 建议使用限定措辞
- 建议用户研究或咨询专家
