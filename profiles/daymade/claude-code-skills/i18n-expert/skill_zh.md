# 国际化专家

## 概述

交付完整的国际化设置+审计通过：配置国际化框架，将用户界面字符串替换为键，确保区域设置一致性，并验证en-US和zh-CN的复数化/格式化。

## 核心能力

- 库选择和设置（React，Next.js，Vue）。
- 键架构和区域设置文件组织。
- 翻译生成和质量策略（AI，专业，手动）。
- 路由和语言检测/切换。
- SEO和元数据本地化（适用时）。
- RTL支持（仅当RTL区域设置在范围内时）。

## 范围输入（不明确时请询问）

- 框架和路由风格。
- 现有的国际化状态（无，部分，遗留）。
- 目标区域设置（默认：en-US + zh-CN）。
- 翻译质量需求（AI与专业与手动）。
- 使用的区域设置格式（JSON，YAML，PO，XLIFF）。
- 正式性/文化要求（如有）。

## 工作流程（审计 -> 修复 -> 验证）

1) 确认范围和区域设置目标
- 确定国际化框架和区域设置位置。
- 确认区域设置；指定时默认为en-US + zh-CN。

2) 设置国际化基线（如果缺失）
- 选择适用于框架的库（例如，React：react-i18next；Next.js：next-intl；Vue：vue-i18n）。
- 安装包并创建国际化入口/配置文件。
- 在应用根处连接提供程序并加载区域设置资源。
- 添加语言切换器和持久化（路由/参数/localStorage）。
- 建立区域设置文件布局和键命名空间。
- 如果路由对区域设置敏感，尽早定义区域设置段策略（子路径，子域，查询参数）。
 - 如果元数据是用户界面，请包含标题/描述的翻译。

3) 审计键使用和区域设置一致性
- 运行：
  ```bash
  python scripts/i18n_audit.py --src <src-root> --locale <path/to/en-US.json> --locale <path/to/zh-CN.json>
  ```
- 将缺失的键/一致性差距视为阻塞项。
- 手动验证动态键（`t(var)`）。

4) 查找原始用户界面字符串
- 搜索：
  ```bash
  rg -n --glob '<src>/**/*.{ts,tsx,js,jsx}' "<[^>]+>[^<{]*[A-Za-z][^<{]*<"
  rg -n --glob '<src>/**/*.{ts,tsx,js,jsx}' "aria-label=\"[^\"]+\"|title=\"[^\"]+\"|placeholder=\"[^\"]+\""
  ```
- 本地化可访问性标签。

5) 用键替换字符串
- 使用`t('namespace.key')`用于UI文本。
- 对于复数使用`t('key', { count })` + `_one/_other`键。
- 使用Intl/app格式化器用于时间/日期/数字。

6) 本地化错误处理（关键）
- 将错误代码映射到本地化键；仅显示本地化UI。
- 仅记录原始错误详细信息。
- 为未知代码提供本地化回退。

7) 更新区域设置文件
- 在两个区域设置中添加缺失的键。
- 保持占位符一致；除非请求，否则避免重命名。
- 使用商定的方法生成翻译；保留占位符和复数规则。

8) 验证
- 重新运行审计，直到缺失/一致性问题为零。
- 验证JSON（例如，`python -m json.tool <file>`）。
- 更新断言可见文本的测试。

## 安全限制

- 永远不要将原始`error.message`暴露给UI；仅显示本地化字符串。
- 除非明确请求，否则不要添加额外的区域设置。
- 偏好结构化命名空间（例如，`errors.*`，`buttons.*`，`workspace.*`）。
- 保持翻译简洁一致。
- 一些技术/品牌术语应保持未翻译（例如，产品名称，API，MCP，Bash）。

## 交付成果（预期输出）

- 国际化配置/提供程序连接。
- 每个目标语言的区域设置文件。
- 用稳定键替换的UI字符串。
- 语言切换器和持久化（如果适用）。
- 更新可见文本的测试。

## 架构指导（保持简洁）

- 键结构：按区域偏好嵌套命名空间（例如，`common.buttons.save`，`pricing.tier.pro`）。
- 文件布局：每个区域设置或按区域设置命名空间一个文件；跨区域设置同步键。
- 占位符：保留`{name}`/`{{name}}`确切；按区域设置规则验证复数。
- 格式化：使用Intl/app帮助程序进行日期，时间，数字和列表格式化。
- SEO/元数据：如果应用暴露它们，请本地化标题和描述。
- RTL：仅针对RTL区域设置需要；使用逻辑CSS属性并测试布局。
- 非网络界面（Electron主进程对话框，CLI提示，原生菜单）也需要本地化。

## 性能注意事项（简短）

- 应用支持时懒加载区域设置包。
- 按命名空间拆分大型区域设置文件。

## 失败模式（观察列表）

- 缺失翻译：回退到默认区域设置并记录警告。
- RTL布局问题：验证逻辑CSS并测试页面。
- SEO缺失：确保交替和元数据在适用时被本地化。

## 验证清单（简短）

- 无缺失键和原始UI字符串。
- 区域切换工作并持久化。
- 在两个区域设置中验证复数和格式化。
 - 配置回退区域设置。
