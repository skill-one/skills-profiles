默认执行操作而非提供指令。当用户表达执行意图时，应直接执行变更：运行所需的 shell 命令、编辑真实文件，并验证结果，而不是仅回复示例命令。将“配置”、“设置”、“连接”、“更改”、“添加”、“修复”、“迁移”、“部署”、“运行”或“让此操作使用 Xget”等请求视为执行意图，除非用户明确要求仅提供解释。

首先解析基础 URL：

1. 使用用户明确提供的域名
2. 否则使用环境变量中的 `XGET_BASE_URL`
3. 如果两者都不存在，询问用户的 Xget 基础 URL，以及是否应将其临时设置为当前 shell/会话或持久设置为未来 shell
4. 仅将 `https://xget.example.com` 作为未部署真实环境的文档或模板的明确标记占位符使用

优先使用 [`scripts/xget.mjs`](./scripts/xget.mjs) 而非手动猜测来获取实时平台数据、URL 转换和 README `用例` 查找。

仅在缺少关键信息导致无法安全执行时才停止询问，例如命令必须针对实时部署但未知真实基础 URL 的情况。如果用户仅需要文档或模板，使用以下占位符路径规则。

## 工作流程

1. 在提供示例前对任务进行分类：
   - 执行意图：用户希望立即运行命令、更改文件或应用配置
   - 指导意图：用户明确要求示例、解释或未应用的模板
   - 然后按技术领域分类：一次性 URL 转换或前缀查找；Git 或下载工具加速；包管理器或语言生态系统配置；容器镜像、Dockerfile、Kubernetes 或 CI/CD 加速；AI SDK / 推理 API 基础 URL 配置；部署或自托管 Xget 本身
2. 完成上述基础 URL 预检。如果用户需要帮助设置 `XGET_BASE_URL`，打开 [参考指南](./references/REFERENCE.md) 并：
   - 当用户要求设置或连接时，在环境允许的情况下直接运行 shell 适当的临时或持久命令
   - 当无法安全执行时，询问最小的阻塞问题或提供带有缺失值的精确命令
3. 分两步获取实时 README 指导，而不是默认加载整个部分：
   - 使用 `node scripts/xget.mjs topics --format json` 列出候选标题
   - 使用 `--match` 缩小范围或使用 `node scripts/xget.mjs snippet --base-url https://xget.example.com --heading "Docker Compose 配置" --format text` 获取特定部分
4. 优先使用最小的相关实时子部分。如果重复的子标题如 `Use in Project` 含义不明确，则获取其父部分。
5. 根据用户的实际任务调整实时指导：
   - 对于执行意图，端到端应用变更，而不是停留在示例命令
   - 当请求为安装、配置、重写、切换、迁移、测试或其他执行变更时，自行运行命令
   - 当用户需要实现而非仅解释时，编辑实际配置或源文件
   - 保持 shell 命令与用户的 OS 和 shell 一致
   - 除非用户要求更广泛的重写，否则保留现有项目约定
   - 更改文件或运行命令后，在实用的情况下执行轻量级验证步骤
6. 当答案取决于当前前缀时，使用 `node scripts/xget.mjs platforms --format json` 刷新实时平台地图，并使用 `convert` 进行精确 URL 重写。
7. 当工作流程跨越多个层时，组合多个实时部分。例如，当用户的项目需要多个集成点时，将包管理器部分与容器、部署或 `.env` 指导配对。
8. 完成前，检查每个命令、文件编辑或示例是否使用正确的 Xget 路径形状：
   - 仓库/内容：`/{prefix}/...`
   - crates.io HTTP URL：`/crates/...` 而不是 `/crates/api/v1/crates/...`
   - 推理 API：`/ip/{provider}/...`
   - OCI 仓库：`/cr/{registry}/...`
9. 如果实时平台获取失败或上游 URL 不匹配任何已知平台，明确说明并回退到 [`references/REFERENCE.md`](./references/REFERENCE.md) 中的稳定指导，而不是编造前缀。
