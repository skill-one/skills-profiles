## 概述

使用此技能在云服务器上为 OpenClaw 应用保守的“先部署，后暴露”模式。

默认使用私有控制平面：

- 在暴露任何内容之前加固 Linux 主机。
- 将网关绑定到 `127.0.0.1`。
- 首先通过 SSH 隧道访问控制 UI。
- 保持令牌认证、配对和沙箱功能启用。
- 从狭窄的工具配置文件开始，只有在明确需要时才放宽限制。

此技能适用于安全的 Linux 云托管。如果用户只想在本地计算机上安装最快的通用 OpenClaw，应优先选择官方 OpenClaw 入门文档，而不是强制执行此流程。

需要命令矩阵、基准配置形状、检查清单或访问路径比较时，请打开 [`references/REFERENCE.md`](./references/REFERENCE.md)。

## 何时使用

当用户提到以下任何内容时，使用此技能：

- 云服务器、虚拟机或其他 Linux 主机上的 OpenClaw
- 安全自托管、加固或“私域运行”
- Podman、回环绑定、SSH 隧道或远程控制 UI 访问
- Tailscale 与反向代理的 OpenClaw 对比
- 配对、沙箱、令牌认证或锁定工具权限
- 审查现有 OpenClaw 主机是否过于暴露

不要使用此技能的情况：

- 没有 OpenClaw 组件的一般 Linux 加固
- 无需远程访问的本地单机入门
- 没有远程主机加固问题的纯本地入门
- 非 Linux 托管，除非用户明确希望采用此 Linux 优先模式

## 工作流程

### 1. 分类请求

在提供详细指导之前，将任务归入以下类别之一：

1. **全新部署**：用户希望从零开始在 Linux 云主机上安全地部署 OpenClaw。
2. **加固审查**：用户已经运行 OpenClaw 并希望减少暴露或审计高风险默认设置。
3. **访问模型决策**：用户正在选择 SSH 隧道、Tailscale 或反向代理。

### 2. 从安全基线开始

除非用户明确要求其他内容，否则建议此基线：

- 首先加固 Linux 主机：更新、SSH 密钥、SSH 锁定和与发行版匹配的默认拒绝入站防火墙。
- 以无根权限的 Podman 运行 OpenClaw，而不是作为根拥有的长期进程。
- 将网关仅保持在回环上。
- 将控制 UI 保持私密，并通过 SSH 隧道访问。
- 要求令牌认证。
- 保持配对功能以供入站消息通道使用。
- 从最小工具集开始，默认沙箱会话。

将以下内容视为明确的危险信号：

- 将网关绑定到 `0.0.0.0`
- 向公共互联网开放端口 `18789`
- 默认启用广泛的运行时、文件系统、自动化或浏览器访问
- 将 `~/.openclaw` 对其他本地用户可读

### 3. 分离本地和服务器操作

始终区分：

- **本地计算机操作**：SSH 密钥生成、隧道设置、浏览器访问
- **服务器操作**：Linux 加固、Podman 安装路径、OpenClaw 服务设置、配置权限、服务重启

不要将两个执行上下文混淆在一起。用户应该能够区分在他们的笔记本电脑上运行的命令和在 Linux 主机上运行的命令。

### 4. 仅询问阻塞事实

仅停止以缺失会改变安全路径的事实，例如：

- Linux 发行版和主机访问详细信息，当包管理器或防火墙命令相关时
- OpenClaw 是否已安装
- 用户是否真正需要重复的远程私有访问或公共访问
- 现有部署是否已经可以从互联网访问

如果某个细节不关键，请做出合理的假设并说明。

### 5. 使用访问升级阶梯

按以下顺序推荐远程访问：

1. **SSH 隧道**：首次部署和个人使用的默认选项
2. **Tailscale**：当用户需要在受信任设备之间进行重复私有访问时的下一步
3. **反向代理**：只有在用户明确需要公共暴露并接受额外加固负担时

如果用户要求 Tailscale 或反向代理，仍然解释为什么回环绑定和私有优先模式仍然是基线。

## 常见错误

- 将 OpenClaw 像普通公共 Web 应用一样在第一天使用
- 假设认证可以单独替代网络边界
- 在用户没有明确的流程需要它之前打开更多工具权限
- 为了节省早期设置时间而禁用配对
- 在更改配置或沙箱设置后跳过后续审计
