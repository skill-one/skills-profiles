## 概述

使用此技能将云服务器转换为安全可访问的网站主机，而无需依赖过时的特定发行版内存或 Debian-10 时代的教程。

此技能保留了初学者友好型服务器指南的熟悉教学曲线，但将其转换为可重用的操作员工作流程：

1. 采集和路由
2. 前置条件
3. 安全访问
4. 防火墙和暴露
5. 网站服务器设置
6. 静态站点或应用代理
7. HTTPS
8. 验证
9. 可选的高级调优

在给出可操作的命令之前，识别发行版系列并对照用户所选发行版和工具的官方文档，验证当前软件包名称、服务单元、配置路径和 ACME 客户端指南。

首先打开 [`references/workflow-map.md`](./references/workflow-map.md) 了解阶段顺序，然后打开您需要的更具体的参考文件。

## 何时使用

当用户提到以下任何内容时，使用此技能：

- 他们想要用于托管的云服务器、虚拟机、droplet 或其他 Linux 主机
- 将域名或 DNS A/AAAA 记录连接到服务器
- SSH 登录、SSH 硬化、root 登录、密钥、端口或防火墙设置
- 为网站安装或配置 Nginx
- 从 Linux 服务器提供简单的静态站点
- 将小型应用作为反向代理放在 Nginx 后面
- HTTPS、Let's Encrypt、Certbot、`acme.sh`、证书续订或将 HTTP 重定向到 HTTPS
- 可选的设置后性能或网络调优，例如 BBR

不要使用此技能用于：

- Kubernetes、PaaS 或需要更广泛的 SRE 或平台设计处理的公共多租户生产架构审查
- 应用特定构建或 CI/CD 问题，其中 Linux 托管不是实际问题
- Windows 或 macOS 主机管理

## 工作流程

### 1. 采集和分类当前状态

首先识别：

- 发行版系列或镜像名称
- 用户是否有 root 访问权限、管理员用户，还是只有一个活动的 SSH 会话
- DNS 是否已经指向主机
- 目标是静态站点还是应用反向代理
- 端口是否已经暴露
- HTTPS 是否已经部分配置

如果发行版未知，请要求用户提供或让用户检查 `/etc/os-release`，然后再给出具体的软件包或服务命令。

### 2. 在给出可操作命令前验证当前文档

使用捆绑的参考进行路由，然后在给出依赖于当前发行版行为的命令之前，对照实时官方文档验证详细信息。

始终验证：

- 软件包管理器命令和软件包名称
- 防火墙工具和服务名称
- SSH 服务单元名称和配置包含路径
- Nginx 软件包和配置布局
- 所选 ACME 客户端的当前说明

如果您无法验证某个详细信息，请说明并给出高级指导，而不是假装旧的 Debian 教程路径是通用的。

### 3. 保持阶段顺序

除非用户明确要求审查或修复现有设置，否则按此顺序逐步进行：

1. 前置条件
2. 安全访问
3. 防火墙和暴露
4. 网站服务器
5. 选择一个托管分支：静态站点或应用代理
6. HTTPS
7. 验证
8. 可选的高级调优

不要将静态站点分支和反向代理分支合并为一个默认答案。选择与用户目标匹配的分支。

### 4. 执行安全门禁

将这些视为硬停止检查：

- 在第二个 SSH 会话中基于密钥的登录工作之前，不要建议更改 SSH 端口、禁用密码认证或禁用 root SSH 登录。
- 在 DNS 解析到预期主机并且 HTTP 站点或代理路径按预期工作之前，不要建议颁发证书。
- 在 HTTPS 清晰加载之前，不要强制执行 HTTP 到 HTTPS 的重定向。
- 在安全托管已经工作之前，不要建议 BBR 或类似的调优。

始终区分：

- 本地机操作：SSH、DNS 检查、浏览器测试
- 服务器操作：软件包安装、配置编辑、服务重新加载、防火墙规则

## 输出预期

对于全新设置，提供：

- 当前状态的简要诊断
- 当前阶段及其原因
- 本地机步骤与服务器步骤分开
- 仅在文档验证后提供具体命令或配置片段
- 在每次有风险更改后进行验证步骤
- 短暂的“如果失败，检查 X”分支，用于该阶段可能的错误

对于硬化或故障排除审查，提供：

- 最可能的风险或中断
- 优先级修复顺序
- 在下一个配置更改之前的第一步安全验证步骤

## 常见错误

- 将旧文章中 Debian 特定的命令视为 Linux 通用
- 在唯一活动的会话中硬化 SSH 并将用户锁定在外
- 直接打开应用端口而不是将应用放在回环接口
- 在一个配置中混合静态文件托管指导与反向代理指导
- 在 DNS 或 HTTP 实际正确之前尝试 ACME 发行
- 在 HTTPS 证明之前强制重定向
- 将 BBR 视为核心设置的一部分，而不是可选的后期步骤
- 忽略 SELinux 或 AppArmor 差异，当 Nginx 在一个发行版上可以读取文件但在另一个发行版上不能时
