在不破坏仓库机制的前提下，本地化一个仓库的 `README.md`。

默认任务为翻译 + 配置：

- 读取源 README
- 创建本地化兄弟文件，例如 `README.zh.md`
- 保留 GitHub 风格的 Markdown 结构和仓库特定标记
- 在每个变体的顶部附近添加或更新共享语言选择器

这项技能适用于多语言 README 工作流，而不是通用的网站/应用国际化。

## 输入

当可用时，期望以下输入：

- 源 README 路径，默认为 `README.md`
- 源语言，默认推断或英语
- 一个或多个目标语言
- 可选的术语表或不可翻译列表
- 如果仓库已经使用不同的多语言命名模式，则可选的文件名覆盖

如果目标语言未命名，则检查现有的翻译文件、选择器、文件名、问题或先前的仓库约定。如果仍然无法确定目标语言，则询问一次。不要凭空创造目标语言。

## 默认值和决策规则

- 除非用户明确说明，否则将根 `README.md` 视为源
- 如果源语言不明确，则询问一次。否则假设为英语。
- 保持与源 README 相同的章节顺序。仅在需要生成有效的本地化锚点时，才对小标题措辞进行微调。
- 输出本地化兄弟文件，使用 `README.<bcp47-tag>.md` 命名，除非仓库已经有一个不同的既定模式需要保留。
- 就地更新现有的语言选择器。不要重复它。
- 仅翻译人类语言内容。
- 保留项目名称、包名称、命令、CLI 标志、选项名称、环境变量、URL、文件路径、内联代码、代码分隔符、HTML 属性和徽章/图像 URL。
- 只有在更改不需要更改徽章 URL、查询参数或图像源的情况下，才可翻译徽章的 alt 文本或可见标签。
- 如果提供了术语表或不可翻译列表，则应在每个目标语言中一致地应用它。

## 工作流

### 1. 确定源 README 和语言

- 确认源 README 路径。默认为 `README.md`。
- 从文件内容和仓库上下文中识别源语言。
- 从请求或现有的仓库模式中确定目标语言。
- 记录任何必须保持未翻译的术语表术语、产品名称或短语。

### 2. 在翻译前审计 Markdown 结构

将源 README 一次作为结构读取，而不是文本。打开 [`references/preservation-checklist.md`](./references/preservation-checklist.md) 并列出最可能破坏的元素：

- 标题和标题级别
- 徽章行、shields URL 和图像链接
- 表格和对齐行
- 原始 HTML 块和内联 HTML
- GitHub 提醒或告诫，例如 `> [!NOTE]`
- 代码分隔符、内联代码、命令和配置片段
- 文档内锚点，例如 `(#installation)`
- 相对链接到文件、文档、截图或其他 README 变体

如果 README 已经有本地化兄弟文件，则在选择文件名或选择器样式之前检查它们。

### 3. 仅翻译文本层

翻译：

- 段落文本
- 列表项文本
- 表格单元文本
- HTML 块内的可见文本
- 当安全时，图像 alt 文本
- 选择器标签和其他面向用户的标签

不要翻译：

- 分隔代码块
- 内联代码段
- Shell 命令
- 标志，例如 `--help`
- 环境变量，例如 `OPENAI_API_KEY`
- URL
- 文件路径
- 仓库/包/项目标识符
- 徽章和图像 URL

如有疑问，保留字面量标记，并翻译周围的句子。

### 4. 在编写本地化 README 时保留结构

- 保持与源相同的标题层次结构和章节顺序。
- 除非用户明确要求重写示例，否则保持相同的代码分隔符数量。
- 保留表格形状、列表嵌套、HTML 包装器和 Markdown 评论。
- 除非链接有意需要指向本地化兄弟 README，否则保留相对链接。

### 5. 重写本地化锚点和依赖锚点的链接

当翻译的标题更改时，GitHub 将生成不同的标题 ID。翻译标题后：

- 重新编写所有同文件 `(#...)` 链接，使其与该文件中的本地化标题缩写匹配
- 除非文件已经使用本地化显式 ID，否则保留自定义显式锚点，例如 `<a id="...">`
- 验证每个文档内锚点目标是否解析到现有的标题或显式锚点

优先进行小标题措辞调整，而不是破坏锚点。章节顺序应与源 README 匹配。

### 6. 使用仓库的命名模式编写兄弟文件

默认使用以下兄弟文件名：

- `README.zh.md`
- `README.es.md`
- `README.fr.md`

如果仓库已经使用不同的多语言命名模式，则保持一致使用该模式，而不是强制使用默认模式。

### 7. 插入或更新语言选择器

编辑选择器之前，打开 [`references/language-selector-reference.md`](./references/language-selector-reference.md)。

位置：

- 将选择器保持在文件顶部附近
- 如果 README 以标题、徽章、英雄图像或简短介绍块开头，则将选择器放置在该开头发集群之后

行为：

- 如果已存在选择器块，则就地更新它
- 如果添加新的选择器，请使用参考文件中的规范标记注释，以便后续运行可以确定性地更新它
- 突出当前语言并链接其他变体
- 在每个 README 变体中保持选择器顺序和标签一致

### 8. 最终验证

完成前，验证：

- 本地化文件名遵循所选模式
- 每个 README 变体包含且仅包含一个选择器块
- 代码分隔符数量保持不变
- 徽章/图像 URL 和相对文件链接仍然指向原始目标，除非有意本地化
- 每个 `(#...)` 链接在其自己的文件内解析
- 本地化 README 仍然在结构上与源相同

## 输出

生成：

- 每个目标语言一个本地化兄弟 README
- 每个README变体中更新的选择器块
- 简要说明给用户，涵盖创建或更新的文件、任何假设以及任何有意保留未翻译的术语

## 维护说明

除非用户说明，否则将 `README.md` 作为规范源。当源 README 更改时，通过比较更改的文本，然后重新检查选择器、文件名和锚点链接，而不是从头开始重新格式化整个文件，来更新每个本地化兄弟文件。

## 示例提示

**示例 1**

`将此 README 翻译成中文并添加语言切换器。保留徽章 URL、代码分隔符和所有命令。`

**示例 2**

`使仓库多语言化。添加西班牙语和中文 README 变体，保持内部锚点链接正常工作，并将选择器配置到每个文件。`

**示例 3**

`我们已经有 README.zh.md。添加 README.es.md 并就地更新现有的选择器，而不是添加第二个。`

## 常见错误

- 翻译分隔代码块或内联代码，而不是仅翻译周围的文本
- 重复语言选择器，而不是更新现有的块
- 翻译标题但忘记重写同文件 `(#...)` 链接
- 在尝试翻译可见标签时更改徽章 URL 或图像源
- 即使源 README 是权威，也要重新排序本地化 README 中的章节
