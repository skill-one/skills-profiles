# 本能系统

一个学习系统，三个层级。Claude 在工作时接收到的每一个信号——一个观察到的模式、一个用户纠正、一个令人惊讶的发现——都会被路由到其中一个存储库。

## 核心原则

1. **三个层级，一个路由决策** — *本能* 是未经证实的假设（`.claude/instincts.md`）。*纠正* 是用户确认的规则（`MEMORY.md`）。*发现* 是解释世界的洞察（`.claude/learning-log.md`）。规则规定行为；洞察描述行为；本能是待定的规则。永远不要混淆层级——MEMORY.md 中的假设会污染永久知识，而作为本能保留的确认规则会被遗忘。

2. **本能是假设，不是规则** — 本能始于单一观察的猜测，在确认之前没有权威性。"一个处理器使用 `sealed`" 是一个 0.3 的本能；"所有 12 个处理器使用 `sealed`" 是一个 0.9 的规则。置信度（0.3–0.9）驱动行为：0.3 时记录，0.5 时提及，0.7 时遵循，0.9 时推广。

3. **用户纠正是一个置信度为满值的确认本能** — 当用户纠正你时，完全跳过确认周期。泛化教训，立即在 MEMORY.md 中捕获它并附上原因，然后确认捕获的内容。纠正今天耗费用户 30 秒，但能节省未来所有会话中的数小时——失去一个纠正是最昂贵的错误。

4. **项目范围，永不全局** — 在一个代码库中成立的东西，在另一个代码库中可能错误。本能按项目存在；项目之间的转移通过导出/导入进行，伴随置信度衰减，永不以满值置信度转移。

5. **会话开始时审查，定期修剪** — 在编写任何代码之前，阅读 MEMORY.md 并加载置信度 0.7+ 的本能；扫描近期日志条目以获取工作区域。未审查的知识是浪费的努力。当存储库膨胀时，审查所有三个存储库——过时的本能、重复的规则和未审查的日志会失去意义。

## 模式

### 层级路由

| 信号 | 目的地 | 寿命 |
|------|--------|------|
| 观察到的模式，尚未确认（"我认为它们总是...") | `.claude/instincts.md` 置信度 0.3 | 直到推广或丢弃 |
| 用户纠正（"不，使用 X"，"不要再那样做"，"记住这个"） | `MEMORY.md` 立即，泛化 | 直到被证明错误 |
| 本能达到 0.9 置信度 | 推广到 `MEMORY.md`，从本能中移除 | 永久 |
| 非明显的发现（错误根本原因、陷阱、解决方案、性能发现） | `.claude/learning-log.md` | 3–6 个月，然后存档或推广 |
| 相同的陷阱记录 3 次以上 | 推广到 `MEMORY.md` 作为预防性规则 | 永久 |
| 会话状态（完成/待处理） | 通过总结交接——不是这个系统 | 直到下一个会话 |

### 本能生命周期（观察-假设-确认）

```
1. 观察到——"这个处理器是内部 `sealed` 类。惯例？"
2. 假设——写入 `.claude/instincts.md` 置信度 0.3：
             - 在处理器类上使用 `sealed` | 置信度：0.3 | 看到：1 | 最后：2026-06-12
3. 寻找——主动检查 2-3 个相关文件（find_symbol，get_public_api）。
             被动观察是不够的。
4. 调整——确认：根据调整跟踪提高。
             相矛盾：置信度减半，记录例外。
             混合：保持稳定，记录分歧。
5. 推广——达到 0.9 时，提供证据并提议推广到 MEMORY.md。
```

### 本能存储格式

`.claude/instincts.md`，按类别分组，具有结构化元数据：

```markdown
# 项目本能

## 代码风格 [0.7]
- 在所有处理器类上使用 `sealed` | 置信度：0.8 | 看到：5 | 最后：2026-06-12
- 私有字段以下划线前缀 | 置信度：0.5 | 看到：2 | 最后：2026-06-10

## 架构 [0.7]
- 功能文件夹使用单数名称 | 置信度：0.7 | 看到：4 | 最后：2026-06-12
```

类别标题 `[0.7]` = 平均置信度。标准类别：代码风格、架构、命名、测试、数据访问、API 设计、配置、性能、工具。

### 置信度调整规则

没有临时评分。精确遵循此路径：

```
确认：  第一个观察→0.3 | 第二个→0.5 | 第三个→0.7 | 第四个→0.8
        第五个+无矛盾→0.9（推广候选）

矛盾：  任何矛盾→当前置信度减半（0.7→0.35）
        连续两个矛盾→0.1（实际上已死亡）

用户覆盖： 明确确认→0.8 | 明确纠正→0.0（移除，
             在 MEMORY.md 中捕获） | "有时"→上限 0.5

陈旧：  10+ 会话无观察→标记审查
        矛盾、未确认 5 会话→移除
```

### 根据置信度执行本能

```
0.0–0.2 → 忽略  — 证据不足，不要提及
0.3–0.4 → 记录  — 内部记录，不应用
0.5–0.6 → 提及  — "这个项目可能使用 [模式]。遵循吗？"
0.7–0.8 → 遵循  — 默认应用，首次使用时提及
0.9     → 推广  — 提议添加到 MEMORY.md 作为永久规则
```

永远不要无声地应用置信度低于 0.7 的本能。

### 纠正捕获流程（层级 2）

当用户纠正你的输出（"不，用 X 代替"，"我们不那样做"，"总是/从不做 X"，"记住这个"）：

```
1. 检测  — 识别纠正信号。
2. 确认  — "明白了——HybridCache 而不是 IMemoryCache。"
3. 泛化  — 具体化："在 Orders 端点不要使用 IMemoryCache"
             泛化："始终使用 HybridCache 而不是 IMemoryCache ——
                    防止 stampede + L1/L2 开箱即用。"
             询问：这是否仅限于这个文件？这个层？底层原理是什么？存储最广泛的正确陈述。
4. 检查  — 扫描 MEMORY.md 查找重叠。更新现有规则而不是添加几乎重复的规则。
5. 存储  — 在正确类别下写入，一行，理由在短横线后。如果存在匹配的本能，则移除它——它刚刚毕业。
6. 确认  — "已添加到 Memory > 数据访问：HybridCache 而不是 IMemoryCache。"
```

MEMORY.md 格式——与本能相同的类别，每行一个可操作的规则：

```markdown
## 数据访问
- 始终使用 HybridCache 而不是 IMemoryCache — 防止 stampede + L1/L2
- 从不使用仓库模式超过 EF Core — 直接使用 DbContext
```

### 发现记录（层级 3）

立即将有机发现记录到 `.claude/learning-log.md`——立即写入的两行条目优于稍后重建的段落。条目格式：

```markdown
## 2026-06-12 | 陷阱 | MassTransit 消费者注册顺序重要
一个消息类型的多个消费者按注册顺序运行；如果第一个出错，其余的会被跳过。导致遗漏审计事件。
**文件：** `src/Shared/Extensions/MassTransitConfig.cs:15-30`
**解决方案：** 独立消费者端点或重试过滤器。
```

在（并且仅当）你遇到以下触发器时记录：

```
错误根本原因        — 原因不在错误出现的地方
架构决策            — 发现了为什么某物以某种方式构建
陷阱                — 框架/库行为出乎意料
性能发现            — 意外的性能行为，附带测量
模式发现            — 值得记住的可重用代码库模式
外部服务            — 第三方 API 的行为与文档不同
```

这六个触发器名称也是类别词汇——在条目中直接使用它们。没有令人惊讶的常规变化不会记录。

### 会话开始时加载

```
1. 阅读 MEMORY.md — 主动应用规则，不要等待提醒
2. 阅读 `.claude/instincts.md` — 加载置信度 0.7+ 作为默认值，记录 0.5–0.6
3. 扫描近期学习日志条目以获取你正在工作的区域
4. 标记陈旧本能（10+ 会话无观察）以供审查
```

## 模式

三个对本能存储库的操作，通过名称或触发短语调用。

### 状态（"显示本能"，"你学到了什么"，"列出本能"）

1. 读取 `.claude/instincts.md`；解析每个条目的元数据。
2. 按置信度降序排序，按类别分组，以表格形式呈现：
   本能 | 置信度 | 类别 | 状态（新 / 稳定 / 加强 / 衰减 / 推广候选）。
3. 总结健康状况：总数、平均置信度、最近加强与衰减的条目、任何冲突的本能。

### 导出（"导出本能"，"分享本能"）

1. 读取 `.claude/instincts.md`；过滤置信度 > 0.7（阈值可配置）。
2. 脱离项目特定上下文（文件路径、行号），同时保留模式本身。
3. 写入 `.claude/instincts-export.md` 并带有可移植元数据。
4. 报告导出内容和被跳过的内容（低于阈值），以及输出路径。

### 导入（"导入本能"，"从加载本能"）

1. 读取导出文件（用户提供的路径或 `.claude/instincts-export.md`）和当前的 `.claude/instincts.md`。
2. 合并每个导入的本能：
   - **无本地匹配** — 添加置信度衰减 0.2（0.9→0.7）；永不导入高于 0.7。标记 `来源：从 [项目] 导入`。
   - **存在匹配本能** — 保留较高置信度，标记加强。
   - **存在冲突本能** — 向用户展示两者以供解决；不要自动覆盖本地证据。
3. 写入合并结果并报告导入/合并/冲突。每个项目必须本地确认导入的模式。

## 反模式

### 过度积极的模式识别

```
# 坏——第一个观察被视为规则
*读取一个处理器* "这个项目总是使用内部 `sealed` 类。"
*生成 5 个处理器，与 9 个现有的一致性矛盾 8 个*

# 好——假设 0.3，然后主动确认
"注意到 `CreateOrderHandler` 中的内部 `sealed`。本能 0.3。
检查 3 个更多处理器..." *全部公开* → "已确认。丢弃。"
```

### 未捕获的修复

```
# 坏——修复并丢失教训
用户："不，这里使用 HybridCache"
Claude："修复。" *下一个会话：同样的错误*

# 好——修复并捕获
Claude："修复。添加到 Memory > 数据访问：
         始终使用 HybridCache 而不是 IMemoryCache。"
```

### 记录所有内容

```
# 坏——噪音条目
## 2026-06-12 | 模式发现 | 使用主要构造函数

# 好——只有非明显的才值得记录
## 2026-06-12 | 陷阱 | 主要构造函数参数捕获为字段
声明与相同名称的显式字段会警告但编译——两者可以无声地分化。
```

### 只写存储

```
# 坏——3 个月前 40 个置信度 0.3 的本能；MEMORY.md 200 行
  有重复；500 行日志无人阅读
# 好——定期审计：移除置信度低于 0.2 或陈旧 10+ 会话的本能；
  合并/修剪过去 50 个规则的 MEMORY.md；大约每 20 个日志条目，
  推广重复发现并存档陈旧。保持本能少于 50 个活跃条目。
```

## 决策指南

| 情景 | 操作 |
|------|------|
| 首次看到模式 | 本能 0.3，检查 2-3 个相关文件 |
| 模式看到 3+ 次，无矛盾 | 提高到 0.7，默认遵循 |
| 模式相矛盾 | 置信度减半，记录例外 |
| 用户说 "我们总是做 X" | 本能 0.8（用户确认） |
| 用户纠正你的代码 | 泛化→MEMORY.md 立即；丢弃任何匹配的本能 |
| 用户说 "记住这个" / "总是/从不" | 在 MEMORY.md 中按所述捕获，泛化 |
| 相同的纠正给出两次 | 高优先级——规则未被捕获或审查 |
| 关于一次性任务的纠正 | 不要存储——只有可重用模式 |
| 用户要求忘记一个规则 | 立即从 MEMORY.md 中移除 |
| 非明显的错误、陷阱、解决方案、性能意外 | 记录到学习日志，带类别+文件 |
| 相同的陷阱记录 3+ 次 | 推广到 MEMORY.md 作为预防性规则 |
| 置信度 0.9 的本能 | 提供证据，提议推广到 MEMORY.md |
| 用户部分确认（"仅用于命令"） | 缩小范围，重置为 0.5，重新确认 |
| 与另一个项目分享模式 | 置信度 0.7+ 导出，导入时置信度衰减 0.2 |
| 导入时冲突 | 向用户展示两者；永不自动覆盖 |
| 任何存储库膨胀（50+ 条目/规则） | 审计：修剪死亡，合并重复，推广成熟 |
| 开始会话 | 加载 MEMORY.md，置信度 0.7+ 的本能，近期日志条目 |
