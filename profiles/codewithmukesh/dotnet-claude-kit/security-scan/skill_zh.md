# /security-scan — 6层安全管道

## 什么是

执行跨6层的安全纵深静态扫描。一个没有CVE的项目仍然可能有硬编码的密钥、SQL注入和缺失的认证 — 每一层捕获不同的漏洞类别。发现的问题映射到**OWASP Top 10:2025**分类，并根据可利用性、影响和暴露程度被评为关键/高/中/低 — 公开端点上的关键SQL注入优先于管理页面上的低信息泄露。

检测模式、OWASP映射、修复代码和报告模板位于`references/scan-layers.md`中 — 在执行前阅读它。

**诚实规则：** 这是静态分析，不是渗透测试。它捕获已知模式，但会遗漏业务逻辑缺陷、复杂的授权绕过和仅运行时漏洞。每份报告都会声明这一点。

## 何时使用

- 发布前安全门禁 — 全扫描，生产前不可协商
- "安全扫描"、"安全审计"、"查找密钥"、"CVE检查"、"OWASP"
- 依赖更新后（第1层）、认证变更后（第4层）、配置变更后（第2层）或日志变更后（第6层）
- 渗透测试前准备 — 在支付渗透测试费用前修复静态问题
- 事件响应和季度审查

## 如何使用

### 第1步：选择层

| 场景 | 层 |
|------|----|
| 发布前门禁/渗透测试准备/事件/季度 | 所有6层 |
| 依赖更新后 | 1 |
| 新端点添加 | 3, 4, 5 |
| 认证系统变更 | 4 |
| 配置文件变更 | 2 |
| 日志变更 | 6 |
| 公开API暴露 | 3, 4, 5 |
| 仅内部服务 | 1, 2, 3 |

### 第2步：执行层

阅读`references/scan-layers.md`了解每层的检测模式。将深度认证和密钥审查委托给`security-auditor`代理，结合`authentication`和`configuration`技能。

| # | 层 | OWASP 2025 | 方法 |
|---|----|-----------|------|
| 1 | 包含漏洞 | A03 供应链 | `dotnet list package --vulnerable --include-transitive` |
| 2 | 密钥检测 | — | 在 .cs/.json/.yml/.xml/.config 上进行模式扫描 |
| 3 | OWASP代码模式 | A05 注入、A08 完整性、A04 加密、A01 访问控制 | 源码扫描：原始SQL、`Html.Raw`、`BinaryFormatter`、MD5/SHA1、IDOR |
| 4 | 认证配置 | A07 认证、A01 访问控制 | `get_endpoint_map` — 每个路由的认证状态在一个调用中；标记`unmarked`端点；然后JWT验证设置 |
| 5 | CORS策略 | A02 配置错误 | 通配符来源、凭证组合、方法/头范围 |
| 6 | 数据保护 | A04 加密、A09 日志与告警 | 日志中的PII、范围过广的响应、明文敏感存储 |

### 第3步：结合上下文评分

严重性必须与实际风险匹配 — 过度分类会导致告警疲劳并掩盖真正的关键问题：

- 测试用例中的"密钥"和`appsettings.Development.json`值是预期的 — 跳过或标记为INFO，不要标记为HIGH
- 缺失的XML注释永远不会是安全问题
- 保留关键用于可立即利用的问题：公开端点上的注入、暴露的生产密钥、认证绕过

### 第4步：报告

每个发现：`[严重性] 文件:行号 — 标题`，OWASP类别，问题是什么，如果被利用的影响，以及修复代码（前/后）。从参考模板生成摘要表+每层状态表，前缀静态分析免责声明。

## 示例

```
用户：/security-scan 在我们发布前

Claude：运行所有6层...

| 层 | 状态 | 发现 |
|----|------|------|
| 1. 包 | 通过 | 0 CVEs (142个包，包括传递的) |
| 2. 密钥 | 通过 | 0真实密钥 (2个仅开发值被跳过) |
| 3. OWASP模式 | 失败 | 1 SQL注入 |
| 4. 认证配置 | 警告 | 2个端点缺少显式认证属性 |
| 5. CORS | 通过 | 来自配置的显式来源 |
| 6. 数据保护 | 警告 | 客户电子邮件在信息级别记录 |

[HIGH] SearchOrders.cs:34 — SQL注入 (A05:2025)
  FromSqlRaw($"...LIKE '%{search}%'") → 攻击者控制查询。
  修复：db.Orders.Where(o => EF.Functions.Like(o.Name, $"%{search}%"))

[MEDIUM] OrderEndpoints.cs:18,31 — 没有[Authorize]/[AllowAnonymous]；行为
  取决于环境全局策略。按端点明确意图。

[LOW] OrderPlacedHandler.cs:22 — 日志中的PII (A09:2025)。记录CustomerId，而不是电子邮件。

注意：仅静态分析 — 这不能替代渗透测试。
```
