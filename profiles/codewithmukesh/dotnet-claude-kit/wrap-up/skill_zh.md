# /总结

## 什么是

会话连续性仪式。会话是短暂的；知识是永恒的。
总结将会话连接起来，双向进行：

- **会话结束** — 捕获三个要点：已完成的工作、待办事项和所学内容。将它们写入 `.claude/handoff.md` 并将持久性学习成果流入 `MEMORY.md`。
- **会话开始** — 加载交接内容、记忆和本能，然后呈现摘要总结，确保没有会话盲目开始。

## 何时

- 工作会话结束 — "今天完成"、"就这样"、"结束工作"
- 切换项目或重大里程碑之后
- 隐式结束 — 完成任务后的"谢谢"、"现在足够好了"：提供交接内容，不要只是说再见
- 会话开始 — "开始会话"、"加载交接内容"、"我们之前在做什么"
- 对于会话中不结束的中间保存，使用 `/checkpoint` 而不是结束

## 如何

### 会话结束

1. **回顾会话** — 从 git 状态/差异和对话中：接触的文件、完成的任务与未完成的任务、做出的决策及其原因、观察到的用户更正。
2. **检查未提交的更改** — 如果存在，在总结前提供提交选项。
3. **编写交接内容** — `.claude/handoff.md`，使用以下格式。
   单个文件，始终被覆盖 — 只有当前状态才重要。如果现有的交接内容包含其他人的待办事项，在覆盖前询问：合并、覆盖或跳过。
4. **提取学习成果** — 值得保留的更正和发现进入 `MEMORY.md`（通过 `instinct-system`）；出现的模式更新 `.claude/instincts.md`（通过 `instinct-system`）。交接内容的"所学"部分是触发器，不是目的地 — 交接内容是短暂的。
5. **确认** — 总结捕获的交接内容和学习成果供用户参考。

### 交接文件格式 (`.claude/handoff.md`)

为完全不了解背景的陌生人编写 — 文件路径、推理、具体下一步。 "继续重构"是无用的；"重构 `src/Orders/CreateOrder.cs` 到结果模式 — 查看目录以获取已建立的模式"是可操作的。

```markdown
# 会话交接

> 生成时间：2026-06-12 | 分支：feature/order-validation

## 已完成
- [x] 为 CreateOrder 添加了 FluentValidation (src/Orders/Features/CreateOrder.cs:15-35)
- [x] 修复了 GetOrderDetails 中的 N+1 (src/Orders/Features/GetOrderDetails.cs:28)

## 待办
- [ ] 为 UpdateOrder 添加验证 (src/Orders/Features/UpdateOrder.cs)
  - 参考：CreateOrder 验证器以获取已建立的模式
- [ ] 全面测试运行 — 2 个现有目录失败，不是今天的

## 学习成果
- FluentValidation 验证器必须在模块的 DI 设置中注册
- 测试固定种子每个订单 1 个项，这隐藏了 N+1 查询

## 背景
- 分支：feature/order-validation | 最后提交："添加 CreateOrder 验证"
- 未提交的更改：无 | 解决方案：src/MyApp.slnx
```

当多个开发人员共享项目时，添加 `## 做出的决策` 表格（决策 | 选择 | 理由）和 `## 开放性问题`。

### 学习成果提取清单

1. 用户更正了任何内容吗？ → 通过 `instinct-system` 进入 MEMORY.md
2. 我们发现了什么不明显的东西？ → 学习成果部分
3. 我们基于推理做出了什么决定？ → 记录"原因"
4. 工具/方法失败了吗？ → 记录以便下一个会话不再尝试

好的学习："EF 编译查询不适用于 Include()"。不好的学习："处理了订单模块"（模糊）或"使用了 TimeProvider"（已经是规则）。

### 会话开始

1. **加载上下文** — 读取 `.claude/handoff.md`（待办工作）、`MEMORY.md`（永久规则）、`.claude/instincts.md`（0.7+ 置信度的模式）。缺失文件是没问题的：记录并干净开始 — 从不等待它们。
2. **检测解决方案** — 查找 `.slnx`/`.sln`（当前目录，然后父目录，然后子目录），以便 Roslyn MCP 工具从第一个提示起工作。
3. **呈现摘要总结** — 上一个会话的工作、待办任务、活跃规则/本能计数、检测到的解决方案。然后询问要做什么工作 — 从不自动开始待办任务。

```
## 待办
- [ ] 为支付网关调用添加重试逻辑 (OrderService.cs:42)

## 捕获的学习成果
- 用户更喜欢显式映射而不是 AutoMapper → MEMORY.md

已写入 .claude/handoff.md。下次会话见。
```

## 相关

- `/checkpoint` — 会话中保存（提交+简短备注）而不结束会话
- `instinct-system` — 路由会话学习成果：模式成为本能，用户更正成为永久的 MEMORY.md 规则
