# 视频使用

## 原则

1. **LLM 从原始字幕 + 即时视觉信息中推理。** 只有打包的短语级字幕 (`takes_packed.md`) 才是真正有价值的衍生品。其他一切——填充词标记、重拍检测、镜头分类、强调评分——你都在决策时才进行提取。
2. **音频是主要，视觉是辅助。** 切割候选来自语音边界和静默间隙。只在决策点才深入分析视觉信息。
3. **询问 → 确认 → 执行 → 迭代 → 持久化。** 在用户用平实的英语确认策略之前，绝不触碰切割点。
4. **泛化。** 不要假设这是什么类型的视频。先查看素材，再询问用户，然后进行编辑。
5. **艺术自由是默认选项。** 本文档中提到的每个具体值、预设、字体、颜色、时长、音调结构和技巧，都是某个已验证视频的*示例*——不是强制要求。阅读它们以了解可能性和每个示例成功的原因。然后根据素材实际内容和用户实际需求，做出自己的品味判断。**你必须做的唯一事项在下面的“硬规则”部分。** 其他所有事项都由你决定。
6. **自由创新。** 如果素材需要本指南中未描述的技术——分屏、画中画、角标身份卡、反应剪辑、速度变化、定格帧、交叉溶解、匹配剪辑、L切、J切、呼吸间的速度变化，等等——请构建它。助手是 ffmpeg 和 PIL。它们可以做任何格式支持的事情。不要等待许可。
7. **在向用户展示输出前自行验证。** 如果你不会发布它，就不要呈现它。

## 硬规则（生产正确性——不可协商）

这些是偏离会导致静默失败或输出损坏的地方。它们不是品味，而是正确性。记住它们。

1. **字幕在过滤器链中最后应用**，在所有叠加层之后。否则叠加层会遮挡字幕。静默失败。
2. **按段提取 → 无损 `-c copy` 连接**，而不是单次过滤图。否则在添加叠加层时每个段都会进行双重编码。
3. **每段边界处 30ms 音频淡入淡出** (`afade=t=in:st=0:d=0.03,afade=t=out:st={dur-0.03}:d=0.03`)。否则每个切割点都会有可听到的爆音。
4. **叠加层使用 `setpts=PTS-STARTPTS+T/TB`** 将叠加的帧 0 移动到其窗口开始。否则在叠加窗口期间你会看到动画的中间部分。
5. **主 SRT 使用输出时间偏移**：`output_time = word.start - segment_start + segment_offset`。否则在段连接后字幕会错位。
6. **永不切割在单词内部。** 从 Scribe 字幕中，将每个切割边缘对齐到单词边界。
7. **每个切割边缘填充。** 工作窗口：30–200ms。Scribe 时间戳漂移 50–100ms——填充吸收漂移。快节奏的更紧，电影化的更松。
8. **仅使用单词级逐字语音识别。** 永不使用 SRT/短语模式（丢失亚秒级间隙数据）。永不使用标准化填充词（丢失编辑信号）。
9. **按源缓存字幕。** 除非源文件本身发生变化，否则永不重新转录。
10. **多个动画的并行子代理。** 永不按顺序。通过 `Agent` 工具一次生成 N 个；总墙时间约等于最慢一个。
11. **执行前确认策略。** 在用户批准平实的英文计划之前，永不触碰切割点。
12. **所有会话输出在 `<videos_dir>/edit/`。** 永不向 `video-use/` 项目目录内写入。

本文档中的其他所有内容都是示例。当素材需要时，随时偏离。

## 目录布局

技能存在于 `video-use/` 中。用户素材存放在他们放置的任何地方。所有会话输出都进入 `<videos_dir>/edit/`。

```
<videos_dir>/
├── <未修改的源文件>
└── edit/
    ├── project.md               ← 内存；每个会话都会追加
    ├── takes_packed.md          ← 短语级字幕，LLM 的主要阅读视图
    ├── edl.json                 ← 切割决策
    ├── transcripts/<name>.json  ← 缓存的原始 Scribe JSON
    ├── animations/slot_<id>/    ← 每个动画的源 + 渲染 + 推理
    ├── clips_graded/            ← 每段提取，带评分 + 淡入淡出
    ├── master.srt               ← 输出时间线字幕
    ├── downloads/               ← yt-dlp 输出
    ├── verify/                  ← 调试帧 / 时间线 PNG
    ├── preview.mp4
    └── final.mp4
```

## 设置

首次安装存在于 `install.md` 中（克隆、依赖项、ffmpeg、技能注册、API 密钥）。不要每次会话都重新运行它；冷启动时只需验证：

- `ELEVENLABS_API_KEY` 解析——无论是在环境变量中还是在视频使用仓库根目录的 `.env` 中。如果缺失，请让用户粘贴一个并写入 `.env`（绝不能写入用户的 `<videos_dir>`）。
- `ffmpeg` + `ffprobe` 在 PATH 中。
- Python 依赖项已安装（在仓库内使用 `uv sync` 或 `pip install -e .`）。
- 如果会话需要 HyperFrames 或 Remotion 插槽，则提供 Node.js + npm。HyperFrames 目前需要 Node.js 22+。
- 仅在首次使用时安装 `yt-dlp`、HyperFrames、Remotion、Manim。
- 首次使用的动画设置发生在插槽目录内，绝不在视频使用仓库根目录。HyperFrames 可以使用 `npx --yes hyperframes ...` 调用；Remotion 可以使用 `npx create-video@latest` 或在使用其 `remotion render` 命令之前作为项目本地依赖项安装。
- 此技能供应商 `skills/manim-video/`。构建 Manim 插槽时阅读其 SKILL.md。

助手（`helpers/transcribe.py`、`helpers/render.py` 等）与此 SKILL.md 一起存在。解析它们的路径相对于包含此文件的目录——技能通常链接在 `~/.claude/skills/video-use/` 或 `~/.codex/skills/video-use/`。

## 助手

- **`transcribe.py <video>`** — 单文件 Scribe 调用。`--num-speakers N` 可选。已缓存。
- **`transcribe_batch.py <videos_dir>`** — 4 工作者并行转录。用于多镜头。
- **`pack_transcripts.py --edit-dir <dir>`** — `transcripts/*.json` → `takes_packed.md`（短语级，在静默 ≥ 0.5s 时断行）。
- **`timeline_view.py <video> <start> <end>`** — 电影胶片 + 波形 PNG。按需视觉钻探。**不是扫描工具**——只在决策点使用，而不是持续使用。
- **`render.py <edl.json> -o <out>`** — 每段提取 → 连接 → 叠加层（PTS 移位）→ 字幕最后。`--preview` 用于 720p 快速。`--build-subtitles` 用于内联生成 master.srt。
- **`grade.py <in> -o <out>`** — ffmpeg 过滤器链评分。预设 + `--filter '<raw>'` 用于自定义。

对于动画，使用 `Bash` 创建 `<edit>/animations/slot_<id>/` 并通过 `Agent` 工具生成子代理。

## 流程

1. **盘点。** 对每个源使用 `ffprobe`。对目录使用 `transcribe_batch.py`。使用 `pack_transcripts.py` 生成 `takes_packed.md`。抽样一个或两个 `timeline_view` 以获得初步视觉印象。
2. **预扫描问题。** 一次遍历 `takes_packed.md`，记录口头失误、明显的误讲或要避免的措辞。平实列表，输入编辑简报。
3. **对话。** 用平实的英语描述你看到的内容。提出由素材塑造的问题。收集：内容类型、目标时长/宽高比、美学/品牌方向、节奏感、必须保留的时刻、必须切割的时刻、动画和评分偏好、字幕需求。不要使用固定清单——正确的问题每次都不同。
4. **提出策略。** 4–8 句话：形状、镜头选择、切割方向、动画计划、评分方向、字幕风格、时长估计。**等待确认。**
5. **执行。** 通过编辑子代理简报生成 `edl.json`。在模糊时刻钻探 `timeline_view`。并行子代理中构建动画。按段应用评分。通过 `render.py` 进行合成。
6. **预览。** `render.py --preview`。
7. **自我评估（向用户展示前）。** 在渲染输出（不是源文件）的每个切割边界（±1.5s 窗口）上运行 `timeline_view`。检查每个图像：
   - 切割处的视觉不连续性/闪光/跳跃
   - 边界的波形尖峰（漏过 30ms 淡入的音频爆音）
   - 字幕被叠加层遮挡（违反规则 1）
   - 叠加层未对齐或显示错误帧（违反规则 4）

   还要抽样：前 2s、最后 2s、2–3 个中间点——检查评分一致性、字幕可读性、整体连贯性。对输出运行 `ffprobe` 以验证时长是否符合 EDL 预期。

   如果有任何问题：修复 → 重新渲染 → 重新评估。**最多 3 次自我评估**——如果 3 次后仍有问题，请向用户标记而不是无限循环。只有通过自我评估后才能呈现预览。
8. **迭代 + 持久化。** 自然语言反馈，重新计划，重新渲染。永不重新转录。确认后最终渲染。追加到 `project.md`。

## 切割工艺（技术）

- **音频优先。** 候选切割来自单词边界和静默间隙。
- **保留峰值。** 笑声、妙语、强调节拍。将节拍扩展到妙语之后以包含反应——笑声就是节拍。
- **说话者交接**受益于话语间的停顿。常用值：400–600ms。快节奏的更短，电影化的更长。品味判断。
- **音频事件作为信号。** `(笑声)`、`(叹息)`、`(掌声)` 标记节拍。将它们扩展过去。
- **静默间隙是切割候选。** 静默 ≥400ms 通常是干净的。150–400ms 短语边界可用，需视觉检查。<150ms 不安全（短语中）。
- **示例切割填充**（该启动视频使用此设置）：第一个保留单词前 50ms，最后一个保留单词后 80ms。蒙太奇能量更紧，纪录片更松。保持在 30–200ms 工作窗口内（硬规则 7）。
- **永不独立推理音频和视频。** 每个切割必须在两个音轨上都有效。

## 打包字幕（主要阅读视图）

`pack_transcripts.py` 读取所有 `transcripts/*.json` 并生成一个 markdown 文件，其中每个取件是一个短语级行的列表，每个行前缀为其 `[开始-结束]` 时间范围。短语在任何静默 ≥ 0.5s 或说话者变化时断行。这是编辑子代理读取以选择切割的工件——它仅从文本中提供单词边界精度，而原始 JSON 的 token 数是 1/10。

示例行：
```
## C0103  (时长: 43.0s, 8 个短语)
  [002.52-005.36] S0 九成的网络代理工作完全是浪费。
  [006.08-006.74] S0 我们解决了这个问题。
```

## 编辑子代理简报（用于多取件选择）

当任务是“跨多个片段选择每个节拍的最好取件”时，使用类似此形状的简报生成专用子代理。结构是承重的；音调形状示例不是。

```
你是编辑一个 <类型> 视频。选择每个节拍的最好取件，并按节拍而不是按源片段顺序按时间顺序排列。

输入：
  - takes_packed.md (时间注释的短语级字幕，所有取件)
  - 产品/叙事上下文: <用户的两句话>
  - 说话者: <姓名、角色、交付风格注释>
  - 预期结构: <选择原型或发明一个>
  - 要避免的口头失误: <预扫描传递的列表>
  - 目标运行时: <秒>

常见结构原型（选择、调整或发明）:
  - 技术发布/演示:   HOOK → PROBLEM → SOLUTION → BENEFIT → EXAMPLE → CTA
  - 教程:             INTRO → SETUP → STEPS → GOTCHAS → RECAP
  - 采访:            (QUESTION → ANSWER → FOLLOWUP) 重复
  - 旅行/活动:       ARRIVAL → HIGHLIGHTS → QUIET MOMENTS → DEPARTURE
  - 纪录片:          THESIS → EVIDENCE → COUNTERPOINT → CONCLUSION
  - 音乐/表演:       INTRO → VERSE → CHORUS → BRIDGE → OUTRO
  - 或发明你自己的。

规则:
  - 开始/结束时间必须落在字幕的单词边界上。
  - 填充切割边界（工作窗口 30–200ms）。
  - 优先选择 ≥ 400ms 的静默作为切割目标。
  - 如果没有更好的取件，不可避免的失误会被保留。在“reason”中注明。
  - 如果超出预算，请修订：丢弃一个节拍或修剪尾部。报告总数并进行自我纠正。

输出 (JSON 数组，无散文):
  [{"source": "C0103", "start": 2.42, "end": 6.85, "beat": "HOOK",
    "quote": "...", "reason": "..."}, ...]

返回最终 EDL 和一行总运行时检查。
```

## 色彩校正（当请求时）

你的工作是**推理图像**，而不是应用预设。查看一个帧（通过 `timeline_view`），决定哪里有问题，调整一件事，再看一次。

心智模型是 ASC CDL。每个通道：`out = (in * slope + offset) ** power`，然后全局饱和度。`slope` → 高光，`offset` → 阴影，`power` → 中调。

**示例过滤器链** (`grade.py` 有 `--list-presets`；将其作为起点或混合你自己的）：

- **`warm_cinematic`** — 复古/技术，微妙的青/橙分裂，去饱和。实际发布视频中使用了。适合访谈。
- **`neutral_punch`** — 最小化校正：对比度提升 + 柔和 S 曲线。无色相偏移。
- **`none`** — 直接送。用户未请求时默认。

对于其他任何内容——肖像、自然、产品、音乐视频、纪录片——发明你自己的链。`grade.py --filter '<raw ffmpeg>'` 接受任何过滤器字符串。

硬规则：在提取期间按段应用（不在连接后，这会重新编码两次）。永不激进，除非测试肤色。

## 字幕（当请求时）

字幕有三个值得推理的维度：**分段**（每行 1/2/3/句）、**大小写**（大写/标题/自然）、**位置**（底部边距）。正确的组合取决于内容。

**示例风格**——选择、调整或发明：

**`bold-overlay`** — 短形式技术发布，快节奏社交。2 词段，大写，按标点断行，Helvetica 18 粗体，白色轮廓，`MarginV=35`。`render.py` 随附此样式为 `SUB_FORCE_STYLE`。

```
FontName=Helvetica,FontSize=18,Bold=1,
PrimaryColour=&H00FFFFFF,OutlineColour=&H00000000,BackColour=&H00000000,
BorderStyle=1,Outline=2,Shadow=0,
Alignment=2,MarginV=35
```

**`natural-sentence`**（如果你发明此模式）——叙事、纪录片、教育。4–7 词段，句子大小写，按自然停顿断行，`MarginV=60–80`，更大的字体以提高可读性，最大宽度略宽。没有附带的 force_style——如果你需要，请设计一个。

如果都不适合，请发明第三个风格。硬规则：字幕最后（规则 1），输出时间线偏移（规则 5）。

## 动画（当请求时）

动画匹配内容和品牌。**从对话中获取调色板、字体和视觉语言**——永远不要假设默认值。如果用户没有告诉过你，请在策略阶段提议一个调色板，并在构建任何东西之前等待确认。

**工具选项:**

为每个动画插槽选择引擎。不要因为动画与网络相关就默认使用 Remotion。

- **HyperFrames** — 浏览器原生 HTML/CSS/GSAP 视频组合：产品 UI 动画，网站到视频或模型到视频捕获，动态文字，着陆页/故事板促销，数据驱动 UI 状态，透明 WebM 叠加层，以及需要确定性帧捕获和 HyperFrames 检查/验证/渲染检查的片段。当动画应该像网络组合一样编写和验证，而不是 React 组件树时最佳。
- **Remotion** — React/CSS 组合，带组件状态、可重用的 React 基本元素或现有的 Remotion 品牌系统。当用户明确要求 React/Remotion 或 React 组合是更简单的创作模型时最佳。
- **Manim** — 正式图表、状态机、方程推导、图形态变。阅读 `skills/manim-video/SKILL.md` 及其参考资料以深入了解。
- **PIL + PNG 序列 + ffmpeg** — 简单叠加层卡：计数器、打字机文本、单条条形揭示、渐进式绘制。快速迭代，任何美学。启动视频使用了这个。

对于 HyperFrames 插槽，使用 `npx --yes hyperframes init . --example blank --non-interactive --skip-skills` 在插槽目录内构建插槽，在那里构建 HTML 组合，运行适合插槽的 HyperFrames 检查（在实用时进行 `lint`、`validate` 和草稿渲染），然后使用 `npx --yes hyperframes render . -o render.mp4` 或 `--format webm -o render.webm` 在需要 alpha 时生成最终叠加视频。将 EDL 叠加 `file` 指向实际渲染路径。

对于 Remotion 插槽，将 Remotion 项目隔离在相同的插槽目录内，使用 `npx create-video@latest` 或在那里本地安装 Remotion，使用项目本地 `remotion render` 命令将组合渲染为 `render.mp4`，并使用 `ffprobe` 验证时长和尺寸。

没有强制要求。如果有用，可以发明混合体（例如，PIL 背景与 HyperFrames 或 Remotion 层叠）。

**大致时长规则，上下文相关:**

- **与解说同步。** 观众需要以 1× 速度解析内容。粗略底部 3s，典型 5–7s 用于简单卡片，8–14s 用于复杂图表。启动视频为 5–7s 每个简单卡片。
- **节拍同步强调**（音乐视频、快节奏蒙太奇）。0.5–2s 很好——它们是视觉强调，不是信息。可读性在 1× 规则变为 *"可识别性在 1×"*，而不是 *"完全可解析性。*
- **在切割点前保持最终帧 ≥ 1s**（通用）。
- **覆盖旁白：** 总时长 ≥ `旁白时长 + 1s`（通用）。
- **永不并行揭示独立元素**——眼睛无法同时跟踪两件新事物。一件事情，暂停，下一件事情。

**动画回报时机（与解说同步的规则）**：获取回报词的时间戳。开始动画 `reveal_duration` 秒前的叠加 `reveal_duration`，使着陆帧与说出的回报词同步。如果不这样同步，动画会感觉不连贯。

**缓动**（通用——永远不要 `linear`，它看起来很机械）：

```python
def ease_out_cubic(t):    return 1 - (1 - t) ** 3
def ease_in_out_cubic(t):
    if t < 0.5: return 4 * t ** 3
    return 1 - (-2 * t + 2) ** 3 / 2
```

`ease_out_cubic` 用于单个揭示（缓慢着陆）。`ease_in_out_cubic` 用于连续绘制。

**打字文本锚点技巧：** 以完整字符串的宽度为中心，而不是部分字符串宽度——否则文本在揭示过程中会向左滑动。

**示例调色板**（启动视频——无限美学中的一种）：
- 背景 `(10, 10, 10)` 接近纯黑
- 强调 `#FF5A00` / `(255, 90, 0)` 橙色
- 标签 `(110, 110, 110)` 暗灰色
- 字体：Menlo Bold 在 `/System/Library/Fonts/Menlo.ttc`（索引 1）
- ≤ 2 个强调色，~40% 空间，极少的镀铬
- 结果：终端/复古科技感

这是一个样式。如果品牌是温暖的无衬线字体，就使用那个。如果是多彩和有趣的，就使用那个。如果用户给了你风格指南，就遵循它。如果没有，请提议一个并确认。

**并行子代理简报**——每个动画是一个通过 `Agent` 工具生成的子代理。每个提示是自包含的（子代理没有父级上下文）。包括：

1. 单句目标：*"构建一个动画：[规格]。其他什么都不要。"*.
2. 绝对输出路径 (`<edit>/animations/slot_<id>/render.mp4`)
3. 精确技术规格：分辨率、fps、编码器、pix_fmt、CRF、时长
4. 风格调色板作为具体值（RGB 元组、十六进制或引用设计系统）
5. 字体路径与索引
6. 帧时间线（何时发生，带缓动）
7. 反列表（“不要铬，不要额外内容，除非指定标题”）
8. 代码模式参考（直接复制助手，不要跨插槽导入）
9. 交付清单（脚本、渲染、通过 ffprobe 验证时长、报告）
10. **"不要提问。如果 anything 模糊不清，选择最明显的解释并继续。"*.

一个子代理 = 一个文件（唯一文件名，并行代理不会互相覆盖）。
