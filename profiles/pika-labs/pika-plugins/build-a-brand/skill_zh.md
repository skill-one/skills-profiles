# 建立品牌

> 以下工具是 **Pika MCP** 工具，命名为 bare — 在您的会话中为 Pika MCP 暴露的任何前缀下调用每个工具。

接受任何输入——一个想法、一个网站、一份参考品牌列表、产品照片或一个需要更新的现有品牌——并生成可用的品牌标识。

这是一个独立的品牌建设工作流，专注于策略、标识、设计和文案。默认输出是一个 **快速品牌交付**，可以在几分钟内完成。完整的 14-16 页品牌指南 PDF 仍然可用，但只有在用户明确要求完整深度或选择在快速浏览后深入时才可用。

## 参考文件

仅在相关阶段开始时加载这些：
- `references/brand-directions.md` — 策略角度结构和差异化定位板。
- `references/brand-identity.md` — logo 管道、符号规则、概念车道和板面文案预算。
- `references/brand-guidelines.md` — 完整指南布局、渲染合同、页面结构和 QA 规则。
- `references/brand-md-template.md` — 必要的机器可读 `brand.md` 结构。

## 执行模型——本地优先，仅在需要时使用云端

此技能是本地优先的。将确定性生产工作保留在用户的机器上：
- **本地：** 工作区设置、下载的字体、下载后生成的图像文件、图像压缩、透明背景清理、16x16 网站图标测试、HTML/CSS 页面构建、PDF 渲染、PNG/JPG QA 快照、logo 资产组装、token/prompt 文件和最终 zip 打包。
- **云端：** 仅限付费生成（`gpt-image-2` 用于符号、情绪图像、摄影、插画和环境纹理）以及在简报要求时进行 URL/来源研究。

默认情况下不要使用云端 PDF 渲染器或上传 PDF。将快速 PDF、板面 PDF、指南 PDF 和品牌包 zip 保存到 Mac 上的 `~/Desktop`，或者在无法使用桌面时保存到项目工作目录。只有在用户明确要求托管文件时才通过 CDN 上传/共享。

**PDF 资产卫生：** 永远不要将全尺寸 gpt-image-2 PNG 直接嵌入板面或指南 PDF 中。这之前产生了巨大的 PDF，并且在渲染器尝试获取多 MB 的 CDN 图像时导致 `ASSET_FETCH_TIMEOUT` 失败。下载每个生成的图像，将其下采样到插槽大小，并在将其用于渲染 HTML 之前保存一个约 85-180KB 的本地 JPEG 目标。仅将透明 PNG 用于 logo/符号源资产和 favicon/logo 导出，不要用于摄影页面图像。**永远不要在照片或渲染 HTML 中的 `background-image` 上放置 CSS `filter:`/`backdrop-filter:`（暖色调、棕褐色、饱和度、亮度、模糊）——它强制 Chromium 将该元素光栅化为 PDF 中的全分辨率 *无损* 位图，这取消了上面的 JPEG 步骤并重新膨胀文件（仅一个暖色调情绪板页面就将整个包膨胀到 70 MB）。将任何颜色色调烘焙到 JPEG 本身中（在 gpt-image-2 提示或当您 `img.save(..., 'JPEG', ...)` 时）；`drop-shadow()` 是唯一安全的滤镜。

## 成本透明度门

在任何付费 MCP 调用之前，调用一次 `identity_balance({verbose: true})`。显示当前余额、最近消耗率和剩余运行空间，然后用确切的消息为所选深度设置门：

> 预计成本：快速品牌约 100-300 个信用（~$1-$3），完整品牌指南约 900-1,500 个信用（~$9-$15）。这些范围涵盖 gpt-image-2 符号/情绪/触点生成以及一次针对失败的图像 QA 的目标再生。快速品牌通常低于 $5；完整品牌指南超过 $5，因此回复 `proceed` 继续 或 `cancel` 停止。

在用户回复 `proceed` 之前不要调用任何付费 MCP 工具。如果用户回复 `cancel`，则不生成。对于非交互式 `--quick`、`--full` 或 `--config` 调用者，需要在配置或调用元数据中要求 `cost_ack=proceed`；如果缺失，则停止并给出估计，而不是花费信用。

## 深度模式

在选择任何长时间运行的生成或渲染工作之前选择深度：

1. **快速品牌（默认）**—— 用于首次创始人包运行、`--quick`、创作者教程流程、批量/子代理调用，或任何要求品牌但不明确要求完整品牌指南的用户。目标：在可用输入后 8-12 分钟；最多 4 个生成的图像，除非 QA 失败；一个快速 PDF 渲染加上一个当需要时的 QA 重新渲染。
2. **完整品牌指南（可选）**—— 仅在用户要求“完整”、“品牌指南”、“品牌指南”、“14-16 页”、“15 页”、“--full”，或批准快速路径的“深入”升级时使用。目标：在锁定选择后 25-45 分钟，不包括用户回复时间。

快速品牌不是一个部分或失败的完整指南包。它是一个故意较小的交付物，有其自己的完成标准。如果选择的模式是完整，所有完整指南完成门仍然适用。

## 模式选择

### 阶段 0 — 摄入（空参数菜单）

如果使用没有输入（没有想法、没有 URL、没有照片、没有参考品牌，并且对话中没有相关先前的上下文）调用，请将此菜单逐字打印为您的完整响应并停止。不要调用任何工具。等待用户的下一条消息。

> **我们在为谁建立品牌？** 粘贴以下任何一项：
>
> - **一个想法/描述** —— 例如，“为猫爱好者创立街头服饰品牌”
> - **一个网站 URL** —— 例如，“在 example.com 更新我的现有网站”
> - **产品照片** —— 将它们拖入聊天
> - **参考品牌** —— 例如，“我想获得一种感觉像 Aesop + Patagonia 的品牌”
> - **一个需要更新的现有品牌** —— 名称 + 哪些方面有效/无效
>
> 我将默认使用快速品牌。如果您想要更深入的 14-16 页指南路径，请说 **完整品牌指南**。

如果用户已经拖入以上任何一项，请跳过菜单并进入所选模式：默认快速品牌的快速步骤 1，或当选择完整品牌指南模式时的步骤 1。

### 阶段 0.5 — 快速品牌和非交互式快速通道

当调用者传递 `--quick`、省略显式的完整深度请求，或声明他们正在从 CI、子代理、批量作业、教程录制或任何其他非交互式框架运行时，使用快速品牌模式。

仅当调用者传递 `--full`、在配置中设置 `mode: "full"`、明确要求完整指南/品牌指南深度，或批准快速之后的“深入”升级时，使用完整品牌指南模式。

本节优先于下面的交互式询问/等待说明。当快速模式适用时，使用下面的快速品牌工作流，并且不要转入多轮完整工作流摄入，除非确实缺少必要的输入。

- `--config <path>` 指向一个 JSON 文件，其中预烘焙了摄入答案：
  `input`、`photos`、`reference_brands`、`audience`、`positioning`、`assets_to_keep`、
  `references`、`mode`、`chosen_direction`、`chosen_identity` 和 `export_kit`。
- `--quick` 意味着快速品牌模式。使用模型判断所有确认门。
  如果原始输入完全缺失，请询问；否则推断合理的默认值，选择最强的策略方向和身份选项，然后继续。
- `--full` 意味着完整品牌指南模式。在非交互式运行中，仍然使用模型判断确认门的判断，但不要省略所需的 14-16 页指南。
- 对于 `--quick` 或 `--config`，不要在交付预览、策略方向选择、身份选项选择或品牌包导出门停止确认。直接记录假设，然后继续。
- 如果缺少必要的资产且无法从输入中推断，请一次性停止并显示一个紧凑的缺失字段列表，而不是开始多轮 Q&A 循环。
- 在快速模式下，交付下面定义的快速品牌包；不要将其描述为精简的完整指南包。
- 在完整模式下，不要因为调用者是非交互式的或运行时间短而交付精简或部分的品牌输出。一个精简的 6 页包不能替代所需的 14-16 页指南。如果运行超出墙钟预算，请保存一个可恢复的检查点，其中包含已完成页面/资产，并停止；不要将工作流标记为完成。

**自主完整模式：** 仅在存在显式完整深度请求（`--full`、`mode: "full"` 或用户要求完整品牌指南/完整指南）并且运行已经具有 `cost_ack=proceed` 时使用。在这种情况下，简报就是规范。不要等待用户选择板面，也不要在包导出之前等待明确的用户批准。在一次运行中生成所有三个完整交付物：

1. `brand-boards.pdf` — 生成所有三个板面，并使用模型判断选择最强的板面或混合。
2. `brand-guidelines.pdf` — 为所选板面构建完整的 14-16 页指南。
3. `brand-kit.zip` — 在指南通过 QA 后导出完整的包。

在 `brand.md` 和最终响应中记录假设和所选方向。如果简报足够模糊，以至于板面选择将是任意的，请一次性停止并给出缺失的决策，而不是假装运行是自主的。非交互式清晰简报而没有明确完整深度的保持快速；永远不要仅仅因为简报清晰就将批量/教程/创始人包运行提升到完整。

## 快速品牌工作流（默认）

使用此工作流进行快速品牌模式。它是创始人包快速通道：更少的选择、更少的生成资产，以及一个可以无消耗地传递下游技能的完整起始品牌。

### 快速步骤 1 — 单次摄入

如果有可用输入，不要开始长时间的问卷。声明您正在使用的假设，并在答案会实质性改变品牌时最多询问 3 个紧凑的问题：

- 这个品牌销售或做什么？
- 它面向谁？
- 我是否应该保留任何现有的名称、logo、颜色、字体、照片或参考？

对于 `--quick`、`--config`、CI、子代理、批量或教程录制流程，除非原始输入完全缺失，否则不要等待这些答案。推断合理的默认值，并在输出中记录它们。

### 快速步骤 2 — 选择一个最强的方向

在快速模式下不要呈现 2-3 个方向或 3 个身份选项。使用模型判断选择一个最强的策略和身份。快速策略必须仍然包括：

- 品牌名称或保留名称
- 标语（最多 8 个字）
- 受众细分：主要细分市场、次要细分市场（如有）和一个锚定角色
- 定位声明
- 保留的资产
- 参考品牌/灵感，如果提供

### 快速步骤 3 — 构建起始身份

创建一个连贯的身份系统：

- Logo 概念：文字标志 + 独立符号/标记 + 锁定计划。对于新符号，使用 `generate_image` 并将批准的符号作为透明 PNG 尺寸发送，而不是 SVG。文字标志和锁定资产可以是 SVG，因为文字标志是从真实字体文本转换为轮廓路径的。
- 调色板：4 个核心颜色及其角色和十六进制值。
- 字体：一个有特色的展示字体和一个实用的正文字体，当可用时提供 Google Fonts URL。
- 语气：3 个语气原则、3 个样本行和 5 个禁止的单词/短语。
- 图像方向：一个简短的摄影/插画规则集加上无文本图像提示守卫。
- 起始应用：社交头像/应用图标、简单的网页英雄方向，以及适合品牌类型的实用触点。

限制图像生成：一个符号/标记图像加上最多 3 个情绪或触点图像。重试预算：每个生成的品牌图像资产最多获得 2 次总生成尝试（初始尝试 + 一次目标再生）。如果 QA 失败，请仅重新生成失败的资产。在耗尽任一上限后，停止并询问用户他们想要放松哪些失败的资产或布局问题，而不是继续花费信用。

### 快速步骤 4 — 交付快速品牌包

快速交付必须足够完整，以便创作者可以立即使用：

```
[brand-name]-quick-brand/
├── quick-brand.pdf              # 3 页：封面/策略，身份系统，起始应用
├── brand.md                     # 紧凑的机器可读品牌规范
├── README.md                    # 如何使用快速品牌以及何时升级
├── logo/                        # 生成的符号、文字标志和锁定资产
├── tokens/
│   ├── tokens.css
│   ├── tokens.json
│   └── tailwind.config.snippet.js
└── prompts/
    ├── system-prompt.md
    └── imagery.md
```

3 页 `quick-brand.pdf` 页面结构：

1. **封面 + 策略** — 品牌名称、标语、定位、受众细分、锚定角色、参考和英雄视觉。
2. **身份系统** — logo 系统、调色板、字体、语气规则和图像规则。
3. **起始应用** — 社交头像/应用图标、网页英雄/社交卡片方向、一个真实的触点或产品上下文图像，加上 3 个品牌特定的做和 3 个不做。

使用 Chrome 无头（或当 HTML 为其编写时使用 WeasyPrint）本地渲染 `quick-brand.pdf` 并在交付前检查 PNG/JPG 预览。快速视觉 QA 必须捕获剪切的文本、缺失的 logo/符号、难以阅读的字体、生成的图像中嵌入的文本、空占位符和明显的布局冲突。如果无法生成快速包或 zip，请停止并显示可恢复的检查点，其中包含已完成文件、缺失文件、资产路径/URL 和确切障碍。

交付快速品牌后，提供完整的 14-16 页指南作为“深入”升级。不要在用户明确要求之前开始完整工作流。

**始终也要询问（无论输入类型如何）：**
- 您是否有任何希望保留或融入的现有品牌资产？（标志、文字标志、符号、名称、颜色、字体、摄影、包装——任何您不希望失去的东西。）
- 您是否有任何特定的参考、灵感或您希望从中汲取灵感的情绪板？
- **这是数字产品吗**（应用程序、网站、SaaS、网络工具）？这决定了图标页面是否属于完整指南——对于非数字品牌（产品、服务、餐厅、时尚等），图标页面将被跳过。

这两点是必不可少的——它们可以防止您生成用户已经拥有的东西，并将工作锚定在用户实际喜欢的参考中。始终包含它们。

保持单一信息。目标是总共5-7个问题（特定输入问题+2个通用问题），对话式而非临床式。等待答案后再继续。

**回答后**，将输入和答案一起分析并回顾：
- **美学领域**：这个视觉世界存在于哪里？
- **受众细分**：主要细分市场、次要细分市场以及主要细分市场中的一个生动锚定角色。不要将受众简化为一个过于具体的个人。
- **定位**：什么是楔形——这个产品代表什么而竞争对手不代表？
- **价格等级/类别匹配**：这个产品在市场货架上位于何处？
- **故事钩子**：是什么情感原因让某人关心？
- **保留的资产**：明确列出用户表示要保留的内容（现有的文字标志、名称、颜色等）。
- **锚定工作的参考**：列出用户命名的灵感。

**然后预览交付物并邀请具体指导**——在进入品牌方向之前，向用户展示最终指南中会包含的内容，以便他们可以标记要添加、更改或指出的任何内容：

```
我将构建到品牌指南中（14-16页，取决于您的品牌）：

1. 封面（品牌名称、标语、英雄情绪）
2. 策略与定位（主要/次要受众细分+锚定角色）
3. 品牌基础（使命、价值观、故事）
4. 标志（文字标志+符号+变体）
5. 标志禁忌
6. 色彩搭配
7. 字体
8. 图标——UI图标系统+库指导，仅当这是数字产品（应用程序/网站/SaaS）时包含。对于非数字品牌将被跳过。
9. 声音与语气
10. 图像规则（摄影和/或插画，根据品牌媒介调整；如果是混合的，则分为2页）
11. 视觉世界/生活方式图像
12. 触点（真实照片显示品牌的使用情况）
13. 品牌应用（模型：名片、应用程序图标、网站图标等）
14. 数字+社交
15. 要与不要

最后是一个品牌包zip，包含：`brand.md`规范、标志资产（符号PNG尺寸、文字标志SVG/PNG、组合SVG/PNG）、品牌字体、设计令牌（CSS / JSON / Tailwind）、AI提示（系统提示+特定任务的起始提示），如果适用，则包含图标SVG。

您想添加、更改、具体指出或让我以不同方式处理的内容是什么？如果没有，我将继续进行3个品牌板。
```

等待回复。根据任何具体的用户指导（添加页面、交换内容、特别关注某个部分、排除某个内容）进行修改，然后再进行步骤2。这可以尽早捕获范围不匹配——比在PDF构建后发现它们要便宜得多。

### 步骤2——生成3个视觉品牌板（PDF）

这一步是用户与品牌首次接触的视觉元素。没有仅包含文本的“指示”会先于它出现。这些板就是指示，使其可见。每个板都包含一个完整的视觉标识，以便用户可以看到差异，而不仅仅是阅读它。

构建一个3页PDF（每页一个板，1200×850每个），并将其保存到 `~/Desktop/[brand-slug]-brand-boards.pdf`。每个板都是一个真正不同的品牌方向——不是模板重新着色。根据目标受众和品牌存在的理由进行区分，同时使视觉系统、布局、字体、色彩逻辑、摄影风格和声音感觉不同。

**每个选项必须包含：**
- **文字标志**：使用品牌展示字体——如果用户有一个他们喜欢的现有文字标志，则使用它；如果他们需要标志或不喜欢当前的标志，则建议一个新的。如果需要新的文字标志，则必须有定制的字母处理：调整间距、连字、切割、终端、大小写、下划线或其他可拥有的细节。它不仅仅是输入颜色的Google字体。
- **符号/标记**：一个可以独立于文字标志存在的图形。如果用户有一个他们喜欢的现有符号，则使用它；否则建议一个新的。即使用户保留他们的文字标志，如果没有符号，也建议一个符号—— favicons和应用程序图标需要一个非文字标记。对于新符号，通过 `generate_image` 生成透明PNG，使用 `provider="gpt-image-2"`。请求干净的隔离标记在透明背景上，没有内置字母，没有水印，没有模型，居中在一个方形中。不要将生成的符号转换为SVG；从批准的主导导出PNG尺寸。必须在16×16和512×512上工作。
- **印章/徽章**：如果选项使用印章、戳记、徽章或单字母，则必须在小型和中型尺寸下可读和可拥有。它不能是通用的圆形字体锁闭、剪贴画徽章或低对比度装饰填充。
- 标语（最多8个字）
- 声音样本，带有可见的“声音”标签（一个引用的句子，最多14个字）
- 紧凑型板故事（最多35个字，至少2句话）
- 生活方式世界描述，带有可见的“世界”标签（最多22个字，至少1个完整句子）
- 生活方式情绪图像（通过gpt-image-2生成）
- 4色调板，带有十六进制+角色标签
- 显示+正文类型样本，带有命名字体

品牌板页面应该看起来足够不同，以便用户在阅读标签之前就能知道他们正在看到哪个身份。不要使用3次重新着色的相同模板；每个板的布局应该体现该选项的设计理念。杂志封面选项应该像杂志封面（全出血照片，杂志头样式）；柔软的消费者选项应该像主页英雄（圆形形状，软圆形用于色板）；编辑选项应该像文学版面（巨大的斜体居中，内嵌照片）。参见 `references/brand-guidelines.md` “品牌板布局——根据选项区分”部分中的示例。

如果您在没有阅读标签的情况下无法物理上区分您正在查看的品牌——在视觉-QA重试预算以下重新生成。

**页面大小**：1200×850px。渲染器：首选本地无头Chrome；仅当HTML为它编写时才允许WeasyPrint。在本地渲染板PDF和预览，然后将最终板PDF复制到 `~/Desktop`。

**板质量门禁**：3页预览必须通过视觉QA，而不仅仅是渲染QA。

重试预算：每个品牌板或指南PDF视觉-QA循环最多只能为同一选项/套件获得2次渲染/修复尝试（初始渲染+一次修复重新渲染）。在任何一个上限用尽后，停止并询问用户他们想要放宽哪个失败的资产或布局问题；包括失败页面/资产名称、QA原因以及到目前为止的最佳预览URL。

1. 在发送PDF之前检查每个PNG预览。失败密度高、层次结构弱、单音调调板、小字不可读、空模型/图像插槽、文本剪切、正文副本或非杂志头文本与图标、色板、印章、照片、手机模型或装饰规则相交。还检查16×16和512×512处的符号；如果小尺寸可读性差、模糊、过于通用或变成噪音，则在交付前重新生成或简化。网站/社交/应用程序模型在品牌板上是可选的；除非它们包含真实内容，否则不要添加它们。如果包含，则平面色块视为空占位符，除非该部分明确是调板样本。
2. 在全尺寸下阅读每个板预览。失败低对比度文本、小字不可读、文本/照片碰撞、内容缺失、层次结构弱和单音调调板。杂志头文字标志/标语/问题元数据覆盖照片仅在它们使用故意负空间或对比度遮罩并通过 `references/brand-guidelines.md` 规则5中定义的对比度QA时才允许。图像上的正文仍然禁止。
3. 在交付之前修复每个捕获的失败。如果板在技术上有效但丑陋，将其视为失败，并在重新渲染之前简化层次结构、副本密度或装饰元素。

**字体规则**：每个品牌使用新鲜字体，并且字体必须有特点。永远不要默认使用Inter / Karla / Outfit / DM Sans / Lato——它们作为展示面没有观点。探索完整的Google Fonts库。参见 `references/brand-guidelines.md` “必须有特点——不要默认使用安全字体”部分中的高特点选项按氛围。将所选字体文件下载到本地，并在渲染的HTML中使用绝对 `file://` `@font-face` 声明。

**非拉丁品牌名称的字体回退**：品牌板、快速PDF和完整指南中的每个 `font-family` 链必须包含广泛的脚本回退。使用Chromium的每个字形回退，以便拉丁文保持在所选品牌面中，而CJK、阿拉伯文、西里尔文和其他脚本解析为Noto系列，而不是 tofu 箱。最小链：显示/衬线 `BrandDisplay, "Noto Serif SC", "Noto Serif TC", "Noto Serif JP", "Noto Serif KR", "Noto Sans Arabic", serif`；正文/无衬线 `BrandBody, "Noto Sans SC", "Noto Sans TC", "Noto Sans JP", "Noto Sans KR", "Noto Sans Arabic", system-ui, sans-serif`。

在用户选择选项之前，不要构建完整的14-16页指南PDF——这会浪费被拒绝身份的时间。例外：在自主完整模式下，使用模型判断选择最强的板或混合，并继续而不等待。

清晰地呈现所有3个。要求用户选择一个，或从不同选项中混合元素。

### 步骤3——构建完整的品牌指南PDF

一旦用户确认了板，就构建14-16页的品牌指南PDF。在自主完整模式下，根据假设日志中记录的模型选择的板或混合进行构建。

**页数是条件性的：**
- **14页**——非数字品牌（产品、餐厅、时尚、服务等）具有单一媒介图像。图标页面被跳过。
- **15页**——数字品牌（应用程序/网站/SaaS）具有单一媒介图像。包括图标页面。
- **15页**——非数字品牌具有混合图像（照片+插画）。图像分为2页；图标被跳过。
- **16页**——数字品牌具有混合图像。图标和分图像都存在。

根据包含的内容连续重新编号页面。不要留下页码空白。

**页面结构（完整列表——根据上述条件条件性地应用）：**

1. **封面**——品牌名称、标语、英雄情绪图像。全出血。
2. **策略与定位**——方向名称。定位声明（一句响亮的句子）。目标受众系统：主要细分市场、次要细分市场，以及主要细分市场中的一个生动锚定角色。不要只描述一个过于具体的客户。3-4个参考品牌，带有“借鉴这个”注释。
3. **品牌基础**——使命。品牌价值观（3-5个）。这个“为什么存在”的故事（2-3段真实的品牌声音副本——不是模板）。
4. **标志**——主要标志+所有变体（水平、仅图标、反转），使用规则（在暗色/亮色/彩色上），标志解释，清晰空间规则。
5. **标志禁忌**——明确显示CSS中的误用：永远不要拉伸，永远不要旋转，永远不要错误背景，永远不要重新着色，永远不要使用阴影。使用✗标签视觉显示每个违规行为。
6. **颜色**——所有色板带有十六进制+RGB+CMYK，主要配对，无障碍/对比度注释，永远不要做的组合。全出血色列，不是漂浮在白色上的色板。
7. **字体**——完整层次结构（H1到标题，带有确切的px尺寸），显示/强调/正文字体，每个上下文的使用规则，颜色背景上的文本，最小尺寸。
8. **图标** *(仅限数字品牌——产品、时尚、餐厅、服务品牌跳过)*——UI图标系统：8-12个基本图标（箭头右、对勾、关闭、加号、设置、搜索、用户、铃铛、菜单、信息等）以品牌的几何风格渲染+笔划/角落/网格规则+图标库推荐，用于该集合之外的图标。参见 `references/brand-guidelines.md` “图标页面——结构和规则”部分。
9. **声音与语气**——语气形容词，按上下文（标题、正文、按钮、错误状态、社交标题）提供的副本示例，禁止的单词/短语。显示实际品牌副本，而不是通用示例副本。
10. **图像规则**——根据品牌的媒介进行调整。**以摄影为主导** → 摄影规则（主题/光线/颜色/阴影/纹理/禁忌+1个示例照片）。**以插画为主导** → 插画规则（风格/颜色/线条/角色/构图/禁忌+1个示例插画）。**混合**（两者平等）→ 分为两页，指南变为16页。参见 `references/brand-guidelines.md` “图像规则页面——根据品牌调整”。
11. **视觉世界**——4列全出血网格的4张图像，匹配品牌的媒介混合（所有照片、所有插画或混合）。必须种族多元化，对于任何包含人物图像，必须具有代表性。
12. **触点——真实照片**——一个2×2网格的4张真实生成的照片，显示品牌在物理环境中的使用情况。**根据品牌类型调整：**
    - **实体产品品牌**：服装上的挂牌，编织标签宏观，牛皮纸邮件带组织，产品+包装的平面布置
    - **数字/应用程序品牌**：手持电话显示应用程序，书桌上显示网站，水瓶上的贴纸，真实场景中的托特包
    - **服务品牌**：手拿名片，书桌上放品牌笔记本，建筑物上的标志，环境中放赠品
    在这一页上不要有CSS矢量模型——如果没有真实生成的照片，触点看起来像是一个Figma练习，而不是一个品牌。真实图像证明了品牌可以与物理世界接触。

**以 PDF 格式交付。** 保存至 `~/Desktop/[品牌名称]-品牌指南.pdf` 并告知用户本地路径。除非用户明确要求上传或托管 PDF，否则不要上传或托管 PDF。如果用户不在 Mac 上，则保存到项目工作目录并在回复中提及路径。

### 第 4 步 — 导出品牌工具包（硬性门槛 — 仅在用户明确批准指南后）

在交付 14-16 页的指南 PDF 后，**等待用户明确批准**后再导出品牌工具包。不要自动导出 — 工具包编码了最终品牌，因此只有在品牌确定后才能构建它。例外：在完全自主模式下，单个清晰的简报已经授权了完整交付集，因此指南通过 QA 后导出 `brand-kit.zip`。

然后构建一个全面的品牌工具包 zip，让用户可以在任何地方制作符合品牌要求的工作 — 在 Claude、GPT、Figma 中，与设计师一起，与开发者一起。

**要导出的颜色变体**（每个标志）：主要色在浅色背景上、主要色在深色背景上、中性色在浅色背景上（墨水）、中性色在深色背景上（奶油色），以及一种强调色组合。通常每个标志类型有 4-5 个颜色集。

**brand.md** — 请参阅 `references/brand-md-template.md` 获取完整结构。它必须包括：
- 快速参考块（名称、标语、主要颜色、字体、声音在一个可扫描的部分）
- 定位 + 目标受众细分
- 使命、价值观、故事
- 声音和语气（形容词、按上下文提供的文案示例、禁止的词语）
- 颜色（带有十六进制 / RGB / CMYK /潘通/角色的表格）
- 字体（展示 + 正文 + Google Fonts URL + 完整层次结构）
- 标志（wordmark 描述 + symbol 描述 + lockup 规格 + 带路径的文件列表）
- 摄影规则
- 视觉世界描述
- 触点规格
- 要做和不要做的事情列表
- 借鉴品牌（带有“借鉴这个”的注释）
- 告知下游工具/人员如何应用规范的指南部分

**标志资产管道：**
1. **Symbol 资产** — symbol 是一个生成的光栅标志，因此只导出 PNG。从批准的 2048x2048 透明主文件开始，验证真实透明度，然后为每个需要的颜色/背景变体生成 `16/32/64/128/256/512/1024/2048` PNG。**不要**将其描摹为 SVG，**不要**声称它是矢量。
2. **Wordmark 资产** — 将品牌名称渲染为实际字体文本，然后将选择的字体文本转换为轮廓路径以生成 `wordmark-[颜色].svg`；还导出 1024 宽的透明 PNG 备用。wordmark 是可重复的，因为它是一种排版，而不是图像生成工件。
3. **Lockup 资产** — 将批准的 symbol PNG 与轮廓化的 wordmark 组合在锁定尺寸下。导出 `lockup-[方向]-[颜色].svg`，将 PNG 嵌入内联，wordmark 作为路径，并提供 1024 宽的 PNG 备用。保持颜色变体之间的几何形状相同。
4. **可选打印 PDF** — 仅当用户或打印机明确要求时才添加 PDF。PDF 可能嵌入光栅 symbol 和矢量 wordmark，但它不是一个纯矢量标志文件。
5. **Icon SVGs** — 仅限数字品牌，将图标集作为具有 `stroke="currentColor"`、`viewBox="0 0 24 24"` 和品牌选择的笔触重量 + 角样式一致应用的独立 SVG 编写。请参阅 `references/brand-guidelines.md` “Icons Page — Structure & Rules” 以了解要包含哪些图标。
6. **设计令牌** — 从品牌规范生成所有三个文件：
    - `tokens.css` — `:root` 块，包含 `--color-*`、`--font-*`、`--font-size-*`、`--line-height-*`、`--space-*`、`--radius-*`、`--shadow-*` 自定义属性
    - `tokens.json` — 与 JSON 对象相同的内容，分为：`color`、`font`、`fontSize`、`lineHeight`、`spacing`、`radius`、`shadow` 部分
    - `tailwind.config.snippet.js` — 粘贴到 `module.exports.theme.extend` 内部的 JavaScript 段落，涵盖颜色、fontFamily、fontSize、borderRadius、boxShadow
7. **AI 提示** — 使用品牌特定信息插值生成每个提示文件：
    - `system-prompt.md` — 一个系统提示，粘贴到任何 Claude/GPT 线程的顶部。包括：品牌声音形容词、禁止的词语、文案规则、摄影方向、颜色/字体规格、样本声音示例。以“除非明确指示否则始终应用此品牌声音”结束。
    - `tweet.md` — 任务启动器：最大 280 字符，声音约束，样本目标推文，然后是“任务：[用户填写]”
    - `landing-hero.md` — 任务启动器：英雄文案结构（标题 + 副标题 + CTA），品牌声音规则，来自指南的示例
    - `email.md` — 任务启动器：电子邮件语气、主题行指导、正文结构、署名惯例
    - `error-message.md` — 任务启动器：品牌如何处理错误/空/加载状态的声音（温暖而不是机器人，具体而不是模糊）
    - **`photography.md`** — 任务启动器，用于生成品牌风格的摄影（gpt-image-2 等）。必须包括：针对品牌摄影方向的定制主提示模板（主题、光线、色彩等级、投射多样性、纹理）；明确的“提示中要避免的内容”列表（工作室闪光灯、库存术语、玻璃合作空间、“工程师在笔记本电脑上”、“专业”、“高端”等）；禁止的陈词滥调概念列表（沙漏、灯泡、握手、网络节点、发光的大脑等）；主题替代“做 X 的人”；质量要求（黄油强调、多样性、胶片颗粒、纪录片）；明确的无文本防护措施字符串；注意永远不要命名真实出版物。
    - **`illustration.md`** — 仅当品牌使用插图作为媒介时。任务启动器，用于生成品牌风格的插图。具有严格调色板 + 风格规则的模板（平面矢量/线艺术/等），禁止的元素（渐变、阴影、3D、摄影纹理），何时使用插图而不是摄影。如果品牌在其视觉世界中没有任何插图，请完全跳过此文件。
8. **品牌字体** — 本地导出步骤。从 Google Fonts（或品牌字体所在的任何地方）下载实际字体文件，并将其包含在 `fonts/` 中：
    - 可用时，变量字体文件：`[FontName]-Variable.ttf`（单个文件，支持所有权重）
    - 或品牌使用的静态权重
    - 使用本地 TTF 在本地渲染 HTML 中通过绝对 `file://` 路径使用
    - 添加 `fonts/README.md`，注明许可证（OFL 是常见的，允许重新分发）+ Google Fonts URL 用于在线安装
9. **品牌指南 PDF** — 将在第 3 步生成的 14-16 页指南 PDF 复制到工具包中作为 `brand-guidelines.pdf`。没有它，工具包是不完整的。
10. **README.md** — 1 页指南，告诉用户：工具包中有什么，如何使用 `brand.md` 与 AI 工具，哪种标志文件用于哪种上下文，在哪里安装字体（本地 TTF 或 Google Fonts URL），如何使用摄影/插图提示。
11. **压缩所有内容**：`zip -r [品牌]-品牌工具包.zip brand.md brand-guidelines.pdf README.md logo/ icons/ fonts/ tokens/ prompts/`

**品牌工具包完成门槛：** 当用户确认导出，或当 `export_kit` 在 `--config` 中设置时，品牌工具包 zip 是必需的交付物。在 zip 存在并包含 `brand.md`、`brand-guidelines.pdf`、README、标志资产、图标、字体、令牌和提示之前，不要将品牌工具包标记为完成。如果任何必需文件无法生成，请停止并使用可恢复的检查点列出缺失的文件，而不是发货部分 zip。

**README.md** — 1 页指南，告诉用户：
- 工具包中有什么
- 如何使用 `brand.md` 与 AI 工具（粘贴到 Claude/GPT 以生成符合品牌要求的工作）
- 哪个标志文件用于哪种上下文（网络 favicons → symbol PNG；印刷材料 → PDF；网络标题 → wordmark SVG；等）
- 字体安装链接（Google Fonts URL 加上本地 TTF 文件名）

**交付：**
- 保存 zip 到 `~/Desktop/[品牌名称]-品牌工具包.zip`，用于本地 Mac 用户。
- 如果环境无法下载字体或写入本地 zip，请不要发送部分工具包。停止并使用可恢复的阻塞检查点，列出完成的工件（本地 PDF 路径、`brand.md`、令牌、标志资产），缺失的文件，以及确切的文件系统/网络阻塞器。
- 仅当用户明确要求时才托管完成的 zip。
- 告知用户完成的 zip 中包含的内容，并链接到 `brand.md`，以便他们可以在不解压的情况下预览。

## 交付后质量门槛

在声明任何交付成功之前，渲染本地预览图像并执行结构化视觉 QA，并带有结构化裁决：

- 快速模式：在交付快速品牌包之前，检查 PNG/JPG 预览或 `quick-brand.pdf` 的接触片。
- 完整模式：在交付本地 PDF 路径之前，检查用于批准指南 PDF 的最终页面 PNG/JPG 预览或接触片。不要在最终 PDF 上运行 analyze_media 作为主要的 QA 路径；页面预览是 QA 工件，因为它们暴露了页面级布局并避免了大型 PDF 光栅化失败。

```
仅返回 JSON：{
  "verdict": "clean" | "degraded" | "catastrophic",
  "observations": string[],
  "quality_warning": string | null,
  "re_roll_suggestion": string | null
}
检查品牌名称是否拼写一致，`quick-brand.pdf` 或指南 PDF 预览是否显示所需页面，是否存在低对比度文本，wordmark/symbol 是否未损坏，以及是否存在空白或看起来重复的页面。
```

- 如果 `verdict` 是 `clean`，则正常返回快速品牌包或本地 PDF 路径。
- 如果 `verdict` 是 `degraded`，则返回快速品牌包或本地 PDF 路径加上 `quality_warning`，以便用户在发布前查看。
- 如果 `verdict` 是 `catastrophic`，则不要将牌组标记为完成；表面 `verdict` 和 `re_roll_suggestion` 而不是声明成功。

## 关键原则

- **输入是简报。** 不要要求漫长的摄入表格。阅读你面前的东西，并提出 3-5 个精确的问题。
- **关于客户要具体，但不要将品牌缩小到一个人。** 模糊的受众 = 弱品牌，但一个高度特定的个人可以使输出变得无法使用。首先定义受众细分：主要细分、1-2 个次要细分，以及一个使主要细分具体化的锚定角色。
- **主要全模式选择点有 3 个板。** 第 2 步始终提供三个视觉品牌板，而不是纯文本指示或模板重新着色。
- **有主见但协作。** 自信地展示你的理解。他们可以反对。
- 生成实际文案 — 不要给带有 [括号] 的模板。用品牌声音写真实文字。
- **所有图像必须看起来真实且精心制作。** 生成的生活方式/触点图像需要胶片颗粒、自然光线、轻微瑕疵、编辑构图。禁止：完美对称、渐变背景、工作室闪光灯、库存照片能量、AI 光滑表面、白色上的漂浮物体。如果它看起来很假，请使用上述图像重试预算；不要在限制重试后继续重新生成。
- **每个选择的深度只有一个交付物集。** 快速模式交付快速品牌包。交互式全模式交付一个品牌指南 PDF，用户确认指南后可选品牌工具包。完全自主模式发送所有三个完整工件：品牌板、指南和品牌工具包。

## 品牌质量标准

此技能生产的每个品牌都应符合以下标准。通用输出是失败状态，因为交付物旨在指导实际设计决策，而不是装饰模板。

### 反通用测试

在交付任何东西之前，问：*这个品牌可以是任何其他品牌的品牌吗？* 如果是 — 它还没有完成。

强大的品牌 = 具体的产品/服务 + 明确的受众模型 + 具体的观点。薄弱的品牌 = 感觉 + 美学情绪板 + 空白标语。永远不要交付第二个。

### 文案标准

**好的品牌文案听起来像什么：**
- 它做出具体声明：“重型羊毛。为十年而制。” / “为一天的一个安静小时而设计。”
- 它有一个观点：“不是趋势导向的。不是大规模制造的。”
- 它可以具体地对某个细分市场的读者说话：“你检查手机之前使用的应用程序。” 这是一种文案风格，不是受众策略；不要将品牌的受众模型缩小到只有那个读者。
- 它制造紧张感或对比：“手工制作。被过度使用。故意。”
- 它信任读者：不要过度解释，不要“适合任何场合”，不要“温馨的氛围”

**坏的品牌文案听起来像什么：**
- “用爱制作” / “用心制作” / “用激情设计”
- “适合任何场合” / “永恒的补充”
- “你能感受到的质量” / “设计以启发”
- 通用标语：“品质与风格相遇” / “穿着你的故事”
- 空虚的超级形容词：“高端”、“奢侈”、“提升”、“精选”、“手工艺”

**标语测试：** 一个伟大的标语只属于这个品牌。“手工制作。被过度使用。故意。” 是 WORN 的。 “Just do it.” 是 Nike 的。如果你的标语可以出现在任何随机的 Etsy 商店或 Squarespace 网站上而无人注意 — 重新编写它。

### 设计标准

**什么是编辑品牌设计：**
- 强大的字体层级——一件事情是明显最重要的
- 坚定的色彩使用——大面积的色块，不是点缀小点
- 摄影图像延伸至边缘——没有带阴影的浮动图像
- 尺寸对比——一个元素主导，其他元素退让
- 页面感觉是设计的，不是拼凑的
- 间距是故意的，不是默认的填充

**什么是通用品牌设计：**
- 网格中排列大小相等的方框
- 正文与所有其他内容大小相同
- 所有内容居中
- 白色背景和几个彩色方框
- 白色空间中带有圆角的浮动照片
- 字体样本显示“字体名称”或“示例文本”
- 色彩样本看起来像油漆店目录

**布局规则：** 如果一个页面可以在10分钟内用Canva或PowerPoint制作——那就不够好。每一页都应该需要只有有品味的人才会做的设计决策。

### 摄影与多样性标准

包含人物的人物图像集应展示种族多样性。这避免了将每个品牌世界都默认为相同的狭窄角色。
- 在所有4张以上的生活方式图像中默认使用混合角色：包括黑人、亚洲人、拉丁裔、南亚人、中东人或混合种族的模特
- 身材多样，不只是肤色
- 如果只展示一个人，就要故意选择这个人——不要默认为白人/浅色皮肤
- 多样性不是一个复选框。它是一个设计选择，使品牌更具共鸣，更诚实

**摄影必须感觉像是偶然发现的，而不是摆拍的：**
- 真实的房间里有真实的生活（纸张、植物、磨损的家具）
- 不完美的光线（窗户光、阴天、清晨）
- 总是胶片颗粒——即使只有一点点
- 除非是强烈的选择，否则主体不要看着相机

### 幻灯片/指南设计标准

- 字体必须加载。下载实际的字体文件，并在本地渲染HTML中使用绝对`file://`路径。在确认渲染之前始终验证加载的字体。如果字体回退到系统默认值——那么幻灯片是损坏的，不可交付。
- 参考`references/brand-guidelines.md`以获取完整的本地渲染合同和QA规则。
- 每一页都必须有一个清晰的可视层级——首先看一件事情。
- 全出血摄影页面应感觉像杂志版面，而不是幻灯片。
- 色彩调色板页面：全出血色彩列，不是漂浮在白色上的色块。
- 标志页面：标志巨大且清晰，有明确的变体，不是胆怯的或小的。
- 语音页面：显示实际的品牌文案，而不是通用的示例文案。
- 触点页面：必须包含实际触点的生成照片——永远不要CSS方框。

将指南作为一个本地PDF交付，而不是作为单独的页面图像。将PDF路径保存下来，在导出套件时将其复制到品牌套件中。

### 品味检查

在交付任何品牌输出之前，问问自己：
1. 一个有品味的25岁的人会想购买/使用/为这个品牌工作吗？
2. 文案听起来像是一个真实的人写的吗？
3. 设计看起来像是一个真正的设计师做的吗？
4. 照片多样且真实吗？
5. 是否有一个特定的观点——这个品牌代表的东西，其他品牌没有代表？

如果任何答案是“不确定”——在交付之前改进它。强烈和具体比安全和通用更好。

## 承重短语

这些是保持这项技能不滑向通用品牌书输出的锚点：

| 短语 | 位置 | 为什么承重 |
|---|---|---|
| `不同业务答案——不是美学变化` | 第2步视觉板 | 强制在视觉变化之前进行定位变化。 |
| `字体必须有个性` | 第2步视觉板 | 防止安全字体默认使每个品牌都感觉可以互换。 |
| `生成图像上没有承重文本` | 指南构建规则 | 使品牌声明在确定性HTML/PDF中可编辑和清晰。 |
| `胶片颗粒、自然光线、轻微瑕疵` | 图像质量标准 | 将生活方式/触点图像从股票照片的光滑度中推开。 |
| `为每个提示命名一个特定种族` | 多样性角色恢复 | 比通用的多样性语言更可靠地修复模型倾向于全白人角色的趋势。 |

## 引擎选择：gpt-image-2（有保留）

默认使用`gpt-image-2`在`质量："medium"`下为所有品牌图像。为什么：
- 对于角色多样性提示的最佳指令遵循（nano-banana-pro倾向于默认为白色，除非 heavily prompted）。
- 最强的无文本护栏遵守——这对于触点照片（吊牌/编织标签/贴纸）至关重要，其中任何嵌入的文本都会毁掉模型。
- 原生3:4 / 4:3 / 9:16比例在锐利主题上干净地裁剪，没有奇怪的拉伸。

避免使用`nano-banana-pro`——当提示中提到“编辑”时，它会将杂志封面风格的文本烘焙到产品照片中。gpt-image-2的1K对于1200×850 PDF页面足够了；如果特定触点确实需要印刷级分辨率，则提升到gpt-image-2的2K层级（或升级到`seedream`以获得更高）。

## 运行时预期

告诉用户大致的总时间——没有状态更新的长时间阶段会感觉是错误的。始终在PST提供时间戳时报告时间。

### 快速品牌目标

| 阶段 | 目标时间 | 备注 |
|---|---:|---|
| 摄入+假设 | 1-2分钟 | 如果原始输入缺失，则跳过多轮问答 |
| 一个策略+身份 | 2-3分钟 | 选择最强的方向；没有3选项的迂回 |
| 符号/情绪/触点资产 | 3-5分钟 | 总共最多4张生成图像，除非QA失败 |
| 快速PDF+套件文件 | 2-3分钟 | 3页PDF，紧凑的`brand.md`，标记，提示，可用的标志资产 |
| 快速QA+交付 | 1-2分钟 | PNG预览检查；只有在出现阻止问题时才重新渲染 |

快速目标总计：在可用输入后8-12分钟，不包括用户响应时间。

对于每个完整运行，在工 作笔记中维护一个时间清单，并在最终交付或可恢复检查点中包含它。捕获PST时间戳：

- 摄入完成
- 视觉板草稿
- 品牌板渲染开始/完成
- 用户身份选择锁定
- 图像生成批次1开始/完成
- 图像生成批次2开始/完成
- 完整指南渲染开始/完成
- 完整Deck QA开始/完成

如果运行再次花费约2小时，不要猜测时间花在哪里。使用此清单命名实际最慢的阶段，并将证据带到下一次切割。

### 完整品牌书目标

| 阶段 | 时间 | 备注 |
|---|---|---|
| 阶段0→步骤1（问答循环） | 5-15分钟 | 用户控制；一个问题在一条消息中 |
| 步骤2（3张视觉品牌板PDF） | 6-10分钟 | 每张板符号+一张情绪图像+本地Chrome渲染 |

完整目标总计：~25-45分钟墙钟时间，不包括用户响应时间。最近的现场反馈表明，为付费创作者教程录制的一个完整运行花费了约2小时；将此视为要击败的基线症状，而不是可接受的目标。

## 失败模式

### 从上游5xx在generate_image中恢复

如果任何付费生成或渲染MCP调用返回：
- `code: "provider_5xx"` AND `retry_class: "retry_after_backoff"`
- 或来自上游图像提供者的HTTP 502 / 503 / 504

这样做：
1. 等待5秒。
2. 用完全相同的参数重新调用完全相同的MCP工具。不要重写提示，交换字体，改变调色板，改变HTML，改变提供者，或重新生成输入。
3. 如果重试也因5xx失败，中止并面向用户： "提供者两次返回了暂时的上游错误。1-2分钟后重试；这通常会自行清除。"

不要重试超过一次。这是一个暂时的中断，不是品牌方向问题；改变创意简报会浪费积分并使重试更难比较。

### 从上游4xx / moderation_blocked中恢复

如果`generate_image`与`provider="gpt-image-2"`返回上游4xx或`moderation_blocked`：
1. 不要重试相同的提示；审查和大多数4xx验证失败是确定的。
2. 如果失败的资产是生成的符号或生活方式图像，当简报可以承受它时，尝试一次只使用回退提供者：`seedream`用于高分辨率品牌图像，或对于简单的几何符号使用内联SVG标记。
3. 如果回退提供者也失败或会实质性改变品牌方向，面向用户： "图像提供者拒绝了此品牌图像提示。尝试一个不太容易识别的参考，删除真实出版物/名人线索，或批准SVG/简单标记替代方案。"

### 从上游429（速率限制）中恢复

如果任何上游返回带有回退提示的HTTP 429：
1. 等待提示的回退，如果没有提供提示，则等待30秒。
2. 用完全相同的参数重新调用完全相同的MCP工具。
3. 不要重试超过一次。如果它仍然返回429，中止并显示速率限制消息，而不是花费更多调用。

### `capture_website`返回空/页面未加载

这项技能通常从用户答案和提供的资产构建，但URL源参考或未来的摄入辅助程序可能会调用`capture_website`。如果`capture_website`返回200但`action_bboxes`为空或`recording_viewport`为0x0：
1. 不要重试；页面在捕获环境中未能渲染。
2. 面向用户： "无法捕获<url>。页面可能被阻止/付费墙/需要认证。请提供截图、标志或托管资产。"

### 长时间运行的`task_status`超过上限

每个异步MCP调用返回要么是内联结果，要么是`{task_id, status}`用于轮询。使用这些上限在决定任务卡住之前：
- gpt-image-2高质量：每个调用3分钟
- Seedream图像生成：每个调用3分钟

使用较早的值：提供者的上限x1.5或任何技能特定的硬轮询上限。如果`task_status`返回`status: "processing"`或`status: "queued"`超过较早的限制，调用`task_cancel({task_id})`并面向用户： "提供者花费时间异常；中止。重试。"

| 症状 | 原因 | 修复 |
|---|---|---|
| 字体在PDF中渲染为Times / Arial | `@font-face`指向缺失或相对本地路径 | 下载TTF到本地工作空间，使用绝对`file://`路径声明它们，并在生成完整PDF之前渲染一个单页本地预览 |
| 生成的图像有烘焙的杂志标题或水印 | 提示中提到了“杂志封面”、“Vogue”、“TIME”、“Bloomberg”或任何真实出版物 | 从提示中删除出版物名称；附加字面量无文本护栏；在图像重试预算内重新生成一次。描述视觉效果，而不是出版物 |
| 触点/生活方式照片只显示前额/只有手部的裁剪 | 9:16肖像源被裁剪到横向单元 | 用`aspect_ratio: "4:3"`或`"16:9"`重新生成以匹配单元纵横比，或者更改布局为肖像单元 |
| 页面溢出850px上限 | 标题>60px，同一页面上有>3个正文段落 | 删减内容，将标题降至48px，或分成两页。重新渲染并使用截图验证 |
| 板面技术上是合适的，但看起来很丑 | 过多的装饰样式，微型文本太小，模糊的单音调调色板，空的模型或弱的层级 | 重新编写板面文案以适应`brand-identity.md`中的预算，删除装饰性微型类型，将正文文本增加到18px+，增加负空间/对比度，并重新运行PNG+视觉QA |
| 文本重叠图标/色块/印章/模型 | 装饰性或绝对定位的元素与文本共享相同的阅读区域 | 给文本一个干净的阅读列/卡片，只在非文本区域后面移动图形，并重新渲染。如果`scrollHeight`不够，则如果兄弟图形遮挡文本，则不是足够 |
| 品牌板页面感觉像重新上色的模板 | 相同模板重复使用，调色板交换 | 从`references/brand-guidelines.md`“品牌板布局——每个选项区分”重建——每个板的布局必须物理体现其设计理念 |
| 多页合并失败 | `pdfunite`或本地合并工具缺失 | 在一个完整的HTML文档上使用Chrome `--print-to-pdf`，或者回退到Python `pypdf.PdfWriter().append()` |
| 用户选择混合身份（“02的调色板+01的语音”） | 技能假设单选项选择 | 在步骤3之前构建混合规范简报，在渲染14-16页之前确认用户 |
| 用户要求托管PDF，上传失败 | PDF上传路径通常拒绝`application/pdf` | 将本地PDF作为规范；如果需要托管，请使用用户批准的文件主机或部署路径 |
| 生活方式网格尽管多样性角色规则都是白人角色 | gpt-image-2在提示中没有明确命名每个提示的种族时默认为较浅的肤色 | 每个提示命名一个特定种族（黑人、混合种族的东亚和白人、东亚人、拉丁裔、南亚人、中东人）——在4个网格提示中变化 |
