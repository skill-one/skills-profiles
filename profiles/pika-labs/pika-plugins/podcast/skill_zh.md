# /pika:podcast

4幕 × 15秒/幕 = 60秒。主持人A始终在左侧，主持人B始终在右侧。接受URL **或** 自由形式的主题/简报。

## 参数

| 参数 | 默认 | 备注 |
|---|---|---|
| `input` | 必填 | 审核URL **或** 自由形式的主题/简报（例如："我和埃隆·马斯克谈论火星"） |
| `bg_img` | 自动生成 | 播客工作室背景 |
| `host_a_img` | 自动生成 | 主持人A肖像——见真人处理部分 |
| `host_b_img` | 自动生成 | 主持人B肖像——见真人处理部分 |
| `voice_a` | `876341503281471517` | 克林预设或克隆语音ID，用于主持人A |
| `voice_b` | `829837252279803904` | 克林预设或克隆语音ID，用于主持人B |
| `aspect_ratio` | `16:9` | 输出宽高比 |

## 成本透明门

在执行任何付费MCP调用之前，调用一次 `identity_balance({verbose: true})`。显示当前余额、近期消耗率和剩余运行时间，然后使用此确切消息来控制运行：

> 预计成本：大约6,000-9,000信用点（约$60-$90），用于四个克林v3-omni专业15秒的剧本，可选缺失资产图像生成，一个剧本纠正重试，连接和飞行后分析_media QA。这超过了$5，所以回复 `proceed` 继续或 `cancel` 停止。

在用户回复 `proceed` 之前，不要调用任何付费MCP工具。如果用户回复 `cancel`，则不生成。这是唯一的“是/否”门；在 `proceed` 之后，渲染四个剧本并返回URL。

## 默认值——快速启动，不进行流程中确认

- **在声音参数表中无声地使用默认值**。`voice_a` 默认为克林预设 `876341503281471517`，`voice_b` 默认为 `829837252279803904`。在启动之前**不要**询问“哪个声音？”——仅尊重显式覆盖（`voice_a=`, `voice_b=`）。
- **无声地自动生成任何缺失的主持人肖像**（步骤1的原始类型提示）。在启动之前**不要**询问“我应该生成主持人图像吗？”——直接生成。
- **只有成本透明门会询问 `proceed`**。在 `proceed` 之后，提交 → 渲染四个剧本 → 返回URL。账户信用余额 + 提供商故障转移是标准的保护措施。`--yes` 标志被接受为向后兼容的无操作。
- **主题模式角色（步骤3）**——当用户命名一个真实的公众人物时，无声地遵循步骤4（真人处理）：默认使用原始类型肖像，不自动生成照片肖像，不向用户询问肖像权。

## 生成前时钟保护墙

在播客输入解析并通过成本门后，在技能启动时启动计时器。第一个付费生成调用是 `generate_image`，用于缺失的背景/主持人资产。如果所有资产都已提供，则第一个付费生成调用是 `generate_reference_video`。第一个付费生成调用必须在技能启动后的5分钟内调用。如果在技能启动后的5分钟内未调用第一个付费生成调用，则在任何付费生成调用之前停止，并报告 `failed_pre_generation_timeout` 以及到目前为止的状态：输入模式、资产状态、声音状态、URL捕获/WebFetch状态、脚本草稿状态和确切障碍。不要继续改进主持人原始类型、事实基础、笑话或剧本措辞。

在每次准备阶段之后，在付费生成调用之前打印单行进度检查点：
- `Stage 1/4 done — input resolved and cost gate passed, locking missing-asset image prompts.`
- `Stage 2/4 done — missing asset prompts ready, calling image generation now.` 在缺少任何背景或主持人图像时，使用此内容在第一个付费 `generate_image` 调用之前。如果所有图像都已提供，则发出 `Stage 2/4 done — assets and voices ready, collecting URL/topic facts.` 代替，然后继续而无需图像生成。
- `Stage 3/4 done — script draft locked, preparing first act.`
- `Stage 4/4 done — first act prompt ready, calling Kling now.`

缺失资产图像提示迭代最多2次，在第一次 `generate_image` 调用之前。在最多2次迭代后，将您拥有的内容发送到 `generate_image`；不要继续完善主持人原始类型、工作室背景细节或角色样式。脚本和剧本提示迭代最多2次，在克林之前。在最多2次迭代后，将您拥有的内容发送到 `generate_reference_video`；不要继续完善笑话、中断、角色框架或摄像机措辞。

## 局部图像在Claude桌面版

Claude桌面版目前无法将内联粘贴的图像传递给MCP工具（Anthropic方面的限制）。如果用户内联粘贴了一张照片，或者提到了他们想要作为 `host_a_img` / `host_b_img` 的本地文件，请暂停步骤1，并友好地发送给他们一些东西——例如：

> 注意——粘贴的图像目前无法到达Claude桌面版的MCP工具（Anthropic限制）。对于您的照片，有两个简单的选项：
>
> - 如果它已经在托管（Imgur、S3、您的网站），请粘贴URL——最快
> - 将图像文件附加给我，以便我在生成之前上传它。

当本地文件到达时，使用 `upload_asset` 将其转换为公共URL，并使用返回的 `public_url` 作为步骤1之前的参数。已托管的 `https://...` URL按原样工作，并跳过此整个过程。

如果用户命名了一个真实的公众人物而没有附加任何内容，则**不要**自动生成他们的肖像——步骤4（真人处理）使用原始类型肖像。

## 长任务 `task_status` 投票

当任何长时间运行的生成或编辑调用返回带有或没有初始状态的 `task_id`，包括 `{task_id}`、`{task_id, status: "queued"}` 或初始 `queued`、`running` 或 `processing` 状态时，立即记录任务ID和启动时间。

- 在 `task_status({task_id})` 中以紧密循环调用，直到终端（`completed | failed | cancelled`）。不要手动睡眠，也不要使用Bash轮询；工作进程会保持每个状态调用打开。
- 在状态为 `queued`、`running` 或 `processing` 时，每60秒发出一条可见的进度行：`Seedance i2v queued for {N}m {S}s... still processing`。在轮询克林、图像生成、克隆语音或连接任务时，替换提供商/阶段标签。
- 在 `completed` 时，解包返回的结果URL并继续。
- 在 `failed` 或 `cancelled` 时，向用户显示失败，包括 `task_id`、状态和最后的状态消息。
- 在原始提交后的15分钟内，如果任务仍然非终端，调用 `task_cancel({task_id})`，然后向用户显示失败。如果取消报告任务已经终端，再次调用状态一次并报告终端结果。
- 在原始任务仍然是 `queued`、`running` 或 `processing` 时，不要提交重复请求。

## 步骤

### 0. 解析输入（空参数菜单）

从 `$ARGUMENTS` 中删除标志（`--yes`、`--no-captions` 等）和 `key=value` 参数。**如果剩余内容为空或仅包含空白**，请打印此菜单**原文**作为您的完整响应，然后**停止并等待用户的下一条消息**——不要调用任何工具，不要进入步骤1，不要编造主题或URL。如果剥离的输入非空（URL或任何文本），则无声地跳过此步骤并进入步骤1。

> **您想播客讨论什么？** 我可以接受任何：
>
> - **网站URL**（产品页面、文档网站、发布页面）——例如 `https://pika.art`
> - **GitHub存储库** —— 例如 `https://github.com/anthropics/claude-code`
> - **博客文章/文章URL** —— 例如您想要讨论的最新文章
> - **自由形式的主题或简报** —— 例如 *"我和埃隆·马斯克谈论火星"* 或 *"两位科学家辩论AGI"* *
>
> 回复您的选择，我将生成一个1分钟的两位主持人播客视频（4幕 × 约15秒）。
>
> *提示：您不需要输入 `/pika:podcast` —— 只要说诸如 "制作关于 <主题> 的播客"、"播客评论 <URL>" 或 "我和 <人物> 谈论 <主题>"，我会自动启动此技能。*

当用户回复时，将他们的回复视为解析后的输入（URL或主题），并进入步骤1。不要重新提示。

### 1. 生成缺失资产（并行）

仅生成未提供的资产。默认原始类型提示：
- `bg_img` — 现代播客工作室，两把椅子，温暖的光线，无人，16:9
- `host_a_img` — 热情主持人，工作室肖像，左侧构图，1:1
- `host_b_img` — 实用怀疑主持人，工作室肖像，右侧构图，1:1

如果输入提到了特定人物（步骤3），请调整原始类型以匹配人物氛围——见真人处理部分。

### 2. 解析声音ID

使用 `voice_a` / `voice_b` 作为给定值；否则回退到默认克林预设（`876341503281471517` / `829837252279803904`）。如果用户通过 `voice_a=` / `voice_b=` 提供了克隆语音ID，则直接使用它。

### 3. 解析输入模式——URL与主题

从 `$ARGUMENTS` 中删除标志（`--yes`、`--no-captions` 等）和 `key=value` 参数。检查剩余内容。

**URL模式**——输入包含 `https?://` URL：
- 调用 `capture_website` 在URL上仅用于视觉定位：产品/页面名称、可见布局、截图、B-roll提示，以及一个可幽默的视觉细节。
- 调用 `WebFetch` 在同一URL上，并使用其完整页面文本作为脚本来源的真相。不要仅依赖截图来获取事实。
- 从组合输入中提取：产品名称、价值主张、2-3个具体功能或事实、定价、一个可幽默的细节，以及任何具体的引言或声明。
- 对于长文档（维基百科、文档、博客文章或文章），扫描 `WebFetch` 完整页面文本以查找引言之外的深度部分。当至少有3个实质性深度部分存在时，脚本必须至少提及引言之外3个不同的部分（例如架构、训练、幻觉、限制、部署或安全），而不仅仅是开头的摘要。
- 使用WebFetch文本作为事实锚点，使用 `capture_website` 作为视觉效果。如果它们冲突，则优先考虑WebFetch作为事实声明，并将截图视为视觉参考。

**主题模式**——输入为自由形式文本（无URL）：
- 将整个输入视为简报。解析以查找：
  - **主题**——对话的内容
  - **主持人**——明确提及（例如："我和埃隆·马斯克"、"两位科学家"、"乔和莎拉"；否则使用默认值（热情主持人 + 怀疑主持人）
  - **角度**——辩论/采访/解释/休闲
  - **具体事实**——用户给出的任何具体声明、数字、日期、引言
- 如果没有给出具体事实，则使用 **2-3个清晰构建的观察或假设** 来锚定笑话和 "等等..." 的怀疑性转折。不要将编造的声明作为事实；如果主题需要事实准确性，请要求来源或URL。
- 如果用户说 "我和X" 或 "我和X"，主持人A = 用户（如果提供了 `host_a_img=`，则使用生成的主持人肖像；否则生成主持人肖像），主持人B = X。

### 4. 真人处理（主题模式仅限）

如果解析的输入命名了一个特定的真实公众人物作为主持人（例如："埃隆·马斯克"、"泰勒·斯威夫特"、"乔·罗根")：

- **默认行为**：**不要**自动生成该人物的肖像。生成匹配角色氛围的**原始类型肖像**——例如："科技亿万富翁能源CEO在播客桌前" 用于埃隆风格的主持人，"流行音乐偶像美学" 用于泰勒风格的主持人。灵感来源，而不是模仿。
- **覆盖**：如果用户明确提供 `host_a_img=<url>` 或 `host_b_img=<url>`，则按原样使用提供的图像。用户对肖像权负责。
- **声音**：相同逻辑——默认使用通用克林预设；仅在用户提供时使用克隆语音（`voice_a=` / `voice_b=`）。
- **脚本语气**：对话可以基于命名人物的已知公共立场或氛围（例如埃隆风格的火星热情）——公共记录意见是可以接受的。**不要**将具体的诽谤性、角色外或编造的私人生活声明放在他们口中。

此保护措施使技能具有创造性（"我想制作一个播客，在那里我和一位科技CEO争论火星"），而不会自动生成命名真实人物的深度伪造。

### CJK/非拉丁处理

在URL、主题、产品名称、主持人名称、引言或所需脚本细节包含中文、日文、韩文、阿拉伯文、天城文、西里尔文、带重音的拉丁文、表情符号或任何其他非拉丁文本时，使用此部分。

- **脚本保留**：在脚本状态和任何事实回顾中精确保留用户提供的非拉丁字符。不要罗马化、转写或翻译产品名称、人名、口号或引用短语，除非用户明确要求。如果发音辅助有用，请将其放在附近的英文文本中，而不是用其替换原始字符。
- **克林语音ID**：`voice_a=` 和 `voice_b=` 必须是有效的克林语音ID。对于中文/日文/韩文对话，优先使用已知会说该语言的克林语音ID或克隆语音样本；如果没有匹配语言的克林语音可用，则保留原始字符在对话中，并显示发音可能带有口音，而不是无声地切换到无关的TTS提供者。
- **混合语言对话**：保持每个主持人的行简短且无歧义。避免要求克林朗读长混合语言段落；将复杂名称或引言跨幕分割，并保持周围的英文简单。
- **字幕/字体回退**：此技能默认跳过 `add_captions`，因为播客对话中的专业术语（产品名称、人物名称、技术术语）的自动转录不可靠。如果用户明确要求字幕，请传递来自授权脚本的 `subtitles[]` 而不是自动转录；对于CJK/非拉丁文本，请遵循上述字体和保留指导。
- **QA**：在交付之前，在最终结论中包含一条单行注释，说明是否在脚本中保留了原始字符，以及所选声音是否与语言匹配或最佳尝试。

## 飞行后质量门

在声明成功之前，调用 `analyze_media` 在最终视频URL上，并要求结构化结论：

```
仅返回JSON：{
  "verdict": "clean" | "degraded" | "catastrophic",
  "observations": string[],
  "quality_warning": string | null,
  "re_roll_suggestion": string | null
}
检查主持人A是否保持在左侧，主持人B是否保持在右侧，产品名称/人物名称/主题特定术语是否明显损坏，四个剧本播客结构是否存在，以及是否存在黑帧或错误的主持人镜头。
还要检查语音，而不仅仅是字幕或可见文本：产品名称、人物名称、主题特定术语、编造的术语和术语必须清晰可辨。标记损坏或发音错误的原生音频，例如 "stablecoins" 听起来像 "stable kinds"，"unbundle" 听起来像 "un-bumble" 或 "unbundable"，或 "reassure" 失去音节。

- 如果 `verdict` 是 `clean`，首先检查脚本状态是否包含已知的困难语音。对于已知的困难术语，在接受干净的结论之前，运行已知的困难可发布回退及其预替换和后替换 `transcribe_audio` / `analyze_media` 检查。只有在替换的MP4检查通过后，才返回最终URL和一句话结论。
- 如果 `verdict` 是 `degraded` 对于普通的非阻塞视觉问题，返回最终URL加上 `quality_warning`，以便用户在发布前可以查看。
- 如果 `verdict` 是 `degraded` 因为语音损坏了术语，则将其视为不可发布，而不是无声成功。对于已知的困难术语或观察到的困难术语漂移，跳过原生音频剧本纠正；不要在Kling原生音频提示预算上花费目标剧本纠正。直接使用已知的困难回退：调用 `generate_speech(text=<spoken-only script>, provider: "minimax-tts", minimax_model: "speech-2.8-hd")`，在TTS音频上运行预替换 `transcribe_audio` 和 `analyze_media`，然后调用 `edit_audio_replace(video_url=<final_mp4>, audio_url=<tts_audio_url>, duration_policy: "video")` 以丢弃原生音频并替换最终MP4音频。在替换的MP4上运行后 `transcribe_audio` 和 `analyze_media`。如果那些检查通过，则返回替换的URL；如果回退检查仍然报告语音术语损坏，或者损坏不够精确以纠正或替换，则不要调用播客完成；返回URL与 `not publish-ready`、受影响的术语和 `quality_warning`。
- 如果 `verdict` 是 `catastrophic`，仅在观察结果或 `re_roll_suggestion` 将问题定位到单个不良剧本、错误主持人镜头、黑帧或局部化视觉/音频故障时，才花费一个目标剧本纠正预算。克林v3-omni没有种子，并且相同的剧本负载可能会解析为相同的作业/资产。不要提交相同的克林负载。在重试之前，通过调整脚本行、拍摄提示、参考图像、语音ID或其他阶段特定输入来实质性更改不良剧本负载。提交一个纠正剧本，使用 `quality_mode: "pro"`，重新连接四个剧本，并再次运行此 analyze_media 检查。不要超过成本门范围：如果第二次结论仍然是 `catastrophic`，或者故障不可归因于一个剧本，不要调用播客完成；表面结论和 `re_roll_suggestion` 而不是声明成功。

---

**规则：**
- `voice_ids` 必须是有效的克林语音ID——永远不要使用名称样式字符串，如 `Calm_Man`
- 主持人A始终在左侧 (`<<<image_2>>>`)，主持人B始终在右侧 (`<<<image_3>>>`)——永远不交换

## 承重短语

这些锚点使播客输出在URL和主题模式之间保持一致：

| 短语 | 位置 | 为什么承重 |
|---|---|---|
| `Host A always LEFT, Host B always RIGHT` | 布局和拍摄提示 | 防止在四个单独的剧本渲染中主持人身份交换。 |
| `4 acts × 15s each` | 整体结构 | 保持连接可预测，避免不均匀的剧本节奏。 |
| `Hook → Feature deep-dive → The Turn → Verdict` | 脚本结构 | 给节目一个对话弧线，而不是四个断开的反应。 |
| `wait, actually...` 怀疑性转折时刻 | 脚本要求 | 创建使播客感觉像真实交流的转折点。 |
| `Do not call add_captions` | 输出规则 | 默认情况下避免低质量的烧录字幕；明确要求字幕时使用手动 `subtitles[]` 并使用字体回退，而不是自动转录。 |

## 引擎选择：Kling v3-omni 用于原生双主持人对话

使用Kling v3-omni来生成四个剧本，因为它支持原生对话，具有两个参考主持人和语音标记在一个单个拍摄计划中。权衡是剧本运行按顺序进行以确保一致性，并且可能比纯编辑/合成流程花费更长的时间。默认情况下不要添加单独的标题或音乐层；此技能的价值在于原生语音交换。

## 运行时预期

典型时钟时间约为24-32分钟，用于完整的4幕渲染：~25分钟实际，~32分钟P95。
四个剧本通过Kling Omni按顺序运行；这是主要的运行时间，不应将其描述为并行工作。
如果用户或执行框架具有紧张的预算低于32分钟，请提前警告可能无法完成完整渲染，并提供2幕/30秒回退。否则保持正常的无确认流程。

| 步骤 | 时钟时间 | 备注 |
|---|---:|---|
| 缺失资产生成 | 30-90秒 | 为提供的背景/主持人引用跳过 |
| URL/主题解析 + 脚本 | 1-3分钟 | URL模式取决于页面获取质量 |
| 四个Kling剧本 | 24-32分钟 | 4 × ~8分钟顺序Kling Omni调用；主要成本 |
| 连接 + 返回 | 30-90秒 | 仅返回最终URL；默认跳过字幕 |

## 失败模式

### 从上游5xx恢复 on capture_website / clone_voice / generate_video / edit_concat

如果任何MCP调用返回：
- `code: "provider_5xx"` AND `retry_class: "retry_after_backoff"`
- 或来自任何上游提供者的HTTP 502 / 503 / 504（克林、语音克隆、捕获、存储）

执行以下操作：
1. 等待5秒。
2. 重新调用完全相同的MCP工具，使用完全相同的参数。不要重写脚本，更改声音，更改主持人引用，更改剧本顺序，或重新提交不同的提示。
3. 如果重试也失败并返回5xx，中止并向用户显示："提供者返回了两次瞬态上游错误。1-2分钟后重试；这通常会自行清除。"

不要重试超过一次。5xx是一个瞬态中断，不是播客主题、声音或脚本错误的证据。

### 从上游4xx / moderation_blocked恢复

如果在上游4xx或 `moderation_blocked` 发生在可选的 `generate_image` 辅助程序、主持人资产或Kling剧本上：

1. 不要重试相同的输入；审查和大多数4xx验证失败是确定的。
2. 如果为该阶段提供了明确的备用提供者，则仅使用备用提供者。对于默认的克林v3-omni双主持人剧本路径，没有等效的备用提供者；不要用无关的标题或单语音TTS伪造播客。
3. 向用户显示："提供者拒绝了此播客输入。尝试使用不同的主持人引用、不太容易识别的公众人物/品牌措辞或更安全的主题角度。"

### 从上游429（速率限制）恢复

如果任何上游返回带有回退提示的HTTP 429：

1. 等待提示的回退，如果没有提示则等待30秒。
2. 重新调用完全相同的MCP工具，使用完全相同的参数。
3. 不要重试超过一次。如果它仍然返回429，中止并显示速率限制消息。

### `capture_website` 返回空 / 页面未加载

如果URL模式调用 `capture_website` 并返回200但 `action_bboxes` 为空或 `recording_viewport` 为 0x0：

1. 不要重试 `capture_website`；页面在捕获环境中未能加载。
2. 如果 `WebFetch` 返回可用的完整页面文本，则继续而无需重试 `capture_website`：使用WebFetch作为事实锚点，并使用通用视觉或生成的视觉代替，而不是假装损坏的捕获包含页面细节。
3. 如果捕获和WebFetch都未能提供可用的源材料，向用户显示："无法捕获 <url>。页面可能被阻止/付费墙/需要身份验证。请提供文本简报或粘贴源材料。"

如果捕获的页面明显仅包含折叠导航，则仅当 `WebFetch` 返回足够的完整页面文本以锚定脚本时继续；在这种情况下，使用捕获用于视觉效果，使用WebFetch用于事实。如果捕获和WebFetch都未能提供可用的源材料，则要求粘贴源材料，而不是幻觉深层页面细节。

### `upload_asset` 网络 / 身份验证失败

如果 `upload_asset` 在将本地主持人引用、语音样本或源媒体转换为托管URL时失败，不要继续使用本地文件系统路径。仅对5xx或429类别进行一次重试。对于 `auth_error`、不支持的MIME、网络故障或重复上传失败，要求提供托管URL或支持替换文件。

### 长任务 `task_status` 超过上限

每个异步MCP调用返回要么是内联结果，要么是 `{task_id, status}` 用于轮询。使用以下上限在使用这些上限之前决定任务是否卡住：
- Kling Omni剧本：每个调用15分钟
- 语音克隆：每个调用5分钟
- 编辑/连接：每个调用5分钟

使用其中较早者：提供商的上限x1.5或任何技能特定的硬轮询上限，包括上述Long-running `task_status` 轮询合同中提到的15分钟总上限。如果 `task_status` 返回 `status: "processing"` 或 `status: "queued"` 过了更早的限制，调用 `task_cancel({task_id})` 并向用户显示："提供者处理时间异常；中止。重试。"
