# Swarm

Swarm 暴露一个可选的工厂端口：

```text
dispatch_once(explicit_disjoint_packets, executor)
  -> per-packet candidate | evidence | error
```

调用者提供每个完整的包，证明它们的写范围不相交，并选择执行器。Swarm 一次性派发每个包，保留包和上下文身份，收集结果，然后停止。

写范围必须是 **相对于工作区且规范的** — 符号链接解析并已归一化。不相交性检查是词法的：它会将前缀进行小写转换，因此仅大小写不同的范围被视为冲突（在大小写不敏感的文件系统中是安全的），但它无法看到将两个范围别名到一个目标的符号链接。提供非规范或符号链接的范围会放弃不相交性保证；非空的 `write_scope.exclude` 会被拒绝，而不是被静默忽略，因为证明无法尊重它。

在已证明不相交的范围上的精确一次派发是并行失败保持独立的原因：没有包可以观察、阻塞或损坏另一个包，因此 N 个包会产生关于 N 个实验的 N 个事实性结果，而不是一个混乱。这些结果不是语义性裁决。

命名故障模式 — **部分批次启动**：在发现一个无效包之前派发有效包，导致批次半运行；在第一次调用之前验证整个批次。

反模式：重新派发执行器返回错误的包。纠正方法：将错误作为该包的事实性结果返回；重试是调用者的决定，而不是派发器的决定。

仅供开发者参考的实现是 [`scripts/dispatch_once.py`](scripts/dispatch_once.py)。仓库测试练习这个模块；支持的本地安装路径跟随调用者选择的执行器，不会调用 Python。它在第一次调用之前验证整个显式批次，为每个包精确调用一次提供的执行器，并将执行器异常作为每个包的事实性错误返回。

Swarm 的作用是针对每个包调用选定的执行器一次；真正的破坏范围取决于包。每个包的传递性效果 — 无论其执行器写入、运行或访问的内容 — 都是由调用者在包上声明的，而不是 Swarm 的限制。

Swarm 不选择工作、创建包、从后备任务中调度、持久化队列、声明所有权、重试、验证、集成、关闭、使用 Git 或交付。执行器故障仍然是执行器证据，不能成为核心阶段或裁决状态。适配器不能选择 AgentOps 语义、发布绑定裁决或将工厂完成转换为交付或验证证明。
