# 状态

当每一条信息都能追溯到当前磁盘上存在的工件时，状态快照才是可靠的；第一条推断出的信息会将报告变成一件穿着报告外衣的猜测。

## 提示

```text
显示 fleet-router 的 AgentOps 状态（ao 已安装）。仅报告可观察的 .agents/ao 证据：意图和判定计数、证据时效性，以及任何损坏或不可用的来源。明确披露已检查和未检查的内容。
```

## 正常工作的情况

- 报告直接引用 `ao status` 输出，而不是对其可能显示的内容的释义。
- 意图和判定计数追溯到 `.agents/ao/intents/sha256` 和 `.agents/ao/verdicts/sha256`，而不是推断出的计数。
- 运行时阶段和工具调用活动除非调用者单独提供了该来源，否则标记为 `not_checked`。
- 追踪器、Git 和工厂状态保持在各自报告的行中，而不是一个混合的 `health` 声称。

## 合约

仅报告可观察的本地事实：可用的意图和判定工件及其计数；确定性检查结果；证据时效性；以及不可用或损坏的来源。规范化的持久存储是 `.agents/ao/intents/sha256` 和 `.agents/ao/verdicts/sha256`。主题清单由调用者提供：仅在调用者命名其位置时报告它们，否则披露为 `not_checked`。当 `.agents/ao` 证据存在时，报告最新存储工件类型，并将该结论标记为证据时效性，而不是运行时阶段或进程活动。`ao status` 快照发出两个计数以及最新工件时效性结论，而不是每个工件的摘要或时间戳列表；仅在调用者询问命名工件时报告特定工件的摘要或时间戳。

始终披露 `checked` 和 `not_checked`。运行时阶段、执行经过时间、工具调用活动和剩余工作除非调用者为其提供了单独的权威来源，否则为 `not_checked`。

`ao status` 是证据存储的视图。它在计数之前验证内容寻址工件名称和内容，报告损坏和不可用的条目，并仅显示意图/判定计数和证据时效性。已退役的遗留表面（会话索引、来源摘要、知识健康信号）不会被聚合到该命令中。

不同的状态类别在每次状态报告中保持不同：追踪器状态属于追踪器，Git 状态属于 Git，工厂或运行时状态属于选定工厂自己的门，确定性检查结果属于生成它们的可执行文件，语义验证属于新的判定。从其各自的权威报告每个，永远不会合并成一个混合的“健康”声称——工厂完整、检查绿色和 AgentOps-PASS 是三个不同的事实。

状态不会检查工作队列、分配优先级、声称工作、推断下一步操作、修复记录、管理重试或更改任何状态。可选的 Git 或追踪器元数据仅在调用者提供时显示；缺失不能改变报告的解释。

命名故障模式——**时效性作为活动**：将“最新工件是判定”解读为“验证正在运行”，从一个时间戳中编造一个运行时阶段。

反模式：用看似合理的叙述填充 `not_checked` 空白，使快照感觉完整。纠正方法：将空白报告为空白；一个诚实的洞比一个平滑的故事更胜一筹。

返回快照并停止。
