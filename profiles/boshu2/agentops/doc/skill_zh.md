# 文档

根据当前仓库及其接受的意图，编写或更新调用者需要的文档。简单的解释不需要面试、覆盖账本或单独的报告。仅选择与任务相关的模式。

## 模式

| 需求 | 范围和参考 |
|---|---|
| 解释 API、命令、代码映射或架构 | 检查其消费者和源代码；在需要时使用 [代码/API 指导](references/default-mode.md) 或 [架构指导](references/architecture-report.md)。 |
| 创建或改进 README | 以用户的问题和工作中的第一条使用路径为起点；保留有用的深度。参见 [README 创作](references/readme-craft.md)。 |
| 审计或搭建 OSS 文档 | 将现有文档与请求的包进行比较。创建缺失的文件；仅在授权请求范围内修改现有文件。参见 [OSS 包](references/oss-pack.md)。 |
| 初始化缺失的入口文档 | 仅创建明确请求的缺失文件；报告现有路径为跳过。参见 [设置示例](references/bootstrap/examples.md)。 |
| 为另一个上下文保留会话 | 将下面描述的紧凑事实性交接写入调用者的授权目的地。 |

这些是可选的任务形状，不是连续的阶段。详细的参考提供了技术和格式；它们不会增加面试、审批检查点、报告或超出接受请求的文件。修改指定文档的现有授权就足够了。

## 基于事实的写作

1. 确定受众、问题和现有文档的所有者。重用接受的意图；仅请求对文档有实质性改变缺失的内容。
2. 阅读相关的声明，并对照代码、配置、命令帮助或可执行行为进行验证。使用调用者的领域术语。对于较大的范围，保留足够的源代码参考以披露检查了什么和仍然未知什么；不要暗示整个仓库的覆盖范围。
3. 进行最小的有用编辑。当解释有助于读者时，解释非明显的规则、顺序和权衡。参考页面不需要制造教训。在授权范围外保留操作员策略和历史记录。
4. 检查链接、示例和仓库适用的文档构建或验证器。删除空的声明和冗余的文本；[文本指导](references/de-slopify.md) 在请求的输出量大的情况下可以帮助。
5. 返回更改的路径和检查结果，以及未解决的事实性差距。仅在调用者请求或现有消费者需要时才编写单独的报告。

对于 AgentOps 本身，阅读 `docs/contracts/ubiquitous-language.md`：该产品是代理工程的操作层。保留该层与调用者拥有的执行、工作跟踪和交付之间的区别。

## 缺失文档的设置

仅创建请求的缺失文档，例如 `PRODUCT.md`、`GOALS.md` 或 `AGENTS.md`；发生冲突时跳过，而不是由设置覆盖。验证创建的路径，并报告创建、跳过和失败的写入。设置不会安装工具、运行 `ao session bootstrap`、初始化 Git 或跟踪器、启动运行时、添加钩子或推断仓库工作流。

在 `.agents/ao/verdicts/sha256/` 处的独立裁决存储仅在明确请求时创建。新的 CDLC 证明使用调用者选择的受保护的对外非 Git 证据根；缺失的路径不允许检出回退。保留现有证据并使用仓库的实际源所有者。

## 会话交接

请求的交接记录另一个上下文可以验证的最终状态事实：

- 接受的目标、完成的工件和确切的证据路径；
- 命令和观察到的结果、未解决的接受、发现和因果关系差距；
- 有用的仓库/内容身份、观察到的原生停止状态和测量的剩余允许或明确的未知数；当该事实对继续有影响时，记录当前 HOLD 事件的帮助者是否使用；
- 允许的调度/启动关联和观察到的运行时/会话/上下文身份，带有单独证据的父/恢复链接和源边界；
- 调用者提供的继续，当存在时。

遵循 [会话关联](../cass/references/SESSION_FORMATS.md#work-to-session-associations) 以便这些身份。最终状态笔记不能替代缺失的启动证据。不要编造 ID，从报告 HOLD 的情况推断暂停的目标，将整个多工作会话分配给一个任务，或通过压缩重置预算和帮助者事件。保留信息性失败和撤回的声明。

在复制元数据之前检查源、接收者/模型和目的地授权。不透明的定位器不授予任何访问权限。新的 CDLC 交接需要选择的受保护的对外非 Git 目的地；保留遗留证据并报告缺失的路由，而无需创建回退文件。否则使用调用者命名的位置，并在写入后读取。

`.agents/handoff/` 下现有的 JSON 保持为只读证据。
`ao session handoff` 写入 `.agents/ao/handoff/`；`ao session rehydrate` 搜索两者并选择最新的词法 ID，对于相同的文件名优先选择规范目录。这些命令不建立启动关联或外部存储授权。返回 Markdown 消费者的确切路径。

写入交接不会改变跟踪器、Git、运行时或裁决状态。原生的调用者继续拥有授权的结果；这种文档模式不会选择工作或为其决定继续。
