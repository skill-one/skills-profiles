# 融合技能

技能生命周期的入口点。解析意图，并调用正确的代理。

## 加载行为

仅加载路由的代理文件。代理在需要时按需加载引用（例如，仅在MCP失败时加载`skill-catalog.md`，仅在设置模式下加载`sync-workflows.md`）。不要预加载所有代理或所有引用。

## MCP工具

此技能使用`mcp_fusion_skills`——处理技能发现和生命周期操作的Fusion MCP工具：
- **发现** (`intent: query`)：通过描述或任务对技能索引进行语义搜索。
- **清单** (`intent: inventory`)：列出已安装的技能。
- **生命周期** (`intent: install | update | remove`)：管理技能的建议命令。

## 路由

| 意图 | 代理 |
|------|------|
| 查找或发现正确的技能；列出已安装的技能 | `agents/discovery.agent.md` |
| 安装、更新、删除或检查技能；设置自动化 | `agents/greenkeeper.agent.md` |
| 创建、编写或改进技能 | `agents/author.agent.md` |
| 检查技能的质量问题，或报告技能故障 | `agents/warden.agent.md` |

如果用户是从`fusion`主门路由到此，并且意图尚未完全解析（例如，“技能”），请直接跳转到最可能的代理，而无需重新询问顶级问题。

如果意图确实不明确，并且用户尚未被问及澄清问题，请问一个问题：“您是想查找技能、安装或更新技能、创建自己的技能，还是报告技能的问题？”

**复合意图**：如果请求涉及多个代理（例如，“检查此技能并修复问题”），请按顺序运行代理。将第一个代理的输出作为上下文传递给第二个。

**防止循环**：如果您是从`fusion`主门激活的，请不要重定向回`fusion`。在您的代理内处理请求，或说明其超出范围。

**超出范围**：解决GitHub问题、审查PR、规划任务分解或编写GitHub问题。将用户引导到相关的已安装技能或`fusion`主门——但如果您是从那里激活的，切勿重新路由回`fusion`。

## 从已弃用的技能迁移

如果此技能与`fusion-discover-skills`或`fusion-skill-self-report-bug`一起安装，请告知用户：
> “您安装了一个已弃用的技能，现在它是`fusion-skills`的一部分。从`apm.yml`中删除其依赖项，然后运行`apm prune`以协调锁文件和部署文件。”

## 安全性

- 不包含秘密或凭证。
- 无需确认，不进行GitHub变更。
- 不执行远程脚本。
- 不编造技能名称或目录结果。
- 已安装的技能文件是副本（使用`apm.yml`和`apm.lock.yaml`检查依赖项来源和部署文件的所有权）——切勿直接就地编辑它们；通过`agents/author.agent.md`（重定向到`fusion-skill-authoring`，源代码库）路由内容修复，通过`agents/warden.agent.md`（报告模式）处理故障）。
