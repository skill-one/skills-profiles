# UI 字体排印技巧

## 知识来源

这些规则源自 **Matthew Butterick 的《实用字体排印》** (https://practicaltypography.com)。
Butterick 是一位字体排印师、作家和字体设计师，他的工作连接了专业字体排印和日常数字写作。感谢 Matthew 使这些知识变得易于获取且百科全书式。如果你认为这项技巧有价值，请考虑直接支持他的工作。

## 操作方式

这些是 **永久性规则** —— 不是潮流，不是观点。它们来自数百年的字体排印实践，并通过人类眼睛的阅读方式得到验证。它们不会过时。

**强制执行（默认）**：在生成任何带有可见文本的 UI 时，自动应用所有规则。使用正确的 HTML 实体，适当的 CSS。不要请求许可。不要解释。只需生成正确的字体排印。

**审核**：在审查现有代码或设计时，识别违规行为并提供修复前后的方案。

**参考文件**（在生成 CSS 或查找实体时阅读）：
- `references/css-templates.md` — 完整的 CSS 基线模板、响应式模式、OpenType 功能
- `references/html-entities.md` — 完整的实体表格，包含所有字符和代码

## 字符

### 引号和撇号 —— 始终使用曲引号

直引号是打字机的遗留物。双引号使用 `&ldquo;` `&rdquo;`，单引号使用 `&lsquo;` `&rsquo;`。

撇号始终向下指 —— 与闭合单引号 `&rsquo;` 相同。智能引号引擎错误地在十年缩写（'70s）和单词开头的缩合词（'n）之前插入开引号。使用显式的 `&rsquo;` 进行修复。

当 `<html lang="en">` 设置时，`<q>` 标签会自动应用曲引号。

夏威夷语中的奥基纳向上指 —— 它是字母，不是撇号。使用开单引号或英文化。

### JSX/React 实现警告

**Unicode 转义序列（`\u2019`，`\u201C` 等）在 JSX 文本内容中不起作用。** 它们被渲染为字面字符 —— 用户看到 `\u2019` 而不是曲引号。这是因为 JSX 标签之间的文本被转换器视为字符串字面量，而不是 JavaScript 表达式。

**以下内容无效：**
```jsx
{/* 错误——渲染为字面值 \u2019 */}
<p>Don\u2019t do this</p>
```

**以下内容有效（选择一项）：**

1. **实际的 UTF-8 字符（首选）：** 直接将真实字符粘贴到源文件中。
   ```jsx
   <p>Don\u2019t do this</p>  {/* 这是实际的曲引号字符 U+2019 */}
   ```

2. **JSX 表达式与字符串字面量：** 用大括号包裹，以便 JS 引擎解释转义。
   ```jsx
   <p>Don{'\u2019'}t do this</p>
   ```

3. **HTML 实体（仅限 HTML 文件）：** 使用 `&rsquo;` —— 但这在 JSX/React 中不起作用。

**通过 CLI 进行批量修复**，使用原始 UTF-8 字节（不是转义序列）：
```bash
CURLY=$(printf '\xe2\x80\x99')  # U+2019 右单引号
sed -i '' "s/don't/don${CURLY}t/g" file.tsx
```

**在 JavaScript 数据数组和字符串字面量中**，`\u2019` 可以正常工作，因为 JS 引擎处理转义。该错误仅影响 JSX 标签之间的文本内容。

### 连字符和短横线 —— 三个不同的字符

| 字符 | HTML | 使用场景 |
|------|------|---------|
| - (短横线) | `-` | 复合词（经济实惠）、换行 |
| – (英文连字符) | `&ndash;` | 范围（1–10）、连接（萨班斯-奥克斯利法案） |
| — (英文长横线) | `&mdash;` | 句子断开——像这样 |

永远不要用 `--` 或 `---` 来近似。如果以 "from" 开头，则与 "to" 配对，而不是英文连字符。短横线用于复合名称（婚姻）；英文连字符用于联合署名。英文长横线通常靠齐；如果挤压，则添加 `&thinsp;`。连字符不应出现在英文连字符的位置。短横线用于短语形容词（五美元纸币）。不要在 -ly 副词后使用短横线。

### 省略号 —— 一个字符

使用 `&hellip;`（…），而不是三个点。前后有空格；在文本相邻的一侧使用 `&nbsp;`。
对于中断的对话，优先使用英文长横线而不是省略号。

### 数学与测量

使用 `&times;` 表示乘法，`&minus;` 表示减法。使用键盘上的 `+` 和 `=`。
英文连字符作为简单的减号也是可接受的。尺寸：8.5″ × 14″ 使用 `&times;`。

**英尺和英寸符号** —— 曲引号的唯一例外。必须为直：`&#39;` 表示英尺，`&quot;` 表示英寸。在值之间使用 `&nbsp;`：`6&#39;&nbsp;10&quot;`。

### 商标和版权

使用真实符号：`&copy;` `&trade;` `&reg;`，永远不要用（c） (TM) (R)。™/® 是上标，前面不加空格。
© 是内联的，后面跟着 `&nbsp;` 然后是年份。"Copyright ©" 是多余的——单词或符号，不是两者都有。

### 段落和章节标记

`&sect;` (§) 和 `&para;` (¶) 始终跟着 `&nbsp;`：`&sect;&nbsp;1782`。在句子开头拼写出来。
复数使用双写：`&sect;&sect;`。

### 带重音的字符

专有名词：重音是强制性的（弗朗索瓦·特吕弗，普拉西多·多明戈）。外来词：查字典——有些自然化了（naive），有些没有（著名案件）。

### 其他标点符号

- **分号** 连接独立分句。**冒号** 引入完成。不要混用
- **问号**：使用不足——用它们简化主题句
- **感叹号**：使用过度——每个长文档预算一个。永远不要连续使用多个
- **和号**：仅在专有名词中正确。在正文文本中写 "and"
- **括号/方括号**：不要采用被包围材料的格式
- **表情符号/emoji**：邮件/Slack 中可以。永远不要在正式文件或专业 UI 文本中使用

## 间距

### 标点符号后始终一个空格

任何标点符号后都恰好一个空格。永远不要两个。没有争议。两个空格会形成河流并破坏文本平衡。句号已经包含视觉空白。

### 非断行空格

`&nbsp;` 防止换行。用于数字引用（`&sect;&nbsp;42`，`Fig.&nbsp;3`），© 之后（`&copy;&nbsp;2025`），头衔之后（`Dr.&nbsp;Smith`），英尺/英寸值之间。

### 空白字符

| 需要 | 工具 |
|------|------|
| 单词间空格 | 一个空格（空格键） |
| 防止换行 | `&nbsp;` |
| 同一段落中的新行 | `<br>` |
| 新段落 | `<p>` 标签 |
| 新页（打印） | `page-break-before: always` |
| 建议连字符点 | `&shy;` |

永远不要按住空格键。永远不要用双换行符进行间距。输出中永远不要用制表符进行缩进。HTML 将所有空白折叠为单个空格（`&nbsp;` 除外）。

## 文本格式

### 粗体和斜体

**规则 1**：粗体或斜体。互斥。永远不要组合。
**规则 2**：尽可能少用。如果所有内容都被强调，那么就没有被强调的内容。

衬线字体：斜体用于温和，粗体用于强烈。无衬线字体：仅使用粗体——无衬线斜体几乎无法突出。永远不要粗体整个段落。永远不要用引号强调。

### 下划线 —— 永远不要

在文档或 UI 中永远不要下划线。打字机解决方案。使用粗体或斜体。对于网页链接，使用微妙的样式：`text-decoration-thickness: 1px; text-underline-offset: 2px`。

### 全大写 —— 少于一行，始终字母间距

大写更难阅读（同质的矩形与变化的斜体轮廓）。适用于短标题、标签、说明文字。**始终**添加 5–12% 的字母间距。**始终**确保字距调整是开启的。**永远**不要全部大写段落。CSS 中 `letter-spacing: 0.06em`。

### 小写大写 —— 真实的只有

永远不要伪造（缩放的下划线大写）。使用 `font-variant-caps: small-caps` 并带有具有真实小写大写（OpenType `smcp`）的字体。系统字体没有它们。添加字母间距 + 字距调整。

### 点大小

打印：10–12pt。网页：15–25px。12pt 默认是打字机的遗留物。半点差异很重要。使用最小增量进行强调。使用 `clamp()` 进行流体网页尺寸。

### 字母间距

所有大写和小写大写都增加 5–12% 的额外间距。小写没有。永远不要分开得那么远，以至于字母可以填入间隙。CSS：`letter-spacing: 0.05em` 到 `0.12em`。

### 字距调整 —— 始终开启

没有例外。`font-feature-settings: "kern" 1; text-rendering: optimizeLegibility;`

### 连字

仅在 fi/fl 视觉上冲突时强制使用。检查粗体和斜体。否则可选。
CSS：`font-feature-settings: "liga" 1`。

### 替代数字

制表符（`"tnum"`）用于数据表。旧式（`"onum"`）用于正文文本。默认数字适用于大多数用途。`font-variant-numeric: tabular-nums lining-nums` 用于数字表。

### 字体选择

1. 专业工作中没有奇怪的字体（新奇、手写、花体）
2. 正文文本不使用等宽字体——仅代码（Courier 是最差的等宽字体）
3. 打印正文：强烈推荐衬线字体
4. 网页正文：衬线或无衬线在现代屏幕上都可以
5. InDesign 中的度量间距，永远不要光学（光学会破坏字距调整）

### 混合字体

最多 2 种字体。每种字体都有一个一致的角色。可以混合衬线+衬线或无衬线+无衬线。很少在段落内混合。低对比度通常比高对比度更有效。

## 页面布局

### 正文文本优先

在设置正文文本之前设置其他任何内容。四个决定决定一切：字体、点大小、行间距、行长度。所有其他元素都根据这些进行校准。

### 行长度 —— 45–90 个字符

设计人员最常犯错的第一个可读性因素。响应式网页布局中的第一个缺陷。
以字符为单位测量，而不是英寸。字母测试：每行适合 2–3 个小写字母。
CSS：`max-width: 65ch` 在文本容器上。

### 行间距 —— 点大小的 120–145%

`line-height: 1.2` 到 `1.45`。单倍行距（~117%）太紧。双倍（~233%）太松。
文字处理器的“单倍”和“双倍”都错过了最佳范围。

### 页面边距

一英寸对于比例字体来说不够。打印：12pt 的 1.5–2.0″。网页：文本容器上的 `max-width` 加 `padding`。不要害怕空白——宽边距看起来专业。

### 文本对齐

网页左对齐（默认）。两端对齐需要 `hyphens: auto` —— 浏览器引擎很粗糙。
居中对齐：谨慎使用，仅用于短标题（< 1 行）。永远不要居中整个文本块。

### 段落分隔 —— 缩进或空格，永远不要两者都做

**首行缩进**：1–4× 点大小。`text-indent: 1.5em`。第一段可选。
**空格之间**：字体大小的 50–100%。`margin-bottom: 0.75em`。永远不要双 `<br>` 标签。

### 标题 —— 最大 3 级

1. 不要全部大写标题（除非非常短 + 字母间距）
2. 不要下划线标题
3. 不要居中标题（罕见例外）
4. 用**上下空间强调**——微妙且有效
5. 使用**粗体，而不是斜体**——更突出
6. 最小的点大小增量（正文 11pt → 标题 13pt，不是 18pt）
7. 标题上的 `hyphens: none`
8. 上面的空间大于下面的空间（标题与后面的文本相关）
9. 将标题与下一段保持在一起（`page-break-after: avoid`）
10. 分级数字（1.1，2.1）优于罗马数字（I.A.1.a.i）

### 块引用

稍微减小大小和行间距。缩进 2–5em。没有引号（缩进表示引用）。
保持行长度可读。谨慎使用——长块引用表示懒惰的写作。

### 列表

语义标记（`<ul>`，`<ol>`），永远不要手动项目符号。优先使用空心项目符号。星号太小，不能用作项目符号。不要过度缩进。

### 表格 —— 移除边框，添加内边距

数据创建了一个隐含的网格。边框添加了杂乱。仅保留表头行下方的细线。
`padding: 0.5em 1em`。数字列使用制表符数字。数字右对齐。

### 线和边框

首先尝试上下空间。边框厚度：0.5–1pt。不要有图案边框。粗线是图表垃圾。

### 流程控制

孤行（最后一行单独在页面上方）和孤行（第一行单独在页面底部）。CSS 打印：`orphans: 2; widows: 2`。标题：`page-break-after: avoid`。软连字符 `&shy;` 用于混淆连字符引擎的单词。

### 列和网格

打印列：信纸 2–3 列，永远不要 4 列。网页列：尴尬（底部边缘不确定）。
网格指导，而不是保证——更简单的网格强制更多一致性。将丑陋对齐到网格上仍然产生丑陋。

## 响应式网页字体排印

**规则不会随着屏幕大小而改变。** 同样的行长度、行间距、层次结构。

1. 一起缩放 `font-size` 和容器 `width`
2. 始终在文本容器上使用 `max-width` —— 永远不要边缘到边缘的文本
3. 不要使用 `ch` 单位进行精确测量（仅测量零宽度）
4. `clamp()` 用于流体缩放：`font-size: clamp(16px, 2.5vw, 20px)`
5. 移动端最小：`padding: 0 1rem` 在文本容器上
6. 常见错误：图像/导航小心缩放，正文文本被忽略

## 屏幕考虑

现代屏幕的字体渲染效果几乎与打印一样好。"屏幕用无衬线字体" 在 72dpi 时是正确的，现在已过时。衬线字体在现代屏幕上工作得很好。暗黑模式：稍微减轻重量。在 macOS 和 Windows 上测试（抗锯齿不同）。

## 页面布局格言

1. **正文文本优先**——它的 4 个属性决定一切
2. **前景与背景**——不要让装饰品盖过正文文本
3. **最小可见增量**——半点很重要
4. **不确定时尝试两者**——制作样本，不要理论化
5. **一致性**——相同的东西看起来相同
6. **将新与现有联系起来**——每个元素都限制下一个元素
7. **保持简单**——3 种颜色和 5 种字体？再想想
8. **模仿你喜欢的东西**——从野外模仿好的字体排印
