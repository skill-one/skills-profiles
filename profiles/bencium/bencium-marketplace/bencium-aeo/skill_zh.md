# AEO内容优化技能

**答案引擎优化** - 优化内容以供AI引用，而非传统搜索排名。

## 何时使用此技能

在以下情况下使用此技能：
- 用户要求优化内容以供AI搜索/引用
- 用户提及ChatGPT、Claude、Gemini的可见性
- 用户需要FAQ模式、JSON-LD或结构化数据以供AI使用
- 用户询问GEO（生成式引擎优化）
- 用户希望分析内容以供AI提取准备
- 用户提及"AI概述"或"答案引擎"

**不适用于传统SEO** - 此技能专门用于AI/LLM引用优化。

## 快速参考：关键原则

### 18个token提取规则
LLM提取约18个token（约15-20个词）的独立句子。关键主张必须是完整的、可引用的声明，无需周围上下文。

**良好**："Eight-API合成将房产分析错误率降低67%。"（9个token）
**不佳**："我们的系统非常快，能提供惊人的结果。"（模糊）

### 单主题专注页面
单概念页面远优于多主题内容。创建专注的URL，如`domain.com/specific-concept`，而不是综合指南。

### 引用+统计数据=30-40%更高的可见性
每个主要主张都需要：
- 可验证的数据和方法
- 数据收集日期
- 专家归属（姓名+资质+组织）

### 新鲜度至关重要
95%的AI引用来自过去10个月内更新的内容。静态内容会过时。

### 权威级别决定策略

| 权威级别 | 优化方法 |
|-----------------|----------------------|
| **挑战者**（新网站、低权威） | 主动：每页5-7个提取点，大量引用，每周微更新 |
| **成熟**（排名靠前、知名） | 轻触：1-2个战略点，信任现有信誉，避免过度优化 |

**普林斯顿发现**：排名第五的网站通过主动优化可见性提升了115%。排名第一的网站因过度优化而损失了30%。

## 应生成的内容

当用户请求AEO内容时，生成：

### 1. 产品概述（50字）
- 它是什么（一个从句）
- 范围/时间背景
- 为什么重要（价值主张）
- "最后更新"日期

### 2. 15个带模式的FAQ
- 问题：7-12个字，自然语言
- 答案：30-50字（AI提取的最佳点）
- FAQPage JSON-LD模式，带`datePublished`和`dateModified`
- 持久锚点ID（#faq-slug）

### 3. 证据面板
对于每个重要主张：
- 主张声明
- 方法
- 数据源+URL
- 数据收集日期
- 限制
- 询问联系人

### 4. JSON-LD模式
- FAQPage（最重要）
- HowTo（用于指南）
- Product（用于产品页面）
- Organization（用于关于页面）

## 应避免的反模式

### 传统SEO策略损害GEO
- 关键词堆砌
- 没有原创见解的通用列表
- 模糊的委婉语（"可能有助于"、"可能有可能"）
- 多主题综合指南
- 在成熟网站过度优化

### 内容结构错误
- FAQ答案超过50字
- 隐藏答案（先放结论）
- 指代词歧义（"它"而不是"产品"）
- 缺少日期和新鲜度信号
- 没有模式标记

## 评估框架

当分析内容以供AEO准备时，评分（0-10）：

| 维度 | 检查内容 |
|-----------|--------------|
| **提取** | 18个token以下有多少可引用的句子？ |
| **专注** | 单主题还是蔓延的多主题？ |
| **权威** | 专家归属带资质？引用？ |
| **新鲜度** | 90天内更新？已标记的内容？ |

**快速测试**：能否在不加上下文的情况下复制粘贴3个完整回答问题的句子？

## 实施检查清单

- [ ] 产品概述：50字，带日期，在H1下
- [ ] 15个FAQ：每个30-50字，自然问题
- [ ] 证据面板：方法、数据、日期、限制
- [ ] 每个部分都有"最后更新"日期
- [ ] FAQPage JSON-LD模式在`<head>`中
- [ ] FAQ的持久锚点ID
- [ ] 使用Google丰富结果测试验证

## 测试协议

实施后，使用以下内容测试：

1. **识别**："什么是[产品]？"（ChatGPT、Claude、Gemini）
2. **比较**："比较[产品]和[竞争对手]"
3. **最佳选择**："对于[用例]的最佳[类别]是什么？"
4. **如何操作**："如何使用[产品]完成[任务]"

**跟踪**：提及？链接？准确？引用证据？
