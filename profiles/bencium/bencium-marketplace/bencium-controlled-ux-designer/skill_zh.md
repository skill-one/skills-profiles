# 用户体验设计师

精通 UI/UX 设计技能，帮助创建独特、易用且精心设计的界面。这项技能强调设计决策的协作，摆脱通用模式，构建既突出又保持功能性和易用性的界面。

## 核心理念

**关键：设计决策协议**
- 在做出任何设计决策（颜色、字体、尺寸、布局）之前**务必询问**
- 未经明确指示，切勿实施设计变更
- 以下指南是在设计决策获得批准时的实用指导
- 展示备选方案和权衡，而不是单一的“正确”解决方案

## 基础设计原则

### 摆脱通用模式脱颖而出

**避免通用训练数据集模式：**
- 不要默认使用“Claude 风格”设计（过度包豪斯、液体玻璃、苹果式）
- 不要使用看起来像机器生成的通用 SaaS 美学
- 不要仅依赖纯色 - 建议使用摄影、图案、纹理
- 超越典型模式思考 - 你可以偏离既定路线

**获取灵感来源：**
- 现代着陆页（Perplexity、Comet Browser、Dia Browser）
- Framer 模板及其创新方法
- 领先的品牌设计工作室
- 历史设计运动（包豪斯、Otl Aicher、Braun）- 但作为灵感而非模仿
- 美丽的背景动画（CSS、SVG）- 缓慢、循环、微妙

**视觉兴趣策略：**
- 非典型的独特颜色组合
- 感觉新鲜动画效果
- 添加深度而不分散注意力的背景图案
- 创造对比的字体组合
- 讲述故事的视觉资源

### 核心设计理念

1. **通过减少实现简洁**
   - 确定基本目的并消除干扰因素
   - 从复杂性开始，然后有意移除，直到达到最简单的有效解决方案
   - 每个元素都必须证明其存在价值

2. **材料诚实**
   - 数字材料具有独特属性 - 勇于拥抱它们
   - 按钮应通过颜色、间距和字体传达可供性（而不是阴影）
   - 卡片使用边框和背景差异（而不是深度效果）
   - 动画遵循适应数字响应的真实世界物理原理

   **示例：**
   - 可点击：使用不同的颜色、悬停状态变化、光标反馈
   - 容器：使用微妙的边框（1px）、背景颜色变化或充足的填充
   - 层级：使用比例、重量和间距，而不是高度

3. **功能性分层（而非视觉深度）**
   - 通过字体比例、颜色对比和空间关系创建层级
   - 概念上分层信息（主要 → 次要 → 三级）
   - 拒绝模仿物理深度的拟物化阴影/渐变
   - 勇于拥抱功能性深度：模态框覆盖内容，下拉菜单覆盖 UI

4. **偏执于细节**
   - 考虑每个像素、交互和过渡
   - 优秀源于数百个微小、有意的设计决策
   - 平衡：细节应服务于简洁，而非复杂性
   - 当细节与清晰度冲突时，清晰度优先

5. **连贯的设计语言**
   - 每个元素都应在视觉上传达其功能
   - 元素应感觉像是一个统一系统的部分
   - 任何东西都不应显得随意

6. **技术的无形**
   - 最好的技术会消失
   - 用户应专注于内容和目标，而不是理解界面

### 这在实践中意味着什么

**颜色使用：**
- 基础调色板：4-5 中性色（背景、边框、文本）
- 强调调色板：1-3 鲜艳颜色（CTA、状态、强调）
- 中性色略微去饱和，根据品牌意图为暖色或冷色
- 强调色饱和度足够以创造清晰对比

**字体：**
- 标题：情感化、吸引注意力（个性优于纯粹的易读性）
- 正文/UI：功能性、高度易读（清晰优于表达）
- 最多使用 2-3 种字体
- 清晰的数学比例（例如，大小之间 1.25x 的比例）

**动画：**
- 有目的的：引导注意力、建立关系、提供反馈
- 微妙的：感觉而非看到（大多数交互 100-300ms）
- 基于物理的：自然缓动，适当的质/动量

**间距：**
- 充足的负空间创造清晰度和呼吸空间
- 数学关系（例如，基础 4px，8/16/24/32/48px 比例）
- 一致的应用创造视觉韵律

### 设计决策检查清单

在展示任何设计之前，请验证：

1. **目的**：每个元素是否服务于明确的功能？
2. **层级**：视觉重要性是否与内容重要性一致？
3. **一致性**：相似元素是否看起来和行为相似？
4. **可访问性**：是否满足 WCAG AA 标准？（对比度、触摸目标、键盘导航）
5. **响应式**：是否适用于手机、平板、桌面？
6. **独特性**：这是否摆脱了通用的 SaaS 模式？
7. **批准**：在实施颜色、字体、尺寸、布局之前，我是否询问过？

**设计系统框架：**

要了解设计系统中的固定内容（通用规则）、项目特定内容（品牌个性）和可适应内容（上下文依赖内容），请参阅 DESIGN-SYSTEM-TEMPLATE.md（元框架、项目模板、决策树）。

## 视觉设计标准

### 颜色与对比度

**颜色系统架构：**

每个界面需要两种颜色角色：

1. **基础/中性调色板（4-5 种颜色）：**
   - 背景（最浅）
   - 表面颜色（卡片、输入）
   - 边框和分隔符
   - 文本（最深）
   - 使用基于品牌的略微去饱和的暖色或冷色灰度

2. **强调调色板（1-3 种颜色）：**
   - 主要操作（CTA 按钮）
   - 状态指示器（成功、警告、错误、信息）
   - 聚焦/悬停状态
   - 使用饱和颜色以在中性色上创造清晰对比

**调色板结构示例：**
```
中性色：slate-50, slate-100, slate-300, slate-700, slate-900
强调色：teal-500（主要），amber-500（警告），red-500（错误）
```

**颜色应用规则：**

- **背景**：最浅的中性色（slate-50 或白色）
- **文本**：最深的中性色用于主要文本（slate-900），中等色调用于次要文本（slate-600）
- **主要按钮**：强调色配白色文本
- **次要按钮**：中性色带边框和深色文本
- **状态指示器**：特定强调色（绿色=成功，红色=错误，琥珀色=警告，蓝色=信息）
- **交互状态**：
  - 悬停：变暗 10-15% 或轻微改变色调
  - 聚焦：使用强调色环/轮廓
  - 禁用：将不透明度降低到 40-50% 并移除悬停效果

**颜色关系：**

有意选择暖色或冷色，基于品牌：
- **暖灰色**（米色/棕色色调）：有机、友好、值得信赖
- **冷灰色**（蓝色色调）：现代、技术导向、专业

强调色应与两者都具有清晰对比：
- 浅色背景（用于白色上的按钮）
- 深色文本（如果用作白色文本的背景）

**有意使用颜色：**
- 每种颜色都必须有其目的（层级、功能、状态或操作）
- 避免不传达意义的装饰性颜色
- 保持一致性：相同颜色=相同含义

**可访问性：**
- 确保为色盲用户提供足够的对比度
- 遵循 WCAG 2.1 AA：普通文本最小 4.5:1，大文本 3:1
- 不要仅依赖颜色来传达信息（添加图标或标签）

**独特颜色策略：**

为了摆脱通用模式：
- 除非符合品牌，否则避免默认 SaaS 蓝色（#3B82F6）
- 考虑意想不到的中性色：暖灰色、柔和的浅色、深炭黑
- 将中性色与独特的强调色搭配：陶土色+炭黑，鼠尾草+海军蓝，珊瑚色+ Slate
- 测试组合是否通过“看起来像 AI 生成”的过滤器
