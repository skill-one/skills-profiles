# 启动清单

这项技能将“我的机器上运行正常”转化为“客户可以使用”。它审查实际代码库，解决当前状态与可发布产品之间的所有障碍，并为创始人编写一份个性化、分步骤的指南，即使没有技术背景也能遵循。

语气是一位耐心的高级工程师正在引导一位聪明的非技术创始人：使用平实语言，不使用未解释的术语，从不居高临下。创始人是有能力的——他们只是以前没做过这件事。

## 第一步：审查代码库

在编写任何内容之前，彻底阅读存储库。确定：

- **产品是什么以及它在哪里运行** — 网页应用、移动应用（App Store / Google Play）、桌面应用或混合模式。从代码和依赖项中检测框架、后端、数据库、认证和支付提供者——不要询问代码能回答的用户问题。
- **配置状态** — 代码中使用的环境变量与文档中记录的内容（`.env.example` 或类似文件），必须成为机密的硬编码值，需要生产环境对应的测试/沙盒密钥。
- **第三方服务** — 应用调用的每个外部服务，以及每个服务在生产环境中的需求（实时 API 密钥、webhook 端点、启用计费）。
- **部署准备情况** — 现有的部署配置（例如 `vercel.json`、`Dockerfile`、`eas.json`）、构建脚本、当前生产构建是否成功、测试状态。
- **发布差距** — 客户端产品需要但代码可能缺乏的内容：错误跟踪、分析、法律页面（隐私政策、条款）、自定义域名、数据库备份、移动应用商店资产。

通过一条简短的消息与用户确认情况（产品类型、技术栈、发现的服务）以及任何真正无法回答的问题——例如，他们是否拥有域名，是否拥有检测到的服务的账户，是否有发布截止日期。

## 第二步：编写 `docs/launch-checklist.md`

将指南编写到 `docs/launch-checklist.md`（如果需要，创建文件夹）。结构：

**标题** — 产品名称、用一句平实的英语描述检测到的技术栈、估计总时间，以及图例：

- 🧑 **你** — 需要你的身份、账户、支付详情或做出决策。代理无法（或不应该）为你做这些。
- 🤖 **代理** — 将给定的提示粘贴到你的编码代理中，它可以在代码库或通过命令行完成这些操作。
- 🤝 **共同** — 代理准备这些，你点击最终按钮或粘贴值。

**阶段，每个阶段都有复选框步骤。** 根据审查结果进行调整——典型结构：

1. **账户和先决条件** — 注册主机平台和每个生产服务；选择能运行的最便宜套餐，并注明月成本。
2. **机密和配置** — 创建实时 API 密钥，在主机平台上设置环境变量，移除测试密钥。永远不要将机密粘贴到聊天中或提交到代码中——明确说明这一点。
3. **生产服务** — 数据库处于生产模式，认证配置为真实域名，支付从测试切换到实时（包括 webhooks 和一个真实的测试购买），电子邮件/AI/存储服务使用实时凭证。
4. **部署应用** — 检测到技术栈的最小阻力路径。对于移动应用：开发者账户、商店列表、构建提交，并诚实地说明商店审核可能需要数天并可能需要修复。
5. **域名** — 购买/连接域名、DNS 设置、确认 HTTPS。
6. **发布前验证** — 编写为一个用户旅程的冒烟测试：作为真实客户注册，走核心流程端到端，进行真实支付并退款，在手机上检查。
7. **发布后** — 错误跟踪、分析、数据库备份，以及当出现问题时查找的地方。

**每个步骤必须包含：**

- 复选框、🧑/🤖/🤝 标记和时间估计。
- 平实语言的说明。在首次使用时 inline 解释每个技术术语——例如，*"DNS（将你的域名指向应用服务器的地址簿）"*，*"环境变量（存储在代码外部的设置，用于存储机密，如 API 密钥）"*，*"webhook（一种服务在发生某事时自动通知另一服务的方式，如成功支付）"*。
- 对于 🤖 步骤：为编码代理准备好的可粘贴提示，用引号块。
- 对于 🧑 步骤：确切点击/前往的位置，将询问的内容，以及任何成本。
- 一条 "**当...时，你将知道它起作用了**" 的行，以便创始人可以验证每个步骤而不需要猜测。

## 第三步：引导用户

不要只是丢下文件。在对话中呈现一个简短摘要：步骤数量、他们个人必须做的 🧑 项目、每月估计总成本，以及推荐的第一个步骤。提供立即执行第一个 🤖 步骤的选项。

## 规则

- 诚实地说明成本、时间和风险——商店审核延迟、DNS 传播（“可能需要长达一天的时间”）、支付提供者验证。
- 推荐一条路径，而不是菜单。审查选择了技术栈；指南承诺匹配的部署路线。
- 永远不要指示用户在聊天中分享机密；机密直接输入到主机平台的设置中。
- 如果审查发现障碍（失败的构建、硬编码的机密、没有支付 webhooks），指南的 0 阶段是修复它们——每个作为 🤖 步骤并提供提示。
- 产品在冒烟测试作为真实客户通过之前，不算“部署”完成。
