# 普遍语言

从当前对话中提取并形式化领域术语，整理成一致术语表，并保存到本地文件。

## 流程

1. **扫描对话**，寻找与领域相关的名词、动词和概念
2. **识别问题**：
   - 同一个词被用于不同概念（歧义）
   - 不同词被用于同一个概念（同义词）
   - 模糊或重载术语
3. **提出规范术语表**，对术语选择保持主观性
4. **写入 `UBIQUITOUS_LANGUAGE.md`**，在当前工作目录中使用下面格式
5. **输出摘要**，在对话中内联总结

## 输出格式

编写一个 `UBIQUITOUS_LANGUAGE.md` 文件，结构如下：

```md
# 普遍语言

## 订单生命周期

| 术语        | 定义                                              | 需避免的别名      |
| ----------- | ------------------------------------------------------- | --------------------- |
| **订单**   | 客户购买一个或多个项目的请求                      | 购买、交易        |
| **发票**   | 交付后发送给客户的付款请求                      | 账单、付款请求    |

## 人物

| 术语         | 定义                                  | 需避免的别名       |
| ------------ | ------------------------------------------- | ---------------------- |
| **客户**     | 下订单的人或组织                        | 客户、买家、账户    |
| **用户**     | 系统中的认证身份                      | 登录、账户         |

## 关系

- 一个 **发票** 属于且仅属于一个 **客户**
- 一个 **订单** 产生一个或多个 **发票**

## 示例对话

> **开发人员：** "当 **客户** 下一个 **订单** 时，我们立即创建 **发票** 吗？"
> **领域专家：** "不——**发票** 只在确认 **交付** 后生成。一个 **订单** 如果项目分批 **发货**，可以产生多个 **发票**。"
> **开发人员：** "所以如果 **发货** 在派送前被取消，没有对应的 **发票** 吗？"
> **领域专家：** "完全正确。**发票** 生命周期与 **交付** 相关，而不是与 **订单** 相关。"

## 标记的歧义

- "account" 被用于指代 **客户** 和 **用户**——这两个是不同的概念：**客户** 下订单，而 **用户** 是一个认证身份，可能代表也可能不代表 **客户**。
```

## 规则

- **保持主观性。** 同一概念有多个词时，选择最好的一个，并将其他列为需避免的别名。
- **明确标记冲突。** 如果术语在对话中被模糊使用，在 "标记的歧义" 部分指出，并给出明确建议。
- **仅包含领域专家相关的术语。** 除非模块或类名在领域语言中有意义，否则跳过。
- **保持定义简洁。** 最多一句。定义它是什么，不定义它做什么。
- **展示关系。** 使用粗体术语名，并在明显时表达基数。
- **仅包含领域术语。** 跳过通用编程概念（数组、函数、端点），除非它们有领域特定含义。
- **将术语分组到多个表格**，当自然集群出现时使用（例如按子域、生命周期或参与者）。每组有自己的标题和表格。如果所有术语属于一个连贯的领域，一个表格就足够，不要强行分组。
- **编写示例对话。** 写一段开发人员与领域专家之间的简短对话（3-5 次交流），展示术语如何自然互动。对话应澄清相关概念的边界，并展示精确使用术语。

## 示例对话

> **开发人员：** "如何在没有 Docker 的情况下测试 **同步服务**？"
>
> **领域专家：** "提供 **文件系统层** 而不是 **Docker 层**。它实现相同的 **沙盒服务** 接口，但使用本地目录作为 **沙盒**。"
>
> **开发人员：** "所以 **同步入** 仍然创建 **包** 并解包它？"
>
> **领域专家：** "完全正确。**同步服务** 不知道它正在与哪个层交互。它调用 `exec` 和 `copyIn`——**文件系统层** 只是将其作为本地 Shell 命令运行。"

</示例>

## 重新运行

在同一对话中再次调用时：

1. 读取已有的 `UBIQUITOUS_LANGUAGE.md`
2. 合并后续讨论中的新术语
3. 如果理解演进，更新定义
4. 重新标记任何新歧义
5. 重写示例对话以包含新术语
