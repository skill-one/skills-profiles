技能的存在是为了从随机系统中提取确定性。**可预测性**——agent 每次采取相同的 _过程_，而不是产出相同的输出——是根本美德；下面所有杠杆都服务于它。

**粗体术语** 在 [`GLOSSARY.md`](GLOSSARY.md) 中定义；需要完整含义时查那里。

## 调用方式

两种选择，成本不同：

- **模型调用** 技能保留 **描述**，所以 agent 可以自主触发它，其他技能也能触达它（用户仍可手动输入名称）。它会带来 **上下文负载**：描述每轮都在上下文窗口中。机制：省略 `disable-model-invocation`，并写面向模型的描述，带丰富触发措辞（"Use when the user wants…"、"mentions…"）。
- **用户调用** 技能把描述从 agent 触达范围中拿掉：只有用户输入名称时才能调用，其他技能也不能调用它。零上下文负载，但会花 **认知负载**：_用户_ 是那个必须记得它存在的索引。机制：设置 `disable-model-invocation: true`；`描述` 变成人类看到的一行摘要，不放触发列表。

只有当 agent 必须自行找到该技能，或另一个技能必须调用它时，才选择模型调用。如果它只会被手动触发，就做成用户调用，不付上下文负载。

当用户调用技能多到用户记不住时，堆积的认知负载由一个 **路由技能** 来治疗：一个用户调用技能，负责命名其他用户调用技能以及何时使用它们。

## 编写描述

模型调用 **描述** 做两件事：说明技能是什么，并列出应触发它的 **分支**。每个词都会增加 **上下文负载**，所以描述比正文更需要修剪：

- **把技能的引导词放前面**——描述是它做调用工作的地方。
- **每个分支一个触发器。** 同义词如果只是重命名单一分支，就是 **重复**——"build features using TDD … asks for test-first development" 是同一个分支写了两次。合并它们；只保留真正不同的分支。
- **删掉正文已有的身份。** 描述只保留触发器，以及必要的 "when another skill needs…" 触达子句。

## 信息层级

技能由两类内容构成：**步骤** 与 **参考**，它们自由混合：技能可以全是步骤、全是参考，或两者都有。核心决策是用哪类内容，以及每块内容放在 **信息层级** 的哪一层——一个按 agent 需要材料的即时程度排序的梯子：

1. **技能内步骤** - `SKILL.md` 中的有序动作，是主要层级：agent 按顺序做什么。每个步骤以 **完成标准** 结束，即告诉 agent 工作完成的条件。让它 _可检查_（agent 能分辨完成与未完成吗？），必要时 _详尽_（"每个修改过的 model 都被考虑到"，而不是 "产出一个变更列表"）——模糊的标准会诱发 **过早完成**。
2. **技能内参考** - `SKILL.md` 中的定义、规则或事实，按需查阅。通常是合法的扁平同级集（一个 review 的所有规则在一个层级上）——这不是坏味道。_本技能全是参考。_
3. **外部参考** - 从 `SKILL.md` 推到独立文件中，经 **上下文指针** 触达，只在指针触发时加载。（涵盖 _披露_ 参考一一像 `GLOSSARY.md` 这样的同级文件，仍是技能的一部分——到完全位于技能系统之外、任何技能都能指向的 **外部参考**。）

强完成标准会驱动充分 **调研**——agent 在工作中做的挖掘——无论技能是否有步骤，因为 "每条规则都被应用" 约束扁平参考，正如 "每个步骤都完成" 约束序列。

把太少内容下放会让顶层膨胀；把太多内容下放会隐藏 agent 实际需要的材料。那种张力就是整个决策。

**渐进披露** 是沿梯子下移——移出 `SKILL.md`、进入链接文件——让顶层保持清晰。Mechanics：技能文件夹中的链接 `.md` 文件，用内容命名（本技能把完整定义披露到 `GLOSSARY.md`）。有些技能以不止一种方式使用，每种不同的方式都是一个 **分支**——不同 runs 沿着不同路径穿过技能。分支是最干净的披露测试：内联每个分支都需要的内容，把只有部分分支触达的内容放到指针后面。**上下文指针** 的 _措辞_，而不是目标文件，决定 agent 何时以及多可靠地触达材料。

梯子决定一块内容 _下移多远_，**共位置** 决定一旦到了那里 _什么在它旁边_：把一个概念的定义、规则和注意事项放在同一标题下，而不是散落各处，这样读一部分时它的邻居也随之而来。

## 何时拆分

**粒度** 是技能切分粒度，每次切分都会花两种负载之一，所以只有切分有收益时才切。两种切法：

- **按调用** - 当你有一个独立的 **引导词** 应自主触发，或另一个技能必须触达它时，拆出 **模型调用** 技能。你要为新的始终加载的 **描述** 支付 **上下文负载**，所以独立触达必须值得。
- **按序列** - 当后续 **步骤**（一个步骤的 **完成后的步骤**）会诱使 agent 急着结束前一步（**过早完成**）时，拆分一连串 **步骤**。把它们藏在视野之外，鼓励 agent 在当前任务上做更多 **调研**。

## 修剪

让每个含义都有 **单一事实来源**：一个权威位置，这样改变 behavior 就是一处的编辑。

逐行检查 **相关性**：它是否仍支撑技能的工作？

然后逐句寻找 **no-ops**，不只是逐行：把每个句子单独做 no-op test；失败时删除整句，而不是只修剪词。要激进——多数失败的 prose 应删除，不应重写。

## 引导词

**引导词** 是一个已经存在于模型预训练中的紧凑概念，agent 会在运行技能时用它思考（例如 _lesson_、_战争迷雾_、_tracer bullets_）。它在文本中反复出现（但不一定——一个强的引导词可能只需要一次），累积分布式定义，并通过招募模型已持有的 priors，用最少 tokens 锚定一整片 behavior。

它两次服务可预测性。正文中它锚定 _执行_：agent 每次遇到该词都触发同类行为。描述中它锚定 _调用_：当同一个词存在于你的 prompts、docs 和 codebase 中，agent 会把那份 shared language 连到该技能，更可靠地触发它。

寻找机会把技能重构为使用引导词。三处重复展开的 triad（**重复**）、花一句话绕一个概念的描述——每一段都是恳求 **合并** 成单个 token 的文字。例如：

- "fast, deterministic, low-overhead" -> _tight_——一个品质在一个阶段中被反复陈述——收进一个预训练词（一个 _tight_ loop）。
- "a loop you believe in" -> _red_——把一个模糊的 gate 转换成一个二元可观察状态（loop 在 bug 上变 _red_，或者不变）。

你同时赢得更少 tokens，_以及_ 一个更尖锐的 hook 让 agent 挂起它的思考。假设每个技能都携带着引导词可以退役的重复陈述——去找它们。

## 失效模式

用这些来诊断用户可能在使用技能时遇到的问题。

- **过早完成** - 当前步骤尚未真正完成就结束，注意力滑向 _正在完成_。防御顺序：先 sharpen completion criterion（廉价、局部）；只有当它不可避免地模糊 _且_ 你观察到 rush 时，才通过拆分隐藏完成后的步骤（序列切分）。
- **重复** - 同一含义出现在多个地方。它提高维护成本、浪费 tokens，并夸大该含义在梯子上的突出程度超过其真实等级。
- **沉积物** - 因为添加看似安全、删除看似有风险而沉积的 stale layers。任何缺少修剪纪律的技能的默认命运。
- **蔓延** - 技能太长，即使每一行都 live 且 unique。伤害 readability 和 maintainability，浪费 tokens。治疗方式是梯子：把 **参考** 披露到指针后面，按 **分支** 或序列拆分，让每条路径只携带它需要的。
- **no-op** - 模型默认就会做的一行，所以你付负载却什么也没说。测试：它是否改变默认 behavior？弱引导词（如 _be thorough_，当 agent 已经大致 thorough）就是 no-op；修法是换更强的词（如 _relentless_），而不是换一种 technique。
- **否定** - 用禁止来引导会适得其反：_don't think of an elephant_ 点名了 elephant，让它更容易浮现，而不是更难。应 prompt **积极**——直接说明目标 behavior，让被禁止的行为从不被说出；只有无法正向表达的 hard guardrail 才保留禁止，即使如此也要配上应该怎么做。
