1. **查看当前的 merge/rebase 状态**。检查 git 历史记录和冲突文件。

2. **为每个冲突找到主要来源**。深入理解每个变更为什么产生，以及原始意图是什么。阅读提交信息，检查 Pull Requests，检查原始的 issue/tickets。

3. **解决每个 hunks**。尽可能保留双方意图。如果两者不兼容，选择符合本次 merge 目标的一方，并记录权衡取舍。**不要**引入新行为。始终解决冲突；不要 `--abort`。

4. 发现项目的 **自动检查** 并运行它们，通常是类型检查、测试、格式化。修复 merge 引入的问题。

5. **完成 merge/rebase**。 Stage 所有内容并 commit。如果正在 rebase，继续 rebase 流程直到所有 commits 都完成。
