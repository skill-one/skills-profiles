# 到问题

使用垂直切片（跟踪箭头）将计划拆分成可独立领取的问题追踪器问题。

问题追踪器和筛选标签词汇表应该已经提供给你；如果没有，运行 `/setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

基于对话上下文中已有内容工作。如果用户传入问题参考（问题编号、URL 或路径）作为参数，从问题追踪器获取它，并读取完整的 body 和 comments。

### 2. 探索代码库（可选）

如果还没探索代码库，就先探索，以理解代码当前状态。问题标题和描述应使用项目领域词汇表，并遵守相关 ADRs。

### 3. 起草垂直切片

将计划拆分成 **跟踪箭头** 问题。每个问题都是一个薄的垂直切片，端到端穿过所有集成层，而不是某一层的水平切片。

切片可以是 `HITL` 或 `AFK`。HITL 切片需要人类交互，例如架构决策或设计评审。AFK 切片可以无人交互地实现并合并。尽可能优先 AFK。

<vertical-slice-rules>
- 每个切片都交付一条窄但 COMPLETE 的路径，穿过每一层（schema, API, UI, tests）
- 完成后的切片自身可 demo 或验证
- 偏好多而薄的切片，而不是少而厚的切片
</vertical-slice-rules>

### 4. 询问用户

将建议的拆分作为编号列表展示。每个切片显示：

- **标题**：简短的描述名
- **类型**：HITL / AFK
- **被阻塞**：哪些其他切片必须先完成（如果有）
- **覆盖的用户故事**：覆盖哪些用户故事（如果源材料中有）

询问用户：

- 粒度是否合适？（太粗 / 太细）
- 依赖关系是否正确？
- 是否需要 merge 或继续 split 某些切片？
- HITL 和 AFK 标记是否正确？

迭代直到用户批准拆分。

### 5. 将问题发布到问题追踪器

对每个批准的切片，将新问题发布到问题追踪器。使用下面的问题 body 模板。这些问题被视为已准备好给 AFK agents 接手；除非另有指示，发布时应用正确的筛选标签。

按依赖顺序发布问题（阻塞者优先），这样可以在 "被阻塞" 字段引用真实问题 identifiers。

<issue-template>
## 父问题

对问题追踪器中父问题的引用（如果源是现有问题；否则省略本 section）。

## 要构建的内容

这个垂直切片的简洁描述。描述端到端行为，不要按层叠实现描述。

避免具体文件路径或代码片段；它们很快会过时。例外：如果 prototype 产出的片段比散文更精确地编码了某个决策（状态机、reducer、schema、类型形状），可以内联在这里，并简短说明它来自 prototype。保留决策密集部分，不要放完整的 working demo。

## 接受标准

- [ ] 标准 1
- [ ] 标准 2
- [ ] 标准 3

## 被阻塞

- 对阻塞问题的引用（如果有）

如果没有 blocker，写 "None - can start immediately"。

</issue-template>

不要 close 或 modify 任何父问题。
