# 写作技巧

## 流程

1. **收集需求** — 询问用户：
   - 技能覆盖哪些任务/领域？
   - 应处理哪些具体用例？
   - 需要可执行脚本，还是只需要说明？
   - 是否有参考材料需要包含？

2. **起草技能** — 创建：
   - 带有简洁说明的 SKILL.md
   - 如果内容超过 500 行，创建额外的参考文件
   - 如果需要确定性操作，创建工具脚本

3. **与用户评审** — 展示草稿并询问：
   - 是否覆盖你的用例？
   - 是否缺失或不清晰？
   - 是否有部分需要更详细或更简短？

## 技能结构

```
skill-name/
├── SKILL.md           # 主说明（必填）
├── REFERENCE.md       # 详细文档（如需）
├── EXAMPLES.md        # 使用示例（如需）
└── scripts/           # 工具脚本（如需）
    └── helper.js
```

## SKILL.md 模板

```md
---
name: skill-name
description: 能力的简要描述。在 [特定触发条件] 时使用。
---

# 技能名称

## 快速入门

[最小可工作示例]

## 工作流程

[带清单的复杂任务分步流程]

## 高级功能

[链接到单独文件：参见 [REFERENCE.md](REFERENCE.md)]
```

## 描述要求

description 是 agent 决定是否加载技能时**唯一看到的内容**。它会和其他已安装的技能一起出现在系统提示中。agent 会读取这些 description，并根据用户请求选择相关技能。

**目标**：给 agent 提供足够信息，让它知道：

1. 这个技能提供什么能力
2. 何时/为何触发它（特定关键词、上下文、文件类型）

**格式**：

- 最多 1024 字符
- 使用第三人称
- 第一句说明它做什么
- 第二句："在 [特定触发条件] 时使用"

**良好示例**：

```
从 PDF 文件中提取文本和表格，填写表单，合并文档。在处理 PDF 文件或用户提到 PDF、表单或文档提取时使用。
```

**不良示例**：

```
帮助处理文档。
```

不良示例无法让 agent 区分它和其他文档技能。

## 何时添加脚本

以下情况添加工具脚本：

- 操作是确定性（验证、格式化）
- 同一段代码会被反复生成
- 错误需要明确处理

相比生成代码，脚本节省 tokens 并提升可靠性。

## 何时拆分文件

以下情况拆分为独立文件：

- SKILL.md 超过 100 行
- 内容有不同领域（财务 vs 销售模式）
- 高级功能很少需要

## 评审清单

草稿完成后验证：

- [ ] 描述包含触发条件（"在..."时使用）
- [ ] SKILL.md 低于 100 行
- [ ] 没有时间敏感信息
- [ ] 术语一致
- [ ] 包含具体示例
- [ ] 参考资料只深入一层
