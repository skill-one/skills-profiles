# LLM 安全指南（OWASP LLM 2025 Top 10）

基于 OWASP LLM 应用程序 Top 10 2025 版构建安全 LLM 应用的安全规则。

## 如何使用此技能

**主动模式** — 在构建或审查 LLM 应用程序时，根据应用程序模式自动检查相关安全风险。您无需等待用户询问 LLM 安全问题。

**被动模式** — 当用户询问 LLM 安全问题时，使用下方映射查找相关规则文件，其中包含详细的漏洞/安全代码示例。

### 工作流程
1. 确定用户正在构建什么（见下方“您正在构建什么？”）
2. 检查该模式的优先级规则
3. 从 `rules/` 读取特定规则文件以获取代码示例
4. 应用安全模式或标记漏洞

## 您正在构建什么？

使用此功能快速识别对用户任务最重要的规则：

| 构建... | 优先级规则 |
|-------------|---------------|
| **聊天机器人 / 对话式 AI** | 提示注入 (LLM01)、系统提示泄露 (LLM07)、输出处理 (LLM05)、无界消耗 (LLM10) |
| **RAG 系统** | 向量/嵌入弱点 (LLM08)、提示注入 (LLM01)、敏感信息泄露 (LLM02)、错误信息 (LLM09) |
| **带工具的 AI 代理** | 过度代理 (LLM06)、提示注入 (LLM01)、输出处理 (LLM05)、敏感信息泄露 (LLM02) |
| **微调 / 训练** | 数据中毒 (LLM04)、供应链 (LLM03)、敏感信息泄露 (LLM02) |
| **LLM 驱动的 API** | 无界消耗 (LLM10)、提示注入 (LLM01)、输出处理 (LLM05)、敏感信息泄露 (LLM02) |
| **内容生成** | 错误信息 (LLM09)、输出处理 (LLM05)、提示注入 (LLM01) |

## 类别

### 严重影响
- **LLM01: 提示注入** (`rules/prompt-injection.md`) - 防止直接和间接的提示操作
- **LLM02: 敏感信息泄露** (`rules/sensitive-disclosure.md`) - 保护个人身份信息、凭证和专有数据
- **LLM03: 供应链** (`rules/supply-chain.md`) - 保护模型来源、训练数据和依赖项
- **LLM04: 数据和模型中毒** (`rules/data-poisoning.md`) - 防止训练数据操作和后门
- **LLM05: 不当的输出处理** (`rules/output-handling.md`) - 在下游使用前清理 LLM 输出

### 高影响
- **LLM06: 过度代理** (`rules/excessive-agency.md`) - 限制 LLM 权限、功能和自主性
- **LLM07: 系统提示泄露** (`rules/system-prompt-leakage.md`) - 保护系统提示不被泄露
- **LLM08: 向量和嵌入弱点** (`rules/vector-embedding.md`) - 保护 RAG 系统和嵌入
- **LLM09: 错误信息** (`rules/misinformation.md`) - 减少幻觉和错误输出
- **LLM10: 无界消耗** (`rules/unbounded-consumption.md`) - 防止拒绝服务、成本攻击和模型盗窃

参考 `rules/_sections.md` 获取包含 OWASP/MITRE 引用的完整索引。

## 快速参考

| 漏洞 | 关键预防措施 |
|--------------|----------------|
| 提示注入 | 输入验证、输出过滤、权限分离 |
| 敏感信息泄露 | 数据清理、访问控制、加密 |
| 供应链 | 验证模型、SBOM、仅信任来源 |
| 数据中毒 | 数据验证、异常检测、沙箱 |
| 输出处理 | 将 LLM 视为不可信、编码输出、参数化查询 |
| 过度代理 | 最小权限、人工审核、最小化扩展 |
| 系统提示泄露 | 提示中无秘密、外部约束 |
| 向量/嵌入 | 访问控制、数据验证、监控 |
| 错误信息 | RAG、微调、人工监督、交叉验证 |
| 无界消耗 | 速率限制、输入验证、资源监控 |

## 关键原则

1. **永不信任 LLM 输出** - 在使用前验证和清理所有输出
2. **最小权限** - 为 LLM 系统授予最低必要权限
3. **纵深防御** - 层叠多重安全控制
4. **人工监督** - 对高影响操作要求批准
5. **监控和记录** - 跟踪所有 LLM 交互以检测异常
