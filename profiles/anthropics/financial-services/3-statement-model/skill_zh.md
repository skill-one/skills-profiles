# 3-Statement Financial Model Template Completion

完成并填充集成财务模型模板，确保损益表、资产负债表和现金流量表之间有正确的链接。

## ⚠️ 关键原则 — 在填充任何模板前阅读

**环境 — Office JS 与 Python:**
- **如果在 Excel 中运行（Office 插件 / Office JS）:** 直接使用 Office JS。通过 `range.formulas = [["=D14*(1+Assumptions!$B$5)"]]` 编写公式 — 永远不要使用 `range.values` 来填充派生单元格。无需单独重算；Excel 本地计算。使用 `context.workbook.worksheets.getItem(...)` 来导航工作表。
- **如果生成独立的 .xlsx 文件:** 使用 Python/openpyxl。编写 `ws["D15"] = "=D14*(1+Assumptions!$B$5)"`，然后运行 `recalc.py` 再交付。
- **Office JS 合并单元格陷阱:** 不要调用 `.merge()` 然后在合并范围内设置 `.values` — 会抛出 `InvalidArgument`，因为该范围仍然报告其合并前的维度。相反，仅将值写入左上角单元格，然后合并并格式化整个范围：`ws.getRange("A1").values = [["损益表"]; const h = ws.getRange("A1:G1"); h.merge(); h.format.fill.color = "#1F4E79";`
- 所有以下原则在任一环境中都完全适用。

**公式优先于硬编码（不可协商）:**
- 每个预测单元格、滚动预测、链接和总计必须是 Excel 公式 — 永远不要使用预计算值
- 使用 Python/openpyxl 时：编写公式字符串 (`ws["D15"] = "=D14*(1+Assumptions!$B$5)"`)，而不是计算结果 (`ws["D15"] = 12500`)
- 只有以下单元格应包含硬编码数字：(1) 历史实际值，(2) 假设标签中的假设驱动因素
- 如果你发现自己用 Python 计算一个值并将其写入单元格 — 停止。编写公式而不是硬编码。
- 原因：当情景切换或假设更改时，模型必须具有灵活性。硬编码会无声地破坏所有下游完整性检查。

**与用户逐步验证:**
1. **映射模板后** → 向用户展示你已识别的哪些工作表/部分，并在触摸任何单元格前确认
2. **填充历史数据后** → 向用户展示历史数据块并确认值/期间与源数据匹配
3. **构建损益表预测后** → 运行总计检查，向用户展示预测的损益表，并在进入资产负债表前确认
4. **构建资产负债表后** → 向用户展示每个期间的资产=负债+权益的平衡检查，并在进入现金流量表前确认
5. **构建现金流量表后** → 向用户展示现金核对（现金流量表期末现金=资产负债表现金），并在最终确定前确认
6. **不要端到端填充整个模型并展示完整** — 在每个报表处中断，展示工作内容，尽早发现错误

## 格式化 — 专业蓝/灰调色板（除非模板/用户指定其他颜色）

**保持颜色最小化。** 仅使用蓝色和灰色填充单元格。不要引入绿色、黄色、橙色或多种强调色 — 干净的模型使用克制。

| 元素 | 填充 | 字体 |
|---|---|---|
| 部分标题（损益表 / 资产负债表 / 现金流量表标题） | 深蓝色 `#1F4E79` | 白色加粗 |
| 列标题（FY2024A、FY2025E 等） | 浅蓝色 `#D9E1F2` | 黑色加粗 |
| 输入单元格（历史数据、假设驱动因素） | 浅灰色 `#F2F2F2` 或白色 | 蓝色 `#0000FF` |
| 公式单元格 | 白色 | 黑色 |
| 跨表链接 | 白色 | 绿色 `#008000` |
| 检查行 / 关键总计 | 中蓝色 `#BDD7EE` | 黑色加粗 |

**总共是 3 种蓝色 + 1 种灰色 + 白色。** 如果模板有自己的调色板，请遵循模板。

字体颜色表示单元格的*类型*（输入/公式/链接）。填充颜色表示*位置*（标题/数据/检查）。

## 模型结构

### 识别模板工作表组织

模板在工作表命名约定和结构上有所不同。填充前，查看所有工作表以了解模板结构。以下是常见工作表名称及其典型内容：

| 常见工作表名称 | 查找内容 |
|------------------|----------------------|
| IS、P&L、损益表 | 损益表 |
| BS、资产负债表 | 资产负债表 |
| CF、CFS、现金流量表 | 现金流量表 |
| WC、营运资本 | 营运资本表 |
| DA、D&A、折旧、PP&E | 折旧与摊销表 |
| Debt、债务表 | 债务表 |
| NOL、税务、DTA | 净经营亏损表 |
| Assumptions、Inputs、Drivers | 驱动假设和输入 |
| Checks、Audit、Validation | 错误检查面板 |

**模板审查清单**
- 确定模板中存在哪些工作表（并非所有模板都包含每个表）
- 记录任何上述列表中未列出的模板特定工作表
- 理解工作表依赖关系（例如，哪些表输入到主报表）
- 在每个工作表上定位输入单元格与公式单元格

### 理解模板结构

填充模板前，熟悉其现有布局，以确保数据输入到正确的位置，公式保持完整。

**识别行结构**
- 在每个工作表顶部找到模型标题
- 识别部分标题及其视觉分隔
- 找到单位行，指示百万美元、百分比、倍数等
- 注意区分实际值与预测期间的列标题
- 确认期间标签（例如，FY2024A、FY2025E）
- 识别输入单元格与公式单元格（通常通过字体颜色区分）

**识别列结构**
- 确认最左侧列中的项目线项
- 验证历史年份先于预测年份
- 注意区分历史与预测期间的分隔视觉边界
- 检查所有工作表上的列顺序是否一致

**使用命名范围**
模板通常使用命名范围来表示关键输入和输出。填充数据前：
- 查看模板中现有的命名范围（Excel 中的公式 → 名称管理器）
- 常见命名范围包括：收入增长率、成本百分比、关键输出（净利润、EBITDA、总债务、现金）、情景选择单元格
- 确保输入在输入到这些命名范围的单元格中

### 预测期间
- 模板通常从最后历史年份向前预测 5 年
- 验证历史（A）与预测（E）列是否清晰分隔
- 确认列使用财政年度表示（例如，FY2024A、FY2025E）

## 边际分析

**注意：以下边际分析仅在用户提示或模板明确要求时执行。如果没有提示，请跳过此部分。**

在损益表（IS）标签上计算并显示盈利边际，以跟踪运营效率和实现同行比较。

### 核心边际
| 边际 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 毛利率 | 毛利润 / 收入 | 定价能力、生产效率 |
| EBITDA 边际 | EBITDA / 收入 | 核心运营盈利能力 |
| EBIT 边际 | EBIT / 收入 | 扣除折旧与摊销后的运营盈利能力 |
| 净利润边际 | 净利润 / 收入 | 最终盈利能力 |

### 损益表布局（含边际）
直接在每条利润线项目下方显示边际百分比：
- 毛利润下方显示毛利率 %
- EBIT 下方显示 EBIT 边际 %
- EBITDA 下方显示 EBITDA 边际 %
- 净利润下方显示净利润边际 %

## 信用指标

**注意：以下信用分析仅在用户提示或模板明确要求时执行。如果没有提示，请跳过此部分。**

在资产负债表（BS）标签上计算并显示信用/杠杆指标，以评估财务健康状况、债务能力和契约合规性。

### 核心信用指标
| 指标 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 总债务 / EBITDA | 总债务 / 近 12 个月 EBITDA | 杠杆倍数 |
| 净债务 / EBITDA | (总债务 - 现金) / 近 12 个月 EBITDA | 扣除现金后的杠杆 |
| 利息保障倍数 | EBITDA / 利息支出 | 偿还债务的能力 |
| 债务 / 总资本 | 总债务 / (总债务 + 股本) | 资本结构 |
| 债务 / 股本 | 总债务 / 总股本 | 财务杠杆 |
| 流动比率 | 流动资产 / 流动负债 | 短期流动性 |
| 速动比率 | (流动资产 - 存货) / 流动负债 | 即时流动性 |

### 信用指标层级检查
验证 Upside 显示最强的信用状况：
- 杠杆：Upside < Base < Downside（越低越好）
- 覆盖率：Upside > Base > Downside（越高越好）
- 流动性：Upside > Base > Downside（越高越好）

### 契约合规性跟踪

如果已知债务契约，请添加明确的合规性检查，比较实际指标与契约阈值。

## 情景分析（基准 / Upside / Downside）

在假设标签中使用下拉菜单和 CHOOSE 或 INDEX/MATCH 公式。

| 情景 | 描述 |
|----------|-------------|
| 基准情景 | 管理层指导或共识估计 |
| Upside 情景 | 高于指导的增长、利润率扩张 |
| Downside 情景 | 低于趋势的增长、利润率压缩 |

**关键驱动因素**: 收入增长、毛利率、SG&A%、DSO/DIO/DPO、资本支出%、利率、税率。

**情景审计检查**: 切换所有报表，所有情景中的资产负债表平衡，现金核对，层级保持（Upside > 基准 > Downside 对于 NI、EBITDA、FCF、边际）。

## 完成模型模板

本节提供完成任何 3-报表财务模型模板的一般指南，同时保留现有公式并确保数据完整性。

### 第 1 步：分析模板结构

在输入任何数据前，彻底审查模板以了解其架构：

**识别输入单元格与公式单元格**
- 寻找区分输入单元格与公式单元格的视觉提示（字体颜色、单元格阴影）
- 常见约定：蓝色字体 = 输入，黑色字体 = 公式，绿色字体 = 其他表链接
- 使用 Excel 的追踪前导项/依赖项（公式 → 追踪前导项）来了解单元格关系
- 检查可能控制关键输入的命名范围（公式 → 名称管理器）

**绘制模板流程**
- 确定哪些工作表输入到其他工作表（例如，假设 → 损益表 → 资产负债表 → 现金流量表）
- 注意任何支持表及其与主报表的链接
- 在填充前记录模板的特定线项和结构

### 第 2 步：填充数据而不破坏公式

**数据输入黄金规则**

| 规则 | 描述 |
|------|-------------|
| 仅编辑输入单元格 | 永远不要覆盖包含公式的单元格，除非有意替换公式 |
| 保留单元格引用 | 当复制数据时，使用粘贴值（Ctrl+Shift+V）以避免用源格式覆盖公式 |
| 匹配模板的单位 | 在输入数据前验证模板使用千、百万或实际值 |
| 尊重符号约定 | 遵循模板现有的符号约定（例如，费用为正或负） |
| 检查循环引用 | 如果模板使用迭代计算，确保 Excel 中启用了迭代计算 |

**安全数据输入流程**
1. 确定指定为输入的精确单元格（通常突出显示或标记）
2. 首先输入历史数据，然后验证公式是否正确计算这些期间
3. 输入驱动预测计算的假设驱动因素
4. 审核计算输出以确认公式按预期工作
5. 如果必须修改公式单元格，在更改前记录原始公式

**处理预构建公式**
- 如果公式引用你尚未填充的单元格，直到所有输入完成前可能会出现临时错误（#REF!、#DIV/0!）
- 当公式产生意外结果时，追踪前导项以识别缺失或错误的输入
- 永远不要删除行/列，除非检查所有工作表上的公式依赖关系

### 第 3 步：验证公式

**公式完整性检查**

在依赖模板输出前，验证公式是否正常工作：

| 检查类型 | 方法 |
|------------|--------|
| 追踪前导项 | 选择公式单元格 → 公式 → 追踪前导项以验证它是否引用正确的输入 |
| 追踪依赖项 | 验证关键输入是否流到预期输出单元格 |
| 评估公式 | 使用公式 → 评估公式以逐步执行复杂计算 |
| 检查硬编码 | 预测公式应引用假设，而不是包含硬编码值 |
| 使用已知值测试 | 输入简单测试值以验证公式产生预期结果 |
| 跨表一致性 | 确保相同的公式逻辑适用于所有预测期间 |

**常见公式问题**
- 混合绝对/相对引用导致复制期间时结果不正确
- 外部文件或删除范围的链接中断（#REF! 错误）
- 早期期间除以零（#DIV/0! 错误）
- 循环引用警告（可能有意用于利息计算）
- 预测期间公式不一致（使用 Ctrl+\ 查找差异）

**验证跨表链接**
- 确认出现在多个工作表中的值是链接的（不是复制的）
- 验证表总计与主报表中的对应线项相匹配
- 检查所有工作表中的期间标签是否一致

### 第 4 步：按工作表进行质量检查

填充模板后，在每个工作表上执行以下验证检查：

**损益表（IS）质量检查**
- 收入数字与历史期间源数据匹配
- 所有费用线项总和与报告总数匹配
- 所有总计（毛利润、EBIT、EBT、净利润）计算正确
- 税计算逻辑适当（正确处理亏损）
- 预测驱动因素引用假设标签（无硬编码）
- 期间间变化方向合理

**资产负债表（BS）质量检查**
- 每个期间的资产 = 负债 + 权益（主要检查）
- 现金余额与现金流量表期末现金匹配
- 营运资本账户与支持表链接（如适用）
- 留存收益正确滚动：前期留存收益 + 净利润 - 股息 +/- 调整 = 期末留存收益
- 债务余额与债务表链接（如适用）
- 所有资产负债表项目具有适当符号（资产为正，大多数负债为正）

**现金流量表（CF）质量检查**
- 顶部的 CFO 中的净利润与损益表净利润匹配
- 非现金加回（折旧与摊销、营运资本变动等）与源表/报表链接
- 营运资本变动具有正确符号（资产增加 = 现金使用 = 负）
- 资本支出与 PP&E 表或固定资产滚动预测链接
- 融资活动与资产负债表上的债务和权益账户变化链接
- 期末现金与资产负债表现金匹配
- 期初现金等于上一期期末现金

**支持表质量检查**
- 期初余额等于上一期期末余额
- 滚动逻辑完整（期初 + 增加额 - 减少额 = 期末）
- 表总计与主报表线项链接
- 计算中使用的假设与假设标签匹配

### 第 5 步：跨报表完整性检查

验证单个工作表后，确认三个报表是否正确集成：

| 检查 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表平衡 | 资产 - 负债 - 权益 | = 0 |
| 现金核对 | CF 期末现金 - BS 现金 | = 0 |
| 净利润链接 | IS 净利润 - CF 期初净利润 | = 0 |
| 留存收益 | 前期留存收益 + 净利润 + 营运资本变动 - 股息 - BS 期末留存收益 | = 0 (根据需要调整 SBC/其他项目) |

### 第 6 步：最终审查

在考虑模型完成前：
- 切换所有情景（如果适用）以验证每个情况下都通过检查
- 审查所有 #REF!、#DIV/0!、#VALUE! 和 #NAME? 错误并解决或记录
- 确认所有输入单元格已填充（搜索占位符值）
- 验证所有标签上的单位一致
- 在进行任何其他修改前保存干净版本

## 模型验证和审计

本节汇总了完成模板的所有验证检查和审计程序。

### 核心链接（必须始终成立）

有关所有公式详情，请参阅 [references/formulas.md](references/formulas.md)。

| 检查 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表平衡 | 资产 - 负债 - 权益 | = 0 |
| 现金核对 | CF 期末现金 - BS 现金 | = 0 |
| 月度现金与年度现金 | 月度期末现金 - 年度期末现金 | = 0 |
| 净利润链接 | IS 净利润 - CF 期初净利润 | = 0 |
| 留存收益 | 前期留存收益 + 净利润 + 营运资本变动 - 股息 - BS 期末留存收益 | = 0 |
| 股本融资 | Δ普通股/APIC (BS) - 股本发行 (CFF) | = 0 |
| 第 0 年权益 | 第 0 年融资的权益 - 第 1 年期初权益资本 | = 0 |

### 符号约定参考

| 报表 | 项目 | 符号约定 |
|-----------|------|-----------------|
| CFO | 折旧与摊销、营运资本变动 | 正（加回） |
| CFO | 应收账款增加 | 负（现金使用） |
| CFO | 应付账款增加 | 正（现金来源） |
| CFI | 资本支出 | 负 |

### 循环引用处理

利息支出导致循环：利息 → 净利润 → 现金 → 债务余额 → 利息

在 Excel 中启用迭代计算：文件 → 选项 → 公式 → 启用迭代计算。将最大迭代次数设置为 100，最大更改设置为 0.001。在假设标签中添加一个电路断路器切换。

### 检查类别

**第 1 部分：货币一致性**
- 货币已识别并记录在假设中
- 所有标签使用一致的货币符号和比例
- 单位行与模型货币匹配

**第 2 部分：资产负债表完整性**
- 资产 = 负债 + 权益（每个期间）
- 公式：资产 - 负债 - 权益（必须 = 0）

**第 3 部分：现金流量完整性**
- 现金与资产负债表链接（CF 期末现金 = BS 现金）
- 月度现金与年度现金：月度期末现金 = 年度期末现金
- 净利润与 IS 链接（CF 净利润 = IS 净利润）
- 折旧与摊销与表链接
- 营运资本变动与 IS 链接
- 资本支出与 DA 表链接
- 融资活动与资产负债表上的债务和权益账户链接
- 期末现金与资产负债表现金匹配
- 期初现金等于上一期期末现金

**第 4 部分：留存收益**
- 留存收益滚动检查：前期留存收益 + 净利润 + 营运资本变动 - 股息 = 期末留存收益
- 显示组件分解以进行调试

**第 5 部分：营运资本**
- 应收账款、存货、应付账款与资产负债表链接
- DSO、DIO、DPO 合理性检查（如果超出正常范围则标记）

**第 6 部分：债务表**
- 总债务与资产负债表链接（当前 + 长期债务）
- 利息计算与 IS 链接

**第 6b 部分：股权融资**
- 股权发行收益与 BS 普通股/APIC 增加额链接
- 股权带来的现金增加 = 股权账户增加（必须平衡）
- 股权融资核对：Δ普通股/APIC (BS) = 股权发行 (CFF)（必须 = 0）
- 第 0 年权益核对：第 0 年融资的权益 = 第 1 年期初权益资本

**第 6c 部分：NOL 表**
- 第 1 年/成立时的期初 NOL = 0（新企业从零 NOL 开始）
- 仅当 EBT < 0 时 NOL 才增加（亏损必须实现才能产生 NOL）
- DTA 与资产负债表链接（NOL 表 DTA = 资产负债表递延所得税资产）
- NOL 利用 ≤ 80% 的 EBT（2017 年后联邦限制）
- NOL 余额为非负（不能利用超过可用的 NOL）
- 仅当 EBT < 0 时才产生 NOL
- 当应税收入 ≤ 0 时税费用 = 0

**第 7 部分：情景层级**
- 绝对指标：Upside > 基准 > Downside（越高越好）（NI、EBITDA、FCF）
- 边际：Upside > 基准 > Downside（越高越好）（毛利率%、EBITDA%、净利润%）
- 信用指标：Upside < 基准 < Downside 对于杠杆（反向）

**第 8 部分：公式完整性**
- COGS、S&M、G&A、R&D、SBC 由收入百分比驱动（无硬编码）
- 预测期间公式一致
- 无 #REF!、#DIV/0!、#VALUE! 错误

**第 9 部分：信用指标阈值**
- 根据契约阈值将指标标记为绿色/黄色/红色
- 任何红色标志的摘要

### 主检查公式

将所有部分状态汇总为单个主检查：
- 如果所有部分通过 → "✓ 所有检查通过"
- 如果任何部分失败 → "✗ 检测到错误 - 以下为详细信息"

### 快速调试工作流

当主状态显示错误时：
1. 滚动到查找红色突出显示的部分
2. 确定哪个检查类别失败
3. 导航到源标签进行调查
4. 修复根本问题
5. 返回检查标签以验证解决
