# 审计电子表格

审计公式和数据以确保准确性和错误。范围决定了深度——从对选定范围的快速公式检查到完整的财务模型完整性审计。

## 第 1 步：确定范围

如果用户已经给出了范围，则使用它。否则，**询问他们**：

> 你希望我审计哪个范围？
> - **选定范围** — 仅当前选定的范围
> - **工作表** — 仅当前活动工作表
> - **模型** — 整个工作簿，包括财务模型完整性检查（资产负债表平衡、现金核对、滚动前、逻辑合理性）

**模型**范围是最深的——用于在发送给客户或投资银行之前对 DCF、LBO、三报表、并购、可比公司分析或任何集成财务模型进行审计。

---

## 第 2 步：公式级检查（所有范围）

无论范围如何，都需要运行这些检查：

| 检查项 | 查找内容 |
|---|---|
| 公式错误 | `#REF!`、`#VALUE!`、`#N/A`、`#DIV/0!`、`#NAME?` |
| 公式中的硬编码 | `=A1*1.05` — `1.05` 应该是单元格引用 |
| 不一致的公式 | 行/列中破坏其邻近公式模式的公式 |
| 偏移一位的范围 | `SUM`/`AVERAGE` 错过第一行或最后一行 |
| 粘贴覆盖的公式 | 看起来像公式但实际上是硬编码值的单元格 |
| 循环引用 | 故意的或意外的 |
| 损坏的跨工作表链接 | 引用已移动或已删除的单元格 |
| 单位/规模不匹配 | 千位与百万位混用，百分比存储为整数 |
| 隐藏的行/工作表 | 可能包含覆盖或过时的计算 |

---

## 第 3 步：模型完整性检查（仅限模型范围）

如果范围是 **模型**，请识别模型类型（DCF / LBO / 三报表 / 并购 / 可比公司分析 / 自定义），并运行以下相应的完整性检查。

### 3a. 结构审查

| 检查项 | 查找内容 |
|---|---|
| 输入/公式分离 | 输入是否与计算清晰分离？ |
| 颜色约定 | 蓝色=输入，黑色=公式，绿色=链接 — 或模型使用的任何约定，是否一致应用？ |
| 工作表流程 | 逻辑顺序（假设 → IS → BS → CF → 估值）？ |
| 日期标题 | 所有工作表是否一致？ |
| 单位 | 是否一致（千位 vs 百万位 vs 实际值）？ |

### 3b. 资产负债表

| 检查项 | 测试 |
|---|---|
| 资产负债表平衡 | 总资产 = 总负债 + 股东权益（每个期间） |
| 留存收益滚动前 | 期初留存收益 + 净收入 - 股利 = 期末留存收益 |
| 商誉/无形资产 | 来自收购假设的现金流（如果涉及并购） |

如果资产负债表不平衡，**按期间量化差距并追踪哪里出现问题** — 在解决这个问题之前，其他一切都无关紧要。

### 3c. 现金流量表

| 检查项 | 测试 |
|---|---|
| 现金核对 | 期末现金 = 资产负债表现金（每个期间） |
| 现金流量表总和 | CFO + CFI + CFF = 现金变动 |
| 折旧与摊销匹配 | 现金流量表中的折旧与摊销 = 利润表中的折旧与摊销 |
| 资本支出匹配 | 现金流量表中的资本支出与资产负债表中的固定资产滚动前匹配 |
| 应收账款变化 | 符号与资产负债表变动一致（ΔAR、ΔAP、Δ库存） |

### 3d. 利润表

| 检查项 | 测试 |
|---|---|
| 收入构建 | 与部门/产品明细挂钩 |
| 税务 | 税费 = 税前收入 × 税率（允许递延税调整） |
| 股份数量 | 与稀释时间表挂钩（期权、可转换证券、回购） |

### 3e. 循环引用

- 利息 → 债务余额 → 现金 → 利息是 LBO/三报表模型中常见的故意循环
- 如果是故意的：验证迭代开关是否存在且正常工作
- 如果是无意的：追踪循环并标记如何打破它

### 3f. 逻辑和合理性

| 检查项 | 标记如果 |
|---|---|
| 增长率 | 收入增长率超过 100% 而没有解释 |
| 利润率 | 超出行业规范 |
| 终值主导 | TV > ~75% 的 DCF EV（黄色警告） |
| 冰球棒效应 | 预测在远期不切实际地增长 |
| 复利 | EBITDA 在第 10 年复合到荒谬的金额 |
| 边缘情况 | 模型在 0% 或负增长、负 EBITDA、杠杆为负时崩溃 |

### 3g. 模型类型特定错误

**DCF:**
- 折现率应用于错误期间（年中 vs 年末）
- 终值未折现
- WACC 使用账面价值而不是市场价值
- 自由现金流包括利息支出（应为无杠杆）
- 税盾双重计算

**LBO:**
- 债务偿还与现金清理机制不匹配
- PIK 利息未计提至本金
- 管理层滚动未反映在回报中
- 出售倍数应用于错误的 EBITDA（LTM vs NTM）
- 费用/支出未从第一天股权中扣除

**并购:**
- 收购/稀释使用错误的股份数量（交易前 vs 交易后）
- 协同效应未分阶段实现
- 购买价格分配不平衡
- 现金递延利息未包含
- 交易费用未包含在来源与使用中

**三报表:**
- 应收账款变化符号错误
- 折旧与固定资产计划不匹配
- 债务到期计划与本金支付不匹配
- 股利超过净收入而没有解释

## 第 4 步：报告

输出一个发现表格：

| 编号 | 工作表 | 单元格/范围 | 严重性 | 类别 | 问题 | 建议修复 |
|---|---|---|---|---|---|---|

**严重性:**
- **关键** — 错误输出（资产负债表不平衡、公式损坏、现金不核对）
- **警告** — 有风险（硬编码、不一致的公式、边缘情况失败）
- **信息** — 格式/最佳实践（颜色编码、布局、命名）

对于 **模型** 范围，请添加一个摘要行：

> 模型类型：[DCF/LBO/三报表...] — 总体：[无问题 / 轻微问题 / 严重问题] — [N] 个关键问题，[N] 个警告，[N] 个信息

**不要在不询问的情况下更改任何内容** — 先报告，再按请求修复。

---

## 注意事项

- **首先检查资产负债表平衡** — 如果不平衡，所有后续内容都有疑问
- **硬编码覆盖是沉默错误的 #1 来源** — 积极搜索
- **现金流出正负符号错误**（正 vs 负）非常常见
- 如果模型使用 VBA 宏，请注意任何无法仅通过公式审计的宏驱动计算
