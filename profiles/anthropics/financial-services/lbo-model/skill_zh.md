## 对CLAUDE的关键指示 - 首先阅读

### 环境：Office JS与Python

**如果在Excel（Office插件/Office JS环境）中运行：**
- 直接使用Office JS (`Excel.run(async (context) => {...})`) — 不要使用Python/openpyxl
- 通过 `range.formulas = [["=B5*B6"]]` 写入公式 — Office JS公式在实时工作簿中原生重新计算
- 相同的公式优先于硬编码规则适用：为应计算的内容设置 `range.formulas`，而不是 `range.values`
- 使用 `range.format.font.color` / `range.format.fill.color` 用于蓝色/黑色/紫色/绿色的约定
- 无需单独的重新计算步骤 — Excel原生处理计算
- **合并单元的陷阱**：不要在合并范围内调用 `.merge()` 然后设置 `.values`（会抛出 `InvalidArgument` — 范围仍然报告原始维度）。相反：仅向合并范围的左上角单元格写入值 (`ws.getRange("A7").values = [["SOURCES & USES"]]`), 然后合并+格式化整个范围 (`ws.getRange("A7:F7").merge(); ws.getRange("A7:F7").format.fill.color = "#1F4E79";`)

**如果生成独立的.xlsx文件（无实时Excel会话）：**
- 使用Python/openpyxl，如下所述
- 写入公式字符串 (`ws["D20"] = "=B5*B6"`), 然后在交付前运行 `recalc.py`

此技能的其余部分使用openpyxl示例编写，但相同的原理适用于Office JS — 仅需转换API调用。

### 核心原则
* **每个计算必须是Excel公式** - 永远不要在Python中计算值并将结果硬编码到单元格中。在使用openpyxl时，写 `cell.value = "=B5*B6"`（公式字符串），而不是 `cell.value = 1250`（计算结果）。模型必须在输入更改时动态更新。
* **使用模板结构** - 遵循 `examples/LBO_Model.xlsx` 或用户提供模板中的组织结构。不要自己发明布局。
* **使用正确的单元格引用** - 所有公式都应引用适当的单元格。永远不要键入应来自其他单元格的数字。
* **保持符号约定的一致性** - 遵循模板使用的任何符号约定（一些使用负数表示流出，一些使用正数）。始终如一。
* **按部分工作，每一步与用户验证** - 完成一个部分，向用户展示已构建的内容，运行该部分的验证检查，并在继续下一个部分之前获得确认。不要端到端构建整个模型然后呈现 — 后续部分依赖于早期部分，所以在构建资金来源与使用后才发现回报部分的错误意味着需要全面返工。

### 公式颜色约定
* **蓝色 (0000FF)**：硬编码输入 - 直接输入的数字，不引用其他单元格
* **黑色 (000000)**：计算公式 - 任何使用运算符或函数的公式 (`=B4*B5`, `=SUM()`, `=-MAX(0,B4)`)
* **紫色 (800080)**：链接到同一工作表中的单元格 - 无计算的直接引用 (`=B9`, `=B45`)
* **绿色 (008000)**：链接到不同工作表中的单元格 - 跨表引用 (`=Assumptions!B5`, `='Operating Model'!C10`)

### 填充颜色调色板 — 专业蓝灰色（除非用户/模板指定其他颜色）
* **保持简洁** — 仅使用蓝色和灰色进行单元格填充。不要引入绿色、黄色、红色或多个强调色。专业的LBO模型使用节制。
* **默认填充调色板：**
  * **部分标题**（资金来源与使用、运营模型等.）：深蓝色 `#1F4E79` 带白色粗体文本
  * **列标题**（第1年、第2年等.）：浅蓝色 `#D9E1F2` 带黑色粗体文本
  * **输入单元格**：浅灰色 `#F2F2F2`（或仅白色） — 蓝色*字体*是信号，填充是次要的
  * **公式/计算单元格**：白色，无填充
  * **关键输出**（IRR、MOIC、退出股权）：中等蓝色 `#BDD7EE` 带黑色粗体文本
* **这就是全部调色板。** 3种蓝色 + 1种灰色 + 白色。如果模板使用自己的颜色，请遵循模板。
* 注意：上述蓝色/黑色/紫色/绿色的**字体**颜色用于区分输入与公式与链接。这些与这里的**填充**调色板是分开的 — 两者协同工作。

### 数字格式标准
* **货币**：`$#,##0;($#,##0);"-"` 或 `$#,##0.0` 取决于模板
* **百分比**：`0.0%`（一位小数）
* **倍数**：`0.0"x"`（一位小数）
* **MOIC/详细比率**：`0.00"x"`（两位小数以保持精度）
* **所有数字单元格**：右对齐

## 常见问题区域

以下计算模式在LBO模型中经常导致问题。在您遇到这些情况时请特别注意：

### 平衡部分
* 当两个部分必须相等（例如，资金来源=使用）时，通常有一个项目是"调节项"（平衡数字）
* 确定哪个项目是调节项，并计算它作为差额

### 税计算
* 税公式应仅引用相关收入线和税率
* 不应引用不相关的部分（例如，债务计划）
* 考虑亏损是否产生税收抵免或仅被忽略

### 利息和循环引用
* 利息计算如果引用受现金流影响的余额可能会产生循环
* 使用**期初余额**（不是平均或期末）来打破循环
* 模式：利息 → 现金流 → 还款 → 期末余额（如果利息使用期末余额，这将循环回）

### 债务偿还 / 现金清理
* 当存在多个债务层级时，通常有一个优先级顺序
* 现金清理应尊重优先级瀑布
* 余额不能为负 - 适当使用MAX或MIN函数

### 回报计算（IRR/MOIC）
* 现金流必须具有正确的符号：投资=负，收益=正
* 如果使用XIRR，需要相应的日期
* 如果使用IRR，现金流应在连续的期间内
* MOIC = 总收益 / 总投资

### 敏感性表
* **使用奇数维度**（5×5或7×7）— 永远不要4×4或6×6。奇数维度保证有真正的中心单元格。
* **中心单元格=基准情况。** 对称地围绕模型的实际假设构建行和列轴值（例如，如果基准倍数=10.0x，轴=`[8.0x, 9.0x, 10.0x, 11.0x, 12.0x]`）。中心单元格的IRR/MOIC必须等于模型的实际IRR/MOIC输出 — 这是证明表格正确连接的证明。
* **突出显示中心单元格** — 中等蓝色填充 `#BDD7EE` + 粗体字，以便视觉锚定基准情况。
* Excel的DATA TABLE函数可能不适用于openpyxl — 相反，应编写显式公式引用行/列标题
* 每个数据单元格应显示不同的值 — 如果都相同，公式可能没有正确变化
* 使用混合引用（例如，`$A5`为行输入，`B$4`为列输入）

## 常见错误避免

| 错误 | 出现问题 | 如何修复 |
|-------|----------|----------|
| 硬编码计算值 | 模型在输入更改时不更新 | 始终使用引用源单元格的公式 |
| 复制后单元格引用错误 | 公式指向错误的单元格 | 验证所有链接，使用适当的$锚定 |
| 循环引用错误 | 模型无法计算 | 使用期初余额进行利息类型计算，打破循环 |
| 部分不平衡 | 应该匹配的总额不匹配 | 确保有一个项目是调节项（计算为差额） |
| 不可能的负余额 | 支付/使用超过可用量 | 适当使用MAX(0, ...)或MIN函数 |
| IRR/回报错误 | 错误的符号或范围不完整 | 检查现金流符号并确保公式覆盖所有期间 |
| 敏感性表显示相同值 | 公式未随输入变化 | 检查单元格引用 - 需要$A5, B$4等混合引用 |
| 滚动前不匹配 | 期初 ≠ 上一期期末 | 验证期间之间的链接 |
| 不一致的符号约定 | 加法变成减法或反之 | 始终如一地遵循模板的约定 |
