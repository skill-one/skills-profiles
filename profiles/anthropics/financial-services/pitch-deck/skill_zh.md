## ⚠️ 关键渲染限制

**LibreOffice 用于验证，但无法准确渲染 PowerPoint 文件。** 它会扭曲字体、渐变、形状位置、文本换行和某些表格格式。

**这意味着：** 在 LibreOffice 中通过视觉验证的幻灯片可能仍在 Microsoft PowerPoint 中存在问题。验证循环可以捕获结构性问题（缺少内容、表格损坏、保留占位符格式），但**无法**捕获字体替换、微妙的对齐偏移或渐变问题。

**必须采取的行动：** 在交付输出时始终包含此声明：
> "此文件使用 LibreOffice 进行了验证。请在分发前在 Microsoft PowerPoint 中进行审查，因为渲染差异可能存在。"

## 模板填充工作流程

复制并跟踪进度：

```
演示文稿进度：
- [ ] 第一阶段：提取和验证源数据
- [ ] 第二阶段：将内容映射到模板部分
- [ ] 第三阶段：使用正确格式填充幻灯片
- [ ] 第四阶段：验证 → 修复 → 重复直到干净
- [ ] 第五阶段：最终验证
```

### 第一阶段：数据提取
1. **在修改原始模板之前创建备份** — 复制到 `[filename]_backup.pptx`。直接 XML 编辑或意外错误可能会损坏文件。
2. 确定所有源材料（Excel、CSV、PDF 报告、Word 文档、数据库、网络来源）
3. 从每个源中提取相关数据点
4. 验证所有数字与原始来源
5. 统一单位和货币（将所有数字转换为模板中使用的首选单位/货币）
6. 记录需要验证的任何计算 → 查看 [`calculation-standards.md`](reference/calculation-standards.md) 获取公式

### 第二阶段：内容映射
1. **打开并视觉审查模板** — 在修改之前了解其结构、样式和现有内容
2. 分析模板结构 — 确定所有占位符区域和内容框
3. 将源数据映射到相应的模板部分 → 查看 [`slide-templates.md`](reference/slide-templates.md) 获取映射指南
4. 确定占位符指导框（任务创建者提供的彩色指令框）
5. 记录任何数据差距或不匹配 → 查看 [`slide-templates.md`](reference/slide-templates.md#handling-data-template-mismatches) 获取解决方案

### 第三阶段：模板填充
1. **删除或重新格式化占位符框** — 彩色指令框显示要创建的内容，而不是如何格式化。删除它们并在其位置创建正确格式的内容。查看 [关键反模式](#critical-anti-patterns-never-do-these)。
2. 使用映射的内容填充每个部分（首先关注内容）
3. **然后应用格式**以匹配模板样式 → 查看 [`formatting-standards.md`](reference/formatting-standards.md)
4. 创建表格作为实际表格对象（**绝对不要**使用管道/制表符分隔的文本）→ 查看 [`xml-reference.md`](reference/xml-reference.md#table-implementation)
5. 创建箭头/形状作为 PowerPoint 对象 → 查看 [`xml-reference.md`](reference/xml-reference.md#arrow-shapes)
6. 如果任务文件中提供了公司标志，则插入公司标志；如果未提供，则向用户标记："[LOGO NOT PROVIDED - 请提供公司标志]"

### 第四阶段：验证 → 修复 → 重复

**这是一个反馈循环。重复直到所有检查通过或触发升级。**

```bash
# 转换为图像进行视觉验证
soffice --headless --convert-to pdf presentation.pptx
pdftoppm -jpeg -r 150 presentation.pdf slide
```

**验证清单（检查每个幻灯片图像）：**
- [ ] 文本是否在背景上可读？
- [ ] 表格是否为实际对象（列对齐，**不是**管道/制表符分隔的文本）？
- [ ] 图表/表格是否填充指定区域？
- [ ] 每个部分的段落格式是否一致？
- [ ] 同一级别的框的字体大小是否匹配？
- [ ] 所有内容是否都在幻灯片边界内？
- [ ] **保留**没有占位符格式（没有填充数据的大彩色框）？
- [ ] **没有**基于文本的“表格”（没有 `|` 或制表符分隔符创建的假列）？
- [ ] **跨幻灯片一致性**：所有幻灯片上出现的相同指标/数字是否相同？

**修复周期协议：**

| 周期 | 操作 |
|------|------|
| 1 | 修复所有已识别的问题，重新验证 |
| 2 | 修复剩余问题，重新验证 |
| 3 | 如果问题仍然存在，记录剩余问题并升级给用户 |

**在 3 个周期后，如果问题仍然存在：**
1. 列出每个未解决的问题，包括幻灯片编号和描述
2. 解释尝试了什么
3. 将文件交付给带有明确免责声明的文件： "以下问题无法自动解决：[列表]。需要人工审查。"

**不要**无限期地继续循环。某些问题（字体渲染、复杂形状对齐）可能需要在 PowerPoint 中进行人工干预。

### 第五阶段：最终验证

在交付之前，运行 [最终质量清单](#final-quality-checklist)。

## 快速参考表格

### 项目符号符号

| 上下文 | 符号 | 使用 |
|--------|------|------|
| 包含/正面 | ✓ | 范围内的项目、功能存在 |
| 排除/负面 | × | 范围外的项目、功能缺失 |
| 中性列表 | • | 一般枚举、评论 |
| 编号序列 | 1. 2. 3. | 步骤、排名 |
| 子项目符号 | – | 主要项目符号下的次要点 |

### 幻灯片层级（典型）

这些是典型范围——根据模板规范进行调整：

| 级别 | 示例 | 典型大小 | 样式 |
|------|------|----------|------|
| 标题 | 幻灯片标题 | 40-48pt | 粗体 |
| 副标题 | 市场定义、幻灯片描述符 | 18-22pt | 粗体 |
| 部分标题 | "关键预测"、"评论" | 14-16pt | 常规 |
| 块标签 | "包含部分"、"定义"侧边栏 | 12-14pt | 常规 |
| 块内容 | 项目符号点、正文 | 11-14pt | 常规 |
| 表格标题 | 列标题 | 10-12pt | 粗体 |
| 表格内容 | 单元格内容 | 9-11pt | 常规 |
| 脚注 | 来源、注释 | 8-9pt | 斜体 |

### 字体一致性匹配

同一层级**的框必须使用相同的字体大小**：

| 同一级别 | 必须与...匹配 |
|--------|--------------|
| "包含部分" | "排除部分" |
| "定义" | "范围理由" |
| 左侧列项目符号 | 右侧列项目符号 |
| 所有块标签 | 每个其他 |
| 所有部分标题 | 每个其他 |

### 演示文稿中的舍入

这些是**典型约定**——根据值的幅度和模板样式进行调整：

| 值类型 | 典型舍入 | 示例 |
|--------|----------|------|
| 大市场规模 ($10bn+) | 最近的 $1bn | 18.5 → $19bn |
| 较小的市场规模 (<$10bn) | 最近的 $0.5bn 或 $0.1bn | 2.3 → $2.5bn |
| 规模范围 | 与来源的精度匹配 | 14.9-22.1 → $15-22bn |
| CAGR | 整数 % 或 0.5% | 16.4% → 16% 或 16.5% |
| 市场份额 | 最近的 5% 或与来源匹配 | 21.4% → 20% |
| 倍数 | 1 位小数 | 9.69 → 9.7x |

**原则：** 舍入不应实质性改变数字。对于较小的值，使用更精细的精度。

### 文本密度规则

- 每个内容框最多 6-7 个项目符号
- 每个项目符号点最多 2 行
- 括号示例：同一条线或缩进在下方
- 没有孤立的单词（单字在新行上）

### 对齐原则

**垂直堆叠的框必须具有相同的：**
- 左侧边距位置、项目符号缩进、文本起始位置、框宽度

**水平相邻的框必须具有相同的：**
- 顶部位置、高度（如果可能）、内部填充

### 多幻灯片一致性

当相同的数据出现在多个幻灯片上时：
- 使用相同的数字、格式和术语
- 如果一个幻灯片上的指标更新，请更新所有出现的位置
- 在验证时进行交叉引用以捕获不匹配

## 必须要求

无论模板如何，这些要求都是非协商的：

| 要求 | 详细信息 |
|------|----------|
| **文本可读性** | 所有文本必须与背景具有足够的对比度。示例：白色/浅色文本在深蓝色、深绿色、黑色背景上；黑色/深色文本在白色、浅灰色、浅黄色背景上。 |
| **实际表格对象** | 表格数据必须是表格对象，而不是管道/制表符分隔的文本。查看 [`xml-reference.md`](reference/xml-reference.md#table-implementation)。 |
| **正确的图表/表格大小** | 粘贴的视觉元素必须填充指定区域。查看 [`formatting-standards.md`](reference/formatting-standards.md#chart-and-image-handling)。 |
| **一致的格式** | 同一部分内的项目符号必须匹配（符号、大小、缩进）。同一级别的框必须使用相同的字体大小。 |
| **内容边界** | 所有内容必须保持在幻灯片边缘。脚注框宽度：~32.5cm（16:9），~24cm（4:3）。 |
| **没有占位符格式** | 删除彩色指令框。正文：深色文本在浅色背景上（根据模板）。 |

## 关键反模式：绝对不要这样做

当占位符格式被误认为输出格式时，就会发生这些错误。识别这些模式至关重要。

### 反模式 1：将数据填充到占位符框中

**会发生什么：** 模板中有彩色指令框（黄色、橙色等），其中包含指导文本。模型将指导文本替换为实际数据，但**保留**了彩色框。

**为什么这是错误的：** 彩色框是占位符。它告诉你要在哪里放置内容。输出应该具有不同的格式——通常为深色文本在浅色背景上，或正确样式的形状。

**识别测试：** 如果您的填充幻灯片有填充数据的大彩色矩形，则您复制了占位符格式而不是替换它。

**关键区别——两种类型的“占位符”：**

| 类型 | 如何识别 | 应该做什么 |
|------|----------|------------|
| **指令框** | 亮色（黄色、橙色），包含指导文本，如“在此处插入 X”，白色/浅色文本在彩色背景上 | 删除整个形状，然后创建新的内容并使用生产格式 |
| **布局占位符** | 是幻灯片母版/布局的一部分，中性颜色匹配模板主题，"点击添加文本" | 保留形状，仅替换文本内容 |

如果不确定：检查是否可以从同一模板的空幻灯片中找到该形状。布局占位符会持续存在；指令框是普通形状。

### 反模式 2：基于文本的“表格”

**会发生什么：** 模型使用分隔符字符（`|`、制表符、空格）创建表格样式内容，而不是实际表格对象。

**为什么这是错误的：** 这**不是**表格。列永远不会对齐正确，无法一致地格式化，看起来不专业。

**识别测试：** 如果您正在输入 `|` 字符或依赖空格/制表符创建列，您正在创建文本，而不是表格。

**必须验证：** 创建任何表格后，验证它是否是实际表格对象。查看 [`xml-reference.md`](reference/xml-reference.md#critical-verify-tables-are-actual-table-objects) 获取验证方法。

### 反模式 3：继承占位符对比度

**会发生什么：** 占位符使用浅色文本在彩色背景上（例如，白色在黄色上）。模型填充数据但保留此颜色方案，导致难以阅读的输出。

**为什么这是错误的：** 占位符颜色是故意不同的，以指示“替换我”。生产幻灯片通常使用深色文本在浅色背景上用于正文内容。

**识别测试：** 如果您的填充内容在正文区域具有浅色/白色文本在亮色背景上，则您继承了占位符格式。

**正确方法：** 应用生产格式——通常为深色文本 (#000000 或 #333333) 在白色或浅色背景上用于正文内容。标题和强调区域可以使用品牌颜色。

### 总结：占位符与生产

| 元素 | 占位符（输入） | 生产（输出） |
|------|----------------|----------------|
| 指令框 | 彩色背景，指导文本 | 删除或重新格式化 |
| 数据区域 | "[在此处插入数据]"文本 | 实际数据并具有干净的格式 |
| 表格 | 应该包含的表格描述 | 实际表格对象（具有行/列） |
| 正文文本 | 浅色文本在彩色背景上 | 深色文本在浅色背景上 |

**占位符告诉您要创建什么，而不是如何格式化它。**

## 错误处理

**如果 PDF/图像转换失败：**
1. 检查 LibreOffice 是否已安装：`which soffice`
2. 尝试替代方案：`libreoffice --headless --convert-to pdf presentation.pptx`
3. 如果仍然失败，请手动在 PowerPoint/LibreOffice 中打开并导出

**如果源数据存在不一致或冲突：**
1. **优先顺序**：首先使用任务文件中明确提供的源数据
2. 如果使用来自其他来源（网络搜索、外部文档）的数据，请向用户标记
3. 明确记录任何差异
4. 添加脚注解释数据来源选择

**如果计算与源预测不一致：**
1. 显示您的计算方法
2. 记录差异并可能的原因（不同的基年、方法）
3. 如果存在实质性差异，请同时显示两个值
4. 向用户标记以供解决

## 表格结构指南

创建表格时（**必须是实际表格对象**）：

**列对齐：**
- 文本列：左对齐（标题和内容）
- 数字列：右对齐或居中对齐（标题与内容匹配）

**标题行：**
- 粗体文本
- 阴影背景（模板的品牌颜色）
- 白色或对比文本

**共识/总计行：**
- 粗体文本
- 上面有分隔线
- 不同背景阴影

**宽度：** 完全填充指定部分的宽度。

对于 XML 实现，请参阅 [`xml-reference.md`](reference/xml-reference.md#table-implementation)。

## 脚注格式

**格式：**
```
来源：[来源 1] (年份)，[来源 2] (年份)。
注释：(1) [第一个注释]；(2) [第二个注释]。
```

**示例：**
```
来源：Grand View Research (2024)，Mordor Intelligence (2024)，Markets and Markets (2023)。
注释：(1) 排除硬件收入；(2) 包括 B2B 和 B2C 部分。
```

所有幻灯片正文中的上标数字 (¹, ², ³) 必须有相应的注释条目。

## 最终质量清单

在交付填充模板之前，请验证：

### 数据准确性
- [ ] 所有数字与原始源文档匹配
- [ ] 计算值验证公式（查看 [`calculation-standards.md`](reference/calculation-standards.md)）
- [ ] 年份和时间范围正确
- [ ] 公司/竞争对手名称拼写正确
- [ ] 在所有出现的地方，相同的数字是相同的

### 内容映射
- [ ] 每个模板部分都填充了适当的数据
- [ ] 没有 `[括号]` 占位符文本剩余
- [ ] 所有来源引用都包含在脚注中
- [ ] 脚注数字 (¹²³) 有相应的注释条目

### 格式
