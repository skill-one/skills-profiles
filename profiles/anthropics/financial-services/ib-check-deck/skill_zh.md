# IB Deck Checker

对演示文稿进行全面的四维度质量检查。读取每一页幻灯片，然后报告发现的问题。

## 环境检查

该技能在 PowerPoint 插件和聊天中都有效。在开始之前，先确定你处于哪种环境：

- **插件** — 从当前打开的演示文稿中读取。
- **聊天** — 从上传的 `.pptx` 文件中读取。

这是只读不编辑的功能 — 所以两种环境的工作流程是相同的。

## 工作流程

### 读取演示文稿

从每一页幻灯片中提取文本，并跟踪每一行文本来自哪一页。对于每个发现的问题，都需要幻灯片级别的归属信息（“$500M 出现在第 3 页和第 8 页，但第 15 页显示 $485M”）。包含 30 页的演示文稿太多，无法可靠地保留在工作内存中 — 将提取的文本写入文件，以便数字检查脚本进行处理。

该脚本期望带有幻灯片标记的类似 Markdown 的输入。格式如下：

```
## 幻灯片 1
[幻灯片 1 文本内容]

## 幻灯片 2
[幻灯片 2 文本内容]
```

### 1. 数字一致性

对收集的内容运行提取脚本：

```bash
python scripts/extract_numbers.py /tmp/deck_content.md --check
```

它会将单位标准化（$500M vs $500MM vs $500,000,000 → 相同的数字），对值进行分类（收入、EBITDA、倍数、利润率），并在不同幻灯片上显示相同指标类别时标记冲突。这是最有可能发现人类在第五次阅读时遗漏的问题的部分。

除了脚本标记的内容外，还需要验证：

- 计算是正确的（总计相加，百分比相加，增长率与端点匹配）
- 单位风格一致 — 演示文稿应该选择 $M 或 $MM 其中一个并保持一致
- 时间段对齐 — FY vs LTM vs 季度，明确标注

### 2. 数据与叙事的一致性

将声明与支持它们的假设数据对应起来。演示文稿通常是在悄无声息中出错的 — 有人编辑了第 7 页的图表，却忘了第 4 页的叙述。

- 趋势声明（“利润率下降”）→ 图表是否真的显示了这个方向？
- 市场地位声明（“第一名的玩家”）→ 收入和份额数据支持它吗？
- 可信度 — “在 1000 亿美元的市场中排名第一”而收入为 2 亿美元，市场份额为 0.2%；这不是第一名的

### 3. 语言润色

IB 演示文稿有特定的正式程度。扫描任何打破这种正式程度的内容：口语化表达（“相当好”、“很多”）、缩写、感叹号、没有数字的模糊量化、对同一概念的术语不一致。

参见 `references/ib-terminology.md` 获取替换模式。

### 4. 视觉和格式质量检查

对每一页幻灯片运行标准的视觉验证检查。你正在寻找：缺少图表来源引用、缺少坐标轴标签、排版不一致、数字格式漂移（同一演示文稿中 1,000 vs 1K）、日期格式漂移、脚注和免责声明缺失。

视觉验证可以捕捉到文本提取中不会显示的重叠、溢出和对比度问题。不要跳过这一步 — 没有来源引用的图表在文本转储中看起来与正确引用的图表一样。

## 输出

使用 `references/report-format.md` 作为结构。按严重程度分类：

- **关键** — 数字不一致、事实错误、数据与叙事矛盾。这些问题会阻止客户交付。
- **重要** — 语言、缺少来源、术语漂移。应该修复。
- **次要** — 字体大小、间距、日期格式。润色。

首先报告关键问题。如果没有关键问题，应明确说明 — “未发现数字不一致”是一个发现，而不是没有发现。
