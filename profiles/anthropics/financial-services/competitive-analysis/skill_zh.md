# 竞争格局分析

构建一份完整的竞争分析演示文稿。这是一个两阶段的过程：首先收集需求并获得大纲批准，然后进行构建。

## 环境检查

此技能在 PowerPoint 插件和聊天中都适用。开始之前，请先确定您处于哪种环境——机制不同，工作流程相同：

- **插件** — 演示文稿实时打开；直接在其中构建幻灯片。
- **聊天** — 生成 `.pptx` 文件（或构建用户上传的文件）。

以下内容在两种环境中都适用。

## 第一阶段 — 确定分析范围

竞争分析对不同的人来说意味着不同的事情。在进行任何研究或幻灯片构建之前，使用 `ask_user_question` 来明确他们实际想要什么。不要猜测——一份 20 张幻灯片的同行基准演示文稿和一份 5 张幻灯片的市场地图都属于“竞争分析”，但形状完全不同。

尽可能在一轮中收集（工具最多可使用 4 个问题）：

- **范围** — 单个目标公司与竞争对手？还是多家公司并列，没有主角？
- **竞争对手范围** — 哪些公司属于范围？如果用户命名，请使用确切的名称。如果他们说“惯常的嫌疑人”，请提出一组并确认。
- **受众和深度** — 快速阅读，适用于已经处于该领域的人，还是完整的入门指南？这决定了您是否需要市场规模、行业经济和历史——或者可以直接跳到比较。
- **投资背景** — 他们是否需要牛市/基准/熊市情景和标志？那是下面第 9 步的内容；如果是战略性审查而不是投资论点，则跳过它。

如果他们上传了包含竞争对手数据的 Excel/CSV 文件，请在开始提取数字之前确认哪些列映射到哪些指标。源文件保真度很重要：使用给定的值，不要重新计算或重新舍入。

## 第二阶段 — 构建大纲、获得批准，然后构建

**在大纲获得批准之前，不要创建幻灯片。** 提出幻灯片标题和一句话的内容注释，向用户展示，获得认可。竞争演示文稿是 10-20 张相互关联的内容幻灯片——因为幻灯片 4 错误而重建是昂贵的。大纲是廉价的迭代点。

在提出大纲时，`ask_user_question` 对于结构决策非常有效：哪种定位可视化（2×2 矩阵 / 雷达 / 层级图——下面第 5 步），如何分组竞争对手（按商业模式 / 分段 / 姿态——下面第 4 步）。这些是用户可能有自己的意见的品味调用。

## 标准 — 全程应用

### 提示保真度

当用户指定内容时，那是一个要求，而不是建议：
- **幻灯片标题和章节名称** — 精确措辞。如果他们说“概述和竞争范围”，不要换成“2024 年竞争格局”。
- **图表与表格** — 不可互换。 “嵌入式图表”意味着一个带有数据标签的条形图/切片的真实图表对象，而不是一个格式化的表格。
- **完整的数据系列** — 如果他们列出 7 家竞争对手，请包含所有 7 家。如果他们显示 2015-2025 年，请包含每一年的数据。
- **精确值和比率** — “超过 DoorDash 4:1，Lyft 8:1”意味着这些比率，而不是“7.6 倍 Lyft”。

### 源质量，当源冲突时

1. 10-K / 年度报告（经过审计）
2. 盈利电话 / 投资者演示文稿（管理层评论）
3. 销售端研究（分析师估计，对私营公司规模有用）
4. 行业报告（麦肯锡，高德 — 市场规模，趋势）
5. 新闻（仅限最新发展；与原始来源核实）

### 数据可比性

- 所有竞争对手指标来自同一财政年度；明确标记例外情况（“FY24”与“H1 2024”）
- 跨竞争对手的相同指标定义
- 对国际货币转换为美元；注明汇率和日期
- 缺失数据显示为“-”或“N/A”，并带有“[E]”标志表示估计——永远不要留空
- 每个数字都有引用："[公司] [文件] ([日期])"

### 设计

- **幻灯片标题是见解，而不是标签。** “规模领导者正在拉开与利基玩家的差距”——而不是“竞争分析。”
- **标志是量化的。** “利润率低于 40%”——而不是“利润率下降。”
- **评级显示实际值。** “●●● 1600 亿” ——而不是仅仅“●●●。”
- **图表是真实的图表对象** ——不是伪装成图表的文本表格。

**字体** — 明确设置，不要依赖默认值：
- 幻灯片标题：28-32pt 粗体
- 章节标题：18-20pt 粗体
- 正文：14-16pt（永远不会低于 14pt）
- 表格文本：14pt
- 来源/脚注：14pt，灰色
- 相同元素类型 = 全部演示文稿中相同大小

**图表：**
- 图例在图表边界内，而不是悬浮在绘图区域上方
- 饼图（≤6 个切片）使用右侧图例，线图/条形图（≤4 个系列）使用底部图例
- 超过 6 个系列 → 分割到多个图表或使用表格
- 饼图在切片上显示百分比，而不仅仅是在图例中显示

**表格：**
- 浅灰色标题行，粗体
- 数字右对齐，文本左对齐
- 足够的单元格填充，使文本不会接触边框

**颜色：** 最多 2-3 种颜色。柔和的——海军蓝，灰色，一个强调色。整个演示文稿中相同的颜色含义相同。

### 严格与灵活的区别

| 严格 | 灵活 |
|---|---|
| 用户指定时精确的标题/章节 | 用户未指定时的创意标题 |
| 用户说图表时图表；用户说表格时表格 | 未指定时的可视化类型 |
| 用户列出的每个竞争对手/数据点 | 未指定时的竞争对手数量 |
| 指定时精确的值 | 未指定精度时的舍入 |
| 标题适合而不会溢出 | 竞争对手类别的数量 |
| 无重叠元素 | 要比较的维度 |

## 分析工作流程

### 第 0 步 — 行业定义指标

在其他任何事情之前：这个行业实际上依赖于 3-5 个指标是什么？在所有竞争对手之间始终如一地使用这些指标。

| 行业 | 关键指标 |
|---|---|
| SaaS | ARR，NRR，CAC 投资回报，LTV/CAC，40 规则 |
| 支付 | GPV，抽成率，附加率，交易利润率 |
| 电商平台 | GMV，抽成率，买家/卖家比率，复购率 |
| 零售 | 同店销售额，库存周转率，每平方英尺销售额 |
| 物流 | 量，单位成本，准时交付百分比，产能利用率 |

未列出的行业——选择投资者和运营商基准的指标。

### 第 1 步 — 市场背景

规模，增长，驱动因素，逆风。带来源。

正确：“嵌入式支付在 2024 年达到 800-1000 亿美元，年复合增长率 20-25%（麦肯锡 2024）”
错误：“市场很大，增长迅速”

### 第 2 步 — 行业经济

绘制价值流动。方法取决于行业结构：
- **垂直结构** — 价值链层，每个层典型的利润率
- **平台/网络** — 生态系统参与者，价值在他们之间流动
- **碎片化** — 整合动态，规模差异的利润率

### 第 3 步 — 目标公司简介

```
| 指标 | 值 |
|---|---|
| 收入 | 49.6 亿美元 |
| 增长 | 同比增长 26% |
| 毛利率 | 45% |
| 盈利能力 | 调整后 EBITDA 3.73 亿美元 |
| 客户 | 13.4 万 |
| 保留率 | 92% |
| 市场份额 | ~15% |
```

多段公司添加细分：

```
| 细分 | 收入 | 收入同比增长 | 收入百分比 | EBITDA | EBITDA 同比增长 | 利润率 |
|---|---|---|---|---|---|---|
| 细分 A | 251 亿美元 | +26% | 57% | 65 亿美元 | +31% | 26% |
| 细分 B | 138 亿美元 | +31% | 31% | 25 亿美元 | +64% | 18% |
| 细分 C | 51 亿美元 | -2% | 12% | -7400 万美元 | -16% | -1% |
| 总计 | 440 亿美元 | +18% | 100% | 65 亿美元* | - | 15% |
```
*注意如果适用，则注明企业成本

### 第 4 步 — 竞争对手映射

按适合的视角分组（如果用户未指定，这是一个好的 `ask_user_question` 决策）：
- 按商业模式 — 平台 / 垂直 / 水平
- 按细分 — 企业 / 中小企业 / 消费者
- 按姿态 — 直接 / 间接 / 新兴
- 按起源 — 现有竞争者 / 打破者 / 新进入者

### 第 5 步 — 定位可视化

| 类型 | 使用场景 |
|---|---|
| 2×2 矩阵 | 两个主要的竞争因素 |
| 雷达/蜘蛛图 | 多因素比较 |
| 层级图 | 自然聚类成战略组 |
| 价值链图 | 垂直行业 |
| 生态系统图 | 平台市场 |

有关按行业划分的 2×2 轴对，请参阅 `references/frameworks.md`。

### 第 6 步 — 竞争对手深度分析

每个竞争对手两张表格。

**指标：**
```
| 指标 | 值 |
|---|---|
| 收入 | $X.XB |
| 增长 | +XX% 同比 |
| 毛利率 | XX% |
| 市值 | $X.XB |
| 盈利能力 | $XXXM EBITDA |
| 客户 | XXK |
| 保留率 | XX% |
| 市场份额 | ~XX% |
```

**定性：**
```
| 类别 | 评估 |
|---|---|
| 业务 | 他们做什么（一句话） |
| 优势 | 2-3 个要点 |
| 劣势 | 2-3 个要点 |
| 策略 | 当前优先事项 |
```

### 第 7 步 — 比较分析

```
| 维度 | 公司 A | 公司 B | 公司 C |
|---|---|---|---|
| 规模 | ●●● 1600 亿美元 | ●●○ 450 亿美元 | ●○○ 80 亿美元 |
| 增长 | ●●○ +26% | ●●● +35% | ●●○ +22% |
| 利润率 | ●●○ 7.5% | ●○○ 3.2% | ●●● 15% |
```

### 第 8 步 — 战略背景

并购交易（乘数，理由），合作趋势，融资模式，监管发展。有关并购交易表格格式的更多信息，请参阅 `references/schemas.md`。

### 第 9 步 — 综合

**护城河评估** — 对每个竞争对手按强/中/弱进行评级：

| 护城河 | 评估内容 |
|---|---|
| 网络效应 | 用户/供应商飞轮强度；跨边 vs 同边 |
| 转换成本 | 技术集成深度，合同锁定，行为习惯 |
| 规模经济 | 量级优势；最小有效规模 |
| 无形资产 | 品牌，专有数据，监管许可，专利 |

**必须综合的元素：**
- 持久优势（难以复制）——映射到护城河类别
- 结构性弱点（难以修复）
- 当前状态与轨迹

**对于投资背景**（如果第一阶段范围说明不需要）：

```
| 情景 | 概率 | 主要驱动因素 |
|---|---|---|
| 牛市 | 30% | 市场份额增长，利润率扩张 |
| 基准 | 50% | 当前轨迹持续 |
| 熊市 | 20% | 竞争压力，利润率压缩 |
```

## 质量检查清单

完成前：

**提示保真度**
- 幻灯片标题与用户指定的内容完全一致
- 用户说图表的地方有图表；用户说表格的地方有表格
- 用户列出的每个竞争对手/年份/数据点都存在
- 指定的精确值和格式

**数据一致性**
- 直接提取源文件值，不要重新计算
- 相同指标在每个幻灯片上显示相同的值
- 与源相同的十进制精度

**布局**
- 标题适合而不会溢出
- 无重叠元素
- 所有文本都在容器内，没有裁剪

**内容**
- 每个数字都有引用
- 所有指标来自同一财政期间（或标记）
- 幻灯片标题陈述见解，而不是主题
- 图表是真实的图表对象

在每张幻灯片上运行标准视觉验证检查——这可以捕获重叠、溢出和低对比度文本，这些文本在阅读 XML 时不会显示出来。
