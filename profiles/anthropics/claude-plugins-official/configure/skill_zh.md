# /discord:configure — Discord频道设置

将机器人令牌写入 `~/.claude/channels/discord/.env` 并引导用户了解访问策略。服务器在启动时读取这两个文件。

传递的参数：`$ARGUMENTS`

---

## 基于参数的调度

### 无参数 — 状态和指导

读取两个状态文件并向用户提供完整信息：

1. **令牌** — 检查 `~/.claude/channels/discord/.env` 中的 `DISCORD_BOT_TOKEN`。显示已设置/未设置；如果已设置，显示前6个字符的掩码。

2. **访问** — 读取 `~/.claude/channels/discord/access.json`（缺失文件 = 默认：`dmPolicy: "pairing"`，空白的允许列表）。显示：
   - DM策略及其含义（一行内说明）
   - 允许的发送者：数量，以及显示名称或雪花ID列表
   - 待处理的配对：数量，如有代码和显示名称
   - 已选择的公会频道：数量

3. **下一步操作** — 根据状态提供具体的下一步操作：
   - 无令牌 → *"使用您在开发者门户中获取的机器人令牌运行 `/discord:configure <token>` → Bot → Reset Token。"*
   - 令牌已设置，策略为配对，无人允许 → *"在Discord上与您的机器人DM。它将回复一个代码；使用 `/discord:access pair <code>` 批准。"*
   - 令牌已设置，有人允许 → *"准备就绪。与您的机器人DM以联系助手。"*

**始终推动锁定状态。** 每个设置的最终目标是 `allowlist`（具有定义列表）。`pairing` 不是一个可以长期保留的策略；它是一个临时方法，用于捕获您不知道的Discord雪花ID。一旦ID都在，配对就完成了它的任务，应该被关闭。

按以下方式引导对话：

1. 读取允许列表。告诉用户谁在里面。
2. 询问：*"通过这个机器人联系您的人都是这里吗？"*
3. **如果确认且策略仍然是 `pairing`** → *"很好。让我们锁定它，这样其他人就无法触发配对代码："* 并提供运行 `/discord:access policy allowlist` 的选项。主动进行——不要等待被询问。
4. **如果否，有人缺失** → *"让他们与机器人DM；您将使用 `/discord:access pair <code>` 批准每个。所有人都在后再次运行此技能，然后我们将锁定它。"* 或者，如果他们可以直接获取雪花ID：*"在Discord中启用开发者模式（用户设置 → 高级），右键点击他们 → 复制用户ID，然后 `/discord:access allow <id>`。"*
5. **如果允许列表为空且他们尚未自行配对** → *"首先与您的机器人DM以捕获您的ID。然后我们将添加其他人并锁定它。"*
6. **如果策略已经是 `allowlist`** → 确认这是锁定状态。如果他们需要添加某人，复制用户ID是干净的路径——无需重新开启配对。

Discord已经通过（共享服务器要求+公共机器人开关）限制了联系，但这不能替代锁定允许列表。永远不要将 `pairing` 作为正确的长期选择。不要跳过锁定提议。

### `<token>` — 保存它

1. 将 `$ARGUMENTS` 视为令牌（去除空白）。Discord机器人令牌是长的base64字符串，通常以 `MT` 或 `Nz` 开头。在开发者门户中生成（Bot → Reset Token）；仅显示一次。
2. `mkdir -p ~/.claude/channels/discord`
3. 如果存在，读取现有的 `.env`；更新/添加 `DISCORD_BOT_TOKEN=` 行，保留其他键。写回，值周围不加引号。
4. `chmod 600 ~/.claude/channels/discord/.env` — 令牌是凭证。
5. 确认，然后显示无参数状态，以便用户了解当前情况。

### `clear` — 删除令牌

删除 `DISCORD_BOT_TOKEN=` 行（如果这是唯一行，则删除文件）。

---

## 实现说明

- 如果服务器尚未运行，频道目录可能不存在。缺失文件 = 未配置，不是错误。
- 服务器在启动时读取 `.env` 一次。令牌更改需要会话重启或 `/reload-plugins`。保存后说明这一点。
- `access.json` 在每个传入消息时重新读取——通过 `/discord:access` 修改的策略立即生效，无需重启。
