# CLAUDE.md 改进工具

对代码库中的 CLAUDE.md 文件进行审计、评估和改进，以确保 Claude Code 具有最佳的项目上下文。

**此技能可以写入 CLAUDE.md 文件。** 在展示质量报告并获得用户批准后，它会使用有针对性的改进更新 CLAUDE.md 文件。

## 工作流程

### 第一阶段：发现

在仓库中查找所有 CLAUDE.md 文件：

```bash
find . -name "CLAUDE.md" -o -name ".claude.md" -o -name ".claude.local.md" 2>/dev/null | head -50
```

**文件类型和位置：**

| 类型 | 位置 | 目的 |
|------|----------|---------|
| 项目根目录 | `./CLAUDE.md` | 主要项目上下文（提交到 git，与团队共享） |
| 本地覆盖 | `./.claude.local.md` | 个人/本地设置（忽略 git，不共享） |
| 全局默认值 | `~/.claude/CLAUDE.md` | 在所有项目中应用的用户范围默认值 |
| 包特定 | `./packages/*/CLAUDE.md` | 单一仓库中的模块级上下文 |
| 子目录 | 任何嵌套位置 | 功能/领域特定上下文 |

**注意：** Claude 会自动发现父目录中的 CLAUDE.md 文件，使单一仓库设置自动生效。

### 第二阶段：质量评估

对每个 CLAUDE.md 文件，根据质量标准进行评估。有关详细评分标准，请参阅 [references/quality-criteria.md](references/quality-criteria.md)。

**快速评估清单：**

| 标准 | 权重 | 检查 |
|-----------|--------|-------|
| 命令/工作流文档化 | 高 | 是否有构建/测试/部署命令？ |
| 架构清晰度 | 高 | Claude 能否理解代码库结构？ |
| 非明显模式 | 中 | 是否记录了陷阱和怪癖？ |
| 简洁性 | 中 | 没有冗长的解释或明显信息？ |
| 时效性 | 高 | 是否反映当前代码库状态？ |
| 可操作性 | 高 | 指令是否可执行，而不是模糊不清？ |

**质量评分：**
- **A (90-100)**: 全面、当前、可操作
- **B (70-89)**: 良好覆盖，存在少量差距
- **C (50-69)**: 基本信息缺失关键部分
- **D (30-49)**: 稀疏或过时
- **F (0-29)**: 缺失或严重过时

### 第三阶段：质量报告输出

**始终在做出任何更新之前输出质量报告。**

格式：

```
## CLAUDE.md 质量报告

### 摘要
- 发现文件：X
- 平均分数：X/100
- 需要更新的文件：X

### 文件逐个评估

#### 1. ./CLAUDE.md (项目根目录)
**分数：XX/100 (等级：X)**

| 标准 | 分数 | 备注 |
|-----------|-------|-------|
| 命令/工作流 | X/20 | ... |
| 架构清晰度 | X/20 | ... |
| 非明显模式 | X/15 | ... |
| 简洁性 | X/15 | ... |
| 时效性 | X/15 | ... |
| 可操作性 | X/15 | ... |

**问题：**
- [列出具体问题]

**建议添加：**
- [列出应添加的内容]

#### 2. ./packages/api/CLAUDE.md (包特定)
...
```

### 第四阶段：有针对性的更新

输出质量报告后，在更新之前请求用户确认。

**更新指南（关键）：**

1. **仅提出有针对性的添加** - 专注于真正有用的信息：
   - 分析期间发现的命令或工作流
   - 代码中发现的陷阱或非明显模式
   - 不清晰的包关系
   - 可用的测试方法
   - 配置怪癖

2. **保持简洁** - 避免：
   - 重复代码中明显的内容
   - 已涵盖的通用最佳实践
   - 不太可能重复的临时修复
   - 当一句话足够时，避免冗长的解释

3. **显示差异** - 对每个更改，显示：
   - 要更新的 CLAUDE.md 文件
   - 具体添加内容（作为差异或引用块）
   - 简要说明此更改如何帮助未来的会话

**差异格式：**

```markdown
### 更新：./CLAUDE.md

**原因：** 缺少构建命令，导致对如何运行项目感到困惑。

```diff
+ ## 快速启动
+
+ ```bash
+ npm install
+ npm run dev  # 在端口 3000 上启动开发服务器
+ ```
```
```

### 第五阶段：应用更新

在用户批准后，使用编辑工具应用更改。保留现有内容结构。

## 常见问题标记

1. **过时的命令**：不再工作的构建命令
2. **缺失依赖项**：未提及的必需工具
3. **过时的架构**：已更改的文件结构
4. **缺失环境设置**：必需的环境变量或配置
5. **损坏的测试命令**：已更改的测试脚本
6. **未记录的陷阱**：未捕获的非明显模式

## 与用户分享的提示

在提出建议时，提醒用户：

- **`#` 键快捷方式**：在 Claude 会话期间，按 `#` 让 Claude 自动将学习内容整合到 CLAUDE.md
- **保持简洁**：CLAUDE.md 应为人类可读；密集优于冗长
- **可操作的命令**：所有记录的命令都应可复制粘贴
- **使用 `.claude.local.md`**：用于个人偏好（添加到 `.gitignore`）
- **全局默认值**：将用户范围偏好放在 `~/.claude/CLAUDE.md`

## 优秀的 CLAUDE.md 是什么样子

**关键原则：**
- 简洁且人类可读
- 可复制粘贴的可操作命令
- 项目特定模式，而不是通用建议
- 非明显的陷阱和警告

**推荐部分**（仅使用相关部分）：
- 命令（构建、测试、开发、格式化）
- 架构（目录结构）
- 关键文件（入口点、配置）
- 代码风格（项目约定）
- 环境（必需变量、设置）
- 测试（命令、模式）
- 陷阱（怪癖、常见错误）
- 工作流程（何时做何事）
