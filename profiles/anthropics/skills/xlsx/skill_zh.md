# XLSX 创建、编辑与分析

| Task | Approach |
|---|---|
| **Create** or **edit** with formulas/formatting | `openpyxl` — 见下文注意事项 |
| **Bulk data** in or out | `pandas` (`read_excel`, `to_excel`) |
| **Quick look** at a sheet | `markitdown file.xlsx` — 每个工作表对应 `## SheetName`；同样支持读取 `.xlsm`。不含单元格坐标，因此不能据此规划编辑 |
| **Read** a model (formulas *and* values) | 两次 `load_workbook` 调用 — 见注意事项 |

> `openpyxl`、`pandas` 和 `markitdown` 已预安装 — 无需先运行 `pip install`；直接编写脚本并导入即可。仅在导入失败（或 `markitdown` 命令缺失）时，安装缺失的包。

> 下方脚本路径相对于本技能所在目录。

## 所有输出所需的

- **专业字体**（Arial、Times New Roman），除非用户另有说明。
- **零公式错误。** 只要 `recalc.py` 报告了 `errors_found`，就永远不要交付。如果你认为某个错误早于你的处理，需证明这一点：用 `data_only=True` 加载*原始文件*，并查看该单元格。你引入的错误与继承的错误看起来完全一样。
- **使用公式，绝不硬编码结果。** 写入 `sheet['B10'] = '=SUM(B2:B9)'`，而不是 Python 计算出的总计。当输入改变时，该工作表必须重新计算。
- **严格按照用户要求执行。** 精确的标签名称、精确的列标题，以及用户指定的公式。任何重新设计计算其他内容的工作，无论多么精巧，都会失败。
- **在读者会看到的地方，记录每一项假设和硬编码的数字** — 通过单元格注释，或在表格末尾的相邻单元格中记录。若存在真实来源，请引用（`来源：公司 10-K，FY2024，第 45 页，收入附注，[SEC EDGAR URL]`）；若数字来自用户，需明确说明。
- **为他人填写而创建的工作簿**，需要一段简短的图例，标明哪些单元格需要编辑，并提供一行示例数据，展示预期格式。切勿将此类行添加到需要你编辑的文件中。
- **编辑现有文件：完全匹配其惯例。** 这些惯例覆盖此处每一项准则。首先找到其指定的输入单元格——不同的字体颜色、填充或阴影标记出这些单元格——仅在此处写入，并保留所有现有公式不动。

## 重新计算（文件包含公式时必做）

openpyxl 将公式以字符串形式写入，**不包含缓存值**。在重新计算之前，每个公式单元格对任何读取缓存值的程序都会读取为 `None` — `pandas`、`load_workbook(data_only=True)` 和大多数预览程序。

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # default 30
```

LibreOffice 计算每个公式，文件**原地重新写入**，并返回 JSON：`status`（`success` | `errors_found`）、`total_formulas`、`total_errors`，以及 `error_summary`（按每种错误类型列出最多 100 个单元格；`locations_truncated` 说明被隐藏的数量 — 请以 `total_errors` 为准，而非列表长度）。修复其中命名的问题后再次运行。**如果 JSON 中出现 `error` 键而非 `status`，说明未进行任何重计算**，且仅在这种情况下以非零状态退出 — `errors_found` 以 0 退出，因此切勿将干净的退出视为干净的工作簿。

**绿色的重新计算证明你的公式*能求值*，而非*正确*。** 范围少一个单位或引用错误的行，会产生一个干净、无错误但数字错误的工作簿。在构建完整表格之前，先编写 2–3 个公式并检查它们是否正确取到了预期的值。

**链接到另一个文件的工作簿会丢失这些链接**，如果你用 openpyxl 重新保存它，然后重新计算。此类公式显示为 `='[1]Returns Analysis'!$B$2` — 其中的 `[1]` 是工作簿外部引用列表的索引，指向磁盘上的一个*独立文件*，而非工作表中的一张表。该文件在此处通常不存在，因此单元格的缓存值是唯一保存其数据的东西。openpyxl 在保存时会清除该值；LibreOffice 随后必须实际解析引用，失败后写入 `#NAME?`，并删除所有链接。`recalc.py` 在这种情况下会拒绝运行 — 在覆盖这些单元格之前，先从原始文件复制这些单元格的值（`--force` 覆盖此选项，并接受该损失）。

## 选择能通过验证的公式

LibreOffice 实现的函数比 Excel 少，若某个函数它无法求值，会作为字面量 `#NAME?` 嵌入到你交付的文件中。

- **优先选择 Excel 2007 时代的函数** — `SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT` — 这些无需前缀。
- **六个 2007 年后的函数可用，但必须以 `_xlfn.` 前缀书写**，因为 openpyxl 将公式逐字写入 XML，且 Excel 存储带前缀的 2007 年后函数名（其界面隐藏了前缀）：`_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。不带前缀书写时，每个都会产生 `#NAME?`。
- **永远不要使用 `XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE` 或 `SEQUENCE`。** 运行时（LibreOffice）在任何前缀下都无法求值这些函数。
- 较新版本确实可以求值它们，但它们属于溢出的数组函数，且 openpyxl 编写的工作簿没有溢出元数据，因此只有范围的左上角单元格会得到值 — 且 `recalc.py` 会对截断后的结果报告 `total_errors: 0`。查找使用 `INDEX`/`MATCH`，并在 Python 中排序、筛选和去重，然后再写入单元格。

## openpyxl 注意事项

- **读取模型需要两次加载。** `data_only=True` 会得到公式被移除的缓存值；默认模式得到不含值的公式字符串。一次加载无法同时获得两者。
- **如果使用 `data_only=True` 保存，具有破坏性。** 该工作簿不再包含公式，因此保存时所有公式都会被替换为字面量 — 永久性损坏。
- openpyxl 刚写入的文件使用 `data_only=True` 读取时，到处都返回 `None` — 需先运行 `recalc.py`。（结果为空字符串的公式也会读取回 `None`。）
- **合并单元格：仅写入左上角锚点。** 范围内其他单元格均为 `MergedCell`，其 `.value` 为只读。
- 若不使用 `keep_vba=True` 调用 `load_workbook`，`.xlsm` 会丢失宏。
- 跨表引用时，包含空格的表名必须在引号内：`='Assumptions Inputs'!$B$5`。不加引号时，会计算为 `#VALUE!`。

## 财务模型

除非用户另有说明，或现有文件已有其他用途。

**颜色：** 硬编码输入和情景杠杆使用蓝色文本（`0,0,255`）；公式使用黑色；链接到另一个工作表的单元格使用绿色（`0,128,0`）；链接到另一个文件的单元格使用红色（`255,0,0`）；用户应填写的关键假设和单元格使用黄色填充（`255,255,0`）。

**数字：** 货币 `$#,##0`，单位在标题中说明（`Revenue ($mm)`）；零显示为 `-`，包括在百分比中（`$#,##0;($#,##0);-`）；负数用括号表示；百分比 `0.0%`，**以分数存储**（`0.15` 显示为 `15.0%`；存储 `15` 显示为 `1500.0%`）；估值倍数 `0.0x`；年份以文本形式（`"2024"`，而非 `2,024`）。

**结构：** 每个假设都位于带标签的独立单元格中，由使用该假设的公式引用（`=B5*(1+$B$6)`，而非 `=B5*1.05`）；所有预测期间公式保持一致，因为单行中间被编辑的单元格是最常见的隐性错误；对可能为零的分母进行保护。
