# XLSX 创建、编辑和分析

| 任务 | 方法 |
|---|---|
| 使用公式/格式**创建**或**编辑** | `openpyxl` — 详见下方注意事项 |
| 批量数据**输入**或**输出** | `pandas` (`read_excel`, `to_excel`) |
| 快速查看工作表 | `markitdown file.xlsx` — 每个工作表使用 `## SheetName`；可读取 `.xlsm` 文件。不包含单元格坐标，因此不要从它计划编辑内容 |
| **读取**模型（公式**和**值） | 两次 `load_workbook` 调用 — 详见下方注意事项 |

> `openpyxl`、`pandas` 和 `markitdown` 已预装 — 不要先运行 `pip install`；直接编写脚本并直接导入。只有在导入失败（或 `markitdown` 命令缺失）时：`pip install` 缺失的包。

> 下方脚本路径相对于此技能的目录。

## 每个输出的要求

- **全篇使用专业字体**（Arial、Times New Roman），除非用户另有说明。
- **零公式错误**。在 `recalc.py` 报告 `errors_found` 时绝不发布。如果你认为错误存在于你之前，请证明：使用 `data_only=True` 加载原始文件并查看该单元格。你引入的错误看起来与你继承的错误完全一样。
- **使用公式，绝不硬编码结果**。编写 `sheet['B10'] = '=SUM(B2:B9)'`，而不是 Python 计算的总和。当输入变化时，工作表必须重新计算。
- **严格遵循用户规格**。精确的标签名、精确的列标题以及他们指定的公式。任何计算其他内容的重新设计，无论多么优雅，都是失败的。
- **在读者可见的地方记录所有假设和硬编码的数字** — 单元格注释或表格末尾的相邻单元格。当存在真实来源时，引用真实来源（`来源：公司 10-K，2024 财年，第 45 页，收入注释，[SEC EDGAR URL]`）；当数字来自用户时，明确说明。
- **为他人填写的**工作簿需要一个简短的图例，说明要编辑哪些单元格，以及一个显示预期格式的真实值示例行。永远不要向被要求编辑的文件添加此类行。
- **编辑现有文件：严格匹配其约定**。它们会覆盖这里的所有指南。首先找到其指定的输入单元格 — 一个独特的字体颜色、填充或阴影标记它们 — 仅在那里编写，并保留所有现有公式。

## 重新计算（每当文件包含公式时强制执行）

openpyxl 将公式作为**无缓存值**的字符串写入。在重新计算之前，任何公式单元格对读取缓存值的任何内容都返回 `None` — `pandas`、`load_workbook(data_only=True)` 和大多数预览器。

```bash
python scripts/recalc.py output.xlsx [timeout_seconds]   # 默认 30
```

LibreOffice 计算每个公式，文件**就地重写**，并返回 JSON：
`status` (`success` | `errors_found`)、`total_formulas`、`total_errors` 和 `error_summary`，其中每个错误类型最多命名 100 个单元格（`locations_truncated` 指出它保留了多少个 — 相信 `total_errors`，而不是列表的长度）。修复它命名的部分并再次运行。**带有 `error` 键而不是 `status` 的 JSON 表示没有任何内容被重新计算**，并且只有在这种情况下才会退出非零 — `errors_found` 退出 0，因此永远不要将干净的退出视为干净的工作簿。

**绿色的重新计算证明你的公式*可以计算*，而不是*正确***。一个范围偏移一位或引用错误行会产生一个干净、无错误的文件，但数字错误。在构建网格之前，先编写 2-3 个公式并检查它们是否拉取你期望的值。

**链接到另一个文件的工作簿在用 openpyxl 重新保存并重新计算时会丢失这些链接**。此类公式读取 `='[1]Returns Analysis'!$B$2` — `[1]` 是工作簿外部引用列表的索引，命名磁盘上的*单独文件*，而不是工作表。该文件很少存在于此处，因此单元格的缓存值是唯一保留其数据的东西。openpyxl 在保存时删除该值；LibreOffice 然后必须实际解析引用，失败，写入 `#NAME?`，并删除所有链接。`recalc.py` 拒绝在这种状态下运行 — 在保存它们之前将单元格的值复制出原始文件（`--force` 覆盖，并接受损失）。

## 选择在验证中存活的公式

LibreOffice 实现的函数比 Excel 少，无法评估的函数会变成文件中嵌入的 `#NAME?`。

- **优先使用 Excel-2007 时代的函数** — `SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT` — 它们不需要前缀。
- **六个 2007 年后的函数可以工作，但必须带有 `_xlfn.` 前缀**，因为 openpyxl 将你的公式直接写入 XML，而 Excel 存储的 2007 年后名称有前缀（其 UI 隐藏了前缀）：`_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。未加前缀，每个都会产生 `#NAME?`。
- **永远不要使用 `XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE` 或 `SEQUENCE`。** 运行时的 LibreOffice 在任何前缀下都无法评估它们。新版本可以评估它们，但它们是溢出数组函数，而 openpyxl 写入的文件没有溢出元数据，因此只有范围内的左上角单元格会获得值 — 并且 `recalc.py` 在截断结果上报告 `total_errors: 0`。使用 `INDEX`/`MATCH` 进行查找，并在写入单元格之前在 Python 中排序、过滤和去重。
- LibreOffice 无法解析的公式会以**小写**形式写回 — 这是 `#NAME?` 旁边的快速提示。

## openpyxl 注意事项

- **读取模型需要两次加载**。`data_only=True` 会返回缓存值但移除公式；默认会返回公式字符串但无值。一次调用无法同时提供两者。
- **`data_only=True` 如果保存会破坏**。该工作簿不再包含公式，因此保存会永久替换每个公式为字面量。
- **对 openpyxl 刚刚写入的文件使用 `data_only=True` 会返回 `None` 到处** — 首先运行 `recalc.py`。 （结果为 `""` 的公式也读取为 `None`。）
- **合并单元格：仅写入左上角锚点**。范围内的其他每个单元格都是 `MergedCell`，其 `.value` 是只读的。
- **`.xlsm` 除非传递 `keep_vba=True` 否则会丢失宏** 到 `load_workbook`。
- **包含空格的工作表名必须在跨工作表引用中加引号**：`='Assumptions Inputs'!$B$5`。未加引号，它将评估为 `#VALUE!`。

## 财务模型

除非用户另有说明，或现有文件已经做其他处理。

**颜色**：蓝色文本 (`0,0,255`) 用于硬编码的输入和情景杠杆 · 黑色用于公式 · 绿色 (`0,128,0`) 用于链接到另一个工作表 · 红色 (`255,0,0`) 用于链接到另一个文件 · 黄色填充 (`255,255,0`) 用于关键假设和用户应填写的单元格。

**数字**：货币 `$#,##0`，在标题中命名单位（`Revenue ($mm)`）· 零渲染为 `-`，包括在百分比中（`$#,##0;($#,##0);-`）· 负数用括号括起来 · 百分比 `0.0%`，**存储为分数**（`0.15` 渲染为 `15.0%`；存储 `15` 渲染为 `1500.0%`）· 估值倍数 `0.0x` · 年份作为文本（`"2024"`，绝不使用 `2,024`）。

**结构**：每个假设在其自己的标记单元格中，由使用它的公式引用（`=B5*(1+$B$6)`，绝不使用 `=B5*1.05`）· 在每个预测期间保持一致的公式，因为行中单独编辑的单元格是最常见的静默错误 · 保护分母可能为零。
