# /legal-response -- 从模板生成回复

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

使用配置的模板生成对常见法律咨询的回复。使用具体细节自定义回复，并包括不应使用模板回复的情况下的升级触发器。

**重要提示**：此命令协助法律工作流程，但不会提供法律建议。生成的回复在发送前应由合格的法律专业人士审查，尤其是对于受监管的通信。

## 调用方式

```
/legal-response [咨询类型]
```

常见的咨询类型：
- `dsr` 或 `data-subject-request` -- 数据主体访问/删除/更正请求
- `hold` 或 `discovery-hold` -- 诉讼保留通知
- `vendor` 或 `vendor-question` -- 供应商法律问题
- `nda` 或 `nda-request` -- 业务团队提出的保密协议请求
- `privacy` 或 `privacy-inquiry` -- 与隐私相关的问题
- `subpoena` -- 传票或法律程序回复
- `insurance` -- 保险索赔通知
- `custom` -- 使用自定义模板

如果未提供咨询类型，系统将询问用户需要哪种类型的回复，并显示可用类别。

## 工作流程

### 第一步：识别咨询类型

接受用户的咨询类型。如果类型不明确，则显示可用类别并请求澄清。

### 第二步：加载模板

在本地设置（例如，`legal.local.md` 或模板目录）中查找模板。

**如果已配置模板：**
- 加载适用于咨询类型的相应模板
- 确定所需变量（收件人姓名、日期、具体细节）

**如果未配置模板：**
- 告知用户未为此咨询类型找到模板
- 提供创建模板的帮助（见下文模板创建指南）
- 根据咨询类型提供合理的默认回复结构

### 第三步：检查升级触发器

在生成任何回复之前，评估此情况是否具有不应使用模板回复的特征。

#### 通用升级触发器（适用于所有类别）
- 涉及潜在诉讼或监管调查的事项
- 咨询来自监管机构、政府机构或执法部门
- 回复可能创建具有约束力的法律承诺或放弃
- 涉及潜在刑事责任
- 涉及媒体关注或可能涉及媒体关注
- 情况是前所未有的（团队以前未处理过）
- 涉及多个具有冲突要求的司法管辖区
- 涉及高管或董事会成员

#### 数据主体请求升级触发器
- 请求涉及未成年人的数据，或来自/代表未成年人
- 请求来自监管机构（不是个人）
- 请求涉及处于诉讼保留状态的数据
- 请求者是当前或以前的员工，有活跃的争议或人力资源事项
- 请求范围异常广泛，或看起来像是在进行钓鱼调查
- 请求涉及在具有独特要求的司法管辖区处理的数据
- 请求涉及特殊类别数据（健康、生物特征、遗传）

#### 诉讼保留升级触发器
- 涉及潜在刑事责任的事项
- 保留范围不明确、存在争议或可能过于宽泛
- 对某些数据是否在范围内存在疑问
- 对同一或相关事项存在先前的保留
- 保留可能显著影响正在进行的业务运营
- 保留与监管删除要求冲突
- 保管人反对保留范围

#### 供应商问题升级触发器
- 问题涉及争议或潜在违规行为
- 供应商威胁诉讼或终止
- 问题涉及监管合规（不仅仅是合同条款）
- 回复可能创建具有约束力的承诺或放弃
- 回复可能影响正在进行的谈判

#### 保密协议请求升级触发器
- 对方是竞争对手
- 保密协议涉及政府机密信息
- 商业环境表明保密协议是为潜在的并购交易而准备的
- 请求涉及不寻常的主题（AI训练数据、生物特征数据等）

#### 传票/法律程序升级触发器
- **始终需要律师审查**（模板仅作为起点）
- 确定特权问题
- 涉及第三方数据
- 跨境生产问题
- 时间安排不合理

**当检测到升级触发器时：**
1. **停止**：不要生成模板回复
2. **提醒**：告知用户已检测到升级触发器
3. **解释**：描述检测到的触发器及其重要性
4. **建议**：建议适当的升级路径（高级律师、外部律师、特定团队成员）
5. **提供**：提供供律师审查的草稿（明确标记为“草稿 - 仅供律师审查”），而不是最终回复

### 第四步：收集具体细节

提示用户提供自定义回复所需的细节：

**数据主体请求：**
- 请求者姓名和联系信息
- 请求类型（访问、删除、更正、可移植性、选择退出）
- 涉及的数据
- 适用法规（GDPR、CCPA、CPRA、其他）
- 回复截止日期

**诉讼保留：**
- 事项名称和参考编号
- 保管人（谁需要保留）
- 保留范围（日期范围、数据类型、系统）
- 外部律师联系方式
- 生效日期

**供应商问题：**
- 供应商名称
- 参考协议（如果适用）
- 正在解决的问题的具体问题
- 相关合同条款

**保密协议请求：**
- 请求业务团队和联系方式
- 对方名称
- 保密协议的目的
- 双方或单方
- 任何特殊要求

### 第五步：生成回复

用收集到的细节填充模板。确保回复：
- 使用适当的语气（专业、清晰，对于商业受众不过于法律化）
- 包括回复类型所需的所有法律要素
- 引用具体日期、截止日期和责任
- 为收件人提供清晰的下一步操作
- 包括适当的免责声明或注意事项

在发送前向用户展示草稿回复。

#### 自定义指南

**必需的自定义** — 每个模板回复都必须使用：
- 正确的姓名、日期和参考编号
- 情况的具体事实
- 适用的司法管辖区和法规
- 基于咨询收到时间的正确回复截止日期
- 适当的签名块和联系信息

**语气调整** — 根据以下因素调整语气：
- **受众**：内部与外部、商业与法律、个人与监管机构
- **关系**：新对手方与现有合作伙伴与对抗性对手方
- **敏感性**：常规咨询与争议性事项与监管调查
- **紧急性**：标准时间表与需要加急回复

**司法管辖区特定调整：**
- 验证引用的法规是否适用于请求者的司法管辖区
- 调整时间表以匹配适用法律
- 包括司法管辖区特定的权利信息
- 使用司法管辖区适当的法律术语

### 第六步：模板创建（如果不存在模板）

如果用户希望创建新模板，请按照模板创建指南（见下文）进行操作，并展示完成的模板供审查。建议用户将批准的模板保存到本地设置以供将来使用。

## 回复类别

### 1. 数据主体请求（DSRs）

**子类别**：
- 收到确认
- 身份验证请求
- 履行回复（访问、删除、更正）
- 部分拒绝并说明
- 完全拒绝并说明
- 延期通知

**关键模板元素**：
- 引用适用法规（GDPR、CCPA 等）
- 具体的回复时间表
- 身份验证要求
- 数据主体的权利（包括向监管机构投诉的权利）
- 跟进联系信息

**示例模板结构**：
```
主题：您的数据 [访问/删除/更正] 请求 - 参考 {{request_id}}

尊敬的 {{requester_name}}，

我们已收到您于 {{request_date}} 提出的在 [适用法规] 下 [访问/删除/更正] 您个人数据的请求。

[收到确认 / 验证请求 / 履行细节 / 拒绝依据]

我们将在 {{response_deadline}} 前做出实质性回复。

[联系信息]
[权利信息]
```

### 2. 诉讼保留（诉讼保留）

**子类别**：
- 向保管人发出初始保留通知
- 保留提醒/定期重申
- 保留修改（范围变更）
- 保留解除

**关键模板元素**：
- 事项名称和参考编号
- 清晰的保留义务
- 保留范围（日期范围、数据类型、系统、通信类型）
- 禁止销毁证据
- 提问联系人
- 确认要求

**示例模板结构**：
```
主题：法律保留通知 - {{matter_name}} - 行动要求

机密
律师-客户沟通

尊敬的 {{custodian_name}}，

您收到此通知是因为您可能拥有与上述事项相关的文件、通信或数据。

保留义务：
立即，您必须保留所有与以下内容相关的文件和电子存储信息（ESI）：
- 主题：{{hold_scope}}
- 日期范围：{{start_date}} 至现在
- 文件类型：{{document_types}}

不要删除、销毁、修改或丢弃任何可能相关的材料。

[针对系统、电子邮件、聊天、本地文件的特定说明]

请在 {{acknowledgment_deadline}} 前确认收到此通知。

联系 {{legal_contact}} 提出任何问题。
```

### 3. 隐私咨询

**子类别**：
- Cookie/跟踪咨询回复
- 隐私政策问题
- 数据共享实践咨询
- 儿童数据咨询
- 跨境传输问题

**关键模板元素**：
- 引用组织的隐私声明
- 基于当前实践的具体答案
- 链接到相关隐私文件
- 隐私团队联系信息

### 4. 供应商法律问题

**子类别**：
- 合同状态咨询回复
- 修订请求回复
- 合规认证请求
- 审计请求回复
- 保险证书请求

**关键模板元素**：
- 引用适用协议
- 对供应商问题的具体回复
- 任何必要的限制或免责声明
- 下一步操作和时间表

### 5. 保密协议请求

**子类别**：
- 发送组织的标准保密协议表单
- 接受对方保密协议（带批注）
- 拒绝保密协议请求并说明
- 保密协议续签或延期

**关键模板元素**：
- 保密协议的目的
- 标准条款摘要
- 签署说明
- 时间预期

### 6. 传票/法律程序

**子类别**：
- 收到确认
- 异议信
- 延期请求
- 合规封面信

**关键模板元素**：
- 案件参考和司法管辖区
- 具体异议（如果有）
- 保留确认
- 履行时间表
- 特权日志参考（如果适用）

**重要提示**：传票回复几乎始终需要个别律师审查。模板仅作为起点框架，不是最终回复。

### 7. 保险通知

**子类别**：
- 初始索赔通知
- 补充信息
- 保留权利回复

**关键模板元素**：
- 保单编号和承保期间
- 事项或事件的描述
- 事件时间线
- 请求的承保确认

## 模板管理方法论

### 模板组织

模板应按类别组织并维护在团队的本地设置中。每个模板应包括：

1. **类别**：模板解决的咨询类型
2. **模板名称**：描述性标识符
3. **使用场景**：何时适用此模板
4. **升级触发器**：何时不应使用此模板
5. **所需变量**：每个使用必须自定义的信息
6. **模板正文**：带有变量占位符的回复文本
7. **后续操作**：发送回复后的标准步骤
8. **最后审查日期**：上次验证准确性的日期

### 模板生命周期

1. **创建**：根据最佳实践和团队输入起草模板
2. **审查**：法律团队审查和批准模板内容
3. **发布**：将模板添加到模板库并添加元数据
4. **使用**：使用模板生成回复
5. **反馈**：跟踪模板在使用过程中是否修改，以识别改进机会
6. **更新**：当法律、政策或最佳实践发生变化时修订模板
7. **退休**：存档不再适用的模板

## 模板创建指南

在帮助用户创建新模板时：

### 第一步：定义使用场景
- 此模板解决什么类型的咨询？
- 此类咨询出现频率如何？
- 典型的受众是谁？
- 典型的紧急程度如何？

### 第二步：确定所需元素
- 每个回复必须包含哪些信息？
- 适用哪些法规要求？
- 哪些组织政策管理此类回复？

### 第三步：定义变量
- 每次使用时会发生什么变化？（姓名、日期、具体细节）
- 哪些保持不变？（法律要求、标准语言）
- 使用清晰的变量名称：`{{requester_name}}`，`{{response_deadline}}`，`{{matter_reference}}`

### 第四步：起草模板
- 使用清晰、专业的语言编写
- 避免对商业受众不必要的法律术语
- 包括所有法律要求要素
- 添加所有变量内容的占位符
- 如果用于电子邮件，请包括主题行模板

### 第五步：定义升级触发器
- 哪些情况不应使用此模板？
- 哪些特征表明事项需要个别关注？
- 要具体：模糊的触发器没有用

### 第六步：添加元数据
- 模板名称和类别
- 版本号和最后审查日期
- 作者和批准者
- 后续操作清单

### 模板格式

```markdown
## 模板：{{template_name}}
**类别**：{{category}}
**版本**：{{version}} | **最后审查**：{{date}}
**批准人**：{{approver}}

### 使用场景
- [条件 1]
- [条件 2]

### 不应使用（升级触发器）
- [触发器 1]
- [触发器 2]

### 变量
| 变量 | 描述 | 示例 |
|---|---|---|
| {{var1}} | [它是什么] | [示例值] |
| {{var2}} | [它是什么] | [示例值] |

### 主题行
[使用 {{variables}} 的主题模板]

### 正文
[带有 {{variables}} 的回复正文]

### 后续操作
1. [操作 1]
2. [操作 2]

### 备注
[此模板用户的任何特殊说明]
```

## 输出格式

```
## 生成的回复：[咨询类型]

**收件人**：[收件人]
**主题**：[主题行]

---

[回复正文]

---

### 升级检查
[确认未检测到升级触发器，或标记有建议的触发器]

### 后续操作
1. [发送后操作]
2. [设置日历提醒]
3. [跟踪或记录要求]
```

## 注意事项

- 始终在建议发送前向用户展示草稿回复
- 如果通过 MCP 连接到电子邮件，请提供使用回复创建草稿电子邮件的选项
- 跟踪回复截止日期，并提供设置日历提醒的选项
- 对于受监管的回复（DSRs、传票），始终注明适用截止日期和监管要求
- 模板应该是“活文档”；当用户修改模板回复时，建议更新模板，以便随着时间的推移改进模板
