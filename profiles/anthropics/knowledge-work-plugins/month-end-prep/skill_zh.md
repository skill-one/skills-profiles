# 月末准备工作

## 快速入门

连接您的账簿和至少一个支付处理器，然后说“让我们结账这个月。”Claude 将引导您完成清单的每个步骤，在每个关卡暂停以获取您的输入，然后才能继续前进。

任何连接的账簿都可以进行结账。每个账簿都有一个用于读取的参考文件和“需要关注”的信号：[reference/quickbooks-reconcile.md](reference/quickbooks-reconcile.md)、[reference/xero-reconcile.md](reference/xero-reconcile.md)、[reference/zoho-books-reconcile.md](reference/zoho-books-reconcile.md)；NetSuite 和 MYOB 在 [reference/v2_sources.md](reference/v2_sources.md) 中。账簿是平等的 (`../../shared/connector-neutrality.md`)：如果两个账簿都连接，请询问哪个持有要结账的账簿，只读取另一个独特持有的内容，并且永远不要在两个账簿之间汇总数字。

每个金额都是业务的本币 (`../../shared/currency-and-locale.md`)。下面的阈值（0.50、0.01、25）也是以该货币表示的。

如果缺少连接器，Claude 会回退到请求 CSV 导出——它不会在无声中跳过步骤。

## 工作流程

按顺序完成这些步骤。每个步骤都有一个完成状态；在当前步骤确定之前，不要继续前进。

### 第 1 步——同意目标月份

询问用户要结账的月份。如果他们没有指定，则默认为上一个日历月。在拉取任何数据之前进行确认。

### 第 2 步——拉取账簿的损益表和登记簿

获取：
- 目标月份的损益表（收入、成本、毛利、营业费用、净收入）
- 登记簿，如账簿的参考文件定义的那样。QuickBooks：交易列表，每条收入和费用行。Xero：账单、发票和银行交易队列，范围在数据包中说明。Zoho Books：发票、费用和采购订单，损益表本身来自导出，因为连接器没有报告端点。

立即使用账簿自己的“需要关注”信号进行标记：
- **QuickBooks** — 未分类的行（“未分类”、“空白”、“询问我的会计师”）及其需要审查标志
- **Xero** — 月末仍未核对的银行行
- **Zoho Books** — 每个银行账户上的 `uncategorized_transactions` 计数

向用户显示计数（“14 笔交易需要关注”），并列出它们以供用户在账簿中解决，然后才能继续进行。除非用户明确说“暂时跳过”，否则不要在打开的项目上继续前进。

见 [reference/quickbooks-reconcile.md](reference/quickbooks-reconcile.md)、[reference/xero-reconcile.md](reference/xero-reconcile.md) 和 [reference/zoho-books-reconcile.md](reference/zoho-books-reconcile.md) 以获取字段映射和 API 注释。

### 第 3 步——拉取支付处理器的结算

获取与连接的 PayPal、Square、Stripe 或 Shopify 的结算报告，时间为相同的日历月。

**首先检查银行流水。** 当处理器通过银行流水付款时，付款已经是账簿行，问题是它是否已匹配。查找命名处理器的未核银行行，并按处理器列出它们作为行动项目，然后再进行任何 CSV 匹配。这适用于任何带有已核销状态的银行流水的账簿——在 Xero 中是常见情况，以及当连接器暴露 QuickBooks 银行流水行时。MYOB 没有银行方面，Zoho Books 暴露余额但没有银行交易列表，因此 MYOB 或 Zoho Books 的结账直接进入下面的 CSV 匹配。

**净对净比较，否则每行都看起来是错误的。** 账簿记录净银行存款；处理器的报告显示毛销售额。直接匹配它们，并且每一行都显示与费用相同大小的差异。使用处理器的 **净支付**（毛额减去费用）——见 [reference/gotchas.md](reference/gotchas.md)。

将每个结算存款与账簿的银行存款行进行匹配：
- **匹配** — 金额和日期在 2 天内一致 → 标记为已核销
- **差异 < 0.50** — 四舍五入/费用；记录但不要标记
- **差异 ≥ 0.50** — 带有差额金额标记
- **结算存在，账簿存款不存在** — 标记为“账簿中缺失”
- **账簿存款存在，结算不存在** — 标记为“处理器数据中不存在存款”

见 [reference/paypal-settlements.md](reference/paypal-settlements.md) 以获取结算报告字段映射（PayPal、Square、Stripe）和 [reference/v2_sources.md](reference/v2_sources.md) 以获取 Shopify。

### 第 4 步——检测可疑重复项

扫描登记簿以查找可能的重复收费或存款。当所有三个都匹配时，将交易标记为可疑重复项：
- 相同金额（在 0.01 内）
- 相同供应商或客户名称
- 在彼此 5 个日历日内发布

扫描账簿实际持有的内容。在 QuickBooks 中，这是交易列表，将拆分行按交易 ID 首先分组。在 Xero 中，重复键入的账单会生成两个未支付的文档和没有银行行，因此扫描账单和发票（相同联系人、相同总金额、在 5 天内、都未支付或一个在窗口内支付）而不是银行行——映射在 [reference/xero-reconcile.md](reference/xero-reconcile.md) 中。Zoho Books 是相同的形状：扫描文档作为发票和费用（[reference/zoho-books-reconcile.md](reference/zoho-books-reconcile.md)）。

向用户显示标记的对。他们决定每个是否合法（例如，每周一次的定期订阅）或真实重复项以作废。

**5 天窗口是一个过滤器，不是一个保证。** 它可以捕获两次输入的相同收费，而不会让所有者淹没在每周的定期账单中，但三周 apart 的真实双倍支付会溜走。说明扫描的内容（“5 天内重复”），如果他们对供应商有疑问，则放宽窗口，而不是称之为干净。

见 [reference/gotchas.md](reference/gotchas.md) 以获取常见误报模式以及如何区分它们。

### 第 5 步——收据检查

首先检查账簿：交易上的附件计为已存档的收据（QuickBooks 中的 `AttachmentCount`；Xero 中的 `has_attachments`，仅当 `include_line_items=true` 时返回；Zoho Books 发票和费用上的 `has_attachment`）。然后，如果桌面连接器可用，扫描目标月份的收据文件夹（请求用户提供路径；默认 `~/Documents/Receipts`）。

对于每笔金额超过 25 且没有附加文档的费用交易：
- 检查是否存在匹配的收据文件（按金额 ± 0.50 和日期在 3 天内匹配）
- **匹配** → 记录为“已存档收据”
- **未匹配** → 标记为“缺少收据”

列出缺少的收据。用户可以提供文件或标记为“不需要收据”（例如，没有收据的定期自动付款）。

如果桌面连接器不可用，请询问用户他们是否有收据的哪些费用——不要在无声中跳过此步骤。

### 第 5a 步——工资单交叉检查

仅当连接了工资单连接器（Gusto 或 QuickBooks Payroll — 平等，无论哪个连接）时运行。否则跳过它，并在数据包中说明没有工资单列。

拉取本月实际支付的总额：

- **Gusto** — `list_payrolls` 使用 `include=totals`，保留 `check_date` 落在目标月份的工资单。从每个 `totals`：`gross_pay`、`employer_taxes`、`employee_taxes`、`net_pay`。然后 `list_contractor_payments` 对于相同日期范围使用 `group_by_date=true`，取 `total.wages` 和 `total.reimbursements`。承包商总额仅涵盖美国承包商——在数据包脚注中说明。
- **QuickBooks Payroll** — `qbo_payroll_get_company_last_payroll_run` 用于最近的运行；月份内更早的运行来自工资单摘要导出。（在第一次结账之前确认。）

与账簿交叉检查：净工资加上雇主税费加上承包商工资应作为本月的工资费用行出现。差异超过 0.50 是核销项目——通常是发布到错误月份的运行，或尚未发布的工资单分录。

**仅总额，从不为个人。** 数据包包含本月的总额和运行计数。没有员工姓名、费率或每人金额离开连接器——那是工资数据，并且 `payroll-prep` 是它所属的地方。见 [reference/v2_sources.md](reference/v2_sources.md) 以获取字段映射。

### 第 6 步——所有者确认关卡

在继续之前显示摘要：

```
需要关注（未分类或未核销）： X of X 已解决
结算差异：                        X 标记，X 已解决
可疑重复项：                           X 标记，X 已清除
缺少收据：                                X 未解决
工资单交叉检查：                             匹配 / X 差异 / 没有工资单连接器
```

询问：“准备好编写损益表摘要并导出结账数据包？”

**在未明确确认的情况下不要继续到步骤 7–8。**

### 第 7 步——编写损益表说明

编写一个简体中文摘要，说明本月——所有者会与配偶或会计师分享，而不是 CFO 的备忘录。目标为 150–250 字。

结构：
1. **标题** — 一句话： “3 月净额为 12,400 澳元，比 2 月增长 6%。” 货币代码，不要裸露符号。
2. **收入** — 推动数字的因素；如果数据显示集中，请命名产品、服务或客户。
3. **毛利** — 它是否保持、上升或压缩，以及主要原因。
4. **主要费用** — 任何超过 10% MoM 或超出正常范围的行；每行一句。
5. **底线** — 净收入与上个月相比；询问他们是否有目标进行比较。
6. **关注列表** — 下个月要监控 1–3 件事。

避免术语；如果任何内容不是简体中文，请定义它（“MoM” = 月环比）。

见 [reference/examples/pl-narrative.md](reference/examples/pl-narrative.md) 以获取已完成的损益表说明示例。

### 第 8 步——导出结账数据包

生成两个文件：

**`close-packet-[YYYY-MM].xlsx`** — 三个工作表，连接了工资单连接器时为四个：
- `P&L` — 账簿的损益表数据，格式化
- `Reconciliation` — 匹配和标记的交易并排显示
- `Action Items` — 任何未解决的标记（未分类、缺少收据等）
- `Payroll` — 步骤 5a 的总额旁边是账簿的工资费用，以及差异

**`close-packet-[YYYY-MM]-summary.pdf`** — 一页：
- 顶部是月份和公司名称
- 关键指标（收入、毛利%、净收入）
- 步骤 7 的损益表说明
- 如果有的话，未解决行动项目的计数

将两个文件都保存到桌面（或用户指定的路径）。确认文件位置。

见 [reference/close-packet-format.md](reference/close-packet-format.md) 以获取列规范和 PDF 布局详细信息。

还以所有者存储的输出偏好为页面交付结账——永远不会默认为 Markdown 文件。检查 `## 业务背景` 块的 `Output preference`（共享样式指南规则，`../../shared/artifact-style.md`）：

- **视觉工件（默认）：** 以公司风格渲染结账为 HTML 页面——作为聊天摘要和文件的补充，永远不会是替代品。收入、毛利百分比和净收入是带有其月环比变化的统计瓦片；核销结果是一个带有 tabular-nums 金额的表格；每个标记都带有状态药丸——适用于已核销、警告用于缺少收据和未分类项、对于未解决的结算差距和重复项为关键；损益表说明和未解决项清单每个都得到一个面板。
- **docx / md / notion / canva 偏好：** 以该形式交付相同内容——DOCX 或 Markdown 文件、通过连接器创建的 Notion 页面（命名目的地，永远不会覆盖）、或通过 Canva 连接器创建的 Canva 文档（每次运行都是新设计，以日期命名；表格变为列表）；如果 Notion 或 Canva 未连接，则回退到视觉工件——并说明原因。数据包 xlsx 和 PDF 保持其格式。
- **技能最佳：** 使用视觉工件——在数据包发送给会计师之前，结账在屏幕上审查。

### 第 9 步——结账后

用一句话说明已结账的内容和仍需处理的内容。然后提供最相关的单个下一步行动，最多两个其他行动：

- “现金预测” 运行 `cash-flow-snapshot`，基于新结账的数字。
- “为我创建报告” 运行 `report-builder` 以发布和分发数据包。
- “税务” 运行 `/tax-prep`，当季度或年度结束时——仅在业务背景说明国家是美国时提供，因为该链的税务计算是美国的联邦。

最多三个提议。永远不会重复本会话中所有者拒绝的提议。

## 批准关卡

- **永远不要在已提交的月份上运行核销。** 在拉取数据之前确认账簿仍然打开。
- **永远不要直接在账簿交易中作废或修改。** 显示标记；所有者会在账簿中做出更改。
- **总是在步骤 6** 之前暂停，然后再生成输出。必须确认未解决的标记或明确跳过。
- **永远不要在结账包中重新创建个人工资、SSN 或银行号码** 超过工资单总额 (`../../shared/personal-data.md`)。

## 平滑退化

| 缺少连接器 | 回退 |
|---|---|
| QuickBooks | 请求 **两个单独的导出** — 损益表报告，和按账户的交易明细报告。一个文件不会包含两者；请求“一个 QB 导出”会得到其中一个，并需要第二轮行程 |
| Xero | 请求 **两个导出** — 损益表报告，和所有账户都选中的账户交易报告——再加上银行核销屏幕上的未核销行计数，导出不包含它 |
| NetSuite 或 MYOB | 请求本月的损益表和交易明细作为两个导出；MYOB 没有银行余额，因此银行方面来自报表 |
| Zoho Books | 即使连接，也请求 **损益表** 导出（没有报告端点）和 **银行对账单**（没有银行交易列表）；登记簿和未分类计数来自连接器。未连接：添加账户交易导出 |
| 支付处理器 | 从处理器的网站请求结算 CSV。它必须包括费用列，而不仅仅是毛额，否则步骤 3 中的净对净匹配无法完成 |
| 支付处理器连接但返回该期间零付款 | 视为数据差距，而不是干净的零。说明连接器本月返回了什么，请求相同的结算 CSV（包括费用列），并在报告中命名差距，而不是与空集合核销 |
| 工资单连接器（Gusto、QuickBooks Payroll） | 跳过步骤 5a。数据包没有工资单工作表，摘要说明“没有工资单连接器”；账簿的工资费用行仍然出现在损益表中未检查 |
| 桌面（收据） | 请求用户确认每笔标记费用的收据状态 |

## 更多来源

阅读 `reference/v2_sources.md` 以获取映射：

- **Shopify** — 结算核销作为一级路径。订单、付款和费用各自不同落地，并且它是无法解释差距的常见来源
- **NetSuite** — 记录账簿，在较大端段的细分市场中很常见；报告和 SuiteQL 供应损益表和登记簿
- **Xero** — 记录账簿，具有自己的登记簿形状（账单、发票、银行队列）和自己的关注信号（未核对的银行行）；在 `reference/xero-reconcile.md` 中映射
- **MYOB** — 损益表和 AR/AP 余额；没有银行余额，因此结账的银行方面来自报表
- **Zoho Books** — 记录账簿，具有文档登记簿（发票、费用、采购订单），银行余额带有未分类计数作为关注信号，没有报告或银行端点，因此损益表和付款匹配来自导出；在 `reference/zoho-books-reconcile.md` 中映射
- **Ramp、Expensify** — 卡和费用明细，关闭了实际支出和编码之间的差距
- **Gusto、QuickBooks Payroll** — 实际运行的工资：毛工资、雇主税费、净工资和承包商付款作为月总额，因此步骤 5a 将账簿的工资费用与实际支付的进行核销，而不是计划的。仅总额；没有个人数据进入数据包

相同的结账序列，相同的数据包。更多来源核销。

**QuickBooks 摘要字段撒谎。** 在引用任何 QuickBooks 摘要对象的总额之前阅读 `../../shared/quickbooks-report-traps.md`：AP 老龄化摘要将供应商信贷净额到其桶中，并可能显示负逾期金额，并且损益表摘要可能报告费用为零，但实际行。总计行，或使用详细调用。
