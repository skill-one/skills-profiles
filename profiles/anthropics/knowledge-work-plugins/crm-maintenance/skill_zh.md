# CRM 维护

## 快速入门

从引用的电子邮件或日历事件中提取上下文，解析正确的 HubSpot 联系人和交易，记录活动，并展示已更改的内容。对于交易清理，根据最近的电子邮件/日历活动审计交易并提出更新建议——未经批准，切勿应用这些更改。

```
用户："将此通话记录到 Acme 交易中"
→ 读取最近完成的日历事件
→ 确认与会者映射到 Acme 交易的联系人
→ 在 Acme 交易上记录通话活动
→ 报告："已将通话记录到 Acme Q2 扩张。[交易链接]"
```

## 工作流程

1. **识别意图。** 根据用户的消息和上下文，确定适用于以下三种路径中的哪一种：
   - **电子邮件路径** — "更新我的 CRM"、"将此添加到交易中" 或任何提及电子邮件线程的参考
   - **通话路径** — "记录此通话"、"记录会议" 或任何提及日历事件的参考
   - **清理路径** — "清理 HubSpot"、"此交易是否最新" 或任何要求审计特定交易的请求
   如果意图不明确（例如，没有引用电子邮件/会议/交易的 "更新 HubSpot"），请在继续之前询问路径。

2. **收集上下文。**
   - 电子邮件路径：读取线程（主题、参与者、最后 1-3 条消息）。确定主要外部联系人。
   - 通话路径：读取日历事件（标题、与会者、时间、描述）。如果没有指定事件，请使用过去 24 小时内最近完成的会议，并在继续之前确认用户。
   - 清理路径：提取交易（阶段、金额、关闭日期、下一步、相关联系人、过去 60 天内的活动），以及涉及交易联系人的最后 14 天的电子邮件线程和日历事件。

3. **解析 HubSpot 联系人和交易。** 对于电子邮件/通话路径：
   - 通过电子邮件地址搜索 HubSpot 联系人。如果缺少联系人，请从电子邮件签名或日历邀请数据中创建它——在写入聊天之前宣布创建。
   - 按以下顺序查找正确的交易：(a) 如果用户命名了一个交易，则进行显式匹配；(b) 联系人的唯一开放交易；(c) 模糊匹配联系人的开放交易与电子邮件主题或会议标题——在写入前确认；(d) 如果没有匹配项，请询问用户。**切勿自动创建交易。**
   - 对于字段名称、活动类型和关联规则，在写入任何内容到 HubSpot 之前，请阅读 [参考/hubspot-fields.md](reference/hubspot-fields.md)。
   - 如果去重或交易解析感觉模糊，请在继续之前检查 [参考/gotchas.md](reference/gotchas.md)——它涵盖了最常见的失败模式。

4. **执行操作。**
   - 电子邮件路径：使用线程主题作为标题，并使用简洁的摘要（不是完整线程）作为正文写入电子邮件活动。时间戳到最新消息。有关示例，请参阅 [参考/examples/log-email-happy-path.md](reference/examples/log-email-happy-path.md)。
   - 通话路径：使用事件标题、持续时间和任何可用笔记写入通话活动。时间戳到事件开始。有关包括缺少联系人场景的示例，请参阅 [参考/examples/log-call-happy-path.md](reference/examples/log-call-happy-path.md)。
   - 清理路径：根据 [参考/cleanup-checklist.md](reference/cleanup-checklist.md) 检查每个字段，并组装一个建议更改列表。并排显示当前值和建议值。仅写入用户批准的内容。有关完整示例，请参阅 [参考/examples/cleanup-deal.md](reference/examples/cleanup-deal.md)。

5. **批准门禁——每个对外可见的写入。** 对于联系人创建和活动记录，在写入前宣布并在写入后展示结果。对于清理编辑，在用户批准具体更改之前，不要写入任何内容。

6. **报告已发生的事情。** 告诉用户已写入的内容和待处理的内容。在可能的情况下，包括受影响交易的 HubSpot 链接。保持简短。

## 批准门禁

- **切勿删除记录。** 无论是联系人、交易还是活动。如果用户要求，请说明该技能无法执行，并指导他们使用 HubSpot。
- **未经明确用户批准，切勿更改交易阶段或关闭交易。** 即使有强有力的证据。标记并推迟。
- **切勿未经提示创建新交易。** 如果无法解析正确的交易，请询问。
- **在写入前宣布联系人创建。** 一行——让用户捕获拼写错误或重复项。
- **清理时的并排差异。** 显示当前值和建议值；逐项等待批准。
