# /brief -- 法律团队简报

> 如果您看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

为法律工作生成情境化简报。支持三种模式：每日简报、主题简报和事件简报。

**重要提示**：此命令协助法律工作流程，但不会提供法律建议。简报应在依赖之前由合格的法律专业人士进行审查。

## 调用方式

```
/brief daily              # 早晨法律相关事项简报
/brief topic [查询]      # 针对特定法律问题的研究简报
/brief incident [主题]   # 关于正在发展情况的快速简报
```

如果未指定模式，将询问用户需要哪种类型的简报。

## 模式

---

### 每日简报

法律团队成员开始一天工作所需了解事项的早晨摘要。

#### 需扫描的来源

检查每个已连接的来源，查找法律相关事项：

**电子邮件（如果已连接）：**
- 新合同请求或审阅请求
- 合规性问题或报告
- 交易对手方在活跃谈判中的回复
- 法律团队收件箱中的标记或紧急事项
- 外部律师沟通
- 监管或法律更新简报

**日历（如果已连接）：**
- 需要法律准备的本日会议（董事会会议、交易审阅、供应商电话会议）
- 本周即将到期的截止日期（合同到期、提交截止日期、回复截止日期）
- 定期法律团队同步会议

**聊天（如果已连接）：**
- 法律团队频道中的夜间消息
- 请求法律意见的直接消息
- 提及法律相关主题（合同、合规、隐私、保密协议、条款）
- 升级或紧急请求

**CLM（如果已连接）：**
- 等待审阅或签署的合同
- 30天内即将到期的合同
- 新签署的协议

**CRM（如果已连接）：**
- 进入需要法律参与的阶段的交易
- 标记供法律审阅的新机会

#### 输出格式

```
## 每日法律简报 -- [日期]

### 紧急 / 需采取行动
[需要立即关注的项，按紧急程度排序]

### 合同流程
- **等待您的审阅**：[数量和列表]
- **等待交易对手方回复**：[数量和列表]
- **即将到期**：[本周到期的项]

### 新请求
[自上次简报以来收到的合同审阅请求、保密协议请求、合规问题]

### 今日日历
[与法律相关的会议和需要准备的资料]

### 团队活动
[法律团队频道中的关键消息或更新]

### 本周截止日期
[即将到来的截止日期和提交日期]

### 不可用的来源
[未连接或返回错误的任何来源]
```

---

### 主题简报

跨可用来源研究和简报特定法律问题或主题。

#### 工作流程

1. 接收用户提供的主题查询
2. 在已连接的来源中搜索：
   - **文档**：内部备忘录、先前分析、操作手册、先例
   - **电子邮件**：关于该主题的先前沟通
   - **聊天**：团队关于该主题的讨论
   - **CLM**：相关合同或条款
3. 将发现结果整合为结构化简报

#### 输出格式

```
## 主题简报：[主题]

### 摘要
[发现要点的2-3句执行摘要]

### 背景
[来自内部来源的背景和历史]

### 当前状态
[基于可用文档，组织当前立场或方法]

### 关键考虑因素
[重要因素、风险或开放问题]

### 内部先例
[在内部来源中发现的先前决定、备忘录或立场]

### 缺失项
[缺失的信息或不可用的来源]

### 建议的下一步行动
[用户应如何使用这些信息]
```

#### 重要提示
- 主题简报整合已连接来源中可用的信息；它们不能替代正式法律研究
- 如果主题需要当前法律权威或案例法，建议用户咨询法律研究平台（Westlaw、Lexis等）或外部律师
- 始终注明搜索来源的限制

---

### 事件简报

需要立即法律关注的正在发展情况（数据泄露、诉讼威胁、监管调查、知识产权纠纷等）的快速简报。

#### 工作流程

1. 接收事件主题或描述
2. 快速扫描所有已连接的来源，查找相关背景：
   - **电子邮件**：关于事件的沟通
   - **聊天**：实时讨论和升级
   - **文档**：相关政策、响应计划、保险范围
   - **日历**：计划的响应会议
   - **CLM**：受影响的合同、赔偿条款、保险要求
3. 整合为可操作的事件简报

#### 输出格式

```
## 事件简报：[主题]
**准备时间**：[时间戳]
**分类**：[如果可确定，进行严重程度评估]

### 情况摘要
[关于事件的已知信息]

### 时间线
[基于可用来源的事件时间顺序总结]

### 立即法律考虑事项
[监管通知要求、证据保存义务、特权问题]

### 相关协议
[可能受影响的合同、保险政策或其他协议]

### 内部响应
[根据电子邮件/聊天已发生的响应活动]

### 关键联系人
[从来源中识别的相关内部和外部联系人]

### 建议的立即行动
1. [最紧急的行动]
2. [第二优先级]
3. [等]

### 信息缺失
[尚未知晓且需要确定的事项]

### 检查的来源
[已搜索和不可用的内容]

```

#### 事件简报的重要提示
- 速度至关重要。用可用信息快速生成简报，而不是等待完整信息
- 立即标记任何诉讼保留或证据保存义务
- 注特权考虑（如果适用，将简报标记为律师-客户特权/工作成果）
- 如果事件可能涉及数据泄露，标记适用的通知截止日期（例如，GDPR的72小时）
- 如果事项重大，建议聘请外部律师

## 一般说明

- 如果来源不可用，请突出显示差距，以便用户知道哪些内容未被检查
- 对于每日简报，随着时间的推移学习用户的偏好（他们觉得有用的内容、他们希望过滤掉的内容）
- 简报应可操作：每项内容应有明确的下一步行动或包含原因
- 保持简报简洁。链接到来源材料，而不是全文复制
