# Slack 消息最佳实践

这项技能为编写格式良好、有效的 Slack 消息提供指导。

## 何时使用

无论何时编写、起草或帮助用户撰写 Slack 消息时，都应使用此技能——包括使用 `slack_send_message`、`slack_send_message_draft` 或 `slack_create_canvas` 时。

## Slack 格式 (mrkdwn)

Slack 使用自己的标记语法，称为 **mrkdwn**，这与标准 Markdown 不同。编写 Slack 消息时始终使用 mrkdwn：

| 格式     | 语法        | 备注 |
|---------|------------|------|
| 粗体     | `*text*`   | 使用单星号，不是双星号 |
| 斜体     | `_text_`   | 使用下划线 |
| 删除线   | `~text~`   | 使用波浪号 |
| 内联代码  | `` `code` `` | 使用反引号 |
| 代码块   | `` ```code``` `` | 使用三个反引号 |
| 引用     | `> text`   | 使用尖括号 |
| 链接     | `<url\|显示文本>` | 使用尖括号内的竖线分隔 |
| 用户提及  | `<@U123456>` | 使用尖括号内的用户 ID |
| 频道提及  | `<#C123456>` | 使用尖括号内的频道 ID |
| 项目符号列表 | `- 项目` 或 `• 项目` | 使用短横线或圆点字符 |
| 编号列表  | `1. 项目`   | 使用数字后跟句号 |

### 常见错误避免

- 不要使用 `**粗体**`（双星号）——Slack 使用 `*粗体*`（单星号）
- 不要使用 `## 标题`——Slack 不支持 Markdown 标题。应单独使用 `*粗体文本*` 在一行中
- 不要使用 `[文本](链接)` 格式创建链接——Slack 使用 `<链接|文本>` 格式
- 不要使用 `---` 创建水平分割线——Slack 无法渲染这些

## 消息结构指南

- **开门见山。** 将最重要的信息放在第一行。许多人通过手机或通知阅读 Slack，而通知中通常只显示第一行。
- **保持简短。** 目标是 1-3 个简短段落。如果消息过长，可以考虑使用 Canvas。
- **大量使用换行。** 大段文字难以阅读。用空行分隔不同的想法。
- **使用项目符号创建列表。** 任何 3 个或更多项的内容都应使用列表，而不是连续的句子。
- **突出关键信息。** 使用 `*粗体*` 突出显示姓名、日期、截止日期和行动项，以便在扫描时能注意到。

## 线索与频道礼仪

- **在线索中回复** 当回复特定消息时，以保持主频道的整洁。
- **使用 `reply_broadcast**`（同时发布到频道）仅在回复包含每个人都需要看到的信息时使用。
- **在频道中发布**（不要在线索中）当开始新主题、发布公告或向整个小组提问时。
- **不要开始新线索** 以继续现有对话——找到并回复原始消息。

## 语气与受众

- 根据频道匹配语气——`#general` 通常比 `#random` 更正式。
- 使用表情符号反应代替回复消息进行简单确认（但请注意：MCP 工具无法添加反应，因此如果合适，建议用户手动操作）。
- 编写公告时，使用清晰的结构：背景、关键信息、行动号召。
