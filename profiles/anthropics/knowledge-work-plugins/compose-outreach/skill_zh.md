# 撰写外联内容

根据 Common Room 信号，为特定公司或联系人生成三种个性化的外联格式——电子邮件、电话脚本和领英消息。

## 外联流程

### 第一步：查找目标

使用 Common Room MCP 工具查找并获取目标（公司和/或特定联系人）的数据。提取：
- 近期产品活动和参与信号
- 社区活动（帖子、问题、反应）
- 第三方意图信号（招聘信息、新闻、融资）
- 关系历史（先前的联系、会议、邮件打开情况）

如果用户指定了个人，则运行联系人级别的调研。如果只提供了公司，则根据职位、参与度和角色确定最佳目标联系人。

### 第二步：外部搜索钩子（如果 CR 信号不足）

如果 CR 返回了强烈的信号（近期活动、参与度、产品使用情况），这些信号应驱动个性化——跳过网络搜索。如果 CR 信号不足或潜在客户在 CR 中的活动很少，则运行网络搜索以查找外部钩子：

**搜索内容：**
- `"[公司名称]" 融资 OR 收购 OR 发布 OR 宣布` — 过去 30 天
- `"[联系人全名]" "[公司名称]"` — 查找近期文章、采访、领英帖子或会议演讲

**优先考虑以下外部钩子：**
- 非常近期（< 2 周）——潜在客户可能仍在考虑
- 公开可见——他们知道你可能看到了
- 变化信号——增长、新职位、新产品、新市场

如果用户明确要求网络搜索或外部钩子，无论 CR 信号丰富程度如何，都应运行。

### 第三步：触发丰富（如果可用）

如果 Spark 可用，则对目标联系人运行丰富操作以获取角色分类、背景和影响力信号。使用这些信息来校准语气和消息角度。

### 第四步：确定最佳钩子

从信号数据中确定 1–3 个最强的个性化钩子。按以下顺序排序：
1. **时效性** — 过去 7–14 天内发生
2. **具体性** — 他们采取的具体行动，而不是一般趋势
3. **相关性** — 直接连接到你的产品提供的价值

好的钩子：在社区中发布了关于 X 的问题，刚刚招聘了 5 名工程师，最近开始使用 [功能]，公司刚刚完成 B 轮融资，试用即将到期，倡导者刚刚换工作。

不好的钩子："我注意到你是客户" 或泛行业趋势。

### 第五步：生成所有三种格式

使用最强的钩子来撰写所有三种格式。每种格式都有不同的约束和惯例——请遵循 `references/outreach-formats-guide.md` 中针对每个渠道的格式特定指南。

始终生成所有三种，并清晰标注。

当用户的公司背景可用时（见 `references/my-company-context.md`），在用户的具体产品和定位基础上，构建价值桥梁和提案。

### 第六步：标注你的选择

在三个草稿之后，包括一个简短说明（2–4 句话），解释：
- 使用了哪些信号以及选择的原因
- 任何假设（例如，推断的电话目标）
- 如果主要钩子不奏效，其他角度

## 输出格式

```
## 外联内容 [姓名 / 公司]

### 📧 电子邮件

**主题：** [主题行]

[邮件正文——3–5 句话]

---

### 📞 电话脚本

**开场白：**
[开场白——对话式，1–2 句话]

**价值桥梁：**
[为什么现在打电话以及原因——2–3 句话，与信号相关]

**请求：**
[单一、低摩擦请求——例如，15 分钟通话、具体问题]

---

### 💼 领英消息

[少于 300 个字符。温暖、个性化、无推销内容。]

---

### 信号说明
[2–4 句话：使用了哪些信号、原因以及任何其他角度]
```

## 当信号数据稀疏时

如果 Common Room 对目标返回的数据很少（例如，只有姓名、职位、标签——没有活动、没有分数、没有 Spark）：

1. **不要凭空撰写外联内容。** 基于虚构信号的外联比没有外联更糟。
2. **首先运行网络搜索**——这成为你主要的个性化来源。查找近期新闻、领英帖子、会议演讲、公司公告。
3. **如果网络搜索也返回很少内容**，请诚实地呈现你所拥有的内容，并请求用户提供背景：

```
## 外联内容 [姓名 / 公司] — 有限数据

**我找到的内容：**
[来自 CR 和网络搜索的真实数据]

**我现在还没有足够的信号来撰写个性化的外联内容。** 要写出有力的内容，我需要：
- 近期活动或参与信号
- 你从先前对话中拥有的背景
- 现在联系的具体原因

你能分享以上任何信息吗？
```

## 质量标准

- 每条消息都必须引用具体内容——不接受泛泛的外联内容
- 根据背景匹配语气：对于入站/社区信号，语气要温暖和对话式；对于冷启动/高管外联，语气要更正式
- 领英消息必须少于 300 个字符——没有例外
- 电话脚本必须自然可读——在脑海中大声朗读以检查节奏
- **永远不要虚构信号**——只能引用从 Common Room 或网络搜索检索到的数据
