# /debug

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

运行结构化调试会话，以系统性地查找和修复问题。

## 使用方法

```
/debug $ARGUMENTS
```

## 工作原理

```
┌─────────────────────────────────────────────────────────────────┐
│                       DEBUG                                        │
├─────────────────────────────────────────────────────────────────┤
│  第 1 步：复现                                                  │
│  ✓ 理解预期行为与实际行为的差异                                   │
│  ✓ 确定精确的复现步骤                                             │
│  ✓ 确定范围（何时开始？影响哪些人？）                             │
│                                                                    │
│  第 2 步：隔离                                                   │
│  ✓ 缩小组件、服务或代码路径的范围                                 │
│  ✓ 检查最近的变更（部署、配置变更、依赖项）                     │
│  ✓ 查看日志和错误信息                                             │
│                                                                    │
│  第 3 步：诊断                                                  │
│  ✓ 提出假设并验证                                               │
│  ✓ 追踪代码路径                                                 │
│  ✓ 确定根本原因（而不仅仅是症状）                                 │
│                                                                    │
│  第 4 步：修复                                                   │
│  ✓ 提出带解释的修复方案                                           │
│  ✓ 考虑副作用和边界情况                                           │
│  ✓ 建议防止回归的测试                                             │
└─────────────────────────────────────────────────────────────────┘
```

## 我需要你提供的信息

请描述问题。以下信息会很有帮助：
- 错误信息或堆栈跟踪
- 复现步骤
- 最近的变更
- 日志或截图
- 预期行为与实际行为的差异

## 输出

```markdown
## 调试报告：[问题摘要]

### 复现
- **预期**：[应该发生什么]
- **实际**：[实际发生什么]
- **步骤**：[如何复现]

### 根本原因
[解释为什么会出现这个错误]

### 修复
[需要进行的代码变更或配置修复]

### 预防措施
- [需要添加的测试]
- [需要实施的防护措施]
```

## 如果连接了相关工具

如果 **~~监控** 已连接：
- 拉取问题发生时间段的日志、错误率和指标
- 显示最近的部署和配置变更，这些可能相关

如果 **~~源代码管理** 已连接：
- 确定最近修改了受影响代码路径的提交和 PR
- 检查问题是否与特定变更相关

如果 **~~项目追踪器** 已连接：
- 搜索相关的错误报告或已知问题
- 一旦确定，创建一个修复工单

## 小贴士

1. **精确分享错误信息** — 不要转述。确切的文本很重要。
2. **说明发生了什么变更** — 最近的部署、依赖项更新和配置变更是主要嫌疑对象。
3. **包含上下文** — "在测试环境中正常，但在生产环境中不正常" 或 "仅影响大型有效负载" 能快速缩小范围。
