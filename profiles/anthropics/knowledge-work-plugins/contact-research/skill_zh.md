# 联系人研究

从 Common Room 中检索全面的联系人资料。支持通过电子邮件、社交账号或姓名+公司进行查询。返回包含活动历史记录、Spark 分数、网站访问记录和 CRM 字段等丰富数据。

## 第 1 步：定位联系人

Common Room 支持多种查询方法 — 使用用户提供的信息：

| 用户提供的信息 | 查询方法 |
|----------------|----------|
| 电子邮件地址 | 通过电子邮件查询（最可靠） |
| LinkedIn、Twitter/X 或 GitHub 账号 | 通过社交账号查询 — 明确指定账号类型 |
| 姓名 + 公司 | 通过姓名+组织域名进行身份解析；若存在歧义则显示匹配结果 |
| 仅姓名 | 通过姓名搜索；若存在多个匹配项，则显示简要列表并要求用户确认 |

若未找到匹配项，则回复："Common Room 没有此人的记录。" 不要猜测或编造联系人资料。

## 第 2 步：获取联系人字段

使用 Common Room 对象目录查看可用的字段组及其内容。对于完整资料，请求所有组。对于针对性问题，仅请求相关字段。

**需要了解的关键字段组：**
- **分数** — 始终以原始值或百分位数返回，绝不能返回标签
- **近期活动** — 使用 `联系人发起` 筛选（最近 60 天）查看其行为，而非团队行为
- **网站访问记录** — 总访问次数 + 具体页面（最近 12 周）
- **Spark** — 追踪参与度演变时，检索所有 Spark

## 第 3 步：运行 Spark 丰富化（若可用）

若 Spark 可用，则使用它。Spark 提供：
- 专业背景和工作历史
- 社交存在感和影响力信号
- 人设分类：拥护者、经济购买者、技术评估者、最终用户或守门人
- 在购买过程中的推测角色

若 Spark 不可用但存在真实活动数据（近期行为、网站访问记录、社区参与），则根据这些信号推测人设。若 Spark 和活动数据均不可用，则分类为未知 — 不要仅凭职位猜测人设。

当用户希望了解此联系人参与度随时间的变化时，检索**所有 Spark**（而不仅仅是最近的 Spark）。

## 第 4 步：评估账户背景

为该联系人的母公司获取简化的账户快照。注意：
- 账户层面的开放机会、扩张信号或流失风险
- 该公司其他联系人是否活跃
- 此人的参与度与其同事相比如何

## 第 5 步：识别对话角度

根据活动和信号，呈现最强的 2-3 个钩子：
- 近期的 `联系人发起` 活动（社区帖子、产品活动、支持工单）
- 最近访问的特定网页 — 尤其是若其显示评估意图
- 职位变动、晋升或公司新闻
- 其 Spark 人设及其对沟通风格的影响
- 其在已知活跃交易中的角色

## 输出格式

仅包含实际返回数据的部分。对于无数据的部分，不要填充猜测。

**当数据丰富时：**

```
## [联系人姓名] — 资料概览

**概述**
[2 句话：其身份、角色和关系状态]

**详情**
- 职位：[职位]
- 公司：[公司]
- 电子邮件：[电子邮件]
- LinkedIn：[URL]
- 其他账号：[Twitter/X, GitHub, CRM 链接（若可用）]

**分数** [若返回分数]
[所有分数以原始值或百分位数显示]

**近期活动** (最近 60 天) [若返回活动]
[3-5 个带日期的要点]

**网站访问记录** (最近 12 周) [若有访问数据]
[总访问次数 + 访问页面列表]

**Spark 资料概览** [若 Spark 数据非空]
[人设类型、背景摘要、影响力信号]

**细分** [若返回细分]
[此联系人所属的细分名称列表]

**账户背景**
[1-2 句关于其公司状态的话]

**对话起点**
[2-3 个具体、基于信号的开放性话题]
```

**当数据稀疏（例如，仅返回姓名、职位、电子邮件、标签；sparkSummary 为空）时：**

```
## [联系人姓名] — 资料概览（有限数据）

**可用数据：** [列出 Common Room 返回的内容]

[仅呈现返回的字段]

**网络搜索**
[搜索其姓名+公司找到的结果]

**注意：** Common Room 对此联系人的数据有限。无活动历史记录、分数或 Spark 资料可用。我可以进行更深入的网络搜索或查询其公司以获取更多背景信息。
```

不要从稀疏数据生成对话起点、人设推断或参与度评估。这些需要真实信号。

## 质量标准

- 查询必须使用正确的输入类型方法 — 不要猜测电子邮件与账号的区别
- 分数始终以原始值/百分位数显示 — 绝不能返回标签
- `联系人发起` 活动（最近 60 天）是主要参与度信号 — 优先呈现
- 若 Spark 不可用，则说明 — 不要仅凭职位编造人设
- 标记任何最近活动超过 30 天的联系人
