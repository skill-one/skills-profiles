# /部署检查清单

> 如果你看到不熟悉的占位符，或者需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

在发货前生成一个预部署检查清单以验证准备情况。

## 使用方法

```
/deploy-checklist $ARGUMENTS
```

## 输出

```markdown
## 部署检查清单：[服务/版本]
**日期：** [日期] | **部署者：** [姓名]

### 部署前
- [ ] 所有CI中的测试通过
- [ ] 代码已审查并批准
- [ ] 版本中无已知严重错误
- [ ] 数据库迁移已测试（如适用）
- [ ] 功能开关已配置（如适用）
- [ ] 回滚计划已记录
- [ ] 已通知值班团队

### 部署中
- [ ] 部署到预发布环境并验证
- [ ] 运行冒烟测试
- [ ] 部署到生产环境（如有可用则进行金丝雀发布）
- [ ] 监控15分钟内的错误率和延迟
- [ ] 验证关键用户流程

### 部署后
- [ ] 确认指标正常
- [ ] 更新版本说明/变更日志
- [ ] 通知相关方
- [ ] 关闭相关工单

### 回滚触发条件
- 错误率超过 [X]%
- P50延迟超过 [X]ms
- [关键用户流程] 失败
```

## 定制化

告诉我你的部署情况，我会定制检查清单：
- "我们使用功能开关" → 添加开关验证步骤
- "这包括数据库迁移" → 添加迁移特定检查
- "这是一个破坏性API变更" → 添加消费者通知步骤

## 如果有连接器

如果 **~~源代码管理** 已连接：
- 拉取版本差异和变更列表
- 验证所有PR是否已批准并合并

如果 **~~CI/CD** 已连接：
- 自动检查构建和测试状态
- 部署前验证流水线为绿色

如果 **~~监控** 已连接：
- 从当前基线预填回滚触发阈值
- 设置部署后指标监控

## 小贴士

1. **每次部署前运行** — 即使是常规部署。检查清单可防止"我忘记..."的情况。
2. **定制一次，重复使用** — 告诉我你的技术栈，我会记住你的部署流程。
3. **包含回滚标准** — 在部署前决定何时回滚，而不是部署中。
