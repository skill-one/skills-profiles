# /ux-copy

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

为任何界面上下文编写或审阅 UX 文本。

## 使用方法

```
/ux-copy $ARGUMENTS
```

## 我需要你提供的信息

- **上下文**：是哪个屏幕、流程或功能？
- **用户状态**：用户试图做什么？他们有什么感受？
- **语气**：正式、友好、俏皮、令人安心？
- **限制条件**：字符限制、平台指南？

## 原则

1. **清晰**：准确表达你的意思。避免行话，避免模棱两可。
2. **简洁**：用最少的字传达完整的意思。
3. **一致**：对同一事物使用相同的术语。
4. **有用**：每个字都应帮助用户实现他们的目标。
5. **人性化**：像一位乐于助人的人一样写作，而不是像机器人。

## 文本模式

### 操作按钮（CTAs）
- 以动词开头："开始免费试用"、"保存更改"、"下载报告"
- 要具体："创建账户"而不是"提交"
- 将结果与标签匹配

### 错误消息
结构：发生了什么 + 为什么 + 如何解决
- "支付失败。您的卡被银行拒绝。请尝试使用另一张卡或联系您的银行。"

### 空状态
结构：这是什么 + 为什么是空的 + 如何开始
- "还没有项目。创建您的第一个项目，开始与您的团队协作。"

### 确认对话框
- 明确行动："删除3个文件？"而不是"你确定吗？"
- 描述后果："此操作无法撤销"
- 按钮标签应与行动匹配："删除文件" / "保留文件"而不是"确定" / "取消"

### 提示框（Tooltips）
- 简洁、有帮助，但不要显而易见

### 加载状态
- 设定预期，减少焦虑

### 新手引导
- 逐步披露，一次一个概念

## 语气和风格

根据上下文调整语气：
- **成功**：庆祝但不过分
- **错误**：富有同情心且有帮助
- **警告**：清晰且可操作
- **中性**：信息丰富且简洁

## 小贴士

1. **具体说明上下文**——"支付失败时的错误消息"比"错误消息"更好。
2. **分享你的品牌语气**——"我们专业但温暖"有助于我匹配你的语气。
3. **考虑用户的情绪状态**——错误消息需要富有同情心。成功消息可以庆祝。
