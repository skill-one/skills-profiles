# 测试策略

设计有效的测试策略，平衡覆盖范围、速度和维护性。

## 测试金字塔

```
        /  E2E  \         少量、慢速、高置信度
       / 集成测试 \     一些、中速
      /    单元测试  \   大量、快速、聚焦
```

## 按组件类型制定策略

- **API 端点**：业务逻辑的单元测试、HTTP层的集成测试、消费者的契约测试
- **数据管道**：输入验证、转换正确性、幂等性测试
- **前端**：组件测试、交互测试、视觉回归、可访问性
- **基础设施**：冒烟测试、混沌工程、负载测试

## 需要覆盖的内容

重点关注：业务关键路径、错误处理、边界情况、安全边界、数据完整性。

跳过：琐碎的 getter/setter、框架代码、一次性脚本。

## 输出

生成测试计划，包括：要测试的内容、各区域的测试类型、覆盖目标、以及示例测试用例。识别现有覆盖范围的不足之处。
