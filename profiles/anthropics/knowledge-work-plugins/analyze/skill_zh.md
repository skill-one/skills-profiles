# /analyze - 回答数据问题

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

回答数据问题，从快速查询到全面分析再到正式报告。

## 使用方法

```
/analyze <自然语言问题>
```

## 工作流程

### 1. 理解问题

解析用户的问题并确定：

- **复杂程度**：
  - **快速回答**：单一指标、简单过滤、事实查询（例如，“上周有多少用户注册？”）
  - **全面分析**：多维探索、趋势分析、比较（例如，“是什么导致转化率下降？”）
  - **正式报告**：包含方法论、注意事项和建议的全面调查（例如，“准备我们订阅指标的季度业务回顾”）
- **数据需求**：需要哪些表、指标、维度和时间范围
- **输出格式**：数字、表格、图表、叙述或组合

### 2. 收集数据

**如果已连接数据仓库 MCP 服务器：**

1. 探索模式以找到相关的表和列
2. 编写 SQL 查询以提取所需数据
3. 执行查询并检索结果
4. 如果查询失败，调试并重试（检查列名、表引用、特定方言的语法）
5. 如果结果看起来出乎意料，在进行下一步之前运行合理性检查

**如果没有连接数据仓库：**

1. 要求用户提供以下方式之一的数据：
   - 直接粘贴查询结果
   - 上传 CSV 或 Excel 文件
   - 描述模式，以便你可以为他们编写查询以运行
2. 如果为手动执行编写查询，使用 `sql-queries` 技能以获取特定方言的最佳实践
3. 提供数据后，继续分析

### 3. 分析

- 计算相关指标、聚合和比较
- 识别模式、趋势、异常值和异常
- 跨维度（时间段、细分、类别）进行比较
- 对于复杂分析，将问题分解为子问题并逐一解决

### 4. 呈现前验证

在分享结果之前，运行验证检查：

- **行数合理性**：记录数是否合理？
- **空值检查**：是否有意外空值可能扭曲结果？
- **幅度检查**：数字是否在合理范围内？
- **趋势连续性**：时间序列是否有意外空白？
- **聚合逻辑**：子总计是否正确汇总到总计？

如果任何检查引发问题，调查并记录注意事项。

### 5. 呈现结果

**对于快速回答：**
- 直接陈述答案并包含相关背景
- 包括使用的查询（折叠或代码块格式）以实现可重复性

**对于全面分析：**
- 首先呈现关键发现或见解
- 用数据表格和/或可视化支持
- 注明方法论和任何注意事项
- 建议后续问题

**对于正式报告：**
- 包含关键要点的执行摘要
- 解释方法和数据来源的方法论部分
- 详细发现并附上支持证据
- 注意事项、限制和数据质量说明
- 建议和下一步行动

### 6. 在需要时可视化

当图表比表格更有效地传达结果时：

- 使用 `data-visualization` 技能选择合适的图表类型
- 生成 Python 可视化或构建到 HTML 仪表板中
- 遵循可视化最佳实践以确保清晰和准确

## 示例

**快速回答：**
```
/analyze 十二月有多少新用户注册？
```

**全面分析：**
```
/analyze 过去 3 个月支持工单量增加的原因是什么？按类别和优先级分解。
```

**正式报告：**
```
/analyze 准备我们客户表的 数据质量评估 -- 完整性、一致性以及我们应该解决的问题。
```

## 小贴士

- 尽可能具体说明时间范围、细分或指标
- 如果你知道表名，请提及它们以加快进程
- 对于复杂问题，Claude 可能将它们分解为多个查询
- 结果在呈现前总是经过验证 -- 如果有异常，Claude 会标记它
