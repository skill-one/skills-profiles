# /signature-request -- E-Signature Routing

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

准备一份用于电子签名的文档 — 验证完整性、设置签署顺序，并进行签署路由。

**重要提示**：此命令有助于法律工作流程，但并不提供法律建议。在发送签署请求前，请确认文档已最终定稿。

## 使用方法

```
/signature-request $ARGUMENTS
```

准备签署：@$1

## 工作流程

### 第一步：接受文档

以任何格式接受文档：
- **文件上传**：PDF、DOCX
- **URL**：指向云存储或 ~~CLM 中文档的链接
- **参考**："我们昨天最终确定的 Acme Corp MSA"

### 第二步：签署前检查清单

在进行签署路由前，请验证：

```markdown
## 签署前检查清单

- [ ] 文档为最终、约定的格式（无未关闭的红色修订标记）
- [ ] 所有附件和附表均已添加
- [ ] 签署栏上的法律实体名称正确
- [ ] 日期正确或留空以供签署日期
- [ ] 签署栏与授权签署人匹配
- [ ] 已获得所有必需的内部批准
- [ ] 文档已由适当的法律顾问审阅
```

### 第三步：配置签署

收集签署详情：
- **签署人**：谁需要签署？（姓名、电子邮件、职务）
- **签署顺序**：顺序签署还是并行签署？
- **内部批准**：在对方签署前是否需要有人批准？
- **抄送收件人**：谁应收到已签署文档的副本？

### 第四步：路由至签署

**如果 ~~电子签名已连接：**
- 创建签署信封/请求
- 设置签署字段和顺序
- 添加任何必需的首字母缩写或日期字段
- 发送签署请求

**如果未连接：**
- 生成签署指示文档
- 提供格式化为手写签名或手动电子签名的文档
- 列出所有签署人及其联系方式

## 输出

```markdown
## 签署请求：[文档标题]

### 文档详情
- **类型**：[MSA / NDA / SOW / 修订案 / 等.]
- **相关方**：[一方] 和 [另一方]
- **页数**：[X]

### 签署前检查：[通过 / 存在问题]
[列出在发送前需要关注的问题]

### 签署配置
| 顺序 | 签署人 | 电子邮件 | 职务 |
|-------|--------|-------|------|
| 1 | [姓名] | [电子邮件] | [一方授权签署人] |
| 2 | [姓名] | [电子邮件] | [另一方授权签署人] |

### 抄送收件人
- [姓名] — [电子邮件]

### 状态
[已发送签署请求 / 准备发送 / 需先解决部分问题]

### 下一步
- [发送后可预期的情况]
- [预计处理时间]
- [若 X 天内未签署时的后续处理]
```

## 小贴士

1. **仔细检查实体名称** — 最常见的签署错误是法律实体名称错误。
2. **验证授权** — 确保每位签署人均有权代表其组织签署。
3. **保留副本** — 签署完成后，应立即将已签署的副本存档于 ~~云存储或 ~~CLM 中。
