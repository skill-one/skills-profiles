运行客户声音合成。从所有已连接的来源中提取反馈信号，识别可实际解决的问题主题，并生成所有者可以审阅和发送的草稿回复。

解析参数：
- `--since`（默认：过去30天）— 回顾窗口的起始日期 `YYYY-MM-DD`

## 第1步 — 收集反馈信号

使用 `customer-pulse` 技能工作流：

1. 提取指定期间内的PayPal争议和 chargebacks：原因代码、金额、解决状态。
2. 提取指定期间内的HubSpot支持工单和对话记录。
3. 如果在文件中提供评审导出文件（Google Reviews CSV、Yelp导出等）：读取并解析它们。
4. 按来源统计总信号数。

## 第2步 — 主题提取

将所有信号聚类为重复出现的主题。对于每个主题：
- 统计提及该主题的信号数量
- 分类：产品质量 / 配送 / 账单 / 沟通 / 期望不符 / 其他
- 评估影响：🔴 高（收入风险、客户流失） / 🟡 中 / 🟢 低

## 第3步 — 前3个可解决的问题

使用 `ticket-deflector` 技能工作流：

按频率 × 影响评分选择前3个主题。对于每个主题：
1. 用一句话陈述问题
2. 解释根本原因（如果明显）
3. 提出具体的运营解决方案
4. 草拟客户回复模板

回复模板格式：
```
主题：回复：{问题主题}

你好 {名字}，

感谢联系。{用1-2句话认可他们的体验}。

{我们正在如何处理它 / 发生了什么 / 提供的解决方案}。

{下一步或提议}。

{结束语}
```

## 第4步 — 摘要表格

将输出格式化为：

```
客户声音 — {日期范围}
总信号数：{n} ({PayPal争议：n} | {HubSpot工单：n} | {评论：n})

前3个可解决的问题
1. {问题} ({频率}) — {影响} — 解决方案：{一句话解决方案}
2. {问题} ({频率}) — {影响} — 解决方案：{一句话解决方案}
3. {问题} ({频率}) — {影响} — 解决方案：{一句话解决方案}
```

## 连接器故障

使用已连接的任何来源运行——此命令优雅降级。如果缺少PayPal，则跳过争议数据并注明“PayPal未连接——争议数据跳过”。如果缺少HubSpot，则跳过工单数据并注明。如果没有任何来源连接，则停止并告知所有者：“未连接任何反馈来源。连接至少一个PayPal、HubSpot或上传评审导出CSV。”

## 审批关卡

- **永远不要自动发送回复邮件。** 仅向所有者展示草稿供审阅。
- **未经所有者明确确认，永远不要关闭HubSpot工单或解决PayPal争议。**
- **摘要中永远不要包含客户PII** — 仅使用名字+姓氏首字母。

## 输出

展示摘要表格，然后是每个回复模板。询问所有者他们希望发送哪些模板，然后在获得明确批准之前等待，再开始草拟发送。
