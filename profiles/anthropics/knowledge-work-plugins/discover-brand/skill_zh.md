# 品牌发现

在跨企业平台自主发现品牌材料。此技能协调发现品牌代理，搜索已连接平台（Notion、Confluence、Google Drive、Box、Microsoft 365、Figma、Gong、Granola、Slack），对来源进行分诊，并生成结构化的发现报告及开放性问题。

## 发现工作流程

### 0. 引导用户

开始前，简要说明即将发生的事情，让用户知道预期：

"品牌发现流程如下：

1. **搜索** — 我将搜索您已连接的平台（Notion、Google Drive、Slack 等）中的品牌相关材料：风格指南、提案演示文稿、模板、转录文本等。
2. **分析** — 我将分类和排序发现的内容，提取最佳来源，并生成包含发现内容、来源冲突及开放性问题的发现报告。
3. **生成指南** — 在您审阅报告后，我可以根据结果生成结构化的品牌语音指南文档。
4. **保存** — 一旦您批准指南，将保存到您工作文件夹中的 `.claude/brand-voice-guidelines.md`。在批准前不会写入任何内容。

搜索通常需要几分钟时间，具体取决于已连接平台的数量。准备好开始吗？"

等待用户确认后再继续。如果他们对流程有疑问，应先回答。

### 1. 检查设置

如果存在 `.claude/brand-voice.local.md`，则读取并提取：
- 公司名称
- 启用的平台（notion、confluence、google-drive、box、microsoft-365、figma、gong、granola、slack）
- 搜索深度偏好（标准或深度）
- 最大来源限制
- 在“已知品牌材料”下列出的任何已知品牌材料位置

如果没有设置文件，则使用所有已连接平台和标准搜索深度继续。

### 2. 验证平台覆盖范围

在确认范围前，检查实际已连接的平台并分类：

**文档平台**（品牌指南、风格指南、模板和演示文稿存储的地方）：
- Notion、Confluence、Google Drive、Box、Microsoft 365（SharePoint/OneDrive）

**补充平台**（对模式有价值，但不是存储品牌文档的地方）：
- Slack、Gong、Granola、Figma

应用以下规则：

1. **如果零个文档平台已连接**：**停止**。告知用户："您没有连接任何文档存储平台（Google Drive、SharePoint、Notion、Confluence 或 Box）。品牌指南和风格指南几乎总是存储在这些平台上。请在运行发现前连接至少一个。Gong/Granola/Slack 转录文本很有价值，但不太可能包含正式的品牌文档。"

2. **如果既没有 Google Drive，又没有 Microsoft 365，也没有 Box**：**警告**（但继续）："您的所有主要文件存储平台（Google Drive、SharePoint、Box）均未连接。品牌文档经常存储在这些平台上。发现流程将使用 [已连接平台] 继续，但结果可能存在重大缺失。请考虑连接 Google Drive 或 SharePoint。"

3. **如果总共只连接了一个平台**：**警告**（但继续）："仅连接了 [平台]。发现效果最佳时需要 2 个或更多平台进行跨来源验证。来自单个平台的结果置信度较低。"

### 3. 与用户确认范围

在启动发现前，确认：
- 要搜索哪些平台（默认：所有已连接）
- 是否包含对话转录文本（Gong、Granola）或仅文档
- 任何已知优先级位置

保持简短——一个问题，不是问卷调查。

### 4. 委派给发现品牌代理

通过任务工具启动发现品牌代理。提供：
- 公司名称（来自设置或用户输入）
- 启用平台
- 搜索深度
- 任何已知优先检查的 URL 或位置

代理将自主执行 4 阶段发现算法：
1. **广泛发现** — 跨平台并行搜索
2. **来源分诊** — 分类和排序来源
3. **深度获取** — 从最佳来源检索和提取
4. **发现报告** — 结构化输出及开放性问题

### 5. 呈现发现报告

当代理返回时，向用户呈现报告并附摘要：
- 发现和分析的总来源数量
- 发现的关键品牌元素
- 来源之间的任何冲突
- 需要团队输入的开放性问题

### 6. 提供下一步操作

在呈现报告后，提供：
1. **立即生成指南** — 使用发现报告作为输入链到 `/brand-voice:generate-guidelines`
2. **先解决开放性问题** — 在生成指南前处理高优先级问题
3. **保存报告** — 将发现报告保存到 Notion 或作为本地文件
4. **扩展搜索** — 如果覆盖范围低，搜索更多平台或更深入

## 开放性问题

当发现代理遇到无法解决的歧义时会出现开放性问题：
- 冲突文档（例如，2023 年风格指南与 2024 年品牌更新）
- 缺少关键部分（例如，未找到社交媒体指南）
- 平台间术语不一致

每个开放性问题都包含代理建议。将问题呈现为“确认或覆盖”——不是死胡同。

## 与其他技能的集成

- **指南生成**：发现品牌代理通过任务工具返回发现报告。直接将其作为结构化输入传递给指南生成技能，无需用户手动收集来源。
- **品牌语音执行**：一旦从发现生成指南，执行将自动使用这些指南。

## 错误处理

- 如果零个平台已连接，告知用户插件支持的平台及如何连接。
- 如果所有搜索均返回空结果，将发现标记为“低覆盖范围”，并建议用户手动提供文档或检查平台连接。
- 如果平台已连接但返回权限错误，记录差距并继续使用其他平台。
