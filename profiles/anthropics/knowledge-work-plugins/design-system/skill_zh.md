# /design-system

> 如果你看到不熟悉的占位符，或者需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

管理你的设计系统——检查一致性、记录组件或设计新的模式。

## 使用方法

```
/design-system audit                    # 全系统检查
/design-system document [组件]     # 记录一个组件
/design-system extend [模式]         # 设计一个新的组件或模式
```

## 设计系统的组成部分

### 设计令牌
定义视觉语言的原子值：
- 颜色（品牌、语义、中性）
- 字体（比例、字重、行高）
- 间距（比例、组件内边距）
- 边框（半径、宽度）
- 阴影（提升级别）
- 动效（持续时间、缓动曲线）

### 组件
具有定义的：
- 变体（主要、次要、幽灵）
- 状态（默认、悬停、激活、禁用、加载中、错误）
- 尺寸（小、中、大）
- 行为（交互、动画）
- 可访问性（ARIA、键盘）

### 模式
组合组件的常见 UI 解决方案：
- 表单（输入组、验证、提交）
- 导航（侧边栏、选项卡、面包屑）
- 数据展示（表格、卡片、列表）
- 反馈（提示、模态框、内联消息）

## 原则

1. **一致性优先于创意** — 系统的存在是为了避免团队重新发明轮子
2. **在约束内保持灵活性** — 组件应该是可组合的，而不是僵化的
3. **记录所有内容** — 如果没有记录，就等于不存在
4. **版本和迁移** — 破坏性变更需要迁移路径

## 小贴士

1. **从检查开始** — 在决定去哪里之前，先知道你现在在哪里。
2. **边设计边记录** — 在设计组件时记录它更容易。
3. **优先覆盖而非完美** — 记录 80% 的组件胜过 10 个组件的 100%。
