# 现金流快照

生成包含百分比差异置信区间和命名风险标志的30/60/90天现金流预测。提供两部分的输出：一份简洁的聊天摘要和一份可下载的XLSX工作簿。

**快速入门**

> “我下个月能发工资吗？”

Claude从连接的来源中提取当前的银行余额、应收账款/应付账款和固定成本，计算30、60和90天窗口内的预期现金流入和流出，应用每个客户的支付差异置信区间，并按名称标记特定风险。

---

## 工作流程

### 第1步 — 确定可用的数据源

检查哪些连接器处于活动状态。批量从每一个活动连接器中提取数据：

1. 总账 — MYOB、NetSuite、QuickBooks、Xero或Zoho Books（以连接的为准）— 用于应收账款账龄分析、应付账款、固定成本和现金余额。总账是平等的（`../../shared/connector-neutrality.md`）；如果两个总账都连接，请询问哪个是记录来源，并仅从那个来源获取总计
2. PayPal — 交易历史和结算时间
3. Square — 销售和支付历史
4. Stripe — 收款和支付历史
5. Shopify — 订单（`list-orders`）作为流入，加上支付时间。仅使用Shopify就足以运行：对于商业企业，它通常是最大的流入。支付读取可能会失败，因为连接器的范围排除了Shopify Payments — 那么请询问所有者他们的支付时间表和模型；永远不要推断延迟（`reference/v2_sources.md`）
6. CSV上传 — 当没有连接器时

如果没有任何连接器处于活动状态且未附加文件，请询问用户连接一个来源或上传CSV（收入/支出表格数据，任何合理格式）。
注意输出中使用的来源 — 这会影响置信区间的宽度。

**始终确定起始现金余额** — “我能发工资吗？”是一个关于余额的问题，而不是净额。在步骤2中提取它，或者询问：“企业账户当前有多少资金，截至什么日期？” **永远不要假设一个。** 如果没有人知道，请将输出标题为“无初始余额 — 仅显示净变化”并将现金持有量从风险标志中删除。

### 第2步 — 提取数据

**从总账：**
- 资产负债表：截至日期的银行和现金余额 — 初始余额（MYOB不持有任何；参见`reference/v2_sources.md`）
- 应收账款账龄报告：客户名称、发票金额、发票日期、到期日期、逾期天数
- 应付账款：供应商名称、应付金额、到期日期
- 定期固定成本：租金、工资、订阅（查找定期交易）

**从Gusto连接时：**
- 下一次工资运行日期和预期金额，以及常规工资时间表周期 — 最大固定成本的真实数字，而不是从定期交易中推断工资。当Gusto和总账对工资存在分歧时，信任Gusto的金额和时间，并在输出中说明

**从PayPal / Stripe / Square：**
- 结算历史：交易日期、金额、结算日期
- 使用结算延迟（交易日期→支付日期）来计算每个来源的平均和支付延迟差异

**从CSV上传：**
- 解析为收入/支出表格数据
- 必要列（灵活命名）：日期、金额、类型（收入或支出）、描述
- 如果列不明确，显示标题行并要求用户确认映射

### 第3步 — 计算历史支付时间

对于每个应收账款客户（或来自CSV的收入来源），计算：
- **平均支付延迟** — 从发票/交易日期到收款平均天数
- **支付差异** — 过去6-12笔支付中支付延迟的标准差
- 使用差异来设置置信区间宽度（参见步骤4）

如果某个客户的支付少于3笔，则使用总体平均值作为点估计，并应用±30%的差异区间作为默认值。当在具有足够历史记录的CSV数据上运行（每个来源≥3笔支付）时，根据实际支付差异计算区间 — 不要假设±30%。

### 第4步 — 构建30/60/90天预测

生成三个时间窗口：0-30天、31-60天、61-90天。

对于每个窗口，计算：

| 项目 | 方法 |
|---|---|
| 预期流入 | 窗口内到期的应收账款，根据平均支付延迟调整 |
| 预期流出 | 窗口内到期的应付账款 + 窗口内到期的固定成本 |
| 净现金余额 | 流入 - 流出 |
| 置信区间 | 预期流入的加权平均支付差异的百分比 |

置信区间公式：
```
band_pct = weighted_avg_stddev_days / avg_payment_lag_days
low  = net_cash × (1 − band_pct)
high = net_cash × (1 + band_pct)
```

将band_pct四舍五入到一位小数。上限为±50% — 更高的差异意味着数据太稀疏无法建模；相反应标记它（参见步骤5）。

### 第5步 — 标记命名风险

扫描可能导致低区间估计为负或造成流动性危机的条件。对于每个发现的风险，生成一条简短的风险标志：

- **延迟付款风险：** “客户X历史上支付延迟18天；这使他们的8,400美元发票从30天窗口移至第48天。”
- **工资危机：** “工资（22,000美元）将于4月15日支付。4月1日的31,000美元初始余额加上流入减去流出，使4月14日的低区间现金持有量为19,200美元。短缺风险：2,800美元。”需要记录的余额。
- **数据稀疏警告：** “仅记录了客户Y的2笔支付 — 置信区间设置为默认±30%。”
- **无连接器警告：** “仅使用CSV数据运行 — 没有实时的应付账款或定期成本数据。置信区间比正常情况下更宽。”

按严重程度（按美元影响大小排序）限制为前5个风险。

### 第6步 — 提供输出

**聊天摘要**（始终）。使用Markdown表格而不是代码块来显示预测 — 聊天界面渲染Markdown表格；代码块显示为原始等宽字体。格式：

- 标题行：现金流快照 — <日期范围>
- 来源：<使用的连接器>
- 初始余额：AUD X,XXX截至<日期>（或：文件中无 — 仅显示净变化）

然后是Markdown表格形式的预测，金额包含企业的货币代码（`../../shared/currency-and-locale.md`），永远不会是裸符号：

| 窗口 | 预期 | 低 | 高 |
|---|---|---|---|
| 30天净 | AUD X,XXX | AUD X,XXX | AUD X,XXX |
| 60天净 | AUD X,XXX | AUD X,XXX | AUD X,XXX |
| 90天净 | AUD X,XXX | AUD X,XXX | AUD X,XXX |

然后是风险，作为“⚠ 标记风险：<数量>”下的小型项目符号列表。

**XLSX工作簿**（始终）：首先读取`xlsx/SKILL.md`，然后生成三个工作表：

1. **摘要** — 30/60/90预测表格和置信区间。在每个窗口行下方，扩展内联子行显示构成其流入（绿色）和流出的单个交易。这使得估计可以在不离开摘要工作表的情况下进行审计。

2. **明细** — 所有按窗口分组并按日期排序的交易。包括一个运行净列（窗口内累计流入减去流出）和每个窗口底部的一个汇总行，显示总流入、总流出和净额。将过去的交易在底部单独区域中灰显以供参考。确保三个窗口都有行，即使某个窗口为空 — 显示“此窗口无交易”的占位符行。

3. **风险** — 标记的风险及其美元影响和受影响的窗口。

保存为`cash-flow-snapshot-[YYYY-MM-DD].xlsx`。

**预测页面**（始终，与聊天摘要一起提供 — 永远不能替代它），根据所有者存储的输出偏好提供 — 永远不要默认为Markdown文件。检查`## 业务背景`块的`输出偏好`（共享样式指南规则，`../../shared/artifact-style.md`）：

- **视觉对象（默认）：** 按公司风格渲染完整预测的HTML页面。30/60/90天净额是带有置信区间的统计瓦片；交易明细是一个表格，金额右对齐为tabular-nums；每个风险标志都带有状态药丸 — 对于预期的短缺为关键，对于延迟付款和数据稀疏标志为警告；来源和初始余额位于一个小型页眉面板中。
- **docx / md / notion / canva偏好：** 以该形式提供相同内容 — DOCX或Markdown文件、通过连接器创建的Notion页面（命名目标，永不覆盖）、或通过Canva连接器创建的Canva文档（每次运行都是新设计，按日期命名；表格变为列表）；如果Notion或Canva未连接，则回退到视觉对象 — 并说明原因。XLSX仍然随附。
- **最适合技能：** 使用视觉对象 — 预测可以一目了然地阅读并经常重新运行。

## 运行后

一行说明刚刚发生了什么：预测已生成，风险已命名。然后提供最相关的下一步操作，以及最多两个其他操作：

- 如果标记了工资危机：运行`plan-payroll`来“我能发工资吗？”
- “谁欠我钱？”运行`invoice-chase`来提前催收。
- “结账”运行`/close-month`以便下一个预测基于干净的账簿运行。

最多三个提议，并且永远不会重复本会话中拒绝的提议。

## 审批门槛

此技能是只读的 — 生成预测前没有审批门槛。

交付后提醒用户：
> “此预测基于[列出的来源]。它不能替代会计建议 — 在做出融资决策前请与您的账目人员核实。”

## 更多来源和计划

阅读`reference/v2_sources.md`以获取完整映射：

- **Shopify** — 支付流入时间，通常是商业企业最大的单一流入，并且结算延迟值得建模
- **NetSuite** — 记录总账，在较大规模的细分市场中很常见：应收账款、应付账款、固定成本，以及通过报告和SuiteQL提供的现金余额
- **Xero** — 记录总账：账龄应收账款、账单、银行余额，以及组织的货币和财年
- **Ramp** — 尚未进入账簿的卡消费，这是预测被悄悄乐观的最常见原因
- **Ramp余额** — 带有历史的真实业务和资金账户余额。当所有者使用Ramp进行银行时，这是一个来源的初始余额，而不是他们必须记住的数字
- **MYOB** — MYOB商店的应收账款和应付账款部分。只读，并且它**不持有任何银行或现金余额** — 永远不要从它那里获取初始余额

预测逻辑没有变化。这些是进入相同模型的额外部分。

### 按计划运行

此技能可以按计划运行。每月预设是在月份开始前提供现金预警。

在所有者发现有用的一次预测后提供它：
```
想要每月一次，在月底前几天？那时它最有用，并且是您刚刚收到的相同预测。
```

计划是这个技能的特性。没有单独的命令。

**QuickBooks摘要字段会撒谎。** 在引用QuickBooks摘要对象中的任何总计之前，请先阅读`../../shared/quickbooks-report-traps.md`：应付账款摘要会将供应商信贷计入其桶中，并可能显示负的逾期金额，并且损益摘要可能会报告费用为零对真实行。汇总行，或使用明细调用。
