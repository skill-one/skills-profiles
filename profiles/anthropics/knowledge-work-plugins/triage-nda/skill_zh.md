# /triage-nda -- NDA 预筛选

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

筛选 NDA：@$1

快速根据标准筛选标准对传入的 NDA 进行筛选。对 NDA 进行分类以便路由：标准批准、法律顾问审查或全面法律审查。

**重要提示**：你协助法律工作流程，但不提供法律建议。所有分析在依赖之前都应由合格的法律专业人士进行审查。

## 调用方式

```
/triage-nda
```

## 工作流程

### 第 1 步：接受 NDA

以任何格式接受 NDA：
- **文件上传**：PDF、DOCX 或其他文档格式
- **URL**：指向文档系统中的 NDA 的链接
- **粘贴文本**：直接粘贴的 NDA 文本

如果没有提供 NDA，提示用户提供。

### 第 2 步：加载 NDA 框架

在本地设置中查找 NDA 筛选标准（例如，`legal.local.md`）。

NDA 框架应定义：
- 互惠与单方面的要求
- 可接受的期限长度
- 必须的排除条款
- 禁止的条款
- 组织特定的要求

**如果没有配置 NDA 框架**：
- 使用合理的市场标准默认值继续
- 明确说明正在使用默认值
- 默认应用：
  - 互惠义务是必需的（除非该组织仅披露）
  - 期限：标准 2-3 年，商业秘密最长 5 年
  - 需要标准排除条款：独立开发、公开可用、从第三方合法获得、法律规定
  - 没有非招揽或非竞争条款
  - 没有残值条款（如果存在则范围狭窄）
  - 适用合理商业司法管辖区的法律

### 第 3 步：快速筛选

系统地根据每个筛选标准评估 NDA。

#### 1. 协议结构
- [ ] **类型识别**：互惠 NDA、单方面（披露方）或单方面（接收方）
- [ ] **上下文适用性**：NDA 类型是否适合业务关系？（例如，探索性讨论为互惠，单向披露为单方面）
- [ ] **独立协议**：确认 NDA 是独立协议，而不是嵌入在更大的商业协议中的保密条款

#### 2. 保密信息的定义
- [ ] **合理范围**：不过于宽泛（避免“所有信息，无论是否标记为机密”）
- [ ] **标记要求**：如果需要标记，是否可行？（书面标记在口头披露后 30 天内是标准的）
- [ ] **排除条款存在**：定义了标准排除条款（见下文标准排除条款）
- [ ] **没有有问题的包含项**：不将公开可用信息或独立开发材料定义为机密

#### 3. 接收方的义务
- [ ] **合理标准**：合理谨慎或至少与自己的机密信息相同的谨慎
- [ ] **使用限制**：仅限于声明的目的
- [ ] **披露限制**：仅限于需要知道且受类似义务约束的人员
- [ ] **没有过重的义务**：没有不切实际的要求（例如，加密所有通信、维护物理日志）

#### 4. 标准排除条款
以下所有排除条款都应存在：
- [ ] **公开知识**：通过接收方无过错而成为公开可用或公开的信息
- [ ] **先期占有**：接收方在披露之前已经知道的信息
- [ ] **独立开发**：在不使用或参考机密信息的情况下独立开发的信息
- [ ] **第三方接收**：从第三方合法获得且无限制的信息
- [ ] **法律强制**：在法律、法规或法律程序要求时有权披露（在法律允许的情况下通知披露方）

#### 5. 允许的披露
- [ ] **员工**：可以与需要知道的员工共享
- [ ] **承包商/顾问**：可以与承包商、顾问和专业顾问共享，并受类似的保密义务约束
- [ ] **关联方**：可以与关联方共享（如果业务目的需要）
- [ ] **法律/监管**：根据法律或法规要求披露

#### 6. 期限和持续时间
- [ ] **协议期限**：合理的业务关系期限（1-3 年是标准的）
- [ ] **保密期限**：义务在终止后合理期间内持续（2-5 年是标准的；商业秘密可能更长）
- [ ] **非永久性**：避免无限期或永久的保密义务（例外：商业秘密，可能需要更长时间的保护）

#### 7. 返还和销毁
- [ ] **义务触发**：在终止时或应要求时
- [ ] **合理范围**：返还或销毁机密信息和所有副本
- [ ] **保留例外**：允许保留法律、法规或内部合规/备份政策要求的副本
- [ ] **认证**：销毁认证是合理的；宣誓书是过重的

#### 8. 补救措施
- [ ] **禁令救济**：承认违约可能造成不可弥补的损害，并且可能适用衡平救济是标准的
- [ ] **没有预先确定的损害赔偿**：避免 NDA 中的固定损害赔偿条款
- [ ] **非单方面**：补救措施条款平等适用于双方（在互惠 NDA 中）

#### 9. 需要标记的问题条款
- [ ] **没有非招揽条款**：NDA 不应包含员工非招揽条款
- [ ] **没有非竞争条款**：NDA 不应包含非竞争条款
- [ ] **没有排他性条款**：NDA 不应限制任何一方与其他方进行类似讨论
- [ ] **没有僵局条款**：NDA 不应包含僵局或类似的限制性条款（除非在并购背景下）
- [ ] **没有残值条款**（或范围狭窄）：如果存在残值条款，则应仅限于个人无辅助记忆中保留的信息，并且不应适用于商业秘密或专利信息
- [ ] **没有 IP 赋予或许可**：NDA 不应授予任何知识产权
- [ ] **没有审计权**：在标准 NDA 中不常见

#### 10. 适用法律和司法管辖权
- [ ] **合理司法管辖权**：一个成熟的商业司法管辖权
- [ ] **一致性**：适用法律和司法管辖权应在相同或相关的司法管辖权中
- [ ] **没有强制仲裁**（在标准 NDA 中）：诉讼通常是为 NDA 争议首选的

### 第 4 步：分类

根据筛选结果，分配一个分类：

#### 绿色 -- 标准批准

**所有**以下条件必须为真：
- NDA 是互惠的（或在适当的单向方向上）
- 所有标准排除条款都存在
- 期限在标准范围内（1-3 年，生存期 2-5 年）
- 没有非招揽、非竞争或排他性条款
- 没有残值条款，或残值条款范围狭窄
- 合理的适用法律司法管辖权
- 标准补救措施（没有固定损害赔偿）
- 允许的披露包括员工、承包商和顾问
- 返还/销毁条款包括法律/合规保留例外
- 保密信息的定义是合理范围的

**路由**：通过标准授权委托批准。不需要法律顾问审查。
- **行动**：继续签名，使用标准授权委托

#### 黄色 -- 需要法律顾问审查

**一个或多个**以下情况存在，但 NDA 并非根本性问题：
- 保密信息的定义比首选的更宽泛，但并非不合理
- 期限比标准更长，但在市场范围内（例如，协议期限 5 年，生存期 7 年）
- 缺少一个可以轻松添加的标准排除条款
- 残值条款存在，但范围狭窄到无辅助记忆
- 适用法律在可接受但非首选的司法管辖权
- 互惠 NDA 中存在轻微不对称性（例如，一方有略微更广泛的允许披露）
- 标记要求存在且可行
- 返还/销毁缺乏明确的保留例外（很可能暗示，但应添加）
- 不寻常但无害的条款（例如，有义务通知潜在的违约）

**路由**：标记具体问题供法律顾问审查。法律顾问可能可以在一次审查中用轻微的修订解决。
- **行动**：法律顾问可能可以在一次审查中解决

#### 红色 -- 重大问题

**一个或多个**以下情况存在：
- **单方面，而需要互惠**（或关系方向错误）
- **缺少关键排除条款**（尤其是独立开发或法律强制）
- **非招揽或非竞争条款**嵌入 NDA 中
- **排他性或僵局条款**没有适当的业务背景
- **不合理的期限**（10 年以上，或没有商业秘密理由的永久性）
- **过于宽泛的定义**可能捕获公开信息或独立开发材料
- **宽泛的残值条款**实际上创造了使用机密信息的许可
- **IP 赋予或许可**隐藏在 NDA 中
- **固定损害赔偿或处罚条款**
- **审计权**没有合理的范围或通知要求
- **非常不利的司法管辖权**与强制仲裁
- **文件实际上不是 NDA**（包含实质商业条款、排他性或其他保密义务之外的义务）

**路由**：需要全面法律审查。不要签署。需要与组织的标准格式 NDA 进行谈判、反提案或拒绝。
- **行动**：不要签署；需要谈判或反提案

### 第 6 步：路由建议

根据分类，建议适当的下一步：

| 分类 | 建议行动 | 典型时间 |
|---|---|---|
| 绿色 | 根据授权委托批准并路由签署 | 同一天 |
| 黄色 | 发送给指定审查者，并标记具体问题 | 1-2 个工作日 |
| 红色 | 征求法律顾问进行全面审查；准备反提案或标准格式 | 3-5 个工作日 |

对于黄色和红色分类：
- 确定应审查的特定人员或角色（如果组织已定义路由规则）
- 提供一个简短的问题摘要，供审查者快速了解关键点
- 如果组织有标准格式 NDA，建议将标准格式 NDA 作为红色分类 NDA 的反提案发送

## 常见 NDA 问题及标准立场

### 问题：保密信息定义过于宽泛
**标准立场**：保密信息应限于与声明目的相关的非公开信息，并具有明确的排除条款。
**修订方法**：将定义缩小到被标记或识别为机密的信息，或根据信息的性质和披露情况，一个合理的人会认为机密的信息。

### 问题：缺少独立开发排除条款
**标准立场**：必须包括一个独立开发排除条款，即在不参考或使用披露方的机密信息的情况下独立开发的信息。
**风险如果缺失**：可能导致声称内部开发的产品或功能是从对方机密信息中派生的。
**修订方法**：添加标准的独立开发排除条款。

### 问题：员工非招揽
**标准立场**：非招揽条款不属于 NDA。它们适用于雇佣协议、并购协议或特定的商业协议。
**修订方法**：完全删除该条款。如果对方坚持，则限制为有针对性的招揽（不是一般招聘），并设置短期（12 个月）。

### 问题：宽泛的残值条款
**标准立场**：抵制残值条款。如果需要，限制为：
  - (a) 保留在个人无辅助记忆中的一般想法、概念、专有技术或技术；
  - (b) 明确排除商业秘密和可专利信息；
  - (c) 不授予任何 IP 许可。
**风险如果过于宽泛**：实际上授予了使用披露方机密信息的许可，用于任何目的。

### 问题：永久保密义务
**标准立场**：2-5 年从披露或终止，以较晚者为准。商业秘密可能需要更长时间的保护，只要它们仍然是商业秘密。
**修订方法**：用定义的期限替换永久义务。为合格信息提供商业秘密排除条款，以获得更长时间的保护。

## 备注

- 如果文件实际上不是 NDA（例如，标记为 NDA 但包含实质商业条款），立即标记为红色，并建议进行全面合同审查
- 对于作为更大协议一部分的 NDA（例如，保密条款在 MSA 中），注意更广泛的协议背景可能会影响分析
- 始终注意这是一个筛选工具，用户不确定的任何项目都应由法律顾问审查
