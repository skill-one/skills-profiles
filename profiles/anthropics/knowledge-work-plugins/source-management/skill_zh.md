# 源管理

> 如果你看到不熟悉的占位符，或者需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

了解有哪些可用源，帮助连接新源，并管理如何查询源。

## 检查可用源

通过检查可用工具来确定哪些 MCP 源已连接。每个源对应一组 MCP 工具：

| 源        | 主要功能         |
|----------|-----------------|
| **~~chat** | 搜索消息，读取频道和线程 |
| **~~email** | 搜索消息，读取单个邮件 |
| **~~cloud storage** | 搜索文件，获取文档内容 |
| **~~project tracker** | 搜索任务，类型前搜索 |
| **~~CRM** | 查询记录（账户、联系人、机会） |
| **~~knowledge base** | 语义搜索，关键词搜索 |

如果工具前缀可用，则表示该源已连接并可搜索。

## 引导用户连接源

当用户搜索但连接的源很少或没有时：

```
您当前连接了 [N] 个源：[列表]。

要扩展搜索范围，您可以在 MCP 设置中连接其他源：
- ~~chat — 消息、线程、频道
- ~~email — 邮件、对话、附件
- ~~cloud storage — 文档、表格、幻灯片
- ~~project tracker — 任务、项目、里程碑
- ~~CRM — 账户、联系人、机会
- ~~knowledge base — 维基页面、知识库文章

连接的源越多，搜索结果就越完整。
```

当用户询问一个未连接的特定工具时：

```
[工具名称] 当前未连接。要添加它：
1. 打开您的 MCP 设置
2. 添加 [工具] MCP 服务器配置
3. 当提示时进行身份验证

连接后，它将自动包含在未来的搜索中。
```

## 源优先级排序

不同的查询类型受益于首先搜索某些源。使用这些优先级来加权结果，而不是跳过源：

### 按查询类型

**决策查询**（“我们决定……”）：
```
1. ~~chat (发生决策的对话)
2. ~~email (决策确认、公告)
3. ~~cloud storage (会议记录、决策日志)
4. 维基 (如果决策已记录)
5. 任务跟踪器 (如果决策已记录在任务中)
```

**状态查询**（“……的状态是什么”）：
```
1. 任务跟踪器 (~~project tracker — 权威状态)
2. ~~chat (实时讨论)
3. ~~cloud storage (状态文档、报告)
4. ~~email (状态更新邮件)
5. 维基 (项目页面)
```

**文档查询**（“……的文档在哪里”）：
```
1. ~~cloud storage (主要文档存储)
2. 维基 / ~~knowledge base (知识库)
3. ~~email (通过邮件共享的文档)
4. ~~chat (频道中共享的文档)
5. 任务跟踪器 (链接到任务的文档)
```

**人员查询**（“……由谁负责” / “……谁知道”）：
```
1. ~~chat (消息作者、频道成员)
2. 任务跟踪器 (任务指派者)
3. ~~cloud storage (文档作者、协作者)
4. ~~CRM (账户所有者、联系人)
5. ~~email (邮件参与者)
```

**事实/政策查询**（“……的政策是什么”）：
```
1. 维基 / ~~knowledge base (官方文档)
2. ~~cloud storage (政策文档、手册)
3. ~~email (政策公告)
4. ~~chat (政策讨论)
```

### 默认优先级（一般查询）

当查询类型不明确时：
```
1. ~~chat (最高量、最实时)
2. ~~email (正式通信)
3. ~~cloud storage (文档和文件)
4. 维基 / ~~knowledge base (结构化知识)
5. 任务跟踪器 (工作项)
6. CRM (客户数据)
```

## 速率限制意识

MCP 源可能有速率限制。优雅地处理它们：

### 检测

速率限制响应通常表现为：
- HTTP 429 响应
- 提及“速率限制”、“请求过多”或“配额超出”的错误消息
- 受限或延迟的响应

### 处理

当源被速率限制时：

1. **不要立即重试** — 尊重限制
2. **继续使用其他源** — 不要阻塞整个搜索
3. **通知用户**：
```
注意：[源] 暂时被速率限制。以下结果来自 [其他源]。您可以在几分钟后再试以包含 [源]。
```
4. **对于摘要** — 如果扫描中途被限制，请记录在限制生效前覆盖的时间范围

### 预防

- 避免不必要的 API 调用 — 在查询前检查源是否可能包含相关结果
- 尽可能使用定向查询而不是广泛扫描
- 对于摘要，如果 API 支持批量请求，请分批处理
- 缓存意识：如果刚刚运行了搜索，请避免立即重新运行相同的查询

## 源健康

在会话期间跟踪源可用性：

```
源状态：
  ~~chat:        ✓ 可用
  ~~email:        ✓ 可用
  ~~cloud storage:  ✓ 可用
  ~~project tracker:        ✗ 未连接
  ~~CRM:   ✗ 未连接
  ~~knowledge base:      ⚠ 速率限制（2 分钟后重试）
```

报告搜索结果时，请包含已搜索的源，以便用户知道答案的范围。

## 添加自定义源

企业搜索插件可与任何已连接的 MCP 源配合使用。随着新的 MCP 服务器可用，它们可以被添加到 `.mcp.json` 配置中。搜索和摘要命令将自动检测并包含新的源，基于可用工具。

要添加新源：
1. 将 MCP 服务器配置添加到 `.mcp.json`
2. 如有需要，进行身份验证
3. 该源将自动包含在后续搜索中
