# /accessibility-review

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅[CONNECTORS.md](../../CONNECTORS.md)。

审计设计或页面是否符合WCAG 2.1 AA无障碍标准。

## 使用方法

```
/accessibility-review $ARGUMENTS
```

审计无障碍性：@$1

## WCAG 2.1 AA快速参考

### 可感知性
- **1.1.1** 非文本内容有替代文本
- **1.3.1** 通过语义传达信息和结构
- **1.4.3** 对比度 >= 4.5:1（普通文本），>= 3:1（大文本）
- **1.4.11** 非文本对比度 >= 3:1（UI组件、图形）

### 可操作性
- **2.1.1** 所有功能都可以通过键盘访问
- **2.4.3** 逻辑焦点顺序
- **2.4.7** 可见焦点指示器
- **2.5.5** 触摸目标 >= 44x44 CSS像素

### 可理解性
- **3.2.1** 聚焦时具有可预测性（无意外变化）
- **3.3.1** 错误识别（描述错误）
- **3.3.2** 输入的标签或说明

### 强健性
- **4.1.2** 所有UI组件的名称、角色、值

## 常见问题

1. 颜色对比度不足
2. 缺少表单标签
3. 交互元素无法通过键盘访问
4. 有意义图像缺少替代文本
5. 模态框中的焦点陷阱
6. 缺少ARIA地标
7. 无控制按钮的自动播放媒体
8. 无延长时间选项的时间限制

## 测试方法

1. 自动扫描（可捕获约30%的问题）
2. 仅通过键盘导航
3. 屏幕阅读器测试（VoiceOver、NVDA）
4. 验证颜色对比度
5. 放大至200%——布局是否崩溃？

## 小贴士

1. **从对比度和键盘开始** — 这些可以捕获最常见和最有影响的问题。
2. **使用真实的辅助技术进行测试** — 我的审计是一个很好的开始，但使用VoiceOver/NVDA进行手动测试可以捕获我无法发现的问题。
3. **按影响优先级** — 首先修复阻止用户的问题，然后进行优化。
