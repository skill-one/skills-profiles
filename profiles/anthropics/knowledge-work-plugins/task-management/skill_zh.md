# 任务管理

任务在一个简单的 `TASKS.md` 文件中进行跟踪，你和用户都可以编辑该文件。

## 文件位置

**始终在当前工作目录中使用 `TASKS.md`。**

- 如果它存在，则读取/写入它
- 如果它不存在，则使用以下模板创建它

## 仪表板设置（首次运行）

有一个可视化仪表板用于管理任务和记忆。**在首次与任务交互时：**

1. 检查当前工作目录中是否存在 `dashboard.html`
2. 如果不存在，则从 `${CLAUDE_PLUGIN_ROOT}/skills/dashboard.html` 复制到当前工作目录
3. 告知用户："我已经添加了仪表板。运行 `/productivity:start` 来设置完整系统。"

任务看板：
- 读取和写入相同的 `TASKS.md` 文件
- 自动保存更改
- 监听外部更改（通过 CLI 编辑时同步）
- 支持拖放重新排序任务和部分

## 格式与模板

创建新的 TASKS.md 时，使用此确切模板（不包含示例任务）：

```markdown
# 任务

## 进行中

## 等待中

## 有朝一日

## 已完成
```

任务格式：
- `- [ ] **任务标题** - 背景，为谁，截止日期`
- 子项目用于附加详细信息
- 已完成：`- [x] ~~任务~~ (日期)`

## 如何交互

**当用户询问"我有什么任务" / "我的任务"时：**
- 读取 TASKS.md
- 总结进行中和等待中部分
- 突出显示任何逾期或紧急的事项

**当用户说"添加一个任务" / "提醒我"时：**
- 以 `- [ ] **任务**` 格式添加到进行中部分
- 如果提供背景信息，请包含（为谁，截止日期）

**当用户说"完成 X" / "完成 X"时：**
- 找到该任务
- 将 `[ ]` 改为 `[x]`
- 添加删除线：`~~任务~~`
- 添加完成日期
- 移动到已完成部分

**当用户询问"我在等待什么"时：**
- 读取等待中部分
- 记录每个项目等待了多长时间

## 规则

- **加粗** 任务标题以提高可扫描性
- 当它是针对某人的承诺时，包含 "for [人]"
- 包含 "due [日期]" 用于截止日期
- 包含 "since [日期]" 用于等待项目
- 子项目用于附加背景信息
- 将已完成部分保留约 1 周，然后清除旧项目

## 提取任务

在总结会议或对话时，提供添加提取的任务的选项：
- 用户做出的承诺（"我会发过去"）
- 分配给他们的行动项
- 提到的后续事项

添加前询问 - 不要未经确认自动添加。
