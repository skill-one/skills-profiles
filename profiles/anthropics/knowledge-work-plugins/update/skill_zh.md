# 更新命令

> 如果你看到不熟悉的占位符，或者需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

保持你的任务列表和记忆信息最新。有两种模式：

- **默认模式**：从外部工具同步任务，筛选过时的项目，检查记忆信息中的空白
- **`--comprehensive`**：深度扫描聊天记录、邮件、日历、文档 — 标记遗漏的待办事项并建议新的记忆信息

## 使用方法

```bash
/productivity:update
/productivity:update --comprehensive
```

## 默认模式

### 1. 加载当前状态

读取 `TASKS.md` 和 `memory/` 目录。如果它们不存在，则建议先运行 `/productivity:start`。

### 2. 从外部源同步任务

检查可用的任务源：
- **项目追踪器**（例如 Asana、Linear、Jira）（如果 MCP 可用）
- **GitHub Issues**（如果在仓库中）：`gh issue list --assignee=@me`

如果没有可用的源，则跳到步骤 3。

**获取分配给用户的任务**（打开/进行中）。与 TASKS.md 对比：

| 外部任务 | TASKS.md 匹配？ | 操作 |
|---------------|-----------------|--------|
| 已找到，不在 TASKS.md | 无匹配 | 提供添加选项 |
| 已找到，已在 TASKS.md | 标题模糊匹配 | 跳过 |
| 在 TASKS.md 中，但在外部未找到 | 无匹配 | 标记为可能过时 |
| 外部完成 | 在 Active 部分 | 提供标记为完成选项 |

展示差异并让用户决定要添加/完成的内容。

### 3. 筛选过时项目

审查 TASKS.md 中的 Active 任务并标记：
- 过期日期的任务
- Active 30 天以上的任务
- 没有上下文（没有人员、没有项目）的任务

对每个项目进行筛选：标记完成？重新安排？移动到 Someday？

### 4. 解码任务以填补记忆空白

对每个任务，尝试解码所有实体（人员、项目、缩写、工具、链接）：

```
任务: "发送 PSR 给 Todd 关于 Phoenix 阻塞"

解码：
- PSR → ✓ 管道状态报告（在词汇表中）
- Todd → ✓ Todd Martinez（在 people/中）
- Phoenix → ? 不在记忆中
```

跟踪已完全解码的内容与存在空白的部分。

### 5. 填补空白

分组展示未知术语：

```
我在你的任务中发现了我没有上下文的信息：

1. "Phoenix"（来源: "发送 PSR 给 Todd 关于 Phoenix 阻塞")
   → Phoenix 是什么？

2. "Maya"（来源: "与 Maya 同步 API 设计")
   → Maya 是谁？
```

将答案添加到相应的记忆文件（people/、projects/、glossary.md）。

### 6. 捕获补充信息

任务通常包含比记忆更丰富的上下文。提取并更新：
- **任务中的链接** → 添加到项目/人员文件
- **状态变化**（"发布完成"）→ 更新项目状态，从 CLAUDE.md 降级
- **关系**（"Todd 对 Maya 的提案的批准"）→ 交叉引用人员
- **截止日期** → 添加到项目文件

### 7. 报告

```
更新完成：
- 任务：从项目追踪器（例如 Asana）+3，1 个完成，2 个筛选
- 记忆：填补了 2 个空白，1 个项目补充
- 所有任务已解码 ✓
```

## 全面模式 (`--comprehensive`)

默认模式的所有内容，加上对近期活动的深度扫描。

### 额外步骤：扫描活动源

从可用的 MCP 源收集数据：
- **聊天记录**：搜索最近的消息，读取活跃频道
- **邮件**：搜索已发送的消息
- **文档**：列出最近修改的文档
- **日历**：列出最近的和即将到来的事件

### 额外步骤：标记遗漏的待办事项

将活动与 TASKS.md 对比。展示未追踪的行动项：

```
## 可能遗漏的任务

根据你的活动，这些看起来是你尚未捕获的待办事项：

1. 从聊天记录（1月18日）：
   "我会在周五前发送更新的模型图"
   → 添加到 TASKS.md？

2. 从会议 "Phoenix Standup"（1月17日）：
   你有一个周期性会议但没有活跃的 Phoenix 任务
   → 这里需要什么？

3. 从邮件（1月16日）：
   "我本周会审查 API 规范"
   → 添加到 TASKS.md？
```

让用户选择要添加的内容。

### 额外步骤：建议新的记忆信息

展示不在记忆中的新实体：

```
## 新人员（不在记忆中）
| 名称 | 频率 | 上下文 |
|------|-----------|---------|
| Maya Rodriguez | 12 提及 | 设计、UI 审查 |
| Alex K | 8 提及 | 关于 API 的私信 |

## 新项目/主题
| 名称 | 频率 | 上下文 |
|------|-----------|---------|
| Starlight | 15 提及 | 规划文档、产品 |

## 建议清理
- **Horizon 项目** — 30 天内没有提及。标记为完成？
```

按置信度分组展示。高置信度项直接提供添加选项；低置信度项询问意见。

## 注意事项

- 未经用户确认，从不自动添加任务或记忆信息
- 当可用时，保留外部源链接
- 任务标题的模糊匹配处理轻微的措辞差异
- 可以频繁运行 — 仅在有新信息时更新
- `--comprehensive` 总是交互式运行
