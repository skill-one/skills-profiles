# /incident-response

> 如果你看到不熟悉的占位符，或者需要检查哪些工具已连接，请参阅[CONNECTORS.md](../../CONNECTORS.md)。

从检测到事后分析，管理一个事件。

## 使用方法

```
/incident-response $ARGUMENTS
```

## 模式

```
/incident-response new [描述]     # 开始一个新事件
/incident-response update [状态]       # 发布状态更新
/incident-response postmortem            # 从事件数据生成事后分析
```

如果未指定模式，将询问事件处于哪个阶段。

## 工作原理

```
┌─────────────────────────────────────────────────────────────────┐
│                    事件响应                                       │
├─────────────────────────────────────────────────────────────────┤
│  阶段 1：分诊                                                  │
│  ✓ 评估严重程度（SEV1-4）                                     │
│  ✓ 确定受影响的系统和用户                          │
│  ✓ 分配角色（IC、通讯、响应者）                         │                                                                    │
│                                                                    │
│  阶段 2：沟通                                                  │
│  ✓ 起草内部状态更新                                  │
│  ✓ 起草客户沟通（如有需要）                     │
│  ✓ 设置战室和节奏                                   │                                                                    │
│                                                                    │
│  阶段 3：缓解                                                 │
│  ✓ 记录采取的缓解措施                               │
│  ✓ 跟踪事件时间线                                      │
│  ✓ 确认解决                                            │                                                                    │
│                                                                    │
│  阶段 4：事后分析                                               │
│  ✓ 无指责的事后分析文档                                 │
│  ✓ 时间线重建                                       │
│  ✓ 根因分析（五个为什么）                                  │
│  ✓ 带有负责人的行动项                                      │
└─────────────────────────────────────────────────────────────────┘
```

## 严重程度分类

| 等级 | 标准 | 响应时间 |
|-------|----------|---------------|
| SEV1 | 服务中断，所有用户受影响 | 立即，全员 |
| SEV2 | 主要功能退化，许多用户受影响 | 15分钟内 |
| SEV3 | 轻微功能问题，部分用户受影响 | 1小时内 |
| SEV4 | 修饰性或低影响问题 | 下一个工作日 |

## 沟通指南

定期以清晰、事实性的更新。包括：发生什么、谁受影响、我们正在做什么、下次更新何时。

## 如果连接器可用

如果 **~~监控** 已连接：
- 拉取警报详情和指标
- 显示受影响指标的图表

如果 **~~事件管理** 已连接：
- 在 PagerDuty/Opsgenie 中创建或更新事件
- 页面值班响应者

如果 **~~聊天** 已连接：
- 在事件频道中发布状态更新
- 创建战室频道

## 小贴士

1. **立即开始写作** — 不要等待完整信息。随着了解更多信息，随时更新。
2. **保持更新基于事实** — 我们知道什么，我们做了什么，接下来会做什么。不要猜测。
3. **事后分析是无指责的** — 专注于系统和流程，而不是个人。
