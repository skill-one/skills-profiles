运行潜在客户优先级排序。扫描管道，按紧急程度和机会进行排序，提取相关的邮件上下文，并让负责人准备好进行通话。

解析参数：
- `--n`（默认值：`5`）— 要展示的潜在客户数量（1–10）
- `--date`（默认值：今天）— 构建通话列表的日期（`YYYY-MM-DD`）

## 第 1 步 — 管道扫描（潜在客户分诊）

运行 `lead-triage` 技能工作流进行拉取和评分 — 它拥有 HubSpot 字段列表、四维模型、笔记正文紧急程度获取、平面分数保护以及丰富化分支（如果连接了 Apollo 或 Clay，公司适配用于没有公司记录的潜在客户 — 计量，因此 `lead-triage` 询问一次信用成本；将这个问题传递给负责人而不是回答它）。在这里不要重新构建任何内容。然后从 Mail 中为每个存活的潜在客户拉取邮件线程（每个联系人最后 3 封邮件）用于谈话要点。

## 第 2 步 — 排序并选择前 N 名

取 `lead-triage` 的排序并选择前 `--n` — 当存在那么多潜在客户时，总是正好 `--n`，无论管道大小如何。对于平局，优先选择有未回复的入站信号的潜在客户。如果 `lead-triage` 报告平面分数，则呈现其 CRM 事实阶梯顺序，并说明这一点。

对于每个选定的潜在客户，生成一个通话卡片：

```
{排名}. {联系人姓名} — {公司}
交易：{货币代码} {金额} | 阶段：{阶段} | 最后联系：{X 天前}
信号：{最近的活动}

谈话要点
• {来自邮件/交易上下文的要点}
• {来自邮件/交易上下文的要点}
• {要问的开放性问题}

本次通话目标：{一句话 — 进入下一阶段 / 重新参与 / 关闭}
```

## 第 3 步 — 预约日历

对于列表中的每个潜在客户，提供在负责人日历上预约 20 分钟的目标日期。

显示建议的日历条目：
```
{时间段} — 通话：{联系人姓名} ({公司})
```

等待负责人确认要预约哪些通话，然后再创建日历事件。

## 第 4 步 — 起草后续跟进

对于任何有超过 3 天未回复的邮件的潜在客户，起草一个简短的后续跟进：
```
主题：回复 {邮件主题}

你好 {名字}，

{一句提及之前的对话}。{一句有明确的下一步或问题}。

{结束语}
```

## 连接器故障

如果 HubSpot 无法访问，停止并告诉负责人 — 潜在客户评分需要 CRM 数据。如果 Mail 无法访问，跳过第 1 步中的邮件上下文拉取和第 4 步中的后续跟进起草，并在输出中注明“Mail 未连接 — 邮件上下文和后续跟进起草跳过”；第 3 步中的日历预约仍然运行。如果 Google Calendar 无法访问，跳过日历预约并注明。如果潜在客户数据连接器无法访问或负责人拒绝丰富化支出，没有公司记录的潜在客户的公司适配保持平面 — 在输出中说明这一点，而不是呈现适配排序。

## 批准关卡

- **永远不要自动发送邮件。** 仅向负责人展示草稿以供批准。
- **永远不要在未经负责人确认的情况下创建日历预约** — 首先显示建议列表。
- **永远不要自动更新 HubSpot 交易阶段。**

## 输出

展示带谈话要点的排名通话列表。然后显示建议的日历预约并请求确认。然后显示后续跟进草稿并询问要发送哪些。

在聊天摘要旁边 — 永远不取代它 — 使用房屋风格 (`../../shared/artifact-style.md`) 渲染列表为 CALL SHEET 艺术品：负责人在拨打电话时打印并使用的工作表。打印友好的行，每个潜在客户一行，每个包含通话目标和两个或三个简短的谈话要点，以及一条空白的结果行供涂鸦。这是一个工作表，不是仪表板 — 没有统计图块，没有图表。

## 结束提议

用一行说明构建了什么，然后是最相关的下一步及其触发短语 — 通常是为需要邮件而不是电话的潜在客户使用“撰写此外联” (`outreach-composer`)。最多两个其他：”填充我的管道” (`/grow-pipeline`) 或 ”更新 CRM” (`crm-autopilot`)。最多三个，并跳过负责人在此会话中拒绝的任何内容。

## 使用未列出的工具

此技能中命名的连接器是测试路径，不是墙。如果负责人希望此流程使用未连接或未列出的工具，提供 `build-connector` — 它首先检查连接器目录，否则通过 Zapier 连接，从不直接针对原始 API 手动构建。一旦连接存在，该工具就像任何其他可选连接器一样加入此技能，在相同的批准关卡下。
