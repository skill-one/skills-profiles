# 商业脉搏

一个指令，一页内容。从所有连接的工具中实时提取数据，将其综合成一份可扫描的简报，并展示今天最需要采取的行动事项。着手处理工作——不要要求用户帮助查找数据。

## 第一步——并行拉取数据

**将所有连接器调用在一个并行批次中分派**——有关工具到指标的精确映射，请参阅 `reference/data_sources.md`。不要串行拉取；延迟会将一个30秒的技能变成痛苦的等待。

同时尝试连接的连接器：

- **QuickBooks** — 现金余额、当月收入、未收回应收账款、逾期发票
- **Xero** — Xero 商店的相同总账读取：现金状况、应收账款、损益趋势
- **Zoho Books** — Zoho 商店的相同总账读取：银行余额、开票收入、逾期发票（没有损益端点，因此收入线是开票收入并注明这一点）
- **PayPal / Square** — 7天结算、销售趋势、失败/待处理交易
- **Stripe** — 结算和销售趋势、失败付款以及任何新的争议——一个新的争议会直接进入观察列表（如果已连接）
- **Ramp** — 公司卡本周支出和账户余额，只读（如果已连接）
- **Gusto** — 下一次工资运行日期和金额，本周最大的现金支出（如果已连接）
- **TikTok Ads** — 上周的广告支出、结果和每个结果的成本，以便付费支出显示在声称推动的销售旁边（如果已连接）
- **Expensify** — 上周的卡支出和任何缺少收据的费用，只读，以便在月末混乱之前出现支出意外（如果已连接）
- **HubSpot** — 按阶段的管道、已移动/关闭的交易、已冷却的交易、新线索
- **Google Calendar** — 关键会议、截止日期、本周和未来7天的活动
- **Gmail 或 Microsoft 365** — 标记为紧急的线程、客户投诉、有时间敏感性的请求
- **Slack / Teams** — 紧急内部信号、需要负责人注意的线程
- **RingEx Chat** — RingEx 商店的相同内部信号读取：需要负责人注意的紧急团队聊天帖子（如果已连接）
- **DocuSign** — 没有签署的文件包，一旦它们超过几天就标记一次——等待签名的钱（如果已连接）
- **Zoho Desk** — 打开的工单、升级（如果已连接）
- **Shopify** — 订单、收入、销售趋势和履行问题，以便商业企业看到其实际情况（如果已连接）
- **Square** — 履行问题（如果已连接）

如果一个连接器出错或返回没有数据，请内部记录并继续。永远不要因为单个糟糕的集成而阻塞脉搏。

**QuickBooks 备用方案**：如果 QBO 返回意外状态（账户未连接、同步挂起、空响应），请将现金部分标记为“n/a — QuickBooks 不可用”并继续。不要重试或要求用户重新连接。

**Gmail 备用方案**：Gmail 认证不稳定。如果调用出错，请静默跳过观察列表部分，并在附录中注明“Gmail 不可用”——不要在脉搏中途显示错误。

**完全未连接是一种支持路径，而不是失败。** 如果所有连接器都不可用，不要停止，也不要告诉负责人去连接东西。一次，用一条简短的消息，请求少数几个携带脉搏的数字：

- 银行中的现金，以及大约一周前的现金状况
- 任何逾期款项——他们欠的发票、他们欠的账单
- 本周的销售与正常周的销售相比，即使大致也是如此
- 本周已经让他们担心的事情

根据这些答案构建同一份一页脉搏，将来源行标记为“负责人提供，未拉取”，并跳过他们没有数字的部分。如果他们宁愿不输入数字，请将他们指向运行文件导出的兄弟工具——`cash-flow-snapshot` 和 `report-builder` 都接受 CSV——并明确说明这给出的是部分画面，而不是完整画面。

## 第二步——计算指标

阅读 `reference/thresholds.md` 了解红/黄/绿截止值。计算：

- **AR 老化**——按到期日以来的天数分组打开的 QuickBooks 发票（0-30、31-60、61+）
- **管道覆盖率**——HubSpot 加权管道 ÷ 月度收入目标
- **收入趋势**——本月 QBO 收入与上个月（或7天 PayPal/Square 与前7天）的比较

为每个部分分配一个 🟢/🟡/🔴 状态。如果一个来源返回了没有数据，请将指标标记为“n/a”并在附录中注明。

## 第三步——主动标记风险

扫描可操作事项。每个风险条目必须指明特定记录和下一步行动——“一些逾期发票”是无用的；“Acme Corp 的 3,400 美元，47 天逾期，自 3 月 12 日以来没有回复”是可操作的。

- 超过 30 天的账簿发票——指明客户、金额、逾期天数
- HubSpot 7 天以上没有活动的交易，或截止日期已过但仍然打开的交易
- 标记为紧急或包含“升级”、“投诉”、“取消”、“退款”的邮件线程
- 超过 `reference/thresholds.md` 中阈值的 PayPal/Square/Stripe 交易失败或待处理（以业务货币计）

## 第四步——编写输出

使用 `reference/output_template.md` 中的确切模板。仅包含有实际数据的部分——省略未连接连接器的标题。根据上下文调整深度：一个随意的“我们做得怎么样”得到一份完整的报告；“打电话前的快速快照”得到一份更紧凑的报告。

跨连接器综合是这项技能的价值所在。如果一个 Slack 消息连接到一个停滞的 HubSpot 交易，请在 #1 优先部分显示该链接。综合使脉搏比单独检查每个工具更有用。

编写规则：
- 数字领先，文字跟随。永远不要写“收入健康”——写“本月 43,000 美元，▲ 8% MoM”并让负责人判断。
- 每个数字都与前一个时期进行比较（如果可用）。绝对快照（现金余额）仍然显示 WoW 差异。
- 名字和金额，而不是形容词。“来自 Acme 的 4,200 美元，23 天逾期”比“一些令人担忧的应收账款”更好。
- 没有填充。如果一个部分没有值得报告的内容，请写“没有重大变化”并继续。

## 第五步——交付脉搏页面

在聊天脉搏旁边——而不是替代它——根据负责人的存储输出偏好交付完整的脉搏——永远不要默认为 Markdown 文件。检查 `## 商业背景` 块的 `输出偏好`（共享样式指南规则，`../../shared/artifact-style.md`）：

- **视觉工件（默认）：** 将脉搏渲染为符合公司风格的 HTML 页面。现金余额、当月收入和加权管道是带有其差异作为上下文线的统计瓦片；每个部分的 🟢/🟡/🔴 变成一个状态药丸（良好、警告、关键）；观察列表风险是一个带有表格数字列的表格；#1 优先级有自己的面板在顶部；不可用的连接器在一个安静的附录行中。
- **docx / md / notion / canva 偏好：** 以该形式交付相同的内容——一个 DOCX 或 Markdown 文件、一个通过连接器创建的 Notion 页面（命名目的地，从不覆盖）、或通过 Canva 连接器创建的 Canva 文档（每次运行都有一个新设计，用日期命名；表格变成列表）；如果 Notion 或 Canva 未连接，则回退到视觉工件——并说明原因。
- **最适合技能：** 使用视觉工件——脉搏是扫描的，而不是归档的。

## 第六步——导出和共享（一次）

在展示脉搏后，提供一次：
- “想要我将其保存为文件吗？”（如果可用，请使用 Files 连接器——这意味着在他们的驱动器中创建副本，而不是在工件旁边创建第二个 HTML 下载）
- “我应该将它发布到你的 Slack 吗？”（只有当 Slack 已连接并且用户确认时——Slack 写入需要明确批准）

如果他们说是，那就做。如果他们说不或没有回复，就继续——不要再次询问。

## 运行后

用一句话总结脉搏涵盖的内容，然后是单个最相关的下一步和最多两个其他步骤：

- 如果现金或 AR 标记为红色：“谁欠我钱”运行 `invoice-chase`。
- 如果增长问题占主导地位：“我的营销有效吗”运行 `growth-pulse`。
- 为了使其成为定期运行：“周一简报”每周运行 `/monday-brief`。

最多三个提议。永远不要重复本次会话中负责人拒绝的提议。

## 范围变体

负责人可能会要求一个更窄的切片：

- **“仅现金” / “财务检查”** → 仅现金和财务 + 与 AR 相关的风险
- **“仅管道” / “交易检查”** → 仅管道部分 + 停滞交易风险
- **“观察列表” / “任何紧急情况”** → 仅观察列表 + 所有风险，无指标部分
- **“打电话前的快速快照”** → TL;DR + #1 优先级仅，无完整部分

## 不应该做的事情

- **在拉取数据之前不要请求权限。** 如果技能被调用，就运行它。询问“我应该检查 QuickBooks 吗？”会破坏整个目的。
- **不要编造或估计数字。** 如果一个来源返回了没有数据，请明确标记为“n/a”。永远不要用猜测来填补空白。
- **不要省略差异。** 没有比较的数字是一个错失的见解。如果没有前一个时期的基本线，请写“(没有前一个基本线)”而不是省略该字段。
- **不要在脉搏中途显示连接器错误。** 将它们记录到附录中。脉搏以交付的内容领先。
- **不要相信 QuickBooks 摘要对象。** 费用、利润和应付账款老化桶来自行或详细调用（`../../shared/quickbooks-report-traps.md`）。

## 更多来源，以及计划预设

阅读 `reference/v2_sources.md` 了解映射：

- **Shopify** — 订单、收入和履行状态，以便商业企业看到其实际情况在脉搏中
- **任何总账** — MYOB、NetSuite、QuickBooks、Xero 或 Zoho Books 提供现金和财务部分；它们是平等的（`../../shared/connector-neutrality.md`）。有两个连接时，负责人指定一个作为总计的记录来源

脉搏仍然从已连接的内容构建，并优雅地降级——一个连接器给出部分脉搏，完整的堆栈给出完整画面。

### 计划预设

这项技能是可计划的，预设决定了形状：

| 预设 | 时间 | 形状 |
|---|---|---|
| 周一 | 周开始 | 完整脉搏，前瞻性。即将到来和需要关注的事情 |
| 周五 | 周结束 | 回顾。什么移动了，什么关闭了，什么滑脱了 |

计划是一个属性，而不是一个单独命令的理由。

在负责人发现有用后提供节奏。不要问两次。
