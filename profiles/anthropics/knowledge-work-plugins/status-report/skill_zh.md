# /状态报告

> 如果你看到不熟悉的占位符，或者需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

为领导层或利益相关者生成一份精炼的状态报告。有关风险矩阵框架和严重性定义，请参阅 **风险评估** 技能。

## 使用方法

```
/status-report $ARGUMENTS
```

## 输出

```markdown
## 状态报告：[项目/团队] — [周期]
**作者：** [姓名] | **日期：** [日期]

### 执行摘要
[3-4 句话的概述——哪些进展顺利，哪些需要关注，关键成果]

### 总体状态：🟢 正常 / 🟡 有风险 / 🔴 偏离轨道

### 关键指标
| 指标 | 目标 | 实际值 | 趋势 | 状态 |
|------|--------|--------|-------|--------|
| [关键绩效指标] | [目标] | [实际值] | [上升/下降/持平] | 🟢/🟡/🔴 |

### 本期成果
- [成果 1]
- [成果 2]

### 进行中
| 项目 | 负责人 | 状态 | 预计完成时间 | 备注 |
```

## 如果连接了工具

如果 **~~项目追踪器** 已连接：
- 自动获取项目状态、已完成事项和即将到来的里程碑
- 识别有风险的项目和逾期任务

如果 **~~聊天** 已连接：
- 扫描最近的团队讨论，以包含决策和阻碍因素
- 提供将完成的报告发布到频道的选项

如果 **~~日历** 已连接：
- 引用报告周期内的关键会议和决策

## 小贴士

1. **先突出重点** — 忙碌的领导只会看前 3 行。让它们发挥作用。
2. **诚实地说明风险** — 早期暴露问题可以建立信任。意外会破坏信任。
3. **让决策变得简单** — 对于每个需要决策的事项，提供背景和建议。
