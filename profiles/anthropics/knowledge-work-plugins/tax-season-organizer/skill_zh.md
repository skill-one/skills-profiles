# 税季组织器

> **说明：** 此技能为注册会计师准备准备材料，而非税务建议。应尽早说明这一点，并明确说明每个假设，以便会计师进行调整。

## 快速入门

确定用户需要的模式，提取相关数据，计算或汇编，并交付会计师可以直接工作的结构化文档。

```
用户："我这个季度需要预缴多少税？"
→ 从 QuickBooks 提取年度利润表
→ 计算预估联邦所得税 + 社会保障税
→ 减去本年度已支付的款项
→ 显示特定季度的应缴金额、截止日期和假设说明
→ 输出："预估 Q2 应缴金额：X 美元，截止日期为 6 月 16 日——详细分解如下"

用户："我需要发送 1099 表"
→ 从 QuickBooks、PayPal 和 Stripe 提取所有承包商/供应商付款
→ 识别年度累计收入 ≥ 600 美元的承包商
→ 标记缺少 W-9 / EIN 的记录
→ 输出：1099-NEC 候选人名单 + 缺少 W-9 行动清单
```

## 第 0 步 — 首先检查国家

以下两种路径均为 **美国联邦税**：自雇税、联邦税率表、1099-NEC 和 W-9。在选择模式之前，从 `## 业务背景` 块中读取 `Country`（规则：`../../shared/currency-and-locale.md`）。如果缺失，请询问。

- **美国** → 继续执行确定模式。
- **其他任何国家** → 简要说明并停止美国计算：*"这里的季度预估和 1099 路径是为美国联邦税设计的。您的账簿在英国，因此我将为您会计师准备已结账的账簿包，而不是美国预估。"* 然后提供 `/close-month` 以处理相关期间。不要在非美国业务上运行美国计算，也不要将其重新标记为通用预估。

输出中的所有金额均以业务货币代码表示；600 美元线是美国法律，并以此命名。

## 确定模式

根据用户消息和背景决定适用路径：

- **季度预估** — 关键词：预估付款、季度税、需要预留多少、安全港、Q1/Q2/Q3/Q4
- **年末 1099 准备** — 关键词：1099、1099-NEC、年末、承包商、W-9、发送 1099、申报 1099
- **组合** — 一些用户会询问 "年末总结" 并需要两者。先运行季度预估；先运行 1099 准备，因为它会驱动最多的行动项。

如果意图不明确，请询问："您是在查看本季度的预估税付款，还是在为您的承包商准备 1099，或者两者都需要？"

## 路径 1：季度预估税

### 1. 提取年度财务数据

使用连接的账簿（MYOB、NetSuite、QuickBooks、Xero 或 Zoho Books — 根据 `../../shared/connector-neutrality.md` 的同行）提取从当前年度 1 月 1 日到最近完成的季度最后一天的利润表。捕获：
- **毛收入**（总收入）
- **总费用**（运营费用、成本等）
- **净普通收入** = 收入 - 费用

如果没有连接账簿，请要求用户上传利润表作为 CSV 或粘贴关键数字。字段名称和每个账簿的查询方法，请参阅 [reference/connector-queries.md](reference/connector-queries.md)。

### 2. 询问已支付的预估税

在计算之前，请询问："今年到目前为止，您已经预缴了多少所得税？" 如果用户不知道，请说明您将计算总负债——他们可以自行减去付款或咨询会计师。

### 3. 计算预估负债

有关完整计算和必须包含在输出中的假设表，请参阅 [reference/calculation-assumptions.md](reference/calculation-assumptions.md)。

**首先，年度化。** 计算基于预期的全年净利润，而不是年度累计值：
`年度化净利润 = 年度累计净利润 ÷ 已过月数 × 12`。显示两者，并标注。季节性业务：询问而不是直接线性化。

简而言之，所有六步都基于 **年度化** 净利润运行：
1. **社会保障税** = 年度化净利润 × 0.9235 × 0.153（然后除以 2——可抵扣部分抵消收入）
2. **调整后净利润** = 年度化净利润 - (社会保障税 / 2)
3. **联邦所得税** = 应用适用于用户业务类型和预估年度收入的适当税率（默认为 22%，除非用户告知您其税率；明确说明此假设）
4. **年度总负债** = 联邦所得税 + 社会保障税
5. **季度付款** = (年度总负债 - 已支付款项) ÷ 剩余季度数
6. **安全港检查** — 说明用户是否应与上一年度税额核对（100% 的上一年度，或 AGI > 15 万美元时为 110%）

**如果已过期的付款尚未支付**，请命名并单独显示其补缴金额，与下一笔付款分开。罚金和利息由会计师处理——请说明适用，但不要估算。没有剩余季度时，应与纳税申报表一起缴纳。

### 4. 说明假设并交付输出

完整的逐节文档结构在
[reference/output-formats.md](reference/output-formats.md) 中。

有两点是不可协商的：**税年出现在标题中**，**假设部分列出了每个假设**——税率、业务结构、州税排除、可抵扣的社会保障税以及未应用的扣除项。会计师从这些杠杆进行调整，因此遗漏一项将导致他们重新构建。

## 路径 2：年末 1099 准备

### 1. 从所有来源提取承包商付款

查询每个连接的来源，提取税年度内向个人或企业支付的服务费用。不包括商品付款、退款或内部转账。

**账簿** — 首先尝试实时连接，然后回退到 CSV 导出。QuickBooks 可能只返回类别级别的总计，没有付款人明细，在这种情况下，您需要用户导出按供应商的交易列表。Xero 提供按联系人提供的账单和付款，以及美国组织的 1099 报告摘要。检测逻辑、询问的确切措辞以及每个账簿的列映射在
[reference/connector-queries.md](reference/connector-queries.md) 中。

**PayPal**：提取所有 "商品和服务" 付款。注意：PayPal 向收入超过阈值的承包商发出自己的 1099-K——在输出中单独标记这些，以便会计师可以确定是否还需要 1099-NEC。

**Stripe**：提取所有向外部方进行的转账/付款。PayPal 的 1099-K 限制同样适用。

**Square**：通过连接器不持有向外部方的付款（付款直接进入所有者自己的银行；承包商付款在 Square Payroll 中，它无法触及）。将其标记为无贡献来源，而不是无声地忽略；1099-K 注意同样适用于该业务的收款。详情在 [reference/connector-queries.md](reference/connector-queries.md) 中。

**桌面/CSV**：如果用户直接上传 CSV（未通过 QuickBooks 导出），映射列：付款人名称、金额、日期、付款方式、EIN/SSN 状态。

### 2. 按付款人汇总

跨来源合并并按个人或企业实体汇总付款。按名称去重（注意 "John Smith" 与 "John A. Smith" 的区别——标记可能重复，供人工审核，而不是自动合并）。

### 3. 应用 600 美元阈值

- **标记 1099-NEC**：任何支付给服务（承包商、自由职业者、顾问）≥ 600 美元的付款人
- **标记 1099-MISC**：任何支付给租金、律师费、奖金/奖项 ≥ 600 美元的付款人
- **接近阈值警报**：标记支付 400–599 美元的付款人——接近阈值，会计师可能需要核实

公司（Inc.、Corp.、LLC 按 C 或 S 公司纳税）通常不需要 1099-NEC——请说明，但标记供会计师确认。

### 4. 检查 W-9 状态

对于每个标记的付款人，请说明账簿中是否有 W-9 / EIN。标记为：
- ✅ W-9 已记录（EIN/SSN 记录在账簿的供应商或联系人记录中）
- ⚠️ 缺失——W-9 未记录；必须收集才能申报
- ❓ 未知——无法从可用数据中确定

### 5. 交付 1099 准备包

完整的逐节结构在
[reference/output-formats.md](reference/output-formats.md) 中。

最重要的部分：**缺少 W-9 行动清单**，因为它会阻止申报，且截止日期为 1 月 31 日；**支付处理器说明**，因为仅通过 PayPal 或 Stripe 支付的承包商可能已经收到 1099-K，会计师必须决定是否还需要 1099-NEC。

## 安全机制

- **在每次输出中命名税年。** [reference/calculation-assumptions.md](reference/calculation-assumptions.md) 中的税率、工资基数和截止日期均为 **2025 年数据**。准备不同年份：在显示任何数字之前大声说明，然后引用 IRS.gov 的当前数据或询问所有者。**永远不要编造税率、工资基数或截止日期。**
- **非税务建议。** 每个可交付成果都以以下内容开头："为您的会计师审查而准备——非税务建议。" 请将其包含在文档标题中，而不仅仅是聊天中。
- **说明每个假设。** 如果您假设 22% 的税率，请说明。如果您排除了州税，请说明。会计师将进行调整；给他们杠杆。
- **不要自动合并付款人。** 标记可能重复的记录，供人工审核。
- **不要提交任何内容。** 输出是准备材料。提交是超出范围的。
- **公司豁免是判断性决定。** 标记它；不要自动排除。
- **永远不要在包、聊天或渲染页面中重复承包商的 SSN 或完整的银行或卡号。** 1099 上的业务 EIN 是唯一例外 (`../../shared/personal-data.md`)。

## 更多来源

- **Gusto** — 实际运行的工资：工资、扣缴和承包商付款。这加深了两种模式——季度预估停止猜测工资数字，1099 准备可以与 Gusto 已申报的承包商付款进行核对。当 Gusto 显示已为付款人发出 1099 时，请标记它，而不是重复准备。
- **Xero** — 季度路径的利润表；按联系人提供的账单和付款；以及对于美国组织，1099 报告摘要，它是路径 2 的一次性预期输出。查询在 `reference/connector-queries.md` 中。
- **Ramp、Expensify** — 卡片支出和费用明细，用于季度预估的扣除项方面；以及供应商付款明细，有助于确认 1099 清单是否完整。Expensify 的收据过滤器找到不会在证明中存活的费用，这是会计师在提交前最希望看到的标记。
- **MYOB** — 仅利润表，用于 MYOB 商户。只读，三年财务历史，**并且没有承包商或供应商付款人明细**——因此它仅用于季度预估，并在 1099 准备中不起作用。

相同的税计算，相同的会计师包。更多来源，更少的假设需要说明。

## 输出

**根据所有者存储的输出偏好交付预估或 1099 包——永远不要默认为 Markdown 文件。** 检查 `## 业务背景` 块的 `Output preference`（共享风格指南规则，`../../shared/artifact-style.md`）：

- **视觉对象（默认）**：以公司风格渲染摘要为 HTML 页面——预估或 1099 计数作为主要状态磁贴，假设表，缺少 W-9 作为每个带有药丸的行，截止日期在顶部。以 "非税务建议" 开头。会计师的文档自己保留 `reference/output-formats.md` 中的结构。
- **docx / md / notion / canva 偏好**：以该形式交付相同内容——DOCX 或 Markdown 文件、Notion 页面（通过连接器创建，命名为目的地，从不覆盖）、或通过 Canva 连接器创建的 Canva 文档（每次运行使用新设计，以日期命名；表格变为列表）；如果 Notion 或 Canva 未连接，则回退到视觉对象——并说明原因。
- **技能最佳**：使用视觉对象——此输出是会计师文档的状态页面。

## 包之后

预估或 1099 包已交到会计师手中，假设已说明。下一步自然是 "关闭月份"——`/close-month` 使下一个预估基于对账数字而不是原始注册运行。附近还有："现金预测" (`cash-flow-snapshot`) 以确认付款在截止日期到期时到账，以及 "谁欠我钱" (`invoice-chase`) 如果需要收款来覆盖。最多提供三个，并跳过本会话中所有者已拒绝的提议。
