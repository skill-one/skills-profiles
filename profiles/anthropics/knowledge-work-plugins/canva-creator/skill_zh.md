# Canva 创作者

## 范围

该技能处理一个活动，分为五个连续的阶段，每个阶段都需要所有者批准：

```
简报 → 日历 → 资产清单 → Canva 设计 → 文本 → HubSpot 预发布
```

| 路径 | 渠道 | 该技能生成的内容 |
|------|----------|--------------------------|
| Canva (社交) | Instagram、Facebook、X/Twitter、LinkedIn | Canva 设计 + 标题 + 定时 HubSpot 帖子 |
| 文本仅 | 邮件 (Newsletter、营销、滴灌) | 主题 + 预览 + 正文，以内联形式呈现给所有者 |

**在任何情况下，Canva 都不用于邮件行** — 没有模板，没有自动填充，没有设计副本，没有资产上传，没有导出。由于邮件模板自动填充在图像插槽超出可用照片时会产生占位符图形，并且变体缩略图在聊天预览中无法渲染，因此邮件图形不在此技能范围内。如果所有者要求 Canva 邮件设计，请查看 `reference/gotchas.md` 以获取重定向语言。

## 预飞行检查

在第一阶段之前，请确认：

1. **简报。** 用户已引用或粘贴了批准的简报。如果没有：
   "在我构建活动之前，我需要内容简报。您有来自内容策略技能的简报，还是现在想写一个？"

2. **Canva 层级。** Pro/Teams 需要用户从其库中手动选择模板（没有自动填充 API）。企业可以从品牌模板中自动填充。

3. **HubSpot 层级。** 社交预发布需要 Marketing Hub Professional。入门级或免费版 → 跳过第五阶段，并导出 CSV（见 [reference/hubspot-staging.md](reference/hubspot-staging.md)）。

4. **品牌资产。** 如果连接了店面（Shopify 或 Square — 对等，`../../shared/connector-neutrality.md`），请先读取产品列表：每个简报中提到的产品的标题、图像 URL 和价格。仅读取 — 直到第二阶段第 5 步，才会上传到 Canva，并且只有图像才会上传，这些图像是批准的日历的插槽所需的。该列表是起始照片清单；只询问商店没有图像的产品。拉取规则 — 哪些字段、价格声明规则 — 在 [../social-content-engine/reference/shopify-assets.md](../social-content-engine/reference/shopify-assets.md)（为 Shopify 编写；Square 的目录图像遵循相同的工具清单步骤）。如果没有店面，
   确认磁盘上的产品照片路径或品牌包是否在 Canva 中为活动。

5. **生成预算。** 估计活动的 Canva 量，并在第一阶段开始之前显示它。默认值为每行 Canva 绑定 3 个候选者；每个设计成本约为 5 个 API 调用（自动填充 + 导出 + 命令）。

   ```
   此活动的生成预算：
     Canva (社交) 行：8
     每行候选者： 3   (默认 — 说 "单个候选者" 以使用 1)
     总设计：       24
     API 调用（约）： ~120  (自动填充 + 导出 + 命令)

   Canva 限制：每分钟 100 个请求。这将需要 ~2-3 分钟的生成时间，远在您的层级限制之内。继续？
   ```

   如果预计的总设计超过 30，建议从一开始就使用单候选者模式 — 大型活动很快就会超出可用空间。所有者可以在第一阶段开始之前将默认值更改为每行 1、2 或 3 个候选者。锁定所选值以供整个会话使用。

## 工作流程

### 第一阶段 — 发布日历

从简报中提取：内容主题、渠道、节奏、硬日期（发布、销售、假日）。

构建一个带有 `路径` 列的日历表，该列将每一行路由到 Canva 或纯文本起草：

| 日期 | 渠道 | 路径 | 主题 | 资产类型 | 标题/主题角度 |
|------|---------|------|-------|------------|-----------------------|
| 6 月 2 日 | Instagram 信息流 | Canva (社交) | 亚麻发布 | Square 帖子 | "终于，一件连衣裙…" |
| 6 月 5 日 | 邮件 | 文本仅 | 亚麻发布 | 邮件正文 | "真正呼吸的亚麻" |

在呈现之前，将每个邮件渠道行标记为 `文本仅`。最多限制为 30 天，除非简报另有说明。提前标记调度冲突（同一天为同一产品发布两个帖子）。

**检查点 1。** 呈现日历。询问："这是否与计划匹配？是否有日期要调整、渠道要添加或主题要交换？" 迭代直到批准，然后在继续之前重申分割情况 — "N 行通过 Canva，M 行通过纯文本起草" — 才能继续。在此处捕获分类错误是免费的；在生成设计后捕获它则不是。

---

### 第二阶段 — 资产清单（仅限 Canva 行）

邮件行完全跳过此阶段。对于每个 `Canva (社交)` 行，构建一个清单，列出模板需要的内容和已提供的内容。

1. **按名称枚举每个图像插槽。** Square Instagram 帖子通常有 1-2 个图像插槽；轮播图和产品网格可能有 5 个以上。将它们单独列出 (`Header_Image`, `Product1_Image`, `Product2_Image`, …) — 永远不要将它们汇总为 "产品图像"。
   - 企业：从品牌模板的 `dataset[].label` 上读取字段名称 (`GET /v1/brand-templates/{id}`)。
   - Pro/Teams：计算模板中的每个独特图像矩形。

2. **清点可用资产。** 从简报中获取文本内容（产品名称、优惠副本、标语、定价），从预飞行从连接的店面读取产品图像 URL（在第 5 步上传，仅用于间隙表所需的插槽，并按 `asset.id` 记录），已上传到 Canva 的产品照片 (`GET /v1/assets`) 或所有者磁盘上的产品照片，品牌包颜色和字体（企业）。标题中的价格来自店面返回的值或简报，永远不会来自内存。

3. **构建按插槽的间隙表。** 每个设计每个插槽一行 — 不是每个设计一行。

   | 日期 | 插槽名称 | 插槽类型 | 可用资产 | 状态 |
   |------|-----------|-----------|-----------------|--------|
   | 6 月 2 日 | Hero_Image | 图像 | bloom_summer.jpg → asset_id 待定 | 上传 |
   | 6 月 2 日 | Headline | 文本 | "夏日亚麻，终于" | 准备 |
   | 6 月 9 日 | Product1_Image | 图像 | — | **缺失** |

4. **与所有者解决插槽/资产不匹配问题。** 如果模板的图像插槽比简报提供的照片多，请暂停并询问：

   ```
   "夏季轮播" 模板有 5 个图像插槽。简报给了我 1 张照片 (bloom_summer.jpg)。我应该如何填充其余的 4 个？

     1. 在所有 5 个插槽中重复同一张照片
     2. 你发给我 4 张更多照片（文件路径）
     3. 选择一个更简单的模板，插槽更少
   ```

   在所有者选择之前，不会进行任何生成调用。使用空插槽生成会产生充满 Canva 默认风景占位符的设计。

5. **上传缺失的照片并捕获验证的资产 ID。** 通过 `POST /v1/asset-uploads` 上传，然后轮询 `GET /v1/asset-uploads/{job_id}`，直到 `status == "success"`。记录响应中的 `asset.id` — 这是仅在自动填充图像字段中起作用的唯一值。传递空字符串、URL、文件路径或过时的 ID 将静默渲染 Canva 的库存风景图形，而不是照片。

6. **确认清单。** 向所有者展示完成的按插槽表，其中每个插槽都已解决，并且每个图像 `asset.id` 都已确认。这是在 Canva API 调用之前的最后一步。

### 第三阶段 — Canva 设计生成

在进行任何 Canva API 调用之前，重新阅读日历，并删除 `路径` 不是 `Canva (社交)` 的任何行。邮件行不通过此阶段。

一次生成一个日历行的设计，每个行有 3 个候选者（或在预飞行中选择的值）。每一行都遵循相同的循环：生成候选者 → 验证 → 导出 → 视觉检查 → 重试失败 → 呈现 → 等待所有者选择 → 下一行。行之间暂停 30 秒。这将生成速率限制在 ~30 秒内 3 个生成 + 3 个导出 — 远低于 Canva 的每分钟 100 个请求速率限制。不要并行化多个行；一次一行是防止所有者在活动期间达到配额的保护措施。

**轮询节奏。** 每 3-5 秒轮询一次工作状态，不要更快。更紧密的间隔会消耗配额而不会加快完成速度。

**预览 URL — 只有一种类型是安全的。** 自动填充响应返回 `design.canva.ai` 缩略图，这些缩略图在几分钟内过期；将它们作为 markdown 图像嵌入会产生损坏的 "显示图像" 占位符。永久导出 URL (`export-download.canva.com` 或 `export-design` MCP 工具) 不会过期。原生 Cowork 轮播图使用连接器的认证会话直接渲染自动填充结果 — 让它们自行渲染，不要重新嵌入。

#### 行循环

1. **解析模板。** （每个会话一次 — 跨行使用相同的模板，除非资产类型混合。）
   - 企业：`GET /v1/brand-templates` 按资产类型过滤。
   - Pro/Teams：`GET /v1/designs?ownership=any&query={模板名称}`，向所有者展示前 3 个，确认一个后再生成。

2. **并行生成行的候选者。** 同时启动行的 3 个候选者（或来自预飞行的 N 个）。
   - 企业：每个候选者使用模板 ID 和字段值通过 `POST /v1/autofills` 发送。并发轮询所有作业。
   - Pro/Teams：通过 `POST /v1/designs` 创建副本。描述所有者在 Canva 中应用的文本和图像编辑；收集设计 ID。

3. **验证作业状态。** 对于每个候选者，确认 `GET /autofills/{job_id}` 返回 `status == "success"` 并且 `result.design.id` 存在。按设计处理错误：
   - `JOB_FAILED` → 读取 `job.error.message`，修复字段值或资产 ID，重试一次。
   - `RATE_LIMIT_EXCEEDED`（本会话首次遇到此错误）→ 等待 60 秒，重试该候选者一次。这处理了瞬态峰值。
   - `RATE_LIMIT_EXCEEDED`（本会话第二次遇到此错误）**或** 任何 `quota_exceeded` / 每日上限错误 → 立即停止生成。不要重试。显示进度并询问：

     ```
     Canva 正在限制此活动。状态如下：
       ✓ 已生成： 1-4 帖子（12 个设计）
       ⏸ 剩余： 5-8 帖子（尚未生成的 12 个设计）

     我应该如何继续？
       1. 切换到每行 1 个候选者（总共 4 个设计）— 现在完成
       2. 暂停活动 — 在 60 分钟后配额刷新时恢复
       3. 停止生成 — 使用我们现有的内容，继续标题
     ```

     等待所有者的选择。不要在重试时循环。

4. **将每个成功的候选者导出到永久 PNG。** 并行启动行的导出。
   - REST：`POST /v1/exports` 使用 `format.type: "png"`，轮询 `GET /v1/exports/{job_id}` 直到成功，捕获 `urls[0]`。
   - Canva MCP：`export-design` 使用设计 ID。

   这些永久 URL 将用于预览和稍后附加到 HubSpot 帖子。自动填充响应缩略图永远不会用于下游。

5. **视觉验证每个导出。** 查看图像并拒绝任何这些 — 它们都表示未填充的插槽或错误的资产：
   - 带有云和绿色山丘的通用风景（Canva 的默认占位符）
   - 应该是照片的实心灰色矩形
   - Lorem-ipsum 或模板默认文本
   - 主题与简报不匹配（错误的产品、错误的品牌）

   如果候选者验证失败：重新检查受影响的插槽的清单，修复 `asset.id`，重新生成该单个候选者，重新导出，重新验证。

6. **在部分失败时按候选者重试。** 如果行中的 N 个候选者中有 1 个在步骤 3 或 5 失败，请重新生成该单个候选者 — 不要重做整行，也不要呈现部分损坏的轮播图。如果第二次尝试也失败：

   ```
   6 月 9 日帖子的第三个候选者持续失败 — Canva 返回 [错误 / 渲染了占位符]。我应该如何继续？

     1. 跳过它 — 呈现其他 2 个并继续
     2. 交换一个更简单的模板，仅用于此候选者
     3. 尝试使用不同的照片一次
   ```

7. **呈现行的候选者。** 让原生 Cowork 轮播图渲染自动填充工具结果。在它下方添加文本提示：

   ```
   6 月 9 日的候选者已准备好 — 上下滚动上面的轮播图。
   我应该使用哪个设计用于 6 月 9 日的帖子？
   ```

   如果轮播图无法渲染或一个位置损坏，请嵌入来自步骤 4 的永久导出 PNG URL。最终后备：链接到设计的 Canva 编辑 URL (`https://www.canva.com/d/{design_id}`)。永远不要重新嵌入 `design.canva.ai` URL。

8. **暂停 30 秒，然后转到下一行。**

**检查点 2。** 满足条件后，一旦每个日历行都选择了一个设计。如果他们想要重新生成，请仅重新生成该单个候选者。

### 第四阶段 — 文本起草

对于每个日历行，起草文本。社交行获得标题；邮件行获得完整的邮件。

**社交标题** — Instagram、Facebook、X、LinkedIn：

- 长度：渠道适用（Instagram ≤ 2,200 字符；Facebook ≤ 500 字符建议；X ≤ 280）。
- 结构：钩子 → 一个产品优势 → CTA → 3-5 个标签（不是 30 个）。
- 语气：匹配简报的语气标记。如果简报说 "休闲和友好"，不要写企业级文案。
- 没有填充。没有 "令人兴奋的消息！" 或 "我们很高兴宣布。" 从价值开始。

**邮件内容** — Claude 写整个邮件；不使用 Canva：

- 主题：≤ 50 字符，具体，没有标题党。"春季项目正在预订" 比起 "不要错过！" 更好。
- 预览：≤ 90 字符，补充主题，不重复它。
- 正文：纯文本，100-250 字。引人入胜的第一行 → 1-2 段实质性内容 → 单个清晰的 CTA → 签名。
- 语气：与社交相同的语气标记。所有者希望他们的邮件听起来像他们自己，而不是像模板化的简报。
- 没有图像引用。不要写 "查看上面的图像"。如果所有者想要视觉效果，他们可以在他们的邮件工具中添加它们。
- 每个邮件一个 CTA。选择最重要的操作并首先提出它。

在社交行下方内联呈现标题。在邮件行下方内联呈现完整邮件：

```
主题：<主题行>
预览：<预览文本>

<正文文本>
```

对于示例，请参阅
[reference/examples/boutique-brief-campaign.md](reference/examples/boutique-brief-campaign.md)。

**检查点 3。** "是否有标题或邮件需要重写？标记日期和要更改的内容。" 迭代直到批准。

### 第五阶段 — HubSpot 预发布 + 邮件交接

在 HubSpot 中预发布社交帖子。邮件内容不会预发布 — 它将内联显示供所有者复制到他们的邮件工具中。有关 API 字段参考，请参阅
[reference/hubspot-staging.md](reference/hubspot-staging.md)。

1. **创建活动。** `POST /marketing/v3/campaigns` 使用活动名称和日历的开始和结束日期。

2. **预发布每个社交帖子。** `POST` 到 HubSpot Social API 每个社交行：
   - `channel`：将日历渠道映射到 HubSpot 账户 ID
   - `scheduledAt`：ISO 8601 日期时间 — 在调用之前确认它在未来
   - `content.body`：批准的标题
   - `attachments`：来自第三阶段的永久 Canva 导出 PNG URL
   - `status`：`SCHEDULED`（永远不会 `PUBLISHED`）

3. **确认队列。** 调用
   `GET /marketing/v3/social/posts?status=SCHEDULED`，显示列表，提供直接链接到 HubSpot 活动视图。

4. **内联显示邮件内容以供交接。** 对于每个邮件行，内联显示批准的主题 + 预览 + 正文，按发送日期分组。所有者将这些复制到他们的邮件工具（HubSpot Marketing Email、Mailchimp、Gmail 或 M365）。

**最终检查点。**

```
您的社交帖子已预发布在 HubSpot：[链接]
它们将按计划发送 — 您可以在 HubSpot 中取消或编辑任何帖子。

邮件内容已起草如下 — 在您准备发送时，将每个复制到您的邮件工具：

  6 月 5 日 — "春季项目正在预订"
  7 月 15 日 — "夏季维护窗口正在填满"

在我们完成之前，还有什么要更改的吗？
```

除了该摘要之外 — 永远不要替代它 — 按照房屋风格 (`../../shared/artifact-style.md`) 渲染活动为 HTML 资产：作为表格的发布日历，每行上的按渠道状态药丸（已发布 / 起草 / 交接），以及每行的已发布帖子面板，带有批准的标题或邮件副本及其导出 PNG 链接。

**结束语。** 活动现在包含的内容的一行，然后是最相关的下一步及其触发短语 — 一旦帖子开始发送，通常是 "我的营销效果如何？" (`growth-pulse`)。最多两个其他："制作内容" (`social-content-engine`) 用于站立日历，或 "我的广告" (`ad-manager`)。最多三个；永远不会重新提供本会话中所有者拒绝的内容。

## 批准关卡

- **邮件行不进行 Canva 调用。** 在每个 API 调用之前，重新检查 `路径` 列。
- **不发布。** 每个HubSpot 帖子都作为 `SCHEDULED` 预发布；所有者控制发布时间。
- **始终在预飞行中显示生成预算。** 所有者看到总设计数量，并在第一阶段开始之前批准。
- **第三阶段一次一行。** 行内的候选者并行启动，但行是按顺序执行的，间隔 30 秒 — 这是配额保护措施。
- **在第二次配额错误时暂停并询问。** 永远不要在重试时循环。
- **始终在呈现之前导出到永久 PNG。** 作业成功并不意味着设计正确渲染。
- **永远不要在消息中嵌入 `design.canva.ai` URL。** 它们会过期。
- **当候选者失败时，永远不要重新生成整行。**
  仅按候选者重试。
- **永远不要为 Pro/Teams 用户自动选择模板。** 始终确认。
- **永远不要跳过按插槽的清单。** 多插槽模板在任何插槽为空时都会渲染占位符风景。
- **永远不要跳过检查点 1。** 在日历批准之前生成是此技能中最大浪费工作的来源。
