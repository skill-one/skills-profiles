# /sprint-planning

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

通过定义工作范围、估算能力并设定明确的目标来规划冲刺。

## 使用方法

```
/sprint-planning $ARGUMENTS
```

## 工作原理

```
┌─────────────────────────────────────────────────────────────────┐
│                    SPRINT PLANNING                                 │
├─────────────────────────────────────────────────────────────────┤
│  独立模式（始终可用）                                       │
│  ✓ 定义冲刺目标和成功标准                     │
│  ✓ 估算团队能力（考虑休假、会议）        │
│  ✓ 范围界定和优先排序待办事项                           │
│  ✓ 确定依赖关系和风险                              │
│  ✓ 生成冲刺计划文档                                │
├─────────────────────────────────────────────────────────────────┤
│  超级加速模式（连接工具时）                      │
│  + 项目追踪器：拉取待办事项，创建冲刺，分配项目   │
│  + 日历：在能力中考虑休假和会议           │
│  + 聊天：与团队分享冲刺计划                        │
└─────────────────────────────────────────────────────────────────┘
```

## 我需要你提供的信息

- **团队**：团队成员及其本次冲刺的可用性？
- **冲刺长度**：多少天/周？
- **待办事项列表**：优先处理哪些？（从追踪器中拉取、粘贴或描述）
- **遗留问题**：上次冲刺未完成的事项？
- **依赖关系**：是否有阻塞其他团队的事项？

## 小贴士

1. **预留缓冲** — 计划 70-80% 的能力。你会遇到中断。
2. **一个清晰的冲刺目标** — 如果不能用一句话表达，冲刺就会失去焦点。
3. **识别扩展项** — 知道如果事情比预期时间长，需要裁剪什么。
4. **诚实地遗留问题** — 如果某事未能交付，在重新承诺之前要理解原因。
