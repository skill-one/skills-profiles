# 技术债务管理

系统性地识别、分类和优先处理技术债务。

## 分类

| 类型 | 示例 | 风险 |
|------|------|------|
| **代码债务** | 重复逻辑、糟糕的抽象、魔法数字 | 错误、开发缓慢 |
| **架构债务** | 应该拆分的单体、错误的数据存储 | 扩展限制 |
| **测试债务** | 覆盖率低、不可靠的测试、缺失的集成测试 | 回归错误 |
| **依赖债务** | 过时的库、未维护的依赖 | 安全漏洞 |
| **文档债务** | 缺失的运行手册、过时的README、部落知识 | onboarding困难 |
| **基础设施债务** | 手动部署、无监控、无IaC | 事件、恢复缓慢 |

## 优先级框架

对每个项目进行评分：
- **影响**：它有多慢地拖慢团队？ (1-5)
- **风险**：如果我们不修复它会发生什么？ (1-5)
- **工作量**：修复有多难？ (1-5，反向——工作量越低优先级越高)

优先级 = (影响 + 风险) x (6 - 工作量)

## 输出

生成一个包含估计工作量、每个项目的业务理由以及分阶段修复计划（可与功能工作并行进行）的优先级列表。
