# 搜索命令

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

在一个查询中跨所有已连接的 MCP 源进行搜索。分解用户的提问，并行运行搜索，并整合结果。

## 说明

### 1. 检查可用源

在搜索前，确定哪些 MCP 源可用。尝试从可用工具列表中识别已连接的工具。常见源：

- **~~chat** — 聊天平台工具
- **~~email** — 邮件工具
- **~~cloud storage** — 云存储工具
- **~~project tracker** — 项目跟踪工具
- **~~CRM** — CRM 工具
- **~~knowledge base** — 知识库工具

如果未连接任何 MCP 源：
```
要跨你的工具进行搜索，你需要至少连接一个源。
检查你的 MCP 设置以添加 ~~chat、~~email、~~cloud storage 或其他工具。

支持的源：~~chat、~~email、~~cloud storage、~~project tracker、~~CRM、~~knowledge base，
以及任何其他 MCP 已连接的服务。
```

### 2. 解析用户查询

分析搜索查询以理解：

- **意图**：用户在寻找什么？（一个决策、一个文档、一个人、一个状态更新、一次对话）
- **实体**：提到的人、项目、团队、工具
- **时间限制**：时效性信号（"本周"、"上个月"、具体日期）
- **源提示**：对特定工具的引用（"在 ~~chat 中"、"那封邮件"、"那个文档"）
- **过滤器**：从查询中提取显式过滤器：
  - `from:` — 按发送者/作者过滤
  - `in:` — 按频道、文件夹或位置过滤
  - `after:` — 仅结果在此日期之后
  - `before:` — 仅结果在此日期之前
  - `type:` — 按内容类型过滤（消息、邮件、文档、线程、文件）

### 3. 分解为子查询

针对每个可用源，使用该源的原生搜索语法创建目标子查询：

**~~chat:**
- 使用聊天平台的可用搜索和阅读工具
- 翻译过滤器：`from:` 映射到发送者，`in:` 映射到频道/房间，日期映射到时间范围过滤器
- 在适当情况下使用自然语言查询进行语义搜索
- 使用关键字查询进行精确匹配

**~~email:**
- 使用可用邮件搜索工具
- 翻译过滤器：`from:` 映射到发送者，日期映射到时间范围过滤器
- 适当地将 `type:` 映射到附件过滤器或主题行搜索

**~~cloud storage:**
- 使用可用文件搜索工具
- 翻译为文件查询语法：名称包含、全文包含、修改日期、文件类型
- 考虑文件名和内容

**~~project tracker:**
- 使用可用任务搜索或自动完成工具
- 映射到任务文本搜索、指派者过滤器、日期过滤器、项目过滤器

**~~CRM:**
- 使用可用 CRM 查询工具
- 跨账户、联系人、机会和其他相关对象进行搜索

**~~knowledge base:**
- 使用语义搜索回答概念性问题
- 使用关键字搜索进行精确匹配

### 4. 并行执行搜索

跨所有可用源同时运行所有子查询。不要等待一个源完成再搜索另一个源。

针对每个源：
- 执行翻译后的查询
- 带元数据（时间戳、作者、链接、源类型）捕获结果
- 记录任何失败或返回错误的源——不要让一个失败阻塞其他源

### 5. 排序和去重结果

**去重：**
- 识别跨源出现的相同信息（例如，在 ~~chat 中讨论的决策和通过邮件确认的决策）
- 将相关结果组合在一起，而不是显示重复项
- 优先选择最权威或最完整的版本

**排序因素：**
- **相关性**：结果与查询意图匹配程度如何？
- **时效性**：对于状态/决策查询，更近的结果排名更高
- **权威性**：官方文档 > 维基 > 聊天消息（用于事实性问题）；对话 > 文档（用于"我们讨论了什么"查询）
- **完整性**：包含更多上下文的结果排名更高

### 6. 呈现统一结果

将响应格式化为整合后的答案，而不是原始结果列表：

**对于事实/决策查询：**
```
[直接回答问题]

来源：
- [源 1：简要描述] (~~chat, #频道, 日期)
- [源 2：简要描述] (~~email, 来自某人, 日期)
- [源 3：简要描述] (~~cloud storage, 文档名, 最后修改)
```

**对于探索性查询（"关于 X 我们知道什么"）：**
```
[整合所有源信息的综合摘要]

跨以下源找到：
- ~~chat: X 条相关消息在 Y 个频道中
- ~~email: X 个相关线程
- ~~cloud storage: X 个相关文档
- [其他适用源]

关键来源：
- [最重要来源的链接/引用]
- [第二重要来源]
```

**对于"查找"查询（寻找特定事物）：**
```
[他们正在寻找的事物，带直接引用]

其他找到：
- [其他源的相关项]
```

### 7. 处理边缘情况

**歧义查询：**
如果查询可能指代多件事，在搜索前问一个澄清问题：
```
"API 重构"可能指代几件事。你在寻找：
1. REST API v2 重构（项目 Aurora）
2. 内部 SDK API 变更
3. 其他？
```

**无结果：**
```
我无法在 [搜索的源列表] 中找到与 "[查询]" 匹配的内容。

尝试：
- 更广泛的术语（例如，"数据库"而不是"PostgreSQL 迁移"）
- 不同的时间范围（目前搜索 [时间范围]）
- 检查相关源是否已连接（目前搜索：[源]）
```

**部分结果（部分源失败）：**
```
[来自成功源的结果]

注意：在本次搜索中无法连接 [失败的源]。以上结果仅来自 [成功源]。
```

## 注意事项

- 始终并行搜索多个源——不要按顺序搜索
- 将结果整合为答案，不要仅列出原始搜索结果
- 包含来源归因，以便用户可以深入挖掘
- 尊重用户的过滤器语法，并根据每个源适当应用
- 当查询提到特定人员时，跨所有源搜索他们的消息/文档/提及
- 对于时效性查询，在排序中优先考虑时效性
- 如果只有一个源已连接，仍然从该源提供有用结果
