# 指标审查

> 如果您看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

审查和分析产品指标，识别趋势，并发现可采取的行动建议。

## 使用方法

```
/metrics-review $ARGUMENTS
```

## 工作流程

### 1. 收集指标数据

如果 **~~产品分析~~** 已连接：
- 提取相关时间段的关键产品指标
- 获取比较数据（上一周期、去年同期、目标）
- 如果可用，提取细分数据

如果没有连接分析工具，请要求用户提供：
- 指标及其值（粘贴表格、截图或描述）
- 比较数据（上一周期、目标）
- 有关近期变化的任何背景信息（发布、事件、季节性）

询问用户：
- 要审查哪个时间段？（上周、上个月、上季度）
- 要关注哪些指标？或者我们应该审查完整的产品指标套件？
- 有哪些特定的目标或目标要与之比较？
- 是否有任何已知事件可能解释变化（发布、停机、营销活动、季节性）？

### 2. 组织指标

使用指标层次结构来组织审查：顶部是北极星指标，L1 健康指标（获取、激活、参与、留存、收入、满意度），以及用于下钻的 L2 诊断指标。有关完整定义，请参阅下方的 **产品指标层次结构**。

如果用户尚未定义其指标层次结构，请在继续之前帮助他们确定其北极星和关键 L1 指标。

### 3. 分析趋势

针对每个关键指标：
- **当前值**：该指标今天是什么？
- **趋势**：与上一周期相比是上升、下降还是持平？时间范围是多少？
- **与目标比较**：它如何与目标或目标进行比较？
- **变化率**：趋势是加速还是减速？
- **异常值**：是否有任何突然的变化、峰值或下降？

识别相关性：
- 一个指标的变化是否与另一个指标的变化相关？
- 是否有领先指标可以预测滞后指标的变化？
- 细分数据是否显示整体趋势是由特定群体驱动的？

### 4. 生成审查报告

#### 摘要
2-3 句话：整体产品健康状况、最显著的变化、关键要点。

#### 指标记分卡
快速扫描的表格格式：

| 指标 | 当前值 | 上一周期 | 变化 | 目标 | 状态 |
|------|---------|----------|------|------|------|
| [指标] | [值] | [值] | [+/- %] | [目标] | [按计划进行 / 存在风险 / 未达标] |

#### 趋势分析
针对每个值得讨论的指标：
- 发生了什么以及变化有多显著
- 为什么它可能发生（基于已知事件、相关指标、细分分析进行归因）
- 这是一次性事件还是持续趋势

#### 亮点
进展顺利的地方：
- 超过目标的指标
- 值得持续的正向趋势
- 表现强劲的细分或功能

#### 关注领域
需要关注的领域：
- 未达标或呈负趋势的指标
- 在问题变成麻烦之前出现的早期预警信号
- 我们缺乏可见性或理解的指标

#### 推荐行动
基于分析的下一步具体措施：
- 要进行的调查（深入调查令人担忧的趋势）
- 要启动的实验（测试可能改善指标假设）
- 要进行的投资（加倍投入正在起作用的事情）
- 要设置的警报（更密切地监控指标）

#### 背景和注意事项
- 已知的数据质量问题
- 影响可比性的事件（停机、节假日、发布）
- 我们应该跟踪但尚未跟踪的指标

### 5. 跟进

生成审查报告后：
- 询问是否需要更深入地调查任何指标
- 提供创建持续监控的仪表板规范
- 提供起草关注领域的实验提案
- 提供设置指标审查模板以供重复使用

## 产品指标层次结构

### 北极星指标
最能捕捉产品为用户带来的核心价值的单一指标。它应该是：

- **价值对齐**：当用户从产品中获得更多价值时，该指标会随之变化
- **领先指标**：预测长期业务成功（收入、留存）
- **可行动性**：产品团队可以通过他们的工作影响它
- **可理解性**：公司里的每个人都能理解它的含义以及为什么它很重要

**按产品类型举例**：
- 协作工具：每周有 3 名或更多成员参与贡献的活跃团队
- 交易市场：每周完成的交易
- SaaS 平台：每周完成核心工作流程的活跃用户
- 内容平台：每周参与阅读/观看时间
- 开发者工具：每周使用该工具的部署次数

### L1 指标（健康指标）
共同描绘完整产品健康状况的 5-7 个指标。这些指标映射到用户生命周期的关键阶段：

**获取**：新用户是否在寻找产品？
- 新注册或试用开始（数量和趋势）
- 注册转化率（访客到注册）
- 渠道组合（新用户来自哪里）
- 获取成本（付费渠道）

**激活**：新用户是否达到价值时刻？
- 激活率：完成预测留存的关键操作的 % 新用户
- 激活时间：从注册到激活需要多长时间
- 设置完成率：完成入门步骤的 % 用户
- 首次价值时刻：用户首次体验核心产品价值的时间

**参与**：活跃用户是否在获得价值？
- DAU / WAU / MAU：不同时间范围内的活跃用户
- DAU/MAU 比率（粘性）：每月用户中有多少比例是每日用户
- 核心操作频率：用户执行最重要的事情的频率
- 会话深度：用户每次会话执行多少操作
- 功能采用率：使用关键功能的 % 用户

**留存**：用户是否回来？
- D1、D7、D30 留存率：1 天、7 天、30 天后返回的 % 用户
- 簇留存曲线：每个注册簇的留存如何演变
- 跳槽率：每个周期失去的用户或收入 %
- 复活率：跳槽用户中 % 回来的用户

**变现**：价值是否转化为收入？
- 转化率：免费到付费（针对免费增值产品）
- MRR / ARR：月度或年度经常性收入
- ARPU / ARPA：每用户或账户的平均收入
- 扩张收入：现有客户带来的收入增长
- 净收入留存：包括扩张和收缩的收入留存

**满意度**：用户对产品的感受如何？
- NPS：净推荐值
- CSAT：客户满意度分数
- 支持工单数量和解决时间
- 应用商店评分和评论情绪

### L2 指标（诊断指标）
用于调查 L1 指标变化的详细指标：

- 每个步骤的漏斗转化率
- 功能级使用率和采用率
- 特定细分数据的细分（按计划、公司规模、地理位置、用户角色）
- 性能指标（页面加载时间、错误率、API 延迟）
- 内容特定参与度（哪些功能、页面或内容类型驱动参与度）

## 常见产品指标

### DAU / WAU / MAU
**衡量内容**：在一天、一周或一个月内执行合格操作的唯一用户。

**关键决策**：
- “活跃”是什么？登录？页面浏览？核心操作？仔细定义——不同的定义会讲述不同的故事。
- 哪个时间段最重要？DAU 对于日常使用产品（消息、电子邮件）。WAU 对于每周使用产品（项目管理）。MAU 对于不频繁使用的产品（税务软件、旅行预订）。

**如何使用它们**：
- DAU/MAU 比率（粘性）：值高于 0.5 表示每日习惯。低于 0.2 表示使用频率低。
- 趋势比绝对数字更重要。活跃使用是否在增长、持平或下降？
- 按用户类型细分。重度用户和休闲用户的行为差异很大。

### 留存率
**衡量内容**：在周期 X 开始的用户中，有多少 % 在周期 Y 仍然活跃？

**常见的留存时间段**：
- D1（第二天）：第一次体验是否足够好以至于回来？
- D7（一周）：用户是否建立了习惯？
- D30（一个月）：用户是否长期留存？
- D90（三个月）：这是否是耐用的用户？

**如何使用留存率**：
- 按簇绘制留存曲线。寻找：初始流失（激活问题）、稳定下降（参与问题）或扁平化（良好——你有一个稳定的留存基础）。
- 比较不同时间段的簇。较新的簇是否比旧的簇留存更好？这意味着产品改进正在起作用。
- 按激活行为细分留存。完成入门的用户与未完成入门的用户。使用功能 X 的用户与未使用功能 X 的用户。

### 转化率
**衡量内容**：有多少用户从一个阶段移动到下一个阶段。

**常见的转化漏斗**：
- 访客到注册
- 注册到激活（关键价值时刻）
- 免费到付费（试用转化）
- 试用到付费订阅
- 月度到年度计划

**如何使用转化率**：
- 绘制完整漏斗并测量每个步骤的转化率
- 确定最大的流失点——这是你最高杠杆的改进机会
- 按来源、计划、用户类型细分转化率。不同的细分市场转化差异很大。
- 跟踪随时间的转化率。随着你对体验的迭代，转化率是否在改善？

### 激活
**衡量内容**：% 新用户达到首次体验产品核心价值时刻。

**定义激活**：
- 查看留存用户与跳槽用户。留存用户执行了哪些操作而跳槽用户没有执行？
- 激活事件应该是长期留存的强预测指标
- 它应该在会话内或几天内即可实现
- 例子：创建第一个项目、邀请队友、完成第一个工作流程、连接集成

**如何使用激活**：
- 跟踪每个注册簇的激活率
- 测量激活时间——越快越好
- 构建引导用户到激活时刻的入门流程
- A/B 测试激活流程，并测量对留存的影响，而不仅仅是激活率

## 目标设定框架

### OKRs（目标与关键成果）

**目标**：描述您想要实现什么的定性、有抱负的目标。
- 令人鼓舞且难忘
- 有时间限制（季度或年度）
- 方向性，而不是指标特定

**关键成果**：告诉您是否实现了目标的定量指标。
- 具体且可衡量
- 有时间限制，并有明确的靶标
- 基于结果，而不是基于产出
- 每个目标 2-4 个关键成果

**示例**：
```
目标：使我们的产品成为日常工作流程不可或缺的一部分

关键成果：
- 将 DAU/MAU 比率从 0.35 提高到 0.50
- 将新用户的 D30 留存率从 40% 提高到 55%
- 3 个核心工作流程的任务完成率 > 80%
```

### OKR 最佳实践
- 设定既雄心勃勃又可实现的目标。70% 的完成率是拉伸目标的目标。
- 关键成果应衡量结果（用户行为、业务结果），而不是产出（已发布的功能、已完成的任务）。
- 不要设置太多的 OKR。每个目标 2-3 个，每个目标 2-4 个 KR 就足够了。
- OKR 应该令人不安。如果您确信会达成所有目标，它们就不够雄心勃勃。
- 在中期审查 OKR。如果一些 KR 显然偏离了轨道，请调整资源分配。
- 诚实地在期末对 OKR 进行评分。0.0-0.3 = 未达标，0.4-0.6 = 有进展，0.7-1.0 = 已实现。

### 设置指标目标
- **基线**：当前值是多少？在设置目标之前，您需要一个可靠的基线。
- **基准**：可比产品实现了什么？行业基准提供了背景。
- **轨迹**：当前趋势如何？如果指标已经在以每月 5% 的速度改善，6% 的目标就不够雄心勃勃。
- **投入**：您在这背后投入了多少资源？更大的赌注值得更雄心勃勃的目标。
- **信心**：您实现目标的信心有多大？设置“承诺”（高信心）和“拉伸”（雄心勃勃）。

## 指标审查节奏

### 每周指标检查
**目的**：快速发现问题、监控实验、了解产品健康状况。
**持续时间**：15-30 分钟。
**参与者**：产品经理，可能还有工程负责人。

**要审查的内容**：
- 北极星指标：当前值、周环比变化
- 关键 L1 指标：任何显著变化
- 活动实验：结果和统计显著性
- 异常值：任何意外的峰值或下降
- 警报：任何触发了监控警报的内容

**行动**：如果看起来不对劲，请调查。否则，记录下来并继续。

### 每月指标审查
**目的**：对趋势进行更深入的分析、与目标保持一致、战略影响。
**持续时间**：30-60 分钟。
**参与者**：产品团队、关键利益相关者。

**要审查的内容**：
- 完整的 L1 指标记分卡与月环比趋势
- 对季度 OKR 目标的进展
- 簇分析：较新的簇是否表现更好？
- 功能采用率：最近发布的功能表现如何？
- 细分分析：用户细分之间是否有任何差异？

**行动**：确定 1-3 个要调查或投资的区域。如果指标揭示了新信息，请更新优先级。

### 季度业务审查
**目的**：战略评估产品绩效、为下一季度设定目标。
**持续时间**：60-90 分钟。
**参与者**：产品、工程、设计、领导层。

**要审查的内容**：
- 季度 OKR 评分
- 季度 L1 指标趋势分析
- 年度同比
- 竞争背景：市场变化和竞争对手动态
- 哪些有效，哪些无效

**行动**：为下一季度设定 OKR。根据数据所示调整产品战略。

## 仪表板设计原则

### 有效的产品仪表板
一个好的仪表板在一瞥中就能回答“产品表现如何？”的问题。

**原则**：

1. **从问题开始，而不是数据**。这个仪表板支持哪些决策？从决策反向设计。
2. **信息的层次结构**。最重要的指标应该是视觉上最突出的。北极星指标在顶部，L1 指标在其次，L2 指标可在下钻时查看。
3. **内容比数字更重要**。没有上下文的数字是无意义的。始终显示：当前值、比较（上一周期、目标、基准）、趋势方向。
4. **较少的指标，更多的洞察**。50 个指标的仪表板对谁都没有帮助。专注于 5-10 个最重要的指标。将其他所有内容放在详细报告中。
5. **一致的时间段**。仪表板上的所有指标都使用相同的时间段。混合每日和月度指标会造成混乱。
6. **视觉状态指示器**。使用颜色在 glance 中指示健康状况：
   - 绿色：按计划进行或改善
   - 黄色：需要关注或持平
   - 红色：未达标或下降

7. **可操作性**。仪表板上的每个指标都应该是团队可以影响的。如果您无法对其采取行动，则它不应出现在产品仪表板中。

### 仪表板布局

**第一行**：北极星指标，带有趋势线和目标。

**第二行**：L1 指标记分卡——每个关键指标的当前值、变化、目标、状态。

**第三行**：关键漏斗或转化指标——显示每个阶段流失的可视化漏斗。

**第四行**：最近的实验和发布——活动的 A/B 测试、最近发布的功能的早期指标。

**底部/下钻**：L2 指标、细分数据以及用于调查的详细时间序列。

### 仪表板反模式
- **虚荣指标**：总是上升但不指示健康的指标（总注册量、总页面浏览量）
- **太多指标**：需要滚动才能查看的仪表板。如果它不适合一个屏幕，请删除指标。
- **没有比较**：原始数字没有上下文（当前值没有上一周期或目标）
- **过时的仪表板**：数月未更新或审查的指标
- **产出仪表板**：衡量团队活动（关闭工单、合并 PR）而不是用户和业务结果
- **所有受众的单一仪表板**：高管、PM 和工程师需要不同的视图。一种尺寸不适合所有。

### 警报
为需要立即关注的指标设置警报：

- **阈值警报**：指标低于或高于关键阈值（错误率 > 1%、转化率 < 5%）
- **趋势警报**：指标在多天/周内持续下降
- **异常警报**：指标显著偏离预期范围

**警报卫生**：
- 每个警报都应该是可操作的。如果您无法对其采取行动，请不要警报。
- 定期审查和调整警报。太多的误报会导致人们忽略所有警报。
- 为每个警报定义所有者。当它触发时谁响应？
- 设置适当严重级别。不是所有事情都是 P0。

## 输出格式

使用表格创建记分卡。使用清晰的状况指示器。保持摘要简洁——读者应在 30 秒内了解关键故事。

## 小贴士

- 从“所以是什么”开始——这个指标审查中最重要的东西是什么？首先提出这个。
- 没有上下文的绝对数字是无用的。始终显示比较（与上一周期、与目标、与基准）。
- 谨慎进行归因。相关性不等于因果关系。如果指标发生了变化，请承认对原因的不确定性。
- 细分分析通常显示整体指标掩盖了重要差异。整体数字持平可能隐藏了一个细分市场增长而另一个细分市场下降的情况。
- 不是所有指标运动都重要。小的波动是噪音。专注于有意义的改变。
- 如果指标未达标，不要只是报告未达标——建议如何解决它。
- 指标审查应推动决策。如果审查没有导致至少一个行动，则它没有用处。
