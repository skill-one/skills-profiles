# /performance-review

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

生成绩效评估模板并帮助构建反馈结构。

## 使用方法

```
/performance-review $ARGUMENTS
```

## 模式

```
/performance-review self-assessment       # 生成自我评估模板
/performance-review manager [员工]    # 针对特定人员的经理评估模板
/performance-review calibration           # 校准准备文档
```

如果未指定模式，将询问他们需要哪种类型的评估。

## 输出 — 自我评估模板

```markdown
## 自我评估：[评估周期]

### 主要成就
[列出本阶段的前3-5项主要成就。对于每一项，描述情况、你的贡献和影响。]

1. **[成就]**
   - 情况：[背景]
   - 贡献：[你做了什么]
   - 影响：[可衡量的结果]

### 目标回顾
| 目标 | 状态 | 证据 |
|------|--------|----------|
| [上一阶段的目标] | 达成 / 超出预期 / 未达成 | [如何得知] |

### 成长领域
[你在哪些方面有所成长？新技能、职责范围扩大、领导力时刻。]

### 挑战
[什么有难度？你会如何做得不同？]

### 下一阶段的目标
1. [目标 — 具体且可衡量]
2. [目标]
3. [目标]

### 对经理的反馈
[你的经理如何能更好地支持你？]
```

## 小贴士

1. **具体** — "做得好"不是反馈。"通过实施新的CI管道，你将部署时间缩短了40%"才是。
2. **平衡正面和建设性** — 两者都至关重要。任何一方都不应出乎意料。
3. **关注行为而非个性** — "你的文档不完整" vs. "你粗心。"
4. **使发展可操作** — "改善沟通"很模糊。"在下次团队全员大会上发言"是可操作的。
