# /code-review

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

以结构化的视角审查代码变更，关注安全性、性能、正确性和可维护性。

## 使用方法

```
/code-review <PR URL 或文件路径>
```

审查提供的代码变更：@$1

如果未提供特定文件或 URL，请询问要审查的内容。

## 工作原理

```
┌─────────────────────────────────────────────────────────────────┐
│                      代码审查                                   │
├─────────────────────────────────────────────────────────────────┤
│  独立运行（始终可用）                                       │
│  ✓ 粘贴差异、PR URL 或指向文件                      │
│  ✓ 安全审计（OWASP Top 10、注入、认证）               │
│  ✓ 性能审查（N+1、内存泄漏、复杂度）           │
│  ✓ 正确性（边界情况、错误处理、竞态条件）    │
│  ✓ 代码风格（命名、结构、可读性）                        │
│  ✓ 提供代码示例的可操作建议                    │
├─────────────────────────────────────────────────────────────────┤
│  升级版（连接工具时）                      │
│  + 版本控制：自动拉取 PR 差异                    │
│  + 项目追踪器：将发现的问题链接到工单                     │
│  + 知识库：检查团队编码规范           │
└─────────────────────────────────────────────────────────────────┘
```

## 审查维度

### 安全性
- SQL 注入、XSS、CSRF
- 认证和授权缺陷
- 代码中的密钥或凭证
- 不安全的反序列化
- 路径遍历
- SSRF

### 性能
- N+1 查询
- 不必要的内存分配
- 算法复杂度（热点路径中的 O(n²)）
- 缺少数据库索引
- 无界查询或循环
- 资源泄漏

### 正确性
- 边界情况（空输入、null、溢出）
- 竞态条件和并发问题
- 错误处理和传播
- 误判错误
- 类型安全

### 可维护性
- 命名清晰
- 单一职责
- 重复代码
- 测试覆盖率
- 非明显逻辑的文档
