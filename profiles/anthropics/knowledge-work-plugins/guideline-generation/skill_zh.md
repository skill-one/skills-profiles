# 指南生成

从任何组合的来源生成全面、适用于大型语言模型的品牌声音指南——品牌文件、销售通话记录、发现报告或直接用户输入。将原始材料转化为结构化、可执行指南，并附带置信度评分和开放性问题。

## 输入

接受任何组合：
- **发现报告**（来自发现品牌技能，结构化、预筛选）
- **品牌文件**（上传或来自连接平台，PDF、PPTX、DOCX、MD、TXT）
- **对话记录**（来自 Gong、Granola、手动上传或 Notion 会议笔记）
- **直接用户输入**（关于其品牌声音和价值观）

当提供发现报告时，将其作为主要输入——来源已预筛选和排序。根据需要补充额外分析。

## 生成工作流程

### 1. 识别和分类来源

确定用户提供了什么。如果没有来源可用：
- 检查是否在先前的 `/brand-voice:discover-brand` 运行中存在发现报告
- 检查 `.claude/brand-voice.local.md` 以查找已知品牌材料位置
- 建议先运行发现：`/brand-voice:discover-brand`

### 2. 处理来源

**对于文档：** 委托给文档分析代理进行深度解析。提取声音属性、信息主题、术语、语气指导和示例。

**对于记录：** 委托给对话分析代理进行模式识别。提取隐含的声音属性、成功的语言模式、上下文中的语气和反模式。

**对于发现报告：** 提取预筛选来源、冲突和空白。直接使用排序后的来源。

### 3. 合并成指南

将所有发现合并到统一指南文档中，遵循 `references/guideline-template.md` 中的模板。关键部分：

**"我们是谁 / 我们不是谁" 表格**——核心品牌身份锚点：

| 我们是谁 | 我们不是谁 |
|--------|------------|
| [属性——例如，"自信"] | [反例——例如，"傲慢"] |
| [属性——例如，"平易近人"] | [反例——例如，"随意或粗心"] |

从来源中最一致的模式中推导属性。每行应有支持证据。

**声音常数与语气灵活**——阐明什么是固定的，什么是可变的：
- **声音** = 个性、价值观、"我们是谁 / 我们不是谁"——所有内容中都保持不变
- **语气** = 正式性、能量、技术深度——根据上下文变化

**按上下文划分的语气矩阵：**

| 上下文 | 正式性 | 能量 | 技术深度 | 示例 |
|---------|-----------|--------|-----------------|---------|
| 冷启动 | 中等 | 高 | 低 | "[示例短语]" |
| 企业提案 | 高 | 中等 | 高 | "[示例短语]" |
| 社交媒体 | 低 | 高 | 低 | "[示例短语]" |

### 4. 分配置信度评分

使用 `references/confidence-scoring.md` 中的方法对每个部分进行评分：
- **高置信度**：3个或更多相互印证的来源，找到明确指导
- **中等置信度**：1-2个来源，或从模式中推断
- **低置信度**：单个来源、推断或冲突数据

### 5. 提出开放性问题

为任何无法解决的歧义生成开放性问题：

```markdown
## 需团队讨论的开放性问题

### 高优先级（阻止指南完成）
1. **[问题标题]**
   - 发现内容：[冲突或不完整信息]
   - 代理建议：[带推理的推荐解决方案]
   - 需要您：[需要的具体决策或确认]
```

每个开放性问题必须包含代理建议。将歧义转化为"确认或覆盖"——绝不走到死胡同。

### 6. 质量检查

在展示前，通过质量保证代理（定义在 `agents/quality-assurance.md`）进行验证：
- 所有主要部分已填充（如果来源支持，包括品牌个性和内容示例）
- 至少有3个带证据的声音属性
- "我们是谁 / 我们不是谁" 表格有4+行
- 语气矩阵覆盖至少3个上下文
- 每个部分分配了置信度评分
- 所有提取元素都有来源归因
- 未暴露 PII
- 开放性问题包含建议

### 7. 展示并提供下一步操作

总结关键发现：
- 生成的总部分数及置信度分解
- 最强的声音属性和最有效的信息
- 开放性问题数量（如有）

### 8. 保存以供未来会话使用

默认保存位置是用户工作文件夹内的 `.claude/brand-voice-guidelines.md`。

**重要提示：** 代理的工作目录可能不是用户的项目根目录（尤其是在 Cowork 中，插件从插件缓存目录运行）。始终相对于用户的工作文件夹解析路径，而不是当前工作目录。如果没有设置工作文件夹，则跳过文件保存，并告知用户指南仅在本次对话中可用。

1. **解析保存路径。** 文件必须保存到用户工作文件夹内的 `.claude/brand-voice-guidelines.md`。在写入前确认工作文件夹路径。
2. **检查该路径下是否已存在指南**
3. **如果存在，存档旧版本：** 将现有文件重命名为 `brand-voice-guidelines-YYYY-MM-DD.md`（使用当前日期）在同一目录下
4. **保存新指南** 到用户工作文件夹内的 `.claude/brand-voice-guidelines.md`
5. **向用户确认** 带有完整绝对路径："指南保存到 `<完整路径>`。`/brand-voice:enforce-voice` 将在未来的会话中自动找到它们。"

指南也存在于本次对话中，因此 `/brand-voice:enforce-voice` 可以立即使用它们，无需从文件加载。

保存后，提供：
1. 按部分逐个讲解指南
2. 开始使用 `/brand-voice:enforce-voice` 创建内容
3. 解决开放性问题

## 隐私和安全

在整个生成工作流程中强制执行这些隐私约束，而不仅限于输出时：
- 从所有示例中删除客户姓名和联系信息
- 如果要求，对记录摘录中的公司名称进行匿名化
- 标记处理过程中检测到的任何敏感信息
