# 客户心声

## 快速入门

询问：*"本月客户感觉如何？*"

Claude 会提取过去 30 天内的争议、工单、邮件线程和 Intercom 对话，将其归纳为 3-5 个主题，并提供包含具体证据的“本周执行这三件事”的行动清单。

若要包含 Google/Yelp 评论，可在触发后粘贴，或说“我有一些评论要添加。”

## 工作流程

1. **设置日期范围。** 默认：过去 30 天。如果用户指定了范围，则使用该范围。

2. **提取 PayPal 争议。** 获取窗口期内打开的争议。如果 PayPal API 返回速率限制错误，则跳过并添加 `PayPal: 速率限制 — 未包含` 到来源部分。不要重试；不要报错。有关速率限制模式，请参阅 [reference/gotchas.md](reference/gotchas.md)。

3. **提取 HubSpot 工单和反馈。** 获取开放和最近关闭的工单。如果工单数量为 0，则记录 `HubSpot 工单：0` 并继续 — 不要显示警告。

4. **提取 Gmail 邮件线程。** 搜索窗口期内包含以下关键词的邮件线程：`退款 取消 不满 问题 问题 失望 沮丧 破损 迟到 慢 错误 缺失`。提取每条线程的主题行和 1-2 句节选内容。

5. **提取 Intercom 对话。** 调用 `search_conversations` 获取开放和最近关闭的对话。然后对返回的每个对话 ID 调用 `get_conversation` 以访问完整的 `conversation_parts`。提取 `author.type === 'user'` 的部分 — 这些是客户消息。排除 `author.type` 为 `admin` 或 `bot` 的部分。

6. **接受粘贴的评论（可选）。** 如果用户粘贴了 Google 或 Yelp 评论文本，则将其包含在来源池中并标记为 `[评论]`。无需连接器。

7. **提取主题。** 将所有证据归纳为 3-5 个重复出现的主题。每个主题必须包含：
   - 一个一句话的标签（例如，“运输延迟导致重复投诉”）
   - 2-3 个带来源标签的逐字引用：`[PayPal]`、`[HubSpot]`、`[Gmail]`、`[Intercom]` 或 `[评论]`
   - 信号计数（有多少项涉及该主题）

   逐字引用是必须的 — 不要意译。有关逐字引用的反模式，请参阅 [reference/gotchas.md](reference/gotchas.md)。

8. **生成“本周执行这三件事”清单。** 按信号计数对主题进行排序。选择前 3 个，并为每个主题写一个具体、可由负责人执行的一步。格式为编号清单。

9. **交付报告。** 按以下顺序结构化输出：
   - **标题** — H2 标签，包含“客户心声”和日期范围。
   - **提取的来源** — 带有每个来源信号计数的编号列表（PayPal 争议、HubSpot 工单、Gmail 邮件线程、Intercom 对话、粘贴的评论）。注明任何被速率限制跳过的来源。
   - **主题** — 对每个主题，显示加粗的编号主题标签和信号计数，随后是两个逐字引用，每个引用都标明来源。
   - **本周执行这三件事** — 三个具体、可由负责人执行的一步的编号清单，每个步骤都与一个顶级主题相关联。

   完整的工作示例，请参阅 [reference/examples/example-report.md](reference/examples/example-report.md)。

## 审批门槛

此技能为 **只读** — 它不会发布、发送、回复或修改任何记录。无需审批门槛。
