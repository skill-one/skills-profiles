# /explore-data - 分析和探索数据集

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

为表格或上传的文件生成全面的数据分析报告。在深入分析之前，了解其结构、质量和模式。

## 使用方法

```
/explore-data <table_name or file>
```

## 工作流程

### 1. 访问数据

**如果已连接数据仓库 MCP 服务器：**

1. 解析表名（处理模式前缀，如果模糊则建议匹配）
2. 查询表元数据：列名、类型、如果可用则提供描述
3. 对实时数据运行分析查询

**如果提供文件（CSV、Excel、Parquet、JSON）：**

1. 读取文件并加载到工作数据集中
2. 从数据中推断列类型

**如果以上都不满足：**

1. 提示用户提供表名（其仓库已连接）或上传文件
2. 如果他们描述了表模式，提供有关运行哪些分析查询的指导

### 2. 理解结构

在分析任何数据之前，了解其结构：

**表级问题：**
- 行数和列数是多少？
- 粒度是什么（每行代表什么）？
- 主键是什么？是否唯一？
- 数据最后更新时间是什么时候？
- 数据回溯时间有多长？

**列分类** — 将每列分类为以下之一：
- **标识符**：唯一键、外键、实体 ID
- **维度**：用于分组/筛选的分类属性（状态、类型、区域、类别）
- **指标**：用于度量的定量值（收入、计数、持续时间、得分）
- **时间**：日期和时间戳（创建时间、更新时间、事件日期）
- **文本**：自由文本字段（描述、备注、名称）
- **布尔值**：真/假标志
- **结构**：JSON、数组、嵌套结构

### 3. 生成数据分析报告

运行以下分析检查：

**表级指标：**
- 总行数
- 列数和类型明细
- 大致表大小（如果元数据中可用）
- 日期范围覆盖（日期列的最小/最大值）

**所有列：**
- 空值计数和空值率
- 唯一值计数和基数比率（唯一值 / 总数）
- 最常见值（前 5-10 个及频率）
- 最不常见值（底部 5 个以发现异常）

**数值列（指标）：**
```
最小值、最大值、平均值、中位数（p50）
标准差
百分位数：p1、p5、p25、p75、p95、p99
零值计数
负值计数（如果意外）
```

**字符串列（维度、文本）：**
```
最小长度、最大长度、平均长度
空字符串计数
模式分析（值是否遵循格式？）
大小写一致性（全部大写、全部小写、混合？）
首尾空格计数
```

**日期/时间戳列：**
```
最小日期、最大日期
空日期
意外未来日期（如果存在）
按月/周分布
时间序列中的空白
```

**布尔列：**
```
真值计数、假值计数、空值计数
真值率
```

**以干净的摘要表格形式呈现分析报告**，按列类型分组（维度、指标、日期、ID）。

### 4. 识别数据质量问题

应用以下质量评估框架。标记潜在问题：

- **高空值率**：空值率 >5% 的列（警告），空值率 >20% 的列（警报）
- **低基数意外**：本应高基数的列但不是（例如，“user_id”只有 50 个唯一值）
- **高基数意外**：本应为分类但唯一值过多的列
- **可疑值**：预期为正但出现负数、历史数据中存在未来日期、明显的占位符值（例如，“N/A”、“TBD”、“test”、“999999”）
- **重复检测**：检查是否存在自然键以及是否存在重复
- **分布偏斜**：可能影响平均值的极偏斜数值分布
- **编码问题**：分类字段中混合大小写、尾随空格、格式不一致

### 5. 发现关系和模式

在分析单个列之后：

- **外键候选**：可能链接到其他表的 ID 列
- **层次结构**：形成自然下钻路径的列（国家 > 州 > 城市）
- **相关性**：一起变化的数值列
- **衍生列**：似乎由其他列计算出的列
- **冗余列**：包含相同或几乎相同信息的列

### 6. 建议有趣的维度和指标

根据列分析报告，建议：

- **最佳维度列**：用于切片数据（具有合理基数的分类列，3-50 个值）
- **关键指标列**：用于度量（具有有意义分布的数值列）
- **时间列**：适合趋势分析
- **自然分组**或数据中的层次结构
- **潜在连接键**：链接到其他表的 ID 列、外键

### 7. 推荐后续分析

建议用户运行 3-5 个具体分析：

- "按[time_column]分组，按[dimension]分析[metric]的趋势"
- "对[skewed_column]进行分布深度分析以了解异常值"
- "对[problematic_column]进行数据质量调查"
- "分析[metric_a]和[metric_b]之间的相关性"
- "使用[date_column]和[status_column]进行群组分析"

## 质量评估框架

### 完整性评分

对每列进行评分：
- **完整**（>99% 非空）：绿色
- **基本完整**（95-99%）：黄色 —— 调查空值
- **不完整**（80-95%）：橙色 —— 了解原因及是否重要
- **稀疏**（<80%）：红色 —— 可能需要插补才能使用

### 一致性检查

查找：
- **值格式不一致**：同一概念的不同表示方式（"USA"、"US"、"United States"、"us"）
- **类型不一致**：数值存储为字符串，日期格式多样
- **引用完整性**：外键不匹配任何父记录
- **业务规则违规**：负数量、结束日期早于开始日期、百分比 >100
- **跨列一致性**：状态 = "completed" 但 completed_at 为空

### 准确性指标

提示准确性问题红旗：
- **占位符值**：0、-1、999999、"N/A"、"TBD"、"test"、"xxx"
- **默认值**：单个值频率异常高
- **过时数据**：活跃系统中 updated_at 没有最近更新
- **不可能值**：年龄 >150、远未来日期、负持续时间
- **四舍五入偏差**：所有值以 0 或 5 结尾（暗示估计而非测量）

### 及时性评估

- 表格最后更新时间是什么时候？
- 预期更新频率是什么？
- 事件时间与加载时间之间是否存在延迟？
- 时间序列中是否存在空白？

## 模式发现技术

### 分布分析

对数值列，描述分布：
- **正态**：平均值和中位数接近，钟形
- **右偏**：高值的长尾（常见于收入、会话持续时间）
- **左偏**：低值的长尾（较少见）
- **双峰**：两个峰值（暗示两个不同的人口）
- **幂律**：少数非常大的值，许多小值（用户活动的常见情况）
- **均匀**：范围内频率大致相等（通常是合成或随机）

### 时间模式

对时间序列数据，查找：
- **趋势**：持续向上或向下的移动
- **季节性**：重复模式（每周、每月、每季度、每年）
- **星期几效应**：工作日与周末差异
- **假日效应**：已知假日周围的下降或峰值
- **变化点**：水平或趋势的突然变化
- **异常值**：打破模式的单个数据点

### 分段发现

通过以下方式识别自然分段：
- 查找具有 3-20 个唯一值的分类列
- 比较不同分段值上的指标分布
- 查找行为差异显著的分段
- 测试分段是否同质或包含子分段

### 相关性探索

在数值列之间：
- 计算所有指标对的相关矩阵
- 标记强相关性（|r| > 0.7）以供调查
- 注意：相关性不等于因果关系——明确标记这一点
- 检查非线性关系（例如，二次方、对数）

## 模式理解和文档

### 模式文档模板

为团队使用而记录数据集时：

```markdown
## 表：[schema.table_name]

**描述**：[该表代表什么]
**粒度**：[每行代表...]
**主键**：[列]
**行数**：[近似值，带日期]
**更新频率**：[实时/每小时/每天/每周]
**负责人**：[团队或负责人]

### 关键列

| 列 | 类型 | 描述 | 示例值 | 备注 |
|----|------|------|--------|------|
| user_id | STRING | 唯一用户标识符 | "usr_abc123" | FK to users.id |
| event_type | STRING | 事件类型 | "click"、"view"、"purchase" | 15 个唯一值 |
| revenue | DECIMAL | 美元交易收入 | 29.99、149.00 | 非购买事件为空 |
| created_at | TIMESTAMP | 事件发生时间 | 2024-01-15 14:23:01 | 该列分区 |

### 关系
- 与 `users` 通过 `user_id` 连接
- 与 `products` 通过 `product_id` 连接
- `event_details` 的父表（事件 ID 一对多）

### 已知问题
- [列出任何已知数据质量问题]
- [分析师的注意事项]

### 常见查询模式
- [该表的典型用例]
```

### 模式探索查询

连接到数据仓库时，使用这些模式发现模式：

```sql
-- 列出模式中的所有表（PostgreSQL）
SELECT table_name, table_type
FROM information_schema.tables
WHERE table_schema = 'public'
ORDER BY table_name;

-- 列详情（PostgreSQL）
SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_name = 'my_table'
ORDER BY ordinal_position;

-- 表大小（PostgreSQL）
SELECT relname, pg_size_pretty(pg_total_relation_size(relid))
FROM pg_catalog.pg_statio_user_tables
ORDER BY pg_total_relation_size(relid) DESC;

-- 所有表的行数（通用模式）
-- 每个表运行：SELECT COUNT(*) FROM table_name
```

### 血缘和依赖

探索不熟悉的数据环境时：

1. 从“输出”表开始（报告或仪表板消费的表）
2. 向上游追溯：哪些表输入到它们？
3. 识别原始/暂存/星型层
4. 从原始数据到分析表映射转换链
5. 记录数据在哪里被丰富、过滤或聚合

## 小贴士

- 对于非常大的表（1000 万+ 行），分析查询默认使用采样——如果需要精确计数请说明
- 首次探索新数据集时，此命令可让你在编写特定查询前了解概况
- 质量标志是启发式的——并非每个标志都是真实问题，但每个都值得快速查看
