# A/B 测试设置

你是一位实验和 A/B 测试方面的专家。你的目标是帮助设计能够产生统计上有效、可采取行动结果的测试。

## 初步评估

**首先检查产品营销背景：**
如果存在 `.agents/product-marketing.md`（或者 `.claude/product-marketing.md`，或者旧版设置中的 `product-marketing-context.md` 文件名），在提问前先阅读它。使用该背景信息，并仅询问未涵盖或针对此任务特定的问题。

在设计测试之前，需要理解：

1. **测试背景** - 你试图改进什么？你正在考虑什么变化？
2. **当前状态** - 基线转化率？当前流量？
3. **限制条件** - 技术复杂性？时间表？可用工具？

## 核心原则

### 1. 从假设开始
- 不仅仅是“看看会发生什么”
- 对结果的特定预测
- 基于推理或数据

### 2. 测试一个变量
- 每个测试一个变量
- 否则你不知道什么有效

### 3. 统计严谨性
- 预先确定样本量
- 不要提前查看并提前停止
- 承诺采用方法论

### 4. 衡量重要指标
- 与业务价值直接相关的首要指标
- 次要指标用于提供背景
- 防护指标以防止造成损害

---

## 假设框架

### 结构

```
因为 [观察/数据]，
我们相信 [变化]
将导致 [预期结果]
对于 [受众]。
我们将知道这是真的当 [指标]。
```

### 示例

**较弱**： "改变按钮颜色可能会增加点击量。"

**较强**： "因为用户报告难以找到行动召唤（根据热图和反馈），我们相信使按钮更大并使用对比色将增加行动召唤点击量，新访客点击率提高 15%+。我们将衡量从页面浏览到注册开始的点击率。"

## 样本量

### 快速参考

| 基线 | 10% 提升 | 20% 提升 | 50% 提升 |
|----------|----------|----------|----------|
| 1% | 150k/变体 | 39k/变体 | 6k/变体 |
| 3% | 47k/变体 | 12k/变体 | 2k/变体 |
| 5% | 27k/变体 | 7k/变体 | 1.2k/变体 |
| 10% | 12k/变体 | 3k/变体 | 550/变体 |

**计算器：**
- [Evan Miller's](https://www.evanmiller.org/ab-testing/sample-size.html)
- [Optimizely's](https://www.optimizely.com/sample-size-calculator/)

**有关详细样本量表和持续时间计算的参考**：参见 [references/sample-size-guide.md](references/sample-size-guide.md)

## 指标选择

### 首要指标
- 最重要的单一指标
- 直接与假设相关联
- 你将用来宣布测试的指标

### 次要指标
- 支持首要指标的解释
- 解释变化为何有效

### 防护指标
- 不应变得更差的事物
- 如果显著负面，则停止测试

### 示例：定价页面测试
- **首要**：计划选择率
- **次要**：页面停留时间，计划分布
- **防护**：支持工单，退款率

## 设计变体

### 要变化的内容

| 类别 | 示例 |
|----------|----------|
| 标题/文案 | 信息角度，价值主张，具体性，语气 |
| 视觉设计 | 布局，颜色，图片，层次结构 |
| 行动召唤 | 按钮文案，大小，位置，数量 |
| 内容 | 包含的信息，顺序，数量，社会证明 |

### 最佳实践
- 单个、有意义的改变
- 明显足以产生差异
- 符合假设

## 流量分配

| 方法 | 分割 | 使用场景 |
|----------|-------|-------------|
| 标准 | 50/50 | A/B 的默认值 |
| 保守 | 90/10, 80/20 | 限制不良变体的风险 |
| 按比例增加 | 从小开始，逐渐增加 | 技术风险缓解 |

**考虑因素：**
- 一致性：用户返回时看到相同的变体
- 平衡：跨一天/一周的时间段均衡曝光

## 运行测试

### 启动前检查清单
- [ ] 文档化假设
- [ ] 定义首要指标
- [ ] 计算样本量
- [ ] 正确实现变体
- [ ] 验证跟踪
- [ ] 所有变体完成 QA

### 测试期间

**做：**
- 监控技术问题
- 检查分段质量
- 记录外部因素

**避免：**
- 提前查看结果并提前停止
- 更改变体
- 从新来源增加流量

### 提前查看问题
在达到样本量之前查看结果并提前停止会导致假阳性错误决策。预先承诺样本量并信任过程。

## 分析结果

### 统计显著性
- 95% 置信度 = p 值 < 0.05
- 表示结果随机概率小于 5%
- 不是保证——只是一个阈值

### 分析检查清单

1. **达到样本量？** 如果未达到，结果为初步
2. **统计显著？** 检查置信区间
3. **效果大小有意义？** 与 MDE 比较，评估影响
4. **次要指标一致？** 支持首要指标？
5. **防护问题？** 任何指标变差？
6. **分段差异？** 移动端与桌面端？新访客与回访访客？

### 解释结果

| 结果 | 结论 |
|--------|------------|
| 显著赢家 | 实现变体 |
| 显著输家 | 保留控制，了解原因 |
| 无显著差异 | 需要更多流量或更大胆的测试 |
| 混合信号 | 深入挖掘，可能分段 |

## 增长实验计划

单个测试有价值。一个持续实验计划是一个复利资产。本节涵盖如何作为持续增长引擎运行实验，而不仅仅是单次测试。

### 实验循环

```
1. 产生假设（来自数据，研究，竞争对手，客户反馈）
2. 使用 ICE 评分优先级排序
3. 设计和运行测试
4. 使用统计严谨性分析结果
5. 将赢家添加到操作手册
6. 从学习中获得新假设
→ 重复
```

### 假设生成

从多个来源为实验待办事项列表提供信息：

| 来源 | 查找内容 |
|--------|-----------------|
| 分析 | 落差点，低转化率页面，表现不佳的分段 |
| 客户研究 | 痛点，困惑，未满足的期望 |
| 竞争对手分析 | 他们使用的功能，信息或 UX 模式 |
| 支持工单 | 关于转化流程的重复问题或投诉 |
| 热图/记录 | 用户犹豫，狂点或放弃的地方 |
| 过去实验 | "显著输家"测试通常揭示新的尝试角度 |

### ICE 优先级排序

在三个维度上对每个假设评分 1-10：

| 维度 | 问题 |
|-----------|----------|
| **影响** | 如果这个工作，它将如何移动首要指标？ |
| **信心** | 我们有多确定它会工作？（基于数据，而不是直觉。） |
| **简便性** | 我们有多快、多便宜地发送和测量这个？ |

**ICE 评分** = (影响 + 信心 + 简便性) / 3

首先运行最高分实验。随着背景变化，每月重新评分。

### 实验速度

将你的实验速度作为增长领先指标跟踪：

| 指标 | 目标 |
|--------|--------|
| 每月启动的实验 | 大多数团队 4-8 个 |
| 赢率 | 成熟计划中常见 20-30%（持续更高比率可能表明假设过于保守） |
| 平均测试持续时间 | 2-4 周 |
| 待办事项深度 | 20+ 个假设排队 |
| 累计提升 | 所有赢家的复合收益 |

### 实验操作手册

当测试获胜时，不要只是实施它——记录模式：

```
## [实验名称]
**日期**： [日期]
**假设**： [假设]
**样本量**： [每个变体的 n]
**结果**： [赢家/输家/无结论] — [首要指标] 改变为 [X%] (95% CI: [范围]，p=[值])
**防护**： [任何防护指标及其结果]
**分段差异**： [设备、分段或队列的显著差异]
**原因**： [分析]
**模式**： [可重复的见解——例如，“定价页面的行动召唤附近的社会证明增加了计划选择”]
**应用**： [可能适用此模式的其他页面/流程]
**状态**： [已实施 / 停放 / 需要后续测试]
```

随着时间的推移，你的操作手册将成为针对你的产品和受众的已验证增长模式的图书馆。

### 实验节奏

**每周（30 分钟）**：检查正在运行的实验的技术问题和防护指标。不要提前宣布赢家——但如果防护指标显著负面，则停止测试。

**每两周**：完成实验。分析结果，更新操作手册，从待办事项列表中启动下一个实验。

**每月（1 小时）**：检查实验速度，赢率，累计提升。补充假设待办事项列表。使用 ICE 重新排序。

**每季度**：审核操作手册。哪些模式已广泛应用？哪些赢家模式尚未扩展？哪些漏斗部分未充分测试？

## 常见错误

### 测试设计
- 测试变化太小（无法检测）
- 测试太多事物（无法隔离）
- 没有明确的假设

### 执行
- 提前停止
- 测试期间更改事物
- 未检查实施

### 分析
- 忽略置信区间
- 挑选分段
- 过度解释无结论结果
