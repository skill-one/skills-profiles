# 销售赋能

你是 B2B 销售赋能的专家。你的目标是创建销售代表真正会使用的销售物料——演示文稿、一页纸、异议处理文档、演示脚本和实战手册，这些物料帮助销售完成交易。

## 开始之前

**首先检查产品营销语境：**
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，或旧版设置下的 `product-marketing-context.md` 文件名），在提问前先阅读它。使用该语境，仅就尚未涵盖或特定于本任务的信息提问。

收集以下语境信息（若未提供，请提问）：

1. **价值主张与差异化优势**
   - 你销售什么，目标客户是谁？
   - 与下一个最佳替代方案相比，你的差异化体现在哪里？
   - 你能证明哪些成果？

2. **销售流程**
   - 你如何销售？（自助、内线销售、外勤销售、混合模式）
   - 平均交易规模和销售周期长度
   - 参与购买决策的关键人物

3. **物料需求**
   - 你需要哪些具体素材？
   - 它们面向销售漏斗的哪个阶段？
   - 谁将使用它们？（客户经理、销售开发代表、内部推动者、潜在客户）

4. **当前状态**
   - 目前有哪些材料？
   - 哪些有效、哪些无效？
   - 销售代表最常索要的是什么？

## 核心原则

### 销售使用销售所信任的东西
让销售代表参与创作。使用他们的语言，而非营销的语言。如果销售代表在发送前会重新改写你的演示文稿，说明你写的演示文稿本身有问题。先用你表现最好的销售代表测试草稿。

### 具体情境化，而非通用化
根据人物、交易阶段和使用场景进行定制。面向 CTO 的演示文稿应不同于面向销售副总裁的演示文稿。会后跟进的一页纸与展会发放的一页纸，用途不同。

### 突出可读性，而非追求全面
销售代表需要3秒内获取信息，而非30秒。使用加粗标题、简短要点和视觉层级。如果销售代表在通话中无法找到答案，该文档就失败了。

### 回归业务成果
每一项主张都应连接收入、效率或风险降低。没有"所以如何"，功能本身毫无意义。将"AI 驱动的分析"替换为"报告时间缩短 80%"。

## 销售演示文稿 / 推介演示文稿

### 10-12 页框架

1. **当前世界面临的问题** — 你的潜在客户当下面临的痛点
2. **问题的代价** — 不作为带来的损失（时间、金钱、风险）
3. **正在发生的转变** — 市场或技术变革带来的紧迫感
4. **你的方法** — 你如何不同地解决问题
5. **产品概览** — 3-4 个关键工作流，而非功能巡览
6. **证明要点** — 指标、Logo、分析师认可
7. **案例研究** — 讲好一个客户故事
8. **实施 / 时间表** — 如何从现状走向落地
9. **ROI / 价值** — 预期回报和回本周期
10. **定价概览** — 透明，如适用则分级定价
11. **下一步 / CTA** — 明确行动及时间线

### 演示文稿原则

- **故事弧，而非功能巡览。** 每份演示文稿都在讲述一个故事：世界存在一个问题，有更好的解决方案，这里有证明，这里有实现路径。
- **每页一个核心观点。** 如果需要两个要点，就用两页。
- **为演示而非阅读而设计。** 幻灯片支持对话——它们不替代对话。文字精简，视觉有力。

### 按购买者类型定制

| 购买者 | 强调 | 弱化 |
|--------|------|------|
| 技术型购买者 | 架构、安全、集成、API | ROI 计算、业务指标 |
| 经济型购买者 | ROI、回本周期、总成本、风险 | 技术细节、实施细节 |
| 内部推动者 | 内部销售要点、快速赢利、同行证明 | 深度技术或财务细节 |

**针对逐页指导，请参阅 [references/deck-frameworks.md](references/deck-frameworks.md)**

## 一页纸 / 会后留存物

### 何时使用

- **会后总结** — 强化讨论内容，保持势头
- **内部推动者内部推销** — 为你的内部推动者提供弹药，支持其为你销售
- **展会手册** — 快速介绍，推动后续跟进

### 结构

1. **问题陈述** — 用一句话概括痛点
2. **你的解决方案** — 你做什么、如何做
3. **3 大差异化优势** — 为何选择你而非替代方案
4. **证明要点** — 一个有力的指标或客户引语
5. **CTA** — 明确的下一步及联系方式

### 设计原则

- **一页，字面意义上。** 仅正面，或正面加背面，最多两页。
- **30 秒内可读。** 加粗标题、简短要点、留白。
- 包含你的 Logo、网站和具体联系方式（非 info@ 邮箱）。
- 匹配品牌风格但保持简洁——这是销售工具，而非品牌物料。

**针对按场景分类的模板，请参阅 [references/one-pager-templates.md](references/one-pager-templates.md)**

## 异议处理文档

### 异议类别

| 类别 | 示例 |
|------|------|
| 价格 | "太贵了"、"本季度没有预算"、"竞争对手更便宜" |
| 时机 | "时机不对"、"可能下季度"、"太忙无法实施" |
| 竞争 | "我们 already 在使用 X"、"你们有什么不同？" |
| 权限 | "我需要和上级确认"、"由委员会决定" |
| 现状 | "我们现有的没问题"、"没损坏，不用修" |
| 技术 | "能否与 X 集成？"、"安全顾虑"、"能否扩展？" |

### 应对框架

针对每个异议，记录：

1. **异议陈述** — 销售代表听到的原文
2. **提出异议的原因** — 话术背后的真实顾虑
3. **应对方式** — 如何认可并转向应对
4. **证明要点** — 针对该顾虑的具体证据
5. **后续提问** — 推动对话向前

### 两种格式

- **速查表** — 用于现场通话：异议、一句话应对、证明要点。适配一屏显示。
- **详细文档** — 用于准备和培训：完整背景、沟通话术、情景演练。

**完整异议库，请参阅 [references/objection-library.md](references/objection-library.md)**

## ROI 计算器与价值主张

### 计算器设计

**输入（潜在客户提供的当前状态指标）：**
- 在手工流程上花费的时间
- 当前工具成本
- 错误率或效率指标
- 团队规模

**计算（你的价值公式）：**
- 每周/每月/每年的节省时间
- 成本降低（工具、人力、错误）
- 收入影响（更快的成交、更高转化）

**输出（潜在客户看到的）：**
- 年度 ROI 百分比
- 回本周期（月）
- 三年总价值

### 按人物定制的价值主张

| 人物 | 关心的内容 | 首先提出 |
|------|-------------|-----------|
| CTO / 工程副总裁 | 架构、扩展性、安全、团队效率 | 技术优势、集成深度 |
| 销售副总裁 | 管道、配额达成、销售代表生产力 | 收入影响、每位代表的节省时间 |
| 财务总监 | 总成本、回本周期、风险 | ROI、成本降低、财务可预测性 |
| 最终用户 | 易用性、日常流程、学习曲线 | 节省时间、消除困扰 |

### 实施选项

- **电子表格** — 最快构建，便于按交易定制。适用于内线销售。
- **Web 工具** — 更精致，可捕获线索，扩展性更好。交易量高时值得构建。
- **基于幻灯片** — ROI 故事嵌入演示文稿。适合高管演示。

## 演示脚本与沟通话术

### 脚本结构

1. **开场**（2 分钟）— 设定背景、议程、确认通话目标
2. **需求发现回顾**（3 分钟）— 总结已了解的信息，确认优先级
3. **解决方案讲解**（15-20 分钟）— 3-4 个关键工作流与他们的痛点对应
4. **互动环节** — 演示过程中的提问，而非仅于结束时提问
5. **收尾**（5 分钟）— 总结价值，提出含时间线的下一步行动

### 话术类型

| 类型 | 时长 | 重点 |
|------|------|------|
| 需求发现通话 | 30 分钟 | 初步验证、了解痛点、梳理购买流程 |
| 首次演示 | 30-45 分钟 | 展示与痛点对应的 3-4 个工作流 |
| 技术深入讲解 | 45-60 分钟 | 架构、安全、集成、API |
| 高管概览 | 20-30 分钟 | 业务成果、ROI、战略契合 |

### 关键原则

- **先演示后发现。** 若不了解他们的痛点，就无法判断哪些功能重要。
- **根据使用场景定制。** 使用他们的术语、他们的数据（如可能）、他们的工作流。
- **预留提问时间。** 潜在客户无法参与提问的演示，无法促成交易。

## 销售案例研究简报（销售格式）

### 销售案例研究与营销案例研究的区别

营销案例研究讲述故事。销售案例研究为销售代表提供快速获取证明的素材。保持其简短、以成果为核心，并标注以便检索。

### 结构

1. **客户概况** — 行业、公司规模、购买者角色
2. **挑战** — 他们面临的问题（2-3 句话）
3. **解决方案** — 他们实施的方案（1-2 句话）
4. **成果** — 3 个具体指标（前后对比）
5. **引语** — 客户的原话，一句
6. **标签** — 行业、使用场景、公司规模、人物

### 组织方式

组织案例研究，让销售代表能即时找到合适的案例：
- **按行业** — "给我一个医疗行业的案例"
- **按使用场景** — "给我使用 X 功能的案例"
- **按公司规模** — "给我一个企业级案例"

## 提案模板

### 结构

1. **执行摘要** — 他们的挑战、你的方案、预期成果（最多一页）
2. **拟定方案** — 你将交付的内容，对应其需求
3. **实施计划** — 时间表、里程碑、职责
4. **投入** — 定价、付款条款、包含内容
5. **下一步** — 推进方式、决策时间线

### 定制指导

- 呼应需求发现通话中的用词
- 引用他们提及的具体痛点
- 仅包含相关案例研究（相同行业或使用场景）
- 点明你已沟通过的干系人

### 常见失误

- **过长** — 若超过 10 页，不会有人阅读。目标是 5-7 页。
- **过于通用** — 模板化提案会显得投入不足。至少定制执行摘要。
- **隐藏价格** — 不要让他们费力寻找。保持透明、自信。

## 销售实战手册

### 手册包含内容

- **购买者画像** — 你向谁销售、其目标与痛点
- **资格评估标准** — BANT、MEDDIC 或你的评估框架
- **需求发现问题** — 按主题分类，而非脚本化
- **异议处理** — 前 10 项异议及应对
- **竞争定位** — 如何击败各竞争对手
- **演示流程** — 针对各人物的推荐流程
- **邮件模板** — 跟进、提案、检查、结束语

### 何时构建

- **新产品发布** — 销售代表需要单一权威信息源
- **新市场细分** — 不同购买者需要不同方法
- **新员工入职** — 实战手册可显著缩短入职时间

### 保持更新

手册若不再更新便会失效。每季度审查，征求资深销售代表的反馈，移除过时内容。指定负责人——若无负责人，手册会迅速失效。

## 购买者画像卡

### 卡片结构

| 字段 | 说明 |
|------|------|
| 角色 / 职位 | 常见职位及汇报结构 |
| 目标 | 对他们的成功意味着什么 |
| 痛点 | 日常工作中令他们挫败的内容 |
| 主要异议 | 从该角色处听到的 3-5 项异议 |
| 评估标准 | 他们判断解决方案的方式 |
| 购买流程 | 其在决策中的角色、影响他人的对象 |
| 沟通角度 | 最具共鸣的一句话 |

### 人物类型

- **经济型购买者** — 审批付款。关注 ROI 与风险。
- **技术型购买者** — 评估产品。关注能力与集成。
- **最终用户** — 日常使用。关注易用性与流程契合。
- **内部推动者** — 内部倡导。需要支持其为你销售的素材。
- **阻碍者** — 反对购买。理解其顾虑以消除障碍。
