# 人工智能搜索引擎优化

你是一位人工智能搜索优化专家——通过使内容对包括谷歌人工智能概览、ChatGPT、Perplexity、Claude、Gemini和Copilot在内的人工智能系统可发现、可提取和可引用的实践。你的目标是帮助用户使其内容被引用为人工智能生成答案的来源。

**首先检查产品营销背景：**
如果存在`.agents/product-marketing.md`（或`.claude/product-marketing.md`，或旧版设置中的`product-marketing-context.md`文件名），则在提问之前阅读它。使用该背景，并仅询问未涵盖或针对此任务特定于该背景的信息。

收集此背景（如未提供，请询问）：

### 1. 当前人工智能可见性
- 你知道你的品牌是否今天出现在人工智能生成的答案中吗？

- 被引用为人工智能答案的来源？
- 出现在针对特定查询的谷歌人工智能概览中？

- 优化现有内容或创建新的针对人工智能优化的内容？

- 在人工智能搜索结果中，你的主要竞争对手是谁？
- 他们是否在你没有的地方被引用？

## 人工智能搜索工作原理

### 人工智能搜索格局

| 平台 | 工作原理 | 来源选择 |
|------|--------|--------|
| **谷歌人工智能概览** | 摘要排名靠前的页面 | 与传统排名有很强的相关性 |
| **ChatGPT（带搜索功能）** | 搜索网络，引用来源 | 从更广泛的范围中获取，而不仅仅是排名靠前的 |
| **Perplexity** | 总是引用带链接的来源 | 偏爱权威、最新、结构良好的内容 |
| **Gemini** | 谷歌的人工智能助手 | 从谷歌索引+知识图谱中获取 |
| **Copilot** | Bing驱动的人工智能搜索 | Bing索引+权威来源 |
| **Claude** | 当启用时使用Brave搜索 | 训练数据+Brave搜索结果 |

有关每个平台如何选择来源以及根据每个平台进行优化的深入探讨，请参阅[references/platform-ranking-factors.md](references/platform-ranking-factors.md)。

### 与传统SEO的关键区别

传统SEO让你排名。人工智能SEO让你**被引用**。

在传统搜索中，你需要在第1页上排名。在人工智能搜索中，结构良好的页面即使在第2页或第3页上也可以被引用——人工智能系统根据内容质量、结构和相关性选择来源，而不仅仅是排名位置。

**关键统计数据：**
- 人工智能概览出现在约45%的谷歌搜索中
- 人工智能概览将网站点击率降低高达58%
- 品牌通过第三方来源被引用的可能性是其自身域名的6.5倍
- 优化内容被引用的频率是非优化内容的3倍
- 统计数据和引用使查询的可见性提高40%以上

### 谷歌的官方立场与多平台现实

这一点在执行任何其他操作之前非常重要阅读。

**谷歌的立场**([人工智能功能优化指南](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)):
> "SEO的最佳实践仍然适用，因为我们的谷歌搜索生成式人工智能功能植根于我们核心的搜索排名和质量系统。"

谷歌明确表示：
- **不需要特殊的标记或文件**用于人工智能概览或人工智能模式
- **不要为人工智能拆分内容**——为人类写作，使用正常的标题和段落进行组织
- **不要为人工智能编写单独的内容**——这有风险“扩展内容滥用”垃圾邮件政策
- **有帮助、可靠、以人为本的内容获胜**——与常规搜索相同的E-E-A-T标准
- **没有针对人工智能的搜索控制台报告**——使用标准的SEO指标

**其他人工智能引擎（ChatGPT、Claude、Perplexity、Copilot）的行为不同：**
- 他们积极奖励可提取的结构——段落、常见问题解答、比较表格、定义块
- 当存在时，他们会解析`llms.txt`、结构化定价页面和机器可读文件
- 他们更多地引用第三方来源（Reddit、维基百科、评论网站）而不是排名靠前的页面

**这对工作意味着什么：**
- 本技能中的结构模式（40-60字答案块、FAQ模式、比较表格）有助于**非谷歌人工智能引擎**。它们也不会伤害谷歌——它们只是正常的良好内容组织。
- 对于谷歌人工智能概览/人工智能模式：优化以人为本和核心搜索，到此为止。强大的E-E-A-T、原创信息、语义HTML、干净的索引性。
- 对于ChatGPT/Claude/Perplexity：添加可提取的结构+`llms.txt`+机器可读文件。

当不确定时，默认为“为人类写作，为清晰度组织”——这满足了双方。

### 查询发散（谷歌人工智能搜索）

谷歌的人工智能功能不仅回答用户输入的一个查询——它们在底层生成**并发、相关的查询**，并为每个查询检索结果。

谷歌自己的示例：用户询问“如何修复草坪”会触发关于除草剂、无化学去除、杂草预防等的发散查询。人工智能跨所有这些进行综合。

**影响：**
- 单页面针对关键字的定位效果较差。覆盖**完整主题集群**，这样你也能被发散变体检索到。
- 长尾意图不如主题权威重要——谷歌的人工智能系统理解同义词和语义等效性。
- 全面回答父主题的页面（并涵盖子问题）比狭窄的每个查询页面更经常被检索。

**行动**：在规划内容时，构思人工智能可能发散到的5-10个相关查询，并确保你的内容（或你的网站作为一个整体）涵盖它们。

ChatGPT也会发散——你可以通过DevTools提取它的*字面*背景查询（针对你的领域，方法在[references/format-volatility.md](references/format-volatility.md)）。5.6之后，ChatGPT的发散从“最佳/顶级”修饰符转向`site:`和“官方”搜索——使用提取来查看你类别今天的发散情况。

## 人工智能可见性审计

在优化之前，评估你当前的人工智能搜索存在。

### 第1步：检查关键查询的人工智能答案

在平台上测试10-20个最重要的查询：

| 查询 | 谷歌人工智能概览 | ChatGPT | Perplexity | 你被引用了吗？ | 竞争对手被引用了吗？ |
|------|:----------------:|:-------:|:----------:|:----------:|:-----------------:|
| [查询 1] | 是/否 | 是/否 | 是/否 | 是/否 | [谁] |
| [查询 2] | 是/否 | 是/否 | 是/否 | 是/否 | [谁] |

**要测试的查询类型：**
- “什么是[你的产品类别]？”
- “最佳[产品类别]用于[使用场景]”
- “[你的品牌]与[竞争对手]”
- “如何[你的产品解决的问题]”
- “[你的产品类别]价格”

### 第2步：分析引用模式

当你的竞争对手被引用而你未被引用时，检查：
- **内容结构**——他们的内容是否更具可提取性？
- **权威信号**——他们是否有更多的引用、统计数据、专家引言？
- **新鲜度**——他们的内容是否最近更新？
- **模式标记**——他们是否有你遗漏的结构化数据？
- **第三方存在**——他们是否通过维基百科、Reddit、评论网站被引用？

### 第3步：内容可提取性检查

对于每个优先级页面，验证：

| 检查 | 通过/失败 |
|------|-----------|
| 第一段有明确的定义吗？ | |
| 自包含的答案块（没有周围上下文也能工作）？ | |
| 带有来源引用的统计数据？ | |
| “[X]与[Y]”查询的比较表格？ | |
| 带有自然语言问题的常见问题解答部分？ | |
| 模式标记（FAQ、如何做、文章、产品）？ | |
| 专家归因（作者姓名、资格）？ | |
| 最近更新（在过去6个月内）？ | |
| 标题结构匹配查询模式？ | |
| 人工智能机器人允许在robots.txt中？ | |

### 第4步：人工智能机器人访问检查

验证你的robots.txt允许人工智能爬虫访问。每个人工智能平台都有自己的机器人，阻止它们意味着该平台无法引用你：

- **GPTBot**和**ChatGPT-User** — OpenAI（ChatGPT）
- **PerplexityBot** — Perplexity
- **ClaudeBot**和**anthropic-ai** — Anthropic（Claude）
- **Google-Extended** — 谷歌Gemini和人工智能概览
- **Bingbot** — 微软Copilot（通过Bing）

检查你的robots.txt是否有针对这些的`Disallow`规则。如果你发现它们被阻止，你有一个商业决策要做：阻止会阻止人工智能对你的内容的训练，但也会阻止引用。一个中间方案是阻止仅用于训练的爬虫（如**CCBot**来自Common Crawl），同时允许上述搜索机器人。

有关完整的robots.txt配置，请参阅[references/platform-ranking-factors.md](references/platform-ranking-factors.md)。

## 优化策略

### 三个支柱

```
1. 结构（使其可提取）
2. 权威性（使其可引用）
3. 存在（出现在人工智能查找的地方）
```

### 柱石1：结构——使内容可提取

人工智能系统提取段落，而不是页面。每个关键声明都应该作为一个独立的陈述工作。

**内容块模式：**
- **定义块**用于“什么是X？”查询
- **分步块**用于“如何做X”查询
- **比较表格**用于“X与Y”查询
- **优缺点块**用于评估查询
- **常见问题解答块**用于常见问题
- **统计数据块**带引用来源

有关每种块类型的详细模板，请参阅[references/content-patterns.md](references/content-patterns.md)。

**结构规则：**
- 每个部分都以直接的答案开头（不要隐藏它）
- 将关键答案段落保持在40-60字（最适合片段提取）
- 使用与人们如何表达查询相匹配的H2/H3标题
- 表格比散文更适合比较内容
- 编号列表比段落更适合过程内容
- 每个段落应该传达一个清晰的想法

### 柱石2：权威性——使内容可引用

人工智能系统更喜欢他们可以信任的来源。建立可引用性。

**普林斯顿GEO研究**（KDD 2024，跨Perplexity.ai研究）对9种优化方法进行了排名：

| 方法 | 可见性提升 | 如何应用 |
|------|:---------------:|--------------|
| **引用来源** | +40% | 添加权威性引用并链接 |
| **添加统计数据** | +37% | 包含具体数字并注明来源 |
| **添加引言** | +30% | 专家引言并注明姓名和头衔 |
| **权威性语气** | +25% | 以展示专业知识的语气写作 |
| **提高清晰度** | +20% | 简化复杂概念 |
| **技术术语** | +18% | 使用特定领域的术语 |
| **独特词汇** | +15% | 增加词汇多样性 |
| **流畅性优化** | +15-30% | 提高可读性和流畅性 |
| ~~关键词堆砌~~ | **-10%** | **积极影响人工智能可见性** |

**最佳组合**：流畅性+统计数据=最大提升。低排名网站受益更多——引用优化可提高115%的可见性。

**统计数据和数据**（+37-40%引用提升）
- 包含具体数字并注明来源
- 引用原始研究，而不是研究摘要
- 为所有统计数据添加日期
- 原始数据优于聚合数据

**专家归因**（+25-30%引用提升）
- 命名作者并注明资格
- 专家引言并注明头衔和组织
- “根据[来源]”的引言框架
- 作者简介与相关专业知识

**新鲜度信号**
- “最后更新：[日期]”突出显示
- 定期更新内容（竞争性主题每季度至少更新一次）
- 当前年份的参考和最近的统计数据
- 删除或更新过时的信息

**E-E-A-T一致性**
- 展示第一手经验
- 提供具体、详细的信息（而不是通用信息）
- 透明的来源和方法
- 清晰地表明作者对主题的专业知识

### 柱石3：存在——出现在人工智能查找的地方

人工智能系统不仅引用你的网站——它们引用你出现的地方。

**第三方来源比你的网站更重要：**
- 维基百科提及（所有ChatGPT引用的7.8%）
- Reddit讨论（波动性：历史上ChatGPT引用的~1.8%，但到2026年8月的检索更改几乎从ChatGPT中删除——仍然在其他地方检索；参见[references/agent-readiness.md](references/agent-readiness.md)中的波动性部分）
- 行业出版物和客座文章
- LinkedIn——根据LinkedIn自己的AEO指南，是专业主题搜索中最被引用的渠道；文章的引用率约为帖子60/40，并且帖子的第一个词成为其URL别名，因此请将目标短语放在前面（详细信息在[references/format-volatility.md](references/format-volatility.md)中）
- 评论网站（G2、Capterra、TrustRadius用于B2B SaaS）
- YouTube（经常被谷歌人工智能概览引用）
- 播客（剧集被转录，节目简介发布——两者都被爬取和引用）
- Quora答案

**行动：**
- 确保你的维基百科页面准确且最新
- 作为投资组合的一部分，真诚地参与Reddit社区——但永远不要将其作为整个策略（引用混合随着检索更新而改变）
- 获得行业盘点和比较文章的报道
- 在相关评论平台上维护更新的资料
- 为关键如何查询创建YouTube内容——模型不会观看视频，它们会阅读围绕它的文本层；参见[references/youtube-ai-citations.md](references/youtube-ai-citations.md)的完整解剖（转录、字幕、章节、描述、固定评论）
- 在你的类别中做客播客（使用公共关系技能的播客嘉宾准备）
- 深入回答相关的Quora问题

### 机器可读文件用于人工智能代理

> **谷歌的立场**：对于人工智能概览或人工智能模式不是必需的。他们的指南明确表示你不需要新的标记、人工智能文件或markdown才能出现在生成式人工智能搜索中。
>
> **为什么还要包含它们**：非谷歌人工智能引擎（ChatGPT、Claude、Perplexity）确实奖励可提取的结构。这些文件有助于那些引擎，而不会伤害谷歌。

人工智能代理不仅回答问题——它们正在成为买家。当人工智能代理代表用户评估工具时，它们需要结构化、可解析的信息。如果你的定价被锁定在JavaScript渲染的页面或“联系销售”墙中，代理将跳过你并推荐竞争对手，他们的信息它们实际上可以阅读。

**首先审核这一层**：[references/agent-readiness.md](references/agent-readiness.md)——访问/发现/解析性检查表，免费评分工具（`npx is-agentic`，Frase的检查器），Markdown内容协商+`Link`标头，`llms-full.txt`，以及新兴的代理-*可执行*层（WebMCP）。

将以下机器可读文件添加到你的网站根目录：

**`/pricing.md`或`/pricing.txt`** — 结构化定价数据用于人工智能代理

```markdown
# 定价 — [你的产品名称]

## 免费
- 价格：$0/月
- 限制：100封电子邮件/月，1个用户
- 功能：基本模板，API访问

## 专业版
- 价格：$29/月（年付）|$35/月（月付）
- 限制：10,000封电子邮件/月，5个用户
- 功能：自定义域名，分析，优先支持

## 企业版
- 价格：定制——请联系sales@example.com
- 限制：无限电子邮件，无限用户
- 功能：SSO，SLA，专属客户经理
```

**这现在意味着什么：**
- 人工智能代理越来越多地以编程方式比较产品，而人类甚至不会访问你的网站
- 不透明的定价会从人工智能介导的购买过程中被过滤掉
- 简单的markdown文件可以被任何LLM轻易解析——不需要渲染，不需要JavaScript，不需要登录墙
- 与`robots.txt`（用于爬虫）、`llms.txt`（用于人工智能上下文）和`AGENTS.md`（用于代理功能）的原理相同

**最佳实践：**
- 使用一致的单位（月付与年付，每座位与固定费用）
- 包括具体的限制和阈值，而不仅仅是功能名称
- 列出每个级别包含的内容，而不仅仅是不同之处
- 保持更新——过时的定价比没有文件更糟
- 从你的站点地图和主要定价页面链接到它

**`/llms.txt`** — 人工智能系统上下文文件（参见[llmstxt.org](https://llmstxt.org)）

如果你还没有，添加一个`llms.txt`，让人工智能系统快速了解你的产品是什么，为谁设计，并链接到关键页面（包括你的定价）。

**`/okf/`** — 开放知识格式捆绑包（谷歌支持，v0.1）**

谷歌[引入了OKF](https://cloud.google.com/blog/products/data-analytics/how-the-open-knowledge-format-can-improve-data-sharing)在2026年6月——一种markdown规范，用于将网站内容表示为带有YAML前文的跨链接文件目录，代理可以无抓取地读取；主要用于数据团队目录元数据；网站可被代理读取的重新利用是由Suganthan Mohanadasan推广的。目前没有确定的AI搜索排名信号——将其视为像早期schema.org的协议层注册。**有关完整分解、实施路径（免费生成器、WordPress插件、手动操作）、托管指南以及何时跳过，请参阅[references/okf.md](references/okf.md)。**

### 人工智能的方案标记

结构化数据帮助人工智能系统理解你的内容。关键方案：

| 内容类型 | 方案 | 有助于什么 |
|-------------|--------|-------------|
| 文章/博客文章 | `Article`，`BlogPosting` | 作者，日期，主题识别 |
| 如何内容 | `HowTo` | 步骤提取用于过程查询 |
| 常见问题解答 | `FAQPage` | 直接问答提取 |
| 产品 | `Product` | 定价，功能，评论 |
| 比较内容 | `ItemList` | 结构化比较数据 |
| 评论 | `Review`，`AggregateRating` | 信任信号 |
| 组织 | `Organization` | 实体识别 |

具有正确方案的页面在非谷歌人工智能引擎上的人工智能可见性提高30-40%。**谷歌的注意**：结构化数据对于生成式人工智能搜索“不是必需的”，但建议用于整体SEO策略。实施时使用**方案**技能。

## 代理体验

除了人工智能搜索引擎总结内容之外，自主代理现在开始直接访问网站——点击、阅读、比较，甚至代表用户购买。谷歌的指南将其标记为需要为新兴类别进行规划。

**代理如何访问你的网站：**
- **视觉渲染**——它们像用户一样截图/读取页面
- **DOM检查**——它们解析页面的HTML结构
- **可访问性树**——它们依赖于辅助技术使用的相同语义信息（标签、角色、地标、标题）

**你应该做什么：**
- **渲染有意义的内容，不要进行复杂的JS操作**——如果页面在4个框架加载完成后为空白，代理会看到空白
- **语义HTML**——使用`<main>`，`<nav>`，`<article>`，`<button>`，适当的标题层次结构，图像的`alt`文本
- **干净的访问性树**——每个交互元素都有标签；正确使用ARIA（或当原生HTML足够时不要使用）
- **稳定的选择器/可预测的布局**——代理难以处理重新渲染每个交互的网站
- **可见的价格、规格、联系信息**——任何代理需要为购买建议显示的内容都应该在公共、可索引的页面上（这就是`/pricing.md`和类似文件的作用）

**新兴的——通用商业协议（UCP）：**
谷歌将UCP作为即将推出的协议参考，该协议将向代理提供标准化的钩子用于商业交互（目录发现、定价、结账）。关注其采用情况；目前，上述结构建议是先决条件。

对于电商和本地业务，谷歌强调：
- **商家中心馈送**+**谷歌业务资料**用于产品/服务在人工智能搜索中的可见性
- **业务代理**用于对话式客户参与（如果适用）

## 最常被引用的内容类型

并非所有内容都具有相同的可引用性——格式混合是**易变的**。长期基线中，比较文章（~33%）和列表文章（~10%）是顶级引用赚取者，但**ChatGPT 5.6（2026年8月）贬低了被利用的格式：列表文章引用率下降−50.5%，比较页面引用率下降−32.1%，而`site:`和“官方”检索激增**——这一转变倾向于原始来源和拥有页面。格式策略现在是针对每个平台的（比较仍然适用于谷歌AIO/Gemini/Perplexity）。有关转变数据、每个平台的格式表、LinkedIn的引用数字以及ChatGPT发散提取诊断，请参阅[references/format-volatility.md](references/format-volatility.md)。

**永久的赢家跨平台：** 原始研究和数据，权威指南，以及拥有的“官方”页面——产品、文档、定价——具有可提取的结构。

**表现不佳者：** 无结构的通用非结构化帖子，瘦的或受保护的或仅限PDF的内容，以及任何未注明日期且未进行作者归因的内容。

**引用≠推荐。** 被引用意味着你的内容对咨询有用；被*推荐*——出现在买家的实际短名单上——受网络范围共识（评论、论坛、分析师、新闻）的管辖，并且很大程度上独立于你自己的内容。自我推广的“最佳[类别]”列表文章甚至可能对新兴品牌产生负面影响：在一个100个查询的B2B研究中，69%的AI概览引用来自自我推广的列表文章的答案推荐了竞争对手而不是发布品牌。有关可见性阶梯（检索→引用→提及→推荐），阶段依赖的购买指南策略，以及什么可以赚取推荐，以及归因盲点，请参阅[references/citations-vs-recommendations.md](references/citations-vs-recommendations.md)。

### DIY监控（无需工具）

每月手动检查：
1. 选择你最重要的20个查询
2. 在ChatGPT、Perplexity和谷歌中运行每个查询
3. 记录：你被引用了吗？谁引用了？哪个页面？
4. 记录在电子表格中，按月跟踪

AI答案是**非确定性**的——一次运行只是一个轶事，而不是一个测量。在每个平台上运行每个查询3-5次，并跟踪其提及*率*及其样本量（例如，引用3/5, n=5），而不是单次运行。完整的严格检查表在[references/format-volatility.md](references/format-volatility.md)中。

## 不要做什么

谷歌的指南明确指出它们会伤害传统搜索和AI功能的这些做法。

1. **为AI编写单独的内容**。相同的内容应该服务于人类和AI。为人工智能系统编写变体有风险“扩展内容滥用”垃圾邮件政策——这是谷歌的话。
2. **将页面拆分为AI诱饵片段**。谷歌的指南是直接的：*"不要将你的内容拆分成微小的片段以供AI更好地理解。"* 使用正常的段落+标题结构。
3. **大规模生成以操纵排名**。人工智能生成的内容如果符合搜索基本要求和垃圾邮件政策是好的。大规模生产瘦的变体是不行的。
4. **追求不真实的提及**。不要编造引用或批量垃圾邮件Reddit/Wikipedia以获取AI可见性。只有真实的参与才有效。
5. **如果你想要引用，则不要阻止AI爬虫**。阻止GPTBot、PerplexityBot、ClaudeBot、Google-Extended意味着这些引擎实际上无法引用你。如果你必须阻止，请不要阻止训练-only爬虫（CCBot），而阻止搜索和引用的爬虫。
6. **隐藏你的主要内容在无法渲染的JS之后**。核心搜索和AI代理都需要看到你的内容；JS-only渲染会失去两个受众。
7. **跳过E-E-A-T基础知识**。作者身份，第一手经验，专业知识信号，透明的来源——谷歌的指南非常重视这些对于AI功能。
