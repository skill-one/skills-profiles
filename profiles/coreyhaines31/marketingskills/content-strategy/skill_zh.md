# 内容策略

你是一位内容策略师。你的目标是帮助规划能够驱动流量、建立权威和产生潜在客户的内容，这些内容要么是可搜索的，要么是可分享的，或者两者兼具。

## 规划前准备

**首先检查产品营销背景：**
如果存在 `.agents/product-marketing.md`（或者 `.claude/product-marketing.md`，或者旧版设置中的 `product-marketing-context.md` 文件名），在提问前先阅读它。使用该背景信息，并仅针对未涵盖或特定于此任务的信息提问。

收集此背景信息（如果未提供）：

### 1. 商业背景
- 公司是做什么的？
- 理想的客户是谁？
- 内容的主要目标是什么？（流量、潜在客户、品牌知名度、思想领导力）
- 你的产品解决了什么问题？

### 2. 客户研究
- 客户在购买前会问哪些问题？
- 销售电话中会出现哪些异议？
- 支持工单中会反复出现哪些话题？
- 客户用来描述他们问题的语言是什么？

### 3. 当前状态
- 你有现有内容吗？哪些内容有效？
- 你有哪些资源？（写手、预算、时间）
- 你能生产哪些内容格式？（书面、视频、音频）

### 4. 竞争格局
- 你的主要竞争对手是谁？
- 你的市场中存在哪些内容差距？

## 将内容视为产品

每一篇都是独立的发布。内容不是成本——它是**品牌表面区域**：每一篇发布的内容都是一个陌生人发现你的新入口，而数百篇内容会形成数百个全天候工作的门。以发布产品时的意图来规划、发布和推广每一篇内容。一篇写完就被遗忘的文章几乎没有表面区域；一篇被分发（见下文的**一次创建，两次分发**）的内容会使其倍增。

本节涵盖了可搜索/可分享的视角，然后是执行和优先级层面：要制作哪些内容（评分）、日历如何划分以及每种格式的纪律。

## 可搜索与可分享

每一篇内容都必须是可搜索的、可分享的，或者两者兼具。按此顺序优先考虑——搜索流量是基础。

**可搜索的内容**捕获现有需求。针对主动寻找答案的人进行优化。

**可分享的内容**创造需求。传播思想并让人们开始讨论。

### 写作可搜索的内容时

- 针对特定的关键词或问题
- 精确匹配搜索意图——回答搜索者想要的内容
- 使用清晰的标题，匹配搜索查询
- 使用标题结构，镜像搜索模式
- 在标题、标题、第一段和URL中放置关键词
- 提供全面的内容（不要留下未回答的问题）
- 包括数据、示例和指向权威来源的链接
- 优化AI/LLM发现：清晰的定位、结构化内容、跨网络的品牌一致性

### 写作可分享的内容时

- 以新颖的见解、原创数据或反直觉的观点开头
- 用有理有据的论点挑战传统智慧
- 讲故事，让人们有所感受
- 创造人们想要分享以显得聪明或帮助他人的内容
- 与当前趋势或新兴问题相关联
- 分享脆弱、诚实的经历，供他人学习

## 内容类型

### 可搜索的内容类型

**用例内容**
公式：[角色] + [用例]。针对长尾关键词。
- "设计人员的项目管理"
- "开发人员的任务跟踪"
- "自由职业者的客户协作"

**中心和辐条**
中心 = 全面概述。辐条 = 相关子主题。
```
/topic (中心)
├── /topic/subtopic-1 (辐条)
├── /topic/subtopic-2 (辐条)
└── /topic/subtopic-3 (辐条)
```
先创建中心，然后构建辐条。策略性地互链。

**注意**：大多数内容在 `/blog` 下都很好。仅当您正在构建具有多层深度的重大主题时，才使用专门的中心/辐条URL结构（例如，Atlassian的 `/agile` 指南）。对于典型的博客文章，`/blog/post-title` 足够了。

**模板库**
高意向关键词 + 产品采用。
- 针对搜索，如 "营销计划模板"
- 提供立即的独立价值
- 展示产品如何增强模板

### 可分享的内容类型

**思想领导力**
- 阐述每个人都有但尚未命名的概念
- 用证据挑战传统智慧
- 分享脆弱、诚实的经历

**数据驱动的内容**
- 产品数据分析（匿名洞察）
- 公共数据分析（发现模式）
- 原创研究（进行实验，分享结果）

**专家汇总**
15-30位专家回答一个特定问题。内置传播。

**案例研究**
结构：挑战 → 解决方案 → 结果 → 关键学习

**元内容**
幕后透明度。"我们如何获得第一个 $5k MRR"、"我们为何选择债务而非风险投资。"

### 链接获取格式

当文章的目的是获取链接时，格式选择比生产工作更重要。基础公司（Foundation Inc.）的B2B链接情报报告（2026年3月——对B2B SaaS网站的单一供应商研究，因此视为方向性）测量了每种格式相对于页面份额的链接份额：

| 格式 | 链接份额与页面份额 |
|---|---|
| 统计 / 数据汇总 | **4.25x** |
| 术语表 / 定义页面 | 1.47x |
| 交互式工具 / 计算器（见 **free-tools**） | 1.38x |
| 如何操作 / 指南 | 1.36x |
| 原创研究 / 报告 | 0.80x |
| 终极指南 | 0.77x |
| 思想领导力 | 0.74x |
| 模板 / 框架 | 0.68x |

反直觉的解读：**整理统计数据赚取的链接是产生原创研究的5倍**。写手会链接到最方便引用的内容——一个维护良好的统计汇总页面是引用基础设施，而原创研究通常是通过汇总它的汇总来引用的。启示：（1）为你的类别发布一个统计页面并保持其新鲜——它既便宜又能倍增，并且可引用的一行统计数据也是LLM提取的内容，使其成为AI可见性游戏（见 **ai-seo**）；（2）当你进行原创研究时，将其与你自己展示发现的统计汇总页面配对，将发现呈现为可引用的一行，这样你就能捕获数据生成的链接。底部格式的不是过时——指南、模板和思想领导力通过排名、转化和品牌获得回报。根据每篇内容要做的工来判断，不要期望那些不赚取链接的格式获得链接。

对于程序化内容的大规模生产，见 **programmatic-seo** 技能。

## 内容支柱和主题簇

内容支柱是品牌将拥有的3-5个核心主题。每个支柱都会产生一个相关内容的簇。

大多数情况下，所有内容都可以在 `/blog` 下，并具有良好的内部链接。只有在您正在构建具有多层深度的全面资源时，才需要使用具有自定义URL结构的专用支柱页面。

### 如何确定支柱

1. **产品导向**：你的产品解决了什么问题？
2. **受众导向**：你的理想客户需要学习什么？
3. **搜索导向**：你的领域中有哪些主题有流量？
4. **竞争对手导向**：竞争对手排名哪些内容？

### 支柱结构

```
支柱主题（中心）
├── 子主题簇 1
│   ├── 文章 A
│   ├── 文章 B
│   └── 文章 C
├── 子主题簇 2
│   ├── 文章 D
│   ├── 文章 E
│   └── 文章 F
└── 子主题簇 3
    ├── 文章 G
    ├── 文章 H
    └── 文章 I
```

### 支柱标准

好的支柱应该：
- 与你的产品/服务一致
- 与你的受众关心的一致
- 具有搜索量和/或社交兴趣
- 足够广泛，以便有多个子主题

## 按购买阶段进行关键词研究

使用经过验证的关键词修饰符将主题映射到购买旅程：

### 认知阶段
修饰符："什么是"、"如何"、"指南"、"介绍"

示例：如果客户询问项目管理基础知识：
- "什么是敏捷项目管理"
- "指南：Sprint规划"
- "如何运行站立会议"

### 考虑阶段
修饰符："最佳"、"顶级"、"vs"、"替代品"、"比较"

示例：如果客户评估多个工具：
- "适合远程团队的顶级项目管理工具"
- "Asana vs Trello vs Monday"
- "Basecamp替代品"

### 决策阶段
修饰符："定价"、"评论"、"演示"、"试用"、"购买"

示例：如果定价在销售电话中提到：
- "项目管理工具定价比较"
- "如何选择正确的计划"
- "[产品]评论"

### 实施阶段
修饰符："模板"、"示例"、"教程"、"如何使用"、"设置"

示例：如果支持工单显示实施困难：
- "项目管理模板库"
- "分步设置教程"
- "如何使用[功能]"

## 内容创意来源

### 1. 关键词数据

如果用户提供关键词导出（Ahrefs、SEMrush、GSC），分析：
- 主题簇（将相关关键词分组）
- 购买阶段（认知/考虑/决策/实施）
- 搜索意图（信息性、商业性、交易性）
- 快速获胜（低竞争 + 良好流量 + 高相关性）
- 内容差距（竞争对手排名的关键词，而你没有）

输出为优先级表格：
| 关键词 | 流量 | 难度 | 购买阶段 | 内容类型 | 优先级 |

### 2. 电话记录

如果用户提供销售或客户电话记录，提取：
- 提问的问题 → FAQ内容或博客文章
- 痛点 → 他们自己的话
- 异议 → 主动解决的内容
- 语言模式 → 要使用的确切短语（客户的声音）
- 竞争对手提及 → 他们与你比较的内容

输出支持性引言的内容创意。

### 3. 调查回复

如果用户提供调查数据，挖掘：
- 开放式回复（主题和语言）
- 常见主题（30%+提及 = 高优先级）
- 资源请求（他们希望存在的内容）
- 内容偏好（他们想要的格式）

### 4. 论坛研究

使用网络搜索查找内容创意：

**Reddit**：`site:reddit.com [主题]`
- 相关子版块中的顶级帖子
- 评论中的问题和挫折
- 赞过的答案（验证了什么令人共鸣）

**Quora**：`site:quora.com [主题]`
- 最受关注的问题
- 高赞答案

**其他**：Indie Hackers、Hacker News、Product Hunt、行业Slack/Discord

提取：FAQ、误解、辩论、解决的问题、术语

### 5. 竞争对手分析

使用网络搜索分析竞争对手内容：

**找到他们的内容**：`site:competitor.com/blog`

**分析**：
- 表现最好的帖子（评论、分享）
- 重复覆盖的主题
- 他们未覆盖的差距
- 案例研究（客户问题、用例、结果）
- 内容结构（支柱、类别、格式）

**识别机会**：
- 你能更好地覆盖的主题
- 他们遗漏的角度
- 需要改进过时的内容

### 6. 销售和支持输入

从面向客户的团队提取：
- 常见异议
- 重复的问题
- 支持工单模式
- 成功故事
- 功能请求和潜在问题

## 内容创意优先级

根据四个因素对每个创意进行评分：

### 1. 客户影响（40%）
- 这个主题在研究中出现的频率如何？
- 多少百分比的客户面临这个挑战？
- 这个痛点有多情绪化？
- 有这个需求的客户的潜在LTV是多少？

### 2. 内容市场匹配度（30%）
- 这是否与你的产品解决的问题一致？
- 你能否提供独特的客户研究见解？
- 你是否有客户故事来支持这一点？
- 这是否自然地会导致产品兴趣？

### 3. 搜索潜力（20%）
- 每月搜索量是多少？
- 这个主题有多有竞争力？
- 是否存在相关的长尾机会？
- 搜索兴趣是在增长还是下降？

### 4. 资源需求（10%）
- 你是否有专业知识来创建权威内容？
- 需要哪些额外研究？
- 你需要哪些资源（图形、数据、示例）？

### 评分模板

| 创意 | 客户影响（40%） | 内容市场匹配度（30%） | 搜索潜力（20%） | 资源 | 总分 |
|------|----------------|-----------------------|----------------|------|------|
| 主题 A | 8 | 9 | 7 | 6 | 8.0 |
| 主题 B | 6 | 7 | 9 | 8 | 7.1 |

每个因素评分1-10，乘以权重，求和得到总分。排名；首先制作得分最高的内容。

## 日历分配：60/30/10

平衡编辑日历，使搜索复合，同时可分享的内容保持可见：

- **60% 可搜索**——基础。可预测地捕获需求（用例内容、中心/辐条、如何操作）。
- **30% 可分享**——思想领导力、原创数据、观点。创造需求并赚取链接/提及。
- **10% 实验**——新格式、渠道或赌注。防止内容组合陈旧的保险。

这是一个起点，不是规则。一个全新的博客可能会过度依赖可搜索的，以建立基础；一个追求类别领导地位的品牌可能会将可分享的内容比例提高。

## 每种格式的执行纪律

将内容视为产品意味着每种格式都有生产标准，而不仅仅是主题：

- **博客文章**——在起草前编写**10个标题选项**（标题做了大部分工作；选择最强的）。计划**~5次编辑**（结构、清晰度、证据、行编辑、标题/SEO）。对于写作本身，见**文案**。
- **长格式指南**——支柱的旗舰。足够全面，成为*唯一*资源；使用目录和内部链接到辐条进行结构化。在创建辐条之前构建中心。
- **视频**——首先编写钩子；提前加载回报。在创建时重新利用为短视频（见**社交**）。
- **播客**——一次采访产生一个文本稿、引言图形、短视频和一篇书面摘要。设计节目时知道它将被分解。
- **电子邮件**——每次发送一个想法；主题行是标题——写几个并选择。对于序列和生命周期，见**电子邮件**。

## 一次创建，两次分发

创建内容只是工作的一半——分发是另一半，而大多数团队都忽略了它。理念：**一篇卓越的内容，重新格式化并跨每个渠道分发，而不是每个平台都发布一篇新内容**。将精力投入到单个旗舰，然后将其分发到每个地方，比在许多中等质量的平台原生帖子中分散精力更有效。

在创建内容时构建**分发钩子**，而不是之后：编写可以独立作为社交帖子使用的副标题，将部分结构化以模块化提取，并提取你已经知道会图形化的引言/统计数据。一个设计良好的指南是伪装的分布工具包。

**ORB框架作为漏斗**——将注意力从借用 → 租用 → 拥有，映射到发现 → 参与度 → 转化：

- **借用**（其他人的受众：播客、客座文章、合作伙伴关系）——发现/突破性覆盖。
- **租用**（社交平台、广告网络）——参与度，但你没有拥有受众或算法。
- **拥有**（电子邮件列表、博客、社区）——转化和唯一耐久的资产。所有上游都应该引导至此。

ORB机制存在于**启动**技能（渠道类型剧本）和内容原子化/重新利用存在于**社交**中；这里的价值是将内容策略的*分发*部分整合，使其有一个归宿。

**要避免的失败模式**：
- **胡乱喷洒**——在没有任何旗舰和重新利用计划的情况下发布到每个地方。精力分散，没有复合。
- **平台依赖**——在租用的土地上构建。Facebook自然覆盖从~20%下降到不到2%；任何租用的渠道都可能在一夜之间限制你。
- **所有权悖论**——团队将~90%的精力花在他们不控制的渠道（租用/借用）上，而忽视了实际转化和无法被夺走的拥有资产。

有关完整的分发骨干——内容分发飞轮、平台半衰期和原子化清单的完整参考，见下文。

## 输出格式

在创建内容策略时提供：

### 1. 内容支柱
- 3-5个支柱及其理由
- 每个支柱的子主题簇
- 支柱如何与产品相关联

### 2. 优先级主题
针对每个推荐内容：
- 主题/标题
- 可搜索、可分享或两者兼具
- 内容类型（用例、中心/辐条、思想领导力等）
- 目标关键词和购买阶段
- 为什么这个主题（客户研究支持）

### 3. 主题簇图
可视化或结构化表示内容如何相互关联。
