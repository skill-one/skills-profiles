# 产品营销上下文

您帮助用户创建和维护产品营销上下文文档。本文档记录了其他营销技能所参考的基础定位与沟通信息，确保用户不重复表述。

文档存储于 `.agents/product-marketing-context.md`。

## 工作流程

### 步骤 1：检查现有上下文

首先，检查 `.agents/product-marketing-context.md` 是否已存在。此外，也检查 `.claude/product-marketing-context.md`（用于旧版本设置），如果在其中找到但不在 `.agents/` 目录下，请提供将其移动的选项。

**如果存在：**
- 阅读文档并总结已记录的内容
- 询问他们希望更新哪些章节
- 仅收集相关章节的信息

**如果不存在，提供两个选项：**

1. **从代码库自动起草**（推荐）：您将研究该代码库——包括 README、落地页、营销文案、package.json 等——并起草上下文文档的第一版。用户随后进行审阅、修正和补充遗漏信息。相比从零开始，速度更快。

2. **从零开始**：逐章以对话方式推进，每次收集一个章节的信息。

多数用户更倾向于选项 1。在呈现草稿后，请询问：“需要修正什么？哪些内容缺失？”

### 步骤 2：收集信息

**如果是自动起草：**
1. 阅读代码库：README、落地页、营销文案、关于页面、元描述、package.json 及任何现有文档
2. 根据所发现的内容起草所有章节
3. 呈现草稿，并询问哪些内容需要修正或缺失
4. 迭代，直到用户满意

**如果是从零开始：**
逐章以下文内容以对话方式进行，每次推进一章。不要一次性罗列所有问题。

对于每个章节：
1. 简要说明正在收集的信息
2. 提出相关问题
3. 确认准确性
4. 进入下一章

鼓励获取客户的原话——确切的短语比润色后的描述更有价值，因为它们能反映客户实际的思想与表达方式，从而使文案更具共鸣感。

## 需捕获的章节

### 1. 产品概述
- 一句话描述
- 功能说明（2-3句话）
- 产品类别（您所处的“货架”——客户寻找您的途径）
- 产品类型（SaaS、市场平台、电子商务、服务等）
- 商业模式与定价

### 2. 目标受众
- 目标企业类型（行业、规模、发展阶段）
- 目标决策者（角色、部门）
- 主要使用场景（您解决的核心问题）
- 待办任务（客户为您“聘用”的2-3项任务）
- 具体使用场景或场景

### 3. 用户画像（仅限B2B）
如果购买过程中涉及多个利益相关方，请为每一位记录：
- User, Champion, Decision Maker, Financial Buyer, Technical Influencer
- 各自关注的重点、面临挑战以及我们向他们承诺的价值

### 4. 问题与痛点
- 客户在找到您之前面临的核心挑战
- 当前解决方案为何存在不足
- 它们为此付出的代价（时间、金钱、机会）
- 情感压力（压力、担忧、疑虑）

### 5. 竞争格局
- **直接竞争对手**：提供相同解决方案、解决相同问题（例如 Calentry 与 SavvyCal）
- **次要竞争对手**：提供不同解决方案、解决相同问题（例如 Calentry 与 Superhuman 排程）
- **间接竞争对手**：采用相悖的解决方案（例如 Calentry 与个人助手）
- 它们各自在客户身上存在的不足

### 6. 差异化
- 关键差异化点（替代方案所不具备的能力）
- 我们如何以不同方式解决问题
- 为什么这样做更好（优势）
- 为什么客户选择我们而非替代方案

### 7. 异议与反用户画像
- 在销售过程中听到的头 3 个异议及如何应对
- 哪些人群不适合（反用户画像）

### 8. 切换动态
JTBD 四大力量：
- **Push**：哪些不满促使他们离开当前解决方案
- **Pull**：哪些内容吸引他们选择我们
- **Habit**：哪些因素让他们始终停留在当前方案
- **Anxiety**：他们在切换过程中所担忧的事项

### 9. 客户语言
- 客户如何描述问题（原话）
- 客户如何描述我们的解决方案（原话）
- 应使用的词汇/短语
- 应避免使用的词汇/短语
- 产品特定术语词汇表

### 10. 品牌语调
- 语调（专业、轻松、俏皮等）
- 沟通风格（直接、口语化、技术性）
- 品牌个性（3-5个形容词）

### 11. 佐证要点
- 需引用的关键指标或成果
- 显著客户/品牌标识
- 推荐语片段
- 主要价值主题及支撑证据

### 12. 目标
- 主要业务目标
- 关键转化动作（希望用户执行的操作）
- 当前指标（如已知）

## 步骤 4：确认与保存

- 展示完成的文档
- 询问是否有需要调整的地方
- 保存至 `.agents/product-marketing-context.md`
- 告知用户：“其他营销技能现在将自动使用该上下文。随时运行 `/product-marketing-context` 即可更新文档。”

## 提示

- **具体明确**：询问“他们让你产生第一反应的#1痛点是什么？”，而非“他们解决什么问题？”
- **记录确切词汇**：客户语言优于润色后的描述
- **询问示例**：“能给我举个例子吗？”有助于获取更好的答案
- **边进行边验证**：每章节总结后，在进入下一章前进行确认
- **跳过不适用内容**：并非所有产品都需要所有章节（例如面向消费者业务无需“用户画像”章节）
