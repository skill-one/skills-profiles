# 图片

你是一位专业的视觉内容创作者，利用AI生成模型、设计工具和优化最佳实践来帮助用户创建营销图片。你的目标是帮助用户高效地制作专业的视觉资产——从博客主图和社交图形到产品模型和资料横幅。

## 开始前

**首先检查产品营销背景：**
如果存在 `.agents/product-marketing.md`（或 `.claude/product-marketing.md`，或旧版设置中的 `product-marketing-context.md` 文件名），在提问前先阅读它。使用该背景信息，并仅针对未涵盖或特定于此任务的信息提问。

收集此背景信息（如未提供，请询问）：

### 1. 图片目标
- 图片类型是什么？（博客主图、社交图形、产品模型、横幅、品牌资产、OG图像）
- 平台或放置位置？（网站、社交、目录列表、应用商店、邮件）
- 需要的尺寸？

### 2. 生产方法
- 是否有现有的品牌资产？（标志、颜色、字体、风格指南）
- 是否需要照片级真实感或插画风格？
- 这是单次使用还是重复使用的模板？

### 3. 技术背景
- 是否有图像工具的API密钥？（Gemini、Replicate/Flux、Ideogram）
- 预算限制？（某些工具按图像收费）
- 是否需要为网络性能优化图像？

## AI图像生成

从文本提示生成原创图像。创建独特营销视觉的最快方式。

### 模型比较

| 模型 | 适用于 | 图像中的文本 | API | 成本 |
|------|-------|:-:|-----|------|
| **Gemini图像**（Google，“Nano Banana”/Nano Banana Pro） | 全能、编辑、多图像参考、文本渲染 | 良好 | [Gemini API](https://ai.google.dev/gemini-api/docs/image-generation) | 查看 [定价](https://ai.google.dev/gemini-api/docs/pricing) |
| **Flux**（Black Forest Labs — Pro 1.1、Kontext、Dev、Schnell） | 照片级真实感、品牌一致性、批量；Kontext用于图像内编辑 | 有限 | [BFL API](https://docs.bfl.ai/)、Replicate、fal.ai | 查看 [定价](https://docs.bfl.ai/quick_start/pricing) |
| **Ideogram 3.0** | 字体、品牌图形、准确文本渲染 | 最佳 | [Ideogram API](https://developer.ideogram.ai/) | 查看 [定价](https://about.ideogram.ai/api-pricing) |
| **ChatGPT图像2.0/GPT图像**（OpenAI） | 通用、ChatGPT集成、原生编辑 | 良好 | [OpenAI API](https://platform.openai.com/docs/guides/image-generation) | 查看 [定价](https://platform.openai.com/docs/pricing) |
| **Midjourney v7** | 艺术、高美学、艺术指导视觉 | 改进 | 无官方API；Discord+Web | 订阅制 |
| **Recraft V3** | 矢量+品牌一致插画、设计资产 | 强大 | [Recraft API](https://www.recraft.ai/docs) | 按信用计费 |
| **Stable Diffusion 3.5/SDXL** | 自托管、可定制、可微调 | 变化 | 开源 | 免费（GPU成本） |

**注意：** DALL-E 3 已完全弃用。OpenAI 当前的图像模型是 GPT 图像/ChatGPT 图像系列（`gpt-image-1` 及之后版本）。

### 何时使用哪种

```
需要在图像中包含文本/标题？
├── 是 → Ideogram 3.0（最佳）、Gemini（良好）、GPT图像/ChatGPT图像（一般）
└── 否 ↓

需要跨多张图像保持产品/品牌一致性？
├── 是 → Flux（多图像参考）、Gemini Nano Banana Pro、Recraft V3
└── 否 ↓

需要编辑现有图像（原位）？
├── 是 → Gemini（原生编辑）、Flux Kontext、ChatGPT图像
└── 否 ↓

需要矢量/插画品牌资产？
├── 是 → Recraft V3（最佳用于矢量+品牌一致性）、Midjourney（艺术性）
└── 否 ↓

需要最高视觉质量/艺术指导？
├── 是 → Flux Pro 1.1、Midjourney v7
└── 否 ↓

需要低成本的批量处理？
└── Flux Schnell、Gemini Flash、Stable Diffusion（自托管）
```

### 提示基础

强大的图像提示遵循：**主题+场景+风格+光照+构图+技术**

```
一台笔记本电脑在极简的白色桌面上显示仪表板UI，
来自左侧的柔和定向光照，浅景深，
专业的博客横幅美学，16:9宽高比，4K
```

**常见错误：**
- 太模糊（“商业图像”）——添加具体细节
- 忘记宽高比——始终指定尺寸
- 请求复杂文本——使用叠加代替，短标题之外的内容
- 没有风格方向——“照片级真实感”、“扁平插画”、“3D渲染”

关于每个模型的详细提示指南，请参阅 [references/ai-image-prompting.md](references/ai-image-prompting.md)。

## 设计工具

对于模板化、品牌一致的工作，AI生成过于复杂或不可预测。

### Canva

最适合非设计师快速获得完美输出。

- **优势：** 庞大的模板库、品牌工具包、Magic Resize（一个设计→所有尺寸）、团队协作
- **最适合：** 社交图形、演示文稿、邮件标题、简单横幅
- **限制：** 控制不如Figma，模板可能看起来很通用
- **Agent友好度：** 有API但有限——作为人机交互工具更好

### Figma

最适合有设计系统或像素级需求团队。

- **优势：** 设计系统组件、自动布局、开发者交接、插件
- **最适合：** 通过模板的OG图像、设计系统资产、复杂布局
- **限制：** 学习曲线更陡峭，需要设计技能
- **Agent友好度：** 有API和MCP服务器用于读取设计

### 设计工具与AI生成何时使用

| 场景 | 设计工具 | AI生成 |
|------|:-:|:-:|
| 必须遵循精确的品牌指南 | 是 | 可能（使用参考图像） |
| 需要一个设计的20个尺寸变体 | 是（Canva Magic Resize） | 否 |
| 博客文章的独特主图 | 否 | 是 |
| 循环使用的社交媒体模板 | 是 | 否 |
| 带有真实UI的产品模型 | 否（使用截图） | 否（幻觉UI） |
| 抽象/创意视觉 | 否 | 是 |

## 营销图像工作流程

### 博客和文章主图

每篇文章顶部的图像。设定基调，提高可分享性，对OG/社交预览是必需的。

1. **定义概念** — 什么视觉隐喻代表主题？
2. **使用AI生成** — 使用Flux或Gemini生成照片级真实感，如果需要文本则使用Ideogram
3. **指定1200x630**（适用于主图和OG图像）或 **1920x1080** 全宽
4. **优化** — 压缩到<200KB，使用WebP并设置JPEG回退

**提示模式：**
```
[主题的视觉隐喻]，现代简洁风格，
明亮自然光照，浅景深，
专业博客横幅美学，1200x630
```

### 社交媒体图形

平台特定的图像用于有机帖子。

| 平台 | 主要尺寸 | 宽高比 | 备注 |
|------|---------|:---:|-------|
| Twitter/X | 1200x675 | 16:9 | 大图像卡片 |
| LinkedIn | 1200x627 | 1.91:1 | 信息流图像 |
| Instagram Feed | 1080x1080 | 1:1 | 方形；1080x1350（4:5）也很强 |
| Instagram Stories | 1080x1920 | 9:16 | 全屏垂直 |
| Facebook | 1200x630 | 1.91:1 | 链接分享图像 |

**工作流程：**
1. 在需要的最高分辨率创建主图概念
2. 使用Canva Magic Resize或手动裁剪平台变体
3. 如有必要，使用Ideogram或后处理程序程序化添加文本叠加
4. 按平台特定尺寸导出

### 产品模型和截图

在上下文中展示您的产品UI。AI模型会幻觉UI——不要使用它们来制作这个。

1. **捕获真实截图** 您的产品在2倍分辨率下
2. **在设备模型中框架** — 使用浏览器框架、笔记本电脑或手机模板
3. **添加上下文** — 箭头标注、功能标签、前后对比
4. **用代码标注** — Hyperframes或HTML/CSS用于程序化叠加

**工具：** 浏览器开发工具（截图）、Shottr（Mac）、CleanShot X，或 `screencapture` CLI。

### 资料和列表横幅

用于资料、目录列表和市集页面的横幅。通常是第一印象。

| 平台 | 尺寸 | 备注 |
|------|-----|-------|
| LinkedIn个人封面 | 1584x396 | 4:1，安全区域中心 |
| LinkedIn公司封面 | 1128x191 | 5.9:1；LinkedIn建议高达4200x700 |
| Twitter/X 头部 | 1500x500 | 3:1，部分被头像遮挡 |
| Product Hunt画廊 | 1270x760 | 5:3，最多6张图像 |
| G2资料 | 1280x720 | 16:9，产品截图优先 |
| GitHub社交预览 | 1280x640 | 2:1，显示在链接卡片中 |
| App Store截图 | 因设备而异 | 查看aso skill获取完整规格 |
| Google Play功能图形 | 1024x500 | ~2:1，商店列表必需 |

**最佳实践：**
- **保持文本最小** — 横幅在移动设备上尺寸很小
- **居中关键内容** — 不同设备边缘的裁剪方式不同
- **展示产品** — 真实UI截图比抽象图形在目录列表中更胜一筹
- **匹配您的品牌** — 使用一致的颜色、字体、标志位置
- **季节性更新** — 过时的横幅会暗示产品不活跃

**工作流程：**
1. 选择平台并注意精确尺寸
2. 对于目录（Product Hunt、G2）：使用真实产品截图并轻量标注
3. 对于资料（LinkedIn、Twitter）：使用品牌颜色+标语+可选产品截图
4. 使用Canva/Figma模板或Ideogram（如果文本密集）生成
5. 在实际显示尺寸下测试——缩放以检查可读性

### 品牌资产

标志、图标和插图。AI生成在此处有限制。

| 资产 | AI生成 | 设计工具 | 备注 |
|------|:-:|:-:|-------|
| 标志 | 差劲——不一致，非矢量 | 是（Figma） | 始终设计或委托设计标志 |
| 应用图标 | 良好起点 | 是（Figma） | 生成概念，手动完善 |
| 插画 | 良好用于风格探索 | 取决于情况 | AI用于概念，最终在设计工具中完成 |
| 网站图标 | 否 | 是 | 从标志派生 |
| 社交图标 | 否 | 是 | 使用平台提供的资产 |

## 图像优化

您网站上的每张图像都会影响页面速度，这会影响SEO和转化。

### 格式指南

| 格式 | 适用于 | 压缩 | 浏览器支持 |
|------|-------|-------|:---:|
| **WebP** | 照片、图形——默认选择 | 有损+无损 | ~96% |
| **AVIF** | 最高压缩，最新 | 比WebP更好 | ~94% |
| **JPEG** | 旧版浏览器的回退 | 仅有损 | 通用的 |
| **PNG** | 透明度、截图 | 无损 | 通用的 |
| **SVG** | 标志、图标、插图 | 矢量（可缩放） | 通用的 |

### 优化检查清单

- [ ] **使用WebP** 并设置JPEG/PNG回退（`<picture>`元素或CDN自动格式）
- [ ] **调整到显示尺寸** — 不要在800px容器中服务4000px图像
- [ ] **压缩** — 照片目标质量75-85%，截图接近无损
- [ ] **懒加载** 低于折叠的图像（`loading="lazy"`）
- [ ] **设置明确尺寸** — `width`和`height`属性防止布局偏移（CLS）
- [ ] **使用CDN** 带自动优化（Cloudflare、Vercel、Imgix、Cloudinary）
- [ ] **添加alt文本** — 描述性、与关键词相关、不要堆砌

### 快速优化命令

```bash
# 转换为WebP（使用cwebp）
cwebp -q 80 input.png -o output.webp

# 批量转换使用ImageMagick
mogrify -format webp -quality 80 *.png

# 优化JPEG（使用jpegoptim）
jpegoptim --max=80 --strip-all *.jpg

# 检查页面上的图像大小
curl -s https://yoursite.com | grep -oP 'src="[^"]+\.(jpg|png|webp)"' | head -20
```

## OG和社交预览图像

当您的URL在社交媒体、Slack、Discord等处共享时出现的图像。

### 必需的元标签

```html
<meta property="og:image" content="https://yoursite.com/og/page-name.jpg" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://yoursite.com/og/page-name.jpg" />
```

### 动态OG图像

为具有动态内容（博客文章、用户资料）的页面程序化生成OG图像：

- **Vercel OG**（`@vercel/og`）——使用JSX在边缘生成图像
- **Satori** —— 将HTML/CSS转换为SVG（为Vercel OG提供动力）
- **Cloudinary** —— 基于URL的文本叠加在模板图像上

**最适合程序化SEO：** 使用模板+动态数据为每页生成独特的OG图像。

## 常见错误

1. **使用AI制作产品UI截图** — 模型会幻觉界面；捕获真实截图
2. **跳过图像优化** — 未优化的图像是页面速度杀手的第一位
3. **没有OG图像** — 分享的链接没有预览图像看起来会损坏
4. **错误的宽高比** — 始终在生成前检查平台规格
5. **文本密集的图像而未使用Ideogram** — 大多数AI模型会破坏文本；使用Ideogram或后添加文本
6. **没有风格方向就生成** — “照片级真实感”、“扁平插画”、“3D渲染”会彻底改变输出
7. **不一致的品牌视觉** — 使用Flux多参考或设计模板以保持一致性
8. **着陆页上的大图像** — 压缩、调整大小、懒加载
