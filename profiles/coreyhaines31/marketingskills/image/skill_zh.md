## AI图像生成

从文本提示词生成原始图像，这是创作独特营销视觉图的最快方式。

### 模型对比

| 模型 | 适用场景 | 图像内文本 | API | 费用 |
|-------|----------|:-:|-----|------|
| **Gemini图像**（Google，“Nano Banana” / Nano Banana Pro） | 全能型、可编辑、多图参考、文本渲染 | 良好 | [Gemini API](https://ai.google.dev/gemini-api/docs/image-generation) | 查看 [定价](https://ai.google.dev/gemini-api/docs/pricing) |
| **Flux**（Black Forest Labs — Pro 1.1, Konxt, Dev, Schnell） | 写实摄影、品牌一致性、批量生成；Konxt用于图像内编辑 | 有限 | [BFL API](https://docs.bfl.ai/), Replicate, fal.ai | 查看 [定价](https://docs.bfl.ai/quick_start/pricing) |
| **Ideogram 3.0** | 排版、品牌化图形、准确的文本渲染 | 最佳 | [Ideogram API](https://developer.ideogram.ai/) | 查看 [定价](https://about.ideogram.ai/api-pricing) |
| **ChatGPT图像2.0 / GPT图像**（OpenAI） | 通用用途、ChatGPT集成、原生编辑 | 良好 | [OpenAI API](https://platform.openai.com/docs/guides/image-generation) | 查看 [定价](https://platform.openai.com/docs/pricing) |
| **Midjourney v7** | 艺术型、高审美、艺术指导型视觉 | 有所提升 | 无官方API；Discord + Web | 订阅制 |
| **Recraft V3** | 矢量+符合品牌一致的插画、设计素材 | 强劲 | [Recraft API](https://www.recraft.ai/docs) | 按额度计费 |
| **Stable Diffusion 3.5 / SDXL** | 自托管、可自定义、可调优 | 因情况而异 | 开源 | 免费（需GPU成本） |

**注意：** DALL-E 3 已完全停用。OpenAI 当前的图像模型为 GPT Image / ChatGPT 图像系列（`gpt-image-1` 及以后版本）。

### 使用时机

```
需要图像中包含文本/标题？
├── 是 → Ideogram 3.0（最佳），Gemini（良好），GPT Image / ChatGPT 图像（尚可）
└── 否 ↓

需要多张图像间保持产品/品牌一致性？
├── 是 → Flux（多图参考），Gemini Nano Banana Pro，Recraft V3
└── 否 ↓

需要原地编辑现有图像（in-place）？
├── 是 → Gemini（原生编辑），Flux Konxt，ChatGPT 图像
└── 否 ↓

需要矢量/插画式品牌素材？
├── 是 → Recraft V3（矢量+品牌一致性最佳），Midjourney（艺术型）
└── 否 ↓

需要最高视觉质量/艺术指导？
├── 是 → Flux Pro 1.1，Midjourney v7
└── 否 ↓

需要低成本大批量生成？
└── Flux Schnell, Gemini Flash, Stable Diffusion（自托管）
```

### 提示词基础

优秀的图像提示词遵循：**主体 + 场景 + 风格 + 光影 + 构图 + 技术参数**

```
一张显示仪表盘UI的笔记本电脑放置在极简白色桌面上，
左侧柔和的方向性 lighting，浅景深，
简洁的商业摄影风格，16:9 宽高比，4K
```

**常见错误：**
- 过于模糊（“一张商业图”）——添加具体细节
- 忘记指定宽高比——务必指定尺寸
- 请求复杂文本——对于超出短标题的内容，请使用叠加层
- 无风格方向——“写实摄影”“扁平插画”“3D渲染”

关于各模型的详细提示词指南，请参阅 [references/ai-image-prompting.md](references/ai-image-prompting.md)。

## 设计工具

针对模板化、符合品牌规范的工作，当AI生成效果过剩或过于不可控时使用。

### Canva

最适合不需要设计能力、需要快速产出精美效果的员工。

- **优势：** 庞大的模板库、品牌套件、Magic Resize（一个设计 → 所有尺寸）、团队协作
- **最适合：** 社交媒体配图、演示文稿、邮件页头、简单横幅
- **局限性：** 不如Figma可控，模板可能看起来较为普通
- **对智能体友好度：** 有API但功能有限——更适合作为人工介入工具使用

### Figma

最适合有设计系统或对像素级精度有要求的团队。

- **优势：** 设计系统组件、自动布局、开发者交接、插件
- **最适合：** 通过模板生成OG图、设计系统素材、复杂布局
- **局限性：** 学习曲线较陡，需要设计技能
- **对智能体友好度：** 有API和MCP服务器用于读取设计

### 使用设计工具还是AI生成

| 场景 | 设计工具 | AI生成 |
|----------|:-:|:-:|
| 必须严格遵循品牌规范 | 是 | 视情况而定（有强烈的参考图像时） |
| 需要一种设计20个尺寸变体 | 是（Canva Magic Resize） | 否 |
| 博客文章独特的主视觉图 | 否 | 是 |
| 定期使用的社交媒体模板 | 是 | 否 |
| 带有真实UI的产品原型图 | 否（使用截图） | 否（虚构UI） |
| 抽象/创意视觉 | 否 | 是 |

## 营销图像工作流程

### 博客与文章主视觉图

每篇文章顶部的主视觉图，用于设定基调、提升分享率，是OG/社交预览的必备素材。

1. **明确概念** — 用什么样的视觉隐喻来代表主题？
2. **使用AI生成** — 使用Flux或Gemini生成写实摄影图，若需要文本则使用Ideogram
3. **指定1200x630**（适用于主视觉和OG图）或 **1920x1080** 用于全宽
4. **优化** — 压缩至 <200KB，以WebP格式提供，并设置JPEG备用

**提示词模式：**
```
[主题的视觉隐喻], 简洁现代风格，
明亮自然光照，浅景深，
专业博客页眉风格，1200x630
```

### 社交媒体配图

针对不同平台的有机帖子图像。

| 平台 | 主尺寸 | 比例 | 备注 |
|----------|-------------|:---:|-------|
| Twitter/X | 1200x675 | 16:9 | 大图卡片 |
| LinkedIn | 1200x627 | 1.91:1 | 信息流图像 |
| Instagram信息流 | 1080x1080 | 1:1 | 正方形；1080x1350 (4:5)也适用 |
| Instagram快拍 | 1080x1920 | 9:16 | 全屏垂直 |
| Facebook | 1200x630 | 1.91:1 | 链接分享图 |

**工作流程：**
1. **创建最高分辨率的主视觉概念**
2. **使用Canva Magic Resize或手动裁剪生成平台变体**
3. **如需添加文本叠加，可程序化实现（使用Ideogram或后期处理）**
4. **按平台特定尺寸导出**

### 产品原型图与截图

在场景中展示产品界面。AI模型会虚构界面，因此请勿使用其生成此类内容。

1. **截取产品真实屏幕截图**，并设置为2倍分辨率
2. **在设备原型中框定** — 使用浏览器框架、笔记本电脑或手机模板
3. **添加上下文** — 添加指示箭头、功能标签、前后对比
4. **用代码标注** — 使用Hyperframes或HTML/CSS实现程序化叠加

**工具：** 浏览器开发者工具（截图），Shottr（Mac），CleanShot X，或 `screencapture` CLI。

### 个人资料与列表横幅

用于个人资料、目录列表和商品页的横幅。往往是视觉第一印象。

| 平台 | 尺寸 | 备注 |
|----------|------|-------|
| LinkedIn个人封面 | 1584x396 | 4:1，安全区居中 |
| LinkedIn公司封面 | 1128x191 | 5.9:1；LinkedIn建议最大使用4200x700 |
| Twitter/X页眉 | 1500x500 | 3:1，被头像部分遮挡 |
| Product Hunt画廊 | 1270x760 | 5:3，最多6张图 |
| G2个人资料 | 1280x720 | 16:9，优先使用产品截图 |
| GitHub社交预览 | 1280x640 | 2:1，在链接卡片中展示 |
| 应用商店截图 | 视设备而定 | 参见aso技能获取完整规格 |
| Google Play功能图 | 1024x500 | ~2:1，上架必需 |

**最佳实践：**
- **精简文字** — 横幅在移动端常以小尺寸展示，文字需精简
- **居中核心内容** — 不同设备的边缘裁剪方式不同，需居中重要内容
- **展示产品** — 在目录列表中，真实UI截图优于抽象图形
- **匹配品牌** — 使用一致的色彩、字体和Logo位置
- **定期更新** — 陈旧的横幅暗示产品处于不活跃状态

**工作流程：**
1. **选择平台并记录确切尺寸**
2. **针对目录（Product Hunt、G2）：** 使用带轻量标注的真实产品截图
3. **针对个人资料（LinkedIn、Twitter）：** 使用品牌色彩 + 标语 + 可选产品图
4. **使用Canva/Figma模板生成，或若文字较多使用Ideogram生成**
5. **在实际显示尺寸下测试** — 缩小以检查可读性

### 品牌资产

Logo、图标和插画。AI生成在此方面存在局限。

| 资产 | AI生成 | 设计工具 | 备注 |
|-------|:-:|:-:|-------|
| Logo | 较差 — 不一致，非矢量 | 是（Figma） | 始终设计或委托设计Logo |
| 应用图标 | 尚可的起点 | 是（Figma） | 生成概念后手动精修 |
| 插画 | 适合风格探索 | 视情况而定 | AI用于概念，在设计工具中定稿 |
| 收藏图标 | 否 | 是 | 从Logo派生 |
| 社交图标 | 否 | 是 | 使用平台提供的素材 |

## 图像优化

网站上每张图像都会影响页面速度，进而影响SEO和转化率。

### 格式指南

| 格式 | 适用场景 | 压缩 | 浏览器支持 |
|--------|----------|-------------|:---:|
| **WebP** | 照片、图形 — 默认选择 | 有损+无损 | ~96% |
| **AVIF** | 最高压缩，最新 | 优于WebP | ~94% |
| **JPEG** | 旧浏览器备用 | 有损 | 通用 |
| **PNG** | 透明、截图 | 无损 | 通用 |
| **SVG** | Logo、图标、插画 | 矢量（可缩放） | 通用 |

### 优化清单

- [ ] **以WebP格式提供**，并设置JPEG/PNG备用（使用 `<picture>` 元素或CDN自动格式转换）
- [ ] **缩放至显示尺寸** — 不要在800px的容器中提供4000px的图像
- [ ] **压缩** — 照片目标质量75-85%，截图接近无损
- [ ] **懒加载** 折叠以下的图像（使用 `loading="lazy"`）
- [ ] **设置明确尺寸** — `width` 和 `height` 属性可防止布局偏移（CLS）
- [ ] **使用带自动优化的CDN**（Cloudflare、Vercel、Imgix、Cloudinary）
- [ ] **添加alt文本** — 描述性、与关键词相关，不要堆砌

### 快速优化命令

```bash
# 转换为WebP（使用cwebp）
cwebp -q 80 input.png -o output.webp

# 使用ImageMagick批量转换
mogrify -format webp -quality 80 *.png

# 优化JPEG（使用jpegoptim）
jpegoptim --max=80 --strip-all *.jpg

# 检查页面上的图像大小
curl -s https://yoursite.com | grep -oP 'src="[^"]+\.(jpg|png|webp)"' | head -20
```

## OG与社会预览图

当您的链接在社交媒体、Slack、Discord等平台分享时显示的图像。

### 必需Meta标签

```html
<meta property="og:image" content="https://yoursite.com/og/page-name.jpg" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://yoursite.com/og/page-name.jpg" />
```

### 动态OG图像

为内容动态的页面（如博客文章、用户个人资料）程序化生成OG图像：

- **Vercel OG** (`@vercel/og`) — 使用JSX在边缘生成图像
- **Satori** — 将HTML/CSS转换为SVG（驱动Vercel OG）
- **Cloudinary** — 在模板图像上以URL为基础添加文本叠加

**最适合程序化SEO：** 使用模板 + 动态数据，为每页生成独特的OG图像。

## 常见错误

1. **使用AI生成产品UI截图** — 模型会虚构界面；截取真实截图
2. **跳过图像优化** — 未优化的图像是导致页面速度变慢的首要原因
3. **没有OG图** — 共享链接缺少预览图像时看起来会断裂
4. **宽高比错误** — 生成前务必核对平台规格
5. **文字过重的图像未使用Ideogram** — 大多数AI模型会损坏文本；使用Ideogram或在后期添加文字
6. **未明确风格方向就生成** — “写实摄影”“扁平插画”“3D渲染”等方向会大幅改变输出结果
7. **品牌视觉不一致** — 使用Flux多图参考或设计模板以确保一致性
8. **落地页使用过大的图像** — 需进行压缩、缩放和懒加载
