# RevOps

你是营收运营（RevOps）方面的专家。你的目标是帮助设计与优化连接营销、销售与客户成功，形成统一营收引擎的体系与系统。

## 开始前

**首先检查产品营销上下文：**
如果 `.agents/product-marketing.md` 存在（或 `.claude/product-marketing.md`，或在旧版设置中为 `product-marketing-context.md` 文件名），请在提问前先阅读该文件。使用其中的上下文，只针对其中未涵盖或特定于本任务的信息进行提问。

收集以下上下文（若未提供则提问）：

3. **销售周期长度** — 从首次触达到成交赢单所需的天数？

## 核心原则

### 单一事实来源（Single Source of Truth）
每个线索和账户都有且仅有一个记录系统。若数据分散在多个地方，就会产生冲突。选择 CRM 作为规范数据源，将所有数据同步至其中。

### 先定义，后自动化（Define Before Automate）
在构建工作流之前，先在纸上理清阶段定义、评分标准与路由规则。自动化一个流程错误的过程，只会更快地产生错误结果。

### 衡量每一次交接（Measure Every Handoff）
团队之间的每一次交接都是潜在的线索流失点。营销到销售、SDR 到 AE、AE 到 CS——每项交接都需要 SLA、追踪机制，以及明确的责任人确保跟进落实。

### 营收团队协同（Revenue Team Alignment）
营销、销售与客户成功必须就定义达成一致。若营销将某条线索称为 MQL，但销售不愿跟进，说明定义存在问题。协同会议并非可选项。

## 线索生命周期框架

### 阶段定义

| 阶段 | 进入标准 | 退出标准 | 负责人 |
|-------|------------|------------|--------|
| **订阅者** | 选择订阅内容（博客、新闻通讯） | 提供公司信息或表现出互动 | 营销 |
| **线索** | 已识别联系人并掌握基本信息 | 符合最低适配标准 | 营销 |
| **MQL** | 通过适配与互动门槛 | 销售在 SLA 内接受或拒绝 | 营销 |
| **SQL** | 销售接受并通过沟通进行资格验证 | 创建商机或进行线索回收 | 销售（SDR/AE） |
| **商机** | 预算、权限、需求、时间线已确认 | 成交赢单或成交输单 | 销售（AE） |
| **客户** | 成交赢单的交易 | 扩展、续约或流失 | CS / 客户经理 |
| **推广者** | 高 NPS、推荐活动、案例研究 | 持续参与推广计划 | CS / 营销 |

### MQL 定义

MQL 需同时满足**适配（fit）**与**互动（engagement）**：

- **适配得分** — 该人员是否符合您的 ICP？（公司规模、行业、职位、技术栈）
- **互动得分** — 是否表现出购买意向？（访问定价页面、申请演示、多次访问）

二者缺一不可。完全符合条件但从未互动的公司并非 MQL。每个电子书都下载的学生并非 MQL。

### MQL 到 SQL 交接 SLA

明确响应时间并予以文档化：
- MQL 警报发送至指定销售代表
- 代表在**4 小时内**（工作时间）联系
- 代表在**48 小时内**完成资格验证或拒绝
- 被拒绝的 MQL 进入回收培育流程，并注明拒绝原因代码

**关于完整生命周期阶段模板与 SLA 示例，详见 [references/lifecycle-definitions.md](references/lifecycle-definitions.md)**

## 线索评分

### 评分维度

**显式评分（适配）** — 关于"谁"：
- 公司规模、行业、营收
- 职位、职级、部门
- 技术栈、地域

**隐式评分（互动）** — 关于"做了什么"：
- 页面访问（尤其是定价页、演示、案例研究）
- 内容下载、网络研讨会参会
- 邮件互动（打开、点击）
- 产品使用（针对 PLG）

**负面评分** — 淘汰性信号：
- 竞品邮箱域名
- 学生/个人邮箱
- 退订、垃圾邮件投诉
- 职位不匹配（实习生、学生）

### 构建评分模型

1. 定义您的 ICP 属性并设定权重
2. 从已成交数据中识别高意图行为信号
3. 为每个属性与行为设定分值
4. 设定 MQL 阈值（通常为 100 分制中的 50-80 分）
5. 与历史数据对照测试——模型是否能正确识别过去的成交
6. 上线、测量并每季度校准

### 常见评分错误

- 对内容下载赋予过高权重（研究 ≠ 购买意向）
- 未纳入负面评分（会让不良线索漏过）
- 设定后遗忘（买家行为会变化，需每季度校准）
- 将所有页面访问等量评分（定价页 ≠ 博客文章）

**关于详细评分模板与示例模型，详见 [references/scoring-models.md](references/scoring-models.md)**

## 线索路由

### 路由方式

| 方法 | 运作方式 | 适用场景 |
|--------|----------------------|----------|
| **轮询（Round-robin）** | 平均分配给各代表 | 辖区均等、商机规模相近 |
| **基于辖区** | 按地域、行业或细分分配 | 区域团队、行业专家 |
| **基于账户** | 指定账户分配给指定代表 | ABM 策略、战略账户 |
| **基于技能** | 按商机复杂度、产品线或语言路由 | 产品线多元、全球团队 |

### 路由规则要点

- 优先路由至**最匹配**的匹配项，再回退至通用规则
- 包含**备选负责人** — 未分配线索会迅速流失线索，浪费销售管道
- 轮询需考虑**代表容量与可用性**（休假、配额完成情况）
- 记录每一次路由决策，便于审计与优化

### 线索获取速度（Speed-to-Lead）

响应时间是线索转化的最大单一因素：
- **5 分钟内**联系 = 转化可能性高 21 倍（Lead Connect）
- **30 分钟后**，转化概率下降 10 倍
- **24 小时后**，线索实际上已失去活跃度

构建优先考虑速度的路由规则。立即向代表发送警报。若 SLA 未达，进行升级处理。

**关于路由决策树与平台特定配置，详见 [references/routing-rules.md](references/routing-rules.md)**

## 管道阶段管理

### 管道阶段

| 阶段 | 必填字段 | 退出标准 |
|-------|----------------|---------------|
| **已资格化** | 联系人信息、公司、来源、适配得分 | 已预约发现通话 |
| **发现** | 痛点、现有方案、时间线 | 需求已确认，演示已预约 |
| **演示/评估** | 技术需求、决策人 | 正向评估，已要求方案 |
| **方案** | 定价、条款、干系人地图 | 方案已交付并完成评审 |
| **谈判** | 红线、审批链、成交日期 | 条款达成一致，合同已发送 |
| **已成交赢单** | 已签署合同、付款条款 | 交接至 CS 完成 |
| **已成交输单** | 输单原因、竞品（如有） | 已记录复盘 |

### 阶段卫生（Stage Hygiene）

- **每阶段必填字段** — 不得让代表在填写必填数据前推进商机
- **停滞商机警报** — 标记停留阶段时间超过平均值（如 2 倍平均天数）的商机
- **跳阶段检测** — 当商机跨阶段跳转（如从"已资格化"直接跳至"方案"而跳过"发现"）时发出警报
- **成交日期纪律** — 日期推进必须有理由，不得静默推进

### 管道指标

| 指标 | 揭示的内容 |
|--------|-------------------|
| 阶段转化率 | 商机在何处流失 |
| 阶段平均停留时间 | 商机在何处停滞 |
| 管道速度 | 漏斗每日通过的交易额 |
| 覆盖率比率 | 管道价值与配额（目标 3-4 倍） |
| 来源赢单率 | 哪些渠道能产生真实收入 |

## CRM 自动化工作流

### 必要自动化

- **生命周期阶段更新** — 当满足条件时自动推进阶段
- **交接时任务创建** — MQL 分配至代表时创建跟进任务
- **SLA 警报** — 代表未达响应时间 SLA 时通知负责人
- **商机阶段触发** — 自动发送方案、更新预测、成交时通知 CS

### 营销到销售自动化

- **MQL 警报** — 即时通知指定代表，并附带线索上下文
- **会议预约** — 通过日程安排工具预约商机时通知 AE
- **线索活动摘要** — 活跃线索高意图行动每日汇总
- **重新互动触发** — 线索恢复访问网站时通知销售

### 日程安排集成

- **轮询日程安排** — 将会议均摊至团队
- **基于条件的路由** — 企业级线索分配至高级 AE，中小企业线索分配至初级代表
- **会前信息丰富** — 通话前自动填充 CRM 记录
- **缺席工作流程** — 商机人未参会时自动跟进

**关于平台特定工作流方案，详见 [references/automation-playbooks.md](references/automation-playbooks.md)**

## 交易台（Deal Desk）流程

### 何时需要交易台

- ACV 高于 **$25K**（或非标准交易的自设阈值）
- 非标准付款条款（净 90 天、季度结算）
- 多年期合同及定制定价
- 超出公开层级的量级折扣
- 定制法律条款或 SLA

### 审批工作流层级

| 交易规模 | 审批要求 |
|-----------|-------------------|
| 标准定价 | 自动审批 |
| 10-20% 折扣 | 销售经理 |
| 20-40% 折扣 | 销售 VP |
| 40% 以上折扣或定制条款 | 交易台评审 |
| 多年期/企业级 | 财务 + 法务 |

### 非标准条款处理

记录每一次例外。追踪哪些非标准条款最常被提出——若所有人都提出同样的例外，则应将该例外视为标准条款。每季度评审。

## 数据卫生与信息丰富

### 去重策略

- **匹配规则** — 邮箱域名 + 公司名称 + 电话号码作为主要匹配键
- **合并优先级** — CRM 记录优先于营销自动化；字段以最新活动信息为准
- **定时去重** — 每周运行自动化去重，对边缘情况进行人工复核

### 必填字段执行

- 在每个生命周期阶段强制执行必填字段
- 字段为空时阻止推进阶段
- 采用渐进式信息完善——无需一次性要求全部信息

### 信息丰富工具

| 工具 | 优势 |
|------|----------|
| **Clearbit** | 实时信息丰富，适合技术公司 |
| **Apollo** | 联系数据 + 序列，适合潜在客户拓展 |
| **ZoomInfo** | 企业级，最大的 B2B 数据库 |

### 季度审计清单

- 审查并合并重复数据
- 验证过期联系人的邮箱投递可达性
- 归档 12 个月以上无活动联系人的数据
- 审计生命周期阶段分布情况（排查瓶颈）
- 在样本集上验证信息丰富数据的准确性

## RevOps 指标看板

### 关键指标

| 指标 | 公式/定义 | 基准 |
|--------|---------------------|-----------|
| 线索转 MQL 率 | MQL / 总线索 | 5-15% |
| MQL 转 SQL 率 | SQL / MQL | 30-50% |
| SQL 转商机 | 商机 / SQL | 50-70% |
| 管道速度 |（# 交易 × 平均交易规模 × 赢单率）/ 平均销售周期 | 随 ACV 变化 |
| CAC | 总销售 + 营销投入 / 新客户 | LTV:CAC > 3:1 |
| LTV:CAC 比率 | 客户生命周期价值 / CAC | 3:1 至 5:1 为健康区间 |
| 线索获取速度 | 从信息表填写至首次代表联系的时间 | 理想值 < 5 分钟 |
| 赢单率 | 成交赢单 / 总商机 | 20-30%（因业务而异） |

### 看板结构

构建三个视图：
1. **营销视图** — 线索量、MQL 率、来源归因、每个 MQL 成本
2. **销售视图** — 管道价值、阶段转化率、速度、预测准确性
3. **执行视图** — CAC、LTV:CAC、收入与目标对比、管道覆盖率
