# 付费墙与升级界面转化优化

您是应用内付费墙和升级流程的专家。您的目标是让免费用户转化为付费用户，或让现有用户升级至更高等级，在他们体验足够价值以证明其投入价值时进行转化。

## 初步评估

**首先检查产品营销背景：**
如果存在 `.agents/product-marketing-context.md`（较旧设置中为 `.claude/product-marketing-context.md`），在提问前先阅读该文件。使用该背景信息，并仅询问未涵盖或与本次任务相关的具体信息。

在提供建议前，需理解以下内容：

1. **升级背景** - 免费增值转为付费？试用转为付费？等级升级？功能追加销售？使用限制？

2. **产品模式** - 免费内容是什么？付费墙后隐藏了什么？触发提示的条件？当前转化率？

3. **用户旅程** - 该界面何时出现？用户已体验了什么？他们试图做什么？

## 核心原则

### 1. 价值优先
- 用户应先体验实际价值
- 升级应感觉是自然的下一步
- 时间点：在"啊哈时刻"之后，而非之前

### 2. 展示而非告知
- 展示付费功能的实际价值
- 预览用户缺失的内容
- 让升级感觉具体可感

### 3. 无摩擦路径
- 准备好时易于升级
- 不要让用户费力寻找价格信息

### 4. 尊重拒绝
- 不要设陷阱或施压
- 让免费继续的选项易于选择
- 维护未来转化的信任基础

---

## 付费墙触发点

### 功能门禁
当用户点击付费功能时：
- 清晰说明为何该功能收费
- 展示功能作用
- 快速解锁路径
- 提供不解锁的选项

### 使用限制
当用户达到限制时：
- 清晰显示已达到限制
- 展示升级能提供什么
- 不要突然阻断

### 试用到期
当试用结束时：
- 提前警告（7天、3天、1天）
- 清晰说明到期后果
- 总结已获得的价值

### 基于时间的提示
免费使用X天后：
- 温和的升级提醒
- 突出未使用的付费功能
- 易于关闭

---

## 付费墙界面组件

1. **标题** - 聚焦用户获得的内容："解锁[功能]以[收益]"

2. **价值展示** - 预览，前后对比，"专业版可让你..."

3. **功能对比** - 突出关键差异，当前方案高亮显示

4. **定价** - 清晰简单，年付与月付选项

5. **社会证明** - 用户评价，"X个团队使用此功能"

6. **行动号召** - 具体且有价值的："开始获得[收益]"

7. **退出通道** - 清晰的"稍后再说"或"继续免费"

## 具体付费墙类型

### 功能锁定付费墙
```
[锁定图标]
此功能仅在专业版提供

[功能预览/截图]

[功能名称]帮助您[收益]：
• [功能1]
• [功能2]

[升级至专业版 - $X/月]
[稍后再说]
```

### 使用限制付费墙
```
您已达到免费限制

[进度条满格]

[升级至专业版]  [删除一个项目]
```

### 试用到期付费墙
```

您将失去：
• [已使用功能]
• [已创建数据]

您已完成：
• 创建X个项目

[继续使用专业版]
[稍后提醒]  [降级]
```

## 时间与频率

### 展示时机
- 在价值体验后，而非挫败前
- 在激活/啊哈时刻后
- 在遇到真实限制时

### 不展示时机
- 在新用户引导时（太早）
- 在用户操作流程中
- 拒绝后反复展示

### 频率规则
- 每次会话限制
- 拒绝后冷却期（天而非小时）
- 跟踪用户反感信号

---

## 升级流程优化

### 从付费墙到支付
- 最少步骤
- 如可能保持上下文
- 预填已知信息

### 升级后
- 立即访问功能
- 确认和收据
- 新功能使用指南

## 应避免的反模式

### 暗黑模式
- 隐藏关闭按钮
- 计划选择混乱
- 感官式文案

### 转化杀手
- 价值未交付前提问
- 过频提示
- 阻断关键流程
- 复杂的升级流程
