# 创建游戏资源

将游戏的视觉意图转化为一致的、引擎可用的资源集。将图像生成视为受控流程中的一个生产工具，而不是证明资源可发布的依据。

## 核心工作流程

1. **在创新前进行审视。** 寻找现有的截图、概念艺术、精灵、模型、字体、导入设置、相机构图、目标分辨率和命名规范。除非用户要求重新设计，否则保留一致的方向。
2. **锁定技术框架。** 记录引擎、2D/3D、相机/视图、原生显示尺寸、资源尺寸、世界比例、透明度、调色板、过滤、动画帧、纹理预算和目标平台。使用 `assets/art-direction-brief.md` 作为可复制的简报。
3. **命名视觉系统。** 定义形状语言、轮廓优先级、价值结构、调色板角色、材质、光照、细节密度、边缘处理和运动特征。使用具体的视觉属性；不要用活体艺术家的名字来替代艺术指导。
4. **制作资源清单。** 复制 `assets/asset-manifest.json`，然后列出每个必需的资源、状态、变体、尺寸、枢轴、碰撞角色、来源、许可和审批状态。区分生产资源和可丢弃的灰盒占位符。
5. **批准一个视觉目标。** 在生成完整资源集之前创建或选择一个代表性的英雄资源或小型风格板。在游戏实际比例和游戏玩法背景下评估它。如果用户已将选择权委托出去，选择最强的可行方向并记录决策，而不是阻止。
6. **作为家族生成相关资源。** 将批准的目标作为编辑/参考输入进行复用。保持调色板、视图、比例、光照、轮廓和纹理密度不变。生成小而连贯的批次；避免无关的单独提示导致漂移。
7. **确定性地规范化。** 使用常规的图像/DCC工具进行裁剪、调整大小、锚定、切片、命名、压缩和检查alpha。未经检查，不要信任生成的网格、透明度、接缝、枢轴、拓扑或尺寸。使用捆绑的脚本进行光栅QA和接触片。
8. **使用引擎原生设置导入。** 故意设置过滤、Mipmap、每单位/世界比例、色彩空间、压缩、精灵切片、纹理类型、材质和碰撞。编辑引擎文件前，先阅读相关引擎技能。
9. **在上下文中验证。** 检查接触片和实际游戏的原生分辨率。检查轮廓、比例、动画稳定性、接缝、可读性、调色板、碰撞匹配、内存和压缩伪影。在源资源上迭代，而不仅仅是运行时补偿。
10. **记录来源。** 在清单旁边保留源URL/工具、许可或生成说明、编辑历史和限制。当流程可以时，保留嵌入的来源元数据。

## 选择生产路径

| 需求 | 默认路径 |
|------|----------|
| 现有资源需要受控的更改 | 编辑原始/参考；说明必须保持不变的内容 |
| 新的2D视觉家族 | 批准种子 → 生成/源家族 → 规范化 → 预览 → 导入 |
| 真像素艺术 | 将生成的工作作为草稿；使用像素工具强制执行网格、调色板、簇和帧 |
| 可平铺的表面或瓦片集 | 生成一个小型家族；修复接缝；在批准前测试重复的3×3 |
| UI艺术或图标 | 保持文本和交互代码原生；对于简单的几何符号，优先使用SVG/矢量 |
| 3D模型或材质 | 将概念作为参考；在DCC中创建/清理；验证拓扑、UV、比例、枢轴和LODs |
| 没有生成/编辑工具可用 | 构建简报和清单；获取许可资源或保留明确的灰盒占位符 |
| 音频资源 | 将声音实现和混音路由到 `audio-design`；仍在清单中跟踪来源/许可 |

## 图像生成交接

当安装了功能强大的图像生成或编辑工具时，使用它进行实时视觉创建。如果工作区暴露了 `imagegen` 技能，请阅读并遵循它以进行实际生成/编辑调用；此技能拥有游戏艺术简报、约束、规范化和验收门。

使用这些模块构建提示：

```text
角色/目的：[游戏玩法角色] 的生产资源
主题：[特定对象/角色和动作]
视图：[正交/俯视/侧视/四分之三]，[相机和朝向]
艺术指导：[形状语言]，[调色板角色]，[材质]，[边缘处理]
游戏比例阅读：[必须以 WxH 存活的轮廓和焦点细节]
技术输出：[尺寸/长宽比]，[透明或场景背景]，[帧/插槽数量]
锁定：保留 [身份、比例、调色板、服装、光照、线条重量]
排除：文本、标签、草稿框架、场景、重复对象、裁剪边缘、签名
```

对于编辑，说明更改的内容和保持固定的内容。当可用时，通过工具的原生透明度选项请求透明输出，然后验证alpha通道——提示文字本身并不能保证透明度。

## 光栅QA配方

检查约束并发出机器可读的报告：

```bash
python scripts/asset_report.py assets/player-idle.png \
  --expect-size 64x64 --require-alpha --max-colors 48 --json
```

在棋盘格上构建最近邻接触片：

```bash
python scripts/build_preview_sheet.py output/player/*.png \
  --out output/player-preview.png --columns 4 --cell-size 192
```

相对于此技能目录运行脚本路径，或首先解析已安装的技能路径。两个脚本都需要 Python 3.10+ 和 Pillow。当它不可用时，使用 `python -m pip install -r scripts/requirements.txt` 安装唯一的依赖项。

## 质量门

- **凝聚力：** 相关资源共享调色板角色、线/边缘处理、视图、光照方向、比例和细节密度。
- **游戏玩法可读性：** 轮廓和状态变化在原生分辨率、运动中和真实背景下保持清晰。
- **技术匹配：** 精确的尺寸/帧数、可用的alpha、稳定的锚定/枢轴、正确的色彩空间/过滤、没有剪裁内容、没有意外的标签或烘焙的草稿铬。
- **动画：** 身份、体积、比例、服装、朝向和基线不会漂移；时间和预期在引擎预览中可读。
- **瓦片/背景：** 必需的边缘无缝平铺；重复是可接受的；视差层有意深度且没有烘焙的碰撞提示。
- **3D：** 检查变换、比例、枢轴、法线、UV、材质、拓扑、 rig、碰撞代理、LODs 和运行时格式，而不是从渲染中推断。
- **权利：** 每个发布的文件都有记录的来源和与项目兼容的条款。

仅凭提示结果不要将资源称为生产就绪。批准需要相关的技术检查加上引擎或原生比例的视觉检查。
