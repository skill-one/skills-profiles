# Roguelike

Roguelike 的开发指南——回合制引擎、程序化迷宫、视野范围、永久死亡和运行经济。这是一种 **组合式** 技能：它将程序化生成、瓦片地图、存档处理和 AI 协调成一个基于运行的游戏。它不会重新教授噪声/RNG 或瓦片地图 API；它定义了游戏循环以及让一个 *运行* 令人着迷的系统。

## 使用场景

- 在构建一个 **回合制、网格制** 的迷宫爬行者时使用，其中每次死亡都会结束运行并重新生成世界——即 rogue-like 或 "roguelite"（带有元进度）。
- 在设计程序化迷宫、视野范围/战争迷雾、永久死亡风险或战利品表时使用。

**不使用场景：** 带有 rogue-like *装饰* 的实时动作 → 构建 **动作** 类型 (`平台游戏`/`第一人称射击游戏`) 并叠加 `程序化生成`。没有永久死亡的深度统计/任务/对话 → `角色扮演游戏`。需要开放世界/制作 → `生存制作游戏`。

## 什么构成了 rogue-like（设计锚点）

社区参考是 **柏林解释**（RogueBasin、IRDC 2008）：一组“roguelike 特征”因素，而不是一个清单。高价值的因素是设计目标：
**随机环境生成、永久死亡、回合制、网格制、非模态**（所有操作在一个模式中），**复杂性**（许多物品/怪物交互），**资源管理**，**砍杀与砍伐**，以及 **探索与发现**。深入这些感觉就像 rogue-like；有意识地选择保留哪些。通常，“roguelite” 会用元进度来放宽永久死亡。

## 核心循环

**执行一个回合（移动 / 战斗 / 使用）→ 世界解决它的回合 → 查看新状态 → 下降 / 搜刮 / 幸存 → 死亡并重新开始一个全新的迷宫。** 可重玩性来自于每次运行世界都在变化，而不是玩家记住一个固定的布局。

## 必须有的系统

1. **回合调度器** — 能量/主动性系统，使得快速行动的角色更频繁地行动（模式 2）。
2. **网格地图 + 移动** — 瓦片坐标；碰撞攻击；阻挡/可通行查询。
3. **程序化迷宫生成器** — 房间 + 走廊，或 BSP/元胞；保证连通性。
4. **视野范围 + 已探索记忆** — 当前可见的与之前见过的（模式 3 / 参考）。
5. **战斗 + 实体** — 生命值、攻击/防御、状态；怪物遵循与玩家相同的规则。
6. **战利品 + 掉落表** — 加权、深度缩放的物品/怪物生成（参考）。
7. **永久死亡 + （可选）元进度** — 清除运行；仅保留解锁/得分。
8. **消息日志 + 清晰 UI** — 玩家从文本/状态中推理；显示数字和事件。

## 设计旋钮

| 旋钮 | 效果 | 备注 |
|------|------|------|
| 迷宫大小 / 房间数量 | 运行长度、密度 | 随深度缩放。 |
| 连通性保证 | 没有无法到达的房间 | 生成后始终验证可达性。 |
| 怪物密度 / 深度曲线 | 难度递增 | 按深度加权表生成。 |
| 战利品稀有度权重 | 力量变化 | 稀有 = 更大的波动；识别增加了发现。 |
| 视野范围 / 照明 | 紧张感、信息 | 较小半径 = 更吓人、更慢。 |
| 资源稀缺性（食物/生命值/弹药） | 下降压力 | 经典 RLs 中的核心紧张杠杆。 |
| 永久死亡 vs 元进度 | 运行风险 vs. 留存 | Roguelite 使其缓和。 |
| 识别 / 未知项 | 探索价值 | 未识别的物品奖励实验。 |
| 可播种 RNG | 每日运行、调试 | 始终允许一个固定种子（见 `程序化生成`）。 |

## 模式

### 1. 确定性、可播种的运行 RNG

```python
# 伪代码。每个运行一个播种 RNG 使迷宫可重复（每日运行、错误重现）。
run_seed = chosen_seed or random_seed()
rng = Rng(run_seed)                 # 使用您的引擎的可播种 RNG，而不是全局随机
dungeon = generate_dungeon(rng, depth)   # 相同种子 + 深度 => 相同迷宫
# 在存档中保留 run_seed，以便崩溃可以恢复相同的世界（见 `存档系统`）。
```

### 2. 基于能量的回合调度器（速度不同）

```python
# 伪代码。每个角色每刻钟获得能量，并在有足够能量时行动。
# 更快的角色每刻钟获得更多，因此他们更频繁地行动——没有固定的“玩家然后敌人”。
TURN_COST = 100
def next_actor(actors):
    while True:
        for a in actors:                 # 稳定顺序避免偏向一方
            a.energy += a.speed          # 例如，速度 100 = 正常，150 = 加速
            if a.energy >= TURN_COST:
                a.energy -= TURN_COST
                return a                 # 这个角色现在执行一个确切的操作
```

### 3. 视野范围 + 已探索记忆

```python
# 伪代码。每次玩家移动时重新计算可见性。
visible = compute_fov(map, player.pos, radius=8)   # 对称阴影投射（见参考）
for cell in visible:
    explored.add(cell)                  # 永久记住它（暗淡“战争迷雾”）
# 渲染：可见 -> 亮；已探索但不可见 -> 暗淡；从未见过 -> 隐藏。
```

使用经过验证的视野算法（递归阴影投射或对称阴影投射）。不要对每个单元格进行简单的射线投射——它会产生不对称的、“闪烁”的视野。见参考。

## 陷阱 / 失败模式

- **不连通的迷宫** → 玩家无法到达的房间。始终运行连通性/洪水填充并通过雕刻走廊，直到每个可通行的单元格都可到达。
- **简单的视野范围** → 闪烁或不对称的视野（你能看到他们，他们看不到你）。使用阴影投射；测试对称性。
- **假装是回合制的实时循环** → 输入竞争和双倍移动。一次解决一个离散的回合；排队输入。
- **平坦难度** → 没有下降压力。按深度缩放怪物/战利品，并保持资源稀缺。
- **永久死亡会清除元解锁** → 愤怒。在存档时将 *运行* 状态（清除）与 *配置文件* 状态（解锁、得分）分开（见 `存档系统`）。
- **“永久死亡”游戏的存档作弊** → 如果你想真正的永久死亡，在加载时删除或使运行存档无效；仅保留配置文件。
- **无法读取的状态** → 玩家无法计划。显示生命值、回合结果和消息日志。

## 组合（从这些技能构建）

- **生成：** `程序化生成`（噪声、播种 RNG、迷宫/房间算法）——可重玩性的引擎。
- **地图渲染：** `godot-tilemap` / `unity-tilemap-2d` 用于网格；`关卡设计` 用于固定房间/保险库。
- **敌人：** `游戏 AI` 用于怪物决策（通常在网格上很简单：追逐/逃跑/巡逻）。
- **持久性：** `存档系统` 用于运行恢复、配置文件/元进度，以及真正的永久死亡清除。
- **脚本/数据：** `godot-resources` / `unity-scriptableobjects` 将物品、怪物和掉落表定义为数据。
- **UI：** `godot-ui-control` 用于消息日志、背包和 HUD。
- **感觉：** `游戏感觉` 用于命中/死亡汁液——屏幕抖动和命中停止，在回合制网格上出售冲击。
