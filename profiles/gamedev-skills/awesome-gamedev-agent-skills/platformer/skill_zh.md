# 平台游戏

一个用于2D平台游戏的开发手册——包括跑动/跳跃控制器的手感、关卡结构、危险元素和目标。这是一种**组合式**技能：它将引擎移动技能、瓦片地图技能和设计技能组合成一个可运行的游戏。它**不会**重新教授物理或瓦片地图；它告诉你该构建什么以及如何让跳跃感觉良好。

## 使用场景

- 在构建横版滚动或单屏平台游戏时使用，例如“马里奥”风格/“ celeste”风格，或任何核心动作是**在表面之间跳跃**的游戏。
- 当跳跃感觉漂浮、不响应或“不公平”时，需要手感修复（猫头鹰时间、跳跃缓冲、可变高度、角落修正）。

**不使用场景：** 无重力的俯视移动 → 直接使用引擎移动技能。3D第一人称移动 → `fps-shooter`。网格/回合移动 → `roguelike`。对于原始的运动体API，使用 `godot-2d-movement`（或你的引擎的控制器技能）。

## 核心循环

**观察间隙/危险 → 决定跳跃或移动 → 安全落地（或死亡）→ 到达下一个检查点/目标。** 一个平台游戏的生或死取决于这个单一跳跃的*即时*手感，重复数千次。首先优化控制器；其他都是内容。

## 必须的系统

1. **跑动/跳跃控制器** — 水平加速/减速、重力、跳跃，以及以下手感辅助。
2. **实体+单向碰撞** — 地面、墙壁和“可穿透”平台。
3. **关卡几何** — 瓦片地图或手动放置的碰撞器；可玩空间。
4. **危险+死亡/重生** — 尖刺、坑洞、敌人；重置到最后一个检查点。
5. **检查点 / 关卡目标** — 进度标记和胜利条件（旗帜、门、出口）。
6. **摄像机** — 跟随玩家，带有死区和预读，限制在关卡边界内。
7. **Juice** — 落地尘土、挤压/拉伸、击停、音效。廉价，手感回报巨大。

## 设计旋钮（让跳跃感觉正确）

通过**结果**（高度以瓦片为单位，到达顶点所需时间以秒为单位）而不是原始数字来调整这些。

| 旋钮 | 效果 | 合理的起始点 |
|------|------|--------------|
| 最大跳跃高度 | 到达 | 3-4 瓦片 |
| 到达顶点所需时间 | “重量”/快速感 | 0.30-0.40 秒 |
| 下落重力乘数 | 快速、不漂浮的下落 | 1.5-2.0×上升重力 |
| 猫头鹰时间 | 离开平台后立即跳跃 | 0.08-0.12 秒 (~5-7 帧@60) |
| 跳跃缓冲 | 在落地前按下仍可跳跃 | 0.10-0.15 秒 |
| 可变跳跃切割 | 点击 = 短跳，按住 = 全跳 | 释放时向上速度 ×0.4-0.5 |
| 顶点悬停 | 在顶部短暂漂浮以进行空中控制 | 在 `|vy|`<阈值附近减少重力 ×0.5 |
| 地面加速 / 摩擦力 | 响应性 vs. 冰面 | 在 0.05-0.1 秒内达到最高速度 |
| 角落修正 | 推过被1-2像素遮挡的平台边缘 | 向侧方推约 4 像素 |

根据*手感*值而不是猜测来推导重力和跳跃速度——见模式1。

## 模式

### 1. 从高度+时间解决跳跃物理（而不是魔法数字）

```python
# 伪代码。选择你想要的手感，然后推导物理。y轴指向向下。
# 从运动学：h = (g * t^2) / 2 和 v0 = g * t。
JUMP_HEIGHT   = 3.5 * TILE      # 多高，以世界单位计
TIME_TO_APEX  = 0.35            # 到达顶点的秒数

gravity       = (2 * JUMP_HEIGHT) / (TIME_TO_APEX ** 2)   # 上升重力
jump_velocity = -(2 * JUMP_HEIGHT) / TIME_TO_APEX         # 负值 = 向上
fall_gravity  = gravity * 1.8   # 下落时更重 → 感觉不那么漂浮
```

### 2. 猫头鹰时间+跳跃缓冲+可变高度（手感核心）

```python
# 伪代码在每帧更新中。dt = 自上一帧以来的秒数。
# 计时器向下计数；在站立时刷新猫头鹰时间，在新的按下时刷新缓冲时间。
if on_floor:
    coyote_timer = COYOTE_TIME           # 0.1
if jump_pressed_this_frame:
    buffer_timer = JUMP_BUFFER           # 0.12
coyote_timer -= dt
buffer_timer -= dt

# 如果我们最近按下了并且最近站在地面上，就允许跳跃。
if buffer_timer > 0 and coyote_timer > 0:
    velocity.y   = jump_velocity
    buffer_timer = 0
    coyote_timer = 0                     # 消耗两者，以防止双重跳跃

# 可变高度：在上升时提前释放跳跃会缩短弧线。
if jump_released_this_frame and velocity.y < 0:
    velocity.y *= 0.45

# 非对称重力：下落比上升更快。
g = fall_gravity if velocity.y > 0 else gravity
velocity.y += g * dt
```

### 3. 单向平台

从上方实体，下方可穿透。大多数引擎在瓦片/碰撞器上暴露“单向碰撞”标志；启用它，并让玩家通过在玩家按住下+跳跃时禁用该碰撞几帧来**掉落**。不要重新实现碰撞数学。

## 陷阱/失败模式

- **每帧移动未按 `dt` 缩放** → 速度随帧率变化。每个速度积分和计时器必须使用 `dt`。（见 `physics-tuning`。）
- **漂浮的跳跃** → 对称重力。使下落重力比上升重力更重。
- **“跳跃没有注册”** → 无输入缓冲。在落地前缓冲按下的动作约 0.1 秒。
- **“我掉下去了，不能跳跃”** → 无猫头鹰时间。在离开地面后允许跳跃约 0.1 秒。
- **粘在墙上 / 卡在瓦片接缝处** → 使用单个胶囊/盒状碰撞器，而不是每个瓦片的碰撞器，并添加角落修正。
- **高速穿过地板** → 启用连续碰撞 / 为快速运动体使用较小的固定固定步长（见 `physics-tuning`。）
- **摄像机突然移动并引起恶心** → 平滑/插值跟随，添加死区，限制在边界内。
- **由于教学不当而产生的难度墙** → 在组合它们之前，每个区域引入一个机制。

## 组合（从这些技能构建）

- **控制器运动体：** `godot-2d-movement` (Godot `CharacterBody2D`)；对于其他引擎使用引擎核心+物理技能 (`unity-physics`, `phaser-arcade-physics`, `pygame-core`)。
- **关卡：** `godot-tilemap` / `unity-tilemap-2d` 用于几何；`level-design` 用于布局、节奏和教学顺序。
- **手感/物理：** `physics-tuning` 用于步长、CCD 和稳定性。
- **输入：** `input-systems` 用于缓冲、重新绑定和游戏手柄支持。
- **润色：** `audio-design` 用于音效/音乐；引擎动画技能用于挤压/拉伸。
- **流程：** `prototype-fast` 在构建内容前快速灰盒化控制器。
