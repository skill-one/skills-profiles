# caveman — 规范编码

适用于SPEC.md编写、规范引用的散文、反向传播条目。
不适用于代码、错误字符串、提交信息、PR描述。

## 语法

- 删除冠词（a、an、the）。
- 删除填充词（just、really、basically、simply、actually）。
- 删除在片段中可用的助动词（is、are、was、were、being）。
- 删除客套话。
- 不使用犹豫表达（跳过"might"、"perhaps"、"could be worth"）。
- 片段形式可以。
- 短同义词：fix > implement，big > extensive，run > execute。

## 符号

优先使用符号代替文字：

```
→   导致 / 变为 / 在 <x>
∴   因此 / 修复
∀   对所有 / 每个
∃   存在 / 一些
!   必须 / 需要
?   可能 / 可选 / 未知
⊥   从不 / 禁止 / 空值
≠   不等于
∈   在
∉   不在
≤   至多
≥   至少
&   和
|   或
§   章节引用
```

## 必须逐字保留

从不压缩：

- 代码块、代码片段、带反引号的单行。
- 路径：`src/auth/mw.go`。
- URL。
- 标识符：函数名、变量名、环境变量。
- 数字和版本号。
- 错误信息字符串。
- SQL、正则表达式、JSON、YAML。
- 引号字符串。

## 形式

**不变式**：
```
V<n>: <主语> <关系> <条件>
V1: ∀ req → 在处理器之前进行身份验证检查
V2: token过期 ≤ 当前时间 → 拒绝
```

**错误行**（§B下的管道表）：
```
id|日期|原因|修复
B1|2026-04-20|token `<` 而不是 `≤`|V2
```

**任务行**（§T下的管道表）：
```
id|状态|任务|引用
T3|x|添加身份验证中间件|V1,I.api
```
状态：`x` 完成，`~` 进行中，`.` 待办。转义文字 `|` 为 `\|`。

**接口**：
```
<类型>: <名称> → <形式>
api: POST /x → 200 {id:string}
cmd: `foo bar <参数>` → stdout JSON
env: FOO_KEY ! 设置
```

## 示例

**错误**：
> 系统应确保每个传入请求在被转发到相应的处理器函数之前都经过适当的身份验证。

**正确**：
> V1: ∀ req → 在处理器之前进行身份验证检查

**错误**：
> 我们发现中间件中的token过期检查使用了严格的"小于"比较运算符，这意味着token会在过期时刻被拒绝。

**正确**：
> B1: token `<` 而不是 `≤` → 在过期边界拒绝。

**错误**：
> /x的POST端点接受JSON正文并返回200响应，其中包含包含创建id的对象。

**正确**：
> api: POST /x → 200 {id}

## 边界

- 用户要求散文解释 → 切换到正常英语。
- 外部评审的规范文档（RFC、提案）→ 正常英语。
- 提交信息 → 正常英语（git读者期望如此）。
- 代码中的差异注释 → 正常英语。

## 不确定时

如果删除一个词会丢失事实，保留它。Caveman是压缩，不是截肢。
