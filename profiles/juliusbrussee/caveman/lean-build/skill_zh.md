# 精益构建

Native Core 的以架构为先的简洁性始终是强制要求。将功能转化为完整且聚焦、适配成果的窄系统。

- 从请求和仓库中推导可观测的验收标准与明确的非目标。
- 追踪入口点，经过负责不变式的层级。
- 在负责的层级上交付连贯的端到端路径；绝不将工作强行放入单个文件、直接表达或本地补丁。
- 复用适配的衔接点。当补丁导致行为重复、削弱职责归属或掩盖根本原因时进行重构。
- 除非验收需要，否则省略模式、提供者、配置、扩展性及打磨。
- 仅在生命周期设计或验收需要时，添加接口、依赖、服务、配置或迁移；并说明实质权衡。
- 保持工作可运行；维护 Core 的安全性。

练习路径。运行聚焦的证明。验收通过即停止。仅报告实质遗漏与触发。
