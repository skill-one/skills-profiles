# 管理评估门控实验

将每个生命周期变更视为生产控制操作。读取当前状态和结果，然后报告一个支持的建议或阻止。
当前代理的MCP有意设计为只读：control-api尚未强制执行完整的生命周期转换表和证据门控的原子操作。

## 不可协商的门控

1. 审查、检查、解释或建议的请求仅授权读取。
2. 永不批准结果悬而未决、所需护栏缺失或证据报告违规的实验。
3. 永不将实验提升转换为`verified_savings`。只有活跃的真实流量加上提供者因果、提供者完整的账本证据才能做到这一点。
4. 永不提供组织ID。项目和租户范围来自登录的Caveman身份和服务器RBAC。
5. 即使用户批准，也永不执行生命周期突变。确切的`<action>:<experiment_id>`字符串是代理生成的，并不能证明人类意图。
6. 未知状态和服务器错误失败关闭。报告确切的`cave_snake_code`。

## 第一步 — 加载项目和实验

优先使用MCP：

```text
caveman_context {}
caveman_experiment_get {"action":"get","experiment_id":"<id>"}
caveman_experiment_get {"action":"results","experiment_id":"<id>"}
```

当用户未指定ID时，使用`{"action":"list"}`。

CLI备用方案：

```bash
caveman cloud experiments list
caveman cloud experiments show <id>
caveman cloud experiments results <id>
```

如果登录、项目、实验或结果不可用，则停止。

## 第二步 — 评估证据

报告：

- 当前生命周期状态和安全等级；
- 控制和候选样本大小；
- 质量或评估结果；
- 当存在时，延迟、错误、成本、重试、丢弃和升级护栏；
- 证据成本；
- 回滚或暂停原因；
- 结果是否悬而未决、失败、可提升或活跃。

缺失不代表通过。如果必需字段缺失，请声明`evidence incomplete`，不要提出批准建议。

## 第三步 — 提出一个操作建议

允许的操作：

- `start` — 仅从可启动的草稿或配置了评分器的排队状态开始；
- `approve` — 仅在具有完整通过证据且当前角色可以批准的安全等级的情况下；
- `cancel` — 停止用户不再需要的非活动实验；
- `rollback` — 通过服务器的关联策略路径回滚活跃或有害的变更。当前部署可能诚实地使用`cave_not_implemented`拒绝此操作；永远不要将此响应描述为回滚。

显示建议和ID：

```text
建议操作：批准实验 7f...
原因：候选者通过质量和所有配置的护栏。
执行：阻塞，直到服务器权威的生命周期和证据门控交付。
```

不要将“管理它”或“做最好的事”等早期通用声明视为突变批准。

## 第四步 — 阻止不安全的执行

不要发出或运行可执行的生命周期命令。解释当前服务器尚未强制执行每个证据/状态转换的原子性。因此，CLI和MCP代理界面仅暴露实验读取。

## 第五步 — 外部操作员操作后重新读取

如果操作员表示他们执行了命令，请再次读取详细信息和结果。报告服务器观察到的后状态、审计或结果响应以及任何返回的策略交付状态。仅凭操作员意图绝不推断成功。

使用此关闭：

```text
操作：`<action> <experiment-id>`
之前：`<state>`
服务器响应：`<状态和cave_snake_code（如有）>`
之后：`<重新读取状态>`
依据：仅实验证据。除非签署的账本独立记录活跃、提供者因果的真实流量节省，否则验证的节省不变。
```
