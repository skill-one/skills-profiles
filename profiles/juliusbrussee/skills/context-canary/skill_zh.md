# 上下文金丝雀

上下文金丝雀是一种可以轻易检查的持久指令，其唯一工作就是明显地失败。经典形式：“每条回复都以我的名字开头。” 代理遵守这条指令几乎不耗费成本——因此当名字消失时，这种缺失就是数据。指令本身没有变得更难；代理对其早期上下文指令的掌控力变弱了。就像煤矿中的金丝雀一样，它在您真正关心的那些失败（被遗忘的约束、被忽视的惯例、重新商议的决定）开始出现在您的代码之前就先死亡了。

这种方法之所以有效，是因为上下文退化是**无声且渐进的**。模型不会宣布它们停止关注8万个token之前的指令，并且压缩摘要会悄无声息地删除持久指令。金丝雀将一个不可见的失败转换为一个二进制、按回合、零成本检查。关于为什么会出现这种情况的研究——上下文腐烂、中间丢失、指令漂移、压缩丢失——可以在**[references/research.md](references/research.md)**中找到。

## 何时使用这项技能

- 在长时间或高风险会话的开始安装金丝雀。
- 用户注意到金丝雀不再出现并询问发生了什么。
- 代理本身意识到它再也找不到其金丝雀合同中的上下文。
- 用户询问当前的上下文仍然有多可信。

## 金丝雀合同

被调用时，通过在一条简短的消息中明确声明合同来安装金丝雀，然后遵循它。默认格式——从那时起每条回复的第一行：

```
**Julius · t14 · ctx ok**
```

三个字段，每个字段探测不同的事物：

| 字段 | 示例 | 其失败的含义 |
|---|---|---|
| 名称 | `Julius` | 持久指令本身已从有效上下文中消失——遵守漂移或压缩将其删除。 |
| 回合计数器 | `t14` | 每条回复时加1。重置、跳过或重复意味着连续性中断——几乎总是压缩或摘要边界。 |
| 自检 | `ctx ok` / `ctx aging` / `ctx thin` | 代理的诚实估计。`aging`：会话很长，早期的细节在其对任务的当前工作感知中正在被总结。`thin`：代理正在重建早期的决定而不是记住它们。 |

使用用户的实际名称（如果未知则询问）。如果用户想要最简版本，仅使用名称即可——这是原始技巧，仍然可以捕捉到大的失败。永远不要解释、道歉或装饰金丝雀行；它必须保持字节稳定，以便人类可以在半秒内进行模式匹配。

**会话金丝雀与持久金丝雀。** 一个仅存在于对话中的金丝雀测试的是*对话*上下文是否存活（压缩、截断、漂移）。一个写入`CLAUDE.md`或代理内存中的金丝雀通过设计可以抵抗压缩——这意味着它测试的是是否在关注基于文件的指令，这是一个不同且较弱的信号。默认使用会话金丝雀；那是检测退化的一种。仅在用户希望所有会话中都保持这种习惯时才提供持久变体，并告诉他们它不再衡量什么。

## 发射规则

1. 金丝雀是**每条回复的第一行**，包括短回复、错误报告和工具调用后的回复。
2. 每条回复时增加计数器。如果不确定计数，这种不确定性本身就是一个信号——发出`t?`并标记它，永远不要猜测一个可能的数量。
3. 自检必须诚实。习惯性地报告`ctx ok`会破坏整个仪器。
4. 如果在任何时候金丝雀合同在上下文中找不到（您只知道它来自摘要，或者根本不知道），**请自行宣布故障**——不要等待用户注意到。

## 故障协议

故障是：金丝雀缺失、格式错误、计数器不连续，或代理侧的自我声明。

在发出警报之前进行校准——一个在其余连贯回复中错过的金丝雀是一个警告（记录下来，继续金丝雀，继续进行）。**连续两个错过的金丝雀、计数器不连续，或代理未能通过其自己的合同检查是确认故障。** 然后：

1. **停止信任漂移状态。** 不要使用您无法保证的当前上下文继续执行当前任务。
2. **检查点。** 将持久状态放在对话之外的地方：当前目标、做出的决定及其原因、接触的文件、已验证与进行中的内容、下一步。`HANDOFF.md`或存储库中的笔记文件可以工作。
3. **重新锚定。** 重新阅读项目指令（`CLAUDE.md`、原始任务声明）和检查点。向用户陈述三条或四行，说明您认为任务和约束是什么——以便他们可以廉价地纠正任何漂移。
4. **故意重置。** 建议用户开始一个新的会话（或运行一个明确的压缩），用检查点文件进行初始化，而不是勉强继续。退化的上下文不会愈合；它会累积。
5. **重新安装金丝雀**，计数器重置为`t1`，并注明生成：`t1 (gen 2)`。

在间隙后不要默默继续金丝雀，好像什么都没发生——这会破坏仪器的可信度，这是它唯一拥有的东西。

## 金丝雀告诉您什么和不告诉您什么

测试是一边的。一个**缺失**的金丝雀是退化强有力证据。一个**存在**的金丝雀是健康弱有力证据——一个廉价的风格习惯可以存活，而更难的约束（架构决策、“永远不要触摸X”）则悄无声息地腐烂，并且被塞入内存文件的金丝雀可以比它要监控的上下文存活得更久。将金丝雀视为烟雾探测器，而不是结构检查：当它响起时采取行动；当它安静时，在上下文窗口大约50%或任何压缩事件之后保持合理怀疑。

将其与减少金丝雀需要捕捉的廉价结构习惯配对：将持久决定保存在文件中而不是聊天中，在明确的边界处压缩而不是等待强制压缩，并且优先选择每个任务的新会话而不是一个永生的会话。详细信息和来源在**[references/research.md](references/research.md)**。
