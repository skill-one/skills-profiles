## 核心原则
- **保持状态可预测：** 单一事实来源，派生其他所有内容。
- **使数据流显式化：** 大多数情况下，属性向下传递，事件向上传递。
- **优先使用小型、专注的组件：** 更容易测试、重用和维护。
- **避免不必要的重新渲染：** 慎用计算属性和观察者。
- **可读性很重要：** 编写清晰、自文档化的代码。

## 默认设置（除非用户另有说明）

- 优先使用 **组合式 API** 而不是选项式 API。

## 响应式

**重要提示：** 在创建、更新组件或可组合项时，您**必须**遵循 `references/reactivity-guide.md` 以进行响应式状态管理。

## 组件

**重要提示：** 在使用 Vue 单文件组件 (SFC) 时，您**必须**遵循 `references/sfc-guide.md` 中的最佳实践。

- 默认情况下，优先使用 **`<script setup lang="ts">`**（TypeScript）的 Vue 单文件组件 (SFC)。
- 在 Vue 单文件组件中，保持以下顺序排列部分：`<script>` → `<template>` → `<style>`。

### 保持组件专注

当组件具有**多个明确的职责**时（例如，数据编排 + UI，或多个独立的 UI 部分），请拆分组件。

- 优先使用**更小的组件 + 可组合项**而不是一个“巨型组件”
- 将**UI 部分**移入子组件（输入属性，输出事件）。
- 将**状态/副作用**移入可组合项（`useXxx()`）。

**注意：** 此规则默认适用于 Vue / Nuxt 项目中的入口组件（例如 App.vue）。

### 数据流

**重要提示：** 您**必须**遵循 `references/data-flow-guide.md` 以使用以下方式在组件之间传递和接收数据：
- 属性
- 事件
- `v-model`
- provide/inject

要在整个应用程序中共享数据，请遵循 `references/state-management-guide.md` 并考虑使用 Store 作为状态管理解决方案。
