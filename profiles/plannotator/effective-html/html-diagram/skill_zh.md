# HTML图表

构建最小的可视化模型，使其比纯文字更容易理解。匹配符号和视觉语言与用户的项目和主题。不要强迫每个主题都进入相同的SVG框和箭头。

## 选择合适的模型

确定读者应该回答的问题，然后选择形式：

-拓扑结构，用于组件和连接；
-序列，用于按时间顺序的消息；
-流程，用于步骤、分支和交接；
-状态，用于转换和条件；
-层次结构，用于包含或所有权；
-时间轴，用于随时间变化；
-矩阵，用于重复关系；
-定量视图，当幅度很重要时。

决定必须一起保持可见的内容和可以按需显示的内容。当更简单的形式传达相同含义时，使用更简单的形式。

## 选择渲染方法

根据信息和规模使用HTML和CSS、SVG、Canvas或WebGL。不要仅仅因为输出是图表而使用SVG。

- 在添加交互之前，保持标签、分组、方向和连接器的可读性。
- 当读者必须比较状态或步骤时，使用稳定的节点位置。
- 将边缘交叉和模糊的箭头头保持到最少。
- 将有意宽泛的画布放在包含的视窗或滚动区域内。
- 只有当符号不自我解释时，才使用图例。

只有当它有助于回答所提出的问题时，才添加顺序、过滤、路径跟踪、平移和缩放或动画。保持覆盖层可关闭，控件可通过键盘访问，运动与`prefers-reduced-motion`兼容。

当[`design-artifact`](../design-artifact/SKILL.md)可用时，阅读它以了解图表的周围构图和视觉注册。保持选择的图表语法、标签可读性和关系权威性高于装饰性处理。

## 构建和验证

交付一个包含必要CSS和JavaScript的内联自包含HTML文件。无需构建步骤或外部服务。使用可访问的文本替代品，并保持重要意义可在没有动画或颜色的情况下获得。

在宽度和窄宽度下检查结果。检查标签冲突、剪切的节点、边缘路由、阅读顺序、键盘操作、溢出和每个交互状态。

返回绝对路径、选择的图表形式和主要的简化或假设。
