# HTML

构建一个自包含的 HTML 文件，使主题更清晰、更易于使用或更易于理解。标准是一致的细致，而不是一致的样式。不要复制先前的调色板、排版堆栈、卡片系统或布局。

## 首先路由请求

使用拥有主要审查问题的最窄技能：

- 当调色板、排版、构图、主题或整体视觉风格仍不确定时，使用选定的工作流阅读和编写 [`design-artifact`](../design-artifact/SKILL.md)。它提供创意方向；它不会取代拥有保真度、结构或行为的专家。
- 当结构、信息层次结构、导航或任务流程尚未确定时，阅读和遵循 [`html-wireframe`](../html-wireframe/SKILL.md)。它应保持明显的低保真度，并可能比较两个或三个布局方向。
- 当用户需要一个精致的模型或一个工作的交互流程时，阅读和遵循 [`html-prototype`](../html-prototype/SKILL.md)。模型是该技能内的静态保真度模式。
- 当工件主要是一个计划、路线图、实施顺序或发布文档，其源承诺必须保持易于验证时，阅读和遵循 [`html-plan`](../html-plan/SKILL.md)。
- 当关系、顺序、拓扑、状态、层次结构或系统行为是主要内容时，阅读和遵循 [`html-diagram`](../html-diagram/SKILL.md)。
- 继续 `html` 用于报告、解释器、演示文稿、着陆页、数据故事、工具和没有更清晰所有者的混合工件。

这些兄弟链接是当集合一起安装时的嵌套机制。如果专用技能不可用，继续这里并加载最接近的参考。不要在完成请求之前让用户安装另一个技能。

## 设计前先了解情况

检查用户的请求以及他们提供的任何材料。在仓库中工作时，查找其设计语言在 `AGENTS.md`、`CLAUDE.md`、设计系统文档、标记、现有组件和附近工件中。

权威按此顺序运行：

1. 用户的明确视觉和功能指令。
2. 项目的既定设计系统和约定。
3. 此工件的主题、受众和目的。
4. 你自己的设计判断。

在编码之前，在工作笔记中确定五件事：

- **受众和工作：** 谁将使用这个，以及他们应该理解或做什么？
- **形式：** 文档、演示文稿、界面、图表或数据可视化。
- **风格：** 安静而实用、精致而编辑或有意表达。
- **保真度：** 是否要保留用户的结构和措辞或更自由地综合。
- **交互：** 如果有的话，什么可以从探索、顺序、过滤或运动中受益。

如果项目已经回答了视觉问题，请遵循它。否则，当可用时，阅读和编写 [`design-artifact`](../design-artifact/SKILL.md)。如果集合没有安装该兄弟技能，则在选择调色板、排版、构图或运动之前，阅读 [`references/creative-direction.md`](references/creative-direction.md)。

## 仅加载工件需要的指导

- 对于报告、简报、计划、解释器和演示文稿，阅读 [`references/documents-and-presentations.md`](references/documents-and-presentations.md)。
- 对于界面、计算器和其他仍处于此广泛技能中的工具，阅读 [`references/interfaces.md`](references/interfaces.md)。
- 对于架构、流程、顺序、状态、层次结构或概念图表，阅读 [`references/diagrams.md`](references/diagrams.md)。
- 对于定量图表、表格、指标或数据故事，阅读 [`references/charts-and-data.md`](references/charts-and-data.md)。

请求可以跨越形式。阅读每个实质性适用的参考，然后给工件一个连贯的方向。

## 构建合同

- 生成一个 `.html` 文件及其必要的 CSS 和 JavaScript，并内联。它应在直接打开时即可工作，无需构建步骤。除非用户允许外部依赖，否则不要要求网络连接。
- 使用真实内容。不要用占位符文本、装饰性统计数据或无用的控件填充显眼空间。
- 让内容决定结构。一个序列应按顺序阅读；一个比较应使差异易于扫描；一个界面应暴露状态和操作；一个图表应使关系清晰。
- 使用语义 HTML、响应式布局、可访问性对比度、可见键盘焦点和减少运动处理。使交互元素能与键盘配合工作。
- 保持页面主体没有意外的水平溢出。将有意宽泛的内容放在一个包含滚动或可平移的区域中。
- 为选定的方向定义一组小的 CSS 标记，并始终如一地使用它们。标记是实现工具，而不是预定的调色板。
- 将运动视为解释或反馈。如果移除动画不会丢失任何意义或有用反馈，请移除它。
- 遵循用户或项目的主题政策。当不存在时，如果这改善了它们的使用，请提供被认为是浅色和深色主题的持久效用工件。一个故意的单主题概念是有效的。

## 完成工作

将文件写入请求的位置，或在当前工作空间中选择一个清晰的文件名。当浏览器工具可用时，打开它并检查宽视图和窄视图。操作其控件，检查控制台，并修复剪切、重叠、难以阅读的文本、损坏的状态和意外的溢出。

在交付之前，运行一次原创性检查：如果主题被相邻的主题交换，同一视觉概念是否仍然有同样多的意义？如果是，方向太通用；请修改构图、排版、颜色、图像或交互，使其属于这个主题。

返回绝对路径和工件视觉和交互选择的简短描述。
