# HTML线框图

将产品问题转化为易于检查、修改和讨论的低保真HTML工件。线框图应帮助审阅者决定屏幕上应包含的内容以及任务应如何工作。它不应看起来像是一个成品。

## 确立审阅问题

在确定布局之前，请阅读对话、提供的简报以及附近的项目材料。重用项目的词汇、内容模型和已知的产品约束。

权威按以下顺序运行：

1. 用户的明确指令和接受的决策。
2. 产品的现有结构和术语。
3. 被建模的用户、任务和内容。
4. 你自己的布局判断。

在编码之前，确定：

- 用户和他们需要完成的任务；
- 审阅的屏幕或边界流程；
- 工件必须包含的信息和操作；
- 可以安全地做出的假设；
- 线框图应帮助回答的结构性问题。

使用真实的标签和代表性内容。低保真度不是使用匿名框或Lorem ipsum来影响布局的许可。

## 在样式之前探索结构

当[`design-artifact`](../design-artifact/SKILL.md)可用时，阅读它以获取特定主题的组成和层次结构指导，而无需导入编辑润色。此技能的低保真合同仍然是权威的。

当布局尚未确定时，创建两个或三个有意义的不同方向。变化产品决策，例如：

- 导航模型；
- 分组和顺序；
- 主要操作的位置；
- 内容密度；
- 概览与分步流程；
- 桌面到移动的重新流式化。

不要将颜色变化或小的卡片重新排列称为单独的方向。给每个方向一个简短的描述性名称和一句话来描述其权衡。

在实用的情况下，将方向保存在一个HTML文件中。使用一个小型、可通过键盘操作的 选择器，以便审阅者可以在不打开多个文件的情况下比较它们。跨方向保留相同的核心内容和任务。如果用户已经选择了一个结构，则仅构建该方向。

## 保持工件有意未完成

- 使用受约束的灰度调色板、系统类型、普通边框和简单的块。
- 避免品牌颜色、渐变、阴影、插图、装饰性图像和抛光的组件样式。
- 使用有限的半径和间距。应存在足够的顺序来判断层次结构，但不应存在足够的润色以邀请品牌审阅。
- 除非资产改变了结构决策，否则将图像或富媒体显示为标记的占位符。
- 仅在它们暴露假设、开放问题或无法直接显示的行为时添加注释。

线框图可能仍然很好地组成。有意未完成与粗心的间距、难以辨认的字体或损坏的响应式行为不同。

## 仅添加有用的行为

当它有助于测试导航、披露或简短的任务流程时，使用基本的点击通过行为。保持它直接和平凡。

- 当链接、选项卡和下一步或后退操作是审阅的一部分时，使其工作。
- 使用原生控件和可见的键盘焦点。
- 不要构建复杂的动画、持久性、模拟API或生产状态管理。
- 删除没有审阅目的的控制项，或将其清楚地标记为超出范围。

## 建立合同

- 提供一个包含基本CSS和JavaScript的内联自我包含的`.html`文件。
- 不需要构建工具或外部服务。
- 使用语义地标、标题、列表、表单和按钮。
- 使布局在宽桌面和窄移动宽度下都有用。
- 保持页面免受意外的水平溢出。
- 尊重源材料。不要为了填满空间而发明额外的产品范围。

## 验证和交接

在桌面和移动宽度下打开结果。检查阅读顺序、换行、溢出、焦点可见性和每个实现的点击路径。确认在两种尺寸下，方向在结构上仍然是不同的。

返回绝对文件路径、方向的名称和权衡，以及有意推迟到后续模拟或原型的视觉决策。
