# 作品集案例研究撰写工具

## 使用此技能的场景

当用户需要：
- 创建作品集案例研究
- 将简历要点扩展为详细说明
- 构建作品集网站
- 深入展示项目工作
- 提及："案例研究"、"作品集"、"项目说明"、"工作样本"、"作品集项目"

## 核心功能

- 将简历要点转化为详细的案例研究
- 构建具有最大影响力的案例研究结构
- 创作引人入胜的项目叙述
- 平衡技术细节与商业背景
- 为作品集网站格式化
- 根据受众调整深度

## 案例研究目的

**案例研究的重要性：**
- 简历展示你做了什么；案例研究展示你如何做以及为什么
- 展示思考过程，而不仅仅是结果
- 更深入地展示技能
- 使你与其他候选人区分开来
- 许多产品经理、用户体验和创意职位都要求案例研究

## 案例研究结构

### 标准结构

```
1. 概述（项目总结）
2. 问题（需要解决的问题）
3. 过程（如何着手处理）
4. 解决方案（你创建/交付的内容）
5. 结果（影响）
6. 学习心得（你会如何做得不同）
```

### 阅读时间
- **快速阅读：** 3-5分钟（作品集必备）
- **深入阅读：** 10-15分钟（针对感兴趣读者）

## 分部分指南

### 1. 概述部分

**目的：** 吸引用户，提供背景

**包含内容：**
- 项目名称和公司
- 你的角色
- 时间线
- 团队规模
- 一句话总结的影响

**示例：**
```
# 重新设计结账流程

**公司：** 电子商务公司
**角色：** 首席产品设计师
**时间线：** 6周
**团队：** 2名设计师，3名工程师，1名产品经理

**总结：** 通过简化3步结账流程，将购物车放弃率降低了35%，创造了200万美元的挽回收入。
```

### 2. 问题部分

**目的：** 设置这项工作为何重要

**包含内容：**
- 商业背景
- 用户痛点
- 关键指标或目标
- 限制条件

**示例：**
```
## 问题

电子商务公司正经历68%的购物车放弃率——显著高于行业平均55%。退出调查和用户研究表明存在以下问题：

- **步骤过多：** 我们的结账流程有7个页面
- **强制账户创建：** 用户必须在购买前注册
- **隐藏费用：** 运费直到第5步才显示
- **移动端摩擦：** 表单未针对移动端优化

**目标：** 在3个月内将购物车放弃率降至50%以下。

**限制条件：**
- 不得更改现有的支付集成
- 必须保持PCI合规
- 6周时间线，在假日季节前
```

### 3. 过程部分

**目的：** 展示你的思考和 methodology

**包含内容：**
- 进行的研究
- 相关利益相关者
- 形成的假设
- 考虑的选项
- 做出的决策（及原因）

**示例：**
```
## 过程

### 研究
我首先深入理解问题：
- 分析了Mixpanel漏斗数据以确定放弃点
- 进行了10次与近期放弃者的用户访谈
- 查看了热图和会话录制
- 与5个竞争对手的结账流程进行对比

**关键洞察：** 73%的放弃发生在账户创建屏幕。用户想购买，而不是建立关系。

### 创意构思
我探索了多种方法：
1. 仅支持游客结账（最简单）
2. 社交登录选项（降低摩擦）
3. 逐步收集信息（分阶段收集）
4. 一页结账（亚马逊风格）

权衡可行性、时间线和影响后，我们选择了混合方法...

### 做出的决策
- **首先支持游客结账：** 使注册可选，并在购买后进行
- **透明定价：** 在第一页显示运费
- **移动端优先设计：** 先为移动端设计，然后适配桌面端
- **进度指示器：** 添加清晰的"第1步，共3步"指示器
```

### 4. 解决方案部分

**目的：** 展示你实际创建的内容

**包含内容：**
- 视觉素材（原型、截图、图表）
- 关键功能/变更
- 技术实现（如相关）
- 如何解决这些问题

**示例：**
```
## 解决方案

### 新的结账流程

**之前：** 7个页面，强制注册
**之后：** 3个页面，可选游客结账

[图片：前后对比]

### 关键变更

**1. 透明定价小部件**
[图片：定价小部件原型]
从开始就显示订单总额、运费和税费。没有意外。

**2. 游客结账选项**
[图片：游客结账屏幕]
使账户注册可选，并清晰说明注册的价值主张。

**3. 智能表单设计**
[图片：表单设计]
- 移动端单列布局
- 电话/卡号自动格式化
- 地址自动完成集成
- 清晰的错误消息

**4. 信任信号**
添加安全标志、退款保证和客户服务联系方式。
```

### 5. 结果部分

**目的：** 用数据证明影响

**包含内容：**
- 定量结果（带时间范围）
- 与目标的对比
- 影响的次要指标
- 商业影响

**示例：**
```
## 结果

### 主要指标（发布后90天）

| 指标 | 之前 | 之后 | 变化 |
|------|------|------|------|
| 购物车放弃率 | 68% | 44% | -35% |
| 结账完成率 | 32% | 56% | +75% |
| 移动端转化率 | 18% | 41% | +128% |
| 每访客收入 | $2.40 | $3.85 | +60% |

### 商业影响
- **第一季度额外收入200万美元**
- **移动端订单增加15%**
- **关于结账的客户支持工单**减少45%

### 次要影响
- 账户注册率实际增加了20%（购买后）
- 平均订单价值保持稳定
- 重复购买率提高
```

### 6. 学习心得部分

**目的：** 展示成长心态和自我认知

**包含内容：**
- 哪些做得好
- 你会如何做得不同
- 意外的挑战
- 培养的技能

**示例：**
```
## 学习心得

### 哪些做得好
- **早期用户研究**防止我们构建错误解决方案
- **跨职能对齐会议**使每个人都保持一致
- **使用分析工具发布**立即衡量影响

### 我会如何做得不同
- **更多A/B测试：** 我们一次性发布了完整改版。更希望逐个测试变化以了解结果驱动因素。
- **更早关注移动端：** 我们先为桌面端设计再适配移动端。从移动端开始会更高效。
- **利益相关者教育：** 花费太多时间说服领导。下次会提前进行利益相关者对齐。

### 培养的技能
- 高级Figma原型设计
- 使用A/B测试框架
- 向高管展示数据驱动的设计决策
```

## 按角色划分的案例研究类型

### 产品经理案例研究
**重点：**
- 策略和优先级排序
- 利益相关者管理
- 指标和结果
- 技术权衡

### 用户体验/产品设计师案例研究
**重点：**
- 用户研究
- 设计过程
- 视觉素材
- 用户体验改进

### 软件工程师案例研究
**重点：**
- 技术架构
- 问题解决方法
- 系统设计
- 代码质量/性能

### 市场营销案例研究
**重点：**
- 策略和目标定位
- 创意执行
- 渠道表现
- 投资回报率/归因

## 视觉元素

### 必须包含的视觉元素
- 前后对比
- 关键屏幕或交付物
- 流程图
- 结果图表

### 可选的视觉元素
- 用户旅程图
- 线框图演变
- 研究素材
- 团队照片

### 视觉技巧
- 使用一致图片尺寸
- 添加说明每张图片的标题
- 如有需要模糊敏感数据
- 确保移动端友好的图片尺寸

## 案例研究质量检查清单

- ✅ 清晰的问题陈述
- ✅ 体现用户/客户关注
- ✅ 清晰解释过程
- ✅ 你的具体贡献明确
- ✅ 定量结果
- ✅ 包含视觉素材
- ✅ 诚实地面对挑战/学习心得
- ✅ 适当长度（3-10分钟阅读）
- ✅ 校对和润色
- ✅ 可以在面试中详细讨论
