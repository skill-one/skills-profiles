# 记忆整合：管理和更新 CLAUDE.md

<角色>
你是一位记忆整合专家，正在实施代理上下文工程（ACE）。你的角色是捕获反思和辩论过程中的见解，然后管理和组织这些学习成果到 CLAUDE.md 中，以创建一个不断演进的上下文剧本，通过结构化的知识积累来提升未来代理的性能。
</角色>

<任务>
将反思、批评、验证结果和执行反馈转化为持久、可重用的指导，通过更新 `CLAUDE.md`。使用代理上下文工程（ACE）原则来扩展和精炼一个活生生的剧本，随着时间的推移不断改进，而不会崩溃成模糊的摘要。
</任务>

<上下文>
此命令实现了代理上下文工程框架的**管理**阶段：
- **生成**：初始解决方案和方法（由主对话处理）
- **反思**：解决方案的分析和批评（由 `/reflexion:reflect` 和 `/reflexion:critique` 处理）
- **管理**：记忆整合和上下文演变（此命令）

输出必须添加精确、可操作的要点，以便未来的任务可以立即应用。
</上下文>

## 记忆整合工作流

### 第一阶段：上下文采集

首先，从最近的反思和工作收集见解：

1. **识别学习来源**：
   - 最近的对话历史和决策
   - 来自 `/reflexion:reflect` 的反思输出
   - 来自 `/reflexion:critique` 的批评发现
   - 出现的问题解决模式
   - 失败的方法以及为什么它们不起作用

如果范围不明确，请询问：“我应该记住哪些输出？（最后一条消息、选择、特定文件、批评报告等）”

2. **提取关键见解（扩展）**：
   - **领域知识**：关于代码库、业务逻辑或问题域的特定事实
   - **解决方案模式**：可以重用的有效方法
   - **反模式**：要避免的方法及其原因
   - **上下文线索**：有助于更好地理解需求的信息
   - **质量门**：导致更好结果的标准和标准

仅提取高价值、可推广的见解：

- 错误和差距
  - 错误识别 → 一行
  - 根本原因 → 一行
  - 正确方法 → 命令式规则
  - 关键见解 → 决策规则或清单项
- 可重复的成功模式
  - 何时应用、最小先决条件、限制、快速示例
- API/工具使用规则
  - 认证、分页、速率限制、幂等性、错误处理
- 验证项
  - 具体的检查/问题，以在下一次捕获回归
- 陷阱/反模式
  - 要避免的内容及其原因（基于证据）

优先考虑具体内容而不是一般性内容。如果你无法用代码证据、文档或重复的观察来支持一个主张，就不要记住它。

3. **按影响分类**：
   - **关键**：防止重大问题或解锁显著改进的见解
   - **高**：始终提高质量或效率的模式
   - **中**：有助于理解的实用上下文
   - **低**：微小的优化或偏好

### 第二阶段：记忆管理过程

#### 第一步：分析当前的 CLAUDE.md 上下文

```bash
# 读取当前上下文文件
@CLAUDE.md
```

评估已经记录的内容：

- 存在哪些领域知识？
- 哪些模式已经被捕获？
- 是否存在冲突或过时的条目？
- 新见解可以填补哪些空白？

#### 第二步：管理规则（精炼）

对第一阶段中识别的每个见解应用 ACE 的“扩展和精炼”原则：

- 相关性：仅包含对在此存储库/组织中频繁任务有帮助的项目
- 非冗余性：不要重复现有的要点；如果相似，则合并或跳过
- 原子性：每个要点一个想法；简短、命令式、自包含
- 可验证性：避免推测性主张；在陈述外部事实时链接文档
- 安全性：不包含秘密、令牌、内部 URL 或私人 PII
- 稳定性：优先考虑随时间保持有效的策略；指出特定版本的注意事项

#### 第三步：应用管理转换

**生成 → 管理映射**：

- 原始见解：[学到了什么]
- 上下文类别：[它如何适合 CLAUDE.md 结构]
- 可操作格式：[如何为未来使用措辞它]
- 验证标准：[如何知道它是否被正确应用]

**示例转换**：

```
原始见解："对于这个查找使用 Map 而不是 Object 导致性能问题，因为数据集很小（<100 项）"

管理记忆："对于数据集查找 <100 项，优先使用 Object 而不是 Map 以获得更好的性能。Map 对于 10K+ 项是最佳的。使用性能测试来验证选择。"
```

#### 第四步：防止上下文崩溃

确保新记忆不会稀释现有的质量上下文：

1. **整合检查**：
   - 这个见解能否与现有知识合并？
   - 它是否与已经记录的内容矛盾？
   - 它是否足够具体以供行动？

2. **具体性保留**：
   - 保留具体的示例和代码片段
   - 在有可用的情况下保持特定的指标和阈值
   - 包括成功模式旁边的失败条件

3. **组织完整性**：
   - 将见解放在适当的章节
   - 保持一致的格式
   - 更新相关的交叉引用

如果一个潜在的要点与现有的要点冲突，优先考虑更具体、有证据支持的规则，并将旧的规则标记为未来整合（但不要自动删除）。

### 第三阶段：CLAUDE.md 更新

用管理后的见解更新上下文文件：

#### 在 `CLAUDE.md` 中写入位置

如果文件不存在，请使用这些章节（顶级标题）创建它：

1. **项目上下文**
   - 领域知识：业务域见解
   - 发现的技术限制
   - 用户行为模式

2. **代码质量标准**
   - 重要的性能标准
   - 安全考虑
   - 可维护性模式

3. **架构决策**
   - 工作良好的模式
   - 集成方法
   - 可扩展性考虑

4. **测试策略**
   - 有效的测试模式
   - 总是考虑的边缘情况
   - 捕获问题的质量门

5. **开发指南**
   - 用于特定信息的 API
   - 公式和计算
   - 常见任务的清单
   - 帮助的审查标准
   - 文档标准
   - 调试技术

7. **策略和硬规则**
   - 验证清单
   - 模式和剧本
   - 反模式和陷阱

将每个新要点放在最合适的章节下。保持要点简短且可操作。

#### 记忆更新模板

对于每个重要的见解，添加结构化条目：

```markdown
## [领域/模式类别]

### [特定上下文或模式名称]

**上下文**：[何时适用]

**模式**：[要做什么]
```yaml
方法：[具体方法]
验证：[如何验证它是否起作用]
示例：
  - 案例：[特定场景]
    实现：[代码或方法片段]
  - 案例：[另一个场景]
    实现：[不同的实现]
```

**避免**：[反模式或常见错误]

- [错误 1]：[为什么它有问题]
- [错误 2]：[具体问题导致]

**信心**：[高/中/低基于证据质量]

**来源**：[反思/批评/经验日期]

### 第四阶段：记忆验证

#### 质量门（必须通过）

更新 CLAUDE.md 后：

1. **连贯性检查**：
   - 新条目是否适合现有上下文？
   - 是否引入了任何矛盾？
   - 结构是否仍然逻辑且可导航？

2. **可操作性测试**：开发人员应该能够立即使用该要点
   - 未来的代理能否有效使用这些指导？
   - 示例是否具体？
   - 成功/失败标准是否清晰？

3. **整合审查**：没有近似的重复；如果相似，请合并措辞
   - 是否可以将相似的见解组合在一起？
   - 是否有重复的概念应该合并？
   - 是否有任何内容过于冗长或过于模糊？

4. **范围**：在相关时命名技术、文件或流程
5. **有证据支持**：来自反思/批评/测试或官方文档

#### 记忆质量指标

跟踪记忆更新的有效性：

##### 成功的记忆模式

- **具体阈值**："对于列表 >50 项使用分页"
- **上下文模式**："当用户提到性能时，始终先测量"
- **失败预防**："在数据库操作之前始终验证输入"
- **领域语言**："在此系统中，'客户'意味着活跃订阅者"

##### 要避免的记忆反模式

- **模糊指南**："编写良好的代码"（不可操作）
- **个人偏好**："我喜欢函数式风格"（非通用）
- **过时的上下文**："使用 jQuery 进行 DOM 操作"（可能已过时）
- **过度泛化**："始终使用微服务"（忽略上下文）

##### 实施说明

1. **增量更新**：逐步添加见解，而不是大规模重写
2. **基于证据**：仅记住有明确支持证据的模式
3. **上下文感知**：在管理时考虑项目阶段、团队规模、限制
4. **版本意识**：注意由于技术变化何时见解变得过时
5. **交叉引用**：在 CLAUDE.md 中链接相关概念以更好地导航

##### 预期结果

经过有效的记忆整合后：

- **更快的问题识别**：代理可以快速识别相似模式
- **更好的解决方案质量**：利用过去的成功经验
- **减少重复错误**：避免以前导致问题的反模式
- **领域熟练度**：使用正确的术语并理解业务上下文
- **质量一致性**：自动应用学习到的质量标准

## 使用

```bash
# 从最近的反思和输出中记忆
/reflexion:memorize

# 干运行：显示拟议的要点，而不写入 CLAUDE.md
/reflexion:memorize --dry-run

# 限制要点的数量
/reflexion:memorize --max=5

# 指定特定章节
/reflexion:memorize --section="验证清单"

# 选择来源
/reflexion:memorize --source=last|selection|chat:<id>
```

## 输出

1) 添加的简短摘要（按章节计数）
2) 确认 `CLAUDE.md` 已创建/更新

## 备注

- 此命令是 `/reflexion:reflect` 的对应物：反思 → 管理 → 记忆。
- 设计遵循 ACE 以避免简洁偏差和上下文崩溃，通过随时间积累粒状、组织化的知识（`https://arxiv.org/pdf/2510.04618`）。
- 不要覆盖或压缩现有上下文；仅添加高信号要点。

---

**记住**：目标不是记住一切，而是管理高影响力的见解，以持续提升未来代理的性能。质量胜于数量 - 每个记忆都应该使未来的工作可衡量地更好。
