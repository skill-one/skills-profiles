# 基于思维的推理技术用于大型语言模型

## 概述

思维链（CoT）提示及其变体鼓励大型语言模型在得出最终答案之前生成中间推理步骤，显著提高了它们在复杂推理任务上的性能。这些技术通过将隐式推理显式化，改变了模型解决问题的方式。

## 快速参考

| 技术 | 使用场景 | 复杂度 | 准确率提升 |
|-----------|-------------|------------|---------------|
| 零样本CoT | 快速推理，没有示例可用 | 低 | +20-60% |
| 少样本CoT | 有良好示例，需要一致格式 | 中等 | +30-70% |
| 自洽性 | 高风险决策，需要置信度 | 中等 | 比CoT高+10-20% |
| 思维树 | 需要探索的复杂问题 | 高 | 在难题上提升+50-70% |
| 从少到多 | 具有子问题的多步骤问题 | 中等 | +30-80% |
| ReAct | 需要外部信息的任务 | 中等 | +15-35% |
| PAL | 数学/计算问题 | 中等 | +10-15% |
| 反思 | 迭代改进，从错误中学习 | 高 | +10-20% |

---

## 核心技术

### 1. 思维链（CoT）提示

**论文**: "Chain of Thought Prompting Elicits Reasoning in Large Language Models" (Wei等人, 2022)
**引用次数**: 14,255+

#### 使用场景
- 多步骤算术或数学应用题
- 需要逻辑推理的常识推理
- 符号推理任务
- 当你有显示推理过程的良好示例时

#### 工作原理
提供包含中间推理步骤的少样本示例，而不仅仅是问答对。模型学习生成类似的逐步推理。

#### 提示模板

```
Q: 罗杰有5个网球。他买了2盒网球。每盒有3个网球。他现在有多少个网球？
A: 罗杰最初有5个球。2盒3个网球的网球是6个网球。5 + 6 = 11。答案是11。

Q: 食堂最初有23个苹果。他们用了20个做午餐，又买了6个。他们现在有多少个苹果？
A: 食堂最初有23个苹果。他们用了20个做午餐。所以它们有23 - 20 = 3个。他们又买了6个苹果，所以他们有3 + 6 = 9个。答案是9。

Q: [你的问题在这里]
A:
```

#### 优势
- 显著提高推理任务的准确率
- 可解释的中间步骤
- 对大型模型（>100B参数）效果良好

#### 限制
- 需要设计良好的示例
- 对小型模型效果较差
- 仍然可能做出计算错误

### 2. 零样本思维链

**论文**: "Large Language Models are Zero-Shot Reasoners" (Kojima等人, 2022)
**引用次数**: 5,985+

#### 使用场景
- 没有示例可用
- 需要快速推理
- 跨任务通用推理
- 在创建少样本示例之前进行原型设计

#### 工作原理
只需在提示中附加"让我们逐步思考"（或类似短语）。这会触发模型生成推理步骤，而无需任何示例。

#### 提示模板

```
Q: 一个杂耍演员可以同时抛16个球。一半的球是高尔夫球，一半的高尔夫球是蓝色的。有多少个蓝色的高尔夫球？

让我们逐步思考。
```

**替代触发短语**:
- "让我们一步步计算以确保我们得到正确的答案。"
- "让我们分解这个问题。"
- "让我们系统地处理这个问题。"
- "首先，让我理解这个问题..."

#### 两阶段方法（更稳健）

**阶段1 - 推理提取**:
```
Q: [问题]
A: 让我们逐步思考。
```

**阶段2 - 答案提取**:
```
[阶段1的推理]
因此，答案是
```

#### 优势
- 无需示例设计
- 跨任务泛化
- 易于实现

#### 限制
- 比少样本CoT效果差
- 可能产生冗长或不相关的推理
- 对精确措辞敏感

### 3. 自洽性

**论文**: "Self-Consistency Improves Chain of Thought Reasoning in Language Models" (Wang等人, 2022)
**引用次数**: 5,379+

#### 使用场景
- 需要置信度的高风险决策
- 具有多个有效推理路径的问题
- 当你需要减少输出方差时
- 验证推理正确性

#### 工作原理
采样多个不同的推理路径，然后通过多数投票选择最一致的答案。直觉：正确答案可以通过多个推理路径到达。

#### 提示模板

```
[使用任何CoT提示 - 零样本或少样本]

[生成N个温度>0的样本]

[从每个样本中提取最终答案]

[返回最频繁的答案（多数投票）]
```

#### 实现示例

```python
def self_consistency(prompt, n_samples=5, temperature=0.7):
    answers = []
    for _ in range(n_samples):
        response = llm.generate(prompt, temperature=temperature)
        answer = extract_answer(response)
        answers.append(answer)

    # 多数投票
    return Counter(answers).most_common(1)[0][0]
```

#### 优势
- 比单路径CoT显著提高准确率
- 提供置信度度量（协议水平）
- 任务无关的改进

#### 限制
- 计算成本更高（N倍生成）
- 需要可提取的离散答案
- 超过~10-20个样本后收益递减

### 4. 思维树（ToT）

**论文**: "Tree of Thoughts: Deliberate Problem Solving with Large Language Models" (Yao等人, 2023)
**引用次数**: 3,026+

#### 使用场景
- 需要探索/回溯的复杂问题
- 初始决策至关重要的问题
- 创意问题解决（写作、谜题）
- 当CoT单独使用时准确率低于50%时

#### 工作原理
将CoT推广为树结构，其中每个节点是一个“思维”（连贯的语言单元）。使用搜索算法（BFS/DFS）进行自我评估，以探索和选择有希望的推理路径。

#### 提示模板

**思维生成**:
```
给定当前状态：
[状态]

生成3-5个可能的下一步来解决这个问题。
```

**状态评估**:
```
评估以下部分解决方案是否：
- "确定"（肯定会导致解决方案）
- "可能"（可能有效）
- "不可能"（不可能导致解决方案）

部分解决方案：
[目前的思维]
```

**BFS/DFS搜索**:
```python
def tree_of_thoughts(problem, max_depth=3, beam_width=3):
    queue = [(problem, [])]  # (状态, 思维路径)

    while queue:
        state, path = queue.pop(0)

        if is_solved(state):
            return path

        # 生成候选思维
        thoughts = generate_thoughts(state, k=5)

        # 评估并保留前k个
        evaluated = [(t, evaluate(state, t)) for t in thoughts]
        top_k = sorted(evaluated, key=lambda x: x[1])[:beam_width]

        for thought, score in top_k:
            if score != "不可能":
                new_state = apply_thought(state, thought)
                queue.append((new_state, path + [thought]))

    return None
```

#### 示例：24点游戏

```
问题：用4、9、10、13得到24（使用+、-、*、/，每个数字使用一次）

思维1：13 - 9 = 4（现在有：4、4、10）
评估："可能" - 有两个4和10，可能有效

思维2：10 - 4 = 6（现在有：4、6、13）
评估："可能" - 4 * 6 = 24，需要使用13

思维3：4 + 9 = 13（现在有：10、13、13）
评估："不可能" - 没有办法从这些得到24
```

#### 优势
- 显著提高难题的性能（在24点游戏中从4%提升到74%）
- 支持回溯和探索
- 自我评估可及早发现错误

#### 限制
- 计算成本显著更高
- 需要针对任务进行思维分解
- 实现复杂

### 5. 从少到多提示

**论文**: "Least-to-Most Prompting Enables Complex Reasoning in Large Language Models" (Zhou等人, 2022)
**引用次数**: 1,466+

#### 使用场景
- 比你的示例更难的问题
- 组合泛化任务
- 具有清晰子问题的多步骤问题
- 符号操作和SCAN类任务

#### 工作原理
两阶段过程：
1. **分解**：将复杂问题分解为更简单的子问题
2. **顺序求解**：按顺序解决子问题，使用先前答案

#### 提示模板

**阶段1：分解**
```
Q: 四年前，科迪的年龄只是穆罕默德的一半。如果穆罕默德现在 twice as old as 30 years old，科迪现在多大？

要解决"Four years ago, Kody was only half as old as Mohamed. If Mohamed is currently twice as old as 30 years old, how old is Kody?"，我们需要首先解决：
- "如果穆罕默德现在 twice as old as 30 years old，穆罕默德多大？"
然后我们需要解决：
- "Four years ago, Kody was only half as old as Mohamed. 科迪多大？"
```

**阶段2：顺序求解**
```
Q: 如果穆罕默德现在 twice as old as 30 years old，穆罕默德多大？
A: 穆罕默德是30的两倍，所以穆罕默德是30 * 2 = 60岁。

Q: 四年前，科迪只是穆罕默德的一半。穆罕默德是60岁。科迪多大？
A: 四年前，穆罕默德是60 - 4 = 56岁。科迪是一半大，所以科迪是56 / 2 = 28岁。因此，科迪现在是28 + 4 = 32岁。

答案是32。
```

#### 优势
- 在更难的问题上表现优异
- 组合任务效果良好
- 显式问题分解有助于可解释性

#### 限制
- 需要两阶段提示
- 分解步骤可能在新型结构上失败
- 比单阶段CoT更复杂的设置

### 6. ReAct（推理+行动）

**论文**: "ReAct: Synergizing Reasoning and Acting in Language Models" (Yao等人, 2022)
**引用次数**: 5,012+

#### 使用场景
- 需要外部信息的任务（搜索、API）
- 交互式决策环境
- 多跳问答
- 当纯推理导致幻觉时

#### 工作原理
交替推理痕迹（"思维"）与行动（"行动"）和观察（"观察"）。推理帮助规划行动；行动为推理提供新信息。

#### 提示模板

```
问题：科罗拉多山脉东部区域的海拔范围是多少？

思维1：我需要搜索科罗拉多山脉造山运动，找到东部部门延伸的区域，然后找到该区域的海拔范围。
行动1：搜索[Colorado orogeny]
观察1：科罗拉多山脉造山运动是在科罗拉多州和周边地区发生的一次造山运动（造山运动）。

思维2：它没有提到东部部门。所以我要查找东部部门。
行动2：查找[东部部门]
观察2：东部部门延伸到高平原。

思维3：东部部门延伸到高平原。我需要搜索高平原并找到它的海拔范围。
行动3：搜索[高平原]
观察3：高平原指的是两个截然不同的陆地区域：美国的高平原...

思维4：我需要搜索美国的高平原。
行动4：搜索[美国的高平原]
观察4：高平原是大平原的一个子区域... 海拔约为1,800至7,000英尺（550至2,130米）。

思维5：海拔范围是1,800至7,000英尺。
行动5：完成[1,800至7,000英尺]
```

#### 行动类型
- `搜索[查询]` - 搜索信息
- `查找[关键词]` - 在当前上下文中查找关键词
- `完成[答案]` - 返回最终答案

#### 优势
- 通过外部知识接地减少幻觉
- 可解释的行动痕迹
- 通过自适应推理处理异常

#### 限制
- 需要集成外部工具
- 更复杂的协调
- 行动空间必须定义

### 7. PAL（程序辅助语言模型）

**论文**: "PAL: Program-aided Language Models" (Gao等人, 2022)
**引用次数**: 608+

#### 使用场景
- 数学/算术推理
- 需要精确计算的问题
- 符号操作
- 当CoT做出计算错误时

#### 工作原理
生成代码（通常是Python），而不是自然语言推理。执行代码以获取答案。LLM处理分解；解释器处理计算。

#### 提示模板

```
Q: 罗杰有5个网球。他买了2盒网球。每盒有3个网球。他现在有多少个网球？

# Python中的解决方案：
def solution():
    """罗杰有5个网球。他买了2盒网球。每盒有3个网球。他现在有多少个网球？"""
    tennis_balls_initial = 5
    bought_cans = 2
    tennis_balls_per_can = 3
    tennis_balls_bought = bought_cans * tennis_balls_per_can
    tennis_balls_total = tennis_balls_initial + tennis_balls_bought
    return tennis_balls_total

Q: 比佛利山丘烘焙坊的面包师在周一早上烤了200条面包。他们早上卖了93条，下午卖了39条。一家杂货店退回了6条未售出的面包。他们剩下多少条面包？

# Python中的解决方案：
def solution():
    """面包师烤了200条。早上卖了93条，下午卖了39条。一家商店退回了6条。还剩多少？"""
    loaves_baked = 200
    loaves_sold_morning = 93
    loaves_sold_afternoon = 39
    loaves_returned = 6
    loaves_left = loaves_baked - loaves_sold_morning - loaves_sold_afternoon + loaves_returned
    return loaves_left
```

#### 优势
- 消除算术错误
- 清晰的变量命名有助于可解释性
- 利用代码执行进行验证

#### 限制
- 需要代码解释器
- 不适用于非计算推理
- 模型必须生成语法正确的代码

### 8. Auto-CoT

**论文**: "Automatic Chain of Thought Prompting in Large Language Models" (Zhang等人, 2022)
**引用次数**: 838+

#### 使用场景
- 没有手动设计的示例
- 想要自动化少样本CoT设置
- 扩展CoT到许多任务
- 当零样本CoT不够用时

#### 工作原理
1. 按多样性对问题进行聚类
2. 使用零样本CoT为代表性问题生成推理链
3. 使用这些自动生成的链作为少样本示例

#### 提示模板

**步骤1：生成多样化演示**
```python
# 聚类问题
clusters = cluster_questions(all_questions, k=8)

# 对每个聚类，选择代表性并生成CoT
demonstrations = []
for cluster in clusters:
    question = select_representative(cluster)
    reasoning = zero_shot_cot(question)  # "让我们逐步思考"
    demonstrations.append((question, reasoning))
```

**步骤2：用作少样本示例**
```
Q: [演示问题1]
A: 让我们逐步思考。[生成的推理1]

Q: [演示问题2]
A: 让我们逐步思考。[生成的推理2]

...

Q: [新问题]
A: 让我们逐步思考。
```

#### 优势
- 无需手动创建示例
- 多样性采样提高鲁棒性
- 与手动CoT性能相当

#### 限制
- 质量取决于零样本CoT质量
- 聚类需要相似性度量
- 一些生成的链包含错误

### 9. 反思

**论文**: "Reflexion: Language Agents with Verbal Reinforcement Learning" (Shinn等人, 2023)
**引用次数**: 2,179+

#### 使用场景
- 多次尝试的迭代改进
- 无需微调即可从错误中学习
- 复杂编码或决策任务
- 当单次推理不足时

#### 工作原理
任务失败后，代理生成一个语言“反思”分析哪里出了错。这个反思被存储在内存中，并在后续尝试中用于避免重复错误。

#### 提示模板

**初始尝试**:
```
任务：[任务描述]

思维：[推理]
行动：[行动]
...
结果：[失败/部分成功]
```

**反思**:
```
之前的尝试失败是因为：
1. [具体错误分析]
2. [应该做什么]
3. [关键见解用于下次尝试]

反思：在下次尝试中，我应该...
```

**后续尝试（带内存）**:
```
任务：[任务描述]

之前的反思：
- [反思1]
- [反思2]

使用这些见解，我现在将再次尝试任务。

思维：[改进的推理]
行动：[更好的行动]
```

#### 示例：代码生成

```
任务：编写一个函数来找到最长的回文子串。

尝试1：[有错误的代码]
测试结果：在"babad"上失败 - 期望"bab"或"aba"，得到"b"

反思：我的解决方案只检查单个字符。我需要：
1. 考虑所有长度的子串
2. 使用扩展中心技术提高效率
3. 跟踪起始位置和最大长度

尝试2：[使用反思的改进代码]
测试结果：通过所有测试
```

#### 优势
- 无需权重更新即可学习
- 在HumanEval上达到91%（超过GPT-4的80%）
- 建立了包含见解的情景记忆

#### 限制
- 需要多次尝试
- 长会话的内存管理
- 反思质量影响改进
