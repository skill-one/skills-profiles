# 设计评审

评审 Web 应用或页面的视觉设计质量。这不是用户体验审核（可用性、工作流程、摩擦点）——而是检查设计是否**专业、一致且精致**。

目标：一个注重设计的人看到这个会想“这个做得很好”或“这个看起来像开发者设计的”？

## 使用时机

- 展示给客户或团队之前
- 东西“看起来不对劲”但你说不出为什么
- 完成一个功能后，在称之为完成之前
- 已发布产品的定期质量检查
- 用户体验审核之后——这是视觉上的配套

## 浏览器工具检测

与 ux-audit 相同——Chrome MCP、Playwright MCP 或 playwright-cli。

## URL 解析

与 ux-audit 相同——优先部署/在线版本而非 localhost。

## 需要检查的内容

### 1. 布局和间距

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **一致的间距** | 网格中所有卡片之间的间隙相同，所有部分中的填充相同 | 一些卡片有 16px 间隙，另一些有 24px。页眉填充与正文不同 |
| **对齐** | 内容在各个部分的左边缘垂直对齐 | 标题从一种缩进开始，正文文本从另一种开始，卡片从第三种开始 |
| **呼吸空间** | 内容周围有充足的空白，元素不显得拥挤 | 文本紧贴容器边缘，按钮紧贴输入框 |
| **网格纪律** | 内容遵循清晰的列网格 | 元素随意放置，没有底层结构 |
| **响应式比例** | 侧边栏/内容比例在每个宽度上看起来都是有意设计的 | 侧边栏在平板电脑上占 50%，内容被挤压 |
| **垂直韵律** | 一致的垂直间距模式（例如 8px/16px/24px/32px 缩放） | 随机间距：这里 13px，那里 27px，别处 8px |

### 2. 字体排印

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **层级** | h1 → h2 → h3 → 正文之间存在清晰的可视差异 | 标题和正文文本看起来大小/粗细相同 |
| **行长度** | 正文每行 50-75 个字符 | 全宽文本运行 150+ 个字符——难以阅读 |
| **行高** | 正文 1.5-1.7，标题 1.1-1.3 | 拥挤的文本或过高的行高 |
| **字体大小** | 一致的缩放（例如 14/16/20/24/32） | 随机大小：15px，17px，22px 没有任何关系 |
| **粗细使用** | 正文使用常规，标签使用中等，标题使用半粗，粗体谨慎使用 | 所有内容都粗体，或者所有内容都常规且没有层级 |
| **截断** | 长文本使用省略号截断，标题属性显示完整文本 | 文本溢出容器，包装不自然，或者没有省略号就被截断 |

### 3. 颜色和对比度

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **语义颜色** | 使用设计令牌（bg-primary，text-muted-foreground） | 原始 Tailwind 颜色（bg-blue-500，text-gray-300） |
| **对比度比例** | 文本符合 WCAG AA（正文 4.5:1，大文本 3:1） | 浅灰色文本在白色背景上，或深色文本在深色背景上 |
| **颜色一致性** | 相同的蓝色意味着相同的意思（主要 = 操作） | 在一个地方蓝色表示“可点击”，在另一个地方表示“信息性” |
| **暗黑模式** | 所有元素都可见，边框定义明确，没有不可见的文本 | 元素消失，文本变得难以阅读，图像看起来不正确 |
| **状态颜色** | 绿色=成功，黄色=警告，红色=错误始终一致 | 绿色用于成功和“活动”但含义不同 |
| **颜色过度使用** | 2-3 种颜色 + 中性色 | 彩虹色系，没有明确的层级 |

### 4. 视觉层级

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **主要操作** | 每页一个清晰的 CTA，视觉上突出 | 三个同等风格的按钮争夺注意力 |
| **眯眼测试** | 眯着眼睛看页面，最重要的元素突出 | 所有元素都是相同的视觉权重——没有吸引眼睛的元素 |
| **渐进式披露** | 最重要信息可见，详细信息可通过交互获取 | 一次性显示所有内容——令人不知所措 |
| **分组** | 相关项目在视觉上分组（邻近性、边框、背景） | 相关项目分散，不相关的项目接触 |
| **负空间** | 有意留出的空白，框架内容 | 看起来是偶然的空白（不均匀，被困住的白色空间） |

### 5. 组件一致性

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **按钮样式** | 一种主要样式，一种次要样式，一种破坏性样式——始终如一地使用 | 应用程序中有 5 种不同的按钮样式 |
| **卡片样式** | 所有卡片都有相同的 border-radius，阴影，填充 | 一些卡片是圆角的，一些是尖角的，一些有阴影，一些没有 |
| **表单输入** | 所有输入高度相同，边框样式相同，焦点环相同 | 混合高度，边框样式，焦点行为 |
| **图标样式** | 一种图标家族（Lucide，Heroicons），大小和笔画一致 | 混合图标家族，不同大小，一些填充，一些轮廓 |
| **边框半径** | 一致的半径缩放（例如 4px 输入，8px 卡片，12px 模态） | 随机半径值：3px，7px，10px，16px |
| **阴影** | 一到两个阴影级别始终如一地使用 | 每个组件都有不同的阴影深度 |

### 6. 交互设计

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **悬停状态** | 按钮和链接以及可点击卡片在悬停时变化 | 没有悬停反馈——用户不确定什么可点击 |
| **焦点状态** | 所有交互元素上都有可见的键盘焦点 | 焦点环缺失或背景不可见 |
| **激活状态** | 导航项，标签，侧边栏链接显示当前选择 | 激活项看起来与未激活项相同 |
| **过渡** | 悬停/焦点时有微妙的过渡（150-200ms 缓动） | 没有过渡（突兀）或过渡缓慢（卡顿） |
| **加载指示器** | 异步操作期间使用骨架屏幕或旋转器 | 内容未经警告弹出，布局变化 |
| **禁用状态** | 禁用元素在视觉上减弱，光标变化 | 禁用按钮看起来可点击，没有光标变化 |

### 7. 响应式质量

| 检查项 | 良好 | 不好 |
|-------|------|-----|
| **移动导航** | 干净的汉堡/面板菜单，易于点击 | 桌面导航被挤压到移动端，微小的点击目标 |
| **图像缩放** | 图像按比例填充容器 | 图像被拉伸，裁剪不当，或溢出 |
| **表格响应式** | 移动端水平滚动，或堆叠成卡片 | 表格比屏幕宽，没有查看列的方法 |
| **触摸目标** | 移动端至少 44x44px | 微小的链接，关闭按钮，复选框 |
| **平板电脑** | 布局在 768px 上工作（不仅仅是桌面和手机） | 布局在平板电脑宽度上中断，不自然的间隙 |

## 严重性指南

| 级别 | 含义 | 示例 |
|-------|---------|---------|
| **高** | 看起来是错误的或不专业的 | 暗黑模式下不可见文本，行内按钮高度不同 |
| **中** | 看起来不精致 | 不一致的间距，混合图标样式，没有省略号的截断 |
| **低** | 细节问题 | 1-2px 对齐，稍微不同的 border-radius，阴影太强 |

## 输出

将发现结果写入 `.jez/artifacts/design-review.md`：

```markdown
# 设计评审：[应用名称]
**日期**：YYYY-MM-DD
**URL**：[url]

## 整体印象
[1-2 句话——专业 / 不精致 / 不一致 / 干净]

## 发现

### 高
- **[问题]** 在 [页面/组件] — [什么不对劲] → [修复]

### 中
- **[问题]** 在 [页面/组件] — [什么不对劲] → [修复]

### 低
- **[问题]** — [描述]

## 看起来好的地方
[执行良好且应保留的模式]

## 顶级 3 个修复
1. [最高视觉影响变化]
2. [第二]
3. [第三]
```

对发现的问题进行截图，其中问题具有视觉性（大多数情况）。

## 小贴士

- 检查暗黑模式和亮色模式——大多数问题在一个模式下出现，但在另一个模式下不出现
- 眯眼测试是发现层级问题的最快方法
- 组件不一致是开发构建 UI 中最常见的問題
- “看起来不对劲”通常意味着间距——首先检查边距和填充
- 如果您无法识别问题，请与同一类别中设计良好的应用程序进行比较
