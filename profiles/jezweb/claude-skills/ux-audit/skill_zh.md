# 用户体验审计

以真实用户身份体验一个在线应用程序。审计是**以交互为先**的——输入、点击、发送、观看、截图。静态的DOM扫描无法得出结论。

## 审计结果

审计将恰好以以下一种方式结束：

- **通过**——关键 = 0，高 = 0，所有硬性门槛为绿色，交互清单完整。
- **有条件通过**——关键 = 0，高 = 0，所有硬性门槛为绿色，但存在中/低问题。
- **失败**——至少有一个关键或高问题，或硬性门槛为红色。
- **不完整**——交互清单缺少必要条目，某个阶段未运行，或审计审计的元检查触发（清单时间戳相距<0.5秒，截图少于2倍路由，控制台读取少于1倍路由，阶段3对详尽审计耗时<1分钟）。即使观察到的所有内容看起来都很好，也不允许升级为通过。

如果工作不包括完整的交互清单，唯一的合法结论是**不完整**。"看起来OK"不是通过。带有不可信时间的高清通过会被拒绝——代理必须使用真实交互重新进行审计。

## 硬性门槛

这些会自动使审计失败。它们不能降级。

| 门槛 | 阈值 | 违反严重性 |
|------|------|------------|
| 走廊期间控制台错误 | > 0 | 关键 |
| 走廊期间控制台警告 | > 0 | 高 |
| 网络5xx | > 0 | 关键 |
| 认证页面的网络403 / 404 | > 0 | 高 |
| 在任何测试的视口/面板组合中布局崩溃 | > 0 | 高 |
| 任何审计页面上的axe-core关键违规 | > 0 | 关键 |
| 任何审计页面上的axe-core严重违规 | > 0 | 高 |
| 代表性路由上的LCP（实用预算） | > 4.0秒 | 高 |
| 代表性路由上的CLS | > 0.25 | 高 |
| 代表性路由上的INP | > 500毫秒 | 高 |
| 缺少必要的交互清单条目 | n/a | 不完整 |
| 清单条目之间的中位数差距<0.5秒 | n/a | 不完整（未实际交互） |

控制台警告至少是高*最低限度*。5xx自动是关键*。不存在"中控制台错误"——这个类别在这个技能中不存在。

axe-core阈值按**每页**运行（>1违规在任何单个页面上都会失败）。性能阈值按**代表性路由**运行一次（每页过度）；实用预算远高于损坏，远低于CWV-严格。完整阈值+理由在[参考资料/性能预算.md](参考资料/性能预算.md)。完整的无障碍布线+严重性映射在[参考资料/无障碍自动化.md](参考资料/无障碍自动化.md)。

### 已知噪声的允许清单

一些应用程序具有已知的噪声控制台/网络类别，这些不是错误（Sentry信息日志、浏览器扩展聊天、认证检查探针上的预期401）。在阶段3之前阅读审计配置文件并应用其允许清单。路径回退：`.jez/audit-config.yml` → `audit-config.yml` → `.audit/config.yml`。允许条目保留在交互清单中，但抑制在发现中。结论块显示原始和允许的：`控制台警告：3（1个允许，2个可报告）`。

没有配置：每个控制台错误/警告都是一个发现。格式、语义、表面覆盖在[参考资料/审计配置.md](参考资料/审计配置.md)。

## 阶段（按顺序）

1. **预飞行**——角色锁定、浏览器工具、URL、视口、能力测试
2. **发现**——站点地图、线程清单、元素清单
3. **演练**——交互清单、线程、元素耗尽、多面板压力、新用户视角、实时交互烟雾
4. **润色**——视觉润色扫描、组件完美性清单
5. **压力**——场景电池（11个场景）+扩展压力配方
6. **结论**——结论状态、硬性门槛计分卡、完美路线图、可复现的发现
7. **修复和验证**——修复发现、重新演练受影响的切片、更新报告

对于30秒的预部署检查，使用本文件底部的dogfood drill——这是一个项目级规则，不是技能调用。

## 阶段1——预飞行

五个门槛。如果任何一个失败，则停止。

### 1. 角色锁定

在执行任何操作之前，审计需要一个角色。如果没有锁定的角色，发现会偏向于笼统的"看起来很好"。

按此顺序源角色：

1. **参数**——如果用户提供了一个（"作为忙碌的保险经纪人进行用户体验审计"）
2. **项目角色**——读取现有的角色文件（回退链：`.jez/audit-personas/<slug>.md` → `docs/personas/<slug>.md` → `personas/<slug>.md` → `.audit/personas/<slug>.md`）。第一个匹配的获胜。
3. **问一次**——*"谁使用这个应用程序以及他们试图完成什么？*"

捕获：角色、技术舒适度、时间压力、情绪状态、设备上下文。一个好的角色可以预测他们会错过什么（"接线员在电话通话中不会滚动到折叠以下"）。

通过在审计报告的顶部写入选定的角色来锁定角色。每个发现都必须从这个角色的角度可以辩护。如果你发现自己想着*"一个开发人员会知道..."*——停止。你的角色不是。

**始终运行第一次用户视角**（强制，见阶段3）在所有多页功能上，即使显式角色是其他角色。这是AI/内部工具最大的盲点。

见[参考资料/角色锁定.md](参考资料/角色锁定.md)了解角色库和编写协议。

### 2. 浏览器工具

| 目标 | 工具 | 原因 |
|------|------|-----|
| **认证应用程序** | Chrome MCP | 使用你的真实登录Chrome会话——OAuth、cookies、RBAC正常工作 |
| **公共网站** | Playwright MCP | 无需登录 |
| **两者都不可用** | **停止** | 请用户连接Chrome MCP或安装Playwright |

不要在认证应用程序中无声地回退到新的Playwright会话——如果你无法登录，审计就毫无价值。如果Chrome MCP未连接，请停止并说：*"打开Chrome，点击Claude扩展中的连接，然后重新运行。*"

见[参考资料/浏览器工具.md](参考资料/浏览器工具.md)了解命令。

### 3. URL

优先考虑部署/实时版本——真实认证、真实延迟、真实CDN和CORS。发现：读取项目CLAUDE.md / README以获取"URL"→检查堆栈配置（`wrangler.jsonc`、`vite.config.ts`、`next.config.js`、`config/database.yml`、`manage.py`、`.env` `APP_URL`、`wp-config.php`）→ `lsof -i :PORT`（常见：5173 Vite、3000 Next/Rails、8000 Django/Laravel、8787 Wrangler、4321 Astro）→ 询问。特定于堆栈的指南在[参考资料/项目适应.md](参考资料/项目适应.md)。仅在用户要求或功能未部署时使用本地。

### 4. 视口

将窗口固定在1440×900开始。阶段3的多面板压力测试375 / 768 / 1024 / 1280 / 1440 / 1920。**不要超过2000px**——它会破坏支架。

### 5. 能力测试

在演练之前，证明工具可以工作——每个调用一次：

- 一个截图
- 一个控制台读取
- 一个网络请求清单
- 一个元素选择器查询

如果任何一个失败，请停止并在开始审计之前修复连接。对控制台输出的盲目的审计是无用的。

## 阶段2——发现

### 站点地图爬取

在审计任何页面之前，构建完整的页面清单。

1. **路由配置**——读取应用程序的路由定义（React Router、TanStack Router、Next.js应用目录）
2. **导航爬取**——点击每个侧边栏/菜单的每个部分和子部分
3. **深度链接**——CLAUDE.md、文档或先前审计报告中的URL

每行一个路由，并附上目的：`/app/clients — 客户列表，搜索，添加新客户`。

### 线程清单

确定构成用户一天中3-5个真实任务的线程。这些是审计的骨干。

如何找到它们：询问用户，阅读CLAUDE.md / README，从顶级导航推断。例如：保险经纪人→续保保单，创建客户，处理今天的队列。项目管理→早晨分类，更新任务，发送客户摘要。空间/聊天应用程序→创建空间，发送消息，打开线程。

### 元素清单

对于您到达的每个路由，列出每个交互元素。懒惰地构建清单——按页面遍历，而不是事先所有内容。这驱动了覆盖指标：*"在/app/clients上测试了29个元素中的31个"*。

## 阶段3——演练（审计本身）

### 交互清单（强制）

每个演练都产生一个清单。没有它，结论=不完整。

```
交互清单——/dashboard/spaces/marketing-pod
  角色：中小企业所有者，时间紧迫，低技术舒适度
  [✓] 14:32:01 在消息输入（textarea[placeholder*="message"]）中键入"@assistant test"
  [✓] 14:32:03 从自动完成中选择了@assistant（li[data-mention-id="assistant"）
  [✓] 14:32:05 点击了发送（button[aria-label="发送"）
  [✓] 14:32:06 验证输入在1000毫秒内清除（textarea.value === ""）
  [✓] 14:32:08 验证消息出现在转录中（[data-message-id]计数+1）
  [✓] 14:32:12 打开消息上的线程（[data-thread-trigger]）
  [✓] 14:32:13 验证主列宽度≥200px打开线程后（getBoundingClientRect().width）
  [✓] 每个步骤后读取控制台（0警告，0错误）
  [✓] 每个步骤前后截图
  [✓] 网络请求清单（0 5xx，认证页面的0 403/404）
```

每个复选框都需要一个工具调用（点击、截图、控制台读取）和时间戳+选择器记录。代理无法生成"通过"报告而没有完整的清单。

**每个审计页面所需的条目**：

- ≥ 1输入键入（真实文本，而不仅仅是点击）
- ≥ 1主要操作触发（发送/保存/提交/创建/发布——无论哪个适合）
- ≥ 1模态或详细信息面板打开
- ≥ 1主要操作后读取控制台
- ≥ 1主要操作前后截图
- 验证预期后操作状态（输入清除，成功提示，路由更改，列表更新）

完整模板+重播协议在[参考资料/交互清单.md](参考资料/交互清单.md)。

### 线程遍历

对于每个线程：

1. **从应用程序入口点开始**——不是线程中。真实用户在`/`或`/dashboard`着陆。
2. **以角色身份演练**——如果他们会浏览，就浏览。如果他们会误读标签，就误读。注意犹豫。
3. **截图每个状态变化**——默认→悬停/焦点→活动→点击后→加载后→确认。电影胶片是证据。
4. **跟踪成本**——点击次数、决策点、死胡同、中断恢复（在步骤3关闭标签，在步骤4返回——状态是否存活？）
5. **在每次线程结束时将截图交给子代理进行审查**。

在每次线程结束时，以角色的身份回答：*是否清晰地结束？我会回来吗？让这个变得容易两倍的一件事？*

见[参考资料/演练清单.md](参考资料/演练清单.md)和[参考资料/工作流理解.md](参考资料/工作流理解.md)。

### 元素耗尽

对于每个路由，工作清单。跳过线程遍历已经锻炼的元素。详情见[参考资料/演练清单.md](参考资料/演练清单.md)。

对于**每个列表/表格**，如果数据允许，测试在0/1/100/1000+的容量。

### 多面板压力（对于具有可折叠UI的应用程序强制）

面板组合隐藏了最差的布局错误——仅在1024-1280px且所有三个面板都打开时才出现的垂直文本在空间中的错误。对于具有侧边栏/成员/线程/抽屉/面板的应用程序，运行矩阵：1920 / 1440 / **1280（高错误）** / **1024（灾难性错误）** / 768 / 375 × 所有打开，2面板，1面板，默认。对于每个组合：滚动最长的内容，捕获截图，运行布局检测JS以检测溢出/剪切/垂直文本堆栈。完整矩阵+JS片段+自动化在[参考资料/多面板压力.md](参考资料/多面板压力.md)。

### 新用户视角（强制）

除了锁定的角色，每个多页功能都必须通过**新用户**检查。这捕获了内部/AI工具最大的UX失败模式：由设计它们的人构建的功能对它们有效，但一个全新的用户在相同的屏幕上不知道任何控件的意思。

采用*某人第一次登录此应用程序，没有任何先验知识、没有源访问、没有内部文档*的角色。对于每个屏幕询问：

| 问题 | 它捕获的内容 |
|---|---|
| 我能在不阅读代码或文档的情况下完成任务吗 | 将隐藏的技术知识融入表单 |
| 字段标签是普通语言，而不是内部词汇吗 | `agentClass`、`slug`、`webhook_id`泄漏到UI中 |
| 下拉菜单/选择器显示**每个选项的作用**，而不仅仅是ID | 蛇形枚举、原始类名、不透明的slugs |
| 默认值是否足够合理以保留并继续？ | 必填字段没有默认值，强制ID输入 |
| 当需要输入时，是否存在可发现的值列表？ | 应用于应使用组合框的自由文本输入 |
| 如果我因为不理解设置而说"点击跳过"，那是一个UX错误。 | 可选但令人困惑的设置作为主要输入公开 |

当镜头触发时，即使屏幕在技术上可以工作，也要记录一个发现。常见修复：用选择器替换文本输入，公开元数据，自动派生值，将内部ID隐藏在"高级"下，添加内联指导。

当屏幕通过镜头时，一个全新的角色可以完成任务，而无需背通道帮助。

见[参考资料/演练清单.md](参考资料/演练清单.md)和[参考资料/工作流理解.md](参考资料/工作流理解.md)。

### 实时交互烟雾

代码读取验证按钮存在并具有`onClick`。它不会验证点击实际上做了什么可观察的事情。对于每个页面上的每个交互控件：

1. **点击它。** 指针移动，元素高亮，点击落地。
2. **观察网络选项卡。** 是否发出请求？到正确的URL？正确的方法+正文？
3. **观察DOM。** 是否有明显的更改——新元素，删除元素，状态转换？
4. **如果(2)或(3)中没有任何更改，那就是一个错误。**

已知静默失败控件（工具调用卡片上的Approve/Deny、对话框中的OAuth阻止、异步验证表单、乐观UI删除、偏移量分页、具有陈旧TanStack Query的过滤器芯片、回复/转发没有Message-ID）：见[参考资料/实时交互烟雾.md](参考资料/实时交互烟雾.md)的完整静默失败目录和SDK合同检查（`@ai-sdk/react`、better-auth、TanStack Query、React Router v7、Radix Dialog、zodResolver）。

### 循环工作流完整性（强制）

由电池中的场景10（阶段5）覆盖。在阶段3演练中运行它——在遍历线程时遇到的每个A→B→A流程在继续之前进行完整突变，并验证返回的A反映了新状态，而无需重新加载。可发现的返回约定。标题徽章更新。最大的"项目只是空白的当我回去"来源。

见[参考资料/循环工作流.md](参考资料/循环工作流.md)。

### 响应式扫描

每个宽度上的布局检测JS（溢出、剪切、隐藏文本）。捕获过渡点。与上述多面板压力测试结合，以实现全面覆盖。

### 认证过期中审计

如果导航或API调用在先前认证的路由上返回401/403，则会话丢失。**不要无声地重新认证**——每个后续观察都是损坏的。停止，捕获破坏步骤（无声过期本身就是一个发现）。以结论`Incomplete`终止，建议重新认证+重启。完整协议+发现标准在[参考资料/认证过期处理.md](参考资料/认证过期处理.md)。

## 阶段4——润色

### 视觉润色扫描

页面按页面的微观润色扫描，涵盖十个AI指示类别：光学居中、嵌套border-radius规则、离尺度间距、vibe greys、border-weight漂移、drop-shadow方向、动画时间偏离规范、hover-delta校准、下划线/大写字母间距、对称与编辑节奏。

此外，为按钮、徽章、输入、下拉菜单、卡片、选项卡、头像、toast进行每个组件的光学扫描。

完整协议与DevTools工作流、严重性指南和校准参考应用程序在[参考资料/视觉润色.md](参考资料/视觉润色.md)。

### 组件完美性清单

组件级粒度页面级审计会遗漏。六个类别，每个类别都有具体的yes/no检查，需要证明工件：

1. **按钮和触发器**——状态清晰度、意图匹配、微文案、加载状态、层次结构
2. **输入和表单**——持久标签、掩码、内联验证、错误清晰度、默认值
3. **导航和层次结构**——我在哪里？点击深度、搜索逻辑、粘性标题栏
4. **视觉一致性**——图标一致性、空状态、border radii、对比度
5. **移动和触摸**——可点击表面（≥ 48×48）、键盘优化、滑动手势
6. **性能和反馈**——骨架屏幕、成功toast、仅高风险的确认模态

此外，每个主要组件的六个视觉状态（默认、骨架、空、部分、错误、禁用）——空白处的骨架不是骨架。

报告中的每个复选框都引用一个证明工件（截图、控制台行、DOM选择器、代码引用）。没有证明=不计入。

完整清单在[参考资料/完美性清单.md](参考资料/完美性清单.md)。

### 自动化无障碍（axe-core，强制）

手动键盘仅步行（场景5）捕获焦点陷阱和tab顺序。它们遗漏了约80%的结构性无障碍错误（标题跳过、悬停/focus对比度失败、缺少aria-labels、角色不匹配）。axe-core在不到1秒内覆盖了80%。

对于每个审计页面：

1. 通过CDN注入axe-core（一个script标签）。
2. 页面稳定后运行`axe.run()`。
3. 违规映射→审计发现（axe `critical` → 审计Critical，axe `serious` → 审计High，等等）
4. 硬性门槛：> 0 axe Critical或> 0 axe Serious在任何页面上=审计失败。

一个16路由审计的总运行时间约为16秒。通过项目的audit-config（路径回退链在[参考资料/审计配置.md](参考资料/审计配置.md)）进行允许，用于构建者模式参考页面（组件、样式指南）。完整片段、严重性映射和发现格式在[参考资料/无障碍自动化.md](参考资料/无障碍自动化.md)。

### 性能预算（实用，强制）

在代表性路由上运行一次性能API捕获（通常用户最常访问的页面——通常是仪表板或主要工作表面）。实用预算（LCP < 4.0秒，CLS < 0.25，INP < 500毫秒）远高于损坏，远低于Google的CWV"良好"层。CWV-严格是为着陆页面和营销团队准备的；对于真实用户坐在其中的应用程序内部，实用的是正确的标准。

添加到结论块。任何阈值违规都会触发硬性门槛。使用Chrome DevTools Performance跟踪诊断（大型英雄、晚字体的成本、重点击处理程序的成本、hydration成本）。完整测量片段、限制规范和常见错误在[参考资料/性能预算.md](参考资料/性能预算.md)。

## 阶段5——压力

### 场景电池（11个场景）

所有11个，始终。它们捕获屏幕逐页测试遗漏的内容。完整协议在[参考资料/场景测试.md](参考资料/场景测试.md)。

1. **首次接触**——在没有先验知识的情况下弄清楚应用程序，并编写每个线程的2分钟纯英文指南。
2. **中断工作流**——开始任务，关闭标签，在表单中途刷新，导航到其他地方。状态是否存活？
3. **走错路恢复**——故意点击错误。需要多少点击才能恢复？
4. **返回用户**——重复线程。更快？快捷方式？你能告诉我自上次访问以来发生了什么变化吗？
5. **仅键盘**——每个线程仅键盘。焦点可见，tab顺序逻辑，Escape关闭。
6. **大量数据**——播种500+条记录。列表虚拟化，搜索返回正确的内容，过滤器缩小。
7. **破坏性信心**——每个删除/发送/发布/支付/分享：同意清晰，复制特定，撤销可用。
8. **第二个用户（角色）**——受限角色（查看者不是编辑者，客户不是员工）。只读视图，权限错误。
9. **生命周期位置**——角色#1（创始人），#2（第一个邀请者，部分状态），#N（后来的加入者，填充的工作空间）。每个看到不同的现实。
10. **循环工作流完整性**——每个A→B→A流程：在B上进行完整突变，并在返回时验证A反映了新状态，而无需重新加载。可发现的返回约定。标题徽章更新。应用程序中的A→B→A流程完整性是最大的"项目只是空白的当我回去"来源。
11. **数据季节化**——第0天/1天/7天/30天播种范围。时间分布数据捕获了数量测试遗漏的内容：时间分隔符、最新排序、cron触发的影响、通知徽章溢出、搜索历史性能、图表桶化。如果不存在时间分布数据，请跳过。完整协议+项目播种脚本架构在[参考资料/数据季节化.md](参考资料/数据季节化.md)。

### 扩展压力配方

除了场景之外，运行[参考资料/压力测试配方.md](参考资料/压力测试配方.md)中的每个相关配方：

| 压力 | 它捕获的内容 |
|------|-----------------|
| 空的/饱和的/长内容 | 边缘布局AI在开发过程中很少看到 |
| 竞态条件（双击，快速输入然后失去焦点，慢网络） | 乐观UI错误，debounce失败 |
| 慢网络（3G限制） | 加载状态，骨架节奏，超时UX |
| 减少运动（`prefers-reduced-motion: reduce`） | 忽略偏好的动画 |
| i18n（长德语，RTL阿拉伯语，CJK宽度） | 对文本长度的布局假设 |
| 离线模式 | 重试/队列/脏状态UX |
| 打印样式表 | 遗忘媒体查询 |
| 高对比度模式 | 强制颜色媒体查询处理 |
| **真实风味数据电池**（接受任何表单应用程序的强制） | 验证静默删除字符的验证（撇号、重音符号、RTL）；长度截断而无需警告；SQL/XSS canaries未转义；文件上传不适用（.heic，8000×8000 PNG，50MB PDF）。AI构建的UI以开发数据干净而闻名。 |

## 自主性

- **直接执行**：导航，截图，读取页面，注入布局检测JS，提交表单使用假测试数据，写入报告文件，派发截图审查子代理。
- **先询问**：破坏性行动（删除，发送，发布，支付）。对于破坏性信心测试，在运行该场景之前询问一次。
- **停止并确认**：任何向外部人员发送电子邮件/通知的操作。

## 执行纪律

1. **从主会话驱动审计，而不是子代理**。跨交互状态存在于正在观察的会话中。一个全新的子代理是冷启动的，会错过二级发现。
2. **直接使用浏览器工具**。Chrome MCP或Playwright MCP从主会话。不要将截图交给一个全新的代理进行意见反馈。
3. **循环到 exhaustion with variations**。在每次通过之后，生成一个新的角度（不同的角色，不同的工作流，不同的输入量，不同的起始点）。只有在完整通过不再产生新发现时才停止。

对于预期运行时间超过30分钟的审计，设置一个15分钟的`/loop`检查 alongside the main session — 它记录发现，使会话立足，并提供一个自然的终止信号。见[参考资料/长时间运行检查模式.md](参考资料/长时间运行检查模式.md)。

## 小贴士

- **每个犹豫都是发现**。如果你停下来思考如何点击，那是一个值得报告的摩擦。
- **大量使用吸管**。最快的方法是找到vibe greys、off-token颜色、设计系统漂移。
- **覆盖率是算术**。清单中的发明家÷测试。在报告中发布该比率。
- **子代理用于截图审查和增量写入发现**。不要在单个循环中驱动浏览器并分析200张截图。报告文件比你的上下文更便宜。
