# 响应式测试

测试网站布局如何响应视口宽度变化。在单个浏览器会话中通过断点进行缩放，对每个宽度进行截图，比较相邻尺寸，并报告布局出错的位置。

**测试内容**：布局响应性 — 溢出、堆叠、导航过渡、内容重排。

**不测试内容**：通用可访问性（ARIA、语义HTML、标题层级、色彩对比）。这些不随视口宽度变化 — 使用ux-audit技能代替。

## 浏览器工具优先级

开始前，检测可用的浏览器工具：

1. **playwright-cli**（首选） — 支持缩放、命名会话和子代理并行。如果已安装，首先运行`/playwright-cli`加载完整命令参考。
2. **Playwright MCP** (`mcp__plugin_playwright_playwright__*`) — `browser_resize`用于视口变化。
3. **Chrome MCP** (`mcp__claude-in-chrome__*`) — `resize_window`用于视口变化。使用用户登录的Chrome会话。

如果没有可用工具，通知用户并建议安装playwright-cli或Playwright MCP。

## 操作模式

### 模式1：标准测试

**适用场景**："check responsive"、"responsiveness check"、"test breakpoints"

测试覆盖设备范围的8个关键断点：

| 宽度 | 设备上下文 |
|------|-----------|
| 320px | 小手机（iPhone SE） |
| 375px | 标准手机（iPhone 14） |
| 768px | 横屏平板（iPad） |
| 1024px | 横屏平板/小笔记本电脑 |
| 1280px | 笔记本电脑 |
| 1440px | 台式机 |
| 1920px | 全高清 |
| 2560px | 超宽/4K |

**流程**：

1. 在单个浏览器会话中打开URL（高度：900px）
2. 从320px开始。对每个断点宽度：
   a. 调整视口大小
   b. 等待短暂CSS重排（布局过渡）
   c. 截图首屏内容
   d. 如果页面有重要首屏以下内容，滚动并截图
   e. 运行8个布局检查（见下表）
   f. 记录任何严重问题
3. 比较相邻宽度 — 识别布局过渡发生的位置
4. 撰写报告

### 模式2：扫描

**适用场景**："responsive sweep"、"sweep all breakpoints"、"find where it breaks"

从320px到2560px每160px测试一次（共15个宽度）。与标准模式相同，只是数据点更多。这是找到**精确宽度**布局出错的模式。

宽度：320, 480, 640, 800, 960, 1120, 1280, 1440, 1600, 1760, 1920, 2080, 2240, 2400, 2560

**开始扫描前简要确认**（15张截图是一个有意义的会话）。

### 模式3：目标范围

**适用场景**："check between 768 and 1024"、"test tablet breakpoints"、"focus on mobile widths"

测试用户指定的80px增量范围。当已知问题区域需要详细调查时使用。

示例："check between 768 and 1024"测试：768, 848, 928, 1008（加上1024作为终点）。

### 多URL

测试多个URL（例如："check the homepage, about page, and contact page"）：

- 启动**并行子代理**，每个URL一个（不是每个断点一个）
- 每个子代理在其自己的命名会话中对其URL运行标准检查
- 将结果合并为单个报告

```
# 子代理模式（playwright-cli）
playwright-cli -s=page1 open https://example.com/ &
playwright-cli -s=page2 open https://example.com/about &
```

## 布局检查矩阵

这8个检查针对随视口宽度实际变化的**问题**：

| # | 检查项 | 查找内容 |
|---|-------|---------|
| 1 | **水平溢出** | 内容超出视口 — 出现水平滚动条，元素被裁剪 |
| 2 | **文本溢出** | 文本中间截断，重叠相邻元素，字体大小不可读（<12px） |
| 3 | **导航过渡** | 汉堡菜单在正确宽度出现/消失，模式间无"损坏"状态 |
| 4 | **内容堆叠** | 多列布局在窄宽度上堆叠为单列，逻辑阅读顺序 |
| 5 | **图像/媒体缩放** | 图像溢出容器，变形的宽高比，缺少响应式尺寸 |
| 6 | **触摸目标** | 移动宽度（<768px）上的交互元素<44px — 按钮、链接、表单输入 |
| 7 | **空白平衡** | 手机上太拥挤（无呼吸空间），宽屏上太稀疏（内容丢失在空间中） |
| 8 | **CTA可见性** | 每个宽度上主要行动号召在首屏可见，无需滚动 |

## 过渡检测

此技能的独特价值在于**找到布局过渡发生的位置**以及是否干净。

当比较相邻宽度的截图时，标记任何以下宽度：
- **列数变化**（3列→2列→1列网格）
- **导航模式切换**（全导航→汉堡菜单，反之亦然）
- **侧边栏出现/消失**（内容宽度跳跃）
- **网格重排**（卡片换到下一行）

报告每个过渡发生的**精确宽度范围**：

| 过渡 | 从 | 到 | 宽度范围 |
|------|---|----|----------|
| 导航：汉堡菜单→全导航 | 768px | 1024px | 在~960px切换 |
| 网格：1列→2列 | 640px | 768px | 在~700px重排 |
| 侧边栏出现 | 1024px | 1280px | 在~1100px显示 |

这告诉开发者**精确位置**需要设置（或修复）CSS断点。

## 严重程度等级

与ux-audit一致：

| 严重程度 | 含义 |
|---------|------|
| **严重** | 布局损坏 — 内容不可读，导航无法访问，页面无法使用 |
| **高** | 显著布局问题 — 主要溢出，关键内容隐藏，损坏的过渡 |
| **中** | 可见但可用 — 不自然的间距，轻微溢出，堆叠顺序欠佳 |
| **低** | 精细调整 — 空白调整，轻微对齐问题，轻微触摸目标不足 |

## 自主规则

- **直接执行**：调整视口大小，截图，分析布局，比较宽度
- **简要确认**：扫描模式（15个视口），测试4+个URL并行时
- **先询问**：交互表单或点击认证流程前
