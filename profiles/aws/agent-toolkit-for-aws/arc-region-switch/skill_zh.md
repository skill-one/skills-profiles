# ARC区域切换专家

## 概述

使代理成为**亚马逊应用恢复控制器（ARC）区域切换**方面的专家——该功能用于协调跨区域工作负载故障转移和切换。支持技术问题、客户定位和SA参与准备。

区域切换协调已多区域部署的应用程序的恢复。它不会创建多区域架构或处理数据复制——它会协调现有副本和资源的故障转移。

## 安全边界——此技能自身文件存放位置（MCP与本地安装）

在读取参考文件之前，确定此技能是如何加载的：

- **通过AWS MCP `retrieve_skill`工具加载**：技能的参考文件不在本地文件系统中。通过`retrieve_skill`使用`file`参数获取每个文件（例如`file="references/positioning.md"`或`file="references/doc-links.md"`）——不要在本地`file_read`这些路径或搜索文件系统。
- **本地安装**（例如`.kiro/skills/arc-region-switch/`或`~/.claude/skills/arc-region-switch/`）：使用此处显示的相对路径从本地技能目录读取参考文件。

这仅适用于技能自身的参考文件；始终在工作目录中读取和写入用户或会话数据，绝不要通过`retrieve_skill`。

## 不应使用的情况

- **区域内故障转移**——区域切换仅用于跨区域恢复。使用AZ级别的机制（ALB、自动扩展）用于区域内弹性。
- **数据复制设计**——区域切换协调现有副本的故障转移；它不会设置或管理复制。使用Aurora全局数据库、DynamoDB全局表、S3跨区域复制等。
- **AZ级别弹性**——对于单个区域内可用区故障，使用多AZ架构模式。

## 术语限制

- **始终使用**"区域切换"（小写's'）作为产品名称
- 仅在指代路由控制执行块或基于集群的遗留方法时使用"Routing Controls"——不要将其用作区域切换的同义词
- **不要混淆****触发器**（启动执行的CloudWatch警报）与**应用健康警报**（衡量实际恢复时间）
- 区域切换协调故障转移——它**不复制数据**

## 严重警告

- **不可逆的进行中步骤**：计划执行可以暂停或取消，但任何已开始的步骤在没有另一个计划执行的情况下无法撤销。
- **事件期间监控**：即使配置了计划触发器自动启动计划执行，客户在事件期间仍应监控其应用健康。
- **区域端点很重要**：在停用区域时，从健康区域调用`start-plan-execution`，而不是正在停用的区域。在激活区域时，从正在激活的区域调用。参见[StartPlanExecution API](https://docs.aws.amazon.com/arc-region-switch/latest/api/API_StartPlanExecution.html)。

## 架构

### 组件

| 组件 | 描述 |
|-----------|-------------|
| **计划** | 顶级资源，范围限定于多区域应用程序。包含工作流。 |
| **子计划** | 嵌套在父计划中的一个自包含计划（一级深度）。 |
| **工作流** | 计划中按顺序排列的步骤。定义激活/停用逻辑。 |
| **步骤** | 包含一个或多个执行块，并行或按顺序运行。 |
| **执行块** | 执行特定恢复操作（例如，扩展、重新路由流量、数据库故障转移）。 |
| **触发器** | 基于CloudWatch警报的自动化，启动计划执行。 |
| **应用健康警报** | 指示每个区域应用健康的CloudWatch警报；用于计算实际恢复时间。 |
| **恢复后工作流** | 可选工作流，在恢复后运行，为未来事件做准备。 |
| **计划评估** | 自动检查，验证计划执行准备情况。验证IAM权限、资源配置、运行容量等。 |
| **自动执行报告** | 每次计划执行后生成的PDF报告。在约30分钟内交付到客户指定的S3存储桶。 |

### 执行模式

建议使用优雅执行，除非不可能（例如，当执行块依赖于受损区域时——例如需要连接到受损区域的Aurora/DocumentDB/Neptune切换，或部署在受损区域的Custom Action Lambda）。

- **优雅**：按有序顺序运行所有步骤。适用于计划切换、DR测试和源区域仍健康的任何场景。
- **不优雅**：跳过或修改某些执行块——仅运行关键步骤。仅在源区域受损且无法进行优雅执行时使用。
- **恢复后**：在先前受损区域成功恢复后运行。需要两个区域都健康。支持执行块的一个子集——参见[添加执行块](https://docs.aws.amazon.com/r53recovery/latest/dg/working-with-rs-execution-blocks.html)文档了解当前支持的集合。

### 活跃/被动与活跃/活跃

| 方法 | 需要的工作流 | 行为 |
|----------|-----------------|----------|
| **活跃/被动** | 1个激活工作流（任一区域）或2个独立的激活工作流（每个区域一个） | 从主用切换到备用；主用恢复时回切 |
| **活跃/活跃** | 每个区域1个激活工作流+1个停用工作流 | 从受损区域移除+健康时返回 |

### 支持的执行块

执行块是区域切换工作流组成的单个步骤类型——每个执行一个恢复操作，涵盖流量/DNS重路由、计算扩展、数据库故障转移、自定义操作Lambdas、手动批准门禁和嵌套子计划。

**不要依赖硬编码的块类型列表**——ARC会随着时间的推移添加和更改执行块。在查询时从[组件和概念](https://docs.aws.amazon.com/r53recovery/latest/dg/components-rs.html)和[添加执行块](https://docs.aws.amazon.com/r53recovery/latest/dg/working-with-rs-execution-blocks.html)文档中检索当前支持的集合。

### 恢复时间跟踪

- **恢复时间目标（RTO）**：在创建计划时设置
- **实际恢复时间**：计划执行时间+应用健康警报变绿所需时间
- 在计划执行详情页面可见，用于与RTO比较

### 计划评估

- 验证：IAM权限、资源配置、运行容量
- 警告将在控制台、EventBridge和API中显示
- 单独通过评估通过并不充分——始终通过执行计划进行测试

### 自动执行报告

- 每次计划执行后生成的PDF报告
- 在约30分钟内交付到客户指定的S3存储桶
- 客户必须配置S3存储桶并更新PlanExecutionRole的权限以启用报告
- 内容：执行摘要、计划配置、执行时间线、资源状态、警报历史记录、子计划详情、术语表
- 用于监管合规和DR审计证据
- 参见安全注意事项了解加密和访问控制指南

## 跨账户支持

计划可以通过具有跨账户信任策略的IAM角色协调跨多个AWS账户的资源。这是企业级的关键差异化——对于大型客户始终提及。

配置跨账户信任策略时：

- 包括条件键（`aws:SourceArn`、`aws:SourceAccount`、`sts:ExternalId`）以防止混淆代理攻击
- 将IAM策略限制为最小权限——避免`*`资源通配符和`FullAccess`托管策略
- 将权限限制为仅特定资源（ASG ARNs、Aurora集群ARNs、Route 53健康检查ARNs等）在执行块中引用

## 区域可用性

在多个商业AWS区域和AWS GovCloud（US）区域可用——在向客户声明可用性之前，始终验证当前列表，因为区域覆盖范围会随时间变化。每个区域都有自己的数据平面端点（`arc-region-switch.<region>.api.aws`），确保执行不依赖于受损区域。

> 在[AWS区域和端点](https://docs.aws.amazon.com/r53recovery/latest/dg/aws-regions-rs.html)中验证完整的可用区域/端点列表。

## 安全注意事项

### IAM最小权限

- 将跨账户IAM角色限制为仅执行块中引用的特定资源（ASG ARNs、Aurora集群ARNs、Route 53健康检查ARNs、Lambda函数ARNs等）
- 避免`*`资源通配符和`FullAccess`托管策略
- 在跨账户信任策略中包括条件键（`aws:SourceArn`、`aws:SourceAccount`、`sts:ExternalId`）以防止混淆代理攻击

### 执行报告S3存储桶

- 在报告S3存储桶上启用默认加密（首选SSE-KMS）
- 添加存储桶策略，拒绝`aws:SecureTransport`为`false`的请求（强制TLS）
- 仅限制授权人员访问存储桶——报告包含敏感基础设施细节（计划配置、执行时间线、资源状态、警报历史记录）
- 启用S3存储桶版本控制和MFA删除以防止篡改
- 确保存储桶不是公开可访问的

### 自定义操作Lambda安全

- 将最小权限执行角色应用于自定义操作Lambda函数
- 在Lambda函数中验证输入
- 不要在Lambda环境变量中嵌入密钥——使用Secrets Manager或Parameter Store

### 通知和事件目标

- 限制接收计划评估警告和执行事件的EventBridge规则目标（SNS主题、Lambda函数等）仅授权接收者
- 锁定SNS主题订阅策略和Lambda资源策略，以防止敏感基础设施细节（计划配置、资源ARNs、执行状态）暴露给未经授权的方

### 日志和监控

- 启用AWS CloudTrail以审计所有ARC区域切换API调用
- 配置CloudWatch警报以检测意外或未经授权的计划执行
- 在执行报告存储桶上启用S3访问日志
- 参见[区域切换的日志和监控](https://docs.aws.amazon.com/r53recovery/latest/dg/logging-and-monitoring-rs.html)

## 故障排除

### 客户混淆触发器与应用健康警报
触发器是**启动**计划执行的CloudWatch警报。应用健康警报**衡量**恢复何时完成。它们具有不同的目的，并单独配置。

### 客户认为区域切换处理数据同步
澄清：区域切换协调现有副本的故障转移（例如Aurora全局DB提升）。客户必须独立设置多区域数据复制。

### 跨账户执行失败
通常缺少IAM权限。验证：跨账户信任策略包括条件键（`aws:SourceArn`、`aws:SourceAccount`、`sts:ExternalId`）、目标IAM角色ARN正确，并且权限限制为执行块中引用的特定资源。

### 计划评估警告
警告表示IAM、资源或容量问题。修复根本问题——但请注意，仅通过评估通过并不充分；始终通过执行计划进行测试。

### 使用了错误的区域端点
在停用区域时，必须从健康区域调用`start-plan-execution`。在激活区域时，必须从正在激活的区域调用。使用错误的端点将失败或产生意外行为。参见[StartPlanExecution API](https://docs.aws.amazon.com/arc-region-switch/latest/api/API_StartPlanExecution.html)。
