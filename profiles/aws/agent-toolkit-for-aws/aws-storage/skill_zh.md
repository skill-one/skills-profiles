## 概述

这项技能为选择 AWS 存储服务、选择存储类别、优化成本以及路由到操作存储服务的资源提供了专业领域知识。它涵盖了对象存储（S3 通用存储桶及其存储类别、S3 Express One Zone 目录存储桶、S3 表格、S3 向量）、文件存储（Amazon EFS、S3 文件、FSx for Lustre、FSx for NetApp ONTAP、FSx for OpenZFS 和 FSx for Windows File Server）、块存储（EBS 卷类型和 EC2 实例存储）以及连接它们的移动和保护服务（DataSync、Storage Gateway、Transfer Family 和 AWS Backup）。它不提供数据库或分析查询引擎的建议。它可与 AWS MCP 服务器一起使用或单独使用；当可用时，建议使用 [AWS MCP 服务器](https://docs.aws.amazon.com/agent-toolkit/) 来验证当前规范和定价，并且所有指导也适用于标准 AWS CLI。对于深度的单服务任务，请路由到下方路由部分中列出的专业技能。

## 如何处理用户查询

当此技能被触发时，对用户的请求进行分类并遵循相应的路径。

### 规则

这些规则适用于所有路径的响应，无论路径如何：

1. 您必须验证当前数字。当 AWS MCP 服务器可用时，使用 search_documentation 和 read_documentation 进行交叉检查，然后再引用具体信息。在引用成本时，您必须包含相关定价页面的链接。在引用性能指标时，您必须包含相关产品页面的链接。否则，请与链接的 AWS 文档页面进行验证或使用 AWS CLI 确认当前值。如果参考文件指导您获取当前值的文档，您必须在回答之前从链接页面检索该值。不要替代记忆中的数字，不要用估算值或范围代替检索到的值。如果当前环境中无法检索，请命名您无法验证的值，而不是引用记忆中的值。
2. 您必须在回答有关该服务的问题之前，从下方路由部分中检索相关服务参考文件。AWS 存储规范、限制和服务功能经常变化。您必须不能仅凭记忆回答。您必须在您的响应中呈现参考文件中的相关故障排除指南和“陷阱”。通过工作负载匹配来证明建议，而不是提及参考文件“明确”提到了给定服务的某个工作负载。
3. 您必须在推荐服务或方法时包含成本影响。不要等待用户提问。不要仅基于存储费用来比较服务；对象费用（如元数据费用）可能会实质性地改变 TCO。对于超出存储选择的深度成本分析、监控或优化，请路由到 [`billing-and-cost-management`](https://github.com/aws/agent-toolkit-for-aws/tree/e2588f4b494416e68c5a991e51b21c2d99038de3/skills/core-skills/aws-billing-and-cost-management) 技能。
4. 当提供建议时，您必须明确用户的需求。将您的响应的具体性匹配到请求的具体性。当查询确定存储类别和相关服务时，直接检索信息并提供建议。当查询未完全指定时，您必须提及建议的假设和限制，并包含将确认或更改它的附加问题。仅在查询完全不允许您确定存储类别时，才用后续问题代替建议。即使它超出此技能的范围，也推荐最适合工作负载的服务；将相关范围内的选项作为替代方案添加。

### 第一步：分类意图

确定用户需要什么：

| 意图 | 示例触发器 | 这意味着什么 |
| --- | --- | --- |
| SELECT | "我应该使用什么？", "哪个服务？", "比较服务 A 和服务 B", "帮助我选择", "我想将 X 迁移到 AWS"（没有命名服务的工作负载描述） | 用户需要帮助选择存储服务或方法 |
| INVESTIGATE | "我如何配置服务 X？", "服务 Y 为什么失败？", "服务 Z 的限制是什么？", "我如何开始使用服务 X？"（命名特定服务并提出操作性问题） | 用户知道他们正在使用什么，并需要入门、故障排除或操作帮助 |

您必须遵循下面相应的路径说明中的交互逻辑。

模糊案例：如果用户的主要请求是推荐，则无论上下文如何，它都是 SELECT。如果他们需要帮助执行已知计划，则它是 INVESTIGATE。

### 第 2a 步：SELECT 路径

用户需要帮助选择。您必须使用以下决策因素来为您提供建议，并询问问题以填补会改变选择的信息空白。

决策因素：

| # | 决策因素 | 需要理解什么 |
| --- | --- | --- |
| 1 | 工作负载上下文 | 这是一个新工作负载还是现有工作负载的迁移？如果迁移，源系统是什么（例如，NetApp、ZFS、Windows 文件服务器、Lustre、GPFS 等）？哪个应用程序或工作负载将访问此存储？它如何访问数据（API、文件协议、块设备）？客户端正在运行什么操作系统或平台？数据模型是什么（结构化/表格、向量嵌入、非结构化对象、文件系统）？ |
| 2 | 容量和访问模式 | 有多少数据，多少文件或对象，典型大小是多少？顺序访问还是随机访问模式？读重、写重还是混合？ |
| 3 | 性能要求 | 有特定的延迟、吞吐量或 IOPS 要求吗？预期的并发量是多少（同时访问的客户端或计算节点数）？ |
| 4 | 可靠性和数据保护 | 恢复时间目标 (RTO) 是什么？恢复点目标 (RPO) 是什么？合规保留要求是什么？跨区域弹性？不可变需求？ |
| 5 | 可用性 | 可以接受多 AZ 还是单 AZ？与特定计算共置？ |

使用存储选项表来识别候选服务，而不是削减服务；与常见工作负载列的关键字匹配不一定是唯一的答案。您必须使用下方路由部分检索每个候选服务的参考文件。

考虑这些因素，推荐特定的 AWS 存储服务（或服务），并：

1. 您必须包含与用户陈述要求相关的明确理由。
2. 您必须在选择接近或依赖于未指定信息的情况下提供替代方案，并解释权衡。

### 第 2b 步：INVESTIGATE 路径

用户知道他们的服务或方法，并需要操作帮助。

1. 根据下表对问题域进行分类，以确定哪个上下文很重要。

| 问题域 | 示例触发器 | 需要澄清什么 |
| --- | --- | --- |
| 迁移和数据传输 | "我如何将我的数据迁移到 AWS？", "设置 DataSync", "从本地 NFS 同步到 EFS", 源到目标问题 | 源系统和协议、目标服务、数据量、到 AWS 的网络路径（Direct Connect、VPN、互联网） |
| 数据保护和弹性 | "设置备份", "跨区域复制", "我的 DR 策略是什么？", "RTO 小于 1 小时", 故障转移、不可变 | 故障场景（删除、损坏、AZ/区域丢失、合规保留），RTO 和 RPO 目标，复制范围（同一区域、跨区域、跨账户） |
| 成本和生命周期 | "减少我的存储账单", "调整我的卷大小", "成本优化", 生命周期规则、分层决策、存储类别选择 | 当前服务和配置、访问频率（每日、每周、很少）、数据量和增长轨迹 |
| 性能 | "我的读取很慢", "吞吐量瓶颈", "我需要更多的 IOPS", 尺寸 | 观察到的与要求的对比（延迟、IOPS 或吞吐量），访问模式（随机/顺序、读写混合），是否怀疑存储、计算或网络是瓶颈 |
| 安全和合规 | "静态加密", "限制存储桶访问", "满足 HIPAA", 访问控制、合规框架 | 安全目标（限制访问、审计访问、加密、隔离网络、满足合规要求），如果有任何合规框架 |
| 配置和指导 | "在 EKS 上挂载 EFS", "设置复制", "服务 X 是否支持 Y？", 部署步骤、最佳实践 | 客户端环境（操作系统、计算类型、VPC/本地），目标操作或功能 |
| 故障排除 | "遇到 AccessDenied 错误", "挂载挂起", "意外的延迟激增", "为什么我的生命周期规则没有转换？" | 错误消息或症状，最近发生了什么，他们尝试了什么 |

2. 根据列出的“需要澄清什么”对信息不在查询中的情况进行范围问题。如果缺少的详细信息不会改变指导，则假设声明代替等待询问更多问题。
3. 您必须从下方路由部分检索所有候选服务的参考文件。
4. 提供具体、可操作的指导、陷阱和文档链接。

## 存储选项

此技能涵盖的 AWS 存储服务，按存储类别分组。有关存储类别的更多信息，请参阅 [块存储、文件存储和对象存储比较](https://aws.amazon.com/compare/the-difference-between-block-file-object-storage/)。

### 对象存储

| 服务 | 关键特性 | 常见工作负载 |
| --- | --- | --- |
| S3 通用 | 基本上无限扩展的对象存储，具有多个存储类别，从频繁访问到低成本归档；生命周期规则将数据移动到针对较少频繁访问数据优化的较低成本存储类别。区域可用性。通过 REST/HTTP API 从任何地方访问。 | 数据湖和分析、备份和归档目标、ML 训练数据、媒体存储和内容分发、日志和事件数据、静态网站和应用程序资源、监管和合规归档 |
| S3 Express One Zone | 单 AZ 目录存储桶，针对频繁访问的延迟敏感数据优化，具有个位数毫秒级延迟。 | 大规模 ML 训练和推理、Spark 和 EMR 混洗、ML 检查点、临时、ETL 中间数据、交互式分析热分区、可观察性和日志分析（热层）、Kafka 分层存储、媒体和视频编辑、高频事务访问、机器学习推理缓存 |
| S3 表格 | 在 S3 上管理的 Apache Iceberg 表格，具有自动压缩和查询优化。区域可用性。为结构化、表格数据构建，使用 SQL 引擎查询。 | 数据湖表格、结构化分析数据、ETL 管道输出、流式传输到用于 SQL 分析的表格、迁移到 S3 或自管理的 Iceberg 在 S3 之外的开表格式数据 |
| S3 向量 | 在 S3 上进行向量存储和相似性搜索，原生支持以经济高效的方式存储和查询向量嵌入。提供与 S3 通用存储桶相同的弹性、可靠性和可用性。区域可用性。 | RAG 管道、语义搜索、推荐系统、向量去重和匹配、异常和欺诈检测、AI 代理内存、经济高效的存储大型向量数据集 |
| S3 元数据 | 可查询的对象元数据，在完全管理的只读 Apache Iceberg 表格中，包括系统定义的详细信息、用户定义的元数据、对象标签和注释 | 业务分析、内容目录、数据治理和合规、存储优化、实时推理应用程序、AI 代理 |

### 文件存储

在命名服务时，您必须始终指定完整名称（FSx for Lustre、FSx for Windows File Server、FSx for NetApp ONTAP 或 FSx for OpenZFS）。EFS 和 S3 文件可以通过 Lambda 和 Fargate 挂载。使用最新的 AWS 文档验证可从无服务器计算挂载的附加服务。FSx for NetApp ONTAP 和 FSx for OpenZFS 数据可通过 S3 访问点从无服务器计算和基于 S3 的管道访问（通过 S3 API 显示文件数据，而无需复制；在用户需要从 S3 原生消费者或分析服务读取 FSx 居住数据时显示此功能）。

| 服务 | 关键特性 | 常见工作负载 |
| --- | --- | --- |
| EFS | EFS 标准、EFS 不频繁访问 (EFS IA) 和 EFS 归档存储类别，由 EFS 生命周期管理管理以自动成本优化。无容量规划或预配的无服务器弹性 NFS，可由 Lambda、Fargate、EC2、ECS 和 EKS 挂载。默认为多 AZ（区域）或单 AZ。共享 Linux 文件访问的最简单路径，具有跨许多并发客户端的高聚合吞吐量。 | 容器（ECS、EKS、Fargate）、云原生 Linux 应用程序、无服务器持久存储、分析 (包括 SageMaker) 和 ML 训练数据、大数据、媒体处理、内容管理、共享主目录、Web 服务、开发/测试、很少访问的文件数据 |
| FSx for Lustre | SSD 和智能分层存储类别，其中智能分层是完全弹性的，SSD 是固定容量的。为跨许多计算节点提供非常高的聚合吞吐量的大规模并行访问而设计的并行文件系统。 | 大规模的 ML 和 GPU 训练和推理、HPC、基因组学和地震处理、金融建模、媒体渲染、后端 EDA |
| FSx for OpenZFS | 智能分层和 SSD，与 ZFS 数据管理（即时可写克隆、快照、压缩、按需复制）结合使用。非常低延迟和高 IOPS，易于操作且对性能敏感的工作负载和快速开发/测试周期具有成本效益。单 AZ 和多 AZ 部署模型。通过 S3 访问点访问 FSx for NetApp ONTAP 或 FSx for OpenZFS。 | 数据库（包括在 EC2 上）、快速克隆的开发/测试、ZFS 或 Linux-NFS 迁移、前端 EDA、金融建模、媒体处理、延迟敏感的业务应用程序 |
| FSx for NetApp ONTAP | 完整的 ONTAP 数据管理（SnapMirror 复制、FlexClone、去重、压缩、SnapLock WORM、QoS、vscan 抗病毒、文件访问审计）。多协议：NFS、SMB、iSCSI、NVMe-over-TCP，以及通过 S3 访问点访问的 S3 API。可扩展到高聚合吞吐量和 IOPS。单 AZ 和多 AZ 部署模型。 | 企业网络附加存储 (NAS) 迁移、多协议环境、通用文件共享和主目录、业务关键数据库（包括在 EC2 上（SAP HANA、Oracle、SQL Server））、VMware 数据存储、业务应用程序（医学成像、产品生命周期管理）、前端 EDA（芯片设计和验证）、混合和 DR |
| FSx for Windows File Server | 基于 Windows Server 的完全管理 SMB 文件存储，具有 Active Directory 身份（Kerberos、NTFS ACL）、DFS 命名空间、阴影副本和 FSRM 配额；共享也可以从 Linux 和 macOS 客户端访问。单 AZ 和多 AZ 部署模型。 | Windows 文件、主目录和部门共享、.NET 应用程序、Microsoft SQL Server、Windows Server 迁移 |

### 块存储

| 服务 | 关键特性 | 常见工作负载 |
| --- | --- | --- |
| EBS | 高性能虚拟磁盘，通过网络连接到 EC2 实例。持久、可调整大小的 SSD 或 HDD，独立于实例而持久，支持快照用于备份、基于时间的快照复制，并在 gp3 上独立于容量提供性能（确认最新卷限制）。支持即时卷克隆。AZ 范围。 | 数据库、事务应用程序和文件系统、启动卷、开发/测试环境、顺序批处理、日志和数据仓库扫描 |
| EC2 实例存储 | 物理集成到主机服务器的本地 SSD 存储，提供最低延迟和最高吞吐量。易失性：如果实例停止或硬件故障，数据将丢失。 | 可以负担得起的临时临时数据、缓存和缓冲区 |
