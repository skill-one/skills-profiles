# React 模式

> 构建生产级 React 应用的原则。

---

## 1. 组件设计原则

### 组件类型

| 类型 | 用途 | 状态 |
|------|-----|-------|
| **服务器端** | 数据获取、静态 | 无 |
| **客户端** | 交互性 | useState、副作用 |
| **展示型** | UI 显示 | 仅接收 props |
| **容器型** | 逻辑/状态 | 复杂状态 |

### 设计规则

- 每个组件只有一个职责
- props 向下传递，事件向上传递
- 组合优于继承
- 优先使用小型、专注的组件

---

## 2. Hook 模式

### 何时提取 Hook

| 模式 | 提取时机 |
|---------|-------------|
| **useLocalStorage** | 需要相同存储逻辑时 |
| **useDebounce** | 多个防抖值时 |
| **useFetch** | 重复获取模式时 |
| **useForm** | 复杂表单状态时 |

### Hook 规则

- 仅在顶层使用 Hook
- 每次渲染保持相同顺序
- 自定义 Hook 以 "use" 开头
- 在卸载时清理副作用

---

## 3. 状态管理选择

| 复杂度 | 解决方案 |
|------------|----------|
| 简单 | useState、useReducer |
| 本地共享 | Context |
| 服务器状态 | React Query、SWR |
| 复杂全局 | Zustand、Redux Toolkit |

### 状态放置

| 范围 | 位置 |
|-------|-------|
| 单个组件 | useState |
| 父子组件 | 向上提升状态 |
| 子树 | Context |
| 应用全局 | 全局存储 |

---

## 4. React 19 模式

### 新 Hook

| Hook | 目的 |
|------|---------|
| **useActionState** | 表单提交状态 |
| **useOptimistic** | 乐观 UI 更新 |
| **use** | 在渲染中读取资源 |

### 编译器优势

- 自动记忆化
- 减少手动 useMemo/useCallback
- 专注于纯组件

---

## 5. 组合模式

### 复合组件

- 父组件提供上下文
- 子组件消费上下文
- 柔性插槽式组合
- 示例：Tabs、Accordion、Dropdown

### Render Props 与 Hooks 对比

| 用例 | 优先选择 |
|----------|--------|
| 可重用逻辑 | 自定义 Hook |
| 渲染灵活性 | Render Props |
| 跨切面 | 高阶组件 |

---

## 6. 性能原则

### 何时优化

| 信号 | 操作 |
|--------|--------|
| 渲染缓慢 | 先进行性能分析 |
| 大列表 | 虚拟化 |
| 昂贵计算 | useMemo |
| 稳定回调 | useCallback |

### 优化顺序

1. 检查是否确实缓慢
2. 使用 DevTools 进行性能分析
3. 识别瓶颈
4. 应用针对性修复

---

## 7. 错误处理

### 错误边界使用

| 范围 | 放置位置 |
|-------|-----------|
| 应用全局 | 根级别 |
| 功能模块 | 路由/功能级别 |
| 组件 | 包围有风险的组件 |

### 错误恢复

- 显示降级 UI
- 记录错误
- 提供重试选项
- 保留用户数据

---

## 8. TypeScript 模式

### Props 类型化

| 模式 | 用途 |
|---------|-----|
| Interface | 组件 props |
| Type | 联合类型、复杂类型 |
| Generic | 可重用组件 |

### 常用类型

| 需求 | 类型 |
|------|------|
| 子元素 | ReactNode |
| 事件处理器 | MouseEventHandler |
| Ref | RefObject<Element> |

---

## 9. 测试原则

| 级别 | 重点 |
|-------|-------|
| 单元测试 | 纯函数、Hooks |
| 集成测试 | 组件行为 |
| E2E 测试 | 用户流程 |

### 测试优先级

- 用户可见行为
- 边缘情况
- 错误状态
- 可访问性

---

## 10. 反模式

| ❌ 避免 | ✅ 推荐做法 |
|----------|-------|
| 深度 prop 钻探 | 使用 Context |
| 巨型组件 | 分割为小组件 |
| 所有场景使用 useEffect | 服务器组件 |
| 过早优化 | 先进行性能分析 |
| 使用索引作为 key | 稳定的唯一 ID |
