# 产品经理工具箱

面向现代产品管理，从发现到交付的必备工具和框架。

## 快速入门

### 用于功能优先级排序
```bash
python scripts/rice_prioritizer.py sample  # 创建示例CSV
python scripts/rice_prioritizer.py sample_features.csv --capacity 15
```

### 用于访谈分析
```bash
python scripts/customer_interview_analyzer.py interview_transcript.txt
```

### 用于PRD创建
1. 从`references/prd_templates.md`选择模板
2. 基于发现工作填写各部分
3. 与利益相关者评审
4. 在您的PM工具中进行版本控制

## 核心工作流

### 功能优先级排序流程

1. **收集功能请求**
   - 客户反馈
   - 销售请求
   - 技术债务
   - 战略计划

2. **使用RICE评分**
   ```bash
   # 创建包含：名称、影响范围、影响程度、信心水平、工作量的CSV
   python scripts/rice_prioritizer.py features.csv
   ```
   - **影响范围**：每个季度受影响的用户数
   - **影响程度**：巨大/高/中/低/极小
   - **信心水平**：高/中/低
   - **工作量**：xl/l/m/s/xs（人-月）

3. **分析产品组合**
   - 评审快速见效与重大赌注
   - 检查工作量分布
   - 与战略进行验证

4. **生成路线图**
   - 每季度容量规划
   - 依赖关系映射
   - 利益相关者对齐

### 客户发现流程

1. **进行访谈**
   - 使用半结构化格式
   - 聚焦问题而非解决方案
   - 经同意后录音

2. **分析洞察**
   ```bash
   python scripts/customer_interview_analyzer.py transcript.txt
   ```
   提取：
   - 痛点及严重程度
   - 功能请求及优先级
   - 需要完成的任务
   - 情感分析
   - 关键主题和引言

3. **综合发现结果**
   - 将相似的痛点分组
   - 识别访谈中的模式
   - 映射到机会领域

4. **验证解决方案**
   - 创建解决方案假设
   - 使用原型进行测试
   - 衡量实际与预期行为

### PRD开发流程

1. **选择模板**
   - **标准PRD**：复杂功能（6-8周）
   - **一页PRD**：简单功能（2-4周）
   - **功能简介**：探索阶段（1周）
   - **敏捷史诗**：基于Sprint交付

2. **结构化内容**
   - 问题 → 解决方案 → 成功指标
   - 始终包含不包含范围
   - 清晰的验收标准

3. **协作**
   - 工程可行性
   - 设计用户体验
   - 销售市场验证
   - 支持运营影响

## 关键脚本

### rice_prioritizer.py
高级RICE框架实现，包含产品组合分析。

**功能**：
- RICE评分计算
- 产品组合平衡分析（快速见效与重大赌注）
- 每季度路线图生成
- 团队容量规划
- 多种输出格式（文本/json/csv）

**使用示例**：
```bash
# 基本优先级排序
python scripts/rice_prioritizer.py features.csv

# 自定义团队容量（每季度人-月）
python scripts/rice_prioritizer.py features.csv --capacity 20

# 输出为JSON进行集成
python scripts/rice_prioritizer.py features.csv --output json
```

### customer_interview_analyzer.py
基于NLP的访谈分析，提取可操作的洞察。

**功能**：
- 痛点提取及严重程度评估
- 功能请求识别和分类
- 需要完成的任务模式识别
- 情感分析
- 主题提取
- 竞争对手提及
- 关键引言识别

**使用示例**：
```bash
# 分析单个访谈
python scripts/customer_interview_analyzer.py interview.txt

# 输出为JSON进行聚合
python scripts/customer_interview_analyzer.py interview.txt json
```

## 优先级框架

### RICE框架
```
评分 = (影响范围 × 影响程度 × 信心水平) / 工作量

影响范围：每季度用户数
影响程度：
  - 巨大 = 3x
  - 高 = 2x
  - 中 = 1x
  - 低 = 0.5x
  - 极小 = 0.25x
信心水平：
  - 高 = 100%
  - 中 = 80%
  - 低 = 50%
工作量：人-月
```

### 价值 vs 工作量矩阵
```
         低工作量    高工作量
         
高价值    快速见效    重大赌注
[优先排序]   [战略]
         
低价值    填充项    浪费时间
[可能]       [避免]
```

### MoSCoW方法
- **必须**：对发布至关重要的
- **应该**：重要但不关键
- **可以**：不错
- **不会**：超出范围

## 发现框架

### 客户访谈指南
```
1. 背景问题（5分钟）
   - 职责和责任
   - 当前工作流程
   - 使用工具

2. 问题探索（15分钟）
   - 痛点
   - 频率和影响
   - 当前解决方案

3. 解决方案验证（10分钟）
   - 对概念的反应
   - 价值感知
   - 愿意付费

4. 总结（5分钟）
   - 其他想法
   - 推荐人
   - 跟进许可
```

### 假设模板
```
我们相信，[构建此功能]
对于[这些用户]
将[实现此结果]
我们将知道我们正确时[指标]
```

### 机会解决方案树
```
结果
├── 机会1
│   ├── 解决方案A
│   └── 解决方案B
└── 机会2
    ├── 解决方案C
    └── 解决方案D
```

## 指标与分析

### 北极星指标框架
1. **识别核心价值**：用户最看重的价值是什么？
2. **使其可衡量**：可量化且可追踪
3. **确保可行动**：团队可以影响它
4. **检查领先指标**：预测业务成功

### 漏斗分析模板
```
获取 → 激活 → 留存 → 收入 → 推荐

关键指标：
- 每个步骤的转化率
- 损失点
- 步骤间时间
- 群组差异
```

### 功能成功指标
- **采用率**：使用功能的用户百分比
- **频率**：每个用户每段时间的使用量
- **深度**：使用的功能能力百分比
- **留存**：持续使用时间
- **满意度**：功能NPS/CSAT

## 最佳实践

### 写出优秀的PRD
1. 从问题开始，而非解决方案
2. 预先包含清晰的成功指标
3. 明确说明不包含范围
4. 使用视觉（线框图、流程图）
5. 技术细节放在附录
6. 版本控制变更

### 有效优先级排序
1. 混合快速见效与战略赌注
2. 考虑机会成本
3. 考虑依赖关系
4. 为意外工作预留20%
5. 每季度重新审视
6. 清晰传达决策

### 客户发现技巧
1. 重复问"为什么"5次
2. 聚焦过去行为，而非未来意图
3. 避免引导性问题
4. 在其环境中访谈
5. 寻找情感反应
6. 用数据验证

### 利益相关者管理
1. 决策的RACI识别
2. 定期异步更新
3. 演示优于文档
4. 早期解决问题
5. 公开庆祝胜利
6. 公开从失败中学习

## 需要避免的常见错误

1. **先考虑解决方案**：在理解问题前就跳到功能
2. **分析瘫痪**：过度研究而不发布
3. **功能工厂**：发布功能而不衡量影响
4. **忽视技术债务**：不分配时间维护平台健康
5. **利益相关者意外**：不早期频繁沟通
6. **指标剧场**：优化虚荣指标而非真实价值
