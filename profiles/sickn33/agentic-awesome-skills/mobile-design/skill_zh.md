# 移动设计系统

**(移动优先 · 触摸优先 · 尊重平台)**

> **理念：** 触摸优先。注重电池续航。尊重平台。支持离线使用。
> **核心法则：** 移动设备不是小型的桌面。
> **操作规则：** 先考虑限制条件，再考虑美观。

这项技能旨在防止在设计或构建移动应用程序时出现**桌面思维、AI 默认设置和错误假设**。

---

## 1. 移动可行性及风险指数 (MFRI)

在设计和实现**任何移动功能或界面**之前，评估其可行性。

### MFRI 维度 (1–5)

| 维度                  | 问题                                                          |
| ---------------------- | ------------------------------------------------------------- |
| **平台清晰度**       | 目标平台 (iOS / Android / 两者) 是否明确定义？                 |
| **交互复杂度**       | 手势、流程或导航有多复杂？                                     |
| **性能风险**         | 是否涉及列表、动画、复杂状态或媒体？                           |
| **离线依赖**         | 功能在没有网络的情况下会中断或降级吗？                         |
| **可访问性风险**     | 是否会影响运动、视觉或认知可访问性？                           |

### 分数公式

```
MFRI = (平台清晰度 + 可访问性准备度)
       − (交互复杂度 + 性能风险 + 离线依赖)
```

**范围：** `-10 → +10`

### 解释

| MFRI     | 含义   | 所需操作                       |
| -------- | ------ | ----------------------------- |
| **6–10** | 安全   | 正常进行                      |
| **3–5**  | 中等   | 增加性能 + UX 验证            |
| **0–2**  | 风险   | 简化交互或架构                |
| **< 0**  | 危险   | 在实施前重新设计             |

## 4. AI 移动反模式 (严格禁止)

### 🚫 性能罪 (不可协商)

| ❌ 永远                   | 原因                  | ✅ 总是                                |
| ------------------------ | --------------------- | -------------------------------------- |
| 使用 ScrollView 处理长列表 | 内存爆炸             | FlatList / FlashList / ListView.builder |
| 内联 renderItem         | 重新渲染所有行        | useCallback + memo                      |
| 使用索引作为 key         | 顺序错误             | Stable ID                               |
| JS 线程动画              | 卡顿                 | 原生驱动 / GPU                         |
| 生产环境中的 console.log  | JS 线程阻塞          | 移除日志                              |
| 无缓存机制              | 电池和性能消耗       | React.memo / const 组件                |

---

### 🚫 触摸和 UX 罪

| ❌ 永远               | 原因                  | ✅ 总是          |
| ------------------- | --------------------- | ---------------- |
| 触摸目标 < 44–48px  | 容易误触             | 最小触摸目标    |
| 仅手势操作           | 排除用户             | 按钮回退        |
| 无加载状态          | 感觉已损坏           | 明确反馈        |
| 无错误恢复          | 死胡同               | 重试 + 消息      |
| 忽略平台规范        | 肌肉记忆断裂         | iOS ≠ Android    |

---

### 🚫 安全罪

| ❌ 永远                | 原因                | ✅ 总是               |
| --------------------- | ------------------- | --------------------- |
| AsyncStorage 中的令牌 | 容易被盗            | SecureStore / Keychain |
| 硬编码密钥            | 可逆向工程          | 环境变量 + 安全存储   |
| 无 SSL 钩子          | 中间人攻击风险      | 证书钩子             |
| 记录敏感数据          | PII 泄露            | 永远不要记录密钥      |

## 6. 移动 UX 心理学 (非可选)

### Fitts 定律 (触摸现实)

* 指尖 ≠ 光标
* 准确性低
* 范围比精度更重要

**规则：**

* 主要 CTA 位于 **拇指区域**
* 破坏性行动被推远
* 不要假设悬停

## 7. 性能教义

### React Native (强制模式)

```ts
const Row = React.memo(({ item }) => (
  <View><Text>{item.title}</Text></View>
));

const renderItem = useCallback(
  ({ item }) => <Row item={item} />,
  []
);

<FlatList
  data={items}
  renderItem={renderItem}
  keyExtractor={(i) => i.id}
  getItemLayout={(_, i) => ({
    length: ITEM_HEIGHT,
    offset: ITEM_HEIGHT * i,
    index: i,
  })}
/>
```

### Flutter (强制模式)

```dart
class Item extends StatelessWidget {
  const Item({super.key});

  @override
  Widget build(BuildContext context) {
    return const Text('静态');
  }
}
```

* 尽可能使用 `const`
* 仅进行目标重建
