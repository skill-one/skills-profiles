# last30days：过去30天内的任何主题研究

在Reddit、X和网络上研究任何主题。揭示人们当前正在讨论、推荐和辩论的内容。

用例：

- **提示**："Nano Banana Pro中的照片级真实人物"，"Midjourney提示"，"ChatGPT图像生成"→学习技巧，获取可复制粘贴的提示
- **推荐**："最佳Claude Code技能"，"顶级AI工具"→获取人们提到的具体事物列表
- **新闻**："OpenAI的最新动态"，"最新的AI公告"→当前事件和更新
- **一般**：任何你好奇的主题→了解社区在说什么

## 关键：解析用户意图

在执行任何操作之前，解析用户输入以获取：

1. **主题**：他们想要了解的内容（例如，"网络应用原型"，"Claude Code技能"，"图像生成"）
2. **目标工具**（如果指定）：他们将在哪里使用提示（例如，"Nano Banana Pro"，"ChatGPT"，"Midjourney"）
3. **查询类型**：他们想要进行的研究类型：
   - **提示** - "X提示"，"为X提示"，"X最佳实践"→用户想要学习技巧并获取可复制粘贴的提示
   - **推荐** - "最佳X"，"顶级X"，"X应该使用什么"，"推荐X"→用户想要具体事物的列表
   - **新闻** - "X的最新动态"，"X新闻"，"X的最新消息"→用户想要当前事件/更新
   - **一般** - 任何其他内容→用户想要对该主题的广泛了解

常见模式：

- `[主题]用于[工具]` → "Nano Banana Pro的网络原型"→工具已指定
- `[主题]提示用于[工具]` → "Midjourney的UI设计提示"→工具已指定
- 仅`[主题]` → "iOS设计原型"→工具未指定，可以
- "最佳[主题]"或"顶级[主题]" → 查询类型 = 推荐
- "最佳[主题]"是什么 → 查询类型 = 推荐

**重要提示**：在研究之前不要询问目标工具。

- 如果查询中指定了工具，请使用它
- 如果工具未指定，先运行研究，然后在显示结果后询问

**存储这些变量**：

- `主题 = [提取的主题]`
- `目标工具 = [提取的工具，如果未指定则为"未知"]`
- `查询类型 = [推荐 | 新闻 | 如何操作 | 一般]`

## 设置检查

该技能根据可用的API密钥以三种模式工作：

1. **完整模式**（两个密钥）：Reddit + X + WebSearch - 使用参与指标的最佳结果
2. **部分模式**（一个密钥）：Reddit仅限或X仅限 + WebSearch
3. **仅网络模式**（无密钥）：仅WebSearch - 仍然有用，但没有参与指标

**API密钥是可选的**。该技能在没有它们的情况下使用WebSearch回退也能工作。

### 首次设置（可选但推荐）

如果用户想要添加API密钥以获得更好的结果：

```bash
mkdir -p ~/.config/last30days
cat > ~/.config/last30days/.env << 'ENVEOF'
# last30days API配置
# 两个密钥都是可选的 - 技能使用WebSearch回退

# 用于Reddit研究（使用OpenAI的web_search工具）
OPENAI_API_KEY=

# 用于X/Twitter研究（使用xAI的x_search工具）
XAI_API_KEY=
ENVEOF

chmod 600 ~/.config/last30days/.env
echo "配置创建在 ~/.config/last30days/.env"
echo "编辑以添加您的API密钥以增强研究。"
```

**如果密钥未配置，不要停止**。继续使用仅网络模式。

## 研究执行

**重要提示**：脚本会自动处理API密钥检测。运行它并检查输出以确定模式。

**步骤1：运行研究脚本**

```bash
TOPIC_FILE="$(mktemp)"
trap 'rm -f "$TOPIC_FILE"' EXIT
cat <<'LAST30DAYS_TOPIC' > "$TOPIC_FILE"
$ARGUMENTS
LAST30DAYS_TOPIC
python3 ~/.claude/skills/last30days/scripts/last30days.py "$(cat "$TOPIC_FILE")" --emit=compact 2>&1
```

脚本将自动执行：

- 检测可用的API密钥
- 如果密钥缺失，显示促销横幅（这是有意的市场营销）
- 如果密钥存在，运行Reddit/X搜索
- 指示是否需要WebSearch

**步骤2：检查输出模式**

脚本输出将指示模式：

- **"模式：both"**或**"模式：reddit-only"**或**"模式：x-only"**：脚本找到结果，WebSearch是补充
- **"模式：web-only"**：没有API密钥，Claude必须通过WebSearch进行所有研究

**步骤3：进行WebSearch**

对于**所有模式**，进行WebSearch以补充（或在仅网络模式下提供所有数据）。

根据查询类型选择搜索查询：

**如果推荐**（"最佳X"，"顶级X"，"我应该使用什么X"）：

- 搜索：`最佳{主题}推荐`
- 搜索：`{主题}列表示例`
- 搜索：`最受欢迎的{主题}`
- 目标：找到具体事物的名称，而不是通用建议

**如果新闻**（"X的最新动态"，"X新闻"）：

- 搜索：`{主题}新闻2026`
- 搜索：`{主题}公告更新`
- 目标：找到当前事件和最新发展

**如果提示**（"X提示"，"为X提示"）：

- 搜索：`{主题}提示示例2026`
- 搜索：`{主题}技巧提示`
- 目标：找到提示技巧和示例以创建可复制粘贴的提示

**如果一般**（默认）：

- 搜索：`{主题}2026`
- 搜索：`{主题}讨论`
- 目标：找到人们实际在说什么

对于所有查询类型：

- **使用用户的精确术语** - 不要根据你的知识替换或添加技术名称
  - 如果用户说"ChatGPT图像提示"，搜索"ChatGPT图像提示"
  - 不要添加"DALL-E"、"GPT-4o"或其他你认为相关的术语
  - 你的知识可能已过时 - 相信用户的术语
- 排除reddit.com、x.com、twitter.com（由脚本覆盖）
- 包括：博客、教程、文档、新闻、GitHub存储库
- **不要输出"来源："列表** - 这是噪音，我们将在最后显示统计数据

**步骤3：等待后台脚本完成**
使用TaskOutput获取脚本结果，然后再继续到综合。

**深度选项**（从用户的命令中传递）：

- `--quick` → 更快，较少来源（每个8-12个）
- （默认）→ 平衡（每个20-30个）
- `--deep` → 全面（每个50-70个Reddit，40-60个X）

## 判断代理：综合所有来源

**所有搜索完成后，内部综合（不要显示统计数据）**：

判断代理必须：

1. 对Reddit/X来源**权重更高**（它们有参与指标：点赞、评论）
2. 对WebSearch来源**权重较低**（没有参与数据）
3. 识别所有三个来源中出现的模式（最强的信号）
4. 注意来源之间的任何矛盾
5. 提取前3-5个可操作的见解

**不要在这里显示统计数据** - 它们会在邀请之前出现。

---

## 首先：内化研究

**关键**：基于实际研究内容，而不是你的先验知识来内化你的综合。

仔细阅读研究输出。注意：

- **提到的确切产品/工具名称**（例如，如果研究提到"ClawdBot"或"@clawdbot"，那是一个不同于"Claude Code"的不同产品 - 不要混淆它们）
- **来自来源的具体引言和见解** - 使用这些，而不是通用知识
- **来源实际说什么**，而不是你假设的主题是什么

**要避免的反模式**：如果用户询问"clawdbot技能"，而研究返回ClawdBot内容（自托管AI代理），不要将此综合为"Claude Code技能"，只是因为两者都涉及"技能"。阅读研究实际说了什么。

### 如果查询类型 = 推荐

**关键**：提取具体名称，而不是通用模式。

当用户询问"最佳X"或"顶级X"时，他们想要一个具体事物的列表：

- 扫描研究以查找具体产品名称、工具名称、项目名称、技能名称等
- 计算每个提及的次数
- 注意每个来源推荐的内容（Reddit线程、X帖子、博客）
- 按流行度/提及次数列出它们

**"最佳Claude Code技能"的坏综合**：

> "技能很强大。保持它们在500行以下。使用渐进式披露。"

**"最佳Claude Code技能"的好综合**：

> "最提到的技能：/commit（5次提及），remotion skill（4次），git-worktree（3次），/pr（3次）。Remotion公告在X上获得了16K个赞。"

### 对于所有查询类型

从实际研究输出中识别：

- **提示格式** - 研究是否推荐JSON、结构化参数、自然语言、关键词？这是关键。
- 出现多次的顶级3-5个模式/技巧
- 来源提到的具体关键词、结构或方法
- 来源提到的常见陷阱

**如果研究说"使用JSON提示"或"结构化提示"，你必须以那种格式交付提示。**

## 当用户分享他们的愿景时：写一个完美的提示

根据他们想要创建的内容，使用你的研究专业知识写一个**单一的、高度定制的提示**。

### 关键：匹配研究推荐的格式

**如果研究说使用特定的提示格式**，你必须使用那个格式：

- 研究说"JSON提示"→将提示作为JSON编写
- 研究说"结构化参数"→使用键：值格式
- 研究说"自然语言"→使用对话式散文
- 研究说"关键词列表"→使用逗号分隔的关键词

**反模式**：研究说"使用JSON提示与设备规格"，但你写的是纯散文。这违背了整个研究的目的。

### 输出格式：

```
这是你的{TARGET_TOOL}提示：

---

[实际提示，以研究推荐的格式 - 如果研究说JSON，这是JSON。如果研究说自然语言，这是散文。匹配什么有效。]

---

这使用了[研究见解的简短1行解释]。
```

### 质量检查清单：

- [ ] **格式匹配研究** - 如果研究说JSON/结构化等，提示是那种格式
- [ ] 直接解决用户说的他们想要创建的内容
- [ ] 使用研究发现的特定模式/关键词
- [ ] 可以直接粘贴，无需零编辑（或标记[占位符]以供明确编辑）
- [ ] 针对TARGET_TOOL的适当长度和风格
