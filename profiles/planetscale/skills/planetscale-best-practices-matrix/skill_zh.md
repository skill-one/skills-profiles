# 最佳实践矩阵

## 目的

将数据库发现映射到推荐的 PlanetScale 功能。使用此矩阵确保评估不会遗漏主要的安全和操作表面。

## 跨引擎推荐

### 查询洞察

为每个生产数据库推荐：

- 审查慢速、昂贵、高频和报错的查询模式。
- 对于 Postgres，在诊断 CPU 压力时按 CPU 排序洞察（在洞察 API 上使用 `sort=cpuTime`）
- 对于分片的 Vitess，审查每个查询模式的 vindex 使用情况以及索引或路由更改后的使用趋势。
- 将回归与部署相关联。
- 使用标签/注释将查询映射回代码。
- 使用查询洞察中的标签过滤/导航：两个引擎上的标签 API (`insights/tags`, `insights/tags/summaries`），以及 Vitess 仪表板中的 `tag:key:value` 过滤和每次执行标签下钻。
- 使用异常作为警报和自动化输入。

### Webhooks

为操作事件推荐：

- 异常。
- 存储压力。
- 分支就绪/睡眠状态。
- 主节点提升。
- 维护。
- 可用的模式建议。
- Vitess 的部署请求生命周期。

### MCP 和代理

推荐：

- 使用仅洞察的 MCP 进行大多数自动分析。
- 仅在狭窄范围内且默认为只读时使用完整 MCP。
- 将数据库目标和安全规则放在 `AGENTS.md` 中。
- 代理生成 PR/问题/变更计划；人类批准数据库变更。

### SQLCommenter / 查询标签

推荐：

- 添加框架原生的兼容 SQLCommenter 的instrumentation。
- 使用低基数标签。
- 包括应用、服务、路由/作业、功能、来源和发布 SHA。
- 避免PII和无界 ID。

### 模式建议工作流

推荐：

- 筛选开放建议。
- 与代码和洞察相关联。
- 转换为迁移或分支变更。
- 生产前测试。
- 仅通过批准的工作流应用。

## Vitess 特定推荐

### 安全迁移

为生产分支和接受部署请求的预发布分支推荐。

### 部署请求

为受保护的分支中的模式变更推荐。

### 强制切换规范

推荐记录谁可以使用“强制立即切换”来处理因长时间运行的事务而延迟的部署请求。它停止运行的事务以完成模式切换，因此频繁使用应在使用激进切换作为数据库默认设置之前触发工作负载审查。

### 管理员批准

为多管理员组织的生产部署请求推荐。

在单管理员组织中，批准本身并不是对代理的保障：该管理员可以打开并批准相同的部署请求。优先考虑单独的代理身份，或无法批准部署请求的服务令牌。

### 受控部署

当切换时间和人工控制很重要时推荐。

### 模式回滚运行手册

推荐记录回滚责任和应用回滚关系。

### 分支策略

推荐在生产、预发布和短命开发分支上使用安全的迁移，并将受保护的靶标设为安全迁移目标。

### 分片/键空间审查

当查询模式或增长表明存在分片感知问题时要推荐。不要自动重分片。

## Postgres 特定推荐

### 用户定义角色

为应用服务器推荐使用默认角色，而不是默认角色。如果角色由 Terraform 管理，并且密码不应保留在 Terraform 状态中，则优先考虑 `planetscale_postgres_redacted_branch_role` 加上单独的密码重置和密钥管理器存储路径。

### pg_strict

在评估后为应用角色推荐，特别是为了阻止意外的全表更新/删除错误。

### 流量控制

为代理、导出、报告、工作器、集成、BI 和已知昂贵指纹的资源隔离推荐。

### 备份和 PITR

推荐验证保留和恢复演练覆盖范围。如果 Terraform 是客户的真实来源，推荐在那里管理备份策略，以便备份态势变更作为基础设施代码进行审查。

### PgBouncer 和连接池

在连接周转或无服务器/边缘行为产生压力时推荐，但受事务池限制约束。

### 私有连接和 IP 限制

为需要私有网络态势或减少公共暴露的客户推荐。将变更视为生产风险。

### 扩展

仅在用例明确且接受重启/激活影响时推荐。当自动计划记录用于慢速查询会显著改善诊断，且产生的日志量可接受时，包括 `auto_explain`。如果 Terraform 管理Postgres 分支参数或支持的扩展，请保持该真实来源与批准的仪表板/API 变更保持一致。

### 活连接

在活动连接压力事件期间，推荐检查 `pscale branch connections top` 以识别会话、阻塞者和空闲事务根，而无需依赖正常数据库连接容量。

## 输出

对于每个矩阵项，标记：

- 适用：是/否/未知。
- 当前状态。
- 差距。
- 价值：此功能解决的具体测量发现（查询指纹、异常计数、事件、指标）。说明机制和测量。差距是具有量化影响的能力差距，而不是安全避免的风险。
- 推荐ID。
- 批准要求。

结束：

“未应用任何变更。”
