# Vitess 安全审查

## 目的

为 PlanetScale Vitess 数据库推荐最佳实践。重点关注生产安全、部署能力、可观测性和代理安全自动化。不要应用任何变更。

## 需要评估的主要安全特性

### 安全迁移

检查生产分支和预发布分支是否启用了安全迁移。

在以下情况下推荐启用安全迁移：

- 分支接收生产流量。
- 团队会在部署请求之外运行 DDL。
- 没有受保护的分支工作流。
- 应用程序预期会频繁地演变模式。

解释权衡：安全迁移会拒绝在受保护分支上直接执行 DDL，并强制通过部署请求进行模式变更。这是一个特性，但它可能会破坏依赖直接生产 DDL 的团队。将启用行为视为会改变行为的变更，需要审批。

### 部署请求

检查：

- 是否使用部署请求进行模式变更。
- 是否需要管理员审批。
- 是否对部署请求进行数据丢失、冲突、语法错误、外键问题、字符集问题、分片影响等方面的审查。
- 团队是否使用受控部署进行切换控制。
- 是否使用“立即部署”，以及团队是否理解它会移除受控部署/回滚的形状。
- 长时间运行的事务是否定期导致切换延迟。
- 是否通过 Webhook 订阅部署请求事件。

推荐：

- 要求对生产模式变更使用部署请求。
- 当有多名管理员时，为生产部署请求启用管理员审批。
- 在单管理员组织中，管理员审批不会阻止作为该管理员代理的代理：
  打开部署请求的管理员也可以批准它。如果目标是防止代理自我批准，则给代理一个单独的用户，或一个没有部署请求审批权限的服务令牌。
- 除非迁移已知是即时安全的且回滚方案可接受，否则优先选择正常安全部署而不是即时部署。
- 当切换时间重要时使用受控部署。
- 将“立即切换”视为操作员控制的延迟切换操作：它会激进地停止运行的事务以完成模式切换。推荐在使用前审查阻塞工作负载和事件上下文，并且仅在理解并接受频繁切换阻塞时推荐数据库级别的激进切换默认设置。

### 模式回滚

检查团队是否了解回滚窗口，以及他们的事件运行手册是否包含它。

推荐记录：

- 如何识别不良的模式迁移。
- 如何在支持窗口内回滚。
- 谁有权回滚。
- 哪些应用程序部署应与模式回滚一起回滚。

### 分支策略

推荐分支拓扑：

- 启用安全迁移的 `main` 或等效生产分支。
- 从生产分支派生的、启用安全迁移的 `staging` 分支。
- 基于预发布分支的短期开发分支。
- 在适当的时候从开发分支部署到预发布分支，然后从预发布分支部署到生产分支。

未经批准不得创建分支。

### 查询洞察

审查洞察：

- 慢查询。
- 读取过多行的查询。
- 出错的查询。
- 索引使用不良的查询。
- 对于分片数据库，查询模式是否使用相关的 vindex，以及索引或路由变更后 vindex 使用情况如何变化。
- 异常的查询量。
- 缺失的 SQL 注释标签。
- 当存在内置元数据或 SQLCommenter 标签时，标签分解：
  仪表板中的 `tag:key:value` 过滤，以及 `insights/tags` 和 `insights/tags/summaries` API 端点用于程序化分解。
- 部署关联数据。

推荐启用或改进应用程序查询标签，以便洞察可以将查询归因于应用程序、路由、控制器、操作、作业、部署 SHA 和功能。

### 异常

审查活动和最近的异常。

推荐：

- 将 `branch.anomaly` Webhook 订阅到团队的告警或自动化系统。
- 将异常有效载荷路由到打开问题或代理任务的排障工作流。
- 将异常与部署请求、应用程序部署和查询标签相关联。
- 不要自动从异常事件应用模式或代码变更；仅生成提案或 PR。

### 模式建议

审查开放的模式建议。

对于每个建议，捕获：

- 类型：添加索引、删除冗余索引、主键耗尽、未使用表、遗留字符集/排序或其他。
- 影响的表和键空间。
- 支持的查询遥测。
- DDL。
- 预期收益。
- 风险。
- 测试计划。

推荐实施路径：

- 将建议转换为应用程序迁移或 PlanetScale 分支模式变更。
- 打开部署请求。
- 审查生成的 DDL 和分片影响。
- 在分支上进行基准测试或验证。
- 使用安全迁移部署。
- 部署后监控洞察和异常状态。

不要直接应用建议。

### 备份和恢复

检查备份态势和恢复运行手册。

推荐：

- 验证自动备份是否存在。
- 定期进行非生产恢复演练。
- 记录恢复目标、RPO/RTO 预期值和应用程序切换计划。
- 对于分片数据库，记录分片感知恢复预期。

### 分片和键空间安全

如果数据库是分片的，审查：

- 键空间和分片。
- Vschema。
- 跨分片查询模式。
- 模式部署请求是否显示每个分片的影响。
- 查询是否使用分片友好的访问路径。

仅作为提案推荐代理安全的分片审查。永远不要自动重新分片、更改 vschema 或更改路由。

## Vitess 的 Webhook 建议

评估并推荐以下 Webhook：

- `branch.anomaly`
- `branch.primary_promoted`
- `branch.ready`
- `branch.sleeping`
- `cluster.storage`
- `keyspace.storage`
- `deploy_request.opened`
- `deploy_request.queued`
- `deploy_request.in_progress`
- `deploy_request.pending_cutover`
- `deploy_request.schema_applied`
- `deploy_request.errored`
- `deploy_request.reverted`
- `deploy_request.closed`
- 如果客户的数据库 Webhook API 中提供 `branch.schema_recommendation`，则提供它

推荐目的地：

- 告警用于异常、主提升、存储和部署错误。
- Slack 或内部通知用于部署请求生命周期。
- 代理摄入队列用于模式建议和异常，默认输出为仅 PR。

## 输出

返回：

- 当前 Vitess 安全态势。
- 缺失的安全特性。
- 推荐的工作流。
- 推荐的 Webhook 订阅。
- 模式建议排障表。
- 部署安全差距。
- 需要审批的提议变更。

以：

“未对 Vitess 应用任何变更。”
结束。
