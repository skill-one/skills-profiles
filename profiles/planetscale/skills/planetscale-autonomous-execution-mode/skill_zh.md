# 自主执行模式

## 目的

让明确接受风险的操作员将整个任务交给代理：计划、执行、验证和报告——全程实时状态——而不是逐个批准每个变更。此模式消除了每步审批的摩擦。它不会移除任何验证、排序、回滚或停止的纪律。自主性改变了谁点击“开始”，而不是工作执行的仔细程度。

## 激活协议

自主模式仅在操作员的消息包含以下全部三项时激活：

1. **明确的风险承认。** 明确的陈述，例如“我理解风险”、“我接受风险”、“我知道这可能影响生产”。较缓和的措辞——“继续”、“听起来不错”、“执行”——**不**激活自主模式；它们在变更门禁技能下保持逐变更审批。
2. **命名的范围。** 以下之一：
   - 命名的变更ID（“VIT-1, VIT-3, WEB-1”），或
   - 命名的数据库或组织，具有变更类上限（“店面演示报告中所有内容”），或
   - “报告中所有建议” —— 仅在此模式下有效，因为报告已经命名了每个变更。
3. **生产声明。** 是否包含生产影响的（类D）变更。如果操作员没有说明，询问一次；如果仍然未说明，以`auto-safe`（排除类D）运行。

在执行任何操作之前，将承认内容逐字记录在运行日志中。

### 自主级别

| 级别 | 解锁 | 需要 |
|---|---|---|
| `auto-safe` | 范围内的类B + 类C | 风险承认 + 范围 |
| `auto-production` | 添加范围内的类D | 风险承认 + 范围 + 明确的生产声明 |
| — | 类E | 永不可用。没有措辞可以解锁它。 |

类E操作（删除生产数据库/表、同时禁用所有安全机制、暴露机密、移除仅限私有的网络配置）在任何模式下都会被拒绝。如果请求的变更集中包含类E项，执行其余部分并报告排除——不要无声地跳过，也不要要求操作员“更确认”。

### 承认有效期

- 仅适用于**本次运行**。新的会话、新的报告或实质上改变的数据库状态需要重新承认。
- 仅适用于**命名的范围**。运行中途发现新问题不会授权修复——将其添加到报告中并继续。
- 操作员可以随时说**“停止”**；在当前原子步骤后停止，并生成部分运行报告。

### 持久授权（计划自动化）

交互式承认是单次运行的。计划代理（cron、Cursor自动化、webhook触发的运行）在**持久授权**下操作：一个书面工件，提交到代理读取指令的位置（`AGENTS.md`部分或专用授权文件），包含：

- 自动化名称和所有者。
- 范围：组织、数据库、分支。
- 类上限：B、C或D。类E不可授权。
- 操作白名单，声明为有界操作，而不是意图。
  有效：“从开放模式建议中开放添加DDL的部署请求；带回滚窗口部署；仅添加（ADD INDEX, ADD COLUMN NULL）”。无效：“保持模式优化”。
- 适用时数字界限：每次运行最大变更数、最大分支年龄用于删除、允许的预算模式（仅警告与强制）。
- 到期日期。过期授权=仅报告模式。建议的审查间隔：90天。

持久授权的运行规则：

- 代理在每次运行开始时重新读取授权；执行受工件约束，而不是受记忆约束。
- 允许列表外的一切在该运行中仅报告。
- 所有停止条件保持不变。已停止的计划运行不会自我恢复；它会报告并等待所有者。
- 状态流到配置的交付渠道（webhook、Slack、问题跟踪器），因为没有操作员在观看交互式会话。没有交付渠道的计划运行不得执行变更——没有读者的状态不是状态。
- 运行日志按运行持久化，并在交付渠道消息中引用。

## 感性执行：计划

在第一个变更之前，生成并显示**执行计划**：

1. **按依赖关系排序，然后按风险排序。** 先执行先决条件（例如，在启用安全迁移之前停止应用的启动时DDL，在删除它所替换的索引之前添加索引）。在独立变更中，最低风险优先，以便早期失败成本最低。
2. **每个变更预飞行。** 在变更之前立即重新读取实时状态（分支标志、建议状态、webhook配置）。如果状态不再与报告证据匹配，该变更**已过时**：跳过它，标记为`BLOCKED — 状态漂移`，并继续执行独立变更。
3. **安全先决条件是步骤，而不是假设。** 在任何类D DDL之前：确认备份在保留窗口内完成，确认安全迁移或部署请求是支持它的引擎，并优先使用可回滚机制（带回滚窗口的部署请求，Traffic Control的警告模式之前强制模式）。
4. **一次一个原子变更。** 永远不要将无关的变更批量到一个命令中。永不要并行化类D步骤。
5. **每步后验证。** 读取状态并确认预期效果后再继续。当命令退出0时，变更并未“完成”；当回读匹配预期状态时才完成。

## 状态协议

操作员已交出控制权；可见性是他们得到的回报。在每一步都发出状态：

- **计划公告** — 编号的步骤，每个步骤都有目标、确切命令/接口、预期效果、回滚机制和类。这是执行开始前显示的最后内容。
- **每步前**：`[步骤 3/7] STARTING VIT-3a — 部署请求：将 idx_orders_on_user_id 添加到 storefront-demo/main（类D，可回滚窗口）`
- **每步后**：`[步骤 3/7] DONE — 部署请求 #4 已部署，索引在模式回读中可见（耗时 2m 10s）`
- **长时间运行操作**（部署请求、迁移、恢复）：以合理的频率轮询并报告进度，而不仅仅是完成时。包括队列位置/状态转换。
- **跳过和阻止**：立即报告原因（`BLOCKED — 状态漂移`、`EXCLUDED — 类E`、`SKIPPED — 先决条件失败`），永不要无声地跳过。
- **运行摘要** — 变更门禁技能的执行后报告：变更内容、时间、成功证据、警告、回滚状态、后续监控。加上承认引用和使用的自主级别。

状态行必须足够具体，以便仅阅读状态流的操作员可以重建运行：每次命名变更ID、目标和机制。

状态是纯文本，在代理的正常输出流中每次步骤发生时发出。它必须不依赖于任何主机特定的渲染表面（画布、HTML、TUI小部件）——那些可以补充流，永不要取代它。纯文本流和运行日志是每个代理中运行的记录。

## 停止条件

生产线规则。当任何一项触发时，完成或安全中止当前原子步骤，执行预置的回滚（如果步骤部分应用），并报告：

1. **任何类D步骤失败或验证错误** → 停止整个运行。
2. **类B/C步骤失败** → 停止该变更的依赖链；独立变更可以继续；在状态中说明。
3. **运行中途目标数据库出现异常** → 暂停运行，报告异常，等待操作员。
4. **生产目标上的状态漂移**（其他人中途更改了它）→ 停止运行。
5. **范围压力**——需要任何超出承认范围的内容 → 不要执行；报告它。
6. **破坏性步骤出错** → 永不要自动重试。重试仅允许用于幂等的读取和非破坏性调用中的瞬时网络故障。

停止后：报告每个步骤的状态（完成 / 回滚 / 阻止 / 未开始）、当前数据库状态，以及需要重新承认才能继续的内容。永不要在原始承认上恢复已停止的运行。

## 回滚纪律

- 在每个步骤之前，预置具体的回滚：确切的命令或机制（部署请求回滚、预算回到警告、webhook禁用、恢复点）。
- 当步骤部分应用且回滚本身是非破坏性的并在计划中预声明时，自动回滚，无需询问。
- 永不要对破坏性操作自动回滚（例如，永不要自动恢复数据）；报告并等待。

## 运行日志

为整个会话维护一个仅追加的运行日志：时间戳、步骤ID、命令、结果、回读证据。将其（或其路径）包含在运行摘要中。日志是审计轨迹，使“代理自主执行”可审查。

## 与其他技能的交互

- `../planetscale-change-gates-and-approval-contract/SKILL.md` — 类定义和执行前/后的检查表仍逐字适用；有效的风险承认在范围内替代逐变更审批。类E规则不变。
- `../planetscale-safe-orchestrator/SKILL.md` — 当伴随有效承认的评估请求（“运行审计并修复你发现的问题，我接受风险”）时，先运行完整评估，展示报告和执行计划，然后直接进入此技能的执行，无需停止审批。
- `../planetscale-schema-recommendations-agent-loop/SKILL.md` — 在自主模式下，循环可以带建议通过分支、部署请求和部署，使用在切换时间点重要的受控部署。

## 必须的拒绝行为

如果操作员要求完全自主但不包含承认要素，不要协商模糊。回复：

“自主模式需要一个明确的风险承认、命名的范围以及是否包含生产变更。例如：‘我接受风险——将所有报告建议应用于店面演示，生产包含’。”

然后等待。
