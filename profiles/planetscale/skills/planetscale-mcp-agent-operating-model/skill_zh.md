# MCP代理操作模型

## 目的

定义代理应如何安全地使用PlanetScale MCP。代理应使用生产遥测数据生成有用的工作，同时避免自主进行生产变更。

## 默认MCP选择

当任务只需要Insights和Schema推荐时，使用PlanetScale MCP Insights-only服务器。

只有当任务明确需要超出Insights的数据库/Schema访问权限时，才使用完整的PlanetScale MCP服务器。优先选择只读权限。

完整的MCP服务器具有查询执行工具。除非操作员明确批准特定的非生产操作或经过仔细审查的生产操作，否则将写入查询工具视为禁用状态。

## AGENTS.md指南

两个不同名称为`AGENTS.md`的文档服务于不同的目的：

1. **CLI代理指南** — 随`pscale`一起提供（在[planetscale/cli](https://github.com/planetscale/cli)存储库中的`AGENTS.md`，或使用`pscale agent-guide --format json`）。涵盖认证、`--format json`、标志位置和`pscale sql`。加载技能`planetscale-pscale-cli-automation`以在技能包内使用相同的约定。

2. **项目代理指南** — 您应用程序存储库中的`AGENTS.md`（或等效文件）。涵盖此应用程序的数据库目标和支持政策。

在存储库内工作时，建议在`AGENTS.md`或等效项目说明中添加**项目**数据库目标部分：

- PlanetScale组织。
- 数据库。
- 分支。
- 引擎：Vitess或Postgres。
- 生产分支名称。
- 代理是否可以使用MCP Insights-only或完整MCP。
- 是否禁止写入查询。
- Schema、Traffic Control、webhooks、角色和网络变更所需的审批协议。

未经批准，不要编辑`AGENTS.md`。

## 安全自主任务

默认允许：

- 读取Insights。
- 读取Schema推荐。
- 读取Schema元数据。
- 读取现有webhooks和Traffic Control配置。
- 读取分支元数据。
- 检查存储库代码。
- 将查询模式与代码关联。
- 提交问题。
- 打开拉取请求。
- 创建开发分支。
- 将DDL和迁移应用到非生产开发分支。
- 向受评审工作流保护的分支打开部署请求。
- 起草Traffic Control预算提案。
- 起草webhook接收器要求。

在存在PR + 部署请求工作流的情况下，Schema推荐的默认交付成果是可审查的完整单元：应用了DDL的开发分支、包含证据（指纹、指标、预期效果）的PR以及打开的部署请求。人的操作是合并/部署决策，而不是引导提案的产生。

默认不允许（审查门禁操作和非审查性变更）：

- 对生产执行写入SQL。
- 直接对生产分支执行DDL。
- 部署部署请求/将Schema应用到生产。
- 合并拉取请求。
- 创建webhooks。
- 创建或执行Traffic Control预算。
- 旋转凭证。
- 更改角色。
- 更改IP限制或私有连接。
- 恢复或提升分支。

## 代理循环

### 每日推荐循环

1. 读取开放的Schema推荐。
2. 读取顶级Insights回归。
3. 与存储库代码关联。
4. 生成排名问题或PR。
5. 人工审查。
6. 人工批准任何影响数据库的操作。

### 异常循环

1. 接收或检查异常。
2. 汇总受影响的查询模式和标签。
3. 确定源路由/作业/部署。
4. 生成事件笔记和提议的补救措施。
5. 如果代码修复显而易见，则打开PR。
6. 如果需要数据库变更，则仅创建提议的变更集。

### Traffic Control循环

1. 从Insights/标签中识别不安全的流量切片。
2. 起草`warn`预算提案。
3. 人工批准创建。
4. 观察警告。
5. 人工仅在验证后批准强制模式。

## 定时循环（cron / 自动化）

上述循环是交互式运行的。它们也可以在没有人工参与的调度下运行，分为两个级别。第2级需要`../planetscale-autonomous-execution-mode/SKILL.md`的持续授权；第1级不需要。

每个定时循环，两个级别：在运行开始时重新读取授权，将状态流式传输到配置的交付通道，持久化运行日志，并避免提交重复项（不要重新提交已为相同指纹/推荐ID打开的问题）。

### 第1级 — 通过审查工作流提议（无需授权）

- **推荐到PR循环**（每日）：通过MCP列出开放的Schema推荐；对于每个符合工作流的新推荐（添加性或破坏性 — PR审查是门禁），创建开发分支，应用DDL，打开PR并包含指纹、指标和预期效果，并打开部署请求。当人类可以通过一次合并/部署操作来部署时，可审查单元是完整的。输出：每个推荐一个分支+PR+部署请求。

- **回归监控**（每小时或每次部署）：将顶级模式与存储的基线（p50/p99、读取行数、执行次数）进行比较；在出现重大回归时，从查询标签中识别部署SHA，并提交一个将模式链接到提交范围的报告。输出：报告。

- **标签覆盖审计**（每周）：测量带有标签的查询时间的百分比；列出未标记的高成本模式及其可能的代码路径；打开或更新一个跟踪问题。输出：问题。

- **异常分诊**（webhook触发，非轮询）：在`branch.anomaly`时，收集受影响的模式，分类可能的原因，将分诊笔记发布到事件通道。输出：分诊笔记。

- **姿势漂移检查**（每日）：将当前安全迁移标志、webhook配置、角色列表和备份计划与上次评估报告进行比较；报告任何漂移。输出：报告。

### 第2级 — 执行审查门禁操作（需要持续授权）

- **推荐部署器**（每日，PR循环之后）：部署符合白名单的开放部署请求 — 通常为“添加性DDL、PR已批准或来自开放推荐、带回滚窗口、每次运行最多N个” — 然后通过Schema回读和目标指纹的Insights后续验证来确认。破坏性DDL部署仅在授权声明运行时可验证的界限时自动进行（例如，“仅在30天内读取为零的索引，通过运行时的Insights确认”）。如果组织需要在部署前获得PR批准，则已批准的PR满足审查门禁，授权仅涵盖机械部署。

- **分支卫生**（每周）：删除授权年龄界限内没有开放部署请求的旧开发分支；永远不要触摸生产或受保护的分支。

- **Warn预算园丁**（每周）：为新识别的高成本切片创建`warn`模式Traffic Control预算，符合白名单；报告现有预算的warn计数。除非授权指定了特定预算，否则永远不会自动进入强制模式。

- **凭证过期执行**（每日）：删除或标记超过授权最大年龄的密码，仅当授权列出了受影响的角色并且存在旋转运行簿时。

### 循环反模式

- 使用cron轮询MCP以获取事件，而webhooks已经交付 — 使用webhook作为触发器；使用cron进行基线、扫描和审计。

- 一个第2级循环，其白名单是意图（“保持健康”），而不是有界操作。

- 没有状态交付通道而进行变更的循环。

- 无界发散：一次运行应用所有开放的推荐，而没有每运行限制。

## 查询执行保护措施

对于读取查询：

- 当可用时，优先使用副本。
- `planetscale_execute_read_query`默认将读取路由到副本，当分支配置了副本（`use_replica: true`）时。仅在任务需要主读语义时设置`use_replica: false`，例如检查立即后写状态或主行为。
- 为代理工作添加源标签/注释。
- 避免无界扫描。
- 除非明确批准，否则避免在生产上使用`EXPLAIN ANALYZE`。
- 限制结果大小。
- 除非需要且批准，否则避免查询敏感列。
- 对于具有行级安全性的Postgres表，请记住MCP读取角色使用`pg_read_all_data`并不绕过RLS。如果读取查询返回零行或零计数，并且MCP响应警告RLS可能过滤结果，则将结果视为策略过滤/未知，直到通过批准路径确认；不要得出结论表为空。
- 当在Postgres上调试高CPU时，使用Insights数据按CPU使用排序（通过MCP可用时，或`sort=cpuTime`在Insights API上）。CPU时间指标是Postgres专用的；不要在Vitess上请求相同的CPU排序视图。

对于写入查询：

- 默认禁止。
- 如果批准，优先使用非生产分支。
- 需要精确SQL审查。
- 需要回滚计划。
- 需要分支和数据库名称确认。

## 输出

返回：

- 推荐的MCP服务器选择。
- 所需权限。
- 需要添加到AGENTS.md的说明。
- 允许的自主工作。
- 禁止的工作。
- 提议的代理循环。
- 审批门禁。

以：

“未使用任何MCP写入工具或数据库变更。”
结束。
