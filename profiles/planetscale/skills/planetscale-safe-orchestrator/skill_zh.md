# PlanetScale 安全编排器（主技能）

## 目的

端到端运行 PlanetScale 安全最佳实践技能包。按顺序加载并执行每个子技能，累积证据，并生成一份统一的建议报告。第一遍仅进行评估。

## 非协商安全协议

默认为只读模式。

您可以检查配置、分支、查询遥测数据、建议、Webhook、角色、备份、流量预算和存储库代码。未经明确批准的变更集，您不得修改 PlanetScale、数据库、存储库、网络配置、凭证、模式、生产流量控制或自动化端点。

C/D/E 类变更需要根据 `../planetscale-change-gates-and-approval-contract/SKILL.md` 进行批准。如有疑问，请停止并添加到建议变更集中，而不是执行。

存在一个例外：如果操作员明确承认风险，并根据 `../planetscale-autonomous-execution-mode/SKILL.md` 指定范围，则在该技能的状态和停止规则下自动执行，而不是停止等待每个变更的批准。下方的评估阶段无论如何都是相同的。

子技能是与此技能并置的兄弟文件夹，通过相对路径引用；如果引用的路径不存在，则定位到具有匹配的前置 `name` 的兄弟技能并使用它。

将 CLI 和 API 使用基于官方文档，而不是猜测：文档索引位于 https://planetscale.com/docs/llms.txt（将 `.md` 添加到任何文档 URL 以获取 Markdown 版本），API 参考文档位于 https://planetscale.com/docs/openapi.yaml。当命令或端点失败时，在记录证据差距之前检查文档以获取正确的形式。工具和访问失败属于内部运行日志，绝不能出现在客户报告中。

## 开始前

1. 仔细阅读此文件。
2. 将下方的进度清单复制到您的工作笔记中，并随着进度更新它。
3. 收集输入（询问或从 `AGENTS.md`、MCP 上下文、环境、存储库推断）：

   - 组织别名
   - 数据库名称
   - 分支名称
   - 引擎：PlanetScale Vitess 或 PlanetScale Postgres
   - 生产分支或分支
   - 连接的应用程序存储库路径（如果可用）
   - 应用程序语言、框架、ORM、查询构建器、连接池
   - 操作员容忍度：仅报告、生成 PR、分支仅迁移或监督生产应用

如果输入缺失，继续进行发现。不要因完整性而阻塞。

## 接口优先级顺序

1. PlanetScale MCP 仅洞察服务器 — 无需查询执行的自主分析
2. 带只读范围的完整 PlanetScale MCP — 模式或有限读取查询
3. `pscale` CLI 和 `pscale api` — 结构化清单和精确 API 状态
4. 存储库检查 — 代码库分析和仪器建议
5. 直接 SQL — 仅在操作员授予数据库读取访问权限时进行只读内省

操作员声明的接口约束优先于此顺序。如果运行仅限于特定接口（例如仅 CLI），请使用这些接口；这不是冲突，无需在客户报告中添加除范围部分接口行之外的任何解决方法或注释。

## 执行计划

对于每个阶段：**阅读技能文件**，遵循其说明，捕获其所需输出，并将发现结果传递下去。除非清单指示跳过，否则不要跳过阶段。

### 阶段 0 — 安全协议

阅读：`../planetscale-change-gates-and-approval-contract/SKILL.md`

内化操作类别 A–E。所有后续阶段在操作员明确批准命名变更之前均按 A 类操作。

### 阶段 1 — 只读清单

阅读并执行：`../planetscale-readonly-inventory/SKILL.md`

传递的交付物：

- 带证据的清单表（来源、路径/命令、时间戳、置信度）
- 缺失证据表
- 风险标志
- 确认的引擎（Vitess 或 Postgres）
- 分支拓扑和生产分支

如果清单后引擎仍未知，则在阶段 2 之前确定它。

### 阶段 2 — 引擎安全审查

运行其中一个：

| 引擎 | 技能文件 |
|------|---------|
| Vitess | `../planetscale-vitess-safety-review/SKILL.md` |
| Postgres | `../planetscale-postgres-safety-review/SKILL.md` |

交付物：特定于引擎的安全差距、工作流差距和需要批准的建议变更。

### 阶段 3 — 查询洞察和标签

阅读并执行：`../planetscale-query-insights-and-tags/SKILL.md`

交付物：查询风险表、标签覆盖表、不良/高基数标签、建议标签模式、候选流量控制切片、候选模式和代码变更。

### 阶段 4 — 流量控制（仅 Postgres）

**为 Vitess 跳过此阶段。** 将清单项标记为完成并备注“不适用 — Vitess”。

对于 Postgres，阅读并执行：`../planetscale-traffic-control-recommendations/SKILL.md`

交付物：建议预算（名称、模式、流量切片、规则类型、限制理由、测试/回滚计划）。

如果查询标签较弱，则根据该技能备注“先标记”，并推迟执行模式建议。

### 阶段 5 — Webhook 自动化

阅读并执行：`../planetscale-webhook-automation-recommendations/SKILL.md`

交付物：Webhook 清单、缺失订阅、目标质量审查、自动化机会、不安全自动化风险。

### 阶段 6 — 模式建议代理循环

阅读并执行：`../planetscale-schema-recommendations-agent-loop/SKILL.md`

交付物：每个建议的筛选（类型、严重性、证据、安全实现路径、验证/回滚计划）。

### 阶段 7 — 代码库 SQLCommenter 仪器

阅读并执行：`../planetscale-codebase-sqlcommenter-instrumentation/SKILL.md`

仅当没有存储库可用时才跳过。在最终报告中备注“未审查存储库”。

交付物：检测到的堆栈、当前标签状态、建议的包/路径、建议的标签模式、可能更改的文件。

### 阶段 8 — MCP 代理操作模型

阅读并执行：`../planetscale-mcp-agent-operating-model/SKILL.md`

交付物：建议的 MCP 服务器选择、`AGENTS.md` 添加、允许/禁止的自主工作、建议的代理循环。

### 阶段 9 — 最佳实践矩阵覆盖检查

阅读并执行：`../planetscale-best-practices-matrix/SKILL.md`

将每个矩阵项与阶段 1–8 的发现进行交叉检查。对于每个项记录：

- 适用：是 / 否 / 未知
- 当前状态
- 差距
- 建议编号（见编号方案下方）
- 批准要求

填补差距：如果某个矩阵项未被先前阶段覆盖，请现在收集缺失证据（仅限只读）。

### 阶段 10 — 统一客户报告

阅读并执行：`../planetscale-customer-report-template/SKILL.md`

将所有阶段交付物综合为一份报告。不要直接堆砌原始阶段输出 — 合并、去重，并按影响排序。

#### 建议编号方案

| 前缀 | 域 |
|------|-----|
| `OBS-*` | 洞察和查询标签 |
| `VIT-*` | Vitess 安全和部署工作流 |
| `PG-*` | Postgres 角色、pg_strict、流量控制、PITR、网络 |
| `WEB-*` | Webhooks 和自动化 |
| `APP-*` | 存储库仪器 |
| `AGENT-*` | MCP 和代理工作流 |

在整个报告中分配稳定编号。在建议变更集中引用相同的编号。

#### 排序指南

按以下顺序排序建议：

1. 生产安全和可用性风险（最高优先）
2. 阻碍诊断或流量控制的观察性差距
3. 减少检测/响应平均时间的自动化
4. 具有明确证据的性能和模式改进

### 阶段 11 — 停止门

重新阅读：`../planetscale-change-gates-and-approval-contract/SKILL.md`

验证：

- 未执行任何 C/D/E 类操作
- 每个建议的变更都有编号、目标、接口、效果、风险、回滚和测试计划
- 报告以所需的最终句子结束

**停止。** 不要应用变更 — 除非请求伴随着有效的自主模式承认（根据 `../planetscale-autonomous-execution-mode/SKILL.md`），在这种情况下，展示报告和执行计划，然后直接进入该技能下的执行。

## 需要的最终报告结构

使用 `../planetscale-customer-report-template/SKILL.md` 中的模板。最小部分：

1. **范围** — 组织、数据库、分支、引擎、存储库、接口、时间窗口；应用的变更：无
2. **执行摘要** — 3–7 个要点关于最高风险差距和最高价值改进
3. **当前状态** — 数据库拓扑、安全工作流、观察性、自动化、存储库仪器（带证据）
4. **建议** — 排序表，带编号、目标、收益、风险、批准需要、先测试、证据
5. **需要批准的建议变更集** — 每个C/D项的精确变更、接口、回滚、生产影响
6. **有意不应用的变更** — 明确列出未更改的内容
7. **证据附录** — 来源、命令/路径、时间戳、值、备注
8. **最终必需句子**（逐字）：

   > 未应用任何变更。在执行任何变更之前，请批准特定的变更编号。

## 处理部分运行

如果 MCP、CLI、API 或存储库访问不可用：

- 继续使用可用接口
- 在报告中记录缺失证据
- 降低受影响建议的置信度
- 不要编造状态 — 标记未知

## 报告后

执行的两个路径：

**逐变更批准。** 操作员批准特定编号：

1. 重新阅读 `../planetscale-change-gates-and-approval-contract/SKILL.md`
2. 仅执行命名编号
3. 生成该技能中定义的执行后报告

**自主模式。** 操作员明确承认风险，并指定范围（“我接受风险 — 将所有报告建议应用于 storefront-demo，包括生产”）：

1. 阅读 `../planetscale-autonomous-execution-mode/SKILL.md` 并根据其激活合同验证承认
2. 展示依赖排序的执行计划，然后端到端执行，带持续状态、每步验证和该技能的停止规则
3. 生成运行摘要和运行日志

永远不要将“应用最佳实践”、“修复所有问题”或“继续”解释为批准或风险承认。

## 快速调用

当用户说“运行完整评估”或“运行所有 PlanetScale 最佳实践技能”：

1. 加载此技能
2. 按顺序运行阶段 0–11
3. 返回统一报告
4. 停止
