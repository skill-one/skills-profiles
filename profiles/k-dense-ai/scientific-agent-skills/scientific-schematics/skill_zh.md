# 科学示意图和图表

## 概述

科学示意图和图表将复杂概念转化为清晰的视觉表现形式用于发表。**此技能使用 Nano Banana 2 AI 进行图表生成，并使用 Gemini 3.6 Flash 进行质量审查。**

**工作原理：**
- 用自然语言描述您的图表
- Nano Banana 2 自动生成符合发表标准的图像
- **Gemini 3.6 Flash 审查质量**，对照文档类型的阈值
- **智能迭代**：仅在质量低于阈值时才重新生成
- 分钟内即可获得符合发表标准的输出
- 无需编码、模板或手动绘图

**按文档类型划分的质量阈值：**
| 文档类型 | 阈值 | 描述 |
|---------------|-----------|-------------|
| 期刊 | 8.5/10 | Nature、Science、同行评审期刊 |
| 会议 | 8.0/10 | 会议论文 |
| 学位论文 | 8.0/10 | 学位论文、论文 |
| 资助申请 | 8.0/10 | 资助申请 |
| 预印本 | 7.5/10 | arXiv、bioRxiv 等 |
| 报告 | 7.5/10 | 技术报告 |
| 海报 | 7.0/10 | 学术海报 |
| 演示文稿 | 6.5/10 | 幻灯片、演讲 |
| 默认 | 7.5/10 | 通用 |

**只需描述您想要的内容，Nano Banana 2 就会为您创建。** 所有图表都存储在 figures/ 子文件夹中，并在论文/海报中引用。

**输出内容：** 无论图像模型返回何种分辨率，都是矢量 PNG。此技能没有矢量路径和 DPI 控制——如果期刊要求 PDF、EPS 或 300 dpi TIFF，请下游转换 PNG 并在最终打印尺寸下检查结果。

## 快速入门：生成任何图表

通过简单地描述即可创建任何科学图表。Nano Banana 2 自动处理一切，并使用 **智能迭代**：

```bash
# 为期刊论文生成（最高质量阈值：8.5/10）
python scripts/generate_schematic.py "CONSORT 参与者流程图，500 名筛选者，150 名排除者，350 名随机分配" -o figures/consort.png --doc-type journal

# 为演示文稿生成（较低阈值：6.5/10 - 更快）
python scripts/generate_schematic.py "Transformer 编码器-解码器架构，左侧为编码器堆栈，右侧为解码器堆栈，显示多头注意力和交叉注意力连接" -o figures/transformer.png --doc-type presentation

# 为海报生成（中等阈值：7.0/10）
python scripts/generate_schematic.py "从 EGFR 到基因转录的 MAPK 信号通路" -o figures/mapk_pathway.png --doc-type poster

# 自定义最大迭代次数（最多 2 次）
python scripts/generate_schematic.py "包含运算放大器、电阻器和电容器的复杂电路图" -o figures/circuit.png --iterations 2 --doc-type journal
```

**幕后发生的事情：**
1. **生成 1**：Nano Banana 2 根据科学图表最佳实践创建初始图像
2. **审查 1**：**Gemini 3.6 Flash** 评估质量，对照文档类型阈值
3. **决策**：如果质量 >= 阈值 → **完成**（无需更多迭代！）
4. **如果低于阈值**：基于评论改进提示，重新生成
5. **重复**：直到质量满足阈值或达到最大迭代次数

**智能迭代的好处：**
- ✅ 如果第一次生成足够好，则节省 API 调用
- ✅ 为期刊论文设定更高的质量标准
- ✅ 演示文稿/海报的快速交付
- ✅ 每种用例都适用适当的质量

**输出**：版本化的图像（`name_v1.png`、`name_v2.png`）、您请求路径的获胜者副本，以及包含每次迭代的分数、评论和提前停止原因的 `name_review_log.json`。

**当审查无法运行时**——速率限制、内容过滤器、审查者以某种意外形状回答——图像仍然会生成并保存，但不会为其编造分数。日志记录 `"score": null` 和 `"reviewed": false`，原因记录在 `"review_error"` 中，运行时打印 `Review unavailable — image kept, quality not verified`。将此图像视为未检查，并自行查看；重新运行值得一试，因为失败通常是暂时的。

### AI 生成最佳实践

**科学图表的有效提示：**

✓ **好的提示**（具体、详细）：
- "CONSORT 流程图，显示从筛选（n=500）到随机分配再到最终分析的参与者流程"
- "Transformer 神经网络架构，左侧为编码器堆栈，右侧为解码器堆栈，显示多头注意力和交叉注意力连接"
- "生物信号级联：EGFR 受体 → RAS → RAF → MEK → ERK → 细胞核，标注磷酸化步骤"
- "物联网系统框图：传感器 → 微控制器 → WiFi 模块 → 云服务器 → 移动应用"

✗ **避免模糊的提示**：
- "制作流程图"（过于笼统）
- "神经网络"（哪种类型？包含哪些组件？）
- "通路图"（哪种通路？哪些分子？）

**包含的关键元素：**
- **类型**：流程图、架构图、通路、电路等
- **组件**：要包含的特定元素
- **流程/方向**：元素如何连接（从左到右、从上到下）
- **标签**：要包含的关键注释或文本
- **风格**：任何特定的视觉要求

**科学质量指南**（自动应用）：
- 干净的白色/浅色背景
- 高对比度以提高可读性
- 清晰、可读的标签（最小 10pt）
- 专业字体（无衬线字体）
- 色盲友好色板（Okabe-Ito 色板）
- 适当的间距以防止拥挤
- 在适当的地方添加比例尺、图例、坐标轴

## 最佳实践总结

### 设计原则——在提示中请求这些内容

1. **清晰胜于复杂** - 简化，移除不必要的元素
2. **一致的样式** - 在论文的所有图表中描述相同的视觉约定
3. **色盲可访问性** - 请求 Okabe-Ito 色板和冗余编码
4. **适当的字体** - 无衬线字体，标签大小适中
5. **逻辑流程** - 明确说明方向（从左到右、从上到下）

生成器默认应用所有这些，但用自己的话描述特定图表比仅依赖内置指南效果更好。

### 管道无法完成的任务

1. **矢量输出** - 仅 PNG；不产生 PDF、SVG 或 EPS
2. **分辨率控制** - 图像模型选择；没有 DPI 标志
3. **色域** - 仅 RGB；下游转换为 CMYK 打印工作流程
4. **精确的线权重或文本大小** - 在提示中描述它们，然后通过肉眼验证

对于需要矢量艺术或 300+ dpi TIFF 的期刊，生成后转换 PNG 并在其实际打印尺寸下检查结果。

### 集成指南

1. **包含在 LaTeX 中** - 使用 `\includegraphics{}` 引用生成的图像
2. **彻底添加标题** - 描述所有元素和缩写
3. **在文本中引用** - 在叙述流程中解释图表
4. **保持一致性** - 论文中所有图表采用相同风格
5. **版本控制** - 将提示和生成的图像存储在存储库中

## 常见问题排查

生成是随机的，迭代次数最多为 2，因此实际改变结果的杠杆是提示、文档类型和重新运行。此技能没有后处理步骤和质量检查库：您可以在生成的 PNG 和 `<name>_review_log.json` 中检查所有内容。

### 图表不正确

**文本重叠、元素拥挤或箭头未命中目标**
- 在提示中指定布局："垂直流程，每行一个框，阶段之间间距充足"
- 指定连接："从 RAF 到 MEK 标注磷酸化"，而不是 "显示级联"
- 重新运行。相同提示的两次运行不同，不良布局通常是运气不好

**内容科学上不正确或缺少组件**
- 明确列出组件，包括数量和标签——模型不会推断它们
- 阅读审查日志中的 `critique` 字段：审查者通常会指出缺少的内容

**标签中的文本不正确，或图像中嵌入了图形编号**
- 提示已经禁止 "Figure 1:" 标题；如果无论如何都出现，请重新运行
- 图像模型最常犯的错误是拼写错误的标签。在使用标签之前，请仔细阅读每个标签

### 分数似乎不正确

**分数低于图表应有的水平**
- 在重新运行之前阅读评论；审查者的投诉通常是合法且具体的
- 阈值，而不是分数，决定是否迭代——`--doc-type journal` 要求 8.5

**运行在低于阈值的分数下停止**
- 这是迭代次数上限。`--iterations 2` 是最大值；保留最后图像并报告其真实分数

**日志中的 `"score": null` 和 `"reviewed": false`**
- 审查调用失败或以不可用的形状回答。图像很好，已被保留；只有其质量从未被测量。检查 `"review_error"`，自行查看图像，并重新运行

### 设置

**`Error: OPENROUTER_API_KEY not found`**
- `export OPENROUTER_API_KEY='sk-or-v1-...'`，或将其添加到 `.env` 文件中，或传递 `--api-key`

**`Error: requests library not found`**
- `uv pip install requests`

**任何 API 错误**——使用 `-v` 运行以查看请求、模型别名和完整的错误正文

## 快速参考清单

提交图表之前，请验证：

### 阅读审查日志（这是唯一的自动检查）
- [ ] `<name>_review_log.json` 存在，且最终迭代的 `"reviewed"` 为 `true`
- [ ] `"final_score"` 是一个真实数字，不是 `null`，并且满足您的文档类型阈值
- [ ] 阅读评论——即使通过分数，审查者剩余的问题也会列出
- [ ] 如果生成了多个版本，请比较 `_v1` 和 `_v2` 并保留更好的一个

### 自己查看图像
- [ ] 每个标签都拼写正确——图像模型会拼写错误文本，这里没有自动检查捕获
- [ ] 没有重叠或剪切的文本
- [ ] 所有箭头都连接它们要连接的元素
- [ ] 科学上是正确的：正确的组件、正确的方向、没有虚构的内容
- [ ] 单位和数量与您请求的一致

### 可访问性（通过肉眼或外部检查器）
- [ ] 色盲安全色板，编码不是仅颜色
- [ ] 转换为灰度后仍然可读
- [ ] 相邻元素之间有足够的对比度

### 发表适用性
- [ ] 与论文中其他图表保持一致的样式
- [ ] 在实际打印宽度下可读
- [ ] 如果 PNG 不被接受，则转换为期刊要求的格式
- [ ] 撰写标题，定义每个缩写
- [ ] 在论文文本中引用

### 版本控制
- [ ] 提示被记录（它被逐字存储在审查日志中）
- [ ] 审查日志与图像一起提交，以便分数可审计
- [ ] 记录重新生成图形的命令

### 最终集成检查
- [ ] 图表在编译的论文中正确显示
- [ ] 跨引用工作（`\ref{}` 指向正确的图表）
- [ ] 图形编号与文本引用匹配
- [ ] 标题出现在相对于图表的正确页面上
- [ ] 与图形相关的没有编译警告或错误
