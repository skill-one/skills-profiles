# 科学头脑风暴

## 目的和边界

使用这项技能来创建、组织、挑战和透明地优先考虑候选研究方向。将每个输出视为一个**提案**，而不是一个发现。创意方法可以改变参与度和想法产出，但没有一种方法能普遍提高原创性、实用性或科学有效性。证据基础及其局限性总结在`references/sources.md`中。

将这些活动分开：

- **构思**产生问题、机制、替代方案或研究概念。
- **证据评估**检查可靠的文献和数据支持情况。
- **假设验证**需要观察、预测、合适的
  设计、分析以及独立审查；头脑风暴不能验证假设。
- **伦理、生物安全、双重用途、监管和机构审查**需要相关的授权审查员。一次头脑风暴永远不会是批准。
- **临床建议**需要合格的临床医生和患者特定的
  背景。不要将研究想法变成诊断或治疗指导。

对于以观察为引导的可检验假设，转交给
`hypothesis-generation`。对于研究架构，使用`experimental-design`；对于样本量，`statistical-power`；对于现有证据，
`literature-review`；并且对于分析，`statistical-analysis`。

## 运作规则

1. 将主张标记为**想法**、**假设**、**预测**、**已定位证据**或**决策**。永远不要混淆这些类别。
2. 在向参与者展示他人的或AI生成的想法之前独立生成。面对面轮流发言可能会阻碍生产，而例子可能会锚定后续输出。
3. 保留少数观点、负面证据、不确定性以及弃权。共识不是真理，投票数也不是效应量。
4. 记录来源，但不要泄露机密、个人、受控或未发表的信息。
5. 在评分之前定义评价标准和方向。保留原始评分、理由、范围和分歧。
6. 在实际可行的情况下，在初步独立轮之后搜索文献，然后故意重新开放构思。这减少了早期锚定，而不会将不完整的搜索误认为研究差距。
7. 不要自动选择一个“赢家”。评分是可追溯的决策辅助工具；定性判断、不确定性、可行性和伦理门槛仍然是控制因素。

## 可重复的工作流程

### 1. 界定会议范围

写一个焦点问题并记录：

- 目的、受众、决策所有者和时间范围；
- 在范围内和范围外的主题；
- 真实的、假设的、可协商的或未知的限制；
- 当前知识、未解决的观察结果和禁止的输出；
- 是否可能涉及人类参与者、动物、临床护理、敏感数据、病原体、受控技术或环境释放。

如果请求寻求患者特定的护理、规避监管、有害优化或操作上支持双重用途细节，停止构思并转交给适当的专业或机构流程。

### 2. 故意多样化视角

邀请相关的方法论、领域、实施、统计、安全、伦理、利益相关者和生活经验视角。多样性不是创造力的保证：解释谁的观点被代表、缺失或结构上处于不利地位。在适当的情况下使用可访问的参与模式和假名参与者ID。

促进者应披露利益冲突、避免首先提供倾向性答案、防止高级成员主导，并要求领导者在独立轮之后贡献。

### 3. 独立生成

给每个人相同的 neutral 提示、限制和固定时间窗口。参与者私下平行地写想法，然后再讨论。对于每个想法，捕获：

- 一个稳定的ID和一个句子的陈述；
- 贡献者ID和阶段（`independent`、`discussion`或`post-check`）；
- 起源（`human`、`AI-assisted`、`literature-inspired`、`mixed`或`other`）；
- 假设、预测观察结果、不确定性以及可能的
  否定证据；
- 文献启发的想法的来源标识符和AI协助的工具/目的披露。

在这个轮次之前不要展示示例解决方案，除非示例是必要的；如果是，将它们记录为潜在的锚定。

### 4. 无立即评估地分享

使用轮流发言或集中沉默分享。澄清措辞而不进行倡导。允许一个私人或匿名渠道。询问每个参与者什么缺失、什么与主导框架相矛盾，以及哪个想法在听到小组之后变得不明显。

### 5. 结构化聚类

按明确的关联关系（如共享结果、机制、人群、规模或方法）分组想法。保留原始ID和文本。记录合并和拆分。相似的措辞不是语义等价的证明；当它们的假设、干预、人群或预测不同时，保留不同的想法。参见`references/facilitation_workflows.md`。

### 6. 定义透明标准

在评分之前，定义每个标准、方向、量表锚点、所需证据、冲突和明确的权重。常见的维度包括：

- 潜在的信息增益和区分性预测；
- 与界定问题的相关性；
- 相对于已检查文献的原创性，而不仅仅是相对于房间；
- 可行性、资源和可逆性；
- 方法论严谨性和易受偏差的影响；
- 伦理、安全、公平、双重用途和监管负担；
- 如果结果是零或与受青睐的机制相矛盾，其价值。

在评估者不确定的情况下使用范围或置信度标签。不要将否决票隐藏在平均分数中。参见`references/idea_evaluation.md`。

### 7. 运行对抗性审查

分配一个没有原创每个短名单想法的审查者。询问：

- 哪个观察结果会使这个想法错误或不具信息量？
- 哪种替代解释适合相同的预测结果？
- 哪个隐藏的依赖关系、测量失败、混杂因素或选择效应可能占主导？
- 权威性、锚定、群体忠诚度、发表激励或吸引人的技术是否在推动偏好？
- 这是否会造成伤害、加剧不平等、暴露敏感信息或促成滥用？

记录回应、缓解措施、剩余不确定性以及想法是否被修改—not just pass/fail。

### 8. 检查文献和证据

搜索权威数据库、原始研究、方法指导、负面结果和相邻领域。在来源处验证每个引用。对于每个想法，记录查询/日期、筛选的来源、支持和对立证据以及搜索限制。使用状态，如`not-checked`、`search-incomplete`、`support-located`、`challenge-located`或`mixed`。

从有界搜索中缺失并不能证明新颖性，支持性文献也不能验证新机制。在证据检查后重新开放一轮独立的生成。

### 9. 应用可行性、严谨性和伦理门槛

在推进一个想法之前，识别适当的领域审查：

- 对于生物医学工作，考虑先前研究的严谨性、稳健设计、相关的生物变量和资源认证。当NIH政策适用时，性别作为生物变量应从研究问题开始，通过设计、分析和报告都应考虑；用相关证据证明单一性别范围的合理性。
- 将涉及人类受试者、动物、生物安全、数据治理、出口管制、临床、环境和其他受监管的工作转交给相关办公室。
- 早期筛选生命科学和使能技术想法的双重用途或滥用潜力。当前的美国监管正在发展；咨询机构并参考当前政策，而不是依赖静态清单。
- 不要将敏感、未发表、专有、受控或个人信息上传到外部AI服务。

伦理或可行性问题可能需要重新设计、受控处理或停止。高创造力分数永远不会覆盖门槛。

### 10. 决策和记录

负责的人类决策者记录：

- 考虑的候选方案和使用的标准/权重；
- 原始评分、不确定性范围、异议、弃权和敏感性结果；
- 文献和审查日期；
- 门槛结果和所需批准；
- 决策、理由、拒绝的替代方案、未解决的风险、所有者以及重新审视触发器。

正确标记下一步行动：进一步搜索、咨询、模拟、试点设计、方案开发、预先登记或无行动。如果计划进行确认性研究，在结果未知之前预先登记假设和分析决策；透明地报告后续偏差和探索性工作。预先登记提高了透明度，但不是同行评审、伦理批准或有效性的证明。

## 偏见和失败控制

- **生产阻塞**：独立平行生成之前进行口头讨论。
- **锚定和设计固定**：独立轮之前不要有领导答案或AI示例；在证据审查后重新开放生成。
- **权威和地位效应**：领导者最后分享、匿名输入、独立评分和可见的异议。
- **群体思维**：分配一个真正的替代生成角色，邀请外部审查，并记录被拒绝的选项。将“群体思维”视为一组风险，而不是一个单一的普遍确立的诊断。
- **评价焦虑**：在可能的情况下将贡献与归属分开；批评想法，而不是贡献者。
- **过早收敛**：固定的发散窗口后进行明确过渡和预先声明标准。
- **虚假精度**：使用锚定量表、不确定性范围、敏感性分析和叙述性审查。
- **研究差距膨胀**：记录搜索边界并使用“未找到直接证据”，而不是“从未研究过”。
- **AI幻觉或同质化**：以人为先的构思、来源、独立验证、多个非AI视角，并比较可疑的重复框架。参见`references/responsible_ai.md`。

## 可选的本地CLI

脚本是有确定性的、标准库工具。它们不调用网络服务、LLM或科学数据库，也不做科学结论。

```bash
python scripts/session_scaffold.py --help
python scripts/validate_register.py --help
python scripts/evaluate_matrix.py --help
```

创建会议注册：

```bash
python scripts/session_scaffold.py \
  --session-id "microbiome-01" \
  --title "Microbiome mechanism ideation" \
  --question "Which mechanisms could explain the scoped observation?" \
  --participant P01 --participant P02 \
  --output session.json
```

验证结构和来源：

```bash
python scripts/validate_register.py session.json --output validation.json
```

从CSV计算完全披露的加权矩阵，包括评分间隔和一次一个的权重敏感性：

```bash
python scripts/evaluate_matrix.py scores.csv \
  --config criteria.json \
  --weight-delta 0.10 \
  --output matrix.json
```

输出拒绝符号链接和现有文件，除非明确指定`--force`；输入和集合大小是有限的。验证器检查结构，而不是真相。矩阵保留定性审查和不确定性，并将`decision`设置为null。输入格式和解释在`references/idea_evaluation.md`中记录。
