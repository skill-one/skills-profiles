# 科学假设生成

将一个观察转化为透明的候选解释和测试集。假设是一个有待挑战的提议，而不是一个发现、事实、诊断或建议。

## 不可协商的界限

在使用未发表的、敏感的、受控的、个人的、专有的、出口受控的或与安全相关的材料之前：

1. 确认授权和适用的机构、资助者、出版商、数据使用、隐私和人工智能政策。
2. 除非经授权人员明确批准了命名的外部目的地和数据范围，否则将材料保留在本地。
3. 最小化输入。未经授权，不要将敏感或未发表的数据放在网络搜索或外部人工智能系统中。
4. 在适当的人类、动物、生物安全、双重用途、数据治理或监管关卡处停止。

永远不要：

- 将假设、机制、因果关系、引用或明显模式作为既定证据呈现；
- 因为快速搜索未找到任何内容而声称新颖；
- 仅凭关联、时间顺序、预测准确性或模型输出推断因果关系；
- 提供针对特定患者的诊断、治疗、剂量、预后或其他临床建议；
- 提供对病原体、毒素、武器、规避或其他滥用的有害实验优化或操作细节；
- 绕过IRB/REC、IACUC、IBC、生物安全、双重用途、隐私、法律或监管审查；
- 编造来源、标识符、搜索范围、数据、结果、批准或预先注册；
- 自动评分、排名、选择、接受或拒绝科学假设。

如果请求跨越了安全关卡，仅生成高级别的风险/监督说明，并将其路由到合格的地方当局。不要继续进行操作细节。

## 保持对象区分

| 对象 | 含义 |
|---|---|
| **观察** | 测量、注意到或报告的内容，包括来源和不确定性 |
| **研究问题** | 定义范围的可回答问题 |
| **假设** | 候选的解释或关系命题 |
| **机制** | 连接条件与结果的拟议过程 |
| **因果估计量** | 精确定义的因果对比，用于估计 |
| **预测** | 在检查目标结果之前得出的可观察推论 |
| **替代解释** | 竞争性解释，包括偏差或非因果关系解释 |
| **零假设** | 分析中使用的指定无效应/无差异模型 |
| **阴性对照** | 预期不会通过拟议机制起作用的对照 |
| **操作化** | 如何将构念转化为变量、测量、干预或类别 |
| **分析计划** | 预先指定的转换、模型、对比、不确定性和决策规则 |
| **证据** | 对声明有影响的现象或来源；永远不会是声明本身 |

不要混淆这些标签。一个机制性故事不是预测；预测不是证据；拒绝一个零假设并不能证明机制；对一个候选的支持并不能消除未考虑的竞争对手。

## 工作流程

### 1. 运行范围和安全关卡

记录：

- 可问责的人类所有者和预期用途；
- 数据敏感性、授权、保留和允许的处理；
- 受影响的人、动物、生态系统、社区或安全利益；
- 需要的伦理、可行性、生物安全、双重用途和监管审查；
- 未解决的障碍和需要的领域专业知识。

没有脚本批准就是伦理、安全、监管或科学批准。

### 2. 冻结观察

在解释之前记录观察：

- 测量或来源；
- 人口、系统、地点和时间；
- 观察单位和分析单位；
- 不确定性、缺失值、排除和预处理；
- 模式是预期的、探索性的还是查看结果后选择的。

使用“报告的”、“观察到的”或“关联的”，而不是因果语言，除非因果设计和估计量证明它是合理的。

### 3. 构建研究问题

仅在适合时选择框架：

- **PICO/PICOT** 用于干预/效果问题：人口、干预、比较对象、结果，以及可选的时间。
- **PECO** 用于暴露问题。
- **人口-索引测试-参考标准-目标条件** 用于诊断准确性。
- **人口-预后因素-结果-时间** 用于预后。
- 特定领域的构念-背景-结果框架，用于定性、描述性、机制性或理论性工作。

PICO不是一个通用的模板。定义利益相关者、背景、界限、可行性和答案将如何改变知识或实践。FINER是一个问题细化助记符——可行的、有趣的、新颖的、伦理的、相关的——而不是一个评分系统。将“新颖的”视为未解决的，直到有记录的、适合目的的搜索和专家审查支持它。

### 4. 建立日期证据边界

在做出依赖文献的声明之前进行搜索。优先考虑原始研究、官方政策、原始方法论文、当前报告指南和用于定向的系统评价。

记录：

- 搜索日期和截止日期；
- 数据库/索引、查询、过滤器和筛选边界；
- 包含和排除的来源类型；
- 支持每个声明的来源、挑战或背景化的来源；
- 已知的访问、语言、数据库和时间限制。

搜索可以确定搜索了什么，而不是普遍的缺失。说“在记录的搜索边界内未找到”，而不是“没有先前的作品存在”。使用 `assets/search_boundary_template.json`，`assets/evidence_ledger_template.csv`，和 `references/literature_search_strategies.md`。

### 5. 在选择测试之前生成竞争对手

当可能时，从真正不同的解释类别中创建多个候选者：

- 拟议机制；
- 测量或处理伪影；
- 混淆或共同原因；
- 选择或损耗；
- 条件化于碰撞器；
- 逆因果关系；
- 时间、背景或边界条件差异；
- 随机变化；
- 另一尺度上的竞争机制。

在人工智能辅助扩展之前，独立生成初始竞争对手集，以减少锚定和同质化。不要强迫固定数量或虚假对称。保持每个候选者标记为 `candidate`。

Platt的强推断模式激励替代假设和关键测试，但失败的替代假设并不能使幸存者真实。未知的替代假设、辅助假设、测量误差和混合机制仍然是可能的。

### 6. 声明声明类型和估计量

将每个目标分类为：

- 描述性；
- 关联性；
- 预测性；
- 因果性；
- 机制性。

对于因果目标，在分析之前定义：

- 目标人口或系统；
- 干预/暴露和比较对象；
- 结果和时间范围；
- 人口水平摘要；
- 治疗版本和并发事件处理（如相关）；
- 识别假设和目标试验/设计类似物。

分别记录混杂、选择、碰撞器、测量和逆因果关系风险。观察性因果估计仍然是假设依赖的。使用 `references/causal_inference_and_claims.md`。

### 7. 推导区分性预测

对于每个候选者：

1. 陈述条件和边界条件。
2. 命名可观察的和测量。
3. 陈述预期模式和不确定性。
4. 陈述在声明假设下与候选者不一致的结果。
5. 与至少一个竞争对手进行对比。
6. 定义不确定结果和从它们中学到的东西。

优先考虑竞争对手预测明显不同结果的测试。在科学上适当的时候添加阳性、程序和阴性对照。阴性对照必须无法通过目标机制起作用，同时共享相关的偏差路径；它不是一个装饰性的未处理组。

使用 `assets/prediction_rival_matrix_template.csv` 和 `assets/falsification_controls_template.json`。

### 8. 操作化和验证测量

对于每个构念记录：

- 变量角色和操作定义；
- 人口/系统、单位、时间条件和背景；
- 仪器/方法、校准、质量控制、掩码；
- 可靠性/可重复性；
- 有效性证据和适用性；
- 缺失值、检测限、转换、截止点及其理由；
- 测量不变性或跨组可比性（如相关）；
- 可预见的测量偏差和限制。

不要将方便的代理视为构念本身。使用：

```bash
python3 scripts/check_operationalization.py local-operationalization.json
```

### 9. 使设计和分析匹配声明

指定：

- 抽样、实验单元、分配、随机化、掩码和控制；
- 包括/排除和停止规则；
- 基于声明假设的样本量、精度或信息理由；
- 结果、对比、估计量、模型、效应测量和不确定性；
- 缺失数据处理和并发事件处理；
- 结果、模型、亚组、观察和假设的多次性；
- 假设、诊断、稳健性和敏感性分析；
- 复制或独立验证计划；
- 确认性 versus 探索性。

不要使用通用的样本量最小值。不要将阈值化的p值解释为假设为真的概率或效应重要性。参见 `references/experimental_design_patterns.md`。

对于干预试验，在适用时使用当前的SPIRIT 2025方案指南和CONSORT 2025报告指南。这些提高了完整性；它们不认证设计质量、伦理或监管合规性。

### 10. 防止HARKing并暴露偏差

在访问目标结果之前，在可行时记录问题的时间戳、候选者、预测、结果、排除、转换、分析、多次性、缺失数据计划和停止规则。

之后：

- 将数据依赖的想法和分析标记为探索性的；
- 保留和报告计划分析；
- 列出偏差的日期、理由、决定者以及预期影响；
- 永远不要将观察到的模式重写为先验预测。

预先注册是一个透明的计划，而不是禁止适应。已注册的报告增加了结果盲审和期刊政策下的原则上接受。参见 `references/preregistration_and_open_science.md`。

### 11. 计划复制和更新

区分：

- **可重复性**：从相同的数据/代码/条件获得的计算结果的一致性；
- **可复制性**：新数据收集的相同问题的研究之间的一致性。

在授权共享时保留来源、版本、代码、材料和决策日志。计划跨相关边界的独立复制或传输测试。当出现相反的、中性的或复制证据时更新候选者状态；不要隐藏负面结果。

### 12. 应用人类问责制

可问责的人类必须验证：

- 每个引用和来源到声明的链接；
- 领域合理性和测量有效性；
- 因果假设和统计设计；
- 伦理、可行性、安全、隐私和监管状态；
- 所有人工智能辅助文本、想法和引用；
- 是否需要更广泛的专业知识或社区输入。

人工智能可以编造引用、锚定推理和同质化候选集。记录允许的人工智能使用和材料影响。保持独立的人类构思和竞争对手生成在过程中。

## 本地工具索引

所有CLI都是有限的、无依赖的、本地的、确定性的和非评分的：

| 任务 | 资产 | 命令 |
|---|---|---|
| 假设记录模式 | `assets/hypothesis_record_template.json` | `python3 scripts/validate_hypothesis_schema.py record.json` |
| 测量清单 | `assets/operationalization_template.json` | `python3 scripts/check_operationalization.py checklist.json` |
| 预测/竞争对手矩阵 | `assets/prediction_rival_matrix_template.csv` | `python3 scripts/validate_prediction_matrix.py matrix.csv` |
| 声明语言检查 | 注释Markdown | `python3 scripts/lint_causal_claims.py draft.md` |
| 伪证/控制 | `assets/falsification_controls_template.json` | `python3 scripts/check_falsification_controls.py controls.json` |
| 证据/来源审计 | `assets/evidence_ledger_template.csv` + `assets/search_boundary_template.json` | `python3 scripts/audit_evidence_ledger.py ledger.csv boundary.json` |
| 预先注册脚手架 | `assets/preregistration_scaffold_template.md` | `python3 scripts/generate_preregistration_scaffold.py record.json -o preregistration.md` |

退出代码是 `0` 对于结构上有效的输出，`1` 对于完成验证时出现错误，`2` 对于格式错误/不安全的输入。报告验证声明和内部一致性；它们不验证科学真相或选择假设。完整模式在 `references/tool_reference.md` 中。

http://export.arxiv.org/api/query?id_list=2609.00065），并从该记录中获取作者列表、年份和版本。如果记录列出了期刊引用或出版商DOI，请引用已发表版本。
