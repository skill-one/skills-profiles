# opencli-browser-sitemap

当 `opencli browser open` 或 `opencli browser analyze` 报告 `sitemap.available: true`，或用户要求使用某个网站的站点地图时，使用此技能。

站点地图是**先验知识**，而非事实真相。它应减少盲目点击，但绝不能覆盖实时浏览器状态。

---

## 消费循环

1. 运行或重用 `opencli browser <session> state` 以了解当前页面。
2. 仅读取最小的相关站点地图文件：
   - `SITE.md` 用于网站级导向。
   - 一个匹配当前状态的 `pages/<page-id>.md`。
   - 一个匹配用户目标的 `workflows/<task-id>.md`。
   - 仅在流程被阻塞或警告时读取 `pitfalls.md`。
3. 优先选择流程的**最佳路径**。如果它指定了如 `opencli twitter post` 的适配器，则在使用原始浏览器操作之前使用该适配器。
4. 如果适配器不可用或失败，使用**备用路径**的浏览器流程。
5. 每次导航或状态变更操作后，刷新 `state` 并比较流程的 `state_signature`。
6. 如果现实与预期不符，信任现实，继续探测，并记录本地过时笔记或草稿补丁。
7. 如果操作恢复包含 `adapter_health_update: <adapter> -> suspect|broken`，更新引用该适配器的本地覆盖流程，以便未来的代理直接跳转到备用路径。

---

## 查找顺序

先读取本地覆盖，再读取全局种子：

```text
~/.opencli/sites/<site>/sitemap/    # 本地覆盖
sitemaps/<site>/                    # 仓库种子（顶层）
```

本地文件会覆盖具有相同稳定 ID 的全局文件。

不要将整个大型站点地图加载到上下文中。如果目录很大，先列出文件名，然后仅读取所需的页面/流程。

---

## 信任现实规则

如果站点地图说明按钮、URL、路由或 API 应存在，但浏览器未显示：

- 重新运行 `state` 或 `find` 并使用语义锚点。
- 检查登录、区域设置、视口、A/B 测试或路由状态是否不同。
- 如果有安全路径可见，则跟随真实页面。
- 在本地覆盖中将站点地图项标记为过时。

永远不要因为“站点地图说明它应该工作”而持续点击。

---

## 过时 / 草稿笔记

当你发现偏差时，在相关页面/流程文件或本地覆盖中的草稿文件下写一个小的本地笔记：

```md
过时笔记：
- observed_at: YYYY-MM-DD
- current_url:
- expected:
- actual:
- next_probe:
```

除非任务是明确的书签地图编写或仓库 PR 任务，否则不要编辑全局种子文件。

## 适配器健康回写

当适配器失败且站点地图操作或流程指示你更新适配器健康时：

1. 在 `~/.opencli/sites/<site>/sitemap/workflows/` 下找到本地流程文件，其 `Best path` 引用了适配器命令。
2. 如果不存在本地流程，首先将匹配的全局流程复制到本地覆盖中；在浏览器任务执行期间绝不要直接编辑全局种子。
3. 按指示设置 `adapter_health: suspect` 或 `broken`。
4. 添加一个简短的过时笔记，包含观察到的错误、当前 URL 和时间戳。
5. 继续使用浏览器备用路径。

这种回写是记忆循环：当前代理回退一次，下一个代理不会浪费时间重试已知的可疑适配器。

---

## 输出规范

报告时需包含：

- 所选路径：适配器最佳路径或浏览器备用路径。
- 到达的检查点：当前 URL/状态签名。
- 站点地图健康：原样使用、标记为过时或缺少流程。

保持报告任务导向。不要总结整个站点地图。
