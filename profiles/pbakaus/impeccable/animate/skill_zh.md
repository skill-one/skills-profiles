分析功能特性，并策略性地添加动画和微交互，以增强理解、提供反馈并创造愉悦感。

## 必须准备

调用 `/impeccable` — 它包含设计原则、反模式和**情境收集协议**。在继续之前必须遵循该协议 — 如果还没有设计背景，你必须先运行 `/impeccable teach`。此外还需收集：性能约束。

## 评估动画机会

分析运动可以改善体验的地方：

1. **识别静态区域**：
   - **缺少反馈**：没有视觉确认的动作（按钮点击、表单提交等）
   - **突兀的过渡**：即时状态变化感觉突然（显示/隐藏、页面加载、路由变化）
   - **关系不明确**：空间或层级关系不明显
   - **缺乏愉悦感**：功能但无乐趣的交互
   - **错失引导**：引导注意力或解释行为的机会

2. **理解背景**：
   - 个性是什么？（活泼与严肃、活力与平静）
   - 性能预算是什么？（移动优先？复杂页面？）
   - 目标用户是谁？（对运动敏感的用户？追求速度的效率用户？）
   - 什么最重要？（一个英雄动画还是许多微交互？）

如果代码库中这些信息不明确，直接向用户询问以澄清你无法推断的内容。

**关键**：尊重 `prefers-reduced-motion`。始终为需要它们的用户提供非动画替代方案。

## 规划动画策略

创建有目的的动画计划：

- **英雄时刻**：唯一的标志性动画是什么？（页面加载？英雄区域？关键交互？）
- **反馈层**：哪些交互需要确认？
- **过渡层**：哪些状态变化需要平滑过渡？
- **愉悦层**：我们可以在哪里惊喜并带来愉悦？

**重要**：一个精心编排的体验胜过到处散落的动画。专注于高影响力的时刻。

## 实现动画

系统性地在这些类别中添加运动：

### 进入动画
- **页面加载编排**：错开元素显示（100-150ms延迟），淡入+滑动组合
- **英雄区域**：为主要内容添加戏剧性进入（缩放、视差或创意效果）
- **内容显示**：使用交叉观察者触发的滚动动画
- **模态/抽屉进入**：平滑滑动+淡入，背景淡入，焦点管理

### 微交互
- **按钮反馈**：
  - 悬停：轻微缩放（1.02-1.05），颜色变化，阴影增加
  - 点击：快速缩放后恢复（0.95 → 1），涟漪效果
  - 加载：旋转器或脉冲状态
- **表单交互**：
  - 输入焦点：边框颜色过渡，轻微缩放或发光
  - 验证：错误时抖动，成功时打勾，平滑颜色过渡
- **切换开关**：平滑滑动+颜色过渡（200-300ms）
- **复选框/单选按钮**：打勾动画，涟漪效果
- **点赞/收藏**：缩放+旋转，粒子效果，颜色过渡

### 状态过渡
- **显示/隐藏**：淡入+滑动（非即时），适当时间（200-300ms）
- **展开/收起**：高度过渡带溢出处理，图标旋转
- **加载状态**：骨架屏淡入，旋转器动画，进度条
- **成功/错误**：颜色过渡，图标动画，轻微缩放脉冲
- **启用/禁用**：不透明度过渡，光标变化

### 导航与流程
- **页面过渡**：路由间交叉淡入，共享元素过渡
- **选项卡切换**：滑动指示器，内容淡入/滑动
- **轮播/滑块**：平滑变换，快照点，惯性
- **滚动效果**：视差层，粘性头部带状态变化，滚动进度指示器

### 反馈与引导
- **悬停提示**：工具提示淡入，光标变化，元素高亮
- **拖放**：提升效果（阴影+缩放），放置区域高亮，平滑重新定位
- **复制/粘贴**：粘贴时短暂高亮闪烁，"已复制"确认
- **焦点流**：通过表单或工作流的路径高亮

### 愉悦时刻
- **空状态**：插图上轻微的浮动动画
- **完成操作**：五彩纸屑，打勾效果，成功庆祝
- **彩蛋**：隐藏的交互供发现
- **情境动画**：天气效果，一天中的主题，季节性点缀

## 技术实现

为每个动画使用适当的技术：

### 时间与缓动

**按目的划分的持续时间：**
- **100-150ms**：即时反馈（按钮按下，切换）
- **200-300ms**：状态变化（悬停，菜单打开）
- **300-500ms**：布局变化（手风琴，模态）
- **500-800ms**：进入动画（页面加载）

**缓动曲线（使用这些，而非CSS默认值）：**
```css
/* 推荐 - 自然减速 */
--ease-out-quart: cubic-bezier(0.25, 1, 0.5, 1);    /* 平滑，精致 */
--ease-out-quint: cubic-bezier(0.22, 1, 0.36, 1);   /* 略微更敏捷 */
--ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);     /* 自信，果断 */

/* 避免 - 感觉过时且俗气 */
/* bounce: cubic-bezier(0.34, 1.56, 0.64, 1); */
/* elastic: cubic-bezier(0.68, -0.6, 0.32, 1.6); */
```

**退出动画比进入动画更快。** 使用约75%的进入持续时间。

### CSS动画
```css
/* 优先用于简单、声明式动画 */
- 过渡用于状态变化
- @keyframes 用于复杂序列
- 仅使用 transform + opacity（GPU加速）
```

### JavaScript动画
```javascript
/* 用于复杂、交互式动画 */
- Web Animations API 用于程序化控制
- Framer Motion 用于 React
- GSAP 用于复杂序列
```

### 性能
- **GPU加速**：使用 `transform` 和 `opacity`，避免布局属性
- **will-change**：谨慎添加已知昂贵动画
- **减少重绘**：最小化重绘，适当使用 `contain`
- **监控FPS**：确保目标设备达到60fps

### 可访问性
```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

**永远不要**：
- 使用弹跳或弹性缓动曲线 — 它们感觉过时且吸引人对动画本身注意
- 动画布局属性（宽度、高度、top、left）— 使用 transform 代替
- 使用超过500ms的持续时间进行反馈 — 感觉卡顿
- 无目的动画 — 每个动画都需要理由
- 忽视 `prefers-reduced-motion` — 这是可访问性违规
- 动画所有内容 — 动画疲劳使界面感觉疲惫
- 在动画期间阻塞交互，除非有意为之

## 验证质量

彻底测试动画：

- **60fps时平滑**：目标设备上无卡顿
- **感觉自然**：缓动曲线感觉有机，非机械
- **适当时间**：不过快（突兀）或过慢（卡顿）
- **减少运动有效**：动画禁用或简化适当
- **不阻塞**：用户可在动画期间/之后交互
- **增加价值**：使界面更清晰或更愉悦

记住：运动应增强理解并提供反馈，而不仅仅是添加装饰。有目的地动画，尊重性能约束，并始终考虑可访问性。优秀的动画是看不见的 — 它只是让一切感觉对劲。
