## 评估动画机会

分析运动（动画）能够在哪些方面提升体验：

1. **识别静态区域**：
   - **缺失的反馈**：缺乏视觉确认的操作（按钮点击、表单提交等）
   - **突兀的过渡**：感觉突然、不连贯的即时状态变化（显示/隐藏、页面加载、路由切换等）
   - **关系不清晰**：空间或层级关系不明显
   - **缺乏愉悦感**：功能正常但缺乏愉悦感的交互
   - **指导缺失**：引导注意力或解释行为的契机

2. **理解上下文**：
   - 产品的性格是什么？（活泼 vs 严肃，活力 vs 沉静）
   - 性能预算是什么？（以移动端优先？复杂页面？）
   - 受众是谁？（对动画敏感的用户？追求速度的高效用户？）
   - 最重要的是什么？（一个核心动画，还是多个微交互？）

如果上述任何一项无法从代码库中推断出来，请直接询问用户以澄清您无法推断的内容。

**关键**：遵守 `prefers-reduced-motion`。始终为用户提供无需动画的替代方案，以满足有需求用户的需要。

## 制定动画策略

制定具有明确目的的动画计划：

- **核心瞬间**：唯一标志性动画是什么？（页面加载？核心区块？关键交互？）
- **反馈层**：哪些交互需要给予确认反馈？
- **过渡层**：哪些状态变化需要平滑处理？
- **愉悦层**：我们在哪里可以制造惊喜与愉悦感？

**重要**：一个精心编排的体验胜过到处零散的动画。聚焦于高影响（高冲击力）的时刻。

## 实现动画

在各个类别中系统性地添加运动（动画）：

### 入场动画
- **页面加载编排**：错落元素显现（100-150ms 延迟），淡入与滑动组合
- **核心区块（Hero 区）**：主内容的戏剧性入场（缩放、视差或创意效果）
- **内容显现**：使用 intersection observer 触发的滚动动画
- **弹窗/抽屉入场**：平滑滑动与淡入，背景淡入，焦点管理

### 微交互
- **按钮反馈**：
  - 悬停：细微缩放（1.02-1.05）、颜色变化、阴影加深
  - 点击：快速缩放回弹（0.95 → 1），涟漪效果
  - 加载中：旋转器（Spinner）或脉动状态
- **表单交互**：
  - 输入框聚焦：边框颜色过渡，轻微缩放或发光
  - 验证：出错时抖动，成功时显示对勾，颜色平滑过渡
- **开关切换**：平滑滑动与颜色过渡（200-300ms）
- **复选框/单选框**：对勾动画，涟漪效果
- **点赞/收藏**：缩放与旋转，粒子效果，颜色过渡

### 状态过渡
- **显示/隐藏**：淡入与滑动（非瞬间），适当时长（200-300ms）
- **展开/折叠**：高度过渡并处理溢出，图标旋转
- **加载状态**：骨架屏淡入，旋转器动画，进度条
- **成功/错误**：颜色过渡，图标动画，轻微缩放脉动
- **启用/禁用**：不透明度过渡，光标变化

### 导航与流程
- **页面切换**：路由间的交叉淡入，共享元素过渡
- **标签页切换**：指示器滑动，内容淡入/滑动
- **轮播/滑块**：平滑变换，吸附点，惯性
- **滚动效果**：视差层，带有状态变化的固定页头，滚动进度指示器

### 反馈与引导
- **悬停提示**：提示框淡入，光标变化，元素高亮
- **拖放**：抬起效果（阴影+缩放），落地区高亮，平滑重新定位
- **复制/粘贴**：粘贴时短暂高亮闪烁，“已复制”确认
- **焦点流**：表单或工作流中的高亮路径

### 愉悦时刻
- **空状态**：插画上的细微浮动动画
- **已完成的动作**：彩带散落，对勾绽放，成功庆祝
- **彩蛋（Easter eggs）**：用于发现的隐藏交互
- **情境动画**：天气效果，昼夜主题，季节点缀

## 技术实现

为每种动画使用合适的技术：

### 时长与缓动

**按目的划分的时长：**
- **100-150ms**：即时反馈（按钮按压、开关切换）
- **200-300ms**：状态变化（悬停、菜单打开）
- **300-500ms**：布局变化（手风琴、弹窗）
- **500-800ms**：入场动画（页面加载）

**缓动曲线（请使用以下曲线，而非 CSS 默认值）：**
```css
/* 推荐 - 自然减速 */
--ease-out-quart: cubic-bezier(0.25, 1, 0.5, 1);    /* 平滑、精致 */
--ease-out-quint: cubic-bezier(0.22, 1, 0.36, 1);   /* 稍显轻快 */
--ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);     /* 自信、果断 */

/* 避免使用 - 显得过时且浮夸 */
/* bounce: cubic-bezier(0.34, 1.56, 0.64, 1); */
/* elastic: cubic-bezier(0.68, -0.6, 0.32, 1.6); */
```

**退出动画比入场动画更快。使用入场时长的约 75%。**

### CSS 动画
```css
/* 优先用于简单、声明式的动画 */
- 使用 transitions 处理状态变化
- 使用 @keyframes 处理复杂序列
- 仅使用 transform + opacity（GPU 加速）
```

### JavaScript 动画
```javascript
/* 用于复杂、交互式的动画 */
- 使用 Web Animations API 进行程序化控制
- 使用 Framer Motion 进行 React 开发
- 使用 GSAP 处理复杂序列
```

### 性能
- **GPU 加速**：使用 `transform` 和 `opacity`，避免使用布局属性
- **will-change**：对于已知的高成本动画，谨慎添加
- **减少重绘**：最小化重绘，在合适时使用 `contain`
- **监控帧率（FPS）**：确保目标设备达到 60fps

### 无障碍访问
```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

**切勿**：
- 使用回弹或弹性缓动曲线——它们显得过时且会让人注意到动画本身
- 对布局属性（width、height、top、left）进行动画——应使用 transform 代替
- 为反馈使用超过 500ms 的时长——会感觉滞涩
- 无目的地进行动画——每个动画都需要理由
- 忽略 `prefers-reduced-motion`——这是无障碍访问违规
- 对所有内容进行动画——动画疲劳会让界面显得疲惫
- 除非有意为之，否则在动画期间阻塞用户交互

## 质量验证

全面测试动画：

- **在 60fps 下平滑运行**：目标设备无卡顿
- **感觉自然**：缓动曲线自然，而非机械
- **时长恰当**：既不过快（显得突兀），也不过慢（显得滞涩）
- **无障碍动画生效**：动画被正确禁用或适当简化
- **不阻塞交互**：用户可以在动画期间及之后进行交互
- **增加价值**：使界面更清晰或更愉悦

记住：运动（动画）应增强理解并提供反馈，而不仅仅是添加装饰。以目的为导向进行动画，尊重性能约束，并始终考虑无障碍访问。出色的动画是“隐形”的——它只是让一切感觉更舒适。
