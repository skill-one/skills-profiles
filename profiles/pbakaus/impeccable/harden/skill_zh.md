强化接口以应对边缘情况、错误、国际化问题和实际使用场景，这些场景会破坏理想化的设计。

## 评估强化需求

识别弱点和边缘情况：

1. **使用极端输入进行测试**：
   - 非常长的文本（姓名、描述、标题）
   - 非常短的文本（空、单个字符）
   - 特殊字符（表情符号、从右到左的文本、重音符号）
   - 大数字（百万、十亿）
   - 许多项目（1000+ 列表项、50+ 选项）
   - 无数据（空状态）

2. **测试错误场景**：
   - 网络故障（离线、慢速、超时）
   - API 错误（400、401、403、404、500）
   - 验证错误
   - 权限错误
   - 流量限制
   - 并发操作

3. **测试国际化**：
   - 长翻译（德语通常比英语长 30%）
   - 从右到左的语言（阿拉伯语、希伯来语）
   - 字符集（中文、日语、韩语、表情符号）
   - 日期/时间格式
   - 数字格式（1,000 vs 1.000）
   - 货币符号

**关键**：仅当完美数据时才工作的设计并非生产就绪。针对现实情况进行强化。

## 强化维度

系统地提高弹性：

### 文本溢出和换行

**长文本处理**：
```css
/* 单行带省略号 */
.truncate {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

/* 多行带 clamp */
.line-clamp {
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}

/* 允许换行 */
.wrap {
  word-wrap: break-word;
  overflow-wrap: break-word;
  hyphens: auto;
}
```

**Flex/Grid 溢出**：
```css
/* 防止 flex 项目溢出 */
.flex-item {
  min-width: 0; /* 允许小于内容大小收缩 */
  overflow: hidden;
}

/* 防止 grid 项目溢出 */
.grid-item {
  min-width: 0;
  min-height: 0;
}
```

**响应式文本大小**：
- 使用 `clamp()` 实现流体排版
- 设置最小可读尺寸（移动设备为 14px）
- 测试文本缩放（缩放到 200%）
- 确保容器随文本扩展

### 国际化 (i18n)

**文本扩展**：
- 为翻译预留 30-40% 的空间预算
- 使用适应内容的 flexbox/grid
- 使用最长的语言（通常是德语）进行测试
- 避免在文本容器上设置固定宽度

```jsx
// ❌ 不好：假设英文文本短
<button className="w-24">提交</button>

// ✅ 好：适应内容
<button className="px-4 py-2">提交</button>
```

**从右到左 (RTL) 支持**：
```css
/* 使用逻辑属性 */
margin-inline-start: 1rem; /* 不是 margin-left */
padding-inline: 1rem; /* 不是 padding-left/right */
border-inline-end: 1px solid; /* 不是 border-right */

/* 或者使用 dir 属性 */
[dir="rtl"] .arrow { transform: scaleX(-1); }
```

**字符集支持**：
- 在所有地方使用 UTF-8 编码
- 使用中/日/韩（CJK）字符进行测试
- 使用表情符号（它们可以是 2-4 字节）
- 处理不同的脚本（拉丁文、西里尔文、阿拉伯文等）

**日期/时间格式**：
```javascript
// ✅ 使用 Intl API 进行正确格式化
new Intl.DateTimeFormat('en-US').format(date); // 1/15/2024
new Intl.DateTimeFormat('de-DE').format(date); // 15.1.2024

new Intl.NumberFormat('en-US', { 
  style: 'currency', 
  currency: 'USD' 
}).format(1234.56); // $1,234.56
```

**复数形式**：
```javascript
// ❌ 不好：假设英文复数形式
`${count} item${count !== 1 ? 's' : ''}`

// ✅ 好：使用正确的 i18n 库
t('items', { count }) // 处理复杂的复数规则
```

### 错误处理

**网络错误**：
- 显示清晰的错误消息
- 提供重试按钮
- 解释发生了什么
- 提供离线模式（如果适用）
- 处理超时场景

```jsx
// 错误状态带恢复
{error && (
  <ErrorMessage>
    <p>加载数据失败。{error.message}</p>
    <button onClick={retry}>重试</button>
  </ErrorMessage>
)}
```

**表单验证错误**：
- 在字段附近显示内联错误
- 显示清晰、具体的消息
- 提供建议的更正
- 不必要地阻止提交
- 在出错时保留用户输入

**API 错误**：
- 适当地处理每个状态码
  - 400：显示验证错误
  - 401：重定向到登录
  - 403：显示权限错误
  - 404：显示未找到状态
  - 429：显示速率限制消息
  - 500：显示通用错误，提供支持

**优雅降级**：
- 核心功能在没有 JavaScript 的情况下也能工作
- 图片有 alt 文本
- 渐进增强
- 不支持的特性的回退方案

### 边缘情况和边界条件

**空状态**：
- 列表中没有项目
- 没有搜索结果
- 没有通知
- 没有要显示的数据
- 提供清晰的下一步操作

**加载状态**：
- 初始加载
- 分页加载
- 刷新
- 显示正在加载的内容（“正在加载您的项目...”）
- 长操作的预估时间

**大数据集**：
- 分页或虚拟滚动
- 搜索/过滤功能
- 性能优化
- 不要一次性加载所有 10,000 个项目

**并发操作**：
- 防止重复提交（加载时禁用按钮）
- 处理竞争条件
- 乐观更新带回滚
- 冲突解决

**权限状态**：
- 没有查看权限
- 没有编辑权限
- 只读模式
- 清晰解释原因

**浏览器兼容性**：
- 现代特性的 polyfills
- 不支持的 CSS 的回退方案
- 功能检测（不是浏览器检测）
- 在目标浏览器中测试

### 引导和首次运行体验

生产就绪的功能不仅对高级用户有效，对新手用户也有效。设计引导新用户快速获得价值的路径：

**空状态**：每个零数据屏幕都需要：
- 这里会显示什么（描述或插图）
- 对用户的重要性
- 清晰的 CTA 创建第一个项目或从模板开始
- 视觉吸引力（不只是空白空间和“还没有项目”）

需要处理的空状态类型：
- **首次使用**：强调价值，提供模板
- **用户清除**：轻触，容易重新创建
- **没有结果**：建议不同查询，提供清除过滤器
- **没有权限**：解释原因，如何获取访问权限

**首次运行体验**：尽快让用户达到“啊哈时刻”。
- 展示，而不是说明——工作示例胜过描述
- 逐步披露——一次教一件事，而不是一开始就全部教
- 使引导可选——让有经验的用户可以跳过
- 提供智能默认值，使必要设置最小化

**功能发现**：在用户需要时教功能，而不是一开始就教。
- 使用点使用时的上下文工具提示（简短、可关闭、一次性）
- 新用或未使用功能的徽章或指示器
- 安静地庆祝激活事件（一个提示，而不是一个模态框）

**永远不要**：
- 在用户可以接触产品之前强制长时间引导
- 重复显示相同的工具提示（跟踪并尊重关闭）
- 在整个界面出错时阻塞整个 UI
- 创建与真实产品脱节的教学模式
- 设计只说“没有项目”而没有下一步操作的空状态

### 输入验证和净化

**客户端验证**：
- 必填字段
- 格式验证（电子邮件、电话、URL）
- 长度限制
- 模式匹配
- 自定义验证规则

**服务器端验证**（始终）：
- 不要只信任客户端
- 验证并净化所有输入
- 防止注入攻击
- 流量限制

**约束处理**：
```html
<!-- 设置清晰的约束 -->
<input 
  type="text"
  maxlength="100"
  pattern="[A-Za-z0-9]+"
  required
  aria-describedby="username-hint"
/>
<small id="username-hint">
  只允许字母和数字，最多 100 个字符
</small>
```

### 可访问性弹性

**键盘导航**：
- 所有功能都可以通过键盘访问
- 逻辑的 Tab 顺序
- 模态框中的焦点管理
- 长内容中的跳过链接

**屏幕阅读器支持**：
- 正确的 ARIA 标签
- 宣布动态变化（活区域）
- 描述性 alt 文本
- 语义 HTML

**运动敏感性**：
```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

**高对比度模式**：
- 在 Windows 高对比度模式下测试
- 不要只依赖颜色
- 提供替代视觉提示

### 性能弹性

**慢速连接**：
- 渐进式图片加载
- 骨架屏
- 乐观 UI 更新
- 离线支持（服务工作者）

**内存泄漏**：
- 清理事件监听器
- 取消订阅
- 清除计时器/间隔
- 在卸载时中止挂起的请求

**节流和防抖**：
```javascript
// 防抖搜索输入
const debouncedSearch = debounce(handleSearch, 300);

// 节流滚动处理
const throttledScroll = throttle(handleScroll, 100);
```

## 测试策略

**手动测试**：
- 使用极端数据（非常长、非常短、空）
- 使用不同语言测试
- 离线测试
- 测试慢速连接（节流到 3G）
- 使用屏幕阅读器测试
- 仅键盘导航测试
- 在旧浏览器上测试

**自动化测试**：
- 边缘情况的单元测试
- 错误场景的集成测试
- 关键路径的端到端测试
- 视觉回归测试
- 可访问性测试（axe, WAVE）

**重要**：强化意味着预期意外。真实用户会做你从未想到的事情。

**永远不要**：
- 假设完美输入（验证所有内容）
- 忽略国际化（为全球设计）
- 错误消息过于通用（“发生错误”）
- 忘记离线场景
- 单独信任客户端验证
- 为文本使用固定宽度
- 假设英文长度的文本
- 当一个组件出错时阻塞整个界面

## 验证强化

使用边缘情况彻底测试：

- **长文本**：尝试 100+ 个字符的姓名
- **表情符号**：在所有文本字段中使用表情符号
- **从右到左**：使用阿拉伯语或希伯来语测试
- **CJK**：使用中/日/韩测试
- **网络问题**：禁用互联网，节流连接
- **大数据集**：测试 1000+ 个项目
- **并发操作**：快速连续点击提交 10 次
- **错误**：强制 API 错误，测试所有错误状态
- **空**：删除所有数据，测试空状态

记住：你是在为生产现实进行强化，而不是为演示完美。预期用户会输入奇怪的数据，在操作过程中断开连接，并以意想不到的方式使用你的产品。将弹性构建到每个组件中。
