## 强制性准备工作

调用 `/impeccable` — 它包含设计原则、反模式以及**情境收集协议**。在进行下一步之前，请遵循该协议——如果尚未存在设计情境，你必须先运行 `/impeccable teach`。此外还需收集：质量标准（MVP 与旗舰版本）。

---

进行细致的最终检查，以捕捉所有区分优秀与卓越的小细节。这是从已发布到精炼完成的区别。

## 设计系统发现

在精炼之前，了解你正在精炼的目标系统：

1. **找到设计系统**：搜索设计系统文档、组件库、样式指南或符号定义。研究核心模式：颜色符号、间距比例、排版样式、组件 API。
2. **注意规范**：共享组件如何导入？使用什么间距比例？哪些颜色来自符号定义而非硬编码值？已建立哪些动效和交互模式？
3. **识别偏差**：目标功能在哪些方面偏离了系统？应使用符号定义的硬编码值、重复共享组件的自定义组件、与比例不匹配的间距。

如果存在设计系统，精炼应使功能与之对齐。如果不存在，则根据代码库中可见的规范进行精炼。

## 精炼前评估

了解当前状态和目标：

1. **审查完整性**：
   - 是否功能完整？
   - 是否有已知问题需要保留（用 TODO 标记）？
   - 质量标准是什么？（MVP 还是旗舰功能？）
   - 何时发布？（有多少时间用于精炼？）

2. **识别精炼区域**：
   - 视觉不一致性
   - 间距和对齐问题
   - 交互状态缺失
   - 文本不一致
   - 边缘案例和错误状态
   - 加载和过渡平滑度

**关键**：精炼是最后一步，而非第一步。不要精炼未完成功能的工作。

## 系统性精炼

按部就班地处理这些维度：

### 视觉对齐与间距

- **像素级对齐**：所有元素都与网格对齐
- **一致间距**：所有间隙使用间距比例（无随机 13px 间隙）
- **视觉对齐**：根据视觉重量调整（图标可能需要偏移以实现视觉居中）
- **响应式一致性**：间距和对齐在所有断点下均有效
- **网格遵循**：元素吸附到底线网格

**检查**：
- 启用网格覆盖层并验证对齐
- 使用浏览器检查器检查间距
- 在多个视口尺寸下测试
- 寻找感觉不对的元素

### 排版优化

- **层级一致性**：相同元素在整个界面使用相同的尺寸/权重
- **行长度**：正文文本 45-75 个字符
- **行高**：适合字体大小和上下文
- **孤字**：最后一行无单个词
- **连字符**：适合语言和列宽
- **字距调整**：根据需要调整字母间距（尤其是标题）
- **字体加载**：无 FOUT/FOIT 闪烁

### 颜色与对比度

- **对比度比例**：所有文本符合 WCAG 标准
- **符号一致性**：无硬编码颜色，所有颜色均使用设计符号
- **主题一致性**：适用于所有主题变体
- **颜色含义**：相同颜色在整个界面代表相同含义
- **可访问焦点**：焦点指示器具有足够的对比度
- **中性色调**：无纯灰色或纯黑色—添加细微颜色色调（0.01 色相）
- **颜色上的灰色**：不要将灰色文本放在彩色背景上—使用该颜色的阴影或透明度

### 交互状态

每个交互元素都需要所有状态：

- **默认**：静止状态
- **悬停**：微妙反馈（颜色、比例、阴影）
- **焦点**：键盘焦点指示器（移除时必须替换）
- **激活**：点击/轻触反馈
- **禁用**：明确非交互状态
- **加载**：异步操作反馈
- **错误**：验证或错误状态
- **成功**：成功完成

**缺失状态会导致混淆和糟糕的体验**。

### 微交互与过渡

- **平滑过渡**：所有状态变化均适当动画化（150-300ms）
- **一致缓动**：使用 ease-out-quart/quint/expo 实现自然减速。绝不使用弹跳或弹性效果——它们显得过时。
- **无卡顿**：60fps 动画，仅动画 transform 和 opacity
- **适当动效**：动效服务于目的，而非装饰
- **减少动效**：尊重 `prefers-reduced-motion`

### 内容与文本

- **术语一致性**：同一事物在整个界面使用相同名称
- **大小写一致性**：标题大小写与句子大小写应用一致
- **语法与拼写**：无错别字
- **适当长度**：不过于冗长，也不过于简短
- **标点一致性**：句子后加句号，标签后不加（除非所有标签都加）

### 图标与图片

- **风格一致性**：所有图标来自同一系列或匹配风格
- **适当尺寸**：图标根据上下文尺寸一致
- **正确对齐**：图标与相邻文本视觉对齐
- **替代文本**：所有图片均有描述性替代文本
- **加载状态**：图片不导致布局偏移，具有正确宽高比
- **高分辨率支持**：为高 DPI 屏幕提供 2x 资产

### 表单与输入

- **标签一致性**：所有输入均有正确标签
- **必填指示器**：清晰且一致
- **错误消息**：有帮助且一致
- **Tab 顺序**：逻辑键盘导航
- **自动聚焦**：适当（不要过度使用）
- **验证时机**：一致（失去焦点时或提交时）

### 边缘案例与错误状态

- **加载状态**：所有异步操作均有加载反馈
- **空状态**：有帮助的空状态，而非空白空间
- **错误状态**：清晰的错误消息与恢复路径
- **成功状态**：确认操作成功
- **长内容**：处理非常长的名称、描述等
- **无内容**：优雅处理缺失数据
- **离线**：适当离线处理（如适用）

### 响应式设计

- **所有断点**：测试手机、平板、桌面
- **触摸目标**：触摸设备最小 44x44px
- **可读文本**：手机上无小于 14px 的文本
- **无水平滚动**：内容适配视口
- **适当重排**：内容逻辑适应

### 性能

- **快速初始加载**：优化关键路径
- **无布局偏移**：加载后元素不跳转（CLS）
- **平滑交互**：无卡顿或卡顿
- **优化图片**：适当格式和尺寸
- **懒加载**：屏幕外内容懒加载

### 代码质量

- **移除控制台日志**：生产环境无调试日志
- **移除注释代码**：清理废弃代码
- **移除未使用导入**：清理未使用的依赖
- **命名一致性**：变量和函数遵循规范
- **类型安全**：无 TypeScript `any` 或忽略的错误
- **可访问性**：正确的 ARIA 标签和语义 HTML

## 精炼清单

按部就班地检查：

- [ ] 所有断点下视觉对齐完美
- [ ] 间距使用设计符号一致
- [ ] 排版层级一致
- [ ] 所有交互状态已实现
- [ ] 所有过渡平滑（60fps）
- [ ] 文本一致且精炼
- [ ] 图标一致且尺寸适当
- [ ] 所有表单均有标签和验证
- [ ] 错误状态有帮助
- [ ] 加载状态清晰
- [ ] 空状态友好
- [ ] 触摸目标最小 44x44px
- [ ] 对比度比例符合 WCAG AA
- [ ] 键盘导航正常
- [ ] 焦点指示器可见
- [ ] 无控制台错误或警告
- [ ] 加载时无布局偏移
- [ ] 在所有支持浏览器中正常工作
- [ ] 尊重减少动效偏好
- [ ] 代码干净（无 TODO、控制台日志、注释代码）

**重要**：精炼关乎细节。放大。眯眼观察。亲自使用。小细节累积成大影响。

**绝不**：
- 在功能未完成前精炼
- 如果 30 分钟内发布，花数小时精炼（优先级排序）
- 精炼时引入错误（彻底测试）
- 忽视系统性问题（如果所有间距都错，修复系统）
- 在一件事上完美，其他地方粗糙（保持一致质量水平）
- 存在设计系统等效组件时创建新的单次组件
- 硬编码应使用设计符号的值

## 最终验证

标记为完成前：

- **亲自使用**：实际交互功能
- **在真实设备上测试**：不只是浏览器开发者工具
- **请他人审查**：新鲜眼光能发现细节
- **与设计对比**：匹配预期设计
- **检查所有状态**：不只测试成功路径

## 清理

精炼后确保代码质量：

- **替换自定义实现**：如果设计系统提供组件而您重新实现，切换到共享版本。
- **移除废弃代码**：删除因精炼而不再使用的样式、组件或文件。
- **整合符号**：如果您引入了新值，检查是否应为符号。
- **验证 DRY 原则**：查找精炼期间引入的重复内容并整合。

记住：您具有无懈可击的细节关注力和精致品味。精炼直到感觉毫不费力，看起来有意为之，且完美运行。注重细节——它们很重要。
