## 强制准备工作

调用 /immacable — 它包含设计原则、反模式以及**上下文收集协议**。在继续之前，必须遵循该协议——如果目前尚无设计上下文，你必须先运行 /immacable teach。此外需收集：质量基准（MVP 与旗舰产品的对比）。

---

执行细致的最终检查，捕捉区分优质工作与卓越工作的所有细节。这是发布版本与精修版本的差别。

## 设计系统发现

在精修之前，先理解你正在为其精修的系统：

1. **查找设计系统**：搜索设计系统文档、组件库、样式指南或令牌定义。研究核心模式：颜色令牌、间距缩放、排版样式、组件 API。
2. **记录规范**：共享组件如何导入？使用何种间距缩放？哪些颜色来自令牌，哪些为硬编码值？已确立的动效与交互模式是什么？
3. **识别偏差**：目标功能在何处偏离了系统？应为令牌却使用硬编码值的情况，重复共享组件的自定义组件，间距与缩放不匹配的情况。

若存在设计系统，精修应使功能与其对齐；若不存在，则依据代码库中可见的规范进行精修。

## 精修前评估

理解当前状态与目标：

1. **审查完整性**：
   - 功能是否完整？
   - 是否存在需要保留的已知问题（需用 TODO 标记）？
   - 质量基准是什么？（MVP 还是旗舰功能？）
   - 何时发布？（精修有多少时间可用？）

2. **识别精修区域**：
   - 视觉不一致问题
   - 间距与对齐问题
   - 交互状态缺失
   - 文案不一致问题
   - 边界情况与错误状态
   - 加载与过渡平滑度问题

**关键**：精修是最后一步，而非第一步。不要对功能不完整的工作进行精修。

## 系统化精修

按以下维度逐一系统化推进：

### 视觉对齐与间距

- **像素级精准对齐**：所有元素对齐到网格
- **间距一致性**：所有间距均使用间距缩放（不使用随意的 13px 间距）
- **视觉权重对齐**：根据视觉权重进行调整（图标可能需要偏移以实现视觉居中）
- **响应式一致性**：间距与对齐在所有断点均正常
- **网格遵循性**：元素吸附到基线网格

**检查**：
- 开启网格覆盖层并验证对齐情况
- 使用浏览器检查器检查间距
- 在不同视口尺寸下测试
- 查找“感觉不对”的元素

### 排版精修

- **层级一致性**：相同元素在全文中使用相同的字号/字重
- **行长度**：正文字符数在 45-75 之间
- **行高**：与字号和场景相适应
- **孤行与孤立行**：末行不出现单个词
- **断行**：与语言和栏宽相适应
- **字间距调整**：在需要时调整字母间距（尤其是标题）
- **字体加载**：无 FOUT/FOIT 闪烁

### 颜色与对比度

- **对比度比例**：所有文本均符合 WCAG 标准
- **令牌使用一致性**：不使用硬编码颜色，全部使用设计令牌
- **主题一致性**：在所有主题变体中均正常
- **颜色含义**：全文中相同颜色含义相同
- **可访问焦点**：焦点指示器可见且对比度充足
- **带色调的中性色**：不使用纯灰或纯黑，添加细微颜色色调（0.01 色度）
- **彩色背景上的灰色文本**：切勿将灰色文本放在彩色背景上——使用该颜色的深浅色调或透明度

### 交互状态

每个交互元素都需要所有状态：

- **默认**：静止状态
- **悬停**：细微反馈（颜色、缩放、阴影）
- **焦点**：键盘焦点指示器（切勿在不替换的情况下移除）
- **激活**：点击/触摸反馈
- **禁用**：明确不可交互
- **加载**：异步操作反馈
- **错误**：校验或错误状态
- **成功**：操作完成

**缺失的状态会造成困惑与体验断裂**。

### 微交互与过渡

- **平滑过渡**：所有状态变化的动画设置合适（150-300ms）
- **一致的缓动**：使用 ease-out-quart/quint/expo 实现自然的减速效果。切勿使用弹跳或弹性效果——会显得过时
- **无卡顿**：动画为 60fps，仅动画 transform 与 opacity
- **适度动效**：动效服务目的，而非装饰
- **减少动效**：遵守 `prefers-reduced-motion`

### 内容与文案

- **术语一致性**：同一事物全程使用相同名称
- **大小写一致性**：标题式大小写与陈述式大小写应用一致
- **语法与拼写**：无错别字
- **长度适中**：不过于冗长，不过于简略
- **标点一致性**：句号加在句子上，而非标签上（除非所有标签均有句号）

### 图标与图片

- **风格一致**：所有图标来自同一系列或风格匹配
- **尺寸适当**：图标根据场景一致地设置尺寸
- **对齐正确**：图标与相邻文本实现视觉对齐
- **替代文本**：所有图片均有描述性替代文本
- **加载状态**：图片不导致布局偏移，宽高比正确
- **Retina 屏幕支持**：为高端 DPI 屏幕提供 2x 资源

### 表单与输入框

- **标签一致性**：所有输入框均正确标注
- **必填标识**：清晰且一致
- **错误信息**：有帮助且一致
- **标签顺序**：逻辑的键盘导航顺序
- **自动聚焦**：适度（勿过度使用）
- **校验时机**：一致（在失焦时与提交时均可，需保持一致）

### 边界情况与错误状态

- **加载状态**：所有异步操作均有加载反馈
- **空状态**：有帮助的空状态，而非仅空白区域
- **错误状态**：清晰的错误信息与恢复路径
- **成功状态**：操作成功的确认
- **长内容**：可处理非常长的名称、描述等
- **无内容**：优雅处理缺失数据的情况
- **离线**：适当的离线处理（如适用）

### 响应式适配

- **所有断点**：测试移动端、平板端与桌面端
- **触摸目标**：触摸设备上最小尺寸为 44x44px
- **文本可读性**：移动端无小于 14px 的文字
- **无横向滚动**：内容适配视口
- **合理重排**：内容逻辑自适应

### 性能优化

- **快速初始加载**：优化关键路径
- **无布局偏移**：加载后元素不跳变（CLS 无问题）
- **流畅交互**：无延迟或卡顿
- **优化图片**：格式与尺寸合适
- **懒加载**：屏外内容懒加载

### 代码质量

- **移除控制台日志**：生产环境中无调试日志
- **移除注释代码**：清理无用代码
- **移除未使用导入**：清理未使用的依赖
- **命名一致**：变量与函数遵循规范
- **类型安全**：无 TypeScript 中的 `any` 或忽略的错误
- **无障碍支持**：正确的 ARIA 标签与语义化 HTML

## 精修清单

系统逐一检查：

- [ ] 所有断点下视觉对齐完美
- [ ] 间距一致使用设计令牌
- [ ] 排版层级一致
- [ ] 所有交互状态均已实现
- [ ] 所有过渡平滑（60fps）
- [ ] 文案一致且精修
- [ ] 图标风格一致且尺寸合适
- [ ] 所有表单均正确标注与校验
- [ ] 错误状态有帮助
- [ ] 加载状态清晰
- [ ] 空状态友好
- [ ] 触摸目标最小尺寸为 44x44px
- [ ] 对比度比例符合 WCAG AA 标准
- [ ] 键盘导航正常
- [ ] 焦点指示器可见
- [ ] 无控制台错误或警告
- [ ] 加载时无布局偏移
- [ ] 支持所有支持的浏览器
- [ ] 遵守减少动效偏好
- [ ] 代码整洁（无 TODO、控制台日志、注释代码）

**重要**：精修在于细节。放大查看。眯眼检查。亲自使用。微小的细节会累积成显著成效。

**切勿**：
- 在功能完整前进行精修
- 若产品 30 分钟即可发布，却花数小时精修（需进行优先级排序处理）
- 精修时引入 bug（需充分测试）
- 忽略系统性问题（若所有地方间距都有误，需修正系统）
- 只精修某一处，而其余部分粗糙（保持质量水平一致）
- 当存在设计系统对应组件时，创建新的一次性组件
- 使用应使用设计令牌的值进行硬编码

## 最终验证

标记为完成之前：

- **亲自使用**：实际与功能进行交互
- **在真实设备测试**：不仅限于浏览器 DevTools
- **请他人审阅**：新鲜视角能发现遗漏之处
- **与设计对比**：与预期设计一致
- **检查所有状态**：不仅测试正常流程

## 清理

精修完成后，确保代码质量：

- **替换自定义实现**：若设计系统提供了你重新实现的相关组件，切换到共享版本。
- **移除孤立代码**：删除精修后不再使用的样式、组件或文件。
- **整合令牌**：若引入了新的值，检查其是否应作为令牌存在。
- **验证 DRY 原则**：查找精修过程中引入的重复，进行整合。

请记住：你具备无懈可击的细节关注力与精妙品味。持续精修，直到它流畅自然、设计有章、运行无瑕。打磨细节——细节至关重要。
