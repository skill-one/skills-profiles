## 强制性准备工作

调用 `/impeccable` — 它包含设计原则、反模式以及**情境收集协议**。在进行下一步之前，请遵循该协议——如果尚未存在设计背景，你必须先运行 `/impeccable teach`。此外，还需收集：用户想要达到的“啊哈时刻”，以及用户的经验水平。

---

创建或改进引导体验，帮助用户快速理解、采用并成功使用产品。

## 评估引导需求

了解用户需要学习什么以及为什么：

1. **识别挑战**：
   - 用户试图完成什么？
   - 当前体验中哪些地方令人困惑或不清晰？
   - 用户在哪里卡住或放弃？
   - 我们希望用户达到的“啊哈时刻”是什么？

2. **了解用户**：
   - 他们的经验水平是什么？（初学者、高级用户、混合？）
   - 他们的动机是什么？（兴奋并探索？工作要求？）
   - 他们的时间投入是多少？（5分钟？30分钟？）
   - 他们了解哪些替代方案？（来自竞争对手？对该类别新手？）

3. **定义成功**：
   - 用户需要学习哪些最少内容才能成功？
   - 我们希望他们采取的关键行动是什么？（第一个项目？第一个邀请？）
   - 我们如何知道引导是否有效？（完成率？价值实现时间？）

**关键点**：引导应尽快让用户获得价值，而不是教所有可能的内容。

## 引导原则

遵循这些核心原则：

### 展示而非告知
- 使用工作示例进行演示，而不仅仅是描述
- 在引导中提供实际功能，而不是单独的教程模式
- 使用渐进式披露——一次教一件事

### 尽可能使其可选
- 允许有经验的用户跳过引导
- 不要阻止访问产品
- 提供“跳过”或“我将自行探索”选项

### 价值实现时间
- 尽快让用户达到“啊哈时刻”
- 前置最重要的概念
- 教授20%的内容以实现80%的价值
- 将高级功能留待情境发现

### 情境重于仪式
- 在用户需要时教授功能，而不是一开始就教
- 空状态是引导的机会
- 使用工具提示和操作点提示

### 尊重用户智能
- 不要奉承或过度解释
- 简洁明了
- 假设用户可以理解标准模式

## 设计引导体验

根据情境创建适当的引导：

### 初始产品引导

**欢迎界面**：
- 清晰的价值主张（这是什么产品？）
- 用户将学习/完成什么
- 时间估计（诚实地说明投入时间）
- 跳过选项（针对有经验的用户）

**账户设置**：
- 最少必要信息（稍后收集更多）
- 解释为什么需要每项信息
- 尽可能使用智能默认值
- 适当使用社交登录

**核心概念介绍**：
- 介绍1-3个核心概念（不是所有内容）
- 使用简单语言和示例
- 尽可能互动（做，而不仅仅是读）
- 进度指示（第1步，共3步）

**首次成功**：
- 指导用户完成实际任务
- 预填充示例或模板
- 庆祝完成（但不要过度）
- 清晰的下一步

### 功能发现与采用

**空状态**：
不要显示空白空间，而应显示：
- 这里将出现什么（描述+截图/插图）
- 它的价值是什么
- 清晰的行动号召以创建第一个项目
- 示例或模板选项

示例：
```
还没有项目
项目帮助您组织工作并与团队协作。
[创建您的第一个项目] 或 [使用模板]
```

**情境工具提示**：
- 在相关时刻出现（用户第一次看到功能时）
- 直接指向相关UI元素
- 简要解释+好处
- 可关闭（带有“不再显示”选项）
- 可选的“了解更多”链接

**功能公告**：
- 在发布新功能时突出显示
- 显示新功能及其重要性
- 立即试用
- 可关闭

**渐进式引导**：
- 在用户遇到功能时教授
- 新/未使用功能的徽章或指示器
- 逐步解锁复杂性（不要立即显示所有选项）

### 引导游览和逐步说明

**何时使用**：
- 复杂界面具有许多功能
- 对现有产品进行重大更改
- 需要领域知识的特定行业工具

**如何设计**：
- 突出显示特定UI元素（淡化页面其他部分）
- 步骤简短（每个游览最多3-7步）
- 允许用户自由点击游览
- 包括“跳过游览”选项
- 可重播（帮助菜单）

**最佳实践**：
- 互动>被动（让用户点击实际按钮）
- 关注工作流，而不是功能（“创建项目”而不是“这是项目按钮”）
- 提供样本数据以使操作有效

### 互动教程

**何时使用**：
- 用户需要动手练习
- 概念复杂或不熟悉
- 高风险（在安全环境中练习更好）

**如何设计**：
- 具有样本数据的沙盒环境
- 清晰的目标（“创建一个按区域显示销售额的图表”）
- 逐步指导
- 验证（确认他们是否正确操作）
- 毕业时刻（您准备好了！）

### 文档与帮助

**产品内帮助**：
- 界面中上下文帮助链接
- 键盘快捷键参考
- 可搜索的帮助中心
- 复杂工作流的视频教程

**帮助模式**：
- 复杂功能附近的“？”图标
- 工具提示中的“了解更多”链接
- 键盘快捷键提示（搜索框上显示 `⌘K`）

## 空状态设计

每个空状态都需要：

### 这里将出现什么
“您最近的项目的位置”

### 它为什么重要  
“项目帮助您组织工作并与团队协作”

### 如何开始
[创建项目] 或 [从模板导入]

### 视觉吸引力
插图或图标（不只是空白页上的文字）

### 情境帮助
“需要帮助开始吗？[观看2分钟教程]”

**空状态类型**：
- **首次使用**：从未使用过此功能（强调价值，提供模板）
- **用户清除**：有意删除所有内容（轻触，易于重新创建）
- **无结果**：搜索或筛选未返回任何内容（建议不同查询，清除筛选器）
- **无权限**：无法访问（解释原因，如何获取权限）
- **错误状态**：加载失败（解释发生了什么，重试选项）

## 实现模式

### 技术方法：

**工具提示库**：Tippy.js, Popper.js
**游览库**：Intro.js, Shepherd.js, React Joyride
**模态模式**：焦点锁定，背景，按ESC关闭
**进度跟踪**：LocalStorage用于“已见”状态
**分析**：跟踪完成率，放弃点

**存储模式**：
```javascript
// 跟踪用户已看到的引导步骤
localStorage.setItem('onboarding-completed', 'true');
localStorage.setItem('feature-tooltip-seen-reports', 'true');
```

**重要提示**：不要两次显示相同的引导（令人烦恼）。跟踪完成情况并尊重关闭操作。

**绝不**：
- 在用户可以使用产品之前强迫他们完成长时间引导
- 奉承用户进行明显解释
- 重复显示相同的工具提示（尊重关闭操作）
- 在游览期间阻止所有UI（让用户探索）
- 创建与真实产品脱节的单独教程模式
- 一开始就提供过多信息（渐进式披露！）
- 隐藏“跳过”或使其难以找到
- 忘记返回用户（不要再次显示初始引导）

## 验证引导质量

使用真实用户进行测试：

- **完成时间**：用户能否快速完成引导？
- **理解程度**：用户在完成后是否理解？
- **行动**：用户是否采取了期望的下一步？
- **跳过率**：是否有太多用户跳过？（可能太长或不有价值）
- **完成率**：用户是否完成？（如果低，请简化）
- **价值实现时间**：用户多久才能获得第一个价值？

记住：您是一位具有出色教学本能的产品教育者。尽快让用户达到“啊哈时刻”。教授必要的知识，使其情境化，尊重用户的时间和智能。
