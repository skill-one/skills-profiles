## 强制准备工作

调用 `/inpeccable` — 它包含设计原则、反模式以及 **Context Gathering Protocol（情境收集协议）**。在继续之前，请遵循该协议 — 如果目前尚无设计语境，你必须先运行 `/inpeccable teach`。此外，还需收集以下内容：你想让用户达到的“aha 时刻”，以及用户的使用经验水平。

---

创建或优化引导体验，帮助用户快速理解、采用并成功使用产品。

## 评估引导需求

理解用户需要学习什么以及为何需要学习：

1. **Identify the challenge**：
   - 用户试图实现什么目标？
   - 当前体验中哪些内容令人困惑或不清晰？
   - 用户在哪些环节会卡住或流失？
   - 我们希望用户达到的“aha 时刻”是什么？

2. **Understand the users**：
   - 用户的经验水平如何？（新手、高级用户、混合用户？）
   - 用户为何使用？动机是什么？（充满热情地探索使用？因工作要求而使用？）
   - 用户愿意投入多长时间？（5 分钟？30 分钟？）
   - 用户了解哪些替代方案？（来自竞争对手？该领域的新用户？）

3. **Define success**：
   - 用户为实现成功，至少需要学习什么？
   - 我们希望用户采取的关键操作是什么？（首个项目？首次邀请？）
   - 如何判断引导是否有效？（完成率？达到价值的时间？）

**关键**：引导应尽快让用户获得价值，而不是尽可能多地传授一切内容。

## 引导原则

遵循以下核心原则：

### Show, Don't Tell
- 通过实际运行的示例来演示，而非仅靠描述
- 在引导中提供真实功能，而非单独的教程模式
- 采用渐进式展示——每次只教一件事

### Make It Optional (When Possible)
- 允许有经验的用户跳过引导
- 不要阻挡用户访问产品
- 提供“跳过”或“我自己探索”选项

### Time to Value
- 尽快让用户达到其“aha 时刻”
- 前置重要概念
- 教授能带来 80% 价值的 20% 内容
- 将高级功能留作在上下文中的发现

### Context Over Ceremony
- 在用户需要时教授功能，而非一开始就全部教授
- 空状态是引导机会
- 在用户使用过程中提供提示与提示信息

### Respect User Intelligence
- 不要取悦用户或过度解释
- 简洁清晰
- 假设用户能够理解常规模式

## 设计引导体验

创建适合当前语境的引导体验：

### 初始产品引导

**欢迎页面**：
- 清晰的價值主张（这是什么产品？）
- 用户将学习/完成什么
- 预计时间（如实说明所需投入）
- 跳过选项（供有经验用户使用）

**账户设置**：
- 所需的最少信息（后续再收集更多）
- 解释你为何询问每一部分信息
- 在可能时提供智能默认值
- 在合适时提供社交登录

**核心概念介绍**：
- 介绍 1 至 3 个核心概念（而非全部内容）
- 使用简单语言和示例
- 在可能时采用交互方式（实践，而非仅阅读）
- 进度提示（第 1/3 步）

**首次成功**：
- 引导用户完成真实的操作
- 预填示例或模板
- 庆祝完成（但不过度）
- 明确的下一步

### 功能发现与采用

**空状态**：
不要只显示空白区域，而是呈现：
- 此处将显示什么（说明 + 截图/插图）
- 为什么它有价值
- 创建首个内容的明确行动号召（CTA）
- 示例或模板选项

示例：
```
No projects yet
Projects help you organize your work and collaborate with your team.
[Create your first project] or [Start from template]
```

**上下文提示**：
- 在相关时机出现（首次看到该功能的用户）
- 直接指向相关的 UI 元素
- 简要说明 + 益处
- 可关闭（提供“不再显示”选项）
- 可选“了解更多”链接

**功能公告**：
- 新功能上线时进行高亮
- 展示新功能及其重要性
- 让用户立即尝试
- 可关闭

**渐进式引导**：
- 在用户遇到功能时教授功能
- 为新功能或未使用功能添加徽章或指示器
- 逐步解锁复杂度（不要立即展示所有选项）

### 引导游览与漫步引导

**何时使用**：
- 功能繁多的复杂界面
- 对现有产品进行重大变更
- 需要领域知识的行业专用工具

**设计方法**：
- 聚焦特定 UI 元素（其他页面元素变暗）
- 每个游览步骤尽量简短（每次最多 3-7 步）
- 允许用户自由点击完成游览
- 包含“跳过游览”选项
- 可重播（在帮助菜单中）

**最佳实践**：
- 交互优于被动展示（让用户点击真实按钮）
- 以工作流为核心，而非功能（如“创建项目”，而非“这是项目按钮”）
- 提供示例数据，使操作可用

### 交互式教程

**何时使用**：
- 用户需要进行动手练习
- 概念复杂或不熟悉
- 风险较高（最好在安全环境中练习）

**设计方法**：
- 提供带有示例数据的沙盒环境
- 明确目标（如“创建一张按地区显示销售的图表”）
- 分步骤引导
- 验证（确认操作正确）
- 毕业时刻（你已经准备就绪！）

### 文档与帮助

**产品内帮助**：
- 全界面语境化的帮助链接
- 快捷键参考
- 可搜索的帮助中心
- 复杂工作流的视频教程

**帮助模式**：
- 复杂功能附近显示 `?` 图标
- 提示中提供“了解更多”链接
- 在搜索框上显示快捷键提示（`⌘K`）

## 空状态设计

每个空状态都需要包含以下内容：

### 这里将显示什么
“你的最近项目将显示在此处”

### 它为何重要
“项目帮助你组织工作并与团队协作”

### 如何开始
[创建项目] 或 [从模板导入]

### 视觉吸引力
插图或图标（而非空白页面上的纯文本）

### 语境化帮助
“需要帮助开始使用吗？[观看 2 分钟教程]”

**空状态类型**：
- **首次使用**：从未使用过该功能（强调价值，提供模板）
- **用户清除**：用户有意删除了所有内容（保持轻量，易于重新创建）
- **无结果**：搜索或筛选未返回结果（建议不同的查询，清除筛选条件）
- **无权限**：无法访问（说明原因，以及如何获取权限）
- **错误状态**：加载失败（说明发生的情况，提供重试选项）

## 实现模式

### 技术方案：

**提示库**：Tippy.js, Popper.js
**游览库**：Intro.js, Shepherd.js, React Joyride
**弹窗模式**：焦点陷阱、背景遮罩、按 ESC 关闭
**进度追踪**：使用 LocalStorage 记录“已查看”状态
**分析**：追踪完成度和流失节点

**存储模式**：
```javascript
// 追踪用户已查看的引导步骤
localStorage.setItem('onboarding-completed', 'true');
localStorage.setItem('feature-tooltip-seen-reports', 'true');
```

**重要**：不要重复展示相同的引导流程（会令人厌烦）。追踪完成状态并尊重用户关闭行为。

**绝不**：
- 在用户仍无法使用产品之前，强制用户完成冗长的引导流程
- 用明显的解释取悦用户
- 反复显示相同提示（尊重关闭行为）
- 在游览时阻挡所有 UI（让用户自行探索）
- 创建与真实产品脱节的独立教程模式
- 一开始就因信息过多而让用户过载（渐进式展示！）
- 隐藏“跳过”按钮或使其难以找到
- 忘记回头客（不要再次展示初始引导）

## 验证引导质量

用真实用户进行测试：

- **完成时间**：用户能否快速完成引导？
- **理解程度**：用户完成后是否理解内容？
- **行动**：用户是否采取期望的下一步行动？
- **跳过率**：是否过多用户跳过？（可能内容过长或不具备价值）
- **完成率**：用户是否完成引导？（如果较低，需简化）
- **达到价值的时间**：用户多久能获得首次价值？

请记住：你是一位具备出色教学直觉的产品教育者。尽快让用户达到其“aha 时刻”。教授核心内容，使其具备情境性，尊重用户的时间和智能水平。
