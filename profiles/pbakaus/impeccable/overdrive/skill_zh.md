将界面推向传统极限之外。这不仅仅是关于视觉效果——它是在使用浏览器的全部功能，让界面的任何部分都感觉非凡：一个能处理百万行数据的表格，一个从触发器变形的对话框，一个能实时验证并带有流式反馈的表单，一个具有电影感的页面过渡。

## 必须的准备

调用 /impeccable — 它包含设计原则、反模式和**情境收集协议**。在继续之前，请遵循该协议——如果还没有设计背景，你必须先运行 /impeccable teach。

**对这个技能特别重要**：情境决定“非凡”的含义。在一个创意作品集中的粒子系统令人印象深刻。在设置页面上使用相同的粒子系统则令人尴尬。但带有即时乐观保存和动画状态转换的设置页面？那也是非凡的。在决定什么是恰当之前，了解项目的个性和目标。

### 在构建之前提出建议

这个技能最容易出问题。不要直接跳到实现。你必须：

1. **思考2-3种不同的方向** — 考虑不同的技术、雄心程度和美学方法。对于每个方向，简要描述结果将看起来和感觉如何。
2. **直接询问用户澄清你不能推断的内容**。在编写任何代码之前，展示这些方向并获取用户的挑选。解释权衡（浏览器支持、性能成本、复杂性）。
3. 只进行用户确认的方向。

跳过这一步的风险是构建一个令人尴尬的、需要被扔掉的东西。

### 使用浏览器自动化进行迭代

技术上雄心勃勃的效果几乎从未一次成功。你必须积极使用浏览器自动化工具来预览你的工作，视觉验证结果并进行迭代。不要假设效果看起来是正确的——检查它。期待多轮细化。“技术上可行”和“看起来非凡”之间的差距是通过视觉迭代，而不仅仅是代码来弥补的。

## 评估这里的“非凡”是什么意思

正确的技术雄心完全取决于你在做什么。在选择技术之前，问：**什么会让这个特定界面的用户说“哇，那很棒”？**

### 对于视觉/营销表面
页面、英雄区域、着陆页、作品集——这里的“哇”通常是感官上的：滚动驱动的揭示、着色器背景、电影感的页面过渡、响应光标的生成艺术。

### 对于功能UI
表格、表单、对话框、导航——这里的“哇”在于感觉：一个通过视图转换从触发按钮变形的对话框，一个通过虚拟滚动以60fps渲染10万行数据的表格，一个带有流式验证感觉即时的表单，带有弹簧物理学的拖放。

### 对于性能关键UI
“哇”是看不见但能感受到的：一个过滤5万项而不闪烁的搜索，一个永远不会阻塞主线程的复杂表单，一个以近乎实时处理图像编辑器。界面永远不会犹豫。

### 对于数据密集型界面
图表和仪表板——这里的“哇”在于流畅性：通过Canvas/WebGL为大型数据集进行GPU加速渲染，在数据状态之间进行动画过渡，自然稳定的力导向图布局。

**共同点**：实现方面的某些内容超出了用户对网页界面的预期。技术服务于体验，而不是反过来。

## 工具包

按你试图实现的目标组织，而不是按技术名称。

### 让过渡感觉像电影
- **视图转换API**（同文档：所有浏览器；跨文档：Firefox不支持）——共享元素在状态之间变形。一个列表项扩展成一个详情页。一个按钮变形成一个对话框。这是最接近原生FLIP动画的东西。
- **`@starting-style`**（所有浏览器）——仅用CSS从`display: none`到可见元素进行动画，包括进入关键帧
- **弹簧物理**——具有质量、张力和阻尼的自然运动，而不是cubic-bezier。库：motion（前身为Framer Motion）、GSAP，或者自己编写弹簧求解器。

### 将动画与滚动位置关联
- **滚动驱动的动画**（`animation-timeline: scroll()`）——纯CSS，无需JS。视差、进度条、揭示序列全部由滚动位置驱动。（Chrome/Edge/Safari；Firefox：仅标志——始终提供静态备用方案）

### 超越CSS进行渲染
- **WebGL**（所有浏览器）——着色器效果、后期处理、粒子系统。库：Three.js、OGL（轻量级）、regl。用于CSS无法表达的效果。
- **WebGPU**（Chrome/Edge；Safari部分支持；Firefox：仅标志）——下一代GPU计算。比WebGL更强大，但浏览器支持有限。始终回退到WebGL2。
- **Canvas 2D / OffscreenCanvas**——自定义渲染、像素操作，或完全通过Web Workers + OffscreenCanvas将重渲染移到主线程之外。
- **SVG滤镜链**——位移图、湍流、形态学用于有机扭曲效果。CSS可动画。

### 让数据感觉生动
- **虚拟滚动**——为具有数万项的表格/列表仅渲染可见行。简单情况下无需库；TanStack Virtual用于复杂情况。
- **GPU加速图表**——Canvas或WebGL渲染的数据可视化，用于数据集太大无法使用SVG/DOM的情况。库：deck.gl，基于regl的自定义渲染器。
- **动画数据过渡**——在图表状态之间变形，而不是替换。D3的`transition()`或视图转换用于基于DOM的图表。

### 动画复杂属性
- **`@property`**（所有浏览器）——注册具有类型的自定义CSS属性，使CSS无法通常插值的渐变、颜色和复杂数值能够进行动画。
- **Web动画API**（所有浏览器）——具有CSS性能的JavaScript驱动动画。可组合、可取消、可逆。复杂编排的基础。

### 推动性能边界
- **Web Workers**——将计算移到主线程之外。大量数据处理、图像操作、搜索索引——任何会导致卡顿的东西。
- **OffscreenCanvas**——在Worker线程中渲染。主线程保持空闲，而复杂的视觉效果在后台渲染。
- **WASM**——对于计算密集型功能具有接近原生的性能。图像处理、物理模拟、编解码器。

### 与设备交互
- **Web音频API**——空间音频、音频反应式可视化、声音反馈。需要用户手势才能启动。
- **设备API**——方向、环境光、地理位置。要谨慎使用，并且始终需要用户许可。

**注意**：这个技能是关于增强界面感觉，而不是改变产品做什么。添加实时协作、离线支持或新的后端功能是产品决策，而不是UI增强。专注于让现有功能感觉非凡。

## 带有纪律地实现

### 渐进增强是不可协商的

每种技术都必须优雅地降级。没有增强的体验也必须仍然良好。

```css
@supports (animation-timeline: scroll()) {
  .hero { animation-timeline: scroll(); }
}
```

```javascript
if ('gpu' in navigator) { /* WebGPU */ }
else if (canvas.getContext('webgl2')) { /* WebGL2回退 */ }
/* CSS回退仍然必须看起来很好 */
```

### 性能规则

- 目标是60fps。如果低于50，请简化。
- 尊重`prefers-reduced-motion`——始终。提供一个美丽的静态替代方案。
- 仅在靠近视口时才延迟初始化重型资源（WebGL上下文、WASM模块）。
- 暂停离屏渲染。杀死你无法看到的东西。
- 在真实的中间设备上测试，而不仅仅是你的开发机器。

### 精细是关键

“酷”和“非凡”之间的差距在于最后20%的细化：弹簧动画的缓动曲线、交错揭示的时机偏移、使过渡感觉物理的微妙次要运动。不要发布第一个能工作的版本——发布感觉不可避免的版本。

**永远不要**：
- 忽略`prefers-reduced-motion`——这是一个无障碍性要求，而不是建议
- 发布在中间设备上会导致卡顿的效果
- 没有功能回退就使用前沿API
- 添加声音而没有明确用户选择入
- 使用技术雄心来掩盖薄弱的设计基础——首先用其他技能修复这些
- 堆叠多个竞争的非凡时刻——专注创造冲击力，过多创造噪音

## 验证结果

- **“哇”测试**：展示给一个没见过的人。他们会反应吗？
- **移除测试**：拿走它。体验感觉是否减弱，或者没人注意到？
- **设备测试**：在手机、平板电脑、Chromebook上运行。仍然流畅吗？
- **无障碍性测试**：启用减少运动。仍然美丽吗？
- **情境测试**：这对这个品牌和受众来说是否有意义？

记住：“技术上非凡”不是关于使用最新的API。它是关于让界面做一些用户认为网站不可能做的事情。
