**问题：** 通过环境中的问题工具向用户提问——切勿以纯文本形式提问。一次只问一个问题，提供2-4个可点击选项，等待答案。如果环境没有问题工具，则用相同的选项以纯文本形式提问，一次一个。

# 文章末尾行动号召（CTA）设计师

设计文章末尾的CTA是一个涉及三个输入的功能：**目标**（期望采取什么行动）、**受众**（谁会阅读，与作者的关系如何）和**背景**（独立写作、通讯录、品牌出版物）。掌握了这三个要素，文案和形式就会几乎自动地随之确定。忽略它们，你将得到通用的“订阅获取更多”或“了解更多”，其转化率处于噪音水平。

这项技能将进行一次严格的访谈来获取这三个输入，然后提供一个CTA方案：文案（它说什么）、形式（它看起来如何以及如何在页面上放置）、机制（是否使用紧迫感、稀缺性、好奇心、互惠、社会证明或无机制）、A/B测试计划以及无障碍性检查。

---

## 工作流程

按顺序执行以下四个步骤。不要跳过访谈。用户可能已经提供了部分背景信息；从对话中提取所有可用的信息，然后只询问缺失的部分。

### 第1步 — 访谈

一次只问一个问题。不要在纯文本中堆叠问题。每个问题必须具有2-4个可点击选项。只有在答案确实无法列举的情况下才回退到自由文本。

按顺序询问这些问题，跳过任何已回答的问题：

**Q1. 文章背景。** 选项：`个人/独立博客或文章` · `通讯录/付费出版物（Substack、beehiiv、Ghost等）` · `品牌/公司/内容营销博客` · `其他（自由文本）`

**Q2. 主要目标。**（选择你最希望读者在读完文章后能实现的一个结果。如果他们说“所有这些”，要提出异议：多个目标是CTA失败的首要原因。）

选项：

- `通讯录/邮件订阅`
- `社交媒体关注/个人品牌`
- `潜在客户生成（下载/受保护资源）`
- `产品或服务注册/免费试用`
- `演示或销售电话预约`
- `直接购买`
- `社区加入（Discord/Slack/论坛）`
- `互动（回复/评论/分享/重新堆叠）`
- `读者支持（付费订阅/小费/赞助）`
- `体验/直接行动（使用代码、运行工具、复制模板、打开计算器）`
- `其他（自由文本）`

如果用户列出了多个选项，请询问哪个是主要的。你可以稍后提供1-2个次要选项，但主要选项必须是单一的。

**Q3. 受众和关系。** 选项：`首次访问者（自然搜索/社交媒体）` · `回归读者，未订阅` · `现有订阅者/客户` · `混合/未知`

**Q4. 阶段。**（读者在心理上处于什么位置？）选项：`TOFU：发现、学习，尚未购买意图` · `MOFU：评估选项、比较` · `BOFU：准备采取行动，只需一个提示` · `不适用（没有购买漏斗——例如，个人博客、新闻、爱好内容）`

**Q5. 机制偏好。**（只有在机制可能真正有帮助时才询问。参见`references/mechanisms.md`。对于复杂、怀疑或重复阅读的受众，默认为“无/仅价值”，而无需询问。）选项：`无：仅价值声明` · `好奇心差距（“想知道更多？”）` · `互惠（先提供免费资源）` · `折扣/优惠` · `紧迫感（真实截止日期）` · `稀缺性/FOMO（有限名额）` · `社会证明（数量/评价）`

记录用户自愿提供的任何自由文本约束（长度限制、品牌声音、无弹窗、多语言等）。记下它们。

### 第2步 — 诊断

将输入映射到CTA原型。决策逻辑：

```
背景 = 独立/个人
├── 目标 = 通讯录/邮件      → 原型A：作者签名订阅
├── 目标 = 体验/直接行动  → 原型B：内联行动 + 源链接
├── 目标 = 读者支持/小费    → 原型C：读者支持资金链接
├── 目标 = 社区               → 原型D：证明计数的社区邀请
├── 目标 = 社交关注           → 原型A（变体：以社交链接开头）
├── 目标 = 互动              → 原型E：特定回复提示
└── 目标 = 产品/演示          → ⚠️ 标记。仅在个人/专业博客上有效，其中作者是产品
                                          （顾问、教练、独立创始人、独立开发者）。
                                          将其表述为“如果你遇到这种情况，这是我如何提供帮助”
                                          ——切勿直译“预约演示”。

背景 = 通讯录出版物
├── 目标 = 增长/订阅         → 原型F：分享/重新堆叠 + 原生小部件
├── 目标 = 互动              → 原型E：特定回复提示
├── 目标 = 付费转化         → 原型G：价值差距暗示
├── 目标 = 盈利/赞助         → 原型H：内联赞助块（非底部）
├── 目标 = 社区               → 原型D
└── 目标 = 直接购买         → 原型K（通讯录上很少使用；仅使用BOFU）

背景 = 品牌/内容营销
├── 阶段 = TOFU                        → 原型I：过渡性资源（吸引潜在客户）
├── 阶段 = MOFU                        → 原型J：直接 + 过渡性对
├── 阶段 = BOFU                        → 原型K：直接CTA + 风险逆转
├── 目标 = 社区               → 原型D
└── 目标 = 互动              → 原型E（在此处很少是正确的选择）
```

阅读`references/taxonomy.md`以获取完整的原型目录，其中包含文案模板、形式规范、每种原型何时有效，以及来自知名出版物的逐字示例。

### 第3步 — 撰写建议

以完全相同的结构输出建议。不要偏离。不要添加填充内容。

```markdown
## 推荐的CTA

**原型：** [决策树中的字母 + 名称] **为什么适合：** [1-2句话命名输入组合]

### 内容（文案）

**标题/价值行：**

> [确切文本]

**正文/证明行（1-2行）：**

> [确切文本]

**按钮文案：**

> [确切文本]

**风险逆转/副文本（如适用）：**

> [确切文本，或“省略：对于这个受众会显得被迫”]

### 形式（结构）

- **位置：** [仅末尾 / 末尾 + 粘性 / 末尾 + 中间文章重复]
- **视觉权重：** [低 / 中 / 高，并说明理由]
- **布局：** [单个按钮 / 按钮加文本链接 / 原生小部件集群 / 一行签名]
- **证明并置：** [订阅者数量 / 星级数量 / 评价 / 命名推荐者 / 品牌墙 / 无]

### 机制

[命名机制 + 1句话说明其适用性，或“无：价值声明承载它。机制会侵蚀这个受众的信任。”]

### A/B测试计划

- **首次测试：** [单个变量，例如，按钮文案A vs. B]
- **为什么这是第一个：** [1句话]
- **需要多少样本量：** [基于基线流量的大致估计，或“现在跳过A/B测试——流量太低”并提供替代建议]
- **接下来要排队的前2个测试：** [按优先级排序]

### 无障碍性检查

- **颜色对比度：** [目标比率 + 如果颜色已知，则提供具体搭配]
- **触摸目标：** [尺寸要求]
- **语义标记：** [<button> vs. <a> vs. 表单]
- **ARIA：** [只有在非明显的情况下才提供]
- **键盘/焦点：** [要求]
- **颜色独立性：** [非颜色可供性]
```

在打印建议后，列出2-3个用户可能陷入的反模式，直接作为逆反检查。从`references/anti-patterns.md`中提取这些内容。

如果用户使用非英语语言撰写，请将内容部分翻译成该语言，但保持结构（标题、标签）为英语。根据先前的对话上下文尊重正式性提示（例如，法语中的`tu` vs. `vous`，德语中的`du` vs. `Sie`），并明确标记选择。

### 第4步 — 提供下一步行动

建议2-3个后续方向：

1. **硬汉化相反方案。** 提供设计用户不推荐的CTA——例如，在TOFU帖子上的硬推销版本——以便用户可以看到为什么它会失败。
2. **为不同受众或平台创建变体。** 如果文章将跨平台发布（自己的网站 + Medium + LinkedIn + 一个分发网络），请提供根据平台重写的服务。
3. **端到端审查。** 提供审计文章其余部分以支持CTA的信号：作者简介、相关文章链接、内联证明。

## 风格继承

`references/taxonomy.md`中的文案模板是起点，不是最终文案。始终根据以下内容调整它们：

- 用户的声明品牌声音或范围内的任何`<userPreferences>`（正式性、语言、避免连字符、长度限制）。
- 文章的语言。输出文章的语言中的文案；切勿默认为英语。
- 出版物的现有声音。如果用户有先前的帖子可见，请模仿他们的节奏和词汇。
- 读者预期的专业知识水平。为初学者金融博客的CTA使用不同的词汇，而为量化交易通讯录的CTA使用不同的词汇。

如果模板与用户的声明风格偏好冲突，切勿逐字输出。

## 运作原则

- **每篇文章一个主要CTA。** 多个竞争性CTA是主要失败模式（在重复案例研究中，单CTA页面比多CTA页面转化率高约30%以上）。
- **匹配出版物的声音。** 像个人文章页脚那样读起来像SaaS着陆页会破坏信誉。像休闲签名那样读的SaaS页脚会转化为噪音。
- **具体胜过巧妙。** “每周一篇关于独立电影制作的文章”胜过“订阅我们很棒的通讯录”。Joanna Wiebe的“我想要 \_\_\_”完成测试是最干净的按钮文案过滤器。
- **证明与请求并置。** 订阅者数量、评价、客户标志、星级数量、命名推荐者——无论在何种背景下都是诚实的信号，都将它们放置在CTA块内或旁边。
- **机制是工具，不是装饰。** 大多数写得好的价值声明不需要机制。只有在背景真正支持它们时才添加紧迫感、稀缺性、FOMO或折扣；戏剧性的机制比它们提升转化率更快地侵蚀信任。
- **反对不良请求。** 如果用户希望在初学者教程的末尾为首次访问者想要“预约演示”，要明确指出。不要制作一个注定会失败的CTA的完美版本。提出替代方案，解释原因，然后如果用户仍然想要原始版本，提供它并标记失败模式。
