# Substack 代笔与内容优化

一种用于撰写 Substack 内容的技能——包括订阅邮件（以邮件优先）和网页文章（以网页优先的文章/论文）——该技能能够增加订阅者并促使读者转化。它处理两种语音模式（自己的声音、代笔）和两种格式模式（订阅邮件、网页文章）。

## 核心理念

Substack 不是一个带有邮件列表的博客。它是一种社交媒体-订阅混合体，其算法优化的是订阅量，而不是参与度。这改变了你在该平台上撰写、格式化和分发内容的方方面面。

算法的激励措施确实与质量相一致。Substack 的收入来自订阅分成（而不是广告），因此操纵参与度指标没有帮助。有帮助的是：撰写足够好的内容，让读者转化为付费订阅者并向他人推荐你。

对于代笔来说：这份工作的目的是捕捉某人的现有见解，并以他们的声音表达，而不是从零开始产生见解。正如 Nicolas Cole 所描述的那样：客户是“见解丰富但时间匮乏”，而作者是“时间丰富但见解匮乏”。艺术在于提取和声音匹配。

## 模式检测

确定两个维度：

**语音维度：**

- **自己的声音**——用户以自己的名义撰写/发布。直接进入写作工作流程。
- **代笔**——以他人的声音撰写，或为客户准备内容。首先完成代笔工作流程，然后完成写作工作流程。

**格式维度：**

- **订阅邮件**（以邮件优先）——发送到订阅者的收件箱。主题行和邮件格式最重要。在第三阶段阅读 `references/email-formatting.md`。
- **网页文章**（以网页优先）——作为 Substack 文章/论文发布，可通过搜索和 Substack 的信息流发现。SEO 和网页格式最重要。在第三阶段阅读 `references/web-post-formatting.md`。

如果不确定，询问用户。当用户说“订阅邮件”或“邮件”时，默认为订阅邮件；当用户说“文章”、“论文”、“帖子”或“常青内容”时，默认为网页文章。

## 代笔工作流程

为他人撰写时，声音匹配优先于内容。阅读 `references/voice-matching.md` 了解完整的提取过程——它涵盖了样本收集（转录稿 > 撰写 > 媒体）、声音标记提取、构建声音指南（10-15 个标记附带示例）以及与用户的迭代。

在进入写作工作流程之前，完成声音指南并获得用户验证。

## 写作工作流程

**第一阶段是强制性的——始终在撰写任何内容之前向用户询问摄入问题并等待答案。**如果用户已经提供了一些背景信息，提取你能提取的内容，并仅询问缺失的部分。

### 第一阶段：声音校准（自己的声音模式）

如果代笔（代笔工作流程单独处理声音），则跳过此阶段。

向用户询问他们的 **现有的 Substack URL**。如果他们有，最近的帖子是获取语气标记的宝贵来源——正式程度、句子节奏、幽默风格、段落长度、他们如何开头和结尾、重复的短语。用 5-7 个要点总结声音，并在撰写前与用户确认。

如果他们没有现有的 Substack，询问：“你希望听起来是什么样子？随意且对话式、专业且权威，或其它？”使用他们的答案以及他们可以分享的任何其他写作样本。

### 第一阶段：内容规划（访谈）

**停止并询问。**向用户展示以下摄入问题，并等待他们的答案。不要跳过此阶段，不要默默推断，并且在获得明确的答案或确认之前不要开始起草。

1. **主题**：这是关于什么的？如果模糊，询问读者应该具体了解什么角度或故事。
2. **格式**：订阅邮件（以邮件优先）或网页文章（以网页优先）？见模式检测部分。
3. **受众**：谁会阅读这篇？(开发者、创始人、营销人员、一般技术、细分社区...) 为初级开发者准备的订阅邮件与为 CTO 准备的订阅邮件差异很大。
4. **目标**：具体目标是什么？
   - 增加免费或付费订阅者？
   - 驱动到外部产品（SaaS、课程、工具）的注册/流量？
   - 建立权威性/思想领导力？
   - 引导现有订阅者转向付费层级？
   - 其他？目标塑造了 CTA、钩子角度，以及深度内容与付费墙或链接的位置。
5. **背景**：系列的一部分吗？最近帖子涵盖了什么？
6. **长度**：简短（500-800 字）、标准（1000-1500）、深入（2000+）

如果关键部分缺失（尤其是主题、受众、目标或格式），**询问并等待**——不要猜测。错误的假设会浪费整个草稿。

如果用户有 Notes 数据（Notes 获得了参与度），使用它来验证主题选择。Notes 充当长期内容的廉价测试管道。

### 第二阶段：标题和钩子选择

生成 **5 个标题/主题行变体**和 **3 个钩子选项**（每个钩子开头 2-3 句话）。将它们一起呈现，并**要求用户选择或重新组合后再继续**。在用户验证标题和钩子方向之前，不要撰写正文。

**标题原则：**

- 具体性胜于模糊性
- 承诺明确的利益或揭示
- 6-10 个字（在手机上和搜索结果中可读）
- 对于开发者受众：技术关键词筛选正确的受众；“如何”和数字表现良好；避免紧迫性/稀缺性策略

**钩子类型**——使用不同的策略（例如，可信度、反叙事、好奇心、惊喜、数据）撰写 3 个不同的钩子。每个钩子应该是 2-3 句话，可以作为文章的开头。将它们标记为（钩子 A、钩子 B、钩子 C），并附带简短说明所使用的策略。

**订阅邮件——主题行 + 预览文本：**

- 主题行是标题。预览文本（邮件的前 ~90 个字符）是副标题。它们一起决定打开率。
- 预览文本应该补充，而不是重复主题行。

**网页文章——SEO + 可发现性：**

- 保持主标题简洁有力，用于信息流。使用单独的 **SEO 标题**字段用于关键词丰富的版本（少于 60 个字符）。
- 撰写专门的 **SEO 描述**（150-160 个字符）——不要依赖副标题的默认值，它通常太短。
- 建议一个 **URL 段落**：简短（3-6 个词）、关键词丰富、无日期。
- 如果适用，分配到一个出版物部分。
- 阅读 `references/web-post-formatting.md` 了解详细的 SEO 指导。

**等待用户选择**一个标题和钩子，然后进入第三阶段。

### 第三阶段：撰写内容

使用选定的标题和钩子，撰写完整的内容。钩子作为文章的开头，然后继续：

1. **钩子**（来自第二阶段）
2. **背景**（1-2 段话）：为什么现在很重要。是什么促使了这篇文章。
3. **正文**（主体）：实际内容。结构取决于内容类型。
4. **要点**（1-2 句话）：读者应该记住的一件事。
5. **行动号召**（1-2 句话）：要求采取具体行动。邀请回复的问题最强（回复是算法信号）。

**订阅邮件格式**——阅读 `references/email-formatting.md` 了解完整规则：

- 段落：最多 2-3 句话（邮件客户端使长段落看起来像墙壁）
- 代码块：< 10 行（长代码链接到 Gist）
- 图片：有节制地（许多邮件客户端默认阻止图片）
- TL;DR 在顶部，用于超过 1500 字的订阅邮件

**网页文章格式**——阅读 `references/web-post-formatting.md` 了解完整规则：

- 段落：3-4 句话可以接受（全宽网页渲染更宽容）
- 较长的代码块可以接受（最多 30-40 行，带完整语法高亮）
- 图片和嵌入可靠地显示——更自由地使用（图表、截图）
- 对于超过 2000 字的文章，添加目录

**共享格式规则：**

- 每 200-400 字一个副标题。粗体关键短语，以便快速浏览者抓住论点。
- 链接的描述性锚文本，而不是“点击这里。”

### 第四阶段：增长优化的元素

添加利用 Substack 算法的元素。阅读 `references/substack-algorithm.md` 了解完整的机制。

1. **回复提示**：以一个真诚的问题结束。回复会给算法发送参与度信号。
2. **分享提示**：“如果你觉得这篇文章有用，转发给一个符合[具体情况]的同事。”具体性会增加分享率。
3. **推荐钩子**：如果用户有推荐合作伙伴关系，自然地加入交叉引用。
4. **Notes 提示**：为 Substack Notes 撰写 2-3 句话的版本。Notes 应该作为有价值的内容独立存在，而不仅仅是指向问题的链接。

### 第五阶段：付费与免费策略

如果用户有付费层级，建议免费/付费分割：

- 免费订阅邮件应该是你最好的作品（它们推动增长和推荐）
- 付费订阅邮件应该提供深度、独家性或访问权限（不仅仅是正常内容的付费墙）
- 最有效的模式：免费订阅邮件展示的价值足够清晰，以至于读者想要更多

常见错误：过早付费。在 < 1000 订阅者的情况下，一切都应该是免费的。在小规模下，增长比付费转化更快。

### 第五阶段 b：人性化

调用一个人性化技能（例如，“人性化”、“humanizer”、“de-slop”、“自然写作检查”、“AI 检测清理”、“像人类一样重写”）来剥离 AI 生成的模式——填充词、可预测的节奏、过度规避、空洞的过渡、膨胀的语言。Substack 读者为真实的声音付费；AI 听起来像散文会破坏信任并取消订阅。

**保留钩子和主题行。**钩子和标题/主题行（第二阶段）是故意设计的，用于提高打开率和好奇心。指示人性化技能保留它们——为“自然性”重写它们会破坏驱动打开率和第一滚动保留的文案结构。

### 第六阶段：图片建议

在内容草稿完成后，建议 **1-3 张图片**并指定具体位置。对于每张图片，提供：

- **位置**：在订阅邮件中的位置（例如，“作为封面图片”、“在钩子之后”、“在 X 和 Y 部分之间”）
- **目的**：图片添加了什么（设定语气、打断长段落、说明概念、强化情感节奏）
- **描述**：图片应该描绘什么

对于订阅邮件：有节制地使用图片——许多邮件客户端默认阻止图片。优先考虑一个强大的封面图片，最多 1-2 个内联图片。对于网页文章：图片可靠地显示——更自由地使用（图表、截图）。

提供为每张建议的图片生成 **Midjourney 提示**。如果用户接受，使用最新的 Midjourney 模型约定来编写提示。

- 使用 `--ar 16:9` 或 `--ar 3:1` 用于封面图片和宽插图（Substack 标头和社交分享的最佳比例），`--ar 3:2` 用于较小的内联图片。
- 参考 Midjourney 的最新文档了解当前的提示语法和参数。

### 第七阶段：社交分发帖子（可选——提供，不要自动生成）

在内容撰写完成后，**询问用户是否需要社交分发帖子**。不要自动生成它们。

- 如果接受，撰写一个 **LinkedIn 帖子**和/或一个 **Twitter/X 帖子**来推广它。
- 这些不是摘要——它们是独立的、足够引起好奇心或价值的内容，以驱动点击的帖子。

阅读 `references/social-distribution.md` 了解 LinkedIn 和 Twitter/X 帖子模板。

## 输出格式

**订阅邮件：**

- 主题行（选定）+ 2 个替代方案
- 预览文本
- 全部订阅邮件在 markdown 中，格式化为邮件可读性
- 图片建议与位置说明（如果接受，则附带 Midjourney 提示）
- 一个 Notes 提示（2-3 句话）
- LinkedIn + Twitter/X 分发帖子（仅当用户接受时）
- 如果代笔：使用的声音指南

**网页文章：**

- 标题（选定）+ 2 个替代方案
- 副标题/元描述
- 建议的 URL 段落
- 全部文章在 markdown 中，格式化为网页可读性
- 图片建议与位置说明（如果接受，则附带 Midjourney 提示）
- 一个 Notes 提示（2-3 句话）
- LinkedIn + Twitter/X 分发帖子（仅当用户接受时）
- 如果代笔：使用的声音指南

## 调整现有内容

当用户希望将博客文章、谈话或线程转换为 Substack 内容时：

1. **选择正确的格式。** 常青源材料（参考、教程、深入探讨）→ 网页文章。及时源（评论、公告、反应）→ 订阅邮件。
2. **不要只是复制粘贴。** Substack 读者期望的声音和格式与博客读者不同。
3. **添加个人化元素。** Substack 比博客更个人化。添加背景：为什么分享这个，是什么促使了它，你的看法。
4. **提前加载价值。** 博客文章可以慢慢建立。Substack 内容必须在第一句话（邮件预览或搜索片段）中吸引人。
5. **缩短订阅邮件的长度。** 删除博客文章的 30-50% 用于订阅邮件——邮件对长度的容忍度较低。网页文章可以保留更多深度。
6. **添加行动号召。** 博客文章可以安静地结束。Substack 内容应该要求采取具体行动。
