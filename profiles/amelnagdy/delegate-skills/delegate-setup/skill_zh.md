# 委托设置

你是**协调器**，处于**设置模式**。发现已安装的实现者CLI，提议一个**车道舰队**，并在用户批准后才写入配置。

这项技能**不**调度编码工作。它仅编写车道地图。

一个概念：**车道**。永远不要说“路线”。

示例车道：**功能** → 实现者 `opencode`，模型 `opencode/grok`，变体 `高`
(OpenCode 使用 `变体` 表示推理强度，而不是 `努力`)。

## 不应使用此功能的情况

- 用户希望实现任务 — 使用匹配的 `*-delegate` 技能。
- 单次调度上的单个模型更改 — 在该中继上传递 `--model` / `--努力` / `--变体`。

## 硬性规则

1. 每个车道**必须**包含 `implementer`。
2. 如果该实现者支持它们，才在同一对象（`model`，`努力` 或 `变体`，…）上放置旋钮 — 请参阅 [references/schema.md](references/schema.md)。
3. 在每次写入之前显示人类可读的车道表**和**完整的JSON；在每次调整后重新显示。
4. 仅在明确批准（“是”，“批准”，“写入它”）后写入。
5. 除非已经明确，否则询问范围：**全局**（所有项目）与**仅此仓库**。不要因为当前工作目录是git仓库就创建项目文件。如果没有git仓库，默认为全局并说明。
6. 不要编造模型标识符。
7. 在面试或使用扫描模式下，永远不要写入用户没有给出且模式不需要的任何旋钮 — 忽略它，以便CLI或中继自己的默认值适用。
8. 优先考虑3-5个有用的车道，而不是一个包罗万象的地图。
9. 永远不要编辑 `AGENTS.md`，`CLAUDE.md` 或其他用户代理指令文件。
10. 永远不要从此技能运行 `*-delegate` 中继。

(`<skill-dir>` 是此技能的安装目录 — 包含此 `SKILL.md` 的文件夹。)。

## 流程

`发现 → 加载 → 基础菜单 → 提议（带有 Basis）→ 范围 → 批准 → 写入`

### 1. 发现

```bash
node "<skill-dir>/scripts/discover.mjs"
```

总结已安装与缺失的情况，认证（`true` / `false` / `null` = 未知），以及模型是否为
`报告`，`别名`（注册表中管理的别名，不是实时发现 — 完整模型名称也适用），`不支持` 或 `失败`。

### 2. 加载现有（有效地图）

```bash
node "<skill-dir>/scripts/config.mjs" load --cwd "$PWD"
```

- 两者都不存在 → “尚未配置车道。”
- 否则 → 表格形式的**有效**车道，带有源列（`全局` / `项目`）。除非被要求，否则不要粘贴
  两个原始文件。
- 如果 `projectPresent` 为 true 且 `projectTrusted` 为 false，将项目车道标记为**不可信**。
  它们必须等到用户审查并批准项目写入后才能调度。

### 3. 提议

发现报告能力，而不是任务适用性。因此，在提议任何东西之前，问**一个**基础问题 — 一个问题，三个选项，不是一个向导：

> 我应该如何选择车道？ **(1) 快速默认** — 我决定，不提问。
> **(2) 面试** — 关于如何分配工作的四个问题。
> **(3) 使用扫描** — 我重新读取你的CLI的本地会话文件夹（仅计数和日期，从不对话）并让你的车道由数字决定 — 如果一个CLI占主导地位，可以期待一个关于其角色的提问。乐意一起做2和3。

- **快速默认** → 立即提议。
- **面试** → 四个问题（分配策略，从不模型排名）以及如何提问（每轮一个中等）在 [references/setup-dialogue.md](references/setup-dialogue.md) 中 — 在提问前阅读它。
- **使用扫描** → `node "<skill-dir>/scripts/discover.mjs" --usage`。在运行它之前告诉用户它是元数据。每个发现的CLI获得 `usage: { sessions, lastUsed }`；`null` 表示没有配置探测 — 未知，不是未使用。
- **两者** → 首先运行扫描，然后只问数字无法回答的问题。
- 在git仓库中，仓库信号（语言、测试权重、前端份额）是第四个证据来源。它们不会改变菜单；它们为提议提供信息，并为 `repo` basis 提供信息。

**该菜单也是同意表面** — 所选选项设置多少地图由你决定：

- **快速默认** — 用户聘请了你的意见。一个完整地图是合法的，包括旋钮；标记每个车道 `我的意见`，明确说明地图是你的意见，并保持修改成本低。
- **面试 / 使用扫描** — 证据模式，因此**每个**旋钮都受限制（规则7）：仅从用户的答案设置一个，或在模式要求它的情况下（opencode车道要求 `model`）。忽略总是安全的 — 每个旋钮都有一个用户已经接受的默认值，并且CLI的配置默认值是他们目前的选项，比你的先验证据更好。选择哪个已安装的实现者获得车道仍然是你的 — Basis `我的意见` — 但一个提高支出的旋钮不是：仅将你的旋钮选择作为提议后的补充，见
  [references/setup-dialogue.md](references/setup-dialogue.md)。
- **一个未回答的问题会缩小地图；它永远不会授权替代品。** 提议较少、更保守的车道，命名你盲目的轴（没有配额答案 → 说地图是配额盲），并随时邀请答案。最多再问一次；永远不要用沉默填充先验。

**委托经济。** 协调器审查并部署每个结果 — 审查是质量门，因此优化总成本，而不是实现者声望：

- 优先考虑有能力的、经过认证的、可消耗的、**低使用率**的CLI，用于有界、客观限制的工作（测试、机械重构、简单的修复）当它们的可靠性使审查和返工经济时 — 车道将令牌消耗推向用户保护的订阅。
  低使用率本身并不能证明可消耗：发现看不到计划、限制或每次运行成本，并且很少使用的CLI可能是计量的或故意避免的。可消耗来自用户的配额答案 — 或，在快速默认中，来自你标记的意见。
- 避免将车道绑定到用户保护或协调的CLI，默认情况下；仅在用户要求或没有可接受的替代方案时绑定它。车道
  **协调器盲**：从用户驾驶的每个座位，以及从该CLI自己的座位，都会触发相同的车道，并且从该CLI的座位调度CLI到自身。
- 当返工和审查成本超过节省时，过剩放置会崩溃；当实现者不可靠时；当正确性取决于安全、并发、迁移或未声明的领域知识时；以及当输出**是**产品（辩论、架构、研究）时 — 审查限制损害，它不会制造一个良好的第一次尝试。将这些车道绑定到更强的实现者。
- 一个明确的“备用X”答案默认情况下会从提议的车道中移除X，并且会覆盖用户明确保留用于X的任何车道的笼统立场答案 — 询问该立场是否适用；如果未回答，则忽略旋钮。永远不要在与之冲突的轴上静默地扩展一个答案。

烧/备用和信任面试的问题措辞在
[references/setup-dialogue.md](references/setup-dialogue.md) 中。

然后提议车道。根据用户描述的工作命名；如果需要，回退到 `feature`，`tests`，`ui`，`fast`，`complex`。仅使用已安装的实现者。

显示：

| 车道 | 实现者 | 模型 | 努力 / 变体 | Basis | 源（如果更新） |
| --- | --- | --- | --- | --- | --- |
| feature | opencode | opencode/grok | 变体：高 | 你的答案 + 模式要求 | — |
| tests | codex | — | — | 使用数据 | — |
| ui | claude | — | — | 我的意见（实现者） | — |

**Basis** 在每个车道上都是强制性的：`你的答案` / `使用数据` / `repo` / `我的意见` /
`模式要求`（模式强制的一个旋钮既不是证据也不是意见 — 说明这一点）。你从模型质量先验中选择的车道是 `我的意见` — 永远不要将其呈现为工具确定的，并且“已安装和认证”是能力，不是适用性的证据。当一个车道的实现者和它的旋钮来自不同的地方时，分割标签 — 见
[references/setup-dialogue.md](references/setup-dialogue.md)。

然后是**完整的**JSON（`版本`：`delegate-fleet.v1`）。每条车道一行原因；标记认证或模型不确定性。

模式和旋钮表：[references/schema.md](references/schema.md)。

### 4. 范围

- 用户说全局 / 所有项目 / 项目外 → `global`。
- 没有git仓库 → `global`（说明）。
- 否则问一次：全局与仅此仓库。

### 5. 批准和写入

在明确的“是”下，仅写入所选范围（首先验证）。从该范围的原始文件构建负载（如果是新文件，则为空的 `lanes` 对象） — 不是从有效的合并 `load` 视图，或项目写入将阴影全局仅车道，而全局写入将提升项目仅车道。

在平台临时目录下创建一个唯一命名的文件（`$TMPDIR`，`%TEMP%` 或 Node `os.tmpdir()`；永远不要硬编码 `/tmp`，它在原生Windows上会中断），将**精确批准的JSON**用协调器的文件写入工具写入其中，并使用该填充路径作为下方的 `<lanes-json>`。永远不要验证空的临时文件。在验证/写入尝试后，无论成功还是失败，都删除临时文件。

```bash
node "<skill-dir>/scripts/config.mjs" validate "<lanes-json>"
node "<skill-dir>/scripts/config.mjs" write --scope global "<lanes-json>"
# 或:  write --scope project --cwd /path/to/repo "<lanes-json>"
```

用 `load` 重新读取，然后确认写入的路径和活动车道名称。项目写入将批准绑定到确切的配置内容；后续更改将失败，直到重新批准。在更新时，简短的之前/之后就足够了。

### 6. 准备委托

确认后停止。告诉用户地图已准备好。对于后续工作：读取车道的 `implementer`，加载该 `*-delegate` 技能，并用 `--lane <name>`（显式 `--model` / `--effort` / `--variant` 仍然在传递时获胜）调度。除非他们要求，否则不要开始委托任务。

## 重新配置

相同的流程。显示当前有效地图，提议更改，批准，写入一个范围文件。
重新安装技能包必须不会重写这些文件 — 它们存在于包之外。
