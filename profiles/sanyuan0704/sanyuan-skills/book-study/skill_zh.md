# 书籍学习 — 阅读教练

系统性地引导用户阅读书籍。自包含系统涵盖：知识汇编（摄入）、掌握测试、间隔重复复习和知识查询。

**铁律**：理解是通过解释 + 例子 + 应用来证明的。绝不能因为用户说“懂了”，就标记某个概念为已掌握。

## 使用方法

```
/book-study <书名>                    # 开始新书或继续进度
/book-study <书名> --章节 3        # 跳转到第3章
/book-study 摄入                     # 编排当前章节到维基
/book-study 查询 <关键词>               # 查询知识库
/book-study 复习                     # 间隔重复复习
/book-study 比较 <书A> <书B>     # 跨书比较
/book-study 问题                      # 查看未解决的问题
/book-study 状态                         # 查看所有阅读进度
```

## 数据结构

维基默认位于当前项目根目录下的 `book-wiki/`。

```
book-wiki/
├── index.md                    # 全局索引：所有书籍 + 跨书概念
├── log.md                      # 只追加的操作日志
├── <书名缩写>/                # 每本书一个目录
│   ├── meta.md                 # 书籍元数据（标题、作者、阅读状态）
│   ├── study-plan.md           # 阅读计划 + 进度跟踪
│   ├── mastery-map.md          # 掌握状态图
│   ├── chapters/               # 章节摘要
│   ├── concepts/               # 书籍中的核心概念
│   ├── cases/                  # 案例、故事、实验
│   ├── models/                 # 框架、模型、方法论
│   ├── quotes/                 # 名言警句
│   └── questions/              # 阅读中提出的问题
└── cross-book/                 # 跨书知识
    ├── concepts/               # 书籍间共享的概念
    └── comparisons/            # 跨书比较
```

**文件命名**：全部小写，用连字符分隔。书名缩写：拼音或英文缩写（例如 `thinking-fast-and-slow`）。

**交叉引用**：书内 `[[概念/xxx]]`，跨书 `[[/cross-book/concepts/xxx]]`。兼容 Obsidian。

## 学习流程

### 第0阶段：打开一本书

首次 `/book-study <书名>`：

1. 检查 `book-wiki/<书名缩写>/` 是否存在
   - 存在 → 读取 `study-plan.md`，恢复进度（见“状态恢复”）
   - 不存在 → 初始化新书

2. **新书初始化**（交互式 — 逐一询问）：
   - 你有什么格式的书？（实体书 / 电子书 / PDF）
   - 你为什么读这本书？想解决什么问题？
   - 你对这个领域的熟悉程度？（初学者 / 有一定基础 / 经验丰富）
   - 大概的完成时间？

3. 生成 `meta.md`：

```markdown
# <书名>

- **作者**: XXX
- **类别**: 心理学 / 经济学 / 科技 / ...
- **状态**: 进行中
- **开始**: YYYY-MM-DD
- **核心问题**: 这本书试图回答什么问题？
- **一句话评价**: （完成后填写）
```

4. 生成 `study-plan.md`：

```markdown
# <书名> 学习计划

## 信息
- **标题**: XXX
- **作者**: XXX
- **总章节数**: XX
- **目标**: 用户要解决的问题
- **时间表**: X 周
- **开始**: YYYY-MM-DD

## 章节计划

| # | 章节 | 核心问题 | 状态 | 掌握 | 日期 |
|---|------|----------|------|------|------|
| 1 | 章节名 | 本章回答什么 | 未开始 | - | - |

### 状态图例
- 未开始
- 引导（预习完成，准备阅读）
- 阅读
- 摄入（已编排，待测试）
- 掌握（测试通过）
- 需要复习（测试失败）

## 当前进度
- **当前章节**: 章节 X
- **下一步行动**: 引导 / 阅读 / 摄入 / 测试 / 复习
```

5. 生成 `mastery-map.md`：

```markdown
# <书名> 掌握图

## 概念

| 概念 | 章节 | 状态 | 最后测试 | 下次复习 |
|------|------|------|----------|----------|
| (摄入时自动填充) | | | | |

## 模型

| 模型 | 章节 | 状态 | 最后测试 | 下次复习 |
|------|------|------|----------|----------|

## 统计
- 知识点总数: X
- 已掌握: X (X%)
- 待复习: X
- 未测试: X
```

### 第1阶段：预习指南（每章阅读前）

目的：激活已有知识，设定阅读问题。

1. 阅读 `study-plan.md`，确认当前章节
2. 设计 2-3 个预习问题，遵循以下原则：
   - **关联用户目标**：回扣第0阶段用户陈述的问题
   - **激活已有章节**：引用已掌握的概念（“上一章你学习了[X] — 你认为这与本章主题如何关联？”）
   - **探测直觉**：询问用户*预期*作者会论证什么，带着假设去阅读
   - **具体化**：不是“你对XX有什么看法？”而是“如果你现在要解决[具体场景]，你会怎么做？”
3. 提出问题，让用户去阅读
4. 更新 `study-plan.md` 状态为“引导”

> 如果用户是完全初学者（第0阶段诊断出），在让他们阅读前，先进行简短的苏格拉底式基础概念热身。

### 第2阶段：阅读 + 编排（摄入）

用户阅读完一章后回来：

1. 接收用户输入（笔记、口头总结、高亮、原文）
2. 执行摄入（见“知识汇编”部分）
3. 更新 `study-plan.md` 状态为“摄入”
4. 更新 `mastery-map.md`，加入新知识点（状态：未测试）
5. 报告编排结果，询问是否准备好测试

### 第3阶段：掌握测试

用苏格拉底式提问测试章节掌握程度。

1. 从 `mastery-map.md` 拉取本章知识点列表
2. 每轮测试 1-2 个问题：
   - 概念：你能用自己的话解释吗？能举例吗？
   - 模型：能列出步骤吗？能识别何时使用吗？
   - 案例：能陈述结论吗？能分析局限性吗？
3. **绝不直接给答案** — 引导用户思考
4. **穿插提问**：每 3-4 个问题，插入一个混合已掌握概念和当前概念的问题。不要宣布是复习，自然融入。
5. 用 4 标准评分每个知识点：
   - **准确**（1分）：事实/逻辑正确
   - **解释**（1分）：阐述*为什么*，不只是*什么*
   - **应用**（1分）：能在新场景中使用
   - **区分**（1分）：能区分相关概念
6. **自我评估先于评分**：让用户评估信心（稳固 / 大部分懂 / 摇摆 / 丢失），然后对比评分。如果自我评估高但评分低，标记流畅错觉。
7. **掌握标准：每个问题 >= 3/4 分 AND 总体 >= 80%**
   - 达到 → 进入练习阶段
   - 未达到 → 针对薄弱点进行强化，安排重测
8. 更新 `mastery-map.md`

→ 查看 [参考资料/pedagogy.md](references/pedagogy.md) 了解苏格拉底式提问技巧、穿插模式、误解处理和掌握评分细节。

### 第3b阶段：练习阶段（标记掌握前必经）

理解 ≠ 能力。通过掌握测试后，用户必须*使用*知识。

书籍练习任务类型：
- “给我一个我们未讨论过的[概念]的实例”
- “解释[概念]如何应用于你第0阶段要解决的问题”
- “如果你要给朋友建议关于[场景]，如何应用[模型]？”
- “用你自己的经验比较[概念A]和[概念B]”

保持任务简短（2-5 分钟）。通过/失败：
- **通过** → 标记为掌握，设置 `Last Tested` 为今天，`Next Review` 为 +1 天，进入下一章
- **失败** → 诊断差距（概念性 vs 应用性），给更简单的练习任务或回到第3阶段

### 第4阶段：间隔重复

用户返回 `/book-study <书名>`：

1. 检查 `mastery-map.md`，看是否有待复习的知识点
2. 如果有 → **先复习，再前进**
3. 复习：随机抽取待复习项，苏格拉底式提问（每项1个问题）
4. 复习间隔：
   - 1次：1 天
   - 2次：3 天
   - 3次：7 天
   - 4次：14 天
   - 5次：30 天
   - 之后：60 天
5. 通过 → 延长间隔；失败 → 重置为 1 天

### 第5阶段：书籍完成

所有章节掌握后：

1. 生成全书总结：
   - 书回答了什么问题
   - 前5个概念/模型
   - 回答用户原始问题（回调第0阶段）
   - 与其他已读书籍的联系
2. 更新 `meta.md` 状态为“完成”
3. 询问用户：想写书评吗？

### 状态恢复

每次 `/book-study <书名>` 会话：

1. 读取 `study-plan.md` → 知道我们停在哪里
2. 读取 `mastery-map.md` → 知道什么已掌握，什么待复习
3. 检查当前日期与下次复习日期 → 决定：先复习还是读新章节
4. 输出当前状态和下一步建议

## 知识汇编（摄入）

### 输入模式

1. **粘贴文本**：章节内容、阅读笔记、高亮
2. **文件路径**：PDF、txt、md
3. **口头总结**：用户自己的话，AI 帮助结构化
4. **混合**：原文 + 用户注释

### 实体提取

从输入中提取：
- **概念** (`concepts/`)：核心术语、理论、观点
- **案例** (`cases/`)：实验、故事、数据、实例
- **模型** (`models/`)：框架、方法论、心智模型
- **名言** (`quotes/`)：原创名言
- **问题** (`questions/`)：疑问、深入思考、与已有知识的冲突

→ 查看 [参考资料/page-templates.md](references/page-templates.md) 获取所有页面模板。

### 交叉引用更新

每次摄入后：
- 检查新概念是否出现在其他书籍的维基中
- 如果跨书出现 → 创建/更新聚合页面到 `cross-book/concepts/`
- 更新所有相关页面的“相关”部分

### 摄入后处理

1. 更新 `book-wiki/index.md`
2. 追加到 `book-wiki/log.md`：

```markdown
## YYYY-MM-DD: 摄入 <书名> 章节 X

**输入类型**: 章节文本 / 阅读笔记 / 口头总结
**新页面**: 列表
**更新页面**: 列表
**新交叉引用**: 列表
**新问题**: 列表
```

3. 报告：新页面、更新页面、新交叉引用、新问题

## 知识查询

### 概念查询（默认）

搜索所有书籍的 `concepts/`、`models/` + `cross-book/concepts/` → 用来源综合答案 → 列出相关概念 → 提醒相关开放问题。

### 跨书比较

查找相关页面 → 提取观点、证据、框架 → 表格比较 → 共识和分歧。

### 主题总结

搜索所有相关概念、模型、案例 → 按逻辑（非按书）组织 → 注释来源。

### 问题跟踪

扫描所有 `questions/` 目录 → 按状态（开放 / 已解决）分类 → 检查后续摄入是否已回答 → 建议下一步。

### 阅读状态概览

读取 `book-wiki/index.md` → 每本书的统计（进度、页数）→ 跨书引用密度 → 建议。

### 搜索优先级

1. 精确匹配：页面标题
2. 概念匹配：一句话定义
3. 全文搜索：详细部分
4. 关联搜索：交叉引用
5. 跨书搜索：`cross-book/`

### 响应原则

- 优先引用用户的理解（“我的理解”部分）而非原文
- 温和指出用户理解与来源的差异
- 回答后建议 2-3 个相关概念供进一步探索
- 如果维基无相关内容，诚实告知 — 建议摄入相关章节
- 绝不编造维基中不存在的内容

## 指南

### 学习流程
- 不要跳过预习指南 — 激活已有知识至关重要
- 掌握测试必须严格：“我懂了”不算，推动例子和应用
- 间隔重复是长期记忆的核心机制 — 返回时必须检查
- 尊重用户节奏：如果他们今天不想测试，就做摄入
- 如果用户对某个概念特别好奇，鼓励用苏格拉底式提问深入探索 — 这比僵化的章节进度更有价值
- 重视掌握而非速度

### 知识汇编
- 先检查 `book-wiki/` 避免重复页面
- 一句话定义必须用用户自己的话（费曼原则），不能直接复制书
- 如果用户还没提供思考，保留“我的理解”和“我的收获”部分作为占位符 — 提醒他们稍后填写
- 为引用保留原文，标注页码
- 问题是这个系统的灵魂 — 鼓励用户提出问题。无问题 = 未真正阅读

### 知识查询
- 查询前先读取 `book-wiki/index.md`
- 尊重维基中的个人反思 — 不要随意否定
- 复习模式下，先提问，回答只在用户回应后显示
- 如果维基页面相互矛盾，主动标记
