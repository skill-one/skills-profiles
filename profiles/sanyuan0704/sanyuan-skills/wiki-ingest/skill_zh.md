# Wiki Ingest — 知识库编译器

将任何文本内容（文章、文档、笔记）编译成具有交叉引用的结构化维基页面，构建一个可搜索、相互连接的知识网络。

**铁律**：一个维基页面 = 一个知识实体。切勿将多个概念塞入一个页面。

## 维基目录结构

维基默认位于当前项目根目录下的 `wiki/`。用户可以指定不同的路径。

```
wiki/
├── index.md              # 完整目录
├── log.md                # 仅追加的操作日志
├── concepts/             # 核心概念页面
├── products/             # 产品/工具实体页面
├── patterns/             # 工程模式 & 设计决策
└── comparisons/          # 跨主题比较页面
```

## 工作流程

### 1. 确认输入

接受用户指定的内容源：
- 直接粘贴的文本
- 文件路径（md、txt、pdf 等）
- 目录路径（批量处理）

如果用户未指定维基路径，则使用 `wiki/`。如果该目录不存在，则创建它。

### 2. 检查现有维基

读取 `wiki/index.md`（如果存在），以了解现有页面并避免重复。

### 3. 提取知识实体

从内容中提取：
- **概念** (`concepts/`)：抽象概念、术语、理论
- **产品** (`products/`)：具体产品、工具、服务
- **模式** (`patterns/`)：工程模式、设计决策、方法论
- **比较** (`comparisons/`)：跨产品或跨方法的分析

提取阈值：只有当该实体会被其他页面引用时，才值得为其创建一个页面。

### 4. 创建或更新页面

每个实体映射到一个维基页面。

→ 加载 [references/page-templates.md](references/page-templates.md) 获取页面模板。

规则：
- 如果页面已存在 → **更新** 它，追加新信息，不要覆盖现有内容
- 除非新内容提供了明显更好的定义，否则保持单行定义稳定
- 优先更新“来源”和“相关页面”部分

### 5. 更新交叉引用

检查所有现有维基页面。如果新内容涉及其他页面中引用的概念：
- 更新它们的“相关页面”列表
- 更新它们的“来源”列表
- 在它们的详细部分补充新信息

### 6. 更新 index.md

将新页面条目添加到 `wiki/index.md`，按类别组织。

### 7. 追加到 log.md

追加到 `wiki/log.md`：

```markdown
## YYYY-MM-DD: Ingest <source title>

**来源**： <文件路径或 "用户输入">
**新页面**： 列出新创建的页面
**更新页面**： 列出修改的页面
**新交叉引用**： 列出新建立的链接
```

### 8. 报告结果

告知用户：创建了哪些页面，更新了哪些页面，建立了哪些新的交叉引用。

## 文件命名

- 全小写，连字符分隔：`agent-loop.md`，`kv-cache.md`
- 按实体命名，而不是按编号

## 交叉引用格式

- 使用 `[[category/page-name]]` 双链接格式（Obsidian 兼容），例如 `[[concepts/agent-loop]]`，`[[products/claude-code]]`
- 始终包含类别前缀以避免跨目录的歧义
- 在每个页面的底部列出所有相关页面

## 指导原则

- 不要创建重复页面 — 始终先检查 wiki/
- 不要提取琐碎的实体 — 如果一个概念只出现一次且不会在其他地方被引用，则跳过它
- 对于批量处理：先提取所有实体，然后一次性创建页面和更新引用，以避免不一致的中间状态
- 每次导入后始终更新 index.md 和 log.md
