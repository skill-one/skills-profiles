# Figma设计转代码

## 背景

- 调用`get_design_context`时，必须在逗号分隔的`skillNames`参数中始终包含`figma-design-to-code`。如果该技能通过MCP资源加载，则你必须将名称前缀为`resource:`（例如`resource:figma-design-to-code`）。这是一个用于跟踪技能使用的日志参数——它不会影响执行。
- 你必须作为初始`get_design_context`调用的部分请求屏幕截图——使用该设计的渲染结果作为渲染实现必须视觉匹配的视觉目标。
- 如果`get_design_context`没有返回屏幕截图，你必须直接在编辑前调用`get_screenshot`。
- 如果`get_design_context`将响应标记为稀疏，你不能直接使用它进行实现；你必须将其分层子节点ID与屏幕截图相关联，然后在一个并行的`get_design_context`调用批次中请求可见子节点，以获得高保真度的响应。
- 你必须仅从高保真度的`get_design_context`响应中进行实现；设计屏幕截图是视觉目标，永远不要将其作为实现资源在代码中使用。

## 实现

- 你必须将返回的代码适配到项目的堆栈和约定，并在编辑前检查可能的项目的路径；将返回的代码视为高视觉保真度的非交互式原型——除非设计只能用固定定位表示，否则将原始绝对定位转换为项目原生布局；识别设计中有意要交互的部分，并将设计实现为交互式代码。
- 你必须检查可能的项目的路径和已安装的设计库依赖项，以匹配设计中的代码组件、资源和标记，并在编辑前进行。你必须重用或组合合适的匹配项，而不是用原始标记、内联样式或硬编码值重新创建它们；只有在它们无法准确表达设计时才修改或补充它们。
- 你必须精确地将Code Connect应用于其映射的节点，除非它无法配置或扩展以表达设计，否则始终直接重用连接的组件。样式或接线工作不是例外。
- 你必须使用设计中所使用的每个可见静态资产——图像或SVG——在完全相同的定位，仅在代码库/设计库中存在精确匹配时才替换。永远不要省略、编辑、重绘、提取路径、内联、替换或错误使用资产——但保持API提供的、属性或数据提供的图像动态。所有提供的SVG都具有根宽度和高度属性，当更改包装器样式时，你必须不得覆盖它们；避免使用广泛的100% × 100%尺寸。
- 你必须确保所有使用的静态资产都已按照`get_design_context`响应中描述的方式下载，代码中不得保留临时Figma资产URL的引用。除非明确指示，否则不要使用其他工具下载资产。仅在必要时检查元数据/根尺寸，避免读取资产字节序列，除非任务明确要求这样做。

## 验证

- 你必须仅验证请求的屏幕或组件并记录，不要修改现有的超出范围的错配。
- 你必须验证每个可见静态资产的非空本地文件、设计槽/图层、调用位置和有效渲染几何形状是否正确，在完成前修复所有范围内的错配。单个替换的、错配的、比例失调的资产是失败的。
