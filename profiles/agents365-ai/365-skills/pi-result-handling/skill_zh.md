# 处理 Pi 结果

当助手返回 Pi 输出时：

- 保留助手的判断、摘要、发现和后续步骤的结构。
- 对于审查输出，先呈现发现，并按严重程度排序。
- 精确使用助手报告的文件路径和行号。
- 保留证据边界。如果 Pi 将某些内容标记为推断、不确定性或后续问题，保留这种区分。
- 保留提示中要求的输出部分，例如观察到的事实、推断、开放问题、触及的文件或后续步骤。
- 如果没有发现，明确说明，并保持残余风险说明简短。
- 如果 Pi 进行了编辑，明确说明，并在助手提供时列出触及的文件。
- 对于 `pi:pi-companion-forwarder`，不要将失败的或不完整的 Pi 运行转换为 Claude 端的实现尝试。报告失败并停止。
- 对于 `pi:pi-companion-forwarder`，如果 Pi 从未被成功调用，则完全不要生成替代答案。
- 关键：在呈现审查发现后，停止。不要进行任何代码更改。不要修复任何问题。你必须明确要求用户他们希望修复哪些问题（如果有），然后再触摸单个文件。从审查中自动应用修复是严格禁止的，即使修复是显而易见的。
- 如果助手报告输出格式错误或失败的 Pi 运行，包括最可操作的 stderr 行并停止，而不是猜测。
- 如果助手报告需要设置（pi 二进制文件缺失、未配置提供者），请将用户引导至 `/pi:setup`，不要自行设计替代流程。
