# Karpathy LLM 维基

使用 LLM 构建和维护个人知识库。您管理两个目录：`raw/`（不可变源材料）和 `wiki/`（编译后的知识文章）。源材料放入 raw/，您将它们编译成 wiki 文章，维基会随着时间的推移而不断积累。

来自 Karpathy 的核心思想：
- "LLM 编写和维护维基；人类阅读和提问。"
- "维基是一个持久化、不断积累的成果。"

## 架构

三个层级，都在用户的工程根目录下：

**raw/** — 不可变的源材料。您只能读取，不能修改。按主题子目录组织（例如，`raw/machine-learning/`）。

**wiki/** — 编译后的知识文章。您拥有完全的所有权。按主题子目录组织，只有一层：`wiki/<主题>/<文章>.md`。包含两个特殊文件：
- `wiki/index.md` — 全局索引。每篇文章一行，按主题分组，包含链接 + 摘要 + 更新日期。
- `wiki/log.md` — 仅追加操作的日志。

**SKILL.md**（此文件）— 模式层。定义结构和工作流规则。

模板位于相对于此文件的 `references/` 中。当您需要源文件、文章、存档页面或索引的精确格式时，请阅读它们。

### 初始化

仅在第一次摄取时触发。检查 `raw/` 和 `wiki/` 是否存在。仅创建缺失的文件；不要覆盖现有文件：

- `raw/` 目录（带 `.gitkeep`）
- `wiki/` 目录（带 `.gitkeep`）
- `wiki/index.md` — 标题 `# 知识库索引`，空正文
- `wiki/log.md` — 标题 `# 维基日志`，空正文

如果查询或 Lint 无法找到维基结构，请告诉用户："先运行一次摄取来初始化维基。" 不要自动创建。

## 定位不变式

wiki/ 中每个承载事实的数字、日期、直接引语都存在于该文章的 Raw 字段链接的 raw/ 文件中。编译 *建立* 这个不变式（写之前查找）；Lint *验证* 它 (`scripts/check_evidence.py` 在链接的 raw 文件中搜索高信号字面量——后缀或大数字、小数、ISO 日期、长引语；编译时的查找-写规则涵盖其余部分）。由于 raw/ 是不可变的，经验证的文章将保持验证状态；脚本在几秒钟内重新检查整个维基，因此无需维护增量状态。

## 摄取

从源中获取内容到 raw/，然后将其编译到 wiki/——除非源没有添加任何新内容。始终获取；是否编译取决于下面的分拣。

### 获取（raw/）

1. 使用您的环境提供的任何网络或文件工具获取源内容。如果无法访问源，请要求用户直接粘贴。

2. 选择一个主题目录。首先检查现有的 `raw/` 子目录；如果主题足够接近，则重用一个。仅对真正不同的主题创建新的子目录。

3. 保存为 `raw/<主题>/YYYY-MM-DD-描述性缩写.md`。
   - 缩写来自源标题，短横线分隔，最多 60 个字符。
   - 发布日期未知 → 从文件名中省略日期前缀（例如，`描述性缩写.md`）。元数据发布字段仍然存在；将其设置为 `Unknown`。
   - 如果已存在同名文件，则追加数字后缀（例如，`描述性缩写-2.md`）。
   - 包含元数据头部：源 URL、收集日期、发布日期。
   - 保留原始文本。清理格式噪音。不要重写观点。

   参见 `references/raw-template.md` 获取确切格式。

### 分拣

保存源文件后、编辑 wiki/ 之前，使用源的键实体和同义词搜索 wiki/，然后声明处理方式：

- **新** — 创建一个或多个新文章。
- **更新** — 合并到现有文章。
- **有争议** — 与现有内容矛盾；可能合并到新或更新（见编译冲突注释）。
- **无实质性内容** — 除了维基已持有的知识外，没有添加任何新知识。保留源文件，记录（见摄取后），然后停止。不要强行从微弱的源中创建文章。

新、更新和有争议可以组合。无实质性内容是排他的。

### 编译（wiki/）

确定新内容所属位置：

- **与现有文章的核心论点相同** → 合并到该文章。将新源添加到 Sources/Raw。更新受影响的章节。
- **新概念** → 在最相关的主题目录中创建新文章。以概念命名文件，而不是源文件。
- **跨越多个主题** → 放入最相关的目录。添加指向其他相关文章的交叉引用。

这些不是互斥的。单个源可能需要合并到一个文章中，同时为它引入的独特概念创建一个单独的文章。在所有情况下，检查事实冲突：如果新源与现有内容矛盾，请用 **状态：有争议** 块标记有争议的声明（见 `references/article-template.md`）。当冲突内容存在于不同文章中时，标记两者并交叉链接。

**源忠实度。** 每个数字、日期和直接引语必须在写入前在源文件中找到（grep 或读取）；精确写入找到的值——如果源说 42K，则写入 42K，而不是 42,000。派生值（总和、差值、您计算的计数）必须显示其组成部分，以便每个组成部分都可以在源中找到。如果您无法定位一个值，请不要写入其确切形式；删除它或在不精确的情况下声明它。

参见 `references/article-template.md` 获取文章格式。要点：
- Sources 字段：作者、组织或出版物名称 + 日期，分号分隔。
- Raw 字段：指向 raw/ 文件的 markdown 链接，分号分隔。
- 相对路径从 `wiki/<主题>/` 使用 `../../raw/<主题>/<文件>.md`（向上两级到工程根目录）。

### 级联更新

在主要文章后，检查级联效应。不要仅依赖索引：在维基中搜索源的关键实体、别名和它触及的声明，然后更新所有实质性受影响的非存档文章。每个更新文件都会刷新其更新日期。

当新源取代或与现有声明矛盾时，保留旧声明以备记录，但用状态块标记它（见 `references/article-template.md`）：**过时** 当有更新的内容取代它时，**有争议** 当源不一致时。永远不要默默重写历史。

存档页面永远不会级联更新（它们是时间点的快照）。

### 摄取后

更新 `wiki/index.md`：为每个触及的文章添加或更新条目。添加新主题部分时，请包含一行描述。更新日期反映文章知识内容上次更改的时间，而不是文件系统时间戳。参见 `references/index-template.md` 获取格式。

追加到 `wiki/log.md`：

```
## [YYYY-MM-DD] 摄取 | <主要文章标题>
- 处置：<新；更新；有争议>
- 源：<源文件路径>
- 更新：<级联更新的文章标题>
```

当没有级联更新时，省略 `- 更新：` 行。对于无实质性内容，记录并停止。使用工程根相对路径（例如，`raw/topic/file.md`）：

```
## [YYYY-MM-DD] 摄取 | 无实质性内容：<工程根相对源文件路径>
- 处置：无实质性内容
```

确切的“无实质性内容”标题是机器可读的清单键；处置行仍然是完整人类可读日志条目的必需项。

### 研究（多源摄取）

仅在用户明确要求研究主题或收集源到维基时使用。普通知识问题交给查询，查询永远不会写文件。

1. 将主题分成几个角度。对于每个角度，用广泛的大网搜索——官方名称、缩写和同义词，而不仅仅是字面关键词。
2. 对于您预期会得出结论的核心声明，故意搜索对立面：失败、批评、失败的复制。
3. 像平常一样将选定的源保存到 raw/。搜索可能并行运行；编译必须不——一次编译一个源，因为 index.md、log.md 和级联更新是共享状态。

## 查询

搜索维基并回答问题。触发示例：
- "我知道关于 X 的哪些信息？"
- "总结与 Y 相关的所有内容"
- "根据我的维基比较 A 和 B"

### 步骤

1. 阅读 `wiki/index.md` 定位候选文章，然后在 wiki/ 中用主题的关键词及其同义词进行全文搜索。在索引和全文搜索都为空之前，永远不要声称维基没有相关内容——并说明您已搜索。
2. 阅读您找到的文章并综合答案。
3. 优先使用维基内容而不是您自己的训练知识。用 markdown 链接引用来源：`[文章标题](wiki/topic/article.md)`（对话中引用使用工程根相对路径；在 wiki/ 文件中，使用相对于当前文件的路径）。
4. 在对话中输出答案。除非被要求，否则不要写文件。

### 存档

当用户明确要求将答案存档到维基时：

1. 将答案作为新维基页面写入。参见 `references/archive-template.md`。在将对话引用转换为存档页面时，重写工程根相对路径（例如，`wiki/topic/article.md`）为文件相对路径（例如，`../topic/article.md` 或同目录的 `article.md`）。
   - Sources：指向答案中引用的维基文章的 markdown 链接。
   - 无 Raw 字段（内容来自 raw/）。
   - 文件名反映查询主题，例如，`transformer-architectures-overview.md`。
   - 放入最相关的主题目录。
2. 始终创建新页面。不要合并到现有文章（存档内容是综合答案，不是原始材料）。
3. 更新 `wiki/index.md`。摘要前缀 `[存档]`。
4. 追加到 `wiki/log.md`：
   ```
   ## [YYYY-MM-DD] 查询 | 存档：<页面标题>
   ```

## Lint

对维基进行质量检查。三个类别具有不同的权威级别。

### 安全修复（自动修复）

自动修复这些：

**索引一致性** — 比较 `wiki/index.md` 与实际的 wiki/ 文件（不包括 index.md 和 log.md）：
- 文件存在但索引中缺失 → 添加条目，带 `(无摘要)` 占位符。对于更新日期，如果存在，使用文章的元数据更新日期（对于存档页面，使用存档日期）；否则回退到文件的最后修改日期。
- 索引条目指向不存在的文件 → 在索引中标记为 `[缺失]`。不要删除条目；让用户决定。
- 索引条目的更新日期与文章的元数据更新日期（或存档页面，对于存档页面）不同 → 更新索引条目以匹配文章。

**内部链接** — 对于 wiki/ 文章文件中的每个 markdown 链接（正文和 Sources 元数据），排除 Raw 字段链接（由 Raw 引用以下规则验证），排除 See Also 部分链接（由以下 See Also 规则处理），排除 index.md/log.md（以上处理）：
- 目标不存在 → 在 wiki/ 中搜索具有相同名称的文件。
  - 恰好一个匹配 → 修复路径。
  - 零或多个匹配 → 告诉用户。

**Raw 引用** — Raw 字段中的每个链接必须指向一个现有的 raw/ 文件：
- 目标不存在 → 在 raw/ 中搜索具有相同名称的文件。
  - 恰好一个匹配 → 修复路径。
  - 零或多个匹配 → 告诉用户。

**See Also** — 在每个主题目录中：
- See Also 链接的目标不存在 → 在 wiki/ 中搜索具有相同名称的文件。
  - 恰好一个匹配 → 修复路径。
  - 零个匹配 → 删除链接（一个死交叉引用不是承载事实的）。
  - 多个匹配 → 告诉用户。

### 机械报告（无修复）

使用 `python3 <skill-dir>/scripts/check_evidence.py <工程根>` 运行（可选地，后跟工程根相对文章路径以限制范围）。默认范围是整个维基；脚本运行速度快。报告结果；从不自动修复事实。

**源忠实度** — 报告的可疑项是候选项，不是最终裁决：派生值和产品名称可能会出现。根据原始上下文判断每个值，仅报告真实的不匹配。

**证据错误** — 脚本无法验证的文章（缺少 Raw 字段、无法解析的 Raw 链接或 Raw 链接逃逸 `raw/`）。这些总是需要决策，而不是脚本修复。

**未引用的原始文件** — 记录为无实质性内容的文件被排除；其余的都是真实的待办事项提醒。

### 判断报告（无修复）

这些依赖于您的判断。报告结果而不自动修复：

- 文章之间的事实矛盾
- 被新来源取代但仍然以无状态块呈现的过时声明
- 源不一致时缺少冲突注释
- 显然缺失的相互关联文章之间的交叉引用（建议它们；不要默默添加）
- 格式不正确的状态块（缺少日期的过时，或缺少解释的任一块；格式参考：`references/article-template.md`）
- 没有来自其他维基文章的入站链接的孤儿页面
- 缺少跨主题引用
- 经常提到但缺乏专用页面的概念
- 存档页面，其引用的源文章自存档以来已大幅更新

### 检查后

追加到 `wiki/log.md`：

```
## [YYYY-MM-DD] 检查 | 发现 <N> 个问题，<M> 个自动修复
```

## 规范

- 标准的 markdown，整个文档使用相对链接。
- wiki/ 仅支持一层主题子目录。没有更深层次的嵌套。
- 今天的日期用于日志条目、收集日期和存档日期。更新日期反映文章知识内容上次更改的时间。发布日期来自源（不可用时使用 `Unknown`）。
- 在 wiki/ 文件中，所有 markdown 链接使用相对于当前文件的路径。在对话输出中，使用工程根相对路径（例如，`wiki/topic/article.md`）。
- 摄取更新 `wiki/index.md` 和 `wiki/log.md`（无实质性内容的摄取仅更新日志）。存档（来自查询）更新两者。检查更新 `wiki/log.md`（仅当自动修复索引条目时更新 `wiki/index.md`）。普通的查询不会写入任何文件。
