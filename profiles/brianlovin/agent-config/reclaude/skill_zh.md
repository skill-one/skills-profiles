# reclaude

重构 CLAUDE.md 文件以遵循渐进式披露原则。

## 提示

我希望你重构我的 CLAUDE.md 文件以遵循渐进式披露原则。

按照以下步骤操作：

### 1. 检查长度

报告当前行数。标记问题：
- **理想**：<50 行
- **可接受**：50-100 行
- **需要重构**：>100 行（将内容移动到 `.claude/rules/` 文件中）

### 2. 集成工作流编排

读取 `~/.claude/skills/workflow/SKILL.md` 中的工作流技能，并将其原则融入 CLAUDE.md 或 `.claude/rules/workflow.md` 文件中。根据项目进行调整内容——不要逐字复制，但要确保关键行为得到体现：
- 非平凡任务的计划模式
- 子代理策略
- 使用 `tasks/lessons.md` 的自我改进循环
- 完成任务前的验证
- 非平凡变更的优雅性检查
- 自主错误修复

对于较短的 CLAUDE.md 文件，添加简洁的工作流部分。对于较长的文件，创建 `.claude/rules/workflow.md` 并链接到它。

### 3. 确保存在验证部分

检查是否存在 `## Verification` 部分并包含 Claude 在修改后可以运行的命令。如果缺失：
- 在 `package.json` 中查找测试/校验/类型检查/构建脚本
- 查找 Makefile、justfile 或其他任务运行器
- 添加 `## Verification` 部分并列出发现的命令

这是关键——当 Claude 可以验证其工作时，它的表现会显著提升。

### 4. 查找矛盾之处

识别任何相互冲突的指令。对于每个矛盾之处，询问我想要保留哪个版本。

### 5. 检查全局技能提取候选

查找可能成为 `~/.claude/skills/` 中**可重用全局技能**的内容：
- 关于工具/框架（非项目特定）
- 在 2 个或更多项目中出现相同指令（或适用）
- 内容较多（>20 行）

如果找到，建议创建全局技能并附带名称和描述。

### 6. 确定根 CLAUDE.md 的核心内容

仅提取属于根 CLAUDE.md 的内容：
- 一行项目描述
- 包管理器（如果不是 npm）
- 仅非明显命令（跳过 `npm test`、`npm run build` 等标准命令）
- 链接到 `.claude/rules/` 文件并附简短描述
- 验证部分（始终需要）

### 7. 分组剩余内容

按类别（例如 TypeScript 常规、测试模式、API 设计、Git 工作流）将剩余指令组织到 `.claude/rules/` 文件中。

### 8. 标记删除

识别应完全删除的内容：
- **API 文档**——改为链接外部文档
- **代码示例**——Claude 可以从阅读源文件中推断
- **接口/类型定义**——这些存在于代码中
- **通用建议**——"编写干净代码"、"遵循最佳实践"
- **明显指令**——"使用 TypeScript 编写 .ts 文件"
- **冗余信息**——Claude 已经知道的内容
- **过于模糊**——无法执行的指令

## 目标模板

```markdown
# 项目名称

一行描述。

## 命令
- `command` - 它的作用（仅非明显命令）

## 规则
- [主题](/.claude/rules/主题.md) — 简短描述

## 验证
修改后：
- `npm test` - 运行测试
- `npm run lint` - 检查校验
```

## 保留与删除的内容

**保留在 CLAUDE.md 中：**
- Claude 无法从 `package.json` 推断的命令
- 项目特定的非标准模式
- 项目陷阱和易错点
- 链接到详细规则文件

**移动到 `.claude/rules/`：**
- 详细规范（>10 行的主题）
- 风格指南
- 架构决策
- 工作流文档

**完全删除：**
- Claude 可以从代码库中推断的内容
- 语言/框架的标准实践
- 存在于其他地方的文档（改为链接）
