<概述>
LangGraph 将智能体工作流建模为 **有向图**：

- **StateGraph**：构建有状态图的主要类
- **节点**：执行工作并更新状态的函数
- **边**：定义执行顺序（静态或条件）
- **START/END**：标记入口和出口点的特殊节点
- **带 Reducers 的状态**：控制状态更新如何合并

在执行前，必须对图进行 `compile()`。

</概述>

<设计方法>

### 设计 LangGraph 应用

在构建新图时，请遵循以下 5 个步骤：

1. **绘制离散步骤** — 绘制工作流的流程图。每个步骤成为一个节点。
2. **识别每个步骤的作用** — 对节点进行分类：LLM 步骤、数据步骤、动作步骤或用户输入步骤。对于每个步骤，确定静态上下文（提示）、动态上下文（来自状态）、重试策略和预期结果。
3. **设计你的状态** — 状态是所有节点的共享内存。在节点内部按需存储原始数据、格式化提示。
4. **构建你的节点** — 将每个步骤实现为接受状态并返回部分更新的函数。
5. **连接起来** — 使用边连接节点，添加条件路由，如有必要，使用检查点进行编译。

</设计方法>

<何时使用 LangGraph>

| 何时使用 LangGraph | 何时使用替代方案 |
|-------------------|----------------------|
| 需要精细控制智能体编排 | 快速原型 → LangChain 智能体 |
| 构建具有分支/循环的复杂工作流 | 简单的无状态工作流 → LangChain 直接 |
| 需要人工介入、持久化 | 全功能 → Deep Agents |

</何时使用 LangGraph>

## 边

<边类型选择>

| 需求 | 边类型 | 使用场景 |
|------|-----------|-------------|
| 总是前往同一节点 | `add_edge()` | 固定、确定性流程 |
| 基于状态路由 | `add_conditional_edges()` | 动态分支 |
| 更新状态 AND 路由 | `Command` | 在单个节点中组合逻辑 |
| 分散到多个节点 | `Send` | 带动态输入的并行处理 |

</边类型选择>

## Command

Command 在单个返回值中组合状态更新和路由。字段：

- **`update`**：要应用的状态更新（如从节点返回的字典）
- **`goto`**：要导航到的节点名称
- **`resume`**：在 `interrupt()` 后恢复的值 — 见人工介入技能

<Command 返回类型注解>

**Python**：使用 `Command[Literal["node_a", "node_b"]]` 作为返回类型注解来声明有效的 goto 目标。

**TypeScript**：将 `{ ends: ["node_a", "node_b"] }` 作为 `addNode` 的第三个参数来声明有效的 goto 目标。

</Command 返回类型注解>

<warning-command-静态边>

**警告**：`Command` 仅添加 **动态** 边 — 使用 `add_edge` / `addEdge` 定义 的静态边仍然执行。如果 `node_a` 返回 `Command(goto="node_c")`，并且你还定义了 `graph.add_edge("node_a", "node_b")`，则 **两者** `node_b` 和 `node_c` 都会运行。

</warning-command-静态边>

## Send API

使用 `Send` 进行分散：从条件边返回 `[Send("worker", {...})]` 以生成并行工作器。需要对结果字段使用 reducer。

|------|----------------|----------|

## 错误处理

将错误类型匹配到正确的处理程序：

<错误处理表>

| 错误类型 | 谁修复 | 策略 | 示例 |
|---|---|---|---|
| 暂时性（网络、速率限制） | 系统 | `RetryPolicy(max_attempts=3)` | `add_node(..., retry_policy=...)` |
| LLM 可恢复（工具故障） | LLM | `ToolNode(tools, handle_tool_errors=True)` | 错误作为 ToolMessage 返回 |
| 用户可修复（缺失信息） | 人工 | `interrupt({"message": ...})` | 收集缺失数据（见 HITL 技能） |
| 意外 | 开发者 | 让其冒泡 | `raise` |

</错误处理表>

## 核心边界

- 从节点返回部分状态更新，而不是直接修改状态。
- 循环通过命名节点路由；`START` 仅用于入口。
- 为累积列表字段定义 reducer；否则，最后写入者胜出。
- 在使用 `Command` 与 `goto` 时考虑静态边，因为两条路由都会执行。
