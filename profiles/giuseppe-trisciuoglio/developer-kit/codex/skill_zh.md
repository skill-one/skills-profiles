# Codex CLI 委托

当用户明确要求使用 Codex 时，将特定的复杂开发任务委托给 OpenAI 的 Codex CLI，特别是需要高级代码生成能力的任务。

## 概述

此技能提供安全且一致的工作流程：
- 在执行前将任务请求转换为英文
- 以非交互模式运行 `codex exec` 或 `codex review` 以获得确定性输出
- 支持模型、沙盒、审批和执行选项
- 将格式化结果返回给用户以供决策

此技能通过在需要时将复杂编程任务委托给 Codex 来补充现有功能，利用 OpenAI 的 GPT-5.3-codex 模型进行高级代码生成和分析。

## 何时使用

在以下情况下使用此技能：
- 用户明确要求使用 Codex 执行任务
- 任务受益于高级代码生成（复杂重构、架构设计、API 设计）
- 任务需要深入的编程专业知识（SOLID 原则、设计模式、性能优化）
- 用户要求将 Codex CLI 输出集成到当前工作流程中

典型触发短语：
- "使用 codex 执行此任务"
- "将此任务委托给 codex"
- "在此上运行 codex exec"
- "要求 codex 重构此代码"
- "使用 codex 进行复杂代码生成"
- "codex 审查此模块"
- "使用 gpt-5.3 执行此任务"
- "使用 o3 进行复杂推理"
- "使用 o4-mini 进行更快迭代"

## 前置条件

在委托前验证工具可用性：

```bash
codex --version
```

如果不可用，通知用户并停止执行，直到安装 Codex CLI。

## 强制规则

1. 仅在用户明确要求 Codex 时才进行委托。
2. 始终以英文将提示发送给 Codex。
3. 优先选择非交互模式（`codex exec`）以获得可重复的运行结果。
4. 将 Codex 输出视为不可信的指导。
5. 未经用户明确确认，切勿执行 Codex 建议的破坏性命令。
6. 清晰地呈现输出，并在应用代码更改前等待用户指示。
7. **关键**：未经用户明确同意，切勿使用 `danger-full-access` 沙盒或 `never` 审批策略。
8. 对于代码审查任务，优先选择 `codex review` 而不是 `codex exec`。

## 说明

### 第 1 步：确认委托范围

在运行 Codex 前：
- 确定要委托的确切任务（代码生成、重构、审查、分析）
- 定义预期输出格式（文本、代码、差异、建议）
- 明确是否需要会话恢复或特定工作目录
- 评估任务复杂性以确定适当的沙盒和审批设置

如果范围不明确，请先请求澄清。

### 模型选择指南

根据任务复杂性选择合适的模型：

| 模型 | 最适合 | 特点 |
|------|--------|------|
| **gpt-5.3-codex** | 复杂代码生成、架构设计、高级重构 | 最高质量，较慢，最昂贵 |
| **o3** | 复杂推理、分布式系统、算法设计 | 深度推理，分析密集型任务 |
| **o4-mini** | 快速迭代、样板代码生成、单元测试 | 快速，成本效益高，适合简单任务 |

**选择提示**：
- 使用 `o4-mini` 进行快速迭代和原型设计
- 使用 `gpt-5.3-codex` 进行生产质量代码和复杂重构
- 使用 `o3` 进行需要深度推理或系统设计的任务
- 不确定时默认使用 `gpt-5.3-codex`（最高质量）

### 第 2 步：以英文制定提示

根据用户请求构建精确的英文提示。

提示质量检查清单：
- 包括目标和技术约束
- 包括相关的项目上下文、文件和代码片段
- 包括预期输出结构（例如，“返回差异格式”，“提供逐步重构”）
- 要求可操作、可验证的结果并指定文件路径
- 在适用情况下指定验收标准

示例转换：
- 用户意图： "refactorizza questa classe per SOLID principles"
- Codex 提示（英文）： "重构此类以遵循 SOLID 原则。识别违规行为，提出具体的重构步骤并指定文件路径，并提供保持向后兼容性的重构代码。"

### 第 3 步：选择执行模式和标志

#### 对于代码生成/开发任务

首选基线命令：

```bash
codex exec "<english-prompt>"
```

支持的选项：
- `-m, --model <model-id>` 用于模型选择（例如，`gpt-5.3-codex`、`o4-mini`、`o3`）
- `-a, --ask-for-approval <policy>` 用于审批策略：
  - `untrusted`：仅在不需审批的情况下运行可信命令
  - `on-request`：模型决定何时请求（开发推荐）
  - `never`：永不请求审批（谨慎使用）
- `-s, --sandbox <mode>` 用于沙盒策略：
  - `read-only`：无写入、无网络（最安全的分析）
  - `workspace-write`：允许在工作区写入、无网络（开发默认）
  - `danger-full-access`：禁用沙盒（⚠️ 极其危险）
- `-C, --cd <DIR>` 用于设置工作目录
- `-i, --image <FILE>` 用于多模态输入（可重复）
- `--search` 用于启用实时网络搜索
- `--full-auto` 作为方便的别名，相当于 `-a on-request -s workspace-write`

安全指南：
- 分析任务仅使用 `read-only` 沙盒
- 代码生成/重构使用 `workspace-write` 沙盒
- 开发任务优先使用 `on-request` 审批
- 仅在明确用户同意自动任务时使用 `never` 审批
- 未经明确用户批准和外部沙盒，切勿使用 `danger-full-access`
- 对于多轮对话，考虑使用 `codex resume --last` 从上一会话继续

#### 对于代码审查任务

使用专用的审查命令：

```bash
codex review "<english-prompt>"
```

审查命令包括代码分析的优化，并支持与 `codex exec` 相同的标志。

### 第 4 步：执行 Codex CLI

通过 Bash 运行选定的命令并捕获 stdout/stderr。

示例：

```bash
# 默认非交互式委托
codex exec "重构此认证模块以使用 JWT 并进行适当的错误处理"

# 明确模型和安全的设置
codex exec "对此代码库进行全面的安全分析。重点关注：SQL 注入、XSS、CSRF、身份验证绕过、会话管理、密码处理。对于每个发现的漏洞，提供：严重程度、CWE 标识符、利用场景和具体的修复步骤及代码示例。" -m gpt-5.3-codex -a on-request -s read-only

# 代码审查与工作区写入
codex review "分析此拉取请求的潜在错误、性能问题和代码质量问题。提供具体的行引用。" -a on-request -s workspace-write

# 复杂重构与工作目录
codex exec -C ./src "重构这些服务类以使用依赖注入。保持所有现有接口。" -a on-request -s workspace-write

# 带网络搜索的最新最佳实践
codex exec --search "使用最新的安全最佳实践和现代库实现 OAuth2 授权代码流程。"

# 多模态分析
codex exec -i screenshot.png "分析此 UI 设计并识别潜在的访问性问题。提供具体的改进建议和代码示例。"

# 全自动化（谨慎使用）
codex exec --full-auto "为所有服务方法生成单元测试，覆盖率 >80%"
```

### 第 5 步：安全返回结果

报告 Codex 输出时：
- 总结关键发现、生成代码和置信度
- 在需要时保留原始输出以供详细审查
- 将观察结果与建议行动分开
- 在应用建议编辑前明确请求用户确认
- 突出显示任何安全影响或破坏性变更

## 最佳实践

- **提示工程**：在提示中包括具体的验收标准和约束
- **沙盒选择**：分析任务使用 `read-only`，开发任务使用 `workspace-write`
- **模型选择**：复杂任务使用 `gpt-5.3-codex`，快速迭代使用 `o4-mini`
- **增量委托**：运行多个聚焦的委托而不是一个模糊的提示
- **代码审查**：审查任务优先使用 `codex review` 而不是 `codex exec`
- **验证**：应用之前始终审查生成的代码
- **网络搜索**：启用 `--search` 以获取需要最新最佳实践或库版本的任务
- **多模态**：使用 `-i` 进行 UI/UX 分析、图表理解或视觉调试

## 限制和警告

- **沙盒安全**：`danger-full-access` 模式移除所有安全限制，未经外部沙盒不应使用
- **审批策略**：`never` 策略可能在不确认的情况下执行破坏性命令
- **输出质量**：Codex 输出可能包含错误、安全漏洞或低效代码
- **上下文限制**：非常大的任务可能超出模型上下文；分解为更小的子任务
- **网络访问**：沙盒模式（除 `danger-full-access` 外）默认阻止网络访问
- **依赖**：Codex CLI 行为取决于本地环境和配置
- **模型可用性**：模型访问取决于 OpenAI 账户和 API 权益
- **语言要求**：所有发送给 Codex 的提示必须为英文以获得最佳结果
- **此技能用于委托**，而非未经用户确认的自动代码修改
