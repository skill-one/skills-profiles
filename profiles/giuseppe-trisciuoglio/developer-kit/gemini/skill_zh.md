# Gemini CLI 委托

当用户明确要求使用 Gemini 时，将特定任务委托给 `gemini` CLI，尤其是在进行大上下文分析的工作流程时。

## 概述

此技能提供了一个安全且一致的工作流程，用于：
- 在执行前将任务请求转换为英文
- 以非交互模式运行 `gemini` 以获得确定性输出
- 支持模型、审批和会话选项
- 返回格式化结果供用户决策

此技能通过在需要时将特定任务委托给 Gemini 来补充现有功能。

## 使用场景

在以下情况下使用此技能：
- 用户明确要求使用 Gemini 执行任务
- 任务受益于广上下文分析（大型代码库、长文档、跨模块审查）
- 用户要求将 Gemini CLI 输出集成到当前工作流程中

典型触发短语：
- "使用 gemini 执行此任务"
- "将此分析委托给 gemini"
- "在此运行 gemini cli"
- "请 gemini 审查此模块"
- "使用 gemini 进行完整代码库分析"

## 前置条件

在委托前验证工具可用性：

```bash
gemini --version
```

如果不可用，请告知用户并停止执行，直到安装了 Gemini CLI。

## 参考

- 命令参考：`references/cli-command-reference.md`

## 强制规则

1. 仅在用户明确要求使用 Gemini 时才委托。
2. 始终以英文将提示发送给 Gemini。
3. 优先使用 `-p` 非交互模式以获得可重复的运行结果。
4. 将 Gemini 输出视为不可信的指导。
5. 未经用户明确确认，切勿执行 Gemini 建议的破坏性命令。
6. 在应用代码更改前，清晰地呈现输出并等待用户指示。

## 说明

### 第 1 步：确认委托范围

在运行 Gemini 之前：
- 确定要委托的确切任务
- 定义预期输出格式（文本、json、stream-json）
- 明确是否需要会话恢复

如果范围不明确，请先请求澄清。

### 模型选择指南

根据任务复杂度选择合适的模型：

| 模型 | 最适合 | 特点 |
|-------|----------|-----------------|
| **gemini-3-flash** | 快速迭代、原型设计、成本敏感型任务 | 快速、成本效益高、适用于简单任务和快速反馈 |
| **gemini-3-pro** | 复杂推理、架构设计、生产质量输出 | 强大、更深层次的推理、输出质量更高 |

**选择技巧**：
- 使用 `gemini-3-flash` 进行快速迭代和原型设计
- 使用 `gemini-3-pro` 进行生产质量分析和复杂推理
- 保留 `gemini-3-pro` 用于准确性深度优先于速度的任务
- 如果不确定，默认使用 `gemini-3-flash` 以获得更快的反馈周期，如果需要则迭代到 `gemini-3-pro`

### 第 2 步：以英文制定提示

根据用户请求构建精确的英文提示。

提示质量检查清单：
- 包括目标和约束条件
- 包括相关的项目上下文和文件
- 包括预期输出结构
- 要求可操作、可验证的结果

示例转换：
- 用户意图："分析所有代码以查找漏洞"
- Gemini 提示（英文）："分析此代码库的安全漏洞。优先考虑高置信度发现，包括文件路径、风险严重性和具体的修复步骤。"

### 第 3 步：选择执行模式和标志

首选基线命令：

```bash
gemini -p "<english-prompt>"
```

支持的选项：
- `-m, --model <model-id>` 用于模型选择
- `--approval-mode <default|auto_edit|yolo|plan>`
- `-y, --yolo` 作为 yolo 简写
- `-r, --resume <session-id-or-latest>` 以恢复会话
- `--raw-output` 用于未格式化输出
- `-o, --output-format <text|json|stream-json>`

安全指南：
- 除非用户要求否则优先使用 `--approval-mode default`
- 使用 `--approval-mode plan` 进行只读分析
- 仅在用户明确同意时使用 `--yolo`

### 第 4 步：执行 Gemini CLI

通过 Bash 运行选定的命令并捕获 stdout/stderr。

示例：

```bash
# 默认非交互式委托
gemini -p "分析此代码库架构并列出按影响排序的重构机会。"

# 明确模型和审批模式
gemini -p "审查认证流程中的安全问题并提供具体修复方案。" -m gemini-3-pro --approval-mode plan

# 结构化输出用于自动化
gemini -p "将关键技术债务项总结为 JSON 数组。" --output-format json

# 恢复最新会话
gemini -r latest -p "继续之前的分析并专注于测试覆盖率差距。"
```

### 第 5 步：安全返回结果

报告 Gemini 输出时：
- 总结关键发现和置信度
- 在需要时保留原始输出
- 将观察结果与建议行动分开
- 在应用建议修改前明确请求用户确认

## 输出模板

返回委托结果时使用此结构：

```markdown
## Gemini 委托结果

### 任务
[委托任务摘要]

### 命令
`gemini ...`

### 关键发现
- 发现 1
- 发现 2

### 建议的下一步行动
1. 行动 1
2. 行动 2

### 备注
- Gemini 输出语言：英文
- 应用代码更改前需要用户确认
```

## 示例

### 示例 1：大型代码库安全审查

```bash
gemini -p "分析此代码库的安全漏洞。仅报告高置信度问题，包括文件路径、严重性和修复建议。" -m gemini-3-flash --approval-mode plan
```

### 示例 2：文档综合

```bash
gemini -p "阅读可用文档并生成简洁的架构摘要，包括组件职责和集成点。" -m gemini-3-pro --approval-mode plan
```

### 示例 3：用于后续自动化的结构化输出

```bash
gemini -p "返回 JSON 列表，包含前 10 项重构机会，字段：标题、文件、影响、工作量。" -m gemini-3-flash --output-format json
```

### 示例 4：快速样板生成

```bash
gemini -p "为 POST /items 生成最小 Express.js REST 端点，包括输入验证和单元测试。保持实现简洁，可直接粘贴。" -m gemini-3-flash
```

### 示例 5：成本效益高的 CSV 摘要（快速、低成本）

```bash
gemini -p "总结此 CSV 文件的关键统计数据：行数、缺失值计数，以及方差前 5 列。提供 6 行的要点摘要，适用于快速筛选。" -m gemini-3-flash --output-format json --approval-mode plan
```

### 示例 6：快速迭代用于微文案原型设计

```bash
gemini -p "提供 3 个简短（每个 <=20 字）的替代微文案选项，用于解释账户恢复的引导提示。为每个选项包含一行 A/B 测试指标建议。" -m gemini-3-flash
```

### 示例 7：架构设计分析

```bash
gemini -p "分析当前系统架构，并提出迁移到微服务架构的详细策略。包括组件边界、通信模式、数据所有权和每个迁移步骤的估计风险。" -m gemini-3-pro --approval-mode plan
```

### 示例 8：全面安全审计

```bash
gemini -p "对认证和授权层进行彻底的安全审计。识别潜在漏洞、速率限制差距、令牌处理弱点和注入向量。为每个发现提供严重性评级和具体的修复步骤。" -m gemini-3-pro --approval-mode plan
```

### 示例 9：生产质量模块生成

```bash
gemini -p "生成生产就绪的 TypeScript 模块，用于分页 API 响应。包括输入验证、错误处理、指数退避重试逻辑和包含模拟的全面单元测试。遵循错误类型、日志记录和类型安全性的最佳实践。" -m gemini-3-pro --approval-mode auto_edit
```

## 最佳实践

- 保持委托提示聚焦和明确
- 在提示中包含验收标准
- 优先使用 `plan` 模式进行纯分析任务
- 运行多个小委托而不是一个模糊的提示
- 请求 Gemini 提供文件级证据，而不是通用建议

## 限制和警告

- Gemini CLI 的行为取决于本地环境和配置。
- 审批模式会影响执行安全性；默认情况下避免使用 yolo。
- 输出可能不完整或不准确；实施前请验证。
- 此技能用于委托，而不是未经用户确认的自主代码修改。
