# 记忆管理.md

提供全面的工程记忆文件管理功能，包括审计、质量评估和针对性改进。此技能确保编码代理通过维护高质量的文档文件（如 `CLAUDE.md`）拥有最佳的工程上下文。

## 概述

工程记忆文件（如 `CLAUDE.md`）是向编码代理会话提供特定工程上下文的主要机制。此技能管理其完整生命周期：发现、质量评估、报告和改进。它遵循一个5阶段的工作流程，确保文档是最新的、可操作的、简洁的。

该技能根据6个维度中的标准化质量标准评估 `CLAUDE.md` 文件：命令/工作流、架构清晰度、非显而易见的模式、简洁性、时效性和可操作性。每个文件都会获得一个（0-100）的分数和字母等级（A-F），并提供具体的改进建议。

## 何时使用

在以下情况下使用此技能：

- 用户明确要求“检查”、“审计”、“更新”、“改进”、“修复”或“维护” `CLAUDE.md`
- 用户提到“`CLAUDE.md` 质量”、“文档审查”或“工程记忆优化”
- 需要为新的项目从零创建工程记忆文件
- 用户询问如何改进 Claude 对代码库的理解
- 文档已过时或过时
- 开始在新代码库上工作并需要理解现有文档
- 用户在会话期间按下 `#` 将学习内容整合到记忆文件中

**触发短语：** "审计 `CLAUDE.md`"、"检查文档质量"、"改进工程上下文"、"审查 `CLAUDE.md`"、"验证文档"

## 说明

### 第一阶段：发现

在仓库中查找所有 `CLAUDE.md` 文件：

```bash
find . -name "CLAUDE.md" -o -name ".claude.md" -o -name ".claude.local.md" 2>/dev/null | head -50
```

**文件类型和位置：**

| 类型 | 位置 | 目的 |
|------|------|------|
| 项目根目录 | `./CLAUDE.md` | 主要项目上下文（提交到 git，与团队共享） |
| 本地覆盖 | `./.claude.local.md` | 个人/本地设置（忽略 git，不共享） |
| 全局默认值 | `~/.claude/CLAUDE.md` | 跨所有项目的用户默认值 |
| 包特定 | `./packages/*/CLAUDE.md` | 单一仓库中的模块级上下文 |
| 子目录 | 任何嵌套位置 | 功能/领域特定上下文 |

### 第二阶段：质量评估

对于每个 `CLAUDE.md` 文件，阅读 [参考资料/质量标准.md](references/quality-criteria.md) 并根据这些标准进行评估：

| 标准 | 权重 | 检查内容 |
|------|------|--------|
| 命令/工作流 | 20分 | 构建/测试/部署命令是否存在且可用？ |
| 架构清晰度 | 20分 | Claude 能否理解代码库结构？ |
| 非显而易见的模式 | 15分 | 是否记录了陷阱和怪癖？ |
| 简洁性 | 15分 | 内容密集且无填充？ |
| 时效性 | 15分 | 是否反映当前代码库状态？ |
| 可操作性 | 15分 | 指令是否可执行且可复制粘贴？ |

**质量分数：** A（90-100）、B（70-89）、C（50-69）、D（30-49）、F（0-29）

### 第三阶段：质量报告输出

**关键：** 在进行任何更新之前，始终输出质量报告。

格式：

```markdown
## `CLAUDE.md` 质量报告

### 摘要
- 发现的文件：X
- 平均分数：X/100
- 需要更新的文件：X

### 文件评估
#### 1. ./CLAUDE.md（项目根目录）
**分数：XX/100（等级：X）**

| 标准 | 分数 | 备注 |
|------|------|------|
| 命令/工作流 | X/20 | ... |
| 架构清晰度 | X/20 | ... |
| 非显而易见的模式 | X/15 | ... |
| 简洁性 | X/15 | ... |
| 时效性 | X/15 | ... |
| 可操作性 | X/15 | ... |

**问题：**
- [列出具体问题]

**建议添加：**
- [列出应添加的内容]
```

### 第四阶段：针对性更新

输出报告后，在更新前请求用户确认。

**阅读 [参考资料/更新指南.md](references/update-guidelines.md) 了解详细的更新原则。**

主要原则：

1. **仅提议针对性添加** - 命令、陷阱、模式、配置
2. **保持简洁** - 避免明显信息、通用建议、一次性修复
3. **显示差异** - 文件、更改（差异格式）、解释

差异格式：

```markdown
### 更新：./CLAUDE.md
**原因：** [简要解释这有助于什么]

```diff
+ ## 快速入门
+
+ ```bash
+ npm install
+ npm run dev
+ ```
```
```

### 第五阶段：应用更新

在用户批准后，使用编辑工具应用更改。保留现有内容结构。

## 最佳实践

1. **在行动前始终阅读参考资料**：质量标准、模板和更新指南包含重要细节
2. **编辑前报告**：在修改 `CLAUDE.md` 之前，始终先提交质量报告
3. **保留现有结构**：更新时，保持现有的组织方式和风格
4. **保持项目特定**：仅添加特定于此代码库的信息，而不是通用建议
5. **验证命令是否工作**：在建议命令之前，通过心理或实际验证它们是否正确执行
6. **使用渐进式披露**：保持 SKILL.md 简洁，将详细标准在单独文件中引用
7. **一致评分**：在所有文件中应用相同的评分标准，以便公平比较

## 限制和警告

1. **未经批准绝不修改**：在编辑 `CLAUDE.md` 文件之前，始终获取用户确认
2. **不要未经询问就删除内容**：如果建议删除，请明确标记并获取批准
3. **尊重 `.claude.local.md`**：这些是个人设置；切勿建议在共享文档中修改它们
4. **避免通用建议**：不要添加“编写良好代码”类型的内容，专注于项目特定模式
5. **保持差异简洁**：仅显示实际更改，而不是整个文件内容
6. **验证文件路径**：在记录之前确保所有引用的文件都存在
7. **客观评分**：始终使用标准一致地评分；不要因文档不完整而虚高分数
