## 字段参考

脚本打印的所有持有百分比都是**可交易流通量的份额**（`1 - 燃烧 - DEX`），而不是总供应量的份额。API 中的 `amount_percentage` 是总供应量的份额；脚本会重新计算它。由于只获取前 100 个持有者，当这 100 个钱包未能覆盖整个流通量时，流通量百分比是一个**下限**；页脚报告实际覆盖率和说明哪种情况适用——覆盖率 <99.5% 时显示下限，前 100 个覆盖全部时显示完整值。

当燃烧 + DEX 留给可交易供应量的比例低于 2%（通常是迁移前的启动板代币），流通量分母会退化：每个 `/ float_share` 会使尘埃钱包的百分比上升到两位数或 100%。脚本会检测到这种情况，打印带有绝对代币/美元数字的横幅，并将评级设置为 ⚪ 无法评估。

当 `token holders` 返回空列表时（代币没有活跃持有者，或上游停止索引它），相同的抑制措施适用。每个百分比都会显示为 0.00%，每个阈值都会通过，因此报告会显示 "✅ 正常——没有明显的倾销风险"。脚本会打印无数据横幅，将每个 "none found 🟢" 行替换为 ⚪，并将评级设置为 ⚪ 无法评估。"无数据"永远不会报告为"无风险"。

在这两种情况下**都不会打印任何流通量百分比**——每个都会显示为 `n/a`（无法评估），每个百分比标志都会显示 ⚪。谨慎打印数字并附带免责声明并不够：除零除法的流通量将 `hold 100.00%` 和 `hold 0.00%` 报告在同一报告中，而一个快速浏览横幅的读者会将 `Rat Trader 1 hold 100.00%` 视为一个发现。钱包数量、代币金额、美元价值和市值仍然会打印——它们不会通过 `float_share`。

基于**总供应量**的百分比仍然会打印（`burn`、`DEX`、流通量份额本身以及芯片质量桶），因为这些分母不受影响。

### "零成本"必须被证明，而不是从缺失的购买计数中推断

`buy_tx_count_cur == 0` 并不意味着钱包免费收到了其筹码。在 musebook（robinhood）上测量：38 个钱包读取 `buy_tx_count_cur: 0` 和 `avg_cost: null`，但其中 **34 个钱包携带有限的 `unrealized_pnl` 比率**（+2.7%、+76.5%、+546%）——这个比率在没有成本依据的情况下无法计算——而 32 个钱包携带 `fomo` 前端标签，2 个携带 `gmgn` 标签，这是活跃交易的痕迹，与收到空投相反。实际上缺失的是该链上的购买交易索引，而 PnL 字段来自单独的计算，并且已经填充。

错误是按链系统性的，而不是按代币。从未购买供应量的份额相同批次：
**robinhood 27.0% 和 41.2%，arc 26.3%，sol 4.8%。** 因此 20% 空投警告门在本质上几乎每个 robinhood/arc 代币上触发，而在 sol 代币上几乎从不触发——这是一个索引覆盖率的差异，而不是芯片结构的差异。报告一个未填充的字段作为风险结论正是这个技能禁止的。

因此，只有当**完全不存在成本证据**时，钱包才被视为零成本：

```python
def has_cost_basis(h):
    return (h.get('avg_cost') or 0) > 0 or h.get('unrealized_pnl') is not None
```

没有索引购买计数但有真实成本依据的钱包**不会从报告中删除**——它们会得到自己的中性行，`买入未记录 / Buy count unindexed`，并显示其流通量份额。上游没有索引它们的购买这一事实是真实的，并且保持可见；它只是不会驱动零成本门。相同的谓词现在管理 `钻石手 / Diamond` 群组（其声明的理由是“一个从未支付的钱包在持有过程中没有成本”，这被已证明的成本基础满足），`转入筹码未动 / Idle airdrop` 行（其“零成本”标题对于这些钱包是一个错误的陈述），以及 Top5 卖风险分类（将一个 +6.6x 的钱包标记为“零成本空投——可以随时倾销”）。

已知限制：一个真实的空投钱包，其 `unrealized_pnl` 是一个巨大的比率，相对于尘埃级别的成本计算，这里会遗漏。没有为它设置第二个比率阈值——没有可测量的样本来校准一个。

### 代币自己的合约地址不是持有者钱包

上游将其作为普通钱包返回——在 musebook（robinhood）上测量：`addr_type: 0`，0 购买，0 出售，15.01% 的总供应量，$5.06M，携带 `fresh_wallet` 标签。如果将其保留在钱包群组中，它会污染 `biggest`、Top10/Top20、空投、新鲜、风险钱包和 Top5，并且它自己会触发 🔴 危险门，因为“最大钱包持有 16.30% — 极端集中”。该代币上最大的真实钱包供应量为 4.10%。同一批次的控制——JOLLY（robinhood）、SI（sol）、ARGUS（arc）——没有这种行，所以这是一个按代币的上游分类差距，而不是链惯例。

因此，脚本将其从 `normal` 中划分出来，并在自己的行上报告，**基于总供应量**（`合约自持 / Contract self-held`），并为其设置自己的警告门，供应量超过 10%。它**不会**从判断中删除：合约持有供应量在释放交易到达后立即进入市场，因此它仍然可见，并且仍然计入评级。这是一个警告而不是危险，因为释放是一个可观察的先验步骤，而不是一个可以随意出售的鲸鱼——并且没有更高的危险等级，因为只有一个样本被测量，并且基于一个样本设置第二个阈值将是一个猜测。

它被故意**不**从流通量分母中扣除。燃烧是永久性的，DEX 池本身就是市场，所以两者都不会倾销；自持供应量可以。将其从分母中删除将提高每个携带此行的代币上其他钱包的百分比，制造新的错误阳性，同时修复一个。

相同的地址也排除在开发者代理映射之外：发送回代币合约的芯片或支付给它的 gas 不是“转移到内部钱包”。

## 评级标准

所有以下阈值都是**可交易流通量的份额**，与脚本匹配。它们与 GMGN 自己的 UI 不兼容，GMGN 的 UI 报告的是总供应量的份额——在一个 LP 持有 56% 供应量的代币上，这里的钱包读数会高 2.4 倍。

建议部分打印**每个**触发的理由，而不仅仅是第一个：⚠️ 谨慎评级意味着定义上触发了两个或多个警告，因此打印一个会让读者无法理解评级为何如此。

进入时间压力（批次浮盈/出货）**不会**影响整体评级——它只影响部分显示。

| 评级（ZH） | 评级（EN） | Emoji | 条件 |
|-------------|-------------|-------|-----------|
| 无法评估 | Cannot Assess | ⚪ | 可交易流通量 <2% 的供应量，**或** 上游返回零持有者（所有百分比规则被抑制；开发者代理仍然升级为 🔴） |
| 不建议买 | Not Recommended | 🔴 | 任何：Rat traders >5% / 最大钱包 >10% / 开发者代理 |

| 谨慎参与 | Caution | ⚠️ | ≥2 的：开发者仍然持有 >1% / 空投 >20% / 风险钱包 >35% / 关联 >15% / 合约自持 >10% 的供应量 |
| 可轻仓   | Light Position | 🟡 | 恰好 1 个上述警告 |
| 正常参与 | Normal | ✅ | 以上所有均无 |

### 每个指标标志阈值

| 指标 | 🔴 | 🟡 | 🟢 |
|--------|----|----|----|
| Top10 集中度 | >60% | >40% | ≤40% |
| Top20 集中度 | >75% | >55% | ≤55% |
| 空投芯片（从未购买） | >25% | >10% | ≤10% |
| 风险钱包 | >35% | >15% | ≤15% |
| 关联资金 | >25% | >10% | ≤10% |
| 零余额钱包 | — | >10% | ≤10% |

钻石手反向（越多越好）并使用自己的 Emoji 集合：✅ >60% / 🟡 >35% / ⚠️ ≤35%。钻石手需要一个**成本基础**（如上文所述）——一个从未支付的钱包在持有过程中没有成本，因此真正的零成本接收者会单独报告为“转入筹码未动 / Idle airdrop”，而不是被计为钻石手。测试是成本基础，而不是 `buy_tx_count_cur > 0`：在购买计数未索引的链上，后者会丢弃大多数真实的钻石手（在 JOLLY 上测量：34 → 75 个钱包，21.1% → 55.7% 的流通量）。

关联资金在任何一个群组在 60 秒内资助时至少升级为 🟡，无论大小——脚本批处理资助是一个结构性信号，而不是幅度信号。

### 芯片质量（页脚）

观察到的钱包持有的三个互斥桶（分母是 `normal_pct`，即基于总供应量，而不是流通量）：**无风险标签购买** / **零成本空投**（如上文 `has_cost_basis` 所述——不是由缺失的购买计数决定） / **风险标签**。它们被单独报告，而不是合并为一个“健康芯片”数字，因为风险标签意味着一个已证明的坏地址，而零成本空投只意味着未知的来源。

标题标志，第一个匹配者胜出：🔴 风险标签 >30% · 🟢 干净 ≥50% · 🟡 干净 ≥30% · 🟡 当零成本空投占非干净剩余的 ≥80% · 🔴 其他情况。因此，一个空投分配的代币会以 🟡 报告其构成，而不是“健康芯片 0.0% 🔴”。

构成是基于总供应量的，因此在退化流通量时仍然有效，其三个百分比仍然会打印——但标题标志在评级为 ⚪ 无法评估时被中和为 ⚪（并且芯片的供应量份额附加）。

## 开发者查找是双源的

`token holders --tag dev` 是主要来源，但在某些启动板上返回 `{"list": []}`——在 robinhood 的 24 小时趋势 Top 50 中的所有五个银行代币上测量，而 pons_v2 / longxyz 代币在同一链上正常返回创建者。它也可以返回没有任何 `creator` 标签的行（在 bsc 上的一个 flap 代币上测量）。无论如何，整个开发者部分，**包括开发者代理危险门**，都会无声地失效。

因此，当没有 `creator`-标签的行返回时，创建者地址从 `token info` 的 `dev.creator_address` 中恢复，`dev.creator_token_balance` 提供其余额。仅在主要来源失败时才进行此调用，因此在标签工作的代币上它不会产生成本。

`token info` 不包含 `realized_profit` 或 `token_transfer_out`，因此在备用路径上：

- 实现利润数字**完全被省略**——打印 `$0` 会将一个未测量的字段报告为测量
- 代理门切换法官：而不是“开发者的芯片去了 Top-100 钱包”，它询问任何 Top-100 持有者的 `native_transfer.from_address` **是否** 是创建者，即开发者支付了该钱包的 gas。命中会被报告为危险并命名钱包；未命中不会被报告为干净，因为在该测量代币上 57% 的持有者携带该字段。

## 备注

- `balance >= 1` 阈值避免尘埃假阳性时识别开发者持有
- SOL `native_balance` 是以 lamports（÷1e9）计；`bsc`/`eth`/`base` 是以 wei（÷1e18）计。`arc`/`stable`/`robinhood` 的十进制数未经证实，因此在这些链上购买力部分报告“未评估”，而不是打印一个可能错误的转换数字。
- 持有者购买力需要一个活跃的原生代币价格，通过 `token info` 在包装的原生地址（`So111…1112` / WBNB / WETH / Base WETH）上获取。当该调用失败时，该部分会回退到原生单位，并且不会打印美元数字。
- `total_supply` 估计为正常钱包的 `balance / amount_percentage` 的中位数
- `cur_price` 估计为正常钱包的 `usd_value / balance` 的中位数
- 进入 MC = `total_supply * avg_cost`，与每个 Top5 钱包的未实现 PnL 一同显示
- Top5 在可用时显示 Twitter 名称；否则 `first4...last4` 格式
- 风险钱包子总计是按类别计算的，并且可以超过去重总数；脚本在发生这种情况时打印携带多个风险标签的钱包数量。
- `creator_ath_info.ath_mc` 在快速拉升后可以落后于代币的当前 MC（上游 `ath_price` 已被观察到等于 `price_24h`）。脚本无法重新计算它，因此当报告的 ATH 落后于当前 MC 超过 5% 时，它会在数字旁边打印陈旧警告，而不是将其呈现为开发者的峰值。
