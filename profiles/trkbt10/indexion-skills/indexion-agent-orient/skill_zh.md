# 代理导向工作流

在开始实施不熟悉或模糊的代码库部分之前，使用此技能。

## 为什么

编码代理经常锚定用户提示中的路径或名词，并在学习仓库的所有权结构之前就开始编辑。`indexion agent orient` 在选定的代码库中构建增量导向地图，然后渲染一个简短、有证据支持的摘要，可以粘贴到 AGENTS.md、CLAUDE.md、一个 Claude 命令、一个 Codex 技能或子代理提示中。

渲染的 `--limit` 只是一个显示限制。所有权推断必须来自完整的预构建地图，包括代码结构、包 README 和由 `wiki pages update`、`wiki pages ingest` 和 `plan reconcile` 维护的维基页面。

所有权配置文件使用包文档和特定于所有者的维基页面。具有多个源根的广泛维基页面是背景信息，但不应将其视为证明每个引用的包都拥有任务的证据。

## 工作流

0. 验证安装的 CLI 具有此工作流：

   ```bash
   indexion agent orient --help
   ```

   如果缺少此命令，请在继续之前更新或重建 indexion。PATH 中有较旧的 `indexion` 二进制文件不足以使用此技能。

1. 生成摘要：

   ```bash
   indexion agent orient --task-file task.md --output=.indexion/cache/agent/orient.md .
   ```

   第一次运行会写入 `.indexion/cache/agent/orient-map.json`。后续运行仅刷新更改的文件和受影响的业主配置文件。当你有意要查询保存的地图而不刷新它时，使用 `--no-update`。这是零知识代理需要从最新预构建地图立即获得所有权猜测的模式。

   对于简短的任务：

   ```bash
   indexion agent orient --task "添加名称/内容漂移审计" .
   ```

   如果用户任务的语言或措辞不在仓库的标识符和 README 评述中，请将原始任务保留在你的笔记中，并将代码库词汇的释义传递给 `--task`。释义应描述目标，而不是怀疑的业主。例如，说“检测名称和实现内容之间的漂移”而不是命名你未确认的包。

   不要将支持基础设施约束放入所有权推断的 `--task` 释义中。将原始请求、所需工具和实施约束保留在笔记或子代理提示中。释义只是用于查询预构建地图的目标词汇，例如：

   ```bash
   indexion agent orient --no-update --task "名称/内容漂移评分和修复计划" .
   ```

2. 编辑前阅读这些部分：

   - `可能的实现业主`：应该拥有领域行为的核心包。
     将第一个条目视为初始业主假设，除非后续证据与之矛盾。
   - `知识来源`：与任务匹配的发布说明、维基页面、README 或其他文档。将其用作背景；不要将纯文档路径视为实现领域行为的地点。
   - `消费者界面`：可能调用核心的 CLI、技能、文档或适配器。
   - `此处不应实现`：应避免作为领域实现目标的文件。
   - `必需的预飞行`：代理在补丁之前应该读取的文件。
   - `导向地图`：确认在显示截断之前使用的文件/业主/文档总集。

3. 使用聚焦工具确认业主：

   ```bash
   indexion doc graph --format=text <可能的业主>
   indexion grep --semantic=name:<术语> .
   indexion search "<任务概念>" .
   ```

   使用摘要和用户任务中的区分性术语，而不仅仅是广泛的基础设施词汇。如果搜索结果偏向支持系统而不是可能的业主，请在使用 `doc graph`、`grep`、`search` 或 `explore` 收集更多证据之前，用实际定义任务的名称/内容、漂移、分歧或特定于领域的术语来细化查询，然后再更改业主。

4. 控制实施：

   - 如果预期的编辑路径出现在 `此处不应实现` 中，停止并解释冲突。
   - 如果预期的业主不在 `可能的实现业主` 中，使用 `doc graph`、`grep`、`search` 或 `explore` 收集更多证据。
   - 除非摘要和后续证据表明它拥有行为，否则不要使 CLI 代码过薄。

5. 用于零知识委托：

   只给子代理任务和生成的导向摘要，然后在分配实施工作之前对其进行提问。它应该立即命名核心实现业主、一个知识来源、一个不安全的编辑位置和一个预飞行证据路径。通过该测试是预构建地图已转移正确的所有权假设的信号。

## 外部代理映射

- Claude 代码：将稳定指导存储在 `CLAUDE.md` 中，将命令投影到 `.claude/commands/` 中，将子代理投影到 `.claude/agents/` 中。
- Codex：将稳定指导存储在 AGENTS.md 或技能中，并将导向摘要粘贴到委托的任务上下文中。
- 多代理工作流：使用摘要作为结构化交接有效负载，以便每个隔离的代理从相同的仓库特定假设开始。
