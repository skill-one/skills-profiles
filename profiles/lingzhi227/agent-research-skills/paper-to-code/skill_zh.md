# 从论文到代码

将一篇研究论文转换为一个完整的、可运行的代码仓库。

## 输入

- `$0` — 论文 PDF 路径、论文文本或论文 URL

## 参考文献

- Paper2Code 提示（规划、分析、编码阶段）：`~/.claude/skills/paper-to-code/references/paper-to-code-prompts.md`

## 工作流程（来自 Paper2Code）

### 阶段 1：规划
通过四轮对话创建一个全面的计划：

1. **总体计划**：提取方法、实验、数据集、超参数、评估指标
2. **架构设计**：生成文件列表、Mermaid classDiagram、sequenceDiagram
3. **任务分解**：按文件进行逻辑分析、依赖排序的任务列表、所需包
4. **配置**：将训练细节提取到 `config.yaml`

### 阶段 2：分析
对任务列表（依赖排序）中的每个文件：
1. 进行详细的逻辑分析
2. 将论文方法映射到代码结构
3. 所有设置参考 `config.yaml`
4. 严格遵循 UML 类图接口

### 阶段 3：编码
对依赖排序的每个文件：
1. 生成代码，可访问所有先前生成的文件
2. 严格遵循设计的数结构和接口
3. 参考 config.yaml — 不虚构配置值
4. 编写完整的代码 — 无 TODO 或占位符

### 阶段 4：调试（如有必要）
如果执行失败：
1. 收集错误信息
2. 使用 SEARCH/REPLACE 差分格式识别根本原因
3. 应用最小化修复，保留原始意图
4. 重新运行直至成功

## 输出结构

```
reproduced_code/
├── config.yaml        # 训练配置
├── main.py            # 入口
├── model.py           # 模型架构
├── dataset_loader.py  # 数据加载
├── trainer.py         # 训练循环
├── evaluation.py      # 指标和评估
├── reproduce.sh       # 运行脚本
└── requirements.txt   # 依赖
```

## 关键约束

- **依赖顺序**：每个文件生成时都可访问所有先前生成的文件
- **接口契约**：Mermaid 图表作为所有阶段的刚性接口定义
- **不虚构**：仅使用论文中明确声明的配置
- **完整代码**：每个函数必须完全实现

## 规则

- 严格遵循论文方法 — 不得虚构改进
- 按依赖顺序生成代码（数据加载 → 模型 → 训练 → 评估 → main）
- 使用 config.yaml 进行所有超参数和设置
- UML 图中的每个类/方法都必须在代码中存在
- 生成 reproduce.sh 脚本以实现一键执行
- 如果论文细节不明确，需明确标注
