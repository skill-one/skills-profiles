## 1. 工具

- `screen-recording-start` — 开始将已启动设备的屏幕录制为视频文件。帧来自与 `screenshot` 和交互工具相同的模拟器服务器后端，并实时编码为 h264 mp4（恒定 30 fps，设备原生分辨率）。
- `screen-recording-stop` — 停止录制，完成容器，并将视频作为可下载的工件检索（`video.hostPath` 用于同地客户端）。

一次每个设备只能进行一次录制；不同设备可以同时录制。录制不会干扰其他读取设备的内容——预览窗口可以保持在同一屏幕上。

---

## 2. 重要提示：切勿让录制持续运行

录制不会在达到 `timeLimitSeconds` 限制前自动停止，因此忘记启动的录制会持续直到限制触发——占用录制会话、浪费磁盘空间，并延迟您等待的视频（并且如果 `trimStatic: false`，视频会以静音填充）。存在两个安全网——使用两者：

1. **录制开始时立即设置提醒。** 您知道预期的捕获时长（即将驱动的交互）。在 `screen-recording-start` 返回后，立即使用您的 harness 提供的任何工具安排唤醒时间——如果有的话，内置的提醒/唤醒或计划任务工具，否则运行 `sleep <expected-seconds>` 的后台 shell，其完成通知将拉回您。当触发时，调用 `screen-recording-stop`。不要依赖记忆。
2. **阅读工具结果备注。** 录制运行时，每个 argent 工具结果都包含一个 `NOTE:` 提醒您录制仍在进行以及如何停止它。如果备注说录制已结束（时间限制达到），仍然调用 `screen-recording-stop`——这是将文件交给您的操作。

## 3. 工作流程

1. 确保目标设备已启动，并且应用程序处于您希望视频打开的状态（`list-devices`，`launch-app`，`argent-device-interact`）。
2. 使用 `udid` 和略高于预期交互时长的 `timeLimitSeconds` 调用 `screen-recording-start`（默认 180，最大 600）。默认情况下，点击和滑动会被绘制到视频中（见下文的触摸可视化备注）；传递 `showTouches: false` 以获取干净的原始屏幕捕获。
3. 设置 §2 中描述的录制结束提醒——此步骤不是可选的。
4. 驱动捕获交互：手势、导航、输入（`argent-device-interact`）。对于紧密的多步交互，优先使用 `run-sequence` 以避免工具调用延迟填充视频。
5. 使用相同的 `udid` 调用 `screen-recording-stop`。它返回 `{ video, durationMs, wallClockMs?, trimmedMs?, warning? }`；`video` 是一个工件，其解析路径指向持久保存的文件（见下文）。当停止返回时视频已最终确定（水印在捕获过程中而不是在二次传递中被打上），因此停止操作不到一秒。
6. 检查 `warning`：它报告限制触发的停止、早期编码器退出、丢失的帧流以及可能被截断的容器。在向用户展示文件前，验证文件可以播放（或者至少有合理的尺寸）。

**文件存储位置（持久，非临时）。** 与大多数 argent 工件（它们存在于操作系统可回收的临时缓存中）不同，完成的录制持久保存在客户端的 `<project>/.argent/recordings/` 中——项目是客户端工作目录最近的祖先，具有 `.git`/`package.json`/`.argent`，或者当客户端不在项目中时为 `~/.argent/recordings/`。即使对于远程 `argent link` 工具服务器也是如此：mp4 文件在客户端主机上写入，而不是服务器上。目标位置可以通过 `recordings.directory` 配置更改（`argent config set recordings.directory <dir>`，默认全局，`--scope project` 用于每个仓库选择；当两者都设置时项目优先）——值可以是绝对路径、`~` 开头或相对于项目根目录，并且始终在客户端主机上解析。保存的名称为 `screen-recording-<device>-<timestamp>.mp4`；如果该名称已被占用，新文件将与其并列存储为 `… (2).mp4` 而不是覆盖。因为这些文件持久存在于工作树中，请向用户提及路径（并注意它们未被跟踪——将它们添加到 `.gitignore` 或清理它们，如果它们不应被提交）。

**静态帧修剪（默认开启）。** 屏幕未变化的时段会被压缩：每个静止时段的第一秒被保留以便暂停读起来自然，然后丢弃未变化的帧直到再次有移动（即使几像素的变化也计算在内）。因此您可以在缓慢步骤、等待时间或思考时间期间运行录制，而不会用静音填充片段——一个 40 秒的会话中有 5 秒的真实活动会返回一个约 5-7 秒的视频。当修剪移除了任何内容时，停止也会返回 `wallClockMs`（实际经过时间）和 `trimmedMs`（被剪掉的量）；`durationMs` 始终是您实际获得的视频长度。当您需要忠实实时录制时（例如，以测量屏幕上某项操作耗时），向 `screen-recording-start` 传递 `trimStatic: false`。

**触摸可视化（默认开启）。** argent 驱动的每个交互都会直接绘制到视频中：每个点击都有一个脉冲标记，滑动和拖动有一条渐隐的彗星轨迹，并且成对的标记显示了捏合或旋转的两个接触点。这使得录制自我解释——观众可以看到每个手势落在哪里，而不是观看 UI 对不可见的指尖做出反应。这是由模拟器服务器渲染到帧流中的（主机端没有合成任何内容），因此不会增加额外成本，并且永远不会出现在 `screenshot` 中。向 `screen-recording-start` 传递 `showTouches: false` 以录制无覆盖层的原始屏幕（例如，当捕获用户实际看到的精确内容时）。如果模拟器服务器无法启用它，录制仍然成功，并且停止会返回一个 `warning`，说明触摸未显示。

## 4. 平台备注和限制

- **可录制内容**：模拟器服务器驱动的任何内容——iOS 模拟器、Android 模拟器和物理 Android 设备。唯一长度限制是 `timeLimitSeconds`（最大 600）。
- **时间线以稳定的 30 fps 速度进行**：设备仅在屏幕变化时发出帧，因此捕获的帧会被重新调度到固定时间线上，而不是堆积。如果关闭静态帧修剪（`trimStatic: false`），时间线与墙钟时间精确匹配——一个完全静止的屏幕仍然会返回一个完整长度的视频（压缩到几乎为空），并且 `durationMs` 与您实际录制的时长匹配。如果开启修剪（默认，见 §3），超出宽限窗口的静止时段会被压缩，因此 `durationMs` 是修剪后的视频长度，`wallClockMs` 包含实际经过时间。
- **Android**：以设备的原生分辨率录制；安全屏幕（DRM、某些密码字段）会显示为黑色。
- **不支持**：tvOS 模拟器、物理 iPhone、Chromium 应用、Vega/Fire TV 以及远程（以 `remote:` 开头）模拟器——它们都没有暴露可读的帧流。对于单个静止帧，使用 `screenshot`；对于可重放的交互脚本，使用 `argent-create-flow` 而不是视频。
- **ffmpeg 是必需的**：它是编码器，因此如果缺失，`screen-recording-start` 会立即以安装提示失败（macOS 上为 `brew install ffmpeg`）。它从 `PATH` 加上通常的 Homebrew 前缀解析。
- **水印**：Argent 标志 + "By @swmansion" 在编码时被打上左下角，淡色（20% 不透明度）并与背景逐像素对比匹配（亮标志覆盖暗 UI，暗标志覆盖亮 UI）。默认开启——使用 `argent disable video-watermark` 关闭（使用 `argent enable video-watermark` 重新启用）。在录制开始时读取该标志。
