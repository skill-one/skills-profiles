# Momentic 模型

Momentic 通过 fork 后的 Playwright、CDP 和自定义代理，将结构化自然语言转化为浏览器自动化。交互步骤可解析自然语言目标，断言可使用多模态模型，AI 操作可完成更广泛的任务。

# 项目文件与格式

测试使用 `*.test.yaml`；可复用模块使用 `*.module.yaml`。测试 ID 位于测试文件中的 `id` 字段。在假定项目默认设置适用之前，请检查 `momentic.config.yaml` 和测试级元数据。

`fileType: momentic/test/v2` 和 `fileType: momentic/module/v2` 用于识别 v2 文件。将缺失或不同的 `fileType` 视为已弃用的 v1。切勿直接编辑 v1 YAML；请通过 `momentic_test_splice_steps` 保存变更。

v2 测试通过 `defaultEnv` 选择环境，并可通过 `--env <name>` 覆盖。不存在回退到配置中唯一环境的机制。基础 URL 来自 `--url-override`，然后是测试自身的 `url`，最后是 `env.BASE_URL`，因此设置了 `url` 的测试在所有环境中都会保留该 URL。若无基础 URL，运行将失败，提示：“无法在缺少基础 URL 且环境变量中未定义 BASE_URL 的情况下运行测试”。

V2 可引用模块、JavaScript 和认证状态，使用相对路径。路径基于包含引用的 YAML 文件进行解析。使用 `./...` 或 `../...`，切勿使用绝对路径或 `~`。在移动、重命名或删除被引用的文件之前，请使用 grep 检索其路径，并更新或删除所有引用。请勿在 v2 YAML 中添加内部或生成的字段。

# 选择工作流程

除非用户有其他要求，否则优先使用这些精简工作流程：

- **已知 v2 变更**：检查附近的模式 → 编辑 YAML → 在语法或引用不确定时进行 lint → 若校验通过则重载或重启 → 运行相关范围。此方式最快，且能产生最清晰、可审查的差异。
- **v1、未知 UI 或交互验证**：启动 MCP 会话 → 运行任何前置条件 → 预览逻辑检查点 → 进行拼接 → 校验已保存范围 → 终止。这使每次编辑都基于实时应用，而无需反复运行整个测试。
- **新测试**：使用 `momentic_test_create` 创建 → 通过一次 YAML 编辑编写已知 v2 序列，或在需要时使用 MCP 逐步操作。`momentic_session_start` 仅打开已存在的测试。

将 MCP 作为默认交互接口：它返回结构化结果、截图、产物、步骤引用和可轮询的执行。预览和运行工具默认等待 30 秒，然后返回 `stepRunnerId`，同时工作继续进行。除非工具调用的超时时间更短，否则多数调用保持 `timeoutSeconds` 未设置，尤其是单个预设步骤。仅在编码代理的工具调用超时时间更短时，将其设置低于 30 秒。仅在更大的工具调用超时时间内需等待更长时间时，将其调高；使用 `momentic_poll_runner` 轮询返回的句柄。

轮询使用独立的 `timeoutSeconds`（默认 0，最大 30）。传入返回的 `stepRunnerId`，并在编码代理的工具调用超时时间内使用非零等待，而不是不断进行无等待的轮询。

# 编辑前

确认测试目标、用户可见的成功标准、起始环境、认证及环境要求。在任何可能提交、购买、删除、发送、创建或导致其他非幂等副作用的操作或 AI 操作进行预览或运行之前，先提出请求。经批准后，最多执行一次。在编辑共享模块、重启长流程或运行昂贵的完整测试之前，也先提出请求。

# 编写规则

- 优先使用自然语言目标。仅当 AI 无法看到目标或用户要求选择器级精度时，才使用选择器或坐标。
- 浏览器操作和检查使用原生 Momentic 步骤。例外情况见 **Test execution behavior** 下的 **JavaScript**。
- 不添加初始导航；会话从测试的基础 URL 开始。
- 保持断言最小且由用户驱动。导航或发生实质性状态变化后，在依赖操作之前验证契约。
- 优先使用 `waitForUrl` 用于 URL 契约，使用 `waitFor` 用于页面/元素检查稳定文本或结构，使用 AI 断言用于语义视觉状态。
- 除非确切交互序列是契约的一部分，否则新测试优先使用 AI Action V3。
- 除非正确性要求，否则不添加可选或默认值字段。
- 保持变更范围狭窄。保留无关的数值、注释、顺序和步骤风格。不得通过弱化测试来掩盖损坏的应用或服务。
- 除非测试意图要求变更，否则保留现有的 `before` / `steps` / `after` 结构。

## AI Action V3

AI Action V3 接收自然语言目标并确定浏览器步骤。

- **默认缓存**：保存并重放成功的流程，自我修复失败的回放步骤。用于可重复的流程。
- **不缓存**：每次运行都全新运行代理。在 v2 中设置 `cache: false`，或使用 `--disable-cache` 配合 `AI_ACTION_DYNAMIC`。对于聊天、智能体工作流、探索性测试及其他动态或非确定行为，优先使用此方式。

将“确保你能完成 X”视为基于目标的测试，除非用户指定了路径。当控件、顺序、中间断言、确定性回放、速度或风险侧效应本身属于测试对象时，使用细粒度步骤。除非被要求变更策略，否则保持现有细粒度测试的细粒度。

# 测试执行行为

## 缓存与内存

Momentic 缓存已解析的选择器、文本、坐标及其他元数据，使大多数运行避免重复的 AI 调用。AI 断言也可能重用过往结果内存。过期缓存或内存可能解释为何快速匹配到错误元素，或反复得出边界性结论。

缓存按 git 元数据（包括分支）作用域。受保护分支读取缓存，但除非使用 `--save-cache` 或设置了 `CI`，否则不写入缓存。

- 当细粒度步骤的意图发生变化时，更改其描述。切勿在定位器步骤中添加 `DANGEROUS_FORCE_DYNAMIC` 或 `--disable-cache`；内置缓存验证处理内容变化。
- 将成功预览的 `CacheId` 带入正在拼接的精确步骤。
- 当旧内存不再匹配其预期条件时，改写断言。
- 关于 AI Action V3 的缓存行为，参见上文 **AI Action V3**。

## 就绪与计时

智能等待在定位步骤之前运行，默认为五秒。在此窗口内，不要添加睡眠。对于更长时间或语义就绪，等待 URL 或使用描述所需正向状态的页面、元素或 AI 检查。检查会重试直至其超时；应增加该超时，而不是用 JavaScript 轮询 UI。参阅
[browser 配置](https://momentic.ai/docs/configuration/browser) 获取项目级计时设置。

## 测试上下文

每次运行都有一个测试作用域的 `env`，跨步骤和模块持久化。

- 在 v2 中，使用 `saveAs` 保存返回值；在 MCP 步骤字符串中，使用 `--env-key`。在 JavaScript 中使用 `setVariable(name, value)` 保存多个值。
- 在 JavaScript 和模块输入表达式中使用 `env.NAME`。在字符串字段中使用 `{{ env.NAME }}`，但不要在内置 JavaScript 源码中。
- 模块输入是存储在字符串中的 JavaScript 片段。引用字面量字符串，并使用 `env.X` 表示变量。

## JavaScript

使用原生的 click、type、hover、wait 和 check 步骤进行浏览器行为。它们保留 Momentic 的智能等待、缓存、追踪和重试。不要使用浏览器 JavaScript 进行点击或输入，也不要在检查可以重试直至其超时的情况下轮询 UI。

使用 Node JavaScript 进行测试设置、数据生成、API、数据库、OTP/邮件/SMS 以及 Momentic 助手。使用浏览器 JavaScript 访问 `window`、`document`、客户端状态，或在没有原生步骤表达该操作时注入页面脚本。保持一次性代码简短，并遵循附近项目的可复用 v2 脚本约定。参阅
[JavaScript 指南](https://momentic.ai/docs/integrations/javascript) 了解运行时 API 和超时详情。

# 使用 v2 YAML

v2 支持人工编辑。测试使用 `before`、`steps` 和 `after`；模块使用 `steps`。每个步骤有一个命令键，选项嵌套于其下。持续时间为毫秒，步骤 ID 不存储在 YAML 中。

做出最小的编辑并匹配附近的语法。若语法不清楚，在 Momentic  monorepo 中工作时，查阅生成的 v2 格式参考 `infra/scripts/v2-json-schema/build/v2-format-reference.md`；或在安装的技能中查阅 https://static.momentic.ai/v2-format-reference.md。当存在 schema 或文件引用风险时，运行 `npx momentic lint`；`momentic app` 和 `momentic run` 也会自动 lint。

磁盘编辑后，若 MCP 测试工具可用，则重载活跃的 MCP 测试；否则终止并重启会话。`momentic_test_get` 读取已持久化的状态，除非其描述说明如此，否则不会刷新活跃会话。

# MCP 浏览器工作流

使用工具描述以及会话启动时返回的 Step Authoring Guide，获取当前参数和步骤语法。请勿重复本技能中的该参考材料。

## 启动与获取上下文

不要将上下文工具视为会话启动的样板代码。按需使用它们，并遵循其描述，尤其是当它们提供过滤器或返回大量项目数据时。

- 若已知测试 ID，仅启动 `momentic_session_start`。其 Test Content 提供活跃步骤和可运行 ID。
- 仅使用 `momentic_get_artifacts` 发现尚未知的项目路径、测试、模块或环境。避免冗余刷新。
- 使用 `momentic_test_get` 在启动前检查已持久化的状态，或读取不同的测试。后续优先使用活跃会话和拼接响应。
- 仅在步骤需要已知不存在的环境数据时，使用过滤后的 `momentic_get_environment_variables`。
- 仅在使用 `momentic_module_recommend` -> `momentic_module_get` 评估复用；推荐会调用 AI 且非启动会话所必需。

v2 YAML 中没有可运行的步骤 ID。使用会话启动或后续拼接响应返回的 ID。

同一会话中只能运行一个浏览器操作。不要针对同一会话发出并行的预览、运行、状态或拼接操作。

## 预览 -> 拼接 -> 校验

1. 对于测试中段工作，运行前一步骤并保持同一会话。这避免了针对错误页面状态进行编写。
2. 在逻辑检查点（如登录完成、表单就绪、提交完成）处正向预览。检查点使浏览器状态可复用，并保持持久化调用可审查。
3. 使用 `momentic_preview_steps` 对相邻步骤预览。它与 `momentic_preview_step` 支持相同的预设、AI Action 和模块步骤。
4. 首先阅读返回的截图。仅当图像缺乏足够的定位或诊断上下文时，才请求浏览器状态；若页面可能仍在稳定，则再请求一次。
5. 拼接成功检查点。仅将返回的 `CacheId` 附加到其精确步骤；无缓存步骤是正常的。立即阅读拼接响应以获取活跃步骤引用。
6. 运行下一个依赖的已保存步骤或范围。若任何预览或运行返回 `stepRunnerId`，则轮询它，而不是启动另一个浏览器操作。
7. 完成前，若安全，运行覆盖前置条件、已变更步骤和下一个依赖契约的最小已保存范围。若累积状态可能掩盖失败，则先重置。
8. 完成后终止会话。

批量处理明显的低风险字段。单独预览不确定的定位器。对于提交、购买、删除、发送或其他非幂等操作，先预览设置，拼接检查点，然后最多运行一次经批准的已保存动作。

在常规编辑期间不要重置。对于嵌套步骤，使用活跃会话或拼接响应返回的父链。

# 模块

对于约四步或以上可复用步骤的逻辑流程，检查 `momentic_module_recommend` -> `momentic_module_get` -> 复用或内联。复用可减少重复的设置，并使测试聚焦于其独特契约。

模块不能包含模块。更改共享模块之前先提出请求。尊重其声明的参数、默认值和枚举值；模块输入是 JavaScript 片段，而非 `{{ }}` 模板。

# 故障排除

## 页面状态与计时

- 页面错误或过期：检查最新的截图或会话状态；若页面正在稳定，可重试一次状态捕获。
- 某检查点就绪缓慢：添加最窄的页面、元素或 AI 检查，或增加现有检查的超时。检查已重试；不要使用 JavaScript 轮询。
- 项目范围内目标定位普遍缓慢：考虑增加 `browser.smartWaitingTimeoutMs`。勿用此参数掩盖单个缓慢断言。
- 长任务或上传：检查具有适当超时的稳定正向结果，而非睡眠。
- 会话漂移：使用 `resetSession: true` 重新运行所需的已保存范围。

## 浏览器与主机资源压力

在浏览器、CDP、页面加载、截图或快照超时后，重试或重置一次。若问题持续或影响多个浏览器工具，则停止变更测试。不要通过等待、弱化断言、缓存标志或重复浏览器调用来掩盖资源压力。

信号包括响应缓慢的页面、文档树或页面执行超时、空 HTML 快照、浏览器或检查器崩溃，以及 `data-momentic-id` 超时。仅页面加载超时可能反而指示应用或网络问题。

使用可用的主机工具检查 CPU、内存和顶部进程。检查浏览器、Momentic、应用服务器、编译器/打包器、数据库及其他无关工作负载。对于已完成的运行，若存在可关联 `attempts/<n>/assets/resource-usage.ndjson`。

报告错误、步骤、URL、重试结果、资源压力、最大消耗者及支持原因。若证据无法区分主机、应用、服务或 Momentic，请说明这一点。

## 定位与断言

- 元素不存在：调试前置条件。元素可见但未找到：使用基于可见文本、角色及附近上下文的标准描述。
- 快速错误匹配元素：考虑过期缓存，然后修正描述。
- 在正常模式下，元素隐藏、禁用、脱离、被遮挡、移动或超出视口导致的错误源于 Playwright 的动作可执行性执行，Momentic 会呈现该问题；这并非 Momentic 定位器 AI 的失败。修正页面状态或前置条件。仅当绕过动作可执行性是预期行为的一部分时，才使用 force。
- 对于某些本就无法满足 Playwright 动作可执行性要求的控件，例如部分富文本编辑器，`browser.visualActions: true` 使用坐标基于的操作。它避免了那些检查，但也放弃了其稳定性保证。参阅 [Visual actions](https://momentic.ai/docs/configuration/browser#browser-visualactions)。
- 仅在使用必须精确出现的文本时才使用加引号的文本；否则描述含义。使断言具体涉及区域、对象、数量或状态。
- 将视觉目标滚动至视图内。使用仅视觉的断言模式处理微妙视觉条件。
- 用步骤断言断言稳定最终状态。对于短暂提示或随时间变化比较，使用视频支持的
[run assertions](https://momentic.ai/docs/core-concepts/writing-assertions#run-assertions)。

## 格式与数据

- v2 加载失败：lint 文件并检查相对引用。
- 模块失败：重新检查参数、默认值、枚举和输入表达式。
- 缺少环境值：验证生成保存的值，以及 `env.X` 与消费者处的 `{{ env.X }}` 是否一致。
- JavaScript 失败：验证 Node 与浏览器上下文。

在相同失败尝试约三次后，停止并向用户寻求方向。
