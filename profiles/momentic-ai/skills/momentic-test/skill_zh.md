# Momentic 模型

Momentic 将结构化自然语言转换为浏览器自动化，使用 forked Playwright、CDP 和自定义代理。交互式步骤解析自然语言目标，断言可以使用多模态模型，AI 动作可以完成更广泛的目标。

# 项目文件和格式

测试使用 `*.test.yaml`；可重用模块使用 `*.module.yaml`。测试 ID 存在于测试文件的 `id` 字段中。在假设项目默认值适用之前，请检查 `momentic.config.yaml` 和测试级别的元数据。

`fileType: momentic/test/v2` 和 `fileType: momentic/module/v2` 识别 v2 文件。将缺失或不同的 `fileType` 视为已弃用的 v1。切勿直接编辑 v1 YAML；通过 `momentic_test_splice_steps` 持续更改。

v2 测试使用 `defaultEnv` 选择其环境，`--env <name>` 覆盖它。没有回退到配置中的唯一环境。基本 URL 来自 `--url-override`，然后是测试自己的 `url`，然后是 `env.BASE_URL`，因此设置 `url` 的测试在所有环境中保持它。如果没有基本 URL，运行将失败："无法在没有基本 URL 且其环境未定义 BASE_URL 变量的情况下运行测试"。

V2 可以使用相对路径引用模块、JavaScript 和认证状态。路径从包含引用的 YAML 文件解析。在移动、重命名或删除引用文件之前，使用 grep 其路径并更新或删除每个引用。不要向 v2 YAML 添加内部或生成的字段。

# 选择工作流程

除非用户要求其他内容，否则优先选择这些紧凑的工作流程：

- **已知的 v2 更改**：检查附近的模式 -> 编辑 YAML -> 当语法或引用不确定时进行代码检查 -> 如果需要验证则重新加载或重新启动 -> 运行相关范围。这是最快的，并产生最清晰的审查差异。
- **V1、未知 UI 或交互式验证**：启动 MCP 会话 -> 运行任何先决条件 -> 预览逻辑检查点 -> 拼接它 -> 验证保存的范围 -> 终止。这使每个编辑都基于实时应用程序，而无需重复运行整个测试。
- **新测试**：使用 `momentic_test_create` 创建 -> 在一个 YAML 编辑中编写已知的 v2 序列，或者在使用发现需要时使用 MCP 逐步操作。`momentic_session_start` 仅打开现有测试。

使用 MCP 作为默认的交互式界面：它返回结构化结果、屏幕截图、工件、步骤引用和可轮询的执行。预览和运行工具默认等待 30 秒，然后在继续工作时返回 `stepRunnerId`。对于大多数调用，特别是单个预设步骤，请保持 `timeoutSeconds` 未设置。仅在编码代理的工具调用超时更短时才将其设置为低于 30 秒。仅在需要在大工具调用超时内等待更长时才提高它；使用 `momentic_poll_runner` 轮询返回的句柄。

轮询具有单独的 `timeoutSeconds`（默认为 0，最大为 30）。传递返回的 `stepRunnerId` 并在编码代理的工具调用超时内使用非零等待，而不是重复轮询而没有等待。

# 编辑前

确认测试目标、用户可见的成功标准、启动环境、认证和环境要求。在预览或运行可能提交、购买、删除、发送、创建或造成其他非幂等副作用步骤或 AI 动作之前询问。如果获得批准，则最多执行一次。还应在编辑共享模块、重新启动长流程或运行昂贵完整测试之前询问。

# 编写规则

- 优先使用自然语言目标。仅在 AI 无法看到目标或用户需要选择器级精度时才使用选择器或坐标。
- 使用原生 Momentic 步骤进行浏览器操作和检查。有关例外情况，请参阅 **JavaScript** 下 **测试执行行为**。
- 不要添加初始导航；会话从测试的基本 URL 开始。
- 保持断言最小且用户驱动。在导航或材料状态更改后，在依赖操作之前验证合同。
- 优先使用 `waitForUrl` 进行 URL 合同，使用页面/元素检查进行稳定文本或结构，并使用 AI 断言进行语义视觉状态。
- 除非精确交互序列是合同的一部分，否则优先使用 AI 动作 V3 编写新测试。
- 除非正确性要求，否则不要添加可选或默认值字段。
- 保持更改范围狭窄。保留不相关的值、注释、顺序和步骤样式。不要通过削弱测试来隐藏损坏的应用程序或服务。
- 除非测试意图需要更改，否则保留现有的 `before` / `steps` / `after` 结构。

## AI 动作 V3

AI 动作 V3 接收自然语言目标并确定浏览器步骤。

- **默认缓存**：保存并重播成功流程，自我修复失败的回放步骤。用于可重复的流程。
- **不缓存**：每次都运行代理。在 v2 中设置 `cache: false` 或使用 `--disable-cache` 与 `AI_ACTION_DYNAMIC`。优先用于聊天、代理工作流、探索性测试和其他动态或非确定性行为。

将“确保你能做 X”视为基于目标的测试，除非用户指定了路线。在控制、顺序、中间断言、确定性回放、速度或风险副作用本身是测试对象时使用粒度步骤。除非要求更改策略，否则保持现有粒度测试粒度。

# 测试执行行为

## 缓存和内存

Momentic 缓存解析的选择器、文本、坐标和其他元数据，因此大多数运行避免了重复的 AI 调用。AI 断言还可能重用过去的内存结果。过时的缓存或内存可以解释快速错误的元素匹配或重复的边界裁决。

缓存由 git 元数据作用域，包括分支。受保护的分支读取缓存，但除非使用 `--save-cache` 或设置 `CI`，否则不会写入它。

- 当其意图更改时更改粒度步骤描述。切勿向定位步骤添加 `DANGEROUS_FORCE_DYNAMIC` 或 `--disable-cache`；内置缓存验证处理更改内容。
- 将成功预览的 `CacheId` 带入正在拼装的精确步骤。
- 当旧的内存不再匹配其预期条件时，重写断言。
- 对于 AI 动作 V3 缓存行为，请参阅上述 **AI 动作 V3**。

## 就绪和定时

智能等待在目标步骤之前运行，默认为五秒。在该窗口内，不要添加睡眠。对于更长时间或语义就绪，等待 URL 或使用描述所需积极状态的页面、元素或 AI 检查。检查在超时前重试；增加该超时而不是使用 JavaScript 轮询 UI。有关项目范围的定时设置，请参阅
[浏览器配置](https://momentic.ai/docs/configuration/browser)。

## 测试上下文

每次运行都有一个跨步骤和模块的测试作用域的 `env`。

- 在 v2 中，使用 `saveAs` 保存返回值；在 MCP 步骤字符串中，使用 `--env-key`。当保存多个值时，在 JavaScript 中使用 `setVariable(name, value)`。
- 在 JavaScript 和模块输入表达式中使用 `env.NAME`。在字符串字段中使用 `{{ env.NAME }}`，但在 JavaScript 源代码中不要使用。
- 模块输入是存储为字符串的 JavaScript 片段。引用字符串并使用 `env.X` 表示变量。

## JavaScript

使用原生的点击、输入、悬停、等待和检查步骤进行浏览器行为。它们保留 Momentic 的智能等待、缓存、跟踪和重试。不要使用浏览器 JavaScript 点击或输入，并且在检查可以重试到其超时之前不要轮询 UI。

使用 Node JavaScript 进行测试设置、数据生成、API、数据库、OTP/电子邮件/SMS 和 Momentic 帮助程序。使用浏览器 JavaScript 访问 `window`、`document`、客户端状态或在没有原生步骤表达操作时注入页面脚本。保持一次性代码简短，并遵循附近项目约定用于可重用的 v2 脚本。有关运行时 API 和超时详细信息，请参阅
[JavaScript 指南](https://momentic.ai/docs/integrations/javascript)。

# 使用 v2 YAML

V2 是可编辑的。测试使用 `before`、`steps` 和 `after`；模块使用 `steps`。每个步骤都有一个命令键，选项嵌套在其下。持续时间以毫秒为单位，步骤 ID 不会存储在 YAML 中。

进行最小的编辑并匹配附近的语法。如果语法不清楚，请在 Momentic 单一代码库中咨询生成的 v2 格式参考
`infra/scripts/v2-json-schema/build/v2-format-reference.md`，或在安装的技能中使用
https://static.momentic.ai/v2-format-reference.md。当模式或文件引用风险需要时，运行 `npx momentic lint`；`momentic app` 和 `momentic run` 也自动进行代码检查。

在磁盘编辑后，如果工具可用，请重新加载活动的 MCP 测试；否则终止并重新启动会话。`momentic_test_get` 读取持久化状态，但不会刷新活动会话，除非其描述说明需要这样做。

# MCP 浏览器工作流程

使用会话启动返回的工具描述和步骤编写指南以获取当前参数和步骤语法。不要从本技能中复制该参考材料。

## 启动和获取上下文

不要将上下文工具作为会话启动的样板调用。按需使用它们并遵循其描述，尤其是在它们提供过滤器或返回大量项目数据时。

- 如果测试 ID 已知，请单独启动 `momentic_session_start`。其测试内容提供活动的步骤和可运行 ID。
- 仅用于发现尚未知的已安装项目路径、测试、模块或环境。避免重复刷新。
- 使用 `momentic_test_get` 在启动前检查持久化状态，或读取不同的测试。之后优先使用活动会话和拼装响应。
- 仅在步骤需要尚未已知的 env 数据时使用过滤的 `momentic_get_environment_variables`。
- 仅在评估重用时使用 `momentic_module_recommend` -> `momentic_module_get`。推荐会话会调用 AI，并且不是启动会话所必需的。

V2 YAML 没有可运行的步骤 ID。使用会话启动或后续拼装响应返回的 ID。

每个会话只能运行一个浏览器操作。不要针对同一会话并发执行预览、运行、状态或拼装操作。

## 预览 -> 拼装 -> 验证

1. 对于测试中的中间工作，运行一次前面的步骤并保持相同的会话。这避免了针对错误页面状态编写。
2. 在逻辑检查点（如登录完成、表单就绪或提交完成）前向预览。检查点使浏览器状态可重用，并保持持久化调用可审查。
3. 使用 `momentic_preview_steps` 预览相邻步骤。它支持与 `momentic_preview_step` 相同的预设、AI 动作和模块步骤。
4. 首先读取屏幕截图。仅在图像缺乏足够的定位或诊断上下文时请求浏览器状态；如果页面可能仍在稳定中，请再次请求它。
5. 拼装成功的检查点。将每个返回的 `CacheId` 仅附加到其精确步骤；无缓存步骤是正常的。立即读取拼装响应以获取活动步骤引用。
6. 运行下一个依赖的保存步骤或范围。如果任何预览或运行返回 `stepRunnerId`，则轮询它，而不是启动另一个浏览器操作。
7. 在安全时，在完成前运行覆盖先决条件、更改步骤和下一个依赖合同的较小保存范围。当累积状态可能掩盖失败时，首先重置。
8. 完成时终止会话。

批量明显的低风险字段。单独预览不确定的定位器。对于提交、购买、删除、发送或其他非幂等操作，预览设置、拼装检查点，然后最多运行一次批准的保存操作。

不要在常规编辑之间重置。对于嵌套步骤，使用活动会话或拼装响应返回的父链。

# 模块

对于大约四个或更多可重用步骤的逻辑流程，请检查 `momentic_module_recommend` -> `momentic_module_get` -> 重用或内联。重用减少了重复的设置，并使测试专注于其独特的合同。

模块不能包含模块。在更改共享模块之前询问。尊重其声明的参数、默认值和枚举值；模块输入是 JavaScript 片段，而不是 `{{ }}` 模板。

# 故障排除

## 页面状态和定时

- 错误或过时的页面：检查最新的屏幕截图或会话状态；如果页面正在稳定中，请重试状态捕获一次。
- 在一个检查点的一个检查点准备缓慢：添加最窄的页面、元素或 AI 检查，或增加现有检查的定时。检查已经重试；不要使用 JavaScript 轮询 UI。
- 项目范围内广泛的定位缓慢：考虑增加
  `browser.smartWaitingTimeoutMs`。不要使用它来掩盖一个缓慢的断言。
- 长任务或上传：使用适当的定时检查稳定的积极结果，而不是睡眠。
- 会话漂移：使用 `resetSession: true` 重新运行所需的保存范围。

## 浏览器和主机资源压力

在浏览器、CDP、页面加载、屏幕截图或快照超时后重试或重置一次。如果它仍然存在或影响多个浏览器工具，请停止更改测试。不要使用等待、较弱的断言、缓存标志或重复的浏览器调用来掩盖资源压力。

信号包括无响应的页面、文档树或页面执行超时、空的 HTML 快照、浏览器或检查器崩溃，以及 `data-momentic-id` 超时。单独的页面加载超时可能指示应用程序或网络。

使用可用的主机工具检查 CPU、内存和顶级进程。检查浏览器、Momentic、应用程序服务器、编译器/打包器、数据库和不相关的负载。对于完成的运行，当存在时，与
`attempts/<n>/assets/resource-usage.ndjson` 相关联。

报告错误、步骤、URL、重试结果、资源压力、最大消费者和支持的原因。如果证据无法区分主机、应用程序、服务或 Momentic，请说明。

## 定位和断言

- 元素不存在：调试先决条件。元素可见但找不到：使用基于可见文本、角色和附近上下文的稳定描述。
- 快速错误的元素匹配：考虑过时的缓存，然后更正描述。
- 在正常模式下，错误指示元素隐藏、禁用、分离、覆盖、移动或超出视口的错误来自 Playwright 的可操作性执行，Momentic 会将其显示出来；它们不是 Momentic 定位 AI 的失败。修复页面状态或先决条件。仅在绕过可操作性是预期行为的一部分时才使用强制。
- 对于有意无法满足 Playwright 可操作性的控件，例如某些富文本编辑器，`browser.visualActions: true` 使用基于坐标的操作。它避免了这些检查，但也放弃了它们的稳定性保证。请参阅 [视觉操作](https://momentic.ai/docs/configuration/browser#browser-visualactions)。
- 仅在确切的文本必须出现时才使用引用文本；否则描述含义。使断言具体关于区域、对象、计数或状态。
- 将视觉目标滚动到视图中。使用仅视觉断言模式进行微妙的视觉条件。
- 使用步骤断言断言稳定的最终状态。对于简短的通知或随时间变化的比较，使用视频支持的
  [运行断言](https://momentic.ai/docs/core-concepts/writing-assertions#run-assertions)。

## 格式和数据

- V2 加载失败：代码检查文件并检查相对引用。
- 模块失败：重新检查参数、默认值、枚举和输入表达式。
- 缺少 env 值：验证产生的保存和 `env.X` 与
  `{{ env.X }}` 在消费者处。
- JavaScript 失败：验证 Node 与浏览器上下文。

大约在三次相同的失败尝试后，停止并要求用户指示。
