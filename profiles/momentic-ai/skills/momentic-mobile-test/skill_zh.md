# Momentic 模型

Momentic Mobile 将结构化自然语言转换为 Android 模拟器和 iOS 模拟器上的原生和 Webview 自动化。交互式步骤将目标解析为设备操作；断言可以检查截图、原生层次结构和 Webview 状态。

# 项目文件和格式

移动测试使用 `*.test.yaml`；模块使用 `*.module.yaml`。测试 ID 存在于测试文件的 `id` 字段中。在假设项目默认值适用之前，请检查 `momentic.config.yaml` 和测试级别的元数据。

`fileType: momentic/mobile-test/v2` 和
`fileType: momentic/mobile-module/v2` 识别移动 v2。将缺失或不同的 `fileType` 视为已弃用的 v1。切勿直接编辑 v1 YAML；通过 `momentic_test_splice_steps` 持续更改。

移动 v2 测试需要 `platform: ANDROID` 或 `platform: IOS`。命令是平台特定的。

一个移动 v2 测试携带它自己的默认值：`defaultEnv` 用于环境变量，`defaultChannel` 用于应用渠道，`defaultTag` 用于标签或别名，例如 `nightly`。`--env`，`--channel` 和 `--tag` 覆盖它们。`defaultTag` 是可选的：如果没有它，运行将安装渠道中的最新标签。在 `local` 区域，测试将安装 `defaultApkFilePath` 或 `defaultAppFilePath`。

V2 可以使用相对路径引用模块、JavaScript 和注入的文件。路径从包含引用的 YAML 文件解析。使用 `./...` 或 `../...`，切勿使用绝对路径或 `~`。在移动、重命名或删除引用文件之前，使用 grep 其路径并更新或删除每个引用。文件支持的 JavaScript 仅限 v2；v1/MCP 步骤字符串将代码内联。不要向 v2 YAML 添加内部或生成的字段。

# 选择工作流程

除非用户要求其他，否则优先选择这些紧凑的工作流程：

- **已知的 v2 更改**：检查附近的模式 -> 编辑 YAML -> 当语法或引用不确定时进行代码检查 -> 如果正在验证，则重新加载或重新启动 -> 运行相关范围。
- **v1、未知 UI 或交互式验证**：启动 MCP 会话 -> 运行任何先决条件 -> 预览逻辑检查点 -> 拼接它 -> 验证保存的范围 -> 终止。
- **新测试**：使用 `momentic_test_create` 创建 -> 在一个 YAML 编辑中编写已知的 v2 序列，或者当需要实时发现时使用 MCP 逐步操作。`momentic_session_start` 仅打开现有测试。

使用 MCP 作为默认的交互式界面。预览和运行默认情况下等待 30 秒，然后在工作继续时返回 `stepRunnerId`。对于大多数调用，特别是单个预设步骤，请保留 `timeoutSeconds` 不变。仅在编码代理的工具超时更短时降低它；仅在更大的工具超时内提高它。使用 `momentic_poll_runner` 池返回的句柄。

优先使用测试配置的远程设备和应用设置。仅在用户明确要求时才使用本地设备或应用覆盖。

# 设置先决条件

运行 `npx momentic-mobile doctor` 进行初始设置和启动，驱动程序、设备或连接失败。使用 `--json` 收集支持报告。请参阅 [doctor 参考](https://momentic.ai/docs/cli-reference/momentic-mobile/commands/doctor)。

远程 Android 需要 adb 和 `ANDROID_HOME`；本地 Android 还需要 Java 和 Android Studio。本地 iOS 需要 macOS 和 Xcode；一旦有模拟器构建可用，远程 iOS 就不需要了。请遵循 [Android](https://momentic.ai/docs/platforms/android/app-setup) 或
[iOS](https://momentic.ai/docs/platforms/ios/app-setup) 设置指南，而不是猜测缺失的依赖项。

Android WebView 自动化需要一个启用了 WebView 调试的构建。调试构建通常提供它；发布构建必须显式启用它。缺少调试通常表现为 `No browser controller is attached to the requested webview`。移动 WebViews 通过设备运行，不需要本地 Chromium 安装。

# 编辑之前

确认目标、用户可见的成功标准、平台、应用源、提供者、认证和环境要求。在预览或运行任何可能提交、购买、删除、发送、创建或引起其他非幂等副作用步骤或 AI 操作之前，请先询问。如果获得批准，则最多执行一次。在本地设备覆盖、编辑共享模块、重新启动长流程或运行昂贵的完整测试之前，也请先询问。

# 编写规则

- 优先使用自然语言目标。仅当 AI 无法看到表面时（例如画布、地图、游戏或非语义自定义视图）才使用坐标。
- 使用原生移动步骤进行设备操作和检查。请参阅 **JavaScript** 下 **测试执行行为** 中的例外情况。
- 除非测试必须切换应用或恢复应用状态，否则不要添加初始启动/打开应用步骤。
- 保持断言最小且用户驱动。在依赖操作之前验证材料状态变化。
- 优先使用元素或屏幕检查进行确定性状态，使用 AI 检查进行语义视觉状态。仅在条件完全可见且层次结构数据不可用、不可靠或不相关时，才使用仅视觉的 AI 检查。
- 仅当用户请求或现有测试已使用时，才使用 AI 操作。
- 除非正确性要求，否则不要添加可选或默认值字段。
- 保持更改范围狭窄。保留不相关的值、注释、顺序和步骤样式。不要通过隐藏应用、资产、权限、数据或后端故障来削弱测试。
- 除非测试意图需要更改，否则保留现有的 `before` / `steps` / `after` 结构。

# 测试执行行为

## 缓存和内存

Momentic 缓存原生选择器、XML 节点、可见文本、Webview 状态、坐标和其他元数据。AI 检查还可能重用过去结果的内存。过时的缓存或内存可以解释快速错误的操作或重复的边界裁决。

缓存由 git 元数据作用域，包括分支。受保护的分支读取缓存，但除非使用 `--save-cache` 或设置 `CI`，否则不会写入它。

- 当步骤意图发生变化时更改步骤描述。切勿向定位步骤添加 `DANGEROUS_FORCE_DYNAMIC` 或 `--disable-cache`；内置缓存验证会重新找到变化的靶标。
- 将成功预览的 `CacheId` 带入正在拼接的确切步骤。
- 当旧的内存不再匹配其预期条件时，重写断言。

## 就绪和定时

`emulator.smartWaitingTimeoutMs` 为 AI 定位、缓存元素重试和其他单次交互等待预算就绪时间。`emulator.waitForStability` 相反，在每次交互步骤后等待，以便其效果在下一步开始之前生效。为加载增量、屏幕之间动画或普遍较慢的应用打开 `waitForStability`。它不控制预定位等待。

在智能等待内，不要添加睡眠。对于更长时间或语义就绪，使用描述所需积极状态的元素、屏幕或 AI 检查。检查在超时前重试；增加该超时而不是使用 JavaScript 进行轮询。请参阅
[移动配置](https://momentic.ai/docs/configuration/mobile) 以获取项目范围的定时设置。

## 常见执行陷阱

- 键盘和输入动画可能与输入竞争。对于慢速 iOS 输入，使用 TYPE 的键盘设置选项。对于移动或格式化字段（移动光标），显式目标输入并在需要时添加按键延迟。
- 滚动描述要显示的内容；滑动描述手指手势。滚动下找到较低的内容，而滑动上则将手指向上移动以显示它。

## 设备、应用和设置

测试级别的设置可以覆盖项目平台、应用资产、模拟器、区域、时区、地理位置、超时、标头和环境默认值。更改行为之前，请检查两个级别。

对于受管理的资产，使用 `momentic_get_artifacts` 的 `channels` 产物作为有效平台渠道、标签和别名的真实来源。遵循当前工具描述的 `defaultChannel` 和 `defaultTag` 行为。

## 测试上下文

每次运行都有一个跨步骤和模块的测试作用域 `env`。

- 在 v2 中，使用 `saveAs` 保存返回值；在 MCP 步骤字符串中，使用 `--env-key`。当保存多个值时，在 JavaScript 中使用 `setVariable(name, value)`。
- 在 JavaScript 和模块输入表达式中使用 `env.NAME`。在字符串字段中使用 `{{ env.NAME }}`，但不要在 JavaScript 源代码内使用。
- 模块输入是存储为字符串的 JavaScript 片段。引用字面量字符串并使用 `env.X` 用于变量。

## JavaScript

使用原生 tap、type、swipe、scroll、wait 和 check 步骤进行设备行为。它们保留 Momentic 的定位、智能等待、缓存和跟踪。当检查可以重试时，不要使用 JavaScript 来重现这些操作或轮询 UI 状态。

使用移动 JavaScript 进行测试设置、数据生成、API、数据库、OTP/电子邮件/SMS、断言和上下文写入，这些没有原生步骤表达。保持一次性代码简短；对于可重用的 v2 脚本，遵循附近的项目约定。请参阅
[移动 JavaScript 命令](https://momentic.ai/docs/reference/mobile-commands/javascript) 以获取当前语法。

# 使用移动 v2 YAML

移动 v2 是可编辑的。测试使用 `before`、`steps` 和 `after`；模块使用 `steps`。每个步骤有一个命令键，持续时间以毫秒为单位，可运行的步骤 ID 不会存储在 YAML 中。

进行最小的编辑并匹配附近语法。常见陷阱：

- iOS 测试中的 Android 唯一命令。
- v2 YAML 中的坐标或 MCP 步骤字符串中的 `0..1` 之外的坐标。
- 添加 ID、缓存块、工件或错误的详细目标字段。

参考 [文件格式](https://momentic.ai/docs/core-concepts/file-format) 以获取顶层结构和 [步骤](https://momentic.ai/docs/core-concepts/steps) 以获取步骤语法。当模式或文件引用风险需要时，运行 `npx momentic-mobile lint`。

磁盘编辑后，如果可用，重新加载活动的 MCP 测试；否则终止并重新启动会话。`momentic_test_get` 读取持久化状态，但不会刷新活动会话。

# MCP 设备工作流程

使用工具描述和会话启动返回的平台特定步骤编写指南以获取当前参数和步骤语法。不要从本技能中重复该参考材料。

## 启动和获取上下文

不要将上下文工具作为会话启动的样板调用。按需使用它们并遵循它们的描述，尤其是在它们提供过滤器或返回大量项目数据时。

- 如果测试 ID 已知，请单独启动 `momentic_session_start`。其测试内容提供活动步骤和可运行 ID；平台来自测试。
- 仅用于发现未知测试、模块、环境、本地设备、模拟器或受管资产渠道。避免冗余刷新。
- 使用 `momentic_test_get` 在启动之前检查持久化状态，或读取不同的测试。之后优先使用活动会话和拼接响应。
- 仅当步骤需要已知的环境数据时，使用过滤的 `momentic_get_environment_variables`。
- 仅当评估重用时，使用 `momentic_module_recommend` -> `momentic_module_get`。推荐会触发 AI，并且不是启动会话所必需的。

每个会话只能运行一个设备操作。不要针对同一会话并发预览、运行、状态或拼接操作。

## 预览 -> 拼接 -> 验证

1. 对于测试中的中途工作，运行一次前面的步骤并保持相同的会话，以便从正确的屏幕开始编写。
2. 在逻辑检查点（如登录完成、权限处理、表单准备、提交完成或确认可见）前向预览。
3. 首先读取截图。仅在图像缺乏足够的定位或诊断上下文时请求模拟器状态；如果应用可能仍在稳定中，请再次请求它。
4. 拼接成功的检查点。将每个返回的 `CacheId` 仅附加到其确切的步骤，然后读取拼接响应以获取当前步骤引用。
5. 运行下一个依赖的保存步骤或范围。如果预览或运行返回 `stepRunnerId`，则轮询它，而不是启动另一个设备操作。
6. 在安全时，在完成之前，运行覆盖先决条件、更改步骤和下一个依赖契约的最小保存范围。仅在累积状态可能掩盖失败时才首先重置。
7. 完成时终止会话。

批量明显的低风险步骤。单独预览不确定的目标。对于非幂等操作，预览设置、拼接检查点，然后最多运行一次批准的保存操作。

MCP 截图是默认信号。请求序列化的模拟器状态以获取可访问的名称、原生 XML、Webview 结构、屏幕边界或离屏上下文。仅在诊断数据、启动或安装行为时读取环境和已安装应用工件。

# 模块

对于大约四个或更多可重用步骤的逻辑流程，检查 `momentic_module_recommend` -> `momentic_module_get` -> 重用或内联。模块不能包含模块。更改共享模块之前请先询问。

尊重声明的参数、默认值和枚举值。模块输入是 JavaScript 片段，不是 `{{ }}` 模板。

# 故障排除

## 设备状态和定时

- 错误或过时的屏幕：检查最新的截图或模拟器状态；如果应用正在稳定中，则重试状态捕获一次。
- 在一个检查点缓慢就绪：添加最窄的元素、屏幕或 AI 检查，或增加现有检查的超时。检查已经重试；不要用 JavaScript 进行轮询。
- 项目中普遍缓慢的定位：考虑增加 `emulator.smartWaitingTimeoutMs`。不要用它来掩盖一个慢速断言。
- 长任务或上传：使用适当的超时检查稳定的积极结果，而不是睡眠。
- 权限对话框或系统表：在继续之前显式处理它。
- 会话漂移：使用 `resetSession: true` 重新运行所需的保存范围。

## 基础设施和应用健康

- 将 WDA、Appium、adb、模拟器启动或死亡、提供者连接性、丢失的 Webview 上下文和重复的设备状态捕获失败视为基础设施或应用环境信号。首先运行上述医生检查，检查日志和设备健康，并在编辑测试之前从干净会话重试。
- 如果应用永远不会空闲，连续动画、视频或后台 UI 工作可能会阻止 iOS 可访问性快照。优先使用禁用它的测试模式开关；更长的等待不会使永久繁忙的应用空闲。
- 不要削弱断言或增加步骤超时以隐藏基础设施故障。将失败的子系统和支持证据与测试逻辑分开报告。

## 定位和断言

- 元素不存在：调试先决条件或滚动状态。元素可见但未找到：使用可见文本、角色/名称和附近上下文。
- 快速错误的操作：考虑过时的缓存，然后更正描述。
- 仅当语义定位不可用时，才使用坐标目标。MCP 分数使用 `0..1`；v2 YAML 使用 `0..100` 的百分比。
- 使用 `SCROLL_TO` 搜索目标。仅在不存在目标或滚动不合适时使用手动 `SWIPE`。
- 引用文本是字面的。仅在必须出现确切文本时才引用；否则描述含义。
- 使断言关于区域、对象、计数或状态具体。仅视觉检查无法检查离屏内容或层次结构。
- AI 检查在超时前重试瞬时快照。优先使用稳定最终状态；使用确定性元素或屏幕检查来表达契约。请参阅
  [编写断言](https://momentic.ai/docs/core-concepts/writing-assertions)。

## 格式和数据

- V2 加载失败：检查文件并检查平台和相对引用。
- 模块失败：重新检查参数、默认值、枚举和输入表达式。
- 缺少环境值：验证产生保存和 `env.X` 与 `{{ env.X }}` 在消费者中的对比。
- 应用启动/安装问题：检查测试设置、渠道/标签、已安装应用工件以及会话是远程还是本地。

大约尝试相同失败三次后，停止并请求用户指示。
