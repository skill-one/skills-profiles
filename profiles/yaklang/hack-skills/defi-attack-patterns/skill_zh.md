## 1. 闪电贷款攻击

### 1.1 机制

闪电贷款提供单交易内的无抵押借款。整个借款 → 使用 → 偿还周期必须原子性完成；若偿还失败，交易将回滚，如同未发生。

| 提供商 | 最大金额 | 费用 |
|---|---|---|
| Aave V3 | 每种资产池流动性 | 0.05%（经批准的借款人可为 0） |
| dYdX | 池流动性 | 0（使用内部余额操纵） |
| Uniswap V3 | 每对资产池流动性 | 0.3%（交换费率等级） |
| Balancer | 池流动性 | 协议可配置 |

### 1.2 价格预言机操纵

```
1. 闪电借款 100,000 WETH
2. 在 AMM_A 上交换 100,000 WETH → TOKEN
   → AMM_A 上的 TOKEN 现货价格飙升
3. 在 Lending_Protocol（读取 AMM_A 现货价格作为预言机）：
   → 存入少量 TOKEN 抵押品（按被高估的价格计算）
   → 借入大量 WETH
4. 将 TOKEN 交换回 → AMM_A 上的 WETH（恢复价格）
5. 偿还闪电贷款（100,000 WETH + 费用）
6. 保留从 Lending_Protocol 借入的 WETH 减去抵押品成本
```

**关键洞察**：使用 AMM 现货储备（`getReserves()`）作为价格预言机的协议易受攻击。必须使用 TWAP 或外部预言机（Chainlink）。

### 1.3 通过重入耗尽流动性池

闪电借款 → 存入池 → 在回调期间触发重入 → 提取超过存入金额 → 偿还贷款。

利用闪电贷款资本与池会计逻辑中的重入组合进行攻击。

### 1.4 治理闪电借款

```
1. 闪电借款治理代币
2. 创建/投票恶意提案（若无快照或时间锁）
3. 提案立即通过
4. 执行提案（耗尽金库、更改管理员等）
5. 返回治理代币
```

防御：基于快照的投票（Compound Governor Bravo）、时间锁、最低提案期。

## 2. 价格预言机操纵

### 2.1 现货价格 vs TWAP

| 预言机类型 | 操纵成本 | 时间窗口 |
|---|---|---|
| 现货价格（`getReserves()`） | 单次大额交换（可闪电借款） | 同一交易 |
| TWAP（时间加权平均） | 持续多区块操纵 | 多个区块（成本高） |
| Chainlink 聚合器 | 攻击 ≥ 多数预言机节点 | 实际上不可行 |

### 2.2 AMM 操纵流程

```
正常状态：池中有 1000 ETH + 1,000,000 USDC → 价格 = 1000 USDC/ETH

攻击：
├── 交换 9000 ETH 进入池
│   池状态：10000 ETH + 100,000 USDC（恒定乘积）
│   现货价格：10 USDC/ETH（下跌 100 倍）
├── 依赖合约读取此价格
│   → 在错误价格下清算头寸
│   → 或允许以 ETH 抵押品进行廉价借款
├── 交换回：用 USDC 购买 ETH
│   价格恢复至 ~1000 USDC/ETH
└── 净利润 = 从依赖合约提取的价值 - 交换滑点 - 费用
```

### 2.3 Chainlink 预言机陈旧性

```solidity
(, int price, , uint updatedAt, ) = priceFeed.latestRoundData();
// 缺少检查：
// 1. price > 0
// 2. updatedAt != 0
// 3. block.timestamp - updatedAt < HEARTBEAT
// 4. answeredInRound >= roundId
```

若预言机陈旧（网络拥堵、L2 序列器宕机），价格可能过时数小时 → 对陈旧价格进行套利。

**L2 序列器风险**：若 Arbitrum/Optimism 序列器宕机，Chainlink 价格冻结。恢复时价格跳跃 → 大规模在错误价格下清算。

## 3. MEV（最大可提取价值）

### 3.1 三明治攻击

```
Mempool 观察：受害者提交交换 TOKEN_A → TOKEN_B，滑点 1%

前跑：购买 TOKEN_B（推高价格）
受害者交易：在滑点容忍范围内执行交换（价格更差）
后跑：出售 TOKEN_B（从价格影响中获利）

利润 = 受害者的价格影响 - 2 × gas 成本
```

### 3.2 JIT（即时）流动性

```
1. 观察 mempool 中的大额待处理交换
2. 在精确价格范围（Uniswap V3 块）提供集中流动性
3. 受害者交换执行 → JIT LP 赚取多数费用
4. 交换后立即移除流动性
5. 利润 = 费用收入 - gas - 不流动性损失（单区块内最小）
```

### 3.3 清算 MEV

```
1. 监控借贷协议中接近清算阈值的头寸
2. 当价格预言机更新时 → 头寸可被清算
3. 前跑其他清算者 → 执行清算
4. 收到清算奖励（通常为抵押品的 5-15%）
5. 出售抵押品获利
```

### 3.4 MEV 保护机制

| 机制 | 工作原理 |
|---|---|
| Flashbots Protect | 将交易发送至私有 mempool；仅区块构建者可见 |
| MEV Blocker | RPC 端点，通过 MEV 感知的中继器路由 |
| Cow Protocol（批量拍卖） | 批量匹配消除排序优势 |
| 加密 mempool | 阈值加密；仅在区块构建时解密 |
| MEV-Share | 用户捕获从其交易中提取的 MEV 部分 |

## 4. 精度损失利用

### 4.1 代币计算中的四舍五入错误

Solidity 没有浮点数。整数除法截断：

```
shares = depositAmount * totalShares / totalAssets
```

若 `totalAssets` 相对于 `depositAmount * totalShares` 非常大，结果将四舍五入为 0 → 存款人未获得份额但池保留存款。

### 4.2 首次存款 / 宝库膨胀攻击

```
1. 攻击者存入 1 wei → 获得 1 份额
2. 攻击者直接向宝库捐赠 1,000,000 代币（非通过存款）
3. 宝库状态：1,000,001 代币，1 份额
4. 受害者存入 999,999 代币：
   shares = 999,999 * 1 / 1,000,001 = 0（整数截断）
5. 受害者获得 0 份额；攻击者拥有宝库 100%（现为 2,000,000 代币）
6. 攻击者全部提款
```

**防御措施**：
- 在首次存款时铸造死份额（OpenZeppelin ERC4626 偏移）
- 要求最低初始存款
- 内部会计使用虚拟偏移

### 4.3 通过精度截断进行灰尘攻击

重复小额操作，每次截断损失 1 wei。跨数千次操作累积 → 实质性损失。

## 5. 治理攻击

### 5.1 闪电贷款治理

借款治理代币 → 投票 → 返回。仅当协议在投票前不快照余额时才有效。

### 5.2 时间锁绕过

| 向量 | 方法 |
|---|---|
| 时间锁设为 0 | 管理员可立即执行提案 |
| `emergencyExecute` 函数 | 对“紧急情况”绕过时间锁 |
| 守护者/多签绕过 | 单点故障 |
| 攻击者取消提案 | 若达到阈值则前跑取消 |

### 5.3 意识阈值操纵

```
协议要求 10% 意识阈值（1000 万代币中的 100 万）
├── 闪电借款 1000 万治理代币
├── 创建提案：设置 admin = 攻击者
├── 用借款代币投票 → 达到意识阈值
├── 若无时间锁：立即执行
└── 返回代币
```

## 6. 桥接器漏洞

### 6.1 常见桥接器攻击向量

| 向量 | 示例 |
|---|---|
| 签名验证绕过 | Ronin Bridge（6.24 亿美元）— 损害 5/9 验证器 |
| 消息重放 | 在多个链上重放存款证明 |
| 假存款证明 | 提交不存在 L1 存款证明 |
| 验证器串通 | 损害多数桥接器验证器 |
| 智能合约漏洞 | Wormhole（3.2 亿美元）— 未初始化的守护者设置 |
| 可升级代理漏洞 | 攻击者获得升级权限 → 交换实现 |

### 6.2 跨链消息验证

```
安全模式：
├── 源链：发出事件（目标、金额、nonce、chainId）
├── 中继器：提交证明（事件包含的 Merkle 证明）
├── 目标链：验证证明针对已知源区块头
│   ├── 检查 nonce 未重放
│   ├── 检查 chainId 匹配
│   ├── 验证 Merkle 证明针对可信根
│   └── 铸造/释放代币

易受攻击模式：
├── 中继器：提交（目标、金额）由 N-of-M 验证器签名
└── 若 M 较小或密钥被攻破 → 模拟签名
```

## 7. 代币标准边缘情况

### 7.1 ERC-20 授权前跑

```
1. Alice 授权 Bob 100 代币
2. Alice 想更改授权为 50 代币
3. Bob 看到授权更改 tx 在 mempool 中
4. Bob 前跑：transferFrom(Alice, Bob, 100) — 使用旧授权
5. Alice 的授权更改执行：授权 = 50
6. Bob 调用 transferFrom(Alice, Bob, 50) — 使用新授权
7. Bob 提取 150 代币而非 50
```

防御：先 `approve(0)`，再 `approve(newAmount)`。或使用 `increaseAllowance/decreaseAllowance`。

### 7.2 ERC-777 通过钩子重入

ERC-777 代币在完成转账前调用接收方上的 `tokensReceived()` 钩子 → 经典重入向量。

```
transfer(attacker, amount)
├── _beforeTokenTransfer 钩子
├── 余额更新
├── tokensReceived() 回调到接收方 ← 重入窗口
│   └── 攻击者重新进入：转账、交换、存款等
└── _afterTokenTransfer 钩子
```

### 7.3 转账费代币

代币在每次转账时扣除费用。协议收到的金额少于 `amount`：

```solidity
// 易受攻击：假设 received == amount
token.transferFrom(msg.sender, address(this), amount);
deposits[msg.sender] += amount; // 因费用多计

// 修复：测量实际余额变化
uint before = token.balanceOf(address(this));
token.transferFrom(msg.sender, address(this), amount);
uint received = token.balanceOf(address(this)) - before;
deposits[msg.sender] += received;
```

### 7.4 贴现代币

自动调整余额的代币（例如 Aave aTokens、stETH）。持有贴现代币的协议若缓存余额可能存在会计不匹配。

## 9. 决策树

```
分析 DeFi 协议？
├── 是否使用价格预言机？
│   ├── 现货价格（AMM 储备）？ → 闪电贷款操纵（第 1.2 节）
│   │   └── 预言机能否单交易操纵？ → 高风险
│   ├── TWAP？ → 需要多区块操纵 → 中风险
│   ├── Chainlink？ → 检查陈旧性处理（第 2.3 节）
│   │   ├── 心跳检查存在？ → 安全
│   │   └── L2？ → 检查序列器可用性预言机
│   └── 多个预言机带回退？ → 评估每个
├── 是否接受外部代币？
│   ├── 是 → 检查转账费处理（第 7.3 节）
│   ├── 接受 ERC-777 代币？ → 通过钩子重入（第 7.2 节）
│   └── 贴现代币？ → 会计不匹配（第 7.4 节）
├── 是否有治理？
│   ├── 是 → 闪电贷款治理可能？（第 5.1 节）
│   │   ├── 基于快照的投票？ → 更安全
│   │   └── 活余额投票？ → 闪电借款攻击
│   ├── 时间锁存在？ → 检查绕过（第 5.2 节）
│   └── 意识阈值 vs 闪电可借款供应？（第 5.3 节）
├── 是否为宝库 / 收益聚合器？
│   ├── 是 → 首次存款攻击（第 4.2 节）
│   │   └── 虚拟偏移或死份额？ → 减轻
│   └── 份额计算中的精度损失？（第 4.1 节）
├── 是否为桥接器？
│   ├── 是 → 加载桥接器向量（第 6 节）
│   │   ├── 验证器集大小和密钥管理？
│   │   ├── 重放保护（nonce + chainId）？
│   │   └── 可升级？ → 谁持有升级密钥？
│   └── 否 → 继续
├── 用户界面交换功能？
│   ├── 是 → MEV 风险（第 3 节）
│   │   ├── 强制执行滑点保护？
│   │   └── 私有 mempool 集成？
│   └── 否 → 继续
└── 加载 [智能合约漏洞](../smart-contract-vulnerabilities/SKILL.md)
    用于底层 Solidity 级别漏洞
```
