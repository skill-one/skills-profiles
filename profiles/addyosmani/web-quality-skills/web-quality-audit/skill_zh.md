# 网页质量审计

全面的品质审查，结合实时浏览器证据与源代码检查。涵盖性能、可访问性、SEO、最佳实践和智能浏览，但不将综合评分视为品质的证明。

> **Lighthouse 13+。** 性能类别现使用共享的 **性能洞察**，跨Lighthouse和DevTools性能面板（[公告](https://developer.chrome.com/blog/moving-lighthouse-to-insights)）。遵循当前洞察名称和证据。无需要求已移除的审计ID或自动重建其建议；其中一些因过于嘈杂、无行动性或易于过度推荐而被淘汰。

## 工作原理

1.  设定审计目标：代表性URL、重要状态和流程、公开与认证访问，以及移动端/桌面端范围。
2.  如果页面可运行，阅读[测量工作流](../performance/references/MEASUREMENT.md)并收集最小化实时基线，再广泛搜索代码库。
3.  使用运行时错误定位源代码检查。将测量结果与仅在代码中发现的假设区分开。
4.  按用户影响和置信度分类，然后进行或建议具体修复。
5.  重新运行等效自动化检查和受影响的手动流程。报告已验证的内容和仍需现场或人工验证的内容。

## 工具路由

使用已有的最佳功能；不要因可选设置而阻塞审计。

| 需求 | 优先路由 | 备用 |
|------|-----------------|----------|
| 性能和核心网页要素 | 记录浏览器性能跟踪并分析聚焦洞察；使用Chrome DevTools MCP时，使用`performance_start_trace`然后`performance_analyze_insight` | Lighthouse CLI或PageSpeed Insights实验室数据 |
| 真实用户性能 | 包含在当前DevTools跟踪摘要中的CrUX值 | PageSpeed Insights/CrUX Vis；仅当密钥已可用或请求自动化时直接使用CrUX API |
| 可访问性、SEO、最佳实践、智能浏览 | 运行实时Lighthouse审计；使用Chrome DevTools MCP时，使用`lighthouse_audit` | 特定类别的Lighthouse CLI审计加上手动检查 |
| 渲染语义和交互 | 检查可访问性树并操作UI；使用Chrome DevTools MCP时，使用`take_snapshot`和聚焦的`evaluate_script` | 浏览器/手动测试 |
| 源代码冒烟测试 | `scripts/analyze.sh <路径>` | 直接源代码检查 |

Chrome DevTools MCP的`lighthouse_audit`有意排除了性能。其导航模式重新加载页面；当保留当前认证或用户创建的状态很重要时，使用快照模式。静态分析器是快速冒烟测试，不能替代渲染页面审计。

## 审计类别

### 性能

**核心网页要素** — 必须通过以获得良好页面体验：
* **LCP（最大内容绘制）< 2.5秒。** 最大可见元素必须快速渲染。优化图像、字体和服务器响应时间。
* **INP（交互到下次绘制）< 200毫秒。** 用户交互必须感觉即时。减少JavaScript执行时间并拆分长任务。
* **CLS（累积布局偏移）< 0.1。** 内容不得跳转。为图像、嵌入和广告设置明确尺寸。

**资源优化：**
* **压缩图像。** 使用WebP/AVIF并设置回退。通过`srcset`提供正确尺寸的图像。
* **最小化JavaScript。** 删除未使用的代码。使用代码拆分。延迟非关键脚本。
* **优化CSS。** 提取关键CSS。删除未使用的样式。避免`@import`。
* **高效字体。** 使用`font-display: swap`。预加载关键字体。子集到所需字符。

**加载策略：**
* **预连接到源。** 为第三方域添加`<link rel="preconnect">`。
* **预加载关键资源。** LCP图像、字体和首屏CSS。
* **懒加载首屏以下内容。** 图像、iframe和重型组件。
* **有效缓存。** 静态资源的长缓存TTL。哈希文件的不可变缓存。

### 可访问性

**可感知：**
* **文本替代。** 每个`<img>`都有有意义的`alt`文本。装饰性图像使用`alt=""`。
* **颜色对比度。** 正常文本最小4.5:1，大文本3:1（WCAG AA）。
* **不要仅依赖颜色。** 使用图标、模式或文本与颜色指示器一起。
* **字幕和文本记录。** 视频有字幕。音频有文本记录。

**可操作：**
* **键盘可访问。** 所有功能均可通过键盘访问。无键盘陷阱。
* **焦点可见。** 所有交互元素都有清晰的焦点指示器。
* **跳过链接。** 为键盘用户提供“跳到主要内容”。
* **足够的时间。** 用户可以延长时间限制。无自动推进内容而无需控件。

**可理解：**
* **页面语言。** 在`<html>`上设置`lang`属性。
* **一致导航。** 页面间相同导航结构。
* **错误识别。** 表单错误清晰描述并与字段关联。
* **标签和说明。** 所有表单输入都有相关标签。

**稳健：**
* **有效的HTML。** 无重复ID。正确嵌套元素。
* **正确使用ARIA。** 优先使用原生元素。ARIA角色与行为匹配。
* **名称、角色、值。** 交互元素具有可访问的名称和正确的角色。

### SEO

**可爬行性：**
* **有效的robots.txt。** 不阻塞重要资源。
* **XML站点地图。** 列出所有重要页面。提交到搜索控制台。
* **规范URL。** 防止重复内容问题。
* **重要页面无noindex。** 检查meta robots和标头。

**页面SEO：**
* **唯一标题标签。** 使每个标题描述性强且简洁；显示截断因设备和结果类型而异。
* **元描述。** 撰写有用、特定页面的摘要；搜索引擎可能会选择不同的片段。
* **标题层次结构。** 主要标题具有描述性且结构逻辑；仅因使用多个`<h1>`而失败有效HTML不会失败。
* **描述性链接文本。** 不是“点击此处”或“阅读更多”。

**技术SEO：**
* **移动友好。** 响应式设计。点击目标≥48像素。
* **HTTPS。** 需要安全连接。
* **页面体验信号。** 使用字段核心网页要素作为证据，不承诺排名变化。
* **结构化数据。** JSON-LD用于丰富片段（文章、产品、常见问题解答等）。

### 最佳实践

**安全：**
* **到处使用HTTPS。** 无混合内容。HSTS启用。
* **无易受攻击的库。** 保持依赖项更新。
* **CSP标头。** 内容安全策略防止XSS。
* **无暴露的源映射。** 生产构建中。

**现代标准：**
* **无弃用API。** 替换`document.write`、同步XHR等。
* **有效的doctype。** 使用`<!DOCTYPE html>`。
* **声明字符集。** `<meta charset="UTF-8">`作为`<head>`中的第一个元素。
* **无浏览器错误。** 清除控制台。无CORS问题。

**用户体验模式：**
* **无侵入式插屏。** 尤其是在移动端。
* **清晰的权限请求。** 仅在需要时请求，并提供上下文。
* **无误导性按钮。** 按钮与其名称相符。

### 智能浏览

使用Lighthouse智能浏览结果作为技术信号，以评估助手理解和与渲染页面交互的能力。

* **可访问的交互表面。** 语义HTML、标签、名称、角色和状态必须在可访问性树中暴露有意义的控件。
* **WebMCP集成在存在时有效。** 审查注册的工具、模式和表单覆盖率；不要仅添加WebMCP以提高审计分数。
* **`llms.txt`是可选的。** 有效文件可能有助于兼容工具发现精选内容，但Lighthouse通过并不证明搜索或AI产品会摄取、排名或引用它。
* **将此类别与SEO声明分开。** 智能可访问性不是搜索排名或AI可见性的证据。

## 严重程度级别

| 级别 | 描述 | 行动 |
|------|-------------|--------|
| **关键** | 安全漏洞，完全失败 | 立即修复 |
| **高** | 核心网页要素失败，主要可访问性障碍 | 发布前修复 |
| **中** | 性能机会，SEO改进 | 在sprint内修复 |
| **低** | 轻微优化，代码质量 | 何时方便何时修复 |

## 审计输出格式

执行审计时，按以下结构组织发现：

```markdown
## 审计结果

### 证据
| 信号 | 范围/条件 | 结果 | 来源 |
|--------|------------------|--------|--------|
| LCP | URL，手机，p75/28天 | 3.1秒（需要改进） | CrUX |
| 可访问性 | URL，移动导航 | 92 | Lighthouse |

### 关键问题（X个发现）
- **[类别]** 问题描述。文件：`路径/到/文件.js:123`
  - **影响：** 这为什么重要
  - **证据：** 测量失败、运行时观察或源假设
  - **修复：** 具体代码更改或建议

### 高优先级（X个发现）
...

### 总结
- 性能：测量状态和X个发现
- 可访问性：自动化状态，X个发现，手动检查待完成/通过
- SEO：X个发现
- 最佳实践：X个发现
- 智能浏览：X个发现或不可用

### 推荐优先级
1. 首先修复此问题，因为...
2. 然后处理...
3. 最后优化...

### 验证
- 在相同条件下重新运行结果
- 完成手动检查
- 现场验证仍待完成
```
