# PRD 生成器

创建清晰、可执行且适用于实施的产品需求文档。

---

## 工作内容

1.  接收用户提交的功能描述
2.  提问 3-5 个必要的澄清问题（使用字母选项）
3.  根据回答生成结构化的 PRD
4.  保存到 `tasks/prd-[feature-name].md`

**重要提示：** 不要开始实施。只需创建 PRD。

---

## 第一步：澄清问题

仅针对初始提示中模糊不清的地方提问。重点关注：

- **问题/目标：** 该功能解决了什么问题？
- **核心功能：** 关键操作是什么？
- **范围/边界：** 它不应该做什么？
- **成功标准：** 我们如何知道它已完成？

### 按此格式提问：

```
1. 该功能的主要目标是什么？
   A. 改善用户引导体验
   B. 提高用户留存率
   C. 减少支持负担
   D. 其他：[请说明]

2. 目标用户是谁？
   A. 仅限新用户
   B. 仅限现有用户
   C. 所有用户
   D. 仅限管理员用户

3. 范围是什么？
   A. 最小可行版本
   B. 完整功能实现
   C. 仅后端/API
   D. 仅 UI
```

这允许用户以 "1A, 2C, 3B" 的形式快速迭代。记住缩进选项。

---

## 第二步：PRD 结构

使用以下部分生成 PRD：

### 1. 简介/概述
简要描述功能及其解决的问题。

### 2. 目标
具体的、可衡量的目标（项目符号列表）。

### 3. 用户故事
每个故事需要：
- **标题：** 简短的描述性名称
- **描述：** "作为一个 [用户]，我想要 [功能]，以便 [收益]"
- **验收标准：** 可验证的完成标准清单

每个故事应该足够小，以便在一个专注的会话中实现。

**格式：**
```markdown
### US-001: [标题]
**描述：** 作为一个 [用户]，我想要 [功能]，以便 [收益]。

**验收标准：**
- [ ] 具体的可验证标准
- [ ] 另一个标准
- [ ] 通过类型检查/代码检查
- [ ] **[仅限 UI 故事]** 使用 dev-browser 技能在浏览器中验证
```

**重要提示：**
- 验收标准必须是可验证的，不能模糊。"工作正常" 是不好的。"删除前显示确认对话框的按钮" 是好的。
- **对于任何涉及 UI 变更的故事：** 始终将 "使用 dev-browser 技能在浏览器中验证" 作为验收标准。这确保了前端工作的视觉验证。

### 4. 功能需求
编号的特定功能列表：
- "FR-1: 系统必须允许用户..."
- "FR-2: 当用户点击 X 时，系统必须..."

明确且无歧义。

### 5. 非目标（超出范围）
该功能不包括的内容。对管理范围至关重要。

### 6. 设计考虑（可选）
- UI/UX 要求
- 如果可用，链接到原型图
- 相关的现有组件以供重用

### 7. 技术考虑（可选）
- 已知的限制或依赖项
- 与现有系统的集成点
- 性能要求

### 8. 成功指标
如何衡量成功？
- "将完成 X 的时间减少 50%"
- "将转化率提高 10%"

### 9. 开放问题
剩余问题或需要澄清的领域。

---

## 面向初级开发者的编写指南

PRD 的读者可能是初级开发者或 AI 代理。因此：

- 明确且无歧义
- 避免行话或解释
- 提供足够的细节以理解目的和核心逻辑
- 编号需求以便于参考
- 在需要时使用具体示例

---

## 输出

- **格式：** Markdown (`.md`)
- **位置：** `tasks/`
- **文件名：** `prd-[feature-name].md`（连字符命名）

---

## 示例 PRD

```markdown
# PRD：任务优先级系统

## 简介

为任务添加优先级级别，以便用户可以专注于最重要的事项。任务可以标记为高、中、低优先级，并具有视觉指示和筛选功能，帮助用户有效管理工作量。

## 目标

- 允许为任何任务分配优先级（高/中/低）
- 提供清晰的优先级级别视觉区分
- 支持按优先级筛选和排序
- 新任务默认为中等优先级

## 用户故事

### US-001：向数据库添加优先级字段
**描述：** 作为一个开发者，我需要存储任务优先级，以便跨会话持久化。

**验收标准：**
- [ ] 在任务表中添加优先级列：'high' | 'medium' | 'low'（默认 'medium'）
- [ ] 生成并成功运行迁移
- [ ] 通过类型检查

### US-002：在任务卡片上显示优先级指示器
**描述：** 作为一个用户，我想一眼看到任务优先级，以便知道首先需要关注什么。

**验收标准：**
- [ ] 每个任务卡片显示彩色优先级徽章（红色=高，黄色=中，灰色=低）
- [ ] 不需要悬停或点击即可看到优先级
- [ ] 通过类型检查
- [ ] 使用 dev-browser 技能在浏览器中验证

### US-003：在任务编辑中添加优先级选择器
**描述：** 作为一个用户，当编辑任务时，我想更改任务的优先级。

**验收标准：**
- [ ] 任务编辑模态框中的优先级下拉菜单
- [ ] 显示当前选中的优先级
- [ ] 选择更改时立即保存
- [ ] 通过类型检查
- [ ] 使用 dev-browser 技能在浏览器中验证

### US-004：按优先级筛选任务
**描述：** 作为一个用户，当我想专注时，我想筛选任务列表以仅显示高优先级项。

**验收标准：**
- [ ] 筛选下拉菜单选项：所有 | 高 | 中 | 低
- [ ] 筛选状态保存在 URL 参数中
- [ ] 没有匹配筛选条件的任务时显示空状态消息
- [ ] 通过类型检查
- [ ] 使用 dev-browser 技能在浏览器中验证

## 功能需求

- FR-1: 在任务表中添加 `priority` 字段 ('high' | 'medium' | 'low', 默认 'medium')
- FR-2: 在每个任务卡片上显示彩色优先级徽章
- FR-3: 在任务编辑模态框中包含优先级选择器
- FR-4: 在任务列表标题中添加优先级筛选下拉菜单
- FR-5: 在每个状态列内按优先级排序（高到中到低）

## 非目标

- 无基于优先级的通知或提醒
- 无基于截止日期的自动优先级分配
- 无子任务的优先级继承

## 技术考虑

- 重用现有的徽章组件并添加颜色变体
- 筛选状态通过 URL 搜索参数管理
- 优先级存储在数据库中，而不是计算得出

## 成功指标

- 用户可以在 2 次点击内更改优先级
- 高优先级任务立即显示在列表顶部
- 任务列表性能无回归

## 开放问题

- 优先级是否应影响列内任务的排序？
- 是否应添加键盘快捷键以更改优先级？

---

## 检查清单

保存 PRD 之前：

- [ ] 使用字母选项提出了澄清问题
- [ ] 结合了用户的回答
- [ ] 用户故事具体且小
- [ ] 功能需求编号且无歧义
- [ ] 非目标部分定义了清晰的边界
- [ ] 保存到 `tasks/prd-[feature-name].md`
