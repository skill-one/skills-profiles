# 性能优化

> **第 2 层：设计选择**

## 核心问题

**瓶颈在哪里？优化值得吗？**

在优化之前：
- 你是否测量过？（不要猜测）
- 可接受的性能是多少？
- 优化会增加复杂性吗？

---

## 性能决策 → 实现

| 目标 | 设计选择 | 实现 |
|------|----------|------|
| 减少分配 | 预分配、重用 | `with_capacity`，对象池 |
| 提升缓存 | 连续数据 | `Vec`，`SmallVec` |
| 并行化 | 数据并行 | `rayon`，线程 |
| 避免复制 | 零复制 | 引用，`Cow<T>` |
| 减少间接引用 | 内联数据 | `smallvec`，数组 |

---

## 思考提示

在优化之前：

1. **你是否测量过？**
   - 先分析 → 火焰图，`perf`
   - 基准测试 → `criterion`，`cargo bench`
   - 确定实际热点

2. **优先级是什么？**
   - 算法（10 倍 - 1000 倍提升）
   - 数据结构（2 倍 - 10 倍）
   - 分配（2 倍 - 5 倍）
   - 缓存（1.5 倍 - 3 倍）

3. **权衡是什么？**
   - 复杂度 vs 速度
   - 内存 vs CPU
   - 延迟 vs 吞吐量

## 向上追溯 ↑

到领域约束（第 3 层）：

```
"这个需要多快？"
    ↑ 询问：性能 SLA 是什么？
    ↑ 检查：`domain-*`（延迟要求）
    ↑ 检查：业务需求（可接受的响应时间）
```

| 问题 | 追溯到 | 询问 |
|------|--------|------|
| 延迟要求 | `domain-*` | 可接受的响应时间是多少？ |
| 吞吐量需求 | `domain-*` | 每秒多少请求？ |
| 内存约束 | `domain-*` | 内存预算是多少？ |

---

## 向下追溯 ↓

到实现（第 1 层）：

```
"需要减少分配"
    ↓ `m01-ownership`：使用引用，避免 `clone`
    ↓ `m02-resource`：用 `with_capacity` 预分配

"需要并行化"
    ↓ `m07-concurrency`：选择 `rayon` 或线程
    ↓ `m07-concurrency`：考虑异步 I/O 密集型

"需要缓存效率"
    ↓ 数据布局：可能时优先 `Vec` 而非 `HashMap`
    ↓ 访问模式：顺序优于随机访问
```

## 优化优先级

```
1. 算法选择     (10 倍 - 1000 倍)
2. 数据结构       (2 倍 - 10 倍)
3. 减少分配       (2 倍 - 5 倍)
4. 缓存优化       (1.5 倍 - 3 倍)
5. SIMD/并行化     (2 倍 - 8 倍)
```

## 常见技巧

| 技巧 | 何时 | 如何 |
|------|------|------|
| 预分配 | 已知大小 | `Vec::with_capacity(n)` |
| 避免克隆 | 热路径 | 使用引用或 `Cow<T>` |
| 批量操作 | 许多小操作 | 收集后处理 |
| `SmallVec` | 通常较小 | `smallvec::SmallVec<[T; N]>` |
| 内联缓冲区 | 固定大小数据 | 数组优于 `Vec` |

## 常见错误

| 错误 | 为什么不对 | 更好的做法 |
|------|------------|------------|
| 未分析就优化 | 错误目标 | 先分析 |
| 调试模式下基准测试 | 毫无意义 | 始终 `--release` |
| 使用 `LinkedList` | 缓存不友好 | `Vec` 或 `VecDeque` |
| 隐藏的 `.clone()` | 不必要的分配 | 使用引用 |
| 过早优化 | 浪费精力 | 先让它工作 |

---

## 反模式

| 反模式 | 为什么不好 | 更好的做法 |
|--------|------------|------------|
| 为避免生命周期而克隆 | 性能成本 | 正确的所有权 |
| 所有东西都装箱 | 间接引用成本 | 可能时栈分配 |
| 用 `HashMap` 处理小集合 | 开销 | `Vec` 加线性搜索 |
| 循环中字符串拼接 | O(n^2) | `String::with_capacity` 或 `format!` |
