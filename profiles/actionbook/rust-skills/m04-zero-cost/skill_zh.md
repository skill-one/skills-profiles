# 零成本抽象

> **第1层：语言机制**

## 核心问题

**我们需要编译时多态还是运行时多态？**

在泛型与特质对象之间进行选择之前：
- 类型是否在编译时已知？
- 是否需要异构集合？
- 性能优先级是什么？

---

## 错误 → 设计问题

| 错误 | 不要只说 | 而应询问 |
|-------|----------------|-------------|
| E0277 | "添加特质约束" | 这个抽象是否在正确的层级？ |
| E0308 | "修复类型" | 类型应该统一还是区分？ |
| E0599 | "导入特质" | 这个特质是否是正确的抽象？ |
| E0038 | "使对象安全" | 我们是否真的需要动态分发？ |

---

## 思考提示

添加特质约束之前：

1. **需要什么样的抽象？**
   - 相同行为，不同类型 → 特质
   - 不同行为，相同类型 → 枚举
   - 无需抽象 → 具体类型

2. **类型何时已知？**
   - 编译时 → 泛型（静态分发）
   - 运行时 → 特质对象（动态分发）

3. **权衡优先级是什么？**
   - 性能 → 泛型
   - 编译时 → 特质对象
   - 灵活性 → 取决于情况

## 向下追溯 ↓

从设计到实现：

```
"需要抽象具有相同行为的类型"
    ↓ 类型在编译时已知 → impl Trait 或泛型
    ↓ 类型在运行时确定 → dyn Trait

"需要不同类型的集合"
    ↓ 封闭集合 → 枚举
    ↓ 开放集合 → Vec<Box<dyn Trait>>

"需要返回不同类型"
    ↓ 相同类型 → impl Trait
    ↓ 不同类型 → Box<dyn Trait>
```

---

## 快速参考

| 模式 | 分发 | 代码大小 | 运行时成本 |
|---------|----------|-----------|--------------|
| `fn foo<T: Trait>()` | 静态 | +膨胀 | 零 |
| `fn foo(x: &dyn Trait)` | 动态 | 最小 | vtable 查找 |
| `impl Trait` 返回 | 静态 | +膨胀 | 零 |
| `Box<dyn Trait>` | 动态 | 最小 | 分配 + vtable |

## 语法对比

```rust
// 静态分发 - 类型在编译时已知
fn process(x: impl Display) { }      // 参数位置
fn process<T: Display>(x: T) { }     // 显式泛型
fn get() -> impl Display { }         // 返回位置

// 动态分发 - 类型在运行时确定
fn process(x: &dyn Display) { }      // 引用
fn process(x: Box<dyn Display>) { }  // 拥有
```

## 决策指南

| 场景 | 选择 | 原因 |
|----------|--------|-----|
| 性能关键 | 泛型 | 零运行时成本 |
| 异构集合 | `dyn Trait` | 运行时不同类型 |
| 插件架构 | `dyn Trait` | 编译时未知类型 |
| 减少编译时间 | `dyn Trait` | 更少的单例化 |
| 小型、已知类型集 | `enum` | 无间接引用 |

---

## 对象安全性

一个特质如果满足以下条件，则称为对象安全的：
- 没有 `Self: Sized` 约束
- 不返回 `Self`
- 没有泛型方法
- 使用 `where Self: Sized` 对非对象安全的方法

---

## 反模式

| 反模式 | 为什么不好 | 更好的做法 |
|--------------|---------|--------|
| 过度泛型化 | 编译时复杂度 | 可能时使用具体类型 |
| 用 `dyn` 对已知类型 | 不必要的间接引用 | 泛型 |
| 复杂的特质层次结构 | 难以理解 | 简单设计 |
| 忽略对象安全性 | 限制灵活性 | 如有必要计划使用 dyn |
