# 并发

> **第一层：语言机制**

## 核心问题

**这是 CPU 密集型还是 I/O 密集型，以及共享模型是什么？**

在选择并发原语之前：
- 工作负载类型是什么？
- 需要共享哪些数据？
- 线程安全要求是什么？

---

## 错误 → 设计问题

| 错误 | 不要只说 | 而是问 |
|------|----------|--------|
| E0277 发送 | "添加 Send 限制" | 这个类型需要跨线程传递吗？ |
| E0277 同步 | "用 Mutex 包装" | 真的需要共享访问吗？ |
| Future 不是 Send | "使用 spawn_local" | 异步是正确的选择吗？ |
| 死锁 | "重新排序锁" | 锁定设计是否正确？ |

---

## 思考提示

添加并发之前：

1. **工作负载是什么？**
   - CPU 密集型 → 线程 (std::thread, rayon)
   - I/O 密集型 → 异步 (tokio, async-std)
   - 混合型 → 混合方法

2. **共享模型是什么？**
   - 无共享 → 消息传递 (通道)
   - 不可变共享 → Arc<T>
   - 可变共享 → Arc<Mutex<T>> 或 Arc<RwLock<T>>

3. **Send/Sync 要求是什么？**
   - 跨线程所有权 → Send
   - 跨线程引用 → Sync
   - 单线程异步 → spawn_local

## 向下追溯 ↓

从设计到实现：

```
"需要 CPU 工作的并行性"
    ↓ 使用：std::thread 或 rayon

"需要 I/O 的并发性"
    ↓ 使用：async/await 与 tokio

"需要在线程之间共享不可变数据"
    ↓ 使用：Arc<T>

"需要在线程之间共享可变数据"
    ↓ 使用：Arc<Mutex<T>> 或 Arc<RwLock<T>>
    ↓ 或：通道进行消息传递

"需要简单的原子操作"
    ↓ 使用：AtomicBool, AtomicUsize 等
```

## Send/Sync 标记

| 标记 | 含义 | 示例 |
|------|------|------|
| `Send` | 可以在线程之间转移所有权 | 大多数类型 |
| `Sync` | 可以在线程之间共享引用 | `Arc<T>` |
| `!Send` | 必须保持在单一线程 | `Rc<T>` |
| `!Sync` | 没有跨线程共享引用 | `RefCell<T>` |

## 快速参考

| 模式 | 线程安全 | 阻塞 | 使用场景 |
|------|----------|------|----------|
| `std::thread` | 是 | 是 | CPU 密集型并行 |
| `async/await` | 是 | 否 | I/O 密集型并发 |
| `Mutex<T>` | 是 | 是 | 共享可变状态 |
| `RwLock<T>` | 是 | 是 | 读取密集型共享状态 |
| `mpsc::channel` | 是 | 可选 | 消息传递 |
| `Arc<Mutex<T>>` | 是 | 是 | 跨线程共享可变 |

## 决策流程图

```
工作类型是什么？
├─ CPU 密集型 → std::thread 或 rayon
├─ I/O 密集型 → async/await
└─ 混合型 → 混合 (spawn_blocking)

需要共享数据吗？
├─ 无 → 消息传递 (通道)
├─ 不可变 → Arc<T>
└─ 可变 →
   ├─ 读取密集型 → Arc<RwLock<T>>
   └─ 写入密集型 → Arc<Mutex<T>>
   └─ 简单计数器 → AtomicUsize

异步上下文？
├─ 类型是 Send → tokio::spawn
├─ 类型是 !Send → spawn_local
└─ 阻塞代码 → spawn_blocking
```

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| E0277 `Send` 不满足 | 非发送类型在异步中 | 使用 Arc 或 spawn_local |
| E0277 `Sync` 不满足 | 非同步共享 | 用 Mutex 包装 |
| 死锁 | 锁定顺序 | 一致的锁定顺序 |
| `future is not Send` | 跨 await 的非发送 | 在 await 前丢弃 |
| `MutexGuard` 跨 await | 持有期间暂停时锁定 | 适当的作用域锁定 |

---

## 反模式

| 反模式 | 为什么不好 | 更好 |
|--------|------------|------|
| Arc<Mutex<T>> 处处使用 | 竞争条件，复杂性 | 消息传递 |
| thread::sleep 在异步中 | 阻塞执行器 | tokio::time::sleep |
| 跨 await 持有锁 | 阻塞其他任务 | 紧密作用域锁定 |
| 忽略死锁风险 | 难以调试 | 锁定顺序，try_lock |

## 异步特定模式

### 避免 MutexGuard 跨 await

```rust
// 不好：锁定跨越 await
let guard = mutex.lock().await;
do_async().await;  // guard 仍然持有！

// 好：锁定作用域
{
    let guard = mutex.lock().await;
    // 使用 guard
}  // guard 释放
do_async().await;
```

### 异步中的非发送类型

```rust
// Rc 是 !Send，不能在 spawned 任务中跨 await
// 选项 1：使用 Arc 代替
// 选项 2：使用 spawn_local (单线程运行时)
// 选项 3：确保 Rc 在 .await 前释放
```
