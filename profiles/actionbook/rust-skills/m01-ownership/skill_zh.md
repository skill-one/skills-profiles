# 所有权与生命周期

> **第一层：语言机制**

## 核心问题

**谁应该拥有这些数据，以及拥有多长时间？**

在修复所有权错误之前，理解数据的作用：
- 它是共享的还是独占的？
- 它是短暂的还是持久的？
- 它是被转换的还是仅仅被读取？

---

## 思考提示

在修复所有权错误之前，请问：

1. **这些数据的作用域角色是什么？**
   - 实体（唯一标识）→ 拥有
   - 值对象（可互换）→ 克隆/复制可以
   - 临时的（计算结果）→ 可能需要重构

2. **所有权设计是故意的吗？**
   - 设计上 → 在约束内工作
   - 意外 → 考虑重新设计

3. **修复症状还是重新设计？**
   - 如果是第三次尝试（第三次尝试）→ 升级到第二层

## 向下追溯 ↓

从设计决策到实现：

```
"数据需要不可变地共享"
    ↓ 使用：Arc<T>（多线程）或 Rc<T>（单线程）

"数据需要独占所有权"
    ↓ 使用：移动语义，获取所有权

"数据是只读视图"
    ↓ 使用：&T（不可变借用）
```

---

## 快速参考

| 模式 | 所有权 | 成本 | 使用场景 |
|---------|-----------|------|----------|
| 移动 | 转移 | 零 | 调用者不需要数据 |
| `&T` | 借用 | 零 | 只读访问 |
| `&mut T` | 独占借用 | 零 | 需要修改 |
| `clone()` | 复制 | 分配 + 复制 | 实际上需要一个副本 |
| `Rc<T>` | 共享（单线程） | 引用计数 | 单线程共享 |
| `Arc<T>` | 共享（多线程） | 原子引用计数 | 多线程共享 |
| `Cow<T>` | 写时复制 | 如果被修改则分配 | 可能会修改 |

## 错误代码参考

| 错误 | 原因 | 快速修复 |
|-------|-------|-----------|
| E0382 | 值被移动 | 克隆、引用或重新设计所有权 |
| E0597 | 引用比所有者生存时间更长 | 扩展所有者范围或重构 |
| E0506 | 借用时赋值 | 在修改前结束借用 |
| E0507 | 从借用中移动 | 克隆或使用引用 |
| E0515 | 返回局部引用 | 返回拥有的值 |
| E0716 | 临时代码被丢弃 | 绑定到变量 |
| E0106 | 缺少生命周期 | 添加 `'a` 注解 |

## 反模式

| 反模式 | 为什么不好 | 更好 |
|--------------|---------|--------|
| `.clone()` 处处使用 | 隐藏设计问题 | 正确设计所有权 |
| 与借用检查器对抗 | 增加复杂性 | 与编译器合作 |
| `'_static' 对所有内容 | 限制灵活性 | 使用适当的生命周期 |
| 使用 `Box::leak` 泄漏 | 内存泄漏 | 正确设计生命周期 |
