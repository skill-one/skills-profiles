# 资源管理

> **第一层：语言机制**

## 核心问题

**这个资源需要哪种所有权模式？**

在选择智能指针之前，请理解：
- 所有权是单一的还是共享的？
- 访问是单线程的还是多线程的？
- 是否存在潜在的循环？

---

## 错误 → 设计问题

| 错误 | 不要只说 | 而应询问 |
|------|----------|----------|
| "需要堆分配" | "使用 Box" | 为什么不能在栈上分配？ |
| Rc 内存泄漏 | "使用 Weak" | 设计中是否必须存在循环？ |
| RefCell 危机 | "使用 try_borrow" | 运行时检查是否是正确的方案？ |
| Arc 开销抱怨 | "接受它" | 是否确实需要多线程访问？ |

---

## 思考提示

在选择智能指针之前：

1. **所有权模型是什么？**
   - 单一所有者 → Box 或 owned value
   - 共享所有权 → Rc/Arc
   - 弱引用 → Weak

2. **线程上下文是什么？**
   - 单线程 → Rc, Cell, RefCell
   - 多线程 → Arc, Mutex, RwLock

3. **是否存在循环？**
   - 是 → 其中一个方向必须是 Weak
   - 否 → Rc/Arc 即可


---

## 向下追溯 ↓

从设计到实现：

```
"需要单所有者的堆数据"
    ↓ 使用：Box<T>

"需要单线程共享不可变数据"
    ↓ 使用：Rc<T>

"需要多线程共享不可变数据"
    ↓ 使用：Arc<T>

"需要打破引用循环"
    ↓ 使用：Weak<T>

"需要共享可变数据"
    ↓ 单线程：Rc<RefCell<T>>
    ↓ 多线程：Arc<Mutex<T>> 或 Arc<RwLock<T>>
```

---

## 快速参考

| 类型 | 所有权 | 线程安全 | 使用场景 |
|------|--------|----------|----------|
| `Box<T>` | 单一 | 是 | 堆分配、递归类型 |
| `Rc<T>` | 共享 | 否 | 单线程共享所有权 |
| `Arc<T>` | 共享 | 是 | 多线程共享所有权 |
| `Weak<T>` | 弱引用 | 与 Rc/Arc 相同 | 打破引用循环 |
| `Cell<T>` | 单一 | 否 | 内部可变性 (Copy 类型) |
| `RefCell<T>` | 单一 | 否 | 内部可变性 (运行时检查) |

## 决策流程图

```
需要堆分配？
├─ 是 → 单一所有者？
│        ├─ 是 → Box<T>
│        └─ 否 → 多线程？
│                ├─ 是 → Arc<T>
│                └─ 否 → Rc<T>
└─ 否 → 栈分配 (默认)

存在引用循环？
├─ 是 → 使用 Weak 在一个方向上
└─ 否 → 使用常规 Rc/Arc

需要内部可变性？
├─ 是 → 需要线程安全？
│        ├─ 是 → Mutex<T> 或 RwLock<T>
│        └─ 否 → T: Copy? → Cell<T> : RefCell<T>
└─ 否 → 使用 &mut T
```

---

## 常见错误

| 问题 | 原因 | 修复 |
|------|------|------|
| Rc 循环泄漏 | 相互强引用 | 在一个方向上使用 Weak |
| RefCell 危机 | 运行时借用冲突 | 使用 try_borrow 或重构 |
| Arc 开销 | 热路径中的原子操作 | 如果是单线程，考虑使用 Rc |
| 不必要的 Box | 数据适合在栈上 | 移除 Box |

---

## 反模式

| 反模式 | 为什么不好 | 更好的做法 |
|--------|------------|------------|
| 到处使用 Arc | 不必要的原子开销 | 单线程时使用 Rc |
| 到处使用 RefCell | 运行时恐慌 | 设计清晰的所有权 |
| 小类型使用 Box | 不必要的分配 | 栈分配 |
| 忽略 Weak 以解决循环 | 内存泄漏 | 设计父子关系时使用 Weak |
