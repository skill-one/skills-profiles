# 错误处理

> **第一层：语言机制**

## 核心问题

**这是预期的失败还是bug？**

在选择错误处理策略之前：
- 正常操作中是否可能失败？
- 谁应该处理这个失败？
- 调用者需要什么上下文？

---

## 错误 → 设计问题

| 模式 | 不要只说 | 询问相反 |
|------|----------|----------|
| 解包panic | "使用?" | 在这里实际可能吗？None/Err |
| 类型不匹配在?上 | "使用anyhow" | 错误类型设计是否正确？ |
| 丢失错误上下文 | "添加.context()" | 调用者需要知道什么？ |
| 过多的错误变体 | "使用Box<dyn Error>" | 错误粒度是否正确？ |

---

## 思考提示

在处理错误之前：

1. **这是什么类型的失败？**
   - 预期 → Result<T, E>
   - 缺失是正常的 → Option<T>
   - bug/不变性 → panic!
   - 无法恢复 → panic!

2. **谁处理这个？**
   - 调用者 → 使用?传播
   - 当前函数 → match/if-let
   - 用户 → 友好的错误消息
   - 程序员 → 带消息的panic

3. **需要什么上下文？**
   - 错误类型 → thiserror变体
   - 调用链 → anyhow::Context
   - 调试信息 → anyhow或tracing

---

## 向上追溯 ↑

当错误策略不明确时：

```
"我应该返回Result还是Option吗？"
    ↑ 询问：缺失/失败是正常的还是异常的？
    ↑ 检查：m09-domain（领域说明是什么？）
    ↑ 检查：domain-*（错误处理要求）
```

| 情况 | 追溯到 | 问题 |
|------|--------|------|
| 过多的解包 | m09-domain | 数据模型是否正确？ |
| 错误上下文设计 | m13-domain-error | 需要什么恢复？ |
| 库与应用程序错误 | m11-ecosystem | 消费者是谁？ |

---

## 向下追溯 ↓

从设计到实现：

```
"预期失败，库代码"
    ↓ 使用：thiserror用于类型化错误

"预期失败，应用程序代码"
    ↓ 使用：anyhow用于便捷错误

"缺失是正常的（查找、获取、查询）"
    ↓ 使用：Option<T>

"bug或不满足不变性"
    ↓ 使用：panic!, assert!, unreachable!

"需要带上下文传播"
    ↓ 使用：.context("发生了什么")
```

---

## 快速参考

| 模式 | 当...时 | 示例 |
|------|--------|------|
| `Result<T, E>` | 可恢复错误 | `fn read() -> Result<String, io::Error>` |
| `Option<T>` | 缺失是正常的 | `fn find() -> Option<&Item>` |
| `?` | 传播错误 | `let data = file.read()?;` |
| `unwrap()` | 仅开发/测试 | `config.get("key").unwrap()` |
| `expect()` | 不变性成立 | `env.get("HOME").expect("HOME设置")` |
| `panic!` | 无法恢复 | `panic!("关键失败")` |

## 库与应用程序

| 上下文 | 错误库 | 原因 |
|------|--------|------|
| 库 | `thiserror` | 为消费者提供类型化错误 |
| 应用程序 | `anyhow` | 便捷的错误处理 |
| 混合 | 两者 | 边界处使用thiserror，内部使用anyhow |

## 决策流程图

```
失败是预期的吗？
├─ 是 → 缺失是唯一的"失败"吗？
│        ├─ 是 → Option<T>
│        └─ 否 → Result<T, E>
│                 ├─ 库 → thiserror
│                 └─ 应用程序 → anyhow
└─ 否 → 这是bug吗？
        ├─ 是 → panic!, assert!
        └─ 否 → 考虑是否真的无法恢复

使用? → 需要上下文吗？
├─ 是 → .context("消息")
└─ 否 → 纯? ?
```

---

## 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| `unwrap()` panic | 未处理的None/Err | 使用?或match |
| 类型不匹配 | 不同的错误类型 | 使用anyhow或From |
| 丢失上下文 | 无上下文的? | 添加.context() |
| `cannot use ?` | 缺少Result返回 | 返回Result<(), E> |

---

## 反模式

| 反模式 | 为什么不好 | 更好 |
|------|----------|------|
| `.unwrap()`到处使用 | 生产中panic | `.expect("原因")`或? |
| 沉默地忽略错误 | 隐藏bug | 处理或传播 |
| 使用panic!处理预期错误 | 差的体验，无恢复 | Result |
| 到处使用Box<dyn Error> | 丢失类型信息 | thiserror |
