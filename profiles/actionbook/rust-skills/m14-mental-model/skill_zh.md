# 心智模型

> **第 2 层：设计选择**

## 核心问题

**如何正确地思考 Rust 的这个概念？**

在学习或解释 Rust 时：
- 正确的心智模型是什么？
- 应该避免哪些误解？
- 哪些类比有助于理解？

---

## 关键心智模型

| 概念 | 心智模型 | 类比 |
|------|----------|------|
| 所有权 | 唯一钥匙 | 只有一个人持有房子钥匙 |
| 移动 | 钥匙交接 | 把你的钥匙给别人 |
| `&T` | 借读 | 借一本书 |
| `&mut T` | 独占编辑 | 只有你能编辑文档 |
| 生命周期 `'a` | 有效范围 | “票有效至…” |
| `Box<T>` | 堆指针 | 遥控器指向电视 |
| `Rc<T>` | 共享所有权 | 多个遥控器，最后一个关闭 |
| `Arc<T>` | 线程安全 Rc | 来自任何房间的遥控器 |

## 其他语言背景

| 来源 | 关键转变 |
|------|----------|
| Java/C# | 默认情况下值是拥有的，而不是引用 |
| C/C++ | 编译器强制执行安全规则 |
| Python/Go | 没有垃圾回收，确定性销毁 |
| 函数式 | 通过所有权使可变性安全 |
| JavaScript | 没有 null，使用 Option 代替 |

## 思考提示

当对 Rust 感到困惑时：

1. **所有权模型是什么？**
   - 谁拥有这些数据？
   - 它存活多久？
   - 谁可以访问它？

2. **Rust 提供了什么保证？**
   - 没有数据竞争
   - 没有悬垂指针
   - 没有使用后释放

3. **编译器在告诉我什么？**
   - 错误 = 违反安全规则
   - 解决方案 = 遵守规则

## 常见误解

| 错误 | 错误模型 | 正确模型 |
|------|----------|----------|
| E0382 使用后移动 | 垃圾回收清理 | 所有权 = 唯一钥匙转移 |
| E0502 借用冲突 | 允许多个写入者 | 一次只有一个写入者 |
| E0499 多个可变借用 | 别名修改 | 可变修改的独占访问 |
| E0106 缺少生命周期 | 忽略范围 | 引用具有有效性范围 |
| E0507 不能从 `&T` 移动 | 隐式克隆 | 引用不拥有数据 |

## 已弃用的思考方式

| 已弃用 | 更好的方式 |
|------|----------|
| “Rust 像是 C++” | 不同的所有权模型 |
| “生命周期是垃圾回收” | 编译时有效性范围 |
| “克隆解决一切” | 重新结构所有权 |
| “对抗借用检查器” | 与编译器合作 |
| “`unsafe` 来规避规则” | 首先理解安全模式 |

## 所有权可视化

```
栈                          堆
+----------------+            +----------------+
| main()         |            |                |
|   s1 ─────────────────────> │ "hello"        |
|                |            |                |
| fn takes(s) {  |            |                |
|   s2 (移动) ─────────────> │ "hello"        |
| }              |            | (s1 无效)      |
+----------------+            +----------------+

移动后：s1 不再有效
```

## 引用可视化

```
+----------------+
| data: String   |────────────> "hello"
+----------------+
       ↑
       │ &data (不可变借用)
       │
+------+------+
| reader1    reader2    (多个 OK)
+------+------+

+----------------+
| data: String   |────────────> "hello"
+----------------+
       ↑
       │ &mut data (可变借用)
       │
+------+
| writer (唯一)
+------+
```
