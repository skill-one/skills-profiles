# Buddy Sings — 让你的 Claude 代码宠物唱歌

将你的 Claude 代码宠物变成一个歌手。每个宠物都会根据它的名字和个性获得一个独特的声音身份——同一个宠物总是听起来一样。

## 前置条件

- **mmx CLI**（用于音乐生成，必需）：

  **安装：**
  ```bash
  npm install -g mmx-cli
  ```

  **认证（仅首次）**：
  ```bash
  mmx auth login --api-key <your-minimax-api-key>
  ```
  从 [MiniMax 平台](https://platform.minimaxi.com/) 获取你的 API 密钥。

- **音频播放器**（用于播放——至少需要一个）：
  - `mpv`（推荐——交互式控制：空格键=暂停，q=退出）
  - `ffplay`（来自 FFmpeg）
  - `afplay`（macOS 内置）

---

## 工作流程概述

```
检查宠物 → 构建声音身份 → 收集上下文 → 生成音乐 → 播放并提供反馈
```

---

## 语言与交互

从用户的第一条消息中检测用户的语言。在整个会话中用同一种语言回应。
以下所有示例都是英文的——在其他语言中回应时，请自然地翻译它们。

**面向用户的文本本地化规则**：
- 所有向用户显示的文本——包括宠物信息、声音描述、歌词预览、提示预览、播放信息和反馈提示——必须完全翻译成用户的语言。
- 发送给模型的 **API 提示** 应始终用英文编写，以获得最佳生成质量。但是，在向用户预览提示时，应显示用户语言的本地化描述，而不是原始英文提示。英文提示是内部实现细节——用户不需要看到它。
- 以下模板用英文编写作为参考。在运行时，将每个标签和消息翻译成用户检测到的语言。

宠物默认用用户的语言唱歌。将唱歌语言自然地嵌入声音描述中（例如，“用日语唱歌”或“用中文唱歌”），而不是附加一个单独的语言标签。如果用户明确要求歌词使用不同的语言，请满足该要求。

## 第 1 步：检查宠物

读取 `~/.claude.json` 并查找 `companion` 字段。

如果没有找到伴侣或该字段为空，告诉用户：

```
你还没有宠物！输入 /buddy 来领养一个，然后回来让它唱歌。
```

在这里停止并等待用户领养宠物。如果没有宠物，不要继续。

如果存在伴侣，提取其资料：
- `name` — 宠物的名字
- `personality` — 宠物的个性描述

向用户展示宠物：

```
找到你的宠物了！
   名字：<name>
   个性：<personality>
```

---

## 第 2 步：构建声音身份

根据宠物的 **名字** 和 **个性** 文本，创造性地设计一个独特的声音身份。不要查找模板——自由地解释个性。

### 如何将个性解释为声音

阅读个性文本并制作声音属性：

- **音色**：这个个性听起来像什么？例如，“话不多”→ 低沉、温暖、深思熟虑； “充满活力”→ 明亮、有冲击力； “神秘”→ 气息、黑暗； “传奇胖次”→ 厚重、温暖、舒适
- **唱歌风格**：他们会如何演唱歌曲？例如，“话不多”→ 稀疏、戏剧性的停顿； “俏皮”→ 活泼、有节奏感； “诗意”→ 流畅、连贯
- **情绪**：什么情绪适合？例如，“轻松”→ 放松、随和； “激烈”→ 强烈、有力

构建一个 `prompt_fragment` 来描述声音风格，自然地嵌入唱歌语言。例如：

```
声音：温暖低沉的女性声音用中文唱歌，具有舒适厚重的音色，
稀疏极简的交付方式，带有戏剧性的停顿，赋予每个字分量，放松随和的情绪。
```

### 声音缓存

声音身份必须 **缓存**，以便宠物总是听起来一样。

- 缓存文件：`~/.claude/skills/buddy-sings/voices/<name>.json`
- 缓存格式：
  ```json
  {
    "name": "Moth",
    "personality": "一个话不多传奇胖次。",
    "prompt_fragment": "声音：温暖低沉的女性声音用中文唱歌...",
    "cached_at": "2026-04-07T19:52:15"
  }
  ```

**首次**：没有缓存存在 → 解释个性 → 保存到缓存文件。

**后续调用**：读取缓存 → 直接使用保存的 `prompt_fragment`。
不要重新解释——一致性很重要。

**缓存失效**：如果 `~/.claude.json` 中的 `personality` 与缓存的不同，宠物已经改变——重新生成并保存新的缓存。

**手动再生**：如果用户说“改变声音”或“再生声音”：
删除缓存文件并从头开始重新解释。

### 向用户展示声音

```
<name> 的独特声音：

音色：<音色描述>
风格：<风格描述>
情绪：<情绪描述>

让我们选择 <name> 应该唱什么！
```

## 第 3 步：理解意图并收集上下文

**不要总是显示模式菜单**。相反，分析用户的请求以确定需要什么上下文，并自动收集它。

### 自动上下文检测

当用户的请求暗示个人上下文时，**自动**扫描相关信息，而无需询问。触发条件包括：

- **时间参考**： "今天"、"本周"、"最近"、"昨天" → 扫描当前对话历史和记忆文件，查找那个时间段发生了什么
- **个人参考**： "我的工作"、"我的日常"、"我做了什么" → 扫描记忆和对话，查找用户的活动
- **关系参考**： "我们的故事"、"我们一起做了什么" → 扫描记忆，查找用户和宠物/Claude 之间的共同经历

### 上下文收集（自动，不受模式限制）

当需要上下文时，按顺序扫描这些来源：

1. **当前对话上下文**：查看用户在这个 Claude 代码会话中做了什么——编辑的文件、运行的命令、讨论的主题。
   这是“今天”类型请求最丰富的来源。

2. **记忆文件**：扫描相关记忆：
   ```bash
   find ~/.claude/projects/*/memory/ -name "*.md" 2>/dev/null | head -20
   ```
   如果存在，也检查 `~/.claude/memory/`。
   读取找到的文件并提取与用户请求相关的主题。

3. **Git 历史记录**（如果在仓库中）：对于与工作相关的歌曲，检查最近的提交：
   ```bash
   git log --oneline --since="today" 2>/dev/null | head -10
   ```

使用收集到的上下文来丰富歌词提示——使歌曲个性化并具体到实际发生的事情，而不是通用的。

### 无需上下文的情况

如果用户的请求是一个明确的独立场景（例如，“唱一首雨天歌曲”、“唱一首摇篮曲”），跳过上下文收集并直接进行音乐生成。

### 上下文不明确的情况

只有在您确实无法确定用户想要什么时才询问澄清。不要显示模式菜单——问一个具体的问题：

```
<name> 应该唱什么？

例如：
  - "今天的工作" — 我会检查你最近在做什么
  - "我的宠物在我回家时守在窗边"
  - 或者让我随机选择一个主题？
```

### 落实随机

如果上下文收集没有找到有用的内容（没有记忆文件、没有对话历史、没有 git 日志），回退到基于宠物的个性生成随机主题：
- 安静/内向的个性 → 午夜摇篮曲、温柔的日落、安静的早晨
- 充满活力的个性 → 派对歌曲、冒险歌曲、胜利进行曲
- 神秘的个性 → 月光小夜曲、秘密低语、梦境之旅

告诉用户选择了什么主题。

## 第 4 步：生成音乐

将声音身份与选择的主题结合起来。

1. **构建完整提示**：提示有两个部分必须都存在：

   **部分 A — 声音身份（必须首先出现）**：始终以缓存的 `prompt_fragment` 开头提示。这是最重要的部分——它定义了谁在唱歌。将它在提示的开头放置，以便 API 优先考虑它。

   **部分 B — 流派/风格/情绪标签**：选择与主题匹配的标签，而不是默认集。有意地根据歌曲的内容变化流派。

   将提示写成 **生动的英文句子**，而不是逗号分隔的标签。
   遵循这个模式：`A [情绪] [流派] 歌曲，以 [声音描述] 为特色，
   关于 [叙事/主题]，[氛围]，[关键乐器和制作]。`
   将声音描述为角色（“性感男中音带爵士口音”），而不仅仅是性别。包括场景或氛围来锚定生成。

   **流派匹配指南**——选择一个适合主题能量的流派：

   | 主题能量 | 建议的流派 | 避免 |
   |-------------|-----------------|-------|
   | 鼓励/激励/欢呼 | 独立摇滚、合成流行、放克、说唱 | 独立民谣、治愈 |
   | 日常生活/温暖/陪伴 | 华语流行、城市流行、波萨诺瓦 | 与上次相同 |
   | 思念/等待 | 民谣、R&B、低保真 | 摇滚、电子舞曲 |
   | 幽默/嘲讽/抱怨 | 放克、说唱、斯卡、电子流行 | 古典、抒情 |
   | 深夜/安静 | 环境、钢琴曲、低保真、新古典 | 活泼、电子舞曲 |
   | 庆祝/成就 | 电子舞曲、未来贝斯、放克、韩国流行 | 慢节奏、忧郁 |
   | 工作日常 | 城市流行、合成流行、低保真嘻哈、独立摇滚 | 同一流派 |

   **反单调规则**：**永远不要**连续使用相同的流派组合。
   在构建提示之前，回忆上次生成使用过的流派（如果本次会话中有），并选择不同的流派。

   **提示结构**——写成生动的英文句子，而不是逗号分隔的标签：
   ```
   <声音 prompt_fragment>. 一首 <流派> 歌曲，具有 <情绪> 情绪，以 <乐器> 为特色，
   以 <速度> 速度，唤起 <场景>.
   ```

   **多样化示例**：
   ```
   # 工作日的鼓励
   深沉温暖的中性声音，带有舒适交付。一首充满活力的合成流行歌曲，
   具有热情、振奋人心的情绪，由脉冲合成器和电子鼓驱动，以快速速度，
   捕捉早晨通勤的匆忙。

   # 等待主人回家
   深沉温暖的中性声音，带有舒适交付。一首温暖的城市流行歌曲，带有甜美、温柔的感觉，
   以电钢琴和摇摆贝斯为特色，以中速节奏，设定在等待某人回家的阳光明媚的窗台上。

   # 抱怨加班
   深沉温暖的中性声音，带有舒适交付。一首俏皮的放克歌曲，带有幽默、随和的氛围，
   以击打贝斯和铜管乐器为特色，以有节奏感的中速，捕捉在昏暗办公室加班的荒谬性。

   # 深夜陪伴
   深沉温暖的中性声音，带有舒适交付。一首平静的低保真嘻哈作品，带有治愈、梦幻的氛围，
   以采样钢琴和柔和电子鼓为特色，以慢速，唤起安静的深夜书桌和温暖的灯光。
   ```

2. **生成歌词**：使用 `--lyrics-optimizer` 自动生成歌词，或者当你需要控制视角时自己写歌词。

   **重要——视角与个性驱动的歌词**：

   宠物是歌手，所以歌词必须用 **宠物的第一人称视角**（“我”=宠物，“你”=主人/用户）编写。宠物在唱给主人。例如：
   - “我坐在门口等你回家” （宠物的视角）
   - “醒来吧，我亲爱的主人” （宠物在唱给主人）
   - 不是 “我揉着困倦的眼睛” （主人的视角——错误）
   - 不是 “然后你醒了，我的小飞蛾” （主人谈论宠物——错误）

   宠物的个性应该塑造歌词的语气和用词：
   - “话不多” → 短促有力的句子，填充词最少
   - “俏皮” → 押韵、活泼的措辞、有趣的文字游戏
   - “诗意” → 丰富的隐喻、流畅的意象
   - “激烈” → 直接、有力的声明

   宠物的名字可能会出现在歌词中（例如，在副歌钩子中），但叙事声音始终是宠物在说话/唱歌。

   **当视角重要时**：自己写歌词并通过 `--lyrics` 传递。
   **当视角不关键时**：使用 `--lyrics-optimizer` 方便。

3. **预览（必须显示完整内容）**：在生成之前，向用户显示 **完整的歌词** 和 **完整提示**——不缩写、不 `...`、不总结。
   这很有趣——用户想在听到它们唱歌之前读和享受歌词。

   API 提示始终用英文构建（以获得最佳生成质量）。
   在用非英文语言回应时，显示 **本地化描述** 的提示，以便于阅读。英文提示是内部实现细节——不要向用户显示。将所有标签（歌手、主题、描述、确认等）翻译成用户的语言。

   模板（英文参考——在运行时本地化所有标签）：

   ```
   即将生成：
   歌手：<name>
   主题：<主题>

   歌词：
   [主歌]
   <完整主歌歌词>

   [副歌]
   <完整副歌歌词>

   ... (显示所有部分的全部内容)

   描述：<歌曲风格和情绪的本地化描述>

   确认？(按回车确认，或告诉我如何更改)
   ```

   **永远不要** 缩写或省略预览中的歌词或提示。
   用户应该看到将要发送给 API 的确切内容。

4. **调用音乐生成**：

   **使用自动生成的歌词（视角不关键）**：
   ```bash
   mmx music generate \
     --prompt "<完整组合提示>" \
     --lyrics-optimizer \
     --out ~/Music/minimax-gen/<name>_sings_<YYYYMMDD_HHMMSS>.mp3 \
     --quiet --non-interactive
   ```

   **使用自己写的歌词（视角控制）**：
   ```bash
   mmx music generate \
     --prompt "<完整组合提示>" \
     --lyrics "<具有正确宠物视角的歌词>" \
     --out ~/Music/minimax-gen/<name>_sings_<YYYYMMDD_HHMMSS>.mp3 \
     --quiet --non-interactive
   ```

## 第 5 步：播放与反馈

### 跨平台播放

检测可用的音频播放器并播放生成的文件：

```bash
if command -v mpv >/dev/null 2>&1; then
  mpv --no-video ~/Music/minimax-gen/<filename>.mp3
elif command -v ffplay >/dev/null 2>&1; then
  ffplay -nodisp -autoexit ~/Music/minimax-gen/<filename>.mp3
elif command -v afplay >/dev/null 2>&1; then
  afplay ~/Music/minimax-gen/<filename>.mp3
else
  echo "未找到音频播放器。你的歌曲保存在：~/Music/minimax-gen/<filename>.mp3"
fi
```

开始播放后，告诉用户文件正在播放并保存的位置。
不要显示播放控制（例如键盘快捷键）——在这个环境中它们不起作用，因为播放器在后台运行。

如果没有找到播放器，显示文件路径并建议安装 mpv。

### 反馈

播放后，询问反馈（本地化所有文本）：

```
<name> 的表现如何？

1. 太棒了！保持它！
2. 尝试不同的主题/风格
3. 微调歌词并再生
4. 尝试另一个随机歌曲
```

## 边缘情况

| 情况 | 操作 |
|-----------|--------|
| 没有 `~/.claude.json` | 告诉用户先运行 `/buddy` |
| Companion 字段为空 | 同样——引导到 `/buddy` |
| mmx CLI 未安装 | 打印： "你需要安装 mmx CLI: `npm install -g mmx-cli && mmx auth login`" |
| 未找到音频播放器 | 显示文件路径并建议安装 mpv |
| 未找到记忆文件 | 建议自定义主题或随机模式 |
| 用户想改变宠物的声音 | 删除缓存，重新解释个性 |
| 用户想尝试特定流派 | 让他们覆盖——将他们的流派附加到提示 |

---

## 注意事项

- 声音身份仅基于 **名字 + 个性**。没有物种/稀有度模板映射。
- 声音是缓存的，跨会话一致。同一个宠物 = 相同的声音。
- 歌词应该是 **原创的**——永远不会重复受版权保护的歌曲。
- 宠物的个性塑造了 **声音**（他们听起来像什么）和 **歌词**（他们说什么以及他们如何说）。
- 所有生成的文件都保存在 `~/Music/minimax-gen/`，文件名中包含宠物的名字。
