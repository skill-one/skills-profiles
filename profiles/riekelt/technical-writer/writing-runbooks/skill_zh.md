# 编写操作手册

**必备背景知识：** `技术写作` 技能（硬性规则、事实规则、风格）。

## 概述

读者通常很匆忙，往往处于事件处理中。每个操作手册都应按顺序排列，每一步一个操作，可复制粘贴，危险之处用眼睛能看到的地方标记。

基于实际操作编写：每一步都是实际执行过的，每一步失败都是实际发生过的。在书桌前想象出来的流程只是草稿，不是操作手册。部分执行的流程可以以分支分支的诚实度发布：命名尚未执行的变体，标记该分支为草稿，并要求第一个实际执行者反馈。没有任何分支有实际执行的流程就是草稿。当命令需要的信息确实未知时，保持占位符明显括起来，不要凭空编造，并在发布前从实际操作中填充它；事实优先于粘贴就绪。

## 何时调用，以及不调用

对于任何人类将执行的：操作手册、设置和发布流程、故障排除条目、操作检查清单以及系统内面向操作员的字符串。不调用设计原理（`writing-design-docs`）或无人执行的参考材料。如果流程至少未执行过一次，要么先执行它，要么将文档标记为草稿；发布未经测试的流程作为操作手册是缺陷，不是标签。

## 结构

- 标题包含范围："MVP操作手册（Reddit）"、"发布操作手册"。
- 以此文档相对于其兄弟文档是什么开篇（"此文档是顺序；详细步骤生活在X"）并说明它不涵盖什么。
- **在前面提供图例**当步骤在风险上不同时，应用于每个命令：随时可运行安全 / 操作员专用的（写入生产） / 终端外手动步骤。标签组合表示一个步骤超过一个东西。
- **先写happy path**，然后为需要单个步骤的读者按编号部分编写相同的步骤。
- 版本固定的先决条件在任何命令之前，每个都有检查命令。
- 编号顺序步骤（不是项目符号），每个步骤一个动作，现在时态或祈使句，有可见的执行者。
- 每个命令可复制粘贴，带有具体示例值（"常见路径：`/public_html/`，`/www/`"）。在代码块内标记变体：

```bash
# 安全模式
app sync run --channel=reddit --limit=100

# 实际模式（写入提供者）
app sync run --live --approval-token=...
```

- 顺序步骤在行内说明错误顺序的后果："部署jar，然后数据库清理；错误顺序 = 静默数据丢失"。
- 每个改变状态的流程都命名其回滚，或者明确说明不存在回滚及其含义。
- 以"验证它是否起作用"部分结束：可观察的最终状态和证明它的命令。
- 当存在多个路径时标记首选路径 "(推荐)"；将执行相同任务的UI和CLI并排文档而不是两次。
- 如果操作手册在工具到位时会缩小，请说明："当X到位时，步骤2到4将合并为一个命令，此文档将只保留判断"。

## 故障排除条目

以症状为先：

```markdown
## <用户看到的症状>
**症状**：逐字错误字符串（可搜索）
**原因**：...
**修复**：精确命令
```

按诊断步骤成本最低的顺序排列。按故障类别分组条目。交叉链接更深入文档而不是内联它。

## 迁移和弃用指南

迁移指南是主题为变更本身的操作手册：以上所有内容适用，还有它自己的五条规则。迁移的论点是设计文档（`writing-design-docs`），弃用的决定是决策记录（`recording-decisions`），公告是变更日志条目（`writing-changelogs`）；本节只涵盖读者执行的指南。

1. **历史是这里的内容，以积极的方式陈述。** 之前/之后的比较是工作，不是违规：这是没有历史硬性规则明确切割出的文档类别。自由地写"标签现在替换了手动版本号"；这句话在别处被禁止，在这里是承重句。
2. **映射表是核心工件。** 旧到新的行为、配置键、命令或API，每行一个。散文解释需要它的行；表格承载迁移。
3. **回滚是每步强制性的。** 每个步骤命名其撤销，或者明确说明它是不可逆的及其对周围顺序的含义。
4. **弃用合同包含日期。** 停止工作的时间、对滞留者的处理、以及在此之前逃生的出口。 "将在未来的发布中删除"不命名日期，在此处被禁止。
5. **出生时带有有效期。** 当迁移完成时，所有者将指南重新分类为历史，并添加指向当前状态文档的覆盖横幅，从不静默删除。在指南本身中说明完成条件。

## 面向操作员的字符串

错误消息和日志行是具有最短阅读窗口的操作手册文本：保持修复措施具体和可操作，并使错误状态可见而不是让工作流看起来健康。
