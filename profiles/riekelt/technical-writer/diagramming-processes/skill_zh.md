# 绘制流程图

**必要背景知识：** `技术写作` 技能（硬性规则、事实规则、风格）。

## 概述

流程图是一组用图形表示而非文字描述的陈述；每个方框和箭头都受到与句子相同的真实规则约束。核心原则：**绘制行为（流程、生命周期、交互），将源代码置于版本控制中，并将每次渲染视为派生内容。** 文字描述拥有推理过程；流程图承载文字难以序列化的内容：分支、并发和状态。

## 何时使用，以及何时不应使用

当需要展示流程、生命周期或交互时使用：跨越组件或组织的业务流程、状态机、消息交换、遗留活动（`documenting-legacy-codebases`）的 `processes.md`。**不应**用于装饰：三个或四个步骤的线性流程是一个编号列表，重述该流程的图表则是家具。超出范围：从数据生成的图表（指标、趋势）和实现结构，后者被行为规则禁止。

## 符号体系

绘制前确定高度，并匹配符号：

- **业务层：ArchiMate。** 跨部门、组织或多个系统的流程、能力图以及企业利益相关者期望的 TOGAF 风格视图。受众阅读角色、服务和流程，而非组件。
- **系统层：PlantUML 行为图。** 系统内和系统间的流程、状态机和序列：代码文档，位于代码之上的一级。
- **代码层：不使用图表。** 类和包结构是代码自身的展示；IDE 比任何提交的图表都能生成更清晰的图像。

该体系设定符号和词汇，而非工具：一个工具链可以服务于两个层级，因为 PlantUML 在其标准库中包含 ArchiMate 符号。仓库使用的工具一旦确定，就遵循“源代码而非图片”原则。

## 源代码而非图片

- 源代码是已提交的文本，在仓库已使用的图表工具中。若未建立，PlantUML 是默认选项（丰富的标准库，包含 ArchiMate）；若选择开放，建议询问所有者，推荐 PlantUML。核心技能的 `references/truth.md` 拥有基本规则：渲染输出是派生内容，过时的渲染会被删除而非留下误导。
- 每个图表对应一个源文件，以展示的流程命名，分组在文档旁边的图表目录中。
- 渲染需要仓库拥有的工具（脚本、make 目标或构建步骤），由所有者设置而非图表作者。缺失时告知所有者；切勿绕过差距，选择托管平台碰巧内联渲染的符号。
- 一个仓库命令渲染所有内容；除非托管平台已渲染仓库选择的源格式，否则渲染会被提交。源代码变更时，过时的渲染在同一变更中被删除，缺失的渲染在索引中记录直至重新生成。
- 无源代码的截图、导出的图片或白板照片是对包含它的文档的违规：无人能进行差异比较，因此无人会维护它。

## 图表类型回答读者的提问

根据读者的问题选择图表类型，每个图表对应一个问题：

| 读者提问 | 绘制 |
|---|---|
| 该流程如何跨组织运行 | ArchiMate 业务流程视图 |
| 发生什么，按什么顺序，做出什么决策 | 活动图 |
| 该事物处于哪些状态，以及如何转换 | 状态机 |
| 谁与谁按什么顺序，传递什么消息 | 序列图 |
| 该领域存在什么及其关系 | 概念图，业务对象级别 |

回答两个问题的图表无法回答任何一个问题；拆分它。需要自创符号图例的图表同时回答了太多问题。

## 行为而非实现

`documenting-legacy-codebases` 中的重构测试也适用于图表，且图表比段落更能隐藏其漂移：

- **参与者是系统、角色、模块和业务对象。** 类、方法和函数保留在代码中（参见符号体系）。
- **边框携带领域语言的事件或条件**：“支付确认”，而非回调名称。守卫可以命名配置键，因为配置键是合同表面；它从不命名方法。
- **标题命名流程**，而非规范、阶段或计划：无交付叙事硬性规则在图表源代码中也适用，包括注释。
- **错误和异常路径在行为差异处绘制**，并清晰区分；仅绘制成功路径的流程图对具有真实失败分支的流程是夸大声明。
- **特例被绘制，并成为内容。** 无法离开的状态、为特定输入跳过步骤的流程：意外的分支是图表获得其位置的原因（`documenting-legacy-codebases`，特例）。

## 图表索引

超过五个图表时，旁边会获得一个索引文档，作为从文件派生的衍生物（核心真实规则）：

- 覆盖表：每个图表展示的内容、源文件、提交的渲染及其状态。
- 每个图表描述的模块，作为漂移锚点：图表指向代码的唯一位置。
- 渲染命令，使索引也成为构建指令。
- 待渲染项，按源命名，使缺失渲染成为跟踪状态而非沉默的空白。

## 维护

更改流程的变更会更新同一变更中匹配的图表源代码：图表是文档，文档是已完成的一部分（核心真实规则）。渲染是图表的编译步骤：源代码编辑会隐式破坏语法，且破坏仅在渲染运行时显现。作者在提交编辑前渲染；若仓库的管道缺失，本地一次性运行工具即可满足此检查。当功能被移除时，一个变更涵盖文字、图表源代码、索引行和提交的渲染。无人愿意更新的图表回答了过于宏大的问题；沿独立变更的缝隙拆分它。

## 验证

图表中所有可读内容都是声明（核心真实规则），因此图表像文字一样被验证：

- 作者在绘制前验证每个方框、箭头和守卫与代码的匹配。推断而非确认的流程在嵌入文档中标注为推断，而非静默绘制为事实。
- 审查者对照行为阅读图表，并审查源文本而非图片：源代码是下一个编辑者更改的内容。
- 图表源代码像文字一样漂移，并参与每个遗留活动：活动（`documenting-legacy-codebases`）用嵌入它们的文档为图表源代码提供基础。
- 图表及其周边文字共享每个事实的单一家园：文字解释流程存在的原因和注意事项，图表展示流程，两者都不逐步重述对方。
