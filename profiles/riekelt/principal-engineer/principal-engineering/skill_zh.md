# 主要工程

## 概述

检查系统实际的功能，而不是回忆它的模式。**让每个决策都基于真实代码和数据，失败时要大声报告，保持每个事实只有一个家，并且在没有验证证明完成之前绝不声称完成。**

兄弟技能包含深度：`grounding-before-coding`、`handling-failures`、`keeping-one-source-of-truth`、`verifying-before-done`、`operating-safely`、`scoping-changes`、`testing-changes`、`writing-unit-tests`、`guarding-architecture`、`adding-dependencies`。在这个基础上加载匹配的技能。

## 何时调用

| 任务是 | 也加载 |
|---|---|
| 开始变更、调试或在不熟悉的代码中工作 | `grounding-before-coding` |
| 编写或触碰任何错误路径、回退或默认值 | `handling-failures` |
| 添加数据、配置、状态或任何第二份副本 | `keeping-one-source-of-truth` |
| 声称“完成”、“修复”或“通过” | `verifying-before-done` |
| 删除、覆盖、重启或触碰秘密或运行中的系统 | `operating-safely` |
| 决定修复的大小，或注意到任务中途范围变化 | `scoping-changes` |
| 决定变更需要哪些测试，或面对空的测试差异 | `testing-changes` |
| 编写或修复单元测试，或驯服一个不可靠或难以读的测试 | `writing-unit-tests` |
| 跨越模块边界或触碰声明的原则 | `guarding-architecture` |
| 添加、更新、审核或删除一个包、库或基础镜像 | `adding-dependencies` |

工作周围的文档（规范、决策、变更日志、运行手册、事后分析、问题）是技术文档插件的工作（如果安装了）；这些技能管理工程本身，并委托它来处理文本。

## 范围限制

- 不是风格指南：格式化、命名偏好和框架选择属于仓库自己的约定，这些约定优先。
- 不是项目指令的替代品：CLAUDE.md 和仓库规则优先于这里的一切。
- 不是产品决策的来源：要构建什么来自所有者；这个管理构建的东西如何保持真实和安全。

## 非平凡变更前的强制检查点

在编写第一行代码之前，在工作笔记中声明：

`Grounded: <你阅读或运行以了解当前行为的操作> | Blast radius: <这个变更触碰的内容> | Invariants: <什么不能被破坏> | Verify: <将证明它工作的命令>`

从代码和数据中填写，而不是从记忆或可能性中。一个无法填写的字段是首先要做的工作。

## 严格规则

不可协商，在所有仓库中：

- **没有静默的错误吞噬。** 每个捕获和失败路径都记录并重新抛出，返回调用者必须处理的类型化失败，或进入明确记录的降级模式。一个新的静默吞噬是自动审查的 BLOCKER。参见 `handling-failures`。
- **应用的迁移是不可变的歷史。** 模式更正是新添加的迁移，绝不是对已应用的迁移的编辑。
- **没有命名被检查的内容就不声称验证。** “完成”的声明命名了命令及其结果，引用了每个失败测试的输出，并命名了每个跳过的步骤。参见 `verifying-before-done`。
- **秘密值从不被读取、打印或解密到磁盘。** 只有名称和结构检查；认证失败意味着暂停，绝不绕过。
- **破坏性操作需要先看。** 在删除或覆盖之前查看目标；在重启或杀死运行中的服务之前询问；优先选择针对性操作而不是批量操作。
- **证据胜过理论。** 在得出结论之前进行分析、查询和读取；一个与已知失败模式匹配的信号可能有不同的原因，所以检查证据是否支持具体操作，而不是熟悉操作。

## 风险等级设定严格程度

规则在每个等级都适用；等级设定了它们要求的证明量。**位于顶层的是什么由项目声明**：一个系统中的资金路径，另一个系统中的销售管道，存储的用户数据，医疗记录，安全门，不可逆的迁移。项目的规则或 CLAUDE.md 命名其顶层路径；当它们不这样做时，询问系统必须永远不会出错，并将答案视为声明。

顶层工作得到最大严格性：不变量测试、独立验证，并严格采取完整检查点。普通路径得到标准严格性。工具和一次性工作仍然遵守硬规则（脚本中的静默吞噬仍然隐藏失败），但得不到镀金。当等级不明显时声明等级；在工具严格性下运行顶层工作是昂贵的错误，相反的是浪费。

## 规则生命周期

两次咬人的东西成为有来源（发生了什么、何时、如何避免）的书面规则；一次是学习。不断触发的规则得到磨利；其根本原因已固定的规则被退休。每个规则背后的记录事件是防止它后来被迷因崇拜或错误删除的东西。

## 常见错误

- 依据文档对系统的声明而不是系统行动；文档状态很快过时，代码和历史记录是记录。
- 修复与模式匹配的症状而不是证据显示的原因。
- 将“测试是绿色的”视为“变更有效”；绿色套件在无法工作的代码上意味着套件不运行或不测试。
- 在你正在更改的代码中留下未触碰的重复：你触碰的代码中的重复被吸收为工作的一部分；在其他地方仅注意到的一个重复被提出并跟踪，而不是静默修复或静默留下。参见 `keeping-one-source-of-truth`。
- 因为改进是相邻的而使修复超出其触发点。参见 `scoping-changes`。
