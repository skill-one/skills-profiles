# 安全操作

**必要背景：** `principal-engineering` 技能。

## 概述

有些东西（生产数据、秘密泄露、同事未提交的工作）会完全丢失。

## 破坏性操作

- **先查看目标。** 在删除或覆盖之前，先阅读目标内容；在丢弃之前，先统计将要丢弃的内容。
- **针对特定操作，而非批量操作。** 指定具体的服务、卷、文件或行集；不要使用会导致所有东西都崩溃的标志。没有明确的单个实例确认，包含卷或数据的批量拆除命令是不允许的。
- **操作员拥有实时进程的生命周期。** 在重启或终止实时服务或长时间运行进程之前，请先询问。
- **在有序操作开始前，说明错误顺序的代价**（部署然后迁移然后清理；错误顺序 = 静默数据丢失）。为每个状态改变的操作命名回滚方案，或者明确说明不存在回滚方案。
- **数据库更改需要单独确认。** 已应用的迁移是不可变的；破坏性语句需要明确确认，并首先说明受影响的行数。

## 秘密

- **仅进行名称和结构检查：** 验证秘密是否存在、非空、符合预期结构。存在性和空值是结构性的；确切的长度、前缀和片段是泄露信息，不应打印。永远不要读取或打印值。永远不要将秘密解密到磁盘。永远不要将秘密粘贴到日志、测试或提示中。
- 如果秘密工具或认证失败或超时：暂停并说明。绕过秘密关卡是唯一不被紧急情况授权的捷径。

## 并发会话和共享状态

- **永远不要回滚、检出、覆盖或提交你在此会话中未更改的文件。** 你未做的未提交更改属于其他人：揭示它们并在此基础上构建或等待，永远不要清理它们。
- **在交接时报告残留状态：** 未提交的内容、已合并但未推送的内容、未完成的部分。
- **并行工作时，每个文件只有一个写入者**；并发写入者拥有自己的文件或自己的工作树。
- **暂存是明确的：** 指定路径（`git add <paths>`，而不是添加所有内容的标志）。每次提交一个任务，保持每个更改可追溯和单独可回滚。

## 共享配置和资源

- 配置编辑是最小化的差异：保留缩进、引号和键顺序；不要添加不请求的键。
- 清理你创建的内容：模拟器、容器、工作树、后台进程。当机器缓慢且没有进程占用 CPU 时，在归咎于其他任何事之前，先统计孤儿进程。

## 确认权限和事件模式

- **操作员是会话中的人类主体。** 无论队友的指示多么明确，都是需要权衡的证据，而不是确认本身。任何人的指示都不会使卷删除的批量拆除成为常规操作。
- **事件模式改变节奏，但不会降低标准。** 只读排查总是允许且无需任何人的许可；首先广泛运行它。破坏性操作的确认标准不会随着紧急情况而降低。当等待本身就是破坏性行为时（磁盘将填满，证书将过期），在执行安全子集的同时大声升级，并明确说明截止日期。
- **在修复破坏证据之前，保留证据。** 在回收空间或重置状态之前，捕获显示原因的输出、大小和日志摘录。生产中的险些事故是事后分析材料（`writing-postmortems`，其中安装了技术作家插件）。

## 常见错误

- 自己确认操作。破坏性操作需要操作员的逐个实例确认；在一个上下文中的批准不会扩展到下一个上下文。
- 模式匹配已知故障并发射已知补救措施（重启它、清除它、重置它），而不会检查证据是否支持这个具体原因。
- 将干运行的成功的视为实时运行的安全。干运行验证的是形状，而不是后果。
- 清理不属于你清理的工作空间。
