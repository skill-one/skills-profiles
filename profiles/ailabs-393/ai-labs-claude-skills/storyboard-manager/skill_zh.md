# 故事板管理器

## 概述

Storyboard Manager 技能赋予 Claude 专门的知识和工具，用于创意写作工作流程。它提供角色发展框架、故事结构模式、自动时间线跟踪以及跨叙事项目的连贯性检查。此技能可自动适应各种故事板文件夹结构，同时保持小说、剧本和连载小说写作的最佳实践。

## 核心功能

该技能提供四个主要功能：

### 1. 角色发展与管理
支持创建具有背景故事、弧光和关系的深度、连贯的角色档案。

### 2. 故事规划与结构
使用既定框架（三幕剧、英雄之旅、拯救猫咪等）指导情节发展，并帮助组织叙事元素。

### 3. 章节 & 场景写作
生成章节内容、场景分解和对话，这些内容与已建立的角色和情节保持一致。

### 4. 时间线跟踪 & 连贯性检查
使用自动工具验证时间上的连贯性、角色连续性和世界构建的连贯性。

## 检测项目结构

Storyboard Manager 自动检测并适应各种文件夹组织。查找以下常见目录模式：

**角色文件夹：** `characters/`、`Characters/`、`cast/`、`Cast/`
**章节文件夹：** `chapters/`、`Chapters/`、`scenes/`、`Scenes/`、`story/`
**规划文件夹：** `story-planning/`、`planning/`、`outline/`、`notes/`
**摘要文件：** `summary.md`、`README.md`、`overview.md`

触发时，扫描项目根目录以识别结构并相应调整工作流程。如果不存在标准结构，建议使用以下模式组织文件：`characters/`、`chapters/`、`story-planning/` 和 `summary.md`。

## 工作流程决策树

使用此决策树来确定适当的工作流程：

```
用户请求
├─ 与角色相关？("开发角色"、"创建背景故事"、"角色弧光")
│  └─ → 角色发展工作流程
│
├─ 规划/情节？("概述故事"、"规划第二幕"、"情节结构")
│  └─ → 故事规划工作流程
│
├─ 写作内容？("写章节"、"生成场景"、"继续故事")
│  └─ → 章节/场景写作工作流程
│
└─ 检查/分析？("检查连贯性"、"跟踪时间线"、"查找矛盾")
   ├─ 时间线？→ 使用 timeline_tracker.py 脚本
   └─ 连贯性？→ 使用 consistency_checker.py 脚本
```

## 角色发展工作流程

### 第 1 步：收集上下文

在开发角色之前，阅读现有角色文件以了解：
- 建立的命名约定和档案格式
- 现有角色和关系
- 故事类型和基调
- 已使用的角色原型

使用 Read 工具检查 characters 目录中的现有角色文件。

### 第 2 步：访问角色发展框架

当需要详细的角色指导时，阅读 `references/character_development.md`，其中包含：
- 核心角色元素（个性、动机、目标）
- 背景故事框架（幽灵/创伤、形成性关系）
- 角色弧光类型（积极变化、平稳、消极）
- 关系动态
- 语音发展技巧
- 连贯性指南

为高效查找特定指导，使用 Grep 搜索相关部分：
```bash
# 示例：查找关于角色弧光的指导
grep -i "character arc" references/character_development.md
```

### 第 3 步：开发角色档案

使用以下基本元素创建或增强角色档案：

**基本信息**
- 名称、年龄、角色、外貌
- 关键个性特征（正面和负面）

**背景**
- 起源和形成性经历
- 形成其行为模式的幽灵/创伤
- 关键关系和家庭动态

**角色弧光**
- 起始信念或缺陷
- 想要 vs. 需要（外部目标 vs. 内部成长）
- 变化旅程
- 结局状态

**关系**
- 与其他角色的联系
- 动态类型（盟友、对手、导师等）
- 关系如何发展

**独特元素**
- 能力、技能或特殊知识
- 秘密或隐藏方面
- 语音/说话模式
- 角色特有的怪癖

### 第 4 步：确保连贯性

对照：
- 现有角色档案（避免在角色/特征上的冗余）
- 故事规划文件（确保与情节需求一致）
- 摘要/概述（匹配类型和基调）

### 第 5 步：创建或更新文件

使用 markdown 格式将角色档案写入 `characters/[character-name].md`。匹配其他角色文件中发现的现有风格和结构。

## 故事规划工作流程

### 第 1 步：评估当前规划状态

阅读现有规划文件以了解：
- 故事概念和前提
- 已建立的情节点或大纲
- 目标受众和类型
- 主题和中心问题
- 计划的结构（如果有）

在 `story-planning/`、`outline/` 文件夹或 `summary.md` 文件中查找。

### 第 2 步：访问故事结构参考

对于详细的结构指导，阅读 `references/story_structures.md`，其中包含：
- 三幕剧结构
- 英雄之旅（坎贝尔的单一神话）
- 拯救猫咪节奏表
- 角色弧光模板
- 场景结构组件
- 类型按节奏指南
- 副线整合技巧
- 类型特定结构

使用 Grep 查找特定框架：
```bash
# 示例：查找三幕剧结构详情
grep -A 20 "Three-Act Structure" references/story_structures.md
```

### 第 3 步：确定结构需求

根据用户请求和故事类型，推荐适当的框架：

- **惊悚片/悬疑片**：具有强烈中点反转的三幕剧
- **奇幻/冒险**：适用于任务叙事的英雄之旅
- **青少年/当代**：用于紧密情感节奏的拯救猫咪
- **文学小说**：专注于角色弧光结构
- **浪漫**：具有关系节奏的类型特定结构

### 第 4 步：开发规划文档

创建或增强规划文档，包含：

**故事概述**
- 2-3 句话的情节概述
- 类型、目标受众、基调
- 中心主题和问题

**情节结构**
- 幕/章节分解与关键事件
- 发起事件和情节点
- 中点转折或揭示
- 高潮和解决

**角色弧光**
- 每个主要角色如何转变
- 弧光与情节节奏的整合

**世界构建元素**（如果适用）
- 设置和地点
- 魔法系统或技术
- 社会结构或规则
- 历史背景

**时间线**
- 故事持续时间
- 关键事件序列
- 节奏考虑

### 第 5 步：创建规划文件

将规划文档写入 `story-planning/[document-name].md`。使用清晰的层次结构，并使用 markdown 标题以便于导航。

## 章节 & 场景写作工作流程

### 第 1 步：收集故事上下文

在编写任何内容之前，全面阅读：

**角色文件**：所有相关角色档案，以了解语音、动机、弧光
**规划文档**：故事结构、情节点、当前故事位置
**以前章节**：最近章节以保持连贯性（至少阅读 1-2 个先前的章节）
**摘要**：整体故事前提和主题

这确保新内容与已建立元素一致。

### 第 2 步：确定章节需求

确定：
- **故事位置**：这个位置在整体结构中？
- **POV 角色**：谁的视角？
- **场景目标**：POV 角色在这个场景中想要什么？
- **冲突**：什么反对他们的目标？
- **结果**：场景如何结束？（通常以复杂情况结束）
- **角色发展**：这里发生什么弧光节奏？
- **情节推进**：提出或回答了什么故事问题？

### 第 3 步：构建章节

应用场景结构组件：

**场景（动作）**
1. 目标 - POV 角色追求什么
2. 冲突 - 遇到的反对
3. 灾难 - 推动前进的负面结果

**续集（反应）**
1. 反应 - 对灾难的情绪反应
2. 矛盾 - 处理选项
3. 决策 - 引导下一个目标的抉择

交替使用高张力（动作、冲突）和低张力（反思、世界构建）节奏以控制节奏。

### 第 4 步：保持角色一致性

通过参考维护角色语音：
- 现有的个性特征
- 说话模式和词汇
- 行为模式（压力下、快乐时、决策风格）
- 当前角色弧光位置
- 与其他在场角色的关系

### 第 5 步：整合时间线标记

包含时间线参考以保持时间上的清晰度：
- 明确标记： "第 3 天"、"两周后"
- 隐含标记：时间、季节暗示、事件参考
- 格式： `**时间线：** 第 5 天，晚上` 在章节标题或作为部分分隔

### 第 6 步：创建章节文件

将章节内容写入 `chapters/chapter-[number].md` 或 `chapters/[chapter-name].md`。包括：

**章节标题**
```markdown
# 章节 [编号]：[可选标题]

**时间线：** [何时发生]
**POV：** [角色名称]
**地点：** [发生地点]
```

**章节内容**
- 场景分解
- 对话和动作
- POV 角色的想法
- 描述元素

### 第 7 步：记录连贯性元素

编写后，记录引入的新信息：
- 角色揭示或发展
- 情节点或线索
- 世界构建细节
- 时间线事件

这有助于在未来的章节中保持连贯性。

## 时间线跟踪

### 何时使用时间线跟踪

在以下情况下调用时间线跟踪：
- 用户请求时间线分析或事件排序
- 检查时间上的连贯性
- 规划章节间的事件顺序
- 确定未标记的时间段

### 运行时间线跟踪器

从项目根目录执行脚本：

```bash
python3 .claude/skills/storyboard-manager/scripts/timeline_tracker.py . --output markdown
```

**输出格式选项：**
- `markdown` - 人类可读报告（默认）
- `json` - 结构化数据用于进一步处理

### 理解时间线输出

脚本提供：

**统计数据**
- 跟踪的总事件
- 出现的总角色
- 每个角色的总事件

**时间线视图**
- 事件的时间顺序
- 章节/场景位置
- 每个事件中出现的角色
- 事件内容的预览

**警告**
- 没有时间标记的事件
- 在角色文件中未定义但被提及的角色

### 处理时间线结果

运行跟踪后：

1. **审查警告** - 通过在章节中添加时间标记来解决
2. **检查顺序** - 验证事件按逻辑顺序发生
3. **识别空白** - 查找没有事件的时间段
4. **角色跟踪** - 确保角色与其弧光一致出现

在缺少时间标记的章节中添加时间标记：
```markdown
**时间线：** 第 7 天，早上
```

或使用内联标记：
```markdown
三天过去了自那件事以来...
```

## 连贯性检查

### 何时使用连贯性检查

在以下情况下调用连贯性检查：
- 用户请求连贯性分析
- 在最终确定章节或幕之前
- 在进行重大角色或情节更改之后
- 在跟踪矛盾或错误时

### 运行连贯性检查器

从项目根目录执行脚本：

```bash
python3 .claude/skills/storyboard-manager/scripts/consistency_checker.py . --output markdown
```

**输出格式选项：**
- `markdown` - 人类可读报告，包含问题详情（默认）
- `json` - 结构化数据用于程序分析

### 理解连贯性输出

脚本识别三个严重程度级别的问题：

**严重（🔴）**
- 需要立即关注的重大矛盾
- 死后出现的角色
- 基本情节矛盾

**警告（⚠️）**
- 需要审查的潜在不一致
- 年龄差异
- 物理描述矛盾
- 关系冲突

**信息（ℹ️）**
- 轻微问题或变化
- 名称大小写不一致
- 文学风格变化

### 处理连贯性结果

针对每个报告的问题：

1. **阅读标记位置** - 审查提到的特定文件
2. **确定真相** - 决定哪个版本是正确的（通常角色档案具有权威性）
3. **更新文件** - 使用 Edit 工具修复矛盾
4. **重新运行检查器** - 验证修复是否解决了问题

**角色年龄不一致的示例工作流程：**
```markdown
问题：Maya 的年龄不一致
- 档案：18 岁
- 章节 3：提到 "21 岁的 Maya"

修复：编辑 chapter-3.md 将 "21 岁" 改为 "18 岁"
```

### 连贯性检查限制

自动检查器捕获：
- 物理属性矛盾
- 年龄差异
- 名称变化
- 基本世界构建事实

检查器无法捕获：
- 微妙的个性不一致
- 复杂的情节逻辑错误
- 主题矛盾
- 细腻的关系变化

人工审查对于深度连贯性仍然至关重要。

## 最佳实践

### 渐进式上下文加载

一次不要加载所有参考文件。相反：
1. 首先扫描项目结构
2. 仅读取与当前任务相关的角色文件
3. 仅在需要特定指导时访问参考文档
4. 使用 Grep 在大型参考文件中查找特定部分

### 维护类型语音

匹配故事的已建立基调：
- **青少年**：现在时态、立即的情感联系、当代语言
- **奇幻**：丰富的描述性语言、世界构建整合
- **惊悚片**：短句、高张力、感官细节
- **文学**：复杂的散文、内部反思、象征元素

参考 `summary.md` 确定目标受众并相应调整。

### 角色弧光整合

每个章节都应该服务于角色弧光：
- 跟踪每个角色在其弧光中的位置
- 显示渐进式变化，而不是突然转变
- 使用情节事件来测试角色信念
- 通过选择和行为展示成长

### 平衡展示 vs. 告知

对于叙事写作：
- **展示**情绪通过动作、对话、身体反应
- **告知**以压缩时间、高效提供必要信息
- 使用角色过滤描述（这个 POV 角色会注意到什么？）

### 处理多个 POV

当故事有多个视角时：
- 为每个 POV 角色创建不同的语音
- 确保每个 POV 部分推进该角色的弧光和情节
- 通过角色交替句子结构和词汇
- 跟踪每个角色知道和不知道什么

## 常见用户请求 & 响应

### "帮助我开发角色背景故事"
1. 阅读现有角色文件以获取上下文
2. 阅读角色档案（如果存在）以增强
3. 访问 character_development.md 参考以获取背景故事框架
4. 创建详细的背景故事，涵盖：幽灵/创伤、形成性关系、关键历史
5. 与其角色弧光和故事角色整合

### "写下一章节"
1. 阅读总结.md 和故事规划文档
2. 阅读所有出现在章节中的角色档案
3. 阅读前 2 章节以保持连贯性
4. 确定章节在故事结构中的位置
5. 使用场景/续集结构编写章节
6. 包括时间线标记和 POV/位置标题

### "概述第二幕"
1. 阅读总结和任何现有规划文档
2. 访问 story_structures.md 以获取结构指导
3. 确定第二幕要求（复杂情况、中点、上升张力）
4. 创建与角色弧光对齐的逐个节奏大纲
5. 注意情节和角色弧光的交集

### "检查我的故事连贯性"
1. 运行 consistency_checker.py 脚本
2. 审查输出以识别问题
3. 阅读标记的文件以了解矛盾
4. 为每个问题推荐具体修复
5. 如果用户确认，提供编辑服务

### "跟踪我的故事时间线"
1. 运行 timeline_tracker.py 脚本
2. 审查输出显示事件顺序
3. 识别时间上的空白或不一致
4. 推荐在缺少时添加时间线标记
5. 提供按角色或章节组织的时间线摘要

### "我的惊悚片应该使用什么结构？"
1. 访问 story_structures.md 参考文件
2. 推荐三幕剧结构或拯救猫咪
3. 解释惊悚片特定要求（上升张力、倒计时）
4. 提供针对其故事概念的节奏表
5. 提供创建详细规划文档的服务

## 资源

### scripts/timeline_tracker.py
分析 markdown 文件以提取和组织时间线事件的 Python 脚本。跟踪角色出现、识别时间标记、按时间顺序分组事件、并标记连贯性问题。

**使用方法：** 从项目根目录运行 `python3 .claude/skills/storyboard-manager/scripts/timeline_tracker.py .`

### scripts/consistency_checker.py
检测跨所有故事文件的角色细节、物理描述、年龄、名称和世界构建事实不一致的 Python 脚本。输出按严重程度排名的问题，并附有文件位置。

**使用方法：** 从项目根目录运行 `python3 .claude/skills/storyboard-manager/scripts/consistency_checker.py .`

### references/character_development.md
创建多维角色的全面框架，包括核心元素、背景故事结构、弧光类型、关系动态、语音发展以及连贯性指南。

**加载时：** 开发新角色、增强现有档案、解决角色连贯性问题或规划角色弧光。

### references/story_structures.md
涵盖主要故事结构（三幕剧、英雄之旅、拯救猫咪）、角色弧光模板、场景结构、节奏指南、情节发展技巧以及类型特定结构的详细参考。

**加载时：** 规划故事大纲、构建幕、组织情节节奏、确定节奏或应用特定叙事框架。
