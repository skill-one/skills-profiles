# Wiki Synthesize — 一流合成发现

你正在扫描维基，寻找在许多页面中共同出现但没有任何专门的合成页面将它们联系起来的概念。你的工作是揭示这些空白，并用跨领域的合成页面填补其中最有价值的部分。

## 开始前

**写作配置文件：** 在起草或重写自然语言 Markdown 之前，请阅读并应用 `llm-wiki/SKILL.md` 中的 `Writing Profile Resolution` 部分。框架模式、来源、安全性和特定操作的要求优先。
`WRITING.md` 的偏好仅适用于新起草或重写的自然语言 Markdown；保留源内容和结构化记录。

1. **解决配置** — 遵循 `llm-wiki/SKILL.md` 中的配置解决协议（内联 `@name` 覆盖 → 向上遍历 CWD 查找 `.env` → 全局配置 → 提示设置）。这会提供 `OBSIDIAN_VAULT_PATH` 和 `OBSIDIAN_LINK_FORMAT`（默认：`wikilink`）。
2. 阅读 `index.md` 以获取完整的页面清单。
3. 如果存在，请阅读 `hot.md` — 它会展示最近的活跃度和可能已经指向合成机会的活跃线程。
4. 阅读 `_meta/taxonomy.md` 以了解标签词汇。

在合成页面中编写内部链接时，使用 `llm-wiki/SKILL.md`（链接格式部分）中的链接格式，并使用 `OBSIDIAN_LINK_FORMAT` 值。

## 第一步：构建共现图

扫描保险库中的每个非特殊页面（跳过 `index.md`、`log.md`、`hot.md`、`_insights.md`、`_meta/*`、`_archives/*`、`_raw/*`）。

对于每个页面，收集：
- 它包含的所有 `[[wikilinks]]`（出站链接）
- 它的 `tags` 前置内容
- 它的 `category` 前置内容

构建共现矩阵：对于每一对概念/实体页面（A、B），计算有多少其他页面同时链接到 A 和 B。这是它们的共现分数。

你不需要穷尽所有内容 — 目标是按共现分数排名前 20-30 对。使用 Grep 高效地查找反向链接：

```bash
rg -l --glob '*.md' "\[\[ConceptA\]\]" "$OBSIDIAN_VAULT_PATH"
```

对你的顶级候选概念运行此命令，并交叉结果集。

## 第二步：过滤掉已合成的对

检查 `synthesis/` 目录中的现有页面。对于每个现有的合成页面：
- 读取它的 `sources` 前置内容或它的正文中的 `[[wikilinks]]`
- 将这些概念对标记为已覆盖

从候选列表中移除已覆盖的对。

## 第三步：评分和排名候选

对于每个剩余的候选对（或 3 个或更多概念的集群），分配一个合成值分数：

| 信号 | 分数 |
|---|---|
| 共现计数 ≥ 5 | +3 |
| 共现计数 3-4 | +2 |
| 共现计数 1-2 | +1 |
| 概念属于不同类别（跨领域） | +2 |
| 概念共享标签但位于不同文件夹 | +1 |
| 一个或两个概念在 `_insights.md` 中被标记为枢纽 | +1 |
| 合成将解决一个标记的矛盾 | +2 |

选择前 5 个候选。如果用户要求特定主题（“合成关于可观察性的所有内容”），则首先过滤候选以匹配该领域。

## 第四步：起草合成页面

对于每个顶级候选，使用此模板在 `synthesis/` 中创建页面：

```markdown
---
title: <概念 A> × <概念 B>
category: synthesis
tags: [<共享标签>, <领域标签>]
sources: [<所有同时链接到两者的页面>]
created: TIMESTAMP
updated: TIMESTAMP
summary: "关于 <A> 和 <B> 相互作用的跨领域合成，对 <领域> 有启示意义。"
provenance:
  extracted: 0.2
  inferred: 0.7
  ambiguous: 0.1
base_confidence: <所有输入页面 base_confidence 的最小值>
lifecycle: draft
lifecycle_changed: TIMESTAMP_DATE
---

# <概念 A> × <概念 B>

## 连接

*是什么让这两个概念值得一起合成 — 页面中每个概念单独描述时无法捕捉的非明显关系。*

## 共现位置

*两个概念同时出现的页面和上下文。是什么情况将它们联系在一起。*

## 跨领域洞察

*只有当你将两者结合起来才能看到的结论。这是页面的重点 — 你无法从任何一个概念页面单独看到的东西。*

## 矛盾和权衡

*两个概念相互矛盾的地方。未解决的矛盾。应用一个概念会削弱另一个概念的情况。*

## 最强烈的反对意见

*对这个页面跨领域洞察的最佳怀疑性阅读 — 一个敏锐的批评者会提出的、认为这种联系是虚假的、夸大的或源内容编写方式产生的结果。随后附上一个可测试的搜索查询（例如 `> test: 当 Y 受控时 X 是否确实成立？`），而不是编造的引用。一个无法说出自己最强烈反对意见的合成还没有证明其结论。*

## 开放性问题

*这个合成揭示而维基尚未有答案的问题。未来研究的良好候选。*

## 相关

- [[<概念 A>]]
- [[<概念 B>]]
- [[<其他相关页面>]]
```

**合成页面大多是 `^[inferred]`。** 你正在跨来源建立联系 — 这就是合成的定义。对跨领域结论应用 `^[inferred]`，对来源存在分歧的地方应用 `^[ambiguous]`。

**标题格式是 `A × B`** — 这向读者表明这是一个合成页面，而不是关于其中任何一个概念的页面。

## 第五步：从源页面反向链接

对于你创建的每个合成页面，从它合成的两个（或更多）概念页面添加一个链接。在概念页面中，添加到它的 `## Related` 部分：

```markdown
- [[概念 A × 概念 B]] — 合成
```

如果概念页面没有 `## Related` 部分，在底部添加一个。

## 第六步：报告未使用的合成机会

在为前 5 个创建页面后，列出下一个 10 个候选 — 分数较高的对但你没有为其编写页面。这为用户提供了维基认为值得探索的内容的可见性，而不会强迫在一次运行中完成所有合成。

格式：
```
跳过（下次考虑）：
- [[缓存]] × [[一致性]] — 在 4 个页面中共同出现，跨领域
- [[测试]] × [[可观察性]] — 在 3 个页面中共同出现，共享标签
...
```

## 第七步：更新特殊文件

一个锁定调用更新索引、日志和热缓存：

```bash
obsidian-wiki memory sync WIKI_SYNTHESIZE \
  pages_scanned=<N> synthesis_created=<M> candidates_skipped=<K> \
  --takeaways "合成了 5 个跨领域页面：缓存 × 一致性，测试 × 可观察性，…"
```

合成揭示的开放性问题是一系列主题，不是要点 — 记录每个问题：
`obsidian-wiki memory todo add "<问题>" --origin synthesis/<页面>.md`。

永远不要手动编辑 `index.md`、`log.md` 或 `hot.md` — 命令会锁定以防止并行写入者覆盖你的更新。

参见 `.skills/llm-wiki/references/MEMORY.md` 获取完整流程。

## 质量检查清单

- [ ] 每个合成页面都有一个 `summary:` 字段（≤200 字符）
- [ ] 每个合成页面都链接回其源概念
- [ ] 源概念页面链接到合成页面
- [ ] 没有合成页面只是重述源页面上的内容 — 它必须提供跨领域洞察
- [ ] 每个合成页面都使用可测试的搜索查询命名其 `Strongest Objection`（不是编造的来源）
- [ ] `index.md` 和 `log.md` 已更新
- [ ] `hot.md` 已更新

## 小贴士

- **一个只总结其来源的合成页面是无用的。** 价值在于连接 — 两个源页面都没有明确说明的东西。
- **不要为了合成而合成。** 如果两个概念只是偶然经常一起出现而没有真正的概念联系，就跳过它们。
- **三方合成很强大但很少见。** 只有当三个概念形成真正的相互影响三角形时才创建它们 — 而不是因为所有三个都在同一个项目页面中。
- **首先检查 `_insights.md`。** 维基状态技能可能已经在这里标记了合成候选 — 在从头开始进行共现扫描之前从这些候选开始。

## QMD 在保险库写入后刷新

QMD 是一个搜索索引，不是真相来源。如果 `$QMD_WIKI_COLLECTION` 为空或未设置，跳过此步骤。仅在 `此技能写入或重写了保险库 Markdown` 后运行它。如果 QMD 刷新失败，不要回滚保险库更改；单独报告 QMD 状态。

如果设置了 `$QMD_CLI`，使用它；否则使用 `qmd`。

```bash
${QMD_CLI:-qmd} update
```

如果输出说需要向量或嵌入可能已过时，运行：

```bash
${QMD_CLI:-qmd} embed
```

使用以下任一方式验证集合：

```bash
${QMD_CLI:-qmd} ls "$QMD_WIKI_COLLECTION"
```

或，当知道特定页面路径时：

```bash
${QMD_CLI:-qmd} get "qmd://$QMD_WIKI_COLLECTION/<页面>.md" -l 5
```

记录以下之一：
- `QMD 刷新：update + embed + verified`
- `QMD 刷新：update 仅 + verified`
- `QMD 跳过：QMD_WIKI_COLLECTION 未设置`
- `QMD 跳过：qmd CLI 不可用`
- `QMD 失败：<简短错误摘要>`
