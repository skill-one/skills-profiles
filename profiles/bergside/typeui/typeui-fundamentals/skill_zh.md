# 设计基础 — 代理指令

定义**为什么**模式有效、**如何**正确应用它们以及**哪些**无条件的可访问性要求。这些是永恒的、与设计系统无关的基础，适用于任何界面，无论垂直方向或工作流程阶段如何。

## 加载顺序

在设计系统加载完成后（`SKILL.md` / `DESIGN.md` + 符号模块）再读取这些文件。设计系统告诉你要使用*什么*符号；这些文件解释*为什么*这个决定是正确的以及*如何*避免常见的原则违规。

## 这些文件不包括的内容

这些文件不定义：
- **工作流程阶段**（思考→构建→检查→发布） — 见 `skills/vertical/SKILL.md`
- **质量门禁或审核** — 见 `skills/vertical/inspect.md`、`review.md`、`preflight.md`
- **反模式目录** — 见 `skills/vertical/anti-patterns.md`
- **行业特定内容** — 见 `skills/vertical/team-social-saas.md`
- **设计符号或组件规范** — 见 `skills/design-system/SKILL.md`

## 冲突解决

当来源不一致时：

1. **设计系统**在具体值（颜色、尺寸、间距符号、组件规范）上优先。
2. **基础**（这一层）在结构原则（层级、可访问性、运动逻辑）上优先。
3. **垂直**在流程决策和内容架构（区域顺序、必需区域、行业调性）上优先。

可访问性在所有层级都是无条件的 — 它在任何地方都优先于美观偏好。

## 当设计系统保持沉默时，这些原则决定

任何未由系统符号或组件规则涵盖的设计决策都会回退到这里的原理。永远不要与设计系统相矛盾 — 如果一个原则与设计系统规则冲突，设计系统优先。标记冲突以供审查。
