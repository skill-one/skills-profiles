# 测试间隙分析

回答一个问题：**哪些调用者可见的生产行为可以在现有测试未失败的情况下发生变化？** 变异推理是一种探测手段，而非目标。首先列出公共结果，然后仅验证可信的间隙。

## 决策流程

### 1. 确定范围

从清单和文件类型中发现生产和测试文件。在狭窄搜索失败后，在请求路径之前广泛检查当前目录。

| 请求 | 操作 |
|---|---|
| 一个组件或命名风险 | 列出范围内的所有高风险公共结果；除非请求验证，否则不要编辑生产代码 |
| 一般小组件审查 | 列出不同的结果并从源码/断言映射中报告调用者可见的间隙 |
| 显式存活验证 | 列出所有请求的结果；对每个独立的高风险结果执行一个代表性的可观察候选者，然后将其分类为 **存活** 或 **死亡** |
| 显式彻底审计 | 阅读 [references/mutation-catalog.md](references/mutation-catalog.md) 并对所有有意义候选者进行分类 |
| 向现有套件添加测试 | 先分析；仅对验证的存活者或证明未覆盖的结果添加测试 |
| 创建新套件 | 停止并使用 `code-testing-agent` |

在读取代码之前，将请求命名的风险转换为单行公共结果允许列表。一个结果仅仅因为相同的 方法写入它就不在范围内。对于 `money math`，允许计算或返回的金额、利率、等级/边界选择、百分比基数/顺序、地板/天花板和舍入；排除非货币状态谓词（包括派生的布尔值）、身份和格式化。私有代码仅在跟踪允许的结果时才在范围内。

不要将一个集中的请求扩展为一个仓库审计、计划工件或仪表板。直接使用源码和测试来熟悉框架。仅在发现或断言语义不明确时才调用 `test-analysis-extensions`。

### 2. 建立一个基线

运行最狭窄的现有测试命令一次。从项目清单中选择它；Microsoft.Testing.Platform 可执行文件可能需要 `dotnet run`。确认测试执行：仅构建输出退出 0 不是绿色的。如果一次尝试无法运行套件，不要排除运行器或尝试替代命令进行建议性审查；继续静态分析并将所有候选者标记为 **未验证**。不要从缺失输出推断项目配置原因；只有在命令报告它时才命名原因。

运行器输出缺失仅限制经验变异存活的声明。它不会使源证实的事实变得不确定：没有达到测试的公共结果仍然是 **无覆盖**，从未修改的实现派生的确切预期值仍然是可操作的。陈述基线限制一次，然后直接给出静态源/断言结论，而不是犹豫每一行。

对于建议性审查（例如“测试会捕获这个问题吗？”），在基线后停止执行。源到断言映射是 **无覆盖** 和 **候选存活（未验证）** 的充分证据。仅在原始值不明确时才跟踪或运行未修改的代码一次。仅在显式验证、彻底审计或使用测试关闭间隙时才应用变异。

任何集中的变异预算限制执行，而不是发现。保留清单中的每个不同未断言的公共结果。

### 3. 列出公共结果

对于每个公共入口点，映射：

- 输入分区：分类器分支、复合条件、无效和最近有效的保护边界和默认情况；
- 每个独立观察：返回的字段/变体、异常类型、无效输入接受、公共状态转换或外部副作用；
- 通过公共调用者观察到的私有辅助组合、常量/利率、舍入、重试、取消和错误传播。

使用 `公共输入/序列 -> 预期结果 -> 现有断言 -> 间隙`。一个断言的返回字段不会覆盖另一个。一个允许的结果不会覆盖其否定。

**Money math：** 列出无操作路径、每个利率/等级和确切边界、操作顺序、百分比基数或组合、地板/天花板和舍入。通过公共结果跟踪私有辅助。仅断言一个宽范围测试不会固定任何确切金额。对于每个可操作的钱币行，通过完整的调用链推导一个证人输入及其确切原始结果；不要在没有提供该金额的情况下推荐一个通用的“断言确切金额”。

**有序保护和重试：** 列出 `无效低于最小值 | 第一个有效 | 最后允许或可重试 | 第一个受阻 | 后续受阻`。对于上保护（例如 `value >= limit`），使用 `limit - 1`、`limit` 和 `limit + 1`；最后一个证人暴露了缩放到 `value == limit`。列出每个接受和拒绝的错误类。当类型匹配是多态的时，包括一个代表性的派生接受类型，该类型会暴露确切运行时类型缩小。在第一个受阻值处的测试不会保护最后一个允许或后续受阻值。

**授权：** 枚举每个相关的身份/角色、资源类和调用者视图中的操作。未测试的 `false`、禁止和未更改角色的结果是第一流的 安全间隙。在未列出的否定结果存在时，不要分析允许路径的变体。检查每个公共表面：

- 返回权限的 API：每个不同的角色/资源类和每个返回的独立能力；
- 操作调度 API：每个读/写/删除风格的操作分支，特别是必须返回否定的路径；
- 角色/状态转换：接受的、拒绝的、无效的、空的和空的输入，包括必须保持状态不变的结果。

在另一个部分覆盖的辅助之前保留执行完全未测试的公共分支。如果有超过五个高风险行为未断言，执行前 3-5 个并将其余的可见作为 **无覆盖** 或 **候选存活（未验证）**。

执行永远不会取代账本。在变异或回答之前，分类每个所需结果，包括每个无效输入、保护边界、分类器分支、操作和否定。

**完整性检查点：** 在选择发现之前，明确说明每个独立模式/标志，`<= 0` 保护中的零和负数，每个接受的异常类，以及当匹配是多态时一个代表性的派生接受异常。对于移除的保护，跟踪下溢：如果它仍然产生相同的公共异常类型，它是等效的，除非更细的异常元数据是一个已建立的合同。

### 4. 仅承认可观察的候选者

首先将每个确切变异重放给每个现有断言的输入或序列，所有参数都固定。任何改变的返回、异常、状态或副作用都是 **可能死亡**；不需要专门的单一目的测试。永远不要在一个输入上的变异与另一个输入上的原始值进行比较。

对于存活者，在执行或报告之前选择一个证人并陈述 `证人 -> 原始观察 -> 变异观察`。在最小的测试中重用它。仅在跟踪完整调用链后，最后一个两个公开不同时才承认它；否则选择一个区分的证人或放弃它。

排除：

- 需要插入或重新排序语句而不是更改或删除现有表达式、条件、常量、返回或副作用的编辑；
- 无法编译的编辑，包括删除其值仍然被引用的声明；
- 溢出行为、异常消息/`ParamName` 元数据或其他当前合同、源意图或测试未建立的语义；
- 移除的保护或短路导致相同结果、异常、状态和副作用；
- 每个公共输入序列都观察到完全相同的私有表示更改，即使套件保持绿色；
- 一个变异，其建议的测试针对原始和变异都通过；
- 边界编辑在区分输入上返回相同值；例如，将 `result < floor ? floor : result` 更改为 `<=` 在相等时是等效的，因为两个分支都返回 `floor`；
- 一个独立的自动属性或简单的单行包装器/谓词，没有有意义的分支、计算或副作用，除非用户命名它；
- 假设的未来影响、生成代码、仅日志/格式化更改、不可能的值和重复的语法变体。

直接断言缺失不会证明 **无覆盖**：首先通过公共调用者和共享分支跟踪现有断言。缺失断言使 **可观察** 的候选者成为存活者；它们不会使惰性变异有意义。

### 5. 排序和分类

排序： (1) 安全否定、财务结果、错误和状态更改； (2) 完全未断言的公共结果； (3) 边界或由弱断言达到的确切值； (4) 已有断言行为的替代变体。

完成清单之前选择变异或断言。一个死亡的尝试、异常类型或开关分支不会清除其兄弟。

从完成的清单中选择断言：

- **强** 当核心分支和主要边界受保护，并且只有少数验证或默认情况变体剩余时；
- **混合** 当有意义的覆盖存在，但至少有一个重要结果分区未受保护时；
- **弱** 当重要结果广泛未受保护时。

少数验证间隙不会使其他情况下广泛的套件 **混合**，除非验证是命名风险或间隙威胁安全、数据或其他合同关键行为。

当清单满足上述 **强** 标准时，首先 **强** 并在列出次要间隙之前命名受保护边界和双重断言。不要以 `混合`、"仅核心路径" 或风险重的仪表板开头。

当现有断言杀死剩余候选者或没有可信的公共存活者时停止。不要变异每个操作只是为了填写报告或计算分数。

| 结果 | 含义 |
|---|---|
| **可能死亡** | 现有断言观察到改变的输出 |
| **候选存活（未验证）** | 可观察的改变似乎未断言；未执行 |
| **存活** | 确切的观察变异执行且测试保持绿色 |
| **无覆盖** | 没有测试达到公共结果；报告缺失分支而不发明存活者 |
| **等效** | 没有公共观察改变；从发现中省略 |

在显式验证、彻底审计或请求的测试添加之外，不执行任何变异。不要变异以确认明显的无覆盖。对于显式验证，执行每个独立高风险结果中的一个代表性候选者；不要在另一个保护、操作分支、错误类或否定未分类时停止执行第一个或第二个。省略等效语法变体。

### 6. 验证而不产生假阳性

仅在显式验证、彻底审计或请求的测试添加中进入此阶段。

1. 应用一个候选者并确认差异仅更改一个预期表达式。
2. 运行最狭窄的覆盖测试：绿色表示 **存活**，红色表示 **死亡**，仅针对该编辑。
3. 立即还原并确认干净的源/测试基线。
4. 在绿色运行后，重新检查公共反事实。执行证明套件遗漏了编辑，而不是编辑改变了行为；丢弃惰性或不可观察的变异。

永远不要在工作区留下变异。在报告之前，将每个未断言的高风险结果作为 **存活**、**候选存活（未验证）**、**无覆盖** 或省略的 **等效**。当没有可信的公共间隙时停止；不要用内部细节或计算分数填写报告，除非用户请求了彻底审计。

### 7. 仅在请求时关闭间隙

1. 仅对执行的 **存活** 变异或证明的 **无覆盖** 行为添加集中测试。
2. 在为已有断言行为的替代变体添加测试之前，覆盖请求范围内的每个不同间隙。
3. 在编辑之前，创建一个存活者到测试清单。在停止之前，将每个验证的存活者映射到添加的测试，并将每个添加的测试映射回验证的存活者；仅通过最终通过的套件不能证明完整性。
4. 保留请求时的生产代码和现有测试。
5. 优先考虑一个行为聚焦的测试，该测试杀死相关变异，而不是每个语法更改一个测试。
6. 重新应用原始变异并证明新测试杀死它，然后恢复源并干净地运行狭窄套件。
7. 如果固定或仓库提供了一个规范变异验证器，在添加测试后运行该确切命令并引用其成功结果。手创建的替代变异、广泛的绿色套件或测试计数增加不能取代提供的预言者。一旦每个请求的存活者映射到一个集中测试并且规范验证器通过，停止；额外的测试不是优势。
8. 当请求要求现有源或测试文件保持不变时，将每个受保护的文件与编辑前的快照逐字节比较并报告证据。在添加测试之前，证明其证人与相关分支、边界或舍入结果上的每个现有案例都不同，以便名义上新的测试不会重复现有覆盖。

## 输出合同

根据请求调整响应。

对于集中或小分析，返回：

1. 一个单行断言：**强**、**混合** 或 **弱**，以及原因。
2. 对于 **强** 套件，一个简短的优势句子，命名证明断言的具体系受保护边界、保护或配对观察。
3. 每个可操作的 **存活**、**候选存活（未验证）** 或 **无覆盖** 结果一个紧凑行。在添加行之前，如果请求命名了风险，则应用结果允许列表，然后应用可观察候选者规则；省略任何失败任一过滤器的候选者。包括每个高风险结果，使用每个不同公共结果一行，并仅合并相关的低风险变体：

   | 风险 | 公共结果 | 变更 | 结果/证据 | 最小测试 |
   |---|---|---|---|---|

   每个间隙需要一个区分的证人和一个具体的测试。错误路径间隙必须命名无效输入和预期错误/结果。

4. 对于 **混合** 或 **弱** 套件，一个简短的优势句子，命名重要被杀行为。
5. 当请求命名排除时，一个简短的范围句子，命名有意跳过的生成、简单或不相关的代码。

不要在散文中重复表格或报告丢弃的变异、工具时间线或飞行中推理。

对于彻底审计，添加被杀/存活/无覆盖/等效计数，并按风险分组发现。仅执行或明确分类的候选者计数。

对于测试添加，命名添加的测试、它们杀死的验证变异以及成功的最终命令。

## 可靠性规则

- 通过的测试如果未断言改变的输出，不会杀死一个变异。
- 覆盖是按行为分区。一个开关/三元臂或复合输入不会证明兄弟：允许不会证明否定；读取不会证明写入；空不会证明空或空白，当这些输入有不同的调用者可见输出时。一个杀死仅清除运行的编辑和路径。
- 通过公共方法达到的私有辅助仍然在范围内。
- 错误语义是语言特定的：在 Rust 中，`?` 传播与恐慌是可观察的行为；在 C# 中，异常类型以及输入保护或拒绝值是否接受是可观察的行为。
- 将每个确切金额或边界结果与未修改的实现或现有确切断言交叉检查。如果无法检查，则陈述行为关系，而不要编造一个数字。
- 不要仅仅因为一个变异存活就标记发现为高风险。
- 永远不要为现有套件已经保护的行为推荐冗余测试。

## 验证

- [ ] 范围与请求成比例
- [ ] 原始套件通过，或静态限制明确
- [ ] 范围内每个高风险公共结果都被列出
- [ ] 原始和变异有不同的调用者可见观察
- [ ] 每个标记为 **存活** 的结果都执行了；未执行的候选者使用 **候选存活（未验证）**
- [ ] 每个临时变异都还原了
- [ ] 发现排除简单、生成和等效更改
- [ ] 建议仅针对已证明的间隙
- [ ] 范围内每个公共入口点分支和每个接受的异常类型都明确说明
- [ ] 提供的规范变异验证器运行并报告，而不是用临时代理替换
