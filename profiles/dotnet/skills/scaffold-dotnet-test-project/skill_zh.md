# 创建或修复 .NET 测试项目

创建最小的缺失测试容器或仅修复缺失的连接。
目标是通过仓库的真实构建入口点进行测试发现，而不是首选的解决方案布局。

## 仓库覆盖层

对于每个仓库范围的任务，只要允许只读文件检查，就先在仓库根目录检查 `.agents/skill-overlays/dotnet-test/scaffold-dotnet-test-project.md`，然后再进行任何其他发现。这包括要求代码或建议但不进行修改的请求；“不执行”并不禁止读取覆盖层。如果存在，则在采取行动之前只读取一次，并应用其仓库特定的命名、布局、框架和政策绑定。
在应用它之前，要求其 frontmatter 声明 `core: dotnet-test/scaffold-dotnet-test-project`、`binding-revision: "1"` 和 `mode: extend`。如果任何值缺失或不同，则报告不匹配，并继续使用此技能的可移植指南，而无需应用覆盖层。
明确的用户指令和经过验证的项目约束优先于覆盖层；覆盖层优先于此技能中的可移植默认值和示例。如果文件存在但不可读或与仓库冲突，则报告问题并继续使用可移植指南，不使用覆盖层，并受经过验证的项目约束约束。如果它不存在，则继续正常操作。仅在任务未关联到仓库或用户明确禁止所有文件/工具访问时才跳过查找。覆盖层不能扩展工具权限或任务的范围。

## 引导请求

在编辑之前检查仓库，然后选择确切的一条路径：

| 仓库状态 | 操作 | 不要做 |
|---|---|---|
| 没有合适的测试项目 | 创建一个受约束的项目，引用生产项目，并注册它 | 每个源项目创建一个项目 |
| 测试项目存在但缺少必要的 `ProjectReference` | 仅添加该引用并验证直接加入口点执行 | 搭建另一个项目或重写测试 |
| 测试项目直接通过但不在 `.sln`、`.slnx` 或 `.slnf` 中 | 在 CI 使用的确切入口点中注册现有项目 | 重新创建项目或切换解决方案格式 |
| 合适的项目、引用和请求的入口点已经正确 | 保持工作区不变；如果请求测试方法，则使用 `code-testing-agent` | 规范化或替换工作文件 |

当现有项目合适时，其目标框架可以引用生产项目，并且其目的与请求的层匹配。不同的首选名称不是创建重复的原因。

**无操作是必需的结果。** 如果合适的项目、生产引用和请求的入口点注册已经存在，则进行零文件更改。不要添加或删除冒烟测试、规范化项目、重新创建包或编辑基线/快照副本。报告现有路径并停止。

## 工作流程

### 1. 建立仓库契约

从任务的当前工作目录开始。技能上下文的 `Base directory` 是这些指令所在的目录，而不是用户的仓库。永远不会搜索父临时目录或将技能安装视为工作区。如果预期的文件不可见，则在断定项目缺失之前确认当前目录。

将每个编辑和验证命令锚定到用户命名或从当前目录建立的仓库路径。如果存在类似命名的固定装置、解决方案或复制树，则不要编辑或验证一个作为请求树的替代品。在更改解决方案工件之前，记录其确切路径；更改后，立即列出相同的工件，并要求测试项目出现才能继续。

读取足够的信息以确定：

1. 生产项目和请求的测试范围；
2. CI 使用的命令和 `.sln`、`.slnx`、`.slnf` 或项目图；
3. 是否存在合适的测试项目、它引用的内容以及注册位置；
4. 邻近的测试框架、运行器、目标框架、可空和隐式 usings 规则；以及
5. 包或 SDK 版本是否来自 `Directory.Packages.props`、`Directory.Build.props`、`global.json` 或 MSBuild SDK 声明。

如果用户报告测试项目直接通过但解决方案级发现找不到，则将其视为注册证据。在考虑项目创建之前，检查入口点。

### 2. 仅在项目缺失时创建

为最窄请求的生产项目选择一个测试项目。按顺序遵循用户的显式框架选择、邻近的测试项目、仓库范围的包/SDK 常规，然后是一个标准 SDK 模板。

仅在生成的框架生成和包样式与仓库契约匹配时使用 `dotnet new` 模板。在创建之前检查模板可用性。特别是，通用的 `dotnet new xunit` 通常发出 xUnit 2 包；对于中央管理的 `xunit.v3` 仓库，使用仓库或安装的 xUnit v3 模板，或直接创建最小的 SDK 项目。永远不要生成带版本号的 xUnit 2 引用，然后再将它们重写为 xUnit v3。

然后：

1. 对齐目标框架、可空、隐式 usings、运行器和包样式；
2. 使用 `dotnet add <test-project> reference <production-project>` 仅用于请求的测试执行的生产项目；
3. 删除模板示例文件（如 `UnitTest1.cs`），然后创建一个行为命名的测试文件，而不是重用模板文件名；以及
4. 当中央包管理提供版本时，省略包版本。

对于通过 `dotnet test` 运行的 xUnit v3 项目，保留或添加：

```xml
<OutputType>Exe</OutputType>
<TestingPlatformDotnetTestSupport>true</TestingPlatformDotnetTestSupport>
```

`OutputType=Exe` 仅证明自托管运行器路径，而不是通过仓库的 `dotnet test` 命令发现。

### 3. 仅在项目存在时修复缺失的边缘

- 缺失生产引用：使用 `dotnet add <test-project> reference <production-project>`，检查生成的项目，并保持每个其他项目元素和所有测试源文件不变。比较项目前后，以便添加的 `ProjectReference` 是唯一的语义更改。
- 缺失 `.sln` 或 `.slnx` 注册：运行 `dotnet sln <entry-point> add <test-project>`，然后立即运行 `dotnet sln <entry-point> list` 对该确切路径。如果项目缺失，则修复未发生；不要验证兄弟解决方案或报告成功。
- 缺失 `.slnf` 注册：如有必要，将现有项目添加到其底层解决方案，然后在过滤器中包含相同的现有项目路径。如果底层解决方案已经包含它，则仅编辑过滤器。
- 多个解决方案工件：仅修改用户命名或 CI 调用的那个。不要用更简单的格式替换。
- 没有解决方案工件：保留现有的项目导向工作流程。不要为美观创建解决方案。

### 4. 仅添加请求的冒烟行为

对于新创建的项目，用用户请求的最小冒烟套件替换模板示例。每个测试必须调用真实的生产符号，并断言具体的确定性结果，而不依赖网络、时间、进程或真实文件系统。

对于现有项目连接修复，除非用户明确要求测试行为更改，否则不要添加、重写、重命名或扩展测试。注册和测试编写是分开的操作。

### 5. 验证修复的路径

运行证明所选路径的最窄命令：

| 路径 | 必需的证据 |
|---|---|
| 新创建的项目 | `dotnet test <test-project>`、CI 使用的确切入口点命令，以及注册列表。如果入口点是包含测试的 `.slnf`/`.slnx`，则在该工件上运行 `dotnet test` 而不是仅证明它构建。 |
| 缺失引用 | 目标项目测试加上请求的精确解决方案/根测试命令 |
| 缺失 `.sln`/`.slnx` 注册 | 列表和 `dotnet test` 对该确切工件的运行；永远不要使用另一个解决方案作为后备 |
| 缺失 `.slnf` 条目 | 检查过滤器条目并运行确切的 CI 过滤器构建命令；不要添加故意失败的备用命令 |
| 已经正确/无操作 | 现有引用和注册的结构检查。除非请求执行，否则不要运行测试仅为了证明无操作，因为那会创建 `bin`/`obj` 并削弱字节对字节清洁证据。 |

在添加开关之前检查仓库的命令。不要添加推测性的 `--no-restore` 尝试或将替代方案隐藏在 `command-a || command-b` 中；运行配置的入口点命令，其干净的退出是证据。

对于每个连接修复，直接调用确切的验证命令并保留其退出状态。读取生成的文件、评分脚本或后续构建不能替代观察该命令成功完成。

在报告完成之前，检查最终的更改文件集。仅当它们先前不存在且未被有意跟踪时移除 `bin`/`obj` 或等效构建工件；永远不要移除预存在的工件。保留通过命令的完整结果，以便手交可以声明确切的入口点和发现的测试数量。

对于无操作，检查而不是重写并报告现有路径。绿色的 `dotnet build` 不是测试发现证据。如果验证被阻塞，报告确切的失败命令和第一个可操作的错误；永远不要将未运行或失败的命令描述为成功。

## 输出

保持手交与更改成比例：

| 要求 | 证据 |
|---|---|
| 项目创建、重用或修复 | 测试项目路径和选择的路径 |
| 生产引用 | 引用的 `.csproj`，或为什么不需要更改 |
| 构建注册 | 精确的 `.sln`/`.slnx`/`.slnf` 条目或项目工作流程 |
| 测试发现 | 通过的套件级命令和发现的测试 |

## 完成检查

- 在创建之前检查了现有项目。
- 仅引用和测试请求的生产范围。
- 框架、运行器、目标框架和中央包常规保持完整。
- 从新创建的项目中移除了模板样本。
- 对于仅修复连接，现有的测试代码未更改。
- 确切的仓库入口点发现并运行了测试项目。
