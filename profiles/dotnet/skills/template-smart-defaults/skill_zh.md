# 模板智能默认值

此技能帮助代理在创建 `dotnet new` 项目时填写跨参数默认值。以下规则是保持相关参数一致的指导启发式算法——它们仅填充空白，永远不会覆盖用户显式设置的值。

## 使用场景

- 用户要求创建项目但未指定相关参数
- 用户选择的参数隐含了另一个参数的合理值
- 需要解释为何选择了特定默认值

## 不适用场景

- 用户实际要创建项目——路由到 `template-instantiation`
- 用户要查找或比较模板——路由到 `template-discovery` 或 `template-comparison`
- 用户要编写或验证自定义模板——路由到 `template-authoring` 或 `template-validation`

## 输入

| 输入 | 必填 | 描述 |
|-------|----------|-------------|
| 模板简称 | 是 | 项目将基于的模板（例如，`webapi`） |
| 已选择的参数 | 是 | 用户显式设置的参数值 |
| 可用选项 | 推荐 | 来自 `dotnet new <template> --help` 的参数名称/选项 |

## 工作流程

1. 收集用户显式设置的参数。
2. 对每个以下规则**仅在相应的参数未设置时应用**——永远不会覆盖用户显式设置的值。
3. 每当用户要求精确命令时，确认所选参数名称和选项是否符合 `dotnet new <template> --help`。这种检查不会创建文件，即使是仅提供建议的请求也值得进行。仅当概念解释不声称精确选项名称时才跳过。
4. **发出两个必需输出**（见下文）——这是使技能起决定性作用而非被动的原因。

对于说“不要创建文件”的建议性提示，通过追加 `--dry-run` 使显示的命令安全可运行。如果场景需要一个命名示例而用户遗漏了名称，选择一个简短描述性的示例名称并标记为 `Source = rule`。当用户要求仅包含显式请求选项的命令时，或者当模板可以安全演示这些选项而不需要名称时，不要添加名称。

### 必需输出

始终按此顺序生成**两者**：

**A. “已应用默认值”日志**——每个参数一行，覆盖**两者**：用户保留的显式值（`Source = user`）和通过规则填充的空白（`Source = rule`），以便用户可以查看和覆盖每个选择：

| 参数 | 值 | 来源 | 原因 |
|-----------|-------|--------|-----|
| `--framework` | `net10.0` | rule | 原生AOT（来自 `--aot`）需要最新的AOT兼容TFM |
| `--auth` | `Individual` | user | 显式请求——未更改 |
| `--name` | `AotWorker` | rule | 为此命名示例添加了描述性示例名称 |

使用 `Source = user` 表示显式值（永不覆盖），使用 `Source = rule` 表示空白填充。

**B. 您将运行的精确单个 `dotnet new` 命令行**——仅包含您实际传递的标志。不要列出您决定*不*传递的标志（例如，当保留HTTPS时，不要提及 `--no-https`；使用控制器时，不要提及最小API标志）。省略未提及的标志是正确且决定性的信号。

当观察到的模板帮助暴露了用户显式请求的标志时，即使其值与模板默认值匹配，也始终发出该标志；这使意图可见且可重复（例如，`--auth None`）。仅省略**推断**的默认值，即您未实际传递的默认值。布尔开关（如 `--no-https`）不带 `true` 传递。

> **创建时AOT与发布时AOT**。`--aot` 仅在暴露它的模板上是 `dotnet new` 标志——始终通过 `dotnet new <template> --help` 确认，而不是假设某个模板是否提供它。没有 `--publish-aot` 模板标志——发布时原生AOT通过MSBuild属性 `PublishAot=true`（通过 `dotnet publish` 或在 `.csproj` 中）启用，而不是通过 `dotnet new`。仅在模板实际提供 `--aot` 时应用框架规则。

### 规则

| 规则 | 应用的默认值 | 理由 |
|------|-----------------|-----------|
| `--aot` 被设置（在任何 `--help` 暴露它的模板上）且 `--framework` 未设置 | 将 `--framework` 设置为模板提供的最新AOT兼容框架 | 原生AOT需要一个较新、支持AOT的目标框架；使用最新版本可避免构建失败。（工作区或 `global.json` 已固定框架视为已设置——除非它与AOT不兼容，否则保持它。） |
| `--auth` 不是 `None` | 不要传递 `--no-https` | 身份验证流（cookie、令牌、重定向）需要HTTPS；禁用它会破坏身份验证。 |
| `--use-controllers` 被设置 | 不要同时传递最小API标志 | 控制器和最小API是互斥的程序模型；同时传递两者是矛盾的。 |
| 用户显式设置了值 | 保持不变 | 智能默认值仅填充空白；显式用户意图始终优先。 |
| 建议性命令必须不创建文件 | 添加 `--dry-run` | 命令本身必须遵守不写入约束，而不仅仅是代理的行为。 |

当显式请求控制器时，命令必须包含 `--help` 显示的控制器选项；不传递选项解释控制器是不完整的。

## 验证

- [ ] 产生了“已应用默认值”日志，每行包含来源（用户/规则）和理由
- [ ] 发出了精确的单个 `dotnet new` 命令行，仅列出实际传递的标志
- [ ] 未覆盖用户显式设置的任何参数
- [ ] 仅填充了未设置的参数
- [ ] 确认了精确的参数名称/选项是否符合 `dotnet new <template> --help`，包括建议性精确命令
- [ ] 不创建文件的建议性命令包含 `--dry-run`
- [ ] 布尔开关不带尾随的 `true` 发出

## 常见陷阱

| 陷阱 | 解决方案 |
|---------|----------|
| 将启发式算法视为强制执行 | 这些是指导规则，不是验证。始终通过 `dotnet new <template> --help` 选择进行确认，因为参数名称因模板而异。 |
| 覆盖显式用户值 | 仅在目标参数未设置时应用规则。 |
| 假设标志名称 | 每个模板的精确标志都不同——始终通过 `--help` 验证（例如，`--aot` 仅在 `--help` 列出它时存在；控制器使用 `--use-controllers`）。 |
| 选择模板不支持的框架 | 使用模板的 `--framework` 选择中出现的最新框架，而不是任意最新版本。 |
| 在“不要创建文件”后显示普通创建命令 | 追加 `--dry-run` 以确保显示的命令安全可执行。 |
