# 测试异味检测

使用学术分类法、代码证据、校准框架惯用语以及代码库原生修复方法审计测试代码。

## 范围

- 仅审计已暂存或命名的测试。在请求代码之前搜索当前工作区；在搜索未找到相关测试之前，不要声称文件缺失。
- 仅在更改判定结果时读取生产代码。
- 对于不熟悉的框架 API，调用 `test-analysis-extensions` 并读取匹配的语言扩展。
- 当调用者请求所有 19 种异味、请求引文或代码可能包含高信号集以下的外部异味时，读取 [完整目录](references/test-smell-catalog.md)。对于此文件回答的狭窄问题，不要加载它。

## 审计工作流程

1. 搜索并读取已暂存的测试；检测语言、框架、边界和集成标记。即使没有命名路径，这也是第一个动作。
2. 读取测试和仅更改判定结果的生产上下文。
3. 对于每个候选项，验证执行检查、选择正式类别、校准，然后分配严重性。将已证明的非目录测试有效性缺陷单独报告；不要将它们重新标记为异味。
4. 按照虚假置信度或易变性的风险或维护成本对确认的发现进行排序。
5. 为每个可操作的发现提供框架正确的替换方案。不要在其他生态系统中使用 .NET 术语或 API。

## 高信号判定

| 证据 | 学术发现 | 应该做 | 绝对不要 |
|---|---|---|---|
| 断言行为在 `if`、`switch` 或分支循环后面改变 | 条件测试逻辑 | 分割情况或参数化它们 | 仅仅因为存在运行器循环就标记表格驱动或参数化测试 |
| 一个测试依赖于未声明的文件、网络服务、环境值或数据库 | 神秘访客或资源乐观 | 使依赖关系显式且封闭；使用完整目录区分两者 | 仅仅因为执行了其声明的真实资源就谴责集成测试 |
| 固定的墙上睡眠等待结果 | 睡眠测试 | 使用超时等待或轮询条件 | 仅仅因为测试是集成测试就降低其严重性 |
| 可执行的测试没有断言、预期异常标记或模拟验证 | 未知测试 | 断言可观察的结果 | 调用一个空体的未知测试；正式名称是空测试 |
| 异步断言/协程被创建但未被等待或返回 | 重要的非目录虚假通过缺陷 | 单独报告它并显示所需的 `await`/`return` | 强制它进入未知测试；断言语句存在 |
| 一个测试执行许多不相关的生产行为 | 贪婪测试 | 将行为聚焦的测试分开 | 标记一个没有考虑其范围的故意端到端工作流 |
| 预期的数字字面量没有本地意义 | 魔术数字测试 | 命名领域值或从设置中派生它 | 立即标记 `count == 3` 在添加三个项目之后 |
| 断言依赖于 `ToString`、`repr`、`description` 或显示格式，而不是合同 | 敏感等价性 | 断言稳定字段或使用结构匹配器 | 标记一个显式合同是格式化字符串的测试 |
| 测试手动管理预期异常流程 | 异常处理 | 使用框架的异常断言并检查有意义的详细信息 | 声明捕获和断言测试验证什么 |
| 共享设置创建与接收它的测试无关的状态 | 通用固定装置 | 移除未使用的状态或缩小固定装置；低排名廉价状态 | 仅仅因为它是共享的就谴责相关的共享设置 |
| 测试被禁用或跳过 | 忽略测试 | 报告每个跳过，但将跟踪的合理跳过排名低于未解释的跳过 | 因为其原因是好的而清除跳过，或给两者相同的紧迫性 |

## 校准规则

在分配发现之前应用这些规则：

- 模拟调用验证、快照、裸 pytest `assert`、Pester `Should -Invoke` 和预期异常结构是断言。
- 字面量或快照断言可能会暴露覆盖率差距，但没有单独的证据，它不是未知测试或其他异味。
- 计算断言语句。一个断言永远不会是断言轮；单独缺失消息不是异味。
- 相同方法的测试在覆盖不同行为、边界或状态时不是懒惰测试；需要冗余的等效路径。
- 通用固定装置需要共享生命周期状态。重复本地构造本身既不是通用固定装置，也不是测试代码重复。
- 将公共 API 返回的字符串视为可观察的合同，除非生产上下文或要求使其仅用于显示；插值本身不是敏感等价性。
- 魔术数字测试需要一个未解释的预言值。不要标记普通设置数量，其作用在本地明显且与断言行为无关。
- Go 表格驱动子测试、pytest/JUnit/xUnit 参数化、Jest/Vitest `.each`、RSpec 数据表、Pester `-ForEach` 和 Catch2 `SECTION`/`GENERATE` 本身不是条件测试逻辑。
- Go 的 `if err != nil { t.Fatal(...) }` 是断言流程的习惯用法，不是异常处理。
- 集成标记使声明的外部资源和多步流程合法化，但不是固定的睡眠或无断言执行。
- 对于集成测试，在判断分支覆盖率之前跟踪辅助工厂和存储库返回类型。如果一个测试在真实辅助器永远不可能产生的子类型或状态上分支，报告不可达的断言路径并解释由此产生的虚假置信度。不要在分配通用条件测试逻辑标签后停止。
- 本地临时文件仍然符合正式的神秘访客定义。封闭创建和清理降低其严重性；它们不会改变其分类。
- 格式化名称不能证明显示文本是稳定的合同；在从生产行为或要求中确认之前清除敏感等价性。
- 不要仅从方法名称中推断异味。指向证明它的语句或固定装置关系。
- 不要仅从测试名称中推断高严重性的非目录有效性缺陷。如果没有生产代码或明确的合同证明该测试应该调用另一个组件，名称/正文不匹配最多是一个未排名的观察结果，而不是测试在沉默中通过损坏的生产行为的证据。
- Catch2 `SECTION` 和 `GENERATE` 是运行器控制的案例扩展，`REQUIRE` 是一个真正的断言。当这些是唯一可疑的结构时，学术异味判定是 **干净**。不要因为测试可能有更广泛的行为覆盖范围而反转该判定。
- 如果校准后没有实质性的异味剩余，要明确说明。永远不要为了填满报告而制造发现。
- 不要为空或否则不可等待的 API 提议 `await`。如果生产工作是同步的，请移除睡眠并立即断言。

## 严重性

严重性遵循已证明的风险，而不是从目录中复制固定的标签：

- **高**：可以在行为损坏时无声通过，创建非确定性故障，或隐藏未执行的断言路径。
- **中**：使故障模糊或使测试与不稳定细节耦合。
- **低**：主要是维护债务，例如合理的跳过或过宽的廉价固定装置。

说明分配严重性的原因。当周围的测试类型使模式有意时，降级或省略发现。

## 输出合同

根据输入调整响应：

- 对于一个到三个文件，给出判定结果和一个紧凑的表格：严重性、正式异味、证据、风险和修复。
- 对于较大的套件，添加计数和简短的优先级顺序。不要在仪表板、散文和计划中重复发现。
- 仅在修复清晰时显示代码；省略未更改的设置。
- 仅对可能可疑的惯用语添加简短的 **未发现**。
- 在学术异味判定之后放置已证明的非目录有效性缺陷。在一个干净的输入和没有生产合同的情况下，不要为可选的覆盖率观察结果分配严重性，也不要让它们推翻干净的判定。
- 不要叙述发现或目录加载；直接返回审计。

每个报告的异味都必须有一个正式的分类名称、精确的位置、来自代码的证据、实际风险和一个具体的框架正确修复。

## 验证

- 每个发现都由代码支持，而不是关键字或方法名称。
- 未知测试和空测试保持区分。
- 每个禁用的测试仍然是忽略测试，每个本地文件依赖关系仍然是神秘访客；理由和封闭清理仅改变严重性。
- 框架惯用语和集成边界在报告之前进行了校准。
- 干净的测试和可疑但有效的惯用语不会被转换为填充。
- 干净的框架惯用语不会从命名或缺失生产上下文中转换为高严重性的非目录发现。
- 修复使用目标框架的 API 并保留测试行为。
- 关于审查的文件、构建或测试运行的说法与实际执行的操作相匹配。
