# 覆盖率分析

## 目的

解释 .NET 覆盖率证据证明的内容，协调目标算术，并识别阻碍进度的代码。仅在用户明确要求风险热点、CRAP、风险优先级或重构安全性时，才添加复杂度/CRAP排名。

## 使用场景

使用此技能来解释提供的 .NET 行/分支/条件证据、覆盖率缺口和平台期、目标算术，或显式的全项目覆盖率支持的风险分析。

## 不适用场景

- **命名方法、类或文件 CRAP/重构安全性分析** — 使用 `crap-score` 技能
- **静态源码到测试的配对或列出无测试的文件** — 使用 `find-untested-sources`
- **现有测试中的行为或伪变异缺口** — 使用 `test-gap-analysis`
- **按测试类型分布的测试特征/类别或覆盖率形状** — 使用 `test-tagging`
- **编写或生成测试** — 此技能识别测试需求，但不会编写测试
- **与覆盖率或 CRAP 分析无关的通用测试执行**
- **仅收集 .NET 覆盖率或打印未诊断的原始百分比** — 使用 `run-tests`；使用原生工具进行非 .NET 覆盖率收集或分析。解释 .NET 行/分支缺口仍在此范围内

## 输入

| 输入 | 必填 | 默认 | 描述 |
|------|------|------|------|
| 项目/解决方案路径 | 否 | 当前目录 | .NET 解决方案或项目的路径 |
| 行覆盖率阈值 | 否 | 80% | 可接受的最低行覆盖率 |
| 分支覆盖率阈值 | 否 | 70% | 可接受的最低分支覆盖率 |
| 现有 Cobertura 路径 | 否 | 仅在未提供时发现 | 优先输入；可用时无需重新运行测试 |
| CRAP 阈值 | 否 | 30 | 仅用于明确的风险/CRAP请求 |
| 热点数量 | 否 | 3 | 仅限明确的风险请求；最多限制为 10，除非用户要求更多 |

从工作区发现可选输入。当当前目录或提供的报告足够时，不要请求项目路径。

## 选择最小匹配路径

| 用户意图 | 必需工作 | 不要做 |
|----------|----------|--------|
| 解释提供的摘录、条件或摘要 | 直接从提供的证据回答 | 工具、CRAP、发现、报告文件 |
| 解释提供的 Cobertura 路径或诊断平台期 | 读取该报告，协调总数，命名所有重要缺口，直接回答 | 重新运行测试、安装工具、计算 CRAP 或生成文件，除非明确请求 |
| 排名风险热点、计算全项目 CRAP 或评估重构安全性 | 使用提供的/现有的报告，读取 `references/guidelines.md`，并在排名前计算 CRAP | 仅覆盖率排名或完整报告模板，除非请求 |
| 无报告时分析覆盖率 | 调用 `run-tests` 使用与仓库兼容的运行器收集覆盖率，然后分析生成的报告 | 独立选择或执行测试命令；CRAP 除非请求了风险 |
| 生成完整的 markdown/HTML/CSV 报告 | 首先提供直接答案；然后读取 `references/output-format.md` 或 `references/report-generation.md` | 在答案之前生成报告 |

诸如 **分析覆盖率**、**什么阻碍了覆盖率** 或 **为什么覆盖率卡住** 等词语本身并不要求 CRAP。明确信号包括 **风险热点**、**CRAP**、**复杂度加权优先级**、**安全重构** 或等效请求将复杂度与覆盖率结合。

## 现有数据快速路径

当用户提供覆盖率摘录、摘要或有效的 Cobertura 路径时：

- 将其视为权威输入并从此开始。
- 除非源映射必要，否则不要发现解决方案或测试项目。
- 不要运行 `dotnet test`、安装 ReportGenerator、添加覆盖率包或读取 `references/setup-discovery.md` 或 `references/report-generation.md`。
- 除非用户请求保存/完整报告，否则不要编写 `coverage-analysis.md` 或创建报告目录。
- 对于解释和平台期问题，仅解析回答所需的证据。对于明确的全项目风险请求，使用 `references/guidelines.md` 中描述的捆绑脚本。

读取/查看操作失败不是证明命名路径不存在的证据。分类失败，然后进行一次有针对性的存在探测，并仅在使用原生工具可用性、传输或路径规范化失败后使用规范化路径或替代读取器，并在验证规范路径仍在工作区内部后停止。内容排除、权限/策略、工作区边界或未知失败时停止。仅当独立探测也失败时才报告缺失路径；不要扩大搜索或替代另一个工件。

## 收集路径

仅在无可用覆盖率证据且用户请求需要它的分析时使用此路径。

1. 读取 `references/setup-discovery.md`。
2. 优先选择在请求的根下发现的现有 Cobertura。
3. 如果不存在，调用 `run-tests` 进行仓库覆盖、平台、运行器和命令选择，并让它对每个入口点收集一次 Cobertura。
4. 分析生成的 Cobertura。仅当明确请求风险分析时才计算 CRAP。

当工作区包含此路径需要的项目/测试清单时，直接执行发现并将收集委托给 `run-tests`。不要要求用户附加文件或预先运行当前工作区允许检查和生成的覆盖率。

不要修改生产代码。任何为收集所需的测试项目更改都属于 `run-tests`；在最终分析中包含该更改及其撤销命令。

自动收集路径适用于 SDK 风格项目。对于经典非 SDK 或 `packages.config` 项目，仅使用仓库拥有的覆盖率命令。如果不存在，停止并请求 Cobertura XML。永远不要迁移项目、注入 SDK 风格提供程序、创建包装项目或报告来自其他程序的替代覆盖率。

## 解释和算术不变量

- 行命中证明执行，但不是两个决策结果。
- `condition-coverage="50% (1/2)"` 证明一个报告的结果运行了，但不是哪个。建议强制执行相反的结果。没有源码，永远不要编造可能的自变量或声称是否缺失。说明复合自变量需要独立执行的运算符，并在适用时说明短路组合；不要在未提供源码或更完整的 XML 的情况下推断确切组合。
- 从 Cobertura 的覆盖/有效行计数中推导出总体总数。对于目标 `T`，所需覆盖行是 `ceiling(valid lines × T)`。
- 预计覆盖率是 `(当前覆盖行 + 新覆盖的独立行) / 有效行`。说明假设，例如完全覆盖一个方法。
- 当被问及一个成员是否可以达到目标时，显示其最大预计总数，并至少提供一个具体的足够成员或行增益的组合。如果没有提供的组合足够，说明这一点。
- 对于多成员目标，命名确切组合和结果覆盖/有效总数；仅说“与其他成员结合”是不完整的。
- 将成员缺口与项目总数协调。方法行范围可以重叠或省略类级别的行，所以不要将方法计数作为项目真相进行求和。
- 永远不要将一个成员称为 **唯一**、**全部** 或 **所有** 剩余缺口，除非其独特的未覆盖行正好与项目总数协调，并且没有其他低于阈值的成员剩余。
- 命名所有提供的或提取的低于阈值的成员，但保持细节成比例：首先列出阻碍者，用一句话或紧凑表格总结其余部分。

## 响应契约

在第一句到第四句内回答用户的问题。

- **摘录或算术问题**：一个解释加上下一个测试或成员优先级。无仪表板。
- **现有报告解释或平台期**：总体行/分支覆盖率、阻碍成员、协调目标影响和 1-3 条建议。最多使用一个紧凑表格。
- **明确的风险/CRAP 请求**：默认情况下显示前 3 个实际热点，支持复杂度/覆盖率/CRAP 值，剩余标记数量和 1-3 个优先级。从热点表中排除完全覆盖的低风险方法。除非用户请求更大的数量，否则最多不超过 10 行。对于重构安全性，按 CRAP 而不是原始覆盖率单独排名，然后分别命名相对安全的良好覆盖方法。
- **明确的完整报告请求**：读取 `references/output-format.md`。仅在此时保存报告。

仅报告存在的工件。当没有请求文件时，不要宣布无法访问的输出路径或失败的可选文件写入。

## 可选报告

HTML/CSV/markdown 文件不是正常分析的一部分。仅在用户明确请求报告文件或 CI 工件时才生成它们。

1. 首先提供直接的覆盖率/风险答案。
2. 对于完整的 markdown 报告，读取 `references/output-format.md` 并保存它。
3. 对于 HTML/CSV，然后读取 `references/report-generation.md`。在直接答案之前不要安装 ReportGenerator，并且不要重试失败的安装。

## 验证

- 确认使用的报告未进行测试执行或工具安装。
- 在预计影响之前协调覆盖、有效和未覆盖行的总数。
- 确认每个声明的阻碍者来自提供的或提取的证据。
- 如果请求了 CRAP，使用 `references/guidelines.md` 检查一个分数。
- 如果请求了文件，验证它们存在后再报告其路径。

## 常见陷阱

- **现有报告触发设置工作** — 停止。首先分析命名的工件。
- **通用分析触发 CRAP** — 停止。CRAP 需要明确的风险意图。
- **一个方法被称为全部缺口** — 首先协调独特的未覆盖行和所有低于阈值的集合。
- **小请求得到仪表板** — 缩小到直接答案或一个表格。
- **收集无 Cobertura** — 报告收集失败；不要编造替代覆盖率。
- **编译器生成的成员名** — 在呈现它们为用户编写的成员之前，验证可疑的异步、lambda 或局部函数名与源码。
- **测试退出码 1** — 覆盖率可能仍然存在；带警告继续。其他非零构建失败停止收集路径。
