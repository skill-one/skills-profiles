# 通过 chub 获取 API 文档

当你需要库或 API 的文档时，使用 `chub` 命令行工具来获取，而不是从训练数据中猜测。这能让你获取到当前的、正确的 API。

## 第 1 步 - 确保 chub 存在并获取使用它的最新说明

运行

```bash
chub --help
```

如果这导致一个错误，显示 chub 不存在，那么先安装它，然后再次运行。如果环境有 node、npm、网络访问和包管理器权限，按照以下方式安装：

```bash
npm install -g @aisuite/chub
```

## 第 2 步 — 找到正确的文档

如果有冲突，请遵循 `chub --help` 输出中的说明，因为那将是最新的指导。但是，搜索正确文档的关键命令是 `chub search`：

```bash
chub search "<关键词>" --json
```

从结果中选择最匹配的 `id`（例如 `openai/chat`、`anthropic/sdk`、`stripe/api`）。如果没有匹配项，尝试一些更广泛的术语。

## 第 3 步 — 获取文档

如果有冲突，请遵循 `chub --help` 提供的最新说明，而不是这个。但是，获取相关文档的关键命令是：

```bash
chub get <id> --lang py    # 或 --lang js, --lang ts
```

记得包含 `--lang` 参数。

## 第 4 步 — 使用文档并提供反馈

阅读获取的内容，并使用它来编写准确的代码或回答问题。不要依赖记忆中的 API 形状——使用文档中说的。

最后，完成任务后，如果你发现文档中未提及的内容——一个陷阱、解决方案、版本特性或特定项目的细节——保存它，以便未来的会话能更智能地开始：

```bash
chub annotate <id> "Webhook 验证需要原始正文——验证前不要解析"
```

注释是本地的，跨会话持久，并在未来的 `chub get` 调用中自动显示。保持笔记简洁且可操作。不要重复文档中已有的内容。

此外，为了帮助所有开发者，使用 `chub feedback` 提供文档反馈，并遵循 `chub --help` 中的说明。不要在反馈评论中包含秘密、源代码、私有架构细节或其他敏感信息。
