# 会话结束前技能

在结束 Claude Code 会话之前运行此技能，以捕获学习成果并传播有用的设置。

## 激活时机

- 用户说：“完成”、“准备收尾”、“结束会话”、“再见”、“都结束了”、“我完成了”
- 完成了重要工作而没有明确要求继续
- 用户明确调用 `/pre-session-end`

## 工作流程

### 第 0 步：英文校正

在进行其他步骤之前，提供此会话中用户原始提示的修正版或更自然的版本。

**格式：**
```
## 英文校正

**原始：** [用户的原始提示]
**修正：** [修正/更自然的版本]
[如果修改较大，请简要说明修改了什么以及为什么]
```

- 只有在需要时才包含此部分
- 侧重语法、措辞和自然表达
- 保持解释简洁

### 第 1 步：分析会话以查找可学习模式

回顾聊天历史并识别：

#### 技能候选
可能成为可重用技能的模式：
- 重复的工作流程（例如，“提交前始终运行测试”）
- 运作良好的问题解决方法
- 多次应用的特定领域知识
- 一直保持一致使用的代码模式或架构

#### 命令候选
可能成为斜杠命令的操作：
- 重复执行的多步骤序列
- 工具的常用参数组合
- 项目特定的工作流程

#### 代理候选
可能成为代理的专门任务模式：
- 复杂的多工具操作
- 需要特定专业知识或上下文的任务
- 重复的分析或审查模式

### 第 2 步：展示提取的学习成果

针对每个候选项，向用户展示：
```
**潜在技能：** [名称]
- 观察到的模式：[描述]
- 将节省：[它如何帮助]
- 建议位置：~/.claude/skills/learned/[名称].md

创建此技能？ [是/否/编辑]
```

### 第 3 步：将项目权限传播到全局

1. 读取项目设置：`.claude/settings.local.json`
2. 读取全局设置：`~/.claude/settings.json`
3. 识别仅在项目设置中存在的权限

针对每个仅在项目设置中找到的权限：

**对权限进行分类：**
- **通用工具权限**：`Bash(git:*)`、`Bash(npm:*)`、`Bash(docker:*)` → 可能全局有用
- **特定领域网络**：`WebFetch(domain:docs.example.com)` → 询问用户是否通常有用
- **项目特定路径**：包含项目目录路径 → 跳过（不可移植）
- **MCP 服务器权限**：`mcp__*` → 询问用户（可能是项目特定的）

**有选择地展示每个：**
```
**在项目设置中找到的权限：**
`Bash(helm template:*)`

此权限允许：运行 helm template 命令
当前：仅项目
建议：[全局有用 / 项目特定]

传播到全局设置？ [是/否]
```

### 第 4 步：应用已批准的更改

1. **对于已批准的技能**：在 `~/.claude/skills/learned/` 中创建文件
2. **对于已批准的权限**：更新 `~/.claude/settings.json`
3. 报告已应用的更改

### 第 5 步：会话总结

提供简要总结：
```
## 会话收尾完成

**捕获的学习成果：**
- [X] 创建技能：skill-name
- [X] 创建命令：command-name
- [ ] 跳过：pattern-name（用户拒绝）

**传播的权限：**
- [X] Bash(helm:*) → 全局
- [ ] WebFetch(domain:internal.corp) → 保持仅项目

**准备结束会话。**
```

## 重要提示

- **绝不自动应用**：每次更改都需要用户确认
- **保留现有设置**：未经明确批准，不要覆盖现有的技能/设置
- **保持选择性**：只建议真正有用的模式，而不是每个重复的操作
- **解释价值**：对于每个建议，解释为什么值得保存
