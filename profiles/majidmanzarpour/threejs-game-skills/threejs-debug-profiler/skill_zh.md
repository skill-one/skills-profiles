# Three.js 调试分析器

在不影响可玩性的前提下，找到根本原因并优化测量的瓶颈。

追踪行为变化的作用范围。复用负责人现有的复现步骤和证据；修复后验证受影响路径。当共享行为发生变化或存在未解决的隐患时，通过更广泛的测试来验证通过的重点检查。将测量结果和缺陷返回给负责人进行整合验证。

## 参考

`references/debug-playbook.md` — 顺序处理空白画布、资源与音频加载、循环/动画/物理、输入与移动、分析序列以及 `__THREE_GAME_DIAGNOSTICS__` 结构。在调试或分析任何非明显问题时阅读它。

## 调试

1. 使用用户相同的命令和 URL 本地复现。
2. 查看控制台、页面和网络错误。
3. 检查画布显示尺寸与绘制缓冲区尺寸。
4. 检查渲染器、上下文和循环所有权 — 多个活跃循环是常见原因。
5. 检查相机宽高比、近远裁剪平面、灯光、材质、雾效、场景内容、变换。
6. 检查资源路径、加载器、CORS 和基础路径。
7. 检查动画增量单位、物理更新顺序和固定步长、碰撞体和物理体所有权、输入监听器、指针和触摸行为、调整大小和音频上下文解锁（涉及音频时）。
8. 在拥有该模块的负责人处修复根本原因，然后重新测试确切的故障路径。

## 分析

1. 在正确的构建模式下复现 — 当用户界面性能重要时使用生产预览模式。
2. 基线场景：FPS 和帧时间、绘制调用、三角形、几何体、纹理、内存、包。
3. 将瓶颈分类为 CPU、GPU 绘制、GPU 片段、GPU 顶点、内存或网络。
4. 改变一个因素 — 实例化、共享资源、剔除、细节层次、DPR 限制、更便宜的阴影或后期处理、纹理规范。
5. 重新测量相同场景并确认视觉效果和可玩性保持不变。

## 报告

先说明根本原因或测量的瓶颈。然后是更改的文件、基线和后置指标、命令、截图、重新测试的故障路径和残余风险。
