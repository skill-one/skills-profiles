# 图像识别

本技能指导您如何使用多模态图像识别 API 分析来自 URL 的图像，并根据用户意图提取有意义的信息。

## 核心概念

图像识别工具接受一个图像 URL 和一个可选的自然语言要求，描述用户想知道图像中的哪些信息。后端使用多模态 AI 模型来解释视觉内容，并返回文本描述或分析结果。

**支持格式**：JPG、JPEG、PNG、GIF、WebP、BMP。

**工作原理**：您提供一个公开可访问的图像 URL 和一个要求（您想从图像中了解什么）。服务下载图像，运行多模态分析，并返回基于文本的结果。

## 参数指南

| 参数       | 必填 | 描述         |
|------------|------|-------------|
| imageUrl   | 是   | 指向图像的公开可访问 URL。必须是 JPG、JPEG、PNG、GIF、WebP 或 BMP 格式。最大 1000 个字符。 |
| requirement | 否   | 对图像中要识别或分析内容的自然语言描述。省略时默认为“描述此图像的内容”。最大 1000 个字符。 |

### 编写 requirement 参数的提示

1. **具体说明**：不要说“分析此图像”，而要说“列出货架上所有可见的产品并估计其类别”。
2. **说明目标**：如果您需要文本提取，可以说“从图像中提取所有可见文本”。如果您需要物体识别，可以说“识别主要物体及其颜色”。
3. **在必要时提供上下文**：对于产品图像，提及“这是一个电商产品列表图像”，以便模型可以调整其分析。

## 本地图像上传

本工具需要一个**公开可访问的图像 URL**。如果用户提供一个本地图像文件路径（例如 `C:\Users\...\photo.png`、`/home/.../image.jpg`），您必须先将其上传以获取一个公共 URL。

运行上传脚本：
```bash
python scripts/upload_image.py /path/to/local/image.png
```

脚本将返回一个公共 URL（有效期为 24 小时），该 URL 可用作图像 URL 参数。

## 使用示例

**1. 一般图像描述**
- 用户说：“这张图片里有什么？”
- 设置 `imageUrl` 为提供的 URL，`requirement` 保持默认。

**2. 产品图像分析**
- 用户说：“分析这张亚马逊产品图像，并列出显示的关键卖点。”
- 设置 `requirement` 为：“这是一个亚马逊产品列表图像。识别图像中的产品、关键功能和卖点。”

**3. 从图像中提取文本**
- 用户说：“读取这张屏幕截图中的文本。”
- 设置 `requirement` 为：“从图像中提取所有可见文本，尽可能保留布局。”

**4. A+ 页面图像审查**
- 用户说：“描述这张 A+ 内容图像传达的信息。”
- 设置 `requirement` 为：“这是一个亚马逊 A+ 产品描述图像。描述视觉内容、关键信息和品牌元素。”

**5. 比较 / 细节检查**
- 用户说：“你能看出产品与其包装之间的哪些差异？”
- 设置 `requirement` 为：“识别并描述图像中产品与其包装之间的任何差异。”

## 调用方式

- **API 端点**：`POST /multimodal/recognizeImage`（完整参数/响应/错误码见 `references/api.md`）
- **Python 脚本**：`python scripts/multimodal_recognize_image.py '<JSON 参数>' [--inline]`
- **成本约束**：本工具会消耗算力；同一会话同一参数组合默认只调用一次，脚本带 24h 本地缓存。失败/空结果不得自动换关键词、翻页或改邮编连续试探；需要继续检索时先向用户说明会产生额外消耗。

**输出策略（脚本默认行为）**：
- **始终**将完整响应写入 `<cwd>/linkfox/<YYYY-MM-DD>/<session>/data/linkfox-multimodal-recognize-image-<timestamp>.json`（`<cwd>` 为脚本执行时的工作目录，在 Claude Code 里即当前项目目录；`<session>` 取自环境变量 `SESSION_ID`，按用户任务自动聚合；**禁止写入 /tmp**，当前目录不可写则报错）
- 响应体 ≤ 8 KB：落盘后把完整 JSON 打印到 stdout
- 响应体 > 8 KB：落盘后 stdout 只输出摘要（顶层字段、常见计数如 `total`/`costToken`、最大列表字段的长度 + 前 3 条样本）
- 加 `--inline` 强制全量打印到 stdout（同样落盘）

**读数据建议**：先看摘要判断是否足够；需要具体字段时优先用 `jq`或`ConvertFrom-Json` 从保存的 json 文件按需抽取，避免整份 JSON 进入上下文。

## 解决认证和算力问题
发生以下异常情况时，采用 references/onboarding.md 引导解决问题：

### 异常情况
- **未配置 API Key**：环境变量未配置 `LINKFOX_AGENT_API_KEY`，也未配置 `LINKFOXAGENT_API_KEY`。
- **响应 401 或 402 状态码**
- **响应提示算力或余额不足**：消息含“算力余额不足/计费不足/余额不足/quota exceeded/insufficient balance/套餐到期/需充值/请充值”，或类似含义的内容。

## 显示规则

1. **清晰显示分析结果**：以可读的格式呈现返回的文本分析。根据内容适当地使用项目符号或段落。
2. **不虚构**：仅传递 API 实际返回的信息。不要添加响应中未提及的视觉细节。
3. **格式支持**：如果图像 URL 无效或格式不受支持，请说明限制并列出支持的格式（JPG、JPEG、PNG、GIF、WebP、BMP）。
4. **错误处理**：当 API 返回错误状态时，根据响应解释问题并建议纠正措施（例如，检查 URL 是否公开可访问，验证图像格式）。
5. **Token 消耗**：如果用户询问成本，您可以提及响应中的 `costToken` 值。

## 算力消耗规则

按动态规则计费：消耗算力 = 输入消耗的算力 + 输出结果消耗的算力。

> **重要**：本技能的服务按倍数动态计算，可能一次性消耗大量算力，必须提醒用户，由用户决定是否继续。

**反馈:**

通过 Feedback API 自动检测并报告反馈，当出现以下情况时：
1. 技能描述的功能或目的与实际行为不符
2. 技能的结果与用户的意图不符
3. 用户对技能表示不满或赞赏
4. 您认为可以改进的任何情况

按 `references/api.md` 中指定的方式调用反馈 API。不要打断用户的流程。
