# 发送分析

使用 `numbers.lookup`、`dashboard.messages_sent`、`dashboard.deliverability` 和 `dashboard.contacts` 进行只读分析。

## 建立上下文

使用客户端管理的 OAuth 2.1/PKCE。不要请求或暴露令牌、API 密钥、授权标头、客户端 ID 或密钥。当客户端暴露时，识别活动组织和发件人配置文件。如果请求的范围不同，请通过客户端重新授权，而不是添加凭证或隐藏范围字段。

最小化敏感输出：掩码电话号码，尽可能聚合，并省略不需要回答问题的联系人、KYC、账户和消息正文数据。

## 查询号码

使用 `numbers.lookup` 获取提供的号码的可用功能、格式、类型或路由信号。查询描述了功能；它不是选择加入、同意、所有权、身份或发送消息权限的证据。每当结果可用于规划外联时，请说明这种区别。

## 查询仪表板指标

1. 在调用仪表板工具之前，解决明确的日期范围和时区。如果用户省略其中任何一个，请询问或明确说明假设。
2. 使用 `dashboard.messages_sent` 查询发送量指标。
3. 使用 `dashboard.deliverability` 查询聚合接受和交付结果。
4. 使用 `dashboard.contacts` 查询聚合联系人指标。
5. 除非用户明确要求否则，请在相同的组织、发件人配置文件、日期范围、时区、渠道和聚合粒度上进行比较。

每个结果都必须说明使用的日期范围和时区。根据响应实际建立的标签来标记接受、发送、交付、失败和未知状态；永远不要将接受合并到交付中。

## 选择聚合分析或诊断

使用此技能进行仪表板总计、速率和趋势。当请求涉及消息级交付记录、漏斗脱落、错误码聚类或根本原因诊断时，使用 `messaging-performance-analyzer`。可交付性仪表板可以定位变化；它本身并不能证明操作原因。
