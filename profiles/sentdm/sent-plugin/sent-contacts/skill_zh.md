# 发送联系人

使用 `contacts.list`、`contacts.get`、`contacts.create_many`、`contacts.delete` 和 `contacts.message_summary` 操作联系人。

## 建立连接和范围

使用客户端管理的 OAuth 2.1/PKCE。切勿请求或暴露令牌、API 密钥、授权标头、客户端 ID 或密钥。在进行变更之前，从连接上下文中显示活动的组织和发送者配置文件；如果其中任何一个不可用，请使用 `sent-account-readiness` 检查授权范围。要在客户端更改范围，请重新授权。

在可行的情况下，对电话号码进行屏蔽。仅返回任务所需的联系人字段，并且在已审核后不要重复联系人数据。号码存在或消息历史记录并不能建立同意。

## 读取联系人

- 使用 `contacts.list` 搜索或分页浏览联系人。应用最严格的可用过滤器，并且不要不必要地倾倒整个联系人簿。
- 当知道确切的联系人标识符时，或在进行删除之前，使用 `contacts.get`。
- 使用 `contacts.message_summary` 获取联系人的消息摘要。将摘要数据与同意证明或当前可达性区分开来。

只读调用不需要变更确认。

## 批量创建联系人

1. 在本地验证和去重建议的记录。仅保留用户实际提供的字段。
2. 在调用工具之前，构建确切的 `contacts.create_many` 参数。
3. 显示一个包含所选组织、发送者配置文件、记录计数、重复处理和每个确切目标的负载预览。在运营商仍然可以验证电话号码的情况下对其进行屏蔽；只有当确切验证需要时，才显示完整值。
4. 请求对此确切批次的明确确认。较早的或一般的批准是不充分的。
5. 确认后立即调用 `contacts.create_many`。对记录或范围的任何更改都会使确认失效。

切勿在预览和调用之前没有明确确认的情况下调用 `contacts.create_many`。将每个重试视为一个新的变更，并带有一个新的预览和新的明确确认。

## 删除联系人

1. 将请求的联系人解析为单个明确的标识符。
2. 首先使用 `contacts.get` 获取确切的目标。切勿从猜测的标识符、宽泛的过滤器或过时的列表结果中删除。
3. 显示一个删除预览，其中包含所选组织、发送者配置文件、确切的联系人标识符、显示标签和屏蔽的地址。说明删除是破坏性的。
4. 请求删除该确切目标的明确确认。
5. 确认后立即调用 `contacts.delete`。如果目标、范围或记录发生变化，请再次获取它并重复预览。

切勿在获取目标之前没有明确确认的情况下调用 `contacts.delete`。每次重试都需要再次获取、新的预览和新的明确确认。

## 报告结果

报告计数和稳定标识符，而不是完整的联系人记录。如果创建或删除的结果不明确，不要假设成功并且不要自动重试。在可能的情况下，重新读取确切的目标，解释不确定性，并在任何进一步的变更之前要求新的确认。
