# 发送模板

使用 `templates.list`、`templates.get`、`templates.get_by_name` 和 `templates.delete` 对现有模板记录进行操作。

## 建立连接和范围

使用客户端管理的 OAuth 2.1/PKCE，切勿请求或暴露凭证。删除前显示当前组织以及发送者配置文件；如果连接上下文未同时暴露这两者，请使用 `sent-account-readiness`。在客户端重新授权以更改范围。

避免不必要地重复模板正文文本或示例数据。在摘要中优先使用模板标识符、名称、语言、渠道、类别和状态。

## 查找和检查模板

- 使用 `templates.list` 进行过滤发现和分页。
- 使用 `templates.get` 获取精确的模板标识符。
- 当用户提供名称时使用 `templates.get_by_name`。如果名称可以匹配多种语言、渠道或范围，请显示候选者并在继续之前解析一个精确记录。

这些工具检查现有记录。对于编写或分类，请将任务交接给 `waba-template-author`；对于面向租户的创建体验，请将任务交接给 `template-builder-ui`。

## 删除模板

1. 将请求解析为一个精确的模板。
2. 首先使用 `templates.get` 或 `templates.get_by_name` 获取该目标。切勿从猜测的标识符、宽泛的过滤器或过时的列表结果中删除。
3. 显示删除预览，包括所选组织、发送者配置文件、精确的模板标识符、名称、语言、渠道、类别和状态。说明删除是破坏性的；不要重复其正文。
4. 请求明确确认删除此精确目标。早期或一般性批准是不充分的。
5. 确认后立即调用 `templates.delete`。对目标、范围或记录的任何更改都会使确认失效。

切勿在调用之前未获取目标并立即获得明确确认的情况下调用 `templates.delete`。将每次重试视为新的变更：重新获取目标、显示新的预览并获得新的明确确认。

如果结果不明确，在可能的情况下重新读取目标。报告不确定性并不要自动重试。
