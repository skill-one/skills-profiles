## 激活协议

### 首次使用时

- 任务涉及微信小程序认证行为、`wx.cloud` 身份、`OPENID` / `UNIONID`，或小程序调用者在 CloudBase 中的身份识别。
- 项目是 CloudBase 小程序，且认证问题涉及原生小程序身份而非提供者配置。

### 编写代码前需阅读

- 请求中提及小程序登录、云函数中的用户身份或 `wx.cloud` 认证假设。
- 用户期望 Web 风格的登录页面或小程序中的显式令牌交换；将他们引导回原生小程序认证行为。

### 其他需阅读

- 小程序项目实现 -> `../miniprogram-development/SKILL.md`
- 云函数实现 -> `../cloud-functions/SKILL.md`

### 不适用场景

- 基于 Web 的微信登录或 Web 认证 UI。
- 提供者启用/禁用或认证控制台设置。
- 小程序身份处理之外的通用 Node 端认证流程。

### 常见错误/注意事项

- 为 `wx.cloud` 小程序生成 Web 风格的登录页面。
- 将小程序认证视为提供者配置问题。
- 忘记调用者身份在云函数中会自动注入。

## 使用此技能的场景

在 CloudBase 项目中使用此技能进行 **微信小程序（小程序）认证**。

当你需要：

- 使用 CloudBase 实现身份感知的小程序流程
- 在云函数中访问用户身份（openid、unionid）
- 了解微信认证如何与 CloudBase 集成
- 构建需要用户识别的小程序功能

**主要优势：** 使用 CloudBase 进行微信小程序认证是 **无缝且自动的** - 无需复杂的 OAuth 流程。当小程序调用云函数时，用户的 `openid` 会自动注入并由微信验证。

**不适用场景：**

- 基于 Web 的微信登录（使用 **auth-web** 技能）
- 服务器端使用 Node SDK 的认证（使用 **auth-nodejs** 技能）
- 非微信认证方法（使用合适的认证技能）

## 如何使用此技能（针对编码代理）

1. **确认 CloudBase 环境**
   - 向用户询问：
     - `env` – CloudBase 环境ID
     - 确认小程序已关联到 CloudBase 环境

2. **理解认证流程**
   - 微信小程序认证是 **原生且自动的**
   - 大多数情况下无需显式登录 API 调用
   - 用户身份会自动在云函数中可用
   - CloudBase 处理所有认证验证

3. **从本文件中选择场景**
   - 基本云函数中的用户身份，使用 **场景 2**
   - 小程序初始化，使用 **场景 1**
   - 从小程序调用云函数并接收用户身份，使用 **场景 3**
   - 测试认证，使用 **场景 4**

4. **严格遵循 CloudBase API 形状**
   - 在云函数中使用 `wx-server-sdk`
   - 在小程序客户端代码中使用 `wx.cloud`
   - 将此文件中的方法名称和参数形状视为规范

5. **如果对 API 不确定**
   - 查阅官方 CloudBase 小程序文档
   - 仅使用官方文档中出现的 API

## 核心概念

### 微信小程序认证如何与 CloudBase 工作

1. **自动认证：**
   - 当小程序用户调用云函数时，微信会自动注入用户的身份
   - 无需复杂的 OAuth 流程或令牌管理
   - CloudBase 验证身份的真实性

2. **用户标识符：**
   - `OPENID` – 在此特定小程序中用户的唯一标识符
   - `APPID` – 小程序的 App ID
   - `UNIONID` – （可选）在相同微信开放平台账号下所有应用中的唯一标识符
     - 仅在小程序绑定到微信开放平台账号时可用
     - 适用于跨多个小程序或公众号识别同一用户

3. **安全性：**
   - `openid`、`appid` 和 `unionid` 是 **经过验证且可信的**
   - 微信已完成认证
   - 开发者可以直接使用这些标识符，无需额外验证

4. **无需显式登录：**
   - 用户在使用小程序时自动认证
   - 大多数情况下无需调用登录 API
   - 身份立即在云函数中可用
