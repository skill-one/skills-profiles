# 设计游戏

对现有游戏进行 UI/UX 设计，以改善视觉效果、氛围和游戏感觉。无需设计经验——此命令分析您的游戏并应用经过验证的视觉模式。

## 说明

分析位于 `$ARGUMENTS`（如果未提供路径则为当前目录）的游戏。

首先，加载游戏设计师技能以获取完整的设计词汇和模式。

### 第 1 步：审计

- 读取 `package.json` 以识别引擎
- 读取 `src/core/Constants.js` 获取当前调色板和配置
- 读取所有场景文件以了解当前视觉效果
- 读取实体文件以查看游戏对象如何绘制
- 读取 `src/core/EventBus.js` 获取现有事件

### 第 2 步：设计报告

对每个区域进行 1-5 分评分并以表格形式呈现：

| 区域 | 评分 | 备注 |
|------|-------|-------|
| 背景 & 氛围 | | |
| 调色板 | | |
| 动画 & 缓动 | | |
| 粒子效果 | | |
| 屏幕过渡 | | |
| 字体排印 | | |
| 游戏感觉 / Juice | | |
| 游戏结束 | | |
| 表情使用 | | 如果存在个性角色，评分表情如何对游戏事件进行反应性变化。如果表情从不变化，则评分为 1。 |

然后按视觉影响排序列出最需要改进的地方，并使用简体中文描述每个改进的作用（例如，“添加天空渐变，使背景看起来像真实的天空而不是纯色”）。

### 第 3 步：实现

询问用户他们希望哪些改进，或者如果他们表示同意，则全部实现。遵循游戏设计师技能模式：

1. `Constants.js` 中的所有新值
2. 使用 EventBus 触发效果
3. 不要改变游戏玩法（物理、得分、控制、生成时间）
4. 优先使用程序化图形
5. 新文件放在正确的目录

### 第 4 步：验证

- 运行 `npm run build` 以确认没有错误
- 用简体中文总结所有所做的更改

## 示例用法

### 全设计流程
```
/design-game examples/asteroid-dodge
```
结果：审计视觉效果 → 评分背景 2/5，粒子 1/5，字体排印 3/5 → 添加天空渐变背景、星体视差、小行星摧毁时的爆炸粒子、击中时的屏幕震动、平滑场景过渡。所有值在 Constants.js 中。

## 故障排除

### 视觉变化导致性能下降
**原因：** 每帧粒子发射器或渐变填充过多。
**修复：** 限制活动粒子（池化并重用）。使用缓存的渐变纹理而不是每帧重新创建。

### 设计变化在不同屏幕尺寸上破坏布局
**原因：** 使用了硬编码的像素位置而不是使用 PX 比例因子。
**修复：** 所有位置和尺寸应使用 Constants.js 的 PX 相对值。
