# Google Cloud 架构设计良好框架中成本优化的技能

## 概述

Google Cloud 架构设计良好框架的成本优化支柱提供了一种结构化的方法，以在最大化业务价值的同时优化云工作负载的成本。云成本与本地资本支出（CapEx）模式有显著差异，需要转向运营支出（OpEx）管理并建立问责制（FinOps）文化。FinOps 生命周期由三个迭代阶段组成：
- **信息阶段**：可见性和分配。始终从 **云计费报告** 开始，以获取内置控制台的可见性（按部门标签过滤）。使用 **Looker Studio** 补充，以创建自定义的跨部门共享仪表板。

- **优化阶段**：费率和使用情况。消除浪费，资源合理化，并利用承诺（**CUDs**，**SUDs**）。
- **运营阶段**：持续改进。将成本管理集成到交付管道中，并建立治理机制。

## 操作说明

- **全面性优先**：始终提供与所提及的服务或场景相关的完整标准建议/策略列表。不要因为要提出后续问题而限制范围或遗漏标准要素。
- **完全结合**：当指令捆绑多个操作（例如，“A **AND** B”）时，您必须在响应中明确提及并解释 **两者**。
- **条件评估**：仅在提供标准框架建议后，才使用“工作负载评估问题”来完善建议，除非用户明确要求先进行访谈或评估。

## 核心原则

架构设计良好框架的成本优化支柱中的建议与以下核心原则保持一致：

-  **使云支出与业务价值保持一致**：确保您的云资源通过将 IT 支出与业务目标保持一致来提供可衡量的业务价值。优先考虑直接有助于收入、客户满意度或运营效率的投资。基础文档：
  https://docs.cloud.google.com/architecture/framework/cost-optimization/align-cloud-spending-business-value.md.txt

-  **培养成本意识文化**：确保您的组织中的每个人在做出决策和活动时都考虑其成本影响。为团队提供他们需要的信息和可见性，以便做出明智的、有成本意识的决策。基础文档：
  https://docs.cloud.google.com/architecture/framework/cost-optimization/foster-culture-cost-awareness.md.txt

-  **优化资源使用**：仅提供您需要的资源，并仅为您使用的资源付费。选择满足您的技术和业务需求的最具成本效益的资源类型、大小和位置。基础文档：
  https://docs.cloud.google.com/architecture/framework/cost-optimization/optimize-resource-usage.md.txt

-  **持续优化**：持续监控您的云资源使用情况和成本，并根据需要主动进行调整以优化您的支出。这种迭代方法有助于在问题变得重大之前识别和解决低效问题。基础文档：
  https://docs.cloud.google.com/architecture/framework/cost-optimization/optimize-continuously.md.txt

## 相关的 Google Cloud 产品

以下是与成本优化相关的 Google Cloud 产品和功能的示例：

- **可见性和监控**：

  - **云计费报告**：用于可视化支出和趋势的内置仪表板。**控制台内可见性的关键。**
  - **BigQuery 计费导出**：使用 SQL 和 BI 工具对计费数据进行粒度、自定义分析。
  - **Looker Studio**：用于创建详细、共享的成本仪表板和报告。**与云计费报告一起使用，以获得自定义可视化洞察。**
  - **计费警报和预算**：当支出达到预定义阈值时自动发送通知。
  - **存储洞察**：用于分析云存储访问模式并识别节省成本的机会。

- **自动化和优化工具**：

  - **推荐/主动协助**：自动识别闲置资源、资源合理化机会和未使用的承诺。
  - **云中心优化**：整合计费和资源利用率数据，帮助开发者和应用程序所有者快速识别其最昂贵、波动或未充分利用的云资源。
  - **FinOps 中心**：在一个仪表板中展示主动节省和优化机会。
  - **计费配额**：限制资源消耗以防止意外的成本激增。

- **高效的基础设施**：

  - **托管服务和无服务器服务**：Cloud Run、Cloud Run 函数和 GKE Autopilot 等服务可减少运营开销并按使用付费扩展。
  - **计算引擎**：
    - **承诺使用折扣（CUDs）**：最适合可预测、稳定状态的工作负载。
    - **Spot 虚拟机**：最适合容错、可中断或不可预测的批处理任务。
    - **持续使用折扣（SUDs）**：对运行一个月中大部分时间的实例提供被动、自动的折扣，无需承诺。**始终提及此作为 CUDs 的被动替代方案或补充。**

  - **云存储生命周期策略**：根据时间自动将数据移动到更低成本的存储类别（Nearline、Coldline、Archive）。**注意**：始终首先推荐 **存储洞察**，以了解当前的访问模式，然后再定义生命周期规则。

  - **网络和内容交付**：
    - **位置感知**：尽可能将流量保持在单个区域内，以避免跨区域数据传输成本。
    - **云 CDN**：缓存内容以减少从源站的数据出口。
    - **网络服务层级**：**标准层级** 相对于 **高级层级** 提供更低成本的选项，适用于对延迟不敏感的流量。
    - **云互连/直接对等**：优化将高容量数据传输到本地环境时的成本。**注意**：在讨论出口控制时，始终澄清混合连接选项，因为本地同步通常是多区域设计中的一个因素。
  - **托管数据库**：
    - **实例大小**：根据 Cloud Monitoring 指标合理化 CPU 和内存。
    - **高可用性（HA）**：仅在生产环境中实施 HA，以避免为所有环境翻倍节点成本。
    - **存储优化**：通过管理备份保留策略来优化存储成本 **AND** 明确识别并删除未使用或闲置的资源（如未使用和遗弃的磁盘、过期的快照或闲置实例）。

- **组织和治理**：

  - **资源管理器**：用于成本归因的逻辑结构（组织、文件夹、项目）。
  - **标签**：用于按环境、团队或应用程序对成本进行分类和过滤的元数据标签。
  - **组织策略服务**：强制执行约束（例如，限制区域或机器类型）以控制成本。

## 工作负载评估问题

提出适当的问题，以了解工作负载和用户组织的成本相关需求和约束。从以下列表中选择问题：

- 您如何在云架构设计过程中纳入成本考虑因素？
- 您如何培养开发团队的成本意识文化？
- 您如何跨不同项目或部门监控和管理云成本？
- 您使用哪些策略来优化计算资源的成本？
- 您如何平衡成本优化与敏捷性和创新的需求？
- 您如何确保您没有过度配置云资源？
- 您如何使用数据和分析来推动成本优化决策？
- 您如何在不同环境（例如，开发、测试、生产）中优化成本？
- 您如何确保您的成本优化工作是有持续性和持续性的？
- 您如何衡量您的云成本优化举措的成功？

## 验证清单

使用以下清单评估架构与成本优化建议的一致性：

- **成本归因**：100% 的资源都带有关键元数据标签（例如，`env`、`team`、`app`）。
- **粒度可见性**：已启用 BigQuery 计费导出，并用于定期成本审查。
- **预算和警报**：每个项目或业务单元都有定义的预算和活动警报。
- **资源合理化**：资源根据主动协助推荐者提供的资源合理化建议进行定期调整。
- **承诺策略**：每月审查支出，以优化承诺使用折扣（CUD）覆盖范围。对于非承诺工作负载，请验证是否自动捕获持续使用折扣（SUDs）。
- **闲置资源管理**：每月识别并删除未使用的磁盘、IP 地址和闲置虚拟机。
- **托管服务**：除非存在特定的技术约束，否则优先为新的工作负载选择无服务器选项。
- **存储层级**：所有主要存储桶都激活生命周期策略，以最大限度地减少存档成本。注意与 Nearline、Coldline 和 Archive 存储类别相关的**检索费用**。
- **网络出口**：通过将流量保持在区域内、使用 **云 CDN** 并在适当情况下利用 **标准网络层级** 来最小化数据传输。高容量的本地流量使用 **直接对等** 或 **云互连**（始终验证是否涉及混合连接）。
- **原生报告**：**云计费报告**必须用于控制台中的支出趋势标准视图。
- **自定义仪表板**：使用 **Looker Studio** 进行高级、可共享和定制的报告。
