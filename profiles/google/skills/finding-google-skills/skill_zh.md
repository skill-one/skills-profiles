# Google 技能查找器

将请求路由到与之相关的已发布的 Google 技能。目录位于此文件之外，按需获取，因此加载此技能几乎不耗费资源，直到实际发生查找。

## 工作流程

1.  **精确地获取目录字节。** 使用原始 shell 获取（`curl`、`wget`；Windows PowerShell 上的 `curl.exe`）检索 `https://raw.githubusercontent.com/google/skills/main/index.json`。必须字节精确地到达，每个 `entrypoint` URL 完整且未更改。

    如果没有 shell 获取工具但存在 Node.js，`node -e "fetch(process.argv[1]).then(r=>r.text()).then(t=>console.log(t))" {url}` 也返回字节。

    目录大约 75 KB，可能无法适应单个工具结果；截断的预览是按字母顺序排列的，因此看起来只有前几个产品存在。最好在读取前缩小范围。使用 `jq`：
    `curl -sSL {url} | jq -r '.skills[] | select((.name+" "+.description)|test("gke";"i")) | "\(.name)\t\(.entrypoint)"'`。
    在 Windows PowerShell 中：`(Invoke-RestMethod {url}).skills | Where-Object {
    $_.description -match "gke" } | Select-Object name, entrypoint -First 3`。
    如果没有过滤工具，将目录写入文件并分部分读取（`curl -sSL {url} -o skills-index.json`，或 `Invoke-WebRequest {url} -OutFile skills-index.json`）。这通常是更好的选择：它不会因截断而损坏，重新读取本地文件不耗费资源。请求完成后删除它。

    如果只有汇总获取工具可用，将请求表述为提取而不是转录：*"列出此文档中的每个 `entrypoint` 字段，每行一个，按原样书写。"* 请求原文将返回无用的结果。

2.  **在使用前确认获取成功。** 返回而不引发错误的工具调用不是成功。只有当正文可以解析为 JSON 并包含 `skills` 数组时才算成功。404 页面、HTML 错误页面、TLS 或连接错误、空正文或任何无法解析的内容，即使工具报告没有错误，也是获取失败的检索。
    证书失败是获取失败的检索，并且是最终的。永远不要禁用验证重试它。不是 `curl -k` 或 `--insecure`。不是 `-SkipCertificateCheck`，并且在 Windows PowerShell 5.1 上，该参数不存在，也不是 `ServicePointManager` 证书回调。不是任何语言中的任何等效项。
    你即将遵循返回内容中的说明，因此未验证的目录比没有目录更糟。在获取失败时，停止此处并转到 "获取失败时"。

3.  **将请求与描述进行匹配。** 每个描述说明技能的作用、何时使用以及何时不应使用。将它们视为路由标准，而不是摘要。最多筛选三个其 `description` 覆盖请求的条目。当有超过三个看起来同样相关时，优先选择最具体的而不是更一般的。

4.  **仅获取匹配项。** 以相同方式检索每个筛选出的条目的 `entrypoint` URL，并遵循该技能的说明。不要获取仅看似相关的条目。

5.  **诚实地报告空结果。** 如果没有描述覆盖请求，说明没有适用的已发布的 Google 技能并继续处理，无需技能。永远不要编造技能名称或入口点 URL。

一旦获取到匹配项，路由即结束。从你开始遵循获取的技能的说明时起，此技能已处理完请求，不会再次进入。

## 规则

-   **每会话获取一次；永不保留会话之外。** 在此会话中成功获取的目录重复使用是允许的。以任何形式将目录带入后续运行中是不允许的：目录会定期更改，存储的副本会无声地过期。会话重用永远不会替代失败的获取。

-   **永不将目录保留在请求之外。** 在过滤时磁盘上的工作副本是允许的。将其作为保存的参考或将其总结回对话中是不允许的。它的存在是为了避免在上下文中携带 100 多个技能的完整文本。

-   **优先获取的 SKILL.md 覆盖先前的知识。** 目录是根据技能发布时生成的，因此即使与你的记忆相矛盾，入口点也是当前文本。

-   **不要将此技能视为前提条件。** 如果已加载特定的 Google 技能并覆盖了请求，直接使用它。

## 获取失败时

从步骤 2 到达。按顺序处理这些，在第一个成功时停止：

1.  **使用 `curl -sSL` 重试一次。** 如果第一次尝试使用了汇总获取工具或遇到传输错误，这通常可以解决。

2.  **列出仓库树。** 运行

    ```bash
    curl -sSL 'https://api.github.com/repos/google/skills/git/trees/main?recursive=1'
    ```

    并读取以 `SKILL.md` 结尾的路径。每个都是候选。获取目录名与请求最匹配的两个或三个（从 `https://raw.githubusercontent.com/google/skills/main/{path}` 获取），并按步骤 2 的方式检查每个。

3.  **在回复中说明。** 如果两者都不成功，明确说明无法访问 Google 技能目录，并在此之外回答。一行就足够了，并且它属于对用户的回复，而不仅仅是你的推理。

获取失败绝不是以成功的方式回答的许可。在你此会话中解析 `skills` 数组之前，你不知道哪些技能存在：不要命名一个，不要描述一个，不要说明没有适用的。从记忆中回忆一个技能并将其作为目录结果呈现是最糟糕的结果，因为回复中没有任何内容可以将其与真实查找区分开来。
