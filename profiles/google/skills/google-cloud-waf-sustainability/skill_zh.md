# Google Cloud 架构设计最佳实践框架可持续性支柱技能

## 概述

Google Cloud 架构设计最佳实践框架的可持续性支柱提供了原则和建议，帮助您最小化云工作负载的环境影响。它侧重于共同责任模式——Google 优化云的可持续性，而客户优化云中的可持续性。通过在架构、资源分配和区域选择方面做出明智的决策，您可以显著减少碳足迹并提高整体能源效率。

## 核心原则

架构设计最佳实践框架中可持续性支柱的建议与以下核心原则保持一致：

-   **共同责任**：定义责任边界并采用共同命运模型，与云服务提供商和合作伙伴合作，为整个生态系统实现最佳环境效益。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability.md.txt

-   **使用消耗低碳能源的区域**：优先选择具有高比例无碳能源（CFE）和“低二氧化碳”指标的 Google Cloud 区域，以降低部署的总体碳排放。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/low-carbon-regions.md.txt

-   **优化 AI 和 ML 工作负载**：通过将算法需求与专用硬件（如 TPUs）匹配，并应用数学技术来减少计算复杂性，从而最大化每瓦特的计算量。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/ai-ml-energy-efficiency.md.txt

-   **优化资源使用**：通过在空闲时将资源扩展到零、调整虚拟机大小以及优先考虑动态匹配实际需求的托管服务来消除能源浪费。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/optimize-resource-usage.md.txt

-   **开发节能软件**：通过使用事件驱动逻辑和优化资源，设计应用程序以在后台服务器和终端用户设备上最小化不必要的 CPU、内存和网络活动。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/energy-efficient-software.md.txt

-   **优化数据和存储**：通过实施生命周期管理将冷数据存档，并消除没有商业价值的“暗数据”，来减少存储的环境足迹。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/optimize-storage.md.txt

-   **持续测量和改进**：通过分析细粒度数据、识别热点并采取主动措施来纠正低效问题，从而了解您的碳排放情况。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/continuously-measure-improve.md.txt

-   **推广可持续性文化**：将可持续性嵌入组织治理中，将技术决策与环境目标联系起来，并确保员工具备实施绿色实践所需的技能。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/culture.md.txt

-   **与行业指南保持一致**：确保您的可持续性举措与测量、报告和验证的行业指南保持一致，例如 W3C Web 可持续性指南、绿色软件基金会和温室气体协议。依据文档：
    https://docs.cloud.google.com/architecture/framework/sustainability/industry-guidelines.md.txt

## 相关的 Google Cloud 产品

以下是一些与可持续性相关的 Google Cloud 产品和功能的示例：

-   **可视化和测量**：
    -   **碳足迹**：提供仪表板，可查看与 Google Cloud 使用相关的温室气体排放情况。
    -   **BigQuery**：分析导出的碳足迹数据与计费数据，以识别排放热点。

-   **基础设施和运营**：
    -   **Google Cloud 区域选择器**：帮助权衡碳足迹、成本和延迟，以选择部署位置。
    -   **Active Assist / Recommender**：自动识别空闲资源，并提供虚拟机调整大小建议以减少浪费。
    -   **Cloud Run / GKE Autopilot**：完全托管的计算环境，可优化集群使用，并在空闲时扩展到零。
    -   **Cloud Batch**：优化批处理作业的调度，允许在高碳自由能源时段执行。
    -   **Spot VMs**：利用未使用的数据中心容量，以提高容错工作负载的整体硬件效率。

-   **数据和 AI**：
    -   **Cloud Storage 生命周期管理**：自动将旧数据迁移到低能耗存储类别（Nearline、Coldline、Archive）。
    -   **Cloud TPUs**：专为大规模 AI/ML 矩阵乘法的能效优化的专用硬件。

提出适当的问题，以了解工作负载及其用户组织的可持续性相关要求和限制。从以下列表中选择问题：

-   **云可持续性**：
    -   您如何定义您组织与云服务提供商之间的可持续性责任边界？
    -   您如何利用云功能和 AI 来推动更广泛的业务运营的可持续性成果？
    -   您的云战略如何考虑合作伙伴生态系统和多云环境的可持续性影响？

-   **使用消耗低碳能源的区域**：
    -   您如何将碳强度纳入您的 Google Cloud 区域选择策略？

-   **优化 AI 和 ML 工作负载**：
    -   您如何优化您的 AI 和机器学习的生命周期能效？

-   **优化资源使用**：
    -   您如何确保您的基础设施足迹动态匹配实际工作负载需求？
    -   您如何选择和维护用于云工作负载的硬件类型？
    -   您处理非紧急或计算密集型后台任务的策略是什么？
    -   您如何平衡高可用性和灾难恢复的需求与可持续性？

-   **开发节能软件**：
    -   您如何确保您的后台逻辑最小化不必要的 CPU、内存和网络活动？
    -   您如何管理您的代码库的整体效率和维护以实现可持续性？
    -   您如何最小化您的应用程序对终端用户设备的数据量和处理负载？
    -   您的用户体验（UX）设计如何为终端用户提高能效？

-   **优化数据和存储**：
    -   您是否有管理数据和存储环境足迹的流程？

-   **持续测量和改进**：
    -   您如何分析您的碳数据以优先考虑优化工作？
    -   可持续性测量如何嵌入到您组织的治理和文化中？
    -   您当前的流程是什么，以了解与云相关的碳排放？
    -   您采取了哪些主动措施来纠正已识别的碳热点？

-   **推广可持续性文化**：
    -   您如何将单个技术决策与组织的使命联系起来，并对团队结果负责？
    -   您如何确保您的技术和业务人员具备实施可持续性实践所需的特定技能？

## 验证清单

使用以下清单评估架构与可持续性建议的一致性：

-   **云可持续性**：
    -   [ ] 该组织采用共同责任和共同命运模型来处理可持续性。
    -   [ ] AI 被用作提高盈利能力和弹性的催化剂，以简化运营，或者可持续性被整合到设计过程中以创建积极的反馈循环。
    -   [ ] 优先考虑与可持续性合作伙伴的合作，并利用多云数据可移植性，或者内部实践与绿色软件基金会等公认的全球标准保持一致。

-   **使用消耗低碳能源的区域**：
    -   [ ] 采用数据驱动的政策优先考虑具有高无碳能源（CFE%）和“低二氧化碳”指标的区域，或者积极使用 Google Cloud 区域选择器来平衡碳足迹与成本和延迟。

-   **优化 AI 和 ML 工作负载**：
    -   [ ] 算法需求与专用硬件（TPUs）匹配，以最大化每瓦特的计算量，或者应用模型压缩和 PEFT 等数学技术来减少计算复杂性。

-   **优化资源使用**：
    -   [ ] 利用在空闲时扩展到零的完全托管服务，或者在 GKE 中使用水平 Pod 自动缩放（HPA）和垂直 Pod 自动缩放（VPA）以防止过度配置。
    -   [ ] 存在正式流程，以升级到性能每瓦特更高的最新机器类型，或者工作负载被积极匹配到专用机器系列。
    -   [ ] 批处理作业被主动安排在高碳自由能源比例最高的时段或区域运行，或者使用 Spot VMs 处理非关键的批处理作业。
    -   [ ] 优先考虑“冷灾难恢复”或无服务器故障转移，以确保次要区域在事件发生前保持零能耗，或者使用基础设施即代码（IaC）仅在需要时快速配置恢复环境。

-   **开发节能软件**：
    -   [ ] 资源密集型忙循环或持续轮询被事件驱动逻辑替换，或者优先考虑具有最佳时间复杂度和数据结构的算法。
    -   [ ] 遵循“不要重复自己”（DRY）原则，并定期重构，或者使用智能缓存（例如 Memorystore）并实施智能驱逐策略。
    -   [ ] 衡量并维护网站产品的下载大小，以符合严格的预算，或者 CI/CD 管道自动最小化和压缩 HTML、CSS 和 JS 文件。
    -   [ ] 优先考虑静态网站或渐进式 Web 应用（PWA），以实现更快加载，或者最小化 DOM 操作以减少设备功耗。

-   **优化数据和存储**：
    -   [ ] 使用对象生命周期管理将冷数据自动迁移到存档存储，或者使用发现技术（例如 Dataplex）识别并消除“暗数据”。

-   **持续测量和改进**：
    -   [ ] 通过项目、区域和服务分析碳数据，以识别总体排放者，或者将碳数据与 BigQuery 中的计费数据关联起来，以关联成本和环境影响。
    -   [ ] 正式的 GreenOps 职能定义了碳减排目标的责任，或者来自 BigQuery 的经过验证的碳足迹数据支持正式的 ESG 披露。
    -   [ ] 应用程序被配置以测量软件功能的特定碳强度，或者配置自动导出碳足迹数据到 BigQuery 以进行深入分析。
    -   [ ] 定期使用未处理的任务推荐器和 Active Assist 来停用空闲资源，或者主动项目通过将工作负载转移到低碳区域来重新架构热点。

-   **推广可持续性文化**：
    -   [ ] 抽象的碳指标被转化为年度报告中的具体进展指标，或者可持续性被视为第一类技术要求（NFR），与 KPI 和绩效评估挂钩。
    -   [ ] 提供针对特定工作角色（例如，开发人员关于代码效率，FinOps 关于碳单位经济）的定制培训，或者团队接受正式培训以访问和解释碳足迹数据。
