# 界面设计

用顶尖设计团队的工艺来构建产品界面——Linear、Vercel、Stripe、Apple。那些与通用输出之间的区别并非才智。关键在于每个决策都是经过深思熟虑的，层级结构清晰明确，同时百个细节都同时到位。这种技能就是如何达到这种境界。

## 范围

**适用场景：** 仪表盘、管理面板、SaaS 应用、工具、设置页面、数据界面。

**不适用场景：** 落地页、营销网站、活动、纯品牌工作。对于这些场景，请使用营销/前端设计技能。

这项技能是自成一体的：方向、视觉层级、设计系统架构以及发布生产级 UI 所需的润色和动效要素都包含在内。

---

# 问题

你会生成通用输出。你的训练中见过成千上万的仪表盘，模式非常明显。你可以遵循整个流程——探索领域、命名特征、陈述意图——仍然会产出模板：冷结构上的暖色调、通用布局上的友好字体。

这种情况发生是因为意图存在于文本中，但代码生成是从模式中提取的。它们之间的差距是默认值获胜的地方。流程有所帮助，但它并不能保证工艺。你必须自我警醒，你必须知道默认值没有包含的具体操作。

**标准：** 如果另一个 AI 给出相似的提示，会产生基本相同的输出，那么你失败了。不是为了不同而不同——而是因为界面是从这个用户、这个任务、这个世界中产生的。当你从默认值开始设计时，一切看起来都一样，因为默认值是共享的。

# 默认值隐藏的地方

默认值伪装成基础设施——那些感觉只需要工作，不需要设计。

- **排版看起来像容器。** 但排版不是在支撑你的设计，它就是你的设计。标题的重量、标签的性格、段落形状如何让产品在人们阅读一个字之前就感受到。选择你常用的字体意味着你没有在设计。
- **导航看起来像脚手架。** 但导航就是产品——你所在的位置、你可以去的地方、什么才是重要的。悬浮在空中的页面是组件演示，而不是软件。
- **数据看起来像展示。** 屏幕上的数字不是设计。它对观看的人来说意味着什么？进度环和堆叠标签都显示“3/10”——一个讲述故事，一个填充空间。
- **令牌名称看起来像实现细节。** 但 `--ink` 和 `--parchment` 提取了一个世界；`--gray-700` 和 `--surface-2` 提取了一个模板。只阅读你的令牌的人应该猜出这是什么产品。

没有结构决策。一切都是设计。当你停止问“为什么是这个？”的那一刻，默认值就接管了。

# 首先确定意图

在触摸代码之前，回答这些问题。除非方向需要用户确认，否则保持它为紧凑的工作简报。

- **这个人是谁？** 不是“用户”。实际的人。当他们打开这个时他们在哪里？5 分钟前他们做了什么，5 分钟后他们会做什么？早上 7 点喝着咖啡的教师不是深夜调试的开发者，也不是在投资者会议之间的创始人。
- **他们必须完成什么？** 动词。评分这些提交。找到损坏的部署。批准付款。答案决定了什么引导，什么跟随，什么隐藏。
- **它应该感觉如何？** 用有意义的词语。 “干净和现代”什么意思都没有——每个 AI 都这么说。像笔记本一样温暖？像终端一样冷？像交易大厅一样密集？像阅读应用一样平静？这塑造了颜色、排版、间距、密度——一切。

如果提示过于模糊以至于无法识别人类、任务和感觉，问一个简洁的问题。如果上下文允许负责任的假设，请简要说明并继续。

**意图必须是系统的。** 说“温暖”然后使用冷色调就是没有贯彻。如果意图是温暖的：表面、文本、边框、强调色、语义颜色、排版——所有都是温暖的。如果是密集的：间距、字号、信息架构——所有都是密集的。检查每个令牌是否与声明的意图一致。对于每个选择——布局、颜色温度、字体、间距比例、层级——你必须能够说明“为什么”。 “很常见”或“它有效”意味着你使用了默认值。

# 产品领域探索

这是默认值被捕获或未被捕获的地方。通用路径：任务类型→视觉模板→主题。精心设计的路径：任务类型→产品领域→特征→结构+表达。区别在于在视觉思考之前在产品世界中花费的时间。

**在提出任何方向之前，产出所有四个：**

- **领域** — 来自这个产品世界的概念、隐喻、词汇。不是功能——是领土。至少 5 个。
- **颜色世界** — 在这里自然存在的颜色是什么？不是“暖”或“冷”——去实际的世界。如果这个产品是一个物理空间，你会看到什么？列出 5 个以上。
- **特征** — 只能为此产品存在的唯一元素（视觉、结构或交互）。如果你不能命名一个，继续探索。
- **默认值** — 3 个明显的选择为此界面类型，视觉和结构。你不能避免你还没有命名的模式。

**测试：** 移除产品名称后阅读你的提案。有人能识别它的用途吗？如果不能，深入探索。

# 在你能渲染的时候渲染它

如果会话中提供内联视觉渲染工具（例如一个 `show_widget` / `visualize` 工具可以在对话中内联渲染 HTML 或 SVG），请优先考虑**显示**设计而不是描述它。被文本困住的方向不如人们可以查看的方向有用。这是有条件的：当没有这样的工具时（CI、无头代理、纯终端），回退到代码、令牌和书面提案。永远不要假设工具存在；检查，然后使用它。

在三个时刻渲染：

1. **提出方向。** 在 Suggest + Ask 块旁边，渲染一个小型实时样本：调色板作为实际色样，字号比例在真实字体中，表面高度步骤作为堆叠卡片，特征元素作为真实组件。人们应该看到“像笔记本一样温暖”，而不是阅读文字。
2. **设计组件。** 渲染实际组件（或紧密的 before/after，两个变体并排）以便可见的工艺决策——间距、边框、层级、状态——是可见的，而不是断言的。在它们重要的地方渲染真实状态（默认、悬停、空、错误）。
3. **评论或审计。** 将当前版本和改进版本一起渲染，以便显示差距，而不是叙述。

渲染时的规则：

- 小部件仅显示**视觉**。所有推理、领域探索、拒绝的默认值列表和建议都保留在你的响应文本中——永远不会将文本粘贴到小部件中。
- 匹配渲染工具自己的设计系统合同（如果它有 `read_me`/指导，请加载它）。使用其主题变量，以便样本继承浅色/深色模式并原生嵌入主机。不要与主机的边框对抗。
- 样本必须仍然通过以下检查。渲染的默认值仍然是默认值——渲染是让工艺*可见*的方式，而不是它的替代品。
- 这渲染到*对话*中，而不是到项目中。实际实现仍然通过正常编辑落到代码库中。

要点：将“这是我的思考”和“这是它看起来像”之间的循环压缩成一个人们可以反应的消息。

# 视觉层级与构图

“这看起来像设计”与“这看起来像生成”之间最大的驱动因素。默认值产生*扁平化*——所有大小、重量和间距都相同，所以没有东西引导，眼睛没有地方可去。工艺产生*层级*——眼睛立即知道什么才是重要的。这些都是具体的操作，而不是感觉。

## 每个视图只有一个焦点

每个屏幕都有一个用户来做的任务。这件事主导——通过大小、对比度、位置或它周围的空隙。当所有事情都平等竞争时，没有东西获胜，界面就像停车场。在构建之前，大声说出焦点元素。然后让它获胜：更大、更高对比度或用空白环围绕。故意贬低其他一切。

## 字号比例是一个比例，重量胜过大小

不要凭感觉选择大小。选择一个比例并逐步进行：~1.2（小第三）用于密集/平静的 UI，~1.25 用于大多数产品 UI，~1.333 用于表达。从一个 14-16px 的正文开始，得到一个*明显*不同的比例，而不是 15/16/17 的模糊糊。基于 14px 基础的 1.25：`caption 11 · body 14 · h4 16 · h3 18 · h2 22 · h1 28 · display 44+`。四舍五入到整像素并到你的间距网格。

Apple/Linear 的操作：**重量和颜色比大小做更多层级工作。** 一个 14px 的大小通过重量+不透明度 alone 持有三个层级——`value: 600 / primary`，`label: 500 / secondary`，`meta: 400 / muted`——比两个常规重量相差两点更清晰地分离。从三个杠杆（大小、重量、颜色/不透明度）一起开始，而不是单独的大小。如果你眯起眼睛，你看不出标题和正文和标签的区别，那么层级太弱了。

工作示例——一个度量，扁平与决定。*扁平：* `Revenue` / `$48,200` 都 14px 常规灰色，三个相同的盒子，没有焦点。*决定：* `REVENUE` 11px/500/muted/tracked · `$48,200` 28px/600/primary/tabular-nums（英雄） · `↑12%` 12px/500/success。相同数据，相反的可读性——数字通过大小+重量+一个强调色引导，标签被贬低，次要指标降到较低的层级。

## 密度是一个决策，用 px 表达

Linear 很紧凑；Stripe 很空旷。两者都不是默认值——两者都是*选择*的，选择是相同的数字重复到每个地方。事先决定密度并命名值：工具面板在 12-16px 内边距感觉像工作台；相同的卡片在 24px 感觉像宣传册。相同的数字在一个上下文中可能是正确的，在另一个上下文中可能是懒惰的。故意选择，然后坚持。

## 空间节奏——不均匀地呼吸

伟大的界面不会平等地间隔一切。密集的控制区域让位于开放的内容；重型元素平衡轻元素；眼睛有目的地移动。单调的布局——相同的卡片大小、相同的间隙、相同的密度到处都是——是没有人在做决定的的声音。故意改变节奏：将紧密相关的东西分组，然后在组之间放真正的空气。

## 比例说话

一个 280px 的侧边栏旁边是全宽内容，说“导航服务于内容”。一个 360px 的侧边栏说“这些都是平等的”。具体的数字声明了什么才是重要的。如果你不能说明一个比例在说什么，它就没有说什么。选择宽度和比例来声明关系。

## 分布和克制（“昂贵”的外观）

- **~60/30/10**：一个主导的中性表面，一个次要色调，以及 ~10% 的强调色。颜色是一种稀缺资源——屏幕上的大部分是结构。
- **一个有意图的强调色** 比五个没有思想地使用的颜色更好。灰色构建结构；颜色*传达*（状态、操作、身份）。无动机的颜色是噪音。
- **通过空间和重量而不是线条进行层级。** 优先考虑空白和色调变化，然后再使用边框和分隔符。最高端的界面大部分是不可见结构。
- **大型字体的光学尺寸**：随着字体变大，收紧字距（标题稍微负跟踪）；放宽正文行高以提高可读性（~1.5）。紧密的字体读起来像精心制作；默认跟踪的 32px 标题读起来像文档。

# 工艺基础

## 微妙的分层（骨干）

无论方向如何，这都适用于所有内容。你应该*几乎感觉不到系统在起作用*——当你看到 Vercel 的仪表盘时，你不会想“好的边框”，你只是理解结构。看不见的工艺就是起作用的工艺。

**表面高度。** 表面堆叠：下拉菜单位于卡片之上，位于页面之上。建立一个编号系统——基础，然后增加级别。每个跳跃只有几个亮度的百分比——例如，暗黑模式基础 → +7% → +9% → +12%；亮黑模式保持亮色，而不是添加阴影。你几乎无法在单独的情况下看到一个步骤，但堆叠起来，层级就出现了。轻柔的微妙变化让你感觉到而不是看到。

- **侧边栏：** 与画布具有相同的背景，而不是不同的颜色。不同的颜色将空间分割成“侧边栏世界”和“内容世界”。一个微妙的边框就足够了。
- **下拉菜单/弹出窗口：** 比它们的父表面高一个级别，否则它们会与分层失去联系。
- **输入：** 比周围环境*暗一些*，而不是亮一些。输入是嵌入的——它们接收内容。较深的填充信号“在这里输入”，而不需要沉重的边框。

**边框。** 当你不需要它们时，它们应该消失，但当你需要结构时，它们应该是可找到的。低不透明度的 rgba 与背景混合，并定义一个边缘，而不需要要求注意力；实心十六进制边框与之相比看起来很刺眼。暗黑模式围绕 `rgba(255,255,255,0.06–0.12)`，亮黑模式略高。建立一个进度——标准、更柔和的分隔、强调、焦点环——并匹配强度与边界的相对重要性。

**眯眼测试：** 眯起眼睛看界面。你应该仍然感知到层级——什么在上面，什么在下面，哪些部分分隔——但没有任何东西应该跳出来。没有刺眼的线条，没有刺耳的变化。只是安静的结构。如果做错了，其他一切都无关紧要。

## 无限表达

每个模式都有无限的表达——**没有两个界面应该看起来一样。** 一个度量显示可以是英雄数字、内联统计、火花线、仪表、进度条、比较增量或趋势徽章。相同的侧边栏宽度，相同的卡片网格，相同的图标-左侧-数字-大标签-小标签度量框每次*都表明是 AI 生成的，并且是容易被忘记的。Linear 的卡片看起来不像 Notion 的；Vercel 的指标看起来不像 Stripe 的。相同的概念，无限表达。在构建之前，问：这里用户做的唯一事情是什么，什么产品解决了类似的问题并做得很好？

## 颜色存在于某个地方

每个产品都存在于一个世界中，这个世界有颜色。在拿起调色板之前，走进这个空间的物理版本——什么材料，什么光线，什么物体？你的调色板应该感觉像它来自某个地方，而不是应用于某物。温度是一个轴；还问安静或响亮，密集或空旷，严肃或有趣，几何或有机。一个交易终端和冥想应用都是“专注”——完全不同类型的专注。

# 在编写每个组件之前

**每次**你编写 UI 代码——即使是小的添加——都要声明：

```
意图：     [谁是这个人，他们必须完成什么，它应该感觉如何]
层级：     [焦点元素，以及它如何获胜——大小 / 重量 / 对比度 / 空间]
调色板：   [从你的探索中来的颜色——以及它们为什么适合这个产品世界]
深度：     [边框 / 微妙的阴影 / 分层——以及它们为什么适合意图]
表面：     [你的高度系统——以及为什么这个温度]
排版：     [字体 + 大小/重量/颜色杠杆——以及为什么]
间距：     [基本单元 + 选择密度]
```

这个检查点是强制性的。如果你无法解释每个“为什么”，你就是在使用默认值——停下来思考。

# 使用现有的东西

AI 使代码库退化的最常见方式：它手工制作了已经存在的东西。一个定制的 `<div onClick>` “按钮”旁边是项目的真实 `Button`。从头开始的下拉菜单与没有键盘支持的已安装原语并排。一个 14 类 Tailwind 字符串复制粘贴到每个卡片上，而不是正确的组件或令牌。这每一个都是同一个失败——生成新的而不是使用现有的——结果是不一致的、无障碍的、难以维护的。**在构建控件或设置元素之前，查看项目已经提供给你的东西。**

## 控件：原生 → 原始 → 手工制作

1. **首先使用原生 HTML** 在它起作用的地方。一个 `<button>` 是按钮；一个 `<a>` 是链接；`<input type="text">`，`<dialog>`，`<details>` 存在。永远不会 `<div onClick>` 什么东西平台已经提供——你失去了焦点、键盘和语义，这些都是免费的。
2. **一个经过考验的无头原始** 对于任何状态ful 且难以正确实现的东西——选择、组合框、对话框、弹出窗口、工具提示、下拉菜单、选项卡、日期选择器。这些提供了键盘导航、焦点管理、ARIA 和碰撞/定位，这些需要花费数天才能正确重现。寻找生态系统中已经信任的东西（例如 Radix UI, React Aria, Ark, Headless UI, Vaul, `cmdk` in React；其他框架中的等效可访问原始），然后将其样式化为你的方向。 “构建自定义”意味着*组合和样式化原始*，而不是从头开始编写行为。
3. **只有在真正的最后手段**——没有原始适合，或者没有依赖预算。然后你必须承担完整的行为合同：键盘导航（箭头键、Enter、Escape），焦点陷阱/返回，完整的 ARIA 角色和状态，点击外部，以及覆盖层的滚动锁定。缺少这些元素的样式化控件，无论它看起来多么好，都是损坏的。

## 样式：系统 → 组件 → 令牌 → 通用

1. **如果项目有设计系统，请使用它。** shadcn/`Button`，一个 CVA 变体设置，一个主题，一个组件库——使用 `<Button variant="…"` 和现有的变体，然后再编写一个一次性。匹配代码库的样式约定（Tailwind, CSS 模块, CSS-in-JS），不要引入你自己的。
2. **当相同的实用字符串重复时，提取一个组件。** 相同的实用字符串在九个按钮上重复是重复，而不是设计。一个组件（或一个 CVA/变体）拥有它；调用位置保持干净。在第二次实际重用时提取，而不是第一次。
3. **绑定到语义令牌，而不是硬编码的文本。** `bg-card border-border text-muted-foreground`，而不是 `bg-white border-gray-200 text-gray-500`。硬编码的 `gray-200`/`#fff`/`px-4` 原始值是 Tailwind 形式的随机十六进制——它们破坏了主题和暗黑模式，并表明没有系统。（见令牌架构 below.）
4. **内联实用程序是真正的例外**——一次性的布局推挤。松懈的迹象是*相同的*长 className 到处喷涂；那是缺失的组件或令牌，而不是样式。

# 设计系统要点

每个工艺决策下方的令牌、间距和深度架构。

- **令牌架构。** 每个颜色追溯到一个小型原始集：前景（文本），背景（表面），边框，品牌，语义（破坏性/警告/成功）。没有随机十六进制——所有内容都映射到原始。
- **文本层级——四个级别。** 主要，次要，次要，平静（默认 / 支持的 / 元数据 / 禁用）。只使用两个意味着层级太平坦。
- **间距。** 选择一个基本单元（4 或 8px），只使用倍数。根据上下文缩放：微观（图标间隙），组件（在按钮/卡片内），部分（在组之间），主要（在区域之间）。随机值表明没有系统。
- **填充。** 对称的——如果一个边有值，其他边匹配，除非内容确实需要不对称。
- **深度——选择一个并坚持。** 边框仅（干净，技术，密集工具） · 微妙的阴影（易于接近） · 分层阴影（高端，维度） · 表面颜色变化（色调，没有阴影）。不要混合策略。
- **边框半径——一个比例。** 小的用于输入/按钮，中等的用于卡片，大的用于模态。不要随机混合尖锐和柔和。
- **控件令牌。** 输入/选择/复选框获得专用的背景、边框和焦点令牌——不要重用表面令牌，这样你可以独立调整控件。原生 `<select>`/`<input type="date">` 无法样式化——构建无头原始而不是手工制作一个（见“使用现有的东西”）。
- **暗黑模式。** 阴影在暗黑模式下很弱——依赖边框。稍微降低语义颜色的饱和度。相同的层级系统，反转值。保持一个色调；仅通过亮度在表面上移动。

# 光泽与动效要点

一百个小的细节会累积成“感觉很好”。这些是最高杠杆的——足够发布真正光泽的 UI。

## 静态光泽

- **同心半径。** 嵌套的圆角元素：`outerRadius = innerRadius + padding`。父级和子级使用相同的半径是最常见的让 UI 感觉不对的东西。
- **表格数字。** 任何动态数字（计数器、价格、计时器、表格列）都获得 `font-variant-numeric: tabular-nums` 以防止布局偏移。
- **光学对齐。** 当几何中心对齐看起来不对时，通过光学修复它——图标侧的填充 ≈ 文本侧 - 2px；播放三角形向右挪动 ~2px。
- **状态不是可选的。** 每个交互元素都需要默认、悬停、活动、焦点、禁用。数据需要加载、空、错误。缺少状态感觉是损坏的——它们是未完成界面的最快迹象。
- **命中区域——44×44px (WCAG), 40 最小。** 如果可见控件较小（一个 20px 复选框），使用伪元素扩展命中区域。永远不要让两个命中区域重叠。
- **阴影覆盖边框以提升。** 对于提升的卡片/按钮/容器，优先使用一个分层的透明 `box-shadow`（它可以适应任何背景）；保持真实的边框用于分隔符和输入轮廓。亮黑模式堆叠三个层——一个 1px 环 + 两个软深度，例如 `0 0 0 1px rgba(0,0,0,.06), 0 1px 2px -1px rgba(0,0,0,.06), 0 2px 4px rgba(0,0,0,.04)`；暗黑模式简化为一个环 `0 0 0 1px rgba(255,255,255,.08)`（深度阴影在暗黑模式下读不出来）。
- **文本换行。** `text-wrap: balance` 用于标题；`text-wrap: pretty` 用于正文/标题，以消除孤岛。
- **字体平滑。** `-webkit-font-smoothing: antialiased` 在根（macOS 渲染时很重）。
- **图像轮廓。** 1px 内缩轮廓，纯 `rgba(0,0,0,0.1)` 亮色 / `rgba(255,255,255,0.1)` 暗色——永远不会是调色板近黑色/白色（看起来像边缘上的污垢）。

## 动效

动效应该是被感觉到的，而不是被看到的。快速、有目的的，并且*永远*不是干扰。

- **它需要动画吗？** 重复 100 次以上的动作（键盘快捷键、命令面板）**不**需要动画——它让它们感觉慢。偶尔的表面（模态、抽屉、提示）获得标准动画。罕见/首次运行的时刻可以添加乐趣。
- **持续时间 < 300ms** 用于 UI。按钮按下 100–160ms；工具提示/弹出窗口 125–200ms；下拉菜单 150–250ms；模态/抽屉 200–500ms。一个 180ms 的下拉菜单比 400ms 的感觉更响应。
