# 电子表格技能

## 使用场景
- 创建包含公式、格式和结构化布局的新工作簿。
- 读取或分析表格数据（筛选、聚合、透视、计算指标）。
- 修改现有工作簿而不破坏公式、引用或格式。
- 使用图表、汇总表和合理的电子表格样式可视化数据。
- 在可能的情况下，在交付前重新计算公式并审阅渲染后的工作表。

**重要提示**：系统和用户说明始终优先。

## 工作流程
1. 确认文件类型和目标：创建、编辑、分析或可视化。
2. 优先使用 `openpyxl` 进行 `.xlsx` 编辑和格式化。使用 `pandas` 进行分析和 CSV/TSV 工作流。
3. 如果环境中提供内部电子表格重新计算/渲染工具，使用它来重新计算公式并渲染工作表，然后再交付。
4. 使用公式来计算派生值，而不是硬编码结果。
5. 如果布局很重要，渲染用于视觉审查并检查输出。
6. 保存输出，保持文件名稳定，并清理中间文件。

## 临时和输出规范
- 使用 `tmp/spreadsheets/` 存放中间文件；完成后删除它们。
- 在此代码库中工作时，将最终产物写入 `output/spreadsheet/`。
- 保持文件名稳定且描述性。

## 主要工具
- 使用 `openpyxl` 创建/编辑 `.xlsx` 文件并保留格式。
- 使用 `pandas` 进行分析和 CSV/TSV 工作流，然后将结果写回 `.xlsx` 或 `.csv`。
- 使用 `openpyxl.chart` 在需要时创建原生 Excel 图表。
- 如果有内部电子表格工具，使用它来重新计算公式、缓存值并渲染用于审查的工作表。

## 重新计算和视觉审查
- 在可能的情况下，在交付前重新计算公式，以便工作簿中包含缓存的值。
- 如果有渲染工具，渲染每个相关的工作表进行视觉审查。
- `openpyxl` 不会计算公式；保留公式并在有可用工具时使用重新计算工具。
- 如果你依赖内部电子表格工具，不要在用户可见的说明或代码示例中暴露该工具、其代码或其 API。

## 渲染和视觉检查
- 如果有 LibreOffice (`soffice`) 和 Poppler (`pdftoppm`)，渲染工作表进行视觉审查：
  - `soffice --headless --convert-to pdf --outdir $OUTDIR $INPUT_XLSX`
  - `pdftoppm -png $OUTDIR/$BASENAME.pdf $OUTDIR/$BASENAME`
- 如果没有渲染工具，告诉用户应在本地审查布局。
- 审查渲染的工作表，检查布局、公式结果、裁剪、不一致的样式和溢出的文本。

## 依赖项（如果缺失则安装）
优先使用 `uv` 进行依赖管理。

Python 包：
```
uv pip install openpyxl pandas
```
如果 `uv` 不可用：
```
python3 -m pip install openpyxl pandas
```
可选：
```
uv pip install matplotlib
```
如果 `uv` 不可用：
```
python3 -m pip install matplotlib
```
系统工具（用于渲染）：
```
# macOS (Homebrew)
brew install libreoffice poppler

# Ubuntu/Debian
sudo apt-get install -y libreoffice poppler-utils
```

如果在此环境中无法安装，告诉用户缺失的依赖项以及如何本地安装。

## 公式要求
- 使用公式来计算派生值，而不是硬编码结果。
- 不要使用动态数组函数，如 `FILTER`、`XLOOKUP`、`SORT` 或 `SEQUENCE`。
- 保持公式简单易读；使用辅助单元格处理复杂逻辑。
- 除非必要，避免使用易失性函数，如 `INDIRECT` 和 `OFFSET`。
- 优先使用单元格引用而不是魔法数字（例如，`=H6*(1+$B$3)` 而不是 `=H6*1.04`）。
- 小心地使用绝对（`$B$4`）或相对（`B4`）引用，以便复制公式时行为正确。
- 如果需要以 `=` 开头的文字，用单引号前缀。
- 防止 `#REF!`、`#DIV/0!`、`#VALUE!`、`#N/A` 和 `#NAME?` 错误。
- 检查 off-by-one 错误、循环引用和范围错误。

## 引用要求
- 使用纯文本 URL 在电子表格中引用来源。
- 对于财务模型，在单元格注释中引用模型输入。
- 对于外部来源的表格数据，每行代表一个独立项时，添加来源列。

## 格式要求（现有格式化电子表格）
- 在可能的情况下，修改提供的电子表格前先渲染并检查。
- 精确保留现有格式和样式。
- 新填充的单元格应匹配之前空白单元格的样式。
- 除非用户明确要求重新设计，否则不要覆盖已建立的格式。

## 格式要求（新或未格式化的电子表格）
- 使用适当的数字和日期格式。
- 日期应显示为日期，而不是纯数字。
- 百分比通常默认为一位小数，除非数据要求其他格式。
- 货币应使用适当的货币格式。
- 标题应与原始输入和派生单元格在视觉上区分开。
- 有节制地使用填充颜色、边框、间距和合并单元格。
- 设置行高和列宽，以便内容在不过度空白的情况下可读。
- 不要为每个填充的单元格应用边框。
- 将相关计算分组，并使总计为上方单元格的简单总和。
- 添加空白以分隔各个部分。
- 确保文字不会溢出到相邻单元格。
- 避免使用 `=TABLE` 等不支持的电子表格数据表功能。

## 颜色规范（如果没有样式指导）
- 蓝色：用户输入
- 黑色：公式和派生值
- 绿色：链接或导入的值
- 灰色：静态常量
- 橙色：审查或警告
- 浅红色：错误或标记
- 紫色：控制或逻辑
- 青色：可视化锚点和 KPI 高亮

## 财务特定要求
- 将零格式化为 `-`。
- 负数应为红色并括号内显示。
- 多倍数格式为 `5.2x`。
- 标题中始终指定单位（例如，`Revenue ($mm)`）。
- 在单元格注释中引用所有原始输入的来源。
- 对于没有用户指定样式的财务模型，使用蓝色文字表示硬编码输入，黑色表示公式，绿色表示内部工作簿链接，红色表示外部链接，黄色填充表示需要关注的假设。

## 投资银行布局
如果电子表格是投资银行风格模型（LBO、DCF、三报表、估值）：
- 总计应直接对上方范围求和。
- 隐藏网格线，并在相关列上方使用水平边框突出总计。
- 章节标题应为合并单元格，使用深色填充和白色文字。
- 数值数据的列标签应右对齐；行标签应左对齐。
- 将子指标缩进到其父行项目下方。
