# 线性

## 概述

此技能为在 Linear 中管理问题、项目和团队工作流程提供了结构化的工作流程。它确保与 Linear MCP 服务器的一致集成，该服务器为问题、项目、文档和团队协作提供自然语言的项目管理。

## 前置条件
- Linear MCP 服务器必须通过 OAuth 连接并可访问
- 确认可以访问相关的 Linear 工作区、团队和项目

## 必需的工作流程

**按顺序执行以下步骤。不要跳过步骤。**

### 第 0 步：设置 Linear MCP（如果尚未配置）

如果任何 MCP 调用因 Linear MCP 未连接而失败，请暂停并设置它：

1. 添加 Linear MCP：
   - `codex mcp add linear --url https://mcp.linear.app/mcp`
2. 启用远程 MCP 客户端：
   - 在 `config.toml` 中设置 `[features] rmcp_client = true` **或者** 运行 `codex --enable rmcp_client`
3. 使用 OAuth 登录：
   - `codex mcp login linear`

登录成功后，用户将需要重新启动 codex。您应该完成您的回答，并告诉他们，当他们再次尝试时，他们可以继续第 1 步。

**Windows/WSL 注意事项：** 如果在 Windows 上看到连接错误，请尝试通过 WSL 配置 Linear MCP：
```json
{"mcpServers": {"linear": {"command": "wsl", "args": ["npx", "-y", "mcp-remote", "https://mcp.linear.app/sse", "--transport", "sse-only"]}}}
```

### 第 1 步
明确用户的意图和范围（例如，问题筛选、冲刺计划、文档审核、工作量平衡）。根据需要确认团队/项目、优先级、标签、周期和截止日期。

### 第 2 步
选择适当的工作流程（见下文实用工作流程）并确定您将需要的 Linear MCP 工具。在调用工具之前确认所需的标识符（问题 ID、项目 ID、团队密钥）。

### 第 3 步
以逻辑批次执行 Linear MCP 工具调用：
- 首先读取（列出/获取/搜索）以构建上下文。
- 接下来创建或更新（问题、项目、标签、评论）所有必需字段。
- 对于批量操作，在应用更改之前解释分组逻辑。

### 第 4 步
总结结果，指出剩余的差距或障碍，并提出下一步行动建议（附加问题、标签更改、分配或后续评论）。

## 可用工具

问题管理：`list_issues`, `get_issue`, `create_issue`, `update_issue`, `list_my_issues`, `list_issue_statuses`, `list_issue_labels`, `create_issue_label`

项目 & 团队：`list_projects`, `get_project`, `create_project`, `update_project`, `list_teams`, `get_team`, `list_users`

文档 & 协作：`list_documents`, `get_document`, `search_documentation`, `list_comments`, `create_comment`, `list_cycles`

## 实用工作流程

- 冲刺计划：审查目标团队的所有问题，按优先级选择顶级项目，并创建一个新的周期（例如，“Q1 性能冲刺”）并分配任务。
- Bug 筛选：列出关键/高优先级 Bug，按用户影响排序，并将顶级项目移至“进行中”。
- 文档审核：搜索文档（例如，API 认证），然后打开标记为“文档”的问题，以发现差距或过时的部分并附上详细的修复方案。
- 团队工作量平衡：按分配者分组活动问题，标记负载较高的人员，并建议或应用重新分配。
- 发布计划：创建一个项目（例如，“v2.0 发布”）并设置里程碑（功能冻结、Beta、文档、发布），并生成带估计的问题。
- 跨项目依赖：查找所有“阻塞”问题，识别阻塞者，并在缺失的情况下创建链接问题。
- 自动化状态更新：查找带有过时更新的您的问题，并根据当前状态/阻塞情况添加状态评论。
- 智能标签：分析未标记的问题，建议/应用标签，并创建缺失的标签类别。
- 冲刺回顾：为上一个完成的周期生成报告，记录已完成与推进的工作，并打开讨论问题以发现模式。

## 最大化生产力的技巧

- 批量操作相关更改；考虑为常用的问题结构创建智能模板。
- 尽可能使用自然查询（“显示我本周在做什么”）。
- 利用上下文：在新的请求中引用先前的 问题。
- 将大型更新拆分为较小的批次以避免速率限制；在频繁列出时缓存或重用过滤器。

## 故障排除

- 身份验证：清除浏览器 Cookie，重新运行 OAuth，验证工作区权限，确保 API 访问已启用。
- 工具调用错误：确认模型支持多个工具调用，提供所有必需字段，并拆分复杂请求。
- 缺失数据：刷新令牌，验证工作区访问，检查存档项目，并确认正确的团队选择。
- 性能：记住 Linear API 速率限制；批量执行批量操作，使用特定过滤器，或缓存频繁查询。
