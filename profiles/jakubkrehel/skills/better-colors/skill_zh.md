# 颜色

一个颜色系统是一组小范围的渐变，它们以角色命名并验证它们实际渲染的背景。大多数颜色问题都是系统问题。孤立地选择一个值，因为看起来对而借用一个标记，一对没有人测量。

永远不要报告你没有测量的对比值，也永远不要估计你可以计算的颜色。颜色是少数几个具有确切答案的界面问题，所以提供确切答案。

对比要求属于 `better-accessibility`。表面、阴影和图标颜色属于 `better-ui`。

## 匹配项目的颜色系统

重用项目的标记和符号。添加第二个表示来修复一个值会使调色板更难推理。一致的十六进制系统比散布着 `oklch()` 的十六进制更胜一筹。

对于新系统，`oklch()` 是最佳默认值，因为它的数字行为如下面的渐变规则描述的方式。在其他地方，颜色库在项目的自己的符号中生成相同的渐变 ([color-formats.md](color-formats.md))。

## 一个系统是渐变，不是颜色

一个中性渐变，一个强调渐变，以及产品实际渲染的唯一状态渐变。一个没有任何地方导入的 `warning` 渐变是针对零像素的维护。只有在两件事必须一眼就能区分时，第二个强调色调才配得上它的位置。

## 每个步骤都有一个用途

一个渐变不是通过肉眼来选择的渐变。每个步骤的存在是因为一个角色需要它：页面背景、组件悬停、边框、实心填充、正文。不要生成没有角色使用的步骤。Tailwind `50`–`950` 和 Radix `1`–`12` 的约定都映射到这些角色 ([palette-structure.md](palette-structure.md))。

## 用色调命名原始值，用角色命名语义值

原始值命名一个值 (`--blue-500`)，并且永远不会在组件中应用。语义标记命名一个任务 (`--color-text-secondary`)，指向一个原始值，并且是组件唯一参考的级别。

这个缝隙是主题化可能的原因。没有它，暗黑模式意味着审查每个使用情况来确定哪个意味着“强调”以及哪个只是想要蓝色 ([token-naming.md](token-naming.md))。

## 只在它的角色中使用一个标记

永远不要因为它的值今天正确而借用一个标记。用作文本颜色的分隔符工作，直到边框变浅，然后文本也随之变浅。如果一个角色没有标记，添加标记。

## 在整个渐变中保持色调

定义一个良好形成的渐变的四个属性：

- 步骤在感知的亮度中均匀地步进，而不是在格式称为亮度的任何地方。
- 色调始终从始到终保持不变。
- 鲜明度在渐变中间达到峰值，并在两端逐渐减弱。
- 步骤在亮端比在暗端更密集。

两端都短于纯黑和纯白，它们根本无法承载色调。使用颜色库而不是凭肉眼 ([palette-generation.md](palette-generation.md))。

## 一个颜色，一个含义

在整个界面中使用一个颜色用于一个目的，将 `15°` 范围内的色调视为相同的颜色。如果强调意味着交互，那么静态文本上的这个色调告诉用户点击不可点击的东西，而渲染为中性的交互元素同样具有误导性。颜色永远不会是唯一的意义载体，`better-accessibility` 拥有这个。

## 每个视图填充一个动作

当填充颜色编码主要强调时，一个主要动作得到它，而同类保持中性。将颜色放在背景上，而不是标签上。填充的按钮在房间里看起来是主要的；带有中性背景的强调色文本看起来像链接。

当它们编码不同的状态或类别而不是作为同类竞争时，多个彩色背景是 fine 的。

## 测量渲染的对，然后报告

测量前景与它实际渲染的背景，而不是页面背景。当一对失败时，报告这对、它的测量值以及它错过的阈值，然后让颜色保持原样。它们是一个设计决策。只有在被要求时才改变它们，然后重新测量 ([contrast.md](contrast.md))。

## 选择渐变的插值空间

空间是一个外观，而不是一个正确性设置。

- **`in oklab`** 是最佳默认值：亮度均匀，没有色调意外。
- **`in oklch`** 绕着色调轮而不是通过中间旅行，保持鲜明并扫过两个停止之间的每个色调。当两个色调的渐变在中间变灰时，选择它。
- **sRGB 默认** 使中间变暗和减弱。它是大多数界面已经拥有的，因为它是你没有要求时得到的。

参见 [color-usage.md](color-usage.md)。

## 在你完成之前

| 错误 | 修复 |
| --- | --- |
| 项目有一个标记的原始值 | 重用或添加角色标记，在项目的符号中 |
| 孤立地 `oklch()` 值滴入十六进制代码库 | 除非迁移在范围内，否则保持既定符号 |
| 像原始值 `--blue-500` 直接在组件中使用 | 指向它一个语义标记 |
| 以外观命名的标记 (`--color-blue-button`) 或第一次使用 (`--color-sidebar-gray`) | 以它的角色命名：`--color-accent-solid`，`--color-bg-surface` |
| `--color-primary` 意味着品牌，`--color-text-primary` 意味着正文 | 为品牌保留 `accent`；让 `primary` 意味着“同类中最突出的” |
| 在其角色之外使用的语义标记（分隔符作为文本） | 为缺失的角色添加标记；永远不要按值借用 |
| 通过改变 HSL 亮度构建的渐变 | 使用感知亮度与恒定色调重建 |
| 在整个范围内均匀间隔的渐变 | 直到 `50` 和 `100` 看起来像两个表面为止，收紧亮端 |
| 在所有色调中重复相同的饱和度数字 | 匹配每个色调自己的最大值的比例，而不是原始值 |
| 与强调色调冲突的状态色调 | 移动它直到破坏性和主要色调并排阅读时分开 |
| 通过机械反转浅色调色板制作的暗黑模式 | 以反转为起点，然后减少鲜明度，加宽暗端并重新检查每一对 |
| `prefers-color-scheme` 设置一些标记，而 `.dark` 类设置其他标记 | 选择一个切换机制并在整个过程中使用它 |
| 通过改变色调固定的对比度 | 改变亮度，对比度通道对此做出响应 |
| 没有sRGB回退的P3颜色 | 首先声明sRGB值，然后在 `@media (color-gamut: p3)` 内部覆盖 |

## 报告

**严重性。** `HIGH` 使内容无法阅读或分配误导性的语义颜色。`MEDIUM` 是一个明显的主题、标记或色域失败。`LOW` 是孤立的润色。

**验证。** 没有浏览器：标记值，每个声明颜色的色域，两个主题块都存在，以及从声明标记对计算出的对比度。有一个：文本实际渲染的背景，包括不透明度和它下面的任何图像，在亮和暗中都进行测量。一个失败的配对被报告，而不是重新绘制。报告你无法运行的每个检查为 `Not verified`。

**格式。** 按每个违反的原则分组发现，按严重性排序，每个根原因按行列出它出现的位置：

| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |

`位置` 是 `path/to/file:line`。`原因` 命名原则和用户影响。

以 `Block` 结尾，当任何 `HIGH` 保持时，否则以 `Approve` 结尾，将剩余内容留在表中作为待办事项。永远不要 `Approve` 你没有检查的覆盖率。如果没有可报告的内容，请声明“没有可采取的颜色发现”并报告验证。
