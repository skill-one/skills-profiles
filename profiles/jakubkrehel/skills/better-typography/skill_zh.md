# 字体排版

字体排版主要是约束：合理的比例、舒适的间距、足够的对比度。标签、表格单元格、营销标题和文章段落并不共享一套规则。

在审阅时，阅读渲染后的页面而不是扫描代码。糟糕的换行、孤字和截断只有在实际内容长度下才会出现。

将每个修复项都写入项目的样式系统，并使用下方精确的值，而不是看起来熟悉的等效值。[速查表](css-cheat-sheet.md)将每个声明映射到其 Tailwind 对应值。

文字本身属于 `better-writing`。语义标题结构属于 `better-accessibility`。空间从右到左布局和逻辑属性属于 `better-layout`。对比度测量属于 `better-colors`。这项技能决定了文本如何渲染、换行和在不同方向内容中表现。

## 提供正确的格式

在网页上使用 `.woff2`，用于 Brotli 压缩和广泛支持。`.woff` 是非常老旧浏览器的回退方案。`.ttf` 和 `.otf` 是桌面格式，没有网页压缩。文件加载方式是项目的关注点。

## 属性优先于原始标签

当存在 CSS 属性时，使用它。`font-weight: 650` 而不是 `font-variation-settings: "wght" 650`。`font-optical-sizing: auto` 而不是 `"opsz"`。`font-variant-numeric: tabular-nums` 而不是 `font-feature-settings: "tnum" 1`。

属性在非变量回退渲染时仍然有效。保留原始标签用于自定义轴（`"GRAD" 80`）和特殊功能（`"ss01" 1`），它们没有自己的属性。轴和功能标签列在 [variable-fonts-and-opentype.md](variable-fonts-and-opentype.md) 中。

## 加载预期的权重和样式

浏览器合成权重或样式，而活动字族没有提供，会扭曲真实字体。加载设计使用的字体。

`font-synthesis: none` 关闭合成，但它会消除强调而不是报告它。只有在检查完每个必需的粗体、斜体、小写大写、上标和下标形式在回退堆栈中保持不同后，才设置它。

## 更少的字体、尺寸和权重

很少使用超过三种字体。权重和尺寸定义层级；过度使用它们会快速损害可读性。搭配是为了对比而不是相似：衬线标题搭配无衬线正文看起来是故意的，两个几乎相同的无衬线字体看起来是错误。

在 `18px` 以下，保持在权重 `400` 或更重。权重低于 `300` 在 `28px`+ 时仅用于显示；在文本尺寸下它们会消失。搭配指南在 [choosing-fonts.md](choosing-fonts.md) 中。

## 使用带语义名称的类型比例

定义一套尺寸，并尽可能少地偏离它。没有系统支撑的硬编码尺寸在规模上会崩溃。

默认的独立名称如 `text-sm` 在使用规则明确时是没问题的。在团队中，按用途命名尺寸（`text-body-sm`），这样规则才能在其他人的情况下存活。比例构建在 [spacing-and-sizing.md](spacing-and-sizing.md) 中。

## 标题尺寸随级别递减

将标题级别映射到类型比例的递减步骤，这样视觉上从属的标题永远不会压倒其父级。相邻级别可以共享尺寸，只要权重或间距使它们保持区分。语义元素是 `better-accessibility` 的；这项技能只设置视觉处理。

## 按角色设置行高

标题更紧凑，大约 `1.1`。正文 `1.5` 到 `1.6`。优先使用无单位值，这样行高会随字体大小缩放；固定的 `24px` 不会。

紧凑的行高适用于短文本。任何换行到三行或更多行的文本都需要至少 `1.4`，即使在高度受限的行中也如此。

## 按尺寸设置字间距

大标题通常带有轻微负字间距看起来更好。小写大写标签需要一点正字间距，否则字母会显得拥挤。阅读尺寸的正文不需要。

## 限制度量值

长行使眼睛难以找到下一行。将长格式文本的每行限制在 60-75 个字符。任何单位都可以，只要存在上限，并且行长度落在范围内。参见 [unit choices and the pixel equivalents](wrapping-and-punctuation.md#measure-line-length)。

## 故意换行

四个声明，四个任务：

- `text-wrap: balance` 将文本均匀分布在行上。用于标题。
- `text-wrap: pretty` 防止单个短词落在最后一行。用于描述。
- `overflow-wrap: break-word` 在长词、链接或 ID 可能超出容器时使用。
- `white-space: nowrap` 在标签和徽章上使用，因为换行看起来会破坏。

在长格式文本中跳过 `balance` 和 `pretty`。

## 变更值上的表格数字

数字默认宽度不同，所以计时器、计数器和价格在更新时会移动布局。将 `font-variant-numeric: tabular-nums` 应用于任何变化的值。

## 不丢失内容的情况下截断

对于单行，使用 `text-overflow: ellipsis` 并配合 `overflow: hidden` 和 `white-space: nowrap`。对于多行，使用 `line-clamp`。截断会隐藏内容。当缺失的文本很重要时，通过工具提示或展开视图保留完整值。

## 自然地编写文本，用 CSS 样式化

将文本存储在自然大小写中，并通过 `text-transform` 控制呈现，这样 redesign 从不意味着重写副本。

在渲染文本中使用智能标点：

- 散文中使用曲引号，代码中使用直引号。
- 范围中使用连字符：`2010–2020`。
- 使用单个省略号字符，而不是三个点。
- `&nbsp;` 用于在换行符上保持 `16 px`。
- `&shy;` 用于指示长词可能断开的位置。

## 来自字体的下划线

默认下划线位于浏览器决定的位置。使用 `text-underline-position: from-font` 和 `text-decoration-thickness: from-font` 从字体的自身度量中获取位置和厚度。手动调整使用 `text-decoration-thickness`、`text-underline-offset` 和 `text-decoration-skip-ink`。

`text-decoration-style` 绘制虚线、点划线或波浪线。点划线下划线是常见的提示，表示一个词包含额外信息，如缩写或定义术语。

颜色是真实下划线中唯一可靠动画的部分。所以除非唯一动画的是颜色，否则将下划线作为单独元素构建，而不是使用 `text-decoration`。

## 移动端 16px 的输入

iOS Safari 在输入文本小于 `16px` 时缩放整个页面。两个修复方案将大小保持在 `16px` 并看起来不同，所以询问设计想要哪一个：

- 在移动端调整输入大小（`text-base sm:text-sm`）。改变它在小屏幕上的外观。
- 保持 `font-size: 16px` 并使用 `transform: scale()` 渲染预期大小，补偿宽度和 `line-height`。在所有视口下都相同，但维护代码更多。

两种方案都在 [details-and-accessibility.md](details-and-accessibility.md) 中。

## 尺寸和对比度下限

从 `16px` 开始长格式正文，这是浏览器默认值。除非有可命名的理由（字体太小、度量值狭窄或产品是密集的专业工具），否则不要偏离它。

UI 文本可以更小。`14px` 是输入和菜单的有用起点，`13px` 用于标题和很少低于 `12px`。输入在移动端仍然需要 `16px`。

当文本对比度看起来低时，使用 `better-colors` 测量渲染的对，使用 `better-accessibility` 分类要求。除非被要求，否则不要更改颜色。

## 根级别的字体平滑

在 macOS 上，文本渲染比预期更重。在根布局上应用 `-webkit-font-smoothing: antialiased` 和 `-moz-osx-font-smoothing: grayscale`，永远不要每个组件都应用。Tailwind 的 `antialiased` 覆盖两者。

## 语言和双向行为

设置 `lang` 以确保浏览器和辅助技术选择正确的发音、引号和连字符。在文档或方向变化的边界处设置 `dir`。保留数字顺序，并使用 `<bdi>` 来隔离一个多方向值。空间镜像和逻辑 CSS 属性属于 `better-layout`。

## 保持有用的文本可选中

默认情况下保持文本可选中。`::selection` 可以将品牌带入阅读体验，只要选中的组合保持可读。

`user-select: none` 属于可拖动或手势驱动的表面，在那里意外选择会干扰。永远不要在整个界面中使用，也不要因为按钮标签可以被高亮而使用。

## 完成前

| 错误 | 修复 |
| --- | --- |
| 合成的面与设计不同 | 加载真实面；仅禁用已验证的合成模式 |
| 子标题在视觉上压倒其父级 | 将该部分的层级映射到递减的比例步骤 |
| 选择默认尺寸的标题元素 | 首先选择语义，然后在 CSS 中设置尺寸 |
| 段落最后一行的孤字 | `text-wrap: pretty` |
| 两个行的标题不平衡 | `text-wrap: balance` |
| 界面中的两端对齐文本 | `text-align: start`；为特定编辑布局保留对齐 |
| 下划线穿过 descenders | `text-decoration-skip-ink: auto`，`from-font` 度量 |
| 多方向值渲染顺序错误 | 更正 `lang`/`dir`；用 `<bdi>` 隔离值 |
| 应用程序边框禁用选择 | 恢复它；仅在它与拖动或手势冲突时抑制它 |
| 无视觉提示的额外信息提示 | `text-decoration-style: dotted` 的点划线下划线 |
| `14px` UI 文本的细/Light 权重 | `400`+ 以下权重；细权重仅用于显示 |
| 三行卡片描述上的 `leading-none` | 任何换行到 3+ 行的文本至少 `1.4` |

## 报告

**严重性。** `HIGH` 使文本无法阅读或截断内容且无法恢复。`MEDIUM` 破坏字体系统或标题层级。`LOW` 是孤立的润色。

**验证。** 没有浏览器：每个标题级别的计算尺寸和权重，检查递减；声明的行高和度量值；针对实际字符串长度的截断规则。有一个：调整视口大小以捕获换行、孤字和截断在实际内容长度下。报告你无法运行的每个检查为 `Not verified`。

**格式。** 按每个违反的原则分组发现，按严重性排序，每个根原因列出每个位置：

| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |

`位置` 是 `path/to/file:line`。`原因` 指出原则和用户影响。

结束时 `Block` 当任何 `HIGH` 存在时，否则 `Approve`，将剩余部分保留在表格中作为待办事项。永远不要 `Approve` 你没有检查的覆盖率。如果没有可报告的，说明 "No actionable typography findings" 并报告验证。
