# Break

这个技能针对一个组件，在所有实际能到达它的场景下将其渲染到新页面。这个页面就是交付物：一个用户可以滚动查看的视觉报告，所有状态并排展示，并标记了断点。针对一个成功路径构建的组件看起来是完整的，直到实际内容到达。

它观察而非评判。这里的发现是指页面上的明显错误，以负责修复的领域技能的词汇命名。对照标准审查代码是 `interface-review` 和 `better-interface`；探索设计替代方案是 `variant`。

当 `variant` 坚持使用真实页面时，这个技能会刻意隔离。你不是在评判组件在上下文中的外观。你是在检查当内容处于最坏情况时，它是否能自我保护。

整个运行过程是构建、查看一次、报告：几分钟，而不是一个会话。这项工作是将现有组件用不同的属性渲染，其中没有任何内容需要仪器化、浏览器调试或二次处理。

## 1. 范围一个组件

每次运行针对一个组件。 "设置页面" 不是一个组件；个人资料表单的文本输入是。如果请求涉及多个组件，请列出候选组件并询问要测试哪一个，而不是替用户选择。

用一句话重述组件是什么：它接受什么、它渲染什么以及它将存在于何处。

## 2. 从组件中推断场景

仅强调变化的内容。当组件接受可以在生产中呈现为该形状的内容时，场景才会获得一个位置。因此，首先阅读组件：它的属性、它的插槽、它的状态以及它渲染的数据。

[scenarios.md](scenarios.md) 包含轴、每个轴上的值以及一个指示轴是否适用的提示。将其与组件对照，并保留那些提示匹配的轴。文本输入获得内容长度和状态，而不是项目数量。一个带有固定标签的静态图标按钮获得容器和环境，而不是长文本。

在构建之前，将保留的场景写下来，每行一个，以便测试夹具渲染计划集，而不是随意想到的内容。然后说明你舍弃了哪些轴以及原因，用一句话，以便错误的推断可以轻松捕获。

## 3. 构建测试夹具页面

一个一次性页面，包含从项目中导入的真实组件，每个场景在一个单列中渲染一次，每个实例上方有一个简短的文本标签。

组件保持未受影响，在其真实环境中。应用内部的临时路由为其提供应用的自有布局、字体和全局样式，免费使用。标签、容器宽度和固定属性是页面添加的所有内容：没有自己的字体或样式，没有模拟主题或令牌交换，没有探针。在任何这些情况下观察到的组件都是不同的组件。

当框架将服务器组件与客户端组件分开时，页面本身是客户端代码，Next 中的 `"use client"`。固定属性可以在跨越边界进入交互式组件时无声地消失，并且每个场景都渲染为空。

宽度是页面上的场景。在完整宽度的旁边渲染宽度案例在固定宽度的容器内，以便单次加载显示所有宽度，并且永远不会被调整。

将场景作为属性和固定数据输入。测试夹具永远不会导入生产状态，永远不会连接到实时数据，生产环境也不会从测试夹具中导入。

## 4. 查看一次

一次通过。在已经手头的浏览器中加载页面，从上到下快速浏览每个场景并记下明显错误的内容。"文本超出字段的右侧边缘"，而不是 "间距感觉紧"。从未渲染的运行是一次穿着服装的代码审查，预测的失败仍然不是发现。

一次加载是预算。当没有浏览器，或者浏览器需要启动、窗口管理或任何调试时，完全跳过查看：将 URL 交给用户，并让用户自己的眼睛进行观察。他们的查看比你的更有价值，因为页面是他们的。

然后在你看到的每个断点下方，在场景标签下方做一条单行笔记，进行单次编辑。页面必须能作为自己的报告阅读。

## 5. 报告错误并停止

将发现报告为表格，首先列出断开场景：

| 场景 | 观察 | 所有者 |
| --- | --- | --- |
| 一个不可破坏的 60 字符字符串 | 超出卡片，没有换行和截断 | `better-typography` |
| 零项目 | 没有消息的空白区域 | `better-writing` |

所有者列命名诊断断点的领域技能，以便修复从正确的位置开始。这个技能不拥有任何领域规则，也不发布任何裁决。

"所有内容都存活了" 是一份完整且有用的报告。说明页面上的场景及其运行位置，以便用户可以查看每一个。在那里结束，而不是用偏好来填充结果。

不要未经请求就修复任何内容。在修复请求时，遵循所有者技能的规则，然后重新渲染失败的场景以确认。

## 6. 保持页面打开，按请求删除

页面是报告的一半，因此它在发现表格之外存在。保留它运行，并在用户完成使用它时删除它及其固定内容。

## 完成前请注意

| 错误 | 修复 |
| --- | --- |
| 每个轴针对每个组件运行 | 仅保留提示匹配的轴，并说明你舍弃了哪些 |
| 预测的失败报告为观察到的 | 渲染它，或者省略它 |
| 缺少输入内容场景 | 测试夹具损坏，不是组件；将页面作为客户端代码并重新检查 |
| 测试夹具中重建的相似组件 | 从项目中导入真实组件 |
| 测试夹具重新样式或重新主题组件 | 应用布局、字体和令牌的原样；标签和宽度是页面添加的所有内容 |
| 每个场景启动浏览器、调试或截图 | 一次加载和一次查看，或者交出 URL 并跳过查看 |
| 发现以品味为表达 | 报告页面上的可见内容，或者什么也不报 |
| 没有所有者的断点报告 | 命名诊断该断点的领域技能 |
| 干净运行用建议填充 | "所有内容都存活了" 加上场景列表是报告 |
| 视口按场景调整大小 | 宽度是页面上的固定容器；一次加载显示它们全部 |
| 表格中有断点但页面未标记 | 在场景标签下方做笔记；页面作为自己的报告阅读 |
| 报告和页面在同一轮中删除 | 页面是报告的一半；仅在用户请求时删除 |
