# 可访问性

如果你使用该平台，大部分可访问性都是免费的。原生元素自带键盘支持，真实标签会自我宣告，可见的焦点环只需要一条 CSS 规则。

在项目的样式系统中编写每一个修复，并使用下面精确的值，而不是看起来熟悉的替代值。

审查意味着两次遍历。首先是纯键盘遍历，其中每个流程都不需要鼠标即可完成。然后是屏幕阅读器遍历，其中每个控件都会宣告其名称、角色及其状态。当不确定时，选择平台默认值而不是自定义重建，并移除 ARIA 而不是添加它。

对比度测量和颜色修复属于 `better-colors`。文本大小和 iOS 输入缩放属于 `better-typography`。空间 RTL 布局属于 `better-layout`。

## 优先使用原生元素

ARIA 的第一条规则：当存在原生元素时，不要使用 ARIA。使用 `<button>` 执行操作，使用 `<a href>` 进行导航，永远不要使用 `<div onClick>`。真实链接必须支持 Cmd/Ctrl/中键点击。没有 ARIA 比糟糕的 ARIA 更好。有关地标、按钮与链接以及禁用状态的详细信息，请参阅 [semantics-and-aria.md](semantics-and-aria.md)。

## 可见的焦点环

样式化 `:focus-visible`，而不是裸 `:focus`。键盘用户会得到一个环，而鼠标用户通常不会。优先使用浏览器的未修改指示器。

自定义环需要一个项目焦点标记或另一个显式颜色。验证整个指示器与它交叉的每个相邻颜色，包括 `currentColor`。使用至少 `2px` 的实线边界或等效的可见区域。在没有验证替代方案的情况下，永远不要使用 `outline: none`，并在强制颜色模式下保留系统颜色。配方在 [focus-and-keyboard.md](focus-and-keyboard.md) 中。

## 完整的键盘支持

每个指针交互都需要一个键盘路径。遵循 ARIA APG 模式：Esc 关闭覆盖层，箭头键在复合控件内移动，Tab 在控件之间移动，Enter 和空格激活。

仅使用 `tabindex="0"` 加入自然 Tab 顺序，使用 `tabindex="-1"` 进行程序化焦点。正数值会破坏该顺序。复合控件使用游走 tabindex，其中活动项为 `0`，其他项为 `-1`。

## 锁定和恢复焦点

模态在背景内容上设置 `inert`，在打开时将焦点移入，在关闭时将焦点返回到触发器。添加 `overscroll-behavior: contain` 以防止背景内容滚动。

## 最小点击区域

WCAG 2.5.8 的 AA 基线是 24×24 CSS 像素目标，或其间距、等效控件、内联、用户代理和必要例外之一。在触摸屏上目标为 44×44px，在密度允许的桌面上目标为 40×40px。当可见元素应保持较小时，使用伪元素扩展。

永远不要让扩展的点击区域重叠。给装饰性层 `pointer-events: none`，这样光晕永远不会吞噬下方控件的点击。尺寸和碰撞规则在 [hit-areas.md](hit-areas.md) 中。

## 每个控件都进行标签和类型化

每个输入都得到一个 `<label for>` 或一个包装的 `<label>`。占位符永远不会是标签。标签和控件共享一个点击目标，复选框与其文本之间没有死区。

添加 `autocomplete`，使用有意义的 `name`，并加上召唤正确键盘的 `type` 和 `inputmode`。永远不要阻止粘贴；用户粘贴密码和一次性代码。有关表单的详细信息，请参阅 [forms.md](forms.md)。

## 宣告错误

在请求开始之前保持提交按钮启用，然后使用旋转器和原始标签禁用它。在提交时进行验证。将失败的字段标记为 `aria-invalid="true"`，将 `aria-describedby` 指向内联错误文本，并将焦点放在第一个无效字段。

当控件确实不可用时，使用原生 `disabled`。仅在它应该保持可聚焦时才使用 `aria-disabled="true"`，然后在代码和样式中阻止指针、键盘和表单行为，并显式样式化该状态。

## 每处都有可访问名称

仅带图标的按钮需要一个描述性的 `aria-label`。可见的标签文本必须出现在可访问名称中。装饰性元素使用 `aria-hidden="true"`，永远不要在可聚焦元素上使用它。

## 不要仅依赖颜色

状态需要一个冗余提示：一个图标、文本或与颜色一起的下划线。确定适用的 WCAG 对比度要求，然后使用 `better-colors` 测量渲染的对。如果失败，报告该对和它错过的要求，并保留颜色，除非被要求。

## 尊重 `prefers-reduced-motion`

将动画包裹在 `@media (prefers-reduced-motion: no-preference)` 中，使其为可选。在减少动画时，用不透明度交叉淡入替换滑块和缩放，并完全停止视差和自动播放。

无论偏好如何，都有两条规则。自动播放的媒体需要一个可见的暂停控件，而带有操作或错误的吐司会保持到被关闭。有关动画和缩放的详细信息，请参阅 [motion-and-zoom.md](motion-and-zoom.md)。

## 宣告动态内容

三种机制，三种任务。`aria-describedby` 承载特定字段的验证。一个礼貌的实时区域 (`role="status"`) 承载与控件无关的非紧急更新，例如吐司和结果计数。`role="alert"` 承载紧急的未关联错误和除此之外的任何内容。

重复礼貌宣告需要一个在文本更新之前渲染的稳定空区域。动态插入的警报在不同屏幕阅读器上的支持各不相同，因此请在您目标屏幕阅读器上测试它们。有关屏幕阅读器的详细信息，请参阅 [screen-readers.md](screen-readers.md)。

## 根据目的提供替代文本

装饰性图像使用 `alt=""`。信息性图像描述其含义。功能性图像描述其操作：搜索图标按钮是 `alt="Search"`，而不是 `alt="放大镜"`。

## 结构是导航

使用描述其部分的标题，并形成一个连贯的提纲。给页面一个 `<h1>`，并嵌套其下的级别而不跳过。暴露一个可见的主要 `<main>` 地标。当重复的导航或界面先于它出现时，将“跳转到内容”链接设置为第一个可聚焦元素。锚定标题使用 `scroll-margin-top`。

## 适应缩放和文本调整大小

页面必须在 200% 缩放下工作，并在 320px 宽度下重新流式而不水平滚动。在文本容器上使用 `min-height` 而不是固定的 `height`。在适合代码库的地方优先使用 `rem` 断点，并永远不要让视口元数据限制读者的缩放范围。

## 完成前注意事项

| 错误 | 修复 |
| --- | --- |
| 假设自定义焦点颜色适用于所有地方 | 验证它相对于每个相邻颜色和在强制颜色模式下的效果 |
| 重复礼貌更新不一致宣告 | 保持一个稳定的空状态区域并更新其文本 |
| `assertive` 实时区域用于常规吐司 | 使用 `polite`；将 `assertive` 保留用于错误 |
| 可聚焦元素上的 `aria-hidden="true"` | 移除它或使元素不可聚焦 |
| 提交按钮在表单有效之前禁用 | 保持它启用；在提交时验证并聚焦第一个错误 |
| 触摸屏上点击后的悬停处理卡住 | 使用 `@media (hover: hover)` 隔离悬停样式 |
| 原生 `disabled` 控件上的提示 | 它旁边的文本，或 `aria-disabled` 以使其保持可聚焦 |

## 报告

**严重性。** `HIGH` 阻止任务，隐藏辅助技术内容，或创建系统级故障。`MEDIUM` 使交互有意义地更难。`LOW` 是孤立的改进。

**验证。** 没有浏览器：每个交互元素上的可访问名称，非原生控件的键盘处理程序，焦点样式，`prefers-reduced-motion` 保护和表单标签绑定到其输入。有一个：按顺序遍历 Tab，从可访问性树中读取计算名称和角色，确认每个停止点都有可见的焦点指示器，并运行自动审计。报告您无法运行的每个检查为 `Not verified`。

**格式。** 按违反的每个原则分组发现，按严重性排序，每个根原因按其在每个位置出现的顺序列出一行：

| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |

`位置` 是 `path/to/file:line`。`原因` 指出原则和用户影响。

以 `Block` 结尾，当任何 `HIGH` 存在时，否则为 `Approve`，将剩余部分保留在表中作为待办事项。永远不要 `Approve` 您未检查的覆盖率。如果没有可报告的内容，请声明“没有可采取的可访问性发现”并报告验证。
