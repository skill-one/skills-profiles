# 变体

这项技能针对一个描述的 UI 元素，构建三个在目的上有所不同的版本。它们位于真实页面中的选择器后面，因此你可以切换它们并选择。

这里的其他技能都是进行判断。这个技能产生候选方案并将决策权交还。审查现有 UI 是 `interface-review` 和 `better-interface`，它不会挑选出获胜者。

## 不同的答案，而非不同的色调

在强调色上有所不同的三个变体什么也教不了。你切换它们，看不到真正的选择，运行就浪费了。

因此，每个变体都是对同一简报的不同答案，在这个集合拥有的轴上：

| 轴 | 所有者 | 变化的内容 |
| --- | --- | --- |
| 结构 | `better-layout` | 分组、顺序、列数、折叠的内容 |
| 密度 | `better-layout` | 间距比例、点击区域、能容纳多少内容 |
| 强调 | `better-colors` | 填充颜色放置的位置、什么会退后 |
| 字体 | `better-typography` | 尺寸等级、重量对比、度量 |
| 语气 | `better-writing` | 标签、语气、多少文案 |

选择**一个主要轴**，并让每个变体在这个轴上有不同的位置。次要选择是从主要选择衍生出来的，而不是各自独立变化。一个密集的变体可能需要更小的字体等级，这就是一致性，而不是第二个轴。

同时改变所有轴会产生三个无法归因的结果。你了解你喜欢哪一个，而不是什么让它起作用，所以下一个作品从零开始。

## 每个变体必须满足的基础要求

一个在视觉上获胜但在升级触发器上失败的变体不是候选方案。它是一个带有漂亮表面的错误。

在变体进入选择器之前，它必须满足 `better-interface` 的升级触发器。每个控件都有一个可访问的名称，键盘可以到达指针可以到达的所有地方，焦点是可见的，在 320px 时没有任何内容被裁剪，并且没有意义仅依赖于颜色。

这个基础要求在所有变体中都是相同的。它不是一个轴，并且永远不会与一个轴进行权衡。如果一个方向只能通过破坏它才能起作用，就说出来并放弃这个方向。

## 1. 一次只针对一个元素

每次运行一个 UI 元素。 "仪表板" 不是一个元素；指标卡片是。如果简报涵盖多个元素，命名其他元素挂载的那个元素，说明原因，并将其余元素作为后续运行提供。

用一句话重述简报：这个元素是什么，它在哪里渲染，它必须做什么。

## 2. 了解基础

变体必须看起来像是明天就能发布，所以阅读它们所依赖的内容：

- 样式系统、组件库和任何动画库。
- 标记：颜色、间距、半径、字体等级、缓动。
- 产品的密度和语气。一个密集的专业工具限制了最大胆的变体可能走多远。
- 元素渲染的位置：在什么背景上，在哪个邻居旁边，在哪个宽度。

如果没有项目可以参考，使用中性的灰色、一种强调色和系统字体堆栈，并说明你就是这样做的。

## 3. 在编写代码前命名轴

默认为三个变体。只有在被要求时或空间确实很宽时才增加到五个。超过五个后，没有人会进行比较，他们只会滚动。

首先写下这个集合，每个变体一个名称和一个轴位置。名称说明方向是什么，所以 `Quiet`、`Editorial`、`Dense`，而不是 `Option A`。

这一步完成时，没有两个变体共享位置，并且你可以用一句话说明每个变体的轴。

## 4. 将其构建到真实页面中

一个变体在孤立状态下看起来很好，这就是为什么孤立是判断它的错误地方。将变体托管在将实际包含该元素的页面上，带有真实的边框、真实的邻居和真实的数据。

使用 URL 搜索参数（`?variant=quiet`）进行选择，这样每个变体都是一个你可以发送给某人的链接。一个浮动控件设置它；[picker.md](picker.md) 包含规范。

一次渲染一个变体，全尺寸。缩略图会扭曲间距和比例，而间距通常是你要选择的内容。

在没有页面可以托管它的情况下，构建一个自包含的 HTML 文件，并保留相同的选择器。

给每个变体提供真实的内容：产品形状的文案、合理的名称和页面将实际承载的项目数量。Lorem ipsum 和三行使每个结构看起来都很好。

## 5. 展示权衡并停止

首先自己切换每个变体。每个变体都会渲染，每个交互都会响应，控制台是干净的。

然后交出决策权：

| 变体 | 轴位置 | 正确时 | 成本 |
| --- | --- | --- | --- |
| Quiet | 最低视觉重量 | 页面每天使用 | 最不令人难忘 |
| Editorial | 最大字体、最多空间 | 时刻值得分量 | 消耗垂直空间 |

说明选择器运行的位置，哪个键切换它，以及你在哪个宽度下进行判断。答案可以在 375px 和 1440px 之间变化。

永远不要在表格中标记最喜欢的变体。直接被问及时，从该元素被看到的频率和产品的个性出发回答，而不是从你享受构建哪个变体出发。

## 6. 推广一个，删除其余的

在选择后：将那个变体正确地构建到它所属的位置，遵循项目的自身规范，然后删除其他变体和框架。

被要求再进行一轮时，保留框架并再次运行步骤 3，围绕你倾向于的方向采取新的位置。

在推广之前，框架从不从生产中导入，生产也从不从框架中导入。

## 完成前注意事项

| 错误 | 修复 |
| --- | --- |
| 变体仅在强调色或文案上有所不同 | 将其中一个移动到主要轴上的不同位置，或者删除它 |
| 每个轴都同时变化 | 变化一个；让其余的跟随它 |
| 在空白路径上判断 | 将它们托管在将包含该元素的页面上 |
| Lorem ipsum、三行、"Jane Doe" | 真实文案和页面将实际承载的项目数量 |
| 最大胆的变体跳过键盘或焦点 | 满足基础要求或放弃方向 |
| 表格中标记最喜欢的变体 | 说明每个变体的成本并让用户选择 |
| 使用项目的标记重新设计选择器 | 将其明显地放在设计系统之外 |
| 推广后留下框架 | 删除它，除非被要求保留它 |
