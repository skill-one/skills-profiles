# UI 精炼

精炼来自于众多细微之处的累积。这项技能是衡量哪些值得拥有以及它们所代表价值的参考标准。

在评审时，减慢界面的运行速度。在 10% 速度下感觉不对劲的地方，在全速下就是微妙的问题所在。

保持项目组件库、token 和密度，并匹配其动效语言，除非下述规则规定需要精确的交互。

下述的每个持续时间、曲线、缩放和模糊都是特定值，而非近似范围。`cubic-bezier(0.2, 0, 0, 1)` 不是 `cubic-bezier(0.4, 0, 0.2, 1)`，`0.96` 不是 `0.95`。使用所写的值。

文本换行、字体渲染、表格数字和文本间距属于 `better-typography`。点击区域、焦点、键盘支持、ARIA 和减少动效属于 `better-accessibility`。分组、分区间距、断点和非空间 RTL 属于 `better-layout`。

## 同心圆角半径

外半径 = 内半径 + 内边距。嵌套元素上不匹配的半径是导致界面感觉不对劲的最常见问题。半径、阴影和轮廓配方在 [surfaces.md](surfaces.md) 中。

## 视觉对齐而非几何对齐

当几何中心对齐看起来不对劲时，进行视觉对齐。带图标的按钮、播放三角形和非对称图标都需要手动调整。

## 用于提升的阴影，用于结构的边框

当边框仅用于创建深度时，优先使用分层透明 `box-shadow` 值。保留用于传达结构或状态的边框：分隔符、分隔线和选中或焦点状态。

## 可中断的动画

使用 CSS 过渡效果进行交互状态变化，因为它们可以在动画中途中断。保留关键帧用于一次性运行的阶段性序列。

## 分割和错开进入动画

对于不频繁的阶段性进入，且序列传达层级关系时，将内容分割为语义块并错开约 100ms。动画一个容器在相同成本下效果更差。保留高频交互不进行错开。参见 [enter-exit.md](enter-exit.md)。

## 微妙的退出动画

使用小的固定 `translateY` 而非全高度。退出应比进入更柔和。两个方向都使用 `ease-out`。

## 上下文图标动画

使用 `opacity`、`scale` 和 `blur` 动画图标，而非切换可见性。使用精确的值：缩放 `0.25` 到 `1`，不透明度 `0` 到 `1`，模糊 `4px` 到 `0px`。

使用动效库（`motion` 或 `framer-motion` 在 `package.json` 中），匹配该包的导入路径，或在两者都存在时匹配附近的导入。使用 `transition: { type: "spring", duration: 0.3, bounce: 0 }`。弹跳始终为 `0`。

不使用时，将两个图标保留在 DOM 中，一个绝对定位，使用 `cubic-bezier(0.2, 0, 0, 1)` 进行交叉渐变。这提供了无依赖的进入和退出。两种配方在 [icon-transitions.md](icon-transitions.md) 中。

## 图像轮廓

为图像添加低不透明度的 `1px` 轮廓以保持一致深度。亮模式下的纯黑色 (`oklch(0 0 0 / 0.1)`)，暗模式下的纯白色 (`oklch(1 0 0 / 0.1)`)。绝不使用接近黑色的颜色如 Slate 或 Zinc，也绝不使用带色的中性色。带色的轮廓会吸收下方表面的颜色，并在图像边缘看起来像污渍。

## 点击缩放

点击时使用 `scale(0.96)` 给按钮提供触觉反馈。始终为 `0.96`；低于 `0.95` 会感觉夸张。在动效会分散注意力时，添加 `static` 属性禁用它。参见 [recipes for CSS, Tailwind and Motion](animations.md#scale-on-press)。

## 页面加载时跳过动画

在 `AnimatePresence` 上使用 `initial={false}` 以避免首次渲染时出现进入动画。检查它是否保留了有意为之的页面进入。

## 主题切换时抑制过渡

主题切换会同时改变几乎所有元素的颜色、背景、边框和阴影。这些属性的每个过渡效果会同时触发，切换效果会模糊而非瞬间。注入 `*,*::before,*::after{transition:none !important}`，强制重排，然后在下一帧移除它。参见 [recipe](animations.md#suppress-transitions-on-theme-switch)。

## 仅过渡变化的部分

始终指定精确的属性：`transition-property: scale, opacity`。Tailwind 的 `transition-transform` 覆盖 `transform, translate, scale, rotate`。

## 限制使用 `will-change`

仅用于 `transform`、`opacity` 和 `filter`，这些 GPU 可以合成。绝不使用 `will-change: all`。在看到第一帧卡顿时添加它，而非提前添加。参见 [performance.md](performance.md)。

## 匹配图标描边与文本粗细

紧邻文本的图标会携带文本的视觉重量：常规（400）文本旁的描边为 `1.5px`，半粗（600）文本旁为 `2px`。每个图标集使用单一描边粗细，每个表面使用单一图标库。尺寸和 RTL 翻转在 [icons.md](icons.md) 中。

## 每个状态使用一个 SVG，重新上色

图标使用 `currentColor`，并从 CSS 颜色和不透明度获取悬停、选中和禁用状态，而非从单独的资产获取。轮廓是默认变体；填充表示激活状态。

## 动效约束

高频交互应立即提供反馈，或对不透明度和颜色使用 `150ms` 或更短的过渡。自定义动画在那里会为每个触发支付其注意力成本。

每个动画状态变化也需要静态提示：颜色、图标或标签。动效永远不应是唯一的反馈渠道。

## 完成前检查

| 错误 | 修复 |
| --- | --- |
| 图标看起来未居中 | 使用内边距进行视觉调整，或修复 SVG |
| 突兀的阶段性进入或退出 | 错开不频繁的进入；保持退出微妙 |
| 主题切换使整个页面交叉渐变 | 禁用交换时的过渡，强制重排，下一帧恢复 |
| 元素上使用 `transition: all` | 指定精确属性 |
| 第一帧动画卡顿 | 添加 `will-change: transform`（谨慎使用） |
| 粗体文本旁的细线图标 | 匹配描边宽度与文本粗细 |

## 报告

**严重性。** `HIGH` 会破坏交互，使动效无法使用，或仅在动画运行时可见状态变化。`MEDIUM` 是表面、图标或动效的可见不一致。`LOW` 是孤立的精炼。

**验证。** 无浏览器：组件定义的每个状态，即悬停、焦点、激活、加载和空状态，以及从代码中读取的动效持续时间和缓动。有浏览器：逐个检查状态，并在浏览器的动效面板中以 10% 速度重播动效。报告无法运行的每个检查为 `Not verified`。

**格式。** 按违反的原则分组发现，按严重性排序，每个根原因一行列出其出现位置：

| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |

`位置` 是 `path/to/file:line`。`原因` 指出原则和用户影响。

以 `Block` 结尾，当任何 `HIGH` 存在时，否则为 `Approve`，将剩余部分保留在表格中作为待办事项。绝不 `Approve` 未检查的覆盖率。无任何可报告项时，声明 "未发现可操作的 UI-polish 问题" 并报告验证。
