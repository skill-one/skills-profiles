# 让界面感觉更好的细节

优秀的界面很少来自单一因素。通常是一系列小细节的累积构成了卓越的体验。在构建或评审 UI 代码时应用这些原则。在提出或编写修复方案之前，先确定项目现有的样式系统，并在该系统中表达变化：Tailwind 项目中使用 Tailwind，CSS 项目中使用纯 CSS，或使用已建立的 CSS-in-JS 方法。切勿为了应用微调修复而引入第二个样式系统。

在评审时，减慢界面的速度：在浏览器的动画面板中以 10% 的速度重播动画，并遍历每个状态：悬停、聚焦、激活、加载、空。在 10% 的速度下感觉不对劲的地方，就是在全速时微妙出错的地方。

## 核心原则

### 1. 同心圆角半径

外半径 = 内半径 + 内边距。嵌套元素上不匹配的半径是让界面感觉不对劲的最常见原因。

### 2. 光学对齐优于几何对齐

当几何中心对齐看起来不对时，进行光学对齐。带有图标的按钮、播放三角形和非对称图标都需要手动调整。

### 3. 阴影用于提升，边框用于结构

对于边框仅用于创建深度的按钮、卡片和容器，优先使用带透明度的分层 `box-shadow` 值。保留用于传达结构或状态的边框：分隔符、布局分隔符、选中或聚焦状态。

### 4. 可中断的动画

使用 CSS 过渡进行交互状态变化——它们可以在动画中途中断。保留关键帧用于一次性运行的分阶段序列。

### 5. 分割和错开进入动画

对于不频繁的分阶段进入，其中序列有助于传达层级关系，将内容分割为语义块并错开约 100ms，而不是对单个容器进行动画。不要错开常规、高频的交互。

### 6. 微妙的退出动画

使用小的固定 `translateY` 而不是全高度。退出应该比进入更柔和。进入和退出过渡都使用 `ease-out`。

### 7. 上下文相关的图标动画

使用 `opacity`、`scale` 和 `blur` 动画图标，而不是切换可见性。使用确切的值：从 `0.25` 缩放到 `1`，不透明度从 `0` 到 `1`，模糊从 `4px` 到 `0px`。如果项目在 `package.json` 中有 `motion` 或 `framer-motion`，匹配该包的导入路径（或当两者都存在时附近的导入），并使用 `transition: { type: "spring", duration: 0.3, bounce: 0 }`——弹跳必须始终为 `0`。如果没有安装运动库，将两个图标都保留在 DOM 中（一个绝对定位），并使用 CSS 过渡进行交叉渐变，使用 `cubic-bezier(0.2, 0, 0, 1)`——这提供了进入和退出动画，没有任何依赖。

### 8. 字体平滑

在 macOS 的根布局上应用 `-webkit-font-smoothing: antialiased` 以获得更清晰的文本。

### 9. 表格数字

对任何动态更新的数字使用 `font-variant-numeric: tabular-nums` 以防止布局偏移。

### 10. 文本换行

对标题使用 `text-wrap: balance`。对正文文本使用 `text-wrap: pretty` 以避免产生孤行。

### 11. 图像轮廓

为图像添加一个 1px 的低不透明度轮廓以保持一致的深度。颜色在亮模式下必须是纯黑色 (`oklch(0 0 0 / 0.1)`)，在暗模式下必须是纯白色 (`oklch(1 0 0 / 0.1)`)，绝不能是接近黑色的颜色，如 Slate、Zinc 或任何带色的中性色。带色的轮廓会吸收其下方的表面颜色，并在图像边缘看起来像污渍。

### 12. 点击缩放

点击时使用 `scale(0.96)` 给按钮提供触觉反馈。始终使用 `0.96`。绝不要使用小于 `0.95` 的值——任何低于此值的感觉都过于夸张。当运动会造成干扰时，添加 `static` 属性禁用它。

### 13. 页面加载时跳过动画

在 `AnimatePresence` 上使用 `initial={false}` 以防止首次渲染时的进入动画。验证它不会破坏有意设置的进入动画。

### 14. 绝不使用 `transition: all`

始终指定确切属性：`transition-property: scale, opacity`。Tailwind 的 `transition-transform` 覆盖 `transform, translate, scale, rotate`。

### 15. 适度使用 `will-change`

仅用于 `transform`、`opacity`、`filter`——GPU 可以合成的属性。绝不要使用 `will-change: all`。仅在检测到第一帧卡顿时才添加。

### 16. 最小点击区域

交互元素应优先选择 44×44px 的点击区域，用于触摸或移动上下文。在密集的桌面界面中，至少使用 40×40px。如果可见元素较小，使用伪元素扩展。绝不要让两个元素的点击区域重叠。

### 17. 匹配图标描边与文本粗细

紧邻文本的图标承载文本的光学重量：旁边是常规（400）文本的 `1.5px` 描边，旁边是半粗（600）文本的 `2px`。每个图标集使用单一描边粗细；绝不要在一个表面上混合库。

### 18. 一个 SVG，每个状态重新着色

图标使用 `currentColor` 并通过 CSS 颜色和不透明度获得其状态（悬停、选中、禁用），绝不要通过单独的资产。轮廓变体是默认值；填充变体表示激活状态。

### 19. 运动限制

高频交互上不要使用自定义动画：每次触发都会重复注意力成本。运动永远不会是唯一的反馈渠道；每个动画状态变化也需要静态提示，如颜色、图标或标签。

## 常见错误

| 错误 | 修复 |
| --- | --- |
| 父元素和子元素使用相同的边框圆角 | 计算 `outerRadius = innerRadius + padding` |
| 图标看起来未居中 | 使用填充或直接修复 SVG |
| 边框仅用于模拟提升 | 使用带透明度的分层 `box-shadow`；保留结构和状态边框 |
| 令人惊愕的分阶段进入或上下文相关的退出 | 错开不频繁的进入，保持上下文保留的退出微妙 |
| 数字导致布局偏移 | 应用 `tabular-nums` |
| macOS 上的重文本 | 在根布局上应用 `antialiased` |
| 页面加载时播放动画 | 在 `AnimatePresence` 上添加 `initial={false}` |
| 元素上使用 `transition: all` | 指定确切属性 |
| 第一帧动画卡顿 | 适度添加 `will-change: transform` |
| 小控件上微小的点击区域 | 使用伪元素扩展到 44×44px（用于触摸/移动），或在密集的桌面 UI 中至少使用 40×40px |
| 粗文本旁边的细线图标 | 将描边宽度与文本粗细匹配 |
| 每个状态使用单独的图标资产 | 一个 `currentColor` SVG，状态通过 CSS |
| 处处使用填充图标 | 默认使用轮廓，仅在激活状态下使用填充 |
| 每次悬停或按键都有进入动画 | 即时反馈或 ≤150ms 的不透明度/颜色过渡 |

## 评审输出格式

如果没有提供评审模式，使用 `full`。

| 模式 | 覆盖范围 | 找出上限 |
| --- | --- | --- |
| `quick` | 主要用户路径和最高流量状态；仅报告 `HIGH` 和 `MEDIUM` 的问题 | 5 |
| `full` | 跨排版、表面、动画、图标和性能的整个请求范围 | 15 |

### 范围和覆盖范围

说明模式、确切范围、框架、样式约定和任何评审边界。显示实际检查了什么：

| 类别 | 检查的证据 | 结果 |
| --- | --- | --- |
| 排版 | 文件、组件、状态或检查 | 发现数量、`Clear` 或 `Not reviewed` 及原因 |

包含所有五个快速参考类别。绝不要暗示未检查的表面被评审了。

### 发现

按原则分组发现。使用带有 **严重性**、**位置**、**之前**、**之后** 和 **原因** 列的 markdown 表格。包含所有做出的或建议的改变，而不是子集。绝不要使用单独的 "之前:" / "之后:" 行。

- **严重性**：`HIGH` 使交互无法访问、误导、难以阅读或反复干扰；`MEDIUM` 创建明显的可用性或一致性问题；`LOW` 是孤立的微调，仅在 `full` 模式下出现。
- **位置**：引用 `path/to/file:line`。如果该工件没有源文件，引用确切的屏幕和组件。
- **之前 / 之后**：显示当前实现和可操作的替代方案。
- **原因**：命名违反的原则并解释其对用户的影响。

将重复的系统性问题合并为一行，并列出每个受影响的位置。省略没有发现的原理，并且绝不要填充报告以达到上限。

### 示例

#### 同心边框圆角
| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |
| LOW | `src/Card.tsx:28` | `rounded-xl` 在卡片上 + `rounded-xl` 在内部按钮 (`p-2`) | `rounded-2xl` 在卡片 (`8 + 8 = 16`)，`rounded-lg` 在内部按钮 | 嵌套角落应该是同心的 |
| LOW | `src/card.css:11` | 两个嵌套表面上的 `border-radius: 16px` | 卡片外 `24px`，内部 `16px` 带有 `8px` 内边距 | 相同的嵌套半径使内部表面看起来被挤压 |

#### 表格数字
| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |
| MEDIUM | `src/Counter.tsx:17` | `<span>{count}</span>` | `<span className="tabular-nums">{count}</span>` | 比例数字在值变化时会导致布局偏移 |
| LOW | `src/timer.css:8` | 计时器上的默认数字 | 为计时器添加 `font-variant-numeric: tabular-nums` | 等宽数字使计时器保持稳定 |

#### 点击缩放
| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |
| LOW | `src/Button.tsx:19` | `<button className="...">` | 添加 `active:scale-[0.96] transition-transform` | 点击反馈使控件感觉有响应 |
| MEDIUM | `src/button.css:24` | 点击时 `scale(0.9)` | 提高到 `scale(0.96)` | 任何低于 `0.95` 的值都感觉过于夸张 |

### 考虑但拒绝

在 `quick` 模式下包含 1-3 个真实候选，在 `full` 模式下包含 2-5 个：

| 位置 | 候选 | 拒绝原因 |
| --- | --- | --- |
| `src/Card.tsx:28` | 增加阴影 | 现有深度与共享的表面标记匹配；改变一个卡片会降低一致性 |

不要编造填充内容。如果范围包含较少的边缘候选，包含存在的候选并说明。

### 验证和裁决

在发现之后：

1. **验证**：列出运行的确切命令或交互及其观察到的结果。遍历每个相关状态，并在涉及动画时检查 10% 速度的运动。如果检查未运行，标记为 **未验证** 并说明剩余内容。
2. **裁决**：如果任何 `HIGH` 发现仍然存在，则为 `Block`；如果只有 `MEDIUM` 或 `LOW` 发现仍然存在，则为 `Needs changes`；只有在没有可操作的发现时才为 `Approve`。列出所有未验证的检查。

当没有发现时，省略发现表格，说明 "没有可操作的界面微调发现"，报告验证和拒绝的候选，并以 `Approve` 结束。
