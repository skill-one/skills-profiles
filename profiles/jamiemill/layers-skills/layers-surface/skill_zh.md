# /layers-surface

*假设已加载`/layers-intro`。这项技能是一套技术方法，而非脚本——参见那里的“如何使用这些技能”。*

表面层是将下方所有决策转化为用户实际接触到的形式的地方：文字、声音、视觉、物理交互方式、动态效果、反馈信息。它是与媒介特性最相关的层，但最重要的决策首先必须是通用的——无论表面是屏幕、语音界面、物理设备还是服务触点，这一点都适用。

表面层的问题往往是更深层次问题的症状。这里的中心学科在于区分哪些问题可以在表面层解决，哪些问题需要重新审视下层。

---

## 该层做出的决策

- 表面是否遵循概念模型中的词汇和对象
- 每个面包板上的交互方式是否都存在——以及是否任何表面元素背后没有模型支撑
- 情感基调是否与用户正在执行的任务匹配
- 用户如何知道发生了什么、进行中什么、以及出错了什么
- 什么是最突出的，以及是否应该突出
- 所有内容是否对需要它们的用户都可访问

---

## 学科——使表面保持真实的方法

- **表面修复与深层问题。** 关键判断：这是否是需要在文案/布局中修复的问题，还是概念模型或交互流程中存在根本原因的症状？错误的词汇可能是需要重写——或者模型从未确定术语。将深层问题反馈到相关技能，而不是修补症状。
- **术语与通用语言匹配。** 标记直接违规（模型术语使用不一致）、未列出术语（表面词汇不在模型中——添加到模型，或删除为噪音）、以及语气错位。
- **对象一致性。** 没有变形者（同一对象在不同上下文中以显著不同的形式出现），没有隐藏对象（用户无法识别对象类型的表单）。
- **双向完整性。** 每个面包板的交互方式都存在；没有没有模型或流程支撑的表面元素（这些是交互决策中遗漏的——路由到`/layers-interaction-flow`）。
- **错误诊断、解释、恢复。** “出错了”未能满足所有三个要求。标记所有未执行所有三个操作的错误状态。
- **突出反映重要性。** 流程需要用户注意的内容是突出的；不应突出任何不应突出的事物。
- **可访问性由决策决定，而非默认。**
- **情感基调与用户需求中的情感和社会任务匹配——而非将产品利益作为用户需求来表述。**

## 技术

这里包含两种类型的工作：对照下层审计现有表面，以及处理开放的表面决策。根据情况使用其中一种。

| 技术 | 用于 |
|---|---|
| **词汇检查** | 取得通用语言列表；检查每个标签、标题、按钮、错误、通知、帮助字符串。 |
| **对象一致性检查** | 对于每个模型对象：它出现在哪里，以多少种形式出现？捕获变形者和隐藏对象。 |
| **完整性检查** | 沿面包板和表面双向行走——缺失的交互方式，以及没有模型支撑的表面。 |
| **情感基调检查** | 回到情感和社会任务；找到语气、表述或重点错位的地方。 |
| **反馈与错误清单** | 对于每个操作和状态转换：用户如何知道它是否成功、进行中或失败——以及下一步该做什么？ |
| **层级审查** | 每个关键位置：用户必须注意或采取行动的内容是什么，表面是否使其最突出？在决定如何传达之前，先决定什么是主要的。 |
| **可访问性检查** | 每个媒介——屏幕（对比度、尺寸、触摸目标、键盘、屏幕阅读器标签、焦点）、语音（所有内容都通过语言传达，没有视觉上下文时的恢复）、物理（可达性、触觉区分、照明、无需精细运动要求）。 |
| **一致性检查** | 相似事物以相似方式处理，不同事物以不同方式处理；尊重或故意打破媒介惯例。 |
| **制作表面（真实媒介、模型图、样式瓦片、原型、设计系统、先写文案）** | 在制作表面而非审计表面时。使用代码获取真实交互反馈；模型图用于布局/层级；样式瓦片用于早期语气；原型用于时间和动态效果；扩展（不要矛盾）现有设计系统；当语言是主要材料时先写文案。 |

---

## 与设计师合作

确定媒介以及来自下方的存在内容——概念模型（对象+通用语言）、面包板、包含情感/社会任务的作业故事。如果表面已存在，则审计它；如果不存在，则处理开放的决策。

提供适合实时问题的技术——当术语感觉不对时进行词汇检查，当用户不知道发生了什么时进行反馈清单，当可访问性被默认时进行可访问性检查。不要运行所有十个。

仅记录残留物：审计发现（每个标记为表面修复或深层问题的表面），分组和优先排序的开放表面决策（包括选项和约束），需要首先解决的跨层问题，以及已经很好地工作且在修订中不会丢失的内容。

表面要么尊重下方已决定的内容，要么破坏它。在概念模型或交互结构发生任何重大变化后，重新审视。
