# /layers-product-strategy

*假设已加载 `/layers-intro`。这项技能是一个技术库，而非脚本——请参阅那里的“如何使用这些技能”。*

策略是解决方案空间的第一层——在问题空间理解转化为关于范围和方向的明确决策的地方。它涉及选择：要服务哪些用户需求，以及要瞄准哪些业务成果。

---

## 该层做出的决策

- 该工作服务的业务成果
- 哪些用户机会（需求、痛点、愿望）真正与该成果相关联
- 我们在这些机会上押注的解决方案
- 如何以低成本测试风险最大的假设
- 要首先追求哪些赌注，以及原因

如果成果和赌注已经明确，不要为了重建树而重建树。

---

## 纪律——使策略保持诚实

- **成果是可衡量的、有意义的、有边界的。** 不是“发展产品”，而是“增加在30天内激活的用户”。每棵树只有一个成果。
- **机会是客户需求/痛点/愿望——锚定于旅程时刻。** 第一人称、问题空间陈述（“我不知道哪个流媒体服务有这部电影”），而不是工作故事，也不是功能。应用**翻转测试**：如果你能将其表述为功能，那它就是伪装的解决方案。保持它们具体，而不是通用。**按旅程时刻分组机会**——这个强制因素暴露了模糊的机会，并突显了未被解决的时刻。（Teresa Torres。）
- **每个机会都与成果相关联。** 如果服务它不会推动成果，它就不属于这棵树。
- **每个赌注都指明其风险最大的假设，** 每个机会都有多个赌注——抵制过早收敛。
- **每个实验都是测试核心假设的最廉价方式** ——几天，而不是几个月。

---

## 技术

机会解决方案树是默认选项；其余技术服务于特定的战略问题。

| 技术 | 使用场景 |
|---|---|
| **机会解决方案树** (Teresa Torres) | 默认。使成果→机会→解决方案→实验明确化。适用于持续发现。 |
| **解决方案赌注** | 对于选定的机会：*"我们可以[解决方案]，我们相信它会[服务机会]，因为[理由]。"* 生成多个；为每个赌注命名其关键假设。 |
| **实验** | 赌注核心假设的最廉价测试——原型、虚假门、贵宾服务、有针对性的访谈、数据分析。 |
| **影响映射** (Gojko Adzic) | B2B，具有多个必须改变行为的利益相关者。 |
| **工作组合映射** | 许多工作故事——通过频率、严重性、战略契合度决定要瞄准哪些。 |
| **现在/下一刻/稍后路线图** | 团队需要一个共享的时间线视图来展示赌注。 |
| **卡诺分析** | 将候选功能排序为保健、性能和愉悦。 |
| **HEART / 北极星** (Google / Amplitude) | 选择成果指标。HEART构建选择；北极星提炼为单一指标。 |
| **沃德利映射** | 位置取决于能力在进化曲线上的位置；构建/购买/合作。 |
| **捆绑/解绑** (Christensen) | 该产品是否应该拥有更多的工作流程，还是精确地拥有一个工作？ |
| **NPE 画布** | 消费产品：叙事、原始、使能者。 |
| **关键用户旅程** (Google / Reforge) | 哪些流程要优先考虑——到达核心价值的最短路径（高流量、高收入或指标关键）。 |

当你将树作为图表构建时 (`graph TD`)：成果在顶部，通过按**旅程时刻分组**的机会向下分支，然后是赌注，然后是实验。自上而下的阅读是依赖关系，而不是顺序。

## 与设计师合作

首先确定期望的成果，并推动其具体化。然后映射与其相关联的机会（应用上述纪律），为值得追求的机会生成赌注，并确定最有希望的廉价实验。按机会规模、假设风险、努力程度和可逆性进行优先级排序——从高规模、可管理的风险和清晰的实验路径开始，而不一定是雄心勃勃的。

提供适合问题的技术——一个机会解决方案树来连接所有内容，卡诺或工作组合来在多个候选者中选择，沃德利或捆绑来定位。不要全部运行。

仅捕获残留物：成果、机会树（按旅程时刻分组的机会）、前2-3个赌注及其实验、值得返回的延迟赌注，以及开放问题（未测试的假设、未扎根的需求）。如果底层需求薄弱或假设，请明确说明该策略是基于假设的赌注。

这里选择的赌注定义了下一个需要设计的内容——这些解决方案工作的对象、关系和词汇：`/layers-conceptual-model`。
