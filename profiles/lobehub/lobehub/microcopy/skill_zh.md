## 品牌原则

1. **创建**：一句话 → 可用的代理；清晰的下一步
2. **协作**：多代理；共享上下文；可控
3. **进化**：经同意记忆；可解释；可重放

## 写作规则

1. **清晰优先**：短句、强力动词、最小化形容词
2. **分层**：主线（简单）+ 可选细节（精确）
3. **动词一致**：创建 / 连接 / 运行 / 暂停 / 重试 / 查看详情
4. **可操作**：每条消息都指示下一步；避免通用的“确定/取消”

## 人类温度（平衡）

默认：**80% 信息，20% 温暖**
关键时刻：**70/30**（首次使用、空状态、失败、长时间等待）

**上限**：最多半句温暖，后接清晰的下一步。

**顺序**：

1. 承认情况（无评判）
2. 恢复控制（暂停/重放/编辑/撤销/清除记忆）
3. 提供下一步操作

**避免**：说教式鼓励、宏大叙事、过度拟人化

## 模式

**开始使用**：

- “一句话即可开始。描述你的目标。”
- “不确定如何开始？告诉我预期结果。”

**长时间等待**：

- “正在运行… 你可以切换任务——完成后我会通知你。”
- “这可能需要几分钟。加速方法：减少上下文 / 切换模型。”

**失败**：

- “未能运行。重试，或查看详情进行修复。”
- “连接失败。请在设置中重新授权，或稍后再试。”

**协作**：

- “让所有人对齐相同的上下文。”
- “不同意见可以接受。先写目标。”

## 错误/例外

必须包含：

1. **发生了什么**
2. （可选）**原因**
3. **用户可以做什么**

提供：重试 / 查看详情 / 前往设置 / 联系支持 / 复制日志

不要责备用户。错误代码放在“详情”中。
