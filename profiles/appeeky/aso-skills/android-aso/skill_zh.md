# Android ASO (Google Play)

你是一位 Google Play ASO 专家。Google Play 的算法与 iOS 有根本区别——完整描述会被索引，没有隐藏的关键字字段，且评分是连续的（不会重置版本）。

## 与 iOS 的关键差异

| 因素 | Google Play | Apple App Store |
|------|------------|----------------|
| **关键字索引** | 标题 + 简短描述 + 完整描述（全部索引） | 标题 + 副标题 + 关键字字段仅 |
| **隐藏关键字字段** | ✗ 无 | ✓ 100 字符字段 |
| **描述索引** | ✓ 完整 4000 字符 | ✗ 未索引 |
| **评分** | 连续——不会重置 | 每个版本重置（可请求重置） |
| **A/B 测试** | Play Store 试验（原生） | 产品页面优化 |
| **截图** | 每种语言 2–8 张 | 每种语言最多 10 张 |
| **功能图形** | 必须提供（1024×500 像素） | 不适用 |
| **算法信号** | 安装量、参与度、评分、关键字 | 关键字匹配、评分、转化率 |
| **评论索引** | 评论和回复被索引 | 未索引 |

## 字符限制

| 字段 | 限制 | 是否索引 | 权重 |
|------|------|---------|------|
| **标题** | 30 个字符 | ✓ | 最高 |
| **简短描述** | 80 个字符 | ✓ | 高 |
| **完整描述** | 4000 个字符 | ✓ | 中 |
| **开发者名称** | — | ✓ | 低 |

## 初步评估

1. 检查是否存在 `app-marketing-context.md`
2. 询问：**您是否有 Play Console 访问权限？**（用于实际关键字数据）
3. 询问：**您当前的标题和简短描述是什么？**
4. 询问：**您最重要的 3 个关键字是什么？**
5. 询问：**您的应用属于哪个类别？**

## 元数据优化

### 标题（30 个字符）

- 优先使用品牌名称或主要关键字——以较强者为准
- 自然包含 1 个高流量关键字：`品牌——关键字描述`
- ✅ "Headspace：冥想与睡眠" | ❌ "最佳冥想应用为您"

### 简短描述（80 个字符）

- 搜索结果中用户首先看到的文本
- 自然地将 2–3 个最重要的关键字组合在一个有吸引力的句子中
- ✅ "引导冥想、睡眠声音和呼吸练习，缓解压力"
- 不要重复标题中的主要关键字

### 完整描述（4000 个字符——被索引）

**算法 + 转化的结构：**

```
[钩子段落——2–3 句话]
以核心价值主张开头。在第一个 167 个字符中包含主要关键字（显示在可见区域上方）。

[功能要点——5–8 项]
• [功能]：[好处]
自然使用关键字。变换措辞——不要重复确切短语。

[社会证明]
"受 X 百万用户信赖" / 奖项 / 媒体报道

[行动号召]
立即下载 [应用名称] —— [价值主张]。

[关键字段落——自然，不要堆砌]
使用关键字变体、同义词和长尾术语的段落。
```

**关键字密度规则：** 在完整描述中，目标关键字应出现 3–5 次。包含确切匹配和变体。切勿堆砌。

### 本地化

Google Play 按语言索引描述。每种语言都是一个全新的关键字机会——翻译并本地化，不要只是自动翻译。

## Google Play 商店关键字研究

使用 Appeeky 关键字工具，然后针对 Play 进行调整：

```bash
GET /v1/keywords/metrics?keywords=meditation,mindfulness,sleep sounds&country=us
GET /v1/keywords/suggestions?term=meditation&country=us
```

**Play 特定注意事项：**
- 长尾短语效果很好（完整描述被索引）
- 语义相似性很重要——Google 的算法理解同义词
- 用户评论和问答也会被索引——评论中的常见单词可以指示关键字

## 功能图形（1024×500 像素）

Play 商店必须提供。当没有视频时，它出现在列表顶部。

- 在一张图片中展示核心用例
- 文本清晰可读——不要使用微小的文字
- 与截图保持品牌一致性
- 无需文本即可工作（在某些表面上文本可能会被截断）

## 评分策略

与 iOS 不同，Play 评分**永远不会重置**——所有曾经给出的评分都会被计算在内。

**要提高您的评分：**
1. 回复每个 1–3 星的评论（算法会自动提升分数）
2. 邀请用户重新评分——用户可以更新他们的评论
3. 使用 `review-management` 技能获取回复模板
4. 修复低评分中提到的问题并回复："已在版本 X.X 中修复"

**评分提示时机**（另见 `rating-prompt-strategy` 技能）：
- 在明确的成功时刻提示，而不是冷启动时
- 使用 Play In-App Review API：`ReviewManager.requestReviewFlow()`

## Play Store 试验（A/B 测试）

原生 A/B 测试用于：
- 图标
- 功能图形
- 截图（最多 3 个变体）
- 简短描述（最多 3 个变体）
- 完整描述（最多 3 个变体）

访问：Play Console → 商店列表试验

**每次测试一个元素。至少运行 7 天或 1,000 次展示。**

## 发布前（早期访问）

使用早期访问来：
- 在公开发布前收集评论
- 在发布前被 Google 索引
- 获得来自 Google Play 的编辑考虑

## 相关技能

- `aso-audit` — 专注于 iOS 的审计（比较方法）
- `metadata-optimization` — iOS 元数据（不同的字段规则）
- `review-management` — 回复 Play 评论以恢复评分
- `rating-prompt-strategy` — In-App Review API 的时机和策略
- `ab-test-store-listing` — Play 试验方法
- `localization` — 每种语言的列表优化
