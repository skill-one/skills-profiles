# 订阅生命周期

您优化订阅旅程的每个阶段：试用 → 付费 → 续订 → 恢复取消 → 复购。

## 订阅生命周期

```
安装 → 试用开始 → [试用期] → 转化 → 续订 → ... → 取消 → 复购
            ↓                               ↓              ↓           ↓
         未转化                    自愿退出           非自愿       过期
         (培育)                     (退出调查)       (催款)     (活动)
```

## 各阶段关键指标

| 阶段 | 指标 | 公式 | 基准 |
|------|------|------|------|
| 试用 | 试用开始率 | 试用次数 / 下载次数 | > 20% |
| 试用 | 试用转化率 | 转化次数 / 试用次数 | 25–40% 强 |
| 留存 | 第1个月续订率 | 第1个月续订次数 / 订阅用户数 | > 70% |
| 留存 | 第6个月续订率 | 第6个月续订次数 / 订阅用户数 | > 50% |
| 跳出 | 月度跳出率 | 失去订阅数 / 开始订阅数 | < 5% 良好; < 2% 优秀 |
| 收入 | 月度经常性收入 | 活跃订阅数 × 月度价格 | — |
| 收入 | 客户终身价值 | ARPU / 月度跳出率 | — |
| 恢复 | 催款恢复率 | 恢复金额 / 失败支付次数 | > 30% |
| 复购 | 复购率 | 返回次数 / 过期用户数 | 5–15% |

## 阶段1 — 试用优化

### 试用时长

| 应用类型 | 推荐试用时长 | 备注 |
|----------|--------------|------|
| 简单工具型 | 3–7天 | 快速体现价值 |
| 健康/健身 | 7–14天 | 养成习惯需要时间 |
| 生产力 | 7–14天 | 工作流集成 |
| 教育 | 7–14天 | 完成第一课 |
| 娱乐 | 7天 | 狂刷行为 |

**测试：** 每月应用，7天试用 vs 14天试用 — 转化率可能略微下降，但LTV通常增加。

### 试用培育序列

在试用期间通过应用内（或推送）消息驱动激活：

```
第0天：欢迎 — "您的试用已开始。这里是如何充分利用试用期的方法。"
第1天：核心功能突出 — "今天尝试 [核心功能]"
第3天：进度 / 社会证明 — "使用X功能的用户获得3倍更好的结果"
第5天（7天试用）：紧迫性 — "您的试用还剩2天"
第6天：价值回顾 — "这是您已做 / 可以用高级版做的"
第7天：最后一天 — "您的试用今天结束"
```

**规则：** 消息应展示价值，而不仅仅是制造压力。

### 试用结束 — 转化时刻

在试用结束时，显示一个付费墙，其中：
- 回顾用户在试用期间达成的成就
- 展示最常用的付费功能
- 提供3个计划选项（月度 / 年度 / 终身（如适用））
- 突出年度折扣（"节省40%"）

见 `monetization-strategy` 获取付费墙设计详情。

## 阶段2 — 减少自愿跳出

### 用户取消原因（及如何修复）

| 原因 | 信号 | 修复 |
|------|------|------|
| 忘记订阅 | 会话量低，未激活 | 改进引导 + 通知策略 |
| 价值不足 | 功能使用率低 | 推送未使用的高价值功能 |
| 太贵 | 价格敏感 | 引入低价层或暂停选项 |
| 应用问题 | 1星评价 | 修复漏洞，回复评价 |
| 找到替代品 | — | 监控竞争对手安装 |
| 季节性使用 | 每年同一时间跳出 | 提供暂停选项 |

### 取消流程

当用户发起取消（iOS — `ManagedSubscriptionGroup`）：

1. **在完全取消前提供暂停**： "暂停1–3个月而不是取消"
2. **展示价值回顾**： "本月您使用了 [功能] X次"
3. **提供折扣**： 仅作为最后手段 — 3个月20–30%折扣
4. **退出调查**： 总是询问"您为什么取消？"（1次点击，不是长文）

**取消退出调查选项：**
- 太贵
- 用得不够
- 缺少我需要的功能
- 切换到竞争对手
- 技术问题
- 临时休息

### 需要关注的参与信号

高风险跳出用户：
- 会话量 < 每周1次（从更高的基线下降）
- 核心功能14天以上未使用
- 禁用推送通知
- 最后一次会话 > 7天前

在他们取消前触发再激活推送或应用内消息。

## 阶段3 — 非自愿跳出（支付失败）

非自愿跳出占所有订阅取消的 **20–40%**。

### 催款策略

| 天数 | 操作 |
|------|------|
| 0 | 支付失败无声 — Apple/Google重试 |
| 3 | Apple/Google重试 #2 |
| 7 | Apple/Google重试 #3 — 显示应用内"更新支付方式"横幅 |
| 10 | 发送推送："您的订阅无法续订 — 点击更新" |
| 14 | 宽限期结束 — 订阅暂停 |
| 15 | 最终应用内消息："重新激活以保持访问权限" |

**宽限期：**
- iOS: 6天（可在App Store Connect配置最多16天）
- Android: 3天（可配置）

最大化宽限期长度 — 每多一天能恢复更多用户。

### RevenueCat集成

RevenueCat自动处理催款。关键设置：
- 启用iOS计费重试 / Android账户冻结
- 配置宽限期为最大允许值
- 使用RevenueCat webhook在每个失败事件触发应用内消息

见 `revenuecat.md` 集成指南。

## 阶段4 — 复购活动

针对过期订阅者（过去30–90天内取消或过期）。

### 复购优惠阶梯

从最柔和的优惠开始；如果没有回应则升级：

```
过期后1周：  "想念您" — 突出离开后新增的新功能
过期后3周：  "回来享受首月30%折扣"
过期后6周：  "3个月50%折扣 — 我们提供的最佳优惠"
过期后12周+：归档 — 转化概率低
```

### 复购渠道

| 渠道 | 方法 |
|------|------|
| 推送通知 | 如果应用仍安装则应用内 |
| 邮件 | 如果收集了邮箱 |
| Apple复购优惠 | StoreKit 2中的原生iOS复购优惠 |
| 付费再营销 | Meta/Google对过期用户列表的再营销 |

### StoreKit 2复购优惠（iOS 18+）

Apple原生支持为过期订阅者提供复购优惠：
- 在App Store Connect → 订阅 → 复购优惠中设置
- 自动在App Store向符合条件的过期用户展示
- 无需除StoreKit 2集成之外的额外代码

- `app-analytics` — 使用Firebase + RevenueCat跟踪上述指标
- `onboarding-optimization` — 修复早期阶段流失以防止试用开始
- `rating-prompt-strategy` — 满意的订阅者是您最好的评价者
