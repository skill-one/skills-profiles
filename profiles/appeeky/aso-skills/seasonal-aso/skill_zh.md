# 季节性ASO

您帮助用户识别并针对与日历事件、节假日和流行时刻相关的季节性关键词机会和商品列表优化。

## 核心原则

**季节性排名具有竞争性和时效性。** 元数据需要1-3天进行索引。在事件前2周计划变更；在高峰期后3-5天恢复。

## 工作流程

### 第1步 — 确定相关事件

1. 检查 `app-marketing-context.md`
2. 询问：**您要针对哪个事件或季节？**
3. 询问：**您的应用做什么？**（以评估关键词的相关性）
4. 确定该事件是否适合 — 并非每个季节性时刻都适用

### 第2步 — 研究季节性关键词

使用Appeeky查找季节性术语的流量：

```bash
GET /v1/keywords/metrics?keywords=christmas+planner,holiday+tracker
GET /v1/keywords/suggestions?term=christmas&country=us
GET /v1/keywords/trending?country=us&days=7
```

**筛选条件：**
- 流量激增（与30天前的基线相比）
- 难度低于60（季节性关键词竞争激烈）
- 与您应用的核心功能相关

### 第3步 — 计划元数据变更

**关键词字段（100字符，iOS）：**
- 用季节性术语替换表现不佳的关键词
- 添加2-4个季节性关键词，同时保留您最佳的常青词
- 移除与您的核心用途无关的季节性术语

**副标题（30字符）：**
- 如果合适，考虑添加季节性钩子：例如 "您的假日计划器" 或 "新年目标追踪器"
- 只有在原副标题不是关键词关键时才更改

**推广文本（170字符 — 无需审核）：**
- 始终为季节性事件更新 — 即时生效，无需审核
- 用于：季节性号召性用语、限时功能亮点、事件关联

**截图：**
- 为前2张截图添加季节性边框或主题
- 使用 `screenshot-optimization` 技能获取创意指导

### 第4步 — 时间节点检查

```
时间线（从事件日期倒计时）：
- [ ] T-14天：研究关键词，简报创意
- [ ] T-10天：编写新元数据 + 推广文本
- [ ] T-7天：提交截图更新（无需审核）
- [ ] T-5天：提交关键词/副标题更新（预留审核时间）
- [ ] T-0：事件高峰期 — 每日监控排名
- [ ] T+3天：恢复元数据至常青版本
- [ ] T+5天：恢复推广文本
```

## 季节性 vs 常青权衡

| 因素 | 季节性 | 常青 |
|------|--------|------|
| 流量 | 峰值时暂时非常高 | 稳定 |
| 竞争 | 峰值时非常高 | 中等 |
| 风险 | 峰值后排名下降 | 持续稳定 |
| 奖励 | 安装量激增 | 持续增长 |

**规则：** 仅替换已表现不佳的常青关键词。切勿因季节性投机而牺牲高排名关键词。

## 流行时刻（非日历）

对于病毒式/流行时刻（新闻事件、病毒内容、应用商店趋势）：
1. 使用 `GET /v1/keywords/trending?country=us&days=3` 查找新兴术语
2. 在24-48小时内行动（流行窗口期短）
3. 仅更新推广文本（即时生效，无需审核）
4. 在趋势消退后恢复（通常3-7天）
