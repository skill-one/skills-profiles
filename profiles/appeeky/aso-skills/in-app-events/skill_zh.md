# 应用内活动

您帮助用户规划、撰写和优化**应用商店应用内活动**——这些活动卡片会出现在搜索、今日标签页和产品页面上，无需付费媒体即可推动下载和再参与。

## 应用内活动是什么

应用内活动是应用商店上的限时内容卡片。它们会出现在：
- **今日标签页**（编辑推荐 + 算法推荐）
- **搜索结果**（与应用结果并列）
- **您的产品页面**
- **个性化推荐**（针对流失用户）

**主要优势**：未近期打开您应用的现有用户会收到活动通知。非用户则将其视为发现内容。

## 活动类型

| 类型 | 适合场景 | 示例 |
|------|----------|------|
| **挑战赛** | 用户生成竞赛 | "30天连续打卡挑战" |
| **竞赛** | 排名或评分比赛 | "每周高分排行榜" |
| **直播活动** | 实时活动 | "专家直播问答" |
| **重大更新** | 重要新功能 | "推出AI教练功能" |
| **首发** | 首次内容发布 | "新系列：晨间习惯" |
| **特别活动** | 季节性或主题性时刻 | "节日收藏集解锁" |

## 活动卡片规格

| 字段 | 限制 | 备注 |
|------|------|------|
| **活动名称** | 30个字符 | 突出显示——注意关键词 |
| **简短描述** | 50个字符 | 卡片上名称下方 |
| **详细描述** | 120个字符 | 展开活动视图时显示 |
| **活动卡片图片** | 2160×1080像素 | 2:1比例，PNG/JPG，无需文字 |
| **徽章** | — | 从上方的6种类型徽章中选择 |
| **持续时间** | 最长31天 | 需要开始和结束时间 |

一次最多可以有**10个活动**处于活动状态或已安排。

## 规划流程

### 第1步 — 活动创意选择

1. 查看 `app-marketing-context.md`
2. 根据应用类别评估活动类型：

| 应用类型 | 最佳活动类型 |
|----------|--------------|
| 游戏 | 挑战赛、竞赛、重大更新 |
| 健身 | 挑战赛、直播活动、重大更新 |
| 生产力 | 重大更新、首发 |
| 社交 / 社区 | 直播活动、挑战赛 |
| 流媒体 / 内容 | 首发活动、特别活动 |
| 实用工具 | 重大更新、特别活动 |

3. 确定主要目标：
   - **再参与** → 使用触发通知的活动（任何类型）
   - **新用户获取** → 专注于今日标签页可见性（挑战赛或竞赛）
   - **功能发布** → 重大更新类型

### 第2步 — 撰写活动文案

**活动名称（30个字符）——规则：**
- 以用户利益或行动开头，而不是应用名称
- 在自然的地方包含相关关键词
- ✅ "30天习惯挑战" | ❌ "AppName挑战2026"

**简短描述（50个字符）：**
- 用一句话回答"对我有什么好处？"
- ✅ "建立连续记录并赢取专属奖励"

**详细描述（120个字符）：**
- 扩展简短描述：是什么、何时、为何加入
- ✅ "加入我们的30天挑战。完成每日习惯，达成连续记录，解锁您的成就徽章。"

### 第3步 — 活动卡片图片

规格：2160×1080像素，2:1比例

**最佳实践：**
- 无需文字（名称/描述作为叠加显示）——但允许简短标语
- 高对比度、醒目的视觉效果，在小缩略图尺寸下也能清晰
- 展示结果或奖励，而不仅仅是应用UI
- 在390×195像素下测试缩略图以验证可读性

### 第4步 — 在App Store Connect中提交

1. App Store Connect → 您的应用 → 应用内活动 → `+`
2. 填写所有必填字段 + 上传图片
3. 提交审核（通常需要24-48小时）
4. 安排开始和结束时间

**在目标开始日期前3-5天提交**，以预留审核时间。

## 优化建议

### 最大化今日标签页位置

苹果的算法优先考虑以下活动：
- **时效性** — 与现实世界时刻相关（节假日、趋势、应用周年纪念）
- **高质量** — 精美的图片、完整的描述
- **参与度** — 推动会话的活动类型（挑战赛 > 更新）
- **一致性** — 定期运行活动的应用会获得更好的循环推荐

**每月至少运行一个活动**以保持算法资格。

### 搜索中的关键词可见性

活动名称和简短描述会被**应用商店搜索算法索引**。

- 在活动名称中自然地包含1-2个目标关键词
- 简短描述可以强化次要关键词
- 使用 `keyword-research` 技能验证要包含的术语

### 再参与通知

已下载但近期未打开您应用的用户会自动收到活动推送通知——无需选择加入。这是应用内活动最具价值的特性。

**将活动名称作为通知主题行**——将其写成作为独立信息具有吸引力的内容。

## 输出格式

### 活动简报

```
📅 活动：[名称 — 30个字符]
   类型： [徽章类型]
   日期： [开始] → [结束]

文案：
  简短： [50个字符]
  详细： [120个字符]

图片方向：
  视觉： [描述场景/概念]
  风格： [摄影 / 插画 / 抽象]
  关键元素： [奖励、行动、结果]

目标：
  主要： [再参与 / 获取用户 / 功能发布]
  KPI： [会话激增、下载量、活动页面浏览量]

提交截止： [日期 — 开始前4天]
```

### 活动日历（每月）

```
第1周： [活动名称] — [类型] — [日期]
第2周： [无活动 / 缓冲]
第3周： [活动名称] — [类型] — [日期]
第4周： [活动名称] — [类型] — [日期]
```

## 常见错误

| 错误 | 修正 |
|------|------|
| 活动名称中包含应用名称 | 以用户利益开头 |
| 通用图片（UI截图） | 视觉展示奖励/结果 |
| 活动持续时间少于7天 | 至少7天以供今日标签页考虑 |
| 当天提交 | 提交4-5天前以供审核 |
| 无循环计划 | 每月运行1+活动以保持持续推荐 |

## 相关技能

- `seasonal-aso` — 将活动时间与关键词季节性高峰对齐
- `screenshot-optimization` — 将相同的视觉最佳实践应用于活动图片
- `app-store-featured` — 活动增加编辑推荐资格
- `retention-optimization` — 跟踪活动带来的再参与提升
