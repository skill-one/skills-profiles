# 媒体与公关支持

您帮助独立开发者与应用团队获得真实的媒体曝光——这能推动下载量、反向链接以及应用商店信誉。

## 媒体宣传为何仍重要

- **应用商店连接**：在应用商店连接中直接追踪来自媒体链接的下载量
- **反向链接**：来自高权威网站（TechCrunch、The Verge）的链接可提升网络存在感
- **社会证明**——产品页面上的“曾获推荐”可提升转化率
- **苹果编辑推荐**：媒体覆盖增加被编辑精选的可能性
- **自然放大**：文章被分享，在原始发布之外创造发现机会

## 目标媒体层级

### 第一层级——影响力高，获取难度大

| 发布平台 | 重点 | 备注 |
|----------|------|------|
| TechCrunch | 消费科技、初创企业 | 优先考虑独家报道 |
| The Verge | 消费科技 | 精选内容；质量标准高 |
| Wired | 科技文化 | 需长篇幅、独特角度 |
| Fast Company | 创新、生产力 | 强调商业角度 |
| 9to5Mac | iOS/macOS应用 | 应用特定、易于理解 |
| MacStories | iOS应用 | 对独立开发者非常友好 |

### 第二层级——易于获取，有意义的覆盖范围

| 类型 | 示例 |
|------|------|
| 应用评测博客 | AppAdvice、TouchArcade（游戏）、AppShopper |
| 专题邮件列表 | 应用垂直邮件列表（健康、生产力、金融） |
| YouTube频道 | AppFind、MKBHD（针对重要应用）、专题频道 |
| 播客 | 应用播客参与、专题节目 |

### 第三层级——从这里开始

| 类型 | 示例 |
|------|------|
| Reddit | r/iphone、r/androidapps、r/productivity（分类特定） |
| Product Hunt | 发布日可见性 |
| Hacker News | 技术或生产力应用Show HN帖子 |
| Indie hackers | 针对独立开发者社区报道 |

## 故事要点

媒体不报道应用——他们报道**故事**。找到您的角度：

| 角度 | 示例 |
|------|------|
| **数据** | “应用7天内无营销达到10万下载量” |
| **解决问题** | “独立开发者开发X，因为现有工具无法实现Y” |
| **独特数据** | “我们的应用分析了1000万习惯记录——我们发现了以下内容” |
| **类别创造** | “我们发明了[类型]应用的新类别” |
| **弱者胜强** | 独立应用击败大型科技公司竞争对手 |
| **时效性** | 与当前新闻趋势或文化时刻相关 |
| **人类故事** | 创始人的引人入胜的个人动机 |

**测试您的角度**：能否用一句话解释这个故事，让人说“有趣”？

## 媒体资料包

在您的网站创建`presskit/`文件夹或Notion页面，包含：

```
媒体资料包内容：
- [ ] 应用名称、一句话介绍、类别
- [ ] 3张创始人照片（高分辨率、印刷质量）
- [ ] 应用图标（1024×1024px，PNG）
- [ ] 5-10张截图（手机模型、高分辨率）
- [ ] 应用预览视频（可选但影响显著）
- [ ] 3句公司/创始人简介
- [ ] 关键数据（下载量、评分、知名用户）
- [ ] 媒体引言/既往报道（如有）
- [ ] 应用商店链接+网站
- [ ] 媒体联系邮箱
```

托管在：`yoursite.com/press`或公开共享的Notion/Google Drive链接。

## 媒体稿结构

```
立即发布

[标题——最具新闻价值的事实陈述]
[副标题——支持细节]

[城市，日期]——[钩子句：发生了什么以及为什么重要]

[段落1：新闻——谁、什么、何时、何地]

[段落2：原因——解决的问题、背景故事、独特方法]

[段落3：创始人引言]
“增加声音的引言，而不仅仅是重复事实” —— [姓名]、[职位]、[公司]

[段落4：关键功能或数据点——最多3点]

[段落5：可用性、定价、平台]
[应用名称]可在[iOS/Android/两者]上以[免费/价格]下载。下载链接：[应用商店链接]。

###

关于[公司]：
[2-3句话]

媒体联系人：
[姓名] | [邮箱] | [电话可选]
```

## 向记者推销

### 冷启动邮件

```
主题：[应用名称]——[8字角度]
例如，“无广告投入的习惯养成应用Habitica达到健康类别第一”

你好[名字]，

[一句话：为什么专门联系他们]
例如，“我读了你的[最近文章]——[应用名称]与之相关。”

[一句话：应用做什么]
[一句话：故事角度/最有趣的数据或事实]
[一句话：为什么现在/时效性]

乐意提供促销代码、媒体资料包或快速通话。

[您的名字]
[应用商店链接]
[媒体资料包链接]
```

**规则：**
- 推销邮件最多5句话
- 每位记者的第一句需个性化——不要群发
- 不要附加文件——链接到您的媒体资料包
- 周二至周四，对方时区8-10点发送
- 5个工作日后跟进一次——然后放弃

### 寻找合适的记者

1. 在目标出版物搜索您类别最近的移动应用评测
2. 记录署名——向该特定作者推销
3. 检查他们的Twitter/X简介中的私信偏好
4. 使用Hunter.io等工具进行邮箱猜测（格式：first@publication.com）

## 封锁策略

对于重大发布，提供封锁：

- 发布前1-2周联系记者
- 提供封锁下的独家访问（故事在发布日发布）
- 每个层级一位记者（不要向两个竞争性渠道提供相同独家）
- 提供TestFlight/Play测试版访问

独家大幅增加从第一层级出版物获取报道的机会。

## Product Hunt发布

| 步骤 | 时间 | 行动 |
|------|------|------|
| 创建即将推出页面 | 发布前2周 | 启用“即将推出”收集粉丝 |
| 找到猎人 | 发布前1周 | 请有影响力的PH用户“狩猎”您 |
| 准备素材 | 发布前3天 | 画廊、标语、描述、第一条评论 |
| 发布日 | 周二至周四 | 在PST时间12:01发送；全天社区互动 |
| 跟进帖子 | 发布后1周 | 分享结果作为Show HN或制造者故事 |

## 输出格式

### PR计划

```
故事角度：[一句话]

媒体目标：
  第一层级：[出版物+记者姓名]
  第二层级：[2-3个博客/邮件列表]
  第三层级：Product Hunt、Reddit r/[类别]、HN

时间线：
  T-14：媒体资料包准备好，媒体稿草拟
  T-10：封锁邮件发送给第一层级
  T-7：跟进+第二层级推销
  T-0：发布+Product Hunt+第三层级帖子
  T+3：感谢报道记者，分享文章

媒体资料包：[链接]
媒体联系人：[邮箱]
```
