# React 最佳实践

## 与 TypeScript 配合使用

在使用 React 时，始终一起加载此技能和 `typescript-best-practices`。TypeScript 模式（先类型开发、区分联合类型、Zod 验证）适用于 React 代码。

## 核心原则：副作用是逃生舱

副作用让你能够“跳出”React 以同步外部系统。**大多数组件逻辑不应使用副作用。** 在编写副作用之前，请问：“有没有不用副作用的方法来做这件事？”

## 决策树

1. **需要响应用户交互？** 使用事件处理器
2. **需要从 props/状态计算值？** 在渲染期间计算
3. **需要缓存昂贵的计算？** 使用 `useMemo`
4. **需要在 prop 变化时重置状态？** 使用 `key` prop
5. **需要与外部系统同步？** 使用带清理的副作用
6. **需要在副作用中编写非 React 代码？** 使用 `useEffectEvent`
7. **需要不会触发渲染的可变值？** 使用 ref

## 何时使用副作用

与 **外部系统** 同步：浏览器 API（WebSocket、IntersectionObserver）、第三方非 React 库、窗口/文档事件监听器、非 React DOM 元素（视频、地图）。

## 何时不应使用副作用

- 派生状态 — 在渲染期间计算
- 昂贵的计算 — 使用 `useMemo`
- 在 prop 变化时重置状态 — 使用 `key` prop
- 响应用户事件 — 使用事件处理器
- 通知父组件状态变化 — 在同一事件处理器中更新
- 副作用链 — 计算派生状态并在一个事件处理器中更新

## Refs

- 用于不会影响渲染的值（计时器 ID、DOM 节点引用）
- 不要在渲染期间读取或写入 `ref.current`；仅在事件处理器和副作用中操作
- 使用 ref 回调（而不是循环中的 `useRef`）用于动态列表
- 使用 `useImperativeHandle` 限制父组件可以访问的内容

## 自定义钩子

- 共享逻辑，而非状态 — 每个调用都获得一个独立的状态实例
- 只有实际调用其他钩子时才命名 `useXxx`；否则使用普通函数
- 避免 生命周期钩子（`useMount`、`useEffectOnce`） — 直接使用 `useEffect` 以便 linter 捕获缺失的依赖
- 聚焦于单一具体用例

## 组件模式

- 受控：父组件拥有状态；非受控：组件拥有状态
- 倾向于使用 `children` 进行组合，而非 prop 钻孔
- 将切换大型组件树的布尔 prop（`isEditing`、`isThread`、`hideAttachments`）视为组合异味；为不同用例优先使用独立的组合组件
- 对于复杂的可重用 UI，优先使用具有提供程序作用域状态/操作的复合组件，而非具有许多可选 prop 的单体组件
- 当 Context 定义了由后代消费的本地接口时，用于作用域组件家族以及真正的全局状态
- 直接渲染 JSX 用于 UI 变化；除非配置是真实的领域数据，否则避免使用配置数组迷你框架
- 当兄弟或外部控件需要访问相同的状态/操作时，提升提供程序边界
- 当需要在状态更新后同步读取 DOM 时使用 `flushSync`

有关代码示例和详细模式的说明，请参阅 `react-patterns.md`。
