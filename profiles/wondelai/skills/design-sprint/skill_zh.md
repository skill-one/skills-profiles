# 设计冲刺框架

一个通过设计、原型制作和与客户一起测试想法来回答关键业务问题的五天流程。该框架由谷歌风险投资公司开发，并被谷歌、Slack、Airbnb以及数百个初创公司使用。

## 核心原则

**将数月的争论、设计和测试压缩到一周内——并在编写任何生产代码之前用真实用户进行测试。** 冲刺用固定的周一至周五时间框架、严格的时限和唯一的决策者取代了无休止的讨论，使得高风险的产品问题能在五天内得到答案，而不是五个月。

## 评分

**目标：10/10。** 通过为每个完整的项目和正确项授予1分（总共10分）来对冲刺计划或执行进行评分。报告分数以及达到10/10所需的缺失项。

1. 决策者承诺全程参与；由一名冲刺主管进行协调。
2. 周一产出目标客户和场景（而不是模糊的“测试产品”）。
3. 使用严格的时限（Crazy 8s在8分钟内，10am-5pm工作日，无开放式会议）。
4. 独立匿名完成解决方案草图——不进行小组头脑风暴。
5. 周三以单一决策者监督投票结束，而不是达成共识。
6. 在构建任何原型之前指定故事板。
7. 原型是具有“黄金标准”保真度的外壳，可在5-15分钟内进行测试，并完成试运行。
8. 通过筛选器招募恰好5名目标用户（6名安排以应对缺勤）。
9. 周五使用五幕访谈；用户在不解释原型的情况下进行解读。
10. 冲刺结束时的复盘将 +/-/~ 模式网格转化为下一步决策。

缺少决策者、真实用户或同日原型的计划最高为6分——这些都是冲刺旨在防止的失败模式。

## 五天冲刺流程

```
周一 → 周二 → 周三 → 周四 → 周五
  绘制      草图     决策      原型     测试
```

**前提条件：** 一个值得一周专注的重大挑战；合适的团队（决策者加上4-7名具有不同专业知识的成员）；五整天（10am-5pm）且无干扰；一个配备白板的专用房间。一名 **冲刺主管** 进行协调、计时和管理精力。

当你担任冲刺主管时，请参阅 [references/facilitation.md](references/facilitation.md) ——它包含完整的协调指南、时限策略和保持停滞或低能量房间高效产出的精力管理技巧。

## 周一：绘制

**目标：** 理解问题并为本周选择目标。

### 上午：从终点开始

- **长期目标：** 写出对“两年后我们希望成为什么样”的乐观答案——例如，“客户每天使用我们的产品。”
- **冲刺问题：** 将障碍和未知项作为问题记录在白板上，整个团队共同贡献——例如，“客户会信任我们处理支付信息吗？”

### 下午：绘制挑战

- **客户旅程图：** 列出参与者（客户类型），然后从左到右绘制5-15步的旅程：“听说产品 → 访问网站 → 注册 → 首次使用 → 普通用户。”
- **请教专家：** 采访具有专业知识的团队成员（CEO、设计、工程、支持、销售）；在白板上记录笔记。
- **如何可能（HMW）：** 将问题改写为机会——“客户不理解定价”→“HMW让定价立即清晰？”每张便利贴一个；投票并组织最佳方案在地图上。

### 结束当天：选择目标

选择地图上的哪个客户和场景进行关注——最大的风险或机会（例如，“注册后的前10分钟”）。**决策者**（具有权威的人）做出最终决定。

**周一产出：** 长期目标、冲刺问题、旅程图、专家见解、整理好的HMW笔记、目标客户和场景。

在协调周一时，请参阅 [references/monday.md](references/monday.md) ——分步练习脚本、HMW示例和目标选择方法。

## 周二：草图

**目标：** 生成解决方案——每个人绘制一个详细的解决方案。

### 上午：闪电演示

- **寻找灵感：** 3分钟演示竞争对手和类似产品（“这是我所发现的，为什么它有趣”）；在白板上记录好点子。借鉴任何行业。
- **分头行动或集中行动：** 如果地图有多个部分，将其分配给不同的人；否则所有人解决同一个关键问题（大多数冲刺集中行动）。

### 下午：四步草图

每个人独立绘制——**不进行小组头脑风暴**。个人工作能产生更好、更多样化的想法。

1. **笔记（20分钟）：** 安静地走动，回顾地图、HMWs和灵感。
2. **想法（20分钟）：** 粗略的涂鸦、思维导图、火柴人——数量比质量更重要。
3. **疯狂8分钟（8分钟）：** 将纸折叠成8个面板，在8分钟内绘制8个变化——迫使你超越第一个想法。
4. **解决方案草图（30-90分钟）：** 一个3面板的故事板，展示客户体验（开始、中间、结束）。使其自我解释，给它一个吸引人的标题，并保持**匿名**。

**周二产出：** 每个人一个详细、匿名、自我解释的解决方案草图。

在执行四步草图之前，请参阅 [references/tuesday.md](references/tuesday.md) ——疯狂8分钟和解决方案草图模板以及向团队展示的实例。

## 周三：决策

**目标：** 批判解决方案并选择最佳方案进行原型制作和测试。

### 上午：便利贴决策

- **艺术博物馆：** 将草图贴在墙上；安静地查看（不交谈）并用点状便利贴标记有趣的部分。
- **热力图回顾：** 每个草图讨论3分钟——协调员叙述，匿名草图者保持沉默；书记员在白板上记录突出的想法。
- **投票：** 每个人对解决方案投一票，并附上一句理由（非约束性）。
- **监督投票：** 决策者获得三个大圆点；他们的决定获胜。

### 下午：竞争或整合

如果有多个草图获胜，选择：**竞争**（不同方法的竞争原型）或 **整合**（将最佳想法整合到一个原型中——更简单，大多数冲刺这样做）。

- **故事板：** 绘制一个10-15面板的漫画，展示测试体验：开场场景（客户如何发现你）→ 你的解决方案在行动中 → 成功结果。保持简单——火柴人、文字、箭头——但要具体说明UI。只需包含足够多的细节，以便周四构建原型。

**周三产出：** 获胜方案和准备原型的故事板。

在运行便利贴决策和故事板时，请参阅 [references/wednesday.md](references/wednesday.md) ——投票协调步骤和面板式故事板模板。

## 周四：原型

**目标：** 一天内构建一个现实的“黄金标准”外壳——你需要一些东西来在周五进行测试。

**心态：** 假装；只原型制作你将测试的内容。目标“黄金标准”保真度——草图保真度太低，无法获得真实反馈，工作代码浪费时间。它应该看起来真实，但不用于真实（外壳、点击式、视频）。

### 分配角色

| 角色 | 责任 |
|------|------|
| **制作人员**（2个或更多） | 构建原型部件（设计、资源） |
| **整合者**（1个） | 将部件整合为最终原型（Keynote、Figma） |
| **文案**（1个） | 所有文案：标题、按钮标签、描述 |
| **收集者**（1-2个） | 收集照片、图标、竞争对手截图 |
| **访谈者**（1个） | 撰写和排练周五的访谈脚本 |
| **冲刺主管** | 在需要时提供帮助，保持精力 |

### 构建原型

**工具：** Figma、Keynote或用于Web/应用的PowerPoint链接幻灯片；视频演示或3D打印模型用于实体产品；角色扮演视频或脚本交互用于服务。

上午：将故事板分成场景并分配给制作人员。下午：整合、对照故事板进行审查、排练完整流程，并与冲刺团队外的人进行试运行。

**原型清单：**
- [ ] 完全符合故事板
- [ ] 看起来足够真实以获得真实反馈
- [ ] 可以在5-15分钟内走一遍
- [ ] 访谈者知道如何展示它
- [ ] 完成试运行

**周四产出：** 真实原型、访谈脚本、准备好的访谈房间。

在构建原型时，请参阅 [references/thursday.md](references/thursday.md) ——工具技术（Keynote/Figma外壳、视频、模型）以在一天内达到“黄金标准”保真度。

## 周五：测试

**目标：** 访谈5位客户；了解哪些有效，哪些无效。

### 设置

访谈房间：安静空间、带有原型的笔记本电脑、录制屏幕和客户脸部的摄像头。观察室：实时视频，整个团队观看并在白板上做笔记。一名 **访谈者** 进行所有五个访谈。

### 五幕访谈

每个客户约45分钟（五幕运行约35分钟加上设置和过渡），每30分钟休息讨论观察结果和调整问题。请参阅 references/friday.md 了解完整的9am-5pm时间表。

| 幕 | 时间 | 要做什么 |
|----|------|----------|
| **1. 友好欢迎** | 5分钟 | 热情问候；解释你在测试原型而不是他们；获得录制许可；鼓励大声思考 |
| **2. 背景问题** | 5分钟 | “告诉我你目前如何处理[问题]” —— 了解心态和当前行为 |
| **3. 介绍原型** | 5分钟 | “这是什么？你觉得它是什么用途？” 不要解释——让他们自己解读 |
| **4. 任务和提示** | 15分钟 | 开放式探索，然后是故事板任务。当卡住时： “下一步你会做什么？” “你在想什么？” 不要帮助——观察他们挣扎 |
| **5. 复盘** | 5分钟 | “你整体感觉如何？” “这是为谁设计的？” “哪些有效？哪些令人困惑？” |

### 五是魔法数字

在3-5个人后会出现模式，5个访谈加休息后效果会减少——并且五个访谈加休息的时间适合一天（请参阅 references/friday.md）。通过筛选器调查招募目标客户，并提供激励（B2B 100-200美元，B2C 50-100美元）。

在冲刺前两周，请参阅 [references/recruiting.md](references/recruiting.md) ——它包含筛选器调查问题、招募渠道、日程安排细节和激励指导，以锁定五个目标用户。

### 记录笔记：模式识别

将观察结果记录在一个网格中，每列一个客户：

| 客户1 | 客户2 | 客户3 | 客户4 | 客户5 |
|-------|-------|-------|-------|-------|
| 笔记 | 笔记 | 笔记 | 笔记 | 笔记 |

标记每个观察结果 **✓**（正面、成功）、**✗**（负面、失败）或 **~**（中性/混合）。在所有五个访谈后，计算每行的标记数，寻找模式——所有5个人是否在同一个问题上挣扎？

### 冲刺结束复盘

整理发现：**✓哪些有效**（每个人都能理解的流程、引起共鸣的信息）、**✗哪些失败**（令人困惑的术语、遗漏步骤、错误假设）、**~混合**（有些人理解，有些人不理解）。然后决定下一步：

- **核心概念得到验证：** 构建，或运行下一个冲刺来处理细节
- **重大问题：** 转折，或再次冲刺来解决问题
- **完全失败：** 重新开始——你节省了数月时间

**周五产出：** 访谈录音、模式笔记、一个清晰的有效和无效列表、下一步决策。

在访谈前，请参阅 [references/friday.md](references/friday.md) ——逐字五幕脚本、笔记模板、更完整的下一步决策表、以及常见的周五错误避免事项。

## 何时运行设计冲刺

**运行时：** 决策高风险、没有时间正常构建和测试、团队陷入无休止的争论、多个解决方案竞争、新产品/功能/重大改版，或需要在进行投资前降低风险。

**不运行时：** 问题和解法显而易见，你只需要执行，团队没有达成共识，或者你无法在一周内获得决策者。

请参阅 [references/case-studies.md](references/case-studies.md) 获取具体案例研究（Slack、Blue Bottle Coffee、Savioke等），当你需要具体领域（如你的领域）的冲刺如何展开的先例时。

## 变体

- **4天冲刺：** 第1天绘制+草图（压缩），第2天决策，第3天原型，第4天测试。
- **远程冲刺：** 相同时间表，使用Miro/FigJam白板和Zoom。请参阅 [references/remote-sprints.md](references/remote-sprints.md) 当团队分散时——它将每个练习调整到数字白板，设置远程时限，并处理基于视频的原型测试。
- **多轮冲刺：** 第1轮选择宽泛问题的方向，第2轮深入选择的解决方案，第3轮完善细节。

## 常见错误

| 错误 | 失败原因 | 修复 |
|------|----------|------|
| **跳过原型制作** | 没有东西可测试 | 总是原型制作，即使简单 |
| **过度设计原型** | 浪费时间在无关紧要的细节上 | 仅外壳，不是工作代码 |
| **用错误用户测试** | 无效反馈 | 筛选目标客户 |
| **向用户解释原型** | 搞垮测试；困惑是数据 | 按照规定运行3-4幕——他们自己解读和挣扎 |
| **没有决策者** | 无法做出决定 | 获得决策者全程参与或不要冲刺 |
| **干扰** | 打破专注 | 保护这一周，无会议/邮件 |

## 快速诊断

审计任何冲刺计划：

| 问题 | 如果没有 | 行动 |
|------|----------|------|
| 我们有全程参与的决策者吗？ | 冲刺会失败 | 获得承诺或推迟 |
| 问题重要吗？ | 浪费时间 | 只在重大挑战上冲刺 |
| 我们能在1天内原型制作吗？ | 不适合冲刺 | 选择更具体的问题 |
| 我们能招募5个目标用户吗？ | 无法正确测试 | 现在开始招募（提前两周） |
| 团队会承诺无干扰吗？ | 无法保持专注 | 获得领导层的支持 |
