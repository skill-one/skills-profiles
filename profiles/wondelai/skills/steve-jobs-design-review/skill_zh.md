# 史蒂夫·乔布斯设计评审

以史蒂夫·乔布斯的方式运行设计和产品评审：从客户体验出发，不断削减直到只剩下必要元素，拒绝将任何不够极致的工作称为完成。

## 核心原则

**“你必须从客户体验开始，然后倒推技术。”** 从客户看到、感受到和完成的事情来评审每个产品——永远不要从功能列表、组织结构图或偶然可用的技术出发。记住标准：“设计不仅仅是看起来和感觉如何。设计是它的工作方式。”

## 评分

**目标：10/10。** 计算产品通过了7个快速诊断行中的多少个，然后映射到0-10：7/7 = 10，6/7 = 9，5/7 = 7，4/7 = 6，3/7 = 4，≤2/7 ≤ 3。等级：**9-10** = 极致，可发布；**5-8** = 需要真正的削减和修复；**≤4** = 未完成，返回演示。没有“足够好”；要说明分数、失败的精确行、以及达到10/10所需的特定削减或修复项。

## 框架

### 1. 简洁是终极的精妙

**核心概念：** 简洁不是缺乏功能——它是被征服的复杂性。不断削减，直到再削减任何东西都会破坏产品目的。

**为什么有效：** 用户必须感知、解析或决定的所有元素都会分散注意力并侵蚀信心。在深入理解问题后幸存的简洁感是不可避免的；通过隐藏东西实现的简洁感是破败的。

**关键洞察：**
- “让事情变得简单需要大量的努力，真正理解潜在挑战并提出优雅的解决方案”
- iPod没有开/关按钮——需求被设计掉了，而不是按钮被隐藏
- 衡量价值步骤：乔布斯要求任何歌曲在三按内完成；原始iDVD提案是一个窗口，拖入视频，点击“烧录”
- 倾向于一个好的默认值而不是设置；每个偏好都是你未能做出的决定
- 如果必须解释，就重新设计——说明是道歉

**评审应用：**

| 上下文 | 应用 | 示例 |
|--------|------|------|
| 功能审核 | 计算核心价值步骤；削减主路径上的任何东西 | 注册 → 三步内获得第一个价值，而不是九步 |
| UI评论 | 删除元素直到屏幕表达一个意图 | 每个屏幕一个主要按钮 |
| 设置评审 | 用有争议的默认值替换选项 | 自动保存始终开启；没有切换 |

**评审提示：**
- “我们能删除什么，还能让这个工作得更好？”
- “它为什么在这里？谁需要它，核心用户需要它吗？”
- “用一句话解释这个屏幕。不能？它是两个屏幕——或者没有。”

**道德边界：** 通过为用户解决复杂性来简化，而不是隐藏必要的控制或成本（定价、隐私、取消）在哪里找不到。

运行简洁性审核时查看 [参考资料/简洁和专注.md](references/simplicity-and-focus.md) — 5步减法方法、价值步骤测量和表面与深度简洁性表。

### 2. 聚焦意味着说不

**核心概念：** “聚焦就是说不。” 决定不做什么和决定做什么同样重要——创新是说“不”到1000件事。

**为什么有效：** 努力分散在许多不错的事情上什么也做不出。砍掉好主意使团队的最好人员和注意力集中在少数重要产品上，并保护产品免受委员会愿望清单的影响。

**关键洞察：**
- 1997年乔布斯削减了数十款苹果产品，形成了一个2×2矩阵：消费者/专业 × 桌面/便携式——聚焦拯救了公司
- 在会议中，团队的十大优先级列表被削减到三个：“我们只能做三个”
- “我对我们没有做的事情和已经做的事情一样自豪”
- 没有最近被砍掉项目的路线图是不聚焦的，它是未经审视的
- 说“不”包括已经发布的特性——删除也是一种特性

**评审应用：**

| 上下文 | 应用 | 示例 |
|--------|------|------|
| 路线图评审 | 强制排序，然后砍掉第3名以下的所有内容 | Q3计划：3个赌注，而不是14个待办事项 |
| 范围蔓延 | 要求每个添加都删除一个 | 新的仪表板小部件 = 退役一个 |
| 产品线 | 合并重叠的SKU/等级 | 每个客户类型一个计划 |

**评审提示：**
- “如果我们这个季度只能发布一件事，哪一件——为什么其余的没有砍掉？”
- “这个产品故意做得不好是什么？”
- “这个周期我们拒绝的是什么？什么都没有？那么我们就接受了平庸。”

**道德边界：** 对范围说不，永远不对证据说不——删除功能是策略；忽视与你的愿景相矛盾的用户痛点是虚荣。

查看 [参考资料/评审协议.md](references/review-protocol.md) 以了解说不的仪式——强制排序到三个的练习、每个添加都删除的规则，以及如何在实时评审中运行不列表。

### 3. 设计是它的工作方式

**核心概念：** 设计不是在最后应用的装饰——它是产品行为架构。评判流程、速度和失败状态，而不仅仅是模型的美丽。

**为什么有效：** 用户不会体验截图；他们会体验延迟、错误、中断和序列。一个美丽的但卡顿、丢失工作或在失败时令人困惑的产品，无论它看起来如何，都是设计糟糕的。

**关键洞察：**
- iPhone键盘通过行为（积极的自动更正）而不是视觉效果取得成功——工程和设计是一个学科
- 评审最慢的时刻，而不是快乐路径：冷启动、空状态、离线、错误恢复
- “它就是工作”是一个设计规范：零配置、零手动、零仪式
- 与功能作斗争的美是装饰；拒绝它
- 延迟是一个设计属性——2秒的等待是设计缺陷，无论它存在于堆栈的哪个位置

**评审应用：**

| 上下文 | 应用 | 示例 |
|--------|------|------|
| 模拟评审 | 要求交互，而不是静态 | 点击状态，而不是幻灯片 |
| 性能 | 在评审中设置体验预算 | 第一屏幕 < 1秒或它失败评审 |
| 失败设计 | 走错误/空/离线路径 | 支付失败 → 用户确切知道下一步是什么 |

**评审提示：**
- “当它失败时会发生什么。”
- “在演示后它感觉如何，而不是演示时？”
- “用户在哪里等待，我们做了什么？”

查看 [参考资料/端到端体验.md](references/end-to-end-experience.md) 当评审行为而不是视觉效果时——日常使用和失败/支持阶段涵盖了如何走慢时刻、错误路径和大多数演示跳过离线状态。

### 4. 掌控整个体验

**核心概念：** 产品是每个触点：发现、购买、开箱或首次运行、引导、日常使用、失败、支持、计费和离开。评审整个产品，而不是孤立的应用程序。

**为什么有效：** 客户将体验视为一个整体。苹果建立了开箱仪式、自己的商店和天才吧，因为一个伟大的设备卖得不好或支持得不好，在记忆中会变成一个糟糕的产品。

**关键洞察：**
- 包装在苹果得到了设计实验室的待遇——第一印象是产品的一部分
- 首次运行是你的开箱：用户在零分钟看到的东西值得英雄屏幕的照顾
- 支持工单、发票和取消流程是产品表面——通常没有人设计它们
- 团队之间每个手交（营销 → 引导 → 产品 → 支持）都是体验接缝显示的地方
- 绘制端到端的旅程；最差的触点设定了感知质量

**评审应用：**

| 上下文 | 应用 | 示例 |
|--------|------|------|
| 发布评审 | 审计每个触点作为一个旅程 | 广告承诺匹配首次运行的现实 |
| 引导 | 将首次会话视为戏剧 | 首要60秒像关键演讲一样排练 |
| 生命周期 | 评审计费、支持和离线 | 取消只需一个屏幕，保持尊严 |

**评审提示：**
- “带我从未听说这个到推荐它——在哪里破裂？”
- “谁设计了发票？错误电子邮件？取消流程？”
- “体验在销售后是否保持承诺？”

**道德边界：** 掌控整个体验也意味着掌控失败——永远不要设计一个精致的开端和一个充满敌意的退出。

查看 [参考资料/端到端体验.md](references/end-to-end-experience.md) 当绘制旅程时——从发现到离线的7阶段触点图、最差触点规则和组织接缝如何产生未经设计表面。

### 5. 演示或不存在

**核心概念：** 评审可工作的工件，而不是规范或幻灯片。具体的演示揭示了文档隐藏的真相；决策是由决策者对真实事物做出反应而做出的。

**为什么有效：** 抽象让每个人想象不同的产品并达成一致。在真实尺寸和真实设备上的演示强迫提供具体的反馈，早期暴露致命缺陷，并通过决策而不是委员会漂移来收敛。

**关键洞察：**
- 苹果的软件文化（科西enda的“创意选择”）：构建一个演示，向决策者展示，获得直接反馈，迭代——这个循环是过程
- iPhone键盘是通过竞争性工作演示的决赛选出的，而不是需求文档
- 在目标设备上以目标数据规模评审——在投影仪上判断手机UI的谎言
- 首先原型化最危险的时刻；演示容易的80%证明不了什么
- “真正的艺术家会发布”：演示是为了强迫决策，而不是延迟它们

**评审应用：**

| 上下文 | 应用 | 示例 |
|--------|------|------|
| 设计评审 | 禁止仅幻灯片评审 | Figma原型或构建，而不是静态包 |
| 竞争性想法 | 运行演示决赛，选择一个 | 两个导航模型构建，一个裁决 |
| 利益相关者对齐 | 每周向决策者演示 | 30分钟演示取代3个状态文档 |

**评审提示：**
- “不要告诉我——给我看。在设备上。”
- “这两个演示中哪一个赢了？选一个；我们不会发布两者的妥协。”
- “哪个风险最大的假设？哪里有测试它的演示？”

**道德边界：** 演示必须显示诚实状态——一个隐藏已知错误的演示是一个带有UI的谎言。

查看 [参考资料/演示文化.md](references/demo-culture.md) 当设置驱动演示评审时——创意选择循环、如何运行演示决赛、决策者角色和诚实演示规则。

### 6. 品味和围栏后面

**核心概念：** 一个伟大的木匠不会在柜子的后面使用胶合板，即使没有人会看到它。在看不见的表面投入的关怀——以及应用这些品味的人——才是质量真正是什么。

**为什么有效：** 用户会下意识地感觉到工艺：对齐的像素、连贯的文本、优雅的边缘情况加起来就是信任。削减角落的团队训练自己到处削减角落；卓越是由标准强制的习惯，而不是检查。

**关键洞察：**
- 原始Mac团队在机箱内签名；乔布斯让工程师重新设计电路板布局，为了没有客户会看到的美丽
- “技术本身是不够的”——产品存在于技术和自由艺术品的交叉点
- 审计围栏后面的表面：空状态、错误文本、设置页面、加载屏幕、电子邮件
- “做一个质量尺”——A级球员互相提升；容忍平庸会累积
- 品味是可训练的：研究伟大的产品，说明为什么它们很伟大，无情地应用标准

**评审应用：**

| 上下文 | 应用 | 示例 |
|--------|------|------|
| 详细审核 | 评审没有人演示的屏幕 | 404页面保持主页标准 |
| 文本评审 | 大声朗读每个字符串 | 错误消息听起来像人，具体 |
| 团队标准 | 批评最佳工作，而不是平均水平 | “这是你最好的一次？” |

查看 [参考资料/案例研究.md](references/case-studies.md) 以了解标准实际操作的示例——原始Mac电路板为看不见的美丽重新设计、iMac的有争议的减法，以及MobileMe和天线门失败评审和每个对评审者教了什么。

### 7. 运行评审

**核心概念：** 结构化评审：像客户一样冷体验产品，命名必须做的事情，根据原则1-6进行审核，然后交付一个二进制裁决——极致或未完成——以及具体的削减清单和修复清单。

**为什么有效：** 评审因模糊和礼貌而失败。固定的演示顺序、残酷的具体性和二进制裁决防止“足够好”发货，同时给团队一个精确的路径到10/10。产品根据其承诺进行评判——“这个产品应该做什么？那么为什么它不做那个？”

**关键洞察：**
- 在会议前冷体验产品——第一印象无法重跑
- 以承诺开头：说明产品声称的，然后只测试那个
- 反馈必须是具体和可操作的：“这令人困惑”失败评审——说是什么，在哪里，为什么，以及修复方向
- 结束二进制：可发布或一个排名的修复列表；永远不要“稍微润色一下”
- 一个决策者拥有裁决；输入广泛，决策狭窄

始终以以下格式输出评审：

```
# 设计评审：[产品/功能]
**裁决：** 极致 / 未完成（分数 X/10）
**必须做的事：** [这个必须做什么]
**是否履行承诺？** [是/否——证据]
**削减清单：** [什么要删除]
**修复清单：** [排名，具体，带有修复方向]
**围栏后面：** [失败的未看到表面]
```

查看 [参考资料/评审协议.md](references/review-protocol.md) 当运行实际的评审会话时——计时5步议程、修复项具体性测试、坦诚规则（对工作残酷，对人得体）、评审频率，以及如何调整协议以用于单人或异步评审。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|-----------|------|
| 只评审美学 | 设计是它的工作方式；漂亮但笨拙仍然让用户失败 | 走流程、延迟和失败状态 |
| 通过添加来修复问题 | 每个添加都会分散注意力并滋生更多复杂性 | 首先削减；添加需要删除 |
| 一致裁决 | 委员会将想法平均成浆糊 | 一个决策者，广泛输入，狭窄决策 |
| 评审规范和幻灯片 | 抽象隐藏了致命缺陷；每个人想象不同的产品 | 要求在真实设备上运行工作演示 |
| “足够好”裁决 | 平庸会累积成品牌损害 | 二进制：极致或未完成 |
| 跳过围栏后面 | 用户会感觉到胶合板；团队学会到处削减角落 | 审计空/错误/设置/电子邮件状态 |
| 拿着残酷的伪装 | 害怕演示和坦诚，杀死反馈循环 | 对工作残酷，对人得体 |

## 快速诊断

| 问题 | 如果没有 | 操作 |
|------|---------|------|
| 你能用一句话说明这个产品必须做什么吗？ | 没有焦点——一切都是优先级 | 写它；删除不服务于它的东西 |
| 新用户在≤3步内达到核心价值吗？ | 复杂性未被征服 | 绘制价值步骤；删除，不要重新排序 |
| 评审者像客户一样冷体验它吗？ | 你评审了团队的叙述，而不是产品 | 在会议前使用它，没有演示 |
| 是否有在真实设备上的工作演示？ | 你在批准一个想象中的产品 | 推迟直到有演示 |
| 这个周期是否删除了任何东西？ | 路线图正在累积，而不是聚焦 | 每个评审都添加一个删除列表 |
| 错误、空和边缘状态是否与英雄屏幕质量匹配？ | 围栏后面是胶合板 | 审计和修复未看到的表面 |
| 团队是否自豪地每天使用它并签名？ | 标准是“可接受的”，而不是“极致” | 持有二进制裁决，直到自豪感是真实的 |

## 关于作者

史蒂夫·乔布斯（1955-2011）共同创立了苹果，并领导它创造了Mac、iPod、iPhone和iPad，通过设计主导的产品开发建立了世界上最有价值的公司。这项技能提炼了他的记录在案的设计评审实践和标准，来自沃尔特·艾萨克森的授权传记、肯·塞格尔的《极度简单》，以及肯·科西enda的《创意选择》。
