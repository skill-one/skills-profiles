# 用户体验启发式框架

实用的可用性原则，用于评估和改进用户界面。用户不阅读，他们浏览；他们不做最优选择，他们满足；他们不弄清楚事情如何运作，他们勉强应付。

## 核心原则

**“别让我思考”** — 每一页都应该是显而易见的。如果某件事需要思考，那就是可用性问题。用户的耐心和认知带宽有限，因此设计要适应上述的浏览、满足和勉强应付的行为。

## 评分

**目标：10/10。** 审计界面，根据以下严重性量表对每个问题进行评分，然后根据快速诊断结果对界面进行评分：从10分开始，每有一个失败的诊断行就减去分数，并根据其触发的最严重严重性加权（灾难性/主要行约减2分，次要/装饰性减1分）。等级：**9-10** = 没有严重性3+的问题且≤1个失败的诊断行；**6-8** = 一些主要问题或几个失败的行；**3-5** = 一个灾难性问题或许多失败的行；**≤2** = 核心任务被阻塞。始终说明当前分数、最高严重性的问题以及达到10/10所需的特定修复方案。

## Krug的可用性原则

第1-3条是Krug的三大可用性定律；第4条，树干测试，是他的导航定向检查。

### 1. 别让我思考

**核心概念：** 用户脑海中出现的每个问号都会增加认知负荷并分散他们对任务的注意力。

**为什么有效：** 用户有使命在身——他们不想琢磨标签或解码巧妙的营销语言。思考越少，他们完成任务的几率就越大。

**关键洞察：**
- 巧妙的名称总是输给清晰的名称
- 营销术语制造摩擦；平实的语言消除摩擦
- 陌生的类别迫使用户停下来理解
- 模糊的链接和按钮导致犹豫

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| **导航标签** | 直观名称 | “获取路线”而不是“计算目的地路线” |
| **行动召唤（CTA）** | 用户理解的行动动词 | “登录”而不是“访问您的账户门户” |
| **错误状态** | 告诉用户下一步该做什么 | “检查您的电子邮件格式”而不是“验证错误” |

**文案模式：**
- 行动导向按钮：动词+名词（“创建账户”，“下载报告”）
- 避免术语：“保存”而不是“持久化”，“删除”而不是“解除关联”
- 如果标签需要解释，简化标签

**道德边界：** 清晰性应服务于用户——永远不要用平实的语言作为掩盖不利条款的面具。

参见：[参考资料/krug-principles.md](references/krug-principles.md)，当您需要完整的Krug方法时——浏览/满足/勉强应付心理学、善意储备、主页和标语指导，以及0美元可用性测试协议（多少用户，测试脚本）。

### 2. 点击次数无关紧要

**核心概念：** 传说“用户在点击3次后离开”。实际上，如果每次点击都毫不费力、显而易见且能建立信心，用户并不介意点击次数。

**为什么有效：** 每次点击的认知努力比点击次数更重要。用户在失去信心时放弃，而不是在点击次数耗尽时放弃。

**关键洞察：**
- 每次点击都应该毫不费力、显而易见且能建立信心
- 无意识的3次点击比需要深思熟虑的1次点击更好
- 浅层导航与清晰的标签比深层导航与模糊的标签更好

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| **结账流程** | 使每一步都显而易见 | 清晰的步骤指示符和描述性标签 |
| **设置** | 清晰的类别优于扁平列表 | “账户 > 安全 > 修改密码”（3次自信的点击） |
| **引导** | 小而清晰的步骤 | 带有每一步一个清晰操作的向导 |

**文案模式：**
- 进度指示器：“第2步，共4步：运输详情”
- 每一步的确认：“很好，您的电子邮件已验证。现在让我们设置您的个人资料。”
- 清晰的链接文本：“查看所有跑步鞋”而不是“点击这里”

**道德边界：** 永远不要用额外的步骤来隐藏取消流程——每个点击都应该让用户更接近他们的目标，而不是远离它。

### 3. 去掉一半的文字

**核心概念：** 每页删除一半的文字，然后再删除剩下的一半。简洁使有用内容更加突出，并尊重用户的时间。

**关键洞察：**
- 幸福的谈话（“欢迎来到我们的网站！”）浪费空间
- 没人阅读的说明应该被删除
- “请”和“友好”和礼貌的废话增加噪音
- 较短的页面意味着较少的滚动和较快的浏览

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| **着陆页** | 删除欢迎文案，直接展示价值 | 删除“欢迎到……”段落 |
| **错误消息** | 陈述问题和修复，不再更多 | “密码太短（最小8个字符）” |
| **空状态** | 行动导向，最小化 | “没有结果。尝试不同的搜索。” |

**文案模式：**
- 之前：“请友好地注意，您需要输入密码才能继续到下一步。” → 之后：“输入密码以继续。”
- 之前：“我们已收到您的消息，并将尽快回复。” → 之后：“消息已发送。我们将在24小时内回复。”

**道德边界：** 简洁不得省略关键信息——简洁的披露对于定价、条款和数据使用是用户权利。

### 4. 树干测试

**核心概念：** 将用户放在任何随机页面（就像从汽车树干中随机释放一样）——他们应该立即回答六个定向问题：这是什么网站？这是哪一页？有哪些主要部分？这里有哪些选项？我在层次结构中的位置？搜索在哪里？

**为什么有效：** 良好的导航提供持续的定向。无法告诉他们自己位置的用戶会感到迷失并离开。

将其作为导航检查应用：页面标题必须与用户点击的链接匹配，“您在这里”指示器（突出显示的导航项、粗体面包屑）必须存在，并且部分标题必须定向（“您的账户 > 付款”而不是仅仅“设置”）。

**道德边界：** 导航标签必须诚实地代表网站结构——永远不要用误导性的标签来引导用户进入营销页面。

参见：[参考资料/krug-principles.md](references/krug-principles.md)，在运行树干测试或设计导航时——它将每个问题映射到页面上的答案元素，以及面包屑和永久导航规则。

## Nielsen的10个可用性启发式

### 1. 系统状态的可见性
通过及时反馈让用户保持知情。每个操作都需要确认——上传进度条、提交确认、加载时的骨架屏幕。无声的失败会破坏信任。文案模式：“正在保存……”→“已保存”。

### 2. 系统与现实世界的匹配
使用用户的语言：“登录”而不是“身份验证”，“搜索”而不是“查询”。遵循现实世界的隐喻（垃圾桶、购物车）和自然排序（街道→城市→州→邮政编码）。

### 3. 用户控制和自由
提供清晰的“紧急出口”。撤消比“您确定吗？”对话框更好——用户会点击而不阅读确认。每个流程都需要取消/退出，并且后退按钮绝不能破坏。

### 4. 一致性和标准
整个过程中相同的词语、样式和行为都表示相同的意思。内部一致性（您的应用程序）加上外部一致性（平台约定：标志左上角，搜索右上角）。每个概念一个术语——到处都是“项目”，永远不会与“工作区”混合。

### 5. 预防错误
在问题发生之前预防问题：约束输入（日期选择器而不是文本字段）、自动完成、合理的默认值、“未保存的更改”警告。失误（意外错误操作）和错误（错误意图）需要不同的预防。

### 6. 识别而非记忆
最小化记忆负荷——显示选项，而不是要求记忆。面包屑、最近的搜索、预填字段、带有解码值的下拉菜单。工作记忆可以容纳大约7个项目；识别比记忆容易得多。

### 7. 灵活性和使用效率
服务新手和专家：键盘快捷键、批量操作、保存的搜索、命令面板（Cmd+K）。渐进式披露使初学者保持简单，同时让专家访问全部功能。

### 8. 美学和极简设计
每个元素都必须有其存在的理由——当所有东西都在呼喊注意力时，没有任何东西会突出。现在显示什么，隐藏什么。每页一个主要CTA。

### 9. 帮助用户识别、诊断和恢复错误
错误消息需要三个部分：发生了什么、为什么、如何修复。平实的语言（“连接失败”而不是“ECONNREFUSED”）、具体的（“密码必须为8个以上字符”而不是“无效”）、永远不要责怪用户，保留他们的输入。

### 10. 帮助和文档
帮助应该是可搜索的、任务导向的（“如何……”而不是技术参考），并且是上下文的（工具提示、内联提示、引导式游览）。

参见：[参考资料/nielsen-heuristics.md](references/nielsen-heuristics.md)，在针对特定启发式进行审计时——它将每个10个扩展为良好实现/常见违规/严重性表格，带有文案模式和道德边界。

## 严重性评分量表

对审计中发现的每个问题进行评分：

| 严重性 | 评分 | 描述 | 优先级 |
|------|------|------|------|
| **0** | 不是问题 | 不同意，不是可用性问题 | 忽略 |
| **1** | 装饰性 | 轻微烦恼，低影响 | 如果有时间修复 |
| **2** | 次要 | 导致延迟或沮丧 | 安排修复 |
| **3** | 主要 | 显著任务失败 | 尽快修复 |
| **4** | 灾难性 | 阻止任务完成 | 立即修复 |

权衡三个因素：**频率**（它发生的频率）、**影响**（它发生时的严重性）、**持续性**（一次性或持续）。

参见：[参考资料/audit-template.md](references/audit-template.md)，在运行完整的启发式评估时——一个结构化的每屏模板，捕获问题、严重性和建议修复，以一致的格式。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|------|------|
| **神秘肉导航** | 没有标签的图标迫使猜测 | 在图标旁边添加文本标签 |
| **太多选择** | 决策瘫痪减慢用户速度 | 减少到7加减2个项目 |
| **没有“您在这里”指示器** | 用户在层次结构中感到迷失 | 在导航和面包屑中突出当前部分 |
| **没有内联验证** | 提交、错误、滚动周期令人沮丧 | 在模糊时进行验证，并带有具体消息 |
| **不明确的必填字段** | 用户对什么是必需的感到困惑 | 标记可选字段，而不是必填字段 |
| **文本墙** | 没人阅读密集的段落 | 用标题、项目符号、空白分隔 |
| **标签中的术语** | 用户不说你的内部语言 | 用户测试所有标签，使用平实的语言 |
| **没有加载指示器** | 用户认为系统已损坏 | 显示旋转器、进度条或骨架屏幕 |
| **微小的点击目标** | 移动用户不断误点击 | 最小44x44像素触摸目标 |
| **仅悬停信息** | 移动和键盘用户错过了它 | 不要将关键信息隐藏在悬停后面 |
| **没有撤消** | 用户害怕采取任何行动 | 为所有非破坏性行动提供撤消 |
| **糟糕的错误消息** | “无效输入”告诉用户什么也没做 | 解释什么错了以及如何修复它 |
| **低对比度文本** | 许多用户无法阅读 | WCAG AA最低（4.5:1对比度） |
| **不一致的导航位置** | 用户找不到导航 | 固定位置，每页都在相同的地方 |
| **损坏的后退按钮** | 违反浏览器契约 | 永远不要劫持或破坏浏览器历史记录 |

参见：[参考资料/wcag-checklist.md](references/wcag-checklist.md)，在审计可访问性（对比度、键盘、屏幕阅读器、焦点）时——一个完整的WCAG 2.1 AA检查表，带有测试工具。参见[参考资料/cultural-ux.md](references/cultural-ux.md)，在设计全球受众时——从左到右布局、颜色含义、表单/名称/日期约定和本地化陷阱。

## 快速诊断

| 问题 | 如果没有 | 操作 |
|------|------|------|
| 我能立即告诉我这是什么网站/页面吗？ | 用户迷失了 | 添加清晰的标志、页面标题、面包屑 |
| 主要操作明显吗？ | 用户不知道该做什么 | 视觉层次结构、单个主要CTA |
| 导航清晰吗？ | 用户找不到路 | 应用树干测试，添加“您在这里”指示器 |
| 我能找到搜索吗？ | 目标驱动用户被阻塞 | 头部可见的搜索框 |
| 系统显示正在发生什么？ | 用户失去信任并重新点击 | 加载状态、确认、进度 |
| 错误消息有帮助吗？ | 用户卡住了 | 平实的语言和具体的修复 |
| 用户可以撤消或后退吗？ | 用户害怕采取行动 | 撤消、取消和后退选项无处不在 |
| 它可以在没有悬停的情况下工作吗？ | 移动/键盘用户被排除在外 | 悬停交互的可见替代方案 |
| 所有交互元素都有标签吗？ | 用户猜测图标 | 文本标签或描述性工具提示 |
| 任何东西让我停下来思考“嗯？”吗？ | 认知负荷过高 | 简化——如果它需要解释，重新设计它 |

## 启发式冲突

启发式有时会相互矛盾。当它们这样做时：
- 简洁性 vs. 灵活性：使用渐进式披露
- 一致性 vs. 上下文：一致的模式，上下文突出显示
- 效率 vs. 错误预防：优先考虑撤消而不是确认对话框
- 可发现性 vs. 极简主义：主要操作可见，次要隐藏

参见：[参考资料/heuristic-conflicts.md](references/heuristic-conflicts.md)，当两个启发式向相反方向拉扯，而上述四条规则无法解决时——解决框架，带有已处理的权衡示例。

## 暗黑模式识别

暗黑模式故意违反启发式来操纵用户：被迫连续（难以取消）、蟑螂旅馆（容易进，难以出）、确认羞辱（基于罪恶感的选项）、隐藏成本（结账时的意外费用）。

参见：[参考资料/dark-patterns.md](references/dark-patterns.md)，当您怀疑设计操纵用户而不是服务用户时——完整的分类法、道德替代方案和相关法规。

## 何时使用每种方法

| 方法 | 何时 | 时间 | 发现 |
|------|------|------|------|
| 启发式评估 | 之前用户测试 | 1-2小时 | 主要违规 |
| 用户测试 | 启发式修复之后 | 2-4小时 | 真实行为 |
| A/B测试 | 优化时 | 天数-周 | 统计验证 |
| 分析审查 | 持续 | 30分钟 | 模式和问题 |

## 关于作者

**Steve Krug**是一位可用性顾问，他的*“别让我思考”*（2000年，2014年修订版）是阅读量最广的关于网页可用性的书。他证明可用性测试不需要实验室或大预算——只是观察几个真实用户尝试完成任务。

**Jakob Nielsen，博士**是Nielsen Norman Group的联合创始人，作者是10个可用性启发式（1994年），仍然是全球最常用的启发式评估框架。*《纽约时报》*称他为“网页可用性大师”。
