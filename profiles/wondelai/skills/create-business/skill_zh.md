# 创建企业

将一个原始想法转化为一个你可以在每个方面进行辩护的企业：它为谁服务、它做什么工作、它为什么与众不同、它为什么能赢、它的成本是多少，以及为什么任何人会为此付费。这段旅程按顺序运行十个阶段，随着证据的积累而循环。它是交互式的——代理在每次决策之前都会询问——并且是可恢复的：所有状态都存储在 `docs/` 中，因此你可以在不同会话中停止和重新开始。顺序很重要：需求优先于构建，战略优先于规模，价格优先于产品。

## 核心原则

**在消耗你的跑道之前先获得你的证据：需求优先于构建，战略优先于规模，价格优先于产品。** 你可能在一周内就对你的产品感到错误，或者可能在一年后对你的企业感到错误——选择一周。这项技能按顺序排列阶段，在每次决策点提出问题，并将你的决定记录在 `docs/` 中。构成技能承载着方法——调用它们而不是即兴创作它们的框架。

## 运营规则

1. **首先恢复。** 在做任何事之前，阅读 `docs/CREATE-BUSINESS-PLAN.md` 和旅程地图中的每个产出物。如果存在跟踪器，请用 3-5 行总结旅程状态并询问要进入哪个阶段。当用户确认入口点时完成。带有跟踪器的旅程是恢复的，永远不会重新启动。
2. **仅在第一次运行时进行信息输入。** 没有跟踪器：运行下面的信息输入，然后创建 `docs/CREATE-BUSINESS-PLAN.md`，将每个阶段的状态设置为 `pending | in-progress | awaiting-evidence | done | deferred: reason | skipped: reason`。当跟踪器存在并且用户确认了阶段计划时完成。
3. **阶段入口。** 宣布：阶段做什么，它强迫的决策，它产生的产出物，粗略的工作量。提供继续 / 跳过 / 延迟——标记为 GATE 的阶段可以延迟，但永远不能跳过。在继续时将阶段标记为 `in-progress`。当用户选择时完成。
4. **技能调用和回退。** 加载阶段的技能并使用它：每个阶段的调用行命名了技能的 slug——使用该技能来运行阶段。如果它不可用，提供：`npx skills add wondelai/skills/<slug> --global`。如果用户拒绝，从它的简要信息运行阶段——最低可行的方案。说明你处于什么模式。
5. **阶段内的决策。** 询问“与用户一起决策”下的每个问题——具有具体选项和你的建议。在跟踪器的关键决策中记录选择。无声做出的决策是缺陷。
6. **阶段退出。** 在写入之前，呈现草稿产出物内容以供批准。在批准后：写入或扩展 `docs/` 文件，更新跟踪器（状态、关键决策、下一步行动）。当文件写入并且阶段行显示 `done` 时完成。
7. **产出物纪律。** 写作之前先阅读；如果文件不存在，则创建它，否则扩展——添加或更新你的部分，保留其他人的部分。文件在 `docs/` 中是大写的。每个建议都作为一个复选框或一个带有所有者和优先级的表格行出现。在创建 `docs/` 文件时，请参阅 [references/artifact-templates.md](references/artifact-templates.md)——从完整骨架（所有部分标题）创建它，然后填写你的阶段名称的部分。
8. **代理准备和处理；只有人类与客户交谈。** 起草访谈指南并评分访谈记录，然后暂停状态 `awaiting-evidence`，直到用户返回笔记。永远不要模拟客户——角色扮演的访谈证实了你希望为真的是什么。

## 信息输入

在创建跟踪器之前询问以下问题（跳过任何已回答的问题）：

1. 原始想法是什么，用一到两句话概括？ （为阶段 1 中的工作重构提供种子）
2. 你想象中的客户是谁，他们今天如何解决这个问题？ （为竞争替代方案提供输入；紧密的细分市场可以加速阶段 7 和 10）
3. 你有什么客户访问权限——列表、社区、暖介绍？ （为阶段 2-4 开门；没有访问权限，人类访谈阶段将停滞）
4. 已经存在哪些证据——过去的访谈、等待名单、销售、原型？ （让我们快速跟踪或跳过已经完成的发现）
5. 这是 B2B 还是 B2C——如果是 B2B，是销售驱动还是自助服务？ 它是市场产品还是网络产品？ （路由可选的预测收入和冷启动问题）
6. 你的跑道和截止日期是什么？ （设置阶段深度，以及是否要延迟战略阶段）
7. 是否已经构建了任何产品？ （如果是，这可能不是正确的旅程——路由到增长业务或改进业务）

阶段跳过启发式方法：当 CUSTOMER.md 中存在一个具有三个维度的已验证工作声明时，跳过阶段 1；当已经测试了 5 个以上目标用户的工作原型时，跳过阶段 3；对于明显差异化的利基市场，延迟阶段 6，直到内核设置完成；直到阶段 2 返回真实承诺，延迟阶段 5-10——在没有验证的需求上进行战略规划。然后从模板创建 `docs/CREATE-BUSINESS-PLAN.md`，状态每个阶段，并确认计划。当 `docs/CREATE-BUSINESS-PLAN.md` 存在并且每个阶段都被状态化，并且用户确认了计划时完成。

## 阶段

### 阶段 1 — 找到真实的工作（需要完成的任务）

**目的：** 将原始想法重新定义为客户试图完成的进展，以便即使第一个解决方案死亡，企业也能生存。

**简要信息（回退）：** 工作是在上下文中进行的进展，而不是目标或任务——将其写为 `当 [情况]，我想 [动机]，以便我可以 [结果]`，与解决方案无关。每个工作都有功能、情感和社会维度；差异化的产品通常存在于后两个。真实的竞争包括替代方案和非消费——命名你必须击败的竞争对手。

**调用：** 使用 `需要完成的任务` 技能，并提供原始想法和来自信息输入的客户猜测。要求一个 When/I-want-to/so-I-can 工作声明，所有三个维度，以及包括非消费的完整竞争替代方案集。

**与用户一起决策：** 哪个工作声明是真实的，以及你首先必须击败哪个竞争对手。建议最紧密的声明，但仍然命名一个情感或社会维度。

**产出物：** 创建 docs/CUSTOMER.md，包含 `## 工作声明`、`## 工作维度` 和 `## 竞争替代方案`。更新跟踪器。

**完成时：** CUSTOMER.md 包含一个与解决方案无关的工作声明、所有三个维度以及带有要击败的竞争对手的竞争集。

### 阶段 2 — 通过真实对话验证工作（母测试）—— GATE

**目的：** 用事实代替意见——验证阶段 1 中的工作是真实的、痛苦的，并且值得付费解决。阶段 5-10 将保持锁定，直到此阶段返回继续裁决。

**简要信息（回退）：** 三条规则——谈论他们的生活而不是你的想法；询问过去的具体情况而不是假设；说得少（他们说话 80%）。赞美不是数据；只有承诺（时间、声誉、金钱）才 counts。一个好问题可能会摧毁想象中的业务。

**调用：** 使用 `母测试` 技能，并提供来自 docs/CUSTOMER.md 的工作声明和竞争替代方案。要求（a）一个遵守三条规则的 10-12 个问题访谈指南，然后稍后（b）一个评分访谈记录，该记录标记了引导问题和僵尸引导。将指南交给用户，并暂停状态 `awaiting-evidence`；将批准的指南记录在 docs/CUSTOMER.md 下 `## 访谈证据` 的 `### 访谈指南` 子部分，以便它在暂停期间幸存。

**与用户一起决策（返回时）：** 证据是否证实了工作？继续（3 个以上具体承诺）、修改工作声明（循环到阶段 1）或停止（没有痛苦发现——一个便宜的胜利）。

**产出物：** 扩展 docs/CUSTOMER.md：添加 `## 访谈证据`（日期 | 谁 | 事实 | 承诺）和 `## 验证裁决`，记录决策和推理。更新跟踪器。

**完成时：** CUSTOMER.md 包含 5 个以上证据行，裁决已记录，用户选择了继续 / 修改 / 停止，并且在继续的情况下——阶段 5-10 被解锁。

### 阶段 3 — 在五天内测试风险最高的假设（设计冲刺）

**目的：** 在投入数月之前，用五个真实客户反应在一周内证明概念中最危险的部分。

**简要信息（回退）：** 五天——映射、草图、决定、原型、测试。选择一个目标时刻（最危险的步骤）；单独草图（不进行小组头脑风暴）；一个决策者打破僵局；构建一个外壳，而不是工作代码；用正好五个目标客户进行测试。在周五，闭嘴让他们挣扎——解释原型会使测试无效。

**调用：** 使用 `设计冲刺` 技能，并提供验证后的工作和最危险的开放问题。要求周一的地图，带有冲刺问题和一个目标时刻，以及一个不解释原型的周五五幕访谈脚本。将招募简报交给用户，并暂停 `awaiting-evidence` 以便进行真实会话；将批准的脚本和简报记录在 docs/EXPERIMENTS.md 下的冲刺卡片中，以便它们在暂停期间幸存。

**与用户一起决策：** 本周要测试哪个单一假设，以及谁是决策者。返回时：概念是否生存——构建、修复或离开（一个一周的胜利）。

**产出物：** 创建 docs/EXPERIMENTS.md，包含 `## 实验卡片`（EXP-001，类型冲刺，预先承诺的指标，决策规则，结果和裁决）和 `## 实验待办事项列表`。更新跟踪器。

**完成时：** EXPERIMENTS.md 包含带有来自五个会话的记录裁决的冲刺卡片，并且用户选择了构建 / 修复 / 离开。

### 阶段 4 — 运行循环并选择最小的 MVP（精简创业）

**目的：** 将发现转化为一个可重复的验证学习引擎，并交付可以测试风险最高的信仰跳跃的最小 MVP。

**简要信息（回退）：** 向后规划构建-衡量-学习：决定要学习什么，然后是证明它的指标，然后是最小构建。MVP 类型——烟雾测试、 concierge、奥兹巫师——每个测试不同的信仰跳跃假设；首先测试最危险的。衡量可操作的指标，而不是虚荣指标。在运行之前设置转向或坚持标准。选择一个增长引擎：粘性、病毒或付费。

**调用：** 使用 `精简创业` 技能，并提供功能愿望清单和生存的概念。要求单个风险最高的信仰跳跃假设、一个带有构建-衡量-学习实验卡片的 MVP 类型，以及预先设定的转向/坚持阈值。

**与用户一起决策：** 哪个 MVP 类型、哪个单一增长引擎首先进行优化，以及预先设定的转向/坚持阈值。建议粘性引擎（留存率高于流失率）而不是付费获取。

**产出物：** 创建 docs/PRODUCT.md，包含 `## 视野` 和 `## MVP 定义`；扩展 docs/EXPERIMENTS.md，添加新卡片及其决策规则。更新跟踪器。

**完成时：** PRODUCT.md 定义了 MVP 和它排除的内容，EXPERIMENTS.md 包含带有预先承诺的阈值和所选引擎的卡片，并且用户批准了 MVP 范围。

### 阶段 5 — 将雄心转化为战略内核（好战略-坏战略）

**目的：** 用一个真正的战略代替一个目标列表——一个诊断、指导政策以及连贯的行动。

**简要信息（回退）：** 目标命名雄心；战略解释在障碍面前你如何获胜。内核：一个命名单个关键挑战的诊断；一个指导政策是一个真正的选择，有赢家（如果竞争对手可以粘贴它，它就是一个陈词滥调）；连贯的行动，每个行动都有一个所有者和日期。通过四个标志检测坏战略——废话、回避挑战、目标作为战略、狗食般的客观列表。集中力量在一个转向点上。

**调用：** 使用 `好战略-坏战略` 技能，并提供验证后的需求证据和任何一页计划。要求一个四标志审计，然后是一个内核——一个段落诊断、一个指导政策明确排除整个行动类别，三个连贯的行动带有所有者——以及一个明确的无列表。

**与用户一起决策：** 单个关键挑战是什么（诊断），以及指导政策明确拒绝做什么？建议集中在一个转向点上而不是分散精力。

**产出物：** 创建 docs/STRATEGY.md，包含 `## 诊断`、`## 指导政策`、`## 连贯的行动` 和 `## 无列表`。更新跟踪器。

**完成时：** STRATEGY.md 命名一个关键挑战、一个带有赢家的指导政策、带有所有者的连贯行动以及一个明确的无列表。

### 阶段 6 — 找到无争议的空间（蓝海战略）

**目的：** 选择一个通过创造无争议空间而不是在与其他所有人相同因素上进行正面交锋来获胜的地方。

**简要信息（回退）：** 价值创新同时追求差异化和低成本。ERRC 网格——消除、减少、提高、创造——提高了买家的价值，同时降低了成本。绘制战略画布：一个不同的提供物与行业曲线背离。蓝海将非客户（即将到来、拒绝、未探索）转化为客户，而不是竞争对手的客户——找到去除共同障碍的方法。不要消除客户真正重视的因素（信任、安全、准确性）。

**调用：** 使用 `蓝海战略` 技能，并提供来自 CUSTOMER.md 的竞争替代方案和来自 STRATEGY.md 的内核。要求当前因素的策略画布和一个在资源限制内进行价值创新移动的 ERRC 网格。

**与用户一起决策：** 哪些因素要消除 / 减少 / 提高 / 创建，以及首先转换哪个非客户层级。确认没有信任、安全或准确性因素被削减。

**产出物：** 扩展 docs/STRATEGY.md：添加 `## 策略画布 & ERRC 网格`。更新跟踪器。

**完成时：** STRATEGY.md 包含一个填充的 ERRC 网格和显示背离曲线的策略画布，以及选择的目标非客户层级。

### 阶段 7 — 定位以便潜在客户立即理解（显然精彩的）

**目的：** 设置一个上下文，使产品的优势在 30 秒内显而易见。

**简要信息（回退）：** 定位是上下文，而不是信息——客户相对于替代方案来评判你，因此选择比较。五个步骤：真正的竞争替代方案（通常是一个电子表格或什么也不做）；独特属性（通过“只有我们”测试）；通过“那么呢？”测试的价值；最佳匹配客户（紧密的，按标题和公司特征，永远不会是所有人）；市场类别（现有 / 子类别 / 新——一个新的类别需要支付教育税）。

**调用：** 使用 `显然精彩的` 技能，并提供来自 STRATEGY.md 和 CUSTOMER.md 的独特属性。要求完整的五步练习和一个内部定位声明：“对于 [最佳匹配客户]，我们是 [类别]，提供 [关键价值]。”

**与用户一起决策：** 要竞争的市场类别（现有 / 子类别 / 新），以及最佳匹配客户是谁。建议现有或子类别，除非有动力为新的类别保留一些动力。

**产出物：** 创建 docs/POSITIONING.md，包含 `## 竞争替代方案`、`## 独特属性 → 价值主题`、`## 最佳匹配客户`、`## 市场类别` 和 `## 一句话`。更新跟踪器。

**完成时：** POSITIONING.md 包含五步画布和一个 30 秒内外人能理解的一句话。

### 阶段 8 — 构建一个让人感觉愚蠢拒绝的报价（一亿个报价）

**目的：** 将理解转化为购买，使用一个让价格比较不可能的 Grand Slam 报价。

**简要信息（回退）：** 报价是第一杠杆。价值 = (梦想结果 × 感知可能性) / (时间延迟 × 努力程度) — 最大化顶部，最小化底部。组装 Grand Slam 报价：核心报价、命名奖金（每个奖金都消除一个反对意见，每个奖金都有一个合理的价值）、风险逆转保证、道德稀缺性。用 MAGIC 命名它。保持每个价值诚实，每个保证值得尊敬。

**调用：** 使用 `一亿个报价` 技能，并提供来自 POSITIONING.md 的定位和最佳匹配客户。要求基于价值方程的 Grand Slam 报价、每个奖金都消除一个反对意见、一个保证、道德稀缺性和一个 MAGIC 名称。

**与用户一起决策：** 要锚定的梦想结果，以及奖金必须消除哪些反对意见。确认每个美元价值和每个稀缺性声明都是真实存在的——替换任何需要虚构证据的技巧。

**产出物：** 创建 docs/OFFER.md，包含 `## 报价堆栈`（核心 · 奖金 · 保证 · 稀缺性 · 名称）。更新跟踪器。

**完成时：** OFFER.md 包含一个完整的报价堆栈，带有诚实的价值、一个真实的保证和一个名称——没有虚构证据。

### 阶段 9 — 根据验证的支付意愿定价（赚取创新的收益）

**目的：** 在概念仍然是一个概念时，通过测试支付意愿来设计产品。

**简要信息（回退）：** 客户揭示一个范围：询问什么感觉可以接受、昂贵、不可行；只信任顶部的购买概率。避免四个失败——功能冲击、微创新（接近 100% 胜率，没有反对意见）、隐藏的宝石、不死。按价值和支付意愿细分，而不是人口统计。包装领导者 / 填充者 / 杀手；首先设计中间层；将杀手功能作为附加功能拉入。在确定价格指标之前确定价格水平。

**调用：** 使用 `赚取创新的收益` 技能，并提供来自 OFFER.md 的报价和来自 CUSTOMER.md 的细分市场。要求一个支付意愿访谈脚本（可接受 / 昂贵 / 不可行）、领导者/填充者/杀手分类、良好/更好/最好层级，以及一个价格指标。将 WTP 脚本交给用户，并暂停 `awaiting-evidence` 以便进行真实通话；将批准的脚本记录在 docs/OFFER.md 下 `### WTP 访谈脚本` 的 `## 支付意愿证据` 子部分，以便它在暂停期间幸存。

**与用户一起决策：** 要收取哪个价格指标（每个座位 / 每个价值单位），以及良好/更好/最好层级的边界。建议一个跟踪交付价值的指标，以便收入复合。
