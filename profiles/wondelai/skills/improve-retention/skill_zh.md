# 行为设计框架

用于设计能够可靠地改变行为的产品的框架。行为与意志力或动机无关——它是一个具有可预测公式的设计问题。

## 核心原则

**福格行为模型** = B=MAP。当动机、能力和提示同时汇聚在同一个时刻时，行为就会发生。

```
            高 ┃
                 ┃   ★ 行为发生
                 ┃  (在行动线上方)
                 ┃
  动机     ┃━━━━━━━━━━━━━━━━━━━━━━━ ← 行动线
                 ┃
                 ┃   ✗ 行为失败
                 ┃  (在行动线下方)
            低  ┃
                 ┗━━━━━━━━━━━━━━━━━━━━━━━━━
                 难                    易
                        能力
```

**行动线**：当动机和能力足够时，提示会导致行为发生；在线下，没有提示会起作用。高动机可以弥补低能力，反之亦然。可靠的策略是让行为更容易（向右移动），而不是提高动机（向上移动）。

参见：[references/behavior-model.md](references/behavior-model.md)，当你需要了解这个模型背后的曲线机制时——完整的行动线数学、行为类型（点/跨度/路径），以及针对未发生的行为的逐步失败诊断。

## 评分

**目标：10/10**。六个快速诊断行是评分变动的主要来源。对每个通过/失败进行评分，然后从10分开始，每失败一行减去分数：低动机或行动线下方（行1-2）每行减**-2**；提示、庆祝、瓶颈和扩展（行3-6）每行减**-1.5**。一个通过所有六个评分的设计得10分；一个每行都失败的设计得0分。映射到等级：**9-10** = 行为在低动机下可靠地跨越行动线，提示与事件/锚点绑定，关键操作得到庆祝；**5-6** = 依赖于动机爆发或优化非瓶颈因素；**<=3** = 核心操作在行动线下方，提示是垃圾信息，没有习惯性 wiring。始终说明分数并命名具体的失败行。

## 三个要素

### 1. 动机

**核心概念**：动机是行动的能量，由三个核心动机驱动，每个动机都有两个方面：感觉（愉悦/痛苦）、预期（希望/恐惧）、归属（接受/拒绝）。它是强大但不可靠的。

**为什么有效**：动机是波动的——它会飙升（新年决心、产品发布）和崩溃（第3天、第2周）。依赖高动机的产品在浪潮退去时失败；最好的设计在低谷期工作。

**关键洞察**：
- "动机是不可靠的。能力是不可靠的。" — BJ Fogg
- 设计低动机时刻，而不是高峰兴奋时刻
- 动机优先策略（鼓舞人心的视频、有抱负的信息）产生爆发，而不是持续行为
- 将所需动机与行为难度相匹配——困难行为需要高动机

**产品应用**：

| 环境 | 应用 | 示例 |
|------|------|------|
| **引导** | 不要指望新用户的高峰期持续 | 即使兴奋消退，第一个操作也能起作用 |
| **再激活** | 假设回归用户的动机低 | 在要求努力之前立即展示价值 |
| **信息** | 触发正确的动机 | 社交健身 → 归属；金融工具 → 希望 |

**文案模式**：
- "30秒内完成"（暗示简单，降低所需动机）
- "加入50,000个团队..."（归属动机）
- "不要丢失你的7天连续记录"（预期/恐惧动机）

**道德边界**：一个恐惧动机（上述连续记录模式）只有在损失是真实的且用户拥有的（他们的数据，他们的进度）时才是公平的；永远不要编造一个仅仅为了驱动会话而存在的损失。

参见：[references/motivation-waves.md](references/motivation-waves.md) 了解三个动机、动机波动和为低谷期设计的行为。

### 2. 能力

**核心概念**：能力是执行行为的能力——它是六个因素（能力链）中最稀缺资源的函数。如果任何单个环节太弱，行为就会失败。

**为什么有效**：与动机不同，能力可以系统地设计：每移除一个字段、消除一个步骤和预设默认值，都会在模型上使行为向右移动，即使动机低也能跨越行动线。能力链为你提供诊断——找到最薄弱的环节并修复它。

**关键洞察**：
- 六个因素：时间、金钱、体力劳动、脑力劳动、社会偏差、非常规
- 简单性是稀缺资源的函数——找到瓶颈，而不是最明显的因素
- "简单性改变行为" — BJ Fogg
- 启动步骤：将行为缩小到最小版本（2分钟 → 30秒 → 一个字段）
- 默认值是最强大的能力工具——用户很少更改它们

**产品应用**：

| 环境 | 应用 | 示例 |
|------|------|------|
| **注册** | 在所有六个因素上降低成本 | 一键SSO移除时间、脑力劳动、非常规 |
| **核心操作** | 修复最薄弱的环节 | 脑力劳动瓶颈 → 智能默认值和模板 |
| **企业采用** | 解决社会偏差 | "你的团队已经在使用这个"减少了社会风险 |

**文案模式**：
- "一键开始"（时间 + 体力劳动）
- "不需要技术技能"（脑力劳动）
- "就像你已经在使用的工具一样"（非常规）

**道德边界**：仅在真正有价值的行为上减少摩擦——永远不要在没有确认的情况下让过度消费、过度分享或删除重要数据变得太容易。

参见：[references/ability-chain.md](references/ability-chain.md) 了解六个因素的详细信息、摩擦审计模板和简化策略。

### 3. 提示

**核心概念**：提示说“现在做”。没有提示，无论动机和能力如何，行为都不会发生。三种类型：个人提示（内部提醒）、环境提示（环境线索）、操作提示（产品设计的触发器）。

**为什么有效**：团队假设动机 + 能力就足够了——它不是，没有适时提示就不行。但提示只在行动线上方起作用：向缺乏动机或能力的人发送推送通知是垃圾信息。

**关键洞察**：
- 在错误时刻的提示是噪音；在正确时刻是魔法
- 锚点时刻将新行为绑定到现有常规（“打开Slack后，我将...”）
- 提示疲劳是真实的——每个不必要的提示都会降低未来提示的价值

**产品应用**：

| 环境 | 应用 | 示例 |
|------|------|------|
| **通知** | 仅在行动线上方提示 | 在有内容审查时发送摘要，而不是按计划发送 |
| **再激活** | 将提示绑定到真实事件 | “你的报告准备好了”（事件驱动，不是时间驱动） |
| **功能发现** | 在动机和能力一致时提示 | 当用户遇到该功能解决的问题时出现功能向导 |

**文案模式**：
- "你的每周报告准备好了"（环境提示——真实事件）
- "还有一件事来完成你的设置"（操作提示带进度）
- 永远不要： "我们想念你！"（产品需求，不是用户需求）

**道德边界**：每个提示都必须通过测试“我现在会欣赏收到这个吗？”——如果它服务于产品指标（DAU、再激活），但不是用户当前目标，就删除它。

参见：[references/prompt-design.md](references/prompt-design.md) 了解提示类型、时间策略、通知设计和锚点时刻。

## 微习惯方法

B=MAP的实际应用：让行为如此微小，以至于几乎不需要动机，将其锚定到现有常规，并立即庆祝。

### 配方

```
在[锚点时刻]后，我将[微行为]，然后我[庆祝]。
```

- **锚点时刻**：可靠发生的现有常规（打开应用、完成会议、早晨咖啡）。
- **微行为**：目标行为的最小版本——不是“写报告”，而是“打开报告模板”。
- **庆祝**：立即产生的积极情绪，它会形成习惯。仅仅重复是不够的——你需要成功的感觉。

### 启动步骤

每个目标行为都有一个启动步骤——最小有意义的版本：

| 目标行为 | 启动步骤 | 为什么有效 |
|----------|----------|----------|
| 完成引导 | 填写一个字段 | 完成的动力 |
| 每天使用分析 | 打开仪表板 | 看到数据会产生好奇心 |
| 与团队合作 | 发送一条评论 | 社会互惠开始 |

### 扩展行为

一旦形成，微行为会自然增长：打开仪表板 → 查看几个指标 → 自定义 → 自动早晨习惯。永远不要强迫扩展——让动机和动力驱动扩展。微版本是基础，不是失败。

参见：[references/tiny-habits.md](references/tiny-habits.md) 了解完整的微习惯配方、庆祝技术和扩展模式。

## 行为设计流程

福格的系统性流程，用于持久的行为改变：

### 第1步：明确愿望

用户想要什么结果——他们的愿望，而不是产品的目标（“跟上我团队的进度”，而不是“增加DAU”）。

### 第2步：探索行为选项

列出所有可能实现愿望的行为。要彻底——现在不要承诺。

### 第3步：匹配行为

评估每个行为的动机和简单性；在2×2的冲击 vs. 可行性（焦点映射）上绘制。

### 第4步：从微开始

将最佳匹配行为缩小到其启动步骤；设计提示；添加庆祝。

### 第5步：优化

一旦形成，就扩展。用能力链修复瓶颈；从数据中完善提示时间。

参见：[references/product-applications.md](references/product-applications.md) 在将其应用于特定类别时——B=MAP映射到SaaS引导、移动、电子商务、健康和教育，以及按类别划分的动机时间线和瓶颈。

## 行动线

### 将行为移至行动线上方

- **增加能力（向右移动）** — 移除步骤、预填、默认值、模板、向导。最可靠的方法。
- **寻找更好的提示** — 锚定到现有常规；事件驱动优于时间驱动；在动机自然更高的时刻触发。
- **增加动机（向上移动）是不可靠的** — 如果你需要动机策略，行为可能太难。

### 使用B=MAP进行保留诊断

将B=MAP映射到产品指标：

| 指标 | B=MAP诊断 | 行动 |
|------|----------|------|
| **低激活** | 第一个行为在行动线下方 | 将引导缩小到启动步骤；修复最薄弱的能力链环节 |
| **第1天流失** | 提示失败或时机不当 | 重新设计第一天提示；锚定到现有常规 |
| **第7天流失** | 动机波动退去，行为太难 | 降低核心操作难度 |
| **第30天流失** | 习惯未形成，没有内部提示 | 创建微习惯配方；添加庆祝循环 |
| **低功能采用** | 功能对大多数用户在行动线下方 | 摩擦审计；仅在动机存在时提示 |
| **通知疲劳** | 提示在行动线下方发送 | 减少数量；仅在动机 + 能力存在时发送 |

参见：[references/case-studies.md](references/case-studies.md) 了解Instagram、Duolingo、Slack、Calm和Peloton的详细诊断——阅读它，看看M、A和P如何在真实产品上独立评分，然后再诊断你自己的产品。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|----------|------|
| **依赖动机进行保留** | 动机总是退去；需要它的产品在低谷期失败 | 让行为足够小，以承受动机波动 |
| **忽略能力链瓶颈** | 你优化了时间，但障碍是脑力劳动或社会偏差 | 审计所有六个因素；修复最稀缺的资源 |
| **在行动线下方提示** | 对缺乏动机/能力的用户发送通知 = 垃圾信息 | 仅在动机 + 能力充足时的事件触发器 |
| **引导中忽略庆祝** | 没有积极情绪，重复不会形成习惯 | 添加成功状态和微庆祝，在关键操作后 |
| **第一个操作过于雄心勃勃** | “完成你的资料”是一个项目，而不是行为 | 缩小到启动步骤：一个字段，一个操作 |
| **未经B=MAP诊断而复制产品** | 高动机受众的设计对你的产品失败 | 首先诊断你的用户的动机、能力和提示环境 |

## 快速诊断

| 问题 | 如果没有 | 行动 |
|------|----------|------|
| 新用户能在60秒内完成核心操作吗？ | 能力太低 | 摩擦审计；缩小到启动步骤 |
| 产品在动机低时能工作吗？ | 设计依赖于爆发 | 重新设计核心行为，以最小化动机 |
| 提示是否绑定到真实事件或锚点？ | 提示感觉像垃圾信息 | 切换到事件驱动或锚点驱动提示 |
| 关键操作后是否有即时反馈？ | 没有庆祝 = 没有习惯性 wiring | 添加成功状态、进度、社交反馈 |
| 你是否找到了最薄弱的能力链环节？ | 优化了错误的东西 | 对核心行为对六个因素进行1-5评分 |
| 用户能否从微行为自然扩展？ | 过早强迫复杂性 | 启动步骤；让行为自然增长 |

## 关于作者

**BJ Fogg，博士** 创立了斯坦福大学的行為设计实验室，自1998年以来一直研究行为改变。他创建了福格行为模型（B=MAP），创造了“行为设计”一词，并培训了数千名创新者——包括Instagram联合创始人Mike Krieger。*微习惯*浓缩了二十年的研究：持久改变来自微小的、锚定的和庆祝的行为。
