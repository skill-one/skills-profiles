# iOS 人类界面指南设计技能

设计直观、一致且符合苹果设计理念的原生 iOS 界面的框架。基于苹果人类界面指南，它是应用程序无缝集成到 iPhone、iPad 和苹果生态系统的权威资源。

## 核心原则

苹果 iOS 设计理念建立在三个支柱之上：**清晰**（每个元素都清晰易读且目的明确）、**让位**（界面从不 overshadow 它所呈现的内容）和**深度**（层叠、过渡和逼真的动画传达层次结构和空间关系）。

**基础：** 最好的 iOS 应用程序内化这种理念，而不是机械地遵循 HIG 规则。原生组件、系统约定和平台一致性不是限制——它们是 iOS 用户信任并享受感觉像属于那里的应用程序的原因。

## 评分

**目标：10/10。** 快速诊断的满足行数（6 行）每行得 1 分，加上高达 4 分的原生习惯用法：+1 语义颜色/文本样式（无硬编码值）、+1 系统控件优于自定义重实现、+1 标准手势和有意义的触觉反馈、+1 SF Symbols 和正确的应用图标形状。范围：**9-10** = 原生、可访问、适应深色模式和动态类型、零外来模式；**5-6** = 可以工作但泄漏 Android 习惯用法或硬编码颜色/大小；**<=3** = 无法安全区域、触摸目标或 VoiceOver。始终说明分数以及达到 10/10 所需的具体改进。

## iOS 设计框架

### 1. 布局与安全区域

**核心概念：** iOS 设备具有特定的屏幕尺寸、安全区域偏移和硬件入侵（刘海、动态岛、主指示器），每个布局都必须尊重。

**关键洞察：**
- 首先为最小屏幕设计（375pt 宽度，iPhone SE）
- 安全区域保护内容免受刘海、动态岛和主指示器的遮挡——永远不要将交互元素放置在它们下方
- 标准内容边距：屏幕边缘 16-20pt；间距增量：8 / 16 / 24pt
- 最小触摸目标和列表行高度：44pt

**产品应用：**

| 环境 | 布局模式 | 示例 |
|------|----------|------|
| **状态栏** | 20pt 经典，动态岛设备上 44-54pt | 时间、信号、电池区域 |
| **导航栏** | 44pt 标准行 + ~52pt 大标题 (~96pt 总计) | 返回按钮、标题、操作 |
| **内容区域** | 弹性、可滚动、尊重安全区域 | 主要应用内容 |
| **标签栏** | 49pt 高度，半透明并模糊 | 2-5 主要目的地 |
| **主指示器** | 底部 34pt 偏移 | 系统手势区域 |

**文本模式：**
- 使用 `VStack { }`，它默认尊重安全区域
- 仅用于背景和装饰使用 `.ignoresSafeArea()`，永远不要用于交互内容
- 在 iPhone SE 和 Pro Max 等多个尺寸上测试

在布局边框时查看 [references/navigation.md](references/navigation.md)——精确的导航栏和标签栏尺寸、大标题行为和分屏规则。

### 2. 字体与动态类型

**核心概念：** iOS 使用 San Francisco (SF Pro) 字体，具有语义文本样式，通过动态类型自动缩放以实现可访问性。语义样式提供一致的平台层次结构；动态类型让用户可以在他们喜欢的尺寸下阅读，而不会破坏布局。

**关键洞察：**
- 大标题：34pt 粗体；标题：17pt 中等；正文：17pt 常规；标题：12-13pt；次要文本：60% 不透明度的 15pt
- 最小文本大小 11pt（仅标题/次要）
- 行高至少为字体大小的 1.3 倍；移动设备上的最佳行长度 35-50 个字符
- 始终左对齐，非两端对齐文本

**产品应用：**

| 环境 | 字体模式 | 示例 |
|------|----------|------|
| **屏幕标题** | `.largeTitle` 或 `.title` 样式 | 大标题在滚动时折叠 |
| **正文内容** | `.body` 样式，17pt | 列表项、描述 |
| **次要信息** | `.subheadline` 或 `.footnote` | 时间戳、元数据 |
| **标签栏** | 10pt SF 文本 | 标签栏项标签 |
| **按钮** | `.body` 重量粗体 | 主要操作文本 |

**文本模式：**
- 使用 `.font(.title)`、`.font(.body)`、`.font(.caption)` 而不是硬编码的尺寸；`@ScaledMetric` 用于缩放的自定义间距
- 优先考虑重量和颜色变化，而不是极端大小差异以建立层次结构
- 在最大的动态类型尺寸上测试所有布局

在匹配设计到精确规格时查看 [references/typography.md](references/typography.md)——每个样式的十六进制值和深色模式文本颜色映射。

### 3. 颜色与深色模式

**核心概念：** iOS 提供了语义系统颜色，它们在浅色和深色外观之间自动适应，同时保持对比度和层次结构。

**关键洞察：**
- 使用 `Color(.label)`、`Color(.secondaryLabel)`、`Color(.systemBackground)` 而不是硬编码的颜色
- `Color(.systemBlue)` 是默认色调；`.systemRed` 用于破坏性操作；`.systemGreen` 用于成功
- 深色模式反转文本颜色并将背景变暗，同时保持相对层次结构；强调色需要较低亮度和高饱和度才能突出显示
- 在两种模式下保持 4.5:1 对比度；在开发过程中预览两种模式

**产品应用：**

| 环境 | 颜色模式 | 示例 |
|------|----------|------|
| **主要文本** | `Color(.label)` | 根据模式适应白色/黑色 |
| **次要文本** | `Color(.secondaryLabel)` | 两种模式下 60% 不透明度 |
| **背景** | `Color(.systemBackground)` / `.secondarySystemBackground` | 层叠深度 |
| **破坏性操作** | `Color(.systemRed)` | 删除按钮、警告 |
| **交互色调** | 应用强调色或 `.systemBlue` | 链接、切换状态 |

**文本模式：**
- 使用 `.preferredColorScheme(.light)` 和 `.dark` 在预览中测试两种模式并排显示
- 在资源目录中定义自定义颜色，而不是在代码中定义，具有浅色/深色变体
- 假设背景是白色或黑色；启用增加对比度时测试

在检查对比度时查看 [references/colors-depth.md](references/colors-depth.md)——完整的 WCAG 比率表（正常文本、大文本、UI 组件）和三级/分组背景标记。

### 4. 导航模式

**核心概念：** iOS 使用分层导航模型：标签栏用于主要目的地，导航堆栈用于分层钻取，模态用于专注任务。用户依赖这些模式来了解他们所在的位置以及如何返回；重新发明它们使应用程序感觉不熟悉。

**关键洞察：**
- 标签栏：2-5 个主要目的地，始终可见，每个标签记住状态
- 导航栏：左上角的返回按钮、中心或大标题、右上角的操作；大标题在滚动时折叠
- 模态用于专注任务；通过向下滑动或显式关闭按钮关闭
- 永远不要使用汉堡菜单——iOS 用户期望标签栏
- 搜索栏可以位于导航栏下方，直到向下拉出才显示

**产品应用：**

| 环境 | 导航模式 | 示例 |
|------|----------|------|
| **应用结构** | 具有 3-5 个标签的标签栏 | 主页、搜索、个人资料 |
| **内容层次结构** | 推送导航（钻取） | 列表 > 详情 > 编辑 |
| **专注任务** | 模态呈现 | 撰写、设置、过滤器 |
| **搜索** | 向下拉搜索栏 | Spotlight 风格的搜索 |
| **分屏视图** | iPad 侧边栏 + 详情 | 邮件、笔记在 iPad 上 |

**文本模式：**
- 返回按钮文本应该是前一个屏幕的标题，而不是“返回”
- 标签是单个词（“主页”、“搜索”）；模态标题描述任务（“新消息”、“编辑个人资料”）
- 在 SwiftUI 中使用 `NavigationStack`（不是已弃用的 `NavigationView`）

### 5. 控件与输入

**核心概念：** iOS 提供了丰富的原生控件（按钮、列表、切换开关、选择器、菜单、文本字段）供用户理解并期望。

**为什么有效：** 原生控件带有内置的可访问性、触觉反馈和已学习的交互模式；自定义控件会创建摩擦并错过苹果已经解决的边缘情况。

**关键洞察：**
- 页面级操作位于导航栏（顶部）或操作栏（底部）
- 主要按钮填充主题颜色；次要按钮轮廓或纯文本
- 破坏性操作使用红色，并且在不可逆时需要确认
- 列表（表格视图）是 iOS 基本内容模式
- 根据输入匹配键盘类型（`.emailAddress`、`.phonePad`、`.URL`）；使用 `.textContentType` 进行自动填充

**产品应用：**

| 环境 | 控件模式 | 示例 |
|------|----------|------|
| **表单** | 原生文本字段并具有适当的键盘类型 | 电子邮件字段带有 @ 键盘 |
| **设置** | 分组列表，带有切换开关、展开 | iOS 设置样式 |
| **选择** | 选择器、分段控件或操作表 | 日期选择器、排序选项 |
| **破坏性操作** | 红色按钮 + 确认提示 | “删除帐户”流程 |
| **上下文操作** | 长按菜单或滑动操作 | 行编辑、共享、删除 |

**文本模式：**
- 配对 `.keyboardType(.emailAddress)` 与 `.textContentType(.emailAddress)`
- 优先考虑系统确认：`.alert()` 或 `.confirmationDialog()`；使用 `.swipeActions` 在列表行上
- 将主要操作按钮放置在屏幕底部，在拇指范围内

**道德边界：** 永远不要将广告伪装成原生控件，或者使破坏性操作容易意外触发。

在构建特定控件时查看 [references/components.md](references/components.md)——按钮样式、列表/部分变体、选择器与分段控件的选择，以及确认对话框的连接。在构建表单时查看 [references/keyboard-input.md](references/keyboard-input.md)——键盘类型表、输入辅助视图和硬件键盘快捷键。

### 6. 可访问性

**核心概念：** iOS 拥有世界级的可访问性功能（VoiceOver、动态类型、切换控制、语音控制），并且每个应用程序都必须作为一级关注点支持它们。App Store 审查可能会拒绝无法使用辅助技术的应用程序。

**关键洞察：**
- 每个交互元素都需要一个 `.accessibilityLabel`；使用 `.accessibilityValue` 用于状态，`.accessibilityHint` 用于效果
- 使用 `.accessibilityElement(children: .combine)` 组合相关元素
- 支持所有动态类型尺寸；在最大设置上测试
- 尊重 44 x 44pt 触摸目标（第 1 节）和 4.5:1 对比度最低要求（第 3 节）作为可访问性要求，而不仅仅是视觉默认值
- 永远不要仅通过颜色传达含义

**产品应用：**

| 环境 | 可访问性模式 | 示例 |
|------|--------------|------|
| **图标** | `.accessibilityLabel("Favorite")` | 心形图标带有标签 |
| **滑块** | `.accessibilityValue("\(Int(volume * 100))%")` | 音量控制 |
| **按钮** | `.accessibilityHint("Shares this item")` | 分享按钮 |
| **组** | `.accessibilityElement(children: .combine)` | 头像 + 名称行 |
| **图像** | 装饰性：`.accessibilityHidden(true)` | 背景图案 |

**文本模式：**
- 标签作为名词编写（“Favorite”、“设置”）；提示作为动作编写（“与他人分享此项目”）
- 使用 VoiceOver 测试完整的应用程序流程
- 使用 Xcode 的可访问性检查器审计对比度和标签

在签发前查看 [references/accessibility.md](references/accessibility.md)——完整的 VoiceOver 实现模式和一个发货前可访问性检查清单，用于运行应用程序。

### 7. 图标与图像

**核心概念：** iOS 使用 SF Symbols 作为标准图标系统，并要求应用程序图标在特定尺寸下，并自动应用签名超级椭圆（“圆角矩形”）蒙版。SF Symbols 在视觉上与 San Francisco 文本对齐并随动态类型缩放，因此它们在每個重量和尺寸下都保持对齐和清晰。

**关键洞察：**
- 使用 SF Symbols (`Image(systemName:)`) 用于所有标准图标——它们随文本缩放
- 应用程序图标：导出 1024x1024px 正方形；iOS 应用圆角矩形蒙版（圆角半径 = 边 x 0.222，61% 平滑）
- iOS 18+ 支持浅色、深色和着色图标变体
- 避免在应用程序图标中使用文本；保持设计简单，具有可识别的轮廓

**产品应用：**

| 环境 | 图标模式 | 示例 |
|------|----------|------|
| **标签栏** | SF Symbols，选中时填充变体 | `house.fill`，`magnifyingglass` |
| **导航栏** | 常规重量的 SF Symbols | `gear`，`plus`，`ellipsis` |
| **列表附件** | 次要颜色的 SF Symbols | `chevron.right`，`checkmark` |
| **应用程序图标** | 1024px 正方形，简单的粗体设计 | 单个可识别的图符 |

**文本模式：**
- 使用 `Image(systemName: "heart.fill")`；应用 `.symbolRenderingMode(.hierarchical)` 用于多色深度
- 相对于文本使用符号尺寸 `.imageScale(.large)` 或 `.font()`
- 在苹果免费的 SF Symbols 应用中浏览符号

**道德边界：** 永远不要使用暗示不存在功能或与 iOS 约定相矛盾的图标（垃圾桶 = 删除，而不是存档）。

在导出应用程序图标时查看 [references/app-icons.md](references/app-icons.md)——每个上下文尺寸表、精确的圆角矩形数学和 iOS 18 浅色/深色/着色变体要求。

### 8. 手势与触觉反馈

**核心概念：** iOS 定义了标准手势（从右侧滑动返回、从列表下拉刷新、长按显示上下文菜单）和触觉反馈模式，必须尊重且永不覆盖。手势是肌肉记忆——重新定义返回滑动或下拉刷新会使用户感到困惑；触觉反馈提供无形的确认，表明操作已注册。

**关键洞察：**
- 永远不要覆盖：从右侧边缘滑动（返回）、模态上向下滑动（关闭）、列表上向下滑动（刷新）
- 在行上向左滑动显示操作；长按显示上下文菜单；捏合缩放图像和地图
- 三种触觉类型：冲击（物理操作）、通知（结果）、选择（UI 变更）
- 触觉反馈应该是微妙且有意义的——永远不要持续或烦人

**产品应用：**

| 环境 | 手势/触觉反馈模式 | 示例 |
|------|------------------|------|
| **导航** | 从左侧边缘向右滑动 | 系统返回手势 |
| **模态** | 向下滑动以关闭 | 热身关闭 |
| **列表** | 下拉刷新，滑动显示操作 | 刷新内容，删除行 |
| **确认** | 完成时 `.success` 触觉反馈 | 支付确认 |
| **选择** | 切换/选择时选择触觉反馈 | 选择器轮滚动 |

**文本模式：**
- `UIImpactFeedbackGenerator(style: .medium)` 用于物理交互；`UISelectionFeedbackGenerator()` 用于 UI 状态变化
- `UINotificationFeedbackGenerator()` 与 `.success`、`.warning`、`.error` 用于结果
- 在触发触觉反馈之前调用 `.prepare()` 以最小化延迟

在连接手势或动画时查看 [references/gestures.md](references/gestures.md)——完整的保留手势表、触觉反馈生成器配方和标准动画时间/曲线。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|------------|------|
| **覆盖标准手势** | 打破了肌肉记忆，用于返回滑动、下拉刷新 | 使用系统手势的预期方式；仅用于补充操作的自定义手势 |
| **触摸目标小于 44pt** | 错误点击、沮丧、可访问性失败 | 使所有交互元素至少为 44 x 44pt |
| **忽略安全区域** | 内容被刘海、动态岛、主指示器遮挡 | 尊重安全区域偏移；`.ignoresSafeArea()` 仅用于背景 |
| **在 iOS 上使用 Android 模式** | 汉堡菜单、顶部标签、FAB 感觉不熟悉 | 使用标签栏、底部表单、原生 iOS 组件 |
| **跳过深色模式** | 布局损坏、深色模式用户无法阅读文本 | 使用语义颜色；测试两种外观 |
| **硬编码字体大小** | 破坏了动态类型，排除了低视力用户 | 在整个应用程序中使用语义文本样式（`.title`、`.body`、`.caption`） |
| **低对比度文本** | 无法满足 WCAG AA；阳光下的文本无法阅读 | 保持 4.5:1 最小值；使用增加对比度测试 |
| **不在真实设备上测试** | 模拟器遗漏性能、触觉反馈、安全区域边缘情况 | 在物理设备上测试最小和最大尺寸 |

## 快速诊断

审核任何 iOS 界面设计：

| 问题 | 如果没有 | 操作 |
|------|----------|------|
| 布局是否尊重所有设备尺寸上的安全区域？ | 内容被硬件遮挡 | 在 iPhone SE 和 Pro Max 上审核；修复偏移 |
| 所有触摸目标是否至少为 44 x 44pt？ | 错误点击和可访问性失败 | 增加触摸区域；`.frame(minWidth: 44, minHeight: 44)` |
| 应用程序是否在深色模式下完全工作？ | 深色模式用户界面损坏/无法阅读 | 使用语义系统颜色替换硬编码颜色 |
| 文本是否随动态类型正确缩放？ | 排除了低视力用户 | 使用语义文本样式；在最大设置上测试 |
| VoiceOver 用户是否可以完成每个任务？ | 盲人用户无法访问应用程序 | 为所有交互元素添加标签、值、提示 |
| 导航模式是否为原生 iOS？ | 应用程序感觉不熟悉 | 用标签栏替换汉堡菜单；标准的推送/模态导航 |

- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) --- 所有 Apple 平台的权威参考
- [SF Symbols](https://developer.apple.com/sf-symbols/) --- 苹果的图标系统，5,000+ 可配置符号
- [Apple Design Resources](https://developer.apple.com/design/resources/) --- 官方的 Figma/Sketch 模板和 UI 套件
- [WWDC Design Sessions](https://developer.apple.com/videos/design/) --- 关于设计原则和新功能的视频
- *"Designed by Apple in California"* --- 苹果设计过程的摄影集（已绝版；苹果不再销售它）
- [*"The Design of Everyday Things"*](https://www.amazon.com/Design-Everyday-Things-Revised-Expanded/dp/0465050654?tag=wondelai00-20) by Don Norman --- 影响了苹果的人本设计文本
- [*"Universal Principles of Design"*](https://www.amazon.com/Universal-Principles-Design-Revised-Updated/dp/1592535879?tag=wondelai00-20) by William Lidwell, Kritina Holden, and Jill Butler --- 125 个适用于 iOS 的原则

## 关于作者

**Apple Human Interface Guidelines** 由苹果的人机界面设计团队编写和维护，它是技术领域最有影响力的设计组织之一。1984 年与原始 Macintosh 一同首次发布，HIG 建立了直接操作、一致性、用户控制的原理，这些原理定义了图形界面设计，并通过 iPhone、iPad、Apple Watch 和 Vision Pro 不断发展。它仍然免费提供在 developer.apple.com 上，作为 Apple 平台的必要参考。
