# 网页排版

选择、搭配和实现网页字体的实用指南。最好的排版是看不见的——它让读者沉浸在内容中，而不是吸引注意力。

## 核心原则

**排版是内容的灵魂。** 你选择的字体在单个字被阅读之前就设定了基调——一个法律网站不应该感觉有趣；一个儿童应用程序不应该感觉商业化。遵循“清晰的酒杯”原则：排版应该像一块透明的酒杯，让焦点在酒（内容）上，而不是杯子（字体）上。

## 评分

**目标：10/10。** 得分 = 实现满足的 10 项快速诊断行的数量。等级：**9-10** = 正文 16px+，度量值小于 75ch，行高 1.4+，清晰的级别对比度，字体有效载荷小于 200KB，设置了回退字体，在 200% 放大下仍然可用；**5-6** = 可读但缺少度量控制、回退字体或缩放弹性；**<=3** = 正文小于 16px，没有度量上限，FOIT 或不可读的层次结构。始终说明当前得分和失败的特定诊断行。

## 两种排版环境

所有排版都分为两类：

| 环境 | 目的 | 优先级 |
|------|------|--------|
| **用于瞬间的排版** | 标题、按钮、导航、标志 | 个性、冲击力、独特性 |
| **用于长期使用的排版** | 正文、文章、文档 | 可读性、舒适度、持久性 |

**工作型字体** 在“用于长期使用的排版”方面表现出色——在各种尺寸、重量和环境中都很通用的同时不会引起注意。例如：Georgia、Source Sans、Freight Text、FF Meta。

## 排版框架

### 1. 我们如何阅读

**核心概念：** 理解阅读机制是每个排版决策的基础。眼睛不会平滑扫描——它们会以爆发的方式跳跃。

**为什么有效：** 抵抗这些机制会产生摩擦力，导致读者离开；与它们保持一致可以让读者以更少的疲劳更快地吸收内容。

**关键洞察：**
- **跳跃（saccades）**——眼睛以 7-9 个字符的爆发跳跃；行长度和字母间距直接影响跳跃效率
- **固定（fixations）**——眼睛会短暂暂停以吸收内容；密集或间距不当的文本会减慢阅读速度
- **单词形状（bouma）**——有经验的读者会识别单词轮廓，而不是单个字母
- **可识别性 vs. 可读性**——可识别性是指字符是否可以被区分（与字体有关）；可读性是指文本是否可以舒适地长时间阅读（与排版有关：尺寸、间距、行长度）。一个可识别的字体仍然可能设置得不可读

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 长格式内容 | 优化持续舒适度 | 正文 16-18px，行高 1.5-1.7，45-75 个字符的行 |
| 仪表板 UI | 优化快速扫描 | 突出的重量层次结构，数据组之间的空白 |
| 移动阅读 | 考虑距离和照明 | 更大的正文（17-18px），更高的对比度 |

**复制模式：**
```css
.prose {
  font-size: 1.125rem;     /* 18px */
  line-height: 1.6;
  max-width: 65ch;          /* ~45-75 个字符 */
}
```

当你需要命名字母形状部分（x-height、counter、aperture）或将字体放在分类系统中以证明选择时，请参阅：[references/typeface-anatomy.md](references/typeface-anatomy.md)。

### 2. 评估字体

**核心概念：** 字体必须在技术、结构和实际质量检查通过后才能获得项目中的位置。美丽的样本在屏幕上会失败。

**为什么有效：** 屏幕渲染、可变带宽和多样化的设备带来了印刷从未面临过的限制。严格的评估可以防止项目中途更换字体带来的成本。

**关键洞察：**
- **技术质量**——一致的笔画粗细、文本块中均匀的视觉颜色、良好的字偶距对（AV、To、Ty）、完整的字符集、多个重量（最低：常规、粗体、斜体）
- **结构评估**——充足的 x-height（更好的屏幕可读性）、开放的计数器和开口（a、e、c）、独特的字母形状（Il1、O0、rn vs. m）
- **实际需求**——在目标屏幕上的实际使用尺寸进行测试，检查文件大小，验证许可证
- **真实内容测试**——拉丁文隐藏了字符频率、单词长度和段落节奏的问题

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 正文选择 | 优先考虑 x-height、开放的计数器、均匀的颜色 | Source Serif Pro 而不是 Didot 用于长阅读 |
| UI/系统文本 | 优先考虑小尺寸可读性和重量范围 | Inter 或 SF Pro 用于界面元素 |
| 多语言产品 | 验证目标语言中的字形覆盖范围 | Noto Sans 用于广泛的 Unicode 支持 |

**复制模式：**
```css
/* 在每个实际使用尺寸上进行压力测试 */
body { font-size: 16px; }
.caption { font-size: 0.75rem; }
h1 { font-size: 3rem; }
```

**道德边界：** 在发布字体之前始终验证网络许可证——桌面/印刷许可证很少涵盖网络嵌入，未经许可的使用会带来真正的法律责任。

当你审查候选字体时，请参阅：[references/evaluating-typefaces.md](references/evaluating-typefaces.md)——完整质量清单、警告标志表和要检查的结构标准。

### 3. 选择字体

**核心概念：** 从目的而不是美观开始。内容的基调、阅读环境和持续时间应该驱动选择——而不是个人偏好或趋势。

**为什么有效：** 目的性强的选择感觉是不可避免的，而不是随机的，并且可以因为推理而不是品味而被利益相关者接受。

**关键洞察：**
- **首先定义工作**——正文、标题和 UI 元素可能需要不同的字体
- **匹配基调到内容**——一份财务报告需要不同的声音，而不是一家面包店的菜单
- **检查字体族**——在做出承诺之前，确认需要的重量、斜体和样式是否存在
- **安全的起点**——正文衬线：Georgia、Source Serif Pro、Charter；正文无衬线：系统字体、Source Sans Pro、Inter、IBM Plex Sans

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 内容密集型网站 | 工作型衬线或无衬线用于持续阅读 | Source Serif Pro 或 Charter 用于文章 |
| SaaS 仪表板 | 干净的无衬线字体带有强烈的表格数字 | Inter 或 IBM Plex Sans 用于数据丰富的 UI |
| 专注于可访问性 | 为最大可读性而设计的字体 | Atkinson Hyperlegible 用于视力受损用户 |

**复制模式：**
```css
/* 网络字体与系统回退堆栈 */
body {
  font-family: 'Source Sans Pro', -apple-system,
               BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
}
```

当你缩小决赛选手或权衡免费与付费字体时，请参阅：[references/evaluating-typefaces.md](references/evaluating-typefaces.md)——并排比较方法和质量选项短名单。

### 4. 搭配字体

**核心概念：** 成功的搭配会创造清晰的对比——字体应该明显不同，而不是令人困惑地相似。最多使用一到两种字体。

**为什么有效：** 清晰的结构对比（衬线 + 无衬线、轻 + 常规、人文 + 几何）给每个字体一个明确的角色。太相似的字体会制造没有目的的紧张感——读者会感觉到“不对劲”，但不知道为什么。

**关键洞察：**
- **对比类型**——结构（衬线 + 无衬线）、重量（轻 + 常规）、时代（人文 + 几何）、宽度（紧凑 + 常规）
- **同一设计师策略**——同一设计师的字体通常共享协调的 DNA（FF Meta + FF Meta Serif）
- **超家族**——设计为一起工作的字体家族消除了猜测（Roboto + Roboto Slab）
- **搭配失败**——两个几乎相同的字体，两个字体都在争夺注意力，一个字体压倒了另一个字体

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 编辑网站 | 衬线标题 + 无衬线正文 | Playfair Display + Source Sans Pro |
| 文档 | 等宽代码 + 来自同一家族的无衬线散文 | IBM Plex Mono + IBM Plex Sans |
| 极简品牌 | 单个家族的重量变化 | Inter 在不同的重量和尺寸 |

**复制模式：**
```css
/* 经典衬线 + 无衬线搭配 */
h1, h2, h3 { font-family: 'Playfair Display', Georgia, serif; }
body { font-family: 'Source Sans Pro', -apple-system, sans-serif; }
```

当你选择第二种字体时，请参阅：[references/pairing-strategies.md](references/pairing-strategies.md)——经过验证的组合、对比类型表和同一设计师/超家族快捷方式。

### 5. 排版测量

**核心概念：** 三个测量值——字体大小、行长度和行高——构成了舒适阅读的基础。正确设置这些测量值比选择字体更重要。

**为什么有效：** 这些测量值控制着眼睛如何横跨和垂直跟踪文本：最佳行长度与跳跃模式匹配，足够的行高防止眼睛在返回摆动时跳到错误的一行，足够的大小使字母形状在屏幕上可识别。

**关键洞察：**
- **正文大小**——最小 16px；对于阅读密集型网站，错误较大（18px）；移动用户比设计师假设的距离更远
- **行长度（度量）**——理想 45-75 个字符，66 最佳；使用 `ch` 单位或 `max-width` 强制执行
- **行高**——正文 1.4-1.8；较长的行需要更多；标题需要更紧（1.1-1.25）
- **标题比例**——级别之间一致的比率（1.2-1.5）创建层次结构，而不会出现极端情况

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 博客/文章 | 最大宽度 65ch，行高 1.6 | `.prose { max-width: 65ch; line-height: 1.6; }` |
| 仪表板 | 更紧的行高用于密集数据 | `line-height: 1.3;` 用于表格单元格和标签 |
| 登录页面 | 适中的尺寸用于可扫描性 | `font-size: 1.25rem; line-height: 1.7;` |

**复制模式：**
```css
.prose {
  font-size: clamp(1rem, 0.95rem + 0.25vw, 1.125rem);
  line-height: 1.6;
  max-width: 65ch;
}
/* 根据上下文设置行高 */
h1, h2 { line-height: 1.1; }      /* 标题：1.1-1.25 */
.ui-text { line-height: 1.35; }   /* UI：1.3-1.4 */
.body-text { line-height: 1.6; }  /* 正文：1.5-1.7 */
```

当你编写 `clamp()` 公式时，请参阅：[references/responsive-typography.md](references/responsive-typography.md)——如何推导出最小/首选/最大值和基于视口的测量策略。

### 6. 构建排版层次结构

**核心概念：** 层次结构告诉读者什么最重要。通过在大小、重量和颜色中受控的变化创造区别——但不要同时拉三个杠杆。

**为什么有效：** 故意、一致的级别差异让读者可以一眼看出页面结构；如果没有层次结构，一切都竞争，什么也赢不了。

**关键洞察：**
- **三个杠杆**——大小、重量、颜色；在相邻级别之间变化一个或两个，而不是三个
- **眯眼测试**——眯着眼睛看页面时，仍然可以看到层次结构
- **一致的比例**——标题级别之间的模块化比率（1.2-1.5）创建节奏；任意尺寸会制造噪音
- **不要跳过级别**——从 H1 跳到 H3 会打破读者的心理模型

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 内容页面 | 跨 4-5 个级别的大小 + 重量 | H1 2.5rem/700，H2 1.75rem/600，正文 1rem/400 |
| 仪表板 | 重量 + 颜色用于数据 vs. 标签 | 粗体 #111 值，常规 #666 标签 |
| 表单 UI | 标签的轻微重量变化 | 标签：600 重量，输入：400 重量 |

**复制模式：**
```css
h1 { font-size: clamp(2rem, 1.5rem + 2vw, 3rem); font-weight: 700; color: #111; }
h2 { font-size: clamp(1.5rem, 1.25rem + 1vw, 2rem); font-weight: 600; color: #111; }
body { font-size: 1rem; font-weight: 400; color: #333; }
.secondary { font-size: 0.875rem; color: #666; }
/* 标题：上面的空间比下面的空间更多 */
h1, h2, h3 { margin: 1.5em 0 0.5em; line-height: 1.2; }
```

**道德边界：** 不要为了速度而牺牲用户——删除非英语读者需要的字符的子集，或删除用于强调的斜体/粗体重量，会以包容性换取速度。

当你实现 CSS 时，请参阅：[references/css-implementation.md](references/css-implementation.md)——完整的层次结构模式、`@font-face` 加载、`font-variation-settings` 轴和 pyftsubset 中的子集。

### 7. 响应式排版和网页字体性能

**核心概念：** 排版必须适应屏幕，网页字体必须高效加载。流体排版使用 `clamp()` 消除了断点跳跃；战略字体加载防止布局偏移和慢速渲染。

**为什么有效：** 固定的字体大小无法同时服务于 320px 的手机和 1440px 的桌面。网页字体默认情况下会阻塞渲染——未优化的加载会导致不可见文本的闪烁（FOIT）或未样式文本的闪烁（FOUT）。

**关键洞察：**
- **流体排版**——`clamp(min, preferred, max)` 在视口之间平滑缩放，不需要媒体查询来设置排版
- **断点调整**——移动需要稍大的正文（17-18px）和更紧的标题比例；桌面可以将显示尺寸推到极限，同时保持行长度限制
- **加载策略**——`font-display: swap` 立即显示回退文本；预加载关键字体；子集到需要的字符
- **性能预算**——总字体有效载荷小于 200KB；优先考虑 WOFF2；可变字体可以替代 4-6 个静态权重文件

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 内容网站 | 使用 clamp() 的流体尺寸 | `font-size: clamp(1rem, 0.9rem + 0.5vw, 1.25rem)` |
| 电子商务 | 预加载英雄字体，延迟加载次要权重 | `<link rel="preload" href="font.woff2" as="font">` |
| 全球产品 | 按语言子集以减少有效载荷 | 拉丁字母子集用于英语，CJK 子集用于亚洲页面 |

**复制模式：**
```css
h1 { font-size: clamp(2rem, 1.5rem + 2vw, 3.5rem); }

@font-face {
  font-family: 'Custom Font';
  src: url('/fonts/custom.woff2') format('woff2');
  font-display: swap;
  unicode-range: U+0000-00FF; /* 拉丁字母子集 */
}
/* 在 <head>: <link rel="preload" href="/fonts/custom.woff2" as="font" type="font/woff2" crossorigin> */
```

**道德边界：** 不要优化用户——子集删除了非英语读者需要的字符，或删除了用于强调的斜体/粗体重量，会以包容性换取速度。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|----------|------|
| 文本感觉拥挤 | 行高太紧会让读者疲劳 | 增加行高到 1.6+；添加段落间距 |
| 行太长 | 超过 75 个字符时，眼睛会失去返回摆动 | `max-width: 65ch` 在文本容器上 |
| 标题看起来不连贯 | 标题上过多的空间会破坏与内容的关联 | 减少标题上的空间；保持标题下的空间 |
| 文本看起来模糊 | 字体平滑或子像素渲染问题 | 检查字体平滑；尝试不同的重量；增加尺寸 |
| 字体加载缓慢 | 未优化的文件会阻塞渲染 | 子集；`font-display: swap`；预加载关键字体 |
| 正文太小 | 手机比假设的距离更远；会使老眼睛疲劳 | 增加到 18px；在真实距离上测试 |
| 层次结构不明确 | 级别之间对比度不足 | 增加大小/重量差异 |
| 字体冲突 | 没有清晰对比的搭配会制造紧张感 | 一个家族，或确保结构对比（衬线 + 无衬线） |
| 拉丁文测试 | 伪文本隐藏了节奏和频率问题 | 使用真实、有代表性的内容进行测试 |

## 快速诊断

| 问题 | 如果没有 | 操作 |
|------|----------|------|
| 正文文本是否 16px 或更大？ | 太小，无法舒适阅读 | 至少 16px；对于阅读密集型页面，更喜欢 18px |
| 行长度是否小于 75 个字符？ | 眼睛在返回摆动时失去位置 | 在文本容器上 `max-width: 65ch` |
| 行高是否为正文 1.4+？ | 行感觉拥挤，阅读速度减慢 | 增加到 1.5-1.7 |
| 是否在类型级别之间存在清晰对比？ | 层次结构看不见，扫描失败 | 增加大小或重量差异 |
| 是否在真实屏幕上的实际尺寸上进行了测试？ | 生产中渲染的意外 | 在目标设备上测试每个使用尺寸 |
| 总字体有效载荷是否小于 200KB？ | 慢加载损害 UX 和 SEO | 子集，WOFF2，考虑可变字体 |
| 是否指定了回退字体？ | FOIT 留下空白文本 | 在每个 `font-family` 中指定系统回退 |
| 页面是否在 200% 放大下工作？ | 对低视力用户的可访问性失败 | 修复 200% 放大时的溢出和截断 |
| 标题是否没有孤立的单词？ | 尾随单词看起来不完整 | `text-wrap: balance` 或手动换行 |
| 链接是否在视觉上明显？ | 用户找不到交互式元素 | 颜色和/或下划线区分 |
