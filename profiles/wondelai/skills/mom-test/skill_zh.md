# 妈妈测试框架

基于一个基本真理构建的客户对话框架，该真理是：每个人都在对你撒谎——不是恶意地，而是因为你问错了问题。妈妈测试提供了提问的规则，好到连你妈妈都无法对你撒谎。

## 核心原则

**好的客户对话是关于他们的生活，而不是你的想法。** 一旦你提到你在构建什么，人们就会从分享真相转变为表演礼貌。谈论他们的问题、他们的生活和他们的现有行为，而不是推销，并询问过去的具体情况，而不是关于未来的假设。最重要的是，少说多做，多听少说。

## 评分

**目标：7/7。** 通过以下七行快速诊断来评分对话（或面试计划）：**每通过一行得1分。**
- **6-7** = 关注他们的生活和过去行为，捕捉了具体事实，获得了真正的承诺（时间/声誉/金钱），他们谈论了80%以上，并且信念得到了更新。
- **4-5** = 有些人谈论了过去行为的事实，但泄露到了假设中，接受了赞美作为信号，或者没有要求就结束了。
- **<=3** = 一种伪装的推销：引导性问题、观点和废话、礼貌的僵尸领导，没有学到任何东西。

始终声明当前的得分（满分7分），指出失败的诊断行，并为每一行提供具体的改进方法。

## 框架部分

### 1. 妈妈测试规则

**核心概念：** 三条规则，即使是你最支持的爱人也无法给你虚假的验证，将对话从意见收集转变为事实调查。

**为什么有效：** 人们无法预测他们自己的未来行为，所以意见是无用的。过去的行为是唯一可靠的数据，并且可以真正地指导产品决策。

**关键洞察：**
- 规则1：谈论他们的生活，而不是你的想法——如果可能的话，直到最后都不要提及你的解决方案
- 规则2：询问过去的具体情况，而不是关于未来的泛泛而谈或假设
- 规则3：少说多做——目标是让他们谈论80%的时间
- 如果无论商业是否成功，答案总是“是”，那么这个问题就通过了妈妈测试
- 好的问题可能会摧毁你目前设想的企业

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 想法验证 | 询问问题，而不是解决方案 | “告诉我你上次尝试[问题领域]的情况”而不是“你会使用一个做X的应用吗？” |
| 功能优先级 | 了解人们实际做什么，而不是他们说什么 | “带我走过你上周是如何处理的” |
| 定价研究 | 锚定现有的消费行为 | “你目前为了解决这个问题花了多少钱？”而不是“你会付X元吗？” |

**文案模式：**
- “告诉我你上次……”
- “你还试过什么？”
- “为什么这让你烦恼？”

在起草面试脚本时查看：[参考资料/问题模式.md](参考资料/问题模式.md)——一个五层问题等级，特定领域的问题库（SaaS/消费者/市场），以及四个制定练习。

### 2. 好问题与坏问题

**核心概念：** 大多数面试问题都是错误的，因为它们让人们预测未来、评估假设产品或确认你的假设。好问题锚定在可观察的过去行为中，并提取具体事实。

**为什么有效：** 询问“你会买这个吗？”就像询问“你下周会去健身房吗？”——答案总是“是”，但很少兑现。已经发生的行为无法被合理化。

**关键洞察：**
- 坏的：“你觉得这是个好主意吗？”——总是得到“是”
- 坏的：“你会买一个做X的产品吗？”/“你会付多少钱？”——假设性的，以取悦你为锚点
- 好的：“你今天是如何处理这个问题的？”——揭示了实际行为
- 好的：“你之前尝试过什么？为什么停止了？”——揭示了过去的决定
- 好的：“像这样的解决方案的钱从哪里来？”——揭示了真实的预算
- 最可怕的问题——那些有能力改变你正在构建的东西的问题——会产生最有用的数据

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 问题验证 | 确认问题是否存在且重要 | “这最后一次是什么时候出现的？你做了什么？什么没起作用？” |
| 市场规模 | 检查是否足够多的人共享这个问题 | “你行业里还有谁处理这个问题？他们如何处理？” |
| 竞争分析 | 找到已经实际使用的真实替代方案 | “你目前用什么工具/流程来处理这个？” |

**文案模式：**
- “[做这件事]最困难的部分是什么？”
- “这种情况多久出现一次？”
- “带我走过上次这种情况出现时发生了什么”

### 3. 避免赞美和意见

**核心概念：** 三种类型的不良数据感觉像进展，但会积极误导：赞美（“这是个好主意！”）、废话（假设、可能、未来的承诺）、想法（与真实问题脱节的功能请求）。回避这些并挖掘真相是核心技能。

**为什么有效：** 赞美是客户开发的傻瓜金——感觉很好，但包含零信息表明任何人都会付费或使用产品。只有关于真实过去行为的具体信息和真正的承诺才会提供信号。

**关键洞察：**
- 赞美：立即回避，并返回关于他们今天如何处理问题的具体事实
- 废话：没有具体实例的泛泛而谈（“我通常”、“我总是”、“我永远不会”）是无用的
- 想法：挖掘每个功能请求背后的动机——是什么在驱动它，他们上次什么时候需要它
- 寻求赞美（“你觉得这个会有用吗？”）是无意识的验证寻求
- 坏对话的迹象：你离开时感觉很好，但没有具体事实或承诺

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 演示后反馈 | 回避“这个看起来很棒” | “谢谢！你当前的工作流程中哪一部分会替换这个？” |
| 功能请求 | 挖掘潜在的工作 | “为什么你想那个？你能给我展示上次你需要它的时候吗？” |
| 投资者对话 | 将鼓励与兴趣分开 | 请求客户介绍，而不是“好主意”反馈 |

**文案模式：**
- “谢谢，但为了确保我没有浪费你的时间——你当前的工作流程是什么样的？”
- “当你说你“肯定会”使用这个时，你会停止使用什么？”
- “这是一个很好的功能想法——它具体能为你解决什么问题？”

在对话感觉良好但未产生事实时查看：[参考资料/避免不良数据.md](参考资料/避免不良数据.md)——如何实时识别和回避三种不良数据类型（赞美、废话、想法）。

### 4. 承诺和推进

**核心概念：** 客户对话的货币是承诺，而不是赞美。结束每个对话都有一个明确的推进方向，要么是明确的拒绝——最糟糕的结果是一个礼貌但从不承诺的“僵尸领导”。

**为什么有效：** 说“我肯定会买这个”成本为零；提供介绍、存款或试点投资了真实的东西。承诺关闭了人们所说和所做之间的危险差距。

**关键洞察：**
- 承诺货币：时间（会议、试用）、声誉（介绍、推荐信）、金钱（存款、预购、意向书）
- 推进将关系推向销售；原地打转会产生愉快但无用的会议
- 在会议前知道你的“请求”——证明这是真实的最低承诺
- “不”比“可能”更有价值——你可以从中学习并继续前进
- 如果他们不愿意给你时间，他们肯定不会给你金钱

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 早期验证 | 请求一个测试兴趣的承诺 | “下周可以花15分钟时间给我一个原型吗？” |
| B2B销售 | 推向决策者 | “你能介绍我给处理这个预算的人吗？” |
| 发布前 | 收集预购或意向书 | “8周后发布——你想加入第一个队列并获得40%的折扣吗？” |

**文案模式：**
- “还有谁我应该和这个话题的人谈？”
- “你愿意下周试用一个原型吗？”
- “如果我构建了这个，你愿意试用30天吗？”

在对话结束时没有承诺时查看：[参考资料/承诺推进.md](参考资料/承诺推进.md)——货币阶梯（时间/声誉/金钱）和推进而不是原地打转的脚本。

### 5. 寻找对话

**核心概念：** 最好的客户对话是偶然发生的——温暖的介绍、行业活动、在线社区、咖啡。正式的“客户面试”框架会触发表演模式；随意的框架会产生诚实的数据。

**为什么有效：** “我可以对你关于你的问题进行采访吗？”让人们对答如流并守口如瓶；“我正在学习这个行业——我可以请你喝杯咖啡吗？”让他们打开心扉。框架决定了数据的质量。

**关键洞察：**
- 冷接触：保持简短，以他们的专业知识开头，不要推销
- 温暖介绍是最好的来源——一个有影响力的顾问可以打开几十扇门
- 去客户已经聚集的地方：行业活动、会议、在线社区（先真诚参与）
- “我正在学习”比“我正在进行客户研究”更有效
- 使用五部分结构来安排会议：愿景/框架/弱点/宝座/请求

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 早期想法探索 | 沉浸在目标社区 | 3个行业活动和20次随意的对话，然后再写代码 |
| B2B prospecting | 通过顾问进行温暖介绍 | “我们的顾问[姓名]建议我问一下你如何处理[问题领域]” |
| 消费者研究 | 在行为发生时拦截 | 和排队的人、健身房、共享办公空间的人交谈 |

**文案模式：**
- “我正在研究[行业]如何处理[问题]——我可以和你喝15分钟咖啡学习你的经验吗？”
- “[共同联系人]建议我和你谈谈，因为你对[领域]了解很多”
- “我什么也不卖——我只是在尝试了解这个空间”

**道德界限：** 不要将销售电话伪装成学习对话——如果你已经有了产品并且在销售，要透明。

在需要寻找面试时查看：[参考资料/寻找对话.md](参考资料/寻找对话.md)——冷接触与温暖接触模板、五部分会议请求（愿景/框架/弱点/宝座/请求），以及如何保持随意的态度。

### 6. 处理和学习

**核心概念：** 对话只有在处理时才有用：将原始笔记提炼成信念，定期更新，并与你的团队分享。如果没有系统，你会挑选那些确认你偏见的引言。

**为什么有效：** 记忆倾向于最近和情绪化的信息，所以团队会选择性记住确认数据。作为一个团队处理可以防止任何一个人的偏见主导叙述。

**关键洞察：**
- 在对话期间或之后立即做笔记——永远不要依赖记忆
- 分离事实（他们说了什么和做了什么）与解释（你认为这意味着什么）
- 与你的团队分享原始笔记，而不是过滤后的摘要
- 每次批量后更新你的三个关键信念：问题、客户细分、解决方案
- 当对话开始重复时，停止说话并开始构建
- 使用一个简单的电子表格：谁、日期、关键引言、事实、承诺、信念变化

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 团队对齐 | 每周一起回顾笔记 | 每周5次对话；信念板更新 |
| 转折决策 | 跟踪与核心信念相反的证据 | 8次对话表明出现了不同的问题——转折 |
| 功能验证 | 统计未经提示的提及 | 被至少7个人提到的问题是真的；1个人可能不是 |

**文案模式：**
- “我们目前的信念是X——以下是证实它和挑战它的内容”
- “我们听到N个M的人这样说——这是否足够有信号？”
- “是时候停止说话并构建了——对话在重复”

在一批面试后查看：[参考资料/处理学习.md](参考资料/处理学习.md)——笔记到信念的电子表格模板、团队回顾节奏、停止说话并开始构建的信号。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|------|------|
| 提及你的想法而不是询问他们的生活 | 触发礼貌；产生赞美而不是事实 | 直到最后都不要提及你的想法，如果可能的话 |
| 询问“你会买这个吗？” | 假设性的“是”成本为零 | 询问他们已经做了什么：“你现在在这个上面花了多少钱？” |
| 将赞美视为验证 | “好主意！”包含零信息关于行为 | 立即回避：“谢谢——你今天是如何处理这个问题的？” |
| 谈话太多 | 你在学习时不是在说话 | 他们应该谈论80%以上的时间 |
| 结束时没有明确的请求 | 产生礼貌但不会走的“僵尸领导” | 在会议前知道你的推进：试用、介绍、预购 |
| 进行正式的“面试”会议 | 触发表演模式和过滤后的答案 | 保持随意的：咖啡、走廊对话、Slack DM |
| 不作为一个团队处理笔记 | 个别偏见过滤数据以确认 | 每周分享原始笔记；一起更新共享信念 |

## 快速诊断

| 问题 | 如果没有 | 动作 |
|------|------|------|
| 对话是否关注他们的生活和过去行为，而不是你的想法？ | 你进行了一次推销，而不是妈妈测试对话 | 重新做，不要提及你的解决方案 |
| 是否获得了关于他们已经做什么的具体事实？ | 你收集了意见和假设 | 询问问题最后一次发生的情况以及他们做了什么 |
| 他们是否给出了承诺（时间、声誉或金钱）？ | 可能是僵尸领导——礼貌但没兴趣 | 请求一个具体的下一步：试用、介绍或预购 |
| 他们是否大部分时间在说话？ | 你说得太多，学得太少 | 练习沉默；让尴尬的停顿为你工作 |
| 是否学到了可能改变你正在构建的东西的信息？ | 你问了安全、确认的问题 | 询问你一直在回避的可怕问题 |
| 是否根据对话更新了你的信念？ | 你在收集数据但不是在学习 | 与团队一起回顾笔记；更新问题/客户细分/解决方案信念 |
| 是否可以总结关键事实（而不是意见）？ | 差的笔记，或者意见与事实混淆 | 立即分离事实与解释 |

在想要看到规则端到端应用时查看：[参考资料/案例研究.md](参考资料/案例研究.md)——现实的SaaS、消费者、B2B和市场的面试，根据此诊断评分。
