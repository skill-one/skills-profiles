# 创业运营系统（EOS）

一个用于运营企业的完整系统，包含六个关键组成部分。专为希望统一愿景和执行力的创业公司（收入200万-5000万美元，10-250名员工）设计。

## 核心原则

**大多数企业都遭受着相同的核心问题：人员、愿景、执行力。** 没有执行力的愿景是幻觉；没有愿景的执行力是盲目。EOS通过一个实用的每周运营节奏，将两者联系起来，强化任何组织的六个关键组成部分。

## 评分

**目标：10/10。** 根据六个快速诊断行中有多少通过（每个组成部分要么到位，要么不到位）来评分，映射到下面的区间。区间：**9-10** = 六个诊断行全部通过，并且关键任务持续完成80%以上；**7-8** = 五个行通过，一个组成部分薄弱；**5-6** = 三到四个行通过；**3-4** = 一到两个行通过；**<=2** = 没有运营节奏。始终说明当前分数、失败的诊断行以及每个的下一步行动。

## 六个关键组成部分

```
愿景 → 人员 → 数据 → 问题 → 流程 → 执行力
```

### 1. 愿景组成部分

**问题：** 组织中的每个人都清楚你要去哪里以及你打算如何到达吗？

**工具：愿景/执行力组织器（V/TO）** — 在两页纸上回答八个问题：

| 问题 | 定义内容 | 示例 |
|------|----------|------|
| **核心价值观** | 3-7不可协商的信念 | "承担责任"、"做正确的事"、"成长或死亡" |
| **核心焦点** | 目的/事业/热情 + 利基市场 | "简化中小企业" + "云会计" |
| **十年目标** | 大胆、有挑战性、雄心勃勃的目标 | "1000万美元收入"或"1万客户" |
| **营销策略** | 目标市场、3个独特性、验证流程、保证 | 你服务谁，你为什么与众不同 |
| **三年愿景** | 三年后公司看起来是什么样子 | 收入、利润、员工人数、关键指标 |
| **一年计划** | 收入、利润、可衡量的指标、目标 | 今年具体的指标 |
| **季度关键任务** | 本季度3-7个优先事项 | 90天内最重要的事情 |
| **问题清单** | 所有未解决的问题 | 问题、想法、机会 |

**流程：** 领导层一起完成V/TO（2天离岗），与整个组织分享，每季度回顾，每年更新。

**关键洞察：** 如果领导层无法就V/TO达成一致，你有一个更大的问题——统一性是第一位的。

填写V/TO时，请参阅[参考资料/vto.md](references/vto.md) — 八个问题的模板和离岗练习顺序。

### 2. 人员组成部分

**问题：** 你是否把合适的人放在了合适的岗位上？

**工具：责任矩阵** — 不是组织结构图；它定义了结构并明确了谁负责什么。

```
愿景家 ←→ 整合者
              ├── 销售/营销
              ├── 运营
              └── 财务
```

- **愿景家：** 大胆的想法、文化、关键关系、创造性解决问题
- **整合者：** 日常运营、管理团队、执行愿景
- **规则：** 每个岗位一个人 — 共享责任感就是没有责任感

**工具：人员分析器** — 在两个维度上评估每个人：

1. **合适的人（核心价值观匹配）：** 对每个核心价值观进行+、+/-或-的评分。所有项都必须是"+"；一个"+/-"需要谈话；任何"-"意味着不合适。
2. **合适的岗位（GWC）：** **G**ets it（理解角色）、**W**ants it（真诚地）、**C**apacity（精神、身体、情感）。所有项都必须是"是"。

**人员决策：**
- 合适的人，合适的岗位 → 保留并投资
- 合适的人，不合适的岗位 → 调到合适的岗位
- 不合适的人，合适的岗位 → 培训或退出（最难的决定）
- 不合适的人，不合适的岗位 → 立即退出

构建责任矩阵或运行人员分析器时，请参阅[参考资料/people.md](references/people.md) — 模板加上GWC评分指南。

### 3. 数据组成部分

**问题：** 你是基于客观数据还是主观意见进行管理？

**工具：记分卡** — 一份包含5-15个数字的每周报告卡，告诉你公司运营情况。每周数据比每月数据早2-4周发现问题，并取代直觉管理，用责任制管理。

**记分卡规则：**
- 基于活动的指标（领先指标），而不是结果（滞后指标）
- 每周数字 — 每月太慢无法反应
- 每个数字都有所有者和目标
- 红色/绿色：在轨道或偏离轨道

**示例：**

| 指标 | 所有者 | 目标 | W1 | W2 | W3 | W4 |
|------|-------|------|----|----|----|----|
| 收入 | 销售主管 | 每周50K美元 | ✓ | ✓ | ✗ | ✓ |
| 新线索 | 市场营销 | 每周100个 | ✓ | ✗ | ✓ | ✓ |
| 现金余额 | 财务 | >20万美元 | ✓ | ✓ | ✓ | ✓ |

**指标选择：** 如果你需要休假4周，哪些5-15个数字会告诉你公司运营情况？

构建记分卡时，请参阅[参考资料/data.md](references/data.md) — 模板加上如何选择领先指标。

### 4. 问题组成部分

**问题：** 你是否快速识别、讨论和解决问题？

**工具：问题解决跟踪（IDS）** — **I**dentify → **D**iscuss → **S**olve：

1. **识别：** 不断问"为什么"，直到找到根本原因（而不是症状）；用一句话说明问题
2. **讨论：** 每个人都提供意见（而不是平等时间）；停止跑题；一次一个问题，时间限制5-15分钟
3. **解决：** 做出决定，分配行动项（谁 + 什么 + 何时），继续前进

**三种类型的问题：**

| 类型 | 示例 | 行动 |
|------|------|------|
| **问题** | 客户流失、团队冲突、故障 | IDS → 解决 |
| **想法** | 新功能、流程变更、机会 | IDS → 决策（是/否/稍后） |
| **障碍** | 坠毁的关键任务、资源限制 | IDS → 移除或升级 |

**问题清单规则：** 任何人都可以添加问题；优先处理最重要的问题；未解决的问题会延续 — 不是每个会议都能解决所有问题。

**常见的IDS失败：** 讨论症状而不是根本原因，每周重复同一个问题，没有明确的行动项就结束会议。

主持IDS时，请参阅[参考资料/issues.md](references/issues.md) — 一个五问工作示例和跑题控制策略。

### 5. 流程组成部分

**问题：** 你是否记录并始终如一地遵循核心流程？

**工具：核心流程记录** — 20/80法则：记录20%的流程以获得80%的一致性。

**需要识别的核心流程：** 人力资源（招聘、入职、评估）、销售（线索 → 关闭）、运营（交付、履行）、客户服务（支持 → 解决）、财务（开票、收款）。

**记录格式：** 命名流程，列出5-20个主要步骤，提供足够的细节（不是50页的手册），尽可能使其可视化。

**示例：销售流程"关闭者"**
1. 确认线索（BANT：预算、权力、需求、时间线）
2. 探索电话（30分钟，问题指南）
3. 演示（根据他们的痛点定制）
4. 提案（24小时内）
5. 跟进（7天内3次接触）
6. 关闭或淘汰

**所有人员都遵循（FBA）：** 记录它，培训它，衡量合规性，每季度更新。

记录核心流程时，请参阅[参考资料/process.md](references/process.md) — 完整模板和人力资源/销售/运营的工作示例。

### 6. 执行力组成部分

**问题：** 你是否每天都在执行你的愿景？

#### 关键任务（季度优先事项）

未来90天内需要完成的3-7件最重要的事情。90天足够实现有意义的成果，又足够保持紧迫感。

**设定关键任务的流程：**
1. 回顾V/TO（愿景、三年、一年）
2. 头脑风暴本季度必须完成的事情以保持进度
3. 筛选到3-7个公司关键任务，每个任务一个负责人
4. 每位领导成员也设定3-7个个人关键任务
5. 与整个组织分享并每周跟踪

**SMART关键任务：** 具体（"推出新的定价页面"，而不是"改进定价"）、可衡量（有明确的完成标准）、90天内可实现、考虑到资源、有时间限制（在本季度末完成）。

**关键任务评分：** 完成=勾选（没有部分分数）；未完成=继续或删除。目标完成80%以上。注意那些只是"正常业务"的关键任务——它们不会推动进展。

设定季度关键任务时，请参阅[参考资料/rocks.md](references/rocks.md) — 二进制完成测试、九行错误表和中期检查。

#### 10级会议（每周领导会议）

**EOS中最重要的会议。** 每周、同一天、同一时间、同一议程——90分钟，从不更长。

| 时间 | 部分 | 目的 |
|------|------|------|
| 5分钟 | **过渡** | 好消息，个人和职业 |
| 5分钟 | **记分卡** | 回顾每周数字 |
| 5分钟 | **关键任务回顾** | 按关键任务进行进度/偏离进度 |
| 5分钟 | **头条新闻** | 客户/员工快速更新 |
| 5分钟 | **待办事项列表** | 上周的待办事项：完成或未完成 |
| 60分钟 | **IDS** | 识别、讨论、解决问题 |
| 5分钟 | **总结** | 回顾待办事项，评分1-10 |

**规则：**
- 准时开始和结束——保护节奏是使其有效的原因
- 没有手机/笔记本电脑（除了议程）——IDS需要全神贯注
- IDS占90分钟中的60分钟——解决问题是重点，更新不是
- 结束时评分1-10（因此称为"10级"；低于8意味着讨论如何改进）
- 待办事项是7天行动项，有负责人；完成=100%完成；目标完成90%以上

运行或修复10级会议时，请参阅[参考资料/level-10.md](references/level-10.md) — 促进脚本和如何解释会议评分。

## EOS实施时间表

典型推广：2年完成全面实施。

| 阶段 | 时间线 | 重点 |
|------|--------|------|
| **专注日** | 第1天（8小时） | 责任矩阵、关键任务、记分卡、10级会议 |
| **愿景建设日1** | 第1个月 | V/TO：核心价值观、核心焦点、10年目标 |
| **愿景建设日2** | 第2个月 | V/TO：营销策略、三年、一年、关键任务 |
| **季度会议** | 每90天 | 回顾关键任务、设定新关键任务、IDS主要问题 |
| **年度规划** | 每年 | 完整V/TO回顾、一年计划、Q1关键任务 |

**自我实施**（阅读书籍，遵循工具——免费，较慢）与**EOS实施者**（认证促进者——更快，昂贵）。

规划推广时，请参阅[参考资料/implementation.md](references/implementation.md) — 阶段性顺序和自我与实施者决策。有关真实公司如何顺序的示例，请参阅[参考资料/案例研究.md](references/case-studies.md)。

## 组织检查

对每个陈述评分1-5：

| 组成部分 | 陈述 | 评分（1-5） |
|------|------|-------------|
| **愿景** | 领导团队就我们要去哪里以及如何到达达成一致 | |
| **人员** | 我们把合适的人放在了合适的岗位上 | |
| **数据** | 我们基于每周5-15个数字进行管理 | |
| **问题** | 我们快速永久地解决问题 | |
| **流程** | 核心流程被记录并由所有人员遵循 | |
| **执行力** | 我们设定并实现90天优先事项（关键任务） | |

**评分：** 25-30强（微调） | 20-24好（弥补差距） | 15-19平均（大量工作） | 低于15弱（考虑EOS实施者）。

## 常见错误

| 错误 | 失败原因 | 修复 |
|------|----------|------|
| **跳过10级会议** | 每周节奏丢失，问题堆积 | 保护会议，从不取消 |
| **没有记分卡** | 直觉管理，经常意外 | 选择5-15个每周数字 |
| **保留不合适的人** | 拖累整个团队 | 人员分析器，做出艰难的决定 |
| **V/TO未共享** | 团队不知道愿景 | 与整个公司分享 |

关于特定关键任务的错误（太多、太模糊、正常业务、中期变更），请参阅[参考资料/rocks.md](references/rocks.md) — 完整九行表格和修复。

## 快速诊断

| 问题 | 如果没有 | 行动 |
|------|-------|--------|
| 领导层是否就愿景达成一致？ | 失调 | 一起完成V/TO |
| 是否有合适的人在合适的岗位上？ | 绩效问题 | 对所有岗位运行人员分析器 |
| 是否每周基于数据管理？ | 反应式管理 | 建立每周记分卡 |
| 是否永久解决问题？ | 重复相同的问题 | 在10级会议中进行IDS |
| 核心流程是否记录？ | 不一致性 | 记录前5个流程 |
| 是否设定并跟踪90天优先事项？ | 没有执行力 | 设定季度关键任务 |
