# 重构 UI 设计系统

一种实用且带有主观意见的 UI 设计方法。在生成前端代码、评审设计或提供视觉改进建议时，请应用这些原则。

## 核心原则

**先使用灰度设计，最后添加颜色。** 这会迫使你在依赖颜色作为拐杖之前，通过间距、对比度和排版来建立正确的层级结构。

**基础：** 优秀的 UI 并非关于天赋——而是关于系统。对间距、类型、颜色和阴影使用受限的刻度会产生始终如一的专业结果。从过多的空白处开始，然后移除；保留细节（图标、阴影、微交互），直到布局和层级结构起作用。

## 评分

**目标：10/10。** 通过计算 [快速诊断](#快速诊断)（8个是/否检查）中的满足行数来评分：`score = round(satisfied / 8 × 10)`。等级直接跟随：**10** = 所有8项都通过（层级结构在灰度中模糊可读，每个值都在刻度上）；**9** = 恰好1个缺口（通常是层级结构薄弱或白色空间过薄）；**6-8** = 2-3个缺口；**<=5** = 4+个缺口（任意间距，颜色在做层级结构应该做的事情，或对比度不足）。始终说明当前分数以及需要修复的具体诊断行以达到 10/10。

## 重构 UI 框架

构建专业界面的七个原则，无需设计师：

### 1. 视觉层级结构

**核心概念：** 并非所有内容都可以重要。通过三个杠杆创建层级结构：大小、重量和颜色。

**为什么有效：** 当每个元素都在争夺注意力时，没有任何元素会突出；故意弱化次要内容，通过对比使主要内容变得强大。

**关键洞察：**
- 结合杠杆，不要叠加——主要文本 = 大型 或 粗体 或 深色，不要全部三个；将“全部三个”保留给最重要的元素
- 标签是次要的——表单标签、表头和元数据支持数据，而不是与数据竞争；使它们更小、更轻或大写小写
- 语义颜色 ≠ 视觉重量——柔和的次要按钮通常比尖叫的红色更适合常规的破坏性操作

**产品应用：**

| 环境 | 层级结构技术 | 示例 |
|------|--------------|------|
| **表单字段** | 弱化标签，强调值 | 小写标签位于大型值上方 |
| **仪表板** | 关键指标大，上下文小 | "$42,300" 大型，"与上月相比" 小型 |
| **表格** | 弱化表头，强调数据 | 表头大写小写灰色，数据正常 |

**设计模式：**
- 三级层级结构：大小（大/基础/小），重量（粗体/中/正常），颜色（深色/中/浅灰色）
- 按钮层级结构：主要（填充），次要（轮廓或柔和），次要（仅文本）

**道德边界：** 不要使用层级结构技巧来隐藏重要信息，如价格、条款或取消选项。

在设计超出静态布局的组件时（交互/悬停/焦点状态、表单设计、空状态、边框半径系统、文本截断和响应式断点），请参阅 [参考资料/高级模式.md](references/advanced-patterns.md)。

### 2. 间距与尺寸

**核心概念：** 使用受限的间距刻度，而不是任意值。间距定义关系——更近的元素读起来更相关。

**为什么有效：** 任意间距（padding: 13px）会导致不一致；固定刻度迫使深思熟虑的决策和和谐的布局。充足的间距感觉高端；密集感令人不知所措。

**关键洞察：**
- 使用刻度：4、8、16、24、32、48、64px
- 从过多的空白处开始，然后移除——你几乎永远不会移除足够
- 组间间距必须大于组内间距
- 限制宽度：文本到 45-75 个字符（`max-w-prose`），表单到 300-500px；全宽几乎从不正确

**产品应用：**

| 环境 | 间距策略 | 示例 |
|------|----------|------|
| **图标 + 标签** | 紧密耦合（4px） | 小间距将它们连接起来 |
| **卡片部分** | 部分分隔（24px） | 标题、内容、页脚块 |
| **页面部分** | 主要部分（48-64px） | 英雄、功能、客户评价 |

**CSS 模式：**
- `p-1`(4px) `p-2`(8px) `p-4`(16px) `p-6`(24px) `p-8`(32px) `p-12`(48px) `p-16`(64px)
- `max-w-prose`(65ch) `max-w-md`(28rem) `max-w-lg`(32rem) `max-w-xl`(36rem)
- `gap-2` 用于相关项目，`gap-6` 用于部分分隔

### 3. 排版

**核心概念：** 使用模块化类型刻度，根据上下文限制行高，并最多限制两种字体家族。

**为什么有效：** 模块化刻度（每个步骤增长约 1.2 倍）创造了自然视觉节奏；标题和正文行高紧张，正文行高放松，在每个上下文中提高了可读性。

**关键洞察：**
- 刻度：12、14、16、18、20、24、30、36px（~1.2 模块化，手工调整）
- 标题：紧张行高（1.0-1.25）；正文：放松（1.5-1.75）；更宽的文本需要更多行高
- 避免正文文本的重量低于 400；使用粗体（600-700）进行强调，而不是所有内容
- 最多两种字体：一种用于标题，一种用于正文（或一种具有重量变化的字体家族）

**产品应用：**

| 环境 | 排版规则 | 示例 |
|------|----------|------|
| **英雄大标题** | 36px，行高 1.1，粗体 | 大型有影响力的声明 |
| **正文文本** | 16px，行高 1.75，正常 | 舒适阅读 |
| **标题/标签** | 12-14px，行高 1.5，中灰色 | 次要信息 |

**CSS 模式：**
- `text-xs`(12px) `text-sm`(14px) `text-base`(16px) `text-lg`(18px) `text-xl`(20px)
- `font-normal`(400) `font-medium`(500) `font-semibold`(600) `font-bold`(700)
- `leading-tight`(1.25) `leading-normal`(1.5) `leading-relaxed`(1.75)

### 4. 颜色

**核心概念：** 建立系统化的调色板，每个颜色有 5-9 个阴影，为灰色添加微妙饱和度，并首先使用灰度设计。

**为什么有效：** 随机颜色冲突；预定义的阴影系统确保一致性，HSL 调整创造自然感觉的较浅和较深的变体。

**关键洞察：**
- 每个颜色需要 5-9 个阴影，从近白色到近黑色（50-900）；最暗的不是纯黑色——使用 `#111827`，而不是 `#000000`
- 纯灰色看起来无生气——将它们染色（冷 UI：蓝色如 `#64748b`；暖 UI：黄色/棕色如 `#78716c`）
- HSL：较浅 = 提高亮度，降低饱和度，色调朝向 60°；较暗 = 相反，色调朝向 0°/240°
- 对比度最低：正文文本 4.5:1，大文本（18px+） 3:1；使用 `#374151`（灰色-700）在白色上，而不是更浅的灰色

**产品应用：**

| 环境 | 颜色策略 | 示例 |
|------|----------|------|
| **主要调色板** | 品牌颜色 9 个阴影（50-900） | 蓝色-500 按钮，蓝色-100 背景 |
| **语义颜色** | 成功/警告/错误具有阴影范围 | 绿色-500 成功，红色-500 错误 |
| **文本颜色** | 三个级别：深色、中等、浅色 | `text-gray-900`，`text-gray-600`，`text-gray-400` |

**CSS 模式：**
- `text-gray-900`(深色) `text-gray-600`(中等) `text-gray-400`(浅色)
- `bg-blue-50` 用于微妙背景，`bg-blue-500` 用于主要操作
- `border-gray-200` 用于微妙边框，`border-gray-300` 用于更强边框

在构建暗色主题时（十六进制阴影刻度，为什么最暗的是 `#111827` 而不是黑色（光晕），以及通过亮度而不是阴影传达高度），请参阅 [参考资料/暗色主题.md](references/theming-dark-mode.md)。在对比度、焦点环、键盘导航或屏幕阅读器支持在范围内时（完整的 WCAG 2.1 AA 检查表和修复），请参阅 [参考资料/可访问性深度.md](references/accessibility-depth.md)。

### 5. 深度与阴影

**核心概念：** 使用阴影刻度来传达高度——小阴影用于略微抬起的元素，大阴影用于悬浮的元素。

**为什么有效：** 眼睛将阴影大小读作页面上方的高度；一致的刻度使高度可读，因此用户可以直观地知道什么是交互式的、悬浮的或背景的。

**关键洞察：**
- 小阴影 = 略微抬起（按钮、卡片）；大 = 悬浮（模态框、下拉菜单）
- 好的阴影有两个部分：紧密的暗阴影用于清晰度，加上较大的软阴影用于氛围
- 没有阴影的深度：较亮的顶部边框 + 较暗的底部边框，微妙渐变，重叠元素
- 不要过度使用——如果所有东西都在悬浮，就没有深度；阴影颜色是透明的暗色，永远不会不透明的灰色

**产品应用：**

| 环境 | 阴影级别 | 示例 |
|------|----------|------|
| **按钮** | `shadow-sm`（微妙抬起） | 略微高于表面 |
| **下拉菜单** | `shadow-lg`（悬浮） | 菜单明显高于内容 |
| **模态框** | `shadow-xl`（最高） | 脱离页面 |

**CSS 模式：**
- `shadow-sm`: `0 1px 2px rgba(0,0,0,0.05)`
- `shadow-md`: `0 4px 6px rgba(0,0,0,0.1)`
- `shadow-lg`: `0 10px 15px rgba(0,0,0,0.1)`
- `shadow-xl`: `0 20px 25px rgba(0,0,0,0.15)`

在为交互元素添加运动时（持续时间、缓动曲线、加载状态和 `prefers-reduced-motion` 规则），请参阅 [参考资料/动画微交互.md](references/animation-microinteractions.md)。

### 6. 图片与图标

**核心概念：** 将图片视为设计元素，而不是事后想法。有意地调整图标大小，并使用叠加层以保持图片上的文本可读。

**为什么有效：** 尺寸不当的图标看起来笨拙，未风格化的图片会破坏一致性；有意处理（叠加层、对象适应、半径）使界面感觉精致。

**关键洞察：**
- 相对于上下文调整图标大小；使用具有一致笔宽和样式的图标集
- 永远不要拉伸或扭曲——使用 `object-fit: cover` 与固定宽高比和有意裁剪
- 图片上的文本需要叠加层（半透明渐变）
- 空状态是一个机会——使用插图加上清晰的 CTA，而不仅仅是文本

**产品应用：**

| 环境 | 图片/图标技术 | 示例 |
|------|--------------|------|
| **英雄图片** | 半透明渐变叠加层 | 文本在任何照片上可读 |
| **头像** | 一致大小，圆形，后备首字母 | 40px 圆形，对象适应覆盖 |
| **空状态** | 定制插图 + CTA | 友好的插图带有 "开始" |

**CSS 模式：**
- `object-fit: cover` 与固定 `aspect-ratio` 用于一致显示
- 图标大小：`w-4 h-4` 内联，`w-6 h-6` 导航，`w-8 h-8` 功能图标
- 叠加层：`bg-gradient-to-t from-black/60 to-transparent` 用于图片上的文本

### 7. 布局与构图

**核心概念：** 不要将所有内容居中。使用对齐、重叠和强调变化来创建引人入胜的构图。

**为什么有效：** 一致的左边缘为每行眼睛提供了一个固定的返回点，因此扫描成本较低；居中的多行文本移动该边缘，减慢阅读速度。

**关键洞察：**
- 默认左对齐；仅居中短标题、英雄、单个操作 CTA 和空状态
- 卡片不需要包含所有内容——让图片溢出到边缘或重叠容器
- 在列表和提要中变化视觉处理——突出一些项目，最小化其他项目
- 使用对齐在无关元素之间创建关系

**产品应用：**

| 环境 | 布局策略 | 示例 |
|------|----------|------|
| **英雄部分** | 居中文本，充足间距 | 短标题 + 副标题 + 单个 CTA |
| **博客提要** | 变化卡片大小以强调 | 第一篇文章大，其余为 2 列网格 |
| **内容页面** | 限制宽度，左对齐 | `max-w-prose` 容器，左对文本 |

**CSS 模式：**
- `text-left` 默认，`text-center` 仅用于英雄和短标题
- `grid grid-cols-3 gap-6` 用于功能网格；`max-w-4xl mx-auto` 用于页面容器
- `overflow-hidden` 在带有 `object-fit: cover` 图像的卡片上，图像溢出到边缘

在布局图表、表格或仪表板时（图表类型选择、图表中颜色的使用、表格密度和仪表板构图），请参阅 [参考资料/数据可视化.md](references/data-visualization.md)。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|------------|------|
| **"看起来很业余"** | 白色空间不足，宽度不受约束 | 更多白色空间，限制内容宽度 |
| **"感觉扁平"** | 没有深度区分 | 微妙阴影，部分底部边框 |
| **"文本难以阅读"** | 行高差，太宽，对比度低 | 增加行高，限制宽度，提高对比度 |
| **"所有内容看起来都一样"** | 没有视觉层级 | 在主要和次要之间变化大小/重量/颜色 |
| **"感觉杂乱"** | 到处都是相等的间距 | 将相关项目分组，组间更大的间距 |
| **"颜色冲突"** | 随机选择，没有系统 | 降低饱和度，更多灰色，限制调色板 |
| **"按钮不突出"** | 与周围对比度低 | 增加对比度，添加阴影 |
| 任意值 | px 值如 13、17、23 产生不一致 | 遵守间距和类型刻度 |

## 快速诊断

审核任何 UI 设计：

| 问题 | 如果没有 | 操作 |
|------|----------|------|
| 层级结构在眯眼时（模糊测试）中可读吗？ | 元素竞争 | 增加主要/次要对比 |
| 它在灰度中起作用吗？ | 颜色是拐杖 | 加强大小/重量/间距层级 |
| 有足够的空白吗？ | 可能不足——大多数设计过于密集 | 增加间距，尤其是组间 |
| 标签相对于值是否弱化？ | 标签与数据竞争 | 更小、更轻或大写小写标签 |
| 间距是否遵循一致刻度？ | 任意间距 = 视觉噪音 | 仅使用 4/8/16/24/32/48/64 |
| 文本宽度是否受限？ | 长行使读者疲劳 | 应用 `max-w-prose` (~65ch) |
| 颜色是否有足够的对比度？ | 可访问性失败 | WCAG 检查；使用 gray-700+ 在白色上 |
| 阴影是否适合高度？ | 元素悬浮在错误级别 | 匹配阴影刻度到元素目的 |

**Adam Wathan**，Tailwind CSS 的创建者，和 **Steve Schoger**，其设计语言的视觉设计师，撰写了 *重构 UI*，旨在教开发者系统化、可重复的设计技术。他们的方法用受限系统取代了艺术天赋——固定间距、排版、颜色和阴影刻度——产生了专业结果。
