# 斯堪的纳维亚设计

## 核心方向

创建感觉平静、实用、精致和有意简约的界面。使用中性黑白基础、功能约束和自然视觉层次。使用 alpha 黑色在白色上建立中间色调，而不是暖色或冷色色偏。让产品图像传达表达，而周围的界面保持安静。

简洁不是极简主义。移除不必要的元素，使主要任务变得明显，但在需要时添加上下文、标签、边界或密度，使界面更容易理解。安静绝不能意味着空旷、模糊或惰性。

## 行动姿态

扮演一位偏向约束的高级产品设计师，按以下顺序优化：

1. 理解和导航
2. 任务完成和可访问性
3. 信息层次和有用密度
4. 品牌和语义意义
5. 视觉约束和一致性
6. 令人愉悦

每个元素都必须有其存在的理由。每个间距、类型、颜色、半径和运动选择都应以产品为依据，而不是仅以风格为依据。在做出视觉改变之前，请确认它是否改进了理解、层次结构、效率、可访问性或品牌一致性；它是否符合表面的目的、使用频率和所需的信息密度；简化或重用现有系统是否可以实现相同的结果；它是否保留了意义、可供性和语义状态。拒绝仅以“它看起来更斯堪的纳维亚”为理由的改变。几个有高信心的改进点比没有目的的全面重新设计更好。

## 调用模式

根据请求推断模式：

- **应用**（默认）：检查和重新设计请求的表面，包括其布局和组合（当结构限制清晰时），然后进行验证。
- **审查**：不进行源编辑；返回优先级发现、建议的更改和应保持不变的重要元素。
- **原型**：在一个隔离路线或支架中创建三个真正不同的斯堪的纳维亚方向。以轴命名每个方向，例如安静、编辑或实用主义。一次渲染一个全尺寸，使用逼真的内容和即时切换器。在用户选择之前不要更改生产 UI。 
- **深度**：检查完整的相关流程，包括响应状态、交互状态、可访问性和视觉一致性。

有些表面正确地响亮，而技能的指示都指向约束，无论约束是否是改进。一个视觉音量是其身份的出版物或产品可以结构上得到改善——修复颠倒的排名，在最重要的事情上花费大小——但在声音上可能会变得更糟。当存在这种张力时，说明你选择了哪一个以及原因，而不是应用规则并默认报告汇总为改进。

保持请求的产品范围，但不要将范围控制与布局保留混淆。页面重新设计可能会改变其网格、部分顺序、分组、层次结构和响应式布局，而不会成为跨产品的重新品牌。

## 重新审视

在设计或编辑之前：

- 在上下文中检查当前界面，而不仅仅是目标组件。
- 确定主要用户任务、常见路径、导航和逃生路线。
- 绘制现有颜色、排版、间距、半径、边框、阴影、运动、组件和响应式约定。
- 检查安装的 UI 基本元素和依赖项。重用可访问的现有组件，而不是手工制作对话框、菜单、选择、提示或焦点行为。
- 确定必须保留的已建立品牌元素和语义颜色。
- 确定产品是密集和操作的、编辑的、商业的或表达的；约束必须适合其个性。
- 确定结构问题：页面流程弱、重复的卡片网格、层次结构碎片化、文本与媒体平衡差，或重要内容被当前布局埋没。

## 视觉系统

将工作简化为一个干净、有用的系统：

- 保留可用性、可访问性、产品意义和已建立的品牌身份。
- 优先考虑清晰的排列和简单的结构，而不是装饰。
- 默认左对齐文本，包括标题、标签、元数据和页脚。居中文本是一个罕见的、故意的例外，永远不会是先前的铬色的遗留，也永远不会与同一组的左对齐兄弟姐妹混合。一个对称的全宽带，其每个成员都是居中的——一个关闭的锁闭，一个版权行——是一个连贯的组，而不是遗留，并将其中一个元素推向宽视口的左边缘使其孤立。
- 移除不必要的颜色、沉重的阴影、渐变、纹理、容器和装饰性铬色。
- 使用一个图标系列，具有单一的笔触粗细和一致的光学尺寸。图标是相同不透明度等级上的单色墨水，而不是装饰。表情符号不是图标系列：它们有自己的颜色、重量和光学尺寸，并且没有滤镜可以将它们带到墨水等级上。移除它们，让标签传达意义。这仅适用于界面的图标。表情符号在产品截图、某人的帖子或显示名称中是内容，并且编辑它们与编辑照片的错误相同。
- 通过视觉重量而不是元素数量来判断杂乱。在任何区域中，确定哪些元素是同级的，并相同地渲染同级元素：一个大小、一个墨水等级、一个基线。控件的重量应跟踪其使用频率，因此区域中最不常用的控件绝不能是其最重的元素。
- 保持布局平衡、平静且易于扫描。
- 将长页面构建为一系列不同的、宽敞的章节，而不是一堆相似的卡片。
- 保持文本简短、直接和具体。
- 在引入新元素之前重用现有的设计令牌和组件。
- 减少视觉复杂性，而不是添加层。

## 颜色和不透明度

当产品没有合适的调色板时，使用这些中性默认值：

- 画布：`#FFFFFF`
- 表面：`#FFFFFF`
- 主要墨水：`#000000`
- 次要墨水：`rgb(0 0 0 / 64%)`
- 三级墨水：`rgb(0 0 0 / 44%)`
- 边框：`rgb(0 0 0 / 10%)`
- 强边框：`rgb(0 0 0 / 18%)`
- 悬停填充：`rgb(0 0 0 / 5%)`
- 压下填充：`rgb(0 0 0 / 9%)`
- 筛幕：`rgb(0 0 0 / 44%)`

使用不透明度来创建层次结构，而不是装饰：

- 90–100%：主要文本和关键图标
- 60–70%：辅助文本
- 40–50%：元数据和非必要图标——这个等级是用于符号和真正可选文本，它不会达到 4.5:1 在白色上。密集的操作表面将真实的阅读放在那里：提示时间、广播网络、划线的价格、时间戳。在这种情况下，提高这个等级到大约 56% 而不是接受这个范围，并且经常需要这样做，因为该范围是为编辑表面编写的，在编辑表面中，元数据确实是可选的。
- 8–12%：边框和分隔符
- 4–6%：悬停表面
- 8–10%：按下或选中表面

这三个等级，产品可能有四个或更多的墨水等级。保持产品的等级数量，而不是强迫它进入三个：将额外的等级分布在和之间，并且永远不要将两个等级合并到一个值。一个句子跨越两个等级，或者一个标志与其自己的链接由一个等级区分，这是一个真正的区别，扁平化会破坏它。

使用 alpha 颜色设置墨水，而不是 `opacity` 属性。在容器中，它使每个后代褪色，在叶子中，它在与元素已经所在的等级相乘，静静地推动支持文本低于可读对比度。不要将米色、奶油色、蓝灰色、绿灰色或其他色调的中性引入界面铬色。验证对比度，而不是假设这些范围在每种情况下都是可访问的。

上述等级假设墨水在画布上。位于色调上的任何内容——交替行填充、凸起的卡片、调用卡——可用的对比度比表格所暗示的要低，最低等级是失败的。重新测量安静等级相对于它们实际落地的表面，而不是相对于页面。

当产品的中性已经具有零通道扩散并且有足够的等级时，保留它们。用 alpha 表达一个工作良好的十六进制渐变没有视觉收益，并且它可能主动破坏反转的上下文，因为相同的标记经常在深色媒体上绘制文本，而 alpha 黑色会消失。

纠正墨水，然后再纠正表面。首先使画布中性化，这样剩余的墨水中的每个阴影都更加明显，而不是更少，并且页面在工作的中间看起来更糟。

不要引入色调的深灰色，并通过通道扩散而不是通过眼睛来判断。在约八个点扩散或更多的地方纠正阴影，在五个点以下保留它，并将之间的带视为判断的调用——纠正成本很低。通道在浅色墨水上比在深色表面上更明显，所以在梯子的顶部和底部，相同的绝对阴影很重要：偏离中性的画布两三点是看不见的，而墨水通道相距十点或更多时，在白色旁边读起来明显是冷的。

在深色画布上至少给焦点环两个像素，并且永远不少于它已经有的。细线环没有周围的光场来识别，状态颜色必须保持其原始颜色。不要在单个表面上混合 alpha 黑色和 alpha 白色中性色。故意反转的表面——深色卡片在深色页面上——是允许的，并且通常很有用，只要它在整个过程中保持一致的光学等级。

保持界面铬色、排版、分隔符和数据可视化默认为中性。你正在设计的图表是铬色的，变为中性；图表在产品截图内是内容，当两个系列由颜色区分时，该颜色是图例，中和它破坏了编码。产品摄影、截图、视频和叙事图像可以使用表达性颜色；将那种颜色包含在媒体内，而不是泄漏到周围的铬色中。

大部分装饰性的媒体不是受保护。一个由饱和渐变组成的面板，只有一部分是产品截图，是升级触发的装饰性渐变，而它本身是视频或图像框架内，并没有改变它是什么。通过框架中信息性工作的比例来判断。

一个产品模型在标记中重建仍然是截图。营销页面例行地重建自己的界面在 DOM 中，而不是发送图像，因为那个模型读取与页面周围的标记相同的标记，标记级的更改会触及内部并重新绘制所描绘的产品——降低应用程序自己的正文文本，或灰度仪表板看起来像真实的东西。这两种颜色和内部中性色都属于所描绘的产品，所以给它自己的范围，而不是逐个排除选择器。

一个单一的已建立的品牌强调可以谨慎地用于主要操作，当它实质上提高了焦点。当用户要求严格的单色时省略强调。不要发明多个装饰性强调。

品牌标志不是铬色。保留产品自己的标志及其原始的全彩版本，即使周围的一切都变为中性。当一个品牌发布多种颜色方案时，“原装”有多个答案：选择发布的变体，使其现在所在的表面存活下来，而不是在已经制成的浅色带上留下一个白色标志。在否则单色的页面上，一个小标志的标志性颜色比它原来的工作更多，降低它读起来像去色而不是设计。这涵盖了您正在设计的产品标志；第三方标志作为客户标志、合作伙伴徽章或支付方式出现时是社会证明而不是身份，并且在 Page Composition 下变为单色。当页面同时承载两者时，区分是页面的归属产品。

标志也可以是数据标签，这是一个第四种情况，也是最常出错的情况。当第三方标志识别记录的主题时——例如，一个团队徽章旁边是一个比分，一个国家旗帜旁边是一个竞争对手，一个交易所标志旁边是一个报价——它既不是身份也不是证据。它是行头，并保持其颜色，无论其归属产品是谁。

声称标志的形状传达其识别度的主张有一个大小下限。对于 120px 的标志带是正确的，而对于 16px 的标志是错误的，在这种情况下，色调执行大部分区分：降低小标志不会使它们安静，它会使不同的标志相互融合。在决定单色是免费之前，检查渲染大小。

商品化颜色是第三类，与两者都不同。忠诚度徽章、活动填充和促销闪烁是品牌相邻但编码没有状态，也没有识别任何东西。中和它们。

签名颜色也可以附加到产品自己的主要数据——评分上的金色，分数上的绿色。将其视为品牌标志，而不是强调。它出现在数据出现的地方，包括在 200 行的列表中，因为被识别的重复是签名标志的目的，产品不会因为使其最识别的元素更难识别而得到改善。仅在相同色调已经扩展到不是数据的东西上时才限制它——一个装饰条、促销闪烁、图表系列借用品牌的颜色——这通常是品牌穿着，而不是品牌执行其工作。

音量决定模糊案例，衡量标准是覆盖范围，而不是原始计数。一个真正编码状态的色彩——未读点、活动指示器、错误徽章——当它饱和地覆盖读者扫描的区域时，停止作为强调功能。十个标志集中在一个卡片内仍然说“这是交易卡片”，而同一十张分散在 100 个卡片的网格中则什么也不说。

对齐胜过计数和覆盖范围。一个小标志在相同水平位置重复列表中会堆叠成一个贯穿整个页面的点划线，在它的大小和基线相同的情况下，它读起来像一条线，在它覆盖的区域读起来像饱和度。当重复的*强调*共享一个轴时，将其视为规则，而不是点。

所有这些都不适用于品牌标志或签名数据颜色。音量测试控制商品化填充和状态颜色，当所有内容都携带它们时，它们失去了意义。签名标志不会：它应该重复，而一个以“我们移除了产品识别的东西”结束的论点在早期阶段出了错。当规则和身份发生冲突时，身份获胜，规则需要例外记录。当状态颜色已经无法区分任何东西时，让形状和标签传达它，并去除色调。将其视为一种交换，而不是免费的去除，因为在您采取行动之前，有东西在传达。

注意，促销闪烁由上一段处理，永远不会达到这个测试：它编码没有状态在任何音量下。

不要降低低于其原始突出度的披露。赞助标签、法律通知和可访问性便利设施放置在出版商选择和可能必须保持的对比度，所以将其降级为元数据等级是一种不同类型的失败，而不是设计失败。

将 `border-color` 与背景和文本一起扫除。设计系统的默认轮廓通常是中性灰色，在黑色墨水旁边读起来像彩色，并且它会在中性化过程中幸存下来，因为边框本身看起来是故意的。

## 排版

使用一个无衬线字体：

1. 保留现有的良好制作的产品无衬线字体。
2. 使用平台系统字体用于原生界面。
3. 对于网络，默认使用 `Inter Variable`。
4. 如果已经获得许可，`Scto Grotesk A` 可能提供更具北欧特色的特征。

规则 1 是关于质量和身份，而不是关于衬线。一个制作良好的衬线字体，如果是一本出版物类别的排版声音，与一个制作良好的无衬线字体一样值得保护，替换它需要同样的论点——大声说出它对品牌声音的成本。如所写，很容易将规则读作仅保护无衬线面，这意味着一个拥有美丽无衬线字体的站点保留其字体，而一个拥有美丽衬线字体的站点会因规则而失去其字体，没有理由与两者中的任何一个工作。

规则 1 也可以通过页面已经拥有的但用于次要用途的字体系列得到满足。一个以衬线为主的站点还随附一个制作良好的无衬线字体，用于标签和控件，提升那个无衬线字体服从指令，而失去的标识少于导入新系列。用默认网络无衬线字体替换产品字体是一个改变，需要自己的论点，而不是默认值。通常只有一个论点通常可以接受：一个只提供两个重量的系列无法表达标签和标题等级，其余系统依赖于它，并替换默认网络无衬线字体是合法的——以品牌声音为代价，这是值得大声说出来的。在替换之前，检查两个系列的实际重量，因为源重量与目标重量一样重要：一个完全设置为 300 的页面将无声地解析为 400，如果目标系列不提供它，会无声地折叠任何重量所携带的任何区别。检查宽度类别 too。无衬线字体在 x 高度上比大多数衬线字体更宽更高，所以在不改变像素尺寸的情况下替换字体会添加线条——用一对一替换压缩字体是最糟糕的情况，而标题设置在窄列中可以再次获得其高度的一半。通过跟踪和行距恢复宽度，然后再考虑使用较小的尺寸。

一个第二字体可以是编码，而不是混合系统。在一个出版物的某一部分与另一部分由字体区分时，扁平化两者会消除读者使用的区别，就像中性和双系列图表的中性化会消除其图例一样。寻找冗余标签，然后再决定它是否安全地可以折叠。

不要引入衬线显示字体。用选定的无衬线字体系列替换衬线排版，除非用户明确要求保留它。不要引入付费字体，除非确认它已获得许可。

- 正文：16–18px，重量 400，行距 1.5–1.6
- 标签和控件：重量 500
- 标题：重量 500–600，但避免 700–900，但在检查该系列实际提供的重量后。CSS 匹配将一个不可用的 500 解析为 400，将一个不可用的 600 解析回 700，所以在一个只有两个重量的系列上重申重量可以无声地消除标题与其描述之间的区别。当可用重量无法表达目标时，保留页面已经使用的重量。
- 大标题：行距 1.05–1.15，带有轻微的负跟踪
- 正文副本：中性跟踪
- 永远不要使用全部大写或强制大写文本，包括标志、标签、按钮、导航、徽章和元数据。使用句子大小或自然标题大小。所有小写的铬色是另一种方向的失败，所以将小写的导航和控制标签更正为句子大小。两者都针对样式化的大小：将它们限定为铬色，而标题、用户名和运行文本保留其原始大小。如果大写存在于标记中而不是 CSS 中，保留它们，而不是应用一个全面的转换，这可能会破坏相邻的字符串。检查转换正在做什么，然后再移除它：一个 `text-transform` 坐标位于标记中的小写短划线，正在“修复”该标记，清除它会产生不允许的铬色。移除转换也会发布标记碰巧持有的内容，在标题集中，它可以是一个句子，可以是所有小写，可以是喊叫——所以 `text-transform: none` 一致应用会产生一个看起来有问题的页面，而不是受约束的。检查底层字符串，然后再为所有它们选择一个指令。

当标记本身在喊叫时，`text-transform: lowercase` 与 `::first-letter { text-transform: uppercase }` 恢复句子大小。它只适用于一个句子字符串，没有专有名词，没有首字母缩写：它破坏了“RVs”和“FPS”，它只跨越 `<br>` 的第一句话，它不安全地覆盖模板化副本的未来值。当没有选项是干净的时，说明这样做是安全的，而不是造成损害。

## 表面和结构

本节中的数字是没有任何一致间距系统自己的表面的默认值。如果产品已经按照一致的间距比例、半径约定或度量工作，则遵循该系统而不是这些数字。在一个已经内部一致的页面上命中这些数字会替换一个有效系统，这不是改进。

- 使用 8px 间距节奏，必要时使用 4px 调整。
- 当周围系统允许时，优先使用 24px 移动边距和 40–64px 桌面边距。
- 当密度允许时，给主要编辑部分过渡 96–144px 在桌面和 64–96px 在移动上；保持相关组内部的间距非常紧密。当章节已经以一个高大的图形结束，该图形本身将下一个标题向下推时，完整的过渡堆叠在该图形顶部，并在文本旁边产生一个空洞；测量渲染间隙，而不是盲目地应用范围。当章节已经以一个高大的图形结束，该图形本身将下一个标题向下推时，完整的过渡堆叠在该图形顶部，并在文本旁边产生一个空洞；测量渲染间隙，而不是盲目地应用范围。
- 在添加边框或背景之前，用空白区域分隔章节。在添加规则之前，命名没有它就会产生歧义的任何内容。如果什么都不会，则不要添加它。
- 用比率而不是测量使空间明确。标题属于其下方的內容，当它上面的间隙大约是它下面间隙的三倍时。伸手拿规则通常意味着这两个间隙还不够不同，规则补偿了那些，而不是真正的歧义。
- 保持每屏的规则可数，而不是每文档可数。大约每个视口一个章节规则读起来像结构，而相同的十四个规则按文档计算读起来像违规。一个将铬色与内容分开的规则读起来像结构；通过索引的十八条规则读起来像网格，而眼睛开始跟踪线条而不是文字。轨道、部分规则、组规则和网格轮廓很快就会累积，每个看起来局部上都是可以接受的。Rails、部分规则、组规则和网格轮廓很快就会累积，每个看起来局部上都是可以接受的。
- 轴决定了计数和密度之间的权衡。空间可以替换水平规则，因为它分隔按顺序读取的记录，唯一成本是滚动。空间不能替换垂直规则，因为它分隔同时读取的列，并且没有间隔预算可以加宽。首先删除水平规则，并保留垂直规则，这些规则承载多列网格。

永远不要将规则放在关系上。图像及其标题、标签及其字段、记录及其元数据必须读起来像一件事。分隔符属于同级元素，而不是对一对元素。

- 计数每个控件的边界，而不是每个元素。一个带边框的输入框在一个带边框的表单中，表单中有一个带边框的提交按钮，绘制一个控件三次。一个安静的填充可以用作边界，而不是规则。
- 保留原始的安静事物安静。原始版本中不携带边界的控件不会从重设计中获得边界，并且将其装箱会将其提升到邻居之上，没有任何理由。

- 线条是相互比较的，所以删除大多数线条会提升幸存者。在任何删除规则后的任何步骤中，重新检查你保留的任何线条。
- 对于重复记录，用一个小间隙将元数据绑定到其记录，用一个大间隙分隔重复记录：眼睛根据相对距离分组，不需要线条。只有在空间替换它将花费的密度比表面可以承受的情况下，才使用细线；命名你做的交易。
- 交替行填充是空间和细线之外的第三个选项，对于长列表，它优于两者。它不占用垂直空间，也不绘制线条，而空间可以在列表中添加数千像素的垂直高度，而细线每 100 像素绘制一条规则。保持它非常安静，大约 3%，并记住它移动了它上面所有内容的对比度算术。

记录之间的间隙必须大于记录内部最大的间隙。测量它而不是估计：一个操作行固定在底部的卡片与一个短项目之间的空间与一个慷慨的间隔提供的项目之间的空间一样多，而一个慷慨的间隔提供了控制，然后读取为属于记录下方的记录。如果内部间隙无法减少，间隔必须增长以超过它，这会降低密度——这是正确的分组的价格。
- 优先使用细分隔符而不是带框卡片，当分组仍然清晰时。
- 在分割数据区域中，使共享边框干净地相遇。分隔符应跨越其预期容器，相邻单元格应共享边缘，而不是由于填充不一致而造成的近似间隙。
- 保持角落半径受控，通常为 6–12px。
- 允许完全圆形的药丸按钮，但它们不是默认值。选择按钮形状作为组件系统的一部分，而不是每个实例：等效的主要 CTA 必须在整个页面上共享相同半径、高度、填充和重量。如果主要按钮是药丸，则所有主要按钮都使用药丸处理；如果它使用受控的 6–10px 半径，则在整个页面上重复该处理。标签和过滤器可以使用单独的药丸系列，因为它们的作用是不同的。不要用药丸用于数量控件、大型字段、面板或密集操作控件。

- 治理相邻控件作为一组：匹配它们的高度、半径和水平范围，并保持它们之间的间隙小于它们与周围任何内容的间隙。一个仅重申旁边标签的图标是装饰；保持图标，而不是重复标签的地方。

- 每个轴上的间距只设置一次。在添加包装的包装之前，检查子元素是否已经携带它，因为继承的组件 CSS 通常会携带它，两者将堆叠。更改填充、行高或高度时，重新检查任何针对该元素定位的内容。绝对定位的切换和内嵌指示器不会随着它移动，并且添加的偏移量在更改任何其他内容时都会漂移。
- 避免阴影，除非提升传达行为。当阴影是必要的时，使用一个几乎看不见的中性阴影，而不是一个大的模糊。在接近黑色画布上，阴影什么也不做，所以等效工具是一个几乎看不见的白色径向光晕，并且使用与阴影相同的测试。光晕的升级触发针对装饰，而不是提升。

## 结构重新设计

布局和构图在现有结构阻止技能的层次结构、清晰度或章节节奏时都在范围内。保留产品意义、内容和功能以及交互结果—not 现有的 DOM 或排列。

结构许可不是重新排列一切的责任。保留有效的构图，当它已经使主要任务和内容关系明显时。不要用一种熟悉的、强大的产品布局来替换它，仅仅是为了让重新设计看起来更引人注目。

技能可以：

- 更改页面网格、列比例、最大宽度、对齐和部分顺序。
- 移动、合并或拆分部分，以创建更清晰的叙事和任务流。
- 用分隔符、功能行、编辑章节或一个主导媒体构图替换重复的卡片网格。
- 重新构建英雄、导航、社交证明带、产品演示、客户评价、比较或页脚。
- 将支持内容更靠近它解释的控制或结果。
- 将一个分散的小视觉集合转变为一个大的产品截图、照片、视频或插图。
- 创建或提取组件，当新的构图需要更干净的实现时。
- 使用不同的桌面和移动构图，而不是在较小尺寸上保留相同的网格。

在做出大的布局更改之前，声明结构问题和预期层次结构。优先考虑一个连贯的构图，而不是许多局部调整。不要仅仅为了使页面看起来稀疏而删除内容或功能。

媒体后面的填充可能是可供性而不是装饰。一个平坦的面板在图像下方通常是一个占位符，它在图像加载时保留位置，所以删除它会使每个未加载的图像都变成一个带有孤立的标题的白色孔，对于淡入效果也是如此，它可以完全透明。在清除媒体后面的背景之前，检查它。

装饰性装饰消失时，保留的空间不会消失。一个围绕插图的面板或一个偏移网格以清除装饰，会留下一个空洞，读起来像空虚而不是平静，这在小尺寸上也是如此，一个控件仍然保留一个图标的空间，你移除了。关闭释放的空间要故意地。

当装饰性装饰也是控件的唯一可见输出时——一个渐变，一个选择器会改变它，一个动画，一个按钮会重播它——安静它不是删除它的同义词。降低它，这样控件仍然有东西可说，并验证状态仍然彼此可区分。

当装饰性装饰因项目而异时，扁平化它而不是降低它。每个项目后面的不同色调背后的不同灰色读起来像每个项目后面的不同灰色，这读起来像一种不存在的编码；一个单一的平面表面说出了原来的话，而原来的话是空的。这仅适用于界面的图标。表情符号在产品截图、某人的帖子或显示名称中是内容，并且编辑它们与编辑照片的错误相同。

然后检查容器是否仍然值得其位置。每项商品化颜色都是如何变成一个墙，而不是一个卡片网格——均匀的卡片没有主导元素——扁平化它会消除产品显示而不是描述的地方。

一个填充的强调动作如果靠近产品自己的标志并在同一区域，按钮将胜过标志和身份时刻。将按钮设置为中性，让标志是那里唯一的颜色。这假设标志有颜色要被胜过；如果标志以黑色发送，则没有身份时刻要保护，强调可以保持。

相同的推理适用于比例，而不仅仅是颜色。当名称牌和英雄标题都以显示尺寸大声喊叫时，名称牌在与旁边的元素竞争时是在竞争页面，而不是标题。保留一个超大的标志是合理的，只有当旁边的元素被降级时，标志才会比原来做更多的身份工作，因为它不再是两个中的任何一个。

让页脚变得更密集，但保留相同的排版、对齐和中性处理。

在移动设备上，保留每个章节的顺序和层次结构。堆叠并简化；不要仅仅缩小桌面构图。

## 交互和运动

运动应该感觉安静、立即和有目的的。仅在提供反馈、空间连续性、状态指示或防止刺耳的变化时才添加它。

- 不要对键盘启动或非常频繁的操作进行动画处理。
- 减少用户每天执行十几次的交互的运动。
- 保持普通 UI 运动在 300ms 以下；使用更长的运动仅用于罕见的情况说明时刻。
- 使用 `ease-out` 用于入口和出口，`ease-in-out` 用于已经在屏幕上的运动，`ease` 用于颜色或悬停过渡。避免 `ease-in` 用于响应式 UI。
- 优先使用 `transform` 和 `opacity`；避免在复合替代方案存在时动画化布局属性。
- 永远不要从 `scale(0)` 进行入口动画。当缩放是合适的时候，使用一个微妙的 `scale(0.95–0.98)` 与不透明度。
- 锚定弹出框和菜单到它们的触发器；居中的模态框可以保持居中。
- 如果按下的反馈适合产品，使用一个微妙的 `scale(0.97)`，持续约 100–160ms。
- 使快速触发的和手势驱动的运动可中断。
- 尊重 `prefers-reduced-motion`，保留有用的颜色或颜色反馈，同时去除不必要的运动。
- 将仅悬停的运动限制在 `(hover: hover) and (pointer: fine)` 之前。

不要仅仅为了使静态界面感觉更精致而添加动画。当不确定时，删除或减少它。

停止永久装饰性运动意味着将其返回到静止状态，而不是冻结它。禁用动画本身将元素留在它最后帧放置的位置，对于标语或轮播图来说是一个任意的偏移量，内容被切断了容器边缘，对于淡入效果来说可能是完全透明。清除动画所驱动的转换或透明度，并确认捕获到的结果是您预期的静止状态。

## 升级触发器

在范围内发生时，纠正这些，除非品牌或功能明确需要它们：

- 系统中立的暖色或冷灰色代替中性 alpha 黑色色调，包括默认边框颜色继承自设计系统。系统从产品自己的品牌颜色系统系统性地派生出来的中性色，并始终如一地使用的是品牌，而不是一种色调来纠正。
- 衬线显示排版或混合衬线/无衬线系统
- 全大写文本或 CSS `text-transform: uppercase`
- 全小写导航或控制标签
- 表情符号用作界面图标
- 分隔符分隔元素与其自己的标题、标签或元数据
- 屏幕上的规则比读者能数的更多，而空间可以完成相同的工作。在密集查找表面上分隔同级元素的规则购买密度，所以询问可以替换它们的元素是什么，然后再计算它们是否为杂乱。

- 装饰性渐变、纹理、光晕或饱和颜色没有意义
- 大型或分层阴影仅用于使表面看起来更高级
- 均匀的卡片，没有主导元素。每个大小和重量都相同的大容器，每个都包含真实的产品媒体，是一个便当，而不是卡片网格，扁平化它会消除产品显示而不是描述的地方。

- 药丸用于普通的矩形控件或容器
- 相同按钮和 CTA 之间的混合半径、高度或填充
- 不一致的间距、对齐、半径、边框不透明度或图标处理
- 比层次结构需要的更多类型样式或字体权重
- 过大的标题或空白空间降低了有用的密度
- 低对比度正文或控件
- 从状态、焦点、警告、错误、成功、选中、活动或破坏性状态中删除颜色
- 伴随语义颜色的形状或符号被扁平化，留下状态由色调本身携带。检查剩余的内容是否仍然足够强，足以读作状态：一个选中的选项卡与其邻居仅由细线区分，一旦其填充变为中性，就会失去可供性。重新编码它，而不是确认存在差异。

- 语义颜色作为排版或标签规则的影响的副作用被删除。这是它通常丢失的方式，而不是一个有意识的调色板更改：一个 breaking-news 标志和一个普通的标题通常是一个元素，具有相同的标记，它们之间的区别仅在于它们读取的标记，所以一个关于大小和跟踪的规则，它还设置了 `color`，将状态与您精心保留的标记一起带走。

- 没有功能目的的运动

## 纠正顺序

优先考虑早期的动作而不是晚期的动作：

1. 修复页面流、层次结构、导航、分组和控制到内容映射。
2. 当当前构图阻碍这些目标时，重新设计布局。
3. 移除装饰、重复的表面和重复的标签。
4. 归一化间距、对齐和信息密度。
5. 归一化排版、度量、跟踪和行高。
6. 将颜色、边框、半径和提升合并到共享令牌中。更改任何令牌之前，找到每个消费者并检查每个使用它*为什么*，因为同一个值会使填充平静，而作为边框会大声地作为边框：一个以黑色为基准的强调色会平静地阅读每个阅读它的按钮，并将柔和的金色细线变成一个硬黑色盒子，在改变后比改变前更响亮。设计系统也在几个角色中花费一个令牌，所以品牌令牌通常以别名形式定义了活动状态，而装饰性徽章可能借用了一个真实错误状态的价值。当同一个令牌服务于两个工作，这通常是发现——分割它，而不是选择一个折衷值。

7. 完善控件、可供性、焦点、悬停、按下、禁用、加载、空和错误状态。
8. 只有在静态层次结构起作用后，才添加或调整运动。

## 工作流程

1. 确定调用模式和精确范围。
2. 完成重新审视并确定主要任务和层次结构。
3. 评估候选更改是否符合操作姿态。
4. 按纠正顺序应用更改，重用和扩展现有系统，而不是创建一个平行系统。
5. 机械和视觉验证。
6. 报告更改了什么，为什么，以及应该保留什么。

## 验证

### 浏览器验证

如果有任何浏览器、预览、截图或计算机使用工具存在，则需要视觉验证：

1. 启动或定位到真实应用程序并打开精确更改的路线。
2. 在更改前后捕获固定的桌面和移动截图。
3. 检查渲染的截图，而不是依赖代码或 DOM 结构。
4. 测量交互状态，而不是拍摄它们。悬停、焦点或按下规则可能会失去特异性比赛并简单地从未触发，这是截图无法发现的，所以阅读计算样式并强制状态，而不是信任你写的规则是那个获胜的规则。
5. 在渲染输出中验证删除项，而不是在声明中。不是每个行都是边框：界面使用 `box-shadow`、一个 `::before` 或 `::after` 条纹，或者一个元素折叠为单个像素来绘制它们，所以删除一个 `border` 并不是证据线条已经消失。枚举界面实际绘制的元素，而不是源提到的元素。

6. 检查缩小的控件。几像素的错位在页面规模上是看不见的，并且会幸存于修复和全页验证通过。

7. 执行主要交互、键盘焦点、悬停或按下状态以及任何更改的响应行为。

8. 给窄视口自己的通过，而不是检查。为宽列编写的填充、插入和边框是手机宽度的一大部分，并且一个在 1440px 处是精细的规则，在 390px 处是一个回归。

9. 检查浏览器控制台中的错误和视口中的剪切或水平溢出。

10. 对于长页面，滚动通过每个章节的完整页面或多个视口段；第一折是不够的。

11. 修复可见问题并重新捕获，直到结果通过。

如果没有任何浏览器工具，请说明视觉验证不可行。永远不要声称仅通过代码检查就能进行视觉验证。

此列表中的四个检查很难通过肉眼完成，并且已在 `scripts/` 中脚本化，旁边是这个文件。每个都需要一个 URL，通常是您开发服务器上的路线，并且只需要 `playwright-core` 加上本地 Chrome：

- `node scripts/lines.js <url>` — 页面绘制的每个规则，水平和垂直，以及绘制它的机制。在删除分隔符后的任何步骤运行它。
- `node scripts/tints.js <url>` — 色调，其通道扩散将其标记为色调中性色，以及一个饱和颜色清单，一个单色通过中性和单色通过中性和单色通过中色必须考虑的饱和颜色。 
- `node scripts/density.js <url>` — 每屏可见的项目，所以密度声明是测量的而不是估计的。
- `node scripts/bands.js <url>` — 长页面被切分成可审查的视口高度捕获。

阅读它们打印的内容，而不是假设一个干净的运行意味着一个干净的页面：每个都回答一个狭窄的问题，而上面的部分说每个都可能在误导。

命名您无法达到的任何状态，而不是暗示整个表面都经过了检查。访问的链接、错误和加载状态以及认证视图通常在截图 harness 中无法访问。

当一个验证步骤因相同的原因反复失败时，将其写为脚本，而不是决定更加小心。一个使失败可见的工具比另一个指示要小心。

使用逼真的桌面和移动尺寸以及逼真的内容检查结果：

- 主要任务和下一个操作是明显的。
- 导航回答了用户在哪里、用户可以去哪里以及如何离开。
- 分组遵循邻近性和控件靠近它们影响的内容。
- 长文本、空状态、加载、错误和密集数据不会破坏布局。
- 对比度、键盘导航、可见焦点、触摸目标、语义状态保持可访问性。
- 较大的文本和窄屏幕不会崩溃层次结构。
- 不会绘制两次。匹配预期设计不是证据你的规则产生了它，所以检查现有的声明是否已经绘制了相同的像素，然后再添加你自己的。
- 不会偶然变得有意义。移除颜色可能会揭示一个在饱和内容中看不见的编码，当结果比原始版本更可读时，请停止，而不是进一步推向单色。
- 左对齐完成仅当容器、每个中间包装器和文本节点本身都被检查过。居中堆叠，并且纠正两个机制中的三个机制会留下一个块，其居中对齐，而其文本是左对齐的，这比开始时更糟。
- 长页面有明确的章节节奏，不会变成重复的卡片堆。
- 结果通过识别测试：只显示最终状态，一个从未见过原始版本的设计师会将其读作一个有意设计的斯堪的纳维亚表面，而不是原始版本去色。
- 每个原始表面的交互能力——操作、控件、导航、输入、切换器——仍然存在并且可以访问。清点功能，而不仅仅是内容和链接；安静控件是好的，删除控件不是。
- 表达性颜色保留在有意义媒体内或允许的唯一主要强调色内。
- 悬停、按下、选中、禁用和破坏性状态仍然可区分。
- 减少运动行为是存在的。
- 控制台是干净的，现有的检查仍然通过。

如果视觉检查发现歧义、过度空白或效率降低，请恢复必要的上下文或密度并再次检查。

## 护栏

不要：

- 使破坏性和中性操作在视觉上无法区分。
- 移除理解所必需的标签或边界。
- 在从未有过主要操作的表面上发明一个主要调用操作。一个主要操作意味着最多一个，而不是正好一个。
- 将品牌标志去色以匹配调色板。
- 在未经要求的情况下替换已建立的产品身份。
- 保留一个薄弱的布局仅为了最小化代码差异。
- 添加依赖项，当现有组件可以很好地解决问题时。
- 为了创建更清晰的屏幕而隐藏高级功能。
- 混淆新颖性与精致。
