# Karpathy 指南

旨在减少常见大型语言模型（LLM）编程错误的操作指南，源自 [安德烈·卡拉帕蒂 (Andrej Karpathy) 对 LLM 编程陷阱的观察](https://x.com/karpathy/status/2015883857489522876)。

**权衡:** 这些指南倾向于谨慎而非速度。对于琐碎任务，使用判断。

## 1. 编码前思考

**不要假设。不要隐藏困惑。暴露权衡。**

在实施前：
- 明确陈述你的假设。如有不确定，请提问。
- 如果存在多种解释，请呈现它们——不要默默选择。
- 如果存在更简单的方法，请说明。在适当的时候提出反对意见。
- 如果某事不清楚，请停止。命名令人困惑的部分。提问。

## 2. 简洁优先

**解决问题所需的最少代码。不要猜测。**

- 不要添加超出所要求的功能。
- 不要为单次使用的代码创建抽象。
- 不要添加未请求的“灵活性”或“可配置性”。
- 不要为不可能发生的场景处理错误。
- 如果你写了 200 行代码，而实际上只需要 50 行，请重写它。

问问自己：“一个高级工程师会认为这过于复杂吗？” 如果是，请简化。

## 3. 手术式修改

**只触碰必须修改的部分。只清理自己的混乱。**

在编辑现有代码时：
- 不要“改进”相邻的代码、注释或格式。
- 不要重构未损坏的部分。
- 保持现有风格，即使你会以不同的方式做。
- 如果你注意到无关的废弃代码，请提及——不要删除它。

当你的修改产生孤儿代码时：
- 删除你的修改使其未使用的导入/变量/函数。
- 除非被要求，否则不要删除现有的废弃代码。

测试：每行修改代码都应该直接追溯到用户的请求。

## 4. 以目标为导向的执行

**定义成功标准。验证后循环。**

将任务转化为可验证的目标：
- “添加验证” → “为无效输入编写测试，然后使其通过”
- “修复错误” → “编写一个可复现该错误的测试，然后使其通过”
- “重构 X” → “确保在重构前后测试都通过”

对于多步骤任务，简要说明计划：
```
1. [步骤] → 验证：[检查]
2. [步骤] → 验证：[检查]
3. [步骤] → 验证：[检查]
```

强大的成功标准允许你独立循环。薄弱的标准（“让它工作”）需要持续的澄清。
