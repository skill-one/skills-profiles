# 简化技术英语 (ASD-STE100)

ASD-STE100 是由航空航天和国防工业（ASD，欧洲航空航天和国防工业协会）建立的一种受控语言标准，旨在防止维护技术人员误读英语说明。该标准消除了误读的两个主要来源：具有多种含义的词语和具有多种可能结构的句子。

这项技能借鉴了同样的纪律，用于不同的读者：一个**AI 代理或下游系统**，它必须解析一个英语字符串——一个错误消息、一个工具描述、一个代理间指令、一个状态报告——而没有人在回路中解决歧义。如果维护技术人员可以将“关闭阀门”误读为形容词（“靠近的阀门”），而不是命令，语言模型也是如此。

## 何时使用此技能

- 代理的输出（解释、指令、日志消息、工具描述）读起来密集、术语密集或模糊。
- 文本将被另一个代理、一个翻译管道或一个非英语母语读者消费，而误读会带来实际成本。
- 您正在编写一个提示、系统消息或工具描述，并在模型看到它之前消除歧义。
- 您需要一个**前后对比**，显示哪些规则被违反以及重写如何修复它。请求它——默认输出仅是重写的文本（见输出格式）。

此技能不适用于创意或营销文案——STE 是故意平淡和字面的。不要将其应用于以声音、细微差别或说服力为要点的文本。

## 两种模式

在重写之前选择一个模式。如果用户没有说明，则根据文本类型进行推断，并在一行中说明选择。

**严格**——程序、错误消息、工具和函数描述、代理间指令、安全文本。任何地方错误的阅读都会产生成本。应用以下所有规则，包括硬长度限制和单词单义的纪律。

**STE 风格**——README、PR 描述、变更日志、解释性散文。完整应用结构规则，并将词汇规则视为建议（见核心重写规则中的该拆分）。实际上这意味着保持句子长度限制、使用主动语态、简单时态、无短语动词、无分号、无名词化以及无营销形容词，同时放弃单词单义的封锁：散文需要一定的范围，严格的散文重写读起来像人格移植，而不是澄清。

这两种模式和结构/词汇的拆分是从两个方向看到的相同区别。拆分说明此技能可以在没有 ASD 字典的情况下验证哪些规则。模式说明针对给定类型的文本应执行哪些规则。

## 来源和范围

此技能编码了 ASD-STE100 问题 9（2025 年 1 月）的**规则类别**：9 个部分涵盖词语选择、语法、句子结构和风格，涵盖了约 900 个批准的单词（每个单词一个含义、一个词性）和约 1,200 个需要避免的单词以及建议的替代词。有关完整规则摘要和引用，请参阅 `references/writing-rules.md`。

它**不**逐字复制 ASD 的约 900 个字批准字典。ASD-STE100 可以免费获得，但不是免费分发的：问题 9、第 2 页声明“未经 ASD 官员的书面授权，不得以任何形式复制或发布它，全部或部分”，并仅授予八个列出的类别（ASD/AIA/AIAC 成员协会及其成员公司和学生、成员国国防部、A4A、适航当局，以及用于教育目的的大学和研究所）免费复制权）。本项目不属于其中任何一个，因此字典不会包含在此存储库中。

相反，此技能应用**基本原理**（选择最简单、最常见的词语，并以相同的方式使用它）而不是对照固定单词列表进行检查。当确切的 ASD 批准措辞很重要时（例如，实际的飞机维护文档），获取标准并对照真实字典逐字检查。从 [官方下载页面](https://www.asd-ste100.org/STE_downloads.html) 请求它——请注意，这是一个将链接通过电子邮件发送给您请求表单，而不是直接下载。

## 核心重写规则

STE 的规则分为两类，此技能只能完全提供其中之一。**结构规则**是自包含的：它们描述句子结构，并且您可以根据描述单独应用它们。**词汇规则**完全由官方约 900 个单词的字典定义，而此技能故意不复制（见来源和范围）。如果没有该字典，词汇规则将从可检查的标准降级为对简单词语的偏好。

自信地应用结构规则。将词汇规则作为方向，并在输出中说明，而不是暗示您无法验证的字典合规性。

### 结构规则——应用这些

| 规则 | 做 | 不要 |
|---|---|---|
| 主动语态 | "代理删除了文件。" | "文件被代理删除了。"——除非行为者确实未知或不相关 |
| 无短语动词（规则 9.3） | "取下面板。" / "开始工作。" | "取下面板。" / "启动工作。"——一个两词动词具有部分不预测的含义 |
| 每个句子一个指令 | "打开文件。读取第 3 行。" | "打开文件并读取第 3 行，然后检查是否匹配。" |
| 句子长度 | 指令/程序 ≤20 个词，描述 ≤25 个词 | 长复合/从句句子 |
| 无分号（规则 8.1） | 分成单独的句子 | 任何分号——STE 完全禁止该标点符号，而不仅仅是作为从句连接符。（规则 8.1 允许每个其他标准标点符号。连字符*不*被 STE 禁止，尽管它通常表示应该拆分的句子。） |
| 名词簇 | 作为名词短语堆叠 ≤3 个词（“燃油泵阀门”） | 4+ 词名词堆栈（“高压燃油泵入口阀门组件”） |
| 无省略号 | 即使读起来更长，也要保持主语、动词和冠词明确 | 为了节省空间而省略词语（“文件未备份将被丢失”）→ 模糊哪些文件） |
| 保持情态 | "请求**可能已**失败。" 保持 "may have" | 将模糊词升级为事实（“请求失败。”）或发明源未声明的确定性 |
| 段落限制 | 每个段落一个主题，≤6 个句子 | 多主题段落 |
| 列表用于序列 | 使用编号或项目符号列表表示 3+ 步骤或条件 | 将序列隐藏在一个散文句子中 |

### 词汇规则——仅作为方向

| 规则 | 做 | 不要 | 为什么在这里较弱 |
|---|---|---|---|
| 单词一个含义 | 为一个动作选择一个动词并重复使用（例如，始终使用 "check"，从不将 "check"/"verify"/"confirm" 用于同一动作） | 在整个文档中对同一想法旋转同义词 | 文档内的连续性是可检查的。哪个词是*批准*的，如果没有字典，则无法确定。 |
| 单个词性 | "向阀门加油"（油=名词） | "给阀门加油"（油=动词） | "油" 是否作为名词仅被批准是一个字典事实。当两者读起来同样好时，请优先使用名词形式。不要声称合规。 |
| 动词，不是名词（规则 3.7） | "分析日志。" | "对日志执行分析。"——动词形式的动作使句子更长并隐藏谁行动 | 规则 3.7 说“使用**批准**的动词来描述一个动作。”优先使用动词形式是任何地方都可以安全应用的。知道哪个动词是批准的需要字典。 |
| 领域术语 | 保持必要的技术名词/动词，但如果不是常用英语，则一次定义它们（STE 允许项目特定的词汇表，超出其基本字典） | 使用术语而不定义它 | 词汇表允许是真实的 STE，但其扩展的基本字典不包含在此。 |

### 简单时态——应用一个例外

STE 允许不定式、祈使句、简单现在时、简单过去时、简单将来时和过去分词作为形容词。它排除了现在完成时和其他复合形式：“我们收到了报告”，而不是“我们已收到报告”。

飞机手册永远不会需要现在完成时，因此该排除对标准来说没有损失。其他文本并不总是如此幸运。“工作已完成”（并且其输出现在可用）和“工作已完成”（在某个过去点）是不同的陈述，状态文本经常需要第一个。**当复合形式携带简单形式无法携带的信息——当前相关性，或作为“可能已失败”的模糊词——保留它并标记偏离。** 否则，遵循该规则。

## 扫描检查清单

这六个习惯涵盖了机器编写英语难以解析的大部分内容。每一个都是机械的：您可以指向违反规则的精确单词或标点符号，而无需做出判断。在重写任何东西之前，扫描所有六个。

1. **同义词旋转**——同一个东西在一个文档中获得几个名称（“用户”、“客户”、“客户”。）读者无法判断它们是同一个东西还是三个。修复：选择一个名称，每次使用它。
2. **模糊词堆叠**——辅助动词和限定词堆积起来，直到句子声明无事（“它很重要，要注意的是，这可能可能有助于改进”。）修复：陈述声明，或者删除它。
3. **名词化**——动作冻结成名词（“执行分析”、“提供帮助”。）修复：使用动词（“分析”、“帮助”。）
4. **营销形容词**——声称质量而不是展示它的词语：无缝的、强大的、强大的、尖端的、轻松的、飞快的。修复：删除，或用证明该声明的测量值替换它。
5. **连写句子**——由分号或连字符连接的几个想法。修复：每个句子一个想法。
6. **软短语动词**——启动、联系、深入、开始。修复：使用单个简单动词（开始、联系、阅读、开始。）

## 流程

1. 选择模式（严格或 STE 风格）。仅在用户要求规则表时才说明（见输出格式）。
2. 一次阅读输入文本以理解含义——在理解它必须仍然说什么之后，不要开始重写。
3. 逐句阅读它。从核心重写规则表和扫描检查清单中的每个习惯标记每个规则违规。在 STE 风格模式下，标记词汇规则，但不要执行它们。对于结构规则的机械首次扫描，运行 `scripts/ste-lint.py`（stdin 或文件参数，`--json` 用于结构化输出）；它检查分号、句子长度、短语动词、名词化、营销形容词、同义词旋转、支持列表项中的悬垂连词、被动语态和复合时态，并且按设计从不标记模糊词或情态。`--baseline N` 容忍 N 个硬违规（用于采用现有文档）；`--disable rule1,rule2` 静默命名规则。
4. 重新编写每个标记的句子以修复违规，同时保留原始含义完全准确。如果一个重写会丢失必要的精度（安全条件、范围限定符、数字），请保留较长的措辞并标记它，而不是无声地简化。
   - **在提交重写之前检查情态。** 模糊词（“可能”、“可能”、“有时”、“很可能”）携带作者的信心，而信心是内容。一个缩短的句子将模糊词升级为事实并不是简化——它是一个不同的声明。这是精心意图的 STE 重写最常见出错的方式，因为模糊词正是长度限制试图剪切的东西。
   - 从不添加源未声明的事实。一个重写因为提供了原因、频率或机制而读起来更好，已经停止成为重写。
5. 输出重写的文本（见输出格式）。保持模式选择和规则分析内部，除非用户要求看到它们。
6. 如果输入已经符合，请说明——不要强制对合规文本进行更改。

## 输出格式

**默认：仅重写的文本，无其他内容。** 大多数调用者希望得到一个可以粘贴到工具描述、错误字符串或提示中的结果。单独打印简化后的文本。不要添加关于此技能的前言、模式公告、违规计数、更改摘要、规则表或进一步解释的结尾提议。

允许的唯一附加：如果步骤 4 故意保留较长的措辞，请在文本后添加一行，以 `Kept as-is:` 开头，命名该短语以及将丢失的精度。当没有可报告的内容时，省略该行。

**按请求：规则表。** 当用户要求看到推理时——“显示差异”、“哪些规则被违反”、“解释更改”、“前后对比”——输出此表代替：

```markdown
| 违反的规则 | 原始 | 简化 |
|---|---|---|
| 现在完成时态 | "我们已收到您的请求。" | "我们收到了您的请求。" |
| 名词簇（4+ 个词） | "代理任务队列优先级处理程序" | "设置任务队列优先级的处理程序" |

模式：严格。7 个违规被发现。
```

跟随表格，对您故意**没有**简化的任何内容以及原因进行一行说明（通常：简化会丢失必要的精度）。

## 边界

**会：**

- 将模糊或密集的英语重写为简短、单义、主动语态的句子。
- 默认情况下仅返回重写的文本，并在用户请求时命名其应用的规则。
- 保留原始中的每个事实、条件和范围限定符。
- 保留每个模糊词的力量，并添加源未作出的任何声明。
- 建议为必须保留的领域术语提供一个一行词汇表条目。

**不会：**

- 逐字复制 ASD 的官方约 900 个字字典，好像它被逐字记忆了——始终将官方下载视为确切批准措辞的来源。
- 简化创意、营销或说服性文案，其中声音和细微差别是重点。
- 无声地删除安全条件、例外或范围限定符以缩短句子——它将标记权衡而不是无声简化。
- 将“可能已失败”转换为“失败”，或将“可能是 X 的原因”转换为“X 是原因”——丢失模糊词会改变声明。
- 保证航空航天/国防级的 STE 合规文档。这是一个受 STE 启发的通用清晰工具，而不是一个认证的 STE 签名工具。
- 使弱内容成为真实或有用。STE 修复文本的*形式*，而不是其内容。一个空洞的段落在这些规则下重写后成为一个干净、简短、标点清晰的空洞段落。如果文本什么也没说，没有重写可以修复——请这样说，而不是润色它。
- 短到失去清晰度。压缩单词不是目标。消除歧义是目标。在某个点上，压缩开始让读者花费时间而不是节省时间，所以当句子无歧义时停止，而不是当它最短时停止。
