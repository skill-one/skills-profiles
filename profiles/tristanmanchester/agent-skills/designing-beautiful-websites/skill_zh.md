# 清晰、独特的网页界面

确保目的和下一步操作易于理解，使用符合产品受众的视觉语言。基于真实内容和行为进行构建，然后有目的地使用排版、间距、色彩、图像和动效。美不是一种通用的调色板，也不是圆角卡片网格，更不是去除所有装饰的义务。

## 确立实际的设计任务

阅读请求、现有实现、设计系统、资源以及相关内容。识别用户、页面目的、重要流程、品牌信号、目标平台和限制条件。使用提供的答案；推断常规默认值和推论性假设，而无需重复问卷调查。

对于本地优化请求，除非结构问题阻碍了请求结果，否则保持本地化。对于新网站，选择一致的方向并实现请求的交付物，而不仅仅是返回一个规划包。对于审核，展示材料问题、位置和影响，以及具体的修复方案。不要声称与页面有过交互，而实际上只有一张截图可用。

## 先结构化，后装饰

追踪用户从进入到完成和恢复的关键任务。使标签、内容顺序、导航和反馈易于理解，无需内部术语。保留做出决策所需的上下文；更少的话语或点击不总是更好。区分必需步骤和意外摩擦，包括权限、确认、取消和获取帮助。

从内容和优先级开始布局，而不是通用的应用外壳。使用有意义的分组、对齐和空白。定义实际长文本、翻译、缺失图像、表格、错误、加载、空结果和成功状态如何适应。设计信息顺序和控制，以适应窄屏幕、缩放和键盘使用，而不仅仅是缩放后的桌面截图。

## 给界面一个视觉视角

首先使用项目已建立的视觉系统。对于新方向，选择一小部分有意特征：例如，为出版物选择编辑型排版和非对称构图，为技术工具选择精确紧凑的控制，或为酒店网站选择慷慨的摄影和温暖材料。这些是可能的方向，而不是无论简报如何都适用的模板。

通过字体大小、粗细、行长度、间距、对比度和位置建立层次结构，然后再添加更多装饰。使用一致的间距/字体比例作为起始规范，然后允许根据视觉或内容特定进行调整。根据构图使用边框、阴影、背景和插图；对阴影的普遍偏好不是质量规则。

使主要内容和操作可见，而较安静的支持信息。使用有目的的图像和裁剪/焦点选择，而不是随意的库存资产。仅使用有合适权利的资产；不要凭空编造客户标志、评论、奖项、统计数据或产品功能来填充布局。将合成内容标记为占位符。避免虚假稀缺性、隐藏拒绝或误导性价格展示。

在有助于定位或反馈的地方使用克制、有目的的动效，并减少动效和可用的静态状态。不要为简单CSS已能实现的效果添加沉重的库、动画系统或客户端边界。

## 实现完整状态和语义

将按钮作为操作，将链接作为导航。使用现有的组件系统和框架规范；在重新设计时保留refs、焦点、表单提交、验证和加载/错误语义。看起来被禁用的控件必须具有正确的交互行为。定义网络故障、重复激活、取消或过时数据之后会发生什么；视觉反馈不是写入成功的证明。

对于表单，保留输入的数据，并使错误具体且可恢复。对于菜单/对话框/选项卡，使用适当的语义模式和键盘/焦点行为，而不仅仅是带有角色属性的样式化容器。不要在脆弱的JavaScript揭示成功之前隐藏重要内容。在字体/媒体加载时保持布局稳定。

阅读[可访问性](references/ACCESSIBILITY.md)进行针对性检查。对比度或自动扫描只是证据，不是可访问性证书。

## 检查、测试和迭代

快速的第一印象或启发式走查是有用的专家检查；它不是测量的用户测试，不能建立转化率或任务成功率。在请求测试时，使用实际参与者或观察到的交互，并记录范围、条件和结果。不要凭空编造成功的扫视测试。

对于实现，运行授权的相关项目类型检查/构建/测试，然后在有意义宽度、缩放/文本大小、交互状态和输入方法处检查渲染输出。检查焦点、可访问名称、滚动、裁剪、内容换行和浏览器/控制台故障。记录实际测试的内容。静态截图无法建立键盘或屏幕阅读器行为；测试计划不是完成的测试。避免不支持的性能或转化声明。

对于交接，提供实际的补丁或请求的设计工件、有用的更改令牌和组件/状态规则，以及未解决的验证。小的编辑不需要新的站点地图、完整的设计系统或七部分报告。当工作服务于任务时停止；不要为了新奇而不断重新设计一致的选择。
