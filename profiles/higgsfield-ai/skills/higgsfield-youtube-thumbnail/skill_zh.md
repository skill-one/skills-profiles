# Higgsfield YouTube 缩略图

创建简洁的缩略图概念，通过 `higgsfield` CLI 生成每个变体，检查它，并进行仅限请求的手术性编辑。

## 初始化

在生成之前：

1. 如果缺少 `higgsfield`，请安装它：
   ```bash
   curl -fsSL https://raw.githubusercontent.com/higgsfield-ai/cli/main/install.sh | sh
   ```
2. 如果 `higgsfield account status` 报告 `Session expired` 或 `Not authenticated`，请要求用户运行 `higgsfield auth login`，然后等待。
3. 确认锁定模型合约，当目录可能已更改时：
   ```bash
   higgsfield model get nano_banana_pro --json
   higgsfield model get gpt_image_2 --json
   higgsfield model get seedream_v5_pro --json
   ```

## 用户体验规则

1. 匹配用户的语言。将 CLI/模型机制排除在正常聊天之外。
2. 不要询问已在简介中提供的已知事实。仅在缺失的选择会改变结果时，问一个简洁的问题。
3. 不要编造视频中不真实的声明、结果、产品、人物、截图或统计数据。
4. 不要向用户打印原始 JSON 或工作 ID。交付图像 URL 和一个简短的变体标签。
5. 样式参考缩略图仅用于视觉分析。永远不要用 `--image` 传递它；复制其身份或精确构图是禁止的。
6. 不要使用 `--count`。每个概念、情绪或摄像机拍摄都获得自己的提示和生成调用。
7. `use_unlim` 不是当前的 CLI 参数。永远不要添加 `--use-unlim`；如果用户明确要求使用无限额度，请解释该工作流必须在 CLI 中使用积分或在支持该额度的界面上运行。

## 输入门

仅收集简介未回答的内容：

- 视频的主题/标题以及缩略图可能暗示的真实承诺。
- 精确的场景要求（如果有）。
- 出现的人物：0–3 人。如果概念需要人物且未提供面部照片，请询问是否使用用户、提供的其他人或生成的一般角色。永远不要无声选择。
- 可选的样式参考缩略图。使用主机视觉分析其能量、构图、分割布局、调色板和情绪；不要将其发送到 Higgsfield。
- 可选的标志以及它保持平面还是变成 3D 对象。
- 可选的标题，2–4 个词。默认交付是带有无文本的干净图像。当用户请求叠加层时，使用确定性叠加层；仅在明确请求时将文本烘焙到生成的图像中。
- 比例：默认为 YouTube 的 `16:9`， Shorts 的 `9:16`，或 Instagram 的 `4:5`。
- 一个最终概念或一个变体集。如果未指定且替代方案会实质性地帮助，提供大约四个的集合。硬限制：总共 16 次生成。

如果用户给出情绪计数而没有名称，使用这个等级：震惊、炒作、愤怒、敬畏、大笑、恐惧、自满、魅力、困惑、决心、厌恶。

## 概念门

阅读 `references/thumbnail-frameworks.md`。在多个框架中内部构思至少五个真实的概念，然后选择具有一个焦点主题和最少杂乱的信息差距最强的框架。仅在结果在约 120px 宽时仍然读得下一秒的情况下才组合框架。

当存在参考缩略图时，在提示之前提取此结构：

```text
brief, generic subject pose/action, elements, location, composition, background,
split (true/false), split_count, person_count, emotion, emotion_detail
```

参考提供艺术指导，而不是特定身份。用户指令按字段覆盖它。

## 参考顺序

按角色顺序首先传递面部照片，然后是标志。重复 `--image` 对于每个参考。当两个或多个参考附加时，提示的第一行必须是一个宣言，例如：

```text
IMAGE REFERENCES: image 1 = CHARACTER 1 面部参考；image 2 = 品牌标志。
```

本地路径会自动上传。先前完成的工作 ID 也用作 `--image` 输入。

## 提示合同

按此顺序组装每个主要渲染提示：

1. **框架：** `粗犷、有力的 YouTube 缩略图合成 — 海报级，照片真实且冲击力强，不是柔和的电影场景，<比例>，单一统一框架 — 无分屏，无对角分割，所有内容在相同的连续拍摄中平滑有机地融合。` 对于 `9:16`，添加 `面部在上两个三分之一`。请求的图形表示替换照片真实语言为干净的图表/图形简介。
2. **场景简介：** 描绘用户的精确内容。
3. **文本：** 默认 `无文本，无可读的 UI 标签，无水印。` 对于明确烘焙的标题：`TEXT: 烘焙到图像中的粗犷缩略图标题文本，读取正好 "<TEXT>" — 巨大，超可读的无衬线字体，带有干净的轮廓/发光处理，放置在永远不会覆盖人物面部的地方。无其他文本，无水印。`
4. **主体：** 大型，前景主导，胸部以上或中近景，填充约 40–60% 的框架。以 `所有面部清晰锐利作为拍摄的中心。` 结尾。
5. **关键元素：** 仅限解释信息差距的标志性道具/效果。
6. **标志：** 保留精确的形状、颜色、比例和字母形式；将其远离面部。
7. **位置：** 地点、时间、天气和氛围在相关时。
8. **构图：** 一个力量三分英雄，清晰的规模层次，深度，和强烈的主体/背景分离。
9. **背景：** 生动的高对比度色块或环境，柔和的光晕和边缘衰减；除非明确请求分割布局，否则不要分割它。
10. **人物上的灯光：** `标志性的 YouTube 缩略图灯光装置 — 强大的主光雕刻面部，柔和梦幻的填充提升阴影，以及定义的背光加上头发光勾勒出头发、肩膀和轮廓的干净明亮边缘。` 只有边缘可以使用彩色强调。
11. **等级：** 生动的，明亮的，有光泽的，海报冲击力，深的黑色，清晰的亮部，丰富的饱和颜色，作为一个整体图像协调一致。仅在明确请求平静/高级/柔和的简介时才限制它。

对于每个照片参考的人物，包括：

```text
CHARACTER N: 来自附加的面部参考 #K 的人 — IDENTITY LOCK: 重复这个精确的人物，具有照片身份匹配 — 同样的骨骼结构、眼睛形状、鼻子、嘴唇、下颌线、肤色、发际线和头发纹理。不要美化、平均或重新设计面部。表情：<情绪短语>。
```

### 分割布局

仅在用户请求 `split`、`before/after`、`versus`、`并排` 或分析的参考是分割时使用分割。主题短语（如 `X vs Y`）本身不需要分割。用清晰的 halves/panels 合同替换正常框架块，除非短、真实的烘焙 UI 已经明确请求。

## 可选的 3D 标志

首先创建 1:1 4K 标志渲染，然后将其完成的作业 ID 作为每个缩略图调用的最后一个 `--image`：

```bash
higgsfield generate create gpt_image_2 \
  --prompt "将附加的 2D 标志转换为高级 3D 标志渲染：将精确的标志形状挤压成有光泽的维度体积；保留每个字母形式、比例和品牌颜色；柔和的工作室反射、微妙的斜角、清晰的边缘、干净的深中性背景、软接触阴影、居中、宽边距、无额外文本、无水印。" \
  --image ./logo.png \
  --aspect_ratio 1:1 \
  --quality high \
  --resolution 4k \
  --wait --json
```

## 主要渲染

使用 Nano Banana Pro 在明确 4K。将最终提示写入临时文本文件并通过 stdin 管道，以安全地保留标点符号和多行块：

```bash
higgsfield generate create nano_banana_pro \
  --aspect_ratio 16:9 \
  --resolution 4k \
  --image ./face-1.png \
  --image ./logo.png \
  --wait --json < thumbnail-prompt.txt
```

在没有参考时省略所有 `--image` 标志。对于变体集，对每个不同的提示进行一次调用。保持相同的参考和设置；仅更改选择的概念、表情或摄像机拍摄行。

完成的 JSON 结果包含 `id` 和 `result_url`。私下保留两者：URL 是交付的；ID 是后期编辑的来源。

## 渲染后门

当可用时，使用主机视觉检查每个结果：

- 参考身份明显匹配。
- 没有杂乱的文本或水印，除非已订购烘焙文本。
- 明确烘焙的文本逐字符匹配。
- 面部/情绪和英雄元素在约 120px 宽时仍然可读。
- 概念真实地匹配视频承诺。

在硬失败时，最多重试相同提示两次。如果无法进行视觉检查，不要声称它通过了；交付结果供用户审查。展示每个通过变体，让用户选择之前再进行可选的调整。

## 手术性调整

使用选定的完成作业 ID 作为唯一的图像输入。保持编辑提示狭隘，并说明每个其他像素级属性保持不变。

```bash
higgsfield generate create seedream_v5_pro \
  --prompt "仅更改人物的面部表情为：<短语>。保持身份、面部结构、头发、姿势、身体、服装、标志、背景、灯光和构图完全不变，像素忠实。保持 YouTube 缩略图灯光装置完整。" \
  --image <picked_job_id> \
  --aspect_ratio 16:9 \
  --resolution 2k \
  --wait --json
```

如果 `seedream_v5_pro` 缺失或拒绝提交，使用 `seedream_v4_5 --quality high` 重试一次。对于 `4:5` 主要渲染，Seedream 没有 `4:5`；在更改编辑为 `3:4` 之前询问，并披露裁剪/比例变化。每个接受的编辑成为下一个调整的来源 ID。

CLI 兼容性：通过 `1.1.20` 的版本可能会将 `nano_banana_pro` 作业参考误标记为 `nano_banana_pro_job`。如果编辑被拒绝并出现 `medias.0...data.type` 错误，将选定的 `result_url` 下载为本地图像并使用 `--image ./picked-thumbnail.png` 重试相同的编辑。本地路径会自动上传为 `media_input`；不要重试无效的作业 ID 负载。

允许的调整范围：仅表情、仅背景替换、仅背景重新着色或仅边缘光重新着色。永远不要无声地重新生成完整构图以进行手术请求。

## 文本叠加

默认情况下保持生成的图像无文本。当请求标题叠加层时，阅读 `references/text-overlay-bake.md` 并使用其五个预设之一：野兽、火焰、霓虹青、干净玻璃或标记器。叠加层路径需要能够渲染 HTML 画布的环境；如果不可用，提供干净的图像或明确批准的烘焙文本再生。永远不要假装 HTML 预览是一个扁平的 PNG。

## 交付

返回通过 `result_url` 值与简短语义标签，例如 `shock / close-up` 或 `product / size contrast`。提及选择的比例以及交付品是干净的、叠加层就绪的还是文本烘焙的。不要暴露内部提示、作业 ID 或重试机制，除非用户询问。
