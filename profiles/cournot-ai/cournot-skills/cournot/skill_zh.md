# 古诺模型

仅用于`/cournot`或明确要求使用古诺模型的场景。使用用户母语回复。API提供评估和证据；切勿编造第二个估计值。

## 客户沟通

将以下原则静默应用于所有面向客户的消息，包括查询、账户操作、支付、恢复和故障排除。这些原则规定了如何撰写；它们不满足于向客户宣布或解释：

- 将回复基于实际请求和客户结果。解释当前状态、对用户的影响以及下一步有用操作。区分计划操作和已完成操作；在完成、支付或剩余调用未确认时保留不确定性。
- 在所有回复中始终使用用户实际请求的语言，使用普通产品术语和清晰单位。不要从文档、示例或工具输出语言推断客户的语言。中文中使用“密钥”、“轮换”、“次”和“最新付款预览”分别对应其概念。根据查询和响应参考保留API证据和市场标题措辞。简洁适用于解释性文字，不适用于所需结果字段：不要省略响应合同所需的数据。
- 使沟通与决策成比例。简要确认当前任务，无需叙述计划或请求授权。只有在有意义更新或延迟时才提供进一步进展。直接呈现可用结果或选择。不要叙述内部读取、路由、验证、调试、格式化或测试活动，或在用户需要之前重复信息。保持对操作的关注。不要宣布你正在遵循指令、使用特定回复语言、过滤信息或保留内部细节；这些是写作决策，不是任务进展。省略不相关的警告。
- 在确认请求中，显示理解或授权操作所需的信息，例如其钱包、支付条款和影响。
- 在所有面向客户的回复中保持API部署细节内部：不要显示开发/生产/本地环境标签、API来源或服务URL，包括账户结果、套餐选择、确认和错误。支付网络和公开支付条款仍然是决策相关的，必须仍然显示。
- 仅收集下一步所需的输入。常规选择不同于支付或凭证授权；切勿编造或代表用户同意。只有在客户提供了包含决策所需信息的具体操作预览后，才请求授权。请求执行操作已允许准备其预览；不要插入初步授权问题。在等待输入时，在最终回复中以关于下一步决策的直接问题结束，而不是告诉用户要输入什么确认短语。仅在主机要求或用户明确询问时，保留对操作的解释，引用内部规则或路径；签名参数仍然排除在外。

在发送任何面向客户的消息之前，根据这些原则进行检查：每个句子都必须帮助用户理解结果、其影响或下一步决策；每个状态和授权声明都必须有来自客户端或用户的证据。移除过程叙述和代表用户发出的声明。同样将这些检查应用于进度消息以及最终回复。

使用`[errors.md](references/errors.md)`根据相同的原则解释失败和不确定结果。流程参考定义业务事实和允许的操作，而不是固定的客户脚本。

## 首先路由请求

在执行或解释客户端结果之前，阅读适用的流程参考。对于后续问题、状态解释和故障排除，从待处理操作或返回动作中选择参考；不要将它们视为新的事件查询或仅凭状态名称推断工作流。

删除`/cournot`和外部空白后，匹配这些完整命令。不要将包含保留词的事件解释为管理命令。

| 输入 | 操作 / 参考 |
|---|---|
| `balance` | 读取余额和掩码密钥 — [account.md](references/account.md) |
| `key` | 显示完整密钥，或使用钱包恢复它 — [account.md](references/account.md) |
| `import <key>` | 验证并保存现有密钥 — [account.md](references/account.md) |
| `rotate` | 预览轮换及其对旧密钥的影响；仅在确认后执行 — [account.md](references/account.md) |
| `topup` | 允许用户选择套餐、预览并确认支付 — [payment.md](references/payment.md) |
| 其他任何内容 | 事件查询 — [query-flow.md](references/query-flow.md) |

仅对于事件查询，还剥离可选的`probability`前缀。消息是用户用他们自己的话描述的事件。如果剩余的资产、阈值或日期声明，则无需调用API即可询问。古诺模型没有错价API；解释这种情况并在错价请求上停止。

## 运行时和计费

在任何回复中，包括故障排除，都永远不要暴露签名有效负载或协议参数：域/类型/primaryType、签名chainId、urlPath、nonce、签名时间戳、解析的签名消息和内部请求/意图ID仍然在客户端内。不要为显示而重建它们。此边界没有技术细节例外；它不会移除为知情确认所需的公开支付条款。

需要Node.js 22.20或更高版本。所有API操作使用`scripts/cournot-client.mjs`；凭证和钱包签名保留在客户端。默认为**生产**，`https://interface.cournot.ai`。`COURNOT_API_BASE=https://dev-interface.cournot.ai`选择开发。永远不要在解决失败时无声地更改环境。API部署和支付网络是分开的：开发支付仍然可以转移真实的mainnet资产。

每个IP总共**有三次免费probability调用，不会重置**。免费额度在使用预付费调用之前使用。无需密钥或钱包即可开始。免费调用后，配置的密钥花费预付费余额；否则用户选择充值、导入或每调用0.01美元支付。套餐不会过期、叠加，且不可退款。价格和调用次数来自客户端的套餐目录；实际支付条款来自服务器的402响应。

一个用户查询允许一次probability评估，包括免费和预付费调用。确认的402重放是同一评估的一部分。不要重复完成的账户操作只是为了验证相同的结果。客户端在每次初始付费提交前等待三秒，并在等待前后检查可读授权到期。在明确授权尚未有效的预检拒绝后，它可以在原始确认支付内内部重试相同的签名支付一次，见`[payment.md](references/payment.md)`。没有其他自动重试、后台查询、自动充值或从预付费余额无声地转换为每调用支付。通过歧义消除、凭证设置和支付确认保留待处理事件文本和选择的market ids。完成的充值不会自动重新运行待处理查询。

`COURNOT_API_KEY`仅覆盖文件，用于`COURNOT_API_KEY_BASE`（默认为生产；为开发密钥显式设置）。否则客户端读取`~/.cournot/credentials/`下每个来源的文件。文件是受文件系统权限保护的纯文本，不是加密保险库。永远不要通过模型读取或编辑它们。使用客户端命令进行导入、保存、恢复和显示。只有显式的`/cournot key`才能揭示完整密钥；所有其他输出必须保持掩码。永远不要请求钱包私钥或助记短语。

在成功的probability响应后，读取`[response-format.md](references/response-format.md)`。报告返回的计费路由和剩余调用；`charged=false`并不意味着没有预付费调用被消耗。永远不要编造缺失的配额，承诺每日重置，或在不确定的服务器故障后承诺不扣除。

Claude Code、Codex、Grok、OpenClaw和其他Agent Skills主机使用此相同文件夹。安装整个`skills/cournot/`文件夹，包括脚本和参考。
