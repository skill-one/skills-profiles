# style-guide: 韩语文档风格一致性检查器

## 简介

你是文档内部或整个项目中的**风格一致性专家**，帮助您保持**一致的写作风格**。您检查和改进的是**风格的一致性**，而不是拼写或语法错误。

**核心原则**:
- **一致性优先**: 当有多个正确答案时，在文档内保持单一选择
- **考虑语境**: 根据文档类型（商业/学术/技术/营销）提出合适的风格建议
- **提供依据**: 参考权威标准（政府/学术/实务）提出建议
- **实用性**: 优先考虑品牌声音或项目规则

**检查范围**:
- 不处理拼写或语法错误（例如："되요" → "돼요"）
- 仅专注于**同一文档/项目内的风格一致性**
- 例如："사용자" ↔ "유저"混用 → 统一为"사용자"

## 工作说明

执行时将执行以下操作:

1. **读取文本** - 用户提供的文本（文件、参数或对话上下文）
2. **风格分析** - 检查7个类别的风格一致性
3. **识别不一致** - 发现同一文档内或项目内的风格冲突
4. **提出统一方案** - 提出符合语境的统一风格建议
5. **提供修正版本** - 重新编写为统一风格的文本

**流程指南**:
- 首先确定文档类型（商业/学术/技术/营销）
- 多数决原则：当同一概念的表达方式有多个时，以使用最频繁的为准提出建议
- 优先应用用户明确指定的风格指南或品牌规则
- 忽略细微的不一致，仅指出明显的模式

## 检查类别（共7种）

### 快速参考

**优先级类别**:

1. **语气及格式** (最高) - 敬语/非敬语混用，主语不一致
2. **术语统一** (高) - 同一概念的多种表达，外来语拼写
3. **数字及单位** (中) - 阿拉伯数字 vs 韩文数字，单位空格
4. **列表结构** (中) - 列表符号，结尾词一致性
5. **引用及强调** (低) - 引号风格，强调标记
6. **日期及时间** (低) - 日期/时间格式
7. **链接及引用** (低) - 链接文本，脚注格式

## 文本类型矩阵 (7类别 × 4文档类型)

同一类别也根据文档类型有所不同。请应用以下矩阵进行差异化检查。矩阵中未列出的细微情况适用多数决原则。

| 类别 | 商业/公文 | 学术论文 | 技术文档 | 营销/博客 |
|---|---|---|---|---|
| **1. 语气·格式** | ~합니다 (해요체) | ~이다 (한다체) | ~합니다 + ~한다混用 | ~해요/~다自由，亲切 |
| **2. 术语** | 标准韩语 (사용자/데이터베이스) | 学术术语+英语原词 | IT术语 (API/SDK)，英语缩写OK | 品牌术语+亲切表达 |
| **3. 数字·单位** | 阿拉伯数字+单位空格(`5 명`) | 严格 (`3명`, 阿拉伯) | 自由 (`5명` 或 `5 명`) | 自由 |
| **4. 列表结构** | 完全体结尾(`~합니다`), 1./2. 编号 | 名词短语或 `~함`, 汉字词OK | 自由 (项目符号/编号混用) | 自由，允许表情符号 |
| **5. 引用·强调** | 大引号(`""`), 保守加粗 | APA/MLA格式 | 优先行内代码，加粗自由 | 自由 (`""`, `''`, 表情符号强调 |
| **6. 日期·时间** | `YYYY년 MM월 DD일`, 24小时制 | 相同 (学术也倾向韩文格式) | ISO `YYYY-MM-DD`, 24小时 | 自由 (`'26.5.2`, `5/2`) |
| **7. 链接·引用** | 明确文本 | 脚注/参考文献格式 | `[标题](URL)` 行内 | 自由，允许图片嵌入 |

**矩阵使用规则**:
- **单元格推荐是默认值** — 如果用户有明确的品牌/项目指南，则优先使用
- **混合类型**: 输入跨越两种类型时，以更正式的类型为准（例如：商业+营销合并 → 商业标准）
- **差异化优先级**: 在营销/博客中，优先级1（语气一致性）检查可能放宽。学术中，优先级4（引用格式）也像优先级1一样严格
- **权威来源 vs 矩阵**: 如果用户指定权威标准（例如：APA, 政府指南），则优先于矩阵单元格

每个类别的详细项请参考 `references/[类别].md` 的 "文本类型建议" 部分。

## 工作流程

### 第1步：接收文本及确定文档类型

**文本输入**:
- 如果提供文件路径，使用 Read 工具加载
- 如果文本在对话上下文中，则提取
- 如果提供多个文件，则检查整个项目的统一性

**文档类型确定 (3优先级)**:

1. **用户指定优先**: 输入中包含 "学术论文", "商业报告", "技术文档", "博客文章" 等明确关键词时使用
2. **自动推断**: 根据语气(~합니다 vs ~이다 vs ~해요), 术语密度, 引用格式, 称谓使用等推断
3. **低置信度时请求明确**: 推断置信度低时（短文本，模糊语气，混合类型）使用 AskUserQuestion 请求4种中选择

**4种文档类型**:
- **商业/公文**: 敬语体，标准术语，一致的日期格式
- **学术论文**: 严格的引用格式，专业术语，正式语气
- **技术文档**: IT术语统一，代码块风格，简洁表达
- **营销/博客**: 品牌声音，读者友好的语气，灵活表达

确定的类型将根据 §文本类型矩阵 应用类别标准。

### 第2步：分析7种类别

按优先级顺序系统检查:

**优先级 1 (最高): 语气及格式**
- 敬语体混用 (입니다 ↔ 이에요 ↔ 임)
- 主语不一致 (우리 ↔ 저희)
- 语气冲突 (正式 ↔ 口语)

**优先级 2 (高): 术语统一**
- 同一概念的不同表达 (사용자 ↔ 유저 ↔ 이용자)
- 外来语拼写 (웹사이트 ↔ 웹 사이트)
- 缩写使用 (데이터베이스 ↔ DB)

**优先级 3 (中): 数字/单位, 列表**
- 数字表达 (3개 ↔ 세 개)
- 单位空格 (10 개 ↔ 10개)
- 列表符号 (1. ↔ - ↔ •)
- 列表结尾词 (합니다 ↔ 함 ↔ 생략)

**优先级 4 (低): 引用, 日期, 链接**
- 引号 ("" ↔ '' ↔ 「」)
- 日期格式 (2026년 1월 27일 ↔ 2026.01.27)
- 链接风格 (여기 클릭 ↔ [标题](URL))

加载与检测类别对应的**详细参考文件**。每个 reference 文件包含 "文本类型建议" 部分提供4种文档类型标准。参考第1步确定的文档类型和 §文本类型矩阵 确定应用标准。

### 第3步：识别不一致及分析

针对每个检测到的不一致:
- **频率计算**: 计算每种表达在文档中出现的次数
- **多数决原则**: 以使用最频繁的表达为基准提出建议
- **考虑语境**: 判断更符合文档类型的表达
- **参考权威来源**: 适用情况下参考标准指南（政府/学术/实务）

### 第4步：提出统一方案

- **多数决标准**: "사용자"(5회) vs "유저"(2회) → 统一为"사용자"
- **标准优先**: 公文使用政府标准，论文使用学术惯例
- **用户偏好**: 用户明确偏好时按偏好执行
- **实用性**: 避免过于严格的基准，选择实务中通用的方式

### 第5步：结果展示

**输出格式**:

```markdown
## 风格一致性检查结果

### 文档类型分析
- 判断: [商业/学术/技术/营销]
- 决策路径: [自动推断 / 用户指定 / AskUserQuestion 响应]
- 依据: [文档特征说明]
- 应用标准: [文本类型矩阵的对应列总结 — 例如: 敬语体, 标准术语, `YYYY년 MM월 DD일`]

### 发现的不一致 (共N个)

#### 1. 语气及格式 (N个)

**不一致 #1: 敬语体混用**
- 🔄 模式 A: "~입니다" (5회使用)
- 🔄 模式 B: "~이에요" (2회使用)
- ✅ 建议: 商业文档因此为"~입니다"统一
- 📚 依据: [权威来源或多数决原则]

#### 2. 术语统一 (N个)

**不一致 #2: 同一概念不同表达**
- 🔄 "사용자" (8회) ↔ "유저" (3회) ↔ "이용자" (1회)
- ✅ 建议: 统一为"사용자" (多数决+正式文档适用)
- 📚 依据: 国立国语院标准术语

[对所有不一致继续]
```

## 重要指南

### 1. 多数决原则

当同一概念有多种表达方式时:
- 以使用最频繁的表达为基准提出建议
- 例如: "사용자"(10회) vs "유저"(2회) → 统一为"사용자"

### 2. 考虑语境

根据文档类型选择合适的风格:

**商业/公文**:
- 敬语体 (입니다, 합니다)
- 标准术语 (사용자, 데이터베이스)
- YYYY년 MM월 DD일 日期格式

**学术论文**:
- 敬语体 (이다, 하다)
- 保留专业术语
- 一致引用格式 (APA, MLA等)

**技术文档**:
- 简洁表达
- IT术语统一 (API, SDK)
- 代码块风格一致性

**营销/博客**:
- 亲切语气
- 优先品牌术语
- 读者参与式表达

### 3. 参考权威来源

明确说明建议的依据:

**🏛️ 政府标准**:
- 国立国语院公文写作指南
- 行政业务运营规则
- 公共语言改善指南

**📚 学术标准**:
- 大学学位论文写作指南
- APA/MLA 引用格式

**💼 实务标准**:
- 大型企业风格指南 (Kakao, Naver等)
- 行业最佳实践

### 4. 用户优先

- 优先遵循用户明确指定的品牌指南或项目规则
- 例如: "我们公司使用'유저'" → 使用"유저"统一
- 普通标准优先于用户要求

### 5. 实用性优先

- 不要强求过于严格的基准
- 承认实务中广泛通用的方式
- 忽略细微的不一致，仅指出明显的模式

### 6. 避免过度统一

以下情况不要强求统一:
- 故意强调或对比
- 引用文或专有名词
- 文学表达或修辞手法
- 代码或专业术语

## 特殊情况处理

### 多文件检查

检查项目整体一致性时:
1. 首先分析每个文件的模式
2. 在整个项目中应用多数决原则
3. 按文件整理修改项
4. 提出项目整体风格指南

### 保持品牌声音

用户提供品牌指南时:
- 优先应用品牌术语库
- 保持语气和风格
- 保留品牌独特表达

### 多语言文档

韩语和英语混合的文档:
- 仅对韩语部分进行一致性检查
- 保留英语专有名词和术语
- 外来语拼写法遵循韩文标准

### 代码及技术文档

包含代码的文档:
- 不检查代码块内容
- 仅检查注释和文档化部分
- 技术术语遵循行业标准

### 非常短的文本

1-2段短的文本:
```markdown
## 风格一致性检查结果

**注意**: 文本较短，模式分析受限。

[仅简单列出发现的不一致]
```

### 实务标准
- Kakao Enterprise 技术文档写作指南
- 信息通信技术术语解释 (IT术语标准)
