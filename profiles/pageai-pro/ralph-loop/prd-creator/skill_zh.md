# PRD 创建助手

通过两阶段流程，将软件构想转化为全面的 PRD（产品需求文档）和可执行的实施方案。

## 概述

本技能适用于初学者级别的开发者。

1.  接收用户提供的实施方案描述
2.  通过结构化提问创建详细的 PRD 文档
3.  验证实施方案前提条件，包括访问权限、MCPs（主要贡献者计划）、文档、环境变量和测试用户
4.  为开发者生成 JSON 格式的实施方案任务清单
5.  撰写项目整体描述。一份高层级的项目概述，介绍应用及其主要功能。

### 第一阶段：实施方案描述

您将收到用户提供的缺失实施方案描述。
主要目标是理解意图，并思考更大的架构和稳健的实施方式，填补空白。

### 第二阶段：PRD 创建

**文件**: [PRD.md](PRD.md)

您需要通过提问澄清问题，以清晰地理解实施方案。

**使用场景**: 用户希望记录软件构想或创建功能规格

**功能**:
-  指导结构化提问，收集所有需求
-  在 PRD 最终确定前验证项目前提条件
-  创建/更新 `.env.local`，仅使用占位符值
-  创建执行摘要以供验证
-  研究竞争格局
-  生成全面的 PRD.md，包括：
  -  应用概述和目标
  -  目标受众
  -  成功指标和 KPIs
  -  竞争分析
  -  核心功能和用户流程
  -  技术栈建议
  -  前提条件和访问权限
  -  安全考虑
  -  假设和依赖关系

**流程**:
1.  使用 `AskUserQuestion` 工具提问澄清问题
2.  验证前提条件并创建/更新 `.env.local` 占位符
3.  创建执行摘要以供用户批准
4.  通过 WebSearch 研究竞争情况
5.  生成完整的 PRD
6.  根据反馈进行迭代

**请阅读 [PRD.md](PRD.md) 获取完整说明。**

---

### 第三阶段：实施方案任务生成

**文件**: [JSON.md](JSON.md)

您需要分析完成的 PRD 并生成 JSON 格式的全面任务清单。

**使用场景**: PRD 完成并批准后，或用户请求任务分解

**功能**:
-  分析完成的 PRD
-  生成 `TASK-1` 作为强制性前提条件验证
-  生成 JSON 格式的完整实施方案任务清单，涵盖 PRD 中的所有功能和需求
-  保持任务简洁易管理
-  按类型（功能、UI-UX、API 端点、安全等）对任务进行分类
-  为每个任务定义验证（通过）步骤
-  创建开发者可用的检查清单

**重要提示**:
-  每个任务应简单到可以在最多 10 分钟内完成。
-  如果任务过于复杂，应将其拆分为更小的任务。

**请阅读 [JSON.md](JSON.md) 获取完整说明。**

## 第四阶段：整体描述

您需要阅读完成的 PRD，并在 `PROJECT_ROOT/.agent/prd/SUMMARY.md` 中生成项目整体描述。

描述应简短、简洁，并包含：
-  项目的整体描述
-  应用的主要功能
-  关键用户流程
-  关键需求简列表

## 快速入门

**如果用户希望创建 PRD**:
1.  阅读 [PRD.md](PRD.md)
2.  跟随 PRD 创建工作流
3.  验证前提条件并创建/更新 `.env.local`，仅使用占位符值
4.  如有必要，更新整体描述 [SUMMARY.md](SUMMARY.md)
5.  PRD 完成后，询问："您希望我生成实施方案任务吗？参见第二阶段。"

**如果用户希望为现有 PRD 生成实施方案任务**:
1.  阅读 [JSON.md](JSON.md)
2.  阅读 PRD 文件
3.  生成 JSON 格式的全面任务清单，从 `TASK-1` 前提条件验证开始
4.  保存为 `tasks.json`

**如果用户希望两者都做**:
1.  首先完成 PRD 创建 [PRD.md](PRD.md)，包括前提条件验证和 `.env.local` 占位符
2.  获取用户对 PRD 的批准
3.  如有必要，更新整体描述 [SUMMARY.md](SUMMARY.md)
4.  继续生成实施方案任务 [JSON.md](JSON.md)

**如果用户希望更新 PRD**:
1.  阅读 [PRD.md](PRD.md)
2.  更新 PRD
3.  保存为 `PRD.md`
4.  如有必要，更新整体描述 [SUMMARY.md](SUMMARY.md)
5.  询问用户是否希望生成实施方案任务

**如果用户希望更新实施方案任务**:
1.  阅读 [JSON.md](JSON.md)
2.  更新实施方案任务
3.  保存为 `tasks.json`
4.  询问用户是否希望再次更新 PRD

**如果用户希望同时更新 PRD 和实施方案任务**:
1.  首先更新 PRD [PRD.md](PRD.md)
2.  如有必要，更新整体描述 [SUMMARY.md](SUMMARY.md)
3.  更新实施方案任务 [JSON.md](JSON.md)
4.  保存为 `PRD.md` 和 `tasks.json`

## 完成后

确保所需的文件存在：
-  PROJECT_ROOT/.agent/prd/PRD.md
-  PROJECT_ROOT/.agent/prd/SUMMARY.md
-  PROJECT_ROOT/.agent/tasks.json

如果它们不存在，请警告用户并询问他们是否希望创建其中任何一个。

## 重要约束

-  不要生成代码 - 专注于文档和任务规范
-  在第一阶段广泛使用 `AskUserQuestion` 以澄清需求
-  不要在 PRD、任务、聊天、日志或 `.env.local` 中写入真实秘密值；使用占位符值并告诉用户手动填写真实值
-  在第二阶段，生成全面的任务清单（典型项目 50-200+ 个任务）
-  在第二阶段，始终在功能工作之前生成 `TASK-1` 作为前提条件验证
-  始终以 `"passes": false` 初始化任务 - 在生成过程中不要标记任务为完成
-  使用可用工具：`AskUserQuestion`、`WebSearch`、`SequentialThinking`、`Read`
