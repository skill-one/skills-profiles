# 优化 TextMeshPro

## 优先级排序——首先识别症状

在提供建议之前，先确定用户的問題属于哪个类别。如果用户没有描述具体的症状，可以询问：“您在使用 TextMeshPro 时遇到的是**内存/图集膨胀**、**视觉质量**、**CPU/性能**、**构建大小**还是**本地化/对齐**问题吗？”

| 症状 | 前往 |
|---|---|
| 内存分析器显示大型或多个 TMP 图集 | [字体堆栈与动态后备](#font-stack--dynamic-fallbacks)、[内存分析器：包含字体数据](#memory-profiler-include-font-data) |
| 字形粗细不一致、边缘模糊、视觉质量 | [填充与采样率](#padding--sampling-ratios)、[字体资源缩放](#font-asset-scale)、[图集渲染模式：SDF16](#atlas-render-mode-sdf16) |
| 文本更新或画布重建期间 CPU 峰值 | [AutoSize](#autosize)、[Worldspace vs Canvas Text](#worldspace-vs-canvas-text) |
| 从发送的字体文件构建大小过大 | [动态 OS 图集填充](#dynamic-os-atlas-population-tmp-320-pre3) |
| 拉丁文 + CJK 对齐看起来不协调 | [字体规范化](#font-normalization) |
| 需要多种字体样式（斜体、轮廓、发光） | [材质预设](#material-presets) |

## 核心规则

- **主字体 = 静态资源，包含所有字形**。通过后备列表（或 TMP 设置）添加**动态**后备，用于其他所有内容。将动态图集大小保持在 **512-1024** 以限制峰值内存。
- **动态后备字体 -> 启用 `构建时清除动态数据`**。否则编辑器烘焙的字形会包含在播放器中。
- **保持主字体 + 后备字体的填充到采样点大小的比例一致**。不匹配会在同一行上产生不一致的字形粗细。
- **拉丁文采样点大小 70-90；CJK 36-50**。不同脚本需要不同的采样大小以获得干净的 SDF。
- **字体资源缩放 = 1**。任何其他值（例如，0.9）都会破坏标准的点大小计算。
- **在布局锁定后，在运行时禁用 AutoSize**。AutoSize 用于设计，而不是用于实时计数器。
- **Worldspace 文本 -> 使用 `TextMeshPro`，而不是 `TextMeshProUGUI`**。Worldspace 中的画布开销不是免费的。
- **将经常更改的 TMP UI 作为其自身的画布的父级**以限制重建成本。
- **TMP 材质预设 > 复制字体资源**，用于相同字体的斜体/粗体/轮廓/发光变体。
- **对于在 iOS/Android 上发送的多语言构建，评估 `图集填充模式 = 动态 OS`**（TMP 3.2.0-pre.3+）以利用系统字体并缩小构建大小。

## 字体堆栈与动态后备

如果用户报告 TMP 图集的内存膨胀，建议使用以下字体堆栈模式：

```
主字体资源（静态，包含所有必需的拉丁文字形）
  -> 后备 1：动态字体（图集 512 或 1024），用于 CJK
  -> 后备 2：动态字体，用于符号 / 表情符号
```

**绝对不要在未启用 `构建时清除动态数据` 的情况下发送动态后备字体资源**。在编辑器中测试时烘焙的每个字形如果此切换关闭，都会包含在播放器构建中。

## 填充与采样率

如果用户报告笔画宽度不一致或主字体与后备字体的字形粗细差异，请检查填充到采样点大小的比例。

该比例是 `填充 / 采样点大小`。填充 = 9 且采样点大小 = 90 时，比例 = **10%**。

- 主字体有一个比例，后备字体有不同的比例，会在同一行上产生**不一致的笔画宽度**。
- 选择一个比例（10% 是一个安全的默认值），将其应用于链中的所有字体资源。

推荐的采样点大小：

- **拉丁文脚本**：70-90。
- **CJK 脚本**：36-50（CJK 字形在视觉上更密集；较小的采样大小仍然可以产生干净的 SDF 并节省图集内存）。

---

## 字体资源缩放

如果用户报告点大小与设计规范不匹配，请检查字体资源的缩放值。一些导入的 TMP 字体资源会以 `缩放 = 0.9` 而不是 `1.0` 发送。缩放值参与点大小到像素的数学计算，因此非 1 的缩放会产生非标准的点大小。建议用户在调整填充比例之前**将所有字体资源的缩放设置为 1**。

---

## 图形资源

如果用户报告移动设备上 TMP 图形资源的加载时间缓慢，请检查源纹理的纹理类型。它必须设置为 **默认**（不是图形）。图形类型会创建子对象，TMP 不使用它们；默认值可以避免它们。

---

## AutoSize

如果用户报告文本字段在频繁更改时（计时器、计数器、聊天、动态玩家名称）出现 CPU 峰值，请检查 `enableAutoSizing` 是否开启。AutoSize 每次字符串更改时都会调整文本大小，导致持续的 CPU 峰值。

建议：**在布局锁定后禁用 AutoSize 并硬编码选择的点大小**。仅保留 AutoSize 以便在本地化更改时自动适配的静态标签。

---

## 图集渲染模式：SDF16

如果静态字体的点大小 **72 或更大** 看起来不清晰或边缘模糊，建议将 **图集渲染模式**切换为 **SDF16**。对于大字形，使用更高精度的 SDF，但会稍微增加图集内存。

---

## 字体规范化

如果用户报告同一行上的拉丁文 + CJK 文本对齐不正确，请引导他们执行以下步骤：

1. **窗口 -> TextMeshPro -> 设置 -> 导入 TMP 示例与附加组件**（每个项目一次性）。
2. 将 **`TMP_TextInfoDebugTool`** 组件添加到显示对齐不正确文本的 TextMeshPro 对象。
3. 启用 **显示行** 切换 - 字母 ascender、descender 和基线会作为覆盖层渲染。
4. 混合拉丁文 + CJK 字符串；如果行偏离，**调整 TMP 字体资源的 ascender/descender** 直至对齐。

> **注意事项**：导入 TMP 示例与附加组件在某些项目布局上会导致无限导入循环。如果发生这种情况，关闭 Unity 并重新打开——第二次尝试时导入会解决。

---

## 材质预设

如果用户需要相同字体的多种样式（斜体、粗体、轮廓、发光），建议使用材质预设而不是复制字体资源。预设共享相同的字体纹理，但会覆盖着色器参数。

如何创建：

1. 选择一个 TMP 文本 GameObject。
2. 在检查器中，找到 **材质** 部分。
3. **右键单击材质标题 -> 创建材质预设**。
4. 重命名新材质并调整设置。
5. 在 TMP 文本组件中，从 **材质预设下拉菜单**中选择预设。

## 动态 OS 图集填充 (TMP 3.2.0-pre.3)

如果用户正在发送多语言构建并担心构建大小，建议评估 **`图集填充模式 = 动态 OS`**（TMP 3.2.0-pre.3+）：

- 在编辑器中：仍然使用项目中的源字体。
- 在播放器构建中：**源字体不包含**。运行时，Unity 在设备上搜索具有匹配 Family + Style 名称的字体。

推荐的系统字体用于 CJK：

| 平台 | 推荐系统字体 |
|---|---|
| **Android** | NotoSans（广泛涵盖中、日、韩字形）。 |
| **iOS** | PingFang（用于简体中文/繁体中文）。iOS 对 CJK 使用**每种语言独特的字体**（中、日、韩使用不同的字体族）——在跨三种语言发送单个 TMP 设置时检查后备链。 |

优势：构建大小缩小（不发送 CJK 字体文件）和内存降低（系统字体与操作系统共享）。

## 内存分析器：包含字体数据

如果内存分析器在编辑器中显示字体资源大小异常大，请检查 `.ttf` / `.ttc` 导入设置上的 **包含字体数据** 是否启用。编辑器默认将源字体文件包含在资源中，但在设备上（尤其是使用动态 OS）不会支付此成本。

要使编辑器捕获与设备匹配：在字体文件上 -> 在导入设置中取消选中 **包含字体数据**。内存分析器现在将显示**不包括**底层字体文件的开销。

## Worldspace vs Canvas Text

如果用户使用 `TextMeshProUGUI` 的 worldspace 文本（伤害数字、标志、全息图），建议切换到 **`TextMeshPro`**。Worldspace 画布是众所周知的低效。

如果 `TextMeshProUGUI` 元素的 `text` 经常更改（计时器、计数器、聊天），建议**将其作为具有自身画布组件的子 GameObject 的父级**。画布重建是按画布范围进行的，因此隔离易变字段会降低其他 UI 的重建成本。

## 常见陷阱

如果用户的设置符合以下任何一项，请标记它：

- 一个用于所有语言的大型动态字体资源，而不是静态主字体 + 动态后备——动态图集会膨胀。
- 主字体 + 后备之间填充比例不一致——同一行文本看起来像两种字体。
- 字体资源缩放 = 0.9 继承自导入——点大小不会匹配设计规范。
- 为实时计数器保留 AutoSize——隐藏的 CPU 峰值。
- Worldspace 中的 `TextMeshProUGUI` 在 worldspace 画布内——没有好处的情况下额外的重建；使用 `TextMeshPro`。
- 忘记在动态后备字体上启用 **构建时清除动态数据**——编辑器测试字形会包含在播放器中。
- 在编辑器中包含字体数据的情况下捕获内存分析器，然后对设备构建大小较小感到惊讶。
- 图形资源源纹理设置为图形类型——移动加载变慢，因为额外的子对象。
