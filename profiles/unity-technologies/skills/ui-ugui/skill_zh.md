在处理ScrollRect/ScrollView时，请参考参考文件：
- `references/scrollview-setup.md` — 必要的层级结构、设置规则和常见错误

## 范围

确定用户需要什么：

| 请求类型 | 操作 |
|----------|------|
| 关于UI的问题 | **理解** — 分析层级结构，解释结构 |
| 修改特定元素 | **编辑** — 仅进行针对性修改 |
| 创建新的UI | **生成** — 创建新的层级结构 |
| 修复/改进现有的UI | **编辑** — 修改现有结构，不要重建 |

**仅生成所请求的内容：**

| 请求 | 输出 |
|------|------|
| UI布局 | 仅Prefab或场景层级结构 |
| "带代码" / "带逻辑" / "功能性" | 层级结构 + 脚本 |

**这些不意味着脚本：**
- "合适的按钮" → 配置良好的Button组件
- "可工作的UI" → 可渲染的有效层级结构
- "菜单屏幕" → 仅视觉布局

## 关键规则

**命名空间消歧：**
- 创建或引用UI组件时，始终使用完全限定类型名称
- `UnityEngine.UI.Image`，而不是`Image`
- `UnityEngine.UI.Button`，而不是`Button`
- 项目中的其他命名空间可能导致歧义类型错误

**修改前验证：**
- 修改前始终检查当前存在的内容
- 添加子对象前确认父对象存在
- 修改属性前验证组件是否存在
- 不要假设层级状态 — 先查询

**增量修复优于重建：**
- 修复问题时进行针对性修正
- 不要为了解决问题而销毁并重新创建整个层级结构 — 销毁对象会导致空引用级联
- 优先识别并修复特定损坏的属性，而不是重写大段代码
- **当修复失败时，在尝试替代方法前撤销更改**

**一次只做一个更改：**
- 做一个更改，然后验证结果
- 不要批量修改多个不相关的修改
- 编辑特定元素时小心不要无意中修改或删除相邻元素
- 如果某项失败，在尝试替代方法前理解原因
- 避免使用多个同时进行的更改进行"散弹调试"

**颜色和可见性：**
- **确保文本默认可读：** 选择颜色时，确保文本与其背景对比度良好 — 但尊重有意使用的低对比度（禁用状态、占位符文本、装饰元素）
- **检查新元素的可见性：** 创建UI元素后，验证它们具有非零大小并且位于父对象边界内。有意创建的隐藏元素（用于后续切换、动画等）是允许的

**规范遵循：**
- **精确遵循用户规范：** 当用户提供像素尺寸、十六进制颜色、位置、间距或其他精确值时，精确应用它们 — 不要近似或替代
- **最小化不相关的更改：** 编辑时，避免更改用户未请求的属性，除非与修复相关的调整是必要的

## 工作流程

1. **验证状态** — 在任何操作前检查场景/层级结构中存在的内容。
2. **分析** — 确定确切需求。不要有多余的。
3. **搜索** — 查找现有的prefabs、canvases、资源。不要假设路径。
4. **遵循项目模式** — 匹配文件夹结构和命名。
5. **创建或编辑** — 使用正确的锚定构建结构，或进行针对性编辑。
6. **确认结果** — 在继续之前验证更改是否生效。

## Canvas设置

每个UI都需要一个Canvas：

```
Canvas (屏幕空间 - 叠加或相机)
├── CanvasScaler (推荐使用"随屏幕缩放")
├── GraphicRaycaster
└── [UI内容]
```

**CanvasScaler设置：**
- 默认使用UI缩放模式"随屏幕缩放"，除非项目有特定原因使用"常量像素大小"（例如，像素艺术、固定分辨率目标）
- 参考分辨率：匹配项目标准（例如，1920x1080）
- 创建使用屏幕空间-相机时，**先阅读相机的参考分辨率**
- Match Width Or Height: 0.5（平衡）
- 如果现有Canvas使用"常量像素大小"，标记它并在更改前询问用户
- 优先使用锚定和布局组而不是绝对像素位置进行布局

## 布局组件

**布局组控制子元素大小：**
- 当父对象有布局组时，它管理子RectTransforms
- 子元素的锚定和sizeDelta可能被父对象覆盖
- 在设置值前，了解是父对象还是子对象控制大小

**垂直/水平布局组：**
- 控制子元素大小：确定父对象是否设置子元素尺寸
- 子元素强制扩展：确定子元素是否拉伸以填充空间
- 如果控制子元素大小关闭，子元素必须有明确的大小

**避免布局冲突：**
- 不要在父对象控制它们时手动设置子元素锚定/大小
- 不要将布局组添加到应该具有固定大小的元素上
- 嵌套布局组需要仔细配置每个级别
- 布局错误时，先检查父对象设置再修改子元素
- ContentSizeFitter与具有启用Control Child Size的布局组在同一对象上 = 冲突
- 父对象具有启用Control Child Size的子元素的ContentSizeFitter = ContentSizeFitter被覆盖（浪费）
- 使用ContentSizeFitter与布局组父对象时，在相关轴上禁用父对象的Control Child Size
- 常见模式：ScrollView Content应有ContentSizeFitter + VerticalLayoutGroup，其中VLG控制子元素但ContentSizeFitter本身大小化Content

**GridLayoutGroup：**
- 用于库存网格、卡片布局
- 单元格大小必须明确设置 — 子元素大小匹配单元格

**ContentSizeFitter：**
- 水平/垂直适配：首选大小
- 用于应调整到其内容的容器
- 需要一个布局元素或文本组件提供首选大小

## RectTransform锚定

**元素必须有非零大小才能可见：**
- 通过sizeDelta设置显式宽度/高度，或
- 使用具有适当偏移的拉伸锚定，或
- 让父布局组控制大小（启用Control Child Size）

**锚定配置顺序：**
1. 首先设置锚定预设（角落、边缘或拉伸）
2. 然后设置位置/偏移值
3. 验证结果大小是否非零

**常见模式：**
- **拉伸锚定** — 用于响应式填充可用空间的元素
- **角落锚定** — 用于固定位置、固定大小的元素
- **边缘锚定** — 用于仅在单个方向上拉伸的元素

**从自然语言描述中定位：**
当用户描述位置（例如，"右上角"、"底部条"、"左侧"）：
1. 确定是**角落**（固定点）、**边缘**（沿一个轴拉伸）还是**填充**（沿两个轴拉伸）
2. 设置anchor min和anchor max — 角落这些是同一点；边缘/填充它们跨越一个范围
3. **将pivot设置为与锚定点匹配** — pivot必须与元素锚定位置对齐，而不是默认的（0.5, 0.5）。"右上角"元素需要pivot在右上角；"顶部条"需要pivot在顶部边缘中心
4. 设置位置/偏移值**在锚定和pivot配置后**

**可见性检查清单：**
- 宽度和高度都大于零
- 元素在父对象边界内
- 元素没有被兄弟元素遮挡（检查层级顺序）
- Image组件有sprite或alpha > 0的颜色

## 常见组件

| 组件 | 用途 |
|------|------|
| `Image` | 背景、图标 |
| `RawImage` | 渲染纹理、视频 |
| `Text (TMP)` | 所有文本（使用TextMeshPro） |
| `Button` | 可点击元素 |
| `Toggle` | 复选框、单选按钮 |

| `InputField (TMP)` | 文本输入 |

## 最佳实践

- 使用TextMeshPro进行所有文本（不要使用遗留Text）
- WorldSpace UI包含文本的也应该使用Text Mesh Pro，确保检查项目并导入TMP Essentials（如果它们不在项目中）
- 如果导入了TextMeshPro Essentials，在导入资源后确保关闭TMP Importer Windows和Import Unity Package Window
- 逻辑组织层级（Header、Content、Footer）
- 尽可能使用布局组而不是手动定位
- 将Raycast Target = false设置在非交互式图像上
- 使用sprite atlases以获得更好的性能

**绝对不要使用** `EditorApplication.ExecuteMenuItem("Window/TextMeshPro/Import TMP Essential Resources")`，除非用户要求交互式TMP Essentials安装。它打开一个模态对话框，直到人类关闭它才会阻止调用它的任何操作。

**不要使用** `AssetDatabase.ImportPackage()`用于TMP资源，相反`TMP_PackageResourceImporter.ImportResources()`是标准的非交互式API。

## 交互准备

在完成包含交互元素的任何UI前，验证：

1. **EventSystem**必须在场景中存在（仅一个）
2. **GraphicRaycaster**必须在Canvas上
3. **Raycast Target = true**在交互式元素上（非交互式元素上为false以避免阻塞）
4. **Button.onClick应连接**（通过inspector或脚本）— 仅当请求脚本或逻辑时

如果前三个缺失，交互元素在视觉上存在但会静默失败。

## 理解

当用户询问关于现有UI的问题：

**首先阅读层级结构。** 不要假设 — 始终在回答前检查场景或prefab。

**分析结构：**
- 确定Canvas及其渲染模式
- 映射父子关系
- 确定哪些布局组控制哪些子元素
- 检查RectTransform锚定配置

**回答关于：**
- "这个按钮做什么？" → 解释组件、层级位置、事件连接
- "这个布局是怎样的？" → 描述布局组、锚定、层级
- "为什么这个不可见？" → 检查大小、锚定、父对象边界、组件状态
- "什么控制这个元素的大小？" → 追踪布局组设置或锚定

## 编辑

对现有UI进行针对性修改：

**编辑前阅读。** 始终先检查当前状态。

**编辑工作流程：**
1. 验证目标对象存在
2. 确定要更改的特定属性或组件
3. 进行所需的最小更改
4. 验证结果再继续

**绝对不要销毁来修复：**
- 销毁对象会导致空引用级联
- 在原位修复属性而不是重建
- 如果必须移除元素，先更新所有引用

## C#（仅当请求时）

- 使用完全限定的UI类型以避免命名空间冲突
- 使用`[SerializeField]`用于inspector引用
- 在Awake()中缓存组件引用
- 使用事件/委托进行按钮回调
- 将脚本放在与prefabs相同的文件夹（遵循项目模式）

**组件引用：**
- 在访问它们之前验证引用的对象存在
- 处理序列化引用可能为null的情况
- 在连接引用时，确认目标组件存在

## 错误恢复

当出现问题时：

**停止并诊断：**
- 确定确切错误或症状
- 在尝试修复前确定根本原因
- 不要进行猜测性更改

**增量修复：**
- 一次解决一个问题
- 修复每个问题后再移向下一个
- 记录所做的更改

**避免破坏性模式：**
- "从零开始"策略会销毁工作元素和损坏元素
- 重建整个层级结构会产生比解决的问题更多的问题
- 优先使用手术修复而不是大规模替换

**卡住时：**
- 重新验证层级结构的当前状态
- 检查之前更改是否实际应用
- 考虑方法本身是否错误，而不是实现
