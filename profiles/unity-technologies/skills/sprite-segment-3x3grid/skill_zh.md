# 矢量图色块分析

## 目的

该技能通过将矢量图分割为3x3网格，并根据与中心单元格的颜色匹配情况输出文本表示形式来分析矢量图纹理。

## 参数

### 匹配阈值

**匹配阈值**决定了非中心单元格中必须有多少百分比的像素与中心单元格的主要颜色匹配，才能将该单元格视为"匹配"（`.`）。

| 阈值 | 描述 | 用例 |
|------|------|------|
| **50%** | 单元格至少有一半的像素与中心颜色匹配 | 对具有混合区域的矢量图进行宽松匹配 |
| **75%** | 单元格至少四分之三的像素与中心颜色匹配 | 对大部分为实心区域的矢量图进行中等匹配 |
| **90%** | 几乎所有像素都必须与中心颜色匹配 | 对非常均匀的矢量图进行严格匹配 |

**默认值**: 75%

## 算法

1. **分割矢量图**: 将矢量图的纹理区域分割为3x3网格（共9个单元格）
2. **识别中心颜色**: 计算中心单元格（位置[1,1]）中的多数（最频繁）颜色
3. **比较每个单元格**: 对于8个周围的单元格，计算有多少百分比的像素与中心的主要颜色匹配。如果匹配百分比达到或超过**匹配阈值**，该单元格即为匹配（`.`）；否则不匹配（`X`）
4. **生成输出**: 使用下方的图例创建文本表示形式

## 输出图例

| 符号 | 含义 |
|------|------|
| `X` | 单元格未达到匹配阈值（像素匹配中心颜色不足） |
| `.` | 单元格达到匹配阈值（像素匹配中心颜色足够） |
| `*` | 中心单元格本身（网格中始终位于[1,1]的位置） |

## 输出格式

输出为单行，包含三个由` / `分隔的三字符组。每个组代表网格的一行。

**顺序**: 从上到下排列行，每行从左到右排列。

**格式**: `[顶行] / [中行] / [底行]`

每行包含三个由空格分隔的字符：`[左] [中] [右]`

### 网格位置映射

```
网格布局:        输出顺序:
[0,0] [1,0] [2,0]   1  2  3   -> 第一个组
[0,1] [1,1] [2,1]   4  5  6   -> 第二个组（5始终为*）
[0,2] [1,2] [2,2]   7  8  9   -> 第三个组
```

### 示例

**示例1**: 中心仅与左上角和右下角匹配
```
. X X / X * X / X X .
```
网格解释:
```
.  X  X
X  *  X
X  X  .
```

**示例2**: 中心与所有周围单元格匹配
```
. . . / . * . / . . .
```

**示例3**: 中心与周围单元格均不匹配
```
X X X / X * X / X X X
```

**示例4**: 中心仅与底行匹配
```
X X X / X * X / . . .
```

## 实现指南

### 计算中心的主要颜色

对于中心单元格:
1. 采样单元格边界内的所有像素
2. 按颜色分组像素（考虑使用颜色容差阈值来匹配相似颜色）
3. 多数颜色是像素计数最高的颜色
4. 对于平局，使用遇到的第一个颜色

### 匹配非中心单元格

对于8个周围的单元格:
1. 计算单元格中的总像素数
2. 计算与中心多数颜色匹配的像素数（使用颜色容差）
3. 计算匹配百分比：`matchingPixels / totalPixels`
4. 如果匹配百分比 >= 阈值，单元格为匹配（`.`）；否则（`X`）

### 颜色容差

比较像素颜色时:
- 考虑使用容差阈值（例如RGB距离<10）进行"匹配"
- 或者，对于具有有限调色板的矢量图，可以采用精确匹配
- 如果适用，考虑透明通道

### 矢量图边界

使用矢量图的`rect`属性来确定要分析的像素区域:
- `sprite.rect.x`, `sprite.rect.y`为原点
- `sprite.rect.width`, `sprite.rect.height`为尺寸
- 将宽度和高度除以3以获取单元格尺寸

## 用例

- **文档**: 以紧凑的文本格式描述矢量图模式
- **测试**: 在自动化测试中验证预期的矢量图结构
- **分析**: 快速识别具有相似颜色分布的矢量图
- **调试**: 了解矢量图为何与预期外观不同
- **资源目录**: 为矢量图资源生成可搜索的元数据

## 注意事项

- 该分析最适合具有明显颜色区域的矢量图
- 对于具有渐变或多种颜色的矢量图，考虑增加颜色容差
- Y轴与Unity的纹理坐标相反，以产生从上到下的输出
- 透明像素可以根据用例视为不同的"颜色"或忽略
