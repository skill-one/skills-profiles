# 音频混音器设置

将音频源路由到混音器组是一项场景编辑操作，只有正在运行的编辑器才能执行，因此这项技能需要一个可以执行 C# 的在线编辑器来运行。步骤 0 在进行任何其他操作之前就确立了这一点。

**这项技能自动化的内容，以及它将返回给你的内容。** 检查混音器并将音频源路由到组是完全公开的 Unity API，而繁琐的部分是——逐个检查数十个源并根据它们播放的内容进行分类。创建混音器或组没有公开 API；它只存在于 Unity 不承诺保持稳定的类型中。因此，这项技能不会在背后为你创建组。它会清点现有内容，提出路由方案，要求你在音频混音器窗口中添加任何缺失的组，然后自己完成所有路由。

这是一个故意的限制，而不是需要绕过的工作区。不要使用反射来创建组，也不要手动编辑 `.mixer` 文件——混音器结构无法在盲目的情况下安全地授权。

## 步骤 0：确认你可以在编辑器中运行 C#

下面的每个 C# 步骤都在通过 Unity CLI 在运行的编辑器内部运行。**`unity-cli` 技能负责带你到达那里**——安装 CLI、确认连接的编辑器、添加项目的 `com.unity.pipeline` 包、区分真正的缺失编辑器与卡在安全模式下的编辑器，以及发现编辑器的命令目录。首先跟随它；不要在这里重新推导任何内容。

有两件事它不能为你知道：

- **你需要 `eval`，而不仅仅是可连接的编辑器。** 确认它出现在目录中。它的存在取决于 Pipeline 包版本，而不是 CLI，因此健康的安装仍然可能缺少它——如果它缺失，请说明并停止。
- **不要退回到手动编辑 `.mixer` 文件。** 混音器路由无法在盲目的情况下安全地授权，因此无法连接的编辑器是一个停止信号，而不是一个即兴创作的提示。

一旦 `eval` 可用，这就是下面每个 C# 步骤运行的方式。

通过连接的编辑器使用 `eval` 命令运行 C#。从 `unity command --format json` 而不是假设一个来发现其参数形状——内联形式是 `unity command eval --code '<snippet>'`，一些 Pipeline 版本还注册了 `eval_file` 来从文件中运行一个片段。**在尝试 `eval_file` 之前检查目录；它经常缺失。** `unity command` 默认的超时时间为 30 秒。

### 将 C# 传递给 `eval`

`eval` 编译一个**语句块，而不是文件**。有两个后果，两者都会导致编译错误而不是警告：

- **没有 `using` 指令。** 编译器将 `using UnityEngine;` 读取为资源释放语句并拒绝它（`CS0210`）。
- **类型必须完全限定。** 空的 `AssetDatabase` 或 `Volume` 无法解析（`CS0246` / `CS0103`），而空的 `Object` 与 `object` 混淆（`CS0104`）。

在下面的片段中，如果以文件形式编写——出于可读性或因为打算将其保存到项目中——在传递给 `eval` 之前限定类型。

## 步骤 1：预检
如果用户没有明确要求音频混音器，请确认他们是否希望继续设置它们。

然后使用 [references/api.md](references/api.md) 中的混音器清点片段，按照步骤 0 中描述的方式在编辑器中运行。这会给你项目中的每个混音器以及每个组中的组名。

它返回一个组的扁平列表，而不是父子树。这足以进行路由，并且这是公共 API 暴露的所有内容。如果层次结构对对话很重要，请要求用户查看音频混音器窗口并描述它——不要尝试使用非公共树 API 来找出。

**如果项目根本没有混音器，** 请说明并停止，而不是即兴创作一个：创建混音器没有公共 API。要求用户创建一个（窗口 → 音频 → 音频混音器，然后是混音器旁边的 **+**），然后一旦它存在，再从这里继续。

## 步骤 2：查找场景引用
查找所有音频源组件，查看它们分配的生成器资产名称，并概括一个合适的类或声音名称类别，最好是已经存在的。音频剪辑资产名称的示例：
- "FootStep4_Sound" -> Foley
- "Dialogue_Female_Scene4" -> Vox/Voice/Dialogue
- "GunShot" -> SFX
- "Menu_Theme_Variation" -> Music

如果分配的资产不具有描述性或不存在，请尝试查看 GameObject 名称或潜在的相邻 MonoBehaviour 名称。
如果分类看起来很困难或对分类的信心较低，请要求创建一个未分类的组。

## 步骤 3：同意组列表，并创建任何缺失的组
将步骤 2 中的分类作为建议路由呈现——每个音频源及其打算发送到的组——并与用户一起进行修订。

**在继续之前等待用户的响应。**

当现有的组确实涵盖了类别时，即使你可能会用不同的名称命名，也优先选择现有的组。但是，**不要合并混音师会分开的类别**——Foley 是 SFX 的子集，而不是它的另一个名称，因此枪声不应属于 `Foley` 组，仅仅是因为存在一个这样的组。当现有的组只能部分涵盖你的类别时，请说明哪些适合，哪些需要新组，并让用户决定。

对于没有匹配组的类别，你不能创建组——没有公共 API 用于此。精确地传递它，命名混音器和确切的组名，如 [references/api.md](references/api.md) 的末尾所示。然后 **在路由之前重新运行清点片段以确认组是否存在并检查其拼写**。不要假设用户已经完成，也不要假设他们按照你要求的方式拼写。

## 步骤 4：路由音频源
在组列表确定并确认存在的情况下，使用 [references/api.md](references/api.md) 中的路由片段为每个音频源的输出组分配。整个过程都是通过公共 API 实现的，并且它将整个过程包装在一个撤销步骤中，以便用户可以一次性撤销所有内容。

**以你分类的标识符为键。** 步骤 2 首先读取剪辑资产名称，并且只有在回退到 GameObject 名称的情况下才会这样做，因此映射接受两者——这两个是不同的标识符，以错误的标识符为键会导致源丢失。

有三种情况需要报告而不是假设：

- **片段返回的任何 `NO SUCH GROUP` 条目。** 这意味着你期望的组在混音器中不存在——通常是拼写差异。与用户一起解决它，不要在沉默中跳过源。
- **任何 `NOT IN THE MAPPING` 条目。** 这些是你的分类遗漏的音频源。在这里报告成功的路由而源被悄悄留未路由是最糟糕的结果，因为它被视为成功。
- **场景被修改，而不是混音器资产。** 路由存在于音频源上，因此只有在保存场景后才会持久。告诉用户，并在他们同意后保存。

**音量、效果和重新父化不在范围内。** 这些存在于非公共 API 中。如果用户要求它们，请说明路由已完成，并指向音频混音器窗口进行混音本身。
