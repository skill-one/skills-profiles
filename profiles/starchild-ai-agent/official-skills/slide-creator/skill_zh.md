# 幻灯片创建器 — HTML → PDF 演示文稿

以 HTML 构建幻灯片套件，通过无头 Chromium 导出为像素级完美的 16:9 PDF。

**输出格式：PDF** — 而非 Microsoft PowerPoint (.pptx)。PDF 保留了在所有设备上的精确布局、字体和颜色。

## 为什么是 HTML → PDF

- CSS 布局（网格/弹性盒）比任何 PPT 编辑器都灵活得多
- 完整的网页排版、渐变、SVG、动画（打印时优雅降级）
- Git 友好，可重复，可脚本化
- 一条命令 → 带有精确 16:9 页面尺寸的 PDF

## 工作流程

### 0. 确定场景（新）

在任何其他步骤之前，确定演示文稿场景。阅读 `references/content-scaffolding.md` 获取完整模板。

| 场景关键词 | 使用的模板 |
|-----------|-----------|
| 演讲 / 投资者 / 融资 | `pitch-deck` |
| 会议 / 主讲 / 峰会 / 演讲 | `conference-keynote` |
| 产品发布 / 发布活动 | `product-launch` |
| 报告 / 研究 / 分析 | `research-report` |
| （以上都不适用） | 询问用户哪个场景最合适 |

每个模板定义：幻灯片数量、页面标题、每页所需内容。

### 0.5 双语布局（如果需要）

如果受众是双语（例如 HK、新加坡、全球中文会议），或者用户提到中文 + 英文：
- 使用 `references/content-scaffolding.md` 中的 `bilingual` 布局模式
- 标题：英文（大号）+ 中文副标题（较小，--text-muted）
- 正文项目符号：中文优先，英文可选括号内
- 避免为 HK/TW/SG 受众制作纯英文套件

### 1. 规划套件

根据场景模板定义幻灯片数量和每张幻灯片的内容。每张幻灯片 = 一个 `<section class="slide">`。

### 1.5 艺术指导（在构建前运行）

> 每当用户未提供特定视觉风格时，运行此步骤。
> 阅读 `skills/slide-creator/references/art-direction.md` 获取完整风格分类，
> CSS 令牌模板和风格简报输出格式。

**步骤 A — 提问 4 个问题：**
1. 受众和场景：这是给谁看的，以及在什么背景下（投资者 / 内部团队 / 公开主讲）？
2. 氛围关键词：观众应该有什么感觉（权威 / 活力 / 友好 / 时尚现代）？
3. 品牌限制：是否有任何必需的品牌颜色、标志或字体？
4. 参考材料：是否有任何模板参考以对齐（图像、网页链接、现有套件截图）？

**步骤 B — 生成视觉风格选择器页面：**
不要将风格选项作为文本描述呈现 — 用户无法仅从文字中评估风格。

参考处理规则：
- 如果用户提供 **图像文件/截图**：样本调色板（主色/表面色/强调色），从视觉中检查布局密度、圆角、排版语气。
- 如果用户提供 **网页 URL**：使用 `web_fetch` 提取设计提示。**关键 — 遵循此提取协议以避免误读风格：**
  1. **忽略品牌名称 / 域名** — 永远不要根据产品的行业或名称推断视觉风格（例如 "Neo" 不代表霓虹灯，"Opera" 不代表欧洲奢华）。
  2. **阅读文案语气和词汇** — 页面上使用的词语揭示了氛围（例如 "外科手术精度"、"安静的自信" → 保守；"释放"、"彻底" → 大胆/激进）。
  3. **提取明确的颜色词汇** — 在获取的文本中查找 CSS 关键字，或在正文文本/替代文本中提到的颜色名称。暖色 vs 冷色，浅色 vs 深色，柔和 vs 饱和。
  4. **推断布局密度** — 计算每部分的字数；稀疏 = 编辑/奢华，密集 = 技术/功能。
  5. **识别装饰性图案** — 提及或暗示（例如几何图形、渐变、摄影、插画、线条艺术、 brutalism）。
  6. **与 art-direction.md 对齐** — 找到最匹配的模板，然后描述差异（例如 "风格 G 但更暖，将蓝色替换为焦橙色，添加微妙的网格线”）。
  7. **不确定时**：保守 — 适度承诺风格匹配，并提供 3 个选项，其中选项 A 是您的最佳解释，B 更安全/更干净，C 更具实验性。**永远不要自信地断言与实际视觉证据相矛盾的风格。**
- 如果用户提供两者：优先考虑图像提示，其次是 URL 提示。
- 如果未提供参考：使用内置风格分类默认值。

然后：
1. 创建 `output/style-picker/index.html` — 一个包含 3 个并排的迷你幻灯片预览（16:9 纵宽比），每个预览都使用真实的 CSS（颜色、字体、布局、装饰元素）完全渲染。每个预览必须像实际幻灯片，而不是颜色芯片。
2. 构建 3 个选项：**(A) 参考忠实**，**(B) 更安全的公司变体**，**(C) 更大胆的创意变体**。
3. `preview(action='serve')` 目录并显示预览 URL。
4. 每个卡片下方有一个标签：风格名称 + 一行描述。
5. 添加 `onclick` 高亮，以便用户可以点击表示其选择。

用户通过说 "选择 A" / "我想 B" / "混合 A+C" 等进行选择。

**步骤 C — 生成 style-brief.md：**
一旦用户选择风格，就在项目目录中编写 `style-brief.md`（art-direction.md 中的模板）。
所有后续的 HTML/CSS 工作都必须遵循此简报。

**步骤 D — 询问品牌资产（标志 / 颜色）：**
用户选择风格后，询问：
> "您有标志或品牌颜色要包含吗？您可以上传图像文件，我将标志嵌入到所有幻灯片中。"

如果上传标志：以 base64 嵌入 HTML（在 bash 中使用 `base64.b64encode`），放置在左上角或右上角，高度 ≤60px。
如果提供品牌颜色：用用户的颜色覆盖 CSS 令牌块中的 `--accent`。

### 2. 选择主题

如果艺术指导已完成，`style-brief.md` 是主题规范 — 跳过此表格。
否则，用作快速备用：

| 风格 | 背景 | 强调色 | 字体 | 氛围 |
|------|------|--------|------|------|
| 暗色科技 | `#000` / `#0a0a0a` | 明亮的橙色/蓝色/绿色 | Inter, Space Grotesk | 大胆、现代 |
| 浅色简洁 | `#fff` / `#f8f8f8` | 海军蓝、蓝绿色、珊瑚色 | Inter, DM Sans | 专业、极简 |
| 渐变 | 暗色渐变 | 鲜艳的强调色 | 任何无衬线字体 | 创意、活力 |
| 公司 | `#1a1a2e` / 白色 | 品牌颜色 | 系统字体 | 可信赖、正式 |
| 俏皮 | 柔和的粉彩色 | 温暖的流行色 | Nunito, Poppins | 友好、休闲 |

### 3. 构建 HTML + CSS

创建一个项目目录，包含 `index.html` + `styles.css`。

**从 `assets/base.css` 开始** — 结构骨架（幻灯片尺寸、打印规则、布局辅助工具）没有任何颜色或字体。在顶部叠加您的主题：

```css
/* 示例主题层 — 自由定制 */
body {
  font-family: 'Inter', sans-serif;
  color: #fff;
  background: #000;
}
.slide { background: #0a0a0a; }
.slide-tag { background: rgba(0,120,255,0.15); color: #0078ff; }
.card { background: rgba(255,255,255,0.04); border: 1px solid rgba(255,255,255,0.08); }
```

**强制性结构规则**（在 base.css 中 — 不要删除）：

```css
.slide { width: 1280px; height: 720px; page-break-after: always; overflow: hidden; }
@page { size: 1280px 720px; margin: 0; }
```

**关键规则：**
- 使用 `px` 单位 — 永远不要使用 `vh/vw/rem/%` 来定义幻灯片尺寸
- Google Fonts：在 `<head>` 中使用 `<link>`，导出脚本等待网络空闲
- 视口元数据：`<meta name="viewport" content="width=1280">`
- 内容必须适合 720px 高度 — 超出部分会被裁剪

### 4. 预览（可选）

使用 `preview(action='serve')` 在导出前在浏览器中预览。

### 5. 导出为 PDF

```bash
python3 skills/slide-creator/scripts/export_pdf.py --dir <project-dir> --output output/<name>.pdf
```

选项：
- `--dir` — 包含 `index.html` 的目录（必需）
- `--output` / `-o` — 输出 PDF 路径（默认：`<dir>/deck.pdf`）
- `--width` — 幻灯片宽度（像素）（默认：1280）
- `--height` — 幻灯片高度（像素）（默认：720）

### 6. 验证

脚本打印幻灯片数量并确认输出路径。额外检查：

```python
import fitz
doc = fitz.open("output/deck.pdf")
print(f"页数: {doc.page_count}")
for p in doc:
    r = p.rect
    print(f"  {r.width*96/72:.0f}x{r.height*96/72:.0f}px")
```

## 风格指南

- **无默认品牌** — 每个套件都获得针对其内容的主题定制
- 优先使用艺术指导流程（问题 → 参考资料→ 用户选择 → `style-brief.md`）
- 询问用户偏好：深色/浅色，强调色，字体，氛围
- 每张幻灯片应有清晰的视觉层次：标签 → 标题 → 内容
- 保持文本简洁 — 幻灯片是视觉的，不是文档
- 使用 `.bg-glow` 与主题色径向渐变以增加深度
- 默认情况下不要使用 `web_search` 进行风格探索；优先考虑用户提供的参考图像/链接以及 `art-direction.md` 中的模板。
- 当用户提供参考链接时，使用 `web_fetch` 提取设计提示（颜色语气/语气/布局），但使用本地模板和令牌变量实现最终 CSS。
- 当用户要求 "艺术指导建议/风格建议" 时，始终生成视觉风格选择器预览页面（3 个选项） — 永远不要依赖纯文本描述。
- 严格根据选择的艺术指导构建 HTML，然后导出 PDF（除非用户明确选择跳过简报）
- 选择风格后，始终在构建前询问标志/品牌资产
- 对于 HK/TW/SG/双语受众，默认使用双语布局，除非用户说只有英文

## 风格微调（选择风格后）

如果用户说 "将主色改为红色" / "切换字体" / "增加圆角"，不要重新开始艺术指导。
相反，直接修补 `styles.css` 中的 `--accent` / `--font-head` / `--radius` CSS 变量。
只有在用户想要完全不同风格时才重新开始艺术指导。

## 注意事项

- **Chromium**：通过 `workspace/setup.sh` 在容器启动时预安装（~641 MB 缓存在 `~/.cache/ms-playwright/`）。不要在每次导出时运行 `playwright install` — 它会重新下载相同的浏览器。只有在 `export_pdf.py` 以 `Executable doesn't exist` 失败时才运行它，在这种情况下，也将命令追加到 `workspace/setup.sh` 以使其持久化。
- **字体**：Google Fonts 需要 HTTP — 导出脚本会自动启动本地服务器
- **表情符号渲染**：无头 Chromium 可能缺少表情符号字体 — 使用 SVG 图标代替
- **大图像**：以 base64 嵌入或使用相对路径（本地服务器提供项目目录）
- **幻灯片溢出**：超出 720px 高度的内容会被裁剪 — 在边界内设计
- **⚠️ PDF 文本不可选择（验证 2026）**：任何包含文本的祖先元素上的 `filter` / `backdrop-filter` CSS 会导致 Chromium 在 PDF 导出时将该层光栅化为位图 — 所有子文本都变成像素，不可选择。修复：永远不要将 `filter`/`backdrop-filter` 应用于包含文本的容器。仅将它们应用于没有文本子元素的空装饰性 `<div>` 元素（例如 `.blur-layer`，`.glow-overlay`）。相同的规则适用于文本父元素的 `mix-blend-mode`。**导出前检查清单**：
  1) 每个非封面幻灯片都有 `.slide-body` 和 `.slide-footer` 作为兄弟元素；
  2) `.slide-body` 底部填充是 `>=96px`；
  3) 来源/免责声明文本仅出现在 `.slide-footer` 中，永远不会在正文容器中。
- **⚠️ z-index / 装饰性覆盖层错误（验证 2026）**：`.bg-glow` 和其他装饰性伪层必须使用 `z-index: 0`，所有实际幻灯片内容必须显式给出 `z-index: 1`。如果 `.bg-glow` 是 `.slide > *` 的同级元素（不是 `::before`/`::after` 伪元素），请添加此规则以确保内容永远不会在视觉上被埋没：
  ```css
  .slide > *:not(.bg-glow) { position: relative; z-index: 1; }
  .bg-glow { position: absolute; z-index: 0; pointer-events: none; }
  ```
  失败模式：PDF 导出显示内容被推到底部或不可见，即使浏览器预览看起来很好（浏览器合成比 Chromium 的打印路径更宽容地处理 z-order）。
