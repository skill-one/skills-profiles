# HyperFrames 入口

HyperFrames **从 HTML 渲染视频** — 一个组合是一个 HTML 文件，其 DOM 通过 `data-*` 属性声明时间，其动画运行时是可搜索的，其媒体播放由框架拥有。完整的创作合同位于 `/hyperframes-core`；在编写组合 HTML 之前，请阅读它。简报、故事板、审阅、生产、分发和帧工作者的合同位于此技能的 `references/` 中。

## 1. 从项目状态开始

应用第一个匹配的行；不要评估较低状态的行：

| 状态                                                                                                                         | 操作                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 将现有的 Remotion 源显式移植到 HyperFrames                                                                      | 阅读 `references/routes/remotion-to-hyperframes.md`，然后直接路由到该工作流。跳过意图层。                                                                                                                      |
| 对现有的 HyperFrames 项目执行特定操作：检查、诊断、验证、预览、渲染、发布或批量渲染 | 仅执行该操作。跳过意图和工作流路由；加载 `/hyperframes-cli` 和任何必需的领域技能。                                                                                                                 |
| 对现有项目进行特定编辑                                                                                          | 进行编辑。不要运行意图层。要知道一个项目的时间轴上有什么（轨道、片段、开始、结束、播放什么），运行 `npx hyperframes timeline [--json]` 而不是阅读 `index.html` 和每个子组合文件。 |
| 存在 `BRIEF.md`                                                                                                             | 阅读 `workflow` 和 `flow`。执行该工作流；`flow: companion` 始终在 `/general-video` 中执行。不要询问简报问题。                                                                                                      |
| 没有简报，但存在 `hyperframes.json` 或 `STORYBOARD.md`                                                              | 从项目文件和记录的偏好中恢复。从现有工件中推断拥有的工作流。如果无法唯一确定，问一个路由问题；不要运行意图访谈。                                                                                              |
| 新创建                                                                                                                    | 运行意图层 — `references/intent-interview.md` — 然后使用 § 2 的表格进行一次路由。                                                                                                                                           |

如果一个新请求没有识别主题或输入，则在路由之前询问视频是什么。在询问任何问题之前检查偏好和配方 (`references/intent-interview.md`，步骤 1)。一个 `figma.com` 输入或命名配方会改变输入，而不是路由 — 访谈的“Adapt orthogonal inputs”部分处理两者。

### 保持项目的 CLI 当前

一个脚手架项目在其 `package.json` 脚本中固定 `hyperframes@<version>`，以便渲染保持可重复；该固定永远不会自行更新，并且较旧的 CLI 的固定运行不会打印任何警告。当恢复一个其脚本带有固定的项目时，在第一个影响渲染的命令之前进行一次探测：

```bash
npx hyperframes@latest upgrade --project . --check
```

探测是只读的，并报告固定与最新发布的对比；保持显式的 `.` — 在较旧的 CLI 版本中，一个 `--project` 后跟另一个标志会将其作为目录值消耗。当它报告项目落后 — 或任何 CLI 输出已经显示它（stderr 通知 `This project pins hyperframes@… (latest …)`，或 `_meta.updateAvailable: true` 来自固定脚本的一个 `--json` 结果）时 — 使用 `npx hyperframes@latest upgrade --project .` 应用，然后使用 `npx hyperframes check` 验证。通过检查确认项目的组合在新版本上仍然有效 — 不是渲染输出与旧固定帧相同 — 因此成功的提升永远不会是静默的：在运行摘要中命名旧版本和新版本。一个还没有组合的项目不需要验证。如果检查失败，还原 `package.json` 的更改，继续在固定版本上，并报告项目保持在哪个版本以及原因。根据信号采取行动，而不是将其传递给用户；永远不要留下一个提升的固定未验证。

## 2. 路由新创建

使用第一个匹配的行。匹配请求的 **交付物**，而不是在旁文中提到的单词或文件类型。

| 优先级 | 请求                                                                                                            | 工作流                   |
| -------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| 1        | 显式移植现有的 Remotion 源                                                                        | `/remotion-to-hyperframes` |
| 2        | 撰写演示文稿、提案演示文稿或可导航的交互式演示文稿                                                   | `/slideshow`               |
| 3        | 向现有的访谈视频添加纯字幕或字幕而不更改它                               | `/embedded-captions`       |
| 4        | 向现有的访谈、采访或播客视频添加设计的图形叠加层而不更改视频 | `/talking-head-recut`      |
| 5        | 从音乐曲目构建一个节拍同步视频，没有旁白或网站捕获                                 | `/music-to-video`          |
| 6        | 创建一个显式短、无旁白、以动作为主的单元，通常在 10 秒以下                                     | `/motion-graphics`         |
| 7        | 从 PR 引用解释 GitHub 拉取请求或代码更改                                                   | `/pr-to-video`             |
| 8        | 从 URL 或特定简报展示网站、产品网站、应用程序或公司进行市场或展示 | `/product-launch-video`    |
| 9        | 用虚构的视觉效果解释主题、文章或笔记，没有产品或网站捕获                            | `/faceless-explainer`      |
| 10       | 任何其他自定义视频或组合                                                                              | `/general-video`           |

在最终确定路由之前，阅读 `references/routes/<workflow>.md` — 每个路由一个小文件：规范输入/输出/触发合同（在工作流技能懒加载之前可用）加上该路由的访谈入口。如果候选者不满足其合同，则继续路由而不是强制匹配。只阅读匹配的路由文件。

### 解决常见歧义

- 一个简短的动画标题、标志 sting、统计数据、图表 hit、地图 hit 或独立的 lower-third 是 `/motion-graphics`，当它是无旁白且动作为信息时。一个静态标题卡、旁白序列、较长蒙太奇或自定义循环是 `/general-video`。
- 一个显式短的动画面板可以使用 URL、推文、文章或截图作为源材料。一个通用的“从这个网站制作视频”请求是 `/product-launch-video`。
- 现有片段带字幕路由到 `/embedded-captions`；带设计信息卡的片段路由到 `/talking-head-recut`。重新时间、重新排序、重新着色、重新构图或重新混合片段是自定义编辑并落入 `/general-video`。
- 音乐文件仅在它的节拍网格驱动作品时选择 `/music-to-video`。作为床铺使用的音乐不会覆盖匹配的主题路由。
- “我想一个故事板”会改变审阅过程，而不是工作流。在没有其他路由信号的情况下，使用 `/general-video`。一个确认的草图 `storyboard.html` 本身可能是请求的交付物；审阅循环定义了那个停止点。
- 专门的叙事工作流支持长达约 3 分钟，在 30-90 秒时最强。将一个明显更长的作品路由到 `/general-video`。长度永远不会覆盖显式移植、演示文稿、字幕、叠加层或音乐驱动交付物。

## 3. 路由一次，然后离开

对于新创建，意图层 (`references/intent-interview.md`) 运行完整对话 — 记忆、分诊、提案轮、必须有的、运行形状、移交 — 并 **以编写 `BRIEF.md` 结束。简报是唯一路由读取的工作流工件**；之后不会重新打开此技能或访谈。从 `BRIEF.md` 回答每个后续的“路由要求什么？”。

## 4. 安装并进入工作流

在选择工作流之前，安装或刷新它和核心领域技能：

```bash
npx hyperframes skills update <workflow-name>
```

使用不带 `/` 的基本名称。如果命令失败，显示错误；不要从记忆中重建工作流。安装的其余部分 — 核心与懒加载的分割、`init` 刷新的内容、诊断、CI 选择退出和没有 CLI 的回退 — 都在 `references/skill-lifecycle.md` 中。

| 创作者请求                                                                                                    | 必需的领域                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| “剪切这个片段”，硬切、修剪、拼接、重新排序或使用源范围                                         | `/general-video` + `/hyperframes-core`；核心拥有 `data-start`、`data-duration`、`data-media-start` 和轨道布局。                                                            |
| 在这里放大，拳入 / 拳出，平滑多状态缩放或重新构图，Ken Burns，或摄像机移动                  | `/general-video` + `/hyperframes-core` + `/hyperframes-keyframes`；动画内部视觉/裁剪包装器，而不是定时片段。                                                     |
| 匹配切或快速切换摄像机过渡                                                                            | `/general-video` + `/hyperframes-animation` + `/hyperframes-keyframes` + `/hyperframes-registry`；在手工编写之前搜索并安装过渡原语。                    |
| 淡入、交叉淡入、轨道增益/音量、自动化、压低/切割、音频效果或多个轨道的一个效果                     | `/general-video` + `/hyperframes-core` + `/hyperframes-audio`；核心放置片段，音频混合放置轨道 — 包括一组它们的子混音总线。                                                |
| 结合剪切与摄像机运动或混音的图片和声音编辑                                                         | `/general-video` + `/hyperframes-core` + `/hyperframes-keyframes` 当存在视觉运动 + `/hyperframes-audio` 当声音被淡入、混合、压低、自动化或处理时。 |
| 将项目布局好以便在 Studio 中读取良好：字幕轨道、每个元素类型的轨道、子组合、安全区域             | `/hyperframes-studio` + `/hyperframes-core`；studio 拥有布局约定，核心拥有每个编辑。                                                                             |
| 源或生成媒体，或预处理一个不受支持的源冻结                                                         | `/media-use`；仅 sourcing/generation/preprocessing，从不放置轨道混合。                                                                                                  |

常量 `data-playback-rate` 对图片和保留音调的声音是渲染安全的。速度斜坡是 `data-automation` 中的 `rate` 轨道。
对于可复制的编辑合同，加载 `/hyperframes-core` → `references/creator-editing-recipes.md`。

关于摄影媒体外观或行为的广泛反馈也路由到 `/media-use`，即使用户从未说“色彩分级”或“效果”：修复暗/平/无聊的片段、美化片段、隐藏脸或改进媒体揭示。在编辑处理之前阅读 `../media-use/references/media-treatments.md`；它管理片段的处理方式，而不是媒体是否可以使用。
不要用一个通用的 LUT、CSS 过滤器/覆盖或不透明度缓动来替代现有的规范处理原语。保持文本/布局/动画编辑在其所属领域。
在包含重要摄影媒体的建设过程中，在最终质量传递中包含一个基于媒体抛光的扫描；留下合适的媒体未更改是一个有效结果。

领域技能永远不会拥有端到端的交付物。只加载活动工作流需要的技能。
