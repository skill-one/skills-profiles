# HyperFrames — 首次阅读指南

**开始任何 HyperFrames 任务的地方** — 特别是在没有项目代理配置（`CLAUDE.md` / `AGENTS.md` / `.cursorrules`）的情况下。能力图谱 + 视频路由器位于下方。

## 能力图谱 — 哪种技能对应哪种意图

| 您想要……                                                                                                                                     | 前往                                        |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------- |
| **制作视频**（从 URL、简报、主题、GitHub PR、现有素材或单个元素动画）                                                                                     | 下方的**视频路由器**（§ 视频路由）             |
| **编写/编辑 HTML 组合** — `data-*` 合约、片段、轨道、子组合、变量                                                                                     | `/hyperframes-core`                          |
| **动画** — 原子运动规则、场景蓝图、过渡、运行时适配器（GSAP / Lottie / Three.js / Anime.js / CSS / WAAPI / TypeGPU）                               | `/hyperframes-animation`                     |
| **创意指导** — `design.md`、调色板、字体、旁白、节拍规划、音频响应式                                                                                     | `/hyperframes-creative`                      |
| **媒体预处理** — TTS 配音、背景音乐、转录、背景移除、字幕                                                                                             | `/hyperframes-media`                         |
| **CLI 开发循环** — 初始化、检查、验证、预览、渲染、发布、诊断                                                                                       | `/hyperframes-cli`                           |
| **安装注册块/组件**（`hyperframes add`）                                                                                                     | `/hyperframes-registry`                      |

> 组合**编写合约**（每个定时元素都需要 `data-start` / `data-duration` / `data-track-index`；定时元素需要 `class="clip"`；GSAP 时间线在 `window.__timelines` 上暂停并注册；仅确定性逻辑 — 没有 `Date.now()` / `Math.random()` / 网络）**不在此处重复** — 它位于 `/hyperframes-core`。在编写组合 HTML 之前阅读它。

## HyperFrames 无法做什么 — 首先检查此内容

HyperFrames 编写 HTML 组合并将其渲染为 MP4 **从代码**。该模型具有硬性的外部边界。超出其中之一的请求不是路由选择 — 它是**超出范围**，因此拒绝（或指向正确的工具）而不是寻求工作流程。这些源于架构，而不是任何单个请求：

- **渲染是确定性和自包含的。** 每个值、资源和文本在您编写时都已烘焙；渲染不会进行网络调用，也不会在渲染时拉取实时/渲染时数据（核心规则：没有 `Date.now()` / `Math.random()` / 网络）。"在渲染时实时刷新数字" 是不行的 — 在编写时获取一次数据并烘焙它，或者拒绝。
- **现有视频是叠加，从不编辑。** HyperFrames 在源剪辑**之上**组合帧 — `/embedded-captions` 添加字幕层，`/graphic-overlays` 添加设计的图形卡片（下三分屏、数据调用、标题）— 下面播放的剪辑保持不变，但既不处理编码的视频流。改变素材**本身**（其时间、颜色、构图、顺序或音频）是 NLE 风格的编辑，超出范围。
- **Remotion 导入是一方向的。** `/remotion-to-hyperframes` 将 _Remotion 框架的_ 源转换为 HyperFrames。没有反向（HyperFrames → Remotion，或 → 任何其他框架 — 超出范围），非 Remotion React / 网络动画源没有 Remotion 源可以翻译 — 通过 `/general-video` 重新创建它。
- **它无法产生它没有的输入。** 没有屏幕 / 会话录制、没有相机捕捉、没有 AI 谈话头 / 嘴型同步头像生成。如果素材或资源不存在，HyperFrames 无法凭空创造它 — 首先要求用户提供它（或使用正确的捕捉工具）。

所有其他内容 — 从 URL、简报、主题、PR、要注释的素材或单个要动画的元素 — 都在范围内；在下方路由。

# 视频路由

本节仅了解顶级工作流程。它不会加载工作流程内部的阶段、域技能（`hyperframes-*` — 见上方的能力图谱）、或技术参考。

## 决策表

**输入类型（意图）是主要轴；输出长度只是上限，不是门槛。** 对于匹配的输入，专业工作流程处理任何**长达 ~3 分钟** — 哪个工作流程您进入由意图（输入类型，对于文本是主题）决定，而不是长度。长度只在高端重要：一个真正更长的片段（3-5 分钟教程、5 分钟+ 深入探讨）是不同的注册，路由到 `/general-video`。在 ≤~3 分钟范围内，第三个轴将两个文本输入工作流程分开 — **主题**：被营销的产品 vs 被解释的主题（见第 3 步中的歧义规则）。| 长度 / 输入  | 产品发布（URL / 简报） | 一般网站 / URL | GitHub PR / 代码更改 | 主题 / 文章 / 笔记（没有产品，没有 URL） | 现有视频（谈话头） †              |
| --------------- | ------------------------------------- | --------------------- | ----------------------- | -------------------------------------------- | -------------------------------------------- |
| **≤ ~3 min**    | `/product-launch-video`               | `/website-to-video`   | `/pr-to-video`          | `/faceless-explainer`                        | `/embedded-captions` · `/graphic-overlays` † |
| 3-5min 教程     | `/general-video`                      | `/general-video`      | `/general-video`        | `/general-video`                             | `/embedded-captions` · `/graphic-overlays` † |
| 5min+ 深入探讨 | `/general-video`                      | `/general-video`      | `/general-video`        | `/general-video`                             | `/embedded-captions` · `/graphic-overlays` † |
| 静态 / 循环   | `/general-video`                      | `/general-video`      | `/general-video`        | `/general-video`                             | `/general-video`                             |

当前覆盖范围：**≤ ~3 分钟** 范围内有专门的工作流程用于 **产品发布 / 一般网站 / GitHub-PR / 主题** 输入（URL 通过 _种类_ 然后 _意图_ 分割 — 见第 3 步），并且**现有视频**列在**任何长度**下都有覆盖 — 由 `/embedded-captions`（字幕 / 字幕）或 `/graphic-overlays`（设计的图形叠加层）覆盖，按意图分割（见第 2 步）。**其他所有单元格都是 `/general-video**` — 通用 HTML 组合编写流程（输入和长度无关）：所有**超过 ~3 分钟**（3-5 分钟 / 5 分钟+ 行）和所有**静态 / 循环**格式。路由器永远不会在可创建的视频上死锁；唯一真正的“通用 / 无”答案是请求超出 HyperFrames 本身（例如，对完成的视频文件进行 NLE 风格的剪辑/编辑 — 重新计时、重新着色、重新构图、重新排序、音频）。

† **现有素材按意图分割，而不是按长度。** 字幕 / 字幕 → `/embedded-captions`；设计的图形叠加层 / 包装 — 下三分屏、数据调用、标题卡片、引语 — → `/graphic-overlays`。两者都叠加在剪辑上，下面播放的剪辑保持不变；两者都不编辑素材本身。

**类型短路（位于表格之前）。** 一个短（~10 秒以下）、无旁白、以设计为主导的**动态图形** — 动态文字、一个统计 / 数字计数、一个图表 / 数据可视化、一个标志冲击、一个下三分屏 / 叠加层，或一个动画推文 / 标题 / 捕获页面高亮 — 无论输入如何，都路由到 `/motion-graphics`。这是一个输出类型，不是输入类型，因此当要求明显是动态优先且无旁白时，无论输入如何，都优先于此输入类型表。更长时间或带旁白的处理不是此类型（按输入类型路由，或 `/general-video`）。

## 迁移现有组合（特殊情况）

上面的表格是用于**从输入创建视频**。有一个工作流程位于其中：如果用户明确要求将**现有的 Remotion (React) 组合**迁移到 HyperFrames → `/remotion-to-hyperframes`。这是源翻译，不是从输入创建，因此它没有 INPUT × 长度单元格。仅在明确迁移语言（“将我的 Remotion 项目移植过来”、“将这个 Remotion 组合转换为”、“将这个 Remotion 组合改写为 HyperFrames”）时路由到这里 — 提供的源仅是提及 Remotion 不会触发；默认使用创建表或 `/hyperframes-core`。

## 路由程序

1. **确定输入类型 + 目标长度。** 路由需要知道**视频是关于什么的** — 它的主题和输入。如果主题本身未指定（例如，没有 URL、命名产品、主题或资源可供使用），或者输入类型未知，**在进入任何工作流程之前询问** — 首先澄清；不要在调用工作流程技能后询问，因为承诺一个工作流程本身就是路由决策。最多问 2 个澄清问题：
   - “您的输入是什么 — 产品（URL 或简报）、一般网站 / URL、GitHub PR / 代码更改、要解释的主题或文章，或要添加字幕的现有谈话头视频？”
   - “目标长度 — 大约 3 分钟或更短，还是更长（3-5 分钟教程 / 5 分钟+ 深入探讨）？”
   - **特定默认值 — 不提问**（这些**不影响路由**，因此永远不要阻止路由）：**宽高比** 16:9（引擎还支持 **9:16** 垂直 — 仅在用户命名垂直目的地（如 TikTok / Reels / Shorts）时切换）；旁白 / 字幕 **语言** = 用户的。如果用户反对，才确认；所选工作流程在其第 0 步重新确认其自身具体细节。
2. **首先按输入类型（意图）选择；长度只是上限，不是门槛。**
   - **以设计为主导的短动态图形（类型短路，位于输入表之前）** — 动画本身是信息：动态文字、一个统计 / 数字计数、一个图表 / 数据可视化、一个标志冲击、一个下三分屏 / 叠加层，或一个动画推文 / 标题 / 捕获页面高亮；通常在 ~10 秒以下，**无旁白 / 配音** → `/motion-graphics`。这是一个输出类型，不是输入类型 — 当要求明显是快速、无旁白、以设计为主导的动态片段时，无论输入如何，都路由到这里。相同材料的更长或带旁白的处理不是此类型（按输入类型路由，或 `/general-video`）。
   - **现有的谈话头视频**（MP4）（用户有一个片段并希望在上面添加内容）→ 按意图分割，**任何长度**（输入类型胜过长度）：**字幕 / 字幕**（说话内容作为可读文本）→ `/embedded-captions`；**设计的图形叠加层** — 下三分屏、数据调用、标题信息卡片、引语，或一个图形包装编辑 → `/graphic-overlays`。（编辑素材本身 — 重新计时、重新着色、重新构图、重新排序、音频 — 是 NLE 风格，超出范围；见 § HyperFrames 无法做什么。）
   - **GitHub PR / 代码更改**（一个 `github.com/<owner>/<repo>/pull/<N>` 链接、`owner/repo#N` 引用，或在签出库中“这个 PR”）→ `/pr-to-video`（长达 ~3 分钟）（最佳点 ~30-90 秒）（changelog / 功能揭示 / 修复解释 / 重构演练）— 差异高亮、前后、文件树和影响场景
   - **否则**（产品 URL / 简报 / 主题文本）：意图通过第 3 步选择工作流程，并处理任何**长达 ~3 分钟** — 短 15-30 秒促销和 ~100 秒解释都按意图路由，而不是按长度。仅在目标是**明显超过 ~3 分钟**（3-5 分钟教程、5 分钟+ 深入探讨）时才路由到 `/general-video`（长度无关的回退 — 见第 4 步） — 永远不要将一个真正长的片段强行放入 ≤~3 分钟工作流程 — 意图在此范围内决定，`/general-video` 覆盖其余部分。
3. **歧义 ≤~3 分钟 URL / 文本输入（意图分割）。** 两种分割：
   - **URL 种类 + 意图** — URL 不再自动获胜为 PLV；其 _种类_ 然后 _意图_ 决定：一个 **GitHub PR** 链接（`.../pull/<N>`，`owner/repo#N`，"这个 PR") → `/pr-to-video`；否则网站 URL 按意图分割 — **营销 / 发布 / 推广特定产品或 SaaS** → `/product-launch-video`；一个**一般网站 → 视频**（网站导览、作品集 / 博客 / 登录页展示，来自网站自己视觉的社会片段，或仅“将此网站转换为视频”）→ `/website-to-video`。两者都使用无头 Chrome 爬取；PR URL 通过 `gh` 读取。当确实无法确定网站 URL 是产品发布还是一般网站视频时，问一个问题。
   - **产品 vs 主题**（文本，无 URL） — 决定性问题**是视频是关于什么的**，而不是输入格式：
     - 一个特定的 **产品 / 公司 / SaaS / 应用程序 / 网站** 被 **营销、发布或推广** → `/product-launch-video`。
     - 一个 **概念 / 主题 / 文章 / 工作原理** 被 **解释**，**没有产品，没有 URL** → `/faceless-explainer`。
     - 捆绑器："推广 / 发布 / 销售 / 我们的产品" 用语 → PLV。 "解释 / 教学如何 X 工作 / X 是什么" 无产品 → 面无表情。面无表情的发送风格始终是 `pin-and-paper`。
     - **一个没有 URL 的命名网站仍然是 PLV。** 一个提及产品或其网站（"我们的网站是 acme.io"，"推广 <品牌>"）的脚本即使没有可点击链接也路由到 PLV — PLV 可以网络搜索网站并爬取品牌资产（除非用户选择退出，→ no-capture 预设模式）。**不粘贴 URL 不会**使其成为面无表情 / 无捕捉工作。提供的脚本在 PLV 内部的逐字与重构选择是内部的，永远不会改变路由。
     - **冲突提示 → 不猜测。** 如果提供的源是一个产品的**自己的营销**（其登录页、关于 _他们_ 平台的促销博客）但用户明确要求**去除推广** — 一个**中性的解释性视频**，而不是广告 — 将其视为确实模糊（视频是关于 _他们的产品_，还是 _一般概念_？）并**问一个问题**，而不是仅凭“中性的”提示就决定为面无表情，对比：一个一般主题，其中产品只是一个用户说要排除的附言（"解释 OAuth 的工作原理 — 我们销售一个认证产品但不要提及它"）是明确**面无表情** — 无需提问。
   - 读完请求后仍不清楚 → 问一个确切的问题：_“这是在推广特定产品、从一般网站制作视频、解释主题/概念、演练 GitHub PR，还是为现有视频添加字幕？”_
4. **回退到 `/general-video`。** 当上述没有匹配时，路由到 `/general-video` — 通用 HTML 组合编写流程（原始 `hyperframes` 流程：设计系统 → 提示扩展 → 计划 → 动画前布局 → 构建（委托给 `hyperframes-*` 域技能）→ 验证。
   - **触发器**：“制作标题卡片”、“动画这个”、“一个更长的品牌 / 炸弹片”、“一个多场景组合”、“一个静态循环 / 长度海报”，或任何“制作视频”不符合上述工作流程的。 （一个短、无旁白、单个动态图形 — 标志冲击、动态文字冲击、统计 / 图表弹出、下三分屏 / 叠加层 — 是 `/motion-graphics`，不是这个。）
   - **不要用于**推广的产品（→ `/product-launch-video`）；一般网站 → 视频（→ `/website-to-video`）；主题 / 概念解释（→ `/faceless-explainer`）；GitHub PR（→ `/pr-to-video`）；为现有视频添加字幕（→ `/embedded-captions`）；迁移 Remotion（→ `/remotion-to-hyperframes`）；**短、无旁白、以设计为主导的动态图形** — 标志冲击、动态文字冲击、统计 / 图表弹出、下三分屏 / 叠加层，或动画推文 / 标题 / 页面高亮（→ `/motion-graphics`）；对完成的视频进行 NLE 风格的剪辑（超出范围）。

## 视频路由超出范围的内容

- **域技能**（`/hyperframes-core`, `/hyperframes-animation`, `/hyperframes-cli`, `/hyperframes-creative`, `/hyperframes-media`, `/hyperframes-registry`） — 这些**不在此处路由**，但它们在 **能力图谱** 中位于本技能的顶部；工作流程的构建阶段加载它们作为技术参考。
- **工作流程内部阶段** — 阶段位于每个工作流程的文件夹内，由该工作流程的编排器调度，而不是由此路由器调度。
