# media-use

HyperFrames 的媒体操作系统：解析 · 生成 · 操作 · 记忆 — 支持所有媒体类型，一项技能，零上下文干扰。

首次运行：安装并登录 `heygen` CLI（免费使用路径），然后使用 `node <SKILL_DIR>/scripts/resolve.mjs --doctor` 进行验证。设置和提供者：`references/setup-providers.md`。

## 解析 — 一个动词

```bash
node <SKILL_DIR>/scripts/resolve.mjs --type <type> --intent "<description>" --project <dir>
```

返回一行：`resolved <id> → <path> (<type>, <metadata>)`。所有搜索噪音保留在磁盘上。

| 类型    | 一行意图                                                                     |
| ------- | ----------------------------------------------------------------------------------- |
| `bgm`   | 背景音乐（HeyGen 目录，10k+ 曲目）                                      |
| `sfx`   | 音效（捆绑 19 文件库 + 目录）                                   |
| `image` | 照片、背景（HeyGen 资产搜索，75k+ 矢量）                             |
| `icon`  | 图标、符号（透明）                                                        |
| `logo`  | 官方品牌标志（svgl → 简单图标 → GitHub 头像 → 网站图标；永不重绘） |
| `voice` | TTS 配音（HeyGen 免费使用路径；可选本地 Kokoro）                       |
| `grade` | 测量校正候选；后续将根据媒体处理进行广泛润色/风格化    |
| `lut`   | 用户提供的或明确选择的可重用验证 `.cube` 文件                  |

在解析新内容前，使用 `--candidates` 列出可重用候选并自行判断匹配度 — 重用规则、所有标记、摄取 (`--from`) 和采用都在 `references/resolve.md` 中。

## 将广泛的视觉反馈视为媒体意图

当用户明确要求修复、润色、风格化、模糊、强调或
揭示摄影媒体时，即使他们没有提及调色或效果，也要阅读 `references/media-treatments.md`。检查真实的 `<img>`/`<video>`，选择一个主要意图，然后使用确定性持久化和验证。
使用匹配的配方作为可选的测试种子，或检查
`hyperframes media-treatment --capabilities --json`，然后使用 `--capability <id>` 请求一个相关的系列/效果，并从规范控制组装一个自定义处理。对普通创作不要加载 `--all`。一个处理可以组合校正、预设、完成、兼容的着色器效果、支持的关键帧和可选的 Registry 叠加。仅添加基于来源的有限调整和兼容部分，永不使用仅为了使结果看起来更高级的效果。使用
`hyperframes media-treatment` 持久化最终组合的有效负载。

使用逐步升级的工作流程。对视频，检查标记为早期/中期/晚期的接触表，而不是单独读取帧。应用一个候选并检查表后进行普通校正或润色。仅在结果模糊、时间性、风格化、基于 LUT、对 HDR/LOG 敏感、私密或品牌关键时，才升级到单个帧或动态草稿证据。

对普通校正或润色，持久化最终处理的预设/调整 JSON。
不要仅为了编码曝光、阴影、对比度或暖色而生成 `.cube` LUT。仅在用户提供或所选处理明确拥有时使用 LUT。`resolve --type grade --for ... --analyze` 是测量证据，不是用生成的 LUT 替换所选处理的权限。
不要使用 CSS/SVG 叠加重新创建支持的光晕、颗粒、模糊、像素化、颜色或处理效果；那绕过了 Studio 控制和规范预览/渲染着色器路径。

## 主动行动 — 运行媒体机会扫描

人类通常无法判断哪种媒体能提升作品。你能。在构建或审查构图时，进行**一次**基于现实的扫描，然后**询问一次** — 不要默默添加，也不要按每个资产烦扰。

仅在存在具体信号时才暴露机会：

| 检测到的信号                                          | 提供                                                                                                  |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 屏幕上的文本 / 无配音的脚本                          | TTS 配音（音频引擎）                                                                           |
| 表情符号或样式为图标的 `<div>`                     | 解析真实的 `icon`s                                                                                   |
| 作为占位符、极小或看起来被放大的图像                   | 更好的 `image`（以及/或放大 — 见 `references/operations.md`）                                     |
| 硬场景剪辑 / 无声音的过渡                          | 过渡 `sfx`                                                                                       |
| 持续约 10 秒而无背景音乐的作品                      | `bgm`                                                                                                  |
| 读数曝光不足/过度或色偏的素材                      | 校正 `grade`（使用 `hyperframes media-treatment --selector '#hero' --analyze --json'` 检查） |
| 视觉上平淡或主题不符的摄影媒体                      | 一个特定来源适用的预设或自定义处理，并命名目标                                                 |
| 意义重大的媒体进入/揭示但感觉静态                   | 一个支持的安全搜索处理动画；除非请求也证明预设，否则保留颜色 |

保持这只是一个帮助而非烦扰的规则：**基于现实，而非泛泛**（无信号 → 无建议）；**主观且具体**（提出具体的修复方案并选择默认值 — 人类批准**全部 / 部分 / 无**）；**每个项目一次**（一个整合的请求；尊重“保留原样”）；**暴露，永不默默变异**（调色尤其如此：提议并预览 — 灰度世界的“校正”会毁掉有意为之的日落或霓虹外观）。
