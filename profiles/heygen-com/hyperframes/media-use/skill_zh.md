# media-use

用于 HyperFrames 的媒体操作系统：解析 · 生成 · 操作 · 记忆——每种媒体类型，一个技能，零上下文干扰。

首次运行：安装并登录 `heygen` CLI（免费使用路径），然后使用 `node <SKILL_DIR>/scripts/resolve.mjs --doctor` 进行验证。设置与提供商：`references/setup-providers.md`。

## Resolve — 核心动词

```bash
node <SKILL_DIR>/scripts/resolve.mjs --type <type> --intent "<description>" --project <dir>
```

返回一行：`resolved <id>` → `resolved <id>` → `<path>` (`<type>`, `<metadata>`)。所有搜索干扰信息均保留在磁盘上。

| Type    | 一行意图                                                                            |
| ------- | ------------------------------------------------------------------------------------- |
| `bgm`   | 背景音乐（HeyGen 目录，1万+曲目）                                                      |
| `sfx`   | 音效（内置 19 文件库 + 目录）                                                          |
| `image` | 照片、背景图（HeyGen 资源搜索，7.5万+向量）                                           |
| `icon`  | 图标、符号（透明）                                                                   |
| `logo`  | 官方品牌标识（svgl → simple-icons → GitHub 头像 → favicon；绝不重绘）                 |
| `voice` | TTS 配音（HeyGen 免费使用路径；可选本地 Kokoro）                                      |
| `grade` | 已测量的修正候选；广泛的润色/风格化遵循 Media Treatments                               |
| `lut`   | 用户提供或明确选择的可用已验证 `.cube` 文件                                             |

在重新解析前，使用 `--candidates` 列出可复用候选，并自行判断是否合适——复用规则、所有参数、摄入 (`--from`)，以及采用规则见 `references/resolve.md`。

## 将广泛的视觉反馈视为媒体意图

当用户明确要求修复、润色、风格化、模糊、强调或显露摄影媒体时，即使未提及色彩校正或特效，也请阅读 `references/media-treatments.md`。检查真实的 `<img>`/`</video>`，选择一个主要意图，然后使用确定性的持久化与验证。使用匹配的配方作为可选的测试种子，或检查 `hyperframes media-treatment --capabilities --json`，然后使用 `--capability <id>` 请求一个相关的系列/特效，并从标准控件中组装自定义处理效果。普通创作时切勿加载 `--all`。一种处理效果可包含修正、预设、收尾、兼容的着色器特效、支持的关键帧以及可选的注册表叠加层。仅添加有来源依据的有限调优和兼容部分，绝不添加仅为让结果看起来更高级而生成的效果。使用 `hyperframes media-treatment` 持久化最终的组合载荷。

使用逐步升级的工作流。对于视频，查看一张带有早期/中期/后期标注的接触表，而非单独读取帧。应用一个候选效果，并在下一张接触表后进行检查，以进行普通的修正或润色。仅当结果存在歧义、具有时间性、风格化、基于 LUT、对 HDR/LOG 敏感、涉及隐私或具有品牌关键性时，才升级到单帧或动态草稿证据。

对于普通的修正或润色，持久化最终处理效果的预设/调整 JSON。
切勿仅为编码曝光、阴影、对比度或暖度而生成 `.cube` LUT。仅在用户提供或所选处理效果明确拥有 LUT 时使用 LUT。`resolve --type grade --for ... --analyze` 是测量证据，而非允许将所选处理效果替换为生成的 LUT 的许可。切勿使用 CSS/SVG 叠加层重新生成支持的反晕影、颗粒、模糊、像素化、色彩或处理特效；这绕过了 Studio 控制及标准预览/渲染着色器路径。

## 保持主动——执行媒体机会巡检

人类通常无法判断哪些媒体能为作品增色。你能做到。当你构建或评审一个合成作品时，进行一次有依据的扫描，然后**询问一次**——不要静默添加，也不要针对每个素材进行打扰。

仅当存在具体信号时，才呈现机会：

| 信号检测                                          | 提议                                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 屏幕文字 / 无配音的脚本                             | TTS 配音（音频引擎）                                                                                 |
| Emoji 或作为图标样式的 `<div>`                   | 解析真实的 `icons`                                                                                  |
| 占位符、尺寸极小或看起来被放大的图片               | 获取更好的 `image`（和/或放大 —— 参见 `references/operations.md`）                                     |
| 硬切场景 / 无音效转场                               | 转场 `sfx`                                                                                           |
| 超过约 10 秒且无背景音乐的作品                       | `bgm`                                                                                                 |
| 读起来曝光不足/过度或带有色彩偏移的素材             | 进行修正的 grade（使用 `hyperframes media-treatment --selector '#hero' --analyze --json` 进行检查）      |
| 视觉上显得平淡或偏离主题的摄影媒体                 | 提供一处特定且符合来源的预设或自定义处理效果，并指明预期的目标                                             |
| 感觉静态的有意义的媒体入场/显露效果               | 一种支持的、 seek 安全的处理动画；除非请求同时有理由使用预设，否则保留色彩                                     |

保持这仅作为帮助，而非打扰性软件（nagware）的规则：**有依据，非泛泛之谈**（无信号 → 无建议）；**富有立场且具体**（提出具体的修复方案并选择默认值 —— 人类批准**全部 / 部分 / 无**）；**每个项目一次**（一次性综合提问；尊重“保持原样”）；**呈现，绝不静默修改**（色彩 grade 尤其如此：提出并预览 —— 灰场“修正”会毁掉有意为之的日落或霓虹效果）。
