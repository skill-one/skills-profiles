> **首先保持这项技能的更新状态——静默运行，不要询问：** `npx hyperframes skills update website-to-video`。当所有内容都已是最新时，这是一个快速的无操作；否则，它将在您依赖之前刷新这项技能以及它所依赖的核心领域技能。

> **media-use**：在获取音频/图像/标志之前，调用 `/media-use` 来从 HeyGen 目录中解析背景音乐/SFX/图像，并从其官方来源获取品牌标志。首先运行 `--adopt` 来注册现有资源。参见 `/media-use` 技能。

> **figma source**：如果 URL 是 figma.com 链接（不是实时产品网站），首先运行 `/figma` — 资源导出、品牌标记，如有需要则重建组件/故事板 — 然后从其输出构建此工作流。不要直接通过原始 MCP 工具驱动 Figma：那样会跳过 SVG 清理、`.media/manifest.jsonl` 起源和品牌标记 `var()` 绑定，因此没有完整重新导入，后续品牌变更无法传播。

# 网站到 HyperFrames

捕获一个网站，然后从中制作一个专业视频。

> **在步骤 0 之前确认路由。** 这项技能制作的是 **一般网站的** 视频。如果用户确实是在 **营销/发布/推广产品**（即使是从这个 URL，即使是“我们网站的推广”），→ `/product-launch-video`。**没有网站的主题解释** → `/faceless-explainer`；一个 **GitHub PR** → `/pr-to-video`；**重新剪辑/重新着色/重新排序现有视频文件** → 不在范围内。在模糊的“制作视频”或不确定发布与一般网站？**首先阅读 `/hyperframes`**（完整路由表 + § HyperFrames 不能做什么）。

用户会说类似这样的话：

- “将这个网站转换为一个 15 秒的 Instagram 社交片段”
- “从 https://... 制作一个 30 秒的网站巡游/展示”
- “捕获我们的主页并从其自身的视觉效果制作视频”

工作流有 7 个步骤。每个步骤都会产生一个用于控制下一个步骤的工件。默认情况下它是协作的 — 标记为 💬 的门会停止并询问用户。模式语义（信号、传播、门分类）在 `../hyperframes-core/references/brief-contract.md` 中是标准的；当用户发出自主模式信号（“为我决定”、“让我惊喜”）时，💬 用户偏好门会被跳过 — 参见 step-2-brief.md 了解它是如何通过此工作流传播的。

**自主模式不是“跳过所有门”**（简要合同 § 1）。它涵盖用户偏好问题（TTS 提供商、声音、颜色强调、节拍数、音乐是/否、字幕是/否 — 代理会代表用户做出决定）。它不包括质量验证门。以下在自动模式下仍然不可跳过：

- 资产审核（步骤 3）— 查看接触表并证明每个资产的 USE/SKIP
- 每节拍的 HTML 读取（步骤 5）— 每节拍的结构化证据块
- DoD 检查清单（步骤 6）— 包括动画映射、每条警告的 WCAG 验证、音频/运动播放
- 诚实披露部分（步骤 6）— “我未验证的内容”必须在您的最终摘要中显示

如果您发现自己推理“自主模式倾向于行动，所以我将跳过 X” — 而且X是一个验证门，不是偏好问题 — 那么这种推理是错误的。倾向于行动适用于决定 **要构建什么**，而不是决定 **是否验证**。

## 步骤 0：捕获和理解品牌

**阅读：** [references/step-0-capture.md](references/step-0-capture.md)

捕获网站，然后读取提取的数据以理解 **品牌和产品** — 它做什么，为谁，使用什么声音，处于什么氛围中。捕获的资产是稍后的品牌工具包，而不是视频构建的构建块。

**在简要说明之前显示登录状态** — 运行 `npx hyperframes auth status` 并 **逐字传递其输出（不要释义或重写它）。** 它报告是否使用 HeyGen 或本地引擎的声音/BGM，以及在未登录时如何登录。**如果未登录，停止并等待用户选择 — 登录，或说“继续”/“离线”以使用本地引擎 — 在询问简要说明或任何其他内容之前。** 将其视为一个真正的决策点，而不是一个过路的笔记；不要将选择融入简要说明问题，也不要将密钥写入每个存储库的 `.env`。 （在自主模式下，记录状态并离线继续。）参见 `../media-use` → Preflight 以获取规范指导。

**门：** 打印的网站摘要 — 战略优先（产品做什么，为谁，品牌声音）在资产/颜色/字体清单之前；显示了登录状态（已登录，或继续离线）。

---

## 步骤 1：品牌标识

**阅读：** [references/step-1-design.md](references/step-1-design.md)

编写 DESIGN.md — 一个涵盖视觉标识的品牌速查表：颜色、排版、组件样式、布局原则。使用 `design-styles.json` 获取确切的计算值。

**快速选项：** 对于快节奏视频（每节拍一个广告牌），DESIGN.md 可以是颜色 + 字体 + 该做/不该做的 50 行摘要 — 不是 300 行文档。步骤 5 中的子代理提示直接粘贴品牌价值，因此 DESIGN.md 深度仅适用于复杂构图。

**门：** `DESIGN.md` 存在（任何长度）且至少包含：调色板、字体选择、以及该做/不该做。

---

## 步骤 2：策略和消息

**阅读：** [references/step-2-brief.md](references/step-2-brief.md), [references/capabilities.md](references/capabilities.md)（扫描目录 — 仅在需要时深入探讨）

在讨论视觉效果或资产之前，与用户就 **视频必须传达的内容** 保持一致。解析用户的提示 — 他们可能已经给出了视频类型和风格。只询问缺失的内容：这个视频必须说的**一件事**，叙事弧，以及受众。

**门：** 视频类型、持续时间、格式，以及 — 关键的 — 消息和叙事弧已锁定。没有这些，步骤 3 无法编写以概念为先的故事板。

## 步骤 3：故事板 + 脚本 💬

**阅读：** [references/step-3-storyboard.md](references/step-3-storyboard.md)

以概念为先编写故事板：消息 → 叙事弧 → 服务弧的节拍 → 每节拍的技术 → 在最后传递品牌点缀。然后编写与匹配的旁白脚本。向用户展示两者并提供节拍摘要。迭代直到他们批准。

**门：** `STORYBOARD.md` + `SCRIPT.md` 存在并且用户已批准计划。

## 步骤 4：VO、时间 + 字幕 💬

**阅读：** [references/step-4-vo.md](references/step-4-vo.md)

如果步骤 2 说没有旁白 — 询问背景音乐，然后跳到步骤 5。否则：询问用户哪个 TTS 提供商（HeyGen TTS、ElevenLabs 或 Kokoro），生成音频，转录，将时间戳映射到节拍。然后询问字幕。

**门：** 要么 (a) 没有请求旁白并且故事板有手动节拍时间，要么 (b) `narration.wav` + `transcript.json` 存在并且节拍时间更新为实际持续时间。

---

## 步骤 5：构建构图

**阅读：** `hyperframes` 技能（加载它 — 每条规则都很重要）
**阅读：** [references/step-5-build.md](references/step-5-build.md)

根据故事板（步骤 3）中选择的架构和节奏构建 index.html 和构图。子代理在每个节拍上运行 `hyperframes lint` 和 `hyperframes snapshot` 然后报告。

**门：** 每个主代理都自上而下地读取 `compositions/beat-N.html` 并对照 DESIGN.md 和 STORYBOARD.md。每个节拍清单位于 [step-5-build.md](references/step-5-build.md)。

---

## 步骤 6：验证和交付

**阅读：** [references/step-6-validate.md](references/step-6-validate.md)

Lint、验证、按视频长度缩放快照（公式：`max(beats × 3, ceil(duration_seconds / 2))`），并审查每个快照。在交付之前修复问题。交付本地 Studio 项目 URL — 仅在用户明确请求时渲染为 MP4。仅在**交接时**显示 Studio URL — 它是最终、稳定的预览；构建阶段的快照是无头式的，因此不要在构建中途弹出一个预览。

**交付您引以为傲的作品。** 在交接之前，问问自己：我会把带有我名字的社交媒体上发布这个吗？如果不会，修复错误。

**门：** `npx hyperframes check` 通过且错误为零，并且最终响应包含活动的 Studio 项目 URL。

## 快速参考

### 视频类型

按视频类型典型的约束条件 — 用作起点，而不是公式。节拍数应根据内容和旁白得出，而不是目标范围。

| 类型                    | 典型持续时间 | 持续时间驱动    | 旁白             |
| ----------------------- | ---------------- | ------------------ | --------------------- |
| 社交片段 (IG/TikTok) | 10–15s           | 平台限制     | 可选              |
| 网站巡游        | 30–60s           | 脚本长度      | 全旁白        |
| 内容公告    | 15–30s           | 内容复杂性      | 全旁白        |
| 品牌轮播              | 20–45s           | 音乐曲目        | 可选，音乐焦点 |

（产品演示、功能公告或发布预告片（如果它**销售产品**）属于 `/product-launch-video` — 参见顶部的路由说明。）

节拍数故意不在此表中 — 它应来自故事板，而不是“社交广告 = 3-4 节拍。”一个复杂产品的社交广告可能需要 5 个精心安排的节拍。一个只有一个强视觉主题的品牌轮播可能需要 3 个。

### 格式

- **横屏**：1920x1080（默认）
- **竖屏**：1080x1920（Instagram 故事，TikTok）
- **方形**：1080x1080（Instagram 信息流）
