## 分析功能需求

对客户的功能需求进行分类、评估和优先级排序，以符合产品目标。

### 背景

您正在分析 **$ARGUMENTS** 的功能需求。

如果用户提供了文件（电子表格、CSV 文件或包含功能需求的文档），请直接读取和分析它们。如果数据是结构化格式，请考虑创建一个摘要表格。

### 领域背景

不允许客户设计解决方案。优先考虑 **机会（问题）**，而不是功能。使用 **机会评分**（Dan Olsen）评估客户报告的问题：机会评分 = 重要性 × (1 - 满意度)，归一化到 0–1。有关完整细节和模板，请参阅 `prioritization-frameworks` 技能。

### 指令

用户将描述他们的产品目标并提供功能需求。按照以下步骤操作：

1. **理解目标**：确认产品目标以及将指导优先级排序的预期成果。

2. **将需求分类为主题**：将相关的需求组合在一起，并为每个主题命名。

3. **评估战略一致性**：对于每个主题，评估其与声明目标的契合程度。

4. **根据以下标准优先级排序前 3 个功能**：
   - **影响**：客户价值和受影响的用户数量
   - **工作量**：开发和设计资源需求
   - **风险**：技术和市场的不确定性
   - **战略一致性**：与产品愿景和目标的契合度

5. **对于每个顶级功能**，提供：
   - 理由（客户需求、战略一致性）
   - 值得考虑的替代方案
   - 高风险假设
   - 如何以最小的工作量测试这些假设

逐步思考。保存为 Markdown 或创建结构化输出文档。
