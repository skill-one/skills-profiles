## 客户访谈脚本

创建一个结构化的访谈脚本，挖掘真实洞察，而不仅仅是观点。遵循《妈妈测试》原则——询问客户的生活，而不是你的想法。

### 领域背景

客户访谈是持续发现**第一阶段（探索）**的一个来源。其他来源：干系人访谈、使用分析、数据分析、调查、市场趋势、SEO/SEM分析。产品经理需要直接接触用户、干系人、工程师和设计师——"无需中介"。**产品三重奏**（产品经理+设计师+工程师——特蕾莎·托雷斯）应该在发现过程中共同工作，而不仅仅是产品经理单独工作。

### 背景

你正在为关于**$ARGUMENTS**的研究准备一个客户访谈脚本。

如果用户提供了文件（角色模型、假设列表、产品简介或之前的访谈笔记），请先阅读它们。

### 指示

1. **明确研究目标**：
   - 团队需要回答哪些具体问题？
   - 这项研究将指导哪些决策？
   - 需要验证哪些假设？

2. **创建访谈脚本**，包含以下部分：

   ### 开场（2-3分钟）
   - 介绍自己和目的（学习，而非销售）
   - 设定预期："没有正确或错误的答案。我们在这里是为了从你的经验中学习。"
   - 询问是否可以录音（如适用）
   - 确认可用时间

   ### 热身：背景与情境（5分钟）
   - "告诉我关于你的角色以及典型的一天/一周是什么样的。"
   - "你从事与产品领域相关的活动有多长时间了？"
   - 目标：建立融洽关系并了解他们的背景

   ### 核心探索：待完成的工作（15-20分钟）

   **当前情境和行为**（过去时态，具体实例）：
   - "带我回顾一下你上次[做我们正在探索的事情]的情景。发生了什么？"
   - "你使用了哪些工具或方法？"
   - "花了多长时间？谁还参与了？"

   **痛点与挫败感**（观察，不要引导）：
   - "最困难的部分是什么？"
   - "如果你挥动魔法棒，会改变什么？"
   - "你尝试过用什么来解决这个问题的？发生了什么？"

   **期望结果**（用他们的语言，而不是你的）：
   - "对你来说，这个领域的'好'是什么样的？"
   - "你怎么知道这个是否有效？"

   **付费意愿/优先级**（切身利益）：
   - "你目前在这个问题上花费了多少时间/金钱？"
   - "你是否寻找过更好的解决方案？你发现了什么？"
   - "为了解决这个问题，你会放弃什么？"

   ### 探索技巧
   当你遇到有趣的话题时，使用这些技巧：
   - **"告诉我更多关于那个"**——打开任何话题
   - **"为什么？"**（温和地提问，2-3次）——找到根本原因
   - **"你能给我一个具体例子吗？"**——从观点转向事实
   - **"接下来发生了什么？"**——跟随故事
   - **"那让你感觉如何？"**——捕捉情感强度

   ### 妈妈测试规则
   - 询问**他们的生活**，而不是你的想法
   - 询问**过去**，而不是未来（"你会使用X吗？"是无用的）
   - **少说多听**——目标为80/20比例
   - **访谈期间不要推销**
   - 寻找**强烈的情感**——它们表明真实的痛苦或喜悦
   - **赞美是噪音**——"那听起来很酷！"告诉你什么信息

   ### 结束（3-5分钟）
   - "还有什么我没有问到你认为重要的事情吗？"
   - "我应该和谁讨论这个？"
   - 感谢他们花费时间
   - 分享下一步计划（如有）

3. **定制脚本**：根据具体产品领域、角色和研究目标调整问题。根据可用访谈时间增加或删除部分。

4. **包含记录模板**：
   ```
   参与者：[姓名/ID]
   日期：[日期]
   关键任务：[他们试图完成什么]
   当前解决方案：[他们今天使用什么]
   最大痛点：[他们的首要挫败感]
   期望结果：[成功看起来什么样]
   付费意愿：[他们投入/愿意投入多少]
   惊喜发现：[意想不到的事情]
   后续行动：[下一步]
   ```

保存为Markdown格式。包含脚本和记录模板。
