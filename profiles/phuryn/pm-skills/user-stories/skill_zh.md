# 用户故事

遵循 3C 法则（卡片、对话、确认）和 INVEST 标准创建用户故事。生成包含描述、设计链接和验收标准的用户故事。

**使用场景：** 编写用户故事、将功能拆分为故事、创建待办事项或定义验收标准。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$FEATURE`：要拆分为故事的特性
- `$DESIGN`：设计文件链接（Figma、Miro 等）
- `$ASSUMPTIONS`：关键假设或背景信息

## 步骤详解

1. **分析特性**：根据提供的设计和背景信息
2. **识别用户角色**：和不同的用户旅程
3. **应用 3C 法则：**
   - 卡片：简单的标题和一句话描述
   - 对话：详细讨论意图
   - 确认：清晰的验收标准
4. **遵循 INVEST 标准**：独立、可协商、有价值、可估算、小、可测试
5. **使用简单语言**：小学毕业生能理解的语言
6. **链接设计文件**：用于视觉参考
7. **结构化格式输出用户故事**

## 故事模板

**标题：** [特性名称]

**描述：** 作为 [用户角色]，我想要 [动作]，以便 [收益]。

**设计：** [设计文件链接]

**验收标准：**
1. [清晰、可测试的标准]
2. [可观察的行为]
3. [系统正确验证]
4. [边缘情况处理]
5. [性能或可访问性考虑]
6. [集成点]

## 示例用户故事

**标题：** 最近浏览区域

**描述：** 作为在线购物者，我想要在产品页面看到“最近浏览”区域，以便轻松回顾我考虑过的商品。

**设计：** [Figma 链接]

**验收标准：**
1. “最近浏览”区域显示在每个之前至少浏览过 1 个产品的用户的产品页面底部。
2. 对于会话中首次访问产品页面的用户不显示。
3. 当前产品本身不包含在显示的项目中。
4. 该区域展示带有图片、标题和价格的产品卡片或缩略图。
5. 每个产品卡片标明浏览时间（例如，“5 分钟前浏览”）。
6. 点击产品卡片将用户引导至对应的产品页面。

## 输出交付

- 特性的完整用户故事集
- 每个故事包含标题、描述、设计链接和 4-6 个验收标准
- 故事独立且可按任何顺序开发
- 故事适合一个冲刺周期的大小
- 故事引用相关的设计文档
