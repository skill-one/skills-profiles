## 计划冲刺

通过估算团队容量、选择和排序用户故事，以及识别风险来计划一个冲刺。

### 背景

你正在帮助为 **$ARGUMENTS** 计划一个冲刺。

如果用户提供了文件（积压列表、速度数据、团队花名册或之前的冲刺报告），请先读取这些文件。

### 指令

1. **估算团队容量**：
   - 团队成员数量及其可用性（PTO、会议、值班）
   - 历史速度（过去3个冲刺的平均故事点数）
   - 容量缓冲：为意外工作、错误和技术债务预留15-20%
   - 计算可用容量（故事点或理想小时）

2. **审查和选择用户故事**：
   - 从优先级排序的积压列表中获取（优先级最高的优先）
   - 验证每个故事是否满足就绪定义（清晰的验收标准、估算、无阻塞）
   - 标记需要改进才能承诺的故事
   - 当容量达到时停止添加故事

3. **映射依赖关系**：
   - 识别依赖其他故事或外部团队的故事
   - 合适地排序依赖的故事
   - 标记外部依赖和负责人
   - 识别关键路径

4. **识别风险和缓解措施**：
   - 具有高度不确定性或复杂性的故事
   - 可能延期的外部依赖
   - 知识集中（只有一个人能做）
   - 为每个风险提出缓解措施

5. **创建冲刺计划摘要**：

   ```
   冲刺目标：[一句话描述成功的样子]
   持续时间：[2周 / 1周 / 等.]
   团队容量：[X故事点]
   承诺的故事：[Y故事点跨越Z个故事]
   缓冲：[剩余容量]

   故事：
   1. [故事标题] — [点数] — [负责人] — [依赖关系]
   ...

   风险：
   - [风险] → [缓解措施]
   ```

6. **定义冲刺目标**：一个清晰的单句，概括冲刺的主要价值交付。

逐步思考。保存为markdown格式。
