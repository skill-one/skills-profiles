# 测试场景

从用户故事中创建全面的测试场景，包含测试目标、起始条件、用户角色、分步测试操作和预期结果。

**使用场景：** 编写 QA 测试用例、创建测试计划、定义验收测试场景或验证用户故事实现。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$USER_STORY`：要测试的用户故事（标题和验收标准）
- `$CONTEXT`：额外的测试上下文或约束

## 分步流程

1. **审查用户故事**和验收标准
2. **定义测试目标** - 要验证的具体行为
3. **建立起始条件** - 系统状态、数据设置、配置
4. **识别用户角色** - 谁执行测试操作
5. **创建测试步骤** - 分步分解交互
6. **定义预期结果** - 每个步骤后的可观察结果
7. **考虑边界情况** - 无效输入、边界条件
8. **输出详细的测试场景** - 供 QA 执行

## 示例测试场景

**测试场景：** 产品页面查看最近浏览的产品

**测试目标：** 验证“最近浏览”区域是否正确显示，且不包含当前产品。

**起始条件：**
- 用户已登录或启用了浏览器历史记录
- 用户在当前会话中至少浏览过 2 个产品
- 用户现在位于一个不同于之前浏览项目的产品页面

**用户角色：** 网上购物者

**测试步骤：**
1. 导航到任何产品页面 → 区域应出现在页面底部，显示之前浏览的项目
2. 滚动到页面底部 → “最近浏览”区域可见，包含产品卡片
3. 验证产品缩略图 → 图片、标题和价格正确显示
4. 检查当前产品 → 当前产品不在最近浏览列表中
5. 点击产品卡片 → 用户导航到相应产品页面

**预期结果：**
- 只有在至少浏览过 1 个先前的产品后，“最近浏览”区域才会出现
- 区域显示 4-8 张产品卡片，包含完整信息
- 当前产品不包含在列表中
- 每张卡片显示“X 分钟/小时前浏览”时间戳
- 点击卡片可导航到正确的产品页面
- 性能：区域在 2 秒内加载

## 输出交付物

- 每个验收标准的全面测试场景
- 与用户故事意图一致的清晰测试目标
- 详细的分步测试操作
- 每个步骤后的可观察预期结果
- 边界情况和错误场景覆盖
- 供 QA 团队执行和文档化
