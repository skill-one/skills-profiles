## 客户旅程图

绘制从认知到拥护的全流程客户体验，识别每个阶段的情绪、痛点及改进机会。

### 背景

您正在为 **$ARGUMENTS** 创建客户旅程图。

如果用户提供了文件（访谈记录、调查数据、分析数据、支持工单或现有的旅程图），请先阅读这些文件。如果提供了 URL，请使用网络搜索来了解产品。

### 指令

1. **定义用户画像**：这个旅程由谁经历？使用具有明确目标行为（JTBD）的特定用户画像，而不是泛指的用户。

2. **绘制旅程阶段**（根据产品进行调整）：

   | 阶段 | 描述 |
   |---|---|
   | **认知** | 他们如何首次了解产品？ |
   | **考虑** | 他们评估什么？他们比较哪些替代方案？ |
   | **获取** | 他们如何注册或购买？ |
   | **入门** | 首次使用产品——价值实现时间 |
   | **参与** | 规律使用——建立习惯 |
   | **留存** | 什么让他们持续使用？什么可能导致流失？ |
   | **拥护** | 何时以及为何他们会向他人推荐产品？ |

3. **针对每个阶段，记录**：

   - **触点**：用户与产品、品牌或团队互动的地方（网站、邮件、应用内、支持、社交媒体）
   - **用户行为**：在此阶段他们做什么
   - **想法与疑问**：他们脑海中想什么（“这值得我的时间吗？” “我该如何...？”）
   - **情绪**：他们的感受（兴奋、困惑、沮丧、愉悦）——使用评分或表情符号指示
   - **痛点**：摩擦、困惑、流失风险
   - **机会**：如何在此点改进体验

4. **识别关键时刻**：
   - **领悟时刻**：用户首次体验核心价值时
   - **关键时刻**：他们承诺或放弃的决策点
   - **流失触发点**：用户最常流失的地方

5. **创建旅程图表格**：

   | 阶段 | 触点 | 用户行为 | 情绪 | 痛点 | 机会 |
   |---|---|---|---|---|---|

6. **推荐优先级改进建议**：
   - 哪些痛点对转化或留存影响最大？
   - 哪些快速见效的措施可以立即改善体验？
   - 哪些需要更深入的投资但回报最大？

逐步思考。保存为 Markdown 文档。对于视觉旅程图，建议用户使用 Miro 或 FigJam 基于此分析创建一个。
