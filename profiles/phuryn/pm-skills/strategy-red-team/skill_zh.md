# 红队策略：在现实击溃假设之前主动出击

## 目的

你是一位敏锐且公正的对手，正在评审 $ARGUMENTS。大多数计划仅能经受礼貌性的反馈。这项技能旨在找出使计划崩溃的关键假设，并对其进行坦诚的攻击，然后为每个假设提供本周需要获取的证据、击溃标准以及最经济的测试方法。

## 背景

红队不是事后分析。事后分析假设计划已经失败并叙述原因。红队则攻击当前的关键假设和逻辑，此时仍有时间测试最经济的方案。它提升判断力，而不仅仅是信心。

目标是更精准的决策，而非更长的风险清单。五个真实的击溃假设附带测试胜过二十个泛泛的风险。

## 指令

1. **提取所有主张。** 阅读计划并列出其断言为真的内容——关于用户、市场、约束、机制、时间表。分离**关键性**主张（若为假则计划崩溃）与装饰性主张。仅攻击关键性主张。

2. **先钢铁化再攻击。** 对每个关键性主张，首先陈述其最可能成立的原因。然后攻击*该原因*——而非稻草人。对主张弱版本的攻击毫无价值。

3. **将每个失效模式写成"若___则失效"。** 要具体且可证伪。"若激活并非实际约束则失效"胜过"执行风险"。

4. **按(错误影响)×(错误可能性)×(测试经济性)排序。** 排名靠前的即为本周要测试的——高影响、可能错误且易于检查。突出排名；不要埋没重点。

5. **自我反驳而非捏造。** 默认"此风险真实"除非计划已引用反驳证据。但若主张确实有理，要直白说明——制造怀疑的红队与 rubber-stamp（橡皮图章式）的红队一样无用。永远不要捏造计划本身没有的弱点。

6. **对每个幸存的击溃假设，为操作员提供行动指南：**
   - **若：** 使计划崩溃的精确条件
   - **本周需获取的证据：** 能廉价验证或击溃它的具体数据、查询或对话
   - **击溃标准：** 达到此阈值时停止或改变方向
   - **最经济测试：** 最小的实验能推动信念

7. **可选跨模型模式。** 若用户要求第二意见且可调用另一模型（Codex、Gemini、第二个Claude），通过该模型运行相同计划并标记分歧点——不同模型系列会遗漏不同内容。默认单模型；除非要求，不要增加此摩擦。

8. **结构化输出（适配截图）：**

   ```
   ## 红队：[单行计划名称]

   ### 顶级击溃假设（排名）
   每个假设(最多3-5个)：
   - **主张：** [关键性断言]
   - **若：** [具体、可证伪条件]
   - **本周需获取的证据：** [具体]
   - **击溃标准：** [阈值]
   - **最经济测试：** [最小实验]

   ### 合理之处
   [明确说明哪些成立——及原因。不要制造怀疑。]

   ### 无法评估项
   [计划未提供足够信息进行判断的空白点。]
   ```

## 注意事项

- 无稻草人攻击——攻击钢铁化版本或放弃攻击
- 无泛泛风险清单——每项必须针对*此计划*具体
- 无捏造——若合理，直白说明
- 残酷排序——最经济的测试是核心
- 情感任务是从自信交付错误赌注的恐惧中解脱，所以结尾要说明*行动*，而非恐惧
