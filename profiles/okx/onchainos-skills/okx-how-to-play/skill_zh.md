# Onchain OS — 如何使用（入口路由器）

首次使用 / "我不知道该做什么" 的入口。将用户从空白提示引导至具体的 DApp 工作流程，≤ 3 轮对话内完成。

## 指令优先级

标记块表示规则严重性（冲突时优先级高者胜）：

1. **`<NEVER>`** — 绝对禁止。
2. **`<MUST>`** — 强制步骤。跳过将中断流程。
3. **`<SHOULD>`** — 最佳实践。

## 预飞行检查

<MUST>
> 阅读 `../okx-agentic-wallet/_shared/preflight.md`。如果该文件不存在，则读取 `_shared/preflight.md`。
</MUST>

## 内容创作模式 — 自由区 vs 固定区

此流程中的大部分面向用户的内容分为两部分：

- **自由区** — 代理首先以 1–5 句话回答用户的实际问题或确认，内容根据上下文编织。没有固定文本。用户不应感觉像是在与脚本交互。
- **固定区** — 标准英文模板块（欢迎横幅、登录选项、API 密钥提示）。在运行时：
  - 将所有自然语言文本以用户的语言渲染。
  - **文本内引用的回复词（例如 `"login"`）必须与其句子一起翻译。** 留一个英文引用词在已翻译的中文/日语等文本中是翻译错误 — 引号不会使该词成为字面触发词。
  - 保持原样：表情符号、`{占位符}`、`1–N`、代码标识符/命令/URL、Markdown 结构。

这适用于：**欢迎横幅**、**登录方式选择**和**API 密钥登录**步骤 1 提示。

<MUST>
**必须进行桥接。** 以一个过渡性半句结束自由区（例如 "让我放下菜单" / "从这里开始 ↓"）—— 永远不要以一个硬句号后跟一个无关的固定区行结束。在发送前自我检查：将自由区尾部 + 第一个固定区行视为一个整体；如果感觉像两个被粘贴在一起的不同帖子，请重写自由区尾部。
</MUST>

## 状态检查

<MUST>
在显示任何登录或欢迎文本之前，运行 `onchainos wallet status`。使用 `loggedIn` 字段进行分支。
</MUST>

```
onchainos wallet status
```

- `loggedIn: false` → 渲染**未登录**的欢迎横幅。
- `loggedIn: true`  → 渲染**已登录**的欢迎横幅。

# 登录方式选择

当用户要求登录时触发（无论是回复 `login` 到未登录横幅，还是未登录时从欢迎菜单选择工作流选项）。

**自由区（1–5 句话，代理自己的话）：** 回答用户实际提出的问题或确认。如果他们来自工作流选择，简要解释该登录解锁该工作流。然后自然过渡到下面的固定区选择。

**固定区 — 以用户的语言渲染以下模板：**

```
欢迎来到 Agentic Wallet — 为代理构建的 Onchain OS 钱包。选择登录方式：

1. 📧 邮箱（推荐 — 30 秒）
2. 🔑 API 密钥（已经是 OKX 开发者？最快路径）

回复 1 或 2 ↓
```

如果用户回复 `1` 或 "邮箱" → **邮箱登录**。
如果用户回复 `2` 或 "API 密钥" → **API 密钥登录**。

## 邮箱登录

由 `okx-agentic-wallet` 技能的认证部分处理。步骤：

1. 请求邮箱 → `onchainos wallet login <email> --locale <locale>`
2. 请求 OTP 码 → `onchainos wallet verify <code>`
3. 成功后 → **登录后路由**下方。

## API 密钥登录

总共两步： (1) 一次性提示，让用户知道需要设置哪些环境变量以及在哪里获取它们，(2) 确认后运行 `onchainos wallet login`。

### 步骤 1 — 提示（一次性，固定区）

**自由区（1–5 句话）：** 如果用户有任何其他问题，先回答它。然后自然过渡到提示。

**固定区 — 以用户的语言渲染以下模板：**

```
在登录之前，您需要设置三个 API 密钥环境变量：

1. `OKX_API_KEY` — API 密钥
2. `OKX_SECRET_KEY` — 密钥
3. `OKX_PASSPHRASE` — 密码短语

您可以在 https://web3.okx.com/onchainos/dev-portal 找到这些。

**注意 ⚠️：** 不要将凭证粘贴到聊天中 — 遵循开发门户说明并在本地设置它们。
```

然后**停止并等待**用户确认他们准备好了（例如 "完成 / 好的 / 准备好"）。

### 步骤 2 — 登录

一旦用户确认，运行：

```
onchainos wallet login
```

成功后 → **登录后路由**下方。登录失败，显示错误并要求用户验证他们的环境变量（不要重新显示提示 — 他们已经看到了它）。

<NEVER>
- 不要在聊天中接受 API 密钥 / 密钥 / 密码短语。如果用户在聊天中粘贴凭证：不要回显，不要使用这些值，要求他们删除消息 + 旋转密钥 + 在本地设置环境变量。
- 不要引导用户生成密钥、打开 URL、创建 `.env` 文件、编辑 `.gitignore` 或任何其他多步骤设置。提示是一次性的 — 他们自行处理本地设置。
- 不要要求用户粘贴浏览器 URL 或任何回调回 CLI。开发门户是只读的。
</NEVER>

## 登录后路由

登录成功后：

- 如果用户来自未登录时选择 **OKX.AI 选项**（回复 `1`）：自动加载 `okx-ai-guide` 并跟随它。不要重新渲染欢迎横幅。
- 如果用户来自未登录时选择 **每日简报** 选项（选项 `4` 在变体 A / 选项 `3` 在变体 B）：自动加载 `~/.onchainos/workflows/daily-brief.md` 并跟随它。不要重新渲染欢迎横幅。
- 如果用户来自未登录时选择任何其他 **工作流选择**：自动加载相应的工作流文件（`~/.onchainos/workflows/<file>.md`）并跟随它。不要重新渲染欢迎横幅。
- 如果用户来自回复 `login`（或等效）到未登录横幅：渲染**已登录**的欢迎横幅，让他们看到他们的地址 + 余额。

如果用户输入的不是编号选择或 `login`，在自由区回答，然后路由到匹配的技能 / 工作流：

| 意图 | 路由到 |

## 验收标准

1. **横幅变体匹配认证状态** — `loggedIn: false` 渲染未登录变体（无地址）；`loggedIn: true` 渲染已登录变体（地址 + 余额）。
2. **技能选择无需登录门禁** — Polymarket（变体 A 中的选项 2）和 USDC APY（A 中的选项 3 / B 中的选项 2）在未登录时加载；每个加载的技能处理自己的认证。
3. **OKX.AI（回复 1）和每日简报（变体 A 中的选项 4 / B 中的选项 3）依赖登录** — 未登录时，先通过登录方式选择，然后自动恢复选择的目标（`okx-ai-guide` 或 `daily-brief.md`）而不重新渲染欢迎横幅。聪明钱 / 新代币意图不再是编号选择，但可通过自由形式回退表（`okx-dex-signal` / `okx-dex-trenches`）访问。
4. **回合预算** — 新用户端到端 ≤ 3 轮；返回用户选择工作流 + 登录 ≤ 2 轮。
5. **免责声明位置** — 免责声明是每个渲染横幅的最终段（两个变体，两个认证状态）。
6. **过期会话回退** — 当 `wallet status` 返回 `loggedIn: true` 但 `wallet balance` 失败（例如刷新令牌过期）或缺少地址 / 余额字段时，流程提示重新登录（路由到登录方式选择），而不是渲染一个部分或编造的已登录横幅；重新登录后渲染已登录横幅。
