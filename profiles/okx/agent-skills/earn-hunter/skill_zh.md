# 赚取猎人

OKX 快速赚取、固定赚取和灵活赚取（简单赚取）机会的自动监控器。

**`{baseDir}`** = 包含此 SKILL.md 文件的目录。所有相对路径（references/、templates/、config/）都从此处解析。

## 预检查

1. 验证 `okx` CLI 安装：`which okx`。如果缺失，请通过 `npm install -g @okx_ai/okx-trade-cli` 安装。
   在 OpenClaw 上，还请验证会话内的 `cron` 工具是否在代理工具列表中可用（用于计划——不是 `openclaw` CLI）。
2. 检查可选依赖技能：
   ```bash
   okx skill list --json
   ```
   可选技能（不用于扫描/通知）：
   - `okx-cex-earn` — 需要用于购买指南（订阅执行）
   - `okx-cex-auth` — 需要用于身份验证恢复

   如果其中任何一个缺失，请尝试安装，但如果安装失败，**不要阻止**：
   ```bash
   okx skill add okx-cex-earn
   okx skill add okx-cex-auth
   ```
   - 安装成功 → 继续
   - 安装失败（网络错误、市场不可用等）→ **警告并继续**：
     "⚠ `{skill_name}` 安装失败，扫描和通知功能不受影响。申购引导和认证恢复需要该 skill，后续可以手动安装。"
   - 预检查继续，无论技能安装结果如何
4. 身份验证模式检测 — 运行 **两者**，第一个匹配的胜出：
   - `okx config show --json` → 具有 non-empty `api_key` 字段 → **API 密钥模式**。在所有命令中添加 `--profile live`。
   - 无 API 密钥 + `okx auth status --json` → `"status":"logged_in"` → **OAuth 模式**。不需要 `--profile` 标志。
   - 两者都不是 → **停止**。加载 `okx-cex-auth` 技能并按照登录步骤操作。
5. 初始化配置和状态：
   - 如果 `~/.okx/earn-hunter/` 目录不存在 → `mkdir -p ~/.okx/earn-hunter`
   - 如果 `~/.okx/earn-hunter/config.json` 不存在 → 将 `{baseDir}/config/default.json` 复制到其中
   - 如果 `~/.okx/earn-hunter/state.json` 不存在 → 写入 `{"flash":{},"fixed":{},"flexible":{},"consecutive_failures":0,"last_error":""}`
   - 如果 `~/.okx/earn-hunter/platform.json` 不存在 → 运行 [平台检测](#platform-detection-active-probe--user-confirmation)
   - 总是（重新）安装扫描脚本：`cp {baseDir}/scripts/scan.sh ~/.okx/earn-hunter/scan.sh && chmod +x ~/.okx/earn-hunter/scan.sh`。这是 cron 和交互式扫描都调用的脚本。
   - 写入 `~/.okx/earn-hunter/env.snapshot`，包含解析的工具路径（cron 不能依赖用户的登录 PATH）：
     ```bash
     cat > ~/.okx/earn-hunter/env.snapshot << SNAP
     # auto-generated by earn-hunter activation — $(date -Iseconds)
     OKX_BIN=$(command -v okx)
     NODE_BIN=$(command -v node)
     JQ_BIN=$(command -v jq)
     ACTIVATION_PATH=$PATH
     SNAP
     ```
     扫描脚本会引用此文件以解析工具路径，即使在 cron 的最小 `PATH=/usr.bin:/bin` 下也是如此。

   代理读取的配置/状态/平台 JSON 只用于激活/配置管理。周期性的**扫描本身完全由 `scripts/scan.sh` 执行**（shell + jq）— `jq` 是必需的。使用 `which jq` 进行验证；如果缺失，请安装 (`brew install jq` / `apt-get install jq`)。

## 平台 & 通道检测

三个独立维度：**平台**（代理运行的位置）、**计划程序**（触发扫描的内容）、**通知通道**（警报发送的位置）。

### 平台检测（主动探测 + 用户确认）

**首次运行（没有 `platform.json` 存在）：**

1. 探测环境线索：
   - `OPENCLAW_HOME` 环境变量存在吗？→ 提示：OpenClaw
   - 代理工具列表包含 `cron` / `delivery` 工具吗？→ 提示：OpenClaw
   - `HERMES_HOME` 环境变量存在或 `which hermes` 成功？→ 提示：Hermes Agent
   - 在 Claude Code 会话中运行？→ 提示：Claude Code
   - 以上都不匹配 → 提示：通用
2. 显示检测结果并 **要求用户确认**：
   - "检测到你正在使用 **{detected_platform}**，是否正确？"
   - 用户确认 → 继续
   - 用户说不 → 询问： "你使用的是哪个平台？1) OpenClaw  2) Claude Code  3) Hermes Agent  4) 其他"
3. 初始化平台配置：
   - OpenClaw / Claude Code → 将 `{baseDir}/config/<confirmed_platform>.default.json` 复制到 `~/.okx/earn-hunter/platform.json`
   - Hermes Agent → 将 `{baseDir}/config/claude-code.default.json` 作为基础，设置 `.platform` 为 `"hermes"`，`.scheduler.type` 为 `"cron"`
   - 通用 → 将 `{baseDir}/config/claude-code.default.json` 作为基础，设置 `.platform` 为 `"generic"`，`.scheduler.type` 为 `"manual"`
4. 结果写入 `~/.okx/earn-hunter/platform.json`，后续运行跳过检测。

**后续运行（platform.json 存在）：**
读取 `~/.okx/earn-hunter/platform.json` 并提取 `.platform` 字段（返回 `"openclaw"`、`"claude-code"`、`"hermes"` 或 `"generic"`）。

**检测到的平台上没有可用的计划程序**（仅适用于本应具有计划程序的平台）→ 错误： "当前客户端不支持定时任务，请升级到最新版本。"
**通用平台** → 没有自动计划。通知： "当前平台不支持自动调度，你可以手动说'执行 earn-hunter 扫描'来触发。"

### 配置文件

| 文件 | 范围 | 内容 |
|---|---|---|
| `config.json` | 共享 | 扫描范围（闪赚/定期赚币/活期赚币）、货币、APY 阈值、条款、语言、verboseLog |
| `platform.json` | 平台特定 | 计划程序类型/间隔、通知通道、TG/Lark 凭证 |
| `state.json` | 共享 | 去重状态 |

核心配置 (`config.json`) 在所有平台上都相同。平台配置 (`platform.json`) 不同 — `scheduler.type` 字段决定了如何触发扫描：

**OpenClaw (`openclaw.default.json`):**
- scheduler.type = `"openclaw-cron"` — 通过会话内的 **`cron` 代理工具** 安排（不是 OS crontab，不是 CLI 命令）。该作业作为 **隔离的、轻量级上下文** 代理回合运行，并通过 cron **`announce`** 交付将输出返回到对话通道。notify.channel 默认为 `"session"`，因此扫描输出到 stdout 以供 `announce` 推送（避免重复发送）。

**Claude Code / Hermes / 通用 (`claude-code.default.json`):**
- scheduler.type = `"cron"` — 通过 **OS crontab → `scripts/scan.sh`** 安排（零 LLM 令牌成本），通知通过 TG / Lark curl 从脚本本身发送。

### 通知通道（与平台无关）

按优先顺序检测（PRD 要求：TG 优先）：
1. **Telegram** — `$TELEGRAM_BOT_TOKEN` 和 `$TELEGRAM_CHAT_ID` 都设置 → TG 准备好
2. **Lark** — `platform.notify.lark_webhook` 非空 → Lark 准备好
3. **会话** — 备用，仅在交互模式下工作

TG 和 Lark 是 **独立的推送通道** — 它们的工作与代理客户端是否打开无关。在 OS-crontab 平台上，计划扫描通过直接 curl 发送通知。在 **OpenClaw** 中，计划扫描在隔离的 cron 代理回合中运行，并通过 cron **`announce`** 将输出传递到对话通道（通道 = `"session"`）；除非用户明确切换通道，否则不会使用 TG/Lark curl。

## 激活流程

首次设置。只确认平台 — 其他都使用智能默认值。

### 步骤 1 — 平台检测 & 确认

参见 [平台检测](#platform-detection-active-probe--user-confirmation)。探测环境 → 要求用户确认 → 写入 `platform.json`。

### 步骤 2 — 检测通知通道 & 确认

**必须主动检查可用通道后再继续。** 不要默默地退回到会话。

在 OS-crontab 平台上，计划通知通过直接 curl 发送；在 OpenClaw 上，它们通过 cron `announce` 传递到对话通道。检测顺序（检查每个，报告所有状态）：
1. 检查 `$TELEGRAM_BOT_TOKEN` 和 `$TELEGRAM_CHAT_ID` 环境变量：
   - 两者都设置 → TG 准备好
   - Token 设置但 chat_id 缺失 → 警告: "Telegram 配置不完整（缺少 TELEGRAM_CHAT_ID），跳过 TG" → 继续到下一个通道
   - 两者都未设置 → TG 不可用
2. 检查 `platform.notify.lark_webhook` 或 Lark MCP 工具：
   - Webhook 设置且有效（以 `https://` 开头且包含 `/hook/`）→ Lark 准备好
   - Webhook 设置但格式无效（不以 `https://` 开头或缺少 `/hook/`）→ 警告: "Lark webhook 格式无效，跳过 Lark" → 继续到下一个通道
   - 未配置且没有 Lark MCP → Lark 不可用

**总是要求用户确认通知通道 — 永远不要默默地退回到会话。** 对于监控工具，通知至关重要；默认退回到会话意味着当用户不在对话中时，警报会丢失。

**如果检测到一个或多个外部通道：**

"检测到以下推送渠道可用：
- {list of detected channels, e.g. Telegram / Lark}

你希望通知发到哪里？
1. {detected channel 1}
2. {detected channel 2, if any}
3. 仅在当前会话显示（离线收不到）"

**如果未检测到外部通道：**

"新机会才能推送到你手上。你希望通知发到哪里？
1. Telegram — 需要提供 Bot Token 和 Chat ID（通过环境变量）
2. Lark/飞书 — 需要提供 Webhook URL
3. 仅在当前会话显示（⚠ 离线收不到通知）

推荐配置 Telegram 或 Lark，这样即使不在对话中也能收到提醒。"

- 如果用户选择 Telegram → 指导设置 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_CHAT_ID` 环境变量
- 如果用户选择 Lark → 询问 webhook URL，验证格式（以 `https://` 开头，包含 `/hook/`），写入 `platform.notify.lark_webhook`
- 如果用户选择会话 → 写入 `"session"` 并警告: "⚠ 离线状态下不会收到通知，建议后续配置外部渠道。"

将确认的通道写入 `platform.json` `notify.channel`。

### 步骤 3 — 确认扫描配置（3 步与默认值）

显示默认配置并要求用户确认或自定义。每一步都提供默认值 — 用户可以按 Enter 接受。

**步骤 1/3 — 扫描范围：**
"扫描范围（可多选）：
 [1] Flash Earn（闪赚）
 [2] Fixed Earn（定期赚币）
 [3] Flexible Earn（活期赚币）
 默认：全选"
- 默认：全部三个都启用
- 如果用户选择特定项 → 禁用其他项
- 如果用户只选择 [1] → 设置 `config.fixed.enabled = false`, `config.flexible.enabled = false`; 跳过 Step 2/3 和 3/3
- 如果用户只选择 [3] → 设置 `config.flash.enabled = false`, `config.fixed.enabled = false`; 跳转到灵活特定配置（Step 2/3 询问灵活货币，Step 3/3 询问灵活 APY 阈值）

**步骤 2/3 — 监控币种：**
对于 Fixed Earn: "定期监控币种：全部（默认，按回车）或输入指定币种（如 USDT, SOL）"
- 默认: `"all"` (所有货币)
- 如果用户指定 → 设置 `config.currencies` 为数组 (例如 `["USDT", "SOL"]`)

对于 Flexible Earn: "活期监控币种：USDT, USDC（默认，按回车）或输入指定币种"
- 默认: `["USDT", "USDC"]`
- 如果用户指定 → 设置 `config.flexible.currencies` 为数组
- 注意：灵活需要每个货币 API 调用，因此建议保持列表较小

**步骤 3/3 — APY 阈值：**
对于 Fixed Earn: "定期最低 APY 阈值：不限（默认，按回车）或输入百分比（如 8）"
- 默认: `0` (无限制)
- 如果用户指定 → 设置 `config.fixed.globalMinApy` 为 `value / 100` (例如 8 → `0.08`)

对于 Flexible Earn: "活期最低 APY 阈值：8%（默认，按回车）或输入百分比"
- 默认: `0.08` (8%)
- 如果用户指定 → 设置 `config.flexible.globalMinApy` 为 `value / 100`

自动检测语言并写入到 `config.json` `notify.language`.

将配置写入 `~/.okx/earn-hunter/config.json`.

使用 `{baseDir}/templates/activation.md` 模板（使用用户的语言）显示摘要。

### 步骤 4 — 烟雾测试 & 交付确认

**烟雾测试总是发送通知，无论 `verboseLog` 设置如何。**

1. 立即运行一次扫描周期，并强制 `verboseLog` 为 on 以确保始终生成输出，即使在没有机会时。临时切换 `verboseLog`，运行脚本，然后恢复它 — 并使用 `EH_TEST_NAMESPACE=1` 以确保烟雾测试去重键在 `test:` 前缀下，不会污染生产状态：
   ```bash
   jq '.verboseLog=true' ~/.okx/earn-hunter/config.json > ~/.okx/earn-hunter/config.tmp \
     && mv ~/.okx/earn-hunter/config.tmp ~/.okx/earn-hunter/config.json
   EH_TEST_NAMESPACE=1 OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh
   # 然后恢复 verboseLog 的原始值（例如 false）
   ```
2. **如果找到新机会** → 脚本发送正常通知（从模板渲染）
3. **如果没有找到新机会** → 强制 `verboseLog` 为 on，脚本发送简要状态。可选附加激活确认消息：
   "Earn Hunter 已激活，当前暂无新机会，将在下一轮自动扫描。"
   (使用 `{baseDir}/templates/activation.md` 作为基础，附加没有机会的注释)
4. TG 或 Lark 通道 → **询问:** "已向 {channel} 发送测试消息，请确认是否收到？"
5. 用户确认 → 继续
6. 未收到 → 排查（参见 `notify-channels.md`）
7. 5 分钟无回应 → 一次提示
8. 会话通道 → 跳过确认

**注意：** 烟雾测试忽略 `verboseLog` 设置 — 它始终生成输出以验证端到端管道是否正常工作。

### 步骤 4b — OS-crontab 平台烟雾测试（仅限 OS-crontab 平台）

**关键：** 用户的交互式 shell 具有完整的 PATH，但 cron 没有。运行第二个烟雾测试模拟 cron 的最小环境以验证 `env.snapshot` 工作：

```bash
env -i HOME="$HOME" PATH=/usr.bin:/bin \
  EH_TEST_NAMESPACE=1 OKX_PROFILE=live \
  bash ~/.okx/earn-hunter/scan.sh
```

- 如果退出 0 → cron 将会工作。继续到步骤 5。
- 如果退出 127 / "FATAL: 'okx' not found" → `env.snapshot` 不完整或缺失。重新运行 Preflight 步骤以重新生成它。**不要**继续到步骤 5 — cron 作业将静默失败。
- 向用户显示： "已验证 cron 最小环境下可正常执行。如果此步失败，说明 env.snapshot 中的工具路径有误。"

### 步骤 5 — 设置计划程序

计划机制取决于 `platform.json` `.scheduler.type`。根据平台分支。

#### OpenClaw (`scheduler.type = "openclaw-cron"`)

在 OpenClaw 上，计划是通过在对话中调用会话内的 **`cron` 代理工具** 完成的（永远不会是 OS 命令或 `openclaw cron` CLI）（CLI 路径在此上下文中存在权限问题）。鼓励用户在此聊天中设置它：创建的 cron 作业继承当前会话的通道，因此其扫描输出直接传递到此对话。调用 `cron` 工具，使用 `action: "add"` 和如下形状的 `job`（从 `platform.json` 读取 `.scheduler.interval` 获取频率）：

- `name`: `"earn-hunter-hourly"`
- `schedule`: `{ "kind": "every", "everyMs": 3600000 }` — 从 `scheduler.interval` 导出 `everyMs` (`"1h"` → 3600000, `"30m"` → 1800000, `"2h"` → 7200000)
- `sessionTarget`: `"isolated"` — 在隔离的会话中运行，不是主会话
- `payload`: `{ "kind": "agentTurn", "message": "执行 earn-hunter 扫描", "lightContext": true }`
  - `lightContext: true` 以轻量级引导上下文运行回合（跳过工作空间引导文件）→ 每个回合的令牌成本较低。
  - **令牌预算：** OpenClaw cron 作业没有 **每个作业工具白名单字段**（旧的 `--tools exec,read,write` 标志不再存在）。扫描保持廉价，因为它通过 `exec` 运行 `okx` CLI，并且**不依赖于** 160 多个 okx MCP 工具 — 因此，只要隔离的 cron 代理没有被配置为加载 okx MCP 服务器，只有常规工具（exec/read/write）参与其中。加载哪些工具由代理的配置控制，而不是由此作业控制。
- `delivery`: `{ "mode": "announce" }` — 将回合的输出推送到创建作业的对话通道（通道 = `"session"`）；TG/Lark curl 除非用户明确切换通道，否则不使用。

当它触发时，隔离的代理运行提示 `"执行 earn-hunter 扫描"` → [扫描周期](#scan-cycle)（这会运行 `scripts/scan.sh`，通道 `session`/stdout）→ 传递结果 → `announce` 将其传递到这里。因此，任何新机会都会自动发送。

**不要** 在对话中发出任何 shell/`openclaw cron` CLI 命令 — 仅通过 `cron` 驱动调度。

#### OS-crontab 平台 (`scheduler.type = "cron"` 或 `"launchagent"` — Claude Code / Hermes / 通用)

这些使用 **OS 计划程序 → `scripts/scan.sh`**。脚本执行所有内容（CLI 调用、过滤、去重、渲染、curl 通知）并具有 **零 LLM 成本**。

**安装脚本** — 将技能的 `scripts/scan.sh` 复制到状态目录，以便计划程序有一个稳定的路径：

```bash
mkdir -p ~/.okx/earn-hunter
cp {baseDir}/scripts/scan.sh ~/.okx/earn-hunter/scan.sh
chmod +x ~/.okx/earn-hunter/scan.sh
```

**设置计划程序** — 首先尝试 crontab，如果 cron 守护程序未运行，则回退到 macOS 上的 LaunchAgent：

```bash
# 从当前 shell 解析工具目录
NODE_DIR=$(dirname "$(command -v node)")
OKX_DIR=$(dirname "$(command -v okx)")
JQ_DIR=$(dirname "$(command -v jq)")
CRON_PATH=$(printf '%s\n' "$NODE_DIR" "$OKX_DIR" "$JQ_DIR" /usr.bin /bin | awk '!seen[$0]++' | paste -sd: -)
```

**步骤 A: 尝试 crontab + 验证 cron 守护程序（macOS）**

```bash
(crontab -l 2>/dev/null; echo "0 * * * * PATH=$CRON_PATH OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh >> ~/.okx/earn-hunter/cron.log 2>&1) | crontab -
```

在 macOS (`uname -s` == `Darwin`), 立即检查 cron 守护程序是否运行：

```bash
if [[ "$(uname -s)" == "Darwin" ]] && ! launchctl list com.vix.cron >/dev/null 2>&1; then
  # cron 守护程序未运行 — 回退到 LaunchAgent
fi
```

- 如果 cron 守护程序运行 → 完成，`scheduler.type = "cron"`.
- 如果 cron 守护程序**未**运行 → 删除 crontab 条目并继续到步骤 B.
- 在 Linux → 跳过检查（cron 总是可用），`scheduler.type = "cron"`.

**步骤 B: macOS LaunchAgent 回退** (`scheduler.type = "launchagent"`)

生成 `~/Library/LaunchAgents/com.okx.earn-hunter.plist`，包含解析的工具路径：

```bash
SCAN_SCRIPT="$HOME/.okx/earn-hunter/scan.sh"
LOG_FILE="$HOME/.okx/earn-hunter/cron.log"
INTERVAL=3600  # 从 scheduler.interval 导出: "1h"→3600, "30m"→1800, "10m"→600

cat > ~/Library/LaunchAgents/com.okx.earn-hunter.plist << PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.okx.earn-hunter</string>
    <key>ProgramArguments</key>
    <array>
        <string>/bin/bash</string>
        <string>${SCAN_SCRIPT}</string>
    </array>
    <key>StartInterval</key>
    <integer>${INTERVAL}</integer>
    <key>EnvironmentVariables</key>
    <dict>
        <key>PATH</key>
        <string>${CRON_PATH}</string>
        <key>OKX_PROFILE</key>
        <string>live</string>
        <key>HOME</key>
        <string>${HOME}</string>
    </dict>
    <key>StandardOutPath</key>
    <string>${LOG_FILE}</string>
    <key>StandardErrorPath</key>

PLIST

写入 `scheduler.type = "launchagent"` 到 `platform.json`。通知用户：

"macOS cron 服务未运行，已自动切换为 LaunchAgent 调度（无需 sudo，重启自动恢复）。"

**注意：**
- **OAuth 模式** → 在 plist `EnvironmentVariables` 中省略 `OKX_PROFILE`（或设置为空）。
- LaunchAgent plist 路径必须是绝对路径（不能是 `~`）。激活流程在生成时扩展 `$HOME`。
- `RunAtLoad: true` 意味着第一次扫描在加载后立即运行。
- 脚本读取 `config.json` / `platform.json`，写入 `state.json` / `notify.log`，并通过 curl 发送 TG Bot API 或 Lark Webhook 本身发送通知。在扫描时间点，代理不需要参与。

**重要：** 在 OS 计划程序平台上，**不要** 使用代理平台 `/loop` / Routines（Claude Code `/loop`，云 Routines）。这些会为每个时间点生成 LLM 会话，无法可靠地推送外部通知。（OpenClaw 是例外，它设计为使用其会话内的 `cron` 工具和 `announce` 交付）

## 扫描周期

**整个扫描周期完全由 `scripts/scan.sh` 实现**（纯 shell + jq，零 LLM 成本）。无论是通过 OS crontab 触发，还是通过 OpenClaw 隔离的 cron 代理回合，或通过用户在交互式会话中输入 ("执行 earn-hunter 扫描")，周期都是**相同的**：运行脚本并传递其输出。不要在自然语言中重新实现扫描步骤 — 脚本是唯一的信息来源。

**OpenClaw 隔离的 cron 回合：** 作业的提示路由到这里。运行 `scripts/scan.sh`（使用 `platform.json` `notify.channel = "session"`，脚本将任何通知打印到 stdout）；传递 stdout 作为回合的响应。cron 作业的 `announce` 交付将其推送到对话通道。不要从这个回合 curl TG/Lark — 交付由 `announce` 处理。

### 代理如何运行扫描（交互式触发）

```bash
# Profile: 只在 API Key 模式下传递 OKX_PROFILE (OAuth 模式下省略)。
OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh
```

然后 **传递脚本的 stdout 原文** 给用户：
- 如果脚本打印通知（闪赚/定期赚币/混合/详细状态），显示它。
- 如果脚本打印 **无输出**（静默退出 0，没有新机会 + `verboseLog=false` 情况），告诉用户 "本轮扫描完成，无新机会" — 不要在通道中编造 "扫描完成" 消息；沉默是有意为之。

### 脚本执行的内容（参见 `references/scan-logic.md` 以获取规范）

1. 读取 `~/.okx/earn-hunter/config.json`
2. 运行扫描命令（基于 `flash.enabled` / `fixed.enabled` / `flexible.enabled`）:
   - Flash: `okx [--profile live] earn flash-earn projects --status 0,100 --json`
   - Fixed: `okx [--profile live] earn savings fixed-products --json` (自动回退到 `rate-history` + `fixedOffers` 在 CLI <1.3.3)
   - Flexible: 对于 `flexible.currencies` 中的每个货币，`okx [--profile live] earn savings rate-history --ccy <ccy> --limit 1 --json`
3. 过滤（两层 APY 阈值，条款过滤，货币过滤；灵活使用阈值跨越模型）
4. 去重（针对 `~/.okx/earn-hunter/state.json` (`state.flash["<id>:<status>"]`, `state.fixed["<ccy>:<term>:<rate>"]`, `state.flexible["<ccy>"]`)
5. 如果找到新机会 → 渲染匹配的模板（闪赚 / 定期赚币 / 灵活 / 混合）并通过检测的通道（TG → Lark → 会话），记录到 `notify.log`
6. 更新 `state.json`（写入新键；闪赚 ID 级别的差异清理；定期键级别的差异清理；灵活阈值跨越差异清理；7 天 TTL；失败计数器）
7. 如果没有找到新机会：`verboseLog=true` → 简要状态；`verboseLog=false` → **静默退出 0，无输出，未发送**
8. 错误处理：连续失败计数器（在 3 次连续扫描失败时发送警报 + 重置）；401/会话过期 → 凭证警报 + 停止

**通道路由在脚本内部：** 检测顺序 TG (`$TELEGRAM_BOT_TOKEN`+`$TELEGRAM_CHAT_ID`) → Lark (`platform.json` `.notify.lark_webhook`) → 会话。`platform.json` 中的 `notify.channel` 为 `telegram`/`lark`/`session` 强制该通道。

**认证 / 配置：** 脚本从不读取或打印凭证。它将所有认证委托给 `okx` CLI（它从 `~/.okx/config.toml` 读取）。配置是注入的，只有通过 `OKX_PROFILE` 环境变量。
