# 视频字幕转录

## 使用场景
- 当输入为视频文件，目标为语音提取、带时间戳的字幕转录、多语言字幕转录或编辑准备时间戳时使用。
- 当用户需要语义视觉分析时，使用 `media-analysis` 命令。

如果已存在带时间戳的字幕转录，且仅请求字幕输出，则跳过转录过程并读取本地字幕转换参考文件。

## 不适用场景
- 任务需要新的创意生成或视觉分析，而非语音或字幕。
- 所需输入缺失，猜测会改变结果。

## 执行边界
- 托管的视频字幕转录通过公共 `postplus media transcribe` 动词执行，为异步操作。下方的示例生成命令展示了端点密钥。
- 将本地路径、HTTPS URL、现有的 PostPlus 媒体引用或数据 URI 直接传递给 `--video`。CLI 会验证并准备本地媒体，然后进行单次托管提交。
- 默认情况下，在结果用于生成字幕或编辑决策时请求时间戳。
- 托管的视频字幕转录为异步操作。提交记录会记录运行句柄、当前状态和转录结果，当可用时。检查返回的格式；不要假设固定的标准化转录模式。

## 源文件与路径
- 提交前，从源视频或 URL 中推导出 `durationSeconds` 并通过端点的持续时间标志传递，以进行请求验证。
- 先处理单个源文件，再处理大批量文件。
- 将内部请求、响应、标准化转录和下载的工件保存在 `.postplus/video-transcription` 下；将最终面向用户的面孔转录导出保存在 `.postplus` 外部。

## 交接
- 如果状态为待处理，请保留结果路径并遵循 CLI 返回的操作或恢复命令执行相同操作。不要提交另一个任务。当 CLI 等待/恢复边界达到时停止并报告。
- 当请求 SRT/ASS 格式时，使用实际的带时间戳的转录结果并读取 [本地字幕转换](references/subtitles.md)。无需托管请求即可本地转换；不要编造 CLI 导出命令。

## 停止条件
- 当所需用户意图、源证据或拥有的输入工件缺失，且猜测会改变结果时停止。

## 公共命令边界

- 从用户输入中选择最小匹配的命令或工作流并直接运行。
- 准备状态诊断：`postplus doctor --skill video-transcription`。

- 仅在需要完整的端点、标志和枚举契约或正在修复未知请求形状时使用 `postplus media schema --json`。
- 使用下方生成的命令运行托管转录作业；不要使用其他执行界面。
- 直接通过 `--video` 传递源文件；不要预先上传它或构建手动请求对象。
- 如果 CLI 返回引号确认挑战，请在运行 `postplus quote confirm --json --challenge-file <challenge.json>` 并使用返回的令牌重试之前，获得用户对其范围和成本的批准。
