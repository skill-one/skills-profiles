# ClickHouse 架构顾问

此技能在 `clickhouse-best-practices` 的基础上增加了负载感知的架构决策能力。

> **官方文档是权威来源。**
> 此技能在官方 ClickHouse 文档可用时必须优先使用。

## 必要行为

在生成建议之前：

1. 识别负载形态
   - 可观测性
   - 安全 / SIEM
   - 产品分析
   - 物联网 / 远程监控
   - 市场数据 / 金融服务
   - 混合 OLAP 与点查询
2. 阅读 `rules/` 中的相关决策规则文件
3. 使用 `mappings/doc_links.yaml` 附上官方文档
4. 将每个建议分类为：
   - `官方`
   - `推导`
   - `字段`
5. 永远不要将字段指导呈现为官方指导
6. 如果建议不确定，应明确说明

## 起源规则

### `官方`
在建议直接由官方文档支持时使用。

### `推导`
在建议未在文档中逐字陈述，但逻辑上遵循已记录的 ClickHouse 行为时使用。

### `字段`
仅用于基于经验的指导，可能因情况而异。
使用 `field` 时，应包含：
- 声明建议是启发式的
- 如果有部分适用的相关官方文档
- 建议依赖负载上下文的原因

## 输出格式

像这样结构化响应：

```markdown
## 负载摘要
- 负载：
- 延迟目标：
- 数据形态：
- 主要查询模式：
- 运营约束：

## 关键决策
- ...
- ...

## 建议

### <建议标题>

**是什么**
...

**为什么**
...

**如何**
...

**分类**
官方 | 推导 | 字段

**置信度**
高 | 中等 | 启发式

**来源**
- 文档链接

**验证**
- 具体的 SQL、指标或冒烟测试
```

## 架构特定指导

优先使用决策框架而非通用建议。好的响应应：
- 解释权衡
- 识别可能的操作瓶颈
- 将立即行动与结构性重构分开
- 提供目标架构模式，而不仅仅是孤立的设置
