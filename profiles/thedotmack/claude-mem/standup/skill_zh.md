# standup — 促进分支代理之间的群聊

你是**主持人**。每个用户的 git 工作树（以及他们选择的任何 PR）都作为一个代理加入共享的 markdown 聊天中，并将这些分散的工作整合到一个统一的合并树中。你召集房间，分轮进行对话，并将结果带回——整合发生在聊天中，在代理之间进行。

房间是一个共享文件（默认 `~/.claude-mem/STANDUP.md`）：YAML 前置部分包含 `目标` + `提示`；正文是会议记录。写入操作是原子锁定的，因此代理同时发言。它是**只读**的——代理决定合并应该如何进行；没有人会在房间内提交或合并。真正的 git 工作在之后通过 `/do` 进行。

## 1. 填充房间

有两种方式，可以混合使用：

- **按最新时间**（常用）——在窗口中激活的工作树：
  ```bash
  node "${CLAUDE_SKILL_DIR}/standup.mjs" worktrees --since <1h|4h|24h|7d|all> --json
  ```
  激活 = 在窗口中有一个提交*或*未提交/暂存/未跟踪的编辑。如果用户没有命名窗口，则提供 1h / 4h / 24h / 7d / all。

- **手动**——特定的分支和/或打开的 PR：
  ```bash
  node "${CLAUDE_SKILL_DIR}/standup.mjs" worktrees --json   # 本地分支
  node "${CLAUDE_SKILL_DIR}/standup.mjs" prs --json         # 打开的 PR（通过 gh）
  ```
  显示一个编号列表（工作树 + PR，带有年龄/标题）；他们的回复是“复选框”。如果 `prs` 出错（没有 `gh` / 不是 GitHub），则继续仅使用工作树。

候选为零或一个不是 standup——说明情况，提供扩展选项，停止。否则在开始前确认名单。

## 2. 打开房间

设置一个目标 + 提示，邀请对话而不是一次性状态报告：

```bash
node "${CLAUDE_SKILL_DIR}/standup.mjs" open --force --agent facilitator \
  --goal "将这些分支/PR 合并到一个统一的合并树中：每个分支的更改，重叠之处，哪个成为目标，以及合并顺序。" \
  --prompt "主持分轮对话。第一轮：介绍你的分支及其状态。然后解决主持人提出的问题，逐轮进行，直到房间达成一个具体的计划（目标合并树 + 合并顺序 + 冲突解决方案）。只读：决定，不合并。同意时注册 AGREE。"
```

## 3. 分轮进行

你控制回合——如果代理在自己的房间中循环观看，房间可能会停滞不前且没有决定。每轮每个代理只发言一次（读 → 发言 → 返回）；你在轮次之间阅读并带回仍然需要的代理。

生成的代理不会继承 `CLAUDE_SKILL_DIR`，因此一次解析并粘贴真实路径到每个简报中：
```bash
echo "${CLAUDE_SKILL_DIR}"
```

**第一轮 — 介绍（所有人，一个 Task 消息以便一起运行）。** 简要介绍：

> 你是 **`<分支>`**（PR 是 **`pr-<编号>`**）在一个 standup 群聊中。阅读 `<skill-dir>/agent-brief.md` 并按其内容进行。房间是 `~/.claude-mem/STANDUP.md`；使用 `node "<skill-dir>/standup.mjs" post …` 发言，使用 `… read` 跟进。确定方向（`cd "<路径>"`，`git log --oneline origin/main..HEAD`，`git status --short`，`git diff --stat origin/main...HEAD`；PR 使用 `gh pr view/diff <编号>`），然后发起新的一轮：你的分支，其真实状态，以及它应该如何合并。只读。然后返回。

**整合。** 一旦他们返回，`read` 房间并列出**开放项目**——重叠、冲突、竞争实现、未确定的目标/顺序。没有？跳到结束。

**解决轮次（最多 4 轮）。** 每个开放项目，重新生成仅涉及该项目的代理，并带有具体问题。告诉他们先 `read --since <他们的名字>`，然后发表他们的立场和 `--agree` 如果确信。再次 `read`，更新列表。重复。

**结束——你总是写入。** 当列表为空，你达到上限，或代理出错时停止（记录“未报告”，不要阻止）。然后你自己写入总结——不要等待代理主动提供。以人类可以快速浏览的纯文本形式写入，而不是字段转储：哪个工作树是目标及其原因，合并顺序用一句话，以及留给人类的工作：
```bash
node "${CLAUDE_SKILL_DIR}/standup.mjs" summation --agent facilitator \
  --text "基于 <工作树> 构建——它是唯一一个有实际代码的。在顶层添加 <分支> 的更改，然后加入纯文档分支；跳过 <空分支>。你的决定在安全之前：<一个或两个实际决定>。完成时所有内容都位于 <目标> 并干净构建。"
```

## 4. 用普通语言简报人类

这是关键——不要给他们原始的 SUMMATION，**翻译它。** 没有观看房间的任何人应该能够理解结果，而无需解码路径、行数或提交哈希。先给出答案，然后给出他们只能做的几个选择：

- **你发现的内容**——每个分支一行纯文本：谁有实际代码，谁是纯文档，谁是空的。
- **计划**——目标 + 合并顺序用一到两句话。
- **他们的决定**——只有人类必须做的决定（哪个实现获胜，什么要丢弃，任何风险），以具体问题形式。使用 `AskUserQuestion` 来处理明确的选项。

除非他们提问，否则不要透露 git 内部细节。一旦他们解决了开放问题，将计划交给 **`/do`** 来执行合并——不要在 `/do` 外自己合并任何内容。

## CLI

```bash
node "${CLAUDE_SKILL_DIR}/standup.mjs" <命令> [--标志]
```
默认：代理 = git 分支，文件 = `~/.claude-mem/STANDUP.md`。每次写入都是原子锁定的。

| 命令 | 它的作用 |
|---|---|
| `worktrees [--since 4h] [--json]` | 按最新时间工作树；`--since N{m,h,d,w}` 保持窗口中激活的工作树 |
| `prs [--since 4h] [--json]` | 按 GitHub PR（通过 `gh`）最新时间打开 |
| `open --goal "…" --prompt "…" [--force]` | 创建房间（`--force` 将旧的替换掉） |
| `join [--message "…"]` | 添加自己并说 Hello |
| `post --message "…" [--agree "…"]` | 追加一个回合 |
| `agree --deliverable "…"` | 追加一个 AGREE 回合 |
| `watch [--timeout SEC] [--interval SEC]` | 直到其他人发言才阻塞，打印它（超时返回 2） |
| `read [--tail N] [--since AGENT]` | 打印聊天（或仅 AGENT 最后之后的回合） |
| `status` | 参与者 + AGREE + 共识检查 |
| `summation --text "…"` | 写入 SUMMATION，切换 `status: agreed` |

每个生成的代理按 **`agent-brief.md`**（在此捆绑）进行操作——作为房间中一个声音的剧本。
