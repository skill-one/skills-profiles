# Mermaid 可视化工具

## 概述

将文本内容转换为简洁专业的 Mermaid 图表，专为演示文稿和文档优化。自动处理常见语法陷阱（列表语法冲突、子图命名、间距问题），确保图表在 Obsidian、GitHub 和其他兼容 Mermaid 的平台上正确渲染。

## 快速入门

创建 Mermaid 图表时：

1. **分析内容** - 识别关键概念、关系和流程
2. **选择图表类型** - 选择最合适的可视化方式（见下文图表类型）
3. **选择配置** - 确定布局、详细程度和样式
4. **生成图表** - 创建语法正确的 Mermaid 代码
5. **输出为 Markdown** - 用代码分隔符包裹，可添加可选说明

**默认假设：**
- 垂直布局（TB），除非请求水平布局
- 中等详细程度（在简洁和信息量之间平衡）
- 专业的配色方案，使用语义化颜色
- 兼容 Obsidian/GitHub 语法

## 图表类型

### 1. 流程图（graph TB/LR）
**最适合：** 工作流、决策树、顺序流程、AI 代理架构

**使用场景：** 内容描述步骤、阶段或动作序列时

**关键特性：**
- 通过子图使用泳道对相关步骤进行分组
- 箭头标签用于转换
- 反馈循环和分支
- 颜色编码的阶段

**配置选项：**
- `layout`: "vertical" (TB), "horizontal" (LR)
- `detail`: "simple" (仅核心步骤), "standard" (带描述), "detailed" (带注释)
- `style`: "minimal", "professional", "colorful"

### 2. 循环流程（graph TD with circular layout）
**最适合：** 循环流程、持续改进循环、代理反馈系统

**使用场景：** 内容强调迭代、反馈或循环关系时

**关键特性：**
- 中央枢纽与辐射元素
- 弯曲的反馈箭头
- 清晰的循环指示器

### 3. 对比图表（graph TB with parallel paths）
**最适合：** 前/后对比、A/B 分析、传统/现代系统对比

**使用场景：** 内容对比两种或多种方法或系统时

**关键特性：**
- 并列布局
- 中央对比节点
- 通过颜色/样式清晰区分

### 4. 思维导图
**最适合：** 层次概念、知识组织、主题分解

**使用场景：** 内容具有清晰的父子关系时

**关键特性：**
- 径向树结构
- 多级嵌套
- 清晰的视觉层次

### 5. 顺序图
**最适合：** 组件间交互、API 调用、消息流

**使用场景：** 内容涉及随时间推移的参与者/系统间通信时

**关键特性：**
- 基于时间线布局
- 清晰的参与者分隔
- 过程的激活框

### 6. 状态图
**最适合：** 系统状态、状态转换、生命周期阶段

**使用场景：** 内容描述状态及其转换时

**关键特性：**
- 清晰的状态节点
- 带标签的转换
- 开始和结束状态

## 关键语法规则

**始终遵循以下规则以防止解析错误：**

### 规则 1：避免列表语法冲突
```
❌ 错误：[1. 感知]       → 触发 "不支持的 Markdown：列表"
✅ 正确：[1.感知]         → 逗号后移除空格
✅ 正确：[① 感知]         → 使用圆圈数字 (①②③④⑤⑥⑦⑧⑨⑩)
✅ 正确：[(1) 感知]       → 使用括号
✅ 正确：[步骤 1：感知]   → 使用 "步骤" 前缀
```

### 规则 2：子图命名
```
❌ 错误：subgraph AI Agent Core  → 名称中空格未加引号
✅ 正确：subgraph agent["AI Agent Core"]  → 使用 ID 与显示名称
✅ 正确：subgraph agent          → 仅使用简单 ID
```

### 规则 3：节点引用
```
❌ 错误：Title --> AI Agent Core  → 直接引用显示名称
✅ 正确：Title --> agent          → 引用子图 ID
```

### 规则 4：节点文本中的特殊字符
```
✅ 使用引号包裹含空格的文本：["含空格的文本"]
✅ 转义或避免：引号 → 使用 『』代替
✅ 转义或避免：括号 → 使用 「」代替
✅ 圆形节点中仅允许换行：((文本<br/>换行))
```

### 规则 5：箭头类型
- `-->` 实线箭头
- `-.->` 虚线箭头（用于支持系统、可选路径）
- `==>` 粗箭头（用于强调）
- `~~~` 不可见链接（仅用于布局）

完整语法参考和边界情况，请见 [references/syntax-rules.md](references/syntax-rules.md)

## 配置选项

所有图表都接受这些参数：

**布局：**
- `direction`: "vertical" (TB), "horizontal" (LR), "right-to-left" (RL), "bottom-to-top" (BT)
- `aspect`: "portrait" (默认), "landscape" (宽屏), "square"

**详细程度：**
- `simple`: 仅核心元素，最小标签
- `standard`: 平衡细节与关键描述（默认）
- `detailed`: 完整注释、说明和元数据
- `presentation`: 优化用于幻灯片（较大文本，较少细节）

**样式：**
- `minimal`: 单色，简洁线条
- `professional`: 语义化颜色，清晰层次（默认）
- `colorful`: 鲜艳颜色，高对比度
- `academic`: 正式样式，适用于论文/文档

**附加选项：**
- `show_legend`: true/false - 包含颜色/符号图例
- `numbered`: true/false - 为步骤添加序列号
- `title`: string - 添加图表标题

## 工作流程

1. **理解内容**
   - 识别主要概念、实体和关系
   - 确定层次或顺序
   - 记录任何对比或差异

2. **选择图表类型**
   - 将内容结构匹配到图表类型
   - 考虑用户的演示场景
   - 模糊时默认为流程图

3. **选择配置**
   - 应用用户指定选项
   - 未指定选项使用合理默认值
   - 优化可读性

4. **生成 Mermaid 代码**
   - 严格遵循所有语法规则
   - 使用语义化命名（描述性 ID）
   - 应用一致样式
   - 测试常见错误：
     * 节点文本中无 "数字. 空格" 模式
     * 所有子图使用 ID["显示名称"] 格式
     * 所有节点引用使用 ID 而非显示名称

5. **带上下文输出**
   - 用 ```mermaid 代码分隔符包裹
   - 添加图表结构的简要说明
   - 提及渲染兼容性（Obsidian、GitHub 等）
   - 提供调整或创建变体的选项

## 常见模式

### 泳道模式（分组）
```mermaid
graph TB
    subgraph core["核心流程"]
        A --> B --> C
    end
    subgraph support["支持系统"]
        D
        E
    end
    core -.-> support
```

### 反馈循环模式
```mermaid
graph TB
    A[开始] --> B[处理]
    B --> C[结束]
    C -.->|反馈| A
```

### 中心辐射模式
```mermaid
graph TB
    Central[中心]
    A[辐射 1] --> Central
    B[辐射 2] --> Central
    C[辐射 3] --> Central
```
