# 迁移到并行

端到端替换提供者边界。将成功的 HTTP 响应视为中点，而非完成：迁移请求构建、响应消费者、依赖项、配置、测试和操作行为。

将 `<skill-root>` 解析为包含此 `SKILL.md` 的目录。从此目录解析所有捆绑的引用和脚本，无论当前工作目录如何。扫描器仅使用 Python 标准库。如果无法使用 Python 3.9 或更高版本，则使用 harness 的文件搜索工具执行等效的存储库搜索，并说明未运行捆绑扫描。

## 加载正确的引用

1. 当存储库包含 Exa 时，读取 `[references/exa.md](references/exa.md)`。
2. 当存储库包含 Tavily 时，读取 `[references/tavily.md](references/tavily.md)`。
3. 当存储库包含 Perplexity 搜索、Sonar、Agent API 网络工具或 Perplexity 搜索包装器时，读取 `[references/perplexity.md](references/perplexity.md)`。
4. 当存储库包含 Firecrawl 搜索、Scrape、Batch Scrape、Extract、Agent、Research Index、Crawl、Map、Parse、Browser、Interact、Monitor 或 MCP 使用时，读取 `[references/firecrawl.md](references/firecrawl.md)`。
5. 当任何调用可能路由到 Search 或需要查询、过滤、新鲜度、模式或结果列表迁移时，读取 `[references/parallel-search.md](references/parallel-search.md)`。
6. 当任何调用可能路由到 Extract、Chat、Task 或实体发现，或需要流式传输、结构化输出或引用时，读取 `[references/parallel-products.md](references/parallel-products.md)`。
7. 当查询动态生成、提供者作为模型工具公开、提供者响应类型逸出到多个模块，或应用程序需要完整内容或合成答案时，读取 `[references/integration-patterns.md](references/integration-patterns.md)`。
8. 对于任何未涵盖的 SDK、包装器、参数或响应字段，打开当前官方文档。不要猜测提供者行为。

## 保留这些不变量

- 除非用户明确授权更改，否则保留调用者可见行为。
- 永不静默地丢弃过滤器、内容字段、合成答案、图像、安全控制或基于分数的决策。
- 永不打印 API 密钥或秘密值。仅检查密钥是否存在。
- 不要仅仅为了制造 `search_queries` 而添加一个隐藏的 LLM 调用。
- 不要因为用户提示符合 API 长度限制就将其视为关键字查询。
- 将网络研究意图、硬过滤器、处理策略和答案合成指令保留在其各自的合同中。
- 将省略的提供者参数视为行为：在省略 Parallel 设置之前检查其默认值。
- 不要在兼容性遮罩后面重新创建整个遗留提供者 SDK。仅规范化应用程序实际使用的合同。
- 除非用户明确要求，否则不要从外部秘密管理器或提供者仪表板中删除凭证。删除过时的代码引用并更新签入的模板。
- 将模式映射视为起点。使用应用程序的真实查询验证延迟、质量和输出行为。
- 当所需行为没有支持的 Parallel 等价物且没有范围内的替代方案时，在破坏性编辑之前停止。报告确切的差距和最小的决策需求。
- 当 Perplexity 边界需要嵌入时停止；它们不是 Parallel 搜索的替代品。根据消耗的合同，使用 Search、Chat 或 Task 将 `finance_search` 通过 Parallel 的通用索引路由，仅当硬市场数据覆盖、新鲜度或原始结果要求未保留时才停止。除非用户明确扩展迁移范围，否则将 Agent API 模型路由、沙盒、MCP 和现有自定义函数功能保持分离。
- 当 Firecrawl 边界需要完整爬取或 URL 映射、本地/私有文件解析、浏览器操作或会话、截图或其他丰富抓取格式、变更跟踪或 Firecrawl 特定的隐私/安全控制而没有批准的替代方案时停止。Search 和 Extract 不再重现这些合同。
- 遵循存储库本地指令，如 `AGENTS.md`、`CLAUDE.md` 和 `CONTRIBUTING.md`。保留无关工作，永远不要重置或丢弃用户更改。
- 在清单或计划之后，完成安全的存储库本地迁移工作而不会停止。除非用户要求，否则不要提交、推送、更改托管密钥或更改提供者账户。

## 1. 清点真实的迁移表面

编辑之前记录当前分支和工作树状态。从目标存储库运行捆绑扫描器：

```bash
python3 <skill-root>/scripts/scan_provider_usage.py .
```

使用 `--format json` 获取机器可读输出。扫描器有意跳过依赖项/生成的目录、二进制文件、不可读文件和过大的文件；它无法仅从字段名称识别提供者中立的消费者。将其视为清单辅助工具，而非完整性的证明。检查结果，然后跟踪每个提供者响应到其消费者。还检查：

- 包含清单和锁文件；
- 直接 REST 端点和认证标头；
- SDK 客户端、异步客户端、包装器和模型工具定义；
- 环境模式、示例、部署配置和文档；
- 请求构建器、重试、超时、缓存、可观察性和错误处理；
- 用于渲染、排序、阈值、引用或模型上下文的响应字段；
- Firecrawl 爬取、批量、提取、浏览器、交互、webhook 和工作生命周期消费者；
- 测试、模拟、固定和快照。

在可行的情况下，编辑之前运行现有聚焦测试。记录当前覆盖的行为、预存在的失败行为以及必须手动验证的行为。

在编辑之前，为每个提供者调用站点编写决策行：

| 调用站点 | 提供者产品 | 消费行为 | Parallel 路由 | 语义差距 | 行动 |
| --- | --- | --- | --- | --- | --- |
| `path:line` | Search、Scrape、Agent 等。 | 调用者依赖的输入、输出、生命周期和政策 | 精确的产品路径（如果有） | 路由无法保留的任何内容 | `migrate`、`retain` 或 `block` |

在更改调用之前选择确切的一个行动：

- 仅当建议的路由保留消耗的合同或用户已批准命名差异时，选择 `migrate`；
- 当调用在迁移边界之外或是最小安全方式以保留不支持的功能时，选择 `retain`；
- 当请求的边界无法完成而无需用户决策时，选择 `block`。命名最小的决策，并继续任何独立的 `migrate` 行。

不要使用更广泛的 Parallel 产品仅仅为了消除提供者导入。一个合理的结果形状不是源范围、支出控制、模型行为、生命周期或隐私政策的证据。

## 2. 选择迁移边界

在编辑之前考虑两种设计：

- **直接替换**：当提供者调用很少、相邻且提供者特定的响应类型不会逸出时使用。原子地替换每个调用及其消费者。
- **应用程序拥有的网络数据模块**：当调用分散、需要多个 Parallel 产品或提供者字段逸出到应用程序时使用。将请求构建、响应规范化、重试和遥测隐藏在一个小型的调用者接口后面。使其成为一个深度模块，隐藏提供者细节；不要添加一个传递式包装器。

优先考虑将未来搜索提供者更改本地化并最小化对无关调用者编辑的设计。如果应用程序发布旧提供者的原始响应，则通过正常化保留仅记录的应用程序合同，或一起更新所有消费者。

## 3. 有意迁移请求

围绕这些事实构建每个 Parallel 搜索 API 请求：

- `search_queries` 是必需的。至少提供一个非空的关键字查询；当调用流程可以提供时，使用两个或三个多样化的关键字查询。
- `objective` 是可选的但推荐。将自包含的网络研究目标放在那里，而不是整个用户对话或答案格式说明。
- 使用 `https://api.parallel.ai/v1/search`、`x-api-key` 和 `PARALLEL_API_KEY` 进行直接 REST 调用。
- 除非检测到的框架有当前的第一方 Parallel 集成保留所需的合同，否则使用官方的 `parallel-web` 包（适用于 Python 和 TypeScript）。

在翻译之前对每个遗留输入进行分类：

- 完整的网络研究目标、上下文或软源/新鲜度偏好 → `objective`；
- 简洁的检索探测 → `search_queries`；
- 必须仅或必须不源的限制 → `advanced_settings.source_policy`；
- 答案格式、合成指令、结构化输出或流式传输 → 现有的合成层、Chat API 或 Task API；
- 延迟、结果计数、缓存和摘要控制 → 应用程序拥有的明确选择和测试的策略。

对于静态调用，编写显式的目标和两个或三个关键字探测。对于模型工具，使用 [references/integration-patterns.md](references/integration-patterns.md) 中的确切三查询模式。一个单查询直接调用回退仅适用于已经关键字样式的遗留值，并且必须进行评估。不要静默地截断意图、发明关键字变体、添加隐藏的规划者或将硬过滤器移入文本。

仅在分类之后应用提供者映射。仅保留实现真实产品要求的设置；不必要的 `advanced_settings` 可能会降低质量。

在发送之前，根据 Parallel V1 合同验证运行时值。特别关注查询计数/长度、目标长度、组合 200 域限制、日期规范化和支持的位置代码。不要隐式地携带旧提供者的数字范围。

## 4. 迁移响应行为

更新每个消费者以匹配 Parallel 响应形状。Search API 返回带有 `url`、可选 `title`、可选 `publish_date` 和 `excerpts` 数组的排名 `results`。它不返回旧提供者的相关性分数、生成答案、图像字段、响应时间或完整页面正文。

保留字段语义，而不仅仅是字段名称。仅日期的 `publish_date` 不会恢复旧时间戳的时精度，`search_id` 不是会话标识符，SKU 使用计数不是提供者信用或美元成本。仅在应用程序合同定义转换时规范化；否则，使合同更改显式。

显式路由非搜索行为：

- 直接使用 Search API 的 excerpts 作为 LLM 上下文或简洁的证据。
- 使用 Extract API 从已知结果 URL 获取完整内容，重用 Search API 的 `session_id`。
- 使用 Chat API 或应用程序现有的模型获取有根据的答案。
- 使用 Task API 进行异步多步研究或结构化合成。
- 使用 Entity Search 进行同步的人或公司发现。

对于 Firecrawl，在选择路由之前对产品进行分类。Search 通常映射到 Search；公共 URL 的 markdown 或完整内容可能映射到 Extract；结构化多页研究仅在 Task 保留所需的源范围、支出政策、质量选择和生命周期时映射到 Task。确切的已知 URL 结构化提取优先考虑 Extract 加上应用程序拥有的模型/解析器。Research Index、Crawl、Map、Parse 上传、Browser、Interact、Monitor、截图和其他丰富抓取行为不是 Search 字段映射。遵循 [references/firecrawl.md](references/firecrawl.md) 并保留分离的功能，直到批准明确的替代方案。

不要用看起来合理的常量填充缺失的字段。删除过时的消费者，重新设计应用程序合同，或使用适当的 Parallel API。

## 5. 替换依赖项和配置

- 仅添加所选路由所需的 SDK：`parallel-web` 用于 Search、Extract 或 Task；`openai` 用于 Chat，除非应用程序已经有一个兼容的客户端；直接 REST 是更简单的现有模式时，不需要 SDK。
- 仅当没有 `retain` 行仍然依赖于它时，才删除遗留提供者包，然后使用存储库的包管理器重新生成锁文件。
- 仅在 `migrate` 行内替换提供者导入、客户端初始化、端点和标头。保留共享提供者设置，直到保留的调用有自己的显式边界。
- 将 `PARALLEL_API_KEY` 添加到签入的环境模板、验证模式、设置脚本、部署清单、示例和文档。仅在保留的运行时功能不再需要它时，才从这些表面中删除遗留密钥。
- 在 Parallel SDK 支持的情况下保留现有的超时、重试、取消和日志记录行为；否则在应用程序边界实现行为并测试它。
- 除非提供者名称有助于操作员采取行动，否则保持提供者中立的错误消息。

永远不要在日志、报告、补丁或固定中暴露或重写真实的秘密值。

## 6. 验证行为，而不仅仅是语法

添加或更新测试以验证：

- 请求构建，包括 `search_queries`、模式、过滤器、日期和位置；
- 源策略规范化：顶级域名、子域名、方案、路径、通配符、冲突列表和提供者特定限制；
- 查询设计行为：静态请求、直接单查询兼容路径和模型工具模式；
- 省略的遗留默认值、双重域列表和任何批准的语义更改；
- 目标限制验证：动态查询和域列表；
- 响应解析和 excerpt 连接；
- 空结果、缺失可选的标题/日期、警告和错误；
- 任何保留应用程序拥有合同的正常化器；
- 使用完整内容、合成或实体路由时；
- 移除分数阈值或提供者特定字段。

保留存储库的测试执行合同。如果其聚焦测试以前模拟了提供者包并在不安装该 SDK 的情况下运行，则模拟替换 SDK 或将导入保留在注入的边界后面。在等效的干净环境中重新运行确切的迁移前测试命令；依赖于环境包的通过不是存储库仍然自包含的证据。

然后按顺序运行：

1. 狭义的迁移测试；
2. 存储库的格式化器、类型检查器、lint、构建和更广泛的测试（如适用）；
3. `python3 <skill-root>/scripts/scan_provider_usage.py . --provider <legacy-provider> --fail-on-legacy`，当该提供者被完全移除时；
4. 当批准的非搜索 Perplexity 或 Firecrawl 使用仍然存在时，运行提供者扫描而不带 `--fail-on-legacy`，分类每个发现，然后仅扫描迁移的根或使用狭义的 `--exclude` 路径为隔离的保留模块；永远不要排除混合搜索/非搜索边界；
5. 当明确授权且凭证可用时，运行大小写不敏感的 `exa`、`tavily`、`perplexity`、`sonar-`、`firecrawl`、确切的 `model` 分配到 `sonar`、路由的 `perplexity/sonar` 模型 ID、包名、端点和密钥名，排除 `<skill-root>` 如果技能安装在目标存储库中；
6. 审查最终差异，以查找未预期的行为更改、泄漏的值、无关的编辑和过时的锁文件；
7. 仅当提供者调用明确授权此任务且 `PARALLEL_API_KEY` 已经可用时，进行实时冒烟测试，而不打印它。

环境凭证本身并不授权付费网络调用。当授权时，使用一个小型、非敏感的合成查询并检查 `warnings`、结果排序、excerpts 和错误行为。仅在用户批准将它们发送到两个提供者或现有的存储库测试政策已经允许该确切比较时，才比较代表生产查询。不要要求用户粘贴秘密。

## 完成门

仅当所有适用语句都为真时完成：

- 没有遗留提供者运行时依赖项、导入、端点、认证标头、密钥引用、工具定义、固定或过时的设置指令保留在迁移边界内。
- 该边界外的任何 Perplexity 模型路由、嵌入、沙盒、MCP 或自定义函数功能保持完整或作为明确的障碍被指出。
- 任何迁移的 `finance_search` 路径通过评估的 Parallel 路由保留消耗的最终答案或 `finance_results` 合同，并在需要时通过应用程序拥有的正常化器；未保留的硬覆盖或新鲜度要求是明确的障碍。
- 该边界外的任何 Firecrawl 爬取、映射、文件解析、浏览器、交互、丰富格式、变更跟踪、安全/隐私、MCP 或异步工作功能保持完整或作为明确的障碍被指出。
- 每个清点的调用都有一个记录的 `migrate`、`retain` 或 `block` 决策，并且没有 `block` 行被编辑为似乎已解决差距。
- Firecrawl 精确 URL 限制、每次运行信用上限、`spark-1-*` 模型选择和同步/异步行为保留或仅经明确批准更改；域允许列表、省略的预算或猜测的任务处理器不满足此门。
- 每个使用的请求特性和响应字段都有一个实现的 Parallel 路径或明确批准的行为更改。
- 查询构建保留研究目标，使用关键字形状的检索探测，并遵循适用的直接调用或模型工具合同。
- 源策略迁移保留预期的 URL 范围；不支持的路径或通配符行为显式实现或记录为批准的差距。
- 测试和静态检查通过，或识别出无关的预存在失败证据。
- 当提供者被完全移除时，提供者特定的遗留扫描通过。否则，每个剩余发现都属于批准的隔离非搜索边界，并且每个识别的响应都已通过其下游消费者跟踪。
- 当它被明确授权且凭证可用时，实时调用通过；否则，明确说明缺少实时验证。
- 最终报告命名迁移边界、重要的语义选择、验证命令和任何外部秘密清理仍留给操作员的操作。
