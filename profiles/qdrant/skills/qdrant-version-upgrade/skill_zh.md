# Qdrant 版本升级

Qdrant 对版本兼容性有以下保证：

- Qdrant 和 SDK 的大版本和小版本应保持一致。例如，Qdrant 1.17.x 与 SDK 1.17.x 兼容。

- Qdrant 会测试小版本之间的向后兼容性。例如，Qdrant 1.17.x 应与 SDK 1.16.x 兼容。Qdrant 服务器 1.16.x 也预期与 SDK 1.17.x 兼容，但仅限于 1.16.x 中可用的功能子集。

- 要迁移到下一个小版本，建议首先将 SDK 升级到下一个小版本，然后再升级 Qdrant 服务器。

- 存储兼容性仅保证一个小版本。例如，使用 Qdrant 1.16.x 存储的数据预期与 Qdrant 1.17.x 兼容。如果您需要迁移超过一个小版本，必须逐步进行升级，每次一个小版本。例如，从 1.15.x 迁移到 1.17.x，需要先升级到 1.16.x，然后再升级到 1.17.x。注意：Qdrant Cloud 自动化此过程，因此您可以直接从 1.15.x 升级到 1.17.x，无需中间步骤。

- 具有复制因子为 2 或更高的 Qdrant 集群可以通过滚动升级在不中断服务的情况下进行升级。这意味着您可以逐个节点进行升级，同时其他节点继续处理请求。这允许您在升级过程中保持应用程序的可用性。更多关于复制因子的信息：[复制因子](https://skills.qdrant.tech/md/documentation/scaling/distributed_deployment/?s=replication-factor)

要在 Qdrant Cloud 中管理 Qdrant 版本升级，您可以使用 [qcloud](https://github.com/qdrant/qcloud-cli) 命令行工具。

## 升级前检查清单

1. 首先备份：建议在更新前进行备份或快照，以便回滚。如果升级失败或需要回滚，您可以恢复升级前的快照。Qdrant Cloud 在升级过程中应用数据迁移，因此没有实时降级。[快照](https://skills.qdrant.tech/md/documentation/snapshots/) [云备份](https://skills.qdrant.tech/md/documentation/cloud/backups/)

2. 检查 [发布说明](https://github.com/qdrant/qdrant/releases)，而不仅仅是废弃项。版本升级可能会引入对默认设置、验证规则或查询行为的更改，即使 API 保持兼容，这些更改也可能影响现有工作负载。

3. 在非生产环境中首先在目标服务器版本上测试您的客户端应用程序，并在切换之前检查 SDK 发布说明中已弃用/删除的方法。

4. 建议每个节点至少运行 2 个 CPU 核心。在升级期间，Qdrant 可能会在处理常规操作的同时执行后台优化。如果只有 1 个核心，这些任务会竞争 CPU 资源，并可能显著减慢升级过程。

5. 如果您需要零停机时间的滚动升级，建议使用复制因子为 2 或更高。如果复制因子为 1，升级需要停机窗口。

## 跨越多个小版本

使用场景：运行版本比目标版本落后两个或更多小版本。

- 自托管：逐步通过每个中间小版本，并在继续之前停留在每个版本的最新补丁上。从 1.15 到 1.17，首先进入最新的 1.16.x，然后是 1.17.x。 [升级 Qdrant](https://skills.qdrant.tech/md/documentation/upgrades/)
- 每个步骤都是独立的滚动重启，因此总时间是单版本升级的倍数。这比单版本升级耗时更长，因此需要计划并选择非高峰时段。
- Qdrant Cloud 为您串联中间更新，因此 1.15.x 到 1.17.x 是一个单独的操作。 [更新 Qdrant Cloud 集群](https://skills.qdrant.tech/md/documentation/cloud/cluster-upgrades/)
- 定期升级以保持未来跳转到一个小版本的连续性。定期升级还可以通过避免大版本跳跃来减少未来迁移的复杂性。

## 升级后行为更改的故障排除

使用场景：新版本上线后，结果、分数或延迟看起来不同。

- 在升级后调查错误或意外行为时，检查源版本和目标版本之间的 [发布说明/变更日志](https://github.com/qdrant/qdrant/releases) 以查找可能影响您工作负载的弃用项、默认值更改和行为更改。

- 将相对排名和召回率与升级前的基线进行比较，而不是绝对分数值。分数内部可能在版本之间发生变化，但仍然可能是正确的。

## 不应做的事情

- 将相同的绝对分数视为跨版本的接受标准
- 只阅读目标版本的说明并跳过中间的小版本和补丁版本
- 在自托管部署中一次性跳跃多个小版本
- 假设滚动升级完成，而未确认每个节点都报告了目标版本
