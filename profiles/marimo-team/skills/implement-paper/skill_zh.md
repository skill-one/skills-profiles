# 实现论文

将研究论文转化为交互式 Marimo 笔记本。关于通用 Marimo 笔记本规范（单元格结构、PEP 723 元数据、输出渲染、`marimo check`、变量命名等），请参考 `marimo-notebook` 技能。

## 第 1 步：了解用户需求

在获取或读取任何内容之前，先进行简短对话来界定工作范围。向用户询问：

- **您对论文的哪个部分最感兴趣？** 一篇论文可能有多个贡献——用户可能只关心一到两个。不要实现整个论文。
- **目标是什么？** 他们是想理解方法、复现结果、将其应用于自己的数据，还是教给别人？这会改变笔记本的语气和深度。
- **他们想使用特定的数据集吗？** 如果相关，请询问。否则，建议模拟数据。
- **这需要使用 PyTorch 吗？** 有些论文需要，很多论文不需要。如果不确定，请询问——这是一个重量级依赖项。
- **他们的背景是什么？** 论文旨在填补知识空白——评估用户已经了解什么，以便笔记本能恰到好处地满足他们的需求。跳过他们熟悉的基础知识，解释他们不了解的先决条件。

只有当你对要构建的内容有清晰的认识后，才能继续进行。

## 第 2 步：获取论文

如果用户给你 Arxiv/AlphaXiv 链接，你会以高效的方式阅读论文。

参见 [references/fetching-papers.md](references/fetching-papers.md) 了解如何通过 alphaxiv.org 获取论文内容。这避免了读取原始 PDF，并为你提供了结构化的 Markdown。

## 第 3 步：规划笔记本

在编写代码之前，阅读论文后为用户勾勒出笔记本结构。

**尽可能使笔记本保持小巧。** 有时用单个交互式小部件就能最好地传达想法——如果你需要自定义小部件，请考虑 `anywidget` 技能。有时你需要一个完整的训练循环——如果是这样，请考虑使用 `marimo-batch` 技能为重计算提供支持。目标是传达想法所需的最少代码量。

典型结构：

| 部分 | 目的 | 典型元素 |
|------|------|----------|
| 标题和背景 | 引导读者 | `mo.md()` 包含论文标题、作者、链接 |
| 背景 | 设置先决条件 | Markdown + 方程式 |
| 方法 | 核心算法逐步讲解 | 代码 + Markdown 交错 |
| 实验 | 复现关键结果 | 交互式小部件 + 图表 |
| 结论 | 总结要点 | `mo.md()` |

并非每个笔记本都需要所有部分。在编写代码前与用户分享大纲并进行调整。

## 第 4 步：构建笔记本

遵循 `marimo-notebook` 技能规范创建 Marimo 笔记本。

关键指南：

- **永远不要假设数据集。** 使用用户在第 1 步中指定的数据集。如果他们没有指定，请模拟数据。
- **使其自包含。** 读者应该在不阅读整篇论文的情况下理解笔记本。
- **使用 KaTeX 渲染方程式。** 使用 `mo.md(r"""$...$""")` 渲染关键方程式，以便笔记本与论文的符号一致。保持符号与论文一致。
- **在有助于理解的地方添加交互性。** 超参数的滑块、数据集变体的下拉菜单或消融的切换按钮有助于读者建立直观理解。
- **展示而非仅描述。** 优先选择图表或表格而不是解释性段落。
- **尽可能使变量名与论文的符号一致**（例如，`alpha`、`X`、`W`），并添加注释将它们映射到方程编号。

## 小贴士

- **不要复现整篇论文。** 专注于用户在第 1 步中询问的内容。
- **可视化迭代。** 逐步构建图表（例如，显示数据 → 显示模型拟合 → 显示残差），而不是将所有内容一次性放入一个图表中。
- **如果论文使用复杂的符号**，请包含一个小的“符号参考”单元格，其中包含一个将符号映射到描述的 Markdown 表格。

如果用户需要自定义 anywidget，请参考 [references/anywidget.md](references/anywidget.md)。
