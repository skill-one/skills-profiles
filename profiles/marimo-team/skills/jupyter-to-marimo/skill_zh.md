# 将 Jupyter 笔记本转换为 Marimo

## 首先进行转换

**重要提示：** 在阅读源笔记本之前运行转换器：

```bash
uvx marimo convert <notebook.ipynb> -o <notebook.py>
```

只有在转换失败或生成的文件遗漏必要信息时，才读取 `.ipynb` 文件。将生成的文件视为初稿。

转换后以及进行重大修改后，运行此命令：

```bash
uvx marimo check <notebook.py>
```

## 审查转换结果

- 在 PEP 723 元数据中验证所有必需的包。转换器可能会遗漏某些包安装形式。
- 删除残留的安装单元格和过时的安装说明。仅在需要时添加版本约束。
- 当笔记本使用 PEP 723 元数据时，使用 `--sandbox`。
- 保留源笔记本的目的和预期工作流程。
- 为演示目的排列单元格。marimo 根据变量定义和引用确定执行顺序。
- 单元格可以出现在定义其输入的单元格之前。
- 根据当前边界是否清晰，合并或拆分单元格。
- 删除冗余的 Jupyter 产物，例如不必要的 `display()` 调用。
- 审查转换后的魔法命令。保留有效的转换，并解决报告不支持的魔法的注释。
- 将要渲染的值放在每个单元格的最终表达式中。
- 根据笔记本目的，保持添加的 UI 和辅助函数的比例。
- 替换需要等待终端输入或在目标界面中无法工作的交互式输入方法。使用合适的 UI 控件、脚本参数或环境值。
- 不要打印、记录或保存秘密。考虑使用 [EnvConfig](https://koaning.github.io/wigglystuff/reference/env-config.md) 处理多个环境值。
- 识别昂贵的操作和外部副作用。如果操作必须等待，使用 `mo.stop()` 和合适的 UI 元素进行控制。
- 如果用户必须一起提交多个值，使用表单。
- 在门控之后定义下游值，以便依赖图延迟依赖单元格。
- 使用简单的原生组件展示有用结果。仅在预期工作流程需要时才添加实时刷新。
- 对于 ipywidgets，请阅读 [`references/widgets.md`](references/widgets.md)。
- 对于 LaTeX 和 MathJax，请阅读 [`references/latex.md`](references/latex.md)。

## 验证结果

- **所有修改后再次运行 `marimo check`**。
- 在每个预期模式下运行笔记本。确认其行为符合预期。
- 在实际情况下，将源笔记本和转换后的笔记本并排打开，并邀请用户进行审查。
- 比较内容、控件、输出和工作流程。单元格顺序和布局可能不同。
- 检查更改后的文件，查找秘密、生成数据、缓存、日志和其他运行时文件。
