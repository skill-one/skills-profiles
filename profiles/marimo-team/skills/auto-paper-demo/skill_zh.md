# 通过AlphaXiv获取论文

使用alphaxiv.org获取结构化、适合大型语言模型的论文内容。这比尝试阅读原始PDF更快、更可靠。

## 提取论文ID

从用户提供的任何信息中解析论文ID：

| 输入 | 论文ID |
|------|--------|
| `https://arxiv.org/abs/2401.12345` | `2401.12345` |
| `https://arxiv.org/pdf/2401.12345` | `2401.12345` |
| `https://alphaxiv.org/overview/2401.12345` | `2401.12345` |
| `2401.12345v2` | `2401.12345v2` |
| `2401.12345` | `2401.12345` |

## 获取AI生成的概述（首先尝试此方法）

```bash
curl -s "https://alphaxiv.org/overview/{PAPER_ID}.md"
```

返回论文的结构化、详细分析，以纯Markdown格式呈现。一次调用，无需JSON解析。

## 获取完整论文文本（备用方案）

如果概述中不包含您需要的特定细节（例如，某个特定公式、表格或证明）：

```bash
curl -s "https://alphaxiv.org/abs/{PAPER_ID}.md"
```

返回论文的完整提取文本，以Markdown格式呈现。

## 错误处理

- **概述404错误**：该论文的报道尚未生成。尝试获取完整文本。
- **完整文本404错误**：文本尚未被处理。作为最后的手段，请将用户引导至 `https://arxiv.org/pdf/{PAPER_ID}` 的PDF。
- 无需身份验证——这些是公开端点。

## 好的实现方案是什么？

好的实现方案讲述一个故事，这是最重要的。故事应该简单，但不能缺失。

论文通常包含多个概念。这意味着你需要选择一个故事！目标不是完全实现论文或重新运行大型基准测试。目标是提取一个教训/想法，并在一个可以在CPU上简单运行的笔记本中清晰地解释它。这样，用户可以轻松地从中学习。当你查看笔记本时，你认为值得探索的主要概念或想法是什么？哪个概念讲述了一个故事？

选择最容易用最小代码示例解释的想法。对于最小代码示例真正有效，通常有助于有一个，或许两个图表来查看。也许有一个下拉菜单允许你尝试不同的设置。甚至可能有一个滑块。但我们要做的是防止用户需要大量滚动。

通常情况下，你希望比较两种方法。但请花点时间思考示例，因为这最关系到故事。大多数时候，你不想使用玩具示例。它们不具信息量且过于泛滥。或许最好生成一个创意示例，展示某种方法如何真正脱颖而出。我们不想做有选择性的例子，但也不要做那些过于泛滥的例子。

我必须强调，在编写任何代码之前，认真思考故事和示例是多么重要。你应该真正深入思考。给用户一些交互，但尽量防止滚动。一个好的例子讲述故事，而不仅仅是陈述一些事实。

请自由思考这个决定，但一旦你明确了最佳展示想法是什么，立即开始构建marimo笔记本。

使用marimo-notebook技能来完成，可能还需要anywidget技能，但只有当自定义小部件能让故事更好时才使用。如果你强烈认为使用自定义anywidget是合理的，请参考 [references/ANYWIDGET.md](references/ANYWIDGET.md)。

当你准备好时，确保隐藏所有代码，并将包含输入/输出的单元格移到文件顶部。

示例：

```
@app.cell
def _(hide_code=True):
    import marimo as mo
    return mo
```
