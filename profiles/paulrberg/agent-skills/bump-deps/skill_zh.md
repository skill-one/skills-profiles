# 更新依赖项

使用 Taze 构建一个结构化的更新计划，应用兼容的范围内更新，并批量做出主版本决策。

## 工作流程

1. 解析技能目录并从目标存储库保存辅助计划：

   ```sh
   bash <skill-dir>/scripts/run-taze.sh --plan [--include package-a,package-b] > <taze-plan.json>
   ```

   JSON 计划将每个发现的更新分类为 `apply`、`review-major`、`review` 或 `skip-fixed`。辅助工具检测单一代码库，扫描时包含锁定版本，并镜像 Bun 最小发布年龄设置。如果存储库使用包管理器年龄门禁或 Bun 目录，请仅针对该活动分支阅读
   [references/conditional-workflows.md](references/conditional-workflows.md)。

2. 如果请求了 `--dry-run`，则显示计划及其计数，然后停止而不更改清单文件或锁定文件。

3. 选择所有标记为 `apply` 的范围内次要/补丁更新。切勿通过名称自动批准主版本包。将所有 `review-major` 和未知更新在一个决策批次中呈现，包括当前版本、目标版本、在可发现的情况下显示包角色以及相关的迁移/发布说明。仅应用用户选择的主版本。

4. 如果未选择任何内容，则报告无操作并停止。如果根清单文件使用 Bun 目录，则从接受的计划中预览精确选择的目录转换：

   ```sh
   uv run <skill-dir>/scripts/update-bun-catalogs.py \
     --root <repo> --plan <taze-plan.json> --include package-a,package-b
   ```

   预览是只读的。缺少目录条目、冲突的计划行、不支持的版本或目录值不再与计划匹配，则会在写入之前失败。辅助工具不会选择升级。

5. 在第一个清单文件或锁定文件写入之前，发现并运行存储库的标准验证套件，针对现有的依赖状态。优先使用其宣传的聚合检查；否则运行每个暴露的依赖解析、构建、测试、类型检查、代码格式化检查、代码生成检查和存储库不变量命令。在可用的情况下使用冻结或非写入模式，并记录用于后更新重跑的确切命令。命令失败、依赖或同伴解析冲突以及发出不兼容或危险行为信号的可操作警告会阻止更新；不包含不可避免弃用的信息性通知。如果基线有任何阻止问题，则停止并显示 `### ⛔ 依赖更新被阻止 — 基线失败`，显示确切命令和诊断，并要求用户解决预存在的问题。不要修改清单文件、锁定文件、源代码或配置。

6. 使用一个命令写入所有选择的 Taze 更新：

   ```sh
   bash <skill-dir>/scripts/run-taze.sh --write --include package-a,package-b
   ```

7. 对于 Bun 目录，使用相同的计划和包含集加上 `--write` 重新运行 `update-bun-catalogs.py`。它原子性地更新每个匹配的默认/命名目录出现，并保留每个现有的 `^`、`~` 或空前缀。然后运行 `ni`，以便存储库的包管理器更新其锁定文件。

8. 检查清单文件和锁定文件差异。重新运行确切的基本线命令，以及最窄的检查，以执行更新的依赖项和任何必需的迁移。将每个新引入的错误、类型问题、检查失败（包括测试、构建、代码格式化、代码生成和存储库不变量）、依赖或同伴解析冲突以及可操作的兼容性或安全警告视为由更新引起，除非证据表明否则。

9. 修复由更新引起的所有问题，包括必需的源代码或配置迁移，同时保留预期行为。不要仅仅为了使检查通过而抑制诊断、削弱验证或更改预期行为。每次修复后，重新运行受影响的检查，然后重新运行完整记录的套件，直到通过。如果任务权限范围内没有明确的安全修复，则停止并显示 `### ⚠️ 依赖回归决策需要`。在一个表格中呈现所有此类问题，包括证据、受影响位置、修复和还原选项以及可能的影响。不要报告完成，直到用户选择、应用修复或还原有问题的更新、重新生成锁定文件并且完整套件通过。

## 用户界面输出

将计划显示为 `### 📦 依赖计划`，包含计数和紧凑表格：

| ID  | 计划值 | 决策 | 包 | 当前 → 目标 | 类型 | 备注 |
| --- | ------ | ---- | -- | ------------ | ---- | ---- |

使用计划的 `apply`、`review-major`、`review` 和 `skip-fixed` 的确切值以及平决策策。为需要选择的行分配稳定 ID，以便用户一次性回答。使用 `### 🔎 干跑 — 未写入文件` 进行预览，使用 `### ✅ 未选择更新` 进行无操作。

完成应用工作后，显示 `### 🏁 依赖更新`、已更改的清单文件/锁定文件树和 `### 🧪 验证`。仅当非阻止性信息性事项时使用 `### ⚠️ 剩余待审`，绝不用于由更新引起的问题。保持辅助 JSON、包/版本字符串、命令和诊断精确且未装饰。

## 不变量

- 固定版本和非 SemVer 协议除非用户明确要求否则保持不变。
- 包参数约束扫描和写入阶段。
- 扫描和写入使用相同的成熟期策略。
- Bun 目录预览和写入使用相同的接受的 Taze 计划和选择的包集；过时的计划永远不会写入。
- 不要仅凭 SemVer 推断兼容性，当存储库证据、同伴范围或发布说明表明否则。

完成需要一个干净的预写基线、一个已审查的计划、保留的选择更新、重新生成的锁定文件、记录套件和依赖特定检查的通过重跑，以及没有由更新引起的未解决问题。干跑完成需要结构化计划和零写入。
