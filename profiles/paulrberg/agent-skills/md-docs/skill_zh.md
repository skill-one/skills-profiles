# Markdown 文档管理

## 概述

管理 Claude 代码工作流的项目的文档，包括 README.md 和代理上下文文件（AGENTS.md / CLAUDE.md）。此技能强制执行严格的受众划分：**README.md 供人类阅读**，**AGENTS.md 供代理和运行命令的开发者使用**。在初始化新项目、更新现有文档或确保上下文文件准确反映当前代码时使用此技能。

默认情况下，该技能在整个存储库中**递归**运行，而不仅仅是根目录。`update-*` 工作流查找并刷新树中的每个现有的 README.md / AGENTS.md；`init-*` 工作流在存储库根目录和每个缺少文件的包根目录（包含清单或工作区成员的目录）创建文件。每个文件都限定于其自己的目录子树和最近的包含清单。传递 `--root-only` 可将任何工作流限制为存储库根目录，或传递 `path` 参数可将扫描范围限制为一个子树。

该技能强调验证和确认胜过盲目生成——在创建或更新文档之前，分析实际代码库结构、文件内容和模式。所有生成的内容应简洁、祈使式、专家对专家，而不是冗长或教程式。

## 受众划分

这是此技能生成内容的中心规则。

| 文件                                  | 受众                                     | 包含                                                                                                                                                                    | 排除                                                                                                             |
| ------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `README.md`                           | 浏览存储库的人类（GitHub、npm 等平台） | 描述、徽章、指向文档/网站/演示的链接、引用、论文、相关工作、致谢、许可证、贡献指南                                              | 任何 CLI 命令、`just` 菜单、包脚本、构建/测试/校验工作流、项目结构树、API 参考 |
| `AGENTS.md`（以及 `CLAUDE.md` 符号链接） | AI 代理和在存储库中工作的开发者            | 技术、命令（安装、开发、构建、测试、校验）、`just` 菜单、`package.json` 脚本、`Makefile` 目标、代码风格、架构、约定、贡献工作流 | 营销文案、徽章、与开发无关的外部链接                                                              |

不确定时，请询问：*在 GitHub 上阅读的人类会关心这个吗，还是只有运行命令的开发者/代理会关心？* 如果是后者，则将其放入 AGENTS.md。

**例外——操作员运行设置指南**。划分是默认的，不是绝对的。当人类读者也是必须运行步骤的操作员时，README 可能包含简短的技术指南——典型情况：dotfiles 存储库（例如，一个 chezmoi 源树，其 README 记录新机器引导），家庭实验室或基础设施配置，个人工具——或者当用户明确要求时。保持指南简短、任务导向（设置、引导、恢复）；开发工作流命令（构建、测试、校验）仍然属于 AGENTS.md。在更新时，保留现有的例外指南，而不是删除它。

## 工作流选择

选择与用户意图匹配的工作流：

| 触发                                                                 | 工作流             | 参考                     |
| --------------------------------------------------------------------- | -------------------- | ----------------------------- |
| "更新 README" / "刷新 README"（文件已存在）                          | 更新 README        | `references/update-readme.md` |
| "初始化 README" / "创建 README" / "新的 README"（文件不存在或 `--force`） | 初始化 README    | `references/init-readme.md`   |
| "更新 CLAUDE.md" / "更新 AGENTS.md" / "更新上下文文件"                | 更新上下文文件      | `references/update-agents.md` |
| "初始化 AGENTS.md" / "创建 CLAUDE.md" / "初始化上下文"                | 初始化上下文   | `references/init-agents.md`   |

选择规则：

- 如果目标文件已存在，并且用户说“更新” / “刷新” / “修复”，则路由到 `update-*` 工作流。
- 如果目标文件不存在或用户说“创建” / “初始化” / “新的”，则路由到 `init-*` 工作流。
- 对于模糊请求，首先枚举目标文件（见递归发现），并确认用户的意图。
- 如果用户不带任何参数调用此技能，则默认列出树中存在的文件并建议工作流，而不是猜测。
- 一个请求中包含多个工作流（例如“更新 README 和 AGENTS.md”）是允许的——按用户列出的顺序依次运行它们，并独立报告每个结果。
- 每个选定的工作流适用于发现步骤找到的每个目标文件，除非 `--root-only` 或缩窄的 `path` 参数限制了扫描范围。

## CONTRIBUTING.md 策略

此技能**不**维护 `CONTRIBUTING.md`。如果工作流检测到任何目标文件（存储库根目录或任何包根目录）旁边存在 `CONTRIBUTING.md`：

1. 不要阻止其他写入；为该目录显示建议。
2. 建议用户将其内容合并到兄弟 `AGENTS.md`（因为 AGENTS.md 现在拥有开发工作流、分支约定、审查流程和工具参考）。
3. 建议合并后删除 `CONTRIBUTING.md`，以便代理上下文文件是唯一的真实来源。
4. 不要自动合并或自动删除；用户执行合并。

按每个目录的标准摘要格式报告建议，并继续用户请求的 README/AGENTS 工作流，忽略 `CONTRIBUTING.md` 文件本身。

## 前提条件

在使用任何文档工作流之前，请验证基本的项目结构：

```bash
git rev-parse --git-dir
```

确保输出确认您位于 git 存储库中。如果未初始化，文档工作流仍可继续，但 git 特定功能将被跳过。

一次解析存储库根目录；所有发现都是相对于它的（如果提供了 `path` 参数，则相对于该参数）：

```bash
git rev-parse --show-toplevel
```

然后在进行任何工作流之前枚举目标文件（见递归发现）。如果 `CONTRIBUTING.md` 与目标文件相邻，则应用上面针对该目录的策略。

## 递归发现

默认情况下，工作流作用于树中的每个相关文件。`--root-only` 将此操作缩减为存储库根目录；`path` 参数将其限制为一个子树。

**排除（始终）。** 在发现和创建过程中跳过这些内容：

- VCS 和依赖/构建输出目录：`.git`、`node_modules`、`vendor`、`.venv`、`target`、`dist`、`build`、`out`、`.next`、`coverage`。
- 任何 git 忽略的内容（依赖 `--exclude-standard` / `git check-ignore`）。
- 隐藏点目录（`.github`、`.vscode`、`.claude`、…）——**除非**该目录包含清单。

**`update-*` 发现**——查找现有文件以刷新：

```bash
# README.md / AGENTS.md 跟踪或未跟踪，尊重 .gitignore
git ls-files --cached --others --exclude-standard -- '**/README.md' 'README.md' '**/AGENTS.md' 'AGENTS.md'
```

丢弃排除目录下的任何路径。`CLAUDE.md` 是指向其兄弟 `AGENTS.md` 的符号链接，并且永远不会单独处理。

**`init-*` 发现**——查找应获得新文件的包根目录：

```bash
# 包含语言/工具清单的目录 = 包根目录
git ls-files --cached --others --exclude-standard \
  -- '**/package.json' 'package.json' '**/Cargo.toml' 'Cargo.toml' \
     '**/pyproject.toml' 'pyproject.toml' '**/setup.py' 'setup.py' \
     '**/go.mod' 'go.mod' '**/foundry.toml' 'foundry.toml' \
     '**/Gemfile' 'Gemfile' '**/composer.json' 'composer.json'
```

包根目录集是存储库根目录加上这些清单的唯一目录（减去排除项）。`init-*` 仅在缺少目标文件的包根目录中创建目标文件；它不会在任意叶目录中创建文件。

**按文件限定**。独立处理每个目标：

- 元数据源是最近的包含清单（在其自己的目录中，否则向上走到存储库根目录）。
- 嵌套的 `README.md` 链接到其**兄弟** `AGENTS.md`，而不是根目录的。
- 每个 `AGENTS.md` 都在同一目录中获取一个兄弟 `CLAUDE.md` 符号链接（从该目录运行 `ln -sf AGENTS.md CLAUDE.md`）。
- `CONTRIBUTING.md` 按目录检查，并合并到兄弟 `AGENTS.md`。

始终以最深或最浅的顺序处理文件，并按路径分组报告结果。

## 常见参数

这些标志在所有工作流中始终以一致的方式解释。每个参考都详细描述了它们在每个工作流中的效果；见 `references/common-patterns.md` 以获取共享解析约定。

- `path`（位置参数）：将递归扫描限制于此目录子树，而不是整个存储库。与任何工作流结合使用。
- `--root-only`：禁用递归；仅作用于存储库根目录（递归前的行为）。始终支持。
- `--dry-run`：预览将要应用但不会写入文件的变化。始终支持。
- `--preserve`：保留现有用户编写的内容；仅修复可验证的不准确之处。由 `update-*` 工作流使用。
- `--minimal`：生成或验证最小的有用输出（仅顶级结构）。
- `--thorough`（别名 `--full`）：执行深度分析或生成全面内容。最慢模式。
- `--force`：覆盖安全检查（例如，在提示后覆盖现有目标）。由 `init-*` 工作流使用。适用于扫描范围内的每个文件。

如果用户传递了其他标志，则回退到默认模式，并在最终报告中显示一条关于未识别标志的单行通知。

## 写作风格

所有生成的文档都应遵循这些约定，而不管工作流如何：

- **简洁**：省略不必要的词语。直接以答案或链接开头。
- **祈使式**（AGENTS.md）：使用命令形式（“构建项目”）而不是描述性形式（“项目被构建”）。
- **平铺直叙**（README.md）：简短、直接的描述；避免祈使式讲座——受众是在浏览，而不是执行。
- **专家对专家**：跳过基本解释；假设读者具备能力。
- **可扫描**：使用标题、列表和代码块。读者应在 30 秒内找到他们需要的内容。
- **准确**：在写入之前，验证每个命令、链接和路径是否与实际代码库一致。

避免教程式散文、冗余上下文和填充内容，例如“为了…”。不确定时，写得越少越好。见 `references/common-patterns.md` 以获取良好与不良输出的示例。

## 安全默认值

跨所有工作流应用的行为：

- 从不自动提交。工作流仅修改文档文件；用户手动运行 `git add` / `git commit`。依赖 git 进行恢复——不要创建 `*.backup` 文件。
- 对于 `init-*` 工作流：除非设置 `--force` 或用户通过 `AskUserQuestion` 确认，否则拒绝覆盖现有目标。当扫描触及许多文件时，对批次进行一次确认，而不是逐文件提示。
- 默认递归，但保持在存储库内（`git rev-parse --show-toplevel`）；尊重递归发现中的排除项。使用 `--root-only` 或 `path` 参数缩小范围。永远不会写入发现的目標集之外的文件。
- 当扫描将创建或重写大量文件时，列出计划的目标并确认后再写入（将其视为隐式的 `--dry-run` 预览）。
- 如果任何目标旁边存在 `CONTRIBUTING.md`，则不要编辑它；为该目录显示合并到 AGENTS 的建议，并继续。

## 更新上下文文件

何时使用：用户要求更新 CLAUDE.md 或 AGENTS.md，以便它们与实际代码库匹配。触发短语包括“更新 CLAUDE.md”、“更新 AGENTS.md”、“更新上下文文件”、“修复上下文”、“刷新上下文”。

`CLAUDE.md` 是指向其兄弟 `AGENTS.md` 的符号链接，并且不会单独处理。

在树中的每个现有 `AGENTS.md` 上运行（见递归发现）；每个文件限定于其自己的目录和最近的清单。AGENTS.md 拥有：技术栈、所有 CLI 命令（安装、开发、构建、测试、校验、部署）、`just` 菜单、`package.json` 脚本、`Makefile` 目标、代码风格、架构、约定和贡献工作流。

输入：每个现有的 `AGENTS.md`（必需）、最近的包含清单、锁文件、脚本、`justfile`、`Makefile`。输出：重写的 `AGENTS.md` 文件，每个文件都有一个刷新的兄弟 `CLAUDE.md` 符号链接。

识别的标志：`path`、`--root-only`、`--dry-run`、`--preserve`、`--thorough`、`--minimal`。

见 [references/update-agents.md](references/update-agents.md)。

## 更新 README

何时使用：用户要求更新或刷新现有的 README.md。触发短语包括“更新 README”、“刷新 README”、“修复 README”、“重新生成 README”。

在树中的每个现有 `README.md` 上运行（见递归发现）。对于任何没有 `README.md` 的包根目录，将此目录路由到**初始化 README**（或者，使用 `--force`，允许 update-readme 在那里创建它）。

README 拥有：描述、徽章、指向主页、文档网站、演示、包注册中心的链接、引用、相关工作、致谢、许可证、贡献指南。它**不**包含 CLI 命令、`just` 菜单、脚本或项目结构树——这些内容位于兄弟 AGENTS.md 中，README 链接到它以获取它们。

输入：每个现有的 `README.md`；最近的包含清单用于名称/版本/描述/许可证/主页 URL；git 远程用于存储库 URL。输出：重写的 `README.md` 文件。

识别的标志：`path`、`--root-only`、`--dry-run`、`--preserve`、`--minimal`、`--thorough`（别名 `--full`）。

见 [references/update-readme.md](references/update-readme.md)。

## 初始化 README

何时使用：用户要求从零开始在缺少 README.md 的存储库（或包根目录）中创建文件。触发短语包括“初始化 README”、“创建 README”、“新的 README”、“生成 README”。

在每个缺少 README.md 的包根目录中创建 `README.md`（存储库根目录加上包含清单的目录；见递归发现）。除非使用 `--force` 或通过 `AskUserQuestion` 明确确认，否则拒绝覆盖现有的 `README.md`。支持两种操作模式：

- **自动推断**：完全从项目分析中推导出内容。
- **引导**：围绕用户提供的描述（例如，“一个用于解析日期且无依赖项的 TypeScript 库”）组织内容。引导描述适用于根文件；嵌套的包文件从其自己的清单中推断。

与更新 README 相同的受众规则：仅人类，不包含 CLI。

输入：每个包根目录的代码库分析（语言、框架、LICENSE、主页 URL、存储库中的引用或论文），可选的用户提供的描述。输出：在目标包根目录中创建新的 `README.md`。

识别的标志：`path`、`--root-only`、`--dry-run`、`--minimal`、`--full`、`--force`。

见 [references/init-readme.md](references/init-readme.md)。

## 初始化上下文

何时使用：用户要求从零开始在缺少上下文文档的存储库（或包根目录）中创建 AGENTS.md（和 CLAUDE.md 符号链接）。触发短语包括“初始化 AGENTS.md”、“创建 CLAUDE.md”、“初始化上下文”、“新的上下文文件”、“生成 AGENTS.md”。

在每个缺少 AGENTS.md 的包根目录中创建 `AGENTS.md`（见递归发现）。与初始化 README 类似，支持自动推断和引导模式（例如，“具有安全优先意识的 Foundry 智能合约项目”）。对于生成的每个文件，始终通过从该目录运行 `ln -sf AGENTS.md CLAUDE.md` 创建兄弟 `CLAUDE.md` 符号链接。

生成的每个 AGENTS.md 必须包含一个命令部分，该部分汇总了该包的开发者或代理将需要的每个 CLI 调用：安装、开发、构建、测试、校验、格式化、部署，以及其目录中发现的所有 `just` 菜单、npm/pnpm/yarn/bun 脚本和 Makefile 目标。

输入：每个包根目录的代码库分析（技术栈、脚本、`justfile`、`Makefile`、架构提示、最近的 `package.json`、`README.md`、语言特定清单），可选的用户提供的描述。输出：新的 `AGENTS.md` 文件，每个文件都有一个兄弟 `CLAUDE.md` 符号链接。

识别的标志：`path`、`--root-only`、`--dry-run`、`--minimal`、`--full`、`--force`。

见 [references/init-agents.md](references/init-agents.md)。

## 报告

每个工作流都以简短摘要结束。在所有工作流中使用这些约定：

- `✓` 用于成功操作：`✓ 更新了 AGENTS.md`，后跟缩进的项目符号点列出具体更改。
- `⊘` 用于跳过的可选文件。
- `⚠` 用于建议通知（例如 CONTRIBUTING.md 合并建议）。
- `✗` 用于失败：`✗ 失败写入 README.md`，附带一行原因。

将更改详情缩进在每个行下，以便用户可以扫描单个文件的差异而无需重新阅读标题。对于递归运行，按文件路径分组结果（使用相对于存储库根的路径作为子标题），并最终以一行总计结束（例如 `更新了 4 个文件，跳过了 1 个，1 条建议））。对于 `--dry-run`，在报告前添加“计划更改”标题，列出每个目标路径，并包括差异或建议内容预览，而不是确认。参考 `references/common-patterns.md` 以获取完整的报告模板。
