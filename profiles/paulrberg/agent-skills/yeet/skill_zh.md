# GitHub 贡献工作流

这项技能无需协调：其声明的任务可跳过 ai-coord 验证关卡。

根据仓库证据创建或更新 GitHub 贡献，使用匹配工作流的模板、幂等性规则以及 Paul 的写作风格。

## 前置条件

在每个工作流中使用第一个必需的只读 `gh` 命令进行身份验证验证。将 `<skill-dir>` 一次性解析为包含此 `SKILL.md` 的绝对目录。`yeet-context.sh` 辅助工具随此技能捆绑，而非目标仓库；调用它为 `<skill-dir>/scripts/yeet-context.sh`，且永不向目标仓库中搜索它。当工作流需要仓库、模板、讨论、标签或问题/PR 线索上下文时，优先使用辅助工具。

对于 YAML 问题表单，调用 `<skill-dir>/scripts/issue-form.py`。`inspect` 获取并规范化选定的实时表单；`render` 验证按字段 ID 键化的答案，并生成精确的 Markdown 正文及发布元数据。辅助工具永不选择模板、编写答案或标题、执行外部披露审查或发布外部内容。所有问题创建和更新工作流在解析或传递元数据前应用 `references/context.md > Issue Metadata Permissions`。渲染的模板元数据描述请求的值，而非查看者应用它们的权限。

对于拉取请求工作流，还需验证：

- 工作树是干净的或更改已提交
- 当前分支有提交在基础分支之前
- 远程跟踪已配置

使用 `cli-gh` 进行 GitHub 读取、工作流自动化或非创作和发布贡献的命令语法。

每个工作流参考仅链接其需要的共享上下文、写作或发布指南。当用户请求创建或更新时直接发布；不要添加确认关卡。失败写入后，在任何重试前运行链接的幂等性检查。

除非仓库或用户证据验证，否则永不检查外部模板断言。如果必需的断言或字段无法验证，请求缺失的事实，而非编造协议。代理状态装饰属于创作贡献之外；仅在用户内容或线索注册调用时，才向 PR、问题、讨论或评论添加表情符号。

## 完成

当请求的贡献以其最终创作状态存在于 GitHub 中且返回的 GitHub URL 已验证时完成。对于更新/评论，报告一次更改的工件。从读取回显中，而非命令的退出状态确定结果：创建可以在元数据突变失败前成功。

使用 `### 🚀 <工件> 已创建`、`### ✅ <工件> 已更新`、`### ✅ 评论已发布` 或 `### ✅ 评论已更新`，后跟一个包含仓库、编号和标题或操作的 Markdown 链接。仅在基本、草稿状态、审阅者、标签或更改字段重要时，才添加紧凑字段列表。对于验证的部分成功，报告创建或更新的工件，并识别省略或失败的元数据。仅当确认未完成时使用 `### ⛔ <工件> 未 <操作>`；如果读取回显不明确，将结果报告为未验证。包括具体错误、幂等性结果和下一步操作。保持 `gh` 输出、JSON、诊断、模板字段、URL 和创作贡献文本精确且无装饰。
