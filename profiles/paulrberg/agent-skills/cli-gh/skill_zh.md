# GitHub CLI

这项技能无需协调：其声明的任务可跳过ai-coord关卡。

## 路由

使用`yeet`来创建或更新拉取请求、问题、问题评论或讨论。`yeet`负责语义分析、仓库模板、Paul的写作风格、幂等性和直接发布。通过`repo-rename`路由仓库重命名，以便GitHub和本地连续性同步变化。

## 权限

- 无需确认即可读取和检查。
- 仅在用户明确请求该结果时，才执行可逆或常规的GitHub写入操作。
- 永不删除仓库、发布/资产、工作流运行/缓存、密钥/变量、密钥、代码空间、扩展或Gist。
- 标签删除是唯一的破坏性例外：显示目标仓库、确切标签、命令和问题/PR影响，然后在后续消息中要求批准`gh label delete ... --yes`。

## 工作流

1. 当当前工作目录(cwd)不明确时，明确解析仓库。让第一个所需只读命令验证身份；仅用于身份诊断运行`gh auth status`。

2. 使用已安装的`gh <命令> <子命令> --help`解析标志、JSON字段和命令行为；CLI的JSON字段名可能与API字段不同。优先使用`--json`配合`--jq`获取结构化输出。

3. 预览涉及仓库的广泛写入，包括确切目标、命令和问题/PR影响。已请求的常规写入无需再次批准。

## 值得注意的标志 (gh 2.98+)

- `gh pr checkout --worktree <路径>`和`gh issue develop --checkout --worktree <路径>`检查到关联的git工作树而不是切换当前分支。
- `gh search issues --search-type semantic|hybrid`按相关性排序：仅问题、单页、无`--sort`/`--order`、不在GitHub企业版服务器上。
- `gh config set api_host <网关> --host <主机>`将主机API流量通过网关路由；实验性且不构成安全边界。
- 在问题/PR创建、编辑和评论上传时使用`--attach '<文件>#<替代>'`上传图片或视频；将这些写入操作路由到`yeet`。

## 完成

当命令输出验证请求的GitHub数据或状态时完成。写入后获取结果资源。在部分或模糊失败时，检查是否已更改后再重试。报告验证的状态和URL或稳定标识符；在不完整时包含具体错误和下一步操作，并区分未知结果与确认失败。
