# 这个号码是谁的

电话号码是一个强大的识别器：获取成本高，难以更改，并且几乎在所有地方都用作账户恢复的锚点。它也是调查人员最容易出错的地方，因为所有人引用的元数据——运营商——经常是过时的，而且现在很大一部分号码属于软件而不是某个口袋里的SIM卡。不要给目标打电话或发短信；那是联系，不是研究。

## 第1步——授权范围

阅读 [../../ETHICS.md](../../ETHICS.md)。记下目标、目标、边界内的识别器、边界外的操作以及管辖权——在这里比在大多数技能中更重要，因为反向电话查询在许多地方是专门受监管的。现在决定是否授权进行消息应用联系人发现检查；它们是交互式的。

**完成时** 范围已记录，并且联系人发现决策已记录。

## 第2步——首先规范化为E.164

下游的所有内容都会在错误解析的号码上中断。E.164是`+`，国家区号，国内号码——没有空格、标点或中继前缀。

陷阱是国家中继前缀。一个英国号码写成`07700 900123`是`+447700900123`：开头的`0`被丢弃，而不是保留。意大利保留其陆地线路的开头零。猜测错误会使后续的每个查询都转移到不同的用户。

使用`libphonenumber`（Google的解析库，大多数语言都有绑定）而不是正则表达式。它知道每个国家的中继前缀、有效长度范围以及哪些前缀范围是可以分配的，因此它可以区分一个格式良好的号码和一个在该国家实际上是可能的号码。

从规范化形式中，读出**国家区号**（国家，而不是用户的地理位置）、**国内目的地代码**——区号或移动前缀，为陆地线路提供地理区域或为移动设备提供*最初分配*的运营商——以及**线路类型**：固定、移动、VoIP、免费、高级、共享成本或未知。线路类型是最相关的决策字段。

`phoneinfoga`包装了规范化、格式生成和查询扫描器：

```bash
phoneinfoga scan -n "+15551234567"
```

**完成时** E.164形式、国家、国内目的地代码和线路类型已记录。

## 第3步——运营商、VoIP以及为什么两者都在撒谎

对移动号码的HLR查询会到达用户的家庭注册并返回号码*当前*所在的网络，是否可以到达，并且通常是否在漫游。这是实时数据，并且是唯一值得重视的运营商答案。其他一切——前缀到运营商表、大多数免费查询网站——映射号码最初分配的块。**可携性破坏了这一点**。用户保留号码并更换网络；分配表仍然命名原始运营商。因此，“运营商：X”来自前缀查询意味着“这个块被分配给了X”，而不是“这个人X的客户”。每次都说明你的答案是由哪种查询产生的。

然后分类VoIP。对于欺诈、信任和安全以及sockpuppet工作，这是整个技能中最高信号发现的：一个号码解析到虚拟号码提供商而不是移动网络运营商是廉价的、一次性的、在许多司法管辖区无需身份验证即可获得，并且可能是同一方持有的数百个号码之一。指标是VoIP线路类型、分配的运营商托管号码而不是服务消费者，以及与任何其他位置证据无关的区域代码。解释和每个应用的披露矩阵：
[reference/line-types.md](reference/line-types.md)。一个VoIP结果是恶意行为的证据——大多数企业使用VoIP——但它确实意味着这个号码是一个薄弱的身份锚点。

**完成时** 运营商与其查询方法和可携性警告一起记录，并且号码被分类为可能-SIM、可能-VoIP或未知。

## 第4步——消息应用的披露

在消息平台上进行联系人发现可以揭示一个号码是否已注册，并且根据用户的隐私设置，一个显示名称、一个头像、一个关于行，有时是最后出现。它确实提供了信息——注册是一个关于个人的事实，并且头像直接转向`找到原始图像`。

它也是**交互式且涉及隐私**的。你正在向平台查询一个有名字的个人，通常是从一个账户，并且联系人列表同步会将该列表上传到平台。大多数平台限制自动或批量查询。只有在明确授权的情况下才执行它，一次一个号码，从一个在`investigate-without-getting-made`下管理的账户和设备，并记录它为交互步骤。上面的参考列出了每个应用暴露的内容。

**完成时** 应用存在已记录，或标记为未尝试并说明原因。

## 第5步——以每个格式作为字符串搜索号码

这是最高产的无主动步骤，也是最常被跳过的步骤。号码以十多种约定书写，搜索引擎不会在它们之间进行规范化。以引用和非引用国家代码的方式搜索每个格式：

```
"+1 555 123 4567"  "+15551234567"  "(555) 123-4567"  "555-123-4567"
"555.123.4567"     "555 123 4567"  "5551234567"      "001 555 123 4567"
```

完整的排列指南，包括国家约定和混淆形式：
[reference/format-permutations.md](reference/format-permutations.md)。

通过`google-like-a-spy`在多个引擎上运行这些——相同号码的覆盖范围在这些引擎之间差异很大——加上`find-leaks-in-the-wild`、`read-deleted-pages`和`what-leaked-about-you`。分类广告、商业目录、简历和旧的论坛签名是号码在公共场合出现的地方。

众包的来电显示应用和反向查询数据库也会提供一个名称。将这些视为线索，而不是归属：它们的名称数据来自其他用户的地址簿和提交的标签，因此它继承了每个错误标签、过时的联系人以及故意的污染。垃圾邮件评分是可以操纵的，并且许多这些服务要求你自己的联系人作为进入的代价。

**完成时** 每个格式都在两个引擎上搜索过，并且每个候选名称都记录了其来源，并标记为未验证。

## 哪里会出错

- **可携性使运营商数据无声地过时**：一个自信的错误答案，而不是错误。它还破坏了区域代码作为位置代理，以及VoIP分配和通过三次搬迁保留号码的人。
- **回收利用**。断开的号码被重新分配。一个在旧漏洞中的号码可能属于今天没有关联的人——这个人可能仍在接收前主人的账户恢复代码。
- **来电显示欺骗**很简单，所以通话记录上的号码不是其所有者打来的证据。**SIM交换**在所有权记录保持不变的情况下转移控制权：在欺诈工作中，注册所有者和接收SMS的人可能是不同的人，这就是攻击。
- **共享和企业号码**。一个号码，许多人。
- **聚合器过时**。反向查询数据在供应商之间复制，很少重新验证；两个网站同意通常意味着一个来源。

## 置信度分级

- **确认**——由目标在一个他们控制的源上发布，或者在一份权威记录（申报、许可证、注册）中与目标相关联，或者两个真正独立的信息来源同意。
- **可能**——消息应用注册带有与目标一致的显示名称，加上一个佐证公共列表。
- **未确认**——来自来电显示或反向查询服务的名称、聚合器记录或单个漏洞行，无论供应商的UI看起来多么自信。
- **拒绝**——线路类型、分配或时间线与目标矛盾，或者它是一个没有个人归属可能的共享企业线路。

在评级旁边显示线路类型——为VoIP号码命名所有者总是较弱的声明。

## 工作示例

给定`07700 900123`，声称属于一个英国供应商联系人。规范化为`+447700900123`；libphonenumber将前缀分类为移动范围。前缀查询命名一个运营商，基于HLR的查询命名另一个运营商——号码已携出。记录当前网络，将前缀答案标记为历史。

死胡同：反向查询网站返回一个与供应商联系人不匹配的名称，并且两个其他服务返回相同的字符串。一个来源重复了三次，不是佐证。放弃。

通过`google-like-a-spy`搜索每个书写格式，在`cached trade-directory listing`下找到该号码，在公司名称下，注册地址与发票显示的不同。该公司转向`x-ray-a-company`，差异成为发现。号码归属保持可能；企业链接是报告的内容。

## 法律和ToS注意事项

电话查询比大多数OSINT更受监管。几个司法管辖区限制谁可以运行反向查询以及目的，并且一些国家的消费者报告规则规定使用这些数据为就业、租赁或信用决策，无论来源多么公开。号码在GDPR和英国法律下是个人数据，并且联系人列表上传和自动应用注册检查违反了大多数平台的条款。使用号码定位私人个人的住所或启用未经同意的联系是不允许的；合法用途是欺诈工作、尽职调查、授权跳线追踪和自我审计。

## 第6步——报告

运行`write-the-intel-brief`。声明E.164形式、线路类型、运营商及其查询方法和可携性警告、应用存在以及交互步骤标志，以及所有者归属及其置信度等级和来源。

**完成时** 没有运营商声明没有其查询方法，并且每个交互检查都标记为交互步骤。
