# 找到任何人

将姓名转化为特定个人的资料档案。这项工作中有20%是寻找数据，80%是证明这些数据属于你的调查对象，而不是同名其他人。初学者先收集数据，再进行区分；这样最终会得到一份自信且引用详实的档案，描述了两个不同的人被合并成一个。在收集任何数据之前，先将姓名与第二个选择器绑定。

## 第1步 — 授权范围

在搜索之前写下：调查对象、调查目标、哪些在范围内、哪些不在范围内，以及管辖你和你调查对象的法律。阅读[../../ETHICS.md](../../ETHICS.md)。

适用场景：交易对手和投资者尽职调查、欺诈和资产调查、新闻采访、追查失踪人口和债务追讨、失踪人员、高级或受托职位的入职前诚信审查，以及个人自卫——通过自我调查来了解攻击者会找到什么。

始终禁止的范畴：为任何非法律文件的目的，建立私人个人的家庭住址、日常活动、子女、健康状况、移民身份或性取向；任何让你与调查对象接触的行为；以及任何合理人会称之为监视的使用。如果你的目标是面对、羞辱或亲自接触调查对象，请停止。另见`dig-through-data-brokers`中的美国就业和租赁限制，它约束了这里大部分的来源。

**完成标准**：在案件文件中存在范围说明，指明合法目标，并明确列出禁止范围列表。

## 第2步 — 将姓名与第二个选择器绑定

不要单独使用姓名进行搜索。选择一个锚点，并将其带入每个查询中。

| 你持有的信息 | 首要步骤 | 原因 |
|---|---|---|
| 姓名 + 雇主 | 专业网络、公司简介、新闻稿 | 就业是最强的廉价锚点；它提供了时间线和城市信息 |
| 姓名 + 城市/地区 | 当地记录——房产、法院、公开的选民名册、当地媒体 | 地理位置最快地排除同名者 |
| 姓名 + 照片 | `find-the-original-image`，然后`secrets-in-file-metadata` | 面容可以经受姓名变化和转写 |
| 姓名 + 电子邮件或用户名 | `what-an-email-reveals`，`hunt-a-handle` | 机器唯一的选择器；几乎无需进行区分 |
| 姓名 + 大致年龄 | 家谱、讣告、许可证记录 | 年龄段可以清晰地分割同名群体 |
| 仅姓名 | 停止。返回给请求者 | 一个普通的姓名不是一个可调查的选择器 |

同名调查对象需要两个锚点，而不是一个。非拉丁文字姓名需要使用本族文字拼写，加上你在来源中实际使用的转写——搜索所有这些，因为注册机构、文件和新闻媒体各自选择不同的罗马化方式。

**完成标准**：你可以陈述一个区分性测试——"我的调查对象是在X工作的人"——并将这个测试应用于每个候选记录。

## 第3步 — 操作顺序

从最便宜、最高产、最低噪音的开始。不要从数据经纪人开始；他们会在你找到拒绝它们的方法之前，给你一些看似合理的错误答案。

1. **结构化的专业记录**。专业网络、雇主团队页面和简介、新闻稿、会议日程和发言人页面。自我发布，因此关于角色和隶属关系准确，但关于成就不可靠。
2. **已发表的成果**。署名、论文、专利、标准贡献。使用`google-like-a-spy`与`site:`和精确短语运算符。论文带有机构隶属关系，并且通常有一个ORCID，ORCID的存在就是为了解决姓名歧义；专利带有发明人城市和受托公司。
3. **受监管角色的注册**。许可证和专业委员会发布姓名、许可证编号、管辖区、状态，并且通常有纪律处分历史。如果你的调查对象声称有受监管角色，这既证实了也确定了它。
4. **企业记录**。`who-really-owns-it`用于董事和持股。官员姓名转换是对于有商业参与的人来说最高产的单一步骤。
5. **公共法律和房产记录**。法院卷宗、判决、破产和土地登记——在该管辖区公开的地方和仅在该地方公开。
6. **社交和行为**。`hunt-a-handle`来枚举账户，然后`pattern-of-life-from-socials`。故意晚进行：最嘈杂的层，最容易误归因。
7. **聚合器**。`dig-through-data-brokers`，最后使用，并且仅用于你需要用更高层级的记录来确认的线索。
8. **历史记录**。`read-deleted-pages`用于已删除的简介和旧的团队页面——通常是 richest 单一来源，因为人们会清理当前页面并忘记存档。

完整来源目录以及每个来源可以和不能证明的内容：
[reference/source-catalogue.md](reference/source-catalogue.md)。

**完成标准**：每个层级都已处理或明确记录为不适用，并说明原因。

## 第4步 — 在收集时记录来源

每个声明在捕获时都会获得：声明、来源URL、访问日期、保存的副本或存档快照，以及哪个锚点让你将其归因于你的调查对象。在最后重建引用总是失败——页面会改变，而你将不再记得为什么你认为记录14是正确的人。

核实标准：**每个声明至少有两个独立来源**。独立意味着不同的来源，而不是不同的网站。三个经纪人同意是一个来源，因为他们互相购买。公司简介和来自同一宣传团队的新闻稿是一个来源。注册文件和署名的新闻文章是两个。

**完成标准**：案件文件中的每个声明都带有来源、日期和归因依据。

## 第5步 — 当它是不同的人时退出

积极寻找不确认的细节。表明你已经转移到同名者的信号：年龄或毕业年份与你的范围相差几年以上；地点与已知地点没有合理的桥梁；职业中断需要同时担任两个全职角色；中间名与仅仅缺席不同；亲属群组没有与你已经有的成员共享任何成员。

不要悄悄地放弃记录。将文件分开：维护一个候选集，并记录每个候选者什么可以确认或排除它。合并两个人会摧毁整个产品，并且在完成的简报中除非你明确跟踪候选者，否则这是不可见的。

**完成标准**：每个收集的记录都分配给一个命名的候选者，并且非调查对象候选者被记录而不是删除。

## 第6步 — 家庭和关联结构

只有当目标需要时。讣告命名幸存者及其关系和城市，是那里最有效的家庭结构来源；家谱和民事注册索引提供出生、婚姻和死亡信息（如果已发布）；共同董事和共同作者提供职业关联。将亲属视为区分的背景，而不是目标——将整个调查转向一个不相关的家庭成员是禁止的。

**完成标准**：简报中使用的所有关系都有来源，并且没有未涉及的第三方被建立档案。

## 第7步 — 报告

交给`write-the-intel-brief`。将确认的事实与推断分开，在简报开头说明区分依据，列出你排除的候选者，并删除任何与目标不需要的收集内容。

**完成标准**：简报声明其每个声明的信心等级和区分依据，并且已经删除了多余的收集内容。

## 哪里会出错

- **姓名冲突被低估**。即使是罕见的姓名，在一个家庭中也可能共享——初级、高级和以同一祖父母命名的堂兄弟住在同一个城市，并且出现在相同的记录中。
- **聚合器相互洗白错误**。一个错误的中间名或一次合并的家庭信息一旦输入就会传播到所有地方，然后看起来得到了证实。
- **自我发布的简介是理想的**。头衔膨胀，日期四舍五入，学位被升级。在颁发机构或注册处确认资格。
- **没有记录不等于没有事实**。稀疏的足迹可能意味着一个私人人士、非英语足迹、最近移民或关闭的注册机构。这不是隐藏的证据。
- **照片匹配被过度信任**。两个简介上的相同头像证明简介共享图像，而不是一个人——抓取器、库存照片和冒充账户都会重复使用图像。使用第二个选择器进行确认。
- **姓名变化打破连续性**。婚姻、转写、笔名和法律变化将一个轨迹分成两条，并且旧记录在先前的姓名下不会自我链接。
- **你可能正在查看一个合成身份**。欺诈案件产生的调查对象其整洁、最近、浅层的足迹是人为制造的。一个没有先前历史的档案本身就是一个发现。

## 信心等级

- **确认**——两个独立来源，至少一个主要来源（注册文件、法院记录、许可证委员会条目、机构页面），这些来源在声明上同意，并且在共享的区分锚点上同意。
- **可能**——一个主要来源，或两个次要来源有锚点匹配，并且没有找到矛盾记录。
- **未确认**——单个次要来源、聚合器仅使用，或仅依赖于姓名加上一个宽泛地区的锚点匹配。将其报告为线索。
- **拒绝**——分配给不同的候选者。将其保留在文件中并说明原因。

分别评估*身份归属*和*声明*。法院记录可以是完全真实的，但仍然不是你的调查对象。

## 工作示例

目标：对"Marcus Rowntree"进行投资前尽职调查，其被列为CTO，锚点 = 雇主。

1. 公司团队页面提供角色和头像。存档它——供应商网站经常变化。
2. 精确短语搜索姓名加上公司显示两个具有相同头像的会议发言，并声明了先前的雇主。锚点现在有两层。
3. 在`who-really-owns-it`中搜索姓氏的董事返回四个董事职位。其中三个列出了与会议简介隐含年龄范围匹配的出生月份和年份；一个是另一个国家，出生年份相差11年——作为候选者B分开，记录，不使用。
4. 死胡同：聚合器档案将姓名与破产联系起来。列出的中间名冲突，城市没有与任何已知地点的桥梁。分配给第三个候选者；破产不进入简报。
5. 先前雇主声明无法核实——没有新闻稿、没有存档团队页面、没有文件。评级为未确认，并标记为尽职调查问题，而这个问题本身就是一个有用的发现。

## 转换器

| 选择器产生 | 输入到 |
|---|---|
| 用户名或显示名称 | `hunt-a-handle` |
| 电子邮件地址 | `what-an-email-reveals` |
| 电话号码 | `whose-number-is-this` |
| 照片 | `find-the-original-image`，`secrets-in-file-metadata` |
| 带有地点问题的照片 | `where-was-this-taken` |
| 公司名称或注册号 | `x-ray-a-company`，`who-really-owns-it` |
| 个人或虚荣域名 | `recon-a-domain-passively` |
| 确认的社交账户 | `pattern-of-life-from-socials` |
| 地址、亲属、先前城市 | `dig-through-data-brokers` |
| 已删除的简介或旧简介 | `read-deleted-pages` |
| 完成的证据集 | `write-the-intel-brief` |

## 法律说明

在欧盟和英国，对活人进行画像处理个人数据：你需要合法依据，新闻采访、法律索赔和合法利益是不同的依据，有不同的限制。调查对象可能对你拥有访问和删除权。在美国，使用聚合器数据用于就业、租赁、保险或信用决定，在不受监管的消费报告机构之外是合规违规行为——参见`dig-through-data-brokers`。驾驶和车辆记录在许多管辖区是限制用途的。如果你的研究是有害的，并且可能会引发诉讼，请捕获证据以便它能够经受挑战：时间戳、哈希、存档。

对于自卫，运行此工作流程在你自己身上，使用`dig-through-data-brokers`中的选择退出指南，并使用`investigate-without-getting-made`，以便搜索本身不会创造新的风险。
