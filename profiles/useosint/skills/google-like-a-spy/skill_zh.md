# 搜索运算符

运算符将搜索框转化为对爬取索引的过滤器。代价是，你查询的是某个人的*索引*，而不是整个网络——不同引擎的覆盖范围、更新频率和运算符保真度差异巨大。初学者犯的错误是假设他们的查询按原样执行。谷歌会常规性地丢弃、词干提取和同义词扩展你的术语，因此零结果搜索和无声重写的搜索看起来毫无相似之处，但它们同样无济于事。

## 哪个引擎适合哪个任务

| 你想要 | 前往 | 原因 |
|---|---|---|
| 主流网络广泛的覆盖范围 | Google | 最大索引，最差的运算符保真度 |
| 可靠的 `site:` 列举，IP/主机转换 | Bing | 更字面地执行运算符；拥有 `ip:` 和 `contains:` |
| 非拉丁脚本、俄语/中亚/土耳其内容、图像相关工作 | Yandex | 不同的爬取优先级；最强的图像匹配 |
| 匿名查询、快速切换引擎 | DuckDuckGo、Startpage | 代理其他索引；使用感叹号在引擎之间跳转 |
| 独立爬取（大三家从未索引的内容） | Mojeek、Marginalia、Brave | 拥有自有爬取器，规模虽小但确实不同 |
| 代码、容器、主机、存档 | 专业索引 | 一般网络索引从未爬取其中的大部分 |

不要在一个引擎上单独运行搜索。不同的爬取器发现不同的页面，而从未爬取某个URL的引擎无法通过运算符引导它。运算符在何处存活，以及同一个运算符在不同地方意味着不同的含义，请参考 [reference/engine-operators.md](reference/engine-operators.md)。

## 仍然有效的运算符

- `"精确短语"` — 最有用的运算符。仍然可能被重写（见下文），但你能给出的最强信号。
- `site:` — 接受完整主机、可注册域名（匹配子域名）或顶级域名 (`site:gov.uk`)。也可用作 `-site:` 来排除。
- `filetype:` — 谷歌的文档形式。Bing 接受 `filetype:` 和 `ext:`；`ext:` 匹配 URL 扩展名而不是嗅探的内容类型，这对于 `.env`、`.bak`、`.sql` 通常是你想要的。
- `intitle:` / `allintitle:`, `inurl:` / `allinurl:`, `intext:` / `allintext:`。`all*` 形式适用于每个后续术语，但与其他运算符混合效果不佳——单独使用它们。
- `before:` / `after:` 与 `YYYY-MM-DD` — 基于 Google 估计的文档日期进行过滤，这是推断的，并且经常错误。一个粗略的筛子，不是证据。
- `-term` 来排除，`OR`（大写）或 `|` 用于交替，括号用于分组，`*` 作为短语内的单词通配符。

## 仍然被引用但不再值得使用的运算符

`cache:` 和 `info:` 已被弃用，`link:` 很久以前就被撤回，任何残留行为都是噪音，而 `related:` 是不一致的。`inanchor:` 和 `AROUND(n)` 从未被文档化，行为不可预测。`+` 用于强制包含，`~` 用于同义词扩展已被完全移除，引号取代了前者，`daterange:` 被 `before:`/`after:` 取代。使用这些运算符的搜索库返回的是一般结果，而不是错误。

## 强制字面匹配

谷歌的检索层是一个带有关键词过滤器的语义匹配器。它会丢弃它认为无用的术语，替换同义词，或纠正它认为是一个拼写错误——这正是你在查找用户名或错误字符串时不想发生的情况。

1. 查看结果标题。谷歌在丢弃某些内容时打印 "Missing: `<term>`" 并带有 "Must include:" 链接。该链接强制包含该术语重新运行。如果你看到这种情况，你的搜索没有运行。
2. 分别引号每个非明显标记，而不仅仅是短语。
3. 切换到纯文本模式（工具，然后是“所有结果”下拉菜单），这会禁用词干提取、同义词、拼写纠正和个性化。没有它，搜索就是猜测。
4. 扩展重复过滤器。谷歌会合并“非常相似”的结果，并在最后一页的末尾提供一个链接来包含它们。在 `site:` 列举中，这通常会使可见集翻倍。
5. 如果修正后的拼写仍然获胜，则查询被读取为导航意图。添加一个罕见的第二个标记来打破这种情况。

## 在目标站点之外找到目标材料

一个组织泄露的大部分内容都托管在其他地方，因此扫掠*主机*而不是希望目标域上的搜索能捕获它：粘贴和死投主机、代码沙盒、发布到网络的办公文档、全文文档存储库、云对象存储在提供商拥有的主机名上，如 `s3.amazonaws.com` 或 `blob.core.windows.net`，以及具有公共共享默认值的第三方 SaaS——看板、维基、表单后端、状态页面。`site:` 提供商，而不是客户。

## 防御性框架下的发现搜索

在授权评估的域上或你自己的资产上运行这些。读取搜索结果是被动的——引擎已经爬取了页面。获取文件、下载备份或登录你找到的面板不是，这就是法律界限所在。

高收益的形状，按命中率大致顺序：迁移后留下的目录列表 (`intitle:"index of"`), 按扩展名查找配置和环境文件，数据库转储和备份工件，索引文本中形状为凭证的字符串，提供商主机名上的对象存储，以及主机名暴露的管理或监控界面。完整集，包括查找人员和文档的查询，在 [reference/dork-cookbook.md](reference/dork-cookbook.md) 中。

引擎只索引链接到的东西，因此未链接的面板和桶列表代表性严重不足——对于实时服务使用 `find-exposed-servers` 扫描。现在返回 404 的命中仍然是证据：将 URL 带到 `read-deleted-pages`。

## 速率限制、验证码以及为什么自动化会失败

检测主要不是关于请求速率。引擎指纹识别客户端：TLS 握手特征、头部顺序、是否执行 JavaScript、时间行为以及源 IP 的声誉。一个从未渲染 JavaScript 的数据中心 IP 在其第一个请求时就会触发检查，而一个以人类速度驱动真实浏览器的住宅 IP 可以整天进行搜索。这就是为什么减慢你的循环往往在手动输入相同查询时失败的原因。

最糟糕的失败不是验证码，而是一个看起来正常的降级结果集：运算符被无声忽略，结果被截断，没有指示。永远不要假设脚本查询返回了浏览器会返回的内容。

首选的授权路线。**官方搜索 API**，其中引擎出售一个：在术语内，但期望配额，并且与消费者 UI 没有对等性，因为 API 的索引和排名通常是不同的产品。**商业 SERP 提供商**，它们运行代理基础设施并返回结构化结果——付费的，并且仍在根据某些条款抓取。**你自己的 SearXNG 实例**，它跨引擎规范化结果；永远不会是公共的，在那里你继承了陌生人的速率限制声誉，并将你的选择器交给其运营商。以及**在浏览器中手动运行**，对于真实调查中需要的二十到五十个查询来说，这比构建自动化更有效。

旋转 IP 以规避检测是绕过技术访问控制——在几个司法管辖区这是一个更严重的法律问题，与抓取不同，在这里是不允许的。查询本身也被记录下来并可归因，因此将敏感选择器通过非记录引擎或隔离环境路由，根据 `investigate-without-getting-made`。

## 专业索引

每个索引都摄取不同的语料库，并回答谷歌无法回答的问题。

- **代码搜索。** GitHub 代码搜索覆盖公共存储库；grep.app 和 searchcode 跨主机索引。搜索内部主机名、密钥前缀和目标的电子邮件域，而不是其名称。见 `secrets-in-git-history`。
- **云存储索引。** 桶索引，如 Grayhat Warfare，列举的开放对象存储远超引擎触及的范围，因为列表页面很少被可爬取的页面链接。
- **文档存储库。** Scribd、Issuu、SlideShare、DocumentCloud 和学术聚合器全文索引上传，提取在公司自己域上无处出现的 PDF 中隐藏的公司名称。
- **原始 HTML 索引。** Publicwww 和类似搜索页面源，让你可以基于分析 ID 和标签管理容器进行转换。共享的跟踪 ID 比共享的 IP 作为共同所有权证据更有效：一个账户配置了两者。
- **存档索引。** Wayback CDX API 和 Common Crawl 索引是可查询的 URL 语料库，而不是排名搜索，列举爬取器观察到的路径，包括已移除的路径 (`read-deleted-pages`)。扫描器索引主机，而不是页面 (`find-exposed-servers`)；泄露语料库，`find-leaks-in-the-wild`。

## 哪里会出错

- **你输入的查询不是运行的查询。** 词干提取、同义词、拼写纠正和术语丢弃是默认的；没有纯文本，零结果是无意义的。
- **零结果意味着一个索引说“不”** —— 这是关于该引擎的爬取和运算符支持的说法，而不是关于整个网络。在记录之前，你需要三个引擎和一个存档。
- **`site:` 永远不会完全列举。** 谷歌会截断和去重，硬，Bing 深入更多，都不是详尽的。结果计数是估计值，你可能永远不会引用——如果你需要真实的，请到底页。
- **索引是一个过时的镜像。** 命中描述的是爬取时的页面；实时页面可能不同或已消失，快照可能是唯一幸存的副本。与实时 URL 核对并立即存档。
- **`before:`/`after:` 过滤一个推断的日期。** CMS 驱动的站点在渲染时重新标记页面。永远不要用它来确定发布时间。
- **个人化和地理位置改变结果。** 两个调查员运行相同的搜索得到不同的页面，因此记录引擎、查询和日期。
- **复制的搜索库库会无声地腐烂。** 一个被弃用的运算符变成了一个搜索词，而不是错误，因此查询返回看似合理的一般结果，而你永远不会注意到过滤器停止应用。
- **伪装和索引中毒。** 爬取器可以收到与用户不同的内容，并且 SEO 垃圾种子将目标名称种入不相关的页面。提及不代表关系。

## 置信度评级

- **确认** — 你检索了实时文档或其存档捕获，阅读了它，并且其内容直接陈述了事实，其元数据或主机证实了来源。
- **可能** — 在权威主机上有一个独特的精确匹配字符串，或者来自两个独立爬取的相同事实。你无法打开的快照最多是可能的。
- **未确认** — 一个快照；一个在重新发布他人内容的站点上的命中；一个常用词匹配；来自未在纯文本模式下运行的查询的任何内容。
- **拒绝** — 仅在没有纯文本模式下生存的匹配，或者在一个内容是机器生成名称抓取的页面上提及。

引用 URL、引擎、查询字符串和检索日期。一个无人能重新运行的查询不是证据。

## 示例

目标：识别 Example Corp 谁负责采购，用于供应商尽职调查文件。网站没有列出董事会以下级别的姓名。

在纯文本模式下运行 `site:example.com filetype:pdf procurement` 返回四个文档。一个是供应商入职包，其 PDF 属性包含作者字符串，`m.okafor`，以及部门网络共享下的模板路径——从这份文档中发现了两个新的选择器，而其正文没有提及任何人。

死胡同：`"m.okafor" site:linkedin.com/in` 返回空，裸处理也一样。没有个人资料，或者不在索引中。

重写为电子邮件形状有效。`"m.okafor@example.com"` 命中一个在无关域上的公共邮件列表存档，在那里同一个人以全名和职位头衔签署了一个技术问题。然后对目标主机进行 Bing `ext:xlsx` 扫描，表面一个供应商注册证实了角色。

评级：角色 **确认**，在两个都检索并阅读的文档上。身份 **可能** — 处理手柄到名称的映射依赖于一个自签名的帖子。

## 法律和 ToS 注意事项

自动化查询违反了每个主要引擎的服务条款。这是一个合同问题，通常的后果是封锁——但通过旋转 IP 或程序性解决验证码来规避这些封锁是绕过技术访问控制，在几个司法管辖区这是一个更严重的问题。

发现一个暴露的文件不授予检索它的授权。结果是公开的；文件本身可能仍然是根据计算机滥用法受保护的计算机，并且“它在 Google 上”已经不能作为辩护。在授权评估内，记录它，不要窃取它，通过约定的渠道报告。在授权评估外，通知运营商或国家 CERT 并停止。

索引的个人数据仍然是个人数据——搜索不会使其洗净。去索引请求也使欧洲结果集中故意缺席的内容，而在其他地方存在，因此在得出任何东西已经消失的结论之前，请比较地区。最小化 [../../ETHICS.md](../../ETHICS.md)。
