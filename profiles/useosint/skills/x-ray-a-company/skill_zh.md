# 对公司进行X光检查

以一个品牌、一个网站或一张发票为起点，制作一份关于你实际正在与之打交道的人的可辩护的画像。分四个层次——法律实体、人员、基础设施、声誉和风险——按顺序进行。跳过第一个层次会毁掉后续所有工作：合同上的经营名称、网站上的品牌以及法庭上负责的实体通常是三个不同的东西，如果你假设它们是一致的，那么后续的每一个发现都会关联到错误的对象。

## 第1步——授权范围

写明目标、支持工作的决策、范围内的风险区域、涉及的司法管辖区以及超出范围的内容。阅读 [../../ETHICS.md](../../ETHICS.md)。对公共披露信息的公司研究在大多数情况下是合法的，并且通常是强制性的，但有两个限制会带来问题。对公司自身的系统保持被动——读取DNS和证书日志是开源情报（OSINT），而认证或探测则不是。公司内部指定的个人仍然是数据主体：一个官员的董事职务是合理的，而他们的家人则不是。

**完成标志** 范围说明中列出了决策、风险区域和司法管辖区，并声明未经授权进行交互式测试。

## 第2步——首先解决法律实体

你在寻找一个在指定注册机构中的注册号。在你获得一个注册号之前，你并没有一个主体。

| 你持有的信息 | 到达实体的路径 |
|---|---|
| 一个网站 | 页脚、条款和隐私政策——在许多欧洲国家，法定披露规则强制要求在网站上公布法律名称和编号；然后在注册机构中确认 |
| 一个品牌或经营名称 | 商标注册处提供注册所有者；国家注册处将经营名称索引到注册人 |
| 一个发票或合同 | 公司名称、增值税/税号和注册办事处通常都在上面；核实每一个，不要相信信头 |
| 一个上市公司 | 证券监管机构的申报系统比公司注册处更丰富 |
| 一个集团名称 | 找到任何一个成员实体，然后双向追溯链 |

运行 `who-really-owns-it` 以获取注册机构的机制。记录法律名称、注册号、司法管辖区、成立日期、状态、注册办事处、官员和股本。优先考虑编号而不是名称——名称会变化，编号不会。标准陷阱：一个运营公司和一家名称几乎相同控股公司；一个已解散的实体仍在使用其旧品牌进行交易；一个由不同司法管辖区（与交易实体不同）的知识产权实体持有的品牌；一个由不会对产品负责的营销实体运行的网站。

**完成标志** 你能够命名一个实体，该实体将作为你合同的另一方，包括其注册机构和编号，并说明哪些其他实体共享该品牌。

## 第3步——集团结构和受益所有权

向上追溯到最终母公司，向下追溯到子公司。来源：已提交的集团账目和子公司名单、上市公司列举子公司的文件、受益所有权注册处以及 `who-really-owns-it` 中的共享官员和共享地址的枢轴。跨境链是常态，而不是红旗。重要的是链是否以一个指定的自然人结束，或者是否消解到一个不发布任何信息的司法管辖区。记录尽可能多的信息，并说明停止的地方——"追溯到一家开曼实体，其注册处不公开"是一个发现，而不是失败。

受益所有权有四种可预测的分解方式：指定人，法律上记录且经济上无关紧要；信托和基金会，大多数注册处无法穿透；分层，没有任何单一注册处能看到整个链；以及门槛，由于设计上的盲目性，每四个持有接近线以下的人。

**完成标志** 所有权链追溯到其终点或到一个记录在案的透明点，并记录了指定受益所有人及其来源。

## 第4步——人员

从注册处而不是网站获取官员名单——网站显示他们推广谁，注册处显示谁负有法律责任。对于与决策相关的重要人员运行 `find-anyone`，并运行 `who-really-owns-it` 中的官员名称枢轴以查找他们的其他和以前的董事职务。一个有解散公司记录的董事，或一个在二十个不相关的董事会上的董事，与一个有连贯职业生涯的董事的风险状况不同。

员工统计——来自专业网络、招聘信息和团队页面的员工人数和职能组合——测试公司是否在运营上与其声称的一致。平台计数包括过时和重复的配置文件，排除非用户，并根据国家和行业严重倾斜：使用员工队伍的形状，而不是数量。

**完成标志** 每个记录在案的官员都列出了他们的其他董事职务，并且已经检查过，并且员工队伍声明得到了证实或被标记。

## 第5步——数字资产

运行 `recon-a-domain-passively` 作为入口点；它涵盖了 `who-owns-this-domain`、`find-hidden-subdomains` 和 `find-exposed-servers`。尽职调查想要从它那里得到的东西，与安全测试相比：注册日期与声称的成立日期矛盾、基础设施与无关品牌共享一个运营商、子域名揭示了未宣布的产品或合作伙伴、以及工作帖子证据显示了真实的堆栈。检查 `secrets-in-git-history` 以获取公共存储库，并检查 `what-leaked-about-you` 以获取电子邮件域的违规暴露。

**完成标志** 列出了域名组合，将注册日期与公司时间线进行比较，并记录了差异。

## 第6步——诉讼、破产、采购和披露

- **诉讼。** 实体的法院卷宗和判决数据库、其以前的名称及其子公司的判决数据库。阅读判决结果，而不是申报——被起诉不是责任，并且和解告诉你比判决少。
- **破产。** 破产注册处和法定公报载有清算申请、管理和清算通知。检查官员的以前公司；那里是模式显示的地方。
- **采购。** 公开招标和合同授予数据库是第三方验证的收入——最有力的免费证据表明实际运营，并且严重未被使用。禁令和排除名单与它们一起存在。

首先根据申报制度校准财务发现。上市公司提交经审计的报表、部门细节、关联方交易和风险因素。大多数司法管辖区的小型私营公司提交一份简化的、通常未经审计的资产负债表，没有利润表和没有营业额数字——因此，在那里没有收入披露是法律规范，而不是逃避。什么是有意义的：迟交的申报、重复的审计员变更、审计员辞职、有保留意见、资产注册的收费，以及与声称的运营规模不一致的账目。每个风险区域的指定来源：
[reference/diligence-checklist.md](reference/diligence-checklist.md)。

**完成标志** 诉讼、破产和采购每个都有来源发现或记录的“搜索了这些数据库，未发现”，并且财务发现与该实体类型被要求披露的内容进行了对比。

## 第7步——制裁、PEP和负面媒体

它有自己的步骤和自己的记录，因为它是一个监管机构或法院会要求你提供证据的步骤。筛查实体、其母公司和子公司以及每个指定个人。主要发布者：OFAC的制裁名单搜索、欧盟综合名单、英国制裁名单、联合国综合名单。OpenSanctions聚合了跨司法管辖区的制裁和PEP数据集，是跨司法管辖区域扫除的实际起点；OCCRP Aleph是一个研究索引，用于调查而不是合规筛查。PEP状态是风险因素，而不是违规行为，并且扩展到密切关联的亲属和家庭——这正是自动化筛查最薄弱的地方。

负面媒体意味着对实体、其以前的名称及其主要人员在每个链中司法管辖区的地方语言中进行结构化搜索。对一个有外国母公司的公司进行仅英语搜索几乎毫无价值。记录搜索词和日期范围，以便负面内容具有证据意义。

**完成标志** 链中的每个实体和个人都根据制裁和PEP来源进行了筛查，并记录了来源和日期，并且负面媒体在相关语言中进行了搜索。

## 第8步——空壳公司评估

评分你的画像；不要对单个指标做出反应。加权目录：
[reference/shell-company-red-flags.md](reference/shell-company-red-flags.md)。
核心集群：一个地址由数千个实体共享；在参与交易之前不久成立；没有网络存在，或者域名晚于提案；指定董事在无关公司中反复出现；没有员工，并且没有显示活动的账目；一个模仿已建立公司的名称；银行详细信息在一个与实体、董事或工作无关的司法管辖区。任何一个都是常见且无辜的。四个一起就是答案。

**完成标志** 实体根据目录进行评分，每个指标都有来源，并且结论说明了哪些指标导致了这一结果。

## 第9步——报告

交给 `write-the-intel-brief`。以实体图表开头——最终母公司、中间控股公司、合同实体、子公司、关键人员——然后按风险区域列出发现，包括来源、日期和信心。空白部分有自己的部分；一份隐藏了它无法检查的内容的尽职调查报告比一份发现不了任何东西的报告更糟。

**完成标志** 简报有一个实体图表、按风险区域列出发现、一个明确空白部分，以及一个声明的整体信心。

## 哪里会出错

- **注册数据是申报的，而不是核实的。** 大多数注册机构检查表格是否完整，而不是真实情况；记录只能证明申报了什么以及何时申报的。
- **陈旧性是设计中的。** 年度申报周期使已发布的官员和账目落后于现实一年或更长时间，并且聚合器再次滞后——一个已解散的公司仍然显示为活跃。在注册处确认。
- **名称匹配同时产生错误。** 常见名称会产生错误匹配；标点符号、法律形式后缀、音译和合并后的重命名会产生错误否定。故意搜索以前的名称。
- **没有申报可能意味着错误的注册处。** 存在独立的联邦、州和市注册处，以及用于外国分支机构、合伙企业和其他非公司形式的单独注册处。
- **制裁筛查是嘈杂的。** 音译名称会产生大量错误匹配；一个匹配是一个审查触发器，而不是一个发现。
- **负面媒体有语言和财富偏见。** 覆盖在主要市场之外很薄，并且好诉讼的主题会删除覆盖。

## 信心评级

- **确认** —— 在主要注册处或监管机构的申报中，或者在法院记录中，并且文档已检索并注明日期。
- **可能** —— 来自信誉良好的聚合器或单个可信报告，与主要记录一致且未被反驳。
- **未确认** —— 公司营销、单个未来源报告或仅从结构中推断。
- **空白** —— 一个应该返回它的来源未返回，或者该司法管辖区不发布任何信息。命名数据库和日期；一个记录在案的负面是一个可交付成果。

分别评级所有权声明和运营声明。你可以确定注册股东是谁，并且不知道谁受益。

## 工作示例

供应商“Halberd Logistics”推销一份供应合同；你持有网站和发票。

1. 网站页脚命名“Halberd Logistics Group Ltd”并附有公司编号；发票命名“Halberd Ops Ltd”，一个不同的编号。合同方是发票上的，并且它不是承载品牌的一方。
2. 注册处：Halberd Ops 已有十四个月，一名董事，微型实体账目；集团实体已有九年，有真实的账目。提案的交易历史属于一个你不会与之签订合同的实体。
3. 官员枢轴在 Halberd Ops 董事上返回两家以前的公司，这两家公司都在强制解散后解散。
4. 死胡同：注册办事处托管了大约两百个实体，但解析为一个会计事务所。普通——低权重。
5. 域名在发票日期前三个月注册，与声称的九年历史不符。结合 2 和 3：要么与集团实体签订合同，要么根本不签。

## 枢轴

| 选择器产生 | 输入到 |
|---|---|
| 注册号、官员、股东 | `who-really-owns-it` |
| 官员或董事姓名 | `find-anyone` |
| 主要域名 | `recon-a-domain-passively`、`who-owns-this-domain` |
| 官员地址、电话、关联方 | `dig-through-data-brokers` |
| 母公司或子公司实体 | 在第 2 步重新进入此工作流 |
| 公司电子邮件域名、公共存储库 | `what-leaked-about-you`、`secrets-in-git-history` |
| 多实体所有权网络 | `graph-the-network` |
| 完成的证据集 | `write-the-intel-brief` |

## 法律注意事项

KYB、AML和制裁合规义务要求来源和记录保存要求，此工作流本身无法履行；对于受监管目的，你的记录必须显示你搜索了什么、何时搜索的以及结果如何。注册数据通常带有重用条件和速率限制——使用公开的API和批量产品，而不是抓取。官员居住地址和出生日期在许多注册处受保护，并且故意重新识别受保护的地址在某些司法管辖区是犯罪。
