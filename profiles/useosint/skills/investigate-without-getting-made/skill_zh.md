# 探究而不被察觉

收集是双向的。大多数调查者并非被聪明的对手烧毁，而是被平台按照其宣传所做的行为所伤：告知目标者查看了其资料，向目标者推荐调查者认为可能是其熟人，或将某条内容标记为已查看。默认的失败并非泄露 IP 地址，而是登录了真实账户。

## 优先进行威胁建模

OPSEC（操作安全）工作应做到与任务相称。在投入一天时间构建基础设施——或决定根本不需要任何基础设施之前，先回答三个问题。

1. **谁可能会察觉？** 一个休眠的空壳公司、一个有一定技术能力的个人、一个运行受监控基础设施的犯罪团伙，或是一个政府机构。他们的能力决定了标准的严苛程度。
2. **他们会看到什么？** 被动收集：服务器日志中的一行记录。登录访问：你的姓名。交互：你的人设及其历史。
3. **后果是什么？** 无后果，或证据被销毁且账户变为不可用，或调查被归功于你的组织并被披露，或对你或线人造成人身风险。

| 情境 | 相称的姿态 |
|---|---|
| 注册处、档案、CT 日志、法院记录 | 使用常规浏览器，不使用人设。你只是成千上万中的一个。 |
| 查看目标的公开网站 | 干净的浏览器配置，商业 VPN，无登录会话。 |
| 对目标进行任何已登录平台的查看 | 使用人设账户、专用资料，并首先检查平台的查看通知行为。 |
| 目标运行受监控基础设施或具备技术能力 | 专用虚拟机、非数据中心出口、不重复指纹、时间纪律。 |
| 存在有组织犯罪、骚扰风险、人身安全风险 | 上述所有措施外加隔离的硬件，以及知晓你正在做什么的同事。 |

过度设计也有代价：封闭的配置会被打码、限流并拦截，因此你收集到的内容更少，且不寻常的配置本身也显得具有辨识度。若目标是融入其中，就应融入其中。且在确定如何安全地查看某物之前，先检查档案中是否已包含相关内容（`read-deleted-pages`）——快照不会向目标传递任何信息。

## 你的归属暴露面

网站或平台可以从一次访问中学到什么：

| 暴露面 | 会泄露什么 |
|---|---|
| IP 和 **ASN** | 网络而非地址才是关键信息：数据中心 ASN 意味着"VPN 或爬虫"，企业 ASN 意味着你的雇主名称——这是最坏的结果，且很常见，因为人们会忘记办公网络是一个标识符 |
| 浏览器指纹 | 用户代理、窗口几何形状、字体、画布和 WebGL 渲染、硬件并发、时区——通常具有唯一性，且关键的是，在会话和 IP 之间保持稳定，因此在没有其他信息的情况下，能将你的访问关联起来 |
| TLS 指纹 | 客户端 hello（密码套件、扩展、顺序）独立标识你的客户端，与浏览器暴露的任何信息无关；这是代理后的工具能轻易与真实浏览器分离的原因——头部表明是 Chrome，但握手并不反映 |
| 语言和地区 | `Accept-Language`、时区偏移、单位。一个使用英语地区设置的浏览器，从第三国数据中心的 IP 读取区域性语言网站，会留下可辨识的痕迹 |
| 时序 | 活动仅在某一国家的正常工作时段内，节假日有间隔，整点有突发。时序能克服你应用的所有其他控制措施 |
| 链接预览 | 将目标 URL 粘贴到聊天、工单或文档中，会使该平台去获取它；获取会触及目标服务器，并与你的其他活动相关联。禁用预览或改写 URL |

**登录账户是最大的问题。** 认证将匿名请求转变为已识别的请求，而泄露本身就是功能特性：资料查看通知和查看者列表、内容与视频查看列表、"你可能认识的人"建议（基于联系人列表和交互图驱动）、已读回执、粉丝和列表通知、互连展示。有些只需加载页面就会触发，无需其他操作。

针对每个暴露面的检查、各平台类别暴露的内容，以及有助于和无法帮助的设置：[reference/attribution-surface.md](reference/attribution-surface.md)。

## 隔离必须是绝对的

研究身份与现实身份绝不能有任何联系。不是"大部分"——一次跨越就会永久地将它们关联起来，一旦平台将其关联，就不可逆转。造成烧毁的具体泄露，大致按其伤人的频率排列：

- **用于短信验证的真实电话号码。** 这是最强跨平台标识符；平台内部会基于它关联账户，并用它驱动基于联系的推荐。一次验证将人设与你的真实身份永久关联，包括事后追溯。
- **属于你的恢复邮箱** ——或属于另一个人的恢复邮箱，这会将人设彼此关联起来。
- **支付方式。** 任何卡片、钱包或订阅，包括 VPN。
- **重复使用的密码**，未来在数据泄露中会被暴露，并将你的账户集群化，供任何购买这些数据的人使用——见 `what-leaked-about-you`。
- **同步的浏览器配置**，将其中的历史、自动填充和已保存密码带入研究环境。个人 Cookie 和会话也起到其余作用。
- **能够反向搜索回你的头像** ——或回向任何人（`find-the-original-image`）。裁剪后的个人照片、朋友照片、库存图片都会失败，原因各不相同。也清除上传元数据（`secrets-in-file-metadata`）。
- **风格与习惯。** 独特的表述、反复出现的拼写错误、固定的工作时段。
- **上传联系人列表。** 授予应用访问联系人权限，在曾保存过你真实联系人的手机上进行，会向平台提供将一切关联起来的图。

## 人设

仅在观察确实需要账户时创建人设，并先阅读下方关于服务条款的部分。全新且空的账户既无用又显眼：它看不到多少内容，且完全显示其本来的样子，因此在你需要时，它会被拦截、质询或封禁。人设需要合理的历史和年龄，因此应在需要它们的情案之前创建，并让它们积累普通的日常活动。维护一个较小的稳定集合，而非每次调查一个。

一致性是整个游戏的关键：姓名、地区、语言、时区、发布时段、兴趣、连接点，都要彼此一致，并与平台的人口统计特征一致。一个声称身处某城市却在那个城市的夜间发布时段发布的个人，是会被人类立刻察觉的矛盾。

分步构建、标识符来源、老化日程与维护惯例：[reference/persona-runbook.md](reference/persona-runbook.md)。

无论任务要求如何，硬性限制：人设仅用于**观察**——不得用于诱导获取私密信息、诱导任何人行动，或在缺乏进行该操作授权的情况下，以虚假理由获取封闭系统或群体的准入。

## 网络出口

| 选项 | 适合 | 不适合 |
|---|---|---|
| 商业 VPN | 从普通网站隐藏你的 ASN 和大致位置；最常见的默认选项 | 拦截数据中心范围的任何设置；任何"明显 VPN"本身成为信号的场景；信任服务商 |
| 住宅 / 移动代理 | 表现为普通的消费者连接；访问拦截数据中心的业务 | 成本、可靠性波动，以及严重的来源问题——见下文 |
| Tor | 对网络观察者具有强匿名性；访问洋葱服务 | 使用人设账户（出口地址是公开可枚举的，因此预期会被拦截、质询和账户安全挑战）；任何需要会话稳定性或地理合理性的场景 |
| 自有 VPS | 控制与稳定性 | 作为可追溯至计费身份的数据中心 IP，这往往比 VPN 更糟 |

Tor 是这里最强的工具，但多数时候是错误的选择：出口地址公开可枚举，因此受监控的目标会看到"有人使用 Tor 查看了这个"——比普通访问更能吸引注意力——且平台将 Tor 登录视为高风险，会触发杀死人设的验证质询。

住宅代理需要特别警告：许多池子由通过捆绑 SDK 注册的消费者设备组成，其用户并未有实质性的同意，且你的流量通过陌生人的家庭连接出口——这对双方而言既是一个道德问题，也可能是一个法律问题。了解你的服务商如何获取其池子，否则不要使用其中之一。

验证你选择的任何选项：检查出口地址及其 ASN，确认 DNS 通过隧道解析，并屏蔽 WebRTC，因为它能独立于隧道揭示地址。

## 环境与隔离

一案一环境。每个案件一个专用虚拟机是干净的答案；一个专用浏览器配置是最低要求。容器化的标签隔离能分离 Cookie，但不能隔离指纹——这是一种便利，而非边界。跨设置：从不登录任何属于目标的真实账户；快照保持干净，案件之间回滚；将记录和下载内容保存在案件的加密存储中；切勿在能够触及你真实身份的环境中打开目标的文件或 PDF。

隔离意味着用于 A 案的人设绝不在 B 案中使用。两个目标若互相交流——而同一生态系统的目标之间确实会如此——会从重叠处重建你的操作。数字、邮箱、代理和头像也是如此。

**切勿向属于目标的任何内容进行认证。** 不要是他们的门户、他们的 WiFi、使用从泄露数据中获取的凭据登录，也不要用于确认账户存在的"忘记密码"流程。这是开源研究与未授权访问之间的界限，且不会因为密码容易获取而移动。

## 出错的环节

- **登录失误。** 同事发送了一个链接，你用正常浏览器点击，目标者就知道了你的姓名。这是距离最远的烧毁中最常见的一种。改写共享 URL，并使研究浏览器在视觉上与正常浏览器明显区分。
- **并非隐私设置生效。** 匿名浏览模式能阻止*姓名*到达目标，但平台仍然掌握该信息，设置可能回退，且一些通知未覆盖。它们减少暴露，而非消除暴露。
- **联系人图推荐。** 你从未查看过该资料，却因为你的设备或人设触及了其联系人图中的某个号码或地址，而被推荐给对方，对方也被推荐给你。
- **案件进行中的验证质询。** 老龄化和稳定的出口能减少其发生；没有任何措施能消除它。应规划账户在 worst 时刻（最差时刻）失效。
- **你自身输出中的元数据。** 带有人名、主机名或内部路径的截图和报告，发送给客户。
- **关联你自身的人设。** 相同的头像生成器、相同的简介模板、相同的三个兴趣，在一个下午从一个出口 IP 制作而成。平台正正是针对这一点进行集群化的。
- **假设被动即不可见。** 服务器日志中的一行请求并无价值；跨百次的独特模式则成为签名。扫描器和 API 客户端携带自身的时间和头部指纹，其中一些会在服务端记录你的查询——了解你的出口流向何处。

## 评估你的暴露程度

任何收集操作之后，评估目标可能知道的内容。

- **干净** ——未触及目标受控基础设施：仅第三方档案、注册处和日志。
- **匿名联系** ——目标的服务器记录了一次携带你控制的 IP 和通用指纹的请求，除此之外无其他身份信息。
- **匿名身份联系** ——目标能看到一个人设：查看者条目、关注、通知。若人设保持干净且隔离，则仍可恢复。
- **归属** ——真实身份、雇主 ASN 或跨链接选择器触及了目标。立即停止，记录暴露了什么及何时，并告知案件负责人；被隐瞒的烧毁会变成对方首先发现的烧毁。

实时记录暴露事件及其时间戳。案件出错后试图重建是猜测，客户会要求你说明。

## 实例示例

**目标：** 供应商指定的 director 是否在行业论坛上活跃？对象是一个小型企业主，技术能力不复杂，但论坛属于小众，成员会注意到新账户。

**姿态：** 商业 VPN、专用浏览器配置、使用稳定集合中已有的、已老龄的人设——而非新建的，因为论坛的成员列表显示了入会日期。

关键在于死胡同：论坛直接拦截 VPN 的范围。与其升级工具，档案路线（`read-deleted-pages`）提供了缓存的帖子页面，其中包含所需的大部分内容，且完全没有联系。评级为干净。

仍需一个实时资料页面的问题：人设在论坛的运营时间从消费者连接而非 VPN 登录，查看该资料后离开。论坛没有"谁查看过"功能，因此暴露评级为匿名联系——并注明管理员仍可读取访问日志。

未完成：对同一人的专业网络资料查看，因为该平台会通知。它会回答的问题已放入报告的差距部分。一个被提示的对象比一个未被回答的次要问题代价更高。

## 转折点

OPSEC 是一个前提条件，而非选择器的生产者。在运行 `pattern-of-life-from-socials`、`hunt-a-handle`、`find-leaks-in-the-wild` 以及 `find-anyone` 或 `x-ray-a-company` 中的任何交互步骤之前先执行它。用 `find-the-original-image` 检查头像，用 `secrets-in-file-metadata` 清除上传，优先使用 `read-deleted-pages` 而非实时查看，并记录暴露事件，以便 `write-the-intel-brief` 能说明目标可能知道的内容。

## 法律与服务条款说明

明确说明：**伪造账户违反大多数平台的服务条款。** 准确信息要求几乎是普遍的，账户会被封禁，且封禁可能连同你的收集工作一并使账户失效。违反条款一般属于合同事项而非犯罪，但违反条款与未授权访问之间的界限因管辖区而异，且双方均已就此提起诉讼。请咨询律师，决定你的任务范围是否涵盖此类情况，并予以记录。

**冒充** **真实、可识别的个人**远比虚构人设严重——一些管辖区专门将在线冒充列为犯罪（加州刑法 § 528.5 是其中一个例子），且这会令你面临诽谤和民事索赔的风险。冒充**执法人员、政府官员或律师**在许多地方属于刑事犯罪，包括依据美国联邦法律，且没有任何调查任务范围涵盖此类行为。

此外：当用于收集关于在世人员的资料时，人设属于 GDPR 式制度下的个人数据处理，且人设自身的行为可归责于你的组织。见 [../../ETHICS.md](../../ETHICS.md)。若你无法以书面形式为使用人设进行正当性论证，不得创建它。
