# 不被盯上的调查

数据收集是双向的。大多数调查人员不是被一个聪明的对手烧毁，而是被一个平台按其宣传的那样做——告诉目标谁查看了他们的资料，建议调查人员给目标看他们可能认识的人，或者标记一个故事已被查看。默认的失败不是泄露的IP地址。它是在一个真实账户上登录。

## 首先考虑威胁模型

安全操作的努力应与任务相称。在花一天时间建立基础设施之前——或者在你决定不需要任何基础设施之前——回答三个问题。

1. **谁可能会注意到？** 一个休眠的壳公司，一个中等技术水平的个人，一个运行监控基础设施的犯罪团伙，或者一个国家服务。他们的能力设定了标准。
2. **他们会看到什么？** 被动收集：服务器日志中的一行。一个已登录的访问：你的名字。一个互动：你的角色及其历史。
3. **后果是什么？** 什么都没有，或者证据被销毁且账户被关闭，或者调查被归因于你的组织并公开，或者对你或来源构成人身风险。

| 情况 | 合适的姿态 |
|---|---|
| 注册表、档案、CT日志、法院记录 | 普通浏览器，没有角色。你是成千上万中的一员。 |
| 查看目标的公共网站 | 干净的浏览器配置文件，商业VPN，没有登录会话。 |
| 任何已登录平台对目标的查看 | 角色账户，专用配置文件，并首先检查平台的查看者通知行为。 |
| 目标运行监控基础设施或具有技术能力 | 专用虚拟机，非数据中心出口，没有重复使用指纹，时间纪律。 |
| 有组织犯罪、骚扰风险、人身安全在游戏中 | 上述所有内容加上分隔硬件，以及一个知道你在做什么的同事。 |

过度设计成本太高：一个锁定的设置会被CAPTCHA、速率限制和阻止，所以你收集得少，而且不寻常的配置本身就很特别。在需要融入的地方融入。在尝试安全查看某物之前，检查存档是否已经包含它（`read-deleted-pages`）——一个快照告诉目标什么。

## 你的归因表面

一个网站或平台可以从一次访问中学到什么：

| 表面 | 它会透露什么 |
|---|---|
| IP和**ASN** | 网络，而不是地址，是线索：数据中心ASN说“VPN或爬虫”，公司ASN说你的雇主的名字——最糟糕的结果，也很常见，因为人们忘记了办公网络是一个标识符 |
| 浏览器指纹 | 用户代理、窗口几何形状、字体、canvas和WebGL渲染、硬件并发性、时区——通常是唯一的，而且最重要的是，在会话和IP之间保持稳定，所以当其他什么都做不到时，它将你的访问链接到一起 |
| TLS指纹 | 客户端问候（密码套件、扩展、顺序）独立于浏览器暴露的任何内容识别你的客户端；这就是为什么在代理后面的工具与真实浏览器一样简单可分离——标题说Chrome，握手不是 |
| 语言和区域设置 | `Accept-Language`、时区偏移量、单位。一个英文区域设置的浏览器从第三国数据中心IP读取区域语言网站是难忘的 |
| 时间 | 只在一个国家的工 作时间内的活动，在其假期上的空白，在整点上的爆发。时间经受住你应用的每一个控制 |
| 链接预览 | 将目标URL粘贴到聊天、工单或文档中，该平台会获取它；获取会击中目标的服务器并与你的其他活动相关联。禁用预览或削弱URL |

**已登录的账户是最大的问题。** 身份验证将一个匿名请求转换为已识别的请求，泄漏是特性：资料查看通知和查看者列表，故事和视频查看列表，“你可能认识的人”建议由联系人列表和交互图驱动，已读回执，关注者和列表通知，互相关联的显示。有些在加载页面没有其他动作的情况下就会触发。

每个表面的检查、每个平台类别暴露的内容以及有帮助和不帮助的设置：[参考/归因表面.md](reference/attribution-surface.md)。

## 分离是绝对的

研究身份和真实身份永远不会接触。不是“大部分”——一次交叉将它们永久链接在一起，而且一旦平台将其关联起来，就无法撤销。具体的泄漏，大致按烧毁人们的频率排序：

- **一个用于短信验证的真实电话号码。** 最大的跨平台标识符；平台在其内部链接账户，并使用它来提供基于联系人的建议。一次验证将角色与你永远链接在一起，包括追溯。
- **一个属于你的恢复电子邮件**——或者另一个角色的电子邮件，将角色相互链接。
- **一个支付方式。** 任何卡、钱包或订阅，包括VPN。
- **一个重复使用的密码**，它在未来的泄露中暴露，并将你的账户聚集起来，任何人都可以购买转储——参见`what-leaked-about-you`。
- **一个同步的浏览器配置文件**，携带历史记录、自动填充和保存的密码进入研究环境。个人Cookie和会话做其余的事情。
- **一个可以反向搜索回你的头像**——或者任何人（`find-the-original-image`）。一个裁剪的个人照片、朋友的照片和股票图片都失败了，原因不同。剥离上传元数据（`secrets-in-file-metadata`）。
- **风格和习惯。** 一种独特的措辞，一个反复出现的拼写错误，固定的时间。
- **联系人列表上传。** 授予应用程序联系人访问权限，在曾经持有你真实联系人的手机上，平台获得了链接一切的有向图。

## 角色扮演

只有当观察确实需要一个账户时才建立一个，并且首先阅读下面的服务条款部分。一个全新的空账户既无用处又显眼：它看不到太多东西，而且它看起来就像它是什么，所以在你需要它的时候会被阻止、挑战或禁止。角色需要合理的背景和年龄，所以在需要它们的案例之前就创建它们，并让它们积累普通活动。维护一个小而稳定的角色，而不是每个调查一个角色。

连贯性是整个游戏：名字、区域设置、语言、时区、发布时间、兴趣和联系人都与其他人以及平台的统计数据一致。一个声称一个城市而在该城市的夜间时间表上发布角色的角色是一个人类立即注意到的矛盾。

逐步构建、标识符来源、老化计划和维护例程：[参考/角色运行手册.md](reference/persona-runbook.md)。

无论如何的硬限制：角色扮演是为了**观察**——不是为了诱出私人信息，诱使任何人采取行动，或以你没有授权的借口进入封闭的系统或群体。

## 网络出口

| 选项 | 适合 | 不适合 |
|---|---|---|
| 商业VPN | 隐藏你的ASN和大致位置，从普通网站；常见的默认值 | 任何阻止数据中心范围的内容；任何将“明显的VPN”本身作为信号的内容；信任提供者 |
| 居民/移动代理 | 出现为普通消费者连接；达到阻止数据中心的服务 | 成本、可靠性不稳定，以及一个严重的来源问题——参见下面 |
| Tor | 对网络观察者来说很强的匿名性；访问洋葱服务 | 角色扮演账户（出口节点是一个已发布的列表，所以预期会阻止、CAPTCHAs和账户安全挑战）；任何需要会话稳定性或地理可信度的事情 |
| 你自己的VPS | 控制和稳定性 | 是一个数据中心IP，可以追溯到计费身份，这通常比VPN更糟 |

Tor是这里最强的工具，但大多数时候是错的：出口地址是公开可枚举的，所以一个被监控的目标看到“有人使用Tor查看了这个”——比普通访问更具吸引力——并且平台将Tor登录视为高风险，触发杀死角色扮演的验证挑战。

居民代理值得一个特定的警告：许多池子是由通过捆绑SDK注册的消费者设备组成的，其用户没有实质性地同意，并且你的流量通过一个陌生人的家庭连接退出——这是一个道德问题，并且可能对你们双方都是法律问题。了解你的提供者如何为其池子提供来源，或者不要使用它。

验证你选择的内容：检查出口地址及其ASN，确认DNS通过隧道解析，并阻止WebRTC，它独立于它揭示地址。

## 环境和分隔

一个案例，一个环境。每个案例一个专用虚拟机是干净的答案；专用浏览器配置文件是最低限度。容器化标签隔离分隔Cookie，但不分隔指纹——一个便利，不是一个边界。在设置之间：永远不会登录任何个人账户；快照干净并在案例之间回滚；将笔记和下载保存在案例的加密存储中；永远不要在一个可以触及你真实身份的环境中打开目标的文档或PDF。

分隔意味着在案例A上使用的角色扮演永远不会在案例B上使用。两个比较笔记的目标——在一个生态系统中的目标会——从重叠中重建你的操作。数字、电子邮件、代理和头像也是如此。

**永远不要对目标所属的任何内容进行身份验证。** 不是他们的门户，不是他们的wifi，不是使用在泄露数据中找到的凭证的登录，不是“忘记密码”流程来确认账户是否存在。这是开源研究与未经授权访问之间的界线，并且不会移动，因为密码很容易找到。

## 哪里会出错

- **登录的失误。** 一个同事发来一个链接，你在正常浏览器中点击它，目标就有了你的名字。这是最常见的一种烧毁。削弱共享的URL，并使研究浏览器在视觉上有所不同。
- **不是隐私设置。** 匿名浏览模式阻止*名字*到达目标，但平台仍然有它，设置可以恢复，并且一些通知没有涵盖。它们减少了曝光，但没有消除它。
- **联系人图建议。** 你从未访问过该资料，但他们建议给你，你也建议给他们，因为你的设备或角色扮演触及了他们联系人图中的一个数字或地址。
- **案例中途的验证挑战。** 老化和稳定出口减少了它；没有什么能消除它。计划账户在最糟糕的时刻死亡。
- **你自己的输出中的元数据。** 屏幕截图和报告携带你的用户名、主机名或内部路径，发送给客户。
- **关联你自己的角色扮演。** 相同的头像生成器、相同的简介模板、相同的三个兴趣，在一个下午从同一个出口IP制作。平台在这一点上聚集。
- **假设被动意味着看不见。** 服务器日志中的一个请求什么都没有；一百个中的独特模式是一个签名。扫描器和API客户端携带它们自己的TLS和标题指纹，有些在服务器端记录你的查询——知道什么出口到哪里。

## 评估你的暴露

在每次收集操作之后，评估目标可能知道什么。

- **干净**——没有触及目标控制的设施：第三方存档、注册表和日志。
- **匿名接触**——目标的服务器记录了一个包含你控制的IP和常见指纹的请求。
- **假名接触**——目标可以看到一个角色扮演：一个查看者条目、一个关注、一个通知。如果角色扮演干净且分隔，则可恢复。
- **归因**——一个真实身份、雇主ASN或跨链接选择器到达了目标。停止，记录暴露的内容和时间，并告知案例负责人；一个隐藏的烧毁变成了对方首先发现的烧毁。

记录暴露事件，并附上时间戳。在案例出错后重建它们是猜测，客户会问。

## 工作示例

目标：供应商的指定董事是否在行业论坛中活跃？目标是小型企业主，技术不成熟，但论坛是利基的，成员会注意到新账户。

姿态：商业VPN、专用浏览器配置文件、一个现有的年龄角色扮演——不是一个新的，因为论坛的成员名单显示了加入日期。

重要死胡同：论坛直接阻止VPN的范围。与其升级工具，不如使用存档路线（`read-deleted-pages`）获得缓存的线程页面，其中包含大部分需要的内容，没有任何接触。评级干净。

仍然需要的一个问题：一个活着的个人资料页面。角色扮演从消费者连接而不是VPN登录，在论坛的工作时间内，查看个人资料，然后离开。论坛没有“谁查看”功能，所以暴露评级为匿名接触——附注管理员仍然可以读取访问日志。

未完成：同一个人的专业网络资料查看，因为那个平台会通知。它会回答的问题进入了报告的空白部分。一个被警告的目标比一个未回答的次要问题成本更高。

## 转折点

安全操作是前提条件，而不是选择器的生产者。在`pattern-of-life-from-socials`、`hunt-a-handle`、`find-leaks-in-the-wild`和`find-anyone`或`x-ray-a-company`中的任何交互步骤之前运行它。用`find-the-original-image`检查头像，用`secrets-in-file-metadata`剥离上传，优先选择`read-deleted-pages`而不是活访问，并记录暴露事件，以便`write-the-intel-brief`可以说明目标可能知道什么。

## 法律和ToS注释

说清楚：**假账户违反了大多数平台的服务条款。** 准确信息要求几乎是普遍的，账户会被封禁，封禁可能会带走你的收集。违反条款通常是一个合同问题，而不是犯罪，但违反条款和未经授权访问之间的界限是地域特定的，并且已经从两个方向进行了诉讼。与律师商议你的授权是否涵盖它，并记录它。

冒充一个**真实、可识别的人**比一个虚构的角色扮演更严重——一些司法管辖区专门将网络冒充定为犯罪（加利福尼亚刑法典§ 528.5是一个例子），并且它使你面临诽谤和民事诉讼。冒充**执法人员、政府官员或律师**在许多地方本身就是一种刑事犯罪，包括在美国联邦法律下，并且没有调查授权涵盖它。

此外：当用于收集活人时，角色扮演在GDPR式制度下是个人数据处理，并且角色扮演自己的行为可归因于你的组织。参见[../../ETHICS.md](../../ETHICS.md)。如果你不能在书面中证明角色扮演，就不要创建它。
