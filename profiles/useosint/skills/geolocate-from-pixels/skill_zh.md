# 从像素中定位

每张在户外拍摄的照片都包含足够的信息来定位它。限制因素从来不是图像本身；而是你的耐心和你的参考知识。

初学者的错误是在盘点之前就开始搜索。人们看到一座山，在搜索框中输入“两峰山”然后什么也找不到。方法是相反的：首先提取每一个线索，根据每个线索排除多少地球上的可能性来对它们进行排序，然后才开始搜索——因为锁定国家的线索通常不是你眼睛首先看到的那个。

## 在搜索前对线索进行排序

按此列表往下工作。每一行排除的世界范围远大于下一行，所以一个单一的一行线索值二十个六行线索。

| 等级 | 线索 | 它为你带来的价值 |
|---|---|---|
| 1 | 可读的专有名词——公司名称、街道名称、市政标志、学校名称 | 通常可以立即锁定。公司名称加上国家是一个地图查询，而不是调查。 |
| 1 | 标志和车辆上的电话号码 | 国家和通常城市，从前缀和数字组合同规中得知。 |
| 1 | 语言*和*文字，然后是正字法 | 文字缩小到一个家族；特定的变音符号、字母形式和拼写惯例缩小到一个国家和有时一个地区。 |
| 2 | 许可证格式——形状、颜色、条纹、字符布局 | 国家，通常是发行地区。从很远的地方就能看到，经压缩后仍然存在。 |
| 2 | 驾驶侧 | 将世界大致分为三分之一到三分之二。从停放的汽车方向盘上读取，而不仅仅是从交通中读取。 |
| 2 | 道路标记——中心线颜色、虚线节奏、边缘线 | 黄色与白色中心线单独就能排除大部分世界。 |
| 3 | 公用事业杆结构和绝缘器样式 | 区域内保守且很少改变。画面中最可靠的线索之一。 |
| 3 | 桥柱、护栏、人行道涂漆、人字形标记 | 国家标准化，国家特色。 |
| 3 | 交通信号安装、镜头排列、背板 | 顶部的与杆侧的，水平的与垂直的，额外的镜头——都是国家惯例。 |
| 4 | 标志字体和道路标志标准 | 一个国家采用哪种标志标准，以及它的特定字母。 |
| 4 | 卫星天线高度和方位角 | 限制纬度，轨道位置指示服务区域。 |
| 5 | 建筑、屋顶材料、窗户和阳台惯例、屋顶储水箱和加热器 | 地区和气候带。 |
| 5 | 植被和生物群落 | 纬度带、气候、半球。小心：装饰性种植是全球性的。 |
| 6 | 地形和地平线轮廓 | 只有当你有一个候选地区时才有用——然后它是决定性的。 |

每个变体及其含义：
[参考/区域指标.md](reference/regional-indicators.md)。

## 方法

1. **盘点。** 在搜索任何东西之前，写下帧中每个线索的编号列表。包括否定——没有雪、没有棕榈、没有架空线——因为否定同样能排除地区。放大每个标志、每个车辆、每个杆。运行 `find-the-original-image` 中的预处理配方来读取欠曝光或小细节。
2. **确定国家。** 结合你的等级一和等级二线索，直到它们一致。如果两个相互矛盾——西里尔字母标志与右舵汽车——那么这个矛盾就是一个发现：一个进口车辆市场、一个边境地区或一个合成图像。
3. **正确阅读文本。** 转录，然后翻译，然后在当地语言中逐字搜索转录内容。搜索翻译会失去匹配。如果文字不熟悉，在尝试字母之前先识别文字——格鲁吉亚语、亚美尼亚语、阿姆哈拉语、高棉语、泰语、老挝语和僧伽罗语经常被误认为是彼此的邻居。 |
4. **缩小到当地。** 命名的企业进入一个仅限于该国家的地图搜索。连锁店在反向中很有用：一个只在三个省份运营的连锁店排除了该国的其余部分。
5. **查询地图以获取几何形状，而不是地点。** 当你没有任何名称但有结构时——一个水塔旁边是一个铁路交叉口旁边是一个足球场——直接使用 Overpass 查询 OpenStreetMap 特征，而不是滚动。这是大多数人跳过的一步，也是最常起作用的一步。

```
[out:json][timeout:90];
area["ISO3166-1"="RO"]->.a;
nwr["man_made"="water_tower"](area.a)->.t;
foreach.t -> .w (
  nwr(around.w:400)["leisure"="pitch"]["sport"="soccer"];
  out center;
);
```

6. **在图像中确认。** 将候选者与卫星/航空*和*街道级来源进行匹配。比较不变量：建筑物足迹形状、屋顶颜色、窗户的数量和间距、人行道线、树木位置、围栏的确切排列。不要匹配会变化的东西——停放的汽车、遮阳篷、标志、植被密度。
7. **时间定位。** 太阳位置提供一天中的时间和日期带，从植被中获取季节，从天气存档中获取证实。程序在
   [参考/时间定位.md](reference/chronolocation.md)。
8. **评分。** 三个独立特征一致，或停止。

## 图像来源以及每个来源何时使用

| 来源 | 当你 |
|---|---|
| Google Earth (桌面) | 默认卫星工作。历史图像时间线是使用桌面客户端而不是浏览器的原因：它记录了建筑、拆除和土方工程。 |
| Google Street View | 默认街道级，在其覆盖的国家。时间机器功能为您提供同一地点的日期捕获。 |
| Yandex Maps 和全景图 | 俄罗斯、白俄罗斯、哈萨克斯坦、中亚、高加索、土耳其。全景覆盖和卫星细节在那里通常超过 Google 的，Yandex 的图像有时来自不同的日期，这本身就很有用。 |
| Mapillary | 群众来源的街道级。覆盖道路、轨道和国家 Street View 车辆从未驶过的地区。通常是农村地区和非洲、南亚和巴尔干半岛街道级图像的唯一来源。 |
| KartaView | 第二个群众来源的街道级集，具有不同的贡献者地理。当 Mapillary 为空时检查它。 |
| Bing Maps 航空和街道侧 | 不同的捕获日期，有时角度更好。斜视图有助于建筑高度。 |
| Apple Maps | Look Around 覆盖范围和主要城市的高质量 3D。 |
| Esri World Imagery，及其 Wayback 存档 | 版本化的历史底图图像——当 Google 的不足时，第二个独立的历代表。 |
| Copernicus/Sentinel 浏览器 | Sentinel-2 光学十米分辨率，重访时间以天计。对建筑物来说太粗糙，非常适合确定变化：火灾疤痕、洪水、新土路、已填满的水库。 |
| Landsat 存档 (USGS) | 三十米分辨率，但有多十年的记录。用于“这个采石场何时出现”。 |
| NASA FIRMS | 带时间戳的热异常检测。将火灾、火炬和大型爆炸日期精确到数小时。 |
| 解密的歷史图像通过 USGS EarthExplorer | 卫星时代之前的商业覆盖范围，用于非常古老的問題。 |
| 国家和市政正射影像门户 | 通常比任何全球提供者都具有更高的分辨率，并且有日期。搜索该国的地籍或测量机构查看器。 |
| OpenStreetMap 加 Overpass | 按特征类型查询，而不是浏览。也是许多小径、电线和微小结构的唯一来源。 |
| 从高程模型生成的全景图生成器 | 合成从给定坐标和方位角看到的地平线，用于山脊匹配。 |

## 这会出错的地方

- **确认偏差是这个学科的失效模式。** 你会找到一个看起来正确的建筑物，然后开始解释差异。在你看之前设定你的证伪标准：“如果左侧的杆子位于道路的错边，这个候选者就死了。” 然后遵守它们。
- **图像是有日期的，而你是在跨时间比较。** 一个消失的建筑可能已经被拆除；一个现有的建筑可能比照片新。检查图像的捕获日期，并在拒绝候选者之前检查历史时间线。
- **装饰性和引入的植被不断撒谎。** 桉树生长在五个大洲。棕榈树被种植在其原生范围之外。植被是一个五级线索的原因——它证实，它不决定。
- **全球品牌和特许经营标志几乎什么也告诉你** 除了公司运营的地方。一个无处不在的快餐标志不是一个线索；同一标志上的当地语言子品牌和电话号码才是。
- **压缩发明了细节。** 你在 JPEG 艺术效果级别上“阅读”的文本通常不存在。如果一个牌照或标志只有在升级后才能变得清晰，它是一个假设，而不是阅读。回到原始像素。
- **反射和镜子翻转一切。** 商店窗户中的文字，或者镜子中拍摄的场景，都会反转。镜像转发也会这样做。如果驾驶侧和文本方向不一致，在怀疑翻转之前怀疑国家。
- **照片不一定是同一个地方。** 合成图像存在，并且视频可以从几个地点的片段中剪辑。定位一个帧并不定位视频。独立验证帧，并将怀疑交给 `is-this-photo-real`。
- **边境地区和飞地破坏了单线索逻辑。** 标志、牌照、货币和基础设施在边境几公里内混合，并且在具有争议或过渡管理的领土内也是如此。
- **声称会改变你看到的东西。** 如果你被告知照片来自一个特定的城市，你会找到那个城市。尝试在阅读标题之前进行盘点，当你不能这样做时，假设标题说别的地方。
- **长焦压缩，广角拉伸。** 前景主题和背景山脉之间明显的距离是焦距的函数。不要判断“山有多近”，不考虑这一点。

## 置信度分级

- **确认位置**——一个至少有三个相互独立的非暂时性特征与参考图像匹配的特定坐标：例如建筑物足迹几何形状、公用事业杆的位置和数量，以及地形轮廓。要求是独立性——三个相同标志的照片是一个特征，而不是三个。你应该能够重现相机位置和方向，并声明米级半径。
- **可能位置**——正确的当地地点和一个合理的具体位置；两个独立特征匹配，或者三个匹配，但其中一个参考来源是未日期的或低分辨率的。表示为命名地点加上半径，而不是坐标。
- **仅限地区**——从等级一和等级二线索确定国家或省份，没有现场匹配。这是一个完全合理的結果，并且通常是一个案例所需的所有内容。说“在这个省份的某个地方”，而不是一个点。
- **未确认**——一个看起来正确的候选者，但依赖于暂时性特征、单个匹配元素或你自己的相似感。
- **排除**——你可以断定地排除所声称的位置。通常更容易更有价值地找到真正的位置；一个证伪只需要一个硬矛盾，例如驾驶侧。

始终报告与坐标一起的半径。一个裸露的六位小数坐标意味着你没有的亚米级确定性。

## 示例

一张图像被传播为对“在 A 国燃料库”的攻击。没有元数据。

盘点：白色中心线、右舵交通、混凝土公用事业杆，带有一个水平横臂和短小的棕色绝缘器、一个带有拉丁文字的警告标志，其变音符号在 A 国的语言中不存在、一个部分可读的商店标志、低矮的灌木植被、光秃秃的落叶树、阴影地面上只有雪块、左侧地平线上有一座山脊。

变音符号已经与声明矛盾——这是重要的发现。文字和正字法缩小到两个相邻的国家。杆和绝缘器样式与其中一个国家匹配。

商店标志 OCR 到一个片段。将片段作为公司名称搜索，得到一个连锁店，其分店在一个省份。在该省份内搜索燃料库的 Overpass 查询返回了十一个候选者。

第一个候选者在卫星视图上看起来是正确的——相同的油箱数量。被证伪测试杀死：接入道路来自错误的侧，山脊会在相机后面。死胡同，而且是一个好的死胡同，因为它很便宜。

第四个候选者基于油箱排列、围栏角落和从该视点生成的地平线轮廓匹配。来自附近道路的街道级群众来源图像显示了相同的杆线。

时间定位：阴影方位角和围栏柱的阴影长度比率给出上午中和与该视点一致的太阳高度角。阴影仅在阴影中，加上光秃秃的落叶树，选择晚冬带而不是早秋带。最近气象站的天气存档显示降水前几天有降水，那天早晨是晴朗的，一致。

结果：位置**确认**，100 米半径，在 B 国而不是 A 国。日期**可能**到两周窗口。时间**可能**，上午。

## 法律和道德注意事项

读取公共图像和公共地图数据是被动和合法的。两个限制是真实的。首先，从自己的发布照片中定位私人个人的家、学校或常规是跟踪的核心机制，技术令人印象深刻并不能使输出合法；为失踪人员工作、授权调查、威胁评估，或向某人展示他们自己的暴露，而不是其他。发布一个圆滑的位置或地区，而不是门口坐标。其次，在冲突工作中，发布精确位置可能会危及帧中的人或使他们成为目标。这两者都是你必须明确记录的判断。见
[../../ETHICS.md](../../ETHICS.md)。
