# 关于你的信息泄露情况

泄露数据回答了一个其他任何东西都无法廉价回答的问题：这个身份实际上使用了哪些服务。这个服务列表几乎总是比记录中的凭证更有价值，而凭证是绝对不能触碰的部分。无论泄露数据有多公开，使用泄露的密码都是未经授权的访问。

## 记录实际包含的内容以及重要信息

泄露记录是一个服务用户表中的一行。典型字段包括：电子邮件、用户名、密码哈希（或明文，在糟糕的情况下）、注册日期、最后登录时间、注册时的IP地址、显示名称、出生日期、实际地址、安全问题的答案，以及服务碰巧收集的任何其他信息。

元数据总是比凭证更有价值：

| 字段 | 为什么重要 |
|---|---|
| 服务名称 | 会籍本身。这个人在这里有账户——你几乎无法通过其他方式确定这一事实 |
| 注册日期 | 锚定身份的时间。跨服务的注册时间集群可以链接账户 |
| 记录中的用户名 | 你没有的用户名。直接进入 `hunt-a-handle` 搜索 |
| 注册或最后登录的IP地址 | 粗略的地理位置，更有用的是，主机与住宅分类 |
| 显示名称、出生日期、地址 | 用于在其他地方验证的身份属性。永远不要将其视为权威信息 |
| 密码 *模式* | 分析上的链接证据。永远不要将其作为登录表单的输入 |

逐字段解释：
[reference/record-fields.md](reference/record-fields.md)。

## 选择数据源

| 持有数据 | 选择 | 原因 |
|---|---|---|
| 一封电子邮件，需要服务列表 | Have I Been Pwned | 经过筛选、去重，命名了泄露事件及其数据类别。不返回凭证 |
| 一个你已持有的密码（你的或范围内的） | HIBP Pwned Passwords 范围 API | 告诉你密码是否在流通，但不泄露密码本身 |
| 需要实际字段值，或通过用户名、电话、IP或姓名搜索 | 商业服务 | 唯一能让你从检测会籍转向记录的方式 |
| 一个正在流传的特定泄露数据 | `find-leaks-in-the-wild` | 粘贴网站、论坛和频道，在它们被索引之前 |

**Have I Been Pwned** 是默认的起点。它是经过筛选的：泄露事件在加载前会经过验证，数据类别会被标记，所以一个匹配意味着有实际意义。免费网络查询电子邮件；API是经过筛选的，允许程序化和域范围的检查。它故意不提供密码。

**Pwned Passwords** 值得充分理解，因为其设计就是要点。你本地对密码进行 SHA-1 哈希，只将哈希的 **前五个十六进制字符** 发送到范围端点，然后你会收到所有共享该前缀的哈希后缀，以及出现次数。你本地进行匹配。服务永远不会知道你询问了哪个密码。这使得它适用于你合法持有的凭证，并且是自我审计或客户补救练习的正确工具。

**商业服务**—— DeHashed、IntelX 和 Snusbase 是常用的服务。它们之间的区别：

- 跨多种选择器进行记录级搜索，返回实际字段值。这是转换引擎：用户名、电话、IP 和姓名搜索，而不仅仅是电子邮件。
- 语料库广度与筛选。更广泛的语料库会摄取更多的组合列表，因此会摄取更多的垃圾；筛选的服务会遗漏一些东西。了解你的数据源位于哪一边。
- 一些索引文档、粘贴、暗网页面和泄露文件，而不是解析的用户表——更接近于泄露材料的搜索引擎，而不是泄露数据库。

## 没有例外规则

**永远不要使用泄露的凭证来认证任何东西。** 无论是“确认账户是否存在”，还是在测试账户上，还是在客户的口头许可下在目标账户上。凭证填充在大多数司法管辖区都是未经授权的访问，而密码的公开可用性不是抗辩理由——参见 [../../ETHICS.md](../../ETHICS.md)。

衍生操作也适用：不要尝试密码重置，不要使用恢复的安全问题答案，不要尝试在另一个服务上使用恢复的密码来测试重复使用。重复使用是你从已持有的数据中推断出来的，而不是你测试的东西。

## 真正的转换点：服务枚举

将泄露列表作为账户地图来处理。一个电子邮件出现在一个游戏论坛、一个健身应用和一个区域约会服务中，告诉你三个要调查的平台、三个注册日期，并且通常还有三个用户名——每个用户名都是 `hunt-a-handle` 的种子。服务本身定义了这个人的特征：专业、区域、语言和兴趣信号，这些信号是个人资料页面不会给你的。

密码模式在正确处理时是链接证据。如果两个不同身份的记录携带相同的独特密码——一个长、非字典、明显是个人化的字符串——那就是有意义的关联，你将字符串本身脱敏或哈希在你的笔记中记录为分析观察。一个常用密码（`password1`、键盘行走、足球队）链接不到任何地方；成千上万的人共享它。独特性是整个信号，证据是巧合，而不是凭证。

## 哈希不在范围内

记录通常包含哈希：旧泄露中的 MD5 或未加盐的 SHA-1，新泄露中的加盐方案和专门构建的密码哈希。你偶尔会看到明文，因为服务没有对其进行哈希存储，以及可逆加密，因为有人选择不当。

注意哈希类型——它记录了泄露事件的时间，并描述了服务的安全态势，这在尽职调查背景下确实有用。然后停止。破解哈希会产生你不允许使用的凭证，所以这项工作没有合法的输出。例外情况是自我审计或授权的安全评估，其中密码持有者是你的客户，即使在这种情况下，范围 API 也能在不破解任何东西的情况下回答问题。

## 哪里会出错

- **组合列表污染。** 流传的大多数大型“泄露”都是组合列表：来自多个来源的凭证聚合，去重、重新排序，并去除来源。组合列表中的匹配告诉你一对凭证出现在某个地方，而不是来自哪个服务。这破坏了服务枚举的价值，这就是要点。
- **回收和编造的泄露。** 旧数据被重新包装在新的名称下出售，作为新鲜数据。一些“泄露”完全是编造的，或者是公开资料的抓取，被当作黑客攻击进行营销。检查所谓的来源是否曾经承认过事件，以及记录结构是否与该服务可能存储的内容相匹配。
- **泄露日期不是泄露日期。** 三个日期很重要：数据被窃取的时间、首次流通的时间以及你的数据源摄入的时间。它们可能相差数年。“出现在 X 日期的泄露中”表明账户在 X 之前存在，而不是当时活跃。
- **不存在证明不了任何东西。** 任何语料库中都不出现意味着这个人的服务没有被泄露，或者泄露没有被发布，或者你的数据源不包含它。
- **抓取与泄露的混淆。** 通过抓取公共资料汇编的数据集不是泄露的证据，将其报告为泄露是事实错误，会损害报告的可信度。
- **陈旧的归属。** 电子邮件地址和电话号码会被放弃和重新分配。一个十年前的记录可能描述的是完全不同的人。
- **供应商重叠冒充确认。** 两个商业服务频繁同意通常意味着它们摄入了同一个泄露。

## 置信度分级

- **确认**——记录出现在经过筛选的来源中，该来源验证并归属了泄露事件，字段结构与命名服务匹配，并且记录中的第二个选择器独立验证。
- **可能**——来自信誉良好的商业语料库的记录，有明确的归属到命名服务，并且字段内部一致。
- **未确认**——组合列表匹配、未归属的泄露或记录中的单个行没有验证选择器。报告匹配的存在，并明确说明来源未归属。
- **拒绝**——所谓的来源没有合理的事件，字段与该服务收集的内容不匹配，或者数据是重新标记的公开抓取。

评估 *泄露*，而不仅仅是记录。一个良好归属的泄露使其中的每一行都更具可信度；一个匿名的汇编使每一行都更不可信。

## 实例分析

对客户使用 `a.mercer@example.com` 的自我审计。HIBP 返回四个泄露。一个是几年前的论坛大泄露，列出的数据类别为电子邮件地址、用户名、IP 地址和密码哈希。

该泄露中的用户名是 `merce_ada`，客户已经忘记了使用。这个用户名通过 `hunt-a-handle` 搜索，发现了两个客户不知道仍然公开的账户——这是这次练习最有价值的输出，与凭证无关。

死胡同：一个商业源返回第五个“泄露”，归因于一个零售商，其中包含家庭地址。该零售商从未公开过事件，字段布局不像零售订单表，并且相同的地址出现在两个数据经纪人记录中。评估为抓取聚合数据重新标记为泄露。从报告中排除，并记录理由。

补救措施：客户仍然使用的密码通过 Pwned Passwords 范围 API 进行检查，因此没有密码离开机器。任何记录中的凭证都不在任何地方使用。

## 法律和处理说明

持有泄露数据是受监管的，并且比大多数 OSINT 材料更严格。根据 GDPR 和英国数据保护法，泄露记录是个人数据——通常是特殊类别数据——处理它们需要合法依据、定义的保留期限和可证明的数据最小化。一些司法管辖区将持有某些被盗数据本身视为一种罪行，无论你如何获得它。几个商业服务通过许可证将其数据限制在特定目的；在将结果放入客户报告之前，请阅读条款。

实际上：提取实现目标所需的最小字段，完全不保留凭证，将案例材料加密存储，并记录初始时制定的删除计划。如果你为目标本人处理其自己的数据，这是最干净的立场——并且这是测试密码的唯一适当立场。
