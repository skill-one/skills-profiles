# 深入数据中介机构

人脉搜索网站将公共记录、营销数据和自报数据混合后转售。它们是快速、廉价的线索生成器，但却是糟糕的证据。唯一重要的规则：**中介记录是线索，永远不会是事实。** 确认你打算使用的每个字段是否来自中介获取的原始来源——如果你无法识别该原始来源，就不要使用该字段。

## 这些服务实际上是什么

三种输入流，混合后出售：

- **公共记录**——房产契约、法院文件、企业注册、公开的选民名单、专业许可证、破产记录、婚姻和离婚。在原始来源处具有权威性；中介的副本是过时的转录。
- **营销和商业数据**——保修卡、忠诚度计划、订阅、信用头数据、在线表格、广告交换。从未经过验证，通常被推断，经常是家庭级别的而不是个人级别的。
- **自报和抓取**——个人资料、简历、论坛帖子以及中介自己用户输入的任何信息。

它们也相互购买，不断进行。这是该类别最重要的结构性事实：一个错误记录会传播到每个品牌，并且交叉检查五个中介会给你五个戴着不同帽子的同一错误副本。跨中介的明显相互印证几乎毫无价值。

## 数据为何错误

- **地址历史在实践上是仅追加的。** 中介添加地址并很少将其注销，因此“当前地址”通常是几年前的地址。
- **家庭合并。** 住在同一地址的两个人，或者在一个大都市地区具有相同姓名的两个人，会被融合成一个个人资料。同名亲属——父亲和儿子、同名堂兄弟——不断合并。
- **亲属是推断的，而不是记录的。** “亲属”和“关联人士”列表通常是地址共存：以前的室友、房东和以前的住户会作为家人出现。
- **年龄是派生的。** 通常来自信用头中的出生年份或选民名单，并且通常相差一年或显示为年龄范围。
- **电话数据老化最快。** 号码可移植性和预付费客户流失意味着运营商和线路类型归属会迅速衰减——参见 `whose-number-is-this`。
- **更正不会传播。** 让一个中介修正记录并不能修正上游来源或下游的六个购买者。

## 筛选：首先应该查找什么

| 你持有的信息 | 比中介更好 | 使用中介用于 |
|---|---|---|
| 姓名 + 城市 | 当地房产和法院记录、公开的选民名单 | 生成一个候选地址列表以与这些记录进行核对 |
| 电话号码 | 通过 `whose-number-is-this` 进行运营商/线路类型查询 | 逆向查询候选姓名，然后在其他地方确认 |
| 电子邮件地址 | `what-an-email-reveals` | 逆向查询候选姓名 |
| 姓名 + 需要亲属 | 讣告——远更准确并且声明了关系 | 第一轮家庭聚类以与讣告进行测试 |
| 姓名 + 需要就业 | 专业网络、许可证委员会、企业注册 | 什么也不做。中介的就业数据是他们出售的最糟糕的字段 |
| 姓名 + 需要资产 | 房产登记、法院判决、`who-really-owns-it` | 什么也不可用 |
| 你的姓名（自我审计） | 什么也不做——中介就是目标 | 在选择退出之前列举你的风险敞口 |

诚实的总结：中介用于在没有任何其他信息的情况下将姓名转换为候选选择器，以及审计你自己的足迹。对于你打算发布或依赖的每个声明，都必须去原始记录。

## 方法

1. **首先锚定。** 不要运行裸名。将来自 `find-anyone` 的区分锚点带入每个搜索，并将任何未通过锚点测试的结果视为不同的人。
2. **故意搜索少数中介**，而不是所有中介。选择具有不同上游来源的中介，而不是不同品牌的中介。
3. **提取选择器，而不是结论。** 你需要候选地址、电话、电子邮件、中间名、年龄范围和关联姓名。每个都是要测试的线索。
4. **将每个字段与原始来源进行确认。** 地址→房产或法院记录。年龄→选民名单、许可证记录或带有出生日期的文件。就业→雇主或注册。亲属→讣告或民事登记索引。
5. **记录你确认的字段和放弃的字段。** 一个经过确认的中介字段现在引用原始来源，而不是中介。
6. **将确认的选择器**转向下表中的技术技能。

按司法管辖区和记录类型划分的原始来源目录，以及访问和法律说明：[reference/source-catalogue.md](reference/source-catalogue.md)。

## 免费套餐诱饵模式

商业模式是一个诱饵。预期：结果页面确认存在匹配项，但字符被屏蔽；计数（“8个电话号码，12个地址”）旨在暗示深度；填充中介未付费的公共数据；进度动画暗示实时搜索，实际上是结账漏斗；报告作为自动续订的订阅，具有尴尬的取消路径；以及为不存在的姓名提供结果，因为漏斗无论如何都在运行。

永远不要将诱饵计数视为证据，并假设任何付费套餐都会计费，直到你主动停止。一些中介确实提供真正的调查员或商业套餐，具有合同使用限制——这是不同的产品，你必须在签署时同意其中的义务。

## FCRA 和实际约束你的规则（美国）

在美国，在看起来相同的两件事之间存在法律界限：

- **消费者报告机构** 根据《公平信用报告法》进行监管。它必须维护准确性程序，赋予消费者访问和争议权，并且只能出于允许的目的提供报告。
- **数据中介/人脉搜索网站** 不是 CRA，在其条款中否认遵守 FCRA，并且没有任何这些义务。

规则：**你不能使用非 FCRA 中介数据来做出关于就业、租赁、信用或保险的决定。** 这包括筛选求职申请人、审查租户或检查你即将雇佣的承包商。如果决定受 FCRA 覆盖，你必须通过受监管的 CRA 并遵循其程序，包括通知和不利行动要求。中介自己的条款会说这一点；这不是装饰，并且中介和用户都已成为执法的对象。这是否则合法的调查员产生实际责任的最常见方式。

值得了解的相关美国限制：机动车和驾驶员记录根据《驾驶员隐私保护法》限制为列举目的，并且一些州限制选民名单的使用仅限于选举目的。

## GDPR 和英国/欧盟立场

美国式人脉搜索市场在欧洲几乎不存在，并且现有的数据也更为稀薄。持久的原因：聚合和发布个人数据需要合法依据，而“我们购买”不是之一；透明度义务要求告知数据主体你持有他们的数据，这对抓取聚合业务是致命的；特殊类别数据更严格；并且主体拥有访问、更正、删除和反对权，这些权利易于行使且服务成本高昂。选举登记册、土地登记册和法院记录与美国的对应物相比受到相应的限制。

如果你在 GDPR 范围内，*你的* 案卷也是处理。你需要合法依据、保留期限，并且在主体询问你持有哪些信息时提供有说服力的答案。合法利益是可行的，但需要文档化的权衡测试。

## 自我防御：审计并删除你自己的暴露

对于大多数人来说，这项技能最有价值的使用。运行你自己通过主要中介，记录每个个人资料 URL，然后处理每个退出选项。需要了解：

- 退出选项是按中介划分的，故意繁琐，并且通常需要首先找到你自己的个人资料 URL。一些需要电子邮件确认；一些需要身份文件，这本身就是一种风险。
- 删除会失效。中介会从上游重新获取数据，因此删除的个人资料在刷新周期后会重新出现。这是定期维护工作，而不是一次性工作。
- 付费删除服务自动化了跨多个中介的繁琐工作；它们无法触及没有退出选项的中介，并且它们不会触及底层的公共记录。
- 司法管辖区有帮助。加利福尼亚州制定了中介注册要求和一个法定删除机制，旨在让居民一次性向注册中介请求删除；佛蒙特州维护一个中介注册册。法定权利比每个网站表单更持久——使用它们。
- 上游来源是真正的修复：针对高风险人群的地址保密计划、退出英国公开选举登记册、通过实体持有财产都是结构性而非表面的。

## 搜索你自己会留下痕迹

假设你运行的每个搜索都被记录、出售，并且可能可见。

- 中介搜索针对你的账户、IP 和支付身份进行记录，并且搜索本身是中介可以出售的数据。
- 一些专业和社会平台通知主体你查看了他们的个人资料，或者通过联系人图推断向你展示——上传联系人列表是调查员最常被卷入的方式。
- 一些付费和调查员套餐通知主体或生成他们可以访问的记录；信用头产品会留下查询轨迹。
- 从你自己账户搜索你的姓名会创建你和你标识符之间最强的关联。

在处理敏感事务之前使用 `investigate-without-getting-made`。最低限度：一个单独的浏览器配置文件，不重复使用账户，并且永远不会在注册表单中使用案件的真正联系信息。

## 哪里会出错

- **重复带来的信心。** 五个中介，一个上游供应商，一个错误。
- **合并的人被呈现为一个人。** 个人资料看起来连贯，因为合并是看不见的；两个位于互不连接地区的地址集群是线索。
- **已故主体。** 记录会持续存在，并且有时会与同名在世亲属合并——这是一个特定且有害的失败。
- **近期错觉。** “最后更新”反映中介更新其副本的时间，而不是底层事实为真的时间。
- **美国以外的覆盖范围崩溃。** 在美国以外很薄甚至不存在；对于非美国主体没有结果意味着什么也不确定。
- **移动和年轻人群代表性不足。** 租房、经常搬家、最近移民或从未持有房产或固定电话的人在这些数据集中系统性地稀疏。稀疏结果是抽样偏差。
- **被抑制的主体。** 已经退出的人或已经加入地址保密计划的人会产生一个干净的结果，这并不能证明任何事情。

## 置信度分级

- **确认**——该字段由一个原始记录（契约、法院文件、许可证、注册）证实，该记录命名了你的主体并且与你的锚点匹配。引用原始记录；中介完全退出链条。
- **可能**——由一个独立的非中介来源证实，锚点匹配并且没有冲突记录。
- **未确认**——仅在中介上出现，无论多少。报告为带有锚点基础的线索。
- **拒绝**——未通过锚点测试，或与原始记录冲突。将其保留在分配给不同候选人的文件中。

永远不要因为更多中介同意而将声明评级更高。

## 实例分析

对判决债务人进行跳线追踪：姓名加上最后一个已知城市。

1. 两个中介返回一个个人资料，其中包含四个跨越两个州的地址、47 岁的年龄和六个“亲属”。
2. 锚点测试：债务人的已知雇主城市仅与四个地址中的两个匹配。其他两个指向候选 B 文件。
3. 县记录员在匹配的县显示，在主体姓名下有一个契约，三年前出售。地址 2 已确认是历史的而不是当前的——中介将其显示为当前的。
4. 死胡同：一个具有独特姓氏的“亲属”通过实际亲属的讣告发现是地址 2 的前任住户。被放弃。
5. 地址 1 没有房产记录。中介在此处的效用是将四个地址缩小到有一个真实文件背后的地址；其他一切都是噪音。
6. 确认的选择器——一个以前的地址、来自契约的中间名——进入当前服务地址的法院文件。

## 法律和 ToS 注意事项

抓取这些网站违反了它们的条款，并且大多数网站都部署了主动的反自动化措施；商业套餐的存在正是为了向你出售 API。个人数据的批量收集根据你所在位置和数据的法律，在计算机滥用和数据保护法下具有自己的风险。不要使用非 FCRA 数据进行 FCRA 覆盖的决定。除非你有文档化的合法依据——法院命令、跳线追踪授权、活跃调查——否则不要使用中介数据来定位已经采取措施无法找到的人。在开始之前，请阅读 [../../ETHICS.md](../../ETHICS.md)。这个类别是诽谤和跟踪的原始材料，同样的查询在开始时完全合法或犯罪，完全取决于你开始时写下的目标。
