# 找到原始图像

目标几乎绝不是“找到匹配项”。**目标是找到最早的发布并阅读其页面**。匹配项只能告诉你该图像存在于其他地方；而最早的页面能让你看到摄影师、日期、说明文字和人物姓名——这才是你实际需要转向的依据。

**初学者的错误**：将全画面上传到一个引擎，没有结果，便得出该图像未被索引的结论。将图像裁剪至一个独特物体并重新搜索，能找到全画面搜索无法找到的内容。

## 根据你手中的图像选择合适的引擎

| 你拥有的 | 从...开始 | 原因 |
|---|---|---|
| 面部图像 | Yandex | 其索引建立在面部相似度之上，因此会返回长相相似的不同人**以及**其他照片中的同一个人。其他通用引擎无法做到这一点。 |
| 面部图像，且 Yandex 失败 | 专用的面部引擎（见下文） | 在解决法律与授权问题之后。 |
| 北美/西欧以外的街道场景 | Yandex | 深度索引了俄罗斯、中亚、东欧、土耳其和中文网络内容，而这些内容通常被 Google 抓取不足。 |
| 产品、书封、艺术品、植物、动物 | Google Lens | 物体与实体识别，并与购物和知识图谱绑定。 |
| 图像内的文字 | Google Lens | 它进行图像 OCR，并让你能搜索提取出的文字。通常文字才是答案，图像搜索并不相关。 |
| 地标或著名建筑 | Google Lens | 地标分类是其最强的单项功能。 |
| 杂乱照片中的特定区域 | Bing Visual Search | 在已上传的图像上画出框，它便会仅重新搜索该区域——这是任何引擎中速度最快的裁剪重试循环。 |
| 新闻照片、表情包，或任何你怀疑是旧的物品 | TinEye | 唯一可按时间最早排序、并能可靠地呈现*修改版*副本的主要引擎。 |
| 中文或中国托管的内容 | 百度图像搜索 | 其他引擎所不具备的覆盖范围。 |

至少运行三个。它们的结论会频繁出现分歧，而这种分歧就是信息：TinEye 找出几年前的一份精确副本，而 Lens 仅找到最近的转发，这是媒体被重复利用的显著特征。

### 各引擎实际实现的功能

**Yandex** 基于视觉相似度匹配，并带有较强的面部组件。其结果页面将“包含该图像的站点”与“相似图像”分开分组——只有第一组是证据。它对裁剪、旋转和重度重新压缩的容忍度比其他引擎更好。

**Google Lens** 已从全图像重复匹配转向“这是什么，以及我能为你提供什么”。若进行溯源工作，请使用列出包含该图像的选项，而非视觉匹配轮播，并预期它会将视觉相似但不相关的照片当作匹配项返回。

**Bing Visual Search** 处于两者之间。其区域选择工具是使用它的原因：无需下载、裁剪、重新上传的循环。

**TinEye** 基于爬取，且索引规模相对较小——许多图像返回零结果，且缺失于 TinEye 并不能证明任何东西。它所独有且其他引擎不具备的功能：精确与近似重复匹配、可按时间最早排序的能力，以及检测被裁剪、变色或添加水印的副本，并能将它们与输入内容并排展示。

## 方法

1. **修正输入素材。** 获取你能获得的最高分辨率副本——是文件本身，而非其截图。截图会带来尺寸调整与重新压缩，这会消耗你的匹配机会。暂时不要剥离任何内容；在开始编辑副本前，对原始素材运行 `secrets-in-file-metadata`。
2. **全画面，使用全部引擎。** 廉价，有时瞬间完成。
3. **裁剪并重新搜索。** 这是整个技能中收益最高的步骤。全画面的指纹主要由背景主导；将图像紧密裁剪至面部、招牌、logo、车辆、纹身、建筑角落等，并分别搜索每一个裁剪区域。转发内容会被裁剪并重制构图，因此当原图无法匹配时，裁剪后往往就能匹配。
4. **水平翻转。** 镜像是对抗自动化匹配的常规手段，也是录屏与视频转发的常规产物。翻转后重新运行相同的引擎。
5. **对低质量输入进行预处理并重试** —— 放大、去噪、校正明暗。参见 [reference/preprocessing.md](reference/preprocessing.md)。
6. **针对视频，提取关键帧并将其作为静图进行搜索。** 搜索起始、中间和结尾的帧，以及任何包含招牌或面部的帧。关键帧命中通常能突破视频案件。
7. **按时间最早排序。** 在 TinEye 上按时间最早排序。随后将该日期视为上限而非结论，并进入第8步。
8. **阅读匹配页面。** 打开它们。提取：摄影师署名、机构、说明文字、具名人物、页面内日期、图像 URL 中的文件名（通常为 `2019-04-city-event-03.jpg`），以及任何周边文章文字。这是选择器所在之处。

## 确定首发而非仅匹配

最早的已知副本日期是对你的搜索覆盖范围的主张，而非对世界的主张。若要加固该结论：

- 将匹配页面的日期与 `read-deleted-pages` 核对——该归档对 URL 的首个抓取，界定了页面真正存在的时间范围，且页面显示的日期可能因其内容管理系统（CMS）的原因存在超前或滞后。
- 通过 `google-like-a-spy` 使用有时间限制的搜索运算符，查找同一事件或说明文字更早的文字提及。
- 寻找同图的大分辨率版本。最大版本通常最接近原始来源；通讯社的版本会比 Twitter 的转发版本更大。TinEye 的最大图像排序在此非常有用。
- 检查显而易见的素材库。一张因三个不同国家的新闻事件而获署名的照片属于素材库，其“原始”版本只是一个授权页面。
- 画面中的水印和机构标识优于任何索引。裁剪水印后仅单独搜索。

## 专用人脸引擎及其使用禁忌

Pimeyes 和 FaceCheck.ID 在开放网络上爬取面部信息，并基于生物特征相似度进行匹配。它们能找到普通引擎无法找到的人。但它们也伴随着真实的风险：

- 在 GDPR 第9条下，面部模板属于**生物特征数据**——这是一个需要明确合法依据、而非仅凭正当利益即可覆盖的特殊类别。伊利诺伊州 BIPA 与得克萨斯州 CUBI 会为在未经书面同意的情况下收集生物特征标识者创设私人诉权及法定损害赔偿。
- Pimeyes 的自身条款将其定位为用于搜索**你本人**面部的工具，并提供退出选项。无论你的意图如何，运行第三方的面部图像经过它都属于违反该条款。
- Search4Faces 索引俄罗斯社交平台上的面部信息，当主体的足迹涉及 VK 或 Odnoklassniki 时，这是务实的选项。

当**你**拥有有据可查的授权或正当的保护目的时，使用人脸搜索——例如，在欺诈案件中核验对方、经主体同意进行身份验证、失踪人员工作，或核查自身可能面临的暴露风险。切勿用于从照片中识别陌生人、为抗议人群中的面部附上姓名，或定位私人个体。在案卷中记录你执行了该项操作及其原因。并且将人脸引擎的命中结果视为**未确认**——类同误报很常见，且引擎无法提供供你审计的推理依据。

## 此方法可能出错的地方

- **相似并非相同。** 每个引擎都将“包含该图像的页面”与“看似该图像的图像”混入同一视觉网格中。只有第一项才是证据。通过打开候选页面并对比像素级细节来确认——如手的位置、布料褶皱、倒影。
- **缺失是默认状态，而非发现结果。** 未索引、新发布、需登录访问以及仅限应用的图像均无返回结果。“四个引擎均无结果”意味着该图像不在这些索引中，这既不能作为原创性的弱证据，更与真实性毫无关联。
- **库存照片会破坏归属认定。** 一张出现在四十个不相关站点上的“CEO”证件照是库存模型，使用它的实体很可能为伪造——这本身就是一个发现，且是一个很好的发现。
- **AI 生成的图像无法寻找原始出处。** 零匹配加上生成特征提示是截然不同的结果；应将其交由 `is-this-photo-real` 处理，而非断定该照片为未公开发表的原始图像。
- **引擎会改写历史。** 结果不可复现：索引会删除页面，结果会重新排序，你上周找到的命中可能已消失。在找到结果时立即截图结果页，并将匹配 URL 归档。
- **裁剪在另一个方向会误导。** 裁剪草或天空会返回成千上万令人确信却毫无意义的匹配。裁剪到*不寻常*的内容，而非仅仅存在的内容。
- **你可能会泄露信息。** 将客户的图像上传至商业引擎会向该供应商披露信息，并可能导致您的利益被匿名化处理。对于敏感素材，搜索可省略识别细节的裁剪，或者干脆不搜索。参见 `investigate-without-getting-made`。

## 置信度分级

- **已确认原始来源** —— 你拥有在找到的其他所有副本之前发布的页面，且由可信的原始创建者（摄影师、机构、主体自身账号）托管，页面内日期得到独立归档抓取的印证，且不存在更大或更早的版本。
- **高度可能** —— 最早副本在多个引擎中一致，且托管方可信，但日期仅基于页面自身的声称，或该归档无该时期的抓取记录。
- **仅匹配** —— 你能证明该图像在给定 URL 和给定日期出现。务必明确表述这一点。切勿将其升级为“原始图像”。
- **未确认** —— 仅有视觉相似而无像素级验证，或人脸引擎命中，或单一引擎的结果你无法复现。

## 实际案例

某账号发布了一张配文为“今早警方突袭，[城市]”的照片。

Lens 全画面搜索：仅有通用的暴乱警察素材。Yandex：有十几张类似警察照片，但都不匹配。TinEye：无结果——我将其标注为信息无意义，因为 TinEye 的索引规模较小。

将图像裁剪至肩部区域，并用 Bing 的区域选择功能重新搜索。结果显示该画面来自另一个国家的地方执法部门，而非配文所声称的。

裁剪背景中的店铺招牌，在 Lens 中进行 OCR，并以文字形式搜索企业名称。得到两个命中，均位于该国街道。图像搜索本身陷入死胡同——但*文本*的转换方式找到了目标。

回到 Yandex 并使用店面裁剪：一张三年前的新闻画廊，同样的街道，同样的店铺遮阳棚，同样的隔离带布置。署明了摄影师。归档显示该画廊页面在所述日期两天后已有一份抓取记录，这予以印证。

结论：**已确认**该图像在声称的事件发生数年之前，于另一国家发布。这是重新语境化，而非虚构。将位置交由 `geolocate-from-pixels`，将摄影师署名交由 `find-anyone`。

## 关键转换

| 你获得的 | 发送至 |
|---|---|
| 位置、街道场景、店面 | `geolocate-from-pixels` |
| 具名人物、摄影师署名 | `find-anyone` |
| 发布站点或机构域名 | `who-owns-this-domain` |
| 已消失或改动的匹配页面 | `read-deleted-pages` |
| 说明文字、企业名称、文件名标识 | `google-like-a-spy` |
| 怀疑被操纵或生成的图像 | `is-this-photo-real` |
| 发布账号、被复用的头像 | `hunt-a-handle`, `pattern-of-life-from-socials` |
| 完整的照片/视频定位案件 | `where-was-this-taken` |
