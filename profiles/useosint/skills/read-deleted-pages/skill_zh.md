# 查读已删除页面

存档之所以有效，是因为删除是在发布之后做出的决定。初学者的错误是将“互联网档案馆”当作一个可以浏览的网站：日历界面一次只显示一个页面，而CDX API会枚举存档在某个主机下曾经看到过的所有URL，包括那些无人记得的路径。

## 首先查询哪个存档

| 情况 | 前往 | 原因 |
|---|---|---|
| 现在返回404的URL | 互联网档案馆，然后archive.today | 不同的数据集，不同的删除压力 |
| “X之前这个网站说了什么” | 带有`collapse=digest`参数的Wayback CDX | 显示内容变更的日期，而不是每次捕获的记录 |
| JS密集型页面或社交帖子 | archive.today | 捕获渲染后的DOM；Wayback通常只回放一个空壳 |
| Wayback表示URL被排除 | archive.today，然后Common Crawl | 两者都无法回答Wayback的排除流程 |
| 你不知道的路径和子域名 | 带有`matchType=domain`参数的CDX | 它是一个枚举工具，不是查询工具 |
| Wayback从未捕获过的URL | Common Crawl | 独立爬虫，不同的种子 |
| 区域性或国家顶级域名内容 | Memento聚合器，然后国家存档 | 一些国家存档提供全文搜索 |
| 你无法失去的证据 | 自己捕获，然后提交给两个存档 | 没有人为你保留它 |

每个来源的覆盖范围和删除政策：
[reference/archive-comparison.md](reference/archive-comparison.md)。

## CDX API才是实际工具

CDX服务器索引捕获记录——每条记录对应一次捕获——并允许你过滤、合并和枚举它们。主机下爬虫曾经看到的每个URL，去重后：

```bash
curl -s 'http://web.archive.org/cdx/search/cdx?url=example.com/*&output=json&fl=original&collapse=urlkey' \
  | jq -r '.[1:][] | .[0]' | sort -u
```

使用`output=json`而不是默认文本：它能够保留包含空格和引号的URL，而文本格式会破坏它们。第一个JSON行是列名的标题，不是捕获记录——因此使用`.[1:]`。

四个参数几乎完成了所有工作：

- **`matchType`** — `exact`（精确匹配）、`prefix`（前缀匹配）、`host`（主机匹配）或`domain`（域名匹配）。`matchType=domain`返回主机及其所有子域名，常规情况下会暴露已从DNS中消失的测试、遗留和内部主机。将它们带到`find-hidden-subdomains`。
- **`filter=<field>:<regex>`**，可使用`!`进行反转，并可组合使用。过滤到`statuscode:200`以捕获返回内容的捕获，或使用`!mimetype:text/html`以隔离文档、存档和配置文件。
- **`from`/`to`** 接收任何精度的时间戳前缀——`from=2019`、`from=201903`——因此你可以围绕已知事件划定窗口。
- **`collapse`** 抑制共享相同字段的相邻行。`collapse=urlkey`是枚举的惯用方法；`collapse=digest`最为重要。

`digest`对捕获的负载进行哈希处理，因此`collapse=digest`将页面的历史记录减少到内容实际发生变更的捕获。四百次捕获会变成六行，这六天就是故事。

```bash
curl -s 'http://web.archive.org/cdx/search/cdx?url=example.com/about/team&output=json&collapse=digest&fl=timestamp,digest,statuscode'
```

完整参数、分页和现成的枚举流程：[reference/cdx-cookbook.md](reference/cdx-cookbook.md)。

## 回放不是捕获

`web.archive.org/web/<timestamp>/<url>`处的页面是重建的。存档会注入工具栏，将链接和资源引用重写回存档，并且——误导人的部分——从每个资源最近的捕获中拉取资源，这可能距离你请求的HTML有几个月之遥。你截图的渲染页面可能从未存在过。

在时间戳后追加`id_`以获取原始存档响应，不包含注入和重写：

```bash
curl -s 'https://web.archive.org/web/20190412093000id_/http://example.com/pricing' > pricing-2019.html
```

使用`id_`来解析、哈希、差异或引用任何内容。一个回放为空白的页面可能已经捕获得很好，所以在得出存档没有内容的结论之前，先获取原始响应。存档中调用的API在查看时没有数据，因为API响应从未被捕获。这些页面天生就是空壳，而不是失败。

## 实际恢复的内容

从`collapse=digest`列表中获取两个日期的原始捕获并作为文本进行比较。删除的内容是证据：某人在两个日期之间的团队页面中被删除，这是一个带有日期范围的离职记录，并且`find-anyone`线索没有剩余的忠诚理由。实践中会浮现：

- **员工和团队页面**。当前网站列出了现在在岗的人员；存档列出了曾经的所有员工，包括职位、简介，并且经常包含组织迁移到联系表之前直接提供的电子邮件地址。
- **先前的价格和条款**——收取了什么、承诺了什么，以及争议开始日期的退款政策。还删除了帖子和新闻稿：双方都停止提及的合作伙伴关系、资金或客户。
- **旧的联系信息**。电话号码、街道地址和后来被表单取代的命名个人联系人。直接进入`whose-number-is-this`。
- **预编辑副本**。将发布的完整页面与其编辑后的后续版本进行比较，可以显示某人支付律师费删除的确切词语——这是一个非常强烈的信号，表明什么重要。
- **被遗忘的文件**——文档路径、备份文件名和管理界面被索引一次，然后从未清理。参见`secrets-in-git-history`。
- **域名的先前所有者**。一个易手域名的存档历史记录显示了一个不同的业务——发现声誉清洗购买的最快方法。

## 在进一步调查前保存

你发现的内容可能会被删除，而调查有时会导致删除。先捕获，后分析。

将活URL提交到Internet Archive的Save Page Now（`https://web.archive.org/save/`）和archive.today，以便两个独立的组织持有你未创建的带时间戳的副本。然后记录你自己的记录：一个WARC保留完整的HTTP交换，包括标题，而截图则不保留。

```bash
wget --warc-file=evidence-001 --page-requisites --no-parent https://example.com/pricing
sha256sum evidence-001.warc.gz | tee evidence-001.sha256
```

记录捕获时间（UTC）、URL的精确请求和哈希值。截图单独使用很弱——容易伪造，没有标题。第三方存档URL加上你自己的哈希WARC很强，因为它们相互印证，并且其中一个不受你控制。这就是`write-the-intel-brief`所期望的。

## 验证捕获是否真实

任何人都可以将内容存入存档：Save Page Now和archive.today都接受匿名提交者提供的任意URL。捕获证明的是“该URL在那时向该爬虫提供了该内容”，而与谁控制该URL无关。现实的伪造路线：

- **伪造的存档页面截图**。简单。永远不要接受存档页面的截图；从存档URL本身开始并重新获取它。
- **通过URL注入的内容**。反射查询参数、用户生成内容路径或开放重定向允许有人在看起来合法的域上存档攻击者选择的内容。逐字符阅读`original`字段：`?`或`#`之后的内容、任何不熟悉的路径段、任何看起来像主机的。
- **域名易手后的捕获**。该域名是买家的，而不是原企业的。使用`who-owns-this-domain`将转移日期与捕获时间戳进行核对。
- **选择性捕获**——一个真实页面连续11分钟，由放置该页面的个人存档。

印证的顺序和强度：确认记录独立存在于CDX索引中，`statuscode`为200，`digest`存在；寻找由存档自己的爬虫而不是按需提交的相邻捕获，因为爬虫捕获很难被策划；检查同一日期附近的第二个独立存档；检查与网站其他历史记录的一致性。一个没有邻居的按需捕获是提交者的断言。

## 哪里会出错

- **缺失不是证据**。没有捕获意味着未链接、被robots.txt阻止、需要登录、太隐蔽无法爬取，或被删除——而不是页面从未存在过。在写“没有记录”之前检查两个存档。
- **排除看起来像缺失**。明确的排除通知意味着有人采取了行动；简单的404意味着什么也没有。不同的事实——注意你得到了什么。
- **事后删除**。Wayback历史上一直将网站的*当前*robots.txt应用于其整个存档历史，所以一个新的`Disallow`可能一次性拉取多年的捕获——使得过期域名购买加上限制性robots.txt成为清洗网站过去的一种廉价方法。这种做法已经缩小，但在历史看起来过于干净时，前往archive.today和Common Crawl。
- **组合渲染**。混合日期的资源意味着渲染的页面是重建的。引用HTML捕获时间戳，而不是“它看起来像什么”。
- **捕获时间不是发布时间**。在3月份首次捕获的页面可能在1月份发布。捕获仅从上方界定日期。
- **动态和个性化内容**。爬虫看到的是一个变体——一个地理位置、一个A/B桶、已登出。价格和可用性尤其如此。
- **稀疏采样隐藏一切**。每年捕获两次的页面可能会变更和撤销而没有痕迹；`collapse=digest`显示观察到的变更，而不是所有变更。时间戳是UTC，忘记这一点会打破时间线一天。

## 置信度分级

- **确认**——由爬虫发起的捕获，`statuscode:200`，使用`id_`获取原始数据，URL已验证为主题的，由第二个存档或同一爬虫系列中的相邻捕获印证。
- **可能**——一个格式良好的Wayback捕获，没有第二个来源，或与网站其他历史记录一致的archive.today捕获。
- **未确认**——没有邻居的按需捕获；带有查询参数或用户生成内容路径的URL；截图；从组合回放中读取的内容而不是原始响应。
- **拒绝**——捕获的URL在该日期不是主题的控制范围，或是在域名易手后获取并作为先前所有者的。

引用完整存档URL和时间戳、原始URL、UTC捕获时间以及你如何获取它。没有时间戳的存档引用不是引用。

## 实例分析

供应商的网站声称有行业认证。客户希望在签署前验证它。

`collapse=digest`在认证页面上返回了六年内的九次内容变更。最近的原始捕获两侧的原始捕获显示认证机构名称已更改——从一个公认的认证机构变为一个类似名称的实体——没有公告。

死胡同：认证机构的自有注册表在两个方向上都没有活记录，并且其存档成员列表回放为空壳。使用`id_`获取它们显示了原因——列表是客户端渲染的API调用，因此爬虫捕获了一个没有数据的页面。那里没有可恢复的内容。

`matchType=domain`的CDX枚举然后发现一个测试主机持有存档的原始证书PDF。其元数据包含比当前网站声称的覆盖范围早两年的过期日期，并且`secrets-in-file-metadata`从同一文件中获取了作者姓名。

评级：措辞变更**确认**——两个爬虫捕获，原始，都读取。失效**可能**——一个文档，没有认证机构的确认。

## 法律和处理说明

读取存档是被动行为；它接触存档的服务器，而不是目标服务器。对活网站恢复的路径进行获取不是被动行为，会记录在目标日志中——故意决定你正在做什么。

存档中的个人数据仍然是个人数据。根据删除权请求删除的内容可能仍然存在于存档中，并且重新发布它可能会产生删除权旨在消除的负债。权衡调查需求与删除原因，并尽量减少[../../ETHICS.md](../../ETHICS.md)。在已发布的报告中复制大量存档内容是一个独立的版权问题，而不是将其用作证据。

批量检索会消耗非营利组织的资源：限制枚举和原始获取速率，并且一次获取索引而不是重复获取。
