# 设计基因

一个三阶段工作流程，用于提取、构建和应用跨三个维度的设计身份：

1. **设计系统** — 可测量的标记（颜色、排版、间距、布局、形状、层级、动效、组件）
2. **设计风格** — 定性感知（情绪、视觉语言、构图、图像、交互感受、品牌声音）
3. **视觉特效** — 特殊渲染（Canvas、WebGL、3D、粒子、着色器、滚动特效、光标特效、SVG动画、玻璃形态等）

## 阶段

### 阶段 1：构建 — 输出架构

当用户询问结构维度或架构时：

1. 阅读 [参考资料/架构.md](references/schema.md)
2. 展示完整架构及字段描述
3. 解释三个维度及其作用：
   - **design_system**：你可以测量的 — 精确的十六进制值、像素尺寸、rem比例
   - **design_style**：你可以感受到的 — 情绪、个性、构图策略
   - **visual_effects**：你能看到的但不能仅用CSS表达的内容 — WebGL场景、粒子系统、着色器扭曲、滚动驱动的动画
4. 询问用户是否需要自定义或扩展任何维度

### 阶段 2：分析 — 从参考资料中提取基因

当用户提供代表目标设计风格的图像、截图或链接时：

1. 阅读 [参考资料/架构.md](references/schema.md) 获取完整字段列表
2. 对于每个提供的参考资料：
   - 如果是图像/截图：**首先运行确定性颜色测量**（见下文），然后直接分析剩余视觉属性
   - 如果是URL：获取并分析页面的视觉设计
3. 对于架构中的每个字段，从参考资料中提取或推断值
4. 当多个参考资料冲突时，记录主导模式并提及变体
5. 输出一个完整的 Design DNA JSON — 每个字段都已填充，无空字符串
6. 输出后，询问："在使用此生成前是否需要调整任何值？"

**每个维度的分析方法：**

#### 维度 1：design_system
- **颜色**：不要通过肉眼估算十六进制值 — 感知颜色会漂移到熟悉的调色板默认值（通常偏差为ΔE 10+）。当参考资料是图像文件时，应进行测量。将 `SKILL_ROOT` 解析为包含此 `SKILL.md` 的绝对目录；永远不要假设当前项目目录包含技能的 `scripts/` 文件夹。使用绝对路径进行参考资料和输出，并为每个参考资料保留一个唯一命名的测量文件：
  ```bash
  npm install --prefix "$SKILL_ROOT/scripts" --silent
  node "$SKILL_ROOT/scripts/measure-colors.mjs" "$REFERENCE_IMAGE" > "$MEASUREMENT_JSON"
  ```
  在 DNA JSON 中原封不动地使用测量值：将 `background` 角色映射到 `surface.background`；将 `text` 映射到与测量背景对比的 `neutral.scale` 的末尾，并在 `neutral.usage` 中记录前景使用；将 `accent` 映射到 `accent.hex`。将测量的调色板及其 `measurement` 配置保留在 `design_system.color.measured_palette` 和 `design_system.color.measurement` 中，以便验证可以重用相同的聚类配置。覆盖率值是从 `0` 到 `1` 的分数。仅在测量不可能时（例如，无法屏幕截图的仅URL参考资料）才回退到视觉采样。通过语义角色选择主色和次色，使用 `accent` 进行CTA强调，无论主题如何，都将中性比例从最亮到最暗排序。
- **排版**：通过视觉特征（几何形、人文主义、衬线类）识别字体家族。根据标题/正文大小关系估算比例。
- **间距**：通过元素邻近度评估密度。通过部分间隙一致性测量韵律。
- **布局**：通过内容对齐模式识别网格。记录最大宽度、列数、非对称性。
- **形状**：通过与元素高度比较测量 `border-radius`。记录边框和分隔符的存在。
- **层级**：分类阴影的柔和度、扩散和分层方法。
- **动效**：如果可观察（视频/交互），记录缓动曲线和持续时间感受。

#### 维度 2：design_style
- 综合整体印象 — 情绪、个性、构图策略
- 与流派原型（SaaS、编辑、极简主义等）进行比较
- 记录装饰水平和白空间哲学

#### 维度 3：visual_effects
- **从代码**：扫描 `<canvas>`、WebGL上下文、Three.js/Pixi.js导入、GSAP/Lottie使用、自定义着色器、IntersectionObserver滚动触发、SVG `<animate>` 元素
- **从截图**：描述超出标准CSS的可见效果 — 发光的粒子、3D对象渲染、噪点纹理、渐变动画、视差深度、光标轨迹、文本扭曲、玻璃形态表面。当无法确定确切实现时，在 `composite_notes` 中记录这些。
- **从视频/交互演示**：记录滚动行为、悬停扭曲、过渡编排、加载序列
- 为参考资料中未出现的任何效果类别设置 `enabled: false`
- 根据 观察到的内容 评估 `overview.effect_intensity` 和 `overview.performance_tier`

### 阶段 3：生成 — 将基因应用于内容

当用户提供 DNA JSON + 内容进行设计时：

1. 阅读 [参考资料/生成指南.md](references/generation-guide.md)
2. 解析 DNA JSON 并提取三个维度上的所有标记
3. 根据 `design_system` 值构建 CSS 自定义属性
4. 应用 `design_style` 定性字段以指导主观设计决策
5. 当设计需要资产或源材料时，尽可能从原始来源获取。如果用户提供了URL，从该URL获取真实资产，而不是重新创建、近似或替代它。
6. 使用适当的技术实现 `visual_effects`：
   - 轻量级效果 → CSS动画、SVG、原生JS
   - 中等效果 → Canvas 2D、GSAP、Lottie
   - 重效果 → Three.js、自定义GLSL着色器、Pixi.js
7. 生成设计输出（默认：自包含HTML带内联CSS/JS）
8. 运行生成指南中的质量检查
9. **验证（当DNA包含测量调色板时）**：如果当前 Design DNA JSON 不是文件，则保存它，截图生成的输出，然后将其与DNA文件进行评分。从此 `SKILL.md` 解析 `SKILL_ROOT` 并使用绝对路径；不要假设存在名为 `measured-colors.json` 的临时文件：
   ```bash
   node "$SKILL_ROOT/scripts/verify.mjs" "$IMPLEMENTATION_SCREENSHOT" "$DESIGN_DNA_JSON"
   ```
   当只有持久化工件时，可以使用独立的测量JSON代替DNA文件。对于多个图像参考资料，分别针对每个参考资料的测量进行验证。报告给出每色的ΔE和覆盖率漂移，以及PASS/FAIL阈值。如果失败，修复有问题的颜色并重新验证，而不是要求用户通过肉眼判断保真度。

**如果用户仅提供内容而不提供DNA JSON**，询问是否要：
- 首先分析参考资料（进入阶段 2）
- 使用描述的风格（从描述中提取DNA，然后生成）

## 阶段组合

用户可以调用任何组合：
- **仅阶段 1**： "向我展示设计结构/架构"
- **仅阶段 2**： "分析这个设计"（带图像/链接）
- **阶段 2 → 3**： "分析这个设计并在相同风格下为我构建一个着陆页"
- **阶段 1 → 2 → 3**： 完整流程
- **仅阶段 3**： 用户已有DNA JSON

从上下文中检测所需的阶段并相应执行。
