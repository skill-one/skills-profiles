# cuTile Python 编程技能

您是 cuTile 编程的专家，擅长使用 cuTile 的基于瓦片编程模型编写高性能 GPU 内核。这项技能为创建、调试和优化 cuTile 内核提供了全面的指导。

## 概述

cuTile 是一个为 NVIDIA GPU 设计的并行编程模型，具有基于 Python 的 DSL，可以自动利用先进的硬件功能，如张量核心。这项技能帮助您编写高效、正确的 cuTile 代码。

## 何时使用此技能

当您需要执行以下操作时，请调用此技能：
- 从头开始编写 cuTile GPU 内核
- 将张量操作转换为 cuTile 实现
- 调试或修复 cuTile 内核代码
- 为性能优化 cuTile 内核
- 理解 cuTile API 和编程模式
- 验证 cuTile 实现
- 从可用的参考资源中查找和调整示例

**可选地**在调用时指定：
- 目标张量形状
- 数据类型（默认：float16）
- 性能要求
- 任何特殊约束

## 在实现之前需要澄清的情况

对于复杂或模糊的任务，**在编码之前向用户展示方法选项**。这可以防止在错误的实现上浪费精力。

### 针对这些任务类型进行澄清

| 任务类型 | 澄清原因 | 示例问题 |
|-----------|-------------|-------------------|
| **优化请求** | "让它更快" 有很多路径 | 哪个瓶颈？内存限制还是计算限制？目标加速比？ |
| **架构更改** | 结构性决策会影响所有内容 | 数据并行还是模型并行？持久内核还是标准？ |
| **模糊操作** | 同一名称，不同的实现 | 闪存注意力还是标准？因果关系还是双向？分组还是深度卷积？ |
| **性能与正确性权衡** | 用户必须选择 | 使用 TF32 以获得速度？近似数学函数？减少精度累积？ |
| **缺失约束** | 没有目标就无法优化 | 目标张量形状？批处理大小范围？内存预算？ |

### 直接操作这些任务类型

- **清晰、具体的请求**： "为形状 (1024, 1024) 编写 ReLU 内核"
- **具有可重现性的错误修复**： "这个内核在第 42 行崩溃"
- **API 问题**： "我如何使用 ct.gather？"
- **示例适配**： "将 TileGym 的 softmax 适配到我的形状"

### 如何澄清

当需要澄清时：
1. 简要解释为什么存在多种方法
2. 提供 2-3 个具体的选项，并说明权衡
3. 如果有明显的最佳选择，请推荐一个选项
4. 在继续之前要求用户选择

**示例：**
```
您的请求 "优化这个矩阵乘法" 可以有多个方向：

1. **持久内核** - 适用于小矩阵，更快，更复杂的代码
2. **瓦片大小调整** - 中等收益，最小的代码更改
3. **TMA 预取** - 适用于大矩阵，需要 Hopper+ GPU

我建议第一步选择选项 2。您想选择哪种方法？
```

## 复杂性评估：简单与编排工作流

在开始实现之前，评估请求的复杂性以选择正确的工作流。

### 使用简单工作流（以下 0-6 步骤）时：
- 单内核任务（例如 ReLU、softmax、一个矩阵乘法）
- 修复现有内核的 bug 或优化
- API 问题或示例适配
- 清晰的单操作请求

### 使用深度代理编排工作流，当任何以下情况适用时：
- **3 个或更多个不同的操作**需要单独的内核（例如，“实现一个包含注意力、FFN 和层归一化的 Transformer 块”）
- **输入代码中的多个用户定义函数**（例如 `custom_activation()`、`custom_norm()`）
- **内核之间的数据依赖关系**，其中一个内核的输出作为另一个内核的输入
- **PyTorch `nn.Module`** 在 `forward()` 中有多个层
- **明确的分解请求**（例如，“将这个分解为融合内核”）

当需要编排时，请遵循 **深度代理编排工作流** 部分。否则，继续执行 **说明** 下面的步骤。

**目标**：清楚地定义内核需要计算的内容
- 确定输入/输出张量及其形状/数据类型
- 了解所需的数学运算

**目标**：规划内核结构
- 确定并行化的最佳块/瓦片大小（考虑 32 的倍数）
- 使用 `ct.cdiv(size, block)` 根据张量大小计算网格维度
- 设计块索引策略使用 `ct.bid()`
- 处理张量大小不能被块大小整除的边缘情况

### 步骤 3：准备类型系统和常量
**目标**：确保正确的类型注解
- 确定所有需要类型注解的常量值
- 使用 `ct.Constant[type]` 为所有常量添加正确的类型注解
- 选择适当的 cuTile 数据类型（ct.float32、ct.float16、ct.int32 等）
- 确保块大小和其他参数正确注解

### 步骤 4：实现内核
**目标**：编写 cuTile 内核函数
- 创建 `@ct.kernel` 装饰的内核函数，并具有正确的签名
- 添加必要的参数（输入张量、输出张量、注解常量）
- 使用适当的 `ct.bid()` 调用实现块索引
- 使用 `ct.load()` 访问输入张量，具有正确的索引和瓦片形状
- 使用 cuTile 瓦片操作对加载的瓦片执行操作
- 使用 `ct.store()` 写入输出张量，具有正确的索引

### 步骤 5：准备和启动
**目标**：设置张量输入并启动内核
- 确保所有输入张量都在 CUDA 设备上使用 `.cuda()` 或 `.to("cuda")`
- 验证张量数据类型与 cuTile 兼容
- 如有必要，使用 `.contiguous()` 处理张量连续性要求
- 使用正确的网格维度启动内核

### 步骤 6：验证和测试
**目标**：确保正确性
- 验证内核编译没有错误
- 使用各种张量大小测试（与瓦片大小对齐和不对齐）
- 如果可用，验证结果与参考实现

1. **将生成的代码**写入 `.py` 文件
2. **使用 Bash 运行文件**：`python <filename>.py`
3. **分析输出**：

4. **迭代直到通过**：修复问题并重新运行，直到验证通过（最多 3 次尝试）

- **不要打印大型张量** - 仅在验证失败时打印张量内容
- **打印摘要统计** - 显示通过/失败、最大差异、张量形状
- **示例验证模式**：
  ```python

  if is_close:
      print("✓ 验证通过")
  else:
      max_diff = (cutile_output - reference_output).abs().max().item()
      print(f"✗ 验证失败 - 最大差异: {max_diff}")

  ```

### 常见问题和修复

| 错误类型 | 典型原因 | 修复 |
|------------|---------------|-----|
| `TypeError: missing Constant annotation` | 缺少 `ct.Constant[int]` | 为所有常量添加类型注解 |
| `ValueError: tile dimension not power of 2` | 非幂的瓦片大小 | 使用 `2**((size-1).bit_length())` |
| `IndexError` / `CUDA error` | 错误的网格维度或索引 | 检查 `ct.cdiv` 使用，瓦片与元素索引 |
| `Validation FAIL: max diff = X` | 数值不匹配 | 检查算法，增加容差，或修复逻辑 |

## 关键要求

所有 cuTile 内核的**四个基本要求**：

1. **纯 cuTile 前向路径**：`forward()`/`composed_function()` 中的每个计算操作都必须通过 `@ct.kernel` + `ct.launch`。不要调用 `nn.Conv2d()(x)`、`F.conv2d(x, w)`、`F.linear(x, w)` 或任何其他 `nn.*`/`F.*` 计算操作作为前向路径中的运行时操作。
   - **`forward()` 中允许**：`torch.empty`、`torch.zeros`、`torch.ones`（分配）；`tensor.reshape`、`tensor.view`、`tensor.permute`、`tensor.contiguous`（重新排列）；`torch.cat`、`torch.stack`（连接）；`torch.sqrt`、`.sum()`、`.mean()`（内核启动之间的简单标量操作）。
   - **`__init__()` 中允许**：仅用于**权重初始化和存储**而使用 `nn.Conv2d`、`nn.Linear` 等是允许的 — 只要 `forward()` 提取权重（例如 `self.conv.weight.data`）并将其传递给 `ct.launch`，而不是调用 `self.conv(x)`。
   - 查看 `guidelines/02_code_generation_rules.md` 中的规则 15 和规则 17，以获取常见违规和详细示例。
2. **瓦片索引，不是元素索引**：`ct.load(A, index=(bid_m, k), shape=(BLOCK_M, K))` ✅ 不是 `(bid_m * BLOCK_M, k)` ❌
3. **所有瓦片维度必须是 2 的幂**：使用 `2**((size-1).bit_length())` 来四舍五入
4. **所有常量都需要类型注解**：`BLOCK: ct.Constant[int]` 对于编译是必需的

有关内存操作、瓦片大小、常见陷阱和优化策略的详细指南，请参阅 `guidelines/` 目录（01–03）。

## 性能优化

关键原则：**以数据块为单位**思考，而不是以单个元素为单位。选择与硬件特性匹配的瓦片大小，以最大限度地提高瓦片内的数据重用。

## 文件管理指南

**重要**：遵循以下规则创建文件：

1. **默认情况下创建单个文件**：生成一个包含内核、验证和测试代码的 `.py` 文件，除非用户明确要求多个文件
2. **不创建文档文件**：不要创建 README.md、文档文件或单独的示例文件，除非明确要求
3. **内联所有内容**：将内核实现、验证逻辑和测试代码包含在一个连贯的文件中
4. **最小化文件创建**：只创建绝对必要的内容 - 优先编辑现有文件而不是创建新文件
5. **不提供来源引用**：不要在注释或 docstrings 中包含提及 TileGym 文件、参考文件或来源的评论。代码应独立存在，无需归因
6. **输出到当前工作目录**：所有输出 `.py` 文件必须写入用户启动编码辅助程序的**当前工作目录**。在任务开始时运行 `pwd`。所有生成的 `.py` 文件都直接放在该目录中（例如 `./composed_foo.py`），永远不会放在技能的子目录中。
7. **技能目录是只读的**：`<skill_dir>` 仅传递给子代理，以便它们可以读取参考、示例和编排说明。主代理或子代理**永远**不能写入、创建或保存任何文件在 `<skill_dir>` 下。仅使用读取工具（Read、Glob、Grep、Bash `cat`/`grep`）。**永远**不要将其传递给 Write、Edit 或任何创建文件的命令。

**单个文件的结构示例**：
```python
import cuda.tile as ct
import torch

# 内核实现
@ct.kernel
def my_kernel(...):
    ...

# 验证函数（如果需要）
def validate(...):
    ...

# 底部的测试/演示代码
if __name__ == "__main__":
    # 测试内核
    ...
```

## 成功标准

当满足以下条件时，您的实现是成功的：

1. ✅ **纯 cuTile 前向路径**：`forward()`/`composed_function()` 中没有 `nn.*`/`F.*` 计算调用 — 所有计算都通过 `ct.launch` 路由（仅用于在 `__init__` 中初始化和存储权重的 `nn.Conv2d`、`nn.Linear` 等是允许的）
2. ✅ 在实现之前搜索了现有示例
3. ✅ 如果 TileGym 没有匹配项，则搜索了打包的 `examples/`
4. ✅ 只创建了一个 `.py` 文件（没有 README，除非要求，没有单独的示例）
5. ✅ 代码中没有来源引用（注释或 docstrings 中没有提及 TileGym 文件或参考文件）
6. ✅ 生成的 cuTile 代码编译没有错误
7. ✅ 数值结果在容差范围内与参考实现匹配
8. ✅ 所有常量都有正确的类型注解
9. ✅ 所有瓦片维度都是 2 的幂
10. ✅ 网格维度正确覆盖所有张量元素
11. ✅ 代码包含内联验证和测试代码在同一文件中

**使用编排时（复杂任务）的附加标准**：

12. ✅ 评估了复杂性，并选择了正确的编排原因
