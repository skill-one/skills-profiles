# 会话记忆

保存当前工作会话的持久化、人类可读的记录，以便另一个代理在断开连接后能够以最小的上下文丢失恢复。

## 使用场景

在以下情况下使用此技能：
- 用户要求保留、恢复、检查点或管理代理记忆。
- 工作是长时间运行的、实验性的，或者可能跨越断开连接。
- 您即将进行非平凡的编辑、运行长时间任务、切换分支或暂停以获取用户输入。
- 您在已经存在 `./session/` 目录的存储库中恢复。

## 会话目录

为每个工作会话创建一个目录：

```bash
mkdir -p session
date +%Y%m%d_%H%M%S
mkdir -p session/<session_date_time>
```

使用机器的本地时间。对于同一对话中的所有检查点，除非用户明确启动新会话，否则重用相同的会话目录。

预期文件：
- `session_state.md` - 总体目标、当前子任务、加载的技能、状态、计划、假设、障碍和下一步行动。
- `timeline.md` - 仅追加的关于主要操作、命令、结果和决策的日志。
- `files.md` - 检查的文件、更改的文件以及它们的重要性。
- `handoff.md` - 供下一个代理使用的简洁恢复说明。

仅在必要时添加其他文件，例如 `experiments.tsv`、`review_notes.md` 或复制的命令日志。

## 开始或恢复

在会话开始时：
1. 检查现有的会话目录：

```bash
ls -dt session/* 2>/dev/null | head
```

2. 如果用户正在恢复工作，请读取最新的相关 `session_state.md`、`timeline.md` 和 `handoff.md`。
3. 如果没有相关的会话，请创建一个新的带时间戳的目录。
4. 写入初始 `session_state.md`，包含用户的总体目标、当前子任务、加载的技能、存储库路径、分支和已知约束。

不要将会话笔记视为唯一的真实来源。在采取行动之前，请通过 git 状态、文件和命令输出来验证重要声明。

## 检查点节奏

写入检查点：
- 在收集到足够上下文以形成计划后。
- 在有意义的代码编辑之前和之后。
- 在长时间运行的命令、实验、分支切换或任何难以从聊天中重建的内容之前。
- 当用户改变方向时。
- 如果会话有有意义的、值得恢复的状态，则在最终响应之前。
- 在积极进行长时间运行的工作期间至少每 30 分钟。

优先更新相同的文件，而不是创建许多小的检查点文件。保持记录简洁且易于扫描。

## 文件模板

### `session_state.md`

```markdown
# 会话状态

- 会话: <session_date_time>
- 存储库: <绝对存储库路径>
- 分支: <分支名称>
- 开始时间: <本地时间戳>
- 更新时间: <本地时间戳>

## 目标
<用一到两句话表达的稳定总体用户目标。在后续的引导中保留此目标，除非用户明确更改。>

## 当前子任务
<当前正在处理的立即任务或引导请求。>

## 加载的技能
- `<skill-name>` - <加载原因和任何重要的保留说明。>

## 当前状态
<现在是什么。包括已完成的工作和验证状态。>

## 计划
- [ ] <下一步具体步骤>
- [ ] <下一步具体步骤>

## 假设
- <假设以及需要时如何验证。>

## 障碍
- <障碍或“未知”。>
```

### `timeline.md`

```markdown
# 时间线

## <本地时间戳>
- 用户请求: <简要请求>
- 上下文收集: <文件/命令和关键结果>
- 决策: <重要选择和理由>
- 结果: <编辑/测试/结果>
```

### `files.md`

```markdown
# 文件

## 检查
- `<路径>` - <为什么它很重要>

## 更改
- `<路径>` - <发生了什么变化以及原因>

## 生成
- `<路径>` - <目的>
```

### `handoff.md`

```markdown
# 交接

## 从这里恢复
<当前状态的段落总结。>

## 下一步行动
- <最重要下一步行动>
- <仍需验证或清理>

## 注意事项
- <下一个代理必须保留的风险、用户偏好或存储库约束。>
```

## 恢复工作流程

在断开连接后恢复时：
1. 找到最可能的最新会话目录。
2. 首先读取 `handoff.md`，然后 `session_state.md`，然后最近的 `timeline.md`。
3. 运行轻量级验证，例如 `git status --short`、`git branch --show-current` 和目标文件读取。
4. 从最新的验证的下一步行动继续。
5. 追加一个时间线条目，注明恢复和任何发现的不匹配。

## 质量规则

- 保持笔记事实准确且简洁。未来的代理需要状态，而不是谈话记录。
- 记录重要的命令结果，特别是失败的测试或跳过的验证。
- 提及未提交的更改以及它们是由当前代理还是预先存在的。
- 不要在会话文件中存储秘密、令牌、私有凭证或大型日志。
- 如果会话文件变得很大，请总结旧细节并将最新的下一步行动保留在 `handoff.md` 的顶部附近。
