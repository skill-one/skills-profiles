# 多目标探索

cuOpt 每次求解只优化一个目标。许多实际问题存在多个相互冲突的目标——成本与服务水平、回报与风险、生产周期与加班时间、距离与车辆数量。单个求解只能回答“在特定权重下的最优解是什么”，但会隐藏用户实际需要权衡的内容。

这项技能将一系列单目标 cuOpt 求解转化为**帕累托前沿**——即无法在不牺牲其他目标的情况下改进某个目标的解集——并赋予解读它的规则。它不增加求解器功能；它只是协调已经由公式化和 API 技能涵盖的 LP/MILP/QP 求解。

## 适用场景

当问题存在**两个或多个没有公认权重的目标**时，请使用此工作流，语言提示如下：

- "平衡 X 和 Y"、"权衡取舍"、"尽可能便宜 *而不损害服务*"
- "最小化成本 *并* 最大化覆盖范围"、"我想选项，而不是单一答案"
- 任何用户愿意以牺牲另一个目标为代价而放宽的目标

如果存在一个清晰的目标（其他所有内容都是硬约束），则不适用此技能——公式化并一次性求解。

## 核心思想——一个求解对应曲线上的一个点

单个最优解编码了**一个隐式权重**的目标。改变权重，最优解会移动。前沿是所有非支配最优解构成的曲线。

当解 A **支配** B 时，A 在每个目标上至少与 B 一样好，并且在至少一个目标上严格更好。被支配的解永远不值得选择。**帕累托前沿**正好就是非支配集；用户的工作是选择一个点，而你的工作是展示整条曲线以及权衡最尖锐的位置。

不要将多目标问题简化为单个加权数字并报告其最优解为“答案”——这会默默地替用户做出权衡决策。绘制前沿并让用户选择。

目标和约束可以互换。当前被视为固定的要求——覆盖范围下限、公平性上限、预算——通常是潜在目标：其水平是假设的，而不是给定的。将此类约束提升为参数化 ε-约束并扫描它，会揭示你原本隐藏的权衡，因此将单个目标模型的硬约束视为候选目标，而不仅仅是限制——但仅当水平是假设时。一个真正固定且不可协商的限制（硬预算上限、监管最低要求）仍然是约束；不要制造不存在权衡的情况。将任何提升的量线性化，以便它可以作为 ε-约束使用（参见 `cuopt-numerical-optimization-formulation`）。

## 第 1 步——定义目标

需要真实冲突的目标才能生成信息量前沿：如果它们不相互冲突，前沿会收缩成一个点，没有任何可权衡的内容。并且每个目标都必须正确公式化，因为错误的公式、含义或尺度会扭曲权衡，并使拐点位置发生偏移。在扫描之前，使用 `cuopt-numerical-optimization-formulation` 对每个目标进行公式化。

## 第 2 步——构建收益表（锚定每个目标）

首先**独立**求解每个目标。对于 *k* 个目标，这是 *k* 次求解。记录每个目标在最优解处的每个目标值：

```text
              f1        f2        f3
min f1   →   f1*       f2(at f1*) f3(at f1*)
min f2   →   ...       f2*        ...
min f3   →   ...       ...        f3*
```

对角线 (`f1*`, `f2*`, …) 是每个目标的最佳可实现值；非对角线给出了每个目标在其他人最优解中跨越的**范围**。此表具有双重作用：

- 它设置了 ε-约束方法的**扫描边界**（每个受约束目标的可行范围）。
- 它提供了**归一化**的尺度——美元、百分比和小时的目标无法有意义地加权，直到除以其范围。

如果任何单个目标求解已经不可行，请停止并修复模型，然后再扫描——前沿还不存在。

## 第 3 步——选择标量化方法

### 加权求和

将目标组合成一个并扫描权重：

```text
minimize  w1·f1(x) + w2·f2(x) + ... ,   for a grid of weight vectors w
```

使用任何求解器都很简单且直接。需要尊重的两个限制：

- **它只能找到前沿凸包上的点。** 无论如何选择权重，前沿的凹（非凸）区域都是无法触及的，并且对于 MILP，可触及的点可能稀疏且存在较大间隙。如果前沿看起来可疑地线性或只有少数聚集的点，这就是症状。
- **权重只有在目标归一化后才是优先级。** 首先将每个 `f_k` 除以其收益表范围；否则，无论意图如何，最大幅度的目标都会主导。

### ε-约束（完整前沿的首选方法）

保留一个目标；将其他目标移至约束，并扫描其右侧：

```text
minimize  f1(x)
subject to  f2(x) ≤ ε2
            f3(x) ≤ ε3
            (原始约束)
```

扫描每个 `ε_k` 从收益表的范围。每个 `(ε2, ε3, …)` 组合是一个标准的 cuOpt 求解。这可以恢复**完整**前沿，包括加权求和无法触及的凹区域，这就是为什么当完整性重要时它是默认方法。成本是更多的求解（受约束目标的网格）和 ε 值的簿记。

直接 ε-约束线性目标。一个二次目标（例如风险 `xᵀΣx`）最简单的是将其作为目标 `f1`，同时 ε-约束线性目标。一个**凸**二次目标可以直接 ε-约束：将其作为二次约束 `xᵀQx ≤ ε` 添加，cuOpt 支持。非凸或等式二次约束不受支持，MILP 路径保持线性约束。

在现有代码中识别它：一个手写的循环遍历目标或预算值（例如回报目标、成本上限）已经是 ε-约束方法——将其命名为此，过滤被支配的点，并读取扫描约束的对偶（仅限 LP/QP）。

**将这个对偶视为局部交换率。** 在前沿平滑的地方，对偶是它的斜率——保留的目标 `f1` 每单位边界移动多少——无需额外成本即可获得；在拐点处，它只给出单边率。**零**对偶通常意味着边界松弛——扫描已经超出前沿边缘（单向：松弛边界总是显示零对偶，但在退化情况下，绑定边界也可能如此）。这种读取需要 LP/QP 和一个*线性*ε-约束——MILP 最优解和具有二次约束的问题不返回对偶——在无法获得对偶的情况下，比较相邻前沿点。

**选择方法：** 加权求和用于快速凸形草图或已知前沿是凸形（例如纯 LP/QP 权衡）；ε-约束用于 MILP 问题、前沿可能是非凸形，或用户需要一个忠实且完整曲线。

## 第 4 步——扫描、收集和过滤

```text
frontier = []
for each weight vector (or ε vector) in the grid:
    set the combined objective (or ε right-hand sides)
    solve with cuOpt              # reuse the prior solution as a warm start
    if status is Optimal/Feasible:
        record (objective values, solution)
discard dominated and duplicate points
sort the survivors to form the frontier
```

实用提示：

- **使用 LP 扫描的预热启动。** 对于 LP 前沿，将先前求解的 PDLP 预热启动数据带入下一个求解以减少求解时间。根据 cuOpt，这是**仅限 LP**：MILP 求解不使用 PDLP 预热启动（你可以选择性地种子 MIP 启动）。参见 `cuopt-numerical-optimization-api` 了解调用。
- **限制每个 MILP 求解。** 对 MILP 扫描设置每次求解的时间限制（参见 `cuopt-numerical-optimization-api`）——扫描包含多次求解，分支定界可能超出一个小间隙以证明最优性，而 cuOpt 默认不设置限制且不会警告。报告点为到您设置的间隙最优*，而不是认证最优。
- **过滤被支配的点。** 正确的扫描仍然可能发出被支配的点（尤其是在加权求和接近凸包时，或 MILP）。丢弃它们；它们不是前沿的一部分。
- **分辨率是一个预算。** 曲线保真度与求解次数权衡。从粗略开始以查看形状，然后仅在曲线弯曲处细化网格。
- **在 LP/QP 中，在斜率变化处花费预算。** 因为 ε-约束对偶是前沿的局部斜率，比较已求解点的对偶：在它几乎不变的地方，曲线几乎是直线——插值而不是增加求解；在它跳跃超过求解容差的地方，前沿在这两点之间弯曲——在那里细化（较小的差异是求解器噪声，不是曲率）。这会将求解集中在曲线实际弯曲的地方，而不是均匀地分散在网格上。在 MILP 中，根据原始目标值之间的间隙判断细化位置。
- **验证，不要假设。** 当你声称一种方法优于另一种方法时，请测量它——例如，计算 ε-约束恢复而加权求和遗漏的效率点——而不是断言；并标记任何返回可行但不是 `Optimal` 的求解，以便非认证点永远不会被视为精确。

## 第 5 步——完成前沿：测量并填补扫描遗漏的内容

加权求和扫描只返回**支持**点（第 3 步的凸包限制）；在 MILP 前沿上，非支持点——那些加权求和权重无法返回的点——通常构成非支配集的大部分。粗略的 ε-约束网格以相同方式留下间隙：任何有限扫描都可能遗漏区域。在展示扫描前沿之前，测量可能的遗漏并决定是否填补。

### 测量遗漏

按一个目标对扫描点排序。对于相邻的每一对，在目标空间中形成它们之间的矩形（一般而言，是盒子）；标记任何远大于中位数相邻盒子的盒子（3× 是一个合理的标准）或覆盖前沿跨越面积较大份额的盒子——一个只返回少量点的扫描全是间隙，所以没有盒子突出于中位数。大盒子有两个原因——非支持区域（加权求和无法触及它们，在固定费用结构下很常见）和权重聚类（有限网格重新发现相同的角，即使在几乎凸的前沿上也是如此）。填补步骤将两者视为相同。

如果所有盒子都很小且均匀，扫描可能足够——如实说明并停止。

### 首先填补最大的间隙

对于每个标记的盒子，在盒子中点内求解一个目标 ε-约束子问题：优化一个目标，将其他目标在盒子中点处约束（双目标；对于更多目标，按每个目标依次排序并在每个标记的盒子里放置一个目标，而不是递归）。只有认证 `Optimal` 的结果会稳定或引导任何内容——一个有时间限制的当前解被保留为一个点（标记，如下所述），但证明不了关于间隙的内容。一个新认证的点在第 4 步的支配过滤中幸存下来，这意味着间隙是真实的（ε 求解可以返回弱最优点）——二分：在它创建的两个子盒子内放置两个更多目标。一个认证的端点返回来清除约束的一侧；认证整个盒子为真正的不连续性也需要一个已知的步长——所有整数目标系数在整数变量上给出一个——将约束放在远端点内侧并匹配其认证最优解。没有这个步长，将盒子报告为候选间隙，而不是已证明的不连续性。在求解预算耗尽或剩余盒子低于标记标准时停止。

### 每次求解预热启动（廉价的保险）

连续填补求解之间的差异只有一个边界，因此用其邻居作为 MIP 启动（第 4 步的预热启动注释）——一行代码，它永远不会改变什么是最优的。预期求解时间不变；价值是保险在困难子问题上。

### 优雅降级，永不沉默

如果一个子问题在时间限制内遇到可行当前解（`FeasibleFound`），保留该点——它是可行的，求解报告的间隙限制其次优性——但将其记录为近似值。时间限制的求解是主要备用方案：它返回一个当前解和一个边界。启发式模式（`mip_heuristics_only`）放弃证明工作并返回可行点而没有间隙边界——当可行点是你唯一需要时使用它，并说明它返回的所有内容都是近似的。

### 带有来源报告

每个展示的点都带有以下两种标签之一：

- **精确**——在您的间隙设置下 `Optimal`，即到该间隙最优；
- **近似**——时间限制的当前解（引用其报告的间隙）或启发式模式结果（没有边界存在；如实说明）。

报告前沿计数（“14 个点，11 个精确，3 个近似靠近低成本端，最差间隙 2.4%”）。永远不要将混合前沿报告为均匀最优。

## 第 6 步——解读前沿

- **报告权衡，而不是单个数字。** 一个前沿点单独意味着什么。引用交换率——“在此区域，每增加 1% 的覆盖范围约增加 4k 美元的额外成本”——以便用户可以判断是否值得移动。在 LP/QP 前沿上，这个交换率是扫描约束在该点的对偶——前沿的局部斜率，准确到求解的最优性容差（在依赖对偶之前，请先收紧它）；在 MILP 中，从相邻前沿点的间隙估计它。
- **标记拐点；不要自动选择它们。** 曲线弯曲最剧烈的位置是“拐点”——超过它，你为一点付出很多。它通常是最佳平衡妥协，值得突出显示，但最终选择是用户的偏好，而不是规则。在拐点处，斜率是双向的——刚刚下方的对偶与刚刚上方的对偶不同——因此在此处引用交换率作为范围，而不是一个数字。
- **将支配或间隙输出视为诊断。** 如果支配点在过滤后幸存下来，或者前沿不切实际地稀疏或完全线性，怀疑扫描或模型——最常见的是加权求和隐藏了凹区域（返回到第 5 步填补间隙）或归一化错误。
- **说明你使用的权重/ε。** 每个报告的点都取决于其标量化。使这一点明确，以便单个求解永远不会被误认为是“最优解”。在 LP/QP 中，ε-约束对偶是该点的*隐式权重*——解决方案对每个受约束目标的实际价格，以及加权求和求解需要重现该权衡的权重。报告它们使接受的权衡比率明确。

## 接口

这项技能与求解器和接口无关。每次求解的机制——构建目标、添加 ε 约束、传递预热启动、读取状态——存在于 API 技能中：

- `cuopt-numerical-optimization-api` — LP、MILP、QP 求解（Python、C、CLI）。
- `cuopt-routing-api-python` — 相同的前沿工作流程适用于路由权衡（距离与车辆与时间）。
