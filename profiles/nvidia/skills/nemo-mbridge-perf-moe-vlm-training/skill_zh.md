## FSDP 与 3D 并行

| 方法 | 优势 | 最适用场景 |
|---|---|---|
| FSDP | 最简单的实现多模态运行路径 | 首次启动、内存优先调优、嵌入、视觉和解码器阶段边界不规则的模型 |
| 3D 并行 | 调优后性能上限更高 | 具有清晰阶段布局的稳定模型，且有时间进行更深入的调优 |

对于 MoE VLM，实际工作流程通常是：

1. 使用 FSDP 获取第一个可靠的运行结果
2. 稳定真实数据输入、重新计算和内存行为
3. 只有当吞吐量裕量值得额外工作投入时，才迁移到 3D 并行

## 近期 VLM 运行中的主要发现

### Qwen3-VL 系列模型

在追踪器中，主要模式是一致的：

- 在 GB200 级别的系统上使用 FSDP，即使配置相对简单，也能达到健康的高 teens 利用率
- B200 FSDP 运行是可行的，但对重新计算选择和冻结的视觉设置更敏感
- 3D 并行可以在调优 MBS、重新计算和真实视觉路径后恢复到相似或更好的运行点

### 真实数据与模拟数据

模拟数据 VLM 运行不是可靠的性能指标。在实验中，与真实多模态输入相比，无图像的模拟运行看起来更接近“大致快两倍”而不是“略微乐观”。

在得出任何关于 VLM 吞吐量的结论之前，请使用真实或逼真的图像有效载荷。

### 较小的多模态 MoE 运行

较小的 Qwen3.5 风格的多模态实验同样强化了这些教训：

- HybridEP 在 GB200 上是一个可靠的默认选项
- 一旦训练循环稳定，TE 范围内的 CUDA 图会很有帮助
- 更大的 MBS 可以带来回报，但前提是视觉编码器不会成为下一个瓶颈

## 决策指南

### 选择 FSDP 当

- 你首次启动新的 VLM
- 模型在嵌入、视觉和解码器之间存在不规则的阶段边界
- 内存适配比绝对吞吐量更重要
- 在以解码器为重点的调优期间可能冻结视觉堆栈

### 选择 3D 并行当

- 模型在 FSDP 下已经稳定
- PP 布局清晰且可重复
- 可以一起调优 MBS、重新计算和 CUDA 图范围
- 目标是最佳稳态吞吐量，而不是最容易的启动

## 关键调优旋钮

1. **在适当时候冻结视觉堆栈**：如果工作以解码器为重点，冻结视觉侧通常会带来微小但真实的吞吐量提升，并减少内存压力。

2. **激进地调优 MBS**：VLM 比纯文本 MoE 运行对 MBS 更敏感，因为视觉路径改变了计算与开销的平衡。

3. **模型适配后优先选择选择性重新计算**：完全重新计算是一个有用的启动工具，但选择性重新计算通常是更好的稳态。

4. **将 CUDA 图范围与工作负载匹配**：`attn moe_router moe_preprocess` 是 MoE 的更安全默认值，而较窄的范围对于受控实验仍然有用。

5. **仅在 EP 单独不足以用时使用 ETP**：它可以解锁一个布局，但它也引入了更多的通信和更多的调优表面。

## 典型配置系列

### FSDP 优先的 GB200 路径

```text
TP=1  CP=1  PP=1
EP 根据专家拓扑进行配置，通常较大
调度器：GB200 级别系统上的 HybridEP
重新计算：从完全重新计算开始，然后逐渐放松到选择性重新计算
```

### 3D 并行的 GB200 路径

```text
TP=1  CP=1  PP=1 或适度的 PP
EP 和 ETP 根据专家拓扑进行配置
调度器：HybridEP
CUDA 图：从窄开始，只有在真实数据路径稳定后才会放宽
```

## 兼容性

| 功能 | FSDP | 3D 并行 |
|---|---|---|
| GB200 上的 HybridEP | 强大的默认值 | 一旦拓扑稳定，也是强大的默认值 |
| CUDA 图 | 启动后有用 | 有用，但更敏感于范围 |
| 冻结视觉 | 天然匹配 | 可能，但不太常作为主要性能路径使用 |
| 选择性重新计算 | 推荐 | 推荐 |

## 陷阱

1. **模拟多模态数据具有误导性**：它可以使得解码器看起来比真实的端到端 VLM 路径更健康。

2. **视觉编码器可能意外主导**：在将所有内容归因于调度器之前，分别分析编码器、投影器和解码器。

3. **不要比较具有不同有效工作的 FSDP 和 3D 并行运行**：按有用 token 和工作负载形状进行归一化，而不仅仅是按步长时间。

4. **ETP 不是免费的**：将其用作适配或拓扑工具，而不是默认值。

5. **重新计算和 CUDA 图选择是耦合的**：使模型适配的设置通常不是提供最佳稳态速度的设置。
