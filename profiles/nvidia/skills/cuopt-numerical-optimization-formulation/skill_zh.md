# 数值优化建模

从问题描述到清晰建模（覆盖LP、MILP和QP）的概念和工作流程。这里没有API代码。

## 什么是LP / MILP / QP

- **LP**：线性目标函数、线性约束、连续变量。
- **MILP**：与LP相同，加上一些整数或二元变量（例如，调度、设施选址、选择）。
- **QP**：二次目标函数（例如，x²、x·y项——投资组合方差、最小二乘法），线性约束。**cuOpt中的QP支持目前处于Beta阶段。**

## 识别问题类型

| 属性 | LP | MILP | QP |
|---|---|---|---|
| 目标函数 | 线性 | 线性 | 二次 (xᵀQx + cᵀx) |
| 约束 | 线性 | 线性 | 线性 + 凸二次（仅不等式）通过二阶锥表示 |
| 变量 | 连续 | 混合：连续 + 整数/二元 | 连续 |
| 求解方向 | 最小化或最大化 | 最小化或最大化 | **仅最小化**（取反以最大化） |
| 对偶/灵敏度 | 对偶值 + 减少成本 | **无**（整数最优解） | 对偶值 + 减少成本 |

如果目标是纯线性的，优先选择LP/MILP——不要人为引入二次项。如果任何变量是整数或二元，则问题为MILP，无论其余部分如何。

**求解后灵敏度（仅限LP / QP）。** 连续LP和QP解会暴露**对偶值**（每个约束松弛一个单位时目标函数的边际变化：*在哪里投资以改善结果*）和**减少成本**（对于优化器留为零的变量，它必须改善多少才能进入解：一个*近似值*）。**MILP解没有对偶值**——整数最优解不是连续的，所以没有可返回的值。当模型包含二次约束时，对偶值也不可用——二阶锥路径仅返回原始值。有关如何在求解后检索它们，请参阅特定语言的API技能。

## 必须的建模问题

如果还不清楚，请提出这些问题：

1. **决策变量**——它们是什么？边界？
2. **目标函数**——最小化还是最大化？线性还是二次？对于QP：是否有任何平方或交叉项（x²、x·y）？如果最大化二次项，用户必须取反并最小化。
3. **约束**——线性不等式/等式？也支持凸二次约束（仅不等式），作为二阶锥处理；非凸或等式二次约束不受支持。
4. **变量类型**——所有连续（LP / QP）或一些整数/二元（MILP）？
5. **凸性（仅限QP）**——对于最小化，二次形式（矩阵Q）对于良定义问题应该是半正定的。

## 典型的建模元素

- **连续变量**——生产数量、流量、分配、投资组合权重。
- **二元变量**——开/关、是/否（例如，设施开放、项目选择）。
- **连接约束**——例如，仅当设施开放时才生产（Big-M或指示器）。
- **资源约束**——使用线性上限（材料、时间、容量）。
- **二次目标项**——方差（xᵀQx）、平方误差（‖Ax − b‖²）、交互项。

## 典型的QP应用场景

- 投资组合优化——在回报和预算约束下最小化方差。
- 最小二乘法——在线性约束下最小化 ‖Ax − b‖²。
- 其他具有线性约束的二次目标。

## 问题陈述解析

当用户给出**问题描述**时，对每个句子进行分类，然后总结，再进行建模。无论LP / MILP / QP如何，解析框架都适用。

**将每个句子分类为** **参数/给定**、**约束**、**决策**或**目标**。注意**隐式约束**（例如，承诺与可选措辞）和**隐式目标**（例如，“确定计划”+成本→最小化总成本）。

**歧义**：如果任何内容仍然模糊，请询问用户或求解所有可能的解释并报告所有结果；不要假设单一解释。

### 🔒 必须的：有疑问时——询问

- 如果对是否应包含约束或值有任何疑问，**询问用户**并说明可能的解释。

### 🔒 必须的：完整路径运行——尝试所有变体

- 当用户要求**运行完整路径**（例如，端到端、完整管道）时，运行所有可能的变体并**报告所有结果**，以便用户选择；不要假设单一解释。

### 三个标签

| 标签 | 含义 | 示例（句子类型） |
|-------|--------|---------------------------|
| **参数 / 给定** | 固定数据、输入、事实。模型不选择。 | "需求是100单位。" "有3个工厂。" "成本为每单位5美元。" |
| **约束** | 必须满足的内容。可以是显式或**隐式**从措辞中得出。 | "容量是200。" "必须满足所有需求。" "至少需要2班次人员。" |
| **决策** | 我们选择或优化的内容。 | "生产多少。" "开放哪些设施。" "雇佣多少工人。" |
| **目标** | 要最小化或最大化什么。可以是**显式**（"最小化成本"）或**隐式**（"确定计划"且成本已知）。 | "最小化总成本。" "确定生产计划"（成本已知）→最小化总成本。 |

### 隐式约束：承诺与可选措辞

**承诺/固定措辞** → 视为**参数**或**隐式约束**（所有提及的都是给定或必须发生）。不是决策。

| 措辞 | 解释 | 原因 |
|----------|-----------------|-----|
| "计划生产X产品" | **约束**：所有X都必须生产。 | 承诺；生产水平是固定的。 |
| "运营3个工厂" | **参数**：所有3个都开放。不是选址问题。 | 当前状态是固定的。 |
| "雇佣N名工人" | **参数**：所有N都受雇。不是招聘决策。 | 工作人员数量是给定的。 |
| "具有C的容量" | **参数**（C）+ **约束**：使用 ≤ C。 | 容量是固定的。 |
| "必须满足所有需求" | **约束**：需求满足。 | 显式要求。 |

**可选/决策措辞** → 视为**决策**。

| 措辞 | 解释 | 原因 |
|----------|-----------------|-----|
| "最多可生产…" | **决策**：生产多少。 | 可选水平。 |
| "可以选择开放"（工厂、站点） | **决策**：选择哪些开放。 | 选择是确定的。 |
| "考虑招聘" | **决策**：雇佣多少。 | 招聘正在考虑中。 |
| "决定订购多少" | **决策**：订购数量。 | 明确的决策。 |
| "希望最小化/最大化…" | **目标**（驱动决策）。 | 目标；决策是杠杆。 |

### 隐式目标——不要遗漏

**如果问题要求“确定计划”（或类似），但未明确说明“最小化”或“最大化”，目标通常是隐式的。** 你**必须**识别它并在建模前说明；不要构建没有目标模型。

| 措辞/上下文 | 可能的隐式目标 | 原因 |
|-------------------|---------------------------|-----|
| "确定生产计划" + 成本给定（每单位、每小时等） | **最小化总成本**（生产+检验/销售+加班等） | 计划是选择的；成本已指定→自然目标是最小化总成本。 |
| "确定计划" + 成本和收入给定 | **最大化利润**（收入-成本） | 资产负债表两侧→优化利润。 |
| "尝试确定月度生产计划" + 工作室小时成本、检验/销售成本 | **最小化总成本** | 所有成本组成部分都给定；没有收入要最大化→最小化总成本。 |

**规则**：当问题给出成本（或成本和收入）数据并要求“确定”、“找到”或“建立”计划时，**必须明确说明目标**（例如，“我将目标视为最小化总成本，因为只有成本给定。”）。如果成本和收入都存在，请说明是使用“最小化成本”还是“最大化利润”。如果不确定，请询问用户。

### 解析工作流程

1. **拆分**问题描述为句子或逻辑从句。
2. **标记**每个：参数/给定 | 约束 | 决策 | **目标**（如果已说明）。
3. **识别目标（显式或隐式）**：如果问题说明“最小化/最大化X”，那就是目标。如果它只说“确定计划”（或“找到”、“建立”），但给出成本（可能还有收入），目标**隐式**——说明它（例如，最小化总成本，或最大化利润）并与用户确认如果模糊。
4. **标记隐式约束**：对于每个句子，询问——"这是否陈述了一个固定事实或要求（→ 参数/约束），还是我们选择的内容（→ 决策）？"
5. **通过动词和情态词解决歧义**：
   - "是"、"有"、"运营"、"雇佣"、"计划到"（固定/承诺）→ 参数或隐式约束。
   - "可以"、"可以选择"、"考虑"、"决定"、"想要"（可选）→ 决策或目标。
6. **🔒 必须的——如果任何内容仍然模糊**（例如，值或约束有两种可能的解释）：询问用户哪种解释是正确的，或求解所有可能的解释并报告所有结果。不要假设单一解释。
7. **总结**给用户：列出参数、约束（显式+标记隐式）、决策和**目标（显式或推断）**，然后再编写数学建模。

### 解析清单

- [ ] 每个句子都有一个标签（参数 | 约束 | 决策 | 如果已说明，目标）。
- [ ] **目标已识别**：显式（"最小化/最大化X"）或隐式（"确定计划" + 成本→最小化总成本；+收入→最大化利润）。永远不要在未说明目标的情况下建模。
- [ ] 承诺措辞（"计划到"、"运营"、"雇佣"）→ 不是决策。
- [ ] 可选措辞（"可以"、"可以选择"、"考虑"）→ 决策。
- [ ] 承诺措辞的隐式约束被写出来（例如，"必须生产所有X"）。
- [ ] **🔒 必须的——歧义**：任何可能有两种解释的短语→我询问了用户或我将求解所有解释并报告所有结果（不进行无声的单一解释）。
- [ ] 在建模前生成摘要（参数、约束、决策、**目标**）。

### 示例

**文本**："公司运营3个工厂，计划生产500单位。它可以使用加班，但成本更高。最小化总成本。"

| 句子/短语 | 标签 | 备注 |
|-------------------|-------|------|
| "运营3个工厂" | 参数 | 所有3个都开放；不是设施选择。 |
| "计划生产500单位" | 约束（隐式） | 所有500必须生产。 |
| "可以使用加班，但成本更高" | 决策 | 加班量是决策。 |
| "最小化总成本" | 目标 | 驱动决策。 |

结果：参数 = 3个工厂，500单位目标。约束 = 精确生产500（隐式来自“计划生产”）。决策 = 跨工厂分配生产，加班量。目标 = 最小化成本。

**隐式目标示例**：一个要求“确定生产计划”（或类似）并给出成本组件（例如，工作室、检验、销售）但未说明“最小化”或“最大化”的问题→**隐式目标：最小化总成本**。始终明确说明它： "目标是最小化总成本。"

## QP规则：仅最小化

QP目标函数必须是**最小化**。要最大化二次表达式，取反并最小化；然后取最优值的反。

为了使最小化良定义，二次形式 `Q` 应该是半正定的。如果 `Q` 是不定的，问题是非凸的，可能没有有限最优解。

## 常见模式

其余部分涵盖了特定的LP/MILP建模模式。每个都是独立的——阅读与你的问题匹配的部分。

### 分段线性目标与整数生产

当建模**凹分段线性**利润/成本函数（例如，批量销售边际利润递减）时，标准方法使用连续分段变量，其上界等于每个段的宽度。对于凹利润的极大化，求解器自然首先填充高利润段。

**陷阱**：如果生产数量是离散的（块、单位、项目），**总生产**变量必须是**整数**，即使分段变量可以保持**连续**。否则，LP松弛可能会产生分数总生产，导致与真实整数最优解不同的（更高或更低）目标值。

#### 模式

```
x_total  — INTEGER (产品的总生产)
s1, s2, … — CONTINUOUS (在每个价格段中销售的数量，受段宽度限制)

链接：x_total = s1 + s2 + …
资源约束使用 x_total。
目标使用分段变量 × 分段利润率。
```

### 剪切/边角料问题

在剪切问题中，**废料面积**包括**边角料**（每个剪切模式中未使用的宽度）和**过量生产**（超出需求生产的额外卷材）。仅最小化边角料（废料宽度 × 每个模式的长度）忽略了过量生产，导致错误的目标。

#### 正确的目标

由于总有用面积是常数，最小化废料相当于最小化总材料面积消耗：

```
minimize  sum_j (roll_width_j × x_j)
```

其中 `x_j` 是使用模式 `j` 切割的长度。废料面积然后是：

```
waste = total_material_area − required_useful_area
```

其中 `required_useful_area = sum_i (order_width_i × order_length_i)`。

#### 陷阱

使用 `sum_j (waste_width_j × x_j)` 作为目标仅捕获边角料——每个模式中的未使用卷材。它**不**惩罚订单的过量生产。求解器将过量生产窄订单以有效填充模式，但多余的材料仍然是废料。始终使用总材料面积作为目标。

### 目标规划（抢占式/词典序）

目标规划按优先级顺序优化多个目标。将其实现为**顺序求解**——每个优先级级别一个。

#### 建模模式

1. **硬约束**——容量限制、非负性、等。这些在每个阶段都成立。
2. **目标约束**——对于每个目标，引入偏差变量（d⁻ 为未达标，d⁺ 为超标）并写一个等式：`expression + d⁻ − d⁺ = target`。
3. **按优先级顺序求解**：
   - 阶段1：最小化（或最大化）与最高优先级目标相关的偏差。
   - 阶段k：将所有更高优先级的偏差固定在其最优值，然后优化优先级k的偏差。

#### 目标规划中的变量类型

偏差变量（d⁻, d⁺）和松弛/闲置时间变量始终是**连续**的。但是，**决策变量在表示离散/可数数量时必须为整数**（生产单位、车辆、工人等）。不要让连续偏差变量的存在导致你使所有变量都连续——决策变量的整数性直接影响可行性和目标值。

### 多周期库存/采购模型

在涉及多个周期的购买、销售和仓库容量的问题中，根据问题的时序假设决定包含哪些容量约束。

#### 模式

对于每个周期 *t* 的库存平衡 `stock[t] = stock[t-1] + buy[t] - sell[t]`：

- **期末容量**（变量边界）：`stock[t] <= capacity` — 总是需要的。
- **购买后容量**（显式约束）：`stock[t-1] + buy[t] <= capacity` — 防止在周期内任何销售发生之前购买超过仓库容量。

#### 何时包含购买后约束

- **包含它**当问题说明或暗示购买在周期内任何销售发生之前收到（顺序操作），或者当仓库物理上不能在任何时刻超过容量时。
- **省略它**当购买和销售在同一周期内同时发生（教科书交易/库存问题中常见）并且容量仅适用于期末库存。许多经典问题仅约束期末库存。

**关键交互与销售约束**：如果模型已经具有 `sell[t] <= stock[t-1]`（本周期购买的谷物不能在本周期销售），则模型是有界的，即使没有购买后约束。销售约束防止无界的买-卖循环。然后购买后约束是额外的物理限制，而不是数学必要性。

**默认值**：如果问题未指定周期内的时序，请使用**仅**期末容量 (`stock[t] <= capacity`)。仅在问题明确要求时添加购买后约束。

### 混合与共享混合/中间处理

在某些混合问题中，一部分原材料必须**首先混合在一起**（例如，在混合罐中）然后分配给不同的产品。结果中间体具有**均匀成分**——你不能独立地将不同的原材料分配给不同的产品。

#### 为什么标准混合LP在这里是错误的

标准混合LP使用变量 `x[i][j]`（原材料 `i` 在产品 `j` 中的数量）并自由地将每个原材料分配给每个产品。当原材料共享混合步骤时，这些原材料的比例必须在每个接收中间体的产品中**相同**。这种比例约束是**双线性的** (`x[A,1]*x[B,2] = x[B,1]*x[A,2]`) 并且不能直接在LP中表示。

#### 线性化策略

1. **单产品分配**：如果分析表明中间体仅在一种产品中盈利，将中间体分配给其他产品设置为零（设置中间体分配给其他产品为零）。比例约束变得平凡地满足。这是最常见的情况——在尝试一般拆分之前检查每种产品中中间体的盈利能力。

2. **中间体浓度参数化**：将中间体的硫/质量浓度固定为参数 `σ`。对于每个固定的 `σ`，问题是标准LP（中间体成为具有已知属性的虚拟原材料）。求解一个 `σ` 网格或使用结构分析最优解。

3. **场景枚举**：当只有2-3种产品时，枚举哪些产品接收中间体（全-A、全-B、拆分）。对于只有一个接收者的场景，LP是标准的。对于拆分场景，使用策略2。

#### 盈利能力检查

在建模前检查使用中间体在每种产品中的盈利能力：
- 比较**中间体最低成本每吨**（使用最可行的原材料混合）与每个产品的**销售价格**。
- 如果 `cost_intermediate > sell_price[j]` 对于某些产品 `j`，则不应将中间体分配给产品 `j`。原材料C（或其他直接输入）也可能无利可图，如果 `cost_C > sell_price[j]`。
- 这种分析通常完全消除了双线性拆分的需要。
