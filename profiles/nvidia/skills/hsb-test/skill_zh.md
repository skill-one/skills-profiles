# HSB QA 测试运行器

当用户想要对 HSB 板和 devkit 执行 QA 测试计划时，请使用此技能。该技能读取测试文档（本地文件或网页链接），筛选出可以在用户特定硬件配置上自动运行的测试，对每个测试进行通过/失败评估，并生成全面的测试结果报告。

此技能假定 devkit 已设置好（SSH、演示容器已构建、主机已配置、板已连接）。如果设置未完成，它将提供调用 `/hsb-setup` 的选项。

此工作流在演示容器内运行测试应用程序。仅在用户明确调用时才运行它。

## 开始前 — 必须的关卡（按顺序先做这些）

**关卡 1 — 读取环境变量。** 在做任何其他事情之前，检查这些变量并将它们的解析值打印给用户：

```
SSH_TARGET      远程 devkit 登录（例如 nvidia@192.168.1.50）。如果未设置，请询问用户。
REMOTE_ROOT     远程工作目录（例如 /home/nvidia）。如果未设置，请询问用户。
REMOTE_SUDO     sudo / sudo -n / "" — 如果未设置，默认为 "sudo"。
REMOTE_SSH_OPTS 额外的 SSH 选项（可选）。
HSB_PLATFORM    平台提示（可选）。
```

**SSH_TARGET 和 REMOTE_ROOT 是必需的。如果任何一个缺失，就停止并询问用户。**

**关卡 2 — 展示阶段计划，询问测试文档，并获取确认。** 在采取任何行动之前：

1. 显示阶段计划：

```
HSB 测试 — 阶段计划
  阶段 0：验证 devkit SSH、板 ping 和演示容器可用性
  阶段 1：获取测试文档、确认设置、构建可执行测试计划
  阶段 2：执行测试、记录通过/失败、分析失败
  阶段 3：生成测试结果报告（可选择保存）
  阶段 4：清理测试工件
```

2. **如果用户尚未提供测试文档路径或 URL，停止并询问 — 在用户提供之前不要进入阶段 0 或任何阶段**：`请提供您的测试文档的路径或 URL：`。如果用户已经指定了特定测试（例如，“仅连接性检查”），请说明将运行哪些阶段以及将跳过哪些阶段，并注意测试将根据用户的平台/板/传感器配置进行筛选，并分类为可自动执行和手动执行。

3. 明确询问：`是否继续执行阶段 0？[Y/n]` — 在用户确认之前不要开始阶段 0。

## 此技能必须做的事情

1. 验证 devkit 是否可通过 SSH 访问，HSB 板是否已连接且响应正常，以及演示容器是否可用。读取当前的 FPGA 版本和板身份。验证传感器/相机类型、hsb devkit 和发布仓库类型，要么从已设置的环境变量中获取，要么提示用户。如果设置未准备好，请提供调用 `/hsb-setup` 以准备 devkit 的选项。
2. 从用户处获取测试计划文档（文件路径或 URL）。确认用户在阶段 0 中收集的设置详细信息（仓库位置、HSB 版本、平台、板类型、传感器）。研究测试计划和仓库的 `examples/` 目录，以确定哪些测试可以自动运行。跳过手动测试和需要额外设备的测试。为用户呈现可执行测试计划以供批准。
3. 依次执行每个测试用例。对于每个测试：运行应用程序，根据测试计划中的标准评估通过/失败，记录结果。在失败时，分析日志，建议修复，并在运行下一个测试之前让用户决定如何进行。
4. 生成结构化的测试结果报告，包含每个测试的通过/失败状态、遇到的问题和应用的修复。提供保存报告的选项。
5. 清理所有测试工件（容器、临时文件、会话状态）。

## Linux/Windows 友好的包装变量

重用其他 HSB 技能中的相同环境变量：

- `SSH_TARGET` 用于远程登录目标（例如 `nvidia@agx-thor-host`）
- `REMOTE_ROOT` 用于远程工作目录
- `REMOTE_SUDO` 用于特权命令
- `REMOTE_SSH_OPTS` 用于额外的 SSH 选项
- `HSB_PLATFORM` 作为可选的平台提示

如果这些已设置，请通知用户这些设置并使用它们，而无需重新询问。

在阶段 0 之前，打印解析的远程执行设置。

## 强制交互模式

### 会话中的首次运行（无先验验证）

当没有有效的会话状态时，显示完整的阶段计划：

- 阶段 0：验证板连接性、演示容器就绪性和用户设置（发布仓库、平台、传感器/相机）
- 阶段 1：获取测试计划，确认设置，构建可执行测试列表
- 阶段 2：执行测试计划，进行每个测试的通过/失败评估
- 阶段 3：生成测试结果报告（可选择保存）
- 阶段 4：清理

然后一次执行一个阶段。

### 同一会话中的后续运行（快速路径）

当会话状态文件（`/tmp/.claude_hsb_test_session/state.sh`）存在**并且**包含 `_SESSION_VERIFIED=true` 时，该技能跳过阶段 0 和阶段 1 的设置确认，因为连接性、硬件、发布仓库、平台和传感器/相机已经验证。相反，通知用户并直接跳转到测试计划输入：

```
会话已验证 — 跳过连接性检查。
  SSH 目标: $SSH_TARGET
  发布仓库: /home/work/holoscan-sensor-bridge (HSB vX.X.X)
  平台: AGX Thor
  板: HSB Lattice | FPGA: XXXX
  传感器: 双 IMX274

直接进行测试计划输入。
```

然后执行：
- 阶段 1（测试计划输入和测试列表构建 — 跳过设置确认）
- 阶段 2：执行测试计划
- 阶段 3：测试结果报告
- 阶段 4：清理

### 何时从头开始重新运行阶段 0

当需要重新运行阶段 0（忽略快速路径）时：

1. **新会话**：远程主机上不存在会话状态文件，或者启动了新的 Claude Code 会话。
2. **执行失败提示连接性丢失**：如果阶段 2 失败并出现指示板或 devkit 无法访问的症状（ping 失败、SSH 超时、容器启动失败、`No such device` 错误），请从会话状态中清除 `_SESSION_VERIFIED` 并在重试之前重新运行阶段 0。
3. **用户明确要求**：如果用户说“重新验证”、“从头开始”、“从头运行”或调用 `/hsb-test --full`，请从头开始运行阶段 0。

有关完整的确认协议，请参阅下方的 [## 阶段关卡](#phase-gate--user-confirmation-between-phases)。

如果出现故障，请**不要**只是堆砌原始日志。总结：

- 失败的确切命令
- 可能的根本原因
- 推荐的安全操作
- 问题是否阻塞

## 执行规则

### SSH heredoc 模式

使用与其他 HSB 技能相同的持久 SSH 会话模型。每个阶段作为一个单一的 SSH heredoc 块运行：

```bash
ssh -o BatchMode=yes $REMOTE_SSH_OPTS $SSH_TARGET bash -s <<'REMOTE'
set -e

# 从上一个阶段恢复状态
source /tmp/.claude_hsb_test_session/state.sh 2>/dev/null || true
cd "${_CLAUDE_CWD:-__REMOTE_ROOT__}"

# 阶段命令
echo "=== 阶段 N: 描述 ==="
command1
command2

# 为下一个阶段保存状态（如果已设置，则保留 _SESSION_VERIFIED）
_PREV_VERIFIED="${_SESSION_VERIFIED:-}"
mkdir -p /tmp/.claude_hsb_test_session
{
  echo "export _CLAUDE_CWD=\"$(pwd)\""
  echo "export PATH=\"$PATH\""
  echo "export REPO_DIR=\"$REPO_DIR\""
  echo "export VERSION=\"$VERSION\""
  echo "export HSB_PLATFORM=\"$HSB_PLATFORM\""
  echo "export BOARD_TYPE=\"$BOARD_TYPE\""
  echo "export SENSORS=\"$SENSORS\""
  echo "export FPGA_VERSION=\"$FPGA_VERSION\""
  echo "export TEST_PLAN_SOURCE=\"$TEST_PLAN_SOURCE\""
  [ "$_PREV_VERIFIED" = "true" ] && echo "export _SESSION_VERIFIED=true"
} > /tmp/.claude_hsb_test_session/state.sh
REMOTE
```

将 `__REMOTE_ROOT__` 替换为 `$REMOTE_ROOT` 的字面值，当组合 heredoc 时。

### 测试的容器使用

测试命令在演示容器内运行。使用命名容器和看门狗模式以强制执行超时。

每个测试的默认超时时间：**120 秒**（2 分钟）。被以下内容覆盖：
- 技能调用上的 `--timeout N`（适用于所有测试）
- 测试计划中指定的每个测试超时

### 每个测试容器运行后的清理

每次测试运行后，停止并删除容器。有关清理模式，请参阅 [references/phase-details.md](references/phase-details.md)。

### 会话拆除

由阶段 4 处理。如果工作流在阶段 4 之前中止：

```bash
docker ps --filter "name=hsb_test_" --format '{{.Names}}' | xargs -r docker stop -t 2 2>/dev/null || true
ssh -o BatchMode=yes $REMOTE_SSH_OPTS $SSH_TARGET "rm -rf /tmp/.claude_hsb_test_session"
```

## 阶段关卡 — 阶段之间的用户确认

完成每个阶段（0-3）后，**始终提示用户确认**，然后再启动下一个阶段。

**例外**：当 `--y`（自动批准模式）激活时，关卡被跳过。请参阅“自动批准模式 (`--y`)”部分。

**例外**：阶段 4（清理）在阶段 3 完成后自动运行，无需关卡。

```
是否继续到阶段 <N+1> (<阶段描述>)？ [Y/n]
```

### 用户响应处理

此技能中的所有提示都需要明确的键入响应。**永远不要将空白或仅 Enter 的输入视为选择** — 重新提示用户。

- **"y"**, **"yes"**, **"Y"**, **"ok"**, **"go"**, **"continue"**, **"next"** → 继续到下一个阶段。
- **"n"**, **"no"**, **"stop"**, **"abort"** → 停止执行。打印：
  ```
  QA 测试在阶段 N 后暂停。
  您可以通过重新调用技能来恢复。
  ```
  然后运行会话拆除。
- **任何其他文本** → 视为关于当前阶段的问题或指令。回答它，然后重新提示。
- **"retry"** → 重新执行当前阶段，再次显示摘要，然后重新提示。

### 例外

- **阶段 4**（清理）是最终阶段 — 它在阶段 3 完成后或用户拒绝运行另一个测试计划后自动运行。
- **如果阶段失败**且无法恢复，请停止并报告清楚，然后运行清理。

## 详细模式 (`--verbose`)

该技能支持 `--verbose` 标志：

### 检测标志

检查 `$ARGUMENTS`（斜杠命令后的文本）是否包含任何：`--help` / `-h`、`--verbose`、`--y`、`--timeout N` 或 `--full`（不区分大小写）。在进一步解析之前，从参数中删除所有标志（及其值）。

当 `--full` 存在时，忽略缓存的会话状态并从头开始运行阶段 0。

### 详细模式（当设置时）

- 显示每个 SSH 命令的完整原始输出
- 在行内显示完整测试应用程序输出（所有 stdout/stderr）
- 显示详细的阶段状态块

### 简洁模式（默认，无 `--verbose`）

- 在每个阶段后显示要点式摘要
- 抑制原始命令输出
- 显示关键测试输出行（启动、错误、通过/失败指示符），但不是每一行
- 以 4 行格式显示问题（症状、原因、解决方案、阻塞）

## 自动批准模式 (`--y`)

该技能支持 `--y` 标志，它跳过所有关卡并从开始到结束运行整个工作流，而无需在阶段之间等待用户确认。这对于 QA 测试**不推荐**使用。

### 确认警告

当检测到 `--y` 时，显示警告并询问用户确认：

```
⚠  警告：已启用自动批准模式 (--y)。

这对 QA 测试**不推荐**使用。所有关卡将被跳过，整个测试计划将在阶段之间或测试之间不暂停确认的情况下执行。

您将无法查看中间结果、干预失败或测试之间中断。所有输出都将保存到时间戳日志文件中。

注意：在自动批准模式下，您仍然需要在阶段 1 中提供测试计划。失败的测试被记录但不会进行交互式调试 — 测试将自动继续到下一个测试。

输入 'yes' 确认自动批准模式，或输入任何其他内容取消：
```

- 如果用户响应为 **"yes"**（精确匹配，不区分大小写）→ 启用自动批准模式。
- 任何其他响应 → 取消自动批准模式并交互式运行。

### 当 `--y` 激活时的行为

1. **关卡被跳过**。
2. **测试计划批准被跳过** — 生成的测试计划将自动执行。
3. **失败的测试不会暂停** — 失败将被记录，测试将自动继续到下一个测试用例。
4. **测试间提示被跳过** — 测试将连续运行，无需确认。
5. **默认超时适用** — 每个测试 120 秒，或如果指定了 `--timeout N`。
6. **日志文件**：在开始时创建为 `hsb-test-log-YYYY-MM-DD-HHMMSS.md`，位于 `$REMOTE_ROOT/` 或当前目录。
7. **阶段摘要仍然实时显示**。
8. **阻塞连接性故障仍然停止工作流**并触发重新验证。

### 与其他标志的组合

- `--y --verbose`：自动批准并显示完整原始输出。
- `--y --timeout N`：自动批准并设置自定义每个测试超时。
- `--y --full`：自动批准并强制从头开始进行阶段 0 的完整验证。

## 超时处理 (`--timeout`)

该技能支持 `--timeout N` 标志，其中 N 是每个测试的运行秒数。

### 行为

- **当设置**：每个测试最多运行 N 秒，然后停止。根据在该窗口内收集的输出来评估通过/失败。
- **当未设置**：每个测试最多运行 **120 秒**（2 分钟），或直到可以从输出来确定通过/失败，以先到为准。
- **每个测试的覆盖**：如果测试计划为特定测试指定了超时，则该值将优先于默认值和 `--timeout` 标志。

### 验证

- N 必须是正整数
- 最小值：5 秒
- 最大值：3600 秒（1 小时）
- 如果无效，请显示错误并要求用户提供有效的超时
