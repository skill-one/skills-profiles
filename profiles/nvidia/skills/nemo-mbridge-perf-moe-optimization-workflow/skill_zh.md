# MoE 训练优化工作流

稳定文档：@docs/training/moe-optimization.md
卡片：@skills/nemo-mbridge-perf-moe-optimization-workflow/card.yaml
来源：[使用 Megatron Core 进行 MoE 模型的可扩展训练](https://arxiv.org/abs/2603.07685)

## 快速参考

从论文的三个墙开始：

- 内存墙
- 通信墙
- 计算效率墙

对于操作诊断，将计算效率墙拆分为 **计算** 和 **主机/启动** 瓶颈。它们需要不同的证据和不同的修复方法。MoE 调优是迭代的，因此请按此顺序使用：

```text
冻结测量契约 -> 拟合 -> 扩展 -> 分析 -> 重新调优 -> 验证
```

## 首要答案清单

对于 MoE 优化工作流提示，请按此顺序呈现响应：

1. **冻结测量契约**：记录精确的模型和任务、硬件和拓扑、容器和提交、数据和路由语义、精度、序列和批形状、并行性、图作用域以及稳态指标窗口。将每个候选标记为训练等效或仅用于基准。
2. **拟合**：首先使模型内存可行。使用最小的模型并行性使其适用，优先选择选择性重新计算而不是完全重新计算，仅在重新计算和并行性不足时才添加卸载，并使用 `--fake-init-process-group` 对大型布局进行合理性检查。
3. **扩展**：在模型拟合后最大化 DP，将热通信保留在最快的互连内部，使用 PP 加 VPP 进行多节点扩展，优先选择 EP 而不是额外的 TP 用于专家层，当长上下文使注意力内存占主导地位时添加 CP。
4. **分析**：识别主导墙：内存、通信、主机开销或计算。
5. **重新调优**：根据分析的瓶颈一次改变一个变量。调度器、重叠、降低精度、CUDA 图和重新计算是候选者，而不是硬件默认值。
6. **验证**：使用短匹配屏幕拒绝候选者，然后运行获胜者至少 50 步。验证请求的后端或图重放是否实际运行，测量声明的预热窗口，并报告损失健康、跳过/NaN 迭代、内存、步长时间和模型 TFLOPS/GPU。
7. 包括精确的并行折叠网格：`Attention: TP x CP x DP x PP` 和 `MoE: ETP x EP x EDP x PP`。
8. 使用 `alltoall` 进行安全启动，然后在它们的软件包和目标拓扑支持它们时 A/B 测试 `flex` + `deepep` 和 `flex` + `hybridep`。从 BF16 和急执行开始；仅在分析证明其合理性后引入较低精度或最窄的有用 CUDA 图作用域。

## 阶段 0：冻结测量契约

只有在以下保持固定（除非它们是测试的唯一变量）时，比较才有效：

- 桥接器、MCore、Transformer 引擎、容器、CUDA 和 NCCL 版本
- GPU 数量、SKU、节点拓扑和启动器/环境设置
- 模型、任务、数据路径、序列长度、MBS、GBS 和优化器设置
- TP、PP、VPP、CP、EP、ETP 和 DP 布局
- 路由语义、精度、重新计算、调度器、重叠和图作用域
- 预热和稳态时间窗口

分离两个接受类别：

- **训练等效** 变化保留预期的路由、损失、数据、优化器和检查点/恢复行为。
- **仅用于基准** 变化（如强制负载平衡）对于受控的内核研究很有用，但无法建立生产训练的正确性或收敛。

## 阶段 1：使运行内存可行

在追求吞吐量之前，从可靠的配置开始。

推荐顺序：

1. 使用仍然适用的最小模型并行量。
2. 在回退到完全重新计算之前打开选择性重新计算。
3. 仅在重新计算和并行性仍然不足时才添加卸载。
4. 使用 `--fake-init-process-group` 在在单个 GPU 上对大型并行布局进行合理性检查，然后再烧集群时间。

### 重新计算指导

对于 MoE 运行，优先选择选择性重新计算：

- 好的首选：`layernorm`、`core_attn`、`moe_act`、`mlp` 或模型特定模块（`shared_experts`、`mla_up_proj`）
- 仅在运行仍然不适用时使用完全重新计算
- 启用 CUDA 图后重新考虑重新计算，因为某些图作用域和完全重新计算路径混合得不好

作为一般规则，细粒度重新计算通常可以恢复大部分所需内存，同时保持吞吐量与不重新计算的基线更接近，而不是完全层重新计算。

## 阶段 2：为扩展选择并行性

优先顺序：

1. 模型拟合后最大化 DP。
2. 尽可能将热通信路径保留在快速互连内部。
3. 使用 PP，如果需要，加 VPP 进行多节点扩展。
4. 优先选择 EP 而不是额外的 TP 用于专家层。
5. 当序列长度使注意力内存占主导地位时添加 CP。

### 并行折叠

并行折叠将注意力和 MoE 并行性解耦，因此您不必选择单一妥协布局：

```text
Attention: TP × CP × DP × PP
MoE:       ETP × EP × EDP × PP
```

关键旋钮：

- `--expert-model-parallel-size`
- `--expert-tensor-parallel-size`

当注意力偏好某些 TP 或 CP，但专家层受益于比密集层更能容忍的更大 EP 度时使用它。

## 阶段 3：分析主导瓶颈

| 瓶颈 | 看起来像什么 | 主要修复方法 |
|---|---|---|
| 内存 | 仅使用激进完全重新计算或预热期间 OOMs 才能运行 | 选择性重新计算、FP8、卸载、更好的 PP 布局 |
| 通信 | Nsight 显示大型 all-to-all 或集体块 | DeepEP 或 HybridEP、EP 重叠、DP/TP 重叠、更好的 PP 布局 |
| 主机开销 | GPU 间隙、启动器限制的跟踪、Python 开销 | CUDA 图、`--manual-gc`、更高的 MBS、CPU 亲和力调整 |
| 计算 | 在解决通信和主机问题后 SM 利用率低 | 组合 GEMM、融合工作、FP8、调度器特定内核调优 |

### 分析重叠而不误读它

使用未分析的稳态迭代作为接受指标，并使用匹配的分析进行因果解释：

1. 一次改变一个重叠或调度器变量；保持路由、图作用域、并行性、批形状和运行时固定。
2. 为通信内核和计算内核构建间隔联合，然后测量它们的交集以量化隐藏通信。
3. 不要添加内核持续时间并将结果称为墙时间。并发内核可能由于 SM 或带宽争用而运行更长时间，即使暴露的 GPU 活动联合和端到端步长时间下降。
4. 使用调度/组合 NVTX 范围、稳态步长时间、模型 TFLOPS/GPU、损失有限性、跳过/NaN 计数和峰值内存来证实跟踪。

在受控的 16×H100 Qwen3 30B-A3B HybridEP 运行中，纯 EP 重叠将 GEMM/注意力隐藏的通信从 0.11% 增加到 36.55%。未分析的步长从 24.7138s 下降到 20.9920s，吞吐量从 244.039 上升到 287.305 模型 TFLOPS/GPU。`delay_wgrad_compute` 保持禁用。

## 阶段 4：根据证据重新调优

选择针对分析瓶颈的最小候选者，一次改变一个变量。

### 调度器和重叠指导

将调度器选择作为瓶颈修复，而不是硬件查找表。

- `moe_token_dispatcher_type="alltoall"`：最安全的启动路径，适用于较小的 EP 大小
- `moe_token_dispatcher_type="flex"` + `moe_flex_dispatcher_backend="deepep"`：DeepEP 安装且通信暴露时的候选者
- `moe_token_dispatcher_type="flex"` + `moe_flex_dispatcher_backend="hybridep"`：在 NVL8 和 NVL72 系统上对拓扑敏感的候选者，当 HybridEP 安装时

HybridEP 加纯 EP 重叠是当前测量的标准 16×H100 Qwen3 30B-A3B 形状的获胜者，而标准的 256×H100 Qwen3 235B 配方使用 `alltoall` 加重叠。在目标容器中测试基准后端兼容性和吞吐量；GPU 名称和 EP 度本身并不能决定获胜者。

如果 all-to-all 路径在分析中可见，则将调度器调整与以下组合：

- `--overlap-moe-expert-parallel-comm`
- `--overlap-grad-reduce`
- `--tp-comm-overlap`

首先测试纯 EP 重叠、共享专家重叠和延迟权重梯度计算作为单独的候选者。即使一个组件在另一个模型上有所帮助，组合也可能导致回归。

### 低精度候选矩阵

从验证的 BF16 基线开始。硬件能力仅决定哪些低精度候选者是合法的；它不保证加速。

| 平台 | BF16 稳定后的候选者 |
|---|---|
| Hopper | 目标堆栈支持的逐张量、当前缩放或块状 FP8 |
| Blackwell | MXFP8 或另一个支持的 FP8 配方 |
| Blackwell，速度优先探索 | BF16/FP8 路径稳定后的 NVFP4 |

保持路由在 FP32。最大的胜利通常来自专家 GEMM 和其他重型矩阵数学，而不是试图量化每个小的 MoE 组件。要求日志或跟踪显示预期的内核运行，并根据端到端稳态步长时间而不是理论峰值 FLOPS 判断候选者。

### MoE 的 CUDA 图

仅在分析显示有意义的主机/启动间隙后使用 CUDA 图。对于无丢失 MoE，从最窄的部分 TE 作用域图候选者开始：

- `moe_router`
- `moe_preprocess`

仅在模型支持且改进相同匹配堆栈时才添加 `attn`。成功的捕获不是加速的证据，图胜利可能在调度器、重叠或精度变化后消失。

此路径将动态专家工作保留在图外。预算额外内存，验证形状保持静态，确认重放而不是仅捕获，并仅测量捕获后迭代。

仅对图友好的工作负载（如丢弃和填充或紧密控制的静态形状实验）使用全迭代图。

## 阶段 5：验证并打包证据

当工作负载允许时，使用 6–12 个预热后迭代进行廉价筛选。对于选定的候选者，运行至少 50 步并报告一个固定的稳态窗口，例如步骤 41–50。最终证据包应包含：

- 精确的命令/配置差异、提交、容器、硬件和拓扑
- 声明的路由/数据语义和训练等效与仅用于基准标签
- 证明预期的调度器、精度内核、重叠和图重放处于活动状态
- 来自相同未分析稳态窗口的步长时间和模型 TFLOPS/GPU
- 当生产路径需要时，有限的损失、跳过/NaN 计数、峰值内存和检查点/优化器状态验证
- 声称的因果机制的匹配 A/B 分析证据

不要将最终多变量获胜者的总增益归因于一个早期的 A/B。例如，Qwen3 重叠实验将提升从 244.039 上升到 287.305 TFLOPS/GPU；后来的标准配方在额外的 HybridEP 调优后达到 299.352。它们回答了不同的问题。

## 陷阱

1. **不要以错误的顺序优化**：拟合模型和选择合理的并行性比微观优化更重要。

2. **平台改变了限制墙**：H100 级别的运行通常感觉更通信受限，而 GB200 或 GB300 运行通常更早暴露 CPU 或启动开销。

3. **FP8 MFU 可能看起来误导性低**：切换精度模式时，比较绝对吞吐量以及 MFU。

4. **CUDA 图和重新计算相互作用**：TE 作用域图通常与选择性重新计算配对，而不是全面的完全重新计算。

5. **并行折叠在大规模下不是可选的**：一旦注意力和专家层想要明显不同的布局，单一的共享 TP 或 EP 计划就会对两者征税。

6. **求和内核时间不是暴露时间**：验证重叠时使用间隔联合和通信/计算交集。

7. **仅用于基准语义不是生产接受**：强制路由、合成数据或禁用的优化器/检查点路径必须单独披露和验证，与训练等效结果分开。

8. **特征激活需要证据**：当后端可以回退、图可以捕获而不帮助或较低精度的配方可能错过预期内核时，配置转储是不够的。
