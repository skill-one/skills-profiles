# cuOpt Server (通用)

cuOpt REST 服务器的域概念。此处不包含部署命令或客户端代码。

## 服务器功能

- 通过 HTTP 接收优化请求（路由、线性规划、混合整数线性规划）。
- 返回请求 ID；通过该 ID 进行轮询以获取解决方案。
- 不支持通过 REST 进行二次规划 (QP)。

## 支持的问题类型

| 问题类型 | 支持 |
|----------|:----:|
| 路由     | ✓    |
| 线性规划 | ✓    |
| 混合整数线性规划 | ✓    |
| 二次规划 | ✗    |

## 请求流程（概念性）

1. 客户端以所需模式发送问题数据（矩阵、任务、车队、求解器配置）。
2. 服务器返回 `reqId`。
3. 客户端使用 `reqId` 轮询解决方案端点，直到作业完成。
4. 响应包含状态信息，在成功的情况下，还包含解决方案（路线、目标值、原始值等）。

## 部署和使用所需问题

如果不清楚，请询问以下问题：

1. **问题类型** — 路由或线性规划/MILP？（不支持二次规划 QP。）
2. **部署方式** — 本地、Docker、Kubernetes 或云？
3. **客户端** — 哪种语言或工具将调用 API（例如 Python、curl、其他服务）？

## 关键端点（概念性）

- 健康检查。
- 提交请求（POST）。
- 通过请求 ID 获取解决方案（GET）。
- OpenAPI 规范（例如用于有效载荷格式）。
