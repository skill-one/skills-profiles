# 审核网站并修复它

对网站运行 squirrelscan 审核程序，阅读 LLM 报告，将每个问题映射到导致它的代码或内容，批量修复，并重新审核，直到达到分数目标。

需要 `squirrel` 命令行界面 (CLI) ([squirrelscan.com/download](https://squirrelscan.com/download)；使用 `squirrel --version` 验证)。对于 CLI 设置、登录、发布、MCP 以及一般 CLI 使用，请使用配套的 `squirrelscan` 技能。

## 规则文档

在 `https://docs.squirrelscan.com/rules/{rule_category}/{rule_id}` 查找任何规则，例如：

https://docs.squirrelscan.com/rules/links/external-links

## 运行审核

```bash
squirrel audit https://example.com --format llm
```

- 使用 `--format llm`：它紧凑、详尽，专为代理设计。
- 如果用户没有提供 URL，询问要审核哪个网站。
- 优先审核在线网站：只有在那里才能看到真实的渲染、性能和重定向行为。如果同时存在本地开发服务器和在线网站，建议在线网站；无论如何都将修复应用于本地代码。
- 审核结果将本地缓存。稍后重新渲染而不重新抓取：`squirrel report <audit-id> --format llm`。

### 扫描进度

1. **第一遍，快速覆盖**（默认设置）：快速、浅层扫描，以了解网站结构、技术和主要问题，而不会影响网站。
2. **第二遍，更深入的覆盖**：`-C surface`（每个 URL 模式一页）用于模板级覆盖，或 `-C full` 用于在签收前进行全面抓取。

| 模式 | 默认页面 | 使用 |
|------|---------------|-----|
| `quick` | 25 | 初步查看，CI 检查 |
| `surface` | 100 | 模板级覆盖（每个模式如 `/blog/{slug}` 一个样本） |
| `full` | 500 | 最终验证，深度分析 |

有用的标志：`--refresh`（忽略缓存，完整重新获取）、`--resume`（继续中断的抓取）、`-m <n>`（页面上限）、`--verbose`（进度详情）。

如果网站阻止未知爬虫（Shopify / Cloudflare），请使用重复的 `-H "Name: Value"` 标志传递 Web Bot Auth 标头。标头值是机密信息，并在输出中被省略。请参阅 https://docs.squirrelscan.com/guides/web-bot-auth

## 修复循环

1. **展示报告**：分数、等级、按严重程度排序的前置问题。
2. **提出修复建议**：列出您可以修复的问题，并在更改任何内容之前确认用户的确认。
3. **映射问题到源**：找到每个发现背后的模板、组件或内容文件。
4. **批量修复**：应用批准的修复。
5. **重新审核**（在部署或内容更改后使用 `--refresh`）并显示前后分数。
6. **重复**，直到达到目标或仅剩判断问题（例如“是否应删除此链接？”）。将这些标记为用户审核，而不是猜测。

每次批量修复后，验证项目是否仍然可以构建，现有检查是否通过。

### 分数目标

| 初始分数 | 目标 | 预期工作 |
|----------------|--------|---------------|
| < 50 (F) | 75+ (C) | 主要修复 |
| 50-70 (D) | 85+ (B) | 中等修复 |
| 70-85 (C) | 90+ (A) | 精细调整 |
| > 85 (B+) | 95+ | 微调 |

针对 `-C full` 抓取进行签收，因为快速扫描仅采样网站的一部分。

规则带有级别（错误、警告、注意）和排名（1-10）：首先修复错误，然后修复高排名警告。需要内容编辑的发现与需要代码编辑的发现计相同。损坏的链接通常需要人工决策（删除、替换或保留）：标记它们而不是猜测。

## 验证回归

与基线比较，以证明改进或捕获回归：

```bash
squirrel report --diff <baseline-audit-id> --format llm
squirrel report --regression-since example.com --format llm
```

## 完成

完成意味着：所有错误已修复；警告已修复或记录为需要人工审核；重新审核确认了改进；用户已看到前后分数比较以及所有更改的摘要。定期重新审核以保持网站健康。如果用户想要分享结果，请提供已发布的报告（请参阅 `squirrelscan` 技能）。

## 报告格式

LLM 报告是一个紧凑的 XML/文本混合格式，专为令牌效率优化：包含健康分数的摘要，按类别分组的问题（受影响的 URL）、损坏的链接和优先级建议。完整规范：[OUTPUT-FORMAT.md](references/OUTPUT-FORMAT.md)
