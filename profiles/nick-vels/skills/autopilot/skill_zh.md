# 自动驾驶

## 概述

自动驾驶将一个既定的想法从文字转化为一个可工作的项目，**在一个对话中完成**，而无需用户批准每个阶段。它是自包含的：它需要的所有规则都存在于 `phases/` 中。不需要安装其他技能。

两个想法承载了整个设计。

**顺序就是产品。** 代码是在倒数第二阶段编写的。它之前的一切都是为了决定“**要**构建什么”，而它之后的一切都是为了证明“**正确地**构建了什么”。

**简报是合同，不是设计。** 它引出了两个义务，它们故意朝着相反的方向拉动。

*任何东西都不能悄悄消失。* 用户的原始文字在发生任何事情之前都会变成一个编号的清单，并且每个阶段都以它为前提。打破天真编码的不是坏代码——而是一个在第三次重写左右停止存在的需求。

*简报不是设计。* 它是一个轮廓：它描述了快乐路径，而不是其下方——没有空状态，没有失败，没有中断，没有限制。解决这些问题是合法的工作，不是范围蔓延，这也是这个过程价值的重要来源。**要推进多远是用户的旋钮**，由 `[depth](#depth)` 参数设置。在任何设置下都不允许的深度是**脱离**简报的深度。

## 阅读这个技能

这个文件是协调者：模式、阶段顺序、关卡。每个阶段的规则都存在于 `phases/` 中，并且是在**阶段开始时读取，而不是之前**——这就是保持工作上下文小的原因。

**一次一个文件，并且永远不要提前。** 违反这个规则并不像违反它那样感觉：下一个文件很小，飞行计划已经规划好，在你已经阅读时打开它们似乎很整洁。它做的是将第 5 阶段的规则放入第 1 阶段正在思考的上下文中，并在整个运行期间保留它们。加载的单位是文件，而不是章节——一个读取会拉入整个东西，这就是为什么一个阶段需要而另一个阶段不需要的任何东西都是它自己的文件的原因。

**表格中两次的地方只读两次**——第 4 阶段的 `7-instruments.md`，第 5 和第 8 阶段的 `9-memory.md`，合法的地方是因为运行通常在这之间已经压缩。其他地方，因为“细节已经模糊”而重新阅读，买到的仍然是在上下文中仍然存在的东西的副本。

**压缩后，重新读取状态，而不是阶段。** `state.js`（它包含 `skillDir`、审查者和工单），`manifest.md`、`interfaces.md` 和你实际所在的阶段文件——这四个文件和别无其他。拉力是重新打开 `5-subagents.md` 来恢复线程；这花费了八千个代币重新读取你已经执行的规则，而线程从未在其中。

| 阶段 | 读取 | 产生 |
|---|---|---|
| 0 预飞行 | `phases/0-modes.md`、`phases/0-preflight.md`，然后 `0-instruments.md` 和 `0-memory.md` | 宣布模式，配置仓库，创建 `.autopilot/` |
| 1 清单 | `phases/1-manifest.md` | `brief.md`、`manifest.md` |
| 2 简报 | `phases/2-briefing.md` | 将答案记录到清单中 |
| 3 规格 | `phases/3-spec.md` | `spec.md` |
| 4 计划 | `phases/4-plan.md` | `tickets/NN-*.md`（或无——见层级）、`interfaces.md` 种子 |
| 5 子代理 | `phases/5-subagents.md` | 代码、提交、`interfaces.md` 增长 |
| 6 审查 | `phases/6-review.md` | 每个工单的审查 |
| 7 仪器 | `phases/7-instruments.md`——**在第 4 阶段**，当工单被裁剪时 | `state.js`、`dashboard.html` + `index.html`（为用户打开） |
| 8 最终 | `phases/8-final.md` | 盲目接受，最终报告 |
| 9 记忆 | `phases/9-memory.md`——**在第 5 和第 8 阶段** | `CLAUDE.md` / `AGENTS.md`、`docs/adr/`——项目作为下一个会话找到它的样子 |
| — | `phases/5-repair.md`——当工单返回任何不是 `DONE` 的情况时 | 修复路径、重试、规格修订 |
| — | `phases/rationalizations.md`——在失败的门控、在发现自己原谅某事时、在报告之前一次 | 无；它是一个清单 |
| — | `phases/polish.md`——仅使用 `polish` 参数时 | доводка 轮次 |

## 用户看到的文字

这些阶段在这个文件中有英语名称，用户永远不会看到它们。在聊天中、在仪表板和最终报告中，每个阶段**恰好有一个俄语单词**，这就是这个。两个词汇表用于一个过程，这是一个人阅读 README 然后在屏幕上找不到任何东西的方式。

| 阶段 | `stages[].id` | 用户 |
|---|---|---|
| 0 预飞行 | `preflight` | 准备 |
| 1 清单 | `manifest` | 要求 |
| 2 简报 | `briefing` | 简报 |
| 3 规格 | `spec` | 规格 |
| 4 计划 | `plan` | 计划 |
| 5 子代理 | `build` | 开发 |
| 6 审查 | `review` | 代码-审查 |
| 8 最终 | `final` | 接受 |

两条规则将它们联系在一起：

- **“开发”是整个运行，而不是一个阶段。** “开发正在进行”、“开发中断了”、“继续开发”——关于整个过程。因此第 5 阶段称为“开发”：否则一个词既表示部分也表示整体。并且“开发”在 `npm run build` 的意义上也不是它。
- **工作单元是“任务”。** 不是“任务”，不是“工单”，不是“issue”。 “任务”是用户提出的（简报）；一个词用于两件不同的事情会破坏报告和仪表板。

第 7 和第 9 阶段不是顺序的，并且每个阶段都沿着读取线分成两部分。仪器在第 0 阶段从 `phases/0-instruments.md` 抬起——模板、起始状态、更新仪式——`phases/7-instruments.md` 仅在工单被裁剪时打开。项目记忆在第 0 阶段从 `phases/0-memory.md` 抬起——哪个文件，骨架——`phases/9-memory.md` 在构建发现某事时打开，并在第 8 阶段再次打开，其中子代理从完成的代码中编写完整的描述。

## 三个旋钮

在 `/autopilot` 后键入的所有内容都分为四个部分：**模式**（`full`、`semi`、`interview`、`manual`——默认 `semi`）、**深度**（`strict`、`deep`——默认正常）、**完成**（`polish`——默认关闭）、**简报**（其他所有内容）。纯文字，没有连字符；任何无法识别的内容都是简报。

**所有三个的规则都在 `phases/0-modes.md` 中，在 Phase 0 与 `phases/0-preflight.md` 一起读取**——两种语言中的触发器、宣布已解析设置的打开块、每个深度允许什么，以及当用户在运行中途切换时会发生什么。它们在 Phase 1 之前决定一次，之后每个阶段都只应用它们；那个文件存在的目的是防止通过九个阶段携带四个模式而不是三个的理由。

这里保留的是后果：下面的表格，它说明每个模式更改了哪些单元格。关于旋钮的 两件事永远不会移动，并且它们在那里重复，因为它们不是校准——**没有模式移除清单关卡，没有模式移除安全关卡。**

## 何时使用

- 用户规定要构建什么，并期望完成品，而不是对过程的协作。
- 用户是非技术性的：不会阅读规格，判断工单粒度，或审查代码。
- “负责完成”、“直接构建”、“不要问多余的问题”。
- 用户希望与他们一步步拆解想法，而构建不需要他们——这就是**采访**模式，仍然是自动驾驶。
- 用户希望批准规格和工单，但不运行手动管道——这就是**手动**模式，仍然是自动驾驶。

**不使用时**：用户希望逐行共同编写代码（直接与他们合作）；任务是单个文件的小更改（直接做）；想法大于一个项目，并且其目的地不明确（先确定目的地，然后返回这里）。

## 飞行

| 阶段 | full | semi (默认) | interview | manual |
|---|---|---|---|---|
| 0 预飞行 | auto | auto | auto | auto |
| 1 清单 | auto | auto | auto | auto |
| 2 简报 | 跳过→自我简报 | 简报留下的开放部分——有时没有 | 对抗性通过，然后打开每个分支 | 相同 |
| 3 规格 | auto | auto | auto | 显示→等待明确的“好” |
| 4 计划 | auto, 仅通知 | auto, 可停止 | auto, 可停止 | 讨论→等待明确的“好” |
| 5 子代理 | auto | auto | auto | auto |
| 6 审查 | auto | auto | auto | auto |
| 8 最终 | 报告 + 假设 | 报告 | 报告 | 报告 |

**`polish` 在第 8 阶段内部添加一个步骤，在每种模式下**—— доводка 循环，在盲目接受和报告之间。它不改变上面的任何单元格：它不向用户提问，也不与用户批准任何东西。

**`interview` 和 `manual` 在恰好两个单元格上不同**——规格关卡和计划关卡。如果你发现自己以其他任何方式对待它们不同，其中一个是错误的。

**清单关卡在每种模式下运行。** 它们是针对用户自己的文字的检查，而不是请求用户的时间——没有模式购买跳过它们的权利。

| 关卡 | 之后阶段 | 通过条件 |
|---|---|---|
| **G1** | 2 简报 | 每个要求都有一个状态；没有留下 `open` 而没有记录原因 |
| **G2** | 3 规格 | 每个活动要求都是 `in-spec`、`deferred` 或 `dropped`，零 `open`——**并且一个独立的读者仅给出简报和规格发现没有遗漏** |
| **G3** | 4 计划 | 每个在规格中的映射到 ≥1 工单，**并且每个工单追溯到 ≥1 要求** |
| **G4** | 8 最终 | 盲目接受针对简报，规格保留；每个与清单的分歧报告 |

**G2 和 G4 是在飞行的两端进行的相同检查，并且两者都需要。** 它们衡量构建与用户自己的文字，而你的文字释义被拿走——G2 在答案是一段规格时，G4 在它是最后一次机会知道时。它之间的一切都针对规格，因为这是执行者实际得到的合同；通过从未见过它的子代理判断会产生无人能采取的行动的发现。

一个失败的关卡不是警告。它将阶段退回重做——见 `phases/1-manifest.md`。

**计划可以纠正；简报不能。** 当构建证明计划错误时——一个不持数据的模型、一个无法存在的假设接口——规格被修订，并且记录了代码证明的内容和日期的 `D##` 行。这是允许进入清单后唯一的东西，它永远不会退休一个要求，并且它永远不会是您有想法的路线。规则在 `phases/5-repair.md`。

## 秘密

凭证是用户的，不是代理的。本节绑定每个阶段；阶段不会重申它。

- **从不请求一个。** 没有密钥、令牌、密码、连接字符串或卡号是问题。*哪个*提供者是问题。*是否存在*帐户是问题。凭证不是。
- **在摄取时编辑。** 简报、每个用户答案和每个粘贴的片段在 `phases/1-manifest.md` 中的编辑门控*在它们到达文件之前*通过。检测到的秘密变成 `[REDACTED:<VAR_NAME>]`——变量名幸存，值不存。
- **“逐字”始终意味着“逐字编辑后”。** 无论这个技能何时要求用户的确切文字，它都要求编辑后的文字。这两个规则是一个规则。
- **通过名称引用它。** `STRIPE_SECRET_KEY`，而不是值。用户自己将值放入 `.env` 中；`.env` 在第一个提交之前在 `.gitignore` 中；最终报告列出了哪些名称仍然是空的。
- **泄露的秘密是停止条件。** 一个到达文件或提交的秘密会立即用纯语言报告，并建议旋转它。在第一个提交之前，在整个 `.autopilot/` 上运行编辑门控。

## 这个技能拥有的文件

```
.autopilot/
├── <YYYY-MM-DD>-<feature-slug>--wip/   一个运行；日期是它开始的那天，
│   │                    后缀表示它还没有着陆，将在第 8 阶段中
│   ├── <YYYY-MM-DD>-brief.md   用户的原始文字，编辑；稍后的更改附加
│   ├── manifest.md      R01…Rnn — 要求及其状态
│   ├── reference.md     结果应该像什么——用户的比较对象，永远不会是你的
│   ├── spec.md          规格
│   ├── interfaces.md    从规格的边界，然后是完成的工单构建
│   ├── handoff-NN-1.md  仅当工单超出一个上下文时——继任者需要什么
│   └── tickets/NN-<slug>.md
├── README.md            如何阅读这个文件夹，以及运行的注册——供人类：
│                        在 Phase 0 写入，每行运行和关闭都在 Phase 8 添加
├── state.js             运行状态，以及您唯一编辑的文件：阶段、工单、时间、债务
├── dashboard.html       人类视图——在 Phase 0 复制；包含状态快照
├── sync.py              每次更新后一次调用：快照到页面，如果它死了则服务器恢复
└── index.html           到 dashboard.html 的符号链接，以便面板的 `/` 是仪表板

CLAUDE.md | AGENTS.md   项目记忆——下一个会话首先读取的
docs/adr/               值得在运行中存活的决策——在 Phase 9 写入，层级 T2+
```

简报按其文件名进行日期排序，因为一个运行目录比一个会话更持久——目录的日期是运行开始的那天，简报的日期是简报被规定的日子。仪表板是为用户打开的，而不是描述给他们的：它显示了周期的八个阶段，运行现在在哪里，以及运行上的实时时钟，当前阶段和当前工单。

`.autopilot/` 是**这个**运行的记录；根目录中的记忆文件是项目当前状态，供下一个打开仓库的人使用；`docs/adr/` 是为什么它会以这种方式存在。自动驾驶在记忆文件中的内容存在于 `<!-- autopilot:start -->` 标记之间——用户在它们之外写的任何内容都是不可触及的。见 `phases/9-memory.md`。

这三个不是可互换的，并且分裂是保持规格可丢弃的原因。`spec.md` 在工作交付的那天一文不值；它里面的推理——为什么这个数据模型，构建证明了什么错误，哪个词意味着什么——在多年内仍然有价值，并且它随着 `.autopilot/` 消失，除非有东西将其路由出去。这就是 ADR 的作用。

`.autopilot/` 被提交，而不是忽略——它是用户记录承诺和交付的内容。一个留下 `.autopilot/` 下任何东西的运行没有发生。

## 判断

这个技能描述了一个过程，而不是产品。它的数字——层级、问题计数、故事计数、波浪宽度——是**校准的初始猜测，永远不会是目标**。为达到故事计数编写的规格，或为在层级内切割的计划，已经优化了规则而不是请求的人。

下面的规则是同一种东西。每一条都在这里，因为它是付费的，并且每一条都是一个论点——论点可能会输。如果一个规则会导致结果对用户更糟，故意破坏它，在一条线上说，然后继续。这是一个决定，决定会被记录。从不接受的是悄悄破坏一个，或者因为它是写下来的而保留一个。

**五条规则不是校准，也不会输。** 它们在每种模式下、每个深度、每个层级都有效：

1. **要求只有在用户**用自己的话，引用到清单中，**才能被移除——并且附加到简报中，以便独立的关卡可以看到它。** 用户在飞行中途添加的也适用相同的规则。
2. **从不请求、回声或写入秘密**——不写入文件、提示、提交、报告。
3. **关于用户的任何事实永远不会被编造。** 价格、文本、地址、帐户保持可见占位符，直到它们提供它们。
4. **不可逆或面向外部的行动是一个问题**——部署、发布、付款、向第三方发送消息、删除数据、重写历史。
5. **协调者不编写项目的代码。** 它的键盘达到 `.autopilot/`、记忆文件和 git。其他所有东西——一个值得两行修复、一个红测试、一个审查发现——都传递到子代理。规则在 `phases/5-subagents.md`。

其他一切都是论点。

## 当它出错时

两个目录存在于 `phases/rationalizations.md` 中——导致用户得到他们要求的东西以外的东西的借口，以及意味着必须重新开始一个阶段的红旗。**在三个时刻阅读那个文件：关卡失败时、当你注意到自己在组装跳过某个东西的论点时，以及报告之前一次。**

它们是检查，不是指令：它们中的任何东西都不会告诉你如何运行一个阶段，并且每个阶段的自己的机制都在它自己的文件中检查。保留十五万个字符的失败模式从第一个转弯开始——在永远不会刷新的一个上下文中——意味着在运行的每一步上为回答三个中的它们的问题而支付它们。上面的五条规则是必须在你脑海中而不需要查找的；其余的是一个目录，目录是打开的。
