# 小说创作工作坊

协作式小说创作的编辑工作流程分为三个阶段：故事圣经构建、章节发展和读者测试。

## 会话连续性

小说项目可能持续数周或数月。Claude 在会话之间没有记忆，因此故事圣经是你的持久状态。

- **会话开始时：** 在进行任何其他工作之前，先阅读 `story-bible.md`（或项目命名的其他文件）。快速浏览 `sessions/` 中的最近文件，查找未解决的线索。
- **会话结束时：** 在 `sessions/YYYY-MM-DD_topic-slug.md` 中写一个简短笔记，总结已完成的工作、做出的决定和停止点。两到五句话就足够了。
- **当基础发生变化时：** 当前提、人物传记、世界规则或主要情节转折发生变化时，立即更新故事圣经。故事圣经是真相的来源，而不是一次性模板。
- **提出未解决的问题：** 在开始新工作时，列出先前会话中留下的未解决问题，并询问用户要解决哪些问题，然后再继续。

## 何时使用

此技能适用于：

- ✅ 长篇小说（小说、中篇小说、短篇小说集）
- ✅ 需要人物/情节一致性的多章节手稿
- ✅ 需要发展性或行文编辑的小说项目
- ✅ 具有复杂世界观或多个视角角色的故事

## 何时 NOT 使用

此技能不适用于：

- ❌ 短篇故事或单个场景（< 2000 字）- 工作流程对它来说太轻量级
- ❌ 诗歌或实验性散文 - 需要不同的编辑方法
- ❌ 剧本或舞台剧 - 不同的格式惯例
- ❌ 技术写作、文档或学术论文
- ❌ 商业写作或营销文案

对于叙事非虚构作品（回忆录、带有故事元素的自助类书籍），请使用 `narrative-nonfiction` 技能。

## 编辑角色

角色主要用于阶段 2（章节发展）和阶段 3（读者测试）；阶段 1 是自由形式的故事圣经构建，不需要调用角色。通过请求特定视角来在这些角色之间切换：

| 角色 | 调用方式 | 重点 |
|------|------------|-------|
| **发展性编辑** | "作为发展性编辑..." | 情节、节奏、结构、风险、主题 |
| **行文编辑** | "作为行文编辑..." | 语句节奏、用词、"展示而非讲述" |
| **人物顾问** | "作为人物顾问..." | 声音一致性、动机、弧光、关系 |
| **连续性追踪者** | "作为连续性追踪者..." | 时间线、世界事实、内部一致性 |
| **头脑风暴伙伴** | "头脑风暴模式..." | "如果...会怎样" 探索、问题解决、突破僵局 |

仅加载与当前调用的角色匹配的参考文件。不要在会话开始时预加载所有参考文件——这会浪费上下文预算。如果会在会话中途切换角色，请加载新的参考文件，并将先前文件视为超出范围，除非工作明确连接了两者。

有关每个角色的详细指导，请参阅 `references/`。

## 阶段 1：故事圣经构建

**目标：** 在起草或编辑之前，建立共同的故事基础。

### 初始问题

1. 文学和目标读者？
2. 核心前提/一句话梗概？
3. 主角：他们是谁，他们想要什么？
4. 核心冲突？
5. 读者预期的情感旅程？
6. 已写内容与计划内容的比例？

### 故事圣经组件

**情节：** 前提、三幕结构/节拍表、主要转折、结局（即使粗略）

**人物：** 主角（想要/需要/创伤/弧光）、反派（动机/威胁）、配角（功能/关系）、POV 声音笔记

**世界：** 背景（时间/地点/规则）、科技/魔法系统、社会结构、感官调色板

**主题：** 核心问题、道德论点、反复出现的母题

如果存在故事圣经文档，请查看它。如果没有，请使用 `assets/story-bible-template.md` 提供创建一个。

**示例故事圣经条目（人物）：**
```
ALEX CHEN - 主角
想要：揭露阴谋并洗清自己的名字
需要：学会相信自己的直觉而不是机构权威
创伤：导师在之前的机构背叛了她，导致事业受挫
弧光：独行侠 → 意识到自己需要盟友 → 与团队建立信任
声音笔记：分析性，压力下会讲冷笑话，避免使用情感语言
关键关系：与联络员紧张（想要信任，但无法完全信任）
```

**退出条件：** 对故事基础有自信的理解。可以在不重新阅读笔记的情况下描述主角的想要与需要、预测情节影响并识别主题线索。

## 阶段 2：章节发展

**目标：** 通过头脑风暴 → 筛选 → 起草 → 修订循环来起草或完善章节。

**起草新章节？** → 创建工作流程 | **编辑现有章节？** → 编辑工作流程

### 创建工作流程

1. **场景规划**
   - 必须发生什么（情节）？谁的视角？
   - 章节的情感弧？
   - 读者在结束时学到/感受到什么？

2. **头脑风暴转折点**（5-15 个选项）：开场钩子、关键时刻、对话、感官细节、结尾

   **示例（惊悚场景）：** 同一辆车连续三天出现在咖啡店外 | 3 点钟手机震动，来自被屏蔽的来电者 | 门下方的监视照片 | 同事提到只有监视才知道的细节 | 窗户中的相机镜头反射 | 死信箱被清空 | 安全屋钥匙插不进 | 联系人错过了第一次检查

   然后筛选："哪些能立即制造紧张感？可以合并任何吗？"

3. **筛选：** 询问要保留、合并或丢弃哪些内容。原因有助于校准。

4. **起草：** 写章节。使用 `str_replace` 进行修订，不要重新打印。

5. **修订：** 迭代反馈。在 3 次修订后变化最小，询问："什么可以删减？"

### 编辑工作流程

1. **阅读和诊断：** 章节试图做什么，在哪里成功，在哪里失去能量/清晰度

2. **调用角色：** 结构/节奏 → 发展性 | 语句 → 行文 | 声音 → 人物 | 事实 → 连续性

3. **提出更改：** 具体手术性编辑，附带简短的"为什么"

4. **实施：** 使用 `str_replace`。更改后链接到文件。

5. **迭代：** 直到章节实现其目标

### 角色特定指导

当调用特定编辑角色时，加载相应的参考文件：

- 发展性编辑 → `references/developmental-editing.md`
- 行文编辑 → `references/line-editing.md`
- 人物工作 → `references/character-work.md`
- 连续性 → `references/continuity-tracking.md`
- 头脑风暴 → `references/brainstorming.md`
- 惊悚类特定技巧 → `references/thriller-craft.md`
- 科幻世界观构建 → `references/scifi-worldbuilding.md`

## 阶段 3：读者测试

**目标：** 验证手稿在作者不知情的情况下是否有效。

**使用新的子代理（没有故事圣经）：**

1. **理解力：** 他们能否总结情节，理解动机，识别风险？
2. **参与度：** 他们在哪里失去兴趣，有疑问，感到困惑？
3. **情感：** 关键时刻是否到位？结局是否令人满意？主题是否清晰？

**常见问题：** 动机不明确 | 节奏滞后 | 未应得的时刻 | 混乱

**如果遇到困难：** 识别差距 → 返回阶段 2 → 重新测试

**退出条件：** 读者理解并参与，无需作者解释。

## 自检：这是否有效？

使用这些检查点来验证你是否正确遵循了工作流程。

**故事圣经构建后：**
- [ ] 你能否在不重新阅读笔记的情况下描述主角的想要与需要？
- [ ] 你能否预测反派对新的场景的反应？
- [ ] 你是否理解本书探索的主题问题？
- [ ] 你能否用 2-3 句话总结三幕结构？

**调用角色后：**
- [ ] 你是否在请求中明确说了"作为[角色名称]..."？
- [ ] 反馈是否集中在该角色的领域（发展性 = 结构，行文 = 语句）？
- [ ] 你是否在一个遍历中避免了来自多个角色的反馈？

**进行编辑后：**
- [ ] 你是否使用 `str_replace` 进行手术性更改，而不是重新打印整个部分？
- [ ] 你能否说明更改的内容以及为什么它更好？
- [ ] 该更改是否与故事圣经一致（人物声音、情节逻辑、世界规则）？

**头脑风暴后：**
- [ ] 你是否在选择一个之前生成了 5+ 个选项？
- [ ] 你是否通过协作筛选而不是接受第一个建议？
- [ ] 你能否解释为什么选定的选项比其他选项更强？

**在声称"完成"之前：**
- [ ] 是否有新的子代理（没有故事圣经背景）阅读了手稿？
- [ ] 新的读者是否理解情节、人物动机和风险？
- [ ] 是否识别并解决了任何差距或混乱点？

如果你对任何检查点回答"否"，请在继续之前返回该阶段。

## 停止点

每个角色和阶段都有明确定义的结束点。在它结束。不要自动进入下一个角色，不要默默扩大范围，不要在你被要求诊断时开始起草。

| 工具/阶段 | 停止时... | 然后 |
|--------------|--------------|------|
| **故事圣经构建（阶段 1）** | 故事圣经自检通过 | 交还给作者。不要自动进入起草。 |
| **发展性编辑** | 完成请求范围内的完整结构遍历并交付问题清单 | 等待作者应用编辑。不要循环重写，除非明确要求。 |
| **行文编辑** | 行文编辑一个章节（或命名范围）；在 3 次修订后变化最小，询问"什么可以删减？"一次 | 如果没有进一步指示，停止。行文编辑有一个自然的上限。 |
| **人物顾问** | 对命名人物/场景的一个咨询完成 | 不要反射性地检查其他人物或场景。等待下一次调用。 |
| **连续性追踪者** | 审计产生标志列表 | 停止。不要自动修复。作者决定哪些标志是真实的以及如何解决。 |
| **头脑风暴伙伴** | 筛选步骤产生一个选择方向（或 5+ 个选项审查和拒绝） | 交还。不要起草到一个章节，除非明确要求。 |
| **读者测试（阶段 3）** | 新的子代理的报告交付 | 停止。作者决定是否返回阶段 2 以及基于哪些发现。 |
| **会话** | 达到停止点或上下文窗口正在填充 | 如果基础发生变化，更新故事圣经；写一个 `sessions/` 笔记；停止。 |

如果作者明确要求你继续通过停止点，可以——但请说明即将发生的事情（"我现在将从连续性审计转移到应用修复"），以便范围变化是可见的。

## 常见错误

| 错误 | 发生原因 | 修复 |
|---------|---------------|-----|
| **跳过故事圣经** | "我足够了解我的故事" | 故事圣经不是为你——而是为 Claude。没有共享上下文，反馈将错过关键故事元素。构建它。 |
| **没有角色的通用反馈** | 匆忙，忘记调用特定角色 | 在提示中明确说"作为发展性编辑..."或"作为行文编辑..."。不同的视角捕捉不同的问题。 |
| **重新打印整个章节** | 习惯于其他编辑环境 | 使用 `str_replace` 进行手术性更改，不要重新打印。重新打印会烧毁上下文并使更改难以跟踪。更改后链接到文件。 |
| **在结构之前进行行文编辑** | 想要立即"修复"语句 | 如果情节/节奏/人物问题存在，行文编辑是浪费精力。始终先进行发展性遍历。见示例。 |
| **跳过读者测试** | "我已经读过它很多次了" | 你有作者背景。读者测试使用没有故事圣经的新子代理来捕捉读者会遇到的差距。 |
| **一次使用太多角色** | 试图一次性修复所有问题 | 每次调用一个角色。发展性 → 人物 → 行文 → 连续性。专注的反馈是可操作的反馈。 |
| **没有筛选的头脑风暴** | 接受第一个听起来不错的想法 | 生成 5-15 个选项，然后筛选。第一个想法很少是最好的想法。数量使质量成为可能。 |

### 示例：发展性编辑与行文编辑

**同一段落，不同视角：**

> Sarah 走进办公室。她的老板看起来很生气。"我们需要谈谈，"他说。她坐了下来，紧张不安。

**行文编辑反馈（语句级）：**
- "Walked" 太弱——尝试 "strode" 或 "slipped"
- "Looked angry" 告诉而不是展示——描述皱眉、紧绷的下巴
- "Nervously" 是一个副词拐杖——通过动作展示紧张

**发展性编辑反馈（结构/风险级）：**
- Sarah 在这个场景中想要什么？她的老板想要什么？
- 如果这是对抗，我们需要铺垫——冲突历史是什么？
- 风险感觉低——为什么这次对话对故事很重要？
- 节奏：这是进行这场对抗的合适章节吗，还是应该更长地积累紧张？

**区别：** 行文编辑润色句子。发展性编辑确保场景在故事中占有一席之地。始终先进行发展性遍历。

## 格式查找

当此技能的诊断模式（发展性编辑批评、连续性追踪标志）产生发现时，发出符合 `../../references/finding-schema.json`：`audit`（使用模式名称，例如"developmental-editing"）、`technique`（命名的工艺技术——例如"Want/Need/Wound/Lie alignment"）、`severity`（注释/建议/警告）、`location`（文件/行/引用）、`issue`、`confidence`（"判断"——此技能没有确定性组件），以及可选的 `exemplar`（内联单句说明，因为此技能没有经过策展的示例库——可以机会主义地增长）。头脑风暴和起草建议输出不在此合同的范围内。
