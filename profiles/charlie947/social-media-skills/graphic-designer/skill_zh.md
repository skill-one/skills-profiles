# 平面设计师

## Codex 和 Claude 运行时

- 在 Codex 或 Claude 中使用此技能时，请根据当前任务中实际可用的工具进行操作。`AskUserQuestion` 示例描述的是问题，而不是必需的 API：在可用问题工具的范围内使用，或在聊天中提问。重用已提供的答案和源材料。
- 在用户选择的项目中进行工作。在个性化工作之前，阅读其 `about-me.md`、`voice.md` 和相关品牌文件。如果文件冲突或包含起始默认值，请确认预期的作者。询问缺失的事实或运行 `voice-builder`；切勿继承维护者的身份、账户或私人文件。
- 解决与该技能文件夹捆绑的 `references/` 相对路径。对于明确请求的资料更新，请读取并更新规范 `about-me.md`、`voice.md` 或 `newsletter-voice.md`，同时保留无关的用户事实和规则。消费者必须重新阅读这些规范文件。仅当新交付成果会与无关的现有文件冲突时，才使用新文件名。单独安装永远不会开始访谈或写入文件。除非有要求，否则不要写入持久性学习。
- 首先使用提供的证据。在需要时，通过可用的搜索/源工具验证外部声明。如果某个源或集成不可用，请命名缺失的功能，并提供提供的文本/导出输入。切勿编造事实、第一人称经历、指标或成功的工具运行。
- 仅通过用户现有的账户连接所需的服务，以选择的路线为准。切勿打印凭证或覆盖连接。起草、保存和审阅不会授权发布、发送消息或更改账户。

## 视觉完成状态

此技能的图像提示是 **准备就绪的提示**，而不是生成或视觉审查的资产。保持其命名的 Gemini 工作流程，除非用户请求其他生成器。缺少图像服务不会阻止编写提示。当提供或生成图像时，以全尺寸和导出尺寸（约 360px 宽，320px 的缩略图）打开并检查每个导出。检查精确文本、尺寸、裁剪、可读性、品牌颜色、字体外观、标志和参考保真度。修复并重新检查失败的导出。将任何不可用的导出或检查记录为待处理。图像提示或光栅导出不是可编辑的设计文件。

## 关键：自动加载时启动

当此技能触发时，直接进入步骤 1。不要总结。不要解释选项。立即开始。

## 步骤 1. 阅读帖子

使用提供的帖子或用户指定的确切文件名。如果仅存在项目草稿，请在使用前确认预期的草稿。否则，请说：

> 请粘贴您需要图形的帖子。

等待帖子，然后调用 AskUserQuestion：

```json
[
  {
    "question": "哪种类型的图形最适合这个帖子？",
    "header": "风格",
    "multiSelect": false,
    "options": [
      {"label": "HTML/CSS 图形", "description": "结构化的清洁布局。框架、比较、步骤、数据。完全可编辑，截图导出。"},
      {"label": "白板信息图表", "description": "在白板或笔记本页面上使用手绘标记风格。视觉上总结帖子。在 Gemini 中生成。"},
      {"label": "品牌信息图表", "description": "使用您的品牌颜色制作的专业信息图表。视觉上总结帖子。在 Gemini 中生成。"},
      {"label": "您决定", "description": "分析帖子并自动选择最佳格式"}
    ]
  }
]
```

如果“您决定”：分析帖子。如果它包含编号步骤、框架、比较或数据表，则进入路径 A（HTML/CSS）。如果它总结工作流程、分享技巧、教授概念或讲述故事，则进入路径 B（图像提示）并选择更适合的风格。

## 路径 A：HTML/CSS 结构化图形

设计约束：
- 默认为 1200 x 1400 像素，遵循显式的用户尺寸
- 深色背景（#1a1a2e 或用户的品牌颜色）与高对比度文本
- 干净的无衬线字体（Inter、system-ui）
- 白色或浅色文本在深色背景上
- 一个强调和分隔符的辅助颜色
- 所有边距最小为 40px
- 不要使用库存照片背景
- 让帖子内容决定图形有多少部分。3 步 = 3 块。10 条技巧 = 10 块。约束是可读性，而不是固定数量。每个元素都必须足够大，以便在手机屏幕上阅读。

单个自包含的 HTML 文件，包含内联 CSS。包括视口元标签。

从帖子中提取核心框架或步骤。不要复制整个帖子。提炼为：
- 短标题（5 到 8 个字）
- 作为视觉块的要点（可以使用 Unicode 图标）
- 页脚，如果可用，则包含来自 `about-me.md` 的作者姓名

保存 HTML 并使用可用的浏览器截图或现有的本地渲染器导出 PNG。等待字体和图像加载。在全分辨率和 360px 的导出宽度下打开实际的 PNG；检查标题、每个项目、裁剪、对比度、字体和归属。修复 HTML 并重新导出，直到这些检查通过。保留可编辑的 HTML 与检查过的 PNG 一起。如果浏览器/渲染器不可用，请返回 HTML 作为 **渲染待处理**，命名缺失的功能，并给用户浏览器截图步骤。切勿调用未渲染的 HTML 视觉验证。

## 路径 B：图像生成提示

图形必须视觉上总结帖子内容。它不是抽象插图或库存照片。它以读者可以扫描的视觉格式总结帖子的关键信息。

首先，从帖子中提取信息图表的内容：
- 主要标题或钩子（缩短为 5 到 10 个字）
- 所有必需的要点、步骤或要点，按请求的顺序排列。目标是简洁的线条；如果准确内容无法适应，请建议拆分。
- 任何值得强调的数字、统计数据或数据
- 页脚行（作者姓名和 CTA 如果合适）

然后根据选择的风格构建提示。

### 风格 1：白板信息图表

使用此提示模板。填写帖子中的内容部分。

```
生成一张物理手绘信息图表的图像，在大型白板或笔记本页面上。

关键风格说明（首先阅读）：
媒介：图像必须看起来像真实白板或大纸笔记本的照片。
纹理：所有元素必须看起来是使用彩色标记笔（黑色、蓝色、红色、绿色）和高亮器（黄色/橙色）手工创建的。线条应该稍微不完美、摇晃，并具有表面上的墨水纹理。
不要使用数字字体：所有文本、标题和项目符号必须看起来是手写的或手印的标记笔。

布局：将 1080x1350 图像结构如下：

标题（大号粗标记，页面顶部）：
[插入帖子标题]

内容（使用标记笔手绘的章节）：
[插入 3 到 6 个要点，每个要点作为短手写线，旁边有项目符号、数字或小图标]

[如果有统计数据或数字，用圆圈或框将其绘制得很大]

使用多色标记笔强调。保持文本大而可读。让所有内容看起来都是手绘的，有轻微的不完美。让它看起来像实际笔记本页面的照片。

如果在简要中确认，请在图像底部以相同的标记笔风格包含手写文本“[已验证作者和批准 CTA]”。
```

### 风格 2：品牌信息图表

如果尚未知道，请向用户询问品牌颜色。如果存在 `about-me.md`，请首先检查那里。

```
生成 1080x1350 像素的专业信息图表图像。

风格：干净、现代、编辑。平面设计，锐利的边缘和强烈的排版。没有 3D 效果，没有渐变，没有库存照片。

调色板：
- 背景：[主要品牌颜色或深色中性]
- 文本：[白色或高对比度颜色]
- 辅助色：[次要品牌颜色]

布局：
标题（顶部，大粗文本）：
[插入帖子标题]

正文（结构化章节，每个章节都有一个图标或数字）：
[将 3 到 6 个要点作为短行插入，每个要点都有一个视觉标记：编号圆圈、复选标记或简单图标]

[如果有统计数据，将它们显示为大号特征数字，标签在下方]

页脚：
[来自 `about-me.md` 的作者姓名] | [如果合适，则包含 CTA 或标语]

保持文本大而可扫描。目标是在图像上保留 40 个字；保留所需内容并在需要时拆分简要。不要有装饰性边框。不要有水印。除非用户提供，否则不要有标志。
```

以代码块的形式输出完整的提示。告诉用户：

> 请将此粘贴到 Gemini 或您的图像生成器中。提示已准备就绪。

## 完成任一路径后

报告实际状态：**HTML 渲染待处理**、**HTML + 检查过的 PNG** 或 **Gemini 提示准备就绪**。链接实际存在的文件。列出任何未解决的视觉缺陷。帖子评分评论不会替代图像检查。

## 规则

- 在设计之前始终阅读帖子。图形必须总结帖子内容，而不是说明抽象概念。
- 结构化图形（路径 A）必须是单个 HTML 文件，包含内联 CSS。
- 图像提示（路径 B）必须是完全自包含的。用户将冰冷的提示粘贴到 Gemini 中并获取图形。
- 从帖子中提取并提炼内容到图形中。不要复制整个帖子文本。
- 白板风格：始终是手绘标记笔外观，不完美的线条，彩色笔，笔记本/白板纹理。
- 品牌风格：始终是干净、平面、现代，使用用户的品牌颜色。
- 在任何输出中切勿使用破折号。
- 全程使用英式英语。
