# 钩子生成器

## Codex 和 Claude 运行时

- 在 Codex 或 Claude 中使用此技能时，应使用当前任务中实际可用的工具。`AskUserQuestion` 示例描述的是问题，而不是必需的 API：在可用问题工具的范围内使用它，或在聊天中提问。重用已提供的答案和源材料。
- 在用户选择的项目中工作。在个性化工作之前，阅读其 `about-me.md`、`voice.md` 和相关的品牌文件。如果文件冲突或包含启动默认值，请确认预期的作者。询问缺失的事实或运行 `voice-builder`；永远不要继承维护者的身份、帐户或私人文件。
- 解析相对于此技能文件夹捆绑的 `references/`。对于明确请求的配置文件刷新，请就地读取和更新规范 `about-me.md`、`voice.md` 或 `newsletter-voice.md`，同时保留无关的用户事实和规则。消费者必须重新阅读这些规范文件。仅对不会与无关现有文件冲突的新交付成果使用新文件名。单独安装永远不会开始访谈或写入文件。除非被要求，否则不要写入持久性学习成果。
- 首先使用提供的证据。当需要时，通过可用的搜索/源工具验证外部声明。如果某个来源或集成不可用，请命名缺失的功能，并提供提供的文本/导出输入。永远不要编造事实、第一人称经历、指标或成功的工具运行。
- 仅通过用户现有的帐户连接所选路由所需的服务。永远不要打印凭证或覆盖连接。起草、保存和审阅不会授权发布、发送消息或更改帐户。

## 关键：加载时自动启动

当此技能触发时，直接进入步骤 1。不要总结。不要解释一个好的钩子是什么。

## 步骤 1. 获取主题

如果用户已经在他们的消息中粘贴了主题，请使用它并跳到步骤 2。

否则，询问：

> 你想要为哪个主题生成钩子？

等待回复。

## 步骤 2. 写 6 个钩子变体

每个钩子都有相同的结构：

- **第一行（开头）**：最多 40 个字符。不能是问题。陈述意想不到的、具体的或有力的内容。
- **第二行（对比）**：最多 40 个字符。反驳、重新框架或削弱开头。

每个变体必须：

- 仅在作者提供了真实经历时使用 "How I" 或 "I"。否则使用有证据支持的、非个人化的角度，并标记不可用的个人角度。
- 尽可能包含数字或指标
- 遵循点击诱饵原则：张力、好奇心差距、风险

生成 6 个涵盖不同角度的变体：

1. **数字导向**：以特定的数字或指标开头
2. **反常识**：陈述一个信念然后反转它
3. **个人转变**：前后对比，并包含一个数字
4. **权威参考**：引用一个名字、工具或品牌
5. **承认**：承认一个错误或损失
6. **未来冲击**：一个预测或 "X 即将改变"

## 步骤 3. 输出格式

```
钩子 for [主题]

1. [数字导向]
[第一行]
[第二行]

2. [反常识]
[第一行]
[第二行]

3. [个人转变]
[第一行]
[第二行]

4. [权威参考]
[第一行]
[第二行]

5. [承认]
[第一行]
[第二行]

6. [未来冲击]
[第一行]
[第二行]
```

## 步骤 4. 提供下一步行动

询问：

> 想让我将其中一个构建成一个完整帖子吗？调用 post-formatter 技能并传入钩子编号。

## 规则

- 每行最多 40 个字符。计算它们。
- 开头行不能有问题。
- 不能使用破折号。
- 不能使用填充词。每个词都应有其价值。
- 优先使用数字而不是拼写的数字（3，而不是 three）。
- 除非 `voice.md` 另有说明，否则使用英式英语。
- 保留源中的不确定性。永远不要编造结果或确定性来使钩子更强。在交付前，使用可用的文本工具精确计算字符数。
