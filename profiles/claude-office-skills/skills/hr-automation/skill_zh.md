# HR自动化

自动化人力资源工作流程，包括招聘、入职、员工管理和离职。基于n8n的人力资源工作流程模板。

## 概述

本技能涵盖：
- 招聘流程自动化
- 员工入职工作流
- 绩效评估周期
- 休假管理
- 离职流程

---

## 招聘自动化

### 候选人流程

```yaml
recruiting_pipeline:
  阶段:
    - 申请
    - 筛选
    - 电话面试
    - 技术面试
    - 现场面试
    - 发放录用通知
    - 录用
    
  自动化:
    新申请:
      触发: 收到申请
      操作:
        - 向候选人发送确认
        - 通过Slack通知招聘人员
        - 添加到Airtable跟踪
        - 如果启用，进行AI简历筛选
        
    阶段变更:
      触发: 候选人进入下一阶段
      操作:
        - 在ATS中更新候选人信息
        - 通知相关面试官
        - 发送特定阶段的邮件模板
        
    面试安排:
      触发: 日历事件创建
      操作:
        - 向候选人发送确认
        - 向面试官发送准备材料
        - 在系统中创建评分卡
```

### AI简历筛选

```yaml
ai_screening:
  模型: gpt-4
  
  提示: |
    审查这份简历，用于{职位名称}职位。
    
    职位要求:
    {职位要求}
    
    简历:
    {简历文本}
    
    评估:
    1. 技能匹配度（1-10）
    2. 经验匹配度（1-10）
    3. 关键优势
    4. 潜在问题
    5. 建议：是/否/可能
    
  自动化:
    - 如果: 分数 >= 8
      操作: 进入筛选阶段
    - 如果: 分数 5-7
      操作: 标记待审核
    - 如果: 分数 < 5
      操作: 自动拒绝 + 发送拒绝通知
```

### 面试安排

```yaml
interview_scheduling:
  工作流:
    1. 候选人进入面试阶段:
        触发: 阶段变更至面试
        
    2. 检查可用性:
        面试官: 来自招聘计划
        候选人: 通过邮件请求
        
    3. 查找时间段:
        算法: 匹配最早可用时间段
        缓冲: 15分钟间隔
        
    4. 发送邀请:
        接收者: [候选人, 面试官]
        包含: [Zoom链接, 日历邀请, 准备文档]
        
    5. 提醒:
        - 提前24小时: 所有参与者
        - 提前1小时: 所有参与者
        
    6. 面试后:
        - 收集反馈: 来自面试官
        - 汇总评分
        - 如果通过，触发下一阶段
```

## 入职自动化

### 新员工工作流

```yaml
onboarding_workflow:
  触发: 录用通知接受
  持续时间: 30天
  
  入职前:
    提前14天:
      - 发送欢迎邮件
      - 收集文件: [身份证, 税表, 直接存款信息]
      - 订购设备: 笔记本电脑, 外设
      
    提前7天:
      - 创建账户: [邮箱, Slack, 工具]
      - 添加到系统: HRIS, 薪酬系统
      - 安排入职培训
      - 指定伙伴
      
    提前1天:
      - 如果在办公室，设置工位
      - 如果远程，寄送设备
      - 发送第一天信息
      
  第一天:
    上午:
      - 与经理欢迎会
      - IT设置: 凭证, 工具
      - 团队介绍
      
    下午:
      - HR入职培训: 政策, 福利
      - 验证权限
      - 伙伴午餐
      
  第一周:
    - 每日检查: 与经理
    - 按需工具培训
    - 参加所有团队会议
    - 文档审查
    
  第一个月:
    - 每周1对1: 与经理
    - 项目分配
    - 目标设定
    - 30天调查
```

### 入职清单自动化

```yaml
onboarding_checklist:
  员工任务:
    - 完成9: 提前3天截止
    - 设置直接存款: 提前7天截止
    - 完成福利登记: 提前30天截止
    - 审阅手册: 提前7天截止
    - 完成培训: 提前14天截止
    
  经理任务:
    - 介绍给团队: 第一天
    - 指定入职伙伴: 第一天
    - 设定30/60/90目标: 第一周
    - 安排定期1对1: 第一周
    - 提供项目背景: 第一周
    
  IT任务:
    - 创建邮箱: 提前1天
    - 配置工具: 提前1天
    - 设置硬件: 第一天
    - 授予系统权限: 第一天
    - 安全培训: 第一周
    
  通知:
    未完成任务:
      - 提醒负责人: 截止日期50%时
      - 提醒负责人: 截止日期80%时
      - 在截止日期100%时升级
```

## 员工管理

### 休假请求

```yaml
pto_workflow:
  请求:
    触发: 员工提交请求
    字段: [开始日期, 结束日期, 类型, 原因]
    
  审批:
    路由:
      - 如果: 天数 <= 3
        审批人: 直接经理
      - 如果: 天数 > 3
        审批人: [经理, HR]
        
    自动化:
      - 通过Slack DM通知审批人
      - 设置截止日期: 48小时
      - 如果无回应: 升级
      
  已批准:
    操作:
      - 更新日历: 锁定日期
      - 通知团队: 即将休假
      - 更新HRIS: 扣除余额
      - 向员工发送确认
      
  已拒绝:
    操作:
      - 通知员工: 带有原因
      - 记录拒绝: 为合规
```

### 绩效评估

```yaml
performance_review_cycle:
  时间表: 每季度
  
  工作流:
    第一周:
      - 启动周期: 通知所有人
      - 自我评估: 开放
      
    第二周:
      - 自我评估: 截止日期
      - 同事反馈: 开放
      
    第三周:
      - 同事反馈: 截止日期
      - 经理评估: 开放
      
    第四周:
      - 经理评估: 截止日期
      - 校准: HR和领导层
      - 最终确定评分
      
    第五周:
      - 发送评估: 经理会议
      - 设定下一季度目标
      
  自动化:
    提醒:
      - 截止日期前3天: 温和提醒
      - 截止日期前1天: 紧急提醒
      - 过期: 每日直至完成
      
    分析:
      - 完成率
      - 评分分布
      - 反馈主题
```

## 离职

### 离职工作流

```yaml
offboarding_workflow:
  触发: 提交辞职 OR 解雇
  
  立即:
    - 确认辞职: 给员工
    - 通知HR: 处理
    - 通知经理: 过渡计划
    - 通知IT: 权限审查
    
  规划阶段:
    - 计算最终工资
    - 安排离职面试
    - 创建过渡计划
    - 记录知识转移
    
  最后一周:
    - 知识转移: 会议
    - 收集设备
    - 按计划撤销系统权限
    - 更新团队分配
    
  最后一天:
    - HR离职面试
    - 返回徽章钥匙
    - 撤销所有权限
    - 如果自愿离职: 发送告别
    
  离职后:
    - 处理最终工资单
    - 发送福利信息: COBRA
    - 归档文件
    - 30天后进行离职调查
```

### 权限撤销

```yaml
access_revocation:
  解雇后立即:
    - 邮箱: 禁用
    - SSO: 撤销
    - VPN: 撤销
    - 物理访问: 撤销
    - 公司信用卡: 取消
    
  24小时内:
    - 工具许可证: 移除
    - 共享驱动器: 转移所有权
    - 代码仓库: 移除
    - 客户系统: 移除
    
  审计:
    - 记录所有撤销
    - 验证无剩余访问权限
    - 合规报告
```
