# 更新日志生成器

从提交记录、功能列表或更新中生成专业的发布说明和更新日志。

## 概述

此功能可以帮助您：
- 将 git 提交记录转换为可读的更新日志
- 按类型对变更进行分类
- 编写用户友好的发布说明
- 维护更新日志历史记录
- 遵循常规格式

## 如何使用

### 从 Git 提交记录
```
"从这些提交记录生成更新日志：
- fix: 解决登录超时问题
- feat: 添加暗黑模式支持
- docs: 更新 API 文档"
```

### 从功能列表
```
"为 2.0 版本创建发布说明：
- 新的仪表盘设计
- 性能提升（速度提升 50%）
- Fixed: 导出按钮无法使用
- Removed: 旧版 API v1"
```

### 从差异/变更
```
"将这些代码变更总结为更新日志条目"
```

## 类别定义

### 变更类型（常规提交）
| 类型 | 描述 | 更新日志部分 |
|------|-------------|-------------------|
| `feat` | 新功能 | 添加 |
| `fix` | 修复 Bug | 修复 |
| `docs` | 文档 | 文档 |
| `style` | 格式化 | 更改 |
| `refactor` | 代码重构 | 更改 |
| `perf` | 性能 | 更改 |
| `test` | 测试 | N/A（内部） |
| `chore` | 维护 | N/A（内部） |
| `breaking` | 破坏性变更 | ⚠️ BREAKING |
| `security` | 安全修复 | 安全 |
| `deprecate` | 弃用 | 已弃用 |
| `remove` | 移除 | 移除 |

### 语义化版本
```
MAJOR.MINOR.PATCH

MAJOR：破坏性变更（不兼容的 API 变更）
MINOR：新功能（向后兼容）
PATCH：Bug 修复（向后兼容）
```

## 模板

### 提交到更新日志条目
```
输入：feat(auth): 添加 OAuth 2.0 支持 (#123)
输出：- 添加了 OAuth 2.0 认证支持
```

### Bug 报告到修复条目
```
输入：用户报告文件 > 10MB 时导出失败
输出：- 修复了大于 10MB 文件的导出功能
```

## 最佳实践

### 编写良好的条目
✅ **应该**：
- 从用户角度编写
- 具体说明变更内容
- 包含相关问题/PR 编号
- 将相关变更分组

❌ **不应该**：
- 对用户文档使用技术术语
- 在公共更新日志中包含内部变更
- 含糊不清（“各种修复”）
- 在用户文档中包含提交哈希

### 组织变更
1. **优先级排序**：最重要的变更放在顶部
2. **逻辑分组**：按功能区域或类型
3. **保持一致**：全文格式相同
4. **标注日期**：清晰的版本日期

## 限制

- 无法直接访问 git 仓库
- 需要提交记录或变更描述作为输入
- 无法自动验证语义化版本
- 技术细节应由开发人员验证
