# 清理上下文模式

永久删除此项目的会话数据。支持两种范围（问题 #520）：

- **项目范围** (`scope: "project"`): 删除所有内容——知识库、所有会话的会话数据库行、事件 Markdown 和统计信息。
- **会话范围** (`sessionId: "<id>"` 或 `scope: "session"`): 仅删除匹配的会话的行 + FTS5 数据块。兄弟会话、项目统计信息和 FTS5 存储文件将保留。

## 使用说明

1. **首先与用户确定范围**：
   - "仅删除一个会话吗？" → 询问 `sessionId`。
   - "删除整个项目吗？" → 确认范围:'project'（这是破坏性且不可逆的默认选项）。
2. **警告用户关于范围:'project'**。所有内容将被删除：
   - FTS5 知识库（所有来自 `ctx_index`、`ctx_fetch_and_index`、`ctx_batch_execute` 的索引内容）
   - 会话事件数据库（所有项目中的所有会话的指标、元数据、恢复快照）
   - 会话事件 Markdown 文件
   - 内存会话统计信息 + 持久化统计信息文件
3. 使用选择的参数调用 `mcp__context-mode__ctx_purge` MCP 工具：
   - 范围限定：`{ confirm: true, sessionId: "<id>" }` — 意味着范围:'session'。
   - 项目：`{ confirm: true, scope: "project" }` — 明确的破坏性形式。
   - 简洁形式 `{ confirm: true }` 仍然有效，但会发出弃用警告。优先使用明确形式。
4. 向用户报告结果——响应内容列出了被删除的内容，并且（对于范围限定删除）确认其他会话和项目统计信息已保留。

## 模式规则

- `confirm: true` 始终是必需的。
- `sessionId` 和 `scope: "project"` 一起会被拒绝，因为它们是模糊的（sessionId 意味着会话范围；与项目范围结合与意图矛盾）。
- `scope: "session"` 没有 `sessionId` 会抛出异常——sessionId 是必需的。

## 使用场景

- **范围限定（每个会话）**：临时接受场景、钻取回放、隔离受污染的会话而不丢失主工作会话的统计信息。
- **项目**：知识库包含过时或错误的内容污染搜索结果、在同一会话中切换无关的项目、完全重新开始。

## 重要提示

- `ctx_purge` 是**唯一**删除会话数据的方法。没有其他机制。
- `ctx_stats` 是只读的——仅显示统计信息。
- `/clear` 和 `/compact` 不会影响任何上下文模式数据。
- 没有撤销操作。如果需要重新索引内容，请重新索引。
