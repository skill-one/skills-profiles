# Firecrawl 网站设计克隆

当用户希望将一个 URL 转换为一个实用型设计系统文件，供代理立即使用时，使用此功能。

默认结果：**一行代码提取任何网站的设计系统**，并将其格式化为 `DESIGN.md`。

该技能应感觉像是围绕 Firecrawl 抓取的薄型工作流：收集页面的可见内容、结构、元数据、链接和可用的视觉信号，然后将这些发现综合成一个干净的设计系统 Markdown 文件。

## 欢迎面试

根据上下文推断源 URL、目标堆栈以及是否请求实现。如果用户提供一个 URL 并请求设计系统，请立即进行。

如果遇到阻塞，最多只问 1-3 个简洁的问题，例如网站 URL、是否仅输出 `DESIGN.md` 或也进行实现，或所需的目標堆栈。

使用主机代理的正常提示或模态 UI。不要命名特定于 harness 的问题函数。

## Firecrawl 收集计划

通过 CLI 或等效工具界面使用 Firecrawl。始终从提供的 URL 开始两个并行的抓取：

1. 一起抓取 `branding` 和 `images` 格式，用于结构化设计令牌和页面完整图像集。
2. 全页截图，用于视觉上下文。

示例：

```bash
firecrawl scrape "https://example.com" --format branding,images -o ".firecrawl/example-branding.json" --pretty &
firecrawl scrape "https://example.com" --full-page-screenshot -o ".firecrawl/example-screenshot.png" &
wait
```

在一个调用中结合 `branding` 和 `images` 仍然只消耗一个信用，并且是必需的：`branding` 块仅展示精选的品牌资产（`logo`、`favicon`、`ogImage`、`logoHref`），因此如果没有 `images`，代理将错过页面的实际内容图像（英雄、产品照片、轮播图、功能视觉、插图、配件照片、页面末尾的艺术品等）。在产品页面如 `tesla.com/cybertruck` 上，`branding` 块没有英雄 — 只有 `images` 返回主要的 Cybertruck 英雄（例如 `Cybertruck-Hero-Desktop-NA-SA-APAC.png`）和页面其余的摄影。

如果截图抓取返回一个远程图像 URL（例如已签署的存储链接）而不是本地文件，请将其下载到相同的 `.firecrawl/` 路径，以便 `DESIGN.md` 可以引用一个稳定的本地资源。

使用结构化的 `branding` 输出作为颜色、排版、组件、品牌资产（logo、favicon、ogImage）、个性化和信心笔记的主要来源。使用 `images` 列表作为页面内容图像的来源 — 英雄摄影、产品照片、轮播图、功能视觉、插图和装饰图形。使用截图作为布局、层次结构和整体感觉的主要视觉参考。仅在以下情况下才添加补充格式：这些格式不足以生成最终产物。

收集：

- 颜色、排版、间距、按钮、logo、品牌图像、个性和信心的品牌数据
- 完整的 `images` 列表，用于英雄、产品、功能和部分图像，超出精选品牌资产的范围
- 保存到本地 `.firecrawl/` 的全页截图，以便可以嵌入到 `DESIGN.md` 中
- 当需要时，页面的 Markdown，用于标题、复制层次结构、CTA、导航和部分顺序
- 当需要时，品牌、产品和页面目的线索的元数据和链接
- 仅在品牌输出、图像列表和截图不足以推断类名、字体名称、CSS 变量或组件结构时才使用 HTML
- 仅在用户请求更广泛的站点系统时才使用相关页面

默认情况下不要过度抓取。第一个版本应从一个代表性的页面就很有用。

## 要提取的内容

推断并记录站点的设计语言：

- 颜色：主要、次要、强调色、背景、边框、文本、状态
- 排版：如果可检测，字体家族、类型比例、权重、行高、标题/正文规则
- 间距：容器宽度、部分节奏、网格间隙、填充比例、密度
- 布局：页面结构、英雄模式、卡片、网格、导航、页脚、响应式假设
- 组件：按钮、输入、卡片、徽章、导航项、定价块、客户评价、功能行、表单
- 图像和图标：风格、形状语言、插图/照片处理、logo 限制；从完整的 `images` 列表中提取代表性的英雄、产品、功能和部分图像，而不是依赖 `branding.images`，后者仅包含 `logo`、`favicon`、`ogImage` 和 `logoHref`
- 动作和交互：当可观察或可推断时，悬停状态、过渡、动画风格
- 语气和内容模式：CTA 文字、标题风格、产品复制节奏

当从抓取输出中无法精确测量某个值时，将其标记为推断，并给出一个实用的近似值。

## 并行工作

如果合适，使用子代理或等效的并行任务运行器。自然的分割包括多页面站点每个研究人员一个页面，或颜色、排版、间距和组件每个一个审查者。

每个并行研究人员应返回源 URL、提取的证据、推断的设计令牌和信心笔记。

## 最终交付物

创建或返回一个具有此结构的 `DESIGN.md`。在顶部附近嵌入全页截图，以便编码代理在令牌旁边获得视觉上下文。

```markdown
# DESIGN.md: [源站点]

## 源
- URL: [源 URL]
- 捕获日期: [日期]
- 证据: [使用的抓取/截图/HTML/链接]
```

如果用户请求实现，首先生成或更新 `DESIGN.md`，然后使用它作为构建的来源。

## 质量标准

- 不要暗示用户拥有第三方标志、图像、商标或版权的权利。
- 优先使用可重用的设计令牌，而不是一次性观察。
- 将观察到的事实与推断的近似值区分开来。
- 保持输出足够紧凑，以便另一个代理可以将其粘贴到上下文中并从中构建。
- 保留源 URL 和抓取工件以供审查。
