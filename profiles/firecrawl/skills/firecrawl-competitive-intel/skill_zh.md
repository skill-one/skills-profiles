# Firecrawl 竞争情报

用于长期监控竞争对手。这不是全面的竞争对手分析工作流。

## 欢迎面试

根据上下文推断竞争对手、关注点、节奏和输出格式。如果竞争对手明确，请立即进行。

如果遇到阻碍，最多只能问 1-3 个简洁的问题，例如竞争对手列表、关注领域，或是否需要认证页面/资料。

## Firecrawl 收集计划

针对每个竞争对手，根据需要使用 Firecrawl 抓取或浏览器：

- 定价页面、年度/月度切换、扩展功能表格
- 功能和产品页面
- 更新日志、博客、发布说明、文档更新
- 仅在用户具有合法访问权限时使用认证仪表板

## 并行工作

如果合适，可以使用子代理或等效的并行任务运行器。一个自然的划分是每个研究人员负责一个竞争对手，或每个研究人员负责一个关注领域。

每个研究人员应返回定价层级、功能、最近变更、来源 URL 和信心备注。

## 最终交付物

```markdown
# 竞争情报：[竞争对手]

## 提醒
[显著的定价、功能或定位变更]

## 按竞争对手分解
[定价层级、功能清单、最近变更]

## 跨竞争对手比较
[定价表格、功能矩阵、关键差异化]

## 建议后续监控
[下一步要监控的内容]

## 来源
[访问的 URL]

## 重新运行输入
workflow: firecrawl-competitive-intel
competitors: [列表]
focus: [全部/定价/功能/更新日志]
cadence: [一次性/每周/每月]
```

## JSON 结构

当请求结构化输出时，应包含 `generatedAt`、`competitors`、`pricing`、`recentChanges`、`features` 和 `sources`。

## 质量标准

- 当可用时，提取实际计划名称、限制和日期。
- 记录联系销售或受限制的详细信息，而不是猜测。
- 保留来源以便未来运行时进行差异比较。
