# Firecrawl QA

使用此工具测试实时网站并返回统一的QA报告。

## 入职面试

从上下文中推断URL、QA重点和输出格式。如果目标URL清晰，请立即进行。

如果遇到阻塞，最多只问1-3个简洁的问题，例如URL、重点区域或受保护流程的凭据/约束。

## Firecrawl集合计划

使用Firecrawl地图发现页面。使用Firecrawl浏览器进行交互、表单、导航，以及在可用时进行响应式/手动检查。使用scrape获取页面内容和链接提取。

## 并行工作

如果合适，使用子代理或等效的并行任务运行器：

- 全部：导航和链接、表单和交互、内容和视觉、错误状态。
- 表单：表单发现、成功路径、边缘情况、验证。
- 导航：站点地图、导航测试、链接检查、路由。
- 响应式：桌面、平板、移动、交互。
- 性能：页面加载、资源审计、内容效率、比较。

每个测试人员应返回严重程度、URL、描述、证据和重现步骤。

## 最终交付物

```markdown
# QA报告：[网站]

## 摘要
- 健康评分：[x/10]
- 测试页面数：[数量]
- 发现问题数：[严重/主要/次要]

## 严重问题
[C-1] URL | 描述 | 重现步骤 | 预期与实际

## 主要问题
[M-1] URL | 描述 | 重现步骤

## 次要问题
[m-1] URL | 描述

## 积极观察
[工作良好的方面]

## 测试页面
[URLs]

## 代理/测试总结
[谁测试了什么]

## 重新运行输入
workflow: firecrawl-qa
url: [url]
focus: [全部/表单/导航/响应式/性能]
```

## 质量标准

- 为功能性问题包含重现步骤。
- 没有证据的情况下不要报告推测性错误。
- 在测试人员之间去重发现。
