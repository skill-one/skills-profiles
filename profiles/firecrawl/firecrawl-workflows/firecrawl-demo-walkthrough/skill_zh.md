# Firecrawl Demo 演示指南

使用此文档逐步记录产品体验。

## 欢迎面试

根据上下文推断产品 URL、流程重点和输出格式。如果 URL 清晰，请立即进行。

如果遇到阻碍，最多只问 1-3 个简洁的问题，例如 URL、期望的流程重点或受保护区域的凭据/限制。

## Firecrawl 收集计划

使用 Firecrawl 浏览器打开产品并导航关键流程。每一步都进行快照，在必要时抓取页面，并记录用户看到的内容和可以执行的操作。

除非用户明确指示并授权，否则不要提交真实凭据、购买或不可逆的操作。

## 并行工作

如果合适，可以使用子代理或等效的并行任务运行器：

- 首页和营销
- 注册和欢迎
- 定价和计划
- 文档和开发者体验
- 仪表板和核心产品
- 帮助和支持

每个走查者应返回访问的屏幕、执行的操作、观察结果、摩擦点和源 URL。

## 最终交付物

```markdown
# 产品走查：[产品]

## 产品概述
[产品的作用]

## 流程走查
### [流程名称]
1. [屏幕/页面] - 出现的内容和可用的操作
2. [下一个屏幕] - 发生的变化

## 关键发现
[第一印象、突出模式、摩擦点]

## 建议
[用户体验/产品改进]

## 访问的页面
[URL]

## 重新运行输入
workflow: firecrawl-demo-walkthrough
url: [url]
focus: [full/signup/pricing/docs/dashboard]
```

## 质量标准

- 具体说明屏幕、CTA、表单和过渡。
- 将观察结果与观点分开。
- 保留访问的每一页。
