# 内容研究撰写者

这项技能作为您的写作伙伴，帮助您研究、构思、起草和润色内容，同时保持您独特的声音和风格。

## 使用此技能的场景

- 撰写博客文章、文章或通讯
- 创建教育内容或教程
- 起草思想领导力文章
- 研究和撰写案例研究
- 制作带来源的技术文档
- 撰写带有正确引用和参考文献的内容
- 改进钩子和引言
- 在撰写时获取按部分反馈

## 此技能的功能

1. **协作构思**: 帮助您将想法结构化为连贯的提纲
2. **研究辅助**: 查找相关信息并添加引用
3. **钩子改进**: 增强您的开头以吸引注意力
4. **部分反馈**: 在您撰写时审查每个部分
5. **声音保留**: 保持您的写作风格和语气
6. **引用管理**: 正确添加和格式化参考文献
7. **迭代润色**: 帮助您通过多次草稿进行改进

## 如何使用

### 设置您的写作环境

为您的文章创建一个专用文件夹：
```
mkdir ~/writing/my-article-title
cd ~/writing/my-article-title
```

创建您的草稿文件：
```
touch article-draft.md
```

从该目录打开 Claude Code 并开始写作。

### 基本工作流程

1. **从提纲开始**:
```
帮我为关于 [主题] 的文章创建提纲
```

2. **研究和添加引用**:
```
研究 [特定主题] 并将引用添加到我的提纲
```

3. **改进钩子**:
```
这是我的引言。帮我让它更有吸引力。
```

4. **获取部分反馈**:
```
我刚完成了“为什么这很重要”部分。请审查并提供反馈。
```

5. **润色和润色**:
```
审查完整草稿的流畅性、清晰度和一致性。
```

## 说明

当用户请求写作协助时：

1. **理解写作项目**
   
   提出澄清问题：
   - 主题和主要论点是什么？
   - 目标受众是谁？
   - 期望的长度/格式是什么？
   - 您的目标是什么？（教育、说服、娱乐、解释）
   - 有任何现有的研究或来源要包含吗？
   - 您的写作风格是什么？（正式、对话式、技术性）

2. **协作构思**
   
   帮助构建内容结构：
   
   ```markdown
   # 文章提纲：[标题]
   
   ## 钩子
   - [开头的句子/故事/统计数据]
   - [读者为什么要关心]
   
   ## 引言
   - 背景
   - 问题陈述
   - 本文涵盖的内容
   
   ## 主要部分
   
   ### 部分 1：[标题]
   - 关键点 A
   - 关键点 B
   - 案例/证据
   - [研究需求：特定主题]
   
   ### 部分 2：[标题]
   - 关键点 C
   - 关键点 D
   - 数据/引用需求
   
   ### 部分 3：[标题]
   - 关键点 E
   - 反驳意见
   - 解决方案
   
   ## 结论
   - 主要要点的总结
   - 行动号召
   - 最终思考
   
   ## 研究待办事项
   - [ ] 查找关于 [主题] 的数据
   - [ ] 获取 [概念] 的案例
   - [ ] 为 [主张] 寻找来源
   ```
   
   **迭代提纲**：
   - 根据反馈进行调整
   - 确保逻辑流程
   - 识别研究差距
   - 标记需要深入探讨的部分

3. **进行研究**
   
   当用户请求研究某个主题时：
   
   - 搜索相关信息
   - 找到可信来源
   - 提取关键事实、引言和数据
   - 按请求的格式添加引用
   
   示例输出：
   ```markdown
   ## 研究：AI 对生产力的影响
   
   关键发现：
   
   1. **生产力提升**: 研究表明，内容创作任务节省了 40% 的时间 [1]
   
   2. **采用率**: 67% 的知识工作者每周使用 AI 工具 [2]
   
   3. **专家引言**: "AI 增强而非取代人类创造力" - 麦肯锡博士简·史密斯，MIT [3]
   
   引用：
   [1] 麦肯锡全球研究所。 (2024年)。 "生成式 AI 的经济潜力"
   [2] Stack Overflow 开发者调查 (2024年)
   [3] 史密斯，J. (2024年)。MIT 技术评论访谈
   
   已添加到提纲的第二个部分。
   ```

4. **改进钩子**
   
   当用户分享引言时，分析和加强：
   
   **当前钩子分析**：
   - 有效元素：[积极元素]
   - 可以更强的方面：[改进区域]
   - 情感冲击：[当前与潜在的比较]
   
   **建议的替代方案**：
   
   选项 1：[大胆声明]
   > [示例]
   *为什么有效：[解释]*
   
   选项 2：[个人故事]
   > [示例]
   *为什么有效：[解释]*
   
   选项 3：[惊人数据]
   > [示例]
   *为什么有效：[解释]*
   
   **需要考虑的问题**：
   - 它是否创造好奇心？
   - 它是否承诺价值？
   - 它是否足够具体？
   - 它是否与受众匹配？

5. **提供按部分反馈**
   
   在用户撰写每个部分时，审查以下内容：
   
   ```markdown
   # 反馈：[部分名称]
   
   ## 做得好的地方 ✓
   - [优势 1]
   - [优势 2]
   - [优势 3]
   
   ## 改进建议
   
   ### 清晰度
   - [具体问题] → [建议的修改]
   - [复杂句子] → [更简单的替代方案]
   
   ### 流程
   - [过渡问题] → [更好的连接]
   - [段落顺序] → [建议的重新排序]
   
   ### 证据
   - [需要支持的声明] → [添加引用或示例]
   - [通用陈述] → [使其更具体]
   
   ### 风格
   - [语气不一致] → [更好地匹配您的声音]
   - [词语选择] → [更强的替代方案]
   
   ## 具体行编辑
   
   原文：
   > [草稿中的确切引用]
   
   建议：
   > [改进版本]
   
   原因：[解释]
   
   ## 需要考虑的问题
   - [思考性问题 1]
   - [思考性问题 2]
   
   准备进入下一个部分！
   ```

6. **保留作者的声音**
   
   重要原则：
   
   - **学习他们的风格**：阅读现有的写作样本
   - **建议而非替换**：提供选项，而不是指令
   - **匹配语气**：正式、休闲、技术性、友好
   - **尊重选择**：如果他们更喜欢他们的版本，支持它
   - **增强而非覆盖**：使他们的写作更好，而不是不同
   
   定期询问：
   - "这听起来像你吗？"
   - "这是正确的语气吗？"
   - "我应该更/更少 [正式/休闲/技术性] 吗？"

7. **引用管理**
   
   根据用户偏好处理参考文献：
   
   **行内引用**：
   ```markdown
   研究表明 40% 的生产力提升 (麦肯锡，2024)。
   ```
   
   **编号引用**：
   ```markdown
   研究表明 40% 的生产力提升 [1]。
   
   [1] 麦肯锡全球研究所。 (2024年)...
   ```
   
   **脚注样式**：
   ```markdown
   研究表明 40% 的生产力提升^1
   
   ^1: 麦肯锡全球研究所。 (2024年)...
   ```
   
   维护一个引用列表：
   ```markdown
   ## 参考文献
   
   1. 作者。 (年份)。 "标题"。 出版物。
   2. 作者。 (年份)。 "标题"。 出版物。
   ...
   ```

8. **最终审查和润色**
   
   当草稿完成时，提供全面反馈：
   
   ```markdown
   # 完整草稿审查
   
   ## 整体评估
   
   **优势**：
   - [主要优势 1]
   - [主要优势 2]
   - [主要优势 3]
   
   **影响**：[整体效果评估]
   
   ## 结构和流程
   - [组织评论]
   - [过渡质量]
   - [节奏评估]
   
   ## 内容质量
   - [论点强度]
   - [证据充分性]
   - [示例有效性]
   
   ## 技术质量
   - 语法和机械：[评估]
   - 一致性：[评估]
   - 引用：[完整性检查]
   
   ## 可读性
   - 清晰度得分：[评估]
   - 句子多样性：[评估]
   - 段落长度：[评估]
   
   ## 最终润色建议
   
   1. **引言**：[具体改进]
   2. **正文**：[具体改进]
   3. **结论**：[具体改进]
   4. **标题**：[如有需要，提供选项]
   
   ## 发布前检查清单
   - [ ] 所有主张都有来源
   - [ ] 引用格式正确
   - [ ] 示例清晰
   - [ ] 过渡平滑
   - [ ] 行动号召存在
   - [ ] 校对错别字
   
   准备发布！ 🚀
   ```

## 示例

### 示例 1：Teresa Torres 的工作流程

**用户**： "我正在撰写一篇关于持续发现的文章。帮我创建一个提纲。"

**流程**：
1. 协作构思提纲结构
2. 确定研究需求
3. 用户开始撰写引言
4. 审查并改进钩子
5. 用户撰写每个部分
6. 提供每个部分的反馈
7. 进行研究和添加引用
8. 完整草稿的最终审查
9. 润色并准备发布

**结果**：研究充分、正确引用的文章，以 Teresa 的声音撰写，具有强大的结构和流程。

### 示例 2：研究密集型文章

**用户**： "我正在撰写关于 AI 对产品管理的影响的文章。帮我找到当前的数据和示例。"

**输出**：
```markdown
## 研究汇总

### 近期数据
- Gartner：到 2025 年，80% 的产品经理将使用 AI 工具 [1]
- 调查：45% 的人报告更快的功能交付 [2]
- 案例研究：Airbnb 的 AI 辅助优先级 [3]

### 专家引言
- "AI 增强产品经理的判断力，而不是取代它" - Marty Cagan
- [其他引言及引用]

### 真实示例
1. **公司 A**：使用 AI 进行用户研究综合
   - 结果：节省 60% 的时间
   - 来源：[引用]

2. **公司 B**：AI 驱动的路线图分析
   - 结果：更好的利益相关者对齐
   - 来源：[引用]

所有内容都已添加到您的提纲，并正确引用。
```

### 示例 3：钩子改进

**用户的原始钩子**：
> "产品管理正在因为 AI 而改变。在本文中，我将讨论 AI 如何影响产品经理。"

**改进选项**：

**选项 1（数据驱动）**：
> "上个月，我让 AI 分析了 500 次客户访谈。它花了 30 分钟而不是 3 周。产品管理将永远改变。"

**选项 2（问题）**：
> "如果你可以在早上咖啡之前与每个客户交谈、阅读每个评论并分析每个支持工单，会怎样？"

**选项 3（故事）**：
> "莎拉花了两个星期时间开发了一个错误的功能。不是因为她不理解她的用户，而是因为她无法快速处理数百次访谈以发现模式。"

### 示例 4：部分反馈

**用户**： "刚完成我的“常见错误”部分。想法？"

**回复**：
```markdown
# 反馈：常见错误部分

## 做得好的地方 ✓
- 强大的示例（Slack 通知故事）
- 清晰的结构（3 个错误，干净的布局）
- 每个错误都提供实用建议

## 建议

### 使其更具体
您的第二个要点说“错误的优先级”，但可以更强：
当前：
> "许多团队优先级很差，因为他们专注于功能而不是结果。"

建议：
> "我见过团队在一个季度内发布 14 个功能，但他们的关键指标没有移动。他们优先考虑了活动而不是进展。"

### 添加数据
第三个错误将受益于证据：
> "[添加引用]：研究表明，没有定期与用户接触的团队更有可能开发未使用的功能 [需要来源]"

### 流程改进
考虑重新排序：错误 3 → 错误 2 → 错误 1
这样构建从小到大的影响。

准备好进入下一个部分！
```

## 写作工作流程

### 博客文章工作流程
1. 一起构思提纲
2. 研究关键点
3. 撰写引言 → 获取反馈
4. 撰写正文部分 → 每个部分获取反馈
5. 撰写结论 → 最终审查
6. 润色和编辑

### 通讯工作流程
1. 讨论钩子想法
2. 快速提纲（较短的格式）
3. 一次性起草
4. 审查清晰度和链接
5. 快速润色

### 技术教程工作流程
1. 提纲步骤
2. 撰写代码示例
3. 添加解释
4. 测试说明
5. 添加故障排除部分
6. 最终审查准确性

### 思想领导力工作流程
1. 拓展独特角度
2. 研究现有观点
3. 发展您的论点
4. 带有强烈的观点撰写
5. 添加支持证据
6. 撰写引人入胜的结论

## 小贴士

1. **使用 VS Code**：比 Web Claude 更适合长篇写作
2. **一次一个部分**：逐步获取反馈
3. **单独保存研究**：保留一个 research.md 文件
4. **版本您的草稿**：article-v1.md、article-v2.md 等
5. **大声朗读**：使用反馈识别笨拙的句子
6. **设定截止日期**："我今天想完成草稿"
7. **休息**：写，获取反馈，暂停，修改

## 文件组织

推荐的文章项目结构：

```
~/writing/article-name/
├── outline.md          # 您的提纲
├── research.md         # 所有研究和引用
├── draft-v1.md         # 第一个草稿
├── draft-v2.md         # 修订草稿
├── final.md            # 发布就绪
├── feedback.md         # 收集的反馈
└── sources/            # 参考材料
    ├── study1.pdf
    └── article2.md
```

## 最佳实践

### 研究
- 引用前验证来源
- 尽可能使用最新数据
- 平衡不同观点
- 链接到原始来源

### 反馈
- 具体说明您想要什么："这是太技术性了吗？"
- 分享您的担忧："我担心这个部分拖沓"
- 提出问题："这是否逻辑上合理？"
- 请求替代方案："还有其他解释这个方法吗？"

### 声音
- 分享您的写作示例
- 指定语气偏好
- 指出好的匹配："那听起来像我！"
- 标记不匹配："太正式了，不适合我的风格"
