# 更新日志生成器

这项技能将技术性的 git 提交转化为精致、用户友好的更新日志，让你的客户和用户真正能够理解并欣赏。

## 何时使用此技能

- 准备新版本的发布说明
- 创建每周或每月的产品更新摘要
- 为客户记录变更
- 为应用商店提交编写更新日志条目
- 生成更新通知
- 创建内部发布文档
- 维护公共更新日志/产品更新页面

## 此技能的功能

1. **扫描 Git 历史记录**：分析特定时间段或版本之间的提交
2. **分类变更**：将提交分组到逻辑类别（功能、改进、修复错误、破坏性变更、安全）
3. **将技术性 → 用户友好**：将开发者提交转化为客户语言
4. **专业格式化**：创建清晰、结构的更新日志条目
5. **过滤噪音**：排除内部提交（重构、测试等）
6. **遵循最佳实践**：应用更新日志指南和你的品牌声音

## 如何使用

### 基本用法

从你的项目仓库：

```
从上次发布以来的提交创建更新日志
```

```
为过去一周的所有提交生成更新日志
```

```
为版本 2.5.0 创建发布说明
```

### 使用特定日期范围

```
为 3 月 1 日到 3 月 15 之间的所有提交创建更新日志
```

### 使用自定义指南

```
为自 v2.4.0 以来的提交创建更新日志，使用我从 CHANGELOG_STYLE.md 获取的更新日志指南
```

## 示例

**用户**："为过去 7 天的提交创建更新日志"

**输出**：

```markdown
# 更新 - 2024 年 3 月 10 日那一周

## ✨ 新功能

- **团队工作空间**：为不同项目创建独立的工作空间。邀请团队成员并保持一切井井有条。

- **键盘快捷键**：按 ? 查看所有可用快捷键。无需触摸鼠标即可更快地导航。

## 🔧 改进

- **更快同步**：文件现在跨设备同步速度提升 2 倍
- **更好的搜索**：搜索现在包含文件内容，而不仅仅是标题

## 🐛 修复

- 修复了大型图片无法上传的问题
- 解决了计划发布中的时区混淆问题
- 修正了通知徽章数量
```

**灵感来源**：Manik Aggarwal 在 Lenny's Newsletter 中的用例

## 小贴士

- 从 git 仓库根目录运行
- 指定日期范围以生成专注的更新日志
- 使用你的 CHANGELOG_STYLE.md 进行一致格式化
- 在发布前审查和调整生成的更新日志
- 直接将输出保存到 CHANGELOG.md
