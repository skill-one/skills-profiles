# Composio

将此技能用作路由器。识别产品和工作，仅加载相关的指导，参考规范文档获取易变细节，然后回答用户请求的工作。

## 1. 选择产品

不要混合产品。它们使用不同的凭证和设置路径。

| | Composio For You | Composio Platform |
|---|---|---|
| 使用场景 | 有人希望使用自己的应用程序的代理 | 开发者正在构建一个用户连接账户的产品 |
| 主要界面 | MCP 或 Composio CLI | 应用程序内的 SDK 会话 |
| 凭证 | 当客户端需要头部时使用 `ck_...` 消费密钥 | `COMPOSIO_API_KEY` 项目密钥 |
| 仪表盘 | `dashboard.composio.dev` → For You | `dashboard.composio.dev` → Platform |

仅在上下文无法确定产品时，才问一个简短的问题：

> 这是用于您自己的代理和账户，还是用于用户连接其账户的产品？

将没有产品代码的命名个人 AI 客户视为 For You。将应用程序代码库、SDK、用户或租户身份、后端或产品代理视为 Platform。

## 2. 选择工作

在采取行动之前，识别请求的结果：

- **解释或发现**：回答问题、比较方法或查找当前 API。
- **设置**：首次建立凭证、MCP 客户端、CLI 或 SDK。
- **构建或更改**：将 Composio 集成到现有代理或应用程序中。
- **操作**：查找、连接并运行实际任务的工具。
- **调试或迁移**：诊断故障、更新旧集成或从遗留直接执行或 Tool Router 迁移。

不要将解释、文档查找或狭窄的 Bug 修复转换为 onboarding。

## 3. 仅加载相关的指导

- For You：阅读 [Composio For You](references/for-you.md)。
- Platform：阅读 [Composio Platform](references/platform.md)。
- 提供商、连接或执行失败：也阅读 [错误和提供商注意事项](references/errors.md)。

## 完成选择的工作

- 对于问题，在需要时获取当前文档并给出具体答案。不要修改项目或强制工具调用。
- 对于设置或集成，检查现有环境，保留其架构和身份模型，进行最小的有用更改，并在凭证和用户授权可用时，通过一个安全的实际工具调用进行验证。
- 对于操作请求，仅连接任务所需的应用程序并执行请求的工作流程。
- 对于调试，获取 Composio 日志或请求 ID，识别失败的边界，修复该边界，并在用户授权执行时重试。

## 稳定规则

1. 在选择凭证、URL、SDK 或命令之前，先确定产品。
2. 将仪表盘 onboarding 视为上下文，而不是技能的身份。当开发者带着 Getting Started 中的现有 `COMPOSIO_API_KEY` 到来时，使用它，并且永远不要创建、轮换、替换、打印或请求聊天中的它。不要在该路径中运行 `composio dev init`。
3. 对于没有仪表盘凭证传递的通用首次 Platform 设置，遵循 Platform 指南中的当前设置路径。
4. 永远不要发明工具包或工具别名。在运行时或使用 CLI 发现它们。
5. 不要构建提供商 OAuth 流。当需要身份验证时，Composio 会返回一个连接链接。
6. 使用会话进行新的 Platform 集成。保留应用程序现有的用户身份和代理架构。
7. 将凭证、URL、日志、聊天和命令输出排除在源代码控制之外。
8. 在诊断失败的工具调用之前，获取日志或请求 ID。
9. 优先使用完成当前工作的最小配置。将工具包过滤器、标签策略、沙盒控制、自定义身份验证、提供商特定加固和其他高级选项排除在首次路径之外，除非请求或现有代码需要它们。
10. 不要发明仓库事实。在提供或检查之前，永远不要声称文件、框架、环境加载器、身份字段、代理路径或依赖项存在。如果代码库上下文不可用，说明未知情况并请求访问或一个必要细节。
11. 在 SDK 或 API 示例中，使用当前公共页面或模式中的确切标识符和调用形状。复制请求语言的文档化形状，而不是在 TypeScript 和 Python 之间翻译名称；如果必需的细节未记录，则解释行为，不要编造代码。

## 规范信息

使用捆绑的参考进行稳定决策。用户界面源列表仅包含实际咨询的公共 `https://docs.composio.dev/...` 页面；捆绑参考名称、本地路径和 `file://` URL 被省略。对于版本、提供商适配器、客户端特定设置、工具包行为或可能已更改的 API，在回答或编辑代码之前，使用当前的规范文档和当前的 CLI 或工具模式作为主要来源：

当源不一致时，优先考虑当前 API 参考和实时端点行为，而不是任何标记为 Legacy 的页面，并明确指定 REST API 版本。

```text
https://docs.composio.dev/llms.txt
https://docs.composio.dev/docs/<page>.md
https://docs.composio.dev/toolkits/<toolkit>.md
```

如果这些主要来源无法回答 Composio 产品或故障排除问题，请查询公共统一知识搜索 `https://docs.composio.dev/api/knowledge-search?q=<question>`。

结果可能是规范文档、KB、工具包、示例或参考页面。使用返回的证据回答问题；公共记录不能确定用户账户、项目、连接或工具调用的实时状态。

当知识搜索提供证据时，引用返回的 `canonicalUrl`，而不是搜索 API URL。如果 `canonicalUrl` 是相对的，在引用它之前，请将其前缀为 `https://docs.composio.dev`。

仅当其摘录或页面直接回答问题时，才将结果视为证据。如果公共源未直接记录确切的错误或症状，请说明，而不是从相邻结果进行诊断；请求日志或请求 ID，或必要的实时证据。

使用文档完成任务。除非用户要求，否则不要仅仅将链接交给用户。
