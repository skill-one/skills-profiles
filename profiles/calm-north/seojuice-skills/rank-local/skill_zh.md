# 本地排名

构建本地SEO基础，涵盖Google商家资料优化、名称地址电话一致性、引用策略和评价速度。

## 本地SEO排名因素

本地搜索结果由三个主要因素决定：

1. **相关性** — 你的业务与搜索查询的匹配程度
2. **距离** — 你与搜索者的距离
3. **知名度** — 你的业务在线上的知名度和可信度

你不能控制距离，但可以最大化相关性和知名度。

## 第1步：Google商家资料审计

GBP是本地SEO最重要的资产。审计：

### 资料完整性
- [ ] 商业名称与实际名称完全一致（无关键词堆砌）
- [ ] 主要类别是最具体的匹配
- [ ] 次要类别涵盖所有相关服务（最多9个）
- [ ] 地址准确并与网站一致
- [ ] 电话号码是本地号码（非长途）并与网站匹配
- [ ] 网站URL指向正确页面
- [ ] 营业时间是准确的（包括节假日特殊时间）
- [ ] 商业描述自然使用关键词（最多750字符）

### 视觉内容
- [ ] 上传了标志和封面照片
- [ ] 至少10张照片（外部、内部、团队、产品/服务）
- [ ] 定期更新照片（理想情况为每月一次）
- [ ] 如适用，视频（最长60秒）

### 活跃功能
- [ ] 定期发布Google帖子（每周或每两周一次）
- [ ] 列出产品或服务，包含描述和价格
- [ ] 监控问答区（自己预设常见问题）
- [ ] 如团队能及时回复，启用消息功能
- [ ] 如适用，配置预订链接

## 第2步：名称地址电话一致性

NAP = 名称、地址、电话。必须处处相同：

- 网站（页脚、联系我们页面、结构化标记）
- Google商家资料
- 所有引用目录
- 社交媒体资料

**常见不一致问题：**
- "St" vs "Street" vs "St."
- "Suite 200" vs "#200" vs "Ste 200"
- 不同的电话号码（主线 vs 直线）
- 之前地址的旧地址
- 缩写 vs 完整商业名称

**如何检查：** 搜索`"商业名称" + "城市"`并检查所有出现的列表。记录不一致问题。

## 第3步：引用策略

引用是指其他网站上对您商业NAP的提及。关键目录：

### 基础引用（必须拥有）
- Google商家资料
- Apple地图 / Apple商家连接
- Bing地点
- Yelp
- Facebook商业页面
- BBB（更好商业局）

### 行业特定引用
因商业类型而异：
- **餐厅：** TripAdvisor、OpenTable、Zomato
- **医疗：** Healthgrades、Vitals、WebMD
- **法律：** Avvo、FindLaw、Justia
- **家庭服务：** HomeAdvisor、Angi、Thumbtack
- **房地产：** Zillow、Realtor.com、Redfin

### 本地引用
- 本地商会
- 城市区域商业目录
- 本地新闻网站和出版物
- 社区活动赞助页面

**优先级：** 质量重于数量。30个权威目录上的准确引用胜过200个低质量网站上的引用。

## 第4步：评价策略

评价直接影响本地套餐排名和转化率。

### 获取更多评价
- 在服务点向满意的客户询问
- 发送带有直接评价链接的跟进邮件/短信
- 使用Google评价链接生成器：`https://search.google.com/local/writereview?placeid=[PLACE_ID]`
- 培训员工询问——使其成为客户服务流程的一部分
- 从不激励评价（违反Google指南）

### 回复评价

**回复模板（自定义——切勿逐字复制）：**

**正面评价回复：**
"感谢您，[姓名]！很高兴[他们提到的具体事例]进展顺利。[简短的个人触点]。我们期待[未来互动]。"

关键：引用他们评价中的具体内容。泛泛的"感谢评价！"表明您未阅读。

**负面评价回复：**
"[姓名]，感谢您分享此反馈。我们很抱歉[承认具体问题]。这不是我们追求的体验。请通过[联系方式]联系我们，以便我们纠正。"

关键：24小时内回复。承认具体问题。线下解决。切勿公开争论。

**虚假评价回复：**
"我们没有此互动记录。如果您是客户，请通过[邮箱/电话]联系我们，以便我们调查。"

关键：首先通过GBP仪表板报告。客观回复，避免防御。不要指控——陈述事实。

### 评价速度
- 目标是稳定持续的评价——而非爆发式
- 突然的评价激增看起来不自然
- 2-5个每月新评价对大多数小企业来说是健康的
- 月度跟踪评价速度

## 第5步：本地内容

为您的网站创建与位置相关的内容：

- **位置页面**（如果是多地点）：每个位置独特内容，非重复模板
- **本地服务页面：** "[服务]在[城市]"页面，具有真实本地相关性
- **本地博客内容：** 社区参与、本地活动、本地案例研究
- **常见问题解答页面：** 回答位置特定问题

**避免：** 门户页面（薄、模板化页面针对每个社区/邮编）。

## 第6步：本地结构化数据

向您的网站添加结构化数据：

### LocalBusiness结构化数据
```json
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "name": "商业名称",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "123 Main St",
    "addressLocality": "城市",
    "addressRegion": "州",
    "postalCode": "12345"
  },
  "telephone": "+1-555-555-5555",
  "openingHoursSpecification": [...],
  "geo": {
    "@type": "GeoCoordinates",
    "latitude": "40.7128",
    "longitude": "-74.0060"
  }
}
```

使用最具体的商业类型：`餐厅`、`牙科诊所`、`律师事务所`等，而非通用的`LocalBusiness`。
