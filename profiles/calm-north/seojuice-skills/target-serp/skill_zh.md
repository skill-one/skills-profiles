# 目标搜索结果页（SERP）

识别并获取目标关键词的特写片段、人们也问（People Also Ask）框、知识面板以及丰富结果。

## SERP 功能类型

| 功能 | 触发条件 | 需要的内容格式 |
|------|----------|----------------|
| 特写片段（段落） | "是什么"、"如何"、"定义性查询 | 40-60 字的直接答案，位于与查询匹配的 H2/H3 下 |
| 特写片段（列表） | "如何做"、"步骤"、"最佳"、"顶级" | 带有 H2/H3 标题的有序或无序列表 |
| 特写片段（表格） | 比较查询、价格查询、规格查询 | 清晰标题的 HTML `<table>` |
| 人们也问（People Also Ask） | 大部分信息性查询 | 与 PAA 问题匹配的 H2 下 2-3 句的简洁答案 |
| 知识面板 | 品牌或实体查询 | 结构化数据（组织、人物）、维基百科存在性、一致的 NAP（名称、地址、电话号码） |
| 丰富结果（FAQ） | 包含 FAQ 内容的页面 | FAQPage schema 标记 |
| 丰富结果（如何操作） | 指导性页面 | HowTo schema 标记 |
| 丰富结果（评论） | 产品/服务评论页面 | Review/AggregateRating schema 标记 |
| 丰富结果（面包屑导航） | 任何具有层级结构的页面 | BreadcrumbList schema 标记 |
| 网站链接 | 品牌查询 | 清晰的网站结构、描述性导航、内部链接 |

## SERP 功能优先级矩阵

并非所有 SERP 功能都具有同等价值。使用此矩阵来决定在哪里投入精力：

| SERP 功能 | 流量影响 | 获胜所需努力 | 适合类型 |
|----------|----------|--------------|----------|
| 特写片段 | 非常高 | 中等 | 信息性内容网站 |
| AI 概览引用 | 高（增长中） | 中高 | 权威性/专业知识网站 |
| 人们也问 | 中高 | 低-中等 | FAQ 丰富内容 |
| 视频轮播 | 高 | 高 | 指导性内容 |
| 本地面板 | 非常高（本地） | 中等 | 本地企业 |
| 丰富结果（评论） | 中高 | 低-中等 | 产品/服务评论 |
| 图片包 | 中等 | 低-中等 | 视觉内容创作者 |
| 购物结果 | 非常高（电子商务） | 中等 | 产品销售者 |
| 知识面板 | 中等（品牌） | 高（长期） | 已建立品牌 |

### 功能组合模式

当多个功能同时出现时，针对组合进行优化：

| 组合 | 机会 |
|------|------|
| AI 概览 + 特写片段 | 优化两者——结构化内容与清晰答案可赢得两个位置 |
| 视频 + 人们也问 + 特写片段 | 创建包含视频和 FAQ 部分的综合指南 |
| 购物 + 广告 + 评论 | 产品优化 + 评论 schema + 商户数据流 |
| 仅人们也问（无特写片段） | 特写片段机会——创建特写优化内容以获取该位置 |
| 仅 AI 概览（无特写片段） | 结构化、权威性内容，带引用数据可被 AI 包含 |

### AI 概览与传统 SERP 策略

| 查询类型 | 传统策略 | AI 时代策略 |
|----------|----------|-------------|
| 信息性 | 赢得特写片段 | 赢得 AI 概览引用 AND 特写片段 |
| 比较 | 创建比较内容 | 创建结构化比较表格，带清晰结论 |
| 定义 | 写清晰的定义 | 写权威性、可引用的定义，带证据 |
| 如何操作 | 创建步骤列表 | 创建带独特见解的步骤，AI 可综合 |

传统功能奖励**格式优化**。AI 概览奖励**权威性和独特性**。

## 第 1 步：审计当前 SERP 功能

针对每个目标关键词：

1. **搜索关键词**并记录出现的 SERP 功能
2. **记录当前持有每个功能的内容**（哪个域名，什么内容格式）
3. **检查您的网站是否已在任何功能中显示**针对此关键词
4. **评估可赢性**——您能否匹配或超越当前持有者的内容格式？

| 关键词 | 功能存在 | 当前持有者 | 您的页面 | 可赢性 |
|------|----------|------------|----------|--------|
| ... | 特写片段（段落） | 竞争对手.com | /blog/topic | 是——需要更好的答案 |
| ... | 人们也问（3 个问题） | 各种 | 无页面 | 是——创建 FAQ 部分 |
| ... | 知识面板 | — | — | 无——需要维基百科存在性 |

## 第 2 步：特写片段优化

特写片段直接从页面中提取内容。要赢得它们：

### 段落特写片段
- 将简洁的答案（40-60 字）直接放在与查询匹配的 H2 或 H3 下
- 以定义或直接陈述开头："[主题] 是..."
- 在特写诱饵后添加扩展细节（Google 希望页面有深度，而不仅仅是特写）

### 列表特写片段
- 使用正确的 HTML 有序或无序列表
- H2 标题应与查询匹配："如何做某事"或"最佳类别"
- 5-8 个列表项（Google 很少显示更多）
- 每个项目应是一个简洁、可扫描的短语

### 表格特写片段
- 使用语义 HTML `<table>`，带 `<thead>` 和 `<tbody>`
- 列标题应具有描述性
- 保持 3-5 列，4-8 行
- 在表格标题或前置标题中包含查询关键词

### 特写片段优化检查清单
- [ ] H2/H3 标题与目标查询完全或非常接近匹配
- [ ] 答案出现在标题后的第一段
- [ ] 答案是自包含的（没有上下文也能理解）
- [ ] 页面已在第 1 页上针对关键词排名（特写几乎总是来自第 1 页结果）
- [ ] 内容格式与 Google 当前显示的匹配（段落、列表或表格）

## 第 3 步：人们也问（People Also Ask）优化

人们也问框在信息性搜索中占很大比例。要获取它们：

1. **收集针对目标关键词的 PAA 问题**
2. **在相关页面上添加 FAQ 部分**，使用确切的问题作为 H2 或 H3
3. **用 2-3 句话直接在标题下回答**
4. **使用 FAQPage schema 标记**以获得丰富结果资格

PAA 答案应：
- 直接简洁（无"好问题！"开场白）
- 事实准确
- 自包含（答案独立）

## 第 4 步：Schema 标记

添加结构化数据以获得丰富结果资格。

**重要提示：** Google 在 2023 年 8 月大幅限制了 FAQ 丰富结果。FAQPage
schema 现在仅对知名政府与健康权威网站生成丰富结果。对于大多数网站，FAQ schema 仍有助于 AI 系统提取问答内容，但不会在 Google SERP 中产生可见的丰富结果。

### FAQPage（AI 提取——对大多数网站不产生可见丰富结果）
```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [{
    "@type": "Question",
    "name": "什么是[主题]?",
    "acceptedAnswer": {
      "@type": "Answer",
      "text": "直接答案。"
    }
  }]
}
```

### HowTo
用于分步内容。包括 `name`、`step` 数组（带 `HowToStep`）、`estimatedCost` 和 `totalTime`：
```json
{
  "@context": "https://schema.org",
  "@type": "HowTo",
  "name": "如何做[某事]",
  "totalTime": "PT30M",
  "step": [{
    "@type": "HowToStep",
    "name": "步骤 1 标题",
    "text": "步骤 1 描述",
    "image": "https://example.com/step1.jpg"
  }]
}
```

### Article
用于博客文章和指南：包括 `headline`、`datePublished`、`dateModified`、`author`、`image`。

### BreadcrumbList
对于每个具有层级导航的页面：定义从主页到当前页面的路径。

### VideoObject
对于包含嵌入式视频的页面——启用视频丰富结果和视频轮播：
```json
{
  "@context": "https://schema.org",
  "@type": "VideoObject",
  "name": "视频标题",
  "description": "视频描述",
  "thumbnailUrl": "https://example.com/thumb.jpg",
  "uploadDate": "2026-01-15",
  "duration": "PT5M30S",
  "contentUrl": "https://example.com/video.mp4"
}
```

### Dataset
对于包含原创研究或数据的页面——在 Google Dataset 搜索中显示：
```json
{
  "@context": "https://schema.org",
  "@type": "Dataset",
  "name": "数据集标题",
  "description": "数据集包含的内容",
  "creator": { "@type": "Organization", "name": "您的品牌" },
  "datePublished": "2026-01-15",
  "license": "https://creativecommons.org/licenses/by/4.0/"
}
```

### SpeakableSpecification
标记适合文本到语音和语音助手提取的内容部分：
```json
{
  "@context": "https://schema.org",
  "@type": "WebPage",
  "speakable": {
    "@type": "SpeakableSpecification",
    "cssSelector": [".article-summary", ".key-finding"]
  }
}
```

**验证：** 部署前始终使用 Google 的丰富结果测试工具验证 schema。

## 第 5 步：行动计划

针对每个目标关键词和功能：

| 关键词 | 目标功能 | 当前状态 | 需要采取的行动 | 优化页面 | 优先级 |
|------|----------|----------|----------------|----------|--------|
| ... | 特写片段 | 竞争对手持有 | 添加匹配 H2 下的特写诱饵段落 | /blog/guide | 高 |
| ... | 人们也问 | 我们网站上不存在 | 添加带 schema 的 FAQ 部分 | /blog/guide | 中等 |
| ... | 丰富结果（FAQ） | 无 schema | 添加 FAQPage JSON-LD | /faq | 低 |
