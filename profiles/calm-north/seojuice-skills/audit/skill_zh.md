# SEO 审计

运行全面的 SEO 审计，涵盖技术基础、页面优化、内容质量、链接配置和竞争定位。

## 开始前

收集此背景信息（如未提供，请询问）：

1. **域名**。我们要审计哪个网站？
2. **目标**。你试图实现什么？（更多流量、更好的排名、解决下降问题、预发布检查）
3. **已知问题**。你是否有任何怀疑是错误的？
4. **访问权限**。你是否有 Google 搜索控制台和 Google 分析仪数据？（这会显著提高审计效果）
5. **范围**。全面审计还是专注于特定领域？（如有不确定，请运行全面审计）

## 审计框架

完整的 SEO 审计涵盖五个层次。按顺序处理它们——早期层级的错误会破坏后续所有内容。

```
第 1 层：技术基础 ← Google 能否抓取和索引网站？
第 2 层：页面优化 ← 页面是否针对目标关键词进行了优化？
第 3 层：内容质量 ← 内容是否值得排名？
第 4 层：链接配置 ← 网站是否具有权威性？
第 5 层：竞争定位 ← 网站与竞争对手相比如何？
```

## 第 1 层：技术基础

检查搜索引擎是否可以正确访问、抓取、渲染和索引网站。

### 可抓取性
- [ ] `robots.txt` — 获取并审查。是否有关键路径被阻止？是否有站点地图指令？
- [ ] XML 站点地图 — 是否存在、有效的 XML、列出所有重要页面、排除 noindex/重定向页面？
- [ ] 站点架构 — 重要页面是否可以从主页通过 3 次点击到达？
- [ ] 孤立页面 — 是否有任何页面没有零个内部链接指向它们？
- [ ] 重定向链 — 是否有任何路径包含 2 次或更多重定向？
- [ ] HTTP 状态 — 所有重要页面是否返回 200？没有意外的 301、404 或软 404？

### 可索引性
- [ ] `noindex` 标签 — 是否有任何重要页面意外被 noindexed？
- [ ] 规范标签 — 所有页面是否都有自我引用？没有冲突的规范标签？
- [ ] 重复内容 — 是否有相同内容在多个 URL 上可访问（www/非 www、HTTP/HTTPS、尾随斜杠）？
- [ ] 搜索控制台索引覆盖率 — 提交的页面与索引的页面数量是多少？是否有应该被索引但被排除的页面？

### 性能
- [ ] 核心网络指标 — LCP < 2.5 秒，CLS < 0.1，INP < 200 毫秒？
- [ ] TTFB — 从主要地区 < 800 毫秒？
- [ ] 移动友好 — 是否通过 Google 的移动可用性测试？
- [ ] HTTPS — 是否在整个网站中强制使用？证书是否有效？

### 渲染
- [ ] 依赖 JavaScript 的内容 — 关键内容是否在初始 HTML 中或通过 JS 加载？
- [ ] 内容可见性 — 搜索引擎是否可以看到完整页面的内容？

## 第 2 层：页面优化

检查单个页面是否针对其目标关键词进行了正确优化。

### 标题标签
- [ ] 每个页面都有一个唯一的 `<title>`
- [ ] 标题包含主要目标关键词
- [ ] 标题长度不超过 60 个字符（避免截断）
- [ ] 标题描述性强且值得点击（不要堆砌关键词）

### 元描述
- [ ] 每个重要页面都有一个唯一的元描述
- [ ] 描述长度为 150-160 个字符
- [ ] 描述包含价值主张和号召性用语

### 标题结构
- [ ] 每个页面只有一个 H1 包含主要关键词
- [ ] 逻辑标题层次结构（H1 → H2 → H3，没有跳过层级）
- [ ] 标题准确描述了部分内容

### URL 结构
- [ ] URL 干净、易读、描述性强
- [ ] URL 使用连字符（而不是下划线）
- [ ] 索引 URL 中没有过多的 URL 参数或会话 ID
- [ ] 网站范围内 URL 结构一致

### 内部链接
- [ ] 重要页面有足够的入站内部链接（3 个以上）
- [ ] 锚文本描述性强且多样化（不是所有“点击这里”）
- [ ] 存在主题集群的枢纽和辐条结构
- [ ] 没有损坏的内部链接（404 目标）

### 图片优化
- [ ] 所有图片都有描述性的 `alt` 属性
- [ ] 图片使用现代格式（WebP/AVIF）在支持的情况下
- [ ] 图片尺寸适当（不要在 400 像素的容器中提供 4000 像素的图片）
- [ ] 装饰性图片使用空的 `alt=""`

### 结构化数据
- [ ] 存在相关的模式标记（文章、产品、常见问题、本地业务、面包屑列表等）
- [ ] 模式在 Google 的丰富结果测试中验证无误
- [ ] 模式与可见页面内容匹配（没有隐藏/误导性标记）

### 页面级评分标准

对于详细的页面级审计，在 8 个部分对每个页面进行评分：

| 部分 | 权重 | 评分内容 |
|------|------|---------|
| 标题标签 | 15% | 关键词存在、在第一部分、50-60 字符、唯一、有吸引力、意图匹配 |
| 元描述 | 5% | 包含关键词、150-160 字符、包含号召性用语、唯一 |
| 标题结构 | 10% | 单个 H1 包含关键词、逻辑层次结构（没有跳过层级）、H2 涵盖子主题 |
| 内容质量 | 25% | 足够的长度、全面、独特价值、最新、良好格式、E-E-A-T 信号 |
| 关键词优化 | 15% | 关键词在标题/H1/前 100 字符/URL、密度 0.5-2.5%、包含语义术语 |
| 内部/外部链接 | 10% | 足够的内部链接、描述性锚文本、高质量外部链接、没有损坏的链接 |
| 图片优化 | 10% | 所有图片都有 alt 文本、描述性文件名、优化尺寸、现代格式 |
| 页面级技术 | 10% | 干净 URL、正确的规范标签、移动友好、LCP ≤2.5 秒、HTTPS、存在模式 |

**内容长度基准**（“足够长度”获得满分）：

| 意图类型 | 目标字数 |
|--------|---------|
| 信息性 | 1,500+ 字 |
| 商业调查 | 1,200+ 字 |
| 交易性 | 500+ 字 |
| 本地 | 400+ 字 |

**内部链接数量指南:**

| 页面长度 | 目标内部链接数量 |
|--------|----------------|
| <500 字 | 2-4 个链接 |
| 500-1,000 字 | 3-6 个链接 |
| 1,000-2,000 字 | 5-10 个链接 |
| 2,000+ 字 | 8-15 个链接 |

**关键词密度惩罚:** >3.0% = 关键词堆砌（得分为 0）；<0.5% = 优化不足。

**评分等级标准:**

| 得分 | 等级 | 评估 |
|------|------|------|
| 90-100 | A+ | 优秀 — 保持 |
| 80-89 | A | 强劲 — 小幅调整 |
| 70-79 | B | 良好 — 几个方面需要关注 |
| 60-69 | C | 一般 — 需要显著改进 |
| 50-59 | D | 低于一般 — 主要问题 |
| <50 | F | 差 — 需要全面改进 |

## 第 3 层：内容质量

评估内容是否值得排名。

### E-E-A-T 评估
- **经验** — 内容是否展示了第一手经验？
- **专业性** — 内容是否具有主题深度？是否超越了表面？
- **权威性** — 网站是否在该主题领域具有声誉？作者是否可信？
- **可信度** — 声称是否有来源？网站是否透明地说明了发布者？

### 内容覆盖范围
- [ ] 每个页面是否有明确的目标关键词和意图？
- [ ] 内容是否足够全面以完全满足搜索查询？
- [ ] 是否有薄页面（< 300 字）应该扩展或合并？
- [ ] 内容是否最新？是否有页面包含过时数据、损坏的示例或过时的建议？

### 内容差距
- [ ] 竞争对手涵盖哪些主题而本网站没有？
- [ ] 是否有搜索需求的关键词没有现有页面针对？
- [ ] 是否有主题集群不完整（支柱页面但缺少辐条，反之亦然）？

### 重复内容
- [ ] 是否有多个页面针对相同的关键词？
- [ ] 如果是，它们是否在排名中相互竞争？
- [ ] 解决方案：合并、区分或使用规范标签将较弱页面指向较强页面。

## 第 4 层：链接配置

评估网站的背链权威性和质量。

### 背链概述
- 引用域名总数
- 顺链与无顺链比例
- 链接获取趋势（增长、稳定或下降？）
- 引用域名的平均权威性

### 链接质量
- [ ] 是否有任何高垃圾分数的引用域名可能触发处罚？
- [ ] 链接是内容中的上下文链接还是低价值链接（侧边栏、页脚、评论）？
- [ ] 锚文本分布 — 自然多样化还是可疑的过度优化？

### 链接差距
- [ ] 哪些竞争对手页面获得最多的背链？内容类型是什么？
- [ ] 是否有损坏的背链值得恢复？（曾经有链接的 404 页面）
- [ ] 网站上是否有可推广的链接资源？

## 第 5 层：竞争定位

了解网站相对于竞争对手的位置。

### 关键词重叠
- 你与竞争对手共享哪些关键词？
- 你在哪里获胜或失败？
- 竞争对手排名哪些你未排名的关键词？

### 内容比较
- 内容深度和质量与排名靠前的竞争对手相比如何？
- 竞争对手使用哪些你未使用的格式（视频、工具、模板）？
- 你的内容有哪些独特角度或数据可以使其脱颖而出？

### 权威性比较
- 你的域名权威性/评级与竞争对手相比如何？
- 竞争对手的引用域名是否显著更多？
- 你是否有未追求的权威性建设机会？

## 评分

完成所有层级后，分配健康评分：

| 层级 | 权重 | 得分（1-10） | 加权 |
|------|------|------------|------|
| 技术基础 | 25% | [得分] | [加权] |
| 页面优化 | 20% | [得分] | [加权] |
| 内容质量 | 25% | [得分] | [加权] |
| 链接配置 | 15% | [得分] | [加权] |
| 竞争定位 | 15% | [得分] | [加权] |
| **总体** | **100%** | | **[总分]** |

**评分指南:**
- 8-10: 强劲 — 保持并优化
- 5-7: 需要改进 — 明显的改进机会
- 1-4: 严重问题 — 基本问题阻碍性能

### 一票否决条件

这些条件**限制总体得分**，无论其他层级表现如何。
单个一票否决项阻止网站在存在致命缺陷时显示为健康：

| 条件 | 限制 | 理由 |
|------|------|------|
| `robots.txt` 阻止所有 Googlebot 或阻止 `/` | 总体限制为 1/10 | 如果 Google 无法抓取，其他都不重要 |
| > 20% 的重要页面意外使用 `noindex` | 总体限制为 3/10 | 网站的大部分对搜索引擎不可见 |
| 所有三个核心网络指标均为“差” | 技术限制为 3/10 | Google 优先考虑用户体验极差的网站 |
| 整个域名零外部链接 | 链接配置限制为 2/10 | 没有外部权威信号 |
| 网站提供 HTTP 而没有重定向到 HTTPS | 技术限制为 4/10 | Google 要求 HTTPS 以获得信任信号 |
| Google 手动操作激活 | 总体限制为 2/10 | 处罚覆盖所有优化 |

在评分层级**之前**检查一票否决条件。如果任何一票否决项触发，请在执行摘要中突出标记并限制相关得分。
