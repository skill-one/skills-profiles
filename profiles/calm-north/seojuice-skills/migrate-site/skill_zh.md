# 网站迁移指南

指导域名迁移、CMS切换或URL结构调整，不丢失排名 — 重定向映射、监控计划及回滚标准。

## 迁移类型

| 类型 | 风险等级 | 示例 |
|------|-----------|---------|
| 域名变更 | 高 | olddomain.com → newdomain.com |
| 协议变更 | 低 | HTTP → HTTPS |
| CMS切换 | 中高 | WordPress → Next.js, Shopify → 自定义 |
| URL结构调整 | 中 | /blog/2024/post → /blog/post |
| 子域名迁移 | 中 | blog.example.com → example.com/blog |
| 设计/模板变更 | 低中 | 同一URL，新模板 |

所有迁移都存在SEO风险。目标是尽量减少流量下降并加快恢复速度。

## 第一阶段：迁移前审计

### 全面盘点

在触碰任何东西之前，记录当前状态：

**页面：**
- [ ] 所有索引URL的完整列表（来自站点地图 + 搜索控制台）
- [ ] 每个页面的月访问量（搜索控制台，过去6个月）
- [ ] 每个页面的顶级关键词和排名
- [ ] 每个页面的反向链接数量（包含外部链接的页面需要特别关注）

**技术：**
- [ ] 当前robots.txt文件
- [ ] 当前XML站点地图
- [ ] 当前重定向规则
- [ ] 当前结构化数据
- [ ] 当前规范标签
- [ ] 当前内部链接结构

**性能：**
- [ ] 有机流量基线（每周和每月）
- [ ] 流量排名前50的页面
- [ ] 核心网络指标得分
- [ ] 搜索控制台的抓取统计

**保存所有数据。** 你需要这些数据来与迁移后进行比较。

### 识别高价值页面

不是所有页面都平等。为这些页面特别关注：

- 有最多有机流量的页面（前20%）
- 有外部反向链接的页面
- 排名高价值关键词的页面
- 转化相关的着陆页
- 有特色片段的页面

这些页面必须有有效的重定向，并且在迁移后应单独进行验证。

## 第二阶段：重定向映射

重定向映射是最关键的结果。每个旧URL都必须映射到正确的URL。

### 映射规则

| 旧URL | 新URL | 类型 | 备注 |
|---------|---------|------|-------|
| /old-page | /new-page | 301 | 内容匹配 |
| /removed-page | /最相关的页面 | 301 | 合并到相关页面 |
| /deleted-page | / | 301 | 无相关页面 — 发送到主页（最后手段） |

**规则：**
- 使用**301重定向**进行永久移动（不是302）
- 将每个旧URL映射到**最相关**的新URL（不是全部映射到主页）
- 尽可能保留URL结构（重定向越少 = 风险越低）
- 避免重定向链（旧 → 中间 → 新）。每个重定向应该是直接的。
- 处理URL变体：带/不带尾随斜杠，带/不带www，HTTP/HTTPS

### 常见陷阱
- 忘记重定向分页URL (/page/2, /page/3)
- 遗漏有反向链接的查询参数URL
- 大小写敏感问题（某些服务器将/Page和/page视为不同）
- 将所有内容重定向到主页（会破坏页面级权威）

## 第三阶段：技术设置

### 切换前

- [ ] 新站点完全可抓取（不留staging robots.txt）
- [ ] 所有重定向规则已实施并测试
- [ ] 新XML站点地图已准备好（包含新URL）
- [ ] 新页面的规范标签指向新URL（不是旧URL）
- [ ] 内部链接更新为新URL（不要依赖重定向链处理内部链接）
- [ ] 结构化数据更新为新的URL
- [ ] Hreflang标签更新（如果是多语言）
- [ ] 为新域名在搜索控制台创建属性（如果是域名变更）
- [ ] 新站点上的分析跟踪已更新
- [ ] CDN/缓存配置为新站点

### 切换过程

- [ ] 部署重定向规则
- [ ] 部署新站点
- [ ] 验证重定向是否正常工作（抽查20+URL）
- [ ] 向搜索控制台提交新站点地图
- [ ] 如果域名变更：使用搜索控制台的变更地址工具
- [ ] 使用搜索控制台的URL检查功能强制抓取关键页面
- [ ] 实时监控服务器错误，迁移后24小时内

## 第四阶段：迁移后监控

### 第一周（每日检查）

- [ ] 检查搜索控制台中的抓取错误（404，5xx错误）
- [ ] 验证有机流量没有灾难性下降
- [ ] 检查重定向是否仍然正常
- [ ] 查找应重定向但返回404的页面
- [ ] 监控服务器响应时间（迁移可能暴露性能问题）

### 第2-4周（每周检查）

- [ ] 将有机流量与迁移前基线进行比较
- [ ] 检查搜索控制台中的索引状态（索引页面数量）
- [ ] 验证关键页面是否在新URL下被索引
- [ ] 检查顶级关键词的排名
- [ ] 查看抓取统计中的异常情况

### 第2-3个月（每月检查）

- [ ] 流量应恢复到迁移前水平
- [ ] 所有旧URL应在搜索控制台中显示为已重定向
- [ ] 新URL应被索引并排名
- [ ] 核心网络指标应保持稳定

### 预期时间线

- **流量下降：** 正常。预期在2-4周内下降10-30%。
- **恢复：** 大多数网站在重定向正确的情况下可在2-3个月内恢复。
- **完全稳定：** 大型网站需要3-6个月。
- **警告标志：** 如果4周后流量仍未开始恢复，请调查。

## 第五阶段：回滚计划

在迁移前，定义回滚标准：

**回滚条件：**
- 有机流量下降 > 50%，持续超过7天
- 超过20%的重定向损坏
- 关键转化页面无法访问
- 服务器错误超过可接受阈值

**回滚步骤：**
1. 如果域名变更，则还原DNS或重新部署旧站点
2. 删除或撤销重定向
3. 重新提交旧站点地图
4. 调查出错原因，再尝试
