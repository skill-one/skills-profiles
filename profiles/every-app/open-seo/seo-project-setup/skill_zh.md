# OpenSEO SEO 项目设置

## 目标

对用户关于一个网站或 SEO 项目的单次访谈，并将答案存储在 OpenSEO 中的该项目共享上下文中，使用 `update_project_context`。该上下文被其他所有技能、应用中的 SAM 以及用户在项目的上下文页面（AI 侧边栏下）读取——因此它能在新会话、新机器和新代理之间持续存在。这是一个上下文设置工作流，而不是完整的审计。

## 语气

保持友好、实用和结构化。分批提问。仅在必要时解释每个项目的重要性。不要用术语让初学者感到不知所措。

## 答案存储位置

两个项目上下文 MCP 工具负责所有写入操作。两者都是免费的——它们不消耗任何积分。

- `get_project_context(projectId)`: 项目已知信息，以及一个 `missingSections` 列表。
- `update_project_context(projectId, updates)`: 一系列补丁操作。该技能使用的操作：
  - `{ section: "business_overview" | "current_goal" | "positioning" | "writing_preferences", content }`
  - `{ addCompetitors: [{ domain, name?, notes? }] }`
  - `{ addKeyPages: [{ url, role: "hub" | "spoke" | "money" | "other", topic?, notes? }] }`
  - `{ customSection: "<slug>", title?, content }` 用于任何不符合定型部分的项
  - `{ appendResearchLog: { summary } }` 当此会话消耗积分时

随着访谈的进行分批写入——不要等到最后才保存所有答案。部分是散文 (~4,000 字符每个)，所以是几段紧凑的段落，而不是记录。

## 检查清单

### 1. 验证 OpenSEO MCP 并解决项目

写入操作需要一个 `projectId`，所以先做这个：

1. 如果可用，使用 `whoami`。
2. 使用 `list_projects` 确认用户可以访问项目。
3. 将项目与用户希望排名的网站/域名进行匹配。
4. 如果项目列表不明确，询问用户应使用哪个项目。
5. 如果没有匹配的项目，提供使用 `create_project` 创建一个。
6. 如果 MCP 不可用，告诉用户连接 OpenSEO MCP；没有它，什么也保存不了。

不要运行研究工具仅测试连接性；`whoami` 和 `list_projects` 足够。

### 2. 读取现有内容

调用 `get_project_context`。向用户展示 OpenSEO 已知内容的简短摘要和缺失内容。确认或修正现有条目，而不是重新询问已经回答的问题——该技能经常在另一个技能填充部分上下文后重新运行。

### 3. 收集网站范围

询问：

- 主要网站/域名
- 其他域名或子域名
- 重要产品、服务、类别或页面
- 目标国家/语言
- 网站是新的、已建立的、迁移的或从流量下降中恢复的
- 如果相关，CMS 或发布工作流

将持久部分写入 `business_overview`：业务做什么、为谁服务、目标市场/地区、以及网站的当前阶段。

### 4. 捕获目标

询问用户他们希望通过 SEO 实现什么：

- 更多合格线索
- 更多注册/试用
- 更多电商收入
- 更多订阅者/受众增长
- 更多品牌/类别知名度
- 从流量损失中恢复
- 特定页面排名提升

询问成功指标和时间表。如果目标模糊，帮助将其转化为可衡量的目标，例如“增加非品牌自然注册”或“在 20 个购买意向术语中排名前 10”。

将结果写入 `current_goal`，包括指标和时间表。

### 5. 捕获定位和策略上下文

询问他们已经对公司、产品、受众和竞争对手做了哪些研究。请求他们分享任何笔记、文档、客户访谈、定位文档、演示文稿、着陆页或策略备忘录。

探索：

- 产品或网站是为谁服务的
- 它解决了什么痛点
- 用户为什么选择它而不是替代品
- 竞争者和替代品
- 强烈的观点或定位声明
- 最佳客户和不适用的客户
- 现有已转化的内容
- 他们不想定位的主题

如果用户还没有做过这些，提供使用公司网站、竞争对手页面、评论、论坛和网络搜索来帮助研究定位。

写入 `positioning`：受众、问题、差异化以及用户希望捍卫的任何声明。询问关于语气、禁止的词语或短语以及要避免的主题，并将这些写入 `writing_preferences`——内容起草工作流会读取该部分。

### 6. 保存竞争对手

将第 5 步的竞争对手和替代品转换为 `addCompetitors` 条目：每个域名一行，简短的 `notes` 行说明其重要性（“直接竞争对手，拥有比较页面”）。如果用户不确定搜索中的竞争对手是谁，`find_serp_competitors` 在少量种子关键词上会命名它们——在保存前与用户确认列表，并记录消耗。

这里保存的竞争对手会被 `competitive-landscape`、`competitor-analysis` 和 `link-prospecting` 重用。

### 7. 梳理关键资产

询问或发现：

- 网站地图或重要 URL 列表
- 当前博客/资源/内容库
- 产品/类别/功能页面
- 现有关键词列表
- 当前排名追踪器
- 反向链接或 PR 资产
- 可链接资产，如研究、模板、工具、数据集、计算器或原创观点

使用 `addKeyPages` 保存实际重要的页面——盈利页面、主题中心以及可链接资产。这是一个精选短列表，而不是网站清单：10 到 30 个 URL 是正常的。给每个页面分配一个 `role`，如果已知，则分配其目标 `topic`。

### 8. 连接 Google Search Console

GSC 是最丰富的第一方信号：现有印象、近排名术语、吞噬和已有搜索需求的页面。

**首选（托管）：原生连接。** 在项目的集成页面，连接 Google Search Console 并使用 `get_search_console_performance` 拉取实时数据。一旦连接，代理直接在 `keyword-research` 和 `keyword-clustering` 中读取它——无需维护手动文件。

**备用（自托管，或如果用户更喜欢文件）：** 询问用户将 Search Console 的 CSV 导出到本地工作文件夹（见第 9 步）。

推荐导出：

- 查询：最近 3 个月，如果可用，最近 16 个月
- 页面：最近 3 个月，如果可用，最近 16 个月
- 查询 + 页面组合，如果可能
- 如果相关，国家/设备

询问他们将文件放入 `gsc/` 并使用类似名称：

```text
gsc/queries-last-3-months.csv
gsc/pages-last-3-months.csv
gsc/queries-last-16-months.csv
gsc/pages-last-16-months.csv
```

### 9. 设置仅用于文件工作的本地文件夹

项目知识存在于 OpenSEO 中，而不是磁盘上。本地文件夹仍然对实际文件有用：GSC CSV 导出、爬取、草稿、简报和报告。

如果用户需要，建议 `~/SEO/<公司或网站>/` 或网站/内容仓库旁边的一个文件夹，结构如下：

```text
seo-workspace/
  gsc/
  drafts/
  reports/
```

除非用户请求，否则不要创建文件夹，也不要将目标、定位或竞争对手复制到本地文件——这就是项目上下文的作用。

### 10. 推荐第一个工作流

在收集信息后，推荐一个下一个 OpenSEO 工作流：

- `seo-audit`：当网站已存在且用户想知道要修复或首先做什么，尤其是如果他们对 SEO 不熟悉
- `keyword-research`：当用户需要从种子主题获取想法
- `keyword-clustering`：当他们有关键词或 GSC 数据映射到页面
- `competitive-landscape`：当市场不明确
- `competitor-analysis`：当他们知道一个竞争对手要研究
- `link-prospecting`：当他们有一个可链接资产或目标页面

## 输出格式

使用带有状态的检查清单：

| 步骤 | 状态 | 备注 | 下一步操作 |
| ---- | ------ | ----- | ----------- |

然后总结：

- OpenSEO MCP/项目状态
- 范围内的网站
- 目标
- 已知定位
- 保存的竞争对手
- 保存的关键页面
- 搜索控制台状态和任何本地文件
- 项目上下文中仍然缺失的部分
- 推荐的下一个工作流

告诉用户他们可以在项目的上下文页面（AI 侧边栏下）阅读和编辑这里保存的所有内容。

## 防护措施

- 保持设置轻量级。用户应该感到有方向，而不是被分配作业。
- 在写入事实前与用户确认。从网站推断的事实可以提出，但它们被保存为同意的答案，而不是猜测。
- 除非能看到，否则不要假装已上传 GSC CSV，并且除非 `get_search_console_performance` 确认，否则不要声称已连接 Search Console（否则它会返回“未连接”消息）。
- 除非用户要求实时研究，否则保持项目设置专注于设置和上下文。如果某个步骤消耗积分，请附加一个研究日志条目，以便其他技能不会重新购买。
- 如果使用网络搜索或抓取进行定位研究，请区分来源证据和推断。
- 覆盖部分将替换它。当上下文已存在时，将新答案合并到现有散文中，而不是丢弃它。
