# Plannotator 可视化解释器

根据内容类型分为三种路径。每种路径都有其自身的参考和结构。

## 按内容类型划分路径

**实施计划、设计文档或提案** → 跟随 [计划路径](#计划路径)。阅读 `references/design-system.md` 和 `references/svg-patterns.md`。具有规定结构。

**PR 解释、差异审查或代码变更演练** → 跟随 [PR 路径](#pr路径)。阅读 `references/design-system.md` 和 `references/pr-components.md`。具有规定结构。

**其他所有内容**（架构图、数据表、幻灯片演示文稿、项目总结、一般可视化解释）→ 跟随 [可视化解释器路径](#可视化解释器路径)。委托给 nicobailon/visual-explainer 并使用 Plannotator 主题标记。

## 交付

始终通过 Plannotator 的注释 UI 进行交付。不要使用 `open` 或 `xdg-open`。

对于任何使用 Mermaid 的可交付内容，在打开注释 UI 之前，必须在浅色和深色调板中用 Mermaid 12 渲染每个图表。渲染是一个硬性门槛：异常、空 SVG 或错误输出（例如 `aria-roledescription="error"` 或 `Syntax error in text`）表示解释器不可交付。修复图表或主题配置并重新运行两个调板，直到每个 SVG 通过。

对于可缩放图表外壳，在交付前，在两个调板中分别缩放到最大并平移到所有极端：图形标题必须始终保持完全可读（参见 `references/diagram-shell.md`）。

**计划/提案**（用户应批准/拒绝）：
```bash
plannotator annotate <file> --gate
```

**其他所有内容**（信息性）：
```bash
plannotator annotate <file>
```

## 计划路径

适用于实施计划、设计文档、功能规范、迁移指南和提案。

**生成前阅读：**
1. `references/design-system.md` — Plannotator 主题标记、排版、组件模式
2. `references/svg-patterns.md` — 架构图、流程图、数据流的内联 SVG 构建块

**文档结构（按顺序，选择适合的）：**

1. **标题栏** — 眉毛标签（等宽、大写）、标题（衬线、大号）、提示框（原始简报）
2. **摘要条** — 3-5 个统计卡片，快速显示关键数字（组件、端点、表格等）
3. **里程碑/时间线** — 垂直时间线显示阶段，不包含时间估计。阶段显示顺序和依赖关系，而不是持续时间。
4. **架构/数据流** — 内联 SVG 图表。用于 3 个以上交互组件。突出显示的框用于新组件，虚线箭头用于异步路径。
5. **模型** — 直接使用 HTML/CSS 构建 UI 模型，而不是描述
6. **关键代码** — 深色主题代码块，带语法高亮。仅包含架构上重要的接口/模式 — 不是每个函数。
7. **风险与缓解措施** — 带严重性徽章（HIGH/MED/LOW）的表格
8. **开放问题** — 带决策所有者的标注卡片（"与：后端团队共同决定"）

并非每个计划都需要每个部分。跳过不适用于内容的部分。永远不包含时间估计、样板部分或详尽的文件列表。

**适应任务：** 后端 → 以数据流开头。前端 → 以模型开头。重构 → 以前后对比图开头。基础设施 → 以架构图开头。

**质量标准：** 计划在阅读 30 秒内回答“是什么、为什么和如何”。空白是特性 — 每个视口一个想法。

## PR 路径

适用于 PR 演练、差异审查、代码变更解释和审阅者指南。

**生成前阅读：**
1. `references/design-system.md` — Plannotator 主题标记、排版、组件模式
2. `references/pr-components.md` — 差异渲染、审阅者评论气泡、风险芯片、文件卡片、前后面板

**文档结构（按顺序，选择适合的）：**

1. **标题栏** — PR 标题、元条（文件数、+/- 行数、分支、作者）
2. **TL;DR** — 带主要强调色左边的边框卡片。2-3 句话。看到其他内容的读者应该理解要点。
3. **原因** — 动机和前后对比（两列网格）
4. **文件巡游** — 每个文件一个可折叠卡片。每个卡片包含：文件路径 + 徽章（NEW/MOD/DEL）+ 行统计、一个“原因”段落和重要的差异块。高风险文件展开，安全文件折叠。
5. **风险地图** — 显示哪些文件需要仔细审查，哪些是机械的。三个级别：注意（破坏性）、中等（警告）、安全（成功）。
6. **重点区域** — 编号标注卡片。每个卡片命名一个文件/函数并描述问题。
7. **测试计划** — 复选框样式验证清单
8. **发布**（如果适用） — 带功能标志的阶段发布

使用 Pierre diffs 通过 CDN 提供语法高亮的内联差异 — 参见 `references/pr-components.md` 中的模式。

## 可视化解释器路径

适用于架构图、数据表、幻灯片演示文稿、项目总结、比较和任何其他可视化解释。

**生成前：**

1. 确保 `visual-explainer` 已安装：
   - 检查：`~/.claude/skills/visual-explainer/SKILL.md` 或 `~/.agents/skills/visual-explainer/SKILL.md`
   - 如果未找到：`npx skills add nicobailon/visual-explainer -g --yes`
2. 阅读可视化解释器的 `SKILL.md`（工作流程、图表类型、反冗余规则）
3. 阅读与您的内容类型相关的可视化解释器参考和模板
4. 阅读相关主题覆盖文档 `references/theme-override.md` — Plannotator 标记替换 Nico 的调板
5. 对于带控件和标题的可缩放 Mermaid 图表：阅读 `references/diagram-shell.md` 并复制其外壳 — 不要手动编写视口、画布或标题标记

遵循可视化解释器的结构、组件类（`.ve-card`, `.kpi-card`, `.pipeline`）和反冗余规则。覆盖是颜色/排印层 — Plannotator 标记而不是 Nico 的自定义调板 — 以及在 `references/diagram-shell.md` 中的可缩放图表外壳，当可交付内容包含时。

## 设计理念（所有路径）

- **空白是特性。** 丰富的填充、大段间距。如果拥挤，请添加空间 — 不要缩小文本。
- **每个视口一个想法。** 英雄区域，然后图表，然后详细网格 — 不要全部挤在一起。
- **展示而非描述。** 时间线展示顺序。图表展示关系。代码块展示接口。
- **无时间估计。** 时间线显示阶段和依赖关系。永远不附加小时/天估计。
