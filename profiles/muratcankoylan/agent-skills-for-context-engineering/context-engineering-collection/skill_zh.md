# 上下文工程中的代理技能

本集合提供了通过有效的上下文工程构建生产级 AI 代理系统的结构化指导。

## 激活时机

在以下情况下激活这些技能：
- 从零开始构建新的代理系统
- 优化现有代理性能
- 调试上下文相关的故障
- 设计多代理架构
- 创建或评估代理工具
- 实现内存和持久化层
- 设计自主研究或评估框架

## 技能图谱

### 基础上下文工程

**理解上下文基础**
上下文不仅仅是提示文本——它是语言模型在推理时可用的完整状态，包括系统指令、工具定义、检索到的文档、消息历史记录和工具输出。有效的上下文工程意味着理解对当前任务真正重要的信息，并为此信息进行策展以实现最大的信噪比。

**识别上下文退化**
随着上下文的增长，语言模型表现出可预测的退化模式：信息在上下文中间丢失的现象，即上下文中间的信息获得较少关注；U 形注意力曲线优先考虑开头和结尾；当错误累积时发生上下文中毒；当无关信息淹没相关内容时发生上下文干扰。

### 架构模式

**多代理协调**
生产级多代理系统趋同于三种主导模式：具有集中控制的监督者/协调器架构，用于灵活交接的对等点对点群架构，以及用于复杂任务分解的层次结构。关键洞察在于，子代理主要存在是为了隔离上下文，而不是模拟组织角色。

**长时程提示**
长时间运行的自主代理和并行协调的成功或失败取决于启动提示。伪正式的任务简报指定成功谓词、非计数结果、具有审计门控返回条件的持久化规则、努力底线、并行投资组合的多样性策略以及污染防护，将形式化验证的纪律语言应用于没有机器可检查成功条件的问题。

**内存系统设计**
内存架构范围从简单的草稿板到复杂的时序知识图谱。向量 RAG 提供语义检索但丢失关系信息。知识图谱保留结构但需要更多的工程投入。文件系统作为内存的模式允许即时上下文加载，而不会填满上下文窗口。

**基于文件系统的上下文**
文件系统为存储、检索和更新几乎无限的上下文提供了一个单一接口。关键模式包括用于工具输出卸载的草稿板、用于长时程任务的计划持久化、通过共享文件进行的子代理通信以及动态技能加载。代理使用 `ls`、`glob`、`grep` 和 `read_file` 进行有针对性的上下文发现，对于结构化查询，通常优于语义搜索。

**托管代理基础设施**
后台编码代理在远程沙盒环境中运行，而不是在本地机器上。关键模式包括定期刷新的预构建环境镜像、用于即时会话启动的温热沙盒池、用于会话持久化的文件系统快照以及支持协作代理会话的多玩家支持。关键优化包括允许在 git 同步完成之前读取文件（仅阻止写入）、在用户开始输入时预测性沙盒预热，以及用于并行任务执行的自发代理。

**工具设计原则**
工具是在确定性系统和非确定性代理之间的契约。有效的工具设计遵循合并原则（优先选择单一的综合工具而不是多个狭窄的工具）、在错误中返回上下文信息、支持用于令牌效率的响应格式选项，以及使用清晰的命名空间。

### 运营卓越

**上下文压缩**
当代理会话耗尽内存时，压缩变得强制。正确的优化目标是每任务的令牌，而不是每请求的令牌。结构化摘要（为文件、决策和下一步操作指定明确部分）比激进压缩保留更多信息。跨所有压缩方法，工件轨迹完整性是最薄弱的维度。

**上下文优化**
技术包括压缩（在限制附近总结上下文）、观察掩码（用引用替换冗长的工具输出）、前缀缓存（跨请求重用 KV 块）和策略性上下文分区（将工作分配给具有隔离上下文的子代理）。

**潜势简报（KV 内存共享）**
协调器-工作器系统在监督者积累长轨迹但工作器只看到窄文本切片时可能会累积令牌。潜势简报使用任务引导注意力（Attention Matching 风格的压缩）在工作器模型的 KV 缓存中压缩协调器轨迹，以便在工作器在不进行全文重播的情况下接收相关潜势状态，当堆栈暴露工作器 KV 状态并且模型兼容时。

**评估框架**
生产级代理评估需要确定性检查和多维度的评分标准，涵盖事实准确性、完整性、工具效率和流程质量。仅在结构、证据和评分标准数学有效后使用模型法官；将法官设计、成对比较和偏差缓解路由到高级评估。

**框架工程**
可靠的自主代理需要围绕模型设置显式的操作循环：锁定指标、可编辑表面、持久化日志、新颖性检查、回滚规则和人工批准边界。框架防止代理削弱评估者、在压缩过程中丢失状态或将模糊目标转变为不可审查的更改。

**自我改进循环**
当框架本身成为优化目标时，应用不同的纪律：递归自我改进、元框架搜索、故障驱动的有界自我编辑、进化脚手架搜索和上下文机制进化。控制约束是经验双分割接受门、原始跟踪的文件系统经验存档、每个可编辑表面之外强制执行的运行时约束，以及多样性保留以防止崩溃。

### 开发方法论

**项目开发**
有效的 LLM 项目开发从任务-模型拟合分析开始：通过手动原型验证任务是否适合 LLM 处理，然后再构建自动化。生产管道遵循分阶段、幂等的架构（获取、准备、处理、解析、渲染），并使用文件系统状态管理进行调试和缓存。结构化输出设计具有明确的格式规范，可进行可靠解析。从最小的架构开始，只有在证明有必要时才添加复杂性。

### 认知架构

**BDI 心理状态**
信念-欲望-意图建模提供了一种将结构化外部上下文转换为代理心理状态的形式化方法。用于理性代理、可解释性和需要审计信念、目标和所选动作之间链接的系统。

## 核心概念

本集合围绕四个核心主题组织。首先，上下文基础确立了上下文是什么、注意力机制如何工作以及为什么上下文质量比数量更重要。其次，架构模式涵盖了使能有效代理系统的结构和协调机制。第三，运营卓越涉及优化、评估和框架可靠性。第四，开发方法论和认知架构涵盖了项目执行和形式化心理状态建模。

## 实用指南

每个技能都可以独立使用或组合使用。从基础知识开始建立上下文管理心理模型。根据您的系统需求分支到架构模式。在优化生产系统时参考运营技能。

这些技能是平台无关的，适用于 Claude Code、Cursor 或任何支持自定义指令或技能类结构的代理框架。

## 集成

本集合与其自身集成——技能相互引用并建立在共享概念之上。基础知识技能为所有其他技能提供上下文。架构技能（多代理、内存、工具）可以组合用于复杂系统。运营技能（优化、评估）适用于使用基础和架构技能构建的任何系统。
