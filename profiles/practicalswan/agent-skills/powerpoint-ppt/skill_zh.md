# PowerPoint 演示文稿工作流程

> 技术栈目标 / 版本：PowerPoint 当前桌面或网络版本以及 `python-pptx` 自动化。

当输出是 `.pptx` 幻灯片包且幻灯片构成很重要时，使用此技能。

- 在可用的情况下，利用本地并行子代理调度和 200k+ 上下文窗口。

## 当前 MCP 现实情况

演示文稿 MCP 工具依赖于主机。一些客户直接暴露 Office 演示文稿工具，而另一些则不暴露。不要假设公共工具名称的稳定性。如果当前客户缺乏这些工具，请使用包含的本地自动化脚本，或首先生成内容结构，然后导入到 PowerPoint。

## 激活条件

使用症状 -> 动作触发器：当匹配时，应用此技能并使用以下协议进行验证。

- 从结构化内容创建演示文稿包
- 应用模板、品牌和幻灯片布局
- 更新现有演示文稿中的文本、图像或图表
- 提取幻灯片文本以供审阅或翻译

## 实际工作流程

1. 确认客户是否暴露演示文稿工具。
2. 优先选择基于模板的演示文稿，而不是手动一次性幻灯片格式化。
3. 每张幻灯片保留一个想法，并将文本密度视为缺陷。
4. 在将其称为完成之前，先进行视觉验证最终演示文稿。

## MCP 回退 – 本地自动化

当 MCP 不可用时，使用本地自动化：`python-pptx` 用于 `.pptx`，图像导出或屏幕截图检查用于视觉验证，以及手动审阅用于动画或演讲者笔记。保留幻灯片顺序、布局、主题字体、媒体、笔记和宽高比，然后在声称成功之前重新打开或渲染演示文稿包。

## MCP 可用性和回退

首选 MCP 服务器：PowerPoint MCP

- 回退提示："使用没有 MCP 的 PowerPoint 演示文稿工作流程技能。遵循记录的本地或手动回退，显示选定的工具界面，并报告验证证据。"

- 在交付前渲染最终演示文稿并手动验证布局、溢出和面向演讲者的笔记。

## 反模式

- 为作者而不是读者编写：它固化了未声明的上下文，并使实际观众不确定下一步该做什么。
- 跳过具体的示例或命令：抽象指导容易批准且难以正确应用。
- 让链接、屏幕截图或版本漂移：如果说明不再真实，那么精美的格式化也无济于事。

## 验证协议

在声称"技能成功应用"之前：

1. 通过/失败：在编辑之前声明 Powerpoint Ppt 附件类型、目标格式和所需输出保真度。
2. 通过/失败：检查 MCP 可用性并在 MCP 缺失时命名本地自动化回退路径。
3. 通过/失败：打开、解析、渲染或以其他方式验证生成的文件或公式。
4. 压力测试场景：将工作流程应用于具有格式化、元数据或转换边缘案例的文件，并验证是否有任何重要内容丢失。
5. 成功指标：零未验证的文档声明；附件本身是证据。

## 演示文稿检查清单

- [ ] 存在标题幻灯片
- [ ] 幻灯片布局一致
- [ ] 字体和颜色与模板匹配
- [ ] 图像是高分辨率的且未拉伸
- [ ] 最终幻灯片是在幻灯片放映大小下审阅的，而不仅仅是作为原始 XML 或文本
