# 自然风格学术润色——路由器

## 路由协议

对于新的润色任务，请遵循以下路由流程。对于后续编辑，请重用已建立的任务选择和已加载的指导；仅当请求范围发生变化时，才读取额外片段。

### 1. 加载清单和核心层

读取 [manifest.yaml](manifest.yaml)。它声明了轴（`paper_type`、`section`、`language`、`journal`）、允许的值以及每个值映射到的文件路径。

同时读取 `always_load` 下列出的每个文件。这些文件包含适用于每个润色工作的默认立场、故障模式诊断、伦理和输出格式。

### 2. 检测此请求的轴值

对于清单中的每个轴，使用清单的 `detect:` 提示和用户输入决定值：

- `paper_type` — 研究 / 方法 / 假设 / 算法 / 综述。默认：研究。
- `section` — 摘要 / 引言 / 结果 / 讨论 / 结论 / 标题 / 方法。可能多个。如果存在歧义且对润色有影响，请询问用户。
- `language` — 英文或中译英。从草稿本身检测。
- `journal` — 自然 / 自然通讯 / 自然机器智能 / 通用。默认：通用。仅对旗舰自然使用 `nature`，对自然通讯使用 `nat-comms`，对自然机器智能（NMI）使用 `nat-mach-intell`。不要通过旗舰自然规则路由其他自然组合版标题。

在继续之前，向用户简短声明检测到的轴值，以便他们可以廉价地纠正。这是一个进度更新，不是批准关卡；除非必要决策仍存在未解决的问题，否则继续。

### 3. 加载匹配的片段

对于每个轴值，读取清单中映射的文件。仅当用户提供了无章节上下文的自由浮动散文时，才跳过 `section` 轴。

不要读取 `static/` 中的每个片段。仅加载步骤 2 选择的内容。

### 4. 使用加载的材料进行润色

按以下优先级顺序应用加载的片段，匹配 `paper type -> section job -> paragraph logic -> claim/evidence/boundary -> sentence polish` 规则（来自 `core/failure-modes.md`）：

1. 论文类型剧本（架构、写作顺序）。
2. 部分特定的任务和故障模式。
3. 期刊特定的框架和约束。
4. 语言特定的句子和段落规则（最后应用）。
5. 核心立场和伦理贯穿始终。

如果一个段落的结构问题无法在不创造内容的情况下修复，请标记它而不是掩盖它。

对于结果、全文压缩、主文与 SI 分配或修订期间添加的散文，在句子润色之前加载 `../nature-shared/core/main-text-discipline.md`。对每个结果进行分类，保留最短的充分证据链，并要求每个添加项触发受影响段落的删除或替换检查。

对于旗舰自然、自然通讯、自然机器智能或另一个自然组合版标题，加载匹配的共享自然风格语料库指导：

- 结果或讨论 → `../nature-shared/core/nature-results-discussion.md`
- 引言或整篇手稿叙事 → `../nature-shared/core/nature-introduction.md`
- 摘要 → `../nature-shared/core/nature-abstract.md`

保留主张升级、快速问题漏斗、引言-结果对齐、以发现为中心的摘要压缩、证据约束的本地解释和跨结果综合。这些默认值最初是从已发表的 NMI 论文精炼出来的；将它们视为语料库指导，而不是官方政策，当它们不同时，应遵守目标期刊的当前规则。

对于任何讨论润色或重构工作，还加载 `../nature-shared/core/discussion-argument-language.md`。使用其功能标签来移除结果重播，修复从具体发现到限定含义的移动，校准与证据强度匹配的模态和报告动词，并使局限性和未来工作解决命名主张边界。将其视为通用写作指导，而不是期刊政策。

### 5. 仅在需要时才查找参考文献

`references/` 下的文件是深度参考文献，不是默认值。根据清单中的 `references.on_demand` 表格按需打开它们，例如当用户明确要求短语库风格的替代方案或更严格的风格审计时。

当目标是自然机器智能且精确限制、可用性部分、会议扩展披露或生产检查影响修订时，加载 `../nature-shared/journal-formats/nature-machine-intelligence.md`。

对于整篇手稿一致性审计或段落间漂移的证据，加载 `../nature-shared/core/consistency-sweep.md`。本地后续编辑需要检查受影响的术语、数字和主张，而不是仅因为这是另一个编辑轮而重新启动完整审计。更正后，重新检查受影响的实例和依赖主张；当新差异需要时扩展扫描范围。

**排版（排版）请求不同。** 如果用户要求修复*位置*而不是措辞——松散/稀疏页面、无上下文的标题、不填满页面或跨页分割的图形、"浮体过大"、多面板排列、稀疏补充信息——请跳过散文轴（paper_type、section、language、journal），直接加载 `references/latex-layout.md`。该文件是自包含的：它包含诊断工作流（渲染 → 联系表 → 读取日志）、浮体胶水和 `[H]`/`\clearpage`/`placeins` 模式，以及"在源处重新生成宽图形使其更高"的规则。始终在前后编译和视觉检查渲染页面——永远不要仅从 `.tex` 判断排版。
