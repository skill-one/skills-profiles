# Appllama 应用设计技能

你正在构建将在手机上与世界上设计最佳的应用并排显示的界面。用户将在启动后几秒钟内将你的输出与那些应用进行比较。这项技能定义了设定标准和方法来超越这个标准。

## 主要指令：在绘制前先研究

当你可以研究顶级应用如何解决相同界面时，永远不要凭空想象来设计界面。真实、已上线、按收入排名的应用编码了数千小时的设计迭代和 A/B 测试。你对任何界面的第一个动作都是研究：

1. 如果 **Appllama MCP** 已连接，请拉取你要构建的分类和界面类型的真实界面（有关精确研究剧本，请参阅 `appllama-usage` 技能）。在编写一行 UI 代码之前，研究 20-30 个界面。
2. 提取 **模式，而不是像素**：布局骨架、信息层次结构、控制选择、间距韵律、主要 CTA 的位置、什么情况下使用插图而不是纯文本、如何传达进度。注意：每个 Appllama 图像和视频在左上角都带有一个小型 Appllama 水印。它是来源，而不是设计——在阅读界面时忽略它（它可能覆盖状态栏或返回按钮），并且永远不要在你的构建中复制它。
3. 然后设计 **你自己的** 界面：相同的经过验证的骨架，你产品的声音。一对一复制竞争对手的界面既懒惰又存在法律风险；发布一个忽略用户已经知道的每个惯例的界面会更糟。

## 平台基准

默认堆栈假设（如果项目尚未不同，则仅覆盖）：

- **Expo + Expo Router**、React Native、TypeScript。
- `react-native-reanimated` 用于动画，`react-native-gesture-handler` 用于手势，`@shopify/flash-list`（或 FlashList v2）用于任何可以增长的列表。
- `expo-image` 用于图像（以及通过 `source="sf:name"` 在 iOS 上使用 SF Symbols），`expo-video` / `expo-audio`（永远不要使用已弃用的 `expo-av`）。
- `react-native-safe-area-context` 用于内边距。永远不要硬编码凹口数字。
- `process.env.EXPO_OS` 覆盖 `Platform.OS` 用于编译时平台检查。

## 本地保真度法则

这些是区分“包装中的网页”和“原生应用”的细节。违反其中任何一项都是一个发现，而不是风格偏好。

1. **语义颜色，两个主题，第一天使用**。使用系统/语义颜色标记（例如 iOS 上 `expo-router` 的 `Color`：`Color.ios.label`、`Color.ios.secondarySystemBackground`；Android 上的 Material 动态颜色）。每个界面都必须在浅色和深色模式下正确渲染才能完成。
2. **原生控件优于重建的控件**。开关、滑块、分段控件、上下文菜单、日期选择器：使用原生控件或忠实的包装器。重建的切换器与 iOS 的动画时间不同 50 毫秒，会立刻显得不真实。
3. **使用 SF Symbols / Material Symbols 进行图标设计**。在 iOS 上优先使用 SF Symbols（`expo-image` 带有 `sf:` 源，或 `expo-symbols`）；它们继承权重、光学大小和 Dynamic Type 行为。不要在一个界面上混合三种图标家族。
4. **排版是层次结构**。使用平台类型阶梯（iOS 上的“大标题/标题/标题/正文/脚注”）。每个界面只有一个显示大小。用于计数的任何内容、时间或价格使用表格式数字（`fontVariant: ['tabular-nums']`）。`Text selectable` 用于用户可能想要复制的用户数据。
5. **连续圆角**。每个圆角矩形上使用 `borderCurve: 'continuous'`。圆角矩形是存在的最便宜的感觉 iOS 的胜利。
6. **通过 CSS `boxShadow` 而不是遗留的 `shadow*`/`elevation` 属性实现阴影**。阴影用于提升逻辑，而不是装饰——每个应用只有一个提升系统。
7. **间距韵律**。选择一个基本单位（4 或 8），并且永远不要离开它。优先使用 flexbox `gap` 覆盖边距堆叠。ScrollView 的内边距放在 `contentContainerStyle` 中，永远不要放在 ScrollView 本身。
8. **安全区域和 Dynamic Island 是设计的一部分**。必须使用被岛屿/状态栏下滚动的内容验证界面（模糊/淡入淡出处理是否保持？）、主指示器（底部 CTA 是否清除它？）以及在支持的情况下使用横屏。
9. **导航标题属于导航器**。尽可能使用堆栈的原生标题（iOS 上的大标题折叠行为）而不是手工制作的标题。
10. **触觉反馈是标点符号**。当值通过一个步骤时选择确认，当某个东西回到原位时轻击，对于结果使用通知成功/错误——在相同的帧上，每个用户动作一个，永远不会是唯一的反馈。永远不要在滚动时，永远不要在循环中。
11. **像产品一样格式化数字，而不是数据库**：1.4M、38k、$4.99。修剪尾随零。本地化日期。
12. **根滚动行为**：可以溢出的界面在路由中的第一个组件中用 `ScrollView` 包裹（`contentInsetAdjustmentBehavior="automatic"`）。使用 `useWindowDimensions`，永远不要使用 `Dimensions.get()`。

## 导航法则

导航是屏幕中截图无法显示的部分，用户在十秒钟内就能感受到它。每个过渡回答三个问题：目的地是什么，用户是否必须能够返回，以及返回后（箭头、iOS 边缘滑动、Android 硬件返回）会发生什么。

1. **推送更深，替换移动**。当用户想要返回这里时使用 `router.push`；当返回会进入世界已经过去的状态时使用 `router.replace` / `<Redirect>`；`router.dismissTo(href)` 用于“完成此流程并跳转到 X”。返回撤销 *导航*，而不是 *事件*。
2. **呈现具有意义**。一个自包含的任务有步骤 → `presentation: 'modal'` 带有它自己的堆栈和它自己的取消/完成；短时中断（选择器、过滤器、项目选项）→ `formSheet` 带有凹口、可拖动关闭；沉浸式内容 → `fullScreenModal` 带有明确的关闭；悬浮在仍然可见的屏幕上的内容（确认卡、灯箱、教练标记）→ `transparentModal` 覆盖；破坏性确认 → 动作表；项目操作 → 原生上下文菜单；分享/网络/照片选择 → 系统控制器，永远不要重建路由。一个增长第二步的表单是模态；如果链接可以打开它，它是一个路由，而不是 `useState` 表单。
3. **单门门离开堆栈**。在墙上应用上的登录、完成入职（包括跳过）、购买、完成的会话：使用 `Stack.Protected` 进行保护，并使用 `replace` 落地，以便返回永远无法重新进入旧状态——Android 从主屏幕返回退出应用，而不是显示登录；付费付费墙永远不会重新打开。但保留用户的 *位置*：由一个动作（保存、关注、购买）要求的登录是一个模态，覆盖在完成动作被点击的屏幕上，并且付费墙从功能关闭后返回到功能，解锁——永远不要从那里使用 `replace('/(tabs)')`。
4. **返回在两种情况下被阻塞**——正在进行的不可逆转的请求（几秒钟，有可见进度）和模态中的未保存工作（先询问），两者都通过模态的根屏幕上的 `usePreventRemove`。屏幕内的瞬时状态（选择模式、展开的搜索、打开的屏幕内表单）消耗第一个返回，然后返回离开。任何其他困住返回的东西——漏斗、评分提示——都是缺陷；边缘滑动在别处都有效。
5. **标签是平等的**。标签之间没有滑动，每个标签保留它自己的堆栈，重新点击活动标签会弹出到它的根；全注意力屏幕（作曲家、播放器、结账）位于标签根堆栈 *之上*。深度链接在下面带有真实的堆栈着陆（`initialRouteName` / `withAnchor`）；冷启动通过状态着陆， splash 持续到会话状态解析完成——永远不要在 Home 之前显示登录。
6. **研究语法，而不仅仅是像素**。在 Appllama 上走一个成功的流程，注意每个步骤 *是什么*——推送、模态、表单——并复制这种一致性。

## 反滑法则

AI 构建的应用共享外观，用户在几秒钟内就会将其归为“模板”。这些是 *默认禁止*——当品牌明确要求这样做并且你可以说明它为何适合这个产品时，总是有一个覆盖。

1. **没有 AI 默认样式**。紫色/靛蓝色渐变 CTA 带有发光、每张卡片上的玻璃形态、网格渐变英雄、小事件中的五彩纸屑、标题中的闪光——那是模型的风格，不是设计。你的调色板、材料和布局来自你研究的参考界面，而不是你未经提示就会选择的先验。
2. **一个强调色，锁定**。选择一个强调色，它是每个屏幕上的 *唯一* 强调色——一个屏幕上的蓝色 CTA 和下一个屏幕的青色，屏幕七中不会出现新的色调。中性色承载应用；强调色用于最赚钱的地方（主要操作、活动状态、进度）。
3. **一个灰色系列**。暖灰色或冷灰色——一个应用中永远不会两者兼有。
4. **形状锁定**。一个圆角半径规模，声明为一条规则（“操作是药丸，卡片 16，输入 8”），并且永远不要违反。没有声明规则的混合半径读作拼凑起来的。
5. **不要使用表情符号作为图标**。图标是 SF Symbols / Material Symbols（保真度法则 3）。表情符号仅在产品的声音真正适合聊天或俏皮时出现——有节制地，在内容中，永远不要在装饰中。
6. **每个意图一个标签**。“开始使用”、“立即开始”和“开始”是相同的意图——选择一种措辞并在它出现的地方使用它。
7. **强调保持在家族中**。用相同字体的重量或斜体强调一个词；将衬线字词注入无衬线标题（反之亦然）以获得视觉兴趣是业余的。
8. **发布完整状态周期，而不是快乐路径**。只有静态成功状态的默认失败模式：骨架必须匹配最终布局的形状，空状态是组合的（并说明如何填充它们），错误是内联和具体的。
9. **滑翔预飞行是机械的**。在任何流程到达模拟器之前，计算：不同的强调色调（必须是 1），不同的圆角半径（都来自声明的规模），UI 装饰中的表情符号（0），没有品牌原因的渐变（0），一个意图的重复标签（0）。失败的计数是修复，而不是判断。

## 动画法则

动画是最高杠杆的抛光表面，也是最容易过度使用的。按以下顺序决定：

- **频率门首先**。每天 100 次以上（标签切换、键盘、滚动、返回）→ 平台默认值和什么都不是；每天几十次（按下、行选择）→ 几乎无法察觉，小于 150 毫秒；偶尔（表单、模态、toast）→ 标准动画；仅在罕见、第一次的时刻才带来惊喜。标签从不滑动；屏幕过渡保持原生。
  通过这个门，用零行代码通过是成功——当不确定时，最强的动作是删除动画。
- **用一个词命名目的**——反馈、空间连续性、状态变化、防止刺耳的切割、解释、惊喜——或者不构建它。用户正在阅读的数据永远不会因为风格而移动。
- **如果手指参与，它是弹簧**。从实时值开始（在抓取时捕获），将释放速度交给弹簧，从预测的动量中选择目标，以便一个挥手就能提交，过边界时像橡皮筋一样，在飞行中保持可抓取。每个应用使用同一词汇——`{ duration: 400, dampingRatio: 1 }` 来稳定，`{ 300, 0.8 }` 用于表单——并且只有在手势携带动量时才弹回。
- **其他一切都是时间，小于 300 毫秒，强缓出** (`Easing.bezier(0.23, 1, 0.32, 1)` —— 内置曲线太弱；永远不要在进入时缓入）。按下反馈落在按下-*中*，100–150 毫秒：按钮和卡片上缩放 0.97，列表行上的背景高亮（永远不要缩放），条形按钮上的不透明度。退出比进入更快，并以它们来的方式离开；从 `scale(0.95)` + 淡入，永远不要 `scale(0)`；菜单从它们的触发器增长（中心模态除外）。
- **手势→动画永远不会跳过 JS 线程**。工作线程 + 共享值（`.get()`/.`.set()`；`scheduleOnRN` — Reanimated 4 的 `runOnJS` — 仅在手势结束时），`transform`/`opacity` 仅，回收列表行上没有 `entering`，永远不要动画化标题的高度（在固定剪辑内内部平移），通过 `react-native-keyboard-controller` 的键盘跟踪 UI — 永远不要键盘监听器加上猜测的持续时间。
- **尊重 Reduce Motion**：你的空间动画折叠为交叉淡入淡出；原生过渡保持系统的。
- 标准线：60 fps 通过英雄流程，在支持的最慢设备上的发布构建上测量——Expo Go 和开发构建隐藏了你正在寻找的卡顿
  ([references/performance.md](references/performance.md))。一次观看录制以获得感觉，一次逐帧观看，再次以新鲜的眼光第二天观看。

## 状态架构

感觉很好的屏幕是状态无聊的屏幕：

- **服务器状态**在 TanStack Query（或项目的等效方案）：缓存、重试、乐观更新。永远不要 `useEffect`+`fetch`。
- **客户端状态**在一个小的原子存储（Zustand/Jotai）。广泛的“应用状态”上下文会导致导致 UI 感觉沉重的重新渲染级联。
- **瞬态 UI 状态**（打开/关闭、焦点、滚动）保持在组件本地。
- **默认乐观**：点击立即反映，在后台协调，失败时大声回滚。
- 未控制的 `TextInput` 用于高频输入表面；受控输入是导致输入卡顿的前三原因之一。
- 当延迟显示时，在 MMKV 中持久化微小的客户端状态，而不是 AsyncStorage。

## 感知性能

- 仅对于形状已知的 内容使用骨架；否则渐进式揭示。永远不要为部分更新使用全屏旋转器。
- 使用 FlashList 对于每个列表；提供稳定的键。
- 在按下时预加载下一个界面的数据，而不是在导航完成时。
- 图像：正确的源大小，`expo-image` 在列表中使用 `recyclingKey`，拇指哈希/模糊哈希占位符。
- 冷启动 TTI 和捆绑纪律生活在
  [references/performance.md](references/performance.md) — 应用测量 → 优化 → 重新测量循环，永远不要盲目的 memoization。

## 图像和插图资源

当屏幕需要插图、空状态艺术、英雄图像或符号集中的图标之外时：

- 使用你**可用的最佳图像模型**（例如图像生成工具或连接的 Higgsfield MCP/CLI）以**最高质量设置**生成资源，然后缩小到 @1x/@2x/@3x。永远不要放大。
- 每个应用一个视觉语言：选择一个风格（渐变网格、平面双色调、3D-粘土、手绘、吉祥物风格）并在该风格中生成所有资源，相同的调色板，相同的光照。混合风格的资源集读作模板滑翔。
- 提供透明或实心平面背景，与你的表面颜色匹配；复合伪影（白色光晕、错误颜色的磨砂）是自动重做。
- 完整资源管道和提示模式：
  [references/image-assets.md](references/image-assets.md)。

## 模拟器循环（不可协商）

直到你看到它在运行，屏幕才存在。循环：

1. 实现 → 在 iOS 模拟器（或 Android 模拟器）中启动。
2. 截图并**实际查看**：对齐、光学中心、间距韵律、长内容截断、深色模式、Dynamic Type at XL。
3. 运行**完整动画通过**——截图证明布局；它们证明不了关于动画的任何东西。
4. 修复，重新启动，重新验证。重复直到你找不到缺陷——然后运行
   [references/simulator-loop.md](references/simulator-loop.md) 中的检查清单一次更多。

不要仅从代码审查中宣布屏幕完成。不要停在“看起来不错”——停在“在 100% 放大下找不到缺陷”。

### 完整动画通过（强制，每个流程）

每个流程都作为**模拟器中的动态图像**而不是**静态**进行评估。端到端录制整个流程 (`xcrun simctl io booted recordVideo flow.mov`)，执行所有内容：

- 每个屏幕过渡、推送/弹出、标签切换
- 每个返回路径——箭头、边缘滑动、Android 硬件返回——以及，在每次单门门（登录、入职完成、购买、完成会话）之后，尝试返回必须失败以重新进入旧状态
- 每个模态和表单：呈现、拖动、关闭——并在拖动中途取消
- 键盘，两个方向：出现（布局是否滑入，焦点输入是否可见？）和消失（是否有任何东西跳跃切割？）
- 每个用户交互：按下状态、手势跟随、中断的手势、快速点击、极端滚动

观看录制**两次**：一次全速以获得感觉，一次慢速逐帧。你正在寻找：

- 滑落或卡顿的帧——标准线是**持续 60 fps** 通过每个过渡，测量，而不是感觉
- 一帧闪光：白色/未样式化的第一帧绘制、过渡期间错误主题的帧、表面短暂渲染错误标记的位置
- 布局跳跃、双渲染弹出、弹簧卡住或超出内容、元素在出现后重新流
整个录制必须像一件原生作品一样播放——从头到尾平滑，零 UX 故障。一个有故障的帧意味着流程未完成。

## 每个屏幕的完成定义

- [ ] 研究 10+ 个真实参考屏幕（通过可用 Appllama MCP）并为这种屏幕类型命名你采用的模式
- [ ] 导航回答：这个屏幕*是什么*（推送/模态/表单/覆盖/替换），从它返回的 iOS 和 Android 上的返回是什么，以及——在单门门之后——返回无法重新进入旧状态
- [ ] 模拟器中验证亮色和深色模式
- [ ] 验证安全区域 / Dynamic Island / 主指示器
- [ ] 设计长内容、空、加载和错误状态——而不是默认值
- [ ] 动画：完整流程屏幕录制并慢速播放——进入、按下、过渡、模态、键盘——原生感觉，零故障或错误颜色帧；尊重 Reduce Motion；在支持的最慢设备上的发布构建上测量 60 fps
- [ ] Dynamic Type XL 不破坏布局；文本在有用处可选中
- [ ] 所有点击目标 ≥ 44pt；两个主题中的对比度都通过
- [ ] 资源：单一风格家族，@3x 时清晰，没有合成光晕
- [ ] 列表表面虚拟化；没有受控输入卡顿；没有重新渲染风暴（分析，而不是猜测）
