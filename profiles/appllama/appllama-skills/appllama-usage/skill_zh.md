# Appllama 使用技巧

Appllama 是顶级畅销移动应用的设计库——它们的真实屏幕、流程和 UI 模式，以及收入和下载背景。MCP 将这个库交到代理手中：**它不仅是研究工具，更是构建工具。** 你先研究已经成功的案例，然后构建更好的产品。

将此技能与 **appllama-app-design-skill** 配合使用，用于每个设计/实现步骤——这个技能告诉你该研究什么；那个技能告诉你如何构建。

## 基本规则（先阅读）

1. **从 `get_credits` 开始——它是免费的。** 它告诉你余额、限制和重置日期。专业版每月包含 1,500 个信用点（它们在 UTC 时间每月 1 日全额重置）；其他每次调用消耗 1 个信用点。
2. **深入研究。** 设计语言贯穿整个旅程，而不仅仅是一个样本——走遍对任务重要的应用的每个屏幕，包括图片。这就是库的用途。违反条款的唯一事情是收割：扫描目录以提取数据集本身，而不是为了完成一项实际任务。这不是研究，并且会在服务器端被检测到。
3. **媒体 URL 大约在 1 小时后过期。** 及时下载/查看你研究的对象。如果任务中途链接失效，重新请求该页面以获取新鲜链接——屏幕 ID 是持久的，链接不是。
4. **忽略水印。** 每个 Appllama 图片和视频在左上角都带有一个小型 Appllama 水印。它是来源，不是屏幕的一部分——不要让它影响你对该角落（状态栏、返回按钮、标题）的阅读，并且永远不要在你构建的内容中复制它。
5. **分页是顺序的。** 每个列表响应都包含 `next_cursor`；将其返回以继续。你不能跳转到第 N 页——并且光标只对生成它的相同查询有效。如果光标出错，放弃它并从第一页重新开始。
6. **如果你遇到速率限制，请耐心等待。** 每分钟和每天的限额远高于实际研究需求；在罕见的情况下遇到限制，请等待规定的时间——不要重试攻击。
7. **错误是指示。** 工具错误被编写为需要采取行动（过期光标 → 重新开始；信用点用完 → 告知用户他们的信用点在每月 1 日重置，并且他们可以在设置 → 使用中请求更多）。

## 工具地图

| 工具 | 它能为你提供什么 | 典型用途 |
|---|---|---|
| `get_credits` | 余额、限制、重置日期。**免费。** | 会话开始 |
| `search_apps` | 每页 10 个应用：名称、收入、下载量、评分、发布日期、屏幕数量、**带有屏幕数量的流程列表**。自然语言 `query` + 过滤器（收入/下载量/评分/发布日期/价格/引导步骤）+ `sort` + `board_id` | 查找适合某个类别或需求的顶级应用 |
| `get_app` | 一个完整的应用：评分细分、类别排名、IAP 定价、顶级国家、流程 | 判断一个应用是否值得深入研究 |
| `list_app_screens` | 每页 10 个屏幕**按流程顺序**（欢迎 → 引导 → 付费墙 → 产品），每个屏幕带有媒体 URL、流程、UI 元素、颜色。按 `flow` 或 `section` 过滤 | 按屏幕逐个浏览应用 |
| `search_screens` | 库中所有屏幕。`mode="keyword"` 匹配屏幕名称 + 过滤器（流程、屏幕类型、元素、app_id）；`mode="semantic"` 通过含义/视觉语言搜索 | 为一个屏幕类型收集设计参考 |
| `get_screen` | 一个完整屏幕 + 其他应用中最多 5 个视觉相似的屏幕。接受 `screen_ref` = `app_id/screen_id`（appllama.io 的“复制屏幕 ID”功能生成） | 用户粘贴了屏幕引用；或深入到一个参考 |
| `list_flows` | 流程分类法，包含屏幕/应用数量 | 发现某个类别中存在的流程 |
| `get_flow_apps` | 包含流程的应用，按收入排序 | 查找某个流程的最佳示例 |
| `list_ui_elements` | ~38 个 UI 元素家族，包含数量（一次调用） | 元素级研究的词汇 |
| `get_element_screens` | 包含元素家族的屏幕 | 研究获胜者如何构建一个组件 |
| `list_my_boards` | 成员自己的 appllama.io 板（屏幕/应用/流程） | 首先查找他们的筛选结果 |
| `get_board` | 板的完整内容：带有媒体的屏幕、应用资料，或（应用、流程）对 | 当成员为任务筛选了板时，从它开始 |

**屏幕引用握手：** 成员可以在 appllama.io 上的任何屏幕上点击“复制屏幕 ID”并将其粘贴给你。它看起来像 `1393061654/spl_9i075`——直接将其输入到 `get_screen(screen_ref=...)`，你将看到他们指的屏幕，以及库中与其最相似的屏幕。

## 本地参考板

当你拉取屏幕进行研究时，将它们保存到本地工作结构中——链接大约在 1 小时后过期，但你的笔记和下载不会：

```
research/
  <category>/
    apps.md            # 短名单：指标、流程、结论
    <app-name>/
      screens.md       # 每个屏幕的笔记：ID、名称、流程、元素、颜色
      img/             # 下载的屏幕，按流程顺序排列
    patterns.md        # 跨应用综合：类别的视觉语言
```

研究时下载屏幕——综合发生在图片并排时，而不是从元数据中。笔记和屏幕 ID 是持久的；如果你需要像素，请从 ID 重新获取新鲜链接。
