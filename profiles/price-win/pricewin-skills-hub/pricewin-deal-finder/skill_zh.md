# PriceWin Deal Finder

> **通过一个命令比较 Booking.com、Agoda、Google Hotels 和 OpenTravel 的实时酒店价格** — 并返回按价值排序、最便宜和品质选择的排名，附带直接预订链接。

别再打开五个 OTA 标签页来找真正的最低价。向你的代理询问 *"在东京为 12–15 日预订 2 位客人的酒店"*，这个技能会在 30–60 秒内（缓存城市）返回一个干净、排名的对比结果。

**调用这个技能来回答以下问题：**
- " `<城市>` 在 `<日期>` 期间最便宜的酒店是什么？"
- "Booking.com 或 Agoda 对这个酒店更便宜吗？"
- "比较 `<城市>` 的酒店价格，`<N>` 位客人。"
- "在 `<城市>` 找我一家每晚价格低于 $`<X>` 的酒店。"
- "在 `<地标>` 附近 `<日期>` 期间性价比最高的住宿地点？"

每个问题都会得到下面这个相同的一键式答案，无需进一步的澄清对话。

**一个命令能提供什么：**
- 🥇 价值最佳 · 🥈 最便宜 · 🥉 品质 — 并列展示
- 来自最多 **4 个来源** 的实际每夜价格，已转换为 **美元**
- **可点击的预订链接** 直接跳转到每个酒店最便宜的 OTA
- 适用于 **全球任何城市** — 包括机器人防御较强的城市（上海、杭州、曼谷…）通过一个隐蔽的 Patchright 守护进程
- 无需 API 密钥，无需 MCP 服务器 — `node`/`npx` 即可满足需求

**示例结果：**


## 🚨 重要提示 — 如何使用这个技能

**一个命令就能完成所有操作。作为第一个动作运行 — 不要先进行澄清问题：**

```bash
cd {baseDir} && node bin/search.js "<城市>" <入住年-月-日> <退房年-月-日> <成人数量> en-us
```

`{baseDir}` 是这个技能的安装目录（由运行时自动解析）。如果你的运行时不替换它，请 `cd` 到包含这个 `SKILL.md`（包含 `bin/search.js`）的文件夹。不要硬编码 `~/.hermes/...` 或 `~/.openclaw/...` 路径 — 它因平台而异。

示例：
```bash
cd {baseDir} && node bin/search.js "杭州" 2026-06-10 2026-06-13 2 en-us
```

脚本会自动处理所有操作：守护进程启动、Agoda 缓存查找、Google + Booking 内联搜索、OpenTravel API 查询（所有城市）、新城市发现和格式化层级卡片输出。只需运行它并将输出发送给用户。

**不要先进行澄清问题。** 直接运行命令。推断所有参数：
- **年份：** 除非用户另有说明，否则使用当前年份。如果请求的日期/月份已经过去，则假设下一年。 （使用 `date +%Y-%m-%d` 获取当前日期，如果不确定。）
- **"10-13/6"** → `<年份>-06-10 <年份>-06-13` — 用上述规则填充 `<年份>`
- **"2 位客人" / "2 人"** → `2` 位成人
- **地区设置：** 传递给 OTA 的语言/区域代码（控制网站语言+区域）。默认 `en-us`。价格以美元计价（Google Hotels 使用 `gl=us&curr=USD` 请求）；其他来源将遵循你传递的地区设置。

**不要使用任何其他方法。** 没有Python脚本、没有 curl、没有浏览器工具、没有子代理。这个一键式命令就是你需要的全部。

## 🚨 关键规则 — 每次都要遵守

**规则 0 — 禁止使用的工具。请阅读两次。** 这个技能通过 `terminal` 工具驱动一个长时间运行的 Patchright 守护进程。你的运行时暴露了几个看起来方便的工具，但在本技能中严格禁止使用：

❌ `browser_navigate` / `browser_open` — 禁止使用
❌ `browser_click` — 禁止使用
❌ `browser_type` / `browser_fill` — 禁止使用
❌ `browser_snapshot` — 禁止使用
❌ `browser_close` — 禁止使用
❌ 任何其他 `browser_*` 原生工具 — 禁止使用
❌ `delegate_task` / `spawn_agent` / 子代理委托 — 禁止使用

原因：这些原生工具会启动一个普通的 Chromium，无法隐蔽，因此 Booking.com 和 Agoda 几秒钟内就会检测到机器人，请求就会挂起，直到运行时在 "命令超时 30/60 秒后" 杀死它们。你会浪费 5 分钟以上的超时时间，用户什么也得不到。通过 `terminal` 启动的 Patchright 守护进程可以躲避机器人检测。

委托的子代理以空历史记录和没有技能上下文开始 — 它们总是会回退到 Python/curl 抓取，这会立即被机器人阻止。**这个技能必须完全在当前代理中运行，仅使用 `terminal` 工具。**

✅ 本技能中驱动浏览器的唯一允许方式是 via `terminal`:
```
terminal: cd {baseDir} && node bin/search.js ...
```

**规则 1 — `search.js` 处理所有操作。永远不要自己抓取 OTA。** 不要手动调用 `browse.js` 命令，不要在浏览器中 `goto`/`click`/`type`，不要手动构建 Agoda/Booking/Google URL，不要单独调用 OpenTravel API，不要尝试自己启动守护进程。`search.js` 已经通过一个经过精心设计的流程驱动隐蔽的守护进程，该流程可以躲避机器人检测 — 它内部处理了所有城市的 Agoda 发现（包括中文城市如上海、杭州等）。**手动导航 OTA 是导致失败的首要原因：它会触发 Agoda/Booking 的反机器人机制（"检测自动化"、"重定向到主页"、"无法完成搜索"）并导致 IP 被封锁。** 你的唯一任务是运行一次 `search.js` 并发送其输出。如果你认为某个来源 "缺失"，请重新阅读规则 4 — 不要手动去获取它。

**规则 2 — 首次城市发现需要 2–4 分钟。** 如果 `search.js` 输出包含 `"discovering"` 或 `"launching"` 消息，请告诉用户："首次搜索这个城市 — 发现选择器，这需要大约 2–4 分钟..." 并等待结果。不要重试或中止。

**规则 3 — 精确发送输出。** `search.js` 输出的是准备好的层级卡片，可以直接发送。将输出直接复制到你的响应中。不要重新格式化、总结或缩写它。

**规则 3a — 保留 Markdown 超链接。** 输出中的每个酒店名称都已包装为 `[酒店名称](https://booking-url...)`。这是一个可点击的超链接 — 不要：
- 剥离 Markdown 并在单独的 `🔗 https://...` 行显示 URL
- 将 `[Hotel Name](url)` 替换为纯文本
- 大写 OTA 名称（"google" 保持 "google"，不要写成 "Google"）
- 重命名部分 — "📋 更多优惠" 保持原样

输出已准备好用于 Telegram-MarkdownV2。直接发送它会给用户可点击的酒店名称和隐藏的 URL（干净的 UI）。

**规则 3b — 如果你确实在输出后添加了建议/评论部分，你提到的每个酒店名称也必须是一个使用脚本打印的相同 URL 的 Markdown 超链接 `[Hotel Name](url)`。** 不要在你的评论中以纯文本形式写酒店名称。

**规则 4 — 部分结果是正常且可接受的。永远不要手动 "修复" 它们。** 某个来源可能不在输出中（例如，Agoda 在本次运行中被封锁，或者 OpenTravel 对该城市没有库存）。这是正常的 — 发送包含现有来源的层级卡片。页脚（`📊 N家酒店 | <数据来源> • 价格单位：美元`）列出了确实找到的内容。**不要** 尝试通过浏览器、直接 URL 或任何其他工具获取缺失的来源 — 那会触发反机器人机制并使情况更糟。如果 `search.js` 完全出错，请用一句话告诉用户失败的原因，并显示错误上方的任何部分输出。如果你想要更多覆盖范围，唯一有效的重试是再次运行相同的 `search.js` 命令（反机器人通常是暂时的）。

## 输出格式参考

`search.js` 以此格式打印层级卡片 — 你直接发送给用户：

酒店名称是一个指向其最便宜 OTA 的 Markdown 链接。价格行不带链接，OTA 键以小写显示（`agoda`/`booking`/`google`/`opentravel`）。没有星级评分或区域线 — 脚本没有这些数据。

```
🏨 <城市> • <d1>–<d2> • <N>晚 • <成人数量>位客人
━━━━━━━━━━━━━━━━━━━━

🥇 最佳价值
[<Hotel Name>](<cheapest_link>)
  ✅ agoda      💰 <价格>/晚
     booking    💰 <价格>/晚
     opentravel 💰 <价格>/晚
     → 比 Booking 省 <差额>美元

🥈 最便宜
[<Hotel Name>](<cheapest_link>)
  ✅ google     💰 <价格>/晚
     agoda      💰 <价格>/晚

🥉 品质
[<Hotel Name>](<cheapest_link>)
  ✅ booking    💰 <价格>/晚
     agoda      💰 <价格>/晚

📋 更多优惠
  — Agoda —
  • [<Hotel>](<agoda_link>) — agoda: <价格> | booking: <价格>
  — Booking —
  • [<Hotel>](<booking_link>) — booking: <价格>
  — Google —
  • [<Hotel>](<google_link>) — google: <价格>
  — OpenTravel —
  • [<Hotel>](<opentravel_link>) — opentravel: <价格>

💡 提示: <最佳酒店名称>
   [在 <OTA> 上预订](<链接>) — <价格>/晚

📊 <N>家酒店 | <有数据的来源> • 价格单位：美元
```

所有价格都以美元显示。Agoda、Google 和 OpenTravel 通过 IP 地理锁定到越南盾，并通过实时汇率转换；Booking 原生返回美元。仅列出实际返回数据的来源。

## 限制

- 首次搜索每个城市会支付 Agoda 发现成本（2–4 分钟）。Google 和 Booking 是内联（无发现）；OpenTravel 是直接 API 调用。
- 后续搜索会重用 Agoda 缓存，并在 30–60 秒内完成。
