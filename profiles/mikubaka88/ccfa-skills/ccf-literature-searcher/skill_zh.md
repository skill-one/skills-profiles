# CCF文献检索器

## 家庭文件合同

在编写前，为每个任务/工件确定规范的输出格式和稳定的单个工作目录。重用明确的或已建立的路径；否则使用项目根目录 `ccfa-workfiles/<用途>/<工件ID>/`，仅在需要时使用 `source/`、`assets/`、`cache/` 和 `build/`。就地更新当前文件；不要分散中间文件或创建迭代副本。保留输入和所需证据；仅清理由此任务创建的已验证的可丢弃文件。使用UTF-8文本I/O，并在保存或渲染后检查中文文本。对于文件工作，应用 [artifact-contracts.md](../ccf-common/references/artifact-contracts.md) 并在技能转换过程中重用相同的路径。

## 协作合同

在专家执行前，首先阅读并应用 [ccf-humanization](../ccf-humanization/SKILL.md)，然后应用 [ccf-common](../ccf-common/SKILL.md)。在每次交接时，重用其适用的活跃规则或刷新缺失/更改的规则。即使没有文字，这两个预检也是必需的；详细的编辑、实验和维护模式仅在相关时运行。

保留一个集成的负责人，并积极使用其他技能来解决缺失的先决条件或检查材料发现。重用适用的证据；不要跳过必要的准备工作以节省代币。在最终确定前，集成贡献并验证受影响的成果。遵循条件性 [合作路线](../ccf-common/references/routing.md)；避免不相关的阶段和重复报告。

## 调用控制

**CCFA交接模式：部分（推荐）。** 遵循 `metadata.ccf_skill_controls.handoff_question_mode` 和 `../ccf-common/references/handoff-modes.md`。使用 `../ccf-common/references/routing.md` 将文献检索与想法优化、文稿撰写、实验设计、论文评审和反驳分开。

在决定探索性、快速或标准模式之前，加载 `../ccf-common/references/task-modes.md`。使用探索性模式进行早期方向侦察，"看看还有没有机会"、"这个方向是不是被做完了"，或旨在为想法优化提供输入而非最终新颖性判断的文献检索。使用快速模式进行狭窄的相关工作扫描或一组候选引用。使用标准模式进行相关工作、引言、成熟想法新颖性基础、基准发现、实验设计或实质性的多交付成果工作。即使一个写作者将使用它，一个小型引用查找也保持快速。

如果用户要求定期监控、最新论文监控、竞争对手跟踪、"最近是否有类似想法"、arXiv/OpenReview源扫描或实验室/项目跟踪，通过共享交接模式路由到 `ccf-literature-monitor`。使用此技能进行深度检索、最近工作聚类、相关工作结构、基准/数据集发现和引用候选。

将用户想法、草稿文本、未发表结果和私人手稿视为私人材料。在浏览前加载 `../ccf-common/references/privacy-and-evidence.md`。使用公共关键词、公共标题、会议名称、方法名称、公共摘要或用户批准的查询文本进行搜索。除非用户明确授权，否则不要将私人草稿句子粘贴到搜索查询中。

源质量排除：不要搜索、引用、推荐或包含政策排除的会议、期刊、URL或PDF。共享政策包括MDPI源在此排除集中；仅在内部筛选或搜索笔记文件中记录排除项。

## 核心规则

使用高质量、可检查的来源进行新颖性和定位。优先考虑有影响力的会议、强期刊、官方会议录页面、存档库和公共论文页面。不要编造论文、引用、会议、链接、接受状态、基准状态或数值结果。将搜索证据与推论分开。文献检索不是淘汰关卡：相关工作的存在应在任何"方向已覆盖"结论之前产生差异化选项、开放差距、基准/证据选择和警告标签。遵循用户请求的输出形状：短列表、相关工作聚类、机会地图、BibTeX候选、基准表、搜索文件夹或交接摘要。

## 强制搜索清单

在标准模式下，在最终输出前完成此清单。在快速模式下，运行相关子集并返回紧凑的清单状态。

1. 将用户的主题转换为安全的公共搜索查询。
2. 应用共享源质量排除到搜索域、候选和最终输出。
3. 优先考虑主要或高置信度的会议：官方会议录、arXiv/OpenReview在适当情况下、ACL Anthology、CVF、PMLR、ACM、IEEE、USENIX、DBLP、Semantic Scholar、OpenAlex、Crossref以及会议或项目页面。
4. 通过标题对候选论文进行去重，并链接到稳定URL。
5. 每篇包含的论文都有会议/年份/来源状态、论文类型和相关性理由。
6. 仅在请求或对实质性筛选有用时，根据检查的文本支持程度，对论文质量进行评分，仅限于洞察力、完整性和实验数值证据。纯基准论文跳过数值结果评分，并接收基准质量注释。
7. 论文类型是 `纯基准`、`纯方法`、`方法+基准`、`综述`、`系统/工具`、`理论/证明` 或 `其他`。
8. 关于论文的每项声明都可追溯到链接的来源或标记为推论。
9. 对于想法阶段的搜索，每个最近工作聚类包括已覆盖的内容、尚未测试的内容，以及至少一条可能的差异化或救援路线。
10. 仅在请求可重用输出或需要在授权工作流程内使用时才编写文献检索文件夹。遵守无新文件约束。使用现有的规范搜索文件夹进行更新；否则使用 `references/report-template.md` 与默认文件夹名称：

```text
ccfa-workfiles/literature/<主题缩写>/
  papers.md
  papers.csv        # 仅当需要结构化重用/导出时
  search-notes.md    # 仅当查询/覆盖范围必须单独持久化时
  idea-grounding.md  # 在搜索为想法优化提供输入时包括
```

重用现有的日期或自定义搜索文件夹，而不是重命名它。在报告中存储当前搜索日期和源版本；不要为普通更新创建新文件夹。从一组筛选的来源中导出请求的Markdown/CSV视图，而不是编写独立的副本。跳过空或未请求的评分列和通用状态部分。

11. 如果搜索为另一个模块提供输入，请提供包含规范源路径和仅决策相关证据的紧凑交接：
    - 对于写作：最近工作组、新颖性差距、引用警告。
    - 对于想法优化：一个紧凑的想法基础包，包含证据卡片、机制基础、协议锚点、差距/冲突关系、过时/拥挤方向、及时转向和最小可行研究问题。将完整摘要和通用背景排除在交接之外。
    - 对于想法评审：新颖性置信度和可能的先验艺术风险。
    - 对于文献监控：监控查询、跟踪竞争对手和重复重叠信号。
    - 对于实验设计：数据集、基线、指标、基准协议。
    - 对于论文评审：缺失的相关工作和基线风险。

## 自适应输出合同

首先返回请求的工件。如果用户要求论文列表，直接输出列表/表格。如果他们要求相关工作材料，输出聚类和定位注释。如果他们要求文件夹，编写文件夹并总结。使用以下默认值作为标准或快速搜索报告。

对于标准搜索，返回：

```text
搜索目的：
使用的查询：
源政策：
编写的文件夹：
顶级论文表：
最近工作聚类：
机会地图：
质量评分理由：
基准/数据集候选：
新颖性和定位风险：
推荐的下一个模块：
清单状态：
```

对于快速搜索，返回：

```text
快速搜索范围：
顶级候选：
高风险缺失文献：
机会提示：
编写的文件夹：
紧凑清单状态：
```

## 检索执行

在支持时，批量独立公共安全的查询聚类，然后在深入阅读前通过DOI/arXiv标识符和标准化标题进行去重。在原始论文或主要页面上验证重要声明，而不是片段。跟踪检查的章节和出版/版本状态。不要评分未阅读的方法或将无法访问的结果视为缺失。不可用来源限制了该声明；继续使用可用的主要证据并报告相关的覆盖范围差距。
