# CCF人性化

## 家庭文件合同

在编写前，确定每个任务/成果的规范输出和一个稳定的可工作目录。重用明确的或已建立的路径；否则使用项目根目录 `ccfa-workfiles/<用途>/<成果ID>/`，仅在需要时使用 `source/`、`assets/`、`cache/` 和 `build/`。就地更新当前文件；不要分散中间文件或创建迭代副本。保留输入和所需证据；仅清理由此任务创建的已验证的可丢弃文件。使用UTF-8文本I/O，并在保存或渲染后检查中文文本。对于文件工作，应用 [artifact-contracts.md](../ccf-common/references/artifact-contracts.md) 并在技能转换时重用相同的路径。

## 协作合同

这是第一个必需的家庭预检。应用以下基线，然后在使用 [ccf-common](../ccf-common/SKILL.md) 之前激活。两个预检启动一次而不递归地进入对方；重用适用于贡献者的规则。

保持一个集成的负责人，并积极使用其他技能来解决缺失的先决条件或检查材料发现。重用适用的证据；不要跳过必要的准备工作以节省代币。在最终确定之前，集成贡献并验证受影响的结果。遵循条件 [cooperation routes](../ccf-common/references/routing.md)；避免不相关的阶段和重复的报告。

## 调用控制

**CCFA交接模式：PARTIAL（推荐）。** 遵循 `metadata.ccf_skill_controls.handoff_question_mode`、`../ccf-common/references/handoff-modes.md` 和 `../ccf-common/references/task-modes.md`。

为每个CCFA任务和贡献者激活此模式，包括规划、检索、审查、审计、渲染、脚手架和维护。在使用 `ccf-common` 和专家执行之前应用以下家庭基线。在交接时重用已加载的适用基线；刷新更改或丢失的规则。文本编辑和实验检查取决于实际任务，但基线激活是通用的。专家技能保留所有权，显式的用户/主机约束仍然适用。

## 家庭基线

在专家工作之前阅读并应用此条目的基线。直接传达具体的任务、证据和决策；避免想象的反对意见、空洞的保证、重复的警告和不必要的流程说明。保留真实风险、关键审查发现、不确定性、科学事实、来源引用和强制检查。不要将关键评估变成表扬或改变分数以听起来不那么防御性。仅审查的任务诊断而不重写；非文本任务应用这些规则而不编造文本编辑过程。仅启用以下相关的详细模式。此预检默认情况下不会创建报告、警告文件或单独的代理。

## 核心规则

直接写出科学论证：问题、见解、机制、证据和支持的启示。删除作者的自我辩护、想象的审稿人反对意见、道歉式新颖性定位、以否认为主的声明、空洞的保证、堆叠的回避、重复的范围免责声明和强制性的谨慎结尾。用其科学负载替换防御性句子，或如果它不增加任何内容则删除它。

人性化保留严谨性：保留有意义的不确定性、实际假设、负面结果、协议事实、引用、方程式、数字、术语和强制披露。不要将 `suggests` 变成 `proves`，省略已知的失败，或隐藏真实的比较限制。不要将诸如 `only`、`not` 或 `may` 的孤立单词视为错误。

保留方法确认和版本门状态为内部信息。自然地描述实际方法和相关配置。使用提供的规范进行方法起草，使用引用的证据进行先前工作，使用验证的完整配置进行报告的比较；不要仅为了编辑支持的文本而要求新的实验。

## 模式

- `family-preflight`：在任何CCFA专家之前始终应用基线；不需要手稿或实验成果。
- `manuscript-humanization`：在保留科学内容和源格式的同时修改防御性文本。
- `experiment-humanization`：将相同的文本标准应用于最终实验描述和表格；保留完整方法比较和标记的消融。
- `warning-only`：识别一个具体的未解决的科学决策，而不修改其依赖的成果。

## 工作流

对于 `family-preflight`，应用基线，确保 `ccf-common` 处于活动状态，并继续请求的专家任务。以下编辑工作流仅适用于任务包含相关的文本或实验成果时；不要为了完成通用的预检而运行它。

1. 确定请求的成果、现有的授权以及输入是文本、建议的设计还是报告的结果。阅读 `references/humanization-policy.md` 以获取句子决策和双语修复示例。
2. 恢复每个段落的科学信息。直接陈述观察、操作、假设或推断。删除空的自我辩护，而不是将其移入警告块。
3. 删除跨章节的重复警告。在解释发生变化时表达范围；不要要求每个摘要、段落、标题或结论都以限制结束。
4. 在授权编辑中保留材料事实和校准的不确定性。如果一个决策需要新的证据或研究范围更改，隔离该决策并继续不受影响的工作。不要仅仅为了编码警告而编辑源文件。
5. 对于实际的发布比较或可执行的实验更改，加载 `references/experiment-discipline.md`。在内部门中保留验证的标识和完整配置；将合法的消融清晰标记。仅当任务需要时运行此步骤。
6. 在科学论证合理后应用现有的标点符号和术语偏好。对于完整章节或论文，当可用时运行 `../ccf-paper-writer/scripts/check_prose_quality.py` 并检查其在上下文中的候选位置。不要仅仅为了清除启发式警告而重写正确的科学语言。
7. 一次性阅读最终文本。检查修辞谨慎是否已被炒作、事实遗漏或不同的科学声明所取代。仅当文本已更改或发现未解决时才重新运行检查。
8. 以原始格式返回请求的成果。作为侧车时，将所有权返回给内容技能；不要将过程报告附加到普通文本。

## 警告合同

仅用于无法从提供的证据和现有授权中解决的明确决策：

```text
CCF Humanization Warning: not inserted into artifacts
Affected claim / file / experiment:
Evidence gap and material consequence:
Decision needed:
Materiality: advisory / blocking
File changes made for this warning: none
```

`blocking` 适用于依赖的声明或更改，而不是整个任务。风格选择、已记录的限制和准确的地方声明缩小是普通的授权编辑。
