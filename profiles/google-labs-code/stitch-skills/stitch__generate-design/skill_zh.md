# 生成设计

根据文本描述、图像或原型创建新的设计屏幕，使用提示和设计系统标记编辑现有屏幕，并使用 Stitch MCP 生成设计变体。

> [!NOTE]
> 参考您的系统提示，了解如何处理本技能中提到的所有工具的前缀（例如，`list_projects`、`generate_screen_from_text`、`edit_screens`）。

## 🎨 提示增强流程

在调用任何 Stitch 生成或编辑工具之前，您必须增强用户的提示。

### 1. 分析上下文

- **项目**：使用 `list_projects` 找到正确的 `projectId`。如果没有合适的项目，请使用 `create_project` 创建一个。
- **设计系统**：通过 `list_design_systems` 检查项目是否存在设计系统。如果存在，设计标记（颜色、字体、圆角）已经在项目级别应用——不要在生成提示中包含任何颜色、字体或主题说明。如果不存在，请先委托给 **manage-design-system** 技能，然后再生成屏幕。

### 2. 细化 UI/UX 术语

参考 [设计映射](references/design-mappings.md) 替换模糊术语。

- 模糊： "制作一个漂亮的标题"
- 专业： "带有玻璃效果和居中标志的粘性导航栏"

使用 [提示关键词](references/prompt-keywords.md) 进行组件名称、形容词调色板、颜色角色和形状描述。

### 3. 结构化最终提示

为 Stitch 格式化增强后的提示。专注于 **布局、内容和结构**——永远不要包含颜色、字体或主题说明（这些由项目级别的 **manage-design-system** 技能处理）。

对于 **新屏幕**，使用此模板：

```markdown
[页面整体目的和用户意图]

**平台**： [Web/移动端], [桌面端/移动端]优先

**页面结构：**
1. **标题栏**： [导航和品牌描述]
2. **英雄区域**： [标题、副标题和主要 CTA]
3. **主要内容区域**： [详细组件分解]
4. **页脚**： [链接和版权信息]
```

对于 **编辑**，具体说明要更改的内容：

- **位置**： "更改 [主要按钮] 在 [英雄区域]..."
- **视觉效果**： "...改为深蓝色 (#004080) 并添加微妙阴影。"
- **结构**： "在主要按钮旁边添加一个带有 '了解更多' 文本的次要按钮。"

> [!CAUTION]
> 在 **生成** 提示中不要包含十六进制代码、字体名称、调色板、圆角值或任何设计系统标记。这些由 **manage-design-system** 技能在项目级别应用，如果重复则会产生冲突。（对于 **编辑** 提示，十六进制代码可用于精确的颜色调整。）

### 4. 展示 AI 洞察

在调用任何工具后，始终将 `outputComponents`（文本描述和建议）展示给用户。

参考 [示例/增强提示.md](examples/enhanced-prompt.md) 获取完整的增强前/后提示示例。

## 步骤

### 确定模式

根据用户的请求决定使用哪个流程：

- 用户希望从文本描述创建 → **从文本生成** 流程
- 用户提供图像、截图或原型 → **从图像生成** 流程
- 用户希望修改现有屏幕 → **编辑** 流程
- 用户希望布局/颜色/内容变体 → **生成变体** 流程

---

### 从文本生成流程（新屏幕）

#### 1. 增强用户提示

应用上述提示增强流程。

#### 2. 确定项目

如果尚未知道，使用 `list_projects` 找到正确的 `projectId`。

#### 3. 生成屏幕

使用增强后的提示和 `designSystem` ID（如果在步骤 1 中找到）调用 `generate_screen_from_text` 工具。

```json
{
  "projectId": "...",
  "prompt": "[您的增强提示]",
  "designSystem": "assets/...", // 可选：如果在步骤 1 中找到，请传递
  "deviceType": "DESKTOP"  // 选项：MOBILE, DESKTOP, TABLET
}
```

#### 4. 展示 AI 反馈

始终向用户展示 `outputComponents` 中的文本描述和建议。

#### 5. 下载设计资源

生成后，将 HTML 和截图 URL 从 `outputComponents` 下载到 `.stitch/designs` 目录。

- **命名**： 使用屏幕 ID 或描述性别名作为文件名。
- **工具**： 使用 `curl -o` 通过 `run_command` 或类似方式。
- **目录**： 确保 `.stitch/designs` 存在。

#### 6. 审查和细化

- 如果结果不符合预期，请继续使用 **编辑** 流程进行有针对性的调整。
- 除非布局根本错误，否则不要从头重新生成。

---

### 从图像生成流程（图像/原型 → 设计）

当用户提供图像、截图或设计原型以在 Stitch 中重新创建时，使用此流程。

#### 1. 确定项目

使用 `list_projects` 找到正确的 `projectId`。如果没有合适的项目，请使用 `create_project` 创建一个。

#### 2. 上传图像

委托给 **upload-to-stitch** 技能将图像上传到项目。这将创建一个以图像为内容的新屏幕。

#### 3. 使用编辑细化

上传后，使用 `list_screens` 找到新创建的 `screenId`，然后使用描述性提示调用 `edit_screens` 来细化设计：

```json
{
  "projectId": "...",
  "selectedScreenIds": ["<上传的屏幕ID>"],
  "prompt": "[描述要调整、增强或从此原型中重新创建的内容]"
}
```

> [!TIP]
> 为获得最佳结果，描述图像背后的意图，而不是简单地说 "让它看起来像这样"。例如："这是一个仪表板原型——使用适当的数据表、侧边栏导航和图表小部件重新创建它。"

#### 4. 展示 AI 反馈

始终向用户展示 `outputComponents` 中的文本描述和建议。

#### 5. 下载设计资源

将 HTML 和截图 URL 从 `outputComponents` 下载到 `.stitch/designs` 目录。

- **命名**： 使用屏幕 ID 或描述性别名作为文件名。
- **工具**： 使用 `curl -o` 通过 `run_command` 或类似方式。
- **目录**： 确保 `.stitch/designs` 存在。

---

### 编辑流程（修改现有屏幕）

#### 1. 确定屏幕

使用 `list_screens` 或 `get_screen` 找到正确的 `projectId` 和 `screenId`。

#### 2. 制定编辑提示

应用提示增强流程，专注于具体性：

- **位置**： "更改 [主要按钮] 在 [英雄区域] 的颜色..."
- **视觉效果**： "...改为深蓝色 (#004080) 并添加微妙阴影。"
- **结构**： "在主要按钮旁边添加一个带有 '了解更多' 文本的次要按钮。"

#### 3. 应用编辑

调用 `edit_screens` 工具。

```json
{
  "projectId": "...",
  "selectedScreenIds": ["..."],
  "prompt": "[您的目标编辑提示]"
}
```

#### 4. 展示 AI 反馈

始终向用户展示 `outputComponents` 中的文本描述和建议。

#### 5. 下载设计资源

编辑后，将更新的 HTML 和截图 URL 从 `outputComponents` 下载到 `.stitch/designs` 目录，覆盖旧版本以确保本地文件反映最新编辑。

- **命名**： 使用屏幕 ID 或描述性别名作为文件名。
- **工具**： 使用 `curl -o` 通过 `run_command` 或类似方式。
- **目录**： 确保 `.stitch/designs` 存在。

#### 6. 更新项目元数据

下载资源后，更新 `.stitch/metadata.json` 以反映任何更改（例如，更新的屏幕标题或编辑产生的新屏幕 ID）。元数据文件跟踪所有屏幕、它们的设备类型和设计系统信息。参考 **manage-design-system** 技能的 `examples/metadata.json` 格式。

#### 7. 验证和重复

- 检查输出屏幕以确认更改是否正确应用。
- 如果需要更多润色，请重复编辑流程，使用新的具体提示。

---

### 生成变体流程（探索变体）

当用户希望探索现有屏幕的替代布局、配色方案或内容变体时，使用此流程。

#### 1. 确定屏幕

使用 `list_screens` 或 `get_screen` 找到正确的 `projectId` 和 `screenId`。

#### 2. 配置变体选项

使用适当的选项调用 `generate_variants` 工具：

```json
{
  "projectId": "...",
  "selectedScreenIds": ["..."],
  "prompt": "[描述变体的方向]",
  "variantOptions": {
    "variantCount": 3,
    "creativeRange": "EXPLORE",
    "aspects": ["LAYOUT", "COLOR_SCHEME"]
  }
}
```

**变体选项：**
- **`variantCount`**： 1–5 个变体（默认：3）
- **`creativeRange`**： `REFINE`（微妙）、`EXPLORE`（平衡）或 `REIMAGINE`（彻底）
- **`aspects`**： 聚焦于特定维度——`LAYOUT`、`COLOR_SCHEME`、`IMAGES`、`TEXT_FONT`、`TEXT_CONTENT`，或留空以涵盖所有

#### 3. 展示 AI 反馈

始终向用户展示 `outputComponents` 中的文本描述和建议。

#### 4. 下载设计资源

将变体 HTML 和截图 URL 从 `outputComponents` 下载到 `.stitch/designs` 目录。

- **命名**： 使用屏幕 ID 或描述性别名作为文件名。
- **工具**： 使用 `curl -o` 通过 `run_command` 或类似方式。
- **目录**： 确保 `.stitch/designs` 存在。

## 💡 小贴士

- **结构化**： 在提示中将页面分解为标题栏、英雄区域、功能区和页脚。
- **内容优先**： 描述每个部分包含的内容（文本、图像、CTA），而不是它的外观。
- **迭代润色**： 优先使用编辑进行有针对性的调整，而不是完全重新生成。
- **无主题泄漏**： 不要在生成提示中放入十六进制代码、字体名称或颜色角色——设计系统处理所有视觉样式。
- **指定交互**： 提及悬停状态、动画和点击行为，而不是视觉样式。
- **保持编辑聚焦**： 一次一个编辑通常比长列表的更改更好。
- **参考组件**： 使用专业术语，如 "导航栏"、"英雄区域"、"页脚"、"卡片网格"。
- **编辑中的精确颜色**： 使用十六进制代码进行精确的颜色匹配，当编辑现有屏幕时。
