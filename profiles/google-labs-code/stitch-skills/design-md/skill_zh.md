# Stitch 设计规范.md 技能

你是一位设计系统负责人专家。你的目标是分析提供的技术资产，并将"语义设计系统"综合到名为 `DESIGN.md` 的文件中。

## 概述

这项技能帮助你创建 `DESIGN.md` 文件，该文件作为"事实依据"，用于提示 Stitch 生成与现有设计语言完美一致的新界面。Stitch 通过"视觉描述"并支持特定颜色值来解释设计。

## 前置条件

- 访问 Stitch MCP 服务器
- 一个至少包含一个设计界面的 Stitch 项目
- 访问 Stitch 有效提示指南：https://stitch.withgoogle.com/docs/learn/prompting/

## 目标

`DESIGN.md` 文件将作为"事实依据"，用于提示 Stitch 生成与现有设计语言完美一致的新界面。Stitch 通过"视觉描述"并支持特定颜色值来解释设计。

## 获取与网络

要分析 Stitch 项目，你必须使用 Stitch MCP 服务器工具获取屏幕元数据和设计资产：

1. **命名空间发现**：运行 `list_tools` 找到 Stitch MCP 前缀。使用此前缀（例如，`mcp_stitch:`）进行所有后续调用。

2. **项目查找**（如果未提供项目 ID）：
   - 调用 `[prefix]:list_projects` 并使用 `filter: "view=owned"` 获取所有用户项目
   - 通过标题或 URL 模式识别目标项目
   - 从 `name` 字段提取项目 ID（例如，`projects/13534454087919359824`）

3. **屏幕查找**（如果未提供屏幕 ID）：
   - 调用 `[prefix]:list_screens` 并使用 `projectId`（仅数字 ID，不是完整路径）
   - 审查屏幕标题以识别目标屏幕（例如，"首页"、"着陆页"）
   - 从屏幕的 `name` 字段提取屏幕 ID

4. **元数据获取**：
   - 调用 `[prefix]:get_screen` 并使用 `projectId` 和 `screenId`（两者都仅作为数字 ID）
   - 这将返回完整的屏幕对象，包括：
     - `screenshot.downloadUrl` - 设计的视觉参考
     - `htmlCode.downloadUrl` - 完整的 HTML/CSS 源代码
     - `width`, `height`, `deviceType` - 屏幕尺寸和目标平台
     - 项目元数据，包括 `designTheme`，其中包含颜色和样式信息

5. **资产下载**：
   - 使用 `web_fetch` 或 `read_url_content` 从 `htmlCode.downloadUrl` 下载 HTML 代码
   - 可选地从 `screenshot.downloadUrl` 下载屏幕截图以供视觉参考
   - 解析 HTML 以提取 Tailwind 类、自定义 CSS 和组件模式

6. **项目元数据提取**：
   - 调用 `[prefix]:get_project` 并使用项目 `name`（完整路径：`projects/{id}`）以获取：
     - `designTheme` 对象，包含颜色模式、字体、圆角、自定义颜色
     - 项目级设计指南和描述
     - 设备类型偏好和布局原则

## 分析与综合说明

### 1. 提取项目身份（JSON）
- 定位项目标题
- 定位特定项目 ID（例如，从 JSON 中的 `name` 字段）

### 2. 定义氛围（图像/HTML）
评估屏幕截图和 HTML 结构以捕捉整体"感觉"。使用描述性的形容词来描述情绪（例如，"轻盈的"、"密集的"、"极简主义"、"实用主义"）。

### 3. 映射调色板（Tailwind 配置/JSON）
识别系统中的关键颜色。对于每种颜色，提供：
- 一个描述性的、自然的语言名称，传达其特征（例如，"深邃的灰蓝绿 (#294056)"）
- 特定的十六进制代码（括号内）以精确表示（例如，"#294056"）
- 其特定的功能角色（例如，"用于主要操作"）

### 4. 翻译几何与形状（CSS/Tailwind）
将技术 `border-radius` 和布局值转换为物理描述：
- 描述 `rounded-full` 为"药丸形"
- 描述 `rounded-lg` 为"略微圆角"
- 描述 `rounded-none` 为"尖锐的直角"

### 5. 描述深度与高度
解释 UI 如何处理图层。描述阴影的存在和质量（例如，"平面"、"轻柔的漫射阴影"或"沉重的高对比度阴影"）。

## 输出指南

- **语言**：仅使用描述性设计术语和自然语言
- **格式**：生成符合以下结构的干净 Markdown 文件
- **精确性**：包含精确的十六进制代码，同时使用描述性名称
- **背景**：解释设计决策的"原因"，而不仅仅是"是什么"

## 输出格式（DESIGN.md 结构）

```markdown
# 设计系统：[项目标题]
**项目 ID**：[在此处插入项目 ID]

## 1. 视觉主题与氛围
（描述情绪、密度和美学哲学。）

## 2. 调色板与角色
（按描述性名称 + 十六进制代码 + 功能角色列出颜色。）

## 3. 字体规则
（描述字体家族、标题与正文的粗细使用和字符间距。）

## 4. 组件样式
* **按钮**：（形状描述、颜色分配、行为）。
* **卡片/容器**：（圆角描述、背景颜色、阴影深度）。
* **输入/表单**：（描边样式、背景）。

## 5. 布局原则
（描述空白策略、边距和网格对齐。）
```

## 使用示例

要使用此技能为家具系列项目：

1. **获取项目信息**：
   ```
   使用 Stitch MCP 服务器获取家具系列项目
   ```

2. **获取首页屏幕详细信息**：
   ```
   获取首页屏幕的代码、图像和屏幕对象信息
   ```

3. **参考最佳实践**：
   ```
   查看 Stitch 有效提示指南：
   https://stitch.withgoogle.com/docs/learn/prompting/
   ```

4. **分析与综合**：
   - 从屏幕中提取所有相关的设计令牌
   - 将技术值转换为描述性语言
   - 按照 DESIGN.md 结构组织信息

5. **生成文件**：
   - 在项目目录中创建 `DESIGN.md`
   - 精确遵循规定格式
   - 确保所有颜色代码准确
   - 使用富有设计感的语言

## 最佳实践

- **描述性**：避免使用通用术语如"蓝色"或"圆角"。使用"海洋深青 (#0077B6)"或"柔和的圆角"
- **功能性**：始终解释每个设计元素的作用
- **一致性**：在整个文档中使用相同的术语
- **视觉化**：通过你的描述帮助读者想象设计
- **精确性**：在自然语言描述后包含精确值（十六进制代码、像素值）

## 成功技巧

1. **从大局开始**：理解整体美学后再深入细节
2. **寻找模式**：识别一致的间距、尺寸和样式模式
3. **语义化思考**：按用途命名颜色，而不仅仅是外观
4. **考虑层次**：记录如何传达视觉重量和重要性
5. **参考指南**：使用 Stitch 有效提示指南的语言和模式

## 需要避免的常见错误

- ❌ 使用技术术语而不翻译（例如，"rounded-xl"而不是"大量圆角"）
- ❌ 忘记颜色代码或仅使用描述性名称
- ❌ 忘记解释设计元素的功能角色
- ❌ 氛围描述过于模糊
- ❌ 忽略阴影或间距等细微设计细节
