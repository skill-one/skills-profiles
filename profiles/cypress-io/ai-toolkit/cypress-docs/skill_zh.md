# Cypress 文档

## 目的
通过优先考虑官方文档和结构化资源，使代理能够获取关于 Cypress 测试框架的准确、最新且可验证的信息。

## 使用场景

每当任务依赖于 **查找、阅读或引用 Cypress 文档** 而不是一般测试直觉时，请应用此技能：

- **查找事实**：Cypress 文档中定义的命令、API、断言、生命周期钩子、配置选项、环境变量、CLI 标志、插件或 TypeScript 类型。
- **确认行为**：特定 Cypress 版本中的工作方式、E2E 与组件测试的区别、浏览器支持或网络/`cy.intercept` 语义。
- **在断言“Cypress 可以/不可以…” 之前**：先搜索文档；不要依赖记忆来获取确切的签名、默认值或已弃用的 API。
- **提取结构化内容**：在获取或总结文档页面时，遵循 LLM 优化的文档策略（`llms.txt`，`/llm/*`）。
- **为他人提供依据**：向用户解释 Cypress、编写示例或审查代码时，确保正确性必须与官方文档一致。

如果用户只需要 **编写或修复测试** 而无需查找文档，请优先使用 `cypress-author`；如果他们只需要 **解释测试** 而无需获取文档，请优先使用 `cypress-explain`。当官方文档是事实来源时，使用 **此技能**。

## 🤖 LLM-优化的文档策略

当访问 `docs.cypress.io` 时：

1. 获取 `/llms.txt`
2. 解析它以发现：
   - LLM 友好的文档路径
   - 结构化内容端点
3. 优先选择 `/llm/*` 下的内容。网站上的每个路径都在 `/llm` 下有优化版本——例如，`https://docs.cypress.io/app/faq` 可在 `https://docs.cypress.io/llm/markdown/app/faq.md` 获取。
4. 原因：
   - Markdown / JSON 格式
   - 结构更清晰
   - 比 HTML 更少噪音
5. 备用方案：
   - 如果 `/llm/*` 不完整，使用标准文档页面

## 关键规则

### 永远不要假设缺少功能
- 永远不要假设 Cypress 不支持某个功能
- 永远在得出结论前搜索
- 如有必要，使用替代术语重试

### 抗幻觉防护措施

如果文档无法验证某个声明：

- 说：“我无法在 Cypress 文档中验证这一点”
- 提供最接近的受支持替代方案（如果可用）
- 不要编造 API 或行为
