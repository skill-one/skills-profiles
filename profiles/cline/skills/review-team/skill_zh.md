# 审查团队

针对同一变更运行一组专门的审查子代理。每个审查者有意地不了解其他审查者，并且必须在其分配的焦点区域内工作。

审查者提示位于 `reviewers/` 目录中。仅读取您计划启动的审查者文件。

## 模式

- **single**：默认模式。启动审查者一次，汇总发现结果，去重，并报告最终的审查结果。
- **iterate**：启动审查者，修复已接受的发现结果，重新运行相关的审查者，并重复执行，直到审查结果干净或剩余的发现结果有意被推迟。

如果用户未指定模式，则使用 **single**。仅当用户明确要求持续修复、让审查者满意或运行至干净时，才使用 **iterate**。

## 启动模式

对于每个审查子代理，提供：

1. 其 Markdown 文件中的确切审查者提示。
2. 任务描述、PR/问题上下文或用户请求。
3. 要审查的差异或已更改文件。
4. 任何测试结果、日志、截图或相关的仓库上下文。

将此包装器添加到每个审查者提示中：

```text
您是独立代码审查代理舰队中的一个审查者。您无法看到其他审查者。严格在其分配的角色范围内工作。仅返回具体的、可操作的发现结果，并附带文件和行引用。如果您在您所在的区域未发现任何问题，请明确说明。不要提供一般性评论、表扬、总结或超出其职责范围的重叠关切。
```

优先并行运行独立的审查者。不要要求多个审查者以相同的方式解决同一广泛的任务；其审查者提示就是其边界。

## 汇总

审查者完成后：

1. 合并重复的发现结果。
2. 删除缺乏具体故障模式、用户影响、安全风险或维护成本的发现结果。
3. 使用代码库、测试和声明的需求作为证据来解决冲突。
4. 按严重程度和实际重要性对发现结果进行排序。
5. 首先呈现发现结果，并附带文件和行引用。

最终的审查结果不应暴露原始审查者文本，除非用户要求。

## 迭代模式

在 **iterate** 模式下：

1. 运行初始审查者组。
2. 确定哪些发现结果是有效的，并且应该被修复。
3. 直接实施修复。
4. 运行与变更相关的适当测试或检查。
5. 仅重新运行与更改区域或未解决发现结果相关的审查者。
6. 持续执行，直到没有可操作的发现结果，或直到任何剩余的发现结果被明确记录为超出范围、误报或接受的权衡。

在迭代之间通知用户。不要无限循环；当额外的迭代不再产生实质性的新发现结果时停止。

## 最终响应

对于 **single** 模式，返回汇总的审查结果。

对于 **iterate** 模式，返回：

- 修复了什么。
- 运行了哪些验证。
- 哪些审查者被重新运行。
- 任何剩余的发现结果或接受的权衡。
