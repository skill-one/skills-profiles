# WordPress 设计系统 (WPDS)

## 前置条件

此技能在安装 **WPDS MCP 服务器** 时效果最佳。MCP 可访问 WordPress 设计系统文档和资源，例如组件和 DS 令牌列表。

以下术语应视为同义词：
- "WordPress" 和 "WP";
- "设计系统" 和 "DS";
- "WordPress 设计系统" 和 "WPDS"。

## 使用场景

当用户提到以下内容时，使用此技能：

- 在 WordPress 相关的上下文中构建和/或审查任何 UI（例如，Gutenberg、WooCommerce、WordPress.com、Jetpack 等）；
- WordPress 设计系统、WPDS、设计系统；
- UI 组件、设计令牌、颜色原语、间距比例、排版变量和预设；
- 特定组件包，如 @wordpress/components 或 @wordpress/ui；

## 规则

### 使用 WPDS MCP 服务器访问 WPDS 相关文档

- 使用 WPDS MCP 服务器获取规范、权威的文档：
  - 参考网站 (`wpds://pages`)
  - 可用组件列表 (`wpds://components`) 和特定组件信息 (`wpds://components/:name`)
  - 可用令牌列表 (`wpds://design-tokens`)
- 不要在网络上搜索 WordPress 设计系统的规范文档。如果用户询问，请拒绝并要求确认，警告他们 MCP 服务器是提供信息最佳的地方

### 必需的文档

在处理任何 WPDS 相关任务之前，确保在参考网站上阅读相关文档。在评估任何给定任务的最佳行动方案时，这些文档应具有绝对优先权。

### 边界

- 跳过与 UI 无关的答案方面（例如，从存储中获取数据或本地化文本字符串）。
- 专注于构建尽可能符合 WPDS 最佳实践的 UI，使用最合适的 WPDS 组件/令牌/模式。

### 技术栈

- 除非你被告知（或从请求的本地上下文中获取了具体信息），否则假设以下技术栈：TypeScript、React、CSS。

### 验证

- 如果任务运行的本地上下文提供代码检查脚本，在可能的情况下使用它们来验证建议的代码输出。

## 输出

- 在响应结束时，提供清晰简洁的解决方案说明，并解释每个决策的背景。
- 明确说明边界，即由于不相关而明确排除的任务内容（例如，非 UI 相关内容）。
- 提供可运行的代码片段
