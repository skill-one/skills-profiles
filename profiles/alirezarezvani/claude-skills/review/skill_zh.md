# 审查 Playwright 测试

系统性地审查 Playwright 测试文件中的反模式、遗漏的最佳实践和覆盖率缺口。

## 输入

`$ARGUMENTS` 可以是：
- 文件路径：审查该特定测试文件
- 目录：审查该目录中的所有测试文件
- 空值：审查项目 `testDir` 中的所有测试

## 步骤

### 1. 收集上下文

- 读取 `playwright.config.ts` 获取项目设置
- 列出范围内的所有 `*.spec.ts` / `*.spec.js` 文件
- 如果审查单个文件，还需检查相关的页面对象和固定装置

### 2. 检查每个文件的反模式

从本技能目录加载 `anti-patterns.md`。检查所有 20 种反模式。

**关键（必须修复）：**
1. `waitForTimeout()` 的使用
2. 非网页优先断言（`expect(await ...)`)
3. 使用硬编码 URL 而不是 `baseURL`
4. 存在基于角色的选择器时使用 CSS/XPath 选择器
5. Playwright 调用缺少 `await`
6. 测试之间共享可变状态
7. 测试执行顺序依赖

**警告（建议修复）：**
8. 超过 50 行的测试（考虑拆分）
9. 没有命名常量的魔法字符串
10. 缺少错误/边界情况测试
11. 使用 `page.evaluate()` 做定位器能做的事
12. `test.describe()` 嵌套超过 2 层
13. 通用测试名称（"应该工作"、"测试 1"）

**信息（考虑）：**
14. 具有 5+ 定位器的页面没有页面对象
15. 使用内联测试数据而不是工厂/固定装置
16. 缺少可访问性断言
17. UI 密集型页面没有视觉回归测试
18. 未检查控制台错误断言
19. 使用网络空闲等待而不是特定断言
20. 缺少 `test.describe()` 分组

### 3. 为每个文件评分

根据以下标准评分 1-10：
- **9-10**： 生产就绪，遵循所有黄金规则
- **7-8**： 良好，有小的改进空间
- **5-6**： 功能性但有反模式
- **3-4**： 存在严重问题，可能不稳定
- **1-2**： 需要重写

### 4. 生成审查报告

对每个文件：
```
## <filename> — 评分：X/10

### 关键
- 第 15 行：`waitForTimeout(2000)` → 使用 `expect(locator).toBeVisible()`
- 第 28 行：CSS 选择器 `.btn-submit` → `getByRole('button', { name: "submit" })`

### 警告
- 第 42 行：测试名称 "test login" → "登录后应重定向到仪表板"

### 建议
- 考虑添加错误案例：无效凭证会发生什么？
```

### 5. 项目级审查

如果审查整个测试套件：
- 为每个文件启动子代理进行并行审查（最多 5 个并发）
- 或使用 `/batch` 处理非常大的套件
- 将结果汇总到摘要表中

### 6. 提供修复方案

对每个关键问题，提供修正后的代码。询问用户："应用这些修复？[是/否]"

如果用户选择是，使用 `Edit` 工具应用所有修复。

## 输出

- 按文件分的评分审查
- 摘要：总文件数、平均分、关键问题数量
- 可操作的修复列表
- 覆盖率缺口（无测试的页面/功能）
