# 研究摘要工具

> 少读多懂，正确引用。

结构化的研究摘要工作流，将密集的原始材料转化为可操作的简报。专为产品经理、分析师、创始人以及阅读量远超所需的人士打造。

不是通用的“摘要这个”——而是可重复的框架，提取关键信息，跨来源比较，并正确格式化引用。

---

## 范围——与研究/领域区别

此技能摘要用户**已拥有的文档**（论文、文章、报告，粘贴或附加）。它不进行网络搜索，也不需要MCP服务器。它**不是**：

- `research/litreview` — 学术文献*发现*和综述指南生成（通过Consensus/学术API查找论文）
- `research/dossier` — 基于实时网络研究的实体尽职调查
- `research/notebooklm` — 驱动Google的NotebookLM产品界面
- `research/research` — 开放式“研究[主题]”请求的路径，需要搜索

如果用户要求你*查找*来源而不是消化提供的材料，请转至研究/领域。

---

## 此技能何时激活

识别用户的以下模式：

- “摘要这篇论文/文章/报告”
- “这份文档的关键发现是什么？”
- “比较这些来源”
- “从这份PDF中提取引用”
- “给我关于[主题]的研究简报”
- “拆解这份白皮书”
- 任何涉及：摘要、研究简报、文献综述、引用、来源比较的请求

如果用户有文档并希望结构化理解→此技能适用。

## 工作流

### 工作流1——单一来源摘要

1. **识别来源类型**
   - 学术论文 → 使用IMRAD结构（引言、方法、结果、分析、讨论）
   - 网页文章 → 使用主张-证据-启示结构
   - 技术报告 → 使用执行摘要结构
   - 文档 → 使用参考摘要结构

2. **构建简报框架** — `python3 scripts/format_summary.py --template academic`（或`article`/`report`/`executive`根据来源类型），然后从来源填充每个部分：
   ```
   标题：[准确标题]
   作者：[姓名]
   日期：[发布日期]
   来源类型：[论文 | 文章 | 报告 | 文档]

   ## 核心论点
   [1-2句话：中心论点或发现]

   ## 关键发现
   1. [带支持证据的发现]
   2. [带支持证据的发现]
   3. [带支持证据的发现]

   ## 方法论
   [他们如何得出这些发现——数据来源、样本量、方法]

   ## 局限性
   - [来源未涵盖或出错的内容]

   ## 可操作的要点
   - [如何利用这些信息]

   ## 值得注意的引言
   > "[直接引言]" (第X页)
   ```

3. **评估质量**
   - 来源可信度（同行评审、信誉良好的渠道、原始与二手）
   - 证据强度（数据支持、轶事、理论）
   - 时效性（何时发布，是否仍然相关？）
   - 偏见指标（资金来源、作者隶属关系、方法差距）

### 工作流2——多来源比较

1. **收集来源**（2-5份文档）
2. **使用上述单一来源工作流**分别摘要
3. **构建比较矩阵**

   ```
   | 维度        | 来源A        | 来源B        | 来源C        |
   |-------------|-------------|-------------|-------------|
   | 核心论点   | ...         | ...         | ...         |
   | 方法论      | ...         | ...         | ...         |
   | 关键发现    | ...         | ...         | ...         |
   | 样本/范围   | ...         | ...         | ...         |
   | 可信度      | 高/中/低    | 高/中/低    | 高/中/低    |
   ```

4. **综合**
   - 来源在哪里达成一致？（趋同发现 = 更强的信号）
   - 他们在哪里存在分歧？（分歧发现 = 需要调查）
   - 所有来源中存在哪些差距？
   - 每个立场证据的权重是什么？

5. **生成综合简报**
   ```
   ## 趋同发现
   [大多数来源同意的内容]

   ## 争议点
   [来源存在分歧，每方最强证据]

   ## 差距
   [没有来源涉及的内容]

   ## 建议
   [基于证据权重，读者应该相信/做什么？]
   ```

### 工作流3——引用提取

1. **运行提取器** — `python3 scripts/extract_citations.py document.txt --output json`检测DOI/URL/作者年份/编号引用并去重
2. **审查和格式化**提取的列表，按请求的样式（APA 7默认）；手动捕获正则表达式遗漏的引用
3. **按类型分类引用**：
   - 原始来源（原始研究、数据）
   - 二手来源（综述、元分析、评论）
   - 三级来源（教科书、百科全书）
4. **输出**按分类标签排序的参考文献

支持的引用格式：
- **APA 7**（默认）— 社会科学、商业
- **IEEE** — 工程、计算机科学
- **芝加哥** — 人文、历史
- **哈佛** — 一般学术
- **MLA 9** — 艺术、人文

## 工具

### `scripts/extract_citations.py`

用于从文本中提取和格式化引用的命令行工具。

**功能：**
- 基于正则表达式的引用检测（DOI、URL、作者年份、编号参考文献）
- 多种输出格式（APA、IEEE、芝加哥、哈佛、MLA）
- 用于与参考文献管理器集成的JSON导出
- 重复引用的去重

**用法：**
```bash
# 从文件提取引用（APA格式，默认）
python3 scripts/extract_citations.py document.txt

# 指定格式
python3 scripts/extract_citations.py document.txt --format ieee

# JSON输出
python3 scripts/extract_citations.py document.txt --format apa --output json

# 从标准输入
cat paper.txt | python3 scripts/extract_citations.py --stdin
```

### `scripts/format_summary.py`

命令行工具，发出**空的结构化摘要框架**——你（模型）从来源中填充它们。它本身不分析内容。

**功能：**
- 6个模板：学术、文章、报告、执行、比较、文献
- 可配置的框架深度（简报、标准、详细）
- 用于下游工具的文本和JSON输出

**用法：**
```bash
# 生成结构化摘要模板
python3 scripts/format_summary.py --template academic

# 简要执行摘要格式
python3 scripts/format_summary.py --template executive --length brief

# 列出所有模板
python3 scripts/format_summary.py --list-templates

# JSON输出
python3 scripts/format_summary.py --template article --output json
```

## 质量评估框架

对每个来源在四个维度上评分：

| 维度 | 高 | 中 | 低 |
|------|----|----|----|
| **可信度** | 同行评审、知名作者 | 信誉良好的渠道、知名作者 | 博客、未知作者、无评审 |
| **证据** | 大样本、严谨方法 | 中等数据、合理方法 | 轶事、无数据、观点 |
| **时效性** | 2年内发布 | 2-5年旧 | 5年以上，可能过时 |
| **客观性** | 无冲突、平衡观点 | 微小隶属关系披露 | 资助方有利益关系、片面 |

**整体评分：**
- 4个高 = 强来源——有信心引用
- 2个中 = 足够来源——引用时需谨慎
- 2个低 = 弱来源——引用前需独立核实

## 主动触发

无需被要求就标记：

- **来源无日期** → 记录。无日期来源会失去可信度分。
- **来源与其他来源矛盾** → 明确突出矛盾。不要掩盖分歧。
- **来源在付费墙后** → 记录有限访问。如果知道，建议替代方案。
- **用户为比较只提供了一个来源** → 要求至少再提供一个。比较需要2+。
- **引用不完整** → 标记缺失字段（年份、作者、标题）。不要编造元数据。
- **在快速发展的领域，来源是5年以上** → 警告可能过时。

## 验证循环

在交付任何简报前检查：

1. 每个关键发现都引用了来源中的位置（章节、页码或引言）——没有无锚点的断言。
2. `python3 scripts/extract_citations.py <file> --output json`退出状态为0，其`total`与输出中的参考文献计数匹配（调查任何差距）。
3. 每个来源都有4维质量评分（上表）；弱来源被标记，不会被无声包含。
4. 对于比较：矩阵每行对应一个维度，每列对应一个来源——没有来源被遗漏。
5. 什么都没编造：缺失元数据标记为“未说明”，从不填充。
