# 分析测试覆盖率缺口

映射应用程序中所有可测试的表面，并识别已测试内容与缺失内容。

## 步骤

### 1. 映射应用表面

使用 `Explore` 子代理来分类：

**路由/页面：**
- 扫描路由定义（Next.js `app/`、React Router 配置、Vue Router 等）
- 列出所有面向用户的页面及其路径

**组件：**
- 识别交互式组件（表单、模态框、下拉菜单、表格）
- 记录具有复杂状态逻辑的组件

**API 端点：**
- 扫描 API 路由文件或后端控制器
- 列出所有端点及其方法

**用户流程：**
- 识别关键路径：认证、结账、入职、核心功能
- 映射多步骤工作流

### 2. 映射现有测试

扫描所有 `*.spec.ts` / `*.spec.js` 文件：

- 提取哪些页面/路由已被覆盖（通过 `page.goto()` 调用）
- 提取哪些组件已被测试（通过定位器使用）
- 提取哪些 API 端点被模拟或调用
- 按区域统计测试数量

### 3. 生成覆盖率矩阵

```
## 覆盖率矩阵

| 区域 | 路由 | 测试 | 状态 |
|---|---|---|---|
| 认证 | /login | 5 | ✅ 已覆盖 |
| 认证 | /register | 0 | ❌ 缺失 |
| 认证 | /forgot-password | 0 | ❌ 缺失 |
| 仪表盘 | /dashboard | 3 | ⚠️ 部分覆盖（无错误状态） |
| 设置 | /settings | 0 | ❌ 缺失 |
| 结账 | /checkout | 8 | ✅ 已覆盖 |
```

### 4. 优先级排序缺口

按业务影响对未覆盖区域进行排序：

1. **关键** — 认证、支付、核心功能 → 优先测试
2. **高** — 面向用户的 CRUD、搜索、导航
3. **中** — 设置、偏好设置、边缘情况
4. **低** — 静态页面、关于、条款

### 5. 建议测试计划

针对每个缺口，建议：
- 需要的测试数量
- 使用 `templates/` 中的哪个模板
- 预计工作量（快速/中等/复杂）

```
## 推荐测试计划

### 优先级 1：关键
1. /register (4 个测试) — 使用认证/注册模板 — 快速
2. /forgot-password (3 个测试) — 使用认证/密码重置模板 — 快速

### 优先级 2：高
3. /settings (4 个测试) — 使用设置/模板 — 中等
4. 仪表盘错误状态 (2 个测试) — 使用仪表盘/数据加载模板 — 快速
```

### 6. 自动生成（可选）

询问用户："为前 N 个缺口生成测试？[是/否/选择特定]"

如果选择是，则对每个缺口使用推荐的模板调用 `/pw:generate`。

## 输出

- 覆盖率矩阵（表格格式）
- 覆盖率百分比估计
- 带工作量估计的优先级缺口列表
- 自动生成缺失测试的选项
