## 工作流程

1. 识别缺少或错误的元数据页面（标题、描述、规范、OG标签）
2. 根据以下优先级规则进行审核——优先修复关键问题（重复、索引）
3. 确保标题、描述、规范和og:url彼此一致
4. 验证社交卡片在真实URL上正确渲染，而不是在localhost上
5. 保持差异最小化，仅限于元数据——不要重构无关代码
## 何时应用

在以下情况下参考这些指南：
- 添加或更改页面标题、描述、规范、robots
- 实现Open Graph或Twitter卡片元数据
- 设置favicon、应用图标、manifest、theme-color
- 构建共享SEO组件或布局元数据默认值
- 添加结构化数据（JSON-LD）
- 更改区域设置、替代语言或规范路由
- 发布新页面、营销页面或可分享链接

## 按优先级分类的规则类别

| 优先级 | 类别 | 影响 |
|--------|------|------|
| 1 | 正确性和重复 | 关键 |
| 2 | 标题和描述 | 高 |
| 3 | 规范和索引 | 高 |
| 4 | 社交卡片 | 高 |
| 5 | 图标和manifest | 中 |
| 6 | 结构化数据 | 中 |
| 7 | 区域设置和替代 | 低-中 |
| 8 | 工具边界 | 关键 |

## 快速参考

### 1. 正确性和重复（关键）

- 每个页面在单一位置定义元数据，避免竞争系统
- 不要发出重复的标题、描述、规范或robots标签
- 元数据必须是确定性的，没有随机或不稳定的值
- 转义和清理任何用户生成或动态字符串
- 每个页面必须有标题和描述的安全默认值

### 2. 标题和描述（高）

- 每个页面必须有标题
- 在整个网站中使用一致的标题格式
- 保持标题简短易读，避免堆砌
- 可分享或可搜索的页面应有meta描述
- 描述必须是纯文本，没有markdown或引号垃圾

### 3. 规范和索引（高）

- 规范必须指向页面的首选URL
- 仅对私有、重复或非公开页面使用noindex
- robots meta必须与实际访问意图匹配
- 预览或预发布页面在可能的情况下应默认为noindex
- 分页页面必须有正确的规范行为

### 4. 社交卡片（高）

- 可分享的页面必须设置Open Graph标题、描述和图像
- Open Graph和Twitter图像必须使用绝对URL
- 优先使用正确的图像尺寸和稳定的宽高比
- og:url必须与规范URL匹配
- 使用合理的og:type，通常是网站或文章
- 适当设置twitter:card，默认为summary_large_image

### 5. 图标和manifest（中）

- 至少包含一个跨浏览器兼容的favicon
- 在相关情况下包含apple-touch-icon
- manifest必须是有效的，并在使用时引用
- 有意设置theme-color以避免不匹配的UI边框
- 图标路径应该是稳定的和可缓存的

### 6. 结构化数据（中）

- 除非它明确映射到实际页面内容，否则不要添加JSON-LD
- JSON-LD必须有效，并反映实际渲染的内容
- 不要编造评分、评论、价格或组织详细信息
- 除非需要，否则每个页面优先使用一个结构化数据块

### 7. 区域设置和替代（低-中）

- 正确设置html lang属性
- 当存在本地化时设置og:locale
- 只有当页面真正存在时才添加hreflang替代
- 本地化页面必须按区域正确规范化

### 8. 工具边界（关键）

- 优先进行最小化更改，不要重构无关代码
- 除非要求，否则不要迁移框架或SEO库
- 遵循项目的现有元数据模式（Next.js元数据API、react-helmet、手动head等）

## 审核指南

- 首先修复关键问题（重复、规范、索引）
- 确保标题、描述、规范和og:url一致
- 在真实URL上验证社交卡片，而不是在localhost上
- 优先使用稳定、无聊的元数据而不是聪明或动态的
- 保持差异最小化，仅限于元数据
