# 对票证

将计划/规范/对话拆分为**票证**——追踪子弹式垂直切片，每个切片声明会**阻塞**它的票证。按照每个消费者存储库的追踪器约定发布（AGENTS.md）。

## 可重现性不变量

> 完整的问题集，按依赖顺序重放——无论是功能还是修复程序——都必须构建出大致相同的应用程序，无论由谁或什么实现。

问题流 = 可构建的规范。以下每条规则都是为了这个目标服务。

### 自包含性

每个塑造结果的决定都存在于**问题本身**中，或它引用的持久文档中——架构决策记录（`writing-adrs`），术语表条目（`docs/glossary/`）。绝不依赖对话上下文、部落知识、实现者酌情处理。

**测试标准：**两个独立的实现者可以构建有意义的不同事物→票证定义不明确。将决策添加到票证中，或记录为架构决策记录/术语表条目并引用。

### 新词汇

引入领域概念的票证在`## 引入`下声明它——每行一个缩写，每个都**像术语文件已经存在一样链接**（`docs/glossary/<缩写>.md`，链接如存在约定）。实现创建文件；在此之前，`--lint`报告损坏的交叉引用——这就是强制执行，而不是错误。列表 = 票证添加的词汇的持久记录。

### 修复程序 = 规范更正

绝不修补指令（“在文件Z中将Y更改为X”）。将状态更正到规范流：

- *问题N暗示X；实现做了Y；X正确。* — 或
- *问题N指定Y；Y错误；X′现在正确。*

重放然后直接构建X，而不是错误+修补。修复程序揭示了规范级别的决策→架构决策记录+从问题中引用。

### 完成时的协调

票证未完成，直到它反映了构建的内容。在关闭之前：将偏差、会话期间的范围、决策折叠回问题（或其架构决策记录/术语表引用）。否则重放构建的是初稿，而不是最终状态。`documenting-decisions`任务步骤后执行此操作。

## 审查门

票证是承重结构。在上下文中没有审查会话（`docs/glossary/grilling-session.md`）→停止，询问用户：“未找到审查会话——真的跳过？”仅在明确确认的情况下继续；在父问题/PR中记录跳过。

## 流程

### 1. 汇总上下文

从对话上下文中工作。用户传递引用（规范路径、问题编号/URL）→获取，阅读完整正文+评论。

### 2. 探索代码库（可选）

理解当前代码状态。标题/描述使用术语表词汇（`uvx disambiguate <术语>`）；尊重触及区域的架构决策记录。

寻找重构机会。“让更改变得容易，然后让容易的更改。”

### 3. 起草垂直切片

将工作拆分为**追踪子弹**票证：

- 每个切片：狭窄但完整的通过每一层（模式、API、UI、测试）的路径（垂直，不是某一层的水平切片）
- 完成的切片可以单独演示/验证
- 尺寸适合一个新鲜上下文窗口
- 优先重构

每个票证声明**阻塞边**——必须首先完成的票证。无阻塞→立即开始。

对每个草稿应用测试标准：草拟决策（接口、命名、顺序权衡）进入票证正文、架构决策记录或术语表条目——按`documenting-decisions`标记。

**宽泛的重构：垂直切片的例外。**一个机械更改（重命名列、重新类型共享符号），**影响范围**跨越代码库——单个编辑破坏数千个调用点，没有切片变绿。按**扩展-收缩**顺序。扩展：在旧形式旁边添加新形式，什么都不会破坏。迁移：按影响范围分批（按包/目录）迁移调用点，每个批次有自己的票证被扩展阻塞——CI保持绿色，旧形式仍然存在。收缩：在没有任何调用者剩余时删除旧形式，被每个批次阻塞。批次不能单独保持绿色→保持顺序，共享集成分支，所有票证阻塞最终集成和验证票证——只有在那里才承诺变绿。

### 4. 询问用户

编号列表。每个票证：

- **标题**：简短名称
- **被阻塞**：门控票证，如果有
- **交付内容**：端到端行为使其工作

询问：

- 粒度正确吗？（太粗/细）
- 阻塞边正确——只有真正的门控？
- 合并或拆分任何？
- 任何票证未通过测试标准——决策仍然只在对话中？

迭代直到批准。

### 5. 发布

每个票证一个问题，依赖顺序（阻塞的首先）→边引用真实问题编号。在跟踪器有原生阻塞关系的地方，否则“被阻塞”部分。应用`ready-for-agent`标签，除非被告知否则——票证按构造可被代理抓取。

工作**前沿**：所有阻塞都完成的任何票证。线性链→从上到下。

**不要关闭/修改父问题。**

问题模板：

```markdown
## 父问题

指向父问题的引用（如果源不是问题，则省略）。

## 要构建的内容

端到端行为，用户的角度——不是逐层实现。

## 决策

每个塑造结果的决定，声明或引用（架构决策记录/术语表）。修复程序：规范更正声明。仅当确实没有时才省略。

## 接受标准

- [ ] 标准1
- [ ] 标准2

## 引入

- [缩写](docs/glossary/缩写.md) — 一行含义。如果没有新术语则省略。

## 被阻塞

- 每个阻塞票证的引用，或“无——可以立即开始”。

```

票证文本：尽可能简短，原始人模式首选（`caveman`技能）——精确性和可理解性必须不受影响。

无文件路径/代码片段——过时快。例外：原型片段比文本更精确地编码决策（状态机、reducer、模式、类型形状）→内联，注明原型来源，修剪到决策丰富的部分。

一次处理一个票证，在票证之间清除上下文。
