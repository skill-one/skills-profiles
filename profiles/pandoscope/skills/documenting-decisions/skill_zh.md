# 记录决策

## 检查点标签

| 标签     | 标记时机                                                                                          |
| ------- | ----------------------------------------------------------------------------------------------------- |
| `ARCH`  | 新的抽象、依赖、数据模型、组件边界——任何塑造长期结构的内容。 |
| `SCOPE` | 你通过选择一种解释来解决任务中的歧义。                                  |
| `IFACE` | 修改了公共 API、配置模式、CLI 标志、环境变量或线路格式。                               |
| `SEC`   | 涉及认证、加密、权限、网络暴露或输入验证。                             |
| `IRREV` | 创建了迁移、数据删除、部署触发器或外部副作用。                      |
| `NOVEL` | 没有现有的仓库模式可供遵循——你从训练数据中推断。                             |

不要标记常规变更（模式遵循、样板代码、重构）。

## 格式

参考此技能的 `references/` `decision-markers.md`（如有需要）和 `marker-examples.md`。

## 任务完成后

从变更文件中的标记生成决策日志并添加到 PR 描述中：

```markdown
## 需要审查的决策
- **TAG** `文件:行号` — 解释
## 常规（跳过审查）
[一句话总结]
```

如果 `ARCH` 或 `IRREV` 标签符合 `writing-adrs` 标准（难以逆转、没有上下文会令人惊讶、是真实权衡的结果），则根据该技能编写 ADR。

### 协调驱动工单

由工单驱动的任务 → 在关闭前更新它：合并偏差、会话中途的范围、上述决策（或其 ADR/词汇表引用）。根据 `to-tickets` 可重现性不变量：重播问题流构建最终状态，而不是初稿。

## 差分分类模式

当用户请求审查差分时，将每个代码块分类为六个标签之一或 `ROUTINE`。以 `文件: 路径 — 标签` 的形式呈现，并附带行号范围。
