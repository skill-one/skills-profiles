# Paseo Advisor

单一代理。读取你当前所处的情境。给出判断。你决定要做什么——顾问不会驱动工作。

**用户请求：** $ARGUMENTS

## 前置条件

阅读 **paseo** 技能。选择顾问前调用 `list_profiles`。在创建顾问之前，务必阅读配置的配置文件及其 `notes`。

## 选择顾问

1. **用户命名了一个配置文件** (`--profile UI Work`) → 通过名称选择它。
2. **否则** 选择其 `notes` 最符合问题的配置文件。匹配实际工作：设计和方法、审计和审查，或研究和根本原因分析。
3. **对比有助于决策。** 当多个配置文件符合条件时，优先选择与自身不同的提供者系列，以便第二意见真正新鲜。

按照 **paseo** 技能的描述，将选定的配置文件实例化为 `create_agent`。如果没有配置文件符合条件，使用 Paseo 的提供者发现后备方案。

## 简报

顾问没有上下文。使其自包含：

- 问题，明确地。
- 你已经考虑过和已经排除的内容。
- 相关文件通过路径（不要粘贴——让代理读取）。
- 明确请求： "给我一个建议，并说明理由。"

以不编辑的后缀结束：

```
仅进行分析。请勿编辑、创建或删除任何文件。请勿编写代码。
```

## 转发技能

如果 `$ARGUMENTS` 包含另一个技能引用——`/unslop`、`/unslop-risk`、`$unslop` 等——用户要求顾问针对当前任务运行该技能。示例：

- `/paseo-advisor /unslop` → 顾问在当前差异上运行 `/unslop`。
- `/paseo-advisor /unslop-risk` → 顾问进行 unslop-risk 审查。
- `/paseo-advisor $diagnose this build failure` → 顾问调用 `/diagnose`。

从 `$ARGUMENTS` 中解析转发技能名称（`/<name>` 或 `$<name>`）。在简报中，明确告诉顾问：

```
针对此任务调用 `<name>` 技能。在执行任何其他操作之前，通过技能工具加载它。
```

在技能名称之后传递任何剩余参数作为技能自身的输入。顾问——而不是你——运行技能；你仍然只是协调者，将其交给工作。

## 启动和综合

使用 Paseo 以 `[Advisor] <topic>` 标题创建顾问代理，并将简报作为初始提示。等待其完成。阅读其响应。为用户综合——顾问的裁决 + 你的建议。

## 持久顾问

如果用户希望持续输入（“保留此顾问用于接下来的几个决策”），在第一次回复后不要存档。当你需要另一个意见时发送跟进。当用户表示完成时，或当主题转移且新的上下文会更好时存档。
