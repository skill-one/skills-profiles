# Paseo Loop 技能

循环是一个工作/验证的循环：启动一个工作器 → 检查验证 → 重复直到完成或达到限制。用于“持续尝试”、“照看”或“监视直到 X”。

对于需要返回到同一对话的轻量级周期性检查，优先使用 cron 心跳（使用 `create_heartbeat` 创建，完成后使用 `delete_heartbeat` 删除）。要更改它，请删除并重新创建它。当每次迭代都需要一个工作器/验证器生命周期时，使用循环；当每次触发都应该创建一个全新的独立代理和工作区时，使用计划。

**用户的参数：** $ARGUMENTS

## 前置条件

阅读 **paseo** 技能。在选择工作器或验证器提供者之前，除非用户在此请求中明确指定了提供者，否则请阅读 `~/.paseo/orchestration-preferences.json`。在读取它之前，不要启动循环。

循环是一个 CLI 原语：`paseo loop run`。使用 `paseo loop ls`、`paseo loop inspect <id>`、`paseo loop logs <id>`、`paseo loop stop <id>` 进行管理。

## 你的任务

1. 从 `$ARGUMENTS` 和对话中理解用户的意图。
2. **工作器提示** — 自包含、具体说明本次迭代要做什么，明确说明什么算作进度。
3. **验证** — 选择正确的形状：
   - Shell 检查 (`--verify-check`) 用于命令可以回答的客观标准 (`gh pr checks --fail-fast`、`npm test`)。
   - 验证器提示 (`--verify`) 用于判断（“只有在所有测试通过且更改的文件一致时才返回 done=true。引用命令和结果。”）。
   - 两者，当 Shell 排除了明显的失败，而验证器判断其余部分时。
4. **提供者** — `--provider` 用于工作器，`--verify-provider` 用于验证器。从偏好设置中获取，除非用户在此请求中指定了它们。对于实现循环，将工作器和验证器配对在不同的提供者上 — 每个都能捕捉到对方的盲点。
5. **休眠** — `--sleep` 仅在轮询外部内容时使用。否则让循环尽可能快地完成。
6. **停止** — 设置一个合理的 `--max-iterations` 和/或 `--max-time`。无限制的循环是导致失控的原因。
7. **存档** — `--archive` 在每次迭代后保留代理以供检查。
8. 使用 `paseo loop run` 启动。

## 常见形状

**照看一个 PR** — 工作器检查 PR 状态并修复问题；Shell 检查是 `gh pr checks <n> --fail-fast`；休眠 2m；最大时间 1h。

**驱动测试变为绿色** — 工作器调查失败并修复代码；Shell 检查是测试命令；验证器确认所有测试通过；最大迭代次数 10。

**跨提供者实现** — 工作器在 `impl` 提供者上，验证器在另一个提供者上；验证器检查更改的文件，运行类型检查和测试；最大迭代次数和最大时间都有限制；存档以便迭代可以被检查。

## 提示规则

**工作器** — 自包含、具体（命令、文件、分支、测试、PR、系统），明确说明本次迭代什么算作进度。

**验证器** — 检查事实，不提出修复建议，引用命令/输出/文件证据，具体说明“完成”的含义。
