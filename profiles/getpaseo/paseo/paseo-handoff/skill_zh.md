# 交接技能

将当前任务——上下文、决策、失败尝试、约束条件——转移给一个新的代理。接收代理以**零上下文**开始，因此交接提示必须是一个自包含的简报。

**用户的参数：** $ARGUMENTS

## 前置条件

阅读**paseo**技能。在选择接收代理之前，调用`list_profiles`。在阅读配置的配置文件及其`notes`之前，不要创建它。

## 解析参数

1. **代理配置文件**——首先指定显式的配置文件名称；否则选择其`notes`与工作最匹配的配置文件。根据**paseo**技能的描述，将其实例化为`create_agent`。如果没有配置文件匹配，则使用Paseo的提供者发现回退。
2. **隔离**——"在一个工作树中" / "工作树" → 使用从任务派生出的短分支名称创建一个工作空间，使用`isolation: "worktree"`。
3. **任务描述**——用户说的任何其他内容。

## 交接提示

接收代理没有上下文。包括：

```
## 任务
[命令式描述。]

## 上下文
[为什么这个任务存在，所需的上下文。]

## 相关文件
- `path/to/file.ts` — [它是什么以及为什么它很重要]

## 当前状态
[已完成的工作，什么有效，什么无效。]

## 已尝试过的方法
- [方法] — [为什么它失败或被放弃]

## 决策
- [决策 — 原因]

## 接受标准
- [ ] [标准]

## 约束条件
- [必须不 / 必须保留]
```

**保留任务语义。** 仅调查 → "不要编辑文件。" 修复 → "实现修复。" 重构 → "重构，而不是重写。" 执行用户的精确意图。

## 启动

在一个专用工作空间中准备交接：

1. 选择当前工作空间或调用`create_workspace`使用请求的隔离。
2. 调用`create_agent`，使用`[Handoff] <任务>`标题，将简报作为初始提示，并在需要显式放置时使用选定的`workspaceId`。
3. 将代理和工作空间返回给用户，解释它将保留在你的子代理跟踪中，直到他们手动分离它。

不要将独立性编码为创建模式，也不要调用CLI或底层分离操作。分离是子代理跟踪中的用户手势。

不要等待或轮询代理完成。
