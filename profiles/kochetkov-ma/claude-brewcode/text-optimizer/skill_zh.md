## 文本优化器

在不丢失意义的情况下，将提示、文档和代理指令中的 token 数量减少 **20–40%**。
应用 **52 项基于研究的规则**，涵盖 8 个类别：Claude 行为、token 效率、结构、去重、引用完整性、感知、LLM 理解、激进的有损（仅深度）。

**优势：** 更低的 API 调用成本 · 更快的模型响应 · 更清晰的 LLM 指令 · 更少的幻觉

**示例：**
```bash
/text-optimize prompt.md          # 单个文件，中等模式（默认）
/text-optimize -d agents/         # 深度模式 — 目录中的所有 .md 文件
```

> _技能文本是为 LLM 消费而编写的，并针对 token 效率进行了优化。_

## 模式

解析 `$ARGUMENTS`：`-l`/`--light` | `-d`/`--deep` | 无标志 -> 中等（默认）。

| 模式 | 标志 | 范围 |
|------|------|-------|
| 轻量级 | `-l`, `--light` | 仅文本清理 — 结构、列表、流程保持不变 |
| 中等 | _(默认)_ | 平衡的重构 — 所有标准转换 |
| 深度 | `-d`, `--deep` | 最大密度 — 激进地改写、合并、压缩 |

## 模式-to-Rules Mapping

| 模式 | 应用 | 备注 |
|------|---------|-------|
| 轻量级 | C.1-C.8, T.6, D.1, R.1-R.3, P.1-P.4, L.1-L.8 | 仅文本清理 — 无重构 |
| 中等 | 所有规则 (C + T + S + D + R + P + L) | 平衡转换 |
| 深度 | 所有规则 (C + T + S + D + R + P + L) + A.1-A.4（激进的有损） | 合并章节，最大压缩 |

## 每种模式的损失预算

内容本质在轻量级/中等模式下不可更改；仅在深度模式下有小的有意损失 — 明确报告。去重合并的事实计为保留，永不计为损失。

| 模式 | 语义匹配目标 | 允许的损失 |
|------|----------------------|--------------|
| 轻量级 | 100% | 无 — 仅措辞清理 |
| 中等 | 100% | 无 — 自查事实清单，零损失 |
| 深度 | >= 95% | 低价值连接细节；需要自检轮次，如果 < 95% 则警告损失列表 |

## 去重过程（所有模式）

在分析期间运行，压缩之前：

1. 构建事实清单：每行一个原子事实，编号
2. 标记出现 2 次以上的事实（精确、改写或跨格式）
3. 对每个重复进行分类：有意强调（标记为关键/引用块，或开头+结尾三明治）与意外
4. 意外 -> 合并到最具体的单个声明（D.1-D.3），最佳位置获胜
5. 有意 -> 限制为 2：开头完整形式 + 结尾 <=1 行回声（D.4）
6. 错误合并保护（D.6）：不同范围/编号/条件 = 不是重复 — 保留两者

### 执行流程

1. 读取 `references/rules-review.md` — 加载所有优化规则
2. 读取目标文件
3. 分析：识别类型（提示、文档、代理、技能），注意关键信息和交叉引用
3a. 去重过程（D.1-D.6）：事实清单 -> 合并意外重复 -> 在每份文档中限制有意强调为 2
3b. 仅深度：激进的有损过程（A.1 融合 -> A.3 改写 -> A.2 词删除 -> A.4 省略）；A.2/A.4 删除 -> 损失账本；A.4 计为 `elided-known` 对 >=95% 门限，A.2 是门控中性的
4. 根据模式应用规则（见模式-to-Rules Mapping）
5. 使用优化内容编辑文件
5a. 中等：自检 — 重新检查输出中的事实清单，零损失要求
5b. 深度模式：自检 — 原始事实清单与压缩后的对比，(保留+合并)/总数 >= 95%；合并计为保留；如果低于则警告损失列表
6. 生成优化报告

## 反模式

| 避免 | 原因 |
|-------|-----|
| 删除所有示例 | 损害泛化能力 (P.1) |
| 过度缩写 | 降低可读性 (T.5 例外) |
| 通用压缩 | 领域术语很重要 |
| 过度激进的语言 | Opus 4.5 过度触发 (C.5) |
| 扁平化层次结构 | 丢失结构 (P.2) |
| "不要做 X" 措辞 | "做 Y" 更有效 (C.3) |
