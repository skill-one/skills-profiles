# SRED 项目组织

SRED 希望项目以特定格式呈现。取过去一年所参与的项目列表，并按照 SRED 所期望的格式进行总结，并提供支持性证据。输出一个 Notion 文档，其中每个 SRED 类项目都有一个子文档。

# 前置条件

开始之前，确保可以访问 Github、Notion 和 Linear。Notion 和 Linear 应该通过 MCP 连接。Github 可以通过 MCP 连接，但如果你可以访问 `gh` CLI 工具，你可以使用它。

如果其中任何一个无法访问，提示用户授予权限后再继续。

# 流程

## 第一步

提示用户输入一个 Notion 文档的链接，该文档是 `sred-work-summary` 技能生成的过去一年的工作总结。

确保：
- Notion 链接到一个有效的文档，大致匹配以下格式：

```markdown
# 项目

## [项目名称]
*总结*：[X] PRs，[X] Notion 文档，[X] Linear 工单

### 拉取请求 [X]
*[仓库名称]
[所有 PR 的链接]
- [链接] - [合并日期]

### Notion 文档 [X]
[所有 Notion 文档的链接]
- [链接] - [创建日期]

### Linear 工单 [X]
- [链接] - [创建日期]
```

## 第二步

对于工作总结中的每个项目，根据 `references/SRED.md` 中 SRED 项目的描述进行评估。这意味着查看项目的相关 Notion 文档和 PR，并确定项目工作是否像是一个有效的 SRED 项目。要明确：能够被归类为 SRED 项目的项目越多越好。

输出符合 SRED 模型描述的项目列表，以及不符合该模型的项目列表。符合 SRED 描述的项目列表被称为 "SRED 类项目"。

确保：
- 工作总结中的所有项目都已分类为 SRED 类或非 SRED 类。

## 第三步

询问用户 SRED 类项目列表是否正确。给他们手动分类任何项目为 SRED 类或非 SRED 类的选项，并相应地调整列表。

## 第四步

创建一个名为 "SRED 项目描述" 的私有 Notion 文档。输出此文档的完整链接。

## 第五步

对于每个 SRED 类项目，执行以下步骤。

*第一步*
创建一个名为 "SRED 项目总结 - <年份> <项目名称>" 的私有 Notion 文档，该文档是第 4 步创建的 "SRED 项目描述" 文档的子文档。该文档应遵循 `references/project-template.md` 中找到的模板。

*第二步*
填写该文档的 `项目描述` 和 `项目目标` 部分。使用文档中这些部分的 `aside` 部分作为提示，了解每个部分应包含的信息。使用工作总结中收集的所有项目信息。使用项目的 Notion 文档，以及你自己的推理来填写这些部分。

确保：
- 项目描述不应超过 100 字。
- 项目目标不应超过 100 字。

*第三步*
提供用户 "SRED 项目总结" 文档的完整 Notion 链接，并要求他们在继续之前进行审查。根据他们要求进行任何更改。

*第四步*
每个项目将有一个或多个不确定性。不确定性由以下问题定义：
- 我们遇到了哪些没有答案的挑战或问题？
- 是否有先例可以用于我们的问题解决？
- 如果没有，为什么？

审查所有项目的 Notion 文档、Github PR 和 Linear 工单。确定项目的 Uncertainties，并展示给用户。询问用户这些是否正确或需要以某种方式调整。

确保：
- 每个不确定性的描述应只有几句话长。

*第五步*
将不确定性添加到项目总结 Notion 文档的 "技术不确定性" 部分。

确保：
- 不确定性的描述应只有几句话长。

*第六步*
对于上述找到的每个不确定性，使用 Notion 文档、Github PR 和 Linear 工单查找任何解决此不确定性的实验或尝试。在不确定性对应的 `实验` 部分为每个实验制作一个项目符号列表。在 `结果 / 学习 / 成功` 部分制作一个项目符号列表，列出实验的结果，以及任何学习或结论。对于任何引用的 Notion 文档、Github PR 或 Linear 工单，将资源的链接放入不确定性的 `特定文档和链接` 部分。

确保：
- 每个实验只有一个项目符号。
- 每个结果/学习/成功只有一个项目符号。

*第七步*
取工作总结中找到的所有项目链接，对于任何未被作为不确定性链接的部分，将它们包含在项目总结的 `项目文档和链接` 部分。

确保：
- 提供所有具体链接的列表，而不是总结或 Github 通知的通用链接。
- 检查每个链接是否与项目及其不确定性直接相关。

*第八步*
再次提供用户项目总结文档的链接，并要求他们在继续到下一个 SRED 类项目之前进行审查。提醒用户填写文档的参与者部分。

## 第六步

提供 "SRED 项目描述" Notion 文档的链接。
