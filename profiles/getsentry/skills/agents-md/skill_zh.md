# 维护 AGENTS.md

目标：简洁、可操作的代理指令。目标行数少于60行；不超过100行。

## 工作流程

1. 写作前检查：
   - 包管理器：锁文件和清单
   - 命令：`package.json`、`Makefile`、任务运行器、CI工作流
   - 文档/规范/政策：`README.md`、`CONTRIBUTING.md`、`docs/`、`specs/`、`policies/`、`SECURITY.md`、`.github/`
   - 习惯：当前代码模式、测试布局、生成文件、避免的遗留区域
2. 选择范围：
   - 根目录 `AGENTS.md`：仓库级默认值
   - 嵌套 `AGENTS.md`：仅当子树有不同命令或规则时使用
   - 最接近的指令文件优先；保持较窄的文件比根文件短
3. 写最小的有用文件。
4. 验证确切路径和命令是否存在。

## 文件设置

- 在仓库根目录创建 `AGENTS.md`。
- 如果需要Claude兼容的入口点，将 `CLAUDE.md` 符号链接到 `AGENTS.md`。
- 不要维护不同的 `AGENTS.md` 和 `CLAUDE.md` 复本。

## 写作规则

- 使用标题、项目符号和表格；避免段落。
- 使用仓库相对路径；避免模糊的引用，如“见文档”。
- 引用现有的文档/规范/政策，而不是复制它们。
- 列出确切的外部文件，用于设置、架构、API规范、安全、发布和政策文档（如果存在）。
- 优先使用文件范围的测试/代码检查/类型检查命令；仅在不存在更窄的命令时包含完整构建。
- 当有多个命令时，将命令放在表格中。
- 每个项目符号保持一条规则。
- 除非防止可能的错误，否则不包含理由。
- 不要重述代码检查器、格式化器或类型检查器配置。
- 不要列出安装的技能或插件。
- 不要包含通用的质量口号。

## 反模式

- 欢迎文本、介绍、结论或客套话
- 长篇大论解释指令的重要性
- 从 `README.md`、`CONTRIBUTING.md` 或政策文档中重复的内容
- 项目级命令，当有文件级命令可用时
- 重复根指令的嵌套 `AGENTS.md` 文件
