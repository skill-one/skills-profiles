# 品牌规范

请遵循 Sentry 的品牌规范来撰写面向用户的内容。

## 语气选择

根据上下文选择合适的语气：

| 使用平实语言 | 使用 Sentry 语气 |
|-------------|------------------|
| 产品 UI（按钮、标签、表单） | 404 页面 |
| 文档 | 空状态 |
| 错误消息 | 欢迎流程 |
| 设置页面 | 加载状态 |
| 交易邮件 | "新功能"公告 |
| 帮助文本 | 营销文案 |

**默认使用平实语言**，除非上下文特别需要个性。

## 平实语言（默认）

平实语言清晰、直接、功能性强。适用于大多数 UI 元素。

### 规则

1. **简洁** - 使用最少的字
2. **直接** - 告诉用户该做什么，而不是他们能做什么
3. **使用主动语态** - "保存更改"而不是"您的更改将被保存"
4. **避免术语** - 使用用户能理解的简单词汇
5. **具体** - "发现 3 个错误"而不是"发现一些错误"

### 示例

| 而不是 | 写作 |
|-------|-------|
| "点击此处保存更改" | "保存" |
| "您可以按日期筛选结果" | "按日期筛选" |
| "发生错误" | "出错了" |
| "请输入有效的电子邮件地址" | "输入有效电子邮件" |
| "您确定要删除吗？" | "删除此项目？" |

## Sentry 语气

Sentry 语气在适当时刻增添个性。它富有同情心、自我认知，偶尔会带点讽刺。

### 原则

1. **富有同情心的讽刺** - 对情况直接表达沮丧，而不是对用户
2. **自我认知** - 承认软件的荒谬性
3. **有趣但实用** - 个性应该增强意义，而不是掩盖意义
4. **赢得时刻** - 只有在用户有时间欣赏时才使用

### 示例

**404 页面：**
> "这个页面不存在。也许它从来就不存在。也许它只是个梦。无论如何，让我们回到正轨。"

**空状态：**
> "还没有错误。享受这短暂的平静吧。"

**欢迎流程：**
> "让我们开始记录第一个错误。别担心，它不像听起来那么可怕。"

**加载状态：**
> "正在处理数据..."
> "正在获取您的数据..."

### 不使用 Sentry 语气的情况

- 错误消息（用户感到沮丧）
- 设置页面（用户需要专注）
- 文档（用户需要信息）
- 订阅/支付流程（用户需要信任）

## 一般规则

### 拼写和语法

- 使用**美式英语拼写**（color，而不是 colour）
- 使用**标题大小写**用于标题和页面标题
- 使用**句子大小写**用于正文、按钮和标签

### 标点符号

- UI 文本中**不使用感叹号**（庆祝时刻除外）
- 短 UI 标签或按钮文本中**不使用句号**
- 完整句子和帮助文本中**使用句号**
- **不使用全大写**，除非是缩写（API、SDK、URL）

### 词汇选择

| 避免 | 优先 |
|-------|-------|
| 请 | （省略） |
| 对不起 | （具体说明问题） |
| 发生错误 | 出错了 |
| 无效 | （说明哪里出错了） |
| 成功！ | （描述发生了什么） |
| 哎呀 | （具体说明） |

## 连字符使用

| 类型 | 使用 | 示例 |
|------|-----|-------|
| 短连字符 (-) | 复合词、范围 | "实时"，"1-10" |
| 破折号 (--) | 范围、关系 | "2023--2024"，"父级--子级" |
| 长连字符 (---) | 中断、强调 | "错误---即使是小的---也很重要" |

在大多数 UI 上下文中使用短连字符。保留破折号用于日期范围，保留长连字符用于较长的文本。

## UI 元素规范

### 按钮

- 使用行动动词："保存"，"删除"，"创建"
- 具体化："创建项目"而不是仅仅"创建"
- 尽可能使用 2-3 个字
- 不使用句号或感叹号

### 错误消息

1. 说明发生了什么
2. 说明原因（如果有帮助）
3. 说明下一步该做什么

**好：** "无法保存更改。检查您的连接并重试。"
**差：** "错误：保存失败。"

### 空状态

1. 说明通常会出现什么
2. 提供一个清晰的行动来填充状态
3. Sentry 语气在此适用

**好：** "还没有项目。创建您的第一个项目开始跟踪错误。"

### 确认对话框

- 在标题中明确行动
- 如果有破坏性后果，解释后果
- 使用具体的按钮标签（"删除项目"，而不是"确定"）

### 提示和帮助文本

- 保持在 2 句话以内
- 解释原因，而不仅仅是解释内容
- 复杂主题链接到文档

## 反模式

避免这些常见错误：

- **机器人语言：** "项目已成功删除" -> "已删除"
- **被动语态：** "更改已保存" -> "已保存更改"
- **不必要的词：** "为了" -> "到"
- **回避：** "这可能会造成..." -> "这会造成的..."
- **双重否定：** "不不同于..." -> "类似于..."
- **UI 中的营销语言：** "加速您的工作流程" -> "加快您的工作流程"
