# SRED 工作总结

收集某个人在给定年份内完成的所有 Github PR、Notion 文档和 Linear 工单。将所有这些链接按项目分组。将所有内容放入一个私有的 Notion 文档中，并返回该文档的链接。

## 前置条件

开始之前，确保可以访问 Github、Notion 和 Linear。Notion 和 Linear 应该通过 MCP 连接。Github 可以通过 MCP 连接，但如果你有 `gh` CLI 工具的访问权限，你可以使用它。

如果其中任何一个无法访问，提示用户授予权限后再继续。

## 流程

### 第一步

```bash
# 获取当前年份
date +%Y
```

该命令的输出是当前年份。
当前年份减一就是上一年份。

### 第二步

从用户那里收集所有必要的信息：

*Github 用户名*：用户的 Github 用户名是什么？

*Github 仓库*：应该搜索哪些 Github 仓库的 PR？

用户可以指定逗号分隔的列表，或者提供一个包含仓库的目录。在第二种情况下，在指定目录中使用以下命令：

```bash
# 查找 Github 仓库
find . -maxdepth 2 -name ".git" -type d | sed 's/\/.git$//' | sort
```

确保：
- 列出的所有仓库都在 `getsentry` Github 组织中。

输出结果被称为“用户仓库”。

*事件*：询问用户是否要包含事件文档。

答案是“是”或“否”。如果答案是“否”，则会在后续搜索中排除某些文档。

*其他用户*：询问是否有其他用户可能创建了 Notion 文档。

这应该是一个名字的逗号分隔列表。记住这个“其他用户”。

### 第三步

创建一个名为“SRED 工作总结 [当前年份]”的私有 Notion 文档。该文档被称为“工作总结”。

如果已经存在一个名为该名称的文档，通知用户重命名现有文档并停止执行。

确保：
- 如果工作总结已经存在，停止执行。

### 第四步

时间窗口是上一年 2 月 1 日到当前年 1 月 31 日。
查找在时间窗口内由给定 Github 用户名在用户仓库中创建的所有 Github PR。
如果用户不想包含事件文档，忽略标题或描述中包含 `INC-X`、`inc-X` 的 Github PR。
使用 Github MCP 或 `gh` 命令来完成。

查找用户在时间窗口内创建的所有 Notion 文档。
如果用户不想包含事件文档，忽略标题中包含 `INC-XXXX` 的 Notion 文档。
使用 Notion MCP 来完成。

查找用户在时间窗口内被分配的所有 Linear 工单。
如果用户不想包含事件文档，忽略标题中包含 `INC-XXXX` 的 Linear 工单。
使用 Linear MCP 来完成。

确保：
- 所有 Github PR 都是在时间窗口内创建或合并的，并且是由用户打开的。
- 所有 Notion 文档都是在时间窗口内创建的，并且是由用户创建的。
- 所有 Linear 工单都是在时间窗口内打开或完成的，并且在完成时被分配给用户。

### 第五步

对于在第四步中找到的每个 Github PR、Notion 文档和 Linear 工单，将链接放入在第三步中创建的私有文档中。

确保：
- 工作总结中包含所有 Github PR 的链接
- 工作总结中包含所有 Notion 文档的链接
- 工作总结中包含所有 Linear 工单的链接
- 不要截断链接列表。不要使用类似“...以及 75 更多”的缩短器。确保文档中显示所有 Github PR、Notion 文档和 Linear 工单的完整集合。

### 第六步

使用你自己的智能将工作总结文档中的所有 Github、Notion 和 Linear 工单链接分组到项目中。该文档的格式如下所示。

```markdown
# 项目

## [项目名称]
*摘要*：[X] 个 PR，[X] 个 Notion 文档，[X] 个 Linear 工单

### Pull Requests [X]
*[仓库名称]
[所有 PR 的链接]
- [链接] - [合并日期]

### Notion 文档 [X]
[所有 Notion 文档的链接]
- [链接] - [创建日期]

### Linear 工单 [X]
- [链接] - [创建日期]
```

对于 Github PR，使用 PR 的标题和描述进行分组。
对于 Notion 文档，使用完整文档进行分组。
对于 Linear 工单，使用工单的标题和描述。

确保：
- 文件中的所有链接都被分配到项目。
- 文件遵循上述格式。
- 不要截断链接列表。不要使用类似“...以及 75 更多”的缩短器。确保文档中显示所有 Github PR、Notion 文档和 Linear 工单的完整集合。

### 第七步

搜索由“其他用户”创建的 Notion 文档。将任何与工作总结中的项目相关的文档，将链接添加到工作总结中相应的项目中。

### 第八步

将工作总结 Notion 文档的链接返回给用户。

确保：
- 最终输出中包含实际的 Notion 文档链接。
