# 公关文案撰写者

将公关文案作为审阅者的封面信撰写，而非变更日志、模板、验证日志或逐文件摘要。

## 审查变更

需要经过认证的 `gh`。检查当前分支、工作区、PR、基础分支、提交记录和完整差异：

```bash
git branch --show-current
git status --porcelain
gh pr view --json number,title,body,url,baseRefName,headRefName
gh repo view --json defaultBranchRef
```

如果 `gh pr view` 报告不存在 PR，则继续进行首次 PR 创建。对于现有 PR，使用其 `baseRefName`；否则使用仓库默认分支。设置 `BASE`，然后检查：

```bash
git log "$BASE"..HEAD --oneline
git diff "$BASE"...HEAD
```

如果位于 `main` 或 `master`，请先创建功能分支。确保预期变更已提交，并审查整个分支差异，而不仅是最新提交或现有 PR 文本。

## 核心规则

- 在实施细节之前，描述具体变更行为、受影响范围和审阅者影响。
- 仅在有用时解释动机、风险、权衡、迁移或审阅重点。
- 使用最小结构使变更更易于审阅。
- 将内部提示或流程术语替换为具体行为。
- 刷新 PR 时，围绕当前完整差异重写，无需叙述审阅历史。

## 标题

使用 `<类型>(<范围>): <主题>` 或 `<类型>: <主题>`。

允许的类型：`feat`、`fix`、`ref`、`perf`、`docs`、`test`、`build`、`ci`、`chore`、`style`、`meta`、`license` 和 `revert`。

- 使用最精确的类型和范围描述主导的完整分支变更。
- 仅在变更破坏外部契约时使用 `!`，并在正文中解释受影响范围。
- 避免模糊的主题，如 `update`、`cleanup`、`misc`、`fix stuff` 或 `address feedback`。不要添加句号。
- 仅在标题仍描述整个差异时保留现有标题。

## 正文结构

选择最小有用的结构：

| 变更类型 | 包含内容 |
|---------|---------|
| 小或明显 | 无标题的一个简洁段落。 |
| 功能、错误修复或重构 | 变更行为和效果；在相关时添加根本原因、未变更行为或非明显方法。 |
| 合约或破坏性变更 | 受影响的 API、模式、负载、配置、权限、存储或 CLI 表面；包含兼容性和迁移指南。 |
| 运营、视觉或工作流变更 | 用户/操作者效果、衡量影响、故障模式或流程，在有用时。 |
| 广泛、生成或跨切变更 | 组织原则、为何需要广泛性，以及审阅应从何处开始。 |

默认：

```markdown
<变更内容及其效果。>

<如果不明显，解释为何方法、风险、迁移或审阅重点重要。>
```

对于审阅反馈更新，描述整个 PR 结果，而非修订序列。

## 审阅者辅助

仅在减少审阅者重构工作时代码辅助：

- 变更合约的紧凑前后示例或界面示例。
- 用于异步流程或状态转换的小型 Mermaid 图。
- 存在视觉证据时使用截图或录制说明。
- 当审阅者或采用者需要时，添加发布、兼容性、风险或审阅顺序说明。

用一句话介绍辅助工具，说明审阅者应关注的内容。当文本更清晰时省略。

## 边界

- 不要添加默认的 `摘要`、`变更` 或 `测试计划` 部分。
- 除非变更风险评估或解释有意义的回归覆盖，否则省略常规验证。对于文档、技能、文本或配置变更，默认省略。
- 不要粘贴命令、CI 日志、验证转储、提交日志、占位符或详尽的文件列表。
- 永不包含客户或组织名称、用户邮箱、支持工单内容、机密信息或 PII。
- 仅在从用户输入、分支名称、提交记录、PR 讨论或跟踪器输出中验证后使用问题引用。`Fixes <issue>` 会关闭；`Refs <issue>` 仅链接。

## 创建或更新

将新 PR 作为草稿创建。将正文写入临时 Markdown 文件，然后运行：

```bash
gh pr create --draft --title '<标题>' --body-file /tmp/pr-body.md
```

使用 `gh api` 更新现有 PR：

```bash
gh api -X PATCH repos/{owner}/{repo}/pulls/PR_NUMBER \
  -f title='<标题>' \
  -F body=@/tmp/pr-body.md
```

当后续提交实质性改变范围、方法、破坏性行为、风险、迁移或审阅预期时，刷新标题和正文。跳过仅修正拼写、格式或重命名后的后续提交。

## 示例

小变更：

```markdown
AI 自定义部分现在默认折叠，以避免在用户需要前占用侧边栏空间。展开它将保留现有的保存偏好行为。
```

破坏性合约：

````markdown
运行日志现在发出块级记录，而非技能级记录。读取顶层 `findings` 的消费者必须为每条记录迭代 `chunk.findings`。

之前：

```json
{"skill": "security-review", "findings": [...]}
```

之后：

```json
{"schemaVersion": 1, "chunk": {"index": 1, "findings": [...]}}
```
````
