# Sentry 提交信息

## 提交前

```bash
git branch --show-current
```

如果分支是 `main` 或 `master`，除非用户明确要求直接提交，否则创建功能分支。重新检查分支，如果仍然是 `main` 或 `master`，则停止。

一次提交一个连贯的、可独立审查的变更。

## 信息规则

使用：

```text
<类型>(<范围>): <主题>

<可选正文>

<可选页脚>
```

- 范围是可选的。对于破坏性变更，在 `:` 前面添加 `!`。
- 主题使用祈使句的现在时态；首字母大写，省略句号，并保持在 70 个字符以内。
- 每行保持在 100 个字符以内。
- 仅在有用时使用正文。说明变更内容及其原因，包括当有助于理解时之前的行行为或动机。
- 不要包含客户或组织名称、用户电子邮件、支持工单内容、秘密或个人身份信息 (PII)。描述技术症状。

允许的类型：`feat`、`fix`、`ref`、`perf`、`docs`、`test`、`build`、`ci`、`chore`、`style`、`meta`、`license` 和 `revert`。

对于没有行为变更的重构，使用 `ref`；对于没有逻辑变更的格式化，使用 `style`；对于仓库元数据，使用 `meta`。

## 页脚

- `Fixes <issue>` 在合并时关闭问题。
- `Refs <issue>` 链接问题但不关闭。
- 对于破坏性变更，添加 `BREAKING CHANGE: <影响>`。

## 创建提交

为段落和页脚使用单独的 `-m` 参数。不要在提交信息中放入字面 `\n` 序列，也不要打开交互式编辑器。

```bash
git commit -m "fix(api): 处理用户端点的空响应" \
  -m "当用户 API 发现已删除的账户时返回 404。" \
  -m "Fixes SENTRY-5678"
```
