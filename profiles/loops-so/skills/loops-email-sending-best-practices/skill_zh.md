# 发送邮件最佳实践

这项技能有助于审核和规划健康的邮件项目。它默认具有通用性，但有意偏向 Loops 对 SaaS、生命周期和事务性邮件的指导。

## 使用场景

当任务涉及邮件质量、风险或策略，而非低级 API 实现时，请使用此技能。

典型使用案例：

- 诊断收件箱放置率低或发件人声誉问题
- 审核同意流程、双重选择加入、列表卫生或退订行为
- 改进主题行、预览文本、发件人身份、个性化或渲染效果
- 在活动、生命周期自动化和事务性邮件之间进行选择
- 规划用户引导、留存、再激活、催款或产品更新邮件项目
- 审核 Loops 设置以发现最佳实践差距

不要将此技能默认用于纯粹的实现任务，例如“使用 Loops API 发送事件”或“在 Next.js 中配置事务性邮件”。请使用 `loops-api` 技能处理这些任务。

## 工作方式

当此技能激活时：

1. 确定主要问题：
   - 可送达性
   - 受众/同意
   - 内容/设计
   - 邮件类型/项目策略
   - Loops 特定的操作行为
2. 仅加载相关的参考文件。
3. 首先提供通用的邮件最佳实践指导。
4. 在相关位置添加 Loops 特定的注意事项、默认值和产品行为。
5. 如果用户开始涉及冷邮件或事务性邮件的促销使用，请直接指出并引导转向选择加入生命周期或营销发送。

## 类别路由

- 可送达性、发件人声誉、域名设置、邮件预热、收件箱放置率、Postmaster、BIMI 或大列表发送：
  阅读 `references/deliverability.md`
- 同意、列表卫生、双重选择加入、偏好中心、邮件列表、细分或过时受众：
  阅读 `references/audience-and-consent.md`
- 主题行、预览文本、发件人字段、个性化、样式、主题、暗黑模式或模板/设计审核：
  阅读 `references/content-and-design.md`
- 活动 vs 循环 vs 事务性、用户引导/生命周期排序、产品更新或邮件 KPI 框架：
  阅读 `references/email-types-and-program-strategy.md`
- Loops 特定的行为，如 `addToAudience`、事务性跟踪差异、附件、Webhook 或多域限制：
  阅读 `references/loops-operational-caveats.md`

## 输出清单

目标是让用户获得：

- 最可能的原因或机会
- 具体的推荐变更
- 任何可能实质性改变建议的 Loops 特定注意事项
- 变更后应关注的指标或信号

在相关情况下，明确区分：

- 立即修复措施
- 中期项目改进
- 由于证据有限而超出范围或存在风险的事项
