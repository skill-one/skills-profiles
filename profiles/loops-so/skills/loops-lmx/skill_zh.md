# LMX 技能

这项技能有助于编写、审阅和生成 Loops 使用的正确 LMX 邮件标记。LMX 是一种基于 XML 的格式：每个元素都是一个 PascalCase 标签，自闭合标签需要 `/>`，并且只有规范中定义的标签才是有效的。

## 使用场景

在以下任务中使用此技能：

- 生成或编辑 LMX 邮件内容
- 复制原始材料、迁移现有邮件，或将 HTML、MJML、Markdown 或纯文本邮件内容转换为 LMX
- 审阅 LMX 标记的正确性
- 为布局选择合适的 LMX 标签或属性
- 将设计指南应用于 LMX 文档
- 解释特定 LMX 标签或属性的工作原理

## 工作方式

当此技能激活时：

1. 读取 `references/lmx-spec.md` 获取完整的标签和属性参考。它是权威的；不要自行发明标签或属性。
2. 读取 `references/lmx-design-guidelines.md` 获取 Loops 设计指南。将这些指南应用于你生成的每个文档，除非用户明确覆盖了规则。
3. 对于全新的邮件或重大视觉改版，在编写 LMX 之前遵循 Net-New Email Design Flow，除非用户明确要求仅复制或最小化更新。
4. 将原始材料视为输入，而不是覆盖。当从原始材料复制、迁移现有邮件，或将 HTML、MJML、Markdown、截图或纯文本转换为 LMX 时，仍然应用此技能的规范、设计、内容和输出检查清单规则，除非用户明确覆盖了特定规则。
5. 在生成输出之前验证嵌套和内容类型规则（参见规范第 3 节）。
6. 在最终确定输出之前，查阅规范中的常见错误表格。
7. 始终生成完整的、有效的文档，而不是片段，除非用户明确要求生成片段。

## 类别路由

- 标签定义、必需/可选属性、嵌套规则、内容类型、变量语法、自闭合要求或转义：
  读取 `references/lmx-spec.md`

- 色彩对比度、间距、列圆角、Style 标签使用、视觉层次结构或任何“这个应该看起来怎样”的问题：
  读取 `references/lmx-design-guidelines.md`

- 全新邮件设计、重大改版或 gpt-image/imagegen 引用：
  读取 `references/lmx-design-guidelines.md`，特别是 Net-New Email Design Workflow 和 Reference-to-Render QA 部分。仅在 Loops 本地或用户提供的参考不适用且任务仍需要视觉参考时，在 Codex 中使用 `imagegen` 技能。

- 创建活动、通过 API 发布 LMX、修订 ID、主题、组件或图片上传：
  使用 `loops-api` 技能（HTTP）或 `loops-cli` 技能（终端）。此技能涵盖 LMX 文档本身。

## 全新邮件设计流程

在创建全新活动、生命周期、工作流或事务邮件，或用户要求重大视觉改版时使用此流程。

1. 运行 `references/lmx-design-guidelines.md` 中的 Known Brand / Customer Context Gate。
2. 在理解 Loops 本地和用户提供的上下文后，仅从视觉参考开始。使用现有组件/主题预览、用户截图/模型或简洁的书面布局参考（当足够时）。在 Codex 中，仅在任务仍需要视觉探索时生成 `imagegen`/gpt-image 参考。
3. 生成参考时，提示生成一个完整的 600px 宽邮件模型，而不是通用卡片。包括确切的可见文本、主题内容、相关品牌提示，以及仅 LMX 安全的结构：`Style`、`Section`、`Columns`、`Paragraph`、`H1`、`H2`、`H3`、`Button`、分隔符、复选框行和简单的图片占位符。
4. 限制生成参考为现实的 Loops 编辑器输出。避免不支持的 SVG 艺术、重叠层、自定义图标、复杂的应用界面、虚构的产品截图、装饰性色块和落地页规模的英雄文本。
5. 在编写 LMX 之前检查选定的参考。如果布局或文本明显错误，通过聚焦提示进行一次迭代，而不是从记忆中补偿。
6. 将选定的参考或 Loops 本地结构转换为有效的 LMX，同时保留层次结构。将生成的过大标题标准化为设计指南中的邮件默认值，并适当使用 LMX 安全的间距、`Section` 卡片和共享背景 `Columns`。
7. 为正确的邮件类型使用变量：`{contact.*}` 用于活动和流程邮件；`{event.*}` 用于流程邮件，当值来自触发事件时；`{data.*}` 仅用于事务邮件。
8. 如果邮件通过 API、CLI 或编辑器实现，通过修订安全的邮件消息路径更新，并在调用工作完成之前，将最新的 Loops 编辑器预览与视觉参考或 Loops 本地源进行比较。

## 输出检查清单

在返回任何 LMX 输出之前，验证：

- [ ] 所有标签都是 PascalCase 且在允许的集合中
- [ ] 所有自闭合标签使用 `/>`（例如 `<Image />`、`<Divider />`、`<Br />`、`<Icon />`、`<Style />`）
- [ ] 转义 XML 敏感字符：`&` 作为 `&amp;`，`<` 作为 `&lt;`，属性中的 `"` 作为 `&quot;`
- [ ] 必需属性存在：`<Image />` 上的 `src`，`<Component>` 上的 `componentId`，`<Icon>` 上的 `name`，以及 `<Link>` 上的 `href`
- [ ] 顶层没有文本或内联标签
- [ ] 变量使用显式的 LMX 命名空间，并且仅在支持的位置出现：内联内容、按钮文本、`<Button href>`、`<Link href>`、`<Image alt/href/dynamicSrc>` 和 `<Section href>`
- [ ] 变量命名空间与邮件类型匹配：活动使用 `{contact.apiName}`；流程邮件使用 `{contact.apiName}` 和/或 `{event.propertyName}`；事务邮件使用 `{data.variableName}`（不是未前缀的 `{variableName}` 或 `{DATA_VARIABLE:...}`）
- [ ] 没有发明内联后备语法；后备在 LMX 字符串外部
- [ ] `<Button>` 文本没有内联标签，但可以包含变量；为可点击的 CTA 按钮包含 `href`
- [ ] `<CodeBlock>` 将大括号视为字面量
- [ ] `<Style />` 最多出现一次作为顶层标签；在生成输出中将其放在第一位
- [ ] 身体/背景颜色和 X/Y 填充是故意的：由 `themeId` 提供，或显式的 `bodyColor`/`backgroundColor` 加上 `bodyXPadding`/`bodyYPadding`（当需要时）
- [ ] 全新邮件和重大改版遵循了 Net-New Email Design Flow，除非用户明确跳过了它
- [ ] 如果有渲染预览，全新和改版邮件在调用工作完成前，在 Loops 编辑器中与选定的参考或 Loops 本地源进行了视觉比较
- [ ] 生成的文本遵循文本和标点符号指南：没有英文破折号、装饰性箭头符号或省略号，除非要求或保留原始材料
- [ ] 生成的 `<H1>`、`<H2>` 和 `<H3>` 文本不以句号结尾；问号或感叹号仅在有意时使用
- [ ] 生成的文档使用受约束的标题集：通常一个 `<H1>`，仅必要的 `<H2>` 分割，`<H3>` 仅用于真实的嵌套层次结构
- [ ] 标题比例、身体/卡片宽度、水平密度和布局结构适合邮件并遵循设计指南
- [ ] CTA 和 `<Button>` 文本简洁、以行动为导向，并且不以句号结尾
- [ ] 没有相同颜色在同一颜色上的情况（检查文本与块颜色、图标颜色与背景等）
- [ ] 块元素有足够的 Y 间距
- [ ] 重要文本、标题、CTA 和高亮块在适当位置使用微妙的视觉强调
- [ ] `<Section>` 仅用于调用、分组控件、链接组或显式的卡片样式布局；普通正文不默认包裹在多个浮动卡片中
- [ ] 相邻的 `<Section>` 兄弟节点之间使用行间空格分隔，除非用户明确指定了不同的部分间距方法
- [ ] 相邻的高亮块，包括 `blockColor` 段落、列和部分，除非它们有意作为一个连接的卡片，使用可见的垂直空间分隔
- [ ] `<Columns>` 有两个到四个 `<ColumnItem>` 子元素，当提供时 `widths` 与列数匹配
- [ ] 动态图片使用静态 `src` 加上 `dynamicSrc`，而不是 `src` 中的变量
- [ ] `<Icons color>` 使用 `#000000`、`#808080` 或 `#ffffff` 之一；`<Icon>` 没有颜色属性
- [ ] 手动没有添加法律页脚、邮政地址或退订块；Loops 自动添加必需的页脚内容。一个品牌页脚组件可以出现在它上面
