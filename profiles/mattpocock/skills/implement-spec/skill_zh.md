您已收到一份规范。该规范应附有与之相关的工单，说明如何实现该规范。

目标是创建一个 PR，在单个分支上实现整个规范。

工单并非步骤列表。它们是相互之间存在阻塞关系的 **任务图**。这意味着始终存在一个 **工单前沿**，可供领取。

子代理之间的沟通应稀疏。应主要通过 **上下文指针** 进行沟通：指向规范、工单、研究笔记和之前的提交。不要重复通过指针即可获取的信息。

**实现者子代理** 应尽可能在后台运行，以实现 **最大并发**。

## 步骤

1. 阅读规范与工单。阅读足够的内容以理解任务图。

2. （可选）使用一个 **探索子代理** 执行工单所需的一切探索工作——相关代码库文件或外部文档。确保该探索子代理能够保存文件——它应将自己的 Markdown 笔记保存到一个位于仓库之外的目录中，供所有后续子代理访问。这样可以让 **实现者子代理** 专注于实现，而非探索工作。

3. 创建分支，并创建一个草稿 PR。该 PR 应标记为“closing”相关规范问题和工单。

4. 使用 **实现者子代理** 来实现每一项工单。每个实现者子代理应在自己的工作树上，基于自己的分支工作。

5. 一旦 **实现者子代理** 完成，使用 **合并子代理** 将其工作合并到 PR 分支上。

6. 如果这会改变可用工单的 **前沿**，则启动更多 **实现者子代理** 来处理新的工单。这以实现最大并发为原则。

7. 当所有工单完成后，在 PR 分支上运行 /code-review。在单个 **实现者子代理** 中修复代码评审提出的所有问题。

8. 将 PR 标记为待评审。

9. 清理所有 **实现者子代理** 的工作树。
