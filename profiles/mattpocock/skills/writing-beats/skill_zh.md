<what-to-do>

用户已提供（或即将提供）一份原始素材的 Markdown 文件。这是 **利用（exploit）**：探索工作已完成，素材已固定。选定一条贯穿其间的路径，并挖掘素材以填补每一个小节。

如果用户没有说明文章保存位置，询问一次并记住该路径。

然后以“选择你的冒险”的风格，逐节（beat）进行一场逐节旅程：

1. **确立前提条件。** 在编写任何小节之前，与用户确定读者进场时已经了解的内容：即从开始就**已奠基（grounded）**的概念。后续小节若要使用其他内容，必须先在某个小节中得到奠基。详见 [Grounding](#grounding)。
2. 根据原始素材编写 2–3 个候选**起始小节**。每个小节都是文章的不同入口。每个小节只能依赖已奠基的概念，并注明每个小节新奠定的概念。在将内容写入文章文件前，向用户展示这些小节。用户选择其中一个。预览所选小节能够解锁的其他小节，仿佛用户正在看道路的某一段。
3. 用户选定起始小节后，**仅将该小节**写入文章文件。一个小节可能是一句话，也可能是若干段落，具体取决于该小节的自然形态。就此停止。
4. 从磁盘重新读取文章文件。然后提供 2–3 个候选**后续小节**：文章当前所在位置，旅程可能转向的不同方向。每个后续小节都必须能从当前的奠基集合中推导得出；并注明每个后续小节会奠定哪些内容。
5. 循环执行步骤 3 至 5，直到文章达到自然结尾。

</what-to-do>

## Grounding

任何一个**概念**在某个小节依赖它之前，都必须先被**奠基（grounded）**：读者进场时已经了解该概念，或在之前的小节中遇到该概念。若一个小节试图依赖未奠基的概念，就会失去读者；这是旅程无法执行的唯一操作。单位是概念，而非其词汇：一个小节可以依赖读者尚未具备的某个想法，即使眼前看不到任何专业术语。当某个概念有名称（即**术语（term）**），对其进行奠基意味着将该想法与术语同时确立。

概念通过两种方式被奠基：

- **前提条件（Prerequisite）**：在第一个小节之前被奠基。读者自带该概念。在初始阶段固定。
- **引入（Introduced）**：由一个小节确立该概念，此后所有后续小节中它都被奠基。

因此，每个小节有双重职责：它**需要**已奠基的概念，并**奠定**新的概念。始终保持一份已奠基内容的动态列表，并在每次小节落定（落地）时更新它。

这正是塑造“选择你的冒险”的方式。一个候选小节只有在其所需内容均已奠基时才可达；选择奠定概念 X 的小节，会解锁所有依赖 X 的后续小节。当提供后续小节时，它们都必须能从当前的奠基集合中推导得出，并说明每个小节会奠定哪些内容，以便用户能看清打开了哪些路径。

关键杠杆在于，你将什么设为前提条件，而在作品中奠定什么内容。前期要求过高，会将不具备该内容的读者排除在外；在内部奠定过多，会导致早期小节被定义淹没。在确立前提条件时与用户商定这一点，并在任何有吸引力的小节最终发现其所需概念尚未被奠定时重新审视：解决办法要么在它之前加入一个小节来奠定该概念，要么将该概念提升为前提条件。

## 什么是小节（beat）

一个小节是旅程中的一次行动。它做一件事：设定场景、确立观点、提出问题、插入插叙或转折角度。随后它停止，将读者置于能让下一个小节进行转向的节点。

一个小节的大小取决于它的需求：

- 如果该行动仅需一句话（"然后，三周内什么都没发生。"），就写一句话。
- 如果该行动需要铺垫，就写一个短段落。
- 如果一个小节本身是一个自包含的片段、论证或示例，就写多个段落。

如果一个“小节”需要五段文字和三道子标题，那它不是一个小节；它是两个小节拼在了一起。将其拆分。

## 从素材堆中提取内容

从原始素材堆中提取内容，以充实每一个小节。你可以进行转述、拆分、重组或引用。素材堆是一处矿源。

## 结束旅程

文章的结束以旅程的完成为准，而非以素材堆耗尽为准。大多数素材堆都会有无法进入文章的剩余片段。这没什么问题；这正是拥有超出所需原始素材的优势所在。

## 写作节奏

- 一次只追加一个小节，切勿超前写作。
- 每次写入前，都必须从磁盘重新读取文章文件。绝对保留用户的编辑内容。
- 如果用户大幅修改了之前的小节，应使其影响后续内容。
- 如果用户说“重写该小节”或“回到并尝试不同的第 3 个小节”，照做：就地修改，保持其余内容不变。
