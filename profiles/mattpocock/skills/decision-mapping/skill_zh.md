这项技能在松散的想法需要多个代理会话才能转化为计划时被调用。它在一个 Markdown 文件中创建一个有状态决策图，并引导用户通过一系列工单来解决问题——这可能需要原型设计、研究或深入询问。该图与领域无关：它可以规划工程工作、课程内容或任何符合相同模式的任务。

## 决策图

决策图是一个单一的紧凑型 Markdown 文件，每个规划工作一个，与项目一起进行 git 跟踪。它是规范工件——**整个图作为上下文加载到每个会话中**，因此它必须保持紧凑。

工单期间创建的资产应从图中链接，而不是在图中重复。

### 结构

条目（“工单”），每个条目是其自己的部分，以简短的连字符小写别名作为键，该别名读作一个小标题（例如 `relational-db`、`auth-strategy`、`cache-layer`）——简洁到足以保持高效的标记，并且在图中是唯一的。

```markdown
## relational-db: 关系型数据库还是非关系型数据库？

阻塞于：<别名>、<别名>
状态：打开 | 进行中 | 已解决
类型：研究 | 原型设计 | 深入询问 | 任务

### 问题

<此处填写问题>

### 答案

<此处填写答案>
```

别名是规范 ID，用于每个 `阻塞于` 边缘和文本引用；冒号后的标题是可选的。当其 `阻塞于` 列表中的每个工单都为 `已解决` 时，工单**被解锁**。会话**声明**其工单，通过设置 `状态：进行中` 并在执行任何工作之前保存地图，以便并发会话跳过它。

每个工单必须大小适合一个 100K 标记的代理会话。

## 工单类型

有四种类型的工单：

- **研究**：阅读文档、第三方 API 或本地资源（如知识库）。创建一个 Markdown 摘要作为资产。当需要当前工作目录外部的知识时，使用此类型。
- **原型设计**：通过制作廉价、粗糙、具体的工件来提高讨论的保真度以进行反应——大纲、粗略的草稿、桩或通过 `/prototype` 技能的 UI/逻辑代码。创建原型作为资产。当“它应该看起来如何”或“它应该如何表现”是关键问题时，使用此类型。
- **深入询问**：与代理的对话。使用 `/grilling` 和 `/domain-modeling` 技能。一次问一个问题。默认情况。
- **任务**：在进行讨论之前必须完成的实际手动工作——没有需要决定、原型设计或研究的内容。将数据从一个地方移动到另一个地方、注册第三方服务、配置访问权限。代理可以在可能的情况下自动执行它；否则，它将向人类提供一个精确的待办事项清单。当工作完成后即被解决；答案记录了完成的工作以及任何后续工单依赖的结果事实（凭证位置、新 URL、行数）。

## 战争迷雾

地图在边界之外是**故意**不完整的。你的工作是调查边界，并通过解决工单来推动边界前进。一次又一次地驱散战争迷雾——直到通往终点线的路径清晰且没有剩余的工单。

## 转交

有两个分支。无论如何，**每个会话都以一个 [转交](#转交)** 结束——每个会话最多解决一个工单。

### 创建地图

用户以松散的想法调用。

1. 运行 `/grilling` 和 `/domain-modeling` 会话来揭示开放的决定。一次问一个问题。
2. 编写一个新的决策图——大部分是迷雾，边界已确定，简单的可决定条目直接在行内解决。
3. 转交。地图构建是一个会话的工作；不要同时解决工单。

### 通过地图工作

用户以现有地图的路径调用。别名是**可选的**——如果没有，你选择下一个决定，而不是用户。

1. 将**整个地图**作为上下文加载。
2. 选择工单。如果用户指定了一个，使用它。否则选择文档顺序中第一个 `打开` 的且 [未阻塞](#结构) 的工单。[声明它](#结构)：设置 `状态：进行中` 并在执行任何工作之前保存地图。
3. 解决它，根据需要调用技能——包括 `## 备注` 块命名的任何技能。如有疑问，使用 `/grilling` 和 `/domain-modeling`。
4. 在工单的正文中记录答案并设置 `状态：已解决`。
5. 添加新发现的工单，并具有正确的 `阻塞于` 边缘。如果做出的决定使地图的其他部分失效，请更新或删除这些节点。
6. 转交。

用户可以并行运行未阻塞的工单，因此要预期其他代理在自己的会话中编辑地图。

## 转交

每个会话都以清除上下文并打开一个或多个新会话结束。以用户可以复制粘贴的 **下一步** 块结束。有两种情况：

**仍有打开的工单。** 列出当前未阻塞的工单，然后提供两个复制粘贴选项：一个用于单个会话的裸命令（你选择下一个工单），以及每个未阻塞工单一个固定命令用于并行运行。每个新窗口粘贴一行——打开一个、一些或所有它们。

> **下一步** — 3 个工单未阻塞：`auth-strategy`、`cache-layer`、`rate-limits`。
> 清除上下文，然后打开新会话。
>
> **单个会话** — 解决下一个未阻塞的工单：
> ```
> 使用地图在 <路径> 调用 /decision-mapping。
> ```
>
> **并行** — 每个窗口粘贴一行，最多 3 个：
> ```
> 使用地图在 <路径> 调用 /decision-mapping，工单 auth-strategy。
> 使用地图在 <路径> 调用 /decision-mapping，工单 cache-layer。
> 使用地图在 <路径> 调用 /decision-mapping，工单 rate-limits。
> ```

**没有剩余的打开工单。** 迷雾已经推进得足够远，以至于通往终点线的路径清晰——地图已完成。（初始的深入询问也可能没有迷雾，在这种情况下，从未需要构建地图。）建议直接实施，或使用 `/to-prd` 调度多会话实施。

## 备注

一个可选块，声明**领域**、每个会话应 `参考` 的任何技能，以及规划表面中任何自由形式的站立偏好。
