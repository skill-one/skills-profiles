# 写作技巧

## 流程

1. **收集需求** - 向用户询问：
   - 该技能涵盖哪些任务/领域？
   - 需要处理哪些具体用例？
   - 是否需要可执行脚本或仅指令？
   - 是否需要包含参考材料？

2. **起草技能** - 创建：
   - SKILL.md（包含简洁指令）
   - 如果内容超过500行，则创建额外的参考文件
   - 如果需要确定性操作，则创建实用脚本

3. **与用户评审** - 展示草稿并询问：
   - 这是否涵盖您的用例？
   - 是否有任何遗漏或不清晰之处？
   - 是否需要调整任何部分的详细程度？

## 技能结构

```
skill-name/
├── SKILL.md           # 主指令（必填）
├── REFERENCE.md       # 详细文档（如需）
├── EXAMPLES.md        # 使用示例（如需）
└── scripts/           # 实用脚本（如需）
    └── helper.js
```

## SKILL.md 模板

```md
---
name: skill-name
description: 能力的简要描述。在[特定触发条件]时使用。
---

# 技能名称

## 快速入门

[最小可工作示例]

## 工作流程

[具有检查表的复杂任务的分步流程]

## 高级功能

[链接到单独文件：参见[REFERENCE.md](REFERENCE.md)]
```

## 描述要求

描述是您的代理在决定加载哪个技能时**唯一能看到的内容**。它会在系统提示中与其他所有已安装技能一起显示。您的代理会阅读这些描述，并根据用户的请求选择相关技能。

**目标**：向您的代理提供足够的信息，使其知道：

1. 该技能提供什么能力
2. 何时/为何触发（特定关键词、上下文、文件类型）

**格式**：

- 最大1024字符
- 使用第三人称书写
- 第一句：描述它做什么
- 第二句："在[特定触发条件]时使用"

**良好示例**：

```
从PDF文件中提取文本和表格，填写表单，合并文档。在处理PDF文件或用户提到PDF、表单或文档提取时使用。
```

**不良示例**：

```
帮助处理文档。
```

不良示例无法让您的代理区分该技能与其他文档技能。

## 何时添加脚本

在以下情况下添加实用脚本：

- 操作是确定性的（验证、格式化）
- 相同的代码会被重复生成
- 需要显式处理错误

脚本可以节省token并提高可靠性，优于生成代码。

## 何时拆分文件

在以下情况下拆分为单独文件：

- SKILL.md超过100行
- 内容具有不同的领域（如财务与销售模式）
- 高级功能很少使用

## 评审清单

起草后验证：

- [ ] 描述包含触发条件（"在...时使用"）
- [ ] SKILL.md少于100行
- [ ] 无时效性信息
- [ ] 术语一致
- [ ] 包含具体示例
- [ ] 参考文件为同一级
