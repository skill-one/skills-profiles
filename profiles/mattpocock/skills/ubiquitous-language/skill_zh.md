# 普遍语言

从当前对话中提取并规范化领域术语，形成一份一致的术语表，并保存到本地文件中。

## 流程

1. **扫描对话**，查找与领域相关的名词、动词和概念
2. **识别问题**：
   - 同一个词用于不同的概念（歧义）
   - 不同的词用于同一个概念（同义词）
   - 模糊或含义过载的术语
3. **提出规范的术语表**，包含主观的术语选择
4. **使用以下格式将内容写入工作目录中的 `UBIQUITOUS_LANGUAGE.md` 文件**
5. **在对话中内联输出摘要**

## 输出格式

编写 `UBIQUITOUS_LANGUAGE.md` 文件，结构如下：

```md
# 普遍语言

## 订单生命周期

| 术语        | 定义                                              | 需避免的别名      |
| ----------- | ------------------------------------------------------- | --------------------- |
| **订单**   | 客户购买一个或多个商品的需求                      | 购买、交易        |
| **发票**   | 送货后发送给客户的付款请求                      | 账单、付款请求    |

## 人员

| 术语         | 定义                                  | 需避免的别名       |
| ------------ | ------------------------------------------- | ---------------------- |
| **客户**     | 下订单的个人或组织                      | 客户、买家、账户    |
| **用户**     | 系统中的认证身份                      | 登录、账户         |

## 关系

- 一个 **发票** 属于且仅属于一个 **客户**
- 一个 **订单** 产生一个或多个 **发票**

## 示例对话

> **开发人员：** "当 **客户** 下一个 **订单** 时，我们立即创建 **发票** 吗？"
> **领域专家：** "不——**发票** 只有在 **履约** 确认后才会生成。一个 **订单** 可能产生多个 **发票**，如果商品分批 **发货** 的话。"
> **开发人员：** "所以如果 **发货** 在派送前被取消，没有对应的 **发票** 吗？"
> **领域专家：** "完全正确。**发票** 的生命周期与 **履约** 相关，而不是与 **订单** 相关。"

## 标记的歧义

- "account" 同时被用于 **客户** 和 **用户**，这两个是不同的概念：**客户** 下订单，而 **用户** 是一个认证身份，可能代表也可能不代表一个 **客户**。

## 规则

- **主观判断。** 当同一个概念存在多个词语时，选择最佳的一个，并将其他词语列为需避免的别名。
- **明确标记冲突。** 如果一个术语在对话中存在歧义，请在“标记的歧义”部分明确指出并给出建议。
- **仅包含领域专家相关的术语。** 除非模块或类名在领域语言中有意义，否则跳过其名称。
- **定义简洁。** 最多一句话。定义它是什么，而不是它做什么。
- **展示关系。** 使用粗体术语名称，并在明显的情况下表达基数。
- **仅包含领域术语。** 除非具有领域特定含义，否则跳过通用编程概念（数组、函数、端点）。
- **将术语分组到多个表格中。** 当自然形成逻辑集群时（例如按子域、生命周期或参与者分组），每个集群应有自己的标题和表格。如果所有术语属于一个连贯的领域，一个表格即可——不要强制分组。
- **编写示例对话。** 一段开发人员与领域专家之间的简短对话（3-5 次交流），展示术语如何自然交互。对话应澄清相关概念之间的边界，并展示术语的精确使用。

<示例>

## 示例对话

> **开发人员：** "如何在不使用 Docker 的情况下测试 **同步服务**？"
>
> **领域专家：** "提供 **文件系统层** 而不是 **Docker 层**。它实现相同的 **沙盒服务** 接口，但使用本地目录作为 **沙盒**。"
>
> **开发人员：** "**同步入** 仍然会创建 **包** 并解包它吗？"
>
> **领域专家：** "完全正确。**同步服务** 不知道它正在与哪个层交互。它调用 `exec` 和 `copyIn`——**文件系统层** 只是将其作为本地 Shell 命令执行。"

</示例>

## 重新运行

在同一个对话中再次调用时：

1. 读取现有的 `UBIQUITOUS_LANGUAGE.md`
2. 将后续讨论中的新术语纳入其中
3. 如果理解有所发展，更新定义
4. 重新标记任何新的歧义
5. 重新编写示例对话，纳入新术语
