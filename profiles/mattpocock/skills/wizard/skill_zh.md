# 工具师

**工具师**是一个bash脚本，它会一步步引导人类完成一个手动操作繁琐且每次向AI解释都繁琐的流程。它会打开每个URL，明确指示点击和复制的内容，捕获值，将它们写入正确的位置（`.env`，GitHub密钥），并在每个阶段进行确认，同时显示剩余的步骤数量。它可能配置第三方服务，运行一次性迁移，或将项目从一个状态转移到另一个状态。

令人愉悦的用户体验已经由[template.sh](template.sh)解决：分阶段的进度显示、确认关卡、跨平台URL打开（包括WSL）、隐藏密钥输入、幂等的`.env`插入更新、`gh secret`/`gh variable`写入以及结束时的总结。**你的工作仅仅是定义流程范围并编写其步骤。** `STAGES`标记线以上的库在所有工具师中都是相同的；这种一致性才是要点：永远不要手动编辑它。

工具师默认是短暂的：为单次运行而构建，保存到临时或`scripts/`路径，任务完成后删除。只有当用户想要一个应该存在于仓库中的可重复设置路径时，才提交它，并在README中链接它，以便下一个人运行脚本而不是询问AI。

## 流程

### 1. 定义流程范围

确定人类必须执行的每个手动步骤以及沿途捕获的每个值。先阅读仓库，不要冷启动：

- 对于设置：`.env`，`.env.example`，`.env.*`，`README`，`docker-compose*`，框架配置和`.github/workflows/*`（每个`secrets.*` / `vars.*`引用都是工具师必须生成的值）。
- 对于迁移或过渡：当前状态、目标状态以及它们之间的不可逆操作。

然后向用户展示按顺序排列的步骤列表以及每个步骤生成的值，并确认：他们可以添加、删除或重新排序。

**完成标准：** 每个步骤按顺序命名，并且对于每个捕获的值，你知道（a）人类从哪里获取它，（b）它被写入哪里（`.env`，一个GitHub密钥，两者，或无处；某些步骤是纯动作），以及（c）它是否是密钥（隐藏输入）或公开。

### 2. 映射每个步骤的路径

对于每个步骤，编写人类遵循的确切路径：打开哪个URL，在那里做什么，值显示在哪里，哪个变量被填充：例如："仪表盘 → 开发者 → API密钥 → 显示测试密钥 → 复制"。在你不知道当前UI或确切命令的情况下，说明并询问用户或查阅文档：永远不要编造可能不存在的步骤。

**完成标准：** 每个步骤都可以追溯到陌生人可以遵循的具体指令。

### 3. 编写工具师

将`template.sh`复制到目标路径。用每个步骤一个`stage`的依赖顺序替换示例步骤。使用库辅助函数：`stage`，`say`/`step`，`open_url`，`ask`/`ask_secret`，`write_env`，`set_secret`/`set_var`，`pause`/`confirm`。将`TOTAL_STAGES`设置为编写的步骤数量。

保持模板设定的标准：在请求其值之前打开URL，对任何密钥使用`ask_secret`，对每个持久化值使用`write_env`，仅对CI实际需要的值使用`set_secret`，并在任何不可逆操作之前进行`confirm`。每个`stage`清除屏幕，以便只显示当前步骤：保持每个步骤专注于一个任务，以免人类需要的内容滚动消失。不要触摸标记线以上的库。

### 4. 验证并移交

- `bash -n <script>`；如果可用，运行`shellcheck`。
- `chmod +x <script>`。
- 不要自己完整运行它：它会打开浏览器并阻塞人类输入。静态分析它：步骤1的每个值都被捕获并到达步骤1指定的位置，并且每个`set_secret`名称都与CI中的`secrets.*`引用完全匹配。
- 告知用户如何运行它。如果它是可重复的设置路径，提交它并在README中链接它，以便下一个人运行脚本而不是询问AI。
