# 自动化向导

**自动化向导** 是一个 bash 脚本，它一步步引导用户完成一项手动操作极为繁琐，且每次向 AI 重新解释都极其繁琐的手工流程。它会打开每个链接，明确说明需要点击和复制的内容，捕获相关值，并将它们写入相应位置（`.env`、GitHub 密钥），在每一阶段进行确认，并显示剩余的步骤数量。它可能用于配置第三方服务、执行一次性迁移，或将项目从一个状态过渡到另一个状态。

出色的 UX 体验已被 [template.sh](template.sh) 解决：分阶段进度、确认闸门、跨平台链接打开（包括 WSL）、隐藏密钥输入、幂等的 `.env` 写入与更新、`gh secret` / `gh variable` 写入，以及结束总结。**您的工作仅限于界定流程范围并编写其阶段。** `STAGES` 标记上方的库在每个向导中都是相同的；这种一致性才是关键：绝不要手动编辑它。

默认情况下，向导是临时的：为单次运行而构建，保存到临时路径或 `scripts/` 目录下，当任务完成后即被删除。只有用户希望将其作为一个可在仓库中保留的可重复设置路径时，才应将其提交。

## 流程

### 1. 界定流程范围

梳理出用户必须执行的所有手动步骤以及在过程中捕获的所有值。首先阅读仓库代码，不要生硬地提问：

- **针对配置**：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（每一个 `secrets.*` / `vars.*` 引用都是向导需要生成的值）。
- **针对迁移或过渡**：当前状态、目标状态，以及两者之间的不可逆操作。

然后向用户展示各阶段的顺序列表以及每个阶段生成的值，并予以确认：用户可以添加、删除或重新排序。

**完成标准：** 每个阶段均已按顺序命名，并且对于每个捕获的值，您已知（a）人类获取该值的位置，（b）其写入位置（`.env`、GitHub 密钥、两者皆有，或无需写入；部分阶段为纯操作），以及（c）该值为机密（需隐藏输入）还是公开。

### 2. 映射每个阶段的流程

为每个阶段编写人类遵循的具体路径：打开哪个链接、在那里执行什么操作、在哪里显示值、填充哪个变量，例如“仪表盘 → 开发者 → API 密钥 → 显示测试密钥 → 复制”。如果您实际上不清楚当前的界面或确切的命令，请说明并询问用户或查阅文档：切勿编造可能不存在的步骤。

**完成标准：** 每个阶段都能追溯至陌生人在实际可遵循的具体指令。

### 3. 编写向导

将 `template.sh` 复制到目标路径。用每个步骤一个 `stage`，按依赖顺序替换示例阶段。使用库辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。将 `TOTAL_STAGES` 设置为您编写阶段的数量。

保持模板设定的标准：在询问数值之前先打开链接，对机密内容使用 `ask_secret`，对所有持久化值使用 `write_env`，仅在 CI 确实需要的值上使用 `set_secret`，并在任何不可逆操作之前使用 `confirm`。每个 `stage` 会清除屏幕，以便只显示当前步骤：将每个阶段聚焦于一项任务，确保人类需要查看的内容不会滚动离开屏幕。不要改动标记上方的库。

### 4. 验证并移交

- 执行 `bash -n <script>`；若可用则运行 `shellcheck`。
- 执行 `chmod +x <script>`。
- 不要自行端到端运行它：它会打开浏览器并在等待人类输入时阻塞。改用静态方式追踪：第一步中捕获的所有值均按第一步所述落入相应位置，且每个 `set_secret` 的名称与 CI 中的 `secrets.*` 引用完全一致。
- 告知用户如何运行它。如果它是可重复的设置路径，则将其提交，并链接到 `README` 中，使下一个人直接运行该脚本，而无需向 AI 询问。
