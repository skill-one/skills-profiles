## 处理流程

1. 探索代码库，了解当前代码库的状态（如果您尚未了解）。在 PRD 中贯穿使用项目的领域术语词汇，并尊重您所涉及领域的任何 ADR（架构决策记录）。

2. 勾勒出您将在此处测试功能的接口（seams）。应优先使用现有接口，而非新建接口。使用尽可能最高的接口。如果确实需要新建接口，请在可实现的位置提出。代码库中越少的接口越好——理想数量为一个。

请与用户确认这些接口是否符合其预期。

3. 根据下方模板编写 PRD，然后将其发布到项目的 issue 跟踪器中。应用 `ready-for-agent` 分诊标签——无需额外的分诊标签。

## 实施决策

已做出的实施决策列表。可包括：

- 将被构建/修改的模块
- 那些将被修改的模块的接口
- 开发者的技术澄清
- 架构决策
- Schema 变更
- API 契约
- 具体交互

请勿包含具体的文件路径或代码片段。它们可能很快就会过时。

例外：如果原型产生了一种能比文字描述更精确地编码某项决策的片段（状态机、reducer、schema、类型形状），请在相关决策内内联该片段，并简要说明其来自原型。应精简至包含决策细节的部分——不是可运行演示，只是重要的内容。

- 将被测试的模块
- 测试先例（即在代码库中类似的测试类型）
