此技能将在用户想要创建重构请求时被调用。您应按照以下步骤操作。如果您认为某些步骤不必要，可以跳过。

1. 向用户提供他们想要解决的问题的详细描述，以及任何潜在的解决方案建议。

2. 浏览代码库以验证他们的断言，并了解当前代码库的状态。

3. 询问他们是否考虑过其他选项，并向他们展示其他选项。

4. 对用户进行关于实现的访谈。务必非常详细和彻底。

5. 明确实现的精确范围。确定您计划要更改的内容和计划不更改的内容。

6. 检查代码库中该代码区域的测试覆盖率。如果测试覆盖率不足，请询问用户他们的测试计划。

7. 将实现分解为一系列微小的提交计划。记住马丁·福勒的建议：“使每个重构步骤尽可能小，以便您始终可以看到程序在运行。”

## 提交记录

一个长而详细的实现计划。用纯英文编写计划，将实现分解为尽可能小的提交。每个提交都应使代码库处于可工作状态。

## 决策文档

已做出的实现决策列表。这可以包括：

- 将要构建/修改的模块
- 将要修改的模块的接口
- 开发者提供的技术澄清
- 架构决策
- 模式更改
- API 合同
- 具体交互

**不包括**具体的文件路径或代码片段。它们可能会很快过时。

## 测试决策

已做出的测试决策列表。包括：

- 描述什么是一个好的测试（仅测试外部行为，而不是实现细节）
- 将要测试的模块
- 测试的先例（即代码库中类似类型的测试）

描述此重构不在范围内的内容。

关于重构的任何其他备注。
