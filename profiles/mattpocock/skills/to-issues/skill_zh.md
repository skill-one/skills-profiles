# 到问题

使用垂直切片（跟踪弹珠）将计划分解为可独立抓取的问题。

问题追踪器和筛选标签词汇表应该已经提供给你了——如果没有，请运行 `/setup-matt-pocock-skills`。

## 流程

### 1. 收集上下文

从对话中已有的上下文开始工作。如果用户将问题参考（问题编号、URL 或路径）作为参数传递，请从问题追踪器中获取它并阅读其完整正文和评论。

### 2. 探索代码库（可选）

如果你还没有探索代码库，请进行探索以了解代码的当前状态。问题标题和描述应使用项目的领域词汇表，并尊重你触及区域的 ADR。

寻找重构代码以简化实现的机会。"让改变变得容易，然后让容易的改变发生。"

### 3. 起草问题

按照 **垂直切片规则** 将计划分解为 **跟踪弹珠** 问题。**大范围重构** 是该规则的例外——使用 **扩展-收缩** 来切片（见 **大范围重构**）。

### 4. 询问用户

将建议的分解以编号列表的形式呈现。对于每个切片，显示：

- **标题**：简短的描述性名称
- **被阻塞**：哪些其他切片（如果有）必须首先完成
- **覆盖的用户故事**：这个问题解决了哪些用户故事（如果源材料有）

询问用户：

- 粒度是否感觉合适？（太粗 / 太细）
- 依赖关系是否正确？
- 是否应该合并或进一步拆分任何切片？

迭代直到用户批准分解。

### 5. 将问题发布到问题追踪器

对于每个批准的切片，使用 **问题正文模板** 将新问题发布到问题追踪器。这些问题被视为已准备好供 AFK 代理使用，因此除非另有指示，否则请使用正确的筛选标签发布它们。

按依赖顺序发布问题（先发布阻塞项），以便可以引用真实的问题标识符。在追踪器支持的情况下，将每个切片链接到其父项作为原生 **子问题**，并将每个阻塞项作为原生 **阻塞边**（问题追踪器文档中的机制）；如果没有，则使用 `## 父项` 和 `## 被阻塞` 正文部分作为备用。

**不要关闭或修改任何父问题。**

## 参考

### 垂直切片规则

每个问题都是一个通过所有集成层端到端切割的薄切片，而不是一层的一个水平切片。

- 每个切片提供一条狭窄但完整的路径，贯穿每一层（模式、API、UI、测试）
- 完成的切片可以单独演示或验证
- 任何重构都应该首先进行

### 大范围重构

**大范围重构** 是一个机械性变更——重命名一个列、重新类型一个共享符号——其 **爆炸范围** 跨整个代码库，一次编辑就会同时破坏数千个调用点，没有任何垂直切片可以变绿。不要强迫它进入跟踪弹珠；按 **扩展-收缩** 顺序进行。首先扩展：在旧形式旁边添加新形式，以便没有任何东西会中断。然后分批迁移调用点，每批的大小由爆炸范围决定（按包、按目录），每批都有自己的问题，被扩展阻塞，保持 CI 每批变绿，因为旧形式仍然存在。最后收缩：一旦没有调用者，就删除旧形式，在一个被每个迁移批次阻塞的问题中。当即使批次单独也无法保持变绿时，保持顺序，但让它们共享一个集成分支，所有分支都阻塞一个最终的集成和验证问题——只有在那里才保证变绿。

对这个垂直切片的简洁描述。描述端到端行为，而不是逐层的实现。
