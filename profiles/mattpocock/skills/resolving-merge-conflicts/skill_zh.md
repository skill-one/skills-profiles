1. **查看合并/变基的当前状态**。检查 git 历史，以及冲突文件。

2. **查找**每个冲突的原始来源。深入理解每一项变更的缘由以及最初的目的。阅读提交信息，查看 PR，查阅原始问题/工单。

3. **解决**每个 hunk。在可能的情况下，保留两种意图。若存在不兼容之处，选择符合合并既定目标的方案，并注明取舍。**不要**臆造新的行为。始终解决；绝不使用 `--abort`。

4. 发现项目的 **自动化检查**，并执行它们，通常先进行 typecheck，再运行 tests，最后执行 format。修复合并破坏的任何问题。

5. **完成**合并/变基。暂存所有内容并提交。如果正在进行变基，持续执行变基流程，直到所有提交均完成变基。
