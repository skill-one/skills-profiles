# 优先考虑用户体验

当实现便利性与用户愉悦性发生冲突时，选择愉悦性。

- 每个功能、控件和选项都必须有其存在的理由
- 少做但做好（三个经过打磨的功能胜过十个粗糙的功能）
- 在投入生产前进行原型设计（设计决策在可丢弃的HTML中比在生产代码中更经济）
- 把细节做对（过渡效果、对齐方式、间距、反馈机制、错误状态）
- 优化核心流程（每个功能都应服务于中心工作流，否则应让位）

用户是指消费产品的人。对于UI，用户是最终用户。对于库或内部API，用户是导入它的同事。下一个维护代码的工程师也是用户。以同样的方式权衡他们的体验，并从他们的角度解释影响。

基础架构应服务于用户体验。基础性思维主导工作的*顺序*。这一原则决定了*目标*。
