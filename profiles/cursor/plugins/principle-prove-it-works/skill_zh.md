# 证明它有效

通过直接检查实际结果来验证每个任务输出。不要从代理、自我报告或“它可以编译”中推断。

**原因：**未经验证的工作存在未知的正确性。间接验证（文件修改时间、输出新鲜度、代理自我报告、缓存截图）感觉比直接观察便宜。根据错误推断采取行动的成本远高于检查源代码。

检查实际结果，而不是代理：
- 直接检查进程活性，而不是通过派生状态间接检查
- 读取实际值，而不是缓存或派生表示
- 当验证失败时，先怀疑观察方法，再怀疑系统

## 在可能的情况下编写检查脚本

最强大的证明是一个可以重复运行相同比较的确定性脚本，而不是一次性的肉眼检查。编写脚本，运行它，并将其输出作为可由审查者重新运行的工件，而不是相信你的话。

保持工件对人类可见。仅对大型或复杂的工作进行提交，其中需要后续进行可审计的轨迹，例如大型移植或迁移（**展示你的工作**技能）。
