# 最大限度减轻读者负担

可维护性是指读者理解代码所需付出的工作。跟踪两个维度：
1. **追踪层级。** 从问题到答案之间有多少层间接引用。
2. **需要保持的状态。** 读者必须保存在脑海中的隐藏或可变上下文有多少。

**原因：** 代码的阅读频率远高于编写频率。代码行数（LOC）、圈复杂度和“干净架构”都是代理指标。读者负担才是关键因素。这两个维度是独立的。一个包含50个全局变量的扁平文件可能和6层适配器堆栈一样难以推理。要同时关注这两个方面。这是[保护上下文窗口](../principle-guard-the-context-window/SKILL.md)的人类类比。对于读者来说，工作内存也是有限的。

**模式：**
- **折叠那些成本大于收益的层级：** 调用者只有一个的包装器、没有第二个实现的适配器、从未需要过的推测性间接引用。将它们内联。
- **使相邻层级改变抽象。** 重复相同方法和参数的层级会增加读者负担而不提供压缩。折叠传递式层级。
- **要求接口压缩。** 隐藏很少复杂性的宽泛接口会使读者学习表面和实现。优先选择隐藏有意义决策的边界。
- **缩小状态作用域：** 优先选择纯函数（返回值优于修改）、局部变量优于字段、字段优于模块状态，以及模块状态优于全局变量。通过派生而不是同步来实现。
- **在边界处命名不变量，而不是在每个消费者处，这样读者只需学习一次。**
- 在添加层级或状态之前，问自己：这是否通过至少相同的方式减少了其他地方的读者负担？

**测试：** 新读者是否能在30秒内回答“X来自哪里？”和“什么可以改变X？”？如果不能，就削减层级或削减状态。
