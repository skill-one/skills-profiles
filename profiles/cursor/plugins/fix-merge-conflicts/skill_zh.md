# 解决合并冲突

## 触发条件

分支存在未解决的合并冲突，需要一条可靠的路径使其达到可构建状态。

## 工作流程

1. 从`git status`和冲突标记中检测所有冲突文件。
2. 以正确性优先为原则，对每个冲突进行最小化修改。
3. 在安全的情况下优先保留双方变更。否则，选择能够编译且保持公共行为稳定的变体。
4. 使用包管理工具重新生成锁文件，而不是手动编辑。
5. 运行编译、代码检查及相关测试。
6. 提交已解决的文件并总结关键决策。

## 安全准则

- 保持变更最小化且易于阅读。
- 任何文件中不得保留冲突标记。
- 解决冲突期间避免进行大规模重构。
- 冲突解决期间不得推送或打标签。

## 输出结果

- 已解决的文件
- 值得注意的解决方案选择
- 构建及测试结果
