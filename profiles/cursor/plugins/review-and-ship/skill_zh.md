# 审核并发送

## 触发条件

在发送前审核变更。关闭关键问题，验证行为，并打开或更新一个 PR。

## 工作流

1. 收集上下文：与基础分支进行 diff，查看未提交的变更，最近的提交，已更改的文件，以及从最近的关联聊天中获取用户意图（如果有用）。
2. 运行针对更改行为的测试。如果没有专注的测试，决定是否添加它们或记录差距。
3. 审核正确性、回归、安全性和意图匹配。对于较大的 diff，使用并行子代理。
4. 在最终确定前修复关键问题，并重新运行受影响的测试。
5. 提交选择性的文件，并附上简洁的消息。
6. 推送分支并打开或更新 PR。

## 建议检查

```bash
git fetch origin main
git diff origin/main...HEAD
git status
gh pr checks --json name,bucket,state,workflow,link
```

## 指导原则

- 优先考虑正确性、安全性和回归，而不是仅针对样式的评论。
- 保持提交聚焦，避免无关文件变更。
- 如果预提交检查失败，修复问题而不是绕过钩子。
- 使用 `gh pr checks` 而不是仅 GitHub Actions 命令，来评估 PR 的准备情况。

## 输出

- 问题总结（关键、警告、注意）
- 运行的测试和结果
- PR URL
