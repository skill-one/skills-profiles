# 修复 CI

## 触发条件

分支或 PR 的 CI 失败，需要快速、迭代的路径来变为绿色检查。

## 工作流程

1. 解决当前活跃的 PR，并检查 `gh pr checks --json name,bucket,state,workflow,link`。
2. 检查失败的作业，并提取第一个可操作的错误。在可用的情况下使用 GitHub Actions 日志；否则使用检查链接来识别失败的命令或服务。
3. 应用最小的安全修复。
4. 推送，重新检查 PR 检查集，并重复直到变为绿色。

## 安全措施

- 一次修复一个可操作的失败。
- 优先进行最小化、低风险的更改，然后再进行更广泛的重构。
- 将 `gh pr checks` 作为 PR CI 状态的权威来源。

## 输出

- 主要失败的作业和根本错误
- 迭代顺序中应用的修复
- 当前 CI 状态和下一步操作
