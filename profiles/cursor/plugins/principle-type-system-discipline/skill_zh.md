# 类型系统规范

类型检查器是一个证明助手。利用它来在编译时消除不可能的状态、不匹配的原语和未处理的变体。当一个类型让你可以忽略的情况变成了编译器本可以阻止的运行时错误。优先于无节制地增加处理程序来定义错误和特殊情况使其不存在。不可表示的状态、全函数和界面重构（下文中的模式）是工具。

适用于任何带类型语言。像 `typescript-best-practices` 这样的技能将其与特定语法相结合。

**模式：**

- **使非法状态不可表示。** 将变体建模为和类型：TypeScript 中的区分联合、Rust/Swift/Kotlin 中的带有效载荷的枚举、Scala 中的密封类、Haskell/OCaml 中的代数数据类型。不要将状态建模为可选字段的集合，其中矛盾的组合可以编译。一个微妙的反模式：`{ completed: boolean; completedAt?: Date }` 允许 `completed: true; completedAt: undefined`，这是无意义的。从单一来源推导出布尔值，例如 `completedAt !== null`，或者显式地将变体建模为 `{ kind: 'open' } | { kind: 'done'; at: Date }`。如果错误迫使问题“等等，这个组合真的会发生吗？”，那么类型就太松了。
- **类型是构造，不是限制。** 从你想要的值构建类型，而不是从更松散的类型中用检查切割它们。似乎需要精炼类型的不变量通常是可以通过构造来实现的。非空列表是头部加上尾部，而不是带有长度检查的列表。有效的时间范围是开始加上持续时间，而不是必须保持顺序的两个时间戳。没有特权表示。如果将列表解释为偶数长度，那么列表对偶元组就是偶数长度的，所以选择无法构建非法值的形状，并在顶层暴露调用者需要的接口。
- **标记语义原语。** `UserId` 和 `OrderId` 在底层是字符串，但不应该可以互换。Rust 中的 Newtypes、Swift 中的不透明类型、Kotlin 中的值类、Haskell 中的幻影类型、TypeScript 中的标记交集。在创建时验证一次，然后在下游信任类型。
- **外部数据在解析前是无类型的。** RPC 负载、JSON、IPC 消息、CLI 参数、配置文件、环境变量、数据库行。在每一边界都有一个解析函数，将非结构化输入转换为类型化模型。参见 **边界规范** 技能，了解在哪里放置验证。
- **不要欺骗类型系统。** 强制转换、不安全的强制转换和绕过编译器的断言函数是潜在的运行时崩溃。如果编译器无法证明一个事实，就证明它（验证、缩小、精炼模型），或者接受强制转换是有风险的。
- **穷尽匹配是编译器的工作。** 当你在和类型上匹配时，如果添加了新的变体而没有处理，编译器必须失败编译。使用你的语言提供的惯用法：TypeScript 中的 `never`-类型绑定、Rust 中的未注解 `match`、Haskell 中的 `-Wincomplete-patterns`、Kotlin 中的密封类匹配穷尽性。
- **从权威模式推导类型。** 当协议缓冲区、OpenAPI 规范、GraphQL 模式、数据库迁移或设计系统标记文件定义了形状时，从它派生而不是手工制作一个平行的类型。参见 **在结构中编码教训** 技能。
- **仅在部分性出现的地方加强类型。** 运行时断言、空检查或“这永远不会发生”的抛出标记了类型太弱的地方。将这个检查向上推到类型中。然后停止。类型系统的工作是跟踪每个使用位置必须处理的案例，而不是尽可能精确地描述数据。优先于全函数。空列表的 `sum` 是 0，所以它接受普通的列表。空列表的 `head` 没有答案，所以它要求非空的。

**测试：**

- “我能写一条注释解释何时这个字段组合是有效的吗？” 如果可以，类型太松了。将其拆分为和类型。
- “我的两个函数参数共享一个原语类型，但含义不同吗？” 标记它们。
- “这个 `any`、这个 `as`、这个 `assertNotNull` 从哪里来的？” 追踪到边界并在那里验证。
- “如果下个月添加了新的变体，编译器会告诉下一个代理在哪里添加案例吗？” 如果不，匹配就不穷尽。
- “这个类型是否重复了另一个文件拥有的形状？” 派生而不是复制。
- “我是在加强这个类型以保持操作的全局性，还是仅仅为了更精确？” 如果否则会导致恐慌，保留普通类型。
