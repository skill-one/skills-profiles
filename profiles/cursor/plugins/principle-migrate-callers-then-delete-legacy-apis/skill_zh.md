# 先迁移调用者，再删除遗留 API

当我们确定新的 API 是正确的设计时，应在同一次重构浪潮中迁移调用者并移除旧的 API，而不是保留兼容性层。

**规则：**
- 不要仅仅因为内部调用者仍然存在就保留遗留 API 路径
- 列出调用者，迁移它们，并立即删除旧的 API
- 将临时适配器视为例外情况和时间限制的，而不是默认架构
- 更新测试以断言新的契约，并删除仅保护重构前实现细节的测试

**适用情况：**
- 没有外部用户依赖于向后兼容性
- 项目可以承受协调的破坏性变更
- 新的 API 是简化或重构计划的一部分

保留旧 API 和新 API 会产生双路径复杂性，减慢清理速度，并使代码库感觉像是追加式的。
