# Swarm

并行启动 N 个云工作节点。它们可以覆盖不同的切片，竞争相同的任务，或两者混合。父节点等待、聚合，并返回一份报告。

## 启动

在启动任何东西之前，打开一个待办事项列表，每个阶段一条记录。

1. 架构
2. 并行启动
3. 聚合
4. 报告

## 阶段 A：架构

1. 声明完成的谓词以及集群必须返回的工件或报告。
2. 选择形状。切片划分、N 个工作节点竞争相同任务，或两者混合。对于竞争或混合形状，在启动前声明 `首次通过`、`全部排名` 或 `最佳`。
3. 从用户设置或根据形状推导 N。N 是总工作节点数，不是云并发限制。
4. 从 `~/.cursor/rules/pstack-models.mdc` 中的 `swarm workers` 行选择工作节点模型。如果规则或该行缺失，使用 `grok-4.7-xhigh-fast`。对于 `auto` 或 `inherit-parent`，省略 `model` 以使工作节点在父节点模型上运行。如果任务工具拒绝 slug，使用默认值并说明。如果它拒绝默认值，使用其错误信息中相同系列的最近有效 slug。对于模型竞争，提前命名每个分支的模型。
5. 当工作节点写入时，为其提供可写的输出。当工作节点验证或测量提交时，每个任务明确命名确切的 SHA。测量任务还命名方法（样本数量、一个样本是什么、顺序）。工作节点在其结果中记录这两者。

## 阶段 B：并行启动

使用 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true` 和第 4 步的模型（对于 `auto` 或 `inherit-parent` 则省略），在一个消息中并行启动所有 N 个工作节点。仅当工作节点需要访问用户计算机上的内容时，使用 `environment: "local"`。

当工作节点必须从非默认推送分支启动时，传递 `cloud_base_branch`。

每个任务独立存在。包括目标、范围、确切的切片或竞争分支、验证方法以及报告内容。报告使用 `PASS`、`ISSUES` 或 `BLOCKED` 并附带证据。能够证明缺陷的工作节点报告 `ISSUES` 并列出其能证明的所有问题，而不仅仅是第一个。

如果工作节点退出，继续使用 N-1 个并记录该情况。

## 阶段 C：聚合

读取终端结果。丢弃未记录其任务命名的 SHA 和方法的结果，并重新运行该工作节点一次。第二次失败后，记录一次中断。中断不计为通过。对于覆盖率，每个必需的切片都需要一个结果。对于竞争，应用事先声明的选择规则。使用首次通过、全部排名或最佳。不要粘贴原始工作节点转储。

保持一个紧凑的结果表、一条线证据问题以及明确的中断或退出。

## 阶段 D：报告

返回一份整合的聊天报告，包含表格、问题一条线、中断或退出，以及竞争规则（如果使用）。
