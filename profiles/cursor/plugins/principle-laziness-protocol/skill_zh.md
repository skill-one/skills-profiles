# 懒惰协议

以最少的代码和复杂度实现最大的效果。

- **优先删除。** 当被要求重构或改进时，先寻找删除项，再考虑添加项。
- **保持扁平的调用层级。** 避免深层的调用链。一个隐藏了大量工作的丰富接口并不是深层的调用链。如果回答一个问题需要追踪超过3个文件或层级，就将其扁平化。
- **合并决策。** 不要在多个地方重复相同的选项。将其放在一个单一的事实来源后面，并将结果作为一个简单的标志传递。
- **最小化差异。** 做最小的改动以解决问题。更少的代码行比“优雅”的样板代码更优。
- **质疑线程。** 如果一个任务要求你通过类型、模式、管道或类似的层传递一个新的信号，停下来寻找更直接的路径。
- **关注小漏洞。** 在小通道、表示漏洞和重复选择扩散之前将其移除。小漏洞会累积成永久性的协调成本。

**测试：** 如果一个人类开发者会觉得代码难以维护，那么这就是一个糟糕的解决方案。
