# 摸清状况

当任务与任何剧本都不匹配时，设计一个剧本。在编写任何代码之前，交付物本身就是工作流程本身：一个按任务规模调整严谨性的阶段序列，运行科学方法，并在人离开后留下可供人类审计的决策轨迹。

## 开始

打开一个待办事项列表，其中第一项是阅读 **poteto-mode** 技能的“原则”部分。然后添加下面的阶段作为待办事项。

## 阶段 A：构建框架

先立足基础，再进行承诺。在开始运行之前，你必须能够陈述：

- 可证伪的完成定义（**prove-it-works** 原则技能）。
- 范围，量化：粗略的单位和工作量，以及暴露的阻碍因素。
- 严谨性级别，偏向较高。单向门和高影响范围会获得更多。可逆的低风险步骤会获得较少。严谨性是门禁和工件，而不是“加倍努力”。

在承诺进行长时间运行之前，呈现框架和权衡。可逆的工作继续进行（**never-block-on-the-human** 原则技能），但多小时的运行会获得一个检查点。

## 阶段 B：设计工作流程

分解为原子、可独立部署的单元。按风险最高的未知项优先进行排序。基础构建和验证先于功能（**foundational-thinking** 原则技能）。

- 在工作之前构建验证 harness，从变更前的状态捕获基线，以便检查读作“旧值 vs 新值”。
- 对于单向门设计决策，运行 **architect** 技能（它运行 **arena**）。对于形状已经具体明确的机械工作，可以跳过它。在已确定的设计上运行第二个 arena 是过度设计（**laziness-protocol** 原则技能）。
- 决定什么会发散。仅在接缝之间并行化，并为每个工作项提供自己的工作树或分支（**separate-before-serializing-shared-state** 原则技能）。不要过度发散。
- 将设计好的阶段列表记录下来。这个列表是供人类审查的。

然后执行设计。将其步骤添加到待办事项列表中，作为具体项，在阶段 C 条目之后、阶段 D 之前。在阶段 C 的循环纪律下运行每个步骤，并将阶段 D 的日志编织到它们中，每一步成功部署为一行，而不是在最后保存整个轨迹。

## 阶段 C：运行循环

每个单元都是一个实验。陈述假设，进行最小变更，根据真实工件上的谓词进行测量，如果它取得了进展就保留它，如果没有就回滚它。
应用 **sequence-verifiable-units** 原则技能，在开始下一个单元之前验证每个单元，而不是在最后批量检查。

- 通过检查工件来验证，而不是自我报告。当某件事太容易通过时，怀疑观察方法而不是系统。
- 将委托工作与裁判配对。如果工作项操纵了门禁，重置并强化合同。如果门禁本身是错误的，在它自己的变更中修复门禁，而不是绕过它。
- 判决是已验证、未验证或未决。未决不是通过。不要隐藏负面结果。

## 阶段 D：保留审计轨迹

通过 **show-me-your-work** 技能记录运行。figure-it-out 的工作通常足够雄心勃勃，以至于可以提交轨迹，以便审查者可以在 PR 中阅读它。轨迹加上差异是让人类回来并信任工作的关键。

## 阶段 E：验证并交回

将整个内容与阶段 A 的谓词在真实产品上进行检查，而不仅仅是 harness。将任何重复的更正编码为门禁、lint 规则、检查或脚本（**encode-lessons-in-structure** 原则技能）。

**回复：** 你设计的剧本、严谨性级别和原因、决策轨迹路径、已验证谓词的内容，以及仍然开放的内容。
