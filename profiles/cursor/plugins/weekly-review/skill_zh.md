# 每周回顾

## 触发条件

需要每周发布工作的回顾，用于状态更新、回顾或规划。

## 工作流程

1. 从仓库配置中确定当前的git用户邮箱。
2. 在主分支上下文中收集过去7-10天内提交的代码。
3. 排除合并提交。
4. 将有意义的变更归纳为2-5个简洁的要点。
5. 添加一段简短的分类段落，涵盖：
   - 可能的bug修复
   - 可能的技术债务工作
   - 可能的新功能

## 指导原则

- 保持回顾简短且适合高管阅读。
- 所有声明仅基于提交历史和差异。
- 如果git邮箱缺失，提示用户在继续前设置邮箱。

## 输出

- 2-5个要点的每周总结
- 简短分类段落（bug修复 / 技术债务 / 新功能）
