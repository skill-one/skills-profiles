# 运行冒烟测试

## 触发条件

在变更之前或之后需要进行端到端的冒烟验证。

## 工作流

1. 为目标应用构建前置条件。
2. 运行相关的冒烟测试套件或一个聚焦的测试文件。
3. 如果失败，检查跟踪日志并隔离根本原因。
4. 应用最小化修复并重新运行，直到稳定。

## 示例命令

```bash
# 运行完整的冒烟测试套件
npm run smoketest

# 运行特定的冒烟测试文件
npm run smoketest -- path/to/test.spec.ts

# 当构建产物已准备好时进行更快的迭代
npm run smoketest-no-compile -- path/to/test.spec.ts
```

## 安全规范

- 优先使用确定性的等待和断言，而不是脆弱的超时。
- 重新运行通过修复以减少易出错的假阳性。
- 仅在明确请求并记录的情况下隔离测试。

## 输出

- 测试结果摘要
- 根本原因和修复方案
- 剩余的易出错风险（如有）
