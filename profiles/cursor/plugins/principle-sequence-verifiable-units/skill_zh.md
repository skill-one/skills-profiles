# 将工作序列化为可验证的单元

将工作按一系列小的单元来排序，每个单元都以一个你可以检查的状态结束，并且在当前单元变为绿色之前不要继续前进。

**原因：** 在导致问题的单元处捕获中断是易于定位的。在批量处理之后捕获中断则会被掩盖，并且你已经在一个已经损坏的基础上构建了更多内容。将这些相同的单元序列化为一个评审者可以重放的交付，可以将“我相信”转变为“观察它从红色变为绿色”。

**执行。** 在一次扫除、迁移或任何类似的编辑运行中，在开始下一个更改之前验证每个更改。每个单元是一个前后括号：已知的良好状态，一个更改，运行检查，然后继续。首先在干净的干支上进行变基，以便每个检查都针对真实的基线进行衡量。当杠杆执行编辑时，每个单元的检查几乎是免费的。无论如何都要运行它。

**交付。** 按照能够证明工作的顺序堆叠提交和 PR。规范形状是首先失败的测试，然后在顶部进行修复。其他故事顺序是在重塑之前进行减法，在处理之前捕获基线，在功能之前构建脚手架。每个提交都独立落地，并且序列读起来像是一个论点。

这是 **prove-it-works** 原则技能的序列化补充，该技能保持每个检查都是真实的，以及 **build-the-lever** 原则技能的序列化补充，该技能使每个单元的检查变得廉价。
