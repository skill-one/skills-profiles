# 在序列化之前分离共享状态

当并发协作者可能共享可变状态时，首先询问他们是否需要相同的可变对象。如果不需要，则消除共享。当共享是真实存在时，应结构化地强制执行序列化：锁文件、顺序阶段、独占所有权。指令和约定不是并发控制。

**原因：** 对共享状态的并发写入会创建间歇性、难以复现且昂贵难以调试的竞态条件。

**模式：**
1. **识别共享的可变状态**（同时读取和写入的文件、同时推送的分支、同时定义和消费的API）。
2. **默认：消除共享写入目标。** 询问：这些协作者是否需要一个规范对象，或者它们是在发布独立事实？为每个协作者分配其自己的拥有文件、键、分支或状态目录，仅在读取/报告边界处合并。两个工作线程将自己的`lastX`字段写入一个`state.json`仍然是共享变异。`indexer-state.json` + `metrics-state.json` 就不是。
3. **只有当共享写入目标是一个真正的不变量时，结构化地序列化访问**（锁文件、顺序阶段、单一写入者协作者或原子比较并交换）。将“我们需要一个锁”视为需要检查的设计迹象，而不是默认答案。
