# 询问

为每个配置的模型生成一个审查者，以对抗性地审查代码变更。每个模型都获得相同的提示和评分标准。对抗性信号来自模型多样性，而非分配的角色。

交付成果是一个综合性的裁决。**不要自动应用变更**。

## 第 1 步，确定范围

根据上下文确定要审查的内容：

- 如果用户指向特定文件或差异，则使用这些内容
- 如果在功能分支上，运行 `git diff main...HEAD`（或适当的基础分支）以获取完整的变更集
- 如果用户的消息引用了近期的工作，收集相关文件

将差异（或文件内容）以及审查者需要理解代码的任何周边上下文文件打包。

## 第 2 步，陈述意图

在生成审查者之前，明确陈述意图。从以下内容中推导出：

- 用户的消息
- 提交信息
- 如果存在 PR 描述，则使用 PR 描述
- 代码本身

写一个清晰的段落。如果你不确定意图，请在继续之前询问用户。

## 第 3 步，生成审查者

使用任务工具在单个消息中启动所有审查者。在 `~/.cursor/rules/pstack-models.mdc` 中的 `interrogate reviewers` 行中使用，每个条目一个审查者，扩展或缩减下方的 Reviewer A/B/C 标签以匹配配置的条目数量。如果规则或该行缺失，则使用表格默认值。

| 子代理 | 默认模型 |
|--------|----------|
| Reviewer A | `claude-opus-5-5-max` |
| Reviewer B | `gpt-5.6-sol-max` |
| Reviewer C | `grok-4.7-xhigh-fast` |

对于每个审查者：
- `subagent_type`: `generalPurpose`
- `model`: 配置的 `interrogate reviewers` 条目，或表格默认值（如果没有配置的条目）。对于 `auto` 或 `inherit-parent` 条目，省略 `model`，以便审查者在父模型上运行。
- `readonly`: `true`

如果任务工具拒绝配置的条目，则在其家族的表格默认值上运行该审查者，并说明。家族按前缀区分：`claude-*`、`gpt-*` 和 `grok-*`。如果没有匹配的家族，则使用 Reviewer A 的默认值。如果它拒绝表格默认值，请检查任务工具错误消息中的有效 slugs，选择最接近的等效项（优先选择同一家族中推理层级最高的），使用它生成，并打开一个单独的 PR 来更新默认表格。不要因 slugs 问题阻塞审查。永远不要将别名条目视为被拒绝的 slug，也不要将其应用于任何回退。

阅读 `references/reviewer-prompt.md` 并用以下内容填充模板：
1. 陈述的意图
2. 差异或文件内容
3. 来自 `references/rubric.md` 的审查评分标准
4. 来自 `references/code-quality-review.md` 的代码质量透镜

相同的填充模板将发送给所有审查者，因此每个模型都应用代码质量透镜。

## 第 4 步，综合

随着结果返回，构建一个统一的画面：

1. **解析所有发现**来自审查者
2. **识别共识**。由 2 个或更多模型独立提出的发现具有最高信号。
3. **识别单模型发现**。仍然值得阅读，但需相应权衡。
4. **去重**。不同的模型可能以不同的方式描述相同的问题。合并这些问题并注明哪些模型提出了它。
5. **记录分歧**。如果一个模型标记了某项内容，而另一个模型明确表示相反，这为裁决提供了有用的上下文。

## 第 5 步，主导裁决

你是主导审查者，一个务实的资深工程师，而不是一个中立的聚合器。

阅读 `references/lead-judgment.md` 获取完整框架。

使用以下桶对每个发现进行分类：

- **采取行动**。实际影响正确性、安全性或可维护性的问题，考虑到实际目标。这些会阻止一个真实的 PR。
- **考虑**。合法的观点，但你不确定它们是否值得现在解决。值得用户的关注。
- **已记录**。技术上有效但不可操作。上下文相关、过早优化或当前阶段影响较低。
- **驳回**。错误、吹毛求疵或缺少上下文。简要说明原因。

对于每个发现，包括：
- 哪个模型（或哪些模型）提出了它
- 类别（采取行动 / 考虑 / 已记录 / 驳回）
- 对分类的简要理由

## 输出格式

以以下结构呈现裁决：

### 意图
> [来自第 2 步的陈述意图段落]

### 审查者
- Reviewer [标签]: [模型名称], [N 个发现]（每个审查者一条要点）

### 采取行动
[应解决的发现。对于每个：描述、哪些模型提出了它、为什么它很重要。]

### 考虑
[值得思考的发现。对于每个：描述、哪些模型提出了它、权衡涉及的内容。]

### 已记录
[有效但优先级较低。简要列表。]

### 驳回
[被拒绝的发现及其简要理由。]

### 一致性图
[模型在哪里达成一致，在哪里分歧，以及一致/分歧的模式告诉我们什么？]
