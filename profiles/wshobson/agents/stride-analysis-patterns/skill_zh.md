# STRIDE 分析模式

使用 STRIDE 方法论进行系统化威胁识别。

## 使用此技能的场景

- 开始新的威胁建模会话
- 分析现有系统架构
- 审查安全设计决策
- 创建威胁文档
- 对团队进行威胁识别培训
- 合规和审计准备

## 核心概念

### 1. STRIDE 类别

```
S - 欺骗       → 身份验证威胁
T - 篡改       → 完整性威胁
R - 拒绝       → 无法否认威胁
I - 信息       → 机密性威胁
    泄露
D - 拒绝服务    → 可用性威胁
E - 特权提升    → 授权威胁
    特权提升
```

### 2. 威胁分析矩阵

| 类别            | 问题                                  | 控制类别 |
| --------------- | ----------------------------------------- | -------------- |
| **欺骗**        | 攻击者能否伪装成他人？                | 身份验证 |
| **篡改**       | 攻击者能否修改传输/静态中的数据？      | 完整性      |
| **拒绝**       | 攻击者能否否认操作？                | 日志/审计  |
| **信息泄露**    | 攻击者能否访问未授权数据？            | 加密     |
| **拒绝服务**    | 攻击者能否中断可用性？              | 速率限制  |
| **特权提升**    | 攻击者能否获得更高权限？              | 授权  |

## 最佳实践

### 应做

- **涉及利益相关者** - 安全、开发和运维的视角
- **保持系统化** - 覆盖所有 STRIDE 类别
- **现实优先级** - 专注于高影响威胁
- **定期更新** - 威胁模型是活文档
- **使用视觉辅助** - 数据流图有助于沟通

### 不应做

- **不要跳过类别** - 每个类别揭示不同威胁
- **不要假设安全** - 质疑每个组件
- **不要孤立工作** - 协作建模更好
- **不要忽略低概率** - 高影响威胁很重要
- **不要止步于识别** - 跟进缓解措施
