# 视觉编辑精度

## 概述

当变更请求伴随视觉上下文（元素选择、注释、截图）时，进行有针对性、最小的编辑。精度胜于雄心：仅修改指示的部分，保留其他所有内容。

## 流程

当提供视觉上下文时：

1. **识别** - 指示了哪些具体的元素？它们属于哪个组件文件？
2. **范围** - 仅修改指示的部分。不要重构周围代码。
3. **保留** - 保留现有的样式、类和行为。仅修改请求的部分。
4. **针对性** - 进行实现视觉结果的最小 CSS/标记更改。
5. **验证** - 确认更改正确渲染且没有副作用。

## 关键原则

### 精度胜于雄心

视觉上下文给出一个具体的元素。不要：
- 当仅请求一个样式时，重构整个组件
- 当仅指示外观时，更改组件的 API
- 当仅选择视觉效果时，触碰逻辑

要：
- 找到选中元素的确切文件和行
- 进行实现描述的视觉更改的最小编辑
- 保留所有现有行为、事件处理程序、可访问性

### 多次编辑

当出现多个视觉编辑请求时：
- 每个请求独立针对自己的元素
- 不要等待一个完成后再处理另一个
- 如果两个编辑冲突（相同元素，不同请求），处理最新的请求

## 常见错误

- 当用户仅指向一个按钮时，重写整个组件
- 当仅需要调整一个元素的颜色时，更改全局配置
- 通过添加固定宽度来匹配选择，破坏响应式行为
- 忽略特异性（用户指示了一个卡片，代理更改了所有卡片）
- 在视觉编辑期间移除可访问性属性（aria-*, role, tabindex）
