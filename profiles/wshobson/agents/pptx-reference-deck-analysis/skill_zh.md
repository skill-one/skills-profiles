# PPTX参考演示文稿分析

将参考演示文稿作为设计证据进行审查。这项技能永远不会复制、克隆或修改源演示文稿。

## 合同

按需实现所需的提取，使用一个小的本地`python-pptx`脚本。仅捕获新演示文稿所需的信息：

- 紧凑的提示上下文：幻灯片数量和大小、文本摘要、形状数量、样式、品牌信号、模板使用和布局节奏；
- 完整提取：`summary`、幻灯片和只读的`layout_tree`证据；
- 文件夹诊断：每个演示文稿一个结果加上一个清单；
- 样式主分析：颜色、字体、大小分布、主/布局使用和流程模式；
- 派生模板目录：基于零的源索引、布局角色、可用区域、占位符、视觉结构和约束。

## 规则

- 保持源演示文稿只读，并独立编写每个目标幻灯片坐标。
- 仅使用捆绑的OOXML工具处理原始主题、关系、注释、评论、动画、媒体、主控或布局，这些高级提取无法暴露。
- 在分析清单中记录审查部分和解析异常。
- 未经明确许可和许可证证据，不要在生成的演示文稿中使用提取的内容、字体、图像或专有资产。

## OOXML包审查

在使用捆绑工具之前，从`requirements.txt`安装`defusedxml`。

1. 运行`scripts/inspect.py <deck.pptx>`以获取幻灯片顺序、文本、主题令牌、关系、注释、评论、动画和媒体的紧凑JSON报告。
2. 运行`scripts/validate_package.py <deck.pptx> --output <report.json>`以检查格式错误的XML、损坏的内部关系、内容类型空白、重复布局链接和孤立部分。
3. 仅在需要原始包证据时运行`scripts/unpack.py <deck.pptx> <output-dir>`。
4. 相对于`.rels`所有者解析关系目标；切勿从文件名推断幻灯片顺序。

### 安全性

- 不要修改提供的演示文稿或盲目将包部分复制到新演示文稿。
- 从受信任的工作区运行脚本；它们会拒绝路径遍历、符号链接、过大的成员和存档炸弹。
- 使用`defusedxml`解析不受信任的XML；不要启用实体扩展、DTD加载或网络访问。
- 除非与配色方案完全解析，否则将主题颜色视为令牌。

有关输出形状，请参阅`references/reference-deck-analysis.md`；有关仅用于文档的模式，请参阅`references/reference-deck-analysis-patterns.md`；有关包部分映射，请参阅`references/ooxml-parsing.md`。
