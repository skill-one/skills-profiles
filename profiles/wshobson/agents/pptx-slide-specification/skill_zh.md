# PPTX 幻灯片规范

作者直接在 `layout_tree` 中指定最终坐标。任何渲染器在审核后都不得决定位置、缩小文本或推断布局。

## 必须的契约

- 根 JSON 包含 `summary` 和 `slides`。
- 每张幻灯片都有一个稳定的 `id`、以消息为主导的 `title`、可访问性阅读顺序以及完整的 `layout_tree`。
- 布局树声明幻灯片大小、根组、id键值组与对象、最终英寸边界框、样式、z-index 值和分类。
- 每个有意义的对象都有 `id`、`kind`、`role`、`classification`、`content`、`style`、`bbox` 和 `z_index`。
- 生产 `summary` 包含明确的 `layout_policy`（安全边距、内容底部、页脚顶部、最小间距）和可访问性元数据。

## 作者规则

1. 使用稳定的可读 ID、绝对组以及正英寸尺寸。
2. 将普通内容保持在安全边距内且在页脚轨道上方。仅背景 `layout_design` 对象可以全屏显示。
3. 使用原生 `text`、`shape`、`line`、`table` 和 `image` 对象。从任何支持性视觉元素中重新创建标签和值作为原生对象。
4. 为有意义的图像提供替代文本。记录 `source_ref` 以便引用来源。
5. 保持内容文本在 9 pt 或更大；在减小字体之前缩短、调整大小或拆分密集内容。
6. 使用共享网格、一致的间距、明确颜色、明确字体大小和有意设置的 z-order。

## 构建契约

任务本地的构建器从空白幻灯片布局开始，并使用 `Inches(...)` 映射所有边界框。明确设置换行、禁用自动大小、文本内边距、锚点、对齐方式、字体、颜色、线条设置、图像长宽比和隐藏幻灯片状态。在添加对象之前拒绝零或负几何形状。

参考 `references/layout-contract.md` 获取紧凑型模式和修复指南。
