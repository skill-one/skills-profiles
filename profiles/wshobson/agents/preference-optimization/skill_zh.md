# 偏好优化

这项技能假定 `finetuning-method-selection`
已经路由到这里，因为数据形状是偏好对或无配对的点赞/点踩反馈，而不是演示（那是
`lora-qlora-recipes`）或可验证的奖励信号（那是 `grpo-rlvr-training`）。以下是在 DPO 家族中选择方法、选择多少证据表明该选择实际上很重要、生产训练模式以及如何构建对本身的方法。

**输入：** 一个路由决策（偏好优化）加上偏好对或无配对反馈，通常来自一个 SFT 检查点。
**输出格式：** 一个经过验证的方法选择加上一个配置——`references/method-configs.md` 中的 kwarg 值，而不是自由形式的建议——`llm-finetuning-training-engineer`
直接消耗的。

## 方法选择

| 数据形状 | 方法 | 关键参数 |
|---|---|---|
| 偏好对，默认情况 | **DPO** | β=0.1，LR 5e-7–1e-6，1–2 个 epoch |
| 内存限制或没有 SFT 检查点 | **ORPO** | 无参考，融合 SFT+偏好在一个损失中 |
| 无配对的点赞/点踩 | **KTO** | 每个示例一个二元标签，不需要配对 |
| 观察到长度偏差，有扫描预算 | **SimPO** | 无参考；见下方的扫描网格 |

- **DPO 是安全的默认值。** 使用 β=0.1 和 5e-7 到 1e-6 的学习率进行 1–2 个 epoch。
  这个 LR 比产生检查点的 SFT LR *低*——将 SFT 规模的 LR 移植到 DPO 运行中是这里最常见的配置错误，而不是边缘情况。
- **ORPO** 在内存是限制时路由进来，或者在没有单独 SFT 检查点的情况下开始——它是无参考的，并将 SFT 和偏好目标融合到一个损失中，跳过单独的 SFT 遍历和 DPO 携带的参考模型内存成本。
- **KTO** 在反馈是无配对的二元信号（点赞/点踩）而不是匹配的偏好对时路由进来——不要强迫无配对反馈进入合成对以使用 DPO 代替。
- **SimPO** 修复了 DPO 的长度偏差，但只有在有纪律的扫描时才会奏效——它的公布收益是在调整扫描下报告的极限，而不是任何单个配置都会重现的基线。只有在有扫描预算时才路由到这里；如果没有，则使用 DPO 代替。
- **经典的 RLHF（奖励模型 + PPO）在前沿实验室之外已退役。** 不要在生产管道中寻求它——上述每种方法对于相同的数据形状来说都更便宜且有更好的支持。

### 实例

- *"我们有一个 SFT 检查点和干净的偏好对数据，还没有长度偏差投诉。"*
  → 默认情况 → **DPO** 在 β=0.1。
- *"审稿人针对每个回复点击点赞/点踩；没有任何配对。"* → 无配对信号 →
  **KTO**，不是 DPO — 不要合成对以将 DPO 强制用于无配对数据。
- *"GPU 预算不足以覆盖单独的 SFT 遍历加上 DPO 参考模型。"* → 内存限制，没有单独的检查点 → **ORPO**。
- *"DPO 输出倾向于更长的答案，无论质量如何，并且有时间运行扫描。"* →
  长度偏差加上扫描预算 → **SimPO**。如果没有扫描预算实际上存在，则跳过它。

## 低杠杆的真相

一项 2026 年 240-H100 运行的研究（arXiv 2603.19335）是上表中负载承载证据：**损失函数选择大约值 1 个百分点的杠杆，模型规模大约值 50。** 20 个 DPO 变体中没有一个超过普通的 DPO。排名也 **随着规模反转**——在小规模试点中获胜的变体在部署规模下可能会失败。

两个实际后果：

- 不要在路由决策上为 DPO 变体烘烤而苦恼。上表就足够了；更深的变体选择与数据质量和规模相比是低杠杆的。
- **在信任排名之前在部署规模进行验证。** 在小规模试点模型上运行的方法比较不会转移到生产规模类别——一旦规模变化，需要重新检查赢家。

这也是为什么上面的方法选择表故意很短：它编码了 ~1pp 杠杆，而不是 DPO 变体的排名，而同一项研究表明这个排名在规模上并不成立。将任何不在该表中的变体选择建议——包括声称特定变体“获胜”的建议——视为未经证实，直到它在目标部署规模下得到验证。

## 生产模式：迭代策略 DPO

对静态偏好数据集的单次离线 DPO 遍历只是一个起点，而不是生产模式。策略会随着训练的进行偏离对被采样的分布，而静态数据集会相对于这种漂移而过时。生产管道迭代和策略运行 DPO 而不是：

1. 从当前策略检查点采样完成。
2. 评分或排序完成（奖励模型、裁判或任务评分器）。
3. 运行一个 DPO 遍历，使用当前检查点作为参考模型。
4. 结果检查点成为新的策略 *和* 下一个回合的新参考。

重复。每一轮的参考模型是上一轮的输出，而不是一个固定的初始检查点——这就是保持偏好信号策略而不是对越来越过时的分布进行评分的原因。

单次 DPO 运行仍然是一个合理的第一次迭代——它只是不是整个管道。一旦第一个检查点存在，计划至少再进行一轮，而不是将第一遍视为完成的工件。

## 对构建

从 **同一任务通过-失败轨迹** 构建 DPO/ORPO 对——不是从不同任务中拉出的无关的最佳和最差示例。在该轨迹集中，选择奖励分布的 **μ−2σ 处的拒绝成员，而不是最小值**。朴素的最佳-最差对构建（最大奖励与绝对最小值）随着规模增加而退化；μ−2σ 选择对上述低杠杆研究暴露的相同规模敏感性更具鲁棒性。

```
sorted_by_reward = sort(trajectories, key=reward)
chosen   = sorted_by_reward[-1]                # 最高奖励
mu, sigma = mean(rewards), stdev(rewards)
rejected = closest(sorted_by_reward, mu - 2 * sigma)
# NOT sorted_by_reward[0] — 绝对最小值是随着规模增加而退化的朴素最佳-最差构建。
```

有关将评分轨迹转换为这些对的机制——包括拒绝采样和裁判评分的 delta 选择——请参阅
`trace-to-training-data`。

## 参考文献

每种方法完整的 TRL 配置块——`DPOConfig`、`ORPOConfig`、`KTOConfig` 和 SimPO 扫描网格——加上 Unsloth 包装器和灾难性遗忘的笔记位于
`references/method-configs.md`。这些配置使用 `lora-qlora-recipes` 的
`references/unsloth-trl-mapping.md`
(`processing_class`，而不是 `tokenizer=`) 中建立的当前 TRL API 习惯。

`references/method-configs.md` 也包含灾难性遗忘的笔记：当偏好调整的检查点失去一般能力时，过高的学习率是通常的原因，修复方法几乎总是要在达到上述方法选择表中的范围低端之前降低 LR，然后再寻求任何其他补救措施。

将通过/失败轨迹转换为这个技能的配对构建部分消耗的对。
