# 多评审员模式

用于协调跨多个质量维度的并行代码评审、消除重复发现、校准严重性并生成整合报告的模式。

## 使用此技能的场景

- 组织多维度代码评审
- 决定分配哪些评审维度
- 消除来自多个评审员的重复发现
- 一致校准严重性评级
- 生成整合的评审报告

## 评审维度分配

### 可用维度

| 维度         | 关注点                               | 包含时机                             |
| ------------ | ------------------------------------ | ------------------------------------ |
| **安全**      | 漏洞、认证、输入验证                 | 适用于处理用户输入或认证的代码       |
| **性能**      | 查询效率、内存、缓存                 | 修改数据访问或热点路径时             |
| **架构**      | SOLID原则、耦合性、设计模式           | 结构性变更或新模块时                |
| **测试**      | 覆盖率、质量、边界情况               | 添加新功能时                        |
| **可访问性**  | WCAG、ARIA、键盘导航                 | UI/前端变更时                       |

### 推荐组合

| 场景               | 维度                                       |
| ------------------ | ------------------------------------------ |
| API 端点变更       | 安全、性能、架构                           |
| 前端组件           | 架构、测试、可访问性                       |
| 数据库迁移         | 性能、架构                                 |
| 认证变更           | 安全、测试                                 |
| 全功能评审         | 安全、性能、架构、测试                     |

## 发现消除重复

当多个评审员在相同位置报告问题时：

### 合并规则

1. **相同文件:行号，相同问题** — 合并为一个发现，归功所有评审员
2. **相同文件:行号，不同问题** — 保留为独立发现
3. **相同问题，不同位置** — 保留为独立但交叉引用
4. **严重性冲突** — 使用较高的严重性评级
5. **建议冲突** — 包含两者并注明评审员归属

### 消除重复过程

```
对于所有评审员报告中的每个发现：
  1. 检查是否另一个发现引用了相同的文件:行号
  2. 如果是，检查它们是否描述相同的问题
  3. 如果是相同问题：合并，保留更详细的描述
  4. 如果是不同问题：保留两者，标记为"位置重叠"
  5. 使用合并发现中的最高严重性
```

## 严重性校准

### 严重性标准

| 严重性     | 影响                                        | 可能性             | 示例                                       |
| ---------- | ------------------------------------------- | ------------------ | ------------------------------------------ |
| **严重**   | 数据丢失、安全漏洞、完全失效                | 必然或非常可能     | SQL注入、认证绕过、数据损坏                |
| **高**     | 显著的功能影响、性能退化                    | 可能               | 内存泄漏、缺少验证、流程中断                |
| **中**     | 部分影响，存在解决方案                      | 可能               | N+1查询、缺少边界情况、错误不明确          |
| **低**     | 最小影响，仅外观问题                        | 不太可能           | 代码风格问题、微小优化、命名不规范          |

### 校准规则

- 外部用户可利用的安全漏洞：始终为严重或高
- 热点路径中的性能问题：至少中等
- 关键路径缺少测试：至少中等
- 核心功能的可访问性违规：至少中等
- 无功能影响的代码风格问题：低

## 整合报告模板

```markdown
## 代码评审报告

**目标**： {文件/PR/目录}
**评审员**： {维度-1}, {维度-2}, {维度-3}
**日期**： {日期}
**评审文件**： {数量}

### 严重发现 ({数量})

#### [CR-001] {标题}

**位置**： `{文件}:{行号}`
**维度**： {安全/性能等}
**描述**： {发现内容}
**影响**： {可能发生什么}
**修复建议**： {推荐解决方案}

### 高严重发现 ({数量})

...

### 中等严重发现 ({数量})

...

### 低严重发现 ({数量})

...

### 总结

| 维度    | 严重 | 高 | 中等 | 低 | 总计 |
| ------- | ---- | -- | ---- | -- | ---- |
| 安全    | 1    | 2  | 3    | 0  | 6    |
| 性能    | 0    | 1  | 4    | 2  | 7    |
| 架构    | 0    | 0  | 2    | 3  | 5    |
| **总计** | **1** | **3** | **9** | **5** | **18** |

### 建议

{整体评估和优先行动项}
```
