# 内存安全模式

跨语言的内存安全编程模式，包括RAII、所有权、智能指针和资源管理。

## 何时使用此技能

- 编写内存安全的系统代码
- 管理资源（文件、套接字、内存）
- 防止使用后释放和内存泄漏
- 实现RAII模式
- 在语言之间选择安全性
- 调试内存问题

## 核心概念

### 1. 内存错误类型

| 错误类型             | 描述                      | 预防措施        |
| -------------------- | ------------------------- | --------------- |
| **使用后释放**       | 访问已释放的内存          | 所有权、RAII   |
| **重复释放**        | 两次释放同一内存          | 智能指针       |
| **内存泄漏**        | 从不释放内存              | RAII、GC       |
| **缓冲区溢出**      | 写入缓冲区末尾之后        | 边界检查       |
| **悬空指针**        | 指向已释放内存的指针      | 生命周期跟踪   |
| **数据竞争**        | 并发下未同步的访问        | 所有权、同步   |

### 2. 安全范围

```
手动 (C) → 智能指针 (C++) → 所有权 (Rust) → GC (Go, Java)
更不安全                                              更安全
更多控制                                              更少控制
```

## 最佳实践

### 应该做

- **优先使用RAII** - 将资源生命周期与作用域绑定
- **使用智能指针** - 在C++中避免使用原始指针
- **理解所有权** - 知道谁拥有什么
- **检查边界** - 使用安全的访问方法
- **使用工具** - AddressSanitizer、Valgrind、Miri

### 不应该做

- **不要使用原始指针** - 除非与C接口
- **不要返回局部引用** - 悬空指针
- **不要忽略编译器警告** - 它们能捕获错误
- **不要随意使用 `unsafe`** - 在Rust中，尽量减少使用
- **不要假设线程安全** - 要显式声明

## 调试工具

```bash
# AddressSanitizer (Clang/GCC)
clang++ -fsanitize=address -g source.cpp

# Valgrind
valgrind --leak-check=full ./program

# Rust Miri (未定义行为检测器)
cargo +nightly miri run

# ThreadSanitizer
clang++ -fsanitize=thread -g source.cpp
```
