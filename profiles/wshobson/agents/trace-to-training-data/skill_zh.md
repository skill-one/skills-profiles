# 追踪到训练数据

此技能假定 `eval-harness-first`
已经对在此处转换的追踪进行了评分——黄金数据集、评分器以及 `runs/<run-id>/results.json`
在转换开始前都存在。这是技能在其自身流程中命名的飞轮边缘：
“相同的标记追踪成为训练集。” 转换在这里发生；评分已经在上游发生。

**输入：** 评分后的追踪——
`eval/goldens.jsonl` 以及
`runs/<run-id>/results.json`，每一行都包含一个 `task_id`、评分器的 `verdict`，以及当任务支持标量分数（裁判分数、执行部分学分或RLVR验证器）时的 `reward`：

```json
{"task_id": "t-042", "trace_id": "t-042-a3",
 "messages": [{"role": "user", "content": "..."}],
 "verdict": "pass", "reward": 0.91,
 "grader": "exact_match"}
```

**输出格式：** 行格式与 `dataset-curation` 的格式选择表完全一致——SFT `messages` 行或 DPO `prompt`/`chosen`/`rejected` 对——因此，此技能的输出是该技能的输入，中间没有重塑步骤。

## 原则

评估框架已经完成了标记工作：`results.json` 中的每个追踪在技能接触它之前都带有评分，并且通常带有奖励。将评分后的追踪转换为训练行是机械的——从 `dataset-curation` 的表中选择一个形状，映射字段，写入 JSONL。
**策展是剩余的工作**——哪些追踪达到质量标准、哪些配对具有信息量，以及哪些行绝对不能进入训练集。

将任何需要重新评估追踪的转换步骤视为框架缺少评分器的信号，而不是此技能应该弥补的差距。没有评分或奖励的追踪还不能转换——首先将其路由回 `eval-harness-first`，不要在这里手动标记以解除转换阻塞。

## 从追踪生成 SFT

- **保留成功轨迹的奖励分数部分**，而不是每一个通过的轨迹。按奖励对通过的追踪进行排序，并取一部分（Agent-lightning 模式）而不是每一个仅仅通过通过标准的轨迹——一个勉强通过的轨迹比一个得分远高于阈值的轨迹是更弱的 SFT 信号。
- **专家修正的失败轨迹直接成为黄金 SFT 示例**（Langfuse 模式）——当人类编辑失败轨迹的输出为正确时，这种修正不需要奖励阈值；人类已经验证了它。将修正直接路由到 SFT 集合。
- **步骤级掩码优于多步轨迹的整体轨迹丢弃**。当多步轨迹中只有某些步骤是坏的时候，掩码坏步骤的损失并保留好的步骤，而不是丢弃整个轨迹。SRFT 在 SWE-bench 上对步骤级评论掩码与轨迹丢弃的报告中报告了 32.2% 对 30.9% 的结果——这是一个真实但微小的差距，来自更细粒度的切割。

## 从追踪生成偏好配对

- **从同一任务上的通过与失败轨迹构建配对**，永远不要从不同任务中拉取的最佳和最差得分的轨迹构建配对——跨任务配对会教会模型偏爱一个任务而不是另一个任务，而不是偏爱一个响应而不是另一个响应。
- **选择在奖励分布的 μ−2σ 处的拒绝成员，而不是绝对最小值**。
  `preference-optimization` 的配对构建部分拥有完整的选择公式；此技能提供它消耗的评分轨迹。
- **裁判分数差值选择在配对数量上削减信号**。通过选择减去拒绝的裁判差值对候选配对进行评分，并仅保留最高差值子集——16.5k 候选池中的前 5k 与完整池的下游结果匹配。首先构建完整候选集，然后按差值过滤；不要提前限制生成量为 5k。

## 卫生

- **在任何行发送之前扫描密钥和 PII，并删除找到的内容**。来自生产日志的追踪可能包含凭证、API 密钥、令牌或客户数据——对每个 SFT 和 DPO 行运行密钥/PII 扫描并删除匹配项；如果删除后敏感字段仍然存在，则转换失败（行被丢弃，而不是发送原始内容）。永远不要提交密钥。
- **评估黄金数据集绝不能泄漏到训练数据中**。保留每个 `eval/goldens.jsonl` ID 在每个转换的 SFT 和 DPO 集合之外——一个也作为黄金出现的追踪在稍后对检查点进行评分的精确项目上训练，无声地膨胀了每个后续评估运行。
- **与训练集去重，而不仅仅是新转换行内部去重**——完全匹配或嵌入相似性，匹配 `dataset-curation` 的去重方法字段，针对在此批次合并之前已经存在的任何训练数据运行。
- **来源进入数据集卡片**。每个转换后的行都必须追溯到其来源 `run_id` 和 `trace_id`——`dataset-curation` 的来源字段检查与此完全链接到 `trace-to-training-data` 输出；没有可追溯来源的行还不能合并。

## 相关技能

- `eval-harness-first` — 产生此技能转换的评分追踪；没有评分或奖励的追踪还不能转换，在转换之前将其路由回那里。
- `dataset-curation` — 拥有目标格式和数据集卡片，此技能的来源数据为其提供；转换后的行必须与它的格式选择表字段名称完全匹配，而不是它们的近似值。
- `preference-optimization` — 消耗此技能构建的 DPO 配对，并拥有上述参考的完整 μ−2σ 拒绝选择公式。

工作 JSONL-to-JSONL 转换——评分追踪到 SFT 行、追踪对到 DPO 对、修正到 SFT 行、拒绝采样循环和黄金数据集保留检查——位于
`references/conversion-recipes.md`。
