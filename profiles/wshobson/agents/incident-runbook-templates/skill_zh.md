# 事件运行手册模板

用于事件响应的现生产模板，涵盖检测、分诊、缓解、解决和沟通。

## 使用此技能的场景

- 创建事件响应流程
- 构建特定服务的运行手册
- 建立升级路径
- 记录恢复流程
- 响应活跃事件
- 新增值班工程师

## 核心概念

### 1. 事件严重程度级别

| 严重程度 | 影响                     | 响应时间     | 示例                 |
| -------- | -------------------------- | ----------------- | ----------------------- |
| **SEV1** | 完全停机，数据丢失        | 15 分钟          | 生产环境宕机         |
| **SEV2** | 主要退化                 | 30 分钟          | 关键功能损坏         |
| **SEV3** | 轻微影响                 | 2 小时           | 非关键 Bug           |
| **SEV4** | 最小影响                 | 下一个工作日     | 外观问题             |

### 2. 运行手册结构

```
1. 概述与影响
2. 检测与告警
3. 初始分诊
4. 缓解步骤
5. 根因调查
6. 解决流程
7. 验证与回滚
8. 沟通模板
9. 升级矩阵
```

## 最佳实践

### 应做事项

- **保持运行手册更新** - 每次事件后进行审查
- **定期测试运行手册** - 游戏日，混沌工程
- **包含回滚步骤** - 始终有逃生通道
- **记录假设条件** - 步骤生效所需的条件
- **链接到仪表盘** - 压力期间快速访问

### 不应做事项

- **不要假设知识** - 为凌晨 3 点的状态编写
- **不要跳过验证** - 确认每一步都有效
- **不要忘记沟通** - 保持利益相关者知情
- **不要单独工作** - 及时升级
- **不要跳过事后复盘** - 从每个事件中学习

## 故障排除

### 运行手册步骤在测试环境中正常但在实际事件中失败

步骤通常假设健康环境中为真的先决条件，但在停机期间不成立。对于运行手册中的每个命令，添加前提检查和"如果此命令失败要做什么"的注释：

```bash
# 步骤：检查 Pod 状态
kubectl get pods -n payments

# 先决条件：kubectl 配置，kubeconfig 指向正确的集群
# 如果失败：运行 `aws eks update-kubeconfig --name prod-cluster --region us-east-1`
# 预期输出：Pod 处于 Running 状态
```

### 值班工程师恐慌并跳过顺序步骤

在运行手册顶部添加编号清单，与章节编号对应，以便响应者可以在压力下跟踪进度而无需阅读完整文档：

```markdown
## 快速清单
- [ ] 1. 声明事件严重程度并打开战室
- [ ] 2. 检查服务健康 (第 4.1 节)
- [ ] 3. 检查最近部署 (第 4.1 节)
- [ ] 4. 如果部署可疑则回滚 (第 4.1 节)
- [ ] 5. 向 #payments-incidents 发布初始通知
- [ ] 6. 如果 15 分钟未解决则升级
```

### 运行手册过时 — 命令引用旧的集群名称或端点

运行手册因手动更新而陈旧。在顶部添加"最后验证日期"和负责人，并添加 CI 检查以验证所有 `curl` 端点和 `kubectl` 上下文名称是否仍然有效：

```markdown
## 运行手册元数据
| 字段 | 值 |
|---|---|
| 最后验证 | 2024-11-15 |
| 负责人 | @platform-team |
| 审查频率 | 每次发生 SEV1/SEV2 事件后 |
```

### 利益相关者沟通在工程师埋头苦干时延迟

分配一个专门的事件沟通角色（与事件指挥官分开），其唯一工作是发布状态更新。在沟通模板中添加固定议程：

```
每 15 分钟更新一次（即使没有新信息）：
- 当前状态（调查中 / 缓解中 / 监控中）
- 影响（什么损坏，谁受影响，流量百分比）
- 我们正在做什么
- 下次更新时间：15 分钟
```

### 数据库运行手册命令在执行错误时导致额外停机

在破坏性 SQL 命令前添加明确警告，并在执行前要求检查干运行输出：

```sql
-- 警告：这将终止活动连接。先验证数量。
-- 干运行（验证数量前终止）：
SELECT count(*) FROM pg_stat_activity WHERE state = 'idle' AND query_start < now() - interval '10 minutes';

-- 仅在验证数量合理（< 50）后执行：
SELECT pg_terminate_backend(pid) FROM pg_stat_activity
WHERE state = 'idle' AND query_start < now() - interval '10 minutes';
```
