# Nx 工作区模式

用于 Nx 单体仓库管理的生产模式。

## 何时使用此技能

- 设置新的 Nx 工作区
- 配置项目边界
- 使用受影响命令优化 CI
- 实现远程缓存
- 管理项目之间的依赖关系
- 迁移到 Nx

## 核心概念

### 1. Nx 架构

```
workspace/
├── apps/              # 可部署的应用程序
│   ├── web/
│   └── api/
├── libs/              # 共享库
│   ├── shared/
│   │   ├── ui/
│   │   └── utils/
│   └── feature/
│       ├── auth/
│       └── dashboard/
├── tools/             # 自定义执行器/生成器
├── nx.json            # Nx 配置
└── workspace.json     # 项目配置
```

### 2. 库类型

| 类型            | 目的                          | 示例             |
| --------------- | ---------------------------- | ---------------- |
| **feature**     | 智能组件、业务逻辑            | `feature-auth`   |
| **ui**          | 表现层组件                  | `ui-buttons`     |
| **data-access** | API 调用、状态管理          | `data-access-users` |
| **util**        | 纯函数、辅助工具            | `util-formatting` |
| **shell**       | 应用启动                    | `shell-web`      |

## 最佳实践

### 应该做

- **保持标签一致性** - 通过模块边界强制执行
- **尽早启用缓存** - 显著节省 CI 资源
- **保持库专注** - 单一职责
- **使用生成器** - 确保一致性
- **记录边界** - 帮助新开发者

### 不应该做

- **不要创建循环依赖** - 图应该是无环的
- **不要跳过 affected** - 仅测试已更改的部分
- **不要忽视边界** - 技术债务会累积
- **不要过度粒化** - 平衡库数量
