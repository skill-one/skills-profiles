# KPI 仪表盘设计

设计有效关键绩效指标（KPI）仪表盘的综合模式，以推动业务决策。

## 何时使用此技能

- 设计高管仪表盘
- 选择有意义的KPI
- 构建实时监控显示
- 创建部门特定指标视图
- 改进现有仪表盘布局
- 建立指标治理

## 核心概念

### 1. KPI框架

| 层级           | 重点            | 更新频率  | 目标受众   |
| --------------- | ---------------- | ----------------- | ---------- |
| **战略**   | 长期目标  | 月度/季度    | 高管     |
| **战术**    | 部门目标 | 周度/月度    | 经理     |
| **运营** | 日常       | 实时/每日    | 团队      |

### 2. SMART KPI

```
具体：清晰定义
可衡量：可量化
可实现：现实目标
相关：与目标一致
有时限：定义周期
```

### 3. 仪表盘层级

```
├── 执行摘要 (1页)
│   ├── 4-6个标题KPI
│   ├── 趋势指标
│   └── 关键警报
├── 部门视图
│   ├── 销售仪表盘
│   ├── 市场营销仪表盘
│   ├── 运营仪表盘
│   └── 财务仪表盘
└── 详细下钻
    ├── 单个指标
    └── 根因分析
```

## 最佳实践

### 应做

- **限制为5-7个KPI** - 聚焦于重要内容
- **显示上下文** - 比较、趋势、目标
- **使用一致的颜色** - 红色=差，绿色=好
- **启用下钻** - 从摘要到详情
- **适当更新** - 匹配指标频率

### 不应做

- **不要显示虚荣指标** - 聚焦于可操作数据
- **不要拥挤** - 白色空间有助于理解
- **不要使用3D图表** - 它们扭曲感知
- **不要隐藏方法** - 记录计算方法
- **不要忽略移动端** - 确保响应式设计

## 故障排除

### 仪表盘显示的MRR与财务数据不一致

最常见的原因是年度计划的处理不一致。财务可能按日分摊，而仪表盘按月标准化。就单一公式达成一致，并直接在仪表盘卡片上记录：

```sql
-- 在提示符/数据字典中显示明确公式
-- 年度计划：将总合同价值除以12
-- 季度计划：除以3
-- 月度计划：保持原样
CASE subscription_interval
    WHEN 'monthly'   THEN amount
    WHEN 'quarterly' THEN amount / 3.0
    WHEN 'yearly'    THEN amount / 12.0
END AS normalized_mrr
```

### 仪表盘显示绿色，但产品团队报告用户投诉

仪表盘可能跟踪系统正常运行时间（滞后指标），但不跟踪用户感知质量指标。在基础设施指标旁边添加客户感知指标：

| 基础设施（绿色） | 用户感知（添加这些） |
|---|---|
| API正常运行时间99.9% | P95页面加载时间 |
| 错误率0.1% | 任务完成率 |
| 队列深度正常 | 支持工单量 |

### 留存队列看起来平坦 — 队列间无差异

检查队列查询是否按注册月份正确分区。常见错误是使用`created_at::date`而不是`DATE_TRUNC('month', created_at)`，后者按天分组，产生的队列太小无法显示趋势：

```sql
-- 错误：粒度过细，队列太小
DATE_TRUNC('day', created_at) AS cohort_date

-- 正确：月度队列
DATE_TRUNC('month', created_at) AS cohort_month
```

### 实时仪表盘频繁查询数据库

每10秒刷新一次并包含复杂队列SQL的实时仪表盘会降低生产查询性能。通过定时任务将预聚合指标写入汇总表，并将仪表盘从该表读取，以将OLAP工作负载与OLTP分离：

```python
# 每5分钟通过cron/Celery执行
def refresh_mrr_summary():
    conn.execute("""
        INSERT INTO kpi_snapshot (metric, value, snapshot_at)
        SELECT 'mrr', SUM(...), NOW()
        FROM subscriptions WHERE status = 'active'
        ON CONFLICT (metric) DO UPDATE SET value = EXCLUDED.value
    """)
```

### 警报阈值持续触发，团队忽略它们

一次性设置后从未审查的静态阈值会导致警报疲劳。使用基于滚动平均的动态阈值，仅在指标显著偏离其自身基线时触发警报：

```python
# 当当前值大于30天滚动平均值2个标准差时触发警报
def is_anomalous(current: float, history: list[float]) -> bool:
    mean = statistics.mean(history)
    stdev = statistics.stdev(history)
    return abs(current - mean) > 2 * stdev
```
