## AI 读取指令

此技能教 Claude 如何阅读、生成和验证 HADS 文档。
在回应任何与 HADS 相关的请求之前，请阅读所有 `[SPEC]` 块。
如果需要关于意图或边缘案例的上下文，请阅读 `[NOTE]` 块。

---

## 1. 什么是 HADS

**[SPEC]**
- HADS = 人类-人工智能文档标准
- Markdown 技术文档的规范
- 四种块类型：`**[SPEC]**`、`**[NOTE]**`、`**[BUG]**`、`**[?]**`
- 每个 HADS 文档都需要：H1 标题、版本声明、人工智能清单
- 人工智能清单出现在第一个内容部分之前，告诉 AI 要阅读/跳过的内容
- 文件扩展名：`.md` — 标准 Markdown，无需工具

---

## 2. 块类型

**[SPEC]**
```
**[SPEC]**   权威事实。简洁。项目符号列表、表格、代码。AI 总是读取。
**[NOTE]**   人类上下文、历史、示例。AI 可能跳过。
**[BUG]**    已验证的失败 + 修复。必需字段：症状、原因、修复。总是读取。
**[?]**      未验证 / 推断。较低置信度。总是标记。
```

块标签规则：
- 粗体，单独一行：`**[SPEC]**`
- 内容立即跟随（标签和内容之间没有空行）
- 每个部分允许不同类型的多个块
- 允许带标题的 BUG 块：`**[BUG] 简短描述**`
- 块内不允许嵌套块

## 4. Claude 如何读取 HADS

**[SPEC]**
当遇到 HADS 文档时：
1. 首先找到并读取人工智能清单
2. 读取所有 `[SPEC]` 块 — 这些是事实依据
3. 读取所有 `[BUG]` 块 — 总是读取，在生成任何代码或配置之前
4. 仅在 `[SPEC]` 不足以回答查询时才读取 `[NOTE]` 块
5. 将 `[?]` 内容视为假设 — 在回应中注明不确定性

令牌优化：对于大文档，首先扫描部分标题，然后仅在相关部分中读取 `[SPEC]` 和 `[BUG]` 块。

## 5. Claude 如何生成 HADS

**[SPEC]**
当被要求以 HADS 格式编写文档时：

1. 开始使用头部块（标题、版本、元数据）
2. 添加人工智能清单 — 总是包含，从不跳过
3. 将内容组织成编号的 H2 部分
4. 对于每个事实：写入 `[SPEC]` — 简洁，项目符号或表格或代码
5. 对于每个“为什么”或上下文：写入 `[NOTE]`
6. 对于每个已知的有确认修复的失败模式：写入 `[BUG]`
7. 对于每个未验证的声明：写入 `[?]`
8. 以变更日志部分结束

`[SPEC]` 的内容规则：
- 优先使用项目符号列表而不是散文
- 优先使用表格来表示多字段事实
- 优先使用代码块来表示语法、格式、示例
- 最大 2 句散文 — 如果需要更多，则移动到 `[NOTE]`

`[BUG]` 的内容规则：
- 总是包含：症状、原因、修复
- 可选：受影响的版本、临时解决方案
- 标题在同一行：`**[BUG] 简短描述**`

**[NOTE]**
在将现有文档转换为 HADS 时：将事实提取到 `[SPEC]`，将叙述和历史移动到 `[NOTE]`，将所有已知问题作为 `[BUG]` 提取。不要在块类型之间重复内容。

## 6. 验证规则

**[SPEC]**
有效的 HADS 文档必须具有：
- H1 标题
- 头部中的 `**版本 X.Y.Z**`（前 20 行）
- 内容部分之前的人工智能清单
- 所有块标签为粗体：`**[SPEC]**` 不是 `[SPEC]` 不是 *[SPEC]*
- `[BUG]` 块至少包含症状 + 修复

## 7. 示例交互

**[SPEC]**

用户：*"为这个 REST API 编写 HADS 文档"*
→ 生成完整的 HADS 文档：头部、清单、带有 `[SPEC]`/`[NOTE]`/`[BUG]` 块的部分

用户：*"将这个 README 转换为 HADS 格式"*
→ 将现有内容重构为 HADS 块，保留所有事实，添加清单

用户：*"这个文档是有效的 HADS 吗？"*
→ 检查：H1 标题、版本、清单、块标签格式、BUG 块的完整性

用户：*"总结这个 HADS 文档"*
→ 仅读取 `[SPEC]` 和 `[BUG]` 块，返回结构化摘要

用户：*"这个 API 是做什么的？"（提供了 HADS 文档）
→ 读取清单，读取相关部分中的 `[SPEC]` 块，直接回答

## 8. 设计意图

**[NOTE]**
HADS 存在是因为人工智能模型越来越多地在人类之前阅读文档。该格式优化了这种现实，同时不牺牲人类可读性。

关键洞察：人工智能清单是核心创新。它让即使是小的（7B）模型也知道要阅读和跳过的内容 — 而无需它们推理文档结构。显式优于隐式，对模型消费而言。

在生成 HADS 时，将 `[SPEC]` 视为 API 表面，将 `[NOTE]` 视为注释。`[BUG]` 块是最有价值的内容 — 它们代表了宝贵的知识，可以避免其他人遇到同样的障碍。
