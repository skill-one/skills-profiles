# GDPR 数据处理

GDPR 合规数据处理、同意管理及隐私控制的实用实施指南。

## 使用此技能的场景

- 构建 EU 个人数据处理系统
- 实施同意管理
- 处理数据主体请求 (DSRs)
- 进行 GDPR 合规性审查
- 设计以隐私为先的架构
- 创建数据处理协议

## 核心概念

### 1. 个人数据类别

| 类别               | 示例                    | 保护级别   |
| ------------------ | ----------------------- | ---------- |
| **基础**            | 姓名、邮箱、电话          | 标准保护   |
| **敏感数据 (第 9 条)** | 健康、宗教、种族          | 明确同意   |
| **犯罪数据 (第 10 条)** | 定罪、犯罪行为          | 官方机构授权 |
| **儿童数据**         | 16 岁以下数据            | 父母同意   |

### 2. 数据处理的合法基础

```
第 6 条 - 合法基础：
├── 同意：自由给予、特定、知情
├── 合同：合同履行所必需
├── 法律义务：法律要求
├── 生命利益：保护生命
├── 公共利益：官方职能
└── 合法利益：与权利相平衡
```

### 3. 数据主体权利

```
访问权 (第 15 条)      ─┐
更正权 (第 16 条)       │ 必须在 1 个月内响应
删除权 (第 17 条)       │
限制处理权 (第 18 条)    │
可携带权 (第 20 条)     │
反对权 (第 21 条)       ─┘
```

## 最佳实践

### 应做事项

- **最小化数据收集** - 仅收集必要数据
- **记录所有事项** - 处理活动、合法基础
- **加密个人身份信息 (PII)** - 静态存储和传输中
- **实施访问控制** - 基于工作需要
- **定期审计** - 持续验证合规性

### 不应做事项

- **不要预选同意框** - 必须是主动选择
- **不要捆绑同意** - 分开不同目的
- **不要无限期保留** - 定义并执行保留期限
- **不要忽视 DSAR** - 需在 30 天内响应
- **不要无保障地转移** - 需要 SCCs 或充分性决定
