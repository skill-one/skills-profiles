# 视觉-语言微调

这项技能假定 `finetuning-method-selection`
已经路由到这里：数据形状是图像+文本演示，而不是偏好对或可验证的奖励信号，并且基础是一个视觉-语言模型，而不是纯文本模型。`lora-qlora-recipes` 涵盖了纯文本 LoRA/QLoRA 配方，这项技能专门针对视觉塔和投影器；如果还不熟悉 LoRA 基础（秩、alpha、目标模块），请先阅读该技能。

**输入：** 一个图像+文本数据集和已经从模型目录中选定的 VLM 基础模型。
**输出格式：** 一个经过验证的适配器配置——哪些组件被冻结、LoRA 目标模块，以及一个 `min_pixels`/`max_pixels` 预算——`llm-finetuning-training-engineer` 在生成可运行脚本时直接使用。

## 快速参考

| 情况 | 默认值 |
|---|---|
| 在熟悉的图像上调整行为 | 冻结塔+投影器，LoRA r=8–16，α=16–32 |
| 视觉域迁移 | 解冻最后-6 个 ViT 层，视觉学习率 5–10 倍更低 |
| 在目标秩下无法放入 bf16 | QLoRA — 仅冻结视觉塔 |
| `fast_inference=True` | `finetune_vision_layers=False` |
| 损失正常，评估未改进 | 首先检查下方的两个无声杀手 |

## 共识配方

冻结视觉塔和投影器。仅在 LLM 上使用 LoRA，全部线性（与纯文本 SFT 相同的关注力 + MLP 目标列表——见 `lora-qlora-recipes`），在 **r=8–16，α=16–32**。这是在不干扰其视觉感知的情况下适应 VLM 行为的既定默认值。

- **视觉塔和投影器默认保持冻结。** 它们已经编码了通用的视觉表示；重新训练它们很少有必要，并且在不增加能力的情况下增加了风险，对于大多数任务而言。
- **LoRA 秩低于纯文本通用默认值**（此处 r=8–16，而纯文本 SFT 为 r=16–32）是因为 LLM 仅适配器在调整行为，而不是注入新的视觉知识。
- **仅当视觉塔冻结时才允许使用 QLoRA。** 在解冻和训练视觉层的同时量化基础是不受支持且不稳定的——将其视为一个硬性配对规则，而不是可调的。如果视觉塔需要解冻，则放弃 QLoRA，改用 bf16 LoRA。

```python
# 冻结塔 + 投影器；LoRA 仅在 LLM 上
for name, param in model.named_parameters():
    if "vision_tower" in name or "projector" in name:
        param.requires_grad = False

target_modules = [
    "q_proj", "k_proj", "v_proj", "o_proj",
    "gate_proj", "up_proj", "down_proj",
]  # LLM 仅用，全部线性 — r=8-16, alpha=16-32
```

## 何时解冻

解冻视觉层是一个故意的升级，而不是默认决策——只有在域迁移是视觉而不是文本时才使用它。

- **仅针对视觉域迁移解冻。** 如果任务是教塔已经理解的图像上的新行为（图表、日常照片），则上述冻结塔配方就足够了。当视觉域本身对塔来说是陌生的——卫星图像、医学扫描、密集技术图表——并且冻结塔配方停滞不前时，才解冻。
- **最后-6 个 ViT 层是最佳选择。** 解冻最后六个视觉 Transformer 层（而不是整个塔）比冻结基线多测量 **+1.7pt DocVQA，训练成本约 1.75 倍**。将六层视为值得支付的上限；更进一步则花费计算而结果不匹配。
- **解冻时，视觉学习率必须比 LLM 学习率低 5–10 倍。** 视觉塔的预训练表示比 LLM 适配器更脆弱；两者使用相同的学习率会更快地覆盖视觉表示，而 LLM 适配器无法弥补。
- **在 patch-embedding 层上使用高 LoRA 秩会风险出现 NaN。** 如果 patch embedding 在解冻集中，请保持其秩较低并密切观察早期步骤的损失——在 VLM 中应用 LoRA 最脆弱的地方之一。

## 两个无声杀手

两者都会产生一个训练无错误且无学习的运行：损失曲线看起来正常，模型没有改进，并且两者都不会抛出异常——两者都需要显式的预训练检查，而不仅仅是干净的训练日志。

- **图像标签/计数不匹配。** 模板文本中的每个图像占位符标记必须与传递给 collator 的实际媒体项一对一映射。不匹配（一个占位符，零个或两个图像附加；或没有占位符的图像）在大多数 collator 中不会报错——它会无声地错位图像和文本，并且模型“训练但什么都没学到”。在训练开始之前，在每一个示例上验证占位符到媒体的 1:1 映射，而不仅仅是样本。完整的验证清单细节：
  `references/collators-and-pitfalls.md`。
- **`min_pixels`/`max_pixels` 分辨率预算。** 这对是 VLM SFT 中对质量和内存影响最大的超参数——比秩、alpha 或学习率更重要。太低会无声地将图像下采样到任务所需的分辨率以下（即使训练“成功”，小文档文本也变得无法阅读）；太高会耗尽激活内存预算或迫使训练稳定的小批次。根据数据集有意设置它，不要将其留在一个框架默认值。

## Unsloth 特定细节

- **`UnslothVisionDataCollator`** 是 Unsloth 期望用于 VLM SFT 的 collator——它处理图像标签对齐和在 `references/collators-and-pitfalls.md` 中描述的每个架构处理器合同。不要用纯文本 collator 替换 VLM 数据。
- **当 `fast_inference=True` 时，必须要求 `finetune_vision_layers=False`。** vLLM 无法在视觉层上提供 LoRA 适配器，因此即使训练成功，一个解冻视觉层的快速推理设置在服务时间也会失败。如果配方要求解冻最后-6 个 ViT 层（见上文“何时解冻”），则该运行无法进行快速推理——选择一个或另一个，而不是两者都选。

## 模型选择

基础 VLM 选择不在此技能范围内——它存在于 `finetuning-method-selection` 的 `references/model-catalog.md` 中的模型目录中。此技能及其参考描述按架构系列提供的配方，从未推荐一个模型优于另一个。

VLM 增强学习（VLM-GRPO）在此插件中仅作为参考——VLM-RL 特有的碎片化工具和奖励黑客失败模式在 `grpo-rlvr-training` 中涵盖，而不是在这里。此技能的范围止于监督微调。

## 失败模式

上述每个部分中反复出现的错误是认为干净的损失曲线是运行健康的证明。一条看起来正常的曲线与 **既** 一个工作运行 **又** 任何一个无声杀手一致，因为无论哪种情况，模型都在训练*某物*——当存在杀手时，只是没有对齐的图像-文本信号。在正常损失曲线旁边的一个平评估分数意味着在触摸任何超参数之前，重新运行 `references/collators-and-pitfalls.md` 中的检查清单。
