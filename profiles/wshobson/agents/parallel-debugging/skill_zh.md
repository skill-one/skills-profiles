# 并行调试

使用竞争假设分析（ACH）方法，通过并行代理调查来调试复杂问题的框架。

## 使用此技能的场景

- Bug具有多个可能的根本原因
- 初始调试尝试尚未识别问题
- 问题跨越多个模块或组件
- 需要基于证据进行系统性的根本原因分析
- 希望在调试中避免确认偏差

## 假设生成框架

跨6种故障模式类别生成假设：

### 1. 逻辑错误

- 条件逻辑错误（运算符错误、遗漏情况）
- 循环或数组访问中的计算错误
- 遗漏边界情况处理
- 算法实现错误

### 2. 数据问题

- 无效或意外的输入数据
- 类型不匹配或强制转换错误
- 预期值处为null/undefined/None
- 编码或序列化问题
- 数据截断或溢出

### 3. 状态问题

- 并发操作之间的竞态条件
- 返回过时数据的陈旧缓存
- 初始化或默认值错误
- 共享状态意外变更
- 状态机转换错误

### 4. 集成失败

- API契约违规（请求/响应不匹配）
- 组件之间版本不兼容
- 环境之间配置不匹配
- 缺少或不正确的环境变量
- 网络超时或连接失败

### 5. 资源问题

- 内存泄漏导致逐渐退化
- 连接池耗尽
- 文件描述符或句柄泄漏
- 磁盘空间或配额超出
- 由于处理效率低下导致的CPU饱和

### 6. 环境

- 缺少运行时依赖
- 库或框架版本错误
- 平台特定行为差异
- 权限或访问控制问题
- 与时区或区域设置相关的行为

## 证据收集标准

### 什么构成证据

| 证据类型     | 强度 | 示例                                                         |
| ------------ | ---- | ------------------------------------------------------------ |
| **直接**        | 强   | 位于`file.ts:42`的代码显示`if (x > 0)`应为`if (x >= 0)` |
| **关联性**     | 中   | 提交`abc123`后错误率增加                                |
| **证言**       | 弱   | "在我的机器上可以工作"                                      |
| **缺失**       | 可变 | 代码路径中未发现null检查                                |

### 引证格式

始终使用文件:行引用来引证证据：

```
**证据**：位于`src/validators/user.ts:87`的验证函数
未检查空字符串，仅检查null/undefined。这允许空电子邮件地址通过验证。
```

### 置信度级别

| 级别               | 标准                                                                            |
| ------------------ | -------------------------------------------------------------------------------- |
| **高 (>80%)**     | 多个直接证据，清晰的因果链，无矛盾证据                                          |
| **中 (50-80%)**   | 部分直接证据，合理的因果链，轻微模糊之处                                       |
| **低 (<50%)**      | 主要为关联性证据，因果链不完整，存在矛盾证据                                     |

## 结果仲裁协议

所有调查员报告后：

### 第1步：分类结果

- **确认**：高置信度，强证据，清晰的因果链
- **可能**：中等置信度，部分证据，合理的因果链
- **被证伪**：证据与假设矛盾
- **未决**：证据不足以确认或证伪

### 第2步：比较确认的假设

如果多个假设被确认，按以下顺序排序：

1. 置信度级别
2. 支持证据数量
3. 因果链强度
4. 无矛盾证据

### 第3步：确定根本原因

- 如果一个假设明显占优：声明为根本原因
- 如果多个假设可能性相同：可能是复合问题（多个促成原因）
- 如果未确认任何假设：基于收集到的证据生成新假设

### 第4步：验证修复

在声明Bug已修复前：

- [ ] 修复解决了已识别的根本原因
- [ ] 修复未引入新问题
- [ ] 原始复现用例不再失败
- [ ] 相关边界情况已覆盖
- [ ] 相关测试已添加或更新
