# 可访问性合规

掌握可访问性实现方法，创建包容性体验，确保所有用户（包括残障人士）都能使用。

## 使用此技能的场景

- 实现 WCAG 2.2 AA 级或 AAA 级合规
- 构建屏幕阅读器可访问的界面
- 为交互组件添加键盘导航
- 实现焦点管理和焦点锁定
- 创建具有适当标签的可访问表单
- 支持减少动画和高对比度偏好
- 构建移动端可访问性功能（iOS VoiceOver、Android TalkBack）
- 进行可访问性审计并修复违规问题

## 最佳实践

1. **使用语义化 HTML**：在可能的情况下，优先使用原生元素而非 ARIA
2. **使用真实用户进行测试**：将残障人士纳入用户测试
3. **优先考虑键盘操作**：设计无需鼠标的交互方式
4. **不要禁用焦点样式**：对焦点进行样式设计，而非移除
5. **提供文本替代**：所有非文本内容都需要描述
6. **支持缩放**：内容应在 200% 放大下正常工作
7. **通知变更**：使用 live regions 对动态内容进行提示
8. **尊重用户偏好**：遵循 prefers-reduced-motion 和 prefers-contrast

## 常见问题

- **缺少替代文本**：没有描述的图片
- **颜色对比度差**：文字在背景上难以阅读
- **键盘锁定**：焦点卡在组件内
- **缺少标签**：表单输入没有关联标签
- **自动播放媒体**：未经用户启动即播放的内容
- **可访问性不佳的自定义控件**：原生功能实现不佳
- **缺少跳过链接**：无法跳过重复内容
- **焦点顺序问题**：Tab 顺序与视觉顺序不一致

## 测试工具

- **自动化**：axe DevTools、WAVE、Lighthouse
- **手动**：VoiceOver (macOS/iOS)、NVDA/JAWS (Windows)、TalkBack (Android)
- **模拟器**：NoCoffee (视觉障碍)、Silktide (多种残障)
