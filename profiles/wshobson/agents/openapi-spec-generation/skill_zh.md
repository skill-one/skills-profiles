# OpenAPI 规范生成

创建、维护和验证 RESTful API 的 OpenAPI 3.1 规范的全面模式。

## 何时使用此技能

- 从零开始创建 API 文档
- 从现有代码生成 OpenAPI 规范
- 设计 API 合约（先设计后编码方法）
- 根据 规范验证 API 实现
- 根据 规范生成客户端 SDK
- 设置 API 文档门户

## 核心概念

### 1. OpenAPI 3.1 结构

```yaml
openapi: 3.1.0
info:
  title: API 标题
  version: 1.0.0
servers:
  - url: https://api.example.com/v1
paths:
  /resources:
    get: ...
components:
  schemas: ...
  securitySchemes: ...
```

### 2. 设计方法

| 方法         | 描述                  | 适用于            |
| ------------ | --------------------- | ----------------- |
| **先设计**   | 在编码前编写规范       | 新 API、合约      |
| **先编码**   | 从代码生成规范       | 现有 API         |
| **混合**     | 注释代码、生成规范     | 发展中的 API      |

## 最佳实践

### 应该做

- **使用 $ref** - 重用模式、参数、响应
- **添加示例** - 真实值有助于消费者
- **记录错误** - 所有可能的错误代码
- **版本化 API** - 在 URL 或头部中
- **使用语义化版本控制** - 用于规范变更

### 不应该做

- **不要使用通用描述** - 要具体
- **不要忽略安全** - 定义所有方案
- **不要忘记可空** - 明确空值
- **不要混用风格** - 全程保持命名一致
- **不要硬编码 URL** - 使用服务器变量
