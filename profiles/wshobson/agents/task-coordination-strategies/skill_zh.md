# 任务协调策略

将复杂任务分解为可并行单元的策略、设计依赖图、编写有效的任务描述以及跨代理团队监控工作负载。

## 使用此技能的场景

- 将复杂任务分解为并行执行
- 设计任务依赖关系（blockedBy/blocks）
- 编写具有清晰验收标准的任务描述
- 监控和重新平衡团队成员之间的工作负载
- 识别多任务工作流中的关键路径

## 任务分解策略

### 按层级分解

按架构层级划分工作：

- 前端组件
- 后端 API 端点
- 数据库迁移/模型
- 测试套件

**最适合**：全栈功能、垂直切片

### 按组件分解

按功能组件划分工作：

- 认证模块
- 用户资料模块
- 通知模块

**最适合**：微服务、模块化架构

### 按关注点分解

按横切关注点划分工作：

- 安全审查
- 性能审查
- 架构审查

**最适合**：代码审查、审计

### 按文件所有权分解

按文件/目录边界划分工作：

- `src/components/` — 实现者 1
- `src/api/` — 实现者 2
- `src/utils/` — 实现者 3

**最适合**：并行实现、冲突避免

## 依赖图设计

### 原则

1. **最小化链深度** — 优先选择宽而浅的图，而非深的链
2. **识别关键路径** — 最长的链决定了最小完成时间
3. **谨慎使用 blockedBy** — 仅添加真正需要的依赖
4. **避免循环依赖** — 任务 A 阻塞 B，B 阻塞 A 是死锁

### 模式

**独立（最佳并行性）**：

```
Task A ─┐
Task B ─┼─→ 集成
Task C ─┘
```

**顺序（必要的依赖）**：

```
Task A → Task B → Task C
```

**菱形（混合）**：

```
        ┌→ Task B ─┐
Task A ─┤          ├→ Task D
        └→ Task C ─┘
```

### 使用 blockedBy/blocks

```
TaskCreate: { subject: "构建 API 端点" }         → 任务 #1
TaskCreate: { subject: "构建前端组件" }    → 任务 #2
TaskCreate: { subject: "集成测试" }          → 任务 #3
TaskUpdate: { taskId: "3", addBlockedBy: ["1", "2"] }  → #3 等待 #1 和 #2
```

## 任务描述最佳实践

每个任务应包含：

1. **目标** — 需要完成什么（1-2 句话）
2. **所属文件** — 此团队成员可能修改的文件/目录的明确列表
3. **需求** — 期望的特定交付成果或行为
4. **接口契约** — 此工作如何连接到其他团队成员的工作
5. **验收标准** — 如何验证任务是否正确完成
6. **范围边界** — 明确超出范围的内容

### 模板

```
## 目标
构建用户认证 API 端点。

## 所属文件
- src/api/auth.ts
- src/api/middleware/auth-middleware.ts
- src/types/auth.ts (共享 — 仅读，不要修改)

## 需求
- POST /api/login — 接受邮箱/密码，返回 JWT
- POST /api/register — 创建新用户，返回 JWT
- GET /api/me — 返回当前用户资料（需要认证）

## 接口契约
- 从 src/types/auth.ts（由 implementer-1 拥有）导入 User 类型
- 导出 AuthResponse 类型供前端使用

## 验收标准
- 所有端点返回正确的 HTTP 状态码
- JWT 令牌在 24 小时后过期
- 密码使用 bcrypt 进行哈希

## 超出范围
- OAuth/社交登录
- 密码重置流程
- 速率限制
```

## 工作负载监控

### 不平衡的指标

| 信号                     | 含义             | 操作                      |
| -------------------------- | ------------------- | --------------------------- |
| 同事空闲，其他人忙碌     | 分配不均         | 重新分配待处理任务      |
| 同事卡在一个任务上     | 可能的阻塞者    | 检查，提供帮助        |
| 所有任务被阻塞          | 依赖问题    | 先解决关键路径         |
| 一个同事有其他三倍的负载 | 过载          | 分解任务或重新分配     |

### 重新平衡步骤

1. 调用 `TaskList` 评估当前状态
2. 识别空闲或过载的同事
3. 使用 `TaskUpdate` 重新分配任务
4. 使用 `SendMessage` 通知受影响的同事
5. 监控吞吐量改善
