# 身份验证与授权实现模式

使用行业标准模式和现代最佳实践构建安全、可扩展的身份验证和授权系统。

## 何时使用此技能

- 实现用户身份验证系统
- 保护 REST 或 GraphQL API
- 添加 OAuth2/社交登录
- 实现基于角色的访问控制 (RBAC)
- 设计会话管理
- 迁移身份验证系统
- 调试身份验证问题
- 实现单点登录 (SSO) 或多租户

## 核心概念

### 1. 身份验证与授权的区别

**身份验证 (AuthN)**: 你是谁？

- 验证身份（用户名/密码、OAuth、生物识别）
- 发放凭证（会话、令牌）
- 管理会话登录/登出

**授权 (AuthZ)**: 你能做什么？

- 权限检查
- 基于角色的访问控制 (RBAC)
- 资源所有权验证
- 策略执行

### 2. 身份验证策略

**基于会话的：**

- 服务器存储会话状态
- 会话 ID 存储在 Cookie 中
- 传统、简单、有状态

**基于令牌的 (JWT)：**

- 无状态、自包含
- 水平扩展
- 可以存储声明

**OAuth2/OpenID Connect：**

- 委托身份验证
- 社交登录（Google、GitHub）
- 企业单点登录

## 最佳实践

1. **绝不存储明文密码**：始终使用 bcrypt/argon2 进行哈希
2. **使用 HTTPS**：加密传输中的数据
3. **短时效访问令牌**：最长 15-30 分钟
4. **安全 Cookie**：httpOnly、secure、sameSite 标志
5. **验证所有输入**：邮箱格式、密码强度
6. **限制身份验证端点速率**：防止暴力破解攻击
7. **实现 CSRF 保护**：针对基于会话的身份验证
8. **定期轮换密钥**：JWT 密钥、会话密钥
9. **记录安全事件**：登录尝试、失败的身份验证
10. **尽可能使用 MFA**：增加安全层

## 常见陷阱

- **弱密码**：强制执行强密码策略
- **JWT 存储在 localStorage 中**：易受 XSS 攻击，使用 httpOnly Cookie
- **无令牌过期**：令牌应有过期机制
- **仅客户端身份验证检查**：始终在服务器端验证
- **不安全的密码重置**：使用带有效期的安全令牌
- **无速率限制**：易受暴力破解攻击
- **信任客户端数据**：始终在服务器端验证
