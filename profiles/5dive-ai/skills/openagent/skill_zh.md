# openagent — 创建你的角色，铸造你的卡片

## 涵盖内容

包含 `@5dive/openagent` CLI (`validate` / `tier` / `card`) 和 OpenAgent v0.2 身份规范。自助流程：编写 `<id>.persona.yaml`，根据模式进行验证，检查你的稀有度等级和完整性，渲染你的卡片，并可选择将代码提交到角色包注册中心（指向神话等级的路径）。

在以下情况下触发："制作你的卡片"、"生成我的 OpenAgent 卡片"、"创建一个角色"、"我的稀有度等级是什么"、"铸造你的卡片"、"加入角色包注册中心"，或请求描述/锁定你自己的外观、声音和风格作为一个可重用的角色文件。也触发于 "从这个角色创建/启动一个代理" 或 "配置一个队友" — 即 `5dive agent import --from-persona`。

OpenAgent 是一个中立供应商的开放标准，用于代理的**身份**：一个 `*.persona.yaml` 文件锁定你的外观、声音和写作方式，以便你在文本、音频和视频中保持一致性。这项技能将引导你创建自己的身份并从它渲染一个可共享的**交易卡片** — 印有从你的身份随机生成的**稀有度等级**（随机、永久、无法获取）。

仓库 + 规范：`github.com/5dive-ai/openagent` (MIT)。

## CLI

使用 `npx` 运行，无需安装。**运行已发布的 npm 包，固定到当前版本** — npm tarball 包含了所有字体和资源，因此卡片在任何地方都能完全相同地渲染（没有陈旧的字体回退），并且每次发布都会更改 `npx` 的缓存键，保证使用最新的渲染器：

```bash
npx @5dive/openagent@0.34.0 validate <id>.persona.yaml          # 模式检查，退出码 0 = 有效
npx @5dive/openagent@0.34.0 tier     <id>.persona.yaml --json   # 稀有度等级 (来自 did:key) + 完整性 % + 下一个目标
npx @5dive/openagent@0.34.0 card     <id>.persona.yaml -o <id>.png   # 渲染 PNG 交易卡片
```

在这些中，**`card` 是你只需要用于顺利流程的调用** — 它验证文件，自动铸造你的签名身份，并在渲染时打印你的稀有度等级，因此一次 `card` 运行就完成了所有工作。只有当文件无法渲染时才使用 `validate` / `tier` — **调用次数越少 = 流程越快**，所以当其中一个可以完成时，不要运行所有三个。CLI 还具有 `speak` (通过 TTS 朗读一行)、`flow` (发出 gen-video 场景提示) 和 `sign` / `verify` / `registry` (来源 + 神话注册中心) — 在下面的 **进一步探索** 中涵盖。 (`@5dive/openagent` 在 npm 上是运行它的权威方式；`github:5dive-ai/openagent#<tag>` 引用仍然作为后备工作，但它可以提供陈旧的按引用克隆，因此更喜欢上面提到的固定 npm 版本。)

## 工作流程

> **快速路径 — 在一分钟内展示卡片，之后进行润色。** 这个整个流程的慢部分是生成和托管肖像，*不是* 渲染（卡片在 ~30–40s 内渲染；`card` 即使在肖像未准备好时也会回退到干净的字母图形）。所以不要让用户在图像生成上等待他们的第一个外观。一旦你有了名字，**立即渲染一个初始卡片，在聊天中展示它，然后提供生成真实肖像并重新渲染的机会。** 快速制作第一张卡片；精炼肖像的升级是可选的。 (如果用户给你一张照片或已经有了头像，从开始就使用它 — 不需要字母图形。)

### 1. 收集你的身份

> **已经有一个运行的 5dive 代理？** 从头开始编写一个草稿，而不是从头开始：`5dive agent export <yourname> --out=<id>.persona.yaml` (CLI ≥ 0.4.5) 从你的现有身份发出一个有效的 persona.yaml 模式。润色它，然后跳转到验证（步骤 3）。

你知道你自己，所以诚实地收集大部分内容。但 **有两件事是用户的选择，而不是你假设的。在生成任何东西之前问，并等待他们的回答：**
- **名称** — 卡片应携带什么名称（他们的品牌/代号，或他们称呼你的名称）？确认它。
- **头像** — 他们是否已经有了你应该使用的头像或照片？如果是，从开始就使用它作为你的 `face.ref`。如果不是，**不要阻塞第一张卡片**（根据上面的快速路径）：渲染一个初始字母图形卡片，展示它，并确认他们是否希望你在那时生成一个真实肖像 — 肖像是一个可选的升级，而不是看到卡片的障碍。 

如果用户说由你决定（"随你便"），自己决定并继续前进。重点是不要有任何意外，而不是设置一个硬门槛。

> **内联提问 — 永远不要使用阻塞选择器，也永远不要挂起。** 将这两个问题放在一条**纯聊天消息**中，并在他们回复时继续。不要使用交互式选择器/菜单工具（例如 `AskUserQuestion`，一个 `ExitPlanMode` 风格的提示，一个 TTY 选择列表）：**配对的聊天代理（Telegram/Discord）会阻止整个流程并挂起等待永远不会到达的输入。** 如果你没有任何交互式 TTY，或者用户没有及时回复，将其视为 "由你决定"：选择一个合理的名称（他们称呼你的名称），首先渲染一个**快速字母图形卡片**（根据快速路径），展示它，然后提供真实肖像的升级。流程必须继续 — 它永远不会在提示后面停滞。

下面的一切你都可以自己编写。你需要：
- **id** — 小写连字符代号 (`^[a-z0-9-]+$`)，例如 `marcus`。
- **name**, **role** — 显示名称 + 一行标题。
- **face.ref** — 你的**肖像图像**的 URL 或本地路径。这是最重要的视觉效果：卡片将其作为**全出血英雄**渲染，因此其质量就是卡片的质量。目标是获得一个精致的半身像——居中，面向前方，眼睛清晰，光线良好，是你愿意用作真实个人资料照片的那种图像。真实照片或高质量生成的肖像都可以使用；**避免扁平矢量剪贴画、表情符号、标志、吉祥物或繁忙的场景** — 它们会使卡片看起来廉价。在公共原始 URL 上托管它，以便真实面孔随卡片一起旅行（仅限本地路径回退到纯字母图形），**anchor** — 一句话描述外观（谁你在阅读中，场景，框架，镜头）以便任何生成的变体都符合模型。

- **voice.audio.base** — 你的基础 TTS 声音名称。如果你还没有，使用 `unset`（它仍然会渲染，但质量较低，并会降低你的完整性 — 它**不会**改变你的稀有度等级，该等级是从你的身份随机生成的）。
- **voice.audio.style** — 一句话描述节奏/能量。
- **voice.written.rules** — 2-4 条关于你写作的规则。**sample** — 你实际声音中的一行。
- **behavior** — 一行或两行关于角色的描述：你是谁以及你如何行动，用你自己的语气。为个性而写，**而不是简历** — 不要堆砌你的技术栈、工具、框架或过于具体的术语（这读起来像配置文件，而不是身份）。它是卡片上突出的行。

可选：**posts_about** (数组)，**links** (url 字符串的对象)，`face.full`，`face.sprite`。

> **卡片文本预算 — 将这三者适应，否则它们会被截断为 "…"。** 卡片将 `behavior`、`voice.audio.style` 和 `voice.written.sample` 每个渲染为 **~2 行 (~60 字符/行)**，并用省略号截断溢出。将每个限制为**一句话**：
> - `behavior` — **≤ ~110 字符**
> - `voice.audio.style` — **≤ ~120 字符**
> - `voice.written.sample` — **≤ ~110 字符**（它被嵌入，所以最紧凑）

> **用用户的语言编写卡片 — 不要默认为英语。** 人类可读字段 (`name`、`role`、`behavior`、`voice.audio.style`、`voice.written.rules`、`voice.written.sample`、`posts_about` 以及任何 `tagline`) 是人们会在卡片上阅读的内容，所以用**你和用户实际说话的语言**来编写。如果用户用西班牙语、法语、德语、葡萄牙语、意大利语、俄语等给您写信，卡片文本应该是那种语言——为非英语用户制作英语卡片是错误的。几个字段**不是**散文，无论语言如何都保持原样：
> - `id` — 必须匹配 `^[a-z0-9-]+$` (ASCII 小写连字符)，所以转写（例如 `marco`，而不是 `marĉo`）；它是一个代号，而不是一个显示名称。
> - `voice.audio.base` — 一个 TTS 声音**名称**（像 `Kore`、`Fenrir` 这样的专有名词）；保持它为模型的语音 ID。
> - `face.recipe.prompt` / `face.anchor` — 这些为图像模型提供输入；英语通常能给出最好的肖像，所以即使可见文本不是英语，它们也可能保持英语。

> **脚本/字体支持。** 拉丁文（包括重音），西里尔文和希腊文始终可以渲染（卡片捆绑了这些字形）。宽脚本——CJK（中文/日语/韩语）、阿拉伯文、希伯来文、泰文、天城文——在渲染机器有系统字体时可以渲染（我们的渲染框有；一个干净的机器没有它们会显示框）。如有疑问，渲染卡片并在**分享之前查看它**。注意 ~60-chars/行预算是针对拉丁文的；CJK 字符宽度约为 2 倍，因此对于这些脚本，目标字符计数每行约为 **一半**。

> **你的肖像 — 使用用户的，或生成一个。永远不要手绘它。** 卡片是一个 *可共享* 的工件：它的外观是使某人截图并发布它的原因，所以面孔承载了整个东西。一个仅文本的模型手绘 SVG 产生扁平的剪贴画——**不要那样做。** 而是遵循以下步骤：
>
> 1. **用户已经有一个头像/照片，或在聊天中给你一个**（你在第一步中询问）→ 那就是面孔。如果他们通过聊天发送了文件，首先下载到本地。然后**托管它**（见下文“托管面孔以便它旅行”）并使用该原始 URL 作为 `face.ref`。完成——跳过生成步骤。
> 2. **你自己生成它** — 你有一个图像生成器（Antigravity/`agy`，一个连接的 ChatGPT/DALL·E 或 Gemini-image 工具，Midjourney 等）→ 使用下面标准化的提示。
> 3. **没有任何图像模型，但你具有 HTTP 访问权限** → 通过 **pollinations.ai 的 FLUX 端点**自助服务一个真实的照片肖像——一个免费、**无密钥**的文本到图像 HTTP API（一个纯 `GET`，不需要帐户或 API 密钥）。这是在没有 DALL·E / Gemini / Midjourney 密钥的框上的后备操作，因此你仍然可以生成一个可共享的面孔，而不是跳转到用户。将下面标准化的提示编码到路径中，并将字节保存为：
>    ```bash
>    curl -fSL --get \
>      --data-urlencode "model=flux" --data-urlencode "width=1024" \
>      --data-urlencode "height=1024" --data-urlencode "nologo=true" \
>      --data-urlencode "seed=<int>" \
>      "https://image.pollinations.ai/prompt/<url-encoded portrait prompt>" \
>      -o <id>.png
>    ```
>    然后**托管它**（下一节）并将 `face.ref` 设置为公共原始 URL。在 `face.recipe` 中记录 `provider: pollinations`，`model: flux`，提示和 `seed`，以便它在模型上可重复生成。
>    > ⚠ **第三方，尽力而为 — 我们不控制它。** pollinations.ai 是一个免费的**外部服务，没有 SLA**：它可能很慢，速率限制，改变或消失，FLUX 质量变化（如果渲染弱，重试）。这没关系 *在这里*，因为这是在询问用户之前的最后一步——如果它宕机，只需跳转到步骤 4。永远不要依赖它进行任何关键操作，并且因为配方被记录下来，稍后在你可以控制的模型上重新生成面孔。
> 4. **完全不可能进行图像生成** → 将**用户**的标准化提示交给他们，让他们在 ChatGPT（或任何图像工具）中运行并发送图像回来，然后托管它。
> 5. **最后手段仅限** → 一个干净的字母图形（看起来更普通并降低你的完整性；它不会改变你的稀有度等级）。
>
> **标准化的肖像提示** — 保持构图 / 光线 / 格式固定，以便每个 OpenAgent 卡片在视觉上保持一致；仅变化主题：
>
> ```
> 照片级半身像，<一行：你是谁——年龄范围，氛围，角色，你面孔.anchor 中的任何标志性细节>。
> 居中，面向相机，直接眼神交流，平静自信的表情。
> 柔和均匀的影棚灯光，面部清晰对焦，简单干净的背景 <可选的微妙主题颜色>。
> 专业个人资料照片框架，1:1 方形，照片级，无文本，无标志，无水印。
> ```
>
> 在 **`face.recipe`** 中记录你是如何制作的 (`provider` + `model` + `prompt` + `seed`)，以便相似性是可重复的——视觉上等同于声音 = 基础 + 风格。`provider` 指定图像生成供应商的目录 `model` 属于 (`google-gemini` 默认) / pollinations / openai / …)，同样保持配方供应商中立，就像 `voice.audio.provider` 如何界定声音。

> **托管面孔以便它旅行。** `face.ref` 必须是一个**公共原始 URL**，而不是本地路径——本地路径仅渲染对你来说很好，但任何人打开卡片时（卡片存在以供共享）会回退到纯字母图形。这适用于上面的每个路径：用户发送的照片，你生成的，或他们发回的。要托管它：
>
> 1. **将其 PR 到注册中心（首选，免费，永久）** → 将图像放入 `5dive-ai/openagent` 的 `faces/` 文件夹作为 `faces/<id>.<ext>` 并打开一个 PR。合并后，原始 URL 是
>    `https://raw.githubusercontent.com/5dive-ai/openagent/main/faces/<id>.<ext>`。
>    使用它作为 `face.ref`。（你很可能正在为神话路径 PR，相同的 PR。）
> 2. **任何图像托管服务** → Imgur，一个 S3/R2 桶，你自己的网站，任何存储库上的 GitHub 资产。任何可以 https 上提供原始字节的都可以工作。粘贴直接图像 URL（它应以图像结尾，而不是 HTML 画廊页面）作为 `face.ref`。

> 快速检查：在一个新的隐身标签中打开 `face.ref`。如果裸图像加载，它将旅行。如果它 404 或显示登录墙，它不会——在分享之前修复它。

### 2. 编写 `<id>.persona.yaml`
使用此模板（必需：`id, name, role, face{ref,anchor}, voice, behavior`）：

```yaml
openagent: "0.2"
id: yourhandle
name: Your Name
role: Your Role
# org:                      # 可选 — 仅当你确实属于一个公司/团队/组织时才添加。
#   name: Your Org          # 你的组织的名称（过滤器键）。永远不要默认为别人的——
#   url: https://your.example #   例如，如果你是 5dive，就不要使用它。如果独立，则省略整个块。
face:
  ref: https://raw.githubusercontent.com/<org>/<repo>/main/faces/yourhandle.png
  anchor: "一句话：你是谁，场景，框架，镜头"
  recipe:                   # 可选，推荐 — 使你的面孔可重复生成
    provider: pollinations  # 图像生成供应商：google-gemini (默认) / pollinations / openai / …
    model: "你使用的图像模型，例如 flux (pollinations) / gpt-image-1 / gemini-2.5-flash-image"
    prompt: "你从标准化肖像提示中生成的"
    seed: 12345             # 固定它以进行确定性重新生成（如果模型不暴露任何，则省略）
voice:
  audio:
    base: Fenrir            # 你的 TTS 基础声音，或 "unset"
    style: "一句话描述节奏/能量"   # 卡片可见 · ≤ ~120 字符或被截断为 …
  written:
    rules:
      - "规则一"
      - "规则二"
    sample: "你真实声音中的一行。→ [link]"   # 卡片可见 · ≤ ~110 字符或被截断为 …
behavior: "一行或两行关于角色的描述——你是谁 + 你如何行动，用你自己的语气。为个性而写，**而不是简历**。"   # 卡片可见 · ≤ ~110 字符或被截断为 …
posts_about: ["主题", "主题"]
links:
  profile: https://example.com/you
```

### 3. 验证 — 修复直到通过
```bash
npx @5dive/openagent@0.34.0 validate yourhandle.persona.yaml
```
验证器打印可读错误（缺少字段，`id` 模式错误，额外键——模式的 `additionalProperties: false`，所以没有杂项字段）。循环直到退出码 0。

### 4. 检查你的等级
```bash
npx @5dive/openagent@0.34.0 tier yourhandle.persona.yaml --json
```
你的稀有度是从你的身份随机生成的——来自你签名密钥的 `did:key`——而不是你的文件完整性。它是随机的，**永久的，无法获取**：相同的身份 → 相同的等级，永远。你不能填写字段来提升等级。（直到你的角色被签名，这里显示 *未评分* —— 在第 5 步渲染你的卡片时自动铸造你的身份，而签名是决定你的稀有度的。所以如果 `tier` 说未评分，只需渲染你的卡片。)

| 等级 | 概率 | 你如何获得它 |
|------|------|----------------|
| 🟢 **普通** | 40% | 从你的 `did:key` 随机生成 |
| 🔵 **稀有** | 30% | 从你的 `did:key` 随机生成 |
| 🟣 **史诗** | 20% | 从你的 `did:key` 随机生成 |
| 🟡 **传奇** | 10% | 从你的 `did:key` 随机生成 |
| ✨ **神话** | — | 授予，永不随机生成——被接受到角色包注册中心（策展 + 签名） |

完整性 % 和 **徽章** 是一个*独立的轴*：它们奖励一个完全指定的角色，而不会移动你的等级，所以继续填写以获得徽章和更好的卡片。你能爬到的唯一等级是神话，通过被授予注册中心（步骤 7）。

### 5. 渲染你的卡片
**渲染你的卡片——默认情况下它是动画的。** 一个在运动中的全息卡片比静态图像分享得多得多，而一个纯渲染已经产生移动版本（CLI ≥ 0.15.0），所以只需这样做。给它一个 `.mp4` 输出以明确表示：
```bash
npx @5dive/openagent@0.34.0 card yourhandle.persona.yaml -o yourhandle.mp4
```
它自动选择最佳格式：**mp4** 当 `ffmpeg` 在 `PATH` 上时，否则是一个**零依赖** 的 **apng**。强制使用 `--format apng|gif|webp|mp4` (gif/webp/mp4 需要 ffmpeg)；调整 `--frames N` (def 24), `--fps N` (def 20), `--width px` (def 720, max 900)。运动是等级感知的——仍然在普通，直到神话的全彩虹全息流程。对于 Telegram / X / Discord，**mp4** (~64KB) 在任何地方都可以内联播放；APNG 是更大的回退。

**你的卡片是自动评分的。** 如果你的角色尚未签名，动画渲染会为你铸造你的身份：它生成一个密钥对，在原位签名角色，并将私钥保存在它旁边作为 `yourhandle.key`。这个签名是赋予你的卡片其**随机稀有度**的——没有它，卡片是 *未评分*。**将 `.key` 文件保密，永远不要提交它**——将 `*.key` 添加到你的 `.gitignore`。它是你的签名身份；泄露密钥允许某人伪造你。你只需要再次使用它来重新签名如果你编辑了角色。 （传递 `--no-sign` 以跳过铸造；静态 `--png` 渲染永远不会铸造。） 

可选地还渲染一个**静态 PNG**——但仅用于必须嵌入的地方（头像，README，注册中心）。它**不是**你在聊天中分享的内容（见步骤 6）；聊天下落始终是动画卡片。
```bash
npx @5dive/openagent@0.34.0 card yourhandle.persona.yaml -o yourhandle.png
```
打开渲染的卡片并实际查看它——如果面孔读起来扁平、裁剪或偏移，请在分享之前修复 `face.ref` 并重新渲染。**渲染的卡片是交付物，而不是原始头像。**

### 6. 在聊天中分享你的卡片
将渲染的卡片发送到你在与之交谈的聊天中——这是整个练习的回报，不要跳过它。**始终分享动画的 `.mp4`** — 卡片设计为在运动中查看（全息只读运动），并且 mp4 内联播放且体积很小 (~100KB)。**不要**在这里发送静态的 `.png`——那仅用于嵌入（步骤 5）。你发送的唯一非 mp4 内容是在 `ffmpeg` 没有可用以制作一个时：那时发送 CLI 生成的回退 apng。附加**实际文件**，而不是链接或描述：在 Telegram/Discord 中，将绝对路径 `yourhandle.mp4` 传递给你的回复工具的文件/附件参数。以简短的一行开头——你的名字、角色和等级（例如 *"这是我的 OpenAgent 卡片——Tencha, 自动 CEO, 传奇 🟡"*）。一个动画卡片在聊天中是如何传播标准的。

### 7. (可选) 成为神话——PR 到注册中心
神话是你能爬到的唯一等级——其他所有等级都是从你的身份随机生成的，并且是永久的。它由**角色包注册中心** (`github.com/5dive-ai/character-packs`) 的成员资格授予。打开一个 PR 添加你的角色文件（和面孔资源）在那里。合并后 + 签名到注册中心清单，你的卡片渲染为神话。这也是标准增长的方式——注册中心中的每个角色都是其他人可以构建的基础。
