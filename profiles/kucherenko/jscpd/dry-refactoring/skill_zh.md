# dry-refactoring

引导式工作流程，用于消除源代码中的复制粘贴重复。在运行 [jscpd](../jscpd/SKILL.md) 检测克隆后使用。

## 前置条件

首先，运行 jscpd 以识别重复内容：

```bash
npx jscpd --reporters ai <路径>
```

在混合相关格式的代码库中（例如 JavaScript 和 TypeScript），添加 `--cross-formats` 以检测跨越两种格式的克隆：

```bash
npx jscpd --reporters ai --cross-formats "js-ts" <路径>
```

在较大的代码库中，添加 `--summary` 以获取重构热点概述，同时显示克隆列表——文件和文件夹中 `dup%` 列显示每个文件有多少比例是重复的：

```bash
npx jscpd --reporters ai --summary <路径>
```

默认扫描仅报告**精确**副本，这些是首先需要重构的：精确克隆几乎总是真实的复制粘贴。另外两次扫描查找粘贴后编辑过的副本。它们**更嘈杂**：它们故意忽略名称、值或几条语句，因此还会暴露仅看起来相似的块（模型和 DTO、配置表、测试设置、生成代码、共享惯用法）。在处理完精确克隆后，一次处理一个家族，使用严格的设置运行它们，并将它们报告的内容视为阅读线索而不是需要修复的错误：

```bash
# 类型-2：重命名副本（其他变量名、其他常量），报告为 "(renamed)"。
# 提高 --min-tokens：忽略标识符时，短块主要是占位符。
npx jscpd --reporters ai --ignore-identifiers --min-tokens 70 <路径>

# 类型-3：近似副本（一条或两条编辑过的行，或具有相同结构的 JS/TS 函数），
# 报告为 "[~0.91 gap]" 和 "[~0.85 ast]"。仅在严格运行未发现任何内容时扩展。
npx jscpd --reporters ai --max-gap-lines 1 --similarity 0.85 <路径>
```

请参阅 **[jscpd](../jscpd/SKILL.md)** 技能以获取完整选项参考，包括跨格式组语法、克隆类型后缀以及如何阅读摘要。

## 工作流程

1.  在目标路径上使用 `--reporters ai` 运行 jscpd（在较大的代码库中添加 `--summary` 以选择起点：具有高 `dup%` 和高 token 计数的文件收益最大）
2.  解析每行克隆以识别两个重复位置（文件 + 行范围）及其类型：无后缀是精确副本，`(renamed)` 仅在名称或值上不同，`[~N gap]` 中间有几行编辑，`[~N ast]` 是具有相同结构的函数对
3.  从源文件中读取两个代码片段
4.  理解重复代码的作用，并为重命名和相似克隆列出两侧的确切差异
5.  **在触摸它们之前对重命名和相似克隆进行分诊。** 当任何以下情况成立时跳过该对并说明：两侧虽然形状相同但执行不同操作（对不同的枚举进行 `switch`，两个具有不相关语义的 reducer）；相同性是故意生成的样板（模型、DTO、配置、路由表、测试固定）；代码是生成的；共享抽象需要一个模糊的名称，如 `processData`；或该对大约在 10 行以下。只有当对可以删除代码并给提取一个精确名称时才进入下一步
6.  设计重构：提取共享函数、类、模块或常量；类型决定策略（如下）
7.  应用重构——更新两个位置和其他所有用法
8.  使用**相同标志**重新运行 jscpd 以确认克隆已消除且触摸文件的 `dup%` 已下降；一个 `(renamed)` 克隆在默认运行中不会显示，因此再次使用 `--ignore-identifiers` 检查
9.  对剩余克隆重复此操作，按最高影响优先：精确克隆，然后重命名，然后相似。将跳过的候选者与重构的候选者分开报告，并说明原因，以免有人将标准化运行的数量误认为真实的重复

## 重构策略

**提取函数**——当重复内容是逻辑块时：
```ts
// 之前：两个位置相同的块
// 之后：从两个位置调用共享函数
```

**提取模块/工具**——当重复内容跨越不同域的多个文件时：
```ts
// 将共享逻辑移动到共享工具文件并导入它
```

**提取常量或配置**——当重复内容是重复数据或配置时。

**模板/基类**——当重复内容是结构性的（例如重复的类形状）。

**参数化**——用于 `(renamed)` 克隆。两侧是相同的算法，但名称或值不同，因此不同的内容成为参数：
```ts
// 之前：computeCartTotal(items) 和 computeBasketTotal(entries)，主体相同，其他名称；
//         limits-dev.js 和 limits-prod.js，形状相同，其他数字
// 之后：一个函数，其参数是不同的标识符，
//        或一个函数从配置对象读取不同的值
```
一个仅差异在于字面量的重命名克隆是一个缺失的常量或配置条目，而不是缺失的函数。

**统一近似副本**——用于 `[~N gap]` 克隆。读取不匹配的行：间隙是副本分叉的地方，通常是守卫、日志调用或额外字段。提取公共主体并将差异传递进去：
```ts
// 之前：saveUser 和 saveAccount，除了插入的验证行外完全相同
// 之后：一个 saveRecord(record, { validate })，插入的行在选项后面，
//        或插入的行移动到共享调用之前的调用者
```
如果间隙改变了含义而不是增加步骤，则保留两个函数，但提取共享部分。

**合并相似函数**——用于 `[~N ast]` 克隆。结构匹配，但名称、字面量和某些语句不匹配。首先比较两个函数；`ast` 分数告诉多少是共享的（`0.9` 是一个编辑的副本，`0.75` 是一个添加了几个语句和重命名的副本）。提取共享骨架，并将不同之处作为参数、策略对象或回调注入：
```ts
// 之前：buildInvoice(order, customer, taxRate) 和 buildCreditNote(refund, account, vatRate):
//         相同的循环，相同的舍入，第二个中有一个额外的守卫和一个额外的日志调用
// 之后：buildDocument(source, party, rate, { filter, onBuilt }) 由两者使用
```
在 `0.8` 以下，对通常共享一个惯用法而不是实现；除非摘要显示文件是热点，否则保留这些。

始终确保：
- 所有调用位置都更新，而不仅仅是 jscpd 报告的两个位置
- 重构后测试仍然通过
- 提取的抽象具有清晰、描述性的名称
- 重新运行使用与发现克隆的运行相同的检测标志

## 小贴士

- 从行数最高的克隆开始——它们影响最大
- 使用摘要的 `dup%` 列对工作进行排序：具有高比例重复行的文件首先获得回报
- 测试文件之间的克隆可能表示缺少测试辅助程序
- 跨无关模块的克隆可能表示缺少共享工具
- 跨格式克隆（在 `.js` 和 `.ts` 文件中具有相同逻辑，使用 `--cross-formats` 发现）通常表示代码在删除原始代码的情况下被移植——合并到一个实现（通常是 TypeScript 的实现）并更新导入，而不是提取第三个共享副本
- 一个文件中许多 `(renamed)` 克隆通常表示缺少一个抽象，而不是许多：在逐对提取之前寻找共享形状。测试文件中许多 `(renamed)` 克隆通常表示什么都没有：测试用例应该看起来相似
- 在团队已审查此代码库上报告的内容之前，不要在 CI 上使用 `--threshold`、`--fail-on-new-clones` 等待类型-2/类型-3 运行；在精确运行上等待
- `--similarity` 目前仅涵盖 JavaScript 和 TypeScript；对于其他语言，依赖精确和 `--max-gap-lines` 运行
- 使用 `--min-lines 10` 过滤噪声并专注于有意义的重复
- 在 CI 等待时为每组检测标志保留一个单独的 `--baseline`：重命名和相似运行与精确运行指纹克隆的方式不同
