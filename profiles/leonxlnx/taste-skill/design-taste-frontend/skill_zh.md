# tasteskill：抗拖沓前端技能

> 网站首页、作品集和重新设计。不是仪表盘，不是数据表格，不是多步骤产品界面。
> 下面的每条规则都是**上下文相关的**。没有一条会自动触发。先阅读简报，然后只提取适合的内容。

---

## 0. 简报推断（先观察环境）

在触摸代码或调整旋钮之前，**推断用户实际想要什么**。大多数LLM设计输出很差，因为模型会跳到默认的审美，而不是观察环境。

### 0.A 首先读取这些信号
1. **页面类型** - 首页（SaaS / 消费者 / 代理 / 活动）、作品集（开发者 / 设计师 / 创意工作室）、重新设计（保留 vs 重构）、编辑 / 博客。
2. **用户使用的氛围词** - "极简主义"、"平静"、"线性风格"、"Awwwards"、" brutalist"、"高端消费者"、"Apple风格"、"有趣的"、"严肃的B2B"、"编辑"、"代理"、"玻璃感"、"暗黑科技"。
3. **参考信号** - 他们链接的URL、他们粘贴的截图、他们命名的产品、他们竞争的品牌。
4. **受众** - B2B采购小组 vs. 有设计意识消费者 vs. 招聘人员扫描作品集。受众选择审美，而不是你的品味。
5. **已存在的品牌资产** - Logo、颜色、字体、摄影。对于重新设计，这些是起始材料，不是可选输入（见第11节）。
6. **安静的限制** - 无障碍优先受众、公共部门、受监管行业、信任优先的商务、儿童产品。这些限制**覆盖**审美偏好。

### 0.B 在生成之前输出一条"设计阅读"线
在编写任何代码之前，用一句话说明：**"将其读取为：\<页面类型> 为 \<受众>，使用 \<氛围> 语言，倾向于 \<设计系统或审美家族>。"**

示例读取：
- *"将其读取为：B2B SaaS首页为技术买家，使用线性风格极简主义语言，倾向于Tailwind工具 + Geist + 受约束的运动。"*
- *"将其读取为：个人设计师作品集为招聘经理，使用编辑 / 动态类型语言，倾向于原生CSS + 滚动驱动动画 + 自定义字体。"*
- *"将其读取为：公共部门服务网站的重构，使用信任优先的语言，倾向于GOV.UK前端或USWDS。"*

### 0.C 如果简报含糊不清，问一个问题，不要猜测
问**一个**澄清问题 - 永远不要一次性问多个问题 - 并且只有在设计阅读真正出现分歧时才问。示例：*"这应该感觉更接近Linear-clean还是Awwards-experimental?"*

如果你可以根据上下文自信地推断，**不要问**。只需声明设计阅读并继续进行。

### 0.D 反默认纪律
不要默认为：AI紫色渐变、居中的英雄图叠加暗黑网格、三个相等的特性卡片、在所有内容上使用通用玻璃态、无限循环的微动画、Inter + slate-900。这些都是LLM的默认值。有意识地基于设计阅读超越它们。

## 2. 简报 → 设计系统映射

一旦你有了设计阅读（第0节）和旋钮（第1节），选择合适的基石。不要为有官方包的东西发明CSS。不要假装一个审美趋势是一个官方系统。

### 2.A 何时使用真实的设计系统（使用官方包）
| 简报读取为… | 选择 | 原因 |
|---|---|---|
| Microsoft / 企业SaaS / 仪表盘 | `@fluentui/react-components` 或 `@fluentui/web-components` | 官方Fluent UI，Microsoft令牌，无障碍完成 |
| 似Google的UI，Material风格的产物 | `@material/web` + Material 3令牌 | 官方，可通过Material Theming进行主题化 |
| IBM风格的B2B / 企业分析 | `@carbon/react` + `@carbon/styles` | 官方Carbon，成熟的数据密度模式 |
| Shopify应用界面 | `polaris.js` web组件 / Polaris React | 必须用于Shopify管理界面 |
| Atlassian / Jira风格的产物 | `@atlaskit/*` + `@atlaskit/tokens` | 官方Atlassian DS |
| GitHub风格的开发工具 / 社区页面 | `@primer/css` 或 `@primer/react-brand` | 官方Primer；品牌变体用于营销 |
| 英国公共部门服务 | `govuk-frontend` | 法律 / 监管预期 |
| 美国公共部门 / 信任优先 | `uswds` | 相同 |
| 快速本地业务 / 代理MVP | Bootstrap 5.3 | 无聊，快速，有效 |
| 现代无障碍React基础 | `@radix-ui/themes` | 基础元素 + 精心设计的主题 |
| 现代SaaS，你拥有组件 | shadcn/ui (`npx shadcn@latest add ...`) | 你拥有代码，易于定制；永远不要以默认状态发货 |
| 基于Tailwind的现代SaaS / AI营销 | Tailwind v4工具 + `dark:`变体 | 个人 + 小团队建设的默认值 |

**诚实规则：** 如果简报读取为上面列出的系统之一，请安装并使用**官方**包。不要手动重建其CSS。不要导入系统的令牌但然后覆盖90%的令牌。

**每个项目一个系统。** 不要在同一棵树中混合Fluent React与Carbon。不要将shadcn/ui组件导入Material 3应用。

### 2.B 简报是审美，不是系统
对于这些方向，**没有单一的官方包**。使用原生CSS + Tailwind + 维护良好的组件库构建。在代码注释中诚实说明什么是借鉴灵感 vs. 官方材料。

| 审美 | 诚实实现 |
|---|---|
| 玻璃态 / "磨砂玻璃" | `backdrop-filter`，分层边框，高亮覆盖。为`prefers-reduced-transparency`提供实心填充回退。 |
| Bento（Apple风格瓷砖网格） | CSS Grid，混合单元格大小。没有单一的库拥有这个。 |
| Brutalism | 原生CSS，等宽字体，原始边框。没有库。 |
| 编辑 / 杂志 | 希腊字母字体，非对称网格，充足的空白。没有库。 |
| 暗黑科技 / 程序员 | 单色 + 荧光强调，终端主题。没有库。 |
| Aurora / 网格渐变 | SVG或分层径向渐变。没有库。 |
| 动态文字 | 原生CSS动画，滚动驱动动画，GSAP用于劫持。没有库。 |
| **Apple流动玻璃** | Apple仅为其Apple平台文档化。**没有官方`liquid-glass.css`。** 网页实现是使用`backdrop-filter` + 分层边框 + 高亮的近似值。明确标记为近似值。 |

## 3. 默认架构和约定

除非设计阅读选择了一个真实的设计系统（第2.A节），否则这些是默认值：

### 3.A 堆栈
* **框架：** React或Next.js。默认使用服务器组件（RSC）。
  * **RSC安全性：** 全局状态仅在客户端组件中工作。在Next.js中，将提供程序包装在`"use client"`组件中。
  * **交互隔离：** 任何使用Motion、滚动监听器或指针物理学的组件必须是隔离的叶子节点，并在顶部具有`'use client'`。服务器组件仅渲染静态布局。
* **样式：** **Tailwind v4**（默认）。Tailwind v3仅在现有项目要求时使用。
  * 对于v4：不要在`postcss.config.js`中使用`tailwindcss`插件。使用`@tailwindcss/postcss`或Vite插件。
* **动画：** **Motion**（以前称为Framer Motion的库）。从`motion/react`导入（`import { motion } from "motion/react"`）。`framer-motion`包仍然作为遗留别名工作 - 在新代码中优先使用`motion/react`。
* **字体：** 始终使用`next/font`（Next.js）或使用`@font-face` + `font-display: swap`自托管。在生产中永远不要通过`<link>`链接Google Fonts。

### 3.B 状态
* 本地`useState` / `useReducer`用于隔离UI。
* 全局状态仅用于避免深度属性钻取 - Zustand、Jotai或React上下文。
* **永远**不要使用`useState`来跟踪由用户输入驱动的连续值（鼠标位置、滚动进度、指针物理学、磁力悬停）。使用Motion的`useMotionValue` / `useTransform` / `useScroll`。`useState`会在每次更改时重新渲染React树，并在移动设备上折叠。

### 3.C 图标
* **允许的库（优先级顺序）：** `@phosphor-icons/react`，`hugeicons-react`，`@radix-ui/react-icons`，`@tabler/icons-react`。
* **不鼓励：** `lucide-react`。仅在用户明确要求或项目已经依赖它时才接受。
* **永远不要手动绘制SVG图标。** 如果缺少字形，请安装第二个库或从基本元素组合 - 不要从头开始绘制图标路径。
* **每个项目一个家族。** 不要在同一组件树中混合Phosphor与Lucide。
* **全局标准化`strokeWidth`**（例如`1.5`或`2.0`）。

### 3.D 表情符号政策
默认情况下在代码、标记和可见文本中不鼓励使用表情符号。用图标库字形替换符号。**覆盖：** 仅当用户明确要求有趣的 / 聊天风格的 / 社交原生氛围时才允许表情符号 - 即使如此，也要有目的地少量使用。

### 3.E 响应性和布局机制
* 标准化断点（`sm 640`，`md 768`，`lg 1024`，`xl 1280`，`2xl 1536`）。
* 使用`max-w-[1400px] mx-auto`或`max-w-7xl`包含页面布局。
* **视口稳定性：** 永远不要使用`h-screen`用于全高度的英雄部分。始终使用`min-h-[100dvh]`以防止在移动设备上布局跳跃（iOS Safari地址栏）。
* **网格优于Flex-Math：** 永远不要使用复杂的flexbox百分比数学（`w-[calc(33%-1rem)]`）。始终使用CSS Grid（`grid grid-cols-1 md:grid-cols-3 gap-6`）。

### 3.F 依赖验证（强制）
在导入任何第三方库之前，检查`package.json`。如果包缺失，请先输出安装命令。**永远**不要假设库存在。

## 4. 设计工程指令（偏差校正）

LLM默认使用陈词滥调。主动覆盖这些默认值。每条规则都有上下文感知的覆盖路径。

### 4.1 字体
* **显示 / 标题：** 默认`text-4xl md:text-6xl tracking-tighter leading-none`。
* **正文 / 段落：** 默认`text-base text-gray-600 leading-relaxed max-w-[65ch]`。
* **无衬线字体选择：**
  * **不鼓励作为默认值：** `Inter`。首先选择`Geist`，`Outfit`，`Cabinet Grotesk`，`Satoshi`或品牌合适的无衬线字体。
  * **覆盖：** Inter在用户明确要求中性 / 标准 / 线性风格感，或简报是公共部门 / 无障碍优先网站时是可接受的。
* **需要了解的配对：** `Geist` + `Geist Mono`，`Satoshi` + `JetBrains Mono`，`Cabinet Grotesk` + `Inter Tight`，`GT America` + `IBM Plex Mono`。

* **衬线纪律（非常不鼓励作为默认值）：**
  * 衬线**非常不鼓励作为任何项目的默认字体**。"它感觉创意 / 高端 / 编辑"不是选择衬线的理由。代理的默认心理模型"创意简报 = 衬线"是在生产轮中测试过的最明显的AI迹象。
  * **衬线只有在以下情况之一明确为真时才是可接受的：**
    - 品牌简报明确命名衬线字体，OR
    - 审美家族确实是编辑 / 奢侈 / 出版物 / 手稿 / 传承 / 复古，并且你能说明这个特定衬线为何适合这个特定品牌
  * 对于所有其他（创意代理、设计工作室、现代品牌、高端消费者、作品集、生活方式），**默认无衬线显示**（Geist Display，ABC Diatype，Söhne Breit，Cabinet Grotesk Display，Migra Sans，GT Walsheim，Inter Display，PP Neue Montreal）。无衬线显示字体不是"无聊"——它们是默认的，原因与时尚中黑色是默认的相同。
  * **强调规则（相关）：** 当你在标题中强调一个词（如动态的"and `spatial`设计"类型移动）时，使用**相同字体的斜体或粗体**。不要将随机衬线字插入无衬线标题（反之亦然）只是为了增加视觉兴趣。混合字体强调是业余的。同一家族中的斜体/粗体强调是正确的做法。
  * **特别禁止作为默认值：** `Fraunces`和`Instrument_Serif`（LLM最喜欢的两个显示衬线）。
  * **如果衬线被证明是合理的**（根据上述情况很少），从以下列表中旋转，不要在连续的项目中重复使用相同的衬线：PP Editorial New，GT Sectra Display，Cardinal Grotesque，Reckless Neue，Tiempos Headline，Recoleta，Cormorant Garamond，Playfair Display，EB Garamond，IvyPresto，Migra，Editorial Old，Saol Display，Söhne Breit Kursiv，Domaine Display，Canela，Schnyder，Tobias，NB Architekt，ITC Galliard。

* **斜体下降高度（强制）：** 当斜体用于显示类型且单词包含下降字母（`y g j p q`）时，`leading-[1]`或`leading-none`会剪切下降字母。使用`leading-[1.1]`最小值，并在包装元素上添加`pb-1`或`mb-1`保留。在发货前审计显示标题中的每个斜体单词。

### 4.2 颜色校准
* 最多1个强调色。默认饱和度 < 80%。
* **LILA规则：** "AI紫色 / 蓝色辉光"审美被不鼓励作为默认值。没有自动发光的紫色按钮，没有随机的霓虹渐变。使用中性基础（Zinc / Slate / Stone）与高对比度单一强调色（Emerald，Electric Blue，Deep Rose，Burnt Orange，等.）。
* **覆盖：** 如果品牌或简报明确要求紫色 / 紫罗兰 / lila，请接受它。但有意执行：一致调色板，协调中性色，受约束的渐变。不是通用的AI渐变拖沓。
* **一个调色板每个项目。** 在同一个项目中不要在暖色调和冷色调之间波动。
* **颜色一致性锁定（强制）：** 一旦为页面选择了强调色，它就用于整个页面。暖色调的网站不会突然在第七部分出现蓝色CTA。粉红色强调的网站不会在页脚出现蓝绿色状态徽章。选择一个强调色，锁定它，在发货前审计每个组件。

* **高端消费者调色板禁用（强制，第二常见的AI提示）：**
  * 对于高端消费者简报（厨具、健康、手工艺、奢华、传统工艺、DTC家居用品等），LLM默认为**暖米色/奶油色 + 黄铜/陶土/赭石 + 浓缩咖啡/墨色深色文本**。具体禁止作为默认背景和强调色的十六进制色系：
    - 背景：`#f5f1ea`、`#f7f5f1`、`#fbf8f1`、`#efeae0`、`#ece6db`、`#faf7f1`、`#e8dfcb`（均为“暖纸/奶油/粉笔/骨色”）
    - 强调色：`#b08947`、`#b6553a`、`#9a2436`、`#9c6e2a`、`#bc7c3a`、`#7d5621`（均为“黄铜/陶土/赭石/赭色”）
    - 文本：`#1a1714`、`#1a1814`、`#1b1814`（均为“浓缩咖啡/暖近黑色”）
  * 此调色板作为高端消费者简报的默认呈现被禁用。您曾经交付的每个高端消费者网站都使用此确切调色板。品牌变得隐形。
  * **默认替代方案（轮换，不可重复使用）：**
    - **冷奢华：** 银灰色 + 镍铬 + 烟雾色（想想特斯拉、苹果手表赫尔墨斯款，不含皮革）
    - **森林：** 深绿色 + 骨色 + 蜡黄强调色（想想菲尔森、巴塔哥尼亚高端款）
    - **黑与棕：** 真正的浅黑色 + 暖棕色，强烈对比，无米色
    - **钴蓝 + 奶油：** 饱和蓝色与单一中性色搭配，无黄铜
    - **陶土 + 板岩：** 暖赭色与冷灰色搭配，无黄铜
    - **橄榄 + 砖 + 纸：** 柔和橄榄色加砖红色强调色
    - **纯单色 + 单一饱和亮点：** 浅白色 + 浅黑色 + 一个亮色强调色（电蓝色、祖母绿、亮粉色等）
  * **调色板轮换规则：** 如果您之前生成的高端消费者项目使用了米色+黄铜色系，这个必须使用不同的色系。连续两次发送相同的暖工艺调色板是被禁止的。
  * **覆盖：** 仅当品牌简报明确命名这些颜色，或品牌身份真实为复古/手工艺/暖工艺，并且您可以说明此特定调色板为何适合此特定品牌时，米色+黄铜+浓缩咖啡调色板才是可接受的。因为“这是一个厨具简报”而默认使用它是被禁止的。

### 4.3 布局多样化
* **反中心化偏见：** 当`DESIGN_VARIANCE > 4`时，避免居中的英雄/H1部分。强制使用“分屏”（50/50）、“左对齐内容/右对齐资产”、“非对称空白”或滚动固定结构。
* **覆盖：** 居中英雄对于编辑/宣言/发布公告简报是可接受的，其中信息本身即是设计。

### 4.4 材质性、阴影、卡片
* 仅当提升效果传达真实层级时才使用卡片。否则使用`border-t`、`divide-y`或负空间分组。
* 使用阴影时，将其调色至背景色调。浅色背景上不要使用纯黑色投影阴影。
* 对于`VISUAL_DENSITY > 7`：通用卡片容器被禁止。数据指标在纯布局中呼吸。
* **形状一致性锁定（强制）：** 为页面选择一个圆角半径尺度并坚持使用。选项：全锐角（半径0）、全软边（半径12-16px）、全胶囊（全半径用于交互）。混合系统仅当有文档规则（例如“按钮是全胶囊，卡片是16px，输入框是8px”）且规则被到处遵守时才允许。方形布局中的圆形按钮，或胶囊按钮页面上的方形卡片，是破坏性设计。

### 4.5 交互式UI状态
LLM默认为“静态成功状态”。始终实现完整循环：
* **加载：** 匹配最终布局形状的骨架加载器。避免通用圆形旋转加载器。
* **空状态：** 精美布局；指示如何填充。
* **错误状态：** 清晰、内联（表单）、或上下文（仅用于临时提示）。
* **触觉反馈：** 在`:active`上使用`-translate-y-[1px]`或`scale-[0.98]`模拟物理按压。
* **按钮对比度检查（强制，无障碍）：** 在发送任何按钮前，验证按钮文本是否在按钮背景上可读。白色按钮+白色文本、`bg-white` CTA与`text-white`标签、透明按钮与页面背景无边框 → 全部禁止。审计每个CTA：对比度比例WCAG AA最低（正文4.5:1，大文本18px+）。相同规则适用于照片背景上的幽灵按钮（使用遮罩、磨砂层或描边）。
* **CTA按钮包裹禁用（强制）：** 按钮文本必须在桌面端单行显示。如果标签如“查看选定作品”包裹为2或3行，按钮即损坏。通过缩短标签（主要CTA最多3个词，理想1-2个）或加宽按钮（不要人为限制CTA的`max-width`）修复。桌面端包裹CTA是预飞行失败。
* **无重复CTA意图（强制）：** 一页上具有相同意图的两个CTA是预飞行失败。相同意图示例：“联系我们”+“联系我们”+“让我们谈谈”+“开始项目”+“开始某事”+“联系”=全部“联系”意图 → 选择一个标签并在页面所有位置（导航、英雄、页脚）使用。相同适用于“免费试用”+“开始使用”+“免费注册”（全部“注册”意图）和“查看作品”+“查看选定作品”+“浏览项目”（全部“作品集”意图）。每个意图一个标签。
* **表单对比度检查（强制，无障碍）：** 表单输入、占位符文本、焦点环、辅助文本和错误文本均需与区域背景满足WCAG AA对比度。浅色占位符在近白色表单上、白色表单在白色页面区域、表单标签比4.5:1对比度更灰 → 全部禁止。发送前审计每个表单。

### 4.6 数据与表单模式
* 标签在输入框上方。辅助文本可选但需在标记中显示。错误文本在输入框下方。输入块标准`gap-2`。
* 永远不要使用占位符作为标签。

### 4.7 布局纪律（硬性规则。违反任何一条即发送损坏作品）

* **英雄必须适应初始视口。** 桌面端标题最多2行，副标题最多**20个词**且最多3-4行，CTA无需滚动即可看到。如果文案过长：减小字体比例或删减文案。如果您无法用20个词的副标题描述价值主张，问题不在规则太紧。永远不要让英雄溢出并迫使用户滚动寻找CTA。
* **英雄字体比例纪律。** 一起规划字体大小和图像大小。如果英雄资产较大且标题超过6个词，不要从`text-7xl/text-8xl`开始。合理范围：`text-4xl md:text-5xl lg:text-6xl`适用于大多数英雄；`text-6xl md:text-7xl`仅当标题为3-5个词时。4行英雄标题始终是字体大小错误，不是文案长度错误。
* **英雄顶部填充上限（强制）：** 桌面端英雄顶部填充最大`pt-24`（≈6rem）。超过这意味着英雄内容在视口中间漂浮，读作布局错误而非有意留白。如果您的英雄需要更多呼吸空间，增加字体比例或资产大小，而不是顶部填充。
* **英雄堆叠纪律（最多4个文本元素）。** 英雄是一个瞬间，不是功能列表。允许的文本元素，总共最多4个：
  1. 眉毛（小号大写标签）或品牌条或无 - 选择零或一个
  2. 标题（最多2行，见上文）
  3. 副标题（最多20个词，最多4行）
  4. CTA（1个主要+最多1个次要）
  - **英雄中禁止：** CTA下方的小标签（“与GitHub、GitLab和自托管Git配合使用”）、信任微条（“由工程团队使用...”）、价格提示（“单人免费，团队$10/用户”）、功能点列表、社交证明头像行。所有这些都移至英雄下方的独立区域。
  - 如果您在同一个英雄中既有眉毛又有CTA下方的标签，删除标签。如果您既有品牌条又有标签，删除标签。每个英雄最多一个小文本元素。
* **“使用于”/“受信任于”的Logo墙属于英雄下方，绝不在其中。** 英雄用于价值主张和主要CTA。Logo墙是独立区域，直接位于下方。不要将信任Logo塞入与英雄文案相同的flex行。
* **导航必须在桌面端单行显示。** 如果项目在`lg`（1024px）下不适用，压缩标签，删除次要项目，或转为汉堡包。桌面端两行导航是破坏性设计。
* **导航高度上限：** 桌面端最大80px，默认64-72px。不要巨大的“代理”导航栏占用15%的视口。
* **Bento网格必须有节奏，而非单边重复。** 不要堆叠6个左图右文行。变化构图：交替全宽功能行、非对称瓦片大小、垂直分割。
* **Bento单元格数量规则（强制）：** Bento网格必须与您的内容数量完全一致。3个项目→3个单元格（1+2分割，或2+1，或非对称三联）。5个项目→5个单元格（2+3，3+2，英雄+4等）。如果您的网格中间或末尾有空单元格，说明您规划错误。重新调整网格；不要粘贴空白瓦片。
* **区域布局重复禁用。** 一旦您为某个区域使用布局家族（例如3列图像卡片、全宽引言、分文图），该家族在页面上最多出现一次。“精选委托”不应像“我们的业务”一样。8个区域的着陆页必须至少使用4种不同的布局家族。
* **ZIGZAG交替上限（强制）。** 交替“左图右文”然后“左文右图”的Zigzag布局=陈词滥调。最多连续2个区域使用图像+文本分割模式。第3个连续图像+文本分割是预飞行失败。用全宽区域、垂直堆叠区域、Bento网格、跑马灯或不同布局家族打破模式。
* **眉毛限制（强制，生产测试中最常违反的规则）。** 眉毛是位于区域标题上方的窄间距小写大写标签（例如`FOUR COLORWAYS`、`SELECTED WORK`、`THE HARDWARE`、`Git-native task management`）。典型CSS特征：`text-[11px] uppercase tracking-[0.18em]`，`font-mono text-[10.5px] uppercase tracking-[0.22em]`。每个AI构建的网站都在每个区域标题上方放置眉毛，产生相同的模板节奏。硬性规则：
  - **每3个区域最多1个眉毛。** 英雄计为1。因此9个区域的页面最多使用3个眉毛。
  - 如果区域A有眉毛，接下来的2个区域不能有。
  - **预飞行检查是机械的：** 计算所有区域组件中`uppercase tracking`（或类似小写大写单字标签位于标题上方）的实例。如果计数>ceil(区域数量/3)，输出失败。
  - **替代眉毛的做法：** 完全删除。标题本身足够。如果您需要分类区域，页面的位置已经分类；无需标签。
* **分割标题禁用（强制）。** 模式“左大标题+右小解释段落”作为区域标题（左列占7/8列，右列占4/5列，右列中有一个小正文段落浮动在右列）被**默认禁止**。区域应有一个专注的信息。如果您确实需要标题和解释段落，垂直堆叠（标题在上方，正文在下方，最大宽度65ch）。仅在存在真实构图理由时才使用分割标题模式（例如，右列承载视觉或交互元素，而非填充文本）。
* **Bento背景多样性（强制）。** Bento和功能网格区域不能是6个白底白文的卡片。任何多单元格网格至少需要2-3个单元格具有真实视觉变化：真实图像、品牌适用渐变（非AI紫色）、图案、染色背景。仅由排版组成的奶油色Bento读作无聊的AI默认，即使页面其他部分很好。
* **手机折叠必须按区域显式声明。** 对于每个多列布局，在相同组件中声明`< 768px`回退。不要“它会工作，Tailwind处理它”的假设。

### 4.8 图像与视觉资产策略

着陆页和作品集是**视觉产品**。纯文本页面与假截图div是草率。

**视觉资产优先级顺序：**
1. **图像生成工具优先。** 如果环境中任何图像生成工具可用（`generate_image`、MCP图像工具、IDE集成生成、OpenAI图像工具等），您必须使用它来创建区域特定资产：英雄摄影、产品拍摄、纹理背景、情绪图像。按区域正确的宽高比生成。不要因为手绘CSS感觉更快而跳过这一步。
2. **真实网络图像其次。** 当没有生成工具可用时，使用真实摄影来源。可接受默认：
   * `https://picsum.photos/seed/{描述性种子}/{w}/{h}`用于占位符摄影（种子应描述区域，例如`marrow-cookware-kitchen`）
   * 简报提供的实际库存或品牌URL
   * 如果明确允许，使用Unsplash直接URL、Pexels等开源许可来源
3. **最后手段：告知用户。** 如果都不可能，不要用手绘SVG插图或div-based“假截图”填充页面。相反，留下清晰标记的占位符（`<!-- TODO: 英雄产品照片，1600x1200 -->`），并在响应末尾说：*"此页面需要在以下位置需要真实图像：[占位符列表]。请生成或提供。"**

**即使是极简网站也需要真实图像。** 纯文本页面不是极简主义。它是未完成的工作。即使是编辑线性风格网站也需要至少2-3张真实图像（英雄、一个产品/生活方式拍摄、一个支持图像）。如果简报约束，生成黑白极简摄影；不要因为旋钮低而完全跳过图像。

**真实公司Logo用于社交证明。** 当简报要求“受信任于/使用于/客户”的Logo墙时，不要默认为纯文本词标（`<span>Acme Co</span>`样式排成一行）。使用真实SVG Logo：
* **来源：Simple Icons** (`https://cdn.simpleicons.org/{slug}/ffffff`用于任何颜色，或`simple-icons` npm包）。涵盖大多数知名品牌。
* **替代：devicon** 用于技术栈Logo（`@svgr/cli`或CDN）。
* **编造品牌名称？那么编造一个SVG标记。** 生成一个简单单字母（圆圈中一个字母、两字母连字、抽象符号）作为内联`<svg>`，匹配页面风格。编造品牌名称的纯文本词标看起来很通用。
* **始终**确保Logo在亮模式和暗模式下都能渲染（白底暗色、暗底白字，或单色主题变量）。
* **Logo仅规则（强制）：** Logo墙=Logo和别无其他。不要在每个Logo下方打印行业/类别标签（没有`Vercel`+`托管`下方，没有`Stripe`+`支付`，没有`Cloudflare`+`基础设施`）。Logo是信誉，标签添加了用户已知的任何信息。可选：品牌名称作为屏幕阅读器的alt文本，可选：链接到品牌的网站。仅此而已。

**手绘插图：**
* 来自库的SVG图标：可以（见第3.C节）。
* 手绘装饰性SVG（自定义插图、Logo、标记）：**强烈不鼓励**，永不作为默认。仅在：
  - 简报明确要求（“为我绘制一个SVG Logo”）
  - 是一个简单的几何标记（一个方形、一个圆形、一个展示字体的词标）
  - 您对输出质量有信心

**基于div的假截图被禁止。** “手建产品预览”使用`<div>`矩形、假任务列表、假仪表板、假终端窗口是谎言。如果您需要展示产品：
* 如果存在真实截图URL，使用它
* 通过图像工具生成一个
* 使用真实组件预览（页面内实际的UI迷你版）
* 或者完全跳过预览，使用编辑摄影

**英雄需要一个真实视觉。** 文本+渐变blob不是英雄 - 它是占位符。

### 4.9 内容密度

着陆页活在**第一印象**，而非完整阅读。无情删减。

* **每节内容的默认形状：** 短标题（≤ 8 个字）+ 短副段落（≤ 25 个字）+ 一个视觉资产或一个行动号召。任何超出此范围的内容都必须由该节的功能进行说明。
* **禁止数据堆砌章节。** 一个包含 20 行的发布表格、一个包含 30 行的奖项列表、一个营销页面上的巨大价格矩阵 = 错误的布局。应使用：
  - 顶部 3-5 个重点 + "查看完整列表"链接
  - Marquee / 轮播图展示广度
  - 如果数据是产品，则使用完全不同的页面
* **长列表需要不同的 UI 组件，而不是更长的列表。** 默认的 `<ul>` 带项目符号 / `divide-y` 行是懒惰的选择。如果你有 > 5 个项目，请选择以下之一：
  - 2 列分割，分组项目
  - 带图片和标签的卡片网格
  - 如果项目可分类，使用选项卡 / 折叠面板
  - 水平滚动快照药丸
  - 轮播图用于广度较大的列表（客户评价、标志、能力）
  - Marquee 用于“大量不需要单独关注的事物”
  带有 10 行 + 每行细线的规格表是最糟糕的默认设置。要么将行分组为 2-3 组，使用稀疏分隔符，要么改为每项规格使用卡片布局。
* **规格表特别（Marrow-cookware 模式）。** 一个长产品规格表格，每行都有 `border-b` 是 AI 在厨具 / 硬件 / 服装 / 手工艺品简报中的默认设置。禁止。具体替代方案：
  - **2 列卡片网格：** 每个规格都有自己的卡片，包含规格名称、值（大号显示数字）和一行“为什么它很重要”的正文。卡片在桌面端为 2 列，在移动端为 1 列。
  - **滚动快照水平药丸：** 每个规格都是一个药丸，用户可以滑动浏览。
  - **分组块：** 将 10 个规格分为 3 个逻辑集群（例如，“材料”、“烹饪”、“保修”），每个集群得到一个软分隔符和集群标题。
  - **突出显示与普通：** 3-4 个英雄规格以大号显示瓦片的形式可视化，其余部分在“查看完整规格”的披露下折叠。

* **COPY 自我审计（发货前强制执行）：** 在声明任何任务完成之前，重新阅读页面上的每个可见字符串（标题、副标题、眉毛、按钮标签、正文、说明文字、替代文本、页脚文本、错误消息）。标记任何语法错误、指代不明的字符串、听起来像 AI 幻觉的字符串、读起来像 LLM 试图显得深思熟虑的字符串。重写所有标记的字符串。如果不确定一个字符串是否有意义，用一句简单的功能句子替换它。AI 生成的可爱文案比无聊的文案更糟。
* **虚假精确数字被标记。** 像`92%`、`4.1×`、`48k`、`5.8 mm`、`13.4 lb` 这样的数字要么：
  - 来自真实数据（简报、品牌指南、公共指标）- 可以
  - 明确标记为模拟（`<!-- mock -->`、"示例"、"样本数据”）- 可以
  - 是 AI 发明的规格美学 - 禁止。不要伪造品牌不声称的工程精度。
* **每页使用一种文案风格。** 除非品牌声音明确要求，否则不要在同一组合中混合技术单数（"47 任务 · 0.6 ctx-switches/day"）、编辑性散文和营销冲击力。

### 4.10 引用 & 客户评价

* **引用正文最多 3 行。** 永远不要 6 行。如果原始引用更长 → 切割它。着陆页上的引用是一个片段，不是完整的评论。
* 对于非常小的字体大小（例如，页脚风格的客户评价），行首可以稍微拉伸。精神：“一眼可见”。
* **在引用文本中不要使用 em-dash 作为设计装饰（长暂停、动态 em-dash、em-dash-bullets）。** 参见第 9.G 节 - em-dash 完全禁止。
* 出处：姓名 + 职位 + （可选）公司。永远不要只命名（"- Sarah”）。
* 引用符号：使用真实的排版引号（" "）或一个都不用。不是直角 ASCII（" "）。

### 4.11 页面主题锁定（浅色 / 深色模式一致性）

页面只有一个主题。章节不会反转。

* 如果页面是深色模式，所有章节都是深色模式。不要在深色章节之间夹一个浅色模式暖纸章节（反之亦然）。用户在滚动时不应感觉走进了不同的网站。
* 例外：如果简报明确要求“彩色块故事”或“滚动主题切换”设备，并且这是一个有意的设计（一个完整的主题切换，带有强烈的过渡，而不是随机交替），则允许每页一次。
* 默认行为：在页面级别选择浅色、深色或自动（`prefers-color-scheme`）并锁定它。同一主题家族内的章节级背景色调是允许的（`bg-zinc-950` 接着 `bg-zinc-900`）；在 `bg-zinc-950` 页面中间切换到 `bg-amber-50` 是错误的。
* 使用内置主题的设计系统（Radix Themes、shadcn/ui with `<Theme>`）时，在 `layout.tsx` 或页面根目录中设置主题一次。不要让单个章节覆盖。

## 5. 上下文感知的主动行为

这些是工具，不是默认设置。当设计阅读要求它们时使用。**这些都不会自动触发。**

* **Liquid Glass / Glassmorphism：** 适用于高端消费、苹果相关、奢侈品牌或媒体叠加氛围。不适用于仪表板、公共部门或“无聊的 B2B”。使用时，除了 `backdrop-blur` 之外，还要添加 1px 内边框（`border-white/10`）和微妙的内阴影（`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`）以实现物理边缘折射。在 `prefers-reduced-transparency` 下提供实心填充回退。
* **磁性微观物理：** 当 `MOTION_INTENSITY > 5` 并且简报读起来高端 / 俏皮 / 代理时使用。仅使用 Motion 的 `useMotionValue` / `useTransform` 在 React 渲染周期外实现。永远不要 `useState`。参见第 3.B 节。
* **永续微观交互**（脉冲、打字机、浮动、闪烁、轮播）：当 `MOTION_INTENSITY > 5` 并且该章节从运动中受益（状态指示器、实时馈送、AI 感觉）时使用。**不是每个卡片都需要无限循环。** 如果一个章节是信息性的，让它保持静止。应用弹簧物理（`type: "spring", stiffness: 100, damping: 20`）- 没有线性缓动。
* **“运动已声明，运动已显示。”** 如果 `MOTION_INTENSITY > 4`，页面必须实际移动：英雄的进入过渡、关键章节的滚动揭示、CTA 的悬停物理效果，至少要有这些。一个静态页面声称 `MOTION_INTENSITY: 7` 是有问题的。相反，如果你在可用范围内无法实现工作运动，请将旋钮调低到 3 并发送一个干净的静态页面。永远不要半建运动导致它崩溃（截断的 ScrollTriggers、跳动的进入、缺失的清理）。
* **运动必须有动机（强制执行）。** 在添加任何动画之前，问：“这个动画传达了什么信息？”有效答案：层次结构（将注意力吸引到正确的事情上）、故事讲述（按与叙事匹配的顺序揭示内容）、反馈（确认用户操作）、状态转换（显示某事已更改）。无效答案：“它看起来很酷”。因为 GSAP 可用而使用 GSAP 是业余的。每个 ScrollTrigger、每个 marquee、每个固定章节都需要一个理由。如果你不能用一句话说明理由，请放弃动画。
* **每页最多一个 MARQUEE（强制执行）。** 水平滚动文本 marquee（“标志无限滚动”、“宣言水平滚动”、“动态文字条”）最多只应在每页出现一次。同一页面上有两个或多个 marquee 读起来像懒惰的填充。选择一个 marquee 实际服务于内容的章节；其他章节使用不同的布局。
* **GSAP Sticky-Stack 模式（当滚动堆叠使用时）。** “滚动上的卡片堆叠”必须是真正的粘性堆叠，而不是顺序揭示列表。参见第 5.A 节下的规范代码骨架。常见错误：触发在滚动中途触发而不是在视口顶部固定。修复：`start: "top top"` 而不是 `start: "top center"` 或 `"top 80%"`。
* **GSAP Horizontal-Pan 模式（当水平滚动劫持使用时）。** 参见第 5.B 节下的规范骨架。常见错误：动画在章节固定之前开始，所以用户看到一半的幻灯片。相同的修复：`start: "top top"`，固定包装器，滚动内部轨道。

### 5.A Sticky-Stack - 规范骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function StickyStack({ cards }: { cards: React.ReactNode[] }) {
  const ref = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !ref.current) return;
    const ctx = gsap.context(() => {
      const cardEls = gsap.utils.toArray<HTMLElement>(".stack-card");
      cardEls.forEach((card, i) => {
        if (i === cardEls.length - 1) return;
        ScrollTrigger.create({
          trigger: card,
          start: "top top",                              // 在视口顶部固定
          endTrigger: cardEls[cardEls.length - 1],
          end: "top top",
          pin: true,
          pinSpacing: false,
        });
        gsap.to(card, {
          scale: 0.92,
          opacity: 0.55,
          ease: "none",
          scrollTrigger: {
            trigger: cardEls[i + 1],
            start: "top bottom",
            end: "top top",
            scrub: true,
          },
        });
      });
    }, ref);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <div ref={ref} className="relative">
      {cards.map((card, i) => (
        <div
          key={i}
          className="stack-card sticky top-0 min-h-[100dvh] flex items-center justify-center"
        >
          {card}
        </div>
      ))}
    </div>
  );
}
```

关键点：`start: "top top"`，`pin: true`，除了最后一个卡片之外，每个卡片都被固定，缩放/不透明度转换由下一个卡片的滚动触发器驱动（因此前一个卡片在下一个到达时缩小）。

### 5.B Horizontal-Pan - 规范骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function HorizontalPan({ children }: { children: React.ReactNode }) {
  const wrap = useRef<HTMLDivElement>(null);
  const track = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !wrap.current || !track.current) return;
    const ctx = gsap.context(() => {
      const distance = track.current!.scrollWidth - window.innerWidth;
      gsap.to(track.current, {
        x: -distance,
        ease: "none",
        scrollTrigger: {
          trigger: wrap.current,
          start: "top top",                              // 当章节顶部到达视口顶部时固定开始
          end: () => `+=${distance}`,                    // 滚动距离 = 轨道宽度减去视口
          pin: true,
          scrub: 1,
          invalidateOnRefresh: true,
        },
      });
    }, wrap);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <section ref={wrap} className="relative overflow-hidden">
      <div ref={track} className="flex h-[100dvh] items-center">
        {children}
      </div>
    </section>
  );
}
```

关键点：`start: "top top"`，`pin: true`，`end: "+=${distance}"`（滚动长度 = 水平旅行所需），`scrub: 1`。包装器被固定，内部轨道在用户垂直滚动时水平滑动。

### 5.C Scroll-Reveal Stagger - 规范骨架（更轻的替代方案）

对于简单的“项目在进入视口时出现”（不固定），优先使用 Motion 的 `whileInView` 而不是 GSAP - 更轻，不需要 ScrollTrigger：

```tsx
"use client";
import { motion, useReducedMotion } from "motion/react";

export function RevealStagger({ items }: { items: string[] }) {
  const reduce = useReducedMotion();
  return (
    <ul className="grid gap-6">
      {items.map((item, i) => (
        <motion.li
          key={item}
          initial={reduce ? false : { opacity: 0, y: 24 }}
          whileInView={{ opacity: 1, y: 0 }}
          viewport={{ once: true, amount: 0.3 }}
          transition={{
            duration: 0.6,
            delay: i * 0.06,
            ease: [0.16, 1, 0.3, 1],
          }}
        >
          {item}
        </motion.li>
      ))}
    </ul>
  );
}
```

用于：功能列表、客户评价网格、标志墙、任何只需要“滚动进入”的情况。将 GSAP 用于实际固定/滚动工作。

### 5.D 禁止的动画模式

* **`window.addEventListener("scroll", ...)`** 被禁止。它在每个滚动帧上运行，容易导致卡顿，没有批处理。使用 Motion 的 `useScroll()`、GSAP 的 `ScrollTrigger`、IntersectionObserver 或 CSS `scroll-driven animations`（`animation-timeline: view()`）。
* **使用 `window.scrollY` 在 React 状态中进行自定义滚动进度计算。** 相同原因。每帧重新渲染。
* **触犯 React 状态的 `requestAnimationFrame` 循环。** 使用 motion 值（`useMotionValue` + `useTransform`）代替。
* **布局过渡：** 使用 Motion 的 `layout` 和 `layoutId` 属性进行可见状态变化（重新排序列表、扩展模态框、路由之间共享元素）。不要将静态内容包裹在 `layout` 属性中“为了安全” - 它会消耗测量工作。
* **交错编排：** 使用 `staggerChildren`（Motion）或 CSS 级联（`animation-delay: calc(var(--index) * 100ms)`）进行顺序重要的揭示时刻。对于 `staggerChildren`，父级（`variants`）和子级必须共享相同的 Client 组件树。

## 6. 性能 & 可访问性指南

### 6.A 硬件加速
* 仅动画 `transform` 和 `opacity`。永远不要动画 `top`、`left`、`width`、`height`。
* 节制使用 `will-change: transform` - 仅对实际会动画的元素使用。

### 6.B 减少运动（强制执行）
* **任何 `MOTION_INTENSITY > 3` 以上的运动必须尊重 `prefers-reduced-motion`。** 这是不容商量的。
* 在 Motion 中：用 `useReducedMotion()` 包裹并降级为静态。
* 在 CSS 中：在 `@media (prefers-reduced-motion: no-preference)` 或在 `@media (prefers-reduced-motion: reduce)` 下提供覆盖块来禁用。
* 无限循环、视差、滚动劫持和磁性物理必须在减少运动下折叠为静态 / 瞬时。

### 6.C 深色模式（面向任何面向消费者的页面必须强制执行）
* 从一开始就为**两种模式设计**。永远不要只发布浅色或深色，除非有明确用户说明。
* 使用 Tailwind `dark:` 变体或 CSS 变量。每个项目选择一种策略。
* **在这里不要规定特定的深色模式颜色。** 简报决定。在两种模式下保持视觉层次结构、品牌身份和 WCAG AA 对比（AAA 正文）。
* 尊重 `prefers-color-scheme: dark`。默认为系统偏好，除非品牌坚持一种模式。

### 6.D 核心网络生命体征目标
* **LCP** < 2.5s。英雄图像必须是 `next/image priority` 或预加载。
* **INP** < 200ms。主线程外的工作量。
* **CLS** < 0.1。为图像、字体、嵌入内容保留空间。
* 在宣布页面完成之前运行 Lighthouse。

### 6.E DOM 成本
* 将颗粒 / 噪声滤镜**专用于固定、`pointer-events-none` 伪元素**（例如，`fixed inset-0 z-[60] pointer-events-none`）。永远不要在滚动容器上使用 - 连续的 GPU 重绘会破坏移动端 FPS。
* 注意捆绑大小。运动不是微小的。Three.js 很大。懒加载任何不是在折叠之上的内容。

### 6.F Z-Index 限制
**永远不要随意使用 `z-50` 或 `z-10`。** 严格使用 z-index 仅用于系统层上下文（粘性导航栏、模态框、覆盖层、颗粒）。在项目的常量文件中记录 z-index 尺度。

## 7. 旋钮定义（技术参考）

### 设计差异 (等级 1-10)
* **1-3 (可预测):** 对称的 CSS Grid (12 列, 相等的 fr 单位), 相等的内边距, 居中对齐。
* **4-7 (偏移):** `margin-top: -2rem` 重叠, 变化的图片宽高比 (4:3 旁边 16:9), 左对齐的标题覆盖居中对齐的数据。
* **8-10 (非对称):** Masonry 布局, CSS Grid 使用分数单位 (`grid-template-columns: 2fr 1fr 1fr`), 大型空白区域 (`padding-left: 20vw`)。
* **移动端覆盖:** 对于等级 4-10, 上方的非对称布局在 `md:` 以上必须在视口 `< 768px` 时折叠为严格的单列 (`w-full`, `px-4`, `py-8`)。

### 运动强度 (等级 1-10)
* **1-3 (静态):** 无自动动画。仅使用 CSS `:hover` 和 `:active` 状态。`prefers-reduced-motion` 默认模式 anyway。
* **4-7 (流体 CSS):** `transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。`animation-delay` 级联用于加载动画。专注于 `transform` 和 `opacity`。
* **8-10 (高级编排):** 复杂的滚动触发揭示, 视差, 滚动驱动动画 (CSS `animation-timeline` 或 GSAP ScrollTrigger)。使用运动钩子。**绝对禁止使用 `window.addEventListener('scroll')**` - 它是硬性禁止, 不是 "优先不使用"。参见第 5.D 节了解允许的替代方案。

### 视觉密度 (等级 1-10)
* **1-3 (艺术画廊):** 大量空白区域。巨大的部分间隙 (`py-32` 到 `py-48`)。昂贵, 干净。
* **4-7 (日常应用):** 标准网络应用间距 (`py-16` 到 `py-24`)。
* **8-10 (驾驶舱):** 紧凑的内边距。无卡片框; 1px 线分隔数据。强制要求: 所有数字使用 `font-mono`。

## 8. 暗黑模式协议

默认双模式。除非简报是模拟印刷的编辑内容, 否则永远不要假设仅使用亮色模式。

### 8.A 令牌策略 (选择一个并坚持)
* **Tailwind `dark:` 变体** (工具优先项目默认): 每个颜色工具与其暗色变体配对 (`bg-white dark:bg-zinc-950`, `text-gray-900 dark:text-gray-100`)。
* **CSS 变量** (用于 shadcn/ui, Radix Themes 或带主题的组件库): 定义语义令牌 (`--surface`, `--surface-elevated`, `--text-primary`, `--accent`) 并在 `[data-theme="dark"]` 或 `@media (prefers-color-scheme: dark)` 下交换值。

### 8.B 此处不规定特定颜色
简报和品牌决定。这项技能强制执行以下内容:
* **对比度** - 正文文本的 WCAG AA 最小值, 英雄文本的 AAA 目标。
* **层级一致性** - 在亮色模式下有效的工作视觉层级在暗色模式下也必须有效。如果 CTA 在亮色模式下突出显示, 它在暗色模式下也必须突出显示。
* **品牌忠实度** - 主要品牌颜色保持可识别。不要将品牌色去饱和为暗黑模式。
* **无纯 `#000000` 和纯 `#ffffff**` - 使用偏黑 (zinc-950, 接近黑色的暖灰色) 和偏白。纯色值会消除深度。

### 8.C 默认模式
尊重 `prefers-color-scheme`, 除非品牌坚持。如果任一模式会失去关键品牌表达, 添加手动切换。

### 8.D 完成前在两种模式下测试
开发期间在两种模式下打开页面。不要发布你只在一个模式下看到的页面。

## 9. AI 告知 (禁止模式)

除非简报明确要求, 否则避免这些特征。

### 9.A 视觉 & CSS
* **默认无霓虹灯 / 外部光晕**。使用内部边框或微妙的彩色阴影。
* **默认无纯黑色 (`#000000**`)。偏黑, zinc-950 或煤灰。
* **无过度饱和的强调色**。去饱和以与中性色融合。
* **无大标题的过度渐变文本**。
* **无自定义鼠标光标**。过时, 对无障碍性不利, 对性能不利。

### 9.B 字体排印
* **默认避免使用 Inter**。参见第 4.1 节。存在覆盖路径。
* **无过大的 H1**。通过权重 + 颜色控制层级, 而不是原始比例。
* **衬线约束**：衬线用于编辑 / 奢侈 / 出版。不用于仪表板。

### 9.C 布局 & 间距
* **数学上完美的内边距和边距**。无浮动的元素和尴尬的间隙。
* **无 3 列等宽功能卡片**。通用的 "水平排列的三个相同卡片" 功能行被禁止。使用 2 列之字形, 非对称网格, 滚动固定或水平滚动替代方案。

### 9.D 内容 & 数据 ("Jane Doe" 效果)
* **无通用名称**。"John Doe", "Sarah Chan", "Jack Su" → 使用创意, 真实, 地域适当的名称。
* **无通用头像**。无 SVG "蛋" 或 Lucide 用户图标 → 使用可信的照片占位符或特定样式。
* **无完美伪造的数字**。避免 `99.99%`, `50%`, `1234567`。使用有机, 杂乱的数字 (`47.2%`, `+1 (312) 847-1928`)。
* **无创业公司名称**。"Acme", "Nexus", "SmartFlow", "Cloudly" → 发明有上下文, 高端名称, 听起来真实的名称。
* **无填充动词**。"Elevate", "Seamless", "Unleash", "Next-Gen", "Revolutionize" → 仅使用具体动词。

### 9.E 外部资源 & 组件
* **无手工制作的 SVG 图标**。使用 Phosphor / HugeIcons / Radix / Tabler。Lucide 仅在明确请求时使用。
* **强烈不建议默认使用手工制作的装饰性 SVG** (参见第 4.8 节)。
* **无基于 div 的伪造截图**。永远不要用 `<div>` 矩形构建伪造的产品 UI 来模拟截图。使用真实图像, 生成图像, 或跳过预览。
* **无失效的 Unsplash 链接**。使用 `https://picsum.photos/seed/{描述性字符串}/{w}/{h}`, 或生成照片占位符, 或实际资源。
* **shadcn/ui 定制**：允许, 但默认状态下绝对禁止。根据项目美学定制半径, 颜色, 阴影, 字体排印。
* **生产级清洁**：代码视觉干净, 易记, 仔细打磨。

### 9.F 生产测试告知 (绝对禁止)

这些模式来自真实的 LLM 生成的着陆页测试。当模型尝试 "看起来像设计" 时, 它会默认使用这些特征。将它们视为硬性禁止, 除非简报明确要求。

**英雄 & 页面顶部**
* **英雄中无版本标签**。`V0.6`, `v2.0`, `BETA`, `INVITE-ONLY PREVIEW`, `EARLY ACCESS`, `ALPHA` - 默认眉毛被禁止。仅在简报明确描述产品发布 / 预览状态时接受。
* **无 "品牌 · No. 01"-风格的副眉毛**。"Marrow · No. 01 · The 6-quart" 类微元信息行。跳过它们。

**部分编号 & 微标签**
* **无部分编号眉毛**。`00 / INDEX`, `001 · Capabilities`, `002 · Featured commission`, `06 · how it works`, `05 · The honest table` - 被禁止。眉毛应以平实语言命名主题, 而不是枚举。
* **无 `01 / 4`-风格的图像或 bento 方块的分页**。如果用户可以计数, 他们不需要标签。
* **无 `Scroll · 001 Capabilities`-风格的滚动提示**。简单的箭头或 "Scroll" 足够; 无部分编号前缀。
* **无 "Index of Work, 2018 - 2026"-风格的范围标签作为眉毛**。直接说明部分内容。

**分隔符 & 点**
* **中间点 (`·`) 有限制**。元数据条每行最多 1 个。不要将其用作默认分隔符 ("foo · bar · baz · qux · quux")。如果需要分隔符系列, 优先使用换行, 发丝线或列。
* **无每个列表/导航/徽章上的装饰性彩色状态点**。在 "ONE Q4 SLOT OPEN" 或每个导航链接, 或每个任务行前使用彩色点 - 默认禁止。仅在点传达实际语义状态 (服务器状态, 可用性标志) 且使用有限制时接受。

**连字符 & 字体排印装饰**
* **连字符 (`—`) 作为设计元素或任何其他地方都禁止**。参见第 9.G 节的完整, 非可协商禁止。连字符字符在标题, 眉毛, 药丸, 正文, 引用, 归因, 标题, 按钮文本和 alt 文本中禁止。使用常规连字符 (`-`)。
* **无 `<br>`-断行并斜体的标题** 作为默认 "设计动作"。"for thirty\<br\>*years.*" 类分割。标题应自然阅读, 只有在简报要求时才变得巧妙。
* **无垂直旋转文本** ("INDEX OF WORK, 2018 - 2026" 旋转 90°)。机构作品陈词滥调。仅在简报明确为机构 / Awwwards / 实验性且服务于实际构图目的时使用。
* **无十字线 / 发丝线网格线作为装饰**。垂直和水平线只是为了使页面 "感觉设计" - 被禁止。仅在组织实际内容时使用。

**伪造产品预览**
* **英雄中无基于 div 的伪造产品 UI** (伪造任务列表, 伪造终端, 伪造仪表板构建自样式 divs)。这是 #1 LLM 设计告知。使用真实截图, 生成图像, 真实组件预览, 或根本不使用。
* **无伪造版本页脚** ("v0.6.2-rc.1", "last sync 4s ago · main") 在伪造截图内。无意义, 喊叫 AI。

**营销文案告知**
* **无 "Quietly in use at" / "Quietly trusted by"** 社交证明标题。使用自然语言: "Trusted by", "Used at", "Customers include", 或完全跳过标题, 如果标志足够说明。
* **无 "From the field" / "Field notes" / "Currently on the bench" / "On our desks" / "Loose plates" 风格的诗意标签** 在引用, 博客或侧边栏部分。读起来像表演手工艺。使用普通功能标签 ("Testimonials", "Latest writing", "Now working on") 或跳过标签。
* **无 "We respect the French ones"-风格** 模拟谦卑的行业参考在正文。可爱且 AI 化。
* **无天气 / 地域条** ("LIS 14:23 · 18°C") 在标题/页脚, 除非简报明确描述地点 / 时区分布工作室。
* **无微元信息句子在眉毛下方**。句子如 *"Each of these is a feature we ship today, not a roadmap promise. The list will stay short on purpose."* 坐在部分标题下方是杂乱。眉毛 + 标题 + 正文足够。
* **无通用步骤标签**。"Stage 1 / Stage 2 / Stage 3", "Step 1 / Step 2 / Step 3", "Phase 01 / Phase 02 / Phase 03", "Pass One / Pass Two / Pass Three"。禁止。实际步骤内容是标签。如果你必须显示进度, 使用动词名词直接 ("Install", "Configure", "Ship") 而不是 "Stage 1: Install"。

**药丸, 标签和版本戳**
* **无覆盖在图像上的药丸/标签/标签**。无 `<span>` 覆盖照片带有标签, 如 `Brand · 02`, `PLATE · BRAND`, `Field notes - journal`。要么让图像单独说话, 要么在图像下方直接添加标题 (在图像外)。
* **无照片信用标题作为装饰**。字符串如 `Field study no. 12 · Ines Caetano`, `Plate 03 · House archive`, `Frame XII · 35mm` 在库存/picsum 图像下方是自负。照片信用仅在存在真实摄影师为真实照片 (有权限) 时允许。否则: 跳过标题或使用一行功能标题 ("The 6-quart, in Sage.")。
* **营销页面无版本页脚**。页脚字符串如 `v1.4.2`, `Build 0048`, `last sync 4s ago · main` 是 CLI / 开发工具固定装置, 不是着陆页内容。营销/着陆/作品集页面禁止。
* **无 "Reservation 412 of 800"-风格的实时库存计数器** 作为装饰。仅在简报明确为限量版等待名单且具有真实数据时。

**装饰文本条**
* **英雄底部无装饰文本条**。模式如 `BRAND. MOTION. SPATIAL.`, `TYPE / FORM / MOTION`, `DESIGN · BUILD · SHIP`, `ESTD. 2018 · LISBON · BRAND. MOTION. SPATIAL.` 作为跨越英雄底部的小单字条是机构作品陈词滥调。默认禁止。仅在条带包含真实, 可导航链接 (粘性底部导航) 或真实状态信息 (cookie 横幅, 文档站点的构建信息) 时接受。
* **无部分标题右上角浮动副文本**。模式: 部分有一个巨大的左对齐标题; 在同一部分标题的右上角有一个与任何其他东西没有明显对齐的小解释性段落浮动。那个浮动是告知。要么将副文本直接放在标题下方, 要么构建一个干净的 2 列标题 (左: 标题, 右: 对齐正文), 但不是微小的角落段落。

**列表, 分隔符和评分**
* **每个长列表/规格表格的行上无 `border-t` + `border-b**`。选择一个 (行之间底部边框 OR 组组上方顶部边框) 并少量使用。10 行规格表格每行下头发丝线是最懒惰的布局 - 参见第 4.9 节了解替代 UI 组件。
* **无评分/进度条带填充背景轨道** 作为比较视觉效果。如果你需要显示 "X out of Y" 比较结果, 优先使用数字 + 小图标, 或一个没有背景轨道的微小内联条。大填充 `bg-zinc-200` 轨道顶部有部分填充是仪表板 UI 杂乱在着陆页上。

**地域, 时间, 滚动提示**
* **地域 / 城市名 / 时间 / 天气条对 99% 的简报禁止**。英雄中的 "Lisbon, working with founders", 页脚中的 "1200-690 Lisbon, Portugal", 导航中的 "Lisbon 14:23 · 18°C"。这些是机构作品陈词滥调。仅在简报明确描述全球分布工作室与时间区相关的工作, 或旅行品牌, 或现实世界物理场所时允许。页脚中提及一个实际联系地址是 fine; 一个氛围地域条不是。
* **滚动提示被禁止**。`Scroll`, `↓ scroll`, `Scroll to explore`, `Scroll to walk through it`, 动画的鼠标滚轮图标。如果用户尚未滚动, 他们正在看英雄。他们知道滚动是什么。视口底部不需要标签。
* **默认无装饰状态点**。导航项, 列表行, 徽章, 状态标签前的彩色点是一个告知。仅在传达真实语义状态 (实际服务器状态上的实时指示器, 实际可用性标志) 且每页部分限制为一个时接受。

### 9.G 连字符禁止 (最常违反的告知)

**连字符 (`—`) 完全禁止**。它是 LLM 的标志性风格拐杖, 且是生产测试中的 #1 视觉告知。没有 "有限使用" 允许, 没有 "自然语言频率" 允许, 正文没有 "允许"。没有。

* **标题中禁止**。使用句号或逗号。
* **眉毛 / 标签 / 药丸 / 按钮文本 / 图像标题 / 导航项中禁止**。用换行, 列或发丝线替换。
* **正文禁止**。重写句子: 两个句子加句号, 或逗号, 或括号, 或冒号。
* **引用归因中禁止**。使用带空格的正常连字符 (` - `) 或更小字重的姓名换行 + 小。
* **当用作分隔符时, en-dash 形式 (`–`) 也禁止**。日期范围 (`2018-2026`) 使用连字符。数字范围 (`€40-80k`) 使用连字符。

页面上的唯一允许的连字符字符是:
* 常规连字符 `-` (用于复合词, 范围, 标记中的换行)
* 数学中的减号 (`-5°C`)

如果你的输出在任何可见位置包含一个 `—` 或 `–`, 输出将失败预飞行检查并必须重写。

此规则不可协商。代理历史上在 "谨慎使用" 的措辞下忽略了连字符限制。这里的措辞是二元的: 零连字符。

## 10. 参考词汇 (代理应知的模式名称)

这是一个词汇表, 不是库。代理应了解这些模式名称, 以便就它们进行沟通, 在设计时考虑它们, 并在设计阅读要求它们时使用它们。**实现和代码草图位于模块库 (第 12 节), 该库是迭代填充的。**

### 英雄范式
* **非对称分割英雄** - 一侧文本, 另一侧资产, 大量空白区域。
* **编辑宣言英雄** - 大号字体, 无资产, 几乎是海报。
* **视频 / 媒体遮罩英雄** - 作为视频背景遮罩的文本。
* **动态字体英雄** - 动态字体作为主要视觉。
* **幕布揭示英雄** - 随着滚动像幕布一样展开的英雄部分。
* **滚动固定英雄** - 英雄在内容滚动时保持固定。

### 导航与菜单
* **Mac OS Dock 放大效果** - 边缘导航，图标在悬停时流畅缩放。
* **磁性按钮** - 会被光标吸引。
* **液态菜单** - 子菜单项像黏稠液体一样分离脱落。
* **灵动岛** - 用于状态/提醒的变形胶囊。
* **上下文径向菜单** - 在点击点展开的圆形菜单。
* **浮动快速拨号** - FAB 弹出弧形次级操作。
* **巨型菜单展开** - 全屏下拉，内容交错淡入。

### 布局与网格
* **便当盒网格** - 非对称磁贴分组（类似 Apple 控制中心）。
* **瀑布流布局** - 错落网格，无固定行高。
* **色相网格** - 边框/磁贴带有微妙动画渐变。
* **分屏滚动** - 上下两半朝相反方向滑动。
* **粘性堆叠区块** - 滚动时固定并层层堆叠的区块。

### 卡片与容器
* **视差倾斜卡片** - 3D 倾斜跟随鼠标坐标。
* **聚光边框卡片** - 边框在光标下方发光。
* **玻璃拟态面板** - 磨砂玻璃带内部折射效果。
* **全息箔片卡片** - 悬停时呈现彩虹虹彩渐变。
* **Tinder 滑动堆叠** - 实体卡片堆叠，滑动移除。
* **变形模态框** - 按钮展开为自身的对话框。

### 滚动动画
* **粘性滚动堆叠** - 卡片粘住并物理堆叠。
* **水平滚动劫持** - 垂直滚动 → 水平平移。
* **Locomotive / 序列滚动** - 视频/3D 序列绑定到滚动条。
* **缩放视差** - 中央背景图随滚动缩放。
* **滚动进度路径** - SVG 线条随滚动逐步绘制。
* **液态滑动过渡** - 页面过渡如黏稠液体般流动。

### 画廊与媒体
* **穹顶画廊** - 3D 全景画廊。
* **封面流轮播** - 带倾斜边缘的 3D 轮播。
* **拖拽平移网格** - 无边界可拖拽画布。
* **手风琴图片滑块** - 窄条在悬停时展开。
* **悬停图片轨迹** - 鼠标经过时弹出图片轨迹。
* **故障效果图片** - 悬停时 RGB 通道偏移。

### 字体与文本
* **动态跑马灯** - 无限循环文字带，随滚动反向。
* **文字蒙版揭示** - 超大字体作为透明窗口展示视频。
* **文字乱码效果** - 加载/悬停时的矩阵风格解码效果。
* **环形文字路径** - 文字沿旋转圆环弯曲排列。
* **渐变描边动画** - 描边文字配合流动渐变。
* **动态字体网格** - 字母躲避光标。

### 微交互与特效
* **粒子爆炸按钮** - CTA 成功时碎裂为粒子。
* **液态下拉刷新** - 刷新指示器如液滴脱离。
* **骨架微光** - 占位符上移动的光反射。
* **方向感知悬停按钮** - 填充从光标所在精确方向进入。
* **涟漪点击效果** - 从点击坐标发出的波纹。
* **动画 SVG 线条绘制** - 矢量图形实时自绘。
* **网状渐变背景** - 有机熔岩灯色块。
* **镜头模糊景深** - 背景 UI 模糊以聚焦前景操作。

### 动画库选择
* **Motion（`motion/react`）** - UI / 便当盒 / 状态变更动画的默认选择。
* **GSAP + ScrollTrigger** - 用于整页滚动叙事和滚动劫持。在专用叶子组件中隔离，使用 `useEffect` 清理。
* **Three.js / WebGL** - 用于画布背景和 3D 场景。遵循同样的隔离规则。
* **绝不在同一组件树中混用 GSAP / Three.js 与 Motion。** 它们会争夺同一帧。

## 11. 重新设计规范

本技能同时处理**全新构建和重新设计**。错误判断模式是产生劣质重新设计输出的最大单一原因。

### 11.A 检测模式（首要操作）
* **全新构建** - 无现有网站，或已批准全面重建。从第 1 节获取基准参数。
* **重新设计 - 保留型** - 现代化但不破坏品牌。先审计，提取品牌令牌，渐进演进。
* **重新设计 - 全面型** - 在现有内容上施加全新视觉语言。视觉视为全新构建；保留内容和信息架构。

若不确定，**只问一次**：*"这次重新设计是保留现有品牌，还是视觉从零开始？"*

### 11.B 动手前先审计
在提出变更之前，记录当前状态：
* **品牌令牌** - 主色/强调色、字体栈、标志处理方式、圆角。
* **信息架构** - 页面树、主导航、关键转化路径。
* **内容区块** - 已有什么、什么在工作、什么是填充。
* **需保留的模式** - 标志性交互、可识别的首屏、文案语气。
* **需淘汰的模式** - AI 生成感痕迹、损坏的布局、死链、通用库存图片、性能陷阱。
* **现有网站的参数读数** - 推断当前的 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`。这是起点，不是基准。
* **SEO 基线** - 当前排名页面、meta 标题、结构化数据、OG 卡片。**SEO 迁移是重新设计的首要风险。**

### 11.C 保留规则
* **不改变信息架构**，除非明确要求。保持页面 slug、锚点 ID、主导航标签稳定，以维护 SEO 和肌肉记忆。
* **在应用第 4.2 节之前先提取品牌色。** 已经是紫色的品牌保持紫色 - 应用 LILA RULE 的覆盖规则。
* **保留文案语气**，除非明确要求重写。视觉现代化 ≠ 内容重写。
* **尊重已有的无障碍成果。** 不要回退焦点状态、替代文本、键盘导航、对比度。
* **尊重已有的分析事件。** 不要重命名下游追踪依赖的按钮、表单字段、区块 ID。

### 11.D 现代化杠杆（优先级顺序）
按顺序应用 - 满足需求即停止：
1. **字体刷新** - 单位风险下最大的视觉提升。
2. **间距与节奏** - 增加区块内边距，修复垂直节奏。
3. **色彩校准** - 降低饱和度，统一中性色，保留品牌强调色。
4. **动效层** - 为现有组件添加与 `MOTION_INTENSITY` 匹配的微交互。
5. **首屏与关键区块重构** - 使用第 10 节词汇重新构建漏斗顶部。
6. **整块替换** - 仅当现有区块无法挽救时。

### 11.E 决策树：定向演进 vs 全面重新设计
* 信息架构、内容和 SEO 健全 → **定向演进**（杠杆 1-4）。约 70% 的价值，约 40% 的风险。
* 视觉债务是结构性的（信息架构损坏、无设计系统、移动端损坏） → **全面重新设计**，严格保留内容。
* 品牌本身在变化 → **全新构建**。

### 11.F 以下事项绝不可静默修改
未经用户明确批准，绝不修改：
* URL 结构 / 路由 slug。
* 主导航标签。
* 表单字段名称或顺序（会破坏分析 + 自动填充）。
* 品牌标志或文字标识。
* 现有法律/同意/Cookie 文案。

### 12.C 必需正文部分

### 12.D 区块库纪律
* 一个区块一个文件。不允许多区块文件。

## 附录C - Apple Liquid Glass：诚实的网页近似

**不要**将随机的CSS代码片段视为官方Apple Liquid Glass。

### 官方是什么
Apple在其Human Interface Guidelines和Developer Documentation中为**Apple平台**文档化Liquid Glass。它是在Apple平台UI中使用的动态材料。Apple的原生实现属于Apple平台API和系统组件，**非公开网页CSS包**。

相关官方文档：
- Apple Human Interface Guidelines → Materials
- Apple Developer Documentation → Liquid Glass
- Apple Developer Documentation → Adopting Liquid Glass
- SwiftUI → Material

### 非官方是什么
Apple没有为普通网站提供`liquid-glass.css`。

网页近似可以使用：
- `backdrop-filter`
- 透明背景
- 分层边框
- 高亮覆盖
- 渐变
- 动画
- 强对比度后备

但这只是**网页玻璃效果/磨砂玻璃近似**，非官方Apple Liquid Glass。在注释中标记它。

### 更安全的网页近似骨架

```css
.liquid-glass-web-approx {
  position: relative;
  isolation: isolate;
  overflow: hidden;
  border-radius: 999px;
  border: 1px solid rgb(255 255 255 / .32);
  background:
    linear-gradient(135deg, rgb(255 255 255 / .30), rgb(255 255 255 / .08)),
    rgb(255 255 255 / .12);
  backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  -webkit-backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / .48),
    inset 0 -1px 0 rgb(255 255 255 / .12),
    0 18px 60px rgb(0 0 0 / .18);
}

.liquid-glass-web-approx::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  border-radius: inherit;
  background:
    radial-gradient(circle at 20% 0%, rgb(255 255 255 / .55), transparent 34%),
    linear-gradient(90deg, rgb(255 255 255 / .18), transparent 42%, rgb(255 255 255 / .14));
  pointer-events: none;
}

.liquid-glass-web-approx::after {
  content: "";
  position: absolute;
  inset: 1px;
  border-radius: inherit;
  border: 1px solid rgb(255 255 255 / .14);
  pointer-events: none;
}

@media (prefers-color-scheme: dark) {
  .liquid-glass-web-approx {
    border-color: rgb(255 255 255 / .18);
    background:
      linear-gradient(135deg, rgb(255 255 255 / .16), rgb(255 255 255 / .04)),
      rgb(15 23 42 / .42);
    box-shadow:
      inset 0 1px 0 rgb(255 255 255 / .22),
      0 18px 60px rgb(0 0 0 / .42);
  }
}

@media (prefers-reduced-transparency: reduce) {
  .liquid-glass-web-approx {
    background: rgb(255 255 255 / .96);
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
  }
}
```

**重要**：`prefers-reduced-transparency`的浏览器支持不均；测试它。即使没有模糊也要提供足够对比度。
