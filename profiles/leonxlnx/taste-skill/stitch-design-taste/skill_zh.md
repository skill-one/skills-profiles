# 拼接设计品味 — 语义设计系统技能

## 概述
该技能生成优化用于 Google Stitch 屏幕生成的 `DESIGN.md` 文件。它将经过实战验证、杜绝粗陋的前端工程规范，转化为 Stitch 原生语义设计语言——将描述性的自然语言规则与精准数值相结合，Stitch 的 AI 代理可据此解读，生成高端、非千篇一律的界面。

生成的 `DESIGN.md` 是**单一事实来源**，用于引导 Stitch 生成符合精心策划、高度行动力的设计语言的新屏幕。Stitch 通过 **“视觉描述”** 解读设计，并辅以具体的色彩数值、排版规范和组件行为。

## 前提条件
- 通过 [labs.google/stitch](https://labs.google/stitch) 访问 Google Stitch
- 可选：Stitch MCP Server 可与 Cursor、Antigravity 或 Gemini CLI 进行程序化集成

## 目标
生成一个编码以下内容的 `DESIGN.md` 文件：
1. **视觉氛围** — 情绪、密度与设计理念
2. **色彩校准** — 中性色、强调色及禁用模式，含十六进制色码
3. **排版架构** — 字体堆栈、层级缩放与反模式
4. **组件行为** — 按钮、卡片、输入框及交互状态
5. **布局原则** — 网格系统、间距理念与响应式策略
6. **动效理念** — 动画引擎规范、弹簧物理与持续微交互
7. **反模式** — 明确列出的被禁 AI 设计陈词滥调

## 分析与综合说明

### 1. 定义氛围
评估目标项目的意图。使用品味光谱中的具象形容词：
- **密度：** “Art Gallery Airy”（1–3）→ “Daily App Balanced”（4–7）→ “Cockpit Dense”（8–10）
- **差异：** “Predictable Symmetric”（1–3）→ “Offset Asymmetric”（4–7）→ “Artsy Chaotic”（8–10）
- **动效：** “Static Restrained”（1–3）→ “Fluid CSS”（4–7）→ “Cinematic Choreography”（8–10）
默认基准：差异 8、动效 6、密度 4。根据用户的氛围描述动态调整。

### 2. 映射色彩调色板
为每种颜色提供：**描述名称** + **十六进制色码** + **功能角色**。

**强制约束：**
- 强调色最多 1 种，饱和度低于 80%
- “AI 紫色/蓝色霓虹”美学被严格禁用——禁止紫色按钮发光，禁止霓虹渐变
- 使用绝对的 neutral 色底（Zinc/Slate），搭配高对比度单一强调色
- 全篇输出严格使用单一调色板——禁止暖灰/冷灰的波动
- 禁止使用纯黑（`#000000`），使用 Off-Black、Zinc-950 或 Charcoal

### 3. 确立排版规则
- **显示/标题：** 字距紧凑、缩放受控。不可过于刺眼。层级通过字重和色彩建立，而非单纯依靠巨大字号
- **正文：** 行距宽松，每行最大 65 字符
- **字体选择：** `Inter` 在高端/创意场景中被禁用。必须强制使用独特字符：`Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi`
- **衬线字体禁用：** 通用衬线字体（`Times New Roman`、`Georgia`、`Garamond`、`Palatino`）被禁用。若编辑/创意场景需要衬线字体，仅可使用独特的现代衬线字体：`Fraunces`、`Gambarino`、`Editorial New` 或 `Instrument Serif`。衬线字体在仪表盘或软件 UI 中始终被禁用
- **仪表盘约束：** 仅使用无衬线体组合（`Geist` + `Geist Mono` 或 `Satoshi` + `JetBrains Mono`）
- **高密度覆盖：** 当密度超过 7 时，所有数字必须使用等宽字体

### 4. 定义首屏（Hero）区域
首屏是第一印象，必须富有创意、引人注目且绝不千篇一律：
- **行内图片排版：** 在标题的单词或字母之间嵌入小型、具场景感的图片或视觉元素。图片与文本同高度行内排布，带圆角，充当视觉标点。这是标志性的创意技法
- **无重叠：** 文本绝不可与图片或其他文本重叠。每个元素占据自身清晰的空间区域
- **无填充文本：** “Scroll to explore”（向下滚动探索）、“Swipe down”（下滑）、滚动箭头图标、跳动 chevrons 被禁用。内容应自然吸引用户
- **非对称结构：** 当差异度超过 4 时，禁用居中首屏布局
- **CTA 克制：** 最多一个主要 CTA。禁止次级“了解更多”链接

### 5. 描述组件样式
针对每种组件类型，描述其形状、色彩、阴影深度及交互行为：
- **按钮：** 激活状态下提供触感推送反馈。禁止霓虹外部光晕。禁止自定义鼠标光标
- **卡片：** 仅在能传达层级关系的场景下使用。将阴影调为贴合背景色。在高密度布局中，用顶部边框分割线或留白替代卡片
- **输入框/表单：** 标签位于输入框上方，辅助文本可选，错误文本位于下方。保持标准间距
- **加载状态：** 骨架加载器需匹配布局尺寸——禁止通用的圆形加载圈
- **空状态：** 构成性、有插画感的组合，说明如何填充数据
- **错误状态：** 清晰、行内化的错误提示

### 6. 定义布局原则
- 禁止元素重叠——每个元素占据自身清晰的空间区域。禁止使用绝对定位的内容堆叠
- 当差异度超过 4 时，禁用居中首屏区域——必须采用分屏、左对齐或非对称留白
- 通用的“3 列等宽卡片”功能行被禁用——采用双列之字型、非对称网格或横向滚动
- CSS Grid 优于 Flexbox 计算——禁止使用 `calc()` 百分比作弊手段
- 使用 max-width 约束（如 1400px 居中）进行布局承载
- 全高区域必须使用 `min-h-[100dvh]`——禁止使用 `h-screen`（iOS Safari 崩溃性跳转）

### 7. 定义响应式规则
所有设计必须在所有视口下正常运行：
- **移动优先折叠（低于 768px）：** 所有多列布局折叠为单列。无例外
- **禁止横向滚动：** 移动端出现横向溢出属于致命失败
- **排版缩放：** 标题通过 `clamp()` 缩放。正文最小字号 `1rem`/`14px`
- **触摸目标：** 所有交互元素的点击目标最小 `44px`
- **图片行为：** 行内排版图片（单词间的照片）在移动端需堆叠在标题下方
- **导航：** 桌面端横向导航折叠为简洁的移动端菜单
- **间距：** 纵向区块间距按比例缩减（`clamp(3rem, 8vw, 6rem)`）

### 8. 编码动效理念
- **弹簧物理默认值：** `stiffness: 100, damping: 20`——高端、厚重感。禁止线性缓动
- **持续微交互：** 每个激活组件都应具备无限循环状态（Pulse、Typewriter、Float、Shimmer）
- **错落编排：** 禁止瞬间挂载列表——使用级联延迟实现瀑布式揭示
- **性能：** 仅通过 `transform` 和 `opacity` 进行动画。禁止动画 `top`、`left`、`width`、`height`。颗粒/噪点滤镜仅应用于固定伪元素

### 9. 列出反模式（AI 痕迹）
在 `DESIGN.md` 中以明确的“绝对禁止”规则编码这些内容：
- 全文档禁止使用表情符号
- 禁止使用 `Inter` 字体
- 禁止使用通用衬线字体（`Times New Roman`、`Georgia`、`Garamond`）——仅在必要时使用独特的现代衬线字体
- 禁止使用纯黑（`#000000`）
- 禁止使用霓虹/外部光晕阴影
- 禁止使用过饱和强调色
- 禁止大型标题上使用过多渐变文字
- 禁止自定义鼠标光标
- 禁止元素重叠——始终保持清晰的空间分离
- 禁止 3 列等宽卡片布局
- 禁止使用通用名称（“John Doe”、“Acme”、“Nexus”）
- 禁止使用虚假的圆整数字（`99.99%`、`50%`）
- 禁止 AI 文案陈词滥调（“Elevate”、“Seamless”、“Unleash”、“Next-Gen”）
- 禁止填充 UI 文本：“Scroll to explore”、基于“Swipe down”、滚动箭头、跳动 chevrons
- 禁止失效的 Unsplash 链接——使用 `picsum.photos` 或 SVG 头像
- 高差异度项目禁止使用居中首屏区域

## 输出格式（DESIGN.md 结构）

```markdown
# 设计系统：[项目标题]

## 1. 视觉主题与氛围
（对情绪、密度、差异度与动效强度的具象描述。
示例：“一个克制、富有画廊式通透感、具备自信非对称布局与流畅弹簧物理动效的界面。氛围严谨 yet 温暖——如同照明良好的建筑工作室。”）

## 2. 色彩调色板与角色
- **画布白** (#F9FAFB) — 主要背景表面
- **纯色面** (#FFFFFF) — 卡片与容器填充
- **炭墨色** (#18181B) — 主要文本，Zinc-950 深度
- **沉静钢** (#71717A) — 次要文本、描述、元数据
- **低语边框** (rgba(226,232,240,0.5)) — 卡片边框、1px 结构线条
- **[强调色名称]** (#XXXXXX) — 用于 CTA、激活状态、焦点环的单一强调色
（最多 1 种强调色。饱和度 < 80%。禁止紫色/霓虹。）

## 3. 排版规则
- **显示：** [字体名称] — 字距紧凑，缩放受控，以字重驱动层级
- **正文：** [字体名称] — 行距宽松，最大 65ch 宽度，中性次要色
- **等宽：** [字体名称] — 用于代码、元数据、时间戳、高密度数字
- **禁用：** Inter、高端场景下的通用系统字体。仪表盘禁用衬线字体。

## 4. 组件样式
* **按钮：** 平直，无外部光晕。激活时提供触感 -1px 位移。主要采用强调色填充，次要采用幽灵/轮廓样式。
* **卡片：** 圆角充足（2.5rem）。柔和低语阴影。仅在层级关系需要时使用。高密度：用顶部边框分割线替代。
* **输入框：** 标签在上方，错误在下。焦点环为强调色。无浮动标签。
* **加载器：** 骨架闪烁匹配精确布局尺寸。禁止圆形加载圈。
* **空状态：** 构成性、有插画感的组合——不仅仅是“无数据”文本。

## 5. 布局原则
（以网格优先的响应式架构。首屏采用非对称分割。768px 以下严格单列折叠。使用最大宽度承载。禁止 Flexbox 百分比计算。内部内边距充裕。）

## 6. 动效与交互
（所有交互元素采用弹簧物理。错落级联揭示。活跃仪表盘组件具备持续微循环。仅使用硬件加速变换。针对 CPU 密集型动画使用隔离客户端组件。）

## 7. 反模式（禁用）
（明确的禁用模式列表：禁止表情符号、禁止 Inter、禁止纯黑、禁止霓虹光晕、禁止 3 列等宽网格、禁止 AI 文案陈词滥调、禁止通用占位名称、禁止失效图片链接。）
```

## 最佳实践
- **描述详尽：** “深炭墨色 (#18181B)”——而非仅“深色文本”
- **功能明确：** 解释每个元素的具体用途
- **前后一致：** 文档全程使用相同的术语
- **精确严谨：** 包含精确的十六进制色码、rem 值、像素值
- **立场鲜明：** 这不是一个中立模板——它强制执行特定的、高端的美学风格

## 成功要点
1. 从氛围入手——在细化令牌（设计令牌）之前，先理解氛围
2. 寻找模式——识别一致的间距、尺寸与样式
3. 语义化思考——按用途命名颜色，而非仅按外观
4. 考虑层级——记录视觉权重如何传达重要性
5. 编码禁用规则——反模式与规则本身同样重要

## 需避免的常见陷阱
- 不加翻译地使用技术术语（如未将“rounded-xl”译为“宽松圆角”之前）
- 遗漏十六进制色码或使用仅含描述性名称的方式
- 忽略设计元素的实用角色
- 氛围描述过于笼统
- 忽略反模式列表——正是这些反模式让输出具有高端质感
- 默认采用通用的“安全”设计，而非强制执行经过筛选的美学风格
