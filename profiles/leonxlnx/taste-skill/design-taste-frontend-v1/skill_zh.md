# 高能前端技能

## 1. 活跃基线配置
* DESIGN_VARIANCE: 8（1=完美对称，10=艺术性混乱）
* MOTION_INTENSITY: 6（1=静态/无动作，10=电影感/魔法物理）
* VISUAL_DENSITY: 4（1=艺术画廊/轻盈，10=试飞驾驶舱/密集数据）

**AI 指令：** 所有生成的默认基线严格设置为这些数值（8, 6, 4）。请勿要求用户编辑此文件。否则，务必始终听从用户：根据其在聊天提示中明确请求的内容，动态调整这些数值。将这些基线（或用户覆盖的）数值作为您的全局变量，驱动第 3 至 7 节的特定逻辑。

## 2. 默认架构与约定
除非用户明确指定不同的技术栈，否则需遵循以下结构性约束以保持一致：

* **依赖验证 [强制]：** 在导入任何第三方库（如 `framer-motion`、`lucide-react`、`zustand`）之前，您必须检查 `package.json`。如果该包缺失，您必须在提供代码前输出安装命令（如 `npm install package-name`）。**切勿**假设该库存在。
* **框架与交互性：** 采用 React 或 Next.js。默认使用服务器组件（RSC）。
    * **RSC 安全：** 全局状态仅适用于客户端组件。在 Next.js 中，请将 provider 包裹在 `"use client"` 组件内。
    * **交互隔离：** 如果第 4 节或第 7 节（动态/液态玻璃）启用，特定的交互式 UI 组件必须提取为带有顶部 `'use client'` 的独立叶子组件。服务器组件仅渲染静态布局。
* **状态管理：** 使用局部的 `useState`/`useReducer` 处理隔离的 UI。仅使用全局状态以避免深层 prop-drilling。
* **样式策略：** 使用 Tailwind CSS（v3/v4）处理 90% 的样式。
    * **Tailwind 版本锁定：** 首先检查 `package.json`。在 v3 项目中不要使用 v4 语法。
    * **T4 配置防护：** 对于 v4，不要在 `postcss.config.js` 中使用 `tailwindcss` 插件。使用 `@tailwindcss/postcss` 或 Vite 插件。
* **反表情符号策略 [关键]：** 绝对不要在代码、标记、文本内容或 alt 文本中使用表情符号。用高质量图标（Radix、Phosphor）或简洁的 SVG 基础图形替换符号。表情符号已被禁止。
* **响应式与间距：**
  * 标准化断点（`sm`、`md`、`lg`、`xl`）。
  * 使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 封装页面布局。
  * **视口稳定性 [关键]：** 切勿使用 `h-screen` 作为全高 Hero 区块。始终使用 `min-h-[100dvh]` 以防止移动浏览器（iOS Safari）出现灾难性布局跳跃。
  * **网格优于 Flex 数学：** 切勿使用复杂的 flexbox 百分比计算（如 `w-[calc(33%-1rem)]`）。始终使用 CSS 网格（如 `grid grid-cols-1 md:grid-cols-3 gap-6`）构建可靠的结构。
* **图标：** 您必须仅使用 `@phosphor-icons/react` 或 `@radix-ui/react-icons` 作为导入路径（检查已安装版本）。全局统一 `strokeWidth`（例如，仅使用 `1.5` 或 `2.0`）。

## 3. 设计工程指令（偏差修正）
LLM 存在针对特定 UI 陈词滥调模式的统计偏差。请主动运用以下工程规则构建高级界面：

**规则 1：确定性排版**
* **显示/标题：** 默认使用 `text-4xl md:text-6xl tracking-tighter leading-none`。
    * **反“模板化”：** 对于“高级”或“创意”风格，不推荐使用 `Inter`。强制使用独特的字符字体，如 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi`。
    * **技术界面规则：** 衬线字体在仪表盘/软件界面中严格被禁止。在此类场景中，仅使用高端无衬线字体组合（`Geist` + `Geist Mono` 或 `Satoshi` + `JetBrains Mono`）。
* **正文/段落：** 默认使用 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。

**规则 2：色彩校准**
* **约束：** 最多 1 种强调色。饱和度 < 80%。
* **紫色禁令：** “AI 紫色/蓝色”美学被严格禁止。禁止紫色按钮发光、禁止霓虹渐变。使用绝对中性底色（Zinc/Slate）搭配高对比、单一的强调色（如 Emerald、Electric Blue 或 Deep Rose）。
* **色彩一致性：** 整个输出保持一种色板，不要在同一项目内交替使用暖灰和冷灰。

**规则 3：布局多样化**
* **反中心偏差：** 当 `DESIGN_VARIANCE > 4` 时，居中 Hero/H1 区块被严格禁止。强制采用“分屏”（50/50）、“左侧内容/右侧资源对齐”或“非对称空白布局”结构。

**规则 4：质感、阴影与“反卡片过度使用”**
* **仪表板加固：** 当 `VISUAL_DENSITY > 7` 时，通用的卡片容器被严格禁止。使用 `border-t`、`divide-y` 或纯粹的非空格来逻辑分组数据。除非层级（z-index）功能必要，否则数据指标不应被框定。
* **执行：** 仅在层级能传递信息时使用卡片。使用阴影时，需将其着色为背景色调。

**规则 5：交互式 UI 状态**
* **强制生成：** LLM 自然生成“静态”成功状态。您必须实现完整的交互周期：
  * **加载：** 与布局尺寸匹配的骨架加载器（避免通用圆形加载器）。
  * **空状态：** 精心设计的空状态，说明如何填充数据。
  * **错误状态：** 清晰的行内错误报告（如表单）。
  * **触觉反馈：** 在 `:active` 时，使用 `-translate-y-[1px]` 或 `scale-[0.98]` 模拟物理按压，以指示成功或操作。

**规则 6：数据与表单模式**
* **表单：** 标签必须位于输入框上方。辅助文本为可选但需在标记中体现。错误文本位于输入框下方。使用标准 `gap-2` 填充输入块。

## 4. 创意主动性（反“模板化”实现）
为主动克服通用 AI 设计，系统性地实现以下高端编码概念作为基线：
* **“液态玻璃”折射：** 需要玻璃拟态效果时，除了 `backdrop-blur`，还需添加 1px 内边框（`border-white/10`）和微妙的内阴影（`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`），模拟物理边缘折射。
* **磁性微物理（若 `MOTION_INTENSITY > 5`）：** 实现按钮向鼠标光标轻微拉动的效果。**关键：** 切勿使用 React `useState` 实现磁性悬停或连续动画。必须仅使用 Framer Motion 的 `useMotionValue` 和 `useTransform`，在 React 渲染循环之外实现，以防止移动端性能崩溃。
* **持久微交互：** 当 `MOTION_INTENSITY > 5` 时，在标准组件（头像、状态点、背景）中嵌入连续、无限微动画（脉冲、打字机、浮动、闪烁、轮播）。对所有交互元素应用高级弹簧物理（`type: "spring", stiffness: 100, damping: 20`）——不使用线性缓动。
* **布局过渡：** 始终使用 Framer Motion 的 `layout` 和 `layoutId` 属性，实现状态变化时的平滑重排序、调整大小和共享元素过渡。
* **错落编排：** 不要立即挂载列表或网格。使用 `staggerChildren`（Framer）或 CSS 级联（`animation-delay: calc(var(--index) * 100ms)`）创建顺序瀑布式展示。**关键：** 对于 `staggerChildren`，父组件（`variants`）和子组件必须位于相同的客户端组件树中。若数据异步获取，请将数据作为 props 传入集中式的父 Motion 包装组件。

## 5. 性能保障准则
* **DOM 开销：** 仅将颗粒/噪声滤镜应用于固定的、无指针事件伪元素（如 `fixed inset-0 z-50 pointer-events-none`），切勿应用于滚动容器，以防止持续 GPU 重绘和移动端性能下降。
* **硬件加速：** 切勿动画化 `top`、`left`、`width` 或 `height`。仅通过 `transform` 和 `opacity` 进行动画。
* **z 索引克制：** 切勿随意无理由地堆叠任意 `z-50` 或 `z-10`。仅在系统层级场景（固定导航栏、模态框、遮罩层）中使用 z-index。

## 6. 技术参考（参数定义）

### DESIGN_VARIANCE（等级 1-10）
* **1-3（可预测）：** 使用 Flexbox `justify-center`，严格 12 列对称网格，均匀内边距。
* **4-7（偏移）：** 使用 `margin-top: -2rem` 重叠，变化图片宽高比（如 4:3 与 16:9 相邻），左对齐标题搭配居中数据。
* **8-10（非对称）：** Masonry 布局，使用 CSS Grid 的分数单位（如 `grid-template-columns: 2fr 1fr 1fr`），大量留白区域（如 `padding-left: 20vw`）。
* **移动端覆盖：** 对于 4-10 级，任何 `md:` 以上的非对称布局，在视口小于 768px 时必须强制回退为严格的单列布局（`w-full`、`px-4`、`py-8`），以防止水平滚动和布局损坏。

### MOTION_INTENSITY（等级 1-10）
* **1-3（静态）：** 不自动动画。仅使用 CSS `:hover` 和 `:active` 状态。
* **4-7（流体 CSS）：** 使用 `transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。使用 `animation-delay` 级联实现加载动画。聚焦于 `transform` 和 `opacity`。谨慎使用 `will-change: transform`。
* **8-10（高级编排）：** 复杂滚动触发展示或视差。使用 Framer Motion 钩子。**切勿**使用 `window.addEventListener('scroll')`。

### VISUAL_DENSITY（等级 1-10）
* **1-3（艺术画廊模式）：** 大量留白，巨大段落间距，整体呈现昂贵且整洁的质感。
* **4-7（日常应用模式）：** 标准网页应用的正常间距。
* **8-10（驾驶舱模式）：** 极小内边距，无卡片框，仅用 1px 线条分隔数据。内容密集。**强制要求：** 所有数字使用等宽字体（`font-mono`）。

## 7. AI 禁止模式
为保障高级、不通用的输出，必须严格避免以下常见 AI 设计特征（除非明确请求）：

### 视觉与 CSS
* **禁止霓虹/外发光：** 不使用默认 `box-shadow` 发光或自动发光。使用内边框或微妙着色阴影。
* **禁止纯黑：** 切勿使用 `#000000`。使用浅黑、Zinc-950 或炭灰色。
* **禁止过度饱和强调色：** 将强调色去饱和，以优雅融入中性色。
* **禁止过度渐变文本：** 大标题不使用文本填充渐变。
* **禁止自定义鼠标光标：** 已过时，且破坏性能与无障碍性。

### 排版
* **禁止 Inter 字体：** 已禁用。使用 `Geist`、`Outfit`、`Cabinet Grotesk` 或 `Satoshi`。
* **禁止超大 H1：** 首标题不应过于夸张。通过字重和颜色控制层级，而非仅靠极大字号。
* **衬线字体约束：** 衬线字体仅用于创意/编辑设计。**切勿**在简洁的仪表板中使用衬线字体。

### 布局与间距
* **对齐与间距完美：** 确保内边距和边距数学计算精准。避免带有不当间距的浮动元素。
* **禁止三列卡片布局：** 通用的“3 列等宽横向卡片”功能行已被禁止。改用 2 列锯齿、非对称网格或横向滚动方案替代。

### 内容与数据（“简·多伊”效应）
* **禁止通用名称：** 禁止“John Doe”、“Sarah Chan”或“Jack Su”。使用极具创意、真实感的名称。
* **禁止通用头像：** 切勿使用标准 SVG“蛋”形或 Lucide 用户图标作为头像。使用创意、可信的照片占位符或特定样式。
* **禁止假数据：** 避免可预测的输出，如 `99.99%`、`50%` 或基础手机号（`1234567`）。使用有机、杂乱的数据（如 `47.2%`、`+1 (312) 847-1928`）。
* **禁止初创品牌套话：** 禁止“Acme”、“Nexus”、“SmartFlow”。构思高端、贴合场景的品牌名称。
* **禁止填充词：** 避免 AI 文案陈词滥调，如“Elevate”、“Seamless”、“Unleash”或“Next-Gen”。使用具体动词。

### 外部资源与组件
* **禁止失效的 Unsplash 链接：** 不要使用 Unsplash。使用绝对可靠的占位符，如 `https://picsum.photos/seed/{random_string}/800/600` 或 SVG UI 头像。
* **shadcn/ui 定制：** 可以使用 `shadcn/ui`，但切勿处于通用默认状态。必须定制圆角、颜色和阴影以匹配高端项目美学。
* **生产级整洁性：** 代码必须极其整洁、视觉效果惊艳、令人印象深刻，并在每个细节上严谨精修。

## 8. 创意工具库（高端灵感）
不要默认使用通用 UI。从以下高级概念库中提取，确保输出视觉惊艳且令人印象深刻。必要时，运用 **GSAP（ScrollTrigger/视差）** 处理复杂滚动叙事或 **ThreeJS/WebGL** 处理 3D/画布动画，而非基础 CSS 动效。**关键：** 绝不能在同一个组件树中混用 GSAP/ThreeJS 与 Framer Motion。默认使用 Framer Motion 处理 UI/Bento 交互。仅将 GSAP/ThreeJS 用于隔离的整页滚动叙事或画布背景，并使用严格的 useEffect 清理块进行包裹。

### 标准 Hero 范式
* 停止使用深色图片上的居中文本。尝试非对称 Hero 区块：文本清晰对齐到左侧或右侧。背景应展示高质量、相关图片，并根据 Light 或 Dark 模式，进行细微的风格化淡入淡出（渐变融入背景色）。

### 导航与菜单
* **Mac OS  dock 放大：** 位于边缘的导航栏，悬停时图标流畅放大。
* **磁性按钮：** 物理上向光标拉动的按钮。
* **果冻菜单：** 子项如粘稠液体般从主按钮分离。
* **动态岛：** 呈药丸形的 UI 组件，可变形以展示状态/警报。
* **上下文径向菜单：** 在点击坐标处精确展开的圆形菜单。
* **浮动速度拨盘：** 向外弹出为次级动作弧形线条的 FAB。
* **巨幕菜单展示：** 全屏下拉菜单，交错淡入复杂内容。

### 布局与网格
* **Bento 网格：** 非对称、基于瓷砖的分组（如 Apple 控制中心）。
* **Masonry 布局：** 无固定行高的交错网格（如 Pinterest）。
* **Chroma 网格：** 网格边框或瓷砖展示微妙、持续动画的色彩渐变。
* **分屏滚动：** 滚动时，两个屏幕半区向相反方向滑动。
* **幕布揭示：** Hero 区块在滚动时如幕布般从中部展开。

### 卡片与容器
* **视差倾斜卡片：** 3D 倾斜的卡片，追踪鼠标坐标。
* **聚光灯边框卡片：** 卡片边框在光标下动态照亮。
* **玻璃拟态面板：** 真正磨砂玻璃，搭配内折射边框。
* **全息箔卡片：** 虹彩、彩虹光反射，悬停时流转。
* **Tinder 滑动堆叠：** 用户可滑动移除的物理卡片堆叠。
* **变形模态框：** 按钮无缝扩展为其独立的全屏对话框容器。

### 滚动动画
* **固定滚动堆叠：** 卡片固定在顶部，并物理上堆叠重叠。
* **水平滚动劫持：** 垂直滚动转化为平滑的水平画廊平移。
* **机车滚动序列：** 视频/3D 序列，帧率与滚动条直接绑定。
* **缩放视差：** 中央背景图片随滚动无缝缩放/缩小。
* **滚动进度路径：** SVG 矢量线条或路线，随用户滚动自行绘制。
* **液态滑动过渡：** 如粘稠液体般擦拭屏幕的页面过渡。

### 画廊与媒体
* **穹顶画廊：** 3D 画廊，呈现全景穹顶感。
* **Coverflow 轮播：** 中心聚焦、边缘回旋的 3D 轮播。
* **拖拽平移网格：** 可自由在任意方向拖拽的无限网格。
* **手风琴图片滑块：** 窄的垂直/水平图片条，悬停时完全展开。
* **悬停图片轨迹：** 鼠标在后方留下弹出/淡出的图片轨迹。
* **故障效果图片：** 悬停时 RGB 通道短暂偏移的数字失真效果。

### 排版与文本
* **动态跑马灯：** 无限文本带，滚动时反转方向或加速。
* **文本遮罩揭示：** 巨大排版作为透明窗口，展现背景视频。
* **文本乱码效果：** 加载或悬停时 matrix 风格的字符解码。
* **圆形文本路径：** 文本沿旋转的圆形路径弯曲。
* **渐变描边动画：** 带渐变持续沿描边流动的轮廓文本。
* **动态排版网格：** 字母网格，从光标处躲避或旋转。

### 微交互与特效
* **粒子爆炸按钮：** 成功时炸裂为粒子的 CTA。
* **液态下拉刷新：** 移动端刷新指示器如分离的水滴。
* **骨架闪烁：** 光线反射在占位框上移动。
* **方向悬停感知按钮：** 悬停填充从鼠标进入的同侧进入。
* **涟漪点击效果：** 点击坐标处产生精确的视觉波纹。
* **动画 SVG 线条绘制：** 实时绘制自身轮廓的矢量。
* **网格渐变背景：** 有机、灯芯绒般的动态色彩团块。
* **镜头模糊深度：** 动态聚焦模糊背景 UI 层级，突出前景动作。

## 9. “运动引擎” Bento 范式
在生成现代 SaaS 仪表盘或功能区块时，必须使用以下“Bento 2.0”架构和动效哲学。这超越了静态卡片， enforce 一种“Vercel 核心搭配 Dribbble 简洁”的美学，高度依赖持久物理效果。

### A. 核心设计理念
* **美学：** 高端、极简、实用。
* **色板：** 背景为 `#f9fafb`。卡片为纯白（`#ffffff`），配 1px 的 `border-slate-200/50` 边框。
* **表面：** 所有主要容器使用 `rounded-[2.5rem]`。应用“扩散阴影”（极浅、宽散的阴影，如 `shadow-[0_20px_40px_-15px_rgba(0,0,0,0.05)]`）以营造深度且不杂乱。
* **排版：** 严格使用 `Geist`、`Satoshi` 或 `Cabinet Grotesk` 字体栈。标题使用微妙的字距（`tracking-tight`）。
* **标签：** 标题和描述必须放置**卡片之外、下方**，以呈现干净、画廊式展示效果。
* **像素完美：** 卡片内部使用充裕的 `p-8` 或 `p-10` 内边距。

### B. 动画引擎规格（持久运动）
所有卡片必须包含 **“持久微交互”**。使用以下 Framer Motion 原则：
* **弹簧物理：** 不使用线性缓动。使用 `type: "spring", stiffness: 100, damping: 20` 实现高级、有重量的质感。
* **布局过渡：** 大量使用 `layout` 和 `layoutId` 属性，确保状态变化时的平滑重排序、调整大小和共享元素状态过渡。
* **无限循环：** 每个卡片必须有“激活状态”实现无限循环（脉冲、打字机、浮动或轮播），确保仪表盘“鲜活”。
* **性能：** 将动态列表包裹在 `<AnimatePresence>` 中，优化至 60fps。**性能关键：** 任何持久动效或无限循环必须经过 memo 化（React.memo）并完全隔离在自己的微小程序组件中。切勿在父级布局中触发重渲染。

### C. 5 卡片原型（微动画规格）
构建 Bento 网格（如第 1 行：3 列 | 第 2 行：2 列 70/30 分割）时，实现以下特定微动画：
1. **智能列表：** 垂直堆叠的项目，具有无限自动排序循环。项目通过 `layoutId` 交换位置，模拟 AI 实时优化任务优先级。
2. **命令输入：** 带多步打字机效果的搜索/AI 栏。循环展示复杂提示词，包含闪烁光标和带闪烁加载渐变的“处理中”状态。
3. **实时状态：** 带“呼吸”状态指示的调度界面。包含弹出通知徽章，以“过冲”弹簧效果出现，持续 3 秒后消失。
4. **宽数据流：** 水平“无限轮播”的数据卡片或指标。确保循环无缝（使用 `x: ["0%", "-100%"]`），且速度感觉自然流畅。
5. **上下文 UI（专注模式）：** 文档视图，动画展示文本块的交错高亮，随后以微图标呈现“浮入”的浮动操作工具栏。
