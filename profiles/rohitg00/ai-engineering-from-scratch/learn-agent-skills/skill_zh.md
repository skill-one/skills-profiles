# 学习代理技能

教授专注的代理技能路线。一次调用涵盖一个课程。学习者应创建文件、运行实验室、解释边界，并在课程标记为完成前留下一个可观察的检查点。

## 调用属于主机

便携式技能名称为 `learn-agent-skills`。不要将一个命令语法作为通用语法来教授。

| 主机 | 开始或继续 |
|---|---|
| Codex | `learn-agent-skills`，或从 `/skills` 选择 |
| Claude 代码 | `/learn-agent-skills` |
| 其他兼容主机 | `使用 learn-agent-skills 开始或继续代理技能工程路线。` |

## 源

路线的真相来源是 `learning-paths/agent-skills.json`。当这个存储库被克隆时，优先使用本地文件。否则从以下地址获取每个文件：

```text
https://raw.githubusercontent.com/rohitg00/ai-engineering-from-scratch/main/<path>
```

在选择课程前阅读清单。按照 `lessons` 的顺序；不要使用数字 Phase 13 序列。所需路径是 22、24、25、26、27。课程 23 是可选的，并遵循清单的条目规则。

对于每个选定的课程，阅读其 `docs/en.md` 和 `quiz.json`。仅在当前实验室需要时才阅读或运行 `code/` 和 `outputs/` 下的文件。克隆是可选的。如果一个可运行的实验室需要存储库文件并且它们不可用，解释这一事实，并提供到学习者选择的目录的克隆。不要在克隆上阻塞概念课程，但在没有所需文件和运行时的情况下，不要将存储库命令或真实主机检查点记录为完成。

## 真实实验室预检

在课程 22 的主机检查点之前，建立所有这些事实：

1. `node --version`、`npx --version` 和 `python3 --version` 成功。
2. 学习者选择了一个具有技能能力的主机。
3. 学习者选择了一个可写入的项目或用户安装范围。
4. 学习者理解哪个工作目录将成为 `TARGET_ROOT`。

如果任何项目不可用，提供网站或手册 `docs/en.md` 路径，并继续概念性学习。将发现、调用、捆绑脚本、更新和卸载观察标记为 `Pending`。永远不要描述回退为真实主机通过。

## 教授一个课程

1. 将选定的行设置为 `In progress`。
2. 说明确切的课程路径以及每个命令运行的自定义目录。对于安装的捆绑包，将 `SKILL_ROOT` 定义为包含安装的 `SKILL.md` 的绝对目录。从学习者的原始工作空间工作目录定义 `TARGET_ROOT`。永远不要假设进程 cwd 是安装的捆绑包。
3. 用两到三句话描述问题，然后问一个预测或理解问题。
4. 以小块的形式逐步完成课程中的构建和使用材料。如果有，优先使用课程的早期快速启动。
5. 当文件和运行时可用时运行真实本地实验室。如果没有，跟踪一个小示例，并将实验室记录为待定而不是声称它运行了。
6. 要求清单的检查点证据。流利的解释不能替代检查点要求时安装路径、路由、脚本、权限或报告观察。对于每个捆绑脚本，记录解析的脚本路径、解析的目标路径、cwd、确切的 argv 和退出代码。
7. 逐个问课后测验问题。在学习者回答前永远不要暴露 `correct`、答案索引或答案键。永远不要在回复提示中放入真实答案字母或答案分布；使用 `回复一个字母：<A|B|C|D>.`
8. 只有在检查点和测验完成后，才将行标记为 `Done`。记录一个紧凑的证据笔记、日期，并解锁下一行。

未经学习者确认，不要安装、更新、删除、克隆、发布或修改外部系统。技能指令永远不会绕过主机权限或沙盒边界。当主机行为无法观察时，将其记录为未验证而不是推断支持。

## 课程检查点

- **13/22**：创建一个最小的技能，将完整的审查者捆绑包安装到真实主机，显式调用它，验证报告，并干净地删除它。
- **13/24**：在一个跟踪中区分发现、目录元数据、主体激活和引用或脚本加载。
- **13/25**：记录显式、隐式、负面和近失路由结果。
- **13/26**：将每个控制标记为指令、权限、沙盒或验证，并用观察证明声明的边界。
- **13/27**：在一个主机上练习发现、引用、脚本、批准、升级和卸载，然后在第二个主机上重复，或诚实地声明缺失的能力和回退。

## 结束

以记录检查点证据、测验分数和确切的下一课程结束。除非学习者要求离开，否则保持学习者在此路线。
