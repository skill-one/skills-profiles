## 在选择课程前阅读路径

真相来源是 `learning-paths/model-context-protocol.json`。当此存储库可用时，优先使用本地文件。否则从以下地址获取所需的文件：

```text
https://raw.githubusercontent.com/rohitg00/ai-engineering-from-scratch/main/<path>
```

按照清单的 `lessons` 数组的顺序。所需序列是 06、07、08、09、10、11、12、13、14、15、16、18、17、28、29、30、31。数字下一个导航不是 16 个课程之后的路径。

对于选定的课程，完整阅读 `docs/en.md` 和 `quiz.json`。仅在当前教学步骤需要时才阅读或运行 `code/` 和 `outputs/`。使用课程中声明的协议时代。永远不要将遗留握手规则合并到现代的无状态跟踪中。

课程 23 是唯一可选的顶点。只有在所有必需行都完成并且清单 `prerequisitePaths`、课程 19 和 20 都完成后才提供它。不要在沉默中向此路径添加另一个课程。

## 建立证据模式

在第一个可执行检查点之前，确定以下内容：

1. 课程文件是否本地可用。
2. `python3 --version` 是否成功。
3. 学习者是否可以在当前工作目录中写入 `MCP-LEARNING.md`。
4. 如果学习者选择课程 07 中的可选第二个实现，则 TypeScript 运行器是否可用。

当本地文件和 Python 3 可用时，使用可执行模式。记录绝对工作目录、确切命令、退出代码、请求 ID 和方法、选定的协议时代以及观察到的结果或错误。编辑令牌、秘密、cookies、授权标头和敏感参数值。

当存储库或运行时不可用时，继续在概念模式下进行。阅读课程，手动跟踪一个小请求和响应，并将证据标记为 `Conceptual`。将运行时、传输、授权和部署检查标记为 `Pending`。不要将手动跟踪描述为执行通过。

如果需要可执行文件但缺失，则提供将存储库克隆到学习者选择的目录的选项。在克隆之前等待确认。概念课程必须在没有克隆的情况下保持可用。

## 定位或创建进度

使用当前工作目录中的 `MCP-LEARNING.md`。不要将此路径放入 `LEARNING.md` 并不要修改 Agent Skills 进度。

在确定不存在状态之前，安全地处理以前的文件名：

1. 如果 `MCP-LEARNING.md` 存在，则使用它。如果
   `MCP-ENGINEERING-LEARNING.md` 也存在，则不要覆盖任何文件；
   报告冲突并询问哪个文件应拥有下一个更新。
2. 如果 `MCP-LEARNING.md` 缺失且 `MCP-ENGINEERING-LEARNING.md` 存在，
   在教学前将旧文件重命名为同一目录中的 `MCP-LEARNING.md`。保留每个学习者笔记和证据行字节对字节的完整性。如果原子重命名不可用，则复制文件，验证新文件匹配，然后才删除旧文件。
3. 只有当两个文件名都不存在时才创建新状态文件。永远不要用以下空白模板替换旧进度。

如果文件存在，保留所有学习者笔记和证据。继续标记为 `In progress` 或 `Next` 的第一行。如果所有必需行都是 `Done`，则检查可选顶点的先决条件并报告确切的缺失路径，而不是重新启动路径。

## 执行公共部署门

在任何非回环绑定、共享入口、托管端点、注册表发布或其他公共部署之前，从清单中读取 `publicDeploymentGate`。要求可执行课程 15 检查点，审查目标和请求的授权，并获得学习者对外部操作的明确确认。

如果任何所需证据缺失，则教学或重新运行课程 15 并保持部署操作为 Pending。技能调用不会授予网络、凭证、发布或部署授权。

## 教授一个课程

1. 将选定行标记为 `In progress`。声明其清单路径、持续时间、组、协议时代和证据模式。
2. 构建一个生产故障，该课程可防止。要求学习者预测状态、JSON-RPC 结果或状态转换，然后再解释它。
3. 绘制一个请求边界：生产者、传输、消费者以及每侧验证的确切字段。保持协议状态、持久应用程序状态、传输状态、授权状态和 UI 状态区分。
4. 分小部分逐步通过构建和使用。对于代码，解释一个不变量，要求预测，然后运行或跟踪可以证伪它的最小案例。
5. 练习一个成功和至少一个相关失败。优先使用确切的线证据：请求 ID、方法、协议时代、适用时的标头、正文、状态或错误代码、结果类型和终端状态。保留秘密值编辑。
6. 要求课程清单 `checkpointEvidence` 中的每一项。运行时证据必须来自观察到的输出。概念证据必须命名未执行的命令和剩余的不确定性。
7. 逐个提问每个 `post` 测验项。如果测验没有分阶段项，则提问所有项。在学习者响应之前不要透露 `correct`、答案索引或解释。永远不要在回复提示中放入真实的答案字母或答案分布；使用 `回复用一个字母：<A|B|C|D>。`
8. 只有在课程检查点和测验完成后，才将行标记为 `Done`。附加一行紧凑的 Wire 证据，将分数添加到笔记中，将下一行设置为 `Next`，并更新 `Current`。

不要使用通过单元测试作为命名协议证据的替代品。不要从进程内函数推断 HTTP 行为，从身份验证推断授权，从超时推断取消，或从一个 SDK 推断合规性。
