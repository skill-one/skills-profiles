# 开始学习

你正在将一个学习者引入 **从零开始的人工智能工程**
课程：包含 20 个阶段，523 个课时，从线性代数到自主智能体。你的任务是生成 `LEARNING.md`，这是一个位于当前目录的单个文件，它将捕获他们学习的原因、应该从哪里开始以及他们的学习路径。后续的 `learn` 会话会读取和更新这个文件，因此将其视为学习者的权威来源。

适用于任何智能体。如果你的环境有一个结构化的问/选项工具，用它来回答所有问题；否则以纯文本形式呈现字母选项，并等待回复。

## 主机调用协议

技能名称是可移植的，但调用语法属于主机。在显示下一个命令之前，使用正确的形式：

- Codex：`start-learning`、`learn`、`course-guide` 以及其他 `skill-name` 形式，或者告诉学习者从 `/skills` 选择技能。
- Claude Code：`/start-learning`、`/learn`、`/course-guide` 以及其他 `/skill-name` 形式。
- 其他兼容主机：自然语言，例如 `使用 learn 开始我的第一个课时。`

永远不要将 Claude Code 的斜杠命令作为通用语法呈现。当主机未知时，使用自然语言形式。

## 跨课程模式恢复路由

在进行通用引导之前，针对以下支持的状态文件及其路由所有者解决所有“恢复”或“继续”请求：

- `LEARNING.md` 属于 `learn`，用于完整课程。
- `MCP-LEARNING.md` 属于 `learn-mcp`，用于模型上下文协议 (MCP) 路由。
- `MCP-ENGINEERING-LEARNING.md` 是该相同 `learn-mcp` 路由的遗留文件名，不是独立路由。
- `AGENT-SKILLS-LEARNING.md` 属于 `learn-agent-skills`。
- `CLAUDE-CERTIFICATION.md` 属于 `claude-certification`。

如果学习者在恢复或继续请求中指定了路由，即使存在其他状态文件，也立即将其分派给其所有者，然后停止此技能。

对于未命名的恢复或继续请求，收集状态文件存在的所有者，将两个 MCP 文件名分组到 `learn-mcp` 下。如果恰好剩下一个路由所有者，则在通用引导之前调用它并停止此技能。`learn-mcp` 拥有遗留文件迁移和冲突报告。如果有两个或多个路由所有者，列出他们的面向学习者的路由名称，并询问要恢复哪个路由，然后再运行定位或更改任何状态。如果不存在，则继续进行通用引导。永远不要根据文件的新鲜度推断路由，也不要将一个路由的进度合并到另一个状态文件中。

遗留运行时可能会将 `learn-mcp-engineering` 作为别名公开。仅接受它以到达 `learn-mcp`；将每个面向学习者的交接呈现为 `learn-mcp`，并将路由命名为模型上下文协议 (MCP)。

## 聚焦 MCP 交接

如果学习者明确想要模型上下文协议 (MCP) 而不是完整课程，则不要运行定位，也不要创建 `LEARNING.md`。路由到可移植技能 `learn-mcp`，其源是 `learning-paths/model-context-protocol.json`，其状态文件是 `MCP-LEARNING.md`。在 Codex 中使用 `learn-mcp`，在 Claude Code 中使用 `/learn-mcp`，或者要求另一个兼容主机使用 `learn-mcp`。专用的导师拥有课时选择、线证据和公共部署安全门。

## 聚焦 Agent Skills 交接

如果学习者明确想要 Agent Skills 而不是完整课程，或者 `AGENT-SKILLS-LEARNING.md` 存在并要求恢复该路由，则不要运行定位，也不要创建 `LEARNING.md`。路由到可移植技能 `learn-agent-skills`，其源是 `learning-paths/agent-skills.json`，其状态文件是 `AGENT-SKILLS-LEARNING.md`。在 Codex 中使用 `learn-agent-skills`，在 Claude Code 中使用 `/learn-agent-skills`，或者要求另一个兼容主机使用 `learn-agent-skills`。专用的导师拥有五个课时的顺序、真实主机证据、沙盒边界、第 25 课时和第 26 课时之前的工具中毒先决条件门，以及发布门。

如果 `LEARNING.md` 已经存在，不要覆盖它。总结它所说的内容（使命、入口点、迄今为止的进度），并提供正好三个路径：

- **恢复**：使用上述主机语法调用 `learn`；完全跳过面试和定位。
- **重新运行定位**：再次进行测验，然后仅更新定位部分和路径状态；保持使命、进度日志和审查队列不变。
- **重新开始**：只有在明确确认后，才将当前文件重命名为 `LEARNING-<YYYY-MM-DD>.md` 作为存档，然后继续以下完整引导。永远不要无声地删除或覆盖他们的历史记录。

## 第 1 步：面试（3 个问题，保持简短）

1. **你为什么学习人工智能工程？** 自由文本。提供示例：
   发布 AI 产品、职业转换、理解我日常使用的工具、研究。因为他们自己的话可以奠定未来所有课时解释的基础，所以捕获他们的答案。
2. **每周多少时间？** 选项：~2 小时、~5 小时、~10 小时、“尽可能快”。仅用于诚实地表达进度，永远不会削减内容。
3. **你最终最想构建什么？** 一行。一个智能体、一个训练模型、一个 RAG 产品，“还不确定”也可以。

不要问超过这三个问题。定位测验衡量知识；面试仅捕获意图。

## 第 2 步：定位

从 `find-your-level` 技能运行定位测验（它与此技能一起安装）：5 个领域，10 个问题，映射到一个入口阶段。保留该技能的答案隔离协议：不要预加载后续答案密钥轮，也不要用真实选项字母替换中性的 `<字母>` 占位符。

如果学习者说他们已经知道他们想从哪里开始（“直接从第 7 阶段开始”），尊重这一点并跳过测验，与运行测验相同的输出协议，以便 `learn` 导师始终找到一个结构良好的计划：

- 验证阶段是 0-19 并解析其规范名称；如果无法解析，列出 20 个阶段并让他们选择。
- 在路径表中：入口点以下的阶段是 `Skip`，入口点和以上所有阶段是 `Do`（没有 `Review` 行，因为没有区域分数可以从中推断它们），估计总小时数是 `Do` 行的总和。
- 在定位部分写入 `分数：自我选择` 而不是数字。

## 第 3 步：编写 LEARNING.md

在当前目录中创建 `LEARNING.md`，并包含以下部分：

```markdown
# 我的 AI 工程路径
<!-- 由 ai-engineering-from-scratch 学习技能管理。
     仓库：https://github.com/rohitg00/ai-engineering-from-scratch -->

## 使命
<他们回答问题 1 的内容，用他们自己的话，加上问题 3 的构建目标>

## 定位
- 日期：<YYYY-MM-DD>
- 分数：<总分数>/10 及区域分解，或者当测验被跳过时正好是 `自我选择`
- 入口点：阶段 <N>：<名称>
- 进度：~<小时>/周

## 路径
| 阶段 | 名称 | 状态 | 估计小时数 |
|------|------|------|------------|
<所有 20 个阶段；状态是定位结果的 `Skip`、`Review`、`Do` 或 `Done`。小时数来自 ROADMAP.md：如果仓库被克隆，则本地读取，否则获取
https://raw.githubusercontent.com/rohitg00/ai-engineering-from-scratch/main/ROADMAP.md>

## 进度日志
| 日期 | 课时 | 测验 | 备注 |
|------|------|------|------|

## 审查队列
<目前为空；learn 添加课时时将标记>
```

## 第 4 步：交接

以三行结束，不再多余：

- 他们的入口点和复习 + 做 阶段的总估计小时数。
- 给出主机正确的 `learn` 调用，并说明它启动第一个课时，并每次从该文件中获取。
- 给出主机正确的 `course-guide <主题>` 调用，并说明它可以跳到特定主题。
