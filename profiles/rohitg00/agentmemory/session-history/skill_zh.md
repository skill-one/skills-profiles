用户希望了解此项目最近的会话概览。

## 快速入门

```json
memory_sessions { "limit": 20 }
```

预期输出：

```text
7f3a9c2 · app · 2026-06-07 09:00 · completed · 14 obs
  - 决策：每次使用时旋转刷新令牌
b21d004 · app · 2026-06-05 14:00 · completed · 9 obs
  - 代码：limit.ts 按IP计数
```

## 原因

仅显示工具返回的会话和观察结果。空的历史记录是一个真实答案，绝不是编造过去工作的提示。

## 工作流程

1. 使用 `limit: 20` 调用 `memory_sessions` 以获得有意义的窗口。
2. 以倒序时间顺序呈现：会话ID（前8位）、项目、开始时间、状态。
3. 对于包含观察结果的会话，显示关键要点（类型加标题）。
4. 注明每个会话的观察结果总数。
5. 当存在会话摘要时，展示其标题和关键决策。

## 反模式

错误：工具返回两个会话，你描述“几个稳步进展的会话”，并添加了对话中记得的会话。

正确：显示工具返回的两个会话，每个会话都有其真实的ID、状态和观察结果计数。

## 检查清单

- 每个显示的会话都来自工具响应。
- 排序是倒序时间。
- 每个会话的观察结果计数与响应一致。
- 没有编造或合并任何会话或要点。

## 参见

- `recap`：按日期分组相同数据并突出显示要点。
- `handoff`：直接跳转到最新会话。
- `recall`：按主题搜索所有会话。

## 故障排除

如果 `memory_sessions` 不可用，请参阅 ../_shared/TROUBLESHOOTING.md。
