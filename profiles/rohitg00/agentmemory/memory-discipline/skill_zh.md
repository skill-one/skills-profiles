只有在读取发生在工作之前且写入发生在决策点时，内存才能发挥作用。这个循环就是技巧；其中的每次工具调用都是机械的。

## 快速入门

```json
memory_smart_search { "query": "auth refresh flow", "project": "myrepo", "limit": 5 }
```

任务开始时，然后在每个已确定的决策点：

```json
memory_save { "content": "选择了游标分页而不是偏移量；偏移量扫描在db/list.ts中超过10万行时崩溃了。", "concepts": "游标分页, 偏移量扫描限制", "files": "src/db/list.ts" }
```

## 原因

钩子自动捕获发生的事情。它们无法捕获的是判断：哪个事实重要，哪个决策已确定，哪个修正应该改变未来的行为。在正确的时间应用这种判断是这个纪律的核心。

## 工作流程

1. 任务开始，在非平凡任务之前读取代码时：使用`memory_smart_search`并输入任务主题和项目名称。在这里花费第一个工具调用；命中可以节省重新发现，未命中则花费一次调用。
2. 任务中，决策确定或陷阱解决的时刻：使用`memory_save`并输入决策和原因，2-5个具体概念，真实的文件路径。在解决的时刻保存；会话结束时的批量保存会丢失原因。
3. 在你修正方法时：保存一个教训而不是记忆（使用`lesson`技能）。教训带有信心，并在类似工作之前出现；记忆则带有事实。
4. 在重复你已被修正的任务类型时：使用`memory_lesson_recall`并输入任务类型作为查询。
5. 会话结束：停止。钩子会总结和整合；手动回顾保存会重复它们。

## 符合条件的内容

保存：已确定的决策及其原因，通过调试发现的非明显约束，无法从代码库推导出的环境事实。跳过：代码中可读的内容，临时状态，秘密，以及步骤式叙述（钩子已经捕获了它）。

## 反模式

错误：完成实现后，搜索内存进行双重检查，并批量保存所做的一切的摘要。

正确：首先搜索，在每次决策确定时保存，让钩子负责总结。

## 检查清单

- 非平凡任务的第一个工具调用是项目范围的搜索。
- 每次保存都包含原因，而不仅仅是结论。
- 修正变成了教训，而不是记忆。
- 没有保存的内容是代码库或钩子已经记录的。

## 参见

- `recall`, `remember`：用户触发的读和写功能。
- `lesson`：这个纪律交给的修正循环。

## 故障排除

如果`memory_smart_search`或`memory_save`不可用，请查看../_shared/TROUBLESHOOTING.md。
