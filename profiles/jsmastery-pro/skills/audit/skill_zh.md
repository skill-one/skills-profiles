## 输出风格（纯文字，无连字符，无破折号）

<!-- OUTPUT-STYLE:START -->
将此技能生成的所有内容，包括文件和消息，均使用简洁明了的语言书写。以`你`的口吻与读者交流，像同事一样温暖直接，并将每一步都呈现为读者可以选择执行或跳过的建议，而不是命令。保留具有实际意义的术语；用简洁明了的语言解释每个术语。不要使用连字符或破折号作为标点符号：不要使用英文破折号、中文破折号，也不要使用连字符复合词。写`read only`，而不是`read-only`。用简洁明了的语言表达，或者重写句子。代码、文件路径、命令标志和值等其他技能匹配的连字符保持不变。使用短句、逗号或括号。清晰比聪明更重要。
<!-- OUTPUT-STYLE:END -->

## 此技能的作用

上下文引导程序：编写`AGENTS.md`文件，后续技能和AI工具会读取这些文件。

- 绿地（还没有代码）：询问编码标准，从答案中生成根`AGENTS.md`，如果`/scope`设置了构建方法（名称和一行原则），则从范围头部获取。在项目使用其选择的堆栈搭建后运行（`/scope` → `/architect`决定堆栈 → 搭建 → `/audit`）；过早运行是不合适的。
- 老代码，未文档化（代码，没有`AGENTS.md`）：扫描整个项目，编写根`AGENTS.md`和嵌套的`<area>/AGENTS.md`文件，判断什么是全局的（根） versus 区域特定的（嵌套）。
- 老代码，部分文档化：检查现有的根和嵌套文档与整个代码库；仅添加缺失的内容（新的全局事实，未文档化区域的嵌套文档）；从不覆盖编辑过的内容。

不创建规范（`/architect`拥有这些），不维护文件更改后的文件（`/sync`拥有这些），也不编写功能范围（`/scope`拥有`docs/scope/`）。

## 上下文文件规范（`AGENTS.md`是标准的）

持久的上下文存储在工具无关的`AGENTS.md`（根和嵌套）中；每个代理（Codex、Cursor、Claude Code和其他）都会读取它。`CLAUDE.md`只是一个一行指针，其整个主体通过Claude Code的`@`导入导入兄弟`AGENTS.md`（`agent-prompt.md`中的精确指针主体）；内容永远不会在两个文件中重复。

- 将知识写入`AGENTS.md`。当缺失时创建它。不要覆盖现有的`AGENTS.md`（它可能是用户或工具编写的）；保守地填充空白，并获得许可。
- 迁移遗留内容：一个有内容但没有`AGENTS.md`的`CLAUDE.md` → 询问许可，将其内容移入新的`AGENTS.md`，用指针替换`CLAUDE.md`。从不默默丢弃编辑过的内容。
- 根保持简短和全局；嵌套的`AGENTS.md`仅用于有实际约定的有意义区域（与`CLAUDE.md`应用相同的根/嵌套规则）。

## 范围

区域路径参数（例如`auth`、`src/payments`）触发第3阶段。没有参数时，`Pre-flight`信号以下路由到第0阶段（模糊：询问新 vs 现有）、第1阶段（绿地：询问标准，生成根）、第2阶段（已建立，没有根`AGENTS.md`：整个仓库扫描）、或第4阶段（根`AGENTS.md`存在：填充空白）。一个有内容但没有`AGENTS.md`的遗留`CLAUDE.md`会被迁移，然后按第4阶段处理。

## 行动 vs 询问

第1阶段通过多项选择题（MCQ）询问编码标准问题，然后创建根`AGENTS.md`。第2阶段立即行动，不提问；它编写根和它认为值得的嵌套文档。第3阶段和第4阶段行动以探索，但在修改现有根`AGENTS.md`或迁移遗留`CLAUDE.md`之前请求许可；第4阶段首先报告未文档化区域的嵌套文档创建，然后确认后应用。

## 产物所有权

`AGENTS.md`文件包含内容：如果缺失则创建根（第1阶段、第2阶段）和`<area>/AGENTS.md`（如果缺失且值得，根据判断创建，第2阶段、第3阶段、第4阶段）；当存在时，填充空白或提出添加请求并获得许可；从不覆盖。`CLAUDE.md`文件仅是指针（根和区域），如果缺失则创建；一个有内容的遗留文件会根据许可迁移到`AGENTS.md`。创建嵌套的`AGENTS.md`时，在根`AGENTS.md`的`## 上下文文件`下添加精确的一行指针（`- [<area>/AGENTS.md](<area>/AGENTS.md) (<一行描述>)`）。每个子文件夹一个，只有在存在不同约定时才这样做。

## 可移植性（任何操作系统，任何代理）

- 命令：`git`是唯一需要的CLI，在所有操作系统上都是相同的。其他shell片段（文件计数、`find`、`[ -f ]`）是POSIX参考，不是字面脚本；使用你代理的跨平台文件工具（搜索/glob、读取、写入）来列出、计数和检查存在性。
- 嵌套文件位于此技能的文件夹中：`agent-prompt.md`、阶段模式文件（`modes/*.md`）和模式预设（`patterns/*.md`）。解析文件夹为绝对路径。路由时读取匹配的阶段模式文件，然后`agent-prompt.md`加上在写入时选择的模式预设。它的ALL_CAPS占位符（PHASE、AREA、ADDITIONAL_STANDARDS、MONOREPO_OR_NO、INSTALLED_SKILLS、DECLINED_TOOLS等）是你收集的预飞行和问题轮次中的输入；按顺序读取并应用。
- 没有交互式问题支持？将任何多项选择题作为纯文本提出，选项相同。

## 执行

主线程在每个阶段执行写入；它从不将`AGENTS.md`写入交给子代理。唯一的子代理是一个只读的`scout`（最便宜模型，Claude Code：`haiku`，永远不是会话模型），仅在大型扫描时生成；它返回一个紧凑的映射，主线程从它写入。小型搭建或单个区域不需要scout；直接读取它。在写入之前，读取`agent-prompt.md`（角色、每个阶段的说明、模板），在第1阶段，读取选择的模式预设；然后按照它写入。仅在写入时读取`agent-prompt.md`，在预飞行期间不读取。

### `预飞行`（主线程在所有其他操作之前执行）

收集几个信号（仅文件计数会误导：搭建会膨胀它，不熟悉的语言会归零它）：

1. 上下文文件：根`AGENTS.md`存在 → `ROOT_EXISTS`；一个只有内容的`CLAUDE.md` → `ROOT_LEGACY`；两者都没有 → `ROOT_MISSING`。
2. 跨常见生态系统（扩展名如`.ts/.tsx/.js/.jsx/.py/.go/.rs/.java/.rb/.swift/.kt/.php/.cs/.dart/.ex/.exs/.scala/.c/.cpp/.h/.lua/.clj`），排除vendored/generated目录（`node_modules`、`.git`、`dist`、`build`）和配置文件（`*.config.*`）。
3. 已建立信号：`git log --oneline`提交历史深度；一个真实的清单（`package.json`、`pyproject.toml`、`go.mod`、`Cargo.toml`、`composer.json`、`*.csproj`、`pubspec.yaml`、`mix.exs`、`Gemfile`）。
4. 单一仓库信号：工作区标记（`pnpm-workspace.yaml`、`turbo.json`、`package.json`中的`"workspaces"`字段）或任何`apps/*/package.json` / `packages/*/package.json`靠近根。
5. **工作流设置信号（`WORKFLOW_SETUP`）**：根`AGENTS.md`缺失，而工作流已经决定了堆栈，即`docs/specs/`架构规范存在（`## 提议的堆栈`部分），和/或`docs/scope/`有“堆栈和架构”（或类似基础搭建）功能。这是预期的绿地顺序（`/scope` → `/architect`决定堆栈 → `/develop`搭建它 → `/audit`）：新鲜搭建的，仍然需要捕获编码标准。当它触发时，现在存在的清单和搭建源是搭建，而不是现有代码库。

选择阶段。检查的顺序很重要：工作流设置信号优先于原始代码计数，因为新鲜搭建的清单有清单和源文件，但仍然是绿地。

| 条件 | 阶段 |
|---|---|
| 作为参数给出区域路径 | 第3阶段 |
| `ROOT_EXISTS`（或迁移后的`ROOT_LEGACY`） | 第4阶段 |
| `ROOT_MISSING`和`WORKFLOW_SETUP`（堆栈规范和/或范围堆栈功能） | **第1阶段**，即使现在存在清单和搭建源。询问编码标准；从规范的堆栈中生成根。从不将刚刚搭建的工作流项目视为老代码。 |
| `ROOT_MISSING`，没有`WORKFLOW_SETUP`，没有源文件 AND 没有清单 | 第1阶段 |
| `ROOT_MISSING`，没有`WORKFLOW_SETUP`，有代码（源 ≥ 10 或一个清单），≥ 2个提交且显然是真实的功能代码（不仅仅是搭建） | 第2阶段，任何语言 |
| `ROOT_MISSING`，没有`WORKFLOW_SETUP`，代码看起来像未触碰的搭建，或 ≤ 1个提交，或者你无法区分绿地和老代码 | 第0阶段，询问 |

为什么这个顺序：新鲜搭建的清单有清单和启动文件，但仍然是绿地，所以仅凭原始代码计数会将其误读为老代码并跳过标准问题；工作流设置信号捕获这一点，并路由到绿地。真正老代码（第2阶段）意味着真实的功能代码、真实的历史，并且没有正在进行的工作流设置。任何模糊的情况都路由到第0阶段；永远不要将可能绿地的项目默认为老代码。

单一仓库（`MONOREPO=yes`）：根加上每个工作区一个轻量级桩，按需加深。每个工作区（`apps/*`、`packages/*`）是一个一级区域；它的主要文档位于工作区根（`packages/api/AGENTS.md`），永远不会埋得更深。整个仓库运行不会深度扫描每个工作区；写入仓库根`AGENTS.md`（单一仓库工具，共享约定）加上每个工作区的轻量级桩，从其清单，不扫描代码，带根指针。完整的约定/陷阱/关键文件扫描发生在工程师运行`/audit packages/api`（第3阶段）或第一次在那里构建时。工作区内一个值得自己文档的位置（`packages/ui/src/mdx/`）会得到一个，除了工作区根文档外，从它链接。一个文档已经埋在工作区中，但没有工作区根文档：询问："`packages/ui`在`src/mdx/`有一个上下文文件，但在其根没有。将它移到`packages/ui/AGENTS.md`，还是保持它作为新`packages/ui/AGENTS.md`下的嵌套文档？" 移动：将其移到工作区根。保持嵌套：创建工作区根`AGENTS.md`，并保持深层的，从根链接。按照上述约定迁移遗留`CLAUDE.md`内容。应用`MONOREPO=yes`加上工作区列表作为写入的一部分。

遗留迁移（任何阶段）：在`ROOT_LEGACY`，在继续之前询问许可："我发现一个有项目上下文但没有`AGENTS.md`的`CLAUDE.md`。我将将其内容移入新的`AGENTS.md`（以便所有工具读取），并用指针替换`CLAUDE.md`。继续？" 许可：将内容逐字复制到`AGENTS.md`，然后用指针替换`CLAUDE.md`；`AGENTS.md`现在存在，所以继续按第4阶段（填充空白）。不：保持两者不变，继续不迁移。任何嵌套的`<area>/CLAUDE.md`也是如此。

### 路由到选定的阶段

第0阶段（模糊）在下方直接处理。对于第1到第4阶段，只读取匹配的模式文件，然后遵循它：

- 第1阶段（绿地设置）→ `modes/greenfield.md`
- 第2阶段（整个仓库扫描）→ `modes/whole-repo.md`
- 第3阶段（区域扫描）→ `modes/area.md`
- 第4阶段（填充空白）→ `modes/gapfill.md`

不要读取其他模式文件。绿地和整个仓库模式额外读取`modes/tool-skills.md`用于代理技能/MCP扫描（区域和填充空白运行时跳过它）。

### 第0阶段：分类（仅在`pre-flight`模糊时）

不要猜测。通过代理的交互式选项选择器（`AskUserQuestion`在Claude Code上），或纯文本，使用相同的选项提问。通过哪个信号更强（一个像树一样的搭建，有清单但历史很少倾向于新；真实的功能代码和历史倾向于现有），标记一个选项（推荐），选择器在最后添加一个自由文本自定义插槽：
- 问题："我无法判断这是新项目还是现有代码库（<说明原因：例如'存在清单但我看不到我认识的任何语言中的源'，或'文件看起来像未触碰的搭建'>）。这是什么？"
- 标题："项目状态"
- 选项：1. `新项目`，"我将询问您的编码标准并生成上下文。" → 第1阶段（读取清单/搭建以获取堆栈；仍然询问标准）。2. `现有代码库`，"我将扫描这里并记录它。" → 第2阶段。

### 所有阶段之后

如果没有在应该写入时写入`AGENTS.md`（文件缺失/空），报告失败并重做；不要传递它未产生的成功报告。否则传递报告：发现了什么（2到4个要点），写了什么（文件路径），提议或跳过了什么（如果找到现有文件）。
