# 图像生成技能

为博客文章、文档和技术文章生成插图图像。工作流程是提供者感知的：

1. **Codex 内建路径优先** — 当当前代理是 Codex 且内建 `image_gen` 工具可用时，直接使用它。此路径不需要 `OPENAI_API_KEY`。
2. **OpenAI API 降级** — 在 Codex 之外，或当内建工具不可用时，如果存在，使用本地脚本和 `OPENAI_API_KEY`。
3. **Gemini 降级** — 如果 OpenAI API 生成不可用或失败，使用相同的脚本和 `GEMINI_API_KEY` 以及现有的 Gemini 图像模型。

仅在需要时加载特定提供者的参考：

- Codex 内建路径：`references/codex-built-in.md`
- OpenAI API 降级：`references/openai-api.md`
- Gemini 降级：`references/gemini-api.md`

## 何时使用

- 用户要求生成插图、图表、概念图像、文章视觉效果或文档视觉效果
- 用户正在撰写文章并需要用于概念或工作流的视觉解释
- 用户明确要求生成光栅图像

## 第 1 步：确定图像需求

生成前，仅澄清必要信息：

1. **要插图的内容** — 概念、架构、流程或场景
2. **语言** — 默认为英语，用于提示和图像中的文本。仅当用户明确要求时才使用其他语言
3. **保存位置** — 见下文“输出路径”
4. **风格/颜色偏好** — 如果用户有特定需求，使用它们；否则使用默认风格

## 第 2 步：选择提供者路径

### 路径 A：Codex 内建

当满足以下条件时使用此路径：

- 当前代理是 Codex
- 内建 `image_gen` 工具可用
- 用户未明确要求 API/CLI 执行

读取 `references/codex-built-in.md`，使用内建工具生成，如果它是项目绑定的，则将最终图像移动/复制到工作区。

### 路径 B：脚本自动降级

当满足以下条件时使用此路径：

- 当前代理不是 Codex
- 内建工具不可用
- 用户明确要求 API/CLI 执行

运行：

```bash
python <skill-root>/scripts/generate_image.py \
  --prompt "your prompt here" \
  --output "/path/to/save/image.png"
```

脚本默认使用 `--provider auto`：

1. 当 `OPENAI_API_KEY` 设置时尝试 OpenAI API
2. 如果 OpenAI API 失败或未配置，当 `GEMINI_API_KEY` 设置时尝试 Gemini
3. 如果两者凭证都不可用，则报告缺失的环境变量

## 第 3 步：编写提示

### 默认风格前缀

除非使用 `--style-prefix` 或 `--no-style`，否则脚本会自动添加此风格前缀：

> 使用干净、现代的浅色调色彩。极简平面插图风格，具有清晰的视觉层次结构。专业且精致的外观，适合技术博客文章。不使用照片级真实渲染。不使用过多的渐变或阴影。

对于 Codex 内建路径，除非用户要求不同风格，否则直接在提示中包含相同的风格指导。

### 提示编写指南

- 具体说明视觉元素、关系和布局
- 对于技术概念：描述组件及其连接方式
- 对于架构图表：列出层/组件和数据流方向
- 对于流程图表：描述步骤和流程方向
- 如果图像中需要文本标签，请明确拼写并保持文本简短
- 默认语言为英语；仅当请求时使用其他语言

### 示例提示

**架构图表：**

```text
一个系统架构图表，显示：用户将查询发送到 API 网关，该网关路由到标记为 "Milvus" 的向量数据库和生成服务。向量数据库返回相关文档，这些文档与原始查询结合后发送到生成服务以生成最终响应。箭头显示数据流方向。每个组件都是带有图标和标签的圆角矩形。
```

**概念插图：**

```text
关键词搜索与语义搜索的视觉比较。左侧显示关键词搜索，匹配精确单词并突出显示匹配的单词。右侧显示语义搜索，带有大脑图标理解含义，并用虚线连接相关概念。一条分隔线将两种方法分开。
```

## 第 4 步：参数

### 默认参数

| 参数 | 默认 | 备注 |
|-------|------|------|
| 提供者 | 脚本中为 `auto`；Codex 内建时可用 | Codex 内建优先，然后 OpenAI API，然后 Gemini |
| OpenAI 模型 | `gpt-image-2` | 脚本降级使用 |
| Gemini 模型 | `gemini-3.1-flash-image` | 脚本降级使用 |
| 纵横比 | `16:9` | 横向，适合文章插图 |
| 图像大小 | `1K` | 质量和成本的良好平衡 |
| 风格 | 极简、干净、浅色调 | 脚本自动添加 |
| 语言 | 英语 | 提示和图像中的文本 |

### 脚本选项

```text
--provider          auto, openai, gemini
--model             选择的提供者的模型 ID
--openai-model      OpenAI 模型 ID，默认 gpt-image-2
--gemini-model      Gemini 模型 ID，默认 gemini-3.1-flash-image
--aspect-ratio      1:1, 2:3, 3:2, 3:4, 4:3, 4:5, 9:16, 16:9, 21:9, 等
--image-size        512, 1K, 2K, 4K
--openai-quality    low, medium, high, auto
--style-prefix      自定义风格前缀
--no-style          跳过默认风格前缀
```

### 何时更改默认值

| 场景 | 更改 |
|------|------|
| 更高质量的最终资产 | `--image-size 2K` 或 `--openai-quality high` |
| 竖向图像 | `--aspect-ratio 3:4` 或 `--aspect-ratio 9:16` |
| 方形图像 | `--aspect-ratio 1:1` |
| 用户有自己的风格 | `--style-prefix "your style"` 或 `--no-style` |
| 非英语内容 | 以目标语言编写提示 |

## 第 5 步：确定输出路径

按此优先级顺序：

### 优先级 1：当前对话的上下文

如果用户正在处理特定的 markdown 文件或文章：

1. 通过查找 `.md` 文件中的图像引用来确定现有图像的存储位置
2. 将新图像保存在与现有图像相同的目录中
3. 使用与现有命名约定匹配的描述性文件名

示例：如果文章有 `![](images/architecture-overview.png)`，则保存到相同的 `images/` 目录。

### 优先级 2：项目图像目录

如果没有特定文章上下文但正在项目内工作：

1. 查找现有图像目录：`images/`、`assets/`、`static/`、`img/`、`figures/`
2. 在最合适的现有目录中保存
3. 如果都不存在，在项目根目录或相关内容目录下创建 `images/` 目录

### 优先级 3：降级

如果没有明确的 项目上下文：

1. 保存到当前工作目录
2. 使用描述性文件名：`concept-name-illustration.png`

## 第 6 步：验证结果

生成后：

1. 查看图像文件以视觉验证它是否匹配用户的请求
2. 如果结果不令人满意，请修改提示并重新生成一次，进行有针对性的更改
3. 如果图像将插入到 markdown 文件中，建议 markdown 语法：`![alt text](relative/path/to/image.png)`
4. 报告使用的提供者路径以及最终文件保存的位置
