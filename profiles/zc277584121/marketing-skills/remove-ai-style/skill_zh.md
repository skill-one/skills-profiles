# 移除AI风格

使用双层工作流程：

1. 运行确定性分析器以定位可重复的词汇、标点、结构和助手残留信号。
2. 通读全文并进行规则无法覆盖的语境判断。

应用一个强默认设置。在每一级严重性下修复确认的发现，重写不自然的段落，并移除未标记的公式化节奏，同时保留事实、含义、所需结构以及作者意图的语气。不要要求用户选择强度，也不要提供轻量、中等、重度或完全模式。

大多数分析器命中仍需要语境判断。三个规则家族是可编辑散文中的硬性出版约束：

- 移除所有感叹号。
- 移除所有用作连字符的中线、全宽连字符和双连字符。
- 重写所有公式化的二元对比，包括“不是……而是……”、“并非……更是……”、“看似……其实……”、“not just X but Y”及其变体，作为直接断言。

修订后分析器计数必须为 `zh-exclamation` 或 `en-exclamation`、`zh-dash` 或 `en-dash`、`zh-binary-contrast` 或 `en-binary-contrast` 为零。唯一的例外是必须保持原文的受保护区域，如代码、URL、Markdown目标以及源文本。不要将品牌热情、随意语气或作者的惯用标点视为保留这些模式的理由。

## 必需的工作流程

### 1. 确定输入和语言

优先选择绝对Markdown文件路径。如果用户仅提供文本，通过stdin将其传递给分析器。

从文章中检测中文或英文。仅在结果错误或用户明确指定语言时才覆盖自动检测。

完全加载匹配的参考：

- 中文：[references/chinese.md](references/chinese.md)
- 英文：[references/english.md](references/english.md)

### 2. 运行确定性分析器

编辑前运行：

```bash
python3 <skill-root>/scripts/analyze_ai_style.py \
  <article-path> \
  --language auto \
  --format json
```

报告包含：

- 稳定性发现ID
- 规则和类别
- 严重性
- 行和列
- 匹配文本
- 本地上下文
- 建议处理
- 重复规则和文档结构摘要

不要用复制的 `grep` 片段替换此命令。捆绑的脚本拥有确定性检测逻辑的唯一所有权。

### 3. 检查每个发现

重写硬性约束规则家族的每个可编辑发现。不要仅仅因为用法在语法上有效就将其归类为有意或假阳性。

将每个其他报告项归类为以下之一：

- `confirmed`：重写它
- `intentional`：保留它，因为体裁或语气需要
- `protected`：保留它，因为它属于代码、源材料、结构或其他保留区域
- `false_positive`：无变化
- `semantic_review`：本地命中真实，但正确的修复取决于更广泛的上下文

阅读报告的上下文，然后在决定前检查周围的段落。不要跨文档批量替换短语。

### 4. 通读完整的原始文章

除非用户明确要求仅处理摘录，否则始终通读完整文章。分析器无法可靠检测：

- 使用新颖措辞的过度隐喻
- 对称性过强的论证结构
- 词汇不同但逻辑重复的段落
- 合成式情感升级
- 听起来精致但意义不明的模糊主张
- 阅读者心灵阅读和为读者消化要点的句子
- 如“很清晰”或“很重要”的空评价形容词
- 没有机制、数字或示例就宣布重要性的主张
- 体裁不匹配
- 扁平化的作者语气
- 可疑的事实或引用

使用语言参考执行此语义检查。报告是导航辅助工具，不是阅读的替代品。

### 5. 记录受保护结构

编辑前记录必须保留的结构：

- YAML前导块
- 标记代码块
- 当其结构有意时，Markdown表格
- 图片和链接
- HTML注释
- 完整的 `VISUAL_TODO` 块
- 引用的源材料和引用

不要为了使散文听起来更自然而更改事实、数字、URL、代码、图片路径、TODO ID或引用目标。

### 6. 侵略性重写

进行语境编辑而不是短语替换：

- 优先使用具体的主题、动作、机制和结果。先陈述事实，再进行判断；不要添加证据已经包含的强调。
- 移除元写作、读者心灵阅读、通用重要性主张、空评价形容词、助手残留和装饰性过渡。
- 仅在当前节奏感觉不自然时才变化节奏；不要添加俚语、错误或随机片段来模仿人类。
- 保留有意语气、技术精确度和体裁适当的结构。判断可以与叙述相邻，但每个判断应基于事实或机制。
- 在材料允许的范围内尽可能降低确认发现的级别。硬性约束规则计数必须在受保护区域外达到零。

作为子代理在文件上被调用时，直接编辑文件，然后返回简洁的变更报告。不要将重写委托给另一个代理。

### 7. 再次运行分析器

编辑后，重新运行相同的命令并比较前后摘要。

使用硬性约束门进行最终扫描：

```bash
python3 <skill-root>/scripts/analyze_ai_style.py \
  <article-path> \
  --language auto \
  --format json \
  --fail-on-hard-constraints
```

退出状态 `2` 表示扫描的散文中至少仍有一个感叹号、连字符或公式化二元对比。除非检查确认匹配属于必须保持原文的源文本，否则重写它。

逐个审查每个剩余发现。当它是有意、受保护、为确保准确性或已记录的假阳性时，剩余的非硬性约束命中是可以接受的。只有当它是受保护或必须保持原文时，剩余的硬性约束命中才是可以接受的。

最后，再次通读修订后的全文以确保连贯性和语气。较低的发现计数并不能证明重写是好的。

## 完成报告

返回：

- 语言
- 按严重性分类的前后发现计数
- 硬性约束规则计数是否达到零的确认，或受保护原文的精确例外列表
- 处理的确认规则
- 保留的有意或受保护发现
- 仅通过完整阅读发现的重要语义变化
- 确认受保护的Markdown结构存活
- 需要人工验证的事实或引用问题
