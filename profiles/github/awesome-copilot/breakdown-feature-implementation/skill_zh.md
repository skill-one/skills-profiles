# 功能实现计划提示

## 目标

扮演一位经验丰富的软件工程师，负责为大型SaaS公司设计高精度的功能。擅长根据功能PRD创建详细的技术实现计划。审阅提供的上下文，输出一个全面、详尽的功能实现计划。
**注意：** 输出中不要写代码，除非是用于技术场景的伪代码。

## 输出格式

输出应为Markdown格式的完整实现计划，保存到 `/docs/ways-of-work/plan/{epic-name}/{feature-name}/implementation-plan.md`。

### 文件系统

遵循Epoch的monorepo结构的前后端仓库文件夹和文件结构：

```
apps/
  [app-name]/
services/
  [service-name]/
packages/
  [package-name]/
```

### 实现计划

针对每个功能：

#### 目标

功能目标描述（3-5句话）

#### 要求

- 详细的功能要求（项目符号列表）
- 实现计划的具体细节

#### 技术考量

##### 系统架构概述

使用Mermaid创建一个全面的系统架构图，展示该功能如何集成到整个系统中。该图应包括：

- **前端层**：用户界面组件、状态管理和客户端逻辑
- **API层**：tRPC端点、认证中间件、输入验证和请求路由
- **业务逻辑层**：服务类、业务规则、工作流编排和事件处理
- **数据层**：数据库交互、缓存机制和外部API集成
- **基础设施层**：Docker容器、后台服务和部署组件

使用子图清晰地组织这些层。用标记的箭头显示层之间的数据流，指示请求/响应模式、数据转换和事件流。包括任何针对此实现唯一的特定功能组件、服务或数据结构。

- **技术栈选择**：记录每层的选择理由
- **集成点**：定义清晰的边界和通信协议
- **部署架构**：Docker容器化策略
- **可扩展性考量**：水平和垂直扩展方法

##### 数据库模式设计

使用Mermaid创建一个实体关系图，展示功能的数模型：

- **表规范**：详细的字段定义，包括类型和约束
- **索引策略**：性能关键索引及其理由
- **外键关系**：数据完整性和引用约束
- **数据库迁移策略**：版本控制和部署方法

##### API设计

- 带有完整规范的端点
- 带有TypeScript类型的请求/响应格式
- 使用Stack Auth的认证和授权
- 错误处理策略和状态码
- 速率限制和缓存策略

##### 前端架构

###### 组件层级文档

组件结构将利用 `shadcn/ui` 库，以实现一致性和可访问性基础。

**布局结构：**

```
食谱库页面
├── 头部区域（shadcn: Card）
│   ├── 标题（shadcn: Typography `h1`）
│   ├── 添加食谱按钮（shadcn: 带有DropdownMenu的Button）
│   │   ├── 手动输入（DropdownMenuItem）
│   │   ├── 从URL导入（DropdownMenuItem）
│   │   └── 从PDF导入（DropdownMenuItem）
│   └── 搜索输入（shadcn: 带有图标的Input）
├── 主要内容区域（flex容器）
│   ├── 过滤侧边栏（aside）
│   │   ├── 过滤标题（shadcn: Typography `h4`）
│   │   ├── 类别过滤（shadcn: Checkbox组）
│   │   ├── 菜系过滤（shadcn: Checkbox组）
│   │   └── 难度过滤（shadcn: RadioGroup）
│   └── 食谱网格（main）
│       └── 食谱卡片（shadcn: Card）
│           ├── 食谱图片（img）
│           ├── 食谱标题（shadcn: Typography `h3`）
│           ├── 食谱标签（shadcn: Badge）
│           └── 快速操作（shadcn: Button - 查看，编辑）
```

- **状态流图**：使用Mermaid的组件状态管理
- 可重用组件库规范
- 使用Zustand/React Query的状态管理模式
- TypeScript接口和类型
