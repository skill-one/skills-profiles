# AI产品GTM

AI产品的市场进入策略。这些不是通用的AI原则——它们是将自主AI代理销售给企业的模式，其中“自主”让购买者感到恐惧，“队友”则将他们转化。

## 何时使用

**触发因素：**
- “我们如何定位这个AI产品？”
- “购买者表示他们担心AI会破坏生产”
- “我们应该称之为自主的还是副驾驶？”
- “当使用量因客户而异10倍时，我们如何为AI定价？”
- “企业安全通过了，但运维拒绝了，为什么？”

**背景：**
- AI代理平台（编码、支持、运维）
- 基于LLM的应用
- 会做事情的自主工具（而不仅仅是建议）
- AI基础设施
- 任何AI做出决策的地方

## 核心框架

### 1. 企业AI的真实反对意见（并非你所想）

**我销售自主AI代理学到的教训：**

三个月后，企业安全审查迅速通过。这是个好迹象，对吧？然后模式出现了：安全批准，但**运维拒绝了**。

反对意见不是“AI会破坏生产吗？”——他们*假设*它最终会破坏生产。真正的问题是：

**“当代理做错事时，谁负责？”**

不是“我们信任代理吗？”——“我们信任我们的*团队*来处理这个问题吗？”

**为什么这很重要：**

自主代理创造了一个新的运营负担。你不是在销售AI能力，你是在销售组织准备情况。当你的代理在凌晨2点停止生产时，谁会被叫醒？谁会修复它？谁会向副总裁解释它？

**框架：责任级联**

在部署AI代理之前，企业需要明确的答案：

1. **L1响应**：谁监控代理？（24/7运维团队，还是轮值开发团队？）
2. **L2升级**：当代理操作失败时，谁调试？（代理团队，还是产品团队？）
3. **L3所有权**：当事情严重出问题时，谁负责客户沟通？

如果你不能回答所有三个问题，**他们不会购买**。无论你的AI有多好。

**这如何改变你的销售流程：**

**旧方法：**
- 演示AI
- 展示准确度指标
- 谈论ROI

**新方法：**
- 演示AI
- 明确展示*失败模式*
- 询问：“你的团队中谁会处理这种情况？”
- 演示他们的故障响应流程
- 将AI失败映射到他们现有的运行手册

**资格问题：**

“带我走过当代理采取破坏工作流的行动时会发生什么。谁会收到警报？谁会调查？谁会决定回滚还是向前修复？”

如果他们不能回答，他们还没准备好。暂停交易，先帮助他们建立流程。

**常见错误：**

将这视为一个*产品*反对意见（“我们会让AI更准确”）。这是一个*组织*反对意见。更高的准确度并不能解决“凌晨2点谁拥有这个？”的问题。

**我看到的成功模式：**

成功使用AI代理的公司已经拥有：
- 生产系统的轮值呼叫
- 事件响应剧本
- 无指责的事后分析文化
- 明确的升级路径

挣扎的公司：
- 手动部署流程
- 英雄文化（“史蒂夫能修复一切”）
- 没有正式的事件响应
- 指责文化

**决策标准：**

在向企业演示自主AI之前，问问自己：“如果这破坏了他们的生产，他们*团队*中谁拥有修复权？”如果你不能回答，他们不能购买。

### 2. 副驾驶与代理与队友（三种不同的GTM策略）

**定位陷阱：**

早期的企业对话中，我们定位为“自主AI代理”。购买者犹豫了。一个词的改变——“自主”→“AI队友”——交易进展明显改善。

为什么？**词语选择塑造购买者心理。**

**三种定位：**

**1. 副驾驶（最安全，最低价值）**
- **含义**：AI建议，人类每次都决定
- **购买者心理**：感觉安全，不具威胁性
- **GTM策略**：开发者采用，自下而上
- **用例**：代码补全，写作辅助，搜索
- **反对意见**：“这值得付费吗？”（感知价值低）

**2. 代理（最吓人，最高价值）**
- **含义**：AI自主行动，人类定期审查
- **购买者心理**：吓人，暗示取代人类
- **GTM策略**：企业销售，自上而下
- **用例**：批量处理，自动化工作流，运维
- **反对意见**：“如果它破坏生产怎么办？”（责任恐惧）

**3. 队友（最佳平衡点）**
- **含义**：AI与人类协作，分担工作
- **购买者心理**：伙伴关系，不是取代
- **GTM策略**：混合（开发者采用+经理批准）
- **用例**：大多数AI代理平台
- **反对意见**：“我们如何将此集成到我们的工作流中？”（流程问题）

**定位转变：**

**之前**：“端到端处理复杂工作流的自主AI代理”
- 开发者：“酷，但吓人”
- 经理：“这会取代我们的团队吗？”
- 交易进展：缓慢

**之后**：“与你的工程师合作处理复杂任务的AI队友”
- 开发者：“这帮助我”
- 经理：“这使我的团队更有效率”
- 交易进展：四家停滞4个月以上的企业交易在转变后的8周内关闭

**实际的语言选择：**

❌ **不要说：**
- “自主”（吓人）
- “取代”（威胁性）
- “完全自动化”（没有控制）
- “AI优先”（那是什么意思？）

✅ **要说：**
- “队友”（协作性）
- “增强”或“加速”（帮助，不是取代）
- “你保持控制”（令人安心）
- “处理重复性工作”（具体价值）

**如何选择你的定位：**

```
你的AI是否无需人类批准就做决策？
├─ 是 → 你是在向谁销售？
│   ├─ 开发者 → “代理”定位（他们想要自主）
│   └─ 企业 → “队友”定位（他们想要控制）
└─ 否 → “副驾驶”定位（增强，不是自动化）
```

**残酷的真相：**

你可以构建一个代理，但将其定位为副驾驶。你不能构建一个副驾驶，却将其定位为代理。**产品能力设定上限，定位选择在它之下落地。**

**常见错误：**

因为听起来令人印象深刻而使用“自主”。令人印象深刻≠被信任。如果购买者在定位上犹豫，你就输了。

### 3. AI定价问题（当使用量差异10倍时）

**模式：**

我参与过的每个AI公司都面临这个问题：客户A每月使用1000个API调用。客户B使用10000个。你是对客户B收取10倍的费用吗？如果是，他们会流失。如果不是，你的利润会崩溃。

**三种模型：**

**1. 座位制（每用户每月$X）**
- **何时有效**：AI增强人类工作可预测
- **示例**：代码补全，写作辅助
- **问题**：无法捕捉AI价值扩展
- **真实风险**：高使用量客户是你最好的客户，但他们补贴低使用量客户

**2. 使用量制（每个API调用/预测/小时$X）**
- **何时有效**：AI做可变工作，客户理解单位
- **示例**：图像生成，转录，批量ML
- **问题**：高使用量客户的贴现冲击
- **真实风险**：客户优化以使用*更少*的产品

**3. 结果制（每个实现的结果$X）**
- **何时有效**：你可以可靠地衡量结果
- **示例**：“按修复的bug付费”或“按解决的支持工单付费”
- **问题**：难以衡量，容易作弊
- **真实风险**：如果AI表现不佳，你承担所有风险

**实际上有效（混合）：**

固定费用（覆盖固定成本）+可变费用（随价值扩展）。

**示例结构：**
- 基础：每团队每月$X（平台访问权限）
- 可变：每个成功行动/结果$Y
- 为什么这有效：
  - 基础费用覆盖基础设施/支持成本
  - 可变费用与客户价值一致
  - 高使用量客户不会被惩罚（他们获得更多价值）

**我希望早期就有的定价对话：**

在定价使用型AI时：

**询问客户：**
“手动完成这项工作需要花费你多少钱？”

如果它成本为每个API调用$0.10，但为你节省了$2的劳动力，你定价过低。如果它成本为每个调用$0.50，但为你节省了$0.40，他们不会使用足够的量来使其有意义。

**定价规则：**

你的可变成本应该是**客户替代成本的20-30%**。足够高以捕捉价值，足够低以让他们广泛使用。

**常见错误：**

因为“每个人都这样做”而复制OpenAI的定价（每个1000个token $0.01）。你的成本结构不是OpenAI的成本结构。你的价值不是OpenAI的价值。为*你的*业务定价。

### 4. AI信任阶梯（来自一个曾经攀登过它的人）

**模式：**

你不能通过说“相信我们，它有效”来销售AI。你要分阶段建立信任。

**首先：透明度（在第一次演示之前）**

在他们询问之前发送这三个文档：
- 模型卡（什么模型，在什么数据上训练，什么基准上的准确度）
- 安全白皮书（数据去哪里，如何处理）
- 可解释性文档（如何解释AI决策）

**为什么这有效：**
购买者期望做尽职调查。如果你*在他们询问之前*发送文档，你看起来自信且可信。

**其次：控制（在演示中）**

展示安全机制：
- 用户如何批准/拒绝AI建议
- 关闭开关和回滚机制
- 置信度分数以及何时AI说“我不确定”

**为什么这有效：**
对“失控AI”的恐惧是真实的。展示控制机制证明了你考虑了失败模式。

**第三：性能（第4-8周）**

证明它有效：
- 与基线（人类或以前工具）的基准比较
- 来自类似公司的案例研究
- 在他们的数据上进行实时演示（如果可能）

**为什么这有效：**
证明胜过承诺。一个客户说“我们节省了X小时/周”比100个营销声明更有价值。

**第四：扩展（当他们认真时）**

展示企业准备情况：
- 企业部署示例
- 扩展性能（延迟，吞吐量，错误率）
- 合规文档（SOC 2，GDPR等）

**为什么这有效：**
企业不会部署MVP。他们需要证明你不会在1000个用户时崩溃。

**我犯的错误：**

在解释AI工作原理之前尝试证明性能。购买者不理解系统，因此不相信基准。**顺序很重要。**

**决策标准：**

如果购买者在演示之前问“它是如何工作的？”，你就跳过了透明度。后退并发送文档。

### 5. 企业AI演示（展示失败，而不仅仅是成功）

**什么不起作用：**

罐头演示，AI神奇地解决一切。购买者认为“这不会在我的混乱数据上工作。”

**什么有效：**

展示AI犯错误并恢复。认真对待。

**有效演示结构：**

**1. 问题（30秒）**
“你的工程师在[特定任务]上花费了几个小时。这里是什么样子。”
- 展示：当前手动工作流
- 定量：时间×工程师×周=总成本

**2. AI尝试（60秒）**
“这里是AI处理相同任务。”
- 展示：AI分析，采取行动
- **关键步骤**：让AI遇到错误或不确定性
- 展示：AI重新分析，恢复，或寻求帮助
- **叙述**：“注意它第一次没有完全正确。它像人类一样处理不确定性。”

**3. 人类审查（30秒）**
“这里是工程师审查和批准。”
- 展示：工程师检查AI的工作
- **关键步骤**：展示工程师覆盖或调整某事
- **叙述**：“人类保持控制。AI处理重复性工作，人类处理判断。”

**4. 结果（30秒）**
“[X小时]→[Y分钟]。工程师仍然拥有结果，AI加速执行。”
- 定量：时间减少，成本节省，释放容量

**为什么这有效：**

- 展示失败→建立信任（你没有隐藏任何东西）
- 展示恢复→证明AI是稳健的
- 展示人类覆盖→给他们控制权
- 定量节省→使ROI具体化

**我看到的模式：**

完美AI的演示→购买者怀疑
有缺陷但能恢复的AI演示→购买者投入

**常见错误：**

挑选100%准确的示例。购买者知道真实世界数据是混乱的。如果你不展示混乱，他们假设你在隐藏它。

### 6. “谁拥有这个？”反对意见处理

**反对意见：**

“这看起来很棒，但当AI做错事时会发生什么？”

**错误答案：**
“我们的AI准确率为95%，我们每周都在改进它。”
（翻译：“它会在5%的时间内破坏生产，祝你好运”）

**正确答案：**
“好问题。让我们一起走一个失败场景。”

**然后询问：**

1. “当AI采取导致错误的行动时，你团队中谁调查？”
2. “你们是否有针对工具故障的事件响应流程？”
3. “谁拥有回滚决策——批准它的工程师，还是运维团队？”

**这做了什么：**

- 从“它会失败吗？”（会，它会）转变为“我们如何处理失败？”
- 使他们思考运营准备情况
- 揭示他们是否准备好使用AI代理

**后续：**

“我们建议：从低风险环境开始。让AI处理非关键工作流2-4周。看看你的团队如何处理它的错误。然后当你对流程有信心时再扩展范围。”

**为什么这有效：**

你不在销售完美。你正在销售一个需要运营成熟度的工具。**过滤成熟购买者比说服不成熟的购买者更好。**

**模式：**

成熟的购买者说：“我们已经有针对工具故障的运行手册，我们将AI添加到其中。”
不成熟的购买者说：“你能让它永不失败吗？”

**决策标准：**

如果购买者要求100%准确度，就离开。他们还没准备好。在他们建立流程后再回来。

### 7. AI定位陷阱（对抗非对称战争）

**模式：**

你正在AI代理空间竞争。每个竞争对手的主页都说同样的话：“用AI自动化[工作流]”。你的差异化需要解释复杂的基准，购买者不理解。

这就是定位陷阱：**在对手的战场上，用功能与他们竞争。**

**如何诊断：**

1. 收集5-7个直接竞争对手的主页信息
2. 确定共同声明（这些都是标准化的——你不能赢在这里）
3. 映射你的结构性优势（不仅仅是产品功能）
4. 找到竞争对手无法轻易复制的定位

**适合AI定位的结构性优势：**
- 独特的数据或工作流所有权（你控制着竞争对手无法复制的东西）
- 部署灵活性（本地，私有云，客户控制的基础设施）
- 定价模式创新（结果导向，当竞争对手是座位导向时使用使用量导向）
- 社区或生态系统（随时间复合的网络效应）

不会持续的功能优势：
- “更准确的准确度”（竞争对手在一周冲刺中就能赶上）
- “更快的推理”（基础设施商品化）
- “更多集成”（容易复制）

**测试：**

对于每个定位声明，问：竞争对手能否用一个产品冲刺复制这个？如果是，它不可防御。不要在你的GTM上建立它。

**常见错误：**

声称你在“做得更好”于每个人都在做的事情。在AI中，基准每月都在变化。定位你方法的结构性差异，而不是暂时更好的模型。

### 8. 屏幕时刻资格（寻找高意向AI购买者）

**模式：**

对AI代理的最高意向企业购买者是那些已经采用过类似工具并达到其极限的人。他们已经投资于学习，他们理解问题空间，并且他们有清晰的业务案例用于升级。

**如何识别屏幕时刻：**

潜在客户已经：
- 使用了6个月以上的副驾驶/助手工具
- 达到其限制（无法处理复杂任务，不兼容他们的堆栈，自主性不够）
- 低切换成本（心理模型可以转移）
- 清晰的业务案例（“即使使用当前工具，我们也在手动执行这项任务上花费X小时”）

**如何定位他们：**

1. 确定你的AI产品补充或取代的工具
2. 构建使用这些工具的公司目标列表
3. 围绕限制而不是功能制作外联：
   - “使用[现有工具]的团队通常在需要[你的产品提供的功能]时遇到瓶颈”
   - 承认现有工具的价值（不要贬低）
   - 定位为“下一级别”，而不是替代品

**为什么这转化得更好：**

屏幕时刻对话的转化率是冷外联的3-5倍，因为：
- 潜在客户已经理解了问题
- 他们已经投资了该类别
- 他们有内部预算分配
- 他们可以具体说明缺失什么

**资格问题：**

“你最复杂的任务是尝试自动化的，以及它在哪里失败？”

如果他们有具体的答案和具体的痛点，他们就是屏幕时刻购买者。如果他们说“它运行得很好”，他们还没准备好。

**常见错误：**

试图说服对工具无知的潜在客户采用AI代理。转化率差，教育周期长，他们会将你与“不做”而不是“做得更好”进行比较。定位已经相信该类别的购买者。

## 决策树

### 我应该使用哪种定位？

```
你的AI是否自主行动（每项行动无需批准）？
├─ 是 → 你在向谁销售？
│   ├─ 开发者 → “代理”定位
│   └─ 企业 → “队友”定位
└─ 否 → “副驾驶”定位
```

### 我应该使用哪种定价模型？

```
你能可靠地衡量客户结果吗？
├─ 是 → 结果导向（或带有结果组件的混合）
└─ 否 → 继续...
    │
    使用量是否因客户而异5倍以上？
    ├─ 是 → 混合（基础+使用量）
    └─ 否 → 座位制
```

### 这个购买者准备好使用AI代理了吗？

```
他们是否有针对工具故障的事件响应流程？
├─ 是 → 继续...
│   │
│   他们是否有生产系统的轮值呼叫？
│   ├─ 是 → 合格购买者
│   └─ 否 → 先帮助他们建立它
└─ 否 → 未准备好（6个月后回来）
```

---

## 常见错误

**1. 因为听起来令人印象深刻而使用“自主”**
   - 我见过这减缓交易。 “自主”让企业害怕。“队友”进展更快。

**2. 隐藏AI失败模式**
   - 购买者知道真实世界数据是混乱的。如果你不展示失败，他们假设你在隐藏它。

**3. 将“它会破坏生产吗？”视为反对意见**
   - 真正的反对意见：“当它做错事时，谁负责？” 组织准备情况，而不是准确度。

**4. 像OpenAI一样定价使用型AI**
   - 你的成本结构不是他们的。为客户的替代成本的20-30%定价。

**5. 在演示之前跳过透明度文档**
   - 顺序很重要。透明度→控制→性能→扩展。不要跳过步骤。

**6. 演示完美的AI**
   - 展示错误+恢复。比虚假完美更有信任力。

**7. 销售要求100%准确度的购买者**
   - 他们还没准备好。过滤成熟购买者，他们有事件响应流程。

## 快速参考

**企业反对意见清单：**
- [ ] “当AI破坏生产时，谁会被叫醒？”→ 映射到他们的轮值呼叫
- [ ] “谁调试AI故障？”→ 映射到他们的事件响应
- [ ] “谁拥有客户沟通权？”→ 映射到他们的升级路径

**定位词语选择：**
- ✅ 队友，增强，加速，你保持控制
- ❌ 自主，取代，完全自动化，AI优先

**演示结构：**
1. 量化成本的问题（30秒）
2. AI尝试包括失败/不确定性（60秒）
3. 人类审查和覆盖（30秒）
4. 结果与ROI（30秒）

**信任阶梯：**
1. 透明度（模型卡，安全，可解释性）
2. 控制（批准工作流，关闭开关，置信度分数）
3. 性能（基准，案例研究，实时演示）
4. 扩展（企业部署，合规，SLA）

**定价混合公式：**
- 基础：$X/月（覆盖固定成本）
- 可变：$Y/单位（客户替代成本的20-30%）
