# 创建规范

您的目标是创建一个新的规范文件用于 `${input:SpecPurpose}`。

规范文件必须以清晰、无歧义且结构化的方式定义解决方案组件的要求、约束和接口，以便生成式人工智能能够有效地使用。遵循既定的文档标准，并确保内容是机器可读的且自包含的。

## 适用于生成式人工智能的规范最佳实践

- 使用精确、明确且无歧义的语言。
- 明确区分要求、约束和建议。
- 使用结构化格式（标题、列表、表格）以便于解析。
- 避免使用习语、隐喻或依赖上下文的引用。
- 定义所有首字母缩写词和特定领域术语。
- 在适用情况下包含示例和边缘情况。
- 确保文档是自包含的，不依赖于外部上下文。

规范应保存在 `/spec/` 目录中，并按照以下约定命名：`spec-[a-z0-9-]+.md`，其中名称应描述规范的内容，并以高层目的开头，高层目的是 [schema、tool、data、infrastructure、process、architecture 或 design] 中的一个。

规范文件必须使用格式良好的 Markdown 格式化。

规范文件必须遵循以下模板，并确保所有部分都填写适当。Markdown 的前端元数据应按照以下示例正确结构化：

```md
---
title: [简洁描述规范重点的标题]
version: [可选：例如，1.0、日期]
date_created: [YYYY-MM-DD]
last_updated: [可选：YYYY-MM-DD]
owner: [可选：负责此规范的团队/个人]
tags: [可选：相关标签或类别的列表，例如，`infrastructure`、`process`、`design`、`app` 等]
---
