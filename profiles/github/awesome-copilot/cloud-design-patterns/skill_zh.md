# 云设计模式

架构师通过整合平台服务、功能和代码来设计工作负载，以满足功能和非功能需求。为了设计有效的工作负载，你必须理解这些需求，并选择能够应对工作负载约束挑战的拓扑结构和方法论。云设计模式为许多常见挑战提供了解决方案。

系统设计严重依赖于已建立的设计模式。你可以通过使用这些模式的组合来设计基础设施、代码和分布式系统。这些模式对于在云中构建可靠、高度安全、成本优化、运营高效和高性能的应用程序至关重要。

以下云设计模式是技术无关的，这使得它们适用于任何分布式系统。你可以将这些模式应用于 Azure、其他云平台、本地设置和混合环境。

## 云设计模式如何增强设计过程

云工作负载容易受到分布式计算谬误的影响，这些谬误是关于分布式系统如何运行的普遍但错误的假设。这些谬误的例子包括：

- 网络是可靠的。
- 延迟为零。
- 带宽是无限的。
- 网络是安全的。
- 拓扑不会改变。
- 有一个管理员。
- 组件版本管理很简单。
- 可观察性实施可以延迟。

这些误解可能导致工作负载设计存在缺陷。设计模式不会消除这些误解，但有助于提高意识、提供补偿策略和提供缓解措施。每个云设计模式都有权衡。重点在于为什么你应该选择特定的模式，而不是如何实现它。
