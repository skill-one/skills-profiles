# 为 Oracle 到 PostgreSQL 迁移创建集成测试项目框架

创建一个可编译的空 xUnit 测试项目，包含事务管理和种子数据基础设施，用于单个目标项目。每个项目在编写测试之前运行一次。

## 工作流程

```
进度：
- [ ] 第 1 步：检查目标项目
- [ ] 第 2 步：创建 xUnit 测试项目
- [ ] 第 3 步：实现事务回滚基类
- [ ] 第 4 步：实现种子数据管理器
- [ ] 第 5 步：验证项目可编译
```

**第 1 步：检查目标项目**

读取目标项目的 `.csproj` 文件，确定 .NET 版本和现有的包引用。精确匹配这些版本——不要升级。

**第 2 步：创建 xUnit 测试项目**

- 目标与测试应用程序相同的 .NET 版本。
- 添加用于 Oracle 数据库连接的 NuGet 包（`Oracle.ManagedDataAccess.Core`）和 xUnit。
- 仅向目标项目添加项目引用——不要引用其他应用程序项目。
- 添加一个配置为 Oracle 数据库连接的 `appsettings.json`。

**第 3 步：实现事务回滚基类**

- 创建一个基测试类，在每个测试之前打开事务并在之后回滚。
- 捕获并处理所有异常以确保回滚。
- 使该模式可被所有下游测试类继承。

**第 4 步：实现种子数据管理器**

- 创建一个全局种子管理器，用于在事务范围内加载测试数据。
- 不要提交种子数据——事务在每个测试后回滚。
- 不要使用 `TRUNCATE TABLE`——保留现有数据库数据。
- 建立种子文件位置的命名约定，下游测试创建将遵循该约定。

**第 5 步：验证项目可编译**

构建测试项目，并在完成前确认其可编译且无错误。

## 关键约束

- **仅第 3 步**——此技能搭建的是 Oracle 目标测试项目。PostgreSQL 测试项目（第 6 步）是通过复制和迁移此项目创建的；在该点不要再次运行此技能。
- Oracle 是黄金行为源——仅搭建 Oracle，不要搭建 PostgreSQL。
- 遵循现有的 .NET 和 C# 版本；不要引入新的语言或运行时特性。
- 输出是一个仅含基础设施的空测试项目——没有测试用例。
