# 创建高质量的 AGENTS.md 文件

你是一个代码代理。你的任务是创建一个完整、准确的 AGENTS.md 文件，放置在这个仓库的根目录下，并遵循 https://agents.md/ 上的公共指导。

AGENTS.md 是一种开放格式，旨在为代码代理提供所需的上下文和指令，以便它们能够有效地参与项目工作。

## AGENTS.md 是什么？

AGENTS.md 是一个 Markdown 文件，它充当“代理的 README” - 一个专门、可预测的地方，用于向 AI 代码代理提供上下文和指令，帮助它们在你的项目中工作。它补充了 README.md，包含代码代理需要的详细技术上下文，但可能会让面向人类的 README 变得杂乱。

## 关键原则

- **面向代理**：包含为自动化工具准备的详细技术指令
- **补充 README.md**：不会取代人类文档，而是添加针对代理的上下文
- **标准位置**：放置在仓库根目录（或单仓库项目的子项目根目录）
- **开放格式**：使用标准 Markdown 和灵活的结构
- **生态系统兼容性**：兼容 20 多种不同的 AI 代码工具和代理

## 文件结构和内容指南

### 1. 必要设置

- 在仓库根目录下创建文件为 `AGENTS.md`
- 使用标准 Markdown 格式
- 没有必填字段 - 基于项目需求采用灵活结构

### 2. 必须包含的关键部分

#### 项目概述

- 项目功能的简要描述
- 如果复杂，提供架构概述
- 使用的关键技术和框架

#### 设置命令

- 安装说明
- 环境设置步骤
- 依赖管理命令
- 如适用，数据库设置

#### 开发工作流

- 如何启动开发服务器
- 构建命令
- 监视/热重载设置
- 包管理器特定细节（npm、pnpm、yarn 等）

#### 测试说明

- 如何运行测试（单元、集成、端到端）
- 测试文件位置和命名约定
- 覆盖要求
- 使用的特定测试模式或框架
- 如何运行测试子集或专注于特定区域

#### 代码风格指南

- 语言特定的约定
- 代码检查和格式化规则
- 文件组织模式
- 命名约定
- 导入/导出模式

#### 构建和部署

- 构建命令和输出
- 环境配置
- 部署步骤和要求
- CI/CD 管道信息

### 3. 可选但推荐的部分

#### 安全注意事项

- 安全测试要求
- 密钥管理
- 身份验证模式
- 权限模型

#### 单仓库说明（如适用）

- 如何处理多个包
- 跨包依赖
- 选择性构建/测试
- 包特定命令

#### Pull Request 指南

- 标题格式要求
- 提交前必须执行的检查
- 审查流程
- 提交信息约定

#### 调试和故障排除

- 常见问题和解决方案
- 日志模式
- 调试配置
- 性能考虑

## AGENTS.md 的工作示例

这是来自 agents.md 网站的实际示例：

```markdown
# 示例 AGENTS.md 文件

## 开发环境技巧

- 使用 `pnpm dlx turbo run where <project_name>` 跳转到包，而不是用 `ls` 扫描。
- 运行 `pnpm install --filter <project_name>` 将包添加到工作区，以便 Vite、ESLint 和 TypeScript 可以看到它。
- 使用 `pnpm create vite@latest <project_name> -- --template react-ts` 启动一个新的带有 TypeScript 检查的 React + Vite 包。
- 检查每个包的 package.json 中的名称字段以确认正确的名称 - 跳过顶层的一个。

## 测试说明

- 在 .github/workflows 文件夹中找到 CI 计划。
- 运行 `pnpm turbo run test --filter <project_name>` 运行该包定义的所有检查。
- 从包根目录只需调用 `pnpm test`。提交前该提交应通过所有测试。
- 要专注于一个步骤，添加 Vitest 模式：`pnpm vitest run -t "<test name>"`。
- 修复任何测试或类型错误，直到整个套件变为绿色。
- 移动文件或更改导入后，运行 `pnpm lint --filter <project_name>` 确保 ESLint 和 TypeScript 规则仍然通过。
- 为您更改的代码添加或更新测试，即使没有人要求。

## Pull Request 指南

- 标题格式：[<project_name>] <Title>
- 提交前始终运行 `pnpm lint` 和 `pnpm test`。
```

## 实施步骤

1. **分析项目结构** 以理解：

   - 使用的编程语言和框架
   - 包管理器和构建工具
   - 测试框架
   - 项目架构（单仓库、单个包等）

2. **识别关键工作流** 通过检查：

   - package.json 脚本
   - Makefile 或其他构建文件
   - CI/CD 配置文件
   - 文档文件

3. **创建全面的部分** 覆盖：

   - 所有必要的设置和开发命令
   - 测试策略和命令
   - 代码风格和约定
   - 构建和部署过程

4. **包含具体、可执行的命令** 代理可以直接执行

5. **测试说明** 通过确保所有命令按文档工作

6. **保持专注** 在代理需要了解的内容上，而不是一般的项目信息

## 最佳实践

- **具体**：包含确切命令，而不是模糊描述
- **使用代码块**：用反引号包裹命令以提高清晰度
- **包含上下文**：解释为什么需要某些步骤
- **保持更新**：随着项目的发展进行更新
- **测试命令**：确保所有列出的命令实际可用
- **考虑嵌套文件**：对于单仓库，根据需要创建子项目的 AGENTS.md 文件

## 单仓库考虑

对于大型单仓库：

- 在仓库根目录放置主 AGENTS.md
- 在子项目目录创建额外的 AGENTS.md 文件
- 最接近的 AGENTS.md 文件将优先用于任何给定位置
- 包含包/项目之间的导航提示

## 最终说明

- AGENTS.md 兼容 20 多种 AI 代码工具，包括 Cursor、Aider、Gemini CLI 等
- 格式故意灵活 - 根据您的项目需求进行调整
- 专注于帮助代理理解和处理代码库的可执行说明
- 这是“活文档” - 随着项目的发展进行更新

创建 AGENTS.md 文件时，优先考虑清晰度、完整性和可操作性。目标是给任何代码代理足够的上下文，以便它们能够有效地为项目做出贡献，而无需额外的手动指导。
