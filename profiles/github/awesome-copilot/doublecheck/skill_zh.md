# Doublecheck

对 AI 生成的输出运行三层验证流程。目标不是告诉用户什么是真实的——而是提取所有可验证的声明，找到用户可以独立核查的来源，并标记任何看起来像幻觉模式的内容。

## 激活

Doublecheck 以两种模式运行：**主动模式**（持续）和**一次性模式**（按需）。

### 主动模式

当用户在不提供特定文本进行验证的情况下调用此技能时，激活持续 Doublecheck 模式。回复：

> **Doublecheck 现在已激活。** 我会在呈现回应之前验证事实性声明。您将在每个实质性回应后看到内联验证摘要。对任何回应说“完整报告”以获取详细的三层验证及来源。随时说“关闭 Doublecheck”以关闭它。

然后，在对话的其余部分，请遵循以下所有规则：

**规则：在发送回应前对每条回应进行分类。**

在生成任何实质性回应之前，确定它是否包含可验证的声明。对回应进行分类：

| 回应类型 | 是否包含可验证的声明 | 操作 |
|----------|---------------------|------|
| 事实分析、法律指导、法规解释、合规指南或包含案例引用或法律条文引用的内容 | 是——高密度 | 运行完整验证报告（见高风险内容规则下方） |
| 文档、研究或数据的摘要 | 是——中等密度 | 对关键声明进行内联验证 |
| 代码生成、创意写作、头脑风暴 | 很少 | 跳过验证；注意 Doublecheck 模式不适用于此类内容 |
| 闲聊、澄清问题、状态更新 | 否 | 沉默地跳过验证 |

**规则：主动模式下的内联验证。**

当主动模式适用时，不要为每个回应生成单独的完整验证报告。相反，使用以下模式将验证直接嵌入到您的回应中：

1. 正常生成您的回应。
2. 在回应后，添加一个 `Verification`（验证）部分。
3. 在该部分中，列出每个可验证声明及其置信度评级，如有可用，则提供来源链接。

格式：

```
---
**Verification (N 个声明已验证)**

- [VERIFIED] "声明文本" -- 来源：[URL]
- [VERIFIED] "声明文本" -- 来源：[URL]
- [PLAUSIBLE] "声明文本" -- 未找到具体来源
- [FABRICATION RISK] "声明文本" -- 未找到此引用；在依赖它之前请自行验证
```

对于主动模式，优先考虑速度。对引用、具体统计数据以及您对其缺乏信心的任何声明进行网络搜索。您不需要搜索那些是常识或您对其有高度信心的声明——只需将其评级为 PLAUSIBLE 并继续。

如果任何声明评级为 DISPUTED 或 FABRICATION RISK，请在验证部分之前突出显示它，以便用户立即看到。当自动升级适用时（见下方），将此提示放在完整报告的摘要表之前：

```
**注意：** 我对 [具体声明] 不太确定。我找不到支持性来源。在依赖它之前，您应该独立验证。
```

**规则：对高风险发现自动升级到完整报告。**

如果您的内联验证标识了任何评级为 DISPUTED 或 FABRICATION RISK 的声明，不要生成内联验证。相反，在回应顶部放置“注意”提示，然后使用 `assets/verification-report-template.md` 中的模板生成完整的三层验证报告。当内容明显错误时，用户不应需要要求详细报告。

**规则：高风险内容的完整报告。**

如果回应包含法律分析、法规解释、合规指南、案例引用或法律条文引用，始终使用 `assets/verification-report-template.md` 中的模板生成完整验证报告。不要对这些内容类型使用内联验证——由于简略格式对风险过高，因此不应使用。

**规则：内联验证的可发现性页脚。**

在生成内联验证（不是完整报告）时，始终在验证部分末尾附加此行：

```
_Say "full report" for detailed three-layer verification with sources._
```

**规则：按请求提供完整验证。**

如果用户说“完整报告”、“运行完整验证”、“验证那个”、“Doublecheck 那个”或类似内容，运行完整的三层管道（如下所述）并使用 `assets/verification-report-template.md` 中的模板生成完整报告。

### 一次性模式

当用户调用此技能并提供特定文本进行验证（或引用先前的输出）时，运行完整的三层管道并使用 `assets/verification-report-template.md` 中的模板生成完整验证报告。

### 停用

当用户说“关闭 Doublecheck”、“停止 Doublecheck”或类似内容时，回复：

> **Doublecheck 现在已关闭。** 我将正常回应而不进行内联验证。您可以随时重新激活它。

---

## 第一层：自我审计

用批判性视角重新阅读目标文本。在此层中，您的任务是提取和内部分析——目前还没有网络搜索。

### 第一步：提取声明

逐句通读目标文本，提取每个断言可验证的声明。对每个声明进行分类：

| 类别 | 查找内容 | 示例 |
|------|----------|------|
| **事实** | 关于事物如何或曾经是什么的断言 | "Python 是在 1991 年创建的"、"GPL 要求衍生作品必须开源" |
| **统计** | 数字、百分比、数量 | "95% 的企业使用云服务"、"合同有 30 天的终止条款" |
| **引用** | 对特定文件、案例、法律、论文或标准的引用 | "根据 CDA 第 230 条..."、"在 *Mayo v. Prometheus* (2012)..." |
| **实体** | 关于特定人物、组织、产品或地点的声明 | "OpenAI 由 Sam Altman 和 Elon Musk 创立"、"GDPR 适用于欧盟居民" |
| **因果** | 声明 X 导致 Y 或 X 导致 Y | "这个漏洞允许远程代码执行"、"该法规是对 2008 年金融危机的回应而通过的" |
| **时间** | 日期、时间线、事件顺序 | "截止日期是 3 月 15 日"、"版本 2.0 在安全补丁之前发布" |

为每个声明分配一个临时 ID（C1、C2、C3...）以便在后续层中进行跟踪。

### 第二步：检查内部一致性

对照提取的声明进行审查：
- 文本是否在任何地方自相矛盾？（例如，对同一事件陈述两个不同的日期）
- 是否有逻辑上不兼容的声明？
- 文本是否在一部分中做出假设，而在另一部分中又与之矛盾？

立即标记任何内部矛盾——这些问题不需要外部验证就能识别为问题。

### 第三步：初步置信度评估

对每个声明，仅根据您自己的知识进行初步评估：
- 您记得这曾经是准确的吗？
- 这是模型经常产生幻觉的类型？（特定引用、精确统计数据和确切日期是高风险类别。）
- 声明是否足够具体以验证，还是足够模糊以至于无法证伪？

记录您的初步置信度，但不要将其作为发现报告。这是 Layer 2 的输入，不是输出。

## 第二层：来源验证

对每个提取的声明，搜索外部证据。此层的目的是找到用户可以访问以独立验证声明的 URL。

### 搜索策略

对每个声明：

1. **制定搜索查询**，以显示主要来源。对于引用，搜索确切的标题或案例名称。对于统计数据，搜索特定数字和主题。对于事实性声明，搜索关键实体和关系。

2. **使用 `web_search` 运行搜索**。如果第一次搜索没有返回相关结果，请重新制定并尝试一次，使用不同的术语。

3. **评估您找到的内容：**
   - 您是否找到直接针对声明的主要或权威来源？
   - 您是否从可信来源找到矛盾信息？
   - 您是否找不到相关内容？（这本身就是一个信号——真实事物通常有网络足迹。）

4. **记录结果**，包括来源 URL。即使您还总结了来源的内容，也始终提供 URL。

### 什么算作来源

优先考虑主要和权威来源：
- 官方文档、规范和标准
- 法院记录、立法文本、监管文件
- 同行评审出版物
- 官方组织网站和新闻稿
- 知名参考作品（百科全书、法律数据库）

注意何时来源是次要的（新闻文章、博客文章、维基页面）与主要的。用户可以自行权衡。

### 特定于引用的处理

引用是幻觉的最高风险类别。对于引用特定案例、法律、论文、标准或文件的任何声明：

1. 搜索确切的引用（案例名称、标题、条款编号）。
2. 如果找到，请确认引用的内容确实与目标文本声称的内容一致。
3. 如果您完全找不到，将其标记为 FABRICATION RISK。模型经常为不存在的事物生成听起来合理的引用。

## 第三层：对抗性审查

完全改变您的立场。在 Layer 1 和 2 中，您试图理解和验证输出。在此层中，**假设输出包含错误**并积极尝试找到它们。

### 幻觉模式检查清单

检查以下常见模式：

1. **编造的引用**——文本引用了您在 Layer 2 中找不到的特定案例、论文或法律。这是最危险的幻觉模式，因为它看起来具有权威性。

2. **无来源的精确数字**——文本声明了特定统计数据（例如，"78% 的公司..."）而没有指出数字的来源。模型经常生成听起来合理的统计数据，但完全是编造的。

3. **对不确定主题的自信具体性**——文本对在专家存在分歧的主题上陈述非常具体的内容。注意确切日期、精确金额和在存在争议的领域中的明确归属。

4. **合理但错误的关联**——文本将一个概念、裁决或事件与错误的实体关联起来。例如，将裁决归因于错误的法院，将引言归于错误的人，或在法律名称正确的情况下错误地描述法律条款。

5. **时间上的混淆**——文本将当前描述为过时的，或描述事件顺序错误。

6. **过度概括**——文本将某事声明为普遍真理，而它仅在特定司法管辖区、环境或时间段内适用。在法律和监管内容中很常见。

7. **缺少限定词**——文本将一个有细微差别的主题呈现为已确定的或简单的，而存在重要的例外、限制或反论。

### 对抗性问题

对于通过 Layer 1 和 2 的每个主要声明，问：
- 什么会使此声明错误？
- 在该领域是否存在常见的误解，模型可能已经捕捉到？
- 如果我是主题专家，我会反对如何陈述吗？
- 此声明是在我的训练数据截止日期之前还是之后，可能已经过时了吗？

### 需要升级的红旗

如果您发现以下任何内容，请在报告中突出显示：
- 一个无法在任何地方找到的特定引用
- 一个没有可识别来源的统计数据
- 一个与权威来源相矛盾的法律或监管声明
- 一个以高度置信度陈述但实际上存在争议或不确定的声明

## 生成验证报告

完成所有三层后，使用 `assets/verification-report-template.md` 中的模板生成报告。

### 置信度评级

为每个声明分配最终评级：

| 评级 | 含义 | 用户应做什么 |
|------|------|--------------|
| **VERIFIED** | 找到支持性来源并链接 | 如果声明对您的工作至关重要，请检查来源链接 |
| **PLAUSIBLE** | 与一般知识一致，未找到具体来源 | 将其视为合理但未经证实；如果依赖它做决定，请独立验证 |
| **UNVERIFIED** | 找不到支持性或矛盾的证据 | 在没有独立验证的情况下不要依赖此声明 |
| **DISPUTED** | 从可信来源找到矛盾证据 | 查看矛盾来源；此声明可能错误 |
| **FABRICATION RISK** | 匹配幻觉模式（例如，找不到的引用、无来源的精确统计数据） | 假设这是错误的，直到您从主要来源确认 |

### 报告原则

- 提供链接，而不是裁决。用户决定什么是真实的，不是您。
- 当您找到矛盾信息时，提供双方来源。不要选赢家。
- 如果声明无法证伪（过于模糊或主观无法验证），请说明。 "无法证伪"是有用信息。
- 明确说明您无法核查的内容。"我无法验证这个"与"这个是错误的"不同。
- 按严重程度分组发现。优先处理需要最多注意力的项目。

### 局限性披露

始终在报告末尾包含此内容：

> **此验证的局限性：**
> - 此工具加速了人工验证；它不能取代人工验证。
> - 网络搜索结果可能不包括最新信息或受密码保护的来源。
> - 对抗性审查使用与可能生成原始输出的相同底层模型。它捕获了许多问题，但并不能捕获所有问题。
> - 评级为 VERIFIED 的声明意味着找到了支持性来源，而不是声明一定正确。来源也可能错误。
> - 评级为 PLAUSIBLE 的声明仍可能错误。没有矛盾证据不是准确的证明。

## 特定领域指导

### 法律内容

法律内容由于以下原因存在更高的幻觉风险：
- 模型经常编造案例名称、引用和判决
- 司法管辖区的细微差别经常被简化或省略
- 法律条文可能以改变法律意义的方式被释义
- "多数意见"和"少数意见"的区别经常丢失

对于法律内容，请特别审查：案例引用、法律条文引用、法规解释和司法管辖权声明。在可能的情况下，搜索法律数据库。

### 医疗和科学内容

- 确认引用的研究确实存在，并且结果被准确描述
- 注意过时的指南被呈现为当前的
- 标记剂量、治疗方案或诊断标准——这些会变化，错误可能很危险

### 金融和监管内容

- 验证具体金额、日期和阈值
- 确认监管要求归因于正确的司法管辖区并且是当前的
- 注意可能因最近的立法变化而过时的税法声明

### 技术和安全内容

- 验证 CVE 编号、漏洞描述和受影响版本
- 确认 API 规范和配置说明与当前文档匹配
- 注意可能过时的特定版本信息
