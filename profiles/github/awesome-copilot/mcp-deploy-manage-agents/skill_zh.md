# 部署和管理基于 MCP 的代理

使用管理中心在 Microsoft 365 中部署、管理和治理基于 MCP 的声明式代理，以实现组织分布和控制。

## 代理类型

### 由组织发布
- 使用预定义的指令和操作构建
- 遵循结构化逻辑以实现可预测的任务
- 需要管理员批准和发布流程
- 支持合规性和治理要求

### 由创建者共享
- 在 Microsoft 365 Copilot Studio 或 Agent Builder 中创建
- 直接与特定用户共享
- 通过搜索、操作、连接器和 API 增强功能
- 在代理注册表中对管理员可见

### Microsoft 代理
- 由 Microsoft 开发和维护
- 与 Microsoft 365 服务集成
- 预批准并可直接使用

### 外部合作伙伴代理
- 由经过验证的外部开发人员/供应商创建
- 需要管理员批准和控制
- 可配置可用性和权限

### 前沿代理
- 具有实验性或高级功能
- 可能需要有限的发布或额外的监督
- 示例：
  - **App Builder 代理**：通过 M365 Copilot 或 Power Platform 管理中心管理
  - **Workflows 代理**：通过 Power Platform 管理中心管理的流程自动化

## 管理员角色和权限

### 必需角色
- **AI 管理员**：完整的代理管理功能
- **全局读取器**：仅查看访问权限（无编辑权限）

### 最佳实践
- 使用权限最少的角色
- 限制全局管理员仅用于紧急情况
- 遵循最小权限原则

## 在 Microsoft 365 管理中心管理代理

### 访问代理管理
1. 前往 [Microsoft 365 管理中心](https://admin.microsoft.com/)
2. 导航到 **代理** 页面
3. 查看可用、已部署或被阻止的代理

### 可用操作

**查看代理**
- 按可用性（可用、已部署、被阻止）筛选
- 搜索特定代理
- 查看代理详细信息（名称、创建者、日期、托管产品、状态）

**部署代理**
分发选项：
1. **代理商店**：提交到 Partner Center 进行验证和公开可用
2. **组织部署**：IT 管理员部署给所有或选定的员工

**管理代理生命周期**
- **发布**：使代理对组织可用
- **部署**：分配给特定用户或组
- **阻止**：防止代理被使用
- **移除**：从组织中删除代理

**配置访问**
- 为特定用户组设置可用性
- 按代理管理权限
- 控制哪些代理在 Copilot 中显示

## 部署工作流

### 发布到组织

**对于代理开发人员：**
1. 使用 Microsoft 365 代理工具包构建代理
2. 在开发环境中彻底测试
3. 提交代理以供批准
4. 等待管理员审核

**对于管理员：**
1. 在管理中心审查提交的代理
2. 验证合规性和安全性
3. 批准组织使用
4. 配置部署设置
5. 发布给选定用户或整个组织

### 通过代理商店部署

**开发人员步骤：**
1. 完成代理开发和测试
2. 打包代理以供提交
3. 提交到 Partner Center
4. 等待验证过程
5. 接收批准通知
6. 代理出现在 Copilot 商店

**管理员步骤：**
1. 在 Copilot 商店发现代理
2. 审查代理详细信息和权限
3. 分配给组织或用户组
4. 监控使用情况和反馈

### 部署组织代理

**管理员部署选项：**
```
组织范围：
- 所有具有 Copilot 许可的员工
- 自动在 Copilot 中可用

基于组：
- 特定部门或团队
- 安全组分配
- 基于角色的访问控制
```

**配置步骤：**
1. 在管理中心导航到代理页面
2. 选择要部署的代理
3. 选择部署范围：
   - 所有用户
   - 特定的安全组
   - 单个用户
4. 设置可用性状态
5. 如适用，配置权限
6. 部署并监控

## 治理和合规性

### 安全考虑
- **数据访问**：审查代理可以访问哪些数据
- **API 权限**：验证所需的范围
- **身份验证**：确保安全的 OAuth 流程
- **外部连接**：评估外部集成的风险

### 合规性要求
- **数据驻留**：验证数据是否保持在边界内
- **隐私政策**：审查代理隐私声明
- **使用条款**：验证可接受使用政策
- **审计日志**：监控代理使用和活动

### 监控和报告
跟踪：
- 代理采用率
- 用户反馈和满意度
- 错误率和性能
- 安全事件或违规行为

## MCP 特定管理

### MCP 代理特征
- 通过模型上下文协议连接外部系统
- 使用 MCP 服务器暴露的工具
- 需要 OAuth 2.0 或 SSO 身份验证
- 支持与 REST API 代理相同的治理

### MCP 代理验证
验证：
- MCP 服务器 URL 是否可访问
- 身份验证配置是否安全
- 导入的工具是否适当
- 响应数据是否暴露敏感信息
- 服务器是否遵循安全最佳实践

### MCP 代理部署
与 REST API 代理相同的过程：
1. 在管理中心审查
2. 验证 MCP 服务器合规性
3. 测试身份验证流程
4. 部署给用户/组
5. 监控性能

## 代理设置和配置

### 组织设置

### 每个代理设置

- 通过 Power Platform 管理中心管理流程

## 最佳实践

### 部署前
- **试点测试**：与小型用户组测试
- **收集反馈**：从早期采用者获取反馈
- **验证安全**：验证合规性
- **文档**：记录代理功能和限制
- **培训用户**：培训代理使用方法

### 部署期间
- **分阶段发布**：管理采用情况
- **监控性能**：监控错误
- **持续收集反馈**：持续收集反馈
- **及时解决问题**：及时解决问题
- **通知用户**：通知用户可用性

### 部署后
- **跟踪指标**：采用率、满意度、错误
- **迭代**：根据反馈改进
- **更新**：保持代理与最新功能同步
- **淘汰**：移除过时或未使用的代理
- **审查**：定期进行安全和合规性审计

### 沟通
- 向用户宣布新代理
- 提供文档和示例
- 分享最佳实践和用例
- 突出显示功能和优势
- 提供支持渠道

## 故障排除

### 代理未出现
- 在管理中心检查部署状态
- 验证用户是否在分配组中
- 确认代理未被阻止
- 确认用户具有 Copilot 许可
- 刷新 Copilot 界面

### 身份验证失败
- 验证 OAuth 凭据是否有效
- 检查用户是否具有必要权限
- 确认 MCP 服务器是否可访问
- 独立测试身份验证流程

### 性能问题
- 监控 MCP 服务器响应时间
- 检查网络连接
- 在管理中心审查错误日志
- 验证代理是否被限流

### 合规性违规
- 如果不安全，立即阻止代理
- 审查审计日志以查找违规行为
- 调查数据访问模式
- 更新策略以防止再次发生
