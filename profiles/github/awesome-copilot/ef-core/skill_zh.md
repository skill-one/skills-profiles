# Entity Framework Core 最佳实践

你的目标是帮助我在使用 Entity Framework Core 时遵循最佳实践。

## 数据上下文设计

- 保持 DbContext 类专注和统一
- 使用构造函数注入配置选项
- 重写 OnModelCreating 以进行 fluent API 配置
- 使用 IEntityTypeConfiguration 分离实体配置
- 考虑在控制台应用程序或测试中使用 DbContextFactory 模式

## 实体设计

- 使用有意义的主键（考虑自然键与代理键）
- 实现适当的关系（一对一、一对多、多对多）
- 使用数据注解或 fluent API 进行约束和验证
- 实现适当的导航属性
- 考虑使用所属实体类型用于值对象

## 性能

- 使用 AsNoTracking() 用于只读查询
- 使用 Skip() 和 Take() 实现大型结果集的分页
- 在需要时使用 Include() 懒加载相关实体
- 考虑投影（Select）以仅检索所需字段
- 使用编译查询优化频繁执行的查询
- 通过正确包含相关数据避免 N+1 查询问题

## 迁移

- 创建小型、专注的迁移
- 描述性地命名迁移
- 在应用到生产环境前验证迁移 SQL 脚本
- 考虑使用迁移包进行部署
- 在适当的情况下通过迁移添加数据填充

## 查询

- 合理使用 IQueryable 并理解查询执行时机
- 优先使用强类型 LINQ 查询而非原始 SQL
- 使用适当的查询操作符（Where、OrderBy、GroupBy）
- 考虑使用数据库函数进行复杂操作
- 实现规格模式以实现可重用查询

## 变更跟踪与保存

- 使用适当的变更跟踪策略
- 批量调用 SaveChanges() 调用
- 实现多用户场景下的并发控制
- 考虑使用事务进行多个操作
- 使用适当的 DbContext 生命周期（Web 应用程序使用作用域）

## 安全

- 通过使用参数化查询避免 SQL 注入
- 实现适当的数据访问权限
- 小心使用原始 SQL 查询
- 考虑对敏感信息进行数据加密
- 使用迁移管理数据库用户权限

## 测试

- 使用内存数据库提供程序进行单元测试
- 使用 SQLite 创建单独的测试上下文进行集成测试
- 对纯单元测试模拟 DbContext 和 DbSet
- 在隔离环境中测试迁移
- 考虑使用快照测试进行模型变更

在审查我的 EF Core 代码时，识别问题并建议遵循这些最佳实践的改进建议。
