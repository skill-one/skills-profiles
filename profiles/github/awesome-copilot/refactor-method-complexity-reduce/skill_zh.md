# 重构方法以降低认知复杂度

## 目标
重构`${input:methodName}`方法，通过将逻辑提取到专注的辅助方法中，将其认知复杂度降低至`${input:complexityThreshold}`或以下。

## 指令

1. **分析当前方法**以识别认知复杂度的来源：
   - 嵌套的条件语句
   - 多个if-else或switch链
   - 重复的代码块
   - 带条件的多个循环
   - 复杂的布尔表达式

2. **识别提取机会**：
   - 可提取到单独方法的验证逻辑
   - 重复的类型特定或情况特定的处理
   - 复杂的转换或计算
   - 多次出现的常见模式

3. **提取专注的辅助方法**：
   - 每个辅助方法应具有单一、清晰的责任
   - 将验证提取到单独的`Validate*`方法中
   - 将类型特定逻辑提取到处理方法中
   - 为常见操作创建工具方法
   - 使用适当的访问级别（静态、私有、异步）

4. **简化主方法**：
   - 减少嵌套深度
   - 用较小的协调调用替换庞大的if-else链
   - 在适当的地方使用switch语句进行更清晰的调度
   - 确保主方法读取为高级流程

5. **保持功能**：
   - 维持相同的输入/输出行为
   - 保留所有验证和错误处理
   - 保留异常类型和错误消息
   - 确保所有参数正确传递给辅助方法

6. **最佳实践**：
   - 当不需要实例状态时，将辅助方法设为静态
   - 早期使用空值检查和守卫子句
   - 避免创建不必要的局部变量
   - 考虑使用元组进行多个返回值
   - 将相关的辅助方法组合在一起

## 实现方法

- 在重构主流程之前提取辅助方法
- 逐步测试以确保没有回归
- 使用描述提取责任的含义丰富的名称
- 将提取的方法保持在它们使用的地方附近
- 考虑将重复的代码模式转换为通用方法

## 结果

重构后的方法应：
- 将认知复杂度降低至目标阈值`${input:complexityThreshold}`或以下
- 更易于阅读和维护
- 具有清晰的关注点分离
- 更易于测试和调试
- 保留所有原始功能

## 测试和验证

**关键：完成重构后，你必须：**

1. **运行所有与重构方法及其周围功能相关的现有测试**
2. **强制：显式验证测试结果显示"failed=0"**
   - **永远不要假设测试通过** - 始终检查实际的测试输出
   - 搜索包含通过/失败计数的摘要行（例如，"passed=X failed=Y"）
   - **如果摘要显示任何数字而不是"failed=0"，则测试已失败**
   - 如果测试输出在文件中，读取整个文件以定位并验证失败计数
   - 运行测试与验证测试通过不是一回事
   - **在确认零失败之前不要继续**
3. **如果有任何测试失败（failed > 0）：**
   - 清晰说明失败的测试数量
   - 分析每个失败以了解被破坏的功能
   - 常见原因：空值处理、空集合检查、条件逻辑错误
   - 在重构代码中识别根本原因
   - 修正重构代码以恢复原始行为
   - 重新运行测试并在输出中验证"failed=0"
   - 重复直到所有测试通过（failed=0）
4. **验证编译** - 确保没有编译错误
5. **检查认知复杂度** - 确认指标在目标阈值`${input:complexityThreshold}`或以下

- [ ] 代码遵循项目约定和标准
