# 创建 GitHub Actions 工作流规范

为 GitHub Actions 工作流创建全面的规范：`${input:WorkflowFile}`。

此规范作为工作流行为、需求和约束的规范。它必须是实现无关的，专注于工作流**完成什么**，而不是**如何**实现。

## AI 优化要求

- **令牌效率**：使用简洁的语言，不牺牲清晰度
- **结构化数据**：利用表格、列表和图表展示密集信息
- **语义清晰**：在整个规范中始终使用精确的术语
- **实现抽象**：避免特定语法、命令或工具版本
- **可维护性**：设计易于更新，以适应工作流演变

## 分析说明

当分析工作流文件时：

1. **提取核心目的**：识别主要业务目标
2. **映射任务流程**：创建显示执行顺序的依赖关系图
3. **识别契约**：记录输入、输出和接口
4. **捕获约束**：提取超时、权限和限制
5. **定义质量门禁**：识别验证和批准点
6. **记录错误路径**：映射失败场景和恢复操作
7. **抽象实现**：关注行为，而不是语法

## Mermaid 图表指南

### 流程类型
- **顺序**：`A --> B --> C`
- **并行**：`A --> B & A --> C; B --> D & C --> D`
- **条件**：`A --> B{决策}; B -->|是| C; B -->|否| D`

### 样式
```mermaid
style TriggerNode fill:#e1f5fe
style SuccessNode fill:#e8f5e8
style FailureNode fill:#ffebee
style ProcessNode fill:#f3e5f5
```

### 复杂工作流
对于包含 5 个以上任务的工作流，使用子图：
```mermaid
graph TD
    subgraph "构建阶段"
        A[Lint] --> B[Test] --> C[构建]
    end
    subgraph "部署阶段"  
        D[测试环境] --> E[生产环境]
    end
    C --> D
```

## 令牌优化策略

1. **使用表格**：以结构化格式展示密集信息
2. **一致缩写**：一次定义，全程使用
3. **项目符号**：避免散文段落
4. **代码块**：结构化数据胜过叙述
5. **交叉引用**：链接而不是重复信息

专注于创建一个规范，它既作为文档，也作为工作流更新的模板。
