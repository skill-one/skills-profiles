# 产品驱动增长

构建自助获取和扩展动量。但首先，要弄清楚PLG（产品驱动增长）是否真的是适合你产品的正确动量。

## 何时使用

**触发因素：**
- "我们应该构建PLG还是销售驱动？"
- "我们如何推动自助获取的采用？"
- "免费增值到付费的转换效果不佳"
- "开发者驱动的采用策略"
- "我们应该投资哪些增长渠道？"
- "我如何知道PLG是否有效？"

**背景：**
- 开发者工具和平台
- 具有自助获取潜力的B2B SaaS
- 价值无需演示就能明显的产品
- 自下而上的采用动量
- 增长渠道优先级

---

## 核心框架

### 1. PLG现实检验（在投入之前进行测试）

**并行运行两种动量的经验教训：**

经典的创业辩论。PLG阵营："开发者想要自助服务。" 销售阵营："企业需要手把手指导。" 我们没有争论，而是测试了两种方式6个月。相同的产品，两种GTM（市场进入）动量，跟踪了所有数据。

**结果：**

PLG：高销量，低ACV（平均客户价值，约$5K），快速实现收入，更高的流失率。销售驱动：低销量，高ACV（约$50K），较慢的收入实现速度，较低的流失率。**尽管销量只有PLG的十分之一，销售在收入上赢了10倍。**

**原因：** 产品复杂性 + 买方资历 = 销售驱动获胜。该产品需要与现有基础设施集成，跨团队变更管理，以及多利益相关者的协调。开发者喜欢自助服务。但他们不是经济买方。

**PLG在以下情况下有效：**
- 价值在5分钟内就明显
- 实施非常简单
- 个人用户无需团队认可就能获得价值
- 无采购/法律障碍
- 买方 = 用户

**销售驱动在以下情况下有效：**
- 产品需要集成/设置
- 多个利益相关者需要协调
- 买方 ≠ 用户
- 交易规模证明需要人工接触
- 客户需要教育才能看到价值

**在构建PLG之前，测试你的动量。不要假设PLG更好，因为它很时髦。** PLG在销量上很高效，但销售驱动在复杂性上可以更有利可图。

### 2. 增长公式（将输入映射到输出）

**模式：**

当您系统化活动与用户获取之间的关系时，增长会复合。不是"多做营销"——而是将特定的输入映射到可衡量的输出。

**如何构建您的增长公式：**

对于每个渠道，定义：活动（输入）→ 流量（输出）→ 转化。

- **有机搜索：** 1篇高质量博客文章 → 每月400名用户 → 5%转化 = 20名新用户
- **付费广告：** $1K支出，在100K次展示中8%的转化率 = 8K次点击 → 转化率在X%
- **社区活动：** 1次活动 → 60名参与者 → 35%转化 = 21名用户
- **推荐：** 1个集成合作伙伴 → N名推荐用户 → 转化率在Y%

**为什么这很重要：**

一旦您验证了公式，扩展就变成了数学问题。"下个月我需要200名更多用户" → "我需要10篇更多博客文章"或"我需要$5K更多广告支出。" 没有公式，您只是在猜测。

**测试公式：**

1. 从假设开始："如果我创建X，它推动Y转化"
2. 用小样本测试：1篇博客文章，测量实际转化率
3. 验证：现实是否与假设相符？
4. 有信心地扩展：如果是，增加输入
5. 如果不是，放弃：4周的数据足以做出决定

**常见错误：**

在未测试的情况下猜测转化率。假设来自同一渠道的所有用户质量相同。在验证公式之前扩展。

---

### 3. 渠道经济（淘汰失败者，加倍投入成功者）

**模式：**

每个渠道都有其经济性。如果不跟踪它们，您会过度投资于失败者，而低估成功者。

**按渠道跟踪：**
1. **CAC：** 总支出/新用户
2. **转化率：** 注册 → 付费
3. **留存率：** 30天，90天按来源
4. **LTV：** 客户生命周期内的收入，按渠道
5. **回收期：** 需要多长时间才能收回CAC

**决策框架：**

- CAC < (LTV × 利润率) → 积极扩展
- CAC ≈ (LTV × 利润率) → 优化，不要扩展
- CAC > (LTV × 利润率) → 4周内淘汰

**月度渠道审查：** 哪些渠道是盈利的？哪些是消耗的？季度重新分配：将3倍预算分配给成功者，淘汰失败者。

**关键洞察：渠道质量不同**

低CAC不意味着好CAC。有机搜索可能以$0 CAC提供用户，30天留存率为85%。付费搜索可能以$12 CAC提供用户，30天留存率为45%。当您考虑留存率和LTV时，"免费"渠道的价值是10倍。

**系统化测试：**

每月测试2个新渠道。给每个渠道4周的数据。如果经济性不工作，果断淘汰。无论结果如何，都要记录学习成果——失败的价值与成功一样重要。

**常见错误：**

跟踪CAC而不跟踪留存率。一个廉价的渠道流失用户，成本高于一个昂贵的渠道保留用户。

---

### 4. 首次价值时间（唯一激活指标）

**模式：**

用户在5-10分钟内决定产品价值。如果他们不能快速达到"啊哈时刻"，他们会放弃。

**激活审查：**

1. 以新用户身份注册您自己的产品
2. 计算达到首次价值所需的时间
3. 计算达到"啊哈时刻"的步骤数
4. 您在哪里卡住了？

**如果TTFV > 10分钟，您有一个激活问题。**

**之前：** 注册 → 确认电子邮件 → 填写个人资料 → 配置设置 → 阅读文档 → 首次操作

**之后：** 注册 → 预加载样本数据 → 首次操作（立即的"啊哈时刻"）

**具体修复措施：**

1. **预加载样本数据。** 用户想要看到价值，而不是设置。立即给他们一个可工作的示例。
2. **跳过非必要的设置。** 电子邮件确认，个人资料，设置——所有这些都可以在"啊哈时刻"之后等待。
3. **渐进式披露。** 不要一开始就显示所有功能。从一个核心工作流程开始。逐渐揭示复杂性。
4. **展示，而不是告诉。** 交互式教程 > 视频 > 文本文档。让他们点击一个工作流程。

**常见错误：**

假设用户会阅读文档。他们不会。他们会点击5分钟，如果什么都不工作，他们就会离开。

---

### 5. $5K → $50K拐点（当PLG失效时）

**模式：**

PLG适用于$1K-$10K ARR（年度收入）。在$20K-$50K之间，动量会失效，因为组织摩擦开始出现：采购，法律，安全，多利益相关者的认可。

**混合方法：**

**PLG ($0-$10K)：** 自助注册 → 免费层 → 付费层 → 信用卡结账 → 自动化入职

**销售辅助 ($10K-$50K)：** 自助发现 → 销售在用法信号上参与 → 人工协商合同 → 专属入职

**企业 ($50K+)：** 外出或传入线索 → 演示 → POC（概念验证）→ 报价 → 法律/安全审查 → 高管支持

**PQL信号（何时触发销售）：**

- **使用深度：** 每日活跃，使用核心功能，接近限制
- **扩展信号：** 来自同一公司的多个用户，团队功能，集成
- **购买信号：** 对SSO/合规/SLA的请求，询问团队定价

**交接：**

差： "嘿，我看到了你注册了。"（冷，通用，破坏信任）
好："您的团队正在使用[特定功能]跨12个仓库。我们可以帮助您[特定价值]。需要15分钟吗？"（热，具体，提供价值）

**常见错误：**

在<$5K交易上过早参与销售。破坏PLG动量，吓跑用户。让他们自助服务，直到他们需要帮助。

### 6. 增长预测（为不确定性做计划）

**模式：**

预测总是错误的。计划仍然有价值，因为它们迫使思考并创造责任感。

**建立三种情景：**

**基准（当前趋势继续）：**
- 有机搜索：35%增长 → 40K新用户
- 付费：持平 → 2K新用户
- 社区：10%增长 → 400新用户
- 总计：42.4K

**上行（如果所有增长计划执行）：**
- 有机：50%增长（3倍内容）→ 48K
- 付费：2倍支出，相同效率 → 4K
- 新计划（合作伙伴关系）：加速 → 3K
- 总计：55K

**下行（如果关键渠道失败）：**
- 有机：0%增长 → 26K
- 付费：CPA（每次行动成本）翻倍 → 1K
- 总计：27K

**使用此进行：**
- 设置基准目标（基准情景）
- 拉伸目标（上行情景）
- 升级触发器（如果遇到下行，需要改变）
- 资源分配（什么输入改变以实现上行？）

**月度更新：** 比较预测与实际。调整模型。不要预测然后忘记。

**常见错误：**

过于乐观的预测，假设一切都会成功。不每月更新。将预测视为目标（它是一个范围，不是数字）。

---

### 7. 演本文档习惯

**模式：**

知识会随人流失。目标不是一次性成功——而是系统化有效的方法。

**每次成功的活动或实验后，编写1页剧本：**

```
剧本：[渠道/策略名称]

目标：[结果]
步骤：[编号，足够详细，供不熟悉的人执行]
预期输出：[具体指标]
要跟踪的指标：[如何衡量]
风险和缓解措施：[可能出什么问题]
负责人：[姓名]
最后更新：[日期]
```

**测试：** 参与者是否可以执行这个剧本？如果不能，它太模糊了。

**每季度审查。** 删除不再有效的剧本。更新已经演变的剧本。这将成为您的增长操作系统。

**常见错误：**

运行实验而不记录学习成果。在理解机制之前扩展。增长知识被锁定在一个人的头脑中。

## 决策树

### 我们应该构建PLG还是销售驱动？

```
用户在<10分钟内能获得价值吗？没有文档？
├─ 否 → 需要销售驱动
└─ 是 → 他们能自助服务实施吗？
    ├─ 否 → 需要销售驱动
    └─ 是 → 买方 = 用户吗？
        ├─ 否 → 混合（PLG + 销售辅助）
        └─ 是 → 纯PLG可行
```

### 保留、扩展或淘汰这个渠道？

```
CAC < (LTV × 利润率)？
├─ 否 → 4周内淘汰
└─ 是 → 90天留存率 > 60%？
    ├─ 否 → 优化（改进激活/入职）
    └─ 是 → 积极扩展（3倍预算）
```

---

## 常见错误

**1. 假设PLG总是有效**
产品复杂性 + 买方资历 = 销售驱动获胜。测试后再投入。

**2. 没有渠道经济**
每个渠道都有CAC，留存率和LTV。跟踪它们或您在盲目飞行。

**3. 免费层太慷慨或太有限**
太慷慨：没有转化。太有限：没有激活。允许10-20个"啊哈时刻"。

**4. 没有增长公式**
"多做营销"不是一个策略。将输入映射到输出 → 每个渠道的转化。

**5. 在验证之前扩展**
任何渠道4周的数据后再扩展。如果经济性不工作，果断淘汰。

**6. 增长知识在一个人的头脑中**
将每个成功的实验记录为剧本。

## 快速参考

**PLG准备就绪：** 价值在<10分钟 + 自助服务实施 + 买方 = 用户

**增长公式：** 活动（输入）→ 流量（输出）→ 转化，每个渠道

**渠道经济：** CAC，转化率，30/90天留存率，LTV，回收期——每个渠道，每月审查

**淘汰标准：** CAC > (LTV × 利润率) → 4周内改进，然后淘汰

**PQL信号：** 使用深度 + 扩展（多用户）+ 购买（SSO/合规请求）

**销售交接：** <$10K：PLG → $10K-$50K：销售辅助 → >$50K：完整销售

**预测：** 基准 + 上行 + 下行，每月更新
