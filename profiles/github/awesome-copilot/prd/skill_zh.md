# 产品需求文档（PRD）

## 概述

设计全面、适用于生产环境的产品需求文档（PRD），以弥合商业愿景与技术执行之间的差距。这项技能适用于现代软件系统，确保需求得到清晰定义。

## 使用场景

在以下情况下使用此技能：

- 开始新的产品或功能开发周期
- 将模糊的想法转化为具体的技术规范
- 定义人工智能驱动功能的需求
- 利益相关者需要一个统一的项目范围“事实来源”
- 用户要求“编写PRD”、“记录需求”或“规划功能”

---

## 运作工作流程

### 第一阶段：发现（访谈）

在编写PRD的每一行之前，你必须**必须**向用户提问以填补知识空白。不要假设上下文。

**询问关于：**

- **核心问题**：我们现在为什么要构建这个？
- **成功指标**：我们如何知道它有效？
- **限制条件**：预算、技术栈或截止日期？

### 第二阶段：分析与范围界定

综合用户的输入。识别依赖关系和隐藏的复杂性。

- 绘制**用户流程**。
- 定义**非目标**以保护时间表。

### 第三阶段：技术草拟

使用以下**严格的PRD架构**生成文档。

---

## PRD质量标准

### 需求质量

使用具体、可衡量的标准。避免使用“快速”、“简单”或“直观”。

```diff
# 模糊（BAD）
- 搜索应该快速并返回相关结果。
- 界面必须看起来现代且易于使用。

# 具体（GOOD）
+ 搜索必须在200ms内返回10k记录数据集的结果。
+ 搜索算法必须在基准评估中实现>=85%的Precision@10。
+ 界面必须遵循'Vercel/Next.js'设计系统，并实现100%的Lighthouse可访问性分数。
```

---

## 严格的PRD架构

你必须遵循以下精确结构进行输出：

### 1. 执行摘要

- **问题陈述**：关于痛点的一两句话。
- **建议解决方案**：关于修正的一两句话。
- **成功标准**：3-5个可衡量的KPI。

### 2. 用户体验与功能

- **用户画像**：这是为谁设计的？
- **用户故事**：`作为一个[用户]，我想[行动]以便[收益]。`
- **验收标准**：每个故事的“完成”定义的要点列表。
- **非目标**：我们不在构建什么？

### 3. 人工智能系统需求（如适用）

- **工具需求**：需要哪些工具和API？
- **评估策略**：如何衡量输出质量和准确性。

### 4. 技术规范

- **架构概述**：数据流和组件交互。
- **集成点**：API、数据库和认证。
- **安全与隐私**：数据处理和合规性。

### 5. 风险与路线图

- **分阶段发布**：MVP -> v1.1 -> v2.0。
- **技术风险**：延迟、成本或依赖失败。

---

## 实施指南

### 必须做（始终）

- **定义测试**：对于人工智能系统，指定如何测试和验证输出质量。
- **迭代**：展示草稿并请求对特定部分的反馈。

### 不要做（避免）

- **跳过发现**：在至少问两个澄清问题之前，永远不要编写PRD。
- **臆断限制条件**：如果用户没有指定技术栈，请询问或将其标记为`TBD`。

## 示例：智能搜索系统

### 1. 执行摘要

**问题**：用户难以在庞大的存储库中找到特定的文档片段。
**解决方案**：一个智能搜索系统，提供直接答案并附带来源引用。
**成功**：

- 将搜索时间减少50%。
- 引用准确率>=95%。

### 2. 用户故事

- **故事**：作为一个开发者，我想问自然语言问题，这样我就不用猜测关键词了。
- **AC**：
  - 支持多轮澄清。
  - 返回带有“复制”按钮的代码块。

### 3. 人工智能系统架构

- **所需工具**：`codesearch`、`grep`、`webfetch`。

### 4. 评估

- **基准测试**：使用50个常见的开发者问题进行测试。
- **通过率**：90%必须与预期的引用匹配。
