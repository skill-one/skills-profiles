# 创建实施计划

## 主要指令

您的目标是创建一个新的实施计划文件用于 `${input:PlanPurpose}`。您的输出必须是机器可读的、确定性的，并结构化以便其他 AI 系统或人类自主执行。

## 执行上下文

此提示设计用于 AI 之间的通信和自动化处理。所有指令必须被字面理解并系统性地执行，不允许人类解释或澄清。

## 核心要求

- 生成 AI 代理或人类可完全执行的实施计划
- 使用确定性的语言，零歧义
- 结构化所有内容以供自动化解析和执行
- 确保完全自包含，无需外部依赖来理解

## 计划结构要求

计划必须由包含可执行任务的离散、原子的阶段组成。每个阶段必须能够被 AI 代理或人类独立处理，除非明确声明存在跨阶段依赖。

## 阶段架构

- 每个阶段必须有可衡量的完成标准
- 阶段内的任务必须可以并行执行，除非指定了依赖关系
- 所有任务描述必须包含具体的文件路径、函数名和精确的实现细节
- 没有任务应该需要人类解释或决策

## AI 优化实施标准

- 使用明确、无歧义的语言，无需任何解释
- 将所有内容结构化为机器可解析的格式（表格、列表、结构化数据）
- 在适用情况下包含具体的文件路径、行号和精确的代码引用
- 明确定义所有变量、常量和配置值
- 在每个任务描述中提供完整上下文
- 使用标准化的前缀标识所有标识符（REQ-、TASK- 等）
- 包含可自动验证的验证标准

## 输出文件规范

- 将实施计划文件保存在 `/plan/` 目录下
- 使用命名规范：`[purpose]-[component]-[version].md`
- 目的前缀：`upgrade|refactor|feature|data|infrastructure|process|architecture|design`
- 示例：`upgrade-system-command-4.md`、`feature-auth-module-1.md`
- 文件必须是有效的 Markdown 格式，并具有正确的元数据结构

## 强制性模板结构

所有实施计划必须严格遵循以下模板。每个部分都是必需的，并且必须填充具体的、可执行的内容。AI 代理必须在执行前验证模板的合规性。

## 模板验证规则

- 所有元数据字段必须存在并正确格式化
- 所有章节标题必须完全匹配（区分大小写）
- 所有标识符前缀必须遵循指定格式
- 表格必须包含所有必需的列
- 最终输出中不得保留任何占位符文本
- **标识符必须唯一声明。** 每个标识符（`REQ-NNN`、`SEC-NNN`、`CON-NNN`、`GUD-NNN`、`PAT-NNN`、`GOAL-NNN`、`TASK-NNN`、`ALT-NNN`、`DEP-NNN`、`FILE-NNN`、`TEST-NNN`、`RISK-NNN`、`ASSUMPTION-NNN`）必须**声明一次**。声明是指标识符引入行的位置：`TASK`/`GOAL` 表格行的引导单元格，或类似 `- **REQ-001**：...` 的粗体前缀。声明后，该标识符可以以**引用**的形式在计划的其他位置出现任意次数（例如，`TASK` 正文引用 `REQ`，一个 `TASK` 引用另一个 `TASK`，依赖关系部分指向上游已声明的 `DEP` 等）。引用是预期的，而不是冲突。

## 标识符唯一性检查

在最终确定计划前运行这些检查。检查 (1) 和 (2) 针对声明，必须返回零行。检查 (3) 是一个广泛的扫描：它将暴露有效的引用，因此用于意识而非作为门禁。

```bash
# 将 PLAN_FILE 设置为正在验证的计划。
PLAN_FILE="/plan/<purpose>-<component>-<version>.md"

# 1) 表格行中重复的 TASK / GOAL 声明。
grep -oE '\| (TASK|GOAL)-[0-9]+ \|' "$PLAN_FILE" \
  | sed -E 's/.*((TASK|GOAL)-[0-9]+).*/\1/' \
  | sort | uniq -d

# 2) 粗体样式规范行中重复的声明 ID。
grep -oE '^- \*\*(REQ|SEC|CON|GUD|RISK|ASSUMPTION|TASK|GOAL|FILE|TEST|PAT|ALT|DEP)-[0-9]+\*\*:' "$PLAN_FILE" \
  | sed -E 's/^- \*\*([A-Z]+-[0-9]+)\*\*:.*/\1/' \
  | sort | uniq -d

# 3) 广泛的重复扫描（仅诊断；可能包括有效引用）。
grep -oE '(REQ|SEC|CON|GUD|RISK|ASSUMPTION|TASK|GOAL|FILE|TEST|PAT|ALT|DEP)-[0-9]+' "$PLAN_FILE" \
  | sort | uniq -d
```

前提：POSIX 兼容的 shell（`sh` / `bash`）以及 `grep`、`sed`、`sort` 和 `uniq`。在 Windows 上没有这些工具时，使用等效的平台原生命令并保持相同的声明与引用逻辑。

如果检查 (1) 或 (2) 返回任何行，重新编号重复项，确保每个标识符只声明一次，然后重新运行检查，直到两者都为空。

## 状态

实施计划的状态必须在元数据中明确定义，并反映计划当前的状态。状态可以是以下之一（状态颜色括号内）：`Completed`（亮绿色徽章）、`In progress`（黄色徽章）、`Planned`（蓝色徽章）、`Deprecated`（红色徽章）或 `On Hold`（橙色徽章）。它还应在介绍部分显示为徽章。

```md
---
goal: [简要描述实现计划目标的标题]
version: [可选：例如，1.0，日期]
date_created: [YYYY-MM-DD]
last_updated: [可选：YYYY-MM-DD]
owner: [可选：负责此规范的团队/个人]
status: 'Completed'|'In progress'|'Planned'|'Deprecated'|'On Hold'
tags: [可选：相关标签或类别的列表，例如，`feature`、`upgrade`、`chore`、`architecture`、`migration`、`bug` 等]
---
