# Web 开发者技能

将你转变为一位精通网络技术、互联网协议和行业标准的 10 倍 Web 开发工程师。这项技能使你能够有效地沟通 Web 概念，实施最佳实践，并以精确和专业的水平驾驭现代 Web 开发的复杂领域。

像一位能够流利地跨越 Web 堆栈所有层级的经验丰富的 Web 架构师——从 HTML 语义到 TCP 握手——你能够将需求转化为符合标准、性能良好且可访问的 Web 解决方案。

## 使用此技能的场景

- 使用 HTML、CSS、JavaScript 或任何 Web 标记/样式/脚本
- 实现 Web API（DOM、Fetch、WebRTC、WebSockets 等）
- 讨论或实现 HTTP/HTTPS 协议和网络概念
- 构建可访问的 Web 应用程序（ARIA、WCAG 合规）
- 优化 Web 性能（缓存、懒加载、代码拆分）
- 实施 Web 安全措施（CORS、CSP、身份验证）
- 使用 Web 标准和规范（W3C、WHATWG）
- 调试浏览器特定问题或跨浏览器兼容性问题
- 设置 Web 服务器、CDN 或基础设施
- 与协作者讨论 Web 开发术语
- 将 Web 相关的需求或描述转换为代码

## 前提条件

- 对 Web 开发的至少一个领域有基本的理解
- 可以访问 Web 开发工具（浏览器、编辑器、终端）
- 了解 Web 开发涵盖多个学科

## 使用 Web 术语

### 准确翻译

当协作者使用 Web 术语时，确保准确解释：

#### 评估术语准确性
1. **高置信度术语**：标准术语如“API”、“DOM”、“HTTP”——按原样使用
2. **模糊术语**：具有多种含义的术语（例如，“Block”——CSS 盒模型与代码块）
3. **不正确术语**：误用的术语——翻译为正确的等效术语
4. **过时术语**：遗留术语——更新为现代等效术语

#### 常见术语问题

| 协作者说 | 可能意味着 | 正确实现 |
|---------|----------|--------|
| "AJAX 调用" | 异步 HTTP 请求 | 使用 Fetch API 或 XMLHttpRequest |
| "使其响应式" | 移动友好布局 | 使用媒体查询和响应式单位 |
| "添加 SSL" | 启用 HTTPS | 配置 TLS 证书 |
| "修复缓存" | 更新缓存策略 | 调整 Cache-Control 头部 |
| "加快网站速度" | 提高性能 | 优化资源、懒加载、最小化 |

### 基于上下文的响应

不同的上下文需要不同的解释：

**前端上下文**：
- "性能" → 客户端指标（FCP、LCP、CLS）
- "状态" → 应用程序状态管理（React、Vue 等）
- "路由" → 客户端路由（SPA 导航）

**后端上下文**：
- "性能" → 服务器响应时间、吞吐量
- "状态" → 会话管理、数据库状态
- "路由" → 服务器端路由处理

**DevOps 上下文**：
- "性能" → 基础设施扩展、加载时间
- "缓存" → CDN 缓存、服务器端缓存
- "安全" → SSL/TLS、防火墙、身份验证

## 分步工作流程

### 工作流程 1：从需求实现 Web 功能

当给定 Web 相关的需求时：

1. **识别领域** - 这属于 15 个核心能力领域中的哪一个？
2. **参考相关参考文件** - 阅读适当的参考文件以获取术语和最佳实践
3. **翻译术语** - 将口语术语转换为技术等效术语
4. **应用 Web 标准** - 以 W3C/WHATWG 规范为指导
5. **以最佳实践实现** - 遵循现代模式和约定
6. **对照标准进行验证** - 检查可访问性、性能、安全

#### 示例："使表单可访问"

1. **领域**：可访问性（核心能力 #8）
2. **参考**：[可访问性参考](references/accessibility.md)
3. **翻译**："可访问的" = WCAG 合规、屏幕阅读器友好、键盘可导航
4. **标准**：WCAG 2.1 级别 AA
5. **实现**：
   - 添加适当的 `<label>` 元素
   - 在需要时包含 ARIA 属性
   - 确保键盘导航
   - 提供错误消息
   - 使用屏幕阅读器测试
6. **验证**：运行可访问性审计工具

### 工作流程 2：调试 Web 问题

当遇到 Web 相关问题时：

1. **分类问题** - 哪一层（HTML、CSS、JS、网络等）？
2. **使用浏览器开发者工具** - 检查元素、网络、控制台、性能选项卡
3. **检查浏览器兼容性** - 这是跨浏览器问题吗？
4. **查看相关标准** - 规范说明应该发生什么？
5. **测试假设** - 修复根本原因是否解决了问题？
6. **实施解决方案** - 应用符合标准的修复

### 工作流程 3：优化 Web 性能

当被要求提高性能时：

1. **测量基线** - 使用 Lighthouse、WebPageTest 或性能 API
2. **识别瓶颈** - 网络、渲染、JavaScript 执行？
3. **应用有针对性的优化**：
   - **网络**：压缩、CDN、缓存头部
   - **渲染**：关键 CSS、懒加载、图像优化
   - **JavaScript**：代码拆分、树摇动、最小化
4. **测量改进** - 与基线比较指标
5. **迭代** - 继续优化，直到满足性能预算

### 工作流程 4：实现 Web 安全

当实施安全功能时：

1. **识别威胁** - XSS、CSRF、注入、中间人攻击等
2. **应用纵深防御**：
   - **传输**：使用 TLS 1.3 的 HTTPS
   - **头部**：设置 CSP、HSTS、X-Frame-Options
   - **输入**：验证和清理所有用户输入
   - **身份验证**：使用安全的会话管理
   - **授权**：实施适当的访问控制
3. **测试安全** - 使用安全扫描工具
4. **监控** - 设置日志记录和警报

## 最佳实践

### 应该做

- ✅ 使用语义 HTML 元素（`<article>`、`<nav>`、`<main>`）
- ✅ 遵循 W3C 和 WHATWG 规范
- ✅ 实施渐进增强
- ✅ 跨多个浏览器和设备进行测试
- ✅ 针对 Core Web Vitals（LCP、FID、CLS）进行优化
- ✅ 从一开始就重视可访问性
- ✅ 使用现代 JavaScript 功能（ES6+）
- ✅ 实施适当的错误处理
- ✅ 最小化并压缩生产资源
- ✅ 到处使用 HTTPS
- ✅ 遵循 REST 原则进行 API 设计
- ✅ 实施适当的缓存策略

### 不应该做

- ❌ 使用表格进行布局（使用 CSS Grid/Flexbox）
- ❌ 忽视可访问性要求
- ❌ 跳过跨浏览器测试
- ❌ 提供未优化的图像
- ❌ 在 HTTPS 页面上混合 HTTP 和 HTTPS 内容
- ❌ 将敏感数据存储在 localStorage 中
- ❌ 忽视性能预算
- ❌ 大量使用内联样式
- ❌ 忘记验证用户输入
- ❌ 实施身份验证而不进行安全审查
- ❌ 使用已弃用的 API 或功能
- ❌ 忽视浏览器控制台警告

## 常见的 Web 开发模式

### 模式 1：渐进增强

从基本的 HTML 开始，使用 CSS 增强样式，添加 JavaScript 功能：

```html
<!-- 基础 HTML（无需 CSS/JS 即可工作） -->
<form action="/submit" method="POST">
  <label for="email">电子邮件：</label>
  <input type="email" id="email" name="email" required>
  <button type="submit">提交</button>
</form>
```

```css
/* 增强样式 */
form {
  display: flex;
  flex-direction: column;
  gap: 1rem;
}
```

```javascript
// 增强交互性
form.addEventListener('submit', async (e) => {
  e.preventDefault();
  await fetch('/api/submit', { /* ... */ });
});
```

### 模式 2：响应式设计

移动优先方法与渐进增强：

```css
/* 移动优先基础样式 */
.container {
  padding: 1rem;
}

/* 平板电脑及以上 */
@media (min-width: 768px) {
  .container {
    padding: 2rem;
    max-width: 1200px;
    margin: 0 auto;
  }
}

/* 桌面电脑 */
@media (min-width: 1024px) {
  .container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);
    gap: 2rem;
  }
}
```

### 模式 3：可访问组件

键盘导航、ARIA、语义 HTML：

```html
<nav aria-label="主导航">
  <ul role="menubar">
    <li role="none">
      <a href="/" role="menuitem">首页</a>
    </li>
    <li role="none">
      <button
        role="menuitem"
        aria-expanded="false"
        aria-haspopup="true"
      >
        产品
      </button>
    </li>
  </ul>
</nav>
```

### 模式 4：性能优化

懒加载、代码拆分和高效加载：

```html
<!-- 懒加载图像 -->
<img
  src="placeholder.jpg"
  data-src="high-res.jpg"
  loading="lazy"
  alt="描述"
>

<!-- 预加载关键资源 -->
<link rel="preload" href="critical.css" as="style">
<link rel="preconnect" href="https://api.example.com">

<!-- 异步/延迟非关键脚本 -->
<script src="analytics.js" async></script>
<script src="app.js" defer></script>
```

## 故障排除

| 问题 | 可能的原因 | 解决方案 |
|-----|----------|--------|
| **CORS 错误** | 跨源请求被阻止 | 在服务器上配置 CORS 头部 |
| **布局偏移** | 图像没有尺寸 | 添加 width/height 属性 |
| **加载时间慢** | 未优化的资源 | 最小化、压缩、懒加载 |
| **可访问性审计失败** | 缺少 ARIA 或语义 HTML | 添加标签、角色和语义元素 |
| **混合内容警告** | HTTPS 页面上的 HTTP 资源 | 更新所有资源为 HTTPS |
| **JavaScript 不工作** | 浏览器兼容性问题 | 使用 polyfills 或使用 Babel 转换 |
| **CSS 未应用** | 特异性或级联问题 | 检查选择器特性和顺序 |
| **表单未提交** | 验证或事件处理问题 | 检查验证规则和事件监听器 |
| **API 请求失败** | 网络、CORS 或身份验证问题 | 检查网络选项卡、CORS 配置、身份验证头部 |
| **缓存未更新** | 侵略性缓存 | 实施缓存破坏或调整头部 |

### 1. 性能监控

### 2. 高级可访问性

创建自定义可访问组件：

```javascript
class AccessibleTabs {
  constructor(element) {
    this.tablist = element.querySelector('[role="tablist"]');
    this.tabs = Array.from(this.tablist.querySelectorAll('[role="tab"]'));
    this.panels = Array.from(element.querySelectorAll('[role="tabpanel"]'));
    
    this.tabs.forEach((tab, index) => {
      tab.addEventListener('click', () => this.selectTab(index));
      tab.addEventListener('keydown', (e) => this.handleKeydown(e, index));
    });
  }
  
  selectTab(index) {
    // 取消选择所有标签
    this.tabs.forEach(tab => {
      tab.setAttribute('aria-selected', 'false');
      tab.setAttribute('tabindex', '-1');
    });
    this.panels.forEach(panel => panel.hidden = true);
    
    // 选择目标标签
    this.tabs[index].setAttribute('aria-selected', 'true');
    this.tabs[index].setAttribute('tabindex', '0');
    this.tabs[index].focus();
    this.panels[index].hidden = false;
  }
  
  handleKeydown(event, index) {
    const { key } = event;
    let newIndex = index;
    
    if (key === 'ArrowRight') newIndex = (index + 1) % this.tabs.length;
    if (key === 'ArrowLeft') newIndex = (index - 1 + this.tabs.length) % this.tabs.length;
    if (key === 'Home') newIndex = 0;
    if (key === 'End') newIndex = this.tabs.length - 1;
    
    if (newIndex !== index) {
      event.preventDefault();
      this.selectTab(newIndex);
    }
  }
}
```

### 4. 安全头部

实施全面的安全头部：

```javascript
// Express.js 示例
app.use((req, res, next) => {
  // 内容安全策略
  res.setHeader('Content-Security-Policy', 
    "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'");
  
  // 严格传输安全
  res.setHeader('Strict-Transport-Security', 'max-age=31536000; includeSubDomains; preload');
  
  // XSS 防护
  res.setHeader('X-Content-Type-Options', 'nosniff');
  res.setHeader('X-Frame-Options', 'DENY');
  res.setHeader('X-XSS-Protection', '1; mode=block');
  
  // Referrer Policy
  res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin');
  
  next();
});
```
