# 运营节奏

30人的会议结构在100人时就会崩溃。在100人时有效的结构在300人时会崩溃。失败模式总是相同的：太多人在太多会议中，却做出了太少决策。

## 何时使用

**触发因素：**
- "我们的会议没有产生决策"
- "我们正在增长，但协同性却越来越差"
- "我们应该多久开一次会？"
- "没有人知道跨部门正在发生什么"
- "决策需要很长时间"
- "领导层整天都在开会"

**背景：**
- 从20人到300人以上的公司规模扩张
- PMF（产品市场契合）后到增长阶段
- 分布式/远程团队
- 任何"我们需要讨论这个"已成为默认的阶段

---

## 核心框架

### 1. 五级会议架构

**模式：**

不同的会议服务于不同的目的。将它们混淆会导致效率低下（花费过多时间）或混乱（决策不明确）。根据功能、频率和决策权来区分会议。

**第1级：每日站会（15分钟，仅限团队）**

- 我们昨天完成了什么，今天开始什么，有什么阻碍我们
- 最多5-10人。全公司站会是戏剧性的
- 反模式：状态报告（使用Slack，而不是会议）
- 反模式：战略讨论（错误的时间，错误的地点）
- 成功标准：15分钟内结束，暴露1-2个阻碍

**第2级：每周职能回顾（60分钟，职能领导）**

每个职能都有自己的每周节奏：
- 产品团队周五4点：指标、用户反馈、路线图阻碍
- GTM团队周二4点：管道、客户更新、交易健康状况
- 工程团队周三4点：速度、错误积压、部署

格式：指标回顾（10分钟）→ 胜利/阻碍（15分钟）→ 深入探讨（30分钟）→ 下周优先事项（5分钟）

反模式：试图在会议中解决所有问题。选择1-2个，其余的委托给后续会议。

**第3级：每周全员大会（60分钟，整个公司）**

规模化公司中最重要的协同机制。

- CEO更新（15分钟）：北极星进展、本周重点、有什么变化
- 指标仪表盘（10分钟）：每周相同格式（一致性使模式识别成为可能）
- 深入探讨（20分钟）：一个需要团队输入的战略主题——不是演示，而是讨论
- 问答（15分钟）：真实问题，真实答案

反模式：防御性语气。全员大会应该是直截了当的，而不是粉饰太平。
反模式：指标不一致。如果你更改仪表盘，团队就无法跟踪进展。

**第4级：双周领导层协同（90分钟）**

- 北极星进展（5分钟）
- 职能更新（30分钟，每个5-7分钟）
- 需要解决的重大决策（30-40分钟）：资源冲突、战略转变、客户/产品决策
- 未来两周计划（15分钟）

这是解决跨职能阻碍的地方。如果职能独立运作，这个会议就没有起作用。

**第5级：季度战略规划（半天到全天）**

- 上个季度的回顾（90分钟）：什么有效，什么无效，我们会怎么做不同
- 下个季度的规划（120分钟）：我们在优化什么？路线图是什么？
- 职能分解（90分钟）：每个职能规划他们的季度
- 综合分析（60分钟）：职能分享承诺，解决冲突

反模式：过多的"趣味活动"，缺乏实质性内容。
反模式：没有明确的决策产出。

**规模调整：**

- **<30人**：仅2-3级。跳过每日站会（你能看到一切）。跳过双周领导会（你就是领导）。
- **30-100人**：添加所有5级。月度回顾捕捉到你不再每天看到的内容。
- **100-300人**：添加跳级回顾。你与执行层相距2层以上。
- **300人以上**：添加职能特定子节奏。CEO应该参加的会议比50人时更少——而不是更多。

**使这一切奏效的规则：**

每个会议必须产生决策或被取消。状态更新是异步的。如果你在会议中，没有人做出决策，就离开。

### 2. 每周指标报告（早期发现问题仪表盘）

**模式：**

月度报告在问题出现30天后才发现。那时，一个坏月已经形成。每周报告在第二周发现问题，那时你仍然可以挽救这个月。

**格式（每周相同结构）：**

```
[日期]的周

北极星：[指标]
本周：[值] | 上周：[值] | 变化：[+/-] [↑↓]
背景：[一句话——为什么这个趋势很重要]

职能指标：
  产品： 7天留存率：34% | 上周：33% | +1% ↑
            功能采用率：18% | 上周：16% | +2% ↑
            背景：在boarding改进方面显示出影响

  GTM：      管道：$8.2M | 上周：$7.8M | +$400K ↑
            新POC：3 | 上周：2
            背景：合作伙伴管道增加交易

  健康：   团队士气：7.2/10（从7.5下降）
            背景：组织结构调整导致不确定性
```

**纪律规则：**

1. **每周相同指标。** 一致性使模式识别成为可能。可以添加指标，但从不删除指标。
2. **每个指标一句话背景。** 不仅仅是数字——这很重要吗？与计划相比？与上期相比？
3. **每个指标的趋势方向。** 向上/向下/平线箭头。如果它显著移动：暂时性的还是结构性？
4. **交通灯颜色。** 绿色（按计划）、黄色（注意）、红色（需要行动）。每个红色项目必须有：负责人、具体行动、截止日期。

**升级规则：**

如果一个指标连续两周为红色，且行动计划没有奏效，就升级。

**有多少指标：**

选择8-12个。如果一个指标在移动时不会改变你的行为，就删除它。包含40个指标的仪表盘是装饰品，而不是决策工具。

**常见错误：**

看起来不错但不会预测业务成果的虚荣指标。没有采用背景的总下载量。没有支持指标的CEO头条新闻。

### 3. 季度规划（防止战略漂移的过程）

**模式：**

没有季度规划，公司就会漂移。每个职能都在本地优化。销售追逐ICP（理想客户画像）外的交易。产品为单个客户构建功能。营销运行与管道没有连接的活动。

**三周规划周期：**

**第1周：回顾+数据收集**
- 上个季度结果与计划的对比（领导层准备）
- 每个职能撰写一页回顾：什么有效，什么无效，我们会怎么做不同
- 财务准备：实际收入、实际支出、预测
- 市场数据：竞争对手动态、客户反馈主题、赢/输分析

**第2周：优先级设定（领导层半天）**
- 回顾回顾（30分钟——预读，不要演示）
- 确认3-5个公司级优先事项
- 对于每个：负责人、成功指标、资源需求
- 确定你*不*做的事情（与你要做的事情同样重要）
- 解决跨职能依赖关系
- 使用北极星作为裁决标准："这有助于我们实现目标吗？优先考虑。锦上添花？推迟。"

**第3周：OKR级联+资源分配**
- 每个职能将公司优先事项转化为团队OKR
- 领导层审查以确认一致性
- 资源分配最终确定（人员、预算、工具）
- 最终计划全公司共享

**季度承诺格式：**

```
2026年Q2路线图
北极星：[我们优化的目标]

支柱1：产品（25%团队投入）
  初始：[名称]
    问题：[我们正在解决的问题]
    成功：[具体指标]
    负责人：[姓名]
    时间表：[何时]

支柱2：GTM（50%团队投入）
  初始：[名称]
    ...

支柱3：人员（10%投入）
  初始：[名称]
    ...

支柱4：技术债务（15%投入）
  初始：[名称]
    ...
```

**"不做"清单：**

对于每个你添加的优先事项，确定你停止的事情。如果你不能说出你*不*做的事情，你就有太多优先事项。

**常见错误：**

产生30页文档无人阅读的季度规划。输出应该是：1页上的3-5个优先事项，每个都有负责人和指标。就是这样。

### 4. 决策速度和权限

**模式：**

在20人时，CEO实时做出每个决策。快。在100人时，决策需要协同。慢。在300人时，决策需要协同、批准和文档记录。缓慢。

**解决方法不是更多会议，而是明确的决策权。**

**决策权限矩阵：**

| 决策 | 谁做决策 | 时间线 | 升级 |
|------|----------|--------|------|
| 公司战略 | CEO | 1周 | 如果战略，董事会 |
| 功能优先级 | 产品负责人 | 1周 | 如果>3个工程周，CEO |
| 客户支持问题 | CSM | 立即 | 如果升级，CS负责人 |
| 营销活动 | 营销负责人 | 2周 | 如果预算>10K，CMO |
| 招聘 | 职能负责人 | 2周 | 如果角色未批准，CEO |
| 新合作伙伴关系 | CEO | 2周 | 如果战略，董事会 |
| 供应商选择 | 职能负责人 | 1周 | 如果>50K/年，CEO |

**问题：**

规模化公司开始将可逆的低风险决策视为不可逆转的高风险决策。一切都需要批准。一切都需要会议。一切都需要共识。

**解决方法：**

**类型1（不可逆，高风险）：** 定价模型、市场进入、重大合作伙伴关系 → CEO/领导层在一次会议中做出决策，讨论时间：最多1-2周。

**类型2（可逆，低风险）：** 活动创意、功能优先级、单个招聘 → 职能负责人做出决策，通知，迭代。同一天或第二天。

**用70%的信息而不是100%来做决策。** 速度是每个阶段的竞争优势。

**常见错误：**

共识文化伪装成协作。"让我们让每个人都协同"往往意味着"没有人想做出决策"。命名决策者。让他们决策。继续前进。

### 5. 异步优先沟通

**模式：**

同步会议无法扩展。默认为异步，同步升级。

**异步优先（无需会议）：**
- 决策文件（即使是重大的——编写提案，征求评论，48-72小时反馈，决定是否共识或没有实质性反对）
- 进度更新（使用每周报告，而不是会议）
- 流程变更和SOP
- 已做出的决策（通知，不要讨论）

**同步时：**
- 需要实时头脑风暴
- 需要解决重大分歧
- 需要白板复杂主题
- 团队建设/关系

**文档纪律：**

每个决策都记录：决定了什么？为什么？谁决定？何时生效？谁需要知道？

以可搜索的格式存储（维基、共享驱动器）。新员工更快地入职。过去的决策不会再次重新辩论。

**常见错误：**

"快速同步"会议，每周消耗10小时。在Slack中过度沟通（短暂、嘈杂）而在持久格式（文档、电子邮件）中沟通不足。重要的事情应该在6个月后可搜索。

### 6. CEO每周更新

**模式：**

规模化公司中杠杆最大的沟通工具。写5-10分钟。每个人都会阅读它。它设定了背景，庆祝了胜利，命名了优先事项，并创造了共同的理解。

**格式（周日晚上或周一早上发送）：**

**1. 本周重点（一段话）：**
本周的优先事项是什么？团队应该专注于什么？

**2. 北极星进展（1-2个要点）：**
我们在关键指标上的进展如何？趋势上升/下降/平？为什么这很重要？

**3. 本周胜利（3-5个要点）：**
什么已经发布？客户/合作伙伴胜利？大局影响？

**4. 被解决的阻碍（1-2个要点）：**
我们本周会解决什么阻碍？谁需要知道？

**5. 请求（可选，1个要点）：**
团队需要什么帮助？推荐、反馈、客户介绍？

**规则：**

每天相同。一致性表明运营纪律。如果你错过一周，团队会注意到——并且开始想知道你没有告诉他们的事情。

**常见错误：**
太长（团队不阅读），太详细（保留给职能会议），只有好消息（团队失去信任），不一致（团队停止阅读）。

---

### 7. 角色清晰度>头衔

**模式：**

最强大的工具不是等级制度——而是明确的角色清晰度。当某人确切地知道他们拥有什么并且不能将其委托出去时，决策就会更快。

**执行方法：**

- 每个初始项目都恰好有一个负责人（和支持团队）
- 指标与该负责人挂钩
- 通过移动KPI衡量成功，而不是完成任务
- 在48小时内消除没有明确所有权的初始项目

**测试：**

你能说出拥有这个成果的一个人吗？不是"团队"——一个人。如果你不能，这个初始项目将会漂移。

**常见错误：**

将项目分配给多个人（"每个人都拥有它"=没有人拥有它）。衡量活动而不是影响。烧率上升而没有按初始项目跟踪明确ROI。

## 决策树

### 我们需要哪些会议级别？

```
公司规模<30？
├─ 是 → 仅2-3级（每周职能+全员大会）
└─ 否 → 继续...
    │
    30-100人？
    ├─ 是 → 所有5级
    └─ 否 → 所有5级+跳级回顾+职能子节奏
```

### 这个会议值得保留吗？

```
它产生决策吗？
├─ 否 → 它可以是异步的吗？
│   ├─ 是 → 使其异步，取消会议
│   └─ 否 → 用决策议程重新设计
└─ 是 → 会议室里的人是否正确？
    ├─ 否 → 修复与会者名单（少>多）
    └─ 是 → 保留它
```

## 常见错误

**1. 随着增长添加会议**
替换它们。在200人时，CEO应该参加的会议比在50人时更少。

**2. 状态更新会议**
如果可以用电子邮件，就应该用电子邮件。会议是为了做决策。

**3. 每季度更改指标**
一致性使趋势识别成为可能。相同的仪表盘，每次。

**4. 共识文化**
命名决策者。让他们决策。通知所有人。

**5. 所有信息都在Slack中**
短暂、嘈杂、不可搜索。重要决策放在文档中。

**6. 产生30页文档的季度规划**
1页上的3-5个优先事项。这就是输出。

## 快速参考

**会议架构：**
每日站会（15分钟）→ 每周职能（60分钟）→ 每周全员大会（60分钟）→ 双周领导层（90分钟）→ 季度规划（半天）

**每周指标仪表盘：**
8-12个指标，每周相同格式，交通灯颜色，每个指标一句话背景，每个红色都有负责人+行动+截止日期

**季度规划周期：**
第1周：回顾+数据 → 第2周：优先级设定（3-5个最大）→ 第3周：OKR级联+资源

**决策权限：**
类型1（不可逆）：CEO/领导层，1-2周 → 类型2（可逆）：职能负责人，同一天

**CEO每周更新：**
本周重点 → 北极星进展 → 胜利 → 阻碍 → 请求

**信息流：**
每天：Slack胜利/客户声音 → 每周：CEO邮件+职能更新 → 每月：全员大会+跳级 → 季度：规划分享+演示
