# 更新标准 OO 组件文档

通过分析相应的组件代码，更新位于 `${file}` 的现有文档文件。

从现有文档的前置信息（`component_path` 字段）中提取组件路径，或从文档内容中推断。分析当前组件的实现情况，并相应地更新文档。

**文档标准：**

- DOC-001：遵循 C4 模型文档级别（上下文、容器、组件、代码）
- DOC-002：与 Arc42 软件架构文档模板保持一致
- DOC-003：符合 IEEE 1016 软件设计描述标准
- DOC-004：使用敏捷文档原则（提供足够增加价值的文档）
- DOC-005：面向开发者和维护者作为主要受众

**分析说明：**

- ANA-001：阅读现有文档以了解组件上下文和结构
- ANA-002：从前置信息或内容分析中识别组件路径
- ANA-003：检查当前源代码文件以了解类结构和继承关系
- ANA-004：比较现有文档与当前实现情况
- ANA-005：识别设计模式和架构变更
- ANA-006：更新公共 API、接口和依赖项
- ANA-007：识别新的/变更的创建型/结构型/行为型模式
- ANA-008：更新方法参数、返回值、异常
- ANA-009：重新评估性能、安全性、可靠性、可维护性
- ANA-010：更新集成模式和数据流

**语言特定优化：**

- LNG-001：**C#/.NET** - async/await、依赖注入、配置、释放
- LNG-002：**Java** - Spring 框架、注解、异常处理、打包
- LNG-003：**TypeScript/JavaScript** - 模块、异步模式、类型、npm
- LNG-004：**Python** - 包、虚拟环境、类型提示、测试

**更新策略：**

- UPD-001：保留现有文档结构和格式
- UPD-002：将 `last_updated` 字段更新为当前日期
- UPD-003：如果存在，在前置信息中维护版本历史记录
- UPD-004：如果组件显著扩展，添加新章节
- UPD-005：标记已弃用的功能或破坏性变更
- UPD-006：更新示例以反映当前 API
- UPD-007：刷新依赖项列表和版本
- UPD-008：更新 mermaid 图表以反映当前架构

**错误处理：**

- ERR-001：文档文件不存在 - 提供文件位置指导
- ERR-002：文档中未找到组件路径 - 请求澄清
- ERR-003：源代码已移动 - 建议更新路径
- ERR-004：重大架构变更 - 突出破坏性变更
- ERR-005：对源代码访问权限不足 - 记录限制

**输出格式：**

更新现有的 Markdown 文件，保持其结构同时刷新内容以匹配当前实现。保留格式、标题层次结构和现有的组织决策。

**所需文档结构：**

按照相同的模板结构更新现有文档，确保所有章节反映当前实现：

```md
---
title: [组件名称] - 技术文档
component_path: [当前组件路径]
version: [如果适用，更新版本]
date_created: [原始创建日期 - 保留]
last_updated: [YYYY-MM-DD - 更新为当前日期]
owner: [保留现有或如果变更则更新]
tags: [根据当前功能按需更新标签]
---
