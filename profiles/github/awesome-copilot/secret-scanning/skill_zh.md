# 秘密扫描

这项技能提供了配置 GitHub 秘密扫描的程序性指导——检测泄露的凭证、阻止秘密推送、定义自定义模式和管理警报。

## 何时使用此技能

在以下请求中使用此技能：

- 启用或配置仓库或组织的秘密扫描
- 设置推送保护以在秘密到达仓库之前阻止它们
- 使用正则表达式定义自定义秘密模式
- 从命令行解决被阻止的推送
- 分流、驳回或修复秘密扫描警报
- 配置推送保护的授权绕过
- 通过 `secret_scanning.yml` 排除目录
- 了解警报类型（用户、合作伙伴、推送保护）
- 启用有效性检查或扩展元数据检查
- 在提交前扫描本地代码更改中的秘密（通过 MCP / AI 编码代理）——请参阅下文 **通过 AI 编码代理进行预提交扫描** 部分的推荐插件

## 秘密扫描的工作原理

秘密扫描自动检测所有分支上的整个 Git 历史记录、问题描述、评论和标题（开放和关闭）、拉取请求标题、描述和评论、GitHub 讨论标题、描述和评论、维基和秘密 gist 中的暴露凭证。

### 可用性

| 仓库类型 | 可用性 |
|---|---|
| 公开仓库 | 自动、免费 |
| 私有/内部（组织拥有） | 需要 Team/Enterprise Cloud 上的 GitHub 秘密保护 |
| 用户拥有 | Enterprise Cloud 与 Enterprise 管理用户 |

## 核心工作流程——启用秘密扫描

### 第 1 步：启用秘密保护

1. 导航到仓库 **设置** → **高级安全**
2. 点击“秘密保护”旁边的 **启用**
3. 通过点击 **启用秘密保护** 进行确认

对于组织，使用安全配置进行规模化启用：
- 设置 → 高级安全 → 全局设置 → 安全配置

### 第 2 步：启用推送保护

推送保护在推送过程中阻止秘密——在它们到达仓库之前。

1. 导航到仓库 **设置** → **高级安全**
2. 在秘密保护下启用“推送保护”

推送保护会阻止以下场景中的秘密：
- 命令行推送
- GitHub UI 提交
- 文件上传
- REST API 请求
- REST API 内容创建端点

### 第 3 步：配置排除项（可选）

创建 `.github/secret_scanning.yml` 以自动关闭特定目录的警报：

```yaml
paths-ignore:
  - "docs/**"
  - "test/fixtures/**"
  - "**/*.example"
```

**限制：**
- `paths-ignore` 中最多 1,000 个条目
- 文件必须小于 1 MB
- 排除的路径也会跳过推送保护检查

**最佳实践：**
- 尽可能具体地指定排除路径
- 添加注释解释为什么排除每个路径
- 定期审查排除项——删除过时的条目
- 通知安全团队排除项

### 第 4 步：启用附加功能（可选）

**非提供程序模式**——检测私钥、连接字符串、通用 API 密钥：
- 设置 → 高级安全 → 启用“扫描非提供程序模式”

**AI 驱动的通用秘密检测**——使用 Copilot 检测非结构化秘密（如密码）：
- 设置 → 高级安全 → 启用“使用 AI 检测”

**有效性检查**——验证检测到的秘密是否仍然有效：
- 设置 → 高级安全 → 启用“有效性检查”
- GitHub 会定期使用提供程序 API 测试检测到的凭证
- 警报中显示状态：`active`、`inactive` 或 `unknown`

**扩展元数据检查**——关于谁拥有秘密的额外上下文：
- 需要先启用有效性检查
- 有助于优先处理修复并识别负责的团队

## 核心工作流程——解决被阻止的推送

当推送保护从命令行阻止推送时：

### 选项 A：移除秘密

**如果秘密在最新提交中：**
```bash
# 从文件中移除秘密
# 然后修改提交
git commit --amend --all
git push
```

**如果秘密在较早的提交中：**
```bash
# 查找包含秘密的最早提交
git log

# 在该提交之前开始交互式变基
git rebase -i <COMMIT-ID>~1

# 将“pick”改为“edit”以针对有问题的提交
# 移除秘密，然后：
git add .
git commit --amend
git rebase --continue
git push
```

### 选项 B：绕过推送保护

1. 访问推送错误消息中返回的 URL（使用相同用户）
2. 选择绕过原因：
   - **用于测试**——创建警报并自动关闭
   - **误报**——创建警报并自动关闭
   - **稍后修复**——创建开放的警报
3. 点击 **允许我推送此秘密**
4. 在 3 小时内重新推送

### 选项 C：请求绕过权限

如果授权绕过已启用而您缺乏绕过权限：
1. 访问推送错误中的 URL
2. 添加评论解释为什么秘密是安全的
3. 点击 **提交请求**
4. 等待邮件通知批准/拒绝
5. 如果批准，推送提交；如果拒绝，移除秘密

> 详细绕过和授权绕过工作流程，请搜索 `references/push-protection.md`。

## 自定义模式

使用正则表达式定义组织特定的秘密模式。

### 快速设置

1. 设置 → 高级安全 → 自定义模式 → **新建模式**
2. 输入模式名称和秘密格式的正则表达式
3. 添加测试字符串样本
4. 点击 **保存并干运行** 以测试（最多 1,000 个结果）
5. 审查结果以查找误报
6. 点击 **发布模式**
7. 可选地启用该模式的推送保护

### 范围

自定义模式可以在以下级别定义：
- **仓库级别**——仅适用于该仓库
- **组织级别**——适用于所有已启用秘密扫描的仓库
- **企业级别**——跨所有组织

### Copilot 辅助模式生成

使用 Copilot 秘密扫描根据秘密类型的文本描述（包括可选的示例字符串）生成正则表达式。

> 详细自定义模式配置，请搜索 `references/custom-patterns.md`。

## 警报管理

### 警报类型

| 类型 | 描述 | 可见性 |
|---|---|---|
| **用户警报** | 仓库中发现的秘密 | 安全选项卡 |
| **推送保护警报** | 通过绕过推送的秘密 | 安全选项卡（筛选：`bypassed: true`） |
| **合作伙伴警报** | 报告给提供者的秘密 | 不在仓库中显示（仅提供者可见） |

### 警报列表

- **默认警报**——支持提供程序模式和自定义模式
- **通用警报**——非提供程序模式和 AI 检测的秘密（每个仓库最多 5,000 个）

### 修复优先级

1. **立即旋转凭证**——这是关键操作
2. 审查警报以获取上下文（位置、提交、作者）
3. 检查有效性状态：`active`（紧急）、`inactive`（低优先级）、`unknown`
4. 如有必要从 Git 历史中移除（耗时，旋转后通常不必要）

### 驳回警报

提供文档理由进行驳回：
- **误报**——检测到的字符串不是真正的秘密
- **已撤销**——凭证已被撤销
- **用于测试**——秘密仅在测试代码中

> 详细警报类型、有效性检查和 REST API，请搜索 `references/alerts-and-remediation.md`。

## 通过 AI 编码代理进行预提交扫描

在提交前扫描 AI 编码代理中的代码更改以查找秘密，请安装 **高级安全插件**，它提供 `run_secret_scanning` MCP 工具和专用扫描技能。

**GitHub Copilot CLI:**
```bash
/plugin install advanced-security@copilot-plugins
```

**Visual Studio Code:**
- 在 Copilot Chat 中打开 **Chat: Plugins**（或使用 `@agentPlugins`）并安装 `advanced-security` 插件
- 然后在 Copilot Chat 中运行 `/secret-scanning`

参见：[高级安全插件——秘密扫描技能](https://github.com/github/copilot-plugins/blob/main/plugins/advanced-security/skills/secret-scanning/SKILL.md)

> 宣布于 [通过 GitHub MCP 服务器在 AI 编码代理中进行秘密扫描](https://github.blog/changelog/2026-03-17-secret-scanning-in-ai-coding-agents-via-the-github-mcp-server/)（2026 年 3 月）
