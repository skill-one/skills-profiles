# 每日准备

生成一个结构化的准备文件，用于下一工作日，包含会议详情、准备要点、相关任务链接以及生产力建议。

## 使用场景

- 工作日结束："为我准备明天"
- 任何时间："为我准备周五"或"3月25日会是什么样子？"
- 每周计划：可连续运行多天

## 操作步骤

### 1. 确定目标日期

如果用户指定了日期，则使用该日期。否则，默认为明天（当前日期+1天）。
如果明天是周六，则默认为周一。如果周日，则默认为周一。
计算输出路径：`outputs/YYYY/MM/YYYY-MM-DD-prep.html`

### 2. 通过WorkIQ获取日历

使用WorkIQ MCP工具获取日历。向WorkIQ询问：

> "我在{目标日期}有哪些会议？对于每个会议，请包括：主题、开始时间、结束时间、组织者、所有与会者及其电子邮件地址、地点、是否为线上会议，以及我是否已接受或拒绝。"

如果响应信息不足，进行后续查询：

> "在{目标日期}的会议中，哪些被标记为可选或临时？哪些是周期性的？"

### 3. 对每个会议进行分类

根据与会者域名和主题应用以下标签：

| 标签 | 标准 |
|------|------|
| `[客户 · 高]` | 来自客户/合作伙伴域名的外部与会者，或主题匹配已知客户名称 |
| `[内部]` | 仅限公司内部域名与会者 |
| `[社区]` | CoP、社区、公会、学习会议 |
| `[技能提升]` | 培训、研讨会、认证、学习 |
| `[可选 · 跳过]` | 临时、低重要性或已知的周期性可选（例如："办公时间"、"开放问答"） |
| `[个人]` | 私人活动、非工作 |

#### 区域标记

对于每个会议，检查组织者字段并应用以下附加标记：

| 条件 | 标记 | 操作 |
|------|------|------|
| 开始时间 ≥ 15:30且< 16:00（任何组织者） | `⚠️ 工作时间外` | 建议拒绝 |
| 开始时间 ≥ 16:00且**不是**自我组织的 | `⚠️ 工作时间外` | 建议拒绝 |
| 开始时间 ≥ 16:00且自我组织的 | _(无标记)_ | 可以——你选择安排它 |
| 开始时间 < 09:00且**不是**自我组织的 | `⚠️ 早晨` | 建议拒绝——侵占学习时间 |
| 开始时间 < 09:00且自我组织的 | _(无标记)_ | 可以——你选择安排它 |
| 与12:00–13:00重叠 | `🍽️ 午餐冲突` | 在日历备注中注明 |

"自我组织"是指**你**是会议组织者（检查WorkIQ的组织者字段）。

### 4. 理想日结构

用作所有分析步骤的决策框架。每个会议都必须根据这些区域进行评估。用户应根据自己的日常安排调整这些时间和目标。

| 区域 | 时间 | 目的 | 规则 |
|------|------|------|------|
| 早晨专注 | 09:00前 | 行政、学习、个人工作 | 避免他人会议。标记外部活动。 |
| 客户区域 | 09:00–12:00 | 客户/外部会议 | 最多2个客户会议。优先安排早晨的外部通话。 |
| 午餐 | 12:00–13:00 | 休息 | 受保护。标记任何重叠。 |
| 深度工作 | 13:00–15:30 | 可交付成果、专注编码/写作 | 最小化会议。标记非必要会议为深度工作干扰。 |
| 严格保护 | 15:30–16:00 | 结束日收尾 | 无论组织者如何，都标记所有会议。 |
| 灵活保护 | 16:00后 | 结束日 | 仅标记他人会议。自我组织的可以。 |

**每日目标：**
- 学习时间：**1.5小时**（来自早晨专注+间隙时间）
- 深度工作时间：**2.5小时**（13:00–15:30区域）
- 客户会议：**最多2个**（最好在09:00–12:00）

### 5. 检测冲突与日适配问题

比较事件时间窗口。在冲突表中标记重叠，并为每个冲突提供建议——优先考虑客户会议而非内部/可选。

同时检测这些**日适配问题**（在单独的"日适配问题"表中报告）：

| 检查 | 条件 | 标记 |
|------|------|------|
| **客户过载** | >2 `[客户 · 高]` 会议 | 将第3个及以后标记为"考虑重新安排到其他日期" |
| **深度工作干扰** | 13:00–15:30区域中的非必要会议 | "干扰深度工作——考虑移至早晨" |
| **非理想位置** | 客户会议在09:00–12:00之外 | "客户会议在首选早晨区域之外" |
| **早晨侵占** | 他人会议在09:00前 | "侵占学习时间——建议拒绝" |
| **午餐冲突** | 会议与12:00–13:00重叠 | "与午餐休息冲突" |

### 6. 从工作区获取上下文

1. 读取打开的任务文件，查找与客户名称或明天会议与会者相关的任务
2. 搜索工作区文件夹，查找与这些客户或主题相关的最近文件
3. 检查最近的会议总结或计划，获取相关准备上下文
4. 使用这些信息为每个会议生成可操作的准备要点

### 7. 按会议生成准备内容

对于每个会议（按时间顺序），包括：
- 时间、主题、组织者
- 与会者列表（名字、如果外部则包括公司）
- 3–5个基于打开任务、最近总结和会议主题的可操作准备要点
- 如果没有上下文，注明会议中需要询问/澄清的事项

### 8. 找出学习与专注时段

在为每个会议生成准备内容后，分析日程表以找到空闲时段：

1. **早晨专注确认**——验证早晨专注时段是否空闲。如果有任何非自我组织的活动，则标记它。

2. **学习时段**——在早晨时段中找到≥30分钟的间隙，以及任何其他适合技能提升的空闲时段。目标：**每天1.5小时**。对于每个时段：时间范围、持续时间、建议活动。

3. **深度工作块**——在13:00–15:30区域中找到连续空闲的间隙，用于交付成果。对于每个块：时间范围、持续时间、从打开任务中建议的任务。

4. **报告总数：**
   - 学习小时数：找到的 vs. 1.5小时目标（例如，"1.0小时 / 1.5小时目标——缺少0.5小时"）
   - 13:00–15:30区域中可用的深度工作小时数（例如，"2.0小时 / 2.5小时可用"）

### 9. 生产力建议

分析整个日程并提供：

| 部分 | 包含内容 |
|------|----------|
| **日适配分数** | 评估0–100%的日程与理想日结构的匹配程度。标准：(1) 早晨专注时段清晰 (+20%)，(2) 09:00–12:00最多2个客户会议 (+20%)，(3) 12:00–13:00午餐时段受保护 (+15%)，(4) 13:00–15:30深度工作时段完整 (+20%)，(5) 15:30后无会议或仅自我组织16:00后会议 (+15%)，(6) 找到≥1小时学习时段 (+10%)。显示为：🟢 ≥80%，🟡 50–79%，🔴 <50%。 |
| **日形态** | 总会议小时数、专注时间可用、学习小时数、深度工作小时数、重/中/轻评估 |
| **建议拒绝** | 自动包含：(1) 所有15:30–16:00的会议，(2) 他人会议≥16:00，(3) 他人会议<09:00，(4) 第3个及以后客户会议，(5) 深度工作区域的可选会议。显示"回收"列，显示分钟数。自我组织的会议在09:00前或16:00后**不**自动拒绝。 |
| **冲突解决** | 针对每个重叠的特定建议 |
| **学习时段** | 技能提升的空闲时段——来自步骤8。表：窗口、持续时间、建议活动。显示总数 vs. 1.5小时目标。 |
| **深度工作块** | 13:00–15:30中用于交付成果的空闲时段——来自步骤8。表：窗口、持续时间、建议任务。 |
| **精力管理** | 如果>3小时连续客户会议且无休息，则标记 |
| **前3优先事项** | 最具影响力的3件事（会议+任务结合） |

### 10. 生成文件

在`outputs/YYYY/MM/YYYY-MM-DD-prep.html`创建输出文件，作为自包含的HTML文件，嵌入CSS（暗色主题、颜色编码时间线、响应式布局）。

如果该日期的文件已存在，则先读取并更新，而不是覆盖——用户可能已添加手动备注。

## 示例提示

- "为我准备明天"
- "周五会是什么样子？"
- "3月28日的每日准备"
- "为我准备下周一——重点关注客户会议"

## 要求

- **WorkIQ MCP工具**必须可用于访问日历（Microsoft 365 / Outlook）
- 具有任务文件和客户/项目文件夹的工作区，用于上下文丰富
- 输出为自包含HTML——无外部依赖
