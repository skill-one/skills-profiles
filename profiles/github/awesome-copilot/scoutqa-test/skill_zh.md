# ScoutQA 测试技能

使用 `scoutqa` CLI 对 Web 应用程序进行 AI 驱动的探索性测试。

**将 ScoutQA 视为一个智能的测试伙伴**，它可以自主探索、发现问题并验证功能。将测试委托给多个并行的 ScoutQA 执行，以在节省时间的同时最大化覆盖范围。

## 何时使用此技能

在两种场景中使用此技能：

1. **用户请求测试** - 当用户明确要求测试网站或验证功能时
2. **主动验证** - 在实现 Web 功能后，自动运行测试以验证实现是否正常工作

**示例主动使用方式：**

- 实现登录表单后 → 测试身份验证流程
- 添加表单验证后 → 验证验证规则和错误处理
- 构建结账流程后 → 测试端到端购买流程
- 修复错误后 → 验证修复是否有效且未破坏其他功能

**最佳实践**：在完成 Web 功能的实现后，在后台主动启动 ScoutQA 测试，以便在您继续执行其他任务时验证它是否正常工作。

## 运行测试

### 测试工作流程

复制此清单并跟踪您的进度：

测试进度：

- [ ] 编写具有明确期望的具体测试提示
- [ ] 在后台运行 scoutqa 命令
- [ ] 告知用户执行 ID 和浏览器 URL
- [ ] 提取和分析结果

**步骤 1：编写具体测试提示**

有关指南，请参阅下文“编写有效提示”部分。

**步骤 2：运行 scoutqa 命令**

**重要提示**：使用 Bash 工具的超时参数（5000ms = 5 秒）来捕获执行细节：

当调用 Bash 工具时，将 `timeout: 5000` 作为参数设置：

- 这是 Claude Code 中 Bash 工具的内置超时参数（不是 Unix `timeout` 命令）
- 5 秒后，Bash 工具返回控制权并带有任务 ID，而进程继续在后台运行
- 这与 Unix `timeout` 不同，Unix `timeout` 会杀死进程——在这里进程会继续运行
- 前 5 秒从 ScoutQA 的输出来捕获执行 ID 和浏览器 URL
- 测试继续在 ScoutQA 的基础设施上远程运行，作为后台任务

```bash
scoutqa --url "https://example.com" --prompt "您的测试指令"
```

在最初的几秒钟，命令将输出：

- **执行 ID**（例如，`019b831d-xxx`）
- **浏览器 URL**（例如，`https://app.scoutqa.ai/t/019b831d-xxx`）
- 显示测试进度的初始工具调用

5 秒超时后，Bash 工具返回任务 ID，而命令继续在后台运行。您可以在测试运行时处理其他任务。超时只是为了捕获初始输出（执行 ID 和浏览器 URL）——测试既在本地作为后台任务运行，也在 ScoutQA 的基础设施上远程运行。

**步骤 3：告知用户执行 ID 和浏览器 URL**

Bash 工具返回任务 ID（在最初的 5 秒内捕获了执行细节）后，请告知用户：

- ScoutQA 执行 ID 和浏览器 URL，以便他们可以在浏览器中监控进度
- 如果他们以后想检查本地命令输出，请告知后台任务 ID

测试在后台继续运行，而您继续其他工作。

**步骤 4：提取和分析结果**

有关完整格式，请参阅下文“呈现结果”部分。

### 命令选项

- `--url`（必需）：要测试的网站 URL（支持 `localhost` / `127.0.0.1`）
- `--prompt`（必需）：自然语言的测试指令
- `--project-id`（可选）：与项目关联以进行跟踪
- `-v, --verbose`（可选）：显示所有工具调用，包括内部调用

### 本地测试支持

ScoutQA 支持自主测试 `localhost` 和 `127.0.0.1` URL——无需手动设置。

```bash
# 在开发您的应用程序时无缝测试本地运行的应用程序
scoutqa --url "http://localhost:3000" --prompt "测试注册表单"
```

### 何时使用每个命令

**开始新测试？** → 使用 `scoutqa --url --prompt`
**验证已知问题？** → 使用 `scoutqa issue-verify --issue-id <id>`
**从执行中查找问题 ID？** → 使用 `scoutqa list-issues --execution-id <id>`
**代理需要更多上下文？** → 使用 `scoutqa send-message`（见“跟进卡住的执行”）

## 编写有效提示

专注于**要探索和验证的内容**，而不是规定步骤。ScoutQA 自主决定如何进行测试。

**示例：用户注册流程**

```bash
scoutqa --url "https://example.com" --prompt "
探索用户注册流程。测试表单验证的边缘情况，
验证错误处理，并检查可访问性合规性。
"
```

**示例：电子商务结账**

```bash
scoutqa --url "https://shop.example.com" --prompt "
测试结账流程。验证价格计算、购物车持久化，
支付选项和移动响应性。
"
```

**示例：运行并行测试以实现全面覆盖**

通过在单个消息中发出多个 Bash 工具调用来启动并行测试，每个调用都具有 Bash 工具的 `timeout` 参数设置为 `5000`（毫秒）：

```bash
# 测试 1：身份验证和安全
scoutqa --url "https://app.example.com" --prompt "
探索身份验证：登录/注销、会话处理、密码重置，
以及安全边缘情况。
"

# 测试 2：核心功能（并行运行）
scoutqa --url "https://app.example.com" --prompt "
测试仪表板和主要用户工作流程。验证数据加载，
CRUD 操作和搜索功能。
"

# 测试 3：可访问性（并行运行）
scoutqa --url "https://app.example.com" --prompt "
进行可访问性审核：WCAG 合规性、键盘导航，
屏幕阅读器支持、颜色对比。
"
```

**实现**：发送一个包含三个 Bash 工具调用的消息。对于每个 Bash 工具调用，将 `timeout` 参数设置为 `5000` 毫秒。5 秒后，每个 Bash 调用都会返回任务 ID，而进程继续在后台运行。这从初始输出中捕获了每个测试的执行 ID 和浏览器 URL，然后三个测试并行继续运行（既作为本地后台任务，也在 ScoutQA 的基础设施上远程运行）。

**关键指南**：

- 描述**要测试的内容**，而不是**如何测试**（ScoutQA 会决定步骤）
- 关注目标、边缘情况和关注点
- 运行多个并行执行以测试不同的测试区域
- 信任 ScoutQA 自主探索和发现问题
- 始终将 Bash 工具的 `timeout` 参数设置为 `5000` 毫秒，当调用 scoutqa 命令时（这会在 5 秒后返回控制权，而进程继续在后台运行）
- 对于并行测试，在单个消息中发出多个 Bash 工具调用
- 请记住：Bash 工具超时 ≠ Unix 超时命令（Bash 超时在后台继续进程，Unix 超时会杀死它）

### 常见测试场景

**部署后的冒烟测试：**

```bash
scoutqa --url "$URL" --prompt "
冒烟测试：验证部署后关键功能是否正常工作。
检查主页、导航、登录/注销和关键用户流程。
"
```

**可访问性审核：**

```bash
scoutqa --url "$URL" --prompt "
审核可访问性：WCAG 2.1 AA 合规性、键盘导航，
屏幕阅读器支持、颜色对比和语义 HTML。
"
```

**电子商务测试：**

```bash
scoutqa --url "$URL" --prompt "
探索电子商务功能：产品搜索/过滤、购物车操作，
结账流程和价格计算。
"
```

**SaaS 应用程序：**

```bash
scoutqa --url "$URL" --prompt "
测试 SaaS 应用程序：身份验证、仪表板、CRUD 操作，
权限和数据完整性。
"
```

**表单验证：**

```bash
scoutqa --url "$URL" --prompt "
测试表单验证：边缘情况、错误处理、必填字段，
格式验证和成功提交。
"
```

**移动响应性：**

```bash
scoutqa --url "$URL" --prompt "
检查移动体验：响应式布局、导航，
触摸交互和视口行为。
"
```

**验证已知问题：**

```bash
# 首先，从先前执行中查找问题 ID
scoutqa list-issues --execution-id <executionId>

# 然后，验证问题（会自动创建新的验证执行）
scoutqa issue-verify --issue-id <issueId>
```

`issue-verify` 命令将：

1. 为问题创建验证执行
2. 显示执行 ID 和浏览器 URL
3. 实时流式传输代理的验证进度
4. 显示完成摘要，并提供到结果的链接

**功能验证（实现后）：**

```bash
scoutqa --url "$URL" --prompt "
验证新的 [功能名称] 是否正常工作。测试核心功能，
边缘情况、错误处理和与现有功能的集成。
"
```

**示例：实现功能后的主动测试**

实现用户注册表单后，自动验证它是否正常工作：

```bash
scoutqa --url "http://localhost:3000/register" --prompt "
测试新实现的注册表单。验证：
- 表单验证（电子邮件格式、密码强度、必填字段）
- 错误消息显示正确
- 成功的注册流程
- 边缘情况（重复电子邮件、特殊字符等）
"
```

这会在实现时立即捕获问题，而上下文仍然新鲜。

## 列出问题

使用 `scoutqa list-issues` 浏览先前执行中发现的问题。这对于查找要用于 `issue-verify` 的问题 ID 很有用。

```bash
scoutqa list-issues --execution-id <executionId>
```

**选项：**

- `--execution-id`（必需）：执行 ID（来自 `/t/<executionId>` URL 或 CLI 输出）

**示例输出：**

```
显示 3 个问题：

🔴 019c-abc1
   移动端登录按钮无响应
   严重性：关键 | 类别：可用性 | 状态：打开

🟠 019c-abc2
   电子邮件字段缺少表单验证
   严重性：高 | 类别：功能 | 状态：打开

🟡 019c-abc3
   页脚链接颜色对比不足
   严重性：中 | 类别：可访问性 | 状态：已解决
```

## 呈现结果

### 即时呈现（启动测试后）

在运行 scoutqa 命令后，向用户呈现执行细节：

```markdown
**ScoutQA 测试已启动**

执行 ID: `019b831d-xxx`
查看实时: https://app.scoutqa.ai/t/019b831d-xxx

测试正在远程运行。您可以在上面的链接中通过浏览器查看实时进度，而我在此同时继续处理其他任务。
```

### 最终结果（完成时）

当执行完成时，使用此格式呈现结果：

```markdown
**ScoutQA 测试结果**

执行 ID: `ex_abc123`

**发现的问题:**

[高] 可访问性：标志图像缺少 alt 文本

- 影响：屏幕阅读器无法描述标志
- 位置：页眉导航

[中] 可用性：移动视口中的提交按钮不可见

- 影响：用户无法在移动设备上完成表单
- 位置：联系表单，页面底部

[低] 功能：有效查询的搜索返回无结果

- 影响：搜索功能似乎已损坏
- 位置：主搜索栏

**摘要：** 在可访问性、可用性和功能类别中发现了 3 个问题。有关完整的交互式报告和截图，请访问上面的 URL。
```

始终包括：

- **执行 ID**（例如，`ex_abc123`）以供参考
- **发现的问题**，包括严重性、类别（可访问性、可用性、功能）、影响和位置

## 跟进卡住的执行

如果远程代理卡住或需要澄清，请使用 `send-message` 继续：

```bash
# 示例：代理卡在登录处，用户提供凭证
scoutqa send-message --execution-id ex_abc123 --prompt "
使用这些测试凭证：用户名：testuser@example.com，密码：TestPass123
"

# 示例：代理询问下一个要测试的流程
scoutqa send-message --execution-id ex_abc123 --prompt "
下一个专注于结账流程，跳过愿望清单功能
"
```

## 检查测试结果

ScoutQA 测试在 ScoutQA 的基础设施上远程运行。在用短时​​间超时启动测试以捕获执行 ID 后：

1. 测试继续在远程运行（不是本地作为后台任务）
2. 您可以立即继续其他工作
3. 要稍后检查结果，请访问测试启动时提供的浏览器 URL
4. 或者，使用 `scoutqa get-execution --execution-id <id>` 通过 CLI 获取结果

**最佳实践**：启动测试时，将 Bash 工具的 `timeout` 参数设置为 `5000` 毫秒。5 秒后，Bash 工具返回控制权并带有任务 ID 和执行细节（执行 ID 和浏览器 URL），而测试继续在后台运行。然后您可以继续其他工作，并在需要时通过 ScoutQA 的网站或 CLI 检查结果。

## 故障排除

| 问题                          | 解决方案                                                    |
| ------------------------------ | ----------------------------------------------------------- |
| `command not found: scoutqa`   | 安装 CLI: `npm i -g @scoutqa/cli@latest`                 |
| 认证过期 / 未授权            | 运行 `scoutqa auth login`                                    |
| 测试挂起或需要输入            | 使用 `scoutqa send-message --execution-id`                   |
| 检查测试结果                 | 访问浏览器 URL 或 `scoutqa get-execution --execution-id` |
| 需要用于验证的问题 ID        | 运行 `scoutqa list-issues --execution-id <id>`               |
