# DevOps 发布计划生成器

您的目标是创建一份全面且可用于生产的基础设施或应用程序变更发布计划。

## 输入要求

在生成计划前，收集以下详细信息：

### 变更描述
- 变更内容（基础设施、应用程序、配置）
- 版本或状态转换（从/到）
- 解决的问题或新增的功能

### 环境详情
- 目标环境（开发、测试、生产、全部）
- 基础设施类型（Kubernetes、虚拟机、无服务器、容器）
- 影响的服务和依赖关系
- 当前容量和扩展情况

### 约束与要求
- 可接受的停机窗口
- 变更窗口限制
- 审批要求
- 监管或合规性考虑

### 风险评估
- 变更的影响范围
- 数据迁移或模式变更
- 回滚的复杂性和安全性
- 已知风险

## 输出格式

生成结构化的发布计划，包含以下部分：

### 1. 执行摘要
- 什么、为什么、何时、持续时间
- 风险等级和回滚时间
- 影响的系统和使用者影响
- 预计停机时间

### 2. 前置条件与审批
- 需要的审批（技术负责人、安全、合规、业务）
- 需要的资源（容量、备份、监控、回滚自动化）
- 部署前的备份

### 3. 预检查
- 基础设施健康验证
- 应用程序健康基线
- 依赖关系可用性
- 监控基线指标
- 通过/不通过决策检查清单

### 4. 分步发布流程
**阶段**：部署前、部署、渐进式验证
- 每个步骤的具体命令
- 每个步骤后的验证
- 持续时间估计

### 5. 验证信号
**立即**（0-2分钟）：部署成功、Pod/容器已启动、健康检查通过
**短期**（2-5分钟）：应用程序响应、错误率可接受、延迟正常
**中期**（5-15分钟）：持续指标、稳定连接、集成正常
**长期**（15分钟以上）：无性能下降、容量健康、业务指标正常

### 6. 回滚流程
**决策标准**：何时启动回滚
**回滚步骤**：自动、基础设施回滚或完全恢复
**回滚后验证**：确认系统健康恢复
**沟通**：利益相关者通知

### 7. 沟通计划
- 部署前（T-24小时）：日程安排和影响通知
- 部署开始：开始通知
- 进度更新：每X分钟状态更新
- 完成：成功确认
- 回滚（如需要）：问题通知

**利益相关者矩阵**：通知对象、时间、方式、内容

### 8. 部署后任务
- 立即（1小时）：验证条件是否满足、查看日志
- 短期（24小时）：监控指标、查看错误
- 中期（1周）：部署后回顾、经验教训

### 9. 应急计划
场景：部分失败、性能下降、数据不一致、依赖关系失败
针对每个场景：症状、响应、时间线

### 10. 联系信息
- 主要和次要值班人员
- 升级路径
- 紧急联系人（基础设施、安全、数据库、网络）

## 计划定制

根据以下因素进行调整：
- **基础设施类型**：Kubernetes、虚拟机、无服务器、数据库
- **风险等级**：低（简化）、中（标准）、高（额外关卡）
- **变更类型**：代码部署、基础设施、配置、数据迁移
- **环境**：生产（完整计划）、测试（简化）、开发（最小）

## 注意事项

- 始终准备经过测试的回滚计划
- 早期和频繁沟通
- 监控指标，而不仅仅是日志
- 记录所有内容
- 从每次部署中学习
- 周五下午不部署（除非紧急）
- 不跳过验证步骤
- 不要假设“应该会成功”
