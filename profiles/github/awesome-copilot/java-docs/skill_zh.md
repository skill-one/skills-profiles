# Java 文档 (Javadoc) 最佳实践

- 公共和受保护的成员应使用 Javadoc 注释进行文档化。
- 鼓励对包私有和私有成员进行文档化，特别是当它们比较复杂或不易理解时。
- Javadoc 注释的第一句话是摘要描述。它应该是对方法所做事情的简洁概述，并以句号结尾。
- 使用 `@param` 来表示方法参数。描述以小写字母开头，不以句号结尾。
- 使用 `@return` 来表示方法返回值。
- 使用 `@throws` 或 `@exception` 来文档化方法抛出的异常。
- 使用 `@see` 来引用其他类型或成员。
- 使用 `{@inheritDoc}` 来从基类或接口继承文档。
  - 除非有重大行为变化，在这种情况下，你应该记录这些差异。
- 使用 `@param <T>` 来表示泛型类型或方法中的类型参数。
- 使用 `{@code}` 来表示内联代码片段。
- 使用 `<pre>{@code ... }</pre>` 来表示代码块。
- 使用 `@since` 来指示功能引入的时间（例如，版本号）。
- 使用 `@version` 来指定成员的版本。
- 使用 `@author` 来指定代码的作者。
- 使用 `@deprecated` 来标记一个成员为已弃用，并提供替代方案。
