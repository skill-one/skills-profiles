# 自动化这个

分析一个手动流程的屏幕录制，并为其构建可运行的自动化。

用户录制自己进行重复或繁琐的操作，将视频文件交给你，然后你弄清楚他们在做什么、为什么这么做以及如何将其脚本化。

## 前提条件检查

在分析任何录制之前，请验证所需的工具是否可用。静默运行这些检查，并仅显示问题：

```bash
command -v ffmpeg >/dev/null 2>&1 && ffmpeg -version 2>/dev/null | head -1 || echo "NO_FFMPEG"
command -v whisper >/dev/null 2>&1 || command -v whisper-cpp >/dev/null 2>&1 || echo "NO_WHISPER"
```

- **ffmpeg 是必需的。** 如果缺失，请告知用户：`brew install ffmpeg`（macOS）或其操作系统的等效命令。
- **Whisper 是可选的。** 仅当录制包含旁白时才需要。如果缺失且录制包含音频轨道，建议：`pip install openai-whisper` 或 `brew install whisper-cpp`。如果用户拒绝，则仅进行视觉分析。

## 第一阶段：从录制中提取内容

给定一个视频文件路径（通常在 `~/Desktop/` 上），提取视觉帧和音频：

### 帧提取

每 2 秒提取一帧。这平衡了覆盖范围与上下文窗口限制。

```bash
WORK_DIR=$(mktemp -d "${TMPDIR:-/tmp}/automate-this-XXXXXX")
chmod 700 "$WORK_DIR"
mkdir -p "$WORK_DIR/frames"
ffmpeg -y -i "<VIDEO_PATH>" -vf "fps=0.5" -q:v 2 -loglevel warning "$WORK_DIR/frames/frame_%04d.jpg"
ls "$WORK_DIR/frames/" | wc -l
```

使用 `$WORK_DIR` 作为会话中后续临时文件路径。每次运行时创建的目录权限为 0700，确保提取的帧仅对当前用户可读。

如果录制时间超过 5 分钟（超过 150 帧），将间隔增加到每 4 秒一帧，以保持在上下文限制内。告诉用户你为较长的录制降低了采样频率。

### 音频提取和转录

检查视频是否包含音频轨道：

```bash
ffprobe -i "<VIDEO_PATH>" -show_streams -select_streams a -loglevel error | head -5
```

如果存在音频：

```bash
ffmpeg -y -i "<VIDEO_PATH>" -ac 1 -ar 16000 -loglevel warning "$WORK_DIR/audio.wav"

# 使用可用的 whisper 二进制文件
if command -v whisper >/dev/null 2>&1; then
  whisper "$WORK_DIR/audio.wav" --model small --language en --output_format txt --output_dir "$WORK_DIR/"
  cat "$WORK_DIR/audio.txt"
elif command -v whisper-cpp >/dev/null 2>&1; then
  whisper-cpp -m "$(brew --prefix 2>/dev/null)/share/whisper-cpp/models/ggml-small.bin" -l en -f "$WORK_DIR/audio.wav" -otxt -of "$WORK_DIR/audio"
  cat "$WORK_DIR/audio.txt"
else
  echo "NO_WHISPER"
fi
```

如果两个 whisper 二进制文件都不可用且录制包含音频，通知用户他们缺少旁白上下文，并询问他们是否要安装 Whisper（`pip install openai-whisper` 或 `brew install whisper-cpp`）或仅进行视觉分析。

## 第二阶段：重建流程

分析提取的帧（如果可用，则分析转录内容）以构建对用户所做操作的有序结构理解。按顺序处理帧并识别：

1. **使用的应用程序** — 录制中出现了哪些应用程序？（浏览器、终端、Finder、邮件客户端、电子表格、IDE 等）
2. **操作顺序** — 用户做了什么，按顺序？点击点击、一步步。
3. **数据流** — 什么信息在步骤之间移动？（复制的文本、下载的文件、表单输入等）
4. **决策点** — 用户是否在某些时刻暂停、检查或做出选择？
5. **重复模式** — 用户是否多次使用不同输入执行相同操作？
6. **痛点** — 流程看起来是否缓慢、易出错或繁琐？旁白通常直接揭示了这一点（“我讨厌这一部分”、“这总是要花很长时间”、“我必须对每一个都这样做”）。

将此重建呈现给用户，作为编号步骤列表，并在提出自动化之前请他们确认其准确性。这是至关重要的——错误的理解会导致无用的自动化。

格式：

```
这是我在录制中看到你做的：

1. 打开 Chrome 并导航到 [特定 URL]
2. 使用凭证登录
3. 点击进入报告仪表板
4. 下载 CSV 导出
5. 在 Excel 中打开 CSV
6. 过滤列 B 为 "pending" 的行
7. 将这些行复制到新的电子表格
8. 将新的电子表格通过邮件发送给 [收件人]

你重复了步骤 3-8 三次，用于不同的报告类型。

[如果存在旁白]：你提到导出步骤是最慢的部分，并且你每周一早上都要这样做。

这符合你做的吗？我有什么错误或遗漏？
```

在用户确认重建准确之前，不要继续进行第三阶段。

## 第三阶段：环境指纹

在提出自动化之前，了解用户实际可以使用什么。运行这些检查：

```bash
echo "=== OS ===" && uname -a
echo "=== Shell ===" && echo $SHELL
echo "=== Python ===" && { command -v python3 && python3 --version 2>&1; } || echo "未安装"
echo "=== Node ===" && { command -v node && node --version 2>&1; } || echo "未安装"
echo "=== Homebrew ===" && { command -v brew && echo "已安装"; } || echo "未安装"
echo "=== 常用工具 ===" && for cmd in curl jq playwright selenium osascript automator crontab; do command -v $cmd >/dev/null 2>&1 && echo "$cmd: 是" || echo "$cmd: 否"; done
```

使用此信息将建议限制为用户已经拥有的工具。除非简单的路径确实不起作用，否则永远不要建议需要安装五样新东西的自动化。

## 第四阶段：提出自动化

根据重建的流程和用户的環境，提出最多三个级别的自动化。并非每个流程都需要三个级别——使用判断力。

### 级别结构

**第一级——快速见效（设置时间少于 5 分钟）**
最小的有用自动化。一个 shell 别名、一行代码、一个键盘快捷键、一个 AppleScript 段落。自动化最痛苦的步骤，而不是整个流程。

**第二级——脚本（设置时间少于 30 分钟）**
一个独立的脚本（bash、Python 或 Node——用户拥有的那种）来端到端自动化整个流程。处理常见错误。可以在需要时手动运行。

**第三级——完全自动化（设置时间少于 2 小时）**
第二级的脚本，加上：计划执行（cron、launchd 或 GitHub Actions）、日志记录、错误通知以及任何必要的集成基础结构（API 密钥、认证令牌等）。

### 提案格式

对于每个级别，提供：

```
## 级别 [N]：[名称]

**自动化内容**：[来自重建的哪些步骤]
**保持手动**：[哪些步骤仍然需要人工]
**时间节省**：[每次运行估计节省的时间，基于录制长度和重复次数]
**前提条件**：[需要什么但尚未安装——理想情况下不需要]

**工作原理**：
[2-3 句简单的英文解释]

**代码**：
[完整的、可运行的、带注释的代码——不是伪代码]

**如何测试**：
[验证它是否工作的确切步骤，如果可能的话，从干运行开始]

**如何撤销**：
[如果出了问题，如何撤销任何更改]
```

### 针对特定应用程序的自动化策略

根据录制中出现的应用程序使用这些策略：

**基于浏览器的流程**：
- 首选：检查网站是否有公共 API。API 调用比浏览器自动化可靠 10 倍。搜索 API 文档。
- 第二选择：`curl` 或 `wget` 用于具有已知端点的简单 HTTP 请求。
- 第三选择：Playwright 或 Selenium 用于需要通过 UI 点击的流程。优先使用 Playwright——它更快且更稳定。
- 寻找模式：如果用户反复从仪表板下载相同的报告，几乎肯定可以通过 API 或带有查询参数的直接 URL 获取。

**电子表格和数据流程**：
- Python 与 pandas 用于数据过滤、转换和聚合。
- 如果用户在 Excel 中进行简单的列操作，一个 5 行的 Python 脚本可以取代整个手动流程。
- `csvkit` 用于无需编写代码即可快速进行命令行 CSV 操作。
- 如果输出需要保持 Excel 格式，使用 openpyxl。

**邮件流程**：
- macOS：`osascript` 可以控制 Mail.app 发送带附件的邮件。
- 跨平台：Python `smtplib` 用于发送，`imaplib` 用于读取。
- 如果邮件遵循模板，使用变量替换从模板文件生成正文。

**文件管理流程**：
- Shell 脚本用于移动/复制/重命名模式。
- `find` + `xargs` 用于批量操作。
- `fswatch` 或 `watchman` 用于触发式自动化。
- 如果用户按日期或类型将文件组织到文件夹中，这是一个 3 行的 Shell 脚本。

**终端/CLI 流程**：
- Shell 别名用于频繁输入的命令。
- Shell 函数用于多步骤序列。
- Makefile 用于项目特定的任务集。
- 如果用户使用不同的参数运行相同的命令，这是一个循环。

**macOS 特定流程**：
- AppleScript/JXA 用于控制原生应用程序（Mail、日历、Finder、预览等）。
- Shortcuts.app 用于不需要代码的简单多应用程序流程。
- `automator` 用于基于文件的流程。
- `launchd` plist 文件用于计划任务（macOS 上的首选方案）。

**跨应用程序流程（应用程序之间的数据移动）**：
- 识别数据传输点。每个传输都是一个自动化机会。
- 录制中基于剪贴板的传输表明应用程序之间没有直接通信——寻找 API、基于文件的传输或直接集成。
- 如果用户从 App A 复制并粘贴到 App B，自动化应直接从 A 的数据源读取并写入 B 的输入格式。

### 针对性提案

应用这些原则到每个提案：

1. **首先自动化瓶颈。** 录制中的旁白和计时揭示了实际痛苦的步骤。30 秒的自动化最差的步骤比 2 小时的整个流程自动化更有价值。

2. **匹配用户的技能水平。** 如果录制显示某人熟悉终端，请提出 Shell 脚本。如果显示某人导航 GUI，请提出一个简单的触发器（双击脚本、运行 Shortcut 或输入一个命令）。

3. **估计实际时间节省。** 计算录制时长并乘以他们执行的频率。“这个录制是 4 分钟。你说过你每天都要这样做。每年有 17 小时。第一级将其缩短到每次 30 秒——你每年节省 16 小时。”

4. **处理 80% 的情况。** 第一个版本的自动化应完美覆盖常见路径。边缘情况可以在第三级或标记为手动干预。

5. **保留人工检查点。** 如果录制显示用户在流程中途审查或批准某些内容，请将其保留为手动步骤。不要自动化判断调用。

6. **提出干运行。** 每个脚本都应有一个模式，在其中它显示它*将要*做什么而不实际做。`--dry-run` 标志、预览输出或在执行破坏性操作之前进行确认提示。

7. **考虑认证和密钥。** 如果流程涉及登录或使用凭证，永远不要硬编码它们。使用环境变量、密钥链访问（macOS `security` 命令）或在运行时提示它们。

8. **考虑失败模式。** 如果网站宕机怎么办？如果文件不存在？如果格式更改？好的提案会提及这些并处理它们。

## 第五阶段：构建和测试

当用户选择一个级别时：

1. 将完整的自动化代码写入文件（建议一个合理的位置——如果用户有项目目录，则将其放在用户的目录中，否则放在 `~/Desktop/`）。
2. 与用户一起进行干运行或测试。
3. 如果测试通过，展示如何实际运行它。
4. 如果失败，诊断并修复——不要在第一次尝试后放弃。

## 清理

分析完成后（无论结果如何），清理提取的帧和音频：

```bash
rm -rf "$WORK_DIR"
```

告诉用户你正在清理临时文件，以便他们知道没有遗留任何东西。
