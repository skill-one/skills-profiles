# 重构计划

在进行任何代码更改之前，创建一个详细的计划。

## 说明

1. 在准备计划时，不要编辑文件。
2. 搜索代码库以了解当前状态。阅读足够的实现、测试、配置和文档，以便使计划针对存储库特定。
3. 确定受影响的文件、所有权边界、依赖关系和可能的隐藏耦合。
4. 按安全顺序计划更改。优先考虑合同和类型，然后是实现，然后是调用者，然后是测试，然后是清理。
5. 在每个阶段之间包含验证步骤和一个最终验证命令。
6. 对风险最高的阶段包含回滚或恢复步骤。
7. 使用以下格式输出完整计划。
8. 在计划之后停止，并在实施之前请求确认。如果用户已经要求你实施，仍然先生成计划并等待确认，除非他们明确表示在计划之后无需审查即可继续。

如果请求过于模糊，无法安全地计划，则应提出简洁的澄清问题，而不是编辑文件。

## 输出格式

```markdown
## 重构计划：[标题]

### 当前状态
[当前工作方式的简要描述]

### 目标状态
[重构后工作方式的简要描述]

### 受影响的文件
| 文件 | 更改类型 | 依赖关系 |
|------|-------------|--------------|
| path | 修改/创建/删除 | 块 X，被 Y 阻塞 |

### 执行计划

#### 阶段 1：类型和接口
- [ ] 步骤 1.1：在 `file.ts` 中执行 [操作]
- [ ] 验证：[如何检查是否生效]

#### 阶段 2：实现
- [ ] 步骤 2.1：在 `file.ts` 中执行 [操作]
- [ ] 验证：[如何检查]

#### 阶段 3：测试
- [ ] 步骤 3.1：在 `file.test.ts` 中更新测试
- [ ] 验证：运行 `npm test`

#### 阶段 4：清理
- [ ] 移除过时代码
- [ ] 更新文档

### 回滚计划
如果出现故障：
1. [撤销步骤]
2. [撤销步骤]

### 风险
- [潜在问题和缓解措施]

```

计划之后，询问：“是否继续执行阶段 1？”
