# 技术产品定价


## 初步评估

在推荐定价之前，需要了解：

1. **产品类型**：API/平台、开发者工具、SaaS应用程序、基础设施？
2. **当前定价**：你现在收取多少费用？已经这样多久了？
3. **GTM策略**：自助服务、销售辅助、企业级或混合模式？
4. **成本结构**：每个客户/用户/单位的边际成本是多少？
5. **竞争格局**：替代方案的成本是多少？（包括“不做任何事”的情况）

---

## 核心框架

### 1. 没人注意到的价格涨幅（你很可能定价过低）

**模式：**

平台公司，成长阶段。自发布以来定价一直未变。企业客户每年支付15,000美元购买的产品可为他们节省200,000美元以上的工程时间。

领导层争论：“如果我们提高价格，我们会失去客户。”

**实际发生的情况：**

将企业级套餐从每年15,000美元提高到45,000美元。增加了专属支持、SSO、审计日志来证明这一涨幅的合理性。

失去：0个企业客户。零。

获得：每个企业账户收入增加3倍。此外，留下的客户开始更认真地使用产品——更高的采用率，更多的内部拥护者，更多的扩展。

**为什么会发生这种情况：**

技术创始人将定价锚定在成本上（“服务他们的成本是X美元，所以我们收取2X美元”）。企业买家将定价锚定在价值上（“这能为我们节省200,000美元，所以45,000美元很便宜”）。

**定价合理性检查：**

针对每个客户群体，计算：

```
价值比率 = 客户的替代成本 / 你的价格

如果价值比率 > 10倍 → 你定价严重过低
如果价值比率 > 5倍  → 你定价过低（大多数初创公司都在这个阶段）
如果价值比率 3-5倍  → 健康的定价
如果价值比率 < 3倍  → 接近天花板
如果价值比率 < 2倍  → 你定价过高（需要强大的差异化）
```

**如何计算替代成本：**

- 手动流程花费的小时数 × 每小时费率 × 频率
- 内部建设的成本（工程师 × 月数 × 加载成本）
- 现有工具的成本 + 转换成本 + 过渡期间的生产力损失
- 不解决问题的成本（事件、停机时间、客户流失）

**常见错误：**

将你的价格与竞争对手进行比较，而不是与客户的替代成本进行比较。竞争对手会让你陷入价格战。价值会让你专注于客户实际节省的成本。

### 2. 三种定价模型（以及每种何时失效）

**模型1：按席位收费（$X/用户/月）**

**适用情况：**

- 价值随用户数量增加（协作工具、通信）
- 使用情况在用户之间相对均匀
- 你希望获得可预测的收入

**失效情况：**

- 高端用户和普通用户支付相同价格（普通用户流失）
- 产品价值不随席位增加（一个管理员为1,000个用户配置）
- 客户合并席位以降低成本（使用量增加，收入不增加）

**模型2：按使用量收费（$X/单位）**

**适用情况：**

- 使用量因客户差异很大（API调用、计算、存储）
- 边际成本有意义（你需要使用量来跟踪收入）
- 价值直接与使用量相关

**失效情况：**

- 客户无法预测账单（月底价格惊吓）
- 低使用量客户不值得支持
- 高使用量客户谈判批量折扣压缩利润

**模型3：按结果收费（$X/结果）**

**适用情况：**

- 你可以可靠地衡量结果（生成的线索、解决的工单、部署的代码）
- 结果直接为客户创造价值
- 你对你的产品效果有信心

**失效情况：**

- 结果取决于你无法控制的因素
- 衡量结果存在争议（“那个线索不是来自你的工具”）
- 客户操纵指标

**通常获胜的混合模式：**

平台费（覆盖你的固定成本）+ 使用量/结果可变费（随价值扩展）。

示例：500元/月基础费 + 0.05元/交易（或API调用、完成的任务、处理的记录——你的价值单位是什么）。

为什么这有效：

- 基础费确保每个客户覆盖服务成本
- 可变费与价值对齐
- 客户可以预测最低支出（基础费），同时自然扩展
- 当客户增长时，你捕获增长带来的收益

### 3. 免费增值阈值设计（免费与付费的界限）

**模式：**

开发者工具中最难的定价决策：免费和付费的界限在哪里？

**框架：找到生产边界**

从未付费的免费用户很好——他们创造了意识、社区和内容。问题在于生产用户从未付费。

**如何找到边界：**

绘制你的使用量分布：

```
使用量级别          | 用户类型        | 付费意愿
─────────────────────────────────────────────────────────────
<100单位/月        | 爱好者/学习者   | $0（永远不会付费）
100-1K单位/月      | 侧项目         | $0-20/月（可能）
1K-10K单位/月      | 生产使用       | $50-200/月（会付费）
>10K单位/月        | 业务关键       | $200-2K/月（必须付费）
```

**将你的免费套餐限制设置在生产使用开始之前。** 在这个例子中：1,000单位/月免费。

为什么：爱好者和学习者保持免费（他们是你的营销引擎）。生产用户自然达到限制并转化（他们有预算）。

**三种免费到付费的触发器类型：**

**1. 使用量限制**（平台最常见）
- 免费：1,000单位/月（API调用、任务、记录、你的价值单位是什么）
- 触发器：生产使用超过限制
- 转化信号：用户正在构建真实的东西

**2. 团队/协作门禁**（工具最佳）
- 免费：个人使用
- 触发器：用户邀请第二个人
- 转化信号：工具足够有价值可以分享

**3. 企业功能门禁**（平台最佳）
- 免费：核心功能
- 触发器：需要SSO、RBAC、审计日志、SLA
- 转化信号：IT/安全部门参与（真实部署）

**常见错误：**

将免费套餐设置过高（“我们希望开发者喜欢我们”）。如果生产用户没有达到限制，他们永远不会转化。免费套餐中的慷慨应该针对*学习者*，而不是*生产用户*。

### 4. 企业级定价（对话，而不是数字）

**模式：**

企业级定价不是你网站上的一个页面。它是一场对话。存在“联系销售”按钮，因为企业交易有独特的要求——而且你应该基于价值定价，而不是菜单。

**企业级定价变量：**

**1. 部署模式**（自助服务云、专用云、本地、混合）
- 每种模式的服务成本不同 → 不同价格底线
- 本地部署比云贵2-5倍（支持复杂性）

**2. 使用量规模**（席位、API量、数据量）
- 批量折扣不应低于服务成本+40%的利润
- 批量折扣应基于列表价格，而不是已折扣价格

**3. 支持级别**（社区、标准、高级、专属）
- 高级支持：基础价格的1.5-2倍
- 专属CSM：基础价格的2-3倍
- 7x24小时支持带SLA：基础价格的3-5倍

**4. 合规要求**（SOC 2、HIPAA、FedRAMP、数据驻留）
- 每种合规要求增加真实成本（审计、基础设施、流程）
- 相应定价：基础价格的1.5-2倍每个合规标准

**企业级定价对话：**

当潜在客户说“成本是多少？”时：

1. **不要直接回答数字。** 回答一个问题：“这取决于你的部署和规模需求。请帮助我了解你需要什么。”

2. **映射他们的需求：**
   - 用户数/席位/单位有多少？
   - 云或本地？
   - 合规需求？
   - 支持期望？
   - 集成需求？

3. **在展示价格之前锚定价值：**
   - “根据你的描述，你目前在这个问题上花费[X]。我们的解决方案通常可以节省[Y%]。”
   - 然后展示价格作为节省金额的一部分。

4. **展示3个选项：**
   - 好：满足最低要求
   - 更好：满足要求+锦上添花（在此处锚定）
   - 最佳：所有内容，包括他们没有要求的东西
   - 大多数买家会选择更好。这就是你的真实价格。

**常见错误：**

在网站上发布企业级定价。一旦你发布一个数字，那就是天花板——谈判只能往下走。将企业级定价保持为对话。

### 5. 定价作为定位信号

**模式：**

你的价格告诉买家你是为谁服务的。这既是一个定位决策，也是一个收入决策。

**价格信号：**

**$0（开源/免费套餐）：**
- 信号：我们是为希望先试用再购买的开发者
- 吸引：个人贡献者、实验者
- 风险：被视为“不适合企业级”

**$20-100/月：**
- 信号：我们是为团队和小型企业
- 吸引：自助服务买家、初创公司
- 风险：企业级不会认真对待你（太便宜）

**$500-2,000/月：**
- 信号：我们是为生产工作负载
- 吸引：有真实预算的成熟公司
- 风险：初创公司被定价排除（可能需要免费套餐）

**$5,000-50,000/年：**
- 信号：我们是为企业级
- 吸引：中市场和企业级
- 风险：需要销售团队（不能自助服务）

**$100K+/年：**
- 信号：我们是为关键基础设施
- 吸引：大型企业
- 风险：长销售周期、高支持期望

**定位测试：**

如果你定价50/月，但想吸引企业级客户，你的价格正在削弱你的定位。企业级买家将低价与低价值联系起来。你可能需要*提高*价格来吸引你想要的客户。

**常见错误：**

为现有客户定价，而不是为想要的客户定价。如果你的路线图是面向企业级，定价要面向企业级——即使这意味着今天会失去一些SMB客户。

---

### 6. 何时以及如何提高价格

**时机信号：**

- 大多数客户的价值比率 > 5倍
- 赢率 > 40%（你不会因为价格而输掉交易）
- 过去6个月客户没有对定价提出异议
- 客户扩展速度超过预期
- 竞争对手提高价格且未失去份额

**如何在不失去客户的情况下提高价格：**

**1. 为现有客户提供祖父条款**（12-24个月）
- 新客户只适用新定价
- 现有客户获得通知+时间表
- 为潜在客户创造紧迫感（“价格要上涨”）

**2. 增加价值以证明涨幅**
- 新套餐带新功能，价格更高
- 将当前套餐功能移至新的更高套餐
- 这不是简单的价格上涨，而是重新定位

**3. 合同中包含年度增长条款**
- 在企业级合同中包含5-10%的年度递增条款
- 规范价格增长
- 防止“我们已经付了4年的相同费用”的对话

**沟通：**

“我们正在投资于[具体改进]。为了继续这种级别的投资，我们将在[日期]更新我们的定价。您当前的套餐将在[祖父日期]之前锁定在当前价格。”

永远不要为提高价格道歉。将其视为对产品他们喜爱的投资。

## 决策树

### 哪种定价模型？

```
使用量在客户之间差异 >5倍？
├─ 是 → 按使用量收费（或带使用量组件的混合模式）
└─ 否 → 继续...
    │
    价值是否随团队规模增加？
    ├─ 是 → 按席位收费
    └─ 否 → 继续...
        │
        能否可靠地衡量客户结果？
        ├─ 是 → 按结果收费（或混合模式）
        └─ 否 → 平台费+功能级套餐
```

### 我们是否应该提高价格？

```
大多数客户的价值比率 > 5倍？
├─ 是 → 提高价格
└─ 否 → 继续...
    │
    赢率 > 40%？
    ├─ 是 → 价格不是问题，但考虑提高
    └─ 否 → 继续...
        │
        你是否因为价格而输掉交易？
        ├─ 是 → 不要提高。提高价值或更好细分。
        └─ 否 → 其他地方有问题（产品、定位、销售）
```
