# WorkIQ 协作助手技能

## 概述

WorkIQ（公共预览版）允许协作助手使用自然语言查询 Microsoft 365 数据。它支持日程安排、文档、Teams 消息、电子邮件线程、跟进跟踪、利益相关者摘要等。当任务需要本地知识库之外的实时组织智能时，请使用此技能。

## 支持的数据及示例提示

- **电子邮件** – “总结 Sarah 关于预算的电子邮件。”
- **会议** – “我这周有哪些即将到来的会议？”
- **文档** – “查找关于 Q4 规划的最新文档。”
- **Teams** – “总结今天工程频道的消息。”
- **人员/项目** – “谁正在负责 Alpha 项目？”

## 获取访问权限

1. **协作助手 CLI 插件（推荐）**
   - `copilot`
   - `/plugin marketplace add github/copilot-plugins`
   - `/plugin install workiq@copilot-plugins`
   - 重启协作助手 CLI。
2. **独立 CLI / MCP 服务器**
   - `npm install -g @microsoft/workiq`（或 `npx -y @microsoft/workiq mcp`）。
   - 运行 `workiq mcp` 以暴露 MCP 工具（如果需要）。
3. **租户授权**
   - 首次使用提示进行 Microsoft 365 管理员授权（最终用户许可协议 + 权限）。非管理员必须联系租户管理员根据租户管理员启用指南进行批准。

## 预飞行检查清单

- 运行 `Get-Command workiq` 以确保二进制文件可用。
- 通过 `workiq accept-eula` 接受最终用户许可协议一次。
- 确认正确的租户（如果与默认 `common` 不同，请使用 `-t <tenant-id>`）。
- 准备好在提示时在浏览器中完成设备登录。

## 核心工作流程

1. **明确意图** – 议程、行动项、文档查找、人员搜索、风险摘要等。
2. **编写精确提示** – 包括时间段、来源或主题（例如，“总结今天 #eng 中的 Teams 帖子”）。
3. **运行命令** – `workiq ask --question "<提示>"`（如果需要，可以使用 `-q` 简写）。
4. **监控执行** – 长答案可能会分批发送；在发出附加请求之前，请等待响应完成。
5. **总结和编辑** – 突出见解，记录冲突/任务，除非需要，否则避免粘贴原始链接。
6. **提供后续行动** – 阻塞时间、起草笔记、更深入的查询等。

## 命令参考

| 命令                           | 目的                                                       |
| --------------------------------- | ------------------------------------------------------------- |
| `workiq --help`                   | 显示全局选项。                                          |
| `workiq version`                  | 显示安装的版本。                                    |
| `workiq accept-eula`              | 接受许可（首次使用）。                                   |
| `workiq ask`                      | 交互模式。                                             |
| `workiq ask --question "..."`     | 提出一个具体的问题（如果需要，可以使用 `-q` 简写）。    |
| `workiq ask -t <租户> -q "..."` | 目标特定租户。                                     |
| `workiq mcp`                      | 启动 MCP stdio 服务器（将 WorkIQ 工具暴露给其他代理）。 |

## 提示模式

- 议程：“我明天日历上有哪些安排？”
- 行动项：“总结今天客户同步会议的跟进事项。”
- 文档：“列出关于 Contoso FY26 路线的 PowerPoint。”
- 沟通：“我的经理对截止日期说了什么？”
- 见解：“过去三次会议中出现了哪些阻塞？”
- 规划：“建议周二下午的专注时间段。”

## 响应指南

- 保持摘要简洁（2-3 句话），突出负载、优先级、阻塞和可选的下一步行动。
- 除非用户需要链接，否则不要具体引用会议/文档。
- 如果 WorkIQ 可以继续，请提及（例如，“WorkIQ 可以显示周四至周日，如果需要”）。
- 将 WorkIQ 建议的行动映射到明确的提议（阻塞时间、发送跟进、请求录制、运行更深入的查询）。

## 最佳实践

- 优先使用狭窄的提示以减少噪音；如果需要，请运行多个查询。
- 逻辑组合输出（议程 + 冲突 + 行动项）后再回复。
- 尊重隐私：除非明确请求，否则不要暴露与会者列表或机密片段。
- 记录运行了哪些命令，以便未来的步骤可以参考它们（“询问 WorkIQ 获取议程 + 冲突”）。
- 使用 MCP 模式（`workiq mcp`）当另一个代理/工作流需要直接工具访问时。

## 故障排除

- **缺少 CLI** – 通过 npm 安装或确保 PATH 设置正确；如果不可用，请通知用户。
- **授权/认证错误** – 管理员授予权限后重新运行命令或完成设备登录后。
- **长/不完整输出** – 使用更精确的范围重新运行或询问特定数据片段（按天/项目/人员）。
- **命令挂起** – 在终端中取消正在运行的命令（例如，使用 Ctrl+C）或重启协作助手 CLI 会话，然后重试；确保浏览器登录完成。

## 提供后续行动

- 在建议的时间阻塞专注/溢出时段。
- 起草重新安排/拒绝消息，并参考 WorkIQ 指导。
- 请求重叠会议的录制或摘要。
- 将行动项捕获到任务跟踪器。
- 运行额外的 WorkIQ 查询（按项目、利益相关者、时间段）进行更深入的分析。
