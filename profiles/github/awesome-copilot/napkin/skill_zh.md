# Napkin — Copilot CLI的视觉白板

Napkin为用户提供了一个基于浏览器的白板，他们可以在上面绘画、草图，并添加便利贴来直观地思考想法。代理会读取白板内容（通过PNG快照和可选的JSON数据），并以对话方式进行分析、建议和下一步行动进行回应。

目标用户是律师、产品经理和业务利益相关者——而不是软件开发者。保持一切平易近人，避免使用术语。

---

## 激活

当用户调用此技能——说“让我们用Napkin”、“打开一个Napkin”、“开始一个白板”，或使用斜杠命令时——执行以下操作：

1. **将捆绑的HTML模板从技能资源复制到用户的桌面。**
   - 模板位于相对于此SKILL.md文件的`assets/napkin.html`。
   - 复制到`~/Desktop/napkin.html`。
   - 如果`~/Desktop/napkin.html`已存在，询问用户是否要打开现有的文件还是重新开始，然后再覆盖。

2. **在默认浏览器中打开它：**
   - macOS: `open ~/Desktop/napkin.html`
   - Linux: `xdg-open ~/Desktop/napkin.html`
   - Windows: `start ~/Desktop/napkin.html`

3. **告诉用户下一步该做什么。说一些温暖而简单的话：**

   ```
   您的白板已在浏览器中打开！

   绘画、草图或添加便利贴——任何有助于您思考想法的内容。

   当您准备好我的输入时，点击白板上的绿色“与Copilot共享”按钮，然后回到这里并说“查看白板”。
   ```

## 读取白板

当用户说“查看白板”、“看看白板”、“您觉得呢”、“读取我的白板”或任何类似内容时，按照以下步骤操作：

### 第一步——读取PNG快照（主要）

查找名为`napkin-snapshot.png`的PNG文件。按顺序检查以下位置（浏览器将其保存到用户的默认下载文件夹，该文件夹因人而异）：

1. `~/Downloads/napkin-snapshot.png`
2. `~/Desktop/napkin-snapshot.png`

使用`view`工具读取PNG。这会将图像作为base64编码的数据发送到模型，模型可以对其进行视觉解释。PNG是代理理解用户绘制内容的**主要**方式——它捕获自由手绘草图、箭头、空间布局、注释、圈出或划掉的项目以及画布上的任何其他内容。

如果两个位置都找不到PNG，请**不要**默默跳过。相反，告诉用户：

```
我还没有看到您白板的快照。请这样做：

1. 前往浏览器中的白板
2. 点击绿色“与Copilot共享”按钮
3. 回到这里并再次说“查看白板”

该按钮会保存我可以查看的截图。
```

### 第二步——读取剪贴板中的结构化JSON（补充）

也尝试从系统剪贴板获取结构化的JSON数据。白板会自动复制这些数据与PNG一起。

- macOS: `pbpaste`
- Linux: `xclip -selection clipboard -o`
- Windows: `powershell -command "Get-Clipboard"`

JSON包含便利贴和文本标签的确切文本内容、它们的位置和颜色。这通过提供可能难以从截图读取的精确文本来补充PNG。

如果剪贴板不包含JSON数据，那没关系——PNG本身就为模型提供了足够的信息。**不要**将剪贴板的缺失视为错误。

### 第三步——综合两种来源

将视觉快照和结构化文本综合起来，形成对用户想法或计划的连贯理解：

- **从PNG中：** 描述您看到的内容——草图、图表、流程图、分组、箭头、空间布局、注释、圈出的项目、划掉的项目、强调标记。
- **从JSON中：** 读取便利贴和标签的确切文本内容，注意它们的位置和颜色。
- **将两者结合起来**，形成单一的、对话式的解释。

### 第四步——对话式回应

不要直接显示原始数据或技术摘要。像一位查看过他人白板草图的合作者一样进行回应。示例：

- "我看到您绘制了一个三阶段流程——看起来您正在思考[X]流向[Y]，然后是[Z]。角落里的便利贴写着'[文本]'——您希望我解决这个顾虑吗？"
- "看起来您将这四个想法组合在左侧，并将它们与右侧的两个项目分开。您是否认为这些是两个不同的类别？"
- "我看到您绘制了连接[A]到[B]再到[C]的箭头——这是您设想的流程吗？"

### 第五步——询问下一步

始终以提供下一步行动结束：

- "想让我在此基础上继续吗？"
- "我应该将其转换为结构化文档吗？"
- "想让我将建议添加到白板吗？"

---

## 在白板上回应

当用户希望代理将内容添加回白板时：

- 代理**不能**直接修改HTML文件的画布状态——这由浏览器中运行的JavaScript管理。
- 相反，提供实用的替代方案：
  - 在CLI中提供回应，并建议用户手动将其添加到白板。
  - 提供基于从白板中解释的内容创建单独文档（Markdown、备忘录、清单等）的选项。
  - 如果合理，创建一个预加载内容的`napkin.html`更新副本。

---

## 语气和风格

- 使用与noob-mode技能相同的平易近人、非技术性语气。
- **不要**在不用普通英语解释的情况下使用开发者术语。
- 将白板视为一个创意、协作的空间——而不是正式的输入机制。
- 无论艺术质量如何，都要鼓励用户的草图。
- 将回应视为“基于您的思考”，而不是“分析您的输入”。

## 错误处理

**未找到PNG快照：**

```
我还没有看到您白板的快照。请这样做：

1. 前往浏览器中的白板
2. 点击绿色“与Copilot共享”按钮
3. 回到这里并再次说“查看白板”

该按钮会保存我可以查看的截图。
```

**桌面不存在白板文件：**

```
看起来我们还没有开始一个白板。想让我为您打开一个吗？
```

## 重要提示

- PNG解释是**主要**渠道。多模态模型可以读取并解释`view`工具返回的base64图像数据。
- JSON剪贴板数据是**补充**——它提供精确的文本，但无法捕获自由手绘。
- 始终首先检查PNG。如果找不到，提示用户点击“与Copilot共享”。
- 如果剪贴板没有JSON数据，则单独使用PNG继续。
- HTML模板位于相对于此SKILL.md文件的`assets/napkin.html`。
- 走廊图像`assets/step1-activate.svg`、`assets/step2-whiteboard.svg`、`assets/step3-draw.svg`、`assets/step4-share.svg`和`assets/step5-response.svg`是文档插图，不是运行时输入。
- 如果noob-mode技能也处于活动状态，则在请求文件或bash权限时使用其风险指示器格式（绿色/黄色/红色）。
