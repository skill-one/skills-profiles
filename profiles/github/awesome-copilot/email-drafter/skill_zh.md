# 邮件撰写助手

根据您既定的写作风格和语气，起草专业的邮件。使用 WorkIQ 分析您发送的邮件和与收件人的先前往来，然后生成您可审阅和完善的上下文感知草稿。

## 使用场景

- "为 [人名] 起草关于 [主题] 的邮件"
- "给 [客户] 写一封关于 [项目] 的跟进邮件"
- "回复 [人名] 的邮件，主题为 [内容]"
- "为 [计划] 起草提案邮件"
- "分析我与 [收件人] 的邮件语气"

## 工作流程

### 第一步 — 收集上下文

起草前，收集以下信息：

1. **收件人** — 邮件是写给谁？
2. **目的** — 邮件是关于什么？(提案、跟进、技术指导、介绍、状态更新等)
3. **要点** — 需要传达什么信息？
4. **关系背景** — 如果可用，使用 WorkIQ 检查与收件人的先前邮件往来

如果用户提前提供所有这些信息，则直接进行。否则，提出最多 3 个澄清问题。

### 第二步 — 分析语气

为收件人起草时，使用 WorkIQ 了解用户的既定沟通模式：

1. 从用户发送给同一收件人或类似收件人的 3-5 封最近邮件中提取
2. 识别模式：
   - **问候风格** — 正式 ("Dear")、标准 ("Hello")、随意 ("Hi") 或直接 (无问候)
   - **结构** — 短段落 vs. 项目符号列表 vs. 编号步骤
   - **结束语** — 用户通常使用的结束语和姓名格式
   - **正式程度** — 专业、友好专业、随意
   - **语言** — 用户与该收件人使用哪种语言
3. 将这些模式应用于草稿

如果 WorkIQ 不可用或没有先前邮件，则使用合理的专业默认值，并注明语气是推断的。

### 第三步 — 起草邮件

应用发现的（或默认的）风格规则：

**问候语：**
- 匹配第二步中发现的问候风格
- 默认：对外部收件人使用 "Hello [FirstName],"，对内部收件人使用 "Hi [FirstName],""
- 对多个收件人：使用 "Hello [Name1], [Name2],"

**语气：**
- 直接简洁 — 无填充语言
- 友好但专业
- 快速切入重点
- 在适当的地方主动提供帮助 ("很乐意进一步讨论"，"如果您需要任何帮助，请告知")

**结构：**
- 短邮件 (1-2 个要点)：简单段落，无需项目符号
- 长邮件 (提案、多要点更新)：使用项目符号或编号列表
- 在相关时包含先前对话的背景信息 ("根据我们最近的关于...的对话")

**结束语：**
- 匹配用户在第二步中建立的结束语模式
- 默认：在下一行使用 "Best regards,"，然后是用户的名字

**语言：**
- 默认为英语，除非用户指定其他语言
- 如果先前往来使用其他语言，则匹配收件人的语言

### 第四步 — 输出

1. 带有简要说明（说明应用的语气/风格）的草稿审阅
2. 根据用户的要求进行编辑 — 迭代直到满意
3. 将最终草稿保存到 `outputs/<年>/<月>/`，使用描述性文件名（例如，`2026-03-26-email-acme-followup.md`）

## 重要规则

- **永远不要发送邮件** — 仅作为文件为用户提供审阅和手动发送的草稿
- 当可用时，始终使用 WorkIQ 检查与收件人的先前上下文
- 如果用户说 "起草邮件" 或 "写邮件"，则自动激活此技能
- 使用 `outputs/<年>/<月>/` 文件夹约定保存草稿
- 尊重隐私：不要包含来自无关邮件线程的敏感信息

## 示例提示

- "为 Sarah 起草关于项目时间表的邮件"
- "给客户写一封关于他们迁移问题的跟进邮件"
- "为新的培训计划起草提案邮件"
- "回复 John 的邮件 — 同意他的方法，但建议我们添加监控"
- "分析我与 Acme 团队的邮件语气"

## 要求

- **WorkIQ MCP 工具** 推荐用于语气分析和收件人上下文（Microsoft 365 / Outlook）
- 没有 WorkIQ，该技能仍然可以工作，但使用专业默认值而不是个性化语气匹配
- 输出保存为工作区中的 Markdown 文件
