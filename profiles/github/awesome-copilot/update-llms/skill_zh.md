# 更新 LLMs.txt 文件

更新存储库根目录中现有的 `llms.txt` 文件，以反映文档、规范或存储库结构的变更。该文件为大型语言模型（LLMs）提供高级指导，告知它们在哪里可以找到相关内容，以理解存储库的目的和规范。

## 主要指令

更新现有的 `llms.txt` 文件，以保持准确性和与 llms.txt 规范的合规性，同时反映当前的存储库结构和内容。该文件必须保持针对 LLM 消费进行优化，同时保持人类可读性。

## 分析和规划阶段

在更新 `llms.txt` 文件之前，您必须完成彻底的分析：

### 第 1 步：审查当前文件和规范
- 阅读现有的 `llms.txt` 文件以了解当前结构
- 审查 https://llmstxt.org/ 上的官方规范，以确保持续合规
- 根据存储库变更，确定可能需要更新的区域

### 第 2 步：存储库结构分析
- 使用适当工具检查当前存储库结构
- 将当前结构与现有 `llms.txt` 中记录的结构进行比较
- 确定应包含的新目录、文件或文档
- 记录任何已删除或迁移的文件，这些文件需要更新

### 第 3 步：内容发现和变更检测
- 确定新的 README 文件及其位置
- 查找新的文档文件（`/docs/`、`/spec/` 等目录中的 `.md` 文件）
- 定位新的规范文件及其目的
- 发现新的配置文件及其相关性
- 查找新的示例文件和代码示例
- 确定现有文档结构的任何变更

### 第 4 步：创建更新计划
根据您的分析，创建一个结构化的计划，包括：
- 维持准确性的变更
- 需要添加到 llms.txt 的新文件
- 需要删除或更新的过时引用
- 保持清晰性的组织改进

## 实施要求

### 格式合规性
更新的 `llms.txt` 文件必须按照规范保持此确切结构：

1. **H1 标题**：单行包含存储库/项目名称（必需）
2. **Blockquote 摘要**：块引用格式的简短描述（可选但推荐）
3. **附加详细信息**：零个或多个无标题的 markdown 部分用于提供上下文
4. **文件列表部分**：零个或多个包含 markdown 链接列表的 H2 部分

### 内容要求

#### 必要元素
- **项目名称**：作为 H1 的清晰、描述性标题
- **摘要**：解释存储库目的的简洁块引用
- **关键文件**：按类别组织的必要文件（H2 部分）

#### 文件链接格式
每个文件链接必须遵循：`[描述性名称](相对 URL)：可选描述`

#### 部分组织
将文件组织成逻辑 H2 部分，例如：
- **文档**：核心文档文件
- **规范**：技术规范和要求
- **示例**：示例代码和使用示例
- **配置**：设置和配置文件
- **可选**：次要文件（特殊含义 - 可以跳过以缩短上下文）

### 内容指南

#### 语言和风格
- 使用简洁、清晰、无歧义的语言
- 避免无解释的术语
- 为人类和 LLM 读者编写
- 在描述中保持具体和有信息量

#### 文件选择标准
包含以下文件：
- 解释存储库的目的和范围
- 提供基本技术文档
- 展示使用示例和模式
- 定义接口和规范
- 包含配置和设置说明

排除以下文件：
- 仅为实现细节的文件
- 包含冗余信息的文件
- 构建工件或生成内容
- 与理解项目无关的文件

## 执行步骤

### 第 1 步：当前状态分析
1. 彻底阅读现有的 `llms.txt` 文件
2. 完全检查当前存储库结构
3. 将现有文件引用与实际存储库内容进行比较
4. 确定过时、缺失或错误的引用
5. 记录当前文件的结构问题

### 第 2 步：内容规划
1. 确定主要目的陈述是否需要更新
2. 如有必要，审查和更新摘要块引用
3. 规划新文件和目录的添加
4. 规划过时或已移动内容的删除
5. 如有必要，重新组织部分以增强清晰性

### 第 3 步：文件更新
1. 更新存储库根目录中的现有 `llms.txt` 文件
2. 保持与确切格式规范的合规性
3. 添加新的文件引用并附上适当的描述
4. 删除或更新过时的引用
5. 确保所有链接都是有效的相对路径

### 第 4 步：验证
1. 验证持续符合 https://llmstxt.org/ 规范
2. 检查所有链接是否有效且可访问
3. 确保文件仍然作为有效的 LLM 导航工具
4. 确认文件保持人类和机器可读

## 质量保证

### 格式验证
- ✅ H1 标题包含项目名称
- ✅ Blockquote 摘要（如果包含）
- ✅ 用于文件列表的 H2 部分
- ✅ 正确的 markdown 链接格式
- ✅ 无损坏或无效链接
- ✅ 全程保持一致的格式

### 内容验证
- ✅ 清晰、无歧义的语言
- ✅ 全面覆盖必要文件
- ✅ 内容的逻辑组织
- ✅ 适当的文件描述
- ✅ 作为有效的 LLM 导航工具

### 规范合规性
- ✅ 精确遵循 https://llmstxt.org/ 格式
- ✅ 使用所需的 markdown 结构
- ✅ 适当实施可选部分
- ✅ 文件位于存储库根目录（`/llms.txt`）

## 更新策略

### 添加过程
添加新内容时：
1. 确定新文件的正确部分
2. 为链接创建清晰、描述性的名称
3. 编写简洁但信息量丰富的描述
4. 在部分内保持字母顺序或逻辑顺序
5. 考虑是否需要为新的内容类型添加新部分

### 删除过程
删除过时内容时：
1. 验证文件是否确实已删除或迁移
2. 检查是否应更新而不是删除已迁移的文件
3. 如果部分变为空，则删除整个部分
4. 如有必要，更新交叉引用

### 重新组织过程
重新组织内容时：
1. 保持从一般到具体的逻辑流程
2. 将核心文档保留在主要部分
3. 如有必要，将次要内容移至“可选”部分
4. 确保新的组织改进 LLM 导航

> [简洁描述存储库的目的和范围]

## 成功标准

更新的 `llms.txt` 文件应：
1. 准确反映当前的存储库结构和内容
2. 保持与 llms.txt 规范的合规性
3. 提供清晰的文档导航
4. 删除过时或错误的引用
5. 包含新的重要文件和文档
6. 保持逻辑组织，便于 LLM 消费
7. 全程使用清晰、无歧义的语言
8. 继续有效服务于人类和机器读者
