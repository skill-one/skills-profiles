# Oracle-to-PostgreSQL 数据库迁移

识别迁移风险，并根据 `references/` 文件夹中记录的 Oracle/PostgreSQL 行为差异验证迁移工作。

## 使用场景

1. **规划** — 在开始对存储过程、触发器、查询或 refcursor 客户端进行迁移工作之前。识别适用的参考见解，以便提前解决风险。
2. **验证** — 迁移工作完成后，确认每个适用的见解都已解决，并且集成测试涵盖了新的 PostgreSQL 语义。

## 工作流

确定任务类型：

**计划迁移？** 跟随风险评估工作流。
**验证已完成的工作？** 跟随验证工作流。

### 风险评估工作流（规划）

```
风险评估：
- [ ] 第 1 步：确定迁移范围
- [ ] 第 2 步：筛选每个见解的适用性
- [ ] 第 3 步：记录风险和建议操作
```

**第 1 步：确定迁移范围**

列出受影响的数据库对象（存储过程、触发器、查询、视图）以及调用它们的代码。

**第 2 步：筛选每个见解的适用性**

查看 [references/REFERENCE.md](references/REFERENCE.md) 中的参考索引。对于每个条目，确定迁移范围是否包含受该见解影响的模式。只有当见解可能相关时，才阅读完整的参考文件。

**第 3 步：记录风险和建议操作**

对于每个适用的见解，记录具体风险和参考文件中的建议修复模式。标记需要设计决策的见解（例如，是否保留 Oracle 空字符串作为 NULL 的语义或采用 PostgreSQL 行为）。

### 验证工作流（迁移后）

```
验证：
- [ ] 第 1 步：映射迁移工件
- [ ] 第 2 步：交叉检查适用的见解
- [ ] 第 3 步：验证集成测试覆盖率
- [ ] 第 4 步：验证结果
```

**第 1 步：映射迁移工件**

识别已迁移的对象并总结变更集。

**第 2 步：交叉检查适用的见解**

对于 [references/REFERENCE.md](references/REFERENCE.md) 中的每个参考，确认行为或测试要求是否已在迁移工作中得到认可和解决。

**第 3 步：验证集成测试覆盖率**

确认测试涵盖了适用的见解中突出显示的“快乐路径”和失败场景（异常、排序、`UNION ALL` 行为/性能风险、refcursor 消费、并发事务、时间戳、物化视图的新鲜度等）。

**第 4 步：验证结果**

返回一个清单，断言每个适用的见解都已解决、迁移脚本已运行，并且集成测试通过。
