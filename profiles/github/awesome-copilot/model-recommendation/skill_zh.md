# AI模型推荐用于Copilot聊天模式和提示

## 任务

分析`.agent.md`或`.prompt.md`文件，了解其目的、复杂性和所需能力，然后从GitHub Copilot提供的选项中推荐最合适的AI模型。根据任务特征、模型优势、成本效益和性能权衡提供理由。

## 范围和前提条件

- **输入**：`.agent.md`或`.prompt.md`文件的路径
- **可用模型**：GPT-4.1、GPT-5、GPT-5 mini、GPT-5 Codex、Claude Sonnet 3.5、Claude Sonnet 4、Claude Sonnet 4.5、Claude Opus 4.1、Gemini 2.5 Pro、Gemini 2.0 Flash、Grok Code Fast 1、o3、o4-mini（已弃用日期）
- **模型自动选择**：在VS Code（2025年9月之后）中可用 - 从GPT-4.1、GPT-5 mini、GPT-5、Claude Sonnet 3.5、Claude Sonnet 4.5中选择（排除溢价倍数>1）
- **背景**：GitHub Copilot订阅层级（免费：2K次完成+每月50次聊天，仅限0x模型；专业：无限0x + 每月1000次溢价；专业+：无限0x + 每月5000次溢价）

## 输入

必需的：

- `${input:filePath:Path to .agent.md or .prompt.md file}` - 要分析的文件绝对路径或工作区相对路径

可选的：

- `${input:subscriptionTier:Pro}` - 用户Copilot订阅层级（免费、专业、专业+）（默认为专业）
- `${input:priorityFactor:Balanced}` - 优化优先级（速度、成本、质量、平衡）（默认为平衡）

## 工作流程

### 1. 文件分析阶段

**读取和解析文件**：

- 读取目标`.agent.md`或`.prompt.md`文件
- 提取前文（描述、模式、工具、如果指定则模型）
- 分析正文内容以识别：
  - 任务复杂性（简单/中等/复杂/高级）
  - 所需推理深度（基本/中等/高级/专家）
  - 代码生成需求（最小/中等/大量）
  - 多轮对话需求
  - 上下文窗口需求（小/中/大）
  - 专用能力（图像分析、长上下文、实时数据）

**分类任务类型**：

根据内容分析确定主要任务类别：

1. **简单重复性任务**：

   - 模式：格式化、简单重构、添加注释/文档字符串、基本CRUD
   - 特征：逻辑简单、上下文最小、优先快速执行
   - 关键词：格式化、注释、简单、基本、添加文档字符串、重命名、移动

2. **代码生成和实现**：

   - 模式：编写函数/类、实现功能、API端点、测试
   - 特征：中等复杂性、领域知识、惯用代码
   - 关键词：实现、创建、生成、编写、构建、构建框架

3. **复杂重构和架构**：

   - 模式：系统设计、架构审查、大规模重构、性能优化
   - 特征：深度推理、多个组件、权衡分析
   - 关键词：架构、重构、优化、设计、扩展、审查架构

4. **调试和问题解决**：

   - 模式：修复错误、错误分析、系统化故障排除、根本原因分析
   - 特征：逐步推理、调试上下文、验证需求
   - 关键词：调试、修复、故障排除、诊断、错误、调查

5. **规划和研究**：

   - 模式：功能规划、研究、文档分析、ADR创建
   - 特征：只读、收集上下文、决策支持
   - 关键词：计划、研究、分析、调查、文档、评估

6. **代码审查和质量分析**：

   - 模式：安全分析、性能审查、最佳实践验证、合规性检查
   - 特征：批判性思维、模式识别、领域专业知识
   - 关键词：审查、分析、安全、性能、合规性、验证

7. **专用领域任务**：

   - 模式：Django/框架特定、无障碍（WCAG）、测试（TDD）、API设计
   - 特征：深度领域知识、框架约定、标准合规性
   - 关键词：django、无障碍、wcag、rest、api、测试、tdd

8. **高级推理和多步骤工作流**：
   - 模式：算法优化、复杂数据转换、多阶段工作流
   - 特征：高级推理、数学/算法思维、顺序逻辑
   - 关键词：算法、优化、转换、顺序、推理、计算

**提取能力需求**：

根据前文中的`tools`和正文指令：

- **只读工具**（搜索、获取、使用、githubRepo）：复杂性较低，适合快速模型
- **写入操作**（编辑/编辑文件、新建）：中等复杂性，准确性重要
- **执行工具**（运行命令、运行测试、运行任务）：验证需求，迭代方法
- **高级工具**（context7/*、sequential-thinking/*）：复杂推理，受益于溢价模型
- **多模态**（图像分析引用）：需要支持图像的模型

### 3. 推荐生成阶段

**主要推荐**：

- 根据任务分析决策树确定最佳模型
- 提供与文件内容特征相关的具体理由
- 解释倍数成本对用户订阅层级的影响

**替代推荐**：

- 建议最多2个替代模型，并解释权衡
- 包括替代方案可能更受欢迎的场景
- 考虑优先级因素覆盖（速度与质量与成本）

**自动选择指导**：

- 评估任务是否适合自动模型选择（排除溢价模型>1x）
- 解释何时手动选择比让Copilot选择更有利
- 注意自动选择对特定任务的任何限制

**弃用警告**：

- 如果文件当前指定了已弃用的模型（o3、o4-mini、Claude Sonnet 3.7、Gemini 2.0 Flash）
- 提供推荐替代方案的迁移路径
- 包括弃用时间表（例如，“o3将于2025-10-23弃用”）

**订阅层级考虑**：

- **免费层级**：仅推荐0x倍数模型（GPT-4.1、GPT-5 mini、Grok Code Fast 1）
- **专业层级**：在0x（无限）和1x（每月1000次）模型之间平衡
- **专业+层级**：更多自由使用1x模型（每月5000次），仅在例外情况下使用10x

**工具对齐检查**：

- 如果工具包括`context7/*`或`sequential-thinking/*`：推荐高级推理模型（Claude Sonnet 4.5、GPT-5、Claude Opus 4.1）
- 如果工具包括与图像相关的引用：确保模型支持图像（如果选择GPT-5 Codex、Claude Sonnet 4或mini模型，请标记）
- 如果工具是只读的（搜索、获取）：建议成本效益模型（GPT-5 mini、Grok Code Fast 1）

### 失败触发器

- 文件路径无效或无法读取 → 停止并请求有效路径
- 文件不是`.agent.md`或`.prompt.md` → 停止并澄清文件类型
- 无法从内容中确定任务复杂性 → 请求更具体的文件或澄清
- 模型推荐与记录的能力矛盾 → 使用Context7验证当前信息
- 订阅层级无效（不是Free/Pro/Pro+）→ 默认为Pro并注明假设

## 高级用例

### 分析多个文件

如果用户提供多个文件：

1. 单独分析每个文件
2. 为每个文件生成单独的推荐
3. 提供比较推荐的摘要表格
4. 注意任何模式（例如，“所有调试相关模式受益于Claude Sonnet 4.5”）

### 比较分析

如果用户询问“对于此文件，哪个模型更好，X和Y之间？”：

1. 仅关注这两个模型进行比较
2. 使用并排表格格式
3. 声明赢家并给出具体理由
4. 包括订阅层级成本比较

### 迁移规划

如果文件指定了已弃用的模型：

1. 在报告中优先考虑迁移指导
2. 测试当前行为预期与替代模型能力的差异
3. 如果预期有破坏性更改，提供分阶段迁移
4. 包括回滚计划（如果需要）

## 示例

### 示例1：简单格式化任务

**文件**： `format-code.prompt.md`
**内容**： "使用Black风格格式化Python代码，添加类型提示"
**推荐**： GPT-5 mini（0x倍数，最快，足够用于重复性格式化）
**替代**： Grok Code Fast 1 (0.25x, 甚至更快，预览功能)
**理由**： 任务简单且重复；不需要高级推理；优先考虑速度

### 示例2：复杂架构审查

**文件**： `architect.agent.md`
**内容**： "审查系统设计以实现可扩展性、安全性、可维护性；分析权衡；提供ADR级别的建议"
**推荐**： Claude Sonnet 4.5 (1x倍数，专家推理，优秀，适合架构)
**替代**： Claude Opus 1 (10x, 用于超过500K token的大型代码库)
**理由**： 需要深度推理、架构专业知识、设计模式知识；Sonnet 4.5在这方面表现出色

### 示例3：Django专家模式

**文件**： `django.agent.md`
**内容**： "Django 5.x专家，ORM优化、异步视图、REST API设计；使用context7获取最新的Django文档"
**推荐**： GPT-5 (1x倍数，高级推理，优秀代码质量)
**替代**： Claude Sonnet 4.5 (1x, 替代方案，强于框架）
**理由**： 领域专业知识+context7集成受益于高级推理；1x成本对专家模式合理

### 示例4：免费层级用户与规划模式

**文件**： `plan.agent.md`
**内容**： "研究与规划模式，只读工具（搜索、获取、githubRepo）"
**订阅**： 免费层级（每月2000次完成+每月50次聊天，仅限0x模型）
**推荐**： GPT-4.1 (0x, 平衡，包含在免费层级中)
**替代**： GPT-5 mini (0x, 更快但上下文较小)
**理由**： 免费层级仅限于0x模型；GPT-4.1为规划任务提供了质量和上下文的最佳平衡
