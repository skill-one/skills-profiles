# 企业账户规划

针对企业级交易的策略性账户规划和执行。将复杂销售周期转化为系统性的胜利——或者至少在浪费数月之前知道它们何时会失败。

## 何时使用

**触发因素：**
- "我该如何规划这个企业级交易？"
- "这个交易已经进行3个月了，为什么没有达成？"
- "我应该创建完整的账户计划还是简化版本？"
- "我如何知道这个交易是否真的在推进？"
- "MEDDICC资格认证"
- "建立共同行动计划"

**背景：**
- 超过平均ACV的战略交易
- 涉及多个利益相关者
- 销售周期超过60天
- 复杂的购买流程（法律、采购、安全）
- 企业级或中市场账户

## 核心框架

### 1. 如果您的MAP在3周内未更新，那么这个交易就死了

**我观察到的模式：**

共同行动计划（MAP）是衡量交易健康状况的最佳指标。不是管道阶段。不是口头承诺。不是“他们喜欢这个产品。”

**MAP会告诉您一切：**

**健康的交易：**
- 每周更新MAP
- 客户添加自己的行动项
- 双方按计划完成任务
- 新的利益相关者出现在MAP中
- 日期提前（而不是推迟）

**濒临失败的交易：**
- MAP上次更新已超过3周
- 只有您这边有行动项
- 客户任务标记为“待处理”数周
- 没有新的利益相关者参与
- 所有日期都在过去

**为什么会这样发生：**

当交易真实时，客户希望它发生。他们正在工作。他们正在涉及利益相关者。他们正在通过他们的流程。

当交易濒临失败时，您在所有事情上都在努力。他们“太忙了”。他们会“下周再联系您”。经济购买者是“在旅行”。

**3周规则：**

如果您的MAP在3周内未更新，那么这个交易就死了——您只是还不知道。**在我11年的职业生涯中，我从未见过一个带有陈旧MAP的交易达成。一次都没有。**

**要做什么：**

**沉默的第一周：** 发送MAP更新：“我们已经完成了什么？[具体客户行动] 的状态如何？”

**沉默的第二周：** 升级给负责人：“没有收到MAP的回复。我们是否仍然按 [日期] 的计划进行？如果优先级发生了变化，请告诉我。”

**沉默的第三周：** 资格认证或重置：“看起来时机可能不太合适。我们应该暂停并在 [时间范围] 重新联系，还是有我可以帮助的障碍？”

**常见错误：**

因为“他们说他们想要它”而将交易保留在管道中。口头兴趣≠行动。如果他们没有采取行动，他们就不会购买。

### 2. 经济购买者发现问题（以及为什么交易会在第8周失败）

**模式：**

您进入交易的第八周。POC进展顺利。负责人喜欢您。技术验证完成。您发送了提案。

然后：无线电沉默。

**发生了什么？** 您从未见过经济购买者。

**经济购买者（EB）是：**
- 控制预算分配的人
- 做出最终购买决定的人
- 签署合同的人

**不是：**
- 您的负责人（他们影响，不决定）
- 技术负责人（他们验证，不购买）
- 参加了一个演示的副总裁（他们建议，不签署）

**没有EB访问权限，交易为什么会失败：**

您用负责人的假设构建了商业案例。但EB有不同的优先级：
- 负责人关心：解决他们团队的痛点
- EB关心：投资回报率、风险缓解、战略一致性

当您通过负责人向EB发送提案时，EB会看到：
- 没有背景的价格标签
- 解决他们没有说明的问题的方案
- 他们没有评估的风险

**结果：** 交易停滞或失败。

**EB验证检查清单框架**

在发送提案之前进行验证：

- [ ] 您是否确定了EB？（姓名、职位、负责人确认）
- [ ] 您是否见过EB？（最低视频通话，理想情况下是面对面）
- [ ] EB是否同意问题？（用他们的话，不是您的话）
- [ ] EB是否同意成功指标？（他们如何衡量投资回报率）
- [ ] EB是否知道价格范围？（讨论了大致范围，而不是感到惊讶）
- [ ] EB是否理解时间表？（实施、上线、价值实现）

**如果对任何问题的回答是“否”，请不要发送提案。**

**如何获得EB访问权限：**

**询问您的负责人：**
“在我们最终确定价格之前，我希望与 [EB姓名] 进行15分钟的沟通，以确保我们在结果和时间表上保持一致。您能引荐我们吗？”

**如果负责人阻止：** “我可以处理，您不需要和他们谈话”
→ 这是一个危险信号。要么负责人没有访问权限（不是真正的负责人），要么他们害怕EB会杀死交易（这意味着交易很弱）。

**坚持：**
“我完全理解。与此同时，我想确保 [EB] 在看到价格之前看到全部价值。根据我的经验，当经济购买者早期不参与时，交易会在采购中延迟。我们可以进行一次快速的协调通话吗？”

**常见错误：**

将EB会议视为“锦上添花”。对于任何交易> $50K，这是强制性的。没有EB访问权限=没有交易。

### 3. 个人胜利映射（人们为自己购买）

**模式：**

企业软件采购是由委员会做出的。但委员会不会购买。**人们会购买。**

而且人们会出于个人原因购买：
- 职业发展
- 让他们的老板看起来不错
- 减少他们的工作量
- 掩盖自己的后路（CYA）
- 证明他们是对的
- 不显得愚蠢

**个人胜利识别框架**

对于每个利益相关者，映射：

**职业胜利：**
- 如果这个交易成功，他们能得到什么信用？
- 对他们个人来说，什么痛苦会消失？
- 这如何让他们看起来不错？

**职业风险：**
- 如果这个交易失败，会发生什么？
- 如果这个交易出错了，他们的声誉成本是什么？
- 内部谁对他们的观点持怀疑态度？

**个人动机：**
- 他们是否刚上任？（需要快速胜利）
- 面临预算削减？（需要证明支出）
- 即将晋升？（需要可见的成功）
- 之前被供应商伤害过？（额外的风险规避）

**示例：工程副总裁**

**职业胜利：**
- 减少团队的呼叫负担（他们不会再向她抱怨）
- 更快的故障响应（在QBR中看起来不错）
- 吸引更好的工程人才（现代化的工具）

**职业风险：**
- 团队拒绝新工具（她强迫他们使用）
- 迁移出问题（停机时间、事件）
- 供应商失败（她选择了他们）

**个人动机：**
- 新上任（6个月），需要胜利
- 压力下要提高停机时间指标
- 她之前选择的监控工具失败了

**这如何改变您的提案：**

**通用提案：**
“我们的平台可以将事件响应时间缩短40%。”

**个人胜利提案：**
“您提到呼叫负担正在让您的团队筋疲力尽。我们见过团队在第一个月内减少40%的呼叫页面，这有助于提高留存率。而且，自从您专注于董事会层面的停机时间指标，改进的响应时间会立即出现在您的QBR仪表板上。”

**区别：**

通用=商业案例
个人=职业案例

两者都很重要。但个人胜利会促成交易。

**常见错误：**

只针对商业问题进行销售。“这可以节省成本。这可以提高效率。” 这是必要的，但不是充分的。**人们需要看到对他们个人的好处。**

### 4. 企业账户计划结构（四个组成部分）

一个完整的账户计划有四个相互关联的部分。每个部分都为其他部分提供信息。

**组成部分1：账户摘要**
- 公司基本信息（总部、规模、行业、子公司）
- 技术环境（基础设施、工具、平台）
- 顶级企业计划（来自新闻、年度报告、领英）
- 假设：“我们如何帮助他们？”（在参与之前编写）
- 领英关键词分析（量化他们在您领域的投资）

**组成部分2：组织结构图**
- 绘制所有相关联系人：姓名、职位、位置、领英、电子邮件、电话、笔记
- 笔记捕获：责任领域、技术专长、个人胜利
- 包括不同层级的所有人：C级、总监、架构师、负责人、专家
- 不要只绘制购买者——绘制影响者、用户、潜在的障碍者

**组成部分3：机会计划（MEDDICC）**
- **M - 指标**：客户将如何衡量成功？（与EB验证）
- **E - 经济购买者**：谁拥有预算授权？您是否见过他们？
- **D - 决策标准**：他们 sẽ 使用什么标准来做决定？（技术、商业、政治）
- **D - 决策流程**：他们的购买流程是什么？（采购、法律、安全审查）
- **I - 确定的痛点**：他们具体说明的痛点是什么？（他们的话，不是您的话）
- **C - 负责人**：账户内部积极为您销售的人
- **C - 竞争对手**：他们还在评估谁？竞争动态是什么？

此外：问题/风险表，包含缓解计划、需要帮助、责任方

**组成部分4：共同行动计划（MAP）**
- 联合时间表：行动、您的负责人、客户负责人、其他参与人员、截止日期
- 双方都必须有行动——如果只有您这边有行动，那不是交易，只是演示
- 跟踪状态（完成/进行中）
- 将MAP用作检查通话的运行议程
- **如果MAP在3周内未更新，交易就死了**

**决策标准：**

值得投资完整账户计划的前10-20%的账户，按潜在交易规模计算。对于其余的，使用简化版本（摘要 + MEDDICC + 下一步）。

**常见错误：**
- 在交易进行中创建账户计划（在第一次参与之前构建）
- 不每周维护MAP（陈旧的MAP=陈旧的交易）
- 用假设填充MEDDICC，而不是验证信息
- 绘制只有明显的联系人，而不是完整组织结构图
- 不跟踪每个利益相关者的个人胜利

### 5. 领英关键词分析用于账户智能

在参与战略账户之前，通过领英量化他们在您领域的投资。

**如何执行：**

1. 定义与您的领域相关的8-10个关键词（例如，类别术语、技术角色、工作流关键词）
2. 在领英上搜索“[公司名称] + [关键词]”并记录计数
3. 绘制集中度：哪些位置？哪些部门？
4. 识别异常值（在特定部门中关键词集中度高表明成熟）

**为什么有效：**

如果一个公司有50名员工在他们的个人资料中包含“SRE”，那么他们在站点可靠性方面很成熟。如果只有2人，他们还没有准备好先进的可观察性工具。

这告诉您：
- 是否要追求账户（他们是否有团队？）
- 要瞄准谁（在哪里集中？）
- 如何个性化外联（参考他们的特定背景）

**示例：**

搜索“[公司] + DevOps”：
- 120个结果→ 成熟的DevOps组织，适合
- 5个结果→ 早期，不适合

搜索“[公司] + SRE”：
- 50个结果→ 他们关心可靠性，提出停机时间/事件减少
- 0个结果→ 不要首先提出SRE价值主张

**常见错误：**
- 只搜索职位名称（差异很大）而不是关键词（一致）
- 不将计数与员工总数进行比较
- 不刷新分析（招聘趋势每季度变化）

### 6. 统一销售流程（阶段门）

企业销售遵循定义的阶段，具有明确的退出标准。不要在没有满足标准的情况下推进阶段。

**阶段0——管道生成：** 潜在客户→ 确认合格兴趣
**阶段1——发现：** 环境/痛苦/需求→ 确定痛点，绘制利益相关者
**阶段2——展示：** 产品演示，负责人建设→ 确定负责人
**阶段3——证明价值：** POC/试用→ 技术验证完成
**阶段4——提案：** 价格、条款、范围→ 提交提案，EB对齐
**阶段5——纸质流程：** 法律、采购、安全→ 获得批准
**阶段6——已关闭成功：** 签约→ 客户成功交接

**退出标准很重要：**

不要从阶段2→阶段3，直到您有一个负责人。
不要从阶段3→阶段4，直到POC成功标准得到满足。
不要从阶段4→阶段5，直到EB已经批准。

**常见错误：**

基于活动而不是标准推进阶段。“我们演示了，所以我们处于阶段3”——但如果他们没有同意POC，您仍然处于阶段2。

## 决策树

### 我需要完整的账户计划吗？

```
交易规模是否高于平均ACV？
├─ 否 → 简化计划（摘要 + MEDDICC）
└─ 是 → 继续...
    │
    销售周期是否>60天？
    ├─ 是 → 完整账户计划
    └─ 否 → 简化计划
```

### 这个交易是否真的在推进？

```
MAP是否每周更新？
├─ 是 → 健康
└─ 否 → 继续...
    │
    自上次MAP更新以来是否已超过3周？
    ├─ 是 → 死交易（资格认证或重置）
    └─ 否 → 处于风险中（升级给负责人）
```

### 我应该发送提案吗？

```
您是否见过经济购买者？
├─ 否 → 现在不要发送（首先获得EB访问权限）
└─ 是 → 继续...
    │
    EB是否同意问题和成功指标？
    ├─ 是 → 发送提案
    └─ 否 → 在发送之前与EB对齐
```

## 常见错误

**1. 过晚创建账户计划**
   - 在第一次参与之前构建，而不是在交易进行中

**2. MEDDICC填充了假设**
   - 与客户验证每个元素，不要猜测

**3. 陈旧的共同行动计划**
   - 如果MAP每周未更新，交易正在停滞。3+周=死亡。

**4. 只绘制购买者**
   - 需要完整组织结构图：影响者、用户、障碍者

**5. 忽略个人胜利**
   - 人们会出于职业/声誉原因购买，而不仅仅是商业ROI

**6. 不跟踪交易健康**
   - 绿色/黄色/红色指标可以早期发现濒临失败的交易

**7. 跳过负责人验证**
   - 没有内部负责人，您是在单独销售

## 快速参考

**MAP健康检查：**
- 绿色：每周更新，双方都有行动，客户正在完成任务
- 黄色：每两周更新，主要是您的行动，客户反应迟缓
- 红色：3+周陈旧，只有您的行动，客户无响应→ **死亡交易**

**MEDDICC验证：**
- [ ] 指标：与EB同意成功标准
- [ ] 经济购买者：见过他们，验证了问题/解决方案
- [ ] 决策标准：了解他们的评估标准
- [ ] 决策流程：了解采购/法律/安全步骤
- [ ] 确定的痛点：客户的话，不是您的话
- [ ] 负责人：积极在内部为您销售
- [ ] 竞争对手：了解他们正在考虑的替代方案，竞争动态

**个人胜利问题：**
- "对您个人来说，成功看起来像什么？"
- "如果这个工作，您的团队会发生什么？如果它不工作呢？"
- "您今年被衡量的是什么？"
- "谁内部持怀疑态度？为什么？"

**账户计划检查清单：**
- [ ] 账户摘要与假设
- [ ] 组织结构图，映射个人胜利
- [ ] 完全验证的MEDDICC（不是假设）
- [ ] MAP与客户行动（不仅仅是您的）
- [ ] 每周MAP更新节奏安排
