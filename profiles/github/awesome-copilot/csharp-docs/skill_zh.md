# C# 文档最佳实践

- 公共成员应使用 XML 注释进行文档说明。
- 鼓励对内部成员也进行文档说明，特别是那些复杂或不易理解的成员。

## 所有 API 的指导

- 使用 `<summary>` 提供对类型或成员功能的简短、一句话描述。摘要应以现在时态的第三人称动词开头。
- 使用 `<remarks>` 用于附加信息，可以包括实现细节、使用说明或任何其他相关上下文。
- 使用 `<see langword>` 用于语言特定的关键字，如 `null`、`true`、`false`、`int`、`bool` 等。
- 使用 `<c>` 用于内联代码片段。
- 使用 `<example>` 用于成员使用示例。
  - 使用 `<code>` 用于代码块。`<code>` 标签应放置在 `<example>` 标签内。使用 `language` 属性添加代码示例的语言，例如，`<code language="csharp">`。
- 使用 `<see cref>` 用于在句子中内联引用其他类型或成员。
- 使用 `<seealso>` 用于在线文档“参见”部分中独立的（不在句子中）引用其他类型或成员。
- 使用 `<inheritdoc/>` 从基类或接口继承文档说明。
  - 除非有重大行为变化，否则应说明差异。

## 方法

- 使用 `<param>` 描述方法参数。
  - 描述应为不指定数据类型的名词短语。
  - 以介绍性冠词开头。
  - 如果参数是标志枚举，描述应以“指定...的枚举值位组合”开头。
  - 如果参数是非标志枚举，描述应以“指定...的枚举值之一”开头。
  - 如果参数是布尔值，措辞应为“`<see langword="true" />` 表示...；否则，`<see langword="false" />`。”。
  - 如果参数是“out”参数，措辞应为“当此方法返回时，包含...。此参数被视为未初始化。”。
- 使用 `<paramref>` 用于在文档中引用参数名称。
- 使用 `<typeparam>` 描述泛型类型或方法中的类型参数。
- 使用 `<typeparamref>` 用于在文档中引用类型参数。
- 使用 `<returns>` 描述方法返回的内容。
  - 描述应为不指定数据类型的名词短语。
  - 以介绍性冠词开头。
  - 如果返回类型是布尔值，措辞应为“`<see langword="true" />` 如果...；否则，`<see langword="false" />`。”。

## 构造函数

- 摘要措辞应为“初始化 `<Class>` 类 [或结构] 的新实例”。

## 属性

- `<summary>` 应以：
  - “获取或设置...”用于可读写属性。
  - “获取...”用于只读属性。
  - “获取 [或设置] 指示...的值”用于返回布尔值的属性。
- 使用 `<value>` 描述属性的值。
  - 描述应为不指定数据类型的名词短语。
  - 如果属性有默认值，请在单独的句子中添加，例如，“默认值为 `<see langword="false" />`”。
  - 如果值类型是布尔值，措辞应为“`<see langword="true" />` 如果...；否则，`<see langword="false" />`。默认值为...”。

## 异常

- 使用 `<exception cref>` 文档说明构造函数、属性、索引器、方法、运算符和事件抛出的异常。
- 直接由成员抛出的所有异常都应进行文档说明。
- 对于嵌套成员抛出的异常，仅文档说明用户最可能遇到的异常。
- 异常的描述描述了抛出该异常的条件。
  - 在句首省略“如果...抛出”或“如果...”。直接陈述条件，例如“访问消息队列 API 时发生错误。”
