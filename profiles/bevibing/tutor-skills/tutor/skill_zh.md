# 辅导技能

基于测验的辅导工具，在**概念层面**追踪用户掌握和不掌握的内容。目标是帮助用户通过问题发现自己的知识盲点。

## 文件结构

```
StudyVault/
├── *dashboard*              ← 简洁概览：熟练度表格 + 统计数据
└── concepts/
    ├── {area-name}.md       ← 按区域追踪概念（尝试次数、状态、错误笔记）
    └── ...
```

- **Dashboard**：仅显示聚合数据。链接到概念文件。永远保持简洁。
- **概念文件**：每个区域一个。追踪每个概念，包括尝试次数、正确次数、日期、状态和错误笔记。随测试过的独特概念数量（有界）成正比增长。

## 工作流程

### 阶段 0：检测语言

从用户消息中检测语言 → `{LANG}`。所有输出和文件内容均使用 `{LANG}` 语言。

### 阶段 1：发现 Vault

1. 在项目中 Glob `**/StudyVault/`
2. 列出区域目录
3. Glob `**/StudyVault/*dashboard*` 找到 dashboard
4. 如果找到，读取它。无论语言如何，保留现有文件路径。
5. 如果未找到，从模板创建（见 Dashboard 模板）

如果不存在 StudyVault，则通知用户并停止。

### 阶段 2：询问会话类型

**必须**：使用 AskUserQuestion 让用户选择要做什么。分析 dashboard 构建上下文感知选项，然后呈现给用户。

读取 dashboard 熟练度表格，根据当前状态构建选项：

1. 如果存在未测量区域（⬜）→ 包含“诊断”选项，针对这些区域
2. 如果存在薄弱区域（🟥/🟨）→ 包含“强化薄弱区域”选项，命名最薄弱的区域
3. 总是包含“选择一个区域”选项，以便用户可以选择任何区域
4. 如果所有区域都是 🟩/🟦 → 包含“困难模式复习”选项

将这些作为 AskUserQuestion 呈现，标题为“会话”，并显示简洁描述，说明每个选项针对哪些区域。用户必须选择后才能继续。

### 阶段 3：构建问题

1. 读取目标区域（s）中的 markdown 文件
2. 如果在强化薄弱区域：也读取 `concepts/{area}.md` 找到 🔴 未解决的概念 — 在新情境中重述这些概念（不要重复相同的问题）
3. 根据 `references/quiz-rules.md` 精确构建 4 个问题

**关键**：在构建任何问题之前，必须阅读 `references/quiz-rules.md`。不允许任何提示。

### 阶段 4：展示测验

使用 AskUserQuestion：

- 4 个问题，每个问题 4 个选项，单选
- 标题：“Q1. 主题”（最多 12 个字符）
- 描述：中立，无提示

### 阶段 5：评分和解释

1. 显示结果表格（问题 / 正确答案 / 用户答案 / 结果）
2. 错误答案：简洁解释
3. 将每个问题映射到其区域

### 阶段 6：更新文件

#### 1. 更新概念文件 (`concepts/{area}.md`)

对于每个回答的问题：

- **新概念**：在表格中添加行 + 如果错误，在 `### 오답 메모`（或本地化等效项）下添加错误笔记
- **已存在的 🔴 概念正确回答**：增加尝试次数和正确次数，更改状态为 🟢，保留错误笔记（学习历史）
- **已存在的 🟢 概念再次回答错误**：增加尝试次数，将状态改回 🔴，更新错误笔记

表格格式：

```markdown
| Concept | Attempts | Correct | Last Tested | Status |
|---------|----------|---------|-------------|--------|
| concept name | 2 | 1 | 2026-02-24 | 🔴 |
```

错误笔记格式（仅用于错误答案）：

```markdown
### Error Notes

**concept name**
- 混淆：用户混淆的内容
- 关键点：正确的理解
```

#### 2. 更新 dashboard

- 从概念文件中重新计算每个区域的统计数据（跨该区域所有概念汇总尝试次数/正确次数）
- 更新熟练度徽章：🟥 0-39% · 🟨 40-69% · 🟩 70-89% · 🟦 90-100% · ⬜ 无数据
- 更新统计数据：总问题数、累积率、未解决/已解决计数、最弱/最强

Dashboard 保持简洁 — 无会话日志，无每个问题的详细信息。

## Dashboard 模板

在不存在时创建。文件名本地化为 `{LANG}`。英文示例：

```markdown
# 学习仪表盘

> 基于概念元认知追踪。详情请查看链接文件。

---

## 按区域熟练度

| 区域 | 正确 | 错误 | 率 | 等级 | 详情 |
|------|------|------|----|------|------|
（每行一个区域，最后一列 = [[concepts/{area}]] 链接）
| **总计** | **0** | **0** | **-** | ⬜ 未测量 | |

> 🟥 薄弱 (0-39%) · 🟨 一般 (40-69%) · 🟩 良好 (70-89%) · 🟦 精通 (90-100%) · ⬜ 未测量

---

## 统计数据

- **总问题数**：0
- **累积率**：-
- **未解决概念**：0
- **已解决概念**：0
- **最弱区域**：-
- **最强区域**：-
```

## 概念文件模板

在第一次提问时按区域创建。示例：

```markdown
# {Area Name} — 概念追踪器

| Concept | Attempts | Correct | Last Tested | Status |
|---------|----------|---------|-------------|--------|

### Error Notes

（当概念被遗漏时添加）
```

## 重要提醒

- 在创建问题前**始终**阅读 `references/quiz-rules.md`
- **永远**不在选项标签或描述中包含提示
- **永远**不在任何选项上使用“(推荐)”
- 随机化正确答案位置
- 评分后，**始终**更新概念文件和 dashboard
- 使用用户的语言进行沟通
