# 教师设置 — 知识到 Obsidian 学习库

## 当前工作目录边界规则（所有模式）

> **绝对不要访问当前工作目录（CWD）外的文件。**
> 所有源扫描、读取和库输出必须保持在 CWD 及其子目录内。
> 如果用户提供了外部路径，请先让他们将文件复制到 CWD 中。

## 模式检测

在启动时自动检测模式：

1. **检查 CWD 中的项目标记**：
   - `package.json`、`pom.xml`、`build.gradle`、`Cargo.toml`、`go.mod`、`Makefile`，
     `*.sln`、`pyproject.toml`、`setup.py`、`Gemfile`
2. **如果找到任何标记** → **代码库模式**
3. **如果没有找到标记** → **文档模式**
4. **平局判定**：如果 `.git/` 是唯一的指示器且没有源代码文件（`*.ts`、`*.py`、`*.java`、`*.go`、`*.rs` 等）存在，则默认为文档模式。
5. 宣布检测到的模式并要求用户确认或覆盖。

## 文档模式

> 将知识源（PDF、文本、网页、epub）转换为学习笔记。
> 模板：[templates.md](references/templates.md)

### 阶段 D1：源发现与提取

1. **自动扫描 CWD** 中的 `**/*.pdf`、`**/*.txt`、`**/*.md`、`**/*.html`、`**/*.epub`（排除 `node_modules/`、`.git/`、`dist/`、`build/`、`StudyVault/`）。向用户确认。
2. **提取文本（必须的工具）**：
   - **PDF → 仅使用 `pdftotext` CLI**（通过 Bash 工具运行）。绝对不要直接在 PDF 文件上使用阅读工具——它会将页面渲染为图像，并浪费 10-50 倍的 token。先转换为 `.txt`，然后读取 `.txt` 文件。
     ```bash
     pdftotext "source.pdf" "/tmp/source.txt"
     ```
   - 如果未安装 `pdftotext`，请先安装：`brew install poppler`（macOS）或 `apt-get install poppler-utils`（Linux）。
   - URL → WebFetch
   - 其他格式（`.md`、`.txt`、`.html`）→ 直接读取。
3. **读取提取的 `.txt` 文件**——理解范围、结构、深度。仅从转换后的文本工作，绝不要从原始 PDF 工作。
4. **源内容映射（多文件源必须的）**：
   - 对每个源文件读取**封面页 + 目录 + 中间/末尾的 3+ 采样页**
   - **绝对不要假设内容来自文件名**——文件编号通常 ≠ 章节编号
   - 构建验证映射：`{ 源文件 → 实际主题 → 页面范围 }`
   - 标记非学术文件和缺失的源
   - 在继续之前向用户展示映射以供验证

### 阶段 D2：内容分析

1. 识别主题层次结构——章节、领域划分。
2. 分离概念内容与实践问题。
3. 映射主题之间的依赖关系。
4. 识别关键模式——比较、决策树、公式。
5. **完整主题清单（必须的）**——列出每个主题/子主题。驱动所有后续阶段。
>
> **等深度规则**：即使简要提及的子主题也必须获得一个完整的专用笔记，并补充教科书级别的知识。

6. **分类完整性**：当源枚举类别（"X 的 3 种类型"）时，每个成员都获得一个专用笔记。扫描：`"types of"`、`"N가지"`、`"categories"`、`"there are N"`。
7. **源到笔记交叉验证（必须的）**：记录哪些源文件和页面范围涵盖了每个主题。将无法追踪的主题标记为 "source not available"。

### 阶段 D3：标签标准

在创建笔记之前定义标签词汇表：
- **格式**：英文、小写、连字符分隔（例如，`#data-hazard`）
- **层次结构**：顶级 → 领域 → 细节 → 技术 → 笔记类型
- **注册表**：仅允许注册的标签。细节标签会同时附加父级领域标签。

### 阶段 D4：库结构

根据 [templates.md](references/templates.md) 创建 `StudyVault/`，使用编号文件夹。每个文件分组 3-5 个相关概念。

### 阶段 D5：仪表盘创建

创建 `00-Dashboard/`：MOC、快速参考、考试陷阱。参见 [templates.md](references/templates.md)。

- **MOC**：主题地图 + 实践笔记 + 学习工具 + 标签索引（带规则）+ 弱项（带链接）+ 非核心主题策略
- **快速参考**：每个标题都包含 `→ [[概念笔记]]` 链接；所有关键公式
- **考试陷阱**：每个主题的陷阱点在折叠调用中，链接到概念笔记

### 阶段 D6：概念笔记

根据 [templates.md](references/templates.md)。关键规则：
- YAML 前置：`source_pdf`、`part`、`keywords`（必须的）
- **`source_pdf` 必须与验证的 D1 阶段映射匹配**——绝不要从文件名猜测
- 如果不可用：`source_pdf: 원문 미보유`
- `[[wiki-links]]`、调用（`[!tip]`、`[!important]`、`[!warning]`）、比较表格 > 旁白
- ASCII 图表用于流程/序列/步骤
- **带例外简化**：一般性陈述必须注明边缘情况

### 阶段 D7：实践问题

根据 [templates.md](references/templates.md)。关键规则：
- 每个主题文件夹必须有实践文件（≥8 个问题）
- **主动回忆**：答案使用 `> [!answer]- 정답 보기` 折叠调用
- 模式使用 `> [!hint]-` / `> [!summary]-` 折叠调用
- **问题类型多样性**：≥60% 回忆，≥20% 应用，≥2 分析/文件
- `## 相关概念` 与 `[[wiki-links]]`

### 阶段 D8：互链接

1. 每个概念笔记上的 `## 相关笔记`
2. MOC 链接到每个概念 + 实践笔记
3. 概念 ↔ 实践交叉链接；兄弟节点相互引用
4. 快速参考部分 → `[[概念笔记]]` 链接
5. 弱项 → 相关笔记 + 考试陷阱；考试陷阱 → 概念笔记

### 阶段 D9：自我审查（必须的）

根据 [quality-checklist.md](references/quality-checklist.md) **文档模式** 部分进行验证。修复并重新验证，直到所有检查通过。

## 代码库模式

> 从源代码项目生成新开发者的入职学习库。
> 完整工作流：[codebase-workflow.md](references/codebase-workflow.md)
> 模板：[codebase-templates.md](references/codebase-templates.md)

### 阶段总结

| 阶段 | 名称 | 关键操作 |
|------|------|----------|
| C1 | 项目探索 | 扫描文件、检测技术栈、读取入口点、映射目录布局 |
| C2 | 架构分析 | 识别模式、追踪请求流、映射模块边界和数据流 |
| C3 | 标签标准 | 定义 `#arch-*`、`#module-*`、`#pattern-*`、`#api-*` 标签注册表 |
| C4 | 库结构 | 创建 `StudyVault/`，包含仪表盘、架构、按模块、DevOps、练习文件夹 |
| C5 | 仪表盘 | MOC（模块地图 + API 表面 + 入门指南 + 入职路径）+ 快速参考 |
| C6 | 模块笔记 | 每个模块的笔记：目的、关键文件、公共接口、内部流、依赖关系 |
| C7 | 入职练习 | 代码阅读、配置、调试、扩展练习（每个主要模块 ≥5 个） |
| C8 | 互链接 | 交叉链接模块、架构 ↔ 实现、练习 ↔ 模块 |
| C9 | 自我审查 | 根据 [quality-checklist.md](references/quality-checklist.md) **代码库模式** 部分进行验证 |

详细每个阶段的说明，请参阅 [codebase-workflow.md](references/codebase-workflow.md)。
