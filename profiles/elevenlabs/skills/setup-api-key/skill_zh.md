# ElevenLabs API密钥设置

指导用户获取和配置ElevenLabs API密钥。

## 工作流程

### 第0步：首先检查是否存在现有的API密钥

在要求用户提供密钥之前，检查当前环境中是否存在`ELEVENLABS_API_KEY`：

1. 检查`ELEVENLABS_API_KEY`是否存在于当前环境中。如果存在，则使用该值进行初始检查。
2. 只有当它不在环境中时，检查`.env`文件中是否存在`ELEVENLABS_API_KEY=<value>`。
3. 不要打印、引用或重复密钥。如果提及它，请进行匿名处理。
4. 如果找到现有密钥，请验证它：
   ```text
   GET https://api.elevenlabs.io/v1/user
   Header: xi-api-key: <现有API密钥>
   ```
5. **如果现有密钥验证成功：**
   - 告知用户ElevenLabs已经配置并可以正常工作
   - 跳过设置流程
   - 询问用户是否要替换/轮换密钥；如果不是，则停止
6. **如果现有密钥验证失败：**
   - 告知用户现有密钥似乎无效或已过期
   - 继续执行第1步

### 第1步：请求API密钥

告知用户：

> 要设置ElevenLabs，请打开API密钥页面：https://elevenlabs.io/app/settings/api-keys
>
> （需要账户？请先在 https://elevenlabs.io/app/sign-up 创建一个）
>
> 如果您还没有API密钥：
> 1. 点击“创建密钥”
> 2. 为其命名（或使用默认名称）
> 3. 设置密钥的权限。如果您将密钥的“用户”权限设置为“读取”，此技能将自动验证您的密钥是否有效
> 4. 点击“创建密钥”以确认
> 5. **立即复制密钥** - 它只会显示一次！
>
> 不要将密钥粘贴到此聊天中。相反，请将其复制/粘贴到您的本地`.env`文件中：
>
> ```
> ELEVENLABS_API_KEY=您的API密钥
> ```
>
> 如果`.env`文件中已经存在`ELEVENLABS_API_KEY=...`行，请替换该行。
> 告知我您已保存它，但不要分享密钥。

然后等待用户确认密钥已保存在本地。

### 第2步：验证和配置

在用户表示密钥已保存后：

1. 重新检查`.env`文件和当前环境中的`ELEVENLABS_API_KEY`，但在此步骤中，将`.env`文件视为权威来源。
2. 如果`.env`文件包含值，即使当前环境中也有不同的`ELEVENLABS_API_KEY`，也要验证该值。
3. 如果`.env`文件不包含密钥：
   - 告知用户`.env`文件似乎不包含`ELEVENLABS_API_KEY`。
   - 再次显示预期行。
   - 如果当前环境中确实包含密钥，请指出此步骤仍然需要在`.env`文件中保存密钥。
   - 提醒他们不要将密钥粘贴到聊天中。
4. 如果找到`.env`文件中的密钥，请验证它：
   ```text
   GET https://api.elevenlabs.io/v1/user
   Header: xi-api-key: <本地API密钥>
   ```
5. 如果验证失败：
   - 告知用户本地密钥似乎无效或已过期。
   - 提醒他们API密钥页面。
   - 请他们替换`.env`中的值并告知您何时保存。
6. 如果验证成功，请确认：
   > 完成。ElevenLabs已配置，`.env`中的密钥有效。

## 安全规则

- 不要要求用户将API密钥、令牌或密钥粘贴到聊天中。
- 不要打印或回显来自环境变量或`.env`文件的API密钥值。
- 优先使用`.env`文件或管理的密钥，而不是shell历史记录，用于持久化本地配置。
- 对于浏览器或客户端应用程序，请将`ELEVENLABS_API_KEY`保存在服务器上，并在适用的情况下发放短期令牌。
