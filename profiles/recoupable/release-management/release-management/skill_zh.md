# 音乐发行管理

使用 RELEASE.md 作为单一事实来源来管理音乐发行活动。

## 文件夹结构

发行内容存放在艺术家工作空间下的 `releases/` 目录中。从沙盒根目录的完整路径：

```
orgs/{org}/
└── artists/
    └── {artist-slug}/
        └── releases/
            └── {release-slug}/
            └── RELEASE.md
```

使用小写连字符命名法（kebab-case）作为发行标识符（e.g. `blue-slide-park`, `debut-ep`）。

**示例：**
```
orgs/recoup-records/artists/gatsby-grace/releases/adhd-ep/
            └── RELEASE.md
```

## 第一步：识别发行

当用户提到一个发行时，推断：

1. **组织** — 从沙盒结构或对话上下文中获取
2. **艺术家** — 从当前工作空间、对话历史或询问中获取
3. **发行名称** — 专辑名称、EP 名称、单曲名称
4. **发行标识符** — 从名称中派生（e.g. "Blue Slide Park" → `blue-slide-park`）

**如果信息不明确，询问：**
> "您指的是哪个艺术家和发行？"

## 第二步：检查是否存在 RELEASE.md

一旦确定艺术家和发行：

```
1. 导航到：orgs/{org}/artists/{artist-slug}/releases/{release-slug}/
2. 检查是否存在 RELEASE.md
3. 如果是 → 读取并继续
4. 如果不是 → 询问："未找到 [发行] 的 RELEASE.md。是否需要创建一个？"
```

## 第三步：创建、更新或拉取

| 用户意图 | 操作 |
|-------------|--------|
| 讨论发行 | 读取 RELEASE.md，用作上下文 |
| 添加信息 | 更新相关部分 |
| 请求交付物 | 从 RELEASE.md 拉取数据，生成输出 |
| 开始新发行 | 创建文件夹结构 + RELEASE.md 从模板 |

### 创建新发行

```bash
# 1. 创建文件夹结构（从沙盒根目录）
mkdir -p "orgs/{org}/artists/{artist-slug}/releases/{release-slug}"

# 2. 从模板创建 RELEASE.md
# 3. 首先填写部分 1（项目快照）
```

### 更新现有发行

1. 读取当前的 RELEASE.md
2. 确定需要更新的部分
3. 仅更新这些部分
4. 在文档历史（部分 18）中记录变更

## 核心原则

1. **绝不编造数据** — 如果信息缺失，保留部分为空
2. **主动作为** — 信息可用时立即填写部分
3. **尊重共享标签** — `[INTERNAL]`, `[SHAREABLE]`, `[OPS]` 控制分发
4. **每个发行一个文档** — 所有发行信息都存放在 RELEASE.md 中
5. **始终确认发行** — 在进行变更前，确认是哪个发行。

## 共享标签

| 标签 | 含义 |
|-----|---------|
| `[INTERNAL]` | 分享前需清理 |
| `[SHAREABLE]` | 可供公关、DSP、管理层、代理使用 |
| `[OPS]` | 运营/生产团队参考 |

## 文档部分

| 部分 | 目的 | 共享 |
|---------|---------|-------|
| 1. 项目快照 | 核心发行信息 | SHAREABLE |
| 2. 发行标识符与元数据 | UPC、ISRC、曲目数据 | OPS |
| 3. 叙述与定位 | 企划、故事、对比参考 | SHAREABLE |
| 4. 艺术家背景 | 传记、流媒体历史 | SHAREABLE |
| 5. 受众与市场数据 | 人口统计、地理数据 | SHAREABLE |
| 6. DSP 与流媒体策略 | 企划、播放列表目标 | SHAREABLE |
| 7. 营销策略 | 活动目标、KPI | INTERNAL |
| 8. 社交与数字营销 | 自然流量、付费、影响者 | INTERNAL |
| 9. 公关与媒体关系 | 媒体目标、材料 | SHAREABLE |
| 10. 视觉与创意资产 | 艺术作品、视频、画布 | SHAREABLE |
| 11. 实体生产 | 黑胶、CD、磁带规格 | OPS/INTERNAL |
| 12. 商品 | 商品、策略 | INTERNAL |
| 13. 体验与户外广告 | 活动、广告牌 | INTERNAL |
| 14. 巡演与现场 | 日期、场地、路线 | SHAREABLE |
| 15. 团队联系人 | 所有利益相关者 | INTERNAL |
| 16. 预算概览 | 已分配/已花费/剩余 | INTERNAL |
| 17. 性能追踪 | 每周 KPI、学习成果 | INTERNAL |
| 18. 链接与资源中心 | 所有资产链接 | — |

## 生成交付物

参考 `references/deliverables.md` 中的输出模式：

- **DSP 企划** — 从部分 1、3、4、5、6 拉取
- **公关单页** — 从部分 1、3、4、9、10 拉取
- **实体生产规格** — 从部分 2、11 拉取
- **营销简报** — 从部分 1、3、5、6、7、8 拉取
- **巡演营销简报** — 从部分 1、3、5、14 拉取

生成任何交付物时：
1. 检查 RELEASE.md 中的必要数据
2. 确定缺失的字段
3. 请求用户补充信息 或 带有空白标记生成
4. 按交付物规范格式化

## 模板

完整的发行模板在 `references/release-template.md` 中。复制此文件开始新发行。

## 部分深入解析

参考 `references/section-guide.md` 获取每个部分的详细指导，包括：
- 每个字段的含义
- 常见数据来源
- 填写最佳实践
- 需注意的警示标志

## 工作流程

### 新发行设置

1. 复制模板 → RELEASE.md
2. 填写部分 1（项目快照）
3. 填写部分 2.2（曲目元数据）作为可用
4. 起草部分 3（叙述与定位）
5. 拉取艺术家数据用于部分 4-5
6. 构建DSP企划（部分 6）
7. 按时间线继续完成剩余部分

### 发行前检查清单

在宣布前，验证以下部分是否完整：

- [ ] 部分 1：所有日期确认
- [ ] 部分 2：分配 UPC，所有曲目 ISRC
- [ ] 部分 3：企划和叙述最终确定
- [ ] 部分 6：提交 DSP 企划
- [ ] 部分 9：准备媒体材料
- [ ] 部分 10：所有视觉资产交付

### 发行周检查清单

- [ ] 部分 6：预购链接上线
- [ ] 部分 7：执行第二阶段行动
- [ ] 部分 8：启动付费广告
- [ ] 部分 9：媒体禁令解除
- [ ] 部分 17：追踪仪表板准备就绪

### 发行后

- [ ] 部分 17：记录每周 KPI
- [ ] 部分 17：记录成果和学习
- [ ] 更新文档历史

## 示例交互

### 创建新发行
> **用户：** "为新的专辑 'Decisions' 创建 RELEASE.md"
> 
> **流程：**
> 1. 发行 = "Decisions", 标识符 = `decisions`
> 2. 创建 `releases/decisions/RELEASE.md` 从模板
> 3. 询问："发行日期是什么？"（用于填写部分 1）

### 添加元数据
> **用户：** "更新 'Sunrise' RELEASE.md 的这些 ISRC"
>
> **流程：**
> 1. 发行 = "Sunrise", 标识符 = `sunrise`
> 2. 打开 `releases/sunrise/RELEASE.md`
> 3. 更新部分 2.2 为 ISRC 数据
> 4. 如果文件未找到 → "未找到 'Sunrise' 的 RELEASE.md。是否需要创建一个？"

### 生成交付物
> **用户：** "从 Midnights RELEASE.md 生成 DSP 企划"
>
> **流程：**
> 1. 读取 `releases/midnights/RELEASE.md`
> 2. 从部分 1、3、4、5、6 拉取数据
> 3. 按交付物规范格式化
> 4. 如果缺失字段 → "缺失 [字段]。是否带空白标记继续？"

### 检查发行状态
> **用户：** "'For All The Dogs' 发行文档缺失什么？"
>
> **流程：**
> 1. 读取 `releases/for-all-the-dogs/RELEASE.md`
> 2. 运行发行前检查清单
> 3. 报告不完整部分
