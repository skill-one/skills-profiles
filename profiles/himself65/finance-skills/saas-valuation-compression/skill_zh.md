# SaaS 估值压缩分析器

## 该技能的功能

针对给定的 SaaS 公司，研究其融资历史，并在每个轮次中计算基于 ARR 的估值倍数。然后使用涵盖宏观利率、增长轨迹、叙事转变和可比公司的结构化框架来解释压缩（或扩张）。始终以内联可视化（使用可视化工具）和简洁的文本解释的形式呈现输出。不要只返回一堵数字墙。

---

## 分步工作流程

### 1. 通过网络搜索收集数据

尽可能并行运行搜索，搜索以下内容。

**针对目标公司：**
- `[公司] 融资轮次 估值 ARR 收入`
- `[公司] 第[X]轮 融资 估值`（针对每一轮）
- `[公司] 每年经常性收入 ARR [年份]`（针对每一轮日期）
- `[公司] 投资者 主要投资者 [轮次]`

**针对宏观背景：**
- `SaaS ARR 估值倍数 [年份] 私募市场`
- 如果搜索结果不足，使用下方已知的基准表格作为备用。

**针对叙事背景：**
- `[公司] AI 客户 产品发布 [年份]` — AI 叙事溢价？
- `[公司] 增长率 流失率 NRR [年份]` — 基本面变化？

### 2. 构建数据模型

针对每一轮融资，提取或估计：

| 字段 | 获取方式 |
|---|---|
| 融资轮次名称 | 直接从搜索结果获取 |
| 日期 | 直接从搜索结果获取 |
| 融资金额 | 直接从搜索结果获取 |
| 融资后估值 | 直接获取或根据持股比例计算；如果不可用，注明为估计值 |
| 融资轮次日期的 ARR | 明确搜索；如果未找到，根据客户数量 x ARPC 估计或插值 |
| 估值倍数 | `估值 / ARR` |
| 主要投资者 | 直接获取 |

**ARR 估计启发式方法（当未公开时）：**
- 种子轮/系列 A：ARR 通常为 50 万美元–300 万美元
- 系列B：通常为 500 万美元–2000 万美元
- 系列C：通常为 2000 万美元–6000 万美元
- 如果可用，对照客户数量 x 平均交易规模进行交叉验证

### 3. 计算压缩指标

针对每一对连续的轮次（例如，B → C）：

```
倍数压缩百分比 = (后期倍数 - 早期倍数) / 早期倍数 × 100
估值增长百分比 = (后期估值 - 早期估值) / 早期估值 × 100
ARR 增长百分比 = (后期 ARR - 早期 ARR) / 早期 ARR × 100
```

关键洞察：`估值增长 = ARR 增长 + 倍数变化`
如果 ARR 增长速度快于倍数压缩，绝对估值仍然会上升。

### 4. 将压缩归因于原因

使用此清单。针对每个原因，评级：主要 / 贡献 / 不适用。

**宏观 / 利率环境**
- 早期轮次是否在 2020–2021 年的零利率泡沫期间？（增加约 2–5 倍人为溢价）
- 后期轮次是否在 2022–2023 年的加息期间？（消除泡沫溢价）
- 后期轮次是否在 2026 年 4 月的软件熔断期间或之后？（公共 SaaS 从 52 周高点下降 40–86%；关税/贸易战驱动的抛售压垮了整个行业的倍数——即使是高增长名称如 Figma -87%，monday.com -80%，HubSpot -70%，ServiceNow -58%）
- 参考：按时期划分的 SaaS 私募市场中位数倍数：

| 时期 | 大约中位数 ARR 倍数（私募） | 背景 |
|---|---|---|
| 2019 | ~8–12 倍 | 大流行前基准 |
| 2020 | ~12–18 倍 | 零利率开始，倍数扩张 |
| 2021 年第一季度–第三季度峰值 | ~35–45 倍 | 泡沫峰值 |
| 2022 年下半年 | ~15–20 倍 | 加息开始，第一次压缩浪潮 |
| 2023 年低谷 | ~8–12 倍 | 利率平台期，估值重置 |
| 2024 | ~12–18 倍 | AI 叙事复苏，选择性重估 |
| 2025 年上半年 | ~16–22 倍 | 持续的 AI 驱动的复苏 |
| 2025 年下半年–2026 年第一季度 | ~10–16 倍 | 关税冲击 / 贸易战抛售开始 |
| **2026 年第二季度（4 月熔断）** | **~6–10 倍** | **软件熔断——整个行业崩溃，公共 SaaS 从 52 周高点下降 40–86%** |

*(这些是粗略的私募市场估计。公共 SaaS 倍数大约低 30–50%。4 月 2026 年的数字反映了急剧抛售；私募估值通常滞后公共市场 1–2 个季度。)*

**增长减速**
- 在两轮之间，YoY ARR 增长率是否显著放缓？（最常见的原因）
- NRR/净留存率是否下降？

**叙事转变**
- 公司是否失去了一个主要产品故事（例如，失去了 PLG 理论，错过了类别领导地位）？
- 竞争对手是否出现或现有竞争对手是否赶了上来？

**AI 溢价（正面或负面）**
- 公司是否为 AI 原生公司（如 OpenAI、Anthropic 等）提供服务作为客户？→ 溢价
- 公司是否可信地转向 AI 叙事？→ 溢价
- 公司未能阐明 AI 故事？→ 与同行相比存在折价
- 注意：在 4 月 2026 年的熔断中，即使是强大的 AI 叙事也没有保护倍数——Snowflake (-53%)、Datadog (-46%)、MongoDB (-48%) 都大幅下跌，尽管有 AI 尾风。AI 溢价可能是必要的，但在宏观驱动的抛售中不是充分的。

**竞争 / 市场**
- 市场饱和信号（例如，Okta 对 WorkOS 的压力，Auth0 的竞争）
- 客户集中度风险暴露

**投资者供给 / 需求**
- 后期轮次是否规模更小且更严格选择？→ 价格纪律
- 新的领先投资者层级（例如，一级增长基金 vs 种子基金）？→ 可能表明更高的或更低的信心

### 5. 构建可视化

使用可视化工具呈现：

1. **指标卡片行** — 每一轮的估值、每一轮的 ARR、每一轮的倍数、压缩百分比
2. **折线图** — 公司的 ARR 倍数随时间变化 vs 宏观 SaaS 中位数
3. **柱状图** — 估值增长 vs ARR 增长 vs 倍数变化（分解）
4. **比较柱状图** — 公司压缩 vs 2–3 个同行可比公司（Vercel、Netlify、Fastly 或行业同行）
5. **原因归因表格** — 在文本中内联（每个因素按主要 / 贡献 / 不适用评级）

参考设计指南：使用蓝绿色表示正面/增长，珊瑚色表示压缩/负面，灰色表示宏观基准，蓝色表示估值数字。始终遵循 CSS 变量系统。

### 6. 撰写文本摘要

结构如下：
1. **一句话结论** — 例如，"倍数压缩了 36%，但 ARR 增长了 5 倍，因此绝对估值上升了 3.8 倍。"
2. **主要原因** — 解释压缩的首要因素
3. **叙事溢价/折价** — AI 故事、类别领导地位或缺乏 thereof
4. **可比背景** — 该公司的压缩与同行相比如何？
5. **未来影响** — 什么需要为下一轮的倍数扩张为真？

始终生成：
- 内联可视化（可视化工具）— 优先呈现
- 文本摘要（5–8 句话）— 可视化之后
- 可选：如果 ARR 必须估计，则标记数据置信度水平

## 边缘情况

- **下调轮次**：倍数和绝对估值都下降。注意摊薄影响。
- **没有公开 ARR**：使用客户数量 x 估计的 ARPC，并标记为估计值，附 +/- 范围。
- **单一轮次**：计算该日期与行业中位数的倍数；无法进行压缩分析。解释这一点。
- **未盈利**：如果适用，使用前瞻性 ARR 或 GMV 倍数；注意不同的基础。
- **收购/战略收购**：收购价格通常反映战略溢价或困境，而不是纯粹的 ARR 倍数——标记这一点。
