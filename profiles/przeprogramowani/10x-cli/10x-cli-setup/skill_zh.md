# 10x-cli 设置

准备用户的 CLI 和项目，然后将工作上下文传递给引导。在选择版本、安装辅助工具或运行课程命令之前，请阅读
[兼容性参考](references/compatibility.md)。使用实际运行者的帮助及其匹配的发布源；移动的 master README 并不说明已安装的 CLI 支持什么。

下一个 CLI 版本还通过 `10x helpers install --tool <选择的配置文件>` 提供仅针对项目的捆绑安装。此命令是 **未发布的**，并且不包含在 1.21.0/1.22.0 master 基线中：首先检查实际运行者的 `helpers --help`。遵循本地参考中的 **捆绑公共副本** 获取完整文件、明确目标和冲突处理；当运行者不支持时，保留现有的已固定公共路径。

## 1. 建立项目和现有安装

使用用户的请求和现有会话上下文。在写入文件之前，识别预期的项目目录、shell 和 AI 工具。对于引导的 10xDevs4 练习，上下文是 macOS/zsh、`10xdevs4`、`claude-code`、`pl`；不要将其无声地应用于 v3 项目或选择了其他配置文件的用户。

在 POSIX shell 中，检查运行者而不隐藏失败：

```bash
pwd
command -v 10x
```

如果找到，运行 `10x --version` 及其 `--help`、`get --help`、`sync --help` 和 `auth --help`。记录可执行路径和安装方法。现有的工作安装不需要重新安装或登录。如果存在可执行文件但失败，保留错误并诊断其运行时/PATH/权限；这与缺失命令不同。在其他系统上使用其 shell 的可执行文件查找，而不是 POSIX 检测片段。

检查项目的 `.10x-cli.json` 和现有配置文件清单作为本地元数据，而不编辑它们。课程绑定跨配置文件共享；更改 `--tool` 不能将 v3 切换到 v4。对于使用已绑定 v3 项目的 v4 练习，使用单独的目录并保留 v3 项目。保留损坏、未知或冲突的绑定/清单以供诊断；不要删除它们以强制访问。

## 2. 选择兼容的运行者，然后仅在需要时安装

遵循本地参考中的 **版本和能力检查**。记录实际包版本、源修订版和支持的语法。发布的语法是 `get m1l1 --type skills --name NAME`；位置参数是课程参考，不是技能名称。验证相应的内容中的课程和技能。本地构建或更高版本号并不能证明两者。如果技能过滤器支持不可用，继续准备项目和公共辅助工具，并在下载前报告具体的待处理能力。不要在用户选择之前替换完整课程或另一个课程。

对于 npm/npx，验证 Node 是否符合该包的 `engines`（检查的基线需要 Node 20+）。当没有合适的全局 CLI 时，参考中固定的 npx 运行者避免了全局安装。尊重用户请求的全局或独立方法；使用其匹配的安装/更新程序。保留现有的授权进行安装。权限错误不是自动 `sudo`、全局配置重置或删除凭证的理由。

安装或更新后重新运行版本/帮助。在整个设置和引导过程中保留一个确切的运行者，以便 PATH 上的旧版 `10x` 不能替换已验证的 npx 版本。如果没有网络，检查可用的本地版本/帮助和匹配的打包文档；将发布、访问和下载检查留作未验证。不要从离线版本检查中声称设置已完成。

## 3. 将身份验证与课程可用性分开检查

运行选定运行者的 `auth --status`。它可以联系课程 API，但不会请求登录电子邮件。检查会话有效性和实时访问状态：有效的令牌或成功退出并不能证明 `access_checked` 或 v4 访问。保留无法检查访问时的错误。

仅在需要登录时，让用户在交互式终端中运行验证的 `auth` 命令并完成其显示的流程。检查的版本使用通过电子邮件或 Circle 消息发送的魔法链接（`--method email` / `--method circle`）；遵循选定的发布的帮助。不要请求电子邮件、打开魔法链接或在未经用户授权的情况下代表用户执行登录。永远不要读取 `auth.json`、令牌、魔法链接 URL 或电子邮件内容。仅总结会话/访问状态。

然后使用选定运行者的纯 `list`：没有 `--course` 时，CLI 从项目的 `.10x-cli.json` 绑定中获取版本，或在尚未绑定的目录中，从实时 API 推荐（账户可以到达的最高版本）。仅在故意检查另一个有资格的版本时才添加 `--course <slug>`。区分没有会员资格、未发布的课程、锁定模块和网络故障。重新安装 CLI 或选择不同的工具并不能授予访问权限。在后续的下载/同步命令中明确保留 `--tool` 和 `--lang`，并省略 `--course`，以便每个下载都保持在项目的版本上。

## 4. 在制造工具目录之前诊断准备情况

运行选定运行者的 `doctor --json`；读取所有 `data.checks` 和 `data.overall`，以及退出状态。外层的 `status: "ok"` 是输出信封，不是每个检查都通过的承诺。Doctor 使用配置的配置文件（或其默认值），因此比较报告的工具与预期的工具；它在检查的基线中没有 `--tool` 标志。其身份验证检查还报告解析的版本和选择原因（`details.course`、`details.selectionReason`）——将其用作第一次下载前的自检。项目在其第一次写入时绑定到一个版本；后续版本需要一个新的空目录，因为将其写入已绑定的项目会因 `course_mismatch` 失败。

在新项目在第一次下载之前，可能会缺少 `.claude/`（或报告的配置文件目录）。如果这是唯一的失败并且这是正确的可写项目，解释说第一次成功的下载会创建它。不要创建一个虚拟目录只是为了让检查变绿。保留并分别处理任何身份验证、访问、API、绑定或写入权限失败。离线时跳过的更新查找并不能证明 CLI 是最新的。

## 5. 交给实际引导副本

定位项目的已安装 `10x-cli-guide/SKILL.md` 及其自身的 `references/compatibility.md`。使用参考在添加或更新之前检查其安装渠道/所有者。如果不存在，通过选定的公共按需或兼容 CLI 渠道安装引导；验证生成的文件。单独安装 npm CLI 并不会在代理中激活任何辅助工具。不要声称缺失的引导可用或依赖未验证的斜杠命令发现。告诉代理读取确切的材料化引导路径及其本地参考。

在对话中传递这个紧凑的上下文，而不包含秘密：

```text
项目：绝对 cwd；课程绑定或未绑定
课程 / 工具 / 请求的语言：10xdevs4 / claude-code / pl（或用户的选择）
运行者：确切的可执行文件或固定的 npx 命令；观察到的版本和源参考
CLI 安装/更新方法：npx pin / npm global / 独立资产
身份验证：有效 / 需要登录 / 未知；实时课程访问和模块状态
设置辅助工具：实际路径，公共或 CLI 所有者，如果已知则观察到的源参考
引导辅助工具：实际路径，所有者和源参考如果已知；完整的参考存在
准备情况：验证的检查；剩余的发布/网络/访问问题，如果有
下一步任务：引导的课程设置（idea-check/init/shape/prd）→ 使用 → 同步旅程，或用户的更窄请求
```

对于课程 1 设置，在转交中保留所有四个技能：
`10x-idea-check`、`10x-init`、`10x-shape` 和 `10x-prd`，及其参考。
想法评估是可选运行的，不是在课程设置期间省略其文件的理由。对特定技能的请求仍然是一个更窄的下载。将材料化文件与原生斜杠命令发现分开验证。

准备好后，继续在引导中，不要重新运行安装或要求用户重复已提供的选项。如果下载还不能运行，请精确报告剩余的阻塞项；不要将准备视为完成的真实旅程。
