# 研究决策室技能

创建一个单页面的 HTML 决策工件，帮助产品或设计团队将混乱的证据转化为清晰的下一步行动。输出不是装饰性的研究演示文稿。它是一个用于辩论的工作室：证据、主题、信心、权衡和推荐的实验将一起保持可见。

## 资源地图

```text
research-decision-room/
├── SKILL.md
├── example.html
└── references/
    ├── checklist.md
    └── evidence-model.md
```

在综合之前阅读 `references/evidence-model.md`，在发出工件之前运行 `references/checklist.md`。

## 何时使用此技能

当用户有任何混合时使用此技能：

- 访谈笔记、可用性测试观察、支持工单、销售通话笔记、应用商店评论、NPS 评论、调查开放式文本、分析片段或产品决策背景。
- 需要证据的决策："我们应该构建 X 吗？"、"我们应该尝试哪个引导路径？"、"用户为什么流失？"、"客户实际说的慢是什么意思？"
- 需要与不会阅读长篇研究报告的利益相关者分享发现。

不要用于纯视觉灵感、活动构思或品牌情绪板。

## 工作流程

### 第 1 步 - 建立决策框架

从用户的提示中确定决策范围。如果用户没有给出决策，则从证据中推导出一个，并标记为推断。

用简短的框架编写：

- 决策问题。
- 受众或细分。
- 时间范围。
- 已知的约束。
- 此工件不会决定的。

如果关键背景缺失且任务没有被阻塞，则用标记的假设继续，而不是问一个广泛的问题。

### 第 2 步 - 构建证据账本

使用 `references/evidence-model.md` 中的模型将每个有用信号规范化为账本行。

每行账本必须包括：

- `id`：简短的稳定 ID，例如 `I-03`、`T-14`、`M-02`。
- `source_type`：访谈、可用性、支持、调查、分析、销售、现场笔记或利益相关者。
- `segment`：用户类型或 "未知"。
- `signal`：一句话的观察。
- `quote_or_metric`：直接引语、指标或 "未提供"。
- `strength`：强、中或弱。
- `limitations`：为什么这些证据可能存在偏见或不完整。

永远不要编造引语、参与者数量、日期、收入影响或指标。如果用户没有提供数字，请使用 "未提供" 并解释哪些证据会增加信心。

### 第 3 步 - 综合主题和张力

将证据聚类为 4 到 6 个主题。对于每个主题：

- 用人类语言命名主题。
- 列出支持它的证据 ID。
- 解释其背后的行为，而不仅仅是 UI 抱怨。
- 将信心标记为高、中或低。
- 注明矛盾或细分差异。

优先使用动词而不是名词："当第一个空白状态要求太多时，团队会放弃设置" 比起 "引导问题" 更好。

### 第 4 步 - 评分机会

创建一个 3 到 5 个选项的机会矩阵。在 1 到 5 的量表上对每个选项进行评分：

- 证据强度。
- 用户痛点。
- 商业杠杆。
- 实施风险，其中 5 表示低风险，1 表示高风险。

显示总分，但不要让分数取代判断。添加一句说明为什么最高推荐胜出。

### 第 5 步 - 起草决策备忘录

编写决策备忘录，包括：

1. 推荐的行动。
2. 为什么现在。
3. 支持它的证据。
4. 可能出错的地方。
5. 下一步要衡量的内容。
6. 可逆的下一步。

保持备忘录简短，以便在一分钟内阅读。

### 第 6 步 - 创建 HTML 工件

生成一个自包含的 `index.html`。使用活动的 `DESIGN.md` 来设置排版、间距、颜色角色和组件语气，但保持信息架构稳定：

1. 包含决策问题、信心和最后更新标签的标题栏。
2. 高管摘要，包含推荐、风险和下一个实验。
3. 带有过滤芯片的证据账本。
4. 主题地图，包含证据 ID 和信心。
5. 机会矩阵。
6. 决策备忘录。
7. 实验队列，包含负责人、指标和成功阈值。
8. 假设和限制。

工件应该是交互式的但持久的。允许使用简单的纯 vanilla JavaScript 进行过滤证据、切换视图或突出显示相关 ID。不需要框架依赖。

### 第 7 步 - 自检和发出

运行清单。然后发出一句简洁的定向语句和一个 HTML 工件：

```xml
<artifact identifier="research-decision-room" type="text/html" title="Research Decision Room">
<!doctype html>
<html>...</html>
</artifact>
```

在关闭的 `</artifact>` 之后什么也不需要。
