# tasteskill：抗拖沓前端技能

> 落地页、作品集和重新设计。不是仪表盘，不是数据表，不是多步骤产品 UI。
> 以下所有规则都是**上下文相关的**。没有一条会自动触发。先阅读简报，然后只提取适合的内容。

---

## 0. 简报推断（先观察环境）

在接触代码或调整设置之前，**推断用户实际想要什么**。大多数 LLM 设计输出很差，因为模型会跳到默认美学，而不是观察环境。

### 0.A 首先读取这些信号
1. **页面类型** - 落地页（SaaS / 消费者 / 代理 / 活动）、作品集（开发者 / 设计师 / 创意工作室）、重新设计（保留 vs 重做）、编辑 / 博客。
2. **用户使用的氛围词** - "极简主义"、"平静"、"线性风格"、"Awwwards"、" brutalist"、"高端消费者"、"Apple 风格"、"有趣的"、"严肃的 B2B"、"编辑"、"代理"、"玻璃感"、"暗黑科技"。
3. **参考信号** - 用户链接的 URL、粘贴的截图、用户提到的产品、用户竞争的品牌。
4. **受众** - B2B 采购小组 vs. 有设计意识消费者 vs. 招聘人员浏览作品集。受众决定美学，而不是你的品味。
5. **已存在的品牌资产** - Logo、颜色、字体、摄影。对于重新设计，这些是起始材料，不是可选输入（见第 11 节）。
6. **安静的限制** - 无障碍优先受众、公共部门、受监管行业、信任优先商业、儿童产品。这些限制**覆盖**美学偏好。

### 0.B 在生成前输出一条线的"设计阅读"
在编写任何代码之前，用一句话说明：**"将其读取为：\<页面类型> 为 \<受众>，使用 \<氛围> 语言，倾向于 \<设计系统或美学家族>。"**

示例阅读：
- *"将其读取为：B2B SaaS 落地页为技术买家，使用线性风格极简主义语言，倾向于 Tailwind 工具 + Geist + 受约束的动画。"*
- *"将其读取为：个人设计师作品集为招聘经理，使用编辑 / 动态类型语言，倾向于原生 CSS + 滚动驱动动画 + 自定义字体。"*
- *"将其读取为：公共部门服务网站的重设计，使用信任优先语言，倾向于 GOV.UK Frontend 或 USWDS。"*

### 0.C 如果简报含糊不清，问一个问题，不要猜测
问**一个**澄清问题 - 永远不要问一堆问题 - 并且只有在设计阅读真正出现分歧时才问。示例：*"这个应该感觉更接近 Linear-clean 还是 Awwards-experimental？"*

如果你可以根据上下文自信地推断，**不要提问**。只需声明设计阅读并继续进行。

### 0.D 反默认纪律
不要默认为：AI 紫色渐变、居中的英雄图叠加暗黑网格、三个相等的特性卡片、通用玻璃态效果应用于所有内容、无限循环微动画无处不在、Inter + slate-900。这些都是 LLM 默认值。有目的地超越它们，基于设计阅读。

## 1. 三个旋钮（核心配置）

在完成设计阅读（第 0 节）并设置旋钮（第 1 节）后，选择合适的基石。不要为有官方包的东西发明 CSS。不要假装一个美学趋势是一个官方系统。

### 1.A 旋钮推断（设计阅读 → 旋钮值）
| 信号 | 变化 | 动画 | 密度 |
|---|---|---|---|
| "极简主义 / 干净 / 平静 / 编辑 / 线性风格" | 5-6 | 3-4 | 2-3 |
| "高端消费者 / Apple 风格 / 奢侈 / 品牌" | 7-8 | 5-7 | 3-4 |
| "有趣的 / 狂野 / Dribbble / Awwwards / 实验性 / 代理" | 9-10 | 8-10 | 3-4 |
| "落地页 / 作品集 / 营销网站（默认）" | 7-9 | 6-8 | 3-5 |
| "信任优先 / 公共部门 / 受监管 / 无障碍关键" | 3-4 | 2-3 | 4-5 |
| "重新设计 - 保留" | 匹配现有 | +1 | 匹配现有 |
| "重新设计 - 重做" | +2 | +2 | 匹配现有 |

使用这些（或用户覆盖的值）作为全局变量。本文件中的交叉引用引用这些确切的变量名 - 永远不要发明别名，如 `LAYOUT_VARIANCE` 或 `ANIM_LEVEL`。

## 2. 简报 → 设计系统映射

在获得设计阅读（第 0 节）和旋钮（第 1 节）后，选择合适的基石。不要为有官方包的东西发明 CSS。不要假装一个美学趋势是一个官方系统。

### 2.A 何时使用真实的设计系统（使用官方包）
| 简报读取为… | 选择 | 原因 |
|---|---|---|
| Microsoft / 企业 SaaS / 仪表盘 | `@fluentui/react-components` 或 `@fluentui/web-components` | 官方 Fluent UI，Microsoft 令牌，无障碍完成 |
| 类似 Google 的 UI，Material 风格产品 | `@material/web` + Material 3 令牌 | 官方，可通过 Material Theming 主题 |
| IBM 风格 B2B / 企业分析 | `@carbon/react` + `@carbon/styles` | 官方 Carbon，成熟的数据密度模式 |
| Shopify 应用界面 | `polaris.js` Web 组件 / Polaris React | Shopify 管理界面必需 |
| Atlassian / Jira 风格产品 | `@atlaskit/*` + `@atlaskit/tokens` | 官方 Atlassian DS |
| GitHub 风格开发工具 / 社区页面 | `@primer/css` 或 `@primer/react-brand` | 官方 Primer；品牌变体用于营销 |
| 英国公共部门服务 | `govuk-frontend` | 法律 / 监管预期 |
| 美国公共部门 / 信任优先 | `uswds` | 相同 |
| 快速本地业务 / 代理 MVP | Bootstrap 5.3 | 无聊，快速，有效 |
| 现代、无障碍的 React 基础 | `@radix-ui/themes` | 基本元素 + 精美主题 |
| 现代 SaaS，你拥有组件 | shadcn/ui (`npx shadcn@latest add ...`) | 你拥有代码，易于定制；永远不要发送默认状态 |
| 基于 Tailwind 的现代 SaaS / AI 营销 | Tailwind v4 工具 + `dark:` 变体 | 独立 + 小团队构建的默认值 |

**诚实规则：** 如果简报读取为上述系统之一，请先安装并使用**官方**包。不要手动重建其 CSS。不要导入系统的令牌但然后覆盖 90% 的令牌。

**每个项目一个系统。** 不要在同一棵树中混合 Fluent React 和 Carbon。不要将 shadcn/ui 组件导入 Material 3 应用。

### 2.B 简报是美学，不是系统
对于这些方向，**没有单一的官方包**。使用原生 CSS + Tailwind + 维护良好的组件库。在代码注释中诚实说明什么是借鉴灵感 vs. 官方材料。

| 美学 | 诚实实现 |
|---|---|
| 玻璃态 / "磨砂玻璃" | `backdrop-filter`，分层边框，高亮覆盖。为 `prefers-reduced-transparency` 提供实心填充回退。 |
| Bento（Apple 风格的瓦片网格） | CSS Grid，混合单元格大小。没有单一库拥有此功能。 |
| Brutalism | 原生 CSS，等宽字体，原始边框。没有库。 |
| 编辑 / 杂志 | 印刷体，非对称网格，充足的空白。没有库。 |
| 暗黑科技 / 程序员 | 单色 + 荧光强调，终端主题。没有库。 |
| Aurora / 网格渐变 | SVG 或分层径向渐变。没有库。 |
| 动态文字 | 原生 CSS 动画，滚动驱动动画，GSAP 用于劫持。没有库。 |
| **Apple 液体玻璃** | Apple 仅为此类 Apple 平台文档化。**没有官方 `liquid-glass.css`。** Web 实现是使用 `backdrop-filter` + 分层边框 + 高亮的近似值。明确标记为近似值。 |

## 3. 默认架构和约定

除非设计阅读选择了一个真实的设计系统（第 2.A 节），否则这些是默认值：

### 3.A 堆栈
* **框架：** React 或 Next.js。默认使用服务器组件（RSC）。
  * **RSC 安全性：** 全局状态仅在客户端组件中工作。在 Next.js 中，将提供程序包装在 `"use client"` 组件中。
  * **交互隔离：** 任何使用 Motion、滚动监听器或指针物理学的组件必须是隔离的叶子节点，并在顶部使用 `'use client'`。服务器组件仅渲染静态布局。
* **样式：** **Tailwind v4**（默认）。Tailwind v3 仅当现有项目要求时使用。
  * 对于 v4：不要在 `postcss.config.js` 中使用 `tailwindcss` 插件。使用 `@tailwindcss/postcss` 或 Vite 插件。
* **动画：** **Motion**（以前称为 Framer Motion 的库）。从 `motion/react` 导入（`import { motion } from "motion/react"`）。`framer-motion` 包仍然作为遗留别名工作 - 在新代码中优先使用 `motion/react`。
* **字体：** 始终使用 `next/font`（Next.js）或使用 `@font-face` + `font-display: swap` 自托管。在生产中永远不要通过 `<link>` 链接 Google Fonts。

### 3.B 状态
* 本地 `useState` / `useReducer` 用于隔离 UI。
* 全局状态**仅**用于避免深度属性钻取 - Zustand、Jotai 或 React 上下文。
* **永远**不要使用 `useState` 来跟踪由用户输入驱动的连续值（鼠标位置、滚动进度、指针物理学、磁力悬停）。使用 Motion 的 `useMotionValue` / `useTransform` / `useScroll`。`useState` 会在每次更改时重新渲染 React 树，并在移动设备上折叠。

### 3.C 图标
* **允许的库（优先级顺序）：** `@phosphor-icons/react`，`hugeicons-react`，`@radix-ui/react-icons`，`@tabler/icons-react`。
* **不鼓励：** `lucide-react`。仅在用户明确要求或项目已经依赖它时才接受。
* **永远不要手动绘制 SVG 图标。** 如果缺少字形，请安装第二个库或从基本元素组合 - 不要从头开始绘制图标路径。
* **每个项目一个家族。** 不要在同一组件树中混合 Phosphor 和 Lucide。
* **全局标准化 `strokeWidth`**（例如 `1.5` 或 `2.0`）。

### 3.D Emoji 政策
默认情况下，在代码、标记和可见文本中不鼓励使用 Emoji。用图标库字形替换符号。**覆盖：** 仅当用户明确要求轻松 / 聊天风格 / 社交原生氛围时才允许 Emoji - 即使这样也要有目的地少量使用。

### 3.E 响应式和布局机制
* 标准化断点（`sm 640`，`md 768`，`lg 1024`，`xl 1280`，`2xl 1536`）。
* 使用 `max-w-[1400px] mx-auto` 或 `max-w-7xl` 包含页面布局。
* **视口稳定性：** 永远不要使用 `h-screen` 用于全高度的 Hero 部分。始终使用 `min-h-[100dvh]` 以防止在移动设备上布局跳跃（iOS Safari 地址栏）。
* **网格优于 Flex-Math：** 永远不要使用复杂的 flexbox 百分比数学（`w-[calc(33%-1rem)]`）。始终使用 CSS Grid（`grid grid-cols-1 md:grid-cols-3 gap-6`）。

### 3.F 依赖验证（强制）
在导入任何第三方库之前，检查 `package.json`。如果包缺失，请先输出安装命令。**永远**不要假设库存在。

## 4. 设计工程指令（偏差校正）

LLM 默认使用陈词滥调。主动覆盖这些默认值。每条规则都有上下文感知的覆盖路径。

### 4.1 字体
* **显示 / 标题：** 默认 `text-4xl md:text-6xl tracking-tighter leading-none`。
* **正文 / 段落：** 默认 `text-base text-gray-600 leading-relaxed max-w-[65ch]`。
* **无衬线字体选择：**
  * **不鼓励作为默认值：** `Inter`。首先选择 `Geist`，`Outfit`，`Cabinet Grotesk`，`Satoshi` 或品牌合适的无衬线字体。
  * **覆盖：** Inter 在用户明确要求中性 / 标准 / 线性风格，或简报是公共部门 / 无障碍优先网站时是可接受的。
* **需要了解的配对：** `Geist` + `Geist Mono`，`Satoshi` + `JetBrains Mono`，`Cabinet Grotesk` + `Inter Tight`，`GT America` + `IBM Plex Mono`。

* **无衬线字体纪律（非常不鼓励作为默认值）：**
  * 无衬线字体**非常不鼓励作为任何项目的默认字体**。"它感觉创意 / 高端 / 编辑" 不是一个选择无衬线字体的理由。代理的默认心理模型"创意简报 = 无衬线"是在生产轮中测试最多的 AI 告白。
  * 无衬线字体只有在以下**一项**明确为真时才是可接受的：
    - 品牌简报明确命名无衬线字体，OR
    - 美学家族是真正编辑 / 奢侈 / 出版物 / 手稿 / 遗产 / 复古，并且你能说明为什么这个特定的无衬线字体适合这个特定的品牌
  * 对于所有其他内容（创意代理、设计工作室、现代品牌、高端消费者、作品集、生活方式），**默认无衬线显示**（Geist Display，ABC Diatype，Söhne Breit，Cabinet Grotesk Display，Migra Sans，GT Walsheim，Inter Display，PP Neue Montreal）。无衬线显示字体不是"无聊"——它们是默认值，原因与时尚中的黑色相同。
  * **强调规则（相关）：** 当你在标题中强调一个词（如动态的"and `spatial` 设计"类型移动）时，使用**相同字体的斜体或粗体**。不要将随机无衬线字嵌入无衬线标题（反之亦然）只是为了增加视觉兴趣。混合字体强调是业余的。同一家族中的斜体/粗体强调是正确的做法。
  * **特别禁止作为默认值：** `Fraunces` 和 `Instrument_Serif`（两个 LLM 最喜欢的显示无衬线字体）。
  * **如果无衬线字体被证明是合理的**（根据上述情况很少），从以下列表中旋转，不要在连续的项目中重复使用相同的无衬线字体：PP Editorial New，GT Sectra Display，Cardinal Grotesque，Reckless Neue，Tiempos Headline，Recoleta，Cormorant Garamond，Playfair Display，EB Garamond，IvyPresto，Migra，Editorial Old，Saol Display，Söhne Breit Kursiv，Domaine Display，Canela，Schnyder，Tobias，NB Architekt，ITC Galliard。

* **斜体下降清除（强制）：** 当斜体用于显示类型，并且单词包含下降字母（`y g j p q`）时，`leading-[1]` 或 `leading-none` 会剪切下降字母。使用 `leading-[1.1]` 最小值，并在包装元素上添加 `pb-1` 或 `mb-1` 预留。在发货前审计显示标题中的每个斜体单词。

### 4.2 颜色校准
* 最大 1 个强调色。默认情况下饱和度 < 80%。
* **LILA 规则：** "AI 紫色 / 蓝色辉光" 美学作为默认值是不鼓励的。不要自动发光的紫色按钮，不要随机的霓虹渐变。使用中性基础（Zinc / Slate / Stone）与高对比度单一强调色（Emerald，Electric Blue，Deep Rose，Burnt Orange，等等.）。
* **覆盖：** 如果品牌或简报明确要求紫色 / 紫罗兰 / lila，请接受它。但有意执行：一致调色板，协调的中性色，受约束的渐变。不是通用的 AI 渐变拖沓。
* **一个调色板每个项目。** 在同一个项目中不要在暖色调和冷色调灰色之间波动。
* **颜色一致性锁定（强制）：** 一旦为页面选择了强调色，它就用于整个页面。暖灰色网站不会突然在 7 节中添加蓝色 CTA。粉红色强调网站不会在页脚中添加蓝绿色状态徽章。选择一个强调色，锁定它，在发货前审计每个组件。

* **高端消费者调色板禁用（强制，第二常见的AI提示）：**
  * 对于高端消费者简报（厨具、健康、手工艺、奢侈品、传统工艺、DTC家居用品等），LLM默认为**暖米色/奶油色 + 黄铜/陶土/赭石 + 浓缩咖啡/墨色深色文本**。具体禁止作为默认背景和强调色的十六进制色系：
    - 背景：`#f5f1ea`、`#f7f5f1`、`#fbf8f1`、`#efeae0`、`#ece6db`、`#faf7f1`、`#e8dfcb`（均为“暖纸/奶油/粉笔/骨色”）
    - 强调色：`#b08947`、`#b6553a`、`#9a2436`、`#9c6e2a`、`#bc7c3a`、`#7d5621`（均为“黄铜/陶土/赭石/赭色”）
    - 文本：`#1a1714`、`#1a1814`、`#1b1814`（均为“浓缩咖啡/暖近黑色”）
  * 此调色板被禁用为高端消费者简报的默认范围。您曾经交付的每个高端消费者网站都使用此精确调色板。品牌变得不可见。
  * **默认替代方案（轮换，不要重复使用）：**
    - **冷奢华：** 银灰色 + 镀铬 + 烟雾色（想想特斯拉、苹果手表赫尔墨斯款，无皮革）
    - **森林：** 深绿色 + 骨色 + 蜡黄强调色（想想菲尔森、巴塔哥尼亚高端款）
    - **黑与棕：** 真正的浅黑色 + 暖棕色，强烈对比，无米色
    - **钴蓝 + 奶油：** 饱和蓝色与单一中性色搭配，无黄铜
    - **陶土 + 板岩：** 暖赭色与冷灰色搭配，无黄铜
    - **橄榄 + 砖 + 纸：** 柔和橄榄色加砖红色强调色
    - **纯单色 + 单一饱和亮点：** 浅白色 + 浅黑色 + 一个亮色强调色（电蓝色、祖母绿、亮粉色等）
  * **调色板轮换规则：** 如果您之前生成的高端消费者项目使用了米色+黄铜色系，这个必须使用不同的色系。不要连续两次发送相同的暖工艺调色板。
  * **覆盖：** 米色+黄铜+浓缩咖啡调色板仅在品牌简报明确命名这些颜色，或品牌身份真正是复古/手工艺/暖工艺，并且您可以说明此特定调色板适合此特定品牌时才可接受。因“这是一个厨具简报”而默认使用它被禁止。

### 4.3 布局多样化
* **反中心偏见：** 当`DESIGN_VARIANCE > 4`时，避免居中的英雄/H1部分。强制使用“分屏”（50/50）、“左对齐内容/右对齐资产”、“非对称空白”或滚动固定结构。
* **覆盖：** 居中英雄对于编辑/宣言/发布公告简报是可接受的，其中信息本身即是设计。

### 4.4 材质、阴影、卡片
* 仅在提升传达真实层次结构时使用卡片。否则使用`border-t`、`divide-y`或负空间分组。
* 使用阴影时，将其调色至背景色调。浅色背景上不要使用纯黑色投影阴影。
* 对于`VISUAL_DENSITY > 7`：通用卡片容器被禁止。数据指标在纯布局中呼吸。
* **形状一致性锁定（强制）：** 为页面选择一个圆角半径尺度并坚持使用。选项：全锐角（半径0）、全软边（半径12-16px）、全药丸形（全半径用于交互）。混合系统仅当有文档规则（例如“按钮是全药丸形，卡片是16px，输入是8px”）且该规则到处都遵循时才允许。方形布局中的圆形按钮，或药丸形按钮页面上的方形卡片，是破坏性设计。

### 4.5 交互式UI状态
LLM默认为“静态成功状态”。始终实现完整循环：
* **加载：** 与最终布局形状匹配的骨架加载器。避免使用通用圆形旋转加载器。
* **空状态：** 精美布局；指示如何填充。
* **错误状态：** 清晰、内联（表单）、或上下文（仅用于临时通知）。
* **触觉反馈：** 在`:active`上使用`-translate-y-[1px]`或`scale-[0.98]`模拟物理按压。
* **按钮对比度检查（强制，无障碍）：** 在发送任何按钮之前，验证按钮文本在按钮背景上的可读性。白色按钮+白色文本、`bg-white` CTA与`text-white`标签、透明按钮与页面背景无边框 → 全部禁止。审计每个CTA：对比度比例WCAG AA最低（正文4.5:1，大文本18px+）。相同规则适用于照片背景上的幽灵按钮（使用遮罩、磨砂层或描边）。
* **CTA按钮包裹禁用（强制）：** 按钮文本必须在桌面端单行显示。如果标签如“查看已选作品”包裹到2或3行，按钮就是损坏的。通过缩短标签（主要CTA最多3个词，理想1-2个）或加宽按钮（不要人为限制`max-width`在CTA上）修复。桌面端包裹的CTA是预飞行失败。
* **无重复CTA意图（强制）：** 一页上具有相同意图的两个CTA是预飞行失败。相同意图的例子：“联系我们”+“联系我们”+“让我们谈谈”+“开始项目”+“开始某事”+“联系”=全部“联系”意图 → 选择一个标签并在页面所有位置（导航、英雄、页脚）使用（联系意图）和“免费试用”+“开始使用”+“免费注册”（全部“注册”意图）以及“查看作品”+“查看已选作品”+“浏览项目”（全部“作品集”意图）。每个意图一个标签。
* **表单对比度检查（强制，无障碍）：** 表单输入、占位符文本、焦点环、辅助文本和错误文本在区域背景上通过WCAG AA对比度。浅色占位符在接近白色的表单上、白色表单在白色页面区域、表单标签比4.5:1对比度更灰 → 全部禁止。在发送前审计每个表单。

### 4.6 数据与表单模式
* 标签在输入上方。辅助文本可选但应在标记中存在。错误文本在输入下方。输入块的标准`gap-2`。
* 永远不要使用占位符作为标签。

### 4.7 布局纪律（硬规则。违反任何一条都是发送损坏的工作）

* **英雄必须适应初始视口。** 桌面端标题最多2行，副标题最多**20个词**且最多3-4行，CTA无需滚动即可看到。如果文案太长：减小字体比例或删减文案。如果您不能用20个词的副标题描述价值主张，那么价值主张不明确，不是规则太紧。永远不要让英雄溢出并迫使用户滚动以找到CTA。
* **英雄字体比例纪律。** 一起规划字体大小和图像大小。如果英雄资产很大且标题超过6个词，不要从`text-7xl/text-8xl`开始。合理范围：`text-4xl md:text-5xl lg:text-6xl`适用于大多数英雄；`text-6xl md:text-7xl`仅在标题为3-5个词时使用。4行英雄标题始终是字体大小错误，不是文案长度错误。
* **英雄顶部填充上限（强制）：** 桌面端英雄顶部填充最大`pt-24`（≈6rem）。超过这意味着英雄内容在视口中间浮动，读起来像布局错误而不是有意留白。如果您的英雄需要更多呼吸空间，增加字体比例或资产大小，而不是顶部填充。
* **英雄堆叠纪律（最多4个文本元素）。** 英雄是一个瞬间，不是功能列表。允许的文本元素，总共最多4个：
  1. 眉毛（小 uppercase 标签）或品牌条或都不选 - 选择零个或一个
  2. 标题（最多2行，见上文）
  3. 副标题（最多20个词，最多4行）
  4. CTA（1个主要 + 最多1个次要）
  - **英雄中禁止：** CTA下方的小标语（“可与GitHub、GitLab和自托管Git一起使用”）、信任微条（“由工程团队使用...”）、价格提示（“单人免费，团队$10/用户”）、功能点列表、社交证明头像行。所有这些都移到英雄下方的专用区域。
  - 如果您在同一个英雄中既有眉毛又有CTA下方的标语，请删除标语。如果您既有品牌条又有标语，请删除标语。每个英雄最多一个小文本元素，最多。
* **“使用”/“信任”标志墙属于英雄下方，绝不在其中。** 英雄用于价值主张和主要CTA。标志墙是一个单独的区域，直接位于下方。不要将信任标志塞入与英雄文案相同的flex行。
* **导航必须在桌面端单行显示。** 如果项目在`lg`（1024px）下不适用，请压缩标签、删除次要项目或切换到汉堡包。桌面端两行导航是破坏性设计。
* **导航高度上限：** 桌面端最大80px，默认64-72px。不要出现巨大的“代理”导航栏，占用15%的视口。
* **Bento网格必须有节奏，不能单边重复。** 不要堆叠6个左图/右文行。变化构图：交替全宽功能行、非对称瓦片大小、垂直分割。
* **Bento单元格计数规则（强制）：** Bento网格必须与您的内容数量完全一样。3个项目 → 3个单元格（1+2分割，或2+1，或非对称三联）。5个项目 → 5个单元格（2+3、3+2、英雄+4等）。如果您的网格中间或末尾有空单元格，您计划错了。重新调整网格；不要粘贴空白瓦片。
* **区域布局重复禁用。** 一旦您为某个区域使用布局系列（例如，3列图像卡片、全宽引言、分文图），该系列在页面上最多出现一次。“已选项目”不能看起来像“我们在做什么”。具有8个区域的着陆页必须使用至少4种不同的布局系列。
* **ZIGZAG交替上限（强制）。** 交替“左图+右文”然后“左文+右图”的Zigzag布局 = 陈腐。最多连续2个区域使用图像+文本分割模式。第3个连续图像+文本分割是预飞行失败。用全宽区域、垂直堆叠区域、Bento网格、滚动条或不同布局系列打破模式。
* **眉毛限制（强制，生产测试中最常违反的规则）。** 眉毛是位于区域标题上方的短 uppercase 宽间距标签（例如`FOUR COLORWAYS`、`SELECTED WORK`、`THE HARDWARE`、`Git-native task management`）。典型CSS特征：`text-[11px] uppercase tracking-[0.18em]`、`font-mono text-[10.5px] uppercase tracking-[0.22em]`。每个AI构建的网站都在每个区域标题上方放置眉毛，产生相同的模板节奏。硬规则：
  - **每3个区域最多1个眉毛。** 英雄计为1。因此，具有9个区域的页面最多使用3个眉毛。
  - 如果区域A有眉毛，接下来的2个区域不能有。
  - **预飞行检查是机械的：** 计算所有区域组件中`uppercase tracking`（或类似小 caps mono 标签在标题上方）的实例。如果计数 > ceil(sectionCount / 3)，输出失败。
  - **替代眉毛的方法：** 完全删除。标题本身就足够了。如果您需要分类区域，页面的位置已经分类了它；不需要标签。
* **分割标题禁用（强制）。** 模式“左大标题+右小解释段落”作为区域标题（左列占7/8列，右列占4/5列，右列中有一个小正文段落悬浮在右列中）被**默认禁止**。区域应该有一个集中的信息。如果您确实需要标题和解释段落，垂直堆叠（标题在顶部，正文在下方，最大宽度65ch）。仅在存在真实的构图原因时才使用分割标题模式（例如，右列承载视觉或交互元素，而不是填充文本）。
* **Bento背景多样性（强制）。** Bento和功能网格区域不能是6个白底白文的卡片，内部有文本。任何多单元格网格中至少2-3个单元格需要真实视觉变化：真实图像、品牌合适的渐变（不是AI紫色）、图案、染色背景。仅由排版组成的奶油色Bento读起来像无聊的AI默认，即使页面其他部分很好。
* **手机折叠必须按区域显式声明。** 对于每个多列布局，在相同组件中声明`< 768px`回退。不要“它将工作，Tailwind处理它”的假设。

### 4.8 图像与视觉资产策略

着陆页和作品集是**视觉产品**。纯文本页面与假截图div是草稿。

**视觉资产优先级顺序：**
1. **图像生成工具优先。** 如果环境中有任何图像生成工具可用（`generate_image`、MCP图像工具、IDE集成生成、OpenAI图像工具等），您必须使用它来创建特定于区域的资产：英雄摄影、产品拍摄、纹理背景、情绪图像。在适合区域的正确宽高比下生成。不要因为手绘CSS感觉更快而跳过这一步。
2. **真实网络图像其次。** 当没有生成工具可用时，使用真实摄影来源。可接受的默认值：
   * `https://picsum.photos/seed/{描述性种子}/{w}/{h}`用于占位符摄影（种子应描述区域，例如`marrow-cookware-kitchen`）
   * 简报提供的实际库存或品牌URL
   * 如果明确允许，使用开放许可来源（Unsplash直接URL、Pexels）
3. **最后手段：告知用户。** 如果都不可能，不要用手绘SVG插图或div-based“假截图”填充页面。相反，留下清晰标记的占位符槽（`<!-- TODO: 英雄产品照片，1600x1200 -->`），并在响应末尾说：*"此页面需要在以下位置需要真实图像：[占位符列表]。请生成或提供。"*。

**即使是极简网站也需要真实图像。** 纯文本页面不是极简主义。它是不完整的工作。即使是编辑线性风格网站也需要至少2-3张真实图像（英雄、一个产品/生活方式拍摄、一个支持图像）。如果简报是约束的，生成黑白极简摄影；不要因为旋钮低而完全跳过图像。

**真实公司标志用于社交证明。** 当简报要求“信任的/使用的/客户的”标志墙时，不要默认为纯文本词记（`<span>Acme Co</span>`样式排成一行）。使用真实SVG标志：
* **来源：Simple Icons** (`https://cdn.simpleicons.org/{slug}/ffffff`用于任何颜色，或`simple-icons` npm包）。涵盖大多数知名品牌。
* **替代：devicon** 用于技术栈标志（`@svgr/cli`或CDN）。
* **编造品牌名称？那么编造一个SVG标记。** 生成一个简单的单字母圆圈（一个字母在一个圆圈中、两个字母的结合、抽象符号）渲染为内联`<svg>`，匹配页面样式。编造品牌名称的纯文本词记看起来很通用。
* **始终**确保标志在亮模式和暗模式下都能渲染（白底暗色、黑底亮色，或单色主题变量）。
* **LOGO-ONLY规则（强制）：** 标志墙 = 标志和别无其他。不要在每个标志下方打印行业/类别标签（没有`Vercel` + `hosting`下方，没有`Stripe` + `支付`，没有`Cloudflare` + `基础设施`）。标志是信誉，标签添加了用户已经知道的无用信息。可选：品牌名称作为屏幕阅读器的alt文本，可选：链接到品牌的网站。仅此而已。

**手绘插图：**
* 来自库的SVG图标：可以（见第3.C节）。
* 手绘装饰SVG（自定义插图、标志、标记）：**强烈不鼓励**，永不作为默认使用。仅在：
  - 简报明确要求它（“为我绘制一个SVG标志”）
  - 它是一个简单的几何标记（一个方形、一个圆形、一个展示字体的词记）
  - 您对输出质量有信心

**基于div的假截图被禁止。** “手建产品预览”使用`<div>`矩形、假任务列表、假仪表板、假终端窗口是谎言。如果您需要展示产品：
* 如果存在真实截图URL，请使用
* 通过图像工具生成一个
* 使用真实组件预览（页面内实际的UI小版本）
* 或者完全跳过预览并使用编辑摄影

**英雄需要一个真实视觉。** 文本+渐变blob不是英雄 - 它是占位符。

### 4.9 内容密度

着陆页活在**第一印象**，而不是完整阅读。无情删减。

* **每节内容的默认形状：** 短标题（≤ 8 个字）+ 短副段落（≤ 25 个字）+ 一个视觉资源或一个行动号召。任何超出此范围的内容都必须由该节的功能进行说明。
* **禁止数据堆砌节。** 一个 20 行的发布表格、一个 30 行的奖项列表、一个营销页面上的巨大价格矩阵 = 错误的布局。使用：
  - 顶部 3-5 个重点 + "查看完整列表"链接
  - Marquee / 轮播图展示广度
  - 如果数据是产品，使用完全不同的页面
* **长列表需要不同的 UI 组件，而不是更长的列表。** 默认的 `<ul>` 带有圆点 / `divide-y` 行是懒惰的选择。如果你有 > 5 个项目，请选择以下之一：
  - 2 列分割，分组项目
  - 带有图像 + 标签的卡片网格
  - 如果项目可以分类，使用选项卡 / 折叠面板
  - 水平滚动快照药丸
  - 轮播图用于广度较大的列表（客户评价、标志、功能）
  - Marquee 用于“大量不需要单独关注的事物”
  - 带有 10 行 + 每行细线的规格表是最糟糕的默认值。将行分组为 2-3 组，使用稀疏分隔符，或改为每项规格使用卡片布局。
* **规格表特别（Marrow-cookware 模式）。** 一个带有 `border-b` 的长产品规格表格是 AI 在厨具 / 硬件 / 服装 / 手工艺品简报中的默认设置。禁止。具体替代方案：
  - **2 列卡片网格：** 每个规格都有自己的卡片，包含规格名称、值（大显示数字）和一行“为什么它很重要”的正文。卡片在桌面端为 2 列，在移动端为 1 列。
  - **滚动快照水平药丸：** 每个规格都是一个药丸，用户可以滑动浏览。
  - **分组块：** 将 10 个规格分组为 3 个逻辑集群（例如，“材料”、“烹饪”、“保修”），每个集群得到一个软分隔符和集群标题。
  - **突出显示与普通：** 3-4 个英雄规格以大显示瓦片的形式可视化，其余部分在“查看完整规格”的披露下折叠。

* **COPY 自我审计（发货前强制执行）：** 在声明任何任务完成之前，重新阅读页面上的每个可见字符串（标题、副标题、眉毛、按钮标签、正文、说明文字、替代文本、页脚文本、错误消息）。标记任何语法错误、指代不明的字符串、听起来像 AI 幻觉的字符串、读起来像 LLM 试图显得深思熟虑的字符串。重写每个被标记的字符串。如果不确定一个字符串是否有意义，用一句简单的功能句子替换它。AI 生成的可爱文案比无聊的文案更糟。
* **虚假精确数字被标记。** 数字如 `92%`、`4.1×`、`48k`、`5.8 mm`、`13.4 lb` 要么：
  - 来自真实数据（简报、品牌指南、公共指标）- 可以
  - 明确标记为模拟（`<!-- mock -->`、"示例"、"样本数据"）- 可以
  - 是 AI 发明的规格美学 - 禁止。不要伪造品牌不声称的工程精度。
* **每页一个文案风格。** 除非品牌声音明确要求，否则不要在同一组合中混合技术单数（"47 任务 · 0.6 ctx-switches/day"）、编辑性散文和营销冲击力。

### 4.10 引用 & 客户评价

* **引用正文最多 3 行。** 永远不要 6 行。如果原始引用更长 → 切割它。着陆页上的引用是一个片段，不是完整的评论。
* 对于非常小的字体大小（例如，页脚风格的客户评价），行首可以稍微拉伸。精神：“一眼可见”。
* **在引用文本中不要使用 em-dash 作为设计装饰（长暂停、动态 em-dash、em-dash-bullets）。** 参见第 9.G 节 - em-dash 完全禁止。
* 出处：姓名 + 职位 + （可选）公司。永远不要只命名（"- Sarah"）。
* 引用符号：使用真实的排版引号（" "）或一个都不用。不是直角 ASCII（" "）。

### 4.11 页面主题锁定（浅色 / 深色模式一致性）

页面只有一个主题。节不反转。

* 如果页面是深色模式，所有节都是深色模式。不要在深色节之间夹着一个浅色模式暖纸节（反之亦然）。用户在滚动时不应感觉进入了不同的网站。
* 例外：如果简报明确要求“彩色块故事”或“滚动时主题切换”设备，并且这是一个有意的设计（一个完整的主题切换，带有强烈的过渡，而不是随机交替），则允许每页一次。
* 默认行为：在页面级别选择浅色、深色或自动（`prefers-color-scheme`）并锁定它。同一主题家族内的节级背景色调是可以的（`bg-zinc-950` 旁边 `bg-zinc-900`）；在 `bg-zinc-950` 页面中间切换到 `bg-amber-50` 是错误的。
* 使用内置主题的设计系统（Radix Themes、shadcn/ui with `<Theme>`）时，在 `layout.tsx` 或页面根目录中设置主题一次。不要让单个节覆盖。

## 5. 上下文感知的主动行为

这些是工具，不是默认设置。当设计阅读要求它们时使用。**没有一个会自动触发。**

* **Liquid Glass / Glassmorphism：** 适用于高端消费、苹果相关、奢侈品牌或媒体叠加氛围。不适用于仪表板、公共部门或“无聊的 B2B”。使用时，除了 `backdrop-blur`，还要添加 1px 内边框（`border-white/10`）和微妙内阴影（`shadow-[inset_0_1px_0_rgba(255,255,255,0.1)]`）以实现物理边缘折射。在 `prefers-reduced-transparency` 下提供实心填充备用方案。
* **磁性微观物理：** 当 `MOTION_INTENSITY > 5` 且简报要求高端 / 俏皮 / 代理时使用。仅使用 Motion 的 `useMotionValue` / `useTransform` 在 React 渲染周期外实现。永远不要 `useState`。参见第 3.B 节。
* **永续微观交互**（脉冲、打字机、浮动、闪烁、轮播）：当 `MOTION_INTENSITY > 5` 且节积极受益于运动（状态指示器、实时馈送、AI 感觉）时使用。**不是每个卡片都需要无限循环。** 如果一个节是信息性的，保持静止。应用弹簧物理（`type: "spring", stiffness: 100, damping: 20`）- 没有线性缓动。
* **“运动已声明，运动已显示。”** 如果 `MOTION_INTENSITY > 4`，页面必须实际移动：英雄的进入过渡、关键节的滚动揭示、CTA 的悬停物理、至少这些。一个静态页面声明 `MOTION_INTENSITY: 7` 是错误的。相反，如果你在可用范围内无法提供工作的运动，将旋钮调低到 3 并提供一个干净的静态页面。永远不要半建运动而使其损坏（截断的 ScrollTriggers、跳动的进入、缺失的清理）。
* **运动必须有动机（强制执行）。** 在添加任何动画之前，问：“这个动画传达了什么信息？”有效答案：层次结构（将注意力吸引到正确的事情上）、故事讲述（按与叙事匹配的顺序揭示内容）、反馈（确认用户操作）、状态转换（显示某事已更改）。无效答案：“它看起来很酷”。因为 GSAP 可用而使用 GSAP 是业余的。每个 ScrollTrigger、每个 marquee、每个固定节都需要一个理由。如果你不能用一句话说明理由，请放弃动画。
* **每页最多一个 MARQUEE（强制执行）。** 水平滚动文本 marquee（“标志无限滚动”、“宣言水平滚动”、“动态文字条”）最多只应在每页出现一次。同一页面上有两个或多个 marquee 读起来像懒惰的填充。选择一个 marquee 实际服务于内容的节；其他节使用不同的布局。
* **GSAP Sticky-Stack 模式（当滚动堆叠使用时）。** “滚动上的卡片堆叠”必须是真正的粘性堆叠，而不是顺序揭示列表。参见第 5.A 节下的规范代码骨架。常见错误：触发在滚动中途触发而不是在视口顶部固定。修复：`start: "top top"` 而不是 `start: "top center"` 或 `"top 80%"`。
* **GSAP Horizontal-Pan 模式（当水平滚动劫持使用时）。** 参见第 5.B 节下的规范骨架。常见错误：动画在节固定之前开始，因此用户看到一半的幻灯片。相同的修复：`start: "top top"`，固定包装器，滚动内部轨道。

### 5.A Sticky-Stack - 规范代码骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function StickyStack({ cards }: { cards: React.ReactNode[] }) {
  const ref = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !ref.current) return;
    const ctx = gsap.context(() => {
      const cardEls = gsap.utils.toArray<HTMLElement>(".stack-card");
      cardEls.forEach((card, i) => {
        if (i === cardEls.length - 1) return;
        ScrollTrigger.create({
          trigger: card,
          start: "top top",                              // 在视口顶部固定
          endTrigger: cardEls[cardEls.length - 1],
          end: "top top",
          pin: true,
          pinSpacing: false,
        });
        gsap.to(card, {
          scale: 0.92,
          opacity: 0.55,
          ease: "none",
          scrollTrigger: {
            trigger: cardEls[i + 1],
            start: "top bottom",
            end: "top top",
            scrub: true,
          },
        });
      });
    }, ref);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <div ref={ref} className="relative">
      {cards.map((card, i) => (
        <div
          key={i}
          className="stack-card sticky top-0 min-h-[100dvh] flex items-center justify-center"
        >
          {card}
        </div>
      ))}
    </div>
  );
}
```

关键点：`start: "top top"`，`pin: true`，除了最后一个卡片外，每个卡片都被固定，缩放/不透明度转换由下一个卡片的滚动触发驱动（因此前一个卡片在下一个到达时缩小）。

### 5.B Horizontal-Pan - 规范代码骨架

```tsx
"use client";
import { useRef, useEffect } from "react";
import { gsap } from "gsap";
import { ScrollTrigger } from "gsap/ScrollTrigger";
import { useReducedMotion } from "motion/react";

gsap.registerPlugin(ScrollTrigger);

export function HorizontalPan({ children }: { children: React.ReactNode }) {
  const wrap = useRef<HTMLDivElement>(null);
  const track = useRef<HTMLDivElement>(null);
  const reduce = useReducedMotion();

  useEffect(() => {
    if (reduce || !wrap.current || !track.current) return;
    const ctx = gsap.context(() => {
      const distance = track.current!.scrollWidth - window.innerWidth;
      gsap.to(track.current, {
        x: -distance,
        ease: "none",
        scrollTrigger: {
          trigger: wrap.current,
          start: "top top",                              // 节顶部到达视口顶部时开始固定
          end: () => `+=${distance}`,                    // 滚动距离 = 轨道宽度减去视口
          pin: true,
          scrub: 1,
          invalidateOnRefresh: true,
        },
      });
    }, wrap);
    return () => ctx.revert();
  }, [reduce]);

  return (
    <section ref={wrap} className="relative overflow-hidden">
      <div ref={track} className="flex h-[100dvh] items-center">
        {children}
      </div>
    </section>
  );
}
```

关键点：`start: "top top"`，`pin: true`，`end: "+=${distance}"`（滚动长度 = 水平旅行所需），`scrub: 1`。包装器被固定，内部轨道在用户垂直滚动时水平滑动。

### 5.C Scroll-Reveal Stagger - 规范代码骨架（更轻的替代方案）

对于简单的“项目进入视口时出现”（不固定），优先使用 Motion 的 `whileInView` 而不是 GSAP - 更轻，不需要 ScrollTrigger：

```tsx
"use client";
import { motion, useReducedMotion } from "motion/react";

export function RevealStagger({ items }: { items: string[] }) {
  const reduce = useReducedMotion();
  return (
    <ul className="grid gap-6">
      {items.map((item, i) => (
        <motion.li
          key={item}
          initial={reduce ? false : { opacity: 0, y: 24 }}
          whileInView={{ opacity: 1, y: 0 }}
          viewport={{ once: true, amount: 0.3 }}
          transition={{
            duration: 0.6,
            delay: i * 0.06,
            ease: [0.16, 1, 0.3, 1],
          }}
        >
          {item}
        </motion.li>
      ))}
    </ul>
  );
}
```

用于：功能列表、客户评价网格、标志墙、任何只需要“滚动进入”的情况。将 GSAP 用于实际固定/滚动工作。

### 5.D 禁止的动画模式

* **`window.addEventListener("scroll", ...)`** 被禁止。它在每个滚动帧上运行，容易导致卡顿，没有批处理。使用 Motion 的 `useScroll()`、GSAP 的 `ScrollTrigger`、IntersectionObserver 或 CSS `滚动驱动动画`（`animation-timeline: view()`）。
* **使用 `window.scrollY` 在 React 状态中进行自定义滚动进度计算。** 相同原因。每帧重新渲染。
* **触犯 React 状态的 `requestAnimationFrame` 循环。** 使用 motion 值（`useMotionValue` + `useTransform`）代替。
* **布局过渡：** 使用 Motion 的 `layout` 和 `layoutId` 属性进行可见状态变化（重新排序列表、扩展模态框、路由之间共享元素）。不要将静态内容包裹在 `layout` 属性中“为了安全” - 它会消耗测量工作。
* **交错编排：** 使用 `staggerChildren`（Motion）或 CSS 级联（`animation-delay: calc(var(--index) * 100ms)`）进行顺序重要的揭示时刻。对于 `staggerChildren`，父级（`variants`）和子级必须共享相同的 Client 组件树。

## 6. 性能 & 可访问性指南

### 6.A 硬件加速
* 仅动画 `transform` 和 `opacity`。永远不要动画 `top`、`left`、`width`、`height`。
* 节制使用 `will-change: transform` - 仅对实际会动画的元素使用。

### 6.B 减少运动（强制执行）
* **任何 `MOTION_INTENSITY > 3` 以上的运动必须尊重 `prefers-reduced-motion`。** 这是不容商量的。
* 在 Motion 中：用 `useReducedMotion()` 包裹并降级为静态。
* 在 CSS 中：在 `@media (prefers-reduced-motion: no-preference)` 或在 `@media (prefers-reduced-motion: reduce)` 下提供覆盖块来禁用。
* 无限循环、视差、滚动劫持和磁性物理必须在减少运动下折叠为静态 / 瞬时。

### 6.C 深色模式（任何面向消费者的页面都必须强制执行）
* 从一开始就为 **两种模式** 设计。永远不要只发布浅色或深色，除非有明确用户说明。
* 使用 Tailwind `dark:` 变体或 CSS 变量。每个项目选择一种策略。
* **在这里不要规定特定的深色模式颜色。** 简报决定。在两种模式下保持视觉层次结构、品牌身份和 WCAG AA 对比（AAA 正文）。
* 尊重 `prefers-color-scheme: dark`。默认为系统偏好，除非品牌坚持一种模式。

### 6.D 核心网络指标目标
* **LCP** < 2.5s。英雄图像必须是 `next/image priority` 或预加载。
* **INP** < 200ms。主线程外的工作量。
* **CLS** < 0.1。为图像、字体、嵌入保留空间。
* 在声明页面完成之前运行 Lighthouse。

### 6.E DOM 成本
* 专门将颗粒 / 噪声滤镜应用于固定的、`pointer-events-none` 伪元素（例如，`fixed inset-0 z-[60] pointer-events-none`）。永远不要在滚动容器上使用 - 连续的 GPU 重绘会破坏移动端 FPS。
* 注意捆绑大小。运动不是微小的。Three.js 很大。懒加载任何不在首屏以上的内容。

### 6.F Z-Index 限制
NEVER 任意使用 `z-50` 或 `z-10`。严格使用 z-index 仅用于系统层上下文（粘性导航栏、模态框、覆盖层、颗粒）。在项目的常量文件中记录 z-index 尺度。

## 7. 旋钮定义（技术参考）

### 设计差异度 (DESIGN_VARIANCE)（等级 1-10）
* **1-3（可预测）：** 对称 CSS Grid（12 列，等宽 fr 单位），等量内边距，居中对齐。
* **4-7（错位）：** `margin-top: -2rem` 重叠、多样化图片宽高比（4:3 紧邻 16:9）、左对齐标题搭配居中对齐的数据。
* **8-10（非对称）：** 瀑布流布局、带分数单位的 CSS Grid（`grid-template-columns: 2fr 1fr 1fr`）、大面积留白区域（`padding-left: 20vw`）。
* **移动端覆盖：** 对于 4-10 级，`md:` 以上视口的非对称布局在 `< 768px` 的视口上必须折叠为严格单列（`w-full`、`px-4`、`py-8`）。

### 动效强度 (MOTION_INTENSITY)（等级 1-10）
* **1-3（静态）：** 无自动动画。仅使用 CSS `:hover` 和 `:active` 状态。`prefers-reduced-motion` 本就是默认模式。
* **4-7（流畅 CSS）：** `transition: all 0.3s cubic-bezier(0.16, 1, 0.3, 1)`。使用 `animation-delay` 级联实现入场动画。重点关注 `transform` 和 `opacity`。
* **8-10（高级编排）：** 复杂的滚动触发显现、视差、滚动驱动动画（CSS `animation-timeline` 或 GSAP ScrollTrigger）。使用 Motion hooks。**严禁使用 `window.addEventListener('scroll')`** - 这是硬性禁止，不是"尽量不用"。参见 5.D 节了解允许的替代方案。

### 视觉密度 (VISUAL_DENSITY)（等级 1-10）
* **1-3（美术馆）：** 大量留白。巨大的区块间距（`py-32` 到 `py-48`）。昂贵、干净。
* **4-7（日常应用）：** 标准 Web 应用间距（`py-16` 到 `py-24`）。
* **8-10（驾驶舱）：** 紧凑内边距。无卡片容器；用 1px 线条分隔数据。必须：所有数字使用 `font-mono`。

## 8. 深色模式协议

默认双模式。除非简报是模拟印刷的编辑类内容，否则不要假设仅支持浅色。

### 8.A Token 策略（选一种，坚持到底）
* **Tailwind `dark:` 变体**（工具类优先项目的默认方案）：每个颜色工具类都配上其深色变体（`bg-white dark:bg-zinc-950`、`text-gray-900 dark:text-gray-100`）。
* **CSS 变量**（适用于 shadcn/ui、Radix Themes 或有主题功能的组件库）：定义语义化 token（`--surface`、`--surface-elevated`、`--text-primary`、`--accent`），并在 `[data-theme="dark"]` 或 `@media (prefers-color-scheme: dark)` 下切换值。

### 8.B 不要在此规定具体颜色
颜色和风格由简报与品牌决定。本技能仅强制执行：
* **对比度** - 正文文字最低 WCAG AA，主视觉文案目标 AAA。
* **层级对等** - 浅色下有效的视觉层级在深色下同样有效。如果 CTA 在浅色下突出，在深色下也必须突出。
* **品牌忠实度** - 主品牌色必须保持可辨识。不要为了深色模式而将品牌色去饱和。
* **禁止纯 `#000000` 和纯 `#ffffff`** - 使用近黑（zinc-950、暖灰近黑）和近白。纯值会杀死深度感。

### 8.C 默认模式
除非品牌坚持，否则尊重 `prefers-color-scheme`。如果任一模式会丧失关键品牌表达，添加手动切换开关。

### 8.D 完成前必须在两种模式下测试
开发过程中在两种模式下打开页面。不要交付一个你只看过一种模式的页面。

## 9. AI 痕迹（禁止模式）

除非简报明确要求，否则避免以下特征。

### 9.A 视觉与 CSS
* **默认禁止霓虹 / 外发光。** 使用内边框或微妙的着色阴影。
* **禁止纯黑色（`#000000`）。** 用近黑、zinc-950 或炭黑。
* **禁止过度饱和的强调色。** 降低饱和度以融入中性色。
* **禁止大面积渐变文字**用于大标题。
* **禁止自定义鼠标指针。** 过时、对无障碍不友好、对性能不友好。

### 9.B 排版
* **避免将 Inter 作为默认字体。** 参见 4.1 节。存在覆盖路径。
* **禁止仅靠超大 H1 来"喊叫"。** 用字重 + 颜色控制层级，而非原始字号。
* **衬线体限制：** 衬线体用于编辑类 / 奢华 / 出版物。不用于仪表盘。

### 9.C 布局与间距
* **数学上完美**的内边距和边距。不允许有尴尬间隙的悬浮元素。
* **禁止三列等宽特性卡片。** 通用的"三个相同卡片水平排列"特性行已被禁止。使用双列之字形、非对称网格、滚动固定或横向滚动替代。

### 9.D 内容与数据（"Jane Doe" 效应）
* **禁止通用姓名。** "John Doe"、"Sarah Chan"、"Jack Su" → 使用有创意、真实、符合地域的姓名。
* **禁止通用头像。** 不要用 SVG"鸡蛋"或 Lucide 用户图标 → 使用可信的照片占位符或特定样式。
* **禁止假完美数字。** 避免 `99.99%`、`50%`、`1234567`。使用有机、杂乱的数据（`47.2%`、`+1 (312) 847-1928`）。
* **禁止创业公司俗套品牌名。** "Acme"、"Nexus"、"SmartFlow"、"Cloudly" → 创造有语境感、高端、听起来真实的名称。
* **禁止填充动词。** "Elevate"、"Seamless"、"Unleash"、"Next-Gen"、"Revolutionize" → 只用具体动词。

### 9.E 外部资源与组件
* **禁止手写 SVG 图标。** 使用 Phosphor / HugeIcons / Radix / Tabler。仅在明确要求时使用 Lucide。
* **强烈不建议**默认使用手写作装饰 SVG（参见 4.8 节）。
* **禁止用 div 伪造截图。** 永远不要用 `<div>` 矩形拼出假产品 UI 来模拟截图。使用真实图片、生成图片，或跳过预览。
* **禁止损坏的 Unsplash 链接。** 使用 `https://picsum.photos/seed/{descriptive-string}/{w}/{h}`、生成的照片占位符，或实际素材。
* **shadcn/ui 自定义：** 允许，但绝不可使用默认状态。按项目美学自定义圆角、颜色、阴影、排版。
* **生产级整洁度：** 代码在视觉上整洁、有辨识度、精心打磨。

### 9.F 生产测试痕迹（直接禁止）

以下模式来自真实 LLM 生成的落地页测试。它们是模型试图"看起来有设计感"时默认采用的签名。除非简报明确要求，否则视为硬性禁止。

**主视觉与页面顶部**
* **主视觉中禁止版本标签。** `V0.6`、`v2.0`、`BETA`、`INVITE-ONLY PREVIEW`、`EARLY ACCESS`、`ALPHA` - 默认禁止作为眉题。仅当简报明确关于产品发布 / 预览状态时才可接受。
* **禁止"Brand · No. 01"风格的子眉题。** 如"Marrow · No. 01 · The 6-quart"这类微型元信息行。跳过它们。

**章节编号与微型标签**
* **禁止章节编号眉题。** `00 / INDEX`、`001 · Capabilities`、`002 · Featured commission`、`06 · how it works`、`05 · The honest table` - 禁止。眉题应该用平实语言命名主题，而非编号。
* **禁止 `01 / 4` 风格的图片或便当格分页。** 如果用户能数，就不需要标签。
* **禁止 `Scroll · 001 Capabilities` 风格的滚动提示。** 简单的箭头或"Scroll"就够；不要加章节编号前缀。
* **禁止"Index of Work, 2018 - 2026"风格的范围标签**作为眉题。直接说这个章节是什么。

**分隔符与圆点**
* **中圆点（`·`）限量使用。** 元信息条中每行最多 1 个。不要将其作为万能的默认分隔符（"foo · bar · baz · qux · quux"）。如果需要分隔符体系，优先使用换行、细线或分列。
* **禁止在每个列表/导航/徽章前加装饰性彩色状态圆点。** "ONE Q4 SLOT OPEN"前或每个导航链接前、每个任务行前的彩色圆点 - 默认禁止。仅当圆点传达实际语义状态（服务器状态、可用性标志）且使用克制时才可接受。

**破折号与排版装饰**
* **禁止破折号（`—`）作为设计元素或出现在任何位置。** 参见下方 9.G 节了解完整的、不可协商的禁令。破折号字符在标题、眉题、胶囊标签、正文、引言、署名、图注、按钮文字和替代文本中均被禁止。使用普通连字符（`-`）。
* **禁止默认使用 `<br>` 换行 + 斜体的标题**作为"设计手法"。如"for thirty\<br\>*years.*"这类拆分。标题应先自然可读，仅在简报要求时才玩花样。
* **禁止垂直旋转文字**（"INDEX OF WORK, 2018 - 2026"旋转 90°）。这是代理组合集的陈词滥调。仅在简报明确为代理 / Awwwards / 实验性且服务于真实构图目的时才可接受。
* **禁止十字线 / 细线网格线作为装饰。** 为了"让页面看起来有设计感"而画竖线和横线 - 禁止。仅当它们组织真实内容时才可使用。

**假产品预览**
* **主视觉中禁止 div 伪造产品 UI**（假任务列表、假终端、假仪表盘由样式化 div 构成）。这是 #1 LLM 设计痕迹。使用真实截图、生成图片、真实组件预览，或不放。
* **假截图中禁止假版本页脚**（"v0.6.2-rc.1"、"last sync 4s ago · main"）。毫无意义，满口 AI 味。

**营销文案痕迹**
* **禁止"Quietly in use at" / "Quietly trusted by" 式的社会证明标题。** 使用自然语言："Trusted by"、"Used at"、"Customers include"，或如果 logo 能自说明就跳过标题。
* **禁止"From the field" / "Field notes" / "Currently on the bench" / "On our desks" / "Loose plates" 风格的诗意标签**用于引言、博客或侧栏区块。读起来像表演型手艺人。使用平实的功能性标签（"Testimonials"、"Latest writing"、"Now working on"）或跳过标签。
* **禁止"We respect the French ones"式的**假装谦逊的行业引用出现在正文中。讨巧且 AI 味重。
* **禁止地域 / 时区条**（"LIS 14:23 · 18°C"）出现在页眉/页脚中，除非简报明确关于一个跨时区分布的地点 / 工作室。
* **禁止眉题下方的微型元信息句。** 如*"Each of these is a feature we ship today, not a roadmap promise. The list will stay short on purpose."*放在章节标题下方的句子是杂乱。眉题 + 标题 + 正文就够了。
* **禁止通用步骤标签。** "Stage 1 / Stage 2 / Stage 3"、"Step 1 / Step 2 / Step 3"、"Phase 01 / Phase 02 / Phase 03"、"Pass One / Pass Two / Pass Three"。禁止。实际步骤内容就是标签。如果必须显示进度，直接用动词-名词（"Install"、"Configure"、"Ship"），而非"Stage 1: Install"。

**胶囊标签、标签和版本戳**
* **禁止在图片上叠加胶囊/标签/标签页。** 不要 `<span>` 叠加在照片上带 `Brand · 02`、`PLATE · BRAND`、`Field notes - journal` 等标签。要么让图片独自说话，要么在图片正下方（图片外部）添加图注。
* **禁止照片署名图注作为装饰。** 如 `Field study no. 12 · Ines Caetano`、`Plate 03 · House archive`、`Frame XII · 35mm` 放在 stock/picsum 图片下方的字符串是矫揉造作。照片署名仅在为真实摄影师（经许可）署真实照片时才可接受。否则：跳过图注或使用一行功能性图注（"The 6-quart, in Sage."）。
* **营销页面禁止版本页脚。** 页脚字符串如 `v1.4.2`、`Build 0048`、`last sync 4s ago · main` 是 CLI / 开发工具 fixture，不是落地页内容。在营销/落地/组合页面上禁止。
* **禁止"Reservation 412 of 800"式的实时库存计数器**作为装饰。仅当简报明确是限量版候补名单且有真实数据时才可接受。

**装饰文字条**
* **主视觉底部禁止装饰文字条。** 如 `BRAND. MOTION. SPATIAL.`、`TYPE / FORM / MOTION`、`DESIGN · BUILD · SHIP`、`ESTD. 2018 · LISBON · BRAND. MONO. SPATIAL.` 作为主视觉底部小等宽大写文字条是代理组合集的陈词滥调。默认禁止。仅当文字条承载真实可导航链接（底部粘性导航）或真实状态信息（cookie 横幅、文档站构建信息）时才可接受。
* **章节标题右上角禁止悬浮子文本。** 模式：章节有一个巨大的左对齐标题；同一章节头部右上角有一个小解释段落悬浮着，没有与任何元素清晰对齐。那个悬浮物就是痕迹。要么把子文本直接放在标题下方，要么构建干净的双列头部（左：标题，右：对齐的正文），但不要小角落段落。

**列表、分隔线和评分**
* **禁止在长列表/规格表的每一行都加 `border-t` + `border-b`。** 选一种（行间底边框或组上方顶边框）并克制使用。10 行规格表每行下面画细线是最懒的布局 - 参见 4.9 节了解替代 UI 组件。
* **禁止带填充背景轨道的评分/进度条**作为比较视觉。如果需要展示"X / Y"比较，优先用数字 + 小图标，或一个没有背景轨道的微型内联条。大填充的 `bg-zinc-200` 轨道上叠加部分填充是仪表盘 UI 杂乱，不适合落地页。

**地域、时间、滚动提示**
* **地域 / 城市名 / 时间 / 天气条在 99% 的简报中禁止。** 主视觉中的"Lisbon, working with founders"、页脚中的"1200-690 Lisbon, Portugal"、导航中的"Lisbon 14:23 · 18°C"。这些是代理组合集的装饰痕迹。仅在以下情况允许：简报明确描述一个跨时区分布且与时区相关的工作室，或旅行主题品牌，或真实物理场所。页脚中提及一次联系地址没问题；氛围性地域条不行。
* **禁止滚动提示。** `Scroll`、`↓ scroll`、`Scroll to explore`、`Scroll to walk through it`、动画滚轮图标。如果用户还没滚动，他们正在看主视觉。他们知道什么是滚动。视口底部不需要标签。
* **默认零装饰性状态圆点。** 导航项前、列表行前、徽章前、状态标签前的彩色圆点是痕迹。仅在传达真实语义状态（实际服务器状态的实时指示灯、实时可用性标志）且每页每节限一个时才可接受。

### 9.G 破折号禁令（被违反最多的痕迹）

**破折号（`—`）完全禁止。** 它是 LLM 的标志性风格拐杖，是生产测试中 #1 视觉痕迹。没有"有限使用"豁免，没有"自然语言频率"豁免，没有"正文中可以用"豁免。没有。

* **标题中禁止。** 用句号或逗号。
* **眉题 / 标签 / 胶囊 / 按钮文字 / 图片图注 / 导航项中禁止。** 用换行、分列或细线替代。
* **正文中禁止。** 重构句子：用句号分两句，或逗号，或括号，或冒号。
* **引言署名中禁止。** 用带空格的普通连字符（` - `）或换行 + 较细字重姓名。
* **en-dash 形式（`–`）作为分隔符时同样禁止。** 日期范围（`2018-2026`）用连字符。数字范围（`€40-80k`）用连字符。

页面上唯一允许的破折号字符：
* 普通连字符 `-`（用于复合词、范围、标记中的行分隔）
* 数学中的减号（`-5°C`）

如果输出中包含任何用户可见的 `—` 或 `–`，输出未通过 Pre-Flight Check，必须重写。

此规则不可协商。该代理历史上在表述为"尽量不用"时会忽略破折号限制。此处的表述是二元的：零破折号。

## 10. 参考词汇（代理应了解的图案名称）

这是一个词汇表，不是组件库。代理应了解这些图案名称以便交流、在设计时心中有数，并在设计解读需要时调用它们。**实现和代码草图位于 Block Library（第 12 节），该库是迭代填充的。**

### 主视觉范式
* **非对称分屏主视觉** - 一侧文字，一侧素材，大量留白。
* **编辑宣言主视觉** - 大字号，无素材，近乎海报。
* **视频/媒体遮罩主视觉** - 文字作为遮罩镂空在视频背景之上。
* **动力学排版主视觉** - 动画排版作为主要视觉。
* **幕布显现主视觉** - 主视觉像幕布一样随滚动分开。
* **滚动固定主视觉** - 主视觉保持固定，内容在其后方滚动。

### 导航与菜单
* **Mac OS Dock 放大** - 边缘导航，图标在悬停时流畅缩放。
* **磁性按钮** - 吸引至光标位置。
* **粘稠菜单** - 子项像粘性液体一样分离。
* **动态岛** - 用于状态/提示的变形药丸。
* **上下文径向菜单** - 点击点处展开的圆形菜单。
* **浮动快速拨号** - FAB 弹入弯曲的次要操作。
* **巨型菜单展示** - 全屏下拉，内容错落渐变。

### 布局与网格
* **百宝格网格** - 非对称瓦片分组（Apple 控制中心）。
* **马赛克布局** - 错落网格，无固定行高。
* **色度网格** - 带有微妙动画渐变的边框/瓦片。
* **分屏滚动** - 两个部分向相反方向滑动。
* **粘性堆叠区域** - 滚动时固定并堆叠的区域。

### 卡片与容器
* **视差倾斜卡片** - 3D 倾斜跟踪鼠标坐标。
* **聚光灯边框卡片** - 边框在光标下发光。
* **玻璃态面板** - 薄雾玻璃，内部折射。
* **全息箔卡片** - 悬停时彩虹色偏移。
* **火柴 swipe 堆叠** - 物理卡片堆叠，可 swipe 移除。
* **变形模态框** - 按钮扩展成自己的对话框。

### 滚动动画
* **粘性滚动堆叠** - 卡片粘性并物理堆叠。
* **水平滚动劫持** - 垂直滚动 → 水平平移。
* **火车/序列滚动** - 视频/3D 序列与滚动条绑定。
* **缩放视差** - 滚动时中央背景图像缩放。
* **滚动进度路径** - 沿滚动绘制的 SVG 线。
* **液体 swipe 过渡** - 像粘性液体一样的页面过渡。

### 画廊与媒体
* **穹顶画廊** - 3D 全景画廊。
* **Coverflow 轮播** - 倾斜边缘的 3D 轮播。
* **拖动平移网格** - 无边界的可拖动画布。
* **手风琴图像滑块** - 悬停时展开的窄条。
* **悬停图像轨迹** - 鼠标离开时留下弹跳图像轨迹。
* **故障效果图像** - 悬停时 RGB 通道偏移。

### 字体与文本
* **动能跑马灯** - 滚动时反向的无尽文本带。
* **文本遮罩揭示** - 巨大字体作为透明窗口到视频。
* **文本打乱效果** - 加载/悬停时的矩阵风格解码。
* **圆形文本路径** - 沿旋转圆圈弯曲的文本。
* **渐变描边动画** - 带有运行渐变的描边文本。
* **动能文字网格** - 字母躲避光标。

### 微交互与效果
* **粒子爆炸按钮** - 成功时 CTA 破碎成粒子。
* **液体下拉刷新** - 像分离液滴一样的刷新指示器。
* **骨架闪烁** - 在占位符上移动的光反射。
* **方向性悬停感知按钮** - 填充从光标的精确侧进入。
* **涟漪点击效果** - 从点击坐标发出的波。
* **动画 SVG 线绘制** - 向量实时绘制自身。
* **网格渐变背景** - 有机熔岩灯状团块。
* **镜头模糊深度** - 背景 UI 模糊以聚焦前景操作。

### 动画库选择
* **Motion (`motion/react`)** - UI / 百宝格 / 状态变化动画的默认选项。
* **GSAP + ScrollTrigger** - 用于全页滚动叙事和滚动劫持。在专用叶组件中用 `useEffect` 清理。
* **Three.js / WebGL** - 用于画布背景和 3D 场景。相同的隔离规则。
* **NEVER 在同一组件树中混合 GSAP / Three.js 与 Motion。** 它们争夺相同的帧。

## 11. 重新设计协议

这项技能处理 **绿野建设 AND 重新设计**。错误分类模式是产生糟糕重新设计输出的最大来源。

### 11.A 检测模式（第一个动作）
* **绿野** - 无现有网站，或批准全面翻新。从第 1 节设定基线。
* **重新设计 - 保留** - 现代化而不破坏品牌。先审计，提取品牌令牌，逐步演变。
* **重新设计 - 翻新** - 在现有内容之上使用新的视觉语言。视觉效果视为绿野；保留内容和 IA。

如果模糊，**问一次**：*"这个重新设计应保留现有品牌，还是我们视觉上从零开始？*"

### 11.B 触碰前审计
在提出更改前记录当前状态：
* **品牌令牌** - 主要/强调色，字体堆栈，标志处理，半径。
* **信息架构** - 页面树，主要导航，关键转化路径。
* **内容块** - 已存在的内容，正在发挥作用的内容，填充内容。
* **要保留的模式** - 特征交互，可识别的英雄，文案声音。
* **要淘汰的模式** - AI 滥用，损坏的布局，死链接，通用股票图片，性能陷阱。
* **现有网站的基线读数** - 推断当前的 `DESIGN_VARIANCE` / `MOTION_INTENSITY` / `VISUAL_DENSITY`。这是你的起点，不是基线。
* **SEO 基线** - 当前排名页面，元标题，结构化数据，OG 卡片。**SEO 迁移是重新设计的最大风险。**

### 11.C 保留规则
* **除非要求，否则不要更改信息架构**。保持页面别名，锚点 ID，主要导航标签稳定，以利于 SEO 和肌肉记忆。
* **提取品牌颜色** 在应用第 4.2 节之前。已经是紫色的品牌保持紫色 - 应用 LILA 规则的覆盖。
* **保留文案声音** 除非要求重写。视觉现代化 ≠ 内容重写。
* **尊重现有的无障碍性成果**。不要降低焦点状态，替代文本，键盘导航，对比度。
* **尊重现有的分析事件**。不要重命名按钮，表单字段，区域 ID，这些依赖于下游跟踪。

### 11.D 现代化杠杆（优先级顺序）
按顺序应用 - 当简报满足时停止：
1. **字体刷新** - 每单位风险最大的视觉提升。
2. **间距与韵律** - 增加区域填充，修复垂直韵律。
3. **颜色重新校准** - 减饱和，统一中性色，保留品牌强调色。
4. **动画层** - 添加 `MOTION_INTENSITY` 适当的微交互到现有组件。
5. **英雄与关键区域重新组合** - 使用第 10 节词汇重组顶部漏斗。
6. **全块替换** - 只有当现有块无法挽救时。

### 11.E 决策树：针对性演变 vs 全新重新设计
* IA、内容和 SEO 听起来 → **针对性演变**（杠杆 1-4）。约 70% 的价值，约 40% 的风险。
* 视觉债务是结构性（损坏的 IA，无设计系统，损坏的移动端）→ **全新重新设计**，严格保留内容。
* 品牌本身在变化 → **绿野**。

### 11.F 永远不会默默改变
未经明确用户批准，永远不要修改：
* URL 结构 / 路由别名。
* 主要导航标签。
* 表单字段名称或顺序（破坏分析 + 自动填充）。
* 品牌标志或文字标志。
* 现有的法律/同意/cookie 文本。

## 附录C - Apple Liquid Glass：诚实Web近似

**不要**将随机CSS代码片段视为官方Apple Liquid Glass。

### 官方是什么
Apple在其Human Interface Guidelines和Developer Documentation中为**Apple平台**文档化Liquid Glass。它是Apple平台UI中使用的动态材料。Apple的原生实现属于Apple平台API和系统组件，**非公开网页CSS包**。

相关官方文档：
- Apple Human Interface Guidelines → Materials
- Apple Developer Documentation → Liquid Glass
- Apple Developer Documentation → Adopting Liquid Glass
- SwiftUI → Material

### 非官方是什么
Apple没有为普通网站提供`liquid-glass.css`。

Web近似可以使用：
- `backdrop-filter`
- 透明背景
- 分层边框
- 高亮覆盖
- 渐变
- 动画
- 强对比度后备

但这只是**网页玻璃效果 / 水晶玻璃近似**，非官方Apple Liquid Glass。在注释中标记。

### 更安全的Web近似骨架

```css
.liquid-glass-web-approx {
  position: relative;
  isolation: isolate;
  overflow: hidden;
  border-radius: 999px;
  border: 1px solid rgb(255 255 255 / .32);
  background:
    linear-gradient(135deg, rgb(255 255 255 / .30), rgb(255 255 255 / .08)),
    rgb(255 255 255 / .12);
  backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  -webkit-backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / .48),
    inset 0 -1px 0 rgb(255 255 255 / .12),
    0 18px 60px rgb(0 0 0 / .18);
}

.liquid-glass-web-approx::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  border-radius: inherit;
  background:
    radial-gradient(circle at 20% 0%, rgb(255 255 255 / .55), transparent 34%),
    linear-gradient(90deg, rgb(255 255 255 / .18), transparent 42%, rgb(255 255 255 / .14));
  pointer-events: none;
}

.liquid-glass-web-approx::after {
  content: "";
  position: absolute;
  inset: 1px;
  border-radius: inherit;
  border: 1px solid rgb(255 255 255 / .14);
  pointer-events: none;
}

@media (prefers-color-scheme: dark) {
  .liquid-glass-web-approx {
    border-color: rgb(255 255 255 / .18);
    background:
      linear-gradient(135deg, rgb(255 255 255 / .16), rgb(255 255 255 / .04)),
      rgb(15 23 42 / .42);
    box-shadow:
      inset 0 1px 0 rgb(255 255 255 / .22),
      0 18px 60px rgb(0 0 0 / .42);
  }
}

@media (prefers-reduced-transparency: reduce) {
  .liquid-glass-web-approx {
    background: rgb(255 255 255 / .96);
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
  }
}
```

**重要**：`prefers-reduced-transparency`浏览器支持不均；测试。即使无模糊也需足够对比度。
