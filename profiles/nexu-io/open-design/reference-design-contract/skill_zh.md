# 参考设计合同

在用户具有品味信号、参考示例或粗略的“就这个样”请求，并需要在生成前获得可复用的设计合同时，使用此技能。目标不是编写更长的提示。目标是使设计决策明确到足以让后续的原型、演示文稿、重新设计或图像混音运行时无需猜测。

## 此技能生成的内容

创建三个文件：

1. `DESIGN.md` — 可复用的视觉方向，遵循 OpenDesign 的标准九部分设计系统结构。
2. `design-contract.md` — 决策记录：所使用的证据、保留/更改边界、理由、风险和质量门禁。
3. `implementation-handoff.md` — 为下一个生成工件技能或编码代理的简洁构建说明。

如果预览有用，还可以创建 `example.html` 作为一个小型手工构建的合同预览。不要将其作为主要交付成果。

## 工作流程

1. **锁定任务。** 确定目标工件类型、受众、品牌/产品背景、参考示例和约束条件。当缺少答案会改变方向时，最多问两个问题。否则选择一个合理的默认值，并标记为推断得出。
2. **阅读证据。** 使用提供的截图、URL、现有的 `DESIGN.md`、品牌文档、图像工件或用户笔记。如果证据缺失，请说明，并仅基于简介创建合同；不要编造品牌事实。
3. **分离参考语义。** 对于每个参考示例，将其分为：
   - `保留`：要保留的品质，例如密度、构图、材质、排版节奏、色彩温度或运动态度。
   - `更改`：主题内容、文案、品牌标志、精确布局、受保护资产以及用户希望调整的任何内容。
   - `不要复制`：字面截图、标志、声明、定价、专有 UI 或示例中的精确提示措辞。
4. **锁定方向。** 选择一个连贯的视觉立场。不要提供五个不相关的情绪板。如果确实存在竞争方向，请简要命名它们，选择推荐的一个，然后继续。
5. **编写 `DESIGN.md`。** 使用以下九个标题：
   - `## 1. 视觉主题与氛围`
   - `## 2. 色彩`
   - `## 3. 排版`
   - `## 4. 间距与网格`
   - `## 5. 布局与构图`
   - `## 6. 组件`
   - `## 7. 动画与交互`
   - `## 8. 语气与品牌`
   - `## 9. 反模式`
6. **编写 `design-contract.md`。** 包括：
   - 目标和目标工件
   - 包含置信度（`观察到的`、`提供的`、`推断的`）的证据表格
   - 保留/更改/不要复制表格
   - 用一段话描述最终设计立场
   - 风险和明确未知项
   - 质量门禁检查清单
7. **编写 `implementation-handoff.md`。** 保持简短且可操作：
   - 要读取的文件
   - 令牌/调色板/类型/布局约束
   - 资产规则
   - 响应式要求
   - “第一个工件应证明……”的验收说明
8. **验证。** 读取 `references/checklist.md` 并在最终交接前满足所有 P0 门禁。

## 输出规则

- 使每个主张都能追溯到用户输入、观察到的参考证据或明确标记的推断。
- 优先考虑具体约束条件而非形容词：“一个暖色调的强调色，没有紫色或蓝色辉光”优于“高端”。
- 将“做同样的风格”视为“借鉴可控品质”，而不是“克隆原始主题或提示”。
- 如果用户要求立即生成 UI，请先完成这些合同文件，然后在下一步将交接给适当的工件技能。
