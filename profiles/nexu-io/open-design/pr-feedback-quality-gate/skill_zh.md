# PR 反馈质量门

在 PR 存在评审反馈、合并冲突、待处理的检查，或需要修复后的监控跟进时使用。

## 工作流

1. 首先检查 PR 状态：评论、评审、可合并性、检查、分支和本地工作树状态。将无关的本地更改排除在 PR 之外。
2. 当主分支检出脏、落后于远程或被其他代理使用时，使用隔离的工作树进行评审修复或冲突解决。
3. 进行最小的安全修复。保留原始错误不变量和 `main` 引入的任何更新的上游结构。
4. 首先运行窄验证，然后运行仓库要求的门禁。对于此仓库，包括 `pnpm guard`；当修改的文件需要时，添加包类型检查/构建/测试。
5. 在提交或推送之前，运行对已暂存或提议差异的只读交叉评审。禁止文件编辑和 git 写入或协调命令。
6. 将交叉评审视为证据，而非权威。仅接受基于差异、仓库规则、用户目标或验证结果的发现。降级或拒绝与安全或所有权边界冲突的样式偏好、范围扩展建议；简要记录原因。
7. 如果存在接受的阻塞项，修复它们，重新运行验证，并重复评审。只有验证通过且没有接受的阻塞项后，才提交和推送。

## 监控频率

- 活跃评审或失败的检查：频繁检查以快速解除阻塞。
- 清洁或已批准的 PR 等待合并：大约每 12 小时检查一次。
- 已合并的 PR：减少到每日轻量级观察，用于 CI、发布或回归信号，除非被要求，否则停止进行代码更改。

## 报告

始终报告 PR 状态、采取的行动、交叉评审结果、接受的或拒绝的发现、验证运行情况、推送的提交、跳过的检查原因、剩余风险和下一步。
