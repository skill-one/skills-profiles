# 前端设计

> 基于Anthropic官方的`frontend-design`技能，用于OpenDesign。

当用户要求构建或改进前端界面时（例如网站、着陆页、仪表盘、应用界面、HTML/CSS工件、React/Vue/Svelte组件，或现有UI的视觉重新设计）使用此技能。

目标不仅仅是“让它更好看”。目标是交付具有清晰设计观点、精湛工艺和足够产品细节的前端代码，使结果感觉是为用户的实际场景设计的。

## 工作流程

1. 在选择外观之前理解需求。
   - 确定受众、主要任务、领域和情感基调。
   - 记录任何技术限制：框架、现有样式、可访问性、性能、导出目标或响应式要求。
   - 如果代码库中已有设计令牌、组件、截图或`DESIGN.md`，则将其作为事实来源使用。

2. 坚持一个特定的美学方向。
   - 选择符合产品方向的风格：残酷极简、编辑式、奢华、俏皮、工业、复古未来主义、密集操作、平静企业、艺术化消费，或其他精确方向。
   - 通过字体、间距、颜色、层级、动效和组件形状使方向具体化。
   - 避免通用的AI默认值：紫色蓝色渐变、模糊玻璃卡片、可互换的SaaS布局、过度圆润的卡片、库存图标行和不符合界面的装饰性色块。

3. 设计真实的界面，而不是占位符海报。
   - 包括控件、空/加载/错误状态、表格、筛选器、导航和用户期望的响应式行为。
   - 使用真实内容。如果数据未知，则标记为样本、待定或不可用，而不是编造声明。
   - 保持为目标用户的工作流程高效。仪表盘和工具应足够可扫描和密集，便于重复使用；营销页面可以更富有表现力。

4. 构建生产级的前端代码。
   - 优先使用代码库现有的框架、组件规范、图标、令牌和样式方法。
   - 对于独立工件，除非用户要求使用框架，否则创建自包含的HTML/CSS/JS。
   - 使用语义化标记、键盘可访问控件、可见的焦点状态、合理的对比度和响应式布局限制。
   - 使用CSS变量来表示重复的颜色、间距、阴影和字体大小。

5. 精炼视觉工艺。
   - 字体：选择富有表现力但可读的字体组合。除非方向有意是实用主义，否则避免将默认系统堆栈作为主要视觉理念。
   - 颜色：创建具有角色清晰度的平衡调色板。有节制且明确地使用强调色。
   - 布局：有意使用对齐、韵律、密度和负空间。不要让卡片、面板或标签漂移。
   - 动效：为状态变化、揭示和反馈添加有目的的过渡。优先使用变换和透明度以提高性能。
   - 细节：仅在它们支持概念时使用纹理、边框、阴影、分隔符、媒体和图标。

6. 在最终交付前进行自我审查。
   - 界面在移动端和桌面宽度下均可工作。
   - 文本适合其容器且不与相邻UI重叠。
   - 交互元素具有悬停/焦点/激活/禁用状态。
   - 设计避免明显的AI生成的视觉陈词滥调。
   - 结果具有用户在关闭页面后可以描述的一个难忘特质。

## OpenDesign集成

当OpenDesign提供活动的设计系统时，将其视为产品的品牌合同。首先使用注入的颜色、字体、布局和组件指导，然后在设计系统沉默的地方应用此技能的前端工艺规则。

当OpenDesign注入工艺参考，如`typography`、`color`和`anti-ai-slop`时，在完成前应用这些检查。如果用户的品牌指导与通用工艺规则冲突，则用户的品牌指导优先。
