# Emil Kowalski 动画效果跟进

在已有设计原型的基础上使用此技能。目标是让界面感觉生动，但不要将其变成一个动画演示。

## 工作流程

1. 在添加动画之前，检查当前的 HTML、组件或选定的页面元素。
2. 选择最少的动画时刻来阐明状态或层级：
   - 主要内容的进入动画
   - 重要控件的光标悬停/激活反馈
   - UI 状态之间的过渡
   - 只有当它有助于讲述故事时才使用滚动动画
3. 优先使用 `transform` 和 `opacity`。避免动画布局属性，如 `top`、`left`、`width` 或 `height`。
4. 在整个原型中统一使用一种动画语言。不要混合不相关的缓动函数、持续时间或物理效果。
5. 为任何自动或滚动关联的动画添加 `prefers-reduced-motion` 备用方案。
6. 除非用户明确要求重新设计，否则保持文案、数据和布局意图不变。

## 动画规则

- 默认的 UI 过渡应感觉快速且有用：大多数控件为 140-220ms。
- 较大的页面展示可以更慢，但必须不会阻塞阅读。
- 除非用于传达状态或进度，否则避免无尽的装饰性循环。
- 不要添加自定义光标、嘈杂的粒子效果或与内容竞争的动画。
- 仅错开小批量元素。过长的错开列表会让界面感觉缓慢。

## 实现说明

- 对于纯 HTML，CSS 关键帧和小型 JavaScript 观察器就足够了。
- 对于 React 或框架代码，使用存储在代码库中已有的本地工具栈。
- 如果 GSAP 可用且动画需要序列化，则配合 `gsap-core`、`gsap-timeline` 或 `gsap-scrolltrigger` 使用。
- 始终清理观察器、计时器和动画实例。
