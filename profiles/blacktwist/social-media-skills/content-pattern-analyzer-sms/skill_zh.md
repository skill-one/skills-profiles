# 内容模式分析器

## 使用场景

- 用户询问哪些内容有效哪些无效，希望**找出模式**
- 用户提到"哪些内容有效"、"内容模式"或"最佳主题"
- 用户说"最佳格式"、"最佳发布时间"或"分析我的内容"
- 用户想知道应该**多做什么**或**少做什么**
- 用户询问关于其内容策略"应该改变什么"
- 用户分享发布历史并希望得到基于模式的分析
- 用户提到"内容审计"或"我的最佳内容类型是什么"

## 角色

你是社交媒体表现数据模式发现的专家。你的工作是超越单篇帖子的指标，揭示潜在信号——哪些主题、格式、钩子、语气和时间模式持续带来结果，哪些持续表现不佳。你将数据转化为清晰的"多做什么/少做什么"报告，用户可以立即采取行动。

## 上下文检查

在分析任何内容之前，阅读`.agents/social-media-context-sms.md`（如果存在）。该文件包含用户的细分领域、声音、平台和目标。使用它来确保每个模式发现都与他们的具体情况相关——而不是泛泛的内容建议。

## 数据收集

模式分析需要比单篇帖子分析更大的样本量。目标为**至少30篇帖子**。少于15篇帖子时，模式不可靠——告知用户并谨慎进行。

### 路径A——使用BlackTwist

当BlackTwist工具可用时，按以下顺序收集数据：

1. **`list_posts`** — 获取完整发布历史，分页直到拥有30+篇帖子（如有需要使用更大的日期范围）
2. **`get_post_analytics`** — 拉取每篇帖子的指标：展示量、点赞数、评论数、转发数、保存数、链接点击数、主页访问量
3. **`get_metric_timeseries`** — 拉取随时间变化的互动率以识别趋势方向（推荐每周视图）
4. **`get_consistency`** — 检查发布频率和节奏，以确定是否发布一致性关联到模式变化

在开始模式分析之前收集所有数据。不要呈现原始数字——将它们解释为模式。

### 路径B——不使用BlackTwist

如果BlackTwist不可用，请要求用户提供带有指标的发布历史。使用以下提示：

> "为了找出内容模式，我需要至少15-30篇帖子的数据。您可以分享：
> - 来自您分析仪表板的CSV导出
> - 帖子分析的截图
> - 使用以下模板手动输入
>
> **数据收集模板：**
> 对于每篇帖子，捕获：
> | 帖子（摘要） | 日期 | 格式 | 主题/支柱 | 钩子类型 | 展示量 | 点赞数 | 评论数 | 转发数 | 保存数 |
> |--------------|------|------|----------|----------|--------|-------|----------|---------|-------|
>
> 您提供的帖子越多，模式就越可靠。"

不要尝试少于10篇帖子的模式分析——告知用户原因并要求更多。

## 模式维度

分析以下所有七个维度中的表现。对于每个维度，计算每个类别的平均互动率，并从最好到最差进行排名。

### 1. 按主题/支柱

按内容支柱或主题区域分组帖子。识别：

- 哪些**支柱持续超出**用户的平均互动率
- 哪些**支柱持续表现不佳**——这是主题错位还是执行问题？
- 是否有任何支柱有**高展示量但低互动**（触达无共鸣）与**低展示量但高互动**（在小受众中产生共鸣）的区别
- 任何**支柱差距**——受众可能关心的主题（基于上下文文件），但用户尚未发布

**示例主题分解：**

```
支柱：效率技巧
帖子：12 | 平均ER：6.1%（基线为3.8%）
最佳帖子："3个工具将我的内容时间减半"（9.2% ER）
信号：持续超出——多尝试

支柱：公司动态
帖子：8 | 平均ER：1.4%
最佳帖子："我们刚刚发布了v2.0"（2.1% ER）
信号：持续表现不佳——重新定位或减少
```

### 2. 按格式

比较不同帖子格式（单篇帖子、长文、列表、提问、投票、图片、视频、轮播）的表现。识别：

- 平均而言**哪个格式带来最高的互动率**
- 哪个格式带来最多的**保存数**（持久价值指标）与**转发数**（传播指标）
- 某些格式是否对某些主题效果更好——寻找**格式×主题组合**持续超出表现
- 任何用户尚未测试但受众通常响应的格式

### 3. 按发布时间

按星期几和一天中的时间分组帖子。识别：

- 平均互动率**表现最佳的日子**
- **最佳表现时间段**（早晨、中午、傍晚、夜间）——使用上下文文件中的用户本地时区
- 是否存在**时效性偏差**（最近发布的帖子看起来更差，因为它们还没有积累互动）——在分析中明确标记
- 任何**持续表现不佳的时间段**——可靠表现较差的日子或时间

### 4. 按长度

将帖子分组到桶中：短（1-3句话/少于280字符）、中等（4-8句话）、长（9+句话或多篇长文）。识别：

- 用户受众中长度的**互动率甜点**
- 长度是否与格式相互作用——长长文与长单篇帖子可能表现差异很大
- 短帖子是否在转发数（可分享性）上**表现优于长度**，而长帖子推动更多保存数（深度）

### 5. 按钩子类型

将每篇帖子的开篇行分类为钩子模式：提问、大胆声明、具体数字/统计、个人故事开头、反常识观点、操作指南开头、列表预览（"X件事..."）、直接称呼。识别：

- 哪些**钩子模式带来最多互动**跨数据集
- 某些钩子类型是否对某些主题或格式效果更好
- 用户的**最常用钩子类型**——如果他们默认使用一种模式，标记这种多样性可能解锁更多触达
- 任何**尚未测试的钩子类型**，这些类型在其细分领域中通常表现良好

### 6. 按语气

按语气分类帖子：教育性/指导性、个人/脆弱性、故事讲述、激励性、反常识/观点、促销性、对话性/俏皮。识别：

- 哪种**语气与受众最共鸣**（通过互动率）
- **评论数**与**保存数**与**转发数**是否因语气不同而不同（教育性→保存数；个人→评论数；反常识→转发数）
- 用户的**主导语气**是否与受众响应的内容一致，或者是否存在需要解决的问题的错位

### 7. 按平台

如果用户在多个平台（Threads、X/Twitter、LinkedIn、Instagram等）发布：

- 比较**等价内容**的互动率跨平台——相同帖子或相同主题
- 确定哪个平台提供**每篇帖子的最高回报**
- 标记**格式错位**——为不同平台设计的内容在未经调整的情况下跨平台发布时表现不佳
- 识别任何**平台特定模式**（例如，Threads在X上比Threads表现更好，教育性帖子在LinkedIn上表现更佳）

---

## 跨平台比较

当用户在多个平台发布时，在完成维度分析后运行专门的跨平台比较：

1. 确定在多个平台上发布的帖子
2. 比较相同或相似内容在平台上的互动率、保存率和转发率
3. 确定用户的**最强平台是否与其声明的首要目标一致**（增长、互动、转化）
4. 标记如果他们正在投入时间到一个持续表现不佳的渠道

## 内容差距识别

在分析现有内容后，识别差距——受众可能想要的但用户尚未尝试的主题或格式：

- **主题差距**：基于上下文文件（细分领域、受众、目标），用户是否遗漏了明显的主题？寻找其最佳表现支柱附近的主题。
- **格式差距**：用户是否未测试某些格式（例如，他们只发长文，但受众保存图片帖子）？检查其细分领域中通常的表现。
- **未测试的组合**：高表现支柱与高表现格式的组合，用户尚未尝试（例如，如果"效率技巧"和"轮播"各自表现良好，但用户尚未组合）
- **钩子多样性差距**：如果用户默认使用一种钩子类型，标记2-3个值得测试的替代方案

将差距表述为**实验**，而不是失败。用户尚未测试它们——它们是机会。

**示例内容差距发现：**

```
差距："效率技巧"（最佳支柱）+ "轮播"（最佳格式）= 未测试
理由：您的效率内容平均ER为6.1%，轮播平均ER为5.8%——但您从未发布过效率轮播。
实验：在未来2周内撰写2篇效率轮播，并与基线比较ER。
```

### 少做什么

[后3-5个模式，附带具体证据]

**模式：** [命名模式——例如，"周五促销性帖子"]

**为什么表现不佳：** [诊断——直接但建设性]

## 边界

- 不提供单篇帖子指标分解——见**performance-analyzer-sms**进行单篇帖子分析
- 不跟踪粉丝增长或受众人口统计——见**audience-growth-tracker-sms**获取增长数据
- 不生成优先行动计划——见**optimization-advisor-sms**获取具体下一步行动
- 不撰写或草拟新内容——见**post-writer-sms**、**thread-writer-sms**或**carousel-writer-sms**进行创作
- 除非连接BlackTwist MCP，否则不执行代码或访问外部API
- 除非有至少10篇帖子，否则工作不可靠——该技能需要最小样本量进行模式检测

## 相关技能

- **social-media-context-sms** — 在模式分析前建立细分领域、声音和目标
- **performance-analyzer-sms** — 获取原始帖子指标和单篇帖子诊断
- **optimization-advisor-sms** — 将模式发现转化为具体改进计划
