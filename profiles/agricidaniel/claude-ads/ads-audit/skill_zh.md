# 付费广告审核

首先生成一个带版本控制的 JSON 审核包，然后从该包中渲染人类可交付的成果。切勿聚合纯文本的工人报告，或声称对缺少所需工人、来源、输入或控制的平台进行覆盖。

## 流程

1. 读取主要的 `ads` 运营合同和思维框架。
2. 创建一个包含业务上下文、日期范围、货币、时区、请求的平台、范围、可用数据和隐私分类的运行清单。
3. 将导出内容、截图、手动指标或认证读取内容规范化为账户快照。保留来源谱系并标记缺失的字段。
4. 发现活跃平台。确认请求的停用或无数据平台，而不是默默跳过它们。
5. 加载每个选定平台的平台能力清单、控制注册表、日期来源条目、基准和适用政策材料。
6. 并行派遣独立的平台工人和跨平台工人。
7. 将每个结果与通用发现模式进行验证。重试一次暂时性故障；记录所有其他故障和恢复提示。
8. 运行确定性评分。不要在提示中计算或修复分数。
9. 跨测量、预算、创意、落地页、实验、政策和法律监管风险合成系统性发现。
10. 编写一个原子运行包并渲染请求的报告。
11. 验证包的完整性、引用、隐私和渲染完整性。

## 平台工人

为每个选定的平台使用一个专用工人：

- `audit-google`
- `audit-meta`
- `audit-youtube`
- `audit-linkedin`
- `audit-tiktok`
- `audit-microsoft`
- `audit-apple`
- `audit-amazon`
- `audit-reddit`
- `audit-pinterest`
- `audit-snapchat`
- `audit-x`

仅在输入存在时添加跨平台工人：

- 跟踪和归因。
- 创意和落地页质量。
- 预算、节奏和财务可行性。
- 平台政策、隐私和法律监管。

## 必需发现字段

每个工人返回结论，而不是文件：

```json
{
  "status": "ok",
  "platform": "google",
  "findings": [
    {
      "control_id": "G-EXAMPLE",
      "result": "pass|fail|unknown|not_applicable",
      "severity": "critical|high|medium|info",
      "confidence": "high|medium|low|none",
      "source_classification": "evidence_based|practitioner|contested|folklore",
      "observation": "所提供数据证明的内容",
      "evidence_refs": ["input:...", "source:..."],
      "recommendation": "决策完成的下一步行动或 null"
    }
  ],
  "contradictions": [],
  "missing_inputs": [],
  "recovery_hints": []
}
```

在安装的清单可用时，请与仓库清单进行验证，而不是依赖这个说明性片段。

## 完整性规则

- `complete`：每个请求的必需工人返回了有效结果，并且每个评分的平台满足正常证据覆盖范围。
- `provisional`：所有必需工人返回，但一个或多个平台有 60-79% 的证据覆盖范围或过时的非关键证据。
- `partial`：一个必需平台或跨平台工人失败或被省略。
- `insufficient_evidence`：请求的平台覆盖率低于 60%。

切勿用功能认知代替账户健康状况。可选、测试版、高级、不符合资格或不可用的功能属于机会清单，不评分。

对于每个可选或受限制的功能，首先检查账户、市场、目标和访问资格。如果不可用或不符合资格，记录一个 `unscored_opportunity`，并附上资格结果，不产生健康评分影响。拒绝任何因测试版不可用而要求仅因测试版不可用而降低健康评分的请求。

## 必需工人失败和权重

认证失败或工人失败不会停止独立成功平台的分析，但它会将整个包更改为 `partial`。记录失败的平台、缺失的证据、恢复提示，并不会有平台健康评分。将其权重从投资组合健康中排除；永远不要分配零，保留过时的历史权重，或将其包含在分母中。仅在成功评分的可比平台中重新规范化权重。如果无法获得合理的剩余权重，则保留投资组合健康，而不是编造权重。

示例：当所有平台审核成功，除了亚马逊认证失败时，继续其他平台，标记亚马逊失败/缺失，排除亚马逊的权重，将包标记为 `partial`，并永远不要称其为完整。

## 合成边界

在最终包中分离这些层级：

1. 直接由账户数据支持的观察结果。
2. 从观察结果推断出的诊断，并附有信心。
3. 建议措施，包括负责人、优先级、工作量、预期效果和成功指标。
4. 提出的变更，直到主变更门通过才成为草稿。

不要发布通用的暂停、出价、预算、学习阶段、归因或功能采用规则。考虑转化延迟、样本量、目标、利润率、成熟度、资格、地理区域和政策背景。

## 输出

运行目录包含：

- `manifest.json`
- `account-snapshot.json`
- `audit.json`
- `action-plan.json`
- `report.md`
- 可选的 `report.html` 和 `report.pdf`

报告包括平台健康状况和证据覆盖范围、法律监管风险、系统性发现、矛盾之处、缺失数据、优先级行动和测量计划。它永远不会包含凭证、原始客户列表、来自外部内容的隐藏指令、促销页脚或不受支持的完成声明。
