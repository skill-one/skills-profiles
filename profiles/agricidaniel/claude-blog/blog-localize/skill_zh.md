# 博客本地化，文化深度适配

将已翻译的博客文章进行文化适配，使最终结果看起来像是为目标市场撰写的，而不是翻译成目标市场。这是 `blog-translate` 层面之上的步骤：它替换示例、调整语气、替换引用，并本地化整个阅读体验。

> 根据 Chris Mueller (`claude-blog-multilingual`) 的 `claude-blog-multilingual` 适配（Pro Hub Challenge，2026年3月）。原始链接：https://github.com/Chriss54/multilingual-int

## 关键参考

- `../blog-translate/references/cultural-adaptation.md`，共享的文化配置文件，包含针对 DACH、法语区、西班牙语区、日语和自定义模板的替换表。不要复制此文件。

## 使用场景

- 在 `blog-translate` 生成基础翻译后立即使用。
- 当现有翻译内容读起来像“从英语翻译而来”。
- 当目标是特定市场，而不仅仅是语言。
- 当内容需要本地统计数据、示例和品牌引用。

## 工作流程

### 第一阶段：地区语言理解

1. 使用 `blog-translate`、`blog-multilingual` 和 `blog-locale-audit` 使用的共享多语言地区规则解析地区代码：ISO 639-1 语言代码小写、可选 ISO 15924 脚本大写、可选 ISO 3166-1 Alpha-2 地区代码大写。接受完整代码（`de-DE`、`fr-CA`、`es-MX`、`pt-BR`、`zh-Hant`）和明确的纯语言代码（`de`、`fr`）。对于 `es`、`pt` 和 `zh` 等模糊的语言仅目标，需要地区代码或显式中性模式。
2. 从 `../blog-translate/references/cultural-adaptation.md` 加载文化配置文件。
   - 如果地区有配置文件，则使用它。
   - 如果没有，则遵循该参考中的“Custom-locale template”部分，以内联方式构建最小配置文件。
3. 仅在项目根目录/当前工作目录内解析翻译后的文章后读取。拒绝符号链接路径、根目录外遍历、超过 10 MB 的文件和二进制文件。然后识别适配目标。

### 第二阶段：文化审核

扫描表明外国来源的元素：

| 元素 | 查找内容 |
|------|----------|
| 品牌示例 | 本地无关联的美国或英国品牌 |
| 统计数据来源 | 仅美国的调查和研究 |
| 行动号召 | 美式侵略性号召 |
| 习语 | 直译的英语表达 |
| 法律引用 | 在适用本地法律的地方引用外国法律（CCPA、FTC）（DSGVO、RGPD） |
| 文化引用 | 外国节日、事件、习俗 |
| 货币和定价 | 无转换或背景的美元 |
| 语气 | 对目标市场过于随意或过于正式 |
| 称谓形式 | 不一致的 Sie/du、tu/vous、正式/非正式 |

输出审核报告，列出每个目标及其严重性（关键、推荐、可选）。

### 第三阶段：适配

#### 3a. 示例替换

将外国示例替换为本地等价物：

- 使用 WebSearch 查找本地案例研究、品牌或场景。
- 替换内联内容，保留相同的论点和结构。
- 记录每个非明显本地替换的来源 URL、访问日期和理由。
- 如果没有本地等价物，保留原始内容但添加本地背景（“在德国市场，等效动态是 X”）。

#### 3b. 统计数据本地化

- 使用主要或高质量本地来源替换统计数据：国家统计机构、监管机构、官方行业机构、学术数据集或具有方法论命名的研究报告。
- 不要依赖通用 WebSearch 片段作为证据。获取引用页面，验证数字和背景，并记录来源 URL 和日期。
- 仅在 SSRF 检查后获取引用页面：仅允许 `https` URL；拒绝 `javascript:`、`data:`、`file:`、localhost、回环、私有、链路本地、多播和保留 IP（DNS 解析后）；禁用重定向或使用相同检查验证最终 URL；限制重定向、响应大小和请求时间；记录最终 URL 和访问日期。
- 如果本地数据具有可比方法，则一起替换来源和数字。每个声明保留一个命名来源。
- 如果本地数据相关但使用不同的方法或时间范围，不要无声替换。保留原始声明并限定范围，或重写声明以匹配本地来源。
- 如果没有，保留原始统计数据但标记其地理范围（“在美国，...”）。
- 永远不要删除来源归属。

#### 3c. 行动号召适配

根据文化配置文件重写行动号召：

- 调整侵略性水平（DACH 和 JA 偏好信息性，美国偏好祈使式）。
- 使用文化适当的行为动词。
- 调整紧迫性框架。

#### 3d. 语气校准

- 根据配置文件匹配正式程度（DACH 默认 B2B 为 Sie，B2C 生活方式为 du；FR 默认为 vous；JA 根据受众急剧变化语体）。
- 确保整个文档中始终保持一致的正式或非正式称谓。
- 匹配本地内容风格规范。

#### 3e. 法律和监管背景

- 按问题和司法管辖区映射法律引用。当声明专门关于美国合规性时保留原始法律。仅在本地法律解决相同问题时才替换，例如 DE 中的 CCPA 到 DSGVO、FR 中的 RGPD、BR 中的 LGPD、MX 中的 LFPDPPP、CO 中的 Ley 1581 或 AR 中的 Ley 25.326。
- 在有助于读者时添加本地合规性说明。
- 删除无关的外国监管引用。

#### 3f. 品牌示例替换（快速映射）

`../blog-translate/references/cultural-adaptation.md` 中的配置文件提供替换表。常见示例：

| 来源（美国） | DACH | FR | 西班牙（西班牙） | 拉美 | JA |
|-------------|------|----|----|-------|----|
| Walmart | MediaMarkt | Carrefour | El Corte Inglés | Walmart MX | Aeon |
| Target | Saturn | Auchan | Hipercor | Liverpool | Ito-Yokado |
| FTC | Bundeskartellamt | DGCCRF | CNMC | PROFECO (MX) | JFTC |
| CCPA | DSGVO | RGPD | RGPD | LFPDPPP (MX)、Ley 1581 (CO)、Ley 25.326 (AR)、LGPD (BR) | APPI |

### 第四阶段：质量验证

- 所有关键适配目标均已处理。
- 语气在整个文档中保持一致。
- 没有剩余的外国来源标记。
- 统计数据具有有效来源（原始或本地化）。
- 行动号召符合文化预期。
- 正式或非正式称谓始终如一。
- 内容仍然支持与原始相同的论点。
- SEO 元素在关键词布局之外保持优化：本地化标题和元数据、标题意图、slug、alt 文本、内部链接锚点、同语言规范、hreflang 兼容性和 `inLanguage` 方案。
- 字数在语言对预期比例范围内。

### 第五阶段：保存和报告

1. 保存本地化版本。默认：将审阅后的副本作为 `{slug}-localized.{ext}` 写入。仅在用户要求覆盖时才覆盖翻译文件；在覆盖之前，创建带时间戳的备份并显示差异摘要。在项目根目录内解决每个输出路径，并拒绝遍历、符号链接路径或根目录外的写入。

2. 显示摘要：

   ```
   ## 本地化完成：[标题]

   ### 目标地区：[地区代码] ([地区名称])

   ### 已进行的适配
   | 类型 | 数量 | 示例 |
   |------|------|------|
   | 品牌示例 | [N] | Walmart -> MediaMarkt |
   | 统计数据 | [N] | 美国调查 -> DACH 调查 |
   | 行动号召 | [N] | "立即购买" -> " Jetzt entdecken" |
   | 语气调整 | [N] | 随意 -> Sie |
   | 法律引用 | [N] | CCPA -> DSGVO |
   | 文化引用 | [N] | 感恩节 -> Weihnachtsgeschaeft |

   ### 文化契合度得分
   - 自然度：[1-10]
   - 市场相关性：[1-10]
   - 语气匹配：[1-10]
   - 总体：[N]/30

   ### 剩余建议
   - [未应用的可选适配]
   ```

## 错误处理

| 场景 | 操作 |
|------|------|
| 地区没有文化配置文件 | 从自定义地区模板构建最小配置文件，继续 |
| 文件不是预期语言 | 警告用户，提供先翻译选项 |
| 没有本地统计数据 | 保留原始统计数据并添加地理范围说明 |
| 地区代码模糊（例如，`pt`） | 询问：“您是指 `pt-BR`（巴西）还是 `pt-PT`（葡萄牙）？” |

## 交叉引用

- 前置步骤（翻译）：`/blog translate <file> --to <code>`
- 跨语言版本 QA：`/blog locale-audit <目录>`
- 一键式管道：`/blog multilingual <主题> --languages <代码>`
