# 博客GEO：AI引用优化审计

对博客文章在ChatGPT、Perplexity、Claude、Gemini、Copilot、You.com、Google AI概览和Google AI模式中的AI引用准备情况进行评分，作为一个SEO工作流程，而不是一个独立的学科。生成一个0-100的内部AI引用准备启发式算法，并提供平台特定的建议。分数不是引用的校准概率。

Google的2026-05-15指南将生成式AI优化视为SEO：不需要特殊的标记、llms.txt要求或单独的GEO/AEO剧本来获得Google的可见性。仅将GEO/AEO用作简称标签。

## 交叉引用

这项技能涵盖了FLOW表面3（AI助手引用：ChatGPT、Perplexity、Claude、Gemini、Copilot、You.com）并有助于表面2（SERP加上AI概览）。表面映射：`skills/blog/references/flow-alignment.md`。

对于直接相关的AI引用提示（AI支持页面重写、基于证据的质量后续、ChatGPT发现、可见性提示），请参阅`/blog flow optimize`。

## 证据学科

仅在报告包含带有URL、发布者、方法、样本量、引擎或版本、查询类别、检索日期和过期日期的源块时才使用数字AI引用基准。如果任何字段缺失，请将基准标记为方向性或删除数字。默认启发式算法：

- 自包含、有证据支持的说明可以帮助重用，但Google没有规定段落长度或“分段”要求。
- 具有语义标题的比较表可以提高可提取性，但在没有日期源块的情况下不要引用提升。
- AI概览的覆盖范围取决于方法：引用一个日期范围，而不是一个固定点。

## 审计流程

### 第1步：阅读内容

从博客文章中提取：
- 完整内容文本和字数
- 标题结构（H1、H2、H3层次结构）
- 单个段落及其字数
- 常见问题解答部分（如果存在）
- Schema标记（JSON-LD、微数据、RDFa）
- robots.txt提及或meta robots指令
- 任何TL;DR或摘要框
- 比较表及其HTML结构
- 编号/有序列表
- 定义式格式

### 第2步：有证据支持的引用性（4分）

检查每个标题之间的段落是否有AI可提取的段落：

| 检查 | 标准 |
|-------|----------|
| 上下文独立性 | 每个段落从上下文中提取出来也能理解 |
| 声明结构 | 段落包含：具体声明 + 支持证据 + 源归属 |
| 完整性 | 段落回答问题，不需要读者阅读相邻部分 |

**评分：** 计算符合证据和完整性标准的重点段落。不要评分段落长度。
- 4分：80%以上的段落有可引用的段落
- 3分：60-79%
- 2分：40-59%
- 1分：20-39%
- 0分：<20%

### 第3步：目的匹配和读者实用性（3分）

检查标题格式和答案结构：

| 检查 | 标准 |
|-------|----------|
| 明确目的 | 引言确定页面的主题、受众和读者任务 |
| 有用的段落开头 | 重要段落直接陈述要点，不需要铺垫 |
| 意图匹配的格式 | 声明性标题、问题、FAQ、表格和列表仅在适合材料时使用 |

**评分：**
- 3分：所有三个标准都满足
- 2分：满足两个标准
- 1分：满足一个标准
- 0分：都不满足

### 第4步：实体清晰度（3分）

检查主题一致性和消歧义：

| 检查 | 标准 |
|-------|----------|
| 原始主题 | 每个页面有一个明确的主要主题 |
| 一致命名 | 整篇文章使用相同的实体名称（不要令人困惑的同义词） |
| 引言声明 | 引言段落中有明确的主题声明 |
| 标题与内容匹配 | 标题准确反映内容焦点 |

**评分：**
- 3分：所有四个标准都满足
- 2分：满足三个标准
- 1分：满足一个或两个标准
- 0分：都不满足

### 第5步：内容结构用于提取（3分）

检查AI可提取的内容模式：

| 检查 | 标准 |
|-------|----------|
| 摘要 | 可选的独立摘要，当它有助于目标读者时 |
| 比较表 | 具有语义标题的表格，如`<thead>`或清晰的列标签 |
| 有序列表 | 编号列表用于流程和分步说明 |
| 定义格式 | 关键术语使用清晰的定义模式格式化 |
| 有证据支持的说明 | 重要可重用的声明包含足够的上下文和源支持 |

**评分：**
- 3分：4-5个元素存在
- 2分：3个元素存在
- 1分：1-2个元素存在
- 0分：没有元素存在

### 第6步：AI爬虫可访问性（2分）

检查AI爬虫索引的技术要求：

| 检查 | 标准 |
|-------|----------|
| 渲染内容 | 重要内容在渲染的DOM中存在且可被目标爬虫访问 |
| Google可见性 | 正常的爬取性和可索引性，Googlebot不需要特殊的GEO/AEO文件或标记来获得Google AI功能 |
| 非Google AI爬虫 | 如果网站希望在非Google答案引擎中可见，请检查robots.txt对GPTBot、ChatGPT-User、ClaudeBot、PerplexityBot和相关记录爬虫的处理 |
| Schema一致性 | 结构化数据到达渲染的DOM并与可见内容匹配 |
| 页面大小 | 合理的页面大小，在AI爬虫限制内 |

**评分：**
- 2分：Google的爬取性和可索引性干净，并且选定的非Google爬虫策略与网站声明的目标一致
- 1分：Google可索引，但一个选定的非Google爬虫或渲染检查需要审查
- 0分：Google爬取或索引被阻止，或多个选定的爬虫被无意中阻止

### 第7步：平台特定分析

评估每个声明的表面的可观察准备情况。产品行为随模式、查询集、地理位置和日期而变化，因此不要从供应商样本中推断因果关系。

#### ChatGPT
- 检查材料声明是否有源支持且在不需要依赖特定内容格式的情况下有用。
- 将当前的引用样本视为非因果关系背景，而不是列表、新鲜度或域名权威规则。

#### Perplexity
- 检查在查询时间敏感时爬取性、源保真度和材料新鲜度。在描述产品行为之前，用当前日志或可重复的工具验证观察结果。

#### Google AI概览
- 遵循Google的正常SEO指南：使内容有帮助、可爬取、可索引并符合片段资格。不需要特殊的GEO/AEO标记或llms.txt来获得Google的可见性。
- 分别测量搜索和AI功能的可见性。在样本中观察到的有机重叠不能建立偏好或保证包含。

#### Google AI模式
- 在报告中将其与AI概览分开。强调正常搜索资格、清晰的页面目的、可访问的文本以及可见内容与结构化数据之间的一致性。

#### Claude、Gemini、Copilot和You.com
- 评估内容清晰度、源可访问性、新鲜度，以及文档中记录的每个爬虫是否有意允许或阻止。
- 仅在当前文档、日志或测试结果可用时才使用引擎特定建议。

对于每个平台，提供：
- 当前可引用评分（高 / 中 / 低）
- 提高清晰度、源保真度、实用性和爬取性的具体改进
- 内容格式建议

### 第8步：加强可重用的证据

对于缺乏支持的要点部分，建议一个自包含的改进，包括一个具体声明、理解它所需的上下文以及一个经过验证的源或透明的原始方法。不要填充每个部分，不要强加字数限制或编造统计数据。

### 第9步：计算AI引用准备评分（0-100）

将15分子类别分数映射到0-100显示分数：

| 类别 | 原始分数 | 显示权重 | 最大显示分数 |
|----------|-----------|----------------|-------------------|
| 有证据支持的引用性 | /4 | x6.75 | 27 |
| 目的匹配和读者实用性 | /3 | x6.67 | 20 |
| 实体清晰度 | /3 | x6.67 | 20 |
| 内容结构 | /3 | x6.67 | 20 |
| AI爬虫可访问性 | /2 | x6.5 | 13 |
| **总计** | **/15** | | **100** |

评分阈值：
- 90-100：优秀：高度可被AI系统引用
- 70-89：良好：需要轻微改进即可引用
- 50-69：需要改进：可引用性存在重大差距
- 低于50：差：需要重大结构调整

### 可选：搜索性能上下文（blog-google）

如果blog-google凭证包括Tier 1（GSC）并且文章有一个已发布的URL：

1. 使用页面和查询维度查询GSC，然后过滤行到URL：
   `python3 skills/blog-google/scripts/run.py gsc_query --property <property> --dimensions query,page --json`
2. 添加到平台特定分析：
   - 当前印象、点击率、平均位置
   - 驱动流量到此URL的搜索查询
3. 检查索引：`python3 skills/blog-google/scripts/run.py gsc_inspect <url> --json`
4. 报告索引状态、规范选择、移动可用性。
5. 如果跳过，报告`SKIPPED: 凭证不可用`或
   `SKIPPED: 未发布URL`。

### 可选：AI引用准备启发式算法

对于每个引擎的准备视图（与`/blog analyze`评分的15点AI引用准备类别不同），运行：
