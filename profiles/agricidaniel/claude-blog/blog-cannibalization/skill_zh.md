# 博客同化 - 关键词重叠检测

检测多个博客文章是否争夺相同的关键词。有两种模式：
仅本地分析（默认）和 DataForSEO API 模式用于搜索结果页面（SERP）级数据。

## 两种模式

| 模式 | 标志 | 成本 | 数据源 |
|------|------|------|-------|
| 本地 | (默认) | 免费 | 通过 Grep/读取分析文件内容 |
| API | `--api` | ~$0.01/次调用 | DataForSEO 页面交集 + 排名关键词 |

本地模式无需任何 API 密钥。API 模式需要将 DataForSEO 凭证设置为环境变量：`DATAFORSEO_LOGIN` 和 `DATAFORSEO_PASSWORD`。

## 本地模式工作流程

### 第 1 步：扫描博客文件

使用 Glob 查找目标目录中的所有内容文件：
- 模式：`**/*.md`，`**/*.mdx`，`**/*.html`
- 跳过 `node_modules/`，`.git/`，`drafts/` 中的文件

### 第 2 步：提取主要关键词

对于每个文件，读取并提取来自以下位置的关键词信号：
- **标题标签** 或 H1 标题（最高权重）
- **H2 标题**（中等权重）
- **第一段**（支持信号）
- 如果 frontmatter 中存在，则提取 **元描述**

主要关键词提取方法：
1. 将标题、H1、H2s、元描述和第一段分词为 1-gram、2-gram 和 3-gram 短语。
2. 确定性地规范化：小写化、移除区域感知停用词、一致地进行词元化或词干提取，保留产品名称，并保留如 "best"、"pricing"、"vs"、"review"、"template" 和年份等意图修饰符。
3. 分别评分各部分：标题/H1 最高，元描述和 H2s 中等，第一段支持。
4. 选择得分最高的 2-3 词短语作为主要关键词，并记录来自 H2 标题的次要关键词。

### 第 3 步：按相似性聚类

使用以下匹配规则（按优先级顺序）将文章分组到集群中：

1. **完全匹配** - 两个或多个文章具有相同的主要关键词
2. **词干匹配** - 相同的词根（例如，"optimize" vs "optimization"）
3. **语义重叠** - 分配显式意图标签，如信息性、商业性、交易性、比较性或故障排除。包括置信度和一句话理由，或使用具有文档化阈值的嵌入工作流。
4. **子集匹配** - 一个关键词包含另一个（例如，"email marketing" vs "email marketing for startups"）

### 第 4 步：评分和标记

对于每个包含 2 篇以上文章的集群，评估严重性并生成建议。

### 第 5 步：输出报告

显示结果表格和每个集群的建议。

## API 模式工作流程（DataForSEO）

需要 `--api` 标志和一个专用的本地 CLI 包装器，该包装器从环境变量中读取 `DATAFORSEO_LOGIN` 和 `DATAFORSEO_PASSWORD` 并发出 JSON。不要使用 WebFetch 进行 DataForSEO POST 调用，并且永远不要在提示或报告中暴露 Basic 认证头、登录、密码或编码凭证。如果项目中不存在包装器，请报告 `SKIPPED: DataForSEO 包装器不可用` 并运行本地模式。

### 使用的端点

**页面交集** - 查找多个 URL 排名重叠的关键词：
```
POST https://api.dataforseo.com/v3/dataforseo_labs/google/page_intersection/live

{
  "pages": {
    "1": "https://example.com/post-a",
    "2": "https://example.com/post-b"
  },
  "language_code": "en",
  "location_code": 2840
}
```
成本：~$0.01/次调用。返回重叠关键词及其位置、搜索量和 CPC。

**排名关键词** - 获取单个 URL 排名所有关键词：
```
POST https://api.dataforseo.com/v3/dataforseo_labs/google/ranked_keywords/live

{
  "target": "https://example.com/post-a",
  "language_code": "en",
  "location_code": 2840
}
```

包装器从环境变量中发送 DataForSEO 认证头，并且永远不会打印它们。

### API 分析步骤

1. 从用户处收集所有已发布的 URL（或站点地图）
2. 对每个 URL 运行排名关键词以构建关键词配置文件
3. 对共享关键词集群的 URL 对运行页面交集
4. 使用以下公式计算严重性
5. 输出包含搜索量和位置数据的丰富报告

## 严重性评分

基于重叠信号的四个严重性级别：

| 级别 | 标准 | 行动紧迫性 |
|------|------|-----------|
| 危急 | 相同的关键词，两个页面都在前 20 位 | 立即 |
| 高 | 相同的关键词集群，一个页面排名高于另一个 | 本周 |
| 中 | 相关关键词，部分 SERP 重叠 | 本月 |
| 低 | 语义相似但确认意图不同 | 监控 |

### 严重性公式（API 模式）

```
severity_score = overlap_count x avg_search_volume x (1 / position_gap)
```

其中：
- `overlap_count` = 共享排名关键词的数量
- `avg_search_volume` = 共享关键词的平均月搜索量
- `position_gap` = 平均排名位置的绝对差值（最小值为 1）

得分越高 = 更严重的同化问题。

### 严重性启发式（本地模式）

没有 SERP 数据时，使用简化评分：
- **危急**：文章之间存在完全匹配的主要关键词
- **高**：主要关键词词干匹配，或 3 个以上共享的 H2 关键词
- **中**：主要关键词存在语义重叠
- **低**：仅子集匹配，或共享次要关键词

## 输出格式

### 摘要表格

```
| 文章 A | 文章 B | 共享关键词 | 严重性 | 建议 |
|--------|--------|------------|-------|------|
| /best-crm-tools | /top-crm-software | best crm, crm tools, crm software | 危急 | 合并 |
| /email-tips | /email-marketing-guide | email marketing | 高 | 区分 |
| /seo-basics | /seo-for-beginners | seo basics, beginner seo | 危急 | 规范 |
| /react-hooks | /react-state-mgmt | react, state | 低 | 无操作 |
```

### 每个集群的详细信息

对于每个标记的集群，提供：
- 两个文章标题和 URL
- 完整的重叠关键词列表（如果 API 模式则包含搜索量）
- 哪个文章更强（更全面、结构更好）
- 具体的建议和理由

## 建议

每个同化集群有四种可能的操作：

### 合并
当两个页面都很薄弱或以相似深度覆盖相同意图时。
- 将两个文章的最佳内容合并到一个全面的文章中
- 将较弱的 URL 301 重定向到合并后的文章
- 保留指向这两个 URL 的所有内部链接

### 区分
当页面服务于不同意图但关键词定位重叠时。
- 将较弱文章的主要关键词调整为相关的长尾关键词
- 更新标题、H1 和元描述以反映新的重点
- 在两个文章之间添加内部链接以指示不同的主题

### 规范
当一个文章明显是权威而另一个是次要重复时。
- 在较弱页面添加 `rel="canonical"` 指向权威页面
- 不要随意将规范和 noindex 结合使用。仅在打算从搜索中删除时使用 noindex
- 从较弱页面链接到权威页面

### 无操作
当一个页面应该从搜索结果中删除但仍存在供用户使用时。
- 确认该页面没有有意义的独特搜索需求或商业价值
- 保持其可爬行，直到观察到 noindex 指令
- 不要将其用作默认的重复内容修复方法

### 无建议
当意图尽管表面关键词相似但确实不同时。
- 记录未来审计的理由
- 每季度监控排名，查看任何位置变化
- 如果任一文章排名下降，重新评估

## 错误处理

- **未找到博客文件**：如果目录不包含 .md、.mdx 或 .html 文件，请报告 "在 [目录] 中未找到博客文件" 并建议检查路径
- **DataForSEO 凭证缺失**：在 API 模式下，如果凭证未配置，将自动回退到本地模式并通知用户
- **API 速率限制**：DataForSEO 有每分钟速率限制。如果收到 429 响应，请等待并重试一次。如果仍然存在，请切换到本地模式处理剩余的 URL
- **API 请求失败**：如果 DataForSEO 返回错误，请在速率限制内重试一次。如果仍然失败，请切换到本地模式处理剩余的 URL 并报告失败的端点而无需凭证
- **单篇文章目录**：如果只有一个博客文章，请报告 "同化分析至少需要 2 篇文章" 并优雅地退出
