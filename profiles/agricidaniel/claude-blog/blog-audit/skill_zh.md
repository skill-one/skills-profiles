# 博客审核：全站健康评估

对项目中的所有博客文章进行全面健康评估。
扫描质量评分、孤立页面、主题竞争、过时内容和AI引用准备情况。
使用规范分析器JSON作为评分来源，并生成优先级行动队列。

## 审核流程

### 第一步：发现博客文件

扫描项目中所有博客内容文件：

- 递归地在常见的博客目录和CMS导出文件夹中查找`.md`、`.mdx`、`.html`、`.astro`、`.svelte`、`.vue`、`.tsx`和`.jsx`：
- 常见路径检查：
  - `content/`
  - `posts/`
  - `blog/`
  - `src/content/`
  - `_posts/`
  - `pages/blog/`
  - `articles/`
  - `content/blog/**`
  - 用户明确提供的CMS导出文件夹
  - `src/pages/blog/`
- 过滤隐藏、供应商、生成和与秘密相关的路径：`.git/`、点目录、`node_modules/`、`vendor/`、`dist/`、`build/`、`.next/`、`coverage/`、`reports/`、生成导出、README、CHANGELOG、LICENSE、配置文件、SKILL.md、包文件、`.env*`、密钥和私人笔记
- 报告："在[目录]中找到N个博客文件"

如果在标准位置未找到博客文件，则请求允许的根目录或仅搜索用户批准的内容目录。默认情况下，不要扫描整个项目根目录。

### 第二步：规范批量分析

首先运行规范分析器输出，并将其作为每篇文章评分的来源：

```bash
python3 scripts/analyze_blog.py <blog-root> --batch --format json
```

分块处理文件，限制并行后续工作为固定的小数量，尊重上下文限制，并聚合确定性JSON，包含`file`、`score`、`categories`、`issues`和`metadata`。在下面的全站检查之上叠加分析器JSON，而不是单独的评分标准。

#### 内容质量层
- 根据内容质量30分制对每篇文章进行评分
- 在上下文中审查段落和句子的节奏；长度是描述性的，不是通用的通过/失败阈值
- 评估标题结构和问答式标题
- 使用角色和内容类型评估可读性：消费者内容倾向于较简单的级别，专业内容可以是中等的，技术内容在保持清晰度时可能更密集

#### SEO优化层
- 按文章检查页面SEO元素：
  - 标题标签长度（40-60可接受，50-60理想，仅预览警告）
  - 元描述简洁且特定于页面。统计数据是可选的，必须可见且来源可靠
  - H1存在性和唯一性
  - 图片替代文本覆盖率
  - 内部和外部链接数量
  - URL别名质量

#### 规范验证层
- 在所有文章中检测结构化数据
- 验证Article/BlogPosting、Person、Organization和BreadcrumbList规范的完整性
- 如果存在FAQPage，则将其作为可选实体标记进行验证，而不是Google丰富结果
- 规范化`dateModified`、`lastUpdated`、`updated`和`lastmod`，包括时区规范化的生成规范，然后要求新鲜度一致性
- 标记缺失或格式错误的规范

#### 链接健康层
- 映射所有文章中的内部链接
- 构建有向链接图
- 检测孤立页面（零内部入站链接）
- 检测死端页面（零内部出站链接）
- 检查损坏的内部链接目标
- 推荐双向链接机会

#### 新鲜度检查层
- 从每篇文章的前置字段中读取`lastUpdated`或`dateModified`
- 计算自上次更新以来的天数
- 根据内容类型、来源或统计数据年龄和GSC衰减标记新鲜度，而不是通过通用天数计数
- 按刷新优先级分类

#### AI准备层
- 对每篇文章的AI引用准备情况进行评分
- 检查重要部分是否自包含且有证据支持
- 评估目的匹配和实体清晰度；问答标题和FAQ是可选的
- 检查摘要和结构化格式是否有助于目标读者
- 检查robots.txt、llms.txt、SSR/SSG输出、JS门控内容、阻止的资产、GPTBot、ClaudeBot、PerplexityBot、Googlebot、Google-Extended策略

### 第二步.5：技术抓取和搜索性能

在最终建议之前添加全站技术检查：

- 验证站点地图覆盖率、robots.txt、noindex指令、规范标签、重定向、HTTP状态代码、hreflang和内部规范一致性
- 在可用时使用`blog-google`进行核心网络指标、GSC查询、URL检查、索引状态和GA4上下文
- 报告跳过可选检查的原因，例如`SKIPPED: 凭据不可用`

### 第三步：主题竞争检测

跨所有文章分析关键词竞争：

1. 从每篇文章中提取主要关键词/主题：
   - 标题文本
   - H1标题
   - 元描述
   - 第一段
2. 使用停用词处理、词元化、区域感知和意图修饰符规范化关键词
3. 使用分析器数据、嵌入或显式置信度、可用时的GSC查询到URL数据以及可用的SERP重叠进行意图聚类
4. 使用以下建议之一标记竞争文章：
   - **合并**：将两个弱文章合并为一个强文章
   - **重定向**：301重定向较弱的文章到较强的文章，同时保留反向链接、验证重定向映射并更新内部链接
   - **区分**：调整焦点，使文章针对不同的意图

### 第四步：孤立页面检测

构建和分析内部链接图：

1. 对抗站点配置和站点地图规范化URL，包括相对链接、同域绝对路径、尾随斜杠、生成路由、锚点、别名映射
2. 构建邻接映射：`{ 页面 -> [它链接到的页面] }`
3. 构建反向映射：`{ 页面 -> [链接到它的页面] }`
4. 识别孤立页面：具有零内部入站链接的文章
5. 识别死端页面：具有零内部出站链接的文章
6. 对于每个孤立页面，根据主题相关性推荐2-3个现有文章应链接到它

### 第五步：过时内容检测

跨所有文章审计内容新鲜度：

1. 读取前置字段：`lastUpdated`、`dateModified`、`date`、`updated`
2. 计算每篇文章自上次更新以来的天数
3. 按刷新优先级分类：
   - **高**：易变主题、过时来源或统计数据或GSC衰减
   - **中**：常青主题，但示例、链接或截图正在老化
   - **低**：最近验证或稳定参考内容
4. 估计每篇文章的刷新工作量：
   - 轻度刷新：更新统计数据，检查链接（1-2小时）
   - 中度刷新：重写部分，添加新数据（3-4小时）
   - 重度刷新：建议全面重写（5+小时）

### 第六步：生成全站报告

将所有结果汇总为综合报告：

#### 摘要仪表板
```

**审核日期：** [日期]
**总文章数：** N

| 评分<50（差）的文章 | N |
| 孤立页面 | N |
| 死端页面 | N |
| 主题竞争问题 | N |

```

#### 每篇文章表格

### 第七步：保存报告

在`reports/`下保存带时间戳的Markdown和JSON导出，例如`reports/blog-audit-YYYY-MM-DD.md`和`reports/blog-audit-YYYY-MM-DD.json`。不要覆盖以前的审核报告。

保存后，通知用户：
- 报告位置：`[项目根目录]/reports/blog-audit-YYYY-MM-DD.md`和`[项目根目录]/reports/blog-audit-YYYY-MM-DD.json`
- 发现摘要（总文章数、平均评分、关键问题数量）
- 建议首先在最低评分的文章上运行`/blog analyze <文件>`
- 建议在关键文章上运行`/blog flow optimize`进行AI引用SEO检查
