# 博客重写器：优化现有文章

重写并优化现有的博客文章，以实现双重排名：谷歌搜索和人工智能引用平台。在应用优化六支柱的同时，保留作者的声音。

**关键参考：**
- `skills/blog/references/quality-scoring.md` - 5类评分（内容30，SEO 25，E-E-A-T 15，技术15，AI引用15）
- `skills/blog/references/eeat-signals.md` - 经验、专长、权威、信任标记
- `skills/blog/references/internal-linking.md` - 链接策略和锚文本规则
- `skills/blog/references/visual-media.md` - 图片来源和图表样式
- `skills/blog/references/synthesis-contract.md` - 6 LAWs用于重写期间的引用卫生（v1.8.0；跨技能参考存在于协调器的参考目录中）
- `skills/blog/references/research-quality.md` - 跨源聚类用于替换统计数据研究（v1.8.0）

## 跨参考

对于21个证据导向的优化提示（质量后续跟进、CTR审核、模式、PAA重写、技术审核、ChatGPT可见性），这些提示直接适用于重写工作，请参阅`/blog flow optimize`。

## 工作流程

### 第一阶段：审核（只读）

1. **阅读博客文章** - 检测格式（MDX、markdown、HTML）
2. **运行质量清单**，参考`skills/blog/references/quality-scoring.md`：
   - 统计虚构与来源统计数据
   - 检查答案优先格式（H2 -> 第一句话中的统计数据？）
   - 统计图片和图表（类型多样性？）
   - 在上下文中审查段落节奏；仅将记录长度作为描述性辅助
   - 检查标题层次结构（H1 -> H2 -> H3，无跳过？）
   - 检查模式的存在和有效性，优先考虑Article/BlogPosting、Person、Organization和BreadcrumbList；FAQPage仅作为可选实体标记
   - 检查新鲜度信号（lastUpdated、dateModified）
   - 评估自我推广水平
   - 评估引用层级质量
3. **建议性编辑风格扫描**：
   - **句子长度变化** - 当节奏需要审查时，描述性地报告。它不能确定作者身份，且没有通过/失败阈值。
   - **已知AI短语扫描** - 检查这些高频AI短语：
     - "在当今的数字景观中"、"重要的是要注意"、"深入探讨"
     - "变革者"、"导航景观"、"革命化"、"无缝"
     - "尖端"、"利用...的力量"、"利用"（作为动词）
     - "深入研究"、"关键的"、"提升"、"培养"、"景观"（过度使用）
     - "多方面的"、"强大的"、"织锦"、"启程"
     - 完整列表在`agents/blog-writer.md`
   - **词汇样本** - 描述性地报告类型-标记比（TTR），并根据文本长度和专业术语进行解释。
   - 从TTR、句子长度变化、标点符号或短语密度中估计AI作者身份。这些都是建议性的项目风格观察结果。
   - **二级结构反射扫描**（v1.8.0）- 上述一级检查是词汇级的。二级扫描审查可以经受简单措辞编辑的结构重复。针对`skills/blog/references/ai-slop-detection.md`运行。至少标记：
     - 不适合读者意图的重复问题节奏H2
     - 三个或更多"这里..."段落开头
     - 任何200字窗口中三个子句句子节奏超过50%
     - 任何20字跨度中超过2个回避词（"可能"、"经常"、"通常"、"通常"）
     - 对称列表膨胀（列表项词数标准差低于5）
     - 超过2个总结性修辞问题（"这对...意味着什么？"）
     - 超过一半的H2开头是过渡词
     - "关键见解是..."或"这里重要的是..."作为句子开头
     - 列表文章前列表介绍超过250字
     - 开头词重复：前三个首词超过25%份额
     - 段落形状标准差低于25（视觉单调性）
     应用编辑判断；这些指标不会改变分数或阻止交付。
4. **视频嵌入检查**：
   - 统计文章中的现有YouTube嵌入
   - 如果为0个嵌入，标记："没有视频嵌入。考虑在添加相关高质量YouTube嵌入时提供有用的上下文。"
   - 如果存在，检查：懒加载？aria-labels？noscript回退？VideoObject模式？
5. **同化检查**：
   - 从标题、H1和第一段确定文章的主要关键词
   - 在博客目录中搜索其他针对相同关键词的文章：
     - 跨所有博客文章抓取标题和元描述
     - 标记任何具有显著关键词重叠的文章
   - 如果发现同化，报告：
     - 哪些文章竞争相同的关键词
     - 建议：**合并**（合并成一个更强的文章）或**区分**（将一个文章转移到相关但不同的关键词）
6. **计算当前分数**，跨5个类别：
   - 5个类别的分数（内容质量30，SEO优化25，E-E-A-T信号15，技术元素15，AI引用准备15）
   - 总分：0-100
7. **呈现审核摘要**，包含具体发现、建议性诊断、视频状态、同化状态和分数
8. **进入计划模式** - 呈现按部分优化的计划

在继续之前等待用户批准。

### 第二阶段：研究

1. **从现有内容中确定博客的核心主题**
2. **查找替换统计数据**，用于任何虚构/未来源的数据：
   - 搜索：`[主题]研究2025 2026数据统计数据`
   - 仅针对1-3级来源
3. **查找图片**，如果文章少于3张：
   - 优先使用原始截图、产品视觉效果、图表或数据图形（如果可用）
   - 对于库存，使用官方提供者API，如Openverse、Unsplash、Pexels或Pixabay，以便捕获许可、创作者、来源URL和下载URL
   - 本地下载批准的资产，记录归属，并拒绝`javascript:`、`data:`和`file:` URL
   - 如果`blog-image`可用，提供AI生成以用于缺失或不足的图片，并记录选定的模型ID
4. **计划图表**，如果文章少于2张：
   - 确定适合可视化的数据
   - 选择多样化的图表类型

### 第三阶段：图表生成（内置）

当文章需要更多视觉元素时，调用`blog-chart`子技能：

1. 使用多样性规则选择图表类型（每篇文章不重复类型）
2. 传递：图表类型、标题、数据值、来源、平台格式
3. 直接在`<figure>`包装器内嵌入返回的SVG
4. 每篇2000字的文章目标2-4个图表

有关图表类型选择和样式规则的详细信息，请参阅`skills/blog/references/visual-media.md`。

### 第四阶段：内容重写

按以下顺序应用更改：

#### 4a. 保留有效部分
- 保留作者的声音和独特视角
- 保留原始见解和一手经验
- 保留现有质量图片和图表
- 维持内部链接

#### 4b. 修复前matter
- 仅当重写实质性改变了事实、方法或建议时才更新`lastUpdated`
- 保持原始`date`不变
- 修复元描述，使其准确且具体地总结可见内容
- 如果缺少，添加`coverImage` + `coverImageAlt` + `ogImage`
  - 在Pixabay/Unsplash/Pexels中搜索宽英雄图像（1200x630）
  - 或者通过`blog-chart`生成自定义SVG封面（文本在渐变上，带有关键统计数据）
  - 或者当可用时，通过`blog-image`子技能生成自定义AI图像；记录模型ID
- 验证标签/类别是否适当

#### 4c. 应用以目的为先的格式
在重要部分的开头说明其要点，然后添加每个声明所需的验证证据和上下文。不要强迫统计数据或词组。

#### 4d. 替换虚构统计数据
- 搜索模式："X%的..."、"X out of Y..."、未来源的声明
- 用来自1-3级来源的真实数据替换
- 给每个重要声明足够的证据来源以验证和解释它。包括发布者或文档详细信息、相关日期、方法、限制和一个稳定的URL，当声明需要它们时；不要强迫固定的引用形式。

#### 4e. 改进标题
- 根据读者意图使用问题或陈述性标题；没有比率目标
- 确保关键词自然出现在2-3个标题中

#### 4f. 修复段落长度
- 仅当这样做提高理解时才拆分段落
- 将段落长度用作可选的计划观察，而不是固定目标
- 确保每个段落从其最重要的句子开始

#### 4g. 添加视觉元素
- 在H2标题后嵌入新图片，均匀分布
- 在相关部分嵌入图表
- 如果`blog-image`可用：为缺少良好库存匹配的部分生成自定义图片，优先使用当前图像模型注册表，并记录模型ID
- 根据检测到的平台（MDX vs markdown vs HTML）调整嵌入格式

#### 4h. 添加视频嵌入
如果文章缺少YouTube视频嵌入：
- 使用来自`skills/blog/references/video-embeds.md`的质量标准搜索2-3个相关视频
- 使用平台适当的格式嵌入（srcdoc懒加载）
- 放置：介绍后1个，文章中间部分1-2个
- 为AI爬虫包含noscript回退

#### 4i. 添加/改进FAQ
- 如果查询集值得添加且不存在FAQ，则添加一个（3-5个问题）
- 如果FAQ存在，确保答案是完整的，并在需要时包含验证支持
- FAQPage仅作为可选实体标记。Google FAQ丰富结果已于2026-05-07对所有网站完全退役，因此不要将FAQPage作为核心Google丰富结果门。

#### 4j. 减少自我推广
- 最多1个品牌提及（仅在作者简介上下文中）
- 删除"At [Company], we..."模式
- 将促销部分转换为教育内容

#### 4k. 证据支持的解释
对于重要声明，生成或改进一个自包含的解释，包含足够的上下文和验证支持，可以独立存在。不要为每个H2填充解释。
- 自然地放置在部分正文中，而不是作为单独的调用

示例：
```markdown
[验证来源标题]，一个[方法或样本描述]在[日期]发布的[来源名称](https://example.com/full-report)，发现[具体指标]对于[受众或市场]([来源名称](https://example.com/full-report),检索YYYY-MM-DD)。从实际意义上讲，将证据与读者在提出声明或更改工作流程之前应采取的行动联系起来。
```

不要为了达到固定长度或仅仅为了赚取准备点而填充解释。

#### 4l. 项目声音和重复审查
仅在它们改进配置声音的地方应用这些转换：
- **消除em破折号** - 将每个U+2014字符替换为逗号、连字符、冒号或句号。如有必要，拆分句子。这是一个项目风格规则。
- **替换标记短语** - 用自然替代方案替换每个检测到的AI短语（来自第一阶段第3步的扫描）
  - "重要的是要注意" -> "值得注意"或"记在心里"
  - "在当今的数字景观中" -> "现在"或"[具体年份]"
  - "利用" -> "使用"、"应用"、"利用"
  - "深入研究" -> "查看"、"探索"、"深入研究"
  - "强大" -> "强"、"稳固"、"可靠"
  - "关键" -> "关键"、"必要"、"关键"（或重构句子）
- **故意变化句子长度** - 重写后，扫描每个段落。在较长的句子（18-25个词）之间注入简短的冲击性句子（5-10个词）。目标：不超过5个连续句子长度彼此相差5个词以内。
- **谨慎使用修辞问题** - 仅当它澄清读者下一步决策时才添加一个
- **自然使用缩写** - 将正式结构替换为听起来自然的缩写："it is" -> "it's"，"we have" -> "we've"，"do not" -> "don't"，"is not" -> "isn't"。
- **支持第一手语言** - 仅当方法、观察或证据可以证实声明时，保留"我们测试了"或"在我们的经验中"。

#### 4m. 摘要框（关键要点）
如果文章缺少摘要框，立即在介绍后添加一个：
```markdown
> **关键要点**
> - [带有统计和来源的核心发现]
> - [第二个关键见解或建议]
> - [第三个可操作的要点]
> (使用简洁的圆点，大小适合材料。保持摘要自包含，以便读者在不阅读整篇文章的情况下获得核心价值。)
```
默认标签是"关键要点"，但此标签可按角色或品牌声音配置（例如，"底线"、"快速摘要"、"您需要了解的"）。

如果现有的TL;DR框有用，将其转换为简洁的关键要点，并验证每个事实声明都得到支持。不要仅仅为了适应格式而添加统计数据。

#### 4n. 信息增益标记注入
审查文章，查找原创价值并标记它：
- `[原创数据]` - 作者亲自收集的专有数据、调查结果、实验或案例研究指标
- `[个人经验]` - 一手观察、经验教训
- `[独特见解]` - 新颖分析、反主流观点，有数据支持

如果文章缺少原创价值标记：
- 询问作者提供一手数据或经验以包含
- 至少添加连接现有研究的新方式的分析见解
- 目标：每篇文章至少2-3个标记

根据文章风格使用HTML注释（`<!-- [原创数据] -->`）或可见调用。

### 第五阶段：验证

重写后，验证所有质量门通过：

#### 核心质量门
1. 重要声明清晰陈述其要点，并在需要时包含验证支持
2. 段落和句子节奏适合受众；长度本身不能导致审核失败
3. 没有虚构统计数据
4. 标题层次结构清晰
5. 文章优先级模式存在且有效；仅当作为可选实体标记有用时才使用FAQPage
6. 图片具有描述性alt文本
7. 前matter中存在封面图片（coverImage + ogImage）
8. 如果MDX：构建项目以验证没有编译错误

#### 新元素验证
9. 可选摘要有用且不包含不受支持的声明
10. 任何信息增益标记识别支持原创材料
11. 重要可重用声明是自包含的，并有证据支持
12. 内部链接区域标记或实际链接存在（每2000字5-10个）
13. 配置的项目风格列表术语在上下文中审查

#### 编辑风格检查
14. 描述性地审查句子长度变化，不提供作者身份裁决
15. 在整个文档中自然使用缩写
16. 仅在有用时使用修辞问题
17. 没有不受支持的第一手声明
18. 与第一阶段审核相比，所有5个类别分数均提高
19. YouTube视频嵌入存在，带有懒加载、aria-labels和noscript回退

## 第五阶段.5：交付合同执行（v1.9.0）

在呈现重写草稿之前，根据`skills/blog/references/blog-delivery-contract.md`运行5门交付合同。合同适用于重写，就像它适用于新文章一样：用户永远不会是第一个审查者。

步骤：

1. **英雄检查**：如果现有文章已经有一个引用且仍在磁盘上的英雄图像，则保留它。如果重写实质性地改变了主题，或者英雄丢失，则通过`python3 scripts/generate_hero.py --topic "<新标题>" --tags "<标签>" --out <文件夹>`重新生成。
2. **重新渲染**：运行`python3 scripts/blog_render.py --md <slug>.md --out-dir <文件夹>`以刷新`.html`和`.pdf`来自更新的`.md`。
3. **审查者派遣**：将`blog-reviewer`代理针对渲染的`.html`。阈值：分数90/100或更高，且P0问题为0。
4. **预检**：运行`python3 scripts/blog_preflight.py --draft <文件夹> --strict`。退出0 = 发送；退出1 = 阻止。
5. **失败迭代**：最多3次迭代。在第3次失败后，停止并呈现`<文件夹>/preflight-report.json`中的诊断。

重写具有更高的隐含阈值，因为现有的草稿可能已经发布。重新呈现比原始版本更差的内容是不可接受的。如果重写分数低于原始分数，这本身就是一个P0条件。

## 更新模式

当作为`/blog update <file>`调用时，专注于新鲜度：
1. 更新统计数据到最新可用数据（2025-2026）
2. 添加自上次更新以来的新进展
3. 如果图片超过1年旧，则刷新图片
4. 在前matter中更新`lastUpdated`
5. 保留现有结构 - 最小化重写
6. 目标：仅真实新鲜度。替换过时的统计数据，添加真实的新进展，并更新`lastUpdated`/`dateModified`；不要重写以达到百分比变化阈值。
