# 内容质量与E-E-A-T分析

## Google的"谁/如何/为何"测试（规范启发式方法）

在评分E-E-A-T子因素之前，每个页面审核都应通过来自有用内容指南的Google自己的三个问题启发式方法：

| 问题 | 要寻找的内容 |
|---|---|
| **谁**创造了它？ | 可见的署名、作者简介页面、专业资质。在读者期望的地方是必需的；对于YMVL来说是非协商的。 |
| **如何**创造的？ | 在读者合理会询问的地方披露过程，特别是对于AI辅助内容。原始研究/一手证据/生活经验。 |
| **为何**存在？ | "为了帮助人们"，而不是"为了吸引搜索点击"。注意没有专业知识的小众入口、为了新鲜度信号的内容更新、为了字数目标而编写的内容。 |

主要来源：
https://developers.google.com/search/docs/fundamentals/creating-helpful-content

当所有三个答案都较弱时，该页面在核心排名系统的有用性信号下存在风险（以前是独立的"有用内容系统"，在2024年3月更新中合并到核心中）。

## E-E-A-T框架（2025年9月更新QRG）

阅读`${CLAUDE_PLUGIN_ROOT}/skills/seo/references/eeat-framework.md`以获取完整标准。

### 经验（一手信号）
- 原始研究、案例研究、前后结果
- 个人轶事、过程记录
- 独特数据、专有见解
- 直接经验的照片/视频

### 专业知识
- 作者资质、认证、简介
- 与主题相关的职业背景
- 适合受众的技术深度
- 准确、有据可查的声明

### 权威性
- 外部引用、来自权威来源的回链
- 品牌提及、行业认可
- 发表在公认的媒体上
- 被其他专家引用

### 可信度
- 联系方式、实际地址
- 隐私政策、服务条款
- 客户评价、评论
- 日期戳、透明的更正
- 安全网站（HTTPS）

## 内容指标

### 字数分析
与页面类型最低要求进行比较：
| 页面类型 | 最低 |
|-----------|---------|
| 首页 | 500 |
| 服务页面 | 800 |
| 博客文章 | 1,500 |
| 产品页面 | 300+（复杂产品400+） |
| 地点页面 | 500-600 |

> **重要提示**：这些是**主题覆盖的底线**，不是目标。Google已确认字数**不是**直接的排名因素。目标是全面的主题覆盖；一个500字的页面如果彻底回答了查询，将胜过一个没有的2,000字页面。将这些用作足够的覆盖深度的指南，而不是僵化的要求。

### 可读性
- Flesch阅读易度：目标为一般受众60-70

> **注意**：Flesch阅读易度是内容可访问性的有用代理，但**不是**直接的Google排名因素。John Mueller已确认Google不使用基本可读性分数进行排名。Yoast在v19.3中不再优先考虑Flesch分数。将可读性分析用作内容质量指标，而不是直接优化的SEO指标。
- 年级水平：匹配目标受众
- 句子长度：平均15-20个词
- 段落长度：2-4个句子

### 关键词优化
- 主要关键词在标题、H1、前100个词中
- 自然密度（1-3%）
- 语义变体存在
- 没有关键词堆砌

### 内容结构
- 逻辑标题层次结构（H1 -> H2 -> H3）
- 可扫描的章节和描述性标题
- 在适当的地方使用项目符号/编号列表
- 长格式内容的目录

### 多媒体
- 相关图像带有正确的alt文本
- 在适当的地方使用视频
- 使用信息图表表示复杂数据
- 使用图表/图形表示统计数据

### 内部链接
- 每1000字3-5个相关的内部链接
- 描述性锚文本
- 链接到相关内容
- 没有孤儿页面

### 外部链接
- 引用权威来源
- 在新标签页中打开以提升用户体验
- 合理的数量（不是过度）

## AI内容评估（QRG：生成式AI指南于2025年1月添加；当前版本为2025年9月11日）

Google的评估者评估低质量、规模化、复制或AI生成的主体内容模式，而不是将AI作者身份作为单独问题。

### 可接受的AI内容
- 展示真实的E-E-A-T
- 提供独特价值
- 有人类监督和编辑
- 包含原创见解

### 低质量AI内容标志
- 通用短语、缺乏具体性
- 没有原创见解
- 页面之间重复结构
- 没有作者归因
- 事实错误

> **有用内容系统（2024年3月）**：有用内容系统在2024年3月核心更新中合并到Google的核心排名算法中。它不再作为独立的分类器运行。有用性信号现在在每个核心更新中都有权重。相同的原理适用（以人为中心的内容、展示E-E-A-T、满足用户意图），但执行是持续的，而不是通过单独的HCU更新。Google现在还记录**在主要更新之间持续、未宣布的核心更新**（日志2025-12-09）。

> **Gen-AI优化是SEO（Google文档，2026年6月29日）**：官方"针对生成式AI功能进行优化"指南指出，您**不需要**新的AI文件、标记、Markdown、内容分段或AI特定的重写；追逐不真实的"提及"是无益的。AEO/GEO被重新命名为基于核心排名/质量的SEO。

> **诚实范围（Google文档，2026年6月5日）**：根据"使用第三方SEO工具、服务和建议"，没有工具保证排名，第三方工具无法访问Google的内部排名数据。claude-seo的分数是**启发式方法**，不是Google内部信号，因此在报告中要说明，并对照Google的官方指南（Search Console是第一方来源）验证GEO/AEO发现。

## 草稿清理：AI措辞与隐形水印

对于"使其更像人类"、"移除水印"或"清理草稿"，在用户自己的内容上运行捆绑的清理脚本：

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run content_humanize.py draft.md -o cleaned.md
cat draft.md | "${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run content_humanize.py --json
```

两次确定性传递，都在JSON输出中记录：

1. **隐形字符**（`invisible_removed`）：删除零宽度代码点、方向标记/覆盖、Unicode标签字符（隐藏文本走私）并规范化异国情调的空间。表情符号序列（ZWJ、表情符号旁边的变异选择器）被保留。
2. **AI典型措辞**（`changes`）：保守的1:1替换来自替换表（"深入研究"→"探索"等）。没有内容被释义或添加。

范围诚实：统计水印（SynthID风格的令牌概率方案）存在于用词中，而不是代码点。没有工具可以可靠地检测或移除它们；在报告中不要声称如此。此清理是用于编辑用户的草稿，而不是用于漂白第三方内容——拒绝从用户不拥有的内容中移除来源的请求。

## AI引用准备（GEO信号）

针对AI搜索引擎（ChatGPT、Perplexity、Google AI概述）进行优化：

- 清晰、可引用的陈述，包含统计数据/事实
- 结构化数据（尤其是数据点）
- 强大的标题层次结构（H1->H2->H3流程）
- 针对关键问题的先回答格式
- 表格和列表用于比较数据
- 清晰的归因和来源引用

### AI搜索可见性与GEO（2025-2026）

**Google AI模式**是Google的对话式AI搜索界面。Google经常升级AI模式模型（Gemini 3.5 Flash于2026年5月19日成为默认值，并且自那时以来已交付了更新的Flash模型，根据博客.google）；永远不要将建议与模型版本绑定。将第三方AI模式使用、引用和链接共享数据视为方法相关的，除非有主要来源，并针对AI模式和AI概述进行优化（见`seo-geo`技能）。

**AI引用的关键优化策略：**
- **结构化答案**：清晰的问题-答案格式、定义模式以及AI系统可以提取和引用的逐步说明
- **第一方数据**：原始研究、统计数据、案例研究和独特数据集被AI系统高度引用
- **模式标记**：文章和其他相关结构化内容。FAQPage不再产生Google FAQ丰富结果；仅当适当且为真实的用户问答时才使用QAPage
- **主题权威性**：AI系统优先引用展示深度专业知识的来源。构建内容集群，而不是孤立页面
- **实体清晰度**：确保品牌、作者和关键概念通过结构化数据（组织、人物模式）清晰定义
- **多平台跟踪**：跨Google AI概述、AI模式、ChatGPT、Perplexity和Bing Copilot监控可见性，而不仅仅是传统排名。将AI引用视为与有机排名和流量并列的独立KPI。

**生成式引擎优化（GEO）：**
根据Google的AI优化指南，"针对生成式AI搜索进行优化就是优化搜索体验，因此仍然是SEO"：AI概述和AI模式基于与经典搜索相同的排名和质量系统。重要的优化信号（可引用性、归因、标题层次结构、新鲜度）是应用于AI搜索界面的SEO基础，而不是一个独立的学科。参考`seo-geo`技能获取详细工作流程；两个界面共享主要来源合成`${CLAUDE_PLUGIN_ROOT}/skills/seo-geo/references/google-ai-optimization-guide.md`。

## 错误处理

| 情景 | 操作 |
|----------|--------|
| URL无法访问（DNS故障、连接拒绝） | 清晰地报告错误。不要猜测页面内容。建议用户验证URL并重试。 |
| 内容在付费墙后（402/403、登录墙） | 报告内容无法公开访问。仅分析可见部分（元标签、标题）并注明限制。 |
| 薄内容（检索到的字数少于100） | 如实报告发现结果，而不是猜测。将页面标记为可能由JavaScript渲染或受限制，并建议用户提供全文。 |
