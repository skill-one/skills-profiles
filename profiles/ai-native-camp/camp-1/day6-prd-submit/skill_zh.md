# 第 6 天：PRD 编写 & PR 提交

基于模板编写 PRD(Product Requirements Document) 草稿，验证必要格式后，引导 GitHub PR 提交流程。

---

## 术语解释

本技能中使用的关键术语：

| 术语 | 说明 |
|------|------|
| **PRD** | Product Requirements Document. "这个项目要解决什么问题，要做什么" 的整理文档 |
| **GitHub** | 一起管理代码和文档的在线服务。Google Docs 的代码版本 |
| **GitHub ID** | 在 GitHub 网站上用于标识我的名称。在 `github.com/这里` 的最后部分（github.com/这里） |
| **Repository (Repo)** | 项目文件所在的文件夹。类似于 Google Drive 的共享文件夹 |
| **分支(Branch)** | 不修改原版，单独创建我的工作空间。类似于 "另存为副本" |
| **提交(Commit)** | 保存更改。Ctrl+S 的 Git 版本 |
| **推送(Push)** | 将本地计算机上保存的内容上传到在线(GitHub) |
| **PR (Pull Request)** | 向运营人员发送 "请确认我的工作" 的审核请求。与提交按钮相同 |
| **gh CLI** | 可以在终端中操作 GitHub 的工具 |

---

## 前置要求

本技能假定以下环境已准备就绪。Step 0 会进行自动检查。

- 需要安装 `git`
- 需要安装并认证 `gh` CLI
- 目标 repo 已克隆
- repo 中有推送权限（协作者）

|------|------|-----------|
| 0 | 环境检查 | ~1 分钟 |
| 1 | GitHub ID 确认 | ~1 分钟 |
| 2 | PRD 编写 + 验证 | ~10 分钟 |

## PRD 模板

```markdown
# [项目标题]

## 问题
> 一句话：为谁，解决什么不便，如何解决

- **当前状态**： (具体数字 - 如多少个，多少分钟，多少人)
- **期望状态**： (一周后看到的样子)
- **成功标准**： (可以用数字衡量的 1~2 个)

## 技能
| # | 技能名 | 一句话说明 | 状态 |
|---|--------|-----------|------|
| 1 | `/my-skill-1` | 输入 → 输出 | ✅ 已运行 / 🔨 进行中 |
| 2 | `/my-skill-2` | 输入 → 输出 | ✅ 已运行 / 🔨 进行中 |

## 变更记录
- **Day 1**: "最初定义" →
- **Day 6**: "当前定义" →
- **最大变化点**:
```

## 执行流程

```
Step 0           Step 1           Step 2          Step 3
环境检查 →  GitHub ID 确认 → PRD 编写/验证 → 提交 (git + PR)
```

### Step 0: 环境预检查

技能开始时 **在开始前** 会自动检查以下内容:

```bash
git --version
gh --version
gh auth status
git remote -v
```

将结果展示给参与者:

```
=== 环境检查 ===
✅ git: 已安装
✅ gh CLI: 已安装
✅ GitHub 登录: 完成 (用户: {detected-id})
✅ 项目文件夹: 已连接 ({repo-url})

环境准备完成！
```

**如果任何一项失败**，会指导解决方法，解决后重新检查。直到所有项目通过才进行下一步。

| 失败项目 | 指导 |
|----------|------|
| git 未安装 | "git 未安装。请向运营人员寻求帮助。" |
| gh CLI 未安装 | "输入 `brew install gh` 到终端。(macOS 为例)。失败时请呼叫运营人员。" |
| gh 未认证 | "输入 `gh auth login` 并按照提示操作。使用 GitHub 账户登录即可。" |
| repo 连接失败 | "您还没有将项目下载到本地计算机。请在终端中输入: `gh repo clone {owner/repo}`" |

### Step 1: GitHub ID 确认

在 Step 0 中通过 `gh auth status` 检测到的 GitHub ID 会展示并确认:

```
AskUserQuestion: "GitHub 用户名是 '{detected-id}' 对吗？"
- 是，正确
- 不是，其他 ID (直接输入)
```

**ID 格式验证**: 确认输入的 ID 仅包含英文字母、数字和连字符(`-`)。如果包含特殊字符、空格、斜杠等，会指导后重新输入。

输入的 ID 会被转换为小写。

这个 ID 将用于后续的文件路径和分支名:
- 文件: `{github-id}/PRD.md`
- 分支: `prd/{github-id}`

### Step 2: PRD 编写或验证

通过 AskUserQuestion 询问当前状态:

| 选择项 | 动作 |
|--------|------|
| 新建 PRD | Step 2-A: 基于模板的编写指南 |
| 验证现有 PRD | Step 2-B: 验证现有文件 |

#### Step 2-A: PRD 编写指南

1. 展示上述 PRD 模板
2. AskUserQuestion 询问项目主题:

```
"要编写哪个项目的 PRD？"
- 活动中制作的技能 (本周制作的技能作为项目发展)
- 工作自动化想法 (实际工作中想要自动化的东西)
- 直接输入
```

选择 "活动中制作的技能" 会扫描 `.claude/skills/` 目录，展示参与者制作的技能列表供选择。

3. 基于参与者的回答生成 PRD 草稿

4. 在终端中输出草稿，并通过 AskUserQuestion:

| 选择项 | 动作 |
|--------|------|
| 继续进行 | 保存到 `{github-id}/PRD.md` 后进入 Step 2-B |
| 想修改 | 询问想修改哪部分 (问题定义 / 技能列表 / 变更记录) 并应用后再次输出 |

5. **重要**: PRD 内容应反映参与者的实际经验和项目。应包含活动中制作的技能、实际工作问题，而不是通用示例。

#### Step 2-B: PRD 格式验证

读取 `{github-id}/PRD.md` 文件，并使用以下检查清单进行验证。

### 检查清单

| # | 项目 | 验证方法 | 必须项 |
|---|------|----------|------|
| 1 | 项目标题 | 以 `#` 开头的第一行 (大标题) 是否存在 | 必须项 |
| 2 | 问题部分 | 是否存在 `## 问题` 标题 | 必须项 |
| 3 | 当前状态 | 是否存在 "当前状态" 文本且长度 ≥ 10 字符 | 必须项 |
| 4 | 期望状态 | 是否存在 "期望状态" 文本且长度 ≥ 10 字符 | 必须项 |
| 5 | 成功标准 | 是否存在 "成功标准" 文本且长度 ≥ 10 字符 | 必须项 |
| 6 | 技能部分 | 是否存在 `## 技能` 标题 | 必须项 |
| 7 | 至少 2 个技能 | 技能表格中是否存在以 `| 1 |`、`| 2 |` 等编号开始的行 (不包括表头行、分隔线) | 必须项 |
| 8 | 变更记录 | 是否存在 `## 变更记录` 标题 | 必须项 |

### 检查结果输出

```
=== PRD 格式检查结果 ===

[PASS] 或 [需要改进]

✅ 项目标题: 存在
✅ 问题部分: 存在
✅ 当前状态: 存在
✅ 期望状态: 存在
✅ 成功标准: 存在
✅ 技能部分: 存在
✅ 至少 2 个技能: 存在 (N 个)
✅ 变更记录: 存在

结果: 8/8 通过 → PASS
```

需要改进时，会具体指导缺失的项目:

```
❌ 成功标准: 内容太短。请包含具体的数字。
   示例) "每周使用 3 次，每笔处理时间 30 分钟 → 5 分钟"
```

### Step 3: 提交 (git + PR)

验证通过后，通过 AskUserQuestion:

```
"PRD 检查通过！要提交到 GitHub 吗？"
- 是，请提交 (推荐)
- 稍后提交
```

选择 "稍后提交" 时: "准备好后请再次运行此技能。" 指导后结束。

选择 "是，请提交" 时，执行以下操作。每个步骤都会输出韩文进度状态:

```
[1/5] 正在同步到最新状态...
```
```bash
git checkout main && git pull origin main
```

```
[2/5] 正在创建提交空间...
```
```bash
git checkout -b prd/{github-id}
```
> 如果分支已存在，使用 `git checkout prd/{github-id}` 切换。

```
[3/5] 正在注册 PRD 文件...
```
```bash
git add {github-id}/PRD.md
```
> 使用 `git status` 确认 staging 的文件只有 `{github-id}/PRD.md` 1 个。如果包含其他文件，请 unstage 该文件。

```
[4/5] 正在保存...
```
```bash
git commit -m "feat: {github-id} PRD 草稿提交"
```

```
[5/5] 正在上传到 GitHub...
```
```bash
git push origin prd/{github-id}
```

push 完成后，使用 gh CLI 创建 PR:

```bash
gh pr create --repo {owner/repo} --title "PRD: {github-id}" --body "$(cat <<'EOF'
## PRD 草稿提交

- 作者: {github-id}
- 文件: {github-id}/PRD.md

检查结果: PASS (8/8)
EOF
)"
```

输出 PR URL 并指导完成。

## 错误处理

| 情况 | 响应 |
|------|------|
| git 未安装 | "git 未安装。请向运营人员寻求帮助。" |
| gh CLI 未安装 | "输入 `brew install gh`。失败时请呼叫运营人员。" |
| gh 未认证 | "输入 `gh auth login` 并使用 GitHub 账户登录。" |
| PRD.md 文件不存在 | "PRD 文件尚未存在。先编写吗？" |
| 检查需要改进 | 缺失项目 + 具体示例指导 + 提供修改帮助 |
| git 分支已存在 | 自动切换到现有分支 |
| push 失败 (认证) | "需要 GitHub 登录。请运行 `gh auth login`。" |
| push 失败 (权限) | "您没有向该项目提交的权限。请在 Slack 中向运营人员 (@zoon) 发送消息 '需要权限'。" |
| repo 未克隆 | "请先下载项目。在终端中输入 `gh repo clone {owner/repo}`。" |
| GitHub ID 格式错误 | "GitHub ID 只能包含英文字母、数字和连字符 (-)。" |
