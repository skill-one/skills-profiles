# Bitbucket CLI (`bkt`)

使用 `bkt` 进行 Bitbucket Cloud 和 Data Center 的操作。为自动化优先选择结构化的 `--json`、`--yaml`、`--jq` 或 `--template` 输出。

## 从所需操作开始

仅在安装或兼容性不确定时运行 `bkt --version`。当命令需要认证或活跃平台和上下文未知时，运行 `bkt auth status`。不要将设置作为已配置的只读请求的先决条件。

云和 Data Center 具有不同的功能集。根据活跃上下文确定平台，或在无法推断时询问。不要为 Data Center 建议仅适用于 Cloud 的命令，反之亦然。

安装、认证、创建上下文或学习主要命令模式时，请阅读 [设置和常见工作流](rules/guide.md)。对于无配置的 CI 或容器，请阅读 [无头认证](rules/headless.md)。

## 变更和凭证边界

- 列出、查看、状态和检查是只读的。创建、编辑、批准、合并、删除、重新运行或权限更改会修改 Bitbucket；仅在用户请求该更改时执行它们。
- 不要在可能进入日志或提交文件的命令中放置令牌、OAuth 密钥或密码。使用 auth 参考中描述的 CLI 支持的凭证流程或环境变量。
- 官方发布二进制文件嵌入 Cloud 浏览器-OAuth 消费者凭证。不要将其行为作为通用硬化移除。源和 Nix 构建可能需要 `BKT_OAUTH_CLIENT_ID` 和 `BKT_OAUTH_CLIENT_SECRET`。
- 在合并或其他结果性写入之前，检查确切的目标、仓库和当前检查。报告结果 URL 或标识符。
