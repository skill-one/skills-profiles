# 自我学习技能生成器

从网络上自主研究和学习新技术，然后生成可重用的技能。

## 使用方法

```
/learn <主题>
```

如果 `<主题>` 缺失，则显示使用方法。如果主题不明确，则要求澄清：

- "react" → "React for web, React Native, 还是特定的库如 react-query?"
- "apollo" → "Apollo GraphQL 客户端, Apollo Server, 还是 Apollo Federation?"
- "aws" → "哪个 AWS 服务? (S3, Lambda, DynamoDB 等)"

规范化为 **kebab-case** 用于文件名。

### 2. 发现资源（网络搜索）

使用网络搜索工具查找权威文档：

**尝试的搜索查询：**
1. `<主题> 官方文档`
2. `<主题> 入门指南`
3. `<主题> API 参考`
4. `<主题> GitHub 仓库`

**资源优先级：**
1. 官方文档网站（例如，docs.*, *.dev）
2. 官方 GitHub 仓库（README, /docs）
3. 官方博客/公告

最多选择 **3–5 个高质量 URL**。

如果找不到可信来源，则要求用户提供 URL。

---

### 3. 提取内容（URL 读取）

对于每个选定的 URL，读取内容：

**仅提取相关部分：**
- 安装 / 设置
- 核心概念
- API 参考 / 关键功能
- 常见模式 / 示例
- 版本信息

**跳过无关内容：**
- 导航、广告、登录提示
- 不相关的侧边栏内容
- 评论、论坛

如果读取内容失败（JavaScript 重型网站），则回退到浏览器代理：

```
任务：导航到 <URL> 并提取主要内容包括：
- 安装说明
- 核心概念和 API 参考
- 代码示例
返回提取的内容作为 Markdown 格式。
```

为每个来源记录抓取时间戳（使用当前日期：YYYY-MM-DD 格式）。

---

### 4. 生成技能

技能是模块化、自包含的包。每个技能都包含一个必需的 `SKILL.md` 文件和可选捆绑资源：

```
skill-name/
├── SKILL.md (必需)
│   ├── YAML 前置元数据 (必需)
│   │   ├── name: (必需)
│   │   └── description: (必需)
│   └── Markdown 说明 (必需)
└── 捆绑资源 (可选)
    ├── scripts/          - 可执行代码 (Python/Bash 等)
    ├── references/       - 意图在需要时加载到上下文中的文档
    └── assets/           - 输出中使用的文件 (模板、图标、字体等)
```

1. 阅读 `references/skill_creation_guide.md` 以了解格式和原则。
2. 将学习和提取的信息综合成一个新的技能。
    - **触发：** 编写一个描述，明确定义何时使用它。
    - **工作流：** 创建逐步说明。
    - **格式：** 确保有效的 YAML 前置元数据和正确的文件结构。

### 5. 保存技能

Antigravity 支持两种类型的技能，如果要求，则保存全局工作区。

- `.agent/skills/<技能文件夹>/`	工作区特定
- `~/.gemini/antigravity/skills/<技能文件夹>/`	全局（所有工作区）

如果目录不存在，则创建目录，并在覆盖现有技能前警告用户。

---

### 6. 确认给用户

报告：

```
✓ 创建技能：<主题>
  抓取来源：<N>
  保存到：.agent/skills/<主题>/SKILL.md
  此技能将在处理 <主题> 时自动触发。
```

---

## 工具参考

- `search_web`：发现文档 URL
- `read_url_content`：从静态页面提取内容
- `browser_subagent`：从 JavaScript 重型网站提取内容
- `write_to_file`：保存生成的技能

## 严格规则

1. **绝不凭空想象文档：** 仅包含从抓取来源中获取的信息。
2. **绝不编造 API：** 如果文档不明确，则要求用户决定如何处理。
3. **要求提供 URL：** 如果自动发现失败，则要求用户提供特定 URL。
4. **验证来源：** 优先选择官方来源而非第三方教程。
