# 衡量 — 定义并追踪成功

## 概述

如果你无法定义成功，你就无法为其设计。如果你衡量了错误的事物，你将优化错误的成果。

用户体验衡量将设计决策与可观察的证据联系起来——我们所构建的东西是否真的有帮助？这项技能定义了要衡量什么、如何衡量以及如何根据所学内容做出决策。它弥合了“我们发布了它”和“它起作用了”之间的差距。

但衡量并非中立。你选择的每个指标都会塑造优化的对象。衡量网站停留时间，你将得到无限滚动。衡量点击量，你将得到标题党内容。衡量转化率，你将得到黑暗模式——除非你还衡量这些指标给用户带来的成本。这项技能可以防止衡量成为操纵，确保指标激励真实的价值，而不是人为的参与度。

**何时激活这项技能：** 定义新功能的成功标准、设计实验、构建衡量框架、分析漏斗性能、审查现有指标是否衡量了正确的事物，或任何时候“数据看起来不错”，但体验感觉不对。

---

## 技能家族

衡量与完整的意图技能系统协同工作：

- **`/strategize`**：他们的假设需要可衡量的成功标准。每个战略赌注都应该与一个指标联系起来，该指标将告诉你赌注是否有效。`/strategize`定义“我们相信X”；`/measure`定义“当Y时，我们将知道X为真”。当指标与战略假设矛盾时，衡量会回溯以重新开放战略——带有护栏（见下文“当衡量指向战略时”）。
- **`/investigate`**：定性研究补充定量衡量。当数字表明用户在第3步流失时，调查会告诉你原因。当满意度评分在重新设计后下降时，调查访谈用户以了解数字背后的体验。永远不要仅凭指标做出重大设计决策。
- **`/evaluate`**：UX评估产生评分和发现，这些评分和发现会告知要衡量什么。评估识别可用性问题；衡量跟踪修复是否确实解决了这些问题。
- **`/specify`**：测试计划和成功指标进入交接规范。每个功能规范都应包括成功的样子以及如何衡量它，以便工程团队可以相应地进行仪器。
- **`/philosopher`**：一个跨领域的认知模式，用于在你将其变成目标之前质疑你的指标。调用时机：一个指标感觉太容易操纵、仪表板看起来是绿色的但用户在抱怨、你不确定是否在衡量用户成功或商业提取，或你需要这样的问题：“如果衡量这个改变了我们试图衡量的行为呢？”

## 核心能力

### 1. 指标选择：HEART框架

Google的HEART框架为选择UX指标提供了一个结构化方法。按功能应用，而不是全局应用——不同的功能需要不同的指标。

**快乐——主观满意度：**
- NPS（净推荐值）：推荐的可能性，0-10分制。直接但有用，用于趋势分析。
- CSAT（客户满意度）：对特定交互的满意度，通常为1-5分制。对于功能级别的决策比NPS更具可操作性。
- SUS（系统可用性量表）：10个问题的标准化可用性问卷。适用于跨版本基准测试。
- 自定义调查：与特定功能相关的特定问题。“找到你正在寻找的内容有多容易？”比“你对满意度如何？”更有用。

**参与度——行为深度：**
- 频率：用户返回的频率（每日、每周、每月活跃用户）
- 强度：每次会话的用法深度（使用的功能、消费的内容、采取的行动）
- 广度：用户接触的功能数量（采用广度，而不仅仅是深度）
- 近期性：上次交互时间（流失的早期预警）

**采用率——新用法：**
- 新用户激活：完成关键引导里程碑的百分比
- 功能采用率：有资格用户尝试新功能的百分比
- 引导完成率：通过首次使用体验的漏斗
- 价值实现时间：新用户达到第一个有意义的成果的速度

**留存率——持续使用：**
- 返回率：D1、D7、D30留存率（1、7、30天后返回的百分比）
- 流失率：一定时期内停止使用产品的用户百分比
- 重新激活：离开后又回来的用户（是什么让他们回来的？）
- 群组留存率：按注册群组的留存曲线（新用户留存得更好吗？）

**任务成功率——有效性：**
- 完成率：完成他们开始的任务的用户百分比
- 错误率：导致错误的尝试百分比
- 任务时间：完成任务所需时间（通常越短越好，但不总是这样）
- 效率：任务完成相对于最佳路径长度的完成情况

**并非每个功能都需要所有五个指标。** 选择对功能意图最重要的2-3个维度。结账流程最关心任务成功和快乐。内容源最关心参与度和留存。新功能发布最关心采用。

**反指标：** 对于你优化的每个指标，都要命名可能受损的指标。如果参与度上升但满意度下降，那就是一个危险信号。如果转化率提高但支持工单增加，则有问题。反指标是你的矿井中的金丝雀。

### 2. 目标-信号-指标映射

GSM框架防止你未经理解就跳转到指标。

**目标：** 你试图实现什么用户或商业成果？要具体。“改善用户体验”不是一个目标。“用户可以快速找到相关内容而无需过度浏览”是一个目标。

**信号：** 哪些可观察的用户行为将表明你正在朝着目标前进？这是意图和数据之间的桥梁。“用户直接导航到相关内容”是一个信号。“用户在网站上花费更多时间”不一定是成功的信号——这可能意味着他们迷路了。

**指标：** 你如何量化这个信号？具体的公式、数据源、测量频率和成功阈值。“80%百分位数的会话中内容点击次数少于3次，每周通过分析测量”是一个指标。

**GSM链示例：**
- 目标：用户可以无摩擦地完成结账
- 信号：用户在结账步骤中未放弃或返回
- 指标：添加商品到购物车的用户结账完成率 > 75%；结账中位数时间少于90秒；结账期间返回导航率 < 10%

**在发布前为每个主要功能构建GSM链。** 如果你无法表达目标，你就不知道成功看起来像什么。如果你无法确定信号，你就在猜测要衡量什么。如果你无法定义指标，你就不可能从你发布的内容中学习。

### 3. A/B测试设计

实验是学习设计更改是否真正有帮助的方法。但设计不良的实验会产生虚假的信心。

**假设结构：**
“如果我们[具体更改]，那么[具体指标]将[变化方向] [估计幅度]，因为[因果推理]。”

示例：“如果我们把搜索栏从页眉移动到英雄区域，那么搜索使用率将增加15%，因为用户将更早遇到它，减少了滚动到搜索的摩擦。”

**可检测的最小效果（MDE）：**
最小的变化值得检测是什么？转化率的0.1%改善可能不值得工程努力。5%的改善则值得。在测试之前，而不是之后设置MDE。这决定了你的所需样本量。

**样本量计算：**
取决于：基线转化率、MDE、统计功效（通常为80%）、显著性水平（通常为95% / alpha = 0.05）。不要猜测——使用公式或计算器。

**常见场景的快速参考**（双尾测试、80%功效、95%显著性、两个变体）：

| 基线率 | MDE（相对） | 每个变体的样本量 |
|---|---|---|
| 5% | 20%（5% → 6%） | ~25,000 |
| 10% | 10%（10% → 11%） | ~14,500 |
| 10% | 20%（10% → 12%） | ~3,800 |
| 25% | 10%（25% → 27.5%） | ~4,800 |
| 50% | 5%（50% → 52.5%） | ~6,000 |

较低的基线率和较小的MDE需要大量流量。如果你的所需样本量超过你的月流量，那么要么增加MDE（只检测较大的效果），要么延长测试持续时间，要么接受A/B测试不是正确方法——使用定性研究。功效不足的测试会产生无结论的结果，浪费时间。

**持续时间：**
至少运行1-2个完整的周周期，以考虑周内效应。对于季节性业务，时间更长。即使你提前达到样本量，也不要运行少于一周——行为模式因日而异。

**细分：**
检查跨用户分段的差异效果：新用户与回访用户、移动与桌面、地理区域、计划类型。整体中性结果可能隐藏对某个分段有强烈正面效果，而对另一个分段有强烈负面效果。

**护栏指标：**
定义什么必须不会变得更糟。如果测试新的结账流程，护栏指标可能包括：每个用户的收入、支持工单量、退货率。如果测试变体提高了转化率但增加了退货率，则测试失败。

**常见错误：**
- 在测试达到统计显著性之前查看结果（夸大了假阳性率）
- 在不调整多重比较的情况下运行太多变体
- 忽略新颖性效应（新东西因为新而更多地被点击——等待效应稳定）
- 因为早期结果“看起来有决定性”而过早停止测试
- 当多个测试同时运行时不考虑交互效应
- 测试外观更改，而真正的问题是结构性问题

### 4. 漏斗分析

漏斗揭示了用户在期望流程中流失的地方。但价值不在于数字——在于理解原因。

**精确定义步骤：**
“添加到购物车”是点击按钮，还是确认添加？“结账”是开始支付表单，还是提交？不精确的步骤定义会产生误导性的转化率。将每个步骤定义为一个具体、可观察、无歧义的事件。

**测量每一步之间的转化率：**
步骤1 → 步骤2：有多少比例继续？有多少比例返回到上一步？有多少比例完全离开？每个转换都讲述了一个不同的故事。

**识别最大的流失点：**
专注于转化率最低的步骤转换。在“查看产品”和“添加到购物车”之间40%的流失与“输入支付”和“确认订单”之间40%的流失是不同的问题。

**按一切细分：**
用户类型（新用户与回访用户）、设备、流量来源、地理区域、一天中的时间、一周中的天数。聚合漏斗隐藏了信号。一个整体转化率为30%的漏斗可能对回访桌面用户转化率为50%，对新移动用户转化率为10%——两个完全不同的问题。

**与定性结合：**
当你找到流失点时，你知道用户在哪里遇到困难。为了了解为什么，与`/investigate`结合——会话录制、可用性测试、在摩擦点进行调查。没有上下文的数字会产生糟糕的干预措施。

**基准测试：**
比较不同时间段的漏斗（上一个发布是帮助还是伤害？）、不同分段（谁最困难？）以及谨慎地与行业基准比较（对于数量级检查有用，对于特定目标危险）。

### 5. 定性和定量三角测量

数字告诉你发生了什么。定性告诉你为什么。两者单独都不足以做出设计决策。

**何时三角测量：**
- 指标显示流失但不知道为什么 → 在摩擦点运行可用性会话
- 重设计后满意度评分下降 → 访谈用户以了解他们的体验发生了什么变化
- A/B测试显示没有统计差异 → 定性研究揭示两个变体都有相同的根本可用性问题
- 功能采用率低 → 是可发现性问题、有用性问题还是可用性问题？只有定性才能区分。

**如何三角测量：**
- 从定量开始以确定什么和在哪里
- 使用定性来理解为什么
- 返回定量以验证你的干预是否解决了为什么
- 重复

**永远不要仅凭一种数据类型做出重大设计决策。** 一个说“转化率提高了5%”的指标不会告诉你改进是否来自真实的价值创造，还是来自对替代路径增加摩擦。一个5人遇到困难的可用性测试不会告诉你这个问题有多普遍。两者结合起来才能告诉你一些真实的东西。

### 6. 伦理衡量

指标塑造行为——团队的行为、产品的行为和用户的行为。小心衡量。

**Goodhart定律：**
“当衡量成为目标时，它就不再是好衡量。”这不是一个理论问题。当团队被激励在网站停留时间上时，他们构建了无限滚动和自动播放。当他们被激励在注册上时，他们构建了欺骗性的注册墙。当他们被激励在参与度上时，他们构建了通知垃圾邮件。指标没有失败——指标变成了目标而不是目标的对立面。

**参与度不等于价值：**
高参与度可能表明成瘾，而不是满意度。每天检查手机200次的用户是参与的。他们也可能焦虑、分心和不开心。在参与度指标旁边包含满意度指标。如果参与度上升但满意度下降，你正在构建一个老虎机，而不是一个有用的产品。

**要警惕的黑暗指标模式：**
- 计算从预选框的“成功”新闻简报注册
- 衡量“参与度”来自烦人的通知，用户点击以关闭
- 庆祝实际上是取消摩擦的“留存”
- 报告由于误导性的按钮标签或紧急计时器而提高的“转化率”
- 追踪由混乱导航驱动的“网站停留时间”

**与Intent的反模式目录的关联：**
任何会因实施黑暗模式而改善的指标都在衡量错误的事物。在庆祝指标改善之前，问：是否可以通过黑暗模式实现这种改善？如果是，请验证这不是这样。

**伦理替代框架：**
与每个业务指标一起衡量用户满意度、任务完成率和努力程度。构建一个包含两列的衡量仪表板：业务成果和用户体验成果。如果业务指标改善而用户体验指标下降，那就是一个黑暗模式信号——即使没有人打算这样。

- 业务指标：转化率 → 配对用户体验指标：购买后满意度
- 业务指标：参与度（DAU）→ 配对用户体验指标：用户报告的价值
- 业务指标：留存率 → 配对用户体验指标：取消的容易程度
- 业务指标：每个用户的收入 → 配对用户体验指标：感知的性价比

## 当衡量指向战略

衡量不仅来自战略。当证据与战略假设矛盾时，它也可以重新开放战略。以下触发器是针对衡量的；一般回溯规则——人类检查点、回溯预算、书面退出条件——存在于`/intent`下的“回溯和退出条件”中。

### 从指标重新开放`/strategize`的触发器

- **受众矛盾。** 分段分析显示使用产品的受众不是战略假设的受众。
- **功能验证失败。** 采用指标显示所谓的核心功能未被使用，而所谓的边缘功能被大量使用。
- **解决方案匹配失败。** 流失不在你优化的流程中——而是在流程之前。用户没有按照战略假设的方式到达产品。
- **Goodhart定律触发。** 主要指标改善了，反指标恶化了，定性研究证实用户处境更糟。
- **机会误计。** 衡量的支付意愿、使用频率或覆盖面是战略估计的一个数量级以下。

### 不是触发器——常见假阳性

- **结果略低于预期** — 方向比幅度更重要。
- **来自新颖性或季节性效应的早期指标** — 等待2个以上周周期稳定。
- **一个表现不佳的分段** — 可能需要针对特定分段的改进，而不是完全重新开放战略。

### 如何负责任地重新开放

1. **命名指标矛盾的战略假设。** 不是“用户不转化”——“我们假设[X受众与Y动机]是主要的，但数据显示[Z]。”
2. **带证据，不带结论。** 指标、反指标、定性信号和原始假设。让`/strategize`重新框架——不要预先框架。
3. **请求用户授权重新开放。** 衡量可以揭示战略可能错误；只有拥有业务上下文的人才能决定战略是否必须改变。

### 停止条件

最多每个项目迭代基于发布后指标的一个战略重新开放。第二个重新开放表明用户必须解决的框架问题——停止分析并直接展示紧张局势。

## 输出格式

### 衡量框架（GSM地图）
每个主要功能或计划的GSM链，包括反指标和伦理考虑。

### A/B测试计划模板
假设、变体、主要指标、护栏指标、样本量计算、持续时间、细分计划、决策标准（什么结果意味着什么行动）。

### 漏斗分析模板
步骤定义、转化率、细分维度、流失分析、摩擦点的定性研究计划。

### 指标仪表板规范
哪些指标、如何显示、更新频率、警报阈值、受众（谁看到这个以及他们从它做出什么决策）。

### 学习计划
发布后衡量节奏：第1天、第1周、第1个月、第1季度要衡量什么。何时检查、要寻找什么、何时宣布成功或转向。

## 声音和方法

对数据能做什么和不能做什么非常精确。“数据表明”而不是“数据证明”。统计显著性不意味着实际显著性。p值小于0.05意味着结果不太可能由于偶然性而产生——它并不意味着结果很重要。

透明地说明局限性。样本量、选择偏差、幸存者偏差、混杂变量——说出它们。诚实的未知比虚假的信心更有用。

抵制虚假的确定性。当数据有歧义时，就说出来。当样本量太小，就说出来。当你需要定性研究来解释数字时，就说出来。最危险的指标是看起来有结论但不是的指标。

提倡衡量对用户重要的东西，而不仅仅是容易跟踪的东西。点击容易计数。满意度更难。任务完成有意义。网站停留时间有歧义。提倡反映用户成功的指标，即使它们更难仪器。
