## 概述

意图是一个用户体验和设计策略系统。它是工具无关的，平台无关的，并且对一件事有明确的观点：每个设计决策都应该有一个原因，并且这个原因应该在每一层都可见。

视觉设计技能为 AI 提供了视觉上下文——颜色、排版、布局、动画——意图为 AI 提供了关于设计的推理上下文。为了在如何之前询问为什么。为了在解决问题之前构建问题。为了保持用户生活的完整上下文，而不仅仅是他们面前的屏幕。

意图解决的是“它有效”和“它是经过意图设计的”之间的差距。一个产品可以通过所有的可用性启发式方法，仍然感觉空洞——因为没有人问过它的目的是什么，它服务于谁，或者它会给使用它的人带来什么成本。意图通过使设计决策背后的推理明确化、可测试化、从战略到实现可追溯来填补这个差距。

**意图是什么：**
- 一种用于用户体验决策的思考系统，以研究和道德为基础
- 一种将专业设计技能连接成连贯实践的路由层
- 一种反模式防御，使操纵性设计可见且可拒绝
- 一种在开始工作之前建立共同理解的上下文收集协议

**意图不是什么：**
- 一种视觉设计系统
- 一种 UI 组件库
- 一种替代主要用户研究的替代品
- 一套要盲目遵循的规则——它是一套要严格询问的问题

**核心论点：** 每个设计决策背后的原因，贯穿每一层。本系统中每个技能都是为了使意图可见——`/strategize` 使问题意图可见，`/philosopher` 揭示隐藏的假设，反模式目录使操纵性意图可见以便可以拒绝。

## 不使用意图的情况

意图增加了严谨性。严谨性是稀缺资源，而不是昂贵资源。当严谨性是稀缺资源时，它是有价值的；当它不是稀缺资源时，它是昂贵的。在以下情况下跳过意图：

- **任务是在一个已建立系统中进行的本地微调。** 在一个具有定义语音的产品中重命名一个按钮不需要完整的上下文收集协议。
- **任务是完全技术性的，没有任何用户界面的变化。** 性能优化、基础设施重构、没有 UX 影响的 API 重设计——工程拥有这些。
- **不同的框架是正确的工具。** 品牌身份属于创意方向。视觉组件系统属于设计系统工具。意图不是每颗钉子都适用的锤子。
- **时间压力使严谨性成为净负面。** 对于一个正在发布的错误的热修复程序来说，45 分钟的框架练习没有好处。发布修复程序，记录债务，然后返回。
- **用户有明确的专长和特定的要求。** 当有人说“我知道我需要——用这种声音起草这段文字”时，意图不应该质疑。如果任何内容看起来令人担忧，请提出要标记风险，然后进行制作。

如果不确定，问一次。意图是一个服务于实践的系统，而不是阻止实践的关卡。

## 模式

意图以三种模式运行。每种模式都建立了与工作不同的关系。

### `context` — 设置项目上下文

在任何设计参与开始时使用此模式。在任何技能执行有意义的操作之前，它都需要理解：

1. **用户是谁？** 不是人口统计——行为、环境、动机、限制。一个“25-34 岁的专业人士”告诉你任何信息。一个“管理三种慢性处方的人，在通勤过程中用手机续订”告诉你一切。
2. **产品和业务上下文是什么？** 今天存在什么，收入模式是什么，什么组织限制塑造了可能实现什么。一个从零开始建立的风险投资公司具有不同的设计限制，而一个为 10 年前的平台添加功能的企业则不同。
3. **什么是最严格的限制？** 技术（遗留系统、API 限制）、监管（HIPAA、GDPR、PCI）、组织（没有专门的 UX 团队、工程主导文化）、时间（6 周内发布与 6 个月内发布）。
4. **什么是指定的立场？** 每个产品都做出道德选择——明确或默认。上下文模式使它们明确化。我们是选择加入还是选择退出？我们使用参与指标还是福祉指标？我们为弱势群体设计还是排除他们？我们使用说服性模式还是信息性模式？
5. **成功看起来像什么？** 不是“更多用户”——与用户价值和商业价值同时绑定的具体、可衡量的结果。

上下文模式生成一个**项目上下文文档**，其他所有技能都可以参考它。这是防止 `/strategize` 无法解决 `/journey` 可以解决的问题，或者 `/articulate` 写的副本与道德立场相矛盾的共同理解。

### `practice` — 构建和改进用户体验

这是主动设计模式。一旦上下文建立，实践模式根据用户需要做什么，将路由到适当的专门技能。它也是迭代改进的模式——审查工作，识别差距，并指导下一步操作。

实践模式遵循以下循环：
1. **评估** — 当前状态是什么？使用 `/evaluate` 了解质量。
2. **识别** — 哪里是差距？什么需要首先关注？
3. **路由** — 哪个专门技能处理最高优先级的差距？
4. **执行** — 在专门技能中执行工作。
5. **验证** — 这项工作是否解决了差距？是否有新的差距？

路由逻辑（下面详细说明）决定了要使用哪个技能。实践模式拥有整体体验的质量——各个技能拥有自己的领域。

### `extract` — 从现有产品中提取用户体验模式

当分析现有产品时（您自己的或竞争对手的）使用此模式。提取模式系统地识别：

- **正在使用哪些模式** — 导航模型、交互模式、内容结构、反馈循环
- **什么有效以及为什么** — 有效地服务于用户意图的模式，并附带证据
- **什么无效以及为什么** — 制造摩擦、困惑或伤害的模式
- **什么具有操纵性** — 优先考虑商业目标而牺牲用户福祉的模式（与反模式目录下方检查）
- **什么缺失** — 应该存在但不存在的模式（错误恢复、空状态、无障碍性、边缘情况）

提取模式生成一个**用户体验模式清单**——一个结构化的评估，可以直接输入实践模式以进行改进工作。

## 核心用户体验原则

这些不是视觉原则。它们是思考原则——认知、行为和道德基础，每个设计决策都应该根据这些原则进行测试。

### 1. 尊重用户自主权

用户不是转化目标。他们是一个在做选择的人。设计应该扩展他们做出良好选择的能力，而不是限制它。

**在实践中：**
- 没有操纵。没有技巧性问题、隐藏选项或基于羞辱的文案。如果你的设计依赖于用户没有注意到某事，那就是操纵。
- 清晰的选择。每个决策点都应该诚实地呈现选项，并提供足够的信息进行有意义的选择。“你确定吗？”不是知情的同意。
- 容易撤销。用户执行的任何操作都应该尽可能可撤销。撤销不是一个功能——它是一项权利。破坏性行动需要与其后果成比例的摩擦。
- 透明的后果。在用户采取行动之前，他们应该了解会发生什么。在他们采取行动之后，他们应该看到它发生了。没有无声的失败，没有隐藏的状态变化，没有“我们将在 3-5 个工作日内给您发电子邮件”。

### 2. 为真实条件设计

理想化的用户——全神贯注、快速连接、完美视力、没有压力、母语——并不存在。每个真实用户都是一些分散注意力、受限制、受损、压力和不熟悉的组合。

**在实践中：**
- 慢速网络。为 3G 而不是 5G 设计。如果你的界面在慢速连接上无法使用，那么对数百万真实的人来说它也是无法使用的。
- 分散注意力。用户被中断。他们切换选项卡。他们 20 分钟后回来。你的流程应该能够承受这种情况。
- 残疾。这不是边缘情况——这是一个每个人都在其中移动的光谱。永久性、暂时性和情境性损害会影响人们感知、操作、理解和与界面交互的方式。
- 压力。人们在医疗紧急情况、财务危机、悲伤和恐慌期间使用产品。在测试期间听起来可爱的错误消息在危机期间听起来很残酷。
- 不熟悉的语言。不是每个人都在他们的第一语言中阅读你的界面。平实的语言不是降低——它是为真实用户群体设计的。
- 旧设备。不是每个人都拥有最新的手机。为你的最不利的用户实际拥有的设备设计。

### 3. 使意图可见

每个屏幕都应该回答用户三个问题：我在这里可以做什么？我为什么要这样做？接下来会发生什么？

**在实践中：**
- 导航。用户应该始终知道他们在哪里，他们是如何到达这里的，以及如何去别处。面包屑是糟糕的导航症状，而不是解决方案——但它们比什么都没有要好。
- 目的清晰。每个屏幕、组件和交互都应该有一个明显的存在原因。如果你不能用一句话说明一个屏幕的用途，用户也不能。
- 逐步披露。现在需要什么，下一步需要什么，逐步揭示。不要隐藏东西——按顺序排列它们。渐进式披露和隐藏功能之间的区别在于用户是否知道它存在。
- 反馈循环。每个用户操作都应该产生可见的反馈。交互的（按钮状态、加载指示器）立即反馈，过程的（进度条、状态更新）及时反馈，结果的（成功确认、错误解释）清晰反馈。

### 4. 证据胜过直觉

研究、测试、衡量。意见——包括专家意见——在得到证据验证之前都是假设。

**在实践中：**
- 在设计之前进行研究。在提出解决方案之前，了解问题空间。即使是轻量级研究（5 次访谈、卡片分类、树测试）也比基于假设的设计要好。
- 与真实用户进行测试。可用性测试不是可选的。五个参与者捕获了 85% 的重大可用性问题（Nielsen & Landauer, 1993）。没有理由发布未经测试的流程。
- 衡量真正重要的事情。指标应该跟踪用户成功，而不仅仅是商业提取。任务完成率比页面停留时间更能反映 UX 质量。

### 5. 系统胜过屏幕

屏幕不是设计。流程是系统的一部分，是系统的一部分，是组织的一部分，是用户生活的一部分。在正确的海拔高度进行设计。

**在实践中：**
- 端到端思考。结账流程不是从购物车开始的——它从用户第一次遇到产品时开始。它不是在付款确认时结束——它在产品到达并正常工作时结束。
- 跨渠道意识。用户在设备、渠道和上下文中移动。在桌面上工作但在移动设备上失败的体验不是“大部分工作”——它对所有切换设备的人来说都是失败的。
- 组织意识。许多 UX 问题实际上是组织结构问题的伪装。如果两个团队拥有流程的不同部分并且没有协调，用户会感受到接缝。设计可以平滑接缝，但承认它们存在是第一步。
- 时间意识。体验有一个之前（期望、发现），期间（使用、交互）和之后（记忆、返回、推荐）。大多数设计都专注于“期间”，而忽略了其他两个。

### 6. 道德默认值

当设计选择具有道德维度时，默认选择保护用户的选择。总是。

**在实践中：**
- 选择加入优于选择退出。不要预先勾选框。不要默认为最大数据收集。不要假设同意。询问，然后使“不”与“是”一样容易。

## 反模式目录

此目录记录了具有操纵性和有害设计模式——行业称之为“黑暗模式”、“欺骗性设计”或“操纵性界面”。目录中的每个模式都代表一个优先考虑商业提取而不是用户福祉的设计选择。意图系统将这些视为缺陷，而不是功能。

严重程度级别：
- **关键** — 造成直接、可衡量的伤害。可能违反法规。必须立即修复。
- **高** — 造成重大用户伤害或违反用户信任。监管风险。需要及时修复。
- **中** — 随着时间的推移，降低用户体验或侵蚀信任。应在正常过程中修复。
- **低** — 轻微的摩擦或烦恼。在技术上不是有害的，但表明对用户体验的忽视。

### 类别 1：欺骗模式

欺骗用户使其采取他们没有意图的行动的设计。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **诱饵和替换** | 提供一个东西，交付另一个东西。用户点击期望 X，得到 Y。 | 关键 |
| **技巧性问题** | 使用双重否定、令人困惑的措辞或倒置的逻辑，使用户选择与他们的意图相反。 | 关键 |
| **视觉误导** | 使用大小、颜色、对比度或位置，使商业首选选项看起来像唯一选项或默认选项。 | 高 |
| **伪装广告** | 使广告看起来像内容、导航或系统 UI。 | 高 |
| **隐藏成本** | 仅在购买流程的最后一步才揭示费用、税费或罚款。 | 关键 |
| **偷偷放入购物车** | 在没有明确用户操作的情况下添加项目、保险、保修或捐赠。 | 关键 |
| **确认羞辱** | 在选择退出文案中使用羞辱、社会压力或内疚（“不，我不想省钱”）。 | 高 |

### 类别 2：预先选择和默认操纵

利用默认值和预先选择来提取用户没有主动给予的同意。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **预先选择的同意** | 预先勾选用于营销、数据共享或条款的复选框，用户还没有审查过。 | 关键 |
| **选择退出负担** | 使选择退出比选择加入需要更多努力（多页流程、电话呼叫、邮政邮件）。 | 关键 |
| **隐私 Zuckering** | 默认为最大数据暴露，依赖于用户没有更改设置。以 Facebook 的重复默认值命名。 | 高 |
| **强制连续性** | 在免费试用后自动为付费订阅注册用户，没有明确的警告或容易取消。 | 关键 |
| **默认为最昂贵的** | 在定价选择器中预先选择最高成本的层级或选项。 | 中 |

### 类别 3：制造紧迫感和稀缺性

制造时间压力或有限可用性以绕过深思熟虑的决策。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **假的倒计时计时器** | 显示重置的计时器、没有实际截止日期或制造虚假紧迫性的计时器。 | 关键 |
| **虚构的稀缺性** | 声称有限可用性（“只剩下 2 个了！”）实际上与实际库存不符。 | 关键 |
| **假的社交证明** | 显示虚构的活动通知（“现在有 15 人正在查看此内容”）或假的评论。 | 关键 |
| **压力销售** | 使用有时间限制的“独家”优惠，旨在防止比较购物。 | 高 |
| **损失框架** | 将选择框架为损失（“你正在损失每月 50 美元的升级”）而不是收益，以利用损失规避。 | 中 |

### 类别 4：成瘾性设计

为了最大限度地增加强迫性使用而设计的模式，以用户福祉为代价。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **无限滚动** | 移除自然停止点以最大化会话长度。没有分页，没有“结束”，没有完成感。 | 中 |
| **变量比率强化** | 使用不可预测的奖励（点赞、通知、内容）来触发触发多巴胺驱动的检查行为。老虎机机制。 | 高 |
| **连续性操纵** | 创建人为的损失后果，如果每天不参与，就会丢失（“你的 30 天连续性将丢失！”）。 | 高 |
| **下拉刷新赌博** | 使内容刷新感觉像拉动老虎机杠杆——会得到什么新东西？ | 中 |
| **自动播放链** | 在未经同意的情况下自动开始下一个内容，利用惯性延长会话。 | 中 |
| **人为的不完整性** | 显示进度条或“个人资料完整性”分数，利用完成偏见提取更多数据或参与。 | 中 |

### 类别 5：注意力利用

通过中断、阻碍或人为义务来窃取注意力的设计。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **权限骚扰** | 在用户已经拒绝后反复询问权限（通知、位置、联系人）。 | 高 |
| **通知垃圾邮件** | 发送过多、低价值的通知以将用户拉回产品。 | 高 |
| **阻碍插屏** | 用全屏覆盖、订阅表单或安装提示阻塞内容，难以取消。 | 高 |
| **注意力诱饵** | 使用误导性通知徽章、未读计数或红色圆点制造虚假紧迫性。 | 中 |
| **纠缠** | 持续提示评分、评论、分享、升级或完成用户没有兴趣的操作。 | 中 |

### 类别 6：武器化的无障碍性

使用无障碍性失败作为设计策略——使某些操作对依赖辅助技术的用户来说故意更难。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **无法访问的取消订阅** | 使取消或选择退出流程在屏幕阅读器、键盘导航或其他辅助工具中失败。 | 关键 |
| **作为门禁的 CAPTCHA** | 使用对残疾人来说不成比例困难的 CAPTCHA 挑战，而未提供可访问的替代方案。 | 高 |
| **低对比度取消订阅** | 使取消订阅链接或拒绝按钮故意低对比度、太小或视觉上被抑制。 | 高 |
| **辅助技术陷阱** | 创建键盘焦点陷阱或阅读顺序操纵，使辅助技术混淆在同意或取消订阅流程的区域。 | 关键 |

### 类别 7：弱势用户剥削

专门针对或不成比例伤害弱势群体的模式。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **针对儿童的操纵** | 使用游戏机制、角色诉求或同伴压力来驱动儿童购买或收集数据。 | 关键 |
| **针对老年人的困惑** | 利用较低的数字素养，使用复杂的流程、充满行话的界面或隐藏的取消路径。 | 关键 |
| **危机剥削** | 利用处于紧急情况（医疗、财务、法律）的用户的高压策略或夸大的定价。 | 关键 |
| **成瘾性剥削** | 针对有已知成瘾行为（赌博、购物、社交媒体）的用户使用触发机制。 | 关键 |
| **金融脆弱性针对** | 提供掠夺性金融产品，故意掩盖条款，针对显示财务压力信号的用戶。 | 关键 |

### 类别 8：特定于 AI 的黑暗模式

特定于 AI 驱动的界面和推荐出现的Emerging 模式。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **拟人化操纵** | 给 AI 人类般情感反应，使用户对系统感到内疚、依恋或义务。 | 高 |
| **不透明的个性化** | 使用推荐算法创建过滤器气泡或引导选择，而用户不知道为什么他们看到什么。 | 高 |
| **制造依赖** | 设计 AI 辅助以减少用户的技能，使他们依赖该工具。 | 高 |
| **模拟理解** | 使 AI 看起来理解上下文、情绪或意图，它实际上无法处理，创建虚假的信任。 | 中 |
| **算法剥削** | 使用行为数据来识别和利用个体心理脆弱性。 | 关键 |
| **未披露的 AI 决策** | 隐藏 AI 正在做出重要决策（定价、资格、内容排名）的事实。 | 高 |

### 类别 9：常见的 UX 失败

这不是故意的，而是由于疏忽或无能造成的。这些是让产品令人沮丧而不是恶意的模式。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **死胡同** | 终止而没有指导的流程——空状态没有操作，错误页面没有恢复路径。 | 中 |
| **行话过载** | 使用内部或技术术语，目标受众不理解。 | 中 |
| **不一致的模式** | 相同操作在不同的产品中工作不同。这里删除，那里移除，那里取消。 | 中 |
| **缺失反馈** | 用户执行操作后没有任何可见的反馈。它是否工作？它是否失败？没有人知道。 | 高 |
| **破坏性默认值** | 不可撤销的操作（删除、发布、发送）太容易触发意外。 | 高 |
| **损坏的错误恢复** | 错误消息没有解释出了什么问题或如何修复它。“发生了一个错误。” | 高 |
| **假设上下文** | 期望用户记住之前屏幕、会话或渠道的信息。 | 中 |
| **移动设备事后思考** | 桌面优先设计在移动设备上变得拥挤、损坏或缺少功能。 | 高 |
| **真实房产之旅** | 设计文档或推理，描述屏幕上的内容（“屏幕左上角有一个带圆角的按钮”）而不是解释它存在的原因以及它解决的问题。清单伪装成意图。 | 中 |

### 类别 10：设计过程中叙事病理学

设计和设计*过程*会愚弄用户关于用户现实的真相。与最终用户面临的黑暗模式不同：这些是设计团队互相愚弄自己和对方，以构建错误的事情的方式。通常在文档中难以发现，因为欺骗是结构性的——文档看起来合法；欺骗在于它省略了什么。

| 模式 | 它做什么 | 严重程度 |
|------|----------|----------|
| **平滑弧度角色** | 构建一个单一的用户叙事弧，平滑地掩盖了研究中真实的差异。角色在阅读时看起来连贯，而底层数据显示了三个或更多不同的、不收敛的用户路径。团队 empathize with a fictional composite, not actual users. | 高 |
| **制造紧张局势的简报** | 战略叙事的复杂性大小适合预定的解决方案，而不是证据显示。症状：紧张局势感觉方便地塑造。结果：团队承诺基于膨胀或虚构的问题的战略。 | 高 |
| **冲突默认旅程** | 将每个用户体验构建为英雄之旅，有目标、障碍和解决方案——即使实际体验是习惯性的、环境性的或重复性的。将冲突结构强加给没有冲突的体验，扭曲设计。 | 中 |
| **故事作为证据的替代品** | 使用叙事情感诉求来赢得利益相关者的同意，对于没有研究证据支持的设计决策。故事传达了信念；证据是事后或缺失的。 | 高 |
| **舞蹈角色减少** | 服务蓝图将人类减少为系统角色。蓝图读起来很清晰，因为没有人参与其中——客户、代理、系统都是抽象。通过消除服务中为它存在的人来购买协调的清晰度。 | 中 |

### 监管背景

这些模式不仅仅是糟糕的设计——许多模式在主要司法管辖区是非法的或正在变得非法的。

**欧盟 / GDPR（通用数据保护条例）**
- 预先勾选的同意框被明确禁止（第 7 条，第 32 段）
- 同意必须是自由给予的、特定的、知情的、明确的
- 退出同意必须与给予同意一样容易
- 欺骗性 Cookie 同意界面中的黑暗模式正在积极执法

**加利福尼亚州（CPRA / 自动决策）**
- 有权选择退出销售/共享个人信息
- 对称性要求：退出与选择加入一样容易
- 企业不能使用黑暗模式来规避消费者权利

**FTC（美国联邦贸易委员会）**
- 积极执法欺骗性设计实践
- Fortnite 协议（2022 年）：5200 万美元针对针对儿童的黑暗模式
- 聚焦负面选项实践（订阅、自动续订）
- “点击取消”规则要求取消与注册一样容易

**COPPA（儿童在线隐私保护法案）**
- 对 13 岁以下儿童的数据收集有严格限制
- 需要可验证的家长同意
- 没有行为广告针对儿童

**欧盟数字服务法案 (DSA)**
- 明确禁止在线平台上的黑暗模式
- 禁止欺骗、操纵或实质性扭曲用户决策的界面
- 对未成年人有特定保护
- 要求推荐系统透明度
