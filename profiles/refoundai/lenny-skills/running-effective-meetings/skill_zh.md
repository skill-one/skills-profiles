# 举办高效会议

通过40位产品负责人的框架，帮助用户举办更高效的会议。

## 如何提供帮助

当用户寻求会议相关帮助时：

1. **质疑会议的必要性** - 询问这是否可以是异步形式，或者是否真的需要开会
2. **明确会议目的** - 确定会议是为了探索、讨论还是决策
3. **设计会议结构** - 帮助他们创建合适的议程和流程
4. **确保落实** - 指导他们如何记录决策和下一步行动

## 核心原则

### 将战略会议与运营会议分开
Naomi Gleit："我们每周有一个战略会议，比较开放，有时间讨论...我们每周还有一个运营会议，结构非常清晰，我们会过一遍所有优先级项目。"不要将无结构的战略讨论与结构化的运营更新混在一起。

### 会议仅用于讨论
Annie Duke："人们通常认为会议的目的是三个事情，探索、讨论、决策。会议中唯一应该发生的事情就是讨论部分。"探索和决策应该异步进行。将同步时间保留给真正的对话。

### 以三个问题结束会议
Alisa Cohn："我用来结束会议的三个问题是，我们在这里决定了什么？谁需要在何时完成什么？还有谁需要知道？"以标准化的提问结束会议可以确保共识，并防止再次开会。

### 不要跳过预热阶段
Evan LaPointe："一般来说，会议是预热和决策的结合...很多会议完全跳过了预热步骤。"大多数会议功能障碍都源于跳过了背景设置。在做出决策之前，明确包含一个预热阶段。

### 为重要决策清空日程
Jake Knapp + John Zeratsky："设计Sprint的大致想法是在五天内从零到一个原型及其测试。这是一个配方，是一系列预编的活动。"高风险的战略决策受益于有时间限制、清空日程的工作坊。

### 残酷地减少会议
Gibson Biddle："减少会议，好吗？减少会议。这吸干了每个人的精力，包括你。"通过主动移除非必要的会议来保护生产力。满日程是一种耻辱，而不是荣誉。

### 状态变化维持参与度
Wes Kao："状态变化方法是你应该在独白中穿插状态变化。状态变化是指任何能唤醒听众的活动。"在虚拟会议中，每3-5分钟用投票、聊天提示或更换发言人来打断独白。

### 预读将状态更新转为异步
Matt Mochary："如果每个人都能提前准备他们的更新...我们可以将三个小时的会议缩短到45分钟。"要求与会者在会议前提交书面更新和拟议的解决方案。将第一部分用于静读。

## 帮助用户的提问

- "这个会议是否需要召开，或者可以是异步解决的？"
- "这个会议的目的是什么：探索、讨论还是决策？"
- "与会者应在会议前完成哪些准备工作？"
- "决策者是谁，并且每个人都知道吗？"
- "你将如何记录和传达会议后的决策？"
- "什么情况下你会取消这个定期会议？"

## 常见错误

- **状态更新会议** - 使用同步时间共享本可以异步传递的信息
- **没有明确目的** - 没有明确目标的会议
- **缺少预热** - 在建立共同背景之前就跳到决策
- **没有记录成果** - 在没有记录决定和谁负责什么的情况下结束会议
- **与会者过多** - 每增加一个人都会降低坦诚度并增加成本
