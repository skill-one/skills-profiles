# 管理技术债务

通过来自18位产品负责人的见解，帮助用户战略性地管理技术债务。

## 如何提供帮助

当用户寻求技术债务方面的帮助时：

1. **了解情况** - 询问债务的性质（遗留系统、代码质量、架构限制）、如何显现（开发速度慢、事件、无法发布）以及业务背景
2. **诊断紧迫性** - 判断这是否阻碍了关键业务需求，还是一个问题较慢
3. **选择正确方法** - 帮助他们决定是进行渐进式改进、针对性重构，还是（极少情况下）全面重写
4. **构建商业案例** - 帮助量化债务成本并向利益相关者传达价值

## 核心原则

### 重写几乎从不奏效
Camille Fournier： "工程师们一贯、一贯、一贯、大规模低估将旧系统迁移到新系统所需的时间。顺便说一句，在开发新系统时，你仍然需要支持旧系统。" 全面重写是陷阱。优先选择渐进式演进 - 针对特定组件进行升级，而不是从零开始。

### 技术债务是产品债务
Ebi Atawodi： "基础设施就是产品。句号。我无法在摇摇欲坠的基础上建造摩天大楼。所以这也是你的问题 - 不是工程师可以破门而入的问题。" 技术债务应由产品经理作为"产品债务"来拥有，而不是将其视为仅是工程问题。将其列入你的前10个问题清单。

### 初创公司应战略性地承担债务
Gaurav Misra： "作为初创公司，你的工作是承担技术债务，因为这是你比大公司更快运营的方式。" 债务是杠杆 - 评估一个问题是否可以由未来的员工解决，而不是今天解决。但监控"利息" - 如果维护占80-90%的时间，你就耗尽了跑道。

### 删除代码比编写代码更多
Farhan Thawar： "我们有一个删除代码俱乐部。我们几乎总能找到一百万行以上的代码可以删除。一切都会变得更简单 - 代码库加载更快，更容易理解。" 创建专门的时间或团队专注于删除未使用的代码。删除可以提高速度和清晰度。

### 技术债务对用户可见
Matt Mullenweg： "你可以在界面中看到[技术债务]，或者他们的产品如何与自身集成。" 分裂的UI以及功能之间糟糕的集成是累积债务的用户面症状。寻找不一致之处以识别债务累积的位置。

### 量化偿还债务的价值
Casey Winters： "最有影响力的项目是最难衡量的，所以它们持续被资金不足。构建自定义指标来展示价值，运行小型测试来证明投资的合理性。" 创建自定义指标并运行实验来展示商业价值。与工程和设计保持一致，以展示统一战线。

### 立即修复错误，不要积压
Geoff Charles： "我们没有错误积压。一旦出现错误，我们几乎立即修复。" 将错误直接分配给当班的工程师，以确保立即意识到痛苦。错误积压变成了墓地。

### 债务限制创新
Eeke de Milliano： "有时团队只是被紧急工作缠住 - 技术债务太多、错误、不稳定性。如果他们整天埋头处理事件，他们根本没有办法专注于更大的、有创意的事情。" 诊断团队是否陷入"需求层次"陷阱。优先减少债务以释放空间进行创意工作。

### 技术债务是香槟问题
Julia Schottenstein： "如果我们有技术债务，我们会非常幸运，因为这意味着人们正在使用产品。我们在发布时不需要分布式调度器 - 我们没有用户。" 首先构建最简单、最天真的版本。接受债务作为将产品交付到用户手中的代价。

### 为黑暗隧道做计划
Melanie Perkins： "我们以为需要六个月...结果花了两年没有发布任何产品。" 全面重写是"黑暗隧道"，会停滞发布。如果你必须这样做，请将工作游戏化以在漫长的奋斗中保持团队动力。

### 1-2年后进行设计
Austin Hay： "思考一下一年到两年后我们需要什么。在设置工具时，问：'如果一年后我不改变任何东西会发生什么？'" 早期实施基础元素，如SSO或适当的数据模式，以避免以后的灾难性迁移。

## 帮助用户的提问

- "这是否阻碍了关键业务需求，还是一个问题较慢？"
- "有多少工程时间将用于维护而不是新功能？"
- "你是否尝试估算重写实际需要多长时间？谁做了这个估算？"
- "如果你再等6个月什么都不做会怎样？"
- "有没有办法逐步改进而不是重写？"
- "你会如何量化债务对利益相关者的成本？"

## 常见错误

- **计划全面重写** - 重写几乎从不按计划进行。它们比估计的时间长2-3倍，并且你必须同时支持两个系统
- **将技术债务视为工程问题** - 这是产品债务。产品经理应与工程师共同拥有它
- **让错误积压累积** - 错误积压变成了墓地。立即修复或决定不修复
- **在产品市场契合度之前过度设计** - 债务是香槟问题。首先构建天真的解决方案，并接受债务作为学习成本
- **不量化成本** - 技术债务投资因价值未衡量而资金不足。构建指标并运行实验来证明投资回报率
