# 设置 OKRs 与目标

通过 55 位产品领导者的框架和见解，帮助用户创建有效的目标和关键成果。

## 如何提供帮助

当用户需要有关 OKRs 或目标设定的帮助时：

1. **理解背景** - 询问他们的公司发展阶段、团队规模，以及他们是否有现有目标或需要从零开始
2. **明确层级** - 确定这些是公司、部门、团队还是个人目标
3. **识别策略** - 在设定目标前确保他们有明确的策略（目标应该是策略的终点，而不是起点）
4. **指导结构** - 帮助他们撰写鼓舞人心的目标，并设定可衡量的关键成果，避免常见陷阱

## 核心原则

### 目标应与公司目标仅一步之遥
Matt LeMay： "不超过与公司目标一步之遥。不要让它被层层级级地淹没。" 确保团队目标直接围绕主要公司目标旋转，而不是被组织层级淹没。

### 建立系统，而不仅仅是目标
Lane Shackleton： "与其痴迷于目标，不如痴迷于带你到达目标的系统。" 将一次性 OKR 目标替换为可重复的 '默认开启' 系统，如站立式客户会议，以建立长期习惯。

### OKRs 连接策略与执行
Christina Wodtke： "主要优势在于 OKR 可以提供很多具体的行动，而策略往往无法做到。" 使用 OKRs 将抽象策略转化为具体的季度数字，同时通过季度末评估创建学习周期。

### 用三个关键成果进行三角测量
Christina Wodtke： "我喜欢三个。一个是硬核数字，一个是稍模糊的如质量，还有一个涉及金额。" 平衡定量、定性和财务指标，以获得完整的成功视图。

### 使用绝对数字，而不是比率
Archie Abrams： "比率和百分比是危险的指标，因为它们可以通过减少分母来'操纵'。" 将目标从 '转化率' 转变为 '达到特定状态的绝对用户数'，以防止操纵。

### 激进的目标迫使新思维
Daniel Lereya： "设定激进的目标，会让你思考不同。我们真的很喜欢这样做，即使我们不知道这是否可能。" 设定通过 '更努力工作' 无法实现的目标，以迫使 '更聪明地工作' 和根本性重新思考。

### 将策略与 OKR 讨论分开
Lane Shackleton： "OKRs 实际上不是策略。将策略讨论与 OKR 讨论分开至关重要。" 在 OKR 规划之前创建一个独立的策略仪式，以确保 '为什么' 不会在 '什么' 中丢失。

### 限制规划开销
Lane Shackleton： "10% 规划规则 - 确保你的规划时间不超过执行周期的 10%。" 如果为季度规划，规划过程不应超过大约一周。

### 关注成果，而不是产出
Marty Cagan： "在一个真正的产品团队中，当你真正解决问题时，你会庆祝。这就是为什么我们说产品团队是关于成果，而不是产出。" 通过问题解决来定义成功，而不是功能交付。

### 目标是沟通工具
Molly Graham： "没有公司需要超过三个公司目标。重点是帮助人们知道最重要的事情是什么。" 保持目标简洁，确保一个目标在竞争中胜出，并为每个目标分配一个确切的负责人。

## 帮助用户的提问

- "你们公司的当前主要目标是什么，以及这个团队目标如何与之联系？"
- "你将如何知道你是否成功 - 哪个具体数字会改变？"
- "这个目标是否足够鼓舞人心，能够激励团队克服障碍？"
- "你的关键成果是成果（你知道你成功的方式）还是任务（待办事项清单）？"
- "你可以建立什么系统，使这个目标的进展成为 '默认开启'？"
- "如果你实现了这个目标，但损害了用户体验，它仍然会成功吗？"

## 常见错误

- **关键成果是任务** - 关键成果应该是可衡量的成果，而不是完成活动的清单
- **目标过多** - 公司不需要超过三个目标；超过三个会分散注意力，并防止权衡取舍
- **目标模糊** - 目标应该让你兴奋到起床，而不是通用的企业语言
- **在策略之前设置目标** - 如果你没有真正的策略，OKRs 就变成了虚假精确的无意义练习
- **过度关注单一指标** - 这可能会激励保留对客户不利的功能，只是恰好推动了数字
