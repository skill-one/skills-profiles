# 组织转型

利用两位产品领导者的见解，帮助用户将其组织转型为现代产品实践。

## 如何提供帮助

当用户寻求组织转型方面的帮助时：

1. **了解他们的起点** - 询问他们当前的模式是怎样的（功能团队、结果导向、瀑布式），以及推动变革的动因是什么
2. **诊断准备情况** - 确定谁拥有推动变革的权力和意愿，以及他们应该预期会遇到哪些阻力
3. **设计方法** - 帮助他们决定是选择试点团队、逐步引导，还是进行更广泛的转型计划
4. **管理变革** - 指导他们如何沟通、衡量进展以及应对阻力

## 核心原则

### 框架是手段，而非目的
约翰·卡特勒（John Cutler）说：“大多数公司认为采用框架是最终目标。” 目标是更好的成果，而不是实施Scrum或SAFe或任何特定的方法论。评估框架要看它们是否有助于你的特定组织解决其特定的问题。

### 通过试点转型，然后推广
马蒂·卡根（Marty Cagan）说：“TRANSFORMED的目标是分享如何实际改变——转型技术。” 从少数被赋予权力的产品团队开始，这些团队能够证明该模式是有效的。利用他们的成功为更广泛的变革建立信誉。

### 小心引导传统企业
约翰·卡特勒强调要“引导”非硅谷公司走向现代实践，而不会引起系统性的拒绝。激进的变革提案往往会被拒绝。寻找引入新实践的方法，这些方法不会威胁到现有的权力结构。

### 这是结构、文化和流程变革
马蒂·卡根描述了从“功能团队”转变为“产品运营模式”——这需要改变结构（团队如何组织）、文化（人们如何看待他们的工作）和流程（决策如何做出）。只改变一个维度是行不通的。

## 帮助用户的提问

- “是什么推动了转型的需求？今天什么出了问题？”
- “谁拥有推动这项变革的权力和意愿？”
- “你当前的模式是什么——功能团队、瀑布式，还是其他？”
- “你将从哪里开始？是否有团队或领域可以试点新方法？”
- “你应该预期哪些阻力，以及来自哪些人？”
- “你将如何知道转型是否有效？”

## 常见错误

- **将框架采用视为目标** - 实施Scrum并不意味着你已转型。关注成果，而不是仪式
- **大爆炸式转型** - 试图一次性改变所有东西通常都会失败。从试点开始
- **忽视文化** - 没有文化变革的流程变革会被规避。解决信念，而不仅仅是行为
- **缺乏高管支持** - 没有高级支持，转型会被组织的抗体摧毁
- **盲目复制硅谷** - 在谷歌有效的方法可能在50岁的企业中无效。适应，而不是复制
