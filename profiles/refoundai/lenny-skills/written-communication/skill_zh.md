# 领导者的书面沟通

通过结构化、清晰且有说服力的写作，扩大你的影响力并推动团队协同。

利用来自Lenny播客和新闻简报中12位嘉宾的见解和文章，帮助用户提升书面沟通能力。

## 如何提供帮助

1. **框架应用** - 指导用户将SCR或Minto金字塔框架应用于他们的当前草稿。
2. **叙事聚焦** - 帮助用户识别并突出他们的主要结论，以确保高管层面的清晰度。
3. **语气和简洁性** - 审阅草稿以删除冗余内容，强化逻辑，并根据目标受众调整语气。
4. **流程设计** - 协助团队建立异步沟通规范或结构化的反馈循环。

## 核心原则

### 为个人精进而写
Julian Shapiro: "它们是我自我约束和在学习为我个人利益而学的内容时保持周全的工具。这就是它们全部的作用。基本上，如果我想要去学习增长、写作技巧或其他主题，我会进行大量研究，阅读我能找到的所有资料，进行大量实验，试图构建一套新颖的见解，这些见解可能无法从其他人的研究中获得，然后下一阶段是尽量使其简洁且可操作，这样我就可以为了我自己的自私利益而参考它。"

将写作作为你个人学习的工具，以确保最终成果全面且高质量。

### 通过文档扩大影响力
Kevin Yien: "写作是规模化的清晰度，而产品经理工作的一个关键组成部分是创造清晰度，两者都是"

有效的写作是维持整个组织同时保持清晰度和协同性的主要工具。

### 标准化叙事框架
从《Minto金字塔原则和SCR框架》中："如果进一步简化，每个叙事都有三个部分：情况、冲突和解决方案。1. 情况：目前的状态如何。事实、数据和明确的背景。2. 冲突：发生了什么变化需要采取行动。问题是什么？3. 解决方案：我们需要做什么来解决这个冲突。"

围绕情况、冲突和解决方案构建业务沟通，在提出解决方案之前提供必要的背景信息。

### 建立共同的情况
从《产品构建者必读——第二部分》中："最好的高管沟通从状态开始。它是基于事实的，没有歧义。它完全不是有争议的。无论你站在问题的哪一边，或者面临艰难的选择，你都应该能够阅读情况并说，‘这基本上概括了全部。’"

通过从所有人都同意的非争议性事实集开始，在引入冲突之前实现高管级别的清晰度。

## 模板与框架

- **SCR（情况-冲突-解决方案）框架**（《Minto金字塔原则和SCR框架》）- 一种基于通用故事弧的商业沟通叙事结构。在建议之前提供背景信息，避免过于突兀。也
- **Minto金字塔原则**（《Minto金字塔原则和SCR框架》）- 由Barbara Minto在麦肯锡开发的一种沟通框架，用于构建有说服力的商业论证。不是从数据到结论
- **6部分请求模板**（《如何请求帮助（即使你真的不想）》）- 一种在专业环境中进行有效请求的结构化模板。可以根据关系强度、目标重叠和接收者经验
- **写作质量改进清单**（《500,000》）- 基于Lenny的经验和三本推荐书籍，改进新闻简报写作质量的可操作步骤
- **高管编辑GPT**（《如何用AI成为超级管理者》）- 一个自定义GPT，对书面沟通（电子邮件、演示文稿、Slack消息）在结构、清晰度、详细程度和语气上进行评分，并提供可操作的改进
- **TLDR + 上下文消息结构**（Wes Kao）- 一种将最重要的信息放在最上面，然后在下面提供可选上下文的书面商业沟通格式
- **将AI作为写作/编辑合作伙伴使用**（Seth Godin）- Seth使用Claude作为编辑助理的具体流程，同时保持作者声音。
- **结合SCR + Minto金字塔框架**（《Minto金字塔原则和SCR框架》）- 两个框架的集成：SCR提供叙事外壳，Minto金字塔专门构建解决方案部分。

有关完整列表和详细信息的参考，请查看`references/artifacts.md`。

## 帮助用户的提问

- "这份文档的主要受众是谁，以及你希望他们在阅读后做的一件事是什么？"
- "所有参与方都同意的、非争议性的情况是什么？"
- "如果你必须将你的主要建议放在第一句话，它会说什么？"
- "哪些具体领域需要关键反馈，而不仅仅是普遍意识？"
- "哪些支持数据或事实可能缺失，可以加强你的解决方案？"
- "我们如何将这次更新从同步会议转变为异步文档？"

## 常见错误提示

- **以发现过程为先** - 忙碌的利益相关者首先关心结论，其次才是发现过程。
- **隐藏请求** - 不明确的请求会产生摩擦，并延迟你前进所需的帮助或决策。
- **忽略情况** - 在没有共同背景的情况下提出解决方案会导致不一致和关于问题本身的非必要争论。
- **过度依赖AI生成** - 没有严格的规划阶段使用AI会导致缺乏你独特视角和权威的通用内容。
