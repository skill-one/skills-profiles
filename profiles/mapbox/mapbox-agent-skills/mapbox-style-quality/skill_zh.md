# Mapbox 样式质量技能

该技能提供专家级指导，通过验证、可访问性和优化工具确保 Mapbox 样式的质量。

## 何时使用质量工具

### 部署前的检查清单

在将任何 Mapbox 样式部署到生产环境之前：

1. **验证所有表达式** - 在运行时之前捕获语法错误
2. **检查颜色对比度** - 确保文本可读（符合 WCAG 标准）
3. **验证 GeoJSON 源** - 确保数据完整性
4. **优化样式** - 减小文件大小并提高性能
5. **比较版本** - 了解发生了哪些变化
6. **删除空图层** - 作为最终清理步骤删除没有可见画布属性的图层
7. **简化冗余布尔表达式** - 清理具有不必要布尔逻辑的过滤器（例如，`["all", expr]` → `expr`，`["any", false, expr]` → `expr`）

### 开发过程中

**添加 GeoJSON 数据时：**

- 始终使用 `validate_geojson_tool` 在将其用作源之前验证外部 GeoJSON

**编写表达式时：**

- 使用 `validate_expression_tool` 在编写表达式时验证它们
- 尽早捕获类型不匹配（例如，在数字上使用字符串运算符）
- 验证您的 Mapbox GL JS 版本中可用运算符
- 使用预期数据类型测试表达式

**样式化文本/标签时：**

- 使用 `check_color_contrast_tool` 检查前景色/背景色对比度
- 目标是 WCAG AA 最小值（普通文本 4.5:1，大文本 3:1）
- 使用 AAA 标准（普通文本 7:1）以获得更好的可访问性
- 考虑不同的背景场景（地图瓦片、覆盖层）

### 提交更改前

**比较样式版本：**

- 使用 `compare_styles_tool` 生成差异报告
- 审查所有图层更改、源修改和表达式更新
- 了解您更改的影响
- 在提交信息中记录重大更改

### 部署前

**优化样式：**

- 运行 `optimize_style_tool` 以减小文件大小
- 删除引用已删除图层的未使用源
- 消除具有相同属性的重复图层
- 简化过滤器中的冗余布尔表达式（例如，将 `["all", expr]` 折叠为 `expr`，删除同义条件）
- 删除空图层（没有可见画布属性的图层）作为最终清理步骤

## 验证最佳实践

### GeoJSON 验证

**始终在以下情况下验证：**

- 从用户上传中加载 GeoJSON
- 从外部 API 获取 GeoJSON
- 处理来自第三方源的 GeoJSON
- 在数据格式之间转换

**常见的 GeoJSON 错误：**

- 无效的坐标范围（经度 > 180 或 < -180）
- 未关闭的多边形环（第一个和最后一个坐标必须匹配）
- 坐标顺序错误（应该是 [经度, 纬度]，而不是 [纬度, 经度]）
- 缺少必需属性（类型、坐标、几何形状）
- 无效的几何形状类型或嵌套

**示例工作流程：**

```
1. 接收 GeoJSON 数据
2. 使用 validate_geojson_tool 验证
3. 如果有效：将作为源添加到样式
4. 如果无效：修复错误，重新验证
```

### 表达式验证

**验证表达式用于：**

- 过滤条件（图层上的 `filter` 属性）
- 数据驱动样式（`paint` 和 `layout` 属性）
- 特征状态表达式
- 动态属性计算

**常见的表达式错误：**

- 类型不匹配（在数字上使用字符串运算符）
- 无效的运算符名称或错误语法
- 运算符参数数量错误
- 嵌套表达式错误
- 对于您的 GL JS 版本不可用的运算符

**预防策略：**

- 在运行时而不是编写时验证表达式
- 使用代表性数据测试表达式
- 使用类型检查（expectedType 参数）
- 在上下文中验证（图层、过滤器、画布、布局）

### 可访问性验证

**WCAG 级别：**

- **AA**（最低）：普通文本 4.5:1，大文本 3:1
- **AAA**（增强）：普通文本 7:1，大文本 4.5:1

**文本大小类别：**

- **普通**：< 18pt 或 < 14pt 粗体
- **大**：≥ 18pt 或 ≥ 14pt 粗体

**需要检查的常见场景：**

- 地图瓦片上的文本标签
- 具有背景色的兴趣点标签
- 带文本的自定义标记
- 地图上的 UI 覆盖层
- 图例文本和符号
- 归因文本

**测试策略：**

- 对浅色和深色地图瓦片进行测试
- 考虑覆盖层背景（弹窗、模态框）
- 在不同照明条件下测试（户外移动使用）
- 验证不同缩放级别的对比度

## 质量工作流示例

### 基本质量检查

```
1. 在样式中验证表达式
2. 检查文本图层的颜色对比度
3. 如有必要，进行优化
```

### 完整的预生产工作流

```
1. 验证所有 GeoJSON 源
2. 验证所有表达式（过滤器、画布、布局）
3. 检查所有文本图层的颜色对比度
4. 与之前的生产版本进行比较
5. 优化样式
6. 测试优化后的样式
7. 部署
```

### 故障排除工作流

```
1. 比较正常与损坏的样式
2. 确定差异
3. 验证可疑表达式
4. 如果与源相关，检查 GeoJSON 数据
5. 如果有可见性问题，验证颜色对比度
```

## 常见问题和解决方案

### 运行时表达式错误

**问题：** Map 在运行时抛出表达式错误
**解决方案：** 在开发过程中使用 `validate_expression_tool` 验证表达式
**预防：** 在预提交钩子或 CI/CD 中添加表达式验证

### 文本可读性差

**问题：** 文本标签在地图上难以阅读
**解决方案：** 使用 `check_color_contrast_tool` 检查对比度，调整颜色以符合 WCAG AA
**预防：** 在浅色和深色背景下测试文本，检查不同缩放级别

### 样式文件过大

**问题：** 样式加载或传输时间长
**解决方案：** 运行 `optimize_style_tool` 以删除冗余并简化
**预防：** 在开发过程中定期优化，立即删除未使用的源

### 无效的 GeoJSON 源

**问题：** GeoJSON 源无法加载或渲染
**解决方案：** 使用 `validate_geojson_tool` 验证，修复坐标问题，验证结构
**预防：** 在添加到样式之前验证所有外部 GeoJSON

### 预期之外的样式更改

**问题：** 样式已更改但不确定修改了什么
**解决方案：** 使用 `compare_styles_tool` 生成差异报告
**预防：** 对所有重大更改进行前后比较，记录修改

| `optimize_style_tool`       | 部署前              | 优化后的样式 + 节省      |
