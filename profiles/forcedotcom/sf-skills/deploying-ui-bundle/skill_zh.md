# 部署 UI Bundle

在 Salesforce 组织中部署时，操作顺序至关重要。此顺序反映了规范流程。

## 第 1 步：组织认证

检查组织是否已连接。如果没有，请进行认证。后续所有步骤都需要已认证的组织。

## 第 2 步：预部署 UI Bundle 构建

安装依赖项并构建 UI Bundle 以生成 `dist/`。在部署 UI Bundle 实体之前必须执行此步骤。

运行时机：部署 UI Bundle 且 `dist/` 目录不存在或源代码已更改。

## 第 3 步：部署元数据

首先检查是否存在清单（`manifest/package.xml` 或 `package.xml`）。如果存在，则使用清单进行部署。如果不存在，则从项目中部署所有元数据。

部署对象、布局、权限集、Apex 类、UI Bundle 以及所有其他元数据。必须在模式获取之前完成——模式反映了组织的状态。

## 第 4 步：部署后配置

部署不等于分配。部署后：

- **权限集 / 组** — 分配给用户，以便他们可以访问自定义对象和字段。这对于 GraphQL 内省返回正确的模式是必需的。
- **配置文件** — 确保用户具有正确的配置文件。
- **其他配置** — 命名凭证、连接应用、自定义设置、流程激活。

主动行为：成功部署后，在 `force-app/main/default/permissionsets/` 中发现权限集，并为每个权限集分配（或询问用户）。

## 第 5 步：数据导入（可选）

仅当存在 `data/data-plan.json` 时。删除操作将按反向计划顺序执行（子项在父项之前）。导入使用启用重复规则保存的匿名 Apex。

导入或清理数据前，始终询问用户。

## 第 6 步：GraphQL 模式和代码生成

1. 设置默认组织
2. 获取模式（GraphQL 内省）— 在项目根目录下写入 `schema.graphql`
3. 生成类型（代码生成器读取本地模式）

运行时机：模式缺失，或自上次获取以来元数据/权限已更改。

## 第 7 步：最终 UI Bundle 构建

如果第 2 步中未构建 UI Bundle，则进行构建。

## 摘要：交互顺序

1. 检查/认证组织
2. 构建 UI Bundle（如果部署 UI Bundle）
3. 部署元数据
4. 分配权限并配置
5. 导入数据（如果存在数据计划，并经用户确认）
6. 获取 GraphQL 模式并运行代码生成
7. 构建 UI Bundle（如果需要）

## 关键规则

- 部署元数据 **在** 获取模式 **之前** — 自定义对象/字段仅在部署后出现
- 分配权限 **在** 获取模式 **之前** — 用户可能缺乏自定义字段的 FLS
- 每次部署更改对象、字段或权限的元数据后，重新运行模式获取和代码生成
- 不要静默跳过权限集分配或数据导入 — 要么运行它们，要么询问用户

## 部署后检查清单

每次成功部署元数据后：

1. 发现并分配权限集（或询问用户）
2. 如果存在 `data/data-plan.json`，询问用户关于数据导入
3. 从 UI Bundle 目录重新运行模式获取和代码生成
