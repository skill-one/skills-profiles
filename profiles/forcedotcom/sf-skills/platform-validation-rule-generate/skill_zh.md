## 何时使用此技能

当您需要执行以下操作时，请使用此技能：
- 创建验证规则以强制执行数据质量
- 防止无效记录被保存
- 使用公式生成验证规则元数据
- 为对象添加业务逻辑验证
- 排查与验证规则相关的部署错误

## 规格

# 验证规则元数据规格

### 概述
验证规则是 Salesforce 中用于强制执行数据质量和业务逻辑的声明式元数据组件。它们在记录保存时评估公式表达式，如果表达式返回 TRUE 则阻止保存操作。

### 目的
- 在数据层强制执行业务规则
- 防止无效或不完整的记录被保存
- 向用户显示有意义的错误消息以指导用户

### 必须属性

#### 核心验证规则属性

- **fullName**
    - 验证规则的唯一 API 名称
    - 必须以字母开头
        - 可以包含字母、数字和下划线
    - 不能以下划线结尾
    - 不能包含连续的下划线
    - 不能超过 40 个字符。

- **active**
  - 指示验证规则是否启用
  true → 规则被强制执行
  false → 规则处于非活动状态

- **errorConditionFormula**
- 评估记录数据的逻辑公式
- 必须返回 TRUE 或 FALSE
- 如果为 TRUE，验证规则将触发错误

- **errorMessage**
    - 验证失败时向用户显示的消息
- 最大长度：255 个字符

### 具体功能指南
- TEXT - TEXT() 函数不得与文本字段一起使用，要修复此问题，只需删除 TEXT() 函数。
- CASE - 在 Salesforce 的 CASE() 函数中，最后一个参数是默认值。管理员经常遗漏提供此参数，CASE() 函数的参数数量总是偶数。
- VALUE - VALUE() 函数仅应与文本字段一起使用。如果数字被用作 VALUE() 函数的参数，请删除 VALUE() 函数。
- DAY - DAY() 函数仅应与日期字段一起使用。如果日期时间字段被用作 DAY() 函数的参数，请先将其转换为日期。
- MONTH - MONTH() 函数仅应与日期字段一起使用。如果日期时间字段被用作 MONTH() 函数的参数，请先将其转换为日期。
- DATEVALUE - DATEVALUE() 函数仅应与日期时间字段一起使用。如果日期被用作 DATEVALUE() 函数的参数，请删除 DATEVALUE() 函数。
- ISPICKVAL - 如果检查 picklist 类型字段的相等性，必须使用 ISPICKVAL() 函数。
- ISCHANGE - 使用 ISCHANGE() 函数检查记录的值是否已更改。

### 关键规则
1. 公式 XML 处理（最常见错误）
    - 任何包含 XML 标签的 errorConditionFormula 必须在元数据 XML 中的 CDATA 部分内。

2. “更新”指令的解释。在收到修改公式的指令时，区分替换和添加：
    - “将公式更新为 [操作]”：用新要求完全替换现有的公式逻辑。
    - “将公式更新为也要 [操作]”：保留现有逻辑并追加新要求（通常通过将逻辑包装在 AND() 或 OR() 函数中）。

3. 文件格式要求
    - 验证规则文件必须始终使用 `.validationRule-meta.xml` 扩展名。
