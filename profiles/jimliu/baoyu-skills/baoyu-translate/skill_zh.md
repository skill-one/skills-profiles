# 翻译器

三模式翻译技能：**快速**用于直接翻译，**普通**用于分析辅助翻译，**精炼**用于完整出版质量工作流，包含审阅和润色。

## 用户输入工具

当此技能提示用户时，请遵循以下工具选择规则（优先级顺序）：

1. **优先使用当前代理运行时暴露的内置用户输入工具** — 例如，`AskUserQuestion`、`request_user_input`、`clarify`、`ask_user` 或任何等效工具。
2. **降级**：如果不存在此类工具，则发出编号的纯文本消息，并要求用户回复选择的编号/答案以回答每个问题。
3. **批处理**：如果工具支持每调用一次询问多个问题，则将所有适用问题合并为单个调用；如果仅支持单个问题，则按优先级顺序逐个询问。

下文中的具体 `AskUserQuestion` 引用是示例 — 在其他运行时中替换本地等效项。

## 脚本目录

位于 `scripts/` 子目录中的脚本。`{baseDir}` = 此 SKILL.md 的目录路径。解析 `${BUN_X}` 运行时：如果安装了 `bun` → `bun`；如果 `npx` 可用 → `npx -y bun`；否则建议安装 bun。用实际值替换 `{baseDir}` 和 `${BUN_X}`。

| 脚本 | 目的 |
|------|------|
| `scripts/main.ts` | CLI 入口点。默认操作将 Markdown 分割成块；也支持显式的 `chunk` 子命令 |
| `scripts/chunk.ts` | 由 `main.ts` 使用并由 `main.ts` 保持兼容的 Markdown 分块实现 |

## 偏好设置 (EXTEND.md)

按优先级顺序检查 EXTEND.md — 第一个找到的优先：

| 优先级 | 路径 | 范围 |
|----------|------|-------|
| 1 | `.baoyu-skills/baoyu-translate/EXTEND.md` | 项目 |
| 2 | `${XDG_CONFIG_HOME:-$HOME/.config}/baoyu-skills/baoyu-translate/EXTEND.md` | XDG |
| 3 | `$HOME/.baoyu-skills/baoyu-translate/EXTEND.md` | 用户主目录 |

| 结果 | 操作 |
|--------|--------|
| 找到 | 读取、解析、应用。在会话中第一次使用时，简要提醒： "使用来自 [路径] 的偏好设置。您可以编辑 EXTEND.md 来自定义术语表、受众等。" |
| 未找到 | **必须** 运行首次设置（见下文） — 不要静默使用默认值 |

**EXTEND.md 支持**：默认目标语言、默认模式、目标受众、自定义术语表（内联或文件路径）、翻译风格、块设置。

架构：[参考资料/config/extend-schema.md](参考资料/config/extend-schema.md)。

### 首次设置（阻塞）

**关键**：当 EXTEND.md 未找到时，您**必须**在执行任何翻译之前运行首次设置。这是一个 **阻塞** 操作。

完整参考：[参考资料/config/first-time-setup.md](参考资料/config/first-time-setup.md)

使用 `AskUserQuestion` 在一次调用中回答所有问题（目标语言、模式、受众、风格、保存位置）。用户回答后，在选定位置创建 EXTEND.md，确认 "偏好设置已保存到 [路径]"，然后继续。

## 默认值

所有可配置值集中在一个地方。EXTEND.md 覆盖这些；CLI 标志覆盖 EXTEND.md。

| 设置 | 默认值 | EXTEND.md 键 | CLI 标志 | 描述 |
|---------|---------|---------------|----------|-------------|
| 目标语言 | `zh-CN` | `target_language` | `--to` | 翻译目标语言 |
| 模式 | `normal` | `default_mode` | `--mode` | 翻译模式 |
| 受众 | `general` | `audience` | `--audience` | 目标读者画像 |
| 风格 | `storytelling` | `style` | `--style` | 翻译风格偏好 |
| 块阈值 | `4000` | `chunk_threshold` | — | 触发分块翻译的词数 |
| 块最大词数 | `5000` | `chunk_max_words` | — | 每个块的最大词数 |

## 模式

| 模式 | 标志 | 步骤 | 使用场景 |
|------|------|-------|-------------|
| 快速 | `--mode quick` | 翻译 | 短文本、非正式内容、快速任务 |
| 普通 | `--mode normal` (默认) | 分析 → 翻译 | 文章、博客文章、一般内容 |
| 精炼 | `--mode refined` | 分析 → 翻译 → 审阅 → 润色 | 出版质量、重要文档 |

**默认模式**：普通（可以在 EXTEND.md `default_mode` 设置中覆盖）。

**风格预设** — 控制翻译的声音和语气（独立于受众）：

| 值 | 描述 | 效果 |
|-------|-------------|--------|
| `storytelling` | 生动的故事性流程（默认） | 吸引读者，流畅过渡，生动的措辞 |
| `formal` | 专业、结构化 | 中性语气，清晰组织，无俚语 |
| `technical` | 精确、文档风格 | 简洁，术语密集，最小化装饰 |
| `literal` | 接近原始结构 | 最小化重构，保留源句模式 |
| `academic` | 学术、严谨 | 正式语体，允许复杂从句，注意引用 |
| `business` | 简洁、结果导向 | 行动导向，面向高管，要点思维 |
| `humorous` | 保留并适应幽默 | 机智，俏皮，在目标语言中重现喜剧效果 |
| `conversational` | 非正式、口语化 | 友好，易接近，如同向朋友解释 |
| `elegant` | 文学、精致散文 | 美学精致，韵律感，精心措辞 |

也接受自定义风格描述，例如，`--style "诗意和韵律"`。

**自动检测**：
- "快翻", "quick", "直接翻译" → 快速模式
- "精翻", "refined", "出版质量", "校对" → 精炼模式
- 其他情况 → 默认模式（普通）

**升级提示**：普通模式完成后，显示：
> 翻译已保存。要进一步审阅和润色，回复 "继续润色" 或 "refine"。

如果用户回复，继续执行审阅 → 润色步骤（与 refined-workflow.md 中精炼模式步骤 4-6 相同）在现有输出上。

**受众预设**：

| 值 | 描述 | 效果 |
|-------|-------------|--------|
| `general` | 一般读者（默认） | 平凡语言，更多翻译者注释以解释术语 |
| `technical` | 开发人员 / 工程师 | 对常见技术术语减少注释 |
| `academic` | 研究人员 / 学者 | 正式语体，精确术语 |
| `business` | 商业专业人士 | 商业友好语气，解释技术概念 |

也接受自定义受众描述，例如，`--audience "AI感兴趣的普通读者"`。

## 工作流

### 第 1 步：加载偏好设置

1.1 检查 EXTEND.md（见上文的偏好设置部分）

1.2 如果可用，加载语言对内置术语表：
- EN→ZH: [参考资料/glossary-en-zh.md](参考资料/glossary-en-zh.md)

1.3 合并术语表：EXTEND.md `glossary`（内联）+ EXTEND.md `glossary_files`（外部文件，相对于 EXTEND.md 位置的路径）+ 内置术语表 + `--glossary` 文件（CLI 覆盖所有）

### 第 2 步：材料化源文件并创建输出目录

材料化源文件（文件原样保存，内联文本/URL → 保存到 `translate/{slug}.md`），然后创建输出目录：`{source-dir}/{source-basename}-{target-lang}/`。如果未指定 `--from`，则检测源语言。

完整细节：[参考资料/workflow-mechanics.md](参考资料/workflow-mechanics.md)

**输出目录内容**（所有中间和最终文件都放在这里）：

| 文件 | 模式 | 描述 |
|------|------|-------------|
| `translation.md` | 所有 | 最终翻译（始终使用此名称） |
| `01-analysis.md` | 普通、精炼 | 内容分析（领域、语气、术语） |
| `02-prompt.md` | 普通、精炼 | 组合翻译提示 |
| `03-draft.md` | 精炼 | 审阅之前的初始草稿 |
| `04-critique.md` | 精炼 | 关键审阅发现（仅诊断） |
| `05-revision.md` | 精炼 | 基于审阅修订的翻译 |
| `chunks/` | 分块 | 源块 + 翻译块 |

### 第 3 步：评估内容长度

快速模式不进行分块 — 无论长度如何直接翻译。翻译前估计词数。如果内容超过块阈值（默认 4000 词），主动提醒： "这篇文章大约有 {N} 词。快速模式一次性通过而不分块翻译 — 对于长内容，`--mode normal` 产生更好的结果并保持术语一致性。" 然后如果用户不切换，则继续。

对于普通和精炼模式：

| 内容 | 操作 |
|---------|--------|
| < 块阈值 | 作为单个单元翻译 |
| >= 块阈值 | 分块翻译（见第 3.1 步） |

**3.1 长内容准备**（普通/精炼模式，仅 >= 块阈值）

在翻译块之前：

1. **提取术语**：扫描整个文档以查找专有名词、技术术语、重复短语
2. **构建会话术语表**：合并提取的术语与加载的术语表，建立一致的翻译
3. **分块**：使用 `${BUN_X} {baseDir}/scripts/main.ts <file> [--max-words <chunk_max_words>] [--output-dir <output-dir>]`
   - 解析 Markdown 块（标题、段落、列表、代码块、表格等）
   - 在 Markdown 块边界处分割以保留结构
   - 如果单个块超过阈值，则回退到行分割，然后是词分割
4. **组合翻译提示**：
   - 主代理读取 `01-analysis.md`（如果存在）并使用 [参考资料/subagent-prompt-template.md](参考资料/subagent-prompt-template.md) 的第一部分组装共享上下文 — 内联：目标风格、内容背景、合并术语表和翻译挑战
   - 保存为 `02-prompt.md` 在输出目录（仅共享上下文，无任务指令）
5. **通过子代理起草翻译**（如果代理工具可用）：
   - 每个块启动一个子代理，所有并行（模板的第二部分）
   - 每个子代理读取 `02-prompt.md` 以获取共享上下文，接收块位置信息（块 N/M + 它在其中的简要上下文），翻译其块，保存到 `chunks/chunk-NN-draft.md`
   - 通过共享 `02-prompt.md`（术语表、比喻语言映射、理解挑战、源声音和翻译挑战）保证一致性
   - 如果没有块（内容低于阈值）：为整个源文件启动一个子代理
   - 如果代理工具不可用，使用 `02-prompt.md` 逐行翻译块
6. **合并**：所有子代理完成后，按顺序组合翻译块。如果存在 `chunks/frontmatter.md`，则添加到开头。保存为 `03-draft.md`（精炼）或 `translation.md`（普通）
7. 所有中间文件（源块 + 翻译块）都保存在 `chunks/`

**分块草稿合并后**，将控制权返回给主代理进行关键审阅、修订和润色（第 4 步）。

### 第 4 步：翻译和润色

**翻译原则**（适用于所有模式）：

- **重写，而不是翻译**：像熟练的母语作家从头开始创作一样，将内容重写为自然、引人入胜的目标语言。质量测试： "这读起来像它原本就是用目标语言写的吗？"
- **准确性优先**：事实、数据和逻辑必须与原文完全匹配
- **自然流畅**：使用目标语言的惯用词序。将长源句拆分成更短、自然的句子。解释隐喻和习语时，根据预期含义，而不是逐字解释
- **术语**：使用标准翻译并保持一致。专业术语的首次出现：用括号标注原文
- **保留格式**：保留所有 Markdown 格式（标题、粗体、斜体、图片、链接、代码块）
- **主动解释**：对于目标受众可能缺乏上下文的知识或概念，在 **粗体括号** `（**解释**）` 中添加简洁的解释。保留注释很少 — 仅在确实需要理解时才添加
- **前导信息**：如果源文件有 YAML 前导信息，则将源元数据字段用 `source` 前缀重命名（驼峰命名：`url`→`sourceUrl`，`title`→`sourceTitle`，等），将翻译值作为新的顶级字段添加（如果正文有 H1，则跳过 `title`），其他字段保持不变

#### 快速模式

直接翻译 → 保存到 `translation.md`。应用上述所有翻译原则。

#### 普通模式

1. **分析** → `01-analysis.md`（领域、语气、术语、翻译挑战）
2. **组合提示** → `02-prompt.md`（带上下文的翻译指令、术语表、挑战）
3. **翻译**（遵循 `02-prompt.md`）→ `translation.md`

完成后，提示用户： "翻译已保存。要进一步审阅和润色，回复 **继续润色** 或 **refine**。"

如果用户继续，则继续执行关键审阅 → 修订 → 润色（与下文精炼模式步骤 4-6 相同），保存 `03-draft.md`（重命名当前的 `translation.md`），`04-critique.md`，`05-revision.md`，以及更新的 `translation.md`。

#### 精炼模式

完整工作流用于出版质量。有关每一步的详细指南，请参阅 [参考资料/refined-workflow.md](参考资料/refined-workflow.md)。

子代理（如果在第 3.1 步中使用）仅处理初始草稿。所有后续步骤（关键审阅、修订、润色）由主代理处理，主代理可根据需要委派给子代理。

步骤和保存文件（所有在输出目录中）：
1. **分析** → `01-analysis.md`（领域、语气、术语、翻译挑战）
2. **组合提示** → `02-prompt.md`（带内联上下文的翻译指令）
3. **草稿** → `03-draft.md`（审阅前的初始翻译；如果分块，则来自子代理）
4. **关键审阅** → `04-critique.md`（仅诊断：准确性、欧洲化语言、策略执行、表达问题）
5. **修订** → `05-revision.md`（应用所有审阅发现以生成修订翻译）
6. **润色** → `translation.md`（最终出版质量翻译）

每一步都读取前一步的文件并在此基础上构建。

### 第 5 步：输出

最终翻译始终位于输出目录中的 `translation.md`。

在最终翻译写入后，进行轻量级的图像语言检查：

1. 从翻译文章中收集图像引用
2. 识别可能包含与翻译文章语言不匹配的主要文本语言的图像，例如封面、截图、图表、框架和信息图
3. 如果任何图像可能包含与翻译文章语言不匹配的主要文本语言，则主动提醒用户
4. 提醒必须是一个列表。不要自动本地化这些图像，除非用户要求

提醒格式（使用文章中已有的图像语法 — 标准 Markdown 或 wikilink）：
```text
可能需要图像本地化：
- ![示例封面](attachments/example-cover.png)：可能仍然包含源语言文本，而文章现在使用目标语言
- ![示例图表](attachments/example-diagram.png)：可能是文本密集的框架图形，检查标签是否需要翻译
```

显示摘要：
```
**翻译完成** ({mode} 模式)

源文件：{source-path}
语言：{from} → {to}
输出目录：{output-dir}/
最终：{output-dir}/translation.md
应用术语表数量：{count}
```

如果找到不匹配的图像语言候选，则在摘要后附加一条简短说明，告诉用户某些嵌入图像可能仍需图像文本本地化，然后是候选列表。
