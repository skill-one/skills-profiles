# Markdown 格式化工具

将纯文本或 Markdown 转换为结构良好、易于阅读的 Markdown。目标是帮助读者快速把握要点、重点和结构——而不改变任何原始内容。

**核心原则**：仅调整格式并修正明显的错别字。绝不添加、删除或重写内容。

## 用户输入工具

当此技能提示用户时，请遵循以下工具选择规则（优先级顺序）：

1. **优先使用**当前代理运行时暴露的内置用户输入工具——例如，`AskUserQuestion`、`request_user_input`、`clarify`、`ask_user` 或任何等效工具。
2. **降级**：如果没有此类工具，则发出编号的纯文本消息，并要求用户对每个问题回复选择的编号/答案。
3. **批量处理**：如果工具支持每调用一次询问多个问题，则将所有适用问题组合为单个调用；如果仅支持单个问题，则按优先级顺序逐一询问。

下方的具体 `AskUserQuestion` 引用仅为示例——在其他运行时中替换本地等效工具。

## 脚本目录

位于 `scripts/` 子目录中的脚本。`{baseDir}` = 此 SKILL.md 的目录路径。解析 `${BUN_X}` 运行时：如果安装了 `bun` → `bun`；如果可用 `npx` → `npx -y bun`；否则建议安装 bun。用实际值替换 `{baseDir}` 和 `${BUN_X}`。

| 脚本 | 目的 |
|------|------|
| `scripts/main.ts` | 具有命令行选项的主入口点（使用 remark-cjk-friendly 进行 CJK 强调） |
| `scripts/quotes.ts` | 将 ASCII 引号替换为全角引号 |
| `scripts/autocorrect.ts` | 通过自动更正添加 CJK/英文间距 |

| 设置 | 值 | 默认值 | 描述 |
|------|-----|--------|-------|
| `auto_select` | `true`/`false` | `false` | 跳过标题和摘要选择，自动选择最佳 |

| `auto_select_summary` | `true`/`false` | `false` | 仅跳过摘要选择 |
| 其他 | — | — | 默认格式化选项，排版偏好 |

## 使用方法

工作流程分为两个阶段：**分析**（理解内容）然后 **格式化**（应用格式）。Claude 执行内容分析和格式化（步骤 1-5），然后运行脚本进行排版修复（步骤 6）。

## 工作流程

### 步骤 1：读取并检测内容类型

读取用户指定的文件，然后检测内容类型：

| 指示器 | 分类 |
|--------|-------|
| 具有 `---` YAML 前置 | Markdown |
| 具有 `#`、`##`、`###` 标题 | Markdown |
| 具有 `**粗体**`、`*斜体*`、列表、代码块、引用块 | Markdown |
| 以上均无 | 纯文本 |

**如果检测到 Markdown，使用 `AskUserQuestion` 询问：**

```
检测到现有的 Markdown 格式化。您希望做什么？

1. 优化格式化（推荐）
   - 分析内容，改进标题、粗体、列表以提高可读性
   - 运行排版脚本（间距、强调修复）
   - 输出：{filename}-formatted.md

2. 保留原始格式化
   - 保留现有的 Markdown 结构
   - 仅运行排版脚本
   - 输出：{filename}-formatted.md

3. 仅排版修复
   - 在原始文件上原地运行排版脚本
   - 不创建副本，直接修改原始文件
```

**根据用户选择：**
- **优化**：继续到步骤 2（完整工作流程）
- **保留原始**：跳到步骤 5，复制文件然后运行步骤 6
- **仅排版**：跳到步骤 6，直接在原始文件上运行

### 步骤 2：分析内容（读者的视角）

仔细阅读全部内容。从读者的角度思考：什么能帮助他们快速理解和记忆关键信息？

生成涵盖以下维度的分析：

**2.1 重点和关键见解**
- 作者提出的核心论点或结论
- 令人惊讶的事实、数据点或反直觉的声明
- 值得记忆的引言或精心措辞的句子（黄金引言）

**2.2 结构评估**
- 内容是否有清晰的逻辑流程？是什么？
- 是否存在缺少标题的自然章节边界？
- 是否有需要视觉分隔的长文本块？

**2.3 读者重要信息**
- 可操作的建议或要点
- 定义、关键概念的解释
- 被散文埋没的列表或枚举
- 比较或对比，如果以表格形式会更清晰

**2.4 格式化问题**
- 缺少或不一致的标题层级
- 混合多个主题的段落
- 并列项以散文形式而不是列表书写
- 代码、命令或技术术语未标记为代码
- 明显的错别字或格式错误

**保存分析到文件**：`{original-filename}-analysis.md`

分析文件作为步骤 3 的蓝图。使用此格式：

```markdown
# 内容分析：{filename}

## 重点和关键见解
- [列出发现]

## 结构评估
- 当前流程：[描述]
- 建议的章节：[列出标题候选，附简要理由]

## 读者重要信息
- [列出可操作项、关键概念、被埋没的列表、潜在的表格]

## 格式化问题
- [列出具体问题及位置参考]

## 错别字发现
- [列出任何明显的错别字及修正，或“未发现”]
```

### 步骤 3：检查/创建前缀、标题和摘要

检查是否存在 YAML 前置 (`---` 块)。如果缺失则创建。

| 字段 | 处理 |
|------|------|
| `title` | 见下文 **标题生成** |
| `slug` | 从文件路径推断或从标题生成 |
| `summary` | 一句简短的摘要（见下文 **摘要生成**） |
| `description` | 更长的描述性摘要（见下文 **摘要生成**） |
| `coverImage` | 检查同一目录下是否存在 `imgs/cover.png`；如果存在，使用相对路径 |

#### 标题生成

无论标题是否存在，除非 `auto_select_title` 设置为 `true`，否则运行标题优化流程。

**准备**——读取全文并提取：
- 核心论点（一句话：“这篇文章是关于什么的？”）
- 最有影响力的观点或结论
- 读者的痛点或好奇心触发点
- 最令人难忘的隐喻或黄金引言

**生成候选**：使用 `references/title-formulas.md` 中的公式：

1. 根据文章的内容、语气和结构，选择 **2-3 个最匹配的钩子公式**（参考中“何时选择每个公式”部分）
2. 生成 **1-2 个直白的标题**（描述性或声明性，无公式——清晰准确）
3. 如果用户指定方向（例如，“使其充满悬念”），则优先考虑该方向
4. 总计：**4-5 个候选**

通过 `AskUserQuestion` 提示：

```
选择一个标题：

1. [钩子标题 A] — (推荐) [公式名称]
2. [钩子标题 B] — [公式名称]
3. [钩子标题 C] — [公式名称]
4. [直白标题 D] — 直白
5. [直白标题 E] — 直白

输入编号，或输入自定义标题：
```

将最强的钩子放在第一位并标记为 `(推荐)`。参考 `references/title-formulas.md` 了解原则和禁止模式。

如果第一行是 H1，则提取到前缀并从正文移除。如果前缀中已有 `title`，则将其作为上下文但仍然生成新候选——现有标题可能较弱。

**跳过行为**：如果 `auto_select: true` 或 `auto_select_title: true`，则跳过用户提示并直接使用顶级候选。

#### 摘要生成

直接生成两个版本（无需用户选择），均存储在前缀中：

| 字段 | 长度 | 目的 |
|------|------|------|
| `summary` | 1 句话，~50-80 字符 | 简洁的钩子——用于信息流、社交分享、SEO 元数据 |
| `description` | 2-3 句话，~100-200 字符 | 更丰富的上下文——用于文章预览、简报 |

**原则**：

- 向读者传达 **核心价值**，而不仅仅是主题
- 使用具体细节（数字、结果、具体方法）而不是模糊描述
- `summary` 应简洁自包含；`description` 可以扩展支持细节
- 如果前缀中已有 `summary` 或 `description`，则保留现有值并仅生成缺失字段

**禁止模式**：

- "本文介绍了..."、"本文探讨了..."
- 没有价值主张的纯主题描述
- 用不同词语重复标题

一旦标题进入前缀，正文不应包含 H1（避免重复）。

### 步骤 4：格式化内容

根据步骤 2 的分析应用格式。目标是使内容可扫描，关键点无法被忽略。

**格式化工具箱**：

| 元素 | 使用时机 | 格式 |
|------|----------|------|
| 标题 | 自然主题边界、章节分隔 | `##`、`###` 层级 |
| 粗体 | 关键结论、重要术语、核心要点 | `**粗体**` |
| 无序列表 | 并列项、功能列表、示例 | `- 项目` |
| 有序列表 | 顺序步骤、排名项、程序 | `1. 项目` |
| 表格 | 比较、结构化数据、选项矩阵 | Markdown 表格 |
| 代码 | 命令、文件路径、技术术语、变量名 | `` `内联` `` 或 fenced blocks |
| 引用块 | 值得注意的引言、重要警告、引用文本 | `> 引言` |
| 分隔符 | 主要主题转换 | `---` |

**格式化原则——不要做：**
- 不要添加句子、解释或评论
- 不要删除或缩短任何内容
- 不要改写作者的原话
- 不要添加编辑性标题（例如，“惊人的发现”——使用中性的描述性标题）
- 不要过度格式化：不是每个句子都需要粗体，不是每个段落都需要标题

**格式化原则——要做什么：**
- 保留作者的风格、语气和每个字
- **粗体关键结论和核心要点**——读者会高亮的句子
- 仅当结构明显时，从散文中提取并列项到列表
- 在主题真正转换时添加标题——优先使用生动具体的标题而不是通用标题（例如，“3 天搞定 vs 传统方案”优于“方案对比”）
- 使用表格比较或埋没在散文中的结构化数据
- 使用引用块用于黄金引言、令人难忘的声明或重要警告
- 修正明显的错别字（基于步骤 2 的发现）

### 步骤 5：保存格式化文件

保存为 `{original-filename}-formatted.md`

**备份现有文件**：

```bash
if [ -f "{filename}-formatted.md" ]; then
  mv "{filename}-formatted.md" "{filename}-formatted.backup-$(date +%Y%m%d-%H%M%S).md"
fi
```

### 步骤 6：执行排版脚本

对输出文件运行格式化脚本：

```bash
${BUN_X} {baseDir}/scripts/main.ts {output-file-path} [选项]
```

**脚本选项**：

| 选项 | 短 | 描述 | 默认值 |
|------|----|------|--------|
| `--quotes` | `-q` | 将 ASCII 引号替换为全角引号 `"..."` | `false` |
| `--no-quotes` | | 不替换引号 | |
| `--spacing` | `-s` | 通过自动更正添加 CJK/英文间距 | `true` |
| `--no-spacing` | | 不添加 CJK/英文间距 | |
| `--emphasis` | `-e` | 修正 CJK 强调标点问题 | `true` |
| `--no-emphasis` | | 不修正 CJK 强调问题 | |

**示例**：

```bash
# 默认：间距 + 强调启用，引号禁用
${BUN_X} {baseDir}/scripts/main.ts article.md

# 启用所有功能，包括引号替换
${BUN_X} {baseDir}/scripts/main.ts article.md --quotes

# 仅修复强调问题，跳过间距
${BUN_X} {baseDir}/scripts/main.ts article.md --no-spacing
```

**脚本执行（基于选项）：**
1. 修正 CJK 强调/粗体标点问题（默认：启用）
2. 通过自动更正添加 CJK/英文混合文本间距（默认：启用）
3. 将 ASCII 引号替换为全角引号（默认：禁用）
4. 格式化前缀 YAML（始终启用）

### 步骤 7：完成报告

显示总结所有已做更改的报告：

```
**格式化完成**

**文件：**
- 分析：{filename}-analysis.md
- 格式化：{filename}-formatted.md

**内容分析摘要：**
- 重点发现：X 个关键见解
- 黄金引言：X 句令人难忘的句子
- 修复的格式化问题：X 项

**已应用更改：**
- 前缀：[添加/更新] (标题、slug、摘要)
- 添加标题：X (##: N, ###: N)
- 添加粗体标记：X
- 创建列表：X (从散文→列表转换)
- 创建表格：X
- 添加代码标记：X
- 添加引用块：X
- 修正错别字：X [列出每个："原始" → "修正"]

**排版脚本：**
- CJK 间距：[应用/跳过]
- 强调修复：[应用/跳过]
- 引号替换：[应用/跳过]
```

根据实际更改调整报告——未做更改的类别应省略。

## 注意事项

- 保留原始写作风格和语气
- 指定代码块的正确语言（例如，`python`、`javascript`）
- 维持 CJK/英文间距标准
- 分析文件是工作文档——它有助于保持识别和格式化之间的一致性
