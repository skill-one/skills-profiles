# CAD Viewer

来源：维护在 [earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad)。
使用已安装的本地技能文件作为运行时真实来源；仓库链接仅用于来源和发布审核。如果用户要求修改、调试或迭代 CAD Viewer 本身的源代码，那是仓库的工作，而不是这个技能的——这个技能运行 Viewer，它不是你编辑它的地方。

使用此技能在 CAD Viewer 中打开现有的或新生成的 CAD、机器人描述或 DXF 文件，并返回可实时预览的链接。预期的输入是一个或多个明确的文件路径。

## 安装

Viewer 是 `cadgen` 的一部分：将此技能的 `requirements.txt` 安装到 Python >= 3.11 中，`cadgen` 命令会携带服务器和预构建客户端。运行时没有其他需要安装的，也没有 Node。

```bash
python -m pip install -r requirements.txt
```

`cadgen doctor <此技能的目录>` 确认安装的 cadgen 与此技能发布时对应的版本匹配。

## 启动 Viewer

启动是无条件的：下面的命令始终以启动目录的实时 Viewer URL 结尾。如果已经为该目录运行了相同磁盘上的 Viewer 代码（重用键是 realpath(directory) x 一个身份令牌——cadgen 版本加上其 Python 运行时和精确构建客户端的内容摘要，因此升级的 Viewer 或不同的 `--dist` 从不返回过时的实例），则返回其 URL (`"action": "reused"`）；否则，在从 `3245` 向上的第一个空闲端口上启动新的服务器 (`"action": "started"`)。永远不要选择或推理端口——读取命令打印的 URL。每个实例服务于一个目录——它从其中启动的目录——在进程生命周期中固定不变。没有标志为此：当前工作目录 (cwd) 就是服务目录。

> 基本端口 `3245` 是 `0xCAD`——十六进制中的 "CAD"。

```bash
cd /absolute/project/models && cadgen viewer --host 127.0.0.1 --json
```

(`cadgen` 必须是从此技能的 `requirements.txt` 安装的。如果不在 `PATH` 中，`python -m cadgen.viewer` 使用该解释器与启动器相同。)

**故意选择启动目录——这是整个游戏的关键。** cwd 决定目录扫描的内容（一个项目根目录会拉入 `node_modules`、`.git` 和构建输出），并且是实例重用键，因此从你碰巧所在的地方启动可能会返回一个为其他地方服务的 Viewer。切换到用户认为的模型工作区目录——通常是项目的 `models/` 目录——并从那里启动。永远不要在技能目录内启动：那服务于技能，而不是模型。

标志：`--json` 打印机器可读的最后一行 stdout (`{"url", "port", "action": "started"|"reused"}`) —— 始终传递它并从那里获取 URL。`--new` 强制全新实例而不是重用。显式的 `--port <n>` 是严格的——"这个端口或失败"——并禁用重用和滚动。`cadgen viewer --help` 列出其余内容。

## URL 格式

页面是裸露的起源，`file=` 选择服务根目录中的一个工件：

```text
http://127.0.0.1:3245/?file=gripper/STEP/gear_rack_gripper.step
```

`file=` 值相对于服务目录。目录的任何信息都不会出现在 URL 中，因此相同的链接在不同实例下可能表示不同的文件——根目录是服务器的，不是链接的。

**启动目录是工作区，不是文件的文件夹。** Viewer 递归扫描它，因此文件浏览器会列出它下面的所有模型，用户可以在不使用新链接的情况下切换文件。从用户认为的模型工作区目录启动——通常是项目的 `models/` 目录，或你被要求审查的文件的最近公共父目录——并将其余路径放在 `file=` 中。从工件的深层次文件夹启动 (`cd .../models/gripper/STEP`, `?file=gear_rack_gripper.step`) 打开相同的模型但隐藏项目的其余部分，这几乎不是用户想要的。

端口冲突不是你的问题：启动器会滚动到空闲端口，并且它打印的 URL 是事实。在沙盒化代理环境中，本地绑定失败（如 `EPERM`/`EACCES`）仍然可能发生；使用所需的权限/提升权限重新运行。

`cadgen viewer list` 显示每个运行实例及其服务的目录；`cadgen viewer stop --port <n>` 结束一个。两者都可以从任何地方运行——只有启动才关心 cwd。)

要审查当前根目录之外的目录，只需 `cd` 到那里并重新启动——重用或启动使第二次启动廉价且正确。

## 生成是 CAD 技能的工作；文档在 Viewer 中编译

Viewer 是一个静态可视化工具：它渲染已存在的工件。生成的模型必须首先通过运行它们的模型脚本（见 CAD 技能）构建；Viewer 从不运行脚本，也永远不会知道一个文档是否有脚本。

`.step`/`.stp` 文档在 Viewer 中的状态有四种，由文件的字节和存储决定：**未编译**（存储中没有这些字节的树——Viewer 提供编译，并在打开时编译）、**编译中 · <阶段> n/总**（cadgen 的构建池中的一个任务正在生成一个包含此文档的树——Viewer 的编译、终端中的 `python model.py` 或父级的类似子构建）、**已渲染** 或 **失败**（最后一个任务失败；显示消息）。编译是提交到 cadgen 的每个门使用的相同池中的一个任务，因此进度和错误作为数据返回。没有 "过时与源" 状态：一个文档是否落后于其脚本是由 `cadgen store why` 提问的，而不是 Viewer 的。当代理正在做工作时没有需要首先运行的：只需使用文件并返回链接。

## 链接

- 在返回任何链接之前，解析 `<目录>/<文件>` 并确认其存在。传递 `.step`/`.stp` 工件本身——无论是生成的还是导入的。目录列出工件，并按磁盘上的名称精确命名：`moonwatch.step` 在标签、面包屑、目录行和文件选择器中都是 `moonwatch.step`，无论它是生成的还是导入的。Viewer 从不学习一个文档是否生成：其状态仅限于工件侧（未编译 / 编译中 / 已渲染 / 失败），模型脚本不在 UI 的任何地方显示。生成的模型的文档必须已经存在（运行模型脚本）；存储中没有树的文档在打开时从其字节编译。如果解析的路径缺失，不要返回链接；报告问题并指向正确路径。
- 每个请求的文件返回一个 Viewer URL。
- 一次启动 Viewer 并选择一个会话的工作区根。每个链接都是相同的起源加上 `?file=<相对于该根的路径>`，因此它们共享一个可浏览的目录。根目录之外的工件需要自己的 Viewer——再次启动并使用该根（重用或启动使此操作幂等）；单独的链接无法到达它。
- 对于仅目录审查链接，返回不带 `?file=` 的起源。
- 除非用户要求，否则不要停止现有的 Viewer 服务器。
- 如果 Viewer 启动失败，报告失败并继续拥有技能的非 GUI 验证或工件。
