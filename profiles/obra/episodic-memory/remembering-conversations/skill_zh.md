# 回忆对话

**核心原则：** 在重新发明之前先进行搜索。搜索不花费任何成本；而重新发明或重复犯错则代价高昂。

## 强制要求：搜索历史记忆

**你必须为任何历史搜索搜索历史记忆。**

宣布："正在搜索过去的对话中关于 [主题] 的内容。"

### Claude 代码

使用带有 `subagent_type: "search-conversations"` 的任务工具：

```
任务工具：
  描述："搜索过去的对话中关于 [主题] 的内容"
  提示："搜索 [具体查询或主题]。专注于 [你正在寻找的内容 - 例如，决策、模式、陷阱、代码示例]。"
  subagent_type: "search-conversations"
```

### Codex

如果存在 `search-conversations` 代理，使用相同的提示来调度它。如果没有，直接使用 MCP 工具：

1. 使用 episodic-memory `search` 工具进行搜索
2. 使用 episodic-memory `read` 工具阅读前 2-5 个结果
3. 在你的回复中综合发现
4. 包含来源指针，以便用户可以检查原始对话

搜索工作流程将：
1. 使用 `search` 工具进行搜索
2. 使用 `read` 工具阅读前 2-5 个结果
3. 综合发现（200-1000 字）
4. 返回可操作的见解 + 来源

**与加载原始对话相比，可节省 50-100 倍的上下文。**

### opencode

如果没有本地搜索代理可用，直接使用 MCP 工具：

1. 使用 episodic-memory `search` 工具进行搜索
2. 使用 episodic-memory `read` 工具阅读前 2-5 个结果
3. 在你的回复中综合发现
4. 包含来源指针，以便用户可以检查原始对话

## 何时使用

每当当前任务可能受益于你之前可能学到的信息时，即使用户没有明确要求你搜索，也使用此方法。

**当过去的经验可能有所帮助时：**
- 你需要回忆早期工作中的决策、理由、模式、解决方案、陷阱或项目背景
- 一个任务与你之前解决、调试、审查、发布或规划的问题相似
- 你需要重复一个可能存在先前的陷阱或已建立步骤的工作流程或流程

**当你卡住时：**
- 你已经调查了一个问题，但找不到解决方案
- 面对一个当前代码中没有明显解决方案的复杂问题
- 需要遵循一个不熟悉的工作流程或流程

**当存在历史信号时：**
- 用户说 "上次"、"之前"、"我们讨论过"、"你实现过"
- 用户问 "我们为什么..."、"原因是什么..."
- 用户说 "你还记得吗..."、"我们知道关于...的信息..."

**在不确定的答案之前：**
- 在从记忆中猜测或说 "我不知道" 关于可能在过去对话中学到的某事之前，除非当前对话已经回答了它，否则搜索记忆

**不要首先搜索：**
- 对于当前代码库结构（首先使用 Grep/Read 进行探索）
- 对于当前对话中的信息
- 在理解你要做什么之前

## 直接 MCP 工具访问

当搜索代理不可用或当前 harness 不支持代理调度时，直接使用这些：
- `mcp__plugin_episodic-memory_episodic-memory__search`
- `mcp__plugin_episodic-memory_episodic-memory__read`

使用 MCP 工具时，保持上下文简短：先搜索，然后只读取前 2-5 个相关的对话或行范围。

如果需要高级用法，请参阅 MCP-TOOLS.md 获取完整的 API 参考。
