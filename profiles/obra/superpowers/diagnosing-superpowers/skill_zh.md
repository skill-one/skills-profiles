# 诊断超能力

## 概述

与你的人类合作伙伴一起确定会话中出了什么问题，查看磁盘上的会话记录，并附带证据报告发生了什么。你负责报告；你不负责诊断超能力。谁负责初步处理数据包或问题，谁决定是否涉及超能力变更。

**核心原则**：每个发现都引用 `路径:行号`。没有引用，就没有发现。每个数字都来自会话记录或你运行的命令，绝不来自记忆。

## 工作流程

为每一步创建一个待办事项。第5至第7步仅在满足其指定条件时运行。

1. **问题接收**。一次只问一个问题，直到你能写出一个陈述，说明会话（s），如果知道的话，是哪个回合范围，你的合作伙伴期望什么，发生了什么，以及他们关心的可观察指标（时钟时间、令牌数、重复操作、特定操作）。 "太慢了"是一种抱怨，不是问题陈述。请记录目标是否是一个超能力错误报告。
2. **定位**。使用 `references/session-discovery.md` 将每个会话解析为经过验证的绝对文件系统路径。通过引用其第一个提示和时间戳来确认过去的会话，并列出你拒绝的每个候选者及其原因，或“无”。枚举子代理的会话记录。创建 `~/.superpowers/diagnosing-superpowers/<会话ID>/`，告诉你的合作伙伴路径，并在那里填写 `templates/case.md`，遵循其关于环境和技能观察的来源规则。
3. **初步处理**。你自己阅读报告问题的区域。然后并行派遣一个分析师子代理每个维度，每个子代理都获得案例文件路径、`prompts/analyst-common.md` 以及 `prompts/` 中的一个维度文件：`skill-timeline.md`、`plan-adherence.md`、`repeated-work.md`、`stumbles.md`、`quality-evidence.md`、`request-conflicts.md`、`cost-and-time.md`。当会话记录很长时，按回合范围拆分维度。丢弃任何没有 `路径:行号` 的返回发现。
4. **报告**。按顺序填写 `templates/report.md` 的每个部分，将其写入工作区，展示它，并给出路径。检查实际证明所引用的内容并保留支持性案例；符号链接别名不是冗余副本。
5. **GitHub问题** — 当报告 §7 说可能或很可能，或你的合作伙伴要求时。根据 `references/github-issues.md` 搜索开放和关闭的问题中的症状。展示匹配项并建议将报告添加到最接近的问题。如果没有匹配项，填写 `templates/issue.md`，将其写入工作区，展示确切文本，并在批准后创建问题。`gh` 不能附加文件；如果存在数据包，请给你的合作伙伴其路径以便在浏览器中附加。
6. **导出** — 仅当你的合作伙伴要求数据包时；从不未经提示构建。如果输入目标是错误报告，请说一次一个经过清理的数据包在请求时可用，然后等待。询问编辑级别，说明每个包含的内容：骨架（没有工具结果正文）、证据（仅引用事件的正文）、完整。根据 `templates/bundle-README.md` 构建数据包，派遣 `prompts/scrub.md`，然后 `prompts/scrub-audit.md`，重复两者，直到审计返回 CLEAN。在展示最终的清理日志、文件列表和隐私和证据结果之前，完成数据包模板的证据检查和核对。在批准后才能存档（`zip -r` 或 `tar -czf`）。使用存档路径，说明其包含的内容，指向清理日志以进行替换，并说清理可能会遗漏东西：他们必须在分享之前审查每个文件。
7. **相似会话** — 当被要求时。将确认的发现转换为签名，按修改时间（mtime）和大小列出候选者，找到标记行号，为每个候选者并行派遣 `prompts/similar-session.md`，并将报告 §9 追加。

## 快速参考

所有七个分析师始终运行。此表说明在步骤3中你自己要阅读哪个区域，以及在裁决中要首先提出哪些发现。

| 抱怨 | 首先阅读，裁决中首先提出 |
|---|---|
| "太慢了" | cost-and-time, stumbles |
| "为什么它做了这项额外工作？" | repeated-work, plan-adherence |
| "为什么它这么贵？" | cost-and-time |
| "它到底在做什么？"（仍在运行） | skill-timeline；在覆盖中注明进行中 |
| "它忽略了计划" | plan-adherence, 首先查看压缩行 |
| "技能X从未触发" | skill-timeline |

## 严格规则

- **上下文安全**。一条会话记录行可能是一兆字节。每次都遵循 `references/context-safety.md` 中的会话文件。
- **只读**。绝不修改、移动或删除会话文件。
- **子代理的精确路径**。子代理的“当前会话”是其自己的。传递绝对路径和ID。
- **仅人类提示**。钩子输出、系统提醒和工具结果不是你合作伙伴的话。在子代理会话记录中，“用户”是父代理。
- **不诊断超能力**。报告 §7 说明参与并停止。绝不指明技能中的缺陷或提出更改。你的合作伙伴坚持要修复也不放弃此原则；指向问题步骤并提及在请求时可用数据包。也不给合作伙伴建议。
- **批准关卡**。在合作伙伴看过清理日志和文件列表之前，不存档。在他们批准确切文本之前，不发布问题或评论。
- **接收在分析之前**。步骤2至7中的任何内容都不会在合作伙伴回答之前开始。如果他们不在，请写下问题并停止。为你重建的陈述不是答案。一个已经范围明确的请求——一个特定事件、当前正在运行的内容或要运行的分析——本身就是陈述：回答它，然后提问。一个全会话的“为什么”是一种抱怨。

## 信号旗

| 思考 | 现实 |
|---------|---------|
| "问题很明显，跳过接收" | 问题陈述范围一切。提问。 |
| "他们不在，所以我将重建陈述" | 你无法重建他们想要的内容。写下问题并停止。 |
| "我现在清理一切，最后再提问" | 未范围清理会花费他们的预算在错误的问题上。先提问。 |
| "他们想要错误报告，所以我现在构建数据包" | 数据包是他们的会话数据，打包的。仅在请求时构建。 |
| "小范围、有针对性的编辑，不需要重构" | 不是你的决定，无论多么小。报告证据；初步处理者决定。 |
| "每个令牌的价格众所周知" | 你没有从会话记录中计算的数字是编造的。引用或删除。 |
