# 不安全默认值检测

检测**失效开启（fail-open）**漏洞，即应用程序因缺少配置而以不安全方式运行。区分可利用的默认值与安全崩溃的失效安全（fail-secure）模式。

- **失效开启（CRITICAL）:** `SECRET = env.get('KEY') or 'default'` → 应用程序使用弱密码运行
- **失效安全（SAFE）:** `SECRET = env['KEY']` → 应用程序缺少配置时崩溃

## 使用场景

- **生产应用程序的安全审计**（认证、加密、API安全）
- **部署文件、IaC模板、Docker配置的配置审查**
- **环境变量处理和密钥管理的代码审查**
- **部署前的检查**，用于检测硬编码的凭证或弱默认值

## 不应使用场景

不要使用此技能用于：
- **明确限定于测试环境**的测试用例（`test/`、`spec/`、`__tests__/`目录中的文件）
- **示例/模板文件**（具有`.example`、`.template`、`.sample`后缀的文件）
- **仅限开发的工具**（本地Docker Compose用于开发、调试脚本）
- **README.md或docs/目录中的文档示例**
- **部署时被替换的构建时配置**
- **应用程序缺少正确配置时不启动的崩溃行为**（失效安全）

不确定时：追踪代码路径以确定应用程序是使用默认值运行还是崩溃。

## 拒绝的理由

- **"只是一个开发默认值"** → 如果它到达了生产代码，则应视为发现
- **"生产配置会覆盖它"** → 验证生产配置是否存在；如果不存在，代码级别的漏洞仍然存在
- **"如果没有正确配置，它永远不会运行"** → 通过代码追踪来证明；许多应用程序会静默失败
- **"它位于认证之后"** → 深度防御；即使会话被攻破，弱默认值仍然会被利用
- **"我们会在发布前修复它"** → 现在记录下来；"以后"很少会到来

## 工作流程

对每个潜在发现，请遵循以下工作流程：

### 1. 搜索：执行项目发现并查找不安全默认值

确定语言、框架和项目约定。使用这些信息进一步发现密钥存储位置、密钥使用模式、认证的第三方集成、加密以及任何其他相关配置。进一步使用信息分析不安全的默认配置。

**示例**
在`**/config/`、`**/auth/`、`**/database/`和env文件中搜索模式：
- **后备密钥:** `getenv.*\) or ['"]`, `process\.env\.[A-Z_]+ \|\| ['"]`, `ENV\.fetch.*default:`
- **硬编码凭证:** `password.*=.*['"][^'"]{8,}['"]`, `api[_-]?key.*=.*['"][^'"]+['"]`
- **弱默认值:** `DEBUG.*=.*true`, `AUTH.*=.*false`, `CORS.*=.*\*`
- **加密算法:** 在安全上下文中出现`MD5|SHA1|DES|RC4|ECB`

根据发现结果调整搜索方法。

关注生产可访问的代码，而不是测试用例或示例文件。

### 2. 验证：实际行为
对每个匹配项，追踪代码路径以了解运行时行为。

**需要回答的问题：**
- 何时执行此代码？（启动时 vs. 运行时）
- 如果配置变量缺失会发生什么？
- 是否有验证来强制执行安全配置？

### 3. 确认：生产影响
确定此问题是否到达生产环境：

如果生产配置提供了变量 → 严重性降低（但仍然是一个代码级别的漏洞）
如果生产配置缺失或使用默认值 → CRITICAL

### 4. 报告：附带证据

**示例报告：**
```
发现：硬编码的JWT密钥后备
位置：src/auth/jwt.ts:15
模式：const secret = process.env.JWT_SECRET || 'default';

验证：应用程序在没有JWT_SECRET的情况下启动；密钥在行42的jwt.sign()中使用
生产影响：Dockerfile缺失JWT_SECRET
利用方式：攻击者使用'default'伪造JWT，获得未授权访问
```

## 快速验证清单

**后备密钥:** `SECRET = env.get(X) or Y`
→ 验证：应用程序在没有env变量时启动？密钥用于加密/认证？
→ 跳过：测试用例、示例文件

**默认凭证:** 硬编码的`username`/`password`对
→ 验证：在部署配置中激活？没有运行时覆盖？
→ 跳过：禁用账户、文档示例

**失效开启安全:** `AUTH_REQUIRED = env.get(X, 'false')`
→ 验证：默认值不安全（false/禁用/宽松）？
→ 安全：应用程序崩溃或默认值安全（true/启用/限制）

**弱加密:** 在安全上下文中使用MD5/SHA1/DES/RC4/ECB
→ 验证：用于密码、加密或令牌？
→ 跳过：校验和、非安全哈希

**宽松访问:** CORS `*`、权限 `0777`、默认公开
→ 验证：默认值允许未授权访问？
→ 跳过：带说明的明确配置宽松性

**调试功能:** 堆栈跟踪、内省、详细错误
→ 验证：默认启用？在响应中暴露？
→ 跳过：仅日志记录、非用户界面
