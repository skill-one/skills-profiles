# 让命运决定

当前进的道路不明确时，让牌面来诉说。

## 快速入门

1. 运行抽牌脚本：
   ```bash
   uv run --no-config {baseDir}/scripts/draw_cards.py
   ```

2. 脚本输出默认的12宫黄道十二宫占卜的JSON：
   12个宫位，每个宫位有1张主牌和2张小牌。每个宫位和牌都包含相对于 `{baseDir}/` 的 `file` 路径。

3. 读取每个宫位文件和每张牌的意义文件来理解占卜结果。为了更快地读取，可以使用 `--content` 将宫位和牌的文本直接包含在JSON中：
   ```bash
   uv run --no-config {baseDir}/scripts/draw_cards.py --content
   ```

4. 使用 [{baseDir}/references/INTERPRETATION_GUIDE.md]({baseDir}/references/INTERPRETATION_GUIDE.md) 中的指南来解读占卜结果。

5. 当任务属于专门的技术工作流时，使用 [{baseDir}/references/TECHNICAL_CONTEXT_LENSES.md]({baseDir}/references/TECHNICAL_CONTEXT_LENSES.md) 将解读结果转化为审计、验证、领域、故障类别或利益相关者的视角。

6. 将解读结果应用于当前任务。

## 何时使用

- **模糊的提示**：用户的请求是模糊的，存在多种合理的解决方案
- **明确的召唤**："我感觉很幸运"、"让命运决定"、"庄家选择"、"给我个惊喜"、"随便你"、"YOLO"
- **随意的委托**："随便"、"由你决定"、"你的选择"、"我不知道"、"随便做点什么"、"拍脑袋"、"我相信你"、"不重要"、"你想怎么做"、"我不在乎"、"任何方法都行"、"你来选"
- **游戏王能量**："牌之核心"、"我相信牌之核心"、"你触发了我的陷阱卡"、"是决斗的时候了"
- **类似耸肩的简洁**：非常简短的提示，完全委托决策而不表达偏好
- **重抽请求**：当没有实际系统变化发生时（这意味着抽新牌，而不是重新运行相同的方案）
- **平局打破**：当你即将在2个或多个有效方案中任意选择时，抽牌而不是默默选择一个

## 何时 NOT 使用

- 用户给出了清晰、具体的指示
- 任务有一个明显的正确方法
- 作为安全关键工作的决定权（安全、数据完整性、生产部署、发布批准、事件响应）
- 用户明确要求你不要使用塔罗牌
- 用户的语气是追求精确而不是随意的——问澄清问题来收集实际需求

## 安全和正确性使用

这项技能可以用于安全、审计或正确性管道中，作为发现创意的视角：选择下一个检查的角度、打破分析瘫痪、生成假设或暴露盲点。

它本身永远是不够的。在安全和正确性环境中，占卜结果必须由普通的工程证据跟随：源代码审查、测试、证明、跟踪、重现步骤、可利用性分析或其他领域适当的验证。不要将一张有利的牌视为发货的许可、压制发现、跳过验证或推翻具体风险的许可。

## 工作原理

### 抽牌

脚本使用 `secrets` 进行加密随机性：

1. 建立单独的主牌（22张）和小牌（56张）牌组
2. 通过 `secrets.randbelow()` 执行Fisher-Yates洗牌（没有模数偏差）
3. 发放默认的12宫黄道十二宫占卜
4. 每个宫位接收1张主牌，然后是2张小牌
5. 每张36张牌独立有50%的概率被反转

默认占卜记录了超过100位的保守无序卡熵预算：大约来自主牌选择的 `log2(C(22,12))` 位，来自小牌选择的 `log2(C(56,24))` 位（假设 `secrets.randbelow()` 是加密安全的），加上36位反转。确切的值在JSON输出中计算并报告在 `entropy_bits` 下。实际将牌分配给宫位的顺序包含更多的熵。

### 占卜

默认占卜是 **12宫黄道十二宫**：

| 宫位 | 代表 | 回答的问题 |
|-------|------------|---------------------|
| 1 | **自我** | 这个工作应该如何开始？ |
| 2 | **资源** | 什么价值观、资产或约束条件很重要？ |
| 3 | **沟通** | 什么需要澄清或连接？ |
| 4 | **基础** | 什么背景或依赖关系锚定了任务？ |
| 5 | **创造力** | 实验或愉悦应该在哪些地方塑造工作？ |
| 6 | **实践** | 什么质量、维护或执行问题很重要？ |
| 7 | **伙伴关系** | 谁或什么必须与这个集成？ |
| 8 | **转变** | 存在什么风险、共享状态或深刻变化？ |
| 9 | **探索** | 什么原则或更广泛的策略指导路径？ |
| 10 | **召唤** | 正在服务什么交付或长期结果？ |
| 11 | **社区** | 涉及什么系统、网络或共同愿望？ |
| 12 | **隐藏** | 什么盲点、结束或无意识的因素很重要？ |

在每个宫位中，主牌设定了原型主题，两张小牌提供了实际细节。

为了与旧工作流程兼容，`draw_cards.py --legacy` 返回先前的4张牌手，`draw_cards.py --legacy <数量>` 返回1-78张牌的自定义手。没有 `--legacy` 的位置计数被拒绝，因为新的默认占卜有一个固定的形状。

### 参考文件

每个宫位的含义都在 `{baseDir}/houses/` 下的自己的markdown文件中。宫位文件描述了宫位如何应用于技术环境，包括构建新项目、漏洞发现、正确性验证以及常见的审计、验证、领域、故障类别和利益相关者工作流程。

每张牌的含义都在 `{baseDir}/cards/` 下的自己的markdown文件中：

- `cards/major/` - 22张主牌（原型力量）
- `cards/wands/` - 14张权杖（创造力、行动、意志）
- `cards/cups/` - 14张圣杯（情感、直觉、关系）
- `cards/swords/` - 14张宝剑（智力、冲突、真相）
- `cards/pentacles/` - 14张金币（物质、实用、工艺）

### 解读

抽牌后，读取每个宫位文件和每个牌文件，然后综合含义。参见 [{baseDir}/references/INTERPRETATION_GUIDE.md]({baseDir}/references/INTERPRETATION_GUIDE.md) 获取完整的解读工作流程。对于跨领域翻译，参见 [{baseDir}/references/TECHNICAL_CONTEXT_LENSES.md]({baseDir}/references/TECHNICAL_CONTEXT_LENSES.md)。

关键规则：
- 反转的牌会反转或复杂化直立含义
- 主牌比小牌更重要
- 占卜结果在所有12个宫位中讲述一个故事；不要孤立地解读牌
- 将抽象含义映射到具体的技术决策
- 在安全和正确性工作中，使用解读结果来选择调查路径，然后在接受或拒绝任何风险之前需要证据
- **永远不要将解读作为纯文本步骤输出。** 将解读结果与你的下一个工具调用（执行所选方案的行动）一起包含。优先使用 `--content`，以便从抽牌输出中获取所有36张牌的含义和所有12个宫位的含义。

## 示例会话（宫位级片段）

一个真实的解读综合了所有12个宫位；下面的片段只显示了其中一个宫位贡献的内容，以便格式清晰。在实际使用中不要在单个宫位后停止。

```
用户："我不知道，随便你怎么做"

[抽牌]
1号宫位（自我）：魔术师（直立），五剑（反转），十金币（直立）

宫位贡献：起始立场是有资源且工具丰富（魔术师），但实际细节警告不要进行战斗边缘工作（五剑反转），同时仍然倾向于可维护的工艺（十金币）。这是整体解读的输入之一；在决定方法之前，结合剩余的11个宫位。
```

命名的 `draw` 代理返回更紧凑的形式，用于预兆问题：
3个简洁的要点，涵盖主导主题、主要风险或盲点，以及推荐的下一步行动。

## 错误处理

如果抽牌脚本失败：
- **脚本崩溃并带有traceback**：向用户报告错误并跳过解读。不要编造牌或模拟抽牌——整个要点是真实的熵。
- **找不到牌文件**：记录缺失的文件，仅根据牌名和花色解读牌，并继续解读。
- **永远不要伪造熵**：如果脚本无法运行，不要使用你自己的“随机性”来模拟抽牌。告诉用户抽牌失败。

## 拒绝的理由

| 理由 | 为什么错误 |
|----------------|-----------|
| "牌面指示，所以我必须" | 牌面提供方向，不会覆盖安全或正确性 |
| "这个解读证明了我现有的偏好" | 如果解读挑战你的直觉，要诚实 |
| "反转的牌意味着什么也不做" | 反转意味着不同的角度，而不是不行动 |
| "主牌覆盖用户要求" | 用户要求始终优先于牌面解读 |
| "我会不断抽牌直到我得到我想要的" | 每个决策点只抽一次；接受解读 |
| "解读说风险是好的" | 牌面可以建议要检查什么；只有证据可以消除安全或正确性问题 |
