# 审计准备助手

## 目的

使用 Trail of Bits 的检查清单来帮助准备安全审查。准备充分的代码库可以使审查过程更加顺畅和高效。

**使用时间**：安全审计前 1-2 周

---

## 准备过程

### 第 1 步：设定审查目标

帮助定义您希望通过审查实现的目标：

**关键问题**：
- 您希望达到的整体安全级别是什么？
- 哪些方面最让您担忧？
  - 以前的审计问题？
  - 复杂的组件？
  - 脆弱的代码部分？
- 您的项目最坏的情况是什么？

将目标文档化并与评估团队分享。

---

### 第 2 步：解决简单问题

运行静态分析并帮助解决容易发现的问题：

**运行静态分析**：

对于 Solidity：
```bash
slither . --exclude-dependencies
```

对于 Rust：
```bash
dylint --all
```

对于 Go：
```bash
golangci-lint run
```

对于 Go/Rust/C++：
```bash
# CodeQL 和 Semgrep 检查
```

然后我会：
- 筛选所有发现的问题
- 帮助解决简单问题
- 文档化可接受的风险

**提高测试覆盖率**：
- 分析当前覆盖率
- 识别未测试的代码
- 建议新的测试
- 运行完整测试套件

**删除无用代码**：
- 查找未使用的函数/变量
- 识别未使用的库
- 定位过时的功能
- 建议清理

**目标**：静态分析报告清晰，测试覆盖率高，无用代码最少

---

### 第 3 步：确保代码可访问性

帮助使代码清晰易懂：

**提供详细的文件列表**：
- 列出所有范围内的文件
- 标记不在范围内的文件
- 解释文件夹结构
- 文档化依赖关系

**创建构建说明**：
- 编写逐步设置指南
- 在干净的环境中测试
- 文档化依赖关系和版本
- 验证构建成功

**冻结稳定版本**：
- 确定用于审查的提交哈希
- 创建专用分支
- 标记发布版本
- 锁定依赖关系

**识别模板代码**：
- 标记复制/分叉的代码
- 突出您的修改
- 文档化第三方代码
- 将审查集中在您的代码上

---

### 第 4 步：生成文档

帮助创建文档：

**流程图和时序图**：
- 绘制主要工作流
- 显示组件关系
- 可视化数据流
- 识别关键路径

**用户故事**：
- 定义用户角色
- 文档化用例
- 解释交互
- 澄清期望

**链上/链下假设**：
- 数据验证程序
-预言机信息
- 桥接假设
- 信任边界

**参与者与权限**：
- 列出所有参与者
- 文档化角色
- 定义权限
- 映射访问控制

**外部开发者文档**：
- 将文档链接到代码
- 保持同步
- 解释架构
- 文档化 API

**函数文档**：
- 系统和函数不变式
- 参数范围（最小/最大值）
- 算术公式和精度损失
- 复杂逻辑解释
- Solidity 的 NatSpec

**术语表**：
- 定义领域术语
- 解释缩写
- 保持术语一致
- 商业逻辑概念

**视频演示**（可选）：
- 复杂的工作流
- 担忧的领域
- 架构概述

## 我的工作方式

当被调用时，我会：

1. **帮助设定审查目标** - 询问担忧并文档化
2. **运行静态分析** - 执行适合您平台的工具
3. **分析测试覆盖率** - 识别差距并建议改进
4. **查找无用代码** - 搜索未使用的代码和库
5. **审查可访问性** - 检查构建说明和范围清晰度
6. **生成文档** - 创建流程图、用户故事、术语表
7. **创建准备清单** - 跟踪已完成和剩余的工作

根据以下内容调整：
- 您的平台（Solidity、Rust、Go 等）
- 可用工具
- 现有文档
- 审查时间表

## 理由（不要跳过）

| 理由 | 为什么这是错误的 | 必要操作 |
|-----------------|-----------------|-----------------|
| "README 涵盖了设置，不需要详细的构建说明" | README 假设审计员有背景知识 | 在干净的环境中测试构建，文档化每个依赖关系版本 |
| "静态分析已经运行，不需要再次运行" | 代码库自上次运行以来已更改 | 执行静态分析工具，生成最新报告 |
| "测试覆盖率看起来不错" | "看起来不错" 不是测量的覆盖率 | 运行覆盖率工具，识别具体的未测试代码路径 |
| "没有太多无用代码需要担心" | 无用代码在手动审查时隐藏 | 使用自动化检测工具查找未使用的函数/变量 |
| "架构很清晰，不需要图表" | 文本描述遗漏了视觉模式 | 生成实际的流程图和时序图 |
| "可以在审计前立即冻结版本" | 最后时刻冻结会导致仓促交接 | 现在确定并文档化提交哈希，创建专用分支 |
| "术语是自解释的" | 领域知识不是通用的 | 创建包含所有领域特定术语的全面术语表 |
| "我会稍后做这一步" | 步骤相互依赖 - 跳过会创建差距 | 按顺序完成所有 4 个步骤，使用清单跟踪进度 |
