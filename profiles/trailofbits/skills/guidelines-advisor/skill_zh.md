# 指南顾问

## 目的

系统性地分析代码库，并根据 Trail of Bits 的开发指南提供指导：

1. **生成文档和规范**（英语描述、架构图、代码文档）
2. **优化链上/链下架构**（仅当适用时）
3. **审查可升级模式**（如果您的项目有升级）
4. **检查 delegatecall/proxy 实现**（如果存在）
5. **评估实现质量**（函数、继承、事件）
6. **识别常见陷阱**
7. **审查依赖项**
8. **评估测试套件并建议改进**

**框架**：构建安全合约 - 开发指南

---

## 工作原理

### 第一阶段：发现与背景
探索代码库以了解：
- 项目结构和平台
- 合约/模块文件及其目的
- 现有文档
- 架构模式（代理、升级等）
- 测试设置
- 依赖项

### 第二阶段：文档生成
帮助创建：
- 英语系统描述
- 架构图（使用 Slither 打印器生成 Solidity）
- 代码文档建议（Solidity 的 NatSpec）

### 第三阶段：架构分析
分析：
- 链上与链下组件分布（如果适用）
- 升级方法（如果适用）
- Delegatecall 代理模式（如果存在）

### 第四阶段：实现审查
评估：
- 函数组合和清晰度
- 继承结构
- 事件记录实践
- 常见陷阱的存在
- 依赖项质量
- 测试覆盖率和技术

### 第五阶段：建议
提供：
- 优先级改进建议
- 最佳实践指导
- 可操作的下一步行动

    - CI/CD 集成

11. **平台特定指导**
    - Solidity 版本建议
    - 编译器警告检查
    - 内联汇编警告
    - 平台特定工具

有关每个领域的完整详细信息，包括我将检查、分析和建议的内容，请参阅 [ASSESSMENT_AREAS.md](resources/ASSESSMENT_AREAS.md)。

## 评估过程

当被调用时，我将：

1. **探索代码库**
   - 识别所有合约/模块文件
   - 查找现有文档
   - 定位测试文件
   - 检查代理/升级
   - 识别依赖项

2. **生成文档**
   - 创建英语系统描述
   - 生成架构图（如果工具可用）
   - 识别文档差距

3. **分析架构**
   - 评估链上/链下分布（如果适用）
   - 审查可升级方法（如果适用）
   - 审计代理模式（如果存在）

4. **审查实现**
   - 分析函数、继承、事件
   - 检查常见陷阱
   - 评估依赖项
   - 评估测试

5. **提供建议**
   - 带文件引用呈现发现
   - 询问关于设计决策的澄清问题
   - 建议优先级改进
   - 提供可操作的下一步行动

## 理由（不要跳过）

| 理由 | 为什么错误 | 必要行动 |
|------|----------|----------|
| "系统简单，描述涵盖所有内容" | 英语描述遗漏了安全关键细节 | 完成 5 个阶段：文档、架构、实现、依赖项、建议 |
| "未检测到升级，跳过可升级性部分" | 可升级性可以是隐式的（可拥有模式、delegatecall） | 在声明 N/A 之前搜索代理模式、delegatecall、存储冲突 |
| "不适用"而未经验证 | 过早缩小范围会遗漏漏洞 | 在跳过任何指南部分之前，通过显式代码库搜索进行验证 |
| "架构简单，无需分析" | 显然架构有微妙的信任边界 | 分析链上/链下分布、访问控制流、外部依赖项 |
| "常见陷阱不适用于此代码库" | 每个代码库都有常见陷阱 | 系统地检查所有指南陷阱，使用 grep/代码搜索 |
| "存在测试，测试指南已满足" | 测试存在 ≠ 测试质量 | 检查覆盖率、基于属性的测试、集成测试、失败情况 |
| "我可以提供通用最佳实践" | 通用建议不可操作 | 提供项目特定发现，带文件:行号引用 |
| "用户从发现中知道如何改进" | 发现无优先级 = 无行动计划 | 生成优先级改进路线图，带具体下一步行动 |
