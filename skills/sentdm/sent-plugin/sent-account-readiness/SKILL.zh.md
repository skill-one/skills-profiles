# 账户就绪检查

使用 `account.get`、`balance.get` 和 `onboarding.status` 检查就绪状态。

## 安全授权

让 MCP 客户端执行 OAuth 2.1/PKCE。切勿请求、接受、打印或存储令牌、API 密钥、授权头、客户端 ID 或密钥。授权授予的范围限于在客户端流程中选择的组织和发件人配置文件。若要更改该范围，请在客户端重新授权；当不再需要时，通过客户端或适用的 Sent 账户控制来撤销授权。

如果 MCP 不受支持或身份验证失败，请说明从技能中仍可计划的内容，并指导用户在其 MCP 客户端中授权或重新授权。不要让他们粘贴凭证。

## 检查就绪状态

1. 使用 `account.get` 识别授权的账户上下文，并显示所选组织和发件人配置文件。仅返回执行任务所需的最低账户字段。
2. 在高容量发送前或当资金不足可能阻止消息发送时，使用 `balance.get`。当可用时，报告货币和返回的时间戳或新鲜度信息。
3. 使用 `onboarding.status` 识别不完整、待处理、已批准或被阻止的入职步骤。保留观察到的状态与纠正措施之间的区别。

在实用的情况下遮盖标识符。不要不必要地重复账户、KYC、联系人或账单详情。

## 路由纠正措施

此技能诊断就绪状态，但不会变更入职状态。

- 将发件人配置文件边界或租户设计路由到 `sender-profile-architect`。
- 将美国 A2P 注册准备路由到 `sms-10dlc-registration`。
- 将 WhatsApp 嵌入式注册路由到 `waba-embedded-signup`。
- 将 RCS 商业消息发布准备路由到 `rcs-agent-onboarding`。

当用户仅询问账户是否就绪时，报告阻止状态并推荐公共技能，而不要编造操作修复方案。
