# Web Typography

选择、搭配和实现网页字体的实用指南。最好的排版是看不见的——它让读者沉浸在内容中，而不是吸引注意力。

## 核心原则

**排版是您内容的灵魂。** 您选择的字体在单个字被阅读之前就设定了基调——一个法律网站不应该感觉有趣；一个儿童应用程序不应该感觉商业化。遵循“清晰的酒杯”原则：排版应该像一块透明的酒杯，让焦点在酒（内容）上，而不是杯子（字体）上。

## 评分

**目标：10/10。** 得分 = 实现满足的 10 项快速诊断行的数量。等级：**9-10** = 正文 16px+，度量值小于 75ch，行高 1.4+，清晰的级别对比度，字体负载小于 200KB，设置了回退，在 200% 放大下存活；**5-6** = 可读但缺少度量控制、回退或缩放弹性；**<=3** = 正文小于 16px，没有度量上限，FOIT 或可读性层次结构。始终说明当前得分和失败的特定诊断行。

## 两种排版环境

所有排版都分为两类：

| 环境 | 目的 | 优先级 |
|------|------|--------|
| **用于瞬间的排版** | 标题、按钮、导航、标志 | 个性、冲击力、独特性 |
| **用于生活的排版** | 正文、文章、文档 | 可读性、舒适度、持久性 |

**工作型字体** 在“用于生活的排版”方面表现出色——在各种尺寸、重量和环境中都很通用的字体，不会引起注意。例如：Georgia、Source Sans、Freight Text、FF Meta。

## 排版框架

### 1. 我们如何阅读

**核心概念：** 理解阅读机制是每个排版决策的基础。眼睛不会平滑扫描——它们会突然跳跃。

**为什么有效：** 与这些机制作斗争会产生摩擦，导致读者离开；与之保持一致可以让读者以更少的疲劳更快地吸收内容。

**关键洞察：**
- **跳跃（saccades）**——眼睛以 7-9 个字符的爆发跳跃；行长度和字母间距直接影响跳跃效率
- **固定（fixations）**——眼睛短暂暂停以吸收内容；密集或间距不当的文本会减慢阅读速度
- **单词形状（bouma）**——有经验的读者识别单词轮廓，而不是单个字母
- **可识别性 vs. 可读性**——可识别性是指字符是否可以被区分（与字体有关）；可读性是指文本是否可以舒适地长时间阅读（与排版有关：大小、间距、行长度）。一个可识别的字体仍然可能设置得难以阅读

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 长格式内容 | 优化持续舒适度 | 正文 16-18px，行高 1.5-1.7，行长 45-75 字符 |
| 仪表板 UI | 优化快速扫描 | 突出的重量层次结构，数据组之间的空白 |
| 移动阅读 | 考虑距离和照明 | 较大的正文（17-18px），更高的对比度 |

**复制模式：**
```css
.prose {
  font-size: 1.125rem;     /* 18px */
  line-height: 1.6;
  max-width: 65ch;          /* ~45-75 个字符 */
}
```

当您需要命名字母形状部分（x-height、counter、aperture）或将字体放在分类系统中以证明选择时，请参阅：[references/typeface-anatomy.md](references/typeface-anatomy.md)。

### 2. 评估字体

**核心概念：** 字体必须在技术、结构和实践质量检查通过后才能获得项目中的位置。美丽的样本在屏幕上会失败。

**为什么有效：** 屏幕渲染、可变带宽和多样化设备带来了印刷从未面临过的限制。严格的评估可以防止项目中期更换字体带来的成本。

**关键洞察：**
- **技术质量**——一致的笔画粗细、文本块中均匀的视觉颜色、良好的字偶距（AV、To、Ty）、完整的字符集、多个重量（最小：常规、粗体、斜体）
- **结构评估**——充足的 x-height（更好的屏幕可读性）、开放的计数器和孔（a、e、c）、独特的字母形状（Il1、O0、rn vs. m）
- **实际需求**——在目标屏幕上以实际使用大小测试，检查文件大小，验证许可证
- **真实内容测试**——拉丁文隐藏了字符频率、单词长度和段落节奏的问题

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 正文选择 | 优先考虑 x-height、开放的计数器、均匀的颜色 | Source Serif Pro 而不是 Didot 用于长阅读 |
| UI/系统文本 | 优先考虑小号尺寸的可读性和重量范围 | Inter 或 SF Pro 用于界面元素 |
| 多语言产品 | 验证目标语言中字形覆盖范围 | Noto Sans 用于广泛的 Unicode 支持 |

**复制模式：**
```css
/* 在每个实际使用大小上进行压力测试 */
body { font-size: 16px; }
.caption { font-size: 0.75rem; }
h1 { font-size: 3rem; }
```

**道德边界：** 在发布字体之前始终验证网络许可证——桌面/印刷许可证很少涵盖网络嵌入，未经许可的使用会带来真正的法律责任。

当审查候选字体时，请参阅：[references/evaluating-typefaces.md](references/evaluating-typefaces.md)——完整质量清单、红旗表和要检查的结构标准。

### 3. 选择字体

**核心概念：** 从目的而不是美观开始。内容的基调、阅读环境和持续时间应驱动选择——而不是个人偏好或趋势。

**为什么有效：** 目的性选择感觉是不可避免的，而不是随机的，并且可以因为推理而不是品味而经受住利益相关者的审查。

**关键洞察：**
- **首先定义工作**——正文、标题和 UI 元素可能需要不同的字体
- **将基调与内容匹配**——一份财务报告需要不同的声音，而不是一家面包店的菜单
- **检查字体家族**——在承诺之前确认所需的重量、斜体和样式是否存在
- **安全的起点**——正文衬线：Georgia、Source Serif Pro、Charter；正文无衬线：系统字体、Source Sans Pro、Inter、IBM Plex Sans

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 内容密集型网站 | 工作型衬线或无衬线字体用于持续阅读 | Source Serif Pro 或 Charter 用于文章 |
| SaaS 仪表板 | 干净的无衬线字体，具有强烈的表格数字 | Inter 或 IBM Plex Sans 用于数据丰富的 UI |
| 专注于可访问性 | 为最大可读性而设计的字体 | Atkinson Hyperlegible 用于视力受损用户 |

**复制模式：**
```css
/* 网络字体与系统回退堆栈 */
body {
  font-family: 'Source Sans Pro', -apple-system,
               BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
}
```

当缩小决赛选手或权衡免费与付费字体时，请参阅：[references/evaluating-typefaces.md](references/evaluating-typefaces.md)——并排比较方法和质量选项短名单。

### 4. 搭配字体

**核心概念：** 成功的搭配会创造清晰的对比——字体应该明显不同，而不是令人困惑地相似。最多一到两种字体。

**为什么有效：** 清晰的结构对比（衬线 + 无衬线、轻 + 常规、人文 + 几何）给每个字体一个明确的角色。太相似的字体会制造没有目的的紧张感——读者会感觉到“不对劲”，但不知道为什么。

**关键洞察：**
- **对比类型**——结构（衬线 + 无衬线）、重量（轻 + 常规）、时代（人文 + 几何）、宽度（紧凑 + 常规）
- **同一设计师策略**——一个设计师的字体通常共享协调的 DNA（FF Meta + FF Meta Serif）
- **超家族**——设计为一起工作的家族消除了猜测（Roboto + Roboto Slab）
- **搭配失败**——两个几乎相同的字体，两个字体都在争夺注意力，一个字体压倒了另一个字体

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 编辑网站 | 衬线标题 + 无衬线正文 | Playfair Display + Source Sans Pro |
| 文档 | 等宽代码 + 来自一个家族的无衬线散文 | IBM Plex Mono + IBM Plex Sans |
| 极简品牌 | 单个家族的重量变化 | Inter 在不同的重量和尺寸 |

**复制模式：**
```css
/* 经典衬线 + 无衬线搭配 */
h1, h2, h3 { font-family: 'Playfair Display', Georgia, serif; }
body { font-family: 'Source Sans Pro', -apple-system, sans-serif; }
```

当选择第二个字体时，请参阅：[references/pairing-strategies.md](references/pairing-strategies.md)——经过验证的组合、对比类型表和同一设计师/超家族快捷方式。

### 5. 排版测量

**核心概念：** 三个测量值——字体大小、行长度和行高——构成了舒适阅读的基础。正确设置这些比选择字体更重要。

**为什么有效：** 这些测量值控制眼睛如何横跨和垂直移动文本：最佳行长度匹配跳跃模式，足够的行高防止眼睛在返回摆动时跳到错误的一行，足够的大小使字母形状在屏幕上可识别。

**关键洞察：**
- **正文大小**——最小 16px；对于阅读密集型网站，错误较大（18px）；移动用户比设计师想象的更远地拿着手机
- **行长度（度量）**——理想 45-75 个字符，66 个最佳；使用 `ch` 单位或 `max-width` 强制执行
- **行高**——正文 1.4-1.8；较长的行需要更多；标题需要更紧（1.1-1.25）
- **标题比例**——级别之间一致的比率（1.2-1.5）创建层次结构，而不会出现极端情况

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 博客/文章 | 65ch 最大宽度，1.6 行高 | `.prose { max-width: 65ch; line-height: 1.6; }` |
| 仪表板 | 更紧的行高用于密集数据 | `line-height: 1.3;` 用于表格单元格和标签 |
| 登录页面 | 适中的大小用于扫描性 | `font-size: 1.25rem; line-height: 1.7;` |

**复制模式：**
```css
.prose {
  font-size: clamp(1rem, 0.95rem + 0.25vw, 1.125rem);
  line-height: 1.6;
  max-width: 65ch;
}
/* 行高按上下文 */
h1, h2 { line-height: 1.1; }      /* 标题：1.1-1.25 */
.ui-text { line-height: 1.35; }   /* UI：1.3-1.4 */
.body-text { line-height: 1.6; }  /* 正文：1.5-1.7 */
```

当编写 `clamp()` 公式时，请参阅：[references/responsive-typography.md](references/responsive-typography.md)——如何推导出最小/首选/最大和基于视口的测量策略。

### 6. 构建排版层次结构

**核心概念：** 层次结构告诉读者什么最重要。通过在大小、重量和颜色中受控的变化来创造区别——但不要同时拉三个杠杆。

**为什么有效：** 刻意、一致的差异让读者一眼就能掌握页面结构；没有层次结构，一切都竞争，什么也赢不了。

**关键洞察：**
- **三个杠杆**——大小、重量、颜色；在相邻级别之间变化一个或两个，永远不要三个都变
- **眯眼测试**——眯着眼睛看页面时，层次结构仍然可见
- **一致的比例**——标题之间模块化的比率（1.2-1.5）创造节奏；任意的尺寸创造噪音
- **不要跳过级别**——从 H1 跳到 H3 会打破读者的心理模型

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 内容页面 | 跨 4-5 级别的大小 + 重量 | H1 2.5rem/700，H2 1.75rem/600，正文 1rem/400 |
| 仪表板 | 重量 + 颜色用于数据 vs. 标签 | 粗体 #111 值，常规 #666 标签 |
| 表单 UI | 标签的细微重量变化 | 标签：600 重量，输入：400 重量 |

**复制模式：**
```css
h1 { font-size: clamp(2rem, 1.5rem + 2vw, 3rem); font-weight: 700; color: #111; }
h2 { font-size: clamp(1.5rem, 1.25rem + 1vw, 2rem); font-weight: 600; color: #111; }
body { font-size: 1rem; font-weight: 400; color: #333; }
.secondary { font-size: 0.875rem; color: #666; }
/* 标题：比下面多出更多空间 */
h1, h2, h3 { margin: 1.5em 0 0.5em; line-height: 1.2; }
```

**道德边界：** 不要用小号或低对比度的字体隐藏费用、免责声明或退出选项，以降低用户需要看到的内容——隐藏实质性信息的层次结构利用排版对抗读者。

当实现 CSS 时，请参阅：[references/css-implementation.md](references/css-implementation.md)——完整的层次结构模式、`@font-face` 加载、`font-variation-settings` 轴和用 pyftsubset 进行子集。

### 7. 响应式排版和 Web 字体性能

**核心概念：** 排版必须适应屏幕，Web 字体必须高效加载。流体排版使用 `clamp()` 平滑地缩放，无需断点跳跃；战略字体加载防止布局偏移和慢速渲染。

**为什么有效：** 固定字体大小无法同时服务于 320px 的手机和 1440px 的桌面。Web 字体默认阻止渲染——未优化的加载会导致不可见的文本闪烁（FOIT）或未格式化文本闪烁（FOUT）。

**关键洞察：**
- **流体排版**——`clamp(min, preferred, max)` 在视口之间平滑缩放，无需媒体查询即可用于排版
- **断点调整**——手机需要稍大的正文（17-18px）和更紧凑的标题比例；桌面可以将显示大小推到极限，同时保持行长度限制
- **加载策略**——`font-display: swap` 立即显示回退文本；预加载关键字体；子集以需要的字符
- **性能预算**——总字体负载小于 200KB；优先考虑 WOFF2；可变字体可以替代 4-6 个静态权重文件

**产品应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 内容网站 | 使用 clamp() 的流体大小 | `font-size: clamp(1rem, 0.9rem + 0.5vw, 1.25rem)` |
| 电子商务 | 预加载英雄字体，延迟加载次要权重 | `<link rel="preload" href="font.woff2" as="font">` |
| 全球产品 | 按语言子集以减少负载 | 拉丁字母子集用于英文，CJK 子集用于亚洲页面 |

**复制模式：**
```css
h1 { font-size: clamp(2rem, 1.5rem + 2vw, 3.5rem); }

@font-face {
  font-family: 'Custom Font';
  src: url('/fonts/custom.woff2') format('woff2');
  font-display: swap;
  unicode-range: U+0000-00FF; /* 拉丁字母子集 */
}
/* 在 <head>: <link rel="preload" href="/fonts/custom.woff2" as="font" type="font/woff2" crossorigin> */
```

**道德边界：** 不要优化用户离开——子集丢弃了非英语读者需要的字符，或者删除了斜体/粗体权重，这些权重对于强调是必需的，用包容性换取速度。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|----------|------|
| 文本感觉拥挤 | 行高太紧导致读者疲劳 | 增加行高到 1.6+；添加段落间距 |
| 行太长 | 超过 75 个字符时，眼睛会失去返回摆动 | `max-width: 65ch` 在文本容器上 |
| 标题看起来不连贯 | 标题上方过多的空间会打破与内容的关联 | 减少标题上方的空间；保持标题下方的空间 |
| 文本看起来模糊 | 字体平滑或子像素渲染问题 | 检查字体平滑；尝试不同的重量；增加大小 |
| 字体加载缓慢 | 未优化的文件阻止渲染 | 子集；`font-display: swap`；预加载关键字体 |
| 正文太小 | 手机拿的距离比想象的要远；使老眼睛疲劳 | 增加到 18px；在真实距离上测试 |
| 层次结构不明确 | 级别之间对比度不足 | 增加大小/重量差异 |
| 字体冲突 | 没有清晰对比的搭配会制造紧张感 | 一个家族，或确保结构对比（衬线 + 无衬线） |
| 拉丁文测试 | 临时文本隐藏了节奏和频率问题 | 使用真实、有代表性的内容进行测试 |

## 快速诊断

| 问题 | 如果不满足 | 操作 |
|------|----------|------|
| 正文文字是否为16px或更大？ | 字体太小，阅读不舒适 | 至少16px；阅读量大的页面建议使用18px |
| 行长度是否少于75个字符？ | 回扫时眼睛会失去位置 | `max-width: 65ch` 用于文本容器 |
| 正文行高是否为1.4+？ | 行感觉拥挤，阅读速度变慢 | 增加到1.5-1.7 |
| 字体层级之间是否有清晰对比？ | 层级关系不明显，扫描失败 | 增加大小或粗细差异 |
| 是否在真实屏幕上以实际尺寸测试？ | 生产环境出现渲染意外 | 在目标设备上测试所有使用尺寸 |
| 总字体文件大小是否小于200KB？ | 加载缓慢影响UX和SEO | 子集化、WOFF2、考虑使用变体字体 |
| 是否指定了备用字体？ | FOIT导致文本为空白 | 每个字体族中都设置系统备用字体 |
| 页面是否能在200%缩放下正常工作？ | 低视力用户可访问性失败 | 在200%下修复溢出和截断 |
| 标题是否没有孤立的单词？ | 段尾单词看起来不完整 | `text-wrap: balance` 或手动断行 |
| 链接是否视觉上可区分？ | 用户无法找到交互元素 | 颜色和/或下划线区分 |
