# 设计冲刺框架

一个通过设计、原型制作和与客户一起测试想法来回答关键业务问题的五天流程。该框架由谷歌风险投资公司开发，并被谷歌、Slack、Airbnb 和数百个初创公司使用。

## 核心原则

**将数月的辩论、设计和测试压缩到一周内——并在编写任何生产代码之前与真实用户进行测试。** 冲刺用固定的周一至周五的时间框架、严格的时限和唯一的决策者取代了无休止的讨论，以便在五天内而不是五个月内为一个高风险的产品问题得到一个真实的答案。

## 评分

**目标：10/10。** 通过为每个完整的项目和正确项目（共10分）授予1分来对冲刺计划或执行进行评分。报告分数以及达到10/10所需的缺失项目。

1. 决策者承诺整个星期；由一个冲刺主管进行协调。
2. 周一产出目标客户和时刻（不是模糊的“测试产品”）。
3. 使用严格的时限（Crazy 8s 在8分钟内，10am-5pm 的日子，没有开放式会议）。
4. 独立完成解决方案草图，匿名——不进行小组头脑风暴。
5. 周三以一个决策者的监督投票结束，而不是共识。
6. 在构建任何原型之前指定故事板。
7. 原型是一个金发女郎级别的逼真外观，可在5-15分钟内进行测试，并完成试运行。
8. 恰好招募5个目标用户，通过筛选器（6个安排以吸收一个未出现的人）。
9. 周五使用五幕访谈；用户在不解释原型的情况下进行解释。
10. 冲刺结束时的复盘将 +/-/~ 模式网格转换为下一步决策。

缺少决策者、真实用户或同一天原型的计划最高为6分——这些都是冲刺存在的目的以防止的失败模式。

## 五天冲刺流程

```
周一 → 周二 → 周三 → 周四 → 周五
  绘制      草图     决策      原型     测试
```

**前提条件：** 一个值得一周关注的重大挑战；合适的团队（决策者加上4-7名具有不同专业知识的人）；五整天（10am-5pm）且没有干扰；一个带有白板的专用房间。一个 **冲刺主管** 进行协调、计时和管理精力。

当你是冲刺主管时，请参阅 [references/facilitation.md](references/facilitation.md) —— 它包含完整的协调指南、时限策略和保持停滞或低能量房间有生产力的精力管理技巧。

## 周一：绘制

**目标：** 了解问题并为本周选择目标。

### 上午：从终点开始

- **长期目标：** 写下对“两年后我们希望成为什么”的乐观答案——例如，“客户每天使用我们的产品。”
- **冲刺问题：** 将障碍和未知因素作为问题列在白板上，整个团队做出贡献——例如，“客户会信任我们处理付款信息吗？”

### 下午：绘制挑战

- **客户旅程图：** 列出参与者（客户类型），然后从左到右绘制5-15步的旅程：“听说产品 → 访问网站 → 注册 → 首次使用 → 普通用户。”
- **采访专家：** 采访具有专业知识的团队成员（CEO、设计、工程、支持、销售）；在白板上记录笔记。
- **如何可能（HMW）：** 将问题改写成机会——“客户不理解定价”→“HMW 使定价立即清晰？”每个问题一个便利贴；投票并组织最好的在地图上。

### 结束当天：选择目标

选择地图上的哪个客户和时刻进行关注——最大的风险或机会（例如，“注册后的前10分钟”）。**决策者**（具有权威的人）做出最终决定。

**周一产出：** 长期目标、冲刺问题、旅程图、专家见解、整理好的 HMW 笔记、目标客户和时刻。

在协调周一时，请参阅 [references/monday.md](references/monday.md) —— 步骤练习脚本、HMW 示例和目标选择方法。

## 周二：草图

**目标：** 生成解决方案——每个人都要绘制一个详细的解决方案。

### 上午：闪电演示

- **寻找灵感：** 3分钟演示竞争对手和类似产品（“这是我找到的，为什么它有趣”）；在白板上记录好点子。从任何行业借鉴。
- **分裂或群集：** 如果地图有多个部分，将其分成几组；否则，每个人都解决同一个关键问题（大多数冲刺群集）。

### 下午：四步草图

每个人单独绘制——**不进行小组头脑风暴**。个人工作产生更好的、更多样化的想法。

1. **笔记（20分钟）：** 安静地走动，回顾地图、HMWs 和灵感。
2. **想法（20分钟）：** 粗略的涂鸦、思维导图、火柴人——数量比质量更重要。
3. **疯狂8（8分钟）：** 将纸折叠成8个面板，并在8分钟内绘制8个变化——迫使你超越第一个想法。
4. **解决方案草图（30-90分钟）：** 一个3面板的故事板，描述客户体验（开始、中间、结束）。使其自我解释，给它一个吸引人的标题，并保持**匿名**。

**周二产出：** 每个人一个详细的、匿名的、自我解释的解决方案草图。

在执行四步草图之前，请参阅 [references/tuesday.md](references/tuesday.md) —— 疯狂8和解决方案草图模板以及团队展示的示例。

## 周三：决策

**目标：** 批判解决方案并选择最好的一个进行原型制作和测试。

### 上午：便利贴决策

- **艺术博物馆：** 将草图贴在墙上；安静地查看（不说话）并用点状便利贴标记有趣的部分。
- **热力图审查：** 每个草图讨论3分钟——协调员叙述，匿名草图者保持沉默；书记员在白板上记录突出的想法。
- **草投票：** 每个人对解决方案投一票，并附上一句理由（非约束性）。
- **监督投票：** 决策者得到三个大圆点；他们的决定获胜。

### 下午：混战或全合一

如果有多个草图获胜，选择：**混战**（竞争原型测试不同的方法）或 **全合一**（将最好的想法组合成一个原型——更简单，大多数冲刺都这样做）。

- **故事板：** 绘制一个10-15面板的漫画，描述测试体验：开场场景（客户如何发现你）→ 你的解决方案在行动中 → 成功的结果。保持简单——火柴人、文字、箭头——但要具体说明UI。只包含足够详细的细节，以便周四构建原型。

**周三产出：** 获胜解决方案和准备原型的故事板。

在运行便利贴决策和故事板时，请参阅 [references/wednesday.md](references/wednesday.md) —— 投票和故事板的协调步骤，以及面板式故事板模板。

## 周四：原型制作

**目标：** 在一天内构建一个逼真的外观——你需要一些东西来在周五进行测试。

**心态：** 假装；只原型制作你将要测试的内容。目标是要达到金发女郎级别的逼真——草图太低，无法得到诚实的反应，工作代码浪费时间。它应该看起来很真实，但不工作——外观、可点击的、视频。

### 分配角色

| 角色 | 责任 |
|------|------|
| **制作人员**（2个或更多） | 构建原型组件（设计、资源） |
| **拼接者**（1个） | 将组件组合成最终原型（Keynote、Figma） |
| **写手**（1个） | 所有文案：标题、按钮标签、描述 |
| **收集者**（1-2个） | 收集照片、图标、竞争对手截图 |
| **采访者**（1个） | 撰写和排练周五的采访脚本 |
| **冲刺主管** | 在需要时提供帮助，保持精力 |

### 构建原型

**工具：** Figma、Keynote 或 PowerPoint 链接幻灯片用于网络/应用程序；视频演示或 3D 打印模型用于实体产品；角色扮演视频或脚本交互用于服务。

上午：将故事板分成场景并分配给制作人员。下午：拼接在一起，对照故事板进行审查，排练完整流程，并与冲刺团队外的人进行试运行。

**原型清单：**
- [ ] 完全符合故事板
- [ ] 足够逼真以获得诚实的反应
- [ ] 可以在5-15分钟内进行演示
- [ ] 采访者知道如何展示它
- [ ] 完成试运行

**周四产出：** 逼真的原型、采访脚本、准备好的采访房间。

在构建原型时，请参阅 [references/thursday.md](references/thursday.md) —— 工具技术（Keynote/Figma 外观、视频、模型），以在一天内达到金发女郎级别的逼真。

## 周五：测试

**目标：** 采访5个客户；了解什么有效和什么无效。

### 设置

采访房间：安静的空间，带有原型的笔记本电脑，录制屏幕和客户脸部的摄像头。观察室：实时视频源，整个团队观看并在白板上做笔记。一个 **采访者** 进行所有五个采访。

### 五幕采访

每个客户大约45分钟（五幕运行约35分钟加上设置和过渡），每30分钟休息一次以讨论观察结果和调整问题。请参阅 references/friday.md 以获取完整的 9am-5pm 时间表。

| 幕 | 时间 | 要做什么 |
|----|------|----------|
| **1. 友好的欢迎** | 5分钟 | 热情地问候；解释你在测试原型而不是他们；获得录制许可；鼓励大声思考 |
| **2. 上下文问题** | 5分钟 | “告诉我你目前如何处理[问题]” — 了解心态和当前行为 |
| **3. 介绍原型** | 5分钟 | “这是什么？你认为它是什么用途？” 不要解释——让他们自己解释 |
| **4. 任务和提示** | 15分钟 | 开放式探索，然后是故事板任务。当卡住时： “下一步你会做什么？”，“你在想什么？” 不要帮助——观察他们挣扎 |
| **5. 复盘** | 5分钟 | “你总体上有什么想法？”，“这是为谁设计的？”，“什么有效？什么令人困惑？” |

### 五是魔法数字

在3-5个人后会出现模式，5个采访加休息后回报减少——并且五个采访加休息的时间适合一天（请参阅 references/friday.md）。通过筛选器调查招募目标客户，并提供激励（B2B 100-200美元，B2C 50-100美元）。

在冲刺前两周，请参阅 [references/recruiting.md](references/recruiting.md) —— 它包含筛选器调查问题、招募渠道、安排细节和锁定五个目标用户的激励指导。

### 做笔记：模式识别

将观察结果记录在一个网格中，每列一个客户：

| 客户1 | 客户2 | 客户3 | 客户4 | 客户5 |
|-------|-------|-------|-------|-------|
| 笔记 | 笔记 | 笔记 | 笔记 | 笔记 |

标记每个观察结果 **✓**（正面、成功）、**✗**（负面、失败）或 **~**（中性/混合）。在所有五个采访后，计算每行的标记，并寻找模式——所有5个人是否在同一个问题上挣扎？

### 冲刺结束复盘

组织发现：**✓ 什么有效**（每个人都能理解的流程、引起共鸣的信息），**✗ 什么失败**（令人困惑的术语、遗漏的步骤、错误的假设），**~ 混合**（有些人理解，有些人不理解）。然后决定下一步：

- **核心概念得到验证：** 构建，或运行下一个冲刺来处理细节
- **重大问题：** 转折，或再次冲刺来解决问题
- **完全失败：** 回到白板——你刚刚节省了数月时间

**周五产出：** 采访录音、模式笔记、一个清晰的有效和无效列表，以及下一步决策。

在采访前，请参阅 [references/friday.md](references/friday.md) —— 逐字五幕脚本、笔记模板、更完整的下一步决策表，以及要避免的常见周五错误。

## 何时运行设计冲刺

**运行时：** 决策高风险、没有时间正常构建和测试、团队陷入无休止的辩论、多个解决方案竞争、新产品/功能/重大改版，或需要在投资前降低风险。

**不运行时：** 问题和解决方案很明显，你只需要执行，团队没有买账，或者你无法在一周内获得决策者。

请参阅 [references/case-studies.md](references/case-studies.md) 以获取 Slack、Blue Bottle Coffee、Savioke 等领域的实际冲刺演练（当您需要具体先例时）。

## 变体

- **4天冲刺：** 第1天绘制+草图（压缩），第2天决策，第3天原型制作，第4天测试。
- **远程冲刺：** 相同的时间表，使用 Miro/FigJam 白板和 Zoom。在团队分布时，请参阅 [references/remote-sprints.md](references/remote-sprints.md) —— 它将每个练习调整为数字白板，设置远程时限，并处理基于视频的原型测试。
- **多轮冲刺：** 第1轮选择广泛问题的方向，第2轮深入选择的解决方案，第3轮完善细节。

## 常见错误

| 错误 | 失败原因 | 修复 |
|------|----------|------|
| **跳过原型制作** | 没有东西可以测试 | 总是原型制作，即使简单 |
| **过度设计原型** | 浪费时间在无关紧要的细节上 | 外观，不是工作代码 |
| **用错误用户测试** | 无效的反馈 | 筛选目标客户 |
| **向用户解释原型** | 搞垮测试；困惑是数据 | 按照规定运行 3-4 幕——他们自己解释和挣扎 |
| **没有决策者** | 无法做出决定 | 一周获得决策者或不要冲刺 |
| **干扰** | 打破专注 | 保护这一周，没有会议/电子邮件 |

## 快速诊断

审计任何冲刺计划：

| 问题 | 如果没有 | 行动 |
|------|----------|------|
| 我们有一个决策者吗？ | 冲刺会失败 | 获得承诺或推迟 |
| 问题重要吗？ | 浪费时间 | 只在重大挑战上冲刺 |
| 我们能在一天内原型制作吗？ | 不适合冲刺的问题 | 选择更具体的问题 |
| 我们能招募5个目标用户吗？ | 无法正确测试 | 现在开始招募（提前两周） |
| 团队会承诺没有干扰吗？ | 无法保持专注 | 获得领导层的支持 |
