# 创建网站

一个空白页面通过十个按依赖关系顺序运行的阶段转变为一个高转化的网站：先确定信息，然后进行设计，然后进行转化，然后进行残酷的审查。这段旅程是交互式的——代理在每次决策之前都会询问，并且在信息确定之前不会进行设计——并且是可恢复的，因为每个决策和工件都存在于项目的 `docs/` 文件夹中。你驱动阶段；构成技能承载着方法。

## 核心原则

**信息优先于设计，设计优先于转化——按此顺序；看起来不错只是底线，不是目标。** 访客在五秒钟内决定是否留下，这个决定取决于他们是否立刻明白你做什么以及这对 *他们* 的重要性——因此清晰度优先，设计服务于清晰度。这项技能排序阶段，提出问题，并记录决策；构成技能承载着框架。调用它们，而不是即兴创作它们的方法。

## 运行规则

1. **首先恢复。** 在做任何事之前，阅读 `docs/CREATE-WEBSITE-PLAN.md` 和旅程地图中的每个工件。如果存在跟踪器，用 3-5 行总结旅程状态，并询问进入哪个阶段。当用户确认了入口点时完成。有跟踪器的旅程是恢复的，永远不会重新启动。
2. **仅在第一次运行时进行信息收集。** 没有跟踪器：运行下面的信息收集，然后创建 `docs/CREATE-WEBSITE-PLAN.md`，将每个阶段的状态标记为 `pending | in-progress | awaiting-evidence | done | deferred: reason | skipped: reason`。当跟踪器存在并且用户确认了阶段计划时完成。
3. **阶段入口。** 宣布：阶段的作用，它强迫的决策，它产生的工件，粗略的工作量。提供继续 / 跳过 / 延迟——标记为 GATE 的阶段可以延迟，但永远不会跳过。在继续时将阶段标记为 `in-progress`。当用户选择时完成。
4. **技能调用和回退。** 加载阶段的技能并使用它：每个阶段的调用行通过 slug 命名技能——使用该技能运行阶段。如果不可用，提供：`npx skills add wondelai/skills/<slug> --global`。如果用户拒绝，从其简要中运行阶段——最低可行方法。说明你处于哪种模式。
5. **阶段内的决策。** 询问“与用户一起决策”下的每个问题——提供具体的选项和你的建议。在跟踪器的关键决策中记录选择。无声做出的决策是缺陷。
6. **阶段退出。** 在写入之前，展示草稿工件内容以供批准。批准后：写入或扩展 docs/ 文件，更新跟踪器（状态，关键决策，下一步行动）。当文件写入并且阶段行显示 `done` 时完成。
7. **工件纪律。** 写之前阅读；如果文件缺失则创建，否则扩展——添加或更新你的部分，保留其他人的部分。文件在 `docs/` 中是大写的。每个建议都作为一个复选框或一个带有所有者和优先级的表格行出现。在第一次创建 docs/ 文件时查看 [references/artifact-templates.md](references/artifact-templates.md)——从完整骨架（所有部分标题）创建它，然后填写你的阶段名称的部分。
8. **网站上的每个稀缺性声明、推荐信和保证必须真实。** 当一个说服策略需要编造证据时，用你拥有的证据替换它。

## 信息收集

在创建跟踪器之前询问以下问题：

1. 产品或服务是什么，它为谁服务？ (Gates Phase 1 的细分市场和头像，以及信息的每个字。)
2. `docs/POSITIONING.md` 或 `docs/CUSTOMER.md` 是否已经存在，因为之前的 create-business 运行而生？ (如果存在，则减轻 Phases 1-2 并重用它们；如果定位薄弱，则添加显然很棒的可选阶段。)
3. 单一主要转化目标是什么——开始试用、预订演示、购买或进行测验？ (Gates Phases 1, 8, 9 中的每个 CTA 决策。)
4. 多页面网站还是单个着陆页？ (Gates 网站结构范围，以及 Phases 8-9 是否适用。)
5. 技术栈是什么，代码在哪里？ (这样设计和文案会落在真实的文件中，而不是交接文档中。)
6. 今天存在哪些证明资产——推荐信、成果、标志、保证？ (Gates Phase 8 的说服审核和规则 8。)
7. 工艺有多重要——竞争设计，还是功能网站？ (Gates Phases 4-5 是否完全运行或轻量运行，工艺不卖（永远不跳过 refactoring-ui）；当直接 CTA 足够且没有培养动作时跳过 Phase 9；只有在残酷的时间表下才跳过 Phase 3——并警告清晰的文案但容易被忘记。然后从模板创建跟踪器并确认计划。

完成时 `docs/CREATE-WEBSITE-PLAN.md` 存在，每个阶段的状态都已标记，并且用户已确认计划。

## 阶段

### 阶段 1 — 制定策略并选择一个细分市场 (one-page-marketing)

**目的：** 在任何页面存在之前，决定网站为谁服务、独特销售主张 (USP) 和单一主要转化目标。

**简要（回退）：** PVP 指数——根据个人满足感、对市场的价值和盈利能力对候选细分市场进行评分，然后选择一个。“对每个人都说话，对任何人都不说话。” 写一个通过交换测试的 USP：如果竞争对手的名字适合你的标语，它太笼统了。将 Before 和 During 方格映射到具体页面，每个页面只有一个工作。

**调用：** 使用 `one-page-marketing` 技能，并使用信息收集中的产品和目标。询问 (a) 2-3 个细分市场的 PVP 评分，(b) 一个段落头像，(c) 一个交换测试 USP，(d) Before/During 方格映射到主页、着陆页和线索捕获页。

**与用户一起决策：** 哪个细分市场要主导（推荐最高 PVP 评分）？单一主要转化目标是什么——试用、演示、购买或测验线索？

**工件：** 创建 docs/MARKETING.md，包含 `## 目标市场和头像`（细分市场、头像、USP、主要目标）和 `## Before / During / After 网格`。扩展 docs/CUSTOMER.md，包含 `## 细分市场和最佳客户`。更新跟踪器。

**完成时：** MARKETING.md 指定一个细分市场、一个交换测试 USP 和一个主要目标；CUSTOMER.md 记录了最佳匹配的细分市场；用户确认了细分市场和目标。

### 阶段 2 — 使用 StoryBrand 写信息 (storybrand-messaging)

**目的：** 写访客在五秒钟内判断的文字——客户是英雄，你是向导。

**简要（回退）：** SB7——一个想要某物的角色，一个问题（外部/内部/哲学），一个有同情心和权威的向导，一个计划，一个号召行动，失败的赌注，生动的成功。命名内部问题（它 *感觉* 如何），而不仅仅是外部问题。一句话：“我们帮助 [角色] 谁在 [问题] 中挣扎，以 [解决方案] 所以他们可以 [结果]。”

**调用：** 使用 `storybrand-messaging` 技能，并使用 MARKETING.md 中的头像和 USP。询问一个完整的品牌脚本，主页文案遵循 StoryBrand 线框（标题、赌注、价值、向导、计划、CTA），以及五个按可重复性排名的一行变体。

**与用户一起决策：** 哪个一行是最可重复的？确认客户，而不是品牌，是英雄——没有开头的“我们”。

**工件：** 创建 docs/POSITIONING.md，包含 `## 品牌脚本 (StoryBrand)`，`## 一行`，`## 关键信息`。创建 docs/WEBSITE.md，包含 `## 网站结构` 和 `## 页面简要`（线框派生的文案块）。更新跟踪器。

**完成时：** POSITIONING.md 包含一个完整的品牌脚本和一个锁定的一行；WEBSITE.md 包含一个网站结构和主页页面简要；用户批准了一行。

### 阶段 3 — 使信息令人难忘 (made-to-stick)

**目的：** 将清晰的文案转变为令人难忘的文案，它能在关闭的标签页中生存并得到重复。

**简要（回退）：** SUCCESs——简单、意外、具体、可信、情感、故事。对抗知识的诅咒。最高杠杆是具体：用图片替换每个抽象概念（“报告生成从 4 小时到 10 分钟”）。添加一个意外的钩子，一个 Sinatra 测试证明，和一个客户故事。

**调用：** 使用 `made-to-stick` 技能，并使用 WEBSITE.md `## 页面简要` 中的文案和 POSITIONING.md 中的信息。询问一个 SUCCESs 评分，每个抽象益处的具体重写，一个意外的英雄钩子，和一个简短的客户故事。

**与用户一起决策：** 批准粘性重写并选择英雄钩子。哪些数字和声明是真实且可引用的（这为规则 8 提供了信息）？

**工件：** 扩展 docs/POSITIONING.md `## 关键信息`（粘性版本）和 docs/WEBSITE.md `## 页面简要`（具体文案）。更新跟踪器。

**完成时：** 每个抽象益处都是一个具体结果，带有真实的数字，一个意外的钩子和一个客户故事存在，文案已签收。

### 阶段 4 — 设计标志性时刻 (top-design)

**目的：** 使页面看起来像是由代理制作的，而不是模板制作的——从一张值得截图的时刻开始。

**简要（回退）：** 每个像素都是有意为之的。从标志性时刻开始，而不是标题：戏剧性的比例（最小 10:1 显示到身体），非对称构图，协调加载，~80ms 的单词延迟显示。自定义立方贝塞尔曲线（expo-out `0.16,1,0.3,1`），只动画 `transform`/`opacity`，暖色调的黑色 (`#0a0a0a`) 而不是纯黑色。只有在用户选择的情况下才使用自定义光标。

**调用：** 使用 `top-design` 技能，并使用 POSITIONING.md 和 WEBSITE.md 页面简要。询问标志性英雄设计，一个自定义颜色系统（没有 AI 紫色到蓝色的渐变），以及跨字体、构图、运动、颜色和细节的评分审核。

**与用户一起决策：** 哪个标志性时刻值得截图？批准颜色系统。自定义光标——是，还是原生（除非工艺是产品，则推荐原生）？

**工件：** 创建 docs/DESIGN.md，包含 `## 设计方向`（标志性时刻、个性、参考）。更新跟踪器。

**完成时：** DESIGN.md 指定标志性时刻和颜色系统，顶设计审核评分被记录，用户批准了方向。

### 阶段 5 — 选择和调整字体 (web-typography)

**目的：** 使字体既可读又引人注目——戏剧背后的纪律。

**简要（回退）：** 清晰高脚杯原则——字体服务于内容。“为片刻设计字体”（标题）与“为生活设计字体”（正文）。三个测量值优于字体选择：16-18px 正文，45-75ch 测量（66 最佳，`max-width: 65ch`），正文行高 1.5-1.7 / 标题行高 1.1-1.25。一到两个家族。小于 200KB 负载，WOFF2，可变字体，`clamp()` 流体缩放，预加载 + `font-display: swap`。

**调用：** 使用 `web-typography` 技能，并使用 DESIGN.md `## 设计方向`。询问一个显示+正文搭配，完整的 CSS（clamp 缩放，按上下文行高，65ch 测量），以及小于 200KB 的字体加载计划，零布局偏移。

**与用户一起决策：** 批准搭配；确认性能预算（推荐使用单个可变字体以减少文件数量）。

**工件：** 扩展 docs/DESIGN.md `## 字体`（字体、缩放、测量、行高、加载策略）。更新跟踪器。

**完成时：** DESIGN.md `## 字体` 指定搭配、缩放、测量和小于 200KB 的加载策略，用户批准了搭配。

### 阶段 6 — 使其系统化 (refactoring-ui)

**目的：** 添加一致性，以防止在第二部分和第三部分时哇哦效果崩溃。

**简要（回退）：** 首先以灰度设计，最后添加颜色。系统优于才能：约束间距、字体、颜色和阴影的规模。从结合杠杆创建层次结构（大或粗或暗），只保留所有三个元素中的一个。组之间的空间大于组内的空间。近黑色 (`#111827`) 而不是纯 `#000`，色调灰。双层阴影映射到高度。运行模糊测试。

**调用：** 使用 `refactoring-ui` 技能，并使用 DESIGN.md。询问一个灰度层次结构审核，一个约束令牌集（间距、9 色调调色板、色调灰、字体缩放、阴影缩放），以及重写的按钮/表单/卡片组件，每个部分有一个主要操作。

**与用户一起决策：** 批准令牌规模；确认主要/次要/三级按钮层次结构。

**工件：** 扩展 docs/DESIGN.md `## 令牌`（间距、调色板、阴影）和 `## 组件`（每个组件的决策）。更新跟踪器。

**完成时：** DESIGN.md 定义了令牌规模和组件决策，按钮在每个部分显示一个清晰的主要操作，用户批准了令牌。

### 阶段 7 — 使其轻松使用 (ux-heuristics)

**目的：** 移除访客思考的摩擦。

**简要（回退）：** 页面必须显而易见；用户扫描、满足、混用。树干测试——冷掉放在任何页面上，他们能否回答网站是什么、页面是什么、部分是什么、下一步去哪里？运行“去掉一半的单词”。平语文本 CTA。模糊时进行内联验证，标记可选字段而不是必填字段，44x44px 触摸目标，可见系统状态（“保存中”/“已保存”，骨架，确认）。

**调用：** 使用 `ux-heuristics` 技能，并使用 WEBSITE.md 和 DESIGN.md。询问针对 Krug 定律和 Nielsen 的 10 个启发式规则的可用性审核，每个问题评分 0-4，以及重写的错误消息和 CTA 标签。

**与用户一起决策：** 批准优先级修复列表，从灾难性（4）问题开始；确认哪些修复在发布前交付，哪些稍后交付。

**工件：** 扩展 docs/DESIGN.md `## UX 审核发现`（问题 | 启发式 | 严重性 | 修复 | 状态）。更新跟踪器。

**完成时：** 每个页面都通过树干测试，灾难性问题已修复，UX 审核发现记录了严重性，用户批准了修复顺序。

### 阶段 8 — 工程转化 (cro-methodology)

**目的：** 将一个清晰、易用的页面转变为一个能回答访客不转化的真正原因的页面。

**简要（回退）：** 不要猜测——去发现。构建一个反对/反驳表，用于 Big 5（信任、价格、匹配、时机、努力）；将每个反驳放在摩擦点，永远不会埋在 FAQ 中；使用“CO Only”来反对访客不会承认的反对意见。证明层次结构：具体结果带上下文 > 命名推荐信 > 案例研究 > 纯粹的标志。证明三明治；具体数字（“47,832”而不是“大约 50,000”）。

**调用：** 使用 `cro-methodology` 技能，并使用 WEBSITE.md 和信息收集中的证明资产。询问一个 Big-5 反对/反驳表，放置、按证明层次结构排名的劝说资产审核、缺失证明的愿望清单和 A/B 测试假设。

**与用户一起决策：** 哪些反驳现在交付，哪些等待必须获取的证明？确认没有反驳编造证据（规则 8）。

**工件：** 扩展 docs/WEBSITE.md 中的 `## 转化元素`（异议 | 反驳 | 放置 | 状态）。扩展 docs/EXPERIMENTS.md 中的 `## 实验卡片` 和 `## 实验待办列表`。更新追踪器。

**完成标准：** 当 Big-5 表格对每个异议都有基于证据的反驳和放置方案，缺失的证据列在行动项中，测试假设被记录，并且没有反驳依赖于虚构的证据时。

### 第 9 阶段 — 添加一个能产生潜在客户的测验（scorecard-marketing）

**目的：** 捕获大约 97% 目前尚未准备购买的用户，通过提供一个低承诺度的方案。

**简要（备用）：** 一切都源自潜在客户生成；测验的转化率是 30-50%，而静态 PDF 的转化率是 3-10%。四个步骤：一个着陆页（概念钩子 + 三个 C — 清晰性、可信度、连接性），一个在问题之前就捕获邮箱的问卷，一个分层结果页面，以及一个分段的后续跟进。"正在向...发展"的钩子比恐惧型的钩子更有效。对于冷流量，将其保持在 8-15 个问题。

**调用：** 使用 `scorecard-marketing` 技能，以主要目标和用户画像为目标。请求一个概念钩子和着陆页，3-4 类别中的 10-12 个评分问题，三个结果层级，每个层级都有动态文案和 CTA，以及一个按层级分段的后续跟进序列。

**与用户决定：** 网站是否需要一个潜在客户培育动作？如果只有一个直接 CTA 足够，则跳过此阶段。否则批准概念钩子。

**工件：** 扩展 docs/WEBSITE.md 中的 `## 潜在客户捕获`（测验漏斗设计）。扩展 docs/MARKETING.md 中的 `## 培育序列`（分层后续跟进）。更新追踪器。

**完成标准：** WEBSITE.md 中的 `## 潜在客户捕获` 指定了一个钩子，≤15 个问题且在问题之前捕获邮箱，以及分层结果；MARKETING.md 包含分段的后续跟进；钩子承诺的仅是评估能提供的。

### 第 10 阶段 — 按一个极其出色的标准来要求（steve-jobs-design-review）— GATE

**目的：** 在任何访客看到网站之前，对其进行一次残酷、诚实的审查。

**简要（备用）：** "从客户体验开始，然后倒推。" 以陌生人的身份冷体验。用一句话陈述一件事。计算到价值步骤（三个，而不是九个）。走慢速路径 — 空白表单、错误状态、支付失败、移动冷启动。检查围栏后面 — 404、错误文案、确认邮件。结论是二元的：极其出色，或者未完成。聚焦就是说不。

**调用：** 使用 `steve-jobs-design-review` 技能，以实时网站或完整页面集为目标。请求一个冷的第一印象、一件事、到价值步骤计数、失败/空白状态的行走和围栏后面的检查、二元结论、以及一个排名的删减列表和修复列表。

**与用户决定：** 根据删减列表采取行动 — 删除什么来保护单一主要目标？如果结论是 NOT DONE，哪些修复阻碍了发布？

**工件：** 扩展 docs/WEBSITE.md 中的 `## 审计发现`（问题 | 严重性 | 修复 | 状态），包含删减列表和修复列表。更新追踪器。

**完成标准：** 结论是 INSANELY GREAT（不是“还不错”），应用了删减列表，检查了围栏后面，并且阻塞的修复已关闭 — 只有这样，网站才能发布。

| 技能 | 添加条件 | 工件 |
|---|---|---|
| obviously-awesome | `docs/POSITIONING.md` 尚未存在，且信息没有立足点 | 创建 docs/POSITIONING.md |
| influence-psychology | 定价或注册页面需要说服原则审计 | 扩展 docs/WEBSITE.md |
| high-perf-browser | 核心网络指标或加载速度威胁转化率 | 扩展 docs/WEBSITE.md |
| design-everyday-things | 表单或流程在视觉干净的情况下仍让用户困惑 | 扩展 docs/DESIGN.md |

可选阶段遵循相同的操作规则 — 恰当加载并使用每个列出的技能，就像核心阶段一样；在添加条件首次变为真时插入。

## 常见错误

| 错误 | 修复 |
|---|---|
| 在没有信息的情况下进行设计 | 在第 2 阶段（故事品牌）和第 3 阶段之前运行第 4 阶段（顶级设计）；设计服务于文字，而不是相反。 |
| 让品牌成为英雄 | 在故事品牌中，从客户的问题和期望结果开始；如果第一句话以 "We" 开头，请重写它。 |
| 堆叠竞争的号召性用语 | 保持一个直接 CTA 和一个过渡性；refactoring-ui 和 Jobs 审查都强制每个部分一个主要动作。 |
| 混淆清晰与粘性 | 运行 made-to-stick 过程 — 具体数字、一个意想不到的钩子、一个客户故事 — 以确保信息在关闭标签后仍然存在。 |
| 测试按钮颜色而不是异议 | 首先在 cro-methodology 中构建异议/反驳表格；"微小的调整"很少能提高转化率。 |
| 精美的成功路径，其他地方都坏了 | 在 Jobs 审查中，走空白状态、表单错误、404、确认邮件和移动冷启动 — 围栏后面。 |
