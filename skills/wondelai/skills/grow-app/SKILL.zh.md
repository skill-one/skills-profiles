# 增长应用

您的应用有用户注册后便默默消失——用户群逐渐衰减，日活跃用户数停滞不前，激活漏斗总是在老地方泄漏，而且看起来没有任何明显的问题。这段旅程封住了漏斗：它将初次用户转化为活跃用户，然后是习惯用户，最后是会错过的用户，跨越八个交互阶段。代理在每次决策前都会询问并记录结果在 `docs/` 中，以便工作可以在会话之间继续而不是重新开始。这里的增长是一个工程和设计问题，而不是更大的广告预算。

## 核心原则

**在投入获取之前修复漏斗：习惯、激活和留存优先于任何增长支出。** 这项技能按顺序排列八个阶段，询问每个决策问题，并将每个选择记录在 `docs/` 中。构成技能的方法论——调用它们而不是即兴创作它们的框架。

## 旅程地图

| 阶段 | 技能 | 回答的问题 | 产出物 |

| 2 | improve-retention | 为什么新用户没有达到循环？ | 扩展 docs/PRODUCT.md |
| 3 | continuous-discovery | 我们自己的用户实际上需要什么？ | 扩展 docs/PRODUCT.md + docs/CUSTOMER.md |
| 4 | lean-ux | 哪个赌注值得建设？ | 扩展 docs/EXPERIMENTS.md |

阶段 1-2 封住了循环和漏斗；3-5 用证据引导；6 是仪表盘；7-8 是终点和道德底线。尽早获取精益分析的基准（阶段 6）——在阶段 1-2 的修复落地之前——这样每个变更都是与变更前的数字对比，然后不断更新它。习惯形成是缓慢的：用阶段 1 的成功与“5% 规则”（当 5%+ 的用户在没有提示的情况下回来时，习惯已经形成）对比，而不是单个用户群。

## 运营规则

1. **首先继续。** 在做任何事之前，阅读 `docs/GROW-APP-PLAN.md` 和旅程地图中的每个产出物。如果存在追踪器，用 3-5 行总结旅程状态并询问进入哪个阶段。完成时用户确认了入口点。有追踪器的旅程是继续，而不是重启。
2. **仅在首次运行时进行摄入。** 没有追踪器：运行下面的摄入，然后创建 `docs/GROW-APP-PLAN.md`，将每个阶段状态为 `pending | in-progress | awaiting-evidence | done | deferred: 原因 | skipped: 原因`。完成时追踪器存在，用户确认了阶段计划。
3. **阶段入口。** 宣布：阶段的作用、它强制的决策、它产生的产出物、粗略的工作量。提供继续 / 跳过 / 延迟——标记为 GATE 的阶段可以延迟，但不能跳过。在继续时将阶段标记为 `in-progress`。完成时用户选择了。
4. **技能调用和回退。** 加载阶段的技能并使用它：每个阶段的调用行通过 slug 命名技能——使用该技能运行阶段。如果不可用，提供：`npx skills add wondelai/skills/<slug> --global`。如果用户拒绝，从其简要中运行阶段——最小的可行方法。说明你处于哪种模式。
5. **阶段内的决策。** 询问“与用户一起决策”下的每个问题——提供具体的选项和你的建议。在追踪器的关键决策中记录选择。无声做出的决策是缺陷。
6. **阶段退出。** 在写入之前，呈现草稿产出物内容以供批准。批准后：写入或扩展 docs/ 文件，更新追踪器（状态、关键决策、下一步行动）。完成时文件已写入，阶段行显示 `done`。
7. **产出物纪律。** 写之前先读；如果文件缺失则创建，否则扩展——添加或更新你的部分，保留其他人的部分。文件在 `docs/` 中是大写的。每个建议都作为复选框或带所有者和优先级的表格行落地。创建 docs/ 文件时查看 [references/artifact-templates.md](references/artifact-templates.md)——从完整骨架（所有部分标题）创建，然后填充你的阶段名称的部分。
8. **留存优先于获取。** 以获取为导向的阶段——可选的冷启动问题、有传染性、跨越鸿沟，以及任何付费增长工作——在激活和留存低于摄入设置的基准时保持锁定；只有在用户群曲线超过该基准时才解锁它们。每个习惯循环和奖励都必须通过操纵矩阵：只建设制作者会使用并诚实地认为实质性改善用户的东西。当一种策略需要制造焦虑或损失规避时，用基于真实价值的一种策略替换它。

## 摄入

仅在首次启动时运行（无追踪器）。询问：

1. 应用做什么，以及留存用户重复的核心动作是什么？（定义 Hook 循环和 OMTM）
2. 当前留存数字是多少——第 1 天/7 天/30 天或第 4 周的群体？（设置规则 8 的获取基准；为精益分析提供输入）
3. 激活漏斗在哪里泄漏，以及首次运行流程是什么？（控制 improve-retention）
4. 独立/小团队还是完整产品三人组（PM、设计师、工程师）？（扩展 continuous-discovery 和 inspired-product）
5. 应用是网络/市场产品，并且参与用户没有转化为收入？（标记可选的冷启动问题 / 创新变现）
6. 今天存在哪些分析和仪器？ （控制 lean-analytics 和每个实验）
7. 留存是因为 UX 或性能问题而不是缺少互动？ （如果是，先路由到 improve-app）

跳过启发式方法：对于没有团队可以重新对齐的独立创始人，跳过阶段 5；直到循环和激活超过他们的基准再延迟阶段 7；如果没有用户访问，运行阶段 3 的降级节奏。然后从 references/artifact-templates.md 创建追踪器，将每个阶段状态，并确认计划。

完成时 `docs/GROW-APP-PLAN.md` 存在，每个阶段都已状态，并且用户确认了计划。

## 阶段

### 阶段 1 — 设计带来用户回访的习惯循环（hooked-ux）

**目的：** 建设返回的引擎——一个足够强的 Hook 循环，用户在没有付费通知的情况下回来。

**简要（回退）：** Hook 模型运行触发器 → 动作 → 可变奖励 → 投资。将外部触发器（推送、邮件）迁移到内部触发器（情绪——无聊、FOMO、焦虑）。使动作极其简单。使奖励在部落/狩猎/自我之间可变。将投资序列在奖励之后，以提高转换成本并加载下一个触发器。一个循环如果有一个薄弱阶段就会停滞，而不是半工作。

**调用：** 使用 `hooked-ux` 技能，以及核心循环和今天每日活跃用户如何回来。询问它 (a) 跨越所有四个阶段绘制循环，每个阶段评分 0-10，并命名最弱的，以及 (b) 设计由你已有的数据支持的诚实可变奖励概念，每个概念都经过操纵矩阵检查。

**与用户一起决策：**
- 哪个内部触发器（情绪）应该拉回用户——确认一个。
- 哪个单一阶段最弱，现在得到最高杠杆的修复——如果循环已经形成（5%+ 无提示返回），则延迟。
- 哪种奖励类型需要加强——部落（社交）、狩猎（资源）或自我（掌握）——拒绝任何失败操纵矩阵的概念。

**产出物：** 扩展 docs/PRODUCT.md `## Hook Model`（触发器 → 动作 → 可变奖励 → 投资；命名最弱的阶段）。更新追踪器。

**完成时：** PRODUCT.md 命名了内部触发器和对所有四个阶段，记录了最弱的阶段及其修复，入职被重新设计，新用户在首次会话中完成一个完整的 Hook 循环，并且用户选择了要发布的修复。

### 阶段 2 — 通过使首次动作几乎毫不费力来修复激活（improve-retention）

**目的：** 通过使首次有意义的动作几乎毫不费力，让新用户达到循环。

**简要（回退）：** B=MAP——行为只有在动机、能力和提示汇聚时才会触发。动机不可靠；提高能力。简单性受限于六个资源中最稀缺的资源：时间、金钱、体力、脑力、社会偏差、非常规性。将目标缩小为在 30 秒内提供价值的起步步骤，将其锚定到现有例行程序，并立即庆祝胜利。

**调用：** 使用 `improve-retention` 技能，逐步进行真实的激活流程，以及第 1 天/7 天/30 天的流失率。请求所有六个能力链因素的 B=MAP 摩擦审计评分，最稀缺的资源命名，起步步骤重新设计，以及基于事件的提示规则。

**与用户一起决策：**
- 哪个是首次动作的最稀缺资源——首先修复该链接，而不是明显的链接。
- 起步步骤（最小的有价值动作）及其庆祝时刻。
- 哪些基于时间的提示转换为基于事件的，丢弃任何失败的“我现在会欣赏这个吗？”。

**产出物：** 扩展 docs/PRODUCT.md `## 激活和留存计划`（摩擦/时刻 | 修复 | 所有者 | 状态）。更新追踪器。

**完成时：** 最稀缺的资源被命名，起步步骤、庆祝和提示更改是带所有者的行，每个第 1 天/7 天/30 天的流失率都映射到可能的 B=MAP 失败，并且用户批准了修复列表。

### 阶段 3 — 运行持续发现，停止猜测（continuous-discovery）

**目的：** 用每周关于你自己的用户的证据流替换通用最佳实践。

**简要（回退）：** 目标是每周至少有一个客户触点。构建机会解决方案树：结果在顶部 → 客户机会（客户的话中的需求和痛苦）→ 候选解决方案/实验。永远不要从结果→解决方案跳跃。访谈是基于故事的（“告诉我你上次……的时候”），作为一页快照捕获。首先廉价地测试风险最大的信仰跳跃假设。

**调用：** 使用 `continuous-discovery` 技能，以及留存结果和已知的流失模式。请求机会解决方案树，流失用户今天尝试成功当前状态的经验地图，每周基于故事的访谈快照模板，以及下一个计划功能的假设地图。

**与用户一起决策：**
- 树顶部的单一结果。
- 首先追求的两个或三个机会。
- 团队实际上可以持续每周节奏和招募机制——现在设置或运行降级。
- 下一个功能中最危险的信仰跳跃假设（可取性、可行性、可行性、可用性）以及对其进行的最便宜测试。

**产出物：** 扩展 docs/PRODUCT.md `## 机会解决方案树笔记`，`## 结果路线图`（结果/问题 | 满足的工作 | 优先级 | 状态），以及 `## 发现节奏`；扩展 docs/CUSTOMER.md `## 访谈证据`（日期 | 谁 | 事实 | 承诺）。更新追踪器。

**完成时：** 树的结果和顶部机会被记录，节奏已安排，第一个访谈快照模板存在，最危险的假设有一个廉价测试设计。

### 阶段 4 — 用廉价的实验替换辩论（lean-ux）

**目的：** 将机会转化为可证伪的赌注，由行为而不是会议决定。

**简要（回退）：** 结果重于产出——价值是行为变化，而不是可交付成果。写一个假设：“我们相信 [结果] 将会发生，如果 [角色] 实现 [动作] 使用 [功能]，”并承诺指标和阈值*在测试之前*。匹配保真度与风险（用五个用户的纸原型发现 ~85% 的可用性问题）；为调整一个已证明的概念保留 A/B 测试。当被无效时，从积压中移除——不要延迟。

**调用：** 使用 `lean-ux` 技能，当前最大的设计辩论或顶部的发现机会。请求三个标准格式的假设陈述，可以验证顶部一个的最低保真度实验，以及其预承诺的指标、阈值和时间限制。

**与用户一起决策：**
- 首先测试哪个假设。
- 实验保真度——回答实际问题的最低保真度。
- 通过/失败线以及如果失败则离开积压的内容。

**产出物：** 扩展 docs/EXPERIMENTS.md `## 实验卡片`（假设、类型、主要指标 + 阈值、护栏、决策规则）和 `## 实验积压`（想法 | ICE | 状态）。更新追踪器。

**完成时：** 至少有一个实验卡片有预承诺的阈值和决策规则，积压被排序，并且用户选择了第一个测试。

### 阶段 5 — 用授权的团队建设正确的东西（inspired-product）

**目的：** 将团队从功能工厂转变为结果所有权——要解决的问题，而不是要发送的功能。

**简要（回退）：** 授权的团队得到问题，而不是积压，并为结果负责。双轨：发现（什么值得建设——解决价值、可用性、可行性、可行性）与交付持续运行。预期每个发送功能有 10-20 个发现迭代。给团队产品愿景和基于结果的路线图，以便它可以自主决策。

**调用：** 使用 `inspired-product` 技能，以及顶三个积压请求和当前路线图。请求每个机会的评估（目标、目标用户、问题、成功指标、替代方案）和一个段落产品愿景加上四分之一基于结果的路线图项目。

**与用户一起决策：**
- 哪个积压请求有最强的证据——以及哪个在到达冲刺之前被杀死。
- 一个段落产品愿景。
- 路线图是否重新定义为问题 + 关键结果，而不是日期功能。

**产出物：** 扩展 docs/PRODUCT.md `## 愿景` 和 `## 结果路线图`（结果/问题 | 满足的工作 | 优先级 | 状态）。更新追踪器。

**完成时：** 愿景段落存在，每个三个请求都有一个构建/杀死裁决，路线图行是结果，而不是功能。

### 阶段 6 — 测量实际重要的一个数字（lean-analytics）

**目的：** 指导整个团队关注一个重要指标，并暴露隐藏衰减的虚荣指标。

**简要（回退）：** 一个好指标是比较性的，比率/速率（不是累积总数），行为变化的。商业模式决定哪个指标重要；阶段决定顺序（同理心 → 粘性 → 传播 → 收入 → 规模）。留存薄弱 = 粘性阶段，所以留存是 OMTM——首先处理后期阶段是典型的错误。画一条线（目标、日期、错失响应），将 OMTM 与反指标配对，对群体数据进行分组。

**调用：** 使用 `lean-analytics` 技能，当前仪表板/指标和商业模式。请求它标记虚荣指标，选择粘性阶段的 OMTM 加一个反指标，设计一个一屏仪表板（OMTM 大，≤6 个支持），以及一个分组留存视图。

**与用户一起决策：**
- OMTM 和其反指标。
- 线在沙中——目标、日期、预承诺的错失响应。
- 哪些当前指标被标记为虚荣。

**产出物：** 创建 docs/METRICS.md，包含 `## 阶段 & 一个重要指标`，`## KPI 定义`，`## 基线 & 目标`，`## 漏斗`，和 `## 分组笔记`。更新追踪器。

**完成时：** METRICS.md 命名了 OMTM + 反指标，记录了线在沙中与日期，列出了分组的基线，虚荣指标被标记为已退役，一屏仪表板被指定，规则 8 获取门栏的留存条被设置。

### 阶段 7 — 磨光让应用感觉生机勃勃的微时刻（microinteractions）

**目的：** 关闭应用人们忍受和人们爱好的差距，在每天接触的日常时刻。

**简介（备用）：** 每个微交互都有触发器→规则→反馈→循环与模式。反馈是即时的（直接操作时<100毫秒）且成比例的；将用户触摸的元素动画显示在单独的吐司上。映射每个状态：空、加载中、部分、错误、禁用、双击。投资一个或两个通过移除测试的标志性时刻；使用长循环来为高级用户退休提示。

**调用：** 使用 `microinteractions` 技能，针对最常用的五个交互。要求对每个交互进行触发器/规则/反馈/循环的审计，100毫秒内的反馈和缺失的边缘状态，以及一个在真实代码中实现的标志性时刻。

**与用户共同决定：**
- 哪五个交互进行审计。
- 哪一个成为标志性时刻（应用移除测试）。
- 哪些边缘状态优先实现。

**产出物：** 扩展 docs/DESIGN.md `## 微交互清单`（交互 | 触发器/规则/反馈/循环 | 修复 | 状态）。更新追踪器。

**完成时：** 五个交互在清单中包含其缺失的状态和修复，标志性时刻已选择，并且每个修复都有状态。

### 第8阶段 — 通过内在动机维持参与度（驱动动机）

**目的：** 防止循环变质——基于自主性、掌握感和目标感，而不是剥削的参与度。

**简介（备用）：** 对于任何需要认知努力的任务，“如果-那么”奖励会扼杀内在动机。持久的参与度是自主性（对什么、何时、如何、与谁的选择权）、掌握感（可见的进度、流调校的挑战）和目标感（它为何重要）。自主性杀手：强制教程、不可跳过的步骤、强制通知。为有意义的里程碑保留奖励；优先选择“现在-那么”认可，而不是“如果-那么”交易。

**调用：** 使用 `drive-motivation` 技能，针对应用的 gamification、连续记录、积分和通知模式。要求进行 AMP 审计评分0-10，标记所有违反自主性的情况，连续记录在哪个点转变为损失厌恶，以及围绕真实掌握感和目标感进行进展重新设计。

**与用户共同决定：**
- 哪些自主性违反情况需要移除（强制/不可跳过的步骤）。
- 哪些“如果-那么”奖励转换为“现在-那么”认可。
- 是否任何连续记录/积分机制利用了损失厌恶，必须改变。

**产出物：** 扩展 docs/PRODUCT.md `## 激活与留存计划`，添加 AMP 审计行（违反/发现 | 修复 | 负责人 | 状态）。更新追踪器。

**完成时：** AMP 分数和每个自主性违反情况都被记录，奖励/连续记录修复是带有负责人的行，并且循环通过规则8的操纵矩阵。

## 常见错误

| 错误 | 修复 |
|---|---|
| 在修复留存之前购买增长 | 在任何获取支出之前通过粘性门（平缓的队列曲线）；根据规则8锁定获取阶段。 |
| 永远依赖外部触发器 | 通过 hooked-ux 迁移到内部触发器；将通知视为脚手架，而不是承重墙。 |
| 优化错误的 Ability-Chain 链接 | 在 improve-retention 中评估所有六个因素，修复最稀缺的资源，而不是最明显的一个。 |
| 直接从结果跳到解决方案 | 首先在 continuous-discovery 中构建机会解决方案树；最明显的功能通常是五个中最差的。 |
| 衡量输出而不是结果 | 仪器每个发布；在 lean-ux 和 inspired-product 中，成功是用户行为的变化，而不是发送的故事。 |
| 为所有事情使用积分进行游戏化 | 为有意义的里程碑保留奖励，运行 drive-motivation AMP 审计；“如果-那么”奖励会挤占你的高级用户。 |
