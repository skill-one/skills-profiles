# 史蒂夫·乔布斯设计评审

像史蒂夫·乔布斯那样进行设计和产品评审：从客户体验出发，不断削减直到只剩下本质，拒绝将任何未臻完美的工作称为完成。

## 核心原则

**“你必须从客户体验开始，然后倒推技术。”** 评审每一个产品时，都要从客户看到、感受到和完成的事情出发——永远不要从功能列表、组织结构图或偶然可用的技术出发。记住这个标准：“设计不仅仅是看起来和感觉起来怎么样。设计是它的工作方式。”

## 评分

**目标：10/10。** 计算产品通过了其中的7项快速诊断行中的多少项，然后映射到0-10分：7/7=10，6/7=9，5/7=7，4/7=6，3/7=4，≤2/7 ≤ 3。等级：**9-10** = 极致完美，可发布；**5-8** = 需要真正的削减和修复；**≤4** = 未完成，返回演示。没有“足够好”；要陈述分数、具体的失败行、以及达到10/10所需的特定削减或修复项。

## 框架

### 1. 简洁是终极的精妙

**核心概念：** 简洁并非功能的缺失——而是征服了复杂性。不断削减，直到再削减任何东西都会破坏产品的目的。

**为什么有效：** 用户必须感知、解析或决定每一个元素，这都会分散注意力并侵蚀信心。在深刻理解问题后幸存的简洁感是必然的；通过隐藏东西实现的简洁感是破败的。

**关键洞察：**
- “让事情变得简单需要大量的艰苦工作，真正理解底层挑战并提出优雅的解决方案”
- iPod没有开/关按钮——需求被设计掉了，而不是按钮被隐藏了
- 衡量价值步骤：乔布斯要求任何歌曲在三按内完成；原始iDVD提案是一个窗口，拖入视频，点击“烧录”
- 倾向于用一个好的默认值而不是一个设置；每个偏好都是你未能做出的决定
- 如果必须解释它，就重新设计它——说明是道歉

**评审应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 功能审核 | 计算核心价值步骤；削减主路径上的任何东西 | 注册 → 三步内获得第一个价值，而不是九步 |
| UI 批评 | 删除元素直到屏幕表达一个意图 | 每个屏幕一个主要按钮 |
| 设置评审 | 用有争议的默认值替换选项 | 自动保存始终开启；没有切换 |

**评审提示：**
- “我们能删除什么，还能让这个工作得更好吗？”
- “它为什么在这里？谁需要它，核心用户需要它吗？”
- “用一句话解释这个屏幕。不能？它是两个屏幕——或者没有。”

**道德边界：** 通过为用户解决复杂性来简化，而不是隐藏必要的控制或成本（定价、隐私、取消）在哪里都找不到。

运行简洁性审核时查看 [参考资料/简洁与专注.md](参考资料/简洁与专注.md) — 5步削减方法、价值步骤测量和表面与深层简洁性表。

### 2. 聚焦意味着说不

**核心概念：** “聚焦就是说不。” 决定不做什么和决定做什么同样重要——创新是说“不”到1000件事。

**为什么有效：** 努力分散在许多不错的事情上什么也做不出。砍掉好主意可以集中团队最好的人员和注意力在少数重要产品上，并保护产品不被变成委员会的愿望清单。

**关键洞察：**
- 1997年乔布斯削减了数十款苹果产品，缩减为2×2矩阵：消费者/专业 × 桌面/便携式——聚焦拯救了公司
- 在会议中，团队的十大优先级列表被削减到三个：“我们只能做三个”
- “我对我们没有做的事情和已经做的事情一样自豪”
- 没有最近被砍掉项目的路线图是不聚焦的，它是未经审视的
- 说“不”包括已经发布的特性——删除也是一种特性

**评审应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 路线图评审 | 强制排序，然后砍掉第3名以下的所有内容 | Q3计划：3个赌注，而不是14个待办事项 |
| 范围蔓延 | 要求每增加一项都要删除一项 | 新的仪表板小部件 = 停用一个小部件 |
| 产品线 | 合并重叠的SKU/层级 | 每种客户类型一个计划 |

**评审提示：**
- “如果我们这个季度只能发布一件事，哪一个是——为什么其他东西没被砍掉？”
- “这个产品在哪些方面故意做得不好？”
- “这个周期我们拒绝的是什么？什么都没有？那我们就接受了平庸。”

**道德边界：** 对范围说不，永远不对证据说不——删除一个特性是策略；忽视与你的愿景相矛盾的用户痛苦是虚荣。

运行说“不”仪式时查看 [参考资料/评审协议.md](参考资料/评审协议.md) — 强制排序到三个的练习、每个增加都要删除的规则，以及如何在实时评审中运行不列表。

### 3. 设计是它的工作方式

**核心概念：** 设计不是在最后应用的装饰——它是产品行为架构。评判流程、速度和失败状态，而不仅仅是模型的美丽。

**为什么有效：** 用户不会体验截图；他们会体验延迟、错误、中断和序列。一个美丽但卡顿、丢失工作或在失败时令人困惑的产品，无论它看起来如何，都是设计糟糕的。

**关键洞察：**
- iPhone键盘通过行为（积极的自动更正）而不是视觉效果取得成功——工程和设计是一个学科
- 评审最慢的时刻，而不是快乐路径：冷启动、空状态、离线、错误恢复
- “它就是工作”是一个设计规范：零配置、零手动、零仪式
- 与功能作斗争的美是装饰；拒绝它
- 延迟是一个设计属性——2秒的等待是设计缺陷，无论它存在于堆栈的哪个位置

**评审应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 模拟评审 | 要求交互，而不是静态 | 点击状态，而不是幻灯片 |
| 性能 | 在评审中设置体验预算 | 首屏 < 1秒，否则评审失败 |
| 失败设计 | 走错误/空/离线路径 | 支付失败 → 用户确切知道下一步 |

**评审提示：**
- “告诉我它失败时会发生什么。”
- “在演示后，这个感觉如何，而不是在演示时？”
- “用户在哪里等待，我们做了什么来解决它？”

运行行为而非视觉效果评审时查看 [参考资料/端到端体验.md](参考资料/端到端体验.md) — 日常使用和失败/支持阶段涵盖了如何走慢时刻、错误路径和大多数演示跳过离线状态。

### 4. 掌控整个体验

**核心概念：** 产品是每一个触点：发现、购买、开箱或首次运行、引导、日常使用、失败、支持、计费和离开。评审整个产品，而不是孤立的应用。

**为什么有效：** 客户将体验视为一个整体。苹果建立了开箱仪式、自己的商店和天才吧，因为一个伟大的设备如果销售不佳或支持粗鲁，就会在记忆中成为一个糟糕的产品。

**关键洞察：**
- 包装在苹果得到了设计实验室的待遇——第一印象是产品的一部分
- 首次运行是你的开箱：用户在零分钟看到的东西值得英雄屏幕的关怀
- 支持工单、发票和取消流程是产品表面——通常没有人设计它们
- 团队之间（营销 → 引导 → 产品 → 支持）的每一个交接点都是体验接缝显示的地方
- 绘制端到端旅程；最差的触点决定了感知质量

**评审应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 发布评审 | 将每个触点作为一次旅程进行审核 | 广告承诺与首次运行的现实相符 |
| 引导 | 将首次会话视为戏剧 | 首个60秒像关键演讲一样排练 |
| 生命周期 | 评审计费、支持和下线 | 取消只需一个屏幕，保持尊严 |

**评审提示：**
- “带我从未听说这个到推荐它——它在哪崩溃？”
- “谁设计了发票？错误电子邮件？取消流程？”
- “体验在销售后是否仍然保持承诺？”

**道德边界：** 掌控整个体验也意味着掌控失败——永远不要设计一个精致的开端和一个充满敌意的退出。

运行旅程映射时查看 [参考资料/端到端体验.md](参考资料/端到端体验.md) — 从发现到下线的7阶段触点图、最差触点规则和组织接缝如何产生未经设计表面。

### 5. 演示或不存在

**核心概念：** 评审可工作的工件，而不是规范或幻灯片。具体的演示揭示了文档隐藏的真相；决策是由决策者对真实事物做出反应而做出的。

**为什么有效：** 抽象让每个人想象不同的产品并达成一致。在真实尺寸和真实设备上的演示强制执行具体的反馈，早期暴露致命缺陷，并通过决策而不是委员会漂移来收敛。

**关键洞察：**
- 苹果的软件文化（Kocienda的“创意选择”）：构建一个演示，向决策者展示，获得直接反馈，迭代——这个循环是过程
- iPhone键盘是通过竞争性工作演示的决赛选出的，而不是需求文档
- 在目标设备上以目标数据规模进行评审——在投影仪上判断手机UI是谎言
- 首先原型化最危险的时刻；演示容易的80%证明不了什么
- “真正的艺术家会发布”：演示的目的是强迫决策，而不是延迟决策

**评审应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 设计评审 | 禁止仅幻灯片评审 | Figma原型或构建，而不是静态演示文稿 |
| 竞争性想法 | 运行一个演示决赛，选择一个 | 两个导航模型构建，一个裁决 |
| 利益相关者对齐 | 每周向决策者演示 | 30分钟演示取代3份状态文档 |

**评审提示：**
- “不要告诉我——给我看。在设备上。”
- “这两个演示中哪一个赢了？选一个；我们不会发布两者的折衷方案。”
- “哪个风险最大的假设？有哪个演示测试它？”

**道德边界：** 演示必须显示诚实状态——一个隐藏已知错误的演示是一个带有UI的谎言。

运行演示驱动评审时查看 [参考资料/演示文化.md](参考资料/演示文化.md) — 创意选择循环、如何运行演示决赛、决策者角色和诚实演示规则。

### 6. 品味和围栏后面

**核心概念：** 一个伟大的木匠不会在柜子的后面使用胶合板，即使没有人会看到它。投入到未看到的表面上的关怀——以及应用这些品味的人——才是质量真正是什么。

**为什么有效：** 用户会下意识地感觉到工艺：对齐的像素、连贯的文本、优雅的边缘情况加起来就是信任。削减角落的团队在“没有人看”的地方训练自己到处削减角落；卓越是由标准强制的习惯，而不是检查。

**关键洞察：**
- 原始Mac团队在机箱内部署了签名；乔布斯让工程师重新设计电路板布局，为了客户看不到的美
- “技术本身是不够的”——产品存在于技术和文科的交汇处
- 审核围栏后面的表面：空状态、错误文本、设置页面、加载屏幕、电子邮件
- “做一个质量尺”——A类玩家互相提升；容忍平庸会累积
- 品味是可训练的：研究伟大的产品，说明为什么它们很伟大，无情地应用标准

**评审应用：**

| 环境 | 应用 | 示例 |
|------|------|------|
| 细节审核 | 评审没有人演示的屏幕 | 404页面保持主页标准 |
| 文本评审 | 大声朗读每个字符串 | 错误消息听起来像人，具体 |
| 团队标准 | 批评最佳作品，而不是平均水平 | “这是你做过的最好的吗？” |

**评审提示：**
- “给我看产品中最丑陋的屏幕——那就是我们的真实质量标准。”
- “你会在这个里面签你的名字吗？”
- “我们在哪里使用了胶合板？”

查看 [参考资料/案例研究.md](参考资料/案例研究.md) 获取标准实际操作的示例——原始Mac电路板为未看到的美重新设计、iMac的有争议的削减，以及MobileMe和天线门失败评审以及每个评审向评审者教了什么。

### 7. 运行评审

**核心概念：** 结构化评审：像客户一样冷体验产品，命名它必须做的唯一一件事，根据原则1-6进行审核，然后交付一个二元裁决——极致完美，或未完成——以及具体的削减列表和修复列表。

**为什么有效：** 评审因模糊和礼貌而失败。固定的演示顺序、残酷的明确性和二元裁决防止“足够好”的发布，同时给团队一个精确的路径到10/10。产品根据自己的承诺进行评判——“这个产品应该做什么？然后为什么它不做那个？”

**关键洞察：**
- 在会议前冷体验产品——第一印象无法重跑
- 以承诺开头：陈述产品的承诺，然后只测试那个
- 反馈必须是具体和可操作的：“这令人困惑”评审失败——说是什么、在哪里、为什么，以及修复方向
- 结束二元：可发布或一个排名的修复列表；永远不要“稍微润色一下”
- 一个决策者拥有裁决；输入广泛，决策狭窄

始终以以下格式输出评审：

```
# 设计评审：[产品/功能]
**裁决：** 极致完美 / 未完成（分数X/10）
**唯一目标：** [这个必须做什么]
**是否兑现承诺？** [是/否——证据]
**削减列表：** [什么要删除]
**修复列表：** [排名，具体，带有修复方向]
**围栏后面：** [失败的未看到表面]
```

运行实际评审会话时查看 [参考资料/评审协议.md](参考资料/评审协议.md) — 定时的5步议程、修复项明确性测试、坦诚规则（对工作残酷，对人得体）、评审频率，以及如何为单人或异步评审调整协议。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|----------|------|
| 只评审美学 | 设计是它的工作方式；漂亮但笨拙仍然让用户失败 | 走流程、延迟和失败状态 |
| 通过添加来修复问题 | 每个增加都会分散注意力并滋生更多复杂性 | 首先削减；增加需要删除 |
| 一致裁决 | 委员会将想法平均成浆糊 | 一个决策者，广泛输入，狭窄决策 |
| 评审规范和幻灯片 | 抽象隐藏了致命缺陷；每个人想象不同的产品 | 要求在真实设备上运行工作演示 |
| “足够好”裁决 | 平庸会累积成品牌损害 | 二元：极致完美或未完成 |
| 跳过围栏后面 | 用户会感觉到胶合板；团队学会到处削减角落 | 审核空/错误/设置/电子邮件状态 |
| 恶搞残酷 | 恐惧阻止了演示和坦诚，扼杀了反馈循环 | 对工作残酷，对人得体 |

## 快速诊断

| 问题 | 如果没有 | 行动 |
|------|--------|------|
| 你能用一句话说出这个产品必须做的唯一一件事吗？ | 没有重点——所有事情都是优先事项 | 写下来；砍掉那些不服务于它的东西 |
| 新用户能在≤3步内达到核心价值吗？ | 复杂性无法克服 | 绘制价值步骤图；移除，不要重新排序 |
| 审查者是否像客户一样冷体验了它？ | 你审查的是团队的叙述，而不是产品 | 在会议前使用它，不要进行演示 |
| 真实设备上是否有可工作的演示？ | 你正在批准一个想象中的产品 | 推迟安排，直到有演示为止 |
| 这个周期是否移除了任何东西？ | 路线图正在增长，而不是聚焦 | 在每次审查中添加一个削减清单 |
| 错误、空和边缘状态是否与英雄屏幕质量匹配？ | 篱笆后面是胶合板 | 审计和修复看不见的表面 |
| 团队是否会自豪地每天使用它并签名？ | 标准是“可接受的”，而不是“疯狂地伟大” | 持续到自豪感成为现实为止做出二元判断 |

## 关于作者

史蒂夫·乔布斯（1955-2011）共同创立了苹果公司，并领导该公司创造了Mac、iPod、iPhone和iPad，通过以设计为导向的产品开发建立了世界上最有价值的公司。这项技能提炼自沃尔特·艾萨克森在其授权传记、肯·塞格尔的《疯狂地简单》和肯·科西enda的《创意选择》中记录的乔布斯的产品和设计审查实践和标准。
