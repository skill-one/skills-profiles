# iOS 人类界面指南设计技能

设计原生 iOS 界面的框架，使其感觉直观、一致，并与苹果的设计理念保持一致。基于苹果的人类界面指南，它是应用程序与 iPhone、iPad 和苹果生态系统无缝集成的权威资源。

## 核心原则

苹果的 iOS 设计理念建立在三个支柱之上：**清晰**（每个元素都清晰易读且目的明确）、**让位**（界面永远不会盖过它所呈现的内容），以及**深度**（层叠、过渡和逼真的动画传达层次结构和空间关系）。

**基础：** 最好的 iOS 应用程序是将这种理念内化于心，而不是机械地遵循 HIG 规则。原生组件、系统约定和平台一致性不是限制——它们是 iOS 用户信任并享受感觉属于那里的应用程序的原因。

## 评分

**目标：10/10。** 快速诊断（6 行）的每行满足 1 分，加上高达 4 分的原生习语：+1 全程使用语义颜色/文本样式（无硬编码值），+1 系统控件优于自定义重实现，+1 标准手势和有意义的触觉反馈，+1 SF Symbols 和正确的应用图标形状。范围：**9-10** = 原生、可访问、适应深色模式和动态类型、零外来模式；**5-6** = 可以工作但泄露 Android 习语或硬编码颜色/大小；**<=3** = 无法安全区域、触摸目标或 VoiceOver。始终说明分数以及达到 10/10 所需的具体改进。

## iOS 设计框架

### 1. 布局与安全区域

**核心概念：** iOS 设备具有特定的屏幕尺寸、安全区域填充和硬件入侵（刘海、动态岛、主指示器），每个布局都必须尊重这些区域。

**关键洞察：**
- 首先为最小屏幕设计（375pt 宽度，iPhone SE）
- 安全区域保护内容免受刘海、动态岛和主指示器的遮挡——永远不要将交互元素放置在它们下方
- 标准内容边距：屏幕边缘 16-20pt；间距增量：8 / 16 / 24pt
- 最小触摸目标和列表行高度：44pt

**产品应用：**

| 环境 | 布局模式 | 示例 |
|------|----------|------|
| **状态栏** | 20pt 经典，动态岛设备上 44-54pt | 时间、信号、电池区域 |
| **导航栏** | 44pt 标准行 + ~52pt 大标题 (~96pt 总计) | 返回按钮、标题、操作 |
| **内容区域** | 灵活、可滚动、尊重安全区域 | 主要应用内容 |
| **标签栏** | 49pt 高度，半透明并模糊 | 2-5 个主要目的地 |
| **主指示器** | 底部 34pt 填充 | 系统手势区域 |

**文本模式：**
- 使用 `VStack { }`，它默认尊重安全区域
- 仅用于背景和装饰使用 `.ignoresSafeArea()`，永远不要用于交互内容
- 在 iPhone SE 和 Pro Max 等多个尺寸上测试

在布局边框时，请参阅 [参考资料/导航.md](references/navigation.md)——精确的导航栏和标签栏尺寸、大标题行为和分屏视图规则。

### 2. 字体与动态类型

**核心概念：** iOS 使用 San Francisco (SF Pro) 字体，具有语义文本样式，可通过动态类型自动缩放以实现无障碍访问。语义样式提供一致的平台层次结构；动态类型允许用户以他们喜欢的尺寸阅读，而不会破坏布局。

**关键洞察：**
- 大标题：34pt 粗体；标题：17pt 中等；正文：17pt 常规；标题：12-13pt；次要文本：60% 不透明度
- 最小文本大小 11pt（标题/次要文本仅限）
- 行高至少为字体大小的 1.3 倍；最佳行长度移动设备上为 35-50 个字符
- 始终左对齐，非两端对齐文本

**产品应用：**

| 环境 | 字体模式 | 示例 |
|------|----------|------|
| **屏幕标题** | `.largeTitle` 或 `.title` 样式 | 大标题在滚动时折叠 |
| **正文内容** | `.body` 样式，17pt | 列表项、描述 |
| **次要信息** | `.subheadline` 或 `.footnote` | 时间戳、元数据 |
| **标签栏** | 10pt SF 文本 | 标签栏项标签 |
| **按钮** | `.body` 重量粗体 | 主要操作文本 |

**文本模式：**
- 使用 `.font(.title)`、`.font(.body)`、`.font(.caption)` 而不是硬编码尺寸；`@ScaledMetric` 用于自定义缩放间距
- 优先考虑重量和颜色变化，而不是极端大小差异来表示层次结构
- 在最大动态类型尺寸上测试所有布局

在将设计与精确规格匹配时，请参阅 [参考资料/字体.md](references/typography.md)——每个样式的十六进制值和深色模式文本颜色映射。

### 3. 颜色与深色模式

**核心概念：** iOS 提供了语义系统颜色，这些颜色可以在浅色和深色外观之间自动适应，同时保持对比度和层次结构。

**关键洞察：**
- 使用 `Color(.label)`、`Color(.secondaryLabel)`、`Color(.systemBackground)` 而不是硬编码颜色
- `Color(.systemBlue)` 是默认色调；`.systemRed` 用于破坏性操作；`.systemGreen` 用于成功
- 深色模式反转文本颜色并将背景变暗，同时保持相对层次结构；强调色需要较低亮度和高饱和度才能突出显示
- 在两种模式下保持 4.5:1 对比度；在开发过程中预览两种模式

**产品应用：**

| 环境 | 颜色模式 | 示例 |
|------|----------|------|
| **主要文本** | `Color(.label)` | 根据模式自动适应白/黑 |
| **次要文本** | `Color(.secondaryLabel)` | 两种模式下 60% 不透明度 |
| **背景** | `Color(.systemBackground)` / `.secondarySystemBackground` | 层叠深度 |
| **破坏性操作** | `Color(.systemRed)` | 删除按钮、警告 |
| **交互色调** | 应用强调色或 `.systemBlue` | 链接、切换状态 |

**文本模式：**
- 使用 `.preferredColorScheme(.light)` 和 `.dark` 在预览中测试两种模式并并排显示
- 在资源目录中定义自定义颜色，而不是在代码中定义，具有浅色/深色变体
- 假设背景是白色或黑色；启用增加对比度进行测试

在检查对比度时，请参阅 [参考资料/颜色深度.md](references/colors-depth.md)——完整的 WCAG 比率表（正常文本、大文本、UI 组件）和三级/分组背景标记。

### 4. 导航模式

**核心概念：** iOS 使用分层导航模型：标签栏用于主要目的地，导航堆栈用于分层钻取，模态用于专注任务。用户依赖这些模式来了解他们所在的位置以及如何返回；重新发明它们会使应用程序感觉不熟悉。

**关键洞察：**
- 标签栏：2-5 个主要目的地，始终可见，每个标签记住状态
- 导航栏：左上角的返回按钮、中心或大标题、右上角的操作；大标题在滚动时折叠
- 模态用于专注任务；通过向下滑动或显式关闭按钮关闭
- 永远不要使用汉堡菜单——iOS 用户期望标签栏
- 搜索栏可以位于导航栏下方，直到向下拉动才显示

**产品应用：**

| 环境 | 导航模式 | 示例 |
|------|----------|------|
| **应用结构** | 3-5 个标签的标签栏 | 主页、搜索、个人资料 |
| **内容层次结构** | 推送导航（钻取） | 列表 > 详情 > 编辑 |
| **专注任务** | 模态呈现 | 撰写、设置、过滤器 |
| **搜索** | 向下拉动搜索栏 | Spotlight 风格搜索 |
| **分屏视图** | iPad 侧边栏 + 详情 | 邮件、笔记在 iPad 上 |

**文本模式：**
- 返回按钮文本应该是前一个屏幕的标题，而不是“返回”
- 标签标签是单个单词（“主页”、“搜索”）；模态标题描述任务（“新消息”、“编辑个人资料”）
- 使用 `NavigationStack`（不是已弃用的 `NavigationView`）在 SwiftUI 中

### 5. 控件与输入

**核心概念：** iOS 提供了丰富的原生控件库（按钮、列表、切换开关、选择器、菜单、文本字段），用户已经了解并期望它们。

**为什么有效：** 原生控件带有内置的可访问性、触觉反馈和苹果已经解决的交互模式；自定义控件会创建摩擦并错过苹果已经解决的边缘情况。

**关键洞察：**
- 页面级操作位于导航栏（顶部）或操作栏（底部）
- 主要按钮填充主题颜色；次要按钮为轮廓或纯文本
- 破坏性操作使用红色并需要确认不可逆时
- 列表（表格视图）是 iOS 基本内容模式
- 根据输入匹配键盘类型（`.emailAddress`、`.phonePad`、`.URL`）；使用 `.textContentType` 进行自动填充

**产品应用：**

| 环境 | 控件模式 | 示例 |
|------|----------|------|
| **表单** | 原生文本字段并具有正确的键盘类型 | 电子邮件字段使用 @ 键盘 |
| **设置** | 分组列表，带有切换开关、展开 | iOS 设置样式 |
| **选择** | 选择器、分段控件或操作表 | 日期选择器、排序选项 |
| **破坏性操作** | 红色按钮 + 确认提示 | “删除账户”流程 |
| **上下文操作** | 长按菜单或滑动操作 | 行编辑、分享、删除 |

**文本模式：**
- 配对 `.keyboardType(.emailAddress)` 与 `.textContentType(.emailAddress)`
- 优先使用系统确认：`.alert()` 或 `.confirmationDialog()`；使用 `.swipeActions` 在列表行上
- 将主要操作按钮放置在屏幕底部，在拇指范围内

**道德边界：** 永远不要将广告伪装成原生控件，或使破坏性操作容易意外触发。

在构建特定控件时，请参阅 [参考资料/组件.md](references/components.md)——按钮样式、列表/部分变体、选择器与分段控件的选择，以及确认对话框的连接。在构建表单时，请参阅 [参考资料/键盘输入.md](references/keyboard-input.md)——键盘类型表、输入辅助视图和硬件键盘快捷键。

### 6. 可访问性

**核心概念：** iOS 拥有世界一流的辅助功能功能（VoiceOver、动态类型、切换控制、语音控制），并且每个应用程序都必须作为首要考虑事项支持它们。App Store 审核可能会拒绝无法使用辅助技术的应用程序。

**关键洞察：**
- 每个交互元素都需要 `.accessibilityLabel`；使用 `.accessibilityValue` 用于状态，`.accessibilityHint` 用于效果
- 使用 `.accessibilityElement(children: .combine)` 组合相关元素
- 支持所有动态类型尺寸；在最大设置上测试
- 尊重 44 x 44pt 触摸目标（第 1 节）和 4.5:1 对比度最低要求（第 3 节）作为可访问性要求，而不仅仅是视觉默认值
- 永远不要仅通过颜色传达含义

**产品应用：**

| 环境 | 可访问性模式 | 示例 |
|------|--------------|------|
| **图标** | `.accessibilityLabel("收藏")` | 心形图标带有标签 |
| **滑块** | `.accessibilityValue("\(Int(volume * 100))%")` | 音量控制 |
| **按钮** | `.accessibilityHint("分享此项目")` | 分享按钮 |
| **组** | `.accessibilityElement(children: .combine)` | 头像 + 名称行 |
| **图像** | 装饰性：`.accessibilityHidden(true)` | 背景图案 |

**文本模式：**
- 标签作为名词（“收藏”、“设置”）；提示作为动作（“与他人分享此项目”）
- 使用 VoiceOver 测试完整的应用程序流程
- 使用 Xcode 的可访问性检查器审计对比度和标签

在签出前，请参阅 [参考资料/可访问性.md](references/accessibility.md)——完整的 VoiceOver 实现模式和一个预发布可访问性清单，以运行应用程序进行测试。

### 7. 图标与图像

**核心概念：** iOS 使用 SF Symbols 作为标准图标系统，并要求应用程序图标在特定尺寸上，并自动应用签名超椭圆（“圆角矩形”）遮罩。SF Symbols 与 San Francisco 文本在视觉上对齐，并随动态类型缩放，因此它们在每重量和尺寸上都能保持对齐和清晰。

**关键洞察：**
- 使用 SF Symbols (`Image(systemName:)`) 用于所有标准图标——它们随文本缩放
- 应用程序图标：导出 1024x1024px 正方形；iOS 应用圆角矩形遮罩（圆角半径 = 边长 x 0.222，61% 平滑）
- iOS 18+ 支持浅色、深色和着色图标变体
- 避免在应用程序图标中使用文本；保持设计简单，具有可识别的轮廓

**产品应用：**

| 环境 | 图标模式 | 示例 |
|------|----------|------|
| **标签栏** | SF Symbols，选中时填充变体 | `house.fill`，`magnifyingglass` |
| **导航栏** | SF Symbols 在常规重量 | `gear`，`plus`，`ellipsis` |
| **列表附件** | SF Symbols，次要颜色 | `chevron.right`，`checkmark` |
| **应用程序图标** | 1024px 正方形，简单粗体设计 | 单个可识别的图符 |

**文本模式：**
- 使用 `Image(systemName: "heart.fill")`；应用 `.symbolRenderingMode(.hierarchical)` 用于多色深度
- 使用 `.imageScale(.large)` 或 `.font()` 相对于文本大小
- 在苹果的免费 SF Symbols 应用中浏览符号

**道德边界：** 永远不要使用暗示不存在功能或与 iOS 约定相矛盾的图标（垃圾桶 = 删除，不是存档）。

在导出应用程序图标时，请参阅 [参考资料/应用程序图标.md](references/app-icons.md)——上下文尺寸表、精确的圆角矩形数学和 iOS 18 浅色/深色/着色变体要求。

### 8. 手势与触觉反馈

**核心概念：** iOS 定义了标准手势（从边缘向右滑动返回、从列表下拉刷新、长按显示上下文菜单）和触觉反馈模式，必须尊重并永不覆盖。手势是肌肉记忆——重新定义返回滑动或下拉刷新会使用户感到困惑；触觉反馈提供无形的确认，表明操作已注册。

**关键洞察：**
- 永远不要覆盖：从边缘向右滑动（返回）、模态上向下滑动（关闭）、列表上下拉（刷新）
- 向左滑动在行上显示操作；长按显示上下文菜单；捏合缩放图像和地图
- 三种触觉类型：冲击（物理操作）、通知（结果）、选择（UI 变更）
- 触觉反馈应该是微妙且有意义的——永远不要持续或烦人

**产品应用：**

| 环境 | 手势/触觉反馈模式 | 示例 |
|------|-------------------|------|
| **导航** | 从左边缘向右滑动 | 系统返回手势 |
| **模态** | 向下滑动以关闭 | 表单关闭 |
| **列表** | 下拉刷新，滑动显示操作 | 刷新内容，删除行 |
| **确认** | 完成时 `.success` 触觉反馈 | 支付确认 |
| **选择** | 切换/选择时触觉反馈 | 选择器轮滚动 |

**文本模式：**
- `UIImpactFeedbackGenerator(style: .medium)` 用于物理交互；`UISelectionFeedbackGenerator()` 用于 UI 状态变化
- `UINotificationFeedbackGenerator()` 使用 `.success`、`.warning`、`.error` 用于结果
- 在触发触觉反馈之前调用 `.prepare()` 以最小化延迟

在连接手势或动画时，请参阅 [参考资料/手势.md](references/gestures.md)——完整保留手势表、触觉反馈生成器配方和标准动画时间/曲线。

## 常见错误

| 错误 | 为什么失败 | 修复 |
|------|-----------|------|
| **覆盖标准手势** | 破坏滑动返回、下拉刷新的手部记忆 | 按照系统手势的意图使用；自定义手势仅用于辅助操作 |
| **触摸目标小于44pt** | 错误点击、挫败感、无障碍访问失败 | 使所有交互元素至少为44 x 44pt |
| **忽略安全区域** | 内容被刘海、动态岛、主指示器遮挡 | 尊重安全区域内边距；`.ignoresSafeArea()` 仅用于背景 |
| **在iOS上使用Android模式** | 三角形菜单、顶部标签、FAB感觉不自然 | 使用标签栏、底部表单、原生iOS组件 |
| **跳过深色模式** | 布局损坏、深色模式用户无法阅读文本 | 使用语义颜色；测试两种外观 |
| **硬编码字体大小** | 破坏动态类型，排除低视力用户 | 全程使用语义文本样式（`.title`、`.body`、`.caption`） |
| **低对比度文本** | 失败WCAG AA；阳光中难以阅读 | 保持4.5:1最小值；使用“增加对比度”测试 |
| **不在真实设备上测试** | 模拟器遗漏性能、触觉反馈、安全区域边缘情况 | 在最小和最大尺寸的物理设备上测试 |

## 快速诊断

审计任何iOS界面设计：

| 问题 | 否 | 操作 |
|------|----|------|
| 布局是否在所有设备尺寸上尊重安全区域？ | 内容被硬件遮挡 | 在iPhone SE和Pro Max上审计；修复内边距 |
| 所有触摸目标是否至少为44 x 44pt？ | 错误点击和无障碍访问失败 | 增加点击区域；`.frame(minWidth: 44, minHeight: 44)` |
| 应用是否在深色模式下完全工作？ | 深色模式用户界面损坏/无法阅读 | 用语义系统颜色替换硬编码颜色 |
| 文本是否随动态类型正确缩放？ | 排除低视力用户 | 使用语义文本样式；在最大设置上测试 |
| 视觉障碍用户是否可以完成所有任务？ | 应用对盲人用户不可用 | 为所有交互元素添加标签、值、提示 |
| 导航模式是否为原生iOS？ | 应用感觉不自然 | 用标签栏替换三角形菜单；使用标准的推送/模态导航 |

## 超越核心UI

## 关于作者

**Apple Human Interface Guidelines** 由Apple的人机界面设计团队编写和维护，是科技领域最具影响力的设计组织之一。1984年与原始Macintosh一同首次发布，HIG确立了直接操作、一致性、用户控制等原则，定义了图形界面设计，并随着iPhone、iPad、Apple Watch和Vision Pro的发展而演变。它仍然免费提供在developer.apple.com上，作为Apple平台的必要参考。
