# 创建企业

将一个原始想法转化为一个你可以在每个方面进行辩护的业务：它为谁服务，它做什么工作，它为什么与众不同，它为什么能赢，它的成本是多少，以及为什么任何人会付费。这段旅程按顺序运行十个阶段，随着证据的积累会循环回溯。它是交互式的——代理在每次决策之前都会询问——并且可以重新开始：所有状态都存储在 `docs/` 中，因此你可以在会话之间停止和重新开始。顺序很重要：在构建之前考虑需求，在扩展之前考虑战略，在产品之前考虑价格。

## 核心原则

**在消耗你的跑道之前赚取你的证据：在构建之前考虑需求，在扩展之前考虑战略，在产品之前考虑价格。** 你可以在一周内对你的产品感到错误，或者在一年内对你的业务感到错误——选择一周。这项技能按顺序排列阶段，在每次决策点提出问题，并将你的决定记录在 `docs/` 中。构成技能承载着方法——调用它们而不是即兴创作它们的框架。

## 运营规则

1. **首先恢复。** 在做任何事之前，阅读 `docs/CREATE-BUSINESS-PLAN.md` 和旅程地图中的每个产出物。如果存在跟踪器，请用 3-5 行总结旅程状态并询问进入哪个阶段。当用户确认入口点时完成。带有跟踪器的旅程是恢复的，而不是重新开始的。
2. **仅在第一次运行时进行信息收集。** 没有跟踪器：运行下面的信息收集，然后创建 `docs/CREATE-BUSINESS-PLAN.md`，并将每个阶段的状态设置为 `pending | in-progress | awaiting-evidence | done | deferred: reason | skipped: reason`。当跟踪器存在并且用户确认了阶段计划时完成。
3. **阶段入口。** 宣布：阶段做什么，它强迫的决策，它产生的产出物，粗略的工作量。提供继续 / 跳过 / 延迟——标记为 GATE 的阶段可以延迟，但不能跳过。在继续时将阶段标记为 `in-progress`。当用户选择时完成。
4. **技能调用和回退。** 加载阶段的技能并使用它：每个阶段的调用行通过别名命名技能——使用该技能来运行阶段。如果它不可用，提供：`npx skills add wondelai/skills/<slug> --global`。如果用户拒绝，从它的简要信息运行阶段——最小的可行方法。说明你处于哪种模式。
5. **阶段内的决策。** 询问“与用户一起决策”下的每个问题——提供具体的选项和你的建议。在跟踪器的关键决策中记录选择。无声做出的决策是缺陷。
6. **阶段退出。** 在写入之前，展示草稿产出物内容以供批准。批准后：写入或扩展 docs/ 文件，更新跟踪器（状态、关键决策、下一步行动）。当文件写入并且阶段行显示 `done` 时完成。
7. **产出物纪律。** 写在阅读之前；如果文件不存在，则创建它，否则扩展——添加或更新你的部分，保留其他人的部分。文件在 `docs/` 中是大写的。每个建议都作为复选框或带有所有者和优先级的表格行出现。在创建 docs/ 文件时查看 [references/artifact-templates.md](references/artifact-templates.md)——从完整骨架（所有部分标题）创建它，然后填写你的阶段名称的部分。
8. **代理准备和处理；只有人类与客户交谈。** 起草访谈指南和评分访谈记录，然后暂停状态 `awaiting-evidence`，直到用户返回笔记。永远不要模拟客户——角色扮演的访谈证实了你希望为真的事情。

## 信息收集

在创建跟踪器之前询问这些问题（跳过任何已回答的）：

1. 原始想法是什么，用一到两句话概括？ （为阶段 1 中的工作重构提供种子）
2. 你想象中的客户是谁，他们今天如何解决这个问题？ （为竞争替代方案提供信息；紧密的细分市场可以加速阶段 7 和 10）
3. 你有什么客户访问权限——列表、社区、温暖的介绍？ （为阶段 2-4 开门；没有访问权限，只有人类访谈阶段会停滞）
4. 已经存在哪些证据——过去的访谈、等待名单、销售、原型？ （让我们快速跟踪或跳过已经完成的发现）
5. 这是 B2B 还是 B2C——如果是 B2B，是销售导向还是自助服务？ 它是市场产品还是网络产品？ （路由可选的预测收入和冷启动问题）
6. 你的跑道和截止日期是什么？ （设置阶段深度，以及是否要延迟战略阶段）
7. 是否已经构建了任何产品？ （如果是，这可能不是正确的旅程——路由到增长业务或改进业务）

阶段跳过启发式方法：当 CUSTOMER.md 中存在一个经过验证的工作说明，其中包含三个维度时，跳过阶段 1；当已经测试过 5 个以上目标用户的工作原型时，跳过阶段 3；对于明显差异化的利基市场，延迟阶段 6，直到内核设置；直到阶段 2 返回真实承诺，延迟阶段 5-10——在没有验证的需求上进行战略。然后从模板创建 `docs/CREATE-BUSINESS-PLAN.md`，将每个阶段状态化，并确认计划。当 `docs/CREATE-BUSINESS-PLAN.md` 存在，每个阶段都状态化，并且用户确认了计划时完成。

## 阶段

### 阶段 1 — 找到真实的工作（需要完成的任务）

**目的：** 将原始想法重新定义为客户试图完成的进展，以便即使第一个解决方案死亡，业务也能生存。

**简要信息（回退）：** 工作是在情境中的进展，而不是目标或任务——将其写为 `当 [情况]，我想 [动机]，以便 [结果]`，与解决方案无关。每个工作都有功能、情感和社会维度；差异化的产品通常存在于最后两个。真实的竞争包括替代方案和非消费——命名你必须击败的竞争对手。

**调用：** 使用 `需要完成的任务` 技能，并提供原始想法和从信息收集中得到的客户猜测。要求一个 When/I-want-to/so-I-can 工作说明，所有三个维度，以及包括非消费的完整竞争替代方案集。

**与用户一起决策：** 哪个工作说明是真实的，以及你首先必须击败哪个竞争对手。建议最紧密的说明，但仍然命名一个情感或社会维度。

**产出物：** 创建 docs/CUSTOMER.md，其中包含 `## 工作说明`、`## 工作维度` 和 `## 竞争替代方案`。更新跟踪器。

**完成时：** CUSTOMER.md 包含一个与解决方案无关的工作说明、所有三个维度以及带有要击败的竞争对手的竞争集。

### 阶段 2 — 通过真实对话验证工作（母测试）— GATE

**目的：** 用事实代替意见——证明阶段 1 中的工作是真实的、痛苦的，并且值得付费解决。阶段 5-10 在此返回继续裁决之前保持锁定。

**简要信息（回退）：** 三条规则——谈论他们的生活而不是你的想法；询问过去的具体情况而不是假设；说得少（他们说话 80%）。赞美不是数据；只有承诺（时间、声誉、金钱）才计算在内。一个好问题可能会摧毁想象中的业务。

**调用：** 使用 `母测试` 技能，并提供来自 docs/CUSTOMER.md 的工作说明和竞争替代方案。要求 (a) 一个 10-12 个问题的访谈指南，遵守三条规则，然后稍后 (b) 访谈记录评分，标记引导问题和僵尸引导。将指南交给用户并暂停状态 `awaiting-evidence`；在 `## 访谈证据` 的 `### 访谈指南` 子部分下记录批准的指南，以便它在暂停期间保留。

**与用户一起决策（返回时）：** 证据是否证实了工作？继续（3 个以上具体承诺）、修改工作说明（循环到阶段 1）或停止（没有痛苦发现——一个廉价的胜利）。

**产出物：** 扩展 docs/CUSTOMER.md：添加 `## 访谈证据`（日期 | 谁 | 事实 | 承诺）和 `## 验证裁决`，记录决策和推理。更新跟踪器。

**完成时：** CUSTOMER.md 包含 5 个以上证据行，裁决已记录，用户选择了继续 / 修改 / 停止，并且在继续的情况下——阶段 5-10 被解锁。

### 阶段 3 — 在五天内测试风险最大的假设（设计冲刺）

**目的：** 在投入数月之前，用五个真实客户反应在一周内证明概念中最危险的部分。

**简要信息（回退）：** 五天——映射、草图、决定、原型、测试。选择一个目标时刻（最危险的步骤）；单独草图（不要小组头脑风暴）；一个决策者打破僵局；构建一个外壳，而不是工作代码；用五个目标客户测试。在周五，闭嘴让他们挣扎——解释原型会使测试无效。

**调用：** 使用 `设计冲刺` 技能，并提供经过验证的工作和最危险的开放性问题。要求周一的地图，其中包含冲刺问题和目标时刻，以及周五的五幕访谈脚本，该脚本不解释原型。将招聘简介交给用户并暂停 `awaiting-evidence`，等待真实会话；在 docs/EXPERIMENTS.md 中的冲刺卡片下记录批准的脚本和简介，以便它们在暂停期间保留。

**与用户一起决策：** 本周要测试哪个单一假设，以及谁是决策者。返回时：概念是否生存——构建、修复或离开（一个一周的胜利）？

**产出物：** 创建 docs/EXPERIMENTS.md，其中包含 `## 实验卡片`（EXP-001，类型冲刺，预承诺指标，决策规则，结果和裁决）和 `## 实验待办事项列表`。更新跟踪器。

**完成时：** EXPERIMENTS.md 包含带有来自五个会话的记录裁决的冲刺卡片，并且用户选择了构建 / 修复 / 离开。

### 阶段 4 — 运行循环并选择最小的 MVP（精简创业）

**目的：** 将发现转化为一个经过验证学习的可重复引擎，并交付最小的 MVP，它测试了最大的信仰跳跃。

**简要信息（回退）：** 向后计划构建-衡量-学习：决定要学习什么，然后是证明它的指标，然后是最小构建。MVP 类型——烟雾测试、 concierge、Wizard of Oz——每个测试不同的信仰跳跃假设；首先测试最大的。衡量可操作的指标，而不是虚荣指标。在运行之前设置转向或坚持标准。选择一个增长引擎：粘性、病毒或付费。

**调用：** 使用 `精简创业` 技能，并提供功能愿望清单和生存概念。要求最大的信仰跳跃假设、一个带有构建-衡量-学习实验卡片的 MVP 类型，以及预先设定的转向/坚持阈值。

**与用户一起决策：** 哪个 MVP 类型、哪个单一增长引擎首先优化，以及预先设定的转向/坚持阈值。建议粘性引擎（留存率高于流失率）而不是付费获取。

**产出物：** 创建 docs/PRODUCT.md，其中包含 `## 视野` 和 `## MVP 定义`；扩展 docs/EXPERIMENTS.md，添加新的卡片及其决策规则。更新跟踪器。

**完成时：** PRODUCT.md 定义了 MVP 和它排除的内容，EXPERIMENTS.md 包含带有预先设定的阈值和所选引擎的卡片，并且用户批准了 MVP 范围。

### 阶段 5 — 将雄心转化为战略内核（好战略-坏战略）

**目的：** 用一个真正的战略代替一个目标列表——一个诊断、指导政策以及连贯的行动。

**简要信息（回退）：** 目标命名雄心；战略解释在障碍面前如何获胜。内核：一个命名唯一关键挑战的诊断；一个指导政策是一个真正的选择，有输家（如果竞争对手可以粘贴它，它是一个陈词滥调）；连贯的行动，每个行动都有一个所有者和日期。通过四个标志检测坏战略——废话、回避挑战、目标作为战略、狗食式目标列表。集中力量在一个转向点上。

**调用：** 使用 `好战略-坏战略` 技能，并提供经过验证的需求证据和任何一页计划。要求一个四标志审计，然后是一个内核——一个段落诊断、一个排除整个行动类别的指导政策、三个连贯的行动，带有所有者——以及一个明确的不列表。

**与用户一起决策：** 唯一的关键挑战是什么（诊断），以及指导政策明确拒绝做什么？建议集中在一个转向点上，而不是分散精力。

**产出物：** 创建 docs/STRATEGY.md，其中包含 `## 诊断`、`## 指导政策`、`## 连贯的行动` 和 `## 不列表`。更新跟踪器。

**完成时：** STRATEGY.md 命名一个关键挑战、一个带有输家的指导政策、带有所有者的连贯行动，以及一个明确的不列表。

### 阶段 6 — 找到无争议的空间（蓝海战略）

**目的：** 选择通过创造无争议的空间来获胜，而不是在与其他所有人相同因素上进行正面竞争。

**简要信息（回退）：** 价值创新同时追求差异化和低成本。ERRC 网格——消除、减少、提高、创造——提高了买家的价值，同时降低了成本。绘制战略画布：一个不同的提供物偏离了行业曲线。蓝海将非客户（即将到来、拒绝、未探索的），而不是竞争对手的客户——找到移除的共同障碍。不要消除客户真正重视的因素（信任、安全、准确性）。

**调用：** 使用 `蓝海战略` 技能，并提供来自 CUSTOMER.md 的竞争替代方案和来自 STRATEGY.md 的内核。要求当前因素的策略画布和一个 ERRC 网格，用于在资源限制内的价值创新移动。

**与用户一起决策：** 哪些因素要消除 / 减少 / 提高 / 创建，以及首先转换哪个非客户的层级。确认没有信任、安全或准确性因素被削减。

**产出物：** 扩展 docs/STRATEGY.md：添加 `## 策略画布 & ERRC 网格`。更新跟踪器。

**完成时：** STRATEGY.md 包含一个填满的 ERRC 网格和一个显示发散曲线的策略画布，以及选择了目标非客户层级。

**工件：** 创建 docs/POSITIONING.md 文件，包含 `## 竞争替代品`、`## 独特属性 → 价值主题`、`## 最佳匹配客户`、`## 市场类别` 和 `## 一句话介绍`。更新追踪器。

**完成标准：** POSITIONING.md 包含五步画布和一句话介绍，让局外人能在 30 秒内理解。

### 第 8 步 — 打造让人感觉拒绝很愚蠢的提议（百万元级提议）

**目的：** 通过一个无法进行价格比较的“大满贯提议”，将理解转化为购买。

**简述（备用）：** 提议是第一杠杆。价值 = (梦想结果 × 感知可能性) / (时间延迟 × 努力程度) — 最大化分子，最小化分母。组装一个“大满贯提议”：核心提议、命名附加福利（每个都能消除一个反对意见，每个都有可辩护的价值）、逆转风险的保证、道德稀缺性。用 MAGIC 命名。保持每个价值都诚实，每个保证都值得信赖。

**触发：** 使用 `百万元级提议` 技巧，结合 POSITIONING.md 中的定位和最佳匹配客户。要求基于价值方程式构建“大满贯提议”，三个命名附加福利每个消除一个反对意见、一个保证、道德稀缺性，以及一个 MAGIC 名称。

**与用户决策：** 选择锚定的梦想结果，以及附加福利必须消除的反对意见。确认每个美元价值和每个稀缺性声明都是真实可信的 — 替换任何需要虚构证据的技巧。

**工件：** 创建 docs/OFFER.md 文件，包含 `## 提议堆栈`（核心 · 附加福利 · 保证 · 稀缺性 · 名称）。更新追踪器。

**完成标准：** OFFER.md 包含一个完整的提议堆栈，有诚实价值、真实保证和名称 — 没有虚构证据。

### 第 9 步 — 根据验证的支付意愿定价（创新变现）

**目的：** 在概念阶段测试支付意愿，围绕价格设计产品。

**简述（备用）：** 客户会揭示一个范围：询问什么感觉可以接受、昂贵、不可接受；只信任顶端购买概率。避免四个失败 — 功能冲击、微创新（无反对意见的 100% 胜率）、隐藏的宝石、不死产品。按价值和支付意愿细分，永远不要按人口统计。领导者/填充者/杀手；首先设计中间层；将杀手功能拉入附加福利。在价格水平之前选择价格指标。

**触发：** 使用 `创新变现` 技巧，结合 OFFER.md 中的提议和 CUSTOMER.md 中的细分。要求一个支付意愿访谈脚本（可接受 / 昂贵 / 不可接受）、领导者/填充者/杀手分类、好-更好-最好层级，以及一个价格指标。将 WTP 脚本交给用户，暂停 `awaiting-evidence` 等待真实电话；在 docs/OFFER.md 中的 `## 支付意愿证据` 子部分下记录批准的脚本，以便在暂停期间保留。

**与用户决策：** 选择基于什么指标收费（每个座位 / 每单位价值）和好-更好-最好层级的边界。建议一个跟踪交付价值的指标，以便收入复合。

**工件：** 扩展 docs/OFFER.md：添加 `## 支付意愿证据`、`## 领导者 / 填充者 / 杀手功能`、`## 层级（好 / 更好 / 最好）` 和 `## 价格指标`。更新追踪器。

**完成标准：** OFFER.md 包含 WTP 证据、功能分类、中间层首先设计好的层级，以及价格指标在水平之前选择。

### 第 10 步 — 选择你将首先主导的滩头阵地（跨越鸿沟）

**目的：** 选择一个狭窄的细分市场进行主导，并组装整个产品，使其从愿景家到实用主义者跨越鸿沟。

**简述（备用）：** 鸿沟位于愿景家早期采用者和实用主义早期多数之间 — 什么赢得一个会排斥另一个。不要对每个人都做所有事：选择一个狭窄的滩头阵地，有紧迫的昂贵痛点、可触及的渠道、客户之间互相交流、足够小以拥有，但又足够大以重要。组装整个产品（集成、入职、支持、合作伙伴）。参考是货币；将定位从“革命性”转变为“经过验证”。

**触发：** 使用 `跨越鸿沟` 技巧，结合 POSITIONING.md 和 STRATEGY.md。要求对候选细分市场在痛点、可触及性、口碑和可主导性上进行评分，然后绘制实用主义者购买前需要的整个产品需求。

**与用户决策：** 选择第一个要拥有的单一滩头阵地细分市场。建议评分最高的细分市场，足够小以主导；抵制同时追逐多个。

**工件：** 扩展 docs/STRATEGY.md：添加 `## 滩头阵地`（目标细分市场、评分理由）和 `## 整个产品清单`（每个差距有负责人和优先级）。更新追踪器。

**完成标准：** STRATEGY.md 指定一个滩头阵地并附有评分，整个产品清单列出每个差距的负责人和优先级。

## 常见错误

| 错误 | 修复 |
|---|---|
| 在验证前构建 | 用最小的 MVP 购买证据 — 烟雾测试或管家 — 在编写真实代码之前；首先运行阶段 1-4（精益创业）。 |
| 在发现期间提案 | 保持访谈关于他们的生活和过去行为；如果可能的话，将想法放在最后，如果可能的话（妈妈测试）。 |
| 将赞美和注册误认为是验证 | 追求承诺 — 定金、预购、安排试点 — 并在 CUSTOMER.md 访谈证据中记录它们。 |
| 搞混目标与策略 | 首先写出对一个关键挑战的诊断；对照四个标志进行审核（好策略-坏策略）。 |
| 为所有人定位 | 直到定义得令人不适地狭窄，然后更狭窄（显然很棒）。 |
| 基于成本或竞争对手定价 | 从验证的支付意愿范围定价，并在水平之前选择价格指标（创新变现）。 |
