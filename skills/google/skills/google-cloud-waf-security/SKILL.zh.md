# Google Cloud 架构设计良好框架技能 - 安全支柱

## 概述

Google Cloud 架构设计良好框架的安全支柱为通过将安全整合到云工作负载架构的每一层来构建强大的安全态势提供了设计原则和最佳实践。它专注于维护数据和系统的机密性和完整性，同时确保合规性和隐私。它提供了一种结构化的风险管理、威胁防御和身份控制方法，使您能够安全且大规模地运行云工作负载。

## 工作流

当此技能被激活时，请按照以下步骤评估和改进指定 Google Cloud 工作负载的安全态势：

1.  **理解背景**：从 **工作负载评估问题** 列表中提出有针对性的问题，收集有关用户当前架构、安全要求和限制的信息。
2.  **分析和识别差距**：根据 **核心原则** 和 **验证清单** 评估工作负载，以识别安全漏洞、缺失的控制措施或偏离最佳实践的情况。
3.  **提出建议**：根据 Google Cloud 架构设计良好框架提供可操作的、优先级的指导。根据 **相关 Google Cloud 产品** 推荐具体产品来解决已识别的差距。
4.  **解释建议**：将所有建议与相应的 **核心原则** 对齐，并说明每项建议提供的益处。
5.  **迭代和改进**：帮助用户根据其特定需求和限制调整建议。

## 核心原则

架构设计良好框架的安全支柱中的建议与以下核心原则一致：

-  **以设计的方式实施安全**：从应用程序和基础设施的初始设计阶段开始，整合云安全和网络安全考虑因素。Google Cloud 提供架构蓝图和建议，以帮助您应用此原则。基础文档：https://docs.cloud.google.com/architecture/framework/security/implement-security-by-design.md.txt

-  **实施零信任**：采用“永不信任，始终验证”的方法，其中基于持续验证信任来授予对资源的访问权限。Google Cloud 通过 Chrome 企业版高级版、身份感知代理 (IAP) 和 IAM 推荐器等产品支持此原则。基础文档：https://docs.cloud.google.com/architecture/framework/security/implement-zero-trust.md.txt

-  **实施左移安全**：在软件开发生命周期早期实施安全控制。在系统更改之前避免安全缺陷。在系统更改提交后尽早、快速且可靠地检测和修复安全错误。Google Cloud 通过 Cloud Build、二进制授权和 Artifact Registry 等产品支持此原则。基础文档：https://docs.cloud.google.com/architecture/framework/security/implement-shift-left-security.md.txt

-  **实施主动网络防御**：通过实施威胁情报等强大的基础措施来采取主动的安全方法。这种方法有助于您为更有效的威胁检测和响应建立基础。Google Cloud 的分层安全控制方法与此原则一致。Google Cloud 通过 Security Command Center、Google 威胁情报和 Google SecOps 等产品支持此原则。基础文档：https://docs.cloud.google.com/architecture/framework/security/implement-preemptive-cyber-defense.md.txt

-  **安全且负责任地使用人工智能**：以负责任和安全的方式开发和部署人工智能系统。此原则的建议与架构设计良好框架中的人工智能和机器学习视角以及 Google 的安全人工智能框架 (SAIF) 中的指导一致。基础文档：https://docs.cloud.google.com/architecture/framework/security/use-ai-securely-and-responsibly.md.txt

-  **使用人工智能进行安全**：使用人工智能功能通过 Security 中的 Gemini 和整体平台安全能力改进您现有的安全系统和流程。将人工智能用作一种工具，以增加纠正性工作的自动化并确保安全卫生，使其他系统更安全。Google Cloud 通过 Google 威胁情报和 Google SecOps 等产品支持此原则。基础文档：https://docs.cloud.google.com/architecture/framework/security/use-ai-for-security.md.txt

-  **满足监管、合规和隐私需求**：遵守特定于行业的法规、合规标准和隐私要求。Google Cloud 通过 Assured Workloads、组织策略服务和我们的合规资源中心等产品帮助您履行这些义务。基础文档：https://docs.cloud.google.com/architecture/framework/security/meet-regulatory-compliance-and-privacy-needs.md.txt

- **Google Cloud 上的共同责任和共同命运**：了解 Google 负责云的安全，而您负责云中工作负载的安全。了解这种责任划分如何根据工作负载类型而变化。了解 Google 为确保云的安全所做的工作。采取适当的行动以确保您的云中工作负载是安全的。
  基础文档：https://docs.cloud.google.com/architecture/framework/security/shared-responsibility-shared-fate.md.txt

## 相关 Google Cloud 产品

以下是一些与安全相关的 Google Cloud 产品和功能的示例：

-  **身份和访问管理**

  - **Cloud Identity**：管理用户生命周期、身份验证和身份联合。
  - **身份和访问管理 (IAM)**：Google Cloud 资源的细粒度访问控制。
  - **身份感知代理 (IAP)**：无需 VPN 的应用程序安全访问。
  - **Chrome 企业版高级版**：端点安全和上下文感知访问。
  - **IAM 推荐器**：提供策略智能。

-  **网络安全**

  - **Google Cloud Armor**：DDoS 防护和 Web 应用程序防火墙 (WAF)。
  - **VPC 服务边界**：围绕敏感数据定义安全边界以防止数据泄露。
  - **Cloud 下一代防火墙 (NGFW)**：网络流量的高级威胁防护。
  - **共享 VPC**：跨项目集中式网络管理。
  - **Cloud Interconnect 和 IPsec VPN**：安全、私有的连接。
  - **Private Service Connect**：提供对托管服务的私有访问

-  **数据安全**

  - **Cloud 密钥管理服务 (KMS)**：管理加密密钥。
  - **敏感数据保护（原 Cloud DLP）**：发现和删除敏感数据。
  - **机密计算**：加密使用中的数据（内存）。

-  **安全运营 (SecOps)**

  - **Google SecOps（Chronicle）**：威胁检测和安全分析。
  - **安全中心 (SCC)**：集中式漏洞和威胁管理。
  - **Cloud Logging 和 Cloud Monitoring**：系统活动的可见性。
  - **BigQuery**：存储导出日志以进行分析。

-  **自动化和供应链**

  - **Cloud Build**：安全的 CI/CD 管道。
  - **Artifact Analysis**：容器镜像的漏洞扫描。
  - **二进制授权**：部署时策略执行。
  - **Assured open source software**：使用安全的 OSS 软件包。

## 验证清单

使用以下清单评估架构与安全建议的一致性：

-  **以设计的方式实施安全**：

  - 系统组件是否根据其安全功能和加固进行选择？
  - 是否在网络、主机和应用层实施了纵深防御？
  - 是否使用安全的库和应用程序框架来防止常见漏洞？
  - 是否使用行业标准进行风险评估？

-  **零信任**：

  - 是否使用 Cloud Identity 作为集中式身份提供者来管理用户生命周期和联合？
  - 是否基于用户身份和上下文（设备、位置）执行访问控制？
  - 是否使用私有连接方法（Cloud Interconnect、VPN）用于内部流量？
  - 是否在所有项目中禁用默认网络？
  - 是否围绕敏感数据建立了 VPC 服务边界？

-  **左移安全**：

  - 是否使用基础设施即代码（例如 Terraform）进行基础设施配置？
  - 是否将自动安全扫描集成到 CI/CD 管道中？
  - 是否有扫描和修补依赖项漏洞的过程？
  - 是否使用二进制授权来确保仅部署受信任的镜像？

-  **主动网络防御**：

- 威胁情报是否已集成到安全运营中？
  - 是否为所有关键资源启用了安全日志记录并进行集中管理？
  - 是否已为常见安全威胁配置了自动响应？
  - 是否通过定期测试或红队演练来验证防御措施？

- **AI安全与治理**：

  - AI流程是否已防范篡改和数据污染？
  - 是否在适当情况下使用差分隐私或数据屏蔽来处理训练数据？
  - 是否使用Vertex可解释AI和公平性指标进行模型治理？
