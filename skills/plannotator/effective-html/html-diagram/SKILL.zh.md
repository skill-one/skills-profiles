# HTML图表

构建最小的可视化模型，使其比纯文字更容易理解。匹配符号和视觉语言与用户的项目和主题。不要强迫每个主题都进入相同的SVG框和箭头。

## 选择合适的模型

确定读者应该回答的问题，然后选择形式：

- 用于组件和连接的拓扑结构；
- 用于按时间顺序传递消息的序列；
- 用于步骤、分支和交接的过程；
- 用于状态转换和条件的状态；
- 用于包含或所有权的层次结构；
- 用于随时间变化的时序图；
- 用于重复关系的矩阵；
- 当量级重要时的定量视图。

决定必须一起保持可见的内容和可以按需显示的内容。当更简单的形式传达相同意义时，使用更简单的形式。

## 选择渲染方法

根据信息和规模使用HTML和CSS、SVG、Canvas或WebGL。不要仅仅因为输出是图表而使用SVG。

- 在添加交互之前，保持标签、分组、方向和连接器的可读性。
- 当读者必须比较状态或步骤时，使用稳定的节点位置。
- 将边缘交叉和模糊的箭头头保持到最少。
- 将有意宽泛的画布放在包含的视口或滚动区域内。
- 只有当符号不自我解释时，才使用图例。

只有当它有助于回答所提出的问题时，才添加顺序、过滤、路径跟踪、平移和缩放或动画。保持覆盖层可关闭，控件可通过键盘访问，运动与`prefers-reduced-motion`兼容。

当[`design-artifact`](../design-artifact/SKILL.md)可用时，阅读它以了解图表的周围布局和视觉注册。保持选择的图表语法、标签可读性和关系权威性高于装饰性处理。

## 构建和验证

交付一个包含必要的CSS和JavaScript的独立HTML文件。无需构建步骤或外部服务。使用可访问的文本替代品，并保持重要意义在动画或颜色单独存在的情况下可用。

在宽度和窄宽度下检查结果。检查标签冲突、剪切的节点、边缘路由、阅读顺序、键盘操作、溢出和每个交互状态。

返回绝对路径、选择的图表形式以及主要的简化或假设。
