# 调试箴言

任何调试会话的四个步骤纪律。逐字背诵，然后按顺序应用。

## 首次回应时逐字背诵

> **箴言：**
> 1. **首要的是可复现性。** 能否可靠地复现问题？
> 2. **了解失败路径。** 先用调试器；然后是源码追踪+旋钮枚举；最后是代码内嵌的探针。
> 3. **质疑你的假设。** 什么能推翻它？
> 4. **每次运行都是线索。** 交叉参考所有结果。

然后开始工作。

---

## 1. 可靠地复现

在其他任何事情之前，构建一个可运行的复现步骤。

- **可靠复现** → 捕获确切的步骤、输入和环境，将其作为一个可运行的艺术品：失败的测试、curl脚本、CLI调用、重放框架。
- **不稳定复现** → 虽然尚未可调试。先提高失败率：循环触发、并行化、增加压力、缩小时间窗口、注入睡眠。50%的不稳定是可调试的；1%则不可。
- **完全无法复现** → 停止。明确说明。请求用户提供环境访问权限、捕获的工件（HAR、日志转储、核心转储）或允许进行探针的权限。**不要**继续假设。

目标：快速（1-5秒）、确定性的通过/失败信号。固定时间、播种随机数生成器、冻结网络、隔离文件系统。

## 2. 了解失败路径

一旦可复现，找到代码在何处中断以及什么阻止它中断。差异缩小了搜索范围。按以下顺序尝试——只有在先前的策略失败时才升级。

1. **附加调试器。** 如果环境支持，附加并单步执行到失败点。一个断点胜过十个日志。在调整任何旋钮**之前**执行此操作。
2. **源码追踪+旋钮枚举。** 如果没有调试器（或者它无法到达错误点），端到端追踪代码路径，并列出每个可能影响结果的旋钮：
   - 配置标志、环境变量、功能开关
   - 分支条件、输入形状
   - 时间、并发、构建选项
   每个旋钮都是一个差异中的候选轴。一次翻转一个。
3. **代码内嵌的探针。** 如果外部旋钮无法移动失败，就进入内部：在怀疑的失败点添加`printf`/日志语句，转储相关内部状态。给每个探针一个唯一的前缀（例如`[DBG-a4f2]`），以便清理时只需一个grep。让追踪显示现实与你的模型有何不同。

## 3. 推翻假设

当候选根本原因出现时，在测试它**之前**仔细审查。

- 它是否真的能解释端到端的症状？逐步推演。
- 最简单的**证明**是什么？最干净的**推翻**是什么？
- 先运行**推翻**。如果假设存活，它是真实的。如果它死亡，你避免了追逐一个幻影。
- 生成3-5个排序的假设，而不是一个。单假设思维会锚定在第一个看似合理的想法。

## 4. 每次运行都是线索

维护一个会话中每次实验的**账本**。每条记录：改变了什么、发生了什么、排除了什么。

- 当出现新的假设时，回顾账本。它是否适用于**每个**先前的观察，而不仅仅是最近的？
- 如果任何过去的运行与之矛盾，假设是错误的或不完整的——改进或丢弃。
- 在不确定时，设计一个**单一实验**，其结果能使其确定。运行那个，而不是在相邻运行上反复试验。
- 每次运行后更新账本。它是你跨会话的记忆。

---

## 操作规则

- 每个调试会话中**一次**背诵箴言块，在首次回应中。会话中途**不要**重新背诵。
- **逐字**背诵。**不要**释义、缩短或跳过背诵的行。
- 如果用户说“跳过箴言”→ 跳过背诵但仍然在无声中应用四个步骤。
- 按顺序应用四个步骤：
  - 在#1满足（可靠复现存在）之前**不要**提出修复方案。
  - 在#2缩小失败路径之前**不要**开始测试假设。
  - 在#3尝试推翻假设之前**不要**提交假设。
  - 在#4确认它与所有先前的线索一致之前**不要**宣布假设正确。
- 如果你发现自己没有可靠复现就提出修复方案，停止并返回步骤1。
- 箴言是一个你**在会话中携带的约束**——而不是给用户回传的建议。
