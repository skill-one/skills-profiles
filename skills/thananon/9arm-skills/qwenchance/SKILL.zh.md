# 保持专注

多步骤的长期工作会以三种方式失败：**循环重复**、**过度思考**和**上下文信息不足**。在每一步开始前，请运行以下清单。当触发条件出现时，执行相应的操作——不要犹豫不决。

## 每一步前——执行此清单

| 检查项 | 触发条件 | 应该做 |
|---|---|---|
| **循环重复？** | 你即将重复某个操作（见下文信号） | 打破循环——选择以下一项修正 |
| **过度思考？** | 你已经进行了约1000字的分析但未采取行动 | 停止。根据当前最佳决策行动，或向用户提出一个问题 |
| **上下文信息不足？** | 出现低上下文提醒，**或** 有2个以上的预算信号 | 完成本步骤，然后移交 |

如果没有触发条件，则执行该步骤。

## 1. 循环——检测并打破

一个步骤是循环，如果满足以下任意一项：

- 你重新阅读了本会话中已经阅读过的文件（且文件**未**在此会话中更改）。
- 你使用相同的参数重新运行了命令/工具，期望得到相同的结果。
- 你回到了已经尝试并放弃的假设。
- 你“从头重新考虑”但没有新的证据。
- 最后两个步骤没有获得新信息。

**重新阅读你刚刚编辑的文件**不构成循环——那是验证。

当循环触发时，**停止**并执行以下一项：

1. 用一句话陈述障碍，并向用户提出一个具体问题。
2. 写下已知与未知的内容，然后采取**不同**于上次的行为。
3. 在同一个子问题上循环2次以上？将其标记为暂时未解决；继续或移交。

**不要重复失败的操作**，期望得到不同的结果。

**重试上限**：永远不要第三次运行相同的失败命令。在约3次尝试（即使尝试了不同变体）后仍无法让某项功能（命令、测试运行器、导入）正常工作——**停止**并询问用户；不要继续尝试更多变体。

**不要盲目编辑**——这是最常见的循环来源。在编辑前，阅读足够的内容以确认更改正确。每次编辑后，在执行下一步前验证它（查看差异/运行它/运行测试）。一个编辑→一个检查。

## 2. 思考——保持边界

每一步的推理**限制在约1000字**。超过这个字数，你就是在犹豫不决而不是行动。

- 决定→行动→观察。不要重新推导你已经做出的决定。
- 在约1000字内无法决定？该任务定义不明确——**向用户提出一个尖锐的问题**。
- 不要向自己重述整个问题。参考你的结论；不要重新构建。

## 3. 上下文预算——计数信号，不要估算

**权威性信号**：关于低上下文/接近自动压缩的`<system-reminder>`。→ **立即移交**（第4节）。不要开始新工作。

**其他情况，统计当前有多少项为真：**

- [ ] 20个以上助手转化为任务。
- [ ] 阅读了5个以上文件，或任何一个大文件/日志/转储。
- [ ] 长工具输出你不断回滚滚动条。
- [ ] 还有3个以上的计划步骤未完成。

**统计为真的方框数量，然后将数量映射到行动：**

- **数量为0或1 → 正常继续**工作。
- **数量为2、3或4 → 移交**——完成当前步骤，然后转到第4节。

先计数，再决定——不要凭感觉判断。数量越高，表示*更多*的上下文压力，而不是更少。处于最后步骤或“几乎完成”**不会**降低数量或取消移交。

在执行任何**昂贵**步骤（大读取、新子任务、长生成）前，问：“**有足够空间完成这个并移交给下一个会话吗？**”如果计数指示需要移交，完成当前原子单元，然后移交——不要开始下一个。

## 4. 清晰移交

当上下文紧张或用户要求时：

1. **首先交付持久化成果**——保存文件、提交、写入结果。不丢失任何内容。
2. **调用`handoff`技能**来压缩对话。不要手写移交内容。
3. 明确告知用户：“上下文正在变得紧张——现在移交；开始一个新会话(`/clear`)。”
