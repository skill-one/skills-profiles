# DCF模型构建器

## 概述

该技能遵循投资银行标准，创建机构级DCF模型用于股票估值。每次分析都会生成一个详细的Excel模型（DCF表格底部包含敏感性分析）。

## 工具

- 默认使用用户提供的所有信息和MCP服务器上的数据源信息。

## 关键约束 - 首先阅读这些内容

这些约束适用于所有DCF模型构建过程。开始前请查阅：

**环境：Office JS与Python/openpyxl：**
- **若在Excel中运行（Office插件/Office JS环境）：** 直接使用Office JS——不要使用Python/openpyxl。通过`range.formulas = [["=D19*(1+$B$8)"]]`写入公式。无需单独的重新计算步骤；Excel原生计算。使用`range.format.*`进行样式设置。相同的公式覆盖硬编码规则适用：设置`.formulas`，不要为衍生单元格设置`.values`。
- **若生成独立的.xlsx文件（无活动Excel会话）：** 使用Python/openpyxl按以下描述操作，交付前运行`recalc.py`。
- 本技能使用openpyxl示例——在Office JS环境中将其转换为API调用，但所有原则（公式字符串、单元格注释、部分检查点、敏感性表格循环）都完全相同。

**⚠️ Office JS合并单元格陷阱：** 在构建带合并单元格的部分标题时，不要调用`.merge()`然后对合并范围设置`.values`——Office JS仍报告原始范围维度并抛出`InvalidArgument: 输入数组的行数或列数与范围的大小或维度不匹配`。应单独将值写入左上角单元格，然后合并并格式化整个范围：

```js
// 错误——会抛出InvalidArgument:
const hdr = ws.getRange("A7:H7");
hdr.merge();
hdr.values = [["市场数据与关键输入"]];  // 1×1数组与1×8范围不匹配→失败

// 正确——先在单个单元格写入值，然后合并+格式化范围：
ws.getRange("A7").values = [["市场数据与关键输入"]];
const hdr = ws.getRange("A7:H7");
hdr.merge();
hdr.format.fill.color = "#1F4E79";
hdr.format.font.bold = true;
hdr.format.font.color = "#FFFFFF";
```

DCF中的每个合并部分标题（市场数据、情景块、现金流预测、终值、估值摘要、敏感性表格）都适用此规则。

**公式覆盖硬编码（不可协商）：**
- 每个预测、利润率、折现因子、现值和敏感性单元格必须是动态Excel公式——绝不能是Python计算后写入的数值
- 使用openpyxl时：`ws["D20"] = "=D19*(1+$B$8)"`正确；`ws["D20"] = calculated_revenue`错误
- 允许的唯一硬编码数字是： (1) 历史输入原始值， (2) 假设驱动因素（增长率、WACC输入、终值g）， (3) 当前市场数据（股价、债务余额）
- 若发现自己用Python计算结果并写入——停止。模型必须在用户改变假设时具有灵活性。

**与用户分步验证（不要端到端构建）：**
- 数据检索后 → 展示用户原始输入块（收入、利润率、股份、净债务）并确认后再预测
- 收入预测后 → 展示预测的营收和增长率，确认后再构建利润率构建
- FCF构建后 → 展示完整FCF时间表，确认逻辑后再计算WACC
- WACC后 → 展示计算和输入，确认后再折现
- 终值+现值后 → 展示股权桥梁（EV→股权价值→每股），确认后再敏感性表格
- 每个阶段捕获错误——敏感性表格构建后发现错误的利润率假设意味着需要重建下游所有内容

**敏感性表格：**
- **使用奇数行和列**（标准：5×5，有时7×7）——这保证有真正的中心单元格
- **中心单元格=基准情况。** 构建轴值，使中间行标题和中间列标题正好等于模型的实际假设（例如，若基准WACC=9.0%，中间行是9.0%；若终值g=3.0%，中间列是3.0%）。因此中心单元格的输出必须等于模型的实际隐含股价——这是检查表格构建是否正确的合理性检查。
- **突出显示中心单元格** 使用中蓝色填充(`#BDD7EE`) + 粗体字体，使其立即可见哪个单元格是基准情况。
- 用完整DCF重新计算公式填充所有单元格（通常3个表格×25个单元格=75个）
- 使用openpyxl循环（或Office JS循环）编程写入公式
- 无占位符文本，无线性近似，无手动步骤
- 每个单元格必须为该假设组合重新计算完整DCF

**单元格注释：**
- 创建硬编码值时添加单元格注释
- 格式："来源：[系统/文档]，[日期]，[参考]，[适用URL]"
- 每个蓝色输入在进入下一部分前必须有注释
- 不要推迟到最后或写入"TODO: 添加来源"

**模型布局规划：**
- 在编写任何公式前定义所有部分行位置
- 先编写所有标题和标签
- 第二步编写所有部分分隔线和空白行
- 然后使用锁定行位置编写公式
- 创建后立即测试公式

**公式重新计算：**
- 交付前运行`python recalc.py model.xlsx 30`
- 修复所有错误直到状态为"success"
- 零公式错误要求（#REF!，#DIV/0!，#VALUE!等）

**情景块：**
- 为熊/基准/牛案例创建独立块
- 在每个块内水平显示假设（跨预测年份）
- 使用IF公式：`=IF($B$6=1,[熊案例单元格],IF($B$6=2,[基准案例单元格],[牛案例单元格]))`
- 验证公式引用正确的情景块单元格

## DCF流程工作流

### 第1步：数据检索和验证

从MCP服务器、用户提供的数据和网页获取数据。

**数据源优先级：**
1. **MCP服务器**（若配置）- 来自Daloopa等提供者的结构化财务数据
2. **用户提供数据** - 来自其研究的财务历史数据
3. **网页搜索/获取** - 当需要时获取当前价格、贝塔、债务和现金

**验证清单：**
- 验证净债务与净现金（对估值至关重要）
- 确认稀释股份（检查近期回购/发行）
- 验证历史利润率与商业模式一致
- 收入增长率与行业基准交叉检查
- 验证税率合理（通常21-28%）

### 第2步：历史分析（3-5年）

分析和记录：
- **收入增长趋势**：计算CAGR，识别驱动因素
- **利润率进展**：跟踪毛利率、EBIT利润率、FCF利润率
- **资本强度**：D&A和CapEx占收入的百分比
- **营运资本效率**：NWC变化占收入增长的百分比
- **回报指标**：ROIC、ROE趋势

创建显示以下内容的摘要表格：
```
近期历史指标：
收入：$X百万
收入增长率：X% CAGR
毛利率：X%
EBIT利润率：X%
D&A占收入的百分比：X%
CapEx占收入的百分比：X%
FCF利润率：X%
```

### 第3步：构建收入预测

**方法：**
1. 从最新实际收入（近期历史或最新财年）开始
2. 对每个预测年份应用增长率
3. 显示金额和计算的增长率%

**增长率框架：**
- 第1-2年：较高增长率反映近期可见性
- 第3-4年：逐渐放缓至行业平均水平
- 第5年+：接近终值增长率

**公式结构：**
- 收入(第N年) = 收入(第N-1年) × (1 + 增长率)
- 增长率%(第N年) = 收入(第N年) / 收入(第N-1年) - 1

**三种情景方法：**
```
熊案例：保守增长（例如，8-12%）
基准案例：最可能情景（例如，12-16%）
牛案例：乐观增长（例如，16-20%）
```

### 第4步：运营费用建模

**固定/可变成本分析：**

运营费用应模拟真实的运营杠杆：
- **销售与营销**：通常占收入的15-40%，取决于商业模式
- **研究与开发**：通常占技术公司收入的10-30%
- **一般与行政**：通常占收入的8-15%，显示随公司规模增长的杠杆

**关键原则：**
- 所有百分比基于收入，不是毛利润
- 模拟运营杠杆：百分比随收入增长而下降
- 维持S&M、R&D、G&A的单独项目
- 计算 EBIT = 毛利润 - 总运营费用

**利润率扩张框架：**
```
当前状态→目标状态（第5年）
毛利率：X% → Y%（基于规模、效率进行说明）
EBIT利润率：X% → Y%（收入增长+运营费用杠杆的结果）
```

### 第5步：自由现金流计算

**按正确顺序构建FCF：**

```
EBIT
(-) 税费 (EBIT × 税率)
= 税后营业利润 (NOPAT)
(+) D&A (非现金费用，占收入的百分比)
(-) CapEx (占收入的百分比，通常4-8%)
(-) Δ NWC (营运资本变化)
= 杠杆自由现金流
```

**营运资本建模：**
- 计算为收入变化的百分比（Δ收入）
- 典型范围：-2%至+2%的收入变化
- 负数=现金来源（营运资本释放）
- 正数=现金使用（营运资本构建）

**维护与增长CapEx：**
- 维护CapEx：维持当前运营（约收入2-3%）
- 增长CapEx：支持扩张（额外收入2-5%）
- 总CapEx应与公司增长战略一致

### 第6步：资本成本（WACC）研究

**CAPM方法用于股权成本：**

```
股权成本 = 无风险利率 + 贝塔 × 股权风险溢价

其中：
- 无风险利率 = 当前10年期国债收益率
- 贝塔 = 5年月度股票贝塔与市场指数
- 股权风险溢价 = 5.0-6.0%（市场标准）
```

**债务成本计算：**

```
税后债务成本 = 税前债务成本 × (1 - 税率)

从以下来源确定税前债务成本：
- 信用评级（若可用）
- 公司债券当前收益率
- 财务报表中的利息费用 / 总债务
```

**资本结构权重：**

```
市场价值股权 = 当前股价 × 股份总数
净债务 = 总债务 - 现金及等价物
企业价值 = 市值 + 净债务

股权权重 = 市值 / 企业价值
债务权重 = 净债务 / 企业价值

WACC = (股权成本 × 股权权重) + (税后债务成本 × 债务权重)
```

**特殊情况：**
- **净现金状况**：若现金>债务，净债务为负
  - 债务权重可能为负
  - WACC计算相应调整
- **无债务**：WACC = 股权成本

**典型WACC范围：**
- 大型稳定公司：7-9%
- 增长公司：9-12%
- 高增长/高风险：12-15%

### 第7步：折现率应用（5-10年预测）

**年中惯例：**
- 现金流假设发生在年中
- 折现期：0.5，1.5，2.5，3.5，4.5，等
- 折现因子 = 1 / (1 + WACC)^期数

**现值计算：**
```
对每个预测年份：
PV FCF = 杠杆FCF × 折现因子

示例（第1年）：
FCF = $1,000
WACC = 10%
期数 = 0.5
折现因子 = 1 / (1.10)^0.5 = 0.9535
PV = $1,000 × 0.9535 = $954
```

**预测期选择：**
- **5年**：大多数分析的标准
- **7-10年**：高增长公司有更长的运行时间
- **3年**：成熟、稳定的企业

### 第8步：终值计算

**永续增长法（首选）：**

```
终值FCF = 最终年FCF × (1 + 终值增长率)
终值 = 终值FCF / (WACC - 终值增长率)

关键约束：终值增长率 < WACC（否则价值无限）
```

**终值增长率选择：**
- 保守：2.0-2.5%（GDP增长率）
- 适度：2.5-3.5%
- 激进：3.5-5.0%（仅限市场领导者）

**不要超过**：无风险利率或长期GDP增长率

**退出乘数法（替代方法）：**
```
终值 = 最终年EBITDA × 退出乘数

其中退出乘数来自：
- 行业可比交易乘数
- 先例交易乘数
- 典型范围：8-15倍EBITDA
```

**终值现值：**
```
终值现值 = 终值 / (1 + WACC)^最终期数

其中最终期数考虑时间：
5年模型与年中惯例：期数 = 4.5
```

**终值合理性检查：**
- 应代表企业价值的50-70%
- 若>75%，模型可能过度依赖终值假设
- 若<40%，检查终值假设是否过于保守

### 第9步：企业价值到股权价值桥梁

**估值摘要结构：**

```
(+) 预测FCF现值总和 = $X百万
(+) 终值现值 = $Y百万
= 企业价值 = $Z百万

(-) 净债务[或负净现金时+净现金] = $A百万
= 股权价值 = $B百万

÷ 稀释股份总数 = C百万股
= 隐含每股价格 = $XX.XX

当前股价 = $YY.YY
隐含回报 = (隐含价格 / 当前价格) - 1 = XX%
```

**关键调整：**
- **净债务 = 总债务 - 现金及等价物**
  - 若为正：从EV中减去（减少股权价值）
  - 若为负（净现金）：加到EV（增加股权价值）
- **使用稀释股份**：包括期权、RSU、可转换证券
- **其他调整**（若适用）：
  - 少数股东权益
  - 养老金负债
  - 营运租赁义务

**估值输出格式：**
```csv
估值组件,金额 ($M)
预测FCF现值总和,X.X
终值现值,Y.Y
企业价值,Z.Z
(-) 净债务,A.A
股权价值,B.B
,,
股份总数 (M),C.C
隐含每股价格,$XX.XX
当前股价,$YY.YY
隐含上行/下行,+XX%
```

### 第10步：敏感性分析

在DCF表格底部构建**三个敏感性表格**，显示估值如何随不同假设变化：

1. **WACC与终值增长率** - 显示企业价值对折现率和永续增长率的敏感性
2. **收入增长率与EBIT利润率** - 显示营收增长和运营杠杆的影响
3. **贝塔与无风险利率** - 显示股权成本组件的敏感性

**实现**：这些是简单的二维网格（不是Excel的"数据表"功能），每个单元格包含针对该特定假设组合的完整DCF重新计算公式。见关键约束部分关于使用openpyxl编程填充所有75个单元格的详细要求。

### 情景块选择模式 - 遵循此方法

**假设按每个情景的独立块组织：**

**关键结构——每个部分标题三行：**

```csv
熊案例假设（部分标题，跨单元格合并）
假设,FY1,FY2,FY3,FY4,FY5
收入增长率 (%),12%,10%,9%,8%,7%
EBIT利润率 (%),45%,44%,43%,42%,41%

基准案例假设（部分标题，跨单元格合并）
假设,FY1,FY2,FY3,FY4,FY5
收入增长率 (%),16%,14%,12%,10%,9%
EBIT利润率 (%),48%,49%,50%,51%,52%

牛案例假设（部分标题，跨单元格合并）
假设,FY1,FY2,FY3,FY4,FY5
收入增长率 (%),20%,18%,15%,13%,11%
EBIT利润率 (%),50%,51%,52%,53%,54%
```

**每个情景块必须有列标题行**显示预测年份（FY2025E，FY2026E等），立即位于部分标题下方。没有这一行，用户无法知道哪个假设值对应哪一年。

**如何引用假设——创建汇总列：**
1. 案例选择单元格（例如，B6）包含1=熊，2=基准，或3=牛
2. 创建汇总列，使用INDEX或OFFSET公式从正确的情景块中提取
3. 预测公式引用汇总列（干净的单元格引用）
4. 每个情景块包含跨预测年份的完整DCF假设集

**推荐汇总列模式（使用INDEX）：**
`=INDEX(B10:D10, 1, $B$6)`

**不是这个——在整个模型中散布IF语句：**
`=IF($B$6=1,[熊案例块单元格],IF($B$6=2,[基准案例块单元格],[牛案例块单元格]))`

汇总列方法集中逻辑，使模型更易于审计。

### 正确的收入预测模式

**创建一个使用INDEX公式的汇总列，然后在预测中引用它：**

**步骤 1 - FY1增长的汇总列：**
`=INDEX([熊市FY1增长]:[牛市FY1增长], 1, $B$6)`

**步骤 2 - 收入预测引用汇总列：**
`收入第一年: =D29*(1+$E$10)`

其中：
- D29 = 前一年收入
- $E$10 = FY1增长的汇总列单元格（包含INDEX公式）
- $B$6 = 案例选择器（1=熊市，2=基准，3=牛市）

**这种方法比在每个预测公式中嵌入IF语句更清晰**，并且更容易审计所使用的情景假设。

### 正确的自由现金流公式模式

**使用汇总列和INDEX公式，然后在自由现金流计算中引用它们：**

**汇总列方法：**
```csv
项目,公式,引用
折旧与摊销,=E29*$E$21,$E$21 = 汇总列（折旧与摊销百分比）
资本支出,=E29*$E$22,$E$22 = 汇总列（资本支出）
净营运资本变化,=(E29-D29)*$E$23,$E$23 = 汇总列（净营运资本）
税前自由现金流,=E57+E58-E60-E62,E57=税前营业利润 E58=折旧与摊销 E60=资本支出 E62=净营运资本变化
```

**每个汇总列单元格包含一个INDEX公式**，根据案例选择器从适当情景块中提取数据。这保持了预测公式的清晰和可审计性。

在编写公式之前，请确认情景块行位置并设置汇总列。

### 正确的敏感性分析表实现

**重要提示**：这些不是Excel的"数据表"功能。这些是使用openpyxl编写的简单网格。是的，这意味着总计约75个公式（3个表格 × 每个表格25个单元格），但这很直接且是必需的。

**使用公式进行程序化填充：**

每个敏感性分析表必须使用公式完全填充，以重新计算每种假设组合下的隐含股价。**不要使用Excel的"数据表"功能**（它需要手动干预且无法通过openpyxl自动化）。

**实现方法 - 具体示例：**

**表格结构 — 5×5网格（奇数维度，基准案例居中）：**

如果模型的基准WACC为9.0%，基准终值增长率为3.0%，则围绕这些值对称构建轴：

```csv
WACC与终值增长率,  2.0%,  2.5%,  3.0%,  3.5%,  4.0%
              8.0%,       [fml], [fml], [fml], [fml], [fml]
              8.5%,       [fml], [fml], [fml], [fml], [fml]
              9.0%,       [fml], [fml], [★  ], [fml], [fml]   ← 中间行 = 基准WACC
              9.5%,       [fml], [fml], [fml], [fml], [fml]
             10.0%,       [fml], [fml], [fml], [fml], [fml]
                                   ↑
                          中间列 = 基准终值增长率
```

**★ = 中心单元格。** 其公式输出必须等于模型的实际隐含股价（来自估值摘要）。将中等蓝色填充（`#BDD7EE`）和粗体字应用于此单元格，以便在视觉上锚定基准案例。

**轴值的规则：** `axis_values = [base - 2*step, base - step, base, base + step, base + 2*step]` — 围绕基准对称，奇数个值保证有一个中心。

**公式模式 - 单元格B88（WACC=8.0%，终值增长率=2.0%）：**

B88单元格中的公式应使用以下值重新计算隐含股价：
- 从行标题获取WACC：`$A88`（8.0%）
- 从列标题获取终值增长率：`B$87`（2.0%）

**推荐方法：** 引用主DCF计算，但替换这些值。

**示例公式结构：**
`=([使用$A88作为折现率的PV FCF总和] + [使用B$87作为增长率且使用$A88作为WACC的终值] - [净债务]) / [股数]`

**关键 - 为5x5网格中的每个单元格（每个表格25个单元格，总计75个单元格）编写公式。** 使用openpyxl以循环方式程序化地编写这些公式。不要跳过这一步或留下占位符文本。

**Python实现模式：**
```python
# Python伪代码用于填充敏感性分析表
for row_idx, wacc_value in enumerate(wacc_range):
    for col_idx, term_growth_value in enumerate(term_growth_range):
        # 构建使用wacc_value和term_growth_value的公式
        formula = f"=<使用{wacc_value}和{term_growth_value}的DCF重新计算>"
        ws.cell(row=start_row+row_idx, column=start_col+col_idx).value = formula
```

**敏感性分析表必须在模型打开时立即工作，用户无需执行任何手动步骤。**

<常见错误>

本节包含构建DCF模型时应避免的所有错误模式。

### 错误：简化的敏感性分析表近似或占位符文本

**不要使用线性近似：**

```
// 错误 - 线性近似
B97: =B88*(1+(0.096-0.116))    // 假设线性关系

// 错误 - 除法快捷方式
B105: =B88/(1+(E48-0.07))      // 不会重新计算完整DCF
```

**不要留下占位符文本：**
```
// 错误 - 占位符注释
"注意：使用Excel数据表功能（数据 → 假设分析 → 数据表）来填充敏感性分析表。”

// 错误 - 空单元格
[因为“这很复杂”而留下空单元格]
```

**不要混淆术语：**
- ❌ "敏感性分析表需要Excel的"数据表"功能"（不 - 那是特定的Excel工具，我们无法使用）
- ✅ "敏感性分析表是每个单元格都有公式的简单网格"（是 - 这是我们构建的）

**为什么这些捷径是错误的：**
- 线性近似公式实际上不会重新计算DCF - 它们只是应用简单的数学调整
- 关系不是线性的，因此结果将不准确
- 占位符文本需要用户手动干预
- 模型在交付时无法立即使用
- 不专业或无法满足客户需求
- 空单元格 = 不完整的交付

**要拒绝的常见理由：**
"编写75+公式感觉很复杂，所以我将留个注释让用户手动完成它。"

**现实：** 当你使用Python中的循环和openpyxl时，编写75个公式很简单。每个公式都遵循相同的模式 - 只需替换行/列值。这是交付内容的一部分。

**相反：** 使用公式填充每个敏感性单元格，以重新计算该特定假设组合的完整DCF

### 错误：缺少单元格注释

**不要这样做：**
- 创建所有硬编码输入而不加注释
- 认为"稍后添加"
- 写"TODO: 添加来源"
- 留下蓝色输入而无文档

**为什么这是错误的：**
- 无法验证数据来源
- 未满足xlsx技能要求
- 无法审计
- 浪费时间修复

**相反：** 在创建每个硬编码值时添加单元格注释

### 错误：公式行引用错误

**症状：**
FCF部分引用了错误的假设行：
`折旧与摊销:  =E29*$E$34    // 应为$E$21，但引用了错误行`
`资本支出: =E29*$E$41   // 应为$E$22，但行号偏移`

**为什么会发生这种情况：**
1. 先编写公式
2. 然后插入标题
3. 所有行引用都偏移
4. 现在公式指向了错误的单元格 → #REF!错误

**相反：** 首先锁定行布局，然后编写公式

### 错误：每个假设跨情景单行

**不要这样构建假设：**
```csv
假设,熊市,基准,牛市
收入增长FY1,10%,13%,16%
收入增长FY2,9%,12%,15%
```
这种垂直布局使得难以查看每个情景中各年份的假设进展。

**为什么这是错误的：**
- 难以查看每个情景中各年份的假设进展
- 更难比较跨整个预测期情景假设
- 审查情景逻辑不太直观

**相反：**
- 为每个情景（熊市、基准、牛市）创建单独的块
- 在每个块内，按预测年份水平显示假设
- 这使得每个情景的假设更容易作为一个整体进行审查

### 错误：没有边框

**不要交付没有边框的模型：**
- 没有部分分隔
- 所有单元格混在一起
- 难以阅读和不专业

**为什么这是错误的：**
- 无法满足客户需求
- 难以导航
- 看起来业余

**相反：** 为所有主要部分添加边框

### 错误：错误的字体颜色或没有字体颜色区分

**不要这样做：**
- 所有文本都是黑色
- 只使用填充颜色（不改变字体颜色）
- 混淆蓝色和黑色单元格

**为什么这是错误的：**
- 无法区分输入和公式
- 审计变得不可能
- 违反xlsx技能要求

**相反：** 所有硬编码输入使用蓝色文本，所有公式使用黑色文本，链接使用绿色

### 错误：基于毛利润的运营费用

**不要这样做：**
`销售与管理费用: =E33*0.15    // E33 = 毛利润（错误）`

**为什么这是错误的：**
- 运营费用随收入增长，而不是毛利润
- 产生不现实的利润率进展
- 不是企业实际如何运作的方式

**相反：**
`销售与管理费用: =E29*0.15    // E29 = 收入（正确）`

### 顶级5个错误总结

1. **公式行引用错误** → 在编写公式之前定义所有行位置
2. **缺少单元格注释** → 在创建单元格时添加注释，而不是在最后
3. **简化的敏感性分析表** → 使用完整DCF重新计算公式填充所有单元格，而不是近似值
4. **情景块引用错误** → 确保IF公式从正确的熊市/基准/牛市块中提取数据
5. **没有边框** → 添加专业的部分边框以获得客户需求的外观

此外，请注意以下错误：

### WACC计算错误
- 资本结构中混合了账面价值和市场价值
- 使用权益贝塔而不是资产/无杠杆贝塔错误
- 错误地将税率应用于债务成本
- 错误的风险无风险利率（必须使用当前的10年期国债）
- 未调整净债务与净现金头寸

### 增长假设缺陷
- 终值 > WACC（产生无限价值）
- 预测增长率与历史表现不一致
- 忽略行业增长限制
- 收入增长与单位经济性不一致
- 利润率扩张没有运营理由

### 终值错误
- 使用错误的方法（永续年金与退出倍数）
- 终值 >80%的企业价值（表明过度依赖）
- 终值利润率与稳定状态假设不一致
- 终值折现期错误

### 现金流预测错误
- 运营费用基于毛利润而不是收入
- D&A/资本支出百分比与业务模型不一致
- 工作资本变化未正确计算
- 年份间税率不一致
- NOPAT计算错误

这些是最常见的错误。在开始任何DCF构建之前，请重读本节。

## Excel文件创建

**此技能使用`xlsx`技能进行所有电子表格操作。** xlsx技能提供：

- 数字格式约定
- 通过`recalc.py`脚本自动公式重新计算
- 全面错误检查和验证

此技能创建的所有Excel文件必须遵循xlsx技能要求，包括零公式错误和正确的重新计算。

## 质量评分标准

每个DCF模型必须最大化以下方面：
1. **基于历史表现的现实收入和利润率假设**
2. **适当的资本成本计算**，使用正确的CAPM方法
3. **全面的敏感性分析**，显示估值范围
4. **清晰的终值计算**，具有支持性理由
5. **专业的模型结构**，支持情景分析
6. **透明的文档**，说明所有关键假设

### 最小输入要求
1. **公司标识符**：股票代码或公司名称
2. **增长假设**：预测期收入增长率（或"使用一致预期"）
3. **可选参数**：
   - 预测期（默认：5年）

   - 特定WACC输入（如果未使用CAPM）

## Excel模型结构

### 工作表架构

创建**两个工作表**：

1. **DCF** - 主要估值模型，底部有敏感性分析
2. **WACC** - 资本成本计算

**关键**：敏感性分析表位于DCF工作表的底部（不在单独的工作表上）。这使所有估值输出保持在一起。

### 公式重新计算（强制要求）

创建或修改Excel模型后，**使用`recalc.py`脚本重新计算所有公式**：

```bash
python recalc.py [path_to_excel_file] [timeout_seconds]
```

示例：
```bash
python recalc.py AAPL_DCF_Model_2025-10-12.xlsx 30
```

该脚本将：
- 使用LibreOffice重新计算所有工作表中的公式
- 扫描所有单元格以查找Excel错误（#REF!, #DIV/0!, #VALUE!, #NAME?, #NULL!, #NUM!, #N/A）
- 返回包含错误位置和计数的详细JSON

**预期输出格式：**
```json
{
  "status": "success",           // 或 "errors_found"
  "total_errors": 0,              // 错误总数
  "total_formulas": 42,           // 文件中的公式数量
  "error_summary": {}             // 仅当发现错误时存在
}
```

**如果发现错误**，输出将包括详细信息：
```json
{
  "status": "errors_found",
  "total_errors": 2,
  "total_formulas": 42,
  "error_summary": {
    "#REF!": {
      "count": 2,
      "locations": ["DCF!B25", "DCF!C25"]
    }
  }
}
```

**修复所有错误**并重新运行recalc.py，直到状态为"success"，然后才能交付模型。

### 格式标准

**重要提示**：请遵循 xlsx 技能的公式构建规则和数字格式约定。DCF 技能添加了特定的视觉呈现标准。

**配色方案 - 两层结构**：

**第一层：字体颜色（xlsx 技能强制要求）**
- **蓝色文本（RGB：0,0,255）**：所有硬编码输入（股票价格、股份数量、历史数据、假设）
- **黑色文本（RGB：0,0,0）**：所有公式和计算
- **绿色文本（RGB：0,128,0）**：指向其他工作表的链接（WACC 工作表引用）

**第二层：填充颜色 — 专业蓝灰色调（默认，除非用户指定其他颜色）**
- **保持简洁** — 仅使用蓝色和灰色进行填充。不要引入绿色、黄色、橙色或多种强调色。颜色过多的模型看起来不专业。
- **默认填充调色板**：
  - **部分标题**：深蓝色（RGB：31,78,121 / `#1F4E79`）背景，白色粗体文本
  - **子标题/列标题**：浅蓝色（RGB：217,225,242 / `#D9E1F2`）背景，黑色粗体文本
  - **输入单元格**：浅灰色（RGB：242,242,242 / `#F2F2F2`）背景，蓝色字体 — 或者如果想要最大程度的极简主义，则使用白色背景和蓝色字体
  - **计算单元格**：白色背景，黑色字体
  - **输出/汇总行**（每股价值、EV 等.）：中等蓝色（RGB：189,215,238 / `#BDD7EE`）背景，黑色粗体文本
- **就是这样 — 3 种蓝色 + 1 种灰色 + 白色。** 抵制添加更多颜色的冲动。
- 用户提供的模板或明确的颜色偏好始终优先于这些默认值。

**两层结构如何协同工作**：
- 输入单元格：蓝色字体 + 浅灰色填充 = "硬编码输入"
- 公式单元格：黑色字体 + 白色背景 = "计算值"
- 工作表链接：绿色字体 + 白色背景 = "来自另一张工作表的引用"
- 关键输出：黑色粗体字体 + 中等蓝色填充 = "这是答案"

**字体颜色告诉你这是什么（输入/公式/链接）。填充颜色告诉你你在哪里（标题/数据/输出）。**

### 边框标准（专业外观的必需项）

**粗边框**（1.5pt）围绕主要部分：
- 关键输入部分
- 投资假设部分
- 5 年现金流预测部分
- 终值部分
- 估值汇总部分
- 每个敏感性分析表格

**中等边框**（1pt）在子部分之间：
- 公司详细信息 vs 历史表现
- 增长假设 vs EBIT 边际 vs FCF 参数

**细边框**（0.5pt）围绕数据表格：
- 场景假设表格（熊市 | 基准 | 牛市 | 选择）

### 数字格式（遵循 xlsx 技能标准）：
- **年份**：格式化为文本字符串（例如，"2024" 而不是 "2,024"）

- **负数**：`(#,##0)` 括号内（不是减号）

**关键 WACC 公式**：
```
市值 = 价格 × 股份
净债务 = 总债务 - 现金
企业价值 = 市值 + 净债务
股权权重 = 市值 / EV
债务权重 = 净债务 / EV
WACC = (股权成本 × 股权权重) + (税后债务成本 × 债务权重)
```

### 敏感性分析（DCF 工作表底部）

**术语提醒**："敏感性表格" = 带有行标题、列标题和每个数据单元格中公式的简单 2D 网格。不是 Excel 的 "数据表" 功能（数据 → 什么是假设分析 → 数据表）。您将使用 openpyxl 将常规 Excel 公式写入每个单元格。

**位置**：DCF 工作表第 87 行及以下（不是单独的工作表）

**三个敏感性表格，垂直堆叠**：

1. **WACC vs 终值增长率**（第 87-100 行）- 5x5 网格 = 25 个单元格，带公式
2. **收入增长率 vs EBIT 边际**（第 102-115 行）- 5x5 网格 = 25 个单元格，带公式
3. **贝塔 vs 无风险利率**（第 117-130 行）- 5x5 网格 = 25 个单元格，带公式

**总共需要编写 75 个公式**（这是必需的，不是可选的）

**关键**：所有敏感性表格单元格必须使用 openpyxl 程序性地填充公式。不要使用线性近似快捷方式。不要留下占位符文本或关于手动步骤的注释。不要因为 "太复杂" 而合理化留下空白单元格。使用 Python 循环生成公式。

**表格设置**：
1. 创建表格结构，带有行/列标题（要测试的假设值）
2. 用公式填充每个数据单元格，该公式：
   - 使用行标题值（例如，WACC = 9.0%）
   - 使用列标题值（例如，终值增长率 = 3.0%）
   - 使用这些特定假设重新计算完整 DCF
   - 返回该场景的隐含股价
3. 所有单元格必须包含可工作的公式，当交付时
4. 使用条件格式化格式化单元格：绿色刻度表示较高值，红色刻度表示较低值
5. 加粗基准案例单元格
6. 在表格之间留出 1-2 个空白行

**不需要手动干预** - 敏感性表格必须在用户打开文件时完全功能正常。

### 案例选择器实现

**三案例框架**：

### 熊市
- 保守的收入增长率（历史范围低端）
- 利润率压缩或无扩张
- 较高的 WACC（风险溢价增加）
- 较低的终值增长率
- 较高的资本支出假设

### 基准案例
- 共识或管理层指导的收入增长率
- 基于经营杠杆的适度利润率扩张
- 当前市场隐含的 WACC
- 与 GDP 对齐的终值增长率（2.5-3.0%）
- 标准资本支出假设

### 牛市
- 乐观的收入增长率（预测高端）
- 显著的利润率扩张
- 较低的 WACC（降低风险溢价）
- 较高的终值增长率（3.5-5.0%）
- 降低资本支出强度

**公式实现**：

**不要使用分散在各地的嵌套 IF 公式。** 相反，创建一个合并列，使用 INDEX 或 OFFSET 公式从适当的场景块中提取值。

**推荐模式（使用 INDEX）**：
`=INDEX(B10:D10, 1, $B$6)` 其中 `B10:D10` = 熊市/基准/牛市值，`1` = 行偏移，`$B$6` = 案例选择单元格（1、2 或 3）

**然后引用合并列** 在所有预测中：
`收入第 1 年：=D29*(1+$E$10)` 其中 `$E$10` 是第 1 年增长合并列值。

这种方法集中场景逻辑，使模型更容易审计和维护。

### 常见变化

### 高增长科技公司
- 更长的预测期（7-10 年）
- 较高的初始增长率（20-30%）
- 随时间显著扩张利润率
- 较高的 WACC（12-15%）
- 模型单位经济（用户、ARPU 等）

### 成熟/稳定公司
- 较短的预测期（3-5 年）
- 适度的增长率（GDP +1-3%）
- 稳定的利润率
- 较低的 WACC（7-9%）
- 专注于现金产生和资本配置

### 周期性公司
- 模拟经济周期
- 在中周期标准化利润率
- 考虑低谷和高峰场景
- 调整贝塔以反映周期性

### 多部门公司
- 为每个业务单元创建单独的 DCF
- 每个部门具有不同的增长率和利润率
- 部分估值
- 考虑协同效应
