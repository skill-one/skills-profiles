# 3-Statement Financial Model Template Completion

完成并填充集成式财务模型模板，确保损益表、资产负债表和现金流量表之间有正确的关联。

## ⚠️ 关键原则 — 在填充任何模板前阅读

**环境 — Office JS vs Python:**
- **如果在 Excel 中运行（Office 插件 / Office JS）:** 直接使用 Office JS。通过 `range.formulas = [["=D14*(1+Assumptions!$B$5)"]]` 编写公式 — 永远不要为派生单元格使用 `range.values`。无需单独重算；Excel 本地计算。使用 `context.workbook.worksheets.getItem(...)` 在工作表间导航。
- **如果生成独立的 .xlsx 文件:** 使用 Python/openpyxl。编写 `ws["D15"] = "=D14*(1+Assumptions!$B$5)"`，然后交付前运行 `recalc.py`。
- **Office JS 合并单元格陷阱:** 不要调用 `.merge()` 然后在合并范围内设置 `.values` — 会抛出 `InvalidArgument`，因为该范围仍然报告其合并前的维度。相反，仅向左上角单元格写入值，然后合并并格式化整个范围：`ws.getRange("A1").values = [["INCOME STATEMENT"]]; const h = ws.getRange("A1:G1"); h.merge(); h.format.fill.color = "#1F4E79";`
- 以下所有原则在两种环境中都完全适用。

**公式优于硬编码（非可协商）:**
- 每个预测单元格、滚动预测、关联和总计必须是 Excel 公式 — 永远不要使用预计算值
- 使用 Python/openpyxl 时：编写公式字符串 (`ws["D15"] = "=D14*(1+Assumptions!$B$5)"`)，而不是计算结果 (`ws["D15"] = 12500`)
- 只有以下单元格应包含硬编码数字：(1) 历史实际值，(2) 假设标签中的假设驱动因素
- 如果你发现自己用 Python 计算一个值并将其写入单元格 — 停止。编写公式而不是。

**原因：当情景切换或假设更改时，模型必须具有灵活性。硬编码会无声地破坏所有下游完整性检查。**

**与用户逐步验证:**
1. **映射模板后** → 向用户展示你已识别的标签/部分，并在触摸任何单元格前确认
2. **填充历史数据后** → 向用户展示历史数据块并确认值/期间与源数据匹配
3. **构建损益表预测后** → 运行总计检查，向用户展示预测的损益表，并在进入资产负债表前确认
4. **构建资产负债表后** → 向用户展示每个期间的资产=负债+权益的平衡检查，并在进入现金流量表前确认
5. **构建现金流量表后** → 向用户展示现金核对（现金流量表期末现金=资产负债表现金），并在最终确定前确认
6. **不要端到端填充整个模型并呈现完整模型** — 在每个报表处中断，展示工作，尽早发现错误

## 格式化 — 专业蓝灰色调（除非模板/用户指定其他颜色）

**保持颜色最小化。** 仅使用蓝色和灰色填充单元格。不要引入绿色、黄色、橙色或多种强调色 — 干净的模型使用克制。

| 元素 | 填充 | 字体 |
|---|---|---|
| 标题（损益表 / 资产负债表 / 现金流量表） | 深蓝色 `#1F4E79` | 白色加粗 |
| 列标题（FY2024A、FY2025E 等） | 浅蓝色 `#D9E1F2` | 黑色加粗 |
| 输入单元格（历史数据、假设驱动因素） | 浅灰色 `#F2F2F2` 或白色 | 蓝色 `#0000FF` |
| 公式单元格 | 白色 | 黑色 |
| 跨表链接 | 白色 | 绿色 `#008000` |
| 检查行 / 关键总计 | 中蓝色 `#BDD7EE` | 黑色加粗 |

**总共 3 种蓝色 + 1 种灰色 + 白色。** 如果模板有自己的配色方案，请遵循模板。

字体颜色表示单元格的*内容*（输入/公式/链接）。填充颜色表示单元格的*位置*（标题/数据/检查）。

## 模型结构

### 识别模板标签组织

模板在标签命名约定和结构上有所不同。填充前，请查看所有标签以了解模板结构。以下是常见的标签名称及其典型内容：

| 常见标签名称 | 查找内容 |
|------------------|----------------------|
| IS, P&L, 损益表 | 损益表 |
| BS, 资产负债表 | 资产负债表 |
| CF, CFS, 现金流量表 | 现金流量表 |
| WC, 营运资本 | 营运资本表 |
| DA, D&A, 折旧, PP&E | 折旧与摊销表 |
| Debt, 债务表 | 债务表 |
| NOL, 税, DTA | 净经营亏损表 |
| Assumptions, Inputs, Drivers | 驱动假设和输入 |
| Checks, Audit, Validation | 错误检查面板 |

**模板审查清单**
- 确定模板中存在的标签（并非所有模板都包含每个报表）
- 记录任何上述未列出的模板特定标签
- 了解标签依赖关系（例如，哪些报表输入到主报表）
- 在每个标签上定位输入单元格与公式单元格

### 理解模板结构

填充模板前，熟悉其现有布局，确保数据输入到正确位置，公式保持完整。

**识别行结构**
- 在每个标签顶部找到模型标题
- 识别标题及其视觉分隔
- 找到单位行，指示百万美元、百分比、倍数等
- 注意区分实际值与预测期间的列标题
- 确认期间标签（例如，FY2024A、FY2025E）
- 识别输入单元格与公式单元格（通常通过字体颜色区分）

**识别列结构**
- 确认最左侧列中的项目标签
- 验证历史年份先于预测年份
- 注意区分历史与预测期间的视觉边界
- 检查所有标签的列顺序是否一致

**使用命名范围**
模板通常使用命名范围来表示关键输入和输出。填充数据前：
- 查看模板中的现有命名范围（Excel 中的公式 → 名称管理器）
- 常见命名范围包括：收入增长率、成本百分比、关键输出（净收入、EBITDA、总债务、现金）、情景选择器单元格
- 确保输入在输入到这些命名范围的单元格中

### 预测期间
- 模板通常从最后历史年份向前预测 5 年
- 验证历史 (A) 与预测 (E) 列是否清晰分隔
- 确认列使用财政年度表示（例如，FY2024A、FY2025E）

## 边际分析

**注意：如果用户未提示或模板未明确要求，则不应执行以下边际分析。如果未给出提示，请跳过此部分。**

在损益表标签上计算并显示盈利能力边际，以跟踪运营效率和进行同行比较。

### 核心边际
| 边际 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 毛利率 | 毛利润 / 收入 | 定价能力、生产效率 |
| EBITDA 边际 | EBITDA / 收入 | 核心经营盈利能力 |
| EBIT 边际 | EBIT / 收入 | 经营盈利能力（扣除折旧摊销） |
| 净收入边际 | 净收入 / 收入 | 最终盈利能力 |

### 损益表布局（含边际）
直接在每项利润项目下方显示边际百分比：
- 毛利润下方显示毛利率 %
- EBIT 下方显示 EBIT 边际 %
- EBITDA 下方显示 EBITDA 边际 %
- 净收入下方显示净收入边际 %

## 信用指标

**注意：如果用户未提示或模板未明确要求，则不应执行以下信用分析。如果未给出提示，请跳过此部分。**

在资产负债表标签上计算并显示信用/杠杆指标，以评估财务健康状况、债务能力和契约合规性。

### 核心信用指标
| 指标 | 公式 | 衡量内容 |
|--------|---------|------------------|
| 总债务 / EBITDA | 总债务 / 最近 12 个月 EBITDA | 杠杆倍数 |
| 净债务 / EBITDA | (总债务 - 现金) / 最近 12 个月 EBITDA | 扣除现金的杠杆 |
| 利息保障倍数 | EBITDA / 利息费用 | 偿还债务的能力 |
| 债务 / 总资本 | 总债务 / (总债务 + 股本) | 资本结构 |
| 债务 / 股本 | 总债务 / 总股本 | 财务杠杆 |
| 流动比率 | 流动资产 / 流动负债 | 短期流动性 |
| 速动比率 | (流动资产 - 存货) / 流动负债 | 即时流动性 |

### 信用指标层级检查
验证 Upside 显示最强的信用状况：
- 杠杆：Upside < Base < Downside（越低越好）
- 覆盖率：Upside > Base > Downside（越高越好）
- 流动性：Upside > Base > Downside（越高越好）

### 契约合规性跟踪
如果已知债务契约，请添加明确的合规性检查，比较实际指标与契约阈值。

## 情景分析（基准 / Upside / Downside）

在假设标签中使用情景切换器（下拉菜单）和 CHOOSE 或 INDEX/MATCH 公式。

| 情景 | 描述 |
|----------|-------------|
| 基准情景 | 管理层指导或共识估计 |
| Upside 情景 | 高于指导的增长、利润率扩张 |
| Downside 情景 | 低于趋势的增长、利润率压缩 |

**关键驱动因素**: 收入增长率、毛利率、SG&A %、DSO/DIO/DPO、资本支出 %、利率、税率。

**情景审计检查**: 切换开关所有报表，所有情景下的资产负债表平衡，现金核对，层级保持（NI、EBITDA、FCF、边际 Upside > Base > Downside）。

## 完成模型模板

本节提供完成任何 3-Statement 财务模型模板的一般指南，同时保留现有公式并确保数据完整性。

### 第 1 步：分析模板结构

在输入任何数据前，彻底审查模板以了解其架构：

**识别输入与公式单元格**
- 寻找区分输入单元格和公式单元格的视觉提示（字体颜色、单元格着色）
- 常见约定：蓝色字体=输入，黑色字体=公式，绿色字体=跨表链接
- 使用 Excel 的追踪先导/从属（公式 → 追踪先导）来了解单元格关系
- 检查可能控制关键输入的命名范围（公式 → 名称管理器）

**绘制模板流程**
- 确定哪些标签输入到其他标签（例如，假设 → 损益表 → 资产负债表 → 现金流量表）
- 注意任何支持性报表及其与主报表的关联
- 在填充前记录模板的特定项目结构

### 第 2 步：填充数据而不破坏公式

**数据输入黄金规则**

| 规则 | 描述 |
|------|-------------|
| 仅编辑输入单元格 | 永远不要覆盖包含公式的单元格，除非有意替换公式 |
| 保留单元格引用 | 复制数据时，使用粘贴值（Ctrl+Shift+V）以避免用源格式覆盖公式 |
| 匹配模板单位 | 在输入数据前验证模板使用千、百万或实际值 |
| 尊重符号约定 | 遵循模板现有的符号约定（例如，费用为正或负） |
| 检查循环引用 | 如果模板使用迭代计算，确保已启用迭代计算 |

**安全数据输入流程**
1. 确定指定输入的精确单元格（通常突出显示或标记）
2. 首先输入历史数据，然后验证公式是否正确计算这些期间
3. 输入驱动预测计算的假设驱动因素
4. 审核计算输出以确认公式按预期工作
5. 如果必须修改公式单元格，在更改前记录原始公式

**处理预构建公式**
- 如果公式引用你尚未填充的单元格，直到所有输入完成前可能会出现临时错误（#REF!、#DIV/0!）
- 当公式产生意外结果时，追踪先导以识别缺失或错误的输入
- 永远不要删除行/列，而未检查所有标签上的公式依赖关系

### 第 3 步：验证公式

**公式完整性检查**

在依赖模板输出前，验证公式是否正常工作：

| 检查类型 | 方法 |
|------------|--------|
| 追踪先导 | 选择公式单元格 → 公式 → 追踪先导以验证其是否引用正确输入 |
| 追踪从属 | 验证关键输入是否流向预期输出单元格 |
| 评估公式 | 使用公式 → 评估公式以逐步执行复杂计算 |
| 检查硬编码 | 预测公式应引用假设，而不是包含硬编码值 |
| 使用已知值测试 | 输入简单测试值以验证公式是否产生预期结果 |
| 跨表一致性 | 确保相同的公式逻辑适用于所有预测期间 |

**常见公式问题**
- 混合绝对/相对引用导致复制期间时结果不正确
- 对外部文件或已删除范围的链接中断（#REF! 错误）
- 早期期间出现除零错误（#DIV/0! 错误）
- 循环引用警告（可能有意用于利息计算）
- 预测列间公式不一致（使用 Ctrl+\ 查找差异）

**验证跨表链接**
- 确认出现在多个标签上的值是链接的（不是重复的）
- 验证报表总计与对应主报表项目匹配
- 检查所有标签的期间标签是否一致

### 第 4 步：按表进行质量检查

填充模板后，在每个表上执行以下验证检查：

**损益表质量检查**
- 收入数据与历史期间源数据匹配
- 所有费用项目总计为报告总额
- 总计（毛利润、EBIT、EBT、净收入）计算正确
- 税务计算逻辑适当（正确处理亏损）
- 预测驱动因素引用假设标签（无硬编码）
- 期间间变化方向合理

**资产负债表质量检查**
- 每个期间的资产=负债+权益（主要检查）
- 现金余额与现金流量表期末现金匹配
- 营运资本账户与支持性报表（如适用）匹配
- 留存收益正确滚动：前期留存收益 + 净收入 - 股息 +/- 调整 = 期末留存收益
- 债务余额与债务报表（如适用）匹配
- 所有资产负债表项目具有适当符号（资产为正，大多数负债为正）

**现金流量表质量检查**
- 损益表顶部的净收入与损益表净收入匹配
- 非现金加回（折旧摊销、营运资本变动等）与源报表/报表匹配
- 营运资本变动具有正确符号（资产增加=现金使用=负）
- 资本支出与 PP&E 报表或固定资产滚动预测匹配
- 融资活动与资产负债表上的债务和权益账户变动匹配
- 期末现金与资产负债表现金匹配
- 期初现金等于前期期末现金

**支持性报表质量检查**
- 期初余额等于前期期末余额
- 滚动逻辑完整（期初 + 增加额 - 减少额 = 期末）
- 报表总计与主报表项目匹配
- 计算中使用的假设与假设标签匹配

### 第 5 步：跨报表完整性检查

验证单个表后，确认三个报表已正确集成：

| 检查 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表平衡 | 资产 - 负债 - 股本 | = 0 |
| 现金核对 | 现金流量表期末现金 - 资产负债表现金 | = 0 |
| 净收入链接 | 损益表净收入 - 现金流量表期初净收入 | = 0 |
| 留存收益 | 前期留存收益 + 净收入 - 股息 - 资产负债表期末留存收益 | = 0（根据需要调整 SBC/其他项目） |

### 第 6 步：最终审核

在考虑模型完成之前：
- 浏览所有场景（如适用）以验证每个情况下的检查都通过
- 审查所有 #REF!、#DIV/0!、#VALUE! 和 #NAME? 错误并解决或记录
- 确认所有输入单元格都已填写（搜索占位符值）
- 验证所有选项卡中的单位一致性
- 在进行任何其他修改之前保存一个干净的版本

## 模型验证和审计

本节汇总了所有完成的模板的验证检查和审计程序。

### 核心关联（必须始终成立）

有关所有公式详情，请参阅 [references/formulas.md](references/formulas.md)。

| 检查 | 公式 | 预期结果 |
|-------|---------|-----------------|
| 资产负债表平衡 | 资产 - 负债 - 权益 | = 0 |
| 现金核对 | 现金流量表期末现金 - 资产负债表现金 | = 0 |
| 现金月度与年度对比 | 月度期末现金 - 年度期末现金 | = 0 |
| 净收入关联 | 利润表净收入 - 现金流量表期初净收入 | = 0 |
| 留存收益 | 期初留存收益 + 净收入 + 现金流量表补充说明 - 股利 - 资产负债表期末留存收益 | = 0 |
| 权益融资 | 股本/其他综合收益变动（资产负债表） - 权益发行（现金流量表融资活动） | = 0 |
| 第零年权益 | 第零年筹集的权益 - 第一年期初权益资本 | = 0 |

### 正负号约定参考

| 语句 | 项目 | 正负号约定 |
|-----------|------|-----------------|
| 经营活动现金流量 | 折旧与摊销、现金流量表补充说明 | 正（加回） |
| 经营活动现金流量 | 应收账款变动（增加） | 负（现金使用） |
| 经营活动现金流量 | 应付账款变动（增加） | 正（现金来源） |
| 投资活动现金流量 | 资本支出 | 负 |
| 现金流量表融资活动 | 债务发行 | 正 |
| 现金流量表融资活动 | 债务偿还 | 负 |
| 现金流量表融资活动 | 股利 | 负 |

### 循环引用处理

利息费用产生循环：利息 → 净收入 → 现金 → 债务余额 → 利息

在 Excel 中启用迭代计算：文件 → 选项 → 公式 → 启用迭代计算。将最大迭代次数设置为 100，最大更改设置为 0.001。在假设选项卡中添加一个电路断路器切换开关。

### 检查类别

**第 1 部分：货币一致性**
- 在假设中识别并记录货币
- 所有选项卡使用一致的货币符号和尺度
- 单位行与模型货币匹配

**第 2 部分：资产负债表完整性**
- 资产 = 负债 + 权益（每个期间）
- 公式：资产 - 负债 - 权益（必须 = 0）

**第 3 部分：现金流量完整性**
- 现金与资产负债表挂钩（现金流量表期末现金 = 资产负债表现金）
- 现金月度与年度对比：月度期末现金 = 年度期末现金
- 净收入与利润表挂钩（现金流量表净收入 = 利润表净收入）
- 折旧与摊销与计划挂钩
- 现金流量表补充说明与利润表挂钩
- 应收账款、存货、应付账款变动与营运资本计划挂钩
- 资本支出与折旧与摊销计划挂钩

**第 4 部分：留存收益**
- 留存收益逆流检查：期初留存收益 + 净收入 + 现金流量表补充说明 - 股利 = 期末留存收益
- 显示组成部分分解以进行调试

**第 5 部分：营运资本**
- 应收账款、存货、应付账款与资产负债表挂钩
- DSO、DIO、DPO 合理性检查（如果超出正常范围则标记）

**第 6 部分：债务计划**
- 总债务与资产负债表挂钩（流动负债 + 长期债务）
- 利息计算与利润表挂钩

**第 6b 部分：权益融资**
- 权益发行收益与资产负债表股本/其他综合收益增加挂钩
- 权益带来的现金增加 = 权益账户增加（必须平衡）
- 权益融资核对：股本/其他综合收益变动（资产负债表） = 权益发行（现金流量表融资活动）（必须 = 0）
- 第零年权益核对：第零年筹集的权益 = 第一年期初权益资本

**第 6c 部分：NOL 计划**
- 期初 NOL（第 1 年/成立时） = 0（新企业从零 NOL 开始）
- NOL 仅在 EBT < 0 时增加（亏损必须实现才能产生 NOL）
- DTA 与资产负债表挂钩（NOL 计划 DTA = 资产负债表递延所得税资产）
- NOL 利用 ≤ 80% 的 EBT（2017 年后联邦限制）
- NOL 余额为非负（不能利用超过可用的部分）
- 仅在 EBT < 0 时产生 NOL
- 当应税收入 ≤ 0 时，税费用 = 0

**第 7 部分：情景层次结构**
- 绝对指标：上行 > 基准 > 下行（净收入、EBITDA、FCF）
- 利润率：上行 > 基准 > 下行（毛利率%、EBITDA%、净利率%）
- 信用指标：上行 < 基准 < 下行（杠杆率，反向）

**第 8 部分：公式完整性**
- COGS、S&M、G&A、R&D、SBC 由收入的百分比驱动（无硬编码）
- 预测年度之间公式一致
- 无 #REF!、#DIV/0!、#VALUE! 错误

**第 9 部分：信用指标阈值**
- 根据契约阈值将指标标记为绿色/黄色/红色
- 红色警告的摘要

### 主检查公式

将所有部分状态汇总为单个主检查：
- 如果所有部分通过 → "✓ 所有检查通过"
- 如果任何部分失败 → "✗ 检测到错误 - 下方查看"

### 快速调试工作流程

当主状态显示错误时：
1. 滚动查找红色高亮的选项卡
2. 确定哪个检查类别存在失败
3. 导航到源选项卡进行调查
4. 修复根本问题
5. 返回检查选项卡以验证解决方案
