# Canva Creator

## 范围

该技能处理一个活动，分为五个连续的阶段，每个阶段都需要所有者批准：

```
简报 → 日历 → 资产清单 → Canva 设计 → 文本 → HubSpot 预览
```

| 路径 | 渠道 | 该技能生成的内容 |
|------|----------|--------------------------|
| Canva (社交) | Instagram、Facebook、X/Twitter、LinkedIn | Canva 设计 + 标题 + 定时 HubSpot 发布 |
| 文本仅 | 邮件 (Newsletter、营销、滴灌) | 主题 + 预览 + 正文，以内联形式呈现给所有者 |

**在任何情况下，Canva 都不用于邮件行** — 没有模板，没有自动填充，没有设计副本，没有资产上传，没有导出。由于邮件模板自动填充在图像插槽超出可用照片时会产生占位符图形，并且变体缩略图在聊天预览中无法渲染，因此邮件图形不属于此技能的范围。如果所有者要求 Canva 邮件设计，请参阅 `reference/gotchas.md` 获取重定向语言。

---

## 预检查

在第一阶段之前，请确认：

1. **简报。** 用户已引用或粘贴了批准的简报。如果没有：
   "在构建活动之前，我需要内容简报。您有来自内容策略技能的简报，还是现在想写一个？"

2. **Canva 层级。** Pro/Teams 需要从用户的库中手动选择模板（没有自动填充 API）。企业可以从品牌模板中自动填充。

3. **HubSpot 层级。** 社交预览需要 Marketing Hub Professional。入门级或免费版 → 跳过第五阶段，并导出 CSV（见 [reference/hubspot-staging.md](reference/hubspot-staging.md)）。

4. **品牌资产。** 如果连接了店面（Shopify 或 Square — 对等，`../../shared/connector-neutrality.md`），请先读取产品列表：每个简报中提到的产品的标题、图像 URL 和价格。仅读取 — 直到第二阶段第 5 步，不会将任何内容上传到 Canva，并且只有批准的日历的插槽需要的图像才会上传。该列表是起始照片清单；仅询问商店没有图像的产品。拉取规则 — 哪些字段、价格声明规则 — 在 [../social-content-engine/reference/shopify-assets.md](../social-content-engine/reference/shopify-assets.md)（为 Shopify 编写；Square 的目录图像遵循相同的工具清单步骤）。如果没有店面，
   确认磁盘上的产品照片路径或品牌包是否在 Canva 中实时。

5. **生成预算。** 估计活动的 Canva 量，并在第一阶段开始前显示。默认值为每行 Canva 绑定 3 个候选者；每个设计成本约为 5 个 API 调用（自动填充 + 导出 + 投票）。

   ```
   此活动的生成预算：
     Canva (社交) 行：8
     每行候选者： 3   (默认 — 说 "单个候选者" 以使用 1)
     总设计：       24
     API 调用（约）： ~120  (自动填充 + 导出 + 投票)

   Canva 限制：每分钟 100 个请求。这将需要 ~2-3 分钟的生成时间，
   远低于您的层级限制。继续？
   ```

   如果预计的总设计超过 30，建议从一开始就使用单候选者模式 — 大型活动很快就会超出配额。所有者可以在第一阶段开始前将默认值更改为每行 1、2 或 3 个候选者。锁定所选值以供整个会话使用。

## 工作流程

### 第一阶段 — 发布日历

从简报中提取：内容主题、渠道、节奏、硬日期（发布、促销、假日）。

构建一个带有 `路径` 列的日历表，该列将每行路由到 Canva 或文本仅草稿：

| 日期 | 渠道 | 路径 | 主题 | 资产类型 | 标题/主题角度 |
|------|---------|------|-------|------------|-----------------------|
| 6 月 2 日 | Instagram 信息流 | Canva (社交) | 亚麻发布 | Square 发布 | "终于，一件连衣裙…" |
| 6 月 5 日 | 邮件 | 文本仅 | 亚麻发布 | 邮件正文 | "真正呼吸的亚麻" |

在呈现之前，将每个邮件渠道行标记为 `文本仅`。最多 30 天，除非简报另有说明。提前标记调度冲突（同一天为同一产品发布两个帖子）。

**检查点 1。** 呈现日历。询问："这是否符合计划？需要调整任何日期、添加任何渠道或交换任何主题？" 迭代直到批准，然后大声重申分割情况 — "N 行通过 Canva，M 行通过文本仅草稿" — 然后再继续。在此处捕获分类错误是免费的；生成设计后捕获它则不是。

---

### 第二阶段 — 资产清单（仅限 Canva 行）

邮件行完全跳过此阶段。对于每个 `Canva (社交)` 行，构建一个清单，列出模板需要的内容和已提供的内容。

1. **按名称枚举每个图像插槽。** Square Instagram 发布通常有 1-2 个图像插槽；轮播图和产品网格可能有 5 个以上。将它们单独列出 (`Header_Image`, `Product1_Image`, `Product2_Image`, …) — 永远不要将它们汇总为 "产品图像"。
   - 企业：从品牌模板的 `dataset[].label` 中读取字段名称 (`GET /v1/brand-templates/{id}`)。
   - Pro/Teams：计算模板中的每个独特图像矩形。

2. **清点可用资产。** 简报中的文本内容（产品名称、促销文案、标语、定价），从连接的店面在预检查中读取的产品图像 URL（在第 5 步上传，仅用于间隙表需要的插槽，并按 `asset.id` 记录），已上传到 Canva 的产品照片 (`GET /v1/assets`) 或所有者磁盘上的品牌包颜色和字体（企业）。标题中的价格来自店面返回的值或简报，永远不会来自内存。

3. **构建按插槽的间隙表。** 每个设计每个插槽一行 — 不是每个设计一行。

   | 日期 | 插槽名称 | 插槽类型 | 可用资产 | 状态 |
   |------|-----------|-----------|-----------------|--------|
   | 6 月 2 日 | Hero_Image | 图像 | bloom_summer.jpg → asset_id 待定 | 上传 |
   | 6 月 2 日 | Headline | 文本 | "终于，亚麻" | 准备 |
   | 6 月 9 日 | Product1_Image | 图像 | — | **缺失** |

4. **与所有者解决插槽/资产不匹配问题。** 如果模板的图像插槽比简报提供的照片多，请暂停并询问：

   ```
   "Summer Carousel" 模板有 5 个图像插槽。简报给了我 1 张照片 (bloom_summer.jpg)。应该如何填充其余 4 个？

     1. 在所有 5 个插槽中重复同一张照片
     2. 您发给我 4 张更多照片（文件路径）
     3. 选择一个更简单的模板，插槽更少
   ```

   没有生成调用，直到所有者选择。使用空插槽生成会产生充满 Canva 默认风景占位符的设计。

5. **上传缺失的照片并捕获验证的资产 ID。** 通过 `POST /v1/asset-uploads` 上传，然后轮询 `GET /v1/asset-uploads/{job_id}` 直到 `status == "success"`。从响应中记录 `asset.id` — 这是仅在自动填充图像字段中起作用的唯一值。传递空字符串、URL、文件路径或过时的 ID 会静默渲染 Canva 的默认风景图形，而不是照片。

6. **确认清单。** 向所有者展示完成的按插槽表，其中每个插槽都已解决，并且每个图像 `asset.id` 都已确认。这是 Canva API 调用前的最后一步。

---

### 第三阶段 — Canva 设计生成

在任何 Canva API 调用之前，重新阅读日历，并删除 `路径` 不是 `Canva (社交)` 的任何行。邮件行不通过此阶段。

**一次一个日历行生成设计**，每个行 3 个候选者（或在预检查中选择的值）。每行遵循相同的循环：生成候选者 → 验证 → 导出 → 视觉检查 → 重试失败 → 呈现 → 等待所有者选择 → 下一行。行之间暂停 30 秒。这将突发限制在每 ~30 秒 3 个生成 + 3 个导出 — 远低于 Canva 的每分钟 100 个请求速率限制。不要并行化多个行；一次一行是防止所有者在活动期间超出配额的保护措施。

**轮询节奏。** 每 3-5 秒轮询一次工作状态，不要更快。更紧密的间隔会消耗配额而不会加快完成速度。

**预览 URL — 只有一种类型是安全的。** 自动填充响应返回 `design.canva.ai` 缩略图，几分钟内过期；将其作为 markdown 图像嵌入会产生损坏的 "显示图像" 占位符。永久导出 URL (`export-download.canva.com` 或 `export-design` MCP 工具) 不会过期。原生 Cowork 轮播图使用连接器的认证会话直接渲染自动填充结果 — 让它们自行渲染，不要重新嵌入。

#### 行循环

1. **解析模板。** （每个会话一次 — 如果日历混合了资产类型，则跨行使用相同模板。）
   - 企业：`GET /v1/brand-templates` 按资产类型过滤。
   - Pro/Teams：`GET /v1/designs?ownership=any&query={模板名称}`，向所有者展示前 3 个，确认一个后再生成。

2. **并行生成行的候选者。** 同时启动行的 3 个候选者（或预检查中的 N 个）。
   - 企业：每个候选者 `POST /v1/autofills` 带有模板 ID 和字段值。并发轮询所有作业。
   - Pro/Teams：`POST /v1/designs` 创建副本。描述所有者在 Canva 中应用的文本和图像编辑；收集设计 ID。

3. **验证作业状态。** 对于每个候选者，确认 `GET /autofills/{job_id}` 返回 `status == "success"` 且 `result.design.id` 存在。按设计处理错误：
   - `JOB_FAILED` → 读取 `job.error.message`，修复字段值或资产 ID，重试一次。
   - `RATE_LIMIT_EXCEEDED`（本会话首次遇到）→ 等待 60 秒，重试该候选者一次。这处理了暂时的峰值。
   - `RATE_LIMIT_EXCEEDED`（本会话第二次遇到）**或**任何 `quota_exceeded` / 每日上限错误 → 立即停止生成。不要重试。显示进度并询问：

     ```
     Canva 正在限制活动。状态如下：
       ✓ 已生成： 1-4 帖子 (12 个设计)
       ⏸ 剩余： 5-8 帖子 (12 个尚未生成)

     如何继续？
       1. 切换到每行 1 个候选者（总共 4 个设计）— 现在完成
       2. 暂停活动 — 60 分钟后恢复，配额已刷新
       3. 停止生成 — 使用现有内容，继续标题
     ```

     等待所有者的选择。不要重试循环。

4. **将每个成功的候选者导出为永久 PNG。** 并行启动行的导出。
   - REST：`POST /v1/exports` 带有 `format.type: "png"`，轮询 `GET /v1/exports/{job_id}` 直到成功，捕获 `urls[0]`。
   - Canva MCP：`export-design` 带有设计 ID。

   这些永久 URL 将用于预览和稍后附加到 HubSpot 发布。自动填充响应缩略图永远不会用于下游。

5. **视觉验证每个导出。** 查看图像并拒绝任何这些 — 它们都表示未填充的插槽或错误的资产：
   - 带有云和绿色山丘的通用风景（Canva 的默认占位符）
   - 应该是照片的实心灰色矩形
   - Lorem-ipsum 或模板默认文本
   - 与简报不匹配的主题（错误的产品、错误的品牌）

   如果候选者验证失败：重新检查受影响的插槽的清单，修复 `asset.id`，重新生成该单个候选者，重新导出，重新验证。

6. **在部分失败时重试每个候选者。** 如果行中的 N 个候选者在第 3 步或第 5 步失败，请重新生成该单个候选者 — 不要重做整行，也不要呈现部分损坏的轮播图。如果第二次尝试也失败：

   ```
   6 月 9 日发布的第三个候选者持续失败 — Canva 返回 [错误 / 渲染了占位符]。如何继续？

     1. 跳过它 — 呈现其他两个并继续
     2. 为此候选者切换到更简单的模板
     3. 尝试使用不同照片一次
   ```

7. **呈现行的候选者。** 让原生 Cowork 轮播图渲染自动填充工具结果。在其下方添加文本提示：

   ```
   6 月 9 日的候选者已准备好 — 向上滚动查看轮播图。我应该使用哪个设计发布 6 月 9 日？
   ```

   如果轮播图无法渲染或一个位置损坏，请嵌入第 4 步的永久导出 PNG URL。最终后备：链接到设计的 Canva 编辑 URL (`https://www.canva.com/d/{design_id}`)。永远不要重新嵌入 `design.canva.ai` URL。

8. **暂停 30 秒，然后转到下一行。**

**检查点 2。** 所有者对每个日历行选择了一个设计后才会满意。如果他们想要重新生成，请仅重新生成该单个候选者。

### 第四阶段 — 文本草稿

为每个日历行起草文本。社交行获得标题；邮件行获得完整邮件。

**社交标题** — Instagram、Facebook、X、LinkedIn：

- 长度：渠道适用（Instagram ≤ 2,200 字符；Facebook ≤ 500 推荐字；X ≤ 280）。
- 结构：钩子 → 一个产品优势 → CTA → 3-5 个标签（不是 30 个）。
- 语气：匹配简报的语气标记。如果简报说 "休闲友好"，不要写企业文案。
- 无填充。无 "令人兴奋的消息！" 或 "我们很高兴宣布。" 从价值开始。

**邮件内容** — Claude 写整个邮件；不使用 Canva：

- 主题：≤ 50 字符，具体，无标题党。"春季项目正在预订" 比 "不要错过！" 更好。
- 预览：≤ 90 字符，补充主题，不重复。
- 正文：纯文本，100-250 字。引人入胜的开头 → 1-2 段实质性内容 → 单个清晰 CTA → 签名。
- 语气：与社交相同。所有者希望他们的邮件听起来像他们自己，而不是模板化的简报。
- 无图像引用。不要写 "查看上方图像"。如果所有者想要视觉效果，他们会在自己的邮件工具中添加。
- 每个邮件一个 CTA。选择最重要的操作并首先突出显示。

在社交行下方内联呈现标题。在邮件行下方内联呈现完整邮件：

```
主题：<主题行>
预览：<预览文本>

<正文文本>
```

有关示例，请参阅
[reference/examples/boutique-brief-campaign.md](reference/examples/boutique-brief-campaign.md)。

**检查点 3。** "需要重写任何标题或邮件吗？标记日期和更改内容。" 迭代直到批准。

---

### 第五阶段 — HubSpot 预览 + 邮件交接

在 HubSpot 中预览社交帖子。邮件内容不预览 — 它以内联形式呈现给所有者，以便他们复制到自己的邮件工具。有关 API 字段参考，请参阅
[reference/hubspot-staging.md](reference/hubspot-staging.md)。

1. **创建活动。** `POST /marketing/v3/campaigns` 带有活动名称和日历的起止日期。

2. **预览每个社交帖子。** `POST` 到 HubSpot 社交 API 每个社交行：
   - `channel`：将日历渠道映射到 HubSpot 账户 ID
   - `scheduledAt`：ISO 8601 日期时间 — 在调用之前确认它在未来
   - `content.body`：批准的标题
   - `attachments`：永久 Canva 导出 PNG URL（来自第三阶段）
   - `status`：`SCHEDULED`（永远不会 `PUBLISHED`）

3. **确认队列。** 调用
   `GET /marketing/v3/social/posts?status=SCHEDULED`，显示列表，提供直接链接到 HubSpot 活动视图。

4. **内联显示邮件内容以供交接。** 对于每个邮件行，内联显示批准的主题 + 预览 + 正文，按发送日期分组。所有者将这些复制到他们的邮件工具（HubSpot Marketing Email、Mailchimp、Gmail 或 M365）。

**最终检查点。**

```
您的社交帖子已安排在 HubSpot 中：[链接]
它们将按计划发送 — 您可以在 HubSpot 中取消或编辑任何帖子。

邮件内容已草拟如下 — 准备好发送时复制每个：

  6 月 5 日 — "春季项目正在预订"
  7 月 15 日 — "夏季维护窗口正在填满"

完成前有什么要更改的吗？
```

在附上该摘要之后——绝不替代摘要——按照公司风格（`../../shared/artifact-style.md`）将此营销活动渲染为 HTML 工件：将发布日历呈现为表格，在每一行中为每个渠道添加一个状态标签（已排期 / 草稿 / 待移交），并在每一行中提供一个分阶段发布的面板，其中包含已批准的文案或电子邮件正文及其导出的 PNG 链接。

**收尾提议。** 用一行说明营销活动当前包含的内容，然后给出最相关的下一步及其触发短语——通常当帖子开始发布时，就是"我的营销有效吗？"（`growth-pulse`）。最多还可提供另外两项："制作内容"（`social-content-engine`）用于常设日历，或"我的广告"（`ad-manager`）。最多三项；绝不重新提议所有者在本次会话中已拒绝的内容。

## 审批门禁

- **电子邮件行不得调用 Canva。** 在每次 API 调用前，务必重新检查 `Path` 列。
- **禁止发布。** 所有 HubSpot 帖子均以 `SCHEDULED`（已排期）状态暂存；由所有者控制正式上线。
- **在预检阶段始终公开生成预算。** 所有者需看到设计总数并审批，第一阶段方可开始。
- **第三阶段每次只处理一行。** 同一行内的候选项并行触发，但各行顺序执行且间隔 30 秒——这是配额保护机制。
- **遇到第二次配额错误时，暂停并询问。** 绝不循环重试。
- **在展示前，务必导出为永久 PNG。** 任务成功并不意味着设计正确渲染。
- **绝不在消息中嵌入 `design.canva.ai` 链接。** 这些链接会过期。
- **绝不在某个候选项失败时重新生成整行。** 仅对单个候选项进行重试。
- **绝不为 Pro/Teams 用户自动选择模板。** 必须始终确认。
- **绝不跳过逐槽位检查。** 多槽位模板在任何槽位为空时，都会渲染占位图片。
- **绝不跳过检查点 1。** 在日历获批前生成内容，是本技能中造成最大工作量浪费的原因。
