# /review-contract -- 根据操作手册进行合同审查

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅 [CONNECTORS.md](../../CONNECTORS.md)。

根据你所在组织的谈判操作手册审查合同。分析每个条款，标记偏差，生成修订建议，并提供商业影响分析。

**重要提示**：你协助法律工作流程，但不提供法律建议。所有分析在依赖之前都应由合格的法律专业人士进行审查。

## 调用方式

```
/review-contract <合同文件或URL>
```

审查合同：@$1

## 工作流程

### 第一步：接受合同

以以下任何格式接受合同：
- **文件上传**：PDF、DOCX或其他文档格式
- **URL**：指向你CLM（合同生命周期管理系统）、云存储（例如Box、Egnyte、SharePoint）或其他文档系统的合同链接
- **粘贴文本**：直接粘贴到对话中的合同文本

如果未提供合同，提示用户提供合同。

### 第二步：收集背景信息

在开始审查之前，向用户询问背景信息：

1. **你代表哪一方？**（供应商/承包商、客户/购买者、许可方、被许可方、合作伙伴——或其他）
2. **截止日期**：何时需要最终确定？（这会影响问题的优先级）
3. **关注领域**：有任何特定关注点吗？（例如，“数据保护至关重要”、“我们需要在期限上保持灵活性”、“知识产权所有权是关键问题”）
4. **交易背景**：有任何相关的商业背景吗？（例如，交易规模、战略重要性、现有关系）

如果用户提供了部分背景信息，则使用现有信息继续，并注明假设。

### 第三步：加载操作手册

在本地设置中查找组织的合同审查操作手册（例如，`legal.local.md`或类似的配置文件）。

操作手册应定义：
- **标准立场**：组织对每个主要条款类型的首选条款
- **可接受范围**：可以同意而无需升级的条款
- **升级触发条件**：需要高级法律顾问审查或外部法律顾问参与的条款

**如果没有配置操作手册**：
- 告知用户未找到操作手册
- 提供两个选项：
  1. 帮助用户设置他们的操作手册（逐步定义关键条款的立场）
  2. 使用广泛接受的商业标准作为基线进行通用审查
- 如果进行通用审查，请明确说明该审查基于通用商业标准，而不是组织的特定立场

### 第四步：逐条分析

应用以下审查流程：

1. **确定合同类型**：SaaS协议、专业服务、许可、合作伙伴关系、采购等。合同类型会影响哪些条款最重要。
2. **确定用户立场**：供应商、客户、许可方、被许可方、合作伙伴。这从根本上改变了分析（例如，责任限制保护有利于不同的当事人）。
3. **在标记问题之前阅读整个合同**。条款相互关联（例如，无上限的赔偿可能部分被广泛的限制责任所减轻）。
4. **根据操作手册立场分析每个重要条款**。
5. **全面考虑合同**：整体风险分配和商业条款是否平衡？

系统性地分析合同，至少涵盖以下内容：

| 条款类别 | 关键审查点 |
|----------|-----------|
| **责任限制** | 金额上限、例外情况、相互与单方面、间接损害 |
| **赔偿** | 范围、相互与单方面、上限、知识产权侵权、数据泄露 |
| **知识产权所有权** | 现有知识产权、开发中的知识产权、雇佣作品、许可授予、转让 |
| **数据保护** | DPA（数据处理协议/补充协议）要求、处理条款、分包商权利、通知义务、跨境传输 |
| **保密** | 范围、期限、例外情况、返还/销毁义务 |
| **陈述与保证** | 范围、免责声明、存续期 |
| **期限与终止** | 持续期限、续订、便利终止、因故终止、清算 |
| **管辖法律与争议解决** | 管辖权、地点、仲裁与诉讼 |
| **保险** | 覆盖要求、最低标准、覆盖证明 |
| **转让** | 同意要求、控制权变更、例外情况 |
| **不可抗力** | 范围、通知、终止权利 |
| **付款条款** | 净条款、逾期费用、税费、价格递增 |

对于每个条款，根据操作手册（或通用标准）进行评估，并注明是否存在、缺失或不寻常。

#### 详细条款指导

##### 责任限制

**审查要点**：
- 金额上限（固定金额、费用倍数或无上限）
- 限制是否相互或对每方不同
- 上限的例外情况（哪些责任无上限）
- 是否排除后果性、间接、特殊或惩罚性损害
- 排除是否相互
- 后果性损害排除的例外情况
- 限制是否按索赔、按年或按总额适用

**常见问题**：
- 限制金额为费用的较小比例（例如，在低价值合同中，“过去3个月的费用”）
- 不对称的例外情况有利于起草方
- 广泛的例外情况实际上消除了上限（例如，“违反第X节”而第X节涵盖大多数义务）
- 对一方违约没有后果性损害排除

##### 赔偿

**审查要点**：
- 赔偿是否相互或单方面
- 范围：什么触发赔偿义务（知识产权侵权、数据泄露、人身伤害、违反陈述与保证）
- 是否赔偿有上限（通常受整体责任上限约束，或有时无上限）
- 程序：通知要求、控制辩护的权利、和解的权利
- 是否被赔偿方必须减轻损失
- 赔偿与责任限制条款之间的关系

**常见问题**：
- 单方面知识产权侵权赔偿，而双方都贡献了知识产权
- 对“任何违约”的赔偿（过于广泛；实际上将责任上限转换为无上限责任）
- 没有控制索赔辩护的权利
- 赔偿义务在终止后无限期存续

##### 知识产权

**审查要点**：
- 现有知识产权的所有权（每一方都应保留自己的）
- 在参与期间开发的知识产权
- 雇佣作品条款及其范围
- 许可授予：范围、排他性、地域、再许可权
- 开源考虑
- 反馈条款（对建议或改进的授权）

**常见问题**：
- 广泛的知识产权转让，可能捕获客户的现有知识产权
- 雇佣作品条款超出交付物范围
- 无限制的反馈条款授予永久、不可撤销的许可
- 许可范围比业务关系所需的更广

##### 数据保护

**审查要点**：
- 是否需要数据保护协议/补充协议（DPA）
- 数据控制者与数据处理者的分类
- 分包商权利和通知义务
- 数据泄露通知时间（GDPR为72小时）
- 跨境数据传输机制（SCCs、充分性决定、约束性公司规则）
- 终止时的数据删除或返还义务
- 数据安全要求和审计权利
- 数据处理的目的限制

**常见问题**：
- 处理个人数据时没有DPA
- 没有通知的空白授权分包商
- 违约通知时间比监管要求长
- 没有跨境传输保护，而数据跨国转移
- 不充分的数据删除条款

##### 期限与终止

**审查要点**：
- 初始期限和续订条款
- 自动续订条款和通知期
- 便利终止：可用吗？通知期？早期终止费用？
- 因故终止：补救期？什么构成因故？
- 终止的影响：数据返还、过渡协助、存续条款
- 清算期和义务

**常见问题**：
- 初始期限长且没有便利终止
- 自动续订具有短通知窗口（例如，年度续订的30天通知）
- 因故终止没有补救期
- 不充分的过渡协助条款
- 存续条款实际上无限期延长协议

##### 管辖法律与争议解决

**审查要点**：
- 法律选择（管辖权）
- 争议解决机制（诉讼、仲裁、先调解）
- 诉讼的地点和管辖权
- 仲裁规则和地点（如果仲裁）
- 排除陪审团审判
- 排除集体诉讼
- 胜诉方律师费

**常见问题**：
- 不利的管辖权（不寻常或遥远的地点）
- 对起草方有利的强制性仲裁
- 没有陪审团审判的豁免而没有相应的保护
- 没有正式争议解决之前的升级程序

### 第五步：标记偏差

使用三级系统对与操作手册的偏差进行分类：

#### 绿色——可接受

条款与组织的标准立场一致或更好。商业上合理且不会实质性增加风险的细微变化。

**示例**：
- 责任限制为18个月的费用，而标准是12个月（对客户更有利）
- 相互保密期为2年，而标准是3年（更短但合理）
- 管辖法律在一个成熟的商业司法管辖区，靠近首选的司法管辖区

**行动**：仅作记录。无需谈判。

#### 黄色——谈判

条款超出标准立场但在可谈判范围内。该条款在市场上很常见，但不是组织的偏好。需要关注并可能需要谈判，但不需要升级。

**示例**：
- 责任限制为6个月的费用，而标准是12个月（低于标准但可谈判）
- 单方面知识产权侵权赔偿，而标准是相互的（市场常见立场但不是首选）
- 自动续订通知期为60天，而标准是90天
- 管辖法律在一个可接受但非首选的司法管辖区

**行动**：生成具体的修订建议。提供后备立场。估计接受与谈判的商业影响。
- **包括**：将条款恢复到标准立场的具体修订建议
- **包括**：如果对方坚持，后备立场
- **包括**：接受与谈判的商业影响

#### 红色——升级

条款超出可接受范围，触发定义的升级标准，或构成实质性风险。需要高级法律顾问审查、外部法律顾问参与或业务决策者批准。

**示例**：
- 无上限责任或没有责任限制条款
- 单方面广泛赔偿且无上限
- 现有知识产权的转让
- 处理个人数据时未提供DPA
- 不合理的竞业禁止或排他性条款
- 管辖法律在有问题且具有强制性仲裁的司法管辖区

**行动**：解释具体风险。提供市场标准的替代语言。估计风险。建议升级路径。
- **包括**：为什么这是一个红色标志（具体风险）
- **包括**：标准市场立场是什么
- **包括**：商业影响和潜在风险
- **包括**：建议的升级路径

### 第六步：生成修订建议

对于每个黄色和红色偏差，提供：
- **当前语言**：引用相关的合同文本
- **建议修订**：具体的替代语言
- **理由**：适合与对方律师分享的简要解释
- **优先级**：这是谈判中的必需品还是可选项

#### 修订建议最佳实践

在生成修订建议时：

1. **具体**：提供确切的语言，而不是模糊的指导。修订建议应准备好插入。
2. **平衡**：提出对关键点坚定但商业上合理的语言。过于强硬的修订建议会拖慢谈判。
3. **解释理由**：包括适合与对方律师分享的简要、专业的理由。
4. **提供后备立场**：对于黄色项目，如果主要要求被拒绝，请包括后备立场。
5. **优先级**：并非所有修订建议都同等重要。指出哪些是必需品，哪些是可选项。
6. **考虑关系**：根据这是新供应商、战略合作伙伴还是大宗商品供应商，调整语气和方法。

#### 修订建议格式

对于每个修订建议：
```
**条款**：[节引用和条款名称]
**当前语言**："[合同中的确切引用]"
**建议修订**："[具体的替代语言，添加内容加粗，删除内容概念上划线]"
**理由**：[1-2句话解释原因，适合外部分享]
**优先级**：[必需品 / 应该 / 可选]
**后备**：[如果主要修订被拒绝，替代立场]
```

### 第七步：商业影响摘要

提供涵盖以下内容的摘要部分：
- **整体风险评估**：合同风险概况的高级视图
- **前3个问题**：需要解决的最重要事项
- **谈判策略**：推荐方法（哪些问题要首先提出，哪些要妥协）
- **时间考虑**：任何影响谈判方法的紧迫因素

#### 谈判优先级框架

在提出修订建议时，按谈判优先级组织：

**第一级——必需品（交易破裂）**
无法在没有解决的情况下继续的问题：
- 无上限责任或责任限制不足
- 缺少对受监管数据的保护要求
- 可能危及核心资产的知识产权条款
- 与监管义务冲突的条款

**第二级——应该（强烈偏好）**
对风险有实质性影响但有谈判空间的问题：
- 责任限制调整在范围内
- 赔偿范围和相互性
- 终止灵活性
- 审计和合规权利

**第三级——可选（战略妥协候选）**
可以改善立场但可以战略性地让步的问题：
- 首选管辖法律（如果替代方案可接受）
- 通知期偏好
- 定义上的微小改进
- 保险证明要求

**谈判策略**：首先提出第一级项目。用第三级让步来换取第二级胜利。永远不要在没有升级的情况下让步第一级。

### 第八步：CLM路由（如果已连接）

如果通过MCP连接了合同生命周期管理系统：
- 根据合同类型和风险级别推荐适当的审批工作流
- 建议正确的路由路径（例如，标准审批、高级法律顾问、外部法律顾问）
- 注明基于合同价值或风险标志的任何所需批准

如果没有连接CLM，跳过此步骤。

## 输出格式

将输出结构化为：

```
## 合同审查摘要

**文档**：[合同名称/标识符]
**当事人**：[当事人名称和角色]
**你的立场**：[供应商/客户等]
**截止日期**：[如果提供]
**审查基础**：[操作手册 / 通用标准]

## 关键发现

[前3-5个问题及其严重性标志]

## 逐条分析

### [条款类别] -- [绿色/黄色/红色]
**合同规定**：[条款概述]
**操作手册立场**：[你的标准]
**偏差**：[差距描述]
**商业影响**：[实际意义是什么]
**修订建议**：[具体语言，如果是黄色或红色]

[重复每个主要条款]

## 谈判策略

[推荐方法、优先级、妥协候选]

## 下一步

[具体要采取的行动]
```

## 备注

- 如果合同不是英文，请注明并询问用户是否需要翻译或以原始语言进行审阅
- 对于非常长的合同（50页以上），建议先专注于最重要的部分，然后再进行完整审阅
- 始终提醒用户，在进行法律决策之前，应先由具备资质的法律顾问审阅此分析
