# 账户研究

从 Common Room 中检索和综合账户信息。处理四种交互模式：完整概览、目标字段问题、稀疏数据情况以及结合 MCP 数据 + LLM 推理。

## 第 0 步：加载用户上下文（Me）

在研究任何账户之前，从 Common Room 中获取 `Me` 对象。这提供了：
- 用户的个人资料、头衔、角色和 CR 中的 Persona
- 用户的细分（"我的细分"）

默认所有查询都针对用户自己的细分，除非用户明确要求更广泛的视图。这使结果保持在他们的领域内。

## 第 1 步：识别交互模式

在决定要检索多少数据之前，确定用户实际需要什么：

**模式 1 — 完整概览**："告诉我关于 Datadog 的情况" / "总结 cloudflare.com"
→ 检索完整字段集并生成结构化简报。

**模式 2 — 目标问题**："谁拥有 Snowflake 账户？" / "acme.io 是否显示出购买信号？" / "notion.so 的员工人数是多少？"
→ 仅检索相关字段。返回直接、简洁的答案 — 不要为简单问题生成完整简报。

**模式 3 — 稀疏数据**："告诉我关于 tiny-startup.io 的情况"
→ 如果 Common Room 对账户的数据有限，要诚实地说："此账户的信息有限。" 永远不要猜测或用通用陈述来填补空白。

**模式 4 — 结合推理**：检索结构化的 MCP 数据，然后加入 LLM 分析 — 例如，"Stripe 有 8,000 名员工，正在大力招聘 AI 职位。根据您的 ICP 为 1k–10k 的金融科技公司，这是一个很好的匹配。"

## 第 2 步：查找账户

通过域名或公司名称在 Common Room 中搜索账户。首先尝试精确匹配；如果没有结果，请尝试部分匹配，并在继续之前与用户确认。

## 第 3 步：获取正确的字段

使用 Common Room 对象目录查看可用的字段组和它们的内容。对于完整概览，请求所有字段组。对于目标问题，仅请求相关内容。

**需要了解的关键字段组：**
- **分数** — 始终以原始值或百分位数返回，永远不要返回标签
- **摘要研究** — RoomieAI 输出；通常是最丰富的定性信号
- **主要联系人** — 按分数降序排序；使用 communityMemberID 进行完整查找

**选择要获取的内容：**

| 用户查询类型 | 请求的字段 |
|-------------|-----------|
| 完整账户概览 | 所有字段组 |
| "谁拥有此账户？" | 公司资料和链接、CRM 字段 |
| "这家公司是否是一个好的匹配？" | 关键字段、分数、关于 |
| "这个账户显示出哪些信号？" | 分数、摘要研究、CRM 字段 |
| "主要联系人是谁？" | 主要联系人 |
| "RoomieAI 对他们说了什么？" | 摘要研究、所有研究 |
| "在这个账户中找到工程师" | 潜在客户（带标题过滤器） |

## 第 4 步：网络搜索（仅限稀疏数据）

Common Room 是主要数据源。当 CR 返回丰富数据时，不要运行网络搜索。

当 CR 数据稀疏（模式 3 — 返回字段少、无活动、无分数）时，运行目标网络搜索以填补空白：
- `"[公司名称]" 新闻` — 限制在最后 30 天内
- 查找：融资轮次、收购、产品发布、高管变动、新闻报道

如果用户明确要求外部背景或最新新闻，无论数据丰富程度如何，都运行网络搜索。

## 第 5 步：应用推理（模式 4）

当用户的问题需要综合，而不仅仅是数据检索时，加入分析：
- 将账户数据与会话上下文中的已知 ICP 标准进行比较
- 识别匹配信号（规模、行业、技术栈、招聘模式）
- 注意时间信号（融资、试用状态、最近活动激增）
- 将见解明确地推导自数据，而不是假设

当用户的公司背景可用时（参见 `references/my-company-context.md`），将发现结果与用户的价值主张和 ICP 相对。

## 第 6 步：生成输出

仅包含 Common Room 返回实际数据的部分。完全省略部分，而不是用猜测填充它们。

**完整概览（当数据丰富时）：**

```
## [公司名称] — 账户概览

**快照**
[2–3 句话：他们做什么，计划/阶段，关系状态]

**关键详情**
[员工人数、行业、位置、域名、融资 — 来自关键字段]

**CRM & 所有权** [如果返回了 CRM 字段]
[所有者、机会阶段、ARR]

**分数** [如果返回了分数]
[所有可用分数作为原始值或百分位数]

**信号亮点** [如果有活动/信号]
[3–5 个最重要的信号及其日期]

**主要联系人** [如果返回了联系人]
[姓名 | 标题 | 分数 — 前 5 名按分数降序排序]

**RoomieAI 研究** [如果摘要研究非空]
[摘要研究输出；列出所有可用研究主题名称]

**建议的下一步**
[2–3 个具体的、有信号支持的行动]
```

**目标问题**：1–3 句话的直接答案。不需要完整简报。

**稀疏数据（返回字段少，大多数部分将为空）：**

```
## [公司名称] — 账户概览（有限数据）

**可用数据**：[列出 Common Room 返回的确切内容]

[仅呈现返回的字段]

**网络搜索**
[网络搜索结果 — 或 "未发现重要近期新闻"]

**注意**：Common Room 对此账户的数据有限。此账户可能需要在 Common Room 中进行丰富。
```

## 质量标准

- 分数必须始终为原始值或百分位数 — 永远不要分类标签
- 对于目标问题，要精确回答，不要过度提供
- 当数据缺失或过时时，要明确说明 — 不要猜测
- 保持完整简报在 2–3 分钟内可读
- **每个事实都必须追溯到工具调用** — 不要包含 Common Room 未返回的数据
