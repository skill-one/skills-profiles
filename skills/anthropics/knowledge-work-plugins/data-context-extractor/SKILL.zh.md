# 数据上下文提取器

一种元技能，用于从分析师处提取特定公司的数据知识，并生成定制化的数据分析技能。

## 工作原理

该技能有两种模式：

1. **引导模式**：从零开始创建一个新的数据分析技能
2. **迭代模式**：通过添加特定领域的参考文件来改进现有技能

---

## 引导模式

使用场景：用户希望为其数据仓库创建一个新的数据上下文技能。

### 第一阶段：数据库连接与发现

**步骤 1：识别数据库类型**

询问："您正在使用什么数据仓库？"

常见选项：
- **BigQuery**
- **Snowflake**
- **PostgreSQL/Redshift**
- **Databricks**

使用 `~~数据仓库` 工具（查询和架构）进行连接。如果不确定，请检查当前会话中可用的 MCP 工具。

**步骤 2：探索架构**

使用 `~~数据仓库` 架构工具执行以下操作：
1. 列出可用的数据集/架构
2. 确定最重要的表（询问用户："分析师最常查询的 3-5 个表是哪些？")
3. 拉取这些关键表的架构详情

按方言的示例探索查询：
```sql
-- BigQuery：列出数据集
SELECT schema_name FROM INFORMATION_SCHEMA.SCHEMATA

-- BigQuery：列出数据集中的表
SELECT table_name FROM `project.dataset.INFORMATION_SCHEMA.TABLES`

-- Snowflake：列出架构
SHOW SCHEMAS IN DATABASE my_database

-- Snowflake：列出表
SHOW TABLES IN SCHEMA my_schema
```

### 第二阶段：核心问题（必须询问这些问题）

在架构发现之后，以对话形式询问这些问题（不要一次性全部问）：

**实体消歧（关键）**
> "在这里，当人们说 '用户' 或 '客户' 时，他们具体指的是什么？是否有不同类型？"

倾听：
- 多个实体类型（用户与账户与组织）
- 它们之间的关系（1:1, 1:N, N:N）
- 连接它们的 ID 字段

**主要标识符**
> "【客户/用户/账户】的主要标识符是什么？同一个实体是否有多个 ID？"

倾听：
- 主键与业务键
- UUID 与整数 ID
- 遗留 ID 系统

**关键指标**
> "人们最常询问的 2-3 个指标是什么？每个指标是如何计算的？"

倾听：
- 精确公式（ARR = monthly_revenue × 12）
- 每个指标所依赖的表/列
- 时间段约定（过去 7 天、日历月等）

**数据卫生**
> "哪些数据永远不应该出现在查询中？（测试数据、欺诈、内部用户等）"

倾听：
- 总是包含的标准 WHERE 子句
- 指示排除的标记列（is_test, is_internal, is_fraud）
- 要排除的特定值（状态 = '已删除'）

**常见陷阱**
> "新分析师在使用这些数据时通常犯哪些错误？"

倾听：
- 混淆的列名
- 时区问题
- NULL 处理的怪癖
- 历史数据与当前状态表

### 第三阶段：生成技能

创建具有以下结构的技能：

```
[公司]-data-analyst/
├── SKILL.md
└── references/
    ├── entities.md          # 实体定义和关系
    ├── metrics.md           # KPI 计算
    ├── tables/              # 每个领域一个文件
    │   ├── [领域1].md
    │   └── [领域2].md
    └── dashboards.json      # 可选：现有仪表板目录
```

**SKILL.md 模板**：参见 `references/skill-template.md`

**SQL 方言部分**：参见 `references/sql-dialects.md` 并包含相应的方言说明

**参考文件模板**：参见 `references/domain-template.md`

### 第四阶段：打包和交付

1. 在技能目录中创建所有文件
2. 打包为 zip 文件
3. 向用户展示捕获内容的摘要

## 迭代模式

使用场景：用户已有现有技能，但需要添加更多上下文。

### 第一步：加载现有技能

要求用户上传其现有技能（zip 或文件夹），或如果已在会话中，则定位它。

读取当前的 SKILL.md 和参考文件，以了解已记录的内容。

### 第二步：识别差距

询问："哪个领域或主题需要更多上下文？哪些查询失败或产生错误结果？"

常见差距：
- 新的数据领域（营销、财务、产品等）
- 缺失的指标定义
- 未记录的表关系
- 新术语

### 第三步：针对性发现

针对识别的领域：

1. **探索相关表**：使用 `~~数据仓库` 架构工具查找该领域的表
2. **询问领域特定问题**：
   - "用于【领域】分析的表有哪些？"
   - "【领域】的关键指标是什么？"
   - "【领域】数据的特殊过滤或陷阱？"

3. **生成新的参考文件**：使用领域模板创建 `references/[领域].md`

### 第四步：更新和重新打包

1. 添加新的参考文件
2. 更新 SKILL.md 的 "知识库导航" 部分以包含新领域
3. 重新打包技能
4. 向用户展示更新后的技能

## 参考文件标准

每个参考文件应包含：

### 表文档

- **位置**：完整表路径
- **描述**：该表包含的内容，何时使用它
- **主键**：如何唯一标识行
- **更新频率**：数据刷新频率
- **关键列**：表，列名、类型、描述、备注
- **关系**：该表如何与其他表连接
- **示例查询**：2-3 个常见查询模式

### 指标文档

- **指标名称**：人类可读名称
- **定义**：平实的英文解释
- **公式**：精确计算，包含列引用
- **源表**：数据来源
- **注意事项**：边缘情况、排除项、陷阱

### 实体文档

- **实体名称**：其名称
- **定义**：业务中它代表什么
- **主表**：在哪里找到该实体
- **ID 字段**：如何识别它
- **关系**：如何与其他实体关联
- **常见过滤**：标准排除（内部、测试等）

- [ ] 每个领域至少 2-3 个示例查询
- [ ] SQL 使用正确的方言语法
- [ ] 参考文件从 SKILL.md 导航部分链接
