# 拨打前准备

通过整合 Common Room 中的账户研究、联系人研究和信号合成，生成一份完整、可扫描的拨打前准备简报。

## 准备流程

### 第一步：识别账户和参会人员

解析用户提供的以下信息：
- **公司名称** — 必须提供；在 Common Room 中查找该账户
- **参会人员姓名** — 可选；如果提供，研究每一个

**日历查询：** 如果有 `~~calendar` 连接器可用，搜索与指定公司即将举行的会议，以自动提取参会人员姓名、会议时间以及任何会议笔记或议程。使用此方法填补用户未提供的信息。

如果既找不到参会人员，也找不到日历匹配项，请询问：“[公司] 将有谁参加会议？我可以研究每个参会人员，使您的准备更有效。”

### 第二步：运行账户研究

使用账户研究技能流程构建完整的账户快照。对于拨打前准备，优先考虑：
- 近期产品信号（他们目前在产品中做什么？）
- 开放的机会或续订时间表
- 任何风险信号（使用率下降、支持工单、流失座位）
- 关键近期事件（融资、高管变动、新员工加入）

在查看活动历史记录时，优先考虑 Gong 和通话录音活动——这些提供了关于先前对话的直接背景信息。不要按活动来源过滤通话录音。

### 第三步：为每个参会人员运行联系人研究

对于每个外部参会人员，使用联系人研究技能流程。对于拨打前准备，重点关注：
- 在购买过程中所扮演的角色和影响力
- 他们的个人活动和参与历史
- 任何表明其当前情绪/优先级的近期信号
- 如果可用，Spark 人格分类

### 第四步：综合谈话要点和目标

根据整合的账户和联系人研究：
- 确定会议**目标**（例如，发现、演示、扩展对话、续订、QBR）
- 生成 3–5 个基于特定信号数据的**定制化谈话要点**
- 预测客户可能提出的**2–3 个可能异议或话题**
- 建议会议的**推荐结果**

当用户的公司背景信息可用时（见 `references/my-company-context.md`），根据用户的产品和价值主张调整谈话要点。

### 第五步：近期检查（网络搜索）

在收集所有 Common Room 数据后，运行快速近期检查，以捕获自上次 CR 数据同步以来发生的事情。这是补充性的——CR 数据驱动准备；网络搜索仅用于补充近期信息。

**公司新闻：** 搜索 `"[公司名称]" news` 并过滤到过去 14 天。寻找融资公告、产品发布、领导层变动、裁员、合作伙伴关系或新闻报道。

**参会人员动态：** 对于每个外部参会人员，搜索 `"[完整姓名]" "[公司名称]"` — 寻找近期文章、领英帖子、会议演讲、播客或已发表的评论。

如果公司新闻项目很重要（例如，刚刚完成融资、宣布重大人事任命），请在信号突出显示中标记它。否则，简要包含发现——不要让网络搜索结果掩盖 CR 信号。

## 输出格式

输出格式根据 Common Room 返回的数据量进行调整。仅包含有实际数据的部分。切勿用编造的细节填充部分。

### 当数据丰富（返回多个字段组、活动历史记录、评分、信号）：

```
## 拨打前准备：[公司] — [日期/时间（如果知道）]

**会议背景**
[参会人员、会议类型以及任何已知的议程]

---

### 公司快照
[4–6 个要点：关键账户状态、信号和近期活动]

---

### 参会人员简介

**[参会人员姓名] — [职务]**
[3–4 个要点：角色、近期活动、如果可用 Spark 人格分类、个人钩子]

[重复每个参会人员]

---

### 信号突出显示
[与本次特定会议最相关的 3 个信号]

---

### 谈话要点
1. [与特定信号相关的要点]
2. [与特定信号相关的要点]
3. [与特定信号相关的要点]

### 可能的话题/需要准备的异议
- [话题或异议 + 建议的回应]
- [话题或异议 + 建议的回应]

### 推荐的会议结果
[1–2 句话：这次会议成功的标准]
```

### 当数据稀疏（返回字段少、无活动、null sparkSummary）：

```
## 拨打前准备：[公司] — [日期/时间（如果知道）]

**可用数据：** [列出 Common Room 返回的确切内容——例如，“姓名、职务、电子邮件、两个标签。无活动历史记录、无评分、无 Spark 数据。”]

### 我找到的内容
[实际返回的字段，按原样呈现]

### 网络搜索结果
[关于公司和参会人员的发现——或“无显著结果”]

### 建议的下一步
- 如果可用，我可以从 Common Room 拉取 [特定字段组]
- 我可以对 [特定主题] 运行更深入的网络搜索
- 您可能需要直接在 Common Room 中检查 [缺失的内容]
```

不要从稀疏数据中生成完整的拨打前准备简报。简短的诚实输出始终比冗长的编造输出更好。

## 质量标准

- 每个谈话要点都必须基于真实信号——没有通用填充
- 保持简报简洁——应在 5 分钟或更短时间内可读
- 明确标记未知信息——如果参会人员研究薄弱，请说明
- 限制研究时间——不要以牺牲速度为代价过度研究
- **永远不要编造交易背景**——没有编造的提案、竞争对手比较、定价、试用条款或工具调用未返回的异议
