# 合成研究

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅[CONNECTORS.md](../../CONNECTORS.md)。

将来自多个来源的用户研究合成结构化的见解和建议。

## 使用方法

```
/synthesize-research $ARGUMENTS
```

## 工作流程

### 1. 汇集研究输入

接受来自以下任意组合的研究：
- **粘贴的文本**：访谈笔记、转录稿、调查回复、反馈
- **上传的文件**：研究文档、电子表格、录音摘要
- **~~知识库**（如果已连接）：搜索研究文档、访谈笔记、调查结果
- **~~用户反馈**（如果已连接）：获取最近的客服工单、功能请求、错误报告
- **~~产品分析**（如果已连接）：获取使用数据、漏斗指标、行为数据
- **~~会议转录**（如果已连接）：获取访谈录音、会议摘要和讨论笔记

询问用户他们拥有什么：
- 研究类型是什么？（访谈、调查、可用性测试、分析、客服工单、销售通话笔记）
- 来源/参与者数量？
- 他们是否在调查特定问题或假设？
- 这项研究将影响哪些决策？

### 2. 处理研究

针对每个来源，提取：
- **关键观察**：用户说了什么、做了什么或经历了什么？
- **引言**：说明重要观点的逐字引言
- **行为**：用户实际做了什么（与他们会说什么不同）
- **痛点**：挫败感、变通方法、未满足的需求
- **积极信号**：哪些工作得很好、令人愉悦的时刻
- **背景**：用户细分、用例、经验水平

### 3. 识别主题和模式

应用主题分析——有关主题分析、亲和图和三角测量技术的详细指导，请参阅下文的**研究合成方法论**。

将观察结果分组为主题，跨参与者统计频率，并评估影响严重程度。注意矛盾和意外之处。

创建优先级矩阵：
- **高频率 + 高影响**：最高优先级发现
- **低频率 + 高影响**：对特定细分市场很重要
- **高频率 + 低影响**：生活质量改进
- **低频率 + 低影响**：记录但降级

### 4. 生成合成结果

生成结构化的研究合成：

#### 研究概述
- 方法论：研究类型、参与者/来源数量
- 研究问题：我们试图了解什么
- 时间范围：研究何时进行

#### 关键发现
针对每个主要发现（目标5-8个）：
- **发现陈述**：一句清晰的话描述见解
- **证据**：支持性引言、数据点或观察结果（注明来源）
- **频率**：多少参与者/来源支持此发现
- **影响**：这对用户体验或业务的影响程度
- **置信度**：高（强证据）、中（暗示性）、低（早期信号）

按优先级（频率 x 影响）排序发现。

#### 用户细分 / 人设
如果研究揭示了不同的用户细分：
- 分段名称和描述
- 关键特征和行为
- 独特的需求和痛点
- 如果有数据，估计规模

#### 机会领域
根据发现，确定机会领域：
- 哪些用户需求未满足或服务不足
- 当前解决方案存在哪些不足
- 哪些新功能将释放价值
- 按潜在影响排序

#### 建议
具体、可操作的建议：
- 要构建、更改或进一步调查的内容
- 与特定发现相关联
- 按影响和可行性排序

#### 开放性问题
研究未回答的问题：
- 理解上的差距
- 需要进一步调查的领域
- 建议的后续研究方法

### 5. 审查和扩展

生成合成结果后：
- 询问是否需要更多细节或不同的表述方式
- 提供生成特定工件：人设文档、机会地图、研究演示文稿
- 为开放性问题提供创建后续研究计划的建议
- 提供草拟产品影响（研究结果应如何影响路线图）的建议

## 研究合成方法论

### 主题分析
定性研究合成的核心方法：

1. **熟悉**：通读所有数据。在编码任何内容之前，了解整体情况。
2. **初始编码**：系统性地处理数据。用描述性代码标记每个观察结果、引言或数据点。编码要慷慨——以后合并比拆分容易。
3. **主题发展**：将相关代码分组为候选主题。主题捕获了与研究问题相关的数据的重要信息。
4. **主题审查**：对照数据检查主题。每个主题是否有足够的证据？主题彼此是否清晰？它们是否讲述了一个连贯的故事？
5. **主题完善**：清晰地定义和命名每个主题。用1-2句话描述每个主题捕获的内容。
6. **报告**：将主题作为发现编写，并提供支持性证据。

### 亲和图
用于分组观察的协作方法：

1. **捕获观察结果**：将每个独立的观察结果、引言或数据点作为单独的笔记
2. **分组**：根据相似性将相关的笔记分组。不要预先定义类别——让数据自行显现。
3. **标记分组**：给每个分组一个描述性名称，以捕捉共同线索
4. **组织分组**：如果出现模式，将分组排列为更高级别的组
5. **识别主题**：分组及其关系揭示了关键主题

**亲和图的技巧**：
- 每个笔记一个观察结果。不要合并多个见解。
- 自由地移动笔记到不同的分组。第一次分组很少是最好的。
- 如果一个分组太大，它可能包含多个主题。将其拆分。
- 异常值很有趣。不要强迫每个观察结果都进入一个分组。
- 分组的过程与输出一样有价值。它建立了共同的理解。

### 三角测量
通过结合多个数据源来加强发现：
- **方法学三角测量**：相同问题，不同方法（访谈 + 调查 + 分析）
- **来源三角测量**：相同方法，不同参与者或细分市场
- **时间三角测量**：同一观察结果在不同时间点

由多个来源和方法支持的发现比单一来源支持的发现强得多。当来源不一致时，这很有趣——它可能揭示了不同的用户细分或背景。

## 访谈笔记分析

### 从访谈笔记中提取见解
针对每个访谈，识别：

**观察结果**：参与者描述做了什么、经历了什么或感觉如何？
- 区分行为（他们做什么）和态度（他们想/感觉什么）
- 注意背景：何时、何地、与谁、多久一次
- 标记变通方法——这是未满足需求的伪装

**直接引言**：有力说明观点的逐字引言
- 好的引言是具体的和生动的，而不是泛泛的
- 归因于参与者类型，而不是姓名："企业管理员，200人团队"而不是"莎拉"
- 引言是证据，而不是发现。发现是你对引言含义的解释。

**行为与陈述偏好**：人们实际做什么往往与他们声称想要做什么不同
- 行为观察比陈述偏好更有力
- 如果参与者说"我想功能X"，但他们的工作流程表明他们从未使用过类似功能，请标记矛盾之处
- 通过实际行为寻找显露的偏好

**强度信号**：这对参与者有多重要？
- 情感语言：挫败感、兴奋、无奈
- 频率：他们多久遇到这个问题
- 变通方法：他们为解决问题付出了多少努力
- 影响：当事情出错时后果是什么

### 跨访谈分析
处理完单个访谈后：
- 寻找模式：哪些观察结果出现在多个参与者中？
- 注意频率：多少参与者提到了每个主题？
- 识别细分市场：不同类型的用户是否有不同的模式？
- 揭示矛盾：参与者在哪里意见不一致？这通常揭示了有意义的细分市场。
- 发现惊喜：什么挑战了你的先入为主的观念？

## 调查数据解读

### 定量调查分析
- **回复率**：样本有多具代表性？回复率低可能引入偏差。
- **分布**：查看回复的形状，而不仅仅是平均值。双峰分布（很多1和5）与正态分布（很多3）讲述不同的故事。
- **细分**：按用户细分拆分回复。汇总可能掩盖重要差异。
- **统计显著性**：对于小样本，对从微小差异中得出结论要谨慎。
- **基准比较**：分数与行业基准或以前的调查相比如何？

### 开放式调查回复分析
- 将开放式回复视为迷你访谈笔记
- 用主题对每个回复进行编码
- 统计回复中主题的频率
- 为每个主题提取代表性引言
- 寻找在开放式回复中出现但在结构化问题中未出现的主题——这些是你没有想到要问的问题

### 常见调查分析错误
- 报告平均值而不报告分布。3.5的平均值可能意味着每个人都冷淡，或者一半喜欢一半讨厌。
- 忽略未回复偏差。未回复的人可能系统地不同。
- 过度解释微小差异。NPS的0.1点变化是噪音，不是信号。
- 将李克特量表视为区间数据。 "非常同意"和"同意"之间的差异不一定与"同意"和"中立"之间的差异相同。
- 在交叉分类中混淆相关性与因果关系。

## 结合定性和定量见解

### 定量-定性反馈循环
- **定性优先**：访谈和观察揭示发生了什么以及为什么。它们产生假设。
- **定量验证**：调查和分析揭示多少和多少。它们在大规模上测试假设。
- **定性深入**：返回定性方法以了解意外的定量发现。

### 整合策略
- 用定量数据优先考虑定性发现。来自访谈的主题如果使用数据表明它影响许多用户，则更重要。
- 用定性数据解释定量异常。保留率下降是一个数字；访谈表明这是由于一项令人困惑的入门更改。
- 展示综合证据："47%的受访者报告X有困难（调查），访谈显示这是因为Y（定性发现）。"

### 当来源不一致时
- 定量和定性来源可能讲述不同的故事。这是信号，不是错误。
- 检查分歧是否是由于测量了不同的人群
- 检查陈述偏好（调查）是否与实际行为（分析）不同
- 检查定量问题是否捕捉到了你认为它捕捉到的东西
- 坦诚地报告分歧并进一步调查，而不是选择一个来源

## 从研究中发展人设

### 构建基于证据的人设
人设应从研究数据中产生，而不是想象：

1. **识别行为模式**：寻找参与者中行为、目标和背景相似的集群
2. **定义区分变量**：什么维度区分一个集群与另一个集群？（例如，公司规模、技术技能、使用频率、主要用例）
3. **创建人设档案**：针对每个行为集群：
   - 名称和简要描述
   - 关键行为和目标
   - 痛点和需求
   - 背景（角色、公司、使用的工具）
   - 代表性引言
4. **用数据验证**：能否用定量数据确定每个人设细分市场？

### 人设模板
```
[人设名称] — [一句话描述]

他们是谁：
- 角色、公司类型/规模、经验水平
- 如何找到/开始使用产品

他们试图完成什么：
- 主要目标和要完成的任务
- 如何衡量成功

他们如何使用产品：
- 使用频率和深度
- 关键工作流程和使用的功能
- 与此产品一起使用的其他工具

关键痛点：
- 顶级3个挫败感或未满足的需求
- 他们已经开发的变通方法

他们重视什么：
- 在解决方案中最重要的是什么
- 什么会让他们转换或流失

代表性引言：
- 2-3句逐字引言，捕捉此人设的视角
```

### 常见人设错误
- 人口统计人设：按年龄/性别/地点定义，而不是行为。行为比人口统计更能预测产品需求。
- 人设太多：3-5个是甜点。超过5个则无法行动。
- 想象人设：基于假设而不是研究数据虚构的人设。
- 静态人设：产品和市场演变时从未更新的人设。
- 没有影响的人设：没有人设改变产品决策则没有用。

## 机会规模

### 估计机会规模
针对每个研究发现或机会领域，估计：

- **可服务用户**：多少用户可以从解决中获得利益？使用产品分析、调查数据或市场数据估计。
- **频率**：受影响的用户多久遇到这个问题？（每天、每周、每月、一次性）
- **严重程度**：这个问题发生时对用户的影响程度？（阻断、显著摩擦、轻微烦恼）
- **支付意愿**：解决此问题是否会推动升级、保留或新客户获取？

### 机会评分
在简单的矩阵上评分机会：

- **影响**： (受影响的用户) x (频率) x (严重程度) = 影响分数
- **证据强度**：我们对发现的信心如何？（多个来源 > 单一来源，行为数据 > 陈述偏好）
- **战略一致性**：这个机会是否与公司战略和产品愿景一致？
- **可行性**：我们能否现实地解决？（技术可行性、资源可用性、影响时间）

### 呈现机会规模
- 坦诚地说明假设和置信度
- 显示计算过程："基于支持工单量，每月大约有2,000名用户遇到此问题。访谈显示，其中60%的人认为这是一个重大阻断。"
- 使用范围而不是虚假精度："此问题每月影响1,500-2,500名用户"而不是"此问题影响2,137名用户每月"
- 比较机会以创建相对排名，而不仅仅是绝对分数

## 输出格式

使用清晰的标题和结构化格式。每个发现应独立存在——读者应该能够阅读任何单个发现并理解它，而无需阅读其余部分。

## 建议

- 让数据说话。不要将发现强行纳入预定的叙述。
- 区分用户说什么和做什么。行为数据比陈述偏好更有力。
- 引用是强有力的证据。慷慨地包含它们，并归因于参与者类型（而不是姓名）。
- 明确说明置信度。来自2个访谈的发现是假设，而不是结论。
- 数据中的矛盾是有趣的，而不是不方便。它们通常揭示了不同的用户细分市场。
- 建议应该是具体的，可以采取行动。"改进入门"是不可操作的。"在设置流程中添加进度指示器"是。
- 抵制将太多主题合成的诱惑。5-8个强发现比20个弱发现更好。
