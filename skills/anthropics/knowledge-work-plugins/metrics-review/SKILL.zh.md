# 指标审查

> 如果你看到不熟悉的占位符或需要检查哪些工具已连接，请参阅[CONNECTORS.md](../../CONNECTORS.md)。

审查和分析产品指标，识别趋势，并发现可采取的见解。

## 使用方法

```
/metrics-review $ARGUMENTS
```

## 工作流程

### 1. 收集指标数据

如果**~~产品分析~~**已连接：
- 提取相关时间段的关键产品指标
- 获取比较数据（上一周期、去年同期、目标）
- 如果可用，提取细分数据

如果没有连接分析工具，请要求用户提供：
- 指标及其值（粘贴表格、截图或描述）
- 比较数据（上一周期、目标）
- 有关近期变化的任何背景信息（发布、事件、季节性）

询问用户：
- 要审查哪个时间段？（上周、上个月、上季度）
- 要关注哪些指标？或者我们应该审查完整的产品指标套件？
- 有哪些特定的目标或目标要与之比较？
- 有任何已知事件可能解释变化（发布、停机、营销活动、季节性）？

### 2. 组织指标

使用指标层次结构来组织审查：北星指标位于顶部，L1 健康指标（获取、激活、参与、留存、收入、满意度），以及用于下钻的 L2 诊断指标。有关完整定义，请参阅下方的**产品指标层次结构**。

如果用户尚未定义其指标层次结构，请在继续之前帮助他们确定其北星和关键 L1 指标。

### 3. 分析趋势

针对每个关键指标：
- **当前值**：该指标今天是什么？
- **趋势**：与上一周期相比是上升、下降还是持平？时间范围是多少？
- **与目标比较**：它与目标或目标相比如何？
- **变化率**：趋势是加速还是减速？
- **异常值**：有任何突然变化、峰值或下降吗？

识别相关性：
- 一个指标的变化是否与另一个指标的变化相关？
- 是否有领先指标可以预测滞后指标的变化？
- 细分数据是否显示聚合趋势是由特定群体驱动的？

### 4. 生成审查报告

#### 摘要
2-3 句话：整体产品健康状况、最显著的变化、关键要点。

#### 指标记分卡
表格格式，便于快速扫描：

| 指标 | 当前值 | 上一周期 | 变化 | 目标 | 状态 |
|------|---------|----------|--------|--------|--------|
| [指标] | [值] | [值] | [+/- %] | [目标] | [按计划进行 / 存在风险 / 未达标] |

#### 趋势分析
针对每个值得讨论的指标：
- 发生了什么以及变化有多显著
- 为什么它可能发生（基于已知事件、相关指标、细分分析的归因）
- 这是一次性事件还是持续趋势

#### 亮点
进展顺利的地方：
- 超过目标的指标
- 值得持续的正向趋势
- 表现强劲的细分数据或功能

#### 关注领域
需要关注的方面：
- 未达标或呈负趋势的指标
- 在问题变成麻烦之前出现的早期预警信号
- 我们缺乏可见性或理解的指标

#### 推荐行动
基于分析的下一步具体措施：
- 要进行的调查（深入调查令人担忧的趋势）
- 要启动的实验（测试可能改善指标假设）
- 要进行的投资（加倍投入正在起作用的事情）
- 要设置的警报（更密切地监控指标）

#### 背景和注意事项
- 已知的数据质量问题
- 影响可比性的事件（停机、假期、发布）
- 我们应该跟踪但尚未跟踪的指标

### 5. 跟进

生成审查报告后：
- 询问是否需要更深入地调查任何指标
- 提供创建持续监控的仪表板规范
- 提供关注领域的实验提案草稿
- 提供设置指标审查模板以供重复使用的方案

## 产品指标层次结构

### 北星指标
最能捕捉产品为用户带来的核心价值的单一指标。它应该是：

- **价值对齐**：当用户从产品中获得更多价值时，该指标会变化
- **领先**：预测长期业务成功（收入、留存）
- **可行动**：产品团队可以通过他们的工作影响它
- **易于理解**：公司里的每个人都能理解它的含义及其重要性

**按产品类型举例**：
- 协作工具：每周有 3 名以上成员贡献的活跃团队
- 交易市场：每周完成的交易
- SaaS 平台：每周完成核心工作流的活跃用户
- 内容平台：每周参与阅读/观看时间
- 开发者工具：每周使用该工具的部署次数

### L1 指标（健康指标）
共同描绘完整产品健康状况的 5-7 个指标。这些指标映射到用户生命周期的关键阶段：

**获取**：新用户是否在寻找产品？
- 新注册或试用开始（数量和趋势）
- 注册转化率（访客到注册）
- 渠道组合（新用户来自哪里）
- 获取成本（对于付费渠道）

**激活**：新用户是否达到价值时刻？
- 激活率：完成预测留存的关键动作的新用户百分比
- 激活时间：从注册到激活需要多长时间
- 在线配置完成率：完成在线引导步骤的百分比
- 首次价值时刻：用户首次体验核心产品价值的时间

**参与**：活跃用户是否在获得价值？
- DAU / WAU / MAU：不同时间段的活跃用户
- DAU/MAU 比率（粘性）：每月用户中有多少比例每天回来
- 核心动作频率：用户执行最重要的事情的频率
- 会话深度：用户每次会话执行多少操作
- 功能采用率：使用关键功能的用户百分比

**留存**：用户是否回来？
- D1、D7、D30 留存率：1 天、7 天、30 天后返回的用户百分比
- 群组留存曲线：每个注册群组的留存如何演变
- 退订率：每个周期失去的用户或收入百分比
- 复活率：退订用户中重新回来的百分比

**变现**：价值是否转化为收入？
- 转化率：免费到付费（对于免费增值模式）
- MRR / ARR：月度或年度经常性收入
- ARPU / ARPA：每个用户或账户的平均收入
- 扩张收入：来自现有客户的收入增长
- 净收入留存率：包括扩张和收缩的收入留存

**满意度**：用户对产品的感受如何？
- NPS：净推荐值
- CSAT：客户满意度分数
- 支持工单数量和解决时间
- 应用商店评分和评论情绪

### L2 指标（诊断）
用于调查 L1 指标变化的详细指标：

- 每个步骤的漏斗转化率
- 功能级使用率和采用率
- 特定细分数据的分解（按计划、公司规模、地理位置、用户角色）
- 性能指标（页面加载时间、错误率、API 延迟）
- 内容特定参与度（哪些功能、页面或内容类型驱动参与度）

## 常见产品指标

### DAU / WAU / MAU
**衡量内容**：在一天、一周或一个月内执行合格动作的唯一用户。

**关键决策**：
- 什么算是“活跃”？登录？页面浏览？核心动作？仔细定义——不同的定义会讲述不同的故事。
- 哪个时间段最重要？DAU 对于日常使用产品（消息、电子邮件）。WAU 对于每周使用产品（项目管理）。MAU 对于不太频繁使用的产品（税务软件、旅行预订）。

**如何使用它们**：
- DAU/MAU 比率（粘性）：值高于 0.5 表示有日常习惯。低于 0.2 表示使用频率低。
- 趋势比绝对数字更重要。活跃使用是在增长、持平还是下降？
- 按用户类型细分。权力用户和休闲用户的行为差异很大。

### 留存率
**衡量内容**：在 X 期间开始使用的用户中，有多少百分比在 Y 期间仍然活跃？

**常见的留存时间段**：
- D1（次日）：首次体验是否足够好以至于回来？
- D7（一周）：用户是否建立了习惯？
- D30（一个月）：用户是否长期留存？
- D90（三个月）：这是一个耐用的用户吗？

**如何使用留存率**：
- 按群组绘制留存曲线。寻找：初始流失（激活问题）、稳定下降（参与问题）或扁平化（良好——你有一个稳定的留存基础）。
- 比较随时间变化的群组。较新的群组留存率是否优于较旧的群组？这意味着产品改进正在起作用。
- 按激活行为细分留存率。完成在线引导的用户与未完成在线引导的用户。使用功能 X 的用户与未使用功能 X 的用户。

### 转化率
**衡量内容**：从一个阶段移动到下一个阶段的用户百分比。

**常见的转化漏斗**：
- 访客到注册
- 注册到激活（核心价值时刻）
- 免费到付费（试用转化）
- 试用到付费订阅
- 月度到年度计划

**如何使用转化率**：
- 绘制完整漏斗并测量每个步骤的转化率
- 确定最大的流失点——这是你最高杠杆的改进机会
- 按来源、计划、用户类型细分转化率。不同细分用户的转化差异很大。
- 跟踪随时间的转化率。随着你对体验进行迭代，转化率是否在改善？

### 激活
**衡量内容**：完成新用户首次体验产品核心价值百分比的指标。

**定义激活**：
- 查看留存用户与退订用户。留存用户执行了哪些退订用户没有执行的动作？
- 激活事件应强烈预测长期留存
- 它应在会话内或几天内可实现
- 示例：创建第一个项目、邀请队友、完成第一个工作流、连接集成

**如何使用激活**：
- 跟踪每个注册群组的激活率
- 测量激活时间——越快越好
- 构建引导用户到激活时刻的在线引导流程
- A/B 测试激活流程，并测量对留存的影响，而不仅仅是激活率

## 目标设定框架

### OKRs（目标与关键成果）

**目标**：描述你想实现什么的定性、有抱负的目标。
- 令人鼓舞且难忘
- 有时间限制（季度或年度）
- 方向性，而不是指标特定

**关键成果**：告诉你是否实现目标的定量指标。
- 具体且可衡量
- 有时间限制，有明确目标
- 基于结果，而不是基于产出
- 每个目标 2-4 个关键成果

**示例**：
```
目标：使我们的产品成为日常工作流程不可或缺的一部分

关键成果：
- 将 DAU/MAU 比率从 0.35 提高到 0.50
- 将新用户的 D30 留存率从 40% 提高到 55%
- 3 个核心工作流的任务完成率 >80%
```

### OKR 最佳实践
- 设定既雄心勃勃又可实现的目标。70% 的完成率是拉伸目标的目标。
- 关键成果应衡量结果（用户行为、业务结果），而不是产出（已发布的功能、已完成的任务）。
- 不要设置太多 OKR。每个目标 2-3 个，每个 KR 2-4 个就足够了。
- OKR 应该令人不安。如果你确信会达成所有目标，它们就不够雄心勃勃。
- 在中期审查 OKR。如果某些 KR 显然偏离轨道，请调整资源分配。
- 在期末诚实地评定 OKR。0.0-0.3 = 未达标，0.4-0.6 = 有进展，0.7-1.0 = 已实现。

### 设置指标目标
- **基线**：当前值是多少？在设置目标之前，你需要一个可靠基线。
- **基准**：可比产品实现了什么？行业基准提供了背景。
- **轨迹**：当前趋势如何？如果指标已经在每月 5% 的速度改善，6% 的目标就不够雄心勃勃。
- **投入**：你在这背后投入了多少资源？更大的赌注值得更雄心勃勃的目标。
- **信心**：你对达成目标有多自信？设置“承诺”（高信心）和“拉伸”（雄心勃勃）。

## 指标审查节奏

### 每周指标检查
**目的**：快速发现问题、监控实验、了解产品健康状况。
**持续时间**：15-30 分钟。
**参与者**：产品经理，可能还有工程负责人。

**要审查的内容**：
- 北星指标：当前值，周环比变化
- 关键 L1 指标：任何显著变化
- 活跃实验：结果和统计显著性
- 异常值：任何意外的峰值或下降
- 警报：任何触发监控警报的内容

**行动**：如果看起来不对劲，进行调查。否则，记录下来并继续。

### 每月指标审查
**目的**：对趋势进行更深入的分析、与目标保持一致、战略影响。
**持续时间**：30-60 分钟。
**参与者**：产品团队、关键利益相关者。

**要审查的内容**：
- 带有月环比趋势的完整 L1 指标记分卡
- 对季度 OKR 目标的进展
- 群组分析：较新的群组表现是否更好？
- 功能采用率：最近发布的功能表现如何？
- 细分分析：用户群组之间是否存在差异？

**行动**：确定 1-3 个要调查或投资领域。如果指标揭示了新信息，请更新优先级。

### 季度业务审查
**目的**：战略评估产品绩效、为下一季度设定目标。
**持续时间**：60-90 分钟。
**参与者**：产品、工程、设计、领导层。

**要审查的内容**：
- 季度 OKR 评分
- 季度 L1 指标趋势分析
- 年度比较
- 竞争背景：市场变化和竞争对手动向
- 哪些有效，哪些无效

**行动**：为下一季度设定 OKR。根据数据显示调整产品战略。

## 仪表板设计原则

### 有效的产品仪表板
一个好的仪表板在一瞥中就能回答“产品表现如何？”的问题。

**原则**：

1. **从问题开始，而不是数据**。这个仪表板支持哪些决策？从决策反向设计。
2. **信息的层次结构**。最重要的指标应该是视觉上最突出的。北星指标在顶部，L1 指标在其次，L2 指标可在下钻时查看。
3. **内容比数字更重要**。没有上下文的数字是无意义的。始终显示：当前值、比较（上一周期、目标、基准）、趋势方向。
4. **较少的指标，更多的见解**。50 个指标的仪表板对谁都没有帮助。专注于 5-10 个最重要的指标。将其他所有内容放在详细报告中。
5. **一致的时间段**。仪表板上的所有指标都使用相同的时间段。混合每日和月度指标会造成混乱。
6. **视觉状态指示器**。使用颜色在瞬间指示健康状况：
   - 绿色：按计划进行或改善
   - 黄色：需要关注或持平
   - 红色：偏离轨道或下降

7. **可操作性**。仪表板上的每个指标都应该是团队可以影响的。如果你不能对其采取行动，它就不应出现在产品仪表板上。

### 仪表板布局

**第一行**：北星指标，带有趋势线和目标。

**第二行**：L1 指标记分卡——每个关键指标的当前值、变化、目标和状态。

**第三行**：关键漏斗或转化指标——显示每个阶段流失的可视化漏斗。

**第四行**：最近的实验和发布——活跃的 A/B 测试、最近发布的功能及其早期指标。

**底部/下钻**：L2 指标、细分数据以及用于调查的详细时间序列。

### 仪表板反模式
- **虚荣指标**：总是上升但不指示健康的指标（总注册数、总页面浏览量）
- **太多指标**：需要滚动才能查看的仪表板。如果它不适合一个屏幕，请删除指标。
- **没有比较**：没有上下文的原始数字（当前值没有上一周期或目标）
- **过时的仪表板**：几个月没有更新或审查的指标
- **产出仪表板**：衡量团队活动（关闭工单、合并 PR）而不是用户和业务成果
- **所有受众的单一仪表板**：高管、PM 和工程师需要不同的视图。尺码不合适。

### 报警
为需要立即关注的指标设置报警：

- **阈值报警**：指标低于或高于临界阈值（错误率 > 1%，转化率 < 5%）
- **趋势报警**：指标在多天/多周内持续下降
- **异常报警**：指标显著偏离预期范围

**报警维护**：
- 每个报警都应该是可操作的。如果你无法处理它，就不要报警。
- 定期审查和调整报警。过多的误报会导致人们忽略所有报警。
- 为每个报警定义负责人。当报警触发时，谁会响应？
- 设置适当的严重程度级别。并非所有事情都是P0。

## 输出格式

使用表格制作评分卡。使用清晰的状况指示器。保持摘要简洁——读者应在30秒内获取核心信息。

## 小贴士

- 从“那么有什么意义”开始——这次指标审查中最重要的东西是什么？先从这里切入。
- 没有背景的绝对数字是无用的。始终显示比较（与上期比较、与目标比较、与基准比较）。
- 注意归因问题。相关性不等于因果性。如果指标发生了变化，要承认对原因的不确定性。
- 分段分析常常揭示出汇总指标掩盖了重要差异。整体数字平稳可能隐藏着某个分段增长而另一个分段萎缩的情况。
- 并非所有指标变化都重要。小的波动是噪音。将注意力集中在有意义的变动上。
- 如果指标未达目标，不要只报告未达标情况——建议如何处理。
- 指标审查应推动决策。如果审查没有至少导致一个行动，它就是没有用的。
