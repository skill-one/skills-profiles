# 产品驱动增长

构建自助获取和扩展的流程。但首先，要确定 PLG（产品驱动增长）是否真的适合你的产品。

## 何时使用

**触发点：**
- "我们应该构建 PLG 还是销售驱动？"
- "我们如何推动自助获取的采用？"
- "免费增值到付费的转换效果不佳"
- "开发者驱动的采用策略"
- "我们应该投资哪些增长渠道？"
- "我如何知道 PLG 是否有效？"

**背景：**
- 开发者工具和平台
- 具有自助获取潜力的 B2B SaaS
- 价值无需演示就能明显的产品
- 自下而上的采用流程
- 增长渠道优先级排序

---

## 核心框架

### 1. PLG 现实检验（在投入之前进行测试）

**并行运行两种流程的教训：**

经典的创业争论。PLG 派：开发者想要自助服务。销售派：企业需要手把手指导。与其争论，我们测试了两种流程 6 个月。相同的产品，两种 GTM（市场进入）流程，跟踪了所有数据。

**结果：**

PLG：高销量，低 ACV（平均客户价值，约 $5K），快速实现收入，更高的客户流失率。销售驱动：低销量，高 ACV（约 $50K），较慢的收入实现速度，较低的客户流失率。**尽管销量只有 PLG 的十分之一，销售在收入上赢了 10 倍。**

**原因：** 产品复杂性 + 买方资历 = 销售驱动获胜。该产品需要与现有基础设施集成，跨团队进行变更管理，以及多利益相关者的协调。开发者喜欢自助服务。但他们不是经济买方。

**PLG 在以下情况下有效：**
- 价值在 5 分钟内就明显
- 实施非常简单
- 个人用户无需团队认可就能获得价值
- 无采购/法律障碍
- 买方 = 用户

**销售驱动在以下情况下有效：**
- 产品需要集成/设置
- 多个利益相关者需要协调
- 买方 ≠ 用户
- 交易规模证明需要人工服务
- 客户需要教育才能看到价值

**在构建 PLG 之前，测试你的流程。不要假设 PLG 更好，因为它很时髦。** PLG 在销量上很高效，但销售驱动在复杂性上可以更盈利。

### 2. 增长公式（将输入映射到输出）

**模式：**

当系统化活动与用户获取之间的关系时，增长会复合。不是“做更多营销”——而是将特定的输入映射到可衡量的输出。

**如何构建你的增长公式：**

对于每个渠道，定义：活动（输入）→ 流量（输出）→ 转化。

- **自然搜索：** 1 篇高质量博客文章 → 每月 400 用户 → 5% 转化 = 20 个新用户
- **付费广告：** 在 100K 次展示中，以 8% 的转化率花费 $1K = 8K 点击 → 转化率在 X%
- **社区活动：** 1 次活动 → 60 名参与者 → 35% 转化 = 21 个用户
- **推荐：** 1 个集成合作伙伴 → N 个推荐用户 → 转化率在 Y%

**为什么这很重要：**

一旦你验证了公式，扩展就变成了数学问题。“下个月我需要 200 个更多用户” → “我需要 10 篇更多博客文章”或“我需要额外的 $5K 广告支出”。没有公式，你就是在猜测。

**测试公式：**

1. 从假设开始：如果创建 X，它将推动 Y 的转化率
2. 用小样本测试：1 篇博客文章，测量实际转化率
3. 验证：现实是否与假设相符？
4. 有信心扩展：如果是，增加输入
5. 如果不行，放弃：4 周的数据足以做出决定

**常见错误：**

在未测试的情况下猜测转化率。假设来自同一渠道的所有用户质量相同。在验证公式之前扩展。

### 3. 渠道经济（淘汰失败者，加倍投入成功者）

**模式：**

每个渠道都有其经济性。如果不跟踪它们，你会过度投资失败者，而低估成功者。

**按渠道跟踪：**
1. **CAC：** 总支出 / 新用户
2. **转化率：** 注册 → 付费
3. **留存率：** 30 天，90 天按来源
4. **LTV：** 客户生命周期中的收入，按渠道
5. **回收期：** 需要多长时间才能收回 CAC

**决策框架：**

- CAC < (LTV × 利润率) → 积极扩展
- CAC ≈ (LTV × 利润率) → 优化，不要扩展
- CAC > (LTV × 利润率) → 4 周内淘汰

**每月渠道审查：** 哪些渠道是盈利的？哪些是消耗的？季度重新分配：将 3 倍预算分配给成功者，淘汰失败者。

**关键洞察：渠道质量不同**

低 CAC 不代表好 CAC。自然搜索可能以 $0 CAC 提供用户，30 天留存率为 85%。付费搜索可能以 $12 CAC 提供用户，30 天留存率为 45%。当考虑留存率和 LTV 时，“免费”渠道的价值是 10 倍。

**系统化测试：**

每月测试 2 个新渠道。给每个渠道 4 周的数据。如果经济性不工作，果断淘汰。无论结果如何，都要记录学习经验——失败的经验与成功一样有价值。

**常见错误：**

跟踪 CAC 而不考虑留存率。一个便宜但流失用户的渠道比一个昂贵但留存用户的渠道成本更高。

### 4. 首次价值时间（唯一激活指标）

**模式：**

用户在 5-10 分钟内决定产品价值。如果他们不能快速达到 aha 时刻，他们就会放弃。

**激活审查：**

1. 以新用户身份注册自己的产品
2. 计算达到首次价值所需的时间
3. 计算达到 aha 时刻的步骤数
4. 你在哪里卡住了？

**如果 TTFV > 10 分钟，你有一个激活问题。**

**之前：** 注册 → 确认电子邮件 → 填写个人资料 → 配置设置 → 阅读文档 → 首次操作

**之后：** 注册 → 预加载示例数据 → 首次操作（立即的 aha 时刻）

**具体修复措施：**

1. **预加载示例数据。** 用户想要看到价值，而不是设置。立即给他们一个可工作的示例。
2. **跳过非必要的设置。** 电子邮件确认、个人资料、设置——所有这些都可以在 aha 时刻之后进行。
3. **渐进式披露。** 不要一开始就展示所有功能。从一个核心工作流程开始。逐渐揭示复杂性。
4. **展示，而不是告诉。** 交互式教程 > 视频 > 文本文档。让他们点击一个工作流程。

**常见错误：**

假设用户会阅读文档。他们不会。他们会点击 5 分钟，如果什么都不工作，他们就会离开。

### 5. $5K → $50K 转折（PLG 失效时）

**模式：**

PLG 适用于 $1K-$10K ARR。在 $20K-$50K 之间，流程会失效，因为组织摩擦开始：采购、法律、安全、多利益相关者的认可。

**混合方法：**

**PLG ($0-$10K)：** 自助注册 → 免费层 → 付费层 → 信用卡结账 → 自动化入职

**销售辅助 ($10K-$50K)：** 自助发现 → 销售在使用信号上参与 → 人工协商合同 → 专属入职

**企业 ($50K+)：** 外出或传入线索 → 演示 → POC → 报价 → 法律/安全审查 → 高管支持

**PQL 信号（何时触发销售）：**

- **使用深度：** 每日活跃，核心功能使用，接近限制
- **扩展信号：** 来自同一公司的多个用户，团队功能，集成
- **购买信号：** 请求 SSO/合规/SLA，询问团队定价

**交接：**

差： "嘿，我看到了你注册了。"（冷，通用，破坏信任）
好："你的团队正在使用 [特定功能] 跨越 12 个仓库。我们可以帮助你 [特定价值]。想要 15 分钟？"（热，具体，提供价值）

**常见错误：**

在 <$5K 交易上过早参与销售。破坏 PLG 流程，吓跑用户。让他们自助服务，直到他们需要帮助。

### 6. 增长预测（为不确定性做计划）

**模式：**

预测总是错误的。计划仍然有价值，因为它们迫使思考并创造责任感。

**建立三种场景：**

**基线（当前趋势继续）：**
- 自然搜索：35% 增长 → 40K 新用户
- 付费：持平 → 2K 新用户
- 社区：10% 增长 → 400 新用户
- 总计：42.4K

**上行（如果所有增长计划执行）：**
- 自然：50% 增长（3 倍内容）→ 48K
- 付费：2 倍支出，相同效率 → 4K
- 新计划（合作伙伴关系）：加速 → 3K
- 总计：55K

**下行（如果关键渠道失败）：**
- 自然：0% 增长 → 26K
- 付费：CPA 加倍 → 1K
- 总计：27K

**使用此进行：**
- 设置基线目标（基线场景）
- 拉伸目标（上行场景）
- 升级触发器（如果遇到下行，需要改变）
- 资源分配（什么输入改变以实现上行？）

**每月更新：** 比较预测与实际。调整模型。不要预测后忘记。

**常见错误：**

过于乐观的预测，假设一切都会成功。不每月更新。将预测视为目标（它是一个范围，而不是一个数字）。

---

### 7. 演示文稿文档习惯

**模式：**

知识会随人流失。目标不是一次性成功——而是系统化有效的方法。

**每次成功的活动或实验后，编写 1 页演示文稿：**

```
演示文稿：[渠道/策略名称]

目标：[结果]
步骤：[编号，足够详细，供不熟悉的人执行]
预期输出：[具体指标]
要跟踪的指标：[如何衡量]
风险和缓解措施：[可能出什么问题]
负责人：[姓名]
最后更新：[日期]
```

**测试：** 没有参与的人能否执行这个演示文稿？如果不能，它太模糊了。

**每季度审查。** 删除不再有效的演示文稿。更新已经演变的演示文稿。这将成为你的增长操作系统。

**常见错误：**

运行实验而不记录学习经验。在理解机制之前扩展。增长知识被一个人困住。

## 决策树

### 我们应该构建 PLG 还是销售驱动？

```
用户在 <10 分钟内能否在没有文档的情况下获得价值？
├─ 否 → 需要销售驱动
└─ 是 → 他们能否自助实施？
    ├─ 否 → 需要销售驱动
    └─ 是 → 买方 = 用户？
        ├─ 否 → 混合（PLG + 销售辅助）
        └─ 是 → 纯 PLG 可行
```

### 保留、扩展或淘汰这个渠道？

```
CAC < (LTV × 利润率)？
├─ 否 → 4 周内淘汰
└─ 是 → 90 天留存率 > 60%？
    ├─ 否 → 优化（改进激活/入职）
    └─ 是 → 积极扩展（3 倍预算）
```

## 常见错误

**1. 假设 PLG 总是有效**
产品复杂性 + 买方资历 = 销售驱动获胜。测试后再投入。

**2. 没有渠道经济**
每个渠道都有 CAC、留存率和 LTV。跟踪它们，否则你是在盲目飞行。

**3. 免费层太慷慨或太有限**
太慷慨：没有转化。太有限：没有激活。允许 10-20 个 aha 时刻。

**4. 没有增长公式**
"做更多营销"不是一个策略。将输入 → 输出 → 每个渠道的转化映射。

**5. 在验证之前扩展**
任何渠道在扩展前都需要 4 周的数据。如果经济性不工作，果断淘汰。

**6. 增长知识在一个人头中**
将每个成功的实验记录为演示文稿。

## 快速参考

**PLG 准备情况：** 价值在 <10 分钟内 + 自助实施 + 买方 = 用户

**增长公式：** 活动（输入）→ 流量（输出）→ 转化，按渠道

**渠道经济：** CAC、转化率、30/90 天留存率、LTV、回收期——按渠道，每月审查

**淘汰标准：** CAC > (LTV × 利润率) → 4 周内改进，然后淘汰

**PQL 信号：** 使用深度 + 扩展（多用户）+ 购买（SSO/合规请求）

**销售交接：** <$10K: PLG → $10K-$50K: 销售辅助 → >$50K: 全销售

**预测：** 基线 + 上行 + 下行，每月更新
