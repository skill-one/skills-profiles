# 技术产品定价

## 初始评估

在推荐定价策略之前，请了解以下信息：

1. **产品类型**：API/平台、开发者工具、SaaS 应用程序、还是基础设施？
2. **当前定价**：目前的收费是多少？这个价格已经维持多久了？
3. **市场进入方式（GTM）**：自助服务、销售辅助、企业级销售，还是混合模式？
4. **成本结构**：每个客户/用户/单位的边际成本是多少？
5. **竞争格局**：替代方案的成本是多少？（包括“不做任何事”的成本）

---

## 核心框架

### 1. 没人察觉的涨价（你很可能定价过低）

**典型模式：**

一家处于增长阶段的平台公司。定价自发布以来从未改变。企业客户每年支付 15,000 美元，购买的产品却为他们节省了 20 万以上的工程时间成本。

领导层辩论：“如果我们提高价格，就会失去客户。”

**实际发生的情况：**

将企业级套餐价格从每年 15,000 美元提高到 45,000 美元。增加了专属支持、单点登录（SSO）和审计日志来为这次大幅涨价提供理由。

失去：0 家企业客户。零。

获得：每个企业账户的收入提高了 3 倍。此外，那些留下来的客户开始更严肃地对待该产品——采用率更高，内部支持者更多，扩张机会更多。

**为什么会这样：**

技术创始人通常以成本为锚点来定价（“服务他们的成本是 X 美元，所以我们收取 2X 美元”）。企业买家则以价值为锚点（“这为我们节省了 20 万美元，所以 45,000 美元很便宜”）。

**定价合理性检查：**

对于每个客户细分群体，请计算：

```
价值比率 = 客户的替代方案成本 / 你的价格

如果价值比率 > 10x → 你的定价严重偏低
如果价值比率 > 5x  → 你的定价偏低（大多数初创公司处于这一区间）
如果价值比率 3-5x  → 定价健康
如果价值比率 < 3x  → 接近天花板
如果价值比率 < 2x  → 你的价格昂贵（需要强大的差异化）
```

**如何计算替代方案成本：**

- 手动流程所花费的小时数 × 每小时费率 × 频率
- 内部构建的成本（工程师人数 × 月数 × 全成本）
- 现有工具的成本 + 转换成本 + 过渡期间的生产力损失
- *不解决该问题*的成本（事故、停机时间、客户流失）

**常见错误：**

将你的价格与竞争对手进行比较，而不是与客户的替代方案成本进行比较。竞争对手会将你锚定在价格战的底线。而价值会将你锚定在客户实际节省的金额上。

### 2. 三种定价模式（以及各自何时失效）

**模式 1：按席位计费（$X/用户/月）**

**适用场景：**
- 价值随用户数量增加而增加（协作工具、通信工具）
- 用户的使用量相对均匀
- 你希望收入可预测

**失效场景：**
- 重度用户和轻度用户价格相同（轻度用户会流失）
- 产品价值不随席位数量扩展（一个管理员为 1,000 名用户配置）
- 客户整合席位以减少成本（使用量上升，但收入未上升）

**模式 2：按用量计费（$X/单位）**

**适用场景：**
- 客户之间的使用量差异巨大（API 调用、计算、存储）
- 边际成本有意义（你需要使用量与收入挂钩）
- 价值与使用量直接相关

**失效场景：**
- 客户无法预测账单（月底出现账单冲击）
- 低用量客户不值得支持
- 高用量客户谈判获得批量折扣，压缩了利润率

**模式 3：基于结果计费（$X/结果）**

**适用场景：**
- 你可以可靠地衡量结果（生成的潜在客户、解决的工单、部署的代码）
- 结果直接为客户创造价值
- 你对产品的有效性有信心

**失效场景：**
- 结果取决于你无法控制的因素
- 测量存在争议（“那个潜在客户不是来自你的工具”）
- 客户为了操控指标而作弊

**通常获胜的混合模式：**

平台费（覆盖你的固定成本） + 用量/结果变量费（随价值扩展）。

示例：每月 500 美元基础费 + 每笔交易 0.05 美元（或每次 API 调用、每个完成的任务、每条处理的记录——即你的价值单位）。

为什么这有效：
- 基础费确保每个客户都能覆盖服务成本
- 可变费使价格与价值保持一致
- 客户可以预测最低支出（基础费），同时自然扩展
- 当客户增长时，你也能获取额外收益

### 3. 免费增值阈值设计（免费在哪里结束，付费在哪里开始）

**典型模式：**

开发者工具中最艰难的定价决策：你在哪里划定免费和付费之间的界限？

**框架：寻找生产边界**

永远不会付费的免费用户是没问题的——他们创造了知名度、社区和内容。问题在于当*生产用户*永远不会付费时。

**如何寻找边界：**

绘制你的使用量分布：

```
使用量水平           |  用户类型        |  支付意愿
─────────────────────────────────────────────────────────────
<100 单位/月         |  爱好者/学习者   |  $0（永不付费）
100-1K 单位/月      |  副项目         |  $0-20/月（可能）
1K-10K 单位/月      |  生产使用       |  $50-200/月（愿意付费）
>10K 单位/月        |  业务关键       |  $200-2K/月（必须付费）
```

**将你的免费套餐限制设置在生产使用量开始前的位置。** 在这个例子中：每月 1,000 个单位免费。

原因：爱好者和学习者保持免费（他们是你的营销引擎）。生产用户会自然地触及限制并转化（他们有预算）。

**三种免费转付费触发器类型：**

**1. 使用量限制**（平台最常见）
- 免费：每月 1,000 个单位（API 调用、任务、记录，即你的价值单位）
- 触发条件：生产使用量超过限制
- 转化信号：用户正在构建真实的东西

**2. 团队/协作门槛**（工具类最佳）
- 免费：个人使用
- 触发条件：用户邀请第二个人
- 转化信号：该工具的价值足以分享

**3. 企业级功能门槛**（平台最佳）
- 免费：核心功能
- 触发条件：需要 SSO、基于角色的访问控制（RBAC）、审计日志、SLA
- 转化信号：IT/安全部门介入（真实部署）

**常见错误：**

将免费套餐设置得过高（“我们希望开发者喜欢我们”）。如果生产用户没有触及限制，他们就不会转化。免费套餐的慷慨应该针对*学习者*，而不是*生产用户*。

### 4. 企业级定价（是一场对话，而不是一个数字）

**典型模式：**

企业级定价不是你网站上的一个页面。它是一场对话。“联系销售”按钮的存在是因为企业交易有独特需求——而且你应该基于价值进行定价，而不是基于菜单价格。

**企业级定价变量：**

**1. 部署模式**（自助云端、专用云端、本地部署、混合部署）
- 每种模式的成本不同 → 不同的价格底线
- 本地部署通常比云端有 2-5 倍的溢价（支持复杂性）

**2. 使用规模**（席位、API 流量、数据量）
- 批量折扣永远不应低于服务成本 + 40% 的利润率
- 折扣应基于列表价，而不是已经打折后的价格

**3. 支持级别**（社区、标准、高级、专属）
- 高级支持：基础价格的 1.5-2 倍
- 专属客户成功经理（CSM）：基础价格的 2-3 倍
- 提供 SLA 的 24/7 支持：基础价格的 3-5 倍

**4. 合规要求**（SOC 2、HIPAA、FedRAMP、数据驻留）
- 每项合规都增加实际成本（审计、基础设施、流程）
- 相应定价：每个合规标准加收 1.5-2 倍基础价格

**企业级定价对话：**

当潜在客户问“多少钱”时：

1. **不要用数字回答。** 用问题回答：“这取决于您的部署和规模要求。请帮我了解您的需求。”

2. **映射他们的需求：**
   - 多少用户/席位/单位？
   - 云端还是本地部署？
   - 合规需求？
   - 支持期望？
   - 集成要求？

3. **在展示价格之前锚定价值：**
   - “根据您描述的情况，您目前在这个问题上花费 [X]。我们的解决方案通常会将此减少 [Y%]。”
   - 然后将价格作为节省金额的一部分来展示。

4. **展示 3 个选项：**
   - 良好：满足最低要求
   - 更好：满足要求 + 锦上添花的需求（在此锚定）
   - 最佳：一切，包括他们没问到的东西
   - 大多数买家会选择“更好”。这是你的真实价格。

**常见错误：**

在企业级定价上公开列出价格。一旦你公布了一个数字，那就是天花板——谈判只会从这里向下走。保持企业级定价作为一种对话。

### 5. 定价作为定位信号

**典型模式：**

你的价格告诉买家你是为谁服务的。这既是一个收入决策，也是一个定位决策。

**价格信号：**

**$0（开源 / 免费套餐）：**
- 信号：我们服务于希望先试后买的开发者
- 吸引：个人贡献者、实验者
- 风险：被认为“未准备好用于企业环境”

**$20-100/月：**
- 信号：我们服务于团队和小型企业
- 吸引：自助服务买家、初创公司
- 风险：企业不会认真对待你（太便宜）

**$500-2,000/月：**
- 信号：我们服务于生产工作负载
- 吸引：拥有真实预算的成长型公司
- 风险：初创公司被排除在外（可能需要免费套餐）

**$5,000-50,000/年：**
- 信号：我们服务于企业
- 吸引：中型市场和企业
- 风险：需要销售团队（在这个价格点无法自助服务）

**$100K+/年：**
- 信号：我们是任务关键型基础设施
- 吸引：大型企业
- 风险：销售周期长，支持期望高

**定位测试：**

如果你定价为每月 50 美元但想要企业客户，你的价格正在削弱你的定位。企业买家将低价与低价值联系起来。你可能需要*提高*价格来吸引你想要的客户。

**常见错误：**

为你现有的客户定价，而不是为你想要的客户定价。如果你的路线图是企业级，就按企业级定价——即使这意味着今天会失去一些中小企业（SMB）客户。

### 6. 何时以及如何涨价

**时机信号：**

- 大多数客户价值比率 > 5x
- 胜率高于 40%（你不是因为价格而输掉交易）
- 过去 6 个月没有客户对定价提出反对
- 客户扩展速度快于预期
- 竞争对手提价且未失去市场份额

**如何涨价而不失去客户：**

**1. 老用户特权（12-24 个月）**
- 新定价仅适用于新客户
- 老用户获得通知 + 时间表
- 为潜在客户创造紧迫感（“价格要涨了”）

**2. 增加价值以证明涨价的合理性**
- 以更高价格推出具有新功能的新层级
- 将当前层级的功能移至更高价的新层级
- 这是重新定位，而不仅仅是涨价

**3. 合同中的年度递增条款**
- 在企业合同中包含 5-10% 的年度递增机制
- 使价格正常化
- 避免“我们四年都付同样的价格”的对话

**沟通方式：**

“我们正在投资于 [具体改进]。为了维持这种投资水平，我们将于 [日期] 更新定价。您当前的计划在您当前费率下锁定至 [老用户特权截止日期]。”

永远不要为涨价道歉。将其框定为对他们喜爱的产品的投资。

## 决策树

### 选择哪种定价模式？

```
使用量在客户之间是否差异 >5 倍？
├─ 是 → 按用量计费（或带有用量分量的混合模式）
└─ 否 → 继续...
    │
    价值是否随团队规模扩展？
    ├─ 是 → 按席位计费
    └─ 否 → 继续...
        │
        你能可靠地衡量客户结果吗？
        ├─ 是 → 基于结果计费（或混合模式）
        └─ 否 → 平台费 + 基于功能的层级
```

### 我们应该涨价吗？

```
大多数客户的价值比率是否 > 5 倍？
├─ 是 → 涨价
└─ 否 → 继续...
    │
    胜率是否 > 40%？
    ├─ 是 → 价格不是问题，但可以考虑涨价
    └─ 否 → 继续...
        │
        你是否专门因价格而输掉交易？
        ├─ 是 → 不要涨价。改进价值或更好地细分客户。
        └─ 否 → 其他方面有问题（产品、定位、销售）
```
