# AI产品GTM

AI产品的市场进入策略。这些不是通用的AI原则——它们是将自主AI代理销售给企业的模式，其中“自主”让购买者感到恐惧，“队友”则将他们转化过来。

## 何时使用

**触发因素：**
- “我们如何定位这个AI产品？”
- “购买者表示他们担心AI会破坏生产”
- “我们应该称之为自主的还是副驾驶？”
- “当客户的使用量相差10倍时，我们如何为AI定价？”
- “企业安全通过了，但运维拒绝了，为什么？”

**背景：**
- AI代理平台（编码、支持、运维）
- 基于LLM的应用
- 会做事情的自主工具（而不仅仅是建议）
- AI基础设施
- 任何AI做决策的地方

## 核心框架

### 1. 企业AI的真实反对意见（它和你想的不一样）

**销售自主AI代理学到的教训：**

三个月后，企业安全审查很快就通过了。这是个好兆头，对吧？然后，一个模式出现了：安全批准了，但**运维拒绝了**我们。

反对意见不是“AI会破坏生产吗？”——他们*假设*它最终会破坏生产。真正的问题是：

**“当代理做错事时，谁负责？”**

不是“我们信任代理吗？”——“我们信任我们的*团队*来处理这件事吗？”

**为什么这很重要：**

自主代理创造了一个新的运营负担。你卖的不是AI能力，而是组织准备情况。当你的代理在凌晨2点停止生产时，谁会被叫醒？谁会修复它？谁会向副总裁解释它？

**框架：责任级联**

在部署AI代理之前，企业需要明确的答案：

1. **L1响应**：谁监控代理？（24/7运维团队，还是呼叫中的开发团队？）
2. **L2升级**：当代理行动失败时，谁调试？（代理团队，还是产品团队？）
3. **L3所有权**：当事情严重出问题时，谁负责客户沟通？

如果你不能回答所有三个问题，**他们就不会购买**。你的AI有多好都不重要。

**这如何改变你的销售流程：**

**旧方法：**
- 演示AI
- 展示准确率指标
- 谈论ROI

**新方法：**
- 演示AI
- 明确展示*失败模式*
- 问：“你们团队中谁会处理这种情况？”
- 演示他们的应急响应流程
- 将AI失败映射到他们现有的运行手册

**资格问题：**

“带我走过当代理采取行动破坏工作流时会发生什么。谁会收到警报？谁会调查？谁会决定回滚还是向前修复？”

如果他们不能回答，他们还没准备好。暂停交易，先帮助他们建立流程。

**常见错误：**

将这视为一个*产品*反对意见（“我们会让AI更准确”）。这是一个*组织*反对意见。更高的准确率不能解决“凌晨2点谁拥有这个？”的问题。

**我看到的成功模式：**

成功使用AI代理的公司已经拥有：
- 生产系统的呼叫轮班
- 事件响应剧本
- 无指责事后分析文化
- 清晰的升级路径

遇到困难的公司：
- 手动部署流程
- 英雄文化（“史蒂夫能解决一切”）
- 没有正式的事件响应
- 指责文化

**决策标准：**

在向企业演示自主AI之前，问问自己：“如果这破坏了他们的生产，他们*团队*中谁负责修复？”如果你不能回答，他们就不能购买。

### 2. 副驾驶 vs 代理 vs 队友（三种不同的GTM策略）

**定位陷阱：**

早期的企业对话中，我们定位为“自主AI代理”。购买者退缩了。一个词的改变——“自主”→“AI队友”——交易进展明显改善。

为什么？**词语选择塑造购买者心理。**

**三种定位：**

**1. 副驾驶（最安全，最低价值）**
- **含义**：AI建议，人类每次都决定
- **购买者心理**：感觉安全，不具威胁性
- **GTM策略**：开发者采用，自下而上
- **用例**：代码补全，写作辅助，搜索
- **反对意见**：“这值得付费吗？”（感知价值低）

**2. 代理（最吓人，最高价值）**
- **含义**：AI自主行动，人类定期审查
- **购买者心理**：吓人，暗示取代人类
- **GTM策略**：企业销售，自上而下
- **用例**：批量处理，自动化工作流，运维
- **反对意见**：“如果它破坏生产怎么办？”（责任恐惧）

**3. 队友（最佳平衡点）**
- **含义**：AI和人类合作，分担工作
- **购买者心理**：合作，不是取代
- **GTM策略**：混合（开发者采用+经理批准）
- **用例**：大多数AI代理平台
- **反对意见**：“我们如何将这集成到我们的工作流中？”（流程问题）

**定位转变：**

**之前**：“端到端处理复杂工作流的自主AI代理”
- 开发者：“酷，但吓人”
- 经理：“这会取代我们的团队吗？”
- 交易进展：缓慢

**之后**：“与您的工程师合作处理复杂任务的AI队友”
- 开发者：“这帮助我”
- 经理：“这使我的团队更有效率”
- 交易进展：四个月停滞的企业交易在转变后的8周内关闭了

**具体影响语言的选择：**

❌ **不要说：**
- “自主”（吓人）
- “取代”（威胁性）
- “完全自动化”（没有控制）
- “AI优先”（那是什么意思？）

✅ **要说：**
- “队友”（合作）
- “增强”或“加速”（帮助，不是取代）
- “您保持控制”（令人安心）
- “处理重复性工作”（具体价值）

**如何选择你的定位：**

```
你的AI是否无需人类批准就做决策？
├─ 是 → 你是在向开发者还是企业销售？
│   ├─ 开发者 → “代理”定位（他们想要自主）
│   └─ 企业 → “队友”定位（他们想要控制）
└─ 否 → “副驾驶”定位（增强，不是自动化）
```

**残酷的真相：**

你可以构建一个代理，但将其定位为副驾驶。你不能构建一个副驾驶，却将其定位为代理。**产品功能设定上限，定位选择在它之下落地。**

**常见错误：**

因为听起来令人印象深刻而使用“自主”。令人印象深刻≠被信任。如果购买者在定位上退缩，你就输了。

### 3. AI定价问题（当使用量相差10倍时）

**模式：**

我工作过的每个AI公司都面临这个问题：客户A每月使用1000个API调用。客户B使用10000个。你是对客户B收取10倍的费用吗？如果是，他们会流失。如果不是，你的利润会崩溃。

**三种模型：**

**1. 基于用户（每用户每月X美元）**
- **何时有效**：AI增强人类工作可预测
- **示例**：代码补全，写作辅助
- **问题**：不能捕捉AI价值扩展
- **真实风险**：高使用量客户是最好的客户，但他们补贴低使用量客户

**2. 基于使用量（每个API调用/预测/小时X美元）**
- **何时有效**：AI做可变工作，客户理解单位
- **示例**：图像生成，转录，批量ML
- **问题**：高使用量客户会感到震惊
- **真实风险**：客户会优化以使用*更少*的产品

**3. 基于结果（每个实现的结果X美元）**
- **何时有效**：你可以可靠地衡量结果
- **示例**：“按修复的bug付费”或“按解决的支持工单付费”
- **问题**：难以衡量，容易作弊
- **真实风险**：如果AI表现不佳，你承担所有风险

**实际上有效（混合）：**

固定费用（覆盖固定成本）+ 可变费用（随价值扩展）。

**示例结构：**
- 固定：每团队每月X美元（平台访问权限）
- 可变：每个成功行动/结果Y美元
- 为什么这有效：
  - 固定覆盖基础设施/支持成本
  - 可变与客户价值一致
  - 高使用量客户不会被惩罚（他们获得更多价值）

**我希望早期就有的定价对话：**

在定价使用型AI时：

**问客户：**
“手动完成这项工作对您来说成本多少？”

如果它成本0.10美元每个API调用，但节省他们2美元的劳动力，你定价过低。如果它成本0.50美元每个调用，但只节省他们0.40美元，他们不会使用足够的量来产生影响。

**定价规则：**

你的可变成本应该是**客户替代成本的20-30%**。足够高以捕捉价值，足够低让他们大量使用。

**常见错误：**

因为“每个人都这样做”而复制OpenAI的定价（每1000个token 0.01美元）。你的成本结构不是OpenAI的成本结构。你的价值不是OpenAI的价值。为*你的*业务定价。

### 4. AI信任阶梯（从有人爬过的人那里）

**模式：**

你不能通过说“信任我们，它有效”来销售AI。你分阶段建立信任。

**首先：透明度（在第一次演示之前）**

在他们询问之前发送这三个文件：
- 模型卡（什么模型，训练在什么上，什么基准的准确率）
- 安全白皮书（数据去哪里，如何处理）
- 可解释性文档（如何解释AI决策）

**为什么这有效：**
购买者期望做尽职调查。如果你*在他们询问之前*发送文件，你看起来自信且可信。

**其次：控制（在演示中）**

展示安全机制：
- 用户如何批准/拒绝AI建议
- 关闭开关和回滚机制
- 置信度分数以及何时AI说“我不确定”

**为什么这有效：**
“失控AI”的恐惧是真实的。展示控制机制证明了你考虑了失败模式。

**第三：性能（第4-8周）**

证明它有效：
- 与基线（人类或以前工具）的基准比较
- 来自类似公司的案例研究
- 如果可能，在他们的数据上进行实时演示

**为什么这有效：**
证明胜过承诺。一个客户说“我们节省了X小时/周”比100个营销声明更有价值。

**第四：扩展（当他们认真时）**

展示企业准备情况：
- 企业部署示例
- 扩展性能（延迟，吞吐量，错误率）
- 合规文件（SOC 2，GDPR等）

**为什么这有效：**
企业不会部署MVP。他们需要证明你不会在1000个用户时崩溃。

**我犯的错误：**

在解释AI如何工作之前尝试证明性能。购买者不相信基准，因为他们不理解系统。**顺序很重要。**

**决策标准：**

如果购买者在演示之前问“它是如何工作的？”，你就跳过了透明度。后退并发送文件。

### 5. 企业AI演示（展示失败，而不仅仅是成功）

**什么不起作用：**

罐头演示，AI神奇地解决了所有问题。购买者认为“这不会在我的混乱数据上工作。”

**什么有效：**

展示AI犯错误并恢复。认真对待。

**有效演示结构：**

**1. 问题（30秒）**
“您的工程师在[特定任务]上花费数小时。这是它看起来像什么。”
- 展示：当前手动工作流
- 定量：时间×工程师×周=总成本

**2. AI尝试（60秒）**
“这是AI处理相同任务。”
- 展示：AI分析，采取行动
- **关键动作**：让AI遇到错误或不确定性
- 展示：AI重新分析，恢复，或寻求帮助
- **叙述**：“注意它第一次没有完全正确。它像人类一样处理不确定性。”

**3. 人类审查（30秒）**
“这是工程师审查和批准的地方。”
- 展示：工程师检查AI的工作
- **关键动作**：展示工程师覆盖或调整某事
- **叙述**：“人类保持控制。AI处理重复性工作，人类处理判断。”

**4. 结果（30秒）**
"[X小时]→[Y分钟]。工程师仍然拥有结果，AI加速执行。”
- 定量：时间减少，成本节省，释放能力

**为什么这有效：**

- 展示失败→建立信任（你没有隐藏任何东西）
- 展示恢复→证明AI是稳健的
- 展示人类覆盖→给他们控制权
- 定量节省→使ROI具体

**我看到的模式：**

完美AI的演示→购买者怀疑
有缺陷但能恢复的AI演示→购买者参与

**常见错误：**

挑选AI 100%准确的例子。购买者知道现实世界的数据是混乱的。如果你不展示混乱，他们假设你在隐藏它。

### 6. “谁拥有这个？”反对意见处理

**反对意见：**

“这看起来很棒，但当AI做错事时会发生什么？”

**坏答案：**
“我们的AI准确率是95%，我们每周都在改进它。”
（翻译：“它会在5%的时间内破坏生产，祝你好运”）

**好答案：**
“好问题。让我们一起走过一个失败场景。”

**然后问：**

1. “当AI采取导致错误的行动时，你团队中谁调查？”
2. “你对工具故障是否有事件响应流程？”
3. “谁拥有回滚决定——批准它的工程师还是运维团队？”

**这做了什么：**

- 从“它会失败吗？”（是，它会）转变为“我们如何处理失败？”
- 使他们思考运营准备情况
- 揭示他们是否准备好使用AI代理

**后续：**

“我们建议：从低风险环境开始。让AI处理非关键工作流2-4周。看看你的团队如何处理它的错误。然后在你们对流程有信心时再扩展范围。”

**为什么这有效：**

你卖的不是一个完美的工具。你卖的是一个需要运营成熟度的工具。**过滤成熟的购买者比说服不成熟的购买者更好。**

**模式：**

成熟的购买者说：“我们已经有工具故障的运行手册，我们会将AI添加到其中。”
不成熟的购买者说：“你能让它永不失败吗？”

**决策标准：**

如果购买者要求100%准确，放弃。他们还没准备好。等他们有了事件响应流程再回来。

1. 确定您的AI产品补充或取代了哪些工具
2. 建立已知使用这些工具的公司目标清单
3. 围绕限制条件而非产品特性进行沟通：
   - "使用[现有工具]的团队在需要[您的产品提供的功能]时，往往会遇到瓶颈"
   - 承认现有工具的价值（不要贬低）
   - 定位为"进阶版本"，而非替代品

**为什么这种方式转化效果更好：**

遇到瓶颈时的沟通比冷接触转化率高3-5倍，因为：
- 潜在客户已经了解问题所在
- 他们已经投入了该领域
- 他们已分配内部预算
- 他们能清晰说明缺失的部分

**资格认证问题：**

"您当前工具尝试自动化过的最复杂任务是什么？以及它在哪里失败？"

如果他们给出具体答案并描述具体痛点，他们就是遇到瓶颈的购买者。如果他们说"工作得很好"，他们还没准备好。

**常见错误：**

试图说服对工具不熟悉的潜在客户采用AI代理。转化率低，教育周期长，他们会将您与"不做任何事"进行比较，而不是"做得更好"。目标应是那些已经相信该领域的购买者。

## 决策树

### 我应该使用哪种定位？

```
您的AI是否自主运行（每项操作无需审批）？
├─ 是 → 您在向谁销售？
│   ├─ 开发者 → "代理"框架
│   └─ 企业 → "伙伴"框架
└─ 否 → "协作者"框架
```

### 我应该使用哪种定价模式？

```
能否可靠地衡量客户成果？
├─ 是 → 基于成果（或含成果成分的混合模式）
└─ 否 → 继续...
    │
    客户使用量差异是否超过5倍？
    ├─ 是 → 混合模式（基础+使用量）
    └─ 否 → 基于席位
```

### 这个购买者是否准备好使用AI代理？

```
他们是否有针对工具故障的事件响应流程？
├─ 是 → 继续...
│   │
│   他们是否有生产系统的呼叫轮班？
│   ├─ 是 → 合格购买者
│   └─ 否 → 先帮助他们建立流程
└─ 否 → 未准备好（6个月后回来）
```

## 常见错误

**1. 因为"自主"听起来很厉害而使用**
   - 我见过这个拖慢交易。 "自主"会让企业感到恐惧。"伙伴"推进更快。

**2. 隐藏AI的故障模式**
   - 购买者知道真实世界数据很混乱。如果您不展示故障，他们会认为您在隐瞒。

**3. 将"会不会破坏生产环境"当作反对意见**
   - 真正的反对意见是："出问题时谁负责？" 组织准备度，而非准确性。

**4. 像OpenAI那样定价基于使用量的AI**
   - 您的成本结构不是他们的。按客户替代成本的20-30%定价。

**5. 在演示前跳过透明度文档**
   - 顺序很重要。透明度→控制→性能→扩展。不要跳过步骤。

**6. 演示完美的AI**
   - 展示错误+恢复过程。比虚假完美更能建立信任。

**7. 向要求100%准确性的购买者销售**
   - 他们还没准备好。筛选成熟购买者，他们有事件响应流程。
