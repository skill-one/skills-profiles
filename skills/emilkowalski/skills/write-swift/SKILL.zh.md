# 学习 Swift 编程

## 初始响应

当这个技能首次被调用而没有具体问题时，仅响应：

> 我已准备好帮助你以现代 Swift 的方式编写代码，这也是 Swift 语言期望的方式。

在用户提问之前，不要提供任何其他信息。

以 Swift 6.4 为当前版本，学习如何以 Swift 语言期望的方式编写 Swift 代码。

**工具链基准：Swift 6.3**（截至 2026 年 8 月的当前版本）。这里的一切都在 6.3 上编译，除非特别标记 ⚠，否则标记的是未发布的 Swift 6.4 功能。并发指南假设 Swift 6.2 模型——如果项目在 6.1 或更早版本上，§3 中关于 `async` 和 `@concurrent` 的规则不适用。

核心思想：**Swift 是一种渐进式披露的语言。从最简单、最静态、最单线程的工作开始，只有在需要动态性——并发、引用语义、存在类型、不安全指针——的地方才购买这些功能。** 以下每条规则都是该思想的体现。

建立这个默认层次结构。只有在你有理由的情况下才能向下移动一个级别：

| 需求         | 寻求               | 只有在下列情形下才向下移动      |
| ------------ | ----------------------- | ---------------------------------------------------------- |
| 数据         | `struct` / `enum`       | 你需要身份、共享或继承                 |
| 抽象  | 具体类型           | 你在类型之间有重复代码                        |
| 多态性 | `some P`（泛型）      | 你需要异构存储 → `any P`                   |
| 执行    | 主执行者，同步 | 分析显示有挂起 → `async` → `@concurrent` → `actor` |
| 内存       | `Array`，`String`       | 分析显示成本 → `InlineArray`，`Span`           |
| 安全性       | 安全 API                | C 互操作或经过测量的热点路径 → `Unsafe*`               |

## 1. 使用值类型建模数据

值类型是 Swift 的默认值，而不是特殊情况。

- **默认使用 `struct` 和 `enum`。仅在需要身份、共享可变状态、继承或资源生命周期时使用 `class`。** 窗口、数据库连接、渲染引擎中存储的实体——这些都有身份。`Point`、`Drink`、`Material` 则没有。
- **默认使用 `let`；仅在需要可变时使用 `var`。** 这是 `some` 在 `any` 之前和值在引用之前的相同纪律：从狭窄开始，随着原因而扩展。
- **具有可变引用类型属性的 `struct` 既不是值类型也不是引用类型。** 复制会共享对象；修改会跨复制泄漏。要么保持引用类型不可变，要么只暴露转发到它的计算属性，或者将其作为 behind copy-on-write 的 `private` 存储属性。
- **Copy-on-write 是如何获得离线存储和值语义的。** 将一个最终类包装在 `struct` 中，并在修改前检查 `isKnownUniquelyReferenced(&storage)`；如果不是，则首先复制。这正是 `Array`、`String` 和 `Dictionary` 的工作原理。
- **枚举是“一组固定事物”和互斥状态的工具。** 用一个 `enum State` 替换一堆可选存储属性（`isSharing`、`selectedRows`、`shareTarget`）使无效组合无法表示，并使状态变化原子化而不是一系列可以忘记完成的属性写入。
- **组合值会产生一个值。** 一个所有存储属性都是值类型的 `struct` 具有值语义，这是使撤销、差异和状态恢复成为单个代码路径而不是每个属性一个代码路径的原因。

```swift
struct Material {                       // 保留值语义
  var roughness: Double
  private var _texture: Texture         // 一个类

  var color: Color {
    get { _texture.color }
    set {
      if !isKnownUniquelyReferenced(&_texture) { _texture = Texture(copying: _texture) }
      _texture.color = newValue
    }
  }
}
```

**不可复制类型**（`~Copyable`）表达唯一所有权：文件描述符、银行转账、打开的资源。抑制复制将“你不应该运行此操作两次”从断言转换为编译错误，并使结构体的 `deinit` 具有意义。将完成方法标记为 `consuming`，以便编译器证明它是最后一次使用。参数所有权变得明确：`borrowing`（只读，默认）、`consuming`（拿走它）、`inout`/`mutating`（临时写访问）。

## 2. 错误和可选类型——使失败路径可见

Swift 错误处理基于三点：错误源被标记，以免让你意外；错误包含足够的上下文以供行动；**可恢复的错误与程序员错误不同**。

- **可恢复的 → `throw`。程序员错误 → `precondition`/`fatalError`。** 失败的网络调用保持程序运行。越界的索引意味着代码错误并且必须停止，以防止漏洞成为安全问题。
- **具有关联值的枚举是最佳错误类型。** `case duplicateFriend(String)` 比 `case duplicateFriend` 更好——上下文是关键点。
- **使用 `guard` 处理错误条件**，因为它强制退出路径。`if let` 用于普通解包。
- **带类型 `throws`（`throws(MyError)`）用于内部函数、错误转发泛型代码和受约束的环境**，在这些环境中装箱 `any Error` 太昂贵。对于公共 API，未类型化的 `throws` 保留了以后更改错误类型的自由。注意统一：`throws` 是 `throws(any Error)`，非抛出是 `throws(Never)`——这正是 `map` 抽象两者的原因。
- **仅在你可以声明不变式的情况下强制解包**，并优先选择带有消息的失败 `#require`/`precondition` 而不是裸 `!`。

## 3. 并发：在分析显示否则之前保持单线程

这是代理最常犯错的区域，因为 Swift 6.2 中模型发生了变化。

每个应用程序完全在主线程上开始。单线程代码可以走得很远，大多数应用程序永远不需要离开它。

**按顺序进行。不要跳过步骤。**

1. **在主执行者上单线程。** 完全没有并发。对大多数应用程序都很好。
2. **`async`/`await`** 来隐藏延迟（网络、磁盘）。仍然没有自己的并发——SDK API 如 `URLSession.data(from:)` 代表你卸载。
3. **`@concurrent`** 将你的昂贵工作移出主线程——只有在 Instruments 显示挂起时。4. **`actor`** 将状态移出主执行者——只有在太多主执行者状态迫使任务不断跳回时。

**首先打开正确的构建设置。** 在每个项目中启用 **Approachable Concurrency**。对于应用程序模块和面向 UI 的模块，还将 **Default Actor Isolation** 设置为 **MainActor**——它是 Xcode 26 中新应用程序项目的默认值，并删除了大多数 `@MainActor` 注释。在包中：`swiftSettings: [.defaultIsolation(MainActor.self)]`。**不要为通用库设置主执行者默认值**——库应提供 `nonisolated` API，并让客户端决定工作运行的位置。

### 改变的规则

**在 Swift 6.2 中，将函数标记为 `async` 并不会将其移出当前执行者。** 它在调用它的地方运行。这是默认情况下“最自然的代码”无数据竞争的原因。

- **`@concurrent`** — 总是切换到并发线程池。用于你的 CPU 密集型工作。
- **`nonisolated`** — 在调用它的任何地方运行。**这是库 API 的正确默认值**，因为调用者决定。`nonisolated` 在类型上使所有成员非隔离（Swift 6.1+）。
- 两者都不是——保持在调用者的执行者上。

```swift
nonisolated struct PhotoProcessor {          // 与主执行者解耦
  @concurrent                                // 保证在后台运行
  func process(_ data: Data) async -> ProcessedPhoto {
    async let sticker = extractSticker(data)  // 两个独立的工作，并行
    async let colors  = extractColors(data)
    return await ProcessedPhoto(sticker: sticker, colors: colors)
  }
}
```

- **在卸载之前进行分析。** 使用 Instruments（时间分析器、挂起）。如果代码可以在没有并发的情况下更快，始终首先这样做。并发有真实成本——任务分配、调度和推理。
- **不要为琐碎的工作创建任务。** 读取 `UserDefaults` 值的子任务成本高于节省的成本。
- **每个端到端操作一个任务。** 必须按顺序发生的工作放在一个任务中；独立操作获得单独的任务，以便运行时可以交错它们。
- **`await` 是一个挂起点，并且它打破了原子性。** 状态可以在你挂起时改变，并且你可能会在不同的线程上恢复。在每次 `await` 后重新检查假设。从不跨一个持有锁。从不依赖跨一个线程本地存储。

### 执行者可重入性

执行者保证互斥，而不是事务。在同一个执行者上的两个 `await` 之间，其他工作会运行。

- **在同步方法中修改执行者状态。** 在执行者上的同步代码会不间断地运行到完成——那是你的事务边界。
- **保持异步执行者方法精简**，由同步事务性操作组成，并在每个 `await` 时保持执行者在一致状态。
- 经典错误：检查缓存 → `await` 下载 → 写入缓存。两个任务都错过，都下载，第二个覆盖第一个。在 `await` 后重新检查，或者去重飞行中的工作。
- **执行者不是 FIFO。** 它们首先运行最高优先级的工作，以避免优先级反转。如果你需要顺序，使用任务（它从开始到结束运行）或 `AsyncStream`，而不是执行者。

## 4. Sendable 和共享数据

`Sendable` 标记一个类型可以在隔离域之间安全共享。编译器在每次任务和执行者边界处检查它。

- **值类型在其存储是** 时为 `Sendable`——非公共类型自动推断。**公共类型永远不会推断可发送性**：标记公共类型 `Sendable` 是对客户端的承诺，所以 Swift 要求你手动编写它。
- **执行者和 `@MainActor` 类是隐式 `Sendable`**，因为它们的状态是隔离的。
- **大多数模型类既不是 `@MainActor` 也不是 `Sendable`。** 故意保持它们非 `Sendable`——这防止了模型的一半在主线程上被修改，而另一半在后台被修改。如果它们需要离开主执行者，使它们 `nonisolated`，而不是 `Sendable`。
- **只要发送者停止使用它，你仍然可以发送非 `Sendable` 对象** 在域之间。在交出之前进行所有修改；之后触摸它是错误。
- 闭包捕获状态太多。仅在函数类型真正跨域时标记 `@Sendable`。
- **`@unchecked Sendable` 是编译器无法检查的承诺。** 仅保留具有真实内部同步（`Mutex`、锁）的类型。对于全局上的 `nonisolated(unsafe)`，也是最后手段，不是警告静音器。

**当你遇到数据竞争错误时，按此列表操作：**

1. **不要共享它。** 将共享对象放入本地，以便每个并发任务都获得自己的实例。（这是大多数真实错误的修复方法。）
2. **将其作为 `Sendable` 值类型**，这样“共享”实际上是复制。
3. **将其隔离到执行者**——主执行者，或你自己的。
4. 只有到那时才使用 `Mutex`/`Atomic` 从 `Synchronization` 模块（将它们存储在 `let` 属性中），或 `@unchecked Sendable`。

**全局和静态变量是最常见的错误来源。** 按优先级顺序：使其为 `let`；放在 `@MainActor` 上；用 `Mutex` 包装它；`nonisolated(unsafe)`。注意 Swift 中的全局变量是懒惰初始化和原子化的——与 C 不同。

**桥接旧的回调 API**：如果你拥有委托协议，请用 `@MainActor` 注解。如果你没有，请将方法标记为 `nonisolated` 并使用 `MainActor.assumeIsolated { }`——它断言而不是跳转，所以它会大声捕获而不是无声竞争。`@preconcurrency` 在协议上是相同事情的简写。使用 `@preconcurrency import` 来暂时静音尚未迁移模块的可发送性警告；一旦它迁移，警告会正确返回。

## 5. 结构化并发

始终优先选择结构化任务。

结构化任务（`async let`，任务组）像局部变量一样作用域：它们不能超出块，会自动等待，并通过任务树继承取消、优先级和任务局部值。

- **`async let`** 用于固定、静态已知的并发子任务。
- **`withTaskGroup`** 当数量是动态时。任务组符合 `AsyncSequence`——按结果迭代。使用 **`withDiscardingTaskGroup`** 当子任务返回无：它会立即释放每个子任务资源并取消兄弟任务在第一个错误时。
- **`Task { }`** 仅当工作生命周期不适合作用域时——反应委托回调、按钮点击、视图出现。它继承执行者隔离和优先级；你必须自己管理取消。
- **`Task.detached`** 几乎从不。它继承不到任何东西——不是隔离，不是优先级，不是任务局部。如果你需要一个分离的根，将任务组放在它里面，而不是重复分离。

**取消是协作的。** 取消设置一个标志；它不会停止任何东西。在开始昂贵工作之前检查 `Task.isCancelled` 或 `try Task.checkCancellation()`，在同步辅助函数中也这样。对于挂起而不是运行的工作（`AsyncSequence` 的 `next()`），使用 `withTaskCancellationHandler`——并记住处理程序立即并发运行，所以它触及的状态需要真实同步（原子或锁，而不是执行者——你不能保证执行者上的顺序）。

**限制你的并发。** 不要在无界列表上为每个项目分出一个子任务。开始 N 个子任务，然后每次一个完成时添加一个新任务。

**任务局部值**（`@TaskLocal`）传播上下文——请求 ID、跟踪跨度——通过任务树，而无需在每个签名中通过参数传递。使它们可选，以便未绑定的读取具有合理的默认值。

**桥接回调**：`withCheckedContinuation` / `withCheckedThrowingContinuation`。合同是 **在每个路径上精确一次恢复**——从不恢复会无限期挂起调用者；恢复两次是致命错误。对于稍后触发的委托 API，存储延续并在恢复时将其置为 nil。（Swift 6.4——未发布——添加了一个 `Continuation` 类型，它在编译时检查单次恢复。）

**`AsyncSequence`**：使用 `for await` / `for try await` 迭代。用 `AsyncStream` / `AsyncThrowingStream` 适应现有的基于处理程序或委托的 API——在闭包内构造源，从处理程序中 `yield`，并在 `onTermination` 中清理。

## 6. SwiftUI 中的并发

- **`View` 是 `@MainActor` 隔离的**，它包含的所有内容也是如此，包括你的 `@State`。你几乎不需要在视图或视图模型上写 `@MainActor`——并且随着主执行者默认值，你可以删除已有的。
- **SwiftUI 故意将一些代码运行在主线程之外** 以保持帧廉价。API 签名中的信号是 `@Sendable`：`visualEffect`、`Shape.path(in:)`、`Layout` 要求、`onGeometryChange`。当你在其中一个闭包中遇到隔离错误时，**不要发送 `self`——将你需要的一个值复制到闭包的捕获列表中。**

```swift
.visualEffect { [pulse] effect, proxy in    // 复制布尔值，不要捕获 self
  effect.blur(radius: pulse ? 2 : 0)
}
```

- **SwiftUI 的动作回调是故意同步的。** 时间敏感的 UI 更新——例如响应手势或滚动事件的动画启动——必须在同一帧中发生。将 `withAnimation` 状态变化放在同步回调中；仅对后续的长时间运行工作开启 `Task`。
- **在 UI 和异步工作之间的边界放置一个状态。** 视图启动一个任务；异步层在完成时执行同步变异；UI 响应。这保持了视图逻辑的同步性，并使异步逻辑无需导入 SwiftUI 即可进行测试。

## 7. 协议和泛型

不要从类开始。**也不要从协议开始。**

工作流程：**编写具体类型 → 注意它们之间重复的代码 → 将共享能力提取到协议中 → 针对它编写泛型代码。** 具有几乎相同体的重载是泛型化信号。

- **没有类型特定定制的协议是浪费的协议。** 如果每个符合项都会使用相同的默认实现，则在现有协议上编写约束扩展。复杂的协议层次结构（“类型动物学”）会增加编译时间和二进制大小，而不会带来任何好处。
- **优先使用“有”而不是“是”。** 如果协议的某些操作对你的类型没有意义，不要细化它——将其包装在通用结构中并暴露你确实需要的 API。（`GeometricVector<Storage: SIMD>` 而不是 `GeometricVector: SIMD`。）
- **协议要求是一个定制点**——它是动态分派的，符合项的实现将胜出。**仅在扩展中存在的方法是静态分派的**，因此符合项的版本会隐藏而不是重写它，而仅知道 `any P` 的代码会调用扩展。如果类型应该能够定制某些内容，请将其作为要求。
- **组合优于继承。** 类继承是整体的（一个超类），侵入性的（你继承存储属性和初始化器复杂性），并且会留下关于什么可以被重写以及何时调用超类的未写合同。组合小值。
- **强制向下转型是一个代码异味**——它通常意味着类型关系因类层次结构或存在类型而丢失。

### `some` vs `any`

- **默认情况下编写 `some P`。当你需要存储任意类型时，改为 `any P`。** 与 `let` 之前的 `var` 相同的纪律。
- `some P` — 每个作用域都有一个固定的底层类型。你保留每种类型关系，包括关联类型，并且编译器可以进行特化。
- `any P` — 类型擦除的盒子，运行时动态类型变化。用于异构集合、底层类型的可选性和完全隐藏抽象。你为此付费：关联类型关系被擦除到它们的上界，并且调用对优化器不透明。
- **你不能在 `any P` 上调用接受关联类型的方法。** 擦除在产生位置（结果是擦除到它的上界）起作用，但在消费位置不起作用。修复方法是将存在类型传递到接受 `some P` 的函数——编译器会将其解包，在该作用域内类型再次固定。
- **约束存在类型和 opaque 类型**——`some Collection<Element>`，`any Collection<any Animal>`——让你隐藏 `LazyFilterSequence<[Animal]>`，同时仍然暴露元素类型。在你的协议上声明主要关联类型（`protocol Container<Item>`），而不是实现细节（如 `Iterator`）。
- **`where` 子句中的相同类型要求**是如何在协议之间固定关系的（`where Self.CropType.FeedType == Self`）。没有它们，“生长然后收获”不会通过类型检查，错误的符合项会编译。

## 8. API 设计——使用点上的清晰性

使用点上的清晰性是这里优先于所有其他目标的目标。

- **Swift-only API 中没有类型前缀。** 模块可以消除歧义。仅在 API 映射 Objective-C API 时保留前缀。但避免来自特定框架的非常通用的名称——它们在上下文中读起来很糟糕，并强制手动消除歧义。
- **从异步替代方案和直接返回结果的任何内容中删除 `get`。** `persistentPosts`，而不是 `getPersistentPosts`。
- **访问控制是文档。** `private`（文件），`internal`（模块，以及默认值），`package`，`public`。在边界处明确是强制执行可发送性和 API 进化决策的事情。
- **设计模型以防止非法状态被拼写。** 私有设置器加上一个验证的 mutating 方法；枚举用于封闭集合；强类型的 `UUID` 而不是 `String`。
- **属性包装器**提取出访问策略（`@Argument`，`@Published`，防御性复制，懒加载，线程本地），因此声明位置用一句话说明策略。与 `@dynamicMemberLookup` 在键路径上结合以投影通过包装器（这就是 `$binding.title` 的工作原理）。
- **结果构建器**用于声明式 DSL。**宏**当编译器可以编写这些样板代码时（§12）。

## 9. 性能——测量，然后选择

低级 Swift 性能由四个成本主导。知道你正在支付什么。

1. **函数调用**——参数复制，静态与动态分派，调用帧分配，以及阻塞优化。
2. **内存布局**——内联与外联存储；动态尺寸类型。
3. **分配**——全局（释放），栈（便宜：一个减法），堆（昂贵：搜索加锁定）。
4. **复制**——保留/释放和递归结构复制。

**但首先进行算法工作。** 每次你编写一个循环，尝试用算法调用替换它。最大的收益几乎都不是微优化：

- **了解你调用的复杂性。** `Array.remove(at:)` 是 O(n)；在循环中调用它是 O(n²)。`removeAll(where:)` 总共是 O(n)。通过逐字节重新切片构建 `Data` 是 O(n²)；`popFirst()` 是 O(1)。这两者都是隐藏在看起来干净的代码背后的 100×+ 回归。
- **链接的 `map`/`flatMap`/`filter` 每个阶段分配一个数组。** 优雅 ≠ 快速。如果一个管道在每个像素或每个元素中运行在一个热循环中，请一次设置输出大小并写入它。
- **然后进行性能分析。** Instruments 的时间分析器和分配，针对一个 _测试_（次点击测试的运行按钮 → 性能分析）运行，以便你正在测量你关心的确切代码。`platform_memmove` 在火焰图中主导意味着意外的复制；一百万个临时分配意味着中间数组；`swift_beginAccess` 意味着运行时排他性检查；`swift_retain`/`swift_release` 意味着引用计数流量。

**具体杠杆，大致按它们带来的顺序：**

- **在你不打算子类的类上使用 `final`** 将动态分派转换为静态并解锁内联。整个模块优化允许编译器在许多情况下为你证明这一点——并启用泛型特化，这是泛型不再有任何成本的地方。
- **结构存储是内联的；类存储是外联的。** 小结构是免费的；一个具有三个引用类型字段的大结构每次复制成本三个保留，而类一次一个。如果你经常复制它，请使用写时复制。
- **`any P` 存在类型有一个 3 字节的内联缓冲区。** 值适合内联；较大的值在每个复制时堆分配。相同的技术适用：给大型类型间接存储并使用写时复制，它再次适合缓冲区。
- **同构的 `[MyModel]` 胜过 `[any Model]`**——密集打包，一次传递类型信息，可特化。`[any Model]` 是灵活但 opaque 的选项；当你需要它时使用它。
- **将泛型参数约束到类**（`T: AnyObject`）给编译器一个已知表示，即使没有特化。
- **`InlineArray<N, T>`**（Swift 6.2）用于固定大小存储：元素内联存储，大小通过值泛型在类型中，没有堆分配，没有引用计数，没有唯一性或排他性检查。如果它被复制或共享，这是错误的选择。
- **`Span` / `RawSpan` / `OutputSpan`**（Swift 6.2）替换 `withUnsafeBufferPointer` 以直接访问连续存储。它们是非逃逸的，因此编译器将它们的生命周期与容器绑定——你得到指针性能而没有生命周期错误，保留/释放消失。
- **将存储属性从嵌套类移出父结构**移除运行时排他性检查。
- 在 Swift 6.3 中发布，当你测量到需要时：`@inline(always)`（与 `final` 在方法上配对）和 `@specialized(where T == ...)`（SE-0460）以预特化泛型为热具体类型。
- 在 Swift 6.4 中发布（**未发布**——见下文 §15）：`borrow`/`mutate` 访问器而不是 `get`/`set` 用于大型存储值，`UniqueArray`/`UniqueBox`，以及 `Ref`/`MutableRef` 以将重复查找从循环中提升。

**异步函数**将它们的状态保留在每个任务的 slab 分配器上，而不是 C 栈上，并在每次挂起点分裂为部分函数。成本配置与同步函数相似，但调用开销略高——这是不将某些内容设为 `async` 的另一个原因，因为它们没有等待。

**到主演员的跳转和从主演员返回的成本一个真实的上下文切换。** 批量：将循环 _推入_ `loadArticles`/`updateUI` 以使它们接受数组，而不是每次迭代两次跳跃。

## 10. ARC 和对象生命周期

- **对象的保证生命周期在其最后使用时结束，而不是在关闭括号时结束。** 观察到的生命周期是优化器涌现的属性，并且会改变。依赖于 `deinit` 运行时间的代码是潜在的 Bug。
- **`weak`/`unowned` 仅用于打破引用循环——别无他用。** 在强所有者的最后一次使用后读取 `weak` 引用可能会合法地给出 `nil`。可选绑定在那里比强制解包更糟：它将一个响亮的崩溃变成一个无声的错误答案。
- **比 `weak` 更好的：不要构建循环。** 将共享数据分解为双方都引用的第三类型，将循环转换为树。
- **下一个最佳：重新设计 API** 以使对象只能通过强引用访问。`withExtendedLifetime` 有效，但将正确性转移到你身上，并扩散到整个代码库——将其视为补丁，而不是设计。
- **保持 `deinit` 侧效应局部。** 从 `deinit` 发布指标或触发全局效应与优化器决策冲突。在调用位置使用 `defer`，并保留 `deinit` 用于验证。
- Xcode 的 **Optimize Object Lifetimes** 构建设置将观察到的生命周期缩短到保证的最小值，并将暴露这些 Bug。

## 11. 测试——Swift 测试默认

使用 **Swift 测试**编写新测试。XCTest 仍然需要三个确切的东西：UI 自动化（`XCUIApplication`），性能指标（`XCTMetric`），以及必须在 Objective-C 中编写或必须捕获 Objective-C 异常的测试。

- **在任何函数上使用 `@Test`**——全局的，静态的，或实例的；`async`，`throws`，和全局演员隔离的都有效。
- **`#expect(...)` 接受普通表达式。** 没有要记忆的 `XCTAssertEqual`-样式函数——`#expect(a == b)`，`#expect(list.isEmpty)`，`#expect(!x.contains(y))` 都会捕获并显示失败时的子表达式值。
- **`try #require(...)`** 停止测试失败，并安全地解包可选值。这替换了 `continueAfterFailure = false` 并允许你选择每个期望。
- **套件是 `struct`。** 为每个测试函数创建一个新鲜实例，因此状态不能在测试之间泄漏。使用 `init` 进行设置；仅在需要 `deinit` 进行清理时使用 `class`/`actor`。嵌套套件以分组。
- **参数化而不是复制粘贴或循环。** `@Test(arguments: [...])` 独立运行每个案例，并行，可单独重新运行，失败的参数在结果中命名。两个参数集合产生完整的交叉乘积——当你想要匹配对时，使用 `zip()`。
- **特征携带意图：** `.enabled(if:)` / `.disabled("reason")` 用于条件（从不注释测试——禁用的测试仍然编译），`.bug(url)` 用于跟踪，`.tags(...)` 以跨文件和目标关联测试，`.timeLimit`，`.serialized` 当测试确实不能并行运行时。使用 `@available` 而不是运行时 `#available` 检查，以便测试库知道。
- **`withKnownIssue { }`** 用于在无法控制的事情上失败的测试——它保持编译和运行，并在问题修复时告诉你，这与 `.disabled` 不同。
- **`confirmation`** 用于触发 N 次的回调；`withCheckedContinuation` 用于单次回调，没有异步重载。
- **测试默认并行运行，随机顺序。** 这是一个特性：它暴露了隐藏的测试间依赖关系。重构而不是使用 `.serialized`。
- **退出测试**——`#expect(processExitsWith: .failure) { ... }`——在隔离的子进程中覆盖 `precondition`/`fatalError` 路径。仅限 macOS，Linux，FreeBSD，Windows。
- 迁移：两个框架在同一个目标中共存，因此逐步迁移并从今天开始编写新的 Swift 测试。**测试框架互操作性**（swift-testing ST-0021；检查你的 Xcode 版本以获取可用性）允许从 Swift 测试测试中调用包装 `XCTFail` 的帮助程序，反之亦然；将模式设置为 **完整** 或 **严格**（不是 **有限**，永远不要 **无**）以便跨框架问题保持错误并指向 `Issue.record` 替换。

## 12. 宏

当你编写编译器可以推导的代码时才使用宏。

- **宏在展开前进行类型检查。** 参数根据宏声明的签名进行检查，因此误用是在调用点的一个干净错误，而不是生成的代码中的混乱。
- **自由站立（`#foo`）** 产生表达式或声明。**附加（`@Foo`）** 在五个角色之一中增强声明：成员，同级，访问器，成员-属性，符合。角色组合——`@Observable` 是成员 + 成员-属性 + 符合。
- **使用 `assertMacroExpansion` 测试宏作为纯语法树转换。** 它是最快的循环，也是你如何避免代码中无人阅读的 Bug 的方法。在 `expansion` 中设置断点，并 `po` 语法节点以学习其形状。
- **当宏不适用时发出真实诊断。** 抛出错误，或者使用 `context.addDiagnostic` 在特定位置发出警告和修复方案。永远不要让宏静默地生成无法编译的代码。
- 展开的代码是普通的 Swift：可检查的（“展开宏”），可调试的，可单步执行的。

## 13. 日志和调试

- **`os` 的 `Logger`，而不是 `print`。** 为每个子系统创建一个并分类。消息以优化的形式存储，只有在显示时才渲染，因此日志足够便宜，可以保留。
- **非数字插值默认情况下被屏蔽。** 每个值通过 `privacy: .public` 仅针对确实不是个人数据的数据进行选择。使用 `.private(mask: .hash)` 当你需要关联值而不暴露它们时。
- **级别控制持久性和成本：** `debug`（从不持久化，最快——消息构造被优化掉，当不流式传输时完全消失），`info`，`notice`（默认），`error`，`fault`（最持久，最慢）。为你在错误报告中想要的东西记录 `error`/`fault`。
- **记录一个关联 ID**（任务或请求 UUID），然后你可以从设备日志存档中过滤出整个失败的记录，而无需重现它。`log collect --device --start ...`，然后在 Console 中按子系统过滤。
- `format:` 和 `align:` 是免费的——使用它们使日志可读并可选择列。
- LLDB 理解 Swift 任务：它跨线程单步执行 `await`，`swift task info` 显示优先级和子任务，命名任务在调试器和 Instruments 的 Swift 并发模板中显示。

## 14. 不安全代码和互操作

- **"不安全"意味着 API 无法完全验证其输入，因此违反其先决条件是未定义行为**——而不是崩溃。安全的 API 会故意捕获；一个干净的致命错误才是安全的结果。
- **优先使用 `Span` 而不是 `Unsafe*Pointer`**。自 Swift 6.2 起，有一种安全、非逃逸、同样快速的方法来访问连续存储。将原始指针保留用于 C 互操作。
- 如果你必须使用指针：保持不安全区域尽可能小，使用**缓冲区**指针（地址 + 计数）而不是裸指针，以便跟踪边界，永远不要让指针逃逸出提供它的闭包，并运行**地址检查器**。
- 在安全关键模块中启用**严格内存安全**——它强制源代码中承认每个不安全的使用，这是审计的基础。Swift 6.4 的 `@diagnose` 属性（未发布）允许你为单个函数启用它。
- **互操作是双向和渐进的**。C、Objective-C 和 C++ 类型直接映射到 Swift（包括 C++ 值语义、容器作为 Swift 集合，以及仅可移动类型作为 `~Copyable`）。Swift 6.3 的 `@c` 属性将 Swift 函数暴露回 C（当声明已存在于头文件中时使用 `@implementation`）。逐文件采用 Swift；不要重写。

## 16. 将现有代码库迁移到 Swift 6

顺序很重要，混合步骤会导致迁移停滞。

1. **首先使用新编译器构建**。源兼容性意味着这应该直接工作，在 Swift 5 模式下。
2. **每个目标，启用完整的并发检查**（Swift 5 模式 + 所有 Swift 6 警告）。从 **UI/应用层** 开始，而不是框架层——其中大部分已经由 SDK 标注了 main-actor，因此修复率很高。
3. **按最低成本修复警告**。从少量根本原因预期数百个警告：`var` 全局变量应改为 `let`，属于 `@MainActor` 的自由函数，一个需要 `: Sendable` 的公共结构。单行代码可以清除数十个。
4. **将目标切换到 Swift 6 语言模式** 以锁定工作。
5. **移动到下一个目标并重复**。
6. **之后进行重构**。永远不要将重大重构与启用数据竞争安全结合——你将不得不回滚两者。

你可以关闭严格检查并发布；你做出的每个修复都是真实的改进，并且会持续存在。启用 **Approachable Concurrency**，对于应用模块，默认 main-actor **在开始之前**——两者都显著减少了你会看到的错误数量，并且 Xcode 提供了迁移工具，可以为你应用许多更改（swift.org/migration）。
