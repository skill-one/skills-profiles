# 苹果设计

## 初始响应

当这个技能首次被调用而没有具体问题时，仅响应：

> 我已准备好帮助您在网页上构建流畅的苹果风格界面，我的知识来源于苹果的 WWDC 设计演讲，专为网页平台（CSS、Pointer Events、`requestAnimationFrame`、Motion/Framer Motion 等弹簧库）翻译而来。

在用户提问之前，不要提供任何其他信息。

苹果如何构建那些感觉不再像电脑而是您延伸的界面的知识，来源于苹果的 WWDC 设计演讲——主要参考《设计流畅界面》（WWDC 2018），并将其提炼并翻译到网页平台。

主线：**当运动从当前屏幕值开始、继承用户的速度、向前投射动量，并且可以在任何时刻抓取和反转时，界面才会感觉生动。** 弹簧是实现这一切自然的关键，因为它们本质上是可以中断的，并且感知速度。

## 核心思想

> “当我们将界面与我们的思考和运动方式对齐时，就会发生奇妙的事情——它不再感觉像一台电脑，而是开始感觉像我们无缝的延伸。”

当界面表现得像物理世界一样时，它就是流畅的：事物会即时响应、持续移动、携带动量、在边界处产生阻力，并且可以在运动中改变方向。下面的一切都是接近这种状态的方法。

苹果将设计视为满足人类四个需求：**安全性/可预测性、理解、成就感以及快乐。** 这里的每条规则都服务于其中之一。

## 1. 响应——消除延迟

一旦出现延迟，直接性的感觉就会“掉下悬崖”。响应是构建其他一切的基础。

- **在按下时而非释放时响应。** 按下按钮的瞬间就应高亮显示。等待 `click`/touch-up 才显示反馈会感觉死气沉沉。
- **警惕所有延迟。** 审计防抖动、人工计时器、过渡等待和约 300ms 的点击延迟。输入路径上任何非必要的东西都是倒退。
- **反馈必须在交互过程中持续进行，而不仅仅是在结束时。** 对于拖动、滑块或抽屉，整个过程中都要与指针 1:1 更新 UI——永远不要在手势完成后才动画。

```css
/* 反馈存在于按下时，并且是即时的 */
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## 2. 直接操作——1:1 追踪

> “触摸和内容应该一起移动。”

当用户拖动某物时，它必须紧贴手指——并尊重从他们抓取的位置开始的偏移量。在抓取时对齐元素中心会立即破坏这种错觉。

- 使用 Pointer Events 和 `setPointerCapture`，以便即使指针离开元素边界时也能继续追踪。
- 追踪一个短 **速度/位置历史**（最近的几个 `pointermove` 事件），而不仅仅是当前点——你需要在释放时获得速度。

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // 尊重抓取的位置
  // ...追踪位置和时间戳历史以获取速度
});
```

## 3. 可中断性——最重要的原则

> “思考和手势是并行发生的。”

每个动画都必须在任何时刻可中断和可重定向。用户必须能够在飞行中的元素中途抓取并反转，而无需等待动画完成。用户再次抓取正在关闭的模态时，它应该跟随手指——而不是先完成关闭，然后再重新打开。

- **在过渡期间永远不要锁定输入。**
- **始终从 *当前* 值（呈现值）开始动画，而不是目标值。** 在中断时，读取元素当前的屏幕变换并从那里开始新的动画。从逻辑值/目标值开始会导致可见的跳跃。
- **避免使用 CSS 过渡和 `@keyframes` 进行任何手势驱动的操作**——它们无法在飞行中平滑地抓取和反转。弹簧默认从当前值进行动画，这正是中断所需。
- **当手势反转时，平滑过渡速度——不要硬切。** 在反转时用另一个动画替换一个动画会创建速度不连续性，即“砖墙”。能够携带速度通过重新定位的弹簧库可以避免这种情况。（这是 iOS 的 *additive animations* 的原生功能；在网页上，选择一个从当前速度重新定位的弹簧库。）
- **将 2D 运动分解为独立的 X 和 Y 弹簧。** 在 2D 距离上使用单个弹簧时，如果 X 和 Y 具有不同速度，就会出现不同步。

## 4. 行为而非动画——使用弹簧

> “将动画视为您与对象之间的对话，而不是由界面规定的东西。”

预定义的固定时长动画无法响应新输入。弹簧可以——新输入只是改变了目标，而运动保持连续。为用户可以触摸的任何东西使用弹簧。

苹果故意用两个设计师友好的参数替换了物理三重组（质量/刚度/阻尼）。用这些参数思考：

- **阻尼比**——控制过冲。`1.0` = 临界阻尼，无弹跳，平滑稳定。`< 1.0` = 过冲并振荡。越低 = 越弹跳。
- **响应**——值达到目标的速度，以秒为单位。越低 = 越快。**这不是“时长”**——弹簧没有固定时长；其稳定时间来自参数。

**默认值：**
- 大多数 UI 从 **阻尼 `1.0`**（临界阻尼）开始——优雅且不分散注意力。
- 仅在手势本身携带动量时（快速滑动、抛出、拖动释放）添加弹跳（阻尼约 `0.8`）。刚淡入的菜单上的过冲感觉不对；你快速滑动的卡片上的过冲感觉是对的。

**苹果提供的具体值：**

| 交互 | 阻尼 | 响应 |
| --- | --- | --- |
| 移动/重新定位（例如 PiP） | `1.0` | `0.4` |
| 旋转 | `0.8` | `0.4` |
| 抽屉/面板 | `0.8` | `0.3` |

**网页映射（Motion / Framer Motion）：** `bounce` + `duration` 弹簧 API 与苹果的阻尼 + 响应紧密对应。安全的做法是默认所有地方使用 `damping: 1.0` 弹簧；将弹跳保留用于动量驱动的物理交互。

```js
import { animate } from 'motion';

// 临界阻尼默认（无过冲）
animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });

// 动量交互——轻微弹跳，仅因为之前有快速滑动
animate(el, { y: target }, { type: 'spring', bounce: 0.2, duration: 0.4 });
```

## 5. 速度传递——拖动和动画之间的无缝衔接

当手势结束时，动画必须 **在手指的确切速度下继续**，以便拖动和动画之间没有可见的缝隙。这是将“流畅”与“精细”区分开来的关键细节。

将指针的释放速度作为弹簧的初始速度传递。一些弹簧 API 需要相对速度——通过剩余距离对其进行归一化：

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

示例：元素位于 `y=50`，目标 `y=150`（剩余 100px），手指移动 50px/s → 初始弹簧速度 = `50 / 100 = 0.5`。Framer Motion / Motion 直接接收绝对 px/s 速度（`velocity` 选项），因此通常传递原始值。

## 6. 动量投射——动画到手势的 *方向*

> “将小输入变成大输出。”

不要从释放点对齐到最近的边界。使用速度来 **投射静止位置**——就像滚动减速一样——然后对齐投射点最近的最近目标。这就是快速滑动感觉像它将元素抛出的原因。

苹果的确切投射函数（来自《设计流畅界面》示例代码）：

```js
// decelerationRate ≈ 0.998 对于正常的滚动感觉；0.99 对于更快的响应
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);   // 从投射中选择目标
animateSpringTo(target, { velocity: releaseVelocity }); // 然后传递速度（§5）
```

注意：物理教科书的 `v²/(2·decel)` *不是* 苹果提供的——使用上面的指数衰减形式。这是良好底部面板和轮播（Vaul、Embla）的标准行为。

## 7. 空间一致性——对称路径、锚定原点

> “如果某物以某种方式消失，我们期望它从它出现的地方出来。”

- **沿相同路径进入和退出。** 从右侧滑入的面板必须向右侧消失。从右侧进入/从底部出去感觉不连贯且令人困惑。
- **将交互锚定到其源。** 菜单、弹出框或面板应从触发它的元素开始——将 `transform-origin` 设置为触发器，以便按钮和内容之间的空间关系显而易见。（这是与弹出框从其触发器而不是中心缩放相同的原点感知点。）
- **镜像可反转过渡的缓动效果**，以便出站路径与返回路径匹配（使用两个方向的逆三次贝塞尔控制点）。

## 8. 手势方向的暗示

人类根据轨迹预测最终状态。中间运动应暗示事情的去向——Control Center 模块“向上并朝向你的手指生长”。让中间帧指向结果，而不仅仅是盲目地插值到结果。

## 9. 弹簧效果——软边界

在边界处逐渐抵抗，而不是硬停止。硬停止读作“冻结”；连续阻力读作“响应，但这里没有更多内容”。应用随用户拖动超出边界的距离而增加的阻尼。

```js
// 越过边界越远，元素跟随得越少——真实事物在停止前会减速
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

## 10. 手势设计细节（“感觉”清单）

- **点击：** 触摸*下*时高亮（即时），触摸*上*时提交。在目标周围添加约 10px 的滞后/点击填充，并允许通过拖动离开并返回来取消。
- **拖动/滑动：** 在提交到方向之前需要一个小移动阈值（滞后，约 10px），然后 1:1 追踪。
- **从第一次移动开始并行检测所有可能的手势**，一旦意图明确，就自信地取消输赢者。避免只报告*最终*状态的识别器（`swipeleft`-类型事件）——它们会丢弃您需要用于反馈的连续追踪。
- **最小化歧义延迟。** 双击检测不可避免地会延迟单击；仅在双击确实存在的地方支付这种成本。

## 11. 帧级平滑度

平滑度是关于*帧中包含的内容*，而不仅仅是帧率。

- 保持每帧位置变化低于感知阈值，以避免闪烁。
- 对于非常快的运动，轻微的 **运动模糊/拉伸** 比硬锐利条纹更好地编码速度并读起来更好。
- `requestAnimationFrame` 是网页的显示同步时钟（苹果使用 `CADisplayLink`）。仅动画合成器友好的属性——`transform` 和 `opacity`——并使用 `will-change` 暗示即将发生的运动。

## 12. 材质与深度——透明度传达层次

苹果使用半透明材质作为浮动功能层，在不分散注意力的同时带来结构。在网页上，使用 `backdrop-filter` 模拟。

- **将导航/工具栏/面板构建为半透明层**（`backdrop-filter: blur()` + 半透明背景）并让内容在其下滚动——而不是不透明的固定条带。
- **材质重量编码层次：** 更暗/更重的材质分隔结构区域（侧边栏）；更轻的材质吸引对交互元素（按钮）的注意。**永远不要将轻质半透明表面堆叠在另一个上**——可读性会崩溃。
- **更大的表面应读作更厚：** 比小芯片更强的模糊 + 更深的阴影。考虑上下文感知阴影——在繁忙/文本内容上较重，在纯背景上较轻。
- **变暗以聚焦，分离以保持流畅。** 模态任务将表面与变暗的遮罩配对，并将背景推回/向下。一个平行的非阻塞面板使用半透明度和偏移量*而不*使用遮罩，因此不会打断流畅性。对于堆叠的面板，逐步变暗并推回每个父层。
- **鲜艳度保持文本在变化背景上的可读性。** 在模糊/半透明表面上，不要使用平坦的灰色文本——使用更高对比度、稍重的字重和微小的字间距增加。将颜色放在实色层上，而不是半透明前景。
- **滚动边缘效果，而不是硬分隔符。** 取代粘性标题下方的 1px 边框，在内容与浮动铬重叠的地方淡出一个小模糊/渐变掩码——仅在浮动 UI 实际重叠内容的地方。
- **材质化，而不仅仅是淡出。** 对于玻璃/模糊表面，在进入/退出时一起动画模糊半径和缩放，以便表面读作一个真实的材料到达，而不是简单的透明度淡出。

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* 亮顶部边缘 = 光线照射到材质 */
}
```

## 13. 多模态反馈——运动 + 声音 + 触觉

结合感官的三条规则（来自《设计音频触觉体验》）：

1. **因果关系** — 必须明显是什么导致了反馈。在真正的因果事件（切换翻转、项目归位）上触发它，并使其特征与动作的物理性相匹配。
2. **和谐** — 视觉、声音和触觉必须在**同一帧**上触发。它们之间的延迟会破坏错觉。不要让 CSS 过渡延迟音频/触觉（振动 API）。
3. **实用性** — 仅在它值得其位置的地方添加反馈。将触觉/声音保留用于有意义时刻（成功、错误、提交、归位）。过度反馈会训练用户忽略所有反馈。

## 14. 减少运动与无障碍

减少运动并不意味着*没有*反馈——而是更温和、非前庭等效的反馈。响应三个独立信号并将其烘焙到您的组件中：

- **`prefers-reduced-motion: reduce`** — 用短透明度**交叉淡入或静态过渡**替换滑动/弹簧/视差。放弃弹性/过冲。保留有助于理解的透明度/颜色变化。
- **`prefers-reduced-transparency: reduce`** — 使半透明表面更冷/更实：提高背景不透明度，去掉模糊。
- **`prefers-contrast: more`** — 近似实色背景，具有明确的对比边框。

此外：避免全屏移动背景、慢速循环振荡（约 0.2 Hz / 每 5 秒一个周期）、以及黑暗↔亮主题变化的突然亮度跳跃。在移动时使大型移动对象半透明，并在大重新定位期间淡出大表面，在稳定后淡入。

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
@media (prefers-reduced-transparency: reduce) {
  .toolbar { background: white; backdrop-filter: none; }
}
```

## 15. 字体排印——光学尺寸、追踪、行距

苹果设计字体以随尺寸改变形状；在网页上应用同样的纪律。（来自《UI 字体排印的细节》，WWDC 2020。）

- **字间距（tracking）与字号相关——不同字号不应使用相同的字间距值。** 大号显示文本需要*负值*字间距（随着字号增大，字母间距显得过大）；小号文本需要略微*正值*字间距以保证可读性。固定`letter-spacing`值是错误的。标题部分收紧字间距，正文部分接近`0`。
- **行间距（leading）与字号成反比。** 大号标题行间距要紧凑，正文部分要宽松。对于有长上/下标的脚本，增加行间距；对于信息密集型UI，收紧行间距。
- **以权重+字号+行间距作为组合构建层级结构，而非单独以字号为准。** 通过权重强调重点——它能在不占用更多空间的情况下增加存在感。
- **尊重用户的字体大小设置**（动态类型）。与文本一起缩放布局——使用`rem`/`em`的间距，而非固定`px`——这样即使字体变大也不会破坏布局。
- **优先使用平台系统字体，再考虑自定义字体；** 系统字体已内置光学尺寸调整、字间距表和可读性优化。仅在有理由的情况下才覆盖默认设置。

```css
:root { font: 100%/1.5 system-ui, sans-serif; } /* 正文：系统字体，舒适行间距 */

.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* 大号文本的紧凑行间距 */
  letter-spacing: -0.02em;  /* 随着字号增大使用负值字间距 */
  font-optical-sizing: auto;
}
```

## 16. 设计基础——八项原则

上述动态效果与工艺服务于苹果的八项设计原则（《卓越设计原则》，WWDC 2026）。将这些作为你思考的框架：

1. **目的性。** 带着意图去构建；决定不做什么。每个功能都在消耗用户的精力、注意力和信任——只在有回报的地方投入这些资源。
2. **自主性。** 让用户保持掌控：提供选择，不要强迫单一路径。用容错机制支撑——轻松撤销误操作，仅对真正破坏性、不可逆的操作（谨慎使用；过度使用会训练用户直接跳过确认）使用确认对话框。
3. **责任感。** 以用户利益为出发点。隐私：在恰当的时机请求，仅获取必要信息，保持透明。安全：预见滥用和危害——特别是针对AI（过敏敏感的食谱应用不能推荐有害成分）。添加预览、确认、免责声明；删除风险大于价值的特性。
4. **熟悉性。** 基于用户已有的认知构建。使用既不直白也不过于抽象的隐喻（垃圾桶代表删除），并遵循其物理逻辑。保持一致性：外观相同的元素必须行为一致且位于相同位置（macOS上关闭按钮始终在左上角）——这样用户才能预测接下来会发生什么。除非能证明其更优，否则不要打破熟悉模式——然后进行测试，不要想当然。
5. **灵活性。** 为不同场景、设备和能力范围设计。适应平台（iPhone=快速触摸；桌面=精确指针控制的深度工作流）和情境。包容性设计（年龄、语言、专业水平、无障碍）。当单一布局无法满足所有人时，允许用户个性化——重新排列控件，隐藏不常用的部分。
6. **简洁性——非极简主义。** 剥离不必要的元素，让核心目的凸显；将所有内容堆砌一处看似极简，但并非简洁。保持简洁（使用平实语言、无术语、减少步骤）和清晰（使用层级结构——顺序、间距、对比度——让最重要的事最显眼）。每个元素都应有其存在的理由；有时*添加*上下文反而简化（显示剩余时间的视频进度条）。先展示常规路径，高级选项放在更深一层。
7. **工艺性。** 对细节的极致关注能建立信任。优美的排版、随光线变化的配色、清晰的图标和能提供即时自然反馈的响应式动画。没有随机性——每个间距、时序和排列值都是你能够辩护的深思熟虑的选择。抖动的滚动、错位的图标和旋转时崩溃的布局都显得粗心。工艺需要迭代和持久性——随着功能和硬件的变化持续优化设计。
8. **愉悦感。** 这是前七项原则正确执行的结果，而非顶部撒的彩带。确定你希望用户感受到的情绪（平静、自信、兴奋），并在每个决策中强化它。

服务于这些原则的战术规则：

- **反馈分为四种类型：** 状态、完成、警告、错误。确认重要操作，展示持续状态，在问题发生前警告，在提交前进行内联验证（而非提交后）。
- **导航。** 每个界面都应回答：我在哪里？我能去哪里？这里有什么？如何退出？永远不要困住用户。
- **分组与映射。** 邻近性暗示关联；将控件放置在它影响的对象附近，并排列控件以反映其修改的内容。如果需要标签解释控件，说明映射关系较弱。
- **直接、具体的标签优于安全的通用标签。** 导航项应按内容命名（"进度"、“库"），而非模糊的伞状词（"主页"）。具体性创造可预测性。

## 17. 流程

- **交互式原型——交互式演示胜过“百万静态设计”。** 你通过构建和交互来发现界面；可工作的原型也设定了具体标准，防止最终实现平庸。
- **交互设计与视觉设计同步进行。** “你不应该能分清哪部分是交互，哪部分是视觉。” 动态效果不是像素之外的附加层。
- **在真实场景中用真人测试**，并从新视角审视动态效果——慢放/逐帧播放以捕捉全速时不可见的细节。
