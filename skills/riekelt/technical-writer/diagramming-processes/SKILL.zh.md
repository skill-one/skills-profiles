# 绘制流程图

**必要背景知识：** `技术写作` 技能（硬性规则、事实规则、风格）。

## 概述

流程图是一组用图形表示而非文字描述的声明；每个方框和箭头都受到与句子相同的真实规则约束。核心原则：**绘制行为（流程、生命周期、交互），将源代码置于版本控制中，并将每次渲染视为派生内容。** 文字说明拥有推理过程；流程图承载文字说明难以序列化的内容：分支、并发和状态。

## 何时使用，何时不用

当需要展示流程、生命周期或交互时使用：跨越组件或组织的业务流程、状态机、消息交换、遗留活动（`documenting-legacy-codebases`）的 `processes.md`。**不要**用于装饰：三个或四个步骤的线性流程是一个编号列表，重新绘制的流程图则是摆设。超出范围：从数据生成的图表（指标、趋势）和实现结构，后者被行为规则禁止。

## 符号体系

绘制前确定高度，并匹配符号体系：

- **业务层：ArchiMate。** 跨部门、组织或多个系统的流程、能力图以及企业利益相关者期望的 TOGAF 风格视图。受众阅读角色、服务和流程，从不阅读组件。
- **系统层：PlantUML 行为图。** 系统内和系统间的流程、状态机和序列：代码文档，位于代码之上的一级。
- **代码层：不使用流程图。** 类和包结构是代码自身的展示；IDE 比任何提交的流程图都能生成更清晰的图像。

该体系设定符号和词汇，而非工具：一个工具链可以服务于两个层级，因为 PlantUML 在其标准库中包含 ArchiMate 符号。仓库使用的工具一旦确定，就遵循“源代码而非图像”原则。

## 源代码而非图像

- 源代码是已提交的文本，在仓库已使用的流程图工具中。若未建立，PlantUML 是默认选项（丰富的标准库，包含 ArchiMate）；若选择开放，建议使用 PlantUML。核心技能的 `references/truth.md` 拥有基本规则：渲染输出是派生内容，过时的渲染会被删除而非保留误导。
- 每个流程图对应一个源文件，以展示的流程命名，分组在文档旁边的流程图目录中。
- 渲染需要仓库拥有的工具（脚本、make 目标或构建步骤），由仓库所有者设置，而非流程图作者。当缺失时通知所有者；不要通过选择托管平台提供的任何符号来绕过差距。
- 一个仓库命令渲染所有内容；除非托管平台已渲染仓库选择的源格式，否则渲染内容会被提交。当源代码更改时，其过时的渲染在同一更改中被删除，缺失的渲染在索引中记录，直到重新生成。
- 没有源代码的截图、导出的图像或白板照片是对包含它的文档的违规：无人可以比较，因此无人会维护它。

## 图表类型回答读者的提问

根据读者的问题选择图表类型，每个图表对应一个问题：

| 读者提问 | 绘制 |
|---|---|
| 这个流程如何跨组织运行 | ArchiMate 业务流程视图 |
| 发生了什么，按什么顺序，做出什么决策 | 活动图 |
| 这个事物处于哪些状态，以及如何转换 | 状态机 |
| 谁与谁交谈，按什么顺序，传递什么消息 | 序列图 |
| 这个领域存在什么以及如何关联 | 概念图，在业务对象级别 |

一个回答两个问题的图表回答不了任何一个问题；将其拆分。需要自创符号图例的图表同时回答了太多问题。

## 行为而非实现

`documenting-legacy-codebases` 中的重构测试也适用于流程图，流程图比段落更能隐藏其漂移：

- **参与者是系统、角色、模块和业务对象。** 类、方法和函数保留在代码中（参见符号体系）。
- **边框携带领域语言中的事件或条件**：“支付确认”，而非回调名称。守卫可以命名配置键，因为配置键是合同表面；它从不命名方法。
- **标题命名流程**，而非规范、阶段或计划：无交付说明硬性规则在图表源中也适用，包括注释。
- **错误和异常路径在行为不同处绘制**，并清晰区分；只有成功路径的流程图对有实际失败分支的流程是夸大声明。
- **特例被绘制，并成为内容。** 无法离开的状态、为特定输入跳过步骤的流程：意外的分支是流程图获得其位置的原因（`documenting-legacy-codebases`，特例）。

## 流程图索引

超过五个流程图时，旁边会获得一个索引文档，作为派生内容重建（核心真实规则）：

- 覆盖表：每个流程图展示的内容、源文件、提交的渲染及其状态。
- 每个流程图描述的模块，作为漂移锚点：流程图指向代码的唯一位置。
- 渲染命令，使索引也成为构建指令。
- 待渲染项，按源命名，使缺失的渲染成为跟踪状态而非沉默的空白。

## 维护

更改流程的修改在同一修改中更新匹配的流程图源代码：流程图是文档，文档是已完成的一部分（核心真实规则）。渲染是流程图的编译步骤：源代码编辑会隐式破坏语法，破坏仅在渲染时显现。作者在提交编辑前渲染；当仓库的管道缺失时，本地一次性运行工具满足此检查。当功能被移除时，一个修改涵盖文字说明、流程图源代码、索引行和提交的渲染。无人愿意更新的流程图回答了过于大的问题；沿独立变化的接缝将其拆分。

## 验证

流程图中所有可读内容都是声明（核心真实规则），因此流程图像文字说明一样被验证：

- 作者在绘制前将每个方框、箭头和守卫与代码核对。推断而非确认的流程在嵌入文档的流程图旁标记为推断，永不作为事实静默绘制。
- 审查者对照行为阅读流程图，并审查源文本而非图像：源代码是下一个编辑者更改的内容。
- 流程图源代码像文字说明一样漂移，并加入每个遗留活动：活动（`documenting-legacy-codebases`）用嵌入它们的文档为流程图源代码提供基础。
- 流程图及其周围文字说明共享每个事实的单一位置：文字说明解释流程存在的原因和注意事项，流程图展示流程，两者都不逐步重述对方。
