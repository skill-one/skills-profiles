# 完成前的验证

**必要背景：** `principal-engineering` 技能。

## 概述

完成意味着已验证，验证即已检查的内容。细致的工作并非验证。

## 纪律

1. **在变更表面驱动变更，捕获其行为。** 在运行系统中运行执行变更代码的最小路径；下文中的“在表面验证”将扩展此概念。
2. **运行验证命令，粘贴其输出。** 验证命令来自变更前的检查点；它证明门禁有效，其实际输出支持该声明的部分。在引用输出前删除秘密值（`operating-safely` 负责秘密值卫生）。始终使用“PASS（检查了 X 和 Y）”表示“已验证”，而不是一个简单的对勾。
3. **忠实报告，双向报告。** 报告失败的测试及其输出，将跳过的步骤标记为跳过，平实地陈述已验证的工作而不含糊其辞。低估已验证的工作与高估工作浪费读者信任一样浪费读者的重新验证。
4. **不信任绿色。** 绿色套件在无法工作的代码上意味着套件未运行、未覆盖或无法失败。当结果对变更规模来说过于干净时，确认测试已执行（单独运行它，观察它出现）并确认它可以失败（破坏代码，观察它变红，再修复它）。从未运行过的测试和从未触发的门禁会产生自信的错误“完成”。
5. **区分层级。** 已实现（在仓库中）不是已部署（在线）不是外部验证（在外部系统中检查）。从不从早期证据中声称后期层级。
6. **在声明完成前回顾。** 浏览差异：无无关变更，代码或注释中无规划残留，文档在同一变更中更新，每个验收标准都实际满足而非近似满足。
7. **顶级变更的独立验证。** 变更的作者是验证它的最不利位置。对于项目声明的关键路径（资金、销售、存储数据、安全，系统绝不能出错的内容）和不可逆迁移，验证者必须是未编写代码的人或物。当无法及时找到独立验证者时，使用最近的替代方案并称其为较弱的形态；无声地降级检查是失败，明显降级检查是决策。

## 在表面验证

门禁（验证命令、套件、构建）证明仓库有效；变更在调用者遇到它的地方被证明：运行它的命令行、服务它的端点、渲染它的屏幕或导入它的消费者。

- **在运行系统中驱动执行变更代码的最小路径。** 运行带变更标志的标志，向变更处理器发送请求，触发变更错误路径的错误。内部函数不是表面：其调用者在表面结束，所以在那里观察。
- **将测试视为作者的证据，而非验证。** 测试说明要驱动什么；门禁重新运行它。
- **在变更旁边探测。** 快乐路径确认声明；邻居测试它：空值、重复调用、冲突选项、变更未触及的相邻错误。声明过去至少一个探测是最低限度；一个保持的探测仍然报告，因为它说明已覆盖的内容。
- **引用系统生成的内容。** 响应体、终端输出和渲染屏幕支持声明。引用前删除：令牌、连接字符串和认证头。将模糊输出视为失败并附带红acted 原始捕获，永不将其解释为通过。
- **当不存在时说“无运行时表面”。** 文档、注释和类型声明未产生行为时得到验证，永不运行替代门禁来填补空间。
- **永不在线驱动破坏性路径。** 变更代码删除或超出工作区且无安全目标时，围绕它验证并命名未执行的路径（`operating-safely` 负责守卫）。

## 你拥有的失败门禁

首先归因来源，然后无论是谁的测试都修复它。“预存在”是报告中的脚注，绝不是门禁中的借口。例外是程序性的：主分支上的预存在红色阻止无关绿色修复时，以提议无论如何合并绿色修复，由操作员决定。

## 常见错误

- 从看起来正确的差异中声明完成。差异是假设；表面运行是实验。
- 运行整个套件而不是目标验证命令，并将“无新失败”读作“我的变更有效”。从未覆盖路径的套件无法为其作证。
- 重新运行门禁并称之为验证。绿色门禁加上未驱动的表面声称“CI 正常”，不是“变更有效”。
- 验证风险在失败路径的变更的快乐路径。
- “本地测试通过”作为环境风险（配置、迁移、权限、生产数据形状）变更的终端声明。
- 当红色不方便时修复测试而不是代码。测试是信使。
