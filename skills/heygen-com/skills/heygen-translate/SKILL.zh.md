# HeyGen 视频翻译

将现有视频翻译成175种以上的语言。系统将主讲人的声音克隆到目标语言中，重新同步他们的嘴唇到新音频，并返回一个完整的配音视频。您提供一个源视频和目标语言——引擎将处理转录、翻译、声音克隆、唇同步和（可选的）烧入的字幕。

这不是新视频生成。原始视频中的主讲人、表演、构图和品牌资产都得到保留。翻译建立在已有的基础上。

## 用户界面行为

1. **简洁明了。** 不要在聊天中堆砌翻译ID、原始API负载或状态JSON。报告结果（视频链接、语言），而不是底层结构。
2. **避免内部术语。** 不要说“轮询”、“视频翻译ID”、“资产ID”、“v3端点”。要说“正在翻译”、“即将完成”、“您的文件”。
3. **轮询是静默的。** 后台长时间运行的翻译，只在（a）结果交付时、（b）>5分钟停滞（一次更新）、（c）硬故障时发言。
4. **一个结果，一条消息。** 当视频完成时，发送链接并附上一行简短摘要（目标语言、时长、模式）。不要每个API字段都报。
5. **不要描述传输选择。** MCP vs CLI vs OpenClaw插件是内部的。在会话开始时无声选择；永远不要提及正在使用哪个。
6. **使用用户的语言沟通。** 从他们的第一条消息中检测。回复、确认和问题使用他们的语言。技术CLI/API指令保持英文。

## API模式检测

**在会话开始时选择一种传输方式。会话期间从不混合，从不切换，从不描述选择。**

按以下顺序检测：

1. **OpenClaw插件模式** — 如果在OpenClaw中运行且`video_generate`工具暴露了HeyGen翻译模型，优先使用该模型。*目前插件生成视频但直接不暴露翻译——直到HeyGen通过`video_generate`提供翻译为止。*
2. **CLI模式（API密钥覆盖）** — 如果`HEYGEN_API_KEY`在环境中设置且`heygen --version`退出为0，使用CLI。API密钥的存在是用户希望直接API访问的明确信号。
3. **MCP模式** — 没有`HEYGEN_API_KEY`且HeyGen MCP工具可见（`mcp__heygen__*`）。OAuth认证，使用用户的计划积分。
4. **CLI模式（回退）** — MCP工具不可用且`heygen --version`退出为0。通过`heygen auth login`进行认证。
5. **都不是** — 告诉用户一次：“要使用此技能，请连接HeyGen MCP服务器或安装HeyGen CLI：`curl -fsSL https://static.heygen.ai/cli/install.sh | bash`然后`heygen auth login`。”

### 认证验证（在任何API调用之前运行）

模式检测后，在进入阶段1之前验证认证是否实际工作。这避免了浪费用户的时间收集输入，只在提交时遇到认证错误。

- **MCP模式：** 认证由OAuth处理——不需要检查。
- **CLI模式：** 运行`heygen auth status`（静默）。如果退出为0，则继续。如果退出非零（没有密钥、过期、无效）：
  1. 询问用户：*"我需要您的HeyGen API密钥才能继续。您可以从https://app.heygen.com/settings?nav=API获取一个——粘贴在这里。*"
  2. 一旦他们提供，持久化它：`echo "<key>" | heygen auth login`（写入`~/.heygen/credentials`，跨会话持久化）。
  3. 验证：`heygen auth status`。如果仍然失败，显示错误并停止。

这是一个**一次性设置**。一旦`heygen auth login`持久化密钥，未来的会话将自动获取它。如果`heygen auth status`通过，则不要再问。

**硬性规则：**

- **永远不要调用`curl api.heygen.com/...`** 此技能中的每个操作都有一个CLI命令，以及（在支持的情况下）一个MCP工具。使用这些。
- **MCP模式：仅`mcp__heygen__*`工具。** 如果翻译尚未通过MCP暴露，则针对翻译操作回退到CLI。不要合成原始HTTP调用。
- **CLI模式：仅`heygen ...`命令。** 运行`heygen video-translate --help`和`heygen video-translate <子命令> --help`发现参数。使用`--request-schema`查看任何创建命令的完整JSON形状。
- **以下操作显示MCP和CLI并排**——只读检测到的模式的列。

### MCP工具名称（仅MCP模式）

`create_video_translation`（单语言）。多语言和校对尚未通过MCP暴露——针对这些回退到CLI。在会话开始时运行`mcp__heygen__*`工具列表以确认可用性；工具界面会演变。

### CLI命令组（仅CLI模式）

```
heygen video-translate
├── languages list              # 支持的目标语言
├── create                      # 提交翻译任务（单次或批量）
├── get <id>                    # 检查状态/获取结果
├── list                        # 列出过去的翻译
├── update                      # 更新任务元数据
├── delete                      # 删除任务
└── proofreads
    ├── create                  # 在最终渲染前提取可编辑的字幕
    ├── get <id>                # 检查校对会话状态
    ├── srt get <id>            # 下载提取的SRT
    ├── srt update <id>         # 上传编辑后的SRT
    └── generate <id>           # 从批准的SRT渲染最终视频
heygen asset create --file <path>   # 用于本地源视频上传（最大32 MB）
```

每个命令都支持`--help`。在`create`上使用`--request-schema`查看完整的JSON正文。CLI输出：标准输出为JSON，标准错误为`{error:{code,message,hint}}`包，退出码`0`为成功 · `1` API · `2` 使用 · `3` 认证 · `4` 超时。在`create`上添加`--wait`以阻塞直到任务完成（默认超时20分钟）。

## 默认工作流程

该技能运行四个阶段。阶段1（发现）是唯一可以提问的地方。阶段2（预飞行）是静默的。阶段3（提交+轮询）是静默的。阶段4（交付）是一条短消息。

```
阶段1 — 发现       — 从用户收集最小必需输入
阶段2 — 预飞行      — 验证语言、分类内容、设置标志
阶段3 — 提交+轮询   — 启动，后台轮询，只在完成/失败时显示
阶段4 — 交付         — 发布结果并附上一行简短摘要
```

### 阶段1 — 发现

只问你没有的信息。使用用户的语言沟通。**永远不要运行表单。** 每轮最多一两个问题。

**必需输入（阻塞直到你拥有这些）：**

1. **源视频。** 公共URL、本地文件路径，或来自先前步骤的HeyGen资产ID。如果用户尚未提供，请问：*"源视频是什么——URL、文件路径，或现有的HeyGen资产？*"
2. **目标语言（）。** 用用户的语言作为开放式问题询问：*"我应该把它翻译成哪种语言？*"* 不要提供选择器或预分配选项——让用户自由输入。他们可能想要一种语言、多种语言，或特定区域变体。接受他们提供的任何内容并对照阶段2中的标准语言列表进行验证。

**重要输入（如未提供，则智能默认）：**

3. **说话人数。** 单人默认且大多数用户都有。当模糊时一次性询问：*"视频中有多多数量的不同说话人？*"* 错误的说话人数是#1质量杀手——说话人混淆会在翻译过程中产生声音交换。不要为多人内容跳过此步骤。
4. **内容类型。** 你通常不需要询问——从视频推断并确认。以下五个配置文件涵盖了~95%的情况。只有当确实模糊时才询问。
5. **字幕偏好。** 对话头和公司默认为开启；播客/音频仅默认为关闭。如果你翻转默认值，请在阶段4简要提及。
6. **时长灵活性。** 询问：*"翻译后的视频需要与原始视频完全相同长度，还是可以稍长或稍短？允许灵活性通常听起来更自然——翻译的语音有足够的空间以舒适的速度说出，而不是被加速或压缩。*"* 默认建议：灵活（`enable_dynamic_duration: true`）。仅在用户需要帧精确计时时设置为`false`（例如，与时间轴、广告位或外部音频轨道同步）。

**可选（仅当相关时）：**

7. **术语表/不翻译术语。** 对于公司或技术内容，询问：*"是否有产品名称、公司名称或术语我应该保留原始语言？*"* HeyGen目前不接受硬术语表，因此这成为高赌注时校对步骤（阶段3-校对）的指导。
8. **部分翻译。** 如果用户提到特定片段（“仅引言”、“从1:30到4:00”），捕获`start_time`和`end_time`（以秒为单位）。
9. **在最终渲染前校对？** 默认为OFF（更快，较少批准）。默认为ON：长视频（>3分钟）、公司/品牌内容、高风险法律/医疗/教育、用户母语（以便他们可以验证）。询问：*"想要在最终渲染前审查和编辑字幕吗？这会多花约5分钟，但可以修复任何错误的术语。*"

📖 **区域对问题（正式性注册、从右到左语言、声调压缩、唇同步上限）→ [references/language-locale-guide.md](references/language-locale-guide.md)**

### 阶段2 — 预飞行

静默。没有用户界面聊天。三个检查，按顺序进行。

**检查2a：语言验证。**

**MCP：** `list_video_translation_languages()`（如果暴露）。否则CLI。
**CLI：** `heygen video-translate languages list | jq -r '.data.languages[]'`

列表包含确切的字符串（"西班牙语（西班牙）"、"中文（普通话，简体）"、"阿拉伯语（沙特阿拉伯）"）。将用户输入的大小写不敏感地与这些确切的字符串匹配。如果他们说“西班牙语”，默认为“西班牙语（西班牙）”，并在阶段4中确认。如果他们说“中文”，默认为“中文（普通话，简体）”。如果指定区域（“墨西哥西班牙语”），映射它（“西班牙语（墨西哥）”）”。如果没有匹配：让用户从最接近的选项中选择。

**检查2b：源视频路由。**

| 用户提供的源视频 | 路由 |
|------------------|------|
| 公共HTTPS URL（无认证，`HEAD`返回视频MIME） | 直接作为`{type: "url", url: "..."}`传递 |
| 认证受保护的URL、403、404或HTML响应 | 告诉用户，请求公共URL或本地文件 |
| 本地文件路径 | 通过`heygen asset create --file <path>`（CLI）或`upload_asset`（MCP）上传（最大32 MB）。使用返回的`asset_id`作为`{type: "asset_id", asset_id: "..."}` |
| 现有HeyGen资产ID | 直接作为`{type: "asset_id", asset_id: "..."}`传递 |

📖 **资产路由边缘情况（非常大的文件、预签名URL、认证受保护的源）→ [references/asset-routing.md](references/asset-routing.md)**

**检查2c：内容配置文件。**

根据源选择一个配置文件。不要向用户列出所有五个——无声提议，只有当源确实模糊时才询问（例如，一个音乐为主的对话头，你无法判断语音增强是否会有帮助）。

| 配置文件 | 使用场景 | 标志 |
|---------|----------|-------|
| **对话头/主讲人**（默认） | 一个人对着镜头说话；干净音频 | `mode: precision`，`enable_speech_enhancement: true`，`enable_caption: true`，`enable_dynamic_duration: true`，`keep_the_same_format: true` |
| **播客/音频仅** | 视觉是静态的，不重要，或不存在 | `mode: precision`，`translate_audio_only: true`，`enable_speech_enhancement: true`，`enable_caption: true` |
| **音乐/高音轨** | 背景音乐干扰语音 | `mode: precision`，`disable_music_track: true`，`enable_speech_enhancement: true`，`enable_dynamic_duration: true`，`keep_the_same_format: true` |
| **多说话人** | 两个或多个不同的说话人 | 对话头默认值 + `speaker_num: <数量>`。说话人数是必需的——不要猜测。 |
| **公司/品牌** | 品牌声音、术语表纪律、高风险 | 对话头默认值 +（如果用户有一个）`brand_voice_id`。强烈考虑为这个配置文件进行校对。 |

**始终：**
- `mode: "precision"`，除非用户明确要求“快速”/“快速”/“快速”。
- `enable_dynamic_duration`：根据阶段1中用户对时长灵活性问题的回答设置。默认`true`（推荐）——让翻译的语音呼吸，而不是被压缩到源的精确时间。仅在用户明确需要固定长度输出时设置为`false`。声调压缩使灵活性对en→zh、en→ja、en→ko（亚洲语言运行较短）；de→en、ja→en（运行较长）；ar/he/ur（从右到左+注册转换）特别重要。
- `keep_the_same_format: true`用于视觉翻译——保留源的分辨率和比特率，以便配音视频与原始视频的编码匹配。
- `enable_watermark: false`（默认）。

### 阶段3 — 提交+轮询

静默。后台工作。只在（a）每种语言完成、（b）每种语言硬故障、（c）>5分钟进度检查时显示。

**分支：**

- **标准路径**（校对=OFF）：提交翻译，后台轮询，交付。
- **校对路径**（校对=ON）：创建校对会话 → 下载SRT → 用户编辑或您协助 → 上传编辑后的SRT → 生成最终 → 后台轮询 → 交付。

#### 标准路径

使用批量语法提交每种目标语言（`--output-languages`接受多个）。

**MCP**（目前仅限单语言）：
```
create_video_translation(
  video={type, url|asset_id},
  output_languages=["Spanish (Spain)"],
  mode="precision",
  enable_speech_enhancement=true,
  enable_caption=true,
  enable_dynamic_duration=true,
  keep_the_same_format=true,
  speaker_num=<n>,           # 仅当已知多说话人时
)
```

**CLI:**
```bash
heygen video-translate create \
  -d '{"video":{"type":"url","url":"https://..."},"output_languages":["Spanish (Spain)","Japanese (Japan)"]}' \
  --mode precision \
  --enable-speech-enhancement \
  --enable-caption \
  --enable-dynamic-duration \
  --keep-the-same-format \
  --speaker-num 1 \
  --title "<短标题>"
```

响应返回每种语言的一个`video_translation_id`。捕获所有它们。

**轮询（静默，后台）:**

在运行一种语言时使用`--wait`在`create`上阻塞直到完成。对于批量，丢弃`--wait`并轮询每个ID：

```bash
# CLI模式轮询（后台）
heygen video-translate get <video-translation-id>
# 返回 { data: { status: "pending"|"running"|"completed"|"failed", video_url, ... } }
```

轮询节奏：前3分钟每30秒一次，然后60秒。大多数翻译在5-15分钟内完成；一些（长视频，批量语言）需要30+分钟。硬超时：每种翻译60分钟——超过此时间，视为卡住并显示问题。

**MCP等效：** `get_video_translation(id)`（如果暴露）。否则回退到CLI进行轮询。

📖 **后台轮询模式（不要在前景中轮询/特定于harness的注释）→ [references/troubleshooting.md#polling](references/troubleshooting.md)**

#### 校对路径

对于高风险内容，首先运行校对会话，以便用户可以在引擎提交最终渲染之前审查/编辑翻译后的字幕。

```bash
# 1. 创建审阅会话 — 返回审阅ID（每个语言一个）
heygen video-translate proofreads create \
  -d '{"video":{"type":"url","url":"https://..."}}' \
  --output-languages "西班牙语（西班牙）" \
  --mode 精准 \
  --enable-speech-enhancement \
  --keep-the-same-format \
  --speaker-num 1 \
  --title "<简短的文件名安全的标题>"
# → 状态：处理中  （短视频需要 3–5 分钟）

# 2. 直到完成（或失败 + 错误信息）
heygen video-translate proofreads get <审阅ID>
# → 状态：已完成

# 3. 获取可编辑的原始 SRT 的预签名 URL
heygen video-translate proofreads srt get <审阅ID> > /tmp/srt-resp.json
SRT_URL=$(jq -r '.data.srt_url'          /tmp/srt-resp.json)  # 目标语言，请修改此内容
ORIG_URL=$(jq -r '.data.original_srt_url' /tmp/srt-resp.json) # 源语言字幕
curl -s "$SRT_URL" -o /tmp/proofread.srt

# 4. 手动或使用 sed 编辑 /tmp/proofread.srt（词汇表、语域、人名）
#    参考文档/审阅工作流程.md 了解完整的编辑剧本。

# 5. 将编辑后的 SRT 作为资产上传，然后通过资产ID引用它。
#    `heygen asset create` 接受 srt（png、jpeg、mp4、webm、mp3、wav、pdf、srt）。
#    备用方案：在公共 URL 上托管，并使用 {"type":"url","url":"..."}。
ASSET_ID=$(heygen asset create --file /tmp/proofread.srt | jq -r '.data.asset_id')
heygen video-translate proofreads srt update <审阅ID> \
  -d "{\"srt\":{\"type\":\"asset_id\",\"asset_id\":\"$ASSET_ID\"}}"

# 6. 启动最终渲染 — 返回视频翻译ID
heygen video-translate proofreads generate <审阅ID> --captions
# → {"data":{"video_translation_id":"<vid-id>","status":"处理中"}}

# 7. 等待翻译完成（不是审阅 get — 在这里毕业）
heygen video-translate get <vid-id>
# → 状态：运行 → 完成；data.video_url 包含最终的 mp4
```

📖 **何时坚持审阅，常见 SRT 编辑，词汇表规范 → [参考资料/审阅工作流程.md](参考资料/审阅工作流程.md)**

### 第四阶段 — 交付

每个完成的语言一条消息。格式：

> ✅ 西班牙语（西班牙） — <视频_url>
> 1m 47s，精准模式，带字幕。

如果语言失败：一条简短的消息说明原因（来自故障排除参考）。不要向用户发送重试选项，除非他们要求。如果用户批量处理了多种语言，按完成顺序交付每个语言 — 不要等到所有语言都完成后再发布任何内容。

**源质量免责声明。** 翻译无法改善源内容。如果源内容有模糊的音频、快速剪辑、面部遮挡严重或低分辨率，口型同步和语音质量会下降。当你在第二阶段（或用户提到）检测到这些条件时，应提前警告。不要在结果差之后才显示这些信息。

### CLI 模式下的反馈报告

翻译交付后 — 或者在过程中遇到问题 — 运行以下命令（每个任务一次）：

```bash
heygen feedback --rating <1-5> --comment "<什么有效，或什么出错了以及你尝试了什么>"
```

- `--rating`: `5` = 工作得很好 · `3` = 有摩擦地工作 · `1` = 出错/无法使用。
- `--comment`: 任何错误、过时的文档、缺失的标志或令人困惑的行为，加上触发它的命令或流程。

匿名，无需 API 密钥，在禁用分析时（`HEYGEN_NO_ANALYTICS` 或 `heygen config set analytics false`）不执行操作。这是 CLI 团队的主要信号渠道 — 一个无声完成的任务告诉他们什么也没发生。**CLI 模式仅限：** 在 MCP 或 OpenClaw-plugin 模式下跳过（这些通过 MCP/plugin 界面路由，该界面没有反馈命令）。

## 嵌入式专业知识

上述默认值涵盖了常见情况。以下决策将此技能与通用 API 封装区分开来。在流程中根据判断使用它们，而不是逐字背诵清单。

### 说话人数是 #1 质量杀手

对于单人访谈：1 个说话人。对于访谈/播客/小组讨论：准确计数，不要猜测。引擎通过 `speaker_num` 分离声音；错误计数会导致配音输出中声音混合。如果用户不确定，请要求他们观看视频并计数。

### 源质量分诊（在提交前执行）

第二阶段的 30 秒分诊可节省 10–30 分钟的不良翻译。观看/收听源的前 ~10 秒，并检查：

- **音频：** 语音是否清晰？背景音乐主导？噪音/嘶嘶声？→ 如果语音不清晰，默认 `enable_speech_enhancement: true`。如果音乐主导，`disable_music_track: true`。如果两者都有，警告用户无论标志如何，质量可能较低。
- **面部可见性：** 说话人的面部是否大部分时间都在镜头前，正面，光线充足？→ 重度遮挡（太阳镜、手放在脸上）、仅侧面拍摄、非常快的剪辑或低于 720p 的面部都会降低口型同步质量。
- **屏幕上的文本：** 源语言中的烧入字幕？→ 这些不会被重新渲染。它们将在配音输出中保留源语言。如果用户想要新语言字幕，他们会有两条字幕轨道 — 建议 `enable_caption: true` 并警告现有烧入字幕。

### 区域对问题

- **音调压缩/扩展。** en→zh、en→ja、en→ko 运行约 30% 更短；de→en、ja→en 运行更长；en→ar/he 通常会扩展。动态时长（第一阶段时长灵活性问题）对这些对特别重要 — 没有它，en→zh 听起来会不自然地慢（语音被压缩以适应 30% 太长的时线）。如果用户选择了固定长度的输出，警告他们高压缩对的高质量对会降低质量。
- **正式性/语域。** ja-JP（敬语/keigo）、ko-KR（尊称）、de-DE（Sie vs du）、th-TH（皇家/礼貌/随意）、id-ID（正式 vs 口语）— 引擎默认选择中性正式。如果源是口语化的，并且用户希望在目标语言中匹配语域，请在审阅中标记或在审阅前警告，它听起来会比原始版本稍微正式。
- **从右到左的语言。** 阿拉伯语、希伯来语、乌尔都语、波斯语 — 字幕从右到左渲染。烧入字幕可能与源视频的底部三分图形在错误的一侧发生冲突。如果源有屏幕上的文本或底部三分图形，建议仅音频翻译或审阅字幕样式。
- **区域变体很重要。** 西班牙语（西班牙）vs 西班牙语（墨西哥）vs 西班牙语（阿根廷）在词汇、语调和语速上有明显不同。拉丁美洲观众通常认为卡斯蒂利亚西班牙语是外来的。默认为用户声明的受众区域；如果未指定西班牙语，请询问一次。同样适用于葡萄牙（葡萄牙 vs 巴西）、法语（法国 vs 加拿大 vs 瑞士）、阿拉伯语（阿拉伯语有 19 个区域变体）。
- **普通话特别。** "中文（普通话，简体）" 是中国大陆观众的标准默认值。"中文（粤语，繁体）" 用于香港/海外粤语方言群体。"中文（台湾普通话，繁体）" 用于台湾。这些不是可互换的。

📖 **完整区域对表，包括语域说明和已知怪癖 → [参考资料/语言区域指南.md](参考资料/语言区域指南.md)**

### 口型同步上限

口型同步最佳情况：
- 稳定、正面拍摄
- ≥720p 的面部分辨率
- 干净、光线充足的面部
- 最小剪辑（长镜头效果更好）

口型同步下降情况：
- 侧面拍摄、向下拍摄、面部部分遮挡
- 快速剪辑（<2 秒镜头）
- 暗光、运动模糊或低分辨率面部
- 重度手势，面部快速移动

如果用户的源有这些条件，在第一阶段/第二阶段警告他们：*"注意 — 源有 [X]，所以口型同步不会像单人访谈那样紧密。要我继续吗，还是切换到仅音频翻译？*"

### 字幕：烧入 vs 侧车

`enable_caption: true` 默认将字幕烧入视频中。优点：无需单独文件，任何地方都可以播放。缺点：后期无法编辑，可能与源图形冲突，固定字体/样式。对于高风险内容，用户可能想要重新设计字幕（品牌套件、特定语言字体），请选择审阅工作流程 — 它会提供 SRT，他们可以用它作为侧车字幕文件。

### 仅音频翻译

`translate_audio_only: true` 完全跳过口型同步。用于：
- 播客（"视频" 是静态图像或波形）
- 您将在后期重新合成到不同视频中的音频
- 任何口型同步不可能的情况（无面部、源面部质量很差）

输出是音频文件（通常是 MP3）。告诉用户如何使用它：*"这会给你一个翻译后的音频轨道。将它重新合成回原始视频中的编辑器，或单独使用。*"* 不要将仅音频翻译作为"不良口型同步的解决方案"推销 — 它是不同的交付内容。

### 成本和时间意识

翻译按源视频时长计费。一个 5 分钟的视频翻译成 5 种语言 = 25 可计费分钟。在第一阶段请求批量时显示时间和成本预期：*"那是 5 种语言 × 5 分钟 = ~25 分钟的翻译时间。每个都会花费 10–20 分钟渲染。可以吗？*"

不要报美元金额（价格变化，因计划而异）。报源分钟 × 语言数量，加上诚实的渲染时间范围。

### 故障模式解码器

常见错误响应 → 人类可读原因 → 下一步操作：

| 症状 | 可能的原因 | 修复 |
|------|------------|------|
| `400` "视频 URL 无法访问" | URL 需要认证，返回 HTML，或错误的 MIME | 请求公共 URL 或本地文件 → 上传路线 |
| `400` "语言不受支持" | 字符串未匹配规范语言列表 | 重新运行 `languages list`，显示最接近的匹配项 |
| `failed` 状态与 "音频提取" | 源没有可听语音、音频严重损坏或错误的编解码器 | 验证源有语音；考虑重新编码 |
| `failed` 与 "说话人检测" | `speaker_num` 与实际说话人不匹配，或音频太嘈杂 | 重新提交正确的说话人数量或 `enable_speech_enhancement: true` |
| 超过 30 分钟卡在 `running` | 后端队列/偶尔停顿 | 检查状态，总共给 60 分钟，然后向用户显示 |
| 输出中的口型看起来很糟糕 | 源面部条件（见口型同步上限） | 重新调整预期；提供仅音频作为替代方案 |
| 字幕方向错误 | 从右到左的语言与烧入字幕与源布局冲突 | 切换到审阅 + 侧车 SRT |

## 首次使用用户检测

表明用户对 HeyGen 翻译不熟悉：
- 询问 "你们支持哪些语言？"
- 不知道口型同步与音频-only 的区别
- 之前未使用过 HeyGen（没有头像，`heygen video-translate list` 上没有过去的翻译）

对于首次使用用户，建议在提交完整视频之前使用 30–60 秒的测试片段。这可以捕获源质量问题、语音克隆保真度和口型同步上限，而不会浪费长视频翻译。

## 第二阶段/路线图（仅如果被问及）

目前最佳支持通过审阅工作流程，但尚未作为首选标志：
- **品牌词汇表/不翻译列表。** 在审阅期间注入，通过还原自动翻译的 SRT 中的术语。`brand_voice_id` 标志用于跨翻译保持声音一致性，而不是用于词汇表。
- **自定义 SRT 输入。** 通过 `srt` 字段（企业计划）在 `create` 中支持，或通过 `proofreads srt update` 支持任何计划。使用 `srt_role: "input"` 将您的字幕应用于源语言；`output` 将其应用于目标语言字幕。
- **部分翻译。** `start_time` / `end_time` 以秒为单位。适用于 "仅翻译分钟 2:00–4:00"。
- **多语言批量。** 已支持 — 将多个值传递给 `--output-languages`（CLI）或 `output_languages` 数组（MCP）。每个语言返回一个作业 ID。
- **Webhook 回调。** `--callback-url` 和 `--callback-id` 完全跳过轮询。当您有 webhook 端点并希望事件驱动完成时使用。

## 最佳实践（简版）

1. **始终使用精准模式**，除非用户明确要求速度。
2. **始终确认说话人数量**，对于不明显的情况。
3. **在提交前验证语言字符串** 对应规范列表。
4. **建议新用户使用短测试片段。**
5. **源质量是上限** — 提前说明，而不是事后。
6. **不要过度配置** — 五个内容配置文件涵盖了 ~95% 的情况。
7. **翻译需要时间** — 设置 5–30 分钟的预期。
8. **匹配语域** — 如果源是口语化的，并且目标语言是语域重的语言（ja、ko、th、de），审阅。
9. **默认审阅 ON：长视频、企业、用户母语的语言。**
10. **永远不要描述运输。** MCP vs CLI 是内部的。
