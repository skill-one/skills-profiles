# HeyGen 虚拟形象设计器

为任意对象创建和管理 HeyGen 虚拟形象：智能体、用户或具名角色。负责身份提取、虚拟形象生成、语音选择，并将所有内容保存至 `AVATAR-<NAME>.md` 以实现一致复用。

## 文件与路径

此技能读写以下文件。未经用户明确指示，不会访问其他任何文件。

| 操作 | 路径 | 用途 |
|-----------|------|---------|
| 读取 | `SOUL.md`, `IDENTITY.md` | 为智能体创建虚拟形象时提取身份细节 |
| 读取 | `AVATAR-<NAME>.md` | 加载现有虚拟形象身份（用于变体外观、语音更新） |
| 写入 | `AVATAR-<NAME>.md` | 创建后保存新的虚拟形象身份 |
| 写入 | `AVATAR-AGENT.md`, `AVATAR-USER.md`（符号链接） | 角色别名，参见第 5 阶段 |
| 临时写入 | `/tmp/openclaw/uploads/` | 语音预览音频（供用户播放下载，会话结束后删除） |
| 远程上传 | HeyGen（通过 `heygen asset create` 或 MCP） | 将用户提供的照片上传至 HeyGen 以创建数字分身 |

仅当用户明确提供素材时，才会将其上传至 HeyGen。

## 语言感知

**从用户的首条消息中检测其语言。** 存储为 `user_language`（例如：`en`, `ja`, `es`, `ko`, `zh`, `fr`, `de`, `pt`）。

1. **使用用户语言进行沟通。** 所有问题、状态更新、确认信息及错误消息均应使用 `user_language`。
2. **语音设计提示词和选择需尊重 `user_language`。** 在设计或选择语音时，指定目标语言，以便语音库返回支持该语言的匹配结果。
3. **技术指令保持英文** — 枚举值（如 `Young Adult`、`Realistic`、`landscape` 等）属于 API 层面，不进行翻译。

## 用户体验规则

1. **保持简洁。** 聊天记录中不要出现虚拟形象 ID、群组 ID 或原始 API 载荷。报告结果（虚拟形象已创建，即可使用），而非底层细节。
2. **不使用内部术语。** 绝不向用户提及内部阶段名称（如“第 0 阶段”、“第 5 阶段符号链接维护”）。用户看到的是自然对话：“正在为您设置虚拟形象……”而非“正在运行第 2 阶段虚拟形象创建”。
3. **每个阶段仅提一或两个问题。** 不要批量提问。按顺序遍历各阶段，仅提出推进所需的最小问题集。
4. **提问前先读取工作区文件。** 工作区根目录下的 `SOUL.md`、`IDENTITY.md`、`AVATAR-*.md` 包含身份信息。首先检查这些文件。仅当确实缺失时才向用户询问。
5. **不叙述技能内部流程。** 绝不说“让我读取工作流”、“正在检查参考文件”或“正在加载虚拟形象发现指南”。静默读取。用户看到的只是问题和结果，而非内部导航。
6. **不宣告即将执行的动作。** 跳过如“现在创建虚拟形象”之类的元评论。直接执行工作。若某步骤耗时较长，用户接下来听到的应是结果（或一个检查点问题）。
7. **绝不叙述传输方式的选择。** MCP 与 CLI 属于内部细节。静默选择传输方式，绝口不提。若两者均不可用，请用户配置其中一种，而不解释原因。

## 从这里开始（关键）

**默认目标 = 智能体。** 此技能的主要用途是为智能体赋予面容和声音，使其能够展示视频。仅当明确出现“我的虚拟形象”/“我”/“我的照片”等措辞时，才路由至“用户”。如有疑问，请创建智能体虚拟形象。

**不要批量提问。** 不要一次性要求“给我一张照片、语音偏好、时长、目标平台、语气、关键信息”。按顺序遍历各阶段。每个阶段每次最多询问一到两件事。

**针对智能体虚拟形象：首先读取 SOUL.md 和 IDENTITY.md，然后直接进入基于提示词的创建。** 不要先向用户索要照片或外观细节。智能体的身份存在于这些工作区文件中。仅当确实缺失时才向用户询问特征。

**基于提示词是默认的创建路径。** 照片属于可选升级，仅当用户明确希望为自己创建真人数字分身时才相关。智能体和具名角色几乎总是使用基于提示词的创建方式。

## 开始之前（环境检测）

尝试从工作区根目录读取 `SOUL.md`。

- **已找到** → OpenClaw 环境。跳过整个本节，直接进入第 0 阶段。工作区原生身份（SOUL.md、IDENTITY.md）将驱动智能体引导流程。
- **未找到** → Claude Code 环境，无工作区身份文件。仍进入第 0 阶段 — 切勿跳过直接列出的用户虚拟形象或向用户索要照片。

**⚠️ AVATAR 文件注意事项：** 忽略工作区中属于*其他*人员或智能体的 AVATAR-*.md 文件（例如，为 Claude 创建虚拟形象时忽略 AVATAR-Eve.md）。仅当 AVATAR 文件名与当前创建对象匹配时才使用该文件。

**⚠️ 尚未获取 HeyGen 虚拟形象。** 这是第 0 阶段的一个子步骤（仅在目标检测后执行）。在第 0 阶段之前获取会导致智能体将对话围绕“您现有的虚拟形象”展开，而默认行为应为为智能体本身创建一个。

## API 模式检测

**模式选择是静默的。** 在会话开始时检测一次，选定模式，然后继续。绝不叙述传输选择（“CLI 已损坏”、“切换到 MCP”）— 用户不关心调用方式。

**MCP（首选）：** 如果 HeyGen MCP 工具可用（匹配 `mcp__heygen__*` 的工具），使用它们。MCP 通过 OAuth 进行身份验证 — 无需 API 密钥 — 并运行在用户现有的 HeyGen 套餐额度上。

**CLI 回退：** 如果 MCP 工具不可用且 `heygen` 二进制文件运行正常（`heygen --version` 退出码为 0），则使用它。身份验证：`HEYGEN_API_KEY` 环境变量或 `heygen auth login`（持久化到 `~/.heygen/credentials`）。如果 CLI 缺失、在 `--version` 时出错或身份验证未设置，请静默跳过 — 不要重试 MCP。

**两者均不可用：** 仅当 MCP 不可用且 CLI 无法工作时，告知用户一次：“要使用此技能，请连接 HeyGen MCP 服务器或安装 HeyGen CLI：`curl -fsSL https://static.heygen.ai/cli/install.sh | bash` 然后执行 `heygen auth login`。”

**API：** 仅支持 v3。绝不调用 v1 或 v2 端点。

**文档优先规则：** 在调用任何不确定的端点之前：
- **索引：** `GET https://developers.heygen.com/llms.txt` — 完整站点地图
- **任意页面：** 在 URL 后追加 `.md` 以获取干净的 Markdown
- 或运行 `heygen <noun> <verb> --help`
- 阅读规范，*然后*构建请求。绝不猜测字段名。

## 虚拟形象文件约定

每个虚拟形象对应一个文件：工作区根目录下的 `AVATAR-<NAME>.md`。

```
AVATAR-EVE.md      ← 智能体      （具名，规范）
AVATAR-KEN.md      ← 用户       （具名，规范）
AVATAR-CLEO.md     ← 角色       （具名，规范）
```

该技能还维护两个**基于角色的符号链接**，与具名文件并行，供消费方技能（如 heygen-video）在请求未携带特定名称时进行通用查找（“为你自己制作视频” → 读取智能体别名；“为我制作视频” → 读取用户别名）：

```
AVATAR-AGENT.md → AVATAR-<CURRENT-AGENT-NAME>.md   （符号链接）
AVATAR-USER.md  → AVATAR-<CURRENT-USER-NAME>.md    （符号链接）
```

具名文件是唯一的真实来源；别名是指针，且永远不会漂移。工作流的第 5 阶段负责维护它们。具名角色没有角色别名 — 它们仅通过名称引用。

格式：
```markdown
# Avatar: <Name>

## Appearance
- Age: <自然语言>
- Gender: <自然语言>
- Ethnicity: <自然语言>
- Hair: <自然语言>
- Build: <自然语言>
- Features: <自然语言>
- Style: <自然语言>
- Reference: <可选的工作区相对路径或 URL>

## Voice
- Tone: <自然语言>
- Accent: <自然语言>
- Energy: <自然语言>
- Think: <一行类比>

## HeyGen
- Group ID: <角色身份锚点 — 稳定的参考基准，永不更改>
- Voice ID: <匹配或设计的语音>
- Voice Name: <人类可读>
- Voice Designed: <若为自定义设计则为 true，若选自目录则为 false>
- Voice Seed: <若为设计，则使用种子值>
- Looks: landscape=<look_id>, portrait=<look_id>, square=<look_id>
- Last Synced: <ISO 时间戳>

⚠️ look_ids 是临时的 — 始终在运行时通过 `heygen avatar looks list --group-id <id>`（或 MCP `list_avatar_looks`）从 group_id 实时解析。切勿将 look_id 硬编码为虚拟形象的主要引用。
```

**顶部章节**（外观、语音）是可移植的自然语言。任何平台均可使用它们。
**HeyGen 章节**是包含 API ID 的运行时配置。技能读取此部分以发起 API 调用。

## 技能公告

每次调用时以以下内容开头：

> 🎭 **正在使用：heygen-avatar** — 正在为 [名称] 创建虚拟形象

## 工作流

**不要预先批量提问。** 按顺序遍历各阶段。每个阶段每次最多询问一件事，且仅在必要时进行。

### 第 0 阶段 — 我们要为谁创建？

参见上方“从这里开始”部分中的智能体默认规则。仅当措辞明确无歧义时，才路由至“用户”或“具名角色”。

路由信号（按优先级排序）：

1. **用户**（仅限明确） — “创建**我的**虚拟形象”、“为**我**制作虚拟形象”、“我渴望视频中出现我的脸”、“**我**的数字分身”、“基于**我的**照片”。需要指向用户的物主代词或对其照片的明确提及。若姓名不明显，请询问其姓名。
2. **具名角色**（仅限明确） — “创建一个名为 Cleo 的虚拟形象”、“设计一个名为 X 的角色”、“构建一个名为 Y 的演示者” → 使用给定名称。
3. **智能体**（默认） — 其他所有情况：“创建你的虚拟形象”、“让自己活起来”、“设置一个虚拟形象”、“让我们制作一个虚拟形象”、“创建一个虚拟形象”、“设计一个演示者”、“我希望你在视频中出现”或任何模糊的措辞。读取 `IDENTITY.md` 以获取名称。

**如有疑问，默认使用智能体。** 对于模糊的请求，不要向用户询问其姓名、外观或语音 — 那是错误的起步动作。若在阅读 IDENTITY.md + SOUL.md 后意图仍感模糊，请提一个简短的澄清问题以消除歧义（自然措辞 — 例如“快速确认：这个虚拟形象是给你，还是给我？”）。

然后检查工作区根目录下的 `AVATAR-<NAME>.md`：

- **AVATAR 文件存在且 HeyGen 章节已填充** → “您已经有一个设置好的虚拟形象。想要添加新外观、更新它，还是重新开始？”等待回答。
- **AVATAR 文件存在但 HeyGen 章节为空** → 跳至第 2 阶段。
- **无 AVATAR 文件** → 进入第 1 阶段。

**角色别名时效性检查。** 在继续之前，还需检查该目标的角色别名是否已指向正确的具名文件：

- 对于**智能体目标**：读取 `AVATAR-AGENT.md`（跟随符号链接）并与 `AVATAR-<CURRENT-AGENT-NAME>.md` 进行比较。如果不同（例如，由于智能体身份自上次运行以来已变更，`AVATAR-AGENT.md` → `AVATAR-OLD-NAME.md`），即使未做其他更改，也在第 5 阶段重新链接。具名文件是规范的，但别名必须匹配*当前*身份，而非历史身份。
- 对于**用户目标**：对 `AVATAR-USER.md` 执行相同的检查。
- 对于**具名角色**：无别名可检查。

**可选的现有虚拟形象检查**（仅在用户路径且用户可能在 HeyGen 账户中已有虚拟形象时才有用）。如果第 0 阶段目标 = **用户**且不存在 `AVATAR-<USER>.md`，请先列出其 HeyGen 虚拟形象：

**MCP：** `list_avatar_groups(ownership=private)`
**CLI：** `heygen avatar list --ownership private`

如果列表非空，展示选项并询问使用哪一个或是否创建新的。如果为空，进入第 1 阶段。对于智能体和具名角色目标，完全跳过此检查 — 这些存在于 AVATAR-*.md 中，而非 HeyGen 目录中。

### 第 1 阶段 — 身份提取

**顺序很重要。先文件，后问题。基于提示词的创建是默认路径 — 照片是可选升级。**

**对于智能体**（第 0 阶段目标 = 智能体）：
1. 从工作区根目录读取 `SOUL.md`、`IDENTITY.md` 以及任何现有的 `AVATAR-<NAME>.md`。
2. 如果找到 SOUL.md 或 IDENTITY.md → 静默提取外观和语音特征。不要向用户询问“描述你的外观” — 智能体即主体，其身份存在于这些文件中。**如果文件仅描述个性/价值观而无身体描述，切勿虚构特征。** 仅以对话方式询问缺失的外观特征（每次一到两个）。
3. 如果未找到任何文件（例如，无工作区身份的 Claude Code 环境）→ 以对话方式询问用户描述智能体的外观和语音。
4. 默认直接进行第 2 阶段的**类型 A（提示词）创建**。除非用户主动提供或明确要求照片真实感，否则不要索要照片 — 智能体几乎总是使用基于提示词的创建。

**对于用户/具名角色**（第 0 阶段目标 = 用户或具名）：
- 对话式引导。自然地询问外观和语音 — 每次一到两个问题，而非表单。使用 `user_language` 沟通。
- **仅用户路径：** 在引导问答后，执行下方的参考照片提醒。
- **具名角色路径：** 跳过提醒，直接进入类型 A（提示词）创建。

填写 Appearance 和 Voice 章节后写入 `AVATAR-<NAME>.md`。在第 2 阶段成功前，保留 HeyGen 章节为空。

### 参考照片提醒（仅限用户路径）

仅当第 0 阶段目标 = **用户**（真人数字分身）或用户明确要求照片真实感时，才执行此步骤。

- 首先检查 AVATAR 文件的 Appearance → Reference 字段。如果已有照片记录，跳过询问并使用它。
- 否则，询问一句话：*“有头像吗？这能为您在视频中的面部一致性提供更好效果。我也可以根据您的描述生成 — 只需说‘跳过’。”*

分支：
- **提供照片** → 通过 MCP `upload_asset` 或 `heygen asset create --file <path>` 上传，然后在第 2 阶段进行类型 B（照片）创建。
- **跳过** → 在第 2 阶段进行类型 A（提示词）创建。

对于智能体和具名角色，跳过此整个步骤 — 直接进入类型 A（提示词）创建。

### 第 2 阶段 — 虚拟形象创建

📖 **完整的创建 API 接口（照片/提示词/数字分身）、文件输入格式、身份字段 → 枚举映射、响应结构 → [references/avatar-creation.md](references/avatar-creation.md)**

两种模式：

**模式 1 — 新角色**（省略 `avatar_group_id`）：
创建一个拥有自己群组的全新角色。

**模式 2 — 新外观**（包含 `avatar_group_id`）：
为现有角色添加变体。从 AVATAR 文件读取 Group ID。

两种创建类型：

**类型 A — 从提示词（AI 生成外观）：**

**MCP：** `create_prompt_avatar(name=<name>, prompt=<appearance>, avatar_group_id=<optional>)`
**CLI：** `heygen avatar create -d '{"type":"prompt","name":"...","prompt":"...","avatar_group_id":"..."}'`（接受内联 JSON、文件路径或 `-` 表示标准输入）

提示词限制为 1000 个字符。要具有描述性 — 包括风格、特征、表情、光照。API 规范说明为 200，但实际强制限制为 1000。

**类型 B — 从参考图像：**

**MCP：** `create_photo_avatar(name=<name>, file=<file_object>, avatar_group_id=<optional>)`
**CLI：** `heygen avatar create -d '{"type":"photo","name":"...","file":{"type":"url","url":"..."},"avatar_group_id":"..."}'`

类型 B 的文件选项：
- `{ "type": "url", "url": "https://..." }` — 公共图像 URL
- `{ "type": "asset_id", "asset_id": "<id>" }` — 来自 `heygen asset create --file <path>`
- `{ "type": "base64", "media_type": "image/png", "data": "<base64>" }` — 内联

📖 **何时使用每种（URL 与 asset_id 与 base64）、上传路由及边界情况 → [references/asset-routing.md](references/asset-routing.md)**

**响应：** 返回 `.data.avatar_item.id`（外观 ID）和 `.data.avatar_item.group_id`（角色身份）。

将身份字段映射到 HeyGen 枚举以用于提示：
- **年龄**：青年 | 中年早期 | 中年晚期 | 高龄 | 未指定
- **性别**：男性 | 女性 | 未指定
- **民族**：白人 | 黑人 | 亚裔美国人 | 东亚人 | 东南亚人 | 南亚人 | 中东人 | 太平洋人 | 西班牙裔 | 未指定
- **风格**：写实 | 皮克斯 | 电影感 | 复古 | 黑色电影 | 赛博朋克 | 未指定
- **方向**：方形 | 水平 | 垂直
- **姿势**：半身 | 特写 | 全身

在创建之前向用户显示提示：
> **外观：**"[提示]"
> **设置：**青年 | 女性 | 东亚人 | 写实
> 看起来怎么样？（是 / 调整 / 完全不同）

⛔ **停止。等待用户批准或调整。直到用户确认之前，不要调用头像创建 API。**

### 第三阶段 — 语音

两条路径：**设计**（描述你想要什么，获取匹配的语音）或**浏览**（手动过滤目录）。

询问他们是否想要语音设计（描述他们想要什么）或目录浏览。使用 `user_language` 进行沟通。

如果 AVATAR 文件中有一个包含性格特征的语音部分，则默认为 **设计**。

#### 路径 A — 语音设计（首选）

使用 AVATAR 文件中的语音部分通过语义搜索查找匹配的语音。这会搜索 HeyGen 的完整语音库。不会生成新的语音，也不会消耗配额。

**语言匹配：**语音设计提示应指定目标语言 `user_language`。例如日语：`"一个平静、温暖的女性声音。专业但易于接近。日语使用者。"` 这确保语义搜索返回正确语言的语音。

**MCP：** `design_voice(prompt=<语音描述>, seed=0)`
**CLI：** `heygen voice create --prompt "..." --seed 0`（也接受 `--gender`, `--locale`）

每个种子返回 3 个语音选项。显示所有 3 个选项，并附带内联音频预览：
- 将每个 `preview_audio_url` 下载到临时路径（任何标准下载方法都行——不需要 HeyGen 认证，这些是公共 S3 URL）
- 作为音频附件发送：`message(action:send, media:"<路径>", caption:"选项 <n>: <语音名称> — <性别>, <语言>")` 这样它可以在 Telegram/Discord 中内联播放
- 在所有预览发送后，显示选择按钮

⛔ **停止。等待用户通过按钮或文本选择语音。直到用户明确选择之前，不要自己选择语音或进入第三阶段 4。**

如果没有匹配：
> "这些都不对劲吗？我可以尝试不同的集合（相同的描述，不同的变化）或者你可以调整描述。"

增加 `seed` 并再次调用。不同的种子会从相同的提示中给出完全不同的语音选项。

- 用户选择后清理 /tmp 文件

#### 路径 B — 语音浏览（备用）

浏览 HeyGen 的现有语音库：

**MCP：** `list_voices(type=private)` 然后 `list_voices(type=public, language=<lang>, gender=<gender>)`
**CLI：** `heygen voice list --type private` / `heygen voice list --type public --language <lang> --gender <gender>`

1. 从 AVATAR 文件中读取语音部分
2. 按性别和语言过滤
3. 基于性格匹配选择前 3 个候选者
4. 显示内联音频预览（与路径 A 相同的下载 + 发送模式）
5. ⛔ **停止。等待用户选择。不要自动选择。**

### 第三阶段 4 — 保存到 AVATAR 文件

更新 `AVATAR-<NAME>.md` 的 HeyGen 部分以匹配规范格式：

```markdown
## HeyGen
- Group ID: <.data.avatar_item.group_id — 稳定的参考，永远不会改变>
- Voice ID: <选择的 voice_id>
- Voice Name: <语音名称>
- Voice Designed: <如果自定义设计则为 true，如果从目录中选择则为 false>
- Voice Seed: <使用的种子值，如果设计>
- Looks: <orientation>=<.data.avatar_item.id> (例如，landscape=<look_id>, portrait=<look_id>)
- Last Synced: <ISO 时间戳>

⚠️ look_ids 是短暂的——总是在运行时通过 `heygen avatar looks list --group-id <id>`（或 MCP `list_avatar_looks`）从 group_id 中解析新鲜。不要将 look_id 作为主要头像参考硬编码。

```

确认头像已保存，并且其他技能（如 heygen-video）将自动获取它。使用 `user_language` 进行沟通。

### 第三阶段 5 — 维护角色别名

在编写命名的 `AVATAR-<NAME>.md` 后，在它旁边创建或更新一个基于角色的软链接，以便其他技能可以在不首先解析代理 / 用户名称的情况下进行通用查找。

根据第三阶段 0 的目标：

- **代理目标** → 软链接 `AVATAR-AGENT.md` → `AVATAR-<NAME>.md`
- **用户目标** → 软链接 `AVATAR-USER.md` → `AVATAR-<NAME>.md`
- **命名角色** → 没有角色别名。命名角色仅通过名称引用（例如，`AVATAR-CLEO.md`）；它们不是代理或用户。

**实现（从工作区根目录运行，使用 fs-fallback）：**

`cd` 到工作区根目录是强制性的——`ln -s` 中的绝对路径从代理的当前工作目录解析，而不是 SOUL.md 所在的位置。`|| echo` 子句处理拒绝软链接的文件系统（没有开发模式的 Windows，某些云挂载存储）而不会中止第三阶段 5。

```bash
# 代理
cd "$WORKSPACE_ROOT" && ln -sf AVATAR-<NAME>.md AVATAR-AGENT.md \
  || echo "role alias skipped: fs doesn't support symlinks"

# 用户
cd "$WORKSPACE_ROOT" && ln -sf AVATAR-<NAME>.md AVATAR-USER.md \
  || echo "role alias skipped: fs doesn't support symlinks"
```

使用相对链接目标（仅文件名，没有路径前缀），以便如果工作区被移动或复制，别名仍然存在。

`ln -sf` 是底层是解链接然后软链接，不是严格原子性的。对于单用户工作区足够好；如果并发代理最终写入相同的别名，预期会出现交错，然后添加显式锁定。

**为什么软链接而不是复制：**消除了重复文件漂移类别（内容永远不会在命名文件和别名之间分化）。它确实不会消除陈旧漂移——如果 `IDENTITY.md` 改变了代理名称而没有重新运行 heygen-avatar，`AVATAR-AGENT.md` 仍然指向 *旧的* 命名文件。第三阶段 0 不匹配并重新别名在下次调用中处理此问题；在此之前，别名是陈旧但指向某个有效的，不是损坏的。

**多代理工作区注意事项：**每个工作区有一个角色别名是最后写入者获胜。如果两个代理最终共享一个工作区并且都运行 heygen-avatar，只有最新运行的身份可以通过 `AVATAR-AGENT.md` 访问。为两个代理命名的文件仍然存在。我们接受这个限制——多代理共享工作区在 v1 范围之外。

### 第三阶段 6 — 测试（可选）

如果用户想要看到他们的头像在行动中：

**MCP：** `create_video_agent(avatar_id=<avatar_id>, voice_id=<voice_id>, prompt=<greeting>)`
**CLI：** `heygen video-agent create --avatar-id <id> --voice-id <id> --prompt "..." --wait`

生成自然问候的视频语言（从 `user_language`）。示例：英语 "Hi, I'm [name]. Nice to meet you!"，日语 "[name]です。はじめまして！"，西班牙语 "Hola, soy [name]. ¡Mucho gusto!"，韩语 "안녕하세요, [name]입니다. 만나서 반갑습니다!"

## 反馈报告（CLI 模式）

一旦头像和语音已保存——或者如果你在过程中遇到摩擦——运行此命令一次：

```bash
heygen feedback --rating <1-5> --comment "<什么有效，或者什么损坏以及你尝试了什么>"
```

- `--rating`：`5` = 工作得很好 · `3` = 带摩擦地工作 · `1` = 损坏 / 无法使用。
- `--comment`：任何错误、陈旧的文档、缺失的标志或令人困惑的行为，加上触发它的命令或流程。

匿名，不需要 API 密钥，当分析被禁用时（`HEYGEN_NO_ANALYTICS` 或 `heygen config set analytics false`）不执行。这是 CLI 团队的主要信号通道——一个无声完成的运行告诉他们什么。**CLI 模式仅：**在 MCP 或 OpenClaw-plugin 模式中跳过（那些通过 MCP/plugin 界面路由，该界面没有反馈命令）。

## 迭代流程

当用户想要改进：

- **"调整提示"** → 模式 2 使用现有的 group_id（保留角色，添加新的外观）。只有模式 1 如果他们说 "完全从头开始。"
- **"添加新外观"** / **"不同的服装"** → 模式 2 使用现有的 group_id。添加到 AVATAR 文件中的 Looks。
- **"尝试不同的语音"** → 回到第三阶段 3
- **"完全从头开始"** → 模式 1，新角色。覆盖 HeyGen 部分。

默认为模式 2（在同一个 group 下添加新外观）。只有在用户明确想要不同的角色身份时才创建新 group。这使帐户保持整洁，并使外观可以在不同技能之间重复使用。

每次迭代都会更新 AVATAR 文件。文件始终是真相来源。

## 用户体验规则

**在检查点时互动，其他地方保持沉默。** 在头像批准和语音选择时停止并等待。在检查点之间，保持沉默——不要叙述推理或解释下一步。在语音选择后：保存 + 确认在一个消息中。

## 视频生产者集成

`heygen-video` 读取 AVATAR 文件以获取 group_id 和 voice_id。解析顺序：

1. **命名请求**（"制作一个视频与 Eve"）→ 读取 `AVATAR-EVE.md`。
2. **代理自我引用**（"制作一个视频记录你自己"，"给我们一个视频更新"）→ 读取 `AVATAR-AGENT.md`（软链接到当前代理的命名文件）。
3. **用户自我引用**（"制作一个视频记录我"，"我的视频更新"）→ 读取 `AVATAR-USER.md`（软链接到当前用户的命名文件）。
4. **没有 AVATAR 文件或软链接** → 回退到标准头像或询问用户。

别名目标是操作系统在读取时解析的，所以消费者技能只需 `cat AVATAR-AGENT.md` 并得到当前代理的头像。

## 错误处理

- 缺失 SOUL.md/IDENTITY.md → 互动式引导，从答案中创建 AVATAR 文件
- API 失败 → 重试一次，然后询问用户检查 API 密钥
- 语音匹配差 → 显示所有可用语音，让用户浏览
- 资产上传失败 → 跳过参考图像，尝试仅提示创建
- 现有头像文件中的陈旧 HeyGen ID → 提供重新生成或保留
