# Seam Craft — 场景间切换的渲染前提条件

这是PLV场景间切换的**渲染正确性准则**：确保任何切换都能正确合成的前提条件和主时间线机制，与具体选择的切换方式无关。每个切换的目录（交叉淡入淡出、推拉、缩放穿过、曲线裁剪、…）都存在于切换注册表中——本页是所有这些准则的基础准则。

受此准则管辖的切换是**Tier-B级别**：仅对两个场景的**剪辑包装器**（`#el-<sid>`）进行纯变换/不透明度/滤镜处理，无注入的叠加DOM，无每场景协作。叠加家族（错落块、百叶窗、光晕、网格溶解、页面烧灼）和着色器切换将推迟到后续阶段。

## 舞台基础前提（白闪防护）

几个模板在两个包装器的不透明度之和小于1时打开窗口（曲线裁剪的中间窗口裁剪、缩放穿过的0.15底部、普通交叉淡入淡出的功率曲线下坠）。在此窗口期间，包装器后面的内容会显示出来。如果组装的`index.html` `#root`没有不透明背景，渲染器会将下坠合成到其默认的**白色**页面→每个切换处都会出现白闪，在深色胶片上刺眼（在修复前观察到的两个Spotify运行中）。**组装者必须绘制舞台**：`#root { background: var(--canvas-deep, var(--canvas, #000)) }`——`assemble-index.mjs`现在会发出这个；使用这些模板的任何其他消费者都拥有相同的保证。

## 注入器如何应用切换

在场景_i_（`from`）和场景_i+1_（`to`）之间的`break`边界处，注入器：

1. 将`#el-<from>`包装器的`data-duration`扩展`duration_s`（持有其最终帧——验证：`core/src/runtime/init.ts:1393-1410`外部槽分支）。
2. 将`#el-<to>`包装器的`data-start`提前`duration_s`（创建重叠窗口）。
3. 重新分配**所有**剪辑的`data-track-index`为0/1乒乓，以便两个重叠的包装器永远不会共享一个轨道（相同轨道重叠是非法的——`core/src/lint/rules/composition.ts`）。较高轨道合成在顶部。
4. 在`T = 重叠开始`时将`gsap_template`戳入`window.__timelines["main"]`。

通过原型渲染验证（2026-05-31）：主时间线包装器的缓动动画被寻求和渲染（没有与子合成自己的暂停时间线双重寻求——运行时独立驱动它们），扩展的包装器持有场景_i_的最终帧，较高轨道的传入包装器合成在+与传出包装器混合。

## 模板占位符

注入器在每个`gsap_template`行中替换这些标记：

| 标记                              | 含义                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------ |
| `__OLD__`                          | `"#el-<from>"` — 传出剪辑包装器选择器（带引号）                         |
| `__NEW__`                          | `"#el-<to>"` — 传入剪辑包装器选择器（带引号）                           |
| `__T__`                            | 重叠开始时间（秒）（主时钟）                                             |
| `__DUR__`                          | 此边界的`duration_s`                                                   |
| `__DX__`                           | 方向类型水平移动：`-1920`（左） / `1920`（右）                          |
| `__DY__`                           | 垂直移动：`-1080`（上） / `1080`（下）                                |
| `__ORIGIN_OUT__` / `__ORIGIN_IN__` | `squeeze`的transformOrigin对                                             |

`filter` / `scaleX` / `transformOrigin`在主时间线上是代码检查干净的（验证：`core/src/lint/rules/gsap.ts`没有每个属性的白色列表，并将其检查范围限制为`data-composition-id`范围；x/y/scale/旋转/不透明度的白色列表只是一个_场景工作器_提示规则——它不会绑定index.html）。
