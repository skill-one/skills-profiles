# HyperFrames 入口点

HyperFrames **从 HTML 渲染视频** — 一个组合是一个 HTML 文件，其 DOM 通过 `data-*` 属性声明时间，其动画运行时是可搜索的，其媒体播放由框架拥有。完整的创作合同位于 `/hyperframes-core`；在编写组合 HTML 之前，请阅读它。简报、故事板、审查、生产、分发和 frame-worker 合同位于此技能的 `references/` 中。

## 1. 从项目状态开始

应用第一个匹配的行；不要评估较低状态行：

### 保持项目的 CLI 更新

模板化项目在其 `package.json` 脚本中固定 `hyperframes@<version>`，以便渲染保持可重复；该固定永远不会自行更新，并且较旧 CLI 的固定运行不会打印任何警告。当恢复脚本带有固定的项目时，在第一个影响渲染的命令之前进行一次探测：

```bash
npx hyperframes@latest upgrade --project . --check
```

探测是只读的，并报告固定与最新发布的对比；保持显式的 `.` — 在较旧的 CLI 版本中，一个空白的 `--project` 后跟另一个标志会将其作为目录值消耗该标志。当它报告项目落后 — 或任何 CLI 输出已经显示它（stderr 通知 `This project pins hyperframes@… (latest …)`，或 `--json` 结果中的 `_meta.updateAvailable: true` 来自固定的脚本）时 — 使用 `npx hyperframes@latest upgrade --project .` 应用，然后用 `npx hyperframes check` 验证。通过检查确认项目的组合在新版本上仍然有效 — 不是渲染输出与旧固定帧完全相同 — 因此成功的提升永远不会无声：在运行摘要中命名旧版本和新版本。还没有组合的项目不需要验证。如果检查失败，请还原 `package.json` 的更改，继续在固定版本上，并报告项目保持在哪个版本以及原因。根据信号采取行动，而不是将其传递给用户；永远不要留下未验证的固定。

## 2. 路由新建

使用第一个匹配的行。匹配请求的 **交付物**，而不是在旁白中提到的单词或文件类型。

| 优先级 | 请求                                                                                                        | 工作流                   |
| ------ | ----------------------------------------------------------------------------------------------------------- | ------------------------ |
| 1      | 显式移植现有的 Remotion 源                                                                                  | `/remotion-to-hyperframes` |
| 2      | 编写演示文稿、提案演示文稿或可导航的交互式演示文稿                                                              | `/slideshow`               |
| 3      | 向现有的访谈视频添加纯字幕或字幕，而不更改视频                                                               | `/embedded-captions`       |
| 4      | 向现有的访谈、采访或播客视频添加设计的图形叠加，而不更改视频                                                   | `/talking-head-recut`      |
| 5      | 从音乐曲目构建一个节拍同步视频，没有旁白或网站捕获                                                             | `/music-to-video`          |
| 6      | 创建一个明确简短、无旁白、以动作为主的单元，通常在 10 秒以内                                               | `/motion-graphics`         |
| 7      | 从 PR 引用解释 GitHub 拉取请求或代码更改                                                                   | `/pr-to-video`             |
| 8      | 从 URL 或特定于网站的简报展示或推广网站、产品网站、应用程序或公司                                               | `/product-launch-video`    |
| 9      | 解释主题、文章或笔记，使用虚构的视觉效果，没有产品或网站捕获                                                 | `/faceless-explainer`      |
| 10     | 任何其他自定义视频或组合                                                                                  | `/general-video`           |

在最终确定路由之前，阅读 `references/routes/<workflow>.md` — 每个路由一个小文件：标准的输入/输出/触发合同（在工作流技能懒加载之前可用）加上该路由的访谈入口。如果候选者不满足其合同，请继续路由而不是强制匹配。只阅读匹配的路由文件。

### 解决常见歧义

- 短动画标题、标志 sting、统计击中、图表击中、地图击中或独立的 lower-third 在它无旁白且动作为信息时是 `/motion-graphics`。静态标题卡、旁白序列、较长蒙太奇或自定义循环是 `/general-video`。
- 明确简短的动画面标可以使用 URL、推文、文章或截图作为源材料。通用的“从这个网站制作视频”请求是 `/product-launch-video`。
- 带有字幕的现有片段路由到 `/embedded-captions`；带有设计信息卡的片段路由到 `/talking-head-recut`。重新时间、重新排序、重新着色、重新构图或重新混合片段是自定义编辑，并传递到 `/general-video`。
- 音乐文件仅在它的节拍网格驱动作品时选择 `/music-to-video`。作为底层的音乐不会覆盖匹配的主题路由。
- “我想一个故事板”会改变审查过程，而不是工作流。在没有其他路由信号的情况下，使用 `/general-video`。确认绘制的故事板 `storyboard.html` 本身可能是请求的交付物；审查循环定义了那个停止点。
- 专门的叙事工作流支持最长约 3 分钟，在 30-90 秒左右最强。将明显更长的作品路由到 `/general-video`。长度永远不会覆盖明确的移植、演示文稿、字幕、叠加或音乐驱动交付物。

## 3. 路由一次，然后离开

对于新建，意图层（`references/intent-interview.md`）运行完整对话 — 记忆、分诊、提案轮、必须有的、运行形状、移交 — 并 **以写入 `BRIEF.md` 结束。简报是唯一路由读取的工作流工件**；之后不会重新打开此技能或访谈。从 `BRIEF.md` 回答每个后续的“路由要求什么？”。

## 4. 安装并进入工作流

在读取选定的工作流之前，安装或刷新它和核心领域技能：

```bash
npx hyperframes skills update <workflow-name>
```

使用不带 `/` 的纯名。如果命令失败，请显示错误；不要从记忆中重建工作流。安装的其余部分 — 核心与懒加载的分割、`init` 刷新的内容、诊断、CI 退出和没有 CLI 的回退 — 都在 `references/skill-lifecycle.md` 中。

| 创作者请求                                                                                                      | 必需的领域                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| “剪切这个片段”，硬切、修剪、拼接、重新排序或使用源范围                                                             | `/general-video` + `/hyperframes-core`；核心拥有 `data-start`、`data-duration`、`data-media-start` 和轨道布局。                                                                 |
| 在这里放大，推入/推出，平滑多状态缩放或重新构图，Ken Burns，或摄像机移动                                                | `/general-video` + `/hyperframes-core` + `/hyperframes-keyframes`；动画内部视觉/裁剪包装器，而不是定时片段。                                                                 |
| 匹配切或快速切换摄像机过渡                                                                                      | `/general-video` + `/hyperframes-animation` + `/hyperframes-keyframes` + `/hyperframes-registry`；在手动编写之前搜索并安装过渡原语。                                                              |
| 淡入、交叉淡入、轨道增益/音量、自动化、切割/切割、音频效果或多个轨道上的一个效果                                             | `/general-video` + `/hyperframes-core` + `/hyperframes-audio`；核心放置片段，音频混合放置轨道 — 包括一组它们的子混音总线。                                                                   |
| 结合切割与摄像机运动或混音的组合编辑                                                                             | `/general-video` + `/hyperframes-core` + `/hyperframes-keyframes` 当存在视觉运动时 + `/hyperframes-audio` 当声音被淡入、混合、切割、自动化或处理时。                                             |
| 布局项目以便在 Studio 中阅读良好：字幕轨道、每个元素类型的轨道、子组合、安全区域                                                 | `/hyperframes-studio` + `/hyperframes-core`；工作室拥有布局约定，核心拥有每个编辑。                                                                                                     |
| 源或生成媒体，或预处理不受支持的源冻结                                                                           | `/media-use`；仅 sourcing/generation/preprocessing，从不放置轨道混合。                                                                                                              |

常量 `data-playback-rate` 对图片和保留音调的声音是渲染安全的。速度渐变是 `data-automation` 中的一个 `rate` 通道。对于可复制的编辑合约，加载 `/hyperframes-core` → `references/creator-editing-recipes.md`。

关于摄影媒体外观或行为的广泛反馈也会路由到 `/media-use`，即使用户从未说“色彩校正”或“效果”：修复暗/平/乏味的素材、风格化片段、隐藏面部或改进媒体揭示。编辑处理前请阅读 `../media-use/references/media-treatments.md`；它规定了素材的处理方式，而非是否可以使用媒体。不要用通用的 LUT、CSS 滤镜/叠加或透明度缓动来替代现有的规范处理原语。将文本/布局/仅运动编辑保留在其所属领域。

在包含重要摄影媒体构建过程中，在最终质量传递中包含一次基础媒体润色扫描；保留合适的媒体不变是一个有效结果。

领域技能永远不会拥有端到端的交付成果。仅加载当前工作流所需的内容。
