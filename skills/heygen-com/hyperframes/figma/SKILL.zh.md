**插件安装：** 在设置或新鲜命令之前，当此技能位于 HyperFrames 插件内时，请遵循 [插件执行规则](../hyperframes/references/plugin-installation.md)。独立安装则保留下方的更新说明。

> **首先，保持此技能新鲜——在运行前与用户确认：** `npx hyperframes skills update figma`。当一切都是最新时，这是一个快速的无操作；否则，在您依赖它们之前，此技能及其依赖的核心域技能将得到刷新。

# Figma → HyperFrames

将用户的 Figma 工作导入一个组合。**按能力分割**（设计规范 §2）：

| 阶段 | 内容                | 传输                 | 表面                       |
| ---- | ------------------- | ------------------------- | ----------------------------- |
| 1     | 静态资源       | REST                      | `hyperframes figma asset`     |
| 2     | 品牌标记/样式 | REST                      | `hyperframes figma tokens`    |
| 3     | 组件 → HTML   | REST                      | `hyperframes figma component` |
| 4     | 动画 → GSAP       | 连接器（当可用时）  | 使用其动画上下文        |
| 5     | 着色器             | 连接器 / 手动导出     | 使用它或原生导出     |

REST 在任何可以使用的位置都使用（在容量、无头模式下可用）。对于动画和着色器数据，兼容的 Figma 连接器是可选的；如果没有，请请求原生导出。每个路径在本地冻结资源，以便渲染保持确定性。故事板重建组合了阶段-1 资源导出（REST）和代理驱动的时序组装——不需要连接器。现有的冻结资源、清单记录和绑定不受路由更改的影响——分割仅更改下一个导入使用的凭证。

## 认证 — 两个凭证，作用域限定

**预检——在第一次 CLI 调用之前，检查是否存在令牌**： shell 环境（`[ -n "$FIGMA_TOKEN" ]`）**或**项目 `.env`（CLI 自动加载它——`.env` 条目计为配置）。如果两者都没有，请**不要**运行采集错误的命令——先引导用户进行一次性设置，然后停止并等待：

1. figma.com/settings → **安全** → **个人访问令牌** → 生成新令牌。
2. 权限范围——只读是此集成永远需要的（它永远不会向 Figma 写入）：**文件内容：只读** + **文件元数据：只读**。如果您将在非企业计划上运行 `tokens`，请添加 **库内容：只读**——发布的样式回退会命中 `/v1/files/:key/styles`，如果没有它将返回 403（较旧的设置文本省略了这个范围）。可选 **变量：只读** 用于品牌变量——企业专享；没有它，`tokens` 会自动降级为发布样式（预期如此，不是错误——请说明）。现在 403 会指明确切的缺失范围；429 会自动重试（每分钟限制，尊重 `Retry-After`）。
3. 让用户在他们的 shell 配置文件或项目 `.env` 中设置 `FIGMA_TOKEN`；永远不要让他们在对话中粘贴令牌。

在引导过程中，也要在一句话内设定预期：每个导入都作为一个**本地冻结文件，记录来源**——渲染永远不会调用 Figma，重新运行命令只会重新导入 Figma 中更改的内容，一个令牌适用于其 Figma 账户可以查看的所有文件中的资源、品牌标记和组件。

- **阶段 4–5（动画/着色器）**：一个兼容的 Figma 连接器，具有与令牌分开的授权。如果它不可用或未认证，请要求用户连接它或提供原生导出，然后停止。
- 明确指出失败阶段需要的凭证——永远不要将分割呈现为损坏。
- `BAD_TOKEN`（401）在流程中 → 令牌已过期/被撤销；重新生成。`FORBIDDEN`（403）→ 消息指明确切的缺失范围（例如 `library_content:read` 用于样式回退）——添加它，或者文件对账户不可见。`REQUIRES_ENTERPRISE`（变量上的 403）→ 不是失败：样式回退已经运行。`RATE_LIMITED`（429）→ 客户端已经使用退避重试（这适用于所有读取——资源、标记、样式、节点树、版本——重试存在于共享请求路径；`Retry-After` 被尊重，限制在 60 秒）；如果它仍然出现，请等待一分钟或每次调用导入较少的节点。

**速率限制意识（规范 §2.1）**：连接器配额因 Figma 计划而异——批量父框架请求，除非被要求，否则跳过验证截图，并缓存原始响应，以便重新派生永远不会花费第二个调用。REST 每分钟（每端点 10+/分钟，配额桶）——在容量下很好，在 429 上退避。

## 路由

使用 `parseFigmaRef`（URL，`fileKey:nodeId`，裸 `fileKey`）解析用户的 figma 链接。然后根据意图：

- "使用这个图层 / logo / 图像" → **资源**（CLI）
- "拉取我的品牌 / 颜色 / 标记" → **标记**（CLI）
- "从这个框架构建场景" → **组件**（CLI）
- "导入这个动画 / 动画" → **动画**（连接器当可用时，下方）
- 故事板部分 / 场景帧的胶片strip → **故事板**（下方）
- 着色器填充/效果 → **着色器**（下方）

**为用户讲述每一步**——在每次命令之前，说明您要从 Figma 拉取什么；之后，说明工件落在哪里（冻结路径 / 侧边栏 / 组件目录），组合中发生了什么变化，以及立即的下一步操作（预览、添加打印的变量、重新导入以链接绑定）。用户永远不需要问“它起作用了吗？”或“现在做什么？”。

## 资源（阶段 1 — CLI）

```bash
hyperframes figma asset '<url-or-fileKey:nodeId>' [更多引用…] [--format svg|png|jpg|pdf] [--scale 2] [--description "..."] [--entity "..."]
```

通过 REST 渲染，清理 SVG，冻结在 `.media/images/` 下，附加清单记录来源，重新生成 `.media/index.md`（共享媒体使用清单），打印 `<img>` 摘要。每个 `fileKey:nodeId:format:scale:version` 都是幂等的。优先选择 SVG 用于矢量/标志（可缩放，可动画），PNG `--scale 2` 用于光栅保真度。**始终传递 `--description "<它是什么>"`**（它成为索引行 + `<img alt>`）；为命名品牌标记添加 `--entity "<名称>"`，以便媒体使用 `resolve --entity` 后找到它们（实体命中跨图像/图标匹配）。

**批量许多节点在一个请求中**——传递同一文件的多个引用（空格分隔或逗号连接）：`hyperframes figma asset 'KEY:1-2' 'KEY:3-4' 'KEY:5-6'`。所有内容都在一个 `/v1/images` 调用中渲染，这是 figma 对每分钟速率限制的回答——在拉取整个框架的资产时，优先选择它而不是 N 个单独的命令。`--description`/`--entity` 适用于批量中的每个节点，因此批量节点共享相同的目的。429 也自动带退避重试。

## 标记（阶段 2 — CLI）

```bash
hyperframes figma tokens <fileKey>
```

导入变量作为组合品牌变量条目 + `figma-tokens.json` 侧边栏 + 绑定索引记录（`.media/figma-bindings.jsonl`）。变量在企业上游受限制：在其他计划上，该命令降级为发布样式元数据（值在组件导入时解析）。将打印的条目添加到组合的 `data-composition-variables`。

**在组件之前导入标记**，当两者都需要时——这就是允许组件颜色链接到品牌变量而不是烘焙副本的原因。

**非企业变量路径（经过测试的）**：REST 变量受企业限制，但兼容的连接器可能提供变量定义。当 `tokens` 报告 `REQUIRES_ENTERPRISE` 且连接器可用时，检索父场景的变量一次，将原始响应缓存到 `.media/figma-cache/`，并使用它来构建绑定索引。REST 节点树的 `boundVariables` 提供每个属性的 `VariableID`；按节点和属性连接它们，然后写入 `.media/figma-bindings.jsonl` 行（`{kind:"binding", figmaId, sourceFileKey, compositionVariableId: "figma:<name>", version}`）加上组合变量条目。下游所有内容（组件 `var()` 解析、刷新、运行时 CSS 变量）都是已发货的机械装置。为用户标记它：“通过 Figma 连接器导入的标记——企业计划直接通过 `hyperframes figma tokens` 获取此内容。”

运行时将每个声明的组合变量定义为一个 CSS 自定义属性（文档根 + 子组件托管），因此导入的 `var(--slug, literal)` 在变量默认值更改时填充重色——更新 `data-composition-variables` 中的一个值会重新品牌化每个导入的组件，而无需重新导入任何内容。`hyperframes render --variables '<json>'` 在渲染时覆盖它们。

## 组件（阶段 3 — CLI）

```bash
hyperframes figma component '<url-or-fileKey:nodeId>'
```

节点树 → 可编辑的 HTML，精确 figma 几何形状，作为 `compositions/components/<name>/` 下的注册项打包。矢量/布尔运算自动光栅化通过阶段-1 导出。绑定传递（规范 §7.1，仅精确 ID——从不匹配值）：

- **静态保真度自我检查（英雄内容强制要求）**：导入后，渲染片段并与 figma 自身的像素进行比较——`figma asset <相同节点> --format png` 是绝对真理。文本是已知漂移轴：比其行高短的 figma 文本框垂直修剪边界（映射器为这些发出 `text-box-trim`；没有它，测量漂移约为 6px 在 70px 字体的情况下）。如果比较显示映射器不涵盖的漂移，请报告它——不要在沉默中手动调整片段。
- 绑定到**导入**的标记 → `var(--slug, #literal)` — 品牌刷新传播。
- 绑定到**未知**的标记 → 字面量 + `data-figma-unresolved` 标志。命令告诉您；为用户提供选项：在源（或库）文件上运行 `tokens`，然后重新导入组件以链接它们。询问**一次**每个未知库它是哪个文件——永远不要猜测，永远不要通过十六进制匹配。

## 动画（阶段 4 — 连接器辅助）

**使用信标：** 连接器辅助阶段没有 CLI 端点，因此开始和结束时发射技能信标（匿名，同意控制，永远不会失败）：`npx hyperframes events --skill=figma-motion` 当您开始时，`npx hyperframes events --skill=figma-motion --event=skill_completed --outcome=success|error` 当完成时。相同适用于着色器（`figma-shaders`）和故事板（`figma-storyboard`）。

没有 REST 等价物。当有兼容的连接器时，使用它并将输出交给 `@hyperframes/core/figma` 中的纯辅助程序；否则请求原生导出：

1. 一次递归请求检索父框架的运动上下文，而不是每个元素一个请求。将原始 JSON 保存在项目旁边（`.media/figma-cache/`）以便重新翻译免费。
2. 使用 `motionContextToDocs(rawResponse, { selectorFor, repeat })` 从 `@hyperframes/core/figma` 规范化成 `MotionDoc`s — **永远不要手动转录关键帧编号**。辅助程序机械地编码经过测试的解码规则：它解析 motion.dev 片段（可靠的编码——CSS 片段拉伸持续时间，可能不一致；它们被忽略），剥离循环包装尾部关键帧（亚毫秒段在时间 ≈0.9999→1 是循环的即时重置，不是作者的运动——包装由 `repeat` 重启实现），并逐字保留贝塞尔缓动。`selectorFor` 必须返回来自阶段-3 组件导入的 ID——不要从节点名称派生选择器。
   2b. **在调用它完成之前与绝对真理进行验证——强制要求**：通过可用的连接器导出根框架，并运行 `node skills/figma/scripts/verify-motion.mjs --reference <export.mp4> --render <render.mp4> --crop WxH+X+Y` — 它比较运动能量差（静态导入保真度抵消）并失败在 15dB 最小运动-PSNR（校准：忠实 ≈ 20+，偏离 ≈ 5）。测量 `--crop` 从渲染的实际卡片边缘，不要猜测。失败意味着重新检查翻译，而不是阈值。
3. `motionToGsap(doc)` → `emitTimelineScript(spec)` → 作为 `<script>` 注入 GSAP + CustomEase CDN 标签之后。暂停，有限，注册在 `window.__timelines` 上，带有字面量键。
4. 不可翻译的轨道（着色器驱动，不受支持属性，复杂蒙版）→ 通过连接器导出，冻结 MP4，然后嵌入 `<video class="clip">`。例外：着色器驱动轨道——Figma 的导出路径将着色器扁平化为基础颜色（见下文着色器），在那里烘焙会无声丢失着色器；请要求用户进行原生 Figma 导出。始终说明您使用了什么路径以及为什么。映射集外的命名缓动会回退到线性——映射表存在于 `motionEase.ts` 中；当它触发时，向用户标记回退。
5. 在调用它完成之前运行 `npx hyperframes check`。

## 着色器（阶段 5 — 主要手动）

Figma 的连接器渲染路径不会执行着色器（它们会扁平化为基础颜色），并且着色器源仅可通过**库发布的**样式（付费全座席）访问。默认路径：要求用户在 Figma 中原生导出着色器帧（PNG 或运动 MP4），然后将其作为阶段-1 资源/剪辑导入。不要尝试连接器像素捕获着色器——它将无声地产生错误的东西。

## 故事板（场景帧的一部分 → 动画）

**基本规则：** 故事板帧是关键帧，不是幻灯片。包含相同元素的两个帧描述了该元素随时间的状态——在状态之间动画元素；永远不要按顺序播放故事板帧作为静止图像。在四个连续帧中绘制的标志在下降的 y 轴上是一个元素通过四个关键帧上升。播放故事板帧是失败模式；重建它们暗示的元素时间线是这项工作的任务。

故事板文件遵循一个您可以机械解析的语法——不要肉眼，解码：

1. **场景单元**：在 SECTION 内，每个帧大小的节点都是一个场景——命名 FRAME 和松散的全帧 RECTANGLE 都一样（设计师直接将静止图像粘贴到 SECTION 中）。按大小过滤（≈组合纵横比，例如 >1400×900），而不是按节点类型或名称。
2. **顺序 = x 位置**（如果胶片 strip 绕行，则按行主序）。按 `absoluteBoundingBox.x` 对场景进行排序。
3. **将相邻帧的差异转换为元素链**——动画就存在于这里。跨连续帧匹配子元素：首先按 **名称**（相同名称 = 相同元素 → 在状态之间插值其相对 x/y/w/h），然后按 **几何相似性**（相似大小 + 中心附近 = 相同逻辑元素，其像素已更改 → 在原地交叉淡入两个导出，同时插值几何；涵盖键入文本进展和变形状态）。未匹配的子元素在其场景的节拍进入/退出。帧背景填充作为颜色轨道淡入。每个链导出一个资源（仅在像素真正不同时每个状态导出一个）——永远不会每帧一个静止图像。
4. **静止图像是默认值，不是默认值**——仅用于无法分解的帧（扁平全帧截图，没有共享元素）；这些将得到下文的动画处理。
5. **导演笔记**：strip 下方的 TEXT 节点是运动意图，与它们 x 范围重叠的场景配对。它们描述了如何动画——它们不是屏幕上的文本。
6. **批量导出**（元素或静止图像）：`GET /v1/images` 接受逗号分隔的 ID，但当大场景帧超过 ~12 个 ID 时会触发“渲染超时”——将它们分成每调用 ~4 个，并重试。 （每个场景调用浪费速率预算；26 个场景 ≈ 52 个通过单个资源路径的调用。）
7. **注意动词 → 过渡**（起始词汇表，遇到时扩展）：

| 备注说明                       | 执行                                                         |
| ------------------------------- | ----------------------------------------------------------------- |
| 爆炸 / 爆裂                   | 输入比例 ~1.5→1 + 淡出，`power3.out`                        |
| 滑动 / 滑向… / 滚动           | 从该边缘方向滑动进入                                       |
| 变形 / 揭示                   | 淡入淡出 — 或如果运动在单个场景内，则使用 Phase-3 导入       |
| 循环播放 / 每个元素            | 更长的保持时间 — 或如果元素在场景内动画，则使用 Phase-3 导入 |
| （无备注）                     | 淡入淡出 + 缓慢的 Ken-Burns 漂移                           |

8. **静态图像与组件路由**：描述场景之间运动的备注 → 在静态图像上应用过渡（上方）。描述场景内部运动的备注（“文本行逐一揭示”，“药丸动画进入”）→ 该帧值得使用 Phase-3 组件导入（真实元素）根据备注进行动画，而不是扁平的 PNG。先使用静态图像进行动画预览，然后升级备注中特别指出的场景。
9. 一个 `main` 时间轴序列所有内容（每个场景的透明度/x/y 在绝对时间点） — 不需要为动画预览创建每个场景的子合成。
10. **升级 — 帧描绘一个产品 UI → 重建应用程序，而不是元素链。** 当连续帧是相同应用程序屏幕在不同状态时（注册流程、设置面板、播放器），元素链会低估其价值。将 UI 重建为实时 DOM — Phase-3 组件导入用于状态变化的部件，静态的边框使用真实导出的像素（**改变状态的部分编写代码，不变的部分冻结**）— 并将每个帧的差异视为一个**要执行的交互**，而不是要应用的补间：光标进入，点击控件，状态响应，屏幕推/滑作为真实导航。结果读作一个工作应用程序的连续屏幕录制。这是针对 UI 流程的指导原则的最终结论；静态图像/元素链处理适用于不是连贯应用程序的故事板。

## 确定性

永远不要在合成中留下 Figma URL — 先冻结。永远不要发出 `repeat: -1`。时间轴暂停，有限，字面的 `window.__timelines` 键。所有 Figma I/O 在导入时进行；渲染仅看到本地文件。
