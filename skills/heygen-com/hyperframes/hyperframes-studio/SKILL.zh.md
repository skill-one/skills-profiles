# HyperFrames Studio 规范

Studio 为每个顶层元素绘制一行时间线。遵循以下规则的项目将以简短、可读的时间线形式打开；反之，则打开一堵无法编辑的无标签行墙。这些是构建的规范。要更改剪辑，请遵循 `/hyperframes-core` `references/creator-editing-recipes.md`，切勿发明同种编辑的不同形式。

## 0. 构建前先沟通

打开文件前阅读消息。决定它要求什么：

| 人员                                                                                             | 你                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 提出变更请求，无论多么礼貌（“让标题更大”，“你能删掉第三场吗？”）                               | 执行。                                                                                                                                                              |
| 对构建的影片给出反馈（“开场感觉太突兀”，“时长不够”）                                           | 找到原因，改变可测量的东西，说明反馈含义及所做的改动，并按照 `/hyperframes-creative` `references/storyboard-recipe.md` § 4 记录。 |
| 提出问题但未提出变更请求（“标题为何跳跃？”）                                                   | 回答。不做任何改动。                                                                                                                                            |
| 表示不要更改任何东西，保持，"只是思考"，"我们聊聊"                                             | 不更改任何文件，甚至不修复你注意到的错误。用文字提出建议。                                                                                                        |
| 带来此影片的新想法但无具体变更（“我想让结尾更有冲击力”）                                        | 提出变更并将其添加到计划（下方）。不更改任何构图文件。                                                                                                              |
| 要求制作新影片                                                                      | 计划它（§ 5）。                                                                                                                                                  |
| 批准计划（“构建它”，“开始”）                                                              | 构建已批准的内容。                                                                                                                                              |

一个既提出问题又提出变更请求的消息会得到回答和变更。只有当你无法判断它是否要求任何东西时，它才是一段对话：一个错误的回答会浪费一条消息；一个错误的构建会浪费很长时间和一轮笔记。

对话回复：

- 首先用平实的语言，用几句话回答。
- 只问那些回答会改变影片的问题，每个问题都应有推荐答案及其权衡（“30 秒适合信息流；60 秒为演示留出空间”）。
- 当有需要塑造的想法时：对于新影片，按照 `/hyperframes` `references/pitch-round.md` 的指导；对于此影片的想法，为所提部分提供两到三个选项。推荐一个。
- 以下一步行动和其起始词结束（“说构建，我会开始”）。

将计划保存在项目中，而不仅限于聊天：下一条消息可能会开始一个无法看到此条消息的新会话。按照 `/hyperframes-creative` `references/storyboard-recipe.md` § 4 记录一轮的方式将计划添加到 STORYBOARD.md；切勿覆盖锁定的帧。如果被要求不做任何更改，则不写任何内容：将计划放在回复中，并提出保存它。

## 1. 每个场景都是一个子构图

根构图只包含带时间的宿主、媒体和音频。任何具有嵌套结构（一个包含子元素的 div、一个带副标题的标题、一个图表）的场景都是自己的文件，通过 `data-composition-src` 加载，并按照 `references/sub-compositions.md` 连接。

嵌套的标记保留在根构图中不会成为自己的行。它隐藏在一个不可见的行中，该行无法部分修剪或移动。

像结构 lint 拒绝任何违规一样编写。

## 2. 一个字幕轨道

- 所有字幕都在一个轨道上：一个单一的子构图宿主（一个 `data-track-index`）标记为 `data-track-kind="captions"`，它按顺序携带每个字幕组。
- 永远不要每个字幕组一行，也永远不要将字幕混合到另一个类型的轨道上。
- 字词时间规则保持不变：参见 `/embedded-captions` 和 `caption_*` lint 规则。

## 3. 每个轨道一个元素类型

按类型分组，以便每行是用户可以选择、静音或作为一组拖动的单个事物。

| 类型                                    | `data-track-kind`      |
| --------------------------------------- | ---------------------- |
| 基础视频 / A-roll                     | `video`（来自标签）    |
| 场景、叠加层、图形                    | `graphics`             |
| 字幕                                    | `captions`             |
| 音频（旁白、音乐、音效）               | `audio`（来自标签）    |

将 `data-track-kind` 放在子构图宿主上。视频和音频类型来自标签，因此 `<video>` 和 `<audio>` 无需属性。给每种类型分配自己的 `data-track-index`；数字仅用于显示；它永远不会改变渲染的顺序。使用 CSS 进行层叠。

## 4. 安全区域

任何标尺或安全框覆盖都存在于预览窗格中，而不是构图中，因此不要将指南元素添加到 HTML 中。
宽屏和垂直两种构图都使用相同的安全框，即 Premiere 的默认设置。预览切换器在每个边缘的中点绘制一个标记。来源：`ACTION_SAFE_PERCENT` 和 `TITLE_SAFE_PERCENT` 在 `packages/studio/src/utils/previewSafeMargins.ts` 中。

| 框         | 帧的占比 | 每个边缘的填充 |
| ----------- | -------- | ------------- |
| Action-safe | 90%      | 5%            |
| Title-safe  | 80%      | 10%           |

- 安全边距：所有可见内容都应保留在动作安全框（90%）内，字幕和关键内容应保留在标题安全框（80%）内。
- 上下布局和 50/50 布局应使每半部分的内容都保留在标题安全框内。

## 5. 新影片：计划、故事板、构建

[hyperframes-launches](https://github.com/heygen-com/hyperframes-launches) 影片是按以下顺序制作的。每个步骤都有负责人；遵循它，不要在此处重述。

| 步骤          | 负责人                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. 简报      | `/hyperframes` `references/intent-interview.md`。在现有项目中，只有对同一影片的后续项目保持：新版本或剪辑，相同的工作流程和纵横比。问必须有的问题，跳过 `hyperframes init`，永远不要覆盖 BRIEF.md 或 STORYBOARD.md，为每个文件添加新的日期部分，并在回复中说明。一个具有不同工作流程或纵横比的电影开始一个新项目，回复中会说明。 |
| 2. 指导      | `/hyperframes` `references/pitch-round.md`                                                                                                                                                                                                                                                                                                                                                                                     |
| 3. 故事板    | `/hyperframes-creative` `references/storyboard-recipe.md`                                                                                                                                                                                                                                                                                                                                                                      |
| 4. 构建      | 简报路由的工作流程（`/hyperframes` § 2）及其自己的参考                                                                                                                                                                                                                                                                                                                                                                          |
| 5. 笔记      | `/hyperframes` `references/review-loop.md`                                                                                                                                                                                                                                                                                                                                                                                     |

[hyperframes-launches](https://github.com/heygen-com/hyperframes-launches) 影片添加的，对于产品发布。当工作流程选择的道路与此相反时，道路优先。

- **真实素材用于发布的产物。** 在简报中要求屏幕录制，除非工作流程本身捕获它（从其 URL 获取的网站），并使用标记占位符保留其位置，直到它到来。永远不要模拟发布产物的 UI。作为背景显示的第三方工具（聊天应用、编辑器）需要忠实地从捕获中重建。
- **一个世界。** 同一个窗口或画布贯穿所有节奏。擦拭每个剪辑：任何持续存在的东西都不能跳跃。
- **光标和滚动内容。** 光标或窗口本身滚动出去的内容通过窗口或框架边缘离开，而不是在帧中段淡出。元素和文本交换遵循工作流程的 `cut-catalog.md`，如果它有的话。
- **在命令或地址上关闭，标志出现在仍在移动的素材中。**
- **在每个版本中声明运行时间。** 超过目标运行时间是由用户决定，而不是你。

## 检查你的工作

运行 `hyperframes lint` 并修复所有发现。然后以 Studio 打开项目，并检查时间线显示基础行、每个场景宿主一行、字幕行和音频行。
