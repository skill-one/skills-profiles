# 字幕叠加原则

> **叠加原则 — 补充上游 `embedded-captions` 技能。应用于其之上；不要期望它被合并到上游技能中。**

这里结合了两个概念。首先，**字幕模型** — 每个口语片段是 `drop`、`rail` 或 `embed`，其中 `embed` 是稀缺的、通过努力获得的顶峰，而非默认选项。其次，**叠加法则** — 字幕行作为叠加层叠加在影片之上；它不是保留区域，因此你永远不会向上移动内容或留出空白区域“为其腾出空间”。这两个概念相互强化：因为字幕作为叠加层呈现（逐字记录的 `rail` 位于前方，偶尔的 `embed` 位于主体后方），构图能保持完整画幅并居中于真正的垂直中心。

## 字幕模型 — drop / rail / embed

每个口语片段属于以下三种情况（源自 `embedded-captions` 的逐字记录）：

|           | 内容类型                                     | 显示方式                                                                                                                                                    |
| --------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **drop**  | 填充词 — um/uh、结巴、自我修正               | 不显示                                                                                                                                                         |
| **rail**  | 默认选项 — 普通口语内容（逐字记录）            | 干净的底部三分之一字幕，**位于前方**，可读。强调词可以获得内联 `emphasis` 高亮（强调色/活跃词弹出）—— 它会保持在 `rail` 上。 |
| **embed** | 推广的顶峰 — 标题性强词                      | 一个大字叠加在**主体后方**（磨砂遮挡），设计好的进入和退出效果                                                                        |

**`rail` 承载大部分文本；`embed` 是稀缺的、通过努力获得的顶峰** — ≤1 个/节拍，永远不会相邻/同时可见，间隔 ≥ 一个节拍。短片段 → 通常一个 `embed`；长解释性内容 → 约 一个/节。逐字嵌入是常见错误。

这是**标准**模式形状（`rail` = 逐字记录的底部三分之一；`embed` = 叠加在主体后方的顶峰）。**电影感**模式丢弃 `rail` 并使所有内容都采用 `embed` 风格 — 仅用于纯电影感请求，绝不用于解释性/旁白内容，其中文字必须可读。

### 优先 `rail`、稀缺 `embed`（承重规则）

引自 `embedded-captions` 的不可协商原则：

- **口述片段/解释性内容优先 `rail`。** 不要嵌入整个文稿 — 大部分文本是 `rail`；仅嵌入顶峰。嵌入所有内容是默认错误。
- **`embed` 稀缺且间隔。** ≤1 个 `embed` 每个/节拍，永远不会相邻或同时可见，间隔 ≥ 一个节拍，最多一个 `apex`。顶峰 = 每节拍顶峰，**不是**“整个片段的唯一回报。”

## 叠加法则 — 字幕不是保留区域

在生成的发布构图时，当字幕启用时，将最终合成**一个小的、极简的逐字字幕行**作为叠加层叠加在整个影片之上（单行文本，底部居中，约画布高度的底部 5-8%）。它是一个叠加层，不是保留区域（源自产品发布视频场景代理的限制 #13）：

- **将构图居中于真正的垂直中心 — y = H / 2**（横屏 540，竖屏 960）。不要向上移动内容“为字幕腾出空间”；以 0.42 × H 居中且底部有空白带的构图是错误，不是解决方案。
- 内容可以延伸至画布底部。全出血主体、`rail` 和背景都受欢迎。
- **一条柔和的礼貌规则：** 避免将**关键的小可读文本**（URL 行、法律行、子字幕）正好停靠在字幕行所在的底部 ~80px 居中跨度内 — 叠加层会与之冲突。字幕下方的大图像/卡片/环境内容是没问题的；字幕皮肤设计为可覆盖内容。
- 没有机器保留门禁（旧的 `captions.mjs keepout` 检查已退役）。最终快照 QA 通过视觉判断字幕覆盖内容的可读性。

**当字幕禁用时：** 相同的定位自由度 — 叠加层仅不存在。

## 为什么这两个规则是一个原则

模型指出 `rail` 骑在**前方**，而 `embed` 是一个罕见的字叠加在**主体后方** — 两者都是添加到未经修改的影片上的层。叠加法则指出字幕行是一个叠加层，叠加在**整个影片之上**，而不是从布局中切割出的区域。因此，在字幕处理流程和发布视频流程中，字幕都是你添加的叠加层，而不是你保留的区域：

- 保持完整画幅；居中于真正的中心；让内容延伸至边缘。
- 使 `rail`（或小型叠加字幕行）承载逐字记录的词。
- 仅在真正的顶峰时将词提升为 `embed` — 稀缺、间隔，永远不会同时出现。
- 保留任何内容；通过视觉判断字幕覆盖内容的可读性，而不是通过保留门禁。
