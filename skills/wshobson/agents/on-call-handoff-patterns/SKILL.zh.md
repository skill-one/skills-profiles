# 接班交接模式

有效的交接班模式，确保交接班期间工作的连续性、信息传递和可靠的事件响应。

## 使用此技能的场景

- 交接值班职责
- 撰写交接班总结
- 记录进行中的调查
- 建立值班轮换流程
- 提高交接班质量
- 新值班工程师入职培训

## 核心概念

### 1. 交接班内容

| 内容项                  | 目的                 |
| ---------------------- | -------------------- |
| **活跃事件**       | 当前出现的问题       |
| **进行中的调查** | 正在调试的问题     |
| **近期变更**         | 部署、配置变更     |
| **已知问题**           | 已有的临时解决方案   |
| **即将发生的事件**        | 维护、发布计划     |

### 2. 交接班时间安排

```
建议：交接班有30分钟的重叠时间

交接班方：
├── 15分钟：撰写交接班文档
└── 15分钟：与接替方进行同步通话

接替方：
├── 15分钟：审阅交接班文档
├── 15分钟：与交接班方进行同步通话
└── 5分钟：验证告警设置
```

## 故障排除

**接替方工程师因交接班文档不完整而遗漏了关键问题。**
使用交接班方检查清单作为关键节点：直到每个部分至少有一条记录（或明确的“无”），才标记交接班完成。将不完整的交接班作为无责复盘行动项。

**由于时区差异，无法进行30分钟的同步通话。**
回退到异步快速交接班模板（模板2）。补充使用简短的Loom或语音备忘录，概述监控列表。确保接替方工程师在有问题时能直接联系到值班人员。

**接替方工程师接手进行中的事件，并立即感到不知所措。**
使用事件交接班模板（模板3）。交接班方应在交接班后15分钟内保持Slack在线，即使不在值班状态，也要回答澄清问题。

**不同团队之间交接班文档格式不一致。**
在全公司范围内采用交接班模板，并将完成的交接班文档存储在共享位置（维基、Notion、Confluence）。从PagerDuty中的值班安排条目链接到每个交接班文档。

**接替方工程师在交接班方下线前无法验证告警是否正常工作。**
增加标准步骤：交接班方发送测试告警，并确认接替方在PagerDuty和Slack中收到告警，然后结束重叠窗口。
