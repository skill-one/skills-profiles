# 驱动式开发

实现和维护上下文作为代码的配套管理工件指南，通过结构化的项目文档实现一致的AI交互和团队协作。

## 使用此技能的场景

- 使用Conductor设置新项目
- 理解上下文工件之间的关系
- 在AI辅助开发会话中保持一致性
- 将团队成员引入现有的Conductor项目
- 决定何时更新上下文文档
- 管理新建项目（greenfield）与现有项目（brownfield）的上下文

## 详细模式和实例

详细模式文档位于`references/details.md`。当上层导航层级不足时，请阅读该文件。

## 最佳实践

1. **先读上下文**：开始工作前始终阅读相关工件
2. **小步更新**：进行增量式上下文变更，而非大规模重写
3. **关联决策**：在做出实现选择时参考上下文
4. **版本控制上下文**：将上下文变更与代码变更一同提交
5. **代码评审中审查上下文**：将上下文工件评审纳入代码评审
6. **定期验证**：在重大工作前运行上下文验证清单
7. **变更沟通**：当上下文工件发生显著变更时通知团队
8. **保留历史**：使用git追踪上下文随时间演变的历程
9. **质疑陈旧性**：若上下文感觉不正确，应调查并更新
10. **保持可操作性**：每个上下文项都应指导决策或行为
