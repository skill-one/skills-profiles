# 会话保护

## 概述

长会话会无声地损坏。上下文压缩会突然丢失指令。钩子无法修复这个问题（GitHub问题#19471、#9796、#64171中多位开发者已确认）。这项技能通过行为自我约束来防止这两种情况：监控健康状态，通过压缩锚定关键规则，在损坏发生前拆分会话。无需包，无需数据库——纯粹的基于行为约束的解决方案，适用于任何环境。

## 使用场景

- 会话超过40次工具调用
- 代理与先前决策矛盾
- 风格/命名规范开始偏离
- 任何上下文压缩事件之后
- 任务范围无界增长

## 健康信号

| 信号 | 阈值 | 动作 |
|------|------|------|
| 工具调用次数 | >40 | 黄色：检查点 + 重申关键规则 |
| 工具调用次数 | >60 | 红色：拆分或锚定压缩 |
| 代理与先前决策矛盾 | 任何 | 核实：重读事实依据 |
| 风格/命名偏离 | 任何 | 重申：大声说出当前规则 |
| 文件读取返回意外内容 | 任何 | 重读：不信任缓存状态 |
| 任务范围无界增长 | 持续 | 拆分：每个会话一个任务 |

## 协议

### 绿区（0-40次工具调用）
正常操作。无需干预。

### 黄区（40-60次工具调用）
1. 检查点 - 用一句话总结进度
2. 重申 - 大声说出3-5条最关键的活动规则："当前规则：[命名规范]、[文件结构]、[错误处理模式]、[测试要求]"
3. 评估 - 几乎完成？继续推进。未完成？准备拆分
4. 减少 - 无探索性读取。仅执行目标操作。

### 红区（60次以上工具调用或偏离信号）
1. 停止 - 不再进行工具调用
2. 核实 - 重读项目规则（不信任记忆）
3. 检查点 - 将状态写入交接文档
4. 拆分 - 创建交接内容，建议新会话

## 上下文锚定（反压缩）

当发生压缩时（突然丢失先前上下文，或执行/compact之后）：

1. 立即重读项目的规则文件
2. 在回应中大声说出3-5条关键规则
3. 在执行前核实计划的下一条操作是否与规则一致
4. 如对任何先前决策不确定，重读源文件——不要猜测

### 压缩中保留的内容：
- 最新的用户消息（高优先级）
- 当前调用的技能体（限制5K个token，最旧的先被丢弃）
- Git状态和项目结构
- 压缩后读取的文件内容

### 压缩中丢失的内容：
- 会话早期做出的决策
- 仅口头说明的架构规则（未写入文件）
- 工具输出中的上下文（文件读取、命令输出）

### 安全压缩模式
将关键指令保存在文件（CLAUDE.md、CONTEXT.md）中，而不是对话中。如果规则重要，它必须存在于代理可以重读的文件中——而不是先前达成共识的内容。

## 常见错误

- 认为在50次以上工具调用后仍记得规则（实际上不记得——重读）
- 为了安全而重读所有内容（浪费工具调用——要目标明确）
- 感觉良好因此假设上下文良好（压缩是无声的）
- 在发现问题后才拆分（应在问题前拆分——预防而非恢复）

## 重要性

上下文压缩是2026年未解决的#1平台问题。钩子无法修复它（确认：代理忽略压缩后注入的内容，因为压缩摘要创建了叙事惯性）。这项技能是轻量级的行为性反制措施：无需基础设施，无需包——在任何环境中都有效的自律自我监控。
