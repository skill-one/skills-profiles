# Unity ECS模式

Unity数据导向技术栈（DOTS）的生产模式，包括实体组件系统、作业系统和爆发编译器。

## 何时使用此技能

- 构建高性能Unity游戏
- 高效管理数千个实体
- 实现数据导向的游戏系统
- 优化CPU密集型游戏逻辑
- 将面向对象游戏代码转换为ECS
- 使用作业和爆发进行并行化

## 核心概念

### 1. ECS与OOP

| 方面      | 传统面向对象   | ECS/DOTS        |
| ----------- | ----------------- | --------------- |
| 数据布局 | 面向对象   | 数据导向   |
| 内存      | 分散         | 连续      |
| 处理  | 按对象        | 批量处理         |
| 扩展性     | 计数时扩展性差   | 线性扩展  |
| 最适合    | 复杂行为 | 大规模模拟 |

### 2. DOTS组件

```
Entity: 轻量级ID（无数据）
Component: 纯数据（无行为）
System: 处理组件的逻辑
World: 实体的容器
Archetype: 组件的唯一组合
Chunk: 相同原型实体的内存块
```

## 最佳实践

### 应该做

- **使用ISystem而不是SystemBase** - 性能更好
- **所有内容都进行爆发编译** - 大幅提升速度
- **批量进行结构变化** - 使用ECB
- **使用Profiler进行性能分析** - 识别瓶颈
- **使用Aspects** - 清晰地分组组件

### 不应该做

- **不要使用托管类型** - 会破坏爆发编译
- **不要在作业中进行结构变化** - 使用ECB
- **不要过度设计** - 从简单开始
- **不要忽略块利用率** - 将相似实体分组
- **不要忘记释放** - 原生集合会泄漏
