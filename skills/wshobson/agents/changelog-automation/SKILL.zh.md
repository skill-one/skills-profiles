- 设置自动化版本更新日志生成

- 创建发布说明工作流

- 管理语义化版本控制

## 提交信息示例

```bash
# 带范围的特性
feat(auth): 为 Google 登录添加 OAuth2 支持

# 带问题引用的 Bug 修复
fix(checkout): 解决支付处理中的竞态条件

Closes #123

# 不兼容变更
feat(api)!: 修改用户端点响应格式

BREAKING CHANGE: 用户端点现在返回 `userId` 而不是 `id`。
迁移指南：更新所有 API 消费者以使用新的字段名。

# 多段落
fix(database): 优雅处理连接超时

之前，连接超时会导致整个请求失败且不重试。此变更实现了指数退避，最多重试 3 次后才失败。

根据 p99 延迟分析，超时阈值已从 5s 提升至 10s。

Fixes #456
Reviewed-by: @alice
```

## 最佳实践

### 应该做

- **遵循常规提交** - 启用自动化
- **编写清晰的提交信息** - 未来的你会感谢你
- **引用问题** - 将提交与工单关联
- **一致使用作用域** - 定义团队规范
- **自动化发布** - 减少手动错误

### 不应该做

- **不要混合变更** - 每个提交只包含一个逻辑变更
- **不要跳过验证** - 使用 commitlint
- **不要手动编辑** - 仅使用生成的版本更新日志
- **不要忘记不兼容变更** - 用 `!` 或页脚标记
- **不要忽略 CI** - 在流水线中验证提交
