# 向量索引调优

用于生产性能优化的向量索引调优指南。

## 何时使用此技能

- 调整 HNSW 参数
- 实现量化
- 优化内存使用
- 降低搜索延迟
- 平衡召回率与速度
- 扩展至数十亿向量

## 核心概念

### 1. 索引类型选择

```
数据量           推荐索引
────────────────────────────────────────
< 10K 向量  →    Flat（精确搜索）
10K - 1M       →    HNSW
1M - 100M      →    HNSW + 量化
> 100M         →    IVF + PQ 或 DiskANN
```

### 2. HNSW 参数

| 参数          | 默认值 | 效果                                               |
| ------------- | ------ | -------------------------------------------------- |
| **M**         | 16     | 每个节点的连接数，↑ = 召回率更好，内存消耗更多 |
| **efConstruction** | 100    | 构建质量，↑ = 索引质量更好，构建速度更慢        |
| **efSearch**   | 50     | 搜索质量，↑ = 召回率更好，搜索速度更慢         |

### 3. 量化类型

```
全精度 (FP32): 4 字节 × 维度
半精度 (FP16): 2 字节 × 维度
INT8 标量:           1 字节 × 维度
产品量化:            ~32-64 字节总计
二进制:               维度/8 字节
```

## 最佳实践

### 应该做

- **使用真实查询进行基准测试** - 合成数据可能无法代表生产环境
- **持续监控召回率** - 可能因数据漂移而下降
- **从默认值开始** - 仅在需要时调优
- **使用量化** - 显著节省内存
- **考虑分层存储** - 热数据/冷数据分离

### 不应该做

- **不要过早过度优化** - 先进行性能分析
- **不要忽略构建时间** - 索引更新有成本
- **不要忘记重新索引** - 计划维护工作
- **不要跳过预热** - 冷索引速度较慢
