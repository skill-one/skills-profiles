# CQRS 实现

实现 CQRS（命令查询责任分离）模式的全面指南。

## 何时使用此技能

- 分离读写关注点
- 独立地扩展读操作与写操作
- 构建事件溯源系统
- 优化复杂查询场景
- 需要不同的读写数据模型
- 高性能报表需求

## 核心概念

### 1. CQRS 架构

```
                    ┌─────────────┐
                    │   客户端    │
                    └──────┬──────┘
                           │
              ┌────────────┴────────────┐
              │                         │
              ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │  命令      │          │   查询      │
       │    API      │          │    API      │
       └──────┬──────┘          └──────┬──────┘
              │                         │
              ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │  命令处理程序  │          │   查询处理程序  │
       │                │          │                │
       └──────┬──────┘          └──────┬──────┘
              │                         │
              ▼                         ▼
       ┌─────────────┐          ┌─────────────┐
       │   写模型    │─────────►│    读模型    │
       │                │          │                │
       └─────────────┘          └─────────────┘
```

### 2. 关键组件

| 组件           | 责任                  |
| -------------- | --------------------- |
| **命令**         | 改变状态的意图          |
| **命令处理程序** | 验证并执行命令          |
| **事件**           | 状态变化的记录          |
| **查询**           | 数据请求                |
| **查询处理程序**   | 从读模型检索数据        |
| **投影器**       | 从事件更新读模型        |

## 最佳实践

### 应该做的

- **分离命令和查询模型** - 不同的需求
- **使用最终一致性** - 接受传播延迟
- **在命令处理程序中验证** - 在状态改变之前
- **非规范化读模型** - 优化查询
- **版本化事件** - 用于模式演进

### 不应该做的

- **命令中不要查询** - 仅用于写操作
- **不要耦合读写模式** - 独立演进
- **不要过度设计** - 从简单开始
- **不要忽视一致性 SLA** - 定义可接受的延迟
