# 财务洞察

使用此技能回答有关用户 Link 财务数据的只读问题。
使用发现的挂载前缀调用扩展的原生工具，例如
`link__list_transactions`。输入和结果都是结构化对象；使用工具模式定义参数名称和约束。

对于购买或支付凭证，请加载挂载的
`create-payment-credential` 技能。

## 身份验证和访问

应用程序配置钱包和授权提供程序。如果 Eve 请求用户连接 Link，请先完成该授权，然后再继续。
不要在聊天中请求令牌。如果访问被拒绝或工具报告缺少权限，请说明无法检索哪些数据并停止。不要重复尝试相同的拒绝操作。

## 选择正确的工具

使用能回答问题的最小集合。

| 用户询问关于 | 工具 |
| --- | --- |
| 购买、商家、支出、收入、存款、定期付款 | `list_transactions` |
| 当前余额、可用资金、现金状况 | `list_balances` |
| 已连接账户、来源详情、数据能力 | `list_sources` |

对于上个月的餐厅支出，检索该时期的交易。
对于账户余额，检索余额。对于已连接的账户，检索来源。仅在问题需要时才组合工具，例如将来源名称连接到余额。

## 金额和来源

财务数据金额是以货币最小单位表示的整数。使用货币的 ISO 4217 次要单位指数格式化；不要总是除以 100。
例如，`152340` 表示 $1,523.40 USD。

只有交易 `amount` 使用负值表示账户资金流出，使用正值表示资金流入。根据余额类型解释余额字段。在聚合时保持货币分离。

来源是连接到 Link 的账户。使用其 `id` 来连接显示 `source_id` 的记录。不要猜测哪个账户拥有 `source_id` 为空的交易。来源可以描述银行、卡和其他账户类型。

## 交易

使用相关过滤器调用 `list_transactions`，例如：

```json
{
  "start_date": "2025-01-01",
  "end_date": "2025-01-31",
  "category": "groceries",
  "origin": "external_connection",
  "sources": ["<source_id>"],
  "limit": 100
}
```

根据用户的问题选择日期和过滤器；省略不必要的字段。

| 输入 | 含义 |
| --- | --- |
| `start_date`, `end_date` | `YYYY-MM-DD` 格式的包含日期 |
| `category` | 类别过滤器 |
| `origin` | `link` 或 `external_connection` |
| `sources` | 来源 ID 数组 |

有用的响应字段：

| 字段 | 解释 |
| --- | --- |
| `amount` | 负值表示流出；正值表示流入 |
| `origin` | Link 原生或来自外部连接 |
| `category` | 未分类时可能为 null |
| `status` | API 提供的状态；不要假设一组固定的值或在不了解其含义的情况下解释/过滤未知状态 |

区分支出与信用、存款和退款。说明报告的总额是毛支出还是净变动。仅在相关时按商家、类别、来源、货币或时期进行分组。根据有限窗口或部分分页相应地标记摘要。

## 余额

使用 `{}` 获取初始页面，或按来源过滤：

```json
{ "sources": ["<source_id>"], "limit": 100 }
```

| 字段 | 解释 |
| --- | --- |
| `type` | `cash` 或 `credit`；决定哪个子对象存在 |
| `current` | 挂起交易前的余额；不一定是可用资金 |
| `cash.available` | 考虑挂起活动后的货币到金额映射，用于可用现金 |
| `credit.used` | 信用已使用的货币到金额映射 |
| `as_of` | 最后更新时间；数据可能已过时 |

使用 `current` 回答一般余额问题，使用 `cash.available` 当用户询问可用现金时。不要将已使用的信用呈现为可用资金。
保留货币，按来源汇总，并提及相关的新鲜度限制。

## 来源

使用 `{}` 或分页参数调用 `list_sources`。

| 字段 | 含义 |
| --- | --- |
| `id` | 余额和交易使用的来源标识符 |
| `name`, `type` | 显示名称和账户类型 |
| `capabilities` | 具有状态值的数据能力，例如 `balances.status` |
| `external_connection.status` | 外部机构处的连接状态 |
| `granted_actions` | 用户为此来源授予的操作 |

使用能力和授予的操作来了解哪些数据可以访问。
在相关时总结机构、账户类型和连接状态。避免泄露完整的账户号码、令牌或不必要的标识符。

## 分页

所有三个工具都接受：

| 输入 | 含义 |
| --- | --- |
| `limit` | 每页结果，从 1 到 100 |
| `starting_after` | 下一页的游标 |
| `ending_before` | 反向导航的游标 |

响应包含 `data`，可能包含 `has_more`。当 `has_more` 为 true 时，从最后一个返回的项目中推导出 `starting_after`：

| 工具 | 游标字段 |
| --- | --- |
| `list_transactions` | `id` |
| `list_balances` | `source_id` |
| `list_sources` | `id` |

例如，使用相同的过滤器继续交易查询，并使用
`starting_after: "<last_transaction_id>"`。仅跨页面更改游标。
当 `has_more` 为 false 或不存在，或当用户的非穷尽查找满足时停止。如果报告了更多结果但页面为空或缺少可用游标，停止并解释分页无法继续。

当需要完整的有界结果时（例如指定月份的总额）进行完全分页。不要将部分页面的总和呈现为完整总额。

## 回答问题

首先陈述答案，然后是相关时期和来源。提及限制，例如缺少类别、挂起活动、过时的余额、部分结果或无法访问的账户。总结而不是倾倒原始记录或对象 ID。

如果工具返回没有匹配的数据，说明对于请求的过滤器和访问没有可用数据。这不能证明没有活动发生或无法访问的余额为零。将不确定的派生见解报告为不确定。

此技能不会移动资金、发起支付或修改来源。仅检索相关的财务数据，并永远不会暴露支付凭证。
