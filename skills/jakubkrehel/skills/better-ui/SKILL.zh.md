# UI 精细打磨

精细打磨源于众多微小细节的累积。这项技能是衡量哪些元素值得保留及其价值的标准。

在评审时，减慢界面的运行速度。在 10% 速度下感觉不对劲的地方，在全速下也微妙地存在问题。

保持项目的组件库、样式令牌和密度，并匹配其动效语言，除非以下规则中规定了确切的交互方式。

下方的每个持续时间、曲线、缩放和模糊效果都是特定值，而非近似范围。`cubic-bezier(0.2, 0, 0, 1)` 不是 `cubic-bezier(0.4, 0, 0.2, 1)`，`0.96` 也不是 `0.95`。使用指定的值。

文本换行、字体渲染、表格数字和文本间距属于 `better-typography`。点击区域、焦点、键盘支持和 ARIA 以及减少动画属于 `better-accessibility`。分组、分区间距、断点以及空间 RTL 属于 `better-layout`。

## 同心圆边框半径

外半径 = 内半径 + 内边距。嵌套元素上不匹配的半径是导致界面感觉异常的最常见问题。半径、阴影和轮廓配方在 [surfaces.md](surfaces.md) 中。

## 视觉对齐而非几何对齐

当几何中心对齐看起来不对时，进行视觉对齐。带图标的按钮、播放三角形和非对称图标都需要手动调整。

## 通过阴影提升层级，通过边框结构化

当边框仅用于创建深度时，优先使用分层透明 `box-shadow` 值。保留用于传达结构或状态的边框：分隔符、分隔线和选中或焦点状态。

## 可中断的动画

使用 CSS 过渡效果进行交互状态变化，因为它们可以在动画中途中断。保留关键帧用于一次性运行的阶段性序列。

## 分割和错开进入动画

对于不频繁的阶段性进入，且序列传达层级关系时，将内容分割为语义块并错开约 100ms。动画一个容器获得的收益与相同成本相比更少。保留高频交互不进行错开。参见 [enter-exit.md](enter-exit.md)。

## 微妙的退出动画

使用小的固定 `translateY` 而非全高度。退出应比进入更柔和。两个方向都使用 `ease-out`。

## 上下文图标动画

使用 `opacity`、`scale` 和 `blur` 动画图标而非切换可见性。使用确切值：缩放 `0.25` 到 `1`，不透明度 `0` 到 `1`，模糊 `4px` 到 `0px`。

使用动效库（`motion` 或 `framer-motion` 在 `package.json` 中），匹配该包的导入路径，或在两者都存在时匹配附近的导入。使用 `transition: { type: "spring", duration: 0.3, bounce: 0 }`。弹跳始终为 `0`。

没有动效库时，将两个图标保留在 DOM 中，其中一个绝对定位，并使用 `cubic-bezier(0.2, 0, 0, 1)` 进行交叉渐变。这提供了无依赖的进入和退出。两种配方在 [icon-transitions.md](icon-transitions.md) 中。

## 图像轮廓

为图像添加低不透明度的 `1px` 轮廓以保持一致深度。亮模式下的纯黑色 (`oklch(0 0 0 / 0.1)`)，暗模式下的纯白色 (`oklch(1 0 0 / 0.1)`)。绝不使用接近黑色的颜色如 Slate 或 Zinc，也绝不使用带色的中性色。带色的轮廓会吸收下方表面并使图像边缘看起来像污渍。

## 点击缩放

点击时使用 `scale(0.96)` 给按钮提供触觉反馈。始终为 `0.96`；低于 `0.95` 的感觉会夸张。在动效会分散注意力时添加 `static` 属性以关闭它。参见 [recipes for CSS, Tailwind and Motion](animations.md#scale-on-press)。

## 页面加载时跳过动画

在 `AnimatePresence` 上使用 `initial={false}` 以避免首次渲染时出现进入动画。检查它是否保留了有意为之的页面进入。

## 主题切换时抑制过渡

主题切换会同时改变几乎所有元素的颜色、背景、边框和阴影。这些属性的每个过渡效果同时触发，切换效果会模糊而非瞬间。注入 `*,*::before,*::after{transition:none !important}`，强制重排，然后在下一帧移除它。参见 [recipe](animations.md#suppress-transitions-on-theme-switch)。

## 仅过渡变化属性

始终指定确切属性：`transition-property: scale, opacity`。Tailwind 的 `transition-transform` 覆盖 `transform, translate, scale, rotate`。

## 限制使用 `will-change`

仅用于 `transform`、`opacity` 和 `filter`，这些 GPU 可以合成。绝不使用 `will-change: all`。在看到第一帧卡顿时添加它，而非提前添加。参见 [performance.md](performance.md)。

## 匹配图标描边与文本粗细

紧邻文本的图标会携带文本的视觉重量：常规（400）文本旁的描边 `1.5px`，半粗（600）文本旁的描边 `2px`。每个图标集使用单一描边粗细，每个表面使用单一图标库。尺寸和 RTL 翻转在 [icons.md](icons.md) 中。

## 每个状态使用单一 SVG 并重新着色

图标使用 `currentColor` 并从 CSS 颜色和不透明度获取悬停、选中和禁用状态，而非从单独资源获取。轮廓是默认变体；填充表示激活状态。

## 动效约束

高频交互应立即提供反馈，或对不透明度和颜色使用 `150ms` 或更短的过渡。自定义动画在那里会为每个触发支付注意力成本。

每个动画状态变化都需要静态提示：颜色、图标或标签。动效永远不是唯一的反馈渠道。

## 完成前检查

| 错误 | 修复 |
| --- | --- |
| 图标看起来未居中 | 使用内边距进行视觉调整，或修复 SVG |
| 阶段性进入或退出突兀 | 错开不频繁的进入；保持退出微妙 |
| 主题切换使整个页面交叉渐变 | 禁用交换时的过渡，强制重排，下一帧恢复 |
| 元素上使用 `transition: all` | 指定确切属性 |
| 第一帧动画卡顿 | 添加 `will-change: transform`（谨慎使用） |
| 粗体文本旁的细线图标 | 匹配描边宽度与文本粗细 |

## 报告

**严重性。** `HIGH` 会破坏交互、使动效无法使用或仅在动画运行时可见状态变化。`MEDIUM` 是表面、图标或动效的可见不一致。`LOW` 是孤立的精细打磨。

**验证。** 无浏览器：组件定义的每个状态（悬停、焦点、激活、加载和空状态），以及从代码中读取的动效持续时间和缓动。有浏览器：逐个状态检查，并在浏览器的动画面板中以 10% 速度重播动效。报告无法运行的每个检查为 `Not verified`。

**格式。** 按违反的原则分组发现，按严重性排序，每个根因一行列出其出现位置：

| 严重性 | 位置 | 之前 | 之后 | 原因 |
| --- | --- | --- | --- | --- |

`位置` 是 `path/to/file:line`。`原因` 指出原则和用户影响。

以 `Block` 结尾时任何 `HIGH` 未解决，否则以 `Approve` 结尾，将剩余内容保留在表格中作为待办事项。绝不 `Approve` 未检查的覆盖率。无可报告时，说明“无可行动的 UI-polish 发现”并报告验证。
