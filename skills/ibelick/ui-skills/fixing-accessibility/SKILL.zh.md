# 修复可访问性问题

修复可访问性问题。

## 如何使用

- `/修复可访问性问题`
  将这些约束应用于此对话中的任何 UI 工作。

- `/修复可访问性问题 <文件>`
  根据以下所有规则审查文件，并报告：
  - 违规（引用确切的行或片段）
  - 为什么重要（一句话说明）
  - 具体的修复方案（代码级别的建议）

不要重写 UI 的很大部分。优先选择最小化、有针对性的修复。

## 何时应用

在以下情况下参考这些指南：
- 添加或更改按钮、链接、输入、菜单、对话框、选项卡、下拉菜单
- 构建表单、验证、错误状态、辅助文本
- 实现键盘快捷键或自定义交互
- 处理焦点状态、焦点捕获或模态行为
- 渲染仅包含图标的控件
- 添加仅通过悬停交互或隐藏内容

## 快速参考

### 1. 可访问性名称（关键）

- 每个交互控件必须有可访问性名称
- 仅包含图标的按钮必须有 `aria-label` 或 `aria-labelledby`
- 每个输入、选择和 `textarea` 都必须有标签
- 链接必须有有意义的文本（不能是“点击这里”）
- 装饰性图标必须有 `aria-hidden`

### 2. 键盘访问（关键）

- 不要在未提供完整键盘支持的情况下使用 `div` 或 `span` 作为按钮
- 所有交互元素都必须可通过 Tab 键访问
- 必须对键盘用户可见焦点
- 不要使用大于 0 的 `tabindex`
- `Escape` 键应在适用情况下关闭对话框或覆盖层

### 3. 焦点与对话框（关键）

- 模态对话框打开时应捕获焦点
- 关闭时恢复焦点到触发元素
- 对话框应设置初始焦点
- 打开对话框不应意外滚动页面

### 4. 语义（高）

- 优先使用原生元素（`button`、`a`、`input`）而不是基于角色的技巧
- 如果使用角色，必须存在所需的 `aria` 属性
- 列表必须使用 `ul` 或 `ol` 并带有 `li`
- 不要跳过标题级别
- 在适用情况下，表格必须使用 `th` 作为标题

### 5. 表单与错误（高）

- 错误必须使用 `aria-describedby` 链接到字段
- 必须宣布必填字段
- 无效字段必须设置 `aria-invalid`
- 辅助文本必须与输入关联
- 禁用提交操作必须解释原因

### 6. 通知（中高）

- 关键表单错误应使用 `aria-live`
- 加载状态应使用 `aria-busy` 或状态文本
- Toast 不应成为传达关键信息的唯一方式
- 可展开控件必须使用 `aria-expanded` 和 `aria-controls`

### 7. 对比度和状态（中）

- 确保文本和图标的对比度足够
- 仅通过悬停交互必须有键盘等效项
- 禁用状态不能仅依赖颜色
- 不要在没有可见替代方案的情况下移除焦点轮廓

### 8. 媒体与动画（低中）

- 图片必须有正确的 `alt` 文本（有意义的或空的）
- 带有语音的视频在相关时应提供字幕
- 尊重 `prefers-reduced-motion` 以减少非必要动画
- 避免自动播放带声音的媒体

### 9. 工具边界（关键）

- 优先进行最小化更改，不要重构无关代码
- 当原生语义已经解决问题时，不要添加 `aria`
- 除非被要求，否则不要迁移 UI 库

## 常见修复

```html
<!-- 仅包含图标的按钮：添加 aria-label -->
<!-- 之前 --> <button><svg>...</svg></button>
<!-- 之后 -->  <button aria-label="关闭"><svg aria-hidden="true">...</svg></button>

<!-- div 作为按钮：使用原生元素 -->
<!-- 之前 --> <div onclick="save()">保存</div>
<!-- 之后 -->  <button onclick="save()">保存</button>

<!-- 表单错误：使用 aria-describedby 链接 -->
<!-- 之前 --> <input id="email" /> <span>无效的邮箱</span>
<!-- 之后 -->  <input id="email" aria-describedby="email-err" aria-invalid="true" /> <span id="email-err">无效的邮箱</span>
```

## 审查指南

- 首先修复关键问题（名称、键盘、焦点、工具边界）
- 优先使用原生 HTML 而不是添加 `aria`
- 引用确切的片段，说明失败原因，提出小修复
- 对于复杂控件（菜单、对话框、组合框），优先使用成熟的可访问性基础元素而不是自定义行为
