# Three.js 调试分析器

在不影响可玩性的前提下，找到根本原因并优化测量的瓶颈。

追踪行为变化的作用范围。复用负责人现有的复现步骤和证据；修复后验证受影响路径。当共享行为发生变化或存在未解决的隐患时，通过聚焦性测试仅需更广泛的测试。将测量结果和缺陷返回给负责人进行整合性验证。

## 参考

`references/debug-playbook.md` — 顺序分类处理空白画布、资源与音频加载、循环/动画/物理、输入和移动、分析器序列以及 `__THREE_GAME_DIAGNOSTICS__` 结构。在调试或分析任何非明显问题时阅读它。

## 调试

首先使用用户相同的命令和 URL 复现问题，并阅读控制台、页面和网络错误。找到拥有失败的模块（渲染器、循环、相机、场景、资源、音频、输入、物理、UI 或基础路径），在该处修复根本原因，并重新测试精确的故障路径。剧本的分类顺序涵盖了常见原因，例如多个活跃循环、画布的显示尺寸与其绘制缓冲区不匹配，以及错误的增量单位。

## 分析

当用户界面性能重要时，分析生产预览。基线一个固定场景，分类瓶颈（CPU、GPU 绘制、片段、顶点、内存或网络），改变一个因素，并重新测量相同场景，确认视觉效果和可玩性保持不变。剧本列出了基线指标和分析优化顺序。

## 报告

首先提出根本原因或测量的瓶颈。然后是更改的文件、基线和后置指标、命令、截图、重新测试的故障路径和残余风险。
