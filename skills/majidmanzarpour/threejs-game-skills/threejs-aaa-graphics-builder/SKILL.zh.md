# Three.js AAA级图形构建器

掌握生产图形流程：将基础截图转化为精心制作、高密度、注重性能的视觉效果。

## 参考文献

| 文件 | 何时阅读 |
| --- | --- |
| `references/视觉评分卡.md` | 评分视觉效果或进行任何高端/AAA/展示性声明 |
| `references/制作配方.md` | 构建英雄、障碍物、奖励、世界套件或道具模型；更改光照、色调映射、阴影、雾气、后期处理或图形架构 |
| `references/技术美术.md` | 渲染预算、材质套件、VFX系统、实例化/LOD、导入资源清理，任何可能影响浏览器性能的内容 |
| `references/着色器食谱.md` | 自定义着色器、`onBeforeCompile`、天空或后期处理；将配方作为经过测试的起点并针对项目的Three.js版本进行验证 |

对于广泛的“看起来仍然基础”或高端流程，在实施前应阅读所有四个。狭窄的图形编辑仅加载其相关的参考文献和检查；请求的样式和范围会覆盖配方默认值。

## 核心规则

辉光不会让基础图形看起来像AAA级。首先构建精心制作的形状，然后是材质，然后是光照，然后是效果——按此顺序。

## 工作流程

1. 当存在可玩场景时，在目标视口上捕获或检查实际游戏截图。
2. 对于现有游戏，评分受影响的视图并选择最薄弱的表面。对于新游戏，首先确定艺术方向、相机比例、材质角色和英雄目标；不要凭空捏造之前的截图。
3. 添加游戏缺失的图形架构：材质库、程序化纹理和贴花、模型工厂、世界道具套件、VFX系统、渲染管线、诊断工具。
4. 为每个高价值表面选择一个来源：程序化Three.js、`threejs-image-generator`参考文献或纹理、`threejs-3d-generator`模型，或图像到3D混合链。当外部生成在范围内时，运行凭证探测。
   在依赖生成或绑定之前，检查概念/模型。在扩展内容套件之前，使用实际资产和反馈完成一个代表性的可玩场景。
5. 升级每个薄弱的可视表面，而不仅仅是英雄：危险、奖励、地面和轨道、前景道具、背景层、电报、材质变化、状态VFX。
6. 在精心制作的形状存在后，添加光照、色调映射和渲染润色。
7. 添加与游戏状态相关的事件驱动VFX。
8. 根据校准锚点重新评分，引用检查器的测量指标。继续进行，直到每个高端类别至少达到2，或者明确指出障碍。

## 资源获取

当外部生成在范围内时，首先运行`threejs-game-director/scripts/probe_asset_credentials.sh`；显式程序化艺术无需探测。设置密钥后，生成英雄表面（玩家、角色、生物、首领、车辆、飞船、建筑、武器、标志性道具、英雄环境部件）和高价值2D（天空、背景、纹理和边框参考文献、贴花、阵营标记、图标、GUI和标题艺术、图像到3D输入），除非用户将艺术限制为程序化或排除了外部服务。程序化Three.js处理重复的道具、套件、碰撞代理、VFX几何形状和实例化体积。使用导演的`references/资产恢复.md`处理失败；单个超时不是生成不可用的证据。

对于动画资源，除了轮廓外，还要检查动作：移动、混合过渡、脚接触、命中时机和实际游戏中的次要动作。一次集中的独立评论可能在大量处理后识别缺陷；负责人仍需对最终评分和集成负责。

## 报告

使用每个类别的证据行进行评分前后对比，升级的表面、更改的文件、截图、与预算表对比的渲染器诊断、生成资产路径和任务ID，以及仍然薄弱的内容。当使用生成3D时，包含导入资源诊断（比例、边界、碰撞代理、剪辑）。
