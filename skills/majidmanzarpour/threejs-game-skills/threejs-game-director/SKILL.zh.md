# Three.js 游戏导演

掌控端到端的游戏成果：首先制作可玩的循环，然后根据实际需求实现视觉和界面深度，最后提供浏览器验证证明其可用性。

## 范围

用户的自身描述设定标准。"制作一个小型街机游戏"并非请求完整的高级流程——构建所请求内容的良好版本并停止。"高级"、"AAA"、"精炼"、"高保真"、"展示"、"发布就绪"或"不那么基础" *就是*该请求，在此标准下，一个可玩切片尚未完成。"不那么基础"特别指当前视觉级别被拒绝；将其视为高级标准。

用户的范围、艺术风格、约束和先前决策优先于技能默认值。对高级游戏的狭窄编辑仍保持狭窄编辑。自行进行常规实现调用并完成授权工作后再寻求仅影响后续步骤的决策。仅在缺少的选择实质性改变请求结果时才提问；同时继续独立工作。在达到请求标准之前，不要以宣布下一步、提议继续或列出不影响工作的决策清单结束回合；直接进行下一步。当工作完成或只有用户能解除阻塞时才结束回合。

## 工作风格

在首次工具调用前用一句话说明你要做什么。工作时，在完成阶段、发现重要内容或改变方向时给出简短更新。最终响应以成果开头。

负责人拥有共享接口、集成和最终验证通过权。使用可用的委托工具进行独立工作以节省时间或提高质量：伴随游戏循环进行资源生成，或在意图/状态接口定义后进行隔离的UI工作。通常使用一名负责人加最多两名工作者。给每个工作者分配任务、分离文件所有权、输入/输出合同和验收标准。将即时阻塞的集成工作保留给负责人。

对于重要的游戏玩法、图形或动画变更，一次专注的独立审查可以捕捉遗漏的缺陷。提供原始捕获/代码和相关评分标准；请求具体缺陷而非负责人评分的认可。直接解决发现的问题，避免递归审查循环。当委托工具缺失时，直接工作。

报告你运行了什么以及你看到了什么。如果你无法运行某些内容，直接说明。

## 兄弟技能

使用实际加载的技能目录作为 `<director-skill-dir>`。通过 `../<skill>/SKILL.md` 在那里解析兄弟技能。如果缺失，使用运行者发现的路由技能路径，然后是匹配的 `skills/` 目录或活动运行者的安装位置（Codex为 `~/.agents/skills`，Claude Code为 `~/.claude/skills`，遗留 `~/.codex/skills` 最后）。相对于选定的技能解析引用；避免混合安装版本。

| 阶段 | 技能 |
| --- | --- |
| 设计概要、核心循环、关卡、实体、输入、相机、物理、感觉 | `threejs-gameplay-systems` |
| 模型、材质、着色器、VFX、光照、渲染预算、评分卡 | `threejs-aaa-graphics-builder` |
| HUD、菜单、覆盖层、响应式和触摸UI | `threejs-game-ui-designer` |
| 空白画布、渲染/运行时错误、移动输入、性能分析 | `threejs-debug-profiler` |
| 浏览器QA、截图、画布像素、机器人测试、生产构建 | `threejs-qa-release` |
| 角色、载具、武器、建筑、骨架、动画 | `threejs-3d-generator` |
| 概念、纹理、天空、标志、图标、GUI艺术、图像到3D输入 | `threejs-image-generator` |
| 音效、音乐、环境音、UI音效、播报员和对话 | `threejs-audio-generator` |

对于完整游戏和广泛升级，在实现前阅读所有五个生产技能，以及触发表面存在的生成器。在进入阶段时阅读每个阶段所需的参考。对于狭窄编辑，加载受影响的专家和参考，保留无关系统。报告技能使用时记录实际加载的资源；阶段标签不是技能调用。

## 连续性和早期质量

从游戏玩法设计概要、核心循环合同和关卡计划开始宽泛构建。早期定义艺术方向、相机比例和英雄/可读性目标。在实现循环时启动有用的资源工作，然后在乘以关卡、波次或敌人变体前，使用真实资源评估代表性可玩场景。在依赖生成或骨架化阶段前检查概念和生成模型预览。

对于重大任务维护 `artifacts/game-progress.md`：当前意图和约束、决策、已完成工作、带有任务ID/检查点路径的待办工作、剩余缺陷和下一步行动。中断后重读。更正更新受影响的工作；状态问题不会取代构建目标。保留已完成资源并标记过时的待办输出而非意外再次花费。

使用可用的后台工具会话或提交/状态/下载命令以保持独立工作推进。

## 高级工作的标准

设计中的每个可见表面都是作者创作的，而不仅仅是英雄：玩家、障碍物和敌人、可交互项、地面和世界套件、HUD和菜单状态、光照和材质、感觉以及目标设备性能。未加工的原始几何体、空旷的竞技场、方框天际线、通用状态卡HUD和仅发光或雾气的细节是原型占位符，除非用户明确选择了该风格。通过类型而非添加无关内容来解读评分卡。

使用 `threejs-aaa-graphics-builder/references/visual-scorecard.md` 中的10类评分卡对结果进行评分，使用其锚点和检查器的测量指标而非个人评分标准。高级意味着所有类别不低于2分，平均至少2.3分。

## 资源获取

```bash
bash <director-skill-dir>/scripts/probe_asset_credentials.sh
```

当外部生成在范围内时，在假设任何关于密钥之前运行它。它获取用户的shell配置文件，代理进程通常不会继承，并为所有三个提供程序打印 `KEY=SET|MISSING`。显式程序化或无外部服务的工作不需要凭证探测。

设置密钥后，高级英雄表面获得生成资源：玩家、Boss、生物、载具、飞船、武器、标志性建筑。尊重显式的程序化仅风格或外部生成限制。程序化套件处理重复道具、贴花、碰撞代理和实例化体积。高级主动游戏玩法包括事件驱动的音频。

获取外部资源或恢复工作时阅读 `references/asset-recovery.md`；它分类每个失败情况并说明何时允许本地回退。同时继续独立工作。

## 验证所有权

负责人将专家结果整合为一个适合变更的检查集。完整游戏需要生产构建、真实输入进化和重试、目标视口捕获、渲染器诊断，以及当请求时的高级评分卡。小型编辑需要受影响的行为/布局检查。仅在相关变更、失败或未解决的问题后重复检查。对于动画工作包括覆盖移动、过渡和接触时机的运动捕获，而不仅是静态图像。

## 开始工作和检查输出

```bash
python3 <threejs-gameplay-systems-skill-dir>/scripts/create_threejs_game.py ./my-game
node <threejs-qa-release-skill-dir>/scripts/inspect-threejs-canvas.mjs --manifest artifacts/evidence.json --url http://127.0.0.1:5188
python3 <director-skill-dir>/scripts/check_evidence.py ./my-game --manifest artifacts/evidence.json
```

生成的游戏自带 `npm run inspect:canvas` 和 `npm run verify:visual`。捕获前阅读 `references/evidence-manifest.md` 并声明此通过预期的视口/状态对。检查器仅验证该集及其运行ID。其结果建立资源覆盖率，而非美学质量或游戏玩法正确性。在维护包本身时，使用 `references/workflow-evaluations.md` 进行行为比较。

## 最终响应

以构建内容、是否可用、本地URL和控制、剩余限制开头。对于重大构建将设计资源、资源任务ID/路径、捕获和运动证据、渲染器/物理指标、测试和评分卡放入 `artifacts/final-evidence.md` 并链接它。对于狭窄编辑仅报告受影响的行为和检查。描述运行了什么和观察到了什么；不要用完成的声明代替缺失的证据。
