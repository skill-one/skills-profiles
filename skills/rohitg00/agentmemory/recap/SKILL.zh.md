用户希望得到摘要。时间窗口参数：$ARGUMENTS

## 快速入门

```json
memory_sessions { "limit": 30 }
```

然后针对每个存活的会话：`memory_recall { "query": "<核心概念>", "limit": 3 }`。

预期输出：

```text
2026-06-07
  7f3a9c2 · "认证刷新重构" · 14 次观察 · 已完成
    - [8] 每次使用时旋转刷新令牌
2 天内 3 个会话，41 次观察。
```

## 原因

仅总结工具返回的会话和观察结果。空窗口是真实答案，而不是提示创造活动。

## 工作流程

1. 解析 `$ARGUMENTS`：`today` = 当前本地日期；`this week` = 过去 7 天；`last <n>` 或纯数字 = 最近 N 个；空 = `last 10`。
2. 调用 `memory_sessions`，过滤到当前项目（匹配 `cwd` 与工作目录），应用窗口，按 `startedAt` 降序排序。
3. 按本地日历日期（YYYY-MM-DD）对存活的会话进行分组。
4. 每个会话列出 ID（前 8 位）、标题或首个提示、观察次数、状态。缩进 2-3 个高亮（重要性 >= 7）来自 `memory_recall`。
5. 结尾为 "N 个会话跨越 M 天，K 次观察"。

## 反模式

错误：窗口为空，因此你从对话记忆中总结 "一个富有成效的认证工作周"。

正确："该项目在过去 7 天内没有会话。"

## 检查清单

- 从参数正确解析窗口。
- 会话过滤到当前项目的工作目录。
- 高亮来自 `memory_recall`，而非释义。
- 总计行反映实际显示的计数。

## 参见

- `handoff`, `session-history`, `recall`：相同会话数据，不同视角。

## 故障排除

如果 `memory_sessions` 或 `memory_recall` 不可用，请查看 ../_shared/TROUBLESHOOTING.md。
