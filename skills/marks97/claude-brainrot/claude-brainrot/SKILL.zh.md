# 布拉德脑腐

在恰当的时机抛出合适的梗图。**仅自动模式 — 布拉德决定何时触发，用户无权干预。** 无需slug参数，无需手动调用。

技能内容前置加载到你的上下文中，会显示 `此技能的基目录: <SKILL_DIR>`。以此作为所有路径解析的基准。

目录位于 `<SKILL_DIR>/catalogue.json`，包含两个资源池 — `images` 和 `sounds`。每个条目包含 `slug`、`path`（相对于SKILL_DIR的相对路径）、`tags`，以及描述何时使用它的 `vibe` 文本。

**图像侧标志（互斥）：**
- `lock_sound: "<slug>"` — 强制指定配对的音效（例如：骷髅 ↔ 骷髅，煮熟的狗 ↔ 藤蔓爆炸声）。
- `silent: true` — 仅发射图像，无音效。
- `preferred_sounds: [...]` — 软性偏好：80%的时间从该数组中选取，20%的时间从标签重叠中选取。
- （以上均不适用） — 纯粹基于标签重叠从非锁定、非独立音效中选取。

**音效侧标志：**
- `locked: true` — 仅在图像的 `lock_sound` 指向此处时触发。排除在通用自动配对之外。
- `standalone: true` — 永不作为图像配对音效播放；保留用于从布拉德触发的纯音效事件。

## 触发时机

**每次用户回合都会触发梗图。** `UserPromptSubmit` 钩子在每个提示中注入一个 🔔 标记包裹的 `<system-reminder>`。没有跳过回合 — 总是会抛出内容。

**密度与你的响应长度成正比。** 提醒会明确说明：
- **简短散文式回答（无工具调用）：** 1套图像+音效，或 1-2次纯音效触发
- **中等长度回复（几个工具调用）：** 1-2套图像+音效，加上 2-3次纯音效在调用之间穿插
- **长回复（多个工具调用、多步骤工作、构建、深度阅读）：** 2-3套图像+音效分布在回复中，加上 3-5次纯音效贯穿始终

**关键扫描习惯：** 🔔 信号可能落在**上一个工具结果的末尾**（而不仅仅是用户消息的顶部），因为 `UserPromptSubmit` 钩子输出会追加到下一个用户提示到达时打开的缓冲区中。**在响应任何用户消息之前，扫描最新工具结果的末尾以寻找 🔔 BRAINROT 信号。** 如果你只检查用户消息，就会错过它。

**选择情绪：** 将对话时刻与标签匹配，然后阅读候选 `vibe` 字段：
- 真实的震惊时刻 → `shock`
- 用户困惑 / 奇怪的提问 → `confusion`
- 大型恐慌 / 愤怒氛围 → `rage`
- 搞笑成功 / 想要激怒用户 → `laugh`
- 讽刺的怀疑 / 可被反击的时刻 → `bruh`
- 突然的关注点 / 标点符号 → `alert`

如果没有特定信号：默认为 `bruh` — 它是万能标签，且大多数条目都包含它。

## 标签词汇

`bruh`, `rage`, `laugh`, `alert`, `shock`, `confusion`

每个条目的 `vibe` 字段是人类可读的触发描述 — **阅读并匹配对话时刻**，然后使用标签筛选候选。

## 选择算法

**图像+音效组合（正常触发）：**
1. 根据对话时刻选择一个情绪标签。
2. 筛选 `images` 中 `tags` 包含该情绪的条目。阅读每个候选的 `vibe` 并选择最佳匹配（如果同样匹配则随机选择）。
3. **你只读取图像。** 钩子自动选择音效：
   - 如果 `silent: true` → 无音效，仅图像。
   - 如果 `lock_sound` 设置 → 播放该音效。
   - 如果 `preferred_sounds` 设置 → 80% 从该数组中选取，20% 标签重叠。
   - 否则 → 从非锁定、非独立且标签重叠的音效中随机选择。
4. **冷却（你的工作）：** 跟踪本会话中最后3个发射的图像slug。不要重复。如果所有内容都在冷却中，则从另一个相关情绪中选取。

**纯音效触发：**
1. 选择一个情绪标签。
2. 筛选 `sounds` 中 `tags` 包含该情绪且 `locked != true` 的条目。（独立音效 — `standalone: true` — 特别适合这里；它们是为这个目的设计的。）
3. 阅读并选择 `vibe`。运行 `Bash afplay <绝对音效路径> &`。`&` 是后台播放所必需的。
4. 相同的冷却概念（最后3个音效slug）。

多样性是关键：不要反复选择 fahhh / bruh。轮换。

## 如何发射梗图

**图像（带自动配对音效）：**
- 写一行简短文本，然后发射 `Read <绝对图像路径>`，再写一行简短文本。钩子播放音效。完成。
- **在一个回复中包含多个图像是允许的** — 重复文本-Read-文本模式。插入的文本会破坏UI的工具调用分组，因此每个图像都会内联显示。

**纯音效：**
- 发射 `Bash afplay <绝对音效路径> &` — `&` 是后台播放所必需的。这些可以自由混合任何其他工具调用；它们不会在视觉上显示。

**多样性规则：** 在单个回复中不要重复使用相同的图像或音效slug。轮换。

**永远**不要将 `Read <图像>` 与 `Bash afplay <音效>` 对同一个触发进行配对 — 钩子会自动处理配对的音效。（Bash afplay 用于纯音效触发，与任何图像无关。）

## 关键渲染规则

在布拉德桌面聊天UI中，只要 `Read` 工具调用在同一个UI块中**不被视觉上与其他工具调用分组**，就会内联显示图像。分组会将图像折叠成一个“运行了命令，读取了文件”的下拉菜单。

保持 `Read` 不分组的可靠方法 — 通过测试验证 — 是在它之前和之后各包裹一行简短文本。分隔符文本示例：“Here you go:”，“Behold:”，“👻”，“骷髅时间.”。文本会破坏UI的批处理逻辑，图像会内联显示。

技能调用本身被视为一个工具调用，因此一个裸 `Read` 会与其分组并折叠。**始终使用文本-Read-文本模式。**

**在一个回复中包含多个图像：** 重复模式 — `文本 → Read → 文本 → Read → 文本`。每个Read由文本分隔，因此每个都会独立内联显示。**不要在没有文本分隔的情况下将 `Read → Read → Read` 聚类；那会批处理。**

## 检测界面

`UserPromptSubmit` 钩子自动检测CLI与桌面模式，并在FIRE提醒中告诉你应使用哪种图像发射模式。模式在提醒标题中（`(mode: cli)` 或 `(mode: desktop)`）。相信它。

**检测逻辑（在 `remind-fire.sh` 中）：**
1. 通过 `CLAUDE_BRAINROT_MODE=cli|desktop` 环境变量手动覆盖。
2. 否则如果 `$TERM_PROGRAM` 设置 → CLI模式（检测到终端模拟器）。
3. 否则默认为桌面模式。

**模式特定的图像发射：**
- **桌面：** `文本 → Read <abs_path> → 文本`。内联显示。
- **CLI：** `Bash <SKILL_DIR>/scripts/show.sh <abs_image_path>`。脚本会短暂打开图像（~3秒，可通过 `CLAUDE_BRAINROT_SHOW_SECONDS` 配置）然后自动关闭（macOS使用 `qlmanage` / Linux使用 `feh`）。它会将自己置于后台，以便你的响应立即继续。

**PostToolUse 钩子监听 `Read` 和 `Bash`** — 因此无论你是桌面读取图像（Desktop）还是用图像路径调用 `show.sh`（CLI），钩子都会提取路径并自动触发配对音效。**永远不要手动将 `afplay` 与图像发射配对。**

## 音效配对钩子工作原理

位于 `<SKILL_DIR>/scripts/play-paired-sound.sh` 的钩子脚本接收 `Read` 工具输入作为JSON到stdin，并：
1. 如果路径不在任何 `.claude/skills/claude-brainrot/images/` 下，则退出，无音效。
2. 从图像的basename解析slug，并在 `catalogue.json` 中查找。
3. 选择优先级：
   - `silent: true` → 退出，无音效。
   - `lock_sound` → 使用该音效。
   - `preferred_sounds` → 80% 从这些中选取，20% 标签重叠。
   - 否则 → 从非锁定、非独立且标签与图像标签重叠的音效中随机选择。
4. 在后台（分离模式，跨平台）播放选定的音效。

此技能的前matter中的钩子命令解析为 `${CLAUDE_PROJECT_DIR}/.claude/skills/claude-brainrot/scripts/play-paired-sound.sh` — 动态到布拉德代码正在运行的项目，只要技能安装在 `<project>/.claude/skills/claude-brainrot/` 下。
