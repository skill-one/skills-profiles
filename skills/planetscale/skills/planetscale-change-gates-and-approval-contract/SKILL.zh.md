# 更改门禁和审批合同

## 目的

防止可能影响可用性、安全性、安全性、数据或开发者工作流程的意外或自主更改。

## 操作类别

### 类 A：默认只读

无需审批即可执行：

- 列出数据库、分支、键空间、Webhook、备份、角色、流量预算、模式建议、部署请求和 Insights 数据。
- 检查存储库代码。
- 读取模式元数据。
- 读取非敏感数据库元数据。
- 生成报告和提议的更改集。

### 类 B：创建状态的提议

默认允许；仅在操作员要求严格的无修改模式时需要审批：

- 通过 API POST 创建查询模式报告，即使结果是只读的遥测数据。
- 触发 Webhook 测试事件。
- 创建临时本地分支或文件。
- 在外部工具中打开 PR 或问题。
- 创建数据库开发分支。
- 将 DDL 或迁移应用于非生产开发分支。
- 打开针对受版本控制工作流保护的分支的部署请求。

最后三项是现有版本控制系统内的提议：在人类合并或部署之前，任何东西都不会到达生产环境。门禁应属于合并/部署操作（类 C/D），而不是提议创建。一个停止请求权限以打开 PR 的代理是分类错误的。

### 类 C：改变行为的

始终需要明确审批：

- 启用安全迁移。
- 禁用安全迁移。
- 更改部署请求审批设置。
- 创建/更新/删除流量控制预算或规则。
- 将流量控制预算移至强制模式。
- 创建/更新/删除 Webhook。
- 启用原始查询收集。
- 启用/禁用需要重启的扩展或设置。
- 创建/更新/删除角色。
- 重置密码。
- 更改 pg_strict 设置。
- 更改连接池行为。
- 更改 IP 限制、PrivateLink、PSC 或公共访问。
- 更改备份计划或保留。
- 创建恢复分支。
- 创建自动备份之外的备份。
- 更改分支大小或副本拓扑。
- 编辑存储库文件或依赖项。

### 类 D：影响生产数据/可用性的

需要明确审批、命名目标确认、回滚计划，并最好进行第二次人类审查：

- 生产 DDL。
- 生产 DML。
- 将模式建议应用于生产。
- 将 Vitess 部署请求排队或应用于生产。
- 推广或恢复分支。
- 删除分支、数据库、角色、Webhook、备份或流量规则。
- 在生产上强制流量控制。
- 更改生产网络访问。
- 旋转生产凭证。
- 高负载期间的紧急备份。

### 类 E：永不自主

没有直接人工操作或单独批准的事件程序，绝不执行：

- 删除生产数据库。
- 禁用所有生产安全机制。
- 删除生产表或列。
- 移除 IP 限制或仅限私有的姿态。
- 在日志、问题、PR、Slack 或报告中存储或暴露密钥。
- 自动合并来自数据库遥测数据的代码。
- 自动应用由 LLM 生成的 DDL。

## 审批要求

有效的审批必须包括：

- 更改 ID。
- 目标组织/数据库/分支。
- 是否影响生产。
- 执行确切操作的权限。

无效的审批：

- “做最佳实践。”
- “修复所有问题。”
- “应用建议。”
- “继续”而不命名更改 ID。

## 自主执行例外

只有一个替代每项更改审批的选项：在 `../planetscale-autonomous-execution-mode/SKILL.md` 中定义的风险确认自主模式。当操作员明确确认风险、命名范围并说明是否包含生产时，该确认可替代命名范围内类 B/C（生产包含时为类 D）操作的每项更改审批。

此技能中的其他所有内容在自主模式下仍然适用：

- 类 E 不会因任何措辞而解锁。
- 每个类 C/D 步骤（显示为执行计划，而不是停止等待）仍需生成预执行清单。
- 执行后报告仍然需要。
- 超出范围的工作仍然需要新的审批或新的确认。

## 需要的预执行清单

在执行任何类 C 或 D 操作之前，生成：

- 确切命令、API 端点、仪表板操作、SQL 或存储库差异。
- 目标确认。
- 预期效果。
- 可用性影响。
- 数据风险。
- 安全风险。
- 回滚计划。
- 验证计划。
- 监控计划。

然后停止等待审批。

## 需要的执行后报告

如果已批准的更改稍后执行，报告：

- 发生了什么更改。
- 何时更改。
- 谁批准。
- 使用的接口。
- 成功的证据。
- 任何警告。
- 回滚状态。
- 后续监控。

## 需要的拒绝行为

如果要求应用广泛或模糊的生产更改，拒绝广泛操作并生成更安全的命名更改计划。

使用此句子：

“我不会根据模糊指令应用广泛的生产更改。我可以生成具有风险和回滚详情的命名更改集。”
