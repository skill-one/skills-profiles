# 新手引导优化

你需要优化首次使用体验，以最大化激活——即新用户完成能预测长期留存的核心操作的瞬间。

## 激活原则

**激活 ≠ 注册。** 激活是用户首次从你的应用中获得实际价值。在考虑其他任何因素之前，先确定它。

| 应用类型 | 激活事件 |
|----------|-----------------|
| 健身 | 完成首次锻炼 |
| 生产力 | 创建首个任务或项目 |
| 社交 | 建立首个连接或发布内容 |
| 金融 | 链接首个账户或设置预算 |
| 游戏 | 完成首个关卡或对战 |
| 冥想 | 完成首个冥想会 |
| 照片/视频 | 编辑或导出首张照片 |

**规则：** 新手引导中的所有内容都应尽可能快速地导向那个唯一的激活事件。

## 初步评估

1. 检查是否存在 `app-marketing-context.md`
2. 询问：**你的激活事件是什么？**
3. 询问：**24小时内有多少新用户能到达它？**（基准值）
4. 询问：**用户在哪些环节流失？**（如果已知）
5. 询问：**你当前的新手引导需要多长时间？**（步骤、界面）
6. 询问：**你是否设置了 Firebase/Mixpanel 流程？**

## 新手引导审计框架

### 第一步 — 绘制当前流程

列出从应用打开到激活的每个界面：

```
应用打开 → [界面1] → [界面2] → ... → 激活事件
```

标记每个界面：**必需** | **增加价值** | **仅增加摩擦**

移除或延后所有仅增加摩擦的内容。

### 第二步 — 评估每个界面

| 因素 | 问题 | 分数 |
|--------|---------|-------|
| **必要性** | 用户能否不通过这个界面也能到达激活？ | 0 = 跳过它 |
| **时机** | 这个请求是否是恰当的时机？ | |
| **价值交换** | 用户是否理解这个对他们有什么好处？ | |
| **认知负荷** | 这个界面需要用户做多少决策？ | |

### 第三步 — 权限请求时机

权限是 #1 流失点。规则：

| 权限 | 何时请求 | 从不请求 |
|-----------|------------|-----------|
| 推送通知 | 激活之后，而不是之前 | 冷启动时 |
| 位置 | 当功能需要它时 | 注册时 |
| 相机/麦克风 | 上下文相关，使用时请求 | 任何价值之前 |
| 联系人 | 当社交功能被使用时 | 新手引导中 |
| 跟踪 (ATT) | 用户投入之后 | 首次打开时 |

**预权限请求界面：** 在系统提示之前，始终显示一个原生风格的解释界面。理解“为什么”的用户同意率是 2–3 倍。

### 第四步 — 注册摩擦

| 模式 | 影响 | 建议 |
|---------|--------|---------------|
| 注册前必须要求 | 高流失率 | 延后到激活后 |
| 仅邮箱+密码 | 中等流失率 | 添加 Apple + Google 登录 |
| 长配置文件设置 | 高流失率 | 最多问一个问题，其余延后 |
| 邮箱验证必需 | 削弱势头 | 延后或设为可选 |

**访客模式 / 注册前体验：** 允许用户在要求账户之前体验核心价值。访客 → 注册的转化率通常为 40–60%，而硬性门槛仅为 15–30%。

## 按应用类型划分的新手引导模式

### 价值优先（推荐大多数应用）

```
打开 → 核心功能演示 / 交互式预览
     → 激活时刻
     → “保存你的进度” → 注册
     → 权限请求
     → 个性化
```

### 个性化优先（适用于健康、健身、AI 应用）

```
打开 → 3–5 个性化问题（显示进度条）
     → “你的计划已准备好” 揭示时刻
     → 注册门槛（现在已投入）
     → 激活
```

### 社交优先（适用于社交应用）

```
打开 → Apple/Google 单击登录
     → 查找朋友 / 跟随建议
     → 带内容的首次信息流
     → 激活（发布、评论、反应）
```

## 流程基准

| 步骤 | 基准 | 较差 |
|------|-----------|------|
| 应用打开 → 首次交互 | > 85% | < 70% |
| 注册转化率 | > 60% | < 40% |
| 推送权限同意率 | > 50% | < 30% |
| 激活（D0） | > 40% | < 20% |
| 第 1 天留存率 | > 30% | < 15% |

## 个性化问题

如果你包含个性化，请遵循以下规则：
- 新手引导中最多 **3–5 个问题**
- 每个问题必须明显影响体验
- 显示进度指示器（步骤 1/3）
- 使用视觉选择，而不是文本输入
- 从不请求你不会立即使用的数据

## 新手引导中的付费墙位置

**规则：** 在付费墙之前展示价值。

| 位置 | 适用情况 |
|-----------|-----------|
| 激活之前 | 几乎从不 — 用户没有价值的参考 |
| 激活时 | 强烈 — 用户刚刚感受到价值 |
| 激活后第 1 天 | 对订阅应用来说最强 |
| 上下文（功能门槛） | 适用于基于功能的付费墙 |

有关付费墙设计的详细信息，请参阅 `monetization-strategy`。

## 输出格式

### 新手引导审计

```
当前流程：
  [界面1] — 必需 / 摩擦
  [界面2] — 增加价值
  [界面3] — 必需 / 摩擦
  ...
  [激活事件] — 第 N 步

流失分析：
  最大流失：[界面] ([X]% 退出率，如果已知)
  估计原因：[假设]

建议变更：
1. [移除 / 延后 X] — 预期影响：[激活提升]
2. [重新排序 Y 在 Z 之前] — 预期影响：[理由]
3. [为 Z 添加预权限界面] — 预期影响：[同意率提升]

修订流程：
  打开 → [界面] → [界面] → 激活 → 注册 → 权限
  预计移除步骤：[N]
  预计激活时间：[Xs → Xs]
```

### 权限界面文案模板

```
[代表权限的图标]

[利益标题 — 用户获得什么]
例如，“完成目标时接收通知”

[一句话解释]
例如，“我们只会发送你设置的提醒 — 不会发垃圾信息。”

[允许按钮]     [稍后]
```
