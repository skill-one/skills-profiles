# /layers-surface

*假设已加载 `/layers-intro`。这项技能是一套技术库，而非脚本——请参阅那里的“如何使用这些技能”。*

表面层是将下方所有决策转化为人们实际接触到的形式的地方：文字、声音、视觉、物理可供性、运动、反馈。它是与媒介最相关的层，但最重要的决策首先具有普遍性——无论表面是屏幕、语音界面、物理设备还是服务触点，这一点都成立。

表面问题通常是更深层次问题的症状。这里的中心学科是区分可以在表面解决的问题和需要重新审视下层的问题。

---

## 该层做出的决策

- 表面是否尊重概念模型中的词汇和对象
- 是否存在面包板中的所有可供性——以及是否有任何表面元素没有模型支撑
- 情感基调是否适合用户正在执行的任务
- 用户如何知道发生了什么、正在进行什么以及出了什么错
- 什么是最突出的，以及是否应该如此
- 是否所有内容都对需要它们的用户可访问

---

## 学科——使表面保持真实

- **表面修复与深层问题。** 关键判断：这是否是在副本/布局中修复的问题，还是概念模型或交互流程中存在根本问题的症状？错误的词汇可能是重写——或者模型从未确定术语。将深层问题返回到相关技能，而不是修补症状。
- **术语与通用语言匹配。** 标记直接违规（模型术语使用不一致）、未列出术语（表面词汇不在模型中——添加到模型，或删除为噪音）、以及语调错位。
- **对象一致性。** 没有变形者（同一对象在不同上下文中以显著不同的形式出现），没有掩蔽对象（用户无法识别对象类型的表单）。
- **双向完整性。** 每个面包板可供性都存在；没有没有模型或流程支撑的表面元素（这些是交互决策中遗漏的——路由到 `/layers-interaction-flow`）。
- **错误诊断、解释、恢复。** “出了错”在所有三个方面都失败。标记每个没有完成这三个方面的错误状态。
- **突出反映重要性。** 流程需要用户注意的内容是突出的；不应突出任何不应突出的事物。
- **可访问性是决定，而非默认。**
- **情感基调与用户需求中的情感和社会任务匹配——而不是将产品的益处作为用户的益处来表述。**

## 技术

这里有两种类型的工作：对照下层审计现有表面，以及处理开放的表面决策。根据情况使用其中一种。

| 技术 | 用于 |
|---|---|
| **词汇检查** | 取得通用语言列表；检查每个标签、标题、按钮、错误、通知、帮助字符串。 |
| **对象一致性检查** | 对于每个模型对象：它出现在哪里，以多少种形式出现？捕获变形者和掩蔽对象。 |
| **完整性检查** | 沿面包板和表面双向行走——缺失的可供性，以及没有模型支撑的表面。 |
| **情感基调检查** | 返回到情感和社会任务；找到语调、框架或强调错位的地方。 |
| **反馈与错误清单** | 对于每个动作和状态转换：用户如何知道它是否成功、正在进行或失败——以及下一步该做什么？ |
| **层级审查** | 每个关键位置：用户必须注意或采取行动的内容是什么，表面是否使其最突出？在决定如何发出信号之前，决定什么是主要的。 |
| **可访问性检查** | 每个媒介——屏幕（对比度、尺寸、触摸目标、键盘、屏幕阅读器标签、焦点）、语音（所有内容都通过语言传达，没有视觉上下文的恢复）、物理（范围、触觉区分、照明、没有精细运动要求）。 |
| **一致性检查** | 相似的事物以相似的方式对待，不同的事物以不同的方式对待；尊重或故意打破媒介惯例。 |
| **制作它（真实媒介、模型图、样式瓦片、原型、设计系统、先写文案）** | 在制作表面而非审计表面时。在代码中工作以获得真实的交互反馈；模型图用于布局/层级；样式瓦片用于早期语调；原型用于时间和运动；扩展（不要矛盾）现有的设计系统；当语言是主要材料时先写文案。 |

## 与设计师合作

确定媒介以及下层存在的内容——概念模型（对象+通用语言）、面包板、包括情感/社会任务的作业故事。如果表面已存在，则审计它；如果不存在，则处理开放的决策。

提供适合实时问题的技术——当术语感觉不对时进行词汇检查，当用户不知道发生了什么时进行反馈清单，当可访问性被默认时进行可访问性检查。不要运行所有十个。

仅捕获残留物：审计结果（每个标记为表面修复或深层问题的表面）、分组和优先级的开放表面决策（包括选项和约束）、首先需要解决的跨层问题，以及已经很好地工作且在修订中不会丢失的内容。

表面要么尊重下方的决策，要么破坏它。在概念模型或交互结构发生任何重大变化后重新审视。
