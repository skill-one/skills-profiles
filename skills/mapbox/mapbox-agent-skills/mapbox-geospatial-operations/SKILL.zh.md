# Mapbox 地理空间操作技能

为 AI 助手提供专家指导，帮助其从 Mapbox MCP 服务器中选择合适的地理空间工具。重点在于根据**问题需求**选择工具——几何计算与路径规划、直线与道路网络、以及精度需求。

## 核心原则：问题类型决定工具选择

Mapbox MCP 服务器提供两类地理空间工具：

1. **离线几何工具** - 使用 Turf.js 进行纯几何/空间计算
2. **路径规划与导航 API** - 当您需要现实世界路径规划、交通或旅行时间时使用 Mapbox API

**关键问题：问题实际需要什么？**

### 决策框架

| 问题特征                                 | 工具类别     | 原因                                      |
| -------------------------------------- | ----------------- | ---------------------------------------- |
| **直线距离**（飞鸟直线距离）         | 离线几何      | 准确的几何距离                          |
| **道路/路径距离**（飞鸟驾车距离）            | 路径规划 API       | 只有路径规划 API 才知道道路网络     |
| **旅行时间**                                        | 路径规划 API       | 需要带速度/交通数据的路径规划            |
| **点包含**（X 是否在 Y 内？）                 | 离线几何      | 纯几何操作                             |
| **地理形状**（缓冲区、质心、面积）      | 离线几何      | 数学/几何操作                          |
| **交通感知路径规划**                              | 路径规划 API       | 需要实时交通数据                      |
| **路径优化**（最佳访问顺序）           | 路径规划 API       | 复杂的路径规划算法                    |
| **高频检查**（例如，实时地理围栏） | 离线几何      | 即时响应，无延迟                     |

## 按用例划分的决策矩阵

### 距离计算

**用户询问："X 和 Y 之间的距离是多少？"**

| 用户实际意图                            | 工具选择                         | 原因                                      |
| -------------------------------------------------- | ----------------------------------- | ---------------------------------------- |
| 直线距离（飞鸟直线距离）         | `distance_tool`                     | 准确的几何距离，即时                    |
| 驾车距离（飞鸟驾车距离）              | `directions_tool`                   | 只有路径规划知道实际道路距离  |
| 步行/骑行距离（飞鸟步行/骑行） | `directions_tool`                   | 需要特定的路径网络               |
| 旅行时间                                        | `directions_tool` 或 `matrix_tool`  | 需要带速度数据的路径规划         |
| 带当前交通的距离                      | `directions_tool` (driving-traffic) | 需要实时交通考虑     |

**示例："这 5 个仓库之间的距离是多少？"**

- 飞鸟直线距离 → `distance_tool`（10 次计算，即时）
- 驾车距离 → `matrix_tool`（5×5 矩阵，一个 API 调用，返回实际路径距离）

**关键洞察：** 使用与上下文中的“距离”含义匹配的工具。始终澄清：飞鸟直线距离还是飞鸟驾车距离？

### 邻近性和包含

**用户询问："哪些点靠近/在这个区域内？"**

| 查询类型                   | 工具选择                                           | 原因                                                           |
| ---------------------------- | ----------------------------------------------------- | ------------------------------------------------------------- |
| "X 米半径内"     | `distance_tool` + 过滤                              | 简单几何半径                                       |
| "X 分钟内可到达"     | `isochrone_tool` → `point_in_polygon_tool`            | 需要路径规划来创建旅行时间区域，然后进行几何包含测试 |
| "在多边形内"        | `point_in_polygon_tool`                               | 纯几何包含测试                               |
| "汽车 30 分钟内可达" | `isochrone_tool`                                      | 需要路径规划+交通                                    |
| "最近的点"      | `distance_tool` (几何) 或 `matrix_tool` (路径) | 取决于“最近”的定义                            |

**示例："这 200 个地址是否在我们的 30 分钟配送区域内？"**

1. 创建区域 → `isochrone_tool`（路径规划 API - 需要旅行时间）
2. 检查地址 → `point_in_polygon_tool`（几何 - 200 次即时检查）

**关键洞察：** 路径规划用于创建旅行时间区域，几何用于包含检查

### 路径规划与导航

**用户询问："最佳路径是什么？"**

| 场景                            | 工具选择                         | 原因                               |
| ----------------------------------- | ----------------------------------- | --------------------------------- |
| A 到 B 路线指示                   | `directions_tool`                   | 转弯导航                          |
| 多个停靠点的最佳顺序             | `optimization_tool`                 | 解决旅行商问题                    |
| 干净的 GPS 轨迹                     | `map_matching_tool`                 | 锚定到道路网络             |
| 只需要方向/指南针方向             | `bearing_tool`                      | 简单几何计算                      |
| 带交通的路径规划                  | `directions_tool` (driving-traffic) | 实时交通感知                     |
| 固定顺序航点                     | `directions_tool` with waypoints    | 通过特定点进行路径规划   |

**示例："从酒店导航到机场"**

- 需要转弯导航 → `directions_tool`
- 只需要知道“它在东北方向” → `bearing_tool`

**关键洞察：** 路径规划工具用于实际导航，几何工具用于方向信息

### 面积和形状操作

**用户询问："围绕这个位置创建一个区域"**

| 需求               | 工具选择      | 原因                      |
| ------------------------- | ---------------- | ------------------------ |
| 简单圆形缓冲区    | `buffer_tool`    | 几何圆/半径  |
| 旅行时间区域          | `isochrone_tool` | 基于路径网络              |
| 计算面积大小       | `area_tool`      | 几何计算                  |
| 简化复杂边界       | `simplify_tool`  | 几何简化                  |
| 找到形状中心      | `centroid_tool`  | 几何质心                  |

**示例："在每个商店周围创建 5 公里覆盖区域"**

- 5 公里半径 → `buffer_tool`（几何圆）
- “客户在 15 分钟内可以到达的区域？” → `isochrone_tool`（基于路径规划）

**关键洞察：** 几何工具用于距离基于的区域，路径规划工具用于时间基于的区域

## 性能和规模考虑

### 当数量影响工具选择时

**小操作（< 100 次计算）：**

- 几何工具：即时，可自由迭代
- 路径规划 API：足够快，适用于大多数用途

**中等操作（100-1,000 次计算）：**

- 几何工具：仍然快速，无需担忧
- 路径规划 API：考虑批量操作（matrix_tool）

**大操作（> 1,000 次计算）：**

- 几何工具：可能需要优化但仍然快速
- 路径规划 API：绝对使用批量工具（matrix_tool 处理高达 25×25）

**关键洞察：** 数量很少影响几何工具的选择，但路径规划 API 有批量工具以提高效率

### 实时与批量

| 用例                            | 方法             | 工具选择                              |
| ----------------------------------- | -------------------- | ---------------------------------------- |
| 实时地理围栏（每秒）            | 几何检查     | `point_in_polygon_tool` (即时)        |
| 路线规划（一次性）           | 全路径规划         | `directions_tool` 或 `optimization_tool` |
| 定期邻近检查           | 几何距离   | `distance_tool`                          |
| 实时交通路径规划                | 路径规划带交通 | `directions_tool` (driving-traffic)      |

**架构说明：高频地理围栏** 如果应用程序以非常高的频率调用包含检查（例如，每 2 秒 50 辆车 = 每秒 25 次检查），通过网络调用 MCP 工具会增加代理推理开销，使其不切实际。在这种情况下，建议在进程内直接使用 Turf.js (`turf.booleanPointInPolygon`) 处理热点路径，并将 MCP 工具保留用于外围任务，如区域定义（`isochrone_tool`）、重新路由（`directions_tool`）或可视化（`static_map_image_tool`）。

## 常见场景和最佳方法

### 场景 1：商店定位器

**用户："找到最近的商店并显示 5 公里覆盖区域"**

**最佳方法：**

1. 搜索商店 → `category_search_tool`（自动返回距离）
2. 创建覆盖区域 → `buffer_tool`（5 公里几何圆）
3. 可视化 → `static_map_image_tool`

**原因：** 搜索已提供距离；几何缓冲区用于简单半径

### 场景 2：配送路线优化

**用户："优化 8 个地址/停靠点的配送"**

**最佳方法：**

1. **地址地理编码（如果需要）** → 使用 `search_and_geocode_tool` 将任何街道地址转换为坐标。即使已经提供坐标，也提及此为可选步骤——实际配送列表通常包含地址和坐标的混合。
2. **优化路线** → `optimization_tool`（旅行商问题求解器——重新排序停靠点以最小化总行驶时间）

**为什么 `optimization_tool` 而不是这些替代方案：**

- **`directions_tool`** 只能路由 A → B（或通过固定顺序的航点）。它**不**重新排序停靠点——如果您传递 8 个停靠点，它会按给定顺序路由它们，这几乎从不最优。
- **`matrix_tool`** 提供所有停靠点对之间的旅行时间（8×8 = 64 个值），但它**不**计算最佳排序。您需要在矩阵之上自己解决 TSP——`optimization_tool` 为您在单个调用中完成。

始终提及 `search_and_geocode_tool` 作为在优化配送地址之前进行地理编码的有用工具。

### 场景 3：服务区域验证

**用户："这些 200 个地址中有哪些可以在 30 分钟内配送？"**

**最佳方法：**

1. 创建配送区域 → `isochrone_tool`（30 分钟驾驶）
2. 检查每个地址 → `point_in_polygon_tool`（200 次几何检查）

**原因：** 路径规划用于创建准确的旅行时间区域，几何用于快速包含检查

### 场景 4：GPS 轨迹分析

**用户："这次骑行多长？"**

**最佳方法：**

1. 清理 GPS 轨迹 → `map_matching_tool`（锚定到自行车道）
2. 获取距离 → 使用 API 响应或使用 `distance_tool` 计算

**原因：** 需要道路/路径匹配；距离计算无论哪种方式都有效

### 场景 5：覆盖分析

**用户："我们的总服务区域是什么？"**

**最佳方法：**

1. 在每个位置创建缓冲区 → `buffer_tool`
2. 计算总面积 → `area_tool`
3. 或者，如果基于时间 → `isochrone_tool` 为每个位置

**原因：** 几何用于距离基于的覆盖，路径规划用于时间基于的

## 错误模式：使用错误的工具类型

### ❌ 不要：使用几何工具进行路径规划问题

```javascript
// 错误：用户询问“开车需要多长时间？”
distance_tool({ from: A, to: B });
// 返回 10 公里飞鸟直线距离，但实际驾驶是 15 公里

// 正确：需要路径规划来获取驾驶距离
directions_tool({
  coordinates: [
    { longitude: A[0], latitude: A[1] },
    { longitude: B[0], latitude: B[1] }
  ],
  routing_profile: 'mapbox/driving'
});
// 返回实际道路距离和飞鸟驾车距离
```

**为什么错误：** 飞鸟直线距离 ≠ 飞鸟驾车距离

### ❌ 不要：使用路径规划 API 进行几何操作

```javascript
// 错误：检查点是否在多边形内
// （不能用路径规划 API 完成）

// 正确：纯几何操作
point_in_polygon_tool({ point: location, polygon: boundary });
```

**为什么错误：** 路径规划 API 不执行几何包含

### ❌ 不要：混淆“邻近”与“可达”

```javascript
// 用户询问： "在 20 分钟内可以到达什么？"

// 错误：20 分钟距离乘以平均速度
distance_tool + 计算 20min * avg_speed

// 正确：实际路径规划带道路网络
isochrone_tool({
  coordinates: {longitude: startLng, latitude: startLat},
  contours_minutes: [20],
  profile: "mapbox/driving"
})
```

**为什么错误：** 道路不是直线；交通变化

### ❌ 不要：当指南针足够时使用路径规划

```javascript
// 用户询问： "机场的方向是什么？"

// 过度复杂：完整路径规划
directions_tool({
  coordinates: [
    { longitude: hotel[0], latitude: hotel[1] },
    { longitude: airport[0], latitude: airport[1] }
  ]
});

// 更好：只需要方向
bearing_tool({ from: hotel, to: airport });
// 返回： "东北方向 (45°)"
```

**为什么更好：** 更简单，即时，回答了实际问题

## 混合方法：组合工具类型

某些问题受益于同时使用几何和路径规划工具：

### 模式 1：路径规划 + 几何过滤

```
1. directions_tool → 获取路径几何
2. buffer_tool → 在路径周围创建走廊
3. category_search_tool → 在走廊中查找 POI
4. point_in_polygon_tool → 过滤那些实际在路径上的
```

**用例：** "沿我的路线查找加油站"

### 模式 2：路径规划 + 距离计算

```
1. category_search_tool → 查找 10 个附近的位置
2. distance_tool → 计算直线距离（几何）
3. 对于前三名，使用 directions_tool → 获取实际驾驶时间
```

**用例：** 快速缩小范围，然后对决赛者进行精确路径规划

### 模式 3：Isochrone + 包含

```
1. isochrone_tool → 创建旅行时间区域（路径规划）
2. point_in_polygon_tool → 检查数百个地址（几何）
```

**用例：** "哪些客户在我们的配送区域内？"

## 决策算法

当用户询问地理空间问题时：

```
1. 它是否需要路径规划、道路或旅行时间？
   是 → 使用路径规划 API (directions, matrix, isochrone, optimization)
   否 → 继续

2. 它是否需要交通感知？
   是 → 使用 directions_tool 或 isochrone_tool 带交通配置文件
   否 → 继续

3. 它是否是几何/空间操作？
   - 点之间的距离（直线） → distance_tool
   - 点包含 → point_in_polygon_tool
   - 面积计算 → area_tool
   - 缓冲区/区域 → buffer_tool
   - 方向/指南针 → bearing_tool
   - 几何中心 → centroid_tool
   - 边界框 → bounding_box_tool
   - 简化 → simplify_tool

4. 它是否是搜索/发现操作？
   是 → 使用搜索工具 (search_and_geocode, category_search)
```

## 关键决策问题

选择工具之前，请询问：

1. **“距离”是指飞鸟直线距离还是飞鸟驾车距离？**
   - 飞鸟直线距离（直线）→ 几何工具
   - 飞鸟驾车距离（道路距离）→ 路径规划 API

2. **用户是否需要旅行时间？**
   - 是 → 路径规划 API（只有他们知道速度/交通）
   - 否 → 几何工具可能足够

3. **这是关于道路/路径还是纯空间关系？**
   - 道路/路径 → 路径规划 API
   - 空间关系 → 几何工具

4. **这需要实时执行且低延迟吗？**
   - 是 + 几何问题 → 离线工具（即时）
   - 是 + 路径问题 → 使用路径规划 API（仍然快速）

5. **准确性是否关键，还是近似值可以接受？**
   - 关键 + 路径 → 路径规划 API
   - 近似值可以接受 → 几何工具可能有效

## 快速参考

### 几何操作（离线工具）

- `distance_tool` - 两点之间的直线距离
- `bearing_tool` - 从 A 到 B 的指南针方向
- `midpoint_tool` - 两点之间的中点
- `point_in_polygon_tool` - 点是否在多边形内？
- `area_tool` - 计算多边形面积
- `buffer_tool` - 创建圆形缓冲区/区域
- `centroid_tool` - 多边形的几何中心
- `bbox_tool` - 几何的最小/最大坐标
- `simplify_tool` - 减少几何复杂性

### 路由与导航（APIs）

- `directions_tool` - 转弯导航
- `matrix_tool` - 多对多旅行时间
- `optimization_tool` - 路线优化（旅行商问题）
- `isochrone_tool` - 旅行时间区域
- `map_matching_tool` - 将 GPS 数据映射到道路

### 何时使用每个类别

**使用几何工具当：**

- 问题涉及空间/数学（包含、面积、方位）
- 直线距离适用
- 需要实时检查的即时结果
- 纯粹几何（不涉及道路/交通）

**使用路由 API 当：**

- 需要实际驾驶/步行/骑行距离
- 需要旅行时间
- 需要考虑道路网络
- 需要交通意识
- 需要路线优化
- 需要转弯导航

## REST API 诚实度（路线 / 等时线）

在生成针对 Mapbox REST API 的浏览器演示（不仅限于 MCP 工具）时：

### 路线 — 使用 API 的路线对象指标

```javascript
const route = data.routes[0];
// 良好 — 来自 API 的米数 / 秒数
stats.textContent =
  `距离 ${(route.distance / 1000).toFixed(2)} 公里 · ` + `时长 ${Math.round(route.duration / 60)} 分钟`;

// 不良 — 修饰性标签或硬编码的 ETA，看起来像工作演示
// "长度 0.00 公里 · 时间 2 分钟" / Math.round(120/60)
```

### 等时线 — 当提示要求多个区域时请求多个轮廓

```javascript
// 良好 — 三个旅行时间区域
`contours_minutes=15,30,60`;

// 不良 — 当 UX 需要 15 / 30 / 60 时使用单个轮廓
`contours_minutes=30`;
```
