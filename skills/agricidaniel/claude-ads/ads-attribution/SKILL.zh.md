# 归因审计

1. 阅读 `ads` 主合同和标准化账户快照。
2. 声明业务转化、价值、数据窗口、时区、货币以及归因分析必须支持的决定。
3. 列出每个浏览器、服务器、平台、分析、MMP、离线和应用归因来源的身份、计数、去重和隐私规则。
4. 核对可比事件并解释由资格、曝光规则、同意、建模数据、转化延迟、阈值或范围引起的差异。
5. 将测量质量与平台报告的性能分开。
6. 通过公共 JSON 合同返回发现、矛盾、置信度、缺失证据和测量改进计划。

不要假设某个平台是绝对标准，不要将不兼容的报告合并，或在操作员决策背景下不推荐归因模型。

## 可比性门

在来源共享或明确标准化到相同的转化事件和价值定义、归因窗口、点击/查看范围、计数方法、去重身份、时区、货币、归因模型和建模数据处理之前，拒绝聚合。在此之前，请并列报告其定义，不要计算总和。

示例：Meta 七日转化和 Google 三十日转化是不兼容的。拒绝将它们相加，应先核对窗口和定义，并仅聚合新形成的可比数据集。
