# 搜索体验优化 (SXO)

SXO 桥接了 SEO（谷歌奖励的内容）和 UX（用户需要的内容）之间的差距。
传统的 SEO 审计检查技术健康状况。SXO 会问："根据谷歌在搜索结果页面 (SERP) 中实际奖励的内容，这个页面是否值得为这个关键词排名？"

## 核心洞察

一个页面在技术 SEO 上的得分可以达到 95/100，但仍可能无法排名，因为它对于这个关键词来说**页面类型不匹配**。如果谷歌针对你的关键词显示 8 个产品页面和 2 个比较页面，你的博客文章无论如何都无法突围——无论它多么优化。

## 命令

| 命令 | 目的 |
|------|------|
| `/seo sxo <url>` | 执行完整的 SXO 分析（自动从页面检测关键词） |
| `/seo sxo <url> <keyword>` | 针对特定关键词执行完整的 SXO 分析 |
| `/seo sxo wireframe <url>` | 生成 IST/SOLL 线框图，包含具体的占位符 |
| `/seo sxo personas <url>` | 仅进行用户画像评分（跳过 SERP 分析） |

## 执行流程

### 第 1 步：目标获取

1. 通过 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run render_page.py <URL> --mode auto`（感知 SPA 和 SSRF 安全）抓取目标 URL
2. 使用 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run parse_html.py <URL>` 解析，提取：标题、H1、元描述、标题层级、字数、模式化标记、行动号召 (CTA)、媒体元素
3. 如果未提供关键词，从标题标签和 H1 重叠中提取主要关键词
4. 在继续之前验证关键词非空

### 第 2 步：SERP 逆向分析

阅读 `references/page-type-taxonomy.md` 获取分类规则。

1. 在谷歌搜索目标关键词（WebSearch）
2. 对于前 10 个有机结果，记录：
   - URL 和域名权威层级（品牌 / 垂直权威 / 未知）
   - 页面类型（使用分类法分类）
   - 内容格式（长文、列表、教程、比较、工具、视频）
   - 字数估计（根据摘要长度和页面结构）
   - 存在的模式化类型（根据当前支持的 SERP 功能；排除 FAQ/教程）
   - 媒体信号（视频轮播、图片包、缩略图存在）
3. 记录 SERP 功能：
   - 突出显示片段（段落 / 列表 / 表格 / 视频）
   - 也有人问 (People Also Ask)（提取所有可见问题）
   - 广告（顶部和底部——计数和分析广告文案主题）
   - 相关搜索（提取所有）
   - 知识面板 / 本地包 / 购物结果
   - AI 概览存在及其来源类型
4. 计算 SERP 共识：
   - 主导页面类型（>60% = 强共识，40-60% = 混合，<40% = 分散）
   - 内容深度预期（平均字数层级）
   - 模式化预期（最常见的结构化数据类型）
   - 媒体预期（需要视频吗？图片是否关键？）

### 第 3 步：页面类型不匹配检测

这是核心的 SXO 洞察。比较目标页面类型与 SERP 共识。

**不匹配严重程度等级：**

| 目标类型 | SERP 预期 | 严重程度 | 建议 |
|----------|----------|----------|------|
| 博客文章 | 产品页面 | 严重 | 创建专门的产品页面 |
| 博客文章 | 比较 | 高 | 重组为比较矩阵 |
| 产品页面 | 信息性 | 高 | 添加教育性内容层级 |
| 登录页面 | 工具/计算器 | 高 | 构建交互式工具组件 |
| 服务页面 | 本地结果 | 中 | 添加位置信号 + 本地模式化 |
| 任何类型匹配 | - | 匹配 | 专注于内容深度和 UX |

**分类规则：**
- 使用 `references/page-type-taxonomy.md` 对目标页面进行分类
- 使用相同的分类法对每个 SERP 结果进行分类
- 如果目标类型与 SERP 主导类型不同，则标记不匹配
- 如果 SERP 分散（无主导类型），则注意差异化机会

### 第 4 步：用户故事推导

阅读 `references/user-story-framework.md` 获取完整框架。

从 SERP 信号中推导用户故事：

1. **PAA 问题**揭示知识空白和关注点
2. **广告文案主题**揭示商业触发因素和价值主张
3. **相关搜索**揭示搜索旅程（之前/之后）
4. **突出显示片段格式**揭示预期的答案结构
5. **AI 概览**揭示谷歌认为的权威答案

对于每个信号集群，生成一个用户故事：
```
作为一个 [从信号推导出的用户画像]，
我想要 [目标推导自查询意图]，
因为 [来自广告文案/ PAA 语气中的情感驱动]，
但我被 [来自 PAA 问题/相关搜索的障碍] 阻碍。
```

生成 3-5 个覆盖主要意图角度的用户故事。

### 第 5 步：差距分析

在 7 个维度上比较目标页面与 SERP 预期：

| 维度 | 比较 | 分数 |
|------|------|------|
| 页面类型 | 目标类型与 SERP 主导类型 | 0-15 |
| 内容深度 | 字数、标题层级、主题覆盖 | 0-15 |
| UX 信号 | CTA 清晰度、首屏内容、移动布局 | 0-15 |
| 模式化标记 | 存在 vs 预期的结构化数据类型 | 0-15 |
| 媒体丰富度 | 图片、视频、交互元素 vs SERP 规范 | 0-15 |
| 权威信号 | E-E-A-T 标记、社会证明、资质 | 0-15 |
| 新鲜度 | 最后更新、日期信号、内容时效性 | 0-10 |

**总分：0-100 SXO 差距分数**（较低 = 较大差距，较高 = 更好匹配）

### 第 6 步：基于用户画像的评分

阅读 `references/persona-scoring.md` 获取方法。

1. 从 SERP 意图信号中推导 4-7 个用户画像：
   - 按主题对 PAA 问题进行聚类
   - 按目标受众对广告文案进行细分
   - 将相关搜索映射到旅程阶段
2. 对于每个用户画像，在 4 个维度（每个 25 分）上评分目标页面：
   - **相关性**：页面是否解决了这个用户画像的需求？
   - **清晰度**：这个用户画像是否能在 10 秒内找到答案？
   - **信任度**：是否有足够的信任信号？
   - **行动**：是否有清晰的下一步行动？
3. 输出用户画像卡片，包含分数和具体的改进建议
4. 按最弱的用户画像排序（最大的机会）

### 第 7 步：线框图生成（可选）

仅当执行 `/seo sxo wireframe` 时执行。

阅读 `references/wireframe-templates.md` 获取模板。

1. 从解析的页面结构生成 IST（当前状态）线框图
2. 基于：
   - SERP 共识页面类型
   - 差距分析结果
   - 用户画像评分弱点
   生成 SOLL（目标状态）线框图
3. 使用超具体的占位符：
   - 不： "在这里添加 CTA"
   - 是： "在英雄图下方添加带年度节省徽章的定价 CTA，链接到 /pricing#enterprise"
4. 输出为带注释的语义 HTML 章节大纲

## DataForSEO 集成

如果 DataForSEO MCP 工具可用：

1. **在调用任何 API 之前**，运行成本估算并确认用户
2. 使用 `serp_organic_live_advanced` 获取精确的 SERP 数据（位置、功能、片段）
3. 使用 `kw_data_google_ads_search_volume` 获取搜索量和竞争指标
4. 如果 DataForSEO 不可用，则回退到 WebSearch——注意输出精度降低

## SXO 分数与 SEO 健康分数

SXO 分数**独立于**主要的 SEO 健康分数。

- SEO 健康分数 = 技术合规性（可爬取性、速度、模式化等）
- SXO 差距分数 = 页面与 SERP 预期的匹配度
- 一个页面可以得 95 SEO + 30 SXO = 技术完美但战略错位
- 当两者都可用时，应一起报告

## 输出格式

### 完整的 SXO 分析

```
## SXO 分析：[URL]
### 目标关键词：[keyword]

### 1. SERP 风景
- 主导页面类型：[类型] ([置信度]% 共识)
- SERP 功能：[列表]
- 内容深度规范：[字数范围]
- 模式化预期：[类型]

### 2. 页面类型匹配
- 你的页面类型：[类型]
- SERP 预期：[类型]
- 判定：[匹配 | 不匹配 (严重程度)]
- 影响：[解释]

### 3. 用户故事（从 SERP 信号推导）
[3-5 个用户故事及来源信号]

### 4. 差距分析 (SXO 分数：XX/100)
[7 维度分解表格]

### 5. 用户画像分数
[4-7 个用户画像卡片，4 维度分数]

### 6. 优先行动
[排序列表：首先修复不匹配，然后最弱的用户画像差距]

### 7. 局限性
[无法评估的内容，数据源注释]
```

## 错误处理

| 错误 | 操作 |
|------|------|
| URL 抓取失败 | 报告错误，建议检查 URL 可访问性 |
| 未提供关键词或检测不到 | 要求用户提供目标关键词 |
| WebSearch 返回 <5 个结果 | 使用可用数据继续，注意样本有限 |
| SERP 没有有机结果（全是广告） | 注意高度商业化的 SERP，仅分析广告文案 |
| 目标页面是 JavaScript 渲染的 | 注意限制，使用可用 HTML 内容 |
| DataForSEO 成本超过阈值 | 回退到 WebSearch，通知用户 |

## 质量检查清单

交付结果前，验证：
- [ ] 目标 URL 通过 `"${CLAUDE_PLUGIN_ROOT}/scripts/claude-seo" run render_page.py <URL> --mode auto`（不是原始 curl/fetch）抓取
- [ ] 页面类型分类使用来自 references 的分类法
- [ ] 至少分析了 5 个 SERP 结果
- [ ] 用户故事引用了具体的 SERP 信号作为证据
- [ ] 用户画像分数包含具体的改进建议
- [ ] 清晰标记 SXO 分数独立于 SEO 健康分数
- [ ] 局限性部分存在且诚实
- [ ] 相关技能建议在相关情况下包含
