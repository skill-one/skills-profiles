# 博客撰写器：新文章生成

根据主题、简报或提纲撰写完整的博客文章。每篇文章都遵循双重优化（谷歌排名+AI引用）的六大支柱。

**关键参考资料**（相对于仓库根目录的路径；参考资料位于主要的`blog`技能的参考资料目录中，而不是在`blog-write/`中）：

- `skills/blog/references/synthesis-contract.md`：合成输出的6 LAWs（v1.8.0；每当文章嵌入研究合成文本时适用）
- `skills/blog/references/content-templates.md`：模板选择指南和使用方法
- `skills/blog/references/quality-scoring.md`：5类评分（内容30，SEO 25，E-E-A-T 15，技术 15，AI引用 15）
- `skills/blog/references/eeat-signals.md`：经验、专长、权威、信任标志
- `skills/blog/references/internal-linking.md`：链接策略和锚文本规则
- `skills/blog/references/visual-media.md`：图片来源和图表样式
- `skills/blog-write/references/delivery.md`：此子技能的交付合同步骤和总结模板

## 工作流程

### 阶段 0：表面目标定位（在研究之前执行）

确定此帖子旨在赢得的FLOW 5表面的哪一个。选择会塑造结构、长度、引用密度和号召性用语。2026年的5个表面：

1. 自有网站（有机谷歌排名）
2. 包括AI概述的搜索结果页面（SERP）
3. AI助手引用（ChatGPT、Perplexity、Claude、Gemini、Copilot、You.com）
4. 本地包（博客内容不在此范围内；使用claude-seo用于本地）
5. 社区和视频（Reddit、YouTube、LinkedIn、Quora、专业论坛）

默认情况下，大多数帖子针对表面1、2和3。如果相同的查询也出现在社区中（Reddit帖子、YouTube评论），则应用双重表面思维：优化帖子以供提取，并计划社区回响（在`/blog repurpose`中涵盖）。

要了解更深入的逐表面工作流程，请参阅`skills/blog/references/flow-alignment.md`和`/blog flow find`。

### 阶段 1：主题理解

1. **明确主题** - 如果用户只提供主题，请询问：
   - 目标受众（这是为谁准备的？）
   - 主要关键词 / 搜索意图
   - 期望的字数（默认：2,000-2,500字）
   - 平台/格式（MDX、markdown、HTML - 如果在项目中则自动检测）
2. **如果存在简报** - 加载它并跳到阶段1.5

### 阶段 1.5：模板选择

从`skills/blog/templates/`中的12个模板中选择合适的内容模板（主要的`blog`技能拥有模板目录）。

1. **根据主题和搜索意图自动检测内容类型**：
   | 信号 | 模板 |
   |------|------|
   | "如何..."、过程、步骤 | `how-to-guide` |
   | "最佳X"、"前N名"、列表格式 | `listicle` |
   | 客户成果、前后对比、指标 | `case-study` |
   | "X与Y对比"、比较、替代方案 | `comparison` |
   | 广泛主题、综合指南 | `pillar-page` |
   | "X是否值得"，产品评估 | `product-review` |
   | 意见、预测、行业观点 | `thought-leadership` |
   | 专家引言、多来源收集 | `roundup` |
   | 代码演示、工具演示、技术 | `tutorial` |
   | 突发新闻、算法更新、事件 | `news-analysis` |
   | 调查结果、实验、原始数据 | `data-research` |
   | 问答、知识库、"X是什么" | `faq-knowledge` |

2. **加载匹配的模板**：从`skills/blog/templates/<type>.md`读取
3. **调整提纲** - 使用模板的章节结构、标题模式和字数指导来塑造阶段3的提纲
4. **后备** - 如果没有模板明显适用，则使用阶段3下方的通用提纲结构。通知用户选择的模板（或没有匹配的模板）。

有关详细的选择标准和意图映射，请参阅`skills/blog/references/content-templates.md`。

### 阶段 2：研究

生成`blog-researcher`代理（或使用WebSearch进行内联研究）：

1. **找到8-12个当前统计数据**（优先考虑2025-2026年的数据）
   - 搜索：`[主题] study 2025 2026 data statistics`
   - 优先级：1-3级来源（见`skills/blog/references/quality-scoring.md`）
   - 记录：统计数据、来源名称、URL、日期、方法
2. **找到封面图片**（宽、高质量、主题相关）：
   - 优先使用原始截图、产品视觉效果、图表或数据图形（如果可用）
   - 对于库存，使用官方API，如Openverse、Unsplash、Pexels或Pixabay，以便捕获许可、创作者、来源URL和下载URL
   - 将批准的资产下载到草稿文件夹，存储归属，并且永远不要热链接任意的CDN URL
   - 拒绝`javascript:`、`data:`和`file:`图片URL
   - 目标尺寸：1200x630（OG兼容）或1920x1080
   - 或者通过`blog-chart`生成自定义SVG封面（带有关键统计的渐变文本）
   - 或者通过`blog-image`生成自定义AI图片；优先使用`gemini-3.1-flash-image`，然后是`gemini-3.1-flash-lite-image`或`gemini-3-pro-image`（当可用时），并记录模型ID
   - 有关封面图片尺寸的详细信息，请参阅`skills/blog/references/visual-media.md`
3. **从开源平台找到3-5个内联图片**：
   - 使用官方API或Openverse搜索；保留每个资产的许可、创作者、来源URL和检索日期
   - 将图片本地下载并使用草稿中的本地路径引用
   - 在下载前，使用交付合同的SSRF规则验证最终URL
4. **计划2-4个数据可视化**从研究统计数据
   - 选择多样化的图表类型（见`skills/blog/references/visual-media.md`）
   - 将数据点映射到图表格式
5. **AI图片生成**（可选，如果`blog-image`可用）：
   - 如果库存照片结果不足（少于3个良好匹配）或主题过于专业
   - 通过`blog-image`子技能生成自定义英雄图片和/或内联插图
   - 记录提示、提供者和模型ID；库存照片仍然可用，但当原始和数据视觉效果更好地服务于主题时，它们是首选
6. **NotebookLM研究**（可选，如果用户有相关的笔记本）：
   - 如果用户提到NotebookLM笔记本或主题与配置的笔记本对齐
   - 通过`blog-notebooklm`查询用户上传文档中的来源数据
   - 继承底层文档来源的来源级；用户自己的主要文档可以是Tier 1，而复制的二级来源保留其原始级
   - 如果未配置或未认证，则静默回退
7. **找到相关的YouTube视频**（每篇文章2-3个）：
   - 使用`blog-google` youtube命令或WebSearch `site:youtube.com [主题] [年份]`
   - 应用来自`skills/blog/references/video-embeds.md`的质量标准（最低分数50/100）
   - 选择2-3个最佳视频。如果没有找到，则静默回退。

### 阶段 4：图表生成（内置）

当研究人员识别出值得制作图表的数据（3个以上可比较的指标、趋势数据、前后对比）时：

1. 使用多样性规则选择图表类型（每篇文章不要重复相同类型）
2. 调用`blog-chart`子技能，提供：图表类型、标题、数据值、来源、平台格式
3. 将返回的SVG直接嵌入文章中，使用`<figure>`包装器
4. 每篇2,000字的文章目标2-4个图表
5. 均匀分布图表，不要将它们聚集在一起

有关图表类型选择和样式规则的详细信息，请参阅`skills/blog/references/visual-media.md`。

### 阶段 5：内容撰写

按照以下规则撰写完整文章：

#### 5a. 前置信息
```yaml
---
title: "[包含主要关键词的问题格式标题]"
description: "[事实密集型，150-160字符，包含1个统计数据]"
coverImage: "[来自Pixabay/Unsplash/Pexels的URL或生成的SVG路径]"
coverImageAlt: "[关于封面图片的描述性句子]"
ogImage: "[与coverImage相同，或自定义OG图像URL]"
date: "YYYY-MM-DD"
lastUpdated: "YYYY-MM-DD"
author: "[作者姓名]"
tags: ["keyword1", "keyword2", "keyword3"]
---
```

如果平台使用不同的字段名（例如，`image`、`hero`、`thumbnail`），则适应以匹配项目的现有前置信息约定。

#### 5b. 摘要框（关键要点）

在介绍之后（在第一个H2正文部分之前）添加摘要框：

```markdown
> **关键要点**
> - [带有统计数据的核心理解]([来源], 年份)
> - [第二关键见解或建议]
> - [第三条可操作的要点]
```

要求：
- 3-5个要点，40-60字组合
- 必须是自包含的 - 不阅读文章即可理解
- 包含1个具体统计数据和来源名称
- 陈述关键发现、建议或答案
- 默认标签："关键要点"。如果有人格处于活动状态，则使用该人格的summary_label
- 向后兼容：接受在重写期间现有的TL;DR框

#### 5c. 首先回答格式（关键）
每个H2部分必须以包含以下内容的40-60字段落开头：
- 至少一个带有来源归因的具体统计数据
- 对标题隐含问题的直接答案

模式：
```markdown
## 如何在2026年X影响Y？

[来自来源的统计数据]([来源名称](url), 年份)。[用1-2句话直接回答标题问题，解释其影响以及这对读者意味着什么。]
```

**FLOW证据三重（草稿要求，不仅仅是审计）**：

在草稿时间，每个公开统计数据必须携带三个组件：

1. **文本中的年份锚点**。在统计数据之前，在句子主体中写上"在2026年"或"截至2026年第一季度"，年份埋在括号内不计。示例：
   - 良好： "在2026年，Ahrefs发现当存在AI概述时，第一名的CTR降低了58%。"
   - 弱： "第一名的CTR下降了58%（Ahrefs，2026）。"

2. **带有出版商和标题的内联引用**。命名出版商和文档标题（或报告名称），而不仅仅是品牌。示例：
   - 良好： "Ahrefs，《[文档或报告标题]》，2026"
   - 弱： "Ahrefs报告..."

3. **在帖子底部的来源块中的URL和检索日期**。来源纪律使未来的读者和AI爬虫能够验证来源仍然说所声称的内容。格式：
   - "[出版商]，[标题]，检索YYYY-MM-DD，[完整URL]"

**FLOW质量条（放弃或替换）**：
公开声明必须使用已验证来源，或保持定性。如果一个统计数据无法验证，则放弃它。如果一个更近期的来源与之矛盾，则用已验证的替代方案替换它。不要软化模糊语言以保留无法验证的数字。

有关证据导向优化提示（CTR审计、AI检测测试、模式、PAA重写、ChatGPT可见性），请参阅`/blog flow optimize`。

#### 5d. 信息增益标记

在整个文章中至少分布2-3个信息增益标记。这些标记向搜索引擎和AI系统表明，内容包含其他地方无法获得的原创价值。

用评论或可见标记标记每个标记：

- `[原创数据]` - 专有调查、实验、A/B测试结果、作者亲自收集的案例研究指标
- `[个人经验]` - 亲自观察、直接参与学到的教训、"当我们尝试X时，Y发生了"叙事
- `[独特见解]` - 别人没有做的分析、有数据支持的逆向观点、现有研究之间的新联系

放置：
- 自然地编织到正文文本中
- 作为内联评论使用：`<!-- [原创数据] -->` 在相关段落之前
- 或者如果格式支持，作为可见引言：
  ```markdown
  > **我们的发现**：[有具体数据支持的原创观察]
  ```
- 每篇文章至少2个，全面文章目标3个

这些标记直接映射到内容质量评分类别中的"原创性/独特价值标记"标准（见`skills/blog/references/quality-scoring.md`）。

#### 5e. 引用胶囊

为每个主要H2部分生成引用胶囊 - 一个40-60字的自包含段落，设计为AI系统可以直接提取和引用。

每个胶囊的要求：
- 40-60字，自包含（孤立即可理解）
- 包含：一个具体声明 + 一个数据点 + 来源归因
- 用陈述性、可引用的风格编写
- 放置在H2部分正文内（不是单独的块）

示例：
```markdown
根据2026年的Gartner研究，58%的企业买家现在在联系供应商之前会咨询AI助手（[Gartner](https://www.gartner.com), 2026）。这种转变意味着B2B内容必须简洁地回答特定问题，以便AI系统能够提取并在其响应中引用。
```

胶囊映射到`skills/blog/references/quality-scoring.md`中的"AI引用准备"评分类别（15分）。

#### 5f. 内部链接区域

使用占位符符号在整个文章中标记内部链接机会。用户（或后续步骤）将解决这些到实际URL。

区域放置：
- **简介** - 链接到相关的支柱内容或主题中心
- **每个H2部分** - 链接到支持文章、深入探讨、相关工具
- **FAQ部分** - 将答案链接到详细内容，该内容扩展了答案
- **结论** - 链接到读者应该消费的下一个逻辑内容

格式：
```markdown
[内部链接：锚文本→目标描述]
```

示例：
```markdown
有关关键词集群的深入探讨，请参阅我们的
[内部链接：完整的键

#### 5g. 段落规则
- 每个段落：40-80字（不超过150字）
- 每个句子：最多15-20字
- 每个段落以最重要的信息开头
- 目标Flesch易读性：60-70

#### 5h. 标题规则
- 一个H1（仅标题）
- H2用于主要章节（60-70%作为问题形式）
- H3用于子章节，且不能跳过层级
- 在2-3个标题中自然包含核心关键词

#### 5i. 图片嵌入

标准markdown：
```markdown

```

- 在文章中均匀分布（不聚集）

#### 5k. 视频嵌入
使用`skills/blog/references/video-embeds.md`中的srcdoc懒加载模式嵌入YouTube视频。包含aria-label、noscript回退以供AI爬虫使用。放置在相关H2标题后、500字以上处。

#### 5l. 引用格式
行内归因（始终）：
```markdown
2026年2月，Seer Interactive的AI概述CTR追踪器报告了AI概述SERP上2.4%的有机CTR（[Seer Interactive](https://www.seerinteractive.com/)，检索日期YYYY-MM-DD）。
```

#### 5m. FAQ部分
当用户问题需要时，添加3-5个FAQ项，答案为40-60字。当存在相关来源支持的数字时，每个答案必须包含一个经过验证的统计数据。

FAQPage是可选的实体标记。自2023年指导以来，Google FAQ丰富结果主要限于知名、权威的政府与健康网站，因此不要将FAQ模式作为核心Google丰富结果输出或引用杠杆。优先考虑Article/BlogPosting + Person + Organization + BreadcrumbList；仅在平台已支持且问题确实帮助用户时才发出FAQPage。

对于带有可选FAQSchema组件的MDX：
```mdx
<FAQSchema faqs={[
  { question: "问题?", answer: "40-60字答案，包含统计数据和来源。" },
]} />
```

对于标准markdown：
```markdown
## 常见问题解答

### 问题文本？

用统计数据和来源归因进行回答（40-60字）。
```

#### 新元素验证

11. 至少2-3个信息增益标记（`[原创数据]`、`[个人经验]`或`[独特见解]`）

14. 没有来自禁止列表的可检测AI短语（见`agents/blog-writer.md`）

#### 爆发性和自然性检查
15. **句子长度差异** - 验证短句（8字）和长句（25字）的混合。均匀的句子长度表明AI作者身份。
16. **禁止AI短语扫描** - 检查并删除：
    - "在当今数字环境中"、"重要的是要注意"、"深入探讨"
    - "变革者"、"导航环境"、"革新"、"无缝衔接"
    - "尖端"、"利用"、"杠杆"（作为动词）
    - "深入"、"关键"、"提升"、"促进"、"环境"（过度使用）
    - "多方面"、"稳健"、"织锦"、"启程"
    - 完整列表在`agents/blog-writer.md`
17. **缩写** - 验证自然使用缩写（"it's"、"we've"、"don't"、"isn't"）。正式AI文本避免缩写；自然写作使用缩写。
18. **反问句** - 验证每200-300字至少一个反问句以打破陈述模式。
19. **YouTube视频** - 2-3个嵌入，带懒加载、aria-label和noscript回退（见`skills/blog/references/video-embeds.md`）
