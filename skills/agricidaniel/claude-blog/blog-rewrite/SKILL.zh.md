# 博客重写器：优化现有文章

重写并优化现有博客文章，以实现双重排名：谷歌搜索和AI引文平台。在应用优化六支柱的同时，保留作者的声音。

**关键参考：**
- `skills/blog/references/quality-scoring.md` - 5类评分（内容30，SEO 25，E-E-A-T 15，技术 15，AI引文 15）
- `skills/blog/references/eeat-signals.md` - 经验、专长、权威、信任标志
- `skills/blog/references/internal-linking.md` - 链接策略和锚文本规则
- `skills/blog/references/visual-media.md` - 图片来源和图表样式
- `skills/blog/references/synthesis-contract.md` - 6 LAWs在重写期间用于引文卫生（v1.8.0；跨技能参考存在于协调器的参考目录中）
- `skills/blog/references/research-quality.md` - 跨源聚类用于替换统计数据研究（v1.8.0）

## 交叉引用

对于21个证据导向的优化提示（AI检测器测试、CTR审计、模式、PAA重写、技术审计、ChatGPT可见性），这些提示直接适用于重写工作，请参阅`/blog flow optimize`。

## 工作流程

### 第一阶段：审计（只读）

1. **阅读博客文章** - 检测格式（MDX、markdown、HTML）
2. **运行质量清单** 对 `skills/blog/references/quality-scoring.md`：
   - 统计虚构与来源统计数据
   - 检查答案优先格式（H2 -> 第一句话中的统计数据？）
   - 统计图片和图表（类型多样性？）
   - 衡量段落长度（是否有 > 150 个字的？）
   - 检查标题层次结构（H1 -> H2 -> H3，没有跳过？）
   - 检查模式的存在和有效性，优先考虑Article/BlogPosting、Person、Organization和BreadcrumbList；FAQPage仅作为可选实体标记
   - 检查新鲜度信号（lastUpdated、dateModified）
   - 评估自我推广水平
   - 评估引文层质量
3. **AI内容检测扫描**：
   - **爆发性分数** - 衡量文章中句子长度的差异。低差异（大多数句子彼此相差3-5个字）是强烈的AI信号。
     计算：句子单词数的标准差。目标SD > 6。
   - **已知AI短语扫描** - 检查以下高频AI短语：
     - "在当今数字环境中"、"重要的是要注意"、"深入探讨"
     - "变革者"、"导航环境"、"革命化"、"无缝"
     - "尖端"、"利用...的力量"、"利用"（作为动词）
     - "深入研究"、"关键"、"提升"、"培养"、"环境"（过度使用）
     - "多方面的"、"强大的"、"织锦"、"启程"
     - 完整列表在`agents/blog-writer.md`
   - **词汇多样性** - 计算Type-Token Ratio (TTR)：独特单词 / 总单词数。低TTR（< 0.40）表明AI生成的重复短语。
     目标TTR > 0.50，用于自然散文。
   - **AI内容百分比估计** - 基于爆发性、短语密度和TTR，估计内容中有多少比例看起来像AI生成的（0-100%）。
     报告为："AI内容估计：~X%"
   - **二级结构反射扫描**（v1.8.0） - 上述一级检查是词汇级的。二级扫描捕获它们之后幸存的结构和节奏特征，LLM在替换明显单词后默认采用这些特征。与`skills/blog/references/ai-slop-detection.md`运行。至少标记：
     - 70%的标题中超过70%的问句式H2
     - 三个或更多的"这里..."段落开头
     - 任何200字窗口中50%以上的三句式句子节奏
     - 任何20字跨度中超过2个缓冲词（"可能"、"通常"、"典型"、"通常"）
     - 对称列表膨胀（列表项单词数SD低于5）
     - 超过2个总结性修辞问题（"这对...意味着什么？"）
     - 超过一半的H2开头以过渡词开头
     - "关键洞察是..."或"这里重要的是..."作为句子开头
     - 列表文章的列表前介绍超过250字
     - 开头单词重复：前三个首字母单词超过25%的份额
     - 段落形状SD低于25（视觉单调性）
     - 草稿只有在两次扫描都干净时才为"AI检测干净"。两个命名空间的术语（用于斜坡检测的第一级/二级与来源权威的1级/2级/3级）是故意的：参见`skills/blog/references/ai-slop-detection.md`了解v1.8.1中标签为何出现分歧。
4. **视频嵌入检查**：
   - 统计文章中现有的YouTube嵌入
   - 如果0个嵌入，标记："没有视频嵌入。考虑在添加相关高质量YouTube嵌入时提供有用的上下文。"
   - 如果存在，检查：懒加载？aria-labels？noscript回退？VideoObject模式？
5. **同化检查**：
   - 从标题、H1和第一段确定文章的主要关键词
   - 在博客目录中搜索其他针对相同关键词的文章：
     - 跨所有博客文章grep标题和元描述
     - 标记任何有显著关键词重叠的文章
   - 如果发现同化，报告：
     - 哪些文章竞争相同的关键词
     - 建议：**合并**（合并成一个更强的文章）或**区分**（将一个文章转移到相关但不同的关键词）
6. **计算当前分数** 跨5个类别：
   - 5个类别中的分数（内容质量30，SEO优化25，E-E-A-T信号15，技术元素15，AI引文准备15）
   - 总分：0-100
7. **呈现审计摘要**，包括具体发现、AI检测结果、视频状态、同化状态和分数
8. **进入计划模式** - 呈现按部分优化的计划

在继续之前等待用户批准。

### 第二阶段：研究

1. **从现有内容中确定博客的核心主题**
2. **查找替换统计数据**，用于任何虚构/未来源的数据：
   - 搜索：`[主题]研究2025 2026数据统计数据`
   - 仅目标1-3级来源
3. **查找图片**，如果文章少于3张：
   - 优先使用原始截图、产品视觉效果、图表或数据图形（如果可用）
   - 对于库存，使用官方提供者API，如Openverse、Unsplash、Pexels或Pixabay，以便捕获许可、创作者、来源URL和下载URL
   - 本地下载批准的资产，存储归属，并拒绝`javascript:`、`data:`和`file:` URL
   - 如果`blog-image`可用，提供AI生成缺失或不足的图片，并记录选定的模型ID
4. **计划图表**，如果文章少于2张：
   - 确定适合可视化的数据
   - 选择多样化的图表类型

### 第三阶段：图表生成（内置）

当文章需要更多视觉元素时，调用`blog-chart`子技能：

1. 使用多样性规则选择图表类型（每个文章不重复类型）
2. 传递：图表类型、标题、数据值、来源、平台格式
3. 直接在`<figure>`包装器内嵌入返回的SVG
4. 每个每2000字的文章目标2-4个图表

参见`skills/blog/references/visual-media.md`了解图表类型选择和样式规则。

### 第四阶段：内容重写

按顺序应用更改：

#### 4a. 保留有效部分
- 保留作者的声音和独特视角
- 保留原始见解和一手经验
- 保留现有质量图片和图表
- 维持内部链接

#### 4b. 修复Frontmatter
- 添加`lastUpdated: "YYYY-MM-DD"`（今天的日期）
- 保持原始`date`不变
- 修复元描述：事实密集，150-160个字符，包含1个统计数据
- 如果缺少，添加`coverImage` + `coverImageAlt` + `ogImage`
  - 在Pixabay/Unsplash/Pexels搜索宽英雄图片（1200x630）
  - 或者通过`blog-chart`生成自定义SVG封面（渐变上的文本与关键统计数据）
  - 或者当可用时，通过`blog-image`子技能生成自定义AI图片；记录模型ID
- 验证标签/类别是否适当

#### 4c. 应用答案优先格式
每个H2部分必须以包含以下内容的40-60字段落开头：
- 至少一个带来源归因的具体统计数据
- 对标题隐含问题的直接答案

#### 4d. 替换虚构统计数据
- 搜索模式："X%的..."、"X out of Y..."、未来源的声明
- 用来自1-3级来源的真实数据替换
- 始终包含完整的FLOW证据三元组：文本中的年份锚点、带出版商+文档标题/报告名称的内联引文，以及带完整URL+检索日期的来源块条目

#### 4e. 改进标题
- 将陈述标题转换为自然的问题（60-70%的目标）
- 保持2-3个陈述标题以增加多样性
- 确保关键词自然出现在2-3个标题中

#### 4f. 修复段落长度
- 分割任何超过150字的段落
- 目标：每段40-80字
- 确保每个段落以最重要的句子开头

#### 4g. 添加视觉元素
- 在H2标题后嵌入新图片，均匀分布
- 在相关部分嵌入图表
- 如果`blog-image`可用：为缺少良好库存匹配的部分生成自定义图片，优先使用当前图像模型注册表，并记录模型ID
- 根据检测到的平台（MDX vs markdown vs HTML）调整嵌入格式

#### 4h. 添加视频嵌入
如果文章缺少YouTube视频嵌入：
- 使用来自`skills/blog/references/video-embeds.md`的质量标准搜索2-3个相关视频
- 使用平台适当的格式嵌入（srcdoc懒加载）
- 放置：介绍后1个，文章中间部分1-2个
- 为AI爬虫添加noscript回退

#### 4i. 添加/改进FAQ
- 如果查询集值得添加且不存在FAQ，则添加一个（3-5个问题）
- 如果FAQ存在，确保答案为40-60字，包含已验证的统计数据
- FAQPage仅作为可选实体标记。自2023年指南以来，谷歌FAQ丰富结果主要限于知名、权威的政府和健康网站，因此不要将FAQPage作为核心谷歌丰富结果门。

#### 4j. 减少自我推广
- 最大1个品牌提及（仅在作者简介上下文中）
- 删除"At [Company], we..."模式
- 将促销部分转换为教育内容

#### 4k. 引文胶囊注入
对于每个H2部分，生成（或改进现有的）引文胶囊：
- 每个H2 40-60字的自包含段落
- 包含：一个具体声明 + 一个数据点 + 来源归因
- 以陈述风格编写，以便AI系统可以直接提取并引用它
- 自然地放置在部分正文中，而不是作为单独的调用

示例：
```markdown
根据2026年的Gartner研究，58%的企业买家现在在联系供应商之前咨询AI助手
([Gartner](https://www.gartner.com), 2026)。这种转变意味着B2B内容必须简洁地回答
具体问题，以便AI系统能够提取并在其响应中引用。
```

胶囊映射到`skills/blog/references/quality-scoring.md`中的"AI引文准备"类别（15分）。

#### 4l. Anti-AI-Detection Patterns
应用这些转换以减少可检测的AI写作模式：
- **消除em破折号** - 将每个U+2014字符替换为逗号、连字符、冒号或句号。如有必要，拆分句子。破折号是AI写作的线索。
- **替换标记短语** - 将每个检测到的AI短语（来自第一阶段第3步的扫描）替换为自然替代方案。示例：
  - "it's important to note" -> "值得注意"或"记在心里"
  - "in today's digital landscape" -> "现在"或"[具体年份]"
  - "leverage" -> "使用"、"应用"、"利用"
  - "delve" -> "查看"、"探索"、"深入研究"
  - "robust" -> "强大"、"坚固"、"可靠"
  - "crucial" -> "关键"、"必要"、"关键"（或重构句子）
- **故意变化句子长度** - 重写后，扫描每个段落。在较长的句子（18-25个字）之间注入简短的冲击性句子（5-10个字）。
  目标：不超过5个连续句子长度彼此相差5个字。
- **注入修辞问题** - 每200-300字至少添加一个修辞问题，以打破陈述单调性。
- **自然使用缩写** - 将正式结构替换为在听起来自然的地方使用缩写："it is" -> "it's"、"we have" -> "we've"、"do not" -> "don't"、"is not" -> "isn't"。
- **包含缓冲语言** - 撒播第一人称缓冲词，以表明真实经验："在我们的经验中"、"我们发现"、"从我们看到的"、"这倾向于"、"这取决于"。

#### 4m. 摘要框（关键要点）
如果文章缺少摘要框，立即在介绍后添加一个：
```markdown
> **关键要点**
> - [带统计数据和来源的核心发现]
> - [第二个关键见解或建议]
> - [第三个可操作的要点]
> (3-5个要点，40-60字组合。自包含 - 读者在不阅读整篇文章的情况下获得
> 核心价值。)
```
默认标签是"关键要点"，但这是可配置的，每个角色或品牌声音（例如，"底线"、"快速摘要"、"您需要了解的"）。

如果存在现有的TL;DR框，将其转换为要点式关键要点格式。验证它是否满足40-60字要求，并至少包含一个带来源归因的统计数据。

#### 4n. 信息增益标记注入
审查文章以查找原创价值并标记它：
- `[原创数据]` - 作者一手收集的专有数据、调查结果、实验或案例研究指标
- `[个人经验]` - 一手观察、学到的教训
- `[独特见解]` - 新颖分析、反主流观点，有数据支持

如果文章缺少原创价值标记：
- 询问作者提供一手数据或经验以包含
- 至少添加连接现有研究的新方式的分析见解
- 目标：每篇文章至少2-3个标记

使用HTML注释（`<!-- [原创数据] -->`）或可见调用，具体取决于文章的风格。

### 第五阶段：验证

重写后，验证所有质量门通过：

#### 核心质量门
1. 每个H2以统计数据+来源开头
2. 没有段落超过150字
3. 零虚构统计数据
4. 标题层次结构清晰
5. 文章优先级模式存在且有效；仅当作为可选实体标记有用时才使用FAQPage
6. 图片具有描述性alt文本
7. Frontmatter中存在封面图片（coverImage + ogImage）
8. 如果MDX：构建项目以验证没有编译错误

#### 新元素验证
9. 介绍后存在TL;DR框（40-60字，包含统计数据）
10. 至少存在2-3个信息增益标记
11. 主要H2部分中的引文胶囊（40-60字，自包含）
12. 内部链接区域标记或实际链接存在（每2000字5-10个）
13. 没有来自禁用列表的AI可检测短语剩余

#### 爆发性和自然性检查
14. 句子长度方差：SD > 6（混合短句和长句）
15. 全文自然使用缩写
16. 每200-300字至少出现一个修辞问题
17. AI内容估计从审计基线降低
18. 与第一阶段审计相比，所有5个类别分数提高
19. 存在YouTube视频嵌入，带懒加载、aria-labels和noscript回退

## 第5.5阶段：交付合同执行 (v1.9.0)

在展示重写的草稿之前，按照`skills/blog/references/blog-delivery-contract.md`运行5门交付合同。该合同适用于重写，就像它适用于新帖子一样：用户永远不会是第一个审查者。

步骤：

1. **英雄图检查**：如果现有帖子已经引用了英雄图且仍在磁盘上，保留它。如果重写改变了主题实质性地OR英雄图丢失，通过`python3 scripts/generate_hero.py --topic "<新标题>" --tags "<标签>" --out <文件夹>`重新生成。
2. **重新渲染**：运行`python3 scripts/blog_render.py --md <slug>.md --out-dir <文件夹>`以从更新的.md刷新`.html`和`.pdf`。
3. **审查者派遣**：对渲染的`.html`派遣`blog-reviewer`代理。阈值：分数90/100或更高AND零P0问题。
4. **预检**：运行`python3 scripts/blog_preflight.py --draft <文件夹> --strict`。退出0 = 发送；退出1 = 阻止。
5. **失败迭代**：最多3次迭代。在第3次失败后，停止并呈现`<文件夹>/preflight-report.json`中的诊断。

重写有更高的隐含阈值，因为现有的草稿可能已经被发布。重新展示比原始版本更差的内容是不可接受的。如果重写的分数低于原始分数，这本身就是一个P0条件。

1. 将统计数据更新为最新可用数据（2025-2026）
2. 添加自上次更新以来的新进展
3. 如果图片超过1年，则刷新图片
4. 在frontmatter中更新`lastUpdated`
5. 保留现有结构 - 最小化重写
6. 目标：仅实现真实的新鲜度。替换过时的统计数据，添加真实的新进展，并更新`lastUpdated`/`dateModified`；不要重写以达到百分比变化阈值。
