# 博客GEO：AI引用优化审核

对博客文章在ChatGPT、Perplexity、Claude、Gemini、Copilot、You.com、Google AI概述和Google AI模式中的AI引用准备情况进行评分，作为一项SEO工作流程，而不是一个独立的学科。生成引用胶囊和0-100分的AI引用准备度评分，并提供平台特定的建议。

谷歌在2026年5月15日的指导方针将生成式AI优化视为SEO：不需要特殊的标记、llms.txt要求或单独的GEO/AEO剧本来获得谷歌的可见性。仅将GEO/AEO用作简称标签。

## 交叉引用

这项技能涵盖了FLOW表面3（AI助手引用：ChatGPT、Perplexity、Claude、Gemini、Copilot、You.com）并有助于表面2（SERP加上AI概述）。表面映射：`skills/blog/references/flow-alignment.md`。

对于直接相关的AI引用提示（AI支持页面重写提示、ai检测测试、ChatGPT发现、可见性提示），请参阅`/blog flow optimize`。

## 证据学科

仅在报告包含包含URL、发布者、方法、样本量、引擎或版本、查询类别、检索日期和过期日期的源块时才使用数字AI引用基准。如果任何字段缺失，请将基准标记为方向性或删除数字。默认启发式规则：

- 自包含120-180字的答案段落是实践者的启发式规则。
- 具有语义标题的比较表可能会提高可提取性，但在没有日期源块的情况下不要引用提升。
- AI概述的覆盖范围取决于方法：引用日期范围，而不是固定点。

## 审核流程

### 第1步：阅读内容

从博客文章中提取：
- 完整内容文本和字数
- 标题结构（H1、H2、H3层次结构）
- 单个段落及其字数
- 常见问题解答部分（如果存在）
- Schema标记（JSON-LD、微数据、RDFa）
- robots.txt提及或meta robots指令
- 任何TL;DR或摘要框
- 比较表及其HTML结构
- 编号/有序列表
- 定义式格式

### 第2步：段落级可引用性（4分）

检查标题之间的每个部分是否包含可被AI提取的段落：

| 检查 | 标准 |
|-------|----------|
| 字数 | 每个部分包含120-180字的自包含段落 |
| 上下文独立性 | 每个段落从周围上下文中提取出来也能理解 |
| 声明结构 | 段落包含：具体声明 + 支持证据 + 来源归因 |
| 完整性 | 段落回答问题，不需要读者阅读相邻部分 |

**评分：** 计算满足所有标准的段落数与总部分数的比例。
- 4分：80%以上的部分有可引用的段落
- 3分：60-79%
- 2分：40-59%
- 1分：20-39%
- 0分：低于20%

### 第3步：问答格式（3分）

检查标题格式和答案结构：

| 检查 | 标准 |
|-------|----------|
| 问题标题 | 60-70%的H2是作为问题表述的 |
| 答案优先格式 | 每个H2下的首段提供直接的答案 |
| 常见问题解答部分 | 具有结构化问答对的专用常见问题解答部分 |

**评分：**
- 3分：满足所有三个标准
- 2分：满足两个标准
- 1分：满足一个标准
- 0分：一个标准都不满足

### 第4步：实体清晰度（3分）

检查主题一致性和消歧义：

| 检查 | 标准 |
|-------|----------|
| 原始主题 | 每页一个明确的主要主题 |
| 一致命名 | 在整个页面中使用相同的实体名称（不使用令人困惑的同义词） |
| 引言声明 | 引言段落中有明确的主题声明 |
| 标题-内容匹配 | 标题准确反映内容重点 |

**评分：**
- 3分：满足所有四个标准
- 2分：满足三个标准
- 1分：满足一个或两个标准
- 0分：一个标准都不满足

### 第5步：内容结构以供提取（3分）

检查AI可提取的内容模式：

| 检查 | 标准 |
|-------|----------|
| TL;DR框 | 40-60字的自包含摘要出现在顶部 |
| 比较表 | 具有语义标题的表格（如`<thead>`或清晰的列标签） |
| 有序列表 | 用于流程和分步说明的编号列表 |
| 定义格式 | 使用清晰定义模式的键术语 |
| 引用胶囊 | 每个主要部分中40-60字的确定性声明 |

**评分：**
- 3分：4-5个元素存在
- 2分：3个元素存在
- 1分：1-2个元素存在
- 0分：没有元素存在

### 第6步：AI爬虫可访问性（2分）

检查AI爬虫索引的技术要求：

| 检查 | 标准 |
|-------|----------|
| 静态HTML | 内容以静态HTML渲染，而不是JavaScript |
| Google可见性 | Googlebot的正常可爬取性和可索引性。不需要特殊的GEO/AEO文件或标记来获得Google AI功能 |
| 非Google AI爬虫 | 如果网站希望在非Google答案引擎中可见，请检查robots.txt对GPTBot、ChatGPT-User、ClaudeBot、PerplexityBot和相关记录爬虫的处理 |
| HTML中的Schema | 静态HTML中的Schema标记，而不是JS注入 |
| 页面大小 | 合理的页面大小，在AI爬虫限制内 |

**评分：**
- 2分：Google可爬取/可索引干净，并且选定的非Google爬虫策略与网站声明的目标一致
- 1分：Google可索引，但一个选定的非Google爬虫或渲染检查需要审查
- 0分：Google爬取/索引被阻止或多个选定的爬虫被无意中阻止

### 第7步：平台特定分析

评估文章针对每个AI平台的引用偏好：

#### ChatGPT
- 偏好“最佳X”列表（43.8%的引用）
- 偏好引用良好、权威的内容
- 新鲜度很重要：最近更新的优先
- 域名权威性影响引用可能性

#### Perplexity
- 通常偏好新鲜、来源密集、社区验证的内容。在声称引用窗口之前，请使用当前日志或工具进行验证。

#### Google AI概述
- 遵循谷歌正常的SEO指导：使内容有帮助、可爬取、可索引，并符合片段资格。不需要特殊的GEO/AEO标记或llms.txt来获得Google可见性。
- 偏好已经有机排名良好的内容，但请使用日期源块验证任何数字声明。

#### Google AI模式
- 在报告中将其与AI概述分开处理。强调正常搜索资格、清晰页面目的、可访问文本以及可见内容与结构化数据之间的一致性。

#### Claude、Gemini、Copilot和You.com
- 评估内容清晰度、来源可访问性、新鲜度，以及文档中记录的爬虫是否有意允许或阻止。
- 仅在当前文档、日志或测试结果可用时使用引擎特定建议。

对于每个平台，提供：
- 当前可引用评分（高 / 中 / 低）
- 提高引用可能性的具体改进建议
- 内容格式建议

### 第8步：生成引用胶囊

对于文章中的每个H2部分，编写一个引用胶囊：

- **长度**：40-60字，自包含
- **结构**：具体声明 + 数据点 + 来源归因
- **目的**：AI可以直接引用的段落
- **格式**：作为作者可以嵌入的建议添加

示例：
```
根据[来源]，[具体声明带数字]。这代表[背景/比较]，使其[重要性]。[支持声明
的细节]。
```

为每个H2部分生成一个胶囊。用它所属部分的标题进行标记。

### 第9步：计算AI引用准备度评分（0-100）

将15分子类别分数映射到0-100显示分数：

| 类别 | 原始分数 | 显示权重 | 最大显示分数 |
|----------|-----------|----------------|-------------------|
| 段落级可引用性 | /4 | x6.75 | 27 |
| 问答格式 | /3 | x6.67 | 20 |
| 实体清晰度 | /3 | x6.67 | 20 |
| 内容结构 | /3 | x6.67 | 20 |
| AI爬虫可访问性 | /2 | x6.5 | 13 |
| **总计** | **/15** | | **100** |

评分阈值：
- 90-100：优秀：高度可被AI系统引用
- 70-89：良好：可引用，只需轻微改进
- 50-69：需要改进：可引用性存在重大差距
- 低于50：差：需要重大结构调整

### 可选：搜索性能上下文（blog-google）

如果blog-google凭证包含Tier 1（GSC）并且文章有已发布的URL：

1. 通过页面和查询维度查询GSC，然后过滤行到URL：
   `python3 skills/blog-google/scripts/run.py gsc_query --property <property> --dimensions query,page --json`
2. 添加到平台特定分析：
   - 当前印象、点击率、平均位置
   - 驱动流量到此URL的搜索查询
3. 检查索引：`python3 skills/blog-google/scripts/run.py gsc_inspect <url> --json`
4. 报告索引状态、规范选择、移动可用性。
5. 如果跳过，报告`SKIPPED: 凭证不可用`或
   `SKIPPED: 未发布URL`。

### 可选：AI引用概率评分

对于每个引擎，运行以下命令以获取文章被AI答案引擎引用的可能性评分（与`/blog analyze`评分的15分AI引用准备度类别不同）：

```bash
python3 scripts/ai_citation_score.py <文件> --format markdown
```

它返回一个0-100的总体评分，以及Google AI概述、Perplexity和ChatGPT的每个引擎子评分、因素分解，以及最多三个最有影响力的修复。
