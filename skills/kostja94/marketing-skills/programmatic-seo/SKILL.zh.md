# SEO：程序化SEO

指导程序化SEO——使用模板和结构化数据自动创建大量SEO优化的页面，而不是手动编写每个页面。**经典的“邮件合并”式pSEO**（一个刚性模板+替换变量）往往产生**低差异化**和感觉单薄的URL。**在相同的数据骨干上负责任地使用AI**，您可以扩展**每个URL的定制**——意图一致的文案、部分深度、常见问题解答、语气、本地化——同时仍然遵循**证据块**、**数据层级**和**QA**（见下文的**数据强度层级**和**AI辅助生成**）。

**调用时**：在**首次使用**时，如果有帮助，用1-2句话说明此技能涵盖的内容及其重要性，然后提供主要输出。在**后续使用**或当用户要求跳过时，直接进入主要输出。

**项目背景**：当存在时，读取根`contextus.md`并仅加载与此任务相关的模块。没有Contextus，使用可用的项目材料或用户提供的 факты，并请求缺失信息；不要创建并行背景系统。

## 定义

**程序化SEO** = 构建一个模板并使用来自数据库、API或电子表格的数据来生成数百或数千个唯一页面。每个页面都针对一个长尾关键词（例如，“[城市]最佳SEO工具”、“[应用A] + [应用B]集成”）。

**与传统SEO的关键区别**：技术性（SEO + 工程师）；长尾关注；数据驱动（数据质量=成功）；自动化；为规模而构建。

## 经典限制与AI增强差异化

| 时代 | 破坏点 | 帮助点 |
|-----|-------------|------------|
| **刚性pSEO** | 一个模板，最小差异 → 相似的标题/正文，弱的**E-E-A-T**，“明显的邮件合并” | 仍然需要**每个URL的独特证据**和选择性索引 |
| **AI增强pSEO** | 相同的**结构化行**（事实、SKU、指标）驱动页面，但模型添加**每个URL的叙事**：引言、FAQ深度、角色角度、本地化、内部链接建议——**规模化差异化** | **事实保留在您的数据层**；AI塑造**措辞和结构**，而不是编造数字——见**AI辅助生成** |

**最佳实践立场**：AI是一个**加速器和定制器**，而不是**数据防御性**（层级1-5）或**技术SEO**（URL、模式、CWV）的替代品。用得好，它符合**质量胜于数量**：较少的瘦URL，更多**独特**有用的页面。

## 三部分框架

| 组件 | 角色 |
|-----------|------|
| **模板** | 可重用的页面结构：布局、标题、内部链接、内容块；空字段的条件逻辑 |
| **数据** | 结构化信息：位置、产品、价格、功能——必须准确、完整并具有真实价值 |
| **自动化** | 连接数据到模板的系统；动态生成页面或批量发布页面 |
| **AI层（可选）** | 在**有根据的输入**（行JSON + 规则）上，生成**多样化的文案**、FAQ扩展和部分强调**每个URL**——减少“相同模板”疲劳，同时保持可审计性 |

## 模板结构（推荐）

| 部分 | 目的 |
|---------|---------|
| **引言** | 介绍；匹配用户意图 |
| **证据块** | 数据驱动内容，每个页面独特（表格、列表、验证统计数据）；区别于瘦内容 |
| **决策** | 比较、推荐或下一步 |
| **FAQ** | 常见问题 |
| **CTA** | 行动号召 |

**证据块** = 每个页面的真实、结构化数据（商业列表、价格、评论、验证统计数据）。确保每个页面提供真实价值，而不是带有替换变量的循环样板。

## 数据强度层级（防御性）

**最强的程序化页面由只有您的产品（或您的产品中的客户）可以产生的内容驱动**——尤其是**模板、导出和生成工件**。第三方或抓取列表单独是基础最弱的。

| 层级 | 来源 | 示例 | 相对风险 |
|------|--------|----------|----------------|
| **1 — 产品生成** | 您的产品创建或渲染的资产：页面/布局**模板**、电子邮件/Notion/代码模板、导出包、生成预览、品牌片段、“使用[产品]构建”示例 | 模板库行链接到真实的`.json` / CMS字段；导出截图；独特的预览URL | **最低**当每个URL显示不同的生成输出时 |
| **2 — 产品衍生** | 您拥有的遥测和产品内数据：聚合、群体、基准、功能采用 | “[行业]中团队中值时间到价值”来自您的仓库（聚合） | 低如果聚合/匿名化并符合政策 |
| **3 — UGC/客户** | 评论、提交、展示项、审核社区内容 | 展示网格；验证引言 | 中等——需要审核+同意 |
| **4 — 许可/合作伙伴** | 独家源、联合营销数据集 | 合作伙伴价格层级；许可行业统计数据 | 中等——合同和引用纪律 |
| **5 — 公共/抓取** | 开放式网络、目录、通用丰富 | 名称/地址填充；商品事实 | **最高**——需要编辑层、事实核查和真实的**证据块** |

**为什么Tier 1（模板和生成内容）胜出**：从**您的**模板系统构建的页面携带专有结构、变量和品牌安全块——更难逐字复制，更容易证明独特性（嵌入、下载、ID）。配合**template-page-generator**使用时，UX是“浏览画廊→使用模板”。

### Tier 2 — 产品衍生（实用）

| 它是什么 | 注意事项 |
|------------|----------------|
| 来自**您的**后端、数据仓库或支持/CRM导出的指标：按群体激活率、集成流行度、错误预算、时间到价值——不是通用的“行业报告”。 | **隐私&ToS**：最小单元格大小；无个人识别；记录聚合了什么以及窗口期。 |
| 当您可以展示**“只有我们才能知道这一点，因为它运行在我们的产品中”**时，这是合适的。 | **过时数据**损害信任：管道作业，“截至[日期]”标签，自动无效化。 |

**AI在此处**：使用模型将结构化聚合转换为散文（引言段落，“对[群体]意味着什么”）——**输入必须是来自您的管道的验证数字/表格**，而不是自由形式的发明。保留页面上的**机器可读表格或JSON**，以便声明保持可审计。

### Tier 3 — UGC/客户（实用）

| 它是什么 | 注意事项 |
|------------|----------------|
| 引言、评论、展示提交、社区模板——**每个用户生成的工件**，有同意。 | **审核**：垃圾邮件、PII、竞争对手攻击；**同意**使用名称/徽标；**模式**（评论、CreativeWork）仅当准确时。 |
| 当与**Tier 1**结合时强大（例如，“客户构建的模板”画廊）。 | **没有质量的量**→瘦页面；限制或评分提交。 |

**AI在此处**：总结长评论为要点；**生成草稿替代文本**用于图像；**聚类**提交到主题页面——始终**人工批准**后再发布。不要编造客户评价。

### Tier 4 — 许可/合作伙伴（实用）

| 它是什么 | 注意事项 |
|------------|----------------|
| 合作伙伴价格列表、联合营销报告、API驱动的**允许**字段（徽标、SKU）。 | **合同范围**：哪些字段可以出现在哪些URL上；归属行；**DMCA/商标**在徽标上。 |
| 通常**一个源→多个URL**；独特性必须来自**您的框架**、比较逻辑或计算器——而不是原始源。 | **刷新频率**与合作伙伴SLA挂钩。 |

**AI在此处**：起草**比较文案**和**FAQ**来自**固定属性表**（许可+合作伙伴规则）；从不编造SKU或价格——**从源拉取**，让AI措辞和缩短。

### Tier 5 — 公共/抓取（实用）

| 它是什么 | 注意事项 |
|------------|----------------|
| 开放数据、目录、维基百科式事实、**丰富**公共实体。 | **最高**重复/瘦风险：每个人都拥有相同的事实；**您必须添加**综合、编辑角度或**独特工具**（计算器、过滤器）在上面。 |
| **实体SEO**和**引用**很重要：链接到权威来源；日期戳易变事实。 | 计划**修剪**或**noindex**在低流量瘦URL上。 |

**AI在此处**：使用模型将混乱的公共文本结构化为表格、**概述**部分、**建议**内部链接——然后**事实核查**名称、数字和日期。**不要**使用AI编造统计数据或引用；将输出视为**草稿**，直到验证。

### AI辅助生成（跨层级）

**为什么AI适合现代pSEO**：早期的程序化SEO赢得了坏名声，因为**模板被冻结**，**文案是可互换的**——每个查询的真实差异化很少。**LLM**，当**基于每行的事实和您的品牌规则**时，使**按URL定制**标题、引言、FAQ和“为什么这个页面很重要”**成为可能**，而无需手写数千个页面。这使执行更接近**最佳实践**（意图匹配、有用内容、独特价值）**规模化**，前提是您**不**让模型编造数据。

| 原则 | 原因 |
|-----------|-----|
| **将AI基于结构化输入** | 将JSON/CSV行（层级、源URL、指标）输入提示；**禁止**系统提示中的幻觉数字。 |
| **分离“事实”与“措辞”** | 数据层=事实来源；AI=语气、缩短、本地化、FAQ、**按群体强调**——反之则非。 |
| **变化结构，而不仅是形容词** | 请求不同的**部分顺序**、FAQ数量，或“初学者与高级用户”角度**按意图标志**在行中——减少模板相同性。 |
| **人工或自动化QA** | 检查高流量URL；如果必需字段为空或引用缺失，则阻止发布。 |
| **在有用时披露** | 例如，“引言由AI生成；数字来自[内部报告，2025年第三季度]。” 建立信任并匹配政策趋势。 |

**当AI生成是一个强杠杆时**：层级2-5——其中原始材料已经是表格或重复的，但**需要可读、差异化文案**规模化。层级1仍然受益于AI（从导出JSON生成草稿），但**差异化仍然**是产品工件本身。

### 运营要求（所有层级）

| 要求 | 实践 |
|-------------|----------|
| **来源** | 记录数据来源；按字段跟踪来源 |
| **新鲜度规则** | 例如，评分每90天，价格每30天，布局更改时的模板版本提升 |
| **优先1-2而非5** | 用产品生成或产品衍生数据填充证据，然后再转向公共抓取 |
| **AI治理** | 结构化输入仅；无未经验证的数字；审核UGC；可选披露 |
| **清洁和合并** | 去重键；删除产生重复意图的行 |

| 要求 | 目的 |
|-------------|---------|
| **每页300+字** | 避免内容质量惩罚 |

## 技术注意事项

| 主题 | 实践 |
|-------|----------|
| **子文件夹 vs 子域名** | 优先使用**子文件夹** (`yoursite.com/integration/slack-notion/`) 而不是**子域名** (`integrations.yoursite.com/...`)，以便权威集中在主域名上；查看**URL结构**、**域名架构**如果重构 |
| **选择性索引** | 不要索引所有页面；使用noindex规则对低价值页面进行管理 |
| **站点地图分段** | 按国家、语言、部门分段；管理爬行预算 |
| **URL结构** | 描述性URL；清晰的层次结构；查看**URL结构** |
| **模式** | JSON-LD：每页类型的产品、地点、常见问题解答、项目列表 |
| **性能** | 缓存、静态生成；核心网络指标 |

## 严重错误

| 错误 | 后果 |
|---------|-------|
| **内容质量低** | 超过关键词的最小信息；通用文本；占位符章节 → 惩罚 |
| **重复页面** | 相同内容仅数据交换 → 内容质量低惩罚 |
| **索引膨胀** | 生成永远不应索引的页面 → 爬行预算浪费 |
| **大量发布** | 一次性发布许多相似页面 → 垃圾信号 |
| **过滤器URL** | 使用过滤器而不是唯一的URL/标题 → 争夺排名 |

仅包含标题、一段文字和交换城市名称的页面不会排名，并可能受到Google的惩罚。

## 修复已构建的同类化页面

如果程序化页面已经发布并且感觉可以互换——共享的结尾句子、跨URL的相同价值主张、克隆的章节结尾——在触发质量信号之前修复内容。

### 诊断方法

在渲染或源文件中运行正则表达式扫描，以暴露共享的句子尾部和重复的段落结构。查找在30%以上的同类页面中出现的模式。常见的迹象：每个工具页面都以"X是Y的理想选择"结尾，每个分类页面都共享相同的技术摘要，每个位置页面都使用相同的常见问题解答尾部。

在三个范围内扫描：在单个页面内（它的章节是否重复相同的结尾公式？），在同类中（所有视频工具页面是否共享模板？），跨类别（每个页面是否都有相同的价值声明？）。

### 将修复分为三个优先级

| 优先级 | 是什么 | 操作 |
|----------|------------|--------|
| **P0 — 消除** | 纯模板填充，没有信息价值；每个页面都说同样的事情 | 独立重写每个页面，添加页面特定细节 |
| **P1 — 重写** | 核心信息正确但交付公式化（例如，“不同的工具使用不同的架构”——正确但通用） | 准备8-15个语义变体，循环使用，使相邻页面不同 |
| **P2 — 降低密度** | 正常词汇出现过于频繁（例如，80%的页面出现“无缝”） | 替换~30-40%的实例，而不是全部——正常词汇在中等频率下是正常的 |

### 分阶段执行

首先修复P0模式，一次一个类别。每次修复后，重新扫描以确认模式已清除且未出现新模式。一个常见的陷阱：用相同的修复统一应用一个模板来替换另一个模板。分阶段重写，按顺序处理的页面应获得不同的处理。

对于单页面内部重复——其中所有用例或工具描述在单个文件中共享相同的结尾句子——使用功能性的结尾而不是评估性的结尾。功能性结尾描述了实际解决瓶颈的内容；评估性结尾只是声明它是好的选择。

### 管道中的预防措施

在AI生成提示中添加结构多样性要求（变化章节结尾，禁止重复的结尾公式）。从不同类别批量生成页面，而不是一次一个类别。在发布前跨同类页面运行N-gram重叠检查。

## 分步工作流程

1. **研究** — 领域、意图；包含低流量关键词；SEO工具、问题数据库
2. **收集数据** — 出身记录、新鲜度规则；第一方/许可；定义模板字段
3. **选择堆栈** — Next.js + DB、Webflow CMS、WordPress、无头；API + 模板重用
4. **设计模板** — 简介、证据、决策、常见问题解答、CTA；模式；条件逻辑
5. **构建数据库** — 将字段映射到模板插槽；隐藏空值
6. **生成页面** — 描述性URL；优化性能
7. **部署和监控** — 站点地图；索引、排名、CTR、跳出率、转化
8. **优化** — 删除薄弱页面；刷新数据；A/B测试布局、CTA

## 最佳实践

| 实践 | 目的 |
|----------|---------|
| **质量胜过规模** | 每个页面必须提供真正独特、可验证的价值 |
| **差异化胜过克隆** | 优先使用**AI驱动**的复制变体+证据块，而不是一个静态段落与`{城市}`交换 |
| **分批发布** | 小批量的，你可以衡量；避免大量发布 |
| **强大的IA** | 内部链接到相关指南/分类 |
| **视觉元素** | 在相关的地方使用表格、地图、比较 |
| **匹配意图** | 避免通用模板文本；精确的用户意图 |
