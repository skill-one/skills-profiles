# 策略：转化率优化

提供转化率优化（CRO）指南：提高完成预期操作的访客比例。更高的转化率意味着增加收入、降低CAC（客户获取成本）和更好的ROI（投资回报率）。在优化漏斗、运行实验或减少高流量页面的摩擦时使用此技能。

**调用时机**：在**首次使用**时，如果有帮助，先用1-2句话说明此技能涵盖的内容及其重要性，然后提供主要输出。在**后续使用**时或当用户要求跳过时，直接进入主要输出。

## 初步评估

**项目背景**：当存在根`contextus.md`时，读取并仅加载与此任务相关的模块。没有Contextus时，使用可用的项目材料或用户提供的 факты（事实），并请求缺失信息；不要创建一个平行的背景系统。

识别：
1. **漏斗阶段**：认知、考虑、决策、购后
2. **转化目标**：注册、购买、下载、演示请求
3. **流量**：数量；移动端与桌面端的分割
4. **当前转化率**：改进的基线

## CRO流程

| 步骤 | 操作 |
|------|--------|
| **1. 研究** | 绘制漏斗；识别高流量、低转化率的页面 |
| **2. 假设** | 提出可测试的假设（如果X，那么Y因为Z） |
| **3. 优先级排序** | 按潜力、重要性、易行性（PIE）评分 |
| **4. 测试** | A/B测试或多变量测试；足够的样本量 |
| **5. 分析** | 统计显著性；实施获胜者 |

## PIE优先级排序框架

对每个测试想法评分1-10：

| 因素 | 问题 |
|--------|----------|
| **潜力** | 可能的改进程度如何？ |
| **重要性** | 该页面流量多大？ |
| **易行性** | 实施有多容易？ |

按总分数对积压任务进行排序；首先运行影响最大的测试。

## A/B测试最佳实践

| 实践 | 指导方针 |
|----------|-----------|
| **样本量** | 在发布前计算最小值；没有足够样本的95%显著性 = 假阳性 |
| **持续时间** | 运行完整的周循环；考虑星期几的影响 |
| **单一变量** | 每个实验测试一个元素（或使用MVT进行多个） |
| **移动端独立** | 移动端转化率约为桌面端的50%；独立测试移动端——拇指触及范围、表单复杂度不同 |
| **低流量** | 使用贝叶斯测试以获得更快、可操作的结果 |

## 关键测试领域

| 页面类型 | 测试想法 |
|-----------|------------|
| **首页** | 搜索栏突出度；个性化内容；英雄CTA；社会证明位置 |
| **着陆页** | 标题；表单长度；CTA文案；首屏布局 |
| **产品/分类** | 快速查看；描述；加入购物车位置 |
| **结账** | 表单字段；进度指示器；信任徽章；游客结账 |
| **定价** | 计划顺序；锚定；每个层级CTA |

**个性化**：个性化体验比通用体验产生约41%更大的影响。

## 商业化基础设施

| 模块 | 目的 |
|--------|---------|
| **数据与BI** | 数据仓库；用户行为事件；敏捷调查 |
| **A/B测试** | 实验平台；统计显著性；后端控制的变体 |
| **用户教育** | 帮助文档（多语言）；更新通知；EDM（电子邮件营销） |
| **归因** | 广告像素；归因模型；曝光到点击到销售的跟踪 |

**避免**：侵入式插屏广告；遮挡内容的弹窗。优先考虑非侵入式广告格式。

## 基础要求

- **分析**：绘制漏斗；识别流失点（分析追踪、流量分析）
- **定性**：热力图、会话录制、用户测试——了解流失发生的原因
- **技术**：为每月2-4个测试分配专用资源；保持势头

## 输出格式

- **漏斗图**（阶段、转化率、流失）
- **假设**（如果X，那么Y因为Z）
- **测试计划**（变体、指标、样本量、持续时间）
- **实施**清单
