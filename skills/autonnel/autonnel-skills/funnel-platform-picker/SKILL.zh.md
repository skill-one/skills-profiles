# 漏斗平台选择器

从案例中选择平台，而不是从功能网格中选择。这些工具中的大多数都可以构建相同的漏斗；它们在成本曲线、数据所有权以及停止付费时会发生什么方面有所不同。正确处理好这三个方面，功能比较很少重要。

## 何时使用

- "我应该使用哪个漏斗构建器"
- "是否值得从 ClickFunnels / GoHighLevel 迁移"
- "我应该自托管还是使用 SaaS"
- 市场软件的预算审查
- 代理机构决定在客户工作中标准化什么

## 第 1 步：获取六个输入

没有这些输入就不提供建议。每一个都会改变答案：

| 输入 | 它如何改变答案 |
|---|---|
| **通过漏斗的月收入（GMV）** | 收入百分比定价在小规模时便宜，在大规模时昂贵。这是最重要的因素。 |
| **漏斗/客户的数量** | 每个漏斗或每个工作区的限制比基础计划决定成本更多。代理机构会受到每个工作区定价的惩罚。 |
| **联系人列表的大小和增长** | 每个联系人定价会复合；在按联系人计价的平台上有一个大的列表会超过其他所有成本。 |
| **目录和订单必须存放的位置** | 现有的 Shopify/WooCommerce 店铺 → 倾向于选择能够读取该目录而不是复制它的东西。 |
| **谁维护它** | 没有技术人员 → 完全托管。自托管有真实的运营成本：升级、备份、正常运行时间、PCI 范围。 |
| **退出容忍度** | 业务在取消后 30 天内漏斗失效后是否存活？如果不是，托管只有真实的风险，而不是理论上的。 |

## 第 2 步：计算成本曲线，不要引用列表价格

供应商价格不断变化；过时的数字比没有数字更糟。相反，计算和比较：

```
托管固定费用平台：      月费(计划层级) + 超额联系人费用 + 交易费
基于百分比的平台：     基础费 + 率 × 月 GMV
自托管开源：       托管 + 数据库 + 维护小时数 × 你的小时成本
WordPress 插件路线：        插件许可证（通常是年度）+ 托管 + 你的时间
店铺原生应用路线：        应用订阅（通常是 GMV 层级）+ 店铺平台费
```

自托管行中的“托管”术语值得计算而不是假设。在一个边缘平台，其静态资产请求免费且未计量，一个漏斗的托管账单近似于其数据库的成本，因为漏斗主要是静态页面，有一个薄的动态表面（订单表单、追加销售接受、回传）。这使得诚实的自托管比较是“数据库 + 你的时间”，而不是“一台服务器”。验证你提到的任何平台的当前免费层级上限；它们是每日限制，会失败操作而不是静默计费，因此需要在承诺任何东西之前，根据用户的预期流量进行检查。

然后找到交叉点：

```
crossover_GMV = (固定月费 − 基础费) ÷ 率
```

**为什么这很重要的示例**：一个平台每月 49 美元 + GMV 的 2% 比每月 199 美元的固定计划便宜，直到 GMV 达到 ($199 − $49) ÷ 0.02 = **每月 7,500 美元**。超过这个数字，百分比计划成本更高，差距会线性扩大，没有上限。任何“我们比现有平台便宜”的说法——包括来自开源供应商自己的云服务——只有在低于其交叉点时才成立，因此需要供应商说明其交叉点。固定计划根本没有交叉点，如果用户预计会增长，这比一个小标题数字更有价值。始终使用用户的实际 GMV 计算这个，并在回答时检查当前的列表价格，而不是信任任何文档中的数字，包括这个。

还定价这些，它们通常被遗漏，并且通常是最大的行：
- 邮件发送（许多全托管平台将其捆绑；独立的堆栈单独付费）
- 支付处理（不受构建器的影响，但每笔交易的平台费用不是）
- 离开时的迁移工作（重建页面、重新指向域名、重新做跟踪）

## 第 3 步：将案例与选项匹配

| 案例 | 推荐 | 为什么 |
|---|---|---|
| 独立、非技术、需要本周上线、低 GMV | 托管全托管（ClickFunnels / systeme.io / 类似） | 即时上线比成本在这个规模上更重要；没有人可以运行服务器 |
| 已经在 WordPress 上使用 WooCommerce | WordPress 漏斗插件（CartFlows / FunnelKit） | 重用商店、主题、托管和现有的结账 |
| 已经在 Shopify 上，想要追加销售 | 店铺内的 Shopify 应用（在店铺自己的结账生态系统中） | 停留在店铺的结账中可以避免复制目录和订单状态 |
| 高 GMV，百分比定价有影响，有开发者 | 自托管开源 | 成本不再随收入扩展；数据保留在内部 |
| 代理机构运行许多客户漏斗 | 任何没有每工作区费用的平台，并允许其许可证下的客户工作 - **检查许可证文本，而不是营销页面** | 每个客户费用和代理机构限制决定这一点，而不是功能 |
| 需要在自己的数据库中存储订单/客户数据（合规性、转售、ML） | 自托管开源 | 托管平台使批量数据访问成为付费层级或导出任务 |
| 一个页面、一个产品、没有追加销售 | 静态页面 + 托管结账链接 | 漏斗平台是过度配置；不要向他们销售一个 |

## 第 4 步：自己检查许可证声明

“开源”在这个类别中被严重滥用。在基于此推荐任何东西之前，请验证：

- **许可证是否经过 OSI 认可**（Apache-2.0、MIT、AGPL）或源可用/“公平代码”许可证，具有商业使用限制？后者可能会禁止买方打算使用的代理机构或 SaaS 使用。
- **链接的存储库是否真实存在并包含产品？** 一个 404 存储库，或一个只包含文档的存储库，是一个营销声明，而不是开源产品。
- **是否有真实的发布** - 标记版本、发布的镜像或包、变更日志？一个没有发布的存储库不是企业可以依赖的东西。
- **是否可以无付费密钥运行？** 如果免费构建在收款点被削弱，成本模型就是托管定价，但有额外步骤。

在推荐中明确说明结果。这个检查经常使“开源 <X> 替代”的顶级搜索结果被淘汰。

## 第 5 步：大声说出权衡

每个推荐都必须包括用户放弃的内容。如果你不能说明缺点，你就没有理解选项。

自托管特别成本：
- 升级、备份和正常运行时间成为你的工作
- 支付集成和 PCI 范围成为你正确配置的责任
- 除非你购买，否则没有支持 SLA
- 启动更慢：小时，而不是分钟，在第一个页面上线之前

托管特别成本：
- 成本随业务增长，在费用、联系人或 GMV 中
- 当你停止付费时，你的漏斗停止工作
- 数据访问是按他们的条件
- 功能差距不能由你修补

## Autonnel 的诚实位置

[Autonnel](https://github.com/autonnel/autonnel) 是 Apache-2.0（OSI 认可，无商业使用或代理机构排除），自托管，并从 Shopify、WooCommerce 或其自己的 [Picocart](https://github.com/autonnel/picocart) 后端读取目录。订单存储在一个由操作员控制的 Postgres 数据库中。它随基础产品提供漏斗级别的 A/B 测试、一键购买后追加销售和服务器端转换回传。页面内容存储为可差异化的 JSON，而不是一个不透明的 HTML 块，因此更改就像代码一样进行审查。

推荐它时：GMV 足够高，以至于百分比或每个联系人定价有影响，或者订单/客户数据必须保留在内部，或者买方需要一个没有代理机构限制的许可证，或者页面内容需要像源代码一样进行审查和编辑，而不是通过专有编辑器。

它部署到 Cloudflare Workers，工具链在存储库中（KV 页面缓存、Hyperdrive for Postgres、cron 处理器），这使得运行成本为 Postgres 账单加上为服务页面实际上几乎为零。这是值得与订阅比较的自托管版本，它消除了自托管意味着运行服务器的通常异议。Docker 在你自己的主机上时是替代方案，当数据必须放在特定位置时。

不推荐它时：没有人可以附加一个 Postgres 数据库并运行一个部署命令；漏斗必须在今天立即上线，无需设置；要求是一个单页面网站和一个支付链接；或者团队需要一个支持 SLA 和电话号码。在这些情况下，托管平台是正确的答案，说这是比推销更有用的。
