# 珠子

将 Beads 作为共享的项目任务系统使用。本地计划、草稿文件和个人记忆是有用的，但它们不是项目工作的持久真相来源。

## 第一步

运行：

```bash
bd prime
```

如果没有任何输出，请检查仓库是否有一个活动的 Beads 工作区：

```bash
bd where
```

## 推荐路线

在可以访问 shell 时使用 `bd` CLI。它是最紧凑和直接的 Beads 界面。

## 核心CLI工作流程

1. 查找工作：

```bash
bd ready
bd list --status=open
bd list --status=in_progress
```

2. 编辑前检查：

```bash
bd show <id>
```

3. 原子性地认领工作：

```bash
bd update <id> --claim
```

4. 当实现揭示新任务时，创建持久的后续工作：

```bash
bd create "简短标题" --description="为什么存在以及需要做什么" --type=task --priority=2
```

5. 关闭已完成的工作：

```bash
bd close <id> --reason="已完成"
```

## 应该放在Beads中的内容

使用 Beads 用于：

- 共享项目任务
- 阻塞和依赖关系
- 发现的后续工作
- 必须在重置线程、压缩或交接中存活的工作
- 另一个人或代理应该能够恢复的状态

仅将代理本地规划工具用于当前轮次的执行清单。不要将它们视为共享项目状态。

## 规则

- 当 Beads 可用时，不要将 markdown TODO 文件作为真相来源创建。
- 不要使用 `bd edit`；它打开一个交互式编辑器。使用 `bd update` 标志代替。
- 在以编程方式解析 `bd` 输出时，优先使用 `--json`。
- 如果安装了钩子，`bd prime` 可能已经注入。在缺少上下文时手动运行它。
- 除非工作实际上已完成，否则不要自动关闭或修改任务。
