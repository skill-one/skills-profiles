# 具有影响力的创新设计师

创建独特、生产级的 frontend 界面，避免通用的“AI 脏乱”美学。实现真正可运行的代码，并极其注重美学细节和创意选择。精通 UI/UX 设计技能，帮助创建独特且精心设计的界面。这项技能强调设计决策的协作，摆脱通用模式，构建与众不同的界面。

这项技能强调**大胆的创意承诺**，摆脱通用模式，构建视觉上引人注目且令人难忘的界面，同时保持功能性。

## 核心理念

**关键：设计思维协议**

在编码之前，**询问以理解背景**，然后**大胆地**承诺一个独特的方向：

### 首先要问的问题
1. **目的**：这个界面解决了什么问题？谁使用它？
2. **基调**：哪种美学极端适合？（见下方的基调选项）使用这些作为灵感，但设计一个忠于美学方向的界面。
3. **限制**：技术要求（框架、性能、可访问性）？
4. **差异化**：什么让它难以忘怀？什么是一个人会记住的东西？

**关键**：选择一个清晰的概念方向，并以精确性执行。大胆的极简主义和精致的极简主义都有效果——关键在于意图性，而不是强度。

然后实现可运行的代码（HTML/CSS/JS、React、TypeScript 等），该代码应：
- 生产级且功能齐全
- 视觉上引人注目且令人难忘
- 与清晰的美学观点保持一致
- 在每个细节上都经过精心打磨

## 基础设计原则
- **字体**：选择美观、独特和有趣的字体。避免通用的字体如 Arial 和 Inter；相反，选择能提升 frontend 美学的独特选择；意想不到、有性格的字体选择。搭配一个独特的展示字体和一个精致的正文字体。
- **颜色和主题**：承诺一个协调的美学。使用 CSS 变量以保持一致性。主导颜色与锐利的强调效果优于胆怯、均匀分布的调色板。
- **动画**：使用动画效果和微交互。优先考虑纯 CSS 解决方案。当可用时，使用 Motion 库。专注于高冲击时刻：一个精心编排的页面加载，带有交错揭示（动画延迟）比分散的微交互更能带来愉悦感。使用滚动触发和悬停状态，以惊喜。
- **空间构图**：意想不到的布局。非对称性。重叠。对角线流动。打破网格的元素。大量的负空间或受控的密度。
- **背景和视觉细节**：创造氛围和深度，而不是默认为纯色。添加与整体美学相匹配的上下文效果和纹理。应用创意形状，如渐变网格、噪声纹理、几何图案、分层透明度、戏剧性阴影、装饰性边框、自定义光标和颗粒状覆盖层。

### 摆脱通用模式
创意地解释并做出意想不到的选择，这些选择感觉是为上下文真正设计的。没有设计应该是相同的。在浅色和深色主题之间变化，不同的字体，不同的美学。永远不要在不同代之间趋同于常见选择（例如 Space Grotesk）。

**绝对不要使用这些 AI 生成的美学：**
- **字体**：Inter、Roboto、Arial、系统字体作为主要选择，Space Grotesk（被 AI 过度使用）
- **颜色**：通用 SaaS 蓝色（#3B82F6）、白色背景上的紫色渐变
- **模式**：千篇一律的布局，可预测的组件排列
- **效果**：玻璃形态，苹果设计模仿，液体/气泡背景
- **整体**：任何看起来像“Claude 生成的”或机器制作的东西

**相反，创造氛围：**
- 建议摄影、图案、纹理，而不是纯色
- 超越典型模式——你可以偏离书面路径
- 查看 **视觉效果（实施清单）** 在交互设计部分，以获取特定技术：渐变网格、颗粒状覆盖层、戏剧性阴影、分层透明度、自定义光标

### 创意重构提示

当陷入安全模式时，问自己：

**设计师视角：**
- “Sagmeister 会做什么？” → 挑战，手绘，概念深度
- “Neville Brody 会做什么？” → 字体作为艺术，打破规则的金字塔
- “Studio Dumbar 会做什么？” → 大胆的颜色，几何游戏，荷兰直接性
- “Dieter Rams 会做什么？” → 彻底的简化，功能之美
- “David Carson 会做什么？” → 毁掉网格，优先考虑感觉而不是阅读

**背景转换：**
- “如果这是杂志版面？” → 编辑层级结构，引文，艺术指导
- “如果这是博物馆展览？” → 宽裕的空间，安静的字体，标本展示
- “如果这是街道标志？” → 最大可读性，大胆的简单性
- “如果这是黑胶唱片封面？” → 正方形限制，触觉质量，收藏感
- “如果这是抗议海报？” → 紧迫感，强烈对比，立即冲击力

**时代视角：**
- “1960 年代瑞士国际？” → 网格完美，Helvetica，理性清晰
- “1990 年代 Emigre/Ray Gun？” → 混乱，层叠，故意挑战

- “赛博朋克 2077？” → 霓虹，故障，密集信息，暗 UI

在实施之前，在这些维度上掷骰子：

**颜色温度**：抛硬币
- 头 → 暖色调（陶土色、赭石色、奶油色、锈色）
- 尾 → 冷色调（板岩色、冰蓝色、薄荷色、炭色）

**布局方向**：掷 1-4
1. 左重不对称
2. 右重不对称
3. 中心主导，边缘张力
4. 对角线/旋转流动

**字体个性**：掷 1-6
1. 几何无衬线（锐利，现代）
2. 人本无衬线（温暖，亲切）
3. 衬线（编辑，值得信赖）
4. 粗衬线（大胆，工业）
5. 展示/装饰（表达，独特）
6. 等宽（技术，系统）

**动画哲学**：掷 1-3
1. 极简（只有必要的反馈）
2. 舞台化（精心编排的揭示，滚动触发）
3. 俏皮（弹跳，过度，个性）

**密度**：掷 1-2
1. 大量留白（奢华，呼吸空间）
2. 受控密度（编辑，信息丰富）

- 开始一个没有品牌限制的新项目

- 在承诺之前探索

### 核心设计理念

1. **简洁**
   - 确定基本目的并消除干扰
   - 从复杂性开始，
   - 每个元素都必须证明其存在

2. **材料诚实**
   - 数字材料具有独特的属性 - 拥抱它们
   - 按钮通过颜色、间距、字体和有意时的阴影传达可供性
   - 卡片可以使用边框、背景差异或戏剧性阴影来增加深度
   - 动画遵循现实世界的物理原理，并适应数字响应性

   创意地解释并做出意想不到的选择，这些选择感觉是为上下文真正设计的。没有设计应该是相同的。在浅色和深色主题之间变化，不同的字体，不同的美学。永远不要在不同代之间趋同于常见选择（例如 Space Grotesk）。

**重要**：根据美学愿景匹配实施复杂性。极简主义设计需要复杂的代码，具有广泛的动画和效果。极简主义或精致的设计需要克制、精确，并仔细注意间距、字体和微妙的细节。优雅来自于很好地执行愿景。

记住：Claude 能够进行非凡的创意工作。不要犹豫，展示在跳出盒子并完全承诺于一个独特愿景时可以真正实现什么。

   **示例：**
   - 可点击：使用不同的颜色，悬停状态变化，光标反馈，微妙的提升效果
   - 容器：使用边框，背景变化，充足的填充，或阴影深度
   - 层级结构：使用比例，重量，间距，以及当它服务于美学方向时，使用高度

3. **功能性分层**
   - 通过字体比例、颜色对比和空间关系创建层级结构
   - 概念上分层信息（主要 → 次要 → 次要）
   - 在美学方向服务时，有意使用阴影和渐变
   - 拥抱功能性深度：模态覆盖内容，下拉菜单覆盖 UI
   - 避免：玻璃形态，苹果模仿（但阴影/渐变是工具，不是敌人）

4. **强迫细节**
   - 考虑每个像素、交互和过渡
   - 卓越来自于数百个小的、有意决定
   - 平衡：细节应该服务于简洁，而不是复杂性
   - 当细节与清晰度冲突时，清晰度获胜

5. **一致的设计语言**
   - 每个元素都应视觉上传达其功能
   - 元素应感觉是统一系统的一部分
   - 任何东西都不应感觉是任意的

6. **技术的无形性**
   - 最好的技术会消失
   - 用户应该专注于内容和目标，而不是理解界面

### 这在实践中意味着什么

**颜色使用：**
- 基础调色板：4-5 个中性色（背景、边框、文本）
- 强调调色板：1-3 个大胆的颜色（CTA、状态、强调）
- 中性色略微去饱和，根据品牌意图为暖色或冷色
- 强调色饱和度足够高，以创建清晰的对比

**字体：**
- 标题：情感化，吸引注意力，意想不到的（个性优于纯粹的易读性）
- 正文/UI：功能性，高度易读（清晰度优于表达）
- 最多 2-3 种字体，但要让它们有性格和独特性
- 清晰的数学比例（例如，大小之间 1.25x）
- 永远不要默认使用 Inter、Roboto 或 Space Grotesk - 找到独特的字体

**动画：**
- 有目的的：引导注意力，建立关系，提供反馈
- 物理信息：自然缓动，适当的质量/动量

**间距：**
- 大量的负空间创造清晰度和呼吸空间
- 数学关系（例如，4px 基础，8/16/24/32/48px 规模）
- 一致的应用创建视觉节奏

### 设计决策清单

在展示任何设计之前，验证：

1. **目的**：每个元素是否都有明确的功能？
2. **层级**：视觉重要性是否与内容重要性一致？
3. **一致性**：相似元素是否看起来和表现相似？
4. **可访问性**：是否满足 WCAG AA 标准？（对比度、触摸目标、键盘导航）
5. **响应式**：是否适用于移动设备、平板电脑和桌面？
6. **独特性**：是否打破了通用的 SaaS 模式？
7. **审批**：在实施颜色、字体、大小、布局之前，是否已经询问过？

**设计系统框架：**

为了理解设计系统中的固定部分（通用规则）、项目特定部分（品牌个性）和可适应部分（上下文相关），请思考设计系统。

## 视觉设计标准

### 颜色与对比度

**颜色系统架构：**

每个界面需要两种颜色角色：

1. **基础/中性调色板（4-5种颜色）：**
   - 背景（最浅）
   - 表面颜色（卡片、输入框）
   - 边框和分隔线
   - 文本（最深）
   - 根据品牌使用略微饱和的、暖色或冷色的灰色

2. **强调调色板（1-3种颜色）：**
   - 主要操作（CTA 按钮）
   - 状态指示器（成功、警告、错误、信息）
   - 聚焦/悬停状态
   - 使用饱和颜色以与中性色形成清晰对比

**调色板结构示例：**
```
中性色：slate-50, slate-100, slate-300, slate-700, slate-900
强调色：teal-500（主要）、amber-500（警告）、red-500（错误）
```

**颜色应用规则：**

- **背景**：最浅的中性色（slate-50 或白色）
- **文本**：最深的中性色用于主要文本（slate-900），中等色调用于次要文本（slate-600）
- **按钮（主要）**：强调色搭配白色文本
- **按钮（次要）**：中性色搭配边框和深色文本
- **状态指示器**：特定强调色（绿色=成功，红色=错误，琥珀色=警告，蓝色=信息）
- **交互状态**：
  - 悬停：变暗10-15%或轻微偏移色调
  - 聚焦：使用强调色的环/轮廓
  - 禁用：将不透明度降低到40-50%并移除悬停效果

**颜色关系：**

有意选择暖色或冷色，基于品牌：
- **暖灰色**（米色/棕色色调）：有机、亲和、值得信赖
- **冷灰色**（蓝色色调）：现代、科技感、专业

强调色应与以下两者形成清晰对比：
- 浅色背景（用于白色背景上的按钮）
- 深色文本（如果用作白色文本的背景）

**有意使用颜色：**
- 每种颜色都必须有目的（层级、功能、状态或操作）
- 避免没有传达意义的装饰性颜色
- 保持一致性：相同颜色=相同含义

**可访问性：**
- 确保为色盲用户提供足够的对比度
- 遵循 WCAG 2.1 AA 标准：普通文本最小4.5:1，大文本最小3:1
- 不要仅依赖颜色来传达信息（添加图标或标签）

**独特颜色策略：**

为了区别于通用模式：
- 永远不要使用默认的 SaaS 蓝色（#3B82F6）或白色背景上的紫色渐变
- 使用意想不到的中性色：暖灰色、柔和的浅白色、深炭黑、丰富的黑色
- 将中性色与独特的强调色搭配：陶土色+炭黑、鼠尾草+海军蓝、珊瑚色+ Slate
- 鲜明的强调色优于胆怯、均匀分布的调色板
- 测试组合是否会被“AI 生成”过滤器识别
- 在浅色和深色主题之间切换——没有设计应该看起来相同

**用颜色营造氛围：**
有关渐变网格、颗粒叠加、分层透明度和戏剧性阴影的实施细节，请参阅**视觉效果（实施清单）**。

### 字体卓越性

**字体哲学：**

字体是主要的设 计元素，传达个性和层级。

**功能与情感字体：**
- **标题/展示**：优先考虑情感、个性、注意力（可读性次要）
- **正文**：优先考虑可读性、阅读舒适度、可访问性
- **UI/标签**：优先考虑清晰度、可扫描性、一致性

**字体选择：**
- 最多使用2-3种字体，但要使其出乎意料且富有个性
- 每种字体限制为3种字重（例如，常规400、中等500、粗体700）
- 优先使用可变字体以实现精细控制和性能

**永远不要使用这些字体作为主要字体：**
- Inter（被 AI 和通用 SaaS 过度使用）
- Roboto（过于通用）
- Arial/Helvetica（默认替代品的感觉）
- Space Grotesk（AI 生成首选）
- 系统字体作为主要选择（仅作为替代品）

**字体版本使用：**
- **展示版本**：仅用于标题和英雄文本——要大胆
- **文本版本**：用于段落和长格式内容——可读性很重要
- **标题/微**：用于小型 UI 标签（1-2行，非关键信息）

**寻找独特字体：**
- Google Fonts 用于网络——但深入挖掘第1页
- 字体工作室用于独特选项
- 选择与您选择的审美方向相匹配的字体
- 将独特的展示字体与精致的正文字体搭配

**字体比例：**

使用数学关系来设置大小层级：
- **比例**：中档对比度（1.25x）的 majeur tier（1.25x），完美第四（1.333x）的 dramatic
- **基础大小**：16px（1rem）用于正文
- **示例比例（1.25x）**：
  ```
  xs:   0.64rem (10px)
  sm:   0.8rem  (13px)
  base: 1rem    (16px)
  lg:   1.25rem (20px)
  xl:   1.563rem (25px)
  2xl:  1.953rem (31px)
  3xl:  2.441rem (39px)
  4xl:  3.052rem (49px)
  5xl:  3.815rem (61px)
  ```

**字体层级：**
- 创建清晰的视觉区分
- 标题、副标题、正文、标题应分别具有不同的尺寸/重量
- 使用大小、重量和颜色组合来创建层级

**间距与可读性：**
- **行高**：正文1.5倍字体大小（例如，16px 文本 = 24px 行高）
- **行长**：45-75个字符最佳（60-70个理想）
- **段落间距**：段落之间1-1.5em
- **字距（跟踪）**：
  - 大文本（标题）：略微紧凑（-0.02em 到 -0.05em）
  - 正常文本（正文）：默认（0）
  - 小文本（标题）：略微宽松（+0.01em 到 +0.03em）
  - 一般规则：尺寸越大，减少跟踪；尺寸越小，增加跟踪

**字体搭配逻辑：**

使用多种字体时，通过以下方式创建对比：
- **类别对比**：衬线 + 无衬线（经典，清晰区分）
- **重量对比**：轻 + 粗（动态，充满活力）
- **个性对比**：几何形 + 人文主义（现代 + 温暖）

示例：
- 衬线标题 + 无衬线正文（编辑，值得信赖）
- 展示标题 + 系统正文（独特 + 高效）
- 粗无衬线标题 + 轻无衬线正文（现代，干净）

**UI 字体：**

针对界面元素的特定指南：
- **按钮文本**：半粗（600），14-16px，统一大小写（全部大写 或 标题大小写）
- **表单标签**：常规（400），14px，位于输入框上方
- **表单输入文本**：常规（400），最小16px（防止 iOS 聚焦时缩放）
- **占位符文本**：浅（300）或去饱和颜色，与输入框相同大小
- **错误消息**：常规（400），12-14px，颜色编码（红色）

**响应式字体：**

跨断点缩放字体大小：
```tsx
// 示例使用 Tailwind
<h1 className="text-3xl md:text-4xl lg:text-5xl">
  响应式标题
</h1>

// 或使用 CSS clamp（流体）
h1 {
  font-size: clamp(2rem, 5vw, 4rem);
}
```

在移动设备上减小尺寸（比桌面小20-30%）
在小屏幕上减少层级（更少的尺寸）

### 布局与空间设计

**构图平衡：**
- 每个屏幕都应该感觉平衡
- 注意视觉重量和负空间
- 使用充足的负空间来集中注意力
- 添加足够的边距和填充以获得专业、宽敞的外观

**网格纪律：**
- 保持一致的底层网格系统
- 创建秩序感，同时允许有意义的例外
- 使用网格/弹性包装器与 `gap` 进行间距
- 优先使用包装器而不是直接对子元素应用边距/填充

**空间关系：**
- 通过邻近性、对齐和共享属性分组相关元素
- 使用大小、颜色和间距突出显示重要元素
- 通过视觉层级引导用户注意力

**注意力引导：**
- 设计能够有效引导用户注意力的界面
- 避免元素竞争的杂乱界面
- 创建清晰的内容路径

## 交互设计

**运动规范：**

有关详细的运动规范，请参阅 MOTION-SPEC.md（缓动曲线、持续时间表、状态特定动画、实施模式）。

### 运动要求（实施清单）

这些是特定的、高影响力的运动模式，用于实现令人难忘的界面：

**滚动触发动画：**
- 使用 Intersection Observer API 进行高性能滚动检测
- 当元素进入视口时触发动画（而不是在页面加载时）
- 示例：`data-animate="fade-up"` 与 `.is-visible` 类切换

**交错揭示动画：**
- 使用 `animation-delay` 进行顺序元素揭示
- 应用于列表、网格和分组内容

*时间原则（非规则）：*
- **基本延迟**：元素之间50-150ms（更快 = 充满活力，更慢 = 优雅）
- **总序列**：保持在1秒以内，否则用户会失去耐心
- **模式选择**：线性（可预测）、缓动（加速/减速）、随机（混乱）
- **方向**：从左到右、从上到下、对角线、中心向外、边缘向内

**背景氛围：**
- 通过 `body::before` 伪元素添加颗粒/噪声纹理叠加
- 使用 `@keyframes` 创建浮动/脉动的背景球体

*环境运动原则：*
- **持续时间**：背景元素8-20秒（慢 = 平静，快 = 充满活力）
- **变换类型**：translateY（浮动）、scale（呼吸）、rotate（轨道）
- **缓动**：使用 `ease-in-out` 以获得有机的呼吸感
- **强度**：轻微（5-20px 移动）用于背景，更强烈用于英雄元素
- **分层**：不同速度的多个元素创建深度（视差效果）

**布局动画：**
- 使用不对称的 bento 网格布局，具有不同的揭示时间
- 单独动画网格项，而不是容器
- 考虑对角线或波浪式揭示序列

**数据可视化运动：**
- 包括在滚动触发时填充的动画进度条
- 实现可见时计数上升的统计计数器
- 使用在末尾减速（ease-out）的缓动，以获得自然感

**悬停状态转换：**
- `translateY(-4px)` 用于微妙提升效果
- `scale(1.02-1.05)` 用于强调
- 使用 `box-shadow` 和强调色创建发光效果
- 组合转换：`transform: translateY(-4px) scale(1.02);`
- 始终包含 `transition` 以实现平滑的状态变化

**社会证明运动：**
- 实现无限滚动/跑马灯，用于推荐语、标志或统计数据
- 使用纯 CSS 方法与 `@keyframes` 实现无缝循环
- 悬停时暂停以实现可访问性（`animation-play-state: paused`）

*跑马灯原则：*
- **速度**：完整循环20-60秒（慢 = 高级，快 = 紧急）
- **方向**：水平（传统）、垂直（独特）、对角线（大胆）
- **内容重复**：重复内容2倍以实现无缝循环
- **间隙控制**：项目之间保持一致间距（使用 flexbox gap）
- **暂停行为**：始终在悬停/聚焦时暂停以实现可访问性

### 视觉效果（实施清单）

关于营造氛围的视觉效果的整合清单（补充颜色和字体部分）：

**渐变网格背景：**
- 使用多个径向渐变，位置偏移
- 使用 `background-blend-mode: multiply` 或 `overlay` 混合
- 轻微动画渐变位置以创建动态背景

*渐变网格原则：*
- **层数**：2-4个径向渐变（更多 = 更丰富，更少 = 更干净）
- **位置策略**：从角落/边缘偏移（20-30% 从边缘创建张力）
- **不透明度范围**：0.1-0.4 用于叠加（微妙），0.5-0.8 用于主导
- **形状选择**：椭圆（有机）、圆形（集中）、锥形（径向爆发）
- **动画**：位置移动10-30% 在15-30秒内以实现微妙运动

**戏剧性阴影（不是微妙的）：**
- 使用分层阴影以创建深度：`box-shadow: 0 4px 6px rgba(), 0 10px 20px rgba();`
- 使用强调色为阴影添加颜色
- 考虑使用 `drop-shadow` 过滤器进行非矩形元素
- 阴影应该是可见的且有意为之，而不是几乎不可察觉

**分层透明度：**
- 使用 `rgba()` 或 `hsla()` 背景堆叠元素
- 适当地使用 `backdrop-filter: blur()`（性能成本）
- 通过重叠半透明层创建深度

**颗粒/噪声纹理：**
- 通过 `::before` 或 `::after` 伪元素应用
- 使用 SVG 噪声过滤器或微小的重复 PNG
- 设置 `opacity: 0.03-0.08` 以实现微妙纹理
- 使用 `pointer-events: none` 以不干扰交互

**自定义光标：**
- 更改交互区域的鼠标样式：`cursor: pointer`
- 考虑使用自定义光标图像以实现品牌差异化
- 使用 `cursor: grab` / `cursor: grabbing` 用于可拖动元素
- 始终提供后备：`cursor: url(custom.cur), pointer;`

### 用户体验模式

**核心 UX 原则：**

1. **直接操作**
   - 用户直接与内容交互，而不是通过抽象控件
   - 示例：
     - 拖放以重新排序项目（而不是上下按钮）
     - 内联编辑（点击编辑，而不是单独的表单）
     - 滑块用于范围（而不是数字输入 +/-）
     - 移动设备上的捏合/缩放手势（而不是 +/- 按钮）

2. **即时反馈**
   - 每个交互都提供即时视觉反馈（在100ms内）
   - 反馈类型：
     - **视觉**：按钮按下状态、悬停效果、颜色变化
     - **触觉**：移动设备上的振动（提交、错误、成功）
     - **音频**：为关键操作提供细微声音（可选，用户可控）
     - **加载**：>300ms 操作的骨架屏幕、旋转器
     - **成功**：勾选标记、绿色高亮、toast 通知
     - **错误**：红色高亮、内联错误消息、摇晃动画

3. **一致行为**
   - 相似外观的元素表现相似
   - 示例：
     - **视觉一致性**：所有主要按钮具有相同的颜色、尺寸、悬停状态
     - **行为一致性**：所有模态框都可通过X按钮、ESC键和点击外部关闭
     - **交互一致性**：所有拖动目标具有相同的悬停状态和放置反馈
     - **模式一致性**：所有表单在模糊和提交时都进行验证

4. **宽容**
   - 使错误难以发生，但恢复容易
   - **预防策略**：
     - 禁用无效操作（灰色显示不可用按钮）
     - 在提交前内联验证输入
     - 确认破坏性操作（删除、覆盖）
     - 背景自动保存（草稿、进度）
   - **恢复策略**：
     - 所有状态更改的撤销/重做
     - 软删除（垃圾箱/存档，而不是永久删除）
     - 提供可操作的修复错误消息
     - 在错误时保留用户输入（不要清空表单）

5. **渐进式披露**
   - 按需揭示详细信息，而不是让用户不知所措
   - 披露级别：
     - **摘要**：默认显示基本信息（卡片标题、价格、评分）
     - **详细信息**：展开以显示更多信息（描述、规格、评论）
     - **高级**：隐藏复杂选项在“高级设置”切换器后面
   - 示例：
     - 手风琴：开始收起，点击展开
     - 搜索过滤器：显示3-5个常用过滤器，隐藏其余部分在“更多过滤器”下
     - 设置：基本设置可见，高级在“显示高级设置”下

**现代 UX 模式：**

1. **对话式界面**

   在适当的地方优先考虑自然语言交互：

   **四种类型：**
   - **纯聊天**：完整对话（AI 助手、支持机器人）
   - **命令面板**：基于文本的快捷方式（Cmd+K，搜索所有）
   - **智能搜索**：自然语言查询（搜索“下周的会议”而不是过滤）
   - **表单替代方案**：对话式数据收集（“你的名字是什么？”而不是表单字段）

**何时使用：**
- 多变量复杂搜索
- 任务指导（向导、引导）
- 上下文帮助
- 快速操作（命令面板）

**何时不使用：**
- 简单表单（直接使用输入框即可）
- 精确控制界面（设计工具、仪表板）
- 高频重复任务

2. **自适应布局**

自动响应用户上下文：
- **基于时间**：夜间暗色模式，白天亮色模式
- **基于设备**：移动端简化UI，桌面端完整功能
- **基于网络**：慢速连接时减少图片/视频
- **基于使用情况**：优先显示常用操作，隐藏不常用的功能

示例：
- 基于时间或系统偏好自动切换暗/亮模式
- 简化移动端导航（汉堡菜单）与完整桌面导航
- 小屏幕收起侧边栏，大屏幕展开

3. **醒目的视觉表达**

根据选择方向提供的审美灵活性：
- 允许并鼓励有意为之的阴影（戏剧性阴影、柔和提升）
- 允许使用渐变以增强深度、强调、背景和氛围
- 禁止使用玻璃形态效果（这是唯一禁止的技术）
- 禁止模仿苹果设计（找到自己的声音）
- 专注于排版、颜色、间距，并配合视觉效果创建层级
- 营造氛围：渐变网格、噪点纹理、颗粒叠加、戏剧性光照

**导航：**
- 清晰的结构和直观的导航菜单
- 深层级（超过2级）的页面使用面包屑导航
- 使用标准UI模式降低学习曲线（汉堡菜单、标签栏）
- 确保可预测的行为（返回按钮有效，链接可点击）
- 保持导航上下文（高亮当前页面，保留滚动位置）

## 样式实现

- 通过CSS自定义属性遵循`index.css`中的主题变量
- 在`@theme`中映射变量（参考`tailwind.config.js`）
- 仅在绝对必要时使用内联样式或CSS模块

**图标：**
- 使用`@phosphor-icons/react`用于按钮和输入
- 示例：`import { Plus } from "@phosphor-icons/react"; <Plus />`
- 使用颜色为纯图标按钮
- 除非有要求，否则不要覆盖默认的`size`或`weight`

**通知：**
- 使用`sonner`用于吐司
- 示例：`import { toast } from 'sonner'`

**加载状态：**
- 始终添加加载状态、旋转器、占位符动画
- 使用骨架屏直到内容渲染完成

### 布局实现

**间距策略：**
- 使用带`gap`的网格/弹性包裹器进行间距
- 优先使用包裹器而非直接在子元素上设置边距/填充
- 根据需要嵌套包裹器以实现复杂布局

**条件样式：**
- 使用三元运算符或clsx/classnames工具
- 示例：`className={clsx('base-class', { 'active-class': isActive })}`

### 响应式设计

**流体布局：**
- 使用相对单位（%、em、rem）而非固定像素
- 使用CSS Grid和Flexbox实现灵活布局
- 先设计移动端，再扩展到其他设备

**媒体查询：**
- 基于内容需求设置断点，而非特定设备
- 在多种设备和方向上测试

**触摸目标：**
- 交互元素最小44x44像素
- 提供足够的触摸目标间距
- 为桌面添加悬停状态，为触摸/键盘添加焦点状态

**性能：**
- 优化移动网络上的资源
- 使用CSS动画而非JavaScript
- 对图片和视频实现懒加载

## 无障碍标准

**核心要求：**
- 遵循WCAG 2.1 AA指南
- 确保所有交互元素可通过键盘导航
- 最小触摸目标尺寸：44×44像素
- 使用语义化HTML以兼容屏幕阅读器
- 为图片和非文本内容提供替代文本

**实现细节：**
- 使用描述性的变量和函数名
- 事件函数：以"handle"为前缀（handleClick、handleKeyDown）
- 添加无障碍属性：
  - `tabindex="0"`用于自定义交互元素
  - `aria-label`用于无文本的按钮
  - 当语义化HTML不足时添加`role`属性
- 确保逻辑的Tab顺序
- 提供可见的焦点状态

## 设计流程与测试

### 设计工作流

1. **理解上下文：**
   - 我们在解决什么问题？
   - 用户是谁？何时会使用这个？
   - 成功标准是什么？

2. **探索选项：**
   - 提供2-3种替代方案
   - 解释每个选项的权衡
   - 哪个方向更契合？

3. **迭代实现：**
   - 先构建结构和层级
   - 逐步添加视觉修饰
   - 每个阶段进行测试

4. **验证：**
   - 使用playwright MCP测试视觉变化
   - 在不同屏幕尺寸上检查
   - 验证无障碍性

### 测试清单

**视觉测试：**
- 使用playwright MCP进行自动化测试（当可用时）
- 在常见断点检查响应式行为
- 验证移动端的触摸目标
- 使用不同长度的内容（短、长、边缘情况）进行测试

**无障碍测试：**
- 测试键盘导航
- 验证屏幕阅读器兼容性
- 检查颜色对比比例
- 确保焦点状态可见

**跨设备测试：**
- 在真实设备上测试，而非仅模拟器
- 测试不同浏览器（Chrome、Firefox、Safari）
- 验证移动端的触摸交互
- 测试横屏和竖屏方向

## 应避免的常见模式

❌ **绝对禁止：**
- 使用Inter、Roboto、Arial、Space Grotesk作为主要字体
- 使用通用SaaS蓝色（#3B82F6）或白色上的紫色渐变
- 模仿苹果设计语言或使用玻璃形态效果
- 创建看起来像AI生成的千篇一律布局
- 在设计前不询问上下文
- 在不同代之间使用常见选择（要与众不同！）
- 创建会延迟用户操作的动画
- 创建元素相互竞争的杂乱界面

✅ **始终：**
- 首先询问目的、语气、限制、差异化
- 大胆地坚持独特的审美方向
- 使用意想不到、有特色的排版选择
- 营造氛围：阴影、渐变、纹理、颗粒（在有意为之时）
- 主色调搭配锐利的强调色（不要胆怯、均匀分布的调色板）
- 提供交互的即时反馈
- 使用真实设备测试
- 验证无障碍性（它扩展创造力，而非限制）

## 何时打破规则

指南的存在是为了防止平庸，而非限制卓越。当：

**上下文要求时：**
- 客户品牌已使用Inter？精彩地使用它，不要强迫替代方案
- 玻璃形态就是审美？全力投入，不要半途而废
- 简报要求苹果式的精致？研究和超越，不要回避

**你有更好的想法：**
- 有意执行的"禁止"模式比没有信念的"安全"模式更胜一筹
- 如果你能够解释为何要打破规则，那就打破它
- 平庸的规则遵循 < 大胆的规则打破（有目的）

**意外就是重点：**
- 故意的冲突（冲突字体、刺眼的颜色）可以很有力
- "丑陋"设计在刻意时是合法的审美选择
- 舒适是记忆点的敌人

**打破规则清单：**
1. 你能解释创意意图吗？
2. 这是深思熟虑的选择，而非懒惰？
3. 它是否服务于用户/品牌/上下文？
4. 资深设计师会为这个选择辩护吗？

如果全部肯定 → 自信地打破规则。
