# 游击战式竞选

一种面向无法通过投入更多资金来取胜的组织和个人的竞选设计技能。它能够为每个主要原型构思竞选概念，审计用户相对于竞争对手的投入不对称性，组装游击队渠道堆栈，对任何付费投入设置严格的提升门禁，并制定提升测试计划，使用户衡量增量影响而非虚荣指标。

## 核心前提

**付费媒体扩展关注度。有机叙事和草根网络扩展信任。**
当信任是瓶颈时——而在2025-2026年，对于大多数弱势方来说，它就是瓶颈——额外的广告投入会产生递减甚至负回报。饱和、不真实和叙事不一致会产生抵触情绪，而非说服力。杠杆点不是覆盖范围；而是可信度和信息市场契合度。

实证支撑：

- 学术领域的实验表明，数字广告投资回报率的置信区间非常宽，以至于大多数竞选活动在统计上无法与零提升区分开来（刘易斯和拉奥，《衡量广告回报的不利经济学》，《经济学季刊》2015年）。
- Meta和Google都推出了转化提升/品牌提升工具，正是因为它们能够区分归因转化和增量转化——平台的工具本身就是对仪表盘ROAS并非因果关系的默示承认。
- 在18,000多个品牌中，2025年有13/14个行业CPA上升；ROAS在13/14个行业下降；转化率在13/14个行业下降。更多的钱正在购买更少的结果。
- Facebook的有机参与度接近0.15%，Instagram约为0.50%，X约为0.15%，TikTok约为2.50%——仍然是最好的有机窗口，但正在快速压缩。
- Meta和Google都在2025年10月结束了欧盟的政治/议题广告，完全移除了付费渠道，迫使有机渠道承担竞选任务。
- 在最极端的投入不对称性情况下（一个草根政党与一个价值40亿的国有宣传机构，并得到外国支持），在2026年4月匈牙利赢得议会超级多数的一方几乎没有任何付费媒体——参见`references/hungarian-case-study.md`。

同样的曲线也弯曲了商业广告。这项技能将付费视为已证明的有机赢家的*放大器*，而不是一个独立的渠道。

## 何时应用此技能

当用户：

- 询问计划任何竞选活动（营销、发布、筹款、动员、提高知名度、投票）。
- 描述被竞争对手、在任者或对手击败。
- 正在考虑广告投入、助推、影响者交易或扩展付费渠道。
- 正在观察有机覆盖范围崩溃，不知道该怎么办。
- 正在准备发布、选举、筹款、产品推广或以行动为导向的时刻。
- 正在决定在付费和有机分配之间，或在不同渠道之间进行选择。

此外，当没有明确命名“竞选”但用户正在讨论在哪里投资时间和金钱用于分发时，也应应用。

## 工作流程

该技能分为七个阶段（1、2、3、3a、4、5、5b）。不要跳过阶段；后面的阶段依赖于用户在早期阶段的答案和选择。阶段3a（MMF门禁）可以拒绝完整的竞选计划，并将用户引导至验证工作。阶段5以形状选择结束——只有用户选择了其中一个形状后，阶段5b才会开始。

此技能设计为可在不同代理环境中移植。当工作流程指示“询问用户”时，请使用您的环境提供的任何结构化问题设施（在Claude Code中，这是`AskUserQuestion`工具，每次最多可批量处理4个问题）；如果没有结构化工具，请以纯文本提问，并在继续之前等待用户回复。无论如何，永远不要编造答案。

**恢复协议（幂等性）。** 在生成任何输出之前，扫描对话以查找先前的技能输出。如果对话中已经存在某个部分的标题（`## N. <name>`），则不要重新生成它。从第一个满足其合同先决条件且其输出部分尚未出现在对话中的阶段开始。如果用户明确要求重新开始，则从阶段1重新开始；否则，恢复而不是重新运行。这使得技能可以安全地重新调用：同一对话中的第二次调用只会生成下一个增量部分，绝不会重复或回归到早期阶段。范围：幂等性在单个对话内有效；如果先前的输出仅存在于外部文件或先前会话中，请先将其粘贴到对话中或从阶段1重新开始。

**阶段合同。** 以下每个阶段都以一个**合同**块开头，声明输入、输出、先决条件、后置条件和失败模式。合同是结构边界——它是使阶段重试安全、错误明确和自我描述的原因。将合同视为具有约束力：如果先决条件未满足，则不要进入该阶段；如果触发失败模式，请采取声明的行动，而不是即兴创作。

### 阶段1 — 访谈/简报捕获

**合同**
- 输入：用户的初始简报（自由文本，任何长度）。
- 输出：模式C下的第0节（假设表）；模式标签（A/B/C）以及为下游阶段捕获在工作内存中的8个字段。
- 先决条件：无（入口阶段）。
- 后置条件：所有8个字段都有值（捕获、默认或标记为`[ask]`表示仍待回答的问题）；模式已确定。
- 失败模式：
  - 在模式C下缺少任何始终捕获的字段 → 将其添加到问题批量中；不要无声地默认。
  - 缺少字段会改变阶段3的不对称性分类或阶段4功能选择 → 将其升级到批量中，即使它通常会默认。
  - 用户对同一字段给出矛盾值 → 问一个澄清问题；不要无声地选择一个。

该技能有**三种摄入模式**。在提问任何问题之前，选择与用户简报匹配的模式。

**模式A — 完整简报模式。** 用户已主动提供以下8个字段（在粘贴的简报、先前的计划、详细消息中）。跳过访谈，用一句话确认理解，然后进入阶段2。

**模式B — 访谈模式。** 用户明确要求进行范围界定（“帮助我确定这个竞选活动应该是什么”，“引导我完成”，“采访我”）。按每轮≤4个问题的批量，使用环境提供的结构化问题设施（见上述工作流程部分的结构化工具注释）。不要编造答案。不要合并问题。

**模式C — 默认模式（适用于简短简报）。** 用户给出了简短简报（≤2句话），而没有要求访谈。这是常见情况。不要运行完整的8个问题访谈——它会将12个字的提示变成审问。相反：

1. **始终捕获字段（一次性批量提问）。** 四个字段太重要了，不能无声地默认；错误会导致通用计划。以**一次性批量**（最多4个问题）向用户提问，涵盖：

   - **结果**——竞选推动的具体行动是什么（注册、票务销售、投票、捐款、出席、预购、合格潜在客户）？
   - **受众**——目标是谁？谁经历了这个问题？地理、资历、社区成员。“所有对AI感兴趣的人”不是一个受众；“在伦敦的资深的AI/ML工程师，在A-C轮融资的初创公司”是。
   - **行业**——从`references/sector-riders.md`中的6个骑手中选择（`cohort-education`、`b2b-saas`、`ngo`、`消费品牌`、`政治公民`、`个人品牌`），或选择`其他`并附上一句话描述。行业骑手会实质性改变阶段4渠道权重和阶段5原型默认值。
   - **预算**——你每月实际可以花费多少（€0 / <€1k / €1k–10k / €10k+），以及竞争对手的大致花费是多少（未知 / 类似 / 我们的5倍 / 我们的50倍+）？预算会实质性改变阶段3不对称性分类和阶段4付费渠道的可用性。永远不要无声地默认。

   如果这四个字段中的任何一个在用户的简报中已经非常清楚，请将其从问题批量中删除。只问缺失的部分。

2. **默认带标记字段。** 剩余字段默认，但在最终交付品（阶段5输出）的顶部以**假设表**的形式呈现。用户可以在阅读计划后直接确认或调整：

   | 字段 | 简短简报下的默认值 |
   |---|---|
   | 竞争（具体） | 抽象——“类别中的基于群体的课程”、“中型SaaS竞争对手”等。使用`references/asymmetry-audit-table.md`中的启发式问题对不对称性进行定性分类。永远不要编造具体的竞争对手名称。 |
   | 现有渠道/进展 | “从零开始”，除非用户的简报、工作目录或CLAUDE.md明确表明存在现有的简报、社区或粉丝基础。 |
   | 瓶颈 | 信任（2025-2026年几乎所有弱势方竞选活动的默认值）。 |
   | 时间窗口 | 永恒的 / 30 / 60 / 90天 / 紧密联系到一个日期锚点（事件、发布、选举），然后是周期性节奏。 |
   | 能力 | 每周6小时。 |

3. **升级规则。** 如果缺少字段会实质性改变阶段3的不对称性分类*或*阶段4主要功能选择，则不要默认它——将其添加到问题批量中。示例：如果用户提到“我们整个团队已经在发布”，但没有指定哪个渠道，请提问，因为它改变了渠道堆栈。

4. **假设表在模式C下是强制性的。** 以一个列出每个默认字段及其假设值的表格打开最终交付品。在交付品末尾添加：*"确认或调整假设表中的任何一行，我将重新运行受影响的阶段。"*。

#### 8个字段

无论模式如何，竞选计划都基于这8个字段：

1. **行业和结果**——哪个6个行业骑手适用，以及竞选推动的具体行动。（行业在模式C中一次性提问；结果在模式C中一次性提问。）
2. **受众**——目标是谁，需要足够的特异性才能想象他们。（模式C中一次性提问。）
3. **竞争/在任者**——命名3-5个具体竞争对手，*或者*说“未知”/“我将抽象地描述他们”。如果未知，保持在类别级别，并使用`references/asymmetry-audit-table.md`中的启发式方法。永远不要编造名称。（模式C中默认；用户可以在假设确认中锐化。）
4. **预算**——用户和竞争对手的，用数字或大致比例表示。
   （模式C中一次性提问。）
5. **现有渠道和进展**——用户在哪里已经触达受众（简报大小、社区大小、重要的粉丝数量、暖邮件列表、先前的新闻）。（模式C中默认。）
6. **瓶颈**——覆盖范围/信任/转化/投票/留存——选择一个。
   （模式C中默认为信任。）
7. **时间窗口**——永恒的 / 30 / 60 / 90天 / 紧密联系到一个日期锚点（事件、发布、选举）。（模式C中默认为60天。）
8. **能力**——现实的每周小时数。硬性限制阶段5的“前30天”行动列表；最低ROI的行动将被削减，直到每周总工作量符合要求。（模式C中默认为每周6小时。）

### 阶段2 — 概念构思（生成5个以上跨原型的竞选概念）

**合同**
- 输入：来自阶段1的8个字段（尤其是行业、受众、竞争描述符）。
- 输出：第1节（竞选想法）包含≥5个跨不同原型的概念；明确要求用户选择一个或多个。
- 先决条件：阶段1完成；行业字段有值（命名或`其他`）。
- 后置条件：呈现≥5个不同原型概念；用户已被提示选择。
- 失败模式：
  - 简报中未命名竞争对手 → 在每个概念中使用`[在任者]`占位符或类别描述符；永远不要编造一个名称。
  - 无法为这个受众/行业生成5个真正不同的原型 → 平静地说明，呈现你拥有的内容，不要用一个原型的化妆品变体填充。
  - 用户的简报命名了一个主要参与者，但期望行业同行 → 不要自动命名明显的第2/#3；使用行业同行规则中的逃生短语。

在任何审计或渠道工作之前，生成**至少五个不同原型的竞选概念**，这些概念来自`references/campaign-archetypes.md`中的不同原型。不要过早收敛。目的是给用户提供一个有形状的菜单供选择。

对于每个概念，生成：

- **名称**——简短、易记、用用户的语气。
- **一句话的论点**——为什么这个竞选活动现在对*这个*用户针对*这个*竞争对手有效。
- **原型**——它来自哪个原型（例如，创始人故事弧、反叙事、赢得媒体噱头、推荐飞轮、社区建设、联盟策略）。
- **主要渠道层级**——这个概念倾向于`references/channel-tier-stack.md`中的哪个层级（层级1/2/3/4）。
- **真实性钩子**——使它可信且难以伪造的具体现实细节、人物、故事或行动。
- **最小可行版本**——两周内证明概念是否有效的最小执行版本。

**概念名称、论点和钩子的反制造规则。** 如果用户在简报中命名了具体的竞争对手，请使用该名称。如果用户说“一个众所周知的在任者”、“市场领导者”、“主要参与者”或以其他方式没有命名，**不要用你的最佳猜测来填补空白**。保持在简报给你的抽象级别。使用类别描述符（例如，“每台400美元的显示器”）、行为（“企业账单税”）或用户将填入的括号占位符（`[在任者]`）。像“我们退出Sentry”或“DataDog替代品”这样的概念名称——从类别描述符而不是简报中发明——违反了阶段1的反制造规则，并且不得出现在阶段2输出中。这同样适用于SEO关键词列表、赢得媒体提议钩子和任何继承概念名称的下游部分。

**行业同行规则。** 反制造规则涵盖简报中缺失的*任何*竞争对手名称——不仅是不 invented 名称，而且是广泛知名的行业同行，对于一个简报命名的在任者。如果用户说“我们被[市场领导者]击败了100倍”，请**不要**自行添加同一类别中明显的第2或第3个（“LexisNexis和Westlaw”、“Salesforce和HubSpot”、“Datadog和New Relic”）作为暗示的上下文存在，好像他们的存在是隐含的。相反，使用逃生短语：“其他主要的[类别]平台”、“[在任者]级工具”或“主要的[类别]在任者”。这适用于每个部分——阶段2概念、阶段4 SEO、阶段5竞争对手饱和、阶段5b赢得媒体目标和广告文案钩子，以及任何其他下游输出。这种纪律在任何后续阶段都不会放松。“整个行业都知道它的存在”不是命名它的许可。

在呈现五个概念后，要求用户选择一个（或多个）以推进阶段3-5。

### 阶段3 — 不对称性审计

**合同**
- 输入：预算（用户+竞争对手的），或来自`references/asymmetry-audit-table.md`的启发式答案；用户从阶段2选择的概念。
- 输出：第3节（支出不对称性裁决）——一句话分类+先决条件得分（0-6）。
- 先决条件：阶段2完成；用户已命名一个或多个要推进的概念。
- 后置条件：不对称性分类为轻微/严重/类别性；先决条件计数在{0..6}中；下游阶段知道要运行哪个剧本规模。
- 失败模式：
  - 0-2个先决条件 → 命名缺失的先决条件，拒绝完整的剧本，将用户引导至构建缺失的先决条件作为竞选本身。
  - 缺少不对称性数字 → 在参考文件中询问启发式问题；不要假设一个水平。
  - 用户以非可比形式给出竞争对手支出（例如，收入、员工人数）→ 问一个澄清问题以将其转换为支出比率；不要无声地估算。

使用 `references/asymmetry-audit-table.md` 中的表格对用户的消费不对称性进行分类。

- 如果用户提供了数字：计算比率（竞争对手支出 ÷ 用户支出），并将其映射到轻微（1:2–1:5）、严重（1:5–1:50）或类别（1:50+）。
- 如果用户没有提供数字：询问参考文件中的启发式问题（政府支持？他们负担得起广告牌吗？他们在你的类别中的搜索广告中占据主导地位吗？），并进行定性分类。

报告一句话：`你的不对称性是 <级别>。这意味着 <这对你的策略意味着什么>`。不要含糊其辞。如果用户处于类别级别，不要提供“平衡”的建议——这会具有误导性。

然后运行一个 **前提条件检查**。当前提条件存在时，叛乱手册会获胜；不对称性本身是不够的。根据使匈牙利案例成功的六个因素（有关完整机制，请参阅 `references/hungarian-case-study.md`）给用户的处境打分。询问或推断：

1. **可信的内部人士 / 创始人故事 / 相当于脱党者。** 是否有一个真实的人，其真实性竞争对手无法制造？
2. **累积的怨恨或未满足的需求。** 是否有长期被现有公司忽视的愤怒，以至于它只需要一个载体？
3. **整合的挑战者领域。** 用户是唯一明确的替代方案，还是众多替代方案之一？分散的领域会稀释有机叙事。
4. **感受到的痛苦，而不是抽象的痛苦。** 每个目标是否直接感受到成本（价格、时间、信任、服务失败），还是怨恨是分散的？
5. **阈值奖励市场 / 平台 / 系统。** 分配系统是否在份额跨越某个阈值后奖励整合（网络效应、类别领导地位、算法约束的注意力、选举数学）？
6. **现有公司过度夸大恐惧 / 饱和手法。** 竞争对手是否正在曲线之外运行——更多广告、更多恐惧、更多精致的內容——以用户可以反定位的方式？

评分 0–6。告诉用户数量以及它意味着什么：

- **5–6 个前提条件：** 在全规模下运行叛乱手册。继续进行第 4 阶段。
- **3–4 个前提条件：** 继续，但将缺失的作为活动子目标标记——用户将在活动中需要构建它们（例如，寻找可信的声音、揭示怨恨）以使有机成分复合。
- **0–2 个前提条件：** 拒绝在全规模下执行手册。**构建前提条件是活动。** 招募可信的声音，整合联盟，揭示并命名怨恨，找到感受到痛苦的叙事。直到这些存在，叛乱手册的表现将不佳，并会消耗它所依赖的志愿者/社区能量。大声说出这一点。不要软化它。

### 第 3a 阶段——信息市场匹配门

**合同**
- 输入：来自用户的三个是/否信号（收入/承诺、受众语言、关闭）。
- 输出：第 3a 部分（3 个信号 + 0–3 分 + 明确的裁决）。
- 前提条件：第 3 阶段完成。
- 后置条件：裁决 ∈ {3/3 继续、2/3 验证周期、0–1/3 拒绝}；下游阶段知道是否要继续、插入验证周期或停止。
- 失败模式：
  - **评分 0–1/3 → 只生成第 3a 部分 + 拒绝文本；不要生成第 4–11 部分。将用户路由到发现周期。**
  - 评分 2/3 → 生成第 3a 部分 + 验证周期前置任务描述；只有在验证周期命名后才能允许第 4 阶段。
  - 用户不知道一个信号的答案 → 将该信号视为“否”（缺乏证据就是证据的缺乏，用于 MMF）；不要跳过问题。

在组装渠道堆栈之前，验证活动是否在解决 **分配问题，而不是 MMF 问题**。分配放大信号；它不能制造信号。创始人优秀的领英帖子不能销售没有人想要的产品，而一个运动的最佳志愿者网络不能为一个不命名其痛苦的口号带来选民。

询问用户三个是/否问题。不要跳过任何一个。如果用户不知道一个问题的答案，将其视为“否”——缺乏证据就是证据的缺乏，用于 MMF。

1. **收入/承诺信号：** 目标受众中是否有 ≥10 人支付、注册、预先注册或直接要求（未经你的提示）你提供的东西？对于活动：≥10 位过去参与者或付费候补名单。对于产品：≥10 名客户或预订单。对于运动：≥10 名志愿者/成员。
2. **语言信号：** 在你向他们推销之前，你能说出目标受众用自己的话表达的 **具体痛苦** 吗？不是你推断的痛苦——某个受众实际说过、写过或发布过的句子。
3. **关闭信号：** 如果你向目标受众中的 5 人承诺今天（在预期的价格/格式/请求级别），至少有 3 人会说“是”。

评分：

- **3/3 — MMF 确认。** 活动是一个分配问题。继续进行第 4 阶段。
- **2/3 — 边界。** 指出薄弱环节并在计划中插入 **1–2 周验证周期** 作为活动前置任务 *在运行完整的第 4–5 手册之前*。示例：如果问题 2 失败，进行 5 次客户发现对话并提取语言；如果问题 1 失败，运行付费候补名单或预订单测试。验证周期后重新审视 MMF 门。
- **0–1/3 — 拒绝完整活动计划。** MMF 是瓶颈，而不是分配。将用户路由到发现周期：5 次结构化客户对话、预订单或付费候补名单测试、小型房间现场演示。明确说明：*"叛乱手册按信任扩展。它不能制造对产品、活动或人们不想要的口号的需求。现在运行完整活动将消耗第 5 阶段依赖的志愿者/社区能量。当至少 2/3 的这些信号存在时再回来。"* 不要软化它。不要生成完整第 4–5 交付物。

在最终输出的第 3 阶段顶部报告 MMF 裁决，以便用户在渠道堆栈之前看到它。

### 第 4 阶段——渠道级别堆栈 + 70/30 分配

**合同**
- 输入：瓶颈（第 1 阶段 Q6）、部门（第 1 阶段 Q1）、不对称性裁决（第 3 阶段）、MMF 裁决（第 3a 阶段）。
- 输出：第 4 部分（渠道级别堆栈）+ 第 5 部分（70/30 或 80/20 分配）。
- 前置条件：第 3a 裁决是 `3/3 继续` 或 `2/3 带有验证周期附加`。**如果裁决是 `0–1/3 拒绝`，此阶段必须不执行。**
- 后置条件：主要功能选择（需求捕获 / 付费放大 / 信任复合）；部门骑手应用；列出渠道并估计每周工作量；以纯数字说明分配比例。
- 失败模式：
  - 不对称性是类别 **且** 用户请求广泛冷付费第 4 级 → 拒绝，路由到第 1/2 级 + 反定位，解释 `references/authenticity-playbook.md` 中的边际收益递减曲线。
  - 部门 = `其他` → 在假设表中标记骑手不匹配，继续使用最接近的骑手，说明哪些骑手的结构假设不适用。
  - 功能选择与部门骑手冲突（例如，B2B SaaS 骑手偏向创始人领英，功能选择是需求捕获）→ 揭示冲突，呈现两条路径，不要无声地折叠。

**功能优先于成本。** 在选择渠道之前，根据用户的瓶颈（来自第 1 阶段 Q6）选择活动的主要功能。使用 `references/channel-tier-stack.md` 顶部的功能表：

- **需求捕获** — 瓶颈是“人们已经想要这个，他们找不到我们。” 小型或不知名挑战者的主要功能，具有可衡量的现有意向。以非品牌谷歌搜索、SEO、目录存在为领导。
- **付费放大** — 瓶颈是“我们的有机内容有效，但覆盖范围太少。” 只有在有机赢家存在（24–48 小时牵引门）之后才是主要功能。以再营销、温热相似用户、在已证明的抖音内容上的 Spark Ads 为领导。
- **信任复合** — 瓶颈是“人们找到我们，有时点击，但不会转换、推荐或回来。” 大多数弱者活动的主要功能。以第 1 级：创始人内容、社区节点、通讯录、志愿者网络为领导。

轻微不对称性用户与信任瓶颈不应仅因为他们负担得起而被路由到付费放大。首先按功能路由；其次在功能内按成本/不对称性分配。

**应用部门骑手。** 在功能选择之后但在分配之前，打开 `references/sector-riders.md` 并应用与用户部门（在第 1 阶段捕获）匹配的骑手。骑手调整：

- **原型默认值** — 哪些活动原型最适合此部门（例如，队列教育偏向社区建设 + 推荐飞轮；B2B SaaS 偏向创始人领英 + 需求捕获）。
- **渠道权重** — 在此部门中复合最快的第 1/2 渠道（例如，消费品品牌依赖 UGC 飞轮；政治活动依赖地面游戏和反媒体；非政府组织依赖志愿者网络 + 在命名受益人故事上的赢得媒体）。
- **失败模式警告** — 部门特定方式叛乱手册在错误应用时表现不佳，这成为第 5 阶段反虚荣仪表板中的永久警告。

不要覆盖功能选择。骑手 *叠加在* 顶部。如果骑手和功能选择冲突（例如，B2B SaaS 骑手偏向创始人领英，但功能选择是需求捕获），揭示冲突并命名两条路径，而不是折叠到一条。

如果用户选择了“其他”作为部门，请在假设表中标记不匹配，并继续使用最接近的骑手——说明骑手的哪些结构假设不适用。

然后使用 `references/channel-tier-stack.md` 组装渠道堆栈。分配规则叠加在功能选择和部门骑手之上：

- **轻微不对称性** → 堆栈可以包括第 1、2、3 和选择性第 4 级。将 ~70% 的精力分配给有机（第 1 + 2 级），30% 分配给付费放大（第 3 级，罕见第 4 级）。
- **严重不对称性** → 第 1、2 和目标第 3 级。避免广泛第 4 级。80/20 分配通常更安全地偏向有机。
- **类别不对称性** → 第 1 和 2 级。拒绝起草广泛冷付费第 4 级创意——它不会起作用，它会烧掉跑道。如果用户坚持，解释边际收益递减曲线和反定位动作（见 `references/authenticity-playbook.md`）后再重新考虑。

以优先列表的形式输出堆栈： (a) 选择的主要功能，(b) 映射到该功能的渠道，(c) 每个渠道估计的每周工作量，(d) 70/30（或 80/20）的纯数字分配。

**反制造贯穿始终。** 第 2 阶段反制造规则适用于第 4 阶段输出的每个元素：SEO 关键字示例、长尾查询列表、目录/评论网站参考、竞争对手饱和描述以及与堆栈内联显示的任何样本文案。如果简要没有命名现有公司，现有公司的专有名词不得在此阶段以任何大小写形式出现——不是标题大小写（“Sentry 替代品”）、不是小写（“sentry alternative”）、不是连字符、不是作为复合关键字或 URL 的一部分。否则需要品牌名称的搜索查询示例必须保留 `[现有公司]` 方括号占位符供用户填写，或者重写为非品牌等效项（“小型团队错误监控”、“100/座位以下应用监控”、“node.js 轻量级 APM”）。这同样适用于第 5 阶段的竞争对手饱和地图以及第 5b 输出部分（`## 8`–`## 11`）：禁止标记纪律在 2 阶段之后不会放松。

### 第 5 阶段——菜单塑形 + 竞争对手饱和地图

**合同**
- 输入：选定概念（第 2 阶段）、渠道堆栈 + 分配（第 4 阶段）。
- 输出：第 6 部分（竞争对手饱和地图）+ 第 7 部分（三个替代活动形状）。**没有其他部分。**
- 前置条件：第 4 阶段完成；分配已说明。
- 后置条件：呈现三个形状及其权衡；用户已被明确要求选择一个；回合结束。
- 失败模式：
  - **达到阶段末尾而未从用户处获得形状选择 → 以选择询问结束回合；不要生成第 8–11 部分。**
  - 用户无法讲述自我故事（马歇尔·冈茨框架）→ 放弃创始人领导形状，呈现社区优先 / 赢得媒体优先 / 搜索捕获优先。
  - 简要已预先选择形状（罕见）→ 在一句话中确认选择，继续进行第 5b 阶段。

给定选定概念 + 渠道堆栈，只生成以下两项。第 5 阶段以用户选择其中一个形状结束；不要生成任何第 5b 输出（`## 8`–`## 11`）直到选择已做出。

1. **竞争对手饱和地图。** 在形状之前、广告文案之前、任何东西之前：对于前 2 个命名竞争对手（或者如果用户没有命名具体竞争对手，则对于前 2 个竞争对手 *类别*——见原则），生成：

   (a) **他们饱和的内容** — 竞争对手淹没的渠道、视觉风格、信息手法、制作价值和情感基调。要具体：“付费密集型领英轮播图，带有股票插图和增长黑客 CTA”，而不是“社交媒体广告”。

   (b) **缺席成为你的信号。** 竞争对手正在做什么，而你的 *拒绝* 做成定位？工作示例：
   - "Fidesz 淹没广告牌 → Tisza 在广告牌上的缺席是信息。"
   - "队列训练营淹没付费领英管道 + 联盟链接 → 我们拒绝广告和我们的免费开放课程是信息。"
   - "SaaS 竞争对手淹没由代理制作的演示视频 → 我们的终端仅限原始素材每周变更日志是信息。"

   (c) **一句话定位行** 用户在活动中承诺坚持。这是每件内容必须加强的句子。

2. **三个替代活动形状** 执行概念，附带权衡。形状示例：*社区优先*（从 100 个真实的人开始，通过口碑增长）、*赢得媒体优先*（一个新闻性动作驱动媒体 + 有机放大）、*搜索捕获优先*（在高意向长尾查询中占据主导地位，需求已存在）。使用 `alternative-generator` 模式——不要过早地折叠到一个建议；让用户选择。每个形状必须至少包含一个以 **自我 / 我们 / 现在**（马歇尔·冈茨的组织框架——见 `references/authenticity-playbook.md`）结构的首席内容：领导者的生活经验、共享的社区现实和特定的时间限制请求。如果用户无法讲述自我故事，放弃创始人领导形状，路由到社区优先、赢得媒体优先或搜索捕获优先。

**停止点。** 只输出部分 `## 6`（竞争对手饱和地图）和 `## 7`（三个替代活动形状），然后以明确的请求结束回合：*"从三个形状中选择一个（或要求我修改它们），我将生成 30 天计划、广告文案、提升测试和反虚荣仪表板。"* 直到用户命名一个形状之前，不要生成 `## 8`–`## 11`。如果用户的初始简要已预先选择形状（罕见），请在一句中确认该选择，并继续进行第 5b 阶段。

### 第 5b 阶段——选定形状计划

**合同**
- 输入：用户在第五阶段选择的*唯一*形状；容量（第一阶段Q8）；来自第四阶段分配的付费渠道角色。
- 输出：第8节（前30天行动计划）+ 第9节（广告文案+助推规则，仅适用于付费）+ 第10节（提升测试/测量计划）+ 第11节（反虚荣指标仪表盘）。
- 前置条件：第五阶段完成*且*用户已命名特定形状（通过索引或名称）。
- 后置条件：30天计划符合声明的容量上限（若不符合则裁剪命名部分）；选择单个命名的提升测试模板；跟踪/忽略列出的指标。
- 失败模式：
  - **未从第五阶段命名形状即进入→请求选择；不生成任何第8-11节内容。**
  - 草拟的每周工作量超出容量上限→裁剪最低ROI行动，直至总量符合；明确命名裁剪内容。
  - 获益媒体目标未知/不在简报中→将第一周研究标记为具有明确研究方法的行动；不要编造渠道名称。
  - 渠道堆栈中不适用付费→完全省略第9节（不要生成空/占位符广告文案）。
  - 非对称类别*且*堆栈中适用付费→在第9节生成反定位拒绝说明，不要冷付费创意。

仅在用户从第五阶段选择了三种形状之一后开始。若未收到选择，请求选择并停止。下四项针对*唯一*选择的形状生成——不是全部三种。

1. **前30天行动计划** — 针对第1-4周的具体每周行动，映射到所选形状。每个行动有负责人（若多人）、工作量估算和明确的成功信号。

   **容量是硬约束。** 草拟周计划后，汇总每周总工作量。若超出用户声明的容量（第一阶段Q8，默认每周6小时），裁剪最低ROI行动，直至总工作量符合上限。明确命名裁剪内容："我裁剪了X和Y，因为草拟计划达到14小时/周，而你只说了6小时/周。若你能抽出更多时间，这些是可重新添加的行动。"
   不要交付用户无法执行的计划。

   **获益媒体行动必须具体或标记。** 列表中的每个获益媒体行动必须包括：
   - (a) **命名目标**（例如，"Latent Space播客，The Pragmatic Engineer通讯"）*或*明确的"目标待定——第一周为研究行动"标记。不要提出"5个细分领域播客"而不命名；这不是行动，这是愿望。
   - (b) **匹配目标近期内容的单句钩子**——不是通用的个人简介轰炸。
   - (c) **成功标准**——回复、提及、嘉宾位置、跨发布、播客预订或通讯特写。
   - (d) **外联日和渠道**——周二上午通过邮件、周四通过LinkedIn私信等。

   若技能不知道用户细分领域的具体目标（因为用户未命名且技能不能编造名称——见原则），将目标研究作为第一周行动，并为研究本身设定成功标准（例如，"周五前生成15个目标，含RSS+联系方式排名列表"）。

   **社区建设是多周子活动，不是单项。** 若渠道堆栈中有Slack/ Discord/ WhatsApp/ Circle社区节点，它在前30天列表中应有自己的区块，而不是每周1小时的单行：
   - **第0周（公开宣布前）：** 选择平台、撰写规则、用用户现有网络邀请10个个人。死房间比没有房间更糟。
   - **第1-2周：** 创始人连续14天每天发布。不可协商。没有创始人的每日存在，社区无法达到逃逸速度。
   - **第3-4周：** 将三个常规仪式（每周主题帖、AMA节奏、成员聚焦）交接给2-3名积极参与的早期成员。若无人接手，社区将在创始人停止时消亡；将其作为验证失败呈现，而不是人员问题。
   - **第2个月+：** 持续预算3-4小时/周——版主、每周发布、成员欢迎、清理死账户。投入不足社区会消亡。

2. **广告文案+助推规则** — 仅在所选堆栈中适用付费时：
   - 创意方向用用户真实声音（见`references/authenticity-playbook.md`）。
   - 明确的**24-48小时自然流量门槛**：不要助推帖子，直到它展示出真实自然信号（保存、分享、持续观看时间、主题深度评论——不是原始点赞）。点赞廉价且虚假。
   - 受众定义：先热重定向，再相似受众，只有带提升测试计划的成熟受众才用冷受众。
   - 频率上限和创意刷新节奏，避免疲劳（见`references/channel-tier-stack.md`中广告疲劳部分）。
   - **不要在未进行提升测试的情况下竞标品牌关键词。** Blake, Nosko & Tadelis的eBay实地实验（2015年）发现品牌关键词竞价弱或无增量提升——流量本来就会自然到达。平台报告的品牌关键词ROAS总是优秀*因为*流量本来就会转化。这是成熟品牌浪费付费预算的最可靠方式。若用户已在竞标品牌，要求品牌关键词排除测试（`references/lift-test-templates.md`中的模板5）后再继续投入。
   - 若非对称是类别性，拒绝生成广泛冷付费文案。提供1/2级内容，并解释原因。

3. **提升测试/测量计划** — 强制执行，无例外。使用`references/lift-test-templates.md`中的模板进行一个具体实验。模板选择：
   - **有预算：** 模板1（地理排除）或模板2/3（转化提升）。
   - **极小预算（<€5k），正式模板能力不足：** 模板4（微提升）。
   - **品牌关键词竞价已生效：** 模板5（品牌关键词排除）。
   - **零预算：** 模板6（自然来源归因）——方向性，带UTM标签，30天窗口，每渠道转化率排名，裁剪底20%再投入顶20%的决策规则。
   指定：
   - 假设（付费渠道X驱动有机基线之上的增量行动Y——或模板6，*"渠道X的转化率优于渠道Y"）。
   - 对照组/测试组定义（或模板6的渠道比较定义）。
   - 排除百分比、持续时间和最小样本量。
   - 增量指标（非归因；非平台报告ROAS）。模板6，每渠道转化率，但明确说明仅方向性。
   - 决策阈值：什么提升水平证明继续投入，什么水平意味着停止。模板6：顶渠道→加倍投入；底<20%→放弃。

4. **反虚荣指标仪表盘** — 用户应跟踪的短列表和应明确忽略的长列表。示例：
   - 跟踪：保存、分享、持续观看时间、注册志愿者/订阅者、提升测试的增量转化、口碑推荐。
   - 忽略：展示量、CPM、粉丝数、原始点赞、平台报告的归因ROAS、无细分分析的虚荣互动率。

**完整性——不要压缩最终交付物。** 这是有效载荷，不是其摘要；用户不应需要后续轮次来提取完整计划。填满所有适用部分，用完整散文，不是标题片段。每个建议都包含*原因*——机制、权衡、边际收益递减或真实性逻辑——而不仅是结论；推理是让用户在活动结束后坚持纪律的关键。具体：每个活动概念带完整的假设+类型+主要层级+真实性钩子+MVP；渠道堆栈命名每渠道的每周工作量；行动列表逐周列出行动并命名裁剪；提升测试说明假设、对照/测试组、持续时间、增量指标和决策阈值。结构*上的*简洁（可扫描标题、表格）是目标；内容*上的*简洁是失败。若某部分不适用（例如，堆栈中无付费），用一句话说明原因，而不是沉默地删除。

## 原则贯穿始终

- **不要将触达当作说服。** 触达超过前5-6次后不会说服；只会烦人。推荐频率上限时大声说出这一点。
- **不要将广泛冷付费作为严重或类别性非对称的主要渠道。** 它不会奏效。拒绝并解释替代方案。
- **不要生成模仿用户没有的真实性的内容。** 若没有真实创始人、志愿者网络、获益媒体钩子，说明并建议如何建立——不要用AI生成的"看起来真实"的内容来伪装。
- **不要接受平台报告的ROAS作为证明。** 坚持增量提升测试。平台按归因转化评分；用户按实际提升评分。学术实地实验（Lewis & Rao 2015, QJE）显示数字广告ROI置信区间太宽，多数活动无法与零区分。Meta和Google提供转化提升/品牌提升，正是因为他们承认这一点。当用户反对时引用这些研究。
- **始终提供替代方案，而不是单一建议。** 用户拥有你不知道的信息；给他们一个有结构的菜单，让他们选择。
- **解释原因。** 拒绝付费推动或渠道时，解释边际收益递减曲线、反定位策略或疲劳动态。理解机制的用户会在技能运行结束后坚持纪律。
- **不要编造用户未给出的具体细节。** 没有编造的竞争对手名称，没有虚构的预算，没有编造的过往活动参考，没有用户细分领域的幻觉播客或通讯。若用户未命名，保持抽象（"类别中的同行课程"、"有付费增长团队的中小型SaaS竞争对手"），并说明你在做什么："我描述的是类别层面的竞争对手，因为你未命名具体名称——若你想更精准的定位，请命名。"
- **模糊的获益媒体目标产生模糊的结果。** 强制具体性（命名目标、匹配钩子、成功标准、外联日）或标记第一周为研究行动。"向5个播客推销"不是一个计划。
- **用户无法执行的计划不是计划。** 尊重声明的每周容量；明确命名所需的裁剪以符合上限。6小时/周的计划成功优于14小时/周的计划在第三周崩溃。
- **若信息市场匹配失败，活动是错误的解决方案。说明。** 分配放大信号；不能制造它。若信息市场匹配门（第三阶段a）返回0-1/3，拒绝完整活动计划，并将用户路由到发现/验证循环。运行完整的Insurgent活动对抗一个有问题的产品会消耗志愿者、社区和创始人注意力的资本，这是剧本依赖的基础。
- **不要过度泛化匈牙利案例。** 当预条件存在时，自然流量优于付费饱和*：可信内部人士、积累的不满、整合的挑战者、感受到的痛苦、奖励系统的阈值、过度膨胀的现有者。缺少这些条件，剧本本身无法获胜——指出缺失条件并建议优先建立它们。
- **宣传和付费广告位于同一曲线。** 拉客农场、国家虚假信息、商业广告购买都操作于同一边际收益递减曲线，并在饱和时面临相同的真实性崩溃。你可以购买触达；你不能购买信念；超过阈值，购买更多触达会使信念更难。拉客农场没有消失——它们学会了这个教训并会适应（更小的网络、嵌入真实性、准社会模仿）。为适应的对手设计，而不是2020年的对手：依赖可验证的真实性（真实的人、真实的地方、真实的时间）、叙事连贯性和对手无法制造的真实来源信号，否则会被揭穿。

## 失败模式快速参考

每阶段合同的一页摘要。在审查输出时检查是否实际采取了声明的失败模式行动。

| 阶段 | 触发条件 | 必需操作 |
|---|---|---|
| 1 | 模式 C 下缺少始终捕获的字段 | 在问题批次中询问；不要静默使用默认值 |
| 1 | 缺失字段改变第 3 阶段 / 第 4 阶段结果 | 即使通常使用默认值，也升级到批次中处理 |
| 2 | 简报中未指名竞争对手 | 使用 `[在位者]` / 类别描述符；切勿凭空捏造 |
| 2 | 无法生成 5 个不同的原型 | 说明如此；展示已有内容；不要填充凑数 |
| 3 | 前置条件得分 0–2 | 拒绝完整战术手册；转向构建前置条件 |
