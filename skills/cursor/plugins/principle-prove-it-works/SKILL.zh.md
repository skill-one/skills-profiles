# 证明它有效

通过直接检查真实结果来验证每个任务输出。不要从代理、自我报告或“它能编译”中推断。

**原因：** 未验证的工作存在未知的正确性。间接验证（文件最后修改时间、输出新鲜度、代理自我报告、缓存截图）感觉比直接观察便宜。基于错误推断采取行动的成本远高于检查源代码。

检查真实结果，而不是代理：
- 直接检查进程活性，而不是通过派生状态间接检查
- 读取实际值，而不是缓存或派生的表示
- 当验证失败时，先怀疑观察方法，再怀疑系统

## 在可能的情况下编写检查脚本

最强的证明是一个可重复执行的确定性脚本，而不是一次性的肉眼检查。编写脚本，运行它，并保留其输出作为审阅者可以重新运行而不是相信你的话的工件。

保持工件对人类可见。仅对大型或复杂的工作进行提交，其中需要后续可审计的轨迹，例如大型移植或迁移（**展示你的工作**技能）。
