# 从聊天中提取工作流

从最近的聊天中推断持久的工作偏好。不要总结聊天内容；提取可重用的工作流指导。

## 范围

- 默认情况下，以最近7天为基准，除非用户要求不同的时间窗口。
- 读取父转录文本和相关子代理转录文本。将子代理内容作为证据使用，但仅引用父级对话。
- 不要暴露本地转录文本路径、密钥、客户数据、私密聊天内容或凭证。

## 工作流

1. 用一段话说明目标工作流或偏好界面。
2. 构建内部转录文本清单：标题/主题、父级对话ID、近似日期、完成状态、相关子代理，以及可能包含偏好证据的原因。
3. 搜索明确的偏好、更正和工作流标记，例如“我更喜欢”、“总是”、“从不”、“不是我问的”、“停止”、“审查”、“PR”、“CI”、“日志”和“技能”。
4. 提取偏好原子：触发器、工作流步骤、决策规则、质量标准、停止条件、证据和置信度。
5. 将置信度评级为强、中、弱或矛盾。
6. 按工作流形状而非转录文本进行聚类：运输、审查、简化、调试、捕获、沟通、委托或验证。
7. 选择工件：新技能、技能编辑、规则、工作流文档或无工件。
8. 仅起草可重用的指导。过滤掉那些不会帮助未来任务的故事。

## 置信度

- 强：明确的用户偏好、改变工作流的更正、重复的父级聊天模式，或直接请求编码行为。
- 中：接受的工性行为、重复的工具/模型/验证偏好，或子代理共识表明父级已成功使用。
- 弱：代理选择的行为且无用户反馈、一个模糊的转录文本，或一个可能的特定任务更正。
- 矛盾：证据指向不相容的方向；在编写文件前询问用户。

## 工件选择

- 技能：具有明确触发器的重复多步工作流。
- 规则：应广泛适用的通用行为。
- 工作流文档：有用的上下文，但不可靠地触发。
- 无工件：情境性、过时或低置信度的观察。

## 输出

首先返回简洁的综合：

- 目标工作流。
- 仅包含父级对话引用的证据语料库。
- 偏好配置文件。
- 采用、考虑、放弃。
- 提出的工件。
- 仅在阻塞编写时提出开放性问题。
