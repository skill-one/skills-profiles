# Swarm

并行启动 N 个云工作节点。它们可以覆盖不同的切片，参与相同的任务，或两者结合。父节点等待、聚合，并返回一份报告。

## 启动

在启动任何任务之前，打开一个待办事项列表，每个阶段对应一条记录。

1. 架构
2. 并行启动
3. 聚合
4. 报告

## 阶段 A：架构

1. 声明完成的条件（done predicate）以及集群必须返回的工件或报告。
2. 选择形状。将任务分割成切片，在相同任务上并行运行 N 个工作节点，或两者结合。对于竞赛或混合形状，在生成节点前声明 `首次通过`、`全部排名` 或 `最佳成绩`。
3. 从用户处设置 N，或根据形状推导出 N。N 是总工作节点数，不是云并发限制。
4. 从 `~/.cursor/rules/pstack-models.mdc` 中的 `swarm workers` 行选择工作节点模型。如果规则或该行缺失，使用 `grok-4.7-xhigh-fast`。对于 `auto` 或 `inherit-parent`，省略 `model` 以使工作节点运行在父节点模型上。如果任务工具拒绝一个 slug，使用默认值并说明。如果它拒绝默认值，根据错误信息使用同一系列的最近有效 slug。对于模型竞赛，提前命名每个分支的模型。
5. 当工作节点写入时，为其提供可写的输出。当工作节点验证或测量提交时，每个任务明确指定 SHA。测量任务还指定方法（样本数量、单个样本是什么、顺序）。工作节点在其结果中记录这两者。

## 阶段 B：并行启动

使用 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true` 和第 4 步的模型（对于 `auto` 或 `inherit-parent` 则省略），在一个消息中并行启动所有 N 个工作节点。仅当工作节点需要访问用户计算机上的内容时，使用 `environment: "local"`。

当工作节点必须从非默认推送分支启动时，传递 `cloud_base_branch`。

每个任务独立存在。包含目标、范围、具体切片或竞赛分支、验证方法以及报告内容。报告使用 `PASS`、`ISSUES` 或 `BLOCKED` 并附带证据。能够证明缺陷的工作节点报告 `ISSUES` 并列出它能证明的所有问题，而不仅仅是第一个。

如果工作节点退出，继续使用 N-1 个节点并记录该情况。

## 阶段 C：聚合

读取终端结果。丢弃未记录其任务指定的 SHA 和方法的结果，并重新运行该工作节点一次。第二次失败后，记录一次中断。中断不计为通过。对于覆盖率，每个必需切片都需要结果。对于竞赛，应用事先声明的选择规则。使用首次通过、全部排名或最佳成绩。不要粘贴原始工作节点输出。

保持一个紧凑的结果表格、一条线证据问题以及明确的中断或退出记录。

## 阶段 D：报告

返回一份聚合的聊天室报告，包含表格、问题简述、中断或退出记录，以及竞赛规则（如果使用）。
