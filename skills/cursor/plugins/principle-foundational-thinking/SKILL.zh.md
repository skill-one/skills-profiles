# 基础思维

**结构化决策**保护选择权价值。**代码级决策**保护简洁性。

**先考虑数据结构。**在编写逻辑之前，确保数据形态正确。尽早定义核心类型，追踪每种访问模式，并选择与主要路径匹配的结构。

在代码层面，应简化结构而非每一行。类型和数据模型应趋于一致。三个相似的语句仍然优于过早的抽象。优先选择明确而非巧妙的方案。测试行为和边界情况，而非行数。

**并发推论。**在角色之间共享状态之前，自问“如果另一个角色同时修改此状态会发生什么？”如果答案不是“无事发生”，则应隔离。

**先搭建框架。**如果某项工作有助于后续所有阶段，则应优先完成。自问“后续所有阶段是否都能从现有基础中获益？”持续集成、代码检查、测试基础设施和共享类型都是框架。按选择权价值排序：先搭建基础再开发功能，先测试再修复。保持提交记录小而单一目的。

每个增量都应落地一个连贯的抽象或深化现有抽象。不要将新功能分散到调用者中作为特殊情况的协调。

减法先于搭建框架。先移除死代码，再奠定基础。
