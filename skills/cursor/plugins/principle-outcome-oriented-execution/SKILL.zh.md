# 以结果为导向的执行

优化目标状态，而不是保留平滑的中间状态。

**原因：** 保持每个中间步骤完全稳定往往会产生长期兼容性代码，形成长期债务。收敛到目标架构，并在明确的验证边界处证明正确性。

**核心规则：**
- 优先考虑最终状态的完整性，而不是过渡稳定性
- 当它是计划、范围明确且可逆时，中间的破坏是可以接受的

**约束条件：**
- 用于具有明确阶段边界的计划重写和迁移
- 声明临时破坏可以接受的区域
- 在迁移过程中，为活跃修改区域保留高信号检查
- 在计划完成时，要求进行完整的静态和运行时验证
