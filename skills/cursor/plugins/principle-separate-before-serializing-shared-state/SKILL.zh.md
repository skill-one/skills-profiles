# 在序列化共享状态之前进行分离

当并发协程可能共享可变状态时，首先询问它们是否需要同一个可变对象。如果不需要，则消除共享。当共享确实是必要的时候，通过结构化方式强制序列化：锁文件、顺序阶段、独占所有权。指令和约定并不是并发控制。

**原因：** 对共享状态的并发写入会创建间歇性、难以复现且昂贵难以调试的竞态条件。

**模式：**
1. **识别共享的可变状态**（同时读取和写入的文件、同时推送的分支、同时定义和消费的API）。
2. **默认：消除共享写入目标。** 询问：这些协程是否需要一个规范对象，或者它们是在发布独立事实？给每个协程其自己的拥有文件、键、分支或状态目录，仅在读取/报告边界进行合并。两个协程各自将它们的`lastX`字段写入一个`state.json`仍然是共享变异。`indexer-state.json` + `metrics-state.json`则不是。
3. **只有当一个共享写入目标是真正的不变量时，才通过结构化方式序列化访问**（锁文件、顺序阶段、单一写入者协程，或原子比较并交换）。将“我们需要一个锁”视为需要检查的设计迹象，而不是默认答案。
