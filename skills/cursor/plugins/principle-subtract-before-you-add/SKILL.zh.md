# 先减后加

在演进系统时，先移除复杂性，再进行构建。

**原因：** 向复杂系统中添加内容会加剧复杂性。先移除复杂性可以减少代码量，揭示核心结构，并通常使下一步设计变得显而易见。默认采用移除策略。

将简化视为持续的投资。在相同或更小的表面上，留下比发现时稍显简单且功能更强大的设计。

**模式：**
- 在构建前先进行移除序列
- 先切割再打磨（在投资质量前达到最小化）
- 根据实际使用情况而非推测性边缘案例进行设计
- 除了规范要求之外，不添加推测性的验证器、解析器或守卫
- 简化提示（移除冗余指令、过度的模板）
- 当引用没有新内容时，删除它而不是留下一个占位符
