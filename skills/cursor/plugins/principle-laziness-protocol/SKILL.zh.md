# 懒惰协议

以最少的代码和复杂度实现最大的效果。

- **优先删除。** 当被要求重构或改进时，先考虑删除再考虑添加。
- **保持扁平的调用层级。** 避免深层的调用链。一个隐藏了大量工作的丰富接口并不是深层的调用链。如果回答一个问题需要追踪超过3个文件或层级，就将其扁平化。
- **整合决策。** 不要在多个地方重复同样的选择。将其放在一个单一的事实来源后面，并将结果作为一个简单的标志传递。
- **最小化差异。** 做最小的改变来解决问题。更少的行数胜过“优雅”的样板代码。
- **质疑线程。** 如果一个任务要求你通过类型、模式、管道或类似的层传递一个新的信号，停下来寻找更直接的路径。
- **关注小漏洞。** 在它们扩散之前，移除微小的中转、表示漏洞和重复的选择。小漏洞会累积成永久性的协调成本。

**测试：** 如果一个人类开发者会觉得代码难以维护，那么这就是一个糟糕的解决方案。
