# scroll-world

生成一个以**滚动驱动相机**为特点的着陆页：它从场景外部潜入其内部，然后飞出并进入下一个场景，持续进行，且无可见剪辑。视觉效果由人工智能生成——静态图像通过 Higgsfield（或 Codex）生成，视频链通过**Monid（默认）**生成（按片段付费的 Seedance 2.0；Higgsfield 信用额度作为备用）——页面仅通过滚动位置刮擦预渲染视频。这是苹果滚动式产品页面背后的相同技术——相机确实在移动，滚动仅驱动时间。

**您将生成的内容：** N 个场景静态图像 → N 个 "潜入" 相机片段 → N-1 个 "连接" 片段无缝连接连续场景 → 一个可移植的刮擦引擎，将整个链作为一次飞行播放。

**决定成败的一条规则：** 接缝必须 *帧完全一致*。在生成任何连接片段之前，请阅读 [无缝链](#step-5--无缝链-关键部分)。如果做得不对，这是最常见的失败，会在场景之间产生可见的 "弹出" 效果。

不要假设前端框架。`references/scrub-engine.js` 中的刮擦引擎是自包含的原生 JavaScript（它构建自己的 DOM + 将自己的 CSS 注入您给它的容器中），因此它可以无缝集成到纯 HTML、Next.js、Vue、Python 服务的页面中，任何东西都可以。这项技能的价值在于 Higgsfield 管道、提示和接缝方法——而不是框架。

## Step 0 — 初始化

1. **Monid CLI — 默认的视频链后端。** 检查 `monid --version`、`monid keys list`（活动密钥）和 `monid balance`——链按片段计费，单位为美元（Step 1.7 有具体数字；1080p N=6 链约 $27）。如果 CLI 缺失或余额不足以覆盖链，请说明并回退到使用 Higgsfield 信用额度渲染链——相同模型，相同管道，不同的账单方（Step 4 → Monid 后端）。
2. **Higgsfield CLI — 即使在 Monid 路径上也需要：** 它渲染场景静态图像（`gpt_image_2`）并包含 `kling3_0` NSFW 备用方案和备用链。如果 `higgsfield` 不在 `$PATH` 中，请按照 `higgsfield-generate` 技能的说明进行安装。如果 `higgsfield workspace list` 失败验证，请要求用户运行 `higgsfield auth login`（交互式 OAuth —— 您无法运行它），如果需要，`higgsfield workspace set <id>`。确认信用额度足够覆盖静态图像（~N 次图像生成）——如果链回退到这里，还需要 `(2N-1)` 次视频生成。
3. **ffmpeg / ffprobe** 在 `$PATH` 上（帧提取 + 编码）。
4. **图像工具** 用于背景抠图，如果您想使场景漂浮：PIL（`python3 -c "import PIL"`），或 `cwebp`/`sips`。可选——见 Step 3。
5. **(可选) Codex CLI** — 如果 `codex` 在 `$PATH` 上（≥ 0.125）且 `codex login status` 报告 ChatGPT 登录，场景静态图像可以通过 Codex 的内置 `image_gen` 生成（相同的 gpt-image-2 模型），费用记入用户的 ChatGPT 订阅，而不是 Higgsfield 信用额度——在 Step 1.7 提供此选项，命令在 Step 2 中使用。不存在则仅移除此选项。
6. 注意事项：macOS 预装 **bash 3.2**（没有 `declare -A`）；脚本中不要使用关联数组。Higgsfield 生成需要 **3–8 分钟**——始终在后台运行并轮询，不要使用阻塞的前台调用。通过作业 UUID 引用被媒体标志拒绝——传递 **本地文件路径** 到 `--image/--start-image/--end-image`。视频模型在接受的参数上不同（例如 Kling 没有参数 `--resolution`），并且在是否支持 start/end-image 条件化上不同——在批处理之前，通过 `higgsfield model get <job_type>` 确认所选模型的架构，并查看 Step 4 模型表。

## Step 1 — 访问用户

主题由用户自行陈述——以纯文本形式作为开放式问题提出，切勿使用虚构的选项列表。虚构的行业列表会引导用户，并读起来像您在替他们决定业务；让他们用自己的话回答（他们的真实业务、客户的业务或任何想法）。保留结构化的选项列表（Claude Code 中的 `AskUserQuestion`；其他地方的纯是/否问题）用于以下真正可枚举、低风险的选择——艺术方向、相机风格和品牌套件方法——即使在那里，也要提示他们可以自行决定（"其他"）。仅询问您无法合理默认的问题。涵盖：

1. **主题**（开放式提问，非选项列表）——"这个世界应该是什么主题？您的业务、客户的业务或任何想法——一个词或一句话都可以。" 捕获行业/产品 + 一行简短介绍（例如："一家珍珠奶茶公司，从茶叶到最后一口"），如果有品牌名称也请提供；否则您将在下面提出一个。
2. **品牌套件**——提供三种路径，选择一种：
   - 从 URL 导入：`higgsfield marketing-studio brand-kits fetch --url <site> --wait`（拉取名称、颜色、语气）。然后使用 `brand-kits list --json` 读取回。
   - 用户直接提供调色板 + 名称 + 语气。
   - 您提出调色板 + 名称并让他们批准。
   捕获 **4–6 个命名十六进制值**、一个显示名称和几个语气词。
3. **艺术方向**——默认是 "软磨砂低多边形 **粘土场景**、等距、倾斜位移微缩模型、暖光。" 提供替代方案（平面纸艺、光泽玩具、粘土动画、霓虹夜）。无论选择什么，都将成为共享的 **风格前缀**，在每个场景提示中逐字重复（这就是世界保持一致的原因）。
4. **相机风格——始终询问；这是电影的个性，不是技术细节。** 通过感觉提问（Claude Code 中的 `AskUserQuestion`；其他地方的纯问题）并记录答案为 `CAMERA`。选项映射到 Step 4 的架构——Step 4 然后实现该选择，它永远不会重新决定它：
   - **"飞越世界"**——相机潜入每个场景，拉起并飞出，跳过微缩世界到下一个场景；角度不断变化，大而富有表现力的空中动作（这是旗舰演示的外观）→ 架构 B。建议将其作为场景/微缩艺术方向的默认选项。
   - **"连续漫游"**——单个向前飞行，滑过每个场景直接进入下一个场景，永不拉回；每个场景都有表现力但始终向前移动（相机语法表）→ 架构 A。建议将其作为接地/照片真实艺术方向的默认选项。
   - **"锁定等距滑行"**——相机在整个电影中保持一个固定角度，Emons 风格；世界滑过/朝它移动，没有旋转，没有揭示。→ 架构 A + 每个片段提示中的锁定等距子句（prompts.md）。
   每行说明权衡（B 在接缝处反转方向——在微缩模型中迷人，在现实主义中令人震惊；锁定等距是最平静且重新录制成本最低的；漫游介于两者之间）。
5. **旅程（部分）**——相机飞过的有序场景。建议一套来自主题自身价值链的，并让用户编辑。5–7 个效果很好。
   Boba 示例：农场 → 珍珠厨房 → 旗舰店 → 配送 → 社区广场 → 英雄产品。每个部分需要：一个简短的主体描述（场景中的内容）、一个眉题、一个标题、一行正文和 0–3 个标签药丸。最后一个部分通常是英雄产品 + CTA。
6. **移动版本——始终询问；切勿无声生成两个。** 作为一个两选项选择提问（Claude Code 中的 `AskUserQuestion`；其他地方的纯问题）：
   *"想要移动优化的版本吗？移动版本是原生 9:16 竖屏渲染的第二相机链——为手机设计，而不是景观电影的裁剪——这大约会使 Higgsfield 信用额度花费翻倍（说明估计数量)."*
   选项："仅桌面" / "桌面 + 移动（原生 9:16 — ~2× 信用额度）"。信用额度成本必须告知用户，而不仅仅是暗示。
   答案控制：
   - **是** → 渲染并作为移动变体发送平行的 9:16 竖屏链（Step 6 / pipeline.md §6b）：竖屏起始画布 → 9:16 潜入 + 连接片段帧锁定对其自己的渲染 → 720 宽 `-m.mp4` 编码 → `stillMobile` 竖屏海报。连接 `clipMobile`/`connectorsMobile`/`stillMobile`（Step 7）；运行完整的移动 QA（Step 8）。预算 ~2N-1 额外的视频生成 + NSFW 重新录制。
     **切勿默认发送中心裁剪作为移动版本**——如果信用额度不足以覆盖竖屏链，请说明并提供标记为临时解决方案的裁剪编码（pipeline.md §6）供用户批准。
   - **否** → 完全跳过移动编码和连接。
     引擎的手机硬化（seek-coalescing、iOS 初始化、安全区域 CSS）始终开启——这不是 "移动版本"，只是当手机访问时页面不会崩溃——因此桌面仅构建仍然优雅地降级。

7. **预算——引擎按成本显示，在渲染之前决定。** 提供渲染层级（`AskUserQuestion`），然后计算并声明用户 N 个场景的估计总成本——`N 静态图像 + (2N−1) 视频 [视频 ×2 如果移动] + ~15% 重新录制缓冲区`——并获得批准之前渲染。
   - **视频层级**（仅名册——每个选项帧锁定接缝，Step 4）：

     | 层级 | 模型 | 粗略成本 |
     |---|---|---|
     | 草稿 / 预演 | `seedance_2_0_mini` (720p) | ~¼ 标准成本 |
     | 标准（默认） | `seedance_2_0` (1080p) | 基线 |
     | 替代 | `kling3_0` (720p 原生) | ≈ 标准；不同外观 + 内容过滤器 |

     草稿也用作预演路径：以低成本运行整个链，批准旅程，然后在标准上重新渲染最终片段（pipeline.md 注释）——建议在余额紧张时未经提示提供。
   - **后端**——Monid 是链的默认账单方（Step 0.1；在 pipeline.md 中连接到 Monid 后端）。相同的 Seedance 2.0，按片段计费，单位为美元，而不是信用额度。按 `width × height × 24 × seconds / 1024` 定价，$7/1M（480p/720p）或 $7.7/1M（1080p）——测量：1080p 8 秒潜入 ≈ $2.99，5 秒连接 ≈ $1.87；720p ≈ $1.21 / $0.76；480p ≈ $0.28 / $0.35。N=6 桌面链在 1080p 约为 $27，720p 约为 ~$11，与 Higgsfield Plus 月度订阅 ≈ $32 / $16 相比——每个片段约便宜 15%，与 Plus 年度相当；对于一次性构建，结构上更好（按使用付费，无月度到期）。在 Monid 上，草稿/预演层级只是 480p 的 **相同端点**——没有模型切换，因此预演→最终始终由构造保持为单模型。对比 `monid balance` 与估计；**回退到 Higgsfield 信用额度**（上述按模型层级）当用户更喜欢他们的订阅、余额不足或模型必须是 `kling3_0`（Higgsfield 仅限）时。它是相同的基本模型（`seedance_2_0` ≙ Monid 的 `seedance-2.0`），因此完成被遗弃的链在另一个账单方是合理的救援——但服务堆栈不同，跨提供商的接缝特征是 **未经测试**：在渲染其余部分之前，仔细检查第一个救援接缝，与任何模型切换相同。
   - **静态图像来源**（仅当 Codex CLI 存在时 Step 0.5 提供）：
     Higgsfield `gpt_image_2`（花费信用额度）与 **Codex `image_gen`**——相同的 gpt-image-2 模型记入 ChatGPT 订阅（零信用额度；计入 Codex 使用限制；1536×1024 输出——正好 3:2，略低于 Higgsfield 的 2k）。静态图像是纯 PNG，传递给 `--start-image`，因此视频链对其来源无关紧要。命令在 Step 2 中使用。**一个构建的 N 个静态图像的来源**——两个渲染具有略微不同的特征（验证：Codex 运行较暖/较冷），并且跨场景混合来源被视为风格漂移，相同原因视频链使用一个模型。
   - **校准成本，不要猜测。** CLI 不暴露定价，计划不同。首先运行一个静态图像和一个视频，diff `higgsfield workspace list` 之前/之后，推算到完整运行，并在估计超过余额约 70% 时警告用户。（在 2026-07 的 Plus 计划上观察到：标准视频 ≈ 40–55 信用额度，静态图像 ≈ 15。）运行中出现的真实 `not_enough_credits` 是可以恢复的（完成的片段幸存；充值后恢复），但很丑——这个步骤的整个点就是用户在花费之前决定。

如果用户指定了名册外的视频模型，仅当它能够帧锁定接缝时才接受它（Step 4）。这项技能仅提供无缝输出，因此无法帧锁定模型将被拒绝，并附上一行原因，而不是替换——使用名册模型。

保持滚动机制固定（连续飞越）——这是这项技能的重点。参见 `references/prompts.md` 获取摄入清单和复制结构。

## Step 2 — 生成场景静态图像

每个部分一个图像，**所有图像共享相同的风格前缀**以确保连贯性。默认模型 **`gpt_image_2`**（清晰，非常适合等距插图；返回纯色/白色背景，非常适合漂浮的微缩场景 "岛屿"）。仅在简报是角色/卡通为主时使用 `nano_banana_2`（注意：`nano_banana_2` 是 CLI 别名——它解析为 `nano_banana_pro`；它不会以该名称出现在 `higgsfield model list` 中）。

提示形状（参考资料在 `references/prompts.md` 中）：

```
<风格前缀，每次都相同>. 在一个纯色 <bg> 背景上带有柔和接触阴影。 <调色板十六进制值>. 无文本、无字母、无标志，居中，3:2.
主题：<这个场景中有什么>.
```

- 同时运行所有 N 个，后台运行。每个场景的命令：
  `higgsfield generate create gpt_image_2 --prompt "$(cat scene_i.txt)" --aspect_ratio 3:2 --resolution 2k --quality high --wait --wait-timeout 15m --json > scene_i.json 2>scene_i.err`
- 结果 URL 是 `--wait --json` 输出中的 `.[]0.result_url`。用 `curl` 下载它。
- **Codex 静态图像变体**（如果在 Step 1.7 中选择——订阅计费，零信用额度）：相同的提示文件，相同的字节完全相同的前缀，由 Codex 的内置 `image_gen` 生成：

  ```bash
  codex exec -C "$WORK" -s workspace-write --skip-git-repo-check \
    '使用图像生成工具 ($imagegen) 生成：'"$(cat "$WORK/still_i.txt")"' 宽 3:2 竖屏，高分辨率。保存为 ./still_i.png。不要做任何其他事情.' \
    < /dev/null
  ```

  单引号 `$imagegen` 段（外壳不能展开它）；如果使用参考图像进行编辑，提示在 `-i` 标志之前（它是可变长的）。
  ~1–3 分钟每个图像；不要一次运行所有 N 个——并保持 `< /dev/null`：并行 `codex exec` 调用共享脚本的 stdin 挂起等待输入（Gotchas）。输出位于
  1536×1024 (3:2) — 对 `--start-image` 和海报很好。下游所有内容（连贯性审查、抠图、潜入）都保持不变。
- 生成可能暂时失败（HTTP 503）——单独重新录制那个——不要重新启动整个批次。
- **在继续之前审查静态图像。** 它们必须读起来像一个连贯的世界（相同角度、调色板、光线）。如果有一个不符合风格，请重新录制它，可以选择传递一个批准的场景作为 `--image` 来锁定风格。

参见 `references/pipeline.md` 获取确切的批处理脚本。

## Step 3 — (可选) 使场景漂浮

如果您想让微缩场景在氛围背景上漂浮，而不是坐在一个实心盒子中，请使用 `references/knockout.py` 将平面背景抠出透明——边界连接的洪水填充——保留与背景匹配的内部颜色（例如，奶油色墙壁）。然后编码为 webp。如果您宁愿保持简单，只需将页面背景设置为与场景背景相同的颜色并跳过此步骤。

这些静态图像也用作 **视频海报和懒加载备用**，因此请保留它们。

## Step 4 — 相机架构（实现 Step 1.4 的选择）

如何在不同场景之间移动相机是影响质量的最关键因素。用户在面试中已经选择了风格（`CAMERA`，步骤 1.4）：飞越 → **B**，行走 → **A**，锁定-ISO → **A + 锁定-ISO 腿条款**（prompts.md）。如果面试以某种方式跳过了这一步，现在要询问——永远不要替他们默默选择。这两种形状及其着色的语法：

### 视频模型——为整个链选择一个

**这项技能只提供无缝输出**，因此唯一可用的模型是那些能够进行接缝锁定的模型：每个链接的片段都必须接受 `--start-image`，连接器也需要 `--end-image`。这种能力——而不是偏好——是选择规则。检查任何使用 `higgsfield model get <job_type>` 的模型，并**跳过媒体输入仅作参考的任何内容**（没有起始/结束图像）：它只能*条件化*生成，而不能*继续*镜头，因此它实际上无法保持接缝。下面的模式已针对 CLI 进行确认：

| 模型 | 起始/结束图像 | 备注 |
|---|---|---|
| `seedance_2_0`（默认） | ✓ / ✓ | 完整链（腿+连接器）。`--mode std --resolution 1080p`。它的 NSFW 过滤器是敏感的（见 Gotchas）。 |
| `kling3_0` | ✓ / ✓ | 完整链——测试：`--mode std --sound off --duration 5` 接受起始+结束图像，接缝干净地帧锁定。**没有 `--resolution` 参数**（不要传递一个；`--mode std` 返回 **720p 原生**——根据 ffprobe 报告编码，不要放大）。声音默认**开启** → `--sound off`。`--duration` 默认 5，腿尝试 10。与 Seedance 不同的内容过滤器——官方 NSFW 备用。 |
| `seedance_2_0_mini` | ✓ / ✓ | 廉价草稿层级，保持帧锁定（720p）。预览层级：首先在此处运行整个链，然后在完整模型上重新渲染最终腿——仍然无缝，因此可以直接转换。 |

这三个是阵容——所有模型都支持两种架构。(`kling3_0_turbo` 也通过 `--start-image` 帧锁定，但没有 `--end-image`，因此仅限架构 A，不能制作连接器；它也使用不同的标志集——没有 `--mode`，有 `--resolution`，因此它不能直接进入管道。它不在默认阵容中；只有当架构 A 的顺序渲染时间被证明是瓶颈，并且您已将其基准测试为实际更快时，才需要它，并手动连接它。）

还有一个仅限架构 A 的候选者，值得了解，因为它远比其他模型便宜：**`minimax_hailuo`**（Hailuo-2.3，每个 768p/6s 片约 6 信用 vs 22–72 信用）。2026-07 验证：`--start-image` + 提示帧锁定（输出帧 0 ≡ 输入，PSNR 33 dB），并服从正向滑翔提示，温和地。限制：2.3 变体拒绝 `end_image`（没有连接器 → 仅限架构 A），输出纵横比跟随输入图像（给它一个 16:9 画布，而不是裸 3:2 静态），运动比 Seedance 更微妙，并且不要传递 `--resolution`（CLI 错误地类型化了枚举；768 默认工作——1080 仅支持 6 秒）。一个片段≠一个链：在押注完整构建之前，先确认腿到腿的交接资格。

规则：
- **所有链接片段使用一个模型。** 每个渲染器都有其独特的运动/颜色/颗粒特征；在链中混合模型保持*位置*连续性（帧仍然交接），但渲染特征变化读作轻微的弹出。唯一特许的例外是单个顽固片段的 NSFW 备用（Gotchas）——一个 5 秒连接器的轻微特征变化胜过缺少连接器。
- 默认使用 `seedance_2_0`，通过默认的 **Monid** 渲染（每片段 USD — 下一个部分）使用 Higgsfield 信用作为备用账单（步骤 0.1/1.6）；如果模型合格（帧锁定），则尊重用户的明确偏好。如果不合格，请说明并使用支持的模型——永远不要为了满足模型请求而发送非无缝构建。`kling3_0` 和 `seedance_2_0_mini` 仅在 Higgsfield 端存在。 |
- 管道脚本将模型作为 `$VMODEL` 传递，并已为每个模型设置标志（`references/pipeline.md`）。

### Monid 后端——默认的链账单（合格于 2026-07-25）

Monid 的 **`bytedance /v1/video/seedance-2.0`** 于 2026-07-25 通过了两个付费测试，并且是此技能渲染链的**默认方式**，适用于**两种架构**——它是阵容的 `seedance_2_0` 以美元计费（在 pipeline.md 中连接为“Monid 后端”；Higgsfield 仅作为备用账单或仅限 Higgsfield 的模型渲染链）：

- **腿测试**（提示 + `first_frame` 图像）：输出帧 0 ≡ 输入静态（PSNR 31.6 dB），服从正向滑翔提示，账单为宣传单元（$0.279 / 480p 4s）。
- **连接器测试**（提示 + `first_frame` + `last_frame`）：起始锁定（31.6 dB）；结束**接近但不完全像素完美**（27.5 dB，相同构图，道具级漂移）——Seedance 在 Higgsfield 上显示的确切结束图像行为，由引擎的接缝淡入淡出和下一个深潜的实际第一帧作为结束图像（步骤 5 法则，未更改）。

I/O 合同与 Higgsfield CLI 不同——三个规则：

1. **图像通过 URL 传递，绝不内联。** `content` 项目是 `{"type":"image_url","image_url":{"url":…},"role":"first_frame"|"last_frame"}`；base64 数据 URL 被**拒绝**（“必须是公共 https:// URL 或 asset://<id> 引用”）。本地帧通过 Monid 的免费工作空间文件系统传输：`sfs /put` → `curl -T` 字节 → `sfs /cat` 返回一个签名的公共 URL 以粘贴到正文（$0，明确构建用于此）。
2. **明确传递 `ratio`** (`16:9`，或 `9:16` 用于移动链）——自适应默认跟随输入图像的纵横比。
3. **每个片段都进行账单检查**：成本是标记定价（`w × h × 24 × sec / 1024` 在 $7–7.7/1M）；从每次运行中读取 `cost.value`。

塑造这些规则的背景（截至 2026-07-25 仍然有效）：Seedance 端点直到 2026 年 7 月下旬才支持文本到视频——**在每次构建前重新 `inspect`；目录双向移动。** `minimax /v1/video_generation`（Hailuo-2.3）仍然被取消资格：发送 `prompt` + `first_frame_image` 一起会无声地丢弃图像（无关的 t2v 输出，错误的价格单元）；仅图像帧锁定（33 dB），但没有相机控制。

**任何新/更改的 Monid 端点的合格协议**（每个测试是一个廉价的 480p 片）：（1）提示 + 来自真实静态的第一帧——帧 0 必须与输入到编解码器噪声匹配（PSNR ≳ 30 dB）并且 `cost.value` 必须与宣传单元匹配；（2）对于连接器任务，添加来自不同静态的 `last_frame`——结束必须落在该构图上（Seedance 风格的近似值可以，淡入淡出覆盖它）。通过 → 按片段计费层级（如果起始仅限架构 A；如果起始+结束则为完整阵容）。

### A) 连续正向拍摄——推荐用于接地/写实/行走
只有一个相机，它只向前移动，从第一场景到最后一个场景，作为一个单一拍摄。按顺序生成腿：腿 0 来自场景 0 的静态（向前滑入它）；然后每个腿的 `--start-image` = **前一个腿的实际最后一帧**（使用 ffmpeg 提取），提示 *"平稳顺畅地向前滑入 [场景 i]，永不拉回"*（或在运动交接合同下进行一个表达性的中间腿移动——见 **相机语法** 下），并且**没有 `--end-image`**——一个宽景深建立镜头的结束图像迫使相机拉回，这是导致卡顿的首要原因。提取每个腿的最后一帧以供下一个使用。结果：每个接缝都是帧相同的**并且**相机永不反转。没有**连接器**（跳过步骤 5）——腿本身就是旅程。将每个腿作为带 `connectors: []` 和小 `crossfade` (~0.08) 的部分片段连接。即使没有 `--end-image`，腿仍然到达不同的房间（提示引导内容）。成本：严格**按顺序**（不能并行化）并且更慢；内部触发 NSFW 过滤器，因此构建中需要重试（每个腿 3 次尝试）。

### B) 潜入+空中连接器——仅适用于场景/微缩模型/上帝之眼世界
一个“潜入每个场景”的片段 + 一个向上拉出并飞向下一个场景的连接器（步骤 5）。拉出**在每次接缝处反转相机方向**（向前潜入 → 向后拉出）。在一个微缩/场景世界中，它读作一个有意“缩出到地图，飞到下一个岛屿”；在一个接地第一人称行走中，它读作一个**令人震惊的回放/卡顿**。仅用于地图式美学——这正是“飞越世界”面试答案选择进入的；反转读作有意。如果用户选择 B 而对接地/照片真实方向，请说明它将读作卡顿，并在渲染前确认。

### 相机语法——动作应符合概念（A 不是“仅向前”）

“仅向前”是*接缝*规则，不是*腿*规则。链的物理：

- **位置连续性** 在接缝处来自帧交接（下一个腿从前一个腿的实际最后一帧开始）。
- **速度连续性** 在接缝处意味着相机永不*跨接缝反转*——这是回放卡顿。
- **在单个腿内相机是自由的。** 一个腿是一个连续渲染——在腿中没有任何接缝可以打破，因此轨道、摇臂上升、横向跟踪，甚至一个推入然后缓慢拉出的动作在*片段内*都是安全的。反转只在*跨接缝*时致命。

因此，为每个腿选择一个来自场景自身逻辑的表达性动作，在**运动交接合同**下：每个腿**都以缓慢、稳定的前向漂移结束**朝向下一个目的地（最后 ~1 s），并且每个腿**都以继续相同漂移开始**。在提示中保持两个条款的原文（`references/prompts.md` 中的模板）。

从概念中选择语法：

| 概念/语气 | 中间腿动作 |
|---|---|
| 产品/奢侈品零售 | 缓慢围绕英雄对象进行半轨道，然后继续经过它 |
| 房地产/酒店 | 通过门廊的 Steadicam 滑动；中庭中轻柔的摇臂上升 |
| 工业/流程/物流 | 沿线低横向跟踪，前景视差 |
| 旅行/户外/校园 | 飞机式上升和揭示，然后下降盘旋 |
| 食物/手工艺/细节驱动 | 推近手工艺时刻，缓慢拉回，继续 |
| 欢乐微缩模型（架构 B） | 潜入+空中跳跃——连接器就是语法 |

诚实成本：表达性中间腿动作提高重试几率——模型可以在一个复杂的动作结束时处于一个不是干净前向漂移的状态。缓解措施：保持最后秒的稳定条款；**仔细检查每个腿的最后一帧**再连接下一个（它应该看起来像一个温和前向漂移的帧——如果不是，则在浪费下一个腿之前重试）；预算约 1 次额外重试每表达性腿。一个简单的向前漂移保持零风险默认值——用于场景本身是主角的腿。

**锁定-ISO 变体**（`CAMERA` = 锁定等距滑翔）：架构 A 中每个腿都锁定视角而不是进行中间腿移动——“相机在整个过程中保持完全相同的高等距角度，不旋转，不轨道，不倾斜；它只直线水平移动，世界从同一视角滑过下方”（prompts.md 中的原文条款）。交接合同保持不变。Seedance 在长腿上轻微漂移角度——现有的检查每个最后一帧规则是关键；重试一个视角已旋转的腿。最平静的外观，最便宜的重试，并且最接近 Emons 参考。

引擎中有两个相关的节奏旋钮存在于步骤 7：每部分的 `scroll`（滚动距离更长 = 在该场景中停留时间更长）和 `linger`（相机在场景中正好在副本峰值时稳定，然后加速朝向接缝）。倾向于片段中的表达性动作和* scrub mapping* 中的克制——它们会叠加。

记住滚动是一个 scrubber：访客可以向上滚动，因此每个动作也以相反方向播放。这是免费且预期的——没有额外工作——但它又是另一个原因，接缝速度在两个方向上必须一致（一个向前读得好的接缝，如果速度反转，向后也读作卡顿）。

**对于 B**，每个场景一个相机飞行：从高空/外部开始，下降进入内部，结构打开。模型：上面选择的链模型（默认 **`seedance_2_0`**），`--start-image = 场景静态`。

- 使用**实心背景静态**（不是被挖空的透明一个）作为起始图像，以便视频有一个完整帧。
- 提示："单个连续电影相机动作，无剪辑。从外部开始，从高处远距离看着整个 <场景> … 下降并飞入内部朝向 <焦点> … 屋顶/墙壁轻轻打开以揭示内部。<风格>，平滑优雅的慢动作。无文字。"（`references/prompts.md` 中的模板。）
- 参数（seedance）：`--mode std --resolution 1080p --aspect_ratio 16:9 --duration 8`。对于 Kling：删除 `--resolution`（没有此参数），添加 `--sound off`，`--duration 10`。**不要传递 `--generate-audio`**（它在 seedance 上出错；音频是浪费的——你会静音）。
- 并行运行，分离，然后下载每个 `.result_url`。重试单个失败。保留原始 1080p 源——您需要它们的帧下一个部分。

## 步骤 5 — 连接器（仅限架构 B）

对于架构 **A** 跳过整个步骤——连续拍摄没有连接器；它的腿已经无缝连接。此步骤适用于 **B**（场景/微缩模型），并注意步骤 4 中的反转警告。

连接器片段使世界感觉*连接*而不是切割。一个连接器从场景 i 的末尾飞出并进入场景 i+1 的开始。**它的两个端点都必须是相邻片段的实际渲染帧——绝不使用原始场景静态。**

原因：每个 Higgsfield 生成渲染略有不同。如果一个连接器*结束*在“厨房场景”的新渲染上，但下一个潜入片段*开始*在它自己的不同渲染的同一场景上，两者不会匹配，在接缝处会出现弹出。解决方法是传递确切的像素：

```
对于 dive_i 和 dive_{i+1} 之间的每个连接器：
  start-image = 从 dive_i 渲染的视频中提取的最后一个帧
  end-image   = 从 dive_{i+1} 渲染的视频中提取的第一个帧
```

现在每个接缝在*两边*都是帧相同的：
`dive_i.end == connector.start` 和 `connector.end == dive_{i+1}.start`。

从渲染的潜入中提取边界帧（不是静态）：

```bash
ffmpeg -sseof -0.15 -i dive_i.mp4   -frames:v 1 -q:v 2 dive_i_last.png    # i 的内部
ffmpeg -ss 0      -i dive_{i+1}.mp4 -frames:v 1 -q:v 2 dive_next_first.png # i+1 的建立
```

生成连接器（`--duration 5` 足够）。连接器需要 `--end-image`，因此模型必须接受它——任何阵容模型都可以（`seedance_2_0`，`seedance_2_0_mini`，`kling3_0`）：

```bash
higgsfield generate create "$VMODEL" \
  --prompt "$(cat connector_i.txt)" \
  --start-image dive_i_last.png --end-image dive_next_first.png \
  $VOPTS --aspect_ratio 16:9 --duration 5 --wait --json
# seedance: VOPTS="--mode std --resolution 1080p"; kling3_0: VOPTS="--mode std --sound off"
```

连接器提示："单个连续相机动作，无剪辑。从 <场景 i> 中向上拉出并拉出，飞入天空，滑过连接的微缩世界，并到达上方 <场景 i+1>，开始向它下降。无缝流动的空中过渡。<风格>。无文字。"（`references/prompts.md` 中的模板。）

保险：Seedance 接近结束图像但并非总是像素完美，因此引擎仍然在每个接缝处应用**短淡入淡出**（几帧）。帧匹配的端点+小淡入淡出=无可见切割。永远不要跳过实际帧交接并仅依赖淡入淡出；一个大的内容跳跃无法被淡入淡出隐藏。

1. **可搜索性，而非关键帧密度，才是使快进功能起作用的关键。** 许多静态主机（以及 `python -m http.server`）不提供 HTTP 字节范围请求服务，这使得 `video.seekable` 被固定为 `[0,0]` 并将所有快进操作都钳制在帧 0 上——视频看起来像是冻结的。稳健的修复方法是**将每个片段作为 `Blob` 获取，并从内存中的对象 URL 播放**（blobs 总是可完全搜索的）。引擎会执行此操作。由于这个原因，您**不需要**全帧内视频。
2. **不要为了获得平滑的快进而牺牲质量。** 在**原生分辨率**下编码（Seedance 的 1080p，不要下采样），`crf ~20`，一个**小的 GOP**（`-g 8`）而不是全帧内（全帧内会使 8 秒的片段膨胀到约 25 MB；GOP 8 大约是 8 MB，通过 blob 可以很好地进行快进）。剥离音频，添加快速启动，并使用轻微的 `unsharp` 来抵消视频的柔和感：

```bash
ffmpeg -i src.mp4 -an -vf "unsharp=5:5:0.8:5:5:0.0" \
  -c:v libx264 -preset slow -crf 20 -pix_fmt yuv420p \
  -g 8 -keyint_min 8 -sc_threshold 0 -movflags +faststart out.mp4
```

使用相同的设置对所有 2N-1 个片段（下潜 + 连接器）进行编码，以获得统一的视频质量。

**移动端编码（仅当用户在步骤 1.6 中选择加入时）。** 移动版本是**原生的 9:16 竖屏链**（pipeline.md §6b）：每个下潜和连接器的竖屏渲染，编码**宽度为 720 (`scale=720:-2`), `-g 4`**（更多关键帧 = 更便宜的快进——手机解码器的快进成本与 GOP 长度成正比），crf 23——作为 `clipMobile` / `connectorsMobile` 编排，并将每个竖屏下潜的第一帧提取为部分的 `stillMobile` 海报（步骤 7）。引擎会自动在手机上提供它们，并在缺失时回退到桌面片段。16:9 中心裁剪的 `encm()` 编码（pipeline.md §6）是**仅作为回退**——当字幕无法覆盖竖屏链时——并且必须明确告知用户发送它们，永远不要静默。如果用户选择了仅桌面版，请跳过此步骤——引擎仍然会通过快进合并和 iOS 初始化来硬化手机快进，因此页面会优雅地降级而不是崩溃。

## 步骤 7 — 组装页面

将 `references/scrub-engine.js`（如果您想创建一个完全独立的页面，还可以将微小的 `references/index-template.html`）复制到用户的项目中——或者将其适配到他们的框架中。它是配置驱动且自包含的：

```js
mountScrollWorld(document.getElementById('world'), {
  brand: { name: 'Pearl & Co.' },
  diveScroll: 1.3, connScroll: 0.9,          // 每个片段的滚动视口高度
  sections: [
    { id:'farm', label:'The Farms', still:'assets/farm.webp',
      clip:'assets/vid/farm.mp4',
      clipMobile:'assets/vid/farm-m.mp4',      // 仅移动端选择加入：原生 9:16 渲染
      stillMobile:'assets/farm-m.webp',        // 其第一帧作为竖屏海报
      scroll: 1.6, linger: 0.45,   // 可选的节奏：更长的停留 + 摄像头在场景中居中稳定
      accent:'#8FB98A', eyebrow:'From leaf to last sip', title:'It starts in the hills.',
      body:'…', tags:['Single-origin','Hand-picked'] },
    // …每个部分一个；最后一个可能包含 `cta`
  ],
  connectors:       ['assets/vid/conn1.mp4','assets/vid/conn2.mp4',   /* … 长度 = sections-1 */],
  connectorsMobile: ['assets/vid/conn1-m.mp4','assets/vid/conn2-m.mp4' /* … 相同长度；仅移动端选择加入 */],
});
```

引擎处理：有序的下潜/连接器链、滚动→currentTime 使用 rAF 平滑、blob 加载、附近片段的懒预取、帧匹配的交叉淡入淡出、每个部分的固定（第一个部分在着陆时问候，最后一个部分保留其 CTA）、路线轨道、`prefers-reduced-motion` 和移动端。**每个部分的节奏：** `scroll` 覆盖 `diveScroll` 以该场景（滚动更多 = 更长的停留）和 `linger`（0–1，保持 ≤ 0.6）重新映射时间，使摄像头在场景中居中稳定——正好在文案达到峰值时——然后加速接近接缝；接缝帧保持不变（f(0)=0, f(1)=1）。给英雄和结尾场景一个更高的 `scroll` + 一些 `linger`；保持过渡场景快速。使用 CSS 变量（`--accent`, `--sw-bg`, `--sw-ink`, …）进行主题化——视觉标识来自生成的片段，因此边框保持安静。有关完整配置 + CSS 变量的信息，请参阅 `scrub-engine.js` 的标题。

**在手机上，引擎会自动适应**（粗指针或 ≤860px）：当存在时，它会提供 `clipMobile` / `connectorsMobile`，**合并快进**（在解码器仍在快进时不会排队新的 `currentTime`——这是防止快速滑动冻结片段的原因），**保持静态图像作为海报，直到片段绘制其第一帧**，并**在第一次触摸时预取每个视频**（修复 iOS 的空白直到播放视频的问题），丢弃漂浮的粒子，忽略仅 URL 框的调整大小（不会滚动跳跃），并使用安全区域内边距，使文案清除缺口/主指示器。所有这些硬化功能默认启用——无需配置。`clipMobile`/`connectorsMobile` 编码是选择加入部分（步骤 1.6）：仅在用户请求移动版本时才连接它们。

对于非 JS 后端（Python/Rails 等.）：提供资源并丢弃引擎 `<script>` 到渲染的 HTML 中；它没有特定于框架的内容。

## 步骤 8 — 测试接缝（不要跳过）

使用无头浏览器驱动页面，并**验证接缝处的帧连续性**，这是最可能出错的地方：

- 在每个接缝之前和之后的位置滚动时截图。两个帧必须几乎相同（下潜的最后一帧 == 连接器的第一帧）。如果它们突然出现，您使用了场景静态图像而不是实际渲染帧（重做步骤 5），或者交叉淡入淡出带太短。校准：通过构图判断接缝，而不是原始 PSNR——在 720p/1080p 下，正确的帧锁定接缝仅通过细节闪烁即可读 ~18–25 dB（在验证良好的构建上观察到）；真正的错位显示为不同的构图/道具，而不仅仅是柔和。
- 检查控制台中的错误，确认 `video.seekable.end(0) > 0`（blob 正常工作），并且 `currentTime` 跨每个片段的带跟踪滚动。
- **移动端——仅当用户选择加入移动版本（步骤 1.6）时进行完整清单检查。** 对于仅桌面构建，只需检查一次手机视口：页面加载，静态海报显示，没有重叠——引擎的硬化功能覆盖了优雅降级。对于移动构建（在真实手机或模拟器上执行，竖屏 + 横屏）：- 模拟手机视口**CPU 限制 4–6 倍**并快速滚动——片段应跟踪而不冻结（快进合并 + `-m.mp4` 编码使其保持稳定）。- 确认第一个场景立即显示（其静态图像是海报），并且您滚动时视频立即接管——没有空白/黑色场景（iOS 初始化修复）。专门测试 iOS Safari；如果此功能回归，它会显示空白。- 确认 `-m.mp4` 变体在移动端实际提供（网络面板），并在桌面端提供 1080p 主版本。移动片段必须**原生竖屏**（`videoWidth < videoHeight`——不是下采样的 16:9 文件），并且 `stillMobile` 海报必须提供并匹配每个竖屏片段的第一帧（在视频绘制时不会从横屏切换到竖屏）。- 缓慢滚动使 URL 框折叠——页面**不能**跳跃（仅高度调整大小的滚动在触摸时被忽略）。旋转设备——布局应干净地重新组合。- 仅当裁剪回退提供时（没有字幕用于竖屏链）：16:9 片段被裁剪到其中心——确认焦点主体仍然可读，并提醒用户这是权宜之计，不是移动版本。
- 检查减少动画（应回退到静态图像，没有视频，没有粒子）。

## 易犯错误（来之不易）

- **接缝突然出现** → 连接器端点是场景静态图像，而不是相邻片段的实际帧。始终提取实际帧（步骤 5）。
- **接缝卡顿 / 摄像头“向后跳跃”** → 即使接缝匹配帧，如果摄像头*速度反转*（向前下潜，然后一个将摄像头拉回的连接器），它看起来像倒带。这是架构 B 的固有特性。对于任何有地面漫游，使用架构 A（一个连续的前进拍摄——腿部链从实际最后一帧开始，没有拉回，没有 `--end-image`）；见步骤 4。
- **冻结视频 / 卡在帧 0** → `seekable=[0,0]`；主机没有提供字节范围。使用 blob URL（引擎执行）。
- **大文件** → 您使用了全帧内。使用 `-g 8` + blob 替代。
- **软 / 低质量** → 您下采样或过度压缩。原生 1080p 编码，crf ≤ 20，添加 `unsharp`。视频本质上比静态图像柔和——将静态图像作为最大保真度的轻量级回退。
- **并发生成 503 / "not_enough_credits" 竞态** → 当许多同时启动时是暂时的；重新启动单个失败，它真的不是没有字幕（使用 `higgsfield workspace list` 验证）。
- **NSFW 假阳性（Seedance `status "nsfw"`）** → 视频内容过滤器会标记完全无害的片段，尤其是在**卧室、泳池、水疗/健康**环境中，以及触发词如“床”、“泳池”、“瀑布”、“葡萄酒”、“游泳”。这是部分由提示词措辞和参考帧引起的。修复顺序：（1）重新启动——它通常是非确定性的，在第二次到第三次尝试时通过；（2）删除触发词并添加“空置、无人、无人物、建筑、雅致”；（3）仅在该片段上使用 `kling3_0` 重新生成，具有相同的起始和结束帧——不同的提供者过滤器通常通过 Seedance 阻止的内容。该片段的渲染字符会略有变化（每个模型都有自己的粒度/运动感）；对于 5 秒的连接器，在交叉淡入淡出后面，通常可以击败选项（4）：将连接器槽设置为 `null`——引擎直接淡入淡出该接缝（可选连接器），因此页面仍然完成。为室内/房地产内容预算额外的字幕/时间以重新启动。
- **暗色/自定义主题** → 引擎将其默认标记包裹在 `@layer sw` 中，因此页面级别的 `:root` / `.sw-root { --sw-bg; --sw-ink; --sw-accent; --sw-font-* }` 块会干净地获胜（无需特定性黑客）。`--sw-ink` 是您的**文本/标题**颜色；**强调色**填充主要按钮和活动导航。对于暗色主题，设置 `--sw-bg` 为暗色，`--sw-ink` 为亮色——文案遮罩和标题阴影会自动跟随 `--sw-bg`。
- **手机快进卡顿/快速滑动冻结** → 1080p 主版本对手机解码器太重，快进堆积。提供 `-m.mp4` 移动端编码（720p, `-g 4`）并连接 `clipMobile`/`connectorsMobile`（步骤 6/7）。引擎已经合并快进；较轻的编码是另一半。在低端设备上仍然卡顿？收紧 GOP（`-g 2` / 全帧内）。
- **iOS 上空白/黑色场景（桌面正常）** → iOS Safari 的一个怪癖：未播放的静音视频不会绘制快进帧。引擎通过保持静态图像作为海报，直到片段绘制并预取每个视频来修复此问题——因此**不要**在 `loadedmetadata` 时隐藏静态图像，或者如果您将引擎适配到框架中，则不要删除 `playsinline`/`muted` 属性。
- **在移动端滚动时页面跳跃** → 某些东西在 URL 框显示/隐藏 `resize` 时重新运行布局。引擎会忽略触摸时的仅高度调整大小；如果您移植了它，请将调整大小处理程序基于宽度变化进行限制（保留 `orientationchange` 路径用于旋转）。
- **文案被 URL 框/缺口遮挡（移动端）** → 使用引擎的安全区域感知底部偏移（`env(safe-area-inset-bottom)` + `dvh`）；确保页面的 `<meta viewport>` 包含 `viewport-fit=cover`（模板中包含）。
- **竖屏裁剪场景** → 在高手机上显示的 16:9 片段只显示其中心——这就是为什么移动版本是原生 9:16 链（§6b），永远不会是裁剪。如果您在移动构建中看到这种情况，要么裁剪回退提供（告知用户），要么 9:16 编码实际上没有被提供（检查 `videoWidth < videoHeight`）。保持每个场景的焦点主体居中（prompts.md）仍然对桌面电影本身很重要。
- **`--generate-audio` 错误（Seedance）** → 跳过它；在 HTML 中静音，在编码时 `-an`。
- **Kling 拒绝您的标记** → `kling3_0` 没有 `--resolution` 参数（不要传递一个；编码为 ffprobe 报告的原生分辨率），并且**声音默认开启**——传递 `--sound off`。持续时间默认为 5；腿部/下潜需要 10。
- **仅在您“节省字幕”的地方出现接缝突然出现** → 您在链中切换了模型，或者使用了仅起始图像的模型，而连接器需要一个 `--end-image`。整个链使用一个模型；唯一的经济型是 `seedance_2_0_mini`，它保持帧锁定，因此保持无缝。（任何具有参考输入的模型根本无法保持接缝——步骤 4。）
- **Monid Seedance 拒绝内联图像** → “必须是公共 https:// URL 或 asset://<id> 引用”：帧通过免费的 `sfs` 文件系统（put → `curl -T` → cat → 签名 URL；pipeline.md → Monid 后端），永远不会是 base64。怪癖：`/put` 回显 `home/<path>`，但 `/cat` 和 `/ls` 想要您给 `/put` 的**原始相对路径**——使用回显路径会导致 404。
- **Monid 片段宽高比错误** → `ratio` 默认是自适应的，并遵循输入图像（3:2 静态图像 → 4:3 左右的视频）。明确传递 `--ratio`——桌面 16:9，移动链 9:16——在**每个链片段**上。
- **Monid CLI “Polling timed out after 120s”** → 仅本地等待超时；运行在服务器端继续。使用 `monid runs get -r <runId> -w 120` 重新轮询（在 `monid runs list` 中找到 id）。结果 URL 过期（~24–48 小时）——立即下载。
- **Monid Minimax 在提示词存在时丢弃图像** → `prompt` + `first_frame_image` 一起返回一个不相关的 t2v 片段，并且计费错误的矩阵单元（$0.56 对比 $0.28 观察）。图像仅帧锁定，但没有相机控制。直到包装器修复，该端点无法链——使用 Monid 的 Seedance-2.0。（模型本身很好——通过 Higgsfield `minimax_hailuo` 的相同提示词+图像可以帧锁定。）
- **Monid 计费意外** → 矩阵/标记价格端点按选择器匹配计费：明确传递每个选择器字段（`model`, `resolution`, `duration`），并在每次片段的运行结果中读取 `cost.value`。任何 body 中的大 base64 字段也可能作为 HTML 错误页面弹回（“意外的标记 '<'”）——这是另一个原因，帧通过 sfs URL 传输。
- **Monid 架构自上次构建以来已更改** → 它会发生（Seedance 直到 2026 年 7 月晚才支持 t2v，然后获得了第一帧/最后一帧支持）。每次构建前使用 `monid inspect`；当输入架构与 pipeline.md 文档的不同时，重新运行步骤 4 的资格探测。
- **Codex 静态图像卡在“从 stdin 读取附加输入…”** → 并行的 `codex exec` 调用从同一个脚本启动共享父级 stdin；一个赢得它，其余的永远阻塞（观察到：1 个中的 3 个完成，2 个挂起，第二批从未开始）。始终在后台 `codex exec` 中追加 `< /dev/null`——管道的 `gen_still_codex` 有它；如果您适配命令，请保留它。
- **白盒场景** → `gpt_image_2` 返回一个实心背景；要么将页面背景与其匹配，要么将其清除（步骤 3）。
- **macOS 上的 bash 3.2** → 脚本中没有关联数组。
- **连接器抓取了错误场景的帧**（或在尚不存在的帧上出错）→ 数组循环在 **zsh**（macOS 默认交互式 shell）中运行，其中数组是 1 索引的，而不是 bash 的 0 索引。保持每个由数组驱动的链步骤在 `#!/bin/bash` 脚本中运行（通过 `bash script.sh`）——永远不要在交互式 shell 中内联数组循环。

- `references/prompts.md` — 输入清单、样式前言模式以及所有带填写槽位的提示模板（场景静止、潜入、连接器）。
- `references/pipeline.md` — 整个运行流程的复制粘贴批处理脚本（生成 → 提取帧 → 连接器 → 编码 → 移动端编码），bash-3.2安全版。
- `references/scrub-engine.js` — 可移植的、配置驱动的清理引擎（构建DOM + 注入CSS；blob查找、惰性加载、接缝交叉淡入淡出、复制、路线轨道、减少动画、手机硬化：移动端编码、查找合并、iOS预加载、安全区域、无跳转调整大小）。
