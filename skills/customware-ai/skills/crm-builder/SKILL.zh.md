# CRM 构建技能

## 此技能的作用

此技能定义了如何构建一个**CRM 工具**——一个用于管理联系人、公司、交易及其之间关系的系统。

CRM 在结构上与 CPQ 和交易构建器不同：
- **CPQ / 交易** = 一个记录按顺序阶段（步骤式导航）移动
- **CRM** = 多种实体类型及其之间的关系（实体导航）

左侧边栏使用**导航模式**（联系人、公司、交易、管道、活动）——**不是**步骤式。用户在实体视图之间切换，而不是顺序阶段。

**常见垂直领域**：销售团队、咨询公司、代理机构、专业服务、房地产、招聘、B2B 服务、任何跟踪关系和交易的业务。

构建器读取此技能，读取特定业务的术语和管道阶段的 `DOMAIN.md`，并使用客户的实际实体、字段和工作流生成可工作的原型。

## 何时使用此技能

当转录或 `DOMAIN.md` 包含以下信号时，使用此技能：

| 信号 | 示例 |
|---|---|
| **联系人/人员跟踪** | "客户数据无处不在"、"找不到我们交谈过的人"、"电子表格中的联系人" |
| **销售管道** | "交易"、"机会"、"管道"、"阶段"、"赢得/失去" |
| **跟进跟踪** | "跟进工作掉链子"、"没人知道上次是谁联系的" |
| **关系管理** | "推荐"、"谁认识谁"、"账户管理" |
| **潜在客户管理** | "来自网站的潜在客户"、"入站查询"、"潜在客户来源跟踪" |

**不要使用此技能用于**：
- 带有定价的产品配置 → 使用 `cpq-builder`
- 建筑/交易项目跟踪 → 使用 `trades-builder`
- 库存和库存管理 → 未来使用 `erp-builder`

## 模板合同

在开始构建之前，了解模板为您提供了什么以及此技能添加了什么。这是合同：

**模板 (`app/layouts/MainLayout.tsx`) 随附：**
- `SidebarProvider`、`Sidebar`、`SidebarContent`、`SidebarInset`、`SidebarTrigger` — 已连接
- `SidebarContent` 是**空的**——这是您的着陆区
- 头部中的一个品牌插槽（标志占位符 + 公司名称）
- `ModeToggle` 和用户菜单在头部右侧集群中

**此技能填充：**
- `SidebarContent` — 使用实体导航（管道、联系人、公司、交易、活动）、快速筛选和最近记录（见布局模式）
- 头部中的品牌插槽 — 使用来自 `DOMAIN.md` 的客户标志和公司名称
- 头部右侧集群 — 在现有用户菜单之前添加一个角色切换器 `DropdownMenu`，如果空间允许，则添加一个全局搜索输入
- `<Outlet />` 在 `<main>` 中 — 通过每个实体视图的路由组件（管道是默认值）

**此技能不执行：**
- 添加第二个 `Sidebar` 组件。只有一个边栏。
- 在 `SidebarContent` 中放置品牌瓦片。品牌仅存在于头部。
- 重新连接 `SidebarProvider` 或替换可折叠行为。使用现有内容。
- 构建步骤式。CRM 使用实体导航——并行视图，而不是顺序阶段。
- 默认情况下将详情视图折叠为弹出窗口或模态框。列表/详情是全页模式（列表视图 → 点击 → 在主内容区域中的详情视图）。

如果您发现自己想要重新结构 `MainLayout.tsx`，请停止——答案几乎总是填充 `SidebarContent`。

## 章节定义

CRM 工具有**五个章节**。与 CPQ/交易构建器不同，这些**不是**顺序阶段——它们是并行实体视图。用户可以自由地在它们之间导航。

### 章节 1：管道

**作用**：交易通过阶段的可视化看板视图。

**显示：**
- 像看板风格的列，每个列对应 `DOMAIN.md` 中的管道阶段
- 如果 `DOMAIN.md` 没有定义阶段，则使用：潜在客户 → 合格 → 提案 → 谈判 → 已赢得/已失去
- 每个交易项显示：交易名称、公司、价值、分配给、阶段中的天数
- 在列之间拖放（或点击以移动阶段）
- 每个列上的“添加交易”按钮
- 按分配人员、日期范围或交易价值筛选

**如果 `DOMAIN.md` 中没有管道阶段**，则使用上述默认值。客户在看到原型后可以对其进行调整。

### 章节 2：联系人

**作用**：人员的列表/详情视图。

**列表视图：**
- 联系人表或轻量级列表
- 列：姓名、电子邮件、电话、公司、最后活动、标签
- 搜索和筛选
- “添加联系人”按钮

**详情视图（点击联系人）：**
- 联系人详情：姓名、电子邮件、电话、公司（链接）、角色/职位、来源、备注
- 活动时间线：通话、电子邮件、会议、备注——按最新顺序显示
- 链接交易：与该联系人相关的交易列表
- “记录活动”按钮：快速添加通话、电子邮件、会议或备注，带日期和描述

**来自 `DOMAIN.md` 的字段：**
- 实体注册表 → 联系人实体字段成为联系人详情字段
- 术语词汇表 → 精确的字段名称和标签
- 如果 `DOMAIN.md` 没有定义联系人字段，则使用：姓名、电子邮件、电话、公司、角色、来源、备注

### 章节 3：公司

**作用**：组织的列表/详情视图。

**列表视图：**
- 公司表
- 列：公司名称、行业、联系人数量、交易数量、总交易价值
- 搜索和筛选
- “添加公司”按钮

**详情视图（点击公司）：**
- 公司详情：名称、行业、规模、网站、地址、备注
- 联系人选项卡：与该公司链接的人员列表
- 交易选项卡：与该公司链接的交易列表
- 活动时间线：来自该公司的所有联系人的汇总

**来自 `DOMAIN.md` 的字段：**
- 实体注册表 → 公司/账户实体字段
- 如果未定义：名称、行业、规模、网站、地址、备注

### 章节 4：交易

**作用**：交易/机会的列表/详情视图。

**列表视图：**
- 交易表
- 列：交易名称、公司、联系人、价值、阶段（徽章）、关闭日期、分配给
- 按价值、阶段、关闭日期排序
- 按阶段、分配人员筛选
- “添加交易”按钮

**详情视图（点击交易）：**
- 交易详情：名称、价值、阶段（可选的下拉菜单）、预期关闭日期、概率、分配给
- 链接的联系人和公司（可点击链接）
- 仅为此交易特定的活动时间线
- 备注部分
- 在最终阶段时，“标记为赢得”/“标记为失去”操作按钮

**阶段进展：**
- 交易阶段是一个 `Select` 下拉菜单，其中包含 `DOMAIN.md` 中的管道阶段
- 更改阶段会自动更新管道看板视图
- 赢得/失去是终端阶段——选择时显示赢/输原因字段

### 章节 5：活动

**作用**：CRM 中所有活动的按时间顺序的动态信息流。

**显示：**
- 时间线/动态信息流视图，按最新顺序显示
- 每个活动显示：类型图标（通话/电子邮件/会议/备注）、描述、链接的联系人、链接的交易、日期、记录者
- 按活动类型、日期范围、人员筛选
- 顶部“记录活动”按钮

**活动类型**：通话、电子邮件、会议、备注、任务。使用图标区分。
- 如果 `DOMAIN.md` 定义了不同的活动类型，则使用那些类型。

## 布局模式

CRM 工具默认使用**双面板布局**（左侧边栏 + 主内容）。在查看记录详情时，右侧边栏会根据上下文出现。

**这不是步骤式布局。** 左侧边栏是实体导航，不是顺序阶段。

### 左侧边栏（始终可见，可折叠）

模板在 `app/layouts/MainLayout.tsx` 中已预装 `SidebarProvider`、`Sidebar`、`SidebarContent` 和 `SidebarTrigger`。`SidebarContent` 是空的——这是此技能填充实体导航的插槽。不要重新连接边栏，不要添加第二个 `Sidebar` 组件，也不要在边栏中放置品牌瓦片。品牌标识仅存在于头部（见模板合同）。

**边栏标题**：使用上下文标签，如“CRM”或“[业务] CRM”——不是工作流描述。如果业务名称简短，“[业务] CRM”读起来很自然；如果它很长，只需“CRM”即可。标题描述的是导航是什么。

| 组件 | 内容 |
|---|---|
| **实体导航** | 在 `SidebarContent` 中使用垂直堆叠的导航列表，包含五个章节：管道、联系人、公司、交易、活动。每个导航项显示：图标、标签和记录数量徽章。点击导航到该实体的视图。**这是一个导航器，不是步骤式**——没有步骤编号，没有完成状态，没有顺序流程。 |
| **快速筛选** | 在导航下方，显示保存的筛选器或视图（如果用户创建它们）。例如，“我的交易”、“热门潜在客户”、“本周跟进”。 |
| **最近记录** | 在筛选器下方，显示 3-5 个最近访问的记录（任何实体类型）以快速导航。每个项显示名称和实体类型徽章。将此部分靠近边栏底部，以便无需滚动即可始终可见。 |

### 主内容（中心——根据选择的导航项变化）

**根据选择的导航项渲染活动章节。** 一次只显示一个章节。

```tsx
{activeSection === "pipeline" && <PipelineView />}
{activeSection === "contacts" && <ContactsView />}
{activeSection === "companies" && <CompaniesView />}
{activeSection === "deals" && <DealsView />}
{activeSection === "activities" && <ActivitiesView />}
```

**每个章节中的列表/详情模式：**
- 默认：列表视图，表或轻量级看板，具体取决于实体。
- 点击记录：详情视图，全宽部分，活动时间线，链接记录
- “返回列表”按钮或面包屑返回
- 这是标准的 Salesforce/HubSpot 模式

### 右侧边栏（上下文——在查看记录详情时出现）

查看联系人、公司或交易记录详情时，右侧边栏可以显示：
- **快速摘要** — 一览关键字段
- **链接记录** — 相关联系人、交易或公司
- **即将进行的活动** — 下一个计划的通话/会议

此边栏对于原型是可选的。如果主内容区域有足够的空间，则详情视图可以是单面板。仅在记录详情受益于同时提供上下文时才添加右侧边栏。

### RBAC 行为

- 使用 `DOMAIN.md` 用户角色或利益相关者地图中的角色向 localStorage 种子角色。
- 角色切换器是头部栏中的一个 `DropdownMenu` 下拉菜单。
- **分配筛选**：当角色处于活动状态时，可选地筛选管道和交易视图，仅显示分配给该人员的记录。
- **活动归因**：记录的活动应归因于活动角色。
- CRM 通常比 CPQ 具有较少的硬权限门——大多数用户可以看到所有内容，但只能看到自己分配的记录。

### 价格/价值可见性

- 在管道项、交易列表和交易详情中显示交易价值。
- 在管道视图顶部按阶段显示总管道价值。
- 使用 `DOMAIN.md` 中的货币。
- 格式："$25,000" 或 "$25,000 CAD"，具体取决于 `DOMAIN.md`。

### shadcn/ui 组件映射

将卡片视为例外，而不是默认布局基元。尽可能将内容内联到页面主体中。仅在确实需要强调、分离、重复或对话框/详情框架时使用卡片。不要构建卡片密集型仪表板、卡片内的卡片或通用浮动面板网格。

| CRM 元素 | shadcn 组件 | 使用说明 |
|---|---|---|
| 实体导航项 | `Button variant="ghost"` 在垂直堆叠中 | 在 `SidebarContent` 中。活动项获得强调背景。图标 + 标签 + 记录数量徽章。 |
| 管道列 | 列部分，如果交易很多则使用 `ScrollArea` | 列标题显示阶段名称 + 交易数量 + 总价值。如果项需要强分离，则使用卡片。 |
| 管道中的交易项 | 紧凑的可点击行或微妙的项块 | 交易名称、公司、价值、分配头像。 |
| 联系人/公司列表 | `Table` | 可排序的列，搜索输入位于上方。 |
| 记录详情 | 全宽部分，使用 `Separator` | 在主页面主体中保持详细信息内联。 |
| 活动时间线 | 自定义列表，带图标 | 每个项目：类型图标、描述、日期、链接记录。使用 `Avatar` 显示人员。 |
| 阶段徽章 | `Badge` | 按阶段颜色编码：潜在客户=灰色，合格=蓝色，提案=琥珀色，谈判=紫色，赢得=绿色，失去=红色。 |
| 交易价值 | `text-lg font-semibold` | 在管道项和详情视图中突出显示。 |
| 分配下拉菜单 | `Select` | 从 `DOMAIN.md` 利益相关者名称填充。**不是**自由文本。 |
| 活动类型选择器 | `Select` 或 `RadioGroup` | 通话、电子邮件、会议、备注、任务。 |
| 搜索输入 | `Input` 带搜索图标 | 在每个列表视图的顶部。 |
| 操作按钮 | `Button` | 主要：“添加联系人”、“记录活动”。破坏性：“删除”、“标记为失去”。 |
| 链接记录芯片 | `Badge variant="outline"` | 可点击——导航到链接的记录。 |
| 快速添加表单 | `Dialog` 或内联表单 | 模态框，快速添加联系人/交易，而无需离开当前视图。 |
| 空状态 | 内联空块，带居中文本 + 操作 | “还没有联系人。添加您的第一个联系人。” |
| 确认对话框 | `AlertDialog` | 删除记录、标记交易为失去。 |
| 提示通知 | `Sonner` / `toast()` | 创建、更新、删除、记录活动后。 |

## 确定性映射规则

### 实体 → CRM 记录映射

| `DOMAIN.md` 实体模式 | 映射到 | 在章节中 |
|---|---|---|
| 联系人 / 人员 / 潜在客户 / 客户 | 联系人记录 | 联系人 |
| 公司 / 账户 / 组织 / 业务 | 公司记录 | 公司 |
| 交易 / 机会 / 销售 / 潜在客户 | 交易记录 | 交易 + 管道 |
| 活动 / 通话 / 会议 / 电子邮件 / 备注 | 活动条目 | 活动 + 记录时间线 |
| 管道 / 阶段 / 状态 | 管道阶段列 | 管道 |
| 推荐 / 来源 / 潜在客户来源 | 联系人或交易上的来源字段 | 联系人/交易 |

### 关系映射

| `DOMAIN.md` 关系 | 实现 |
|---|---|
| 联系人属于公司 | 联系人有一个公司字段（选择下拉菜单）。公司详情显示链接的联系人。 |
| 交易有一个联系人 | 交易有一个联系人字段（选择下拉菜单）。联系人详情显示链接的交易。 |
| 交易有一个公司 | 交易有一个公司字段（自动从联系人的公司填充，可编辑）。 |
| 活动与联系人/交易相关联 | 活动有联系人字段和交易字段（选择下拉菜单）。 |

### 业务规则 → 行为映射

| `DOMAIN.md` 规则模式 | 实现 |
|---|---|
| "管道阶段：X、Y、Z" | 管道列使用这些确切名称 |
| "只有 [角色] 可以关闭交易" | "标记为赢得/失去" 按钮上的 RBAC 门 |
| "X 天内跟进" | 在没有最近活动的联系人/交易上显示过期徽章 |
| "超过 X 的交易需要批准" | 在高价值交易上显示批准要求注释 |
| "推荐来源跟踪" | 联系人上的来源字段具有定义的下拉值 |
| 货币/税务/术语 | 在交易价值和任何开票视图中显示 |

### 管道阶段默认值

如果 `DOMAIN.md` 没有定义管道阶段，则使用这些：

| 阶段 | 颜色 | 含义 |
|---|---|---|
| 潜在客户 | 灰色 | 新未合格的查询 |
| 合格 | 蓝色 | 确认为一个真正的机会 |
| 提案 | 琥珀色 | 发送提案或报价 |
| 谈判 | 紫色 | 在讨论中，条款正在商定 |
| 已赢得 | 绿色 | 交易已签署，收入已确认 |
| 已失去 | 红色 | 交易未关闭 |

这些默认值可以被 `DOMAIN.md` 状态模型覆盖。

## 来自真实 CRM 的关键 UX 模式

这些模式来自 Salesforce、HubSpot、Pipedrive 和 Freshsales。遵循这些模式，以创建对 CRM 用户来说感觉熟悉的原型：

### 1. 所有内容都链接到所有内容
联系人链接到公司。交易链接到联系人和公司。活动链接到联系人和交易。每个链接的名称都是可点击的——点击导航到该记录的详情视图。

### 2. 活动时间线是心跳
每个记录（联系人、公司、交易）都显示活动时间线。最新的互动最重要。“我们上次和这个人谈话是什么时候？”应该可以一目了然地回答。

### 3. 管道是主屏幕
管道看板视图是默认的登录页面。销售团队就驻扎在这里。每个阶段的管道总价值在顶部可见。

### 4. 快速添加无处不在
"记录通话"和"添加交易"应该可以从任何视图访问——无论是通过浮动操作按钮，还是头部固定的"快速添加"。用户不应需要离开当前页面来记录交互。

### 5. 搜索是全局的
一个搜索栏可以按名称查找联系人、公司和交易。结果按实体类型分组。

### 6. 空状态引导操作
当某个部分没有记录时，显示一个有帮助的空状态："还没有交易。添加您的第一个交易来开始跟踪您的管道。"包含一个主要操作按钮。
