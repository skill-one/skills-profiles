# Refero 设计

Refero 为代理提供品味和产品证据。在设计工作之前使用它，而不是依赖通用的模型知识。

Refero 有三个研究层级：

1. **风格** - 视觉方向和品味。
2. **界面** - 具体的 UI 模式和产品界面决策。
3. **流程** - 多步骤旅程逻辑。

最佳结果来自于结合层级：从风格中获得视觉方向，从界面中获得具体的 UI 模式，当任务有多个步骤时，从流程中获得顺序。

## 非妥协项

- **设计工作前进行调研。** 每个设计都必须在实施前基于参考。不要依赖模型的通用设计品味。
- **当 Refero MCP 工具可用时，首先使用风格进行视觉工作。** 如果工具不可用，使用捆绑的工艺参考并保持相同的参考锁定工作流程。
- **不要复制一个参考。** 研究几个强大的参考，并为用户的产品的方向综合一个新的方向。
- **不要将参考平均到一个安全的中间。** 当参考冲突时，选择一个主导的方向并保留其鲜明的特征。次要参考只能添加狭窄的细节。
- **不要改变 token 的含义。** 如果一个参考说颜色、字体、半径、阴影、渐变或组件用于特定的角色，则仅用于该角色或省略它。
- **尊重图像指导。** 如果一个风格依赖于摄影、插画、产品照片或图形，则保留媒体的角色。在可用时使用真实/生成/库存资产；否则创建一个有艺术指导的故意占位符。不要用弱 CSS、文本或装饰框伪造复杂的图像。
- **当这种技能可用时，不要将通用的前端/产品设计技能作为平行的设计权威**。 Refero 是设计方法论；通用的设计技能往往将工作拉回到通用的 AI 设计。
- **调研输出必须是具体的。** 标注参考，描述具体的选择，并解释将进行哪些调整。
- **不要从感觉记忆中设计。** 每个主要的视觉、布局、内容或交互决策都必须追溯到 Refero 调研、用户的简报或工艺参考。
- **实施前进行综合。** 在绘图或编码之前，将调研转化为概念、token 方向和具体决策账本。
- **简报不是构建目标。** 在实施前，锁定用户提供的视觉来源、现有的产品/设计系统目标、选定的生成模型或经批准的直接构建的参考锁定方向。
- **仅在改变结果时使用图像生成。** 图像生成可能很慢，并且可能不在每个编码环境中存在。用于视觉探索、模型、图像、插图、纹理和困难资产；跳过小修复、明显的生产编辑或代码原生 UI 工作。
- **构建视觉工作后进行验证。** 在交接前，将渲染的实施与锁定的目标/参考进行比较。修复可行动的设计漂移，而不是将调研视为足够的。

## MCP 设置

这项技能本身作为调研优先的设计方法论和工艺参考很有用。
调研是强制性的。当可用时，使用 Refero MCP 进行实时风格、界面和流程调研；否则使用捆绑的工艺参考和任何用户提供的参考进行调研。

典型的 MCP 设置：

```bash
claude mcp add --transport http refero https://api.refero.design/mcp
```

然后在 Claude 代码中运行 `/mcp` 并在提示时登录 Refero。

有关完整工具详细信息，请阅读 [references/mcp-tools.md](references/mcp-tools.md)。

## 发现

在调研之前，形成一个简短的设计简报。仅请求会实质性地改变结果而缺失的信息；否则做出合理的假设并继续进行。

澄清：

- 正在设计什么
- 平台：网页、iOS 或两者
- 受众和技术水平
- 主要用户目标
- 期望的感觉或品牌方向
- 要克服的业务/用户反对意见
- 限制：现有的品牌、框架、截止日期、无障碍性、内容
- 任务是否需要视觉方向、具体的 UI 模式、旅程逻辑或混合
- 任务是否应直接转到代码、首先生成视觉选项或实施期间创建生成资产

简报格式：

```text
为 [WHO] 在 [PLATFORM] 上设计 [WHAT]。
目标：[PRIMARY USER GOAL]。
感觉：[DESIRED FEELING]。
主要反对意见/风险：[OBJECTION]。
必须记住：[HOOK OR DISTINCTIVE IDEA]。
限制：[CONSTRAINTS]。
调研需求：[styles/screens/flows]。
路径：[direct build / visual exploration / audit / asset generation]。
```

## 工作流路由

选择可以产生高质量结果的轻量级工作流。

- **直接构建**：用于小 UI 修复、清晰的生产编辑、现有的设计系统工作或具有具体来源匹配的任务。调研并锁定方向，然后编码。
- **视觉探索**：当用户要求变体、新的视觉语言、重大改版、着陆页或具有多个可能方向的另一个高可见度表面时使用。默认为三个参考锁定选项并要求用户选择；参见 [references/visual-workflow.md](references/visual-workflow.md)。
- **审核**：在使用前使用捕获的屏幕截图、Refero 界面或流程作为证据。
- **资产生成**：仅在参考锁定需要位图媒体时使用生成图像，而代码、图标或现有资产无法忠实地提供；参见 [references/visual-workflow.md](references/visual-workflow.md)。

## 工具路由

### 首先使用风格进行视觉工作

当用户要求设计、重新设计、改进、润色或创建任何具有视觉组件的内容时，使用 `refero_search_styles`。

风格是从真实的网络营销/产品页面中提取的语义设计参考。它不是屏幕截图，也不是组件库。搜索结果提供预览；来自 `refero_get_style` 的完整风格参考提供设计指导，例如视觉论点、token、排版、布局/构图、部分节奏、间距、提升、表面、组件、图像处理、实施说明和 do/don't 规则。

当前限制：Refero 风格目前涵盖网页营销/产品页面，例如着陆页、定价页、产品营销网站、编辑品牌网站和 SaaS 网站。它们目前不涵盖应用内仪表板、认证屏幕、设置屏幕或 iOS 应用屏幕作为风格系统。对于产品 UI 任务，仍然使用风格来建立视觉语言，然后使用界面/流程来处理产品逻辑。

使用风格用于：

- 外观和感觉
- 品牌方向
- 着陆页和营销页
- 排版、调色板、布局、部分结构、间距、半径、提升、表面
- 组件处理和有时组件/代码示例
- 图像和产品屏幕处理
- 设计系统灵感
- 使通用界面感觉更优雅

### 使用界面获取具体的 UI 模式

当您需要：

- 特定的屏幕类型
- 特定的组件或 UI 模式
- 页面布局和内容层次结构
- 文本和 CTA 模式
- 表单/状态示例
- 仪表板、设置、模态、表格、定价、空状态、认证或产品屏幕细节

找到强大的界面后：

- 使用 `refero_get_screen` 获取完整详细信息
- 使用 `refero_get_similar_screens` 从强大的示例扩展
- 仅在需要原始屏幕检查时使用 `refero_get_screen_image`

### 使用流程获取旅程

当任务具有前后顺序时，使用 `refero_search_flows`：

- 欢迎体验
- 注册
- 结账
- 订阅管理
- 取消
- 账户删除
- 密码重置
- 个人资料/设置更改
- 任何多步骤流程

找到强大的流程后，使用 `refero_get_flow` 获取每一步的目标、操作、系统响应和完成状态。

### 使用视觉工作流获取图像和 QA

对于图像生成、视觉选项、生成资产和视觉 QA，当任务需要时，请阅读 [references/visual-workflow.md](references/visual-workflow.md)。

## 调研工作流

### 1. 使用风格调研视觉方向

对于任何视觉设计任务，从这里开始。

推荐循环：

1. 搜索 3-5 个不同的视觉角度。
2. 包含一个广泛的审美查询。
3. 包含一个领域/类别查询。
4. 当相关时，包含一个知名品牌或强大产品的查询。
5. 使用 `refero_get_style` 获取 3-4 个强大的风格；完整风格很大，因此将较大的调研分成多个批次。
6. 比较每个风格贡献的内容。
7. 选择一个主要基础，并从其他风格中借用 1-2 个具体细节。
8. 在实施前锁定主要参考的签名特征。

好的风格查询：

- 编辑器单色 SaaS 着陆页
- 温暖可信赖的医疗保健产品营销
- 高端金融科技网站，排版克制
- 活泼的创作者工具着陆页，鲜艳的点缀
- 开发者工具网站，带有产品屏幕
- 奢侈品电商编辑产品页面
- 生产力 SaaS，空旷的间距
- 数据基础设施网站，黑暗的技术风格
- Attio 编辑器 SaaS 排版
- Linear changelog 黑色开发者工具
- shadcn 单色设计系统

从风格中提取：

- 北极星/视觉论点
- 排版个性和类型比例
- 颜色角色和强调纪律
- 间距密度和节奏
- 布局系统、部分节奏和构图模式
- 卡片/按钮/表面处理
- 边框、阴影、半径
- 提升和深度规则
- 组件示例和实施/代码说明（如果存在）
- 图像、图形、插图或产品屏幕处理
- 媒体资产策略：真实资产、生成/库存资产、代码原生原始资产、产品屏幕或占位符
- do/don't 规则
- 一个难忘的视觉动作来适应

综合规则：

- 主要风格：整体情绪、密度和结构。
- 次要风格：具体的借用细节。
- 用户上下文：将所有内容适应用于产品、受众和任务。
- 不要使用所有参考的平均值/交集。如果一个参考是黑暗的，一个是酸性的，一个是衬线，答案是温暖的奶油色 + 柔和的橙色 + 礼貌的衬线。

永远不要将结果呈现为“复制 X”。将其呈现为受几个参考启发的新的方向。

在实施前，创建一个参考锁定：

```text
主要参考/方向：[一个主导来源]
保留：[3-5 个必须保留的特征：画布、类型、强调、布局、密度、媒体]
仅借用：[1-2 个具体的次要细节]
角色规则：[要保留的来源 token/组件含义，例如 CTA 仅限、代码仅限、装饰仅限]
媒体策略：[真实/生成/库存/代码原生/占位符，带有宽高比和艺术方向]
拒绝：[会导致方向崩溃的默认值/平均值]
Token 承诺：[背景、类型、强调、半径、边框/阴影、图像处理，带有角色]
```

如果实施偏离锁定，请停止并纠正它。不要将鲜明的特征软化成更安全的颜色、更安全的字体、更柔和的半径或通用的部分布局。
参考锁定不是克隆；它保留选定的特征，同时将内容、品牌和交互细节适应用于用户的产品的。

当组合风格时，为每个来源分配一个有限的任务。例如：一个来源可以拥有画布/类型，另一个可以拥有代码窗口处理，另一个可以拥有主要的 CTA。
永远不要将 token 移出其来源角色：CTA 颜色保持 CTA 仅限，语法颜色保留在代码内，装饰性渐变保持装饰性，卡片/按钮规则保持其指定的半径、阴影和状态行为。

如果主要风格是图像导向的，不要用纯文本布局替换它。如果您无法生成所需的图像或图形，请保留具有稳定尺寸、宽高比、标题/替代文本和简短艺术方向注释的插槽。仅在它们与来源风格匹配时，才构建简单的图表、图标、代码窗口或几何原始资产。

对于重要的视觉探索、生成模型、位图资产或构建后的视觉 QA，请遵循 [references/visual-workflow.md](references/visual-workflow.md)。

### 2. 使用界面调研产品细节

当您需要知道界面应该包含什么或真实产品如何解决特定的 UI 问题时，使用界面。

好的界面查询：

- 定价页年度/月度切换
- 功能比较表
- 仪表板空状态
- 订阅设置取消模态
- 欢迎体验进度指示器
- 2FA 设置恢复代码
- 数据表过滤器
- 破坏性行动确认

根据屏幕上的事实进行搜索：

- 页面类型
- 组件
- 状态
- 公司/产品
- 屏幕上的文本

避免在任务需要视觉时将界面作为主要风格来源使用。首先使用风格，然后使用界面获取结构和具体细节。

从界面中提取：

- 布局结构
- 信息层次结构
- 组件选择
- CTA 模式
- 内容/文本模式
- 状态和边缘情况
- 信任或转化策略
- 值得适应的具体细节

### 3. 使用流程调研旅程逻辑

当存在多个步骤或用户随时间改变状态时，使用流程。

好的流程查询：

- 欢迎体验欢迎体验
- 带促销代码的结账
- 订阅取消
- 账户删除反馈
- 密码重置 2FA
- 工作区计费升级

如果流程搜索稀疏，请放宽查询。如果仍然稀疏，请使用界面并重建旅程。

从流程中提取：

- 入口点和退出状态
- 步数
- 用户做出的决定
- 摩擦减少器
- 必须的确认
- 保存/恢复状态
- 错误处理
- 留存或说服时刻
- 每一步的系统响应

## 调研深度

根据任务风险匹配深度。

对于快速视觉改进：

- 2-3 风格搜索
- 2-3 个完整风格
- 1 个短综合

对于新的着陆页、品牌方向或重大改版：

- 3-5 风格搜索
- 3-4 个完整风格在一个批次中；仅在需要时使用额外的批次
- 界面调研用于具体部分/组件
- 实施前明确视觉方向

对于产品工作流：

- 风格用于视觉语言
- 界面用于关键状态/组件
- 流程用于顺序

对于高风险或模糊的任务：

- 从几个角度进行搜索
- 检查后续页面
- 比较强大的和不寻常的参考
- 在设计前记录权衡

## 综合

将发现分为三个桶。

### 视觉方向

从风格中：

- 氛围
- 排版
- 调色板
- 密度
- 表面
- 图像
- 独特细节
- do/don't 规则

输出示例：

```text
使用精确的分析型 SaaS 基础：白色画布，紧凑的 UI 文本，克制的黑色主要操作，细边框，以及框架面板中的产品屏幕。从另一个参考借用纪律性的强调使用，但保持颜色罕见。
```

### 产品模式

从界面中：

- 界面需要包含什么
- 常见布局
- 组件模式
- 状态
- 文本和 CTA
- 特定策略

输出示例：

```text
定价页通常将计费切换放在计划卡片上方，突出显示一个计划，并将详细的特征比较放在下面。我们应该适应比较结构，但因为这个产品销售信任而不是炒作，所以我们应该让英雄更安静。
```

### 旅程逻辑

从流程中：

- 步骤
- 决策点
- 系统响应
- 用户信心和摩擦
- 成功/失败状态

输出示例：

```text
取消流程通常收集一个原因，提供相关的替代方案，确认破坏性行动，然后说明访问何时结束。最佳流程提供一个明确的返回路径。
```

## 呈现发现

不要倾倒每个结果。当任务非平凡时，在设计前向用户提供一个简短的调研摘要。

建议格式：

研究总结：
- 审阅的样式：[数量] 个在 [方向] 上
- 审阅的屏幕：[数量]，如果使用
- 审阅的流程：[数量]，如果使用

视觉方向：
- [主要样式基础]
- [参考锁定/保留的签名特征]
- [借鉴细节 1]
- [借鉴细节 2]

产品模式：
- [从屏幕中得出的具体 UI 决策]

旅程逻辑：
- [流程决策，如果适用]

建议：
- [要设计和原因]

在实施之前，将研究转化为简短的决策账本：

| 决策 | 来源 | 来源规则/角色 | 原因 |
|------|------|---------------|------|
| [调色板/类型/布局/媒体/内容选择] | [样式/屏幕/流程/用户约束/工艺规则] | [保留的标记/组件/媒体角色] | [具体理由] |

如果一个主要选择没有来源，不要将其作为设计决策发布。要么进行更多研究，将其与用户的约束联系起来，或者删除它。

- 文案和说服：[参考资料/文案.md](参考资料/文案.md)
- 反 AI 滥用检查：[参考资料/反 AI 滥用.md](参考资料/反 AI 滥用.md)

核心工艺规则：

- 在实施前定义标记：类型比例、颜色、间距、半径、阴影。
- 保留主要参考的最强特征，而不是规范化它们。
- 保留参考资料中的标记角色。不要将 CTA 强调色变成背景，将纯代码颜色变成 UI 亮色，或将装饰性渐变变成界面表面。
- 保留参考资料中的图像角色。在可用时使用有能力的资源；否则，优先选择一个诚实、尺寸合适的占位符，而不是一个糟糕的虚假插图或照片。
- 使用研究中的品牌适当颜色。除非用户明确要求，否则不要默认使用靛蓝/紫罗兰。
- 将“冷静的编辑”视为当前的 AI 滥用风险。不要默认使用装饰性标题字词交换：一个字或短短语以不同的显示/衬线/手写/斜体样式或强调色设置，温暖的象牙/奶油画布，或橄榄/陶土/陶土调色板，除非研究和产品上下文证明它们。
- 避免通用的英雄 -> 功能网格 -> 定价 -> 常见问题解答 -> CTA，除非研究支持它。
- 使用真实产品证据进行文案、信任信号、异议处理和部分顺序。
- 至少创建一个令人难忘的细节：一个视觉动作、交互、布局选择或文案细节，用户会记住。
- 平衡标题和简短显示文本使用 `text-wrap: balance`；选择性地使用 `text-wrap: pretty` 进行散文。检查关键断点以防止孤儿词和不自然的最后一行。
- 在设计中保留无障碍性和响应行为，而不是作为后期通过。

## 质量门

在最终交付之前，确认：

- 我是否使用了样式进行视觉品味？
- 我是否避免直接复制一种样式？
- 我是否将多个参考资料综合成一个独特方向？
- 我是否避免将参考资料平均成一个安全的中心点？
- 我是否保留了主要参考的签名特征？
- 我是否保留了来源标记/组件角色，而不是重新利用它们？
- 我是否使用真实资源、适当的基元或有意占位符保留了所需的图像/媒体角色？
- 我是否在需要具体 UI 模式时使用了屏幕？
- 我是否在任务有多个步骤时使用了流程？
- 我能否命名哪些参考资料影响了设计以及原因？
- 每个主要设计选择是否可以追溯到参考资料、用户约束或工艺规则？
- 我是否在实施前生成了概念和决策账本？
- 实施是否避免了通用的 AI 设计默认值？
- 除非参考资料和内容角色证明，否则我是否避免了装饰性衬线/斜体/颜色字词交换？
- 结果是否符合用户的 产品、受众和约束？

如果答案是 否，在交付前进行更多研究或改进。

对于重要的视觉工作，在交接前在 [参考资料/视觉工作流程.md](参考资料/视觉工作流程.md) 中运行视觉 QA 通过。
