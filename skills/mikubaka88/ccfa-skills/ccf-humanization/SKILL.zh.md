# CCF人性化

## 家庭文件合同

在撰写前，确定每个任务/成果的规范输出和一个稳定的可工作目录。复用明确的或已建立的路径；否则使用项目根目录 `ccfa-workfiles/<用途>/<成果ID>/`，仅在需要时使用 `source/`、`assets/`、`cache/` 和 `build/`。就地更新当前文件；不要分散中间文件或创建迭代副本。保留输入和所需证据；仅清理由此任务创建的已验证的可丢弃文件。使用UTF-8文本I/O，并在保存或渲染后检查中文文本。对于文件工作，应用 [artifact-contracts.md](../ccf-common/references/artifact-contracts.md) 并在技能转换时复用相同的路径。

## 协作合同

这是第一个必需的家庭预审。应用以下基线，然后在专家工作前激活 [ccf-common](../ccf-common/SKILL.md)。两个预审启动一次而不递归地互相进入；在贡献者之间复用适用的规则。

保留一个集成的负责人，并积极使用其他技能来解决缺失的先决条件或检查材料发现。复用适用的证据；不要跳过必要的准备工作以节省代币。在最终确定前，集成贡献并验证受影响的成果。遵循条件性 [cooperation routes](../ccf-common/references/routing.md)；避免无关的阶段和重复的报告。

## 调用控制

**CCFA交接模式：部分（推荐）。** 跟随 `metadata.ccf_skill_controls.handoff_question_mode`、`../ccf-common/references/handoff-modes.md` 和 `../ccf-common/references/task-modes.md`。

为每个CCFA任务和贡献者（包括规划、检索、审查、审计、渲染、脚手架和维护）首先激活此模式。在 `ccf-common` 和专家执行前应用以下家庭基线。在交接时复用已加载的适用基线；刷新更改或丢失的规则。文本编辑和实验检查取决于实际任务，但基线激活是通用的。专家技能保留所有权，显式的用户/主机约束仍然适用。

## 家庭基线

在专家工作前阅读并应用此条目的基线。直接沟通具体任务、证据和决策；避免想象的反对意见、空洞的保证、重复的警告和不必要的流程叙述。保留真实风险、关键审查发现、不确定性、科学事实、引文、方程式、数字、术语和强制性检查。不要将关键评估变成表扬或改变分数以听起来不那么防御性。仅读任务的诊断不重写；非文本任务应用这些规则而不编造文本编辑步骤。仅启用以下相关的详细模式。此预审默认不创建报告、警告文件或单独的代理。

## 核心规则

直接写出科学论证：问题、见解、机制、证据和支持的启示。删除作者的自我辩护、想象的审稿人反对意见、道歉式新颖性定位、否认性声明、空洞的保证、堆叠的回避、重复的范围免责声明和强制性的谨慎结尾。用其科学内容替换防御性句子，如果它不增加任何内容则删除它。

人性化保留严谨性：保留有意义的不确定性、实际假设、负面结果、协议事实、引文、方程式、数字、术语和必要的披露。不要将 `suggests` 变成 `proves`，省略已知的失败，或隐藏真实的比较限制。不要将 `only`、`not` 或 `may` 等孤立单词视为错误。

保留方法确认和版本门状态为内部信息。自然描述实际方法和相关配置。使用提供的规范进行方法起草，使用引用的证据进行先前工作，使用验证的完整配置进行报告的比较；不要仅为了编辑支持的文本而要求新的实验。

## 模式

- `family-preflight`：在任何CCFA专家之前始终应用基线；不需要手稿或实验成果。
- `manuscript-humanization`：在保留科学内容和源格式的同时修改防御性文本。
- `experiment-humanization`：将相同的文本标准应用于最终实验描述和表格；保留完整方法比较和标记的消融。
- `warning-only`：识别一个无法从提供的证据和现有授权中解决的明确决策，而不修改其依赖的成果。

## 工作流

对于 `family-preflight`，应用基线，确保 `ccf-common` 处于活动状态，并继续请求的专家任务。以下编辑工作流仅在任务包含相关的文本或实验成果时适用；不要仅仅为了完成通用的预审而运行它。

1. 确定请求的成果、现有的授权以及输入是文本、建议的设计还是报告的结果。阅读 `references/humanization-policy.md` 了解句子决策和双语修复示例。
2. 恢复每个段落的科学信息。直接陈述观察、操作、假设或推论。删除空的自我辩护，而不是将其移入警告块。
3. 删除跨章节的重复警告。在解释变化时表达范围；不要要求每个摘要、段落、标题或结论都以限制结束。
4. 在授权编辑中保留材料事实和校准的不确定性。如果一个决策需要新的证据或研究范围变更，隔离该决策并继续不受影响的工 作。不要仅仅为了编码警告而编辑源文件。
5. 对于实际的发布比较或可执行的实验变更，加载 `references/experiment-discipline.md`。在内部门中保留验证的标识和完整配置；将合法的消融清晰标记。仅在任务需要时运行此步骤。
6. 在科学论证合理后应用现有的标点符号和术语偏好。对于完整章节或论文，在可用时运行 `../ccf-paper-writer/scripts/check_prose_quality.py` 并检查其在上下文中的候选位置。不要仅仅为了清除启发式警告而重写正确的科学语言。
7. 一次性阅读最终文本。检查修辞谨慎是否已被炒作、事实遗漏或不同的科学声明所取代。仅对更改的文本或未解决的发现重新运行检查。
8. 以原始格式返回请求的成果。作为侧车时，将所有权返回给内容技能；不要将过程报告附加到普通文本。

## 警告合同

仅用于无法从提供的证据和现有授权中解决的明确决策：

```text
CCF人性化警告：未插入到成果中
受影响的声明 / 文件 / 实验：
证据差距和材料后果：
需要的决策：
重要性：建议性 / 阻塞性
为此警告进行的文件更改：无
```

`blocking` 适用于依赖的声明或变更，而不是整个任务。风格选择、已记录的限制和准确的地方声明缩小是普通的授权编辑。
