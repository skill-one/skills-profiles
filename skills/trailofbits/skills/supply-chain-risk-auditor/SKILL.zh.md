# 供应链风险审计员

为项目的直接依赖项（npm、PyPI、Go）生成供应链风险报告，并对其锁文件解析的所有内容进行咨询性扫描。两个确定性脚本执行测量；你的工作是他们拒绝自动化的判断。

## 为什么是脚本做测量，而不是你

本报告中的每一项数据都是关于他人项目的声明，在用脚本重建此技能之前，手动收集的数据被测量错误：GitHub 贡献者计数称有五人以上维护 `lodash`，而 npm 的 ACL 称只有一人，`gh` 显示某个每周移动 1640 万次的项目下载量为零。不要根据 `gh`、网络搜索或记忆来估计维护者数量、下载量、陈旧性或 CVE 历史一一运行收集器，并引用它测量的内容。

脚本强制执行两个值得你在阅读其输出前了解的规则：

- **不可用数据永远不会是风险的证据。** 每个标准都解析为已评估清洁、已评估标记或因原因不可评估。
- **未测量的数据永远不会是清洁的结论。** 执行了无测量内容的运行会以非零退出，而不是打印出发现无内容的报告。

## 工作流程

1. 确认目标目录包含清单：`package.json`、`pyproject.toml`、`requirements*.txt` 或 `go.mod`。如果不存在，请说明并停止——不要审计此收集器无法手动解析的生态系统。读取锁文件以获取精确版本和传递扫描：`package-lock.json`/`npm-shrinkwrap.json`、`uv.lock` 和 go 1.17+ 的 `go.mod`。`yarn.lock`、`pnpm-lock.yaml` 和 `poetry.lock` 不会被读取——当它们存在时，报告会说明，版本会回退到 pin 或最新发布版本。
2. 检查 `gh auth status`。未经身份验证的 GitHub 允许每小时 60 次请求针对 5000，而收集器对每个依赖项都会进行多次请求；如果没有它，仓库标准可能会返回不可评估。与其默默修复，不如说明这一点。
3. 收集，然后渲染。除非另有要求，否则将输出放在审计的存储库之外：

   ```sh
   uv run {baseDir}/scripts/collect.py <project-dir> --json <out-dir>/findings.json
   uv run {baseDir}/scripts/render.py <out-dir>/findings.json --out <out-dir>/report.md
   ```

   对于约 50 个依赖项，需要几分钟时间——每个依赖项都有几个 HTTP 请求，Go 模块较多时更多，未使用经过身份验证的 `gh` 时更慢。如果 `collect.py` 以非零退出，它正在拒绝报告——逐字转达其消息，而不是重试或绕过它。
4. 阅读 `report.md` 和 `findings.json`。报告是交付物；JSON 包含了当你需要引用时每个结论背后的数据。
5. 添加收集器无法做到的内容，并清晰地区分它测量的内容：
   - 为此读者编写简短说明：首先应采取什么行动，以及为什么。
   - 咨询性发现的升级路径——检查修复是否是补丁或主要版本之遥。
   - 废弃或存档依赖项的替代候选。在命名候选之前验证候选是否存在于注册表中，并将这些标记为判断，而不是测量。
   - 对于标记的安装脚本：`npm ci --ignore-scripts` 对此项目的构建是否可行。

## 你添加内容的风格

以安全报告的方式编写添加的文本，并将相同的语调应用于报告附录和最终回复——回复会被逐字粘贴到工单和报告中。说明发现、其背后的数据以及行动。

- 非个人化和陈述性：没有第一或第二人称（“我运行了收集器”、“你应该升级”），没有缩写，没有感叹号。
- 主动语态，以主题为行为者：升级到 1.19.0 清除了所有 25 个咨询，而不是“建议 axios 升级”。
- 客观性：没有强化词或主观框架（“非常”、“重大”、“幸运地”），也没有猜测项目选择的原因。
- 时态：过去时用于审计做了什么，现在时用于依赖项的状态，将来时用于采取行动或不采取行动的后果。
- 建设性：建议命名行动及其成本，而不是指责。

如果 `report-writing:writing-style` 技能在会话中可用，请遵循它——它是此语调的完整版本。

渲染的报告仅包含事实。以下解释性规则是对你的指示，而不是读者的内容——不要将它们复制到交付物中作为免责声明或框架。

## 阅读报告

- **不可评估不等于风险。** PyPI 没有发布维护者 ACL，Go 没有注册表；这些行说明无法知道的内容，而不是什么不正确。
- **覆盖表限制每个声明。** “无咨询”意味着“在评估范围内无” —— 在重复清洁结论之前，请检查评估计数。
- **逐字引用数据。** 不要重新推导、四舍五入或美化报告的数字；每一个都可以从工件中重现。
- **未在发现中出现的不是认可。** 没有发现的依赖项仅针对这些标准进行了测量。

## 拒绝的合理化

- “`gh` 比收集器更快地给我维护者计数。” 测量错误——仓库贡献者和注册表发布权是不同的群体。
- “没有发现，所以依赖项是安全的。” 阅读覆盖表；在 PyPI 和 Go 上，一半的标准在结构上不可评估。
- “不可评估的行只会让读者困惑；我会删除它们。” 它们是报告中每个声明的边界。删除它们将部分覆盖转换为清洁的健康证明，这是此技能重建以防止的失败。
- “版本可能足够接近。” 在最新发布和锁文件解析版本之间检查的范围是不同的声明；报告会标明它做了哪个声明。保留标签。

## 不应使用的情况

- 许可证合规性审计。
- 扫描目标自己的源代码以查找漏洞或秘密——此技能从不读取依赖项源代码，只读取注册表、咨询和仓库元数据。
- 判断项目是否可以安装或构建。审计设计为仅从依赖项列表（清单和锁文件）工作，从不安装、构建或执行任何内容。损坏的安装和导入时中断超出范围，如果用户似乎期望它们，值得说明。
- 除了 npm、PyPI 和 Go 之外的其他生态系统；说明生态系统不受支持，而不是为其临时制作审计。
