# 基于属性的测试

一个示例测试断言一个点。一个属性断言整个输入域的规则，并让生成器去寻找反例。当代码具有代数结构时——一个逆函数、一个不变量、一个预言机——这种权衡是值得的，否则则不值得。没有这种结构的代码使用示例测试；这样说是有效的结果。

首先检查结构是否缺失，还是仅仅被隐藏了。被I/O包装的计算、通过连接构建的字符串、原地突变——每个都有属性，但没有接口可以断言它。在得出没有可断言的内容的结论之前，请参考[参考资料/重构.md](references/refactoring.md)。

## 属性目录

| 属性 | 公式 | 适用范围 |
|---|---|---|
| 往返 | `decode(encode(x)) == x` | 序列化、转换对 |
| 逆函数 | `f(g(x)) == x` | 加密/解密、压缩/解压缩 |
| 预言机 | `new(x) == reference(x)` | 优化、重构、重新实现 |
| 幂等性 | `f(f(x)) == f(x)` | 归一化、格式化、排序 |
| 不变量 | 在之前和之后都成立 | 任何转换、契约状态 |
| 容易验证 | `is_sorted(sort(x))` | 具有廉价检查器的复杂算法 |
| 交换律 | `f(a, b) == f(b, a)` | 二元和集合操作 |
| 结合律 | `f(f(a,b), c) == f(a, f(b,c))` | 组合操作 |
| 单位元 | `f(x, e) == x` | 具有中性元素的运算 |

强度排序，从最弱到最强：
`无崩溃 → 类型保持 → 不变量 → 幂等性 → 往返 / 预言机`。

断言代码支持的最强属性。"无崩溃"单独很少能证明依赖关系——如果你只能找到这些，那么要么微小的重新排列会暴露更强的属性，要么诚实地报告这个代码是较差的基于属性的测试候选。在确定第二种情况之前排除第一种情况。

## 属性测试断言无内容的两种方式

- **重言式。** `assert add(a, b) == a + b` 重述了实现；它们共享的任何错误都不会失败它。选择一个不重新计算函数而约束函数的属性。注意例外：`f(x) == f(x)` 当 `f` 不是一个明显纯函数时是一个真正的确定性属性——字典或集合上的序列化器、哈希、任何读取时钟的操作。
- **空洞。** `assume()` 过滤掉几乎每个输入，而自我矛盾的 `assume()` 在运行零个案例后通过。将约束推入策略中，以便生成器直接生成有效输入。
