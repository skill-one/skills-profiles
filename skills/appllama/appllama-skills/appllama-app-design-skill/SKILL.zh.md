# Appllama 应用设计技能

你正在构建的界面将和世界上设计最佳的应用程序并排出现在手机上。用户会在启动后的几秒钟内将你的输出与那些应用进行比较。这项技能定义了标准以及超越标准的方法。

## 首要指令：在绘制前先研究

当你可以研究顶级应用如何解决相同界面时，永远不要凭空想象来设计界面。真实、已上线、按收入排名的应用程序编码了数千小时的设计迭代和 A/B 测试。你对任何界面的第一个动作都是研究：

1. 如果 **Appllama MCP** 已连接，请拉取你要构建的分类和界面类型的真实界面（有关确切的研究剧本，请参阅 `appllama-usage` 技能）。在编写一行 UI 代码之前，研究 20-30 个界面。
2. 提取 **模式而非像素**：布局骨架、信息层次结构、控制选择、间距韵律、主要 CTA 的位置、什么情况下使用插图而非纯文本、如何传达进度。
   注意：每个 Appllama 图片和视频在左上角都带有一个小型 Appllama 水印。它是来源，而非设计——在阅读界面时忽略它（它可能覆盖状态栏或返回按钮），并且永远不要在你构建的任何内容中复制它。
3. 然后设计 **你自己的** 界面：相同的骨架，你产品的声音。
   逐字复制竞争对手的界面是既懒惰又存在法律风险；发布一个忽略用户已知的所有约定的界面更糟。

## 平台基准

默认堆栈假设（如果项目已经不同，则仅覆盖）：

- **Expo + Expo Router**、React Native、TypeScript。
- `react-native-reanimated` 用于动画，`react-native-gesture-handler` 用于手势，`@shopify/flash-list`（或 FlashList v2）用于任何可增长的列表。
- `expo-image` 用于图片（并通过 iOS 上的 `source="sf:name"` 使用 SF Symbols），`expo-video` / `expo-audio`（永远不要使用已弃用的 `expo-av`）。
- `react-native-safe-area-context` 用于内边距。永远不要硬编码凹口数量。
- `process.env.EXPO_OS` 覆盖 `Platform.OS` 用于编译时平台检查。

## 本地保真度法则

这些是区分“包装中的网页”和“原生应用程序”的细节。违反其中任何一项都是发现，而非风格偏好。

1. **语义颜色，从一开始就使用两种主题**。使用系统/语义颜色标记（例如 iOS 上的 `expo-router` 中的 `Color`：`Color.ios.label`、`Color.ios.secondarySystemBackground`；Android 上的 Material 动态颜色）。每个界面必须在亮色和暗色模式下都正确渲染才能算完成。
   永远不要将语义颜色对象传递到 Reanimated 动画样式中——首先将其解析为字符串。
2. **原生控件优于重建的控件**。开关、滑块、分段控制器、上下文菜单、日期选择器：使用原生控件或忠实的包装器。一个动画与 iOS 开关不同 50 毫秒的重建切换会立刻显得不真实。
3. **使用 SF Symbols / Material Symbols 进行图标设计**。在 iOS 上优先使用 SF Symbols（使用 `expo-image` 带有 `sf:` 源，或 `expo-symbols`）；它们继承权重、光学大小和 Dynamic Type 行为。不要在一个界面上混合三种图标家族。
4. **排版是层次结构**。使用平台类型阶梯（iOS 上的 Large Title / Title / Headline / Body / Footnote）。每个界面只有一个显示大小。用于计数的任何内容、时间或价格使用表格式数字（`fontVariant: ['tabular-nums']`）。`Text selectable` 用于用户可能想要复制的用户数据。
5. **连续圆角**。每个圆角矩形上使用 `borderCurve: 'continuous'`。圆角矩形是存在的最便宜的感觉 iOS 的胜利。
6. **通过 CSS `boxShadow` 而非遗留 `shadow*`/`elevation` 属性实现阴影**。阴影用于提升逻辑，而非装饰——每个应用程序只有一个提升系统。
7. **间距韵律**。选择一个基本单位（4 或 8），并且永远不要离开它。优先使用 flexbox `gap` 而非边距堆叠。ScrollView 的内边距放在 `contentContainerStyle` 中，永远不要放在 ScrollView 本身上。
8. **安全区域和 Dynamic Island 是设计的一部分**。必须使用被滚动到岛屿/状态栏下的内容进行验证（模糊/淡化处理是否保持？），使用主指示器（底部 CTA 是否清除它？），如果支持则使用横屏模式。
9. **导航标题属于导航器**。尽可能使用堆栈的原生标题（iOS 上的大标题折叠行为）而不是手工编写的标题。
10. **触觉反馈是标点符号**。当值通过一个步骤时选择确认，当某物回到原位时轻击，对于结果提供通知成功/错误——在相同的帧上，每个用户动作一个，永远不要是唯一的反馈。永远不要在滚动时，永远不要在循环中。
11. **像产品一样格式化数字，而不是像数据库一样**：1.4M、38k、$4.99。删除尾随零。本地化日期。
12. **根滚动行为**：可以溢出的界面在路由中的第一个组件中用 `ScrollView` 包裹（`contentInsetAdjustmentBehavior="automatic"`）。使用 `useWindowDimensions`，永远不要使用 `Dimensions.get()`。

## 导航法则

导航是一个屏幕的截图无法显示的部分，用户在启动后的十秒钟内就能感受到它。每个过渡回答三个问题：目的地是什么，用户是否必须能够返回，以及返回后（箭头、iOS 边缘滑动、Android 硬件返回）会发生什么。

1. **推送更深，替换移动**。当用户想要返回时使用 `router.push`；`router.replace` / `<Redirect>` 当返回会进入世界已经过去的状态时；`router.dismissTo(href)` 用于“完成此流程并跳转到 X”。返回撤销 *导航*，而不是 *事件*。
2. **呈现具有意义**。一个自包含的任务有步骤 → `presentation: 'modal'` 并有其自己的堆栈和其自己的 Cancel/Done；一个简短的干扰（选择器、过滤器、项目选项）→ `formSheet` 带有 detents、拖动以关闭；沉浸式内容 → `fullScreenModal` 带有明确的关闭；一个浮现在仍然可见的屏幕上（确认卡、灯箱、教练标记）→ `transparentModal` 覆盖层；破坏性确认 → 动作表；项目操作 → 原生上下文菜单；分享/网页/照片选择 → 系统控制器，永远不要重建路由。一个增长第二步的表单是模态；如果链接可以打开它，它是一个路由，而不是 `useState` 表单。
3. **单门门离开堆栈**。在墙上应用程序上登录、完成入职（包括跳过）、购买、完成的会话：使用 `Stack.Protected` 进行保护，并使用 `replace` 落地，以便返回永远无法重新进入旧状态——Android 从主屏幕返回退出应用程序，而不是显示登录；付费的付费墙永远不会重新打开。但保留用户的 *位置*：由一个动作（保存、关注、购买）要求的登录是一个模态，覆盖在完成动作被点击的屏幕上，并且付费墙从功能中关闭会返回到功能，解锁——永远不要从那里使用 `replace('/(tabs)')`。
4. **在两种情况下阻塞返回**——一个正在进行的不可逆转的请求（几秒钟，有可见进度）和模态中的未保存工作（先询问），两者都通过模态的根屏幕上的 `usePreventRemove`。屏幕内的瞬时状态（选择模式、展开的搜索、打开的屏幕内表单）消耗第一个返回，然后返回离开。任何其他困住返回的东西——漏斗、评分提示——都是缺陷；边缘滑动在其余地方都有效。
5. **标签是同级**。标签之间没有滑动，每个标签保持自己的堆栈，重新点击活动标签会弹到其根；全注意力屏幕（作曲家、播放器、结账）位于标签根堆栈 *之上*。深度链接会带有真实的堆栈 underneath（`initialRouteName` / `withAnchor`）；冷启动会根据状态落地， splash 持续到会话状态解析完成——永远不要在 Home 之前显示登录。
6. **研究语法，而不仅仅是像素**。在 Appllama 上走一个成功的流程，注意每个步骤 *是什么*——推送、模态、表单——并复制这种一致性。

## 反滑法则

人工智能构建的应用程序共享外观，用户在几秒钟内就会将其归为“模板”。这些是 *默认禁止*——当品牌明确要求这样做并且你可以说明它为何适合这个产品时，总是有一个覆盖。

1. **没有 AI 默认样式**。带有发光的紫色/靛蓝色渐变 CTA、每个卡片上的玻璃形态、网格渐变英雄、小事件使用五彩纸屑、标题中的闪光——那是模型的房屋风格，不是设计。你的调色板、材料和布局来自你研究的参考界面，而不是你未经提示就会选择的先验。
2. **一个强调色，锁定**。选择一个强调色，它是每个屏幕上 *唯一的* 强调色——一个屏幕上的蓝色 CTA 和下一个屏幕上的青色，屏幕七上不会出现新的色调。中性色承载应用程序；强调色用于关键位置（主要操作、活动状态、进度）。
3. **一个灰色系列**。暖灰色或冷灰色——一个应用程序中永远不会两者兼有。
4. **形状锁定**。一个圆角半径规模，声明为规则（“操作是药丸，卡片 16，输入 8”），并且永远不要违反。没有声明规则的混合半径读作拼凑起来的。
5. **不要使用表情符号作为图标**。图标是 SF Symbols / Material Symbols（保真度法则 3）。表情符号仅在产品的声音真正是聊天原生或俏皮时出现——谨慎使用，在内容中，永远不要在装饰中。
6. **每个意图一个标签**。“开始使用”、“立即开始”和“开始”是相同的意图——选择一种措辞并在它出现的地方使用。
7. **强调保持在家族中**。用相同字体的重量或斜体强调一个词；将衬线字嵌入无衬线标题（反之亦然）以获得视觉兴趣是业余的。
8. **发布完整状态周期，而不是快乐路径**。仅静态成功状态是默认的失败模式：骨架必须匹配最终布局的形状，空状态是组合的（并说明如何填充它们），错误是内联的并且具体的。
9. **滑翔预飞行是机械的**。在任何流程到达模拟器之前，计算：不同的强调色（必须是 1）、不同的圆角半径（全部来自声明的规模）、UI 装饰中的表情符号（0）、没有品牌原因的渐变（0）、一个意图的重复标签（0）。失败的计算是一个修复，而不是一个判断。

## 动画法则

动画是最高杠杆的抛光表面，也是最容易过度设计的。按以下顺序决定：

- **频率门首先**。每天 100 次以上（标签切换、键盘、滚动、返回）→ 平台默认值和什么都不是；每天 10 次左右（按下、行选择）→ 几乎无法察觉，少于 150 毫秒；偶尔（表单、模态、toast）→ 标准动画；只有在罕见、第一次的时刻才提供惊喜。标签从不滑动；屏幕过渡保持原生。
  通过这个门，用零行代码通过就是成功——不确定时，最强的动作是删除动画。
- **用一个词命名目的**——反馈、空间连续性、状态变化、防止刺耳的切割、解释、惊喜——或者不构建它。用户正在阅读的数据永远不会因为风格而移动。
- **如果手指参与，它是弹簧**。从活动值开始（在抓取时捕获），将释放速度交给弹簧，从预测的动量中选择目标，以便一个挥手提交，越过边界，在飞行中保持可抓取。每个应用程序一个词汇——`{ duration: 400, dampingRatio: 1 }` 来稳定，`{ 300, 0.8 }` 用于表单——并且只有在手势携带动量时才弹回。
- **其他一切都是时间，少于 300 毫秒，强缓出**
  (`Easing.bezier(0.23, 1, 0.32, 1)`——内置曲线太弱；永远不要在入口时缓入）。按下反馈落在按下-*in*，100–150 毫秒：按钮和卡片上缩放 0.97，列表行上的背景高亮（永远不要缩放），条形按钮上的不透明度。退出比入口更快，并以它们来的方式离开；从 `scale(0.95)` + 淡入进入，永远不要 `scale(0)`；菜单从它们的触发器增长（居中的模态除外）。
- **手势→动画永远不会跳过 JS 线程**。工作线程 + 共享值（`.get()`/.`set()`；`scheduleOnRN` — Reanimated 4 的 `runOnJS` — 仅在手势结束时），`transform`/`opacity` 仅，没有在回收列表行上 `entering`，永远不要动画化头部的高度（在固定剪辑内内部转换），通过 `react-native-keyboard-controller` 的键盘跟踪 UI — 永远不要键盘监听器加上猜测的持续时间。
- **尊重 Reduce Motion**：你的空间动画折叠为交叉淡入淡出；原生过渡保持系统的。
- 标准线：60 fps 通过英雄流程，在您支持的最慢设备上的发布构建上测量——Expo Go 和开发构建隐藏了你正在寻找的卡顿
  ([references/performance.md](references/performance.md))。观看一次以获得感觉，一次逐帧，再次用新鲜的眼睛。

## 状态架构

感觉很好的屏幕是状态无聊的屏幕：

- **服务器状态**在 TanStack Query（或项目的等效方案）：缓存、重试、乐观更新。永远不要 `useEffect`+`fetch`。
- **客户端状态**在一个小的原子存储（Zustand/Jotai）。广泛的“应用程序状态”上下文会导致重新渲染级联，使 UI 感觉沉重。
- **瞬态 UI 状态**（打开/关闭、焦点、滚动）保持在组件本地。
- **默认乐观**：点击立即反映，在后台协调，失败时大声回滚。
- 未控制的 `TextInput` 用于高频输入表面；受控输入是导致输入卡顿的前三原因之一。
- 在 MMKV 中持久化微小的客户端状态，而不是 AsyncStorage，当延迟显示时。

## 感知性能

- 仅对于形状已知的 内容使用骨架；否则渐进式揭示。永远不要为部分更新使用全屏旋转器。
- FlashList 用于每个列表；提供稳定的键。
- 在按下时预加载下一个界面的数据，而不是在导航完成时。
- 图片：正确大小的源，列表中的 `expo-image` 带有 `recyclingKey`，缩略图哈希/模糊哈希占位符。
- 冷启动 TTI 和捆绑纪律生活在
  [references/performance.md](references/performance.md) — 应用测量 → 优化 → 重新测量循环，永远不要盲目的 memoization。

## 图片和插图资源

当屏幕需要插图、空状态艺术、英雄图像或符号集之外的图标时：

- 使用可用的 **最佳图像模型**（例如图像生成工具或连接的 Higgsfield MCP/CLI）在 **最高质量设置**下生成资源，然后缩小到 @1x/@2x/@3x。永远不要放大。
- 每个应用程序一个视觉语言：选择一个风格（渐变网格、平面双色调、3D-粘土、手绘、吉祥物风格）并在该风格中生成所有资源，相同的调色板，相同的照明。混合风格的资源集读作模板滑翔。
- 提供匹配您表面颜色的 **透明或实心平面背景**；复合伪影（白色光晕、错误颜色的磨光）是自动重做的。
- 完整资源管道和提示模式：
  [references/image-assets.md](references/image-assets.md)。

## 模拟器循环（非协商）

直到你看到它在运行，屏幕才存在。循环：

1. 实现 → 在 iOS 模拟器（或 Android 模拟器）中启动。
2. 截图并 **实际上查看**：对齐、光学中心、间距韵律、长内容截断、暗色模式、Dynamic Type 在 XL。
3. 运行 **完整动画通过**——截图证明布局；它们证明不了关于动画的任何东西。
4. 修复，重新启动，重新验证。重复直到你找不到缺陷——然后运行
   [references/simulator-loop.md](references/simulator-loop.md) 中的清单一次更多。

不要仅从代码审查中宣布屏幕完成。不要停在“看起来不错”——停在“在 100% 放大下找不到缺陷”。

每个流程都在模拟器中作为**动态画面**进行评估，而非静态画面。需要完整录制整个流程的屏幕录像（`xcrun simctl io booted recordVideo flow.mov`），并执行所有功能：

- 每个屏幕过渡、push/pop、标签切换
- 每个返回路径——箭头、边缘滑动、Android硬件返回——以及在每次单向门（登录、引导完成、购买、会话结束）后尝试返回并失败以重新进入旧状态
- 每个模态框和弹出面板：显示、拖动、关闭——并在拖动中途取消
- 键盘，双向操作：出现（布局是否平滑滑动，焦点输入是否可见？）和关闭（是否有画面跳切？）
- 每个用户交互：按压状态、手势跟随、中断的手势、快速点击、在边缘的快速滚动

观看录像**两次**：一次全速观看以感受流畅度，一次逐帧慢放。你正在寻找：

- 丢失或卡顿的帧——进度条在所有过渡期间持续**60 fps**，通过测量而非感觉来评估
- 单帧闪烁：白色/未样式化的首次绘制、过渡期间错误的主题帧、表面短暂渲染错误标记时的颜色突兀
- 布局跳变、双渲染突兀、弹簧裁剪或超出内容范围、元素出现后重新布局

整个录像必须像原生应用一样流畅——从始至终无UX故障。一个故障帧意味着流程未完成。

## 每个屏幕的完成定义

- [ ] 研究了10个以上此类屏幕类型的真实参考屏幕（通过Appllama MCP在可用时）并能够说出你采用的模式
- [ ] 导航已解决：这个屏幕是什么（push / 模态 / 弹出面板 / 覆盖层 / 替换），iOS和Android上的返回操作，以及——在单向门之后——返回不能重新进入旧状态
- [ ] 模拟器中验证了亮色和暗色模式
- [ ] 验证了安全区域 / 动态岛 / 主页指示器
- [ ] 设计了长内容、空、加载和错误状态——非默认设置
- [ ] 动画：完整流程屏幕录像并逐帧慢放——进入、按压、过渡、模态框、键盘——原生感觉，无故障或错误颜色帧；尊重Reduce Motion；在最低支持设备上的发布版本上测量60 fps
- [ ] Dynamic Type XL不会破坏布局；文本在有用处时可选择
- [ ] 所有点击目标≥44pt；两种主题下的对比度均通过
- [ ] 资产：单一风格家族，@3x时锐利，无合成光晕
- [ ] 列表表面虚拟化；无受控输入卡顿；无重绘风暴（通过分析而非猜测）
