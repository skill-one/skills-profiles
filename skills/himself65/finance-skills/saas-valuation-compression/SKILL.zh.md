# SaaS 估值压缩分析器

## 该技能的功能

针对给定的 SaaS 公司，研究其融资历史，并计算每轮融资时的 ARR 基估值倍数。然后使用结构化框架解释倍数的压缩（或扩张），该框架涵盖宏观利率、增长轨迹、叙事转变和可比公司。

以内联可视化（使用可视化工具）和简洁的文本解释的形式呈现输出，而不是一串数字。

---

## 工作流程

### 1. 通过网络搜索收集数据

并行运行独立搜索，研究以下内容：

- **目标公司的每轮融资** — 融资轮次名称、日期、融资金额、投后估值和主要投资者。
- **每轮融资日期附近的 ARR** — 从新闻报道、创始人访谈或投资者帖子中获取；注明何时为估算数据。
- **每轮融资周围的增长和留存** — ARR 增长率、NRR、流失率、重要客户。
- **叙事背景** — AI 定位和产品发布、行业领导地位、竞争举措。
- **每轮融资日期的私有市场 SaaS 倍数** — 搜索结果不足时，可参考 `references/benchmarks.md` 中的过时表格。

### 2. 构建数据模型

针对每轮融资，提取或估算以下信息：

| 字段 | 获取方式 |
|---|---|
| 融资轮次名称 | 直接从搜索结果获取 |
| 日期 | 直接从搜索结果获取 |
| 融资金额 | 直接从搜索结果获取 |
| 投后估值 | 直接获取或根据持股比例计算；若不可用，注明为估算值 |
| 融资日期的 ARR | 明确搜索；若未找到，根据客户数量 x ARPC 估算或插值 |
| ARR 倍数 | `估值 / ARR` |
| 主要投资者 | 直接获取 |

**ARR 估算启发式方法（当未公开时）：**
- 种子轮/天使轮：ARR 通常为 50 万–300 万美元
- A 轮：通常为 500 万–2000 万美元
- B 轮：通常为 2000 万–6000 万美元
- 若有客户数量 x 平均交易规模数据，可交叉验证

### 3. 计算 压缩指标

针对每对连续融资轮次（例如，B 轮 → C 轮）：

```
multiple_compression_pct = (later_multiple - earlier_multiple) / earlier_multiple × 100
valuation_growth_pct = (later_val - earlier_val) / earlier_val × 100
arr_growth_pct = (later_arr - earlier_arr) / earlier_arr × 100
```

这三个变化相乘而非相加：`valuation multiplier = ARR multiplier × multiple multiplier`，即 `(1 + valuation_growth) = (1 + arr_growth) × (1 + multiple_change)`。它们仅在对数术语中相加，因此在对分解需要求和时（例如，堆叠条形图）使用对数变化。如果 ARR 增长快于倍数压缩，绝对估值仍会上升。

### 4. 将压缩归因于原因

使用此清单。针对每个原因，评级：主要 / 贡献 / 不适用。`references/benchmarks.md` 包含按时期的过时私有市场中位数倍数、公开软件缩水额和已知轮次对可比公司，供参考。

**宏观 / 利率环境**
- 早期融资轮次是否在 2020–2021 年 ZIRP 泡沫期间定价？（通常为 2–5 倍的虚假溢价）
- 后续融资轮次是否在 2022–2023 年加息期间定价？（消除了泡沫溢价）
- 后续融资轮次是否在或刚结束一个行业范围内的公开软件抛售期间定价，例如 2026 年 4 月的崩盘？私有市场估值通常滞后于公开市场 1–2 个季度。
- 每轮融资的倍数与其日期的私有市场均值倍数相比如何？

**增长减速**
- 轮次之间的年 ARR 增长率是否显著放缓？（最常见的原因）
- NRR/净留存率是否下降？

**叙事转变**
- 公司是否失去了一个主要产品故事（例如，失去 PLG 理论，错失行业领导地位）？
- 竞争对手是否出现或现有竞争对手是否赶了上来？

**AI 溢价（正面或负面）**
- 公司是否为 AI 原生公司（如 OpenAI、Anthropic）提供客户？→ 溢价
- 公司是否可信地转向 AI 叙事？→ 溢价
- 公司未能阐明 AI 故事？→ 相比同行存在折价
- 在宏观驱动的抛售中，AI 溢价可能是必要的但并非充分条件——`references/benchmarks.md` 中 2026 年 4 月的缩水额显示，强劲的 AI 名称与行业一同下跌。

**竞争 / 市场**
- 市场饱和信号（例如，Okta 对 WorkOS 的压力，Auth0 的竞争）
- 客户集中度风险暴露

**投资者供给 / 需求**
- 后续融资轮次规模更小且更严格？→ 价格纪律
- 新的顶级主要投资者（例如，一级增长基金 vs 种子基金）？→ 可能表明更高的或更低的信心

### 5. 构建 可视化

使用可视化工具渲染：

1. **指标卡片行** — 每轮融资的估值、每轮融资的 ARR、每轮融资的倍数、压缩百分比
2. **折线图** — 公司的 ARR 倍数随时间变化 vs 宏观 SaaS 中位数
3. **条形图** — 估值增长 vs ARR 增长 vs 倍数变化（分解，以对数术语表示，使各部分相加）
4. **比较条形图** — 公司压缩 vs 2–3 个同行可比公司（Vercel、Netlify、Fastly 或行业同行）
5. **原因归因表格** — 按因素标注：主要 / 贡献 / 不适用

参考设计指南：使用蓝绿色表示正面/增长，珊瑚色表示压缩/负面，灰色表示宏观基准线，蓝色表示估值数据。始终遵循 CSS 变量系统。

### 6. 撰写 文本总结

按顺序涵盖：

1. **结论** — 一句话，例如，“倍数压缩了 36%，但 ARR 增长了 5 倍，因此绝对估值仍上升了约 3.2 倍。”
2. **主要原因** — 解释压缩的首要因素
3. **叙事溢价/折价** — AI 故事、行业领导地位或缺乏 thereof
4. **可比公司背景** — 该公司的压缩与同行相比如何
5. **未来影响** — 下一轮融资时需要满足什么条件才能使倍数扩张

## 输出格式

先放置内联可视化，然后是文本总结。当 ARR 需要估算时，标明数据置信度。

## 边缘情况

- **下调轮次**：倍数和绝对估值均下降。注意稀释影响。
- **无公开 ARR**：使用客户数量 x 估算的 ARPC，并标注为估算值，给出 +/- 范围。
- **单轮次**：计算该日期与行业均值的倍数；无法进行压缩分析。解释这一点。
- **营收前**：使用预测 ARR 或 GMV 倍数（若适用）；注意不同的基准。
- **收购 / 战略收购**：收购价格通常反映战略溢价或困境，而非纯粹的 ARR 倍数——标明这一点。
