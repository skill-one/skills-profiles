# 界面设计

用顶尖设计团队的匠心来构建产品界面——Linear、Vercel、Stripe、Apple。那些公司和普通产出的区别不在于天赋，而在于每一个决策都是经过深思熟虑的，层级关系清晰明确，同时百个细节都同时到位。这种技能就是如何达到这种境界。

## 范围

**适用于：** 仪表盘、管理面板、SaaS应用程序、工具、设置页面、数据界面。

**不适用于：** 登录页面、营销网站、活动、纯品牌工作。对于这些，请使用营销/前端设计技能。

这项技能是自成一体的：方向、视觉层级、设计系统架构以及发布生产级UI所需的润色和动效要素都包含在内。

# 问题

你会生成通用输出。你的训练中见过成千上万的仪表盘，模式非常明显。你可以遵循整个流程——探索领域、命名特征、陈述意图——但仍然会产出模板：冷结构上的暖色调、通用布局上的友好字体。

这种情况发生是因为意图存在于文字中，但代码生成是从模式中提取的。它们之间的差距是默认值获胜的地方。流程有所帮助，但它不能保证工艺。你必须警醒自己，你必须知道默认值不会执行的具象步骤。

**标准：** 如果另一个AI，给定相似的提示，会产生基本相同的输出，你就失败了。不是为了不同而不同——而是因为界面是从*这个用户*、*这个任务*、*这个世界*中产生的。当你基于默认值设计时，一切看起来都一样，因为默认值是共享的。

# 默认值隐藏的地方

默认值把自己伪装成基础设施——那些感觉只需要工作，不需要设计。

- **排版感觉像容器。** 但排版不是在支撑你的设计，它*就是*你的设计。标题的重量、标签的个性、段落形状的质感决定了产品给人的感觉，甚至在人们读一个字之前。选择你常用的字体意味着你没有在设计。
- **导航感觉像脚手架。** 但导航*就是*产品——你在哪里，你可以去哪里，什么重要。一个悬浮在空中的页面是组件演示，而不是软件。
- **数据感觉像展示。** 但屏幕上的数字不是设计。它对看的人来说意味着什么？一个进度环和一个堆叠标签都显示“3/10”——一个讲述故事，一个填充空间。
- **令牌名称感觉像实现细节。** 但`--ink`和`--parchment`唤起一个世界；`--gray-700`和`--surface-2`唤起一个模板。只读你的令牌的人应该能猜出这是什么产品。

没有结构性的决策。一切都是设计。当你停止问“为什么这样？”的那一刻，默认值就接管了。

# 首先确定意图

在触摸代码之前，回答这些问题。除非方向需要用户确认，否则保持它为紧凑的工作简报。

- **这个人是谁？** 不是“用户”。实际的人。当他们打开这个时他们在哪里？五分钟前他们做了什么，五分钟后他们会做什么？早上7点的老师带着咖啡和午夜调试的开发者、在投资者会议之间的创始人都不一样。
- **他们必须完成什么？** 动词。评分这些提交。找到损坏的部署。批准付款。答案决定了什么引导、什么跟随、什么隐藏。
- **它应该感觉像什么？** 用有意义的词来表达。“干净和现代”什么意思都没有——每个AI都这么说。像笔记本一样温暖？像终端一样冷？像交易大厅一样密集？像阅读应用程序一样平静？这塑造了颜色、排版、间距、密度——一切。

如果提示过于模糊以至于无法识别用户、任务和感觉，问一个简洁的问题。如果上下文允许负责任的假设，简要说明并继续。

**意图必须是系统的。** 说“温暖”然后使用冷色调不是贯彻意图。如果意图是温暖的：表面、文本、边框、强调色、语义颜色、排版——所有都是温暖的。如果是密集的：间距、字号、信息架构——所有都是密集的。对照声明的意图检查每个令牌。对于每个选择——布局、颜色温度、字体、间距比例、层级——你必须能够说明*为什么*。“很常见”或“它有效”意味着你使用了默认值。

# 产品领域探索

这是默认值被捕获或未被捕获的地方。通用路径：任务类型→视觉模板→主题。工艺路径：任务类型→产品领域→特征→结构+表达。区别在于在视觉思考之前在产品世界中花费的时间。

**在提出任何方向之前，产出所有四个：**

- **领域**——这个产品世界的概念、隐喻、词汇。不是功能——是领土。至少5个。
- **颜色世界**——这里自然存在什么颜色？不是“温暖”或“冷”——去实际的世界。如果这个产品是一个物理空间，你会看到什么？列出5个以上。
- **特征**——一个元素（视觉、结构或交互）只能是*这个产品*存在的。如果你不能命名一个，继续探索。
- **默认值**——这种界面类型3个明显的选择，视觉和结构。你不能避免你未命名的模式。

**测试：** 去掉产品名称，阅读你的提案。有人能识别它的用途吗？如果不能，继续探索。

# 在你能的时候渲染它

如果会话中提供内联视觉渲染工具（例如`show_widget`/`visualize`工具在对话中内联渲染HTML或SVG），优先考虑**展示**设计而不是描述它。被文字困住的方向不如一个人可以查看的方向有用。这是有条件的：当没有这样的工具时（CI、无头代理、普通终端），回退到代码、令牌和书面提案。永远不要假设工具存在；检查，然后使用它。

在三个时刻渲染：

1. **提出方向。** 沿着Suggest + Ask块，渲染一个小型实时样本：调色板作为实际色样、字号比例在真实字体中、表面提升步骤作为堆叠卡片、特征元素作为真实组件。人们应该看到“像笔记本一样温暖”，而不是阅读文字。
2. **设计组件。** 渲染实际组件（或紧密的之前/之后，两个变体并排）以便工艺决策——间距、边框、层级、状态——是可见的，而不是断言的。在它们重要的地方渲染真实状态（默认、悬停、空、错误）。
3. **评论或审计。** 将当前版本和改进版本一起渲染，以便差距是显示的，而不是叙述的。

渲染时的规则：

- 小部件只显示**视觉**。所有推理、领域探索、拒绝的默认值列表和建议都保留在你的响应文本中——永远不会将文字粘贴到小部件中。
- 匹配渲染工具自己的设计系统合同（如果它有的话，加载它的`read_me`/指导）。使用它的主题变量，以便样本继承亮/暗模式并自然地嵌入主机。不要与主机的边框战斗。
- 样本必须仍然通过以下检查。渲染的默认值仍然是默认值——渲染是让工艺*可见*的方式，而不是它的替代品。
- 这渲染到*对话*中，而不是到项目中。实际实现仍然通过正常编辑落到代码库中。

要点：将“这是我的思考”和“这是它看起来像”之间的循环压缩成一个人们可以反应的消息。

# 视觉层级与构图

“这看起来像设计”与“这看起来像生成”的最大驱动因素。默认值产生*扁平化*——所有大小、重量和间距都相同，所以没有引导，眼睛没有地方可去。工艺产生*层级*——眼睛立即知道什么重要。这些都是具体的步骤，不是感觉。

## 每个视图一个焦点

每个屏幕都有一个用户来做的任务。这件事主导——通过大小、对比度、位置或它周围的空格。当一切平等竞争时，什么都不会赢，界面看起来像停车场。在构建之前，大声说出焦点元素。然后让它赢：更大、更高对比度、或用空白环住。故意贬低其他一切。

## 字号比例是一个比率，重量胜过大小

不要凭感觉选择大小。选择一个比例并逐步进行：密集/平静UI约为1.2（小第三），大多数产品UI约为1.25，表达约为1.333。从14-16px的正文开始，得到一个*明显*不同的比例，而不是15/16/17的模糊。14px基础在1.25: `caption 11 · body 14 · h4 16 · h3 18 · h2 22 · h1 28 · display 44+`。四舍五入到整像素并到你的间距网格。

苹果/Linear的步骤：**重量和颜色比大小做更多层级工作。** 一个14px的大小通过重量+不透明度 alone 持有三个级别——`value: 600 / primary`，`label: 500 / secondary`，`meta: 400 / muted`——比两个常规重量两点分开更清晰地分离。从三个杠杆一起开始（大小、重量、颜色/不透明度），而不是单独的大小。如果你眯起眼睛，不能区分标题和正文和标签，层级太弱了。

工作示例——一个度量，扁平与决定。*扁平：* `Revenue` / `$48,200` 都 14px常规灰色，三个相同的盒子，没有焦点。*决定：* `REVENUE` 11px/500/muted/tracked · `$48,200` 28px/600/primary/tabular-nums（英雄） · `↑12%` 12px/500/success。相同数据，相反的可读性——数字通过大小+重量+一个强调色引导，标签被贬低，次要指标降至较低级别。

## 密度是一个决定，用px表达

Linear很紧凑；Stripe很宽敞。两者都不是默认值——两者都是*选择*的，选择是到处重复的相同数字。事先决定密度并命名值：工具面板在12-16px填充上感觉像工作台一样紧凑；相同的卡片在24px上感觉像小册子。相同的数字在一个上下文中可能是正确的，在另一个上下文中可能是懒惰的。故意选择，然后坚持。

## 空间节奏——不均匀地呼吸

伟大的界面不平等地间隔一切。密集的控制区域让位于开放的内容；重型元素平衡轻型元素；眼睛有目的地移动。单调布局——相同卡片大小、相同间隙、相同密度到处——是没有人在决定的声音。故意改变节奏：将紧密相关的项目分组，然后在组之间放真正的空气。

## 比例说话

280px侧边栏旁边全宽内容说“导航服务于内容”。360px侧边栏说“这些是平等的”。具体的数字声明了什么重要。如果你不能说明比例意味着什么，它就什么都没说。选择宽度和比率来声明关系。

## 分配和克制（“昂贵”的外观）

- **~60/30/10**：一个主导的中性表面、一个次要色调和~10%的强调色。颜色是一种稀缺资源——屏幕的大部分是结构。
- **一个强调色，有意图地使用**，胜过五个没有思考的颜色。灰色构建结构；颜色*传达*（状态、动作、身份）。无动机的颜色是噪音。
- **通过空间和重量而不是线条建立层级。** 优先考虑空白和色调变化，然后再考虑边框和分隔符。最昂贵的界面大部分是不可见结构。
- **大型字体的光学尺寸**：随着字体变大，收紧字间距（标题稍微负跟踪）；放宽正文行高以供可读性（~1.5）。紧凑的字体读起来像工艺；默认跟踪的32px标题读起来像文档。

# 工艺基础

## 微妙的分层（骨干）

无论方向如何，这都适用于一切。你应该*几乎感觉不到系统在运作*——当你看到Vercel的仪表盘时，你不会想“好的边框”，你只是理解结构。看不见的工艺就是工作的工艺。

**表面提升。** 表面堆叠：下拉菜单位于卡片上方，位于页面上方。建立一个编号系统——基础，然后增加级别。每个跳跃只有几个亮度的百分比——例如，暗模式基础→+7%→+9%→+12%；亮模式保持亮，并添加阴影而不是。你几乎无法在孤立中看到一步，但堆叠起来，层级就出现了。轻柔的微妙变化让你感觉到而不是看到。

- **侧边栏：** 与画布相同的背景，而不是不同的颜色。不同的颜色将空间分割成“侧边栏世界”和“内容世界”。一个微妙的边框就足够了。
- **下拉菜单/弹出窗口：** 比它们的父表面高一个级别，否则它们会混合在一起，分层就会丢失。
- **输入：** 比周围环境*稍暗*，而不是更亮。输入是内嵌的——它们接收内容。较暗的填充信号“在这里输入”，而不需要沉重的边框。

**边框。** 当你不需要结构时应该消失，但当你需要时应该可见。低不透明度的rgba与背景融合并定义一个边缘，而不需要要求注意力；与六进制边框相比，它看起来很刺眼。暗模式围绕`rgba(255,255,255,0.06–0.12)`，亮模式略高。建立一个进程——标准、更柔和的分离、强调、焦点环——并匹配边界的重要性强度。

**眯眼测试：** 在界面处眯起眼睛。你应该仍然感知到层级——什么在上面，什么在下面，哪里是分隔——但没有什么应该跳出来。没有刺眼的线条，没有刺耳的变化。只是安静的结构。做错了，其他一切都无关紧要。

## 无限表达

每个模式都有无限的表达——**没有两个界面应该看起来一样。** 一个度量显示可以是英雄数字、内联统计、火花线、仪表、进度条、比较增量或趋势徽章。相同的侧边栏宽度、相同的卡片网格、相同的图标-左侧-数字-大标签-小标签度量框每次*都表明是AI生成的*，并且是容易被忘记的。Linear的卡片不像Notion的；Vercel的度量不像Stripe的。相同的概念，无限表达。在构建之前，问：用户在这里做的唯一一件事是什么，什么产品解决了类似的问题并做得很好？

## 颜色存在于某个地方

每个产品都存在于一个世界中，这个世界有颜色。在拿起调色板之前，走进这个空间的物理版本——什么材料，什么光线，什么物体？你的调色板应该感觉像它来自*某个地方*，而不是应用于*某物*。温度是一个轴；还要问安静或响亮、密集或宽敞、严肃或有趣、几何或有机。一个交易终端和一个冥想应用程序都是“专注的”——完全不同类型的专注。

# 在编写每个组件之前

**每次**你编写UI代码——即使是小的添加——都要声明：

```
意图：     [谁是这个人，他们必须完成什么，它应该感觉如何]
层级：     [焦点元素，以及它如何获胜——大小 / 重量 / 对比度 / 空间]
调色板：   [从你的探索中来的颜色——以及为什么它们适合这个世界]
深度：     [边框 / 微妙的阴影 / 分层——以及为什么它适合意图]
表面：     [你的提升量表——以及为什么这个温度]
排版：     [字体+大小/重量/颜色杠杆——以及为什么]
间距：     [基础单位+选择的密度]
```

这个检查点是强制性的。如果你不能为每个解释*为什么*，你就是在使用默认值——停止思考。

1. **优先使用原生 HTML**，在它适用的地方。`<button>` 是按钮；`<a>` 是链接；`<input type="text">`、`<dialog>`、`<details>` 都存在。永远不要用 `<div onClick>` 来做平台已经提供的功能——你会免费失去焦点、键盘和语义化。
2. **一个经过实战检验的无头基础组件**，用于任何有状态且难以正确实现的功能——选择、组合框、对话框、弹出层、工具提示、下拉菜单、选项卡、日期选择器。这些组件自带键盘导航、焦点管理、ARIA 和碰撞/定位功能，这些功能需要花费数天才能正确实现。选择生态系统中已经受信任的组件（例如 Radix UI、React Aria、Ark、Headless UI、Vaul、React 中的 `cmdk`；其他框架中的等效可访问基础组件），然后根据你的方向进行样式化。"自定义构建"意味着 *组合和样式化基础组件*，而不是从零开始编写行为。
3. **仅在真正最后的绝路才手写**——没有基础组件适用，或者没有依赖预算。然后你需要承担完整的行为合同：键盘导航（箭头键、Enter、Escape）、焦点陷阱/返回、完整的 ARIA 角色/状态、点击外部、覆盖层的滚动锁定。一个缺少这些功能的样式化控件是损坏的，无论它看起来多么好。

## 样式：系统 → 组件 → 令牌 → 工具

1. **如果项目有设计系统，请使用它。** shadcn/`Button`、CVA 变体集、主题、组件库——在使用 `<Button variant="…"">` 和现有变体之前，不要编写一次性代码。匹配代码库的样式约定（Tailwind、CSS 模块、CSS-in-JS），不要引入自己的。
2. **当样式元素重复时，提取一个组件。** 九个按钮上使用相同的工具字符串是重复，不是设计。一个组件（或一个 CVA/变体）拥有它；调用位置保持干净。在第二次实际重用时提取，而不是第一次。
3. **绑定到语义令牌，而不是硬编码的常量。** `bg-card border-border text-muted-foreground`，而不是 `bg-white border-gray-200 text-gray-500`。硬编码的 `gray-200`/`#fff`/`px-4` 原始值是 Tailwind 形式的随机十六进制——它们会破坏主题和暗黑模式，并且不传递任何系统。（见令牌架构。）
4. **行内工具用于真正的单次使用**——一次性的布局调整。懒惰的迹象是 *相同的* 长类名到处喷洒；那是缺失的组件或令牌，而不是样式。

# 设计系统要点

每个精心制作的决策之下的令牌、间距和深度架构。

- **令牌架构。** 每种颜色都追溯到一小组基础元素：前景（文本）、背景（表面）、边框、品牌、语义（破坏性/警告/成功）。没有随机十六进制——所有内容都映射到基础元素。
- **文本层级——四个级别。** 主要、次要、三级、减弱（默认/辅助/元数据/禁用）。只使用两个意味着层级过于扁平。
- **间距。** 选择一个基本单位（4 或 8px），只使用倍数。根据上下文缩放：微观（图标间隙）、组件（按钮/卡片内）、部分（组之间）、主要（区域之间）。随机值表明没有系统。
- **填充。** 对称的——如果一侧有值，其他侧匹配，除非内容确实需要不对称。
- **深度——选择一个并坚持。** 只有边框（干净、技术、密集工具）、微弱阴影（平易近人）、分层阴影（高端、立体感）、表面颜色变化（色调、无阴影）。不要混合策略。
- **边框半径——一个比例。** 小用于输入/按钮，中用于卡片，大用于模态。不要随机混合锐利和柔和。
- **控件令牌。** 输入/选择/复选框获得专用的背景、边框和焦点令牌——不要重用表面令牌，以便可以独立调整控件。原生 `<select>`/`<input type="date">` 无法样式化——组合一个无头基础组件，而不是手写一个（见“使用现有组件”）。
- **暗黑模式。** 暗黑模式下阴影很弱——依赖边框。稍微降低语义颜色。相同的层级系统，反转值。保持一个色调；仅调整表面的亮度。

# 精细与动效要点

一百个小的细节会累积成“感觉很好”。这些是最高杠杆的细节——足够让 UI 真正精致。

## 静态精细

- **同心半径。** 嵌套的圆角元素：`outerRadius = innerRadius + padding`。父级和子级使用相同的半径是最常见的让 UI 感觉不对劲的原因。
- **表格数字。** 任何动态数字（计数器、价格、计时器、表格列）都使用 `font-variant-numeric: tabular-nums` 来防止布局偏移。
- **视觉对齐。** 当几何中心对齐看起来不对时，进行视觉修复——图标侧的填充 ≈ 文本侧 - 2px；播放三角形向右移动约 2px。
- **状态不是可选的。** 每个交互元素都需要默认、悬停、激活、焦点、禁用。数据需要加载、空、错误。缺少状态感觉是损坏的——它们是未完成界面的最快迹象。
- **点击区域——44×44px（WCAG），最小 40。** 如果可见控件更小（一个 20px 的复选框），使用伪元素扩展。永远不要让两个点击区域重叠。
- **阴影覆盖边框以提升。** 对于提升的卡片/按钮/容器，优先使用分层的透明 `box-shadow`（它可以适应任何背景）；保留真实的边框用于分隔符和输入轮廓。亮色模式提升堆叠三层——一个 1px 环 + 两个软深度，例如 `0 0 0 1px rgba(0,0,0,.06), 0 1px 2px -1px rgba(0,0,0,.06), 0 2px 4px rgba(0,0,0,.04)`；暗黑模式简化为一个环 `0 0 0 1px rgba(255,255,255,.08)`（深度阴影在暗黑模式下不可读）。
- **文本换行。** 标题上使用 `text-wrap: balance`；正文/标题上使用 `text-wrap: pretty` 来消除孤行。
- **字体平滑。** `-webkit-font-smoothing: antialiased` 在根目录上（macOS 否则会渲染得很重）。
- **图像轮廓。** 1px 内缩轮廓，纯 `rgba(0,0,0,0.1)` 浅色 / `rgba(255,255,255,0.1)` 深色——永远不要使用调色的深色/白色（边缘看起来像污垢）。

## 动效

动效应该是被感知，而不是被观看。快速、有目的性，并且 *永远* 不要碍事。

- **它需要动画吗？** 重复 100+ 次的交互（键盘快捷键、命令面板）**不**需要动画——它让它们感觉慢。偶尔的表面（模态、抽屉、提示）使用标准动画。罕见/首次运行的时刻可以增加乐趣。
- **UI 的持续时间 < 300ms。** 按钮点击 100–160ms；工具提示/弹出层 125–200ms；下拉菜单 150–250ms；模态/抽屉 200–500ms。一个 180ms 的下拉菜单比 400ms 的感觉更响应。
- **自定义缓出，永远不要缓入。** 内置曲线太弱。使用 `cubic-bezier(0.23, 1, 0.32, 1)` 用于进入/交互；缓入缓出 (`cubic-bezier(0.77, 0, 0.175, 1)`) 用于屏幕上的移动。`ease-in` 延迟第一帧——用户正在观看的时刻——并且感觉迟缓。
- **点击反馈。** `transform: scale(0.97)` 在 `:active` 上（永远不低于 0.95）。触觉确认 UI 听到了点击。
- **永远不要从 `scale(0)` 开始动画。** 什么都不会从无中生有——从 `scale(0.95)` + `opacity: 0` 开始。
- **源感知的弹出层。** 弹出层从触发器缩放（`transform-origin` 设置为触发器），而不是从中心。模态是例外——它们保持居中。
- **仅动画 `transform` 和 `opacity`**（GPU 组合）。动画宽度/高度/边距/填充会触发布局+绘制并丢帧。永远不要 `transition: all`——指定确切的属性。
- **错落有致地进入** 30–80ms 之间每个项目，以形成自然级联；保持退出比进入更快、更微妙。
- **尊重 `prefers-reduced-motion`**——保留不透明度/颜色过渡，移除运动。

# 避免

- **生硬的边框**——如果边框是第一眼看到的，它们太强了
- **剧烈的表面跳跃**——提升应该是轻柔的
- **扁平的层级**——所有元素一个大小/重量；没有明确的焦点
- **单调的布局**——相同的卡片大小、间隙和密度到处都是
- **不一致的间距**——没有系统的最明显迹象
- **混合深度策略**——选择一个并坚持
- **缺失状态**——悬停、焦点、禁用、加载、空、错误
- **剧烈的阴影**——微妙，不要吸引注意力
- **小元素上大的半径**；**厚的装饰性边框**
- **渐变和颜色用于装饰**——颜色应该有意义
- **多个强调色**——分散焦点
- **不同表面使用不同色调**——保持一个色调，仅调整亮度
- **默认排版**——系统/Inter 字体和仅大小层级，其中设置了方向
- **结构性技巧**——负边距抵消父级填充，逃生 `calc()`，绝对定位以规避布局流

# 工作流程

## 沟通
保持隐形。不要宣布模式或描述过程。永远不要说“我在 ESTABLISH 模式”或“让我查看 system.md”。直接进入工作；用理由陈述建议。

## 执行纪律
将此技能作为工作纪律，而不仅仅是建议。编辑 UI 时：

1. 检查现有应用、设计令牌、组件模式，如果存在，检查 `.interface-design/system.md`。
2. 在选择布局、颜色、类型、密度和导航之前，使领域探索具体化。
3. 对于绿色字段屏幕、重大改版或模糊方向，如果可用，考虑视觉参考传递 *（否则跳过——它是辅助，永远不会是交付物）*。四种模式：**方向板**（在编写代码前进行 2–3 次抽象情绪/材料/颜色探索——没有实际 UI），**UI 参考**（为选定方向的中保真度组合），**覆盖**（现有截图的更强版本），**光栅资源**（空状态艺术、纹理——永远不要图标/标志/图表）。始终拒绝通用的 SaaS、难以辨认的文本、域外调色板；提取调色板/密度/比例/签名，然后在真实代码中构建并验证在浏览器中。
4. 修补实现，然后在可用时运行相关的构建/类型检查/测试。
5. 对于非平凡的 UI，进行视觉验证。使用行内渲染工具、本地浏览器或桌面和移动宽度的截图；在展示之前修复重叠、损坏的间距、空白状态、难以辨认的文本、缺失的资源和通用组合。
6. 保持面向用户的更新简短。不要暴露冗长的私人设计独白——展示有用的建议或决定。

## 建议 + 询问
以探索和建议为先，然后确认：

```
领域：     [产品世界中 5+ 个概念]
颜色世界：[该领域中 5+ 种颜色]
签名：     [该产品独有的一个元素]
拒绝：     [默认 1] → [替代方案]，[默认 2] → [替代方案]，[默认 3] → [替代方案]
方向：     [连接上述内容的方案]
```

然后询问：“这个方向感觉对吗？” 如果有行内渲染工具，在同一消息中渲染该方向的实时样本——显示调色板、类型和签名，不要只命名它们。

## 构建流程
- **如果存在 `.interface-design/system.md`：** 阅读并应用——决策已做出。
- **如果不存在：** 探索领域（所有四个输出）→ 建议（参考所有四个）→ 当方向模糊或更改成本高昂时确认 → 构建 → 运行下面的检查 → 提供保存。

## 检查（展示之前）
对你的输出运行这些；如果任何一项失败，在展示之前进行迭代。

- **交换测试**——将你的字体换成常用的，你的布局换成标准模板：会感觉有任何不同吗？交换不会影响的地方是默认设置的地方。
- **眯眼测试**——眯起眼睛：层级仍然可读吗？没有任何东西突兀地跳出来？
- **签名测试**——指向五个特定的地方，你的签名出现的地方。“整体感觉”不计入其中。
- **令牌测试**——大声朗读你的 CSS 变量：它们属于这个产品世界，还是任何项目？

# 完成一个任务后

始终提供保存：“想我保存这些模式供未来会话使用吗？” 如果是，写入 `.interface-design/system.md`：

- 方向和感觉
- 深度策略（边框/阴影/分层）和间距基本单位
- 层级决策（类型比例、密度值、焦点模式）
- 关键组件模式——当组件使用 2+ 次、可重用或具有值得记忆的测量值时（不是一次性或属性变体）添加。记录值，例如 `Button primary — 36px h · 12px 16px pad · 6px radius · 14px/500`。
- 视觉方向笔记和选择的参考，当图像传递塑造了设计时

**一致性检查。** 如果 system.md 定义了值，坚持它们：网格上的间距，整个深度策略，调色板中的颜色，记录的模式重复使用而不是重新发明。这会累积——每次保存都会让未来的工作更快、更一致。
