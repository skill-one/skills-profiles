# YouTube 缩略图

## Codex 和 Claude 运行时

- 在 Codex 或 Claude 中使用此技能时，请使用当前任务中实际可用的工具。`AskUserQuestion` 示例描述的是问题，而不是必需的 API：在可用问题工具的范围内使用它，或在聊天中提问。重用已提供的答案和源材料。
- 在用户选择的项目中工作。在个性化工作之前，阅读其 `about-me.md`、`voice.md` 和相关的品牌文件。如果文件冲突或包含起始默认值，请确认预期的作者。询问缺失的事实或运行 `voice-builder`；切勿继承维护者的身份、帐户或私人文件。
- 解析相对于此技能文件夹捆绑的 `references/`。对于明确请求的配置文件刷新，请读取并更新规范 `about-me.md`、`voice.md` 或 `newsletter-voice.md`，同时保留无关的用户事实和规则。消费者必须重新阅读这些规范文件。仅对新的交付成果使用新文件名，以避免与无关的现有文件冲突。单独安装永远不会开始访谈或写入文件。除非要求，否则不要写入持久学习。

- 首先使用提供的证据。当需要时，通过可用的搜索/源工具验证外部声明。如果某个源或集成不可用，请命名缺失的功能并提供建议的文本/导出输入。切勿编造事实、第一人称经历、指标或成功的工具运行。

- 仅连接用户现有帐户中选择的路线所需的服务。切勿打印凭证或覆盖连接。起草、保存和审阅不会授权发布、发送消息或更改帐户。

## 视觉完成状态

此技能的图像提示是**准备就绪的提示**，而不是生成或视觉审查的资产。除非用户请求其他生成器，否则请保留其命名的 Gemini 工作流。缺少图像服务不会阻止编写提示。当提供或生成图像时，请在全尺寸和导出尺寸（约 360 像素宽，320 像素用于缩略图）下打开并检查每个导出。检查精确文本、尺寸、裁剪、可读性、品牌颜色、字体外观、标志和参考保真度。修复并重新检查失败的导出。将任何不可用的导出或检查记录为待办事项。图像提示或光栅导出不是可编辑的设计文件。

## 关键：加载时自动启动

当此技能触发时，请直接进入步骤 1。

## 步骤 1. 收集输入

检查项目中是否有参考照片配置。按以下顺序查找：

1. 项目根目录中的 `thumbnail-config.md`
2. `brand-kit.md` — 查找参考图像路径和品牌颜色
3. `about-me.md` — 用于创作者的姓名和定位

如果存储了参考照片路径，请预先填写它。否则请询问：

> 上传或提供您希望在缩略图中使用的参考照片的路径。理想情况下，应使用清晰的人像、独特的照明和表情，您计划在视频中重复使用以保持品牌一致性。

然后调用 AskUserQuestion：

```json
[
  {
    "question": "视频标题是什么？",
    "header": "标题",
    "multiSelect": false,
    "options": [
      {"label": "我将输入标题", "description": "输入完整的有效标题"},
      {"label": "建议一个", "description": "根据主题，首先提出 3 个吸引点击的标题"}
    ]
  },
  {
    "question": "情绪基调？",
    "header": "基调",
    "multiSelect": false,
    "options": [
      {"label": "震惊 / 惊喜", "description": "大眼睛、张嘴、大胆反应"},
      {"label": "好奇 / 思考", "description": "轻微的微笑、扬起的眉毛、目光偏离画面"},
      {"label": "自信 / 直接", "description": "眼神接触、冷静、自信"},
      {"label": "沮丧 / 强烈观点", "description": "强烈的目光、手势、紧张"}
    ]
  }
]
```

确认标题并针对视频提供的內容做出承诺。不要编造结果，暗示存在演示，或使用未提供的面孔或品牌标记。缺少参考照片会使基于照片的生成待定，而构图简报仍然可以起草。

## 步骤 2. 应用缩略图最佳实践

每个缩略图都必须遵循以下规则：

- **面孔占据 30 到 50 百分比**的框架。在小尺寸下可读。
- **最多 3 到 5 个字**的大文本。如果绝对必要，可以是 6 个。
- **两种颜色主导**。品牌主色 + 一种高对比度的强调色（黄色、红色、青色效果很好）。
- **一个清晰的焦点元素**，除了面孔。工具标志、粗体数字、箭头或道具。
- **面孔、文本和背景之间的高对比度**。通过眯眼来测试。
- **文本不是句子**。它是一个钩子短语。示例："我解雇了我的团队"、"Claude 现在可以..."、"不要这样做"。
- **不要使用小文本，不要在右下角使用标志**（观看时间图标位于那里）。

## 步骤 3. 构建缩略图简报

输出用户可以审查的简洁简报：

```
缩略图简报：[视频标题]

构图：[面孔位置、占框架的百分比、目光方向]
文本："[钩子短语，3-5 个字]"
文本位置：[左、右、顶部、围绕面孔]
调色板：[主色调十六进制]、[强调色十六进制]、[背景色十六进制]
辅助元素：[标志 / 道具 / 箭头 / 数字]
情绪基调：[步骤 1 中的基调]
```

然后询问：

> 这是简报。说 "generate" 以输出图像提示，或告诉我如何更改。

## 步骤 4. 输出 Gemini 提示

一旦批准，以代码块的形式输出图像生成提示：

```
使用附带的我的参考照片，生成 1280 x 720 像素（16:9）的 YouTube 缩略图。

构图：
- 将我放在 [左 / 右 / 中间] 填充 [30-50]% 的框架
- 我的表情：[基调细节 — 例如，震惊，眼睛睁大，嘴巴张开]
- 我的目光：[方向 — 例如，直视相机 / 目光偏离画面朝向文本]

文本：
- 显示 "[钩子短语]" 在大粗体无衬线字体中
- 文本颜色：[十六进制]
- 文本轮廓：[颜色、厚度以提高可读性]
- 文本位置：[特定区域]

调色板：
- 主色：[十六进制]
- 强调色：[十六进制]
- 背景：[十六进制] — [描述处理：平面、渐变、模糊场景等]

辅助元素：[对辅助视觉的特定描述]

约束：
- 面孔必须清晰锐利
- 文本在小尺寸（320 像素宽，YouTube 移动尺寸）下必须可读
- 没有水印，没有 YouTube UI 元素，没有右下角文本
- 面孔、文本和背景之间的高对比度
```

告诉用户：

> 将此内容粘贴到新的 Gemini 聊天中，附加您的参考照片，启用 Create Image，并选择 Nano Banana。在 1280x720 下生成。

## 步骤 5. 提供下一步行动

> 要我概述视频吗？缩略图的钩子、中段、CTA。

## 规则

- 1280x720 像素（16:9）。YouTube 的原生缩略图尺寸。
- 不要在提示本身中包含参考照片路径 — 用户将照片单独附加。
- 不要允许超过 6 个字的文本，5 个是理想的，3 个是最好的。
- 面孔必须始终是一个可见的焦点。没有隐藏面孔的构图。
- 不要使用破折号。
- 除非 `voice.md` 指定否则使用英式英语。
- 如果项目中包含 `brand-kit.md`，请读取并使用确切的品牌颜色。
- 建议用户在视频中保持一致的缩略图风格，以便于频道识别。
