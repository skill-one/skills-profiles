# 应用表单填写工具

## 使用此技能的时机

当用户需要时使用此技能：
- 回答工作申请表中的具体问题
- 填写 Greenhouse、Lever、Ashby、Workday 或任何申请人跟踪系统（ATS）上的文本字段
- 撰写对“请告诉我们关于您自己的情况”或“您为什么想来我们公司”提示的回复
- 获取干净、可复制粘贴的申请问题答案
- 提及：“填写这个”、“这里我该写什么”、“回答这个问题”、“申请表”、“表单字段”

## 核心原则

申请表答案应直接具体——不是把求职信塞进文本框。每个字段都有其目的。清晰回答其目的，然后停止。

**答案应该感觉像：** 真实的人输入的，而不是模板填写的结果。

## 回答前须知

始终阅读：
1. **职位描述** — 模仿其语言和优先事项
2. **候选人的简历/个人资料** — 提取真实的项目、角色和指标
3. **具体问题** — 精确回答所问，而不是你希望被问的问题

如果用户没有提供简历或职位描述，在撰写前先询问。

## 问题类型及处理方法

---

### 类型 1：经验/背景问题

**示例：**
- “您在[技术]方面有多少年的经验？”
- “描述您在[领域]方面的经验”
- “您使用过哪些后端框架？”

**格式：**
```
[技术/技能] — [X年]。[一句话说明您用它来做什么，以及具体项目或背景]。[可选：同一类别的其他工具]。
```

**规则：**
- 以最常用/相关的技术开头
- 如实给出年限——不要夸大
- 将每个声明与真实项目或角色挂钩
- 对于“描述经验”问题：最多2-4句话，每句话一个项目
- 如果经验是间接的（相邻领域），请说明并转向相关内容

---

### 类型 2：为什么这家公司 / 您的兴趣点

**示例：**
- “您为什么想加入[公司]？”
- “您对这个角色有什么兴趣？”
- “您为什么适合这个职位？”

**格式：**
```
关于公司/角色的具体之处，让您真正感兴趣——不是泛泛而谈。
这与候选人实际做过的工作如何联系。
[可选：关于这个领域，而不仅仅是这家公司的一行话]。
```

**规则：**
- 必须针对这家公司——不能是陈词滥调
- 如有必要，在回答前研究公司
- 与真实工作联系，而不是愿望
- 对于表单字段，保持在150字以内
- 不要把职位描述原封不动地回复给他们

---

### 类型 3：作品集 / 工作样本

**示例：**
- “包含您引以为傲的其他任何工作样本”
- “链接到相关的项目或代码库”
- “描述您完整构建的一个项目”

**格式：**
用一句话描述和链接列出项目。以最相关的项目开头。

```
[项目名称] ([在线链接] | [GitHub链接]) — [一句话：是什么以及一个证明点]。[技术栈，如相关]。
```

**规则：**
- 只包含与职位相关的项目
- 始终包含链接（在线演示 > GitHub > 无）
- 如果项目有付费用户或可衡量的使用量，请说明——一次即可
- 不要用不相关的项目来显得经验丰富

---

### 类型 4：技术技能问题

**示例：**
- “您使用得最广泛的前端框架是哪些？”
- “您在Python方面的熟练程度如何？”
- “描述您在云基础设施方面的经验”

**格式：**
对于文本字段：
```
[主要技能] — [X年]。[具体用途：您用它构建了什么，在什么背景下]。
[次要技能] — [X年]。[相同]。
[诚实地说明任何相关差距]。
```

对于评分/下拉菜单字段：选择诚实的水平——如果不够准确，不要为了最高评分而优化。

**规则：**
- 年限+背景比年限单独更好
- 承认差距而不是隐藏它们
- 如果被要求评分，要诚实——虚高的评分会在技术面试中造成问题
- 对于您使用过但最近未使用的技术栈，请说明

---

### 类型 5：开放式/“告诉我们关于您自己的情况”

**示例：**
- “告诉我们关于您自己的情况”
- “描述您的职业背景”
- “您在下一个角色中寻找什么？”

**格式：**
```
当前角色及您在那里做什么（1句话）。
相关的先前经验，简要（1句话）。
您想要什么/为什么这个角色（1-2句话——针对公司）。
可选：一个相关的项目或业余工作（1句话）。
```

**规则：**
- 从当前角色开始，而不是教育背景
- 对于大多数表单字段，保持在100-200字
- 以前瞻性的笔记结束（您想要什么，而不是您在哪里）
- 不要特质声明（“我对……充满热情”）——只是事实和项目

---

### 类型 6：情境/行为问题

**示例：**
- “描述您解决复杂技术问题的一次经历”
- “告诉我们关于您完整领导的一个项目”
- “您如何处理跨多个团队的工作？”

**格式：** 精简的STAR（无标签，仅流程）

```
[一句话说明背景]。[您具体做了什么——2句话]。[结果，如有可能，附带指标——1句话]。
```

**规则：**
- 要具体——说出项目、技术、团队规模
- 不要泛泛而谈（“我总是通过……来解决问题”）
- 保持到150-250字
- 全程使用第一人称、主动语态
- 以结果结尾，而不是学到的教训（面试时再谈）

---

### 类型 7：观点/愿景问题

**示例：**
- “您认为未来最重要的技术是哪些？”
- “如果您有无限时间，您会学习什么？”
- “您认为AI/[领域]在5年后会怎样？”

**格式：**
用真诚的观点回答。选择一到两件事并简要解释理由。

**规则：**
- 有一个实际的观点——模糊的答案容易被忘记
- 将观点建立在领域知识或真实经验之上
- 保持到100-150字
- 不要对一切都犹豫——坚持一个观点，承认这只是其中一种视角

---

## 输出格式

始终用纯代码块包装答案，以便干净地复制粘贴：

```
[答案文本]
```

如果提供多个答案（每个字段一个），使用标签并在每个代码块上方使用标签：

**React经验年限：**
```
4年。用于Screenr（智能招聘SaaS）、一个基于Tauri的POS系统以及几个客户项目。Next.js用于需要SSR的地方。
```

**描述您的后端经验：**
```
...
```

## 长度校准

| 字段类型 | 目标长度 |
|------------|---------------|
| 单行文本 | 1句话 |
| 简短回答 | 2-4句话 |
| 长回答/文本区域 | 100-250字 |
| “描述您的经验” | 150-300字 |
| “告诉我们关于您自己的情况” | 100-200字 |
| 作品集/链接部分 | 列表格式，无散文 |

不确定时，短一些更好。招聘人员会快速浏览表单答案。目标是清晰且令人难忘，而不是全面。

## 常见错误避免

**重复职位描述：**
❌ “我对这个角色感兴趣，因为您正在寻找一个能够构建可扩展后端系统的人……”
✅ “吸引我的是实时限制——毫秒级的医疗数据延迟是大多数后端工作的不同级别问题。”

**泛泛的特质声明：**
❌ “我是一个快速学习者，在协作环境中茁壮成长”
✅ [只描述实际工作——特质会自然显现]

**过度资格：**
❌ “虽然我可能没有正好5年，但我相信我的经验……”
✅ “职位提到5年——我3年，但我交付的系统是面向生产环境的。”

**无背景的列表：**
❌ "React, Vue, Angular, Next.js, TypeScript, Node.js..."
✅ "React是我的主要前端框架——4年用于Screenr和几个客户项目。Vue和Angular各约3年，主要用于仪表板和管理工具。”

**填充空间：**
❌ 添加不相关的项目或经验只是为了显得经验丰富
✅ 只包含与这个特定角色相关的部分
