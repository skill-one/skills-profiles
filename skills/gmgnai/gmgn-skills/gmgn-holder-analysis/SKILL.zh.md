## 分析脚本

运行以下命令，将占位符替换为实际值：

```bash
python3 ~/.claude/skills/gmgn-holder-analysis/analyze.py <FILL_IN_TOKEN_ADDRESS> <FILL_IN_CHAIN> <FILL_IN_LANG>
```

- FILL_IN_CHAIN: 对于 Solana 地址使用 `sol`；对于 EVM `0x...` 地址，除非用户明确指定链（`bsc`/`eth`/`base`），否则使用 `auto`
- FILL_IN_LANG: 如果用户使用中文，则为 `zh`；如果使用英文，则为 `en`，默认为 `zh`

## 输出规则

脚本完成后，将完整的 stdout 原封不动地粘贴到您的回复中——每一行、每一部分，不得遗漏或总结。在输出块之前或之后不要添加任何引言、评论或总结。

## 字段参考

脚本打印的所有持有百分比都是**可交易流通量的份额**（`1 - 燃烧 - DEX`），而不是总供应量的份额。API 中的 `amount_percentage` 是总供应量的份额；脚本会重新计算。由于只获取前 100 名持有人，当这 100 个钱包无法覆盖整个流通量时，流通量百分比是一个下限；页脚报告实际覆盖情况，并说明哪种情况适用——覆盖率 <99.5% 时显示下限，前 100 名覆盖全部时显示完整值。

当燃烧 + DEX 留下的可交易供应量低于 2%（通常是迁移前的启动板代币）时，流通量分母会退化：每个 `/ float_share` 都会使尘埃钱包膨胀到两位数或 100%。脚本会检测到这种情况，打印带有绝对代币/美元数字的横幅，并将评级设置为 ⚪ 无法评估。

当 `token holders` 返回空列表时（代币没有活跃持有人或上游停止索引），所有百分比都会显示为 0.00%，所有阈值都会通过，否则报告会显示“✅ 正常——无明显倾销风险”。脚本会打印无数据横幅，将每个“none found 🟢”行替换为 ⚪，并评级为 ⚪ 无法评估。“无数据”永远不会报告为“无风险”。

在这两种情况下**都不会打印任何流通量百分比**——每个都会显示为 `n/a`（无法评估），每个百分比标志都会显示 ⚪。带有保留说明打印数字是不够的：除以零的流通量会使 `hold 100.00%` 和 `hold 0.00%` 出现在同一报告中，而快速浏览横幅的读者会将 `Rat Trader 1 hold 100.00%` 视为一个发现。钱包数量、代币金额、美元价值和市值仍然会打印——它们不会通过 `float_share`。

基于**总供应量**的百分比仍然会打印（`burn`、`DEX`、流通量份额本身以及芯片质量桶），因为这些分母不受影响。

### “零成本”必须被证明，而不是从缺失的购买次数中推断

`buy_tx_count_cur == 0` 并不意味着钱包免费收到了其筹码。在 musebook（robinhood）上测量：38 个钱包读取 `buy_tx_count_cur: 0` 和 `avg_cost: null`，但其中 **34 个钱包的 `unrealized_pnl` 比率是有限的**（+2.7%、+76.5%、+546%），这个比率无法在没有成本基础的情况下计算，而 32 个钱包带有 `fomo` 前端标签，2 个带有 `gmgn` 标签，这是活跃交易的痕迹，与收到空投相反。实际上缺失的是该链上的购买交易索引，而 PnL 字段来自单独的计算，并且已填充。

错误是按链系统性的，而不是按代币。从未购买供应量的份额相同批次：
**robinhood 27.0% 和 41.2%，arc 26.3%，sol 4.8%。** 20% 空投警告门因此几乎在所有 robinhood/arc 代币上触发，而在 sol 代币上几乎不触发——这是索引覆盖率的差异，而不是芯片结构的差异。将未填充的字段报告为风险结论正是这个技能禁止的。

因此，只有当**完全不存在任何成本证据**时，钱包才被视为零成本：

```python
def has_cost_basis(h):
    return (h.get('avg_cost') or 0) > 0 or h.get('unrealized_pnl') is not None
```

没有索引购买次数但有真实成本基础的钱包**不会从报告中删除**——它们会得到自己的中性行，`买入未记录 / Buy count unindexed`，并显示其流通量份额。上游没有索引它们的购买这一事实是真实的，并且保持可见；它只是不会驱动零成本门。相同的谓词现在管理 `钻石手 / Diamond` 群组（其声明的理由是“一个从未付款的钱包没有持有成本”，这被已证明的成本基础满足），`转入筹码未动 / Idle airdrop` 行（其“零成本”标题对于这些钱包是错误的陈述），以及 Top5 卖出风险分类（将 +6.6x 的钱包标记为“零成本空投——可以随时倾销”）。

已知限制：一个真实的空投钱包，其 `unrealized_pnl` 是相对于尘埃级成本计算出的巨大比率，在这里会被遗漏。没有为它设置第二个比率阈值——没有可测量的样本来校准它。

### 代币自己的合约地址不是持有人钱包

上游将其作为普通钱包返回——在 musebook（robinhood）上测量：`addr_type: 0`，0 次购买，0 次卖出，15.01% 的总供应量，$5.06M，带有 `fresh_wallet` 标签。如果将其保留在钱包群组中，它会污染 `biggest`、Top10/Top20、空投、新鲜、风险钱包和 Top5，并且它自己会触发 🔴 危险门，因为“最大钱包持有 16.30%——极端集中”。该代币上最大的真实钱包供应量为 4.10%。同一批次的控制——JOLLY（robinhood）、SI（sol）、ARGUS（arc）——没有这样的行，所以这是每个代币上游分类的差距，而不是链惯例。

因此，脚本将其从 `normal` 中分离出来，并单独报告，以**总供应量**为基础（`合约自持 / Contract self-held`），并为其设置 >10% 供应量的警告门。它**不会**从判断中移除：合约持有供应量在释放交易落地时立即进入市场，因此它仍然可见，并且仍然计入评级。这是一个警告而不是危险，因为释放是一个可观察的先验步骤，而鲸鱼可以随时卖出——并且没有更高的危险等级，因为只有一个样本被测量，并且基于一个样本的第二个阈值将是猜测。

它被故意**不**从流通量分母中扣除。燃烧是永久性的，而 DEX 池本身就是市场，所以它们不会倾销；自持供应量可以。将其从分母中扣除会提高每个携带此行的代币上其他钱包的百分比，制造新的假阳性，同时修复一个。

相同的地址也排除在开发者幽灵映射之外：发送回代币合约的芯片或支付给它的 gas 不是“转移到内部钱包”。

## 评级标准

所有以下阈值都是**可交易流通量的份额**，与脚本匹配。它们与 GMGN 自己的 UI 不可比——GMGN 的 UI 报告总供应量的份额——在代币的 LP 持有 56% 的供应量时，相同的钱包在这里会显示 2.4 倍更高。

建议部分会打印**每个**触发的理由，而不仅仅是第一个：⚠️ 谨慎评级意味着定义上触发了两个或多个警告，因此打印一个会让读者无法知道评级为什么是这个。

进入时间压力（批次浮盈/出货）**不会**影响整体评级——它只会影响部分显示。

| 评级（ZH） | 评级（EN） | Emoji | 条件 |
|-------------|-------------|-------|-----------|
| 无法评估 | Cannot Assess | ⚪ | 可交易流通量 <2% 的供应量，**或** 上游返回零持有人（所有百分比规则被抑制；开发者幽灵仍然升级为 🔴） |
| 不建议买 | Not Recommended | 🔴 | 任何：Rat traders >5% / 最大钱包 >10% / 开发者幽灵 |

| 谨慎参与 | Caution | ⚠️ | ≥2 的：开发者仍然持有 >1% / 空投 >20% / 风险钱包 >35% / 关联 >15% / 合约自持 >10% 的供应量 |
| 可轻仓   | Light Position | 🟡 | 恰好 1 个上述警告 |
| 正常参与 | Normal | ✅ | 以上所有均无 |

### 每个指标的标志阈值

| 指标 | 🔴 | 🟡 | 🟢 |
|--------|----|----|----|
| Top10 集中度 | >60% | >40% | ≤40% |
| Top20 集中度 | >75% | >55% | ≤55% |
| 空投芯片（从未购买） | >25% | >10% | ≤10% |
| 风险钱包 | >35% | >15% | ≤15% |
| 关联资金 | >25% | >10% | ≤10% |
| 零余额钱包 | — | >10% | ≤10% |

钻石手反向（越多越好）并使用自己的 Emoji 集合：✅ >60% / 🟡 >35% / ⚠️ ≤35%。钻石手需要**成本基础**（上文的 `has_cost_basis`）——一个从未付款的钱包没有持有成本，因此真实的零成本接收者会单独报告为“转入筹码未动 / Idle airdrop”，而不是被计为钻石手。测试的是成本基础，而不是 `buy_tx_count_cur > 0`：在购买次数未索引的链上，后者会丢弃大多数真实的钻石手（在 JOLLY 上测量：34 → 75 个钱包，21.1% → 55.7% 的流通量）。

关联资金在任何组内都在 60 秒内资助时都会至少升级为 🟡，无论大小——脚本批处理资助是一个结构性信号，而不是幅度信号。

### 芯片质量（页脚）

在观察到的钱包持有的芯片上，三个互斥的桶（分母是 `normal_pct`，即基于总供应量，而不是流通量）：**无风险标签购买** / **零成本空投**（由 `has_cost_basis`，上文——不是由缺失的购买次数） / **风险标签**。它们被单独报告，而不是合并为一个“健康芯片”数字，因为风险标签意味着一个已证明是坏地址，而零成本空投只意味着来源未知。

标题标志，第一个匹配者胜出：🔴 风险标签 >30% · 🟢 干净 ≥50% · 🟡 干净 ≥30% · 🟡 当零成本空投占非干净剩余的 ≥80% · 🔴 其他。因此，空投分配的代币会以 🟡 显示其成分，而不是“健康芯片 0.0% 🔴”。

成分是基于总供应量的，因此它会在退化的流通量中幸存，并且它的三个百分比仍然会打印——但每当评级为 ⚪ 无法评估时，标题标志会被中性化为 ⚪（并且芯片的供应量份额会附加），因为 🔴/🟢 裁决在尘埃级芯片上会与上面的评级矛盾。

## 开发者查找是双源的

`token holders --tag dev` 是主要来源，但在某些启动板上返回 `{"list": []}`——在 robinhood 的 24 小时趋势 Top 50 中的所有五个银行代币上测量，而 pons_v2 / longxyz 代币在同一链上正常返回创建者。它也可以返回没有任何 `creator` 标签的行（在 bsc 上的一个 flap 代币上测量）。无论如何，整个开发者部分，**包括开发者幽灵危险门**，都会无声地失效。

因此，当没有带 `creator` 标签的行返回时，创建者地址会从 `token info` 的 `dev.creator_address` 中恢复，`dev.creator_token_balance` 提供其余额。仅在主要来源失败时才会调用此调用，因此它在标签工作的代币上不会花费任何成本。

`token info` 不包含 `realized_profit` 或 `token_transfer_out`，因此在上行路径中：

- 已实现利润数字**完全省略**——打印 `$0` 会将未测量的字段报告为测量
- 幽灵门切换法官：不再是“开发者的芯片转移到了 Top 100 钱包”，而是询问任何 Top 100 持有人的 `native_transfer.from_address` **是否** 是创建者，即开发者支付了该钱包的 gas。命中会被报告为危险并命名钱包；未命中不会报告为干净，因为在该测量代币上 57% 的持有人带有该字段。

## 备注

- `balance >= 1` 阈值可避免在识别开发者持有量时出现灰尘误报
- SOL 的 `native_balance` 以 lamports 为单位（÷1e9）；`bsc`/`eth`/`base` 以 wei 为单位（÷1e18）。`arc`/`stable`/`robinhood` 的十进制数尚未确认，因此购买力部分在这些链上会报告“未评估”，而不是打印可能错误的转换数值。
- 持有者购买力需要一个实时的原生代币价格，通过在包装原生地址（`So111…1112` / WBNB / WETH / Base WETH）上使用 `token info` 命令获取。当该调用失败时，该部分会回退到原生单位，并打印不显示美元数值。
- `total_supply` 估计为普通钱包中 `balance / amount_percentage` 的中位数
- `cur_price` 估计为普通钱包中 `usd_value / balance` 的中位数
- 入场 MC = `total_supply * avg_cost`，与每个 Top5 钱包的未实现 PnL 一并显示
- Top5 在有 Twitter 名称时显示；否则采用 `first4...last4` 格式
- 风险钱包子总计按类别计算，可能超过去重后的总数；脚本会打印出携带多个风险标签的钱包数量，当出现这种情况时。
- `creator_ath_info.ath_mc` 在快速拉升后可能滞后于代币的当前 MC（上游 `ath_price` 曾被观察到等于 `price_24h`）。脚本无法重新计算它，因此当报告的 ATH 高于当前 MC 5% 以上时，会在数值旁边打印陈旧性警告，而不是将其呈现为开发者的峰值。
