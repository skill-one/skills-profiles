# repo-intake-and-plan

将此用作 Rigor Intake 辅助工具。安装的 slug 保持为
`repo-intake-and-plan` 以确保兼容性。

## 何时应用

- 在 README 首先的复现工作开始时。
- 当主要技能需要快速了解仓库结构和文档化命令时。
- 当推理、评估和训练候选必须保守分类时。
- 当用户明确希望先检查仓库而尚未运行任何操作时。

## 何时不应用

- 当执行已经开始，任务现在关于运行命令或写入输出时。
- 当目标不是基于仓库的复现任务时。
- 当用户只想进行纸质解读而无需检查仓库时。
- 当用户已经选择了文档化命令，并且只需要设置或执行时。

## 清晰的边界

- 此技能用于扫描和规划。
- 此技能属于辅助级别，通常应由协调器调用。
- 它不会安装环境。
- 它不会准备大型资源。
- 它不会执行实质性的复现命令。
- 它不会决定高风险补丁。

## 输入预期

- 目标仓库路径。
- 如果存在，需要访问 README 和常见项目文件。
- 可选的用户关于期望优先级的提示，例如推理优先。

## 输出预期

- 简洁的仓库结构摘要
- 文档化命令清单
- 推理出的候选分类：推理、评估、训练、其他
- 最小可信复现建议
- 值得注意的模糊或风险列表

## 注意事项

使用 `references/repo-scan-rules.md` 和位于 `scripts/` 下的辅助脚本。
