# standup — 促进分支代理之间的群聊

你是**主持人**。每个用户的 git 工作树（以及他们选择的任何 PR）都作为一个独立的代理加入共享的 markdown 聊天中，然后这些代理将他们分散的工作整合到一个统一的工作树中。你召集房间，分轮进行对话，并将结果带回来——协调发生在聊天中，在代理之间进行。

房间是一个共享文件（默认 `~/.claude-mem/STANDUP.md`）：YAML 前置部分包含 `目标` + `提示`；正文是记录。写入操作是原子锁定的，因此代理同时发言。它是**只读**的——代理决定合并应该如何进行；没有人会在房间内提交或合并。真实的 git 工作是在之后通过 `/do` 进行的。

## 1. 填充房间

有两种方式，可以混合使用：

- **按最新时间**（常用）——在窗口中激活的工作树：
  ```bash
  node "${CLAUDE_SKILL_DIR}/standup.mjs" worktrees --since <1h|4h|24h|7d|all> --json
  ```
  激活 = 在窗口中的一个提交 *或* 未提交/暂存/未跟踪的编辑。如果用户没有命名窗口，则提供 1h / 4h / 24h / 7d / all。

- **手动**——特定的分支和/或打开的 PR：
  ```bash
  node "${CLAUDE_SKILL_DIR}/standup.mjs" worktrees --json   # 本地分支
  node "${CLAUDE_SKILL_DIR}/standup.mjs" prs --json         # 打开的 PR（通过 gh）
  ```
  显示一个编号列表（工作树 + PR，带有年龄/标题）；他们的回复是“复选框”。如果 `prs` 出错（没有 `gh` / 不是 GitHub），则继续仅使用工作树。

零个或一个候选者不是 standup——说明情况，提供扩展选项，停止。否则，在开始前回显名单以确认。

## 2. 打开房间

设置一个目标 + 提示，邀请对话，而不是一次性状态报告：

```bash
node "${CLAUDE_SKILL_DIR}/standup.mjs" open --force --agent facilitator \
  --goal "将这些分支/PR 合并到一个统一的工作树中：每个分支的更改，重叠之处，哪个成为目标，以及合并顺序。" \
  --prompt "主持分轮对话。第一轮：介绍你的分支及其状态。然后解决主持人提出的问题，逐轮进行，直到房间达成一个具体的计划（目标工作树 + 合并顺序 + 冲突解决方案）。只读：决定，不要合并。当你支持计划时注册 AGREE。"
```

## 3. 分轮进行

你主导回合——如果代理在自己的循环中观看房间，可能会导致没有决定而停滞。每轮每个代理只发言一次（读 → 发布 → 返回）；你在轮次之间阅读，并带回来仍然需要的代理。

生成的代理不会继承 `CLAUDE_SKILL_DIR`，因此一次解析并粘贴真实路径到每个简报中：
```bash
echo "${CLAUDE_SKILL_DIR}"
```

**第一轮 — 介绍（所有人，一个 Task 消息以便它们一起运行）。** 简要介绍：

> 你是 **`<分支>`**（PR 是 **`pr-<数字>`**）在一个 standup 群聊中。阅读 `<skill-dir>/agent-brief.md` 并按其内容扮演角色。房间是 `~/.claude-mem/STANDUP.md`；使用 `node "<skill-dir>/standup.mjs" post …` 发言，使用 `… read` 补充。确定方向（`cd "<路径>"`，`git log --oneline origin/main..HEAD`，`git status --short`，`git diff --stat origin/main...HEAD`；PR 使用 `gh pr view/diff <数字>`），然后发布一个回合：你的分支，其真实状态，以及它应该如何合并。只读。然后返回。

**协调。** 一旦他们返回，`read` 房间并列出 **开放项目**——重叠、冲突、竞争实现、未确定的目標/顺序。没有？跳到结束。

**解决轮次（最多 4 轮）。** 每个开放项目，重新生成仅涉及该项目的代理，并带有具体问题。告诉他们先 `read --since <他们的名字>`，然后发布他们的立场和 `--agree` 如果他们确信。再次 `read`，更新列表。重复。

**结束——你总是写入。** 当列表为空，你达到上限，或代理出错（记下“未报告”，不要阻止）时停止。然后你自己写入总结——不要等待代理主动提供。将其作为人类可以快速浏览的纯文本写入，而不是字段转储：哪个工作树是目标以及原因，合并顺序用一句话说明，以及留给人类的工作：
```bash
node "${CLAUDE_SKILL_DIR}/standup.mjs" summation --agent facilitator \
  --text "基于 <工作树> 构建——它是唯一一个有实际代码的。在顶层添加 <分支> 的更改，然后插入只有文档的分支；跳过 <空分支>。你的决定在安全之前：<一个或两个实际决定>。完成时，所有内容都位于 <目标> 并能正常构建。"
```

## 4. 用普通语言简报人类

这是回报——不要给他们原始的 SUMMATION，**翻译它。** 没有观看房间的任何人应该能够理解结果，而无需解码路径、行数或提交哈希。先给出答案，然后给出他们只能做的几个选择：

- **你发现的内容**——每个分支一行，简单明了：谁有实际代码，谁是只有文档，谁是空的。
- **计划**——目标 + 合并顺序用一到两句话说明。
- **他们的决定**——只有人类必须做的决定（哪个实现获胜，什么要丢弃，任何风险），作为具体问题。使用 `AskUserQuestion` 来处理明确的问题。

除非他们提问，否则不要透露 git 内部细节。一旦他们解决了开放问题，将计划交给 **`/do`** 来执行合并——不要在 `/do` 外自己合并任何内容。

## CLI

```bash
node "${CLAUDE_SKILL_DIR}/standup.mjs" <命令> [--标志]
```
默认：代理 = git 分支，文件 = `~/.claude-mem/STANDUP.md`。每次写入都是原子锁定的。

| 命令 | 它的作用 |
|---|---|
| `worktrees [--since 4h] [--json]` | 按最新时间工作树；`--since N{m,h,d,w}` 保持窗口中激活的工作树 |
| `prs [--since 4h] [--json]` | 按最新时间打开 GitHub PR（通过 `gh`） |
| `open --goal "…" --prompt "…" [--force]` | 创建房间（`--force` 将旧的替换掉） |
| `join [--message "…"]` | 添加你自己 + 说 Hello |
| `post --message "…" [--agree "…"]` | 追加一个回合 |
| `agree --deliverable "…"` | 追加一个 AGREE 回合 |
| `watch [--timeout SEC] [--interval SEC]` | 阻塞直到其他人发布，打印它（超时返回 2） |
| `read [--tail N] [--since AGENT]` | 打印聊天（或仅 AGENT 最后之后的回合） |
| `status` | 参与者 + AGREEs + 共识检查 |
| `summation --text "…"` | 写入 SUMMATION，切换 `status: agreed` |

每个生成的代理按照 **`agent-brief.md`**（在此捆绑）进行回合——作为房间中一个声音的剧本。
