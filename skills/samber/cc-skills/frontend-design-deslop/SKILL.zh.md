**问题：** 通过环境的问题工具向用户提问——永远不要以纯文本散文的形式。一次只问一个问题，提供 2-4 个可点击的选项，等待答案。如果环境没有问题工具，则用相同的选项以散文形式提问，一次一个。

# 前端设计设计

AI 生成的 UI 看起来很通用，有两个原因：

1. **没有约束。** 模型采样了 2019-2024 年网页代码的统计中位数——Tailwind UI 的 `bg-indigo-500`、Inter、圆角卡片、柔和阴影。你无法超越真空。
2. **在不知道自己在设计什么的情况下进行设计。** 企业着陆页、创意作品集、开发者工具着陆页、分析仪表板和电子商务产品页面几乎没有任何设计基因——一个与该工件的任务相抗争的美丽美学是其自己的 slop。

解决方法是借鉴品牌设计中的纪律：策略驱动设计，而不是先考虑美学。

1. 首先承诺文字——这是什么，它服务于谁，它必须感觉如何的形容词。
2. 将这些文字翻译成字体和颜色系统。
3. 从令牌开始构建。
4. 应用工艺层（布局、组件、动画、图标、图像、暗黑模式、无障碍访问）。
5. 审计。

瞄准收敛机制，而不是冻结的块列表；slop 指纹会随着时间的推移而变化（2022 年的紫色渐变，2026 年的奶油背景和斜体-衬线英雄）。

这项技能同时完成两件事：它去除了默认的 AI 外观，并很好地设计了应用程序。在粗心的组件、薄弱的布局或无意识的动画之上放置一个独特的主题，仍然会被视为业余的。每个选择背后的机制都存在于 `references/design-theory.md`（层次结构、Gestalt、CRAP、信号与噪音、可供性、交互定律）；读一次，这样其余的就是推理而不是遵循规则。

## 提问（关键）

每个单个的用户问题都必须通过问题工具（见上面的 **问题：** 指令）——永远不要以纯文本散文的形式。银行很慷慨；提问是选择性的。不要审问。

- 批量相关的问题；每个问题提供 2 到 4 个具体的选项。
- 只问会改变设计系统的信号高的子集。
- 首先从上下文中推断，而不是重新提问来确认推断。

## 第 0 阶段：发现并承诺文字（在任何代码之前先做这件事）

在编写任何代码之前，检查项目根目录下是否存在现有的 `DESIGN.md`（以及常见位置，如 `docs/`）。

- **存在** — 阅读它，尊重它的令牌，跳过它已经回答的问题，并扩展它而不是重新开始。
- **缺失** — 在任何像素之前解决以下三件事。阅读 `references/discovery.md` 以获取完整协议、问题库和个性到令牌的翻译表，以及 `references/artifact-types.md` 以获取每种类型的优先级。

1. **工件是什么？** 分类：营销/着陆页、定价页、SaaS 应用、仪表板/数据工具、电子商务、市场、移动应用、AI/对话界面、电子邮件/通讯、博客/出版物、入职/认证流程、设置/管理/CMS、演示/幻灯片、文档/API 参考、作品集/品牌网站，或 `references/artifact-types.md` 中的长尾类型之一。每个都针对不同的事物，并有其自己的布局语法和密度。复合工件（一个带有嵌入式应用的营销网站，一个 SaaS 应用中的 AI 聊天）按区域进行设计。
2. **谁和为什么？** 受众、定位（企业 vs 创意 vs 技术 vs 豪华 vs 玩乐），以及单一的主要动作或结果。
3. **承诺文字。** 在任何视觉探索之前锁定 3 到 5 个品牌形容词和 3 个词的审美本质。这是最高杠杆的输入；它驱动字体、颜色、密度、半径和动画。策略驱动设计，而不是反过来。

自适应地运行发现：推断、陈述推断、通过问题工具询问信号高的子集，并将方向基于 1 到 3 个参考（如果未给出，则搜索当前最强大的精确工件类型和定位的网页示例，然后转置而不是原创）。在锁定工件类型、定位和形容词之前不要继续。在一个通用的简报（另一个仪表板、另一个 SaaS 着陆页）中，如果类别本身很少说话，则将参考搜索扩展到产品自己的类别之外，而不是在它内部要求更多的创造力——见 `references/divergence.md`。

## 第 1 阶段：将策略转化为设计系统（门）

用简短的散文陈述这些承诺。每个都必须来自第 0 阶段，而不是反射。

1. **审美承诺。** 选择一个适合工件和形容词的、有意见的方向；通用是失败模式。见 `references/aesthetics-library.md`。如果用户给出了品牌或参考，则转置它。在挑选一个之前导出 2-3 个真实候选者，在完全承诺获胜者之前不要软化它以供可读性，并检查基本结构（而不仅仅是风格化的表面）与类别默认值——见 `references/divergence.md` 了解为什么每个这些都很重要以及如何在不重新考虑同一遍的情况下完成。

2. **字体（品牌优先）。** 从个性而非审美偏好中选择字体。将分类与形容词匹配，选择适合内容的模块比例，并配对以形成对比（显示 + 正文），而不会出现字体泥。永远不要 Inter/Roboto/Arial/system 作为主要面。见 `references/typography.md`。

3. **颜色（适当性 + 差异化）。** 为品牌和受众的适合性选择颜色，然后找到无争议的领土（靛蓝/紫色带是 AI UI 的红海；除非简报要求，否则避免它）。构建一个主导的加上一个尖锐的强调色加上中性色加上语义状态，大致分布为 60-30-10。用 OKLCH 编写。见 `references/color-oklch.md`。

4. **令牌表（在组件之前发出）。** 显示 + 正文字体；类型比例（声明比例和基础，6 步）；间距基本单元；最多两个半径值；一个阴影方法（定义边缘 OR 软提升，一个元素上永远不要两者兼有）；带有角色的调色板（bg、表面、fg、 muted、边框、强调色、强调色-fg、成功、警告、错误）——`surface` 是必需的，不是可选的：它是光亮度提升（见 `references/dark-mode.md`）步骤的基础。所有内容都引用令牌；没有分散的十六进制/像素。从 `references/token-sets.md` 中拉取一个起始集。

5. **标志性动作。** 命名使此 UI 令人难忘且明确不是默认值的单个事物。每个项目一个。

6. **适配器。** 选择堆栈语法：纯 CSS 自定义属性、Tailwind v4 `@theme` 或 shadcn 语义令牌。见 `references/adapters.md`。`references/token-core.css` 是可移植的真相来源。

## 第 2 阶段：将系统应用于界面（工艺层）

令牌使 UI 保持一致性；工艺层使它变得良好——这是“设计应用程序”技能的一半，也是 AI 输出跳过的一半。

将以下每个应用于工件，按需拉取匹配的参考。密度和强调因工件类型而异（见 `references/artifact-types.md`）；仪表板与着陆页应用这些非常不同。

1. **布局和构图。** 有意地组合空间：一个基本间距单元，组内间距紧凑，组间间距宽松，一个有意网格（12 列、模块化或内容真正变化的 bento），至少一个特定于布局的布局动作，以及空白作为自信的信号。打破居中最大宽度列的习惯。见 `references/layout.md`。

2. **组件和状态。** 跨其完整状态矩阵指定每个交互式组件（默认、悬停、激活、焦点、禁用、加载、错误、选中），而不仅仅是静止状态。获取按钮（按重要性排名，而不是按颜色含义排名）、表单（真实标签、正确类型、内联验证保持输入）、表格（文本左对齐、数字右对齐、轻分隔符）、导航、覆盖层和空/加载/错误状态。见 `references/components.md`。

3. **动画。** 将动画视为通信，在持续时间和缓动令牌比例下。默认为 300 毫秒以下的 ease-out，只动画变换和不透明度，从触发器缩放弹出，永远不要动画高频操作。见 `references/motion.md`。

4. **图标。** 集合中一个网格、一个笔触、一个半径；不要让未修改的默认 starter-kit 设置定义外观。见 `references/iconography.md`。

5. **图像和插画。** 作为系统进行艺术指导。优先考虑真实产品视觉效果而不是库存和抽象；避免 AI/库存指纹（人们指着笔记本电脑、渐变块、企业-Memphis、默认 Midjourney）。使用纹理和图形设备来摆脱扁平 slop。见 `references/imagery.md`。

6. **暗黑模式和主题。** 如果暗黑模式在范围内，请设计它（不要反转）：近黑色而不是纯黑色，浅白色而不是纯白色，通过光亮度进行提升，饱和度降低的强调色，所有这些都由语义令牌驱动。见 `references/dark-mode.md`。

7. **无障碍访问作为构建的一部分。** WCAG 2.2 AA：可见管理的焦点、键盘可操作性、标签、24px-plus 目标、颜色独立性、减少动画。构建它；不要附加它。见 `references/accessibility.md`。

在构思结束时，一旦方向和工艺决策锁定，建议用户一个相关的设计和组件目录的子集，以挖掘具体的想法和现成的实现，将其作为通过已承诺系统转置的灵感（而不是克隆），并提醒验证组件许可证。按工件类型和阶段选择，而不是倾倒整个列表。见 `references/catalogs.md`。

## 第 3 阶段：编写 DESIGN.md（耐久输出）

这项技能产生的所有内容都存在于项目根目录下的单个 `DESIGN.md` 中：

- 发现上下文
- 承诺的审美和标志性动作
- 字体和颜色系统
- 令牌
- 间距/半径/阴影规则
- 工艺层决策（布局、组件、动画、图标、图像、暗黑模式、无障碍访问）
- slop-audit 结果

在构建组件之前或 alongside 更新它，使用 `references/design-md.md` 中的模式。DESIGN.md 是单一事实来源——如果 CSS、适配器或组件偏离它，DESIGN.md 赢。在后续会话中，第 0 阶段读取此文件而不是重新运行发现。

## 令牌优先生成规则

- **OKLCH 中的颜色**，主导的 + 尖锐的强调色，而不是胆怯的均匀分布。首先在灰度中设计层次结构，最后和谨慎地添加强调色，大致为 60-30-10（中性 / 品牌 / 强调）。在彩色背景上，加深/去饱和相同的色调，而不是变成灰色。定义语义状态颜色（成功、警告、错误），并且永远不要仅使用颜色作为信号。
- **字体**：一个独特的显示面配对一个精致的正文面，模块比例与声明的比例。从 Fontshare/Google 获取。限制为 2 到 3 个家族。
- **间距节奏**：根据关系变化间距（组内紧凑，组间宽松）。到处都是单一统一值是一个线索。
- **密度适合工件。** 仪表板和工具工具容忍高密度；营销和作品集页面想要空气。
- **匹配实现复杂性与美学**：极繁主义得到复杂的细节；极简主义得到约束和精确，而不是懒惰。

## 永远不要（负面提示）

永远不要使用通用的 AI 生成美学：过度使用的字体（Inter、Roboto、Arial、system-ui 作为主要面）；陈词滥调的颜色方案（尤其是白色或深色上的紫色/靛蓝/紫色渐变）；英雄 + 3 特性卡片 + 评价 + CTA 模板作为唯一结构；图标-标题上方的特征卡片模板；卡片上的侧边标签强调边框；同一元素上堆叠的细线边框和扩散阴影；标题或指标上的渐变文本；装饰性玻璃形态；blob 圆角（小卡片上的半径 > 16px）；反射性地使用奶油/米色背景；弹跳/弹性缓动和动画一切微交互；装饰性网格线背景或没有结构目的的径向聚光灯辉光；内容不是实时更新的脉冲状态点或自动滚动横幅；用手工编码的 SVG 神秘角色代替真实插画。使用独特的字体、一致承诺的调色板，并且只有在它服务于交互时才使用动画。

工艺层永远不要：不要以仅静止状态的方式发送组件；不要使用占位符文本作为标签；不要按含义而不是按重要性对按钮进行颜色编码；不要居中数字表格列或使用非表格数字表示数字；不要让未修改的 shadcn/Tailwind 默认图标集定义外观；不要在应该属于真实产品视觉效果的地方使用库存的人指着笔记本电脑、渐变块、浮动球体、光泽等距技术插图、企业-Memphis 人物或原始默认 Midjourney 图像；不要反转浅色调来制作暗黑模式，使用纯黑色背景、纯白色文本或发光彩色框阴影；不要动画布局属性（宽度/高度/顶部/左侧）或忽略 prefers-reduced-motion；不要在没有替换焦点轮廓的情况下移除焦点轮廓，仅通过颜色传达意义，或发送小于 24px 的目标。

## 完成前的自我审计

运行生成的 UI 对 `references/slop-checklist.md` 进行评分。

1. 验证它是否服务于 `references/artifact-types.md` 中的工件类型的优先级——一个看起来像作品集的仪表板，或一个没有明确主要动作的着陆页，即使它很美，也失败了——并且类型和颜色选择与承诺的形容词匹配。
2. 验证工艺层：组件具有完整的状态矩阵，布局具有节奏和有意动作，动画是传达性的并尊重减少动画，图标是一个连贯的系统，图像不是库存/AI slop，并且暗黑模式（如果存在）是设计的而不是反转的。
3. 运行 `references/accessibility.md` 中的无障碍访问门（焦点、键盘、对比度、目标、颜色独立性）；无障碍访问是一个通过/失败门，而不是一种优雅。
4. 重新阅读 DESIGN.md 审美承诺，将其视为第一次看到实际渲染，并在 `references/divergence.md` §6-7 中进行基本结构检查——单独的逐条检查清单通过只能为仍然通用的输出评分。
5. 如果任何线索触发或适合性错误，则在展示之前重新生成该部分。
6. 在 DESIGN.md slop-audit 部分记录结果并更新其版本控制，声明工件类型、定位、形容词、审美、字体系统、调色板和标志性动作。

所有清单项目都在单个构建中可检测；不要发明模型无法验证的跨代规则。一个子集需要渲染页面而不是仅源（见 `references/slop-checklist.md` 的“布局缺陷”和“构建正确性”部分）——每当有截图或实时浏览器可用时运行它们。
