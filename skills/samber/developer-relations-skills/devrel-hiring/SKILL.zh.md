# DevRel招聘

以该领域招聘研究推荐的严谨标准，构建招聘DevRel角色的四项关键要素：角色评分卡和招聘公告、结构化面试流程及问题库、作品集和工作样本评估，以及30-60-90天入职计划。

DevRel没有标准的职位描述或职业阶梯（CNCF CTO Chris Aniszczyk），其招聘文献记录了在缺乏这种规范下编写的招聘公告中的两种命名失败模式——参见“回答解读”。这种缺失是故意构建这四项要素而非调整通用工程或营销招聘模板的原因。

不在此范围内，应转交：

- **DevRel汇报对象和团队构成方式** - samber/developer-relations-skills@devrel-team-structure在技能招聘进入该组织前决定组织结构。
- **指导候选人** - samber/developer-relations-skills@devrel-career是此技能的镜像，为被评估者构建。

如果用户是求职而非招聘（“如何准备DevRel面试”，“这个招聘公告值得申请吗”），用一句话说明，并指向devrel-career。

## 面试

一次问一个问题，尽可能采用选择题。跳过已回答的问题。问题8-10在构建任何要素前重新排序这些要素——在产出任何内容前询问它们。

**记忆：存储关于当前任务或项目背景的少量信息。当记忆存储在文件中时，使用`devrel-context.md`；如果使用不同的记忆系统，则依赖该系统。在不同部分中分离任务信息。删除已完成的任务。给任务添加日期；无日期为一般项目背景。一些面试回答可能在两个任务之间有所不同。**
1. 公司类型：(a) 初创公司，种子轮-A，这将是一个只有一个人的团队 (b) 增长/扩张，B-D (c) 大型科技企业 (d) 以OSS为先的公司或基金会。
2. 角色目标：(a) 开发者倡导者，以拓展为重点 (b) 开发者倡导者，以产品为重点 (c) 社区经理 (d) 开发者教育者 (e) DX工程师 (f) 不确定——建议从资金驱动者中选一个。
3. 这个角色由什么资金——预算背后的驱动因素：开发者采用，销售赋能，开发者赋能，产品输入，生态系统/合作伙伴关系，贡献者社区，或雇主品牌？
4. 市场进入策略：以销售为主导的B2B，以产品为主导（PLG）的B2B，B2C/个人面对，或无购买门槛的OSS/基金会。
5. 编码深度要求：这个角色需要发布SDK示例和审查API设计，还是只需要进行公共沟通和少量编码？
6. 团队阶段：第一个DevRel招聘人员，没有现任人员可以参考，或者是一个可重复招聘，有现有的顶尖表现者可以参考？
7. 薪酬立场：你会在招聘公告中公布一个范围，并且你知道你招聘地区的薪酬透明度要求吗？
8. 截止日期：这个月，这个季度，或者没有硬性日期？
9. 一次性招聘还是第一个，其中评分卡和问题库会被重复使用？
10. 努力上限：每个候选人多少面试官小时，并且是否有招聘人员或训练小组？

## 回答解读

- **Q1设定了标准和工作集权重** - 加载[references/company-type-and-driver-lookup.md](./references/company-type-and-driver-lookup.md)。初创公司招聘一个通才，证明该职能自身的存在；大型科技公司将角色与其工程级别标准挂钩；OSS/基金会的角色在贡献历史而非沟通技巧上进行筛选。
- **Q2 + Q3决定招聘公告筛选的标准** - 参见[references/company-type-and-driver-lookup.md](./references/company-type-and-driver-lookup.md)中的每角色要求表。一个无法说出其目标子角色的候选人是在申请所有角色并匹配不到任何角色；同样，一个无法说明其需要的子角色的招聘公告也是如此。
- **Q3 + Q4决定支柱组合，因此决定角色衡量的指标**：以销售为主导的推广倡导和销售赋能；以产品为主导的推广赋能和产品输入；B2C推广社区和触达；OSS/基金会推广社区和倡导。
- **在起草招聘公告前，根据该领域的两种命名失败模式进行自我审计**（Joe Nash，DevRelCon 2021——这是devrel-career教候选人从外部检测到的相同分类法）：
  - **守门人**——描述一个不可能的人：跨多个技术栈的完整工程职业生涯加上OSS贡献，技术写作，社区建设和活动组织，以入门级薪酬发布。
  - **陷阱**——"创立DevRel，无需背景"实际上期望一个人在没有资源、没有阶梯和没有明确目标的情况下覆盖文档、SDK、社区、支持、销售工程和培训。
  - 两者都有三个症状：核心技能强调，没有明确结果的策略列表，以及与薪酬不一致的级别。一个失败的招聘公告在任何症状出现前都需要重写，而不是在失败到无法转化后才重写。
- **Q6决定候选人画像**。首次招聘：一个能够在没有现任团队的情况下证明该职能存在的建设者，类似于公司首次销售招聘——重视自我导向和广度而非专业深度。可重复招聘：从该组织自己的顶尖表现者中按实际拥有的支柱进行画像。
- **Q7触发质量门下的薪酬门**——永远不要编造一个地区的法律要求；在发布前确认招聘地点当前的薪酬透明度规则。
- **Q8促进快速行动选项**：这个月截止日期促进重用现有的问题库和更短的流程，而不是从头开始设计一个新的定制工作样本。
- **Q9决定工作样本是否保持简洁**。一次性招聘：一次设计，低成本。复合型：冻结的评分标准和问题库为该支柱的每个未来招聘服务，这促进了首先正确构建两者。
- **Q10删除流程阶段而不是重新排序**。在每位候选人少于少量面试官小时下：削减到评分卡，一个结构化的对话轮次，和作品集评估；完全跳过现场工作样本，而不是无评分运行。

## 工作流程

按顺序产出四项要素。交付每一项，与用户验证，然后进行下一项。

1. 运行面试。用一段简短的用户可以否决的段落说明角色和支柱组合建议。
2. **要素1 - 角色评分卡和招聘公告**。从[references/company-type-and-driver-lookup.md](./references/company-type-and-driver-lookup.md)和[references/scorecard-and-posting-template.md](./references/scorecard-and-posting-template.md)构建：
   - 一个句子的使命命名Q3的资金驱动因素
   - 3-8个可衡量的成果按重要性和量化排名（例如，“通过发布的摩擦日志修复，将前三名入职支持线程减少25%”，“第一年从社区获得40个接受的CFP”），永远不要模糊的责任
   - 5-7个按角色和公司类型加权的能力（从Q1-Q2）
   - 在发布前运行上述守门人/陷阱自我审计
3. **要素2 - 面试流程和问题库**。从[references/interview-loop-and-question-bank.md](./references/interview-loop-and-question-bank.md)构建：
   - 从该领域验证的3-5个格式中选择（演示轮次，内容带回家，编码带回家，技术自我评分，对话轮次，DevRel意见轮次，初创公司的创始人/高管轮次）——没有标准的流程，因此选择实际测试该角色支柱组合的格式，而不是默认使用全部格式
   - 在请求候选人对任何新工作之前，放置作品集评估（要素3）
   - 每个评分卡能力从参考文件中的类别库中写2-3个问题，加上至少一个DevRel意见问题——候选人报告说这是最难的一轮，因为它没有记忆中的答案，这正好是为什么它将职位与排练的演讲区分开来
   - 定义评分机制：每个面试官在讨论前独立评分并附上证据笔记，然后机械地结合评分卡的预设权重——这是一个一般性就业选择发现（结构化、独立评分、机械结合的面试优于非结构化的和整体讨论），而不是特定于DevRel，但由于该发现没有特定于领域，因此直接适用
   - 当存在公共作品集时，永远不要要求无偿的特定工作；提供付费的现场工作会面
4. **要素3 - 作品集和工作样本评估**。从[references/portfolio-and-work-sample-scoring.md](./references/portfolio-and-work-sample-scoring.md)构建：
   - 根据目标子角色的权重，对候选人的已发布公共工作评分，使用六信号分布评分标准（公共写作，公共演讲，公开代码，社区证据，教学工件，开发者声音工件），命名负面信号（如有）（如没有实质内容的粉丝数量，只有自我推广，没有发布的代码，无法说出帮助过开发者的开发者）而不是只列出缺失的内容
   - 当作品集薄弱或候选人对该领域不熟悉时，设计一个评分的付费工作样本，而不是仅凭简历判断——一个短闪电演讲轮次，一个文档编辑练习，或一个“向开发者解释这个API变化”的练习，与目标子角色匹配
   - 在[devrel-career](./devrel-career)中，这个技能应用它从评估者的角度
5. **要素4 - 30-60-90天入职计划**。从[references/ramp-plan-template.md](./references/ramp-plan-template.md)构建：
   - 第0-30天：新员工像开发者一样使用产品并发布一个摩擦日志——devrel-career建议作为作品集的相同工件，现在是前30天的交付物
   - 第31-60天：在目标支柱中发布的第一个公共或内部工件，与现有团队成员配对
   - 第61-90天：自我导向的一个周期性项目切片的所有权，以及一个记录的关于该角色资金驱动因素衡量的指标的计划
6. 如果用户尚未确定在哪里找到候选人，从[references/sourcing-channels.md](./references/sourcing-channels.md)中记录候选人来源渠道。
7. 在所有四项要素上运行质量门。迭代直到通过。
8. 如果你的框架有持久记忆，存储评分卡、冻结的问题库、流程设计和入职里程碑，以便未来招聘同一角色时重用，而不是重新开始。

## 公司类型和资金驱动因素

永远不要将招聘公告模板视为跨公司类型可移植的：相同的标题在初创公司、成长阶段公司、大型科技供应商和以OSS为先的基金会意味着不同的工作，并且每个都期望不同的作品集标准和编码深度。完整的比较表、四个支柱和七个资金驱动因素预测角色衡量的指标：[references/company-type-and-driver-lookup.md](./references/company-type-and-driver-lookup.md)。

基金会和OSS相关的大使式角色通常是无偿的，并且基于可衡量的贡献而不是沟通技巧——在编写有薪酬的招聘公告要求到无偿项目，或反之之前，确认这是什么类型的角色。

## 质量门

在最终交付前，根据这些检查评分四项要素。迭代直到每个检查通过。

1. 评分卡有3-8个成果，每个都量化并排名，并命名Q3的资金驱动因素。
2. 招聘公告通过守门人/陷阱自我审计：没有核心技能强调，没有没有明确结果的策略列表，级别与声明的薪酬一致。
3. 每个面试问题都映射到一个命名的评分卡能力；相同的问答题集适用于该角色的每个候选人。
4. 流程至少包含一个实际测试目标支柱的格式（对于以拓展为重点的角色，演示轮次；对于DX/产品为重点的角色，编码带回家），而不是无论如何都复制一个通用集。
5. 没有阶段要求无偿的特定工作，当存在公共作品集证据时。
6. 面试官在讨论前提交独立、附有证据的评分；最终结合是机械地针对预设权重。
7. 作品集评估根据六信号评分标准评分，按目标子角色加权，如有负面信号则明确命名。
8. 如果设计了现场工作样本，它是基于固定评分标准付费的，永远不会被视为免费试用工作。
9. 招聘公告声明一个真实的薪酬立场（一个发布的范围，或一个明确的说明为什么它被限制）与Q7司法管辖区答案一致——永远不要发布“有竞争力的”而没有数字和没有说明理由。
10. 入职计划包含第30天的摩擦日志交付物，第60天的已发布工件里程碑，和第90天的自我导向所有权里程碑。
11. 在此技能的输出中，关于“什么看起来像好”的每个声明都可以追溯到一个命名来源或明确标记为此技能的自己的工作假设——这个领域没有单一的权威职业阶梯机构，因此未标记的声明比它实际更稳定。

## 常见失败模式

未排名，故意：每一行都是一个缺陷，有一个必须修复的解决方案。

| 失败                                                | 解决方案                                                                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 守门人招聘公告                                     | 将核心技能要求列表削减到支柱组合实际需要的；根据实际要求重新定价级别 |
| 陷阱招聘公告                                       | 明确说明资源、阶梯和12个月目标，或者推迟招聘直到它们存在            |
| 复制通用工程或营销JD模板                           | 从资金驱动因素和支柱组合重建；DevRel的成果和能力不映射到任何模板       |
| 仅凭简历判断而不是已发布的工作                      | 在任何对话轮次之前运行六信号作品集评估                                                                                       |
| 无偿的特定工作试镜                                  | 提供付费的现场工作会面或判断现有的公共作品集                                                                                   |
| 一个混合的直觉评分在群体讨论后                      | 在讨论前独立、附有证据的评分，然后机械地结合                                                                                   |
| 对每个DevRel子角色应用相同的流程                      | 根据目标子角色的实际筛选要求选择格式和问题                                                                                   |
| “有竞争力的薪酬”，没有范围，没有理由                | 发布一个范围或明确说明为什么它被限制，与该司法管辖区当前的自身要求一致          |
| 入职计划没有工件里程碑                             | 第30天锚定已发布的摩擦日志，第60天锚定已发布的支柱工件，第90天锚定自我导向所有权          |
| 将标题视为跨公司类型可移植的                        | 在重新使用任何先前招聘公告前，根据Q1的公司类型行重新校准整个评分卡          |
