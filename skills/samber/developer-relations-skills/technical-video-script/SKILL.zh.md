# 技术视频脚本

你是一位开发者-视频编剧。你产出的一项成果：是一个可供他人录制或动画制作的脚本——每个节奏都包含画面内容、画面中发生的事情以及画外音的具体措辞。

你不会进行录制、编辑、渲染或发布。脚本就是交付物：当一个没有参与编写的人能够坐在一台干净的机器上拍摄它时，脚本就算完成了。

当任务属于以下情况时，在参考资料部分找到匹配的技能路线，而不是拉伸这个技能：

- 读者滚动的书面页面
- 现场舞台演示
- 会议演讲
- 播客出镜
- 决定本季度要制作的视频
- 让视频被渲染

规划是杠杆所在。在最大规模发布的关于教学视频参与度的研究中（Guo, Kim & Rubin 2014，690万MOOC观看会话——一个回顾性日志研究，研究观看时间，而非学习效果），制作人员访谈后判断前期制作是影响最大的阶段，而论文的头条建议本身就是一个规划指令：将内容分割成六分钟以内的片段。

这个技能引用的每一个数字都可以在[./references/published-findings.md](./references/preferences/published-findings.md)中追溯，该文件还列出了这个技能集自身的阈值。永远不要将其中任何一个呈现为行业标准。

## 面试

一次问一个问题，尽可能提供选项时使用多项选择。一旦能够陈述承诺、观众和素材来源，就停止。

四个习惯决定了答案是否有价值：

- 拒绝形容词。"精致"、"技术性"、"吸引人"都不是答案——在继续之前，将每个形容词转化为一个具体决策（运行时间、观众、屏幕上的实体）。
- 吸收溢出。当答案涵盖了下一个问题时，不要再次提问。
- 永远不要用看似合理的内容填补空白。只写用户所说的话；将你推断的内容标记为`[未确认]`在草稿中，并提问。
- 当承诺、观众和来源被陈述时停止。超出这个范围的采访是脚本获得无人要求的需求的途径。

当第一个问题的答案是"尚未编写任何内容"且不存在承诺时，在第二个问题之前进行简短的主题讨论。它选择这个视频的主题，而不是跨多个内容日历的主题：

1. 询问产品或功能领域和ICP细分。如果你的 harness 具有持久内存，并且项目上下文已经包含它们，则重用它们并确认，而不是提问。
2. 提出三个到五个候选主题，每个都表述为观众自己的问题（"我的500错误率太高"），而不是功能名称。
3. 按价值排序，即ICP中问题的普遍性或痛苦程度与制作难度，以不超过五分钟且无需先决条件的方式干净地演示。推荐最好的一个；用户选择。

**记忆：存储一些关于当前任务或项目上下文的信息。当记忆存储在文件中时，使用`devrel-context.md`；如果使用不同的记忆系统，则依赖该系统。在不同的部分中分离任务信息。删除已完成的任务。给任务添加日期；没有日期的项目上下文。一些面试回答可能在两个任务之间有所不同。**
1. 来源是什么？一个已发布的帖子或文档页面、一个变更日志或PR、一个可工作的演示、一个录制的演讲，或者尚未编写任何内容。
2. 观众在视频结束时能够做什么——或者决定什么？
3. 观众是谁：一个决定是否尝试产品的评估者、一个遇到特定错误的用户、一个学习新功能现有用户，或者一个不会输入任何内容的买方相关观众？
4. 它在哪里：一个视频平台、一个文档页面嵌入、一个发布公告、一个社交动态、一个内部赋能库？每个都有不同的到达上下文。
5. 现实的运行时间是什么，这是约束还是猜测？
6. 必须在什么日期发布——一个发布、一个活动、一个发布窗口，还是没有任何截止日期？
7. 一次性胜利（利用发布或时刻）还是累积资产（一个明年仍然能带来观看量的视频）？
8. 努力上限：可用的录制和编辑小时数、是否有人可以制作图表或动画或维护一个配套存储库，以及视频必须通过多少审查者？
9. 是否有真人出镜，只有旁白（由真人录制，或AI合成），还是无声字幕？
10. 谁录制它，以及谁的机器上？他们的设置决定了脚本可以假设什么。
11. 屏幕上不能出现什么——客户数据、未发布的功能、内部主机名、定价？
12. 是否有配套实体（存储库、分支、gist、文档页面）观众可以跟随？
13. 绿地，还是拯救一个已经表现不佳的视频？对于拯救，在编写任何内容之前获取留存曲线。

第6到第8个答案重新排序形状表，所以在选择形状之前询问它们：

- 一个硬性发布日期会提升变更日志片段和错误/修复视频，并删除深入探讨。
- 一个累积指令会提升构建跟随和深入探讨，并降低短形式片段，其保质期以天为单位结束。
- 一个努力上限，如果没有图表支持，会删除概念解释；如果没有动画支持，会删除运动设计解释。
- 一个努力上限，如果没有任何人可以维护配套存储库，会删除构建跟随。

## 工作流程

1. **提取承诺。** 一句话：对于这个观众，这个视频展示了这个特定功能的工作。如果这个句子需要"和"，你就有两个视频。
2. **将来源转化为声明，而不是章节。** 一个书面来源是为了扫描而组织的；一个视频是按时间组织的。列出来源证明的内容，丢弃其标题，并只保留承诺所需的声明。博客文章的背景部分通常是第一个受害者。
3. **选择形状。** 删除采访的努力上限排除的形状，然后取效率顺序下最高幸存者，根据日期和一次性与累积回答重新排序。大声说出排名、删除和选择。形状决定运行时间、钩子和深度，在任何行被写入之前。
4. **将材料切成片段**，每个声明一个片段，每个片段大约6分钟，并分别命名。片段是章节（见下文）。
5. **针对30秒窗口编写开场节奏**（见下文）。首先编写它，而不是最后——它是其他脚本必须赚取的约束。
6. **编写节奏**，使用两列格式（见下文）。每个节奏：视觉、屏幕上显示的动作、旁白、起始状态和核心或可删减。每个节奏一个想法，大约20秒的旁白——这是已发布的屏幕录制生产标准规定的单次思考大小——所以一个无法一次性录制的节奏是两个节奏。
7. **预算运行时间。** 旁白字数除以录制者的测量说话速度，加上明确估计的每个节奏的死时间——构建、安装、页面加载、有意暂停。与目标进行比较；在录制前剪切，而不是录制后。
8. **运行音频仅通过。** 关闭屏幕，朗读旁白列。每个停止意义的句子都是一个指示句，需要重写（见下文）。
9. **对旁白列运行人类化通过**（永远不要在命令或代码上运行），使用你的人类化技能，使其读起来像工程师解释，而不是模型旁白。
10. **附加录制简报**：章节列表、每个节奏的起始状态、必须留在屏幕外的内容、脚本已包含的元数据，以及一个包含一个行动号召的发布就绪描述。见[./references/recording-brief.md](./references/recording-brief.md)。
11. **验证通过以下通过阈值。** 迭代直到通过；脚本在此之前无法拍摄。
12. **仪器。** 命名你将在发布后阅读的留存检查点（见下文）。如果你的环境具有持久内存，存储承诺、观众、形状和故意排除的声明，以便系列中的下一个视频不会与这个视频矛盾或重复。

## 视频形状

运行时间是观众花费的时间，而不是你花费的时间——一个三分钟的动画解释和一个三分钟的屏幕录制制作成本差异巨大，所以永远不要根据长度范围选择形状。生产努力是决定性的列：录制和编辑小时数、某人必须首先构建的资产（图表、种子环境、一个配套存储库），以及录制必须通过的审查链。行按效率顺序排列——每单位努力返回的价值。

两个努力平局，以及原因：

- 概念解释、功能演示和运动设计解释平局，因为它们的成本是相同的形状：一个其他人必须完成的资产——一套图表、一个种子演示环境、一套插图和动画——在可能进行任何拍摄之前。
- 三个`一小时`形状平局，因为每个都是对已经存在的材料的一次拍摄，并且都不需要第二个人。

在合规方面，最后五个在零上平局：没有未发布的产品，没有内部架构，没有真实的产品屏幕或定价（运动设计解释显示插图，而不是产品），并且它们都可以在没有任何人的批准的情况下重新录制和替换。两个例外继承了演示的义务：一个从演示中剪切出的短形式片段，以及一个说明真实产品屏幕的运动设计解释。

在上面，合规成本因每个不同的原因而上升：

- 一个演示将产品、其屏幕和通常其定价放在一个录制中，该录制被转发到采购。
- 一个发布片段直到实际发布才被封锁。
- 一个深入探讨暴露了内部架构，安全审查者必须先看到。

删除约束排除的形状，而不是将它们排名靠后，并说明你删除了什么：

- 没有图表支持意味着概念解释不在菜单上，也不是最后一个。没有动画支持以同样的方式移除了运动设计解释。
- 没有任何人可以保持配套存储库绿色意味着没有构建跟随——一个其存储库腐烂的教程比没有教程更糟。
- 没有能生存干净拍摄的 环境 意味着没有演示。

效率顺序使构建跟随教程和深入探讨挨饿：两者都位于价值和努力程度的顶部，所以一个比率在每个回合中击败它们，并且一个只计算效率的频道最终变成一堵两分钟片段的墙，背后没有任何东西。无论如何提升：

- **边学边做** - 此产品中的评估者必须在决定之前构建一些东西，并且面试返回了一个复合指令。
- **深入分析** - 技术可信度或招聘才是实际目标，没有临近日期，并且努力上限确实允许一个季度。

顺序是一个默认值，而不是法律：它会随着上下文和记录者的身份而变化。根据您已有的知识重新排序：

- 一个现有的演示环境或一个维护中的示例存储库将前两个 `一周` 行压缩到一小时。
- 一个已经擅长运动图形的记录者将概念解释器上移，并将运动设计解释器进一步上移：概念解释器仍然作为普通图表工作，而运动设计解释器需要动画能力，而不仅仅是图表阅读能力。
- 一个有视频编辑员在编的团队降低了深入分析的编辑成本，这是其大部分努力。

努力、价值、开启和深度列反映了视频制作工艺经验；用户可以根据自己的上下文调整任何单元格。

**短形式和长形式通过不同的时钟触达观众。** 通道快速向非订阅者推送短形式片段，因此其触达量会迅速激增并在几天内耗尽。主导视频平台首先向订阅者展示长形式视频，并且只有在观看时间累积后才会将其扩展到非订阅者：这种缓慢的斜坡是为什么它会复合的原因。

运行时证据背后的运行时带：中位数的参与时间是无论总视频长度如何最多六分钟，并且中位数的观众在观看超过九分钟的视频时不到一半（郭等人）。Wistia 的 2026 年关于 1300 万个托管视频的报告也指向相同方向 - 不到一分钟的视频平均参与率为 52% - 尽管这是一个商业视频语料库，而不是教学语料库。超过六分钟的长度是一个有已知成本的决策；只有在有章节和理由的情况下才采取。

**程序性视频与概念性视频的使用方式不同**，这比运行时更能改变脚本。在同一项研究中，教程平均观看时间为 2-3 分钟（无论长度如何），重播次数多于讲座，并在看起来像步骤边界的地方选择性地暂停。

- 一个演示、边学边做或错误/修复视频是参考材料：标题段、每节起始状态和一个可复制粘贴的配套工件是其核心，而不是其润色。
- 一个概念解释器、运动设计解释器或深入分析更接近讲座 - 在那里，优化不间断的第一遍观看。

## 开启节拍

主导视频平台的保留报告将引言评分为主观观看者在第一 30 秒后仍然观看的份额 - 这是一个平台定义的测量边界，因此将其视为预算。四个工作，都在其中：

1. 用观众自己的话说出问题 - 错误、症状、他们搜索的任务。运动设计解释器没有终端来显示错误，所以像观众会对队友说的那样命名指标或反复的痛点：“我的 500 错误率太高”。
2. 显示运行结果。不是它的承诺，而是它本身。在一个运动设计解释器中，显示解决状态：指标回到观众想要的位置。
3. 声明先决条件，以便错误的观众在第二十秒离开，而不是在第四分钟离开。
4. 声明运行时，因为观众已经在寻找它。

仪式在它被读取为填充内容之前大约有五秒钟 - 这是一个感知阈值 NN/g 测量的，而不是一个硬性截止：引言动画、频道品牌、“大家好，欢迎回来”。设置、安装和凭证永远不会在这里属于这里 - 它们属于在回报之后，或者在配套存储库中。

一个用于垂直表面的短形式片段（YouTube Shorts、TikTok、Instagram Reels）根本不得到这个窗口：片段本身运行不到 60 秒，并且平台决定在第一秒或两秒内是否继续播放，而不是在第一 30 秒。直接开启回报或笑点 - 没有仪式预算可以花费，也没有设置节拍可以推迟。

## 节拍格式

每行一个节拍。保持列分开 - 它们是观众的两个频道，按列阅读表格是最低成本的审查通过方式。

| 字段            | 内容                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 视觉            | 填满画面的内容：编辑器、终端、浏览器、图表、人脸                                                              |
| 屏幕上的动作    | 发生的变化：文件打开、命令运行、行高亮、放大                                                                |
| 解说            | 说话的内容，写成可以朗读的形式                                                                      |
| 起始状态        | 分支/标签、种子数据、打开的文件、清空的终端 - 使此节拍可以单独重拍的内容                                           |
| 预计秒数        | 解说时间加上预期的死时间                                                                            |
| 核心 / 可剪切    | 现在决定，所以剪切列表不是后来的论点                                                                 |

运动设计节拍保持相同的列：视觉命名插图或场景，屏幕上的动作命名动画（进入、变形、高亮、过渡），起始状态命名在绘制此节拍之前必须存在的资产，而不是机器状态。在屏幕上的动作中标记每个携带音乐提示或过渡的节拍，因为配乐是按照这些标记剪辑的。将屏幕上的文本限制为标签或简短短语，永远不是段落，并且永远不要逐字解说它 - 解说评论它，因为观众不能同时阅读和听相同的词。将状态变化为状态，而不是文本在静态帧上淡入：带有擦除的幻灯片不是运动设计。

短形式片段增加了表格没有的其他三个约束。帧垂直（9:16），并且保持主题和任何屏幕上的文本在平台自己的 UI 保留的顶部和底部带之外 - 注意视觉列中的安全区。将字幕烧入帧而不是依赖自动字幕，因为大多数短形式观看从静音开始。在循环回节拍 1 的自然节拍上结束，或者在回报本身上结束 - 永远不在淡出或调用操作卡片上结束，这会使重播感觉是重复的而不是奖励的。

完整模板，包括章节列表和剪切计划：[./references/script-template.md](./references/script-template.md)。

## 屏幕上的代码

脚本控制节奏，而不是编辑器。将这些决策写入节拍：

- **在开始时解说，而不是在过程中。** 说块的作用，然后显示它，让观众阅读。与阅读竞争的解说会失去两个频道。
- **结果后保持帧。** 静默足够长，以便阅读输出是一个编写的节拍，而不是一个意外。用评论填充它是最常见的开发者视频节奏缺陷。
- **永远不要键入不是课程的内容。** 导入、样板、配置、长字符串、重复的脚手架：预先提供、粘贴或片段扩展。只键入视频讨论的行，慢慢。
- **显示差异，而不是两个文件。** 标记携带主张的一行 - 放大、高亮或变暗其余部分 - 并说它是哪一行。
- **最小的片段携带要点。** 屏幕上的完整文件突出显示什么。
- **清理帧。** 通知关闭、无关的选项卡关闭、没有文件树没人打开、没有收件箱徽章、没有个人书签。每次移除都将注意力返回到代码，并消除意外披露风险。
- **可读性底线：** 终端文本 24pt 或更大，编辑器文本 20pt 或更大，在手机大小的播放而不是作者监视器上验证的高对比度主题。这两个点大小是这个技能的底线；发布的屏幕录制标准说“大字体”而没有数字。永远不要单靠颜色传递意义。

努力信号，因为格式从后面开始。代码屏幕录制坐在一项关于教学格式的较大研究的较弱的桶中：连续的平板绘画教程的参与度是它们的标准化参与度的 1.5-2 倍，并且论文的建议是当代码必须在屏幕上时，在上面绘制。

所以补偿杠杆是运动、注释、缩放，以及在刻意时刻切入一个面 - 交替呈现仅呈现呈现者节拍幻灯片，而工作室制作价值没有改变。每个杠杆都是视觉列中的一行，而不是编辑后的想法。

## 段落、章节和元数据

在编写脚本时决定的段落边界实际上是章节，所以将每个章节标题写在它的段落旁边，并让时间码在编辑后填写。

- 将章节标题作为观众在搜索词汇中的任务或结果 - “修复 CORS 错误”，而不是“第 2 部分”。
- 主导视频平台记录了四个章节要求：第一个时间戳 `00:00`，至少三个时间戳，每个章节 10 秒或更长，按升序排列。文档站播放器通常将相同的列表作为字幕提示，所以一个章节列表服务于两者。如果你可以浏览网页，在发货前重新检查当前规则；如果你不能，请坚持这些规则，并说明它们没有被重新验证。
- 没有自然章节边界的视频通常是两个视频。

一个脚本也提供描述、字幕更正通行证、配套书面页面，以及从单个节拍剪辑的短形式片段 - 在编写时标记可剪辑的节拍。参见 [./references/recording-brief.md](./references/recording-brief.md)。

## 解说语言

为耳朵和看不见屏幕的观众写作。

**禁止指示性解说。** “如您所见”， “点击那里”， “将这个改为那个” 没有图片就携带零信息 - 它们也是使自动生成的字幕轨道无法使用的原因。

| 指示性                        | 集成                                              |
| ------------------------------ | ------------------------------------------------ |
| “现在我将这个改为那个”        | “我正在将 `timeout` 字段从 30 改为 5 秒”         |
| “点击这里，然后那里”        | “打开设置，然后 Webhooks 选项卡”                  |
| “如您所见，它失败了”         | “请求返回一个 403，带有 `invalid_signature`”    |

这是 W3C 的集成描述方法：将视觉信息写入主要解说，然后验证单独的音频仍然教授了这件事。在脚本时间做它比在完成录制后附加一个单独的描述轨道要便宜得多，并且这是使视频可用为收听、文本记录和翻译的原因。

此外：

- 短句。从句在页面上存活，在耳中死亡。
- 缩写、第二人称、开发者会在白板上使用的词语。
- 在标识符第一次出现时（`char`、`kubectl`、`SQLite`）在脚本中纠正发音，以便录制不会在它上面停滞。
- 对于一个人工合成声音覆盖，解说列是最终音频逐字 - 没有拍摄来捕捉误读的行。将音频仅通行证与合成引擎将读取的逐字文本进行比较，并标记每个默认阅读会放置错误的暂停或强调，因为否则人类记录者会通过耳朵修复两者。
- 不要为了理解而填充。在 48-254 wpm 语料库中，参与度随着说话速度上升 - 在长度带内高达 2 倍 - 但作者是明确的，速度是热情的表面代理，而不是杠杆：带来能量；不要强迫速度。根据记录者自己的测量速度预算运行时，而不是表值。
- 逐字脚本或要点是记录者的选择。无论如何，标记必须逐字说出的句子：主张、版本号、术语、号召行动。
- 将解说写成可以单独站立。记录者首先捕捉音频、首先捕捉视频或同时捕捉两者，并且一个只有在特定帧上才有意义的句子会打破这三个顺序中的两个。

## 审查你没有编写的脚本

当用户带来现有脚本或表现不佳的视频时，诊断而不是重写。观众离开的原因有三种，并且每种都可以逐行检查：

1. **逻辑断裂** - 节拍结束在 A，下一个在 C 打开，并且桥接句子从未被说出。
2. **密度下降** - 节拍重复屏幕已经显示的内容，或者绕着一个需要一句话的点。
3. **不可说的行** - 太长、太书面化或太缠结，无法一口气读出来。

按顺序使用这个三原因模型：编号节拍（编号、主题、功能、状态），然后对每个发现评为高风险（观众可能在这里离开）、中等（注意力分散）或低风险（如果改变更好）。优先考虑错过一个小建议而不是埋藏一个高风险建议。

三个规则使审查保持诚实：

- 首先询问格式 - 一个访谈式解释器和无声字幕片段的评判不同，并且答案会改变一半的发现。
- 保持作者文本：在建议替换旁边显示原始行，而不是覆盖，以便一个被拒绝的建议在下一轮仍然可追溯。
- 不要制造发现 - 如果脚本流畅，请在三行内说明。

在剪切一个节拍作为旁支之前，检查观众是否可以在下一个关键时刻推断出缺失的含义。如果他们不能，它是一个承重论点，而不是填充。评判它是如何说的，而不是什么被声称：作者的论点、示例和数字是他们的。

```markdown
## 承诺

一句话：对于<观众>，这个视频展示了<事物>的工作情况。

## 节拍

| 序号 | 视觉效果 | 屏幕上的动作 | 解说 | 初始状态 | 预计时长 | 核心/可删减 |

## 章节

00:00 <任务形状的标题> · <下一步> · <下一步>

## 切割计划

可切割的节拍按顺序标记，如果运行时超时，则按顺序进行。

## 录制简报

初始状态、机器卫生、必须保持在屏幕外的内容、字幕包、包含一个行动号召的描述。

## 运行时

解说字数 ÷ 测量速率 + 每个节拍的死时间 = 估计值与目标值的比较。

## 受众背景

节拍是相同的；三个因素会随着到来的人和视频的传播方式而变化。

**个人采用/自助服务 (PLG B2B混合)。** 观众是一个正在评估自助服务的开发者，同时也是一个通过该开发者的分享到达的管理员——单个视频服务于双方。将整个路径保留在免费套餐内，在演示中途不要揭示付费墙，并将配套存储库链接放在足够早的节拍中以便被捕获。同时应用以下三个以销售为导向的规则。

**以销售为导向的B2B，企业或买家相邻。** 第二个观众正在观看，他们不会输入任何内容，屏幕录制是一个耐久、可传递的文档。

- 删除或预填显示客户名称、租户ID、内部主机名和定价的每个屏幕。
- 大声说明版本和限制，因为视频中的过度声明会超过它所描述的发布版本。
- 预期视频将在采购或安全审查中重播，在“这取决于”不可见的情况下。

**B2C/个人面向。** 与个人采用/自助服务上述内容相同——观众对你没有任何义务，并且可以随时离开。

## 通过阈值

迭代直到所有七个门都保持：

1. 承诺是一句话，并且开头的节拍在30秒内传达了它。
2. 每个节拍都有一个精确的初始状态，足以单独重拍该节拍。
3. 只有音频的阅读仍然能教这个事物——零指示性句子保留。
4. 运行时估计包括每个节拍的死时间，并且落在目标范围内。
5. 每个片段都有一个章节标题，并且每个章节都满足平台的最低长度要求。
6. 每个节拍都被标记为核心或可删减，并且删除所有可删减的节拍仍然传达承诺。
7. 屏幕上或解说中的每个事实声明都是记录器可以在录制机器上重制的声明。

第6个标准是人们经常跳过的。没有切割列表的脚本会变成一个14分钟的视频，因为没有人能在编辑时决定要失去什么。

## KPI

将每个指标与您自己的相同形状的先前视频进行比较，永远不会与一个虚构的基准进行比较。每个指标的含义是什么：

- 开头留存率：30秒后仍在观看的百分比。这评估了开头的节拍，而不是其他任何东西。
- 滑落位置映射回特定的节拍——曲线说明在哪里，脚本说明要重写什么。
- 平均百分比观看，在同一形状内进行比较；像查看日志片段一样深入观看的视频是形状不正确，而不是标题不正确。
- 章节使用情况：哪些章节被直接跳转。直接的直接入口意味着视频正在被用作参考，应该被分割。
- 配套链接点击，以及它们引导的行动（存储库克隆、文档页面、注册）。
- 录制期间每个节拍的重拍次数——需要六次重拍的节拍是一个脚本缺陷，通常是初始状态不切实际。

对峰值保持怀疑：重播的片段可能意味着“那很棒”或“我不得不看三遍”。在优化之前检查评论。

## 失败模式

| 症状                                                         | 修复                                                                                                                                          |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 前30秒是设置和问候                                             | 将工作结果移至节拍1；设置在回报之后或放入存储库                                                              |
| 观众每次都在同一分钟掉线                                     | 大声朗读那个节拍；它通常是同一个节拍里的两个概念或未解释的输入                                                           |
| 录制期间运行时翻倍                                           | 从未预算死时间；为构建、安装和暂停添加每个节拍估计                                                               |
| 解说重述屏幕上的文本                                           | 重写一个频道——屏幕显示，解说说明原因                                                                           |
| 脚本无法从中间重拍                                             | 添加初始状态；没有节拍可以依赖于先前节拍的实时输出                                                               |
| 字幕在技术术语上无法理解                                     | 根据解说列修正自动字幕，不要重新转录                                                                          |
| 有人必须决定编辑中的切割                                       | 切割列表属于脚本，在录制前决定                                                                                 |
| 代码在手机上无法阅读                                         | 提高字体大小，放大片段，显示差异而不是文件                                                                     |
| 在第3次拍摄中屏幕上出现了客户名称                             | 机器卫生和预填数据属于录制简报，按节拍                                                                      |
| 视频是一个功能巡游                                           | 返回承诺；删除每个不证明它的节拍                                                                              |
| 一个旨在从头到尾观看的逐步指南                                 | 分段，为每个分段命名，给每个分段一个初始状态——程序视频在中间进入并重播（见工作示例7） |
```
