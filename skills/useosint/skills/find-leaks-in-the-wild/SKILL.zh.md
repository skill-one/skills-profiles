# 在野外寻找数据泄露

这是数据在索引之前出现的地方，你发现的大部分内容都是多年前泄露内容的重组。两个错误最常导致问题：假设粘贴主机的搜索功能能找到粘贴内容，以及将组合密码列表报告为泄露事件。前者浪费一天时间；后者是在交付成果中存在的事实性错误，并且会被发现。

## 你持有的信息从何处开始

| 你持有 | 从何处开始 | 原因 |
|---|---|---|
| 一封电子邮件或用户名 | 首先使用精选泄露服务 | 价格低廉、可追溯，并能回答大多数问题 —— `what-leaked-about-you` |
| 你认为正在传播的选择器 | 粘贴主机的 `site:` 扫描，然后使用粘贴聚合器 | 搜索引擎很浅但免费；聚合器能触及从未被爬取的内容 |
| 已被删除的粘贴 | 历史粘贴语料库 | 删除是常态；某些服务会保留内容 |
| 对某知名公司的声称泄露 | 该公司的自行披露，然后是监管机构的通知 | 一个权威来源胜过任何论坛讨论 |
| 正在宣传的数据集 | 样本的结构分析 | 你几乎不需要完整的数据集来回答问题 |
| 你正在防御的域名 | 供应商监控加上你自己的示警选择器 | 一次性搜索会错过它们之间发布的一切内容 |

## 为什么粘贴站点搜索不起作用

粘贴默认情况下是未列出的。没有索引页面，没有目录，只能通过 URL 访问——因此主机没有可搜索的内容，爬虫也没有可遵循的链接。当主机提供消防水龙带或抓取界面时，通常仅限于付费账户并使用 IP 白名单，因为公开版本被滥用。数量巨大，保留时间短。

因此人们通过以下四种方式找到粘贴，按产出量大致排序：持续抓取粘贴主机并索引内容的第三方聚合器；在原始内容被删除后保留内容的歷史粘贴语料库；搜索引擎的 `site:` 查询，由于页面未链接且生命周期短，因此很浅但免费；以及索引粘贴泄露事件的精选泄露服务。

首先运行免费工具；查询形状在 `google-like-a-spy`。请注意，粘贴生态系统远比明显的托管站点更广泛：现代粘贴服务、代码沙盒、gist、发布到网络上的文档，以及客户端加密粘贴软件，其内容服务器本身无法读取，因此对现有的所有聚合器都不可见。

## 论坛：一个具有生命周期的类别

不要学习站点名称；要学习模式。论坛积累用户和数据，成为公认的市集，吸引执法部门，被查封或其运营者被捕——几周内就会出现一个声称连续性的继任者，通常与相同的员工和导入的用户数据库。名称会改变。类别不会。

三个改变你行为后果：

- **在查封后被“恢复”的论坛可能由执法部门运营或监控。** 这已经发生过。注册会将你的详细信息放入证据集。
- **注册是一项持久风险。** 论坛数据库泄露、被查封并发布。假设你创建的任何账户最终都会公开，并附带其电子邮件、IP 历史和帖子。
- **未注册的访客能看到的是营销内容，而不是数据。** 声望等级和付费墙会限制实际数据集，这正是购买访问权限导致法律风险升级的原因。

许多组织禁止调查人员接触这些网站，并从接受了风险合同的供应商那里购买情报。这是一个合法的答案，而不是推诿。

## Telegram 是分发层

结构原因，不是时尚：频道向无限数量的订阅者广播，大文件直接附加，被禁止的频道几分钟内就会重新创建，并且公共频道无需邀请即可访问。

**通过平台的公共预览在浏览器中阅读公共频道。** 无需账户，无需加入。加入是一个账户操作，会暴露你，并且对于阅读公共频道来说，它为你提供不了任何东西。首先这样做，并且在大多数调查中，只这样做。

发现是困难的部分——应用内搜索对于找到你不知道的频道很弱。第三方频道索引和频道搜索服务是实际途径，并且它们还为你提供订阅者历史和帖子存档，频道本身不会提供。

两个平台特定细节值得了解。**转发消息会携带对原始频道的归属信息**，因此转发链可以重建分发路径，并且通常能追溯到源头。并且**机器人被用作泄露数据库的检索前端**——查询一个会暴露你的账户并将其选择器交给其操作员，因此将任何此类机器人视为指向你的情报收集器。

频道会消失并带走它们的存档。看到它们时立即捕获帖子、文件列表和元数据。

如果你需要一个账户，它必须是专用的，号码不是你的，并且在首次启动前锁定发现和联系人同步设置。`investigate-without-getting-made` 涵盖了整个环境；不要在这里即兴创作。

## 真实泄露还是循环组合密码列表

将任何作为新泄露呈现的内容的默认假设是它是旧材料的重组，因为大部分内容都是。让声明证明其价值超越这一点。

最强证据是外部的：声称受害者的自行披露，或监管机构或 CERT 的通知。在触摸数据之前检查这些。

结构上，真实的源数据泄露继承了它来自的应用程序的架构：一致的列顺序、连贯的内部标识符（在记录被删除的地方有空白）、跨越服务实际生命周期的注册时间戳、适用于那个时代的哈希方案、电子邮件域分布与用户群匹配，以及——最强的积极信号——只有该服务会收集的字段，如订阅等级或游戏角色名称。

组合密码列表看起来与所有这些都不一样：两列、无元数据、排序和去重、记录数量可疑、几种哈希格式混合在一起，以及与在同一密码下较早且可追溯的泄露事件的重叠严重。一些重叠是正常的，因为人们会重复使用凭证——你在衡量的是重复率。

另外两种要排除的失败模式：一个**作为黑客进行营销的公共抓取**，其中每个字段都是平台已经显示的字段；以及一个**已经以另一个名称流传的数据集**，通过搜索公告的独特字符串——精确记录数量、文件名、卖家的措辞——在粘贴和论坛语料库中找到。

## 监控与搜索一次

一次性搜索回答“现在是否泄露”，并且会错过搜索之间发布的一切内容，鉴于典型的粘贴保留时间，大部分内容都会被错过。持续曝光需要持续收集，实际上这意味着购买供应商监控，因为你针对这些来源运行自己的收集正是你避免的风险。购买前问一个问题：**他们的收集从何时开始**，因为覆盖范围从那时开始，没有人会补充他们从未捕获的内容。

然后衡量它们。将示警选择器——唯一的电子邮件地址和标识符，每个供应商和每个合作伙伴都不同——植入你正在保护的系统。示警不仅告诉你是否发生了泄露，还告诉你*哪个下游方泄露了它*，使其成为这里唯一产生归因而不是检测的机制。它还独立衡量你的监控供应商是否看到了他们声称看到的内容。

## 哪里出错

- **组合密码列表破坏了来源。** 一个匹配告诉你一对出现在某个地方，而不是它来自哪个服务——这正是调查的价值所在。
- **声称的日期是营销。** 泄露日期、首次传播日期和你的源摄入日期是三件不同的事，通常相隔多年。
- **缺席是无信息的。** 没有找到选择器意味着它不在你能触及的语料库中。大多数泄露材料根本不会公开发布。
- **卖家在两个方向上都会撒谎关于范围**，为价格虚报并为了避开注意而低估。抓取经常被重新标记为泄露，包括由供应商标记。
- **你的搜索会被记录**——由供应商平台、机器人、论坛搜索框记录。假设你查找的每个选择器都被某人保留。
- **公告数量不是事件数量。** 同一个数据集会被许多转售商重新公告，并且计帖子会高估活动。
- **恶意软件和钓鱼是镜像和泄露站点克隆的要点**，这些专门针对通过搜索到达新域名的用户。

## 置信评级

- **确认**——声称受害者或监管机构已披露事件，并且样本的结构与该披露一致。
- **可能**——没有披露，但服务特定字段、连贯的内部标识符、合理的时戳和哈希，以及与先前语料库的低重叠。
- **未确认**——一个可信样本，没有披露也没有区分结构，或者你只见过卖家描述的数据集。
- **拒绝**——与同一密码的先前泄露高度重叠、两列组合密码列表形状、记录数量超过受害者的合理用户群、将抓取作为妥协呈现，或以另一个名称更早出现。

在书面记录中将三个声明分开：一个数据集存在并正在传播；它包含与你的主题相关的记录；以及你的主题的系统被入侵。第三个要强大得多，并且你的主题的数据会从供应商、合作伙伴、旧收购和无关服务中泄露。

## 工作示例

客户的域名出现在一个 Telegram 帖子中，该帖子广告宣传对某个知名 SaaS 提供商的“新鲜 2.4M 泄露”。

供应商没有发布任何披露，并且不存在监管机构通知。从频道的公共网络预览中读取卖家的样本，无需加入，是两列 `email:password`，已排序，没有用户 ID，没有注册日期，也没有该产品的特定字段。

死胡同：在粘贴语料库中搜索确切的记录数量和文件名，没有发现更早的，因此“已经以另一个名称流传”的测试是不确定的而不是确认的。

重叠解决了问题。检查的 12 个样本记录中有 3 个出现在三个较早且可追溯的泄露事件中，具有相同的密码。圆形计数、无架构、几乎完全重叠：一个以可识别的品牌名称营销的组合密码列表。

报告为：与客户员工相关的记录正在传播——**可能**；命名提供者被入侵——**拒绝**，并记录了理由。客户的补救措施是密码旋转，无论凭证的来源如何，因为凭证正在流通。

## 法律和处理说明

**永远不要使用泄露的凭证来验证任何内容。** 不是验证账户是否存在，不是一次，不是在客户口头许可下。凭证填充在大多数司法管辖区是未经授权的访问，并且密码的公开性不是抗辩理由。这同样适用于密码重置和恢复的安全问题答案。

**永远不要购买、寻求或交易泄露数据。** 除了资助交易外，购买和寻求在许多司法管辖区是犯罪的，而阅读公共页面不是，这是将调查变成犯罪的行为线。

**占有取决于司法管辖区。** 某些司法管辖区会因获取方式而将某些类别的被盗数据占有定为犯罪，而其他司法管辖区将其视为受数据保护规则约束的合法处理。在下载任何内容之前，了解适用于你的规则，并在考虑下载的任何协议中书面记录该决定。

实际上：分析样本而不是获取完整数据集，保留最少，以加密形式存储并在日志中记录访问，永远不要保留凭证，按开始时编写的计划删除，并记录每个保留项目为何必要。在 GDPR 和同等制度下，这是个人数据，并且通常是特殊类别数据，处理它需要合法依据。参见 [../../ETHICS.md](../../ETHICS.md)。
