# 创意疲劳

分析创意随时间推移的表现数据，判断其是否确实在衰退，衰退的置信度如何，以及应如何应对。核心原则是拒绝：许多因素可能导致指标下降，而创意疲劳只是其中之一。大多数刷新决策都是过早做出，基于单一指标，且没有基线参考。

这项技能按固定顺序运行差值诊断，混淆因素筛查在疲劳判断之前，绝不之后：

1. 基线
2. 混淆因素筛查
3. 衰减测量
4. 置信度门槛
5. 判定

有两个持续的张力：

- 疲劳通常是钩子疲劳而非整个广告疲劳（Ben Heath）。
- 某些广告随着重复曝光效果会提升，Les Binet在品牌广告中描述的“适应效应”，尽管Meta 2023年的研究发现直接响应目标没有适应效应——适应效应只有在目标是品牌而非直接响应时才是真实的判定。

这里没有通用阈值：每个触发因素都源自创意自身的滞后基线和账户自身的历史。命名实践者数字仅作为归因的起始参考点出现。

这项技能在判定和建议行动后结束。

- 制作替换资产属于 `mbfinotti/advertising-skills@ad-copy-variants`、`mbfinotti/advertising-skills@ugc-ad-scripts` 和 `mbfinotti/advertising-skills@ad-creative-brief`。
- 预发布测试的样本量属于 `mbfinotti/advertising-skills@ad-creative-test-plan`。
- 发布前评分视频开篇属于 `mbfinotti/advertising-skills@ad-hook-analyzer`（在此，钩子率仅作为已运行广告的衰减信号读取）。
- 当混淆因素筛查显示问题根本不是创意本身（结构、定向、追踪）时，转交给 `mbfinotti/advertising-skills@ad-account-diagnostic`。
- 再营销序列和频率上限架构设计是 `mbfinotti/advertising-skills@retargeting-funnel`。
- 获胜后的扩展和节奏决策是 `mbfinotti/advertising-skills@paid-media-scaling` 和 `mbfinotti/advertising-skills@ad-budget-pacing`。

## 面谈

在诊断任何内容之前进行询问。每条消息一个问题；尽可能提供多选答案；跳过已回答或提供数据中可见的内容。

- 创意运行在哪些平台？（Meta / Google Ads - 搜索、Performance Max 或 YouTube / LinkedIn / TikTok / 其他）
- B2B还是B2C/电商？
- 渠道阶段：冷触达还是再营销/温触达？（两种情况下的耐受曝光差异很大。）
- 你能导出什么，以及粒度如何：每个创意每天、每个创意每周汇总，还是仅广告组/活动级别？每个创意每天是工作假设；任何更粗粒度的数据都会削弱下游的每个步骤。
- 创意每日支出和转化量？（决定置信度门槛是否能够清除。）
- 广告组的大致受众规模，以及受众列表是否基于ABM或广泛？
- 同一广告组中有多少创意在运行？（兄弟组合改变了“失去支出份额”的含义。）
- 广告或其父广告组/活动最后一次编辑是什么时候——创意、预算、出价、受众、优化事件？确切日期很重要。
- 在可疑窗口期间预算是否发生变化？变化了多少？
- 结果必须在什么日期前得出？（硬性截止日期会促进行动阶梯的当日运行——轮换、预算转移、频率上限——并降低迭代和新创意。）
- 你想要这个创意的一次性胜利，还是复合型资产？（复合型任务即使在配置修复可以维持本周的情况下也会促进迭代和新创意。）
- 你的努力上限是什么：创意生产能力、交付时间、内部编辑小时数、需要哪些人的签核列表工作，以及变更的可逆性如何？（没有人能执行的刷新建议是无用的——这个答案会从行动阶梯中删除步骤，而不是重新排序它们。）
- 创意被评判的目标CPA或ROAS是多少？

## 工作流程

1. 运行面谈；在触摸数据之前收集所有答案。
2. 确定分析单位。在创意和概念级别分析，绝不在活动平均数级别：五个概念各有四十个变体的四十行隐藏了真实模式，一个疲劳广告拉低广告组平均数看起来像是一个全局问题。在平台自动轮换变体（Advantage+-风格交付、动态创意）的情况下，读取资产级分解——自动轮换会掩盖单个资产的衰减。相反，一个创意在没有任何手动更改的情况下默默失去预算份额本身就是一个衰减信号。
3. 构建创意自身的基线。永远不要比较单日。

   提供作为起始默认值的源方法，根据用户的数据粒度选择，并由其自身历史覆盖——两者不进行排名，因为它们产生相同数量的单一导出，只有粒度决定：

   - 3天移动平均与创意自身滞后14天基线对比（AdSights）。
   - 7天滚动窗口与30天基线对比（Segwise）。

   排除已知中断，并使比较窗口的星期几组成与基线相匹配。如果你的 harness 可以读取导出或运行计算，请计算它；否则发出确切的导出步骤和电子表格公式（列、移动平均范围、差值公式 `(当前 - 基线) / 基线`)，供用户运行并反馈。

4. 运行混淆因素筛查，在任何疲劳讨论之前。参考 [references/confounders.md](references/confounders.md) 并标记每个混淆因素通过（排除）或失败（存在）：

   - 预算/出价变化
   - 学习阶段重置
   - 受众重叠/饱和
   - 出价CPM通胀
   - 季节性和窗口组成
   - 追踪中断
   - 归因窗口偏差
   - 布局/设备组合变化
   - 统计噪声
   - 落地页/报价变化
   - 兄弟组合变化

   任何解释下降的失败都会结束疲劳调查：判定是 `confounded`（受众情况为 `saturating`）并针对实际原因进行修复。结构/定向/追踪根本原因转交给 `mbfinotti/advertising-skills@ad-account-diagnostic`。

5. 使用 [references/signal-reference.md](references/signal-reference.md) 对基线进行衰减测量。应用该领域的共识决策规则：没有单一指标可以确认疲劳——要求至少两个信号在两个或多个连续时期内同步移动（Segwise；AdSights）。优先考虑领先信号（链接CTR衰减、视频钩子率衰减、首次印象率下降、沉默预算份额损失）而非滞后信号。频率是一个滞后、确认的信号——Meta自己的分析团队指出报告的频率在广告/广告组级别测量，而疲劳发生在创意级别，且是周期平均值，而不是下一个印象的边际效应。不要基于频率做出判断。
6. 应用置信度门槛（见下文）。如果它失败，判定是 `数据不足`——说明需要多少额外支出或天数才能清除它并停止；拒绝在噪声上建议刷新。
7. 在最终确定之前区分疲劳和饱和。区分逻辑：

   - 疲劳：成本上升而转化率保持。
   - 饱和：两者都下降，伴随首次印象率下降和覆盖范围平缓。

   如果用户可以运行，Meta自己的最终测试是：

   - 新创意在相同受众上恢复表现证明疲劳。
   - 表现仅在新鲜受众上恢复证明饱和。

   他们的修复是相反的，新创意与受众扩展，所以这个区分很重要。

8. 从判定阶梯中发出判定，然后从行动阶梯中选择补救措施——按效率排序的顶部首先，根据面谈的截止日期、一次性与复合、努力上限答案重新排序——并为每个创意填写一个判定块（形状如下；工作版本在 [references/examples.md](references/examples.md) 中）。
9. 设置重新检查日期（在采取任何行动后一个完整比较窗口后）并将决策记录到衡量部分的记分卡中。
10. 如果你的 harness 具有持久内存，记住账户的基线、每个创意的判定、采取的行动和重新检查日期，以便下一次运行从历史记录开始而不是重新推导。

## 置信度门槛

没有判定可以低于数据底部，而底部是用户自己的数学，而不是复制的常数：

- **噪声检查。** 对于率信号（CTR、钩子率、CVR），观察到的下降必须超过抽样噪声。将基线率的噪声带近似为 `p ± 2 × sqrt(p × (1-p) / n)`，其中 `n` 是比较窗口中的展示（或点击，对于CVR）。下降仍在该带内是噪声，无论它在图表上看起来如何。
- **双信号规则。** 至少两个信号，其中至少有一个是领先的，在两个或多个连续时期内朝同一方向移动（Segwise；AdSights）。一个指标，一个时期，永远不会清除门槛。
- **转化底部。** 对于基于CPA/ROAS的声明，基线和比较窗口中的转化足够多，使得delta通过CVR的相同噪声检查。低转化账户（大多数B2B）应基于领先的参与信号进行判定，并在判定置信度行中说明。

当门槛未满足时：报告 `数据不足`，计算需要多少额外天数或支出（天数 ≈ 需要多长时间才能使 `n` 使噪声带比当前流量下的观察到的delta更窄），并拒绝建议刷新。在数据不足的情况下终止创意是最昂贵的假阳性，这项技能存在就是为了防止这种情况。

## 判定阶梯

每个判定都映射到自己的行动——它们永远不会全部崩溃到“制作新创意”。这些判定故意不相互排名：证据精确地选择一个，所以对它们进行效率排序将是虚假精度。排名发生在下一级，在行动阶梯内部。

| 判定             | 含义                                                                                                                                                                  | 行动                                                                                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fatigued`          | 两个以上信号与自身基线衰减，混淆因素排除，门槛清除                                                                                            | 行动阶梯，最高回报每单位努力首先 - 除非证据排除环节1                                                                                       |
| `saturating`        | 受众池正在枯竭 - 首次印象率下降，覆盖范围平缓，CVR随成本下降                                                                                                                         | 受众扩展，新鲜种子，或排除——不是新创意；行动阶梯环节6，在此判定下优先；见 `mbfinotti/advertising-skills@ad-audience-targeting` |
| `confounded`        | 非创意原因解释了下降                                                                                                                                                                                                | 修复实际原因；结构/追踪原因转交给 `mbfinotti/advertising-skills@ad-account-diagnostic`                                                                          |
| `insufficient data` | 置信度门槛未满足                                                                                                                                                  | 报告差距，说明需要多少天数/支出，重新检查后；不刷新                                                                                                                     |
| `healthy`           | 信号在创意自身基线的噪声带内                                                                                                                                             | 留它不动；注明下次计划审查                                                                                                                                             |
| `wear-in`           | 表现随曝光提升——对品牌目标可能（Les Binet）；Meta发现直接响应没有适应效应，所以对直接响应的“适应”读取要持怀疑态度                                                                 | 留它不动；不要在频率数字上轮换它                                                                                                                                         |

## 行动阶梯

按每单位努力的回报排序——每个环节买什么，以及你为发送它付出的成本。不是按价格：最便宜和最值得做的环节很少是同一个环节，而“买一周”与“恢复广告”不是同一购买。

- 效率（默认顺序，以及下面的编号）：钩子交换 > 轮换和休息 > 预算转移 > 迭代赢家 > 频率上限 > 受众扩展 > 新概念 > 暂停
- 努力最轻的首先：轮换 == 预算转移 == 暂停 > 频率上限 > 钩子交换 > 受众扩展 > 迭代 > 新概念——三方平局是真正的平等，不是犹豫：每个都是一次控制台更改，不产生资产，不需要签核，并且可以同一天撤销
- 它买的东西的持久性：新概念 > 迭代 > 受众扩展 > 钩子交换 > 频率上限 > 轮换 > 预算转移 > 暂停——概念是每个迭代运行的原型，所以它比任何单个迭代更持久
- 合规成本最重的首先：受众扩展（客户列表和ABM上传需要法律依据证明和数据处理审查，上传的列表不容易取消共享）> 其他每个环节（近零——所有都是平台设置或新资产）

默认从第一级开始运行，并采用证据支持的最高级别。当上一级别已经尝试且衰退恢复，或信号模式将其排除时（钩子、持有率和CVR同时衰退意味着整个广告被消耗，而不是其开篇）向下移动一级。

**效率顺序的饥饿**。新概念在价值和努力上都很高，因此一个比率在每个回合都将它埋在第七级——它是唯一能修复耗尽的概念的级别，钩子交换或迭代都无法触及。当迭代停止在相同概念上连续尝试恢复性能时，请将其提升到所有其他事情之上：这种模式表明概念被消耗了，而不是其执行，然后每个更便宜的上级级别就什么也买不到了。受众扩展具有相同的价值-努力形状，但在这里没有被饥饿，因为`饱和`的裁决已经根据规则将其提升到第一级——它的失败模式是反向的，在`疲劳`下寻求它，这会浪费一个好的受众。

每个排序都是默认的，不是法律：它会随着账户的上下文和执行者而变化。根据你对这个账户的已有了解重新排序，并根据访谈的截止日期和指令回答：

- 一个始终在挑战者台上的广告会促进轮换到第一级。
- 一个可以当天交付新开篇的内部编辑者将钩子交换置于每个配置修复之前。
- 一个`饱和`的裁决会覆盖整个顺序：受众扩展成为第一级，创意工作被浪费。
- 一个硬截止日期会促进同一天的级别。
- 一个复合指令会促进迭代和新概念。

努力上限做不同的事情：它**删除**账户的梯子上的级别，而不是降级它们。

- 没有生产能力，或领先时间超过截止日期，会删除新概念和迭代。
- 没有编辑会删除钩子交换。
- 一个锁定或空的创意库会删除轮换。
- 没有合法基础签字会删除受众扩展。

在裁决的`排除`行上命名每个被删除的级别和删除它的约束，然后采取最高排名的幸存者。一个仅仅停在公司列表底部的级别仍然在公司列表上，并且稍后作为没有人同意资助的范围回来。

1. **同一主体上的钩子/缩略图交换**
   - 努力：一两个小时的视频编辑，没有简报周期。
   - 购买：广告回到同一受众，只要主体保持。
   - 正确的时间：钩子率或拇指停止衰退，但持有率和CVR保持——开篇累了，不是广告（Ben Heath的“广告疲劳通常是钩子疲劳”）。
   - 注意：如果负面反馈率升高，同一创意ID上的钩子交换不会清除算法惩罚；交付一个新的资产ID。

2. **从现有库存中轮换并休息创意**
   - 努力：近零，仅配置。
   - 购买：一个窗口，在受众循环时，不是修复——衰退在你离开的地方等待。
   - 正确的时间：账户保持一个始终在挑战者台上的广告；没有一个是没用的。
   - 注意：在池子翻滚后重新引入休息的创意，同时推广一个被证明的挑战者。

3. **预算转移到更健康的创意**
   - 努力：近零，可以同一天逆转。
   - 购买：在替代品启动时的时间和CPA保护。
   - 注意：保持一个仍然盈利的疲劳广告运行；永远不要暂停一个没有准备的生产者。与任何其他级别配对，而不是与之竞争。

4. **迭代获胜者**
   - 努力：几天，加上一个生产简报和一个测试槽。
   - 购买：梯子上最大的持久回报——相同的概念在新执行（新钩子、开篇秒数、格式、宽高比或副本）运行几周。
   - 证据：从业者报告元素级迭代通常在没有完全重建的情况下恢复大部分原始性能（Hawky报告的带宽是60-80%——将其视为他们的数字，而不是承诺）。
   - 参考：通过`mbfinotti/advertising-skills@ad-copy-variants`、`mbfinotti/advertising-skills@ugc-ad-scripts`或`mbfinotti/advertising-skills@ad-creative-brief`进行简报生产。

5. **频率上限或排除**
   - 努力：配置，加上就谁拥有上限达成一致。
   - 购买：对一个过度曝光的温暖池子的缓解，以及在冷挖掘中什么也得不到。
   - 正确的时间：曝光集中在已经见过它的温暖池子上。
   - 参考：上限架构的设计属于`mbfinotti/advertising-skills@retargeting-funnel`。

6. **受众扩展或新鲜种子**
   - 努力：配置加上列表工作，对于客户列表或ABM上传，需要一个合法基础签字——几天到一周，一旦列表上传后很难撤销。
   - 购买：一个新的池子，唯一能移动`饱和`裁决的东西。
   - 注意：将其应用于真正的疲劳会浪费一个好的受众；在`饱和`下它是第一级。

7. **新概念**
   - 努力：几周，完整生产和测试计划。
   - 购买：当概念而不是执行被耗尽时，资产的新线——梯子上每次尝试的最低命中率，和最高的上限。
   - 参考框架：一个常见的投资组合分割是70%已证明的/20%测试的/10%实验的；将其视为一个操作启发式算法来适应，而不是一个规则。
   - 参考：用`mbfinotti/advertising-skills@ad-creative-test-plan`测试启动。

8. **暂停**
   - 努力：近零，可以立即逆转。
   - 购买：一个停止的损失和什么也得不到——创意的剩余贡献也随之消失。
   - 注意：最后手段，并且只有在替代品在线或预算重新分配时。暂停不会重置平台学习；编辑一个正在运行的广告会。

## 每个平台的注意事项

仅指明——指标机制和平台怪癖存在于[参考资料/信号参考.md](参考资料/信号参考.md)。

- **Meta**：原生“创意疲劳”和“创意有限”交付状态存在，但滞后严重（据Meta文档通过行业消息来源转述，成本每结果翻倍时报告）——如果它们正在触发，检测已经太慢了。首次印象比率是原生的。优势+无声地转移预算远离疲劳资产，掩盖了信号；阅读每个资产的细分。任何重大编辑都会重置学习阶段。

- **Google Ads**：在RSAs中，资产性能标签（学习/低/好/最佳）是基于性能的信号。广告强度不是——它衡量多样性和完整性，Optmyzr的分析发现“平均”强度的广告具有最佳的CPA/CVR；永远不要将广告强度视为疲劳。绩效最大在组合级别上是不透明的——从每个资产的报告开始工作。YouTube：观看率衰退和每用户频率是杠杆。

- **LinkedIn**：官方指南是每1-2周轮换最低参与度的广告，并保持每个活动4-5个广告。交付机制将曝光与创意数量绑定（AJ Wilcox观察到的“48小时内7个”模式），因此一个小创意集会自我限制。小B2B受众缓慢但无情地积累频率，针对昂贵的CPM。

- **TikTok**：主要平台中最快的磨损；TikTok自己的指南建议大约7天的刷新周期，围绕持续下降的交付趋势。钩子率先移动；每日新用户覆盖直接标志饱和；自动创意优化掩盖了每个资产的衰退——阅读资产细分。

## B2B与B2C

方法（自有基线、混杂屏幕、两信号规则、裁决梯子）在两者中都是相同的。不同之处在于数据量、曝光机制，以及哪些信号发出呼叫。

**B2B**：

- 可寻址受众很小，有时被平台限制，因此频率结构性地上升，而不是作为衰退症状。
- 转化量通常太低，无法达到转化底线；依靠领先的参与信号（链接CTR、参与率趋势、3-6周窗口内的CPL漂移）并在置信行中说明。
- 长销售周期意味着转化信号滞后于创意信号几周。永远不要将一个平坦的管道周视为创意失败。
- ABM和基于列表的受众被设计为饱和；比`疲劳`更频繁地期待`饱和`裁决。

**B2C/电子商务**：

- 大池子和高转化量使完整的统计门可用。
- 磨损在狭窄的再营销段上运行得最快。

**两者**：温暖/再营销受众比冷受众忍受更高的曝光。Ben Heath报告Meta结果在温暖受众上通常在频率10+上保持，而他在2.0-2.5周围看到的下降。在阅读任何曝光数字之前，始终将冷受众与温暖受众分开。

## 衡量这是否有效

这项技能自己的KPI是决策质量，在每一轮裁决的滚动日志上跟踪：

- **刷新胜率**：疲劳触发的替换中击败退役创意衰退前基线（同一受众，完整比较窗口）在重新检查日期的比例。
- **误报率**：退役创意在回顾中仍然健康的比例——替换没有做得更好，或者“衰退”在保留中自行逆转。

作为一个起点（这项技能的实际目标，而不是研究常数），迭代直到至少60%的刷新击败了退役创意，并且低于20%的退役是误报。从账户自己的历史记录中收紧两者，一旦记录了十几个决定。

- 一个低胜率与一个干净的门通常意味着诊断是正确的，但生产能力是约束。
- 一个高误报率意味着门或混杂屏幕被跳过了。

如果刷新在多个概念上同时停止恢复性能，停止刷新：这种模式是报价、着陆页或产品问题，新创意无法解决。

## 常见失败模式

| 陷阱                                                     | 为什么它会燃烧                                                                                                | 修复                                                                                                                                                       |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 从一个指标、一个坏日子叫疲劳                               | 噪声和周末模仿衰退；退役健康的创意                                                   | 两个信号，两个以上的时期，与创意的自己的基线相比                                                                                             |
| 将学习阶段重置读作衰退                                    | 任何重大编辑都会在几天内重新开始波动交付                                                    | 首先检查最后编辑日期；在编辑后的完整窗口后判断                                                                                   |
| 将频率数字视为因果关系                                    | 频率是滞后的、广告组级别的、平均的——一个创意在3.0可以是耗尽的，另一个在5.0是健康的 | 频率确认；链接CTR、钩子率和首次印象比率领先                                                                             |
| 活动平均值隐藏每个创意的衰退                              | 一个疲劳的广告拉低了平均值；其余的广告无事可做地被刷新                                       | 每个创意、每个概念的报告；自动轮换下的资产细分                                                                                 |
| 将创意归咎于第四季度/拍卖CPM通货膨胀                      | CPM上升而CTR平坦是拍卖，不是广告                                                             | 只有当与下降的CTR配对时，CPM才是诊断                                                                                                       |
| 将CVR崩溃与健康的CTR读作疲劳                             | 这种模式是着陆页、报价或跟踪 - 没有创意会修复它                                              | CTR健康 + CVR下降 → 在创意检查之前检查漏斗                                                                                               |
| 归因滞后引起的“衰退”的拖尾窗口                           | 近期总是低估转化；每个拖尾窗口看起来像衰退                                                   | 比较相同转化滞后成熟度的窗口                                                                                                          |
| 用新创意修复饱和                                          | 相反的补救措施：疲劳想要创意，饱和想要受众                                        | 在行动之前运行疲劳与饱和的分割（步骤7）                                                                                                |
| 编辑正在运行的广告来“刷新”它                              | 编辑重置学习并破坏了测量期间的基线                                                           | 与新广告一起启动；暂停，永远不要编辑，一个测量的创意                                                                                          |
| 将Google Ad Strength视为疲劳信号                          | 它评分多样性和完整性，而不是性能                                                           | 使用资产性能标签；忽略Ad Strength用于此呼叫                                                                                              |
| 提升一个具有高负面反馈的创意的钩子交换                    | 算法惩罚骑在资产ID上，而不是钩子                                                            | 将迭代作为新的资产ID交付                                                                                                                      |
| 建议刷新量超出生产能力                                   | 一个不可执行的计划默认为让一切衰退                                                   | 删除Interview的努力上限以上的每个行动梯子级别，在裁决的`排除`行上命名每个，然后采取最高排名的幸存者 |
| 退役一个没有准备的生产者                                  | 广告组变暗或重新进入学习状态                                                             | 准备好替代品，启动它，然后退役                                                                                                               |
