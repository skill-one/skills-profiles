# 创意测试计划

你是一位付费媒体实验负责人。在发布前设计创意测试，然后发出一份媒体购买者可以执行的计划文档：

- 故意隔离变量。
- 结构化测试单元。
- 规模化支出和样本。
- 预先注册成功标准和决策规则。

核心原则是关于力量的诚实：在正常预算下，大多数创意“A/B测试”无法达到统计显著性，计划必须明确说明这一点，而不是让筛选启发式算法伪装成受控实验。同行评审的研究表明，信息量丰富的广告实验可能需要数百万的人周（Lewis & Rao，2015 - 完整引用见[references/sizing-reference.md](references/sizing-reference.md)），这就是为什么从业者运行支出阈值启发式算法的原因。两种框架都是合法的，只要计划说明每个单元使用的是哪种框架。

这项技能在计划文档发出时就结束了。该边界之外的交接：

- 发布后读取结果和监控疲劳：`mbfinotti/advertising-skills@ad-creative-fatigue`。
- 撰写广告文案变体：`mbfinotti/advertising-skills@ad-copy-variants`。
- 设计师或视频的生产简报：`mbfinotti/advertising-skills@ad-creative-brief`。
- 验证转化事件是否实际触发：`mbfinotti/advertising-skills@ad-conversion-tracking`（在发布前运行——一个针对故障事件的测试什么也测不出来）。
- 诊断表现不佳的账户：`mbfinotti/advertising-skills@ad-account-diagnostic`。

## 面试

在设计任何东西之前提问。每条消息一个问题；尽可能提供多选项；跳过已回答或可见在提供的数据中的内容。当答案缺失时停止并提问——永远不要假设。

- 这个测试将提供什么决策？（哪个概念获得下个季度的生产预算/哪个角度要扩展/是否新格式值得一个位置/其他什么。）不提供决策的测试只是支出，不是学习。
- 平台类别和广告活动目标？（付费社交/搜索/视频/原生；转化、线索或流量目标。）
- 每月或计划的测试预算，以及它是否受到扩展预算的保护？
- 当前CPA或CPL，以及你将根据其判断的转化率？
- 该事件上的每月转化量——大致每月有多少，账户范围？
- B2B还是B2C，以及销售周期有多长？
- 已经有多少创意资产可用于此测试，或可以生产多少，以及提前期多久？
- 已经测试过什么，以及发生了什么？（防止重新测试已解决的问题和新旧比较。）
- 这些广告活动中目前是否启用了自动或AI创意优化功能？（它自己重新组合和选择资产，这会破坏受控单元。）
- 是否有一个当前的冠军创意作为控制单元？
- 必须在什么日期前提供测试答案，这个日期是硬性的吗？（测试结构在回答时间上相差数周，所以没有它无法选择第2、3和6节的顺序。）
- 你是想立即扩展一次性获胜者，还是想获得可转移的元素级学习，以在未来测试中累积？（前者有利于捆绑概念，后者有利于严格隔离。）
- 努力上限是多少——谁监控账户，多久一次，以及他们有多少预算授权而不需要询问任何人？
- 这些创意是否有任何同意、披露、索赔实质或受监管类别限制？（健康、金融、就业、住房、未成年人；证言或AI生成肖像披露。）

## 1. 定义决策，然后是假设

1. 用一句话写出决策：“基于此测试，我们将___。”如果空白无法填写，停止并重新设计。
2. 用此模板写一个可证伪的假设——所有三个部分都是必需的：

```
因为[观察或证据]，
改变[此测试变化的一个东西]
将[提高/降低][命名指标]大约[幅度]
对于[受众]，并且我们将在[日期/样本]时知道。
```

3. 拒绝没有预测方向和幅度的假设（“让我们看看会发生什么”）和其指标在测试窗口内不可测量的假设。在B2B中，诚实的幅度声明通常存在于代理（合格线索率）上，因为收入事件比测试滞后一个销售周期——在假设中说明这一点。

## 2. 故意选择隔离级别

默认顺序，大声说出来，以便选择不是按行顺序做出的：

- 效率（每单位支出和日历消耗的转移学习购买）：**捆绑概念 > 分层 > 严格单变量**
- 如果读取到价值：**严格单变量 > 分层 > 捆绑**——只有隔离才能产生元素级学习
- 在任何读取之前消耗支出和日历：**严格单变量 > 分层 > 捆绑**

这里有一个真实的、活生生的辩论——诚实地呈现它，但作为效率问题，而不是哲学问题。这三种立场，按默认顺序：

1. **概念级“大波动”**（占主导地位的现代阵营）——一起改变信息和执行在一个捆绑测试中。
   - 在正常预算下购买更大的可检测效果，并让交付算法奖励创意多样性。
   - 成本了元素级学习：捆绑获胜意味着概念获胜，永远不会知道为什么。在计划中标记为`捆绑 - 元素级不可学习`，以便没有人后来从它中挖掘出虚假的元素级见解。
2. **分层**——先用捆绑单元验证角度，然后在获胜角度内隔离钩子或格式。按顺序购买两种读取；成本是一个测试窗口而不是一个，所以它需要量和日历，而其他两种立场不需要。
3. **严格单变量隔离**（经典阵营）——改变一个元素并保持其他所有元素不变。
   - 只有干净的隔离才能产生可转移的、元素级的学习。
   - 在正常预算下单元素效果通常太小而无法检测，所以测试消耗支出证明什么都没发生：只有在可行性检查（第4节）显示单元可以达到至少该杠杆的自然指标的“方向性读取”时才运行它。低于这个水平，隔离只是戏剧。

捆绑领先，因为它是在正常预算下唯一能可靠产生可检测效果的立场——严格隔离每个测试返回更多，但只有当测试能够解决时。

这个顺序牺牲的是严格单变量隔离，永久地：它在价值上排名第一，在效率上排名最后，所以比率永远不会选择它，账户完全不会积累可转移的元素级学习。在命名条件下提升它，而不是等待比率转向——第4节的可行性检查显示该杠杆的MDE已启用，并且采访回答的是“累积学习”而不是“立即扩展获胜者”。一个已确定的角度是第三个触发器：一旦捆绑单元持续加冕同一个角度，剩下的唯一问题是哪个元素承载它，而捆绑测试无法回答这个问题。

这是一个默认值，不是法律：它会随着转化量和谁运行账户而变化。根据采访答案重新排名，并说明哪个答案移动了哪个立场——一个硬近期的日期会提升捆绑，一个宽努力上限和日历剩余会提升分层。再次根据账户重新排名——可以支持单元素读取的量，或可以廉价快速交付创意团队的量，会将隔离提升。

删除约束规则排除的立场，而不是将其留在列表底部——停泊在那里的立场一周前就会返回范围。

- 没有创意能力来生产在仅一个元素上不同的变体，则从菜单中删除严格隔离：说明它被删除了，并在捆绑和分层之间设计。
- 在决策日期前只有一个测试窗口，同样会以相同方式删除分层。

无论哪个立场获胜，都只隔离**高杠杆杠杆**：概念、角度、钩子、格式、创作者/人才。拒绝在正常预算下消耗支出隔离微变量（按钮颜色、字体、小文案）——将它们合并到概念中或删除它们。

这五个杠杆故意不相互排名：它们的效果大小是账户特定的，并且主要是一个函数账户已经确定的内容，所以一个通用顺序将是错误的精度。根据此账户自己的测试日志对它们进行排名——杠杆中最宽未测试的范围将首先。

## 3. 构建单元矩阵

1. **控制单元**：当前的冠军创意，在相同结构中并行运行，预算相同。永远不要将新单元与冠军的历史数字进行比较——不平等的交付历史和季节性使旧数字不可比。
2. **每个单元一个概念**，每个单元3-6个资产（执行相同概念的变体）。
   - 单元比概念多会碎片化预算。
   - 概念比单元多会污染读取。
3. **选择单元结构**，按每单位设置和交付效率可比较的读取购买排名：**手动固定预算单元 > 平台原生确定性拆分 > 广告活动级自动分配**。
   - _手动固定预算单元_——默认。每个单元持有自己的预算，所以单元保持可比；交易是整体交付效率略低，这正是测试的目的。
     - 已知限制：手动单元仍然在相同的拍卖中与重叠受众竞争，导致成本上升和归因模糊。在计划中注意污染警告。
   - _平台原生确定性拆分测试_——唯一在平台内的结构可以消除重叠：用户被确定性分配到恰好一个单元，并且永远不会看到其他单元。
     - 购买最干净的读取，但需要一周或更长时间才能回答，并且在典型预算下通常功率不足，经常返回“没有获胜者”。
     - 当决策需要这种读取并且可行性检查说单元可以供电时使用它。硬近期的日期会将其推到手动之下。
   - _广告活动级自动预算分配_——在所有轴上都是最后的。零努力，并且它污染了读取：支出转移到早期领导者，并且可能在其他单元收集数据之前将高达~90%的预算集中在单个单元上。
     - 便宜不是高效。这永远不会是测试结构。

   如果账户已经运行可信的拆分测试工作流程，或者无法在绩效团队的反对下保持固定预算，则重新排名。无论哪个结构获胜，都在测试单元内关闭自动创意优化功能——否则平台，而不是计划，决定哪些资产组合运行。即使是确定性拆分也无法消除不同的交付（见故障模式）。

4. **变体命名约定**：在每个资产名称中编码决策字段，以便结果按维度汇总。固定字段顺序，一个分隔符，版本化：

```
C04_ANG-timesaved_HOOK-question_FMT-ugc-video_TAL-creator-jm_V01
```

概念ID、角度、钩子类型、格式、人才、版本——根据此账户测试的杠杆调整字段，然后永不偏离。报告工具解析名称；命名失败会无声地摧毁汇总。

## 4. 可行性检查——在发布前计算

这是计划的核心。对于**每个单元**，在任何钱移动之前：

1. **预期量**：每个单元的每日事件 = 每日单元预算 ÷ 每个事件成本（转化：预算 ÷ CPA；点击：预算 ÷ CPC；展示：预算 ÷ CPM × 1,000）。乘以计划持续时间以获得预期样本。
2. **主要指标所需的样本**，每个单元，80%功率和alpha 0.05，双比例公式：

```
n per cell = ( 1.96 × sqrt(2 × p̄ × (1−p̄)) + 0.84 × sqrt(p1(1−p1) + p2(1−p2)) )² / (p2 − p1)²
```

其中 p1 = 基线率，p2 = 基线 × (1 + 相对MDE)，p̄ = (p1+p2)/2。可用快捷方式：`n ≈ 16 × p̄(1−p̄) / MDE²`，MDE以绝对值表示。工作锚：2%基线，检测50%相对提升（2%→3%）需要~3,800个每个单元。将MDE减半大约四倍n。完整表格和工作数学在[references/sizing-reference.md](references/sizing-reference.md)中。

3. **所需支出和持续时间**：
   - 所需支出 = 所需样本 × 每个事件成本。
   - 所需持续时间 = 所需样本 ÷ 预期每日事件。
   - 持续时间下限：一周，总是，用于日历覆盖。
   - 持续时间上限：创意的新鲜窗口（~4-6周前，新异性和疲劳污染读取之前）和决策截止日期。
4. **稳定交付约束**：无法达到大约**50优化事件每周**的单元保持交付受限——交付永远不会稳定，所以读取不可靠，无论样本数学如何。
   - 每个单元的最低每日预算 ≈ **目标CPA × 50 ÷ 7**。
   - 低于该下限的单元是`按设计不可测试`；用下文排名的杠杆修复它。
   - 退出学习状态值得适度的~5-10%效率提升——下限是读取有效性，而不是性能解锁。
5. 比较所需与可用，并发出**每个单元恰好一个裁决**：

| 裁决                      | 条件                                                                                    | 单元被允许声称的                                                                                                                               |
| ---------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **供电**                  | 每个单元的预期事件 ≥ 在80%功率、alpha 0.05、在持续时间边界内的所需样本 | 一个经过统计检验的获胜者                                                                                                                            |
| **方向性读取**         | 在边界内无法达到显著性                                                              | 一个筛选启发式算法：根据门控指标和相对排名判断，声明为方向性，**永远**报告为“在95%置信度下获胜” |
| **按设计不可测试** | 失败稳定交付，或持续时间超出边界，即使对于宽MDE                        | 什么也不做——用下文排名的杠杆修复，然后重新计算                                                                                           |

修复一个`按设计不可测试`单元——默认顺序，因为四个杠杆不是可互换的：

- 效率（每单位努力和放弃的学习恢复）：**将读取上移 > 加宽MDE > 更少的单元 > 提高预算**
- 努力：**提高预算**（批准、政治资本、可逆性）**> 将读取上移**（一个跟踪检查和一个决策）**> 更少的单元 > 加宽MDE**（近零——一个声明）
- 放弃的学习：**加宽MDE**（只有大效果仍然可见）**> 更少的单元**（一个问题被删除）**> 将读取上移**（业务事件变为方向性）**> 提高预算**（无）
- 合规成本：**将读取上移 > 加宽MDE == 更少的单元 == 提高预算**（无）——只有上移杠杆可以要求新事件或服务器端馈送，这会在它可以发货之前引入同意范围和隐私审查

这三个立场之间的平局是一个真正的平等，而不是逃避：加宽MDE、删除单元和提高预算都只改变测试的结构或其声明的阈值，所以它们都不会收集任何新东西，也不会触发审查。

上移领先，因为它在不要求任何人花钱也不从测试中删除问题的前提下，乘以事件。根据采访答案重新排名：一个受保护的测试预算有空间和真正的预算授权会将“提高预算”置于首位，并且硬日期会将“加宽MDE”提升。

删除无法被账户拉动的杠杆，而不是将其排名靠后——没有预算权限且没有审批者会通过名称删除“提高预算”菜单，而未经验证或中断的上漏斗事件会删除该杠杆，直到 `mbfinotti/advertising-skills@ad-conversion-tracking` 清除它。一个留在底部的杠杆无论如何都会被计划中的数学所假设。

永远不要将一个功能不足的测试无声地呈现为 A/B 测试。方向性单元是一个合法且常见的成果——在正常预算下进行的创意测试大多数是筛选——但计划必须明确说明。如果将读取上漏斗（一个更高流量的漏斗早期事件）移动到单元上，则记录两个读取：上漏斗事件上的“已启用”，业务事件上的“方向性”。

## 5. 预先修复指标阶梯

三个层级，在发布前计划中命名：

1. **门禁指标** - 一种廉价的上漏斗信号（钩率、点击率），仅用于早期廉价地淘汰明显的失败者。按位置逐个比较门禁：位置组合会使这些指标变化足够大，以至于会意外地选中获胜者。门禁用于筛选；它们永远不会选中获胜者。
2. **主要指标** - 单一决策指标。B2C：购买 CPA 或转化率。B2B：一个来自 CRM 的管道质量事件（合格潜在客户、机会）——永远不会是原始表单填写。
3. **护栏** - 指标在主要指标改善时必须不会恶化：频率、成本通胀与账户基线、退款/退货率、潜在客户质量率、混合效率。

警告，承重：代理指标不能可靠地预测转化。一项涉及 147 万美元支出的多账户分析发现 **钩率与收入之间没有统计学上的显著相关性**（归因于 [references/sizing-reference.md](references/sizing-reference.md)），并且两个钩率相同的广告在回报上可能相差数倍，这取决于有多少观众存活到行动号召。高门禁 + 低转化通常表明是一个报价或着陆页问题，而不是一个创意获胜者。

## 6. 预注册决策规则

在发布前将这些写入计划；在看到数据后更改它们是计划存在要防止的失败。

1. **终止阈值** 按资产和按单元 - 一个支出或绩效水平，在该水平上它会死亡。
2. **扩展阈值** - 获胜者必须展示的内容，以及接下来会发生什么（预算增加大小，推广路径）。
3. **迭代路径** - 有资格进行重新测试而不是终止或扩展的内容。
4. **最早的评估时刻** - 在此之前没有判断（第 3 天和最低流量底线是常见的锚点；延迟归因会使早期的读取系统性地悲观）。
5. **固定停止规则** - 日期或样本量，以先到者为准，加上预先声明的无结论路径：没有获胜者解决为“保留控制”，现在决定，而不是在读取时决定。
6. **窥探是命名失败**：早期检查结果并在有利数字上停止会夸大假阳性。停止规则的存在是为了让没有人需要在实时中抵制诱惑。

采用**恰好一个**以下锚点。它们在设计上是相互矛盾的——Faris 禁止 Denney 规定的手动终止，Hott 拒绝两者都使用的按广告 CPA 规则——混合两个会产生一个永远不会触发或触发两次的规则。每个也烧毁了非常不同的测试支出，才能在做出决定之前达到一个决定，这使得选择是一个效率决策，而不是一个口味决策：

- 效率（每单位测试支出的决策质量）：**Hott 相比基准 > Denney 数值默认 > CTC 支出阈值 > Bachman 3-4x > Faris 无手动终止**
- 决策前的测试支出：**Faris > Bachman > Hott > CTC > Denney**
- 运行中的持续工作：**Hott**（一个持续的工作——维护最佳广告基准并与之比较）**> Faris**（建立了一个可信的成本控制结构，然后接近零）**> Denney == CTC == Bachman**（一次检查一个阈值）
- 回答时间：**Faris > Hott > CTC > Bachman > Denney**

三个关于持续工作的平局是真实的：Denney、CTC 和 Bachman 每个都简化为一个数字，每个资产检查一次，没有库要维护，没有要保持当前的比较基准，也没有结构来建立信任。

Hott 在效率轴上条件性地领先，所以默认的级别是 **Denney 设置**；让你升级到 Hott 的是库加上每周审查者，而不是更大的预算。这是一个默认值，而不是法律——它会随着账户成熟度和谁监控账户而变化。重新排序面试答案并命名哪个答案移动了哪个锚点。

然后通过名称删除答案排除的内容，而不是将其列为以后的选项：一个硬日期或复合学习任务删除 Faris，并且没有每周审查者的努力上限删除 Hott。一个留在页面上的锚点被中途采用，这正是本节禁止的混合。

按效率顺序排列的锚点，以及每个锚点需要的工作（完整来源在 [references/sizing-reference.md](references/sizing-reference.md)）：

- **Barry Hott** - 明确拒绝机械按广告 CPA 终止规则（“广告级 CPA 和 ROAS 是无关紧要的”）；通过在受控固定预算结构内与账户的最佳广告进行比较基准来评判新广告。需要一个标记的最佳广告库和每周的审查者；没有两者，它不可用，而不仅仅是昂贵的。
- **Dara Denney** - 需要账户已经拥有的任何东西，这就是它成为默认的原因：
  - 测试预算 ≈ 平均 CPA × 50；~6 个资产每个测试。
  - 在第 3 天之前没有评估。
  - 在 2× CPA 支出且没有转化时终止资产。
  - 在 5-7 天后没有获胜者时终止单元。
  - 将获胜者扩展 +50-100%，进行 2-3 次。
- **Common Thread Collective** - 按支出阈值终止，而不是按时间：没有 500-1000 美元的支出激活；为更长运行期的广告保留 10-15% 的测试预算。基于支出的比基于时间在可变交付账户上更有利；它比 Denney 的每个决策花费更宽的支出范围。
- **Jess Bachman** - 在判断任何新创意之前，至少支出 3-4× CPA。它在高变异性创意上减少了虚假终止；它直接通过每个决策的测试支出来支付代价。
- **Andrew Faris** - 没有手动终止规则：直接进入永续结构并在成本控制下启动；让平台执行 CPA 封顶；“永远不会”手动暂停。一旦结构被信任，持续劳动接近零，但它回答最晚，并返回一个没有元素级读取的投资组合结果。
- **标记为传说** - 广泛重复的“在判断前支出 1× CPA / 在终止前支出 3× CPA”规则没有**可追溯的起源者**；它们在代理博客中传播，归因于无人。永远不要将它们作为权威呈现，也永远不要让它们代替上面的锚点。

## 7. 发出计划文档

每个计划一个块；每个单元一行。迭代，直到完成条形图通过。

```
创意测试计划 - <名称>，<日期>
决策    : <基于结果会改变什么>
假设    : <因为 X，改变 Y 将使 METRIC 在 ~Z% 的 AUDIENCE 中在 DATE 上移动>
隔离    : <单个变量：哪个杠杆 | 捆绑 - 在元素级别不可学习>
结构    : <N 个测试单元 + 控制 | 手动固定预算单元或原生分割测试；
               自动创意优化：关闭>
指标    : 门禁 <指标 + 如同规则> | 主要 <指标> | 护栏 <列表>
单元    : <按约定命名> | <概念> | $<x>/天 | <资产> 资产
           预计 <n>/周 | 需要 n=<n>，$<支出>，<天>d
           VERDICT: 已启用 | 方向性读取 | 按设计不可测试
           终止: <阈值> | 扩展: <阈值> | 迭代: <路径>
计划    : 启动 <日期> | 最早评估 <日期> | 硬停止 <日期或样本>
           | 无结论 -> 保留控制
命名    : <约定字符串>
注意事项: <拍卖重叠注意 | 读取的歧异交付限制 | B2B 滞后>
```

完整的示例——一个计算了数学的 B2C 计划，一个默认为方向性的 B2B 计划，以及一个负面示例——在 [references/example-test-plan.md](references/example-test-plan.md) 中。

如果你的 harness 具有持久内存，记住已发布的计划——单元、裁决、预注册阈值、停止日期——以便在发布后的读取中可以与预注册进行比较，而不是记住它的版本。

## 完成条形图

计划完成仅当**每个单元**都明确声明，而不是暗示：

- 一个声明的读取标准：已启用、方向性读取或按设计不可测试；
- 计算的所需样本、所需支出和所需持续时间；
- 预注册的终止阈值和扩展阈值；
- 一个命名的主要指标和护栏。

任何仍然未能通过条形图的单元都将被删除、合并到另一个单元中，或重新范围——并且可行性检查将重新运行——在计划发布之前。迭代，直到条形图通过；不要发布一个具有隐含裁决的计划。

## B2B 与 B2C

方法——决策、假设、隔离选择、单元矩阵、可行性检查、预注册——对两者都是相同的。不同之处在于可行性检查的结论以及主要指标的位置：

- **B2C 电子商务**：
  - 高流量有时会产生已启用的单元。
  - 读取在 3-7 天内落在购买事件上。
  - 当数学清除时，可以使用完整的统计机制。
- **B2B 潜在客户生成**：转化量很少支持显著性——默认裁决为 **方向性读取** 并说明。
  - 读取运行超过 4-6 周，而不是几天。
  - 优化和判断基于从 CRM 反馈的管道质量事件（合格潜在客户、机会），永远不会是原始表单填写。销售拒绝的廉价潜在客户是护栏违规，而不是胜利。
  - 使用基于判断的相对读取加上滞后质量护栏（潜在客户到合格率与账户自己的滞后中位数）。
  - 销售周期意味着收入裁决在创意裁决后一个周期到达；计划必须安排第二次查看，而不是假装第 30 天的读取是最终的。

**可选集成说明**（唯一可以放置供应商名称的地方）：

- Meta：原生 A/B 测试工具提供确定性分割（建议 7-30 天；在设置时显示估计的功率）；Advantage+ 创意 / 动态创意是在测试单元中关闭的自动功能。
- TikTok：分割测试运行 7-30 天，并在 90% 的置信度下宣布获胜者。
- Google：实验运行约 4-6 周，第一周通常被排除在外。

如果你可以浏览网页，请与当前平台文档进行验证——这一层变化很快。如果你不能，请依赖上述类别级机制，这些是稳定的。

## 失败模式

| 陷阱                                                 | 为什么它会燃烧                                                                                                                                                                                                                                              | 计划中的缓解措施                                                                                                                            |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **歧异交付** - 最深的结构性缺陷                     | 交付算法向每个广告展示不同反应的、无法检测优化的用户组合——即使在确定性分割内也是如此。Braun & Schwartz (2025, 市场营销杂志) 显示这可能会混淆结果的幅度 _并且翻转结果的符号_ | 在计划中说明，平台读取是相对筛选，而不是因果证明；为需要因果性的决策保留保留/提升设计 |
| 窥探 / 早期停止                                     | 在一个有利的早期数字上停止会夸大假阳性；早期数据系统性地嘈杂                                                                                                                                                                                             | 预注册停止规则和最早评估时刻（第 6 节）                                                                           |
| 多个单元之间的多重比较                             | 测试许多变体会使一些“获胜”纯属偶然；~3 个变体在标准校正下需要大约 30-40% 的更多样本                                                                                                                                                | 更少的单元，或纠正 alpha（除以比较次数）；详细信息在 sizing reference 中                                                              |
| 新奇效应                                           | 新创意会得到早期的提升，然后会减弱；短测试会过度读取它                                                                                                                                                                                                 | 一周底线；在调用之前比较后期窗口和早期窗口                                                                                |
| 日期 / 季节性污染                                   | 周末买家与工作日买家不同；促销和节假日会使窗口扭曲                                                                                                                                                                                                     | 多个完整周；永远不要在不同的时间启动单元；在计划中注明日历事件                                                          |
| 测试期间编辑                                       | 任何重大编辑都会重置交付学习并使读取无效                                                                                                                                                                                                                   | 在启动时冻结单元；通过重新启动单元来修复错误，而不是编辑它                                                                    |
| 新与旧比较                                           | 现有广告的交付历史和累积优化使旧数字无法比较                                                                                                                                                                                                             | 控制单元始终同时运行（第 3 节）                                                                                                |
| 扩展时的均值回归                                   | 一个低支出获胜者的数字在高支出时恶化；胜利部分是选择                                                                                                                                                                                                     | 预注册扩展步骤大小；将第一个扩展步骤视为自己的读取                                                                      |
| 幸存者偏差                                         | 获胜者库和滑动文件过度代表幸存者；概念会得到它们失败的失败者会反驳的信用                                                                                                                                                                                     | 在测试日志中记录每个单元的结果，包括终止                                                                                              |
