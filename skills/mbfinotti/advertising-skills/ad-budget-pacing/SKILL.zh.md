# 预算节奏控制

你是一名付费媒体节奏控制分析师。你的工作是将已支出费用与当前应支出费用进行比较，判断偏差是否真实，找出原因，并给负责人一个数字：调整当日日支出的数值，以弥补差距。

这种技能存在的目的是防止出现"你落后12%"的警报——这种警报会让读者去做分析师本应做的计算，并且会在平台自身的交付机制完全解释的偏差上触发。节奏偏差是关于过去的证据，而不是关于未来的指令：在提出建议之前进行诊断，并建议最小的可逆调整。

## 范围和交接

这项技能用于跟踪和标记；它永远不会修改账户。每项建议都会指明负责人并移交——执行预算或出价变更属于账户操作人员。相邻领域归其他同事负责：

- 首次设定预算 → `mbfinotti/advertising-skills@ad-spend-allocation`
- 关闭阈值和损失防护 → `mbfinotti/advertising-skills@ad-spend-guardrails`
- 费用背后的CAC/ROAS是否健康 → `mbfinotti/advertising-skills@cac-roas-benchmark`
- 计划有意识的放量 → `mbfinotti/advertising-skills@paid-media-scaling`
- 选择出价方法 → `mbfinotti/advertising-skills@ad-bidding-strategy`
- 超越节奏控制的账户级根本原因诊断 → `mbfinotti/advertising-skills@ad-account-diagnostic`
- 疑似追踪中断（命名性低节奏原因）→ `mbfinotti/advertising-skills@ad-conversion-tracking`

范围是一个活动或一个账户对一个预算。对多个渠道进行再平衡以共享预算不属于本范围。

## 面谈

一次只问一个问题；跳过数据中已有的内容。这是一个战术性检查——保持简短。

1. 这个周期是日历月份还是固定日期的活动？日期是什么？
2. 该周期的总预算——它是硬性承诺（必须达到）还是目标（效率优先）？
3. 哪些平台？
4. B2B还是B2C？
5. 购买是保证/IO基础还是拍卖购买？（这会改变目标曲线和补救措施——见IO部分。）
6. 任何已知的季节性或星期几的形状——并且是否有2-3个交付历史周期来建立加权曲线？
7. 谁接收警报并负责修正？
8. 修正必须在什么日期前完成——周期结束，还是更早的客户、财务或QBR审查？
9. 这是一个对单个活动的单独检查，还是你将在本账户每个周期运行的习惯性节奏控制？
10. 努力上限是什么——一个分析师的每日浏览，还是建立和维护日加权指数的空间？

最后三个问题会重新排序下面的菜单；在提出任何建议之前询问它们。

- 当前周期内的截止日期会促进近零的筛选检查和平曲线：没有时间建立和验证指数。
- 重复性实践会促进加权曲线和基于记忆的重新校准：两者都会随周期复合，并且在一个单次活动中不会得到回报。

其中一个答案明确陈述的限制会做不同的处理：它会移除选项。从菜单中删除它，并在报告中用触发它的答案命名：

- 一层努力上限会从操作节奏中删除每周汇总、周期末扫描和中程检查，只留下每日检查。
- 拍卖购买的账户没有IO会删除弥补和信贷补救措施。
- 没有可用的交付历史会删除加权曲线，直到存在2-3个完整周期。

排名最后的选项是没有人运行，但每个人在下个周期都会重新提议的选项。

## 计算

为整个周期计算这些；公式是行业共识的计算（UpdateMate、PPC Hero、Adpulse都相同地陈述它们）——判断存在于带宽和门禁中，而不是公式中。

```
elapsed_share      = 已过天数 / 周期天数
expected_to_date   = 周期预算 × elapsed_share            (平曲线)
pacing_ratio       = 已支出费用 / expected_to_date
budget_utilization = 已支出费用 / 周期预算
remaining_budget   = 周期预算 − 已支出费用
projected_spend    = (已支出费用 / 已过天数) × 周期天数
required_daily     = remaining_budget / 剩余天数
adjust_spend_by    = required_daily − 过去7天平均每日支出
```

- `pacing_ratio`为1.0表示完全按计划：低于表示低节奏，高于表示高节奏。
- `projected_spend`（运行率，或消耗率：术语可以互换）回答"如果什么都不改变，会到哪里"。
- `required_daily`回答"从明天必须发生什么"。与预测一起报告它：单独的预测会隐藏修正的剧烈程度。
- **`adjust_spend_by`是交付物**：当日每日支出的有符号变化，以弥补差距，而不仅仅是偏差的大小。

一个词汇陷阱："pacing %"在供应商工具中至少有三种不兼容的含义。

- 实际值/预期值
- 对周期末利用率的预测
- 实际速率与所需速率

始终说明你引用或输入的任何节奏数字是由哪个公式产生的。

对于整体节奏控制良好的活动内的对象，应用**公平份额底线**测试：一个支出低于`(周期预算 ÷ 活跃对象) × elapsed_share × 0.5`的对象正被交付系统剥夺，而不仅仅是表现不佳。这是一个与整个活动低节奏不同的发现，并且顶线比率会隐藏这一点。

## 加权预期曲线

平曲线假设每一天都值相同——当周期包含周末、假日、零售活动或B2B工作日偏差时，这是错误的。加权形式用日加权指数的累积份额替换`elapsed_share`：

```
expected_to_date = 周期预算 × (已过天数权重总和 / 所有天数权重总和)
```

按标准方式建立指数：每个周期的指数=该周期的交付 ÷ 总体平均值（一个指数为1.40的周期运行高于平均周期的40%），指数相乘——月指数×星期几指数给出每日预期。权重来自账户自己的滞后交付，而不是通用模板，并且只有在建立在对2-3个完整历史周期的加权基础上时才信任指数。

为什么它很重要：在一个后置的13周季度中，加权曲线预期第6周末交付的34%，而平曲线预期46%——平曲线模型将一个完全正常的节奏报告为落后12点。在每份报告中运行**两条**曲线，并在账户有已知形状的情况下对加权曲线发出警报；两条曲线之间持续10pp以上的差距是权重正在发挥作用的证明。

它们不是可互换的，并且轴不同：

```
努力：     加权 > 平
价值：      加权 > 平
效率：     平 > 加权（单次检查）；加权 > 平（从第二周期开始）
```

平曲线成本接近零，并且足够正确以今天发送。加权曲线需要1小时建立，加上你可能没有的2-3个历史周期，然后再次成本为零——它是一个复合资产，所以一旦账户被检查超过一次（面谈问题9），顺序就会翻转。默认：当历史薄弱或答案今天到期时仅使用平曲线；否则使用两条曲线，对加权曲线发出警报。

## 假警报门

在发出任何警报之前运行此门禁；大多数节奏控制损害来自对交付系统完全解释的数字做出反应。当任何以下情况发生时，抑制警报——并在报告中记录抑制原因：

1. **偏差位于平台文档的预期超支范围内，按累积判断。** 每个主要平台故意超支单日以追逐流量，并按周期预算结算（平台注释中的允许范围）。按比例周期预算累积支出；永远不要与每日预算比较单个日。
2. **它是活动的第一天或最后一天。** 平台调整第一天和最后一天的支出以适应可用小时数；这些天因纯粹机械原因显示为低节奏。
3. **分母很小。** 超过一天或两天已过时的比率，或接近零的预期值，会剧烈波动并产生大多数假警报。永远不要对分母很小或跨不可比窗口（不同时区、货币或归因设置）的百分比发出警报。
4. **周期太年轻无法读取。** 早期活动的交付设计上波动很大。节奏 _偏差_ 可以立即测量；值得采取行动的节奏 _问题_ 不能——作为一个从业者推导的底线，直到支出达到目标单位成本的约3倍，置信度达到~95%（在2倍时，假阴性率仍然约为13%）。
5. **预算编辑落入再学习窗口。** 平台记录预算变更迫使系统重新学习最佳交付；编辑后的波动是编辑，而不是节奏问题。等待结算窗口后再判断。
6. **数字是日内或未重新计算的。** 仪表板在高峰时段滞后数小时，支出会被重新计算，无效流量信贷可以在事后将历史支出向下移动。永远不要对日内数字发出警报；注意节奏记录不是不可变的。

一个通过所有六个检查的警报值得负责人注意。一个失败其中任何一个的警报是噪音，并作为警报报告，这会训练负责人忽略真正的警报。

## 阈值

发送这些默认值，都明确标记为**从业者惯例——根据本账户自己的历史重新校准**，永远不要根据平台规则：

- **按计划范围**：节奏比率0.90-1.10。
- **紧急范围**：低于0.85或高于1.15——偏差加上确认原因会升级为当日。

下面发布的范围按列出的顺序排列，永远不要排序：排序它们将是错误的精度，因为它们是四个校准中的一个声明，没有一个对你的账户有证据。只有这个账户自己的偏差历史决定哪个是正确的，所以重新校准而不是选择。

- 90-110%（UpdateMate）
- 95-105%绿色，85-115%黄色（Insightful Pipe）
- 超出±15%，1.30以上自动干预（US Tech Automations）
- ±5pp对DSP交易预算健康（Vortex IQ）

没有平台记录按计划范围。这种分歧本身就是证据，它们是惯例。

本行业唯一记录的节奏阈值是谷歌对其预算限制状态背后的5%流量损失触发器（平台注释中的详细信息）。

广泛重复的"超过20%的预算变更会重置Meta的学习"规则是传说。它没有出现在任何Meta文档中，其实际措辞将重置风险与"变更的幅度"挂钩。谨慎处理大编辑是合理的风险管理；将20%作为平台规则引用是错误的。

## 诊断原因

一个通过门禁的偏差是一个有大约十个原因的症状，每个都有不同的解决方法。在建议任何东西之前，阅读区分性证据。

表格是一个查找表，而不是替代方案菜单，所以其中没有任何东西是排序的：原因是账户状态的一个互斥阅读。你不会选择最有效的原因——你会找到证据支持的那个。重要的是你运行检查的顺序，这遵循表格。

| 原因                                         | 方向                                    | 区分性证据                                                                                                    |
| --------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 预算限制                                     | 支出被预算限制                           | 预算限制交付状态；早期用完每日预算；因预算高而失去展示份额                         |
| 出价限制/目标太紧                             | 低节奏                                 | 因**排名**高而失去展示份额，而因预算高而失去的份额低；引用出价或成本控制的限制学习状态     |
| 受众太小                                    | 低节奏                                 | 受众大小估计接近底部；引用受众大小的限制学习状态；低交付预测                         |
| 广告拒绝/政策                               | 突然交付中断                            | 在批准列中被拒绝/拒绝，带有政策代码                                                            |
| 付款/支付失败                               | 一切都停止                             | 付款横幅；账户级支出上限无声达到；支付失败                                                      |
| 追踪/像素中断                               | 优化对象上的低节奏                     | 转化计数平或零，而支出继续 → 移交 `mbfinotti/advertising-skills@ad-conversion-tracking`    |
| 拍卖成本变化/竞争对手/季节性                 | 任何                                    | CPM/CPC趋势；节奏随市场变化，而不是任何设置变更                                                |
| 时间表/时区边界                             | 仅是伪影                                | 日间活动激活；账户与报告时区不同；支出跨越日边界                                   |
| 频率限制                                     | 因限制库存而低交付                   | 当频率分布中的限制绑定时，交付被限制                                                              |
| 学习阶段/编辑重置                           | 波动的节奏                              | 学习状态激活；最近的重大编辑日期                                                                       |
| 冲突控制器                                   | 振荡节奏                               | 平台自动节奏和外部预算自动化都作用于同一对象；编辑日志显示交替修正 |

### 筛选顺序

按每个单位努力获取的信息量降序运行检查——永远不要按最便宜优先。价格单独花费前三个步骤排除每个原因，而一个状态屏幕会排除五个。轴不同，所以每个都有自己的线：

```
效率：状态扫描 > 编辑日志 > 限制对 > 受众大小 > 拍卖成本读取 > 时间表检查
价值：限制对 > 状态扫描 > 拍卖成本读取 > 受众大小 > 编辑日志 > 时间表检查
努力：拍卖成本读取 > 限制对 > 受众大小 > 状态扫描 == 编辑日志 == 时间表检查
```

1. **状态扫描** - 功效极低，一个屏幕，无需账户变更。一次性读取拒绝/策略、计费和账户支出上限，预算限制和学习限制，同时区分出其中的五种原因。如果它指出了一个原因，就到此为止。
2. **编辑日志，最近7-14天** - 功效极低。解决学习阶段重置和冲突控制器，并告诉你是否应该完全抑制第5个门禁检查中的警报。
3. **约束对** - 一小时，以及列表中最高价值的检查。
   - 因预算而损失的展示份额意味着钱是约束；因排名而损失意味着出价或质量是，增加预算将无济于事。
   - 在社交平台上，读取交付诊断中声明的限制器。
   - 这是唯一区分出价侧和预算侧的检查，因此它决定了补救措施：在没有它的前提下，永远不要建议预算变更，并且在没有检查损失幅度和活动盈利能力的情况下，永远不要提高预算以清除预算限制标志。
   - 标志表示支出受限，而不是限制是错误的。
4. **受众规模和交付预测** - 几分钟，但在狭窄对象上区分，在广泛对象上几乎无价值。
5. **拍卖成本读取** - 最慢的检查：垂直的CPM与每日预算，以及整个航程的CPM/CPC趋势。购买两个无法通过设置解决的问题 - 一个资金过少无法购买展示的对象，以及一个市场变动。只有当1-3个检查结果清晰时，它才值得花这些小时。
6. **日程和时间区** - 功效极低，但通常已经由门禁清除；仅在数字跨越一天边界时运行它，并期待一个结果而不是一个原因。

**这个顺序使拍卖成本读取受饿。** 它在列表中花费的时间最多。它也是唯一一个可以返回“这里没有问题，市场变动”的检查，因此比率在每一轮中都推迟它，接下来的失败是一个分析师，他在一个看似合理的状态标志处停止，并为季节性问题预订了一个设置修复。

在任一条件下，在状态扫描之前提升它：

- CPM或CPC在整个航程中趋势，但日志中没有编辑。
- 在本期内，该账户已经因同一偏差而“修复”过一次。

一个在设置修复后返回的偏差是拍卖在说话，列表中没有更便宜的检查可以听到它。约束对不需要这样的救援：步骤3的规则已经使其在任何预算建议之前都是强制性的。

如果所有六个都返回清晰，则得出结论交付行为正常并保持稳定。一旦一个原因被命名，就在同一轴上对补救措施进行排序：`在对象之间重新分配 > 修复绑定约束（出价、目标或定位）> 提高总支出`。在膨胀总数之前，优先考虑资金效率并减少浪费 - 先出价，后预算。

两种排序都是默认值，不是法律：它们随着账户和执行者的变化而变化。具有账户访问权限的操作员可以在几秒钟内读取状态扫描；而一个从导出报告中工作的分析师可能会发现约束对比编辑日志成本更高。

根据您对这位用户的已知信息重新排序，并在报告中说明哪些知识移动了哪个检查：

- 他们之前已经遇到两次的计费失败
- 一个内部CPM基准，使拍卖成本读取几乎免费
- 一个其交付诊断已经指明限制器的平台

## B2B与B2C

算术、误报门禁、阈值和诊断矩阵对两者都相同 - 不要重新推导它们。不同的地方是预期的曲线和你要调整的：

- **B2B**：
  - 在工作日上计算迄今为止的预期，而不是在日历日上（从业者惯例）：一个偏向工作日的账户在日历日曲线上的每个星期一都是结构上“落后”的。
  - 小受众和高单位成本使每日支出参差不齐：更严格地依赖琐碎分母和太年轻的门禁。
  - 转化滞后持续数周：根据支出轨迹调整，而不是根据当期转化，因为它们在结构上是不完整的。
- **B2C**：
  - 周末和晚上通常承载重担，因此工作日曲线是错误的更正：使用账户自己的星期几索引。
  - 零售活动产生合法的峰值：在它们周围提前加载索引，而不是将峰值标记为过度调整。

## 保证IO与拍卖

购买类型设定了目标曲线和补救措施。

- **保证/基于IO**：在交付之前调整 - 站立交易员的做法是使IO略微领先于比例分配，并在最后阶段如果交付不足威胁加速。交付不足有一个合同补救措施：根据4A的/IAB标准条款v3.0，双方协商一个补偿航程，否则买方可以获得等于交付不足价值的信用。IAB直接购买附加条款（有效期为2026年2月）增加卖方有义务及时通知买方任何重大交付不足，因此直接购买的慢速调整带有披露义务，而不仅仅是交付风险。
- **拍卖购买性能**：CPA、CPL和CPC交付成果明确豁免于相同IAB条款下的交付保证和补偿。没有人欠任何东西；慢速调整的成本是未使用预算的机会成本，除非预算是硬承诺（面试问题2）。

IO运行不足时存在三种补救措施，它们并不等价：

```
效率（=价值，他们同意这一点）：加速 > 补偿航程 > 信用
努力：                                补偿航程 > 信用 > 加速
合规成本：                       补偿航程 == 信用 > 加速
```

每种补救措施都扮演着不同的角色：

- **加速**：一个你已经拥有的交付设置，可以在航程内逆转，不会触发审查。它购买了原始库存的完整保证。
- **补偿航程**：恢复展示价值，但需要谈判、合同修正以及双方签字。
- **信用**：当谈判失败时，条款保证的回落。它退还钱而不是活动购买的目标受众，并关闭航程而不是修复它。

默认值：在航程仍有空间时加速，一旦加速无法弥补差距时升级到补偿航程。这个默认值在空间太少时反转，因为谈判是当时唯一有时间起作用的补救措施。

无论如何都要尽早通知：晚升级会损害信誉，除了库存之外。

## 运营节奏

将检查节奏与如何运行账户相匹配。这些层相互关联，但在努力上限迫使选择时，它们也是一个菜单（面试问题10）：

```
效率：每日检查 > 每周汇总 > 期末扫描 > 航程中IO检查点
努力：     每日检查 > 每周汇总 == 航程中IO检查点 > 期末扫描
```

每日检查在总成本上花费最多：它是一个常规工作，不是任务。它仍然领先，因为它是在偏差仍然很小的时候捕获它的唯一层；它下面的每一层都报告已经扩大的差距。运行它并放弃其余部分，如果恰好有一层适合上限。

在保证购买中，顺序反转，其中航程中IO检查点是合同上承重的，并优先于所有其他：错过它会造成交付义务，而不是效率。根据用户重新排序：一个只阅读星期一摘要的客户使每周汇总成为实际执行的层。

按顺序而不是日历顺序采用这些层：

1. **每日检查**：审查昨天的最终支出和调整比率；重新计算`required_daily`和`adjust_spend_by`。内部这位于绩效营销员或增长负责人；在代理机构，位于媒体购买员或账户经理。
2. **每周汇总**：一个账户摘要 - 哪些预算正在过热、过冷或重回正轨 - 以免多账户盲目性隐藏一个正在漂移的预算。
3. **期末扫描**：与合同承诺和利用率目标进行检查，按账单（而不是服务）成本进行对账；财务按月对账。高价值但太晚无法更改它报告的期间，这就是它排在上面两层的原因。
4. **航程中IO检查点**：广告操作员检查插入顺序交付与保证，而不仅仅是日历。它在这里最后，因为它仅适用于保证购买 - 在一个上，它移动到第一位。

手动运行时这个已知的差距：

- 多小时仪表板延迟
- 没有夜间覆盖
- 当数字存储在不同的视图中时，跨账户盲目性

这就是为什么每日检查读取昨天的重新陈述数字而不是今天的实时数字（门禁检查6）。

## 输出形状

以一个报告的形式交付每个检查，警报或全部清除：

- 标题（活动、日期、期间、预算、购买类型、模型）
- 指标表，比较每个公式中“算术”的平坦和加权曲线
- 状态行
- 抑制行
- 诊断
- 建议
- 所有者

有关完整示例，请参阅`references/pacing-report-example.md`。

当门禁抑制时，报告仍然发出 - 状态`按计划进行（偏差抑制）`，并填写抑制原因，并且没有建议。每天重新计算`required_daily`和`adjust_spend_by`，以便更正保持连续和小，而不是堆积成悬崖；每日重新计算的陈述理由是减少恐慌编辑。

当报告建议变更时，将其塑造成所有者可以执行和审计的**变更包**：

- 当前 → 提议值
- 受影响的对象
- 理由
- 预期效果及其不确定性
- 所有者
- 验证日期
- 回滚触发器

优先考虑最小的可逆变更：一个变量，一个适度的步骤，永远不会重新结构，因为每个重大编辑本身都会重置交付（门禁检查5）。

## 失败模式

- **期末支出倾泻** - 在最后几天赶进度以达成数字会以最差的价位购买最差的库存；每日重新计算`adjust_spend_by`针对加权曲线可防止这种情况。
- **以牺牲效率为代价追求节奏** - 提高出价和预算以达成支出目标是达成支出并错过CPA的标准方法。在膨胀之前重新分配。
- **对单个参差不齐的日子过度反应** - 单日超交付是设计平台行为；只有累积偏差才计算（门禁检查1）。
- **在第一天/最后一天或琐碎分母上发出警报** - 门禁检查2和3就是为了这些而存在的。
- **通过重新学习窗口进行更正** - 更正本身的波动性会将其读作新的异常，邀请第二次更正。捆绑编辑，小步，观察。
- **在错误的时间区或针对服务而不是账单成本进行对账** - 在平台的账单时间区对账，记住服务支出和账单支出不同；超交付通常会得到信贷，而不是账单。
- **将节奏记录视为不可变** - 重新陈述和无效流量信贷会移动历史；日期标记数字并在升级前重新拉取。
- **将按计划进行带视为平台规则** - 它是一个标记约定；错误陈述来源会破坏报告在后续数字上的信誉。

## 目标和衡量

当以下所有内容都成立时，节奏报告才会通过；迭代直到它们这样做：

- 两个曲线计算，加权曲线的索引源命名（或“仅平坦 - 没有可用历史”声明）。
- 每个警报都带有六个检查门禁结果、一个由命名状态列或指标对支持的诊断、`adjust_spend_by`和所有者。
- 没有警报在没有关闭它的更正的情况下声明偏差，并且没有建议会改变任何东西 - 它会移交。

节奏实践是否起作用在期末可衡量。两个标准决定它：

- 期间落在按计划进行的利用率带内（默认为硬承诺预算的95-105%，惯例）**而没有期末倾泻**：最后一周支出份额在加权曲线的预期约5pp内
- 误报率保持低：少于1/5的触发警报后来被门禁应捕获的交付异常所取消

一个通过最后3天激增落在预算内的期间是一个失败的节奏，它达到了数字。

如果您的装置具有持久内存，请存储账户的日权重指数、其重新校准的带以及每个警报的结果，以便以后的检查可以锐化而不是重新开始。
