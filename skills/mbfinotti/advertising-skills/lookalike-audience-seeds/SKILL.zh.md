# 相似种子

选择、调整和验证种子客户列表，用于构建相似、类似或基于价值的受众。以下每个步骤都受三个原则的指导：

- **匹配数量，而非行数** - 每个上传的列表在到达平台之前都会根据匹配率缩小。在5,000行中40%的匹配率意味着2,000人的种子，平台底线适用于匹配数量 - 上传2-3倍的靶标。
- **同质性和价值集中优于规模** - Meta自身的指导表明，种子的同质性比规模对受众效果影响更大。从业者共识（Stackmatix、Grow With Sakib - 方向性，未经审计）认为，几百个高价值客户胜过成千个无差别的订阅者。
- **包含是建议，排除是规则** - 在Meta（Advantage+）和Google（Demand Gen，其中相似受众层级现在作为信号而非硬性分段运行）上，交付算法可能会覆盖包含受众。只有排除/抑制受众仍然是硬性规则。

种子的作用是向算法提供最干净的信号，而不是围住受众 - 这会提高质量标准，而不是降低它。

这项技能在指定且经过验证的种子定义及其导出/交接规范结束。它从不涉及在广告平台的界面中创建或上传受众。

每个相邻问题的位置：

- 整体定位计划（兴趣、行为、相似和再营销层级分层）- 种子机制位于此处，层级架构位于 `mbfinotti/advertising-skills@ad-audience-targeting`。
- 再营销序列设计、每个漏斗阶段的受众窗口和频率上限 - `mbfinotti/advertising-skills@retargeting-funnel`。
- B2B购买委员会和角色映射 - `mbfinotti/advertising-skills@ad-buyer-group-mapper`。
- 根本原因分析广泛账户表现不佳 - `mbfinotti/advertising-skills@ad-account-diagnostic`。
- 像素/CAPI仪器为基于参与的种子来源提供支持 - `mbfinotti/advertising-skills@ad-conversion-tracking`。
- 调整归因来源上种子冲突的性能读数 - `mbfinotti/advertising-skills@ad-attribution-gap`。

## 面试

在选择任何东西之前提问。每条消息一个问题；在可能的情况下提供多个选择答案；跳过已经回答或可见在提供的数据中的任何内容。

- B2B、B2C/电子商务或两者兼有？
- 哪些平台将消耗种子？（Meta / Google / LinkedIn / TikTok / 其他 - 底线和匹配机制不同）
- 有哪些客户数据存在，以及它们存储在哪里？（CRM / 数据仓库 / 电子邮件平台 / 仅像素和平台事件 / 几乎没有）
- 大约有多少总客户，每行存在哪些标识符？（电子邮件 / 电话 / 名称 / 邮政地址 / 移动广告ID - 每行更多标识符类型会提高匹配率）
- 是否有可用的价值列 - 它实际衡量的是什么：累积终身收入、利润、预测的LTV，还是仅仅是订单数量？来源比存在更重要。
- 数据有多新 - 列表中多少比例在最近90天和180天内购买或转化？
- 列表是否包含EEA/UK居民或美国州隐私覆盖消费者？是否有上传到广告平台的文档同意或合法依据，并且在导出之前是否执行了退订、删除和不联系记录？
- 列表将如何到达平台 - 手动CSV或自动仓库/CDP同步？谁拥有刷新？
- 相似受众旨在推动什么样的获取结果 - 目标新客户CPA/CAC，以及获取客户的任何LTV或利润预期？
- 账户目前在相同两个数字上的平均值 - 获取客户CPA，以及90天获取客户队列LTV？通过阈值将种子与该基线进行比较，因此未知基线意味着无法对种子进行评级：如实说明并将第一个队列检查点设置为建立基线的运行。
- 必须在什么日期之前使受众上线并开始支出，这个日期是硬性的吗？（种子来源跨越几分钟到一周的协调，并且富集运行通过采购运行 - 步骤3和6中的订购不能在没有这个的情况下选择。）
- 你想要尽快启动的受众，还是一个复合资产 - 自动化仓库同步、丰富标识符、可重复使用的队列定义 - 该资产可以在每个未来的受众中持续支付？
- 努力上限：有多少小时的数据团队时间可用，谁拥有后续刷新，以及您是否实际上可以获得隐私批准和供应商DPA？（“不”会删除步骤，而不是延迟它们。）

## 工作流程

这项技能中的每个排名 - 这里提到的步骤3、6和9，以及参考中的那些 - 都是一个默认值，而不是法律。每个步骤都假设常见情况：没有富集供应商合同、没有内部身份图谱、本周没有分析师空闲。执行者改变顺序与它是什么一样多。

首先根据面试的截止日期、持久性和努力上限答案重新排名，并命名哪个答案移动了哪个步骤：

- 硬性近期日期会提升平台原生参与种子。
- 复合资产指令会提升仓库同步和富集步骤，尽管它们的设置。
- 没有隐私批准路线会直接删除每个基于列表的步骤。

然后根据用户实际拥有的内容重新排名 - 任何这些都会将步骤的努力降至接近零并使其上移：

- 已签署的富集DPA。
- 仓库中已构建的身份解析。
- 可以今天编写队列SQL的分析师。
- 拥有导出作业的数据团队。

1. 运行面试；在选择任何行之前收集所有答案。
2. 运行隐私和同意关卡 - 一个硬性停止，在任何选择工作之前。如果下面有任何项目未经确认，请停止并确切说明缺失的内容。这项技能不是法律建议：合法依据因司法管辖区而异，因此将开放性问题路由到用户的顾问。
   - 上传此列表到广告平台的文档合法依据或同意。根据巴伐利亚数据保护局慕尼黑高等行政法院（2018年，参考号5 CS 18.1157）的立场，GDPR下客户列表自定义受众需要事先同意，哈希值不会改变这一点：SHA-256输出是伪匿名的，而不是匿名的，因此同意义务仍然存在。
   - 对于Google客户匹配的EEA使用，同意信号通过版本2的同意模式传递，两个同意状态字段GRANTED（自2024年3月起强制执行）。
   - CCPA/CPRA“共享”退订和全球隐私控制信号（在十二个美国州得到尊重）在导出前传播。
   - 没有基于敏感类别的种子：健康、性取向、宗教、种族、政治隶属关系、犯罪记录。
   - 平台客户列表条款被接受用于特定的广告账户（基于价值的受众需要在Meta上接受单独的条款）。
   - 一旦在仓库中执行一次，就执行抑制、退订和删除 - 不是在每个平台之后。
3. 选择种子来源：首先购买数据。如果购买数据太薄，则从八个来源中选择替代方案 - 但永远不会单独根据价值排名，因为努力和合规成本都会反向指向它。两个轴不一致，因此请阅读所有四个：
   - 价值：`购买者 > 添加到购物车/启动结账发起者 > 高意向页面浏览者 > 表单提交者 > 电子邮件点击者 > 视频观看者 > 页面参与者 > 所有访客`
   - 努力程度：`视频观看者 == 页面参与者 == 所有访客 > 高意向页面浏览者 == 表单提交者 > 结账发起者 > 电子邮件点击者 > 购买者` - 平台原生参与受众在广告账户内几分钟内通过像素已经触发的规则构建，并跳过客户列表上传及其步骤2的同意关卡。购买者或CRM种子需要一个仓库导出、身份解析连接和完整关卡。两个平局都是真实的平等：前三个是一个针对已经触发的事件的单一规则，接下来的两个是针对命名URL集或命名表单的同一单一规则 - 分钟内，由同一个人完成。
   - 合规成本：`购买者 == 结账发起者 == 电子邮件点击者 > 表单提交者 > 高意向页面浏览者 == 视频观看者 == 页面参与者 == 所有访客` - 任何作为客户列表到达平台的任何内容都会运行完整的步骤2关卡（合法依据、EEA中的同意模式v2、退订传播、基于价值受众的单独条款接受），而平台原生参与受众永远不会离开广告账户并触发任何内容。两个平局是精确的而非近似的：三个基于列表的来源逐项运行相同的关卡项目，而四个原生来源运行其中任何一项 - 这个关卡没有部分版本来区分它们。这个轴可以单独决定选择：如果上传同意未经确认，则每个基于列表的步骤都不可用，而不仅仅是昂贵。
   - 效率：`购买者 > 高意向页面浏览者 > 表单提交者 > 结账发起者 > 电子邮件点击者 > 视频观看者（75%+）> 页面参与者 > 所有访客`。购买者领先 **当客户导出已经存在时**，这是常见情况 - 一个大型价值差距对于单个查询。如果没有，高意向页面浏览者和表单提交者是板上最佳比例：零设置，无上传，无新曝光，仍然处于价值前半部分。这两个是排序而非平局 - 他们的设置是相同的单一规则，因此价值轴将其打破 - 除了B2B线索生成，其中表单提交就是转化，提交者会提前。永远不要让努力将选择拉到它们以下：从这一点开始，每行质量下降的速度比努力下降的速度更快。每源分解和移动此顺序的条件：[references/seed-selection.md](references/seed-selection.md)。

   这个效率顺序忽视的是客户身份资产本身：购买者或CRM种子，以及使其可用的身份富集（后备步骤1）。它在价值轴上排名第一，并且在努力和合规成本上排名最后，因此在导出不存在的情况下，它会在每一轮中输给一个像素规则，该规则几分钟内就会到达 - 账户在下一次询问时仍然没有导出。

   当：
   - 面试回答“复合资产”而不是“尽快启动”时，提升它。
   - 种子是B2B，并且原生匹配率在没有富集的情况下无法达到任何底线。
   - 这个账户现在已经输掉了两次。

   删除它 - 通过名称，从菜单中删除 - 没有隐私批准路线或没有供应商DPA可用。基于列表的来源如果没有合法依据，就不是缓慢选项，它不是选项，并且排名在底部的任何一个都会在下一次受众已经上线后重新出现。

   使用电子邮件点击者，而不是打开者 - Apple Mail隐私保护（2021）将打开量膨胀为噪音。在B2B中，从已关闭的CRM机会中种子，而不是所有MQL导出。仅SQL击败所有MQL。

4. 选择行。[references/seed-selection.md](references/seed-selection.md) 有完整的队列定义、窗口指导和排除列表。
   - 默认选择：RFM冠军+忠诚队列，或按预测LTV或利润排名前10-25% - 永远不要按累积终身收入排名，它跟踪的是任期，而不是价值。
   - 新鲜度窗口：30-90天作为起点，最多180天用于像素/CAPI跟踪的购买者。12-18个月以上的联系数据会实质性地降低匹配率和性能。
   - 负面选择通过（大多数团队会忘记这个）：删除退款者、拒付、连续退货者、仅折扣购买者、员工和批发账户。将现有客户保留在种子中，但在交付级别从获取活动中抑制它们。
5. 计算有效种子：`有效种子 = 上传行数 x 预期匹配率`。从平台在 [references/platform-floors.md](references/platform-floors.md) 中记录的范围中提取预期匹配率，并根据列表的标识符密度和年龄进行调整 - 例如：
   - Google客户匹配：大多数广告商为29-62%（根据Google自己的文档）。
   - Meta：良好列表上的50-80%。
   - LinkedIn：工作电子邮件联系列表上的~30-40%。
   - Reddit：~2%原生CSV。

   将结果与平台的匹配数量底线进行比较，并将上传量调整为靶标的2-3倍。如果您的 harness 可以读取客户导出，请直接计算数量。否则，发出确切的过滤器定义（源表、过滤器条件、新鲜度界限、价值阈值），供用户的数据团队运行，并在继续之前等待数量。

6. 如果有效种子无法达到底线，请走后备梯子 - 永远不要首先放宽选择质量。梯子编号是规范块和工作示例中使用的稳定ID；每个步骤都携带其自己的价值、努力和合规成本：

   - **步骤1，丰富标识符** - 身份解析附加个人电子邮件/电话。价值：唯一一个在不改变模型学习内容的情况下增加匹配人数的步骤，并且在一个消费者平台上的B2B工作电子邮件列表中，它是唯一一个从~5%原生匹配率达到任何底线的步骤。努力：梯子编号隐藏的异常 - 供应商选择、安全审查、预算批准，然后是一个匹配测试，所以在单个行移动之前需要一周或更多的协调。合规：链中的新处理器 - DPA、顾问批准，以及对富集和不仅仅是上传的合法依据重新检查；一旦合同签订，这是最难逆转的步骤。
   - **步骤2，将新鲜度窗口放宽一级**（90到180，180到365）。价值：中等，以信号新鲜度为代价。努力：接近零 - 一个查询编辑，几分钟，完全可逆。合规：无新项。
   - **步骤3，堆叠同一同质性的相邻段** - 添加忠诚到冠军，或者如果行为真正相似，则添加第二个产品线的购买者。价值：中等，并且同质性是面临风险的东西。努力：大约一个小时，加上实际工作的判断。合规：无新项。
   - **步骤4，切换到步骤3排名中下一个非购买种子来源。** 价值：最低 - 唯一一个改变模型学习内容的步骤。努力：如果事件源已经仪器化，大约一个小时。合规：**更低**，而不是更高 - 平台原生来源不需要上传和同意关卡。

     默认效率：`步骤1 > 步骤2 > 步骤3 > 步骤4`。在第一个清除的步骤停止，并在规范中记录它。

     一个记录的翻转：`步骤2 > 步骤1`，当没有富集供应商合同 **并且** 有新鲜度可以放宽时 - 一个下午可能会在采购开始之前解决问题，并且如果它没有，步骤1仍然可用。翻转不适用于标准的B2B情况，其中便宜的步骤在结构上是空的：一个所有时间已关闭的列表没有新鲜度，没有相邻段不是丢失交易，并且原生匹配率太低，无法让步骤2-4达到任何底线。

     步骤1也是删除而不是降级的步骤。没有采购路线、没有DPA或没有供应商预算所有者将其完全从梯子中删除 - 说它被删除并运行步骤2-4。一个无人执行的步骤，坐在效率顺序的顶部，是规范最终假设它的方式。

在完全不保留任何阶梯的标准B2B案例中：将此作为发现报告，而不是用松散的种子填充它。  
7. 如果种子是基于价值的：  
   - 提供利润率或预测的LTV。  
   - 仅限正值。  
   - 值不能全部相同。  
   - 每个列表一个货币单位。  
   - 限制或winsorize鲸鱼异常值，以防止少数大账户扭曲模型。  
   - 确认上传时价值列已映射。未映射的价值列会导致平台静默地构建标准而非基于价值的类似受众——如果基于价值的选项在受众构建时未出现，则表示该列未映射。  
8. 指定标识符准备：  
   - 每行多个标识符优于单独的电子邮件。  
   - 电话号码采用E.164风格的数字，包含国家代码，无加号，无前导零。  
   - 电子邮件小写并修剪。  
   - 永远不要预先散列用于UI上传的文件——平台在摄取时进行散列，加盐或双重散列将永远不会匹配。  

在Meta上，目标事件匹配质量分数为6.0以上，作为从业者基准。  

9. 决定分割、刷新和重叠。  

   **分割。** 按以下顺序分割——`国家 > 产品线 > 高AOV与所有`——当命名的刷新所有者耗尽容量时停止。每个分割的工 effort相同（一个WHERE子句），但每个都会永久增加一个：需要刷新的受众、监控重叠，并永远保持在地板线以上。  

   国家不是选择：Meta类似受众按设计按国家范围划分，因此多国覆盖需要一个种子和类似受众对每个国家。在提交之前，检查每个分割自身的有效种子与地板线。  

   **刷新。** 使用命名的所有者设置刷新频率。静态CSV上传不会自动刷新（领英列表、手动Meta客户列表），因此需要每周至每月的刷新计划或迁移到自动仓库同步。  

   在这两者之间，`自动同步 > 手动CSV`在效率和合规成本上更优，尽管在工 effort上有所损失。一周的工程工作可以消除整个衰减故障模式，并持续传播选择退出和删除。CSV初始接近零，但会变成一个永久性工作，每个周期重新上传昨天的选择退出。  

   仅建议CSV作为桥梁，有命名的所有者和同步到达的日期。Google客户匹配会删除540天内未刷新的成员。  

   **重叠。** 检查此种子受众与现有受众之间的重叠。从业者关注阈值约为20-30%。超过此阈值则合并或排除。  

10. 填写种子规范块（下方形状；在[references/examples.md](references/examples.md)中测试了B2C和B2B版本）并将种子的层级放置给`mbfinotti/advertising-skills@ad-audience-targeting`。  
11. 附上测量计划和一个队列窗口外的重新检查日期。如果您的设备具有持久内存，请记住种子版本、其定义、计数和重新检查日期，以便下一次运行时与历史记录进行比较，而不是重新推导。

定义        : <源记录>通过<选择规则>在<时效窗口>内过滤

## 证据门  

拒绝基于以下任何内容构建的种子规范；相反，说明缺失的内容：  

- **未知的匹配率基础** - 未咨询任何平台范围，且没有先前的上传进行校准。仅根据文档中记录的范围加上列表年龄/标识符密度进行估算，并标记为估算。  
- **未确认的同意基础** - 隐私门（工作流步骤2）未通过。没有选择质量可以证明用户具有合法基础进行上传。  
- **来源不明的价值列** - "我们有LTV字段"不是证据。如果没有人能说它是收入、利润还是模型输出，则种子在有人能说明之前不是基于价值的。  

永远不要凭空编造客户列表、分段定义或用户数据不支持的阈值——请求缺失的证据，而不是用通用列表替代。  

## 种子诊断阶梯  

当现有类似受众表现不佳且怀疑种子时，使用此表格作为症状查找，而不是排序菜单：每个症状都有一个原因和一个操作，因此将它们相互排序将是错误的精度。  

需要排序的是当多个症状同时发生时，应先修复什么。在修复受众服务或匹配问题之前，修复任何关于其质量的问题——地板失败、映射损坏或匹配率低于平台范围——会使其下游的所有质量读取变得无意义。然后修复重叠和刷新，然后是价值/扩展原因。  

| 症状                          | 可能的原因                                                                                   | 操作                                                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 匹配率远低于平台记录的范围     | 陈旧的列表、每行单个标识符或未规范化的格式                                   | 规范化（E.164，小写电子邮件），添加标识符列，删除18个月以上的行，然后丰富                             |
| 列已上传但受众无法构建或服务  | 匹配计数低于地板 - 行数被误读为种子大小                                       | 重新计算有效种子；运行后备阶梯                                                       |
| 受众构建时缺少基于价值的选项  | 上传时未映射价值列                                                              | 重新上传并确认映射；平台静默地构建了标准类似受众                                             |
| CPA良好，90天队列LTV收购客户弱 | 种子扩展了低利润率的转换器（文档中记录的Churney陷阱）                               | 基于利润率或预测LTV重新种子；退役种子版本                                             |
| 类似受众表现接近随机/不如广泛   | 扩展百分比太宽，或异构种子混合了与购买者不同的买家                               | 收紧百分比；按产品线、分段或国家分割种子                                               |
| 计划引用Google类似受众或领英类似受众 | 陈旧的剧本 - 类似受众于2023年8月删除；领英类似受众于2024年2月停止                     | 重建基于客户匹配作为信号/领英预测受众（最低300匹配）                   |
| 两个种子的受众相互蚕食        | 受众重叠高于~20-30%的关注带                                                  | 合并种子或添加互斥排除                                                              |
| 性能随时间推移衰减且未进行更改  | 静态CSV未刷新；成员正在老化                                                    | 设置频率和所有者；自动同步；尊重540天客户匹配截止日期                     |

## B2B与B2C  

**两者相同：** 散列和规范化机制（SHA-256，E.164，小写电子邮件）、匹配率算术、有效种子计算、负选择、仓库优先抑制和测量窗口——它们运行在相同的广告系统上。不同之处在于列表大小和身份。  

**B2B** 必须忍受小列表问题：400个高ACV客户无法原生地提供消费者平台类似受众，因为工作电子邮件在Meta和TikTok上匹配不佳，而个人电子邮件在领英上匹配不佳。上传前身份丰富是记录的解决方案，也是后备阶梯1的原因。  

B2B种子是账户级或联系人级：通过职位/高级别/功能将公司列表扩展为联系人再上传。在领英上，公司列表需要1,000+家公司，而联系人列表需要大约10,000+电子邮件才能可靠地清除300匹配地板。从已关闭的胜利重新种子，而不是从MQLs。  

漫长的销售周期意味着B2B种子的转化读取滞后数周：早期判断匹配质量和参与度，仅在队列成熟时判断种子本身。  

**B2C** 得到相反的权衡：列表足够大，以至于选择纪律而不是地板清除是约束性条件。  

## 衡量是否有效  

匹配率只是一个数据质量领先指标——根据Google自己的措辞，高匹配率表明数据正确，但不保证列表性能。永远不要根据它对种子进行评分。  

根据新客户CPA/CAC、新品牌率、收购客户的AOV以及技能自身的KPI：**90/180/365天队列LTV按种子版本**。命名陷阱（Churney）：低CPA类似受众在成熟时LTV表现不佳，因为种子扩展了低利润率的转换器。解决方法是重新基于利润率或预测LTV重新种子，并退役版本。  

使用用户级分割测试或地理保留来比较种子变体，而不是简单的广告组比较——受众重叠会污染它。在这两种有效方法之间：  

- `分割测试 > 地理保留`在工 effort上——平台设置与为整个测试窗口保留市场的流量相比，后者需要拥有该市场号码的人员的批准。  
- `地理保留 > 分割测试`在证据强度上——它能够承受跨设备身份丢失，并测量增量销售，而不是平台分配的销售。  

默认情况下，在平台提供真正的用户级分割测试时使用分割测试。当种子决策难以逆转时——重新平台的价值列、退役种子版本、国家分割——或当分割测试自身的读取存在争议时，升级到地理保留。  

尊重学习阶段再读取任何内容：大约每周每个广告组50个优化事件（广泛归因于Meta的指导）或2-4周低量。  

通过阈值：种子版本的90天收购客户队列LTV达到或超过账户平均收购客户LTV，且CPA相等或更好。低于此阈值，迭代：基于价值重新种子，收紧时效性，或分割。重新检查一个队列窗口后——种子是一个版本化的工件，而不是一次性上传。  

## 常见故障模式  

故意未排序：这些是陷阱/修复对，而不是竞争一个目标的选项，并且这里的每个修复都足够便宜，以至于按效率排序暗示了一个不存在的分诊选择——做所有的事情。

| 陷阱                                                    | 为什么它会导致消耗                                                                                   | 解决方法                                                                                          |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 按行数进行规模调整                                       | 对于匹配的人群适用；一个匹配率为40%的5,000行列表相当于2,000个种子                                             | 计算有效种子；上传目标数量的2-3倍                                                                 |
| 用所有人填充种子以“达到最低要求”                           | 稀释信号簇；同质化胜过规模                                                                                   | 运行备用阶梯 - 质量永远不是首要被牺牲的东西                                                           |
| 将累积终身收入作为价值列输入                             | 它跟踪任期，高收入低利润的客户会污染模型                                                                 | 使用利润或预测的LTV                                                                               |
| 跳过负选择筛选                                           | 重新投保者、仅折扣购买者、员工、批发客户教模型错误的客户类型                                                 | 在导出前清除它们，每次                                                                                   |
| 为UI上传预哈希文件                                       | 平台在摄取时哈希；加盐哈希匹配不到任何内容                                                                 | 通过UI上传规范化明文；仅在需要API/仓库同步时哈希                                                           |
| 在同意确认之前上传                                       | 哈希列表在GDPR下仍然是个人数据；执行是真实的                                                                 | 首先进行隐私门；在仓库中强制执行一次抑制                                                               |
| 根据匹配率对种子进行评级                                 | 匹配率衡量数据卫生，而不是受众质量                                                                           | 根据种子版本的队列LTV进行评级                                                                       |
| 在学习阶段内评判种子                                       | 早期的CPA是噪音，直到优化量累积                                                                                   | 等待学习退出或2-4周；然后读取                                                                       |
| 为多国相似性使用一个全球种子                               | 相似性按国家范围划分；模型跨市场平均                                                                                   | 每个国家一个种子-相似性对                                                                           |
| 将上传视为永久完成                                       | 静态列表会衰减；成员会老去（Customer Match上的540天规则）                                                     | 与负责人更新刷新周期，或自动同步                                                                 |
| 在每个平台上混合工作和个人身份                               | 工作邮箱在消费者平台上几乎不匹配；个人邮箱在LinkedIn上几乎不匹配                                             | 将匹配标识符类型与平台匹配；在他们偏离时丰富                                                               |
| 复制2022年的操作手册                                     | 类似的Audiences和LinkedIn Lookalikes不再存在；包含项变成了建议                                               | 与实时文档验证功能；将种子视为信号，排除项是唯一的硬规则 |
