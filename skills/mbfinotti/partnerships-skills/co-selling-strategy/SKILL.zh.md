# 合作销售策略

定义直销团队和合作伙伴销售商如何就共享交易进行协作：政策层面，而非逐笔交易的执行。这项技能设计三个文件作为一套连贯的运营章程，并逐节通过用户进行验证：

- **交易注册政策** - 合作伙伴如何正式声明机会以及声明所赋予的权利。
- **信用和归因模型** - 当交易有多个父级时，谁会被计算和支付。
- **合作参与规则** - 直销团队和合作伙伴销售商之间的规则。

合作销售是一种B2B学科，没有真正的B2C类比。它预设了客户账户、承担配额的销售代表、顾问式销售周期和机会记录——这些在消费者交易中都不存在。

消费者端的对应物是贸易营销、合作广告基金和货架陈列/渠道协议：一个不同的学科，不同的机制，因此切勿将交易注册或薪酬中立强加于零售合作关系。唯一适用于任何环境（B2B或B2C）的部分是治理纪律本身：明确的所有权规则、记录在案的平分规则、公开的标准。

## 面谈

在提出任何建议之前进行询问。每条消息只问一个问题；在可能的情况下提供多个选项。跳过用户已经回答的内容。如果您的框架具有持久记忆，请先检查之前批准的章程，并确认发生了哪些变化，而不是重新面谈。

- 直销团队的结构如何——覆盖的细分市场（SMB / 中端市场 / 企业）、内部与外部、配额如何构建？
- 哪些类型的合作伙伴正在参与或计划参与：推荐、经销商/VAR、分销商、系统集成商/咨询公司、独立软件供应商/技术、市场/超大规模？
- ACV、平均销售周期长度和直销获胜率是多少？（周期长度设定了注册保护窗口。）
- AE最后一次关闭合作销售交易并称之为良好体验是什么时候——以及是什么使其良好？
- 当前的薪酬计划是否会对将合作伙伴与交易关联产生任何摩擦？
- AE如何得知今天应联系哪个合作伙伴以处理特定账户——以及需要多长时间？
- 如果AE决定完全忽略合作伙伴的建议，会发生什么？
- 目标是什么：合作伙伴来源的管道、受影响收入、市场交易量、达到直销无法覆盖的细分市场？
- 目前是否存在有效的归因记录——时间戳注册，或在关闭时提出的信用主张？

问这三个问题总是最后。本技能中后续的每个排序菜单都将根据答案重新排序，并且当读者到达一个菜单时，他们已经承诺了一条路径。

- 必须在什么日期之前显示此建议的结果，届时必须满足什么条件？一个季度内的日期会删除重型的JBP轨道，并促进一小时的注册和锁定窗口修复。两个季度之外的日期会保持薪酬计划工作。
- 一次性解锁，还是复合资产？一次性解锁会促进注册政策和合作参与规则，这些将在下一笔交易中支付。复合会促进薪酬中立和归因共同拥有，这些将在每个季度偿还，第一个季度几乎什么都不会。
- 努力上限是多少——可用小时数、销售领导是否会重新打开薪酬计划、以及变更的可逆性如何？拒绝重新打开薪酬会直接删除所有薪酬资金运行。要求可逆性会降低已发布的内容给合作伙伴，因为授予的折扣比内部规则更难撤回。

## 工作流程

1. 运行面谈。如果您可以浏览网页并且用户有一个已发布的合作伙伴或交易注册页面，请阅读它——在一张白纸上设计之前先审计现实。
2. 在设计任何东西之前，根据准备就绪情况进行限制。当任何不合格项成立时，请说明原因拒绝：
   - ICP尚无法清晰地表达。
   - 直销团队尚未证明其可以可靠地自行关闭。
   - 定位、定价或流程仍在变化。
   - ACV低于大约3-5k，这是任何销售辅助动作的从业者底线（通用SaaS共识，而非合作销售特定研究）。
   - 合作伙伴关系是作为增长问题的解决方案而建立的。

   合作伙伴放大了有效的直销动作。它们不会修复一个有问题的动作。当限制失败时，建议两到三个深度参与的推荐合作伙伴，没有正式计划，然后停止。

   参见[references/partner-types-and-process-tracks.md](references/partner-types-and-process-tracks.md)以获取此限制的更深入的诊断问题。

3. 选择流程轨道。以排序顺序呈现两者，并明确说明每个权衡，并明确推荐。轴线不一致：
   - 效率：`轻型剧本 > 重型JBP`
   - 价值：`重型JBP > 轻型剧本`
   - 努力程度：`重型JBP > 轻型剧本`

   **轻型剧本填充**：每个合作伙伴在90分钟内填写一个固定模板。购买每个单元格的命名所有者和一个共享的交易阶段地图，这是实际争议真正关注的两个东西，以及每个合作伙伴一个会话加上一次性模板。最佳比例，并且是每个合作伙伴的默认设置，直到有事情改变它。

   **重型联合业务规划**：双方高管启动，共享可衡量的目标，多周起草，正式签署，季度审查。购买双方高管的赞助和预算计划，这是唯一能影响其自有领域销售代表携带配额的合作伙伴的杠杆，需要几周的起草、双面签署链和季度审查的固定工作。最高价值，最差比例——只有在您需要直接影响其销售代表并且双方都将资助审查周期的合作伙伴时才升级到它。

   当合作伙伴方不会指定高管赞助人时，从菜单中删除JBP轨道，而不是建议反对它：一个未赞助的联合计划会产生无人执行的文件。运行轻型并在存在赞助人时重新审视。

   在此步骤之前阅读[references/partner-types-and-process-tracks.md](references/partner-types-and-process-tracks.md)——上述排序是默认设置，会随着合作伙伴类型、ACV和用户方实际运行会话的人员而变化。

   4. 将每个正在参与的合作伙伴类型映射到其经济实际需要的注册和信用机制（相同的参考）：
   - 推荐合作伙伴需要清晰的归因，而不是利润保护。
   - 经销商需要正式注册。
   - 系统集成商受服务管道的驱动。
   - 独立软件供应商/技术合作伙伴不需要任何转售机制。

   不要跨类型发送一个统一的政策。

   5. 按顺序一次设计五个政策决策。对于每个决策：
   - 提供2-3个候选方法，按每单位努力的价值排序，永远不会按最便宜排序。
   - 将每个选项的权衡纳入自己的行，并明确推荐。
   - 在继续之前获得用户的意见。
   - 大声说出排序，并在成本、价值、努力和效率不一致的地方发出单独的行。
   - 将努力表示为小时、会议、签署链和可逆性，永远不会表示为货币金额。
   - 删除用户对最后三个面谈问题的答案排除的任何选项，而不是降级它，并说明哪个答案删除了它。

   每个排序都是默认的：在呈现之前，根据您对这位用户的了解重新排序它。
   1. **归因分类法** - 合作伙伴来源与合作伙伴影响，以及是否要发布一个组合的“合作伙伴关联”数字。参见[references/attribution-and-compensation.md](references/attribution-and-compensation.md)。
   2. **交易注册政策** - 注册授予什么，保护窗口+扩展规则，批准标准和SLA，已发布的拒绝理由。参见[references/deal-registration-policy.md](references/deal-registration-policy.md)。
   3. **信用和薪酬** - 薪酬中立资金模型和多方分拆规则。相同的归因参考。
   4. **合作参与规则** - 账户类别（直销专有 / 合作伙伴专有 / 共同追求），合作销售触发条件，客户账户例外，升级阶梯。参见注册参考。
   5. **决策权** - 谁批准注册（永远不会是一个其配额受决策影响的角色），谁共同拥有归因（合作伙伴关系加收入运营是合理的默认值），谁裁决争议和SLA，以及谁拥有合作参与规则文件。从业者惯例将其与合作伙伴或生态系统领导层一起放置，与销售、CS、RevOps和法律共同设计，但它是一个咨询公司声明的模式，而不是一个衡量标准——将其作为起点并让用户确认它为自己的组织，而不是断言它已确定。

   6. 组装章程（下一节），并逐节向用户展示，并在继续之前验证每个部分。不要在未获得整个文档的明确批准之前最终确定。
   7. 将批准的草稿与以下通过清单进行评分。说明哪些检查未通过，并迭代直到每个检查都通过。
   8. 如果您的框架具有持久记忆，请记住批准章程的决策——后续运行（KPI审查、添加合作伙伴类型、重新审视窗口）将从它们开始，而不是重新面谈。
   9. 将此技能不做的部分——解决一个正在进行的争议交易、与一个合作伙伴一起规划发布、程序层级和经济——移交给参考资料中的兄弟技能。

## 合作销售运营章程

以该文件交付每次参与——用户可以将其交给销售领导、财务和合作伙伴运营：

```
合作销售运营章程 - <公司>, <日期>
范围            : 覆盖的合作伙伴类型、细分市场、账户类别（直销专有 / 合作伙伴专有 / 共同追求）
流程轨道    : 默认情况下通过轻型剧本填充，例外情况下通过重型JBP，每个合作伙伴类型
归因      : 采纳的分类法、使用的来源测试、交易创建后锁定窗口
注册     : 授予什么，保护窗口+扩展规则，批准标准，SLA，已发布的拒绝理由
信用 & 薪酬    : 中立模型+如何资助，配额退休规则，多方分拆规则
决策权  : 注册批准者，归因共同拥有者，争议裁决者+SLA，合作参与规则文件所有者
参与规则 : 合作销售触发条件，客户账户例外，升级阶梯
KPIs & 审查    : 追踪的指标，目标，审查周期
```

每一行都有一个原因：“90天窗口，因为平均周期是100天”是可审查的。一个裸数字不是。

**通过清单**——章程完成前，每个检查都必须通过。每次说明失败的检查和差距：

- 每个决策权行都命名一个特定角色，并在可能的情况下命名一个个人。共同拥有就是没有拥有。
- 注册批准者的配额不受批准决策的影响。
- 保护窗口至少是用户报告的平均销售周期长度的75%。
- 拒绝理由是已发布的、明确的、封闭的列表——每个理由都可以从注册记录中客观验证，没有临时的。从`mbfinotti/partnerships-skills@partner-channel-conflict`获取规范集，该集合拥有它。枚举而不是修剪，因为遗漏在列表中的理由是无人能辩护的拒绝。
- 薪酬模型带有财务和销售领导的签署，或者偏差被记录为有意的例外，并说明其风险。
- AE可以通过一次阅读来判断一个具体交易是否可注册、受保护且薪酬中立——与用户一起通过规则走一个真实交易场景来测试这一点。
- 直销代表在系统内看到注册。一个政策，其记录仅存在于销售团队从未打开的门户中，按定义失败。

## 既定实践与供应商词汇

诚实地评估您引用的内容——合作销售文献混合了真实标准与供应商营销：

- **既定、安全地按规范性呈现**：合作伙伴来源 / 合作伙伴影响 / 合作伙伴关联分类法、薪酬中立、合作参与规则文件、以及带保护窗口的交易注册。
- **真实但由供应商发起的词汇**：“生态系统驱动增长”和“近边界”——广泛采用的术语，但由供应商创造；作为共享词汇使用，永远不会作为教条。
- **没有标准**：合作销售准备和成熟度模型是竞争性顾问框架。将其作为选项类别呈现，而不是作为规范模型。
- **最好只是方向**：头条合作伙伴提升基准（更大的交易、更高的获胜率、更快的周期）追溯到供应商营销，而非独立研究。只有在附加了该标志的情况下才引用它们。

## 诊断现有动作

当用户带着一个正在运行的合作销售动作而不是空白页面到达时，按以下顺序工作修复——每单位努力的最高价值首先，不是最便宜首先。轴线不一致，因此呈现计划时说明两者：

- 效率：`已发布的拒绝理由 == 锁定窗口 + 争议SLA > 注册可见性 > 平分阶梯 > 归因共同拥有 > 薪酬中立`
- 价值：`薪酬中立 > 注册可见性 > 已发布的拒绝理由 > 锁定窗口 + 争议SLA > 归因共同拥有 > 平分阶梯`

前方的平分是挣来的，不是一种策略：两者都是一页已发布的段落，在约一个小时内在仅合作伙伴关系内部签署，并且每个都消除了一个不同的高频症状。

薪酬中立是这个顺序忽视的。这是页面上最高价值的修复，但在比率上仍然排名最后，因为它是对领域的一项合同承诺，成本为季度，需要财务+CRO签署链。只遵循效率线的读者永远在处理廉价环节，并且永远不会购买其他环节无法替代的唯一修复。

在以下症状上将其提升到第一：代表在注册可见性、拒绝理由和锁定窗口都到位后仍然绕过或沙袋式处理合作伙伴交易。在面试问题3中，如果销售领导表示不会重新打开薪酬计划，则此计划中删除薪酬中立，并记录为已知风险——永远不会将其列在底部，在那里它重新出现为无人签署的范围。根据用户的自身情况重新排序其余部分——一个其拒绝理由已经发布的团队从第二环节开始。

## KPI

分别追踪来源和影响：合并它们会掩盖合作伙伴是否产生管道或加速管道。核心 KPI：

- 合作伙伴来源的管道份额。
- 合作伙伴影响的收入份额。
- 附加率。
- 注册到批准的时间。
- 争议率。
- 裁决 SLA 合规性。

仅在使用者自己的数据中比较合作伙伴附加交易与直接交易的胜率和周期长度，因为跨公司基准不可靠：机会创建标准因公司而异，并且没有独立的行业基准来衡量注册批准率或时间到批准。每季度审查一次。一个合作伙伴驱动超过 ~30% 的渠道收入的计划存在集中风险，值得标记。

现有的少数已发布的基准数字是供应商提供的，仅具方向性。它们及其标记位于 [references/attribution-and-compensation.md](references/attribution-and-compensation.md)。

## 调用示例

- "为我们的经销商和 SI 合作伙伴编写联合销售运营章程 - 中端市场，平均销售周期 100 天，补偿待遇目前未定义。"
- "我们的 AEs 不知道合作伙伴注册的交易何时受保护。起草交易注册政策，并通过一个真实交易进行演练。"
