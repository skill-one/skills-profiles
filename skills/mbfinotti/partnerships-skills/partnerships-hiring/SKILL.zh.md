# 合作伙伴招聘

构建招聘经理在合作伙伴岗位上招聘所需的艺术品，以该领域自身招聘证据支持的严谨性为准：一个根据公司类型校准的评分卡、一个结构化的面试循环，包含命名的案例研究和判断测试、一个招聘计划，以及一个不假装公共基准一致的薪酬立场。

合作伙伴岗位没有跨公司的职业阶梯，也没有像销售或DevRel那样命名的职位质量分类法——这种缺失是为什么这项技能依赖于公司类型的校准和该领域少数几个经过充分记录的循环模式，而不是引进一个不存在的框架。

超出范围，转而移交：指导候选人——mbfinotti/partnerships-skills@partnerships-career 是这项技能的镜像。如果用户是在求职而不是招聘，用一句话说明，并引导他们去那里。

## 面试

一次问一个问题，尽可能使用选择题。跳过已经回答的问题。问题 8-10 重新排序下文的工件——在生成任何东西之前问它们。

1. 哪个子学科：(a) 渠道/联盟和商业伙伴战略 (b) 附属计划管理 (c) 影响者/创作者合作伙伴关系 (d) 推荐计划管理 (e) 不确定——建议根据公司的行动推荐一个。
2. 公司类型：(a) 早期阶段初创公司，这将是有史以来第一个专门的合作伙伴岗位招聘 (b) 正在建立专门团队的成长型公司 (c) 拥有每个超大规模或每个层级人头数的跨国公司 (d) PLG 公司，其中集成/附属商占主导地位。
3. 市场进入策略：以销售为主导的 B2B、产品驱动 (PLG) 或混合模式？
4. 对于第一个专门招聘：是创始人还是其他人目前每周都在花费 10 小时以上处理合作伙伴的 inbound/outbound？
5. 这个角色需要被衡量的是什么——合作伙伴来源的管道、合作伙伴来源的收入、集成/市场激活、附属商驱动的收入或推荐转化？
6. 报告线：这个角色将向销售、市场或自己的职能报告？(这会改变角色实际衡量的内容——诚实地回答，而不是抱有幻想。)
7. 薪酬立场：你会发布一个范围，并且你知道会触发任何变量薪酬的归因模型（来源/影响/关联/交付）吗？
8. 截止日期：本月、本季度或没有硬性日期？
9. 一次性招聘还是第一个在重复使用评分卡和循环的多个招聘中？
10. 努力上限：每个候选人多少面试官小时，并且是否有招聘人员或培训小组？

## 阅读答案

- **Q1 + Q2 决定评分卡模板和面试格式**——加载 [references/company-type-hiring-bar.md](./references/company-type-hiring-bar.md)。初创公司招聘被作为通才筛选；跨国公司招聘被针对一个超大规模或合作伙伴层级的深度筛选；PLG 招聘被针对集成/市场激活的熟练程度，而不是渠道交易注册流程。
- **Q2 + Q4 决定第一个专门招聘的候选人画像。** 两个需要避免的命名失败模式：招聘一个**太资深**的人，他们期望制定战略和领导团队，而实际需求是动手执行；招聘一个**太通才**且没有实际市场进入代表的人，他们无法确定哪些早期行动实际上会奏效。根据工作预期的形状匹配招聘——几个深度、高接触的集成与许多轻接触的合作伙伴需要不同的画像。
- **Q5 设置评分卡的结果指标**——永远不要写笼统的“建立合作伙伴关系”结果；命名这个角色实际拥有的实际指标。
- **Q6 是这次面试中杠杆最大的问题。** 一个角色的实际衡量标准遵循其报告线，而不是其头衔——销售下的合作伙伴角色像销售角色一样被衡量，在市场下的像活动职能一样被衡量，独立的像自己的 P&L。写评分卡的结果以匹配实际报告线，而不是一个抱有幻想的线。
- **Q7 触发质量门下的薪酬门**——合作伙伴职位的发布基准对同一个职位存在 2-3 倍的差异（参见 [references/compensation-guidance.md](./references/compensation-guidance.md)），所以永远不要引用一个单一的混合数字作为市场率。
- **Q8 促进重用现有的循环和问题库，而不是从头设计新的。**
- **Q9 决定面试循环是否保持简洁。** 一次性：保持简洁。复合：正确构建循环和评分卡，因为它们服务于这个子学科中的每个未来招聘。
- **Q10 删除循环阶段而不是重新排序它们**，与销售招聘处理紧张的面试官小时预算的方式相同。

## 工作流程

按顺序生成工件，并在用户验证每个工件后再移至下一个。

1. 运行面试。用一句话说明子学科和公司类型校准，用户可以否决。
2. **工件 1 - 角色评分卡。** 基于 [references/company-type-hiring-bar.md](./references/company-type-hiring-bar.md) 构建：
   - 一句使命声明报告线及其指标 (Q6)
   - 3-8 个可衡量的结果与 Q5 声明的指标匹配，永远不要模糊的责任，如“建立合作伙伴关系”
   - 按子学科和公司类型加权的能力——一个初创公司通才评分卡不应该像跨国公司联盟经理评分卡，只是数字变了
3. **工件 2 - 面试循环和问题库。** 基于 [references/interview-loop-and-case-studies.md](./references/interview-loop-and-case-studies.md) 构建：
   - 对于渠道/联盟招聘，应用文档模式：招聘人员筛选，招聘经理轮次与跨职能利益相关者，行为/场景问题关于合作伙伴冲突，一个技术/工具轮次，在高级别时，一个跨部门小组与一个模拟 30/60/90 天计划或合作伙伴业务回顾
   - 明确包含两个命名的判断探针： “十二月和一月是同一笔交易”的问题，以及优先级降低的合作伙伴后续跟进——两者都是可练习但揭示性的，该领域的 DevRel 意见轮次版本
   - 当适用时，一个谈判角色扮演：一个双边模拟，带有隐藏的约束，根据候选人如何构建条款和找到放弃点进行评分，而不是谁“赢了”
   - 对于附属商、影响者/创作者和推荐招聘：**没有可比的文档循环模式存在**——根据角色的实际结果指标构建循环（项目绩效、活动结果、激励设计决策），而不是全盘照搬渠道经理的案例研究，因为日常差异足够大，那些场景会测试错误的事情
4. **工件 3 - 招聘计划。** 基于 [references/sourcing-channels.md](./references/sourcing-channels.md) 构建：
   - 对于第一个专门招聘，在发布外部之前先在现有的销售/BD 组织内部寻找——已经非正式处理合作伙伴咨询的人是一个经过验证的低风险候选人库
   - 在该领域的唯一专门招聘网站上发布，并将重叠的从业者社区视为自己的招聘渠道，而不仅仅是研究来源
5. **工件 4 - 薪酬立场。** 基于 [references/compensation-guidance.md](./references/compensation-guidance.md) 构建：
   - 永远不要编造一个单一的市场率数字；展示一个带有来源和人口的范围，或者实时检查该领域的特定薪酬数据库
   - 根据子学科匹配薪酬结构（附属商角色的三部分基本工资/奖金/佣金；基本工资加变量与命名的归因模型挂钩的渠道/联盟角色）
   - 决定并声明哪个归因模型（来源、影响、关联、交付）会触发任何变量薪酬，在发布招聘之前
6. 运行质量门。迭代直到通过。
7. 如果你的 harness 具有持久内存，存储评分卡、循环设计和招聘计划，以便这个子学科中的重复招聘重用它们，而不是重新开始。

## 公司类型和子学科校准

永远不要将一个评分卡模板视为可跨公司类型或子学科移植——完整的比较、正式化角色的时间信号，以及该领域在跨国公司规模下的特定人员失衡风险（市场开发在市场下过度旋转，在销售下旋转不足）都存在于 [references/company-type-hiring-bar.md](./references/company-type-hiring-bar.md)。

## 质量门

在最终交付前，根据这些检查对工件进行评分。迭代直到每个检查都通过。

1. 评分卡命名实际报告线 (Q6) 及其指标，并且每个结果都是量化的。
2. 第一个专门招聘的候选人画像避免了两个命名失败模式：不是太资深以至于无法动手执行，也不是太通才且没有市场进入代表。
3. 渠道/联盟招聘的面试循环至少包含一个命名的判断探针，并且当适用时，包含一个评分的谈判角色扮演。
4. 对于附属商、影响者/创作者或推荐招聘，循环是根据角色的实际结果指标构建的，而不是从渠道经理模式复制过来的。
5. 没有阶段要求候选人做无偿的客户式工作，除了一个合理、有边界的练习。
6. 招聘考虑在第一个专门招聘之前首先考虑内部组织。
7. 发布声明一个真实的薪酬立场——一个带有来源和人口的发布范围，或者一个明确的理由说明为什么它被限制——永远不要“有竞争力”而没有背后的东西。
8. 任何变量薪酬背后的归因模型都明确命名，而不是留作隐含。
9. 每个薪酬或基准数字都附带其来源和日期；不提供一个混合数字作为确定的市场率。

## 常见的失败模式

未排名，故意：每一行都是一个缺陷，有一个必须的修复。

| 失败                                                                 | 修复                                                                                              |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| “身兼数职”发布，没有所有权边界或声明路径                                  | 明确说明角色组件的数字时间分配，或所有权边界                                                                 |
| 包含无主要指标的 Buzzword 混合标题                                        | 命名资金行动和角色衡量的一个指标                                                                                               |
| 将跨国公司联盟经理评分卡复制给初创公司通才招聘                               | 在重用任何先前的评分卡之前，根据公司类型重新校准                                                                                              |
| 将渠道经理循环应用于附属商或影响者招聘                                     | 根据该角色的实际结果指标构建循环                                                                                                      |
| 模糊的薪酬，没有范围，没有理由                                        | 发布一个带有命名基准来源和人口的范围，或明确说明为什么它被限制                                                                                 |
| 变量薪酬的归因模型未决定                                               | 在发布招聘之前决定来源/影响/关联/交付                                                                                       |
| 对于第一个专门招聘首先从外部招聘                                       | 检查销售/BD 组织中是否有人已经在非正式地做这项工作                                                                                             |
| 引用一个混合工资数字作为市场率                                           | 提供一个带有来源和人口的范围，或实时检查该领域的特定数据库                                                                                      |
