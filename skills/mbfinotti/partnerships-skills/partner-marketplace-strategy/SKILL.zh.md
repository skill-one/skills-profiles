# 合作伙伴市场策略

制定在第三方市场平台上的策略：选择哪些平台、深度如何、顺序如何、投资多少以及结束的条件。工作方法如下：

- 列出清单 → 交易 → 共同销售 → 扩展能力阶梯（广泛的B2B从业者共识）。
- 采用Tackle的云GTM成熟度模型（供应商编写，分阶段销售工具）。
- 采用McFadyen Digital的市场平台成熟度模型（咨询编写，B2C）。
- 为了了解供应商格局：Canalys全球共同销售软件领导矩阵、IDC MarketScape市场平台评估、Gartner的PERM市场指南（独立分析师），以及Jay McBain的生态系统工作作为最可信的个人声音。

该领域没有独立的纵向验证框架。每个分阶段模型都由销售该过程的方编写：将其作为结构使用，而不是作为证据。

输出是执行该决策的行政资金：市场平台策略备忘录，而不是执行工作。

- 列出清单内容、商店优化和广告策略属于其他地方。
- 每个合作伙伴的经济效益、命名联盟排名和联合GTM计划转交给兄弟技能（见参考资料）。

## 面谈

在制定策略之前进行面谈。每个消息问一个问题，并在可能的情况下提供多个选择答案。只有当用户已经给出答案时才跳过问题。

- B2B软件、消费品牌或混合？
- 产品类型和部署模型：SaaS、自托管/可安装镜像、实物商品、服务？
- 价格区间：典型ACV或订单价值，以及毛利？平台费率可以消耗多少利润？
- 目前通过哪些渠道销售，直接的行动是否已经可重复？证据是什么？
- 目标买家的采购目前处于什么位置：承诺的云支出（以及与哪个提供商），主导的零售平台，还是都不是？
- 买家是否通过市场平台购买？目标账户中是否有承诺支出合同？
- 谁拥有这个决策，谁必须批准它（收入、财务、产品 - 或电商、营销、财务）？
- B2B：市场路由的交易在销售补偿中如何处理 - 中性、惩罚或未定义？
- 运营能力：计量/授权工程、交易台、B2B的税务/法律，或B2C的库存、履行、退货、零售媒体预算？
- 成功意味着什么，哪个指标，以及必须在什么日期之前得到结果？
- 这是一次性的收入胜利，还是复合的采购资产，在几年内支付？
- 努力的上限是什么：可用的工程周数、交易台或履行人员数量、调整补偿计划的政治资本，以及承诺的可逆性如何？

最后三个答案会重新排序这个技能中的每个选项菜单。大声说出哪个答案移动了哪个选项：

- 一个硬性的近期日期会促进仅列出和第三方，并贬低任何需要构建的内容。
- 复合的指令会促进私有报价和深度平台投注等级。
- 低努力上限会直接从备忘录中删除渠道/多方和混合等级，而不是将它们放在底部。

## 工作流程

在每一步中都坚持三个纪律：

- **展示选项，然后等待。** 无论是否存在真正的选择（首先选择哪个平台、评分卡权重、参与深度、1P vs 3P、下架条件），展示2-3个候选方法，包括权衡和推荐，然后等待。永远不要将一个选项作为唯一的选项展示。
- **在引用的每个基准上标记来源。** 几乎所有已发布的市场平台ROI数据都来自在数字看起来好的时候受益的方：平台委托的研究、GTM工具供应商、代理商。将每个标记为运营商发布、供应商、委托研究、分析师或代理商，并将精确度视为营销。
- **根据用户重新排序。** 这个技能及其参考资料中的每个排序都是默认值，而不是法律：它会随着上下文和执行者的变化而变化。说出哪个事实移动了哪个选项，例如，一个现有的计量和授权系统删除了大部分可交易等级的成本，一个承诺支出的客户已经要求通过市场平台购买，会促进私有报价等级高于所有其他内容，并且没有任何交易台，会将其贬低到团队实际上可以运行的等级以下。

使用该行业的协作格式，而不是通用的头脑风暴：

- B2B：商业案例模板和阶段门准备审查、与市场平台团队的QBR、在季度开始前制定的补偿中立政策、账户映射作为共享数据层。
- B2C：渠道P&L模型、书面的行/不行标准、发布前的准备检查清单、每周进度审查和90天回顾。

1. 运行面谈。在评估任何内容之前，确认范围是一个业务领域和一个已声明的目标。
2. 应用准备状态门。允许回答“尚未”。不合格者：
   - 直接行动尚未可重复：市场平台放大了一个工作行动；它不会创造一个。
   - 利润无法吸收费率加上服务成本。首先解决部署模型，因为费率遵循它：SaaS列出的3%，但在AWS市场平台上为服务器/AMI/容器/ML镜像的20%，这个差距决定了这个门本身。
   - 没有命名的所有者或行政赞助人。
   - 缺少运营能力，没有预算来构建它。

   如果不合格，请说明，并指出必须改变的内容，然后停止。

3. 运行需求与采购诊断，并写下答案。市场平台主要是一个交易和采购轨道，而不是一个需求生成渠道：“列出并祈祷”是B2B和B2C中最常被引用的失败。

   明确说明这个列出清单被要求做什么：
   - 解锁承诺支出预算并缩短采购。
   - 捕获真正在那里搜索的需求。

   如果计划假设平台不会供应的需求，则该计划资助需求生成或不会进行。

4. 按类别（超大规模/云、SaaS应用商店、集成目录、零售市场、区域冠军）清点候选市场平台，以市场面谈中买方采购和流量已经处于的位置为锚点。按默认效率顺序评估：每单位努力的价值回报，其中努力是工程周数、交易台重做和可逆性，而不是费用。没有顺序跨越双方：
   - B2B：`超大规模云 > 集成目录 > SaaS应用商店`
   - B2C：`主导零售市场 > 区域冠军`

   如果你可以在网上浏览，从竞争对手列表、平台合作伙伴目录和类别邻居扩展清单。参见[参考资料/市场平台分类.md](references/marketplace-taxonomy.md)以获取每个轴的排序和每个排序会剥夺什么。

5. 在评分之前筛选硬性门槛：范围违规、平台条款业务无法接受、缺失先决条件。将未解决的合规或费用问题标记为“待验证”。永远不要将未知转换为拒绝或接受。
6. 在加权优先级评分卡上对幸存者进行评分：提出权重，在评分前与用户同意，将未支持的维度留空而不是发明精确度。然后应用第二遍影响×努力过滤器在临时影响估计上 - ROI模型在步骤11之前不会构建，因此标记轴为“临时”，并留出一个候选者未绘制，而不是发明一个影响数字。给每个候选者一个四向结果 - 试验、准备、待验证、不优先考虑 - 而不是二进制行/不行。参见[参考资料/优先级评分卡.md](references/prioritization-scorecard.md)。
7. 验证每个排名候选者的经济性。
   - 如果你可以在网上浏览，阅读运营商自己发布的日程并注明日期。
   - 否则，向用户询问，并将他们无法提供的内容标记为“未验证”，而不是假设费率。

   在运营商根本没有费率卡的情况下，记录这一点：费率是谈判输入，而不是常数。对业务案例进行压力测试，以宣布的未来费率和补贴后的费率，而不仅仅是今天的日程。参见[参考资料/市场平台经济性.md](references/marketplace-economics.md)。

8. 决定每个优先级市场平台的参与深度。每个等级都有自己的成本和能力门槛，因此按每单位努力的价值而不是按等级顺序排名：
   - B2B云：`私有报价 > 可交易 > 仅列出 > 渠道报价`
   - SaaS应用商店：`可交易付费应用 > 免费列出 > 深度平台投注`
   - 零售：`第三方 > 一方 > 混合`

   云等级是累积的：将业务案例瞄准私有报价等级，并将可交易视为到达它的通行费，因为一个停在可交易的案例几乎支付了较小价值的一半成本。从备忘录中删除用户努力上限排除的每个等级，并命名。永远不要将其放在底部。参见[参考资料/市场平台分类.md](references/marketplace-taxonomy.md)以获取每个轴的排序、平局和每个排序会剥夺什么。

9. 顺序：首先选择一个平台，证明行动，然后扩展。定义解锁每个阶段的门 - 例如，首先关闭交易（续订是B2B中记录的低风险证明路径），补偿政策书面，贡献边际为正 - 以及每个门需要的要求证据。
10. 设定投资封顶：平台费率、实际成本-服务，以及命名所有者的时间。
    - B2B成本-服务：集成/计量工程、交易台、法律/税务设置。
    - B2C成本-服务：履行、退货储备、实际强制零售媒体。

    没有所有者和封顶的列出清单只是可见性，而不是管道。

11. 构建ROI预期及其衡量计划：
    - 列出清单前的基线。
    - 与财务商定的来源与影响定义。
    - 新增收入与转移收入，分开。
    - 每侧的KPI。

    仅将已发布的基准用作已标记来源的封顶，而不是作为基准案例。然后重新运行步骤6的影响×努力过滤器对完成的模型，并记录每个四象限移动的候选者。这种变化是发现，而不是埋葬的修正。参见[参考资料/ROI和KPI.md](references/roi-and-kpis.md)。

12. 现在在发布之前写下下架/降级触发器：结束或降级列出的条件和审查日期（例如，在约定的几个季度内进行真正努力的交易后没有交易的操作成本，或在广告和退货后贡献边际为负）。提前决定的触发器可以承受沉没成本压力。一个后来决定的触发器很少被触发。
13. 按照以下顺序逐节展示备忘录，并在起草下一节之前与用户验证每一节。在最终确定之前，要求对每一节进行明确的批准。
14. 将完成的备忘录与通过标准进行对照，并迭代直到通过。如果没有候选者通过，建议不列出并记录原因：这是一个有效、可资助的结果。
15. 如果你的套件具有持久内存，请记住批准的决策（排名市场平台、权重、深度选择、封顶、门、下架触发器），以便以后的运行从它们开始，而不是重新进行面谈。

## 市场平台策略备忘录

将每次参与都作为此决策记录交付：

```
市场平台策略  - <公司/业务领域>，<日期>
范围          ：产品线、ICP、地理；B2B、B2C或混合；排除了什么
诊断          ：需求与采购  - 每个列出清单被要求做什么
候选者        ：评估的市场平台、硬性门槛筛选结果、待验证
优先级        ：评分卡结果，显示权重；第二遍过滤器；每个候选者的四向
                 结果（试验/准备/待验证/不优先考虑）
深度          ：每个市场平台  - 仅列出/可交易/私有报价/渠道
                 报价（B2B）或 1P/3P/混合（B2C）；资助的等级、原因，
                 以及用户努力上限排除的等级
经济性        ：每个排名市场平台的费率，来源和日期（“未验证”
                 在哪里声明）；封顶与毛利；补偿待遇（B2B）
                 或广告/退货/履行后的贡献边际（B2C），书面
分阶段计划    ：首先选择一个平台；证明行动，然后扩展。解锁每个阶段的
                 门和证据
ROI预期       ：预期范围和回收期；构建它的每个基准的来源标记
下架触发器    ：降级或删除每个列出的条件的日期
所有者        ：命名所有者、批准者、审查日期
开放问题      ：什么无法验证，以及什么可以验证它
```

每一行都包含一个审查者可以检查的原因。开放问题部分是强制性的：一个没有声明不确定性的备忘录停止提问。

## 通过标准

当所有这些都满足时，备忘录就完成了。迭代直到它们满足：

- **每个排名的市场平台都有一个费率，具有命名的来源和日期**：运营商自己发布的日程（如果存在），在不存在的情况下明确为“未验证”。不沉默地假设费率。
- **业务案例可以承受运营商宣布的未来费率和补贴后的费率**，而不仅仅是今天的日程。
- **存在命名的所有者和批准者**：“列出但没有所有者拥有结果”是该领域最常见的沉默失败。
- **补偿待遇（B2B）或广告、退货和履行后的贡献边际（B2C）在发布前以书面形式决定**。
- **每个基准都带有来源标记**（运营商、供应商、委托研究、分析师、代理商）。
- **存在下架触发器，带有审查日期**，在批准时书面。
- **需求与采购诊断在备忘录中明确回答**。

## B2B和B2C

决策逻辑在五个点上真正相同。说清楚，而不是为每侧重新发明方法：

- 市场平台是一个交易机制，而不是一个潜在客户来源（“列出并祈祷”在两者中都失败）。
- 渠道冲突是一个一级设计问题（B2B中的补偿中立性，B2C中的MAP政策和1P/3P防火墙）。
- 首先选择一个平台，证明它，然后扩展，以运营就绪为依据进行扩展。
- 衡量影响收入以及来源收入。
- 关注集中风险和新增收入与转移收入。

真正不同的是：

| 维度                 | B2B 软件 / 云                                                                                                                               | B2C / 零售                                                     |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 决策者                | 联盟 / 云 GTM 领导、首席合作伙伴或生态系统官员                                                                                                   | 电商负责人/副总裁、市场平台经理                                |
| 审批人                 | CRO + CFO + 产品                                                                                                                             | 电商副总裁 / 市场营销总监 + 财务                               |
| 核心购买驱动因素        | 承诺支出回笼 + 联合销售权限                                                                                                                   | 消费者需求、搜索排名、履约承诺                                |
| 平台收益率             | 取决于部署情况，并非固定：SaaS 为 3%，但大型云市场最大的服务器/AMI/容器/ML 镜像为 20%；随交易规模和续约下降 | 按类别 6-45%，加上履约和广告费用                             |
| 主要成功变量            | 销售佣金中立                                                                                                                                | 广告/退货/履约后的贡献毛利                                    |
| 市场平台真正是         | 现有销售动作上的采购轨道                                                                                                                     | 一个全新的运营业务（商品上架、库存、广告、退货）                 |

## 失败模式

| 失败原因                                                                                 | 解决方法                                                                               |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 上架祈祷 - 将上架视为需求渠道                                                           | 书面进行需求与采购诊断；单独资助需求或不上架                                           |
| 绩效计划惩罚市场平台交易；代表绕过该计划（B2B）                                             | 在季度前书面制定绩效中立政策，写入备忘录                                                 |
| 已上架，但无人负责结果                                                                 | 备忘录中指定负责人和责任范围；无负责人则不上架                                           |
| 商业案例基于当前的收益率或入门 0% 区间                                                     | 压力测试宣布未来收益率和补贴后的收益率                                                   |
| 服务成本隐藏导致后期案例破裂（计量、税务、交易台；增值税、退货、广告）                           | 批准前在责任范围中包含完整服务成本                                                         |
| 1P/3P 自身竞争或同一产品的价格侵蚀（B2C）                                                 | 在混合模式前决定防火墙和定价政策                                                         |
| 迁移收入计为市场平台 ROI                                                                | 上架前设定基准；将新增与转移区分                                                      |
| 在第一个平台证明之前添加第二个平台                                                        | 阶段门需有证据；在第一个平台上的续约优先证明                                                 |
| 上架决定推迟到沉没成本主导时                                                              | 在批准时书面确定触发条件和日期                                                         |

## 调用示例

- "我们是否应该在云市场平台上上架？我们销售自托管容器镜像，ACV 为 40K 美元，销售主导，直接动作有效。"
- "我们在三个市场平台上都有上架，但都没有交易。告诉我该保留哪个、哪个优先级降低，以及上架触发条件应该是什么。"
