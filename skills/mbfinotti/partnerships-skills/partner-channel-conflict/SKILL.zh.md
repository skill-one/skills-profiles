# 合作渠道冲突规则

制定决定争议交易归属的规则，当直销团队和渠道合作伙伴或两个合作伙伴对同一账户提出相同主张时，以及执行这些规则的治理机制。

交付成果包括一份参与规则（RoE）文件及其裁决机制：

- 结构边界。
- 基于注册的索赔政策。
- 具有指定裁决人的升级阶梯。
- 补偿中立性决策。
- 治理节奏。

诊断基于两个框架：垂直/水平/多渠道冲突类型（Stern & El-Ansary, 《营销渠道》, 1977年；当前版本Palmatier, Sivadas, Stern & El-Ansary, 《营销渠道策略：全渠道方法》, 第9版, 2019年），以及潜在→感知→感受→显性阶段进展。解决难度在每个后期阶段都会增加，这就是在第一个显性争议出现之前制定规则的全部理由。Forrester的《缓解渠道冲突：参与规则》是交付成果形状的权威分析文件。

口头表达的边界：

- `mbfinotti/partnerships-skills@partner-ecosystem` 检测和衡量冲突区域（账户重叠、覆盖空白）并将问题转交至此处。这项技能从检测停止的地方开始。
- `mbfinotti/partnerships-skills@co-selling-strategy` 拥有直销和合作伙伴如何就共享交易合作的规则。交易注册仅作为冲突预防和索赔裁决工具出现在此处：保护窗口、平局裁决、拒绝理由，以及当双方都声称同一交易时会发生什么。

## 面谈

在提出任何建议之前提问：每条消息一个问题，尽可能提供选择题，跳过用户已经回答的内容。

- B2B、B2C还是混合？
- 公司销售什么，通过哪些方式 - 直销、转售、推荐、共同销售、市场交易、D2C、零售？
- 销售团队结构，以及如何在涉及合作伙伴的交易中补偿直销代表 - 中立、惩罚、未定义？（这个答案比其他所有答案都重要。）
- 存在哪些类型的合作伙伴，以及大约有多少是活跃的？
- 平均销售周期长度是多少天？（它决定了注册保护窗口的长度 - 通过阈值要求至少75%的周期，因此没有这个数字设置的窗口是猜测。）
- 冲突实际出现在哪里，有什么证据 - 记录的争议、合作伙伴投诉、因内斗失去的交易，还是只有传闻？
- 注册是否在机会创建时出现在记录的CRM系统中，还是仅在直销团队从未打开的合作伙伴门户中？
- 已存在的工件：参与规则、指定账户列表、注册政策、合作伙伴交易中的补偿计划语言？
- 升级文化：当争议升级时，直销销售是否总是获胜？
- 谁必须批准：渠道负责人、CRO、交易台、法务？
- 地域 - 有任何欧盟业务？欧盟规则限制领土、终止和定价条款（标记给律师）。
- 必须在什么日期之前实施规则 - 是活跃争议或截止日期在推动，还是开放式？（硬性日期会促进快速作用的阶梯 - 交易规模阈值、双重补偿、QBR议程项目 - 并降低指定账户列表和合作伙伴咨询委员会，这些只有在季度内才会见效。）
- 一次性解决当前争议，还是复合治理资产？（复合促进对齐工作坊、合作伙伴咨询委员会和指定账户。一次性解决促进阈值、发布规则和中立裁决人，以及它们之外的内容。）
- 努力上限：发布后由谁维护，每个季度多少小时，以及你在直销线中持有多少政治资本？（没有列表所有者会排除指定账户轴。直销线中没有资本意味着补偿中立性不会通过，因此结构轴承担全部负荷。）

## 工作流

始终遵循一个原则：在存在真实选择的地方 - 分段轴、保护窗口长度、平局裁决规则、补偿中立性变体、裁决人席位 - 提供2-3个候选方案，说明权衡和推荐，然后等待。分部分呈现交付成果，在起草下一部分之前用用户验证每一部分，并在最终确定之前设置明确的批准关卡。

以下所有排名都是默认值，不是法律：它会随着上下文和执行者的不同而变化。

根据面谈答案和你对这家公司的了解重新排序：

- 一个已经包含分段字段的CRM使该轴几乎免费。
- 一个已经担任账户列表所有者的职位消除了指定账户的持续成本。
- 一个现有的交易台吸收了裁决人席位。

在呈现每个菜单时说明哪个事实移动了哪个选项。在每次呈现菜单时删除被答案排除的选项，而不是将它们列在列表底部。

1. 运行面谈。
2. 使用类型学对每个报告的冲突进行分类：垂直（直销与合作伙伴）、水平（合作伙伴与合作伙伴）、多渠道（路线与路线；D2C与零售，针对消费品牌）。在潜在→感知→感受→显性进展中定位它：
   - 潜在冲突需要结构规则。
   - 显性冲突需要一个裁决案例和可见的补救措施，然后才会相信任何新规则。
3. 在编写任何规则之前进行经济审计。

   补偿中立性：无论是否涉及合作伙伴，直销代表的薪酬或配额退役率都相同。这是该领域最常引用的实际控制措施。一个具有复杂参与规则的程序，但补偿不中立，无论文件有多好，在结构上都是冲突的。

   特定陷阱：代表按合作伙伴支付的折扣价而不是客户价格获得报酬，预示着持续的垂直冲突。

   坦诚的保留意见：方向是实践者共识，幅度数字是单一来源且受供应商利益影响的。

   按效率排名的变体，成本和行为变化的轴不一致：[参考资料/补偿与激励.md](参考资料/补偿与激励.md)。

4. 设置结构边界。选择每单位持续努力预防的冲突分段轴，而不是精度 - 精度是使指定账户看起来像明显第一步的原因：
   - 效率：交易规模阈值 > 合作方式排除 > 地域 > 产品线 > 指定账户
   - 价值：指定账户 > 交易规模阈值 > 地域 > 合作方式排除 > 产品线
   - 努力：指定账户（一个持续的工作 - 所有者、刷新节奏、边缘案例规则）> 地域（一个星期绘制，在领土排他性情况下需要律师）> 合作方式排除 == 产品线（一小时编写，然后对续订或捆绑的重复边缘案例裁决）> 交易规模阈值（一小时，然后无事）
   - 合规成本：地域（欧盟领土排他性和主动/被动销售限制 - 发布前需要律师）> 其他所有轴（接近零）

   合作方式排除和产品线并列的原因是努力，而不是回避问题：每个都是RoE中的一句话，并且它们都不携带所有者或刷新节奏。它们都购买相同的重复边缘案例裁决清单：一个排除合作方式的续订，跨越两个产品线的捆绑。

   它们在价值上分道扬镳，合作方式排除在该轴上完全胜出。

   这项排名使指定账户受苦：在价值上第一，在努力上第一，在效率上最后，因此比率在每一轮都会降低它。然而，它是唯一一个可以解决公司实际争论的账户冲突的轴。

   当争议集中在少数几个战略账户上，并且一个列表所有者已经存在时，可以提升它。当它过时时，它自身成为冲突的来源。当不存在所有者时，从该菜单中删除它，并在RoE中说明该计划没有指定账户轴。一个停在“以后”的轴返回为一个无人维护的列表，这是失败模式。

   相同规则适用于面谈已经排除的轴：单一产品组合删除产品线，单一区域足迹删除地域，并且它们都标记为删除，而不是列为未来阶段。

   默认：交易规模阈值加上一个合作方式排除 - 大多数计划需要两个轴。如果指定账户通过上述测试，请使用该所有者和刷新节奏定义房屋/指定列表，并将列表和冲突规则保留在RoE附件中，而不是在签署的合同中，以便它们更新而无需重新纸张每个合作伙伴。见[参考资料/参与规则文件.md](参考资料/参与规则文件.md)。

5. 定义索赔工具：
   - 注册资格。
   - 必需数据。
   - 保护窗口（观察到的30-180天，最常见的是90天，至少为平均销售周期长度的~75%）。
   - 批准SLA。
   - 延长和到期。
   - 标准拒绝理由。
   - 平局裁决：首先注册，有一个实质性工作测试，供应商裁量作为后备。

   见[参考资料/交易注册和索赔.md](参考资料/交易注册和索赔.md)。

6. 设计升级和裁决阶梯：
   - 具有触发器、裁决人、SLA的层级。
   - 书面证据标准：注册时间戳、首次参与时间线、活动日志，从不考虑资历。

   指定一个不是直销领导的中立裁决人，并定义输方应得的补救措施。见[参考资料/升级和裁决.md](参考资料/升级和裁决.md)。

7. 设置治理节奏和指标。按每单位持续努力预防的冲突对齐工作坊进行论坛排名：
   - 效率：QBR常驻议程项目 > 渠道对齐工作坊 > 联合账户规划 > 合作伙伴咨询委员会
   - 价值：渠道对齐工作坊（将规则建立在冲突实际存在的位置）> 合作伙伴咨询委员会（合作伙伴在发布前接受的规则变更）> 联合账户规划（在争议存在之前同意每个账户的所有权）> QBR项目（漂移保持可见）
   - 努力：合作伙伴咨询委员会（一个持续的工作）> 渠道对齐工作坊（一周，一次，在起草或重写时）> 联合账户规划（每个命名账户每个周期一天）> QBR项目（接近零 - 一个已经发生的会议的一行）

   这里受苦的论坛是合作伙伴咨询委员会：在价值上第二，在努力上第一，在效率上最后，因此它从未在一次比率中幸存。然而，它是唯一一个在发布规则变更之前让合作伙伴接受的论坛，而不是在之后争论它。

   当重写触及合作伙伴已经赚取的钱（利润、保护窗口、注册资格）时，可以提升它，在这种情况下，单方面发布比委员会花费的时间成本更高。

   当没有人可以承担一个持续的工作时，从治理计划中删除它，并说明这一点。一个列为未来论坛的委员会读起来像是合作伙伴从未真正得到的咨询。

   默认：QBR项目加上在起草时一个对齐工作坊。一旦指定账户存在，就添加联合账户规划，并在第4步中删除指定账户轴，因为没有任何账户可以规划。

   在这些格式中运行设计会议：这个职业有自己的格式，因此永远不要用通用的头脑风暴来替代。从注册拒绝理由的混合开始度量。完整的排名在[参考资料/治理节奏和指标.md](参考资料/治理节奏和指标.md)。

8. 发布和执行：
   - 规则存在于合作伙伴实际阅读它们的地方（合作伙伴门户，而不是内部驱动器）。
   - 注册写入记录的CRM系统，以便在机会创建时可见重叠。
   - 执行支持在文件中命名：它是工件的一部分，而不是一种礼貌。

   一个未执行的规则比没有规则更快地破坏合作伙伴的信任。

9. 对齐通过阈值进行验证。迭代直到每个标准都满足。
10. 如果你的引擎具有持久记忆，请记住批准的参与规则、指定账户排除和裁决先例，以便后来的运行可以从它们开始，而不是重新面谈。

## 通过阈值

当所有这些都满足时，规则就完成了。迭代直到它们满足：

- **补偿中立性决定** - 并且该决定写入合作伙伴协议和直销补偿计划，而不仅仅是其中一个。
- **注册在机会创建时在CRM中可见**，而不仅仅是在预订时或在一个断开的门户中。
- **保护窗口 ≥ ~75%的平均销售周期长度。**
- **每级升级的裁决SLA定义** - 工作级别和中立裁决人层级为48小时决策，在执行层级为5个商业日，用于设定先例的争议和上诉。不要将48小时数字应用于执行层级：这两个数字都是该领域的惯例。将此与注册_批准_ SLA分开，这是一个不同的时钟。
- **一个不是直销领导的中立裁决人。**
- **一个为同一交易的两次索赔的书面平局裁决**。
- **为每个裁决的输方定义补救措施。**
- **每个引用的基准都带有来源标记** - 该领域的数字大多是供应商发布的营销。将主要、贸易和供应商声明分开标记。
- **规则发布在合作伙伴可以实际阅读它们的地方。**

## 参与规则文件

将批准的规则作为此文件交付 - 完整部分解剖结构在[参考资料/参与规则文件.md](参考资料/参与规则文件.md)：

```
参与规则：<公司>，<版本>，<日期>，<指定高管支持者>
分段：哪些账户是直销专有、合作伙伴专有、共享：以及决定该轴的
账户列表：房屋/指定账户，列表所有者，刷新节奏，边缘案例规则（保留为附件，可更新而无需重新纸张）
注册：资格，必需数据，保护窗口，批准SLA，延长/到期，
补偿：中立性声明，在直销补偿计划中镜像
升级：阶梯（层级，触发器，裁决人，SLA），证据标准，补救措施，上诉
例外：如何申请，谁批准，在哪里记录
治理：审查节奏，非周期性重写触发器，在哪里发布，修订程序
```

## B2B和B2C

双方都相同：

- 垂直/水平/多渠道分类。
- 经济错位（不是个性）作为根本原因。
- 单一系统记录。
- 分段作为第一个结构控制。
- 路线间价格一致性。
- 治理节奏。

真正不同：

| 维度         | B2B                                                                         | B2C                                                                                                                |
| ------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 声明工具  | 交易注册带有保护窗口                                                         | 无 - 市场路线图是具有约束力的文件                                                                                       |
| 经济控制  | 商业中立性；联合销售和市场交易交易的利润率路由                               | MAP作为严格单方面的政策（反垄断 - 从不协商）                                                                               |
| 结构杠杆  | 指定客户、交易规模和动议的例外情况                                             | 渠道独家商品组合 / SKU差异化                                                                                         |
| 执行       | 合同和补偿 - 供应商控制两者                                                  | 市场拒绝执行品牌政策；通过商标实质性差异原则进行灰色市场执行                                                               |
| 正式失败  | 直接销售覆盖批准的注册                                                        | 假设MSRP价格平等解决D2C冲突 - 冲突在于注意力、流量和信任（耐克的逆转）                                                       |

完全对比，耐克案例的日期和数字，以及美国/欧盟法律界限：[参考资料/b2b-b2c-and-legal.md](参考资料/b2b-b2c-and-legal.md)。

## 失败模式

| 失败                                                           | 修复                                                                                                                                                                                                      |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 政策作为戏剧 - 规则存在但未执行                                  | 执行或删除；未执行的规则比没有规则更快地破坏合作伙伴信任                                                                                                                                             |
| 直接销售总是赢得升级                                              | 销售线外的中立仲裁者 + 补偿中立性；修复是结构性的，而不是行为性的                                                                                                                                          |
| 注册抢占 - 合作伙伴囤积他们没有处理的交易                      | 默认过期加上基于活动的扩展测试                                                                                                                     |
| 站点和CRM断开连接 - 冲突出现在预订时                              | 注册在提交时写入CRM；自动检查账户与活跃管道                                                                                                         |
| 过期的指定客户列表本身成为冲突来源                               | 指定列表所有者、刷新周期和在RoE中体现的边缘情况规则                                                                                                                                   |
| 无论交易规模如何，注册激励都是扁平的                              | 区分提升；扁平的增幅无法揭示您最需要了解的大型战略交易                                                                                                                                             |
| 为每个边缘情况发明一个新流程                                      | 一个一致的过程；允许一个机会上的多个角色，按记录的贡献分配信用                                                                                                                                             |
| 对早期阶段项目过度监管                                            | 最小可行集：注册与冲突检测、发布规则、对齐补偿、区域边界                                                                                                                                             |
| 每次渠道领导者更迭时重写规则                                      | 平均渠道主管任期是4.2年，2-3年在最大公司之外（杰·麦克贝恩，对337位渠道主管的分析）- 将规则锚定到执行赞助人和修订程序，而不是一个人                                                                         |
| 假设MSRP价格平等解决D2C冲突                                      | 冲突在于注意力、流量和信任；结构杠杆是商品组合差异化，而不仅仅是价格                                                                      |

## 调用示例
