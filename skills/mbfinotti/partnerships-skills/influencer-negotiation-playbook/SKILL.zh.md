# 影响者谈判手册

构建一个品牌方合作经理在与创作者进行交易条款谈判时使用的手册。机会窗口在创作者表示兴趣时开启，在合同签署时关闭。

没有记录任何命名谈判框架（BATNA/ZOPA、战术同理心、Ackerman、MESO）在创作者交易中真正使用的情况——对两家高容量行业出版物进行目标搜索，没有找到任何与创作者交易相关的内容。因此，这项技能使用普通的日常工作词汇（初始立场、让步、放弃阈值），不标明任何方法。

其参考中几乎所有的量化惯例都追溯到一家供应商出版物（影响者营销中心，主要由两名员工撰写，没有调查支持，有时在其自己的文章中不一致）。将此类数字视为谈判范围，以测试用户自己的费率信息，而不是作为市场价格。

这项技能为人类做准备。它从不：

- 代表用户进行谈判。
- 冒充用户。
- 代表用户发送消息。

它不是法律建议：最终条款必须体现在由合格律师审阅的书面合同中。

## 面谈

在起草任何内容之前进行询问。

- 每条消息一个问题，尽可能使用多项选择题回答。
- 跳过用户已经回答过的任何问题。

- 这是一笔B2C品牌合作还是B2B创作者项目（Newsletter、播客、行业专家）？
- 创作者是谁，在哪些平台，以及什么层级/受众规模？
- 你希望创作者制作什么——一个粗略的交付物草图（格式、数量、时间）？
- 批准的预算范围是多少，以及你已经持有的费率信息或基准是什么？这项技能不进行费率基准测试——带来过去的交易范围、创作者的费率卡或你自己的研究。
- 哪些条款是必须的，哪些是可选择的？
- 你实际需要哪些使用权（自然转载、付费广告/白名单、持续时间、地域），以及是否需要竞争对手排他性？
- 内容必须在什么日期上线——固定发布日期，还是灵活窗口？
- 你想要一次性的活动胜利，还是一个可以累积成更便宜、更快交易的关系？
- 你运行此交易的精力上限是多少——每周小时数、是否有人已经拥有跟踪和支付对账，以及你能花费多少内部批准？
- 谁进行谈判——你直接与创作者，还是通过人才经理/代理？
- 你的内部预算授权是多少，以及谁在它之上签字？

生命周期日期、一次性与累积答案，以及精力上限移动这项技能中的排名。重新对每个菜单项进行排名，并说明哪个答案移动了哪个选项：

- 两个星期内的固定日期会固定一次性固定形状，并从让步梯队的发布日期灵活性中删除。
- 累积指令会提升保留。
- 薄弱的精力上限，或者没有人拥有归因，会完全删除混合固定+佣金形状。

## 工作流程

1. 运行面谈；在起草之前收集所有答案。
2. 基于费率信息进行控制：如果用户没有带来费率范围，停止并询问。从不构建费率基准——那超出了范围，也没有其他兄弟技能涵盖它，所以不要将请求转发出去，好像其他人会回答它。相反，按以下顺序将用户交给三种获取范围的方法，然后等待：
   - 效率：创作者自己的费率卡 > 3-5名可比创作者的报价 > 平台的已发布创作者收入范围
   - 价值（数字在会议室中受到挑战后能存活得多好）：可比报价 > 费率卡 > 已发布范围
   - 成本：可比报价（一周的接触和等待回复）> 已发布范围（一小时阅读）> 费率卡（一条消息）
   - 每个选项除了上述排名之外能带来的东西：
     - **费率卡**：基于比例，而不是免费。一条消息在桌上放出一个真实数字，但它是由创作者提出的，而不是一个范围。
     - **可比报价**：唯一能产生你可以在对方施压时辩护的范围的选项。当活动日期超过几周时，推荐它们。
     - **已发布范围**：当两者都不可用时，它是回退。它们仍然是一个方向性的理智检查，永远不会是初始立场。
3. 使用 [references/deal-terms-landscape.md](references/deal-terms-landscape.md) 分别列举每个可谈判条款。从不将“交易”作为一个数字进行谈判。
4. 进入关于交易形状的头脑风暴模式，使用下面的交易形状菜单。首先应用其删除条件，提出最生存的形状加上它后面的一个，并命名哪个面谈答案改变了顺序。一次问一个问题；在用户选择形状之前不要起草任何东西。
5. 为每个条款设置一个初始立场、一个后备方案和一个放弃阈值，根据 [references/concession-ladder.md](references/concession-ladder.md)。明确应用其锚定决策规则——第一个说出数字的人是一个来源未解决的紧张关系，而不是一个已解决的问题。
6. 按每个让步每单位成本给你回扣的顺序对让步梯队进行排序，而不是按哪个让步最便宜，使用 [references/concession-ladder.md](references/concession-ladder.md) 中的排名表格。删除其条件规则排除的行，而不是将它们带到底部，并在手册中说明结果顺序。
7. 添加红色警告响应，并在涉及人才经理时，添加来自 [references/red-flags.md](references/red-flags.md) 的经理特定礼仪。
8. 插入披露门：披露/FTC合规性是交易的不可谈判条件，永远不会是可交易条款。将义务路由到 `mbfinotti/partnerships-skills@affiliate-disclosure-compliance`；不要重述法规。
9. 列出必须达到书面合同的内容（交付物、使用权层级、排他性范围+持续时间、修订上限、支付条款、终止费、披露义务、跟踪）。
10. 与质量门自我检查；迭代直到每个项目都通过。
11. 在最终确定之前，逐节验证手册与用户——条款、梯队、红色警告、合同列表。
12. 提供手册时提醒：用户进行谈判，律师在签署合同前审阅合同。
13. 如果你的框架具有持久内存，一旦知道交易的初始与最终条款，请记录（见KPI）；否则，将日志表格交给用户保存。

## 交易形状

第4步的菜单，排名。三种形状包含创作者交易；顺序不一致，所以大声说出你正在使用的顺序：

- 效率（每轮谈判和每周运营的回报）：固定一次性 > 保留 > 混合固定+佣金
- 价值（一个季度的总回报）：保留 > 混合 > 固定一次性
- 成本（设置和运行的努力）：混合 > 保留 > 固定一次性
- 合规成本：混合 > 保留 > 固定一次性

首先提出固定一次性，因为它赢得了比例，而不是因为它是最小的交易。最大的回报形状也是运行一个固定工作所需的形状，只有比例回答了在周一提出哪个形状。

| 形状                          | 它能买到什么                                                                                                          | 它为你成本什么                                                                                                                                     | 合规风险                                                                                                         |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 固定费用，一次性                | 一个活动，交付并关闭，使用权和排他性作为附加项而不是捆绑销售                                                              | 一次谈判，准备小时数，签署后没有任何义务                                                                                          | 一次时间限制的使用授权和一条披露义务；一旦窗口结束就完全可逆                             |
| 保留/多活动量                 | 更低的每交付物费率，保留创作者容量，以及一个使下一个交易更容易关闭的关系 | 几轮更多，预算授权跨越一个季度，以及固定的关系管理                                                        | 排他性和使用权窗口运行保留的全长——在飞行中 hardest terms to unwind                   |
| 混合固定+佣金                 | 追踪结果的费用，如果活动表现不佳，则有下限保护                                  | 归因、对账和支付操作——一个固定工作，而不是设置任务——加上创作者以换取确定性而提出的更高的固定要求 | 活动后的实质性联系披露，支付和税务处理，以及佣金条款律师必须阅读 |

默认：固定费用，一次性。一旦与该创作者的第一个交易关闭，并重复双方的真实意图，就向上移动一个等级到保留。

删除，不要降级：

- 当内容发布前跟踪不活跃或没有人拥有支付对账时，完全从菜单中删除混合形状。一个未跟踪的佣金是与创作者的争议，而不是交易形状——不要将其保留为预算超支的桥梁。
- 当重复意图不是真实或预算授权止于此活动时，删除保留。针对你无法履行的承诺的量价购买比一次性支付更多。
- 永远不要将删除的形状降级“为了完整性”；菜单中的一个排除选项最终会被选中。

这个顺序是一个默认值，而不是法律：它随着交易和运行它的人而变化。在提出之前，根据你已知的用户重新排名：

- 与此创作者现有的已签署关系将保留放在第一位，因为其谈判和信任成本已经沉没。
- 内部法律加上一个活跃的联盟计划会压缩混合的成本和合规轴，并提升它。
- 两个星期内的固定发布日期会固定固定一次性，无论其他什么为真。

## 调用和预期输出

典型的调用：

- "@plantsbypriya 回复了并表示想讨论条款 - 2个reels + 3个stories，预算从我们过去的交易中4-6k美元。为我构建我的谈判手册。"
- "DevOps播客作家感兴趣，但她的经理报价是我们的预算的两倍。为我准备通话。"

交付一个结构化的工件：

```
影响者谈判手册 - <创作者>, <日期>
交易形状        : 选择的形状 + 其排名，哪些竞争对手被删除以及删除的条件
条款位置        : 表格 - 条款 / 初始 / 后备 / 放弃
让步梯队        : 排序的交易 - 让步 / 顺序 / 它能买回什么
红色警告        : 对手信号 -> 脚本化响应
放弃线          : 总预算上限 + 自动退出条件
不可谈判        : 披露义务（门，而不是条款）
合同中          : 每个必须以书面形式出现的已同意条款
```

## B2B和B2C

- 范围-先于费率顺序、书面合同要求、披露门和支付条款卫生对两者都完全相同。已发布的指导没有细分，这弱弱表明了普遍性——将其视为一个推论，而不是一个记录的规则。
- B2B记录的具体细节：按漏斗阶段分层的佣金（例如，MQL/SQL/已成交交易等级）、高价值交易的年收入百分比、播客按CPM而不是固定费用定价、播客中段主持人阅读CPM，以及至少有一个主要播客市场完全不发布费率（私下谈判）。
- LinkedIn现在有记录的相对费率形状（与这项技能的基于基准无关的方法一致）：一个技术/SaaS创作者比同等级别的普通专业内容创作者大约高40-80%，格式乘数在顶部应用（轮播+20-35%，视频+40-80%，播客位置1.5-3倍，演讲位置≈4倍一个赞助帖子），价格因地区而异（APAC大约比北美低30-60%）。YouTube没有像LinkedIn那样发布的按技术性而非一般性费率划分——最接近的数字是一个赞助跟踪平台的普通技术细分CPM（SponsorRadar：$30-60，对游戏$10-25），方向性仅，且不是开发者特定的。B2B排他性仍然没有已发布的惯例可以继承——明确设置这些条款，而不是假设B2C惯例可以转移。
- B2C：参考文献中的层级费率形状、使用权梯队和排他性惯例偏向B2C——在那里以正常的小心使用每个数字是如何产生的。

## 质量门

对所有十一个项目进行评分。通过阈值：11/11。迭代直到没有任何项目失败。

1. 每个可谈判条款都有一个初始立场和后备方案和放弃阈值——没有条款只带一个数字。
2. 交付物范围在任何费率出现之前完全定义；价格与范围1:1跟踪。
3. 没有数字被呈现为行业标准；每个供应商来源的数字都被标记为供应商的惯例，并被视为一个范围。
4. 费率位置追溯到用户声明的费率信息，而不是这个技能提供的数字。
5. 披露仅在不可谈判部分出现——永远不会在让步梯队中。
6. 使用权和排他性每个都被时间限制并定价的扩展；没有永久性或开放式语言在任何地方存活。
7. 修订轮次被计算和限制，超出限制定义了重新定价。
8. 每个梯队步骤都命名让步买回什么；没有任何东西是免费给出的。
9. 支付条款声明一个特定的净窗口；锚定决策规则被明确应用，而不是默认。
10. 手册以书面合同清单和律师审阅提醒结束。
11. 选择的交易形状是存活其删除条件的最顶级的形状，或者手册命名了面谈答案该答案覆盖了默认顺序。

## KPI

- 没有可信的公共基准来衡量创作者交易谈判结果。永远不要编造或引用一个。
- 记录每个交易：要求的条款、赢得的条款、让步、每个条款的最终与初始，从积极回复到签署的天数。
- 几笔交易后，用户自己的历史是基准：让步模式、总是滑落的条款、现实的签名到签署天数。
- 如果你的框架具有持久内存，请跨会话保留交易日志；否则，将表格交给用户维护。

## 常见失败模式

| 失败                                               | 解决方法                                                                                                                     |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 在定义范围之前协商费率                              | 首先锁定交付物清单；每次费率讨论都参考固定的范围                                        |
| 将使用权视为赠品                                   | 将其作为单独条款定价 - 时长、自然流量与付费流量、地域 - 这是一个高价值条款                      |
| 无限期的排他性                                     | 设定时间限制，限制为指定竞争对手，按期收取扩展费用                                                 |
| 无限次的修改轮次                                 | 书面文件中设定包含的轮次；定义次要修改与主要修改；超出上限的轮次定价                                     |
| 范围蔓延而不重新定价                               | 承认新增交付物，明确命名，立即附加修订价格                             |
| 接受永久使用条款                                   | 替换为限定时长的许可，并预先约定续费定价                                                       |
| 排他性超出使用窗口                                 | 在合同中协调两个期限，以便旧的付费内容不能无声地延长封锁期                          |
| 强加净60/90付款条款                               | 该领域最糟糕的失败 - 迟付款明显会损害创作者关系；承诺净30或更好                              |
| 不同内部团队报价不同数字                           | 在接触外部之前设定一个内部定价权威；不一致会破坏谈判信誉                         |
| 将信息披露视为可交易                              | 它是一个门槛 - 对方或同事提出交易就会触发放弃脚本                           |
| 从重复意向关系中一次性提取价值                     | 将条款视为重复交易的首次行动；第二次合作通常优于第一次               |
