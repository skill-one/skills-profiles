# 合作伙伴绩效

定义B2B合作伙伴计划如何衡量和评估单个合作伙伴：合作伙伴个人评分卡、评估频率和合作伙伴QBR，以及表现不佳阶梯。不存在单一的规范合作伙伴绩效方法论——直截了当地说，而不是编造一个。该领域真正为合作伙伴个人衡量提供的：

- **五类参与分类法**：销售绩效、合作伙伴满意度、培训/认证完成度、市场/线索生成、合作伙伴生命周期和留存。未在任何地方公布数值权重——由用户自行设定。证据类别：供应商博客。
- **成熟度分阶段的KPI分类法**：招募→激活→参与→收入效率，优先考虑计划成熟度而不是固定权重。证据类别：供应商分类法。
- **持续分级**：从CRM、LMS和门户数据重新计算合作伙伴分数，对合作伙伴可见，并带有风险标志，在降级前触发辅导。证据类别：供应商产品模型。
- **四步合作伙伴归因旅程**——将价值归因于包括非交易合作伙伴在内的合作伙伴——关于归因，而不是个人合作伙伴评分卡。在评分卡的收入维度上游使用它作为输入。证据类别：分析师博客。

这四个是证据输入，而不是选择菜单——用户实际的选择是评分卡方法，在“使用户设计系统”下排名。每个模型都以其原始供应商或分析师命名，在[references/scorecard-design.md](references/scorecard-design.md)；上述概念是实际应用技能。保持这种方式——PRM供应商经常重新品牌和重组，所以围绕今天的产品名称编写的文档比其中的思想更快过时。

## 面谈

在设计和任何东西之前提问。每条消息一个问题；提供多个选择；跳过用户已经回答的内容。

- 有多少合作伙伴，以及哪些类型——分销商、VAR/MSP、代理商、SI、ISV/技术、推荐商、分销商？哪些类型实际交易？
- 今天衡量什么，以及数据在哪里——CRM、PRM、LMS、电子表格、无处可寻？
- 合作伙伴目前是否看到自己的数字？
- 今天的评估频率是什么，以及是否因级别而异？
- “表现不佳”今天意味着什么——以及当合作伙伴达到它时是否实际发生什么？
- 大约有多少合作伙伴收入是来源还是影响——以及您的系统能否区分两者？
- 当前的评估文化：QBR是一个工作会还是状态更新？
- 有多少合作伙伴经理（PAM），以及覆盖率是多少——每个经理的合作伙伴数？
- 这是仅限B2B渠道，还是计划也包括联盟/创作者合作伙伴？
- 什么是不可移动的：已签署的合作伙伴协议、财政日历、现有的级别承诺？
- 谁签字：渠道负责人、CRO、财务、法律？
- 到什么日期必须实际落地第一个评分评估——在当前评估周期内、下个财政年度、无固定日期？在当前周期内设置日期会促进加权复合，并推迟计划合作伙伴组合不做的一切。
- 这是一个一次性练习——一个董事会或QBR问题，你必须回答一次——还是一个每季度运行的系统？一次性练习停在复合；复合系统证明领先/滞后分割和每类型跟踪，这些只有在重复评估中才能得到回报。
- 努力上限：合作伙伴运营小时数可用，是否任何人都可以导出门户、LMS和交易注册数据，以及设计在合作伙伴看到后是否仍可更改？没有导出能力会从此设计中删除领先/滞后分割，而不是推迟；一个合作伙伴已经看到的评分卡接近不可逆转，所以在社交化它之前确定维度列表。

最后三个答案会重新排序下一节的设 计选项——在提出任何东西之前提问，而不是在展示菜单时。

## 工作流

1. 运行面谈；收集设计依赖的每个当前状态事实。
2. 确认范围：在一个运行的计划中衡量和评估单个合作伙伴。级别设计、计划设计、单个合作伙伴经济和构建联合GTM计划属于兄弟技能（见参考）——此技能根据联合计划评估绩效，它从不构建一个。
3. 清点数据：标记每个候选指标可计算今天、需要工作才能计算或无法衡量。从不基于估计进行评分。
4. 从“使用户设计系统”中按排名的级别选择评分卡方法，然后设计它：维度与权重、每个KPI目标和红色标志底部、测量窗口、数据源和所有者——为每个合作伙伴类型（包括非交易类型）提供一个跟踪。见[references/scorecard-design.md](references/scorecard-design.md)。
5. 设置重新计算频率和合作伙伴可见性——合作伙伴看到什么，以及何时看到。
6. 设计按级别和合作伙伴QBR的评估频率。见[references/review-cadence-and-qbr.md](references/review-cadence-and-qbr.md)。
7. 设计表现不佳阶梯：触发→干预→纠正行动→降级/退出。将任何可以降级或终止的内容通过法律路由。见[references/underperformance-ladder.md](references/underperformance-ladder.md)。
8. 根据该节进行验证：逐节展示规范，并在编写下一节之前通过每个。
9. 用真实合作伙伴试运行草稿评分卡；检查分数分布和PAM工作量所隐含的内容；调整。
10. 检查通过阈值；迭代直到每个检查都成立。
11. 在用户的明确批准之前停止在完整规范上批准——不要在没有用户明确批准完整规范的情况下最终确定任何东西。
12. 如果您的连接具有持久内存，请记住批准的评分卡、阈值和第一个评估日期；否则告诉用户将规范存储在合作伙伴运营可以检索的地方。

- 如果您可以浏览网页，请在向用户引用供应商模型之前验证它；归因及其日期在[references/scorecard-design.md](references/scorecard-design.md)。
- 否则，将供应商示例标记为可能已过时。

## 使用用户设计系统

按照渠道团队实际工作的方式运行设计——通过合作伙伴运营建模和利益相关者审查，而不是作为单独的电子表格练习：

- 在整个过程中每个消息问一个问题；从不批量提问。
- 汇总渠道团队带来的数据：来源与影响收入的分割、交易注册记录、认证/LMS完成度、门户参与、PSAT/NPS、MDF利用率。用现有数据建模；命名缺失的内容。
- 映射必须参与的人员：渠道负责人负责，合作伙伴运营构建模型，财务验证数字，PAM必须能够运行它，法律审查任何可能触发降级或终止的内容。
- 按给定的排名顺序展示下面的三个候选评分卡方法，并附上您的推荐及其原因。它们是阶梯，不是竞争对手——每个都叠加在前一个之前。
- 一旦用户选择了一个阶梯，逐节展示规范——评分卡，然后频率和QBR，然后阶梯——并在编写下一节之前验证每个。
- 在推出前与合作伙伴咨询委员会或试点队列社交化近最终设计；合作伙伴从未看到的测量系统会产生争议，而不是绩效。
- 在最终确定上依赖用户明确批准组装的规范。

### 排名评分卡方法

按每个方法每小时的合作伙伴运营构建时间解决什么来排名。这是通过阈值5——“PAM可以在他们实际拥有的时间内准备评分卡”——应用于设计工作以及评估准备。

- 效率：加权复合>领先/滞后分割>每类型合作伙伴跟踪
- 价值：加权复合>每类型合作伙伴跟踪>领先/滞后分割
- 努力程度：每类型合作伙伴跟踪>领先/滞后分割>加权复合

1. **加权复合**——4-6个维度，每个合作伙伴一个数字。解决筛选决策：哪些合作伙伴在本季度获得PAM的小时数。定义成本约一周的合作伙伴运营工作，之后每评估近零成本，并且它运行在大多数计划已经持有的CRM/PRM数据上。在合作伙伴看到它之前完全可逆。
2. **领先/滞后分割**——一个结果分数旁边是一个早期指标分数。解决时间决策：现在干预，还是等一个季度。当复合已经携带管道、参与或认证维度时，几乎零工作量——标记每个维度并总计。当门户、LMS或交易注册数据无法导出时，需要四分之一的时间进行管道，并且该情况使其低于复合。
3. **每类型合作伙伴跟踪**——每个合作伙伴类型一个维度集。解决覆盖决策：非交易合作伙伴是否赚取其投资，这是一个单一复合无法用空白回答的问题。定义成本每类型一周，每个都有自己的数据源和协商目标，然后成为一个常规工作，随着合作伙伴类型的增加而增加。

每类型合作伙伴跟踪是此效率顺序所剥夺的：价值第二，努力程度第一，比率最后。一个仅计算效率分数的计划很好地为其交易分销商，而将其ISV、推荐商和顾问合作伙伴留在复合中，复合看起来像空白。一旦计划包含非交易合作伙伴类型，立即将阶梯3提升到阶梯2——通过阈值3要求它有一个真实的分数，并且没有任何复合调整可以产生一个。

默认值和移动它们的内容：

- 每个计划从阶梯1开始；一旦领先数据导出干净，就添加阶梯2。
- 一个只有一个合作伙伴类型的计划从设计中删除阶梯3，并且规范将其列为删除，并说明原因——列为“稍后”的跟踪重新出现为没有人范围的建设。
- 一个无法导出门户、LMS或交易注册数据，并且没有能力构建该管道的计划以相同的方式删除阶梯2——只有在导出存在时才重新审视它。

顺序是一个默认值，不是一个法律：它随着上下文和执行者的变化而变化。根据面谈已经告诉您的重新排名它：

- 一个已经报告领先指标的PRM使阶梯2几乎免费，并提升它高于进一步的复合调整。
- 一个没有分析师支持的合作伙伴经理应该发送阶梯1而不是一个三轨道设计，没有人可以在下个季度重新计算。
- 当前周期内设置硬日期会促进今天可计算的任何东西，而不是更好的东西。

## 合作伙伴绩效系统

交付此工件作为参与——用户交给合作伙伴运营、PAM和法律：

```
合作伙伴绩效系统 , <计划>, <日期>
评分卡：
  维度       : 每个都有权重；权重总和为100%
  每个KPI     : 定义+目标+红色标志底部+测量窗口
                 +数据源+所有者
  跟踪       : 每个合作伙伴类型一个，包括非交易
                 (ISV/技术、推荐商、顾问/SI)
  重新计算    : 连续|每月|每季度，以及谁重新计算
  合作伙伴可见性: 每个合作伙伴看到什么，以及何时
评估：
  按级别频率  : 哪些合作伙伴获得完整的QBR，哪些获得较轻
                 检查；持续时间和与会者（用户的设 计决策）
  QBR议程     : 部分，以最后一个季度的行动检查开头，
                 以联合行动计划结尾
  行动跟踪     : 所有权在哪里，日期行动在评估之间存在
表现不佳阶梯：
  触发         : 触发→干预→时间表
  升级链       : 每个步骤命名角色
  纠正计划     : 形状、持续时间、检查点、声明后果
  降级/退出   : 标准，在记录的纠正行动失败后通过
                 法律审查
系统KPIs        : 如何评估测量系统本身，以及第一个评估日期
```

规范本身的规则：

- 将数据源和命名所有者附加到每个KPI——没有人计算的指标审查没有人。
- 将每个目标与红色标志底部配对；一个单独的目标隐藏衰减，直到它成为一个危机。
- 拒绝任何合作伙伴可以自我报告或游戏的指标；仅使用程序本身记录的数据。
- 将持续时间、与会者列表、阈值和时间线作为用户的设计决策呈现，它们是自我设置的，不是行业规范。

## 通过阈值

在所有五个都成立之前不要发送任何东西；迭代设计直到它们成立：

1. **每个KPI都完全规范**：目标、红色标志底部、测量窗口、命名数据源、命名所有者。
2. **没有任何东西是自我报告或可游戏的**——每个评分卡输入都来自程序记录和可以在争议中辩护的数据。
3. **每个非交易合作伙伴类型都可以评分**，而不需要转售收入——ISV、推荐商或顾问合作伙伴得到一个真实分数，而不是空白。
4. **每个评估都以拥有的、日期的行动结束**——并且下一个评估通过检查它们开始。
5. **PAM可以在他们实际拥有的时间内准备评分卡**——测试准备工作量与面谈的覆盖比率。

| 症状                                               | 首先检查                                                                                                   | 故障的设计变量              |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 上季度的操作从未完成                                  | QBR是否以先前的操作检查开始，以及操作在审查之间如何存储                                                                   | 操作跟踪循环                  |
| QBR是单向状态更新                                   | 是否发出数据预读，以及议程中前瞻性部分的比例                                                                     | QBR议程和预读纪律            |
| 每个合作伙伴都得到相同的审查，无论规模如何             | 是否节奏和深度按级别变化                                                                                   | 节奏分层                      |
| 合作伙伴对数字提出异议                              | 合作伙伴是否在会议前看到相同的数据，以及哪个系统是事实来源                                                              | 数据源和合作伙伴可见性        |
| 评分卡显示绿色，但合作伙伴保持沉默                   | 是否有任何领先指标（门户登录、交易注册、认证活动）在评分卡上                                                              | 维度组合 - 仅滞后            |
| 只有交易合作伙伴有评分                              | 是否为ISV/推荐/顾问合作伙伴存在每类型跟踪                                                                    | 评分卡跟踪                      |
| 从未被降级                                         | 是否梯级触发器有所有者和时间表，以及存在哪些法律障碍                                                              | 梯级执行，而不是评分卡        |

## KPIs

评估测量系统，而不是合作伙伴 - 单个合作伙伴的数字是系统的输入，而不是其分数：

在没有人提供分析师支持的情况下按此顺序进行指标化 - 前三项是程序已经记录的计数，最后两项需要一年的梯级历史或合作伙伴调查：

- 效率：审查完成率 > 操作项完成率 > 拥有当前评分卡的合作伙伴比例 > 争议率 > 梯级及时性 > 梯级结果 > 审查过程PSAT

1. 按级别对计划节奏的审查完成率。
2. 审查之间的操作项完成率。
3. 拥有可计算的当前评分卡的合作伙伴比例。
4. 合作伙伴提出的评分卡数字争议率。
5. 被标记为红色的合作伙伴在规定时间内进入梯级的比例。
6. 梯级结果：在纠正措施后恢复的比例与降级或退出相比。
7. 合作伙伴对审查过程本身的满意度（PSAT/NPS）。

这个顺序使梯级结果受饿：它是唯一一个说明低绩效梯级是否起作用的数量，并且它需要一年的梯级历史才能完全读取，所以比率每个季度都会被程序已经持有的计数埋没。在您面前审查是关于是否保留梯级，或者降级正在被争议时，提升它。在程序没有梯级历史和没有调查能力的情况下，从仪器计划中删除第6和第7行，并将它们命名为已删除 - 作为待定指标携带，它们让后来的读者假设梯级被评估了。

## B2B与B2C

在两个世界中都是相同的：

- 每个指标都带有目标和红色警告底线。
- 指标组合混合了领先和滞后指标。
- 没有任何自我报告。
- 每次审查都产生拥有的操作。

不同之处在于：

- **B2B渠道**：人工审查，基于关系 - 每个合作伙伴的评分卡，PAM运行的QBR，分阶段的人工梯级。
- **B2C联盟/创作者**：自动仪表板，群体级审查，自动再参与 - 仅对分销头进行每个合作伙伴的审查。

有关完整对比及其证据限制，请参阅 [references/b2b-vs-b2c-contrast.md](references/b2b-vs-b2c-contrast.md)。
