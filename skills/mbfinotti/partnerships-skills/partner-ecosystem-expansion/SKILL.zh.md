# 合作伙伴生态系统扩展

规划下一步要添加哪些类别的合作伙伴以及按什么顺序，作为一个分阶段的路线图，并设置关卡。

在考虑任何其他事情之前，诚实地说明证据：

- 没有经过同行评审的最优合作伙伴类别顺序。
- 大多数发表的关于此决策的“框架”都是借用战略网格强行套用在渠道上。
- 几乎每个引用的基准都来自在数字看起来好的时候就能获利的供应商或顾问。

证据真正支持的内容：

- **Adner的最小可行生态系统（MVE）+分阶段扩展+价值蓝图**（《广角镜头》；《赢得正确的游戏》）——唯一一个为这个问题设计的框架：证明能体现联合价值的最小合作伙伴配置，然后按 deliberate 的顺序添加类别，以证据为关卡。
- **联盟组合多样性倒U型**（Jiang, Tao & Santoro 2010, 《SMJ》；Lee等人2017年元分析）——该领域的唯一独立证据：合作伙伴类型多样性在达到一定程度之前有助于公司绩效，然后协调和管理成本占主导地位。它主张约束和顺序；它没有规定顺序。
- **运营覆盖/能力数学和阶段关卡试点**——无品牌，但实际的工作方法：以能力而非热情为每个类别设置关卡。

McBain/Canalys的渠道三分法提供类别分类法（永远不会是顺序），Moore的整体产品/保龄球馆部分转移。当用户带来一个强行套用时，命名并拒绝：Ansoff应用于渠道，McKinsey三个视野，BCG增长份额，Iansiti & Levien用于类别选择。参见[references/sequencing-frameworks.md](references/sequencing-frameworks.md)。

这项技能是按类别排序，而不是按公司名称排序。相关的决策存在于兄弟技能中：

- 排名命名候选人：`mbfinotti/partnerships-skills@alliance-prioritization`
- 映射当前生态系统：`mbfinotti/partnerships-skills@partner-ecosystem`
- 项目结构（层级、利益、要求）：`mbfinotti/partnerships-skills@partner-channel-program`

## 面试

在排序任何东西之前先提问。每条消息一个问题；提供多个选择；跳过用户已经回答的内容。

- B2B、B2C还是混合？你卖什么，卖给谁，价格范围是多少，通过什么方式？
- 当前生态系统形状：哪些合作伙伴类别目前是活跃的，每个类别有多少合作伙伴，实际活跃的比例是多少？（来自映射兄弟技能的生态系统地图是理想的输入。）
- 哪个现有类别是经过验证的——可重复的联合胜利，而不仅仅是签约？任何类别仍然是半建成的桩？
- 产品准备情况：API成熟度和多租户，认证/培训内容，交易注册，利润结构，支持模式，合同——哪些今天存在，哪些仍在路线图中？
- 内部能力：合作伙伴经理及其当前工作量，赋能内容带宽，工具，项目预算？
- 买家实际如何购买——自助服务，销售引导，通过实施者，通过零售或市场？
- 扩张的目标：覆盖某个细分市场/地域/旅程阶段，整体产品差距，新Logo管道，保留/扩张，利润捕获？
- 今天与目标的地理和细分市场覆盖情况？
- 预算和批准：谁资助这个，谁批准，以及它必须落在哪个规划周期中？
- 路线图的时间范围——12、24或36个月？

三个答案在开始任何排序之前重新排序类别顺序——在这里提问，而不是在排名旁边提问：

- **必须在什么日期之前得到第一个结果？** 一个硬性的近期日期会促进快速作用的类别（推荐/联盟，创作者，代理商），并从第一阶段删除那些工作任务的类别——第一个收入在日期之后到达的类别不能是第一阶段，无论其比例如何。
- **一次性胜利，还是复合资产？** 复合会促进技术/ISV以及它使后来变得便宜的那些类别（市场，MSP）；一次性会促进推荐/联盟，创作者和联合品牌，并降低那些仅在多年后才收回成本的类别。
- **努力上限**——小时数，人数，政治资本，可逆性？一个低于一个站立工作的上限会直接删除MSP、SI/GSI、经销商、零售商和分销商；一个包含现有服务部门的上限会提升SI/GSI到最前面。

## 工作流程

在任何存在真实选择的地方——候选人库、顺序、关卡阈值、容量线在哪里——提供2-3个候选方法，包括权衡和你的建议，然后等待。永远不要让一个假设硬化成未说明的路线图。

1. 运行面试。确认输入是一个当前生态系统的画面（地图，或诚实的混合描述）。没有画面 → 路由到生态系统映射的兄弟技能首先。
2. 前面说明证据立场：路线图是一个有理由的、设关的赌注，而不是一个经过验证的公式——并且每个使用的基准都将带有来源标志。
3. 定义MVE：能产生足够价值证据的最小合作伙伴配置，以吸引下一个类别。如果当前动作还不是具有可重复联合胜利的MVE，诚实的路线图的第一阶段是完成它，而不是添加。
4. 运行ego系统检查：从客户的角度起草价值蓝图，而不是从你自己的角度。一个假定你自己的中心性的顺序（Adner的ego系统陷阱）会招募没有理由出现的类别。
5. 从三分桶（影响、交易、保留和交付）构建候选池——加上相关的B2C词汇，以及每个类别将关闭的整体产品差距。参见[references/partner-category-economics.md](references/partner-category-economics.md)。
6. 在排序之前固定容量数字：合作伙伴经理与合作伙伴的比例，赋能带宽，预算。这些限制路线图；没有它们的排序是一个愿望清单。
7. 评分每个候选类别的准备情况和经济效益：商业模型，相对时间到第一个收入，建立工作的努力，站立负载，合规风险，满足的先决条件与缺失的。参见[references/readiness-and-capacity-gates.md](references/readiness-and-capacity-gates.md)。
8. 按效率排名候选池：每单位努力的价值回报，而不是按最便宜排序。使用排序和[references/partner-category-economics.md](references/partner-category-economics.md)中的每个轴线，然后根据这个用户重新排名：他们上面的三个面试答案，一个现有的服务部门，一个不需要实施的产品，一个只有一人的合作伙伴团队。删除用户约束排除的每个类别，并说明原因；它将进入“现在不考虑”并带有重新进入触发器。大声说出顺序，并说出它会剥夺什么。从重新排名的池中起草2-3个候选顺序，包括权衡和你的建议。
9. 在提出自己的建议顺序之前，论证反对它（工作流程步骤9）——另一个类别的倒U型成本，它造成的冲突，它从已证明的动作中窃取的容量。
10. 为每个阶段附加关卡：试点队列形状，合作伙伴市场匹配阈值（可重复的联合胜利），明确的淘汰标准。关卡基于证据，而不是仅基于日历日期。
11. 为任何与现有路线重叠的类别预先检查渠道冲突（直接或另一个合作伙伴类别）。在这里检测和衡量它；制定参与规则属于`mbfinotti/partnerships-skills@partner-channel-conflict`——但在规则存在之前安排启动是一个路线图缺陷。
12. 每个阶段都作为资本请求进行成本核算：总负载成本（人数，赋能建设，激励，工具，项目支出），而不是单独的人数，并命名资金机制。
13. 运行下面的头脑风暴纪律；逐段呈现路线图，并在起草下一部分之前验证每个部分。要求明确批准组装的路线图，然后才能最终确定。
14. 检查通过阈值；迭代顺序、关卡或容量假设，直到每个检查都成立。
15. 设置审查节奏和重新排序触发器：关卡结果，类别的激活崩溃，产品准备延迟，冲突事件，市场变化。路线图是一个持续的假设，设定下次审查的日期。
16. 如果你的套件具有持久内存，记住批准的路线图——顺序，每个阶段的关卡和淘汰标准，以及容量数字——以便在后续运行（关卡审查，重新排序）时从它们开始，而不是重新采访。
17. 如果你能够浏览网页，在最终确定之前验证计划依赖的时间敏感事实（市场政策，候选类别的结构经济）——否则将它们标记为用户提供的未验证信息。

## 头脑风暴顺序

在起草任何路线图之前进入头脑风暴模式——永远不要以一个完成的顺序开始。使用该行业的格式运行，而不是通用的创意。

五个按效率排名的[references/expansion-workshops.md](references/expansion-workshops.md)中——`map re-read > value blueprint > account mapping > partner persona > business-design workshop`——以及它们的问题集和背后的轴线。从顶部开始，与用户确认格式，并在候选池停止变化时停止；顺序会随着现有数据的改变而改变。

- 每条消息一个问题，总是；从不批量。
- 每个真实选择都得到2-3个候选方法，包括权衡和你的建议——然后等待用户。
- 大声说出假设，在它们硬化之前：哪个类别房间已经想要，哪个准备声明没有人验证，哪个容量数字是一个猜测。
- 在提出自己的建议顺序之前，论证反对它（工作流程步骤9）——对类别的热情是这种练习欺骗自己的记录方式。
- 分段呈现交付成果——当前基础，候选池，容量，顺序，关卡，成本——每个部分在起草下一个部分之前都经过验证。
- 在最终确定上依赖用户的明确批准，以组装路线图。

容量        : 经理比例，赋能带宽，预算  -  限制计划的数字

## 通过阈值

在所有这些都成立之前不要发送任何东西；迭代直到它们成立：

1. **一次只开放一个阶段。** 每个阶段只有在通过前一个阶段关卡时才开放；最多两个并行，并且只有在它们共享赋能基础设施时才明确说明。
2. **基于证据，而非日历。** 每个关卡都命名打开它的证据——可重复的联合胜利，激活，来源管道——而不是单独的日期。
3. **容量一致。** 阶段负载总和（经理时间，赋能建设，预算）适合声明的容量数字。
4. **每个阶段都有淘汰标准** —— 至少有一个激活底线，一个首次交易窗口，以及连续两个错过季度的规则。
5. **每个基准都标记。** 每个引用的数字都带有其来源标志（供应商，供应商委托，分析师，顾问，学术）；未标记的数字是缺陷。
6. **至少一个类别被推迟或拒绝**，带有重新进入触发器。一个添加了所有排序的路线图什么也没做。
7. **冲突预先检查** 每个与现有路线重叠的类别，并命名该类别启动阶段前所需的规则。

## KPI

按组对每个添加的类别进行评估，对照其关卡——以及路线图是否其关卡有效。按效率顺序进行仪器——关卡决定按单位测量努力解决——并在关卡可以读取时停止：

- 每个新类别的合作伙伴激活率（至少一年内有一个已关闭交易的签约合作伙伴），对照关卡的底线。
- 每个类别的首次交易时间，对照关卡设置的预期窗口。
- 每个类别的合作伙伴来源和合作伙伴影响的管道（B2B）或增量归因收入（B2C），按组。
- 在boarding窗口内完成赋能/认证，按组。
- 类别随时间推移的新收入份额——被该顺序剥夺（一年前的组才会说任何东西），并且在审查是资金决策而不是阶段关卡时提升。
- 关卡存活率：通过关卡的试点类别比例，而不是被淘汰或重新范围——100%表明软关卡，0%表明候选池有问题。
- 倒U型监测：协调成本上升而总来源收入趋于平稳，随着类别的积累——停止添加并深入的证据信号。

完整指标定义和已发表数据，带有来源标志：[references/kpis-and-benchmarks.md](references/kpis-and-benchmarks.md)。

## B2B和B2C

在两边真正相同，所以使用相同的方法，而不是重新发明它：

- 覆盖/增量分析来决定哪个类别填补差距。
- MVE和试点然后扩展纪律。
- 渠道冲突和蚕食作为当新类别与现有路线重叠时的中心治理风险。
- 合作伙伴经济作为排序关卡。
- 过多的重叠类别产生成本和噪音的倒U型逻辑。

一个DTC品牌按价值每单位努力对创作者、市场和批发进行排名，与SaaS供应商按ISV、代理商和MSP进行排名，具有相同的类别组合逻辑。两种效率顺序都存在于[references/partner-category-economics.md](references/partner-category-economics.md)中。

真正改变的是：

| 维度                    | B2B tech/SaaS                                                     | B2C/consumer                                                                         |
| ---------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 类别词汇          | ISV, VAR, MSP, SI/GSI, 代理商, 推荐, 分销商, 市场                 | 零售/批发, 分销商, 联盟, 创作者/影响者, 许可, 联合品牌                             |
| 效率顺序的头部 | 技术/ISV，然后推荐/联盟                                           | 创作者/影响者，然后联盟                                                           |
| 排序驱动            | 产品准备，覆盖差距，买家路线                                     | 增量（在意图之前覆盖买家）和利润捕获                                                   |
| 归因                  | 交易注册，账户映射，共同销售                                      | 代码，联盟链接，最后点击                                                           |
| 主要风险                | 赋能延迟；与直接销售的冲突                                        | DTC与零售与市场蚕食                                                               |

## 失败模式

| 失败                                                                                      | 解决方案                                                                                                                                                              |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自我中心陷阱 - 该流程假定合作伙伴将围绕你运行                              | 从客户的角度制定蓝图；验证每个类别的当前加入理由                                                                                |
| 在赋能之前进行招募 - 该领域最常见的失败                                      | 在招募前设置能力门槛；激活率低于约20%就意味着停止招募，而不是更加努力地招募                                                              |
| 对一个类别过度关注，从而削减其他类别（耐克/阿迪达斯的模式）                | 将类别的削减视为与增加同等的高风险；在缩减路线之前，评估冲突和依赖关系的大小                                                           |
| 类别蔓延，然后被迫修剪（HubSpot 机构徽章模式）                      | 删除标准加上延迟列表；关注倒U型信号                                                                                              |
| 过早的多元化 - 在证明第一类别之前就推出第二类别                       | MVE门槛：可重复的联合胜利优先；诚实的阶段1可能是“完成当前动作”                                                                     |
| 最便宜类别优先，被误认为是最高效的类别                                 | 按单位努力的价值进行排序：推荐是最便宜的级别，但购买力最低，而ISV行动成本为四分之一，并使后来的三个类别更便宜                                             |
| 被排除的类别被停放在排名的底部                                          | 将其及其原因从池中删除；它属于“现在不考虑”类别，并带有重新进入触发器，而不是在可以重新向上阅读的最响亮的赞助商列表中                               |
| 借用的策略网格被呈现为方法（安索夫、三个视野、BCG、Iansiti-Levien） | 如果它有助于会议，就将其保留为词汇；在MVE + 门槛 + 能力的基础上重新制定决策                                                               |
| 按日历划分的阶段 - “SI计划将在第三季度启动”，无论是否有证据                   | 门槛基于证据触发；日期是预测，不是触发器                                                                                              |
| 引用供应商基准作为证据                                                            | 每个数字都有来源标记；供应商数据仅提供方向性背景                                                                                     |
| 路线图偏离到以公司名称命名的排名中                                                  | 类别仅；将命名候选者交给 `mbfinotti/partnerships-skills@alliance-prioritization`                                                              |
