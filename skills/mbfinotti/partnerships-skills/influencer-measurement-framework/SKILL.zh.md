# 影响者衡量框架

设计如何在推广活动启动前衡量一个影响者/创作者活动，并交付一份衡量计划文档。计划本身，而不是仪表盘或报告，才是成果：它固定了关键绩效指标（KPI）、归因方法、数据来源、周期和盲点，以便在活动结束后确定结果，而不是事后临时决定。

影响者衡量没有全面、具有基准标准的规范支撑。要明确地告知用户，并且永远不要将一个品牌框架呈现为行业标准。

该方法仅借鉴真正建立起来的部分：

- **ANA 影响者营销衡量指南**（2022年6月，MRC认可）：仅标准化定义，没有基准数据。
- **AMEC 巴塞罗那原则**（3.0版 2020年7月，2025年6月重申4.0版）：原则5，“AVEs 并非传播的价值”。
- **MRC 可见性标准**：50%的像素，1秒显示/2秒视频；大多数有机平台指标无法满足。
- **IAB Tech Lab 播客衡量技术指南 v2.2**（2024年5月2日）：用于播客/新闻简报赞助。
- **通过地理提升/合成控制实现的增量性**（Meta的开源GeoLift包，Google的CausalImpact）：与最小可检测效应（MDE）功率检查配合使用。

## 基本规则

- 将主要KPI与活动目标对应的漏斗阶段匹配。优化认知活动指标或反之，是实践中最常被引用的错误。
- 为每个KPI提供一个定义，说明分子、分母和窗口。无法重新计算的指标只是装饰。
- 选择一个互动率分母和一个归因窗口；在整个活动中保持两者不变，并在术语表中标记它们。
- 永远不要将EMV、MIV或任何AVE衍生指标报告为ROI或财务价值——相对的、同供应商方向性比较才是它们唯一合法的使用方式。
- 永远不要采用供应商基准作为目标。目标来自项目自身的滞后历史，或者计划诚实地说明“首次飞行 - 无目标，基线设定运行”。
- 永远不要使用“每1美元5.78美元”（或其变体）作为计划输入——这是一个具有薄弱、不一致来源的供应商基准。
- 三重归因：没有单一方法是可靠的。代码泄露、链接被移除、像素信号丢失、调查记忆错误——每个方法都覆盖了另一个方法的盲点。
- 为计划中引用的每个数字添加来源标签：标准机构定义、平台发布、供应商来源、单一从业者声明或品牌自身历史。

## 面谈

在设计和开发任何东西之前进行面谈。每条消息一个问题；尽可能使用多项选择；跳过已回答的问题。

- 活动目标和漏斗阶段：认知/触达、考虑/互动、转化/表现、联盟链接或始终如一的大使？
- B2B还是B2C？（这决定了收入目标、窗口长度以及哪些归因信号存在）
- 预算和项目规模：总支出、创作者数量、单次飞行或始终如一？
- 涉及哪些平台？（短视频、图片/社交、长视频、直播、播客、新闻简报——每个平台都有不同的数据访问方式）
- 每个创作者的交付类型？（帖子、故事、视频、直播、播客阅读、新闻简报位置）
- 实际存在的跟踪能力有哪些：唯一促销代码、UTM标记链接、联盟网络、平台像素/购物、购买后调查、CRM“您是如何了解到我们的”字段？（多选；“无”是有效答案）
- 是否存在预发布基线——品牌搜索量、直接流量、关注者和互动历史？如果没有，是否有时间在发布前捕捉一个？
- 谁会阅读报告，以及它将推动什么决策？（续签创作者、重新分配预算、向财务证明渠道可行性、创意学习）
- 预期的报告频率和发布者是什么？
- 合同中包含哪些创作者侧分析访问权限：API/帐户连接、平台合作伙伴工具、或仅截图？
- 必须在什么日期前提交结果，以及等待什么决策？（硬日期会促进近零设置的步骤——代码、UTM、品牌搜索代理——并排除地理提升和面板品牌提升研究，这些研究在决策已做出后才报告）
- 这次飞行是一次性读数，还是可重复使用的衡量资产？复合效应会促进购买后调查、联盟网络和可重复使用的地理设计——每个设计一次成本，之后每次飞行都会受益。一次性保持代码+UTM+基线代理的堆栈。

## 工作流程

1. 运行面谈；收集计划依赖的每个答案。
2. 确定目标，然后从[references/kpi-definitions.md](references/kpi-definitions.md)中选择与该目标对应的主要KPI集——主要、次要、警戒线。拒绝来自错误漏斗阶段的KPI；解释原因而不是服从。
3. 在做任何其他事情之前编写指标术语表：每个KPI一个句子的定义，所选的互动率分母、归因窗口和每个平台的可见性定义。平台“可见性”定义在2025-2026年发生了实质性变化，因此需要日期标记；如果你可以浏览网页，请验证当前平台的定义——否则将其标记为“截至计划日期，重新验证”。
4. 将每个KPI映射到面谈确认存在的归因方法和数据源，使用[references/attribution-and-data-sources.md](references/attribution-and-data-sources.md)。删除或标记任何没有可行来源的KPI——由品牌缺乏的能力支持的KPI是虚构的。
5. 按效率顺序组装归因堆栈：每小时投入的覆盖率和置信度，而不是每个方法的表面严谨性。默认顺序：

   a. 唯一促销代码和UTM标记链接一起：每个创作者每天从第一天开始，每个方法各需一小时。这对是底线；单一方法堆栈不是三角测量。
   b. 一个问题的购买后/注册后调查：一周时间通过谁拥有结账发送，之后几乎零成本，是唯一能看到暗社交的方法。
   c. 联盟网络链接：当平台已经上线时几乎为零，当它没有上线时是一个持续的工作任务，涉及合同和入职。
   d. 每个创作者的个性化URL：覆盖范围狭窄，播客和新闻简报位置上唯一存在的步骤。
   e. 平台像素/购物最后：工程和同意工作，为平台自我评估的失真信号。

   ```
   工作量：          像素 > 联盟网络 > 调查 > 个性化URL > 促销代码 == UTM链接
   覆盖率：          调查 > 联盟网络 > 促销代码 == UTM链接 > 像素 > 个性化URL
   合规成本：       像素 > 调查 > 联盟网络 > 促销代码 == UTM链接 == 个性化URL
   效率：           促销代码 == UTM链接 > 调查 > 联盟网络 > 个性化URL > 像素
   ```

   代码和链接并列，因为它们覆盖不同的切片：代码可以存活被截图或大声读出；标记链接不能。这个顺序是默认的，不是法律；它会随着品牌现有的堆栈和谁需要构建每个步骤而变化。

   根据面谈答案重新排序，并在计划中记录哪个答案移动了哪个步骤：

   - 一个已经运行的联盟平台会跳到步骤（a），增量工作量几乎为零。
   - 一个已经收集响应的结账调查已经处于步骤（a）。
   - 一个无法发出每个创作者唯一代码的商店会减少（a）的一半，并提升调查。
   - 一个播客或新闻简报飞行没有可用的步骤，但只有代码和个性化URL。

   在计划中记录每个方法的已知失败和代码泄露政策。

6. 捕获或安排预发布基线；如果发布先于捕获，则在计划中写入“无基线 - 活动后提升声明将不受支持”，而不是隐藏它。
7. 使用[references/incrementality-and-brand-lift.md](references/incrementality-and-brand-lift.md)决定测试设计。首先运行MDE功率检查：这是一个小时的分析师时间，它控制了它下面的每个步骤，以及这里没有替代方案的一个步骤。然后取功率检查和努力上限都允许的最高步骤：

   a. 品牌搜索和直接流量相对于预发布基线的移动：几乎零成本，相关性。它属于每个计划，包括受驱动计划，因为当测试失败时，这个系列仍然存在。
   b. 地理提升/合成控制：在没有用户级标识符的情况下可用的最强因果证据，以分析技能、一个季度的日历时间和政治资本为代价，以从真实市场中撤回渠道为代价。
   c. 平台转化提升保留：平台运行它，所以工作比（b）少，但它需要在该平台的广告支出，平台自我评估自己的作业。
   d. 平台运行的品牌提升研究：态度而不是行为，最低支出，1-4周的飞行中调查，同样的自我衡量冲突。
   e. 独立面板品牌提升：跨平台且无冲突，并且是一个持续的工作任务来委托。

   在上述（a）以上每个步骤的功率下，在计划中写入“方向性衡量仅”。

   ```
   工作量：            面板提升 > 地理提升 > 平台品牌提升 > 转化提升保留 > 搜索代理
   得出答案的时间：    面板提升 == 地理提升 > 平台品牌提升 == 转化提升保留 > 搜索代理
   证据强度：         地理提升 == 转化提升保留 > 面板提升 > 平台品牌提升 > 搜索代理
   合规成本：         面板提升 > 平台品牌提升 > 转化提升保留 > 地理提升 == 搜索代理
   效率：            搜索代理 > 地理提升 > 转化提升保留 > 平台品牌提升 > 面板提升
   ```

   默认步骤：（a）单独。地理提升和面板提升是这个顺序剥夺的：第一个购买可用的最强因果证据，第二个购买唯一无冲突的，两者都因每一轮输给一个成本为零的代理系列而失去。仅使用比率运行的计划永远不会产生因果数字。

   在这些条件下提升一个步骤：

   - 功率检查通过，并且报告驱动的决策是预算规模的：提升一个步骤，因为向财务证明渠道证明工作值得四分之一。
   - 声明必须存活销售媒体评估自己的工作：达到面板提升。
   - 决策是续签或创意学习：保持在（a）。

   这个顺序是默认的，不是法律。根据面谈答案重新排序：

   - 一个以认知为主的活动，没有转化量，完全跳过（b）和（c），因为品牌提升是衡量其目标的唯一工具。
   - 一个内部分析团队压缩（b）的工作量，并提升它高于（c）。
   - 一个不会在任何区域撤回渠道的品牌删除（b）和（c）而不是降级它们。

8. 根据利益相关者设置报告频率——每一行命名谁、多久一次、哪些指标、以及它推动的决策。不推动任何决策的报告将被删除。
9. 明确声明盲点：暗社交、曝光、UTM被移除、代码泄露、仅截图来源、平台定义变化跨越飞行窗口。
10. 在组装最终文档之前，逐部分用用户验证计划——术语表，然后KPI树，然后归因，然后测试设计，然后频率——基于[references/worked-examples.md](references/worked-examples.md)中匹配的工作示例。
11. 检查通过阈值；迭代直到每个标准都满足。
12. 如果你的框架具有持久内存，记住商定的指标定义、所选分母、归因窗口和派生的基线——之后的活动可以从它们开始，而不是重新谈判。否则将术语表交给用户，作为下一个活动的持续参考。

## 输出形状

以这个成果交付每个计划：

```
衡量计划 - <活动>, <日期>
标题      : 品牌、活动、目标+漏斗阶段、飞行日期、预算、平台、创作者
术语表    : 每个指标一个句子的定义（分子/分母/窗口）；所选的ER分母；归因窗口；每个平台的可见性定义，日期标记
KPI树    : 主要 | 次要 | 警戒线 - 每个KPI：定义参考、目标基础
             （内部滞后基线或“首次飞行 - 无”）、归因方法、数据来源
归因      : 使用的堆栈，每个方法的已知限制，代码泄露政策和监控
基线      : 捕获的预发布值（品牌搜索、直接流量、滞后ER中位数）
             或明确的“无基线”声明
测试设计  : 增量性/品牌提升与MDE+功率检查结果，或“方向性仅”+原因
频率      : 利益相关者 -> 频率 -> 显示的指标 -> 它推动的决策
数据来源  : 每个KPI - API / 广告管理器 / 联盟网络 / CRM / 调查 / 截图（标记）
盲点      : 声明的列表 - 该计划结构上无法看到的
待办事项  : 未确认的能力，要添加的合同条款，发布前的疑问
```

完整的工作示例位于[references/worked-examples.md](references/worked-examples.md)，永不内联。

## 通过阈值

计划仅在面谈中命名的利益相关者可以在活动结束时根据它做出其声明的决策，而不需要争论定义。具体来说，所有六个必须满足；迭代直到它们满足：

- 每个KPI的定义都可以被没有编写计划的人重新计算——分子、分母、窗口都声明。
- 主要KPI的漏斗阶段与活动目标的漏斗阶段匹配。
- 每个KPI都由面谈确认存在的归因方法和数据来源支持——零KPI依赖于希望拥有的能力。
- 基线状态是明确的：捕获、计划预发布，或声明不存在及其后果。
- 增量性或品牌提升仅在与通过功率检查一起出现；否则在计划中写入“方向性仅”。
- 零EMV/MIV/AVE衍生数字作为财务价值呈现，并且零供应商基准用作目标。

## B2B vs B2C

对两者都相同，无需修改：

- 术语表纪律。
- KPI与目标匹配。
- 三重测量。
- 基线捕获。
- 来源标记。
- 频率驱动决策规则。

真正不同的地方：

- **收入目标。** B2C衡量订单、AOV和活动窗口内的收入。B2B衡量受影响管道和机会——购买很少在活动期间发生。
- **周期长度和窗口。** B2C归因窗口运行几天到~30天；B2B周期运行数月，因此每次飞行的转化KPI低估，窗口必须延长或移动到管道阶段指标。
- **暗社交主导。** B2B创作者内容通过DM、社区和播客传播，这些播客移除所有跟踪；自我报告的“您是如何了解到我们的”（HDYHAU）在演示/注册表单上分析，在队列级别成为主要来源，而不是平分——品牌搜索量作为佐证代理。
- **受众规模和统计功效。** B2B创作者受众规模小；转化量几乎从不驱动增量性测试，因此B2B计划默认为三角测量+HDYHAU，并说明这一点。
- **调查位置。** B2C在结账时询问购买后；B2B在演示请求或注册表单上询问，并在销售电话上定性询问。

## 失败模式

| 缺陷                                                              | 后果                                                                                     | 修复                                                                                        |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 崇拜虚荣指标（触达、点赞、粉丝数作为标题）                         | 报告看起来很忙；决策者什么也学不到                                               | 主要KPI必须与目标匹配并驱动命名决策；将计数降级为背景信息                                       |
| EMV/MIV/AVE报告为ROI                                             | 财务发现数字是虚构的；整个项目失去信誉                                             | 巴塞罗那原则5；仅进行同供应商方向比较，绝不进行财务价值比较                                     |
| 最后点击作为唯一的转化透镜                                          | 上游内容创作者结构性地被低估；项目看起来比实际情况更糟                               | 通过调查+代码进行三角测量；并列报告基于点击的归因和基于调查的归因                               |
| 启动前未捕获基线                                                   | "提升"主张无法支持；认知活动无法衡量                                               | 捕获启动前的品牌搜索、直接流量、ER中位数 - 或者声明差距                                           |
| 混合参与率分母                                                     | 同一个帖子根据分母读作9%或1.2%；趋势无意义                                         | 一个分母，在词汇表中选择，并在每个数字上标记                                                 |
| 在平台指标定义变更期间比较期间                                       | 任何方向上的虚假趋势                                                              | 在变更日期分拆报告；在词汇表中标记日期戳的视图定义                                               |
| 增量测试功率不足                                                   | "没有显著提升"被读作失败；一个有效的渠道被切断                                     | 在提交前进行MDE功率检查；功率不足时，仅声明方向性                                                  |
| 信任创作者截图                                                     | 轻易被篡改的数字进入报告                                                         | 提前获取API/账户级访问权限；在每次输出中标记来自截图的数据                                         |
| 将供应商基准采用为目标                                               | 目标校准错误；任意声明成功或失败                                                   | 内部按平台/层级/目标的 trailing 中位数；供应商数据仅作为校准背景信息                             |
| 促销码泄露到优惠券扩展                                               | 扩展收集了代码；创作者的信用被夸大，支出被错误分配                                 | 监控兑换情况，无匹配链接点击；超过一定百分比后切换到一次性代码                                   |

## 调用示例

- "我们下个月将为8位TikTok微型影响者支付护肤品发布费用 - 我们如何衡量？制定衡量计划。"
- "为我们的B2B持续大使项目设计KPI和归因计划：4位通讯栏作家，目标是管道。"
- "营销想要一个3位YouTube创作者的认知推广，而财务想要证明它有效。在签署前编写影响者衡量框架。"
- "我们有促销码和GA，其他什么都没有。在这个创作者活动中，我们能诚实衡量什么，以及报告频率应该是多少？"
