# 联合 GTM 规划

与一个特定合作伙伴共同规划一项 GTM（Go-to-Market，市场进入）计划。合作伙伴已经选定 - 排名候选者属于 `mbfinotti/partnerships-skills@alliance-prioritization`。这里规划的是一个单一的行动方案：

- 面向客户的“携手共赢”故事。
- 活动形式。
- 谁负责什么，以及预算分配。
- 双方承诺的发布顺序。
- 领导者共享和归因协议。
- 决定是否重复的复盘会议。

输出是一个两家公司都可以签署的联合 GTM 计划 - 一个决策成果，而不是活动资产。广告文案、邮件正文、网络研讨会脚本和着陆页是此计划下游的战术工作。注意与生态系统兄弟的界限：其联合价值主张研讨会筛选合作伙伴是否能够阐述联合价值；这项技能为指定的合作伙伴和计划草拟实际面向客户的声明。

## 面谈

在提出任何建议之前进行面谈。每条消息一个问题；在可能的情况下提供多个选项。跳过用户已经回答的内容。如果您的 harness 具有持久记忆，请首先检查它是否有与该合作伙伴的先前批准计划，并确认发生了什么变化，而不是重新面谈。

- 哪个合作伙伴，以及关系处于什么状态：新签订的、签订但处于休眠状态、有先前的活动或战略性联盟与高管关系？
- 什么计划，以及什么业务目标驱动它：管道生成、集成或产品发布、进入新的细分市场或市场、品牌关联、共同活动？
- 目标受众是谁，以及验证了哪些账户或受众重叠 - 映射重叠数据、客户访谈证据或假设？
- 两家公司可以共同声称而单独无法做到什么？一个联合价值主张草案，还是一张白纸？
- 每一方已经拥有哪些资产：集成、内容、客户故事、受众渠道、活动参与、自有名单？
- 每一方承诺多少预算，是否有市场开发或合作资金可用 - 具有什么声明规则和截止日期？
- 每一方的努力上限是什么：可用的工时、分配的人员数量、负责人可以花费多少审批资本，以及承诺必须保持多大的可逆性？钱不是决定活动形式的约束 - 两家公司之间的协调才是。
- 时间表是什么，是否有固定日期（活动、产品发布、季度结束），以及必须在什么日期之前获得结果？发布日期和结果日期是不同的约束。
- 目标是本季度的一次性胜利，还是一个在发布后持续产生收益的复合型资产？永远不要让这一点保持隐含 - 它会完全改变活动形式的排名。
- 每一方的指定负责人是谁，以及每一方的执行赞助人是谁？四个名字。
- 适用哪些领导者共享和数据保护约束：覆盖的区域、同意机制、每一方的 CRM、任何现有的数据共享协议？
- 对每一方单独而言，成功意味着什么？永远不要接受一个合并的“共同目标” - 隐藏的不对称将在事后复盘中暴露。

## 工作流程

始终遵循一个原则：在每一个实际分叉点 - 活动形式、顺序模式、领导者分配规则、预算结构 - 呈现 2-3 个候选方案，包括权衡和明确的建议，然后等待用户的决定。永远不要让一个假设在没有说明的情况下硬化成计划。

1. 运行面谈。如果您可以浏览网页，请阅读两家公司的网站、合作伙伴的公共合作伙伴页面以及任何现有的联合列表 - 在计划之前审计现实情况。
2. 在计划任何内容之前，根据准备情况进行控制。当存在不合格项时，请说明原因拒绝：
   - 双方都没有指定负责人或执行赞助人。
   - 合作伙伴无响应或不承诺。
   - 超过在单个资产上放置两个标志牌之外，无法阐述联合价值。
   - 双方的目标完全不相交 - 一方想要线索，另一方只想要品牌覆盖范围，这是一个已知的联合营销失败模式。
   - 一方没有预算或能力。
   - 一个活跃的联合销售政策争议正在燃烧 - 首先将其交给 `mbfinotti/partnerships-skills@partner-channel-conflict`。

   当控制失败时，命名缺失的部分并停止 - 一个计划无法修复一个未配备的合作伙伴关系。

3. 起草此计划的联合价值主张：面向客户的声明、服务对象以及为什么需要两家公司。应用“单独无法做到”的测试 - 如果任何一家公司都可以可信地单独实施该计划，它就是一个佩戴合作伙伴标志的独立活动；重新塑造或取消它。
4. 建立相互价值和受众重叠：
   - 分别陈述每一方的目标，并附带数字和日期。
   - 当存在时，消耗生态系统兄弟验证的重叠输出；否则从客户证据中近似，永远不要从假设中近似。
   - 定义目标细分市场及其明确的排除项 - 双方的现有客户，或仅有一方的？
5. 选择活动形式 - 最大的分叉点。首先阅读 `[references/campaign-formats-and-sequencing.md](references/campaign-formats-and-sequencing.md)`：它按效率对 B2B 和 B2C 格式菜单进行排名 - 每单位两家公司协调的价值 - 默认是 B2B 中的联合网络研讨会，B2C 中的创作者合作。从该顺序的顶部筛选 2-3 个格式，删除面试答案排除的格式，并根据您对这对公司的了解重新排序。呈现它们时附带努力、价值和合规性的权衡，并给出明确的建议。大声说出哪个答案使哪个格式发生了变化：
   - 一个硬性结果日期删除了季度长度的格式。
   - 一个复合型资产指令提升了研究报告和“携手共赢”页面。
   - 一个低努力上限将菜单缩小到一小时格式。
6. 分配工作、资产和预算：
   - 根据每一方的优势分配创作。
   - 将每一方的支出记录为单独的一行。
   - 逐字记录市场开发或合作资金条款 - 合格的活动、执行证明要求、声明截止日期。

   未使用的资金是一个主要的失败模式。

7. 通过六个阶段顺序发布：同意条款、构建资产、预热、在商定的一个日期同时发布、跟进、复盘。预算大约是单公司时间表的两倍 - 剩余部分是另一组织的批准和反馈周期，这是常态，而不是应急措施。从任何固定日期向后锚定。相同的参考。
8. 设计领导者共享和归因协议：收集点处的同意决定，以及由此产生的机制。
   - 法律依据。
   - 两家公司都列出。
   - 同意保持可分离，而不是捆绑。
   - 撤回路线。
   - 谁拥有表单 - 控制点（见下文的数据保护部分）。
   - 转移机制和时间。
   - 一个共同商定的合格线索定义。
   - 去重规则。
   - 每一方的跟踪链接。
   - 此计划的来源与影响规则。

   在这里决定这些参数并记录它们；起草字面的表单副本是下游的资产执行工作。如果存在全局归因政策，则从联合销售兄弟处获取它作为约束 - 永远不要在这里重新设计它。参见 `[references/lead-sharing-and-attribution.md](references/lead-sharing-and-attribution.md)`。

9. 组装计划（下一节）并分部分呈现，在起草下一部分之前向用户验证每一部分。在收到反馈时进行修订。在最终确定之前，要求对整个文档进行明确批准 - 以及其现实世界的对应物：两家公司的负责人在开始任何资产工作之前签署它。
10. 将批准的草稿与通过清单进行评分。说明哪些检查未通过，并迭代直到所有检查都通过。
11. 如果您的 harness 具有持久记忆，请记住批准计划的关键决策 - 合作伙伴、计划、活动形式、发布日期、领导者共享规则、每方目标 - 以便后续运行（飞行中检查、复盘、与该合作伙伴的下一个计划）从它们开始。
12. 将此技能不做的部分 - 选择合作伙伴、交易注册政策、项目等级、关系经济、持续评分卡、赋能课程 - 交给 Reference 中的兄弟。

## 联合 GTM 计划

将每个参与都作为此成果交付 - 两家公司都可以签署的一页：

```
联合 GTM 计划 - <公司> x <合作伙伴>: <计划>, <日期>
目标        : 每一方的目标单独列出，每个目标附带数字和日期
联合价值主张: 面向客户的声明 + 为什么需要两家公司
受众        : 目标细分市场，重叠证据，明确排除项
活动形式    : 选定的格式，它在效率顺序中的位置，是什么使其处于该位置，
              被拒绝的替代方案及其原因
资产与分配  : 谁创作和谁批准每个资产；重用的现有资产
预算与资金  : 每一方的支出作为单独的一行；MDF/合作资金条款逐字记录
顺序        : 阶段日期，商定的一个发布日期，批准缓冲显示
领导者与跟踪: 同意基础 + 参数，转移机制 + 时间，合格线索
              定义，去重规则，每方链接，来源/影响规则
负责人      : 每一方的指定负责人 + 执行赞助人 - 四个名字
衡量        : 每一方的 KPI，报告频率，计划复盘日期
```

每一行都有一个原因 - “因为合作伙伴的会议在 15 号开始，所以在 14 号发布”是可审查的；一个裸日期是不可审查的。

**通过清单** - 计划在所有检查通过之前才算完成；每次都说明失败的检查和差距：

- 每一方的成功标准单独列出，并附带数字。一个合并的单一目标是失败的。
- 联合价值主张通过了“单独无法做到”的测试。
- 四个名字：每一方的一个负责人和一个执行赞助人。团队名称不是负责人。
- 一个发布日期，由双方同意，并在阶段日期中显示批准缓冲。
- 领导者行命名了收集点的同意基础及其参数、转移机制和交接时间 - 参数，而不是起草的表单副本。
- 每个跟踪链接都归因于特定的一方；不存在共享的未标记链接。
- 任何 MDF/合作资金都附带其执行证明要求和声明截止日期。
- 复盘是一个计划日期，在发布之前设定 - 不是“之后”。
- 计划中引用的任何基准都附带一个来源标记。

## 既定实践 vs 供应商词汇 vs 无标准

诚实地评估您引用的内容 - 这个领域混合了真实实践和供应商营销：

- **既定，可以规范性呈现：**
  - 联合营销本身（学术渊源可追溯到 Koichi Shimizu，1981 年）。
  - 签署的联合营销协议，涵盖主题、时间表、每方目标、资产所有权、领导者共享、推广和报告。
  - MDF/合作资金附带执行证明（验证机制可追溯到 20 世纪 30 年代的合作广告）。
  - 每一方有单独的跟踪链接。
  - 表单级别的同意语言。
  - 执行赞助。
  - 活动后的复盘。

  借用的通用框架 - RACI 用于所有权，OKRs 用于目标，阶段门用于批准控制 - 都是真实的，但不是合作伙伴营销的发明；轻柔地使用它们，永远不要强行套用。

- **供应商创造的词汇：** “nearbound” 和 “ecosystem-led growth” 源于一个供应商（Crossbeam）及其收购的媒体品牌；账户映射作为一个命名学科被同一家供应商推广。可以作为共享词汇使用，永远不能作为教条。

- **不存在标准：**
  - 没有标准的联合商业计划或联合 GTM 计划模板 - 上述骨架是组装的实践，因此应分部分验证，而不是将其视为行业表格。
  - 发布级别标准（Tier 1/2/3）、联合业务审查议程、MDF 阈值和跨公司合格线索定义都是项目特定的 - 让用户明确决定它们。
  - 流传的“60-70% 的联盟失败”数字是无源传说。永远不要引用一个单一的联盟失败率作为既定事实：公布的估计因失败定义而异，从 20% 到 80%，因此请附带其来源呈现这个范围 - `mbfinotti/partnerships-skills@alliance-prioritization` 负责处理这个数字。

## B2B 和 B2C

规划纪律在双方都是相同的：

- 目标按每方分别陈述。
- 在资产工作之前签署协议。
- 品牌匹配筛选（关联本身就是风险）。
- 一个商定的发布日期。
- 指定负责人。
- 复盘。

真正变化的是什么：

| 维度                                                                         | B2B（供应商间联合营销）                                              | B2C（联合品牌、品牌和创作者合作）                                                |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 重心                                                                       | 管道和线索机制                                                          | 产品或内容本身，以及品牌匹配的声誉风险                                             |
| 典型交付物（每一方自己的效率顺序在格式参考中）                               | 联合网络研讨会、携手共赢页面、合著报告、集成发布                          | 创作者合作、品牌内容合作、联合品牌产品                                              |
| 成功框架                                                                   | 管道原生：线索、来源/影响收入                                           | 品牌资产和召回；归因结构上更难                                                           |
| 监管                                                                       | 没有消费者披露制度；风险存在于私人合同中                                | 消费者保护披露执法（FTC 风格）适用于赞助的创作者内容                                |
| 独家性                                                                     | 许多并行非独家合作伙伴关系是常态                                        | 类别独家是一个明确的、协商的合同等级                                                   |
| 批准                                                                       | 通过营销和法律链前负荷，在发布前                                       | 品牌否决可以延伸到发布后，进入已发布内容                                             |

### 领导者共享和数据保护

在两家公司之间共享捕获的线索在大多数司法管辖区都是个人数据的受监管处理 - 欧盟的制度（GDPR）是最严格的模板，但逻辑是通用的。每次转移都需要一个法律依据，并且为了一方声明的目的收集的线索不能在无声中为另一家公司服务。

控制点是收集点处的同意措辞。表单必须：

- 列出两家公司。
- 声明目的。
- 保持每一方的同意可分离，而不是捆绑。
- 使撤回变得容易。

当两家公司共同决定收集什么数据以及为什么 - 联合举办网络研讨会是一个经典案例 - 许多制度将它们视为共同控制者：责任分担必须记录并披露，线索可以针对任何一方行使权利，而不管内部分割如何。

完整机制和协议内容：[references/lead-sharing-and-attribution.md](references/lead-sharing-and-attribution.md)。

## KPI

仅测量此计划 - 合作伙伴的持续评分卡属于 `mbfinotti/partnerships-skills@partner-performance`。

- 将**合作伙伴来源和合作伙伴影响分别追踪**；合并它们会隐藏该动议是产生了需求还是进行了装饰。
- 分别针对每方单独声明的目标进行评分——一个活动可能对一个公司成功而对另一个公司失败，并且计划必须能够说明这一点。
- 核心指标：每方的线索数量（通过每方链接）、合格线索转化率（基于共同商定的定义）、管道和收入归属、每方受众增长、资产参与度。定性复盘：合作是否顺畅、内容是否需要两家公司、双方是否会重复。
- 计算回报为该动议可归因的增量利润除以每方的自身支出——每方计算自己的；混合数字会隐藏非对称结果。
- 合作伙伴营销中发布的基准数字绝大多数是供应商自我报告的（销售合作软件的平台，调查自己的客户）。引用此类数字时必须附加该标记；优先使用用户自己的历史活动数据作为基准。

## 失败模式

| 症状                                                  | 解决方法                                                                                                  |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 每方都悄悄地优化不同的结果                             | 在计划中分别重申两个目标； gate批准需要双方都接受两个目标                                             |
| 发布日期反复延误                                       | 双倍单人时间缓冲；从固定外部日期向后锚定；通过赞助人升级                                                 |
| 没有人参与的标志交换活动                               | 应用“双方都不单独”测试；围绕真实的联合能力重塑，或终止该动议                                             |
| 线索从未转移，或在事后发生争议                         | 在发布前将转移机制、时间安排和同意参数写入签署的计划中                                                     |
| MDF或合作资金过期未领取                               | 记录符合条件的活动、执行证明和领取截止日期作为预算行，并指定负责人                                       |
| 合作伙伴在动议中途沉默                               | 早期启动高管赞助人升级路径；缩小范围而不是勉强到日期                                                   |
| 没有人能说它是否有效                                   | 从第一天开始使用每方链接，来源/影响分开，在发布前安排复盘日期                                             |
| 合作伙伴的错误波及到你的品牌                           | 在准备阶段进行品牌匹配筛选；对每个联合品牌资产拥有相互批准权                                               |
