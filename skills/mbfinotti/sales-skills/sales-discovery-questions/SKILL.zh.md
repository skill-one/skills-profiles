# 销售探寻问题

构建销售顾问在销售探寻对话中使用的、按顺序排列的问题集，并附带用于实时调整的后续追问梯级和分支逻辑。

四种具有公开文档化结构的问题框架都收敛于同一个核心脉络：

- SPIN（Rackham，1988）
- Sandler 的痛点漏斗
- MEDDPICC 的“三个为什么”
- GAP 销售法的问题 / 根本原因 / 影响图表

该核心脉络：隔离出一个真实问题，挖掘其根本原因，量化其影响，然后确立为何要在当下行动。本技能编码的是这种收敛性，而非任何单个缩写。供应商提供的问题数量和发言占比基准充其量仅是方向性的——切勿设定必须达到的数字。

## 访谈

在起草之前先提问。每条消息只问一个问题；尽可能提供选择题；跳过用户已回答的内容或其备注中显而易见的内容。

- 是 B2B 还是 B2C？（此处的 B2C 指经过深思熟虑的高客单价消费者销售——如辅导、翻新、财务咨询——而非冲动零售。）
- 目标人物画像是谁，职位有多高？（终端用户、经理、高管——级别会影响问题数量和深度。）
- 产品做什么，解决什么问题？各用一句话说明。
- 这是什么类型的通话：SDR 资格确认（15-30 分钟）、AE 深度探寻（30-45 分钟）、进行中交易的针对特定人物的后续跟进，还是一次 B2C 咨询？时长多少？
- 交易规模和周期复杂度？（交易型单一买家 / 中型市场少数利益相关者 / 企业级采购委员会。）
- 是 inbound（入站）还是 outbound（出站）来源？（入站买家带着确认和深化意向而来；出站买家需要先建立问题意识。）
- 从之前的接触中已经知道了什么——外联回复、备注、之前的通话、交易记录？
- 团队是否强制使用某种方法论（SPIN、MEDDPICC、Sandler、GAP、其他）？如果是，问题集必须映射到该术语体系。
- 买家是否处于受监管环境中（医疗、金融、政府）？（会增加决策流程和采购相关问题；限制可询问的数据和财务内容。）
- 销售顾问已经怀疑存在什么痛点？（这将成为待验证的假设——而非待确认的事实。）
- 什么样的下一步将使这次通话成功？（问题集必须向该方向收尾。）
- 该通话必须在什么日期前产生已预约的下一步？（硬性日期会提升影响三元组——本次通话中获得的数字是带有日期的请求所依据的内容——并降低决策背景覆盖度，因为决策背景在整个周期中发挥作用，而非仅限于当天。）
- 是一次性胜利还是复利资产：针对这次通话的表格，还是团队可重复使用的可复用人物画像模板？（复利会提升决策背景覆盖度和完整的后续追问梯级，因为两者均可在多次通话和人物画像中摊销；一次性则保留最简核心脉络。）
- 工作量上限：通话中有多少分钟可花费在提问上，销售顾问实际会进行多少演练，以及可以消耗买家多少耐心？（低上限会直接删除决策背景阶段，并将所有梯级限制在两级。）

## 工作流程

1. 执行访谈；在写下任何问题之前收集所有答案。
2. 收集上下文。如果可以浏览网页，请研究公司和人物画像；否则根据用户备注进行操作。切勿编造客户事实——研究是为了回答情境问题，以免通话中还要再问。
3. 根据输入写出 2-3 个候选痛点假设，每个都表述为在通话中待验证的假设。与用户确认优先验证哪一个。
4. 选择叠加在下方核心脉络之上的覆盖视角。通话分钟数是每种视角的预算单位，买家的耐心也与之同步消耗——花费更多善意的视角即使对销售顾问免费，成本也很高。
   - 效率：`GAP > Sandler > SPIN > MEDDPICC`
   - 价值：`GAP > MEDDPICC > Sandler > SPIN`
   - 工作量：`MEDDPICC > Sandler == GAP > SPIN`
   - 默认 GAP：大约每个交易一小时的演练和两个影响问题——用潜在买家自己的话获得那个数字，成交、复盘以及所有下游交易技能都运行在这个数字之上。
   - Sandler：花费相同的一小时和已在开放阶段内的少量分钟数，在工作量上与 GAP 并列——用单一痛点的深度换取数字，因此排名第二。
   - SPIN：两个维度几乎为零——它只是重新排序已写好的问题，且核心脉络已吸收其排序规则。免费获取，切勿为此预留预算。
   - 资源匮乏：MEDDPICC 的决策背景。在真实购买群体中价值高，工作量最高——整个额外的阶段，需在周期内按每个人物画像重新收集——因此效率视角将其埋没，销售顾问发出的表格量化了无人能批准的痛点。只要购买群体超过单一经济买家，或买家受监管，就将其提升为首选。仅将各要素作为问题收集；评分属于记分卡技能。
   - 删除，而非降级：
     - 强制指定的方法论会从表格中移除其他三种，并将每个阶段映射到其自身术语。
     - 交易型或 B2C 交易会直接移除决策背景阶段。
     - 被排除在外的视角如果排在末尾，会在通话中途重新出现为范围。
   - 在写下问题之前重新排序——此顺序是默认值，而非法律，并随谁主持通话、谁回答问题而变化：
     - 15 分钟的 SDR 通话只保留前列部分。
     - 与从业专家的一小时通话会将 Sandler 提升至并列。
     - 高管会提升能最快获得数字的视角，并删除其余部分。
5. 根据通话大小调整问题集：大约每 3-4 分钟提问时间对应一个实质性问题及其后续追问；高管则更少、更深。按第 4 步的顺序分配这些分钟数——效率线头部的视角优先获得其问题，预算无法支持的内容从尾部削减，而非在四个视角间均匀削减。发布的“理想问题数量”具有相关性且内部不一致，因此根据通话时长而非魔法数字来定规模。
6. 从 [references/question-bank.md](references/question-bank.md) 起草，按核心脉络顺序，一次一个阶段。为每个主要问题附带 2-3 级的后续追问梯级和聆听要点。
7. 添加分支触发器（如下）和问题库中的禁止询问列表。
8. 按照 [references/call-sheet-template.md](references/call-sheet-template.md) 组装成通话表格。
9. 运行质量门控；迭代——重写并重新检查——直到所有项目通过。
10. 交付，并提醒用户：表格是地图，不是脚本——遵循潜在买家的回答，使用分支。
11. 如果你的框架具有持久记忆，请记住人物画像、被证实为真的假设，以及哪些问题产生了信号——同一个人物画像的下一套问题起点会更温暖。否则，交给用户一份简短的摘要供保留。

## 痛点 → 影响 → 紧迫性 核心脉络

每个问题属于一个阶段。每个阶段都有退出条件。前进是单向的——在走完核心脉络之前，切勿退回到后勤事务。

| 阶段             | 任务                                                                                 | 何时进入下一阶段                                              |
| ---------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 框架             | 一行议程共识（Sandler 的预付合同，Sandler 自创概念）                                  | 目的、时间和可能结果已达成一致                                 |
| 情境             | 无法研究的极少背景 - 最多 1-2 个问题                                                 | 你能用对方的话描述其当前流程                                   |
| 痛点             | 在假设背后揭示真实问题                                                               | 有一个具名、具体的问题，并伴有近期示例                           |
| 根本原因         | 发生的原因及他们已尝试过什么                                                           | 原因与症状已区分；已知先前尝试                                 |
| 影响             | 在技术、业务和个人维度上量化（GAP 销售法的三元组）                                   | 至少有一个数字，以及还涉及其他人                                 |
| 紧迫性           | 为何是现在 - 引人注目的事件                                                            | 有带日期或触发条件的行动理由，或诚实地表示没有                   |
| 决策背景         | （复杂 B2B）决策实际如何做出                                                           | 已勾勒出流程、其他声音、评估路径                                 |
| 收尾             | 用潜在买家原话总结，然后提出带日期的下一步                                             | 针对发现的影响提出具体的下一步                                 |

排序规则 - 整个问题集遵循的逻辑：

- 先开放式后封闭式。用开放式问题开启阶段；仅在确认或量化已说内容时使用封闭式问题。以“学习心态而非销售心态”接近探寻（Chris Riley，引自供应商综述）。
- 先分层再推进：每个有意义的回答在新话题之前值得 2-3 个后续追问。Sandler 痛点漏斗（由供应商发布；Sandler 自己的页面未显示）对梯级进行了排序：模糊 → 具体示例 → 持续时间 → 先前尝试 → 成本 → 情感分量。可迁移的部分是这种排序，而非确切的措辞。
- 根本原因先于影响。“无法解决你不理解的问题”（Keenan）。量化症状的成本是量化了错误的东西——且“痛点可能具有误导性”（Keenan）。
- 影响先于紧迫性。在影响量化之前询问紧迫性只是施压——且已发布的买家决策困境研究（Dixon & McKenna 的 JOLT 工作，其书籍自身的声明）发现施压会加深而非解决决策困境。
- 一个问题一个观点。切勿复合，切勿堆叠。堆叠的问题只会得到其最简单半部分的答案。
- 过去具体优于假设。“那件事上次发生时是什么时候，花了多少钱？”优于“如果……会花多少钱”。关于真实事件的答案是数据；关于想象事件的答案是客套话。
- 用对方的话，而非产品的话。在收尾之前，问题保持与产品无关；产品仅在差距确立后进入。“切勿为需求而销售”（Keenan）。
- 用对方的数字量化。“价值是数字，不是形容词”（Command of the Message, Force Management）。让潜在买家说出数字；销售顾问提供的数字是等待发生的异议。

分支触发器 - 交付物中实时调整的一半，写入每份通话表格。这些没有排名，也永远不会获得排名：每个触发器基于自身条件触发，而非与其他竞争同一分钟，因此对其排序会发明通话并不具备的精确度。

- 两个假设后仍未浮现痛点 → 切换假设，或提出诚实的后备方案：“这种情况必须具备什么条件才值得你花时间？”。切勿制造痛点。
- 潜在买家早期主动提供影响 → 向前跳跃，记录在案，返回寻找根本原因。核心脉络排序的是退出条件，而非脚本。
- 高管在场 → 问题数量减半，以最具假设力度的痛点领先，用观点陈述替代情境问题。“顶尖销售顾问在探寻通话中问得更少”（Gong），且其发布的经验法则明确对 C 级买家失效。
- 回答仍停留在表面层 → 逐级向下降低 Sandler 梯级而非继续前进；未满足退出条件而离开某一阶段，会在复盘邮件中暴露出缺口。
- 潜在买家在核心脉络中途询问价格或演示 → 简要回答，然后交易：在深入之前再走一个阶段。过早推销是下方的主要失败模式。

## 调用方式和预期输出

典型调用方式：

- “为我明天与一家 200 人物流公司运营副总裁的 30 分钟通话构建销售探寻问题集——出站，她回复了一封关于发货错误的冷邮件。”
- “我销售厨房翻新；夫妇们预约 60 分钟的上门咨询。给我问题集。”
- “SDR 资格确认通话，入站演示请求，中型会计公司的 IT 经理——15 分钟。”

交付一份通话表格（完整模板见 [references/call-sheet-template.md](references/call-sheet-template.md)）：

```
销售探寻通话表格 - <人物画像> 于 <公司>，<通话类型>，<时长>
假设           : 2-3 个疑似痛点，按排名排列 - 待验证，非确认
框架           : 一行前置议程
问题路径       : 按核心脉络阶段 - 主要问题，2-3 级后续追问梯级，
                 聆听要点，退出条件
分支           : 若无痛点 / 若有高管 / 若早期出现影响 / 若询问价格
禁止询问       : 应避免的引导性、后勤优先和假设性问题
收尾           : 总结提示 + 带日期的下一步请求
通话之后       : 哪些阶段未获回答 → 下次接触的缺口
```

## B2B 与 B2C

- 两者相同（这些框架在此处收敛，且没有一个按业务模式拆分核心脉络）：
  - 核心脉络本身
  - 排序规则
  - 后续追问梯级
  - 质量门控

  变化的是回答者是谁，以及哪个影响维度领先。

- B2B：购买群体规模较大——一项 Gartner 调查（2017 年，n=750，Gartner 自述数字）显示中位数为 6-10 名决策者——因此探寻需按每个人物画像重复。生成特定人物画像的变体（终端用户的工作流痛点、经济买家的业务成果、技术评估者的架构和安全）；将利益相关者策略本身路由到交易冠军映射技能。
- B2B：在复杂交易中，决策背景问题至关重要；在受监管买家处，采购和合规路径问题扩展，而与个人财务相关的问题消失。
- B2C 高客单价：一次对话，一或两个决策者——通常是获得完整核心脉络的唯一机会，因此收尾比覆盖广度更重要。业务影响变为家庭时间、金钱和压力，这就是为什么问题库在此处重新排序影响维度。与夫妇交谈时，分别询问每个人的痛点和影响问题——两个决策者意味着两个核心脉络。
- B2C：先前尝试的问题（“是什么让你直到现在都没这样做？”）承载根本原因阶段；受监管类别（财务咨询、健康）限制措辞——为用户标记，切勿猜测规则。

## 质量门控

根据全部十项对起草的问题集进行评分。通过阈值：10/10。迭代直到没有失败项。

1. 每个问题映射到且仅映射到一个核心脉络阶段；无孤儿，除合理跳过外（例如 SDR 首次通话中的决策背景）无空阶段。
2. 每个阶段以开放式问题开启；封闭式问题仅用于确认或量化。
3. 在影响之前探究根本原因；在任何紧迫性问题出现之前，影响至少包含一个量化问题。
4. 影响问题至少覆盖技术 / 业务 / 个人中的两个。
5. 无引导性问题（期望答案嵌入在措辞中）且表格中无任何复合问题。
6. 每个可过去具体的问题都是：它引用真实的近期实例，而非假设。
7. 预算、时间线和流程后勤仅在痛点和影响之后出现——切勿作为开场。两个典型违规者（“这个项目的 timeline 是什么？”、“有预算分配吗？”）在禁止询问列表中，是 GAP 销售法从业者发布的负面示例。
8. 问题集符合规定的通话时长，每 3-4 分钟大约一个主要问题加梯级，高管则减少；未引用目标问题数量作为规则。
9. 每个问题都能改变销售顾问接下来的行动。答案不改变任何问题的探寻是表演——删掉它。
10. 表格以潜在买家原话总结提示和带日期的下一步请求结束，并包含分支触发器和禁止询问列表。

## KPI 与衡量

- 每次通话，若表格起到作用：
  - 浮现 3-4 个不同的问题，其中至少一个用潜在买家自己的数字量化。
  - 每个退出的阶段都满足了其退出条件。
  - 接受了带日期的下一步。

一份仅凭答案即可撰写的回顾邮件（路由写入销售会议回顾技能）是诚实的检验——无法回答的部分即为发现差距。

- 在各次通话中，按角色和问题集版本追踪首次通话→下次会议（或→机会）的转化率。此处的进展，而非任何谈话比例目标，才是信号——已发布的谈话-倾听和问题数量基准是供应商的主张，具有相关性，且在供应商自身的更新中内部不一致（详情见[references/frameworks-and-evidence.md](references/frameworks-and-evidence.md)）。
- 如果有对话录音工具，请回顾哪些问题产生了长而具体的答案，哪些产生了简短回答；将这些反馈到下一版本的问题集中。如果没有，则销售人员在表单上的通话后差距笔记同样起到相同的作用。

## 常见失败模式

| 失败模式                                       | 解决方法                                                                                                                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 讯问感——快速连珠炮式提问，无层次感                 | 减少主要问题，深化问题阶梯；根据答案反应（“你提到X——多告诉我一些”）而不是跳转话题                                                                                   |
| 欢迎之耳——在一切事物中听到假设的确认               | 假设是写来被检验的；要求在痛点被视为发现前提供一个最近的、具体的例子                                                                                               |
| 表面层痛点——将投诉误认为问题                     | 沿着阶梯走：具体例子→持续时间→先前尝试→成本；没有故事的痛点只是症状                                                                                               |
| 未量化的影响                                   | 至少存在一个数字，在潜在客户的数字中，在≥2个影响维度上，才有紧迫性问题                                                                                               |
| 没有引人入胜的事件                               | 直接询问“为什么现在”（MEDDPICC的三重为什么：“为什么任何事？为什么是你？为什么现在？”）；记录其诚实的缺失，而不是编造一个——缺失是交易情报                               |
| 引导性问题                                     | 剥离嵌入的答案；“你对那个成本感觉如何？”而不是“那一定很贵，对吧？”                                                                                               |
| 过早推销——在问题核心中插入演示或产品介绍         | 产品在差距建立后才出现；简短回答，然后重新交易回问题核心                                                                                                               |
| 先考虑后勤问题——预算和时间作为开场白             | 它们在问题存在之前就收集后勤信息；按照门栏将其移到影响之后                                                                                                               |
| 发现剧场——回答不会改变任何事情的提问             | 删除任何没有下游后果的问题；覆盖率是以退出条件衡量，而不是以提问数量衡量                                                                                             |
