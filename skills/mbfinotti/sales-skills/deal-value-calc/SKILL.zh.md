# 交易价值计算器

构建一个交易的量化商业案例——将算术和叙述结合起来。组织规则：“你的工作是构建数学方程式。他们的工作是给你假设。”（Armand Farrokh, 30MPC）。这项技能拥有结构、公式和基准脚手架；买方拥有所有公司特定的输入。

记录的失败它无法预防：“大多数卖方创建的商业案例都是绝对的胡说八道”（30MPC）——冠军从未验证的虚高数字，一旦财务人员挑出漏洞就会烧毁冠军的内部信誉。

第二条规则：“仅有的ROI模型不是商业案例。它是一个没有背景的未来也许。叙述为你的数字赋予意义。”（30MPC）。始终交付可见的数学和叙述文档——绝不只提供裸的ROI数字。输出的真正测试：它可以在没有代表在场的情况下转发给CFO。

## 绝不编造数字

- 拒绝编造任何输入。当用户缺乏数字时，要求提供，或者插入一个必须替换的清晰标记占位符（例如 `[NEEDED: 完全加载的小时成本 - 询问买方]`）——绝不使用一个看似合理的虚构值。
- 通过谁提供的标签来标记每个输入：
  - **买方提供** - 买方声明或记录的数字（他们的工资、发票、运营报告、公开披露）。
  - **基准** - 代表带来的外部或市场数字，并标明其来源。“像你这样的公司通常看到15%”，没有命名来源则不合格——它成为代表假设。
  - **代表假设** - 代表自己的估计，未经买方确认。
- 硬规则：商业案例的头条数字实质性依赖于代表假设输入，必须在文档上明确说明——可见的行，而不是脚注。
- 成本方面是例外：代表自己的定价和费用按定义属于代表所有——用书面报价记录它们。每个价值侧输入都属于这三种标签之一。
- 最强的输入来自买方的自有记录：发票、工资、生产数据、公开年度报告。让冠军声明数字；财务人员在打开供应商提案实践之前检查基线）。

## 面试

每条消息问一个问题；尽可能提供多选选项；跳过交易描述已经回答的内容。

1. B2B，或被视为高端B2C（太阳能、家居改善、房地产、私立教育、财务咨询）？
2. 交易细分：交易型（单一决策者、低价）、中市场或企业（购买委员会、采购/安全在路径上）？这决定了工件的大小。
3. 结果必须在哪一天之前完成？一个硬近日期会促进从买方已经持有的文档中可计算的驱动因素——退休合同、招聘计划——并删除任何需要时间研究或队列分析的驱动因素。
4. 一次性胜利，还是买方作为续订或QBR基线重复使用的复合资产？
   - 复合会促进错误/返工和停机时间避免，其测量的基线在交易结束后仍然存在。
   - 一次性保持工件在其最轻的级别。
5. 努力上限：冠军可以花费多少小时，以及他们能否接触到财务数据？低上限会删除错误/返工、客户流失和收入提升，而不是将它们排在最后，并将工件限制在回报估计。
6. 哪些价值驱动因素在起作用？以下是其效率顺序的分类列表作为选项，根据3-5的答案重新排序。
7. 对于每个驱动因素：原始输入（数量、比率、小时数、成本）——以及每个输入，谁提供了它：买方、命名基准或你自己的估计？
8. 投资方面：
   - 订阅/许可证价格
   - 实施和集成成本
   - 内部努力（小时数和谁）
   - 培训
   - 持续管理

   合同长度？

9. 案例的时间范围：1年、3年（企业软件标准）或合同期限？
10. 文档最终面向谁——冠军将把它转发给谁（经济买方、CFO、委员会、B2C中的配偶或共同签署人）？
11. 买方的财务部门（或B2C中的贷款人）会审查它吗？如果是，工作流程中的财务审查者添加适用。

## 按比例调整工件

并非每个交易都得到完整的模型交易类型指导；完整处理的触发器是复杂性——大约6个以上利益相关者、采购或安全在路径上、战略性而不是战术性支出——而不是固定的美元门槛）：

- 效率：回报估计 > 一页摘要 + 轻量级模型 > 完整模型
- 努力：完整模型 > 一页摘要 + 轻量级模型 > 回报估计
- 价值：回报估计 == 一页摘要 == 完整模型在复杂性触发器以下，然后完整模型 > 一页摘要 > 回报估计在它以上

默认为交易复杂性允许的最轻工件；每次跨越复杂性触发器都会将工件提升一个级别。价值轴在触发器以下与复杂性绑定，因为额外的深度在那里真的买不到东西——正式案例对单一决策者来说过于复杂——并且在触发器以上反转，在那里回报估计根本无法通过采购。

| 细分             | 工件                                                                                                                                                            | 深度                                                                   |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 交易型 / SMB       | 短回报估计：一个或两个驱动因素、投资、月数回报                                                                                     | 无正式文档；回报线是整个工件                                          |
| 中市场          | 一页价值摘要加上轻量级模型：输入总账、3-4个驱动因素、三种情景                                                                               | 代表构建；敏感性在结果取决于的一两个输入上                            |
| 企业          | 完整模型：经济买方摘要和带有假设附录的单独财务/采购版本，每个输入的记录来源，敏感性分析 | 如果组织有的话，聘请价值工程师或业务价值顾问                      |

## 价值驱动因素和每个驱动因素的公式

将交易的价值分解为驱动因素并单独计算每个；3-4个量化驱动因素是问题/解决方案部分（30MPC）的记录从业者形状。按买方每小时的案例强度排序它们——绝不按头条大小，也绝不按最容易产生的数字。这里的努力不是驱动因素的价值：它是从买方那里获取输入有多困难，买方的时间成本是多少，以及结果数字在财务审查中保持可争辩的时间有多长。

- 效率：直接成本 > 劳动力时间 > 避免人头数 > 避免停机时间 > 错误/返工 > 减少人头数 > 释放容量 > 收入提升 > 客户流失 > 风险/合规
- 价值（推动头条 _并且_ 在财务中存活）：劳动力时间 > 直接成本 > 错误/返工 > 减少人头数 > 避免停机时间 > 收入提升 == 客户流失 > 避免人头数 > 风险/合规 > 释放容量
- 努力（从买方获取输入所需的时间，加上数字在财务审查中保持可争辩的时间）：减少人头数 > 风险/合规 == 客户流失 > 错误/返工 > 收入提升 > 劳动力时间 == 避免停机时间 > 释放容量 > 避免人头数 == 直接成本
- 合规成本：风险/合规 == 减少人头数 > 其他所有驱动因素，它们不携带任何

每个平局都是真正的平等，绝不是逃避：

- 收入提升 == 客户流失（价值） - 相同的利润算术，并且两者都在相同的归因异议上死亡，因此财务以相同的方式折现它们。
- 风险/合规 == 客户流失（努力） - 两个数字都不存在于买方自己的系统中；两者都成本一周的外部或队列分析。
- 劳动力时间 == 避免停机时间（努力） - 每个都依赖于买方要么已经跟踪（一个小时）要么必须测量的数字（一周）。相同的分支，相同的价格。
- 避免人头数 == 直接成本（努力） - 两者都直接从买方已经拥有的文档中读取，招聘计划和合同列表。
- 风险/合规 == 减少人头数（合规成本） - 每个都需要在交易团队外部进行审查才能将数字写下来：法律或合规部门对声明的监管风险的签字，在某些司法管辖区（如工作委员会）对声明的角色移除的HR咨询。两者一旦写入就很难撤销。

B2C在顶部增加了实质性的证明责任，在所有驱动因素上——见B2B和B2C。

默认：首先提出此交易实际拥有的效率线上的前两个**硬**驱动因素，因为案例必须在买方仅凭硬价值通过障碍，然后添加软驱动因素（避免人头数、释放容量、风险/合规）以关闭。当受众是财务时，硬驱动因素薄弱，则沿着价值线向上移动。

**这个顺序会剥夺什么。** 财务最少与错误/返工减少争论，并且效率将其排在第五位，纯粹因为每个错误的基本成本是团队从未跟踪的数字。当买方已经跟踪它时，或当质量、合规或审计发现是标题中提到的倡议时，将其提升到第一位——在那里它同时是最强和最便宜的案例驱动因素。减少人头数以同样的方式在政治而不是数据努力上受挫；声明的减少指令会提升它。

**删除，不要降级。** 买方无法提供的驱动因素会完全从案例中删除：

- 没有错误的基本成本会删除错误/返工。
- 拒绝毛利会删除收入提升和客户流失，而不是试图制作一个顶线模型。
- 没有书面协议表明一个角色离开预算会删除减少人头数，而不是将其作为软项停放。

被排除的驱动因素留在列表底部稍后作为某人编造的数字回来。

**在你面前的买方面前重新排序。** 这个顺序是默认值，不是法律——它会随着交易和构建案例的人而变化，因为价值工程师可以负担得起一个代表无法负担的驱动因素。

- 一个已经仪器化指标的买方会将该驱动因素同时提升几个位置。
- 以采购为主导的评估最重视直接成本和TCO比较，并给软驱动因素大致为零。
- 一个无法接触到财务数据的冠军无法提供任何基线，这会在排名开始之前删除列表的一半。

公式和警告根据显示的来源标签整合标准从业者和财务实践。

**硬价值与软价值 - 将它们分开。**

- 硬（释放现金）价值会影响损益表或预算。
- 软价值（成本避免、容量、满意度、风险舒适）是真实的，但无法存入银行，财务经过训练会拒绝它在 ROI 数字内部。

将它们作为两个不同的部分呈现：硬部分逻辑上关闭，软部分在情感上关闭 - 故意按此顺序（30MPC）。测试：案例必须仅基于硬价值；如果仅包含软价值才有效，请重建它从业者规则）。

## 核心指标和惯例

在文档中声明每个惯例；财务会拒绝它无法审计的数学。

- **总年度毛价值** = 硬驱动因素价值的总和（软价值单独总计，不在标题中）。
- **总投资（TCO）** = 许可证/订阅 + 实施 + 集成 + 内部努力（小时 x 加载成本）+ 培训 + 持续管理。仅许可证投资严重低估了真实成本，作为记录的财务反对意见）。
- **年度净价值** = 总年度毛价值 - 年度经常性成本。
- **ROI %** = （总收益 - 总成本）/ 总成本 x 100，跨越所述范围。这是净收益惯例；也存在毛惯例（收益 / 成本） - 始终说明文档使用哪种惯例，这两种惯例都在流传）。
- **回收期（月）** = 12 x 第一年总投资 / 总年度毛价值（仅硬）。如果年度毛价值减去经常性成本为零或负，则回收期未定义：写“在范围内无法回收” - 永远不要隐藏除零或负结果。
- **多年视图**：当合同或范围是多年时，显示每年的价值和成本，然后是累积净额。对于财务审查，添加 NPV = (净现金流量_t / (1+r)^t) - 初始投资，其中 r 是买方自己的障碍率或资本成本 - 询问财务，而不是假设（一种商业方法中存在 10% 的默认值）。
- 回收期预期是按细分划分的，来自从业者和供应商内容，而不是同行评审研究：
  - 廉价的 SMB 工具：3-6 个月
  - 云软件：12-18 个月
  - 较大的本地软件：18-30 个月
  - 复杂的数据/AI 购买：12-24+ 个月

  永远不要将任何阈值呈现为普遍规则 - 买方的障碍是一个需要询问财务的问题，并且一个方便地落在干净 12 个月回收期的收益流读起来像是制造的财务反对意见。

## 三个案例，而不是一个点估计

通过在可辩护的范围内变化真正不确定的输入来生成保守 / 预期 / 乐观场景 - 这一惯例在财务建模实践中独立重复，作为跨来源惯例）。

- 呈现顺序：保守 > 预期 > 乐观。努力在三个中是相同的 - 在三个输入设置上运行相同的模型 - 因此一个顺序涵盖了它。
- **首先呈现保守案例。** 它是倡导者捍卫的；如果它仍然超过买方的障碍，则投资不需要完美的采用才有价值从业者共识）。
- 保守案例折扣代表和基准输入最困难；买方提供的基线保持固定，除非买方提供了一个范围。
- 对于中市场和更高市场，添加一次性敏感性：确定结果对哪些两个或三个输入最敏感，并显示作为公认的敏感性实践）。
- 不要按可能性对三个进行排名。永远不要给一个案例附加概率或权重：范围是可辩护的带，而不是分布，并且“70% 可能”标签是虚假的精度，财务将其定价为猜测。

## 叙事

五部分一页结构（30MPC）：

1. **按优先级排序的标题** - 关联到买方高管已经认识的内部优先级或计划。
2. **问题陈述** - 受影响的各方和问题的量化成本，用买方自己的数字表示，并带有紧迫性驱动因素。
3. **推荐方法** - 实践转变，而不是功能列表。
4. **目标结果** - 之前/之后，与可衡量的指标挂钩，与高管级 KPI 相关。
5. **所需投资** - 双方在金钱、人员和时间上的承诺，以及时间表。

使其可信的规则：

- 整个叙事针对经济买方的三个关注点：成本、价值实现时间和对计划的信心（MEDDICC） - 以及不采取行动的成本，用买方自己的单位表示。
- 剥离供应商品牌和销售光泽；纯格式或买方自己的模板，使其读起来像买方内部分析，而不是销售材料）。
- “你不会写给你的倡导者。你会通过他们（发送给他们会转发的人）。”（30MPC）。买方小组只与任何一个供应商花费一小部分时间；文档在代表永远不会进入的房间中做了大部分销售。
- 时间：在第一次发现通话后立即开始案例，并与买方团队迭代 - 永远不要在后期作为留置物产生（30MPC）。邀请买方编辑；每次更正都将代表假设的输入转换为买方提供的输入。（声称在三轮买方编辑后赢率翻三倍的声明未经验证 - 计算编辑轮次，不要承诺提升。）。
- 让倡导者，理想情况下是财务，在案例呈现前书面同意假设，以便数字是买方的，而不是供应商的实践）。

## 工作流程

1. 运行访谈；跳过已回答的问题。
2. 调整工件大小：从最轻的等级开始，每跨越一个复杂性触发器向上移动一级。
3. 从效率顺序中选择驱动因素，根据访谈日期重新排名，复合和努力上限答案；删除买方无法提供的那些，而不是降级它们。
4. 构建输入总账：每个输入及其价值、单位、来源和来源标签（买方提供 / 基准，具有命名来源 / 代表假设）。缺失输入：询问，或插入一个标记的占位符 - 永远不要发明。
5. 计算每个驱动因素的年度毛价值；将硬和软分开在单独的总计中；运行双重计数保护。
6. 计算总投资（完整 TCO，不是许可证仅）。
7. 计算净价值、ROI（声明惯例）、回收期（保护未定义的情况），以及在适用时多年度视图。
8. 构建三个场景；检查保守案例是否超过买方的障碍；为中市场和更高市场添加一次性敏感性。
9. 测试案例仅基于硬价值；如果它失败，在编写任何叙事之前告诉用户。
10. 使用 [references/business-case-template.md](references/business-case-template.md) 的五部分结构编写叙事；剥离供应商品牌；针对成本、价值实现时间和信心。
11. 运行前向测试和质量门；迭代直到门通过。
12. 交付，下一步：倡导者编辑轮次，财务书面假设确认，以及请求 - “如果我写一份我们构建的简短摘要，你是否愿意转发它？”（30MPC 说法）。
13. 如果你的 harness 具有持久内存，存储输入总账、来源标签和场景假设，以便后续运行更新而不是重建；否则，以用户可以粘贴到他们的交易记录中的摘要结束。

如果你可以浏览网页，则在标记为 **基准** 之前验证用户引用的任何基准（来源和数字）；否则，保持为代表假设，直到命名来源。

## 调用和预期输出

- “为我交易构建商业案例：发票自动化购买，8 人 AP 团队，买方给了我他们的业务量和错误率。”
- “这笔交易的 ROI 是多少？30K/年订阅，他们说每个代表每周节省 4 小时。”
- “CFO 周四前想看数学 - 帮我使其可辩护。”

提供两个块（[references/business-case-template.md](references/business-case-template.md) 中的填充模板）：

```
THE MATH     : 输入总账（价值、单位、来源、来源标签），
               每个驱动因素的算术完全显示，硬与软总计，
               TCO，ROI + 惯例，回收期，三个场景表
               （保守优先），敏感性注释，
               如果适用，代表假设披露行
THE NARRATIVE: 五部分一页商业案例，无品牌，
               针对成本 / 价值实现 / 信心，
               加上下一步（编辑轮次、假设确认）
```

## B2B 和 B2C

- 双方完全一致，明确包括：
  - 运算和公式
  - 输入账目和溯源规范
  - 不编造数字规则
  - 硬性/软性分离
  - 由保守情况领导的三个场景
  - 前向测试
  - 质量门
- 上述从业者框架是面向B2B的；没有可触及的从业者来源将其应用于消费者销售作为例外。因此，以下每个框架映射都是结构类比——在B2C输出中明确标记为结构类比。
- B2C映射（结构类比）：
  - 经济购买者 -> 控制家庭开支或其融资审批决定购买的人
  - 推广者 -> 卖给怀疑者的热情家庭成员
  - 动力 -> 公用事业账单节省、避免的维修和维护、转售价值、融资成本与当前支出对比
  - 产出物 -> 通常是一页纸，比较月度付款与当前月度成本，并附带回报范围
- B2C监管约束——B2C确实更严格，而不仅仅是类比：消费者储蓄声明必须在消费者保护法下真实且可证实。在美国：
  - 联邦贸易委员会法案第5条
  - 绝热材料和窗户能源声明的R值规则——有多项针对夸大百分比储蓄声明的执法行动
  - 融资信息披露法
  - 逐门销售冷却期
  - 州太阳能披露法规

  未证实的“节省40-70%”声明是法律风险，而不仅仅是销售弱点。呈现范围时需披露假设，永远不要以平均值为标题；披露总成本和融资条款。
- 在B2C中，保守情况更为重要：购买者的“财务职能”是家庭预算，通常是贷款人，而仅在乐观场景下有效的情况正是监管机构反对的。

## 质量门

对草拟案例进行所有十个检查的评分。通过标准：10/10。迭代——修正并重新检查——直到没有任何失败。

1. 每个价值侧输入都在账目中显示价值、单位、来源和三个溯源标签之一；成本侧输入引用书面报价；数学中没有任何未标记的数字。
2. 未发明任何输入：每个非购买者数字要么是命名来源基准，要么是明确假设的/标记占位符。
3. 如果当假设输入被移除时标题发生实质性变化，文档会明确说明。
4. 硬性和软性价值分别总计，标题仅使用硬性，且仅硬性案例已测试。
5. 两个动力下不计算任何员工人数、工时、收入流或预算线。
6. 每个输出数字都可追溯：显示从输入到标题的运算，总和检查，且隐藏了未定义的回报或除以零。
7. ROI惯例、时间范围和完整TCO（包括内部工作）已声明。
8. 提供三个场景，保守情况优先；保守情况通过购买者障碍或文档明确说明它未通过。
9. 叙事包含所有五个部分且不包含功能列表。它针对成本/时间到价值/信心和采取行动的成本。它通过前向测试：无品牌，对从未见过代表的人自解释，其中没有购买者未验证或未明确要求验证的内容。
10. 每个携带声明保持其溯源标签；未将供应商数据数字呈现为预期结果；未将回报阈值声明为普遍适用。

## KPIs和测量

- **购买者修正了输入**——证明他们参与了数学，每次修正都会提升输入的溯源。
- **编辑轮次完成**——案例是共同构建的，不是交付的；跟踪计数本身，而不是承诺的胜率提升（三倍声明未复制）。
- 建议在展示前获得财务或推广者的书面假设认可；将其作为KPI是结构选择。
- **推广者未编辑地转发文档**，并达到了经济购买者对话。
- 在交易中：比较共同构建案例的交易与未构建案例的无决定损失。基准：40-60%的合格B2B交易以无决定结束（Dixon和McKenna，HBR 2022 / The JOLT Effect）。

## 常见失败模式

| 失败                                                         | 修正                                                                                               |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 推广者重复并受骗的膨胀供应商数学                               | 购买者数字，优先保守情况；推广者的信誉是受保护的资产 |
| 发明或“合理”的输入                                          | 拒绝；要求或使用用户必须替换的标记占位符           |
| 只有ROI数字，没有叙事                                       | “一个未来的可能，没有背景” ——始终交付两个部分        |
| 软性节省与标题ROI混合                                        | 分开部分；单独测试硬性价值案例                     |
| 单点估计                                                     | 三个场景，保守情况优先                             |
| 许可证投资                                                   | 完整TCO：实施、集成、内部工作、培训、管理          |
| 同一员工人数在两个动力下计算                                  | 一个资源支持一个动力；拆分或删除                    |
| 圆数和收益正好落在干净的回报上                                | 保持原始数学可见；方便的数字读作人为制造            |
| 晚期作为遗留物生产的商业案例                                 | 在第一次发现通话后开始；与购买团队迭代              |
| 写给推广者而不是通过推广者                                     | 交付前进行前向测试                               |
| 无来源的“像您看到X%的公司”基准                             | 标注来源或将其重新标记为假设                     |
| 无证实的B2C节省声明                                          | 带有披露假设的范围；披露总成本和融资条款           |
