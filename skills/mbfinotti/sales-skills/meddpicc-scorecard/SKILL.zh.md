# MEDDPICC 评分卡

对描述的交易按照八个 MEDDPICC 元素进行评分，并明确指出缺失的内容、哪些是假设而非验证的内容，以及代表应该去验证下一步的内容。

目前最大规模的实地研究（Ebsta x Pavilion 2023 基准测试，涉及 364 家公司，共 320 万个机会）发现：

- 61% 采用该方法的公司的选择 MEDDPICC。
- 只有 15% 的机会被完全认证。
- 只有 5% 的公司根据每个标准获得信心评分。

这个缩写词随处可见；而该学科却很少见——这个差距被称为“MEDDPICC 剧场”，而这份评分卡就是为了防止这种情况发生。

整个评分卡基于一个轴：**证据而非存在**。一个字母的评分不在于代表能否说出某事；而在于买方是否已经做了可观察的行动来证明这一点。

该技能逐个交易进行评分，自身不收集新信息，只对用户报告的内容进行评分，然后告诉他们下一步需要验证什么。

两个信心区分贯穿始终，并应包含在输出中：

- 规则是由方法学发布还是由该技能设置。
- 数字是独立测量值还是**供应商声明**，供应商自己的相关性数字从未被独立复制。

## 面谈

在这些约束条件下提问：

- 每条消息一个问题。
- 尽可能使用多项选择题回答。
- 跳过交易描述已经回答的内容。

两轮：

交易框架（调整输入，始终是第一个）：

1. B2B，或被视为高价位 B2C（房地产、汽车、太阳能、翻新、私立教育、财务咨询——非冲动型零售）？
2. 交易的大致规模（合同价值或 ACV），以及买方有多少人参与？
3. 交易处于什么阶段，已开放多长时间，以及谁设定了预期的关闭日期——是买方还是代表？
4. 买方方面是否涉及正式采购、安全审查或法律红线？
5. 你的团队是否强制执行自己的 MEDDPICC 定义或规模（第二个 C，Implicate vs. Identify，权重）？如果是，请使用他们的定义，并在输出中注明映射关系。
6. 到什么日期必须改变这个评分卡——本周的预测电话会议、下一次交易审查，还是没有日期？
7. 你想要对这个交易进行一次性阅读，还是一个会随着审查而复合的重新评分记录？
8. 在那个日期之前，你的努力上限是多少：你能提出多少买方问题，以及你能花费多少代表内部信用？

问题 6-8 重新排序下一步行动，而不是评分；哪个答案移动哪个行动是关闭最大差距的关键。

证据收集（仅适用于通过调整框架的元素），每个消息一个元素：

9. 对于这个元素：你知道什么，以及买方侧的哪个工件或事件支持它——电子邮件、录音电话、你看到的文件、提供的介绍、买方提供的日期或数字？“买方似乎持积极态度”是一个答案；它将相应地评分。

## 工作流程

1. 在任何元素问题之前运行交易框架问题。
2. 调整大小（下一节）。在评分任何内容之前，与用户确认元素列表。
3. 按每个评分的元素收集代表的声明和买方侧的证据。
4. 根据证据梯子（评分部分）对每个元素进行评分。
5. 对每个 2 和 3 进行挑战：哪个工件或事件证明了这个分数？没有命名工件 → 将分数降至 1 并记录原因。无例外地应用这个反通胀规则——自我评分的乐观主义是这条规则纠正的记录——评分级别需要客观定义，或者一个乐观者和一个悲观者对同一交易进行不同的评分。
6. 应用两个门，计算总分，划分交易。
7. 指出最大的差距：首先是一个失败的门；否则是买方每单位努力能买到的最大裁决变化（关闭最大差距）。
8. 为每个低于 3 的元素附加下一步行动，按相同比率排序。突出显示最上面一个，以买方可见的测试形式表达——这是一个买方要么执行要么拒绝的请求，因此答案要么是证据。
9. 运行质量门；迭代直到它通过。
10. 使用 [references/scorecard-template.md](references/scorecard-template.md) 提供评分卡。
11. 如果你的 harness 具有持久内存，请存储评分卡、日期和每个评分的证明工件，以便下一次运行可以重新评分并显示差异——交易会衰减，因此每次交易审查都要重新评分。否则，以用户可以粘贴到自己的交易记录中的简短回顾结束。

如果你可以浏览网页，你可以验证评分卡依赖的公共事实（命名经济买方仍然担任该职位；引用的竞争对手仍然销售该产品）；否则，依赖用户的报告，并将这些事实标记为“用户报告”。

## 调整大小后再评分

在每笔交易上使用完整的 MEDDPICC 是过度设计；评分错误的列表是第一个通胀。哪些字母保留本身就是一个按顺序排列的菜单——评分每个字母相对于它返回的裁决信息的成本：

- 小交易的价值（裁决变化每字母评分）：代表 > Implicate the Pain == Metrics > 决策过程 > 竞争 > 决策标准 > 文件流程
- 努力程度（代表时间加上字母成本买方问题，最昂贵的首先）：文件流程 > 决策过程 > 决策标准 > 竞争 > Metrics == Implicate the Pain == 代表

从低价值、昂贵的端点向内删除：文件流程首先离开（轻量级实践中的第一个删除的元素），然后是决策标准，然后是竞争。

- 痛 == Metrics：它们是两个方向的同一个答案：成本后果和买方拥有的数字在同一句话中到达。
- Metrics、Pain 和 Champion 在低成本端平分，永远不会删除：在小交易中每个都是一个单独的问题，并且没有第三个问题，任何两个都是无法理解的。
- 经济买方不属于任何一条线：它是一个门，在小交易中它合并到 Champion 中，而不是被删除。

适合范围：

- 大约 10 万美元以上的合同价值，5 个以上利益相关者，正式采购/安全/法律路径：评分所有 8 个。
- ~2.5 万-10 万美元，2-5 个利益相关者：删除文件流程，除非已知采购参与其中。
- 低于 ~2.5 万美元，1-2 个决策者，无采购：Metrics + Implicate the Pain + Champion，如果存在任何多步骤审批，则添加决策过程。在这里，经济买方和 Champion 通常合并为一个人——作为一个字母评分，并说明这一点。
- 高价位 B2C：见 B2B 和 B2C 部分；积极调整大小。

永远不要评分被调整大小后删除的元素；分母随着元素列表的缩小而缩小，被删除的元素也不会产生下一步行动。

## 八个元素及其证据条

| 元素            | 它的含义（这个技能选择的定义）                                      | 验证（3）看起来像                                               | 假设（1）看起来像                                  |
| ------------------ | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------- |
| Metrics            | 买方期望的量化结果，作为一个他们拥有的数字                      | 买方用自己的话提供的数字                                         | “他们想要效率”；代表构建的 ROI 从未确认             |
| Economic Buyer     | 有权自主支出和否决的唯一一个人                          | 与命名 EB 会面确认案例的会议                                   | “我的联系人表示首席财务官支持”                   |
| Decision Criteria  | 用于比较选项的技术、经济和关系标准                 | 买方写下的或确认的标准，证明映射                               | 将功能列表或 RFP 表格视为中立标准                 |
| Decision Process   | 谁决定什么，按什么顺序，何时决定（技术验证 + 商业批准） | 买方共同编辑的行动计划                                           | 代表编造的关闭日期；“他们说是 Q3”           |
| Paper Process      | 从口头同意到签名的所有内容：法律、采购、安全           | 命名所有者和时间线的映射路径                                   | “采购只是一个形式”                       |
| Implicate the Pain | 成本和拥有的问题；不采取行动的成本                             | 买方陈述不解决的具体成本后果                                     | 没有成本附加的表面痛苦                    |
| Champion           | 权力 + 个人利益 + 当你缺席时向内部销售                 | 联系人已经采取行动：EB 介绍，共享标准，内部介绍                 | 一个友好的联系人，没有，也许不能采取行动       |
| Competition        | 每个替代方案：竞争对手、内部构建、其他计划、惯性               | 买方阐述了替代方案；一个赢计划定位每个                        | “他们是他们唯一考虑的”                 |

有争议的定义——这个技能的立场，当存在时，将被用户的团队标准覆盖：

- 第二个 C 是竞争，包括惯性/不作为（方法学发布者的官方立场）；一些团队使用 Compelling Event 或 Closing 代替。
- 一个引人入胜的事件是贯穿每个元素的线索，而不是它自己的字母；它的诚实缺席是交易情报，永远不会制造它。
- 痛意味着 Implicate the Pain：识别问题，指示其更广泛的影响，暗示买方在成本后果中。
- 可选的“P for Partner”变体不在此处评分。

每个字母的证据示例、红旗以及将字母提升到梯子上的问题在 [references/element-evidence-bar.md](references/element-evidence-bar.md) 中——在评分前阅读它。

## 评分

每个元素的证据梯子：

| 分数 | RAG   | 标签     | 条                                                                 |
| ----- | ----- | --------- | ------------------------------------------------------------------- |
| 0     | 红色  | 未知   | 没有任何信息                                                       |
| 1     | 红色  | 假设   | 代表相信它；没有买方侧证据                                           |
| 2     | 黄色  | 陈述    | 买方说了它——在会议、电话或电子邮件中                                |
| 3     | 绿色  | 验证    | 买方证明了它：一个介绍，一个看到的文件，一个承诺的日期，一个他们提供的数字 |

这个量表来自哪里：红色/黄色/绿色惯例来自 Andy Whyte 的书，被确认为该书自己的核心评分机制，而不是几个选项中的一个。0-3 证据梯子是一个记录的实践者变体，而不是官方方法学教义，这个技能采用它并精确定义了每个台阶。每个字母的权重是可配置的，取决于实践，永远不会是典范——这个技能平等地权衡所有元素，并在输出中说明；如果用户的团队权重不同，请使用他们的权重。

汇总：总计 = 元素分数之和；百分比 = 总计 / (3 × 评分的元素)。范围：

- **≥80% 且两个门都通过 - 预测就绪。** 证据支持承诺交易（锚定：记录的实践者阈值 20+/24）。仍然在每次审查时重新评分。
- **55-79% - 真实但有差距。** 交易正在进行，但不是承诺等级；在预测它之前解决列出的差距。
- **30-54% - 不合格。** 无法预测。在此范围内的后期交易是指导触发器（记录的后期触发器 <16/24）。
- **<30% - 未合格。** 从发现中重新认证或淘汰。淘汰是这个技能的一个有效结果，而不是失败。

门——两个字母限制裁决，无论总分如何。对两个字母的强调是方法学的；限制机制是这个技能的，而不是发布的教义：

- Champion ≤1 → 裁决限制在不合格。 “没有 Champion，没有交易”。
- Economic Buyer = 0 → 裁决限制在不合格。一个不愿意或无法介绍经济买方的 Champion 是一个重大红旗，这也质疑 Champion 是否真实。

将有争议的分数与来源的成熟度梯子一起放置：

- Metrics：M1（为其他客户交付的结果）→ M2（针对此潜在客户个性化）→ M3（上线后验证）。买方确认的 M2 评分 3。复述的 M1 评分 1。
- Champion：联系人 → 教练 → Champion。
- Economic Buyer：未知 → 访问（介绍承诺，未举行）→ 赞助（见过，案例确认）。访问评分 2。赞助评分 3。

永远不要将供应商结果声明（“18% 更高的获胜率 / 24% 更大的交易 / 26% 更短的周期”，“预测准确度到 95%”）作为预期结果——未复制的供应商声明；隔离列表在 [references/vendor-claim-quarantine.md](references/vendor-claim-quarantine.md) 中。

## 关闭最大差距

每个低于 3 的元素都会产生下一步行动，并且它们都在争夺一个稀缺的东西：代表在下一个检查点之前可以对买方提出的请求。按买方每单位努力能买到的裁决变化对它们进行排序。

这里的努力永远不会是金钱。它是：

- 代表小时。
- 日历延迟。
- 代表的 Champion 内部信用花费多少。
- 一个被拒绝的请求是否可以重新提出。

八个候选请求：

- Champion 测试
- EB 会议
- 痛成本
- 买方指标
- 决策过程计划
- 标准记录
- 文件流程地图
- 不作为探测

下面的顺序是这个技能的，而不是发布的教义；努力以数量级而不是数字表示。

- 价值（关闭它使范围移动多少）：代表测试 > EB 会议 > 痛成本 == 买方指标 > 决策过程计划 > 文件流程地图 > 不作为探测 > 标准记录
- 努力程度（最昂贵的首先）：EB 会议 > 文件流程地图 > 决策过程计划 > 标准记录 > 代表测试 == 痛成本 == 买方指标 == 不作为探测
- 效率（默认顺序）：代表测试 > 痛成本 == 买方指标 > 不作为探测 > 决策过程计划 > 标准记录 > EB 会议 > 文件流程地图

数量级，而不是数字：

- 零：代表测试、痛成本、买方指标、不作为探测——日记中已经有一个电话上的一个问题。
- 起草需要一小时内，等待买方在一周内返回：决策过程计划、标准记录。
- 一周和第二次介绍：文件流程地图。
- 一周或更多的日历，加上 Champion 的信用来安排它，并且不能撤销：EB 会议。

代表测试在价值上领先，因为它是最能产生其他请求的请求：一个采取行动的 Champion 安排了 EB 会议，而一个拒绝的 Champion 是一个教练，无论如何都会限制交易。四个零努力请求在努力程度上平分，因为它们都不需要新的会议、新文件或第二次介绍。

这个顺序缺乏：EB 会议和文件流程地图。交易中两个最高价值的请求在每一轮效率线底部，因为通常改变裁决的元素是最昂贵的验证。无论如何都要提升它们：

- 经济买方评分 0。门限制裁决，所以其他验证无法提升范围——无论比率如何，EB 会议都首先进行。
- 交易是后期阶段，采购已知，或口头同意即将到来。文件流程地图首先进行；在同意后，它不再是一个廉价的修复，而是一个停滞。

删除，永不降级：

- 一个元素完全被移除后没有任何后续动作。
- 一个禁止花费冠军信用的努力上限会从菜单中移除EB会议和采购介绍，而不是将它们放在底部，在那里它们会无声地以范围的形式返回。
- 一个团队标准用“引人入胜的事件”替换了第二个C，会删除与它同等的无动作探测。

在评分卡中说明你删除了哪些内容以及原因。

根据你已有的信息重新排序，并记录哪个答案移动了哪个问题：

- 周内的一个检查点（采访问题6）会提升近零要求，并降低EB会议和纸质流程地图——两者都没有及时完成。
- 复合记录（Q7）会提升决策流程计划和纸质流程地图；两者都会留下一个在每次重新评分时都保持评分的工件，而一次性答案则不会。
- 一个买家要求上限（Q8）会使菜单压缩到效率线的顶部。
- 已经采取过一次行动的冠军会使EB会议比这个订单假设的便宜得多——提升它。
- 团队强制的标准或权重（Q5）会完全覆盖顺序；使用他们的。

这个顺序是默认的，不是法律。它会随着交易和执行者而变化：一个与经济买家有长期关系的销售代表为一次会议支付近零费用，而一个第一年的销售代表则可能需要一周的时间和一次人情。

## 调用和预期输出

典型的调用：

- “根据MEDDPICC对这笔交易进行评分：一家物流公司的200个席位推广，180K ACV，提案阶段——我们已知的信息。”
- “在周四的交易审查之前进行MEDDPICC检查。一次一个问题问我你的问题。”
- “这笔交易是真的吗？单创始人买家，9K合同，他说他这个月会签署。”

提供一个评分卡（完整的填写模板在[references/scorecard-template.md](references/scorecard-template.md)）：

```
MEDDPICC 评分卡 - <交易>, <日期>, 评分的元素: <列表>
每个元素：得分0-3 + RAG，声明，证据工件
               （或“无 - 得分下降”），下一步行动及其成本，最佳比率优先
关卡：冠军 / 经济买家状态；是否应用上限
总计：X/<最大值>（NN%），等级，用预测术语中的一句话总结
最大差距：一个元素，为什么它在单位努力上的裁决变化上超过了其他元素，以及买家可见的测试来关闭它
延迟：订单中缺乏的高价值要求，什么会提升它们，以及任何被约束删除的要求
挑战：每个被降低的得分，以及原因
定义：第二个C / 痛点选择使用；权重（默认情况下平等）
重新评分：触发下一次评分通过的事件或日期
```

## B2B 和 B2C

- MEDDPICC 是 B2B 原生的：其自己的出版商将其定位为中型市场和 B2B 企业，而消费者销售不在该方法论声明的范围内。以下关于 B2C 的所有内容都是结构类比，而不是既定实践；在您生成的每个 B2C 评分卡中说明这一点。
- 两者完全相同，明确：
  - 证据轴。
  - 0-3 楼梯。
  - 反通胀规则。
  - 关卡。
  - 工作流程。
  - 质量关卡。
  - 只有角色会变化。
- 高端产品视为 B2C 映射，所有内容都是类比：
  - 经济买家 → 控制资金并持有否决权的人：配偶或合伙人，融资父母，其批准门禁购买的资金提供者。
  - 冠军 → 当销售人员在场时，热情的家庭成员向持怀疑态度的人推销。
  - 决策流程 → 必须同意的人，顺序：查看、检查、第二意见。
  - 纸质流程 → 融资批准、检查、评估、或有条件、关闭。
  - 竞争 → 竞争性选项加上强大的“不做 / 等待”。
  - 指标 → 定量的家庭利益：月付款、转售价值、节能。
  - 痛点 → 状态现状的成本和情感价格。
- 严厉地调整 B2C：通常指标 + 痛点 + 冠军 + 纸质流程作为融资；在家庭购买上使用完整的八个字母评分卡是流程戏剧。纸质流程是这里唯一反转降序的字母——一个未开始的贷款申请，而不是一个未映射的采购路径，实际上是阻止家庭购买的东西，所以在 B2C 中默认提升被剥夺的要求。
- 一个工作的 B2C 适应示例在 [references/worked-examples.md](references/worked-examples.md) 中。

## 质量关卡

根据所有九个检查对起草的评分卡进行评分。通过阈值：9/9。迭代——修复并重新检查——直到没有任何失败。

1. 每个评分的元素都带有声明、得分，或者一个命名的工件/事件，或者一个明确的“无”。
2. 没有 2 或 3 没有它的工件；每个被降低的得分都出现在“挑战”下，并附有原因。
3. 元素列表与调整大小的决策相匹配，分母与元素列表相匹配。
4. 两个关卡都经过了检查；任何应用的上限都在裁决行中说明。
5. 最大差距正好是一个元素；评分卡说明它为什么在单位努力上的裁决变化上超过了其他元素，或者哪个提升条件覆盖了比率；它的下一步行动是一个买家可见的测试，而不是销售代表作业（“更新交易记录”失败；“本周请冠军安排 EB 会议”通过）。
6. 每个低于 3 的元素都有一个下一步行动，按相同的比率排序，被剥夺的要求在“延迟”下命名；没有行动与 3 相关联。
7. 等级的意义用预测术语说明，而不是作为等级。
8. 选择定义（第二个C、痛点）和权重都说明，如果团队有自己的标准，则注明与团队自己的标准保持一致。
9. 评分卡依赖的每条规则都被标记为已发布的 methodology 或作为这项技能自己的，并且没有供应商声明作为预期结果。

这九个检查是故意无排名的：阈值是 9/9，所以没有第一个要运行，也没有最后一个要跳过，并且在这里的顺序只会邀请交易一个。

## KPIs 和测量

- 每笔交易中，评分卡如果：
  - 至少有一个得分因缺少证据而被降低。
  - 最顶端的下一步行动是一个买家可见的测试。
  - 重新评分有所移动——从未改变的得分通常意味着本周没有人与买家交谈。
- 跨交易，措施是排名的——价值是措施能在多大程度上证明评分标准错误，努力是你在它说任何东西之前等待多长时间：
  - 价值：等级与实际结果 > 承诺关闭预测准确性 > 未做决定的损失率 > 滑动交易计数
  - 努力：等级与实际结果 > 承诺关闭预测准确性 > 滑动交易计数 == 未做决定的损失率
    滑动和未做决定率在近零时 Tie，因为两者都是任何管道报告中的列。每周阅读它们，但它们只提供暗示。

    等级与实际结果是受剥夺的度量——一个持续的工作，只有在完整的一个季度关闭的交易后才支付——并且是唯一能伪造评分标准的度量，所以从一开始就无论如何都要对其进行测量。后期滑动会快速侵蚀赢率（作为相对提升）。
- 采用检查：如果评分卡被填写但预测准确性没有移动，证据定义太松了。这是 MEDDPICC 戏剧——为了满足经理而填写字段，而不是为了资格——这是这项技能存在的确切失败。

## 常见失败模式

| 失败                                                                                  | 修复                                                                                                                                  |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 欢迎的耳朵 - 买家的礼貌被读作验证                                         | 要求工件；礼貌不是一个事件                                                                                                          |
| 自我评分通胀 - 乐观被评定为证据                                             | 反通胀规则：无命名工件，无 2 或 3                                                                                                  |
| 出席，而不是证据 - “我们有冠军”得分绿色                                       | 评分这个人的行为，而不是他们存在                                                                                                    |
| 教练被误认为冠军                                                              | 用一个问题测试——EB 介绍，内部标准，向委员会展示；犹豫意味着教练                                                              |
| 功能列表或 RFP 被误认为决策标准                                               | 标准仅在买家确认并涵盖技术、经济和关系维度时计算                                                                                       |
| 纸质流程在口头同意后发现                                                   | 在大交易上早期评分它；“采购只是一个形式”是 1                                                                                         |
| 忽略惯性作为竞争                                                           | “不做”是最常见的赢家；没有不做分析会限制竞争在 2                                                                                 |
| 评分被用作报告卡，而不是行动生成器                                             | 每个差距都有一个下一步行动，按裁决变化每单位努力排序；真正的输出是排名的待办事项列表，而不是数字 |
| 最大差距仅基于价值选择 - 在预测电话前一天选择的 EB 会议                        | 按比率排名，而不是重要性；仅在它声明的条件下提升被剥夺的要求                                                                |
| 单线程交易评分绿色                                                           | 一个联系人为每个字母提供证据本身就是脆弱性 - 在评分卡上标记它                                                                   |
| 过度合格小交易                                                              | 首先调整大小；在 9K 单一决策交易上使用所有八个字母是流程戏剧                                                              |
