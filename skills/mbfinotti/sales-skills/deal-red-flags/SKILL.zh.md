# 交易红旗

审查单个交易的书面记录——通话笔记、机会记录文本字段、CRM活动日志条目、电子邮件线程——并揭示每个红旗背后的资格问题证据。自由文本笔记是有损的，所以笔记中的沉默与确认的问题并不相同。

在两个独立的轴上对每个红旗进行评级，永远不会合并成一个分数：

- 严重程度：如果风险真实，它对这笔交易造成的损害程度。
- 置信度：笔记如何证明它。

一个高严重程度但证据不足的差距与一个低严重程度但确定的差距的处理方式不同。最常见且最有用的结论是未知——笔记对此事无任何表态——因为它将笔记中的空白转化为下一次通话的问题。结构化评分卡无法诚实地产生未知，因为其输入已经是结构化的；这种不对称性是这个技能存在的原因。

硬性规则，而非建议：

- 每个被评为已验证或假设的发现必须引用其来源笔记的确切片段。没有可引用证据的发现按定义是未知的。
- 每个红旗都有一个特定的证伪证据可以清除它。在记录风险之前检查它，以便审查不是单向的棘轮，其中每笔交易看起来都注定失败。

## 使用这个技能，或使用兄弟技能

当用户有一笔交易的书面笔记并希望从文本中揭示其风险时，使用这个技能。当用户需要以下情况时，使用其他技能：

- 用户需要一个针对MEDDPICC标准的结构化评分，标准逐项——`mbfinotti/sales-skills@meddpicc-scorecard`。该技能评分结构化答案；这个技能阅读混乱的文本并报告文本无法支持的内容。这个技能永远不会输出方法论分数。
- 用户需要构建利益相关者地图（谁是倡导者、经济购买者、阻碍者）——`mbfinotti/sales-skills@deal-champion-mapping`。这个技能仅标记倡导者证据缺失或薄弱；它永远不会命名可能的角色或构建地图。
- 用户需要一个完整的发现问题集——`mbfinotti/sales-skills@sales-discovery-questions`。这个技能针对每个空白发出一个诊断问题。
- 用户需要ROI或商业案例叙述——`mbfinotti/sales-skills@deal-value-calc`。
- 用户需要将这些笔记转换成跟进邮件——`mbfinotti/sales-skills@sales-meeting-recap`。
- 用户有一个多个交易的管道导出。这是管道级工作（卫生、预测），在此范围内：这个技能阅读单个交易的书面记录，深入。

## 面谈

在审查之前提问——每条消息一个问题，尽可能多选题。跳过笔记已经回答的内容。

- B2B还是B2C？（B2C在这里意味着考虑购买并有真正的销售对话——改造、金融产品、高端辅导——而不是冲动零售。）
- 大致的交易规模和预期周期长度？（校准严重程度：一个缺失的相互行动计划在六个月的企业交易中严重，在两周的交易中无关紧要。）
- 销售人员认为交易处于什么阶段；它是否在预测或承诺列表上，以及必须在什么日期前得到答案——预测电话、阶段门或买方的活动？（一个承诺的交易提高了每个空白的风险；在那天之后解决的空白在任何价格下都不值得追求。）
- 笔记涵盖什么时期，它们是否完整？（一次通话的笔记无法证明趋势；参见失败模式。）
- 目标是这个交易，还是背后的习惯？（挽救这个周期优先考虑面向买方的请求；修复资格或笔记卫生促进在每笔后续交易中支付的记录工作。）
- 在下一个门之前有多少努力上限——关系可以承受多少请求，以及是否有经理或高管支持者可用？（决定哪些追逐和响应环节是开放的。）
- 用户已经怀疑什么？（成为针对证据的假设来测试——永远不会是确认结论。）

## 接收

接受任何关于交易的文本：

- 原始通话笔记。
- 粘贴的活动日志。
- 机会记录的自由文本字段。
- 电子邮件或聊天线程。
- 回顾邮件。
- 文本摘要。

从任何CRM或对话录制工具导出的笔记都可作为输入——工作流中没有任何内容取决于哪个工具生成了它们。如果你的环境可以读取文件，接受文件路径或导出；否则请用户粘贴文本。

部分、混乱或薄的笔记是可以的——说出缺失的内容是这个技能工作的一半。对用户明确说明审查可以看到和看不到的内容：它评级笔记，而不是交易，所以薄的笔记会产生许多未知，而这是交易卫生本身的一个发现。

## 工作流

1. 运行面谈；然后确认输入涵盖了用户拥有的所有内容（一个杂乱的电子邮件线程通常包含唯一的买方直接引语）。
2. 将笔记标准化为按日期的事件时间线：举行的会议、谁参加了、做出的承诺、日期变动。注意记录在哪里变薄——这也是证据。
3. 提取候选证据：断言或证伪目录中任何内容的逐字片段。区分买方的直接陈述与销售人员的推断以及二手转述——"我有经济买方的书面证明"优于"我的倡导者告诉我"。
4. 运行每个[references/red-flag-catalog.md](references/red-flag-catalog.md)组与时间线和证据。将每个组中的每个红旗解决到一个状态——从不跳过任何组。
5. 在记录风险之前检查每个红旗的证伪证据。一个其清除证据在笔记中引用的红旗被清除，而不是红色。
6. 为每个未清除的红旗分配严重程度，根据交易规模、周期长度和面谈中的信息校准——而不是固定表格。
7. 将有证据支持的内容与仅仅是缺失的内容分开。为每个未知红旗写一个诊断问题（目录为每个红旗提供一个），然后按以下追逐顺序排列空白——代表人员下一次接触只有一个——不是十二个。
8. 按照下面的输出形状写报告，为目录中的每个红色和琥珀色红旗附加一个补救措施，并命名该补救措施所属的响应环节。
9. 运行质量门；迭代——重新评级和重写——直到每个项目都通过。
10. 如果你的框架具有持久内存，记录提出的红旗、其状态及其证据，以便下次审查同一交易时可以检查哪些空白已关闭。否则，在报告中为用户保留一个简短的转发列表。

## 评级标准

置信度状态——笔记如何证明红旗：

| 状态    | 含义                                                                | 证据要求                     |
| -------- | ---------------------------------------------------------------------- | ---------------------------- |
| 清除    | 笔记包含红旗的证伪证据                                                | 清除它的逐字引用            |
| 已验证  | 一个直接的、可引用的买方陈述证明了风险                                | 笔记中的逐字引用            |
| 假设  | 只有销售人员的推断、传闻或二手转述证明了它                            | 推断或转述的逐字引用        |
| 未知  | 笔记对此红旗保持沉默                                                  | 无——沉默是发现            |

严重程度——高、中、低：如果风险真实，对这笔交易造成的损害，根据交易规模和周期长度判断，而不是固定表格。使用已验证与假设的置信度测试对红旗红色/琥珀色/绿色进行评级是交易检查的标准做法（在MEDDPICC-lineage来源中记录）；上面的状态名称通过未知扩展了该词汇，用于笔记审查。

故意未排名：严重程度和置信度是风险评分卡，而不是相互竞争的选项。永远不会将两个轴排序，也永远不会将它们合并成一个分数——评分卡评级笔记说了什么，而下面的两个评级决定了在其输出之上选择的工作。后续步骤应保持评分卡不变。

报告评级——仅用于展示分组；两个轴在每个发现中都保持可见：

- 红色：已验证风险，高严重程度。
- 琥珀色：已验证风险在中/低严重程度，或假设风险在高严重程度。
- 观察：假设风险在中/低严重程度——说出什么可以确认或清除它。
- 空白：任何未知——带有一个诊断问题，永远不会有一个补救措施（没有确认的内容可以补救）。
- 清除：简要列出其清除引用，以便下次审查者不会重新提出它。

## 追逐顺序：哪个空白值得下一次接触

评级解决了每个组中的每个红旗；追逐是单独的小选择。代表人员只有一个下一次接触，所以一个空白只有在答案改变他们下一步做什么时才值得追逐——一个无法推动计划的红旗无论看起来多么严重都不值得追逐。评级工具，而不是红旗：同一个空白根据代表人员如何关闭它可能是昂贵的或便宜的。

这里的努力是代表人员的时间、在请求上花费的买方善意和答案到达前的日历延迟——永远不会是价格。

- 效率（默认顺序）：`桌面检查 > 一个问题 > 访问请求 > 第二个数据点 > 记录修复`
- 价值：`访问请求 > 一个问题 > 桌面检查 > 记录修复 > 第二个数据点`
- 努力从多到少：`记录修复 > 访问请求 > 第二个数据点 > 一个问题 > 桌面检查`

| 环节                                                                                                                          | 它关闭什么                                                                                                 | 努力                                                                   | 答案改变了什么                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 桌面检查 - 从代表人员已经持有的记录中关闭它：日历、已发送邮件、CRM字段历史记录、参会人员名单                                      | 线程覆盖范围、关闭日期推动、销售人员拥有的时间线、延迟和出席趋势、笔记变薄                                       | 零；无善意；答案已经坐在代表人员自己的记录中 | 重新评级证据基础本身——一个薄或错误的记录会破坏所有其他发现，所以这一环节控制了其余部分    |
| 线索中的一个问题——由电子邮件或在已经预订的通话中回答的一个诊断问题                     | 决策过程、预算所有者自己的话、阻碍者的实际反对意见、下一个预定步骤、量化影响                                     | 准备一个小时、一个请求的善意、数天的延迟                    | 通常翻转预测类别并命名下一次会议                                                          |
| 访问请求 - 请求买方花费他们自己的资本：一个介绍、共同决策者、缺失的功能、一个共同拥有的计划 | 经济买方从未见过、共同决策者未被咨询、倡导者到权力的范围、来自一个部门的要求                                    | 一周或更长时间的延迟、真实的善意，且不可拒绝                  | 任何环节中最多——请求既是确认也是补救，拒绝本身就是一个已验证的发现 |
| 第二个数据点 - 等待下一个回复差距、推动或参会人员名单                                                                                   | 两个点记录无法评级的所有趋势标志                                                        | 零小时，但日历延迟的四分之一                       | 现在很少——答案通常在它旨在通知的预测电话之后到达                                    |
| 记录修复 - 填补这个交易的日志，然后保持笔记达到可评级标准                                              | 今天在这个交易上没有内容                                                                                     | 一个持续的工作岗位                                                           | 下一次通话没有内容；随着时间推移，在每个交易的后续审查中累积                                            |

删除，而不是降级：一次完整的重新发现通话关闭几个空白。这个技能对每个空白发出一个问题，一次通话中五个问题看起来像审问——它烧掉的是访问请求需要的精确善意。将一个真实的问题集路由到`mbfinotti/sales-skills@sales-discovery-questions`。

这个顺序会饿死：

- 访问请求：最高价值，最高努力，所以它在效率轮次中输掉。这是这里比例思维的失败模式，因为未满足的权力会杀死后期交易，而廉价的环节报告进展。当交易在承诺中，或下一个阶段门是决策会议时，将其提升为第一个：没有桌面检查可以清除否决。
- 记录修复，也是。当同一交易的连续两次审查中未知占主导地位时，提升它。

根据你对这笔交易和这个代表人员已经了解的内容重新排序，并在报告中说明哪个事实移动了哪个环节：

- 一周内的预测电话提升访问请求，并使第二个数据点变得毫无价值。
- 一个当天回复的倡导者会压缩一个问题的环节的延迟，提升它高于桌面检查。
- 携带三十笔交易的代表人员停留在前两个环节；携带三笔交易的代表人员可以在每个环节上承担一个访问请求。
- 面谈中"修复习惯"的答案将记录修复从最后提升到第一个。
- 覆盖单个通话的笔记使桌面检查返回除未知外的空白——从问题环节开始。

## 响应顺序：如何处理一个确认的红旗

仅适用于红色和琥珀色。一个未知没有确认的内容可以响应；它回到上面的追逐顺序。

- 效率（默认顺序）：`交易它 > 工作它 > 重新预测它 > 升级它 > 淘汰它`
- 价值，作为解封的交易或周期小时数：`升级它 > 交易它 > 工作它 > 淘汰它 > 重新预测它`
- 努力从多到少：`升级它 > 工作它 > 交易它 > 重新预测它 == 淘汰它`

这个联系是真实的：重新预测和淘汰都花费近零代表人员时间，零买方善意，和一个内部更新。它们在代表人员花费上是真正相等的，它们之间的区别仅在于可逆性，价值轴携带——所以仅凭努力不能在它们之间做出选择。

| 环节           | 它是什么                                                                                                        | 努力程度                                                                     | 它能买到什么                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 交易它       | 让修复成为买家已经想要的下一件事的价格 - 提案、范围会议、定价                                                              | 一小时来构建；没有新的善意，因为买家的要求资金它  | 标志在原本就会发生的步骤中关闭                                                                    |
| 处理它        | 将目录播放作为自己的触摸运行                                                                                     | 一小时的准备，一个善意的触摸，几天的延迟                                | 一个标志关闭；默认情况下，当没有东西在交易桌上时                                                    |
| 重新预测它     | 将交易移出承诺期，并命名移动它的标志                                                                               | 近零小时，没有买家善意，一些内部资本                                  | 预测真相，而不是交易进展 - 对紧急情况或预算标志无法清除的诚实答案                                      |
| 升级它        | 带来一个经理或执行赞助人打开代表无法打开的门                                                                        | 政治资本，一周的协调，大约每笔交易花费一次                               | 一切都是访问阻塞；没有什么信息阻塞                                                                    |
| 淘汰          | 将剩余周期的剩余时间返回到管道的其余部分                                                                            | 近零                                                                  | 整个剩余周期 - 它是不可逆的，所以在任何可恢复的标志上是错误的                                          |

删除，而不是降级：将标志提升给买家作为一个没有要求附加的担忧。它消耗善意，并返回没有证据；每个目录播放都带有一个要求，原因就在于此。

这个顺序会饿死：

- 升级：它看起来很昂贵和政治，所以效率永远不会选择它，而且它独自修复的标志（经济买家从未遇到，阻塞未解决）是那些在后期杀死交易的标志。当阻塞是访问而不是信息时，推广它高于交易和工作，当赞助人至少被问过两次，并且阶段门落在当前期内时。
- 淘汰，出于同样的原因。在一个命名的不可恢复的标志上推广它，永远不会在标志计数上。

这两个顺序都不是法律。两者都会随着交易、季度和执行者而变化：一个有投入的执行赞助人的代表会廉价升级，没有赞助人的代表不应该围绕它计划，季度末会促进交易和重新预测，而不是任何具有一周延迟的东西。

## 调用和输出形状

典型的调用：

- “这是我顶级交易的六周笔记 - 我错过了哪些红旗？”（笔记随后粘贴）
- “在我提交机会之前，请查看这个机会的活动日志 - 这笔交易真实吗？”
- “单线程检查：我在这封电子邮件线程中拥有的所有交易信息。”

交付一份报告（包括一个负面示例的工作示例，在 [references/example-review.md](references/example-review.md)）：

```
交易红旗审查 - <交易>，审查 <日期>，笔记涵盖 <周期>
快照   : 规模、阶段、周期年龄、动作（B2B/B2C） - 如所述，或“不在笔记中”
时间线   : 从笔记中重建的日期事件；记录在哪里变薄
红旗    : 标志 - 严重性 - 逐字证据引用 - 一个补救措施 -
             它的响应环节，以及是否提升或降级它
琥珀    : 与红旗相同的形状
观察    : 标志 - 逐字证据引用 - 什么会确认或清除它
差距    : 标志 - 一个诊断问题 - 它的追逐环节；按追逐顺序列出，每单位努力价值最高优先
清除    : 标志 - 清除它的引用
风险检查 : 两个管道审查问题（Armand Farrokh，30MPC）：交易清除其过去阶段标准的方式是否有风险，以及为下一个阶段的计划是否有风险 - 从发现中回答
裁决    : 有证据的 vs 仅仅缺席的；单个下一步行动，这是重新排序后追逐顺序的顶部。永远不会是一个赢率或方法评分。
```

## B2B 和 B2C

在两者中都是相同的，明确说明而不是暗示：

- 证据规则：引用它，否则它是未知。
- 双轴分级。
- 否认证据检查。
- 整个痛苦和价值、参与度和紧急性质量的逻辑：快乐的耳朵、未量化的影响、卖家拥有的时间表、重复的推动以及越来越长的响应延迟在两种动作中都以相同的方式阅读。

在 B2C 和高速度交易性交易中真正不同 - 不要只是重新标记 B2B 列表：

- 单线程不是红旗：这些交易是设计为单利益相关者的。相应的利益相关者风险是一个未咨询的共同决策者（合作伙伴或配偶，其批准是假设的但从未证明）和未验证的支付能力（融资或信用从未确认）。
- 令人信服的事件更可能是个人或季节性的（搬家、生活事件、家庭设定的截止日期）而不是财政的；一个真实的日期触发仍然比“他们看起来很渴望”更好。
- 采购、安全和法律审查通常不存在；流程组合并为一个问题 - 是否有一个约定的日期下一步？购物车或试用放弃和延长回复差距成为主要的参与度红旗。
- 将企业启发式应用于交易性交易本身就是假阳性（见下文），反之亦然：通过交易性响应速度标准判断长期周期企业交易会制造不是真实的幽灵红旗。

## 失败模式和假阳性

| 过度反应                                                   | 修复                                                                                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 将未知视为红旗                                             | 未知意味着笔记是沉默的，而不是交易是破裂的；它值得一个问题，而不是升级                                             |
| 根据企业标准对小型交易性交易进行红旗                        | 通过访谈校准；多线程和共同行动计划红旗在适合它们的动作以下关闭                                              |
| 在笔记涵盖一个电话时称交易为单线程                          | 一个电话的笔记证据一个电话；声明未知，并询问谁还参与                                                 |
| 从一个未回复的电子邮件中推断冠军离开                        | 一个扩大的差距模式是证据；一个沉默不是 - 最高评级为假设，并带有引用                                          |
| 根据红旗计数淘汰                                              | 计数合并了两个轴，计数不是一个决策规则；响应顺序命名什么值得淘汰                                             |
| 单向棘轮 - 记录风险而不检查清除                            | 运行第 5 步对于每个红旗；无法输出清除的审查将始终发现一个注定要失败的交易                                       |
| 将慢速、共识驱动的购买视为不参与                            | 一些购买文化和监管流程确实合法地缓慢和安静；权衡节奏与该细分市场的规范，而不是一个普遍的规范                     |
| 裁决交易而不是笔记                                          | 裁决必须区分“有证据的风险”与“记录薄弱”；当未知主导时建议更好的笔记卫生 |

## 质量门

对照所有六个评分完成的报告。通过阈值：6/6 - 迭代直到没有任何失败。

1. 100% 的红旗和琥珀发现都带有来自笔记的逐字证据引用。
2. 每个目录组将其所有红旗解决到一个状态 - 没有跳过，包括清除和未知。
3. 没有未知出现在红旗、琥珀或观察中；每个未知都带有 exactly 一个诊断问题。
4. 每个红旗和琥珀发现都带有 exactly 一个补救措施。
5. 每个严重性都根据这笔交易的大小、周期和动作进行证明 - 没有固定表的严重性。
6. 差距按追逐顺序列出，红旗/琥珀措施命名响应环节，两者都根据访谈答案重新排序，并声明移动了环节。

## KPIs 和测量

如果随着时间的推移，在审查的交易上：

- 滑动率（关闭日期被推过承诺期）下降。
- 越来越多的被标记的交易在下一个阶段之前关闭红旗。
- 审查交易上的预测准确性比未审查的交易提高。
- 来自一个审查的未知在下一个审查中转换为验证或清除。

在相同交易的审查中不断上升的未知计数意味着笔记卫生，而不是交易质量，是首先要解决的问题。
