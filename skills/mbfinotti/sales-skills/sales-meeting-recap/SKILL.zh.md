# 会议纪要

将用户的通话笔记转化为两种成果：一份买家将通过回复来确认的纪要邮件，以及在交易复杂到需要共享计划时产生的相互关闭计划项。组织规则是Armand Farrokh的（30MPC）：纪要邮件恰好回答两个问题 - "你是否清楚地说明了潜在客户下一步需要做什么？"以及"你是否提醒他们为什么同意采取行动？"其他一切都是装饰，"没有什么应该妨碍我们希望他们做的事情"。

第二规则：纪要是支持销售团队的内容。购买小组只给任何单一供应商大约5-6%的采购时间（Gartner 2017 B2B买家调查），所以邮件在销售代表从未进入的会议室中做了大部分销售工作 - 写作时要考虑转发。

范围边界：

- 仅使用用户提供的笔记、转录或描述。
- 永远不要评分或评论通话是如何进行的 - 这属于`mbfinotti/sales-skills@sales-call-review`。
- 销售到客户成功的售后交接完全不在范围内。

## 面试

每条消息问一个问题；提供多个选择；跳过笔记或上下文已经回答的内容。

1. 谁参加了通话 - 双方姓名和角色？哪些买家联系人应该收到纪要？
2. B2B还是B2C？购买委员会，还是单一决策者？
3. 交易阶段：首次联系、发现、演示、提案或谈判？
4. 大致的交易规模和预期周期长度？这决定了纪要的权重以及关闭计划是否有效。
5. 通话中实际达成的协议 - 承诺、负责人、日期，如实陈述。
6. 是否已安排下次会议并附带日历邀请？如果没有，是否讨论了具体日期？
7. 是否已存在此交易的共同关闭计划，或者这次通话应该为其奠定基础？
8. 必须在何时收到纪要 - 在小时内、今天，还是明天可以接受？同小时内的回答会促进简短纪要并删除需要工作会话的内容。
9. 一次性胜利还是复合资产：这次交易的后续跟进，还是整个管道中重复的模式？复合资产会促进关闭计划和自动序列；一次性胜利会促进手写纪要。
10. 努力上限：每个纪要多少分钟，涉及多少个实时交易？紧缩上限会删除完整的共同行动计划，并将纪要限制在一个屏幕内。

每个排序都是默认值，不是法律 - 它会随着交易、管道和执行者的变化而变化。根据这些答案和您对用户的了解重新排序：一个管理着数十个小交易的代表、一个单一的策略追求，以及一个已经自动草拟纪要的CRM会反转不同的排序。删除其约束条件排除的选项，而不是将它们停放在底部，在那里它们会安静地重新出现为范围。

## 反伪造规则

承重保护。包含买家从未做出的承诺的纪要会破坏它旨在创建的共同记录。

- 永远不要编造买家从未做出的承诺、负责人、日期、报价、与会者或决策。
- 将差距视为输出，而不是填充内容：在"未关闭的差距"块中列出缺失的负责人、日期和未确认的项目，并询问用户。
- 将买家没有明确同意的任何步骤标记为"提议 - 发送前确认"。
- 重用买家自己的话来描述痛点，逐字逐句 - 他们的措辞，他们的数字。永远不要将他们的语言翻译成营销文案（从业者规则："确认，而不是总结”）。

## 纪要邮件

30MPC的3步纪要邮件（Armand Farrokh）：

1. **以下一步行动开头** - 在邮件顶部是行动项目，每个项目都有负责人和日期；使买家的项目在视觉上不可错过。
2. **回顾问题，而不是功能** - 用潜在客户自己的话重述痛点，永远不是功能列表。
3. **保持简短且易于浏览** - 整封邮件适合在一个手机屏幕上。

### 一个手机屏幕能容纳的内容

一个手机屏幕是整个预算，所以这些元素会为它竞争。按每名代表的每分钟价值排序，最佳比例在前：

1. **顶部的带日期的下一步行动块** - 几乎没有额外的分钟，是正在编写的纪要邮件的一部分。购买的是将通话与进展分开的唯一东西：买家必须在日期前做的事情。
2. **买家自己的话中的痛点** - 当笔记捕捉到引言时几乎为零，当笔记没有捕捉到时，通过转录进行一次额外的处理。购买的是转发：它是幸存于销售团队内部简报中的那条线。
3. **跨委员会的发送列表** - 每个交易找到和证明联系人的分钟数，在下一个交易中从头开始重新做。购买的是本节中最大的测量效果：单线程是主要的结构性缺陷，关闭-赢得交易比联系人多67%，并且多线程将50K+交易的胜率提高约130%（Gong Labs；样本已披露，方法专有）。
4. **关闭确认问题** - 一行，"我遗漏了什么？"。购买回复，回复将纪要变成一个同意的记录。
5. **主题行少于50个字符，以下一步行动为基础** - 一行，纯文本："下一步行动 - Acme + Yourco"。购买开放和它之后的所有内容；1-4个词表现最佳（Gong）。
6. **买家要求的一个附件** - 几乎没有附加，当必须首先制作时会更长。购买对单个要求项的可信度。永远不要将附件列为行动项目。

- 价值：下一步行动块 > 买家的痛点 > 发送列表 > 确认问题 > 主题行 > 附件
- 努力程度：发送列表 > 附件 > 下一步行动块 == 痛点引言 == 确认问题 == 主题行 - 这四项在真正接近零的程度上打成平手，每项都是与邮件本身在同一过程中编写的一行或一个粘贴

比率使发送列表挨饿：它是每个交易成本真实分钟的唯一行，所以分钟上限会首先删除它。无论比率如何，一旦笔记中提到多个买家利益相关者，就立即提升它 - 没有比联系一个从未被电子邮件联系过的联系人更便宜的替代品。

删除，而不是降级。将这些完全排除在草稿之外，因为它们在所有轴上都输了：

- 功能或特性回顾（第2步禁止它）。
- 全部会议纪要（不同的成果）。
- 像与连接很棒这样的关系散文，这看起来像自动化。

故意未排名，因为它们不花钱，适用于每个纪要：

- 将要点限制在~4个，每两个要点最多两行（30MPC）。
- 写纯文本，任何电子邮件客户端都以原样渲染 - 没有markdown语法、标题或星号-粗体。

**何时发送**。价值：通话后几小时 > 同一天稍晚 > 第二天 > 多天。努力在每个等级上都是相同的 - 同一个邮件，相同的分钟数 - 所以没有什么可以与速度交易。总是在买家内部简报之前发送（时间规范）。

## 什么使下一步行动真实

- 真实 = **负责人 + 日期 + 可交付成果**，加上任何会议的日历邀请。缺少任何部分都意味着一次愉快的谈话，而不是进展（从业者定义）。
- 拒绝"回头"，"下周"，"很快"，"ASAP"作为日期。被迫选择击败了模糊性： "星期四或星期五？"（技术）。
- 每个项目分配一个命名负责人 - 一个个人，而不是一个团队。
- 活动不是进展：没有确认通过买家决策过程确认的额外演示和参考电话不是进展（MEDDICC）。
- 当笔记显示没有承诺的下一步行动时，不要制造一个。标记它，并规定下次接触时使用30MPC的5分钟演练（框架）："你想买吗？"，"你想什么时候买？"，"你想怎么买？" - 承诺、时间表，然后推荐的多步骤路径。

## 共同关闭计划

三个等级回答"这个交易需要多少计划"。按每名代表的每分钟价值排序，最佳比例在前：

1. **已安排的下次会议，没有计划** - 几乎没有分钟，并且是跨越整个管道的唯一等级。购买大多数交易实际需要的东西：让势头持续的地方。默认等级。
2. **在纪要中嵌入了两个或三个种子里程碑** - 在纪要上额外花费几分钟，一次一个交易。购买对纸张流程的早期了解和至少一个买家拥有的步骤，而不需要买家在文档上共同拥有之前。
3. **一个完整的共同行动计划** - 建立需要一小时，然后是一个持续的工作来通过每个通话保持当前状态，直到上线。购买委员会交易无法以其他方式获得的协调：有日期、负责人里程碑通过安全审查、法律和采购。

- 价值：完整计划 > 种子里程碑 > 安排的会议
- 努力程度：完整计划 > 种子里程碑 > 安排的会议
- 效率：安排的会议 > 种子里程碑 > 完整计划（三个轴在第一两条线上同意，在第三条线上反转 - 这个反转是整个重点）

效率顺序使完整计划挨饿：它是每个交易成本最高的等级，并且在每个比率轮中都输了，但它是目前唯一能将复杂交易粘合在一起的东西。无论比率如何，当购买委员会、多通话周期或采购或安全审查位于路径中时，都会提升它 - 大约$50K+ ACV（阈值推理：多线程回报是在$50K+交易上测量的）。低于这条线，从输出中删除等级2和3，而不是提供它们：为单一决策者交易保留在菜单上的计划会作为代表没有分钟数的范围返回。

- 30MPC的编辑立场，引用："如果你的销售流程涉及超过一次通话的关闭...你应该在每笔交易上使用共同行动计划。"（将上述等级梯子视为在那种立场之上的实际摩擦与控制判断。）
- 建立它作为一个共同拥有的文档，由代表和买家项目领导共同拥有；不可简化的列是里程碑、负责人（买家和卖家）和日期（Salesforce Salesblazer）。
- 从买家的有力事件或上线日期倒推 - 永远不是卖家的季度末。
- 延伸到签名、入职和首次衡量价值，这样计划不会被视为提取合同的工具。
- 早期暴露决策过程和纸张流程（MEDDICC / MEDDPICC，Andy Whyte）：安全审查、DPA、MSA红线、采购。"60%的交易因惯性而流失"（MEDDICC发布的统计数据）。
- 永远不要将一个完整计划交给一个没有同意共同拥有的买家：通过等级2进入等级3，然后要求工作会话和签字（Salesforce策略）。
- 证明诚实：流传的MAP胜率提升（"26%"，"57-200%"）是供应商自我报告的，没有披露的方法，并且有明显的选择偏差。至少方向性 - 永远不要将其作为事实呈现。

## B2B和B2C

在两者中完全相同，明确：

- 同一天时间。
- 负责人 + 日期 + 可交付成果。
- 反伪造规则。
- 买家的痛点。
- 纯文本格式。
- 人类化过程。
- 质量门。

消费者销售跟进实践（房地产、医疗美容、汽车、健身房、财务顾问）独立于其他技能应用于B2B之外，都集中在相同的两个纪律上：通话后约两小时回复，并根据买家实际说的话而不是通用模板进行个性化 - 上述同一天时间和买家的自己话规则不是B2B惯例延伸到B2C，它们在两者中自然存在。

四个纪要权重，按最轻到最重列出。排名是下面的效率线对，而不是这个列表顺序 - 每个权重在每名代表的每分钟中获胜会随着执行者反转：

1. **自动生命周期序列** - 一旦建立，每个交易几乎没有分钟，并且是唯一能覆盖整个管道的选项。购买覆盖，而不是买家的自己话。
2. **简短纪要** - 每个交易几分钟，一次一个交易。三到五句话，一个有真实日期的下一步行动，没有关闭计划。适合交易性、自助服务、单一决策者和B2C运动，包括高消费（太阳能、房地产、财务顾问）。
3. **向多个联系人发送完整纪要** - 每个交易几十分钟。购买多线程、可转发的记录，委员会交易使用。
4. **完整纪要加上共同关闭计划** - 一个小时，然后是一个持续的工作。购买通过买家的纸张流程进行协调。

- 每个交易的价值：完整纪要 + 计划 > 完整纪要 > 简短纪要 > 自动序列
- 每个交易的努力程度：完整纪要 + 计划 > 完整纪要 > 简短纪要 > 自动序列（序列最后是因为其成本是一次性支付，不是按交易支付）
- 效率，一个运行着数十个小交易的代表：自动序列 > 简短纪要 > 完整纪要，计划被完全删除
- 效率，一个单一的策略追求：完整纪要 + 计划 > 完整纪要 > 简短纪要，序列被完全删除

默认权重：

- B2B委员会交易：完整纪要，在上述关闭计划条件下提升为完整纪要加上计划。
- 交易性、自助服务和B2C运动：简短纪要。

为值得分钟数的交易保留人工纪要 - 在高速度运动中，它经常被完全自动生命周期序列取代（交易性销售的切割）。

## 工作流程

1. 运行面试；跳过已回答的问题。
2. 解析笔记：已同意的承诺（负责人/日期/可交付成果如实陈述）、买家的痛点（他们自己的话）、决策、开放问题以及提到但未参加通话的利益相关者。
3. 应用反伪造规则：将同意与提议分开；收集每个差距。
4. 从B2B和B2C中选择纪要权重，然后使用3步结构起草，在上述排名顺序中花费一个屏幕。
5. 选择关闭计划等级。在等级2或3，并且只有在买家表示愿意共同拥有它时，根据[references/mutual-close-plan.md](references/mutual-close-plan.md)起草或更新里程碑；在等级1，在输出中说明你选择了哪个等级以及原因。
6. 如果你的套件可以创建日历事件或发送电子邮件，提供安排下次会议并放置草稿的选项 - 在没有明确批准的情况下永远不要发送。否则提供用户可以粘贴的文本。
7. 可选集成说明：如果你的环境连接到CRM、通话录音平台或AI笔记记录器，提供提取转录作为输入并记录纪要为活动 - 拉取的内容仍然是笔记，在相同的反伪造规则下。
8. 通过你首选的人类化技能运行草稿。原始第一稿输出永远不会是最终稿。
9. 通过质量门；重写，直到每个检查都通过。
10. 提供下面的输出形状。如果你的套件具有持久内存，请存储交易的开放行动项目和计划状态，以便下次纪要从实时状态而不是空白页面开始。

## 调用和预期输出

- "这是我从Acme演示中获得的笔记 - 起草纪要邮件。"
- "将这次发现通话转化为带有下一步行动的跟进，并开始共同行动计划。"
- "为一个小交易、单个联系人提供快速通话总结。"

```
主题     : 少于50个字符，以下一步行动为基础
纪要邮件 : 纯文本；下一步行动首先（负责人 - 可交付成果 - 日期，买家项目突出显示），买家的痛点（他们自己的话），附件命名，关闭确认问题
关闭计划  : 选择的等级，加上新的或更新的里程碑（里程碑 | 买家负责人 | 卖家负责人 | 日期）在等级2或3
开放差距   : 缺失的负责人/日期，未确认的承诺标记为"提议 - 发送前确认"，用户的问题
发送列表   : 谁接收邮件以及原因（多线程检查）
```

## 质量门

通过阈值：每个检查，没有例外。重写并重新检查，直到没有任何东西失败。故意未排名：这些是及格/不及格门，不是可以相互交易的选择，所以排序它们只会暗示便宜的选项是可以跳过的。

1. 所有行动项均包含负责人+日期+可交付成果 - 无模糊日期（“下周”、“尽快”）。
2. 下次会议有实际的日历日期和邀请函，或输出将标记差距并规定进行5分钟速查。
3. 邮件内容适合一个手机屏幕，约200字以内（简短回顾：3-5句话）。
4. 主题行不超过50个字符。
5. 买方提出的痛点以原话完整呈现；任何地方均不得出现功能列表。
6. 每项承诺均可追溯到笔记，或标记为“提议 - 发送前确认”；差距将被列出，永不填补。
7. 在委员会交易中，至少有一项行动由买方负责 - 或标记卖方单方面不平衡为风险。
8. 发送列表涵盖相关买方联系人，或说明为何单个收件人正确。
9. 草稿已通过人性化处理。

## KPIs

按此顺序衡量 - 每单位设置努力的价值，最优比率优先：

1. **下一步设置率**：有预定日历下一步的开放机会百分比。CRM已持有的计数，此处唯一满分指标 - 实践者基准约80%。低于此水平，在关闭计划推广前必须修复（建议）。从这里开始。
2. **多线程率**：每笔交易中接触的买方联系人。CRM中已有（方向明确，规模是营销 - Gong）。
3. **回顾回复率** - 按交易跟踪设置一次，然后接近零。回复确认记录；按交易阶段跟踪。
4. **阶段转换和滑落交易率**：有日期下一步与无日期下一步的交易对比 - 一个管道报告可回答两者。
5. **销售周期长度** - 完整一个季度的数据才会显示结果。背景信息：40-60%的合格B2B交易以无决定结束（Dixon and McKenna, The JOLT Effect, 2.5M次对话）- 下一步纪律直接攻击这一点。

- 价值：下一步设置率 > 销售周期长度 > 阶段转换 == 滑落交易率 > 多线程率 > 回顾回复率（这两项相同，因为它们是同一管道查询在相同窗口内，且两者不会先于对方移动）
- 努力：销售周期长度 > 阶段转换 == 滑落交易率 > 回顾回复率 > 下一步设置率 == 多线程率（这对在接近零时相同：两者都是CRM已存储的计数，来自同一报告）

销售周期长度优先级最低 - 一个季度的等待会每轮降低其比率。但在决定是否在团队范围内推广回顾纪律时，仍需优先考虑；没有比这更经济的方式产生证据。并且永远不要通过供应商赢率提升声明来衡量关闭计划的成功：衡量你自己的前后对比。

## 失效模式

行是缺陷与修复的配对，非竞争选项 - 每个修复是唯一修复，因此无需排序。

| 失效                                        | 修复                                                                        |
| ---------------------------------------------- | -------------------------------------------------------------------------- |
| 将“下周再联系”作为下一步                     | 负责人+日期+可交付成果，或列为开放差距下                       |
| 每项行动均由卖方负责                       | 从笔记中展示买方负责的步骤；若无则标记不平衡                     |
| 功能堆砌而非买方痛点                       | 他们的问题，他们的原话                                             |
| 下次会议无日历邀请函                       | 实际日期加邀请函，或标记并规定5分钟速查                           |
| 委员会交易向单个联系人发送回顾               | 构建发送列表；单线程是最高结构失效                               |
| 买方从未做出的承诺                       | 反伪造规则；标记“提议 - 发送前确认”                               |
| 向未咨询的买方倾倒完整关闭计划               | 2-3个同意的里程碑，然后进行工作会并签字                           |
| 第二天发送回顾                           | 同一天，几小时内，在他们内部复盘前                               |
| 邮件正文中的Markdown格式                   | 仅纯文本                                                             |
| 长度与会议记录相当的回顾                   | 一个手机屏幕；记录是不同载体                                       |
