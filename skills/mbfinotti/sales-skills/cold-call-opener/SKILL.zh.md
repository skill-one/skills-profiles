# 冷启动开场白

草拟销售代表在说"你好"和潜在客户首次真实回应之间所说的话。开场白在潜在客户参与或拒绝时结束——之后的内容属于相邻技能（见参考资料）。关于开场白措辞的公开证据几乎完全来自两个相互矛盾的Gong数据集，以及Cognism的漏斗数据。这项技能如实报告每个来源，而不是将它们混合成一个虚假的行业基准。

## 面试

在草拟任何内容之前进行提问。每条消息一个问题；在可能的情况下提供多项选择题答案。跳过用户已经回答的问题。

- B2B还是B2C？（如果两者都是，草拟不同的开场白——痛苦框架和法律审查不同。）
- 谁接听：职位和资历？（IC / 经理 / 总监-副总裁 / 高管 / 企业主 / 消费者。）
- 产品做什么，用一句话让陌生人能理解？拒绝功能列表；一句话。
- 你认为这个人有什么痛苦，用他们自己的话来说？
- 这个痛苦假设的来源是什么：一个已验证的信号（职位发布、融资、工具变更、他们说的话或提交的内容）还是一个有根据的猜测？这决定了措辞，而不仅仅是信心。
- 电话的预期结果：预约会议 / 资格认证 / 转介给正确的人 / （B2C）报价、预约或注册？
- 名单温度：完全冷、有点热（之前的接触、入站表单）、重试？
- 如果重试：之前尝试发生了什么？
- 销售代表自然说话的方式：直接、热情、低调、高能量？（或者粘贴他们实际说话的两句话。）
- 市场或司法管辖区：美国 / 英国 / 欧盟成员国（哪一个） / 法国 / 其他？对于B2C，这会驱动强制清理——见[参考资料/消费者呼叫限制.md](references/consumer-calling-constraints.md)。
- 必须在什么日期之前预约会议？在两周内预约会议会促进最便宜的模式，并将测试限制为一个变量；三个月或更长时间会使研究密集型模式变得可行。）
- 一次性胜利还是复合资产：一个用于一次营销推广的脚本，还是团队一年的默认开场白？（一次性胜利会促进直接通话原因；复合资产会促进基于许可的模式，其排练成本一次性支付，并在每次通话后收集。）
- 努力上限：每个销售代表的排练时间，他们电话任期背后的月数，以及每个账户可负担的预呼叫研究分钟数。（近零研究分钟数会从本次运行中移除以先例-同行验证选项；第一周的代表性会促进直接通话原因到第一。）

## 开场白结构

四个部分，一个长度预算。整个开场白运行5-30秒的销售代表讲话，然后停止。

保持简短有两个原因：

- Chris Beall的框架：一个冷拨电话者在大约七秒内建立信任，因为好奇心，而不是价值，会避免触发反感。
- Jason Bay的观察，在Cognism的2025年报告中引用：只有10%的冷拨电话能持续超过2分钟。一个吃掉45秒的开场白在潜在客户说一句话之前已经花费了中位数通话的三分之一。

1. **识别** (~3-5秒)。全名加上公司。诚实、不匆忙，没有虚假熟悉感。
2. **通话原因** (~5秒)。一句话说明为什么今天给这个人打电话。Gong将测试归功于John Barrows：如果销售代表无法完成"我打电话的原因是..."，就不要打电话。
3. **痛苦假设** (~10秒)。一句潜在客户会认为是他们自己问题的 spoken 句子。规则见下文痛苦假设行。
4. **提问/过渡** (~5秒)。正好一个提问，与采访中期望的结果相匹配。然后停止说话。

工作预算：大约75个词，一个自我设定的标准，而不是一个发布的标准。用朗读计时器进行验证，而不仅仅是单独的词计数器。

## 工作流程

1. 运行采访；首先收集所有答案。
2. 如果你能够浏览网页，请验证痛苦信号（职位发布、融资新闻、公开声明）；否则请向用户索要证据。永远不要编造信号。将原始信号转化为角度，见`mbfinotti/sales-skills@sales-outreach-personalization`。
3. 进入头脑风暴模式：提出2-3个候选角度（每个=一个开场白模式+一个痛苦框架）。在三个轴上对每个候选角度进行评分，选择模式时使用：
   - 测量价值。
   - 销售代表努力（排练、现场镇定，以及它在非专业手中失败的方式）。
   - 在可以判断之前需要的对话次数。

   推荐一个并命名决定它的轴。一次问一个问题。在用户选择角度之前不要草拟任何内容。

4. 选择排名最高的模式；打开[参考资料/开场白模式与证据.md](references/opener-patterns-and-evidence.md)仅用于完整证据链，该证据链支持排名或归因。
5. 草拟2-3个变体。每个变体隔离正好一个变量（模式、痛苦措辞或提问）；一个改变两件事的变体什么也学不到。
6. 每个变体编写交付笔记（交付下）。
7. 运行你首选的人性化技能到每个变体，然后用计时器朗读每个变体。冷拨电话开场白是 speech；原始第一稿模型输出永远不会是最终交付物。
8. 对每个变体根据Self-check门进行评分；迭代直到所有项目通过。
9. 将工件在预期输出中交付，包括测试计划。
10. 如果你的 harness 具有持久内存，请记住批准的角色、痛苦假设、产品句子，以及在测试后获胜的开场白；以后的运行将跳过采访。

## 选择模式

根据每个单位销售代表努力返回的价值对模式进行排名，并大声说出排名，而不是让行顺序暗示它。这里的努力是排练时间、现场镇定，以及非专业销售代表手中模式失败的程度——一个对老兵来说很强壮而对新代表有损害的模式是高努力，而不是高价值。完整证据、归因和Gong 2018/2024的矛盾位于[参考资料/开场白模式与证据.md](references/opener-patterns-and-evidence.md)。

轴之间存在分歧，因此每个轴都有自己的行：

- 效率：基于许可 > 直接通话原因 > 以先例-同行验证为前提 > 模式中断
- 价值：以先例-同行验证为前提 == 基于许可 > 直接通话原因
- 努力：模式中断 > 以先例-同行验证为前提 > 基于许可 > 直接通话原因

那个`==`是一个真正的平局，而不是避免通话的方式。Gong的2024年研究将这两者分开了0.06个百分点，并且没有发布每个开场白的样本量，所以数据中没有任何东西可以对它们进行排序。它们在努力上分开了。

没有合规成本轴属于这个菜单。同意和清理义务与列表和司法管辖区相同，对每个模式都一样（见[参考资料/消费者呼叫限制.md](references/consumer-calling-constraints.md)）。

1. **基于许可** - 默认的等级。
   - 价值：~11%的连接通话在Gong的2024年研究中产生了保留会议，大约是该研究得分最低的开场白的5倍。
   - 努力：大约一个小时的排练，一次性支付并在每次通话后收集。销售代表在不颤抖的情况下说出中断，然后实际上停止说话。
   - 软弱失败：匆忙，听起来像是一个道歉，这会损失该通话和除此之外的任何东西。
   - 在这里猜测痛苦路线，痛苦行有保留（见痛苦假设行）。一个猜测被断言为事实会交出前五名的拒绝"我没有你们描述的问题"（Cognism 2025）。
2. **直接"我打电话的原因"** - 最便宜的和唯一可组合的。
   - 价值：在Gong的2018年研究中大约是基线价值的两倍，这是该菜单上测量提升最小的。Gong将其描述为可以与任何其他开场白配对，所以它永远不会完全失去一轮。
   - 努力：几分钟。一句话，由John Barrows的规则测试：如果销售代表无法完成"我打电话的原因是..."，就不要打电话。
   - 当任何以下情况发生时，将其提升到第一位：一个硬性截止日期、一个处于第一周的代表性、一个重试（诚实地说出之前的尝试，永远不要假装它是第一次通话）、或者一个所有者、SMB或消费者线路。
   - 在一个同意的B2C列表上，同意事件本身就是通话原因（"你周二在我们的网站上要求了一个报价"。）
3. **以先例-同行验证为前提** - 平分最高测量价值，努力大一个数量级。
   - 努力：每个账户的预呼叫研究，加上在潜在客户现场挑战时为同行声明辩护的镇定。
   - 最难失败：一个无法支持的名人推荐或带有监视口吻的琐事会直接失去通话，参考中记录的个性化反效果模式。
   - 在提问之前说出已验证的信号。
   - 只有当所有三个都成立时，才将其提升到基于许可之上：总监或以上、一个已验证的战略信号已经在手中、并且一个已经运行过该剧本的销售代表。
4. **模式中断** - 最后一个，故意不在价值上排名。没有数据集将其分离，所以这里的数字将是虚假精度伪装的证据。
   - 努力：高。现场即兴发挥，没有可以依赖的脚本。
   - 实践者报告回报随着新奇性成为主流而衰减。报告，而不是测量。
   - 有限度使用。

**已删除，未降级。** 聊天开场白（"你好吗？"、"你今天过得怎么样？"）不在该菜单上。

- Gong数据集测量的唯一形式是针对陌生人，这会失败该技能自身的自我检查门，即虚构的熟悉感。
- 一个被限制规则排除的选项必须被移除：停泊在底部，它作为变体回归。
- 其证据保留在参考资料中作为要报告的矛盾，永远不会作为要提供的选项。

**这个顺序会饿。** 以先例-同行验证为前提平分了最高的测量价值，并且在研究成本上每一轮效率都输掉，这是比率排名的标准失败。故意在短而持久的列表上提升它，其中包含高价值的总监+账户，其中每个账户的研究是可负担的。

Gong的资历条件在此适用：特定于公司的个性化在总监+时支付最多，按电子邮件回复率衡量。因此，将其带到通话中是一个推断，而不是一个发现。

**在草拟之前重新排名。** 这个顺序是一个默认值，而不是法律：它随着上下文和执行者的不同而变化。根据你已知的用户重新排名，然后在呈现选择时说出哪个采访答案移动了哪个模式。

- 一个经验丰富的代表性会提高以先例-同行验证为前提。
- 一个第一周的代表性会将其从菜单中移除。
- 一个热名单或重试会促进直接通话原因。
- 一个很少接听的代表性（尤其是B2C，见B2B与B2C）会提高每次连接的成本，这会进一步促进廉价模式。

## 痛苦假设行

- 写一句潜在客户会认为是他们自己的话。测试：他们会自己大声说出这句话吗？如果不是，请从他们的词汇表中重写，而不是从产品的词汇表中。
- 零术语，零功能语言。该行命名问题，而不是解决方案。
- 具体优于抽象："你的SDR们正在一个已经过时的列表上预约，已经有一年了"胜过"数据质量挑战"。
- 已验证的信号：先说出观察结果，让它携带相关性——它不需要保留。
- 猜测的痛苦：将其保留为从同行那里听到的（"我在与你们公司规模相似的公司的ops负责人交谈时，他们告诉我X——我猜那也是你的任务，但你可能更清楚"。）保留使潜在客户的反对变得廉价而不是对抗性的，并将断言变成一个问题。
- 永远不要将猜测声明为关于他们公司的既定事实，也永远不要暗示销售代表没有做的研究。

## B2B与B2C

在两者中都是相同的——说出来，不要重新推导：

- 四部分结构。
- 5-30秒预算。
- 一个提问规则。
- 暂停纪律。
- 人性化通过。
- 变体测试方法。

不同之处：

- **谁回答。** B2B：采访中提到的职位代表性，通过总机或直接拨号。B2C：拥有个人线路的人——Hiya的2026年呼叫状态（对六个国家12,000多名消费者的调查）发现只有14%的人会立即接听来自未识别号码的电话，因此预期较低的回答底线和更多的重试。
- **痛苦框架。** B2B：代表性在业务结果上衡量的业务成果。B2C：用普通家庭词汇中的金钱、时间或麻烦——完全没有商业词汇。
- **提问。** B2B：通常是预约会议或转介。B2C：通常是对话本身——报价、预约、注册——因此过渡通常继续同一通话，而不是预约未来通话。
- **监管清理。** 消费者呼叫处于基于同意的体制下。B2B大部分被排除在外，有例外。在任何B2C列表被拨打之前：检查司法管辖区的"不要呼叫"注册册和同意基础，并保留内部"不要呼叫"列表。司法管辖区的具体细节（美国、英国、欧盟成员国（哪一个）、法国——包括法国在2026年8月11日生效的消费者自愿加入制度）位于[参考资料/消费者呼叫限制.md](references/consumer-calling-constraints.md)。事实性笔记，不是法律建议：在活动之前咨询律师确认。

## 交付

- 节奏：不匆忙。匆忙会传递恐惧；识别部分尤其要慢慢说。
- 语气：匹配采访中销售代表的自然语调——一个在别人声音中的脚本读起来像脚本。
- 站起来，或者坐直：呼吸支持通过电话线传递能量。练习建议，而不是测量效果。
- 提问后：暂停，不要填充沉默。提问结束了开场白；接下来说话的人是潜在客户。
- **节奏。** Gong的呼叫数据显示成功的冷拨电话不是审问。
  - 提问的数量没有统计学差异。
  - 成功的呼叫包含更长的销售代表独白（37秒与25秒最长爆发）。
  - 潜在客户的 longest turns 在成功的呼叫中更短（3.5秒与8秒）。
  - 成功的呼叫显示每分钟有77%更多的说话者切换。

  一起阅读，这意味着：将开场白作为一个自信的独白交付，然后干净地停止。之后保持快速，短回合，快速来回。

  不要将其理解为"打断潜在客户"。不要教"多听少说"，好像数据支持它。在这些指标上，它指向相反的方向。

## 变体和测试

- 每次运行产生2-3个变体，永远不要一个。每个变体隔离正好一个变量。
- 测试顺序：在可比列表段上以交替块运行变体，同一天，同一销售代表。
- 判断阈值：在每约100次对话之前不要比较变体——一个工作惯例，因为没有供应商发布冷拨电话样本大小基准。在Cognism的2025年连接到对话率（65.6%）下，那是每个变体大约150个连接。这是模式菜单上每个选项的单位价格：每个变体保持成本在它说任何话之前再约150个连接。
- 将小差距视为噪音：在Choosing the pattern中，那个将前两个模式平分的0.06点差距是这种规模的测试无法分离的。一个这么小的差异是一个抛硬币，而不是赢家。

## 测量

在拨号器或通话录音工具中跟踪每个变体：

- **连接对话率** - 成功连接转化为实际对话的比率。基准：65.6%（Cognism 2025），计算自41,936次连接产生27,513次对话。这是发起者的自有KPI：发起者是将搭讪转化为对话的关键。
- **每次对话预订的会议数**。基准：2.7%行业平均水平（Cognism 2026）；Cognism内部团队报告为11.3%，因此平均值是下限而非上限。
- **早期挂断率** - 连接在约30秒内结束的比例。没有供应商将此作为基准KPI发布；根据通话时长分布计算（见下方的来源排名）。
- **对话时长** - 仅与团队自有基线进行趋势对比。跨供应商平均值存在分歧（Cognism 82-93秒；Chorus 132秒；Gong 5分50秒成功 vs 3分14秒不成功），因为每个供应商衡量的是不同的人群，定义也不同。

这两个数据来源存在差异，且坐标轴不一致：

- 价值：录音通话时长数据 > 拨号结果。Chorus发现40%的冷呼被错误分类或根本未分类，因此分类结果更多地反映了销售代表的习惯而非潜在客户的行为。
- 合规成本：录音通话时长数据 > 拨号结果。录音会触发披露义务和保留决策，且同意规则因司法管辖区而异（美国多个州需多方同意，欧盟和英国需通知义务）。分类结果则不会触发这些义务。将其成本计算为强制执行的审查 - 每个拨打的司法管辖区一次法律批准 - 并考虑可逆性：录音无法撤销。
- 默认：录音时长数据，在测试开始前每个司法管辖区完成披露。若录音未获批准，则回退至仅使用分类结果，并标记早期挂断数为方向性数据。

此技能追求的迭代目标：连接对话率达到或超过65.6%的Cognism基准，每次对话预订的会议数达到或超过2.7%的平均水平。若某个变体在评判阈值后低于任一指标，则更改一个变量并重新运行。持续迭代直至变体同时满足两个指标。

## 自检门

每个变体在交接前必须通过所有项目。迭代 - 重新起草，重新运行humanizer - 直至无一失败。

1. 在30秒或更短时间内自然语速朗读（约75字工作容量）。
2. 恰好一个询问，与用户在面试中选择的成果匹配。
3. 痛点句通过“他们会亲口说出来吗”测试；无术语；无功能语言。
4. 猜测的痛点有所保留；验证的痛点指明真实信号。
5. 无虚构的熟悉感；无暗示的既往关系；无销售代表无法证实的调研声明。
6. 身份识别诚实：全名加公司。
7. 以询问结束，随后是计划中的停顿 - 无拖沓的填充。
8. humanizer通过后朗读人类声音。
9. 仅限B2C：名单已根据司法管辖区清理，且同意基础已确认。

## 常见失败模式

| 失败                                                         | 修复                                                                                                                         |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 听起来像脚本                                                | humanizer通过 + 朗读；缩写；销售代表在面试中的自有词汇                                                              |
| 开场过长                                                    | 切割为一句痛点句；30秒计时器是法律                                                                                          |
| 虚假的熟悉感（对一个陌生人问“你最近怎么样？”）           | 引用真实信号或放弃声明；闲聊开场不在模式菜单上，不是判断决定                      |
| 堆叠问题                                                   | 一个询问；将其他问题留待探索                                                                                              |
| 询问销售代表不需要的时间（“我能占用30分钟吗？”）            | 询问正在进行的对话                                                                                                          |
| 功能倾倒                                                    | 开场点明痛点，产品描述仅限于一句话                                                                                          |
| 为致电道歉（“抱歉打扰你”）                                 | 接受打断 - 基于权限的模式无需道歉命名它                                                                                      |
| 邀请退出（“我打中你忙吗？”）                               | 两个Gong数据集都排名更好的选项（2018年0.9%；2024年2.15% - 两者对基线存在分歧，而非排名） |
| 将开场视为探索                                                | 一个假设，一个询问；问题电池属于参与后                                                                                       |
