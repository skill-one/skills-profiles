# 客户健康评分

设计、验证和维护一个综合评分，让售后团队知道哪些账户正在流失，哪些账户适合进行扩展对话。在ChurnZero的2025年客户收入领导力研究（约800名CS和售后领导者被调查）中，73%的人表示他们当前的健康评分并不能可靠地预测流失。

- **表现型评分**。有人选择十个指标，凭直觉进行加权；CS团队会忽略结果，因为它什么也预测不了。
- **预测型评分**。它的权重来源于实际流失的账户在流失前的行为，然后在回测中证明自己。

这项技能拥有将一个转化为另一个的组成和验证：

- 归一化
- 加权
- 衰减
- 分段
- 段落校准
- 覆盖治理
- 将每个分段连接到行动方案

要向它提供哪些指标，以及每个指标的预测能力如何，是`mbfinotti/revops-skills@customer-churn-signals`所拥有的发现工作。在此将信号按类别级别处理（产品使用情况、关系/参与度、支持、商业、情感），并将发现的指标列表作为输入。

在它确实有帮助的领域使用命名规范：

- **Gainsight的DEAR框架**（部署、参与、采用、投资回报率）：一个由4-6个加权指标组组成的平衡计分卡模型，汇总为分段。Gainsight警告说，加权“对每家公司来说都非常独特”。
- **Lincoln Murphy的成功潜力**：将扩展与实现健康度联系起来（“没有客户成功……就没有扩展收入”）。
- **RFM式读取**：使用频率、使用深度和使用趋势。
- **领先与滞后分离**：采用趋势、赞助人参与度和响应时间趋势领先；流失、NRR和续约率仅在之后确认。评分领先指标。

一个综合评分，或一个单独的扩展模型：

- **一个综合评分，顶部分段控制扩展（默认）**。这是正在构建和验证的评分；第二个模型成本为四分之一，需要两个验证循环来保持。在顶部分段上触发扩展方案是主要的实践模式：低分段触发保留，顶部分段触发扩展/倡导动作。
- **一个单独的扩展模型**。只有在系统地跟踪扩展特定输入时才合理；否则它是一个未验证的第二个评分。

只有供应商案例研究支持高健康度导致扩展的因果关系；没有严格的已发表研究。将健康度视为扩展的必要但不充分条件：顶部分段为账户赢得对话，而匹配度、空白和预算决定结果。

B2B和B2C/PLG共享大部分机制：按座位归一化、趋势高于水平、每个分段连接到行动方案、回测循环在两者中都是相同的。当被问及时这样说。真正不同的是：

- **B2B**。将用户级信号汇总到账户级，并额外加权冠军/赞助人连续性：续约取决于购买组织，而不是一个用户，并且平均总使用量可能隐藏一个脱离接触的冠军（“沉默流失”模式）。风险集中在续约日期周围，因此将续约临近度纳入评分。
- **B2C/PLG**。没有CSM和续约悬崖：评分是连续的、系统驱动的，所有权位于增长/产品而不是CS运营，并且非自愿流失层（失败的付款、催收）应属于评分，因为付款失败与参与度下降相关。

## 面试

设计之前先询问。每条消息一个问题；在可能的情况下提供多个选择答案。跳过任何已回答的内容。

- 哪个动作？（a）由CSM覆盖的B2B合同续约日期，（b）PLG/自助服务连续订阅，（c）B2C消费者订阅。
- 有多少账户，以及过去12-24个月内大致有多少流失事件？（决定统计加权还是基于规则的冷启动路径。）
- 目前实际连接了哪些数据源——产品使用数据、参与/会议记录、支持系统、计费？每个数据源的覆盖范围如何？
- 信号发现是否已完成——是否有证据表明指标列出了过去流失的指标（参见`mbfinotti/revops-skills@customer-churn-signals`），还是只有直觉列表？
- 是否已经存在健康评分？如果是：先诊断还是重建？（诊断路径：参见诊断损坏的评分。）
- 存在哪些细分——企业级与中小企业，新用户与成熟用户？（一个70分的健康度对企业来说是健康的，对中小企业新用户来说是一个危险信号；细分校准是强制性的，不是可选的。）
- 团队每月实际上可以处理多少个有风险的账户？（红色分段的大小取决于这个，而不是统计数据。）
- 谁拥有评分逻辑，谁每天执行评分，谁可以覆盖它？
- 必须在什么日期之前使评分生效并执行？（一个硬日期——续约周期、董事会审查——会促进基于规则的代理和前两个信号分段；一个遥远的日期使得统计拟合权重和调查类别变得可行。）
- 一次性胜利还是复合资产——本季度的有风险列表，还是一个不断改进的模型？（一次性列表会省略衰减、细分校准和持续的校准周期；复合任务会促进所有三个，加上拟合权重。）
- 努力上限是什么——分析师小时数、谁的数据工程时间，以及CS团队会真正执行多少手动记录？（手动记录使利益相关者连续性信号真实；如果没有人会记录，那么该类别将减少到CRM自行捕获的内容。）

## 构建顺序

按顺序逐级构建评分，按分析师每小时实际防止的流失数量排序——不是按连接最便宜，也不是按回测评分最佳。这里的努力是分析师小时数、产品必须已经发出的数据、持续的再拟合，以及评分对必须执行评分的人保持的可读性：CSM无法重建的评分，无论多么准确，都是昂贵的。

- 效率：使用/采用 > 商业/计费 > 支持 > 利益相关者连续性 > 情感调查
- 价值（捕获的流失）：利益相关者连续性 > 使用/采用 > 支持 == 商业/计费 > 情感调查
- 努力程度：
  - 使用/采用和商业/计费：零成本——产品和计费系统已经发出事件。
  - 支持：一小时将工单映射到速率和趋势。
  - 利益相关者连续性：一个持续的任务——人类必须记录会议和赞助人变更，以保持输入的真实性。
  - 情感调查：建立一周，加上一个持续的任务来运行——低响应率使其不稳定。

支持和商业因每个都能捕捉到对方无法捕捉的盲点——升级集群、发票争议——并且它们不能相互替代而相互联系。

从顶部两个分段加上任何已有的发现证据开始，验证它，然后添加分段。

**这个顺序会忽视：**

- **利益相关者连续性**。最高价值的输入，捕获沉默流失，并且最差的比率，因为它依赖于人类记录接触。在任何具有续约日期的B2B书中，将其提升到第一分段，或者当一个冠军离开后绿色账户流失时——步骤5中的连续性规则使其强制执行，无论其比率如何。
- **统计拟合权重和第二个、专门的扩展模型**。两者在比率上都输掉了每一轮，但最终都是正确的。两者都需要足够大的账户基础来拟合和验证其自身结果（每个细分至少有数十个流失事件），并且两者都需要更好的信号才能存在。

这个顺序是一个默认值，不是一个法律。它随着上下文和执行者的变化而变化——在提出它之前，根据关于用户的所有已知信息重新排序：

- 一个已经发出丰富使用遥测信号的产品将使用锁定在第一分段，几乎零成本。
- 一个只有一个客户成功团队的团队会降低需要手动记录的所有内容，并提升自动化的使用和计费信号。
- 少于一百个账户完全排除了拟合权重（参见冷启动路径），并将每月CSM访谈验证作为最强的检查。

## 工作流程

1. 运行面试；在设计中收集所有答案。
2. 在任何信号讨论之前定义结果。一个预测未定义事件的评分无法验证。
   - 流失事件：不续约、取消或B2C在N天内未重新激活。
   - 实体级别：B2B的账户，B2C的订阅者。
   - 预测窗口：评分声称要预测的内容，例如90天内流失。
3. 将指标列表作为输入——来自客户流失信号发现工作，或者在没有发现的情况下，来自用户的最佳证据候选者——并将其分组到[references/signal-categories.md](references/signal-categories.md)中的类别。审计每个类别的数据覆盖范围，然后根据上述构建顺序重新排序，根据用户的答案。一次不要集成所有内容，并且删除任何可能永远不会触发行动的信号——如果它不能触发行动，它就是一个虚荣信号。
4. 根据[references/signal-categories.md](references/signal-categories.md)进行归一化：
   - 按座位/用户速率归一化（来自50个用户的500次登录与来自1000个用户的500次登录不同）。
   - 将支持和情感读取为趋势，而不是计数。
   - 在B2B中，将用户级信号汇总到账户级，并加权冠军/赞助人。
5. 根据[references/weighting-and-bands.md](references/weighting-and-bands.md)进行加权：权重来自流失与保留队列中与定义结果的关联，而不是直觉。限制每个类别，以便单个输入不能单独将账户跨分段移动，并要求至少一个利益相关者连续性输入，以便使用户信号组合在冠军离开后保持绿色。
6. 添加衰减：每种参与类型信号都随着时间的推移向中性漂移，因此沉默被读取为不确定性而不是累积的绿色。评分趋势和水平——一个下降的75分比一个稳定的60分更糟。
7. 分段：三个分段，不能再多——更多的分段听起来精确，并增加混乱。首先根据干预能力调整红色分段的大小，然后改进评分，直到相同的干预能力捕获更多流失。设置特定于细分的阈值和加权覆盖。
8. 根据[references/validation-and-kpis.md](references/validation-and-kpis.md)进行验证：对历史队列进行回溯评分，使用精确率/召回率（从不使用原始准确率——流失是类别不平衡的），并在流失前60-90天对流失账户进行回溯检查。迭代权重、衰减和阈值，直到规范部分中的通过底线清除。流失事件太少 → 在同一参考中采取冷启动路径。
9. 将每个分段连接到行动方案，并指定所有者和SLA——一个触发任何内容的分段变化是一个报告，不是一个健康评分。定义覆盖政策：任何CSM都可以使用强制原因代码覆盖；覆盖作为标记的分歧输入重新校准。
10. 发送规范（下一节），在全面推广之前与一小群人进行试点，在第一个90天内每月审查评分分布和遗漏，然后转移到持续的校准周期。
11. 如果您的连接具有持久内存，请记住批准的规范——类别、权重、分段、细分覆盖、验证结果、审查日期——以便后续校准和诊断运行从它开始，而不是重新进行面试。

## 健康评分规范

将每个参与都作为此工件交付——一份用户可以交给CS运营、RevOps和CSM团队的文档。完全工作的版本存储在[references/worked-examples.md](references/worked-examples.md)中。

```
HEALTH SCORE SPEC - <公司/产品>, <日期>, v<n>
结果      : 流失事件定义 | 实体级别 | 预测窗口
细分     : 列表 + 每个细分权重/阈值覆盖
信号      : 类别 -> 权重 | 输入（来自发现） | 归一化 | 证据（结果相关性）
衰减      : 每个类别的向中性漂移规则和窗口
汇总（B2B） : 用户->账户聚合方法，冠军/赞助人加权
分段      : 3分段 -> 评分范围 -> 连接到行动方案，每个分段的所有者、SLA
扩展      : 顶部分段门控 + 非健康条件（匹配度、空白、合同时间）
覆盖      : 谁可以覆盖，原因代码，如何覆盖输入重新校准
验证      : 回溯窗口 | 红色分段流失倍数与基准率 | 低于绿色在流失前60-90天的流失账户百分比
               精确率/召回率在红色阈值处
触发      : 分段变化警报 -> 任务/工作流；续约临近加权（B2B）
治理      : 逻辑所有者 | 执行所有者 | 数据所有者 | 审查周期 | 变更日志位置
```

关于规范本身的三个规则：

- **每个权重都带有其证据**。“采用深度趋势35%：在分析的9个季度中有7个季度流失账户在此下降”是可审查的。一个裸露的百分比是传说。如果一个权重还没有结果证据，请将其标记为临时假设，并注明验证日期。
- **规范有一个通过底线**。没有标准机构发布健康评分的数字发布线；这些底线是这项技能的惯例，因为一个清除较少的模型将无法在实时噪声中生存或赢得CSM信任。
  - 在回溯中，红色分段必须流失至少**基准率的3倍**。
  - **至少三分之二**实际流失的账户必须在流失前60-90天低于绿色。
  - 最多**~80%**的账目可能保持绿色（如果跨越，这是一个已记录的实践者红旗），独立于回溯结果。

  迭代直到所有三个都成立。拒绝发布一个看起来像装饰的评分。

- **评分是版本化的，并且拥有**。分散所有权会产生一个根据读者变化的评分：CS想要采用，RevOps想要CRM活动，产品想要功能使用，而每个人都会得到一个领域。
  - 逻辑的所有者是一个（CS运营/RevOps）。
  - CSM执行和覆盖。
  - 一个数据所有者。
  - 每个变更都记录并宣布。

## 诊断损坏的评分

当用户带着正在运行的评分到来时（“绿色账户继续流失”，“团队忽视它”），诊断每个症状，然后按以下顺序修复——不是按症状报告的顺序，也不是按最严重的错误优先。比率是每小时实际防止的流失，而最致命的错误很少是第一个回报的错误。

- 效率：连接分段->行动方案 > 按座位归一化 > 添加衰减 > 限制类别+连续性输入 > 噪声保护 == 工单读取修复 > 细分校准 > 重新从队列中推导权重 > 确定扩展门控
- 价值：重新从队列中推导权重 == 连接分段->行动方案 > 限制类别+连续性输入 > 按座位归一化 == 添加衰减 > 细分校准 > 噪声保护 == 工单读取修复 > 确定扩展门控
- 努力程度：
  - 衰减和噪声保护：近零。
  - 归一化、限制、工单读取和扩展门控：每个都需要一小时。
  - 细分校准和跨团队协调，将行动方案连接到所有者和SLA：需要一周。
  - 队列重新推导：一个持续的任务，它还需要流失账户历史，而账目可能没有。

平局合理：

- 一个未执行的评分和一个权重错误的评分都防止了零流失——它们在价值上平分，在努力上分开。
- 归一化和衰减平分，因为每个都消除了对同一账目的同一系统错误读取。
- 噪声保护和工单读取是两次应用相同的滞后趋势机制，每个都买回了不同口味的CSM不信任。

表格的顺序与之匹配。

| 症状                                             | 可能故障                                                                                     | 解决方法                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| CSMs忽略或默默不信任分数                          | 没有有线播放；没有门控覆盖；无法解释的权重                                         | 线路频段->播放；允许带原因码的覆盖；发布权重证据                  |
| 大账户总是看起来有病（或总是健康）                | 原始计数而不是比率                                                                      | 按座位/用户标准化；与同规模账户进行基准比较                                 |
| 分数很少变动；大部分书籍为绿色                    | 没有衰减 - 老的正向信号永远累积                                                   | 衰减参与信号至中性；每月重新检查分布 (>80% 绿色 = 故障)      |
| 冠军离开；账户保持绿色数周                       | 单类别主导 - 单独使用使用率即可保持绿色                                           | 限制类别份额；需要能够单独拉低频段的利益相关者连续性输入    |
| 分数每周在频段间波动                           | 单点噪声被视为信号                                                             | 分数滞后窗口趋势；在频段变更触发前需要连续两次读数        |
| 高接触账户在工单量上标记为红色                  | 工单计数被视为风险                                                                        | 率正化工单，读取趋势；将零工单视为可能的脱离，而不是健康 |
| 相同分数在不同账户意味着不同的事情               | 一个全球模型覆盖不同的细分市场                                                            | 细分市场特定权重和阈值（企业 vs SMB，入门 vs 成熟）                |
| 绿色账户不断流失                        | 表演性权重 - 直觉，而不是结果相关性；缺少关系/情感输入                               | 从流失vs保留队列中重新推导权重；添加利益相关者连续性输入        |
| 顶级频段账户从未扩展                      | 健康被视为扩展的充分条件                                                       | 在顶级频段门控扩展，但分别合格于匹配、空白和合同时间        |

重新排序这个：一个没有流失账户历史的书籍没有队列可以重新推导，所以那个层级会从列表中删除，而不是坐在最后（参见冷启动路径）。
