# 用户流失信号

识别、操作化定义、验证实际观察到的历史用户流失，并对用户自身账户中先于流失的信号进行排名。组织上的区分是领先指标与滞后指标：

- **滞后指标**（报告已经发生的事情）：流失率、失去的MRR、下降的NPS。
- **领先指标**（在取消前几周出现，留出行动时间）：登录减少、功能采用范围缩小、关键用户变得沉默。

每个候选指标都必须通过一个两部分的行动性测试，才值得发布：

1. 它触发得足够早，以便有人可以干预。
2. 有人实际上可以对其采取行动。

晚触发的事件——失败的付款、降级请求、采购延迟、续订日期滑移——是确认触发器，它们使几周前做出的决定正式化。将它们归类为确认指标，绝不能归类为领先指标。

林肯·墨菲的成功里程碑框架是整个练习的警示：使用量不是成功。跟踪客户自身结果的进展，因为账户可能一直很活跃，直到出现“意外”的流失。

这项技能的结果是一个排名、经过验证的信号注册表；将那些信号组合成一个综合分数——权重、分数范围、红/黄/绿等级——或客户成功经理剧本、保留优惠和续订行动方案，应该使用 `mbfinotti/revops-skills@customer-health-score`。管道阶段设计、售前线索评分和销售到客户成功交接也在范围之外。

## 面试

在提出任何建议之前提问。每条消息一个问题；尽可能提供多选答案；跳过已经回答的问题。

- B2B、B2C/消费者订阅，还是两本业务簿？
- 过去12-24个月有多少流失账户？这决定了哪种排名方法甚至可能实现：回测和提升适用于小样本；WoE/IV和任何回归都需要大量数据（见排名参考）。
- 哪些数据源实际上是可访问的，以及粒度如何：产品事件流、登录日志、支持工单系统、CRM活动（会议、电子邮件）、账单记录、调查分数？按账户每天，还是只有汇总数据？
- 合同和续订形状：月度自助服务、年度、多年？典型的续订周期长度？
- 存在多少干预能力——谁对标记的账户采取行动，以及他们每周能吸收多少标记？无人能采取行动的信号不值得排名。
- 是否已经存在健康分数？如果存在：首先验证其输入信号与真实流失，或者重新构建注册表？
- 必须在什么日期之前使注册表上线？在下一个续订周期内的日期会删除所有需要新仪器和所有以下保留曲线的方法的信号。
- 一次性胜利——保存本季度的续订——还是团队持续重新校准的复合资产？“复合”将产品遥测和功能采用广度置于构建顺序的前端；”一次性“将注册表保留为CRM衍生。
- 努力上限：分析师可用的小时数、您可以实际申请的工程时间，以及是否有人会在发布后重新配置模型？没有工程时间会删除产品遥测类别；没有人重新配置会删除逻辑回归和Cox在任何样本量下。

在提出任何建议之前，根据这三个答案重新排名候选顺序，并大声说出哪个答案移动了哪个选项——用户无法追溯到其自身约束的排名读作任意。

## 工作流程

1. 运行面试；在提出信号之前收集所有答案。
2. 从 `[references/signal-taxonomy.md](references/signal-taxonomy.md)` 构建候选列表，按照那里陈述的效率顺序工作其类别——登录最近性首先，调查移动最后，产品遥测第六，除非产品已经发出每个账户的事件。删除面试排除的类别，而不是以后列出。从一开始将确认触发器标记为确认。
3. 为每个候选指标编写操作化定义：事件、阈值、观察窗口、比较基线和对账户规模和季节性的归一化。缺少五个中的任何一个的信号是不可测试的；修复定义或放弃候选指标。
4. 拉取流失账户列表，并在流失前30/60/90天重建每个候选指标的状态（对于企业行为扩展到120-180天）。如果您可以直接查询数据，请计算它；否则发出查询或电子表格步骤供用户使用，并从他们的结果开始工作。
5. 根据 `[references/ranking-methods.md](references/ranking-methods.md)` 排名：流失率提升率、中位数领先时间和每个候选指标的覆盖范围，除以该候选指标建立的成本。按该文件中声明的顺序运行方法——首先回测和提升——并在注册表清空时停止；删除面试的样本量和维护答案排除的方法，而不是将它们保留为延伸目标。领先时间是与强度一样的一流排名属性——一个在取消前几天触发的强信号会输给一个在90天外触发的弱信号。
6. 运行生存检查：对于流失的账户，每个存活的候选指标是否在60-90天前实际触发？一个在大多数流失账户前仍然是绿色的信号是盲点，而不是预测器。
7. 填充注册表（形状如下），对每个信号发布/观察/拒绝进行判断，对照通过阈值，并迭代定义、阈值和窗口，直到注册表级别的标准通过。
8. 使用户按部分验证注册表，将发布的信号交给 `mbfinotti/revops-skills@customer-health-score` 进行综合评分，并安排在下个季度流失结果存在时的重新回测。
9. 如果您的适配器具有持久内存，请记住批准的注册表——信号、定义、提升、领先时间、覆盖范围、判断、重新回测日期——以便后续重新校准运行从它开始，而不是重新面试。

## 信号注册表

将每个参与都作为此工件交付。工作版本存储在 `[references/examples.md](references/examples.md)` 中。

```
用户流失信号注册表 - <公司/业务簿>, <日期>, v<n>
基准率 : <B>% 的账户在 <窗口> 内流失；流失样本 = <N> (<周期>)
方法    : 回测 + 提升 [+ 保留曲线 | + WoE/IV] —— 按此顺序，在注册表清空时停止；删除任何被删除的方法及其原因（样本、无重新配置、截止日期）
行      : 按每单位仪器化努力的价值排序

信号      : <名称>
  类别  : 使用量 | 采用 | 座位 | 关系 | 支持 | 账单 | 调查 | CRM | 环境
  来源    : <系统类别，例如产品事件流>
  定义: 事件 + 阈值 + 观察窗口 + 基线 + 归一化
  窗口    : <观察窗口>
  基线  : <正常是什么 - 账户自己的历史和/或细分同行>
  提升      : 在此信号显示的账户中，<N>% 在 <窗口> 内流失，与基准率 <B>% (<x.x>x)
  领先时间 : 首次触发和流失之间的中位数天数
  覆盖率  : 发生此信号的前流失账户的百分比
  努力    : 零 | 一小时 | 一周 | 一个季度 | 一个持续的工作 - 仪器化并保持活跃
  置信度: 证据笔记 - 样本量，如果计算了IV，注意事项
  判断   : 发布 | 观察 | 拒绝（适用时标记为确认）

注册表级别 : 发布集在最小领先时间或更早时捕获了过去流失的账户的百分比
交接        : 发布信号 -> mbfinotti/revops-skills@customer-health-score
```

## 通过阈值

只有当所有三个都清晰时，信号才获得“发布”。将数字视为这项技能的实用底线，而不是研究常数——当样本允许时，从用户自己的数据中收紧它们：

- **提升**: 显示该信号的账户在观察窗口内流失率至少为基准率的**2倍**。较薄的边缘将无法承受实时噪声。
- **领先时间**: 中位数至少在流失前**30天**——对于企业/年度合同行为，**90天**，干预需要采购周期空间。确认触发器是豁免的，但必须携带确认标记。
- **覆盖率**: 为至少**25%**的过去流失账户触发——几乎捕获不到真实流失的信号是无论多么强的提升都是琐事。

注册表级别: 发布集组合必须至少在最小领先时间或更早时触发了过去流失账户的**至少70%**。迭代——调整阈值和窗口，添加类别，分割细分——直到它通过；拒绝会错过大多数已知流失的注册表。

## B2B与B2C

- **仅B2B**: 关键用户和执行赞助人离职，以及多利益相关者购买委员会动态——在B2C中没有内部委员会会失去成员。B2B合同条款也会减弱和延迟可见的流失事件：一份年度合同会保留不满意的客户支付到到期，因此行为信号远早于商业信号，这正是为什么领先指标在那里更重要，而不是更少。
- **共享，相同方法**: 使用量/登录减少、功能采用广度和支持情绪在B2B和B2C中都有跟踪。唯一的单位变化：B2B中的账户及其委员会，B2C中的个人订阅者。
- **B2C特定**: 付款失败是成比例上更大的流失驱动因素；取消是一个人的单次点击决定，因此领先时间压缩，干预窗口缩小；以及“因漠不关心而流失”——一个被遗忘的低成本订阅——在B2B中没有对应物。

## 常见失败模式

| 陷阱                                           | 为什么它会燃烧                                                                                                                                                                                                                                                                      | 修复                                                                                                                                                                                                                    |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 滞后指标作为领先指标发布                      | 流失率、失去的MRR、NPS下降报告过去                                                                                                                                                                                                                                               | 通过测量的领先时间对每个信号进行分类；触发器标记为确认                                                                                                                                                                 |
| 相关性而非预测                               | 指标在流失前移动，但没有预测它                                                                                                                                                                                                                                                  | 要求回测提升；使用流失账户访谈进行合理性检查                                                                                                                                                                         |
| 按比率排名会使遥测信号挨饿                     | 产品使用量和采用广度具有最高的提升和最长的领先时间，并且仪器化成本最高，因此纯效率构建的注册表全部为CRM衍生和滞后——这是由生存偏差从CRM已经持有的任何内容产生的相同注册表                                                                                             | 当事件已经存在时促进遥测，当命令是复合时，或者当廉价注册表错过70%的底线时；拉取流失账户在60-90天前的信号状态——仍然是绿色意味着盲点                                                                                             |
| 支持工单数量单向读取                         | 参与的客户提交更多工单；沉默的脱离者不提交任何工单                                                                                                                                                                                                                               | 将数量与严重性、年龄和情绪配对；将“尖峰后沉默”视为自己的信号                                                                                                                                                    |
| NPS/CSAT加权为强预测                         | 响应偏差——沉默的脱离者不回答调查                                                                                                                                                                                                                                               | 除非用户自己的回测说否则排名低于产品参与                                                                                                                                                                             |
| 供应商联络人工件                             | 客户成功经理向有风险的账户发邮件使“参与度”上升                                                                                                                                                                                                                                  | 只计算客户发起的活动                                                                                                                                                                                                   |
| 准确性作为验证指标                           | 流失者是罕见的；预测“不流失”得分很高                                                                                                                                                                                                                                          | 一旦存在任何模型，就进行精确率/召回率和PR-AUC                                                                                                                                                                      |
| 在小流失样本上过度拟合                       | 一个单一的训练/测试拆分会误导                                                                                                                                                                                                                                                  | K折而不是一次拆分；扩大结果周期                                                                                                                                                                                        |
| 沉默流失在汇总中丢失                         | 慢慢按账户淡出在账簿级报告中是看不见的                                                                                                                                                                                                                                          | 每个账户对其自己的基线进行趋势分析，而不是汇总                                                                                                                                                                        |
