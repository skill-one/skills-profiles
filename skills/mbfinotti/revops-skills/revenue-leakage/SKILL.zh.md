# 收入泄漏

追踪特定漏斗实例中记录和资金如何无声地流失，证明每笔损失都是真实的，估算可收回的金额，并按负责人对修复措施进行排序。

- **生命周期视角**：Winning by Design的蝴蝶图（winningbydesign.com/bowtie）。泄漏贯穿获取、入职、续订和扩张等阶段，而不仅仅是销售阶段——大多数团队过度检查顶部，而从未核对后半部分。
- **后期泄漏**：MEDDPICC的“纸质流程”要素（meddicc.com/meddpicc）指出了经典的后期泄漏——在口头同意和签署合同之间死亡的交易。
- **工作方法**：将流程挖掘应用于漏斗自身的事件日志，这是Celonis推广的方法。根据实际运行的时间戳重建流程，而不是根据记录的流程图。

## 基本规则

- 追踪，永不重新设计。阶段设置、路由规则、评分模型和交接流程是输入。如果其中一个是缺陷，请用一句话说明，并路由到匹配的技能在参考中——不要在这里重建它。
- 可交付成果是泄漏登记册，而不是卫生检查清单。过期交易计数、缺失字段和推送计数是定位泄漏的输入信号；将它们报告为发现是另一项技能的工作（`mbfinotti/revops-skills@sales-pipeline-hygiene`）。泄漏询问记录和资金如何未说明原因地流失，以及其价值是什么。
- 除非通过以下三重分类，否则没有什么是泄漏。将健康的淘汰计为泄漏是最常见的错误发现。将数据捕获差距误认为漏斗流失是第二常见的错误。
- 估算可收回的金额，而不是毛额。将停滞交易的毛漏斗价值报告为“泄漏收入”是这些报告失去财务信誉的标准方式。
- 对一个漏斗实例、一个时期和一个入口队列保持一致。跨团队、漏斗或季度的程序级模式不在范围内。
- 为每个数字阈值标注其来源：已发布的实践、从业者共识或从用户自己的数据中推导出。永远不要将供应商启发式算法呈现为行业常数。
- 警告以下流传的速度到潜在客户统计——携带它们的供应商页面引用了什么：
  - “5分钟内回复 = 100倍可能”
  - “21倍可能合格”
  - “平均B2B回复时间是42小时”
  - “38%的潜在客户从未回复”
  - “391% / 60秒规则”

《HBR 2011年论文“在线销售潜在客户的短暂生命”》（Oldroyd, McElheran, Elkington）是真实且可引用的证据，证明响应延迟很重要，但通常附加到它的具体倍数无法验证。测量用户的响应时间与转化曲线，并从中推导出阈值。

## 守恒测试

进入漏斗步骤的每条记录必须通过一个可计数的可数结果离开：

- **推进**
- **有记录理由的关闭失败**
- **淘汰/回收有记录理由**
- **仍在该步骤的预期停留窗口内**

按转换构建核对：

```
进入 = 推进 + 失败(理由) + 淘汰(理由) + 仍在窗口内 + 剩余
```

每个非零剩余都需要解释。在称其为泄漏之前，请运行三重分类：

1. **真实泄漏** - 记录因流程、系统或所有权原因停止移动（从未联系、从未接受、窗口期后停滞、从未开票）。只有这些才会被估算和排序。
2. **健康淘汰** - 记录出于合法原因离开，并且退出已记录。不是泄漏。零淘汰的漏斗不健康；它是未过滤的。
3. **数据捕获差距** - 记录实际进展但系统从未记录：未跟踪的步骤、存放在收件箱或电子表格中的工作、缺失的时间戳、在从未写回系统的系统中完成的转化。流失在数据中，而不是漏斗；修复是仪器，这里的“修复漏斗”什么也修复不了。

**未跟踪步骤检测是标志性动作。** 对于每对相邻的系统或所有者，询问中间发生什么，以及是否由人工手动完成。在任何收件箱、电子表格或聊天线程中执行的步骤都没有时间戳，因此没有可衡量的流失——将此类步骤视为可疑泄漏点，直到仪器化或证明通过。不产生记录的步骤没有可衡量的泄漏；将其标记为仪器化差距，而不是猜测数字。

## B2B和B2C / 自服务

- **B2B销售引导**：泄漏点是人工操作点——回复、路由、接受、推进、追踪签名。存在代表拥有的管道，因此剩余与所有者关联。
- **B2C / 自服务 / PLG**：漏斗的大部分部分没有代表拥有的管道；机制是技术而不是人工——试用和结账步骤流失、支付失败和催收差距、非自愿流失、自动续订遗漏。非自愿流失占总订阅流失的20-40%（Baremetrics，引用Paddle研究），对B2B SaaS特定为2-5%（Baremetrics自己的平台数据——供应商聚合，不是独立研究）。
- **两者之间完全相同，无需修改**：守恒核对本身、三重分类、可收回美元估算规则，以及未跟踪步骤无法测量，直到仪器化的规则。只有泄漏点目录和证据类型不同。

## 面谈

在分析之前提问。每条消息一个问题；尽可能使用多项选择；跳过任何已回答的内容。

- 哪个漏斗和动作：B2B销售引导、销售辅助PLG、纯自服务/B2C？一个漏斗实例——哪个？
- 什么触发了这次调查：数字下降、董事会问题、交易消失、直觉？
- 漏斗的实际操作步骤是什么（不是官方图表），哪个系统持有记录轨迹的每个部分——营销工具、销售系统、计费系统、电子表格？
- 实际上可以导出或查询什么：带时间戳的阶段变更历史、所有者历史、关闭失败和淘汰理由代码、计费/发票记录、支付失败事件？
- 今天的手动步骤在哪里——哪些交接通过收件箱、电子表格或聊天消息发生？
- 每个漏斗部分由谁拥有，谁拥有部分之间的空间？
- 分析应涵盖哪个时期和入口队列？（一个队列，向前跟踪——永远不要混合年份的快照。）
- 平均交易或订阅价值，以及如果知道的话，历史步骤到步骤的转化率？
- 你愿意签署每个转换中未解释的剩余是多少？这个通过阈值控制这个数字，它必须是你的，而不是这项技能的。一个常见的参考线是每个转换进入记录的5%——一个从业者数字，不是已发布的标准。只有在没有更好的基础时，将5%仅作为占位符，并尽快从漏斗自身的核对历史中收紧它。
- 必须在什么日期之前实际收回收入——本季度关闭、董事会日期、没有固定截止日期？（硬日期删除了此轮注册中的流程重新设计，并导致警报、路由回退和已泄漏记录的重做。）
- 你想要一次性收回已泄漏的记录，还是修复以防止泄漏再次发生？（一次性促进重做；复合促进警报、路由回退和恢复序列。）
- 努力上限——仅分析师小时、工程能力可用，还是跨团队流程变更在桌上？
  - 分析师仅删除仪器化和重新设计修复。
  - 工程能力促进恢复序列和仪器化。
  - 跨团队指令是使流程重新设计可以排序的所有。

## 工作流程

1. 运行面谈；修复漏斗、时期和入口队列；确认范围边界（追踪，不重新设计）。
2. 按实际操作映射漏斗：每个步骤、系统、所有者和交接——包括手动操作。将每个未跟踪或手动执行的步骤标记为可疑泄漏点。使用[参考资料/泄漏点清单.md](references/leak-site-inventory.md)作为要调查的清单，以免遗漏。
3. 如果可以直接查询漏斗的系统，根据事件历史构建每个转换的守恒核对；否则，根据用户提供导出和记录样本推导它，并将您无法核对的每个转换标记为未测量，而不是假设它是干净的。
4. 使用三重测试对每个非零剩余进行分类，并附上每个记录组的证据：时间戳、所有者历史、理由代码或其缺失。无法分类的剩余保持标记为“未解释”——永远不要直接将其提升为“泄漏”。
5. 根据[参考资料/可收回收入估算.md](references/sizing-recoverable-revenue.md)对每个确认的真实泄漏按可收回美元进行估算，对每个数字附加置信度标签。
6. 构建泄漏登记册（输出形状中的模式），按可收回美元与修复努力的单位排序——永远不要单独按美元排序——使用[参考资料/可收回收入估算.md](references/sizing-recoverable-revenue.md)中的修复类别排序，根据面谈中的截止日期、一次性与复合、努力上限重新排序。删除用户约束排除的修复类别，并说明哪个约束删除了它。数据捕获差距有自己的部分，并带有仪器化修复，而不是美元数字。
7. 逐个部分发出报告以供用户验证，基于与[参考资料/示例.md](references/worked-examples.md)中匹配的示例。
8. 检查通过阈值；迭代，直到它成立或每个剩余的差距明确标记为未仪器化，并计划修复。
9. 如果挂钩具有持久内存，请存储漏斗映射、仪器化差距和同意的剩余基线，以便重新检查从它们开始；否则，将所有三个都放在报告的最后一部分，以便用户可以将它们粘贴到下一次运行。

## 输出形状

每个阈值和美元数字都带有来源或置信度标签。

```
收入泄漏报告 - <漏斗>, <队列/时期>, <日期>
漏斗映射       : 步骤 -> 系统 -> 所有者；手动/未跟踪步骤标记
核对           : 每个转换 - 进入 / 推进 / 失败(理由) /
                  淘汰(理由) / 窗口内开放 / 剩余 (% 进入)
泄漏登记册    : 排名 | 点 | 证据 | 分类 | 影响记录 |
                  可收回 $ (置信度) | 所有者 | 修复 | 修复类别
                  (修复类别携带排名背后的努力；排名依据
                  和任何删除的修复类别在登记册上方说明)
淘汰           : 记录因记录的合法理由保留的数量（不是泄漏）
捕获差距      : 未跟踪步骤 + 未记录的已进展记录；
                  每个差距的仪器化修复，没有美元数字
可收回总额    : 注册总和，按置信度带；永远不是毛额
重新检查       : 同意的剩余基线，重新运行日期，差距计划
```

## 通过阈值

- 每个核对转换处的未解释剩余低于与用户事先商定的容忍度——一个常见的参考线是每个转换进入记录的5%（从业者参考线，不是已发布的标准；从漏斗自身的历史中推导出更紧的线）。
- 每个泄漏登记册条目都带有证据、分类、可收回数字和置信度标签、所有者、修复和该修复的类别。
- 每个未核对的转换和未跟踪的步骤都明确标记为未仪器化，并计划仪器化修复——永远不要无声地省略。
- 分析涵盖正好一个入口队列向前跟踪；没有混合队列流计数的快照。

迭代直到所有四个成立。在必须构建仪器化才能核对转换之前，报告会说这样，并计划重新运行——这是一个通过的结果；猜测数字不是。

## 常见错误模式

| 缺陷                                                   | 后果                                                                   | 修复                                                                                               |
| -------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 混合队列年份（快照计数与队列流）                       | 剩余是算术噪声；泄漏被发明或隐藏                                      | 一个队列向前跟踪；仅比较相同时期                                              |
| 将健康淘汰计为泄漏                                     | 夸大的发现；销售不再信任报告                                          | 在称其为泄漏之前进行三重分类                                                     |
| 将捕获差距误认为漏斗流失                                | “修复”针对一个未损坏的漏斗；什么也没有改善                            | 首先在相邻系统中检查进展证据                                                    |
| 重复计算泄漏两次的记录                                | 可收回总额超过现实；信誉丧失                                          | 每条记录只计算一次，在第一次未解释退出时                                          |
| 将毛漏斗价值估算为可收回                               | 财务折扣整个报告                                                        | 可收回 = 记录 x 价值 x 从该点开始的后续转化                                       |
| 将系统缺陷归咎于代表                                     | 政治斗争，没有修复；泄漏仍然存在                                      | 将剩余附加到流程/系统所有者，而不是个人，除非所有者历史证明否则如此                 |
| 为未跟踪步骤猜测一个数字                                | 一个虚构的数字锚定了整个排名                                           | 称其为未仪器化；首先仪器化，然后在下一次运行中测量                                |
| 可交付成果滑向卫生检查清单                            | 重复卫生技能；“它值多少钱”的问题未回答                              | 每个发现都必须说明受影响的记录和可收回的美元或仪器化修复                           |

## KPI

- 每次重新运行跟踪：
  - 每个转换处未解释剩余的份额（趋势到同意的容忍度）
  - 恢复的美元与估算的可收回数字每个固定泄漏
  - 带有时间戳的漏斗步骤份额（仪器化覆盖率）
  - 从泄漏确认到修复所有权的時間
- 恢复与估算的比较是对估算方法本身的诚实检查：如果实际恢复始终远低于估算数字，请在下一次报告之前收紧后续转化的假设。
- 永远不要将“发现的泄漏”作为成功指标——它奖励了通货膨胀注册。

- 在映射漏斗时，请阅读 [references/leak-site-inventory.md](references/leak-site-inventory.md) —— 从入口到非自愿流失的漏点目录，包含每个漏点的检测信号和证据。
- 在规模化和排序时，请阅读 [references/sizing-recoverable-revenue.md](references/sizing-recoverable-revenue.md) —— 可回收美元公式、后续转化预估、置信度标签和排序规则。
- 在塑造交付成果时，请阅读 [references/worked-examples.md](references/worked-examples.md) —— 一个B2B对账案例、一个自助/PLG对账案例，以及一个做错的报告。
- 当呈现症状是预测数字错误而非记录消失时，请查看 `mbfinotti/revops-skills@sales-forecast-diagnostic`。
- 当一个漏点最终需要重新设计分配逻辑时，请查看 `mbfinotti/revops-skills@lead-routing`。
- 当一个漏点最终需要重新设计评分机制时，请查看 `mbfinotti/revops-skills@lead-scoring`。
- 当修复交接漏点的方案是重新设计销售到客服的交接流程时，请查看 `mbfinotti/revops-skills@sales-to-cs-handoff`。
