# 销售线索评分

设计、验证和维护一个按成为收入的可能性的顺序对销售线索进行排名的模型。从业者标准将评分分为两个独立的轴：

- **匹配度**（他们能购买吗）：企业特征、人口统计特征、技术特征。
- **参与度**（他们即将购买）：行为特征、产品内行为。

这种双轴模型以多种名称出现：Marketo的A-D x 1-4级分和评分网格、MadKudu的客户匹配度 x 购买可能性，以及OpenView的产品合格线索（PQL）在PLG中。

评分失败更多地是由于组织忽视——没有销售确认、没有重新校准、MQL数量被视为目标——而不是糟糕的数学，因此验证和治理是设计的一部分，而不是事后考虑。最终的评分是分配的输入：路由、区域和代表匹配属于`mbfinotti/revops-skills@lead-routing`；定义此技能的匹配度轴权重（企业特征和技术特征ICP层级）属于`mbfinotti/sales-skills@sales-icp-definition`；此技能负责将定义（加上行为参与度）转化为一个可工作的评分。

捕获-评分-路由-培养的机制在B2B和B2C/PLG中结构上完全相同。B2C/PLG和B2B之间真正不同的是：

- 主要信号源是产品内行为，而不是表单和内容。
- 没有购买委员会——一个用户的行为就可以资格化。
- 周期以天为单位运行，而不是以季度为单位。

由于这些差异，B2C/PLG中的衰减、阈值、重新评分频率和重新校准都更快。

## 面试

在设计和任何东西之前进行询问。每条消息一个问题；在可能的情况下提供多个选择答案。只有当用户已经给出了答案时才跳过问题。

- 哪种模式？（a）销售主导的B2B，(b) PLG/自助服务带销售协助，(c) B2C交易型。
- 大约每月有多少新线索，以及过去12-24个月有多少已关闭成交和已关闭失败的结果？（决定基于规则还是预测，以及可以进行多少回测。）
- 创建时销售线索记录上实际上有什么——每个匹配度字段的丰富覆盖范围、表单字段、产品事件？（评分是下游的数据质量。）
- 已经存在模型吗？如果是：重新设计，还是先诊断？（诊断路径：参见诊断损坏的模型。）
- 销售实际上每周能处理多少线索？（诚实的阈值约束。）
- 谁确认——哪个销售负责人，以及他们会对模型保持什么样的接受率底线？
- 任何欧盟或同意约束吗？行为评分在GDPR下是画像；合法基础必须记录。
- 必须在什么日期之前让模型开始评分，以及有什么在等待它？（两周内的日期排除了丰富采购和转换带阈值方法；一个季度的运行空间使两者都可行。）
- 一次性胜利还是复合资产？（一个单一活动列表来工作会停在v1权重和容量阈值；复合授权是证明丰富、完整回测和重新校准节奏（在发布后保持模型诚实）的合理性。）
- 努力上限是什么——分析师工时、CRM/营销自动化管理员访问权限、数据合同采购和法律路径，以及你能花费多少销售注意力？（没有分析师会排除从胜利/失败数据中重新推导权重和转换带方法；没有采购路径会完全删除丰富环节，而不是将其排在最后。）

将最后三个答案带到此技能及其参考中的每个排名中；它们是唯一重新排序此用户默认设置的输入。这里的每个排名都是默认值，而不是法律：它会随着上下文和执行者的变化而变化。例如，在推荐一个环节之前重新排名：

- 已存在的丰富合同会使该环节的努力简化为字段映射并提升到顶部。
- CRM的匹配度字段在表单中自我报告的高覆盖率会完全删除覆盖率菜单。
- 没有分析师会提升CRM管理员可以单独发送的每个环节，并降低需要群组分析的所有环节。

## 工作流程

1. 运行面试；在设计中收集每个答案之前。
2. 首先审计数据。测量过去90天内线索的每个匹配度字段的丰富覆盖范围。匹配度字段低于大约70%覆盖率的含义是数据库的大部分数据永远无法达到阈值——丰富上限失败。三种出路，按每单位努力的价值排序，其中努力是分析师工时、管理员工作、采购和可逆性：

   - 效率：评分未知为0 > 丰富字段 > 删除字段
   - 价值（模型可以实际操作的匹配度信号）：丰富字段 > 评分未知为0 > 删除字段
   - 努力：丰富字段 > 删除字段 > 评分未知为0
   - 合规成本：丰富字段 > 评分未知为0 == 删除字段

   努力的量级：

   - 评分未知为0：近零，一个评分配置更改可在点击中逆转。
   - 删除字段：一个小时，并且在这个菜单中最不可逆的选项——信号停止被收集，并且下一次重新校准无法在没有首先重建历史的情况下重新推导其权重。
   - 丰富：在单个线索评分之前是一个采购和合同步骤，然后是一个每个记录的持续依赖关系和一个需要永远监控的覆盖率数字。

   默认评分未知为0：它使每个薄弱记录在参与度上可评分，并本周发货。证明合规性平局：0规则和删除都不会引入新的数据源，因此都不会触发同意或来源审查。丰富会——第三方匹配度数据在GDPR下是画像输入，并且其合法基础和来源必须在评分任何人的之前记录。

   默认购买的偏见：评分未知为0会降低由于匹配度以外的其他原因而薄弱的记录——中小企业、非美国、注重隐私的买家——因此跟踪其转化作为单独的群组，并在他们仍然转化时重新推导权重。这个顺序会剥夺丰富：价值优先，努力优先，所以比率永远不会购买它，并且它是唯一一个恢复信号而不是绕过信号的环节。

   在以下情况下提升丰富：

   - 该字段本身就是ICP门本身（企业ACV的员工数量）。
   - 覆盖率在整个数据库中都很低，而不是在一个细分市场中。
   - 已经存在合同。

   完全删除丰富环节，并说明它被删除了，其中面试没有给出采购路径——一个环节停在公司列表底部，没有人批准。

3. 从结果中推导信号，而不是直觉。

   - 拉取12-24个月的已关闭成交和已关闭失败记录。
   - 比较两组之间的信号频率。
   - 保留具有真实转化差异的信号。

   直觉列表和有证据的列表通常是不同的列表。陷阱：在成交交易中看起来完整的字段，因为销售在关闭前填写了它们——验证每个信号在评分时都存在。

4. 从[references/signal-taxonomy.md](references/signal-taxonomy.md)构建信号目录：匹配度和参与度作为两个独立的评分，硬排除项作为排除项（永远不会是负分），软降级作为负分，参与度上只有衰减。
5. 根据[references/weighting-and-thresholds.md](references/weighting-and-thresholds.md)进行加权：对于销售主导的，开始于60/40匹配度/参与度；混合的50/50；PLG和B2C（行为占主导地位）30-40匹配度/60-70参与度。限制每个信号类别，以便没有单个渠道可以单独跨越阈值。
6. 首先根据销售容量设置阈值，其次是转化带，最后是百分位数作为合理性检查——这是三种方法的效率排名，而不仅仅是顺序，并且相同的参考说明了每种方法的价值和努力，然后再选择。定义层级，其中每个层级映射到一个不同的策略。
7. 根据[references/validation-and-kpis.md](references/validation-and-kpis.md)进行回测：对历史进行后评分，按评分带计算转化率，计算顶部带的提升率相对于未评分基线，运行抽查保留集。迭代信号、权重和阈值，直到通过阈值以下清除。
8. 获得书面销售确认——信号列表、阈值和接受率底线。没有它的模型是该领域最常引用的失败：营销单独构建；销售拒绝了一半的线索；双方都责怪对方。
9. 发射规范（下一节），分阶段推出——在批量评分积压之前评分实时流——并预订v2审查，在发布后60天进行，然后发布。
10. 如果你的框架具有持久内存，记住批准的规范——信号、权重、阈值、版本、审查日期——以便后来的重新校准和诊断运行从它开始，而不是重新进行面试。

## 评分模型规范

以这个工件的形式交付每个参与度——一个用户可以交给营销运营和销售的文档。完整的 worked 版本在[references/examples.md](references/examples.md)中。

```
评分模型规范 - <公司/产品>, <日期>, v<n>
模式       : 销售主导 | PLG | B2C - 匹配度/参与度权重分割，规模（例如 100 分）
匹配度信号  : 属性 -> 分数 | 数据源 | 覆盖率% | 证据（成交vs失败差异）
参与度     : 信号 -> 分数 | 衰减规则 | 每个类别的上限 | 证据
排除项     : 硬排除项，完全排除（竞争对手、学生、客户...）
负分       : 软降级 -> 分数
阈值       : MQL/PQL分数 + 其背后的容量数学
层级       : 带宽 -> 策略（T1 快速人工跟进，T2 队列，T3 培养...)
回测       : 期间，按带宽转化率，顶部带提升率vs基线，假阴性%
护栏       : 销售接受率底线，分数分布膨胀警报
治理       : 所有者，销售确认（姓名，日期），v2 审查日期，变更日志位置
```

关于规范的三个规则：

- **每个分数值都携带其证据。** "定价页面 2+ 访问 +20：在上一财年成交分析中转化率比基线高 2.8 倍" 是可审查的；一个裸数字是等待被操纵的传说。
- **规范有一个通过阈值。** 在回测中，顶部分数带必须以至少 2 倍的未评分所有线索基线转化为机会（仅发布指南要求“优于不评分”；将 2 倍视为此技能的实用底线，因为薄弱边缘将无法在实时噪音中生存）。回测的假阳性率也必须使约定的**销售接受率底线 - 60% 是常见的从业者目标，一个惯例而不是一个研究常数**——合理。迭代直到两者都清除；拒绝发布不优于未评分基线的模型。
- **模型是版本化的。** v1 是一个起点；v2 审查在 v1 发送之前预订；每个变更都被记录并通知销售。无法解释的分数比错误的分数更快地杀死代表采用。

## 诊断损坏的模型

当用户带着运行的模型到来（“我们的分数是错误的”，“销售忽视了分数”），在提出重建之前检查以下每个症状——检查是廉价的，大多数损坏的设置失败两个或三个，而不是一个。修复是在哪里做出的选择，所以行是按每单位努力的价值排序的；从上到下处理它们：

- 效率：将虚荣信号归零 > 报告正确的数字 > 添加衰减 > 修复覆盖率差距 > 添加缺失的购买路径 > 重新推导膨胀权重 > 完全重新校准
- 价值（修正后的模型赢得的机会，或停止失去的机会）：完全重新校准 > 添加缺失的购买路径 > 重新推导膨胀权重 > 添加衰减 > 将虚荣信号归零 > 修复覆盖率差距 > 报告正确的数字
- 努力：完全重新校准 > 重新推导膨胀权重 > 添加缺失的购买路径 > 修复覆盖率差距 > 添加衰减 > 报告正确的数字 > 将虚荣信号归零

| 症状                                        | 可能的故障                                                                                       | 修复                                                                                         | 努力                                                                                 |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 订阅者比真正的买家排名更高                    | 虚荣信号携带分数（电子邮件打开由于收件箱隐私功能而结构上不可靠） | 将低意向信号归零或下限；限制电子邮件类别                                    | 近零 - 分数值已经在矩阵中，仅由模型所有者单独编辑        |
| MQL数量受到庆祝而管道保持平坦                | Goodhart动态 - MQL数量成为目标，所以标准会下降                            | 报告MQL到机会转化率和管道贡献向上，永远不会原始MQL数量                     | 近零小时，但会花费政治资本在设置MQL目标的人身上         |
| 陈旧的联系人看起来和活跃的一样热              | 没有衰减 - 分数永远累积                                                               | 仅对参与度添加衰减（信号分类中的机制）                                    | 一个小时的配置，加上对数据库的一次重新评分                                    |
| 数据库的大部分永远无法达到阈值              | 丰富上限 - 匹配度字段对大多数记录为空                                             | 测量覆盖率，然后应用工作流程步骤 2 中的排名菜单——首先评分未知为0    | 默认环节近零；如果丰富被提升，则是一个季度和一个持续的工作 |
| 从未达到MQL的已关闭成交交易                | 假阴性 - 模型忽略了真正的购买路径（推荐、活动、产品使用）                           | 添加缺失的路径；跟踪假阴性率作为持续KPI                          | 一周——在成交记录中找到路径，添加信号，重新回测                        |
| MQL数量上升，MQL到机会下降                 | 评分膨胀 - 慷慨权重或虚荣信号                                                   | 从胜利/失败数据中重新推导权重；添加类别上限；提高阈值                    | 一周的分析师工作在胜利/失败队列上，加上销售重新确认新的底线      |
| 高分数停止预测胜利                         | 陈旧模型 - ICP、产品或内容自校准以来已发生变化                                     | 在最新的多季度队列上重新校准；安装漂移触发器                          | 一个季度重建，然后是一个持续的工作来保持                                      |

这个顺序会剥夺：完整重新校准——价值优先，努力优先，所以比率永远不会安排它。在ICP、定价或产品自上次校准以来已更改，或当上面两行已经修复且转化率仍然没有跟踪分数时，提升它。
