# 阶段定义审计

评估现有流程的阶段定义是否反映了买方可验证的里程碑——即买方所做、所说或同意的事项——而不是内部代表的活动，并提交一份严重程度排名的调查报告，包含重写的退出标准和安全的迁移计划。

参考框架：

- **Gartner 的 B2B 六个购买角色**（买方参考结构）：问题识别、解决方案探索、需求构建、供应商选择、验证、共识创建。
- **GitLab 的公共商业销售手册**（已发布阶段定义文档的实例）：定义、涉及人员、活动、系统执行、退出标准、交叉链接。
- **MEDDPICC 风格的关卡**：每个退出标准元素评分红/黄/绿，全部绿色才能推进。
- **Winning by Design 的 SPICED**（买方诊断视角）：其元素需经买方确认，而非代表假设。

## 基本规则

- 审计，而非重新设计。现有阶段集是输入。如果漏斗模型本身是缺陷，应指出并转至漏斗设计参考（参考）而非在此重建。
- 为每个阈值标注其来源：已发布的公司实践、从业者共识或源自用户自己的数据。切勿将供应商启发式算法呈现为行业常数。
- 警惕流传的预测统计数据（“93% 的团队无法在 5% 内预测收入”、“85% 的 B2B 公司错失预测”、“CRM 数据仅 40-60% 准确”）——这些数据流传时不注明出处，且绝不能作为事实陈述。应说明其机制：当推进具有主观性时，两位代表对相同交易进行阶段划分不同，这将破坏阶段转换数据及基于此构建的所有内容。
- 阶段记录买方的立场，而非资格评分卡。不存在“MEDDIC 阶段 1-6”（Force Management 的警告）：每个资格维度都是其自身不断更新的字段；将评分卡与阶段选择列表混为一谈将破坏两者。
- 判定任何阶段前，先分类流程类型（见下文）。用交易流程的预期来判定漏斗阶段会产生虚假发现。
- 切勿重命名或删除现有阶段值。在大多数 CRM 中，阶段历史不可变，历史记录将永久引用旧值——重命名或删除将永久破坏前后报告。应停用旧值并添加新值。任何更改后，重新检查每个阶段的预测类别映射。
- 5-7 个阶段，每个阶段 2-4 个退出标准是从业者共识范围，而非法律。阶段通过具有独特目的来赢得其位置；如果其中无任何变化，则应删除它。

## 流程类型

在判定单个阶段前，需确定流程类型——三种类型源自 The RevOps Show（Doug Davidoff 和 Jess Cardenas）：

- **开发流程**——将账户从无意向转变为有意向。阶段跟踪买方兴趣信号，而非交易机制。
- **交易流程**——意向到决策。此审计示例默认假设的经典企业 B2B 模型。
- **交易流程**——高速度、低价值、减少摩擦重点。阶段较少，标准较轻，通常自动化推进信号。

高速度、自助服务、PLG 和 B2C 团队通常根本不运行代表拥有的流程：他们运行的是面向买方的生命周期/漏斗阶段，由市场或增长部门拥有。当动作为销售辅助或向上市场时，真正的流程结构才会重现，并且漏斗和流程必须作为不同的报告结构共存，绝不能合并为一个阶段列表。

- **B2B 和 B2C 相同**：可验证性测试本身、阶段老龄化和转换诊断，以及停用而非重命名的迁移规则。
- **B2B 和 B2C 不同**：阶段数量、证据类型（产品事件和支付信号与已签署文件和安全审查），以及所有权。

B2C 阶段定义的命名从业者文献较少，因此三种流程类型框架是最佳锚点；其余内容源自用户自己的数据并注明来源。

## 访谈

在判定任何内容前先提问。每条消息一个问题；尽可能提供选择题；跳过已回答的问题。

- 复制当前阶段列表及每个阶段的书面定义，与文档完全一致。如果定义仅存在于人们头脑中，应指出——这本身就是一项发现。
- 哪个动作用于此流程：企业销售主导、中市场、高速度内部销售、PLG 销售辅助？一个流程还是多个，多个动作是否共享一个？
- ACV 范围和典型周期长度？
- 触发此审计的症状：交易卡在某个阶段、预测失误、经理对阶段划分意见不一、阶段跳过、静默关闭日期推动？
- 每个阶段的预测类别映射是什么？
- 哪些必需字段、验证规则和自动化与阶段值相关联？
- 可以导出或查询哪些数据：阶段变更历史、关闭成功/失败记录、关闭日期变更历史、按代表细分？
- 谁拥有阶段定义，谁批准变更（RevOps、销售领导、财务）？
- 是否有两人可独立评分相同交易——两位经理，或任何两位可无协商判断交易记录的评审员？Pass Threshold 的跨评审者检查需要他们。如果仅存在一位评审员，应立即指出：检查将变为针对机器记录标准的自动化事件抽查，且交付物必须声明这种替代而非声称达成协议率。
- 阶段上次变更时间及推广情况如何？
- 能否提供样本：20-30 笔近期关闭交易和当前位于每个阶段的开放交易？
- 结果必须在什么日期前提交，该日期是否落在活跃季度内？阶段变更会破坏其落定的季度，因此季度中期的截止日期会破坏 Remediation Order 中的每个迁移步骤，并仅留下标准重写。
- 您希望何时获得结果，该日期是否落在活跃季度内？一个交易前的纠正促进标准重写；累加指令促进证据管道并使定期检查非可选。
- 努力上限是什么：是否有 CRM 管理员可用，多少代表必须重新培训，流程的趋势系列能否承受切换日期？无管理员将跳过证据管道步骤；无趋势中断容忍将触发阶段切割和阶段添加。

## 工作流程

1. 运行访谈；分类流程类型并确认范围边界（审计，非重新设计）。
2. 收集证据并按 [references/audit-intake.md](references/audit-intake.md) 运行利益相关者访谈。在与人交谈前先查看数据。
3. 对每个阶段应用 [references/verifiability-test.md](references/verifiability-test.md) 中的可验证性测试：退出标准必须命名买方所做、所说或同意的事项；必须独立于代表的意见可观察；必须记录在可检查的地方。操作形式：两位经理，查看相同交易记录，能否独立就标准是否满足达成相同结论？
4. 将每个阶段映射到 Gartner 购买角色（同一参考中的表格）。标记映射到无角色（代表活动的伪装）的阶段和多个阶段挤占一个角色的阶段（冗余阶段）。
5. 计算 [references/diagnostic-metrics.md](references/diagnostic-metrics.md) 中的诊断，如果流程数据可直接查询；否则根据交易样本和访谈支持的内容推导，并标记每个未测量的诊断。
6. 按此模式记录每个缺陷为发现：**阶段 | 当前退出标准 | 判定及原因 | 严重程度 | 修复步骤及努力 | 证据 | 映射的购买角色 | 提出标准 | 迁移说明**。严重程度量表：
   - **严重**——退出标准是纯代表活动或未记录；推进是意见。
   - **高**——标准参考买方但不可验证或无可检查记录。
   - **中**——可验证但模糊；两位经理可能合理地意见不一。
   - **低**——标准合理；缺陷是命名、排序或冗余。

   严重程度是发现的值轴，而非其队列位置。通过一个措辞更改修复的严重缺陷将优先于需要阶段列表迁移的中等缺陷。为每个发现标注其落定的步骤及其努力顺序，然后按 Remediation Order 下方排序。

7. 为每个失败阶段起草重写的退出标准（措辞指导见可验证性参考），然后根据 [references/remediation-rollout.md](references/remediation-rollout.md) 构建修复和推广计划——修复按 Remediation Order 顺序排列，停用并添加迁移，预测类别重新映射，自动化审计，培训和推广形状。
8. 分部分次发出报告（输出形状下方）以供用户验证；以匹配的示例工作示例 [references/worked-examples.md](references/worked-examples.md) 为基础。
9. 检查 Pass Threshold；迭代标准及计划，直到其成立或剩余差距明确计划（例如需要完整销售周期新数据的指标）。
10. 如果您的 harness 具有持久内存，请存储阶段清单、每个阶段的判定和约定的阈值，以便迁移后重新检查从这些内容开始，而非重新访谈。

## 修复顺序

六种修复类型，按每单位努力恢复的预测准确性排序——绝不由严重程度排序，也绝不由成本最低优先排序。努力在此处是指管理员配置、重新培训每个处理该阶段的代表、历史数据迁移和可逆性。可逆性主导此列表：一个季度内更改两次阶段定义将破坏定义存在以产生趋势数据的趋势数据，因此任何触及阶段值的修复几乎都是单向的。

- 准确性恢复值（最优先）：`完全重新定义 > 标准重写 > 证据管道 > 阶段添加 == 阶段删除 > 定期检查`
- 努力（最优先）：`完全重新定义 > 阶段添加 > 阶段删除 > 证据管道 > 定期检查 > 标准重写`
- 效率（最佳优先）：`标准重写 > 定期检查 > 证据管道 > 阶段删除 > 阶段添加 > 完全重新定义`

`阶段添加 == 阶段删除` 在值上：流程类型决定哪个胜出，且无其他因素决定。

- **交易流程**：从添加中恢复更多，因为企业交易在验证和共识创建中死亡，这些工作最常被遗漏。
- **交易流程**：从删除中恢复更多，因为减少摩擦是该动作用户的设计目标，跳过的阶段比不跳过的阶段转换更好。

它们在努力上不结盟：迁移相同，仅添加要求代表提供他们从未被要求提供的证据。

1. **标准重写**——将失败的退出标准重写为指向系统已持有的字段或文档的买方行为。无阶段列表更改，无迁移，无预测重新映射。近零到一小时每个阶段，加上已发生的评审会议中的一次演练；旧措辞是文档编辑之遥。自行退休大多数严重和高发现。
2. **定期检查**——在周期性流程评审议程上的退出标准，加上季度跨评审者重采样。每季度一小时，永远。本身不恢复准确性，且通过成为阻止所有上方步骤在两个季度内退回意见的唯一步骤来赢得其排名。
3. **证据管道**——创建重写标准命名的必需字段、验证规则或证据链接，但系统未捕获。一周管理员配置加上重新培训每个接触该阶段的代表。配置上可逆，培训上不可逆。这是将通过评审的标准变为生产中有效标准的东西。
4. **阶段删除或合并**——停用并添加映射到无购买角色或重复其邻居的阶段。一周到一季度：开放交易移动，预测类别重新映射，以及阶段键控自动化清单。在切换时破坏趋势系列，且逆转它将再次破坏它。
5. **阶段添加**——为未覆盖的购买工作添加新阶段。与删除相同的迁移，加上代表从未被要求且经理从未检查的行为。一季度。
6. **完全重新定义**——将阶段集作为连贯系列重建，而非逐个单元格修补。根据基本规则在此处超出范围；转而处理它而非尝试它。

默认步骤：一次通过运行所有标准重写，然后安排定期检查。仅在重写标准命名系统未捕获的证据时才接受下一级步骤——此时管道不是后期阶段，而是使重写真实的东西。

此顺序忽视的是完全重新定义。它在值上排名第一：唯一将阶段集视为系列而非单独措辞单元格列表的修复。它在每个参与中的比率上排名最后，因此严重程度和努力排名将其无限期推迟，而流程积累了无法承载这些写得好的标准的阶段模型。

在以下情况下提升它，并转至 `mbfinotti/revops-skills@revenue-funnel`：

- 审计后少于两个阶段作为可用锚点幸存。
- 多个动作共享一个阶段列表。
- 流程类型本身分类错误。

删除被排除的步骤，而非降级它：停用的步骤在计划底部停放，稍后作为预算无人分配的范围返回。

- **无阶段定义变更的批准者**（按访谈）：从计划中删除切割和添加，并指出它们被删除。无批准者的迁移永远不会发货。
- **无 CRM 管理员可用**：以同样方式删除证据管道。

顺序是默认值，而非法律：它随上下文和执行者变化。根据访谈答案重新排序。

- **有 CRM 管理员**：将管道步骤从一周压缩到一小时，并移至定期检查之上。
- **销售团队在季度中**：删除每个迁移步骤，直到季度结束，因为阶段变更会破坏其落定的季度。
- **流程小到可手动重新阶段**：将切割和添加步骤减少一个数量级，并提升它们到管道之上。

## 输出形状

每个阈值行都带有来源标签。

```
阶段定义审计 - <流程>, <日期>
流程类型    : 开发 / 交易 / 交易 + 动作，ACV 范围，周期长度
阶段清单    : 数量与 5-7 共识范围对比；定义文档化或部落化；
               预测类别映射存在/不存在
按阶段判定  : 阶段 -> 退出标准 -> 可验证性通过/失败 -> 严重程度
购买角色映射：每个阶段覆盖哪个 Gartner 角色；无阶段的角色；多个阶段
诊断        : 转换衰减形状，老龄异常值，跳过/后退率，
               关闭日期推动计数，按代表差异（来源标签）
发现        : 记录按修复顺序排序，严重程度作为其值轴（工作流程步骤 6 中的模式）
修复        : 重写退出标准，选择的步骤和被排除的步骤，停用并添加迁移计划，
               预测类别重新映射，自动化/仪表板清单，培训和推广形状
测量        : 基线值捕获，变更后 KPI，重新检查日期
               （≥ 一个完整销售周期后）
```

## Pass Threshold

- 每个阶段都至少有一个退出标准，该标准命名了一个买方行为，并关联到记录系统中可检查的字段或工件。
- 评阅者间核查：两位经理（或两位独立审阅者）在未经商议的情况下，对10-20个开放交易样本根据重写的标准进行评分。判定必须至少在90%的交易上达成一致——这是从用户自己的数据中得出更严格标准的参考基准，而非已发布的标准。分歧点指向标准中的模糊之处；重写标准并重新抽样。
- 阶段到阶段的转化率在漏斗中单调递减，或者每个例外情况都可以通过设计意图来解释（例如，一个旨在淘汰的验证阶段）。
- 没有开放管道阶段的交易份额与其预期停留时间严重不符——从管道自身的历史中推导预期分布，而不是依赖行业常数。

迭代直到所有四点都成立。转化率和分布核查需要在新的定义下完成整个销售周期后才能被认为是可靠的——如果该数据尚不存在，请在交付物中说明，并将重新核查安排为发布后的第一个关卡。

## 常见失败模式

故意未排序：每一行是一个诊断和一个修复，而不是一个针对单个问题的修复选项菜单，因此对它们进行效率排序会排序读者的症状，而不是他们的选项。应用与每一行匹配的修复。

| 缺陷                                             | 后果                                                                | 修复                                                                      |
| -------------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 在位置重命名或删除阶段值                          | 历史报告永久损坏；自动化操作无声中断                               | 禁用旧值，添加新值；使用映射字段进行桥接                               |
| 跳过预测类别重新映射                              | 预测汇总在阶段名称看似正确时无声偏斜                               | 在任何更改后重新检查每个阶段的映射                                      |
| 资格评分卡嵌入到选择列表中                      | 阶段停止跟踪买方位置；两个结构都退化                               | 分离持续更新的资格字段；阶段 = 买方位置                                  |
| 标准以销售代表活动形式编写                        | 阶段膨胀；基于乐观情绪的推进                                     | 将每个标准重写为以买方行为开头                                             |
| 标准在纸上可验证，但无处记录                      | 通过审计，但在实践中无法执行                                     | 将每个标准关联到必需字段或证据链接                                       |
| 交易管道根据交易管道规则进行评判                  | 错误发现；增加了旨在消除摩擦的运动中的摩擦                         | 首先对管道类型进行分类；调整标准以适应运动                                |
| 超过~7个阶段或类似阶段                          | 相邻阶段无法区分；标准被稀释                                     | 合并；每个阶段需要一个独特的目的（从业者共识）                           |
| 通过记录/合规率衡量成功                          | 代表记录更多、更快、更差；数据没有更好                             | 衡量转化稳定性和评阅者间一致性，而不是记录/合规率                       |
| 在第二周评判修复                                | 没有完整的新交易周期，转化指标没有意义                             | 至少等待一个销售周期；使用30/60/90天采用检查点                         |
| 首次让代表看到标准就进行发布                    | 被忽略的标准；阶段数据质量没有改变                               | 先培训；将退出标准构建到常规管道审查中                                   |

## KPI

- 追踪：阶段到阶段的转化稳定性与单调递减，每个代表的转化方差（主观定义的最尖锐指标），阶段内中位数时间和异常计数，阶段跳过和向后移动率，每笔交易的关闭日期推计数，评阅者间对定期交易样本的协议，以及作为第一天预测与该周期最终结果绝对百分比差异的预测准确性，至少每季度一次。
- 永远不要报告采用率或记录合规率作为成功——它们衡量压力，而非准确性。
- 每季度重新运行评阅者间样本；递减的协议率意味着标准正在回到主观意见。

## 调用示例

- "我们的阶段是'安排演示'、'发送建议书'、'口头承诺'，而每笔交易都长时间停留在'发送建议书'阶段。审计我们的阶段定义。"
- "我的两位经理无法就同一笔交易是否属于第3阶段达成一致。审查我们的退出标准，并告诉我哪些阶段是伪装成代表活动的。"
- "我们正在从PLG向上游市场发展，现在销售协助交易与自助服务注册共享一个管道。在我们根据它们进行预测之前，审计我们的阶段是否有意义。"
