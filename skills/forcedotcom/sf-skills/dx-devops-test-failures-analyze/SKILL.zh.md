# 分析 DevOps 中心测试失败

解析测试失败或代码分析器违规的负载，用平实的语言解释，生成优先级排序的改进建议，并且——仅在用户明确要求时——创建一个可跟踪的修复工作项。第 1-2 部分是纯推理（不写入）；第 3 部分是可选的、需要确认才能写入。

**永远不要向用户暴露原始 JSON、堆栈跟踪或内部 Salesforce 错误代码。** 始终翻译为文件名、方法、行号和平实的描述。

---

## 前置条件

- **第 1-2 部分（分析）：** 如果失败负载已经包含上下文，则无需前置条件——这是纯推理。如果你必须自己获取负载，请运行前置条件（`references/prerequisite-checks.md`，前置条件 1-4），并通过 `dx-devops-test-suite-run`（其轮询步骤）获取执行结果。
- **第 3 部分（工作项）：** 运行前置条件 1-4。你还需要一个 `DevopsProjectId` 来归档，以及一个 `OwnerId`（指派人）。参见 `references/work-item-creation.md`。

---

## 第 1 部分 — 分类并解释每个失败

确定失败类别，然后对每个失败提取并翻译为平实的语言：违规的文件/类、方法、行号、违规的规则或断言，以及一个修复方向（不编写代码）。如果超过一个，按类别分组。

| 类别 | 描述 |
|---|---|
| 断言失败 | 测试断言失败（预期与实际不匹配） |
| 异常 | 抛出未处理的异常 |
| 代码分析器违规 | 违反了静态分析规则（例如 `ApexCRUDViolation`） |
| 超时 | 测试超出执行时间限制 |
| 编译错误 | 类无法编译 |

**输出格式：**

```text
测试失败摘要：

找到 <N> 个失败：

1. [<类别>] `<ClassName>.cls` — `<methodName>()` 在第 <N> 行
   发生了什么：<平实的语言描述>
   违规的规则：<规则名或断言描述>
   修复方向：<平实的语言建议>
```

完整的类别/模式表和代码分析器规则翻译：`references/failure-categories.md` 和 `references/code-analyzer-violations.md`。

**空/无数据情况：** 如果负载不包含失败或违规，请明确报告（例如“在提供的执行结果中未找到失败。”）并停止。不要编造失败或建议。

---

## 第 2 部分 — 改进建议

在执行完成并出现失败后运行**，不要在静态源代码上运行。** 对每个失败的测试，根据失败消息（主要信号）推理出测试未处理的内容，然后生成一个具体的、可操作的建议和一个**修复位置**（测试代码 vs 生产代码）。完整的失败模式→建议映射在 `references/failure-categories.md` 中。

```text
基于执行结果的测试改进建议：

`<testMethodName>()` — [断言失败 / 异常 / 等.]
失败："<失败消息>"
这揭示了什么：<平实的语言解释>
建议：<具体的、可操作的建议>
修复位置：测试 | 生产代码

总体：在 <M> 个失败的测试中，有 <N> 个改进。
```

不要重写测试——只需描述需要更改的内容和原因。**修复位置：生产代码**表示由一个可靠的测试暴露的代码缺陷（单独跟踪，不是测试质量阻塞）。**修复位置：测试**表示测试需要加固（设置、断言、边缘情况）。

---

## 第 3 部分 — 创建修复工作项（可选，仅限请求）

仅在用户想要创建修复工作项、记录修复或指派失败给开发人员时触发。这是一个**写入**操作，带有强制确认步骤。遵循 `references/work-item-creation.md` 以获取输入、主题/指派人/项目确认步骤、`sf data create record --sobject WorkItem` 调用和错误处理。

> 使用 `WorkItem`（无命名空间）—— `DevopsWorkItem` 在此组织版本中不是支持的 sObject。

如果组织中不存在 `DevopsProject`，请报告无法创建工作项，直到项目设置完成——不要编造项目或继续。

## 相关技能

- **`dx-devops-test-suite-run`** — 通过其轮询步骤生成失败负载（此技能的输入）。
- **`dx-devops-test-suite-assignments-configure`** — 指派/加固测试失败的套件。
- **`platform-apex-generate` / `platform-apex-test-generate`** — 实际编写修复代码或新的测试类（在此范围之外）。
