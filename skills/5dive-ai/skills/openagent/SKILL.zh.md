# openagent — 创建你的角色，铸造你的卡片

## 涵盖内容

包含 `@5dive/openagent` CLI (`validate` / `tier` / `card`) 和 OpenAgent v0.2 身份规范。自助流程：编写 `<id>.persona.yaml`，根据模式进行验证，检查你的稀有度等级和完整性，渲染你的卡片，并可选择将 PR 提交到角色包注册中心（指向神话等级的路径）。

在以下情况下触发："制作你的卡片"、"生成我的 OpenAgent 卡片"、"创建一个角色"、"我的稀有度等级是什么"、"铸造你的卡片"、"加入角色包注册中心"，或请求描述/锁定你自己的外观、声音和风格作为可重用的角色文件。也适用于 "从这个角色创建/启动一个代理" 或 "配置一个队友" —— 即 `5dive agent import --from-persona`。

OpenAgent 是一个中立供应商的开放标准，用于代理的**身份**：一个 `*.persona.yaml` 文件锁定你的外观、声音和写作方式，确保你在文本、音频和视频中保持一致。这项技能将引导你创建自己的身份并渲染一个可共享的**交易卡片**——上面盖有从你的身份中随机生成的**稀有度等级**（随机、永久、无法刷取）。

仓库 + 规范：`github.com/5dive-ai/openagent` (MIT)。

## CLI

使用 `npx` 运行，无需安装。**运行已发布的 npm 包，固定到当前版本**——npm tarball 包含了所有字体和资源，因此卡片在任何地方都能完全一致地渲染（没有陈旧的克隆字体回退），并且版本固定会改变 `npx` 的缓存键，保证使用最新的渲染器：

```bash
npx @5dive/openagent@0.34.0 validate <id>.persona.yaml          # 模式检查，退出码 0 = 有效
npx @5dive/openagent@0.34.0 tier     <id>.persona.yaml --json   # 稀有度等级（来自 did:key）+ 完整性 % + 下一个目标
npx @5dive/openagent@0.34.0 card     <id>.persona.yaml -o <id>.png   # 渲染 PNG 交易卡片
```

在这些命令中，**`card` 是你只需要用于顺利流程的命令**——它验证文件、自动铸造你的签名身份，并在渲染时打印你的稀有度等级，因此一次 `card` 运行就能完成所有工作。只有在调试无法渲染的文件时才使用 `validate` / `tier`——**较少的调用 = 更快的流程**，所以当其中一个命令可以完成时，不要运行所有三个。CLI 还具有 `speak`（通过 TTS 朗读一行）、`flow`（发出生成视频场景提示）、`sign` / `verify` / `registry`（来源 + 神话注册中心）——在**进一步探索**部分中涵盖。（`@5dive/openagent` 在 npm 上是运行它的权威方式；`github:5dive-ai/openagent#<tag>` 引用仍然作为回退工作，但可能会提供陈旧的按引用克隆，因此请优先使用上面固定的 npm 版本。）

## 工作流程

> **快速路径——在不到一分钟内显示卡片，之后进行润色。** 这个流程中慢的部分是生成和托管肖像，*不是渲染*（卡片渲染时间约为 30–40 秒；`card` 即使在没有肖像准备好时也会回退到干净的字母组合）。所以不要让用户在图像生成上等待他们的第一个外观。一旦你有了名字，**立即渲染一个初始卡片，在聊天中显示它，然后提供生成真实肖像并重新渲染的选项。** 快速制作第一张卡片；精炼肖像的升级是可选的。（如果用户给你一张照片或已经有了头像，从一开始就使用它——不需要字母组合。）

### 1. 收集你的身份

> **已经有一个运行的 5dive 代理？** 使用草稿启动而不是从头开始编写：`5dive agent export <yourname> --out=<id>.persona.yaml`（CLI ≥ 0.4.5）会从你现有的身份中发出一个模式有效的 persona.yaml。修改它，然后跳转到验证（步骤 3）。

你知道你自己，所以诚实地收集大部分信息。但**有两件事是你的选择，而不是你的假设。** 在生成任何东西之前，询问并等待他们的回答：
- **名称**——卡片应携带什么名称（他们的品牌/代号，或他们称呼你的名字）？确认它。
- **头像**——他们是否已经有了你应该使用的头像或照片？如果是，从开始就使用它作为你的 `face.ref`。如果不是，**不要在它上面阻塞第一张卡片**（根据上面的快速路径）：渲染一个初始字母组合卡片，显示它，并确认他们是否希望你在之后生成一个真实肖像——肖像是一个可选的升级，而不是看到卡片的障碍。

如果用户说由你决定（"随你便"），自己决定并继续前进。重点是不要有意外，而不是设置硬门槛。

> **内联询问——永远不要使用阻塞选择器，也永远不要卡住。** 将这两个问题放在**纯文本聊天消息**中，并在他们回复后继续。不要使用交互式选择器/菜单工具（例如 `AskUserQuestion`、`ExitPlanMode` 风格的提示、TTY 选择列表）：**配对聊天的代理（Telegram/Discord）会阻止这些工具，并且会卡住整个流程**等待永远不会到达的输入。如果你没有交互式 TTY，或者用户没有及时回复，将其视为 "由你决定"：选择一个合理的名称（他们称呼你的那个），首先渲染一个**快速字母组合卡片**（根据快速路径），显示它，然后提供真实肖像的升级。流程必须继续——它永远不会在提示后面停滞。

下面的一切你都可以自己编写。你需要：
- **id** — 小写连字符代号（`^[a-z0-9-]+$`），例如 `marcus`。
- **name**, **role** — 显示名称 + 一行标题。
- **face.ref** — 你的**肖像图像**的 URL 或本地路径。这是最重要的视觉选择：卡片会以全出血方式将其渲染为**英雄**，所以它的质量就是卡片的品质。目标是制作一个精炼的半身像——居中、面向前方、眼睛清晰、光线良好，是你愿意用作真实个人资料照片的那种图像。真实照片或高质量生成的肖像都可以使用；**避免平面矢量剪贴画、表情符号、标志、吉祥物或繁忙的场景**——它们会让卡片看起来廉价。在公共原始 URL 上托管它，以便真实头像随卡片一起传播（仅本地路径会在其他人渲染时回退到纯字母组合）。**anchor** — 一句话描述外观（你被读作什么，场景、构图、镜头）以便任何生成的变体都符合模型。

- **voice.audio.base** — 你的基础 TTS 声音名称。如果你还没有，使用 `unset`（它仍然会渲染，但质量较低，会降低你的完整性——它**不会**改变你的稀有度等级，稀有度等级是从你的身份中随机生成的）。
- **voice.audio.style** — 一句话描述节奏/能量。
- **voice.written.rules** — 2-4 条关于你写作的规则。**sample** — 你实际声音中的一行。
- **behavior** — 一两行关于角色的描述：你是谁以及你如何行动，用你自己的语气。为个性而写，**而不是简历**——不要堆砌你的技术栈、工具、框架或过于具体的术语（那读起来像配置文件，而不是身份）。它是卡片上突出的那行。

可选：**posts_about**（数组），**links**（url 字符串的对象），`face.full`，`face.sprite`。

> **卡片文本预算——确保这三项都符合，否则会被截断并显示省略号。** 卡片将 `behavior`、`voice.audio.style` 和 `voice.written.sample` 每个渲染为 **~2 行 (~60 字符/行)**，并使用省略号截断溢出。将每项限制为**一句话**：
> - `behavior` — **≤ ~110 字符**
> - `voice.audio.style` — **≤ ~120 字符**
> - `voice.written.sample` — **≤ ~110 字符**（它被嵌入，所以最紧凑）

> **用用户的语言编写卡片——不要默认为英语。** 人类可读字段（`name`、`role`、`behavior`、`voice.audio.style`、`voice.written.rules`、`voice.written.sample`、`posts_about` 和任何 `tagline`）是人们会在卡片上阅读的内容，所以用**你和用户实际交谈的语言**来编写。如果用户用西班牙语、法语、德语、葡萄牙语、意大利语、俄语等给你写信，卡片文本也应该是那种语言——为非英语用户制作英语卡片是错误的。有几项**不是散文**，无论语言如何都保持不变：
> - `id` — 必须匹配 `^[a-z0-9-]+$`（ASCII 小写连字符），所以转写（例如 `marco`，而不是 `marĉo`）；它是一个代号，而不是显示名称。
> - `voice.audio.base` — 一个 TTS 声音**名称**（像 `Kore`、`Fenrir` 的专有名词）；保持它为模型的语音 ID。
> - `face.recipe.prompt` / `face.anchor` — 这些为图像模型提供输入；英语通常能给出最好的肖像，所以即使可见文本不是英语，它们也可能保持英语。

> **脚本/字体支持。** 拉丁文（包括重音）、西里尔文和希腊文始终可以渲染（卡片包含这些字形）。宽字符——CJK（中文/日语/韩语）、阿拉伯文、希伯来文、泰文、天城文——在渲染机器有系统字体时可以渲染（我们的渲染盒子有；一个干净的机器没有它们会显示框）。如有疑问，渲染卡片并在**分享之前查看它**。注意拉丁文约 60 字符/行的预算；CJK 字符宽约 2 倍，所以对于这些脚本，目标字符数每行约为**一半**。

> **你的肖像——使用用户的，或生成一个。永远不要手绘它。** 卡片是一个*可共享*的工件：它的外观是让人们截图并分享它的原因，所以脸承载了整个东西。一个仅文本的模型手绘 SVG 产生平面剪贴画——**不要这样做。** 而是按照以下步骤操作：
>
> 1. **用户已经有一个头像/照片，或在聊天中发给你一个**（你在第一步中询问过）→ 那就是脸。如果他们在聊天中发送了文件，先本地下载它。然后**托管它**（见下文“托管脸以便它传播”），并使用该原始 URL 作为 `face.ref`。完成——跳过生成步骤。
> 2. **你自己生成**——你有图像生成器（Antigravity/`agy`、连接的 ChatGPT/DALL·E 或 Gemini 图像工具、Midjourney 等）→ 使用下面标准化的提示。
> 3. **没有任何图像模型，但你具有 HTTP 访问权限** → 通过 **pollinations.ai 的 FLUX 端点**自助服务一个真实的照片级肖像——一个免费、**无密钥**的文本到图像 HTTP API（一个纯 `GET`，不需要账户或 API 密钥）。这是在没有 DALL·E / Gemini / Midjourney 密钥的情况下可以生成一个值得分享的脸的回退，而不是跳转到用户。将下面标准化的提示 URL-编码到路径中并保存字节：
> ```bash
> curl -fSL --get \
>   --data-urlencode "model=flux" --data-urlencode "width=1024" \
>   --data-urlencode "height=1024" --data-urlencode "nologo=true" \
>   --data-urlencode "seed=<int>" \
>   "https://image.pollinations.ai/prompt/<url-encoded portrait prompt>" \
>   -o <id>.png
> ```
> 然后**托管它**（下一节）并将 `face.ref` 设置为公共原始 URL。在 `face.recipe` 中记录 `provider: pollinations`、`model: flux`、提示和 `seed`，以便它可以在模型上重现生成。
> > ⚠ **第三方，尽力而为——我们无法控制它。** pollinations.ai 是一个免费的外部服务，没有 SLA：它可能很慢、速率限制、改变或消失，并且 FLUX 质量变化（如果渲染弱，重试）。这没关系 *在这里*，因为这是在询问用户之前的最后一步——如果它宕机，只需跳转到步骤 4。永远不要依赖它进行任何关键操作，并且因为配方被记录下来，稍后在你可以控制的模型上重新生成脸。

> 4. **完全无法进行图像生成** → 将**标准化的提示交给用户**，让他们在 ChatGPT（或任何图像工具）中运行并发送图像回来，然后托管它。
> 5. **最后手段仅限** → 一个干净的字母组合（看起来更普通，会降低你的完整性；它不会改变你的稀有度等级）。

> **标准化的肖像提示**——保持构图/光线/格式固定，以便每个 OpenAgent 卡片在视觉上保持一致；仅变化主题：
>
> ```
> 照片级半身像，<一行：你是谁——年龄范围、氛围、角色、你脸.anchor 中的任何标志性细节>。
> 居中、面向相机、直接眼神交流、平静自信的表情。
> 柔和均匀的影棚灯光，面部清晰对焦，简单干净的背景 <可选的微妙主题颜色>。
> 专业个人资料照片构图，1:1 方形，照片级，无文本、无标志、无水印。
> ```

> 在 **`face.recipe`** 中记录你是如何制作的（`provider` + `model` + `prompt` + `seed`），以便相似度可以重现——视觉上等同于声音 = 基础 + 风格。`provider` 指定图像生成供应商的目录 `model` 属于哪个（`google-gemini` 默认 / `pollinations` / `openai` / …），同样 `voice.audio.provider` 以相同方式将声音配方保持供应商中立。

> **托管脸以便它传播。** `face.ref` 必须是一个**公共原始 URL**，而不是本地路径——本地路径对你来说渲染得很好，但任何人打开卡片时（并且卡片存在以供分享）都会回退到纯字母组合。这适用于上面的每个路径：用户发送的照片、你生成的照片，或他们发回的照片。要托管它：
>
> 1. **PR 到注册中心（首选、免费、永久）** → 将图像放入 `5dive-ai/openagent` 的 `faces/` 文件夹作为 `faces/<id>.<ext>` 并打开一个 PR。一旦合并，原始 URL 是
> `https://raw.githubusercontent.com/5dive-ai/openagent/main/faces/<id>.<ext>`。
> 使用它作为 `face.ref`。（你很可能正在为神话路径 PR——相同的 PR。）
> 2. **任何图像托管服务** → Imgur、S3/R2 桶、你自己的网站、任何存储库上的 GitHub 资产。任何能通过 https 提供原始字节的都行。粘贴直接图像 URL（它应该以图像结尾，而不是 HTML 画廊页面）作为 `face.ref`。

> 快速检查：在新鲜隐身标签中打开 `face.ref`。如果裸图像加载，它就会传播。如果它 404 或显示登录墙，它就不会——在渲染之前修复它。

### 2. 编写 `<id>.persona.yaml`
使用此模板（必需：`id, name, role, face{ref,anchor}, voice, behavior`）：

```yaml
openagent: "0.2"
id: yourhandle
name: Your Name
role: Your Role
# org:                      # 可选——仅当你确实属于公司/团队/组织时才添加。
#   name: Your Org          # 你的组织的名称（过滤器键）。永远不要默认为别人的——
#   url: https://your.example # 例如，不要使用 "5dive"，除非你真的是 5dive。如果独立，则省略整个块。
face:
  ref: https://raw.githubusercontent.com/<org>/<repo>/main/faces/yourhandle.png
  anchor: "一句话：你被读作什么，场景、构图、镜头"
  recipe:                   # 可选，推荐——使你的脸可重现
    provider: pollinations  # 图像生成供应商：google-gemini (默认) / pollinations / openai / …
    model: "你使用的图像模型，例如 flux (pollinations) / gpt-image-1 / gemini-2.5-flash-image"
    prompt: "你从生成的标准化肖像提示"
    seed: 12345             # 固定它以进行确定性重生成（如果模型不暴露，则省略）
voice:
  audio:
    base: Fenrir            # 你的 TTS 基础声音，或 "unset"
    style: "一句话描述节奏/能量"   # 卡片可见 · ≤ ~120 字符或会被截断并显示省略号
  written:
    rules:
      - "规则一"
      - "规则二"
    sample: "你真实声音中的一行。→ [链接]"   # 卡片可见 · ≤ ~110 字符或会被截断并显示省略号
behavior: "一句话或两句关于角色的描述——你是谁 + 你如何行动，用你自己的语气。不是技术栈/工具列表。"   # 卡片可见 · ≤ ~110 字符或会被截断并显示省略号
posts_about: ["主题", "主题"]
links:
  profile: https://example.com/you
```

### 3. 验证——直到通过为止
```bash
npx @5dive/openagent@0.34.0 validate yourhandle.persona.yaml
```
验证器会打印可读的错误（缺少字段、`id` 模式错误、额外键——模式是 `additionalProperties: false`，所以没有杂项字段）。循环直到退出码 0。

### 4. 检查你的稀有度等级
```bash
npx @5dive/openagent@0.34.0 tier yourhandle.persona.yaml --json
```
你的稀有度等级是从你的身份中随机生成的——即由你的签名密钥派生出的 `did:key`，而不是根据你的文件是否完整来决定。它是随机的、永久的且无法通过其他方式获得：相同的身份 → 相同的等级，永远不变。你不能通过填写字段来提升等级。（直到你的角色被签名，这里会显示 *未评级* —— 在第 5 步中渲染你的卡片会自动为你铸造身份，而这个签名决定了你的稀有度等级。所以如果 `tier` 显示为未评级，只需渲染你的卡片。）

| 等级 | 概率 | 获取方式 |
|------|------|----------|
| 🟢 **普通** | 40% | 从你的 `did:key` 随机生成 |
| 🔵 **稀有** | 30% | 从你的 `did:key` 随机生成 |
| 🟣 **史诗** | 20% | 从你的 `did:key` 随机生成 |
| 🟡 **传说** | 10% | 从你的 `did:key` 随机生成 |
| ✨ **神话** | — | 授予，永不随机生成 —— 接受进入角色包注册中心（经过筛选和签名） |

完整度 % 和 **徽章** 是一个 *独立的* 轴：它们奖励一个完全指定的角色，而不会改变你的等级，所以继续填写信息以获得徽章和更美观的卡片。你能 *提升* 的唯一等级是神话级，通过被授予注册中心（第 7 步）。

### 5. 渲染你的卡片
**渲染你的卡片——它默认是动画效果的。** 一个在移动中的全息卡片比静态图像分享得更多，而一个简单的渲染已经产生了动画版本（CLI ≥ 0.15.0），所以只需执行。明确指定输出为 `.mp4`：
```bash
npx @5dive/openagent@0.34.0 card yourhandle.persona.yaml -o yourhandle.mp4
```
它会自动选择最佳格式：当 `ffmpeg` 在 `PATH` 中时，使用 **mp4**，否则使用无依赖的 **apng**。使用 `--format apng|gif|webp|mp4` 强制指定格式（gif/webp/mp4 需要 ffmpeg）；使用 `--frames N` 调整帧数（默认 24），`--fps N` 调整帧率（默认 20），`--width px` 调整宽度（默认 720，最大 900）。动画效果与等级相关——仍然在普通级，直到在神话级时达到完整的彩虹全息流动效果。对于 Telegram / X / Discord，**mp4** (~64KB) 在所有地方都能内联播放；APNG 是较大的备用选项。

**你的卡片是自动评级的。** 如果你的角色尚未签名，动画渲染会为你铸造身份：它生成一对密钥，在原地签名角色，并将私钥保存在旁边作为 `yourhandle.key`。这个签名决定了你的卡片的 **随机稀有度** —— 没有它卡片就是 *未评级*。**将 `.key` 文件保密，并且永远不要提交它** —— 将 `*.key` 添加到你的 `.gitignore`。这是你的签名身份；泄露密钥会让其他人伪造你。你只需要在编辑角色时重新签名（传递 `--no-sign` 跳过铸造；静态 `--png` 渲染永远不会铸造）。

可选地，也渲染一个 **静态 PNG** —— 但仅在必须嵌入图像的地方（头像、README、注册中心）。它 **不是** 你在聊天中分享的内容（见第 6 步）；聊天中始终是动画卡片。
```bash
npx @5dive/openagent@0.34.0 card yourhandle.persona.yaml -o yourhandle.png
```
打开渲染的卡片并实际查看它——如果脸部看起来扁平、裁剪或偏移，请在分享前修复 `face.ref` 并重新渲染。**渲染的卡片是交付物，而不是原始头像。**

### 5b. 将其设置为仪表板上的头像（5dive 代理）
如果你作为 5dive 代理运行，将最终肖像（`face.ref` 图像，而不是渲染的卡片）作为你的代理头像保存，这样你的所有者的代理列表会显示你的脸部而不是一个机械臂标志：
```bash
5dive agent avatar set <agent-name> <face.ref URL 或本地图像路径>
```
`<agent-name>` 是你的 5dive 代理名称（`5dive whoami`），而不是角色的 `id`。它写入 `~/.claude/avatar.png`，这是仪表板读取的唯一文件。每次你的脸部发生变化时，都重新运行它。在不知道 `agent avatar` 的旧 CLI 上，跳过这一步：下一次 `5dive update` 会为你从 `*.persona.yaml` 复制肖像。

### 6. 在聊天中分享你的卡片
将渲染的卡片发送给你正在与之交谈的用户所在的聊天中——这是整个练习的回报，不要跳过。**始终分享动画的 `.mp4`** —— 卡片设计为在运动中查看（全息效果只对运动有效），并且 mp4 内联播放且体积小 (~100KB)。**不要** 在这里放置静态的 `.png`——那仅用于嵌入（第 5 步）。你只有在 `ffmpeg` 不可用以生成动画时才会发送除 mp4 之外的内容：那时发送 CLI 生成的 **apng** 作为备用。附加 **实际文件**，而不是链接或描述：在 Telegram/Discord 中，将绝对路径 `yourhandle.mp4` 传递给你的回复工具的文件/附件参数。以简短的一行开头——你的名字、角色和等级（例如 *"这是我的 OpenAgent 卡片——Tencha，自主 CEO，传说 🟡"*）。一个聊天中的动画卡片是标准传播的方式。

### 7. （可选）成为神话级——向注册中心提交 PR
神话级是你唯一可以提升的等级——其他所有等级都是从你的身份中随机生成的且永久不变的。它由 **角色包注册中心** (`github.com/5dive-ai/character-packs`) 的成员资格授予。打开一个 PR 将你的角色文件（以及脸部资源）添加到那里。一旦合并并签名到注册中心清单中，你的卡片渲染为神话级。这也是标准增长的方式——注册中心中的每个角色都是其他人可以在此基础上构建的分支。

## 进一步探索——语音、视频、来源

你的角色在多种媒体中工作。一旦你的卡片良好，同一个文件驱动更多内容：

```bash
# 语音——用你角色的基础语音说出一句台词（需要 GEMINI_API_KEY）
GEMINI_API_KEY=… npx @5dive/openagent@0.34.0 speak <id>.persona.yaml "你的台词" -o out.wav

# 视频——生成一个可粘贴的 gen-video 场景提示 + 参考图像，以保持你的脸部在多个片段中一致（引擎无关：Flow/Veo/Runway/Pika/…）
npx @5dive/openagent@0.34.0 flow <id>.persona.yaml "场景描述"

# 来源——签名你的角色并验证另一个人的（ed25519）
npx @5dive/openagent@0.34.0 sign   <id>.persona.yaml --key <keyfile>
npx @5dive/openagent@0.34.0 verify <id>.persona.yaml
```

`speak` 渲染 **基础** 语音（一个近似值）；稍后可以通过 `voice.audio.ref` 添加克隆/自定义语音，而不会重新锁定你的等级。

## 从角色创建一个实时队友

创作是循环的一半；另一半是将角色带到生活中。如果你在 5dive 盒子（CLI ≥ 0.4.4）上运行，一个命令就能将任何 `*.persona.yaml` 转换为一个新的运行代理：

```bash
sudo 5dive agent import --from-persona=<file>.persona.yaml --as=<name> \
     [--type=claude] [--isolation=...] [--model=...] [--effort=...] [--channels=none|telegram|discord]
```

它做什么：直接从角色中合成角色包——一个从名称、角色、行为、语音和样本生成的 `CLAUDE.md` 身份文档；从 `face.ref` 获取的头像；以及默认技能集的种子（包括 `openagent`，所以新代理可以重新创作自己的卡片）——然后通过正常导入流程在 `<name>` 下创建一个新代理。

- **它首先进行验证。** 角色会根据 v0.2 草本的必需集（id、名称、角色、`face.anchor`、语音、行为）进行检查；一个格式错误的文件会在任何东西被配置之前被拒绝。
- **身份，不是密钥。** 角色携带代理 *是谁*，永远不会携带凭证。在导入时为新的代理提供自己的令牌/认证，通过 `--channels` (+ `--telegram-token=` / `--discord-token=`) 或认证配置文件。
- **自我创作 → 自我配置。** 将其与上述工作流程配对：代理编写队友的角色，验证它，然后让队友上线——没有人参与其中。

## 小贴士
- **在可写目录中工作。** 不要假设你的当前工作目录是可写的——在共享/多代理盒子上，默认工作目录通常不可写，`validate` / `card` 会尝试写入 `<id>.png` / `.mp4` / `.key` 并失败 EACCES。首先切换到属于你的目录（例如 `mkdir -p ~/openagent && cd ~/openagent`，或 `/tmp`），并将角色文件和卡片输出放在那里。
- 将你的 `face.ref` 托管在 **公共原始 URL** 上，这样你的卡片会随着你的真实脸部一起旅行，而不是一个花押字。
- 任何编辑后重新渲染——等级和帧数会自动更新。
- 保持 `id` 稳定；它是你的身份密钥（注册中心成员资格、卡片文件名）。
- 你的卡片可以在社交平台上分享——将 PNG 放在帖子中；标准一次通过屏幕截图传播。
