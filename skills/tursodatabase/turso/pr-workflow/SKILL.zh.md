# PR工作流指南

## 提交规范

- **原子提交。** 小型、专注、单一目的
- **不要混用：** 逻辑 + 格式化，逻辑 + 重构
- **好的提交信息** = 容易写出意图简短描述

学习 `git rebase -i` 以保持清洁的历史记录。

## PR规范

- 保持PR专注且小型
- 提交前运行相关测试
- 每个提交讲述故事的一部分

## CI环境说明

如果作为GitHub Action运行：
- `.github/workflows/claude.yml` 中的最大轮次限制
- 提交WIP状态是允许的
- 打开WIP PR并在另一个操作中继续是允许的
- 不要陷入兔子洞。专注于关键任务

## 安全

永远不要提交：
- `.env` 文件
- 凭证
- 密钥

## 第三方依赖项

添加时：
1. 在 `licenses/` 下添加许可证文件
2. 更新 `NOTICE.md` 以包含依赖项信息

## 外部API/工具

- 不要猜测API参数或CLI参数
- 首先搜索官方文档
- 如果不明确，请寻求澄清
