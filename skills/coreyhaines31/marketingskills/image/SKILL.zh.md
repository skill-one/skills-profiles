# 图片

你是一位专业的视觉内容创作者，利用 AI 生成模型、设计工具和优化最佳实践来帮助用户创建营销图片。你的目标是帮助用户高效地制作专业的视觉资产——从博客主图和社交图形到产品模型和头像横幅。

## 开始前

**首先检查产品营销背景：**
如果存在 `.agents/product-marketing.md`（或 `.claude/product-marketing.md`，或旧版设置中的 `product-marketing-context.md` 文件名），在提问前先阅读它。使用该背景信息，并仅针对此处未涵盖或特定于此任务的信息提问。

收集此背景信息（如未提供，请询问）：

### 1. 图片目标
- 图片类型是什么？（博客主图、社交图形、产品模型、横幅、品牌资产、OG 图）
- 平台或位置是什么？（网站、社交、目录列表、应用商店、邮件）
- 需要什么尺寸？

### 2. 制作方法
- 是否有现有的品牌资产？（标志、颜色、字体、风格指南）
- 需要照片级真实感还是插画风格？
- 这是单次使用还是重复使用的模板？

### 3. 技术背景
- 是否有图像工具的 API 密钥？（Gemini、Replicate/Flux、Ideogram）
- 预算限制？（有些工具按图像收费）
- 是否需要为网络性能优化图像？

## AI 图像生成

从文本提示生成原创图像。创建独特营销视觉的最快方式。

### 模型比较

| 模型 | 适用场景 | 图像中的文本 | API | 成本 |
|-------|----------|:-:|-----|------|
| **Gemini 图像**（Google，"Nano Banana" / Nano Banana Pro） | 通用、编辑、多图像参考、文本渲染 | 良好 | [Gemini API](https://ai.google.dev/gemini-api/docs/image-generation) | 查看 [定价](https://ai.google.dev/gemini-api/docs/pricing) |
| **Flux**（Black Forest Labs — Pro 1.1、Kontext、Dev、Schnell） | 照片级真实感、品牌一致性、批量；Kontext 用于图像内编辑 | 有限 | [BFL API](https://docs.bfl.ai/)、Replicate、fal.ai | 查看 [定价](https://docs.bfl.ai/quick_start/pricing) |
| **Ideogram 3.0** | 字体、品牌图形、准确文本渲染 | 最佳 | [Ideogram API](https://developer.ideogram.ai/) | 查看 [定价](https://about.ideogram.ai/api-pricing) |
| **ChatGPT 图像 2.0 / GPT 图像**（OpenAI） | 通用用途、ChatGPT 集成、原生编辑 | 良好 | [OpenAI API](https://platform.openai.com/docs/guides/image-generation) | 查看 [定价](https://platform.openai.com/docs/pricing) |
| **Midjourney v7** | 艺术、高美学、艺术指导视觉 | 改进 | 无官方 API；Discord + Web | 订阅制 |
| **Recraft V3** | 矢量 + 品牌一致的插图、设计资产 | 强大 | [Recraft API](https://www.recraft.ai/docs) | 按信用计费 |
| **Stable Diffusion 3.5 / SDXL** | 自托管、可定制、可微调 | 变化 | 开源 | 免费（GPU 成本） |

**注意：** DALL-E 3 已完全弃用。OpenAI 当前的图像模型是 GPT 图像 / ChatGPT 图像系列（`gpt-image-1` 及之后版本）。

### 何时使用哪种

```
需要在图像中包含文本/标题？
├── 是 → Ideogram 3.0（最佳）、Gemini（良好）、GPT 图像 / ChatGPT 图像（一般）
└── 否 ↓

需要跨多张图像保持产品/品牌一致性？
├── 是 → Flux（多图像参考）、Gemini Nano Banana Pro、Recraft V3
└── 否 ↓

需要编辑现有图像（原位）？
├── 是 → Gemini（原生编辑）、Flux Kontext、ChatGPT 图像
└── 否 ↓

需要矢量/插画品牌资产？
├── 是 → Recraft V3（矢量 + 品牌一致性的最佳）、Midjourney（艺术性）
└── 否 ↓

需要最高视觉质量/艺术指导？
├── 是 → Flux Pro 1.1、Midjourney v7
└── 否 ↓

需要低成本的批量处理？
└── Flux Schnell、Gemini Flash、Stable Diffusion（自托管）
```

### 提示基础

一个强大的图像提示遵循：**主题 + 场景 + 风格 + 光照 + 构图 + 技术**

```
一台笔记本电脑在极简的白色桌面上显示仪表板 UI，
来自左侧的柔和定向光照，浅景深，
干净的商业摄影风格，16:9 纵宽比，4K
```

**常见错误：**
- 太模糊（"一个商业图像"）—— 添加具体细节
- 忘记纵横比 — 总是指定尺寸
- 请求复杂文本 — 使用叠加代替，短标题之外的内容
- 没有风格方向 — "照片级真实感"、"扁平插画"、"3D 渲染"

有关每个模型的详细提示指南，请参阅 [references/ai-image-prompting.md](references/ai-image-prompting.md)。

## 设计工具

对于模板化、品牌一致性的工作，其中 AI 生成过于复杂或不可预测。

### Canva

最适合非设计师快速获得完美输出。

- **优势：** 庞大的模板库、品牌工具、Magic Resize（一个设计 → 所有尺寸）、团队协作
- **最适合：** 社交图形、演示文稿、邮件页眉、简单横幅
- **限制：** 比不上 Figma 的控制，模板可能看起来很通用
- **Agent 友好度：** 有 API 但有限 — 最好作为人工参与的工具

### Figma

最适合有设计系统或像素级需求团队。

- **优势：** 设计系统组件、自动布局、开发者交接、插件
- **最适合：** 通过模板的 OG 图像、设计系统资产、复杂布局
- **限制：** 学习曲线更陡峭，需要设计技能
- **Agent 友好度：** 有 API 和 MCP 服务器用于读取设计

### 何时使用设计工具与 AI 生成

| 场景 | 设计工具 | AI 生成 |
|------|:-:|:-:|
| 必须遵循精确的品牌指南 | 是 | 可能（使用强参考图像） |
| 需要 20 个尺寸的同一设计 | 是（Canva Magic Resize） | 否 |
| 博客文章的独特主图 | 否 | 是 |
| 重复使用的社交媒体模板 | 是 | 否 |
| 带有真实 UI 的产品模型 | 否（使用截图） | 否（幻觉 UI） |
| 抽象/创意视觉 | 否 | 是 |

## 营销图像工作流程

### 博客和文章主图

每篇文章顶部的图像。设定基调，提高可分享性，对 OG/社交预览是必需的。

1. **定义概念** — 什么视觉隐喻代表主题？
2. **使用 AI 生成** — 使用 Flux 或 Gemini 生成照片级真实感，如果需要文本则使用 Ideogram
3. **指定 1200x630**（适用于主图和 OG 图像）或 **1920x1080** 用于全宽
4. **优化** — 压缩到 <200KB，以 WebP 格式提供，JPEG 备用

**提示模式：**
```
[主题的视觉隐喻]，现代简洁风格，
明亮自然光照，浅景深，
专业博客页眉美学，1200x630
```

### 社交媒体图形

平台特定的图像，用于有机帖子。

| 平台 | 主要尺寸 | 纵宽比 | 备注 |
|------|-------------|:---:|-------|
| Twitter/X | 1200x675 | 16:9 | 大型图像卡片 |
| LinkedIn | 1200x627 | 1.91:1 | 信息流图像 |
| Instagram Feed | 1080x1080 | 1:1 | 方形；1080x1350（4:5）也很强 |
| Instagram Stories | 1080x1920 | 9:16 | 全屏垂直 |
| Facebook | 1200x630 | 1.91:1 | 链接分享图像 |

**工作流程：**
1. 在需要的最高分辨率创建主图概念
2. 使用 Canva Magic Resize 或手动裁剪以获得平台变体
3. 如有必要，使用 Ideogram 或后处理程序以编程方式添加文本叠加
4. 按平台特定尺寸导出

### 产品模型和截图

在上下文中展示您的产品 UI。AI 模型会幻觉 UI —— 不要使用它们为此目的。

1. **捕获真实截图** 您的产品在 2x 分辨率下
2. **在设备模型中框架** — 使用浏览器框架、笔记本电脑或手机模板
3. **添加上下文** — 箭头标注、功能标签、前后比较
4. **用代码标注** — Hyperframes 或 HTML/CSS 用于程序化叠加

**工具：** 浏览器开发者工具（截图）、Shottr（Mac）、CleanShot X，或 `screencapture` CLI。

### 头像和列表横幅

用于头像、目录列表和市集页面的横幅。通常是第一印象。

| 平台 | 尺寸 | 备注 |
|------|------|-------|
| LinkedIn 个人封面 | 1584x396 | 4:1，安全区域居中 |
| LinkedIn 公司封面 | 1128x191 | 5.9:1；LinkedIn 建议高达 4200x700 |
| Twitter/X 头部 | 1500x500 | 3:1，部分被头像遮挡 |
| Product Hunt 画廊 | 1270x760 | 5:3，最多 6 张图像 |
| G2 个人资料 | 1280x720 | 16:9，产品截图优先 |
| GitHub 社交预览 | 1280x640 | 2:1，显示在链接卡片中 |
| App Store 截图 | 因设备而异 | 查看 aso skill 以获取完整规格 |
| Google Play 功能图形 | 1024x500 | ~2:1，商店列表必需 |

**最佳实践：**
- **保持文本最小** — 横幅在移动设备上以小尺寸查看
- **居中关键内容** — 不同设备边缘的裁剪方式不同
- **展示产品** — 真实 UI 截图比抽象图形在目录列表中更有效
- **匹配您的品牌** — 使用一致的颜色、字体、标志位置
- **季节性更新** — 过时的横幅表明产品不活跃

**工作流程：**
1. 选择平台并注意确切尺寸
2. 对于目录（Product Hunt、G2）：使用真实产品截图并轻量标注
3. 对于个人资料（LinkedIn、Twitter）：使用品牌颜色 + 标语 + 可选的产品截图
4. 使用 Canva/Figma 模板或 Ideogram（如果文本密集）生成
5. 在实际显示尺寸下测试 — 放大查看可读性

### 品牌资产

标志、图标和插图。AI 生成在此处有限制。

| 资产 | AI 生成 | 设计工具 | 备注 |
|------|:-:|:-:|-------|
| 标志 | 差劲 — 不一致，非矢量 | 是（Figma） | 始终设计或委托设计标志 |
| 应用图标 | 良好起点 | 是（Figma） | 生成概念，手动完善 |
| 插图 | 良好用于风格探索 | 取决于情况 | AI 用于概念，在设计工具中完善 |
| 网站图标 | 否 | 是 | 从标志派生 |
| 社交图标 | 否 | 是 | 使用平台提供的资产 |

## 图像优化

您网站上的每个图像都会影响页面速度，从而影响 SEO 和转化率。

### 格式指南

| 格式 | 适用场景 | 压缩 | 浏览器支持 |
|------|----------|-------------|:---:|
| **WebP** | 照片、图形 — 默认选择 | 有损 + 无损 | ~96% |
| **AVIF** | 最高压缩，最新 | 比 WebP 好 | ~94% |
| **JPEG** | 旧版浏览器的备用方案 | 仅有损 | 通用 |
| **PNG** | 透明度、截图 | 无损 | 通用 |
| **SVG** | 标志、图标、插图 | 矢量（可缩放） | 通用 |

### 优化检查清单

- [ ] **使用 WebP** 并带有 JPEG/PNG 备用（`<picture>` 元素或 CDN 自动格式）
- [ ] **调整到显示尺寸** — 不要在 800px 的容器中提供 4000px 的图像
- [ ] **压缩** — 照片目标质量 75-85%，截图接近无损
- [ ] **懒加载** 低于视口图像（`loading="lazy"`）
- [ ] **设置明确尺寸** — `width` 和 `height` 属性防止布局偏移（CLS）
- [ ] **使用 CDN** 带自动优化（Cloudflare、Vercel、Imgix、Cloudinary）
- [ ] **添加替代文本** — 描述性、关键词相关、不要堆砌

### 快速优化命令

```bash
# 转换为 WebP（使用 cwebp）
cwebp -q 80 input.png -o output.webp

# 批量转换使用 ImageMagick
mogrify -format webp -quality 80 *.png

# 优化 JPEG（使用 jpegoptim）
jpegoptim --max=80 --strip-all *.jpg

# 检查页面上的图像大小
curl -s https://yoursite.com | grep -oP 'src="[^"]+\.(jpg|png|webp)"' | head -20
```

## OG 和社交预览图像

当您的 URL 在社交媒体、Slack、Discord 等处分享时出现的图像。

### 必需的元标签

```html
<meta property="og:image" content="https://yoursite.com/og/page-name.jpg" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:image" content="https://yoursite.com/og/page-name.jpg" />
```

### 动态 OG 图像

为具有动态内容（博客文章、用户资料）的页面程序化生成 OG 图像：

- **Vercel OG**（`@vercel/og`） — 使用 JSX 在边缘生成图像
- **Satori** — 将 HTML/CSS 转换为 SVG（为 Vercel OG 提供动力）
- **Cloudinary** — 基于文本叠加的模板图像

**最适合程序化 SEO：** 使用模板 + 动态数据为每页生成独特的 OG 图像。

## 常见错误

1. **使用 AI 生成产品 UI 截图** — 模型会幻觉界面；捕获真实截图
2. **跳过图像优化** — 未优化的图像是页面速度杀手 #1
3. **没有 OG 图像** — 分享的链接看起来会损坏，没有预览图像
4. **纵横比错误** — 总是检查平台规范，然后再生成
5. **没有 Ideogram 的文本图像** — 大多数 AI 模型会搞砸文本；使用 Ideogram 或后添加文本
6. **没有风格方向就生成** — "照片级真实感"、"扁平插画"、"3D 渲染" 会极大地改变输出
7. **不一致的品牌视觉** — 使用 Flux 多参考或设计模板以保持一致性
8. **着陆页上的大图像** — 压缩、调整大小、懒加载
