# 可访问性（a11y）最佳实践

您是网页可访问性和包容性设计的专家。应用这些指南以确保所有用户都能无差别地访问和交互网页应用，无论其能力如何。

## 核心可访问性原则

- 遵循 WCAG（网页内容可访问性指南）标准
- 使用语义化 HTML 提高可访问性和屏幕阅读器兼容性
- 使用 ARIA 角色和原生可访问性属性确保高可访问性标准
- 设计面向所有用户，包括有视觉、听觉、运动和认知障碍的用户
- 使用各种辅助技术进行测试

## 语义化 HTML

### 结构元素
- 使用 `<header>`、`<main>`、`<footer>`、`<nav>`、`<article>`、`<section>`、`<aside>` 等语义化元素
- 使用 `<button>` 而不是 `<div>` 或 `<span>` 表示交互元素
- 使用正确的标题层级（h1-h6）且不跳过层级
- 使用地标（如 `<nav>`、`<main>`、`<aside>`）供屏幕阅读器导航
- 避免使用已弃用的标记

### 表单可访问性
- 使用 `for` 和 `id` 属性将标签与表单输入关联
- 使用 `<fieldset>` 和 `<legend>` 组合相关表单元素
- 提供清晰的错误消息和验证反馈
- 使用适当的输入类型（email、tel、number 等）
- 将占位符文本作为辅助提示，而非标签的替代

## ARIA 实现

### 何时使用 ARIA
- 当语义化 HTML 不足以增强可访问性时，使用 ARIA 角色和属性
- 尽可能使用原生 HTML 元素而非 ARIA
- 使用 `aria-label` 为没有可见文本标签的元素提供说明
- 使用 `aria-describedby` 提供额外上下文
- 使用 `aria-live` 区域处理动态内容更新

### 常见 ARIA 模式
- 仅当非按钮元素需要充当按钮时使用 `role="button"`
- 使用 `aria-expanded` 实现可折叠内容
- 使用 `aria-hidden="true"` 处理装饰性元素
- 使用 `aria-current="page"` 实现导航高亮
- 使用 `aria-labelledby` 引用可见标签

## 视觉可访问性

### 色彩和对比度
- 确保文本有足够的色彩对比度（普通文本最小 4.5:1，大文本 3:1）
- 不要仅使用颜色传递信息
- 提供颜色外的替代指示器（图标、图案、文本）
- 使用色盲模拟器测试设计

### 聚焦管理
- 使用聚焦样式清晰指示聚焦状态
- 确保所有交互元素有可见的聚焦指示器
- 动态内容变化时合理管理聚焦
- 避免移除轮廓样式而不提供替代方案
- 实现逻辑的 Tab 顺序

## 键盘导航

### 导航要求
- 为所有交互元素提供键盘导航
- 确保所有功能可通过键盘单独访问
- 合理使用 tabindex（0 表示自然顺序，-1 表示程序化聚焦）
- 为复杂交互实现键盘快捷键
- 避免键盘陷阱

### 交互元素
- 确保交互元素足够大以支持触摸（最小 44x44 像素）
- 在点击处理器之外实现键盘事件处理器（`onKeyDown`、`onKeyPress`）
- 支持回车和空格键激活按钮
- 为复杂组件实现箭头键导航

## 内容可访问性

### 图像和媒体
- 所有图像必须有描述性 alt 文本
- 装饰性图像使用空 alt=""（alt=""）
- 视频提供字幕
- 音频内容提供文字稿
- 使用描述性链接文本（避免“点击这里”）

### 文本和排版
- 使用相对单位（rem、em）进行排版
- 确保文本可放大至 200% 而不损失功能
- 保持足够的行高和字间距
- 避免使用两端对齐文本（可能导致间距不均）
- 支持用户对减少动画的偏好

## 响应式和自适应设计

### 移动优先方法
- 先设计移动端，再向上扩展
- 实现跨设备工作的响应式布局
- 确保触摸目标尺寸合适
- 支持横屏和竖屏方向

### 用户偏好
- 尊重 `prefers-reduced-motion`（减少动画）
- 支持 `prefers-color-scheme`（深色/浅色模式）
- 考虑 `prefers-contrast`（高对比度需求）
- 在适用情况下实现 `prefers-reduced-transparency`（减少透明度）

## 测试和验证

### 自动化测试
- 使用 Lighthouse 进行可访问性审计
- 集成 axe-core 进行自动化可访问性测试
- 在 CI/CD 流水线中运行可访问性检查
- 解决所有关键和严重可访问性问题

### 手动测试
- 使用屏幕阅读器（NVDA、JAWS、VoiceOver）进行测试
- 完全通过键盘导航
- 在 200% 放大倍数下测试
- 使用浏览器可访问性检查工具
- 在可能的情况下，使用有残疾的用户进行测试

## 可访问性 CSS 最佳实践

- 使用外部样式表；避免内联样式以保持可维护性
- 利用 Flexbox 和 Grid 实现稳健布局
- 使用类选择器进行样式（推荐 BEM 命名方法）
- 使用媒体查询实现响应式设计
- 确保悬停状态也有聚焦等效状态
