# RPI

通过完成来拥有授权的结果。使用本地编码代理和 shell。业务部门或调用者的追踪者拥有工作及交接；Git 拥有内容和交付。AgentOps 提供一份简短章程和新鲜判断，而非调度器。

## 运营章程

1. 使用现有的公认结果、范围和实际边界。清晰的变更无需 Plan、Recall 或 Learn 工作表。仅在它可能改变实现或接受决策时才解决不确定性。
2. 采取最小的推进接受的动作。[Plan](../plan/SKILL.md) 形成缺失的意图或修订已被证伪的方法。一旦实现者可以行动且验证者可以判断，就实施；不要继续改进计划。方法修订保留接受和授权范围。接受变更需要调用者授权。
3. [Implement](../implement/SKILL.md) 并直接修复普通已知缺陷。已知测试失败需要一个修复和一个区分性检查，而不是另一个规划阶段、委员会或助手。
4. 在编辑期间使用专注检查，并在最终判断前完成所需的集成检查。重用有效的精确输入收据；更改后重新运行受影响的检查。保留集成、审查和修复的容量。在判断期间保持最终主题不变。
5. 从作者模型家族中的一个新鲜作者区分的上下文中获取 [Validate](../validate/SKILL.md)，除非调用者选择所需的额外环节。没有固定的十分钟上限；明确要求的审查者仍然是必需的。风险加深证据，而非审查者倍增。在授权和剩余边界内修复可操作的发现，然后重新验证更改的精确主题。对于因缺失证据的 `NOT_PROVEN`，在不更改主题的情况下收集它并再次获取新鲜判断。
6. 在以下帮助之后停止：完成的接受、取消、拒绝、已用完的实际边界或未解决的因果停滞。相邻的改进不是扩展目标的许可。仅在有用时简要报告它们；不要将它们变成另一个工作批次。

## 上下文和交接

每上下文一次加载所需的合同，然后仅读取下一个决策需要的部分。一个参考链接是可用上下文，而不是阅读列表。在打开大文件前搜索；仅因后果性不确定性而展开。在工具边界处保持成功的输出紧凑；保留完整日志以供检查。重用工作者的组件检查列表和当前收据，而不是重新发现它们。使用本地完成监视或边界等待来进行持续的检查和助手。完成后，验证预期的主题和所需的结果；安静或部分状态不是成功。对于失败、疑似停滞或决策需要，进一步检查。保持所需用户更新简洁，而不是叙述每次轮询。

当授权且有用时，为独立工作选择运行时的任务仅调度选项；在完整历史分支中的简短提示仍然包含完整历史。提供接受的意图/范围、精确主题、相关证据、剩余边界、结果消费者和检查所有权。在有用时恢复作者进行直接修复。验证者始终接收新鲜上下文，而无需作者的期望裁决。观察实际调度设置；提示措辞证明既非隔离也非较小的继承上下文。

返回简洁的发现，检查事实和证据参考在现有的交接中；披露缺失或截断的证据。在集成/判断边界处推导出组合主题的清单和适用的孤儿扫描。未判断的工作者增量提供内容身份和检查事实，而不是重复最终证据包。单独判断的主题仍然需要完整证据。机器证据（如 `verdict.v2`）是可选的，除非被请求或由声明的消费者要求。当未请求或要求机器工件时，返回结果而无需创建它。

## 因果停滞和边界

未知原因、复发、无进展或错误目标最多允许在授权和边界内为该事件提供一个有界的 freshness 帮助。给它失败的假设、证据和一个区分性问题。仅在具有不同的可测试方法时才恢复；无帮助的答案结束尝试。不要链式帮助或重命名事件。已知失败直接修复。取消、拒绝和已用完的硬时间/成本/配额跳过帮助。

尊重实际的调用者/本地限制，包括明确的修复轮次边界。重试、紧凑、帮助者和新主题永远不会续期它们；重试次数本身不是已用完的预算。如果中断威胁证据，则在本地交接中保留接受的意图、精确主题、有用收据、未解决的因果、边界和助手使用。提示文本证明没有本地强制。[Outer-goal guidance](references/outer-goal.md) 保持可选。

## 证据和边界

为新鲜验证者绑定接受的意图、完成的更改路径、精确主题和事实收据；披露受影响的孤儿接受证据。使用现有的可追溯性助手，而不是新的证据格式。请求的证据使用调用者选择的受保护的外部非 Git 存储保留 legacy `.agents/` 证据。缺失身份、新鲜度或证据意味着 NOT_PROVEN；证明失败的接受或范围违规意味着 FAIL。PASS 需要每个标准都经过验证且 `not_checked` 为空。作者不能发布绑定 PASS。

[Memory](../memory/SKILL.md)、专家和运行时适配器按需提供；不匹配和未更改是有效的。当授权、范围、证据或交付有问题时，读取 [boundaries](references/boundaries.md)。可选的 [fixed-dispatch adapter](references/bounded-adapter.md) 不是本地执行引擎。不要发明一个运行时、隐藏的机器工件或工作流来完成一个普通变更。

报告结果、最强检查和实质性限制。计划、活动、审查和保存的页面不获得能力信用；NOT_PLANNED 和 NOT_BUILT 是进度描述，而不是语义裁决。
