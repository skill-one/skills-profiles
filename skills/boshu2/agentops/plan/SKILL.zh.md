# 计划

从调用者的疑问中自主发现，形成一个可执行的分片。塑造仅缺失的意图。如果调用者有追踪器，优先使用调用者的追踪器；否则使用对话或提供的文本。计划不会产生 AgentOps 数据包。明确的变更可以直接进行。在整个意图、示例、代码和验证中，使用已建立的域名。仅当问题可以回答时才加载专家；没有一个是必需的计划阶段。

## 工作流

1. 读取接受的意图、紧凑的现有计划或原生转接，以及相关的源所有者和活动约束。在替换或恢复时，在使用下一个操作之前，使用 `[恢复发现](#恢复发现)`。识别调用者可见的结果，并仅对可能改变下一个分片的未确定性进行分类 `[路由未确定性](#路由未确定性)`。
2. 在实现之前描述预期的可观察行为。重用对话或珠子中已提供的接受；仅澄清阻止行动或判断的内容。命名执行者或调用者、事件和可观察的结果。一个示例通常就足够了；对于分支行为和结果边界，使用 Given/When/Then。仅在它们阻止现有源中可能的范围错误时，包含非目标。如果调用者同时请求代码和回顾，区分代码接受、交付事实和同一意图中的后期分析。代码判断消耗接受和检查；回顾消耗已知结果和判断。保持为整体目标所需的两个请求交付成果，不要使任何一个依赖于自己的结论。范围包括手编辑的所有者、受影响的测试/实时消费者和生成者拥有的同伴作为一个类别；它是权威，而不是预测的文件数量。一个结果性假设值得一个早期的区分检查，而不是一个通用的检查清单或详尽的调查。
3. 精炼一个狭窄但完整的垂直分片，包括其受影响的层、实时消费者和有用的检查。它必须产生一个独立可观察的结果，而不仅仅是一个模式、接口或另一个层的计划。在现有意图中保持后期工作粗糙；仅在新的证据使下一个分片可执行时才将其锐化。对于无法逐片保持工作的机械横切迁移，保留与扩展/迁移/收缩方法的兼容性，并说明集成要求。在必要时包含受影响边界证据的重新捕获；在适用情况下使用 `ao provenance evidence-orphans`，而不是一个强制性的账本。在一个史诗中，[导航](../navigate/SKILL.md) 选择下一个珠子；计划塑造该珠子。
4. 当证据证明方法不正确时，在现有意图或转接中简要保留失败的假设、证据和修订的检查。在接受的成果和范围内，方法变更不需要新的权限；接受或范围扩展需要调用者授权。永远不要将失败的接受条件重新标记为警告以获得绿色。
5. 为另一个上下文提供确切的意图引用和它需要采取行动的证据、其写入范围以及谁拥有集成和最终审查。将方法笔记与冻结的接受分开。传递下一个决策和相关的源引用，而不是整个研究历史。一个新的目标不会清除现有的对话，并且一个全新的上下文仍然可以有很大的启动指令、工具目录和检索输入。

一旦实现者可以行动，验证者可以判断，就停止计划。更多的研究、分解或审查必须解决命名的剩余未确定性。一个可选的 `[探测或原型](references/ground-truth-routing.md)` 可以测试一个命名的假设。一个可选的 `[挑战](references/challenge.md)` 可以检查在源检查和相关观察中幸存的结果性未确定性。[记忆召回](../memory/references/recall.md) 仅当先前的证据可能改变下一个行动时才有用。

## 路由未确定性

仅在它们影响行动时，在现有意图中保留这些区别；它们不是四个必需的工作表或连续的阶段。

| 未确定性 | 下一个行动 |
|---|---|
| 源可回答的事实 | 检查最小的权威源并引用它。[研究](../research/SKILL.md) 拥有更深的跟踪和证据综合；[领域](../domain/SKILL.md) 拥有模糊的词汇和规则边界。不要要求调用者复述可检索的事实。 |
| 结果性调用者选择 | 首先恢复现有的授权。仅在目标、行为、偏好或授权仍然需要调用者时，才问一个专注的问题。包括具体的权衡；代理不能提供调用者的答案。 |
| 需要探测的假设 | 说明竞争的预测和区分它们的最小观察。使用可选的探测方法；一个有说服力的设计或代理投票不能解决未观察到的行为。 |
| 安全延迟的决策 | 说明为什么它不会阻塞这个分片，以及会使它相关的事件或证据。保持它粗糙；延迟不能隐藏一个未回答的接受条件。 |

在接受的范围内解决可逆的实现细节。明确标记推断和缺失的证据；不要将它们提升为源事实或一个确定的调用者选择。一个可选的挑战返回建议或下一个区分器，永远不会返回权限或接受。

## 恢复发现

从现有计划或原生转接中恢复当前结果、接受的示例和源身份。重用已解决的领域术语和调用者选择及其源指针；不要重复面试或加载完整转录稿。仅在缺少的事实或新的矛盾可能改变下一个决策时，才按需读取详细信息。
在重用继承的原型证据之前，遵循 `[源漂移后重用](references/ground-truth-routing.md#源漂移后重用)`。

在建议更多工作之前，对照原生追踪器或运行时检查活动分配、写入范围和集成/审查所有权。转接事实是恢复指针，不是第二个权威分配或状态账本。如果原生源不可用或与转接矛盾，报告该差距并在依赖分发或重叠写入之前解决它；独立安全的发现可以继续。

在干扰或替换否则会丢失决策的情况下，在同一源中留下紧凑的更新：接受的成果/引用；已解决的选择和证据；活动分配引用和范围；一个开放的问题和下一个区分器；延迟的决策及其重新访问触发器。包括已知的失败假设和相关相反证据。一个未更改的恢复不需要重复工件。保留原生所有权和原始证据；新的观察在范围内修改方法，而改变的接受仍然需要调用者。

## 行为和命名

示例可以是纯文本；BDD 不需要 `.feature` 文件或面试。例如，在一个将排队工作称为 **Job** 的存储库中：

> Given a Job has already completed, when the worker receives it again,
> then its completed result is returned and its side effect is not repeated.

使用实际的领域术语，而不是发明一个平行的标签，例如“任务项”。识别调用者可以观察的内容以及区分所需行为和当前失败的最小检查。将接受的示例提供给实现和验证。编码后添加的测试可以补充它；它们不能重新定义承诺的内容。

对于不确定的设计，探测可能改变方法的假设。对于产品规划，区分已展示的行为和期望，并在请求范围内仅精炼现有产品所有者。一个产品文档不是普通功能所必需的。

## 决策成本和停止

在选择谁必须决定时，使用真实的撤销成本、受影响的用户和现有权威。在接受的范围内解决可逆的实现细节。在权威范围之外的一个实质性不可逆选择需要调用者；先前的授权仍然有效。审查者同意是证据，不是替换调用者意图的权限。解释一个结果性分歧及其支持，而不是默默地改变接受。

一个提议的过程工件只有在有具体的消费者、主题或发布决策、观察到的缺陷和退役条件时才值得其成本。如果下一个行动仅增加仪式或重复已解决的证据，则省略它。当实现者可以行动，验证者可以判断时停止，保留实现、集成和修复的容量。

决策指针和粗糙的未来工作借鉴了 Matt Pocock 的 [Wayfinder](https://github.com/mattpocock/skills/blob/main/skills/engineering/wayfinder/SKILL.md)；完整的分片和兼容性迁移借鉴了 [To Tickets](https://github.com/mattpocock/skills/blob/main/skills/engineering/to-tickets/SKILL.md)。AgentOps 保留了调用者的现有意图和原生工作权威。

## 身份和范围

使用运行时派生的源身份和摘要。如果对话意图需要一个确切的快照，现有的 `ao provenance snapshot-intent --source - --evidence-root <explicit-root>` 使用调用者选择的受保护的外部非 Git 存储器。缺少路由不允许工作区回退或第二个计划工件。保留传统证据。

使用归一化的存储库相对范围模式。一个未发现的实时消费者需要一个简洁的精确文件修正来调用者；同时继续独立范围内的工作。已在范围内的生成同伴不需要额外的权限。[边界](../rpi/references/boundaries.md) 将工作/状态保留在调用者的追踪器中，交付在存储库策略下。
