# 实现

执行由已解析的珠子或调用者意图所描述的一个有界实验。实现拥有主题编辑和事实证据。它不会创建第二个计划记录或模型授权的候选数据包。

## 工作流

1. 从其现有源读取意图、接受和范围。运行时可能会自动快照并哈希该源以进行漂移检测。
2. 在改变行为之前运行声明的第一个接受检查。RED-first 仅在接受是行为性时适用：保留证据以表明检查因预期的缺失行为而失败。重定位、文档合并和纯重构不需要失败的检查仪式——记录一个诚实的变更前绿色基线。
3. 执行满足活动行为的最小范围内的变更。
4. 运行目标接受检查并捕获事实结果。
5. 仅在那些检查保持绿色时进行重构。重构不会改变接受测试。
6. 让运行时从变更前后的主题中推导出实际变更路径和 `subject-manifest.v1`。不要让模型转录这些事实。
7. 在响应或运行时通道中返回清单摘要、作者上下文 ID 和确切的检查收据。停止。

专家（如标准、领域、测试、重构和安全）可以提供建议。它们永远不会是硬依赖项，并且不能添加生命周期授权。

## 证据比例性

在编辑期间，运行可以伪证活动变更的最小确定性检查。当其主题和工具身份仍然匹配时，重用确切的输入收据。在集成边界运行昂贵的完整套件检查，或在意图明确将其设置为第一个接受检查时才在更早的时间运行。在每次专注编辑后反复重播完整套件会增加延迟，而不是证明。

## 范围冲突规则

在发现变更范围之外的变更的活跃消费者时——一个断言旧路径的测试、一个生成的孪生、一个读取移动文件的网关——停止并报告确切的文件和行给调用者。不要默默地扩展范围以吸收它。意图的一个修复修订是升级到调用者的最大值；2026-07-15 heal-skill 折叠需要三个意图修订（`.agents/ao/intents/sha256/26a4f2be...eb48` 下），因为手动枚举的范围一直遗漏活跃消费者。

在声明绿色之前，自我审计差异中的模拟、占位符、TODO 拐杖和代表实际行为的硬编码固定值。一个针对占位符通过的检查不是接受标准的证据；要么完成行为，要么报告它未构建。

## 边界

- 不要提交、推送、主张、关闭、发布、着陆、保留、重试或调用语义验证器。
- 不要默默地扩展接受。不同的接受合同是调用者单独开始的新意图。
- 一个失败的检查是调用者的证据，而不是创建数据包或验证循环的权限。
