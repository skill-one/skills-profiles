# 演示设计诊断

## 目的

设计和评估能够有效传达信息的演示文稿。提供规划、视觉设计、认知负荷管理和评估的框架。适用于任何演示工具（reveal.js、PowerPoint、Keynote、Google Slides）。

## 核心原则

**以受众为中心的设计。** 每个决策都应为受众理解服务，而非演讲者便利。

---

## 快速参考：常见问题

| 问题 | 症状 | 解决方法 |
|-------|-------|-----|
| 文本墙 | 幻灯片是段落 | 断言-证据结构 |
| 子弹点病 | 列表代替视觉 | 一个概念 + 视觉证据 |
| 万物皆备 | 包含所有内容 | 必要内容与可扩展内容 |
| 仅有外表 | 设计缺乏实质 | 以信息为先的设计 |
| 认知过载 | 每页信息过多 | 每页一个核心概念 |

## 第一阶段：受众与内容规划

### 关键问题

1. **我的受众具体是谁？** 他们的知识水平如何？
2. **唯一的主题是什么？** 他们应该记住什么？
3. **有哪些3-5个支持点？** 如何强化主题？
4. **每个观点有哪些证据支持？** 视觉、数据、示例？
5. **他们应该采取什么行动？** 行动号召是什么？
6. **时间限制是什么？** 必要内容与可选内容是什么？

### 行动事项

- [ ] 创建受众画像
- [ ] 写下核心信息的一句话
- [ ] 按逻辑顺序组织支持点
- [ ] 确定每个观点的证据
- [ ] 定义必要内容与可扩展内容
- [ ] 草拟演示流程

## 第二阶段：视觉策略

### 断言-证据结构

**用以下内容替换子弹点：**
- **断言：** 清晰、完整的句子陈述观点
- **证据：** 支持断言的视觉内容

**而不是：**
```
主要发现：
• 数据显示增长
• 用户参与度更高
• 收入提升
```

**使用：**
```
"用户参与度在改版后提升了43%"
[显示增长的图表]
```

### 视觉原则

- **有限调色板：** 最多3-5种颜色
- **字体层级：** 2-3种字体，有明确角色
- **留白：** 让内容呼吸
- **一致性：** 相同布局，相同处理
- **视觉进度：** 帮助受众了解当前进度

---

## 第三阶段：认知负荷管理

### 每页一个概念

每页幻灯片应回答："我想让他们从这个页面获取什么？"

### 逐步披露

按顺序披露信息，而不是一次性全部展示：
1. 显示初始状态
2. 带上下文的第一个元素
3. 在第一个元素基础上添加第二个元素

### 语音与视觉

| 在幻灯片上展示 | 大声说出 |
|---------------|-------------|
| 关键断言 | 解释说明 |
| 视觉证据 | 上下文和解释 |
| 关键数据 | 解释 |
| 下一步 | 为什么重要 |

### 代码示例（技术演讲）

- 始终使用语法高亮
- 突出显示关键行
- 逐步构建复杂示例
- 尽可能移除样板代码

---

## 第四阶段：结构模式

### 水平与垂直（多级导航）

**水平幻灯片：** 主要叙事流程
**垂直幻灯片：** 支持细节（可选深入探讨）

示例：
- 水平："客户保留的三个关键因素"
- 垂直（在该幻灯片下）：每个因素的详细幻灯片

### 时间灵活性

将内容标记为：
- **必要：** 任何版本都必须涵盖
- **标准：** 正常时间内包含
- **可扩展：** 仅在额外时间内包含

## 改进优先级

评估后：

**1. 紧急问题（立即修复）：**
- 阻碍受众理解
- 可访问性失败
- 核心信息不清晰

**2. 重要改进（第二优先级）：**
- 认知负荷问题
- 视觉一致性问题
- 结构改进

**3. 可选优化：**
- 高级动画
- 自定义样式
- 精细调整细节

## 反模式

### 1. 数据倾泻

**模式：** 每页幻灯片都充满数据、图表和统计数据，没有解释或层级。
**为什么失败：** 受众无法实时处理原始数据。没有解释，他们被迫进行分析而非学习。大部分数据会被立即遗忘。
**修复：** 每页一个见解，用视觉证据支持见解。陈述结论；展示证据。受众应在看到数据前理解你的观点。

### 2. 脚本阅读者

**模式：** 幻灯片包含演讲者的完整脚本——实际上是段落的子弹点。
**为什么失败：** 受众阅读速度比演讲者说话快。他们会提前阅读，然后在你说话时分心。幻灯片变成提词器，而非沟通工具。
**修复：** 幻灯片展示你无法说的内容；你说你无法展示的内容。视觉、图表和关键断言在屏幕上。上下文、解释和阐述口头表达。

### 3. 模板陷阱

**模式：** 将内容放入通用模板，不考虑设计如何服务于信息。
**为什么失败：** 设计应支持理解，而不仅仅是看起来专业。通用模板创造通用沟通。一刀切适合所有人。
**修复：** 设计服务于信息。问：什么视觉结构帮助这个特定受众理解这个特定内容？从沟通需求开始，而不是模板选项。

### 4. 动画马戏团

**模式：** 到处都是过渡、构建和效果——飞行的文本、旋转的图像、渐变。
**为什么失败：** 动画是注意力。每个效果都在说"看这里"。当所有东西都动画时，没有东西突出。受众会感到不知所措或麻木。
**修复：** 动画仅用于逐步披露（逐步构建复杂概念）或强调（突出关键点）。默认无动画；有目的地添加。

### 5. 子弹点病

**模式：** 一页页的子弹点列表——所有内容的默认结构。
**为什么失败：** 子弹点适用于文档，不适用于演示。它们鼓励对不等重要性的观点给予同等权重，文本过多幻灯片，被动阅读而非主动观看。
**修复：** 使用断言-证据结构。用清晰断言和视觉证据替换列表。如果你需要列表，问是否需要幻灯片。
