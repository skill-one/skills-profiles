# OpenSEO 网站内容

我们发布的一切内容都必须能够追溯到产品实际的功能和成本，并且必须像从业者所写的那样。读者的利益是第一位的：教他们可以采取行动的东西，并直接回答——包括当诚实的答案是“不”或“需要花钱”时。

## 原则

1. **可追溯的真实性。** 每一个功能声明、价格和截图都可以与代码、事实表（`src/server/features/onboarding/openseo-fact-sheet.md`）或实际产品进行验证。如果你无法指出其真实来源，它就不会发布。
2. **优先给出真实答案。** “不”、“不是无限的”和“需要花钱”都是完整的答案。那些让读者推断出比真相更令人满意的事情的回避方式是在误导他们。
3. **诚实的定价及其理由。** 高质量的SEO数据到处都很昂贵——这就是为什么大型套件每月要收费100美元或更高。OpenSEO是经济实惠的选择：每月10美元，免费开始。永远不要简单地“免费”。
4. **像人一样说话。** 修复AI告诉的方法是通过平实地重述底层声明，而不是通过修饰文采。[deslop技能](../deslop/SKILL.md)是关于要寻找什么以及如何修复它的参考。
5. **以读者为中心的高度。** 指南教授独立的可操作的SEO——不是产品文档，不是通用的填充内容。将免费资源归功于其真正所有者（Google的自动完成、读者的搜索控制台）。
6. **一条标准，整个表面。** 当标准改进时，将所有的一切都更新到它——所有的常见问题解答，所有的页面——而不仅仅是被注意到的那个实例。
7. **剧本术语。** 将OpenSEO剧本中的每种方法称为“策略”，而不是“玩法”。使用“工作流”来指代读者执行的操作步骤；仅使用“剧本”来指代完整的集合。

## 审查时需要问的问题

- 如果读者信任每一个声明和截图，然后立即打开OpenSEO，现实与哪里不符？
- 每个答案都以真实答案开头，还是悄悄地引导读者得出更令人满意的推断？
- 大声朗读最尖锐的那句话：一个人会那样说吗？
- 是否有任何被称为免费但实际上需要花费积分的内容？
- 这是在教读者一些有用的东西，还是在漂移到产品文档或填充内容？
- 页面上的每个链接、图像和示例是否都值得读者保留？

## 需要验证的事实，而不是记忆

在重复任何这些内容之前，请与代码进行核对——它们会变化：定价和积分（`src/shared/billing.ts`，定价页面）、免费计划的限制（`src/shared/audit-limits.ts`）、MCP功能（`src/server/mcp/tools/`——每个工具一个文件），以及任何UI功能告诉读者要使用的内容（列、排序或过滤器必须在客户端代码中存在）。

## 流程

生成子代理来运行审查传递（语音/deslop、声明准确性、直接性），并让他们返回精确的旧→新提案，而不是直接编辑。不要盲目接受他们的提案：在应用之前，请逐一与实际文件核对，并逐一与代码核对事实声明——子代理重写可能会引入自己的尴尬或错误，并且与文件不匹配的提案意味着它审查了过时的文本。应用后，自己清理更改的表面（模式会聚集——一个破折号或回避通常有邻居），然后运行`npm --prefix web run types:check`并对接触到的TS/TSX运行prettier。
