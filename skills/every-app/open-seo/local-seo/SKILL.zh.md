# OpenSEO 本地SEO

## 目标

找出为什么一家商家的名称会或不会出现在其客户附近的谷歌地图和本地套餐中，以及首先要解决什么问题。

当排名取决于物理位置或服务区域时，使用此工具。对于全国范围的有机工作，请使用 `competitor-analysis` 或 `keyword-research`。

## 必须的输入

- `projectId`
- 商家：名称，或 `cid`/`placeId`（最可靠）
- 其坐标（纬度/经度）—— 从 `search_local_businesses` / `get_local_serp_results` 行中推导；仅在推导不明确时才询问用户
- 1到3个客户实际搜索的关键词（例如 "紧急水管工"，而不是品牌名称）

## 项目上下文

项目上下文工具免费，并与应用程序和其他代理共享。

1. 首先调用 `get_project_context` 并将其作为工作基础——商家从事的业务和运营地点决定了哪些关键词和半径是重要的。
2. 此技能需要 `business_overview`。如果它为空，请运行最小的内联设置：从网站推断商家从事的业务及其位置，并通过一个问题与用户确认，然后使用 `update_project_context` 将其写回，然后继续。永远不要预先加载完整的访谈；建议在最后使用 `seo-project-setup`。
3. 在花费积分之前，检查研究日志。如果相同的研究在过去30天内运行过，请重用该结果并说明，而不是重新购买。
4. 完成后，使用 `update_project_context` 写回持久内容——通过 `addCompetitors` 拥有网站的本地竞争对手（竞争对手行按域名键值对，因此跳过没有的列表），修正的 `business_overview` —— 并附加一个研究日志条目：`{ appendResearchLog: { summary: "本地SEO: <商家> 在 <区域>。结论: <结论>" } }`。

## 以报告形式交付

通过 `seo-report` 技能交付，并使用 `skill: "local-seo"` 保存。如果该技能不可用，请说明并在写入HTML之前停止。

## OpenSEO MCP工具

- `search_local_businesses`：附近的列表，可按 `minRating`、`minReviews` 和 `isClaimed` 过滤——使用 `isClaimed: false` 在开发时查找未认领的列表。一次调用，使用品牌名称作为 `query` 和宽半径，可以返回连锁店每个位置的类别、评分、评论数量、认领状态、坐标和 `cid`——通常足够，无需对每个位置进行 `get_business_profile` 调用。
- `get_local_serp_results`：靠近坐标的地图/本地查找结果集。行包含 `cid` 和 `place_id`——收集一次并在下面重复使用它们。
- `get_business_profile`：当 `search_local_businesses` 行不足以提供完整信息时，一个商家的完整资料（营业时间、评分细分）。
- `get_business_reviews`：带有评分、文本以及所有者是否回复的评论。排队：`processing` 响应返回 `taskId`——30-60秒后再次调用它，无需额外费用。
- `get_local_rank_grid`：围绕坐标的每个网格点的排名，以及每个点的结果数量和第1名商家。3x3是九次搜索；仅在服务区域确实很宽时才扩展到5x5。
- `get_google_business_questions`：资料上的问答（接受 `cid`/`placeId`）。
- `get_business_updates`：资料上发布的帖子，以及日期。
- `list_business_categories`：`search_local_businesses` 的有效类别slugs。

## 工作流程

1. 找到商家。仅给定名称或网站时，`search_local_businesses`（名称作为 `query`，宽半径）定位列表并生成其 `cid` 和坐标。如果它返回多个位置，则商家是连锁店——见多地点以下。
2. 运行 `get_local_serp_results` 以获取商家坐标附近的主要关键词。记录前3-5名竞争对手的 `cid`/`place_id` 和用户自己的行。
3. 将用户的列表与前两个主要竞争对手进行比较：主要类别、附加类别、评论数量、营业时间完整性、照片数量、认领状态。`search_local_businesses` 行通常包含所有这些信息；使用 `get_business_profile` 获取缺失的部分。
4. 检查每个列表的网站链接（行中的 `url`/`contact_url`）：它应该深度链接到项目域上该位置的页面，而不是主页或过时的域名。对于更广泛的页面工作，转交给 `run_site_audit`。
5. 调用 `get_business_reviews` 以获取用户和最强的竞争对手。查看评论数量、时效性、平均评分以及多少评论得到了所有者回复。
6. 运行 `get_local_rank_grid` 以获取主要关键词。使用网格将“仅在门店排名”与“在整个服务区域排名”分开，并使用每个点的 `topResult` 来命名目标未出现的地方的获胜者。
7. 当资料基本具有竞争力，差距在于参与度而不是设置时，添加 `get_google_business_questions` 和 `get_business_updates`。
8. 将证据转化为优先列表。类别和认领问题总是优先于发布频率。

### 多地点商家

始终为整个连锁店构建资料快照表——一次 `search_local_businesses` 调用就足够了。每个位置的深度研究（评论、网格、帖子、问答）是成本扩展的地方：

- 5个地点或更少：深入研究所有地点。
- 超过5个：展示快照表，然后询问用户（AskUserQuestion）要深入研究1-3个地点。选择合理的默认值来推荐——例如在密集市场中拥有最弱资料的地点。

## 输出格式

`h1`：商家名称。

如果报告模板适用（见 `seo-report`），其部分和语气将替换此列表。

按此顺序排列的部分：

1. **快照**——一到两句话，然后是一个类别、评分、评论数量和认领状态的表格。连锁店每个位置一行。
2. **一个修复**——一个发现。类别和认领问题总是优先于发布频率。
3. **一对一比较**——一个表格，信号、此商家、最佳竞争对手和差距。涵盖类别、评论（数量、时效性、所有者回复）、营业时间和资料完整性，以及列表的网站链接。
4. **地图覆盖范围**——网格显示的内容，可见性下降的地方，以及谁在那里获胜。方向排名的条形图比段落更容易阅读；标记每个值。
5. **问答和发布**——仅当资料基本具有竞争力时。
6. **下一步做什么**——一个有序列表。
7. **此报告是如何制作的**——以 `seo-report` 的技能链接行开头，指向 `https://openseo.so/docs/skills/local-seo`（"OpenSEO 本地SEO技能"），然后是哪些工具返回了什么，并附注说明每个缺失的网格排名与该点的 `resultsCount` 而不是将其称为不可见。

## 防护措施

- 在运行5x5网格或多个关键词的网格之前，先告诉用户成本——每个点都是一个付费SERP调用。
- 当你有 `cid` 或 `place_id` 时，通过名称匹配商家。名称匹配与连锁店和名称相似的商家冲突。
- 网格点上的缺失排名意味着商家不在该点返回的结果中。使用该点的 `resultsCount` 来阅读它：完整的结果集意味着排名靠前；接近空的结果集意味着稀疏的SERP，而不是不可见的证明。
- 不要从全国范围的有机指标推断本地套餐的强度。
- 永远不要推荐评论限制、虚假评论或关键词填充的商家名称。
- 以错误的位置为中心的网格比没有网格更糟糕——在花费网格积分之前，确认坐标与门店匹配。
