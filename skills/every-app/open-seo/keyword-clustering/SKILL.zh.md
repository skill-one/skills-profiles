# OpenSEO 关键词聚类

## 目标

将关键词分组到页面级别的集群中，并决定每个集群应该由现有的页面还是新的页面来定位。这是一个关键词映射工作流程，而不仅仅是语义分组练习。

## 必须的输入

- `projectId`
- 关键词列表、保存的关键词标签、种子主题或目标域名
- 可选的现有 URL/页面用于映射

如果未提供关键词，使用 `list_saved_keywords` 获取保存的集合，使用 `research_keywords` 进行种子发现，或在用户从目标域名开始时使用 `get_ranked_keywords`。

## 项目上下文

项目上下文工具是免费的，并与应用程序和其他代理共享。

1. 首先调用 `get_project_context` 并将其作为基础进行映射——保存的关键页是现有页面集群应该映射到的，业务和目标决定了哪些集群值得定位。
2. 此技能需要关键页面。如果没有保存，运行最小的内联设置：询问用户哪些页面很重要，或从网站、审核或搜索控制台提出简短列表并确认，使用 `update_project_context` (`addKeyPages`) 将其写回，然后继续聚类。不要提前加载完整访谈；建议在最后使用 `seo-project-setup` 进行其余部分。
3. 在花费积分之前，检查研究日志。如果过去 30 天内运行了相同的研究，请重用该结果并说明，而不是重新购买。
4. 完成后，使用 `update_project_context` 写回持久内容——新的或更正的 `addKeyPages` 条目以及每个页面现在定位的主题——并附加一个研究日志条目：`{ appendResearchLog: { summary: "关键词聚类: <关键词集合>. 结论: <结论>" } }`。

## 以报告形式交付

通过 `seo-report` 技能交付，并使用 `skill: "keyword-clustering"` 保存。如果该技能不可用，请在写入 HTML 之前说明并停止。

## OpenSEO MCP 工具

- `list_saved_keywords`：获取现有的关键词集合，可选地按标签过滤。
- `research_keywords`：当用户从主题开始时扩展种子。
- `get_ranked_keywords`：当用户从域名或页面开始时收集精确排名的关键词和 URL。
- `get_search_console_performance`：当连接到搜索控制台时，使用 `dimensions: ["query","page"]` 拉取真实查询，以将术语映射到已经获得印象的页面，并暴露蚕食（一个查询将点击分散到多个 URL）。
- `get_serp_results`：通过检查 SERP 重叠和意图来验证关键词是否属于同一页面。
- `get_local_serp_results`：用于本地 SEO 集群，当地图/本地包意图会影响页面映射时使用。
- `save_keywords`：在用户确认后，可选地为最终集群添加标签。

## 工作流程

1. 收集候选关键词集合。
   - 当连接到搜索控制台时，使用 `get_search_console_performance`（维度 `["query","page"]`）从真实查询和已经排名的页面开始。
   - 使用 `get_ranked_keywords` 进行域名/页面驱动的聚类。
   - 使用 `search_local_businesses` 和 `get_local_serp_results` 当邻近性、本地包或 Google Business 结果决定术语是否属于位置页面时。
2. 移除重复项、不相关的术语以及明显需要不同产品或受众的术语。
3. 围绕意图和页面类型构建集群：
   - 相同 SERP 意图和类似排名页面属于同一集群。
   - 不同意图、购买阶段或 SERP 格式应分开。
   - 相似词语并不保证属于同一集群。
4. 对于重要的边界术语，使用小的 `get_serp_results` 批次进行检查重叠。
5. 为每个集群分配：
   - 现有 URL（如果提供且合适）
   - 新页面建议（如果没有合适的现有页面）
   - 不定位/后期桶（如果较弱或离战略）
6. 当多个页面会定位相同意图时，识别蚕食风险。当连接到搜索控制台时，使用 `get_search_console_performance` (`dimensions: ["query","page"]`) 从真实数据中确认——相同的查询将印象发送到多个 URL。
7. 在应用集群标签之前使用 `save_keywords` 询问。

## 输出格式

`h1`：网站或关键词集合。

如果适用报告模板（见 `seo-report`），其部分和语气将替换此列表。

按顺序排列的部分：

1. **地图**——一到两句话：集群数量、要创建的页面数量、要更新的页面数量以及任何发现的蚕食。
2. **集群**——一个集群、主要关键词、意图、目标页面和优先级的表格。将次要关键词保留在每个集群简报中，而不是在此表格中。
3. **页面简报**——每个集群一个发现：页面类型和搜索者的问题，然后是创建或更新的页面。在下方列出所需部分和内部链接。
4. **蚕食**——一个查询、竞争 URL 和要保留哪个的表格，只有当有真实证据时才显示。
5. **下一步该做什么**——一个有序列表，包括标签建议和在应用它们之前明确的询问。
6. **此报告是如何制作的**——以 `seo-report` 的技能链接行开头，指向 `https://openseo.so/docs/skills/keyword-clustering`（"OpenSEO 关键词聚类技能"），然后是关键词的来源，以及一个标记目标页面为建议的注释（当未提供 URL 数据时）。

## 防护栏

- 不要过度聚类微小的关键词集合。如果可用术语少于 10 个，则生成一个简单的地图。
- 不要仅依赖词汇相似性。SERP 意图优先。
- 不要在没有明确确认的情况下广泛替换标签。
- 如果缺少现有 URL 数据，则将目标页面标记为建议。
