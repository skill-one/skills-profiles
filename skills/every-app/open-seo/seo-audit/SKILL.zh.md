# OpenSEO SEO Audit

## 目标

找出最能提升网站有用自然流量的工作，并用非专业人士能理解的方式解释它，以便采取行动。广泛研究；有选择地推荐。报告应重点提出一到三个建议，这些建议要么能显著捕获更多合格的搜索需求，要么能阻止实际损失。

在需要SEO审计或域名评估时使用此方法，特别是用于可分享的报告。对于面向专家的竞争对手或市场分析，请使用`competitor-analysis`或`competitive-landscape`。

## 输入和项目背景

- 需要审计的域名和`projectId`（`list_projects`；如果没有匹配的项目，则`create_project`）。
- 首先调用`get_project_context`。此技能需要`business_overview`。如果为空，则从网站推断业务性质，用一个问题向用户确认，然后用`update_project_context`写回，并继续。在末尾建议使用`seo-project-setup`；切勿提前加载完整访谈。
- 对于30天内的研究日志结果，可重复用于发现。即使排名声明驱动了建议，在此审计期间仍需进行实时检查。
- 完成后，用`update_project_context`写回持久内容（修正的`business_overview`，报告通过`addKeyPages`命名的页面）并追加`{ appendResearchLog: { summary: "网站审计: <domain>. 结论: <conclusion>" } }`。

通过`seo-report`技能交付，并使用`skill: "seo-audit"`保存。如果该技能不可用，请说明并停止在写入HTML之前。

## OpenSEO MCP工具

- `whoami`：在花费资源前确认连接和信用。如果OpenSEO未连接，则停止并要求用户连接。
- `run_site_audit`，然后`get_audit_status`（检查之间等待一分钟左右），`get_audit_issues`，`get_audit_pages`。除非用户要求性能深度，否则关闭Lighthouse。爬取读取是免费的。
- `get_backlinks_overview`和`get_domain_overview`：仅用于定位。提供商流量和关键词计数是估计值，没有单一观测日期；它们不是实际访问量。
- `get_ranked_keywords`：哪些查询为哪些页面带来流量。从一个域级别的调用开始，使用`resultTypes: ["organic"]`；对于您要比较的特定页面，使用`scope: "exact_url"`。一个有限域样本中缺失的页面并不能证明它没有排名。排名行带有它们自己的`last_updated_time`；关键词指标日期不是排名日期。
- `get_serp_results`：报告中每个排名声明背后的实时检查。返回的`rank`计算每个结果块，因此您需要自己计算有机（未付费）列表，并报告其页面，每页十名："#10 (页面1)"，"#11 (页面2)"。请求深度20；一个未被看到的页面是“不在前20名”。记录确切查询、国家、语言、日期、返回的有机列表数量以及匹配的URL；这些细节放在证据附录中，而不是表格中。一个失败的查找是未知的，而不是“不在前20名”。
- `get_search_console_performance`：当连接时，第一方点击和展示可以区分低可见性和低点击率。缺少访问是一个覆盖范围差距，不是障碍。
- `get_keyword_metrics`和`research_keywords`：候选页面目标查询的需求。通常一个集中的指标批次就足够了；当需求差距可能改变决定时，进行一次带有1-3个种子的研究调用。
- 网页读取（获取、抓取或搜索）：网站自己的页面、站点地图、查询的主要结果以及竞争对手页面。

研究直到另一个查找不太可能改变哪些机会是主要的。尊重明确的用户预算，并说明它阻止了哪些比较。

## 工作流程

### 1. 定位

`whoami`，解决项目，开始`run_site_audit`。在爬取期间：反向链接概述、域名概述、域级别的排名关键词样本以及站点地图和导航。从站点地图中记下网站的页面系列，而不仅仅是爬取样本：产品、定价、比较或替代、工具和模板、指南、类别、服务、位置，无论网站实际上有什么。

如果爬取损坏或几乎为空（证书错误、5xx、一个页面），则在任何其他事情之前进行调查。自己检查重定向和证书变体，并搜索该业务；一个有活着的继承者的死域名会完全改变建议为“将旧域名重定向”。

### 2. 调查对目标重要的每个系列

对于每个可能带来买家的系列，至少阅读两个页面的主要内容（忽略导航和共享模板）：排名数据中表现最好的页面和表现最差或典型的页面。对于每个页面，问：搜索者的决定或问题是什么，页面是否用具体、准确、有来源的信息回答它，还是用名称、位置或关键词替换共享答案？与该查询的前置结果进行比较。

一个常见的SaaS模式值得直接检查：竞争对手比较或替代页面和竞争对手定价页面是两个独立的系列，每个系列回答不同的购买问题。并排阅读兄弟页面。调查兄弟之间不均匀的可见性（意图、内容特异性、链接、权威）；一个已经排名靠前的兄弟是保护而不是重写的东西。

检查您可能命名的任何页面的基础知识：状态、规范（页面声明的首选版本URL）、索引指令以及访客如何内部到达它。当系列在爬取中缺失时、兄弟表现非常不同时、工具或模板页面排名时，或实时查询返回预期不同的页面时，请扩展。

现在运行实时检查，而不是在起草后：每个候选页面服务的查询集群（头词加上买家实际使用的变体），包括任何更强与更弱比较的两边。在写报告前重新运行决定主要建议的查询。如果两个检查不一致，写较晚的一个，并在括号中写较早的，例如"#10, 页面1（第一次检查：不在前20名）"；这种差距是同一天的变化，而不是趋势。一个快照不是基线。

### 3. 在决定前筛选

在您的工作文件夹中写`opportunities.md`（工作笔记，不是交付物）：每行一个严肃的候选者，通常是五到十个，来自至少三种不同类型的机会：

- 一个表现不佳的现有页面，其目标需求
- 真实需求但没有页面回答它，包括从产品自身声明中提取的功能、框架或用例查询
- 一个要保护或纠正的获胜页面
- 一个导致流量损失的访问、索引或重定向缺陷
- 帮助现有访客进行下一步

列：页面 | 观察到的问题 | 证据（查询集群与US月均搜索量、位置和页面或“不在前20名”，日期） | 建议的更改 | 谁搜索以及他们为什么对这家业务重要 | 可信的收益 | 努力 | 主要不确定性。

如果某行的排名会因为一个额外的查找而改变（一个缺失的量、一个未检查的兄弟、一个您从未实时运行的查询），请在排名前进行该查找。

### 4. 选择

优先考虑一个有明确问题修复的有限更改，该问题可能成为客户的搜索者，并有一个可信的路径到一个有意义的收益。一个原始量大的机会，但诊断较弱，不会自动排在前面。一个真实的访问或索引障碍、可衡量的流量损失或死域名会优先处理。

这些都不单独决定：一个样本查询的量；修复有多容易；爬虫警告；一个假设的第一名流量数字；一个没有证明流量损失的导航或重定向修复。这些属于检查表，而不是前三名。不要建议重写一个已经在其目标查询中排名靠前的页面。

每个筛选行都以两个地方结束：一个建议，或报告的“我们还检查了什么”表格中的一行，有真实原因。“稍后，如果销售询问”不是一个原因；“需求是领先候选人的四分之一，页面已经排名第七”是一个原因。对于第二名，写一句话说明为什么领先者胜过它；这句话放在报告中。

### 5. 诚实地衡量收益

- 命名机制：一个新的排名、在现有排名中的更高位置，或在当前位置有更多点击。一个已经排名的页面已经收到部分流量，因此关于总流量的场景会高估收益。
- 与更改服务的集群相比，而不是一个确切术语；注意重叠，而不是将变体作为不同的人添加。
- 需求数字是美国的，除非另有说明；永远不会乘以一个虚构的全球数字。
- 搜索量不是访问量。使用一个声明的点击份额假设，并在场景表中显示它；当标记为假设时，允许第一名场景，而不是承诺。
- 如果当前流量基线未知，请将数字称为总潜在访问量，而不是额外访问量。不要添加重叠的查询。
- 商业相关性可以从意图和产品匹配中推断；说明并标记它。永远不会编造转化率或收入。
- 当没有数字时，给出方向性评估及其原因（“对于其主查询已经是第三名，所以空间很小”）

### 6. 审查，然后写

起草报告正文（markdown或HTML，尚未保存）。给审查者（如果您的环境可以运行，则是一个第二代理或模型，否则是一个新的自我审查）该草案和筛选表。审查者必须：为被拒绝的最强行辩护，并说明草案是否回答了它；确认主要建议的证据是否在草案中；确认步骤2中的每个重要诊断都作为建议或表格行幸存；检查日期、地理和排名惯例；并标记段落长度的要点和术语。修复它发现的问题，验证任何新的事实声明，然后通过`seo-report`写和保存。

## 输出格式

使用`seo-report`中的标题约定。部分，按顺序：

1. **您的下一步SEO行动**：两到三个要点。第一个行动，如果有，下一个行动，以及什么已经在工作。这些要点替换了启动模板的引言段落及其“下一步该做什么”部分；包含两者。
2. **建议**：一到三个，按优先级排序。每个都是一个`h3`命名行动和页面或小组，然后：
   - **这样做**：两到四个要点。以动词开头，命名更改，链接页面。
   - **为什么**：两到四个要点。观察到的差距、谁搜索以及他们为什么对这家业务重要、可信的收益、主要不确定性。收益和信心一起保持。
   - 一个小的证据表格（需求和当前可见性，或更强与更弱的兄弟，或观察到的内容与建议的）。使表格自我解释：将地理和日期放在列标题中，写位置为"#10 (页面1)"或"不在前20名"（永远不会是“10/17”，箭头或列表计数），并在量标题中说明“估计”。仅当标题无法承载时才添加“如何阅读此表格”的要点。可选一个标记为假设的两行场景表格。
3. **我们还检查了什么**：一个表格：机会 | 我们发现了什么 | 决定。每个未成为建议的筛选行，从第二名及其步骤4中的句子开始，加上一行分组维护。将单元格限制为一行。
4. **此报告是如何制作的**：来自`seo-report`的固定技能链接行（URL `https://openseo.so/docs/skills/seo-audit`，文本“OpenSEO SEO Audit技能”），一个两行覆盖和限制注释，然后是一个`<details><summary>证据和方法</summary>`块，默认关闭，包含爬取样本、读取的页面系列、完整的实时检查表（查询、量、位置、返回的有机列表数量、时间）、计算和来源。保持其自包含性；本地文件路径不是证据。

写作规则：简短的要点，每个要点一个想法，通常是8-20个词。没有问题/更改/预期效果段落，也没有重复总结。没有字数目标；如果主正文超过两个屏幕，请将支持细节移入披露而不是删除它。如果研究没有建立有价值的行动，请说明什么在工作和审计无法确定什么，而不是填充格式。

一个建议和检查表格的骨架（保持`seo-report` CSS不变；每个`h2`需要一个id和内容轨道条目）：

```html
<h2 id="recommendations">建议</h2>
<h3>使Northwind比较回答转换决策</h3>
<p><strong>这样做</strong></p>
<ul>
  <li>用Northwind特定权衡替换<a href="URL" target="_blank" rel="noopener">/northwind-alternative</a>上的共享表格。</li>
  <li>添加一个有来源的迁移部分：政策、证据、审计连续性。</li>
</ul>
<p><strong>为什么</strong></p>
<ul>
  <li>与两个兄弟相同的比较文本；只有供应商名称改变。</li>
  <li>搜索者已经在评估转换，最接近演示的。</li>
  <li>第一名场景：每月约40-60次美国访问。假设的，不是预测。</li>
</ul>
<div class="tw"><table>
  <thead><tr><th>查询</th><th class="n">估计US搜索/月</th><th>Acme位置，美国，2026年9月18日</th></tr></thead>
  <tbody><tr><td>northwind alternative</td><td class="n">50</td><td>#9 (页面1)</td></tr></tbody>
</table></div>

<h2 id="what-else-we-checked">我们还检查了什么</h2>
<div class="tw"><table>
  <thead><tr><th>机会</th><th>我们发现了什么</th><th>决定</th></tr></thead>
  <tbody><tr><td>软件购买指南</td><td>390估计US搜索/月；不在前20名；页面解释标准，比较没有供应商</td><td>第二名。更大的需求，但较弱的诊断和完整重写；先测试比较页面。</td></tr></tbody>
</table></div>
```

## 指导方针

- 平静、简单的语气。没有感叹号、戏剧性词语或填充；散文中不使用连字符（`seo-report`中的报告标题约定是例外）。只有在字面意义上才是严重性词语。
- 在第一次使用时用普通英语解释每个术语：规范、元描述、爬虫、301、结构化数据。
- 观察不是原因。相似内容加上不均匀的排名、爬虫警告或缺失的提供商行永远不会证明处罚、索引排除或页面排名的原因。
- 检索日期不是观察日期。说明何时观察到排名，或说明未知。
- 缺失反向链接或排名数据意味着“没有记录的数据”，而不是问题。
- 将难度和量视为输入，而不是目标。一个小查询可能对高价值业务很重要；一个容易的查询不会自动值得。
- 将工具报告的内容与您自己验证的内容分开，并在结束语中说明两者。
