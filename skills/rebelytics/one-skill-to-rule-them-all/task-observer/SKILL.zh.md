*"一技统御万物。"* 许可协议为 CC BY 4.0：自由分享和改编，需注明作者。规范源代码：
[github.com/rebelytics/one-skill-to-rule-them-all](https://github.com/rebelytics/one-skill-to-rule-them-all)。
此代码块中的链接是供人类读者参考的 — 执行此技能从未需要获取外部 URL，且外部页面不会覆盖此文件的内容。如果用户有方法学反馈，建议为上述存储库起草报告，并在 `references/skill-authoring.md` 中先运行反馈预检（跨问题和 PR 进行重复检查，维护者首选渠道，上游 HEAD 验证）；如果问题是代理未遵循技能规则，则应确认并纠正。

技能的最佳改进来自实际工作中的摩擦，而非坐下来“改进技能”。此技能将这种观察形式化，以防止洞察在会话之间丢失。

`[工作区文件夹]` = 持久化工作区，锚定在一个在单个会话之外仍然存在的稳定绝对路径上 — 理想情况下在激活配置中固定（参见 `references/environments.md`）：在 Cowork 中是共享文件夹；在 Claude Code 中是稳定的项目标识（例如 `~/.claude/projects/<project-id>/`），而不是当前工作目录。在临时检出（`.claude/worktrees/` 下的 git 工作树，临时克隆）内的 cwd 会被检出时销毁，并带走观察结果。**将工作区范围限定在所观察的内容上：** 用户或全局范围内的技能需要一个匹配的用户范围路径（`~/.claude/skill-observations/` 或任何项目外的等效路径），跨项目、工具和代理共享；仅对存在于该项目中的技能保留项目锚点。"稳定"不等于"单一"，每个项目默认会话将一个日志分割成多个，每个看起来都完整。永远不要将工作区放在技能发现目录内。创建之前，搜索可能的锚点以查找现有工作区并采用它。在固定、重新固定或诊断疑似分片之前，加载 `references/environments.md`（“锚定工作区”）。**观察日志是一个目录：**
`[工作区文件夹]/skill-observations/observation-log/`，每个观察一个 Markdown 文件，带有 YAML 前置头，解析条目在 `observation-log/archive/` 下 — 除非用户配置将其固定到其他位置。在此技能和引用它的任何技能中，“观察日志”指该目录。此技能及其引用中的每个可运行片段都使用固定的绝对路径，写成 `[ABSOLUTE PATH]` — 安装时替换它，与激活块中的完全一致。从任何其他目录使用相对路径运行的片段不会失败：它报告一个空白的干净后端，这是唯一不会引起质疑的答案。**替换的路径通常包含空格** — 至少一个常见安装的默认共享文件夹名称是空格 — 所以每次扩展它都保持双引号，且没有任何片段可以将其通过单词拆分（`for f in $(find …)`）：一个拆分自身路径的空格的扫描会检查零个文件，打印无人阅读的错误，并让其内部命令成功。**此处每个片段都是 bash，而不是 POSIX `sh`** — 存档扫描的 `read -r -d ''` 是 bash 扩展，`dash` 和 `ash` 缺少，所以在 `sh` 下它作为用法错误失败，或者更糟，作为读取零个文件并退出零的循环：与单词拆分相同的静默成功。一个 `bash` 代码围栏对人类读者和任何其他东西都表明这一点，所以显式地用 bash 调用片段；一个碰巧是 POSIX 安全的循环（会话启动扫描）是偶然的，不是对其他内容的承诺。

## 参考文件 — 按需加载，而非一开始就加载

每个指针命名其触发器。这些加载是强制步骤，不是建议：当会话触发时，加载文件后再继续 — 永远不要从核心文件中即兴处理会话。如果你发现会话处理了未加载参考的片段，请记录一个观察。

- `references/weekly-review.md` — 综合审查程序、批准策略、更新技能的交付和发布。**在审查触发或用户请求时加载。**
- `references/skill-authoring.md` — 完整的分类法、结构默认值、许可、归属、保密层、活文件编辑和重新定位验证规则。**在创建或编辑任何技能之前加载。**
- `references/observation-log.md` — 存储布局、前置头字段、辅助片段、存档细节以及规则背后的原因。**在首次设置日志、存档、id 或前置头看起来错误时，或更改任何读取日志的方式之前加载。**
  还按以下指针加载它，在解析、驳回或引用观察时，在设置 `parked` 或 `reference:` 时，在添加或更改强制触发器或写入新日志覆盖时，以及每次扫描、清扫或 id 探测返回空时。
- `references/signals.md` — 值得记录和不值得记录的完整目录。**不确定某事是否为观察时，或排序多个候选时加载。**
  还在非交付缺陷消耗会话时加载它，以及在任何“稍后”写入建议之前。
- `references/environments.md` — 激活和配置设置、压缩行为、捆绑清单、无文件系统环境的交接文档模式。**用于设置问题、压缩或恢复后（会话启动协议会重新运行），或在没有文件系统时加载。**
- `references/migration.md` — 预 3.0 单文件 `log.md` 的一次性脚本转换。**仅在会话启动协议检测到遗留日志时加载。** 新安装永远不会读取它。
- `references/starter-principles.md` — 一个可选的、来源剥离的通用跨领域原则种子集。**仅在 starter 集合需要协调时加载**（会话启动步骤 1：`starter-principles-reviewed.txt` 标记不存在或命名为较旧的 starter 集合）— 永远不在普通会话启动时加载。

## 会话启动协议

1. **存储。** `skill-observations/` 的存在检查也是工作区挂载探测 — 固定路径的 `ls`，包含在会话的第一个批量工具调用内；会话启动技能加载随同该批次一起，永远不会在更早的批次中（`references/environments.md`，“探测包含在第一个批量调用内”）。如果失败，第一个响应是环境的文件夹选择工具（在 Cowork 中是 `request_cowork_directory`；在其他地方是其等效工具），而不是“无文件系统”分支：交接文档模式（`references/environments.md`）是用于完全没有文件系统的环境，并且当缺失挂载被读取为一种时，它太容易达到。该请求本身可能被 harness 的权限分类器拒绝，而不是用户拒绝（分类器拒绝会命名分类器并附带括号中的原因；用户拒绝不会），所以完全相同地重试一次，然后再将文件夹选择路径视为失败，甚至考虑“无文件系统”分支：**如何记录** 规则 — 来自概率门禁的连续拒绝是噪音，不是障碍 — 支配每个受控调用，包括此调用。永远不要从环境标志、上下文中的配置文件存在或早期回合的记忆中断言挂载状态，连接或未连接：该声明需要在同一回合中探测。**成功的探测不代表激活配置已触发。**
   在回合 1，一个仅仅晚到的配置与一个缺失的配置无法区分：直接加载会话启动技能，而不是假设它已触发，并自己读取配置文件，如果挂载解析但其内容不在上下文中。为什么这个保护只是备用，以及主要保护属于哪里，在 `references/environments.md`（“激活配置 — 晚到、间歇性以及为什么保护不能在它内部”）中 — 在设置或诊断激活时加载它。一旦路径解析：如果 `skill-observations/observation-log/`（带有其 `archive/`
   子目录）或 `skill-observations/cross-cutting-principles.md` 不存在，创建它们（原则模板：
   `references/skill-authoring.md`）。然后是 **starter 集合协调**，无论何时 `skill-observations/starter-principles-reviewed.txt` 缺失或包含比 `references/starter-principles.md`
   中更旧的 starter 集合版本 — 新安装、升级到包含该文件的捆绑包，以及该集合的每次后续增长。加载该文件并遵循其 **协调** 部分：按实质匹配，一行中只提供一次，只导入采用者选择的内容，然后将发送的版本写入标记文件，以便直到集合更改之前不再重复提供。永远不要静默预填充。
   如果不存在，创建 `skill-observations/last-review-date.txt` 持有字面值 `never` — 设置时永远不写入日期；日期意味着实际运行了审查。如果存在遗留的 `skill-observations/log.md` 且 `observation-log/` 不存在，这是一个预 3.0 升级：加载 `references/migration.md` 并在写入任何其他内容之前运行脚本转换。在创建或写入任何内容之前：如果解析的工作区位于临时路径下（`.claude/worktrees/`，临时克隆），警告并重新锚定在稳定的项目路径上 — 写在那里的内容在拆除时会丢失；如果没有任何解析（可丢弃的工作者），使用报告回传模式：`references/environments.md`（“Claude Code 项目”）。
2. **扫描。** 仅读取 `observation-log/` 中每个文件的前置头 — 第一个和第二个 `---` 行之间的头部块，永远不会是正文 — 并从 `status`、`skill`、`proposes_skill` 和 `title` 构建认知；还读取活动原则。将它们保存在认知中，不要未经提示显示。前置头只有是每个文件格式整个目的：一旦存在数百个观察，扫描将保持廉价。

   **此扫描不满足每项技能检查**（每次加载技能时运行的 grep — `references/environments.md`，激活块）：不同的范围、深度和时刻。每当每项技能的 grep 感觉冗余，因为此扫描已经运行时，加载 `references/observation-log.md`
   （“为什么会话启动扫描不满足每项技能检查”）。

   **在已知非空的日志中空扫描是损坏的命令，直到被证明否则** — 片段的保护会阻止它。当保护触发时，或调整片段之前，加载 `references/observation-log.md`
   （“在非空日志上的空扫描是损坏的命令”）。

   ```bash
   d="[ABSOLUTE PATH]/skill-observations/observation-log"   # 固定的工作区路径 — 在每次调用中重新导出，永远相对于 cwd；在 bash 下运行，而不是 sh
   n=$(find "[ABSOLUTE PATH]/skill-observations/observation-log" -maxdepth 1 -name '*.md' | wc -l | tr -d ' ')  # 字面路径：独立于 $d
   parsed=$(find "$d" -maxdepth 1 -name '*.md' -exec awk 'FNR==1 {if (/^---[[:space:]]*$/) print FILENAME; nextfile}' {} + | wc -l | tr -d ' ')
   suspect=$(find "$d" -maxdepth 1 -name '*.md' -exec awk 'FNR==1 && /^---[[:space:]]*$/ {fm=1; next}
     fm && /^---[[:space:]]*$/ {fm=0; nextfile}
     fm && /^[a-z_]+: [^"\047[|>].*: / {print FILENAME; nextfile}' {} + | wc -l | tr -d ' ')   # 值中带有未引号的 ": " — 无效的 YAML
   if [ "$n" -gt 0 ] && [ "$parsed" -eq 0 ]; then
     echo "SCAN COMMAND BROKEN — $n files present, 0 headers parsed"; exit 1
   fi
   [ "$suspect" -gt 0 ] && echo "NOTE: $suspect of $n headers carry an unquoted ': ' in a value — quote those values (File format)"
   printf 'files: %s  parsed: %s  suspect: %s\n' "$n" "$parsed" "$suspect"
   printf '%s [%s] session-start scan: files=%s parsed=%s\n' "$(date '+%F %H:%M')" "${PWD##*/}" "$n" "$parsed" \
     >> "[ABSOLUTE PATH]/skill-observations/checkpoints.log"   # 日期+时间+来源：每会话一行，不是每天一行
   find "$d" -maxdepth 1 -name '*.md' | LC_ALL=C sort | while IFS= read -r f; do  # 最后：内容打印，唯一一个分类器可能拒绝的部分
     awk 'NR==1 && /^---[[:space:]]*$/ {fm=1; next}
          fm && /^---[[:space:]]*$/ {exit}
          fm' "$f"
     printf -- '---\n'
   done
   ```

**先统计和追踪，最后打印内容，因为只有内容可以被拒绝。** 被拒绝的打印不是空日志，也永远不会被报告为空日志——上面的统计和 `checkpoints.log` 追踪是备用方案，仍然满足 BROKEN 防护。加载 `references/observation-log.md`（“被拒绝的打印不是空日志”）之前，不要删除、移动或替换任何部分。
3. **审查触发器。** 读取 `skill-observations/last-review-date.txt`。值包含真相：日期 = 最后一次审查实际运行的时间；`never` = 尚未运行过审查。缺失的文件是异常的（步骤 1 创建它）——用 `never` 重新创建它，不要编造日期。如果值是 `never` 或 7 天以上旧，并且存在 OPEN 观察项：在交互式会话中，用一行提供审查，然后根据用户的任务继续，除非他们选择加入；永远不要在审查上限制他们的工作。根据积压工作调整提议的内容，而不是频率：最多 ~15 个开放的观察项，提供完整审查（“积压工作尚未审查 [在 N 天内 / 尚未] — N 个开放；现在运行它，还是继续？”）；超过这个数量，提供有界切片，其工作单元在积压工作增长时保持不变——“审查最旧的 10 个”，“仅审查针对 <最常提到的技能> 的项”——并说明两个数字，开放的项数和大致有多少个不同的发现（在您刚刚扫描的 `title` 和 `skill` 字段上聚类）。从未排空的积压工作会安静地失败，因为排空它变得太昂贵：正确的会话行为（永远不要阻塞用户）总和起来就是没有人接受的审查。只有计划运行/自主运行会加载 `references/weekly-review.md` 并不提示地运行审查。
4. **激活。** 每次会话一次：如果不存在此技能的 CLAUDE.md（或等效）激活指令，则简要建议添加一个（见 `references/environments.md`）。如果已配置，则跳过。明确说明这一步的作用：它仅在技能被调用后运行，因此它验证了工作配置，在结构上无法检测到缺失的配置——它不是从未激活的安装的安全网。这种情况只能从运行时外部捕获：安装时验证和外部诊断在 `references/environments.md`（在真实工作会话后没有观察日志目录），以及审查对已消失的层级的回归检查。
5. **并发。** 没有共享日志文件来防护：每个观察项都是其自己的文件，因此创建一个永远不会与另一个会话的条目冲突。在更改现有观察项的 *状态* 之前，首先重新读取该文件——可能有一个并行审查已经解决了它。
6. **目标和暂存工作。** 解析扫描的前置文件中每个不同的 `skill:` 值，与已安装的技能集进行匹配，并在一行中提及任何无法解析的值——以及任何解析但无法运行的值，因为列表中的存在不代表能力（`references/skill-authoring.md`，“运行时先决条件”）。被删除的技能会不知不觉地积累观察项；被淘汰的技能更是如此。说明您与什么进行了解析（这个检出，这个安装）：未解析的目标是关于您查找的地方的事实，而不是关于世界。
   如果 `skill-updates/PENDING.md` 列出暂存更新，则在宣布之前进行协调——安装发生在任何会话之外，因此没有会话观察到它，读取账本的所有会话拥有其清理权。对每个暂存副本使用 `diff -rq` 与活动版本进行比较并分类；一个简单的“不同”不是结论，因为活动版本是合法移动的。分类及其案例在 `references/weekly-review.md`（“暂存工作协调门”）中——在判断任何条目之前加载它。然后在一行中说“N 个暂存更新等待审查”。
7. **首次运行，或一个命名的过去会话。** 如果日志为空并且项目有历史（交接或决策文档、提交历史、测试脚本、笔记或内存目录、现有的 CLAUDE.md），则提供一次性填充遍历这些工件；当用户命名一个完成的会话时，运行针对该会话的相同遍历。条目引用持久化工件（文件和部分）在 `session_context` 中，而不是会话。程序：`references/environments.md`（“首次运行填充”）。

## 何时观察

整个任务会话期间激活——执行、任务后反馈、审查讨论、关于技能或方法的元讨论，以及关于如何完成工作的策略对话。**观察心态在对话从执行工作转变为讨论工作时不会停用**；审查阶段的反馈通常是最高信号输入。仅在非正式对话和没有工具或交付物涉及的快速事实性问题时非激活。

## 要观察什么

**新技能：** 可重用的多步骤工作流、用户解释的没有技能捕获的方法论、重复的任务类型、用户描述为“我总是这样做”的过程。**改进技能：** 代理违反了记录的规则（技能需要执行，而不是更响亮的规则）；用户更正揭示了缺失的规则或边缘情况；比技能推荐更好的工作流程或技术出现；错误的假设；新工具使步骤过时；适用于其他技能的原则。**简化技能：** 在许多会话中从未相关的部分、来自单个未验证观察的规则、相互矛盾的规则、代理始终无法遵循的规则——转换为结构执行或删除。完整目录和示例：`references/signals.md`。

**未解决的缺陷是一个有界点的观察。** 当一个不是交付物的缺陷采取第二个假设时，加载 `references/signals.md`（“未解决的缺陷是一个有界点的观察”）并记录证实的有问题报告，而不是第五次探测。

**不要记录：** 不会推广的单一更正；已经捕获在技能中的偏好；与方法无关的工具错误；需要在专有客户端信息中才能在开源技能中有用的观察（除非内部技能是正确的家）。不确定时，运行 `references/signals.md`（“可推广性测试”）：大多不 → 任务上下文，不是观察。在创建 `proposes_skill` 名称之前，重用合适的现有候选者——独立记录的针对一个技能的提议很少共享名称。

**在写入之前检查重述。** 在创建文件之前，列出命名相同目标技能的开放观察项（会话开始时的扫描已经持有它们的标题；否则 `find observation-log -name '*.md' -exec grep -l "skill:.*<skill>" {} +`）并阅读这些标题。如果发现是相同的一个重述——相同的规则、相同的失败形状、不同的示例——则扩展现有条目：将新实例追加到其正文，将会话添加到 `session_context`，编辑该文件。重复只有在汇总中才可见（在一个日志上测量：大约四十个九十一个开放条目被重述），一个近重复每次会话捕获成本和每次审查分类成本。

**写入时验证目标。** `skill:` 指定现在存在的技能。如果正确的家不是一个技能——指令文件、记忆笔记、常规读取的注册表——将那个路径放入 `target_file：` 而不是将条目映射到最近的技能；如果技能不存在，使用 `proposes_skill：`。

**写入时检查目标的兄弟姐妹，并记录您已这样做。** 在写入之前，将目标与家庭注册表（`skill-observations/skill-families.md`）进行解析，并对每个兄弟姐妹，要么将其添加到 `skill：`，要么在正文中说明为什么不适用。快速测试：**这句话可以在删除工具或主题的名称后存活吗？** 如果是，它属于每个兄弟姐妹。在强制 `siblings_checked：` 字段中记录结果，包括“检查——实例特定，不传播”：一个条目的 `skill：` 列表无论是否评估了兄弟姐妹，字节都相同，只有记录的字段使 *缺失* 的判断可见。加载 `references/observation-log.md`（“技能家庭和兄弟姐妹检查”）以获取注册表规范、一致性模型和在没有注册表时的备用方案。

**记录您自己的规则违反。** 违反技能或项目指令文件记录的规则是一流的观察，而不是要移过的尴尬：它是规则 *执行* 太弱的唯一证据，只有代理可以看到它。在同一轮中记录它，并命名实际起作用的保护——写下来、加载到上下文中，或由检查点支持。上面的重述检查会显示较早的条目，因此计数无需额外工作即可到达。

**同一规则的第二次违反：停止提议文本。** 一个在没有任何 `actioned` 修复的两次失败中失败的规则存在保护问题，而不是措辞问题。从第二次出现开始，提议的改进必须是结构障碍——拒绝调用的钩子、lint 规则、使错误路径不可用的默认值——永远不会是更清晰的句子、更响亮的警告或同一规则移动到更突出的位置。在提议任何内容之前，加载 `references/signals.md`（“第二次违反——为什么是障碍，而不是重写”）。

## 如何记录

**在相同回合内或下一个回合内安静地写入观察文件**——永远不要在稍后批量心理；写入行为是执行机制。

**每完成第 3 个待办事项后的强制检查点。** 标记第 3 个、第 6 个、第 9 个（等等）项目完成时，你必须 **写入磁盘**——而不仅仅是问自己是否有待处理项。写入任何待处理的观察文件，或将一行 `no observations` 确认追加到 `skill-observations/checkpoints.log`。所需操作是具体的写入；记住“问是否”不是执行。大约每三个完成是规则；计数不必精确。（对于计价写入工作区：`references/environments.md`。）

**被拒绝或失败的写入不是只读日志。** 在得出工作区不可写之前重试一次，并尝试使用达到相同路径的第二种工具——分类器可以拒绝一种接口而允许另一种，并且来自概率门禁者的连续拒绝是噪音，而不是墙。报告“失败 N 次”，而不是“不能完成”，除非重试和替代接口都已用尽；否则观察在会话剩余时间内会无声丢失。

**交付事件刷新。** 每当单位工作被人类宣布完成时——移交文件、渲染、暂存技能文件、完成通知、最终报告、完成的待办事项批处理——立即写入任何待处理的观察文件。这些检查点已经涉及工具调用，因此刷新依赖于您无论如何都在进行的工作。（为什么两个检查点都是写入而不是问题：`references/observation-log.md`。）

**向外部系统写入失败是刷新触发器的另一种情况**——带有 `permission stream closed`、`permission denied` 或 harness 中断的工具结果。不是完成，但它具有刷新需要的两个属性：它是工具记录中的字面字符串，而不是关于时刻是否合格的判断，并且它落在刚刚发现值得报告的东西并最有可能停止的地方。在决定如何处理失败之前刷新。 （观察到：一个未关注的运行完成了每一步，在第一次外部写入时遇到了权限错误，并以没有报告和没有记录的观察结束。）

**这对组合仍然留下的两个空白：** 第 3 个完成检查点在使用没有待办事项的会话中是惰性的，“这是一个主要交付吗？”是一个自我评估——因此交付刷新是唯一剩下的执行，并且必须故意应用。在添加或更改任何执行触发器之前，加载 `references/observation-log.md`（“这对组合仍然留下的空白——以及背后的规则”）。

**ID 和文件名。** 每个观察都是 `NNNN-short-slug.md`（零填充 ID + 从标题中获取的 kebab-case slug）。ID 是三个值中最高的值加一：`observation-log/` 中最高的数字前缀、`observation-log/archive/` 中最高的、`observation-log/archive/.id-floor` 中的数字（最高 ID——每次您发出 ID 以上时更新它，以便计数在活动目录为空时永远不会从 1 重新开始）。相同的命令首先将过时的解析文件扫入 `archive/`——存档是导出 ID 的副作用，而不是单独的任务（见写入时的存档）：

```bash
d="[ABSOLUTE PATH]/skill-observations/observation-log"   # 固定的工作区路径，永远不会相对于 cwd；它可能包含空格，因此保持引号；bash，不是 sh
today=$(date +%F)          # 存档在此命令内部进行（见下文）：
n_files=$(find "$d" -maxdepth 1 -name '*.md' | wc -l | tr -d ' ')
seen=$(find "$d" -maxdepth 1 -name '*.md' -print0 | { n=0   # -print0/-d '': 永远不要分割包含空格的路径——`read -d` 是 bash 扩展，因此此循环需要 bash
  while IFS= read -r -d '' f; do   # 过时的解析文件在读取 ID 之前移动
    n=$(( n + 1 ))
    hdr=$(awk 'NR==1 && /^---[[:space:]]*$/ {fm=1; next}
               fm && /^---[[:space:]]*$/ {exit} fm' "$f")
    case $hdr in   # 括号内的模式：在 bash 3.2 的 $( ) 内需要
      (*"status: actioned"*|*"status: declined"*|*"status: superseded"*) ;;
      (*) continue ;;
    esac
    r=$(printf '%s\n' "$hdr" | sed -n 's/^resolved:[[:space:]]*//p' | head -1)
    case $r in ([0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]) ;; (*) continue ;; esac
    [ "$r" != "$today" ] && \
      [ "$(printf '%s\n%s\n' "$r" "$today" | sort | head -1)" = "$r" ] && \
      mv "$f" "$d/archive/"
  done; printf %s "$n"; })
[ "$n_files" -gt 0 ] && [ "${seen:-0}" -eq 0 ] && { echo "ARCHIVAL SWEEP BROKEN — $n_files files present, 0 examined"; exit 1; }
hi=$( { ls "$d" "$d/archive" 2>/dev/null | grep -oE '^[0-9]+'; cat "$d/archive/.id-floor" 2>/dev/null; } \
     | sed 's/^0*\([0-9]\)/\1/' | sort -n | tail -1); : "${hi:=0}"
[ "$hi" -eq 0 ] && [ -n "$(find "$d" -maxdepth 1 -name '*.md')" ] && { echo "ID COMMAND BROKEN — log is non-empty but no ids extracted"; exit 1; }
next_id=$(( hi + 1 )); echo "$next_id" > "$d/archive/.id-floor"
f="$d/$(printf '%04d' "$next_id")-<slug>.md"      # 目标路径，从刚刚导出的 ID 构建
[ -n "$(find "$d" -maxdepth 2 -name "$(printf '%04d' "$next_id")-*.md")" ] && { echo "COLLISION — id $next_id already used; re-derive"; exit 1; }   # 跨越活动 + 存档保护 ID 前缀，而不是路径
(set -C; : > "$f") || exit 1                        # noclobber：创建，永不截断现有文件
```

`sed` 在算术之前剥离前缀的零填充——不要“简化”它：shell 算术将前导零读作八进制，因此 `$(( 0105 + 1 ))` 产生 70，并且前缀包含 8 或 9 会出错。

**守卫行区分“日志说零”与“我无法读取日志”，存档循环的计数也这样做，前缀守卫拒绝在任何 slug 下已使用的数字，而 `noclobber` 创建拒绝现有路径——在成功创建后，用编辑工具或一个引号 heredoc 写正文，永远不要用未引号的 heredoc：`references/observation-log.md`（“编辑现有观察”）。
加载 `references/observation-log.md`（“守卫行、存档的计数和 noclobber 创建”）当任何它们触发时。

**立即在每次写入操作之前运行代码片段**——包括会话中仅有的一个写入操作——早期的日志读取不能替代此操作，会话开始扫描打印的ID永远不会是写入操作的输入。当助手可以运行时，`scripts/new-observation.sh <slug>` 是唯一的写入路径：它执行整个代码片段并打印创建的路径，因此派生过程不会偏离创建过程（这是违反第二规则所需的结构性屏障）。当跳过操作合理时，或者当两个文件共享一个ID时，加载 `references/observation-log.md` ("立即在每次写入操作之前运行代码片段")。

**在每个写入操作时解析每个ID**——在每次文件写入之前运行代码片段，永远不要预先计算一个范围，并将它打印的值放入文件名和 `id:` 字段中。在批处理或并行化之前加载 `references/observation-log.md` ("在每个写入操作时解析每个ID")。

**每个仪器都得到相同的保护：空结果或零结果是关于仪器的声明，直到独立的探测显示群体为空。** 在写入任何新的扫描、计数、grep 或查询之前加载 `references/observation-log.md` ("每个仪器都得到相同的保护")。

**一个结构探测在之前存在内容的地方返回空结果是一个停止信号，而不是创建操作**——停止并重新探测；永远不要让追加操作重新创建缺失的目标。在写入此类探测之后加载 `references/observation-log.md` ("一个结构探测在返回空结果是停止信号")。

**文件格式。** YAML 前置部分（每个扫描读取的元数据）后跟 Issue → 改进 → 原则主体。**前置部分是强制性的；在创建时始终写入 `status: open` 和非空的 `siblings_checked:`**——没有 `status` 字段的观察被视为 OPEN，在审查中，永远不会被视为不存在，而没有 `siblings_checked:` 的观察被视为没有执行兄弟检查的记录。

```markdown
---
id: 0
title: "简短的描述性标题"
status: open            # open | actioned | declined | superseded | parked
type: open-source       # open-source | internal
skill: [skill-a, "plugin:skill-b"]  # 现有技能的改进——
                                 # 始终是一个列表，第一个条目是主要的，可以是
                                 # 空的： []; 引用包含冒号的条目
proposes_skill: []               # 新技能的名称，通过工作名称提出
                                 # 观察可以填充任一列表或两个列表
target_file: []                  # 当正确的家不是一个技能时：
                                 # 修复将写入的路径
siblings_checked: "family-name: a, b — a 添加；b 排除 (b/SKILL.md §2)"
                                 # 强制性的，不能为空：家族名称，
                                 # 每个成员的裁决——每个排除项
                                 # 指的是在其中读取的部分，或假设的
                                 # 字面量；没有仅在目标属于
                                 # 没有家族的情况下
area: "技能或工作流的哪个部分"
date: YYYY-MM-DD
session_context: "正在处理什么任务"
parked_until:           # 状态为 parked 时强制性的，否则为空：
                        #   一行命名解锁它的条件
resolved:               # 解决日期；OPEN 时为空
resolution:             # 做了什么——仅在 actioned/declined 时设置
reference:              # 可选的——保存会话本地证据的路径
---

**问题：** [发生了什么——足够具体，以便在没有原始对话的情况下几周后理解。]

**建议的改进：** [具体的改变。对于现有技能，命名部分或规则；对于新技能，范围和关键组件。]

**原则：** [可推广的要点——最重要的字段。]
```

**每个文本值都是双引号，包含冒号的列表项也是双引号。** `title`、`siblings_checked`、`area`、`session_context`、`resolution`、`parked_until` 和 `reference` 包含自由文本，自由文本包含 `: ` 作为常见情况；未加引号，这是无效的 YAML——扫描时没有任何反应，每个解析标题的消费者都会抛出错误。插件作用域的名称在 `[]` 列表中（`[plugin:name]`）在一种 YAML 解析器中加载，在另一种解析器中失败：引用它（`"…"`，内部 `"` 作为 `\"`）；裸 kebab-case 名称、日期和状态词保持不变。加载 `references/observation-log.md` ("前置部分字段") 以了解漂移。

**`parked` 意味着已决定，而不是待定：** 听起来合理但被外部先决条件阻止，不在工作队列中，永远不会存档，`parked_until:` 强制性并命名一个实际可能发生的条件。加载 `references/observation-log.md` ("`parked` 状态——已决定，而不是待定") 在设置、审查或解锁 parked 状态之前。

**上下文保留：** 如果观察依赖于会话本地数据，请首先将其保存到工作区中，并将 `reference:` 设置为新的会话可以解析的持久路径。加载 `references/observation-log.md` ("上下文保留——`reference:` 字段") 以设置 `reference:`。

**记录时的保密性：** 对于 `type: open-source` 观察记录，Issue/Improvement 字段可以引用上下文的具体信息，但原则必须完全泛化——没有客户名称、域名或可追溯到实际项目的详细信息。完整的保密层：
`references/skill-authoring.md`。

**更改现有观察记录：** 重新读取该文件，仅编辑您正在更改的前置部分字段（`status`、`parked_until`、`resolved`、`resolution`），永远不要批量重写目录。存档是一个简单的 `mv`。

## 引用观察记录

通过其前置部分中的 `id` 字段引用观察记录（即 `NNNN-` 文件名前缀），而不是 `grep -n` 行号——这些是位置元数据，不是标识符。引用的 ID 必须在 `observation-log/`、`archive/` 和 `.id-floor` 范围内；一个远超出范围的 ID 几乎肯定是误读行号为 ID。

## 分类（快速版本）

**开源**——客户无关的，方法驱动的，对其他从业者有用。**内部**——包含用户/客户/项目特定信息或个人偏好。当可以两者兼用时，默认为开源，删除特定信息。边界也是一个保密边界，两个错误不是对称的——过度分类为内部的成本只会达到，分类不足可能会泄露——因此当确实不确定时，请选择内部并稍后推广。完整要求（归属、许可、结构）：
`references/skill-authoring.md`。

## 写入时的存档

存档不是在写入之前记住的先导任务——它包含在上述 ID 派生代码片段中：计算下一个 ID 的相同命令首先将已解决的文件从 `observation-log/` 移动到 `observation-log/archive/`，因此扫描在每次发布 ID 时运行，并且不能在不失败写入的情况下跳过。 （文本形式——“在每次写入时，首先存档”——不足以：作为另一个操作的先导附加的义务不会继承该操作的任何执行。如果一个步骤必须始终伴随着工具调用，请将其放在同一个命令中。）计划审查也会存档，在步骤 1 作为独立的后备。 “已解决”是从文件自己的前置部分读取的：`status: actioned`、`declined` 或 `superseded` AND `resolved:` 日期 **在今天之前**。今天解决的文件会保留到第二天，无论哪个会话解决了它们——宽限期存在于文件中，而不是会话内存中。一个没有可读 `resolved:` 日期的已解决文件会将其写入该字段而不是存档（代码片段会跳过它；单独进行单字段编辑）。每个 `mv` 一个文件，不重写任何其他内容，并且扫描之外的批量移动通过守恒验证：
`references/observation-log.md` ("存档")。

## 揭示协议

默认：会话结束时，作为分组摘要——改进按技能分组，新技能候选者单独列出；对于每个，一句话加上建议的类型；询问要采取哪个操作。当观察记录需要用户输入才能完成时、当技能正在产生错误输出时或当观察记录集中在某个技能上时，提前揭示。

**推迟操作戴上了第二种伪装：不是承诺，而是一个论点**（“我们先收集更多数据再说”）。在将“稍后”写入建议之前，加载 `references/signals.md` ("推迟伪装成勤奋") 并命名哪个具体的观察记录会改变决定以及它何时到达。

**默认为记录并推迟。** 揭示观察记录不是采取行动的邀请：声明它已记录供下次审查，然后停止。在会话内应用严格保留在“采取行动观察记录”下的触发器下。不要常规提供“立即应用与留待下次审查”的二进制选择；对于运行定期审查的用户来说，这是不必要的摩擦，如果一个用户说过他们总是推迟，则完全抑制它。

**记录并推迟意味着观察记录是变更的唯一载体**，将见解应用于您面前的工作不是同一个行为。让开放的观察记录改变您在此任务中的行为是日志的目的。将规则写入任何稍后运行会读取它的地方——技能加载的状态文件（注册表、档案、配置笔记）、提示、交接文档、项目指令文件——都是采取行动。测试：**它是否在观察记录之外留下持久的变更？** 伪装是一个桥梁——“规则必须存在于审查运行之前”。它确实存在，并且那个地方是观察记录；一个 parked 的副本没有更新路径，因此当审查下次编辑技能时，它会读取两个。一个确实需要指向规则的状态文件会有一行命名所有者，并指出待处理的更改，永远不会重述。一个 harness 的技能保存控制是更尖锐的版本：它安装一个副本而不是 parked 一个，可能会覆盖并行审查已经准备好的内容。参见“采取行动观察记录”。

**在揭示之前进行自我检查：** 观察记录在整个会话期间记录（包括讨论阶段）；安静地记录；每个都遵循问题 → 改进 → 原则；每个都有类型；现有技能项命名了部分；没有开源原则包含客户识别信息；每个观察记录文件都带有 `status:`（写入时 `status: open`）和非空的 `siblings_checked:`——如果任何一个缺少，请立即执行兄弟检查并记录它，而不是用 `none` 填充该字段。

## 采取行动观察记录

仅在三种情况下采取行动：（1）综合审查（加载 `references/weekly-review.md`）；（2）明确的用户请求（“更新 X 技能”，“采取行动观察记录 #N”）；（3）会话内纠正，当技能产生用户应该知道的错误输出时。否则：记录，不要采取行动。

**结果级别的请求不是触发器 (2)。** 测试：明确的请求命名了工件——“更新 X 技能”，“编辑技能文件”，“重新部署它”，“采取行动观察记录 #N”。仅命名行为的声明——“从现在开始”，“停止做 X”，“总是做 Y”，“将这部分作为工作流程的一部分”，“从过程中排除那部分”——其载体是观察记录，无论听起来多么紧急：范围使推迟感觉不安全，与上面桥接论点戴的伪装相同。含义模糊的措辞会得到一条简短的问题，而不是猜测，因为错误的猜测是未经请求的工件供审查；记录 → 审查 → 部署 → 安装总是获胜。

**harness 自己的技能提议或技能保存控制是安装路径，而不是部署路径。** 当环境在对话中提供保存或提议技能时——并且其工具描述可能确实说技能更改是这样交付的——该控制写入安装的副本；它在 `skill-updates/` 下不会产生任何内容。永远不要在部署那里使用它。并且在进行任何会话内技能更改之前，检查部署清单（`skill-updates/PENDING.md`）和今天的 `skill-updates/<date>/` 对于相同的技能：一个并行运行的审查可能已经部署了它，基于活动文件和其他更改。安装对话侧副本会丢失这些更改，并且在安装审查的副本之后会静默撤销该控制安装的副本——这是一个在另一个会话部署相同工件时被用户必须捕获的合并冲突的捷径。安装一个对话侧副本会丢失这些更改，并且在安装审查的副本之后会静默撤销该控制安装的副本——这是一个在另一个会话部署相同工件时被用户必须捕获的合并冲突的捷径。

**在解决、驳回、修复或引用之前，阅读完整正文**——标题是索引条目，不是内容。**您没有做的改变逐点解决观察记录点，而不是标题对标题：** 列出正文提出的点，命名覆盖每个点的修复行，并且没有行的点保持在载体上为开放。在解决、驳回或引用之前加载 `references/observation-log.md` ("在解决、驳回、修复或引用之前，阅读完整正文")。

采取行动时：小的、清晰可加的、低风险的更改（新规则、澄清、事实修复）可以立即应用，无需等待下次审查——“直接”意味着 *现在*，而不是 *就地*：编辑仍然是在基于对活动文件的新读取的部署副本上进行的，并交给用户安装，在所有环境和所有上下文中。仅部署没有交互式例外；用户必须记住的例外是一个最终会被打开的门。重大更改（重构、新功能、改变方法）和所有新技能创建：首先加载 `references/skill-authoring.md` 并遵循其编辑和部署规则。适用于所有技能的原则将转到跨切原则文件（相同的参考）。

**在采取行动时设置状态。** 在会话内采取行动的观察记录必须在回合结束时更新其前置部分——`status: actioned`、`resolved: YYYY-MM-DD`、`resolution: 做了什么`——否则回合结束。工作和账本有两个行为，第二个行为会被丢弃；一个陈旧的 `open` 条目会邀请重新做已完成的工作，而该部分已经向前移动。写入是执行，与记录完全相同。**“已采取行动”包括作为普通工作落地的修复**——写入指令文件中的规则、代码更正——没有考虑到观察记录；并且稍后找到补救措施已经到位会以相同的方式关闭条目。两者都不像采取行动观察记录，这就是为什么两者都被遗漏（在第一次审查上测量：27 个条目中有 10 个已经在 `open` 状态时被应用）。

**仅对多技能观察记录的 `skill:` 列表的一部分采取行动？** 两个简单的移动都不诚实——保留 `open`，完成的部分会被另一个会话重新应用；标记 `actioned`，未完成的各部分会静默地离开每个未来的队列。使用载体模式：将观察记录标记为 `actioned` 并用 `resolution:` 命名已应用的各部分，然后记录一个载体，保留未完成的技能在其 `skill:` 列表中。完整协议：
`references/observation-log.md`。

## 快速参考

| 问题 | 答案 |
|-------|-------|
| 何时观察？ | 整个会话期间，包括反馈和反思阶段 |
| 如何记录？ | 安静地、立即地，每个观察作为一个名为 `NNNN-slug.md` 的文件；id = max(活跃, 归档, `.id-floor`) + 1，通过在每个写入前立即运行的代码片段推导得出——任何其他目的的日志读取不能替代；如果助手可以运行，`scripts/new-observation.sh <slug>` 是唯一的写入路径 |
| 何时呈现？ | 会话结束时，或需要时提前 |
| 状态字段？ | 每个新观察必须包含强制性的 `status: open` 前置内容；评审将缺失状态视为 OPEN，永远不会视为不存在。五个值：`open`, `actioned`, `declined`, `superseded`, `parked` — `parked` = 已决定但受外部前置条件阻塞，因此它会离开队列，需要 `parked_until:`, 且永远不会归档 |
| 目标技能有兄弟吗？ | 在写入前，先针对 `skill-observations/skill-families.md` 进行解析；将所有适用洞察的兄弟添加到 `skill:`，并在强制性的 `siblings_checked:` 字段中记录结论——包括“已检查，无传播” |
| 扫描或查询返回为空？ | 两种可能性，只有一种是发现：用独立的存续性检查来保护每个旨在防止重复工作的检索，并将已知内容上的空输出视为损坏的命令 |
| 引用观察编号？ | 从 `id:` 前置内容字段（= `NNNN-` 文件名前缀）；绝不是 `grep -n` 的行号；与已知 id 范围进行合理性检查 |
| 开源或内部？ | 默认开源；边界是机密 |
| 小修或重大？ | 增量 → 直接应用；重构/新技能 → `references/skill-authoring.md` |
| 同一规则违反两次？ | 修复是一个结构性障碍（钩子、检查、默认）——永远不会是第三次重写 |
| 修改观察（状态/归档）？ | 重新读取该文件，仅编辑其前置内容，或将其 `mv` 到 `observation-log/archive/` — 没有共享文件重写 |
| 从单文件 `log.md` 升级？ | 脚本化，一次 — `references/migration.md` |
| 每周评审？ | 在会话开始时触发检查；程序在 `references/weekly-review.md` 中 |
| 没有文件系统？ | 交接文档模式 — `references/environments.md` |
