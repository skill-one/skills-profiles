# CRAP 分数分析

计算 .NET 方法的 CRAP（变更风险反模式）分数，以识别既复杂又测试不足的代码。

## 背景

CRAP 分数将 **圈复杂度** 和 **代码覆盖率** 结合为一个指标：

$$\text{CRAP}(m) = \text{comp}(m)^2 \times (1 - \text{cov}(m))^3 + \text{comp}(m)$$

其中：

- $\text{comp}(m)$ = 方法 $m$ 的圈复杂度
- $\text{cov}(m)$ = 方法 $m$ 的代码覆盖率比率（0.0 到 1.0）

| CRAP 分数 | 风险等级 | 解释 |
|------------|------------|----------------|
| < 5        | 低        | 简单且测试充分 |
| 5 到 < 15  | 中等   | 大多数代码可接受 |
| 15 到 30   | 高       | 需要更多测试或简化 |
| > 30       | 危险   | 紧急重构并增加覆盖率 |

100% 覆盖率的方法 CRAP = 复杂度（最小值）。0% 覆盖率的方法 CRAP = 复杂度^2 + 复杂度。

## 使用场景

- 用户希望评估哪些方法由于低覆盖率和高复杂度而存在风险
- 用户要求特定方法、类或文件的 CRAP 分数
- 用户希望根据覆盖率和复杂度的风险，在命名方法、类或文件中确定下一步要测试的内容
- 用户希望评估超出简单覆盖率百分比的测试质量

## 不适用场景

- 用户只想运行测试（使用 `run-tests` 技能）
- 用户想编写新测试（使用 `code-testing-agent`）
- 用户只想获得覆盖率百分比而不进行复杂度分析
- 用户想进行项目范围的覆盖率/CRAP 分析或优先级（使用 `coverage-analysis`）

## 输入

| 输入 | 必填 | 描述 |
|-------|----------|-------------|
| 目标范围 | 是 | 要分析的方法名、类名或文件路径 |
| 测试项目路径 | 否 | 测试项目的路径。默认为在解决方案中查找测试项目。 |
| 源项目路径 | 否 | 分析的源项目的路径 |

## 工作流程

### 第 1 步：收集代码覆盖率数据

如果用户提供了一个包含请求目标的有效的 Cobertura 报告，则直接使用它，不要重新运行测试。如果提供的报告格式错误、为空、内部矛盾或缺少目标，将其视为无效输入：在可能的情况下，使用与存储库兼容的命令重新生成它，或者在不具备收集条件时请求有效报告。否则，调用 `run-tests` 来分类存储库的测试平台并确认兼容的命令格式，然后要求一个输出 Cobertura 的命令：

| 覆盖率提供者 | Cobertura 命令 |
|---|---|
| `coverlet.collector` with VSTest | `dotnet test <test.csproj> --collect:"XPlat Code Coverage" --results-directory <results-dir>` |
| `Microsoft.Testing.Extensions.CodeCoverage` with .NET 9 bridged MTP | `dotnet test <test.csproj> -- --coverage --coverage-output-format cobertura --coverage-output <output-path>` |
| `Microsoft.Testing.Extensions.CodeCoverage` with .NET 10+ native MTP | `dotnet test --project <test.csproj> --coverage --coverage-output-format cobertura --coverage-output <output-path>` |

当项目定义了等效的存储库拥有的命令时，使用该命令。当收集器创建 GUID 子文件夹时，递归搜索结果目录。在没有转换器的情况下，不要替换通用的 `.coverage` 命令。

不要在第一次还原、编译、测试或收集器失败时停止。分类失败的层，检查命令发出的每个报告，并在请求输入之前耗尽非持久重试。安全的重试包括保留源和清单不变的命令行 MSBuild 属性，以及已安装或存储库提供的替代收集器。当可逆的命令行设置可以编译相同的源时，简单的源错误是收集障碍，而不是最终分析。永远不要将空的 Cobertura 文件称为成功的回退。

对于经典非 SDK 项目（`ToolsVersion`、显式编译项或 `packages.config`），仅使用存储库提供的输出 Cobertura 的覆盖率命令。如果不存在，请求 Cobertura XML 并停止；不要迁移项目或注入 SDK 风格提供者。CRAP 分数始终需要真实的覆盖率数据。

#### 永远不要估计覆盖率

**猜测的覆盖率会产生错误的 CRAP 分数，这比没有答案更糟。**
对于没有存储库覆盖率命令或现有报告的经典项目，停止并请求 Cobertura。

除非用户明确授权依赖项/工具更改，否则不要添加覆盖率包、更改项目清单或安装全局工具。如果存储库缺少可用的提供者或转换器，报告确切的先决条件和通过 `run-tests` 确定的兼容命令格式，然后停止。如果存在现有的二进制 `.coverage` 报告，仅使用已安装或存储库提供的转换器进行转换；否则请求授权或 Cobertura 导出。如果测试执行失败但仍然发出有效覆盖率，请继续使用该数据并注明失败。如果有用，单独报告复杂度，但永远不要发布假定覆盖率派生的 CRAP 数字。

在使用报告之前，验证它是否可以解析，是否至少包含一个类和方法，是否包含请求的目标。空的报告或省略目标的报告是失败的收集或过滤，而不是 0% 覆盖率。在可能的情况下重新生成覆盖率；否则，不发布 CRAP 分数。

如果用户提供了现有报告，请说明它没有被重新生成。除非其来源通过在此分析中运行存储库的覆盖率命令得到证实，否则不要描述其数据为当前。

### 第 2 步：计算圈复杂度

优先使用存储库提供的代码指标报告中的每方法复杂度，或来自映射到当前源的 Cobertura 方法的 `complexity` 属性。Microsoft.CodeAnalysis.Metrics 可以通过 `msbuild /t:Metrics` 生成方法级别的 `CyclomaticComplexity` 数据，但未经用户批准，不要添加该包或修改项目。

如果没有机器生成的指标，请分析当前目标源，并将结果标记为手动复杂度计数。计算以下决策点（每个决策点将基础复杂度 1 增加到 1）：

| 结构 | 示例 |
|-----------|---------|
| `if` | `if (x > 0)` |
| `else if` | `else if (y < 0)` |
| `case`（每个） | `case 1:` |
| `for` | `for (int i = 0; ...)` |
| `foreach` | `foreach (var item in list)` |
| `while` | `while (running)` |
| `do...while` | `do { } while (cond)` |
| `catch`（每个） | `catch (Exception ex)` |
| `&&` | `if (a && b)` |
| `\|\|`（OR） | `if (a \|\| b)` |
| `??` | `value ?? fallback` |
| `?.` | `obj?.Method()` |
| `? :`（三元） | `x > 0 ? a : b` |
| 模式匹配臂 | `x is > 0 and < 10` |

每个方法的基准复杂度为 1。每个决策点增加 1。

在手动计数时，请阅读源文件，报告按结构分解的详细情况，不要使用源注释作为证据。计算每个出现，包括嵌套在参数或返回表达式中的运算符；在声明冲突之前，专门扫描 `&&`、`||`、`??`、`?.`、三元运算符和 switch/pattern 臂。如果提供的报告映射到当前方法，并且仔细重新计数一致，则果断使用其指标。如果存在真正的分歧，请标记两个源；当用户明确要求使用该报告时，使用其机器生成的指标计算主要 CRAP 结果，并将手动计数作为警告而不是隐藏请求的结果。

### 第 3 步：从 Cobertura XML 中提取每方法覆盖率

解析 Cobertura XML，以查找目标 `<class>` 元素下每个方法的 `line-rate` 属性。如果 `line-rate` 在方法级别不可用，则从 `<lines>` 元素计算它：

$$\text{cov}(m) = \frac{\text{有命中行的数量} > 0}{\text{总行数}}$$

Cobertura 中的方法名可能与源不同（异步方法、lambda）。当名称不一致时，通过行范围进行匹配。

当 `line-rate` 和 `<lines>` 都存在时，重新计算命中比率并进行比较。仅允许正常报告舍入（一个百分点）；如果它们差异更大，则报告自相矛盾。重新生成它或报告冲突并停止计算 CRAP。永远不要在沉默中选择产生预期分数的值。

### 第 4 步：计算 CRAP 分数

对于范围内的每个方法，应用公式：

$$\text{CRAP}(m) = \text{comp}(m)^2 \times (1 - \text{cov}(m))^3 + \text{comp}(m)$$

使用计算器或脚本进行算术运算，并显示替换的复杂度和覆盖率。不要在脑海中计算公式。直接回答命名方法；仅当请求的范围是类或文件时，分析不相关的方法。一旦确定请求的结果，除非用户要求，否则不要附加假设的重构分数或覆盖率目标。任何数字示例也必须来自计算器或脚本。

### 第 5 步：展示结果

展示一个排序表（最高 CRAP 优先）：

```text
| 方法                          | 复杂度 | 覆盖率 | CRAP 分数 | 风险     |
|---------------------------------|------------|----------|------------|----------|
| OrderService.ProcessOrder       | 10         | 45%      | 26.6       | 高     |
| OrderService.ValidateItems      | 8          | 90%      | 8.1        | 中等   |
| OrderService.CalculateTotal     | 3          | 100%     | 3.0        | 低     |
```

包括：

- **总结**：分析的总方法数，每个风险类别中的方法数量
- **主要违规者**：CRAP > 30 的方法，以及具体建议
- **快速收益**：复杂度高但覆盖率小幅提升即可显著降低分数的方法

### 第 6 步：提供可操作的建议

对于高 CRAP 分数的方法，建议一个或两个：

1. **添加测试** -- 识别未覆盖的分支并建议具体的测试用例
2. **降低复杂度** -- 建议对深层嵌套逻辑进行提取方法重构

计算将方法的 CRAP 分数降至 15 以下所需的 **覆盖率**：

$$\text{cov}_{\text{needed}} = 1 - \left(\frac{15 - \text{comp}}{\text{comp}^2}\right)^{1/3}$$

此公式仅适用于 comp < 15。当 comp >= 15 时，100% 覆盖率的最小可能 CRAP 分数是 comp 本身，这已经达到或超过阈值。在这种情况下，**仅靠覆盖率无法将 CRAP 分数降至阈值以下** -- 必须首先重构方法以降低其圈复杂度。

报告为： "要将 `ProcessOrder`（复杂度 10）的 CRAP 降至 15 以下，请将覆盖率从 45% 提高到超过 63.2%（报告为整数百分比时至少为 64%）。对于复杂度本身超过阈值的 `ComplexMethod`，报告：`ComplexMethod`（复杂度 18）无法仅通过测试达到 CRAP < 15 -- 通过提取子方法降低复杂度。"

## 验证

- 验证是否成功收集了覆盖率数据（存在 Cobertura XML 并包含数据）
- 确认目标方法存在；不存在不是 0% 覆盖率的证据
- 确认每个覆盖率数字都来自该 XML — 没有估计的、假设的或源注释派生的值
- 当两者都存在时，交叉检查方法的 `line-rate` 与其行命中比率
- 交叉检查覆盖率数据中的方法名是否与源代码匹配
- 使用计算器或脚本确认 CRAP 分数
- 确保 100% 覆盖率的方法的 CRAP 等于其复杂度正好

## 常见陷阱

- **收集失败时估计覆盖率**：永远不要这样做 — 生成的 CRAP 分数在重要方向上是错误的。使用通过 `run-tests` 确认的存储库兼容 Cobertura 路径，然后报告障碍。
- **将空报告或缺失方法视为 0% 覆盖率**：这是失败的收集、过滤或方法映射；不要制造分数。
- **信任矛盾的 Cobertura 字段**：比较 `line-rate` 与行命中比率，如果它们超出舍入范围则停止。
- **信任源中的陈旧复杂度注释**：从当前代码计算圈复杂度；先前作者留下的 `// complexity: 7` 注释不是证据。
- **脑海中的 CRAP 算术**：使用计算器或脚本并显示替换的输入。
- **更改工具以绕过收集器错误**：报告失败的存储库兼容命令和缺失的先决条件；不要安装全局收集器或编辑清单，除非明确授权。
- **陈旧的覆盖率数据**：当用户要求当前结果或源/二进制更改时重新生成；否则披露提供的报告未被重新生成。
- **方法名不匹配**：Cobertura XML 可能使用异步方法、lambda 或局部函数的 mangled/编译器生成名称。当名称不匹配时，通过行范围进行匹配。
- **生成代码**：除非明确请求，否则从自动生成文件（例如 `*.Designer.cs`、`*.g.cs`）中排除分析。
