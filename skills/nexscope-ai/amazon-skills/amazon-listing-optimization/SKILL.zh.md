# 亚马逊商品列表优化 📝

从零开始构建关键词优化的商品列表，或审核并优化现有的列表。无需API密钥——开箱即用。

## 安装

```bash
npx skills add nexscope-ai/Amazon-Skills --skill amazon-listing-optimization -g
```

## 两种模式

| 模式 | 使用场景 | 输入 | 输出 |
|------|-------------|-------|--------|
| **A — 创建** | 构建新的商品列表 | 关键词和/或竞争对手ASIN + 产品信息 + 语气 | 完整的商品列表文案 + 关键词覆盖评分 |
| **B — 优化** | 改进现有的商品列表 | 您的ASIN或URL (+可选关键词或竞争对手ASIN) | 优化后的商品列表文案 + 审核报告 + 差距分析 |

## 模式 A — 三种启动方式

| 输入来源 | 工作原理 |
|-------------|-------------|
| **关键词** | 用户提供关键词列表 → 技能优先排序并生成商品列表 |
| **竞争对手ASIN** | 用户提供1-3个竞争对手ASIN → 技能获取其商品列表，提取其关键词，然后生成一个覆盖所有关键词并更多的商品列表 |
| **两者** | 用户提供关键词 + 竞争对手ASIN → 技能合并两者以实现最大覆盖 |

## 功能

- **关键词驱动商品列表生成**：导入关键词（来自amazon-keyword-research、手动列表或从竞争对手ASIN中提取），按优先级排序，生成最大化关键词覆盖的文案
- **竞争对手关键词提取**：获取竞争对手列表并自动提取其标题/要点关键词作为您的基准
- **8维度审核 & 评分**：标题、要点、描述、图片、A+内容、定价、评论、SEO覆盖
- **关键词覆盖跟踪**：显示哪些关键词出现在标题 / 要点 / 描述 / 缺失的可视化地图
- **语气选择**：专业、友好、紧急、奢华 — 影响AI文案写作风格
- **竞争基准**：与竞争对手进行比较
- **多市场**：US、UK、DE、FR、IT、ES、JP、CA、AU、IN、MX、BR

## 模式 A 工作流程 — 从关键词创建商品列表

### 步骤 A1：收集关键词

关键词可以来自四个来源（使用一个或组合多个）：

1. **从 [amazon-keyword-research](https://github.com/nexscope-ai/Amazon-Skills/tree/main/amazon-keyword-research) 技能**（推荐）：先运行关键词研究，然后直接输入结果。安装：`npx skills add nexscope-ai/Amazon-Skills --skill amazon-keyword-research -g`
2. **从竞争对手ASIN**：用户提供1-3个竞争对手ASIN → 在每个上运行 `<skill>/scripts/fetch-listing.sh` → 从他们的标题、要点和描述中提取关键词 → 作为您的关键词基准。这是最快启动的方式 — 您继承了竞争对手已经有效的工作，然后添加更多。
3. **从用户的关键词列表**：用户粘贴自己的关键词列表（例如来自Helium 10 Cerebro、Jungle Scout或手动研究）
4. **自动发现**：使用 `web_search` 查找产品类别的顶级关键词

当提供竞争对手ASIN时，始终获取并分析它们。从它们的标题和要点中提取每个有意义的关键词，然后与任何用户提供的关键词合并。目标：覆盖所有竞争对手覆盖的内容，并添加他们遗漏的关键词。

### 步骤 A2：优先排序关键词

将关键词组织成层级：

```
🔴 主要（必须在标题中）：
  - [关键词] — [搜索量（如果知道）]
  - [关键词] — [搜索量（如果知道）]

🟡 次要（必须在要点中）：
  - [关键词]
  - [关键词]

🟢 次级（应出现在描述或后台）：
  - [关键词]
  - [关键词]

⚪ 长尾（自然使用）：
  - [关键词短语]
  - [关键词短语]
```

优先级规则：
- 最高搜索量 → 标题（前部加载）
- 中等量 + 高相关性 → 要点（每个要点一个主要关键词）
- 较低量 / 长尾 → 描述
- 剩余的 → 后台搜索词（建议卖家在Seller Central中添加）

### 步骤 A3：收集产品特征

询问或从用户输入中提取：
- **产品名称 / 类型**
- **品牌名称**
- **关键属性**：材质、颜色、尺寸、重量、容量、数量
- **关键功能**：使其与众不同的（3-5个功能）
- **目标受众**：谁购买这个？
- **使用场景**：前3种情况
- **包装内容**：包含的所有内容

### 步骤 A4：选择语气

| 语气 | 风格 | 适合 |
|------|-------|----------|
| **专业** | 权威、侧重规格、建立信任 | 电子产品、工具、B2B |
| **友好** | 闲聊、侧重利益、易亲近 | 厨房、生活方式、礼物 |
| **紧急** | 稀缺性驱动、行动词语、解决问题 | 健康、安全、季节性 |
| **奢华** | 高级、感官语言、独特性 | 美容、时尚、高级商品 |

默认：**专业**（如果未指定）。

### 步骤 A5：生成商品列表文案

遵循以下规则生成每个组件：

**标题（最多200个字符）：**
- 格式：`[品牌] + [主要关键词] + [关键属性1] + [关键属性2] + [次要关键词] + [差异化]`
- 主要关键词尽可能靠近前面（品牌之后）
- 除品牌名称外，不要全部大写
- 不要促销声明（“最佳”、“#1”、“顶级评价”）
- 如相关，包含尺寸/颜色/数量

**要点（5个要点，每个最多500个字符）：**
- 每个要点：`[利益标题大写] — [包含关键词的利益解释]`
- 要点1：主要功能 + 主要关键词
- 要点2：关键使用场景 + 次要关键词
- 要点3：质量/材质 + 信任信号
- 要点4：包含内容 / 兼容性
- 要点5：保证 / 差异化 / 社会证明暗示
- 每个要点应至少包含一个目标关键词

**描述（最多2000个字符）：**
- 开头：产品解决的问题/痛点
- 中间：功能 → 利益（扩展要点，不要逐字重复）
- 结尾：号召性用语 + 包装内容
- 嵌入未在标题/要点中使用的关键词
- 使用换行符提高可读性

### 步骤 A6：关键词覆盖评分

生成后，提供覆盖地图：

```
## 关键词覆盖报告

| 关键词 | 量 | 标题中? | 要点中? | 描述中? | 状态 |
|---------|--------|----------|------------|-----------------|--------|
| portable blender | 45,000 | ✅ | ✅ | ✅ | 🟢 覆盖 |
| smoothie maker | 22,000 | ❌ | ✅ | ✅ | 🟡 添加到标题 |
| USB rechargeable | 18,000 | ✅ | ✅ | ❌ | 🟢 覆盖 |
| travel blender | 12,000 | ❌ | ❌ | ✅ | 🟡 添加到要点 |
| mini blender | 8,000 | ❌ | ❌ | ❌ | 🔴 缺失 |

覆盖：18/22个关键词（82%）
标题关键词：6/8个槽位使用
要点关键词：12/15个目标关键词覆盖
未覆盖 → 建议用于后台搜索词
```

**评分：**
- 🟢 90%+ 覆盖 = 优秀
- 🟡 70-89% = 良好，轻微差距
- 🔴 <70% = 需要工作，重要关键词缺失

## 模式 B 工作流程 — 优化现有商品列表

### 步骤 B1：获取列表数据

运行捆绑脚本：

```bash
<skill>/scripts/fetch-listing.sh "<ASIN>" [市场]
```

**参数：**
- `ASIN`（必需）：例如 B09V3KXJPB
- `市场`（可选）：`us`（默认）、`uk`、`de`、`fr`、`it`、`es`、`jp`、`ca`、`au`、`in`、`mx`、`br`

**提取：** 标题、品牌、价格、要点、描述、图片数量、A+内容存在、评分、评论数量、BSR、类别、首次上市日期。

如果脚本返回不完整数据，则回退到在产品URL上运行 `web_fetch`。

### 步骤 B2：发现目标关键词

如果用户提供关键词，使用这些关键词。否则，自动发现：

1. 从当前标题和要点中提取明显关键词
2. 运行 `web_search` 为 `site:amazon.com "[产品类型]"` 查找竞争对手
3. 从前3个竞争对手的标题和要点中提取关键词
4. （可选）链式使用 `amazon-keyword-research` 技能进行深度分析
5. 编排一个包含估计优先级的目标关键词列表

### 步骤 B3：关键词差距分析

将当前列表与目标关键词进行比较：

```
## 关键词差距分析：[ASIN]

### ✅ 列表中找到的关键词
| 关键词 | 标题中 | 要点中 | 描述中 |
|---------|----------|------------|----------------|
| [kw] | ✅ | ✅ | ❌ |

### ❌ 缺失关键词（竞争对手有，您没有）
| 关键词 | 竞争对手1 | 竞争对手2 | 竞争对手3 | 优先级 |
|---------|-------------|-------------|-------------|----------|
| [kw] | ✅ 标题 | ✅ 要点 | ❌ | 🔴 高 |

### 覆盖：X/Y个关键词（Z%）
```

### 步骤 B4：8维度审核

按显示的量表评分，关键词整合因素在内：

| 维度 | 最高分 | 关键标准 |
|-----------|-----------|-------------|
| **标题** | /15 | 主要关键词靠近前面？品牌？属性？少于200个字符？在手机上未截断？ |
| **要点** | /15 | 使用所有5个要点？利益优先？关键词自然嵌入？每个要点少于500个字符？ |
| **图片** | /15 | 7+图片？白色背景主图？信息图表？生活方式？尺寸参考？视频？ |
| **A+ 内容** | /10 | 存在？品牌故事？比较图表？生活方式图片？ |
| **描述** | /10 | 关键词不在标题/要点中？可读？问题→解决方案流程？ |
| **定价** | /10 | 具有竞争力？促销/优惠存在？ |
| **评论** | /15 | 4.0+星？100+评论？最近的评论积极？ |
| **SEO 覆盖** | /10 | 主要关键词在标题+要点+描述中？长尾存在？没有浪费的重复？**关键词覆盖%** |

### 步骤 B5：生成优化文案

整合缺失关键词重写列表：
- 显示 **之前 vs 之后** 每个组件
- 突出显示添加了哪些关键词以及在哪里
- 除非请求不同语气，否则保持品牌现有的语气

### 关键原则

1. 卖家的流程是：**复制列表 → 粘贴到Seller Central → 完成。** 诊断部分解释了为什么选择这些特定词语，但列表本身必须作为一个完整、可直接使用的交付成果独立存在。永远不会只输出报告而不输出实际列表文案。

2. **输出语言必须与目标市场匹配。** 亚马逊美国/英国/澳大利亚/加拿大/印度 → 英语。亚马逊德国 → 德语。亚马逊法国 → 法语。亚马逊日本 → 日语。亚马逊西班牙/墨西哥 → 西班牙语。亚马逊意大利 → 意大利语。亚马逊巴西 → 葡萄牙语。整个输出（列表文案 AND 诊断部分）必须使用市场语言，无论用户在对话中使用的语言是什么。

## 与amazon-keyword-research的集成

此技能在与 [amazon-keyword-research](https://github.com/nexscope-ai/Amazon-Skills/tree/main/amazon-keyword-research) 链接时效果最佳：

