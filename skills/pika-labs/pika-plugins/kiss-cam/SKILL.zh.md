# kiss-cam

一个两步调用的 pika 管道：观众视角 Jumbotron 静图 (`gpt-image-2`) → 15 秒的赛场内亲吻摄像片段，包含 PA 宣讲员评论和观众反应 (`kling-v3-omni`)，第一帧锁定到静图。趋势外观已校准——直接通过参考图像。提示中无文本替换；主题仅通过 `images` 锚定。不要使用 `${subject_a}` / `${subject_b}` 占位符。步骤 1 和步骤 2 的提示是逐字逐句的，不是脚手架。

## 前置条件

主机中可用 pika MCP。工具名称前缀因挂载点而异——使用主机暴露的任何名称。需要的工具：身份余额、资产上传、图像生成、参考视频生成，以及在生成未内联完成时异步状态跟踪。

## 成本透明度门

在支付 MCP 调用之前，调用一次 `identity_balance({verbose: true})`。显示当前余额、近期消耗率和剩余运行时间，然后用确切的消息门控运行：

> 预计成本：GPT-image-2 Jumbotron 静图约 1,500-3,500 信用点（~$15-$35），一个或两个 Kling v3-omni 专业 15 秒渲染（包含一个更改负载的步骤 2 更正重试），以及飞行后 analyze_media QA。这超过 $5，回复 `proceed` 继续，或 `cancel` 停止。

在用户回复 `proceed` 之前，不要调用任何支付 MCP 工具。如果用户回复 `cancel`，则不生成并停止。这是唯一的 yes/no 门；回复 `proceed` 后，管道端到端运行。

## 生成前时钟保护

在两个主题参考 URL 都解析且成本门通过后，在技能开始时启动计时器。第一个支付生成调用是步骤 1 `generate_image_edit`，必须在技能开始后的 5 分钟内调用。如果在技能开始后的 5 分钟内未调用 `generate_image_edit`，则在任何支付生成调用之前停止，并报告 `failed_pre_generation_timeout` 以及到目前为止的状态：主题 URL 状态、上传状态、成本门状态、步骤 1 提示准备状态和确切障碍。不要继续改进 Jumbotron 提示、摄像机语言或样式锁定措辞。

在每个准备阶段后且在支付生成调用之前打印单行进度检查点：
- `Stage 1/3 done — subject references resolved and uploaded.`
- `Stage 2/3 done — cost gate passed, locking the Jumbotron still prompt.`
- `Stage 3/3 done — still prompt locked, calling GPT-image-2 now.`

提示和静图检查措辞迭代在步骤 1 之前最多 2 轮。在最多 2 轮后，将您拥有的内容发送到 `generate_image_edit`；不要继续打磨记分牌细节、赛场氛围或亲吻摄像图形语言。

## 长任务任务_status 投票

当任何长运行生成调用返回带有或没有初始状态的 `task_id`，包括 `{task_id}`、`{task_id, status: "queued"}` 或初始 `queued`、`running` 或 `processing` 状态时，立即记录任务 ID 和开始时间。

- 在终端 (`completed | failed | cancelled`) 之前，在紧密循环中调用 `task_status({task_id})`。不要手动睡眠和不要 Bash 投票；工作进程保持每个状态调用打开。
- 在状态为 `queued`、`running` 或 `processing` 时，每 60 秒发出一条可见的进度行：`Seedance i2v queued for {N}m {S}s... still processing`。在轮询 GPT-image-2 或 Kling 任务时替换提供者/阶段标签。
- 在 `completed` 时，解包返回的结果 URL 并继续。
- 在 `failed` 或 `cancelled` 时，向用户显示失败，包括 `task_id`、状态和最后状态消息。
- 从原始提交起 15 分钟后，如果任务仍非终端，调用 `task_cancel({task_id})`，然后向用户显示失败。如果取消报告任务已终端，再次调用状态并报告终端结果。
- 在原始任务仍为 `queued`、`running` 或 `processing` 时，不要提交重复请求。

## 步骤 0 — 摄入

如果使用空参数且没有可用的先前上下文，打印此菜单并停止：

> **哪两个主题应该在亲吻摄像中出现？** 必须提供：
>
> - **主题 A 参考照片** — 本地路径或 HTTPS URL
> - **主题 B 参考照片** — 本地路径或 HTTPS URL

如果一张照片已经存在，只询问缺失的照片。在两者都到达之前运行会留下步骤 1 中缺失的 `images` 条目，并产生不一致的静图。

- **主题 A 参考照片** *(必需)* — 本地路径或 https URL。保存为 `state.subject_a_url`。
- **主题 B 参考照片** *(必需)* — 本地路径或 https URL。保存为 `state.subject_b_url`。

对于每个：如果已经是 `https://…` URL，则使用它。如果是本地路径 → `upload_asset` → PUT 字节到 `presigned_url` → 使用 `public_url`。在 Claude Desktop 上，粘贴的内置图像无法到达 MCP——询问一次 URL 或 `.zip` 附件（这是允许的澄清；一旦两个 URL 都在，只有成本门剩余）。

任何主题都可以是任何视觉风格——逼真的人像、3D 渲染角色、设计师玩具、插画头像、雕塑小雕像等。配方保留参考使用的任何风格；不要用不同的风格重绘。**任何地方都不使用名称**——亲吻摄像图形没有带有名称的 chyron。只是两个主题被捕捉在 Jumbotron 上。

运行成本透明度门，然后在一行中确认回话（“为这对两人生成一个麦迪逊广场花园亲吻摄像时刻…”）并开始。**成本门后没有进一步的 yes/no 门**——管道端到端运行。

## 步骤 1 — 观众视角 Jumbotron 静图 (`generate_image_edit`, gpt-image-2)

亲吻摄像图形 + 记分牌 + 复古框架在帧 0 被烘焙到静图中——承重，所以 Kling 在步骤 2 中将整个装饰 UI 视为像素锁定烧入 UI，而不是在片段中动画它。

**为什么 gpt-image-2（且没有备用方案）：** 更清晰的 LED 面板细节（记分牌数字、亲吻摄像文字、复古装饰边缘）和比替代提供者更强的参考相似性锁定；LED 锐度 + 相似性组合是卖点。在 `moderation_blocked` 响应中，重新滚动相同的调用而不是切换提供者——替代方案在早期试验中产生较软的相似性和较软的 LED 细节。我们在 1K 16:9（1792×1024）调用 gpt-image-2；更高分辨率的变体在这里没有帮助，因为 Kling 下游输出 1080p。

重试预算：步骤 1 gpt-image-2 静图生成最多 3 次总尝试，包括审查拦截和自我检查重滚。`moderation_blocked` 计入此步骤 1 帽。在每次支付静图调用之前跟踪 `state.step1_attempt_count`。

**为什么 Jumbotron-POV 手机拍摄（而不是电视广播叠加）：** 第一次迭代产生了一个带有粉色心形亲吻摄像图形的电视广播切出——用户反馈是“亲吻摄像图形丑陋，看看真实视频中真实的亲吻摄像时刻的样子。” 网络上几乎所有的病毒式亲吻摄像片段都是 Jumbotron 的观众手机拍摄（奥巴马时代的美国篮球亲吻摄像、Sarah Hyland / Wells Adams 亲吻摄像等）。Jumbotron 拍摄构图击中了用户实际关联到“真实亲吻摄像”的美学——复古红色边框 + 闪亮的爱心 + 手写 Kiss Cam 脚本 + 相邻 LED 记分牌面板 + 赛场黑暗 + 观众用手机拍摄。

**`prompt`** (逐字逐句，发送原样——无模板替换)：

```
在麦迪逊广场花园的尼克斯对公牛的 NBA 比赛中，从拥挤的观众席向下拍摄的观众视角手机截图，拍摄者为下方的粉丝，拍摄悬挂的巨大 Jumbotron 显示的赛场内“亲吻摄像”片段。真实粉丝拍摄的手机视频美学——TikTok / Instagram 在线亲吻摄像片段风格。

前景（帧底部的 20%）：几排前方粉丝的背影/头部的剪影，略微失焦，黑暗；几部手机举起拍摄 Jumbotron，可见明亮的手机屏幕。

中景/上部 80%：Jumbotron 在上中心主导，明亮的 LED 面板与黑暗的赛场天花板和上方电缆形成对比。轻微的手机相机倾斜，略微偏离自然手持构图。周围昏暗的赛场，隐约可见上层看台剪影。

Jumbotron 的中央 LED 面板以标志性的复古赛场亲吻摄像风格显示亲吻摄像片段：
- 厚重的深猩红色发光装饰边框。
- 明亮的红色闪亮卡通爱心图标在角落和边缘发光。
- 边框中有微妙的白色星形纹理。
- 在底部中心，大而流动的白色手写体 "Kiss Cam" 带有红色发光和阴影。

在 Jumbotron 上的亲吻摄像框架内，两个主题以双人镜头胸部向上构图：
- 左边（主题 A）是第一个参考图像中的角色——保留他们的确切相似性和确切视觉风格（中等、风格化程度、调色板、渲染属性）。不要用不同的风格重绘。主题 A 微笑着用手靠近脸，看起来很惊讶和咯咯笑。
- 右边（主题 B）是第二个参考图像中的角色——保留他们的确切相似性和确切视觉风格。不要用不同的风格重绘。主题 B 坐直，与主题 A 旁边，头部略微转向主题 A。
- 他们在框架内周围：穿着蓝橙球衣的拥挤尼克斯球迷，笑着，指向，微笑着看亲吻摄像。

Jumbotron 上的相邻 LED 面板显示："KNICKS 57 — BULLS 61"，Q4，时钟 "4:32"，带有球队标志。小 "MADISON SQUARE GARDEN" / "MSG" / AT&T 品牌标识。

手机相机美学：轻微运动模糊，轻微手持缺陷，黑暗区域略带噪点，明亮 LED 略微过曝，16:9 纵宽比，真实观众视角。看起来像从粉丝拍摄的 Instagram / TikTok 亲吻摄像片段中提取的静止图像。
```

**调用参数：**

- `provider`: `gpt-image-2`（承重——最清晰的 LED 细节和最强的参考相似性锁定；没有备用提供者，仅在步骤 1 预算内重新滚动相同的调用）
- `images`: `[state.subject_a_url, state.subject_b_url]` *(顺序很重要——主题 A 必须是索引 0，主题 B 索引 1；提示的 "FIRST / SECOND reference image" 指的是数组索引)*
- `aspect_ratio`: `16:9`
- `quality`: `medium` *(默认速度；`high` 现在已暴露，但 ~2 分钟/调用——仅在保真度重要时使用)*
- `output_format`: `png`

**不要传递任何主题的文本特征描述。** 上述提示已经仅将每个主题描述为“来自第一个/第二个参考图像的角色”——这是故意的。描述头发/脸/衣服/配饰的文本与参考图像冲突并导致漂移：口头特征覆盖视觉参考，模型将主题同质化到描述中。

参考图像携带所有身份 + 风格信息；提示仅添加样式锁定。这对任何参考风格——逼真、3D 渲染、雕塑、插画等——都有效，而不需要命名风格。

将返回的 URL 保存为 `state.kisscam_still_url`。

**代理端自我检查在步骤 2 之前**：视觉检查——如果 "Kiss Cam" 文字拼写错误，记分牌看起来不对，或任何主题的相似性漂移，在步骤 1 帽内重新滚动步骤 1。下游所有内容都像素锁定到此图像。这是代理自己的检查——不要询问用户。

**失败时** (`gpt-image-2` 从审查拦截——通常是女性/女性主题配对 + "kiss cam"措辞)：仅在步骤 1 预算内重新滚动相同的调用。不要切换提供者——替代方案产生较软的相似性和较软的 LED 细节。

## 步骤 2 — 赛场内亲吻摄像片段 (`generate_reference_video`, kling-v3-omni)

Kling-omni `image_types: ["first_frame"]` 将静图锁定为字面帧 0，所以 Jumbotron、记分牌、亲吻摄像框架、爱心、手写 "Kiss Cam" 文字和前景粉丝剪影在所有 15 秒内都保持像素锁定。只有框架内内容动画。

**调用参数：**

- `provider`: `kling`
- `kling_model`: `kling-v3-omni`
- `duration`: `15`
- `aspect_ratio`: `16:9`
- `quality_mode`: `pro` (1080p)
- `reference_images`: `[state.kisscam_still_url]` *(使用最新值——步骤 1 重滚覆盖它)*
- `image_types`: `["first_frame"]`
- `sound`: `true`
- `prompt_adherence`: `strict`
- `negative_prompt` (逐字逐句)：

```
场景切割，记分牌改变，Kiss Cam 文字改变，图形变形，角色变成真实，角色变成 2D，身份漂移，稳定云台，夸张表演，戏剧性表情，过度表演，对着镜头鬼脸，卡通反应，主题同步 PA 宣讲员对话，角色说出宣讲员台词，主题的嘴随屏幕外声音移动，主题对着镜头说话，屏幕上口型同步
```

`prompt_adherence: strict` 与完整的 `negative_prompt` 锚定列表一起承重——没有两者，Kling 在片段中动画记分牌或 "Kiss Cam" 文字，主题回归过度表演/口型同步离屏 PA 宣讲员。

**`prompt`** (逐字逐句，约 2400 字——因为 Kling 提示在 2500 字处限制，所以保持预修剪)：

```
第一帧：麦迪逊广场花园的 Jumbotron 亲吻摄像片段的观众视角手机拍摄。粉丝拍摄的 TikTok / Instagram 亲吻摄像片段风格。手持手机，不是专业广播。

摄像机：连续手持拍摄。轻微微晃。15 秒内缓慢平滑推进变焦到亲吻摄像面板。

锁定：Jumbotron、记分牌（KNICKS 57 / Q4 4:32 / BULLS 61）、红色亲吻摄像边框、闪亮爱心、手写 "Kiss Cam" 脚本、AT&T 品牌标识、黑暗赛场、前景粉丝剪影——所有内容一致。

在亲吻摄像框架内：
两个主题都是第一个帧参考静图的亲吻摄像面板上已经显示的两个角色——在 15 秒内保留他们的确切相似性和确切视觉风格。不要用不同的风格重绘任何主题。他们在原始风格内以微妙、克制、真实的生活动作动画——小自然眨眼、轻柔呼吸、轻微转头、短暂微笑。既不僵硬也不冻结，也不过度表演。表情水平是当真实的人在体育场摄像机前被意外捕捉时显示的。保持所有动作微妙、可信、人类。
背景中周围尼克斯球迷自然反应。

时间线（所有反应保持微妙和人类规模）：
0-3s：主题 A 注意到相机，小尴尬的半微笑，看向主题 B。主题 B 一会儿后注意到，柔和的自然意识，轻微微笑开始。背景球迷温和反应。
3-7s：A 和 B 交换短暂温暖的眼神，分享安静的小笑声。脸部放松到自然微笑。
7-11s：A 和 B 靠近并温柔地亲吻嘴唇——短暂、甜蜜、自然，不是排练的。观众轻声欢呼。
11-15s：他们分开，带着轻柔的自然微笑。B 轻轻把头靠在 A 的肩膀上。两人分享小安静笑声。

音频（非叙事性/仅离屏——主题 A 和主题 B 在整个过程中保持沉默，嘴巴闭合，不要口型同步以下对话）：
- 整个过程中有拥挤赛场的环境音。
- 离屏性别中性的 PA 宣讲员（不是任何可见主题——一个看不见的体育场声音），放大，略带回声，俏皮。
  0-3s： "哦，花园的亲吻摄像——看看这个！"
  3-7s： "哈哈——看看他们会不会接！"
  7-11s：观众爆发 "AWWWWS"，欢呼，掌声逐渐增强。
  11-15s：PA 笑着： "就在那里！今晚花园的真爱！"
- 手机麦克风比 PA 回声更清楚地拾取附近的球迷声音。

美学：真实观众手机拍摄，黑暗噪点，轻微过曝 LED，轻微运动模糊。16:9，1080p.
```

**为什么“在参考风格内微妙、克制、真实的生活动作”（而不是“仅微妙动作”，一个特定风格标签，或表达性微表情列表）：**

- *第一版*将风格化的主题限制为“仅轻微头部/眼神移动——始终保持为黑胶玩具”，看起来像是冻结并粘贴进去的。
- *第二版*命名了特定风格（“皮克斯质量的3D角色”），即使参考风格不同，也迫使主题趋向于那种外观。
- *第三版*要求“自然且富有表现力地动画”，并附带了一组微表情列表（“眼睛睁大，嘴巴因惊讶而张开，笑时脸颊抬起，双手举到脸上”），然后主题过度表演，对着镜头扮鬼脸，变得戏剧化。

工作框架保留了风格保留锁定，但指定了微妙的、克制的、真实的运动，就像实际上被体育场摄像机捕捉到的人一样——与 `exaggerated acting / theatrical expressions / over-acting / mugging at camera / cartoon reactions` 在 `negative_prompt` 中配对，以抑制回归到第三版失败模式。

将返回的视频URL保存为 `state.kisscam_video_url`。如果生成是异步完成的，请遵循MCP工具返回的状态句柄。客户端层超时会在没有 `task_id` 的情况下创建一个上游任务孤儿；不要提交重复项。将超时和上游任务风险告知用户，然后在任何重跑之前等待可恢复的任务句柄或明确的操作员确认。

步骤2 Kling视频生成最多只有2次总尝试（初始渲染+一次用于文本/记分牌动画、身份漂移、接吻时机、PA时机或口型错误的纠正重试）。kling-v3-omni没有种子，相同的Kling有效负载可以解析为相同的作业/资产。不要提交相同的Kling有效负载只是为了寻求变化。在纠正重试之前，通过使用更新的 `state.kisscam_still_url`、恢复缺失的严格参数/负提示条目或更改PA音频措辞/时机来实质性地更改有效负载。跟踪 `state.step2_attempt_count`。

**失败时**：只有在更改了Kling有效负载之后才使用步骤2的纠正重试——不要切换视频引擎。Seedance的两阶段相似性门（与 `baseball-trend` 同胞）在这里使其无法使用。如果本身是问题（使用步骤1的自检标准——文本拼写、记分牌、相似性——来决定），如果步骤1预算仍然存在，则重新运行步骤1，并使用新的静止图像作为更改的第一帧。在任一上限用尽后，停止并要求更安全的参考或交付最佳尝试；包括最佳静止图像/视频URL和失败检查。

## 步骤3 — 交付

返回两个Pika CDN URL：静止图像URL和最终视频URL。如果主机客户端需要本地媒体标记，请在确认两个CDN URL都可访问后，在此技能之外创建本地预览。

一句话总结：*"MSG的接吻镜头时刻——15秒，16:9，1080p，Kling v3-omni，本土PA播音员评论和观众反应。"*

## 飞行后质量门

在宣布成功之前，对 `state.kisscam_video_url` 调用 `analyze_media` 并要求结构化裁决：

```
仅返回JSON：{
  "verdict": "clean" | "degraded" | "catastrophic",
  "observations": string[],
  "quality_warning": string | null,
  "re_roll_suggestion": string | null
}
检查两个面部是否始终与参考一致，接吻动作是否完成为一个简短的自然唇吻，接吻镜头文本/记分牌样式是否保持可读，并且没有可见主题口型同步屏幕外的PA音频。
```

- 如果 `verdict` 是 `clean`，则正常返回静止URL和最终视频URL。
- 如果 `verdict` 是 `degraded`，则返回URL加上 `quality_warning`，以便用户在发布前查看。
- 如果 `verdict` 是 `catastrophic`，则不要调用运行完成；而是显示裁决和 `re_roll_suggestion` 而不是宣布成功。

## 运行时预期

- **步骤1 — gpt-image-2 中等，16:9，2个参考图像**：~40–90秒
- **步骤2 — kling v3-omni，专业1080p，15秒，带声音**：~3–5分钟
- **步骤3 — 下载+发出标记**：~5–10秒
- **每次拍摄的总时钟时间**：~4–6分钟

如果步骤1需要重跑，预算将重新开始；在步骤2中，只有视频阶段会重复。

## 承重短语（保持原样）

不要未经重新验证传递修改——它们是经验行为依赖，而不是风格选择。

**图像提示（步骤1）：**

- `观众POV手机截图...从看台向下看巨大的悬挂式巨型广告牌`——没有这个，模型默认为广播美学
- `标志性的复古竞技场接吻镜头风格` + 四个装饰性圆点（深红色边框、闪亮的心形、星形图案、手写Kiss Cam）——一起产生可识别的复古外观
- `来自第一个/第二个参考图像中的角色`——图像接地锁定；永远不要用口头特征描述替换
- `保留他们的精确相似性和精确视觉风格` + `不要用不同的风格重绘`——风格保留锁定；两半都是承重

**Kling提示（步骤2）：**

- `第一帧：在MSG的观众POV手机拍摄的广告牌接吻镜头段落`——与静止匹配的锚点
- `在整个15秒内保留他们的精确相似性和精确视觉风格`——身份+风格跨剪辑的连续性
- `在原始风格内进行微妙、克制、真实的运动` + `既不僵硬和冻结，也不过度表演` + `表情水平是当真实的人被体育场摄像机意外捕捉时显示的水平`——校准运动水平（避免“黑胶玩具冻结”和“戏剧性过度表演”的失败模式）
- `嘴唇轻柔接吻——短暂、甜蜜、自然、非排练`——接吻节拍锚点（不要软化到“头部”/“脸颊”——趋势是唇吻）
- `音频（非叙事性/仅屏幕外——主题A和主题B在整个过程中保持沉默，嘴巴闭合，不要口型同步任何对话以下）` + `屏幕外性别中性的PA播音员（不是任何可见主题——一个看不见的竞技场声音）`——没有这些，Kling会将引用的对话归因于一个可见的面部，并将播音员台词口型同步到主题A或B
- `手机麦克风拾取附近观众的噪音比PA回声更大`——销售观众手机音频美学

**Kling负提示（步骤2）：**

- `夸张表演、戏剧性表情、过度表演、对着镜头扮鬼脸、卡通反应`——没有这些，Kling会回归到“表现力”失败模式，其中主题对着镜头扮鬼脸
- `主题口型同步PA播音员对话，角色说着播音员台词，主题的嘴巴随着屏幕外声音移动，主题对着镜头说话，屏幕上口型同步`——与屏幕外音频锚点配对；抑制Kling将可见嘴部动画到匹配任何音频轨道上语音的默认行为

**参数：**

- `provider: gpt-image-2`（步骤1）——见步骤1推理
- `prompt_adherence: 严格`（步骤2）——没有它，记分牌和“Kiss Cam”文本在剪辑中途漂移
- `image_types: ["first_frame"]`（步骤2）——将静止锁定为字面帧0
- `quality_mode: pro`（步骤2）——1080p输出
- `duration: 15`（步骤2）——时间线节拍（0-3秒 / 3-7秒 / 7-11秒 / 11-15秒）是为15秒编写的；更改持续时间会破坏接吻节拍时间

## 引擎选择：gpt-image-2 + Kling-only

**步骤1 — gpt-image-2，无回退。** 经验上最锐利的LED面板细节（记分牌数字、接吻镜头排版、复古装饰边缘）和最强的参考相似性锁定——组合是销售趋势的关键。在 `moderation_blocked` 响应时，如果步骤1预算仍然存在，重新运行相同的调用，而不是在步骤1预算内切换提供者；在早期试验中，替代品产生的相似性和LED细节较软。

**步骤2 — Kling，无Seedance。** Seedance有一个两阶段的 `partner_validation_failed` 422门（与 `baseball-trend` 同胞技能相同）：一个输入端门，它拒绝具有可识别真实人物的参考，以及一个输出端门，它在生成后拒绝如果生成的剪辑包含看起来像人脸的内容。每个接吻镜头拍摄都有充满面孔的拥挤竞技场人群，所以输出端门在这里不可避免。Kling是唯一能实现这个配方的引擎。

**Kling权衡**：2500字符 `prompt` 限制（上面的配方已修剪到~2400字符；重新膨胀它可能会触发提示长度错误）。kling-v3-omni没有种子；相同的Kling有效负载可以折叠到相同的作业/资产，因此纠正重试必须实质性地更改第一帧静止图像、提示、负提示或PA音频措辞。不要提交相同的Kling有效负载以寻求变化。

## 失败速查表

| 症状 | 修复 |

| Kling提示错误：提示 > 2500字符 | Kling提示中音频或美学部分的重新膨胀。从音频或美学块中剪切；永远不要从动画时间线中剪切 |

## 不要做的事情

- **不要添加名字 chyrons。** 这个趋势没有名字——它是两个被摄像头捕捉到的匿名主题。
- **不要将其渲染为带有心形覆盖的电视广播切出。** 它是巨型广告牌拍摄。
- **不要简单地说“仅轻微运动”**（主题冻结成黑胶玩具僵硬）**或加载动画块以同时进行微表情**，如“眼睛睁大，嘴巴张开，脸颊抬起”。工作框架是 `微妙、克制、真实的运动，就像被体育场摄像机意外捕捉到的人一样`——两个失败模式都隐藏在“轻微”一词中；“真实”是校准它的限定词。
- **不要用夸张的情感形容词**（“巨大的微笑”，“害羞的兴奋摆动”，“眼睛睁大”，“咯咯笑”）编写时间线节拍。使用克制的动词：“注意到”，“小微笑”，“交换眼神”，“分享轻声的笑声”。
- **不要在提示中指定特定目标风格**（皮克斯、动漫、迪士尼、照片逼真等）。参考图像定义了风格；提示只是说“保留参考风格”。
- **不要将接吻软化到前额/脸颊/“头顶上的吻”。** 趋势是唇吻——保留逐字 `嘴唇轻柔接吻——短暂、甜蜜、自然、非排练` 节拍。
- **不要将音频块编写为没有屏幕外锚点的简单引用对话。** Kling默认将任何引用的语音归因于一个可见的面部，并将播音员台词口型同步到主题A或B。始终以 `Audio (非叙事性/仅屏幕外——主题A和主题B在整个过程中保持沉默，嘴巴闭合，从不口型同步任何对话以下)` 帧架音频块，并将反口型同步术语添加到 `negative_prompt`。
- **不要在叙事或PA对话中对任何主题进行性别化。** 使用“主题A/主题B”、“他们/他们”，或无代词的描述。
- **不要在审查时切换提供者**——仅在步骤1预算内重新运行相同的 `gpt-image-2` 调用。
- **不要尝试Seedance。**
- **不要生成音乐。** 本地PA播音员+观众环境音就是配乐。
- **不要运行后处理层**（`add_captions`，`generate_music`，`edit_concat`，`edit_text_overlay`，`edit_pip`，任何 `edit_*`）。Kling直接烧毁得分bug+ chyron+ 本土评论；事后添加任何内容都会破坏接吻镜头幻觉。
