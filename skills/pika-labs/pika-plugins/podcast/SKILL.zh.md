# /pika:podcast

4幕 × 15秒每幕 = 60秒。主持人A始终在左侧，主持人B始终在右侧。接受URL**或**自由形式的主题/简报。

## 参数

| 参数 | 默认值 | 备注 |
|---|---|---|
| `input` | 必填 | 审核的URL **或** 自由形式的主题/简报（例如："我和埃隆·马斯克谈论火星"） |
| `bg_img` | 自动生成 | 播客工作室背景 |
| `host_a_img` | 自动生成 | 主持人A肖像 — 见真人处理部分 |
| `host_b_img` | 自动生成 | 主持人B肖像 — 见真人处理部分 |
| `voice_a` | `876341503281471517` | Kling预设或克隆语音ID，用于主持人A |
| `voice_b` | `829837252279803904` | Kling预设或克隆语音ID，用于主持人B |
| `aspect_ratio` | `16:9` | 输出宽高比 |

## 成本透明度门

在支付任何MCP通话之前，调用一次 `identity_balance({verbose: true})`。显示当前余额、近期消耗率和剩余运行时间，然后用以下确切消息锁定运行：

> 预计成本：大约6,000-9,000信用点（~$60-$90），用于四个Kling v3-omni专业15秒的剧集，可选缺失资产图像生成，一个剧集纠正重试，连接，和飞行后analyze_media QA。这超过了$5，所以回复 `proceed` 继续或 `cancel` 停止。

在用户回复 `proceed` 之前，不要调用任何付费MCP工具。如果用户回复 `cancel`，则不生成并停止。这是唯一的“是/否”门；在 `proceed` 之后，渲染四个剧集并返回URL。

## 默认值 — 快速启动，不进行流程中确认

- **在声音参数表中无声地使用默认值。** `voice_a` 默认为Kling预设 `876341503281471517`，`voice_b` 默认为 `829837252279803904`。在启动之前**不要**询问“哪个声音？” — 仅尊重显式覆盖（`voice_a=`, `voice_b=`）。
- **无声地自动生成任何缺失的主持人肖像**（步骤1的原型提示）。**不要**询问“我应该生成主持人图像吗？” — 直接生成。
- **只有成本透明度门会询问 `proceed`。** 在 `proceed` 之后，提交 → 渲染四个剧集 → 返回URL。账户信用余额 + 提供商故障转移是规范的保护措施。`--yes` 标志被接受为向后兼容的无操作。
- **主题模式角色（步骤3）** — 当用户命名一个真实的公众人物时，无声地遵循步骤4（真人处理）：默认使用原型肖像，不自动生成照片肖像，不向用户询问肖像权问题。

## 生成前时钟保护

在播客输入解析后和成本门通过后，在技能启动时启动计时器。第一个付费生成调用是 `generate_image`，用于缺失的背景/主持人资产。如果所有资产都已提供，第一个付费生成调用是 `generate_reference_video`。第一个付费生成调用必须在技能启动后的5分钟内被调用。如果你在技能启动后的5分钟内没有调用第一个付费生成调用，则在任何付费生成调用之前停止，并报告 `failed_pre_generation_timeout` 以及你目前的状态：输入模式、资产状态、声音状态、URL捕获/WebFetch状态、脚本草稿状态和确切障碍。不要继续完善主持人原型、事实基础、笑话或剧集措辞。

在每个准备阶段之后，在付费生成调用之前打印单行进度检查点：
- `Stage 1/4 done — input resolved and cost gate passed, locking missing-asset image prompts.`
- `Stage 2/4 done — missing asset prompts ready, calling image generation now.` 在缺少任何背景或主持人图像时，使用此内容在第一个付费 `generate_image` 调用时。如果所有图像都已提供，则发出 `Stage 2/4 done — assets and voices ready, collecting URL/topic facts.` 而不是，并且继续而无需图像生成。
- `Stage 3/4 done — script draft locked, preparing first act.`
- `Stage 4/4 done — first act prompt ready, calling Kling now.`

缺失资产图像提示迭代在第一个 `generate_image` 调用之前最多2次。在最多2次之后，将你目前的状态发送到 `generate_image`；不要继续完善主持人原型、工作室背景细节或角色样式。脚本和剧集提示迭代在Kling之前最多2次。在最多2次之后，将你目前的状态发送到 `generate_reference_video`；不要继续完善笑话、中断、角色框架或摄像机措辞。

## 本地图像在Claude桌面

Claude桌面目前无法将内联粘贴的图像传递给MCP工具（Anthropic方面的限制）。如果用户内联粘贴了一张照片，或者提到了他们想要作为 `host_a_img` / `host_b_img` 的本地文件，请暂停步骤1并友好地发送他们这个 — 类似于：

> 注意 — 粘贴的图像目前无法在Claude桌面上到达MCP工具（Anthropic限制）。对于您的照片有两个简单的选项：
>
> - 如果它已经在托管（Imgur、S3、您的网站），请粘贴URL — 最快
> - 将图像文件附加给我，以便我在生成之前上传。

当本地文件到达时，使用 `upload_asset` 将其转换为公共URL，并使用返回的 `public_url` 作为步骤1之前的参数。已经托管的 `https://...` URL按原样工作并跳过此过程 entirely。

如果用户命名了一个真实的公众人物而没有附加任何内容，则**不要**自动生成他们的肖像 — 步骤4（真人处理）使用原型肖像。

## 长任务任务_status轮询

当任何长时间运行的生成或编辑调用返回带有或没有初始状态的 `task_id`，包括 `{task_id}`、`{task_id, status: "queued"}` 或初始 `queued`、`running` 或 `processing` 状态时，立即记录任务ID和启动时间。

- 在 `task_status({task_id})` 中以紧密循环调用，直到终端（`completed | failed | cancelled`）。不要手动睡眠和不要Bash轮询；工作进程会保持每个状态调用打开。
- 在状态为 `queued`、`running` 或 `processing` 时，每60秒发出一条可见的进度行：`Seedance i2v queued for {N}m {S}s... still processing`。在轮询Kling、图像生成、克隆语音或连接任务时，替换提供者/阶段标签。
- 在 `completed` 时，解包返回的结果URL并继续。
- 在 `failed` 或 `cancelled` 时，向用户显示失败，包括 `task_id`、状态和最后的状态消息。
- 从原始提交起15分钟后，如果任务仍然非终端，调用 `task_cancel({task_id})`，然后向用户显示失败。如果取消报告任务已经终端，再次调用状态一次并报告终端结果。
- 在原始任务仍然为 `queued`、`running` 或 `processing` 时，不要提交重复请求。

## 步骤

### 0. 解析输入（空参数菜单）

从 `$ARGUMENTS` 中剥离标志（`--yes`、`--no-captions` 等）和 `key=value` 参数。**如果剩余内容为空或仅包含空白**，请将此菜单**逐字**打印为您的完整响应，然后**停止并等待用户的下一条消息** — 不要调用任何工具，不要进入步骤1，不要编造主题或URL。如果剥离的输入非空（URL或任何文本），则无声地跳过此步骤并进入步骤1。

> **您想播客讨论什么？** 我可以接受任何：
>
> - **网站URL**（产品页面、文档网站、发布页面） — 例如 `https://pika.art`
> - **GitHub仓库** — 例如 `https://github.com/anthropics/claude-code`
> - **博客文章/文章URL** — 例如您想要讨论的最新文章
> - **自由形式的主题或简报** — 例如 *"我和埃隆·马斯克谈论火星"* 或 *"两位科学家辩论AGI"*
>
> 回复您的选择，我将生成一个1分钟的两位主持人播客视频（4幕 × ~15秒）。
>
> *提示：您不需要输入 `/pika:podcast` — 只要说类似 "制作关于 <主题> 的播客"、"播客评论 <URL>" 或 "我和 <角色> 谈论 <主题>"，我会自动启动此技能。*

当用户回复时，将他们的回复视为解析后的输入（URL或主题），并进入步骤1。不要重新提示。

### 1. 生成缺失资产（并行）

仅生成未提供的内容。默认原型提示：
- `bg_img` — 现代播客工作室，两把椅子，温暖的光线，无人，16:9
- `host_a_img` — 热情主持人，工作室肖像，左侧构图，1:1
- `host_b_img` — 实用怀疑主持人，工作室肖像，右侧构图，1:1

如果输入提到了特定角色（步骤3），调整原型以匹配角色氛围 — 见真人处理部分。

### 2. 解析声音ID

使用 `voice_a` / `voice_b` 作为给定值；否则回退到默认的Kling预设（`876341503281471517` / `829837252279803904`）。如果用户通过 `voice_a=` / `voice_b=` 提供了克隆语音ID，则直接使用它。

### 3. 解析输入模式 — URL与主题

从 `$ARGUMENTS` 中剥离标志（`--yes`、`--no-captions` 等）和 `key=value` 参数。检查剩余内容。

**URL模式** — 输入包含 `https?://` URL：
- 对URL调用 `capture_website` 仅用于视觉基础：产品/页面名称、可见布局、截图、b-roll提示，以及一个可幽默的视觉细节。
- 对同一URL调用 `WebFetch` 并使用其全页文本作为脚本事实来源。不要仅依赖截图获取事实。
- 从组合输入中提取：产品名称、价值主张、2-3个特定功能或事实、价格、一个可幽默的细节，以及任何具体的引言或声明。
- 对于长文档（维基百科、文档、博客文章或文章），扫描WebFetch全页文本来查找引言之外的深度部分。当至少有3个实质性深度部分存在时，脚本必须提及引言之外至少3个不同部分（例如架构、训练、幻觉、限制、部署或安全），而不仅仅是开头的摘要。
- 使用WebFetch文本作为事实锚点，并使用 `capture_website` 作为视觉参考。如果它们冲突，则优先考虑WebFetch的事实声明，并将截图视为视觉参考。

**主题模式** — 输入是自由形式的文本（没有URL）：
- 将整个输入视为简报。解析：
  - **主题** — 谈话的内容
  - **主持人** — 明确的（如果提到："我和埃隆·马斯克"、"两位科学家"、"乔和莎拉"；否则使用默认值（热情主持人 + 怀疑主持人）
  - **角度** — 辩论/采访/解释/休闲
  - **具体事实** — 用户提供的任何具体声明、数字、日期、引言
- 如果没有具体事实给出，使用 **2-3个清晰构建的观察或假设** 来锚定笑话和 "等等..." 转折。不要将编造的声明作为事实；如果事实准确性对主题很重要，请要求一个来源或URL。
- 如果用户说 "我和X" 或 "我和X"，主持人A = 用户（如果提供了 `host_a_img=`，则使用生成的主持人肖像，否则生成主持人肖像）和主持人B = X。

### 4. 真人处理（主题模式仅限）

如果解析的输入命名了一个特定的真实公众人物作为主持人（例如 "埃隆·马斯克"、"泰勒·斯威夫特"、"乔·罗根")：

- **默认行为**：不要自动生成该人物的摄影肖像。生成匹配角色氛围的原型肖像 — 例如 "科技亿万富翁能源CEO在播客桌前" 用于埃隆风格的主持人，"流行音乐人美学" 用于泰勒风格的主持人。灵感来自，而不是模仿。
- **覆盖**：如果用户明确提供 `host_a_img=<url>` 或 `host_b_img=<url>`，则直接使用提供的图像。用户对肖像权负责。
- **声音**：相同逻辑 — 默认为通用Kling预设；仅在用户提供时使用克隆语音（`voice_a=` / `voice_b=`）。
- **脚本语气**：对话可以基于命名角色的已知公共立场或氛围（例如埃隆风格的火星热情） — 公开记录的意见是可以接受的。不要在他们的口中放入具体的诽谤性、非角色或编造的私人生活声明。

这个保护措施使技能保持创意（"我想制作一个播客，在那里我和一位科技CEO辩论火星"），而不自动生成命名真实人物的深度伪造。

### CJK/非拉丁处理

当URL、主题、产品名称、主持人名称、引言或所需脚本细节包括中文、日文、韩文、阿拉伯文、天城文、西里尔文、带重音的拉丁文、表情符号或任何其他非拉丁文本时，使用此部分。

- **脚本保留**：在脚本状态和任何事实摘要中精确保留用户提供的非拉丁字符。不要罗马化、转写或翻译产品名称、人名、口号或引语，除非用户明确要求。如果发音辅助有用，请将其放在附近的英语散文中，而不是作为原始字符的替代品。
- **Kling语音ID**：`voice_a=` 和 `voice_b=` 必须是有效的Kling语音ID。对于中文/日文/韩语对话，优先选择知道说该语言的Kling语音ID或克隆语音样本；如果没有语言匹配的Kling语音可用，请在对话中保留原始字符，并指出发音可能是口音而不是无声地切换到无关的TTS提供者。
- **混合语言对话**：保持每个主持人的行简短且无歧义。避免要求Kling发音长混合语言段落；将复杂名称或引语跨剧集拆分，并保持周围的英语简单。
- **字幕/字体回退**：此技能默认跳过 `add_captions`，因为播客对话可能无法准确翻译术语。如果用户明确要求字幕，请从编写的脚本中传递手动 `subtitles[]` 而不是自动转录，设置 `font: "noto-cjk"` 用于中文/日文/韩文，并精确保留原始非拉丁文本。
- **QA**：在交付之前，在最终结论中包含一条单行注释，说明是否在脚本中保留了原始字符，以及所选声音是否语言匹配或尽力而为。

### 术语密集的本地音频处理

当URL、主题、产品名称、引言或所需脚本细节是领域密集或术语密集的，特别是金融、法律、医学、AI/加密货币、缩写、编造的术语、不寻常的产品名称、长数字或多词复合词时，使用此部分。Kling-omni本地TTS可能会在本地音频中混淆编造的术语，而不仅仅是自动字幕，因此在使用付费Kling调用之前降低风险。

- **风险扫描**：当某一行包含多个领域专有术语、缩略语、长数字，或嵌套/多子句的经济学风格表达时，将该次运行标记为“术语密集”。将 stablecoins（稳定币）、unbundle（解绑/拆分）和 reassure（使放心）等示例视为必须保持可理解性的关键术语。
- **脚本重写**：在脚本状态和最终回顾中保留规范术语，但缩短其周围的口头表达。使用短句，拆分长从句，每句主持人行话最多保留一两个高风险术语，并避免使 Kling 推断出相似发音的填充词的嵌套从句。
- **发音辅助**：为高风险术语创建每个幕的小型发音辅助，例如 `stablecoins = STAY-bul coins`、`unbundle = un-BUN-dul`、`reassure = ree-uh-SHOOR`。发音辅助仅为提示元数据；不得在对话、字幕、事实或最终回顾中替换规范术语。
- **已知难词纠正**：如果已知某术语会发生漂移，或飞行后定位到近邻误听，请勿重试同一个独立难词。在幕元数据中保留规范术语（`canonical_terms: ["unbundle"]`），然后使纠正后的语音标记行变为一个带有可发音提示/微停顿的简短语境短语，例如 `we un-bundle payments`。在元数据中将观察到的错误形式添加为负向发音保护，例如 `unbundle = un-BUN-dul, not un-bumble`。
- **已知难词可发布回退**：在调用付费的 Kling 之前，当先前的端到端测试或当前飞行后结果显示出漂移（如 `unbundle` -> `unbubble`、`un-bumble` 或 `unbundable`）时，将观察到的难词（如 `unbundle`）标记为已知难词。记录 `canonical_terms` 和 `observed_wrong_forms`。不要用 Kling 原生音频渲染已知难词的口头术语。相反，生成受影响视觉幕或最终视频，使其原生语音标记行中不包含已知的难词口头术语，然后使用 `generate_speech(text=<spoken-only script>, provider: "minimax-tts", minimax_model: "speech-2.8-hd", language: "en")` 生成受控旁白，使用规范拼写（`unbundle`，而非连字符提示）。仅口头的脚本必须保留编写的主持人回合顺序，但不得包含 HOST_A/HOST_B 标签、元数据、发音辅助或观察到的错误形式拼写。在 TTS 音频上运行替换前 QA，同时使用 `transcribe_audio(audio=<tts_audio_url>)` 和 `analyze_media(media=<tts_audio_url>)`；每个必需的 `canonical_terms` 条目必须出现在 `transcribe_audio` 文本中，且必须出现在 `analyze_media` 的观察转录中。如果规范术语缺失、被任何观察到的错误形式替换，或被新的近邻替换，则拒绝该 TTS。然后调用 `edit_audio_replace(video_url=<final_mp4>, audio_url=<tts_audio_url>, duration_policy: "video")` 以丢弃原生音频并用受控 TTS 轨道替换它。在被替换的 MP4 上运行替换后 QA，同时使用 `transcribe_audio(audio=<replaced_mp4_url>)` 和 `analyze_media(media=<replaced_mp4_url>)`；每个必需的 `canonical_terms` 条目必须出现在这两项最终检查中，并且 `analyze_media` 还必须验证主持人回合顺序和可接受的音视频同步。如果任何最终检查听到错误形式、缺失规范术语，或表示回退破坏了播客回合结构，则返回 `not publish-ready`（不可发布）；如果两项检查均通过，则回退输出是可发布的，即使它使用受控 TTS 而非 Kling 原生语音。
- **数字和缩略语**：当重要时，使用便于口头的形式：`$175B` 变为 `one hundred seventy-five billion dollars`；除非品牌通常将其作为一个单词发音，否则 `API` 变为 `A P I`。
- **幕提示**：在每个语音标记行附近包含该幕的发音辅助，并说明它不是对话，不应逐字读出。要求清晰发音规范术语，且不即兴创造相似词汇。

### 5. 编写脚本

编写 4 个幕 × 各 2 行（HOST_A / HOST_B）。每行约 10–12 秒的口头对话。

**必需项（适用于 URL 和主题模式）：**
- 一个具体的小笑话，绑定到具体细节（URL 模式中的抓取事实；主题模式中的主题衍生声明）
- 一个“等等，实际上……”的怀疑论翻转时刻
- 至少一个句中打断
- 自然的填充词：“okay so”（那么）、“wait”（等等）、“right?”（对吧？）、“i mean”（我是说）、“honestly”（老实说）
- 真实的反应，而非泛泛的赞美
- 至少引用一个真实的功能名称、价格、声明或引言
- 自然的结尾——不要强行说“再见！”
- 当主题领域密集、术语密集或使用新造词时，在定稿幕行之前应用“术语密集原生音频处理”。

幕结构：钩子 → 功能深入解析 → 转折 → 结论
（在主题模式中的对应结构：钩子 → 实质内容 → 转折点 → 结论。）

### 6. 生成视频幕（子代理，顺序执行）

将所有已解析的资产和脚本委托给子代理。子代理按顺序运行幕 1→2→3→4——不要并行化。子代理必须遵循上述的长时任务状态轮询契约，在等待 Kling、图像生成、语音克隆或拼接任务期间，每 60 秒向父级中继一次进度行。

每个普通幕：一次 `generate_reference_video` 调用（`kling-v3-omni`、`duration=15`、`sound=true`、`quality_mode: "pro"`）。在每个普通幕中传入 `reference_images=[bg_img, host_a_img, host_b_img]`、`voice_ids=[voice_a, voice_b]` 和 `quality_mode: "pro"`；因为这必须传入 `quality_mode: "pro"`，成本门槛引用的是专业级 15 秒幕的成本。可选旋钮：`kling_model` 用于固定特定的 Kling 系列成员，如果需要跨运行保持可复现性。三个镜头：

- **已知难词回退例外**：对于包含已知难词口头术语的幕，以 `sound=false` 渲染受影响的视觉幕，并且受影响行没有语音标记。在任何 `<<<voice_*>>>` 原生语音标记行中不包含已知的难词规范术语；受控 TTS 替换稍后提供这些词。对于术语密集但非已知难词的幕，将第 5 步中的每幕发音辅助作为非对话元数据包含在幕提示中，并在引用的 `<<<voice_*>>>` 行中保留规范术语。
- 宽景 5 秒：两位主持人，无语音标记
- MCU-A 5 秒：`<<<voice_1>>> '<HOST_A 行>'`
- MCU-B 5 秒：`<<<voice_2>>> '<HOST_B 行>'`

每幕的情感节奏：
- 第 1 幕：A 兴奋，B 怀疑
- 第 2 幕：A 做手势/解释，B 提问
- 第 3 幕：A 坚定，B 惊讶并重新考虑
- 第 4 幕：A 满意，B 让步

在第 4 幕后，子代理调用 `edit_concat([act1, act2, act3, act4])`，向父级中继任何异步轮询进度，并返回最终视频 URL。将四个幕的 URL 保留在状态中，以便飞行后质量门槛可以最多花费一次针对性的幕纠正，而不必重新生成干净的幕。

### 7. 输出

返回最终视频 URL 和一句话结论。**默认不调用 `add_captions`** —— Whisper 自动转录对播客对话中典型的领域专有术语（产品名称、人物名称、技术术语）不可靠。如果用户明确要求字幕，请从编写的脚本传递手动 `subtitles[]`，而不是自动转录；对于 CJK/非拉丁文文本，请遵循上述字体和保留指导。Kling Omni 原生音频是默认交付物。

## 飞行后质量门槛

在声明成功之前，对最终视频 URL 调用 `analyze_media` 并请求结构化结论：

```
仅返回 JSON：{
  "verdict": "clean" | "degraded" | "catastrophic",
  "observations": string[],
  "quality_warning": string | null,
  "re_roll_suggestion": string | null
}
检查 Host A 是否始终在左侧，Host B 是否始终在右侧，产品名称/人物名称/主题特定术语是否可见地未乱码，四幕播客结构是否存在，且没有黑帧或错误主持人镜头。
还要检查口头音频，而不仅仅是字幕或可见文本：产品名称、人物名称、主题特定术语、新造词和术语必须可理解。标记乱码或发音错误的原生音频，例如 "stablecoins" 听起来像 "stable kinds"，"unbundle" 听起来像 "un-bumble" 或 "unbundable"，或 "reassure" 丢失音节。
```

- 如果 `verdict` 为 `clean`，首先检查脚本状态是否包含已知难词口头术语。对于已知难词，在接受 clean 结论之前，运行已知难词可发布回退及其替换前和替换后的 `transcribe_audio` / `analyze_media` 检查。只有在被替换的 MP4 检查通过后才返回成功。如果没有已知难词口头术语，则正常返回最终 URL 和一句话结论。
- 如果 `verdict` 为 `degraded`，原因是普通的非阻塞视觉问题，则返回最终 URL 加上 `quality_warning`，以便用户在发布前审查。
- 如果 `verdict` 为 `degraded`，原因是口头音频使术语、新造词或其他领域专有术语乱码，则将其视为不可发布，而不是静默成功。对于已知难词或观察到的难词漂移，跳过原生音频幕纠正；不要将针对性幕纠正预算花在另一个 Kling 原生音频提示上。直接使用已知难词可发布回退：调用 `generate_speech(text=<spoken-only script>, provider: "minimax-tts", minimax_model: "speech-2.8-hd")`，在 TTS 音频上运行替换前 `transcribe_audio` 和 `analyze_media`，然后调用 `edit_audio_replace(video_url=<final_mp4>, audio_url=<tts_audio_url>, duration_policy: "video")` 以丢弃原生音频并替换最终 MP4 音频。在被替换的 MP4 上运行替换后 `transcribe_audio` 和 `analyze_media`。如果这些检查通过，返回被替换的 URL；如果回退检查仍报告口头术语乱码，或乱码未足够本地化以便纠正或替换，则不要将播客标记为完成；返回带有 `not publish-ready`、受影响术语和 `quality_warning` 的 URL。仅对于非已知难词乱码，如果观察结果或 `re_roll_suggestion` 将问题本地化到一个幕，则花费那一次针对性幕纠正预算：通过缩短受影响行、拆分多子句措辞、添加或细化音素发音辅助、更改镜头提示、参考图像、语音 ID 或导致失败的其他阶段特定输入来实质性更改该幕负载。以 `quality_mode: "pro"` 提交一个纠正后的幕，重新拼接四个幕，并再次运行此 analyze_media 检查。如果第二次结论仍报告口头术语乱码，则不要将播客标记为完成；返回 `not publish-ready`。
- 如果 `verdict` 为 `catastrophic`，仅当观察结果或 `re_roll_suggestion` 识别出单个坏幕、错误主持人镜头、黑帧或本地化的视觉/音频故障时，才花费那一次针对性幕纠正预算。kling-v3-omni 没有种子，相同的幕负载可能解析为相同的任务/资产。不要提交相同的 Kling 负载。在重试之前，通过调整导致失败的脚本行、镜头提示、参考图像、语音 ID、发音辅助或其他阶段特定输入来实质性更改坏幕负载。以 `quality_mode: "pro"` 提交一个纠正后的幕，重新拼接四个幕，并再次运行此 analyze_media 检查。不要超出成本门槛范围：如果第二次结论仍为 `catastrophic`，或故障不能归因于一个幕，则不要将播客标记为完成；代替声明成功，呈现结论和 `re_roll_suggestion`。

---

**规则：**
- `voice_ids` 必须是有效的 Kling 语音 ID——永远不要使用名称样式的字符串，如 `Calm_Man`
- Host A 始终在左侧（`<<<image_2>>>`），Host B 始终在右侧（`<<<image_3>>>`）——永远不要交换

## 关键短语

这些锚点保持播客输出在 URL 和主题模式下的一致性：

| 短语 | 位置 | 为何关键 |
|---|---|---|
| `Host A 始终在左，Host B 始终在右` | 布局和镜头提示 | 防止在四个独立的幕渲染中主持人身份交换。 |
| `4 幕 × 各 15 秒` | 整体结构 | 保持拼接可预测，并避免不均匀的幕节奏。 |
| `钩子 → 功能深入解析 → 转折 → 结论` | 脚本结构 | 赋予节目对话弧线，而非四个不相关的反应。 |
| `wait, actually...` 怀疑论翻转时刻 | 脚本要求 | 创造使播客感觉像真实交流的转折点。 |
| `Do not call add_captions` | 输出规则 | 默认避免低质量的烧录字幕；明确字幕请求使用手动 `subtitles[]` 和字体回退，而非自动转录。 |

## 引擎选择：用于原生双主持对话的 Kling v3-omni

使用 Kling v3-omni 进行四个幕，因为它支持单个镜头计划中具有两个参考主持人和语音标记的原生对话。权衡是幕按顺序运行以确保一致性，可能比纯编辑/合成流程耗时更长。默认不要添加单独的字幕或音乐层；此技能的价值在于原生口头交流。

## 运行时预期

典型的完整 4 幕渲染挂钟时间为 24-32 分钟：约 25 分钟为现实值，约 32 分钟为 P95。
4 个幕通过 Kling Omni 顺序运行；这是主要的运行时，不应描述为并行工作。
如果用户或执行框架有低于 32 分钟的紧张预算，请提前警告完整渲染可能无法完成，并提供 2 幕 / 30 秒的回退。否则保持正常的无确认流程。

| 步骤 | 挂钟时间 | 备注 |
|---|---:|---|
| 缺失资产生成 | 30-90 秒 | 对于提供的背景/主持人参考跳过 |
| URL/主题解析 + 脚本 | 1-3 分钟 | URL 模式取决于页面抓取质量 |
| 四个 Kling 幕 | 24-32 分钟 | 4 × 约 8 分钟顺序 Kling Omni 调用；主要成本 |
| 拼接 + 返回 | 30-90 秒 | 仅最终 URL；默认跳过字幕 |

## 故障模式

### 从 capture_website / clone_voice / generate_video / edit_concat 的上游 5xx 中恢复

如果任何 MCP 调用返回：
- `code: "provider_5xx"` 且 `retry_class: "retry_after_backoff"`
- 或来自任何上游提供商（Kling、语音克隆、抓取、存储）的 HTTP 502 / 503 / 504

执行以下操作：
1. 等待 5 秒。
2. 使用完全相同的参数重新调用完全相同的 MCP 工具。不要重写脚本、更改语音、更改主持人参考、更改幕顺序或重新提交不同的提示。
3. 如果重试也因 5xx 失败，中止并向用户展示：“提供商两次返回瞬态上游错误。请在 1-2 分钟后重试；这通常会自动清除。”

不要重试超过一次。5xx 是瞬态中断，不是播客主题、语音或脚本错误的证据。

### 从上游 4xx / moderation_blocked 中恢复

如果在可选的 `generate_image` 辅助、主持人资产或 Kling 幕上发生上游 4xx 或 `moderation_blocked`：
1. 不要重试相同输入；审查和大多数 4xx 验证失败是确定性的。
2. 仅当该阶段明确可用回退提供商时使用回退提供商。对于默认的 Kling v3-omni 双主持人幕路径，不存在等效的回退提供商；不要用无关的字幕或单语音 TTS 伪造播客。
3. 向用户展示：“提供商拒绝了此播客输入。尝试不同的主持人参考、更少可识别的公众人物/品牌措辞，或更安全的话题角度。”

### 从上游 429（速率限制）中恢复

如果任何上游返回带退避提示的 HTTP 429：
1. 等待提示的退避，如果没有提示则等待 30 秒。
2. 使用完全相同的参数重新调用完全相同的 MCP 工具。
3. 不要重试超过一次。如果仍返回 429，中止并展示速率限制消息。

### `capture_website` 返回空/页面未加载

如果 URL 模式调用 `capture_website` 并返回 200 但 `action_bboxes` 为空或 `recording_viewport` 为 0x0：
1. 不要重试 `capture_website`；页面在捕获环境中未能渲染。
2. 如果 `WebFetch` 返回了可用的完整页面文本，则无需重试 `capture_website`：使用 WebFetch 处理事实锚点，并使用通用视觉或生成视觉代替假装损坏的捕获包含页面详情。
3. 如果捕获和 WebFetch 都未能暴露可用的源材料，则显示："无法捕获 <url>。页面可能被屏蔽 / 支付墙 / 需要认证。请提供文本摘要或粘贴源材料。"

如果捕获的页面仅可见为折叠上方的导航，没有文章/内容主体，则仅当 `WebFetch` 返回足够的完整页面文本足以支撑脚本时继续；在这种情况下，使用捕获用于视觉，使用 WebFetch 用于事实。如果捕获和 WebFetch 都未能暴露可用的源材料，则请求粘贴源材料而不是虚构深层页面细节。

### `upload_asset` 网络认证失败

如果 `upload_asset` 在将本地主机引用、语音样本或源媒体转换为托管 URL 时失败，不要继续使用本地文件系统路径。仅针对上述 5xx 或 429 类重试一次。对于 `auth_error`、不支持的 MIME、网络故障或重复上传失败，请求一个托管 URL 或一个支持的替换文件。

### 长时间运行的 `task_status` 超过上限

每个异步 MCP 调用返回一个内联结果或 `{task_id, status}` 用于轮询。在决定任务卡住之前，使用这些上限：
- Kling Omni 行为：每次调用 15 分钟
- 语音克隆：每次调用 5 分钟
- 编辑/连接：每次调用 5 分钟

使用较早的一个：提供商的上限 x 1.5 或任何特定技能的硬轮询上限，包括上述长时间运行的 `task_status` 轮询合同中的 15 分钟总上限。如果 `task_status` 返回 `status: "processing"` 或 `status: "queued"` 超过这个较早的限制，调用 `task_cancel({task_id})` 并显示："提供商处理时间异常长；中止。请重试。"
