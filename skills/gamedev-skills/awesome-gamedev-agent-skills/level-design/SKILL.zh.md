# 关卡设计

关卡是通过空间传递的**有意体验序列**。
良好的关卡设计是一个*过程*：定义运动构建的指标，用基本元素勾勒几何形状，进行试玩，然后进行装饰——永远不颠倒这个顺序。这项技能是引擎无关的实践；使用 `godot-tilemap`/`unity-tilemap-2d` 来为3D布置2D网格和网格图。

## 何时使用

- 用于规划关卡的结构：关键路径、节奏、门控、遭遇，以及玩家学习与被测试的地方。
- 使用 **勾勒 → 测试 → 迭代 → 装饰** 的工作流程，在任何艺术存在之前就构建一个玩起来流畅的关卡。
- 用于从角色的运动中推导关卡**指标**，使几何形状是可到达且公平的。

**何时*不*使用**：用于算法生成关卡，使用 `procedural-gen`（作者设计和过程设计是互补的）。对于引擎的瓦片/网格绘制工具，使用 `godot-tilemap` / `unity-tilemap-2d`。对于运动能力指标来源，那是引擎运动技能 + `input-systems`。

## 核心工作流程

1. **首先推导指标。** 测量角色：最大跳跃高度和距离、奔跑速度、范围、摄像机范围。每个缺口、边缘和走廊都以这些单位进行尺寸调整。在构建几何形状之前锁定它们。
2. **勾勒（白模/灰模）。** 使用正确比例的无纹理基本元素构建整个关卡。在变化廉价时验证流程、视线和可到达性。还没有艺术。
3. **定义关键路径**（开始 → 目标）以及你期望大多数玩家会走的**黄金路径**。在它上面分层可选/秘密路径。
4. **调整体验节奏。** 在精心设计的曲线上交替紧张和休息；不要连续进行战斗-战斗-战斗。给玩家留出呼吸和预期的空间。
5. **先教学后测试。** 在安全空间中引入每个机制，让玩家练习，然后在压力下测试它。难度呈锯齿形上升，而不是直线上升。
6. **有意门控。** 使用锁/钥匙、能力和单向坠落来控制顺序和节奏；用光线、线条和地标而不是墙壁来引导。
7. **试玩和迭代。** 观察真实玩家：他们在哪里迷失、卡住、感到无聊或被不公平地杀死？修复勾勒；只有在它玩起来流畅时才进行装饰。

## 模式

### 1. 玩家指标驱动每个维度

```gdscript
# 一次性测量角色，然后用这些单位调整几何形状。如果跳跃改变，必须重新推导缺口——不要凭肉眼判断可到达性。
const RUN_SPEED      := 240.0   # px/s（或3D中的m/s）
const MAX_JUMP_H     := 96.0    # 完全跳跃的峰值高度
const MAX_JUMP_DIST  := 200.0   # 奔跑跳跃的水平距离
const SAFE_GAP       := MAX_JUMP_DIST * 0.7   # 舒适的，而不是像素完美
const HARD_GAP       := MAX_JUMP_DIST * 0.95  # 一个有意的技能检查
# 构建平台，使所需跳跃使用 SAFE_GAP；为可选奖励保留 HARD_GAP。
```

一个可到达的关卡来自于诚实的指标。放置在 `MAX_JUMP_DIST + 1` 远的平台是不可能的；一个在 `SAFE_GAP` 的平台是公平的。将这些常量放在关卡数据旁边，以便设计师和代码达成一致。

### 2. 遭遇/节奏作为数据（一个紧张时间线）

```gdscript
# 将关卡作为一系列具有预期强度（0..1）的节拍来编写。
# 这使节奏曲线显式化，并在你构建房间之前可以审查。
const BEATS := [
    { "room": "entry",      "type": "teach",   "intensity": 0.1 },
    { "room": "hall_1",     "type": "combat",  "intensity": 0.5 },
    { "room": "vista",      "type": "rest",    "intensity": 0.1 },  # 呼吸和奖励
    { "room": "gauntlet",   "type": "combat",  "intensity": 0.8 },
    { "room": "save_room",  "type": "rest",    "intensity": 0.2 },  # 在Boss之前
    { "room": "boss",       "type": "climax",  "intensity": 1.0 },
]
# 从上到下读取强度列：它应该总体上升，但在休息时下降（锯齿形），永远不会高平。从这推导出生成/音乐强度。
```

### 3. 门控和关键路径（一个小图）

```gdscript
# 将关卡建模为房间+门控连接。验证目标是否可以用玩家实际按顺序获得的钥匙/能力到达。
const ROOMS := {
    "entry":   { "exits": [ { "to": "hall_1" } ] },
    "hall_1":  { "exits": [ { "to": "vista", "needs": "double_jump" },
                            { "to": "side_room" } ] },           # 可选分支
    "side_room": { "exits": [ { "to": "hall_1" } ], "grants": "double_jump" },
    "vista":   { "exits": [ { "to": "boss", "needs": "red_key" } ] },
}
# 验证（一定要做！）：从 "entry"，玩家能否在 "double_jump" 在 "side_room" 授予之前到达 "boss"？一个仅当其 `needs` 已经可满足时才遍历出口的洪水填充
# 证明了关键路径没有被软锁定。
```

## 陷阱

- **在它玩起来之前进行装饰。** 细节化一个未经验证的勾勒浪费了你在布局上最昂贵的工时，而你将改变它。先进行灰模和测试。
- **忽略指标的几何形状**：跳跃无法清除的缺口、低于可到达的边缘、比摄像机需要的更窄的走廊。用玩家单位调整所有内容。
- **平缓的节奏。** 墙到墙的战斗（或墙到墙的平静）会使玩家麻木。交替紧张和休息；在高潮之前放置一个呼吸和存档点。
- **在教授之前测试机制。** 玩家在第一次遇到一个危险时处于致命位置。安全地引入，让他们练习，然后测试。
- **软锁定和死胡同。** 一个门需要一个只有在门之后才能获得的能力/钥匙。验证关键路径的钥匙/能力顺序，而不仅仅是连通性。
- **没有可读性/指导。** 当没有任何东西吸引注意力时，玩家会迷失方向。使用光线、引导线、颜色和地标来指向路径。
- **没有标记的单向坠落** 会困住或让玩家感到意外。预告不可逆转的移动。
- **混淆过程生成与作者设计。** 生成提供多样性，而不是作者设计的节奏。使用 `procedural-gen` 来提供多样性；手工设计来体现意图。
