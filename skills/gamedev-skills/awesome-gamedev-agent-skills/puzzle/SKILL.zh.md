# 解谜

一个用于网格/棋盘解谜游戏的攻略——棋盘模型、移动输入、规则解析（匹配、推动、逻辑）、计分、撤销和关卡进度。这是一种**组合型**技能：它建模棋盘状态和规则，并通过瓦片图/UI呈现。它不会重新教瓦片图；它定义了解析循环和正确性规则（清洁状态、确定性解析、撤销），这些规则使解谜公平且无bug。

## 使用场景

- 当游戏是一个**离散棋盘**，玩家通过移动来改变，并且棋盘**通过规则解析**时：匹配3/瓦片匹配、推箱子/方块推动者、滑动解谜、逻辑网格。
- 当设计匹配/级联解析、撤销、关卡进度或可解性时。

**不使用场景：** 实时网格动作带永久死亡 → `roguelike`。卡牌区域/回合 → `card-game`。基于物理的“解谜平台游戏” → `platformer` + `physics-tuning`。对于瓦片渲染，使用 `godot-tilemap` / `unity-tilemap-2d`。

## 核心循环

**读取棋盘 → 规划移动 → 执行移动 → 棋盘根据其规则解析（匹配、推动、下落、填充、级联）→ 看向目标的进度 → 重复直到解决/失败。** 有趣的是*规划*；引擎的工作是确定性地解析每个移动并清晰地呈现。

## 必须的系统

1. **棋盘模型** — 一个由单元格组成的网格，包含瓦片；唯一的真相来源（逻辑，而非视觉）。
2. **移动输入** — 交换、推动、拖动、旋转或放置；在应用之前验证合法性。
3. **规则解析** — 检测并应用游戏类型规则（匹配、推动、逻辑）直到稳定。
4. **级联/链式反应** — 当解析改变棋盘时，重新解析直到不再变化。
5. **目标 + 计分** — 胜/负条件（分数、清除所有、达到目标）；移动/时间限制。
6. **撤销** — 撤销上一步移动（及其解析）；对于需要思考的解谜至关重要。
7. **关卡进度 + （通常）生成** — 手工编写或生成的**可解**棋盘。
8. **反馈（“juice”）** — 清晰、令人满意的动画/声音，用于匹配、下落和链式反应。

## 设计旋钮

| 旋钮 | 效果 | 备注 |
|------|------|------|
| 网格大小 / 形状 | 复杂度 | 正方形是标准；六边形/不规则形状改变感觉。 |
| 匹配/推动规则 | 类型身份 | 三连、形状、推入目标等。 |
| 级联计分 | 奖励深度 | 更大的链 = 指数回报。 |
| 移动 / 时间限制 | 压力 | 移动限制 = 解谜感；时间 = 街机。 |
| 难度曲线 | 学习 | 一次引入一个机制。 |
| 撤销深度 | 宽容 | 单步 vs. 完整历史。 |
| 可解性保证 | 公平性 | 生成的棋盘必须是可解的。 |
| 死锁处理 | 无死路 | 检测无移动；洗牌或结束（参考资料）。 |

## 模式

### 1. 棋盘模型 + 匹配检测（逻辑与视觉分离）

```python
# 伪代码。棋盘是真相；渲染从它读取。（0,0）左上角，y向下增长。
board = [[piece_or_empty for _ in range(W)] for _ in range(H)]

def find_matches(board):
    matched = set()
    for y in range(H):                       # 水平连续 >= 3 个相同瓦片
        run = 1
        for x in range(1, W):
            if board[y][x] and board[y][x] == board[y][x-1]: run += 1
            else:
                if run >= 3: matched |= {(y, k) for k in range(x-run, x)}
                run = 1
        if run >= 3: matched |= {(y, k) for k in range(W-run, W)}
    # ... 重复垂直扫描（列）...
    return matched
```

### 2. 解析 → 堆叠 → 填充 → 级联（重复直到稳定）

```python
# 伪代码。一个玩家的移动可以触发链式反应；循环直到棋盘停止变化。
def resolve(board):
    chain = 0
    while True:
        matches = find_matches(board)
        if not matches: break                 # 稳定：解析完成
        chain += 1
        score += score_for(matches, chain)    # 后续链步骤得分更高（见参考资料）
        clear(board, matches)                  # 移除匹配的瓦片
        apply_gravity(board)                   # 瓦片落入空隙
        refill(board, rng)                      # 在顶部生成新瓦片（种子RNG）
    return chain
```

### 3. 通过状态快照或命令撤销

```python
# 伪代码。每次移动前快照；撤销恢复它（棋盘 + 分数 + 计数器）。
def make_move(move):
    history.append(snapshot(board, score, moves_left))   # 在应用前推入
    apply(move); resolve(board); moves_left -= 1

def undo():
    if history:
        board, score, moves_left = history.pop()         # 精确还原，包括解析
```

对于大棋盘，优先使用**命令**模式（存储移动 + 足够的逆向信息）而不是完整快照以节省内存；快照最简单，对于小棋盘也足够。

## 陷阱 / 失败模式

- **混合逻辑和视觉** → 动画与状态不同步导致bug。棋盘模型是唯一的真相来源；视图仅渲染它。
- **只解析一次** → 忽略级联/链式反应。循环解析直到棋盘稳定（模式2）。
- **撤销不恢复所有内容** → 分数/移动计数/随机状态漂移。快照*所有*状态，或使移动完全可逆。
- **未种子的填充RNG** → 无法重现关卡 / 无确定性撤销或每日解谜。种子它。
- **不可解的生成棋盘** → 不公平的死路。生成并验证，或从已知解决方案反向生成（参考资料）。
- **无死锁检测**（匹配3）→ 无有效移动的棋盘软锁。检测“无移动”并洗牌或结束关卡（参考资料）。
- **难度突增** → 同时太多机制。每个关卡教一个机制，然后再组合。
- **动画中接受输入** → 双重移动/腐败。直到棋盘稳定锁定输入。

## 组合（从这些技能构建）

- **棋盘渲染：** `godot-tilemap` / `unity-tilemap-2d` 用于网格；`godot-ui-control` 用于HUD、分数和菜单。
- **关卡：** `level-design` 用于手工编写解谜和难度节奏；`procedural-gen` 用于可解的生成棋盘。
- **持久化：** `save-systems` 用于关卡进度、最高分和种子每日解谜。
- **juice：** `game-feel` 用于匹配/级联爆炸、屏幕震动和链式反馈；引擎动画/`Tween` 技能用于交换/下落/清除；`audio-design` 用于匹配和链式提示音。
- **脚本：** `godot-gdscript` / `unity-csharp-scripting` 用于解析循环和规则。
