# 快速原型

快速将一个机械交给玩家，以判断是否值得构建。原型的输出是一个**决策**（保留/删除/重构），而不是一个产品。优化学习速度，并在一开始就决定代码是废弃型还是承载型。

## 使用时机

- 当验证单个机械或“如果怎样”，构建垂直切片/MVP，灰盒化关卡或交互，或在投入真实时间前降低风险时使用。
- 当用户说“随便弄点可玩的”，“这好玩吗？”或“粗制滥造一下”时使用。

**不使用时机：** 有时间限制的竞赛，有截止日期和提交要求（使用`game-jam`）；发布或更新真实版本（使用`steam-publish` / `itch-publish`）；构建已验证功能的正式版本（直接使用引擎/流派技能）。

## 核心工作流程

1. **提出一个问题。** 明确原型必须回答的单个问题，例如
   *"在坠落时使用抓钩是否令人满意？"* 如果你有两个问题，构建两个原型。一个测试所有内容的原型什么也测不到。
2. **在编写代码前决定废弃型还是保留型。** 废弃型（*spike*）：硬编码，无架构，删除后。保留型：仍然粗糙，但有可扩展的文件夹/名称。大多数原型应该是废弃型；假装否则原型会腐化成发布代码库。
3. **设置一个硬性时间限制**（30-90分钟用于一个机械；一次会话用于一个切片）和一个可见的计时器。约束就是要点——它迫使你测试*核心*概念，而不是装饰。
4. **灰盒化所有非必要元素。** 艺术（盒子、圆形、胶囊）、内置字体、一个调试声音或没有声音。在问题不依赖的任何内容上花费零分钟。
5. **针对问题进行测试。** 添加屏幕上的调试文本/小工具，显示你正在评判的内容（速度、距离、时间窗口）。你在测量，而不是装饰。
6. **立即并诚实地进行测试。** 自己玩一下，然后交给另一个人，不要解释控制方式。观察他们在哪里遇到困难。
7. **根据你的删除标准（见下文）做出决定。** 保留 → 安排真实构建和*重写*，不要提升spike。删除 → 记录教训并继续。重构 → 缩小问题范围并再次spike。

## 模式

### 1. 原型简报（在编码前填写）

```text
问题：     这个必须证明的一件事（如果可能，二元的）。
核心动词：  玩家重复的单个动作。
废弃型？：  是 -> 自由硬编码，删除后。  否 -> 最小结构以供扩展。
时间限制：  例如60分钟。当它响时停止，即使未完成。
保留条件：  可观察的信号，表示“好玩/值得构建”（见删除标准）。
删除条件：  可观察的信号，表示“停止”。
```

### 2. 灰盒化核心循环，伪造其他所有内容（与引擎无关的伪代码）

```text
# 只有CORE VERB是真实的。视觉效果是基本元素；系统是桩件。
on update(dt):
    read_input()
    apply_core_mechanic(dt)        # 你正在测试的唯一东西——让这个感觉对
    draw_primitive(player)         # 一个盒子。不是精灵。不是动画的。
    draw_debug_hud(speed, timing)  # 显示你正在评判的数字
    # 敌人、菜单、保存、音频、艺术 -> 桩件或缺失，直到verb验证成功
```

### 3. 删除标准——使保留/删除的判断可观察，而不是情绪化

```text
保留当，使用占位符艺术：
  - 新玩家在~30秒内故意执行核心动词，未经提示，并且
  - 你（或他们）在没有被要求的情况下重复循环“再来一次”。
删除当：
  - 动词只有在解释后才感觉良好，或者
  - 让它好玩需要超出原型范围的系统，或者
  - 你添加艺术/关卡来避免承认动词很平淡。
重构当一个变量明显不对（太慢，窗口太紧）-> 重新调整，重新测试。
```

### 4. 包容性：将spike与发布代码库分开

```text
prototypes/<idea-name>/      # 分隔的文件夹或项目，永远不会被主游戏导入
  - 硬编码值，单个文件可以，魔法数字受欢迎
  - 在一个废弃分支上提交（或根本不提交）
规则：“保留”决定授权在真实项目中重写，而不是复制粘贴spike。原型代码带有原型假设；发布它就是发布假设。
```

## 陷阱

- **过早打磨。** 艺术、菜单和音频使一个平淡的机械看起来完成并延迟了判断。直到verb被证明前灰盒化。
- **没有删除标准。** 没有书面的“删除如果”，每个原型“有潜力”，并且什么也没被删除。在依赖代码之前决定信号。
- **构建系统而不是机械。** 发货、保存/加载和设置不是问题。桩件它们。
- **spike变成了产品。** 废弃型代码提升到生产是带有有趣起源故事的技术债务。在保留上重写。
- **在真实代码库中原型。** 它将实验与发布系统缠绕在一起，并使删除spike变得昂贵。使用一个分隔的文件夹/项目。
- **只测试自己。** 你知道控制和意图。一个未经指导的外部玩家在两分钟内揭示的比一小时自我测试更多。

## 参考

- 对于在硬性外部截止日期和提交下工作，请阅读`game-jam`技能。
- 对于你将在其中灰盒化的引擎特定核心循环，请阅读该引擎的技能
  (`godot-gdscript`, `phaser-core`, `love2d-core`, `unity-csharp-scripting`, …)。

## 相关技能

- `game-jam` — 应用于有时间限制的竞赛和提交的相同范围纪律。
- 引擎核心和流派技能 — “保留”决定将在哪里正确重建。
