# 性能优化

> **第 2 层：设计选择**

## 核心问题

**瓶颈在哪里，以及优化是否值得进行？**

在进行优化之前：
- 你是否已经进行了测量？（不要靠猜测）
- 可接受的性能标准是什么？
- 优化会增加复杂度吗？

---

## 性能决策 → 实现

| 目标 | 设计选择 | 实现 |
|------|---------------|----------------|
| 减少内存分配 | 预分配，复用 | `with_capacity`，对象池 |
| 改善缓存 | 连续数据 | `Vec`，`SmallVec` |
| 并行化 | 数据并行 | `rayon`，线程 |
| 避免复制 | 零拷贝 | 引用，`Cow<T>` |
| 减少间接引用 | 内联数据 | `smallvec`，数组 |

---

## 思考提示

在进行优化之前：

1. **你是否已经测量过？**
   - 先进行性能分析 → flamegraph, perf
   - 基准测试 → criterion, cargo bench
   - 识别实际的热点

2. **什么是优先级？**
   - 算法（10x-1000x 的提升）
   - 数据结构（2x-10x）
   - 内存分配（2x-5x）
   - 缓存（1.5x-3x）

3. **权衡是什么？**
   - 复杂度 vs 速度
   - 内存 vs CPU
   - 延迟 vs 吞吐量

指向领域约束（第 3 层）：

```
"这需要多快？"
    ↑ 询问：性能 SLA 是什么？

    ↑ 检查：业务需求（可接受的响应时间）
```

| 问题 | 追溯至 | 询问 |
|----------|----------|-----|
| 延迟要求 | domain-* | 可接受的响应时间是多少？ |
| 吞吐量需求 | domain-* | 每秒多少请求？ |
| 内存约束 | domain-* | 内存预算是多少？ |

## 向下追溯 ↓

指向实现（第 1 层）：

```
"需要减少内存分配"
    ↓ m01-ownership: 使用引用，避免 clone
    ↓ m02-resource: 使用 with_capacity 预分配

"需要并行化"
    ↓ m07-concurrency: 选择 rayon 或线程
    ↓ m07-concurrency: 考虑 I/O 密集型使用异步

"需要缓存效率"
    ↓ 数据布局：在可能的情况下优先使用 Vec 而非 HashMap
    ↓ 访问模式：顺序访问优于随机访问
```

## 优化优先级

```
1. 算法选择     (10x - 1000x)
2. 数据结构       (2x - 10x)
3. 减少内存分配 (2x - 5x)
4. 缓存优化   (1.5x - 3x)
5. SIMD/并行     (2x - 8x)
```

## 常见技术

| 技术 | 何时使用 | 如何实现 |
|-----------|------|-----|
| 预分配 | 已知大小 | `Vec::with_capacity(n)` |
| 避免克隆 | 热点路径 | 使用引用或 `Cow<T>` |
| 批处理操作 | 大量小型操作 | 收集后再处理 |
| SmallVec | 通常较小 | `smallvec::SmallVec<[T; N]>` |
| 内联缓冲区 | 固定大小数据 | 使用数组而非 Vec |

---

## 常见错误

| 错误 | 为什么错误 | 更好的做法 |
|---------|-----------|--------|
| 未进行性能分析就优化 | 目标错误 | 先进行性能分析 |
| 在调试模式下进行基准测试 | 没有意义 | 始终使用 `--release` |
| 使用 LinkedList | 对缓存不友好 | `Vec` 或 `VecDeque` |
| 隐藏的 `.clone()` | 不必要的内存分配 | 使用引用 |
| 过早优化 | 浪费精力 | 先让它工作起来 |

---

## 反模式

| 反模式 | 为什么不好 | 更好的做法 |
|--------------|---------|--------|
| 克隆以规避生命周期 | 性能成本 | 正确的所有权 |
| 一切皆 Box | 间接引用成本 | 尽可能使用栈 |
| 对小集合使用 HashMap | 开销大 | 使用带线性搜索的 Vec |
| 循环中拼接字符串 | O(n^2) | `String::with_capacity` 或 `format!` |
