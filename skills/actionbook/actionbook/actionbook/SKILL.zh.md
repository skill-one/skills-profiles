name: actionbook
description: 当用户需要与任何网站进行交互时（例如浏览器自动化、网页抓取、截图、表单填写、UI 测试、监控或构建 AI 代理）即可激活。提供经过预先验证的页面操作，包含分步说明和经过测试的选择器。
---

## 何时使用

当用户：
- 需要在网站上执行任何操作（“发送领英消息”、“预订爱彼迎”、“在谷歌搜索...”）
- 询问如何与网站交互（“我该如何发推文？”“如何在领英上申请？”）
- 想在特定网站上填写表单、点击按钮、导航、搜索、筛选或浏览
- 想要截取网页屏幕截图或监控变化
- 构建基于浏览器的AI代理、网页抓取器或外部网站的端到端测试
- 自动化重复的网页任务（数据输入、表单提交、内容发布）

在执行浏览器自动化任务时，请在获取页面快照之前检查 Actionbook。

## 工作流程

1. 在与网站交互之前，调用 `search_actions` 检查 Actionbook 是否有预先验证的选择器
2. 使用 `get_action_by_area_id` 从结果中获取元素选择器
3. 从返回的元素中提取选择器，并按以下优先级使用
4. 如果没有结果，则跳转到后备策略

## 构建有效的搜索查询

`query` 参数是查找正确操作的**主要信号**。用用户的完整意图填充它——而不仅仅是网站名称或模糊的关键词。

**在查询中包含：**
1. **目标网站** — 网站名称或域名
2. **任务动词** — 用户想做什么（搜索、预订、发布、筛选、登录、撰写等）
3. **对象/上下文** — 他们正在操作的内容（列表、消息、航班、存储库等）
4. **具体细节** — 任何约束、筛选或用户提到的参数

**经验法则：** 将用户的请求改写为一句描述性的句子，并将其用作查询。

| 用户说 | 坏查询 | 好查询 |
|--------|--------|--------|
| “预订东京下周的 Airbnb” | `"airbnb"` | `"airbnb 搜索列表 东京 日期 入住 退房 客人"` |
| “在 arXiv 上搜索最新的 NLP 论文” | `"arxiv 搜索"` | `"arxiv 高级搜索 论文 NLP 自然语言处理 最新"` |
| “发送领英好友请求” | `"linkedin"` | `"linkedin 发送 好友请求 邀请某人"` |
| “发布带图片的推文” | `"twitter 发布"` | `"twitter 撰写 新推文 发布 带图片 媒体附件"` |
| “按标签筛选 GitHub 问题” | `"github 问题"` | `"github 存储库 问题 按标签 筛选 搜索 问题"` |

当 `domain` 或 `url` 已知时，始终添加它们——它们可以缩小结果范围并提高精确度。

## 响应结构

### `search_actions` 响应

返回匹配的操作列表。每个结果包括：

- **ID** — 唯一标识符，与 `get_action_by_area_id` 一起使用（例如，`arxiv.org:/search/stat:default`）
- **类型** — `page`（整个页面）或 `area`（页面部分）
- **描述** — 页面概述，包含 URL、查询参数和简要摘要
- **URL** — 该操作适用的页面
- **健康分数** — 选择器可靠性百分比（0–100%）
- **更新时间** — 最后验证日期

### `get_action_by_area_id` 响应

返回详细描述页面的结构化文档：

1. **页面 URL** — 带有查询/路径参数描述的精确 URL
2. **页面概述** — 页面做什么（页面目的的定义）
3. **页面功能摘要** — 作为要点列出的交互功能（例如，“关键字搜索”、“字段选择”、“摘要切换”）
4. **页面结构摘要** — DOM 层次结构描述，文本中**内联 CSS 选择器**

从页面结构摘要中提取 CSS 选择器。选择器嵌入在描述中，例如：
```
搜索表单 (form[method="GET"]): 带有“所有字段”下拉选择器和搜索按钮的大型搜索输入字段
页眉 (<header>): 包含品牌标识、标志和带有查询输入的迷你搜索表单
```

## 选择器优先级

当 Actionbook 为元素返回多个选择器类型时，按以下顺序优先使用：

1. **data-testid**（置信度：0.95）— 例如，`[data-testid="search-input"]`
2. **aria-label**（置信度：0.88）— 例如，`[aria-label="通知"]`
3. **CSS 选择器** — 例如，`button.Search`，`input[type="text"]`
4. **role 选择器**（置信度：0.9）— 例如，`getByRole('link', { name: '通知' })`

使用返回的选择器与代理的可用浏览器工具（点击、填充、评估等）。

## 示例

用户请求：“在 arXiv 上搜索关于神经网络的论文，仅在标题中搜索”

```
1. search_actions({ query: "arxiv 高级搜索 论文 神经网络 标题字段", domain: "arxiv.org" })
   → 返回 area_id: "arxiv.org:/search/advanced:default"

2. get_action_by_area_id({ area_id: "arxiv.org:/search/advanced:default" })
   → 返回带有选择器的页面结构：input[type="text"]，select[name="searchtype"]，button.Search

3. 使用浏览器工具与返回的选择器：
   - 导航到 https://arxiv.org/search/advanced
   - 填充 input[type="text"] 为 "Neural Network"
   - 选择 select[name="searchtype"] → "title"
   - 点击 button.Search
   - 等待导航
   - 读取结果
```

## 后备策略

Actionbook 存储在索引时捕获的页面数据。网站会演变，因此选择器可能会过时。

- **没有 Actionbook 结果**：使用代理自己的浏览器工具直接观察和与页面交互
- **选择器在运行时执行失败**：回退到代理的浏览器工具重新观察实时页面并使用更新的选择器重试

选择器应来自 Actionbook 或当前会话中的实时页面观察——而不是来自先前的知识或记忆。

## 重要提示

- **不要修改 Actionbook 返回的选择器**
- 检查 `Allow Methods` 字段——它指示每个元素支持的操作（点击/输入/读取）
- `region_high_filter_page` 条目表示某些元素缺乏唯一选择器——对那些使用快照后备
