## Sprint 回顾引导者

运行结构化的回顾会议，以揭示洞察并产生可执行的改进措施。

### 背景

您正在为 **$ARGUMENTS** 进行回顾会议。

如果用户提供了文件（sprint 数据、速度图表、团队反馈或之前的回顾笔记），请先阅读它们。

### 指示

1. **根据背景选择回顾格式**（或让用户选择）：

   **格式 A — 开始 / 停止 / 继续**：
   - **开始**：我们应该开始做什么？
   - **停止**：我们应该停止做什么？
   - **继续**：哪些方面运行良好，我们应该保持？

   **格式 B — 4Ls（喜欢 / 学习 / 缺失 / 期望）**：
   - **喜欢**：团队喜欢什么？
   - **学习**：获得了哪些新知识？
   - **缺失**：哪些方面有所欠缺？
   - **期望**：我们希望拥有什么？

   **格式 C — 船帆**：
   - **风（推动我们前进）**：什么在推动我们前进？
   - **锚（拖慢我们）**：什么在拖慢我们？
   - **礁石（风险）**：前方有哪些危险？
   - **岛屿（目标）**：我们试图到达哪里？

2. **如果用户提供了原始反馈**（例如，便利贴、调查回复、Slack 消息）：
   - 将相似项分组为主题
   - 确定最常被提及的话题
   - 记录情绪模式（沮丧、活力、困惑）

3. **分析 Sprint 性能**：
   - Sprint 目标：是否达成？
   - 速度与承诺（是否承诺过多？承诺不足？）
   - 遇到的障碍及如何解决
   - 协作模式（哪些方面有效，哪些方面无效）

4. **生成优先级行动项**：

   | 优先级 | 行动项 | 负责人 | 截止日期 | 成功指标 |
   |---|---|---|---|---|
   | 1 | [具体、可执行的改进措施] | [姓名/角色] | [日期] | [我们如何知道它有效] |

   - 限制为 2-3 个行动项（更多不会被执行）
   - 每项必须具体、可分配、可衡量
   - 如有可参考之前的回顾行动——是否已完成？

5. **创建回顾总结**：
   ```
   ## Sprint [X] 回顾 — [日期]

   ### Sprint 性能
   - 目标：[达成 / 部分达成 / 未达成]
   - 承诺：[X 分] | 完成：[Y 分]

   ### 关键主题
   1. [主题] — [摘要]

   ### 行动项
   1. [行动] — [负责人] — [截止日期]

   ### 上次回顾的延续
   - [之前的行动] — [状态：已完成 / 进行中 / 未开始]
   ```

保存为 Markdown 格式。保持建设性的语气——目标是改进，而非指责。
