## 版本说明生成器

将技术工单、产品需求文档（PRD）或内部变更日志转换为精炼、面向用户的产品版本说明。

### 背景

您正在为 **$ARGUMENTS** 编写版本说明。

如果用户提供了文件（JIRA导出、Linear工单、产品需求文档、Git日志或内部变更日志），请先阅读这些文件。如果用户提及产品URL，请使用网络搜索来了解产品及其目标受众。

### 指导步骤

1. **收集原始材料**：阅读所有提供的工单、变更日志或描述。提取以下内容：
   - 发生了什么变更（功能、改进或修复）
   - 影响哪些用户群体
   - 为什么这很重要（用户收益）

2. **对变更进行分类**：
   - **新功能**：全新的功能
   - **改进**：现有功能的增强
   - **修复问题**：已解决的问题
   - **不兼容变更**：需要用户采取行动的任何内容（迁移、API变更）
   - **弃用**：即将停止支持的功能

3. **按照以下原则撰写每个条目**：
   - 以用户收益为开头，而非技术变更
   - 使用平实语言——避免使用术语、内部代号或工单编号
   - 每个条目保持1-3句话
   - 如果用户提供了图片或截图，请包含在内

   **示例转换**：
   - 技术： "为仪表板API端点实现了Redis缓存层"
   - 面向用户： "仪表板现在加载速度提升至3倍，让您花费更少时间等待，更多时间分析。"

   - 技术： "修复了并发结账流程中的竞态条件问题"
   - 面向用户： "解决了在高流量时段部分订单可能失败的问题。"

4. **组织版本说明结构**：

   ```
   # [产品名称] — [版本号 / 日期]

   ## 新功能
   - **[功能名称]**：[1-2句话描述其作用及重要性]

   ## 改进
   - **[领域]**：[具体改进内容及其帮助]

   ## 修复问题
   - 修复了 [用用户术语描述的问题]

   ## 不兼容变更（如有）
   - **需要操作**：[用户需要做什么]
   ```

5. **调整语气**以匹配产品的声音——B2B产品需专业，消费级产品需友好，API产品需面向开发者。

保存为Markdown文档。如果用户需要HTML或其他格式，请相应转换。
