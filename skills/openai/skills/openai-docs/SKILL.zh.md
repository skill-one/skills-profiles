# OpenAI 文档

使用 developers.openai.com MCP 服务器提供来自 OpenAI 开发者文档的权威、最新的指导。"Docs MCP" 指的是 `mcp__openaiDeveloperDocs__search_openai_docs` 和 `mcp__openaiDeveloperDocs__fetch_openai_doc`；对于 API 参考、模式、参数或必填字段的问题，在可用时也使用 `mcp__openaiDeveloperDocs__get_openapi_spec`。在那些工具不可用或不适用时，使用官方域网络搜索作为后备。对于广泛的 Codex 问题，使用手动辅助程序在 Docs MCP 之前。此技能还拥有模型选择、API 模型迁移和提示升级指导。

## 工作流配置

### 源优先级

- 对于 Codex 自身知识，使用以下 Codex 源路线；它决定了何时使用手动辅助程序、Docs MCP 或有界不确定性。
- 对于非 Codex OpenAI 文档问题，使用 `mcp__openaiDeveloperDocs__search_openai_docs` 查找最相关的文档页面。
- 对于非 Codex OpenAI 文档问题，在回答之前使用 `mcp__openaiDeveloperDocs__fetch_openai_doc` 获取相关页面。如果搜索结果嘈杂，运行更窄的 Docs MCP 搜索；当知道或找到任何可能官方的 OpenAI 文档 URL 时，尝试通过 Docs MCP 获取该 URL，然后再依赖网络搜索内容。
- 对于 API 参考、模式、参数或必填字段的问题，在可用时使用 `mcp__openaiDeveloperDocs__get_openapi_spec` 来验证相关指南或参考页面的 API 形状。
- 仅在您需要浏览或发现没有明确查询的非 Codex 页面时，才使用 `mcp__openaiDeveloperDocs__list_openai_docs`。
- 对于模型选择、“最新模型”或默认模型问题，首先获取 `https://developers.openai.com/api/docs/guides/latest-model.md`。如果不可用，加载 `references/latest-model.md`。
- 对于模型升级或提示升级，仅在目标是最新/当前/默认或未明确指定其他情况时运行 `node scripts/resolve-latest-model-info.js`；否则保留明确请求的目标。
- 保留明确的目标请求：如果用户指定了目标模型，如“迁移到 GPT-5.4”，即使 `latest-model.md` 指定了一个更新的模型，也要保留该请求的目标。仅作为可选提及更新的指导。
- 如果需要当前的远程指导，直接获取返回的迁移和提示指南 URL。如果直接获取失败，使用 MCP/搜索后备；如果这也失败，使用捆绑的后备参考并披露后备。

## OpenAI 产品快照

1. Apps SDK：通过提供一个 Web 组件 UI 和一个暴露您的应用程序工具给 ChatGPT 的 MCP 服务器来构建 ChatGPT 应用程序。
2. Responses API：为代理工作流中的状态化、多模式、工具使用交互设计的统一端点。
3. Chat Completions API：从一个消息列表（构成对话）生成模型响应。
4. Codex：OpenAI 的软件开发代理，可以编写、理解、审查和调试代码。
5. gpt-oss：在 Apache 2.0 许可证下发布的 Open-weight OpenAI 推理模型（gpt-oss-120b 和 gpt-oss-20b）。
6. Realtime API：构建低延迟、多模式体验，包括自然语音到语音对话。
7. Agents SDK：用于构建代理应用程序的工具包，其中模型可以使用工具和上下文，转交给其他代理，流式传输部分结果，并保留完整跟踪。

## Codex 自身知识

用于 Codex 本身的问题：配置、扩展、操作、故障排除、本地状态、产品界面或 Codex 行为应存在于何处。仅提及插件、技能、钩子、MCP 服务器、浏览器或自动化的代码库是不够的。对于通用软件任务，直接回答软件任务；如果被问及 Codex 自身知识是否适用，简要回答该元问题并继续请求的工件。

### 源路线

Codex 手册是广泛 Codex 合成的第一个来源。将手册和 Docs MCP 视为不同的路径，而不是可互换的官方文档来源。对于已发布的用户 Codex 产品答案，源路线是完整的：手册、当此路线要求时 Docs MCP、官方 OpenAI 网络后备，以及在当前会话中关于该功能时显示的可调用功能。开发人员.openai.com 外部的知识库对于公共产品答案是不在此路线内的。

对于广泛的 Codex 行为、设置、定制、技能、插件、MCP、钩子、`AGENTS.md`、自动化、界面、本地状态或系统图问题：

1. 当它仍然新鲜时，重用同一线程的手册和轮廓路径。
2. 否则，在正常可写会话中首先运行技能本地辅助程序。在没有尝试的情况下跳过它，仅当会话是明确只读的、没有 shell 执行可用或可见策略显示没有允许的临时缓存时。
3. 默认情况下，辅助程序选择此顺序中的第一个可用的临时缓存目录：`$TMPDIR/openai-docs-cache`、`%TEMP%\openai-docs-cache`、`%TMP%\openai-docs-cache`、`/private/tmp/openai-docs-cache`，然后是 `/tmp/openai-docs-cache`。仅工作区写入访问不足以为此临时缓存提供权限。
4. 除非需要覆盖缓存目录，否则直接运行辅助程序。辅助程序在原生 `fetch` 不可用或存在代理环境变量时回退到 `curl`，因此不需要 shell 特定的代理前缀。解析 `<skill-dir>` 到此技能的实际目录；在复制的本地评估工作目录中，这通常是 `.codex/skills/openai-docs`：

```bash
node <skill-dir>/scripts/fetch-codex-manual.mjs
```

如果您需要覆盖缓存目录，请传递 `--cache-dir <cache-dir>`。在 Windows 上，辅助程序会自动检查 `%TEMP%` 和 `%TMP%`；在 PowerShell 中，`$env:TEMP\\openai-docs-cache` 是一个典型的显式覆盖。

将辅助程序的可用性视为由明确的只读/无 shell 策略或实际命令结果建立。猜测的沙盒或猜测的辅助程序失败不足以切换到 Docs MCP 或网络查找；在辅助程序实际命令失败后，继续到最窄的官方下一个来源。

辅助程序验证新鲜度，写入 `codex-manual.md`，并发出 `codex-manual.outline.md`。轮廓将源页面和标题映射到行范围；使用它来选择相关的手册部分，然后阅读或搜索目标手册部分以查找 Codex 产品事实。使用技能目录来定位和运行辅助程序；在辅助程序成功后，使用返回的手册和轮廓路径作为 Codex 产品事实和术语覆盖检查的搜索范围。

对于后续 Codex 问题，重用同一线程的手册和轮廓路径。当手册是在大约一天前获取的、路径不可用、路径来自其他线程或不确定来源，或可能当前的信息缺失且可能过时时，首先刷新。

对于关于手册是否足够当前以依赖的问题，在允许临时缓存时运行辅助程序，并根据其返回状态、手册路径和轮廓路径来回答。

如果手册解析了 Codex 声明，则从它回答并停止为该声明扩展其他来源；如果文档查找只是依赖项之一，则继续用户的更广泛任务。手册源页面和已知锚点足以作为手册覆盖材料的引用支持。

如果由于会话只读、没有 shell 执行或没有允许的临时缓存而跳过辅助程序，下一个来源是 Docs MCP：调用 `mcp__openaiDeveloperDocs__search_openai_docs`，然后对于相关命中使用 `mcp__openaiDeveloperDocs__fetch_openai_doc`，然后再任何网络后备之前。

如果用户命名了一个 Codex 术语或模式，而新鲜的手册不使用该术语，搜索手册以查找明显的相邻概念，然后回答该确切术语未记录，并使用最接近的记录术语。如果提示询问该术语如何映射到 Codex 行为，从相邻的手册部分解析映射。如果确切术语在手册通过后仍然重要或可能当前，使用一个窄 Docs MCP 搜索/获取，然后是有界不确定性；否则，该术语或映射声明的源查找完成。

仅在手册不可用、辅助程序失败、不允许临时缓存、另一个重要声明缺失或可能过时，或用户明确需要一个特定页面引用时，才使用最窄的官方下一个来源。优先考虑一个特定的 Docs MCP 搜索，如果它返回一个明显相关的页面，则执行一个获取；对于未解决的 Codex 能力名称、缩写、调度术语或确切错误文本，此 Docs MCP 步骤是网络搜索之前的下一个来源。在手册加上任何允许的 Docs MCP 间隙填充后，解决剩余的间隙作为有界不确定性。仅在 Docs MCP 路径不可用或不适用后，才使用官方域网络后备。如果声明仍然未建立，则使用有界不确定性。如果官方文档/手册与当前会话中已经显示的可调用能力冲突，请声明冲突，并优先考虑该环境已验证的当前行为。

对于未记录或看起来像私有的模型缩写、产品模式标签、权限标签、帐户访问路径或发布名称，从当前公共文档和有界不确定性中回答。这些标签不是离开公共来源路线的理由。

对于支持式诊断，优先考虑从手册逐层回答而不是提供特定于提供者的网络查找：安装/启用的插件、捆绑应用程序或连接器授权、MCP 设置、工作区/管理员策略、重启或新线程预期，然后如果仍然未解决，则使用支持或反馈。

如果源路线仍然无法建立声明，则返回有界不确定性或路由到支持、管理员或产品反馈，而不是扩大调查。

对于未解决的产品术语，从手册加上允许的官方下一个来源中回答。如果这些来源无法建立该术语，则从这些来源中有界不确定性地回答。

### 界面映射

当 Codex 名词或持久指令界面重叠时，推荐与范围匹配的最小界面：

- 提示或线程上下文 -> 一次性任务约束。
- `AGENTS.md` -> 持久存储库约定、命令、验证步骤和审查预期；更嵌套的文件在其子树下适用。
- 项目 `.codex/config.toml` -> 受信任存储库 Codex 设置，如沙盒、MCP、钩子、模型或推理默认值。
- 全局配置或全局指导 -> 跨存储库的个人默认值。
- 技能 -> 可重用的任务工作流，带有引用或脚本。
- 插件 -> 可安装的捆绑包，包含技能加上命令、工具、MCP 配置、钩子、资源、应用程序或市场元数据。
- MCP 服务器或应用程序连接器 -> 活动外部数据/操作或授权的私有应用程序/工作区数据。使用连接器代替网络搜索或模型内存来处理私有 Google Docs、日历、Slack、GitHub、Notion 和类似数据。
- 自动化 -> 定时检查、提醒、监控或后续工作；在现有线程中重要时使用线程心跳。
- 钩子 -> 围绕工具调用、命令或文件编辑的生命周期强制执行。

拆分混合范围请求，而不是强迫一个答案。示例：“始终执行 X，但仅为此 PR” 默认为当前运行提供提示/线程上下文；如果它应该持久，则使用 `AGENTS.md` 或项目配置，仅当它应该机械执行时使用钩子，并且仅当它应该是计划或后续工作时使用自动化。

在需要时使用此快速产品映射：CLI 是终端优先的本地存储库工作；IDE 扩展是编辑器附加的编码；Codex 应用程序是桌面规划、审查和交互工作；云/网络是托管并行/卸载工作；浏览器使用/应用程序浏览器是 Codex 控制的网络测试；Chrome 扩展使用用户的 Chrome 配置文件；计算机使用控制桌面应用程序和操作系统 UI。保持 `config.toml` 默认值、`requirements.toml` 约束和管理/管理员策略分开。

### 边界和输出

- API 密钥认证不意味着 ChatGPT、云任务或连接器访问。对于插件/应用程序认证失败，检查捆绑包可用性、插件安装/启用状态、连接器/应用程序授权、MCP 设置、重启/刷新预期、工作区策略和每个界面可用性，然后再回答。
- 沙盒或网络拒绝需要具有明确理由的范围升级。破坏性命令、工作区外写入或广泛访问更改需要明确批准。
- 内存可以提供用户偏好或上下文，但明确的提示指令优先，内存不是当前外部事实的来源。
- 对于肯定的界面选择答案，使用此形状：建议、原因、避免什么，以及使用的手册/来源证据。
- 当实际需要特定 Codex 引用时，这些锚点通常适用：`concepts/customization#agents-guidance` 对于 `AGENTS.md`，`concepts/customization#skills` 对于技能，`plugins/build#plugin-structure` 对于插件，`concepts/customization#mcp` 对于 MCP，`config-advanced#hooks` 对于钩子，`app/automations#thread-automations` 对于线程自动化，以及 `config-reference#configtoml` 对于配置。

## 如果 MCP 服务器缺失

如果 MCP 工具失败或没有 OpenAI 文档资源可用：

1. 自己运行安装命令：`codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp`
2. 如果由于权限/沙盒原因失败，立即使用提升权限重试相同的命令，并包括一句批准的理由。
3. 仅在提升尝试失败时才要求用户运行安装命令。
4. 要求用户重启 Codex。
5. 重启后重新运行文档搜索/获取。

## 工作流

1. 确认请求是通用文档查找、模型选择、模型字符串升级、提示升级指导还是更广泛的 API/提供者迁移。
2. 对于 Codex 自身知识请求，遵循上述 Codex 自身知识源程序。
3. 对于模型选择或升级请求，当用户请求最新/当前/默认指导时，优先考虑当前远程文档而不是捆绑参考。
   - 获取 `https://developers.openai.com/api/docs/guides/latest-model.md`。
   - 找到最新模型 ID 和明确的迁移或提示指导链接。
   - 优先考虑来自最新模型页面的明确链接，而不是派生 URL。
   - 对于明确命名的模型请求，保留请求的模型目标。仅作为可选提及更新的远程指导。
   - 对于动态最新/当前/默认升级，运行 `node scripts/resolve-latest-model-info.js`，然后在可能的情况下直接获取返回的指南 URL。
   - 如果直接指南获取失败，使用开发者文档 MCP 工具或官方 OpenAI 域网络搜索来查找相同指南内容。
   - 如果远程文档不可用，使用捆绑的后备参考，并说明使用了后备指导。
4. 对于模型升级，保持更改狭窄：仅在安全时更新活动的 OpenAI API 模型默认值和直接相关的提示。
5. 除非用户明确要求升级，否则保留历史文档、示例、评估基线、固定装置、提供者比较、提供者注册表、价格表、别名默认值、低成本后备路径和模糊的旧模型使用。
6. 除非用户明确要求，否则将 SDK、工具、IDE、插件、shell、认证和提供者环境迁移排除在模型和提示升级之外。
7. 如果升级需要 API 界面更改、模式重绕、工具处理程序更改或超出字面模型字符串替换和提示编辑的实现工作，则报告为受阻或需要确认。
8. 对于通用文档查找，从 2-6 个基本术语的紧凑、标题般的搜索查询开始。不要将完整的用户问题转换为关键字列表。获取需要的最佳页面和确切部分，并使用简洁的引用回答。

- `https://developers.openai.com/api/docs/guides/latest-model.md` -> 当前模型选择和“最佳/最新/当前模型”问题。
- `scripts/fetch-codex-manual.mjs` -> 当前Codex手册获取、验证、本地临时缓存和提纲生成。
- `https://developers.openai.com/codex/codex-manual.md` -> 当前Codex自我知识综合，包括设置、定制、技能、插件、MCP、钩子、`AGENTS.md`、自动化和表面行为；通常通过辅助路径和目标文件读取（当临时缓存可用时）访问。
- `references/latest-model.md` -> 模型选择和“最佳/最新/当前模型”问题的捆绑后备。
- `references/upgrade-guide.md` -> 模型升级和升级规划请求的捆绑后备。
- `references/prompting-guide.md` -> 提示重写和提示行为升级的捆绑后备。

## 质量规则

- 将OpenAI文档视为事实来源；避免推测。
- 对于Codex自我知识，遵循上述来源路径，而不是依赖记忆中的行为。
- 保持迁移变更范围狭窄且行为保持一致。
- 尽可能选择仅提示升级。
- 避免编造定价、可用性、参数、API变更或破坏性变更。
- 保持引言简短并在政策限制内；优先使用引用进行释义。
- 如果多个页面存在差异，指出差异并引用两者。
- 如果官方文档和验证的当前会话行为不一致，在做出广泛声明或编辑前说明冲突。
- 如果文档未涵盖用户需求，请说明并提供下一步操作建议。

## 工具说明

- 对于OpenAI相关的markdown文档，优先使用MCP文档工具，而不是网络搜索。Codex手册流程是例外：对于广泛的Codex综合，遵循Codex自我知识来源程序。
- 如果MCP服务器已安装但返回无意义结果，则使用网络搜索作为后备。
- 当退回到网络搜索时，仅限于官方OpenAI域名（developers.openai.com, platform.openai.com）并引用来源。
