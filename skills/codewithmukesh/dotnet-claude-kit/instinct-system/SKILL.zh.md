# 本能系统

一个学习系统，三个层级。Claude在工作中接收到的每一个信号——一个观察到的模式、一个用户纠正、一个惊人的发现——都会被路由到其中一个存储中。

## 核心原则

1. **三个层级，一个路由决策** — *本能*是未经证实的假设（`.claude/instincts.md`）。*纠正*是用户确认的规则（`MEMORY.md`）。*发现*是对世界的洞察（`.claude/learning-log.md`）。规则规定行为；洞察描述行为；本能是待定的规则。永远不要混淆层级——MEMORY.md中的假设会污染永久知识，而作为本能保留的确认规则会被遗忘。

2. **本能是假设，不是规则** — 本能始于单一观察的猜测，在确认之前没有权威性。"一个处理器使用`sealed`"是一个0.3的本能；"所有12个处理器使用`sealed`"是一个0.9的规则。置信度（0.3–0.9）驱动行为：0.3置信度记录，0.5置信度提及，0.7置信度遵循，0.9置信度推广。

3. **用户纠正是一个置信度为满的确认本能** — 当用户纠正你时，完全跳过确认周期。泛化教训，立即在MEMORY.md中捕获它，并确认捕获的内容。纠正今天花费用户30秒，但节省未来所有会话的时间——失去一个是最昂贵的错误。

4. **项目范围，永不全局** — 在一个代码库中成立的东西，在另一个代码库中可能错误。本能按项目存在；项目之间的转移通过导出/导入进行，并伴随置信度衰减，永不以满置信度转移。

5. **会话开始时审查，定期修剪** — 在编写任何代码之前，阅读MEMORY.md并加载置信度0.7+的本能；扫描最近的工作区域的日志条目。未审查的知识是浪费的努力。当三个存储膨胀时，审计所有三个存储——过时的本能、重复的规则和未审查的日志会失去作用。

## 模式

### 层级路由

| 信号 | 目的地 | 寿命 |
|------|--------|------|
| 观察到的模式，尚未确认（“我认为它们总是...”） | `.claude/instincts.md`在0.3 | 直到推广或丢弃 |
| 用户纠正（“不，使用X”，“不要那样做”，“记住这个”） | `MEMORY.md`立即，泛化 | 直到被证明错误 |
| 本能达到0.9置信度 | 推广到`MEMORY.md`，从本能中移除 | 永久 |
| 非明显的发现（错误根本原因、陷阱、解决方案、性能发现） | `.claude/learning-log.md` | 3–6个月，然后存档或推广 |
| 三次或更多次记录相同的陷阱 | 推广到`MEMORY.md`作为预防性规则 | 永久 |
| 会话状态（完成/待处理） | 通过总结交接——不是这个系统 | 直到下一个会话 |

### 本能生命周期（观察-假设-确认）

```
1. 观察到     — "这个处理器是内部`sealed`类。惯例？"
2. 假设      — 写入`.claude/instincts.md`在置信度0.3：
                 - 在处理器类上使用`sealed` | 置信度：0.3 | 看到：1 | 最后：2026-06-12
3. 寻找      — 主动检查2-3个相关文件（find_symbol，get_public_api）。
                 被动观察是不够的。
4. 调整      — 确认：根据调整跟踪提高。
                 相矛盾：置信度减半，记录例外。
                 混合：保持稳定，记录分歧。
5. 推广      — 达到0.9时，提供证据并提议推广到MEMORY.md。
```

### 本能存储格式

`.claude/instincts.md`按类别分组，带有结构化元数据：

```markdown
# 项目本能

## 代码风格 [0.7]
- 在所有处理器类上使用`sealed` | 置信度：0.8 | 看到：5 | 最后：2026-06-12
- 私有字段以下划线前缀 | 置信度：0.5 | 看到：2 | 最后：2026-06-10

## 架构 [0.7]
- 功能文件夹使用单数名称 | 置信度：0.7 | 看到：4 | 最后：2026-06-12
```

类别标题`[0.7]` = 平均置信度。标准类别：代码风格、架构、命名、测试、数据访问、API设计、配置、性能、工具。

### 置信度调整规则

没有临时评分。请严格按照以下步骤操作：

```
确认：  第一个观察→0.3 | 第二个→0.5 | 第三个→0.7 | 第四个→0.8
               第五个+没有矛盾→0.9（推广候选）

矛盾：  任何矛盾→当前置信度减半（0.7→0.35）
               连续两个→0.1（实际上已死亡）

用户覆盖： 明确确认→0.8 | 明确纠正→0.0（移除，
               在MEMORY.md中捕获） | "有时"→限制在0.5

陈旧性：  10+会话没有观察→标记审查
               矛盾，未确认5会话→移除
```

### 根据置信度采取行动的本能

```
0.0–0.2 → 忽略  — 证据不足，不要提及
0.3–0.4 → 记录   — 内部记录，不应用
0.5–0.6 → 提及   — "这个项目可能使用[pattern]。遵循吗？"
0.7–0.8 → 遵循   — 默认应用，第一次使用时提及
0.9     → 推广   — 提议添加到MEMORY.md作为永久规则
```

永远不要无声地应用置信度低于0.7的本能。

### 纠正捕获流程（层级2）

当用户纠正你的输出（“不，用X代替”，“我们不那样做”，“总是/从不做X”，“记住这个”）：

```
1. 检测      — 识别纠正信号。
2. 确认      — "明白了——HybridCache而不是IMemoryCache。"
3. 泛化      — 具体化："在订单端点不要使用IMemoryCache"
                 泛化："始终使用HybridCache而不是IMemoryCache——
                        防止stampede + L1/L2开箱即用。"
                 询问：这是否仅限于这个文件？这个层？底层原理是什么？
                        存储最广泛的正确陈述。
4. 检查      — 扫描MEMORY.md查找重叠。更新现有规则，而不是添加几乎重复的规则。
5. 存储      — 在正确的类别下写入，一行，理由在短横线后。
               如果存在匹配的本能，则移除它——它刚刚毕业。
6. 确认      — "添加到Memory > 数据访问：HybridCache而不是IMemoryCache。"
```

MEMORY.md格式——与本能相同的类别，每行一个可操作的规则：

```markdown
## 数据访问
- 始终使用HybridCache而不是IMemoryCache — 防止stampede + L1/L2
- 从不使用仓库模式而不是EF Core — 直接使用DbContext
```

### 发现记录（层级3）

立即将有机发现记录到`.claude/learning-log.md`——立即写入的两行条目比稍后重建的段落更优。条目格式：

```markdown
## 2026-06-12 | 陷阱 | MassTransit消费者注册顺序很重要
多个消费者针对一个消息类型按注册顺序运行；如果第一个抛出，其余的将被跳过。导致遗漏审计事件。
**文件：** `src/Shared/Extensions/MassTransitConfig.cs:15-30`
**解决方案：** 独立消费者端点或重试过滤器。
```

在（并且只有当）你遇到以下触发器时记录：

```
错误根本原因        — 原因不在错误出现的地方
架构决策            — 发现了为什么某事是这样构建的
陷阱                — 框架/库表现出乎意料
性能发现            — 意外的性能行为，附带测量
模式发现            — 值得记住的可重用代码库模式
外部服务            — 第三方API的行为与文档不同
```

这六个触发器名称也是类别词汇——在条目中直接使用它们。常规变化没有任何意外的事情不会记录。

### 会话开始时加载

```
1. 阅读MEMORY.md — 主动应用规则，不要等待提醒
2. 阅读`.claude/instincts.md` — 加载0.7+作为默认值，记录0.5–0.6
3. 扫描最近的学习日志条目，针对你正在工作的区域
4. 标记过时的本能（10+会话没有观察）以供审查
```

## 模式

三个对本能存储的操作，通过名称或触发短语调用。

### 状态（“显示本能”，“你学到了什么”，“列出本能”）

1. 读取`.claude/instincts.md`；解析每个条目的元数据。
2. 按置信度降序排序，按类别分组，以表格形式呈现：
   本能 | 置信度 | 类别 | 状态（新 / 稳定 / 加强 / 衰减 / 推广候选）。
3. 总结健康状况：总数，平均置信度，最近加强与衰减的条目，任何冲突的本能。

### 导出（“导出本能”，“分享本能”）

1. 读取`.claude/instincts.md`；过滤置信度>0.7（阈值可配置）。
2. 脱离项目特定上下文（文件路径，行号），同时保留模式本身。
3. 写入`.claude/instincts-export.md`，带有可移植元数据。
4. 报告导出内容和被跳过的内容（低于阈值），以及输出路径。

### 导入（“导入本能”，“从加载本能”）

1. 读取导出文件（用户提供的路径或`.claude/instincts-export.md`）和当前的`.claude/instincts.md`。
2. 合并每个导入的本能：
   - **没有本地匹配** — 添加置信度衰减0.2（0.9→0.7）；永不导入超过0.7。标记`来源：从[项目]导入`。
   - **存在匹配的本能** — 保留更高的置信度，标记加强。
   - **存在冲突的本能** — 向用户展示两者以供解决；不要自动覆盖本地证据。
3. 写入合并结果并报告导入/合并/冲突。每个项目都必须本地确认导入的模式。

## 反模式

### 过度积极的模式识别

```
# 坏的 — 第一个观察被视为规则
*读取一个处理器* "这个项目总是使用内部`sealed`类。"
*生成5个处理器，与9个现有的一致性矛盾8个*

# 好的 — 置信度0.3的假设，然后主动确认
"注意到`CreateOrderHandler`中的内部`sealed`。本能置信度0.3。
检查3个更多处理器..." *所有公共* → "已确认。丢弃。"
```

### 未经捕获的修复

```
# 坏的 — 修复应用，教训丢失
用户："不，这里使用HybridCache"
Claude: "修复。" *下一个会话：同样的错误*

# 好的 — 修复和捕获
Claude: "修复。添加到Memory > 数据访问：
         始终使用HybridCache而不是IMemoryCache。"
```

### 记录所有内容

```
# 坏的 — 噪声条目
## 2026-06-12 | 模式发现 | 使用主要构造函数

# 好的 — 只有非明显的才值得记录
## 2026-06-12 | 陷阱 | 主要构造函数参数捕获为字段
声明一个同名的显式字段会警告但编译——两者可以无声地分化。
```

### 只写存储

```
# 坏的 — 3个月前有40个置信度0.3的本能；MEMORY.md有200行
  重复项；500行日志无人阅读
# 好的 — 定期审计：移除置信度低于0.2或10+会话过时的本能；
  合并/修剪过去50个规则的MEMORY.md；大约每20个日志条目，
  推广经常性发现并存档过时的。保持本能少于50个活跃条目。
```

## 决策指南

| 情景 | 操作 |
|------|------|
| 首次看到模式 | 置信度0.3的本能，检查2-3个相关文件 |
| 模式看到3+次，没有矛盾 | 提高到0.7，默认遵循 |
| 模式被矛盾 | 置信度减半，记录例外 |
| 用户说“我们总是做X” | 置信度0.8（用户确认） |
| 用户纠正你的代码 | 泛化→立即写入MEMORY.md；丢弃任何匹配的本能 |
| 用户说“记住这个” / “总是/从不” | 如声明捕获到MEMORY.md，泛化 |
| 相同的纠正给出两次 | 高优先级——规则没有被捕获或审查 |
| 关于一次性任务的纠正 | 不要存储——只有可重用模式 |
| 用户要求忘记一个规则 | 立即从MEMORY.md中移除 |
| 非明显的错误，陷阱，解决方案，性能惊喜 | 记录到learning-log，带有类别+文件 |
| 相同的陷阱记录3+次 | 推广到MEMORY.md作为预防性规则 |
| 置信度0.9的本能 | 提供证据，提议推广到MEMORY.md |
| 用户部分确认（“仅用于命令”） | 缩小范围，重置为0.5，重新确认 |
| 与另一个项目分享模式 | 置信度0.7+导出，导入时置信度衰减0.2 |
| 导入时冲突 | 向用户展示两者；永不自动覆盖 |
| 任何存储膨胀（50+条目/规则） | 审计：修剪死亡，合并重复，推广成熟 |
| 开始会话 | 加载MEMORY.md，置信度0.7+的本能，最近的日志条目 |
