# 复合刷新

对照当前代码库审计 `<root>/solutions/` 下的学习内容，根据证据支持采取维护操作，并提交完整的每份文档报告及已提交的变更。报告和修正后的文档集是交付物。只有当每份文档都可信赖时，存储库才能增加价值。

## 模式

**现在阅读 `references/modes.md`。** 它从参数中读取模式，并定义每种模式可以无监督应用的内容、陈旧标记回退、问题工具以及 `CONCEPTS.md` 的引导。

两种模式都遵循两条规则。记录失败的写入为 **推荐**，然后继续运行。并且通过主机阻塞工具或定义中引用的编号选项回退来提问，它永远不会静默地跳过。

## 价值透镜

普通刷新判断准确性：每份文档是否仍然真实且仍然独特。它永远不会因为存储库在其他地方声明知识而删除准确的文档。第二个判断，价值，仅在用户要求并确认时运行。它对照代码库读取整个范围，并可以删除准确的文档。

阅读该意图的调用参数：用户希望清理存储库，进行删减、修剪、升级或带到捕获栏，用任何措辞表达，而不是检查漂移。当意图存在时，在调查前陈述阅读内容并确认：

```text
您要求清理学习内容。您想要什么？
1. 删除或缩短代码库已解释的文档。当测试、代码注释或指令文件声明相同理由时，文档将被删除，并且每个删减都引用该文件。漂移也会被修复。范围：<scope>。
2. 仅修复漂移。陈旧路径和链接、重复文档以及代码不再支持的指南。不会删除任何准确的文档。
```

在选项 1 中，**在调查前阅读 `references/worth-audit.md`**；它添加了栏、证据规则和路由。在选项 2 中，或在意图不存在时，不要阅读该参考并不要应用其测试；准确性刷新是整个运行。非交互模式无法确认，因此 `references/modes.md` 声明推断意图在此处的行为。

## 产物根

当您首次组成 `<root>/solutions/` 路径时，解析 `<root>`。将解析的 `<root>/solutions/` 路径传递给任何子代理，而不是配置。每个子代理的生成都省略 `mode` 参数，因此用户的权限设置适用。

<!-- ce-docs-root:start -->
**在组成任何产物路径之前解析 CE 产物根 `<root>`。**

- **读取** `docs_root` 从 `<repo-root>/.compound-engineering/config.yaml` 仅 (`<repo-root>` = `git rev-parse --show-toplevel`)。不要从 `config.local.yaml` 读取它。未设置 -> `<root>` 是 `docs`，与之前完全相同。
- **验证** 设置值：一个相对存储库的目录，其真实路径（解析符号链接后）仍然在存储库内，并且既不是存储库根也不是在 `.git/` 下。否则以错误命名 `docs_root` 和值停止——永远不会回退到 `docs`。
- **使用** `<root>` 作为唯一的产物位置：如果不存在则创建它，使用此技能自己的子目录组成每个路径为 `<root>/<subdir>`，并且永远不会也读取 `docs`。
<!-- ce-docs-root:end -->

## 范围

候选者是 `<root>/solutions/` 下除 `README.md` 和 `_archived/` 下任何内容外的 `.md` 文件。匹配不到的提示永远不会扩大范围。**阅读 `references/scope.md`** 了解缩小策略、每种模式在遗漏时的行为、空存储库消息、分诊顺序以及每个操作附带清理的 README 行。

## 调查

**阅读 `references/investigate.md`** 了解陈旧维度、自动记忆规则、子代理角色和类别形状说明。

将每份学习内容与当前代码库检查，然后检查集合是否存在重叠、替代和矛盾。矛盾会主动误导，因此它优先于单个陈旧性。

知识轨道学习有时指向其命名或链接的指南文件，例如技能的 `SKILL.md`、运行手册或指令文件。仅比较学习内容命名的指南。永远不会在指南层搜索一个。

每个调查子代理的提示包含该参考的三个 **子代理提示** 条款原文。其中两个是搜索工具和自动记忆。第三是：

> 如果学习内容是知识轨道并命名或链接指南文件（技能的 `SKILL.md`、运行手册、根指令文件），读取该文件，当它声明不同的顺序或对同一程序的矛盾规则时，返回两个冲突的引用以及当前代码遵循哪一方——或者代码既不见证任何一方。仅读取学习内容命名的指南；不要搜索一个，也不要编辑它。

## 分类

每份文档恰好有一个结果：**保留**、**更新**、**整合**、**替换** 或 **删除**。文档永远不会原地归档：没有 `_archived/`，因为版本历史是归档。

**在分配任何结果前阅读 `references/classify.md`。** 它定义了每个结果的意义、更新/替换边界、自动删除规则及其预检查、迁移和拆分规则、检索值测试、无法验证不是错误、模式文档以及交互模式询问的内容。

两条边界遵循证据所说的内容。此技能永远不会更改产品代码。关于当前机制的声明遵循当前代码，但独立支持的指南不会仅仅因为实现停止满足它而变得错误：根据指南证据对文档进行分类，并报告实现冲突作为潜在的产品回归。并且当学习内容与指南矛盾时，刷新会报告；它必须永远不会编辑技能、运行手册或指令文件。

## 执行

阅读 `references/per-action-flows.md` 并遵循与每份文档分类匹配的节，每份文档一个流程。它定义了标准、迁移和拆分程序、替换子代理合同和引用清理。

## 词汇捕获

在每份文档操作后，将调查期间标记的领域术语与 `CONCEPTS.md` 进行协调。**无条件阅读 `references/concepts-vocabulary.md`。** 其限定标准不明显，因此未阅读它就达到“无任何资格”的判断是捷径，不是结果。

编辑在每种模式下都静默应用。报告的 `CONCEPTS.md` 行记录扫描发现的内容，包括“扫描，无合格术语”。

## 报告

**以 markdown 打印完整报告。** 它是交付物，而不是内部摘要，并且在非交互模式下它是唯一的。保持其自包含且永不缩写，分为 **已应用** 和 **推荐**。**阅读 `references/report.md`** 了解摘要块、每份文件的详细信息和属于推荐的内容。

## 提交

如果未更改则跳过。否则仅暂存此刷新修改的文件，并按存储库约定提交。**阅读 `references/commit.md`** 了解每种模式的分支决策和 git 失败回退。

## 可发现性检查

在报告后，检查项目指令是否会在文档区域工作前引导代理到 `<root>/solutions/`。每次都要这样做：只有当代理可以找到它时，存储库才能增加价值。**阅读 `references/discoverability.md`** 了解读者必须学习的内容、最小增量规则及其语气、`CONCEPTS.md` 变体、同意与每模式一条报告行，以及将后期编辑折叠到提交中。
