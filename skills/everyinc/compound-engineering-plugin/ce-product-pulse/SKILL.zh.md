# 产品脉搏

`ce-product-pulse` 查询指定时间窗口内的产品数据源，并生成一份紧凑的单页报告，涵盖使用情况、性能、错误和后续跟进。报告保存在 `<root>/pulse-reports/` 目录下，关键要点会在聊天中展示。

**已完成：** 在 `<root>/pulse-reports/YYYY-MM-DD_HH-MM.md` 存在 30-40 行的报告，其标题和顶部后续跟进内容会在聊天中显示，并且已达到阶段 3（调度）。

## 边界

- **只读，无处不在。** 该技能不会修改产品、数据库或任何外部系统。其唯一写入操作是追加到 `.compound-engineering/config.local.yaml` 的脉搏设置（面试和选择退出写入保留在本地覆盖文件中）和报告文件。MCP 和其他数据源工具以只读方式调用；如果某个工具提供写入模式，则不要使用它们。数据库源必须是只读连接——面试拒绝只读/写入凭证，并且 DB 访问是可选的，因为许多产品仅通过分析和跟踪即可完成脉搏检查。
- **保存的报告不包含个人身份信息。** 文件写入磁盘时，不包含任何用户电子邮件、账户 ID 或消息内容。
- **像创始人一样阅读。** 没有硬编码的阈值，没有默认的“好”/“坏”标签，没有告警：直接呈现数据，让读者自行判断。
- **单页。** 目标是 30-40 行。如果某个部分内容较少，就保持其简洁；如果报告过长，就进行裁剪。
- **不是发布日志或仪表板的替代品。** 已发布的工作存在于问题跟踪器和提交历史中。深度调查仍然使用原生工具；这个工具整合了单页阅读，并且每次运行都会保存，因此过去的脉搏可以按时间线浏览。

## 交互方式

默认使用当前工具列表中已有的主机阻塞式问题工具（按能力匹配，而不是按主机特定名称）。当前工具列表中的存在证明该工具可用；永远不要调用面向用户的问题工具来检查其是否存在。如果匹配的工具已列出但未加载，则使用主机的工具发现原语来加载该能力——不要搜索其他主机的工具名称。仅在列表中不存在此类工具或实际问题调用出错时，才回退到主机用户可见聊天界面的编号选项。永远不要无声地跳过问题。

一次只问一个问题。仅将多选保留用于首次运行配置。

## 回溯窗口

**回溯窗口**是指该技能被调用的指定时间范围（例如 `24h`、`7d`）——当前提示或对话中显示，无论用户直接提供还是调用技能传递。常见形式包括 trailing hours (`24h`、`48h`、`72h`)、trailing days (`7d`、`30d`)，以及用于发布的 `1h`。

如果参数为空，则默认使用配置中的 `pulse_lookback_default`（在阶段 0 中根据配置状态解析）；如果这也未设置，则回退到硬编码的默认值 `24h`。如果参数无法解析，则要求用户澄清。

对窗口的上限应用 **15 分钟 trailing buffer**。许多分析和跟踪工具存在数据摄入延迟；在 `now` 时刻直接查询会低估最近的事件。对于 `24h` 窗口，查询 `[now - 24h - 15m, now - 15m]`。

## 产物根目录

该技能在 `<root>/pulse-reports/` 下写入脉搏报告。在首次组合 `<root>/` 路径时解析 `<root>`（根据下方的块），在此之前永远不要使用它。写入 `<root>/...` 和读取 `<root>/solutions/` 都算作组合 `<root>/` 路径，因此任何一种都会触发解析；只有完全不触及任何 `<root>/` 路径的运行（仅临时或无代码库流程）会跳过解析。

<!-- ce-docs-root:start -->
**在组合任何产物路径之前，解析 CE 产物根 `<root>`。**

- **读取** `docs_root` 从 `<repo-root>/.compound-engineering/config.yaml` 仅（`<repo-root>` = `git rev-parse --show-toplevel`）。不要从 `config.local.yaml` 读取。未设置 -> `<root>` 是 `docs`，与之前一样。
- **验证** 设置的值：一个相对仓库的目录，其真实路径（解析符号链接后）仍然在仓库内，既不是仓库根目录，也不在 `.git/` 下。否则出错并命名 `docs_root` 和值——永远不要回退到 `docs`。
- **使用** `<root>` 作为唯一的产物位置：如果不存在则创建它，使用该技能自己的子目录组合每个路径为 `<root>/<subdir>`，并且永远不要再读取 `docs`。

## 阶段 0：根据配置状态路由

<!-- ce-config-layers:start -->
**从两个代码库文件解析普通 CE yaml 键。**

- **读取** `<repo-root>/.compound-engineering/config.local.yaml`，然后 `config.yaml`（`<repo-root>` = `git rev-parse --show-toplevel`）。跳过缺失的文件。Gitignore 不改变解析。
- **优先** 使用第一个活动的（非注释）值。对于标量，空值表示未设置；无效值继续到下一层，然后是技能默认值。对于列表和映射，存在的键——包括空列表或映射——将替换整个键。
- **不要** 使用此规则解析 `docs_root`——该键仅在 `config.yaml` 中。
<!-- ce-config-layers:end -->

使用 `git rev-parse --show-toplevel` 解析 `<repo-root>`，然后应用上述普通键规则到 `pulse_*` 键。每当需要解释 `pulse_*` 值时，读取 `references/config.md`——它是键模式，仅此而已：每个键、其允许值及其默认值，未设置或无效值采用文档中指定的默认值而不是猜测。

**路由：** 每次运行都通过阶段 2（运行脉搏）然后是阶段 3（调度）。当 `pulse_product_name` 在级联（上述普通键规则）后未设置时，当代码库根目录无法解析，或参数为 `setup`、`reconfigure` 或 `edit config` 时，首先运行阶段 1（首次运行面试）；否则从阶段 2（运行脉搏）开始。

## 阶段 1：首次运行面试

首先读取 `references/setup.md`；这是必需的。它定义了策略文档的种子、面试顺序及其回退栏、对读写数据库的拒绝、如何将配置写入 `config.local.yaml` 而不干扰其他键，以及一次性调度提议。问题本身来自 `references/interview.md`，该文件将其命名为自己的必需读取。

## 阶段 2：运行脉搏

如果阶段 1（首次运行面试）已运行，则在任何查询之前，使用原生文件读取工具重新应用从代码库根的普通键规则（本地然后跟踪），以获取在阶段 1 审查步骤中接受的编辑。否则使用阶段 0（根据配置状态路由）中提取的 `pulse_*` 值，对于未设置的任何内容，应用 `references/config.md` 中的默认值。

然后，在派发任何查询之前读取 `references/run.md`；这是必需的。它定义了并行运行和串行运行的查询、决定数据库工作是否运行的 `pulse_db_enabled` 检查、可选的质量采样及其评分规则、四个报告部分，以及报告的写入位置。

## 阶段 3：调度

设置提供一次性运行（`references/setup.md`）。在后续运行中，轻松提及它：如果参数是调度关键字（`daily`、`hourly`、`weekly`），则说明本次运行是临时的，并指向 harness 的调度原语；如果文件中没有调度且这是第三次或后续运行，则提及一次调度可用。不要在每次运行时都烦扰，并且永远不要自动调度——任何转向调度原语的转交都需要明确确认。
