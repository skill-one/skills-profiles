如果某个技能适用于你的任务，你没有选择。你必须使用它。

这不是可以协商的。你不能通过理性分析来逃避这一点。
</EXTREMELY-IMPORTANT>

## 规则

**在做出任何回应或采取任何行动之前——包括提出澄清问题、探索代码库或检查文件——调用相关的或请求的技能**。如果最终发现该技能不适用于当前情况，你不必使用它。

**在进入计划模式之前**：如果你还没有进行头脑风暴，首先调用头脑风暴技能。

然后宣布“使用[技能]来[目的]”，并严格按照技能的步骤执行。如果它有一个检查清单，为每个项目创建一个待办事项。

## 技能优先级

当多个技能适用时，处理技能优先级最高——它们设定方法，然后实现技能（如前端设计等）来执行。头脑风暴和系统化调试是Superpowers最常用的处理技能，但该规则适用于它们中的任何一种。

- “让我们构建X” → 首先使用superpowers:brainstorming，然后使用实现技能。
- “修复这个bug” → 首先使用superpowers:systematic-debugging，然后使用领域技能。

## 信号灯

这些想法意味着停止——你正在理性分析：

| 思想 | 现实 |
|------|------|
| “这只是一个简单的问题” | 问题就是任务。检查技能。 |
| “我需要更多的上下文” | 技能检查应在澄清问题之前进行。 |
| “让我先探索代码库” | 技能告诉你如何探索。先检查技能。 |
| “我可以快速检查git/文件” | 文件缺乏对话上下文。检查技能。 |
| “让我先收集信息” | 技能告诉你如何收集信息。 |
| “这不需要正式的技能” | 如果存在技能，使用它。 |
| “我记得这个技能” | 技能会发展。阅读当前版本。 |
| “这不算是任务” | 行动就是任务。检查技能。 |
| “技能过于复杂” | 简单的事情会变得复杂。使用它。 |
| “我先做这一件事” | 在做任何事情之前检查。 |
| “这感觉很有效率” | 不规范行动会浪费时间。技能可以防止这种情况。 |
| “我知道这意味着什么” | 知道概念 ≠ 使用技能。调用它。 |
