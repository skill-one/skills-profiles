# Earn Hunter

针对 OKX Flash Earn、Fixed Earn 和 Flexible Earn（Simple Earn）机会的自动化监控工具。

**`{baseDir}`** = 包含此 SKILL.md 文件的目录。所有相对路径（references/、templates/、config/）均从此处解析。

## 预检

1. 验证已安装 `okx` CLI：`which okx`。如果缺失，通过 `npm install -g @okx_ai/okx-trade-cli` 安装。
   在 OpenClaw 上，还需验证会话内的 `cron` 工具在代理工具列表中可用（用于调度——不是 `openclaw` CLI）。
2. 检查可选依赖技能：
   ```bash
   okx skill list --json
   ```
   可选技能（扫描/通知不需要）：
   - `okx-cex-earn` — 申购引导（订阅执行）所需
   - `okx-cex-auth` — 认证恢复所需

   如果任一缺失，尝试安装，但如果安装失败**不要阻止**：
   ```bash
   okx skill add okx-cex-earn
   okx skill add okx-cex-auth
   ```
   - 安装成功 → 继续
   - 安装失败（网络错误、市场不可用等） → **警告并继续**：
     "⚠ `{skill_name}` 安装失败，扫描和通知功能不受影响。申购引导和认证恢复需要该 skill，后续可手动安装。"
   - 无论技能安装结果如何，预检都会继续
4. 认证模式检测 —— 运行**两者**，首个匹配项生效：
   - `okx config show --json` → 有非空 `api_key` 字段 → **API Key 模式**。为所有命令添加 `--profile live`。
   - 无 API key + `okx auth status --json` → `"status":"logged_in"` → **OAuth 模式**。无需 `--profile` 标志。
   - 两者都不是 → **停止**。加载 `okx-cex-auth` 技能并遵循登录步骤。
5. 初始化配置和状态：
   - 如果 `~/.okx/earn-hunter/` 目录不存在 → `mkdir -p ~/.okx/earn-hunter`
   - 如果 `~/.okx/earn-hunter/config.json` 不存在 → 将 `{baseDir}/config/default.json` 复制到该位置
   - 如果 `~/.okx/earn-hunter/state.json` 不存在 → 写入 `{"flash":{},"fixed":{},"flexible":{},"consecutive_failures":0,"last_error":""}`
   - 如果 `~/.okx/earn-hunter/platform.json` 不存在 → 运行 [Platform Detection](#platform-detection-active-probe--user-confirmation)
   - 始终（重新）安装扫描脚本：`cp {baseDir}/scripts/scan.sh ~/.okx/earn-hunter/scan.sh && chmod +x ~/.okx/earn-hunter/scan.sh`。这是 cron 和交互式扫描都调用的脚本。
   - 将已解析的工具路径写入 `~/.okx/earn-hunter/env.snapshot`（cron 不能依赖用户的登录 PATH）：
     ```bash
     cat > ~/.okx/earn-hunter/env.snapshot << SNAP
     # auto-generated by earn-hunter activation — $(date -Iseconds)
     OKX_BIN=$(command -v okx)
     NODE_BIN=$(command -v node)
     JQ_BIN=$(command -v jq)
     ACTIVATION_PATH=$PATH
     SNAP
     ```
     扫描脚本会引入此文件以解析工具路径，即使在 cron 的最小 `PATH=/usr/bin:/bin` 环境下也是如此。

   代理对配置/状态/平台 JSON 的读写仅用于激活/配置管理。定期**扫描本身完全由 `scripts/scan.sh` 执行**（shell + jq）——扫描需要 `jq`。使用 `which jq` 验证；如果缺失，请安装（`brew install jq` / `apt-get install jq`）。

## 平台与渠道检测

三个独立维度：**平台**（代理运行的地方）、**调度器**（触发扫描的是什么）、**通知渠道**（警报发送到哪里）。

### 平台检测（主动探测 + 用户确认）

**首次运行（`platform.json` 不存在时）：**

1. 探测环境线索：
   - `OPENCLAW_HOME` 环境变量存在？ → 提示：OpenClaw
   - 代理工具列表包含 `cron` / `delivery` 工具？ → 提示：OpenClaw
   - `HERMES_HOME` 环境变量存在或 `which hermes` 成功？ → 提示：Hermes Agent
   - 在 Claude Code 会话中运行？ → 提示：Claude Code
   - 以上都不匹配 → 提示：Generic
2. 显示检测结果并**询问用户确认**：
   - "检测到你正在使用 **{detected_platform}**，是否正确？"
   - 用户确认 → 继续
   - 用户说否 → 询问："你使用的是哪个平台？1) OpenClaw  2) Claude Code  3) Hermes Agent  4) 其他"
3. 初始化平台配置：
   - OpenClaw / Claude Code → 将 `{baseDir}/config/<confirmed_platform>.default.json` 复制到 `~/.okx/earn-hunter/platform.json`
   - Hermes Agent → 将 `{baseDir}/config/claude-code.default.json` 作为基础复制，设置 `.platform` 为 `"hermes"`，`.scheduler.type` 为 `"cron"`
   - Generic → 将 `{baseDir}/config/claude-code.default.json` 作为基础复制，设置 `.platform` 为 `"generic"`，`.scheduler.type` 为 `"manual"`
4. 结果写入 `~/.okx/earn-hunter/platform.json`，后续运行跳过检测。

**后续运行（platform.json 存在时）：**
读取 `~/.okx/earn-hunter/platform.json` 并提取 `.platform` 字段（返回 `"openclaw"`、`"claude-code"`、`"hermes"` 或 `"generic"`）。

**检测到的平台没有可用的调度器**（仅适用于应该有但没有调度器的平台） → 错误："当前客户端不支持定时任务，请升级到最新版本。"
**Generic 平台** → 没有自动调度器。告知："当前平台不支持自动调度，你可以手动说'执行 earn-hunter 扫描'来触发。"

### 配置文件

| 文件 | 范围 | 内容 |
|---|---|---|
| `config.json` | 共享 | 扫描范围（flash/fixed/flexible）、货币、APY 阈值、条款、语言、verboseLog |
| `platform.json` | 特定平台 | 调度器类型/间隔、通知渠道、TG/Lark 凭据 |
| `state.json` | 共享 | 去重状态 |

核心配置（`config.json`）在各平台之间是相同的。平台配置（`platform.json`）有所不同 —— `scheduler.type` 字段决定了扫描是如何触发的：

**OpenClaw（`openclaw.default.json`）：**
- scheduler.type = `"openclaw-cron"` —— 通过会话内**`cron` 代理工具**进行调度（没有 OS crontab，没有 CLI 命令）。任务作为一个**隔离的、轻上下文**的代理轮次运行，并通过 cron **`announce`** 投递将输出返回到对话渠道。notify.channel 默认为 `"session"`，以便扫描输出到 stdout 供 `announce` 推送（避免重复发送）。

**Claude Code / Hermes / Generic（`claude-code.default.json`）：**
- scheduler.type = `"cron"` —— 通过 **OS crontab → `scripts/scan.sh`** 进行调度（零 LLM 令牌成本），通知通过脚本本身的 TG / Lark curl 发送。

### 通知渠道（独立于平台）

按优先级顺序检测（PRD 要求：TG 优先）：
1. **Telegram** — `$TELEGRAM_BOT_TOKEN` 和 `$TELEGRAM_CHAT_ID` 都已设置 → TG 就绪
2. **Lark** — `platform.notify.lark_webhook` 非空 → Lark 就绪
3. **Session** — 回退方案，仅在交互模式下有效

TG 和 Lark 是**独立推送渠道** — 无论代理客户端是否打开都可以工作。在 OS-crontab 平台上，计划扫描通过直接 curl 发送通知。在 **OpenClaw** 上，计划扫描在隔离的 cron 代理轮次中运行，并通过 cron **`announce`** 投递到对话渠道（channel = `"session"`）；除非用户明确切换渠道，否则不使用 TG/Lark curl。

## 激活流程

首次设置。仅确认平台 — 其他一切使用智能默认值。

### 步骤 1 — 平台检测与确认

参见 [Platform Detection](#platform-detection-active-probe--user-confirmation)。探测环境 → 询问用户确认 → 写入 `platform.json`。

### 步骤 2 — 检测通知渠道并确认

**在继续之前必须主动检查可用渠道。** 不要静默回退到 session。

在 OS-crontab 平台上，计划通知通过直接 curl 发出；在 OpenClaw 上通过 cron `announce` 发送到对话。检测顺序（检查每一个，报告所有状态）：
1. 检查 `$TELEGRAM_BOT_TOKEN` 和 `$TELEGRAM_CHAT_ID` 环境变量：
   - 都已设置 → TG 就绪
   - 设置了 Token 但缺少 chat_id → 警告："Telegram 配置不完整（缺少 TELEGRAM_CHAT_ID），跳过 TG" → 继续到下一个渠道
   - 都未设置 → TG 不可用
2. 检查 `platform.notify.lark_webhook` 或 Lark MCP 工具：
   - Webhook 已设置且有效（以 `https://` 开头且包含 `/hook/`） → Lark 就绪
   - Webhook 已设置但格式无效（未以 `https://` 开头或缺少 `/hook/`） → 警告："Lark webhook 格式无效，跳过 Lark" → 继续到下一个渠道
   - 未配置且没有 Lark MCP → Lark 不可用

**始终询问用户确认通知渠道 — 绝不静默默认到 session。** 对于监控工具，通知至关重要；默认到 session 意味着当用户不在对话中时警报会丢失。

**如果检测到到一个或多个外部渠道：**

"检测到以下推送渠道可用：
- {检测到的渠道列表，例如 Telegram / Lark}

你希望通知发到哪里？
1. {检测到的渠道 1}
2. {检测到的渠道 2，如果有的话}
3. 仅在当前会话显示（离线收不到）"

**如果没有检测到外部渠道：**

"新机会才能推送到你手上。你希望通知发到哪里？
1. Telegram — 需要提供 Bot Token 和 Chat ID（通过环境变量）
2. Lark/飞书 — 需要提供 Webhook URL
3. 仅在当前会话显示（⚠ 离线收不到通知）

推荐配置 Telegram 或 Lark，这样即使不在对话中也能收到提醒。"

- 如果用户选择 Telegram → 引导设置 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_CHAT_ID` 环境变量
- 如果用户选择 Lark → 询问 webhook URL，验证格式（以 `https://` 开头，包含 `/hook/`），写入 `platform.notify.lark_webhook`
- 如果用户选择 session → 写入 `"session"` 并警告："⚠ 离线状态下不会收到通知，建议后续配置外部渠道。"

将确认的渠道写入 `platform.json` 的 `notify.channel`。

### 步骤 3 — 确认扫描配置（带默认值的 3 步）

展示默认配置并询问用户确认或自定义。每一步都提供一个默认值 — 用户可以按回车接受。

**步骤 1/3 — 扫描范围：**
"扫描范围（可多选）：
 [1] Flash Earn（闪赚）
 [2] Fixed Earn（定期赚币）
 [3] Flexible Earn（活期赚币）
 默认：全选"
- 默认：全部三个启用
- 如果用户选择特定项 → 禁用其他项
- 如果用户只选择 [1] → 设置 `config.fixed.enabled = false`，`config.flexible.enabled = false`；跳过步骤 2/3 和 3/3
- 如果用户只选择 [3] → 设置 `config.flash.enabled = false`，`config.fixed.enabled = false`；转到灵活期特定配置（步骤 2/3 询问灵活期货币，步骤 3/3 询问灵活期 APY 阈值）

**步骤 2/3 — 监控币种：**
对于 Fixed Earn："定期监控币种：全部（默认，按回车）或输入指定币种（如 USDT, SOL）"
- 默认：`"all"`（所有货币）
- 如果用户指定 → 将 `config.currencies` 设置为数组（例如 `["USDT", "SOL"]`）

对于 Flexible Earn："活期监控币种：USDT, USDC（默认，按回车）或输入指定币种"
- 默认：`["USDT", "USDC"]`
- 如果用户指定 → 将 `config.flexible.currencies` 设置为数组
- 注意：灵活期需要按货币进行 API 调用，因此建议保持列表简短

**步骤 3/3 — APY 阈值：**
对于 Fixed Earn："定期最低 APY 阈值：不限（默认，按回车）或输入百分比（如 8）"
- 默认：`0`（无限制）
- 如果用户指定 → 将 `config.fixed.globalMinApy` 设置为 `value / 100`（例如 8 → `0.08`）

对于 Flexible Earn："活期最低 APY 阈值：8%（默认，按回车）或输入百分比"
- 默认：`0.08`（8%）
- 如果用户指定 → 将 `config.flexible.globalMinApy` 设置为 `value / 100`

从对话中自动检测语言并写入 `config.json` 的 `notify.language`。

将配置写入 `~/.okx/earn-hunter/config.json`。

使用 `{baseDir}/templates/activation.md` 模板显示摘要（使用用户的语言）。

### 步骤 4 — 冒烟测试与投递确认

**冒烟测试无论 `verboseLog` 设置如何，都会发送通知。**

1. 立即使用强制开启 `verboseLog` 的扫描周期运行一次，以确保始终产生输出，即使没有机会。临时翻转 `verboseLog`，运行脚本，然后恢复它 — 并使用 `EH_TEST_NAMESPACE=1`，使冒烟测试去重键在 `test:` 前缀下，不污染生产状态：
   ```bash
   jq '.verboseLog=true' ~/.okx/earn-hunter/config.json > ~/.okx/earn-hunter/config.tmp \
     && mv ~/.okx/earn-hunter/config.tmp ~/.okx/earn-hunter/config.json
   EH_TEST_NAMESPACE=1 OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh
   # 然后恢复 verboseLog 到用户的原始值（例如 false）
   ```
2. **如果发现新机会** → 脚本发送正常通知（从模板渲染）
3. **如果没有发现机会** → 在强制开启 `verboseLog` 的情况下，脚本发送简短状态。可选地附加激活确认消息：
   "Earn Hunter 已激活，当前暂无新机会，将在下一轮自动扫描。"
   （使用 `{baseDir}/templates/activation.md` 作为基础，附加无机会说明）
4. TG 或 Lark 渠道 → **询问：** "已向 {channel} 发送测试消息，请确认是否收到？"
5. 用户确认 → 继续到步骤 5
6. 未收到 → 故障排除（参见 `notify-channels.md`）
7. 5 分钟无响应 → ping 一次
8. Session 渠道 → 跳过确认

**注意：** 冒烟测试忽略 `verboseLog` 设置 — 它始终产生输出以验证完整管道端到端工作。

### 步骤 4b — Cron 环境冒烟测试（仅限 OS-crontab 平台）

**关键：** 用户的交互式 shell 具有完整的 PATH，但 cron 没有。运行第二个冒烟测试来模拟 cron 的最小环境，以验证 `env.snapshot` 是否有效：

```bash
env -i HOME="$HOME" PATH=/usr/bin:/bin \
  EH_TEST_NAMESPACE=1 OKX_PROFILE=live \
  bash ~/.okx/earn-hunter/scan.sh
```

- 如果退出 0 → cron 可以工作。继续到步骤 5。
- 如果退出 127 / "FATAL: 'okx' not found" → `env.snapshot` 不完整或缺失。重新运行预检步骤以重新生成它。**不要继续到步骤 5** — cron 任务将静默失败。
- 向用户显示："已验证 cron 最小环境下可正常执行。如果此步失败，说明 env.snapshot 中的工具路径有误。"

### 步骤 5 — 设置调度器

调度机制取决于 `platform.json` 的 `.scheduler.type`。根据平台分支。

#### OpenClaw（`scheduler.type = "openclaw-cron"`）

在 OpenClaw 上，调度通过调用会话内**`cron` 代理工具**在**对话内部**完成 — 绝不是 OS 命令或 `openclaw cron` CLI（在此上下文中 CLI 路径存在权限问题）。鼓励用户在此聊天中直接设置：你创建的 cron 任务继承当前会话的渠道，因此其扫描输出直接返回到此处。

调用带有 `action: "add"` 和形状如下的 `job` 的 `cron` 工具（从 `platform.json` 读取 `.scheduler.interval` 作为频率）：

- `name`：`"earn-hunter-hourly"`
- `schedule`：`{ "kind": "every", "everyMs": 3600000 }` — 从 `scheduler.interval` 推导 `everyMs`（`"1h"` → 3600000，`"30m"` → 1800000，`"2h"` → 7200000）
- `sessionTarget`：`"isolated"` — 在隔离的会话中运行，而不是主会话
- `payload`：`{ "kind": "agentTurn", "message": "执行 earn-hunter 扫描", "lightContext": true }`
  - `lightContext: true` 使用轻量级引导上下文运行轮次（跳过工作区引导文件） → 每次 tick 的令牌成本更低。
  - **令牌预算：** OpenClaw cron 任务**没有每任务工具白名单字段**（旧的 `--tools exec,read,write` 标志不再存在）。扫描保持低成本，因为它通过 `exec` 运行 `okx` CLI，并且**不依赖** 160+ 个 okx MCP 工具 — 因此只要隔离的 cron 代理未配置为加载 okx MCP 服务器，就只有常规工具（exec/read/write）参与其中。加载哪些工具由代理的配置控制，而不是由此任务控制。
- `delivery`：`{ "mode": "announce" }` — 将轮次的输出推送到创建任务的对话渠道。

触发时，隔离代理运行提示 `"执行 earn-hunter 扫描"` → [Scan Cycle](#scan-cycle)（使用渠道 `session`/stdout 运行 `scripts/scan.sh`） → 转发结果 → `announce` 在此处投递。因此任何新机会都会自动发送。

**不要**在对话中发出任何 shell/`openclaw cron` CLI 命令 — 仅通过 `cron` 工具驱动调度。

#### OS-crontab 平台（`scheduler.type = "cron"` 或 `"launchagent"` — Claude Code / Hermes / Generic）

这些使用 **操作系统调度器 → `scripts/scan.sh`**。该脚本执行所有操作（CLI 调用、过滤、去重、渲染、curl 通知），并且具有 **零 LLM 成本**。

**安装脚本** — 将技能的 `scripts/scan.sh` 复制到状态目录，以便调度器有一个稳定的路径：

```bash
mkdir -p ~/.okx/earn-hunter
cp {baseDir}/scripts/scan.sh ~/.okx/earn-hunter/scan.sh
chmod +x ~/.okx/earn-hunter/scan.sh
```

**设置调度器** — 首先尝试 crontab，如果 cron 守护进程未运行，则回退到 macOS 的 LaunchAgent：

```bash
# 从当前 shell 解析工具目录
NODE_DIR=$(dirname "$(command -v node)")
OKX_DIR=$(dirname "$(command -v okx)")
JQ_DIR=$(dirname "$(command -v jq)")
CRON_PATH=$(printf '%s\n' "$NODE_DIR" "$OKX_DIR" "$JQ_DIR" /usr/bin /bin | awk '!seen[$0]++' | paste -sd: -)
```

**步骤 A：尝试 crontab + 验证 cron 守护进程（macOS）**

```bash
(crontab -l 2>/dev/null; echo "0 * * * * PATH=$CRON_PATH OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh >> ~/.okx/earn-hunter/cron.log 2>&1") | crontab -
```

在 macOS (`uname -s` == `Darwin`) 上，立即检查 cron 守护进程是否运行：

```bash
if [[ "$(uname -s)" == "Darwin" ]] && ! launchctl list com.vix.cron >/dev/null 2>&1; then
  # cron 守护进程未运行 — 回退到 LaunchAgent
fi
```

- 如果 cron 守护进程正在运行 → 完成，`scheduler.type = "cron"`。
- 如果 cron 守护进程**未**运行 → 删除 crontab 条目并继续步骤 B。
- 在 Linux 上 → 跳过检查（cron 总是可用），`scheduler.type = "cron"`。

**步骤 B：macOS LaunchAgent 回退** (`scheduler.type = "launchagent"`)

使用解析的路径生成 `~/Library/LaunchAgents/com.okx.earn-hunter.plist`：

```bash
SCAN_SCRIPT="$HOME/.okx/earn-hunter/scan.sh"
LOG_FILE="$HOME/.okx/earn-hunter/cron.log"
INTERVAL=3600  # 从 scheduler.interval 衍生："1h"→3600, "30m"→1800, "10m"→600

cat > ~/Library/LaunchAgents/com.okx.earn-hunter.plist << PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>com.okx.earn-hunter</string>
    <key>ProgramArguments</key>
    <array>
        <string>/bin/bash</string>
        <string>${SCAN_SCRIPT}</string>
    </array>
    <key>StartInterval</key>
    <integer>${INTERVAL}</integer>
    <key>EnvironmentVariables</key>
    <dict>
        <key>PATH</key>
        <string>${CRON_PATH}</string>
        <key>OKX_PROFILE</key>
        <string>live</string>
        <key>HOME</key>
        <string>${HOME}</string>
    </dict>
    <key>StandardOutPath</key>
    <string>${LOG_FILE}</string>
    <key>StandardErrorPath</key>
    <string>${LOG_FILE}</string>
    <key>RunAtLoad</key>
    <true/>
</dict>
</plist>
PLIST

launchctl load ~/Library/LaunchAgents/com.okx.earn-hunter.plist
```

将 `scheduler.type = "launchagent"` 写入 `platform.json`。通知用户：

"macOS cron 服务未运行，已自动切换为 LaunchAgent 调度（无需 sudo，重启自动恢复）。"

**注意：**
- **OAuth 模式** → 从 plist `EnvironmentVariables` 中省略 `OKX_PROFILE`（或设置为空）。
- LaunchAgent plist 路径必须绝对（不能使用 `~`）。激活流程在生成时展开 `$HOME`。
- `RunAtLoad: true` 意味着第一次扫描在加载后立即运行。
- 脚本读取 `config.json` / `platform.json`，写入 `state.json` / `notify.log`，并通过 curl 向 TG Bot API 或 Lark Webhook 发送通知。在每次触发时不需要代理参与。
- 当没有新机会且 `verboseLog=false` 时，脚本退出 0 并**不产生任何输出** — 这是预期的静默行为。

**重要提示：在 OS-scheduler 平台上，** **不要** **使用 agent-platform `/loop` / Routines**（Claude Code `/loop`，云 Routines）。这些每个触发都会生成 LLM 会话，并且无法可靠地推送外部通知。（OpenClaw 是例外 — 它设计上使用其会话内的 `cron` 工具并通过 `announce` 交付。）

## 扫描周期

**整个扫描周期由 `scripts/scan.sh`（纯 shell + jq，零 LLM 成本）实现。** 无论是由 OS crontab 触发、由 OpenClaw 独立 cron 代理轮次触发，还是由用户在交互式会话中触发（"执行 earn-hunter 扫描"），周期都是**相同**的：运行脚本并转发其输出。**不要**在自然语言中重新实现扫描步骤 — 脚本是唯一的信息源。

**OpenClaw 独立 cron 轮次：** 任务的提示将路由到这里。运行 `scripts/scan.sh`（`platform.json` `notify.channel = "session"`，脚本将任何通知打印到 stdout）；将 stdout 作为轮次的响应转发。cron 任务的 `announce` 交付将将其推送到对话频道。**不要**从此轮次 curl TG/Lark — 交付由 `announce` 处理。

### 代理如何运行扫描（交互式触发）

```bash
# 配置文件：仅在 API Key 模式下传递 OKX_PROFILE（OAuth 模式下省略）。
OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh
```

然后**逐字转发脚本的 stdout** 给用户：
- 如果脚本打印通知（Flash / Fixed / 混合 / 详细状态），则显示它。
- 如果脚本打印**无内容**（静默退出 0，无新机会 + `verboseLog=false` 的情况），则告诉用户"本轮扫描完成，无新机会" — **不要**向频道编造"扫描完成"消息；沉默是故意的。

### 脚本执行的操作（有关其实现的规范，请参阅 `references/scan-logic.md`）

1. 读取 `~/.okx/earn-hunter/config.json`
2. 运行扫描命令（基于 `flash.enabled` / `fixed.enabled` / `flexible.enabled`）：
   - Flash: `okx [--profile live] earn flash-earn projects --status 0,100 --json`
   - Fixed: `okx [--profile live] earn savings fixed-products --json`（CLI <1.3.3 时自动回退到 `rate-history` + `fixedOffers`）
   - Flexible: 对于 `flexible.currencies` 中的每种货币，`okx [--profile live] earn savings rate-history --ccy <ccy> --limit 1 --json`
3. 过滤（双层 APY 阈值、条款过滤器、货币过滤器；flexible 使用阈值穿越模型）
4. 与 `~/.okx/earn-hunter/state.json` 去重（`state.flash["<id>:<status>"]`，`state.fixed["<ccy>:<term>:<rate>"]`，`state.flexible["<ccy>"]`）
5. 如果有新机会 → 渲染匹配的模板（flash / fixed / flexible / 混合）并通过检测到的频道（TG → Lark → 会话）发送，记录到 `notify.log`
6. 更新 `state.json`（写入新键；flash ID 级别的差异清理；fixed 键级别的差异清理；flexible 阈值穿越差异清理；7 天 TTL；失败计数器）
7. 如果没有新机会：`verboseLog=true` → 简要状态；`verboseLog=false` → **静默退出 0，无输出，无发送**
8. 错误处理：连续失败计数器（3 次失败时发出警报，然后重置）；401/session-expired → 凭证警报 + 停止

**频道路由在脚本内部：** 检测顺序 TG（`$TELEGRAM_BOT_TOKEN`+`$TELEGRAM_CHAT_ID`）→ Lark（`platform.json` `.notify.lark_webhook`）→ 会话（stdout）。`platform.json` 中的 `notify.channel` 为 `telegram`/`lark`/`session` 会强制该频道。

**认证 / 配置文件：** 脚本从不读取或打印凭证。它将所有认证委托给 `okx` CLI（它读取 `~/.okx/config.toml`）。配置文件仅通过 `OKX_PROFILE` 环境变量注入。

**Flexible Earn 去重模型：** 与 Flash/Fixed 不同，后者按特定机会去重，Flexible 使用**阈值穿越**模型 — 关键是 `<ccy>`。当 APY 跨越阈值时通知一次；在保持高于阈值时保持静默；当 APY 低于阈值时重置（差异清理会删除该键）。这避免了因利率波动而频繁通知。

## 暂停/恢复

根据 `platform.json` `.scheduler.type` 分支：

**OpenClaw (`openclaw-cron`)** — 通过会话内的 `cron` 工具管理（无 CLI）：
- **暂停：** 调用 `cron` 并使用 `action: "update"`，针对 `earn-hunter-hourly` 任务，补丁 `{ "enabled": false }`（或 `action: "remove"` 删除它）。
- **恢复：** `action: "update"` 并使用 `{ "enabled": true }`（或像激活步骤 5 中那样重新创建）。
- 使用 `action: "list"` 找到任务 ID。

**OS-crontab 平台 (`cron`)**：
- **暂停：** `crontab -l | grep -v 'earn-hunter' | crontab -`
- **恢复：** 重新添加 crontab 条目（与激活步骤 5 相同）。

**macOS LaunchAgent (`launchagent`)**：
- **暂停：** `launchctl unload ~/Library/LaunchAgents/com.okx.earn-hunter.plist`
- **恢复：** `launchctl load ~/Library/LaunchAgents/com.okx.earn-hunter.plist`

配置和状态被保留 — 恢复时从它停止的地方继续。

## 测试模式

触发短语："测试 earn-hunter" / "earn-hunter smoke test" / "测试定时任务触发"

行为 — 使用测试模式钩子运行脚本（无需单独逻辑）：

```bash
# 强制详细输出，始终产生输出；在测试前缀下写入去重键。
EH_TEST_NAMESPACE=1 OKX_PROFILE=live ~/.okx/earn-hunter/scan.sh   # 暂时将 config.verboseLog 设置为 true
```

1. **执行完整扫描周期** — 脚本运行相同的扫描，但 `EH_TEST_NAMESPACE=1` 隔离状态写入
2. **强制发送通知** — 暂时设置 `config.verboseLog=true`，以便脚本无论是否找到机会都始终发送输出（之后恢复）
3. **测试命名空间去重写入** — `EH_TEST_NAMESPACE=1` 将去重键前缀为 `test:`（例如 `test:flash:12345:100`）；这些键对差异清理免疫（只有 TTL 删除它们），因此测试运行不会污染生产状态
4. **扫描完成后输出诊断**：
   - okx 认证状态（已登录 / 过期 / 未配置）
   - 扫描命令结果（flash 项目数量 + fixed 产品数量 + flexible rate 数量）
   - 过滤后结果（每种类型通过过滤器数量）
   - 通知频道状态（配置了哪个频道，发送结果）
   - 调度器状态（OS-crontab 平台：是否存在 crontab 条目？ / OpenClaw：`cron` 工具 `action: "list"` 显示 `earn-hunter-hourly` 任务？）
   - `~/.okx/earn-hunter/notify.log` 的最后 5 行
5. **完成消息：** "测试完成。test: 前缀的 state 不影响正式去重，正式扫描不受影响。"

## 错误处理

阅读 `{baseDir}/templates/error-alert.md` 了解确切的警报消息模板。

| 错误 | 操作 |
|---|---|
| `okx` 401 / "Session expired" | 停止扫描。发送警报（凭证失效模板）。如果交互式，则加载 `okx-cex-auth`。 |
| 网络错误 / 超时 | 静默重试一次。如果仍然失败，则跳过此周期。 |
| 3 次连续扫描失败 | 发送警报（连续失败模板）。计数器存储在 `state.consecutive_failures`，警报后重置。 |
| `state.json` 损坏 | 通过写入 `{"flash":{},"fixed":{},"consecutive_failures":0,"last_error":""}` 进行重置。可能会造成一轮重复通知。 |
| 通知发送失败 | 记录到 `notify.log`，继续扫描。不去重键（下一周期重试）。 |
| 运行时缺少 `config.json` | 发送警报： "earn-hunter 未配置，请运行首次激活流程。" |
| 双客户端怀疑（用户提及两个平台） | 警告： "建议仅在一个客户端运行 earn-hunter，避免重复通知。" |
| `verboseLog = true` + 无命中 | 发送简要状态（不是静默的）。 |

## 防御性设计原则

这些约束适用于 earn-hunter 的所有更改：

1. **cron PATH ≠ 用户 shell PATH。** 任何 cron 触发的脚本都必须独立解析工具路径 — 永远不要假设 cron 继承了用户的登录 PATH。脚本使用 `env.snapshot` + `resolve_bin` 回退。
2. **首先进行合理性检查。** 在运行任何 CLI 命令之前，验证二进制文件是否存在。工具缺失 → 立即退出并显示清晰错误，而不是静默失败。
3. **永不吞没 stderr。** 使用 `2>&1`（捕获到变量）而不是 `2>/dev/null` 进行 CLI 调用。否则错误消息会消失，`last_error` 为空。
4. **Smoke test 必须模拟生产环境。** 激活 smoke test 运行两次：一次在用户 shell 中（验证凭证/网络），一次在最小 `env -i PATH=/usr/bin:/bin` 中（验证 cron 可以运行）。如果 cron smoke 失败，则不要通过步骤 5。
5. **警报模板必须处理空字段。** 如果 `last_error` 为空字符串，则追加 "检查 `~/.okx/earn-hunter/cron.log`；空错误通常意味着 PATH 问题" 指导。
6. **工具路径使用快照 + 回退，而不是全局 PATH。** `env.snapshot` 在激活时写入确切路径；`resolve_bin` 尝试快照 → `command -v` → 硬编码常见路径。在 `nvm switch` / Homebrew 升级后仍然有效。
