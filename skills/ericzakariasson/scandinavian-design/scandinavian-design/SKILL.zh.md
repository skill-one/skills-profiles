# 斯堪的纳维亚设计

## 核心方向

创建感觉平静、实用、精致且有意简化的界面。使用中性黑白基础、实用约束和自然视觉层次。使用alpha黑在白色上构建中间色调，而不是暖色或冷色色偏。让产品图像承载表达，而周围的界面保持安静。

简洁不是极简主义。移除不必要的元素，使主要任务变得明显，但在它们使界面更易于理解时添加上下文、标签、边界或密度。安静绝不能意味着空泛、模糊或惰性。

## 运作姿态

以资深产品设计师的姿态，偏向于约束。按以下顺序优化：

1. 理解和路径导航
2. 任务完成和可访问性
3. 信息层次和有用密度
4. 品牌和语义意义
5. 视觉约束和一致性
6. 带来惊喜

每个元素都必须有其存在的理由。每个间距、字体、颜色、半径和运动选择都应根据产品而非仅凭风格来论证。在做出视觉改变之前，确认它是否改进了理解、层次、效率、可访问性或品牌一致性；是否适合表面的目的、使用频率和所需信息密度；是否简化或重用现有系统无法达到相同效果；是否保留了意义、可供性和语义状态。拒绝仅以“它看起来更斯堪的纳维亚”为理由的改变。一份高置信度的改进短列表比没有目的的全面改版更好。

## 调用模式

根据请求推断模式：

- **应用**（默认）：检查并重新设计请求的表面，包括其布局和结构限制清晰时，以及重新设计的布局，然后进行验证。
- **审查**：不进行源代码编辑；返回优先级发现、建议的更改和应保持不变的元素。
- **原型**：在隔离路线或框架中创建三个真正不同的斯堪的纳维亚方向。以轴命名每个方向，例如安静、编辑或实用主义。一次渲染一个方向，全尺寸，使用逼真的内容和即时切换器。在用户选择之前，不要更改生产UI。
- **深度**：检查完整的相关流程，包括响应状态、交互状态、可访问性和视觉一致性。

某些表面正确地很响亮，而无论约束是否是改进，所有技能的指示都指向约束。一个出版品或产品的视觉音量是其身份，可以在结构上变得更好——修复倒排的排名、在重要的事情上花费大小——同时在声音上变得更糟。当存在这种张力时，说明你选择了哪一个以及为什么，而不是应用规则并默认报告汇总作为改进。

保持请求的产品范围，但不要将范围控制与布局保留混淆。页面改版可能会改变其网格、部分顺序、分组、层次和响应式布局，而不会成为全产品范围的重新品牌化。

## 侦察

在设计或编辑之前：

- 在上下文中检查当前界面，而不仅仅是目标组件。
- 确定主要用户任务、常见路径、路径导航和逃生路线。
- 绘制现有颜色、字体、间距、半径、边框、阴影、运动、组件和响应式约定。
- 检查安装的UI原语和依赖项。重用可访问的现有组件，而不是手工制作对话框、菜单、选择、提示或焦点行为。
- 确定必须保留的已建立品牌元素和语义颜色。
- 确定产品是密集且操作的、编辑的、商业的或表达的；约束必须适合其个性。
- 确定结构问题：页面流程弱、重复的卡片网格、碎片化的层次、文本与媒体平衡差，或重要内容被当前布局埋没。

## 视觉系统

将工作简化为一个干净、有用的系统：

- 保持可用性、可访问性、产品意义和已建立的品牌身份。
- 优先考虑清晰的排列和简单结构，而不是装饰。
- 默认左对齐文本，包括标题、标签、元数据和页脚。居中文本是一个罕见的、故意的例外，绝不是先前Chrome的遗留物，也绝不会与同一组中的左对齐兄弟姐妹混合。一个对称的全宽带，其中每个成员都是居中的——一个关闭的锁闭、版权行——是一个连贯的组，而不是遗留物，并将其中元素之一推向宽视口的左边缘使其孤立。
- 移除不必要的颜色、沉重的阴影、渐变、纹理、容器和装饰性Chrome。
- 使用一个图标系列，具有单一的笔触粗细和一致的光学尺寸。图标是同一不透明度阶梯上的单色墨水，而不是装饰。表情符号不是图标系列：它们携带自己的颜色、重量和光学尺寸，并且没有过滤器能将它们带到墨水阶梯上。移除它们，让标签承载意义。这仅适用于界面自己的图标。产品截图、某人的帖子或显示名称中的表情符号是内容，编辑它们与重新绘制照片是同样的错误。
- 通过视觉重量的数量，而不是元素的数量来判断杂乱。在任何区域，确定哪些元素是同级的，并相同渲染同级元素：一个大小、一个墨水阶梯、一个基线。控件的重量应跟踪其使用频率，因此区域中最少使用的控件绝不能是其最重的元素。
- 保持布局平衡、平静且易于扫描。
- 将长页面构建为一系列不同的、宽敞的章节，而不是一堆相似的卡片。
- 保持文本简短、直接和具体。
- 在引入新元素之前重用现有的设计令牌和组件。
- 减少视觉复杂性，而不是添加层。

## 颜色和透明度

当产品还没有合适的调色板时，使用这些中性默认值：

- 画布：`#FFFFFF`
- 表面：`#FFFFFF`
- 主要墨水：`#000000`
- 次要墨水：`rgb(0 0 0 / 64%)`
- 三级墨水：`rgb(0 0 0 / 44%)`
- 边框：`rgb(0 0 0 / 10%)`
- 强边框：`rgb(0 0 0 / 18%)`
- 悬停填充：`rgb(0 0 0 / 5%)`
- 压下填充：`rgb(0 0 0 / 9%)`
- 筛幕：`rgb(0 0 0 / 44%)`

使用透明度创建层次，而不是装饰：

- 90–100%：主要文本和关键图标
- 60–70%：辅助文本
- 40–50%：元数据和非必要图标——这个阶梯用于符号和真正可选的文本，并且它不会在白色上达到4.5:1。密集的操作表面将真实阅读放在那里：提示时间、广播网络、划线的价格、时间戳。在这种情况下，将阶梯提升到大约56%，而不是接受该范围，并且经常需要这样做，因为该范围是为编辑表面编写的，其中元数据确实是可选的。
- 8–12%：边框和分隔符
- 4–6%：悬停表面
- 8–10%：压下或选中表面

这是三个阶梯，产品可能有四个或更多的墨水阶梯。保持产品的阶梯数量，而不是强迫它进入三个：将额外的阶梯分布在和之间，并且永远不会将两个阶梯合并为一个值。一个跨越两个阶梯的句子，或一个与其自己的链接区分一个阶梯的标志，是一个真正的区别，扁平化会破坏它。

使用alpha颜色设置墨水，而不是`opacity`属性。在容器上，它会使每个后代褪色，在叶子元素上，它会与元素已经所在的阶梯相乘，悄悄地将辅助文本推到可读对比度以下。不要将米色、奶油色、蓝灰色、绿灰色或其他染色中性色引入界面Chrome。验证对比度，而不是假设这些范围在每种情况下都是可访问的。

上述阶梯假设墨水在画布上。任何位于染色上的内容——交替行填充、凸起的卡片、提示——都比表格暗示的对比度低，最低的阶梯是失败的。重新测量安静的阶梯相对于它们实际落到的表面，而不是相对于页面。

当产品的中性色已经没有通道扩散并且有足够的阶梯时，保持它们不变。用alpha重新表达一个工作中的十六进制坡道是没有任何视觉收益的风险，并且它可能主动破坏倒置的上下文，因为相同的令牌经常在深媒体上绘制文本，而alpha黑会消失。

对于深色画布产品，用同样的纪律反转系统：一个近黑色画布，如`#0A0A0A`，和白色主要墨水。alpha值不会保持不变。相同的alpha在深色画布上比在浅色画布上提供更多对比度——64%的白色在`#0A0A0A`上达到8.2:1，而64%的黑色在白色上达到6.7:1——因此重用浅色百分比会使辅助文本和Chrome更响亮而不是更安静，这与意图相反。使用大约`rgb(255 255 255 / 56%)`作为次要墨水和`rgb(255 255 255 / 36%)`作为三级，以匹配浅色阶梯产生的层次。边框是例外，几乎完全反转，所以`rgb(255 255 255 / 10–12%)`保持不变。

三级阶梯是对一个从未在白色上可访问的阶梯的忠实翻译，因此它属于符号、分隔符和真正可选的文本。当真实内容位于此处——日期、划线的价格、标题——提升它。在一个真正的近黑色画布上，如`#0A0A0A`，46%达到4.66:1，这足够了。这个数字对画布的实际黑暗程度敏感：在`#1F1F1F`上，它下降到4.53:1而没有余量，并且在`#262626`上失败。深色产品通常会发送处于该范围的表面，因此在大约`#1A1A1A`以上使用50%而不是接受该范围，并且经常需要这样做，因为该范围是为编辑表面编写的，其中元数据确实可选。

交互填充不一对一反转，因为浅色洗在深色周围是一个比深色洗在浅色周围更小的感知步骤。期望大约是浅色值的1.5倍：9%用于悬停和14%用于压下。区分休息时的*洗*与休息时的*填充*。大约5%适合行或表面染色，但一个必须作为控件在休息时阅读的按钮需要大约9%，因为5%的白色在近黑色上会将表面移动大约十二个值，并且不会读取为填充。

alpha黑填充不再可用。一个从`rgb(0 0 0 / 25%)`构建的凹陷井在近黑色画布上是不可见的，因此需要坐在页面*下方*的表面必须比它更亮——这是与直觉相反的。

在表面之前纠正墨水。首先中性化画布会使墨水中剩余的每个阴影更加明显，而不是更不明显，并且在任务中途页面看起来更糟。

不要引入染色深灰色，并且通过通道扩散而不是通过眼睛来判断。在约八点扩散或更多时纠正阴影，低于五点时保留它，并将之间的区域视为判断——在这样做不会造成损失的情况下纠正它。扩散在浅色墨水上比在深色表面上更明显，所以在阶梯顶部和底部的相同绝对阴影是不同的：偏离中性的画布两三点或三点是不可见的，而墨水的通道相距十点或更多，在白色旁边会明显地读出冷色调。

在深色画布上至少给焦点环两个像素，并且永远不会少于它已经有的。一个发丝环没有周围的光场来与之对比，状态颜色必须保持不变。不要在单个表面上混合alpha黑和alpha白中性色。一个故意反转的表面——一个浅色卡片在深色页面上——是被允许且通常有用的，只要它在整个过程中保持自己一致的系统。

通过默认保持界面Chrome、排版、分隔符和数据可视化中性。你正在设计的图表是Chrome，并变为中性；图表在产品截图内是内容，当两个系列通过颜色区分时，那种颜色是图例，中性化它会破坏编码。产品摄影、截图、视频和叙事图像可以使用表达性颜色；将那种颜色包含在媒体内，而不是让它泄漏到周围的Chrome中。

大部分是装饰的媒体不受媒体身份的保护。一个九部分饱和渐变和一部分产品截图的面板是装饰性渐变，该渐变触发名称，并且它位于视频或图像框架内的事实不会改变它是什么。通过框架中执行信息工作的比例来判断。

一个在标记中重建的产品模拟仍然是截图。营销页面通常在DOM中重建自己的界面，而不是发送图像，并且由于模拟读取与周围页面相同的令牌，令牌级更改会触及内部并重新绘制所描绘的产品——变暗应用自己的正文文本，或使看起来像真实的东西的仪表板变灰。在这种情况下，模拟内的色调和中性色属于所描绘的产品，因此给它自己的范围，而不是逐个豁免选择器。

可以谨慎地使用一个已建立的品牌强调色，以主要动作来实质性地提高焦点。当用户请求严格单色时，省略强调色。不要发明多个装饰性强调色。

品牌标志不是Chrome。保持产品自己的标志按发送时的全彩色，即使周围的一切都变为中性。当一个品牌发布多种色调时，“发送时”有多个答案：选择现在位于其上的表面而幸存的发布变体，而不是在浅色带上留下一个白色标志。在单色页面上，一小部分标志色比在原始版本中做更多身份工作，并且褪色它读作去色而不是设计。这涵盖了您正在设计的产品标志；作为客户标志、合作伙伴徽章或支付方式出现的第三方标志是社会证明而不是身份，并且在页面组成下变为单色。当一个页面同时承载两者时，区别在于页面属于哪个产品。

一个标志也可以是数据标签，这是第四种情况，也是最常出错的情况。当一个第三方标志识别记录的主题——一个团队徽章旁边得分，一个国家旗帜旁边竞争对手，一个交易所标志旁边报价——它既不是身份也不是证据。它是行标题，并且无论它属于谁，都保持其颜色。测试是标志在该位置的工作，而不是它的所有权。

标志的形状携带其识别的声明有一个大小下限。这在120px的标志带中是真的，而在16px中是假的，其中色调做了大部分区分：褪色小标志不会使它们安静，它们会合并成彼此。在决定单色是免费之前，检查渲染大小。

商品化颜色是第三种类别，与两者都不同。忠诚度徽章、活动填充和促销闪光灯是品牌相邻但编码没有状态并识别不了。中性化它们。

签名颜色也可以附加到产品自己的主要数据——评分上的金色、分数上的绿色。将其视为品牌标志，而不是作为强调色。无论数据出现在哪里，包括在两百行列表中，因为它被识别多次正是签名标志的用途，产品不会因为使其最识别的元素更难发现而得到改善。仅在相同色调已经扩散到不是数据的元素上时才限制它——装饰条、促销闪光灯、借用品牌颜色的图表系列——这是品牌穿着品牌，而不是品牌做它的工作。

决定模糊情况的因素是数量，衡量标准是覆盖范围而非原始计数。一个真正编码状态的色彩——一个未读的点、一个活动指示器、一个错误徽章——当它饱和读者扫描的区域时，就不再作为强调色起作用：一张卡片内集中放置的十个标记仍然表示“这是交易卡片”，而同一十个标记分散在100个格子的网格中则什么也不表示。

对齐优于计数和覆盖范围。一个小的标记在列表中相同水平位置重复堆叠成页面长度的虚线，在面积读作饱和之前，它被读作一条线。当一个重复的*强调色*共享一个轴时，将其视为一条规则而非一个点。

所有这些都不涉及品牌标志或签名数据颜色。数量测试管理商品填充和状态颜色，当所有东西都携带它们时，它们就失去了意义。一个签名标志则不同：它应该重复出现，而一个以“所以我们移除了产品被识别的元素”结尾的论点在早期某个地方出错了。当规则与身份冲突时，身份胜出，规则需要被记录为例外。当一个状态颜色不再有任何区分时，让形状和标签来承担它，并去除色调。将其表述为一种交易而非免费移除，因为在移除之前，它正在传达某种信息。

请注意，促销闪现由上述段落决定，永远不会达到这个测试：它在任何数量下都不编码状态。

不要降低低于其原始突出显示级别的披露。赞助标签、法律通知和可访问性功能是根据其发布者选择并可能必须保持的对比度放置的，因此将其降级为元数据级别是一种不同于设计的失败。

与背景和文本一起梳理`border-color`。设计系统的默认轮廓通常是中性灰色，在普通墨水旁边读作彩色，并且因为它本身看起来是故意的，所以它经受住了中性化过程。

## 字体

使用一个无衬线字体家族：

1. 保留现有的优质无衬线产品字体。
2. 使用平台系统字体用于原生界面。
3. 对于网络，默认使用`Inter Variable`。
4. 如果已经获得许可，`Scto Grotesk A`可以提供更具北欧特色的字体。

规则1是关于质量和身份，而不是衬线。一个优质的衬线字体，如果是一个出版物的字体声音，与一个优质的 grotesque 字体一样值得保护，并且替换它需要同样的论点——明确地说，是对品牌声音的成本。按原文书写，很容易将规则理解为仅保护无衬线面，这意味着一个拥有美丽衬线字体的网站通过规则保留其字体，而一个拥有美丽 Cheltenham 字体的网站则通过规则失去其字体，而没有与任何一种工作相关的理由。

规则1也可以由页面已经拥有的但用于次要用途的家族满足。一个以衬线为主的网站还跨标签和控制发布优质无衬线字体，提升这个无衬线字体遵循了指示，同时失去了导入新家族会失去的身份。替换默认网络无衬线字体与提升产品自己的无衬线字体之间的区别，相当于灰度副本与重新设计之间的区别。

规则3仅当规则1和规则2不适用时才适用。替换优质产品字体是一种需要自己论证的改变，而不是默认设置。通常只有一个论点有效：一个只发布两种权重的家族无法表达标签和标题等级，这是整个系统依赖的，因此替换默认网络无衬线字体是合法的——以牺牲品牌声音为代价，这是值得明确说明的。在替换之前检查两个家族的权重，因为源的权重与目标的权重一样重要：一个完全设置为300的页面在面对一个不发布它的家族时，将无声地解析为400，从而消除权重所携带的任何区别。检查宽度类别。Grotesques在x高度上比大多数衬线字体更宽更高，因此在不改变像素尺寸的情况下替换会添加线条——一对一替换压缩字体是最坏的情况，并且设置在窄列中的标题可以再次获得其高度的一半。通过追踪和行距恢复宽度，然后再考虑使用更小的尺寸。

第二个家族可以是一种编码，而不是混合系统。在一个出版物的某一部分通过字体与另一部分区分开来时，扁平化两者会消除读者正在使用的区别，就像中性化一个双系列图表会破坏其图例一样。在决定安全合并之前，寻找冗余标签。

不要引入衬线展示字体。除非用户明确要求保留，否则用选定的无衬线字体家族替换衬线字体。不要在没有确认已获得许可的情况下引入付费字体。

- 正文：16-18px，权重400，行高1.5-1.6
- 标签和控制：权重500
- 标题：权重500-600，但仅在使用家族实际发布的权重后检查，避免700-900。CSS匹配将不可用的500解析为400，将不可用的600解析回700，因此在一个只有两种权重的家族上重述权重可能会无声地消除标题与其描述之间唯一的区别。当可用权重无法表达目标时，保持页面已使用的权重。
- 大标题：行高1.05-1.15，带有轻微的负追踪
- 正文文本：中性追踪
- 不要使用全部大写或强制大写文本，包括标志、标签、按钮、导航、徽章和元数据。使用句子大小写或自然标题大小写。全小写的铬是另一方向的相同失败，因此将小写导航和控制标签更改为句子大小写。两条规则都针对样式化大小写：将它们范围限定为铬，并将标题、用户名和运行文本保留为它们原始的大小写。当大写存在于标记中而不是CSS中时，保留它们，而不是应用一个会破坏相邻字符串的通用转换。在移除它之前检查转换正在做什么：一个`text-transform`位于标记中的小写短横线上，正在*修复*该标记，清除它会产生本规则禁止的全小写铬。移除转换也会发布标记中包含的内容，在一系列标题中，可以是句子大小写、全小写和喊叫——因此`text-transform: none`统一应用会产生一个看起来破损而不是受约束的页面。在决定对所有内容使用一条指令之前，检查底层字符串。

当标记本身在喊叫时，`text-transform: lowercase`与`::first-letter { text-transform: uppercase }`可以恢复句子大小写。它仅适用于没有专有名词和没有首字母缩略词的单句字符串：它会破坏"RVs"和"FPS"，它只跨`<br>`到达第一句，并且它对于模板化复制是不安全的，其未来值你无法看到。在所有选项都不干净的情况下，说明情况并选择较小损害，而不是报告规则已满足。

将每个屏幕限制为三个或四个清晰不同的文本样式。这是为编辑和营销表面编写的。一个密集的操作屏幕可能合法地需要六个，因为一行数据可以在存在标题或故事标题之前消耗四个等级——标签、值、限定符和状态——因此计算数据本身需要的等级，然后再将剩余的视为违规。

主要通过大小写和空白创建层次结构，而不是通过许多权重
保持文本宽度在55-68个字符附近。在一个以图表为主的页面上缩小度量会花费垂直高度，因此命名该成本并将媒体移入释放的水平空间，而不是让它变成死间隙。

## 表面和结构

本节中的数字是那些没有自己连贯系统的表面的默认值。当产品已经根据一致的间距比例、半径约定或度量工作到一致的空间时，应遵循该系统。在一个已经内部一致的页面上达到这些数字，是用一个不同的系统替换一个工作系统，这不是改进。

- 使用8px的间距节奏，必要时进行4px调整。
- 当周围系统允许时，优先使用24px的移动边距和40-64px的桌面边距。
- 当密度允许时，在桌面上为主要的编辑部分过渡提供96-144px，在移动设备上提供64-96px；保持相关组内的间距非常紧密。当一个章节已经以高大的图表结束，该图表本身将下一个标题向下推时，整个过渡堆叠在该图表之上，并在文本旁边打开一个空白；测量渲染的间隙，而不是盲目地应用范围。
- 让空白分隔部分，然后再添加边框或背景。在添加规则之前，说明没有规则会是什么情况。如果什么都不会，就不要添加它。
- 用比例而不是测量使空间明确。当标题上方的间隙大约是下方间隙的三倍时，标题属于其下方的內容。伸手去拿规则通常意味着这两个间隙还不够不同，规则补偿了这一点，而不是任何真正的模糊性。
- 按屏幕而不是按文档计算规则数量。在大页面上，每个视口大约一个章节规则读作结构，而相同的十四个规则按文档计算读作违规。一个规则将铬与内容分开读作结构；十八条通过索引读作网格，眼睛开始跟踪线条而不是文字。轨道、部分规则、组规则和网格轮廓会迅速累积，并且每个规则在添加时看起来局部上都是可以辩护的。
- 轴决定了可计算规则和密度之间的权衡。空间可以替代水平规则，因为它分隔按顺序读取的记录，唯一的成本是滚动。空间不能替代垂直规则，因为它分隔同时读取的列，并且没有间隔预算可以加宽。首先剪切水平规则，并保留承载多列网格的垂直规则。
- 不要将规则放在关系上。图像及其标题、标签及其字段、记录及其元数据必须读作一个整体。分隔符属于同级元素，而不是一对元素之间。
- 按控制而不是按元素计算边界。一个有边框的输入在一个有边框的表单中，表单中还有一个有边框的提交按钮，会三次绘制一个控制。一个安静的填充可以用作边界，而不是规则。
- 保持安静的事物安静。一个在原始版本中没有携带边界的控制，在重新设计时不会获得一个边界，并且将其框起会使其高于邻居，没有理由。
- 线条被相互比较，因此删除大部分线条会提升幸存者。在删除任何规则后，重新检查保留的规则。
- 对于重复记录，用一个小间隙将元数据绑定到其记录，用一个大间隙分隔记录；眼睛根据相对距离分组，不需要线条。只有在空间它将替换的成本比表面可以负担的密度更高时，才伸手去拿发丝线，并且在做出决定时说明这种权衡。
- 交替行填充是空间和发丝线的第三个选项，在一个长列表中，它优于两者。它不占用垂直空间，也不画线，而空间可以将几百条记录的列表增加数千像素，发丝线每100像素放置一条规则。保持它非常安静，大约3%，并记住它移动了它上面所有内容的对比度计算。
- 记录之间的间隙必须大于其中最大的间隙。测量而不是估计：一个将操作行固定到底部的卡片在短项目内部留下的空间与一个慷慨的间隔在项目之间提供的空间一样多，然后控制读作属于下一条记录。当内部间隙无法减少时，间隔必须增长超过它，这会消耗密度——这是正确分组的诚实价格。
- 当分组保持清晰时，优先使用细分隔符而不是带框卡片。
- 在分段数据区域中，使共享边框干净地相遇。分隔符应该跨越其预期容器，相邻单元格应共享边缘，而不是由于填充不一致而造成的近失间隙。
- 保持角落半径受控，通常为6-12px。
- 完全圆角的药丸按钮是允许的，但它们不是默认设置。选择按钮形状作为组件系统的一部分，而不是每个实例：等效的主要CTA必须在整个页面上共享相同的半径、高度、填充和权重。如果主要按钮是药丸，则所有主要按钮都使用该药丸处理；如果它使用受控的6-10px半径，则一致地重复该处理。标签和过滤器可以使用单独的药丸家族，因为它们的作用是不同的。不要用药丸表示数量控制、大字段、面板或密集操作控制。
- 将相邻控制视为一组：匹配它们的高度、半径和水平范围，并保持它们之间的间隙小于它们周围的间隙。一个只重述旁边标签的图标是装饰；保持图标在它们替换标签而不是重复标签的地方。
- 沿一个轴在一个地方设置间距。在向包装器添加填充之前，检查子元素是否已经携带它，因为继承的组件CSS通常是这样，两者会堆叠。
- 当你改变填充、行高或高度时，重新检查任何与该元素对齐的内容。绝对定位的切换和嵌入指示器不会随它移动，并且添加的偏移量会在任何其他东西改变时漂移。
- 除非提升传达行为，否则避免使用阴影。
- 当需要阴影时，使用一个几乎看不见的中性阴影，而不是一个大的模糊。在接近黑色的画布上，阴影什么也不做，因此等效工具是一个几乎看不见的白色径向辉光，在完全相同的测试下允许使用。对辉光的升级触发针对装饰，而不是提升。

## 结构重新设计

布局和构图在现有结构阻止技能的层次结构、清晰度或章节节奏时都在范围内。保留产品含义、内容、功能和交互结果—not 现有的DOM或排列。

结构权限不是重新排列一切的责任。当它已经使主要任务和内容关系明显时，保留有效的构图。不要用一个强大、熟悉的 产品布局来替换它，仅仅为了让重新设计看起来更引人注目。

技能可以：

- 改变页面网格、列比例、最大宽度、对齐和部分顺序。
- 移动、合并或拆分部分，以创建更清晰的叙事和任务流程。
- 用分隔符、功能行、编辑章节或一个主导的媒体构图替换重复的卡片网格。
- 重新构图英雄、导航、社会证明带、产品演示、评价、比较或页脚。
- 将支持内容移近它解释的控制或结果。
- 将一个分散的小视觉集合变成一个大的产品截图、照片、视频或插图。
- 在新构图需要更清晰的实现时创建或提取组件。
- 使用不同的桌面和移动构图，而不是在较小尺寸上保留相同的网格。

在做出大的布局更改之前，说明结构问题并说明预期层次结构。优先考虑一个连贯的构图而不是许多局部的重新排列。不要仅仅为了让页面看起来稀疏而移除内容或功能。

媒体后面的填充可能是一种可供性而不是装饰。图像下方的平面面板通常是图像加载时保留位置的占位符，因此移除它会将每个未加载的图像变成一个带有孤儿标题的白色洞。在清除媒体后面的背景之前，检查未加载状态。

装饰保留的空间在装饰消失时不会消失。围绕插图的一条带状装饰，或为了清除装饰而偏移的网格，留下的空白看起来是空虚而不是平静，在小尺寸上也是如此，一个仍然保留着您移除的图标的控件也是如此。故意关闭释放的空间。

当装饰也是控件唯一的可见输出时——一个选择器改变的渐变，一个按钮重播的动画——安静它并不等于删除它。将其去饱和，以便控件仍然有话可说，并验证状态彼此之间仍然可区分。

当装饰因项目而异时，将其扁平化而不是去饱和。每个瓦片后面不同的色调变成了每个瓦片后面的不同灰色，这看起来像是不存在的编码；一个单一的平面表面说明了原始内容，而原始内容什么也没有。

然后检查容器是否仍然值得它的位置。按项目扁平化颜色是使不同瓦片的网格变成相同盒子的墙的方法——这种一致性是由过程产生的，而不是继承自页面，而填充的多样性被留下承载着无。通常的答案是删除它，让类型层次结构和间隔来做分组。

在媒体上铺上着色的渐变通常有两个作用。去除其色调也会去除遮挡其上文本的可读性的帘幕，因此请保持帘幕为中性，并仅删除颜色。

对于商业和产品详情页面：

- 使产品媒体成为主要的视觉锚点。
- 在桌面端，当阅读方向支持时，默认在左侧使用大型画廊，在右侧使用紧凑的产品和购买列。
- 将产品名称、价格、选项、可用性和主要购买操作放在一起。特别留意中断：促销瓦片、计划链接或插入价格和交付检查之间的服务模块与将它们放在不同章节中一样有效地分割购买路径，而且更常见。名称、价格、选项、可用性或购买操作之外的东西不属于它们之间。
- 不是每个产品都有变体控件。在没有色样或尺寸的情况下，选项插槽由测量值、系列和目录链接填充，而这些属于购买块而不是它周围的页面。
- 媒体主导性是垂直的，也是水平的。一个高度是画廊两倍高度的购买列通常在购买操作下方积累了服务、忠诚度、融资和保护模块；降低尾部而不是加宽列。
- 当购买操作不可用时，禁用控件保留其插槽并在可读对比度下说明原因——您无法购买某物的理由绝不能是页面中最不清晰的文本。实时替代方案，无论是找到类似项、通知我还是更改商店，可能承载主要权重，因为它是指向访客实际可以采取的唯一操作。
- 基线对齐价格。商业系统习惯性地将货币和分币设置为半大小；将整个价格设置为相同的大小和重量通常是页面上可用的最高影响力的约束。
- 不要将主要产品图像推到长购买前言下方或将其减少为支持装饰。
- 在移动端，首先堆叠画廊，然后是产品详情、选项和购买操作。
- 只有当另一个布局明显提高了产品评估或任务完成时才偏离此模式。

## 没有源访问的网站

此技能是为可以更改的代码库编写的——标记、样式、组件和令牌——上述所有内容都假设该控件。优先编辑系统而不是在其上分层：更改令牌而不是覆盖其消费者，删除规则而不是重置它，当一个是做两件事时拆分组件。与现有代码作斗争的覆盖是关于代码的发现，而不是解决方案。

当目标是已交付或第三方网站而无法编辑时，请阅读 [websites.md](websites.md) 以获取受限的CSS覆盖回退及其支架。明确地说，此模式有一个较低的上限：布局只能弯曲到现有DOM允许的程度，而源级重新设计会走得更远。

## 页面布局和叙事

对于营销、编辑和产品页面：

- 给每个主要章节一个清晰的想法。一个有用的重复结构是：简洁的标题、一个简短的说明、三个或四个功能摘要，然后是一个主导的产品视觉。
- 交替白色和非常浅的中性区域填充，如 `rgb(0 0 0 / 4%)`，以在添加边框或容器之前创建节奏。深色画布没有“非常浅的填充”可用，所以它的等效物是一个真正浅色的带用作中断，或者什么都没有。
- 使用一个超大型的截图、照片、视频或实体产品布局作为章节的视觉锚点。当内容值得沉浸时，让它接近全宽。
- 优先选择几个大型章节容器而不是许多小型卡片。大型媒体章节可以使用受约束的半径；其内部内容不应成为另一个卡片网格。
- 将客户和合作伙伴的标志保持单色并均匀分布，以便社会证明保持安静。这是保持产品自己的标志全彩的对应物：第三方标志是证据，不是身份，它们在原始颜色中的一行是大多数页面中最响亮的条带。这同样适用于支付标志，其形状承载着识别。
- 使用一个大型评价、案例研究图像或编辑性拼贴作为系统中的偶尔中断。一个表达性的中断比每个部分中的装饰更有个性。
- 当卡片不必要时，将功能摘要作为图标、短动词和一行结果呈现。
- 两种色调的内联标题——第一句话全墨水，其延续在同一大小和基线上约为60%——为营销页面提供了真正的层次结构，而不需要第二种重量或第二种大小，并且在中性化过程中保持完整。
- 每个章节一个填充的主要操作是长营销页面的模式，而不是违规。范围“谨慎”到视口而不是文档。
- 当填充的强调操作与产品自己的标志在同一区域附近时，按钮将优先于标志，身份时刻就会丢失。使按钮中性，并让标志是那里唯一的颜色。这假设标志有颜色被优先级超过；当标志以黑色交付时，没有要保护的身份时刻，强调可能保持。
- 相同的推理适用于比例，而不仅仅是颜色。当名牌和英雄标题都大声喊出显示尺寸时，名牌是在与页面竞争而不是引领。保持超大型的标志是合理的，只有当它旁边的的东西被降级时，并且然后标志比它原来做了更多的身份工作，因为它不再是两个之一。
- 让页脚变得更密集，但保留相同的排版、对齐和中性处理。
- 在移动端，保留每个章节的顺序和层次结构。堆叠并简化；不要仅仅缩小桌面布局。

## 交互和运动

运动应该感觉安静、立即和有目的的。仅用于反馈、空间连续性、状态指示或防止令人震惊的变化。

- 不要对键盘启动或非常频繁的操作进行动画。
- 减少用户每天执行几十次操作的交互的运动。
- 保持普通UI运动在300ms以下；仅对罕见的解释性时刻使用较长的运动。
- 使用 `ease-out` 进行进入和退出，`ease-in-out` 进行屏幕上已有的运动，`ease` 进行颜色或悬停过渡。避免对响应式UI使用 `ease-in`。
- 优先选择 `transform` 和 `opacity`；当复合替代方案存在时，避免动画布局属性。
- 永不从 `scale(0)` 进行进入动画。当比例合适时，使用带有不透明度的微妙 `scale(0.95–0.98)`。
- 将弹出框和菜单锚定到它们的触发器；居中的模态框可以保持居中。
- 如果按压力反馈适合产品，请使用微妙的 `scale(0.97)`，持续约100–160ms。
- 使快速触发和手势驱动的运动可中断。
- 尊重 `prefers-reduced-motion`，在删除不必要运动的同时保留有用的颜色或透明度反馈。
- 将仅悬停运动限制在 `(hover: hover) and (pointer: fine)`。

不要仅仅为了使静态界面感觉精致而添加动画。当不确定时，删除或减少它。

停止永久的装饰性运动意味着将其返回到静止，而不是冻结它。仅禁用动画将元素留在其最后一帧放置的位置，对于滚字幕或轮播图来说是一个随机的偏移量，内容被切掉了容器边缘，对于淡入来说可能是完全透明。清除动画正在驱动的转换或透明度，并在捕获中确认静止状态是您打算的状态。

## 升级触发器

在范围内发生时纠正这些，除非品牌或功能明确要求它们：

- 着色的暖色或冷灰色代替中性alpha-黑色调，包括从设计系统继承的默认边框颜色。系统性地从产品自己的品牌颜色派生并一致使用的中性是品牌，而不是用于纠正的色调。
- 希腊体显示排版或混合希腊体/无衬线系统
- 全大写文本或CSS `text-transform: uppercase`
- 全小写导航或控件标签
- 用作界面图标语法的表情符号
- 分隔元素与其自己的标题、标签或元数据的分隔符
- 屏幕上的规则比读者能数的更多，而空间可以完成同样的工作。在密集查找表面上分隔同级元素的规则是在购买密度，所以在计算它们作为杂乱之前，询问什么会替换它们。
- 没有意义的装饰性渐变、纹理、发光或饱和颜色
- 仅用于使表面看起来高级的大或分层阴影
- 没有主导元素的均匀卡片。大小和容器的混合布局，每个都包含真实的产品媒体，是一个便当，而不是卡片网格，扁平化它移除了产品展示而不是描述的唯一地方。
- 用于普通矩形控件或容器的药丸
- 相当按钮和CTA之间混合的半径、高度或填充
- 不一致的间距、对齐、半径、边框不透明度或图标处理
- 类型样式或字体权重多于层次结构需要的
- 过大的标题或空白，减少了有用的密度
- 低对比度的正文文本或控件
- 从状态、焦点、警告、错误、成功、选中、活动或破坏状态中删除颜色
- 伴随语义颜色的形状或符号被扁平化，留下仅由色调携带的状态。检查剩余的是否仍然足够强，可以被视为状态：一个仅通过发丝线与其邻居区分的选中标签，一旦其填充变为中性，在技术上保持了区别并失去了可供性。重新编码它，而不是确认是否存在差异。
- 语义颜色作为排版或标签规则的副作用被删除。这是它通常丢失的方式，而不是故意的调色板更改：一条突发新闻标志和一条普通的开场白通常是相同的元素，具有相同的标记，仅由它们读取的令牌区分，所以一个同时设置 `color` 的关于大小和跟踪的规则将状态与它一起带走，而您仔细保留的令牌保持不变。
- 没有功能目的的运动

## 纠正顺序

优先考虑早期的移动而不是晚上的：

1. 修复页面流、层次结构、寻路、分组和控制到内容映射。
2. 当当前布局阻碍这些目标时，重新结构布局。
3. 删除装饰、冗余表面和重复标签。
4. 规范间距、对齐和信息密度。
5. 规范排版、度量、跟踪和行高。
6. 将颜色、边框、半径和高度合并到共享令牌中。更改任何令牌之前，找到所有消费者并检查每个消费者用它*做什么*，因为同一个值会使填充安静，但会使边框响亮：一个强调变为黑色会使阅读它的每个按钮安静，并将柔软的金色发丝线变成坚硬的黑色框，在改变后比改变前更响亮。设计系统也将在多个角色中花费一个令牌，所以一个品牌令牌通常被用作活动状态的别名，而装饰性徽章可能正在借用真实错误状态的价值。当一个令牌服务于两个工作，这通常是发现——将其拆分而不是选择折衷值。
7. 精炼控件、可供性、焦点、悬停、按下、禁用、加载、空和错误状态。
8. 静态层次结构工作后，仅添加或调整运动。

## 工作流程

1. 确定调用模式和确切范围。
2. 完成重建并确定主要任务和层次结构。
3. 评估候选更改与操作姿态。
4. 按纠正顺序应用更改，重用并扩展现有系统，而不是创建一个平行的系统。
5. 机械和视觉验证。
6. 报告更改了什么，为什么，以及什么被故意保留。

## 验证

### 浏览器验证

如果存在任何浏览器、预览、截图或计算机使用工具，则需要视觉验证：

1. 启动或定位真实应用程序并打开更改的确切路由。
2. 在更改前后捕获固定的桌面和移动截图。
3. 检查渲染的截图，而不是依赖代码或DOM结构。
4. 测量交互状态，而不是拍摄它们。一个悬停、焦点或按下规则可能会失去特异性比赛并简单地不会触发，这是截图无法揭示的，所以强制状态而不是信任您编写的规则是获胜的规则。
5. 在渲染输出中验证删除，而不是在声明中。不是每一行都是边框：界面用 `box-shadow`、`::before` 或 `::after` 棒，或一个折叠成一个像素的元素绘制它们，所以删除一个 `border` 并不是证据线已消失。枚举界面实际绘制的而不是源提到的。
6. 放大检查小控件。几像素的错位在页面比例上是看不见的，并且将幸存于修复和全页验证通过。
7. 执行主要交互、键盘焦点、悬停或按下状态，以及任何更改的响应行为。
8. 给窄视口自己的通过，而不是检查。为宽列编写的填充、内边距和边框是手机宽度的大一部分，并且规则在1440px时是精细的，在390px时是回归。
9. 检查浏览器控制台中的错误和视口中的裁剪或水平溢出。
10. 对于长页面，滚动通过每个章节并捕获整个页面或多个视口段；第一折是不够的。
11. 纠正可见问题并重新捕获，直到结果通过。

如果无法提供浏览器工具，请说明视觉验证不可行。永远不要声称仅从代码检查就进行了视觉验证。

此列表中的四个检查很难通过肉眼完成，并且已在 `scripts/` 中脚本化，与该文件一起。每个都需要一个URL，通常是您开发服务器上的路由，并且只需要 `playwright-core` 加上本地Chrome。

- `node scripts/lines.js <url>` — 页面绘制的每条规则（水平和垂直），以及绘制它们的机制。在移除分隔符的任何步骤之后运行它。
- `node scripts/tints.js <url>` — 被标记为中性淡色的颜色通道，以及单色步骤需要考虑的饱和色清单。
- `node scripts/density.js <url>` — 每屏可见的项目，以便密度声明是测量而非估计。
- `node scripts/bands.js <url>` — 长页面被切割成可审查的视口高度片段。

与其假设一次干净的运行意味着一个干净的页面，不如阅读它们打印的内容：每个回答一个狭窄的问题，上面的章节说明了每个问题在哪里容易误导。

命名你无法达到的状态，而不是暗示整个表面都被检查了。在截图框架中，访问过的链接、错误和加载状态以及经过身份验证的视图通常是无法访问的。

当验证步骤反复因相同原因失败时，将检查作为脚本编写，而不是决定更加小心。一个使失败可见的工具比另一个要求注意它的指示更有价值。

使用逼真的桌面和移动尺寸以及逼真的内容检查结果。验证：

- 主要任务和下一步操作是显而易见的。
- 导航回答用户在哪里、可以去哪里以及如何离开。
- 分组遵循邻近性，控件靠近它们影响的元素。
- 长文本、空状态、加载、错误和密集数据不会破坏布局。
- 对比度、键盘导航、可见焦点、触摸目标和语义状态保持可访问性。
- 较大的文本和窄屏幕不会破坏层级结构。
- 没有重复绘制。匹配预期设计并不是你的规则产生了它的证据，所以在添加自己的声明之前，检查现有的声明是否已经绘制了相同的像素。
- 没有任何东西意外地变得有意义。移除颜色可能会揭示在所有内容饱和时不可见的编码，当结果比原始版本更易读时，就停止进一步向单色推进。
- 左对齐只有在容器、每个中间包装器和文本节点本身都被检查后才能完成。居中对齐堆栈，并修正三个机制中的两个，会留下一个居中的块，而其文本却是左对齐的，这比开始时更糟。
- 长页面有故意的章节节奏，不会变成重复的卡片堆栈。
- 结果通过识别测试：只显示最终状态，一个从未见过原始版本的设计师会将其读作一个有意设计的斯堪的纳维亚表面，而不是原始版本移除了颜色。
- 原始表面的每个交互能力——操作、控件、导航、输入、切换器——仍然存在且可访问。清点功能，而不仅仅是内容和链接；静音控件是可以的，移除它则不行。
- 表达性的颜色保持在有目的的媒体或唯一的允许的主要强调色内。
- 悬停、按下、选中、禁用和破坏状态仍然可区分。
- 减少运动行为在存在运动的地方是存在的。
- 控制台干净，现有的检查仍然通过。

如果视觉检查显示歧义、过度空旷或效率降低，请恢复必要的上下文或密度并再次检查。

## 安全限制

不要：

- 使破坏性和中性操作在视觉上无法区分。
- 移除理解所需的标签或边界。
- 在从未有过主要操作的表面上发明一个主要操作。一个主要操作最多只有一个，而不是正好一个。
- 将品牌标志去饱和以匹配调色板。
- 在未经要求的情况下替换已建立的产品身份。
- 仅仅为了最小化代码差异而保留一个薄弱的布局。
- 当现有组件可以很好地解决问题时添加依赖项。
- 仅仅为了创建一个更干净的截图而隐藏高级功能。
- 将新颖性混淆为改进。

## 审查输出

对于审查模式：

1. 按优先级顺序呈现发现。
2. 对于每个发现，说明当前条件、建议目标，以及它如何改进产品。
3. 将必要的更正与可选的润色分开。
4. 包括一个简短的 **保留** 部分命名不应更改的品牌、语义颜色、有用边界、密度或交互模式。
5. 以裁决结束：已经连贯、需要集中改进，或需要结构重设计。

对于应用模式，总结最高影响力的更改、执行的验证以及任何无法视觉检查的限制。

## 输出标准

结果应感觉平静、功能化、精致和有意简单。当不确定时，使界面更安静——而不是更少可用。
