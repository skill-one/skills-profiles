# 创建技能

创建扩展智能体能力的有效技能的指南，这些技能包含专业知识、工作流和工具集成。

## 关于技能

技能是模块化、自包含的软件包，通过提供专业知识、工作流和工具来扩展智能体的能力。可以将它们视为特定领域或任务的“入职指南”。

### 技能提供的内容

1. 专业工作流 - 特定领域的多步骤流程
2. 工具集成 - 与特定文件格式或API交互的说明
3. 领域专业知识 - 公司特定知识、模式、业务逻辑
4. 打包资源 - 用于复杂和重复任务的脚本、参考和资产

## 渐进式披露原则

**200行规则至关重要。** SKILL.md 必须少于200行。如果需要更多内容，请将内容拆分到 `references/` 文件中。

### 三级加载系统

1. **元数据（名称 + 描述）** - 始终在上下文中（约100字）
2. **SKILL.md 正文** - 当技能被触发时（<200行，理想情况下<500行以获得最佳性能）
3. **打包资源** - 按智能体需要（无限制）

### 为什么渐进式披露很重要

- 初始上下文负载减少85%
- 激活时间从500ms+ 减少到小于100ms
- 智能体只加载需要的内容，在需要时加载
- 技能保持可维护性和专注性

## 技能结构

```
skill-name/
├── SKILL.md (必需，<200行)
│   ├── YAML 前置元数据 (必需)
│   │   ├── name: (必需)
│   │   └── description: (必需)
│   └── Markdown 说明 (必需)
└── 打包资源 (可选)
    ├── scripts/          - 可执行代码
    ├── references/       - 按需加载的文档
    └── assets/           - 用于输出的文件
```

## 核心原则

### 简洁至上

上下文窗口是共享资源。您的技能与智能体需要的一切共享这个资源。请保持简洁，并挑战每一块信息：
- 智能体是否真的需要这个解释？
- 我能否假设智能体知道这些？
- 这段话是否值得它的token成本？

### 设置适当的自由度

- **高自由度**：针对多种有效方法的文本说明
- **中等自由度**：带有参数的伪代码或脚本
- **低自由度**：具有很少或没有参数的特定脚本，用于易碎操作

### 对所有模型进行测试

技能作为模型的补充，因此其有效性取决于底层模型。请使用您计划使用的所有模型测试您的技能。
