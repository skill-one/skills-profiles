# DeepPaperNote

当用户希望得到以下结果时，使用此技能：
- 仔细阅读一篇论文
- 生成高质量的 Markdown 笔记
- 将笔记保存到通过配置解决的工位空间或 Obsidian 目标

中文触发示例：
- `给这篇论文生成深度笔记`
- `写一篇高质量论文精读笔记`
- `把这篇文章整理成 obsidian 笔记`
- `读这篇论文并生成 md 笔记`

英文触发示例：
- `为这篇论文生成深度阅读笔记`
- `将这篇论文转换为 Obsidian 研究笔记`

## 用户配置

在正常论文运行之前，请阅读 `references/user-configuration.md` 以进行配置接纳、迁移、修复、运行覆盖和偏好更改。

首先从明确的请求、CLI 和当前进程环境解决运行覆盖。当它们为选定的保存模式形成完整有效的配置时，配置就绪即可完成，无需读取用户配置。仅在运行覆盖需要回退值时才检查用户配置。

## 语言完整性契约

在配置就绪之后，为运行解决一个 `output_language` (`zh-CN` 或 `en`)。`source_manifest.language_hint` 仅描述源文本，永远不会选择笔记配置文件。

通过保存目标接纳 → 制定计划 → 制定/表格决策 → 综合包 → 笔记计划 → 基础校验 → 最终笔记校验 → 最终质量审查 → 最终可读性审查 → 正式保存绑定该确切值：

- 链中的每个 JSON 工件都携带顶级 `output_language`；综合包也在 `writing_contract.language` 中携带相同的值。
- 在生成其输出之前，每个相邻的消费者都需要每个输入语言，并将其与解析的值进行比较。缺失、不支持或不匹配的值将停止运行；没有阶段推断或默认工件的语言。
- 最终质量审查和最终可读性审查各自接收解析的值，并仅根据该配置文件检查笔记。
- 最终笔记校验记录 `note_sha256`。任何审查编辑都会使先前的校验失效，因此需要在相同的语言下重新运行最终笔记校验。正式保存需要校验语言和 `note_sha256` 与最终笔记匹配，并在任何保存副作用之前验证制定/表格决策的语言。

当每个命名阶段都绑定到解析的值并且正式保存验证了最终字节时，此契约才完整。在起草或调试任一语言时，请阅读 `references/output-language.md` 以了解配置文件内容。

此技能故意范围狭窄：
- 它是一个标准的技能和一个具有两个输出配置文件的管道
- 它一次处理一篇论文
- 它不会更新每日阅读列表
- 它不会将浅层摘要重写视为成功输出
- 它不会将公共入口点拆分为单独的设置、故障排除或启动命令

## 核心标准

完成的笔记必须不仅仅是摘要。它应该重建论文的论点：
- 它解决了什么问题
- 任务是如何定义的
- 它使用什么数据或材料
- 方法或分析实际上是如何工作的
- 最重要的结果是什么
- 论文没有证明什么
- 为什么这篇论文值得保留

默认写作者角色：
- 顶级研究人员或算法工程师
- 正在编写面向复制的实验笔记
- 不是在写科普解释
- 假设读者可以理解 Python、PyTorch、训练循环和评估逻辑

笔记必须适应论文类型。使用相同的基结构，但对于 AI 方法、基准、临床研究以及人文或社会科学论文，要调整重点。

## 工作流程

按此顺序执行：
1. 完成配置就绪：首先解决运行覆盖，仅在它们不完整时才检查用户配置；只有在解析的运行配置完整且有效后才能继续
2. 解析论文身份
3. 收集元数据
4. 使用接受的身份和原始用户参考（`fetch_pdf.py --reference`）获取最佳可用 PDF；在 Obsidian 模式下，在下载之前验证并重用匹配的本地存档，遵循 `references/paper-archive.md` 进行版本/来源选择
5. 提取规范原始源文本：`*_raw_sections.jsonl`、`*_source_manifest.json` 和可选派生的 `*_full_text.md`
6. 在起草或域路由之前执行保存目标接纳：
   - 对于 Obsidian 模式，使用解析的标题、确切的 `output_language`、Vault 和 `*_source_manifest.json` 运行 `scripts/write_obsidian_note.py --preflight`；该程序结果是权威的，因此不要用仅提示的重复检查来替换它
   - 当接纳返回重用结果时，使用该目录并跳过域选择；一个经过验证的 PDF-仅目录不需要注册确认。从预检中读取 `asset_subdir` 并用于源绑定图嵌入
   - 当它返回 `same_language_note_exists` 时，在起草之前停止并询问是否要覆盖报告的笔记。如果用户批准，请使用 `--overwrite-existing-note --expected-existing-note-sha256 <reported_sha256>` 重新运行预检，并将该确切确认带入正式保存；如果用户拒绝，则停止不写入
   - 当多个目录或来源匹配时，遵循 `references/paper-archive.md`：询问当前选择并贯穿预检和正式保存
   - 对于任何其他阻塞冲突，报告返回的歧义并停止不创建第二个目录
   - 工作空间模式不会扫描 Obsidian Vault 并通过其正常域路由继续
7. 提取结构索引和 PDF 资产
8. 规划图的位置
9. 构建完整的制定/表格决策表
10. 构建配置文件综合包
11. 让模型阅读包加上原始章节并创建一个满足生成包合同的短 JSON `note_plan`，包括其确切的 `output_language`
12. 只有在基础门通过后才能从计划中起草
13. 让模型编写笔记
14. 对相同的 `note_plan` 进行最终笔记校验 — 此阶段仅在存在校验工件且每个报告的 `passes_*` 门都是 `true` 时才完成；否则修订并重新运行校验。如果校验输出包含 `passes_style_gate: false`，则在进入步骤 15、16 或 17 之前应用样式门强制规则
15. 在校验通过后执行 `final_quality_review`
16. 在质量审查通过后执行 `final_readability_review`
17. 执行正式保存到接纳的目标，使用 `scripts/write_obsidian_note.py`、相同的源配置文件和任何用户批准的覆盖哈希；该脚本在第一个保存副作用之前重复接纳

这是正常单篇论文笔记请求所需的流程，而不是松散的建议。
除非此技能明确将某个阶段标记为可选，否则必须不沉默地跳过必需阶段、重新排序为快捷方式或因为部分工件已存在而将其视为完成。

全局无短路规则：
- 不要在仅完成早期阶段后就呈现工作流程为完成
- 不要将缓慢、不便或临时不确定性视为跳过必需阶段的许可
- 不要用即兴的快捷方式替换声明的流程
- 如果必需阶段失败，只能做三件事之一：
  - 重试该阶段
  - 进入此技能明确允许的回退
  - 停止并报告哪个阶段被阻塞以及哪些下游必需阶段仍不完整
- 不要在必需的下游阶段仍在等待时描述整个任务为完成

完成语言规则：
- 只有当必需的工作流程实际上完成时，才说 `笔记已完成`
- 当起草完成但校验、最终可读性审查或保存仍在等待时，才说 `已生成草稿`
- 只有当校验实际上已运行并通过时，才说 `已通过校验`
- 只有当写入步骤实际上成功时，才说 `已保存到 Obsidian`
- 不要将 `lint 已通过` 视为等同于 `整篇笔记已经润色完成`
- 如果最终可读性审查仍在等待，请明确说明草稿通过了脚本校验但尚未完成最终语言审查
- 如果工作流程提前停止，请指明当前阶段和仍然缺失的必需阶段，而不是使用完成语言
- 校验是一个底线，而不是写作目标

最终用户报告：
- 保持上述定义的完成措辞。在成功正式保存后，以用户的对话语言报告。
- 首先报告最终笔记链接或路径、保存模式以及实际保存的域。在 Obsidian 模式下，从配置的论文根目录下的最终笔记路径或工作空间模式下的输出根目录中读取域；当保存目标重用了一个现有目录时，报告该目录的现有域。
- 然后，按顺序报告：
  1. 论文标题和最强的验证标识符
  2. Grounding Lint、Final Note Lint、Final Quality Review 和 Final Readability Review 结果，以及警告计数
  3. 实际化和保留占位符的制定/表格计数
  4. 保存的笔记 SHA-256 是否与 Final Note Lint 的 `note_sha256` 匹配
- 仅在发生时才添加覆盖操作、偏好更改或用户相关警告。
- 保持这些字段并从当前运行工件中推导出每个声明。

## 核心执行契约

`SKILL.md` 加上生成的 `synthesis_bundle.json` 必须足以完成一个正常的笔记生成运行。
`references/` 下面的文件是可选的阶段特定深入探讨，不是默认的阅读清单。

不可协商规则：
- 证据优先：从综合包、`source_manifest`、原始章节、覆盖元数据、明确的 `note_plan` 和审查的论文证据起草；从不单独从标题/摘要/标题中完成
- 原始源权威：对于普通 PDF，`*_raw_sections.jsonl` 和 `*_source_manifest.json` 是规范的阅读材料；旧的 top-N 证据桶、截断的 `section_texts` 和 `candidate_chunks` 不是模型面对的写作输入
- 关闭失败：在支持获取路径后无法获得可用的 PDF 或足够的证据时，停止并请求更好的源材料，而不是生成一个完成的降级笔记
- 模型优先：脚本结构证据，但模型必须在配置的语言中决定重点、贡献、机制、局限性和最终散文
- 必需结构：包括本地化的规范章节，按 `writing_contract.must_include_sections` 声明的顺序
- 摘要保真度：在不添加后期证据或模型判断的情况下保留原始摘要的含义；在 `zh-CN` 模式下翻译它，并在 `en` 模式下忠实地渲染它
- 机制深度：方法、框架和系统论文应包括本地化的机制流程子章节，通常作为具有输入、操作和输出目的地的 3 到 4 步编号流程
- 占位符优先图：首先规划主要图/表格占位符；仅在身份匹配和视觉可用性都强时才替换一个；否则保留占位符

参考使用策略：
- 不要默认加载每个参考文件
- 仅当论文复杂或草稿太浅时，才咨询 `references/evidence-first.md`、`references/deep-analysis.md` 或 `references/final-writing.md`
- 仅当图/表格位置不明确或图像替换决策时，才咨询 `references/figure-placement.md`
- 仅当存在 Obsidian 目录、本地 PDF 版本选择或 Connector 交接时，才咨询 `references/paper-archive.md`
- 仅当 Markdown、Vault、frontmatter 或参考链接格式细节时，才咨询 `references/obsidian-format.md`
- 仅在最终审查或域适应时，才咨询 `references/note-quality.md` 或 `references/paper-types.md`
- 仅当元数据不完整时才咨询 `references/metadata-sources.md`，仅当仓库维护决策时才咨询 `references/architecture.md`

## 工具和源优先级

优先使用此顺序中最强的可用源：
1. 用户提供的本地 PDF 路径
2. 如果可用，本地 Zotero 项目和本地 Zotero 附件
3. 接受的工作和请求版本的经过验证的本地 Obsidian PDF
4. DOI 和出版商元数据
5. arXiv 或开放获取 PDF 源
6. Semantic Scholar 或 OpenAlex 用于元数据回填

在 Web 解析之前，使用捆绑的 `scripts/resolve_paper.py` Zotero Local API 路径检查桌面库。其默认 `--zotero-mode auto` 优先匹配唯一的本地匹配，并在 Zotero 不可用或没有匹配时回退到现有提供程序。明确的 Zotero 密钥没有安全的 Web 回退，必须在本地验证。使用 `off` 以使不进行任何本地 API 请求，或使用 `required` 当参考必须通过 Zotero 解析时。一个可信的 JSON 工件或显式的本地 PDF 剩余权威并绕过此查找。兼容的会话范围 Zotero/MCP 集成在可用时仍可能提供可信的输入工件，但它不是内置路径所必需的。

本地库优先规则：
- 首先使用论文标题、DOI、arXiv id 或确切的 Zotero 项目键搜索本地 Zotero 库
- 如果 Zotero 找到论文，则将此结果视为规范的身份解析步骤。
- 优先使用内置 Local API 返回的安全本地附件路径。如果另一个兼容的集成仅暴露附件键和文件名，请使用 `scripts/locate_zotero_attachment.py` 找到用户 Zotero 存储下的 PDF
- 如果本地附件路径可用，请将其转发为首选 PDF 源
- 如果找不到本地附件，仍然使用库解析的元数据以避免标题歧义，然后仅对于文件本身回退到网络 PDF 获取
- 如果多个本地项目同样合理，则关闭并请求 DOI、arXiv id 或确切的 Zotero 键，而不是任意选择一个
- 不要让较弱的标题仅互联网匹配覆盖自信的本地库命中

## 输出规则

正式保存状态：

| 保存目标状态 | 必需操作 |
|---|---|
| `save_mode=obsidian` 且配置的 Vault 可用 | 执行该 Vault 的正式保存。 |
| `save_mode=obsidian` 且正式保存失败 | 保持当前保存目标并尝试范围内的恢复。如果仍然无法完成，报告 `blocked`；不要切换到工作空间。 |
| `save_mode=workspace` | 在当前工作空间输出根内执行正式保存。 |

- 一个正常的笔记生成请求应该在单次遍历中完成：笔记文本、图表占位符决策、有信心时图像材料化，以及最终保存。
- 不要在纯文本草稿后停止，询问用户是否要插入图表。在同一个任务内部完成图表替换决策，除非用户明确要求仅文本。
- 笔记必须使用真实的标题级别：`#`、`##` 和 `###`。
- 每个最终笔记必须在 `#` 标题标题上方开始一个 Obsidian YAML 属性块。至少包含一个带有 `papers/<domain>` 值的 `tags` 字段和有用的 `aliases`；当知道时，包含 `date`、`doi` 或 `arxiv_id`，并省略不可用的字段，而不是编造占位符。
- 本地化的核心信息部分必须是一个固定的元数据块。仅使用 `writing_contract.core_info_fields` 声明的字段和顺序；省略不可用的字段，并将评论移至后续分析部分。
- 当有摘要元数据时，在单句摘要之前，在笔记开头附近包含本地化的摘要部分。
- 摘要部分应忠实地以配置的语言渲染论文的原始摘要，而不是用模型编写的摘要替换它。
- 不要将后续判断、贡献总结或事后解释混合到摘要部分。
- 立即包含一个本地化的贡献部分，紧随摘要之后，并在单句摘要之前。
- 贡献应列举论文的实际创新，并解释每个创新为何重要，而不是提供空洞的赞扬。
- 当论文非平凡时，高质量的笔记通常应在技术部分包含多个有意义的 `###` 子标题。
- 在草稿或保存之前，生成完整的图表/表格决策表并满足生成的 `writing_contract.figure_table_contract`。
- 在构建合成包后，在创建 `note_plan` 之前，完成模型领导的视觉审查门和图表/表格决策冻结；不允许 `review_pending` 项目跨越该边界。
- 在推进之前，通过基础和最终笔记图表门；修订任何失败的决策覆盖、插入、结构或状态检查。
- 只有在正式保存将选定的图像材料化到论文本地的 `images/` 目录并写入成功后，`insert` 决策才完成。
- 笔记必须通过其配置语言的样式门：`zh-CN` 拒绝混合中英文本的文本艺术品，而 `en` 拒绝在引用元数据之外的中文本。
- 样式门也拒绝机械术语替换的艺术品，例如 `KV缓存 of`、`批量ing`、`In相关 Researcher` 或 `Single 序列 generation`；自然地重写句子，而不是保留部分翻译的短语。
- 样式门执行：当 `lint_note.py` 输出包含 `passes_style_gate: false` 时，修复报告的问题并重新运行 lint。持续修复和重新运行，直到 lint 通过——多轮是正常且预期的。不要认为任何失败都是可接受的例外——专有名词、数学公式和引用元数据不是自动豁免。只有在相同失败在多轮中未改变且没有减少，表明模型无法独立进一步进步时，才升级给用户。
- 如果 PDF 或证据质量不足以生成真实的深度笔记，则关闭失败：停止，报告受阻阶段，并要求更好的 PDF、OCR/源材料或其他继续所需的输入。

模型优先规则：
- 脚本可以收集和结构化证据
- 脚本不得是理解论文的主要机制
- 最终论文理解和笔记编写属于模型
- 使用生成的包合同来选择论文类型、部分语义、有证据支持的声明、边界、比较和可重用的后续问题；脚本建议仍然是提示而不是写作权威
- 不要要求或暴露一个长的自由形式的 `<thinking>` 块
- 对于技术论文，优先选择可复制级的解释而不是高级摘要
- 如果公式、目标或复杂性表达式是核心的，在最终笔记中包含关键公式
- 将数学渲染为 `$...$` 或 `$$...$$`，而不是内联代码或围栏代码块
- 在最终保存之前，明确自我审查笔记是否包含足够的技术细节、关键数字和任何必要的公式
- 在 `final_quality_review` 期间，检查完整笔记是否符合七个问题：中心证据链是否完整、是否包含关键设置和数字、机制或协议是否映射到它们解释的结果模式、论文是否定位在强大的基线或替代路径上、讨论/限制结论是否机制化解释、已证明的声明是否与未证明的声明分开、研究、工程、复制或有效性要点是否足够具体以供重用
- 三个或更多系统、设置、任务、数据集、指标或消融行的中心定量比较通常应写成紧凑的 Markdown 表格，然后进行解释；当表格更清晰时，不要将主结果表格作为松散的要点列表留下
- 短论文仍然需要一个完整的深度笔记：使用保存的空间来解释协议细节、消融、限制和部署或复制影响，而不是将笔记压缩成简短摘要
- 在 `final_quality_review` 通过后，再次通读完整笔记以确保可读性；不要仅在形式合规性上停止
- 在 `final_readability_review` 中，将配置语言的文本残余重写为自然散文，同时保留稳定的专有名词
- 不要使用 `final_readability_review` 来编造新事实、空填充文本或更浅但更安全的措辞，只是为了满足 lint

上述主题参考可以改善困难的运行，但正常执行路径不应依赖于阅读所有它们。

## 限制

- 如果论文身份不明确，确认后再编写。
- 如果在尝试了所有支持获取路径后 PDF 不可用，停止并报告所需的输入；不要生成降级的、临时的或仅摘要的笔记作为最终输出。支持的获取路径包括本地 PDF、Zotero 附件、元数据 `pdf_url`、直接 PDF URL、arXiv/开放获取来源、如果可访问的出版商 PDF、DOI 增强以及工作流实现的任何其他当前获取路径。
- 需要占位符优先的图表规划；图像提取是可选的，并且必须永远不会减少文本覆盖。
