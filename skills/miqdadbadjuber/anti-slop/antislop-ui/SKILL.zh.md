# antislop-ui

> Anti Slop: AI 编码代理的规则。UI 与视觉技能

> antislop 系统的一部分。与 `antislop.md`（核心）一起阅读。此技能深入探讨 UI/视觉问题：颜色、布局、组件、装饰、结构流程和动画。它通过编号引用核心规则，并且从不重复或重新编号它们。在构建或编辑网站、网络应用或任何界面时加载它。

## 如何使用此技能

- 每次进行 UI 或视觉工作时，都与 `antislop.md` 一起加载。核心包含机制（目的测试、三个层级、交付门）；此技能包含 UI 特定的深度。
- 每个条目都具有相同的结构：**说明**（模式）、**原因**（为什么看起来像垃圾）、**修复**（应该做什么），并引用作为治理核心规则 R-XX。
- 核心中的交付门仍然是门。此文件末尾的“UI 技能清单”是与它一起运行的 UI 特定补充。

## 视觉与颜色

### 通用蓝紫色渐变

- **说明：** 蓝色到紫色、蓝色到青色或紫色到粉色的渐变用作主要颜色处理，或全页彩色光晕。
- **原因：** 训练数据中最常见的颜色处理。它传递“没有品牌标识”，而不是“我们的调色板”，并一眼就标记设计为 AI 生成。
- **修复：** 从 `DESIGN.md` 或产品自身的身份中提取调色板。仅将渐变作为带有说明的原因的层级功能保留（R-01）。将一个层级与另一个层级分开的渐变是工艺；每个部分都使用相同的渐变是默认的。
- **相同的默认系列：** 严厉或彩虹渐变、紫色和黑色方案、霓虹或粉彩色调板，以及英雄背景后的模糊径向球。它们穿着不同的衣服：颜色来自模型的默认值，而不是来自品牌。所有这些都因没有目的而被禁止作为默认值（R-01）。

### 过度使用毛玻璃效果

- **说明：** 导航栏、卡片、模态框和侧边栏同时使用模糊/背景过滤。
- **原因：** 模糊会去除纹理，并将每个表面置于同一磨砂层中，从而扁平化层级。当每个表面都是玻璃时，没有前景。
- **修复：** 将毛玻璃视为点缀，而不是特征。剂量上限：最多 1-2 个元素（R-10）。需要关注的表面获得毛玻璃；其他表面保持实心。

### 过度使用边框半径

- **说明：** 每个元素都是药丸形状：按钮、输入、卡片、徽章、模态框。
- **原因：** 统一的药丸形状抹去了“这是一个输入，这是一个卡片”的视觉语言。半径变成了装饰，而不是层级工具。
- **修复：** 在设计系统中设置一组小半径，并有意应用它们（R-11）。主要 CTA 上有一个慷慨的半径看起来是故意的；每个元素都使用相同的半径看起来是默认的。

### 过于柔和的阴影

- **说明：** 每个组件都带有大阴影，因此整个页面感觉像是在漂浮。
- **原因：** 当所有东西都被提升时，提升传达了什么。页面失去了地面平面，变得通用柔和。
- **修复：** 仅将阴影用作提升标记，并写下提升原因（R-12）。大多数元素应保持平坦；需要提升到页面上的一个或两个元素才携带阴影。

### 到处都有光晕

- **说明：** 卡片、按钮、图标、徽章、背景和边框同时带有光晕。
- **原因：** 光晕是注意力放大器。应用到处都放大不了什么，并且它是看起来“由 AI 制作”的最快方式之一。
- **修复：** 将光晕保留为最多 1-2 个重要元素作为焦点强调（R-13）。其他一切都保持哑光。

### 背景网格

- **说明：** 内容后面的网格方块、蓝图线、坐标纸、点网格或细重复线。
- **原因：** 它是使平面页面感觉“技术性”的默认方式，而无需做任何实际工作。它看起来像纹理但没有意图。
- **修复：** 仅在它真正支持产品身份时使用纹理或图案，并写下原因（R-07）。真实的身份主题（核心第 3 部分）比股票网格每次都更好。

### 没有理由的暗黑模式默认值

- **说明：** 整个页面只是因为看起来“科技感”而变暗，没有任何品牌考虑。
- **原因：** 暗色是一个决定，而不是默认值。强迫它看起来像是在跟随趋势，而不是为产品服务。
- **修复：** 从品牌身份、产品类型和受众中选择主题（R-21）。开发工具和创意工具有使用暗色的合法理由；以内容为主的产品通常没有。如果固定主题没有强有力的理由，则构建一个可工作的亮色/暗色切换器。

### 调色板中颜色过多

- **说明：** 一页上有 5-7 种不同的颜色，没有任何清晰的设计系统。
- **原因：** 散乱的调色板没有层级。当每个元素可以是任何颜色时，没有任何东西被区分。
- **修复：** 将活动调色板上限设置为 2-3 种核心颜色 + 1 种强调色（R-29），并让其中一种核心颜色成为中性基础。克制才是让强调色发挥作用的关键。

### 过度使用强调色

- **说明：** 按钮上有一个强调色，图标、徽章、链接、线条、背景和光晕。
- **原因：** 强调色在到处都是的时候就不再是强调色。它变成了另一种颜色，设计失去了焦点。
- **修复：** 强调色只属于关键时刻（一个故意的强调色，核心第 3 部分）。零强调色是单调的；到处都是强调色是垃圾。选择它真正重要的一两个地方。

### 单调的默认值

- **说明：** 平坦的白色或近白色、细灰色边框、小半径、无纹理、通用字体、无身份。
- **原因：** 这是过度过滤而没有方向时的“安全”结果。这不是垃圾，但也不是设计：设计应该存在的地方是一个虚空。
- **修复：** 这是一个方向问题，而不是过滤器问题。添加 `DESIGN.md` 或解决设计阅读（核心第 3 部分），然后提高活力旋钮。修复永远不是更多的禁令；它是指明目的并增加能量。

## 布局与组件

### 单调的模板布局

- **说明：** 英雄、副标题、2 个 CTA、截图、功能网格、客户评价、常见问题解答、CTA、页脚，按此顺序，每次都如此。
- **原因：** 顺序是训练数据的默认值，不是产品的叙事。部分出现是因为模板有它们，而不是因为内容需要它们。
- **修复：** 围绕实际内容需求构建结构（R-05, C-3）。如果产品没有客户评价，就没有客户评价部分。部分顺序遵循产品的故事。匹配 RHYTHM 旋钮：如果是 3，部分明显变化。

### 复制粘贴功能卡片

- **说明：** 所有功能卡片的尺寸、高度、图标、布局和填充都相同。
- **原因：** 统一的卡片扁平化了内容。当每个功能都是一个带图标的卡片时，重量真实的功能和没有重量的功能看起来一样。
- **修复：** 创建反映内容层级的变体，并写下原因（R-14）。不是每个功能都需要卡片。旗舰功能可能值得全宽处理，支持功能可以列表显示。

### 拼盘网格

- **说明：** 由不同大小的卡片组成的部分，一些跨越两列或两行，像瓷砖仪表板一样填充空间。
- **原因：** 它是过去几年中默认的“应用样式”着陆布局，所以它传递不了关于产品的任何信息。当每个部分都可以是拼盘时，布局就是一个模板，而不是一个决定。
- **修复：** 仅当内容确实有不同大小的元素要展示时使用拼盘网格（R-05）。如果每个单元格大致相同，简单的网格或列表更诚实。RHYTHM 旋钮决定部分是否变化。

### 统一间距

- **说明：** 每个部分的填充、边距和间隙都相同。
- **原因：** 节奏是一个工具，而单个间距值会去除它。部分不再相互关联；页面看起来像一条平坦的条带。
- **修复：** 将空白作为结构（核心第 3 部分），并使用 RHYTHM 旋钮变化它。建立间距量表，然后使用不同的级别来分隔和连接。统一节奏只有在旋钮说的情况下才是故意的选择（R-05）。

### “工作原理”总是 3 步

- **说明：** 圆形图标 + 数字 1、2、3 + 短文本，总是三步，总是相同的形状。
- **原因：** 产品的真实流程很少是一个整洁的三步列表。模板强迫流程进入它的形状，而不是反过来。
- **修复：** 按照实际流程呈现（R-05）。如果三步带圆形图标是真实的流程，则可以使用；否则使用真实工作流程采取的形状，包括两步或五步。

### “受信任的”标志栏

- **说明：** 英雄下方的一排通用公司标志。
- **原因：** 它是一个没有证据的信任声明：通用标志，没有命名真实客户，没有使用证明。
- **修复：** 仅显示真实、可验证的标志（R-18, R-36, C-5）。如果产品还没有这样的客户，不要编造标志栏。真实的社会证明比通用标志每次都更好。

### “最受欢迎”定价卡片

- **说明：** 中间定价层级始终使用胶囊徽章突出显示。
- **原因：** 它是默认模式，这意味着它不是一个决定。当每个定价部分都这样做时，突出显示的层级不再有任何意义。
- **修复：** 突出显示实际服务于产品目标的服务层级，并写下原因（R-31）。如果没有层级值得强调，则突出显示无。

- **三个列是说明的一部分：** 定价显示为三个层级，无论真实结构如何，中间一个突出显示。这个形状是默认的，所以它不是一个决定（R-05）。使用产品真正拥有的那么多层级，并突出显示它服务于它。

### 没有产品的演示

- **说明：** 页面销售的产品从未展示过工作：没有真实演示，没有服务条款，没有隐私政策，只有承诺。
- **原因：** 它是一个穿着产品衣服的演示。每个声明都是没有背后的信任，并且缺失的法律页面是表明没有真实存在的安静说明。
- **修复：** 显示真实产品的工作，或者诚实地说它尚未发货（R-38, C-5）。如果页面要求注册或付款，服务条款和隐私政策必须存在。诚实的“即将推出”比有说服力的演示更好。

### 4 列模板页脚

- **说明：** 产品/公司/资源/法律列没有变化。
- **原因：** 列存在是因为模板有它们，而不是因为网站有那么多链接组。
- **修复：** 围绕产品实际链接到的内容构建页脚（R-05）。一个链接列可以比四个空列更有用。

### 统一部分节奏

- **说明：** 每个部分都是居中的标题 + 副标题 + 相同的卡片网格，没有变化。
- **原因：** 相同的构图使部分相互模糊，页面感觉重复和平淡。
- **修复：** 使用 RHYTHM 旋钮变化构图（R-05）。交替文本密集和视觉部分，非对称和对称布局。每个部分都遵循相同模板的页面是由模板设计的。

## 装饰元素

### 通用 AI 图标

- **说明：** 闪光、星星、魔法、闪电、钻石、立方体、机器人或 AI 轨道作为功能图标。
- **原因：** 这些符号是“AI 产品”的通用词汇。它们没有传达关于特定功能的任何信息。
- **修复：** 使用与内容真正相关的图标，当符号通用时写下相关性（R-04）。如果没有合适的图标，则使用无。功能标签做工作。

### Lucide 图标

- **说明：** 每个图标都来自同一细描边、圆角库（Lucide 或视觉克隆），所以所有图标共享一个可识别的外观。
- **原因：** 单个默认图标库使每个 AI 网站的图标都相同，所以图标不再告诉你关于产品的任何信息。符号可能相关；统一的库外观是说明。
- **修复：** 图标集是一个视觉选择，而不是默认值（R-04）。首先选择图标的关联性；然后决定库的重量和描边是否适合产品的性格。两个看起来“相似”的图标仍然可以读作你的，如果集是一个决定，而不是导入。

### Emoji 作为装饰

- **说明：** 字面意义的 Emoji 散布在文本、标题、徽章和按钮中：标题中的 🚀、每个功能要点旁边的 ✅、CTA 上的 🔥、图表标题上方的 📈。
- **原因：** Emoji 是“这是生成的，不是写的”最响亮的简写。在 UI 中，它与内容争夺注意力，并将产品的声音扁平化为每个 AI 网站相同的欢快默认值。
- **修复：** 从 UI 文本中删除 Emoji。如果概念需要一个标记，使用一个真实、相关的图标并写下原因（R-04），或者根本不使用标记。副本承载意义；Emoji 没有增加任何东西。

### 每个按钮上的小箭头

- **说明：** `→` 或 `↗` 放置在几乎所有按钮上作为纯粹的装饰。
- **原因：** 箭头变成了模式，而不是信号。当每个 CTA 都有一个箭头时，没有一个指向特定的位置。
- **修复：** 箭头不是按钮的默认身份（R-08）。仅保留那些确实受益于方向提示的元素，按比例调整大小，并写下目的。

### 左侧彩色条纹

- **说明：** 卡片、列表行或部分标题左侧有一条细彩色垂直条，用作装饰。
- **原因：** 条纹添加颜色而不添加意义。它是使卡片“看起来设计过”的最便宜的方式，所以它到处都是，什么也不说。
- **修复：** 条纹是装饰；它必须携带信息或消失（R-01, R-31）。标记真实状态（活动、警告、新）的左侧边缘是一个信号。存在的条纹是为了看起来设计过，是默认的。

### AI 胶囊徽章

- **说明：** 药丸形状、细边框、光晕、小点、大写字母，包含“AI 驱动”、“Beta”、“新”。
- **原因：** 胶囊加光晕加点的组合是一个自我指代的徽章，它说“由 AI 制作，关于由 AI 制作”。它添加了噪音，而不是信息。
- **修复：** 徽章仅在功能上需要时使用，并写下需要，并且永远不会使用完整的组合（R-09）。一个真实的状态标签很好；一个装饰性的“AI 驱动”胶囊不是。

### 标题上方的眉毛徽章

- **说明：** 一个小药丸直接位于 H1 上方，通常带有一个点和细边框，包含类别标签（“Aplikasi Tagihan UKM”、“The platform for teams”）该标题下文已经说了。
- **原因：** 徽章重复了标题，所以它添加了一行阅读而没有添加事实。它在每个生成的页面上都出现在相同的位置，这就是为什么它看起来像模板而不是决定。当它还带有点时，它借用了状态指示器的语言来标记没有状态。
- **修复：** 切掉它，让标题做工作。如果标签承载了标题没有的信息，将其折叠到副标题中，在那里它看起来像内容而不是装饰。徽章在折叠之前需要一个像其他徽章一样的书面原因（R-09），并且点内需要一个真实的状态来标记（R-31）。

### 装饰状态点

- **说明：** 标题旁边、眉毛、导航项或标签旁边的一个小彩色点，通常在循环中发光和脉动，标记了什么。它标记了没有东西。
- **原因：** 点是一个注意力吸引器，背后没有东西：光晕加上无限脉冲是双重争取眼睛，而事实并不存在。它看起来像 AI，因为生成的页面试图使用系统状态词汇作为装饰，并且相同的点在每个页面上都出现在相同的位置。
- **修复：** 点必须标记一个真实状态（活动、实时、录制、警告）。如果它标记了，保留一个点，去掉光晕，去掉无限脉冲（R-19）。如果它标记了没有东西，则删除它：标题不需要指示器来成为标题（R-31）。

### 通用 AI 字体

- **说明：** 大型等宽标题，或带有极宽间距的大写标签（"HOW IT WORKS"、"FEATURES"）。
- **原因：** 等宽字体作为美学和宽间距大写字母是“技术和现代”的简称，而没有进行任何实际的排版工作。
- **修复：** 从品牌字符中选择字体，而不是模型默认选择，并写明原因（R-06）。排版必须提高可读性并反映产品。有理由的选择胜过趋势。
- **默认列表：** 无衬线字体有 Inter、Geist 和 Space Grotesk；等宽字体有 Geist Mono、JetBrains Mono 和 Fira Code。没有禁止的字体；每个字体都有品牌理由才有效。关键在于显示的字体是因为它是默认的，而不是因为它适合（R-06）。

### 伪造的终端窗口

- **说明：** 带有交通灯点、提示行和输入的命令的样式化终端窗口，用作英雄或功能视觉元素。
- **原因：** 这是通用的“这是一个开发者工具”的服装。窗口是装饰；真实的产品很少看起来像这样。它看起来像是一个真实截图的占位符。
- **修复：** 如果产品确实是终端或 CLI，一个真实、可工作的截图是证据。否则，显示实际的产品 UI，而不是服装（R-06、C-5）。等宽字体作为美学已经在 R-06 中涵盖；一个伪造的终端是那种模式作为一个组件。

### 没有联系的插图

- **说明：** Undraw、Storyset 或带有通用 3D 肿胀字符的插图，与产品没有真正的联系。
- **原因：** 装饰性插图表明设计是装饰性的，而不是设计的。它们填充空间而不服务于内容。
- **修复：** 插图必须与产品有直接联系，并写明联系（R-22）。如果不存在，则使用真实截图或无插图。

## 结构与流程

### 死导航

- **说明：** 导航栏链接到不存在的页面或部分。
- **原因：** 死链接是一个破灭的承诺。用户点击它们的那一刻就破坏了信任。
- **修复：** 每个导航项都必须有一个真实的目的地（R-24）。如果功能尚未构建，则将其删除，或明确标记为“即将推出”。导航栏反映实际存在的内容。

### 非功能性控件

- **说明：** 按钮无任何作用，下拉菜单无法打开，表单无法提交。
- **原因：** 视觉效果已完成，但行为尚未完成。这是模型和产品之间的区别。
- **修复：** 每个交互元素都有真实的行为，或者将其删除（R-26）。如果元素确实无法有目的地，则发布一个清晰的 `// TODO` 和一个可见的“即将推出”标签，或者不发布。

### 填充模板的部分

- **说明：** 部分存在是因为“每个 AI 登录页面都有一个”，而不是因为内容需要它。
- **原因：** 模板部分是目的不明确的内容。它们增加了长度并减少了焦点。
- **修复：** 每个部分都应从产品内容中获得其位置（C-3）。删除仅填充模板的部分。一个具有较少、有目的部分页面比一个具有所有默认值的页面更强。

## 应用程序与仪表板

上述模式是登录页面的形状。这些是应用程序侧的等效项：当屏幕是仪表板、管理面板或任何登录视图时，代理会选择的默认值。它们违反的规则是相同的；只有形状是新的。

### 默认仪表板外壳

- **说明：** 左侧边栏、顶部栏、四个统计卡片、一个图表、一个表格。在任何人询问屏幕的用途之前就选择了，并且无论它管理发票、患者还是服务器，都是相同的。
- **原因：** 这是登录页面模板问题在应用程序中的体现：从记忆中选择布局，而不是根据屏幕支持的工作。更换标签后，它属于任何产品。
- **修复：** 命名屏幕的工作以及用户在其中做出的一个决定，然后围绕这个决定构建层次结构（C-3、R-20）。如果工作是为“发现故障任务并重试它”，则故障任务是页面，统计行是一个脚注。仅因为仪表板通常有它们而幸存的部分被删除（C-3）。

### 统计卡片中的虚构数字

- **说明：** 四个卡片显示 12,483 / 94.2% / $48.2K / 1,204，每个卡片都有绿色“本周 +12%”的增量。
- **原因：** 数字是装饰性的，而增量更糟：没有系列背后的趋势声明。真实的仪表板有重要的指标和无关的指标，所以四个相等的卡片已经是一个层次结构失败。
- **修复：** 显示真实数字或不显示（R-17、R-38）。将卡片连接到真实数据，或者发布一个真实的指标。增量仅在比较周期真实且命名时才出现。如果屏幕是原型，则将值标记为占位符，用户可以看到（R-38）。

### 填充活动源

- **说明：** “Sarah Chen 更新了文档，2 小时前”，重复旋转姓名和头像。
- **原因：** 虚构的人、虚构的事件。这是穿着不同布局的推荐部分，并使空产品看起来很忙。
- **修复：** 源显示真实事件或不上线（R-18、R-38）。诚实的空状态比虚构的源更好，并且它告诉用户首先做什么（R-27）。

### 没有问题的图表

- **说明：** 由于空间看起来空荡荡而放置的线形或环形图表，带有通用标题（“概述”、“性能”）和没有读者可以采取的轴。
- **原因：** 图表是一个答案。没有问题，它就是纹理，并且比一个句子需要更多的注意力。
- **修复：** 在绘制它之前写明图表回答的问题，并将这个问题放在标题中（“每小时失败任务，过去 24 小时”）。如果一句话能更好地回答它，就写这句话（C-3）。图表分段仍然需要与邻居 3:1 的对比度（R-25）。

### 通用表格列

- **说明：** 名称、状态、日期、操作，无论行实际上是做什么，每个行都有一个三点菜单。
- **原因：** 列来自表格组件，而不是来自数据。用户扫描以找到决定他们下一步行动的字段，而该字段不存在。
- **修复：** 从用户在此表格中做出的决定中选择列，并将决定字段放在前面。行菜单包含存在的操作；任何无操作的内容都会被删除（R-26）。

### 字段和列中的填充数据

- **说明：** 空白表单字段和表格列填充了伪造但合理的数据：`John Doe`、`johndoe@example.com`、`"让我们构建一些东西"`、属于任何人的电话号码和日期。
- **原因：** 伪装成真实内容的虚构内容。它在模型中读得很好，但在真实用户查看时就会崩溃：名称不是客户，电子邮件不是潜在客户，信息是一个口号。这是屏幕是生成而不是构建的最强的迹象。
- **修复：** 留空单元格为空，或使用清楚地说明应放置什么内容的占位符：`您的姓名`、`email@example.com`、`在此处输入您的信息...`，或者当预期值时使用 `[真实数据]`（R-23、R-38）。当存在时，输入真实数据。像“让我们构建一些东西”这样的通用填充副本是口号垃圾，不应出现在数据列中（R-16）。

### 占位符空和加载状态

- **说明：** “没有可用数据”与插图、裸露的旋转器或模仿真实数据永远不会填充的布局的全页骨架。
- **原因：** R-27 要求这些状态，并且这些状态在技术上具有它们。它们仍然告诉用户什么：没有原因、没有下一步行动、不知道这是否正常。
- **修复：** 空状态说明为什么它是空的，并给出填充它的一个行动（“还没有任务。在此处运行同步以查看结果”）。加载状态说明正在加载什么。错误状态说明什么失败以及下一步该做什么（R-27）。首次运行、过滤为空和权限拒绝是不同的屏幕，并且阅读不同。

## 动画

### 无尽脉冲和循环

- **说明：** 元素脉冲、弹跳或永远浮动，没有任何用户触发。
- **原因：** 永恒的运动是噪音。它争夺内容的注意力，并且永远不会停止让用户休息。
- **修复：** 动画必须有一个明确的 UX 目的，并写明（R-19）。动画将注意力引导到某个时刻；它不会在循环中运行。如果 MOTION 旋钮是 1（仅悬停状态），则无尽循环是对声明的旋钮的失败。

### 模板动画堆叠

- **说明：** 每个元素同时使用 Fade Up + Fade In + Floating + Scale + Bounce。
- **原因：** 每个元素都动画化的页面没有焦点。运动变成了壁纸。
- **修复：** 配合目的和 MOTION 旋钮编排动画（R-19）。不是所有东西都在移动。英雄在说话，支持元素保持冷静。声称“电影感”的页面必须实际移动；声称“静态”的页面不能移动。

## UI 技能检查清单

在执行 UI 工作时，与核心交付门一起运行这些。所有答案必须为 **是**：

- [ ] 色彩板是否来自 `DESIGN.md` 或书写的品牌身份，而不是默认渐变集？（R-01、R-29）
- [ ] 强调色是否仅在关键时刻使用，而不是分散到每个元素？（核心第 3 部分，一个故意的强调色）
- [ ] 文本是否没有装饰性表情符号散布在标题、项目符号和按钮中？（R-04）
- [ ] 部分组合是否根据声明的 RHYTHM 旋钮而不是重复一个模板而变化？（R-05）
- [ ] 布局是否没有默认 AI 形状：bento-grid 砌块、伪造的终端窗口、三个定价列和左侧边缘颜色条纹没有意义？（R-05、R-01）
- [ ] H1 上方的空间是否没有包含一个包含标题已经说明的标签的药丸徽章？（R-09）
- [ ] 每个导航项和交互元素是否有一个真实的目的地或行为，或一个可见的“即将推出”标签？（R-24、R-26）
- [ ] 动画是否遵循声明的 MOTION 旋钮并服务于书写的目的，没有无尽循环？（R-19）
- [ ] 玻璃、发光、阴影和半径是否在其剂量上限内使用，而不是作为页面默认值？（R-10、R-11、R-12、R-13）
- [ ] 每个彩色点和状态灯是否标记一个真实状态，没有装饰性发光或无尽脉冲？（R-13、R-19、R-31）
- [ ] 在应用程序屏幕上，布局是否围绕用户在那里做出的决定构建，而不是侧边栏加上统计行加上图表加上表格默认值？（C-3、R-20）
- [ ] 每个数字、增量、源条目和表格行是否为真实或标记为占位符，没有虚构的指标？（R-17、R-18、R-38）
- [ ] 空白表单字段和表格单元是否保持空白或带有诚实的占位符（您的姓名、email@example.com），而不是看起来像假的（John Doe、johndoe@example.com）？（R-23、R-38）
- [ ] 空的、加载的和错误状态是否命名原因和下一步行动，而不是说“没有数据”？（R-27）
- [ ] 页面是否在每个断点、主题和状态下都保持良好，并通过仅键盘使用？（R-03、R-34、C-4)
