# HSB FPGA 烧录

当用户希望对连接到受支持 NVIDIA 开发套件的 HSB 板上的 FPGA 固件进行烧录（升级或降级）时，请使用此技能。

**此技能支持两种板型：**

1. **HSB Lattice 板** — 独立式 FPGA 板，配备 Lattice CPNX100 FPGA
2. **Leopard Imaging VB1940** — 集成 Lattice FPGA 的“一体化”相机

**关键安全规则：切勿混用不同板型的命令。** 在 Lattice 板上使用 `program_leopard_cpnx100` 或在 VB1940 上使用 `program_lattice_cpnx100` **可能会永久损坏设备**。该技能必须在任何烧录操作之前检测并确认板型，如果板型不明确或与操作不匹配，则拒绝继续执行。

此工作流程具有副作用（它永久修改 FPGA 固件）。切勿自动运行它。只有在用户明确调用时才运行它。

**使用警告：** 此技能使用新固件烧录 FPGA。在调用它之前，请要求用户确保他们有足够的 Claude Code 使用量/代币来完成此工作流程。

## 开始前 — 必须的门控（按顺序执行这些操作）

**门控 1 — 读取环境变量。** 在做任何其他事情之前，检查这些变量并将它们的解析值打印给用户：

```
SSH_TARGET      远程开发套件登录（例如 nvidia@192.168.1.50）。如果未设置，请询问用户。
REMOTE_ROOT     远程工作目录（例如 /home/nvidia）。如果未设置，请询问用户。
REMOTE_SUDO     sudo / sudo -n / "" — 如果未设置，默认为 "sudo"。
REMOTE_SSH_OPTS 额外的 SSH 选项（可选）。
HSB_PLATFORM    平台提示（可选）。
```

**SSH_TARGET 和 REMOTE_ROOT 是必需的。如果任何一个缺失，请停止并要求用户提供它们。**

**门控 2 — 展示烧录摘要和阶段计划。** 在采取任何行动之前：

如果用户的请求已经包含板型、当前 FPGA 版本和目标 FPGA 版本，请在阶段计划之前声明以下内容：烧录工具（Lattice 使用 `program_lattice_cpnx100`，VB1940 使用 `program_leopard_cpnx100` — 切勿混用）、manifest 发布版本和文件名、CLI 标志（`--force --accept-eula`）、该过程是单步还是通过网关 2412 进行两步。对于 VB1940，还声明不需要 v2.0.0 中间仓库。对于从 FPGA 2407 的两步升级，声明步骤 1 使用 `hololink --force fpga_version`（不是 `hololink enumerate`，它与 FPGA 2407 不兼容）并使用 v2.0.0 标志放置：`hololink --force program scripts/manifest.yaml --accept-eula`（`--force` 在子命令之前）。

然后显示阶段计划，并明确询问：`是否继续执行烧录工作流程？[Y/n]` — 在用户确认之前不要开始门控 3：

```
HSB 烧录 — 阶段计划
  阶段 0：代币预算预检
  阶段 1：验证板连接性，检测板型（Lattice 或 VB1940），读取 FPGA 版本
  阶段 2：选择目标 FPGA 版本
  阶段 3：准备烧录基础设施和 YAML 文件，展示烧录计划以供批准
  阶段 4：执行烧录过程（带电源循环验证）
  阶段 5：摘要报告（带保存选项）
  阶段 6：清理烧录残留物
```

**门控 3 — 代币预算预检（阶段 0）。** 在阶段计划（门控 2）显示后且用户确认后运行。在显示阶段计划之前不要运行代币预算检查。预算检查通过之前不要进入阶段 1。

**门控 4 — 明确确认板型。** 在任何烧录命令之前，向用户确认板型是 **Lattice** 还是 **VB1940**。切勿混用 `program_lattice_cpnx100` 和 `program_leopard_cpnx100` — 错误的工具可能会损坏设备。

## 说明

通过键入 `/hsb-flash [OPTIONS]` 调用此技能。该技能自动检测板型，展示烧录计划，并在每个烧录步骤之前提示确认。有关完整的 `--help` 输出，请参阅 [references/help-text.md](references/help-text.md)。

## 此技能必须执行的操作

0. **在任何远程命令、仓库检出、容器构建或烧录准备之前运行强制性的代币预算预检。** 估计完成所有阶段所需的代币数量，使用最佳可用的 Claude Code/账户使用机制检查用户的剩余订阅计划使用量，将估计值和结果显示给用户，如果可用预算不足或无法验证则停止。
1. 验证 HSB 板是否连接到开发套件，SSH 和板连接是否正常工作，读取当前 FPGA 版本，并 **识别板型**（Lattice 或 VB1940）。首先尝试 `hololink enumerate`；如果失败（对于 FPGA 2407 板是预期的），则回退到 `hololink --force fpga_version`。对于 Lattice 板，如果使用现有仓库的容器所有方法都失败，则检出 HSB 发布仓库 v2.0.0 并使用 v2.0.0 容器重试。如果这也失败，则假设版本为 2407 并继续。对于 VB1940 板，如果无法读取版本，请询问用户。
2. 询问用户他们想要烧录到的目标 FPGA 版本（或接受“latest”）。可用版本取决于板型。
3. **处理未文档化的 FPGA 版本**（适用于 Lattice 和 VB1940）：如果当前或目标 FPGA 版本未列在此技能支持版本或映射表中，它可能属于尚未在此处文档化的较新 HSB 版本，或者它可能是一个未发布的开发版本。按以下步骤进行：
   - **检查较新版本**：获取公共发布说明 `https://github.com/nvidia-holoscan/holoscan-sensor-bridge/blob/main/RELEASE_NOTES.md` 并查找引入未文档化 FPGA 版本的发布。如果找到匹配的发布，请在开发套件上检出该发布仓库并按照下面为检测到的板型描述的相同规则进行烧录。同时更新此技能的映射表、支持的 FPGA 版本列表和转换矩阵以包含新版本及其对应的 FPGA 版本。
   - **开发或未发布的 FPGA**：如果未发布发布与 FPGA 版本对应，则使用开发套件上已有的 HSB 仓库（来自 `/hsb-setup`）进行烧录，并按照检测到的板型的相同规则进行。如果烧录失败，报告错误并提示用户进一步指示。
4. 确定正确的烧录程序并准备烧录脚本和 YAML 文件：
   - **Lattice 板**：
     1. 读取 HSB 板上当前烧录的 FPGA 版本。根据烧录方向确定所需的 HSB 发布仓库：升级时使用与目标 FPGA 版本对应的仓库；降级时使用与当前 FPGA 版本对应的仓库（见下文“FPGA 版本到仓库映射”）。如果该仓库在开发套件上不存在，请检出此仓库。
     2. 将目标 FPGA manifest YAML 从此技能的相关 `scripts/` 目录复制到检出的仓库，并根据需要修补文件以补充任何缺失的细节（例如 `fpga_uuid`）。
     3. 确定烧录程序：
        - **单步升级**：如果当前版本是 2412 或更高版本且目标也是 2412 或更高版本，或者从任何版本升级到正好 2412。使用与目标 FPGA 版本对应的仓库（见“FPGA 版本到仓库映射”）直接从当前版本烧录到目标。
        - **单步降级**：如果当前版本和目标版本都是 2412 或更高版本。使用与当前 FPGA 版本匹配的仓库直接从当前版本烧录到目标。
        - **两步降级**：如果目标是比 2412 更旧的版本（即 2407）且当前版本比 2412 新。步骤 1：使用与当前 FPGA 版本匹配的仓库从当前版本烧录到 2412。步骤 2：使用 HSB 发布仓库 v2.0.0 从 2412 烧录到目标。需要电源循环。 （特殊情况：如果当前版本正好是 2412，则只需要步骤 2。）
        - **两步升级**：如果当前版本比 2412 更旧（即 2407）且目标比 2412 新。步骤 1：使用 v2.0.0（对应目标 FPGA 2412）从当前版本烧录到 2412。步骤 2：使用与最终目标 FPGA 版本对应的仓库从 2412 烧录到目标。需要电源循环。
     4. 读取正在用于烧录的 HSB 仓库的用户指南并提取烧录命令。始终添加 `--force` 和 `--accept-eula` 以确保在容器内非交互式执行。 **注意**：v2.0.0 将 `--force` 放在子命令之前，`--accept-eula` 放在后面 — 见下文“v2.0.0 CLI 标志放置”。
     5. 烧录完成后，清理此技能检出的所有临时 HSB 发布仓库，这些仓库与用户在技能调用前存在于开发套件上的原始仓库不同。
   - **VB1940 相机**：直接使用开发套件上的现有 HSB 仓库（不需要 v2.0.0 中间仓库）。烧录始终是单步的。
   向用户展示完整的烧录计划以供批准。
5. 执行烧录程序：
   - 执行必要的预烧录安全检查（ping 板，确认板型和当前 FPGA 版本）。
   - 带完整日志运行每个烧录步骤；在烧录操作之前宣布操作。
   - 在每个关键烧录步骤之前需要明确的用户确认，并在任何需要板/相机电源循环之后需要确认。
   - 所有程序命令必须在演示容器内执行（容器内不需要 sudo）。
   - 烧录后，验证新 FPGA 版本是否与预期目标匹配后再继续。
   - 处理任何错误或不匹配，停止工作流程，报告状态并提供清理选项。
6. 生成整个过程的摘要报告，并提供保存选项。
7. 清理所有烧录残留物，以便用户可以检出任何他们需要的 HSB 发布。

## 支持的板型

| 板型     | 标识符 | 描述                               |
|---------|-------|-----------------------------------|
| **Lattice** | `lattice` | HSB Lattice CPNX100-ETH-SENSOR-BRIDGE 独立式 FPGA 板 |
| **VB1940**  | `vb1940`  | Leopard Imaging VB1940 “一体化”Eagle 相机，集成 Lattice FPGA |

板型在阶段 1 期间从 `hololink enumerate` 输出中检测，并与用户确认。如果检测不明确，用户必须明确指定板型。

## 支持的 FPGA 版本

### Lattice 板 FPGA 版本

| 版本 | YAML 源发布版本 | 备注 |
|------|----------------|------|
| 2407  | v2.0.0         | 最旧的受支持版本 |
| 2412  | v2.0.0         | 用于两步烧录的网关版本 |
| 2507  | v2.3.1         |      |
| 2510  | v2.5.0         | 最新的受支持版本 |

### VB1940 FPGA 版本

| 版本 | YAML 源发布版本 | HSB 发布版本 | 备注 |
|------|----------------|-------------|------|
| 2507  | v2.3.0         | v2.3.0      |      |
| 2510  | v2.5.0         | v2.5.0      | 最新的受支持版本 |

VB1940 **不支持** 2407 或 2412 版本 — 这些是 Lattice 独有的。

**上述未列出的版本**：任何板型的 FPGA 版本都可能比文档化的最新版本更新 — 见下文“处理未文档化的 FPGA 版本”。对于 Lattice 板，2407 之前的版本或已知版本之间的版本（例如 2409）不受支持。对于 VB1940，2507 之前的版本不受支持。在任何情况下，如果版本未列出，请拒绝并显示该板型的支持版本。

## 仓库选择和检出（仅限 Lattice）

上述“Lattice 板 FPGA 版本”表决定了使用哪个 HSB 发布仓库。查找键取决于方向：

- **升级**：查找目标 FPGA 版本的 YAML 源发布版本。
- **降级**：查找当前 FPGA 版本的 YAML 源发布版本。

> **自我更新**：如果遇到未文档化的 FPGA 版本，技能会检查公共发布说明以查找匹配的 HSB 发布（见“处理未文档化的 FPGA 版本”）。如果找到，技能会更新“支持的 FPGA 版本”表、转换矩阵，并记录新发布的 manifest 文件。

### 仓库检出逻辑

1. **检查现有仓库**：如果用户在开发套件上已有 HSB 仓库（来自 `/hsb-setup`），则从 `VERSION` 文件中读取其版本。
2. **确定所需仓库**：对于升级，在映射表中查找目标 FPGA 版本。对于降级，查找当前 FPGA 版本。
3. **如果需要则检出**：如果现有仓库与所需版本不匹配，则克隆并检出所需版本到单独目录。保留现有仓库不变。
4. **两步情况**：如果需要两步烧录，则两个步骤的仓库都必须可用。对于两步降级（当前 > 2412，目标 = 2407），步骤 1 使用当前 FPGA 的仓库，步骤 2 使用 v2.0.0。对于两步升级（当前 = 2407，目标 > 2412），步骤 1 使用 v2.0.0（目标 2412 的仓库），步骤 2 使用与最终目标 FPGA 版本对应的仓库。如果任何所需仓库不存在，则检出。

> **VB1940 注意**：VB1940 烧录**始终**使用开发套件上的现有仓库 — FPGA 到仓库的映射不适用。现有仓库必须为 v2.3.0 或更高版本。如果找不到现有仓库，请指示用户先运行 `/hsb-setup`。

### 检测时要保存的内容

在阶段 1，扫描现有仓库并检测板型时，将以下变量保存到会话状态：

- `BOARD_TYPE` — 检测到的板型：`lattice` 或 `vb1940`
- `EXISTING_REPO_DIR` — 现有 HSB 仓库的绝对路径（如果未找到则为空）
- `EXISTING_REPO_VERSION` — 仓库的发布版本（例如 `2.3.1`），从 `VERSION` 文件中读取
- `FLASH_REPO_DIR` — 将用于烧录的仓库的绝对路径（如果检出不同版本，可能与 `EXISTING_REPO_DIR` 不同）
- `FLASH_REPO_VERSION` — 烧录仓库的版本（从 FPGA 到仓库映射中查找）
- `INTERIM_REPOS` — 此技能检出的仓库目录列表（用于阶段 6 中的清理）

## Linux/Windows 友好的包装变量

重用 `hsb-setup` 技能中的相同环境变量：

- `SSH_TARGET` 用于远程登录目标（例如 `nvidia@agx-thor-host`）
- `REMOTE_ROOT` 用于远程工作目录，其中将创建烧录工作空间
- `REMOTE_SUDO` 用于特权命令
- `REMOTE_SSH_OPTS` 用于附加 SSH 选项
- `HSB_PLATFORM` 作为可选平台提示

如果这些已设置，请通知用户这些设置并使用它们，而无需重新询问。

在阶段 1 之前，打印解析的远程执行设置。

## 强制交互模式

在做出更改之前，显示此阶段计划：

- 阶段 0：代币预算预检；验证用户的剩余计划使用量可以覆盖完整的烧录工作流程
- 阶段 1：验证板连接性，**检测板型**（Lattice 或 VB1940），并读取当前 FPGA 版本
- 阶段 2：选择目标 FPGA 版本（可用版本取决于板型）
- 阶段 3：准备烧录基础设施和 YAML 文件，展示烧录计划以供批准
  - **Lattice**：检出所需仓库（升级时为目标 FPGA 的仓库，降级时为当前 FPGA 的仓库 — 如果尚未存在），复制并修补 manifest YAML
  - **VB1940**：直接使用现有仓库
- 阶段 4：执行烧录过程（带电源循环验证）
- 阶段 5：生成摘要报告（带保存选项）
- 阶段 6：清理烧录残留物

然后一次执行一个阶段。

**每个非最终阶段（阶段 0–5）之后：**

1. 显示阶段摘要，其中包含关键结果。
2. **提示用户** `是否继续执行阶段 <N+1>？[Y/n]` 并指定下一个阶段做什么。在继续之前等待用户确认。

**异常情况**：当 `--y`（自动批准模式）处于激活状态时，阶段门会被跳过，阶段将自动运行。有关详细信息，请参阅“自动批准模式 (`--y`)”部分。

如果出现故障，请**不要**仅堆砌原始日志。请总结：

- 失败的确切命令
- 可能的根本原因
- 您建议的安全操作
- 问题是否阻塞
