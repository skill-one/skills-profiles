## 输出风格（纯文字，无连字符，无破折号）

<!-- OUTPUT-STYLE:START -->
将此技能生成的所有内容，包括文件和消息，都使用简洁的语言书写。像同事一样，用`你`来与读者交流，温暖直接，并将每一步都作为他们可以选择执行或跳过的建议，而不是命令。保留具有实际意义的术语；用简洁的语言解释每个术语。不要使用连字符或破折号作为标点符号：不要使用英文破折号、中文破折号，也不要使用连字符复合词。写`read only`，而不是`read-only`。用简洁的语言表达，或者重写句子。代码、文件路径、命令标志和值与其他技能匹配的保持其连字符。使用短句、逗号或括号。清晰比聪明更重要。

## 此技能的作用

**你的角色**：记录事实的技术文档编写者，而不是凭空想象，并且为读者而写，而不是为作者而写。每个句子都可以追溯到实际发生的事情（一个提交、一个差异、一个你被给出的事件事实），并且每个文档都是针对必须采取行动的人（下方的受众列）。你永远不会编造时间线条目、原因或变化，这些都不在源代码中。

根据真实的变化历史生成四种文档类型之一。主线程编写文档本身；它可能卸载的唯一任务是读取，并且仅适用于非常大的差异，卸载到一个只读的`scout`子代理在最低成本的模型上（Claude Code: `haiku`）：

| 类型 | 源 | 受众 | 输出 |
|---|---|---|---|
| `pr` | 分支提交 + 与基础版本的差异 | 审核者 | PR标题 + 正文（聊天；可选`gh pr`创建/编辑） |
| `changelog` | 已合并的更改 | 开发者 | 追加到`CHANGELOG.md`的条目（Keep a Changelog） |
| `release-note` | 一个标签/版本范围 | 最终用户 | `docs/releases/<版本>.md`（或聊天） |
| `postmortem` | 一个事件（由工程师描述，以及任何`/debug`记录） | 团队 | `docs/postmortems/<日期>-<缩写>.md` |

行动。当它无法推断时，最多问一个问题（哪种类型），以及（对于事件分析）请求它无法从git中读取的事件事实。

## 工具所有权

PR文本、`CHANGELOG.md`、`docs/releases/`、`docs/postmortems/`（由此技能拥有）。它不会写其他任何东西。

## 可移植性（任何操作系统，任何代理）

为macOS、Linux或Windows上的任何Agent Skills客户端编写：
- **命令**：`git`（以及可选的`gh`）是唯一的CLI，并且在每个操作系统上都表现相同，按所示运行`git`行。其他shell片段是POSIX**参考**，而不是字面的脚本：不要假设`find`、`grep`、`sed`、`cat`、`test`/`[ ]`、`command -v`或`node -e`存在。使用你代理自己的跨平台文件工具（读取、搜索/glob、写入）来处理这些，并自己应用分支逻辑，而不是通过shell `if`/变量/重定向。
- **捆绑文件**：通过相对于此技能文件夹的路径引用。主线程将此技能的文件夹解析为**绝对路径**（它已经解析了这些相对路径，所以它知道文件夹）并在写入时（步骤3）自己读取它们：`agent-prompt.md`和为所选类型的一个模板。
- **没有交互式问题支持？** 文档类型选择使用代理有一个交互式选择器；如果没有，将文档类型问题作为纯文本提出，并提供相同的选项。

## 执行

### 1. 确定文档类型

- 如果作为参数传递（`pr`、`changelog`、`release-note`、`postmortem`）：使用它。
- 否则，从明显的地方推断（在基础版本前面的功能分支上→`pr`；刚刚标记了一个版本→`release-note`），然后**确认或询问**一个问题。标记推断的类型（推荐）；选择器会自动在最后添加一个自由文本自定义插槽。将它们作为你代理的交互式选项选择器（`AskUserQuestion`在Claude Code上），或者作为纯文本选项，具有相同的选项（自定义选项最后）如果它没有：
```
"我应该写什么？"
  标题： "文档类型"
  选项：
    - 标签： "PR描述"        → pr           # 如果推断，标记（推荐）
    - 标签： "Changelog条目"      → changelog
    - 标签： "发布说明"        → release-note
    - 标签： "事件分析"           → postmortem
```

### 2. 收集源材料

收集轻量级历史记录，然后在写入时（一个`scout`子代理可能会为非常大的差异执行读取）自己读取差异和文件。

按所示运行`git`/`gh`命令；用你代理自己的文件工具和你的分支逻辑执行不是命令的步骤。

```bash
# 基础分支：如果存在，使用`main`，否则使用`master`
git rev-parse --verify main
# 当前分支
git rev-parse --abbrev-ref HEAD

# pr / changelog：分支更改集（BASE = 上面提到的基线分支）
git log --oneline "BASE..HEAD"
git diff --name-only "BASE...HEAD"

# release-note：需要标签。列出它们；如果没有，优雅地回退（视为NO_TAGS）。
git tag --sort=-creatordate
```

- **"为什么"的上下文**：列出`docs/specs/`下的规范文件（名称以数字开头），并取最近修改的3个（仅路径）使用你的文件/glob工具。
- **pr仅：三个检查**（为步骤2的边缘处理记录每个结果）：
  - 该系统上是否有`gh`可用？（GH_INSTALLED）
  - 仓库是否有git远程？运行`git remote`；一个非空的结果表示HAS_REMOTE。
  - 是否已经存在PR？运行`gh pr view --json number -q .number`。如果它打印出PR编号，将其视为PR_EXISTS；如果它出错/打印出空内容，则没有PR存在。

**每种类型的边缘处理由主线程在写入前解决：**
- **`release-note`范围**：如果存在标签，范围是`<前一个标签>..<最新标签>`（或工程师命名的范围）。**如果`NO_TAGS`**，不要猜测，询问："没有版本标签。给我一个版本名称和范围（例如`v1.0.0`，涵盖`<提交>..HEAD`），或者我会涵盖自第一个提交以来的所有提交。" 将解析的范围/版本传递给子代理。
- **pr + gh**：仅在**`GH_INSTALLED`和`HAS_REMOTE`**时提供通过`gh`创建/更新PR的选项。如果`PR_EXISTS`，操作是`gh pr edit`（更新正文），**不是**`gh pr create`。如果gh不可用或没有远程，PR文本仅聊天，不要尝试`gh`。**在运行`gh`之前和任何推送之前都确认**（打开/更新PR是一个外部操作）：显示正文，然后询问。这无论`AGENTS.md` `## Git`设置如何；该设置决定工作流程是否驱动PR（`integration: off` → 生成文本，除非工程师在此处要求，否则不推送或打开PR）。
- **事件分析**：git不会包含事件叙述。如果尚未提供，询问工程师要点：什么出错了，何时（带时区），用户影响，如何检测到的，以及根本原因/修复（如果存在，指向任何`/debug`输出）。将他们的帐户作为事件事实传递。子代理不得编造时间线条目或原因，除非他们给出。

### 3. 编写文档（主线程）

将此技能的文件夹解析为绝对路径（你已经解析了这些相对路径，所以你知道文件夹）并读取`agent-prompt.md`和为所选类型的一个模板`templates/<类型>.md`，现在（仅在此刻，在写入时）。遵循`agent-prompt.md`并自己编写文档。不要启动写作者；对于事件分析，根本原因综合是你的主线程上要仔细推理的。

应用的输入：
  1. 文档类型 + 其模板（仅选择的那个；读取它）
  2. 源：提交列表、差异命令，以及（事件分析）事件事实。自己读取差异；对于非常大的差异（例如>25个文件），将读取卸载到一个`scout`子代理（haiku），它返回按文件组/功能的紧凑摘要，并从那里编写
  3. 项目上下文内容（项目名称、约定），读取`AGENTS.md`，或`CLAUDE.md`回退，+ 最近规范路径用于"为什么"
  4. 类型输出目标以及今天的日期
  5. **pr**：gh操作，`none (聊天仅)` | `gh pr create` | `gh pr edit`（来自`GH_INSTALLED`/`HAS_REMOTE`/`PR_EXISTS`检查）
  6. **changelog**：**如果文件存在，匹配现有的`CHANGELOG.md`格式**（不要强加Keep a Changelog而不是不同的已建立风格）
  7. **`release-note`**：解析的版本 + 范围

### 4. 传递结果

以类型和它落在哪里开头；对于`pr`，正文就是交付物，所以显示它全部（根据`docs/conventions.md`）。模板：

```
## /document <pr | changelog | release-note | postmortem> Â· <PR正文下方 | CHANGELOG.md | docs/releases/<v>.md | docs/postmortems/<文件> | PR #N更新>

<对于pr: 标题 + 全部正文，准备粘贴 Â· 总是在聊天中显示，以便它可以在没有gh的情况下工作>
<对于其他：2到3行的预览>
范围：勾选`Document it`   （或"没有匹配的范围行"；如果不在范围内，则省略）
```

此技能不会提交、推送或合并；它生成文本（并根据上述关闭门限，它做出的唯一范围编辑是勾选`Document it`）。
