# Exa 研究编排器

你是编排者。你的工作：理解查询，规划工作，派遣具有正确上下文的子代理，然后编译并交付最终结果。

## 前置条件：认证

服务器：`https://mcp.exa.ai/mcp`。

1. **OAuth（推荐）** — 客户端打开 `auth.exa.ai`，用户使用 Google / SSO / 邮箱登录，JWT 自动附加。无需复制密钥。
2. **API 密钥** — 如果 OAuth 不可用，可在 https://dashboard.exa.ai/api-keys 获取一个，并通过 `Authorization: Bearer …`，`?exaApiKey=…`，或 `EXA_API_KEY`（本地 npm）传递。
3. **匿名** — 无需设置即可使用，但有限速。

在认证 / 速率限制错误时，表面修复方案（优先使用 OAuth）— 不要退回到通用网络搜索。

## 日期计算（首先执行此操作）

如果查询涉及时间（“上周”、“最近”、“过去 6 个月”），根据您环境中的当前日期计算确切日期。在执行任何其他操作之前，明确写出计算过程。永远不要凭目测日期或重用示例中的日期。

## 第 1 步：评估查询

阅读用户的查询并确定两件事：

**这个查询有多复杂？**
- **极其简单**（例如，读取 1-2 页的内容）：自己处理。阅读 `references/searching.md` 获取查询编写指导，运行搜索，审查和筛选结果，然后直接回复。无需子代理。
- **中等**（当请求快速或低成本的搜索时）：委派给 1 个子代理以保持您的上下文窗口干净。
- **高级**（主题明确，筛选条件明确，几个并行搜索）：轻度使用子代理。一轮并行子代理，然后编译。
- **复杂**（跨实体类型交叉引用，多跳链，全面覆盖，语义筛选）：完整的多轮并行子代理。

**在模糊时确认：**
如果查询可以合理地处理为极其简单/中等 OR 作为高级/复杂，暂停并询问用户后再继续。提供：
1. 您对查询的理解
2. 两个（或更多）可能的复杂程度
3. 每个级别在实际中的表现（例如，“我可以进行快速 1-2 次搜索查询，或者我可以使用 3-4 个子代理以获得更深入的覆盖范围”）
4. 让用户选择

模糊查询的示例：
- “最好的 LLM 微调框架是什么？” — 可以是一个快速的、有偏见的列表（中等）或一个彻底的评估比较（复杂）
- “找到 Acme Corp 的竞争对手” — 可以是一个快速搜索已知竞争对手（中等）或深入搜索资金数据库、新闻和细分目录（复杂）
- “WebGPU 的最新动态是什么？” — 可以是一个新闻搜索（极其简单）或一个多角度调查规格、浏览器支持、社区采用和基准（高级）

**在以下情况下不要请求确认：**
- 查询非常简单（事实查询，单一实体问题）
- 查询非常复杂（显式多约束，“找到所有内容”，“彻底的”，“全面的”）
- 用户已经指定了深度（“进行深入调查”，“快速回答”）

注意：如果用户明确要求某些内容（例如，“100” 个），继续工作直到完成。

**需要完成哪些工作？** 确定以下哪些适用（大多数查询使用 3-5 个）：

1. **从用户输入中获取种子**：用户提供了一组实体作为起点（公司名称、股票代码、论文标题）。每个种子成为一个并行工作流。
2. **定义什么符合资格**：什么使结果成为有效的“行”？将用户的条件翻译成具体的检查。
3. **定义要捕获的内容**：每个结果需要哪些字段（“列”）？在搜索之前构建模式。
4. **广泛搜索**：生成多样化的查询并运行它们以找到候选者。这是子代理执行重负载的地方。
5. **提取结构化数据**：从原始搜索结果中提取特定字段到模式中。
6. **过滤**：应用硬约束（日期、地理区域、阈值）和软判断（质量、相关性、语义检查）。
7. **合并和去重**：组合来自多个子代理的结果。相同 URL = 删除重复项。来自不同来源的相同实体 = 合并字段，保留最佳数据。
8. **评分和排序**：对于“最佳”（例如，“什么是最棒的 ___？”）查询，明确定义评分标准，然后排序。
9. **综合叙述**：对于研究查询，按主题组织结果并编写带引用的散文。

## 第 2 步：派遣子代理

### 子代理的作用

子代理运行 Exa 搜索并处理结果。它们将原始搜索输出保持在您的上下文窗口之外。每个子代理应：
- 读取您指向它的参考文件
- 运行您指定的特定搜索
- 返回紧凑、结构化的输出

### 如何派遣

使用 **Agent 工具** 派遣子代理。参考文件路径相对于此文件加载的目录是相对的。

使用 `model: "haiku"` 用于子代理。

告诉每个子代理：
1. 要读取哪些参考文件以获取指令（始终包含绝对路径）
2. 要运行哪些特定搜索或要执行哪些特定工作
3. 要返回的输出格式

**模板：**
```
从 [此技能的目录]/references/searching.md 读取关于如何有效查询 Exa 的说明。

然后执行以下操作：
[特定任务描述]
[要运行的特定查询，如果您指定它们]
[验证标准——什么使结果符合资格，以便子代理在返回之前进行过滤]

返回：[输出格式——例如，“每个结果包含名称、url、摘要的紧凑 JSON”或“包含列 X、Y、Z 的 Markdown 表格”]。

以确切的：`sources_reviewed: N` 结尾，其中 N = 每个包含 `numResults` 的 `web_search_exa` 调用（包括重试）的总和。例如，调用 numResults 10、10、5 → `sources_reviewed: 25`。
```

**将 `sources_reviewed` 指令行逐字传递给每个子代理——不要释义。**
### 指向子代理的参考文件

始终将子代理指向 `references/searching.md`。它包含 Exa 查询指南和子代理将根据其任务从其中选择特定领域模式文件的索引。

根据以下情况指向这些文件中的任何一个：

| 文件 | 当您指向子代理时... |
|---|---|
| `references/extraction.md` | 子代理需要将特定数据点提取到您定义的模式中 |
| `references/filtering.md` | 子代理需要根据标准（尤其是语义/软筛选）评估结果 |
| `references/synthesis.md` | 子代理正在生成散文综合而不是结构化数据 |
| `references/source-quality.md` | 子代理需要评估来源可信度，尤其是对于“最佳”、“排名”或“专家查找”查询 |

### 如何将工作分配给子代理

如果运行并行子代理，将主要任务/问题分解为 **子问题** 以覆盖不同的搜索区域。

例如，“用于生产用途的最佳开源 LLM 微调框架” 可以分解为多个并行子问题：
1. “生产工程师推荐哪些开源 LLM 微调框架，以及他们关于在实际部署中使用它们的说法是什么？”
2. “过去 6 个月启动或获得关注的、尚未广泛知晓的开源 LLM 微调工具有哪些？”
3. “团队在生产中迁移特定开源 LLM 微调框架的最常见投诉、故障模式和原因是什么？”

根据您的 “**这个查询有多复杂？**” 分析：有些需要 2-3 个；有些需要很多。有些需要几种不同的角度、创造性思维模式、对抗性视角。这取决于用户在问什么以及他们希望您深入到什么程度。

将子问题直接提供给子代理在其提示中。

### 子代理的规模

- 目标是每个子代理 3-5 次搜索
- 采取激进的并行化——独立工作流应该是启动在单个消息中的不同子代理
- 不要使用 `run_in_background` — 在一个消息中派遣所有子代理并等待它们的结果
- 对于每种子工作（丰富 20 家公司的列表），每 3-5 个种子分配给一个子代理

### 令牌隔离

永远不要在主上下文中运行批量搜索。子代理保留原始搜索输出的整个目的是为了保持上下文窗口。子代理处理结果并仅返回提炼的输出。

### 当出现问题时

- **子代理返回空**：用不同的角度重写查询，而不是同义词。如果仍然为空，主题可能在网络覆盖有限——报告这一点。
- **子代理返回离题结果**：查询过于模糊。用更长、更具体的查询重试。

## 第 3 步：编译结果

子代理返回后：

**去重：**
1. 将所有结果收集到一个列表中
2. 删除精确 URL 重复项
3. 来自不同来源的相同实体：合并字段，保留最完整/最新的数据
4. 跟踪：“去重 X 个结果减少到 Y 个唯一条目”

**验证覆盖范围：**
- 是否有明显的空白？（缺少时间段、缺少地理区域、缺少实体类型）
- 对于每个发现的空白，运行有针对性的后续搜索（如果需要多个查询，通过子代理；如果极其简单，直接运行）
- 对于“找到所有内容”查询，检查来自不同子代理的结果是否重叠严重（好迹象）或完全分离（可能遗漏了角度）

**格式化输出：**

如果您使用了子代理，开头写：“我使用 Exa 审查了跨越 {Y} 个子代理的 {X} 个来源。以下是发现的内容：”（X = 所有子代理和传递的所有直接搜索的 `sources_reviewed` 总和；Y = 派遣的总子代理数。自然复数化。）

然后：格式化输出，不超过 claude 代码屏幕的一个滚动长度。在相关位置包含超链接文本。在它下面，您也可以包含以下内容（以简短易读的格式）：
- (“结果”) 直接回答原始用户请求（用几句话；让每个字都发挥作用）
- (“过程”) 包括任何值得注意的关于您的过程以及您认为在此领域与过滤出的内容相比的高信号内容。
- (“模式”) 任何非明显的模式，需要 n 阶思考，未包含或暗示在输出的其他部分，但可能对用户感兴趣。
- (“笔记”) 基于您对用户及其工作的一切了解，除了这个任务之外，提及任何值得注意/有用的发现，未包含或暗示在输出的其他部分。

如果不可能将完整输出放在一个屏幕内，将文件以最相关/最有用的文件格式（.csv、.md）写入 `./exa-results/<主题>-<YYYY-MM-DD>`，并在 1 屏幕输出下方包含指向完整文件的指针。

**一般输出规则：**
- 除非用户要求，否则不要使用表情符号
- 在输出中整个输出中包含 1 个词或多个词的超链接，其中超链接是一个价值增值。
- 优先选择表格而不是列表（仅在字段非统一或值太长无法整齐排列时才回退到列表）

## 多轮查询

某些查询需要多个顺序传递，其中后续传递依赖于先前结果。常见模式：

**实体链**（多跳）：传递 1 找到实体（公司），传递 2 找到每个结果的相关实体（这些公司中的人），传递 3 丰富这些（他们的公开声明）。每个传递是一轮并行子代理。

**探索然后目标**：传递 1 广泛勘察，传递 2 在传递 1 找到的最有希望的几个方向上深入搜索。

**标准发现**：当“最佳”未预定义时，传递 1 调查从业者实际重视什么，传递 2 搜索符合这些标准的候选者。

在传递之间，编译和去重后再派遣下一轮。

## 评估来源质量

来源质量对于“最佳”、“排名”、“专家查找”和最佳实践查询最重要，但对于几乎所有研究任务都有用。

**在子代理级别：** 指向子代理 `references/source-quality.md`，以便他们在输出中标记来源质量。这允许您在编译时权衡结果。

**在编排器级别**，当编译子代理结果时：

1. **高信号来源的收敛**：收敛本身没有意义（3 个低质量来源同意只是共享的噪音）。重要的是当多个独立的高信号来源（从业者、有切身利益的人）对同一发现达成共识时。
2. **从业者 vs 评论员**：从业者（做工作的人）比评论员（写工作的人）权重更高。
3. **否定法**：在综合之前，定义要排除谁（有利益冲突的来源、没有切身利益、或无法证实的声明）。过滤噪音比寻求卓越更有价值。
4. **反向测试您的编译结果**：缺失哪些视角？哪些偏见可能扭曲了汇总？如果出现空白，运行有针对性的后续查询。
5. **观点胜于实体**：对于专家查找和最佳实践查询，主要输出是收敛的真相，而不是名字的排名列表。首先展示最佳来源同意的内容，然后引用谁说的。

## 注意事项

- **简单查询的过度执行**：如果用户问“X 成立于哪一年”，不要启动子代理。一次搜索，一个答案。
- **困难查询的执行不足**：如果查询有 4 个或更多约束、时间连接或语义筛选，单个搜索将无法胜任。展开。
- **同义词查询**：运行“过誉的 AI 工具”和“过度炒作的 AI 工具”作为单独的子代理查询浪费令牌。它们命中相同的嵌入区域。通过角度多样化而不是同义词。
- **忘记去重**：多个子代理将返回重叠的结果。始终在综合之前去重。
- **将 Exa 结果视为已验证**：Exa 返回相似度，而不是已验证。出现在搜索输出中的结果并不意味着它满足用户的标准。您必须验证。
- **日期漂移**：始终从当前环境日期计算日期。永远不要重用来自这些说明或来自先前查询的日期。
