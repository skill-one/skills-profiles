# check — 偏差报告

纯粹的诊断工具。报告违规情况。不写入任何内容。由用户决定如何修正。

规范在代码中无声地漂移是 #1 SDD 失败模式。check 是检测工具。在每次 `/build` 后和每次发布前运行它 — 在这里捕获到的漂移是差异；在生产环境中捕获到的漂移是 §B。

## 加载

1. 读取 `SPEC.md`。如果缺失 → "没有规范，无事可查。" 停止。
2. 解析调用参数：
   - `§V` → 仅检查不变式（默认）
   - `§I` → 检查接口
   - `§T` → 审核任务状态与代码的对比
   - `--all` → 所有三个

## 检查 §V — 不变式

对于每个 V<n>：

1. 将不变式翻译成关于代码的可验证声明。
2. 使用 Grep / 读取相关文件。
3. 分类：**保持** / **违规** / **不可验证**。
4. 记录地址 + 文件：行证据。

## 检查 §I — 接口

对于每个 I 项：

1. 定位实现。
2. 分类：
   - **匹配** — 代码中的形状 = 规范中的形状。
   - **漂移** — 实现存在，形状不同。
   - **缺失** — 实现缺失。
   - **额外** — 代码暴露了 §I 中未定义的表面。

## 检查 §T — 任务

对于每个 T<n>：

1. 如果 `x`：验证声明的任务是否存在。
2. 如果 `~`：标记为进行中。
3. 如果 `.`：标记为待处理。
4. 标记没有证据的 `x` 行为 **过时**。

## 报告

原始人风格。按严重程度分组。

```
## §V 偏差
V2 违规：auth/mw.go:47 使用 `<` 而不是 `≤`。参见 §B.1。
V5 不可验证：没有测试覆盖所有请求路径。

## §I 偏差
I.api 漂移：POST /x 返回 `{result}` 而不是 `{id}`。route.go:112。
I.cmd 缺失：`foo bar` 缺失于 cli/*.go。

## §T 偏差
T3 过时：状态 `x`，没有中间件文件存在。

## 摘要
2 个违规。1 个缺失。1 个过时。1 个不可验证。
下一步：使用 `bug:` 标记规范技能或修复引用行的代码。
```

## 修正提示（非操作）

以每类一条提示行结束报告：
- 违规 / 漂移 → 调用规范技能 `bug: <V.n>` 或修复代码。
- 缺失 → 如果任务存在，调用构建技能 `§T.n`；否则调用规范技能 `amend §T`。
- 过时 → 使用规范技能 `amend §T` 取消勾选。
- 额外 → 使用规范技能 `amend §I` 记录文档，或删除代码。

从不调用修复。仅报告。

## 非目标

- 零写入。不编辑 SPEC.md。不编辑代码。
- 没有子代理。主线程读取。
- 没有分数，没有等级。每个项目二进制：保持或漂移。
